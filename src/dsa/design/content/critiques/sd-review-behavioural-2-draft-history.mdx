<Brief>

This is the compose screen of a notes app that lets people attach photos. It has its own undo and redo, and it autosaves the draft so nothing is lost if iOS terminates the app. QA says undo "sometimes does nothing", typing feels sluggish once photos are attached, and a beta build crashed on launch for some testers after an update. Review it as you would a pull request.

```swift check ios title="DraftHistory.swift"
import UIKit

final class Draft: Codable {
    var body = ""
    var photos: [Data] = []
}

final class DraftHistory {
    private(set) var draft = Draft()
    private var undoStack: [Draft] = []
    private var redoStack: [Draft] = []

    func setBody(_ body: String) {
        undoStack.append(draft)
        draft.body = body
        save()
    }

    func addPhoto(_ image: UIImage) {
        undoStack.append(draft)
        draft.photos.append(image.jpegData(compressionQuality: 1)!)
        save()
    }

    func undo() {
        guard let previous = undoStack.popLast() else { return }
        redoStack.append(draft)
        draft = previous
    }

    func redo() {
        guard let next = redoStack.popLast() else { return }
        undoStack.append(draft)
        draft = next
    }

    private func save() {
        let data = try! JSONEncoder().encode(draft)
        UserDefaults.standard.set(data, forKey: "draft")
    }

    static func restored() -> DraftHistory {
        let history = DraftHistory()
        if let data = UserDefaults.standard.data(forKey: "draft") {
            history.draft = try! JSONDecoder().decode(Draft.self, from: data)
        }
        return history
    }
}

final class ComposeViewController: UIViewController, UITextViewDelegate {
    private let history = DraftHistory.restored()
    private let textView = UITextView()

    override func viewDidLoad() {
        super.viewDidLoad()
        textView.delegate = self
        textView.text = history.draft.body
        view.addSubview(textView)
    }

    func textViewDidChange(_ textView: UITextView) {
        history.setBody(textView.text)
    }

    @objc func undoTapped() {
        history.undo()
        textView.text = history.draft.body
    }
}
```

<ReferenceReview>

**Most important first.** Undo can't work at all: `Draft` is a class, so every "snapshot" is the live draft itself, and undo swaps the object for itself. Fixing that is a one-word change (`struct`) with a big effect. Then two problems users already feel: a decoding `try!` at launch that turns one bad saved value into a crash on every launch (the beta crash), and an autosave that re-encodes every photo as base64 on the main thread for each keystroke (the sluggish typing).

**The design problem underneath** is that one type is three things at once: the originator (the draft), the caretaker (the stacks) and the persistence layer, and none of them follows the memento rules. Snapshots aren't copies, the history has no bounds or branch handling, and the persisted memento has no version, no per-window identity and no failure path.

**How I'd fix it, in small steps:**

1. Add tests for today's intended behaviour (undo, redo, undo-then-type) against `DraftHistory`. They fail now, which documents the bug.
2. Make `Draft` a `struct` with value properties, and keep photos out of it: store each photo as a file once, and keep its identifier in the draft. Snapshots become small and cheap.
3. Replace the hand-rolled stacks with snapshot undo through `UndoManager` (`registerUndo(withTarget:handler:)` capturing the previous `Draft`), grouping typing into one step per pause and setting `levelsOfUndo`. Shake to undo, ⌘Z and the Undo button then share one history, and redo is cleared on new edits for free.
4. Move persistence behind a small `DraftStore`: a versioned, `Codable` snapshot per draft id, written to a file in Application Support from a debounced autosave, encoded off the main actor (a `Sendable` struct makes that easy). Save after undo and redo too.
5. Restore with `try?` and a version check, falling back to an empty draft and logging the failure. Put the draft's id in the scene's restoration activity, so each iPad window restores its own draft.
6. Handle a nil from `jpegData`, or better, keep the picked image file as it is.

**Tests to add:** undo and redo sequences, including undo-then-edit clearing redo; history capped at the limit; decoding fixtures saved by the previous version, plus a corrupt one that must not crash; autosave debouncing with an injected clock; two draft ids saved and restored independently.

</ReferenceReview>
