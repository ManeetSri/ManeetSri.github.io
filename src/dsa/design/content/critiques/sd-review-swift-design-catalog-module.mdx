<Brief>

`CatalogKit` is a Swift package module that three feature modules of a shop app import: Browse, Search and Checkout. It's the first module the team has split out, and its author wanted it "flexible", so everything is a protocol, an existential or `open`. Support has a ticket saying book rows never show the author. Review the module's public API and its row view as you would a pull request.

```swift check ios title="CatalogKit.swift"
import SwiftUI

public protocol CatalogItem {
    var id: String { get }
    var title: String { get }
    var price: Decimal { get }
}

public struct Book: CatalogItem, Decodable {
    public var id: String
    public var title: String
    public var price: Decimal
    public var author: String
}

public struct Course: CatalogItem, Decodable {
    public var id: String
    public var title: String
    public var price: Decimal
    public var lessonCount: Int
}

public struct AnyCatalogItem: CatalogItem {
    private let base: any CatalogItem
    public init(_ base: any CatalogItem) { self.base = base }
    public var id: String { base.id }
    public var title: String { base.title }
    public var price: Decimal { base.price }
}

open class CatalogStore {
    public var items: [AnyCatalogItem] = []
    public var session: URLSession = .shared
    public var lastResponse: [String: Any] = [:]

    public init() {}
    open func loadBooks(from url: URL) async throws {
        let (data, response) = try await session.data(from: url)
        lastResponse = ["status": (response as? HTTPURLResponse)?.statusCode ?? 0, "bytes": data.count]
        let books = try JSONDecoder().decode([Book].self, from: data)
        items = books.map { AnyCatalogItem($0) }
    }

    public func cheapest(in items: [any CatalogItem]) -> (any CatalogItem)? {
        items.min { $0.price < $1.price }
    }

    public func resetForTesting() {
        items = []
        lastResponse = [:]
    }
}

public struct CatalogRow: View {
    public let item: any CatalogItem
    public init(item: any CatalogItem) { self.item = item }

    public var body: some View {
        if let book = item as? Book {
            return AnyView(VStack(alignment: .leading) {
                Text(book.title)
                Text(book.author).font(.caption)
            })
        }
        if let course = item as? Course {
            return AnyView(Text("\(course.title) · \(course.lessonCount) lessons"))
        }
        return AnyView(Text(item.title))
    }
}
```

<ReferenceReview>

**What matters most.** The visible bug, book rows without authors, comes from a design choice rather than a typo: a hand-written eraser around a protocol that never needed one, combined with a view that downcasts. Delete `AnyCatalogItem` first; that one change fixes the ticket. The two other high findings are about the module boundary. This is the team's first shared module, and `open` plus public mutable state means three other modules can already depend on details the author will want to change next month. Fixing that now costs a morning; fixing it after Browse subclasses the store costs a migration.

**How I'd fix it, in small steps,** each its own pull request that leaves the app working:

1. **Stop the bleeding:** remove `AnyCatalogItem`. Store `[any CatalogItem]` for now, so `as? Book` works again. Ship it; the ticket is closed.
2. **Close the boundary:** make `CatalogStore` `public final`, make `items` `public private(set)`, take the session (better, an `HTTPClient` protocol) in `init` and keep it private. Delete `lastResponse`, or replace it with an internal struct for logging. Build all three client modules: anything that no longer compiles was relying on internals and needs a proper API.
3. **Model what's really closed:** the catalog has books and courses, and every screen switches on that. Introduce `public enum CatalogEntry: Identifiable { case book(Book), course(Course) }`, store `[CatalogEntry]`, and write `CatalogRow` as a `@ViewBuilder` `switch` with no `AnyView`. Adding a podcast later becomes a compile error everywhere it must be handled, which is what you want.
4. **Fix the helpers:** make `cheapest(in:)` a generic static function (or an extension on `Collection where Element: CatalogItem`), and delete `resetForTesting()` in favour of `@testable import` in CatalogKit's own tests.
5. **Turn the rule on:** consider internal imports in client modules (`internal import CatalogKit` where nothing re-exports it), so the compiler stops CatalogKit types leaking into *their* public APIs too.

**Tests to add.** Before step 1, a test that wraps a decoded `Book` exactly as `loadBooks` does and asserts that `as? Book` recovers it: it fails today and proves the fix. With the session injected, `loadBooks` gets tests for decoding and for an error status. A test-target build of each client module after step 2 is the real safety net: the compiler finds every leak for you.

</ReferenceReview>
