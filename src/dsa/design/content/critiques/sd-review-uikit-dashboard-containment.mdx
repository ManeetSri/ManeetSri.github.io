<Brief>

This is the home dashboard of a budgeting app: a UIKit summary at the top, a SwiftUI spending chart below it, and a promo banner that marketing swaps several times a session. Users say the chart always shows £0, the app gets slower the longer it's open, and analytics records two "summary viewed" events per visit. Review it as you would a pull request: what's wrong, what matters most, and how you'd fix it.

```swift check ios title="DashboardViewController.swift"
import SwiftUI
import UIKit

struct SpendingChart: View {
    let total: Decimal
    var body: some View {
        Text(total, format: .currency(code: "GBP")).font(.largeTitle)
    }
}

final class SummaryViewController: UIViewController {
    func reload() {}

    @objc func refreshTapped() {
        (parent as! DashboardViewController).refreshAll()
    }
}

final class PromoViewController: UIViewController {}

final class DashboardViewController: UIViewController {
    private let summary = SummaryViewController()
    private var promo: PromoViewController?

    override func viewDidLoad() {
        super.viewDidLoad()
        addChild(summary)
        view.addSubview(summary.view)
        summary.view.frame = CGRect(x: 0, y: 0, width: view.bounds.width, height: 200)

        let chart = UIHostingController(rootView: SpendingChart(total: 0))
        chart.view.translatesAutoresizingMaskIntoConstraints = false
        view.addSubview(chart.view)
    }

    override func viewDidLayoutSubviews() {
        super.viewDidLayoutSubviews()
        guard let chartView = view.subviews.last else { return }
        NSLayoutConstraint.activate([
            chartView.topAnchor.constraint(equalTo: view.topAnchor, constant: 200),
            chartView.leadingAnchor.constraint(equalTo: view.leadingAnchor),
            chartView.trailingAnchor.constraint(equalTo: view.trailingAnchor),
        ])
    }

    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        summary.viewWillAppear(animated)
        NotificationCenter.default.addObserver(forName: UIApplication.significantTimeChangeNotification, object: nil, queue: .main) { _ in
            MainActor.assumeIsolated { self.refreshAll() }
        }
    }

    func showPromo(_ next: PromoViewController) {
        promo?.view.removeFromSuperview()
        addChild(next)
        view.addSubview(next.view)
        next.didMove(toParent: self)
        promo = next
    }

    func refreshAll() {
        summary.reload()
    }
}
```

<ReferenceReview>

**Most important first.** Three problems get worse every minute the app is open. The **promo swap** leaks a whole view controller each time, because the old promo is never removed as a child. The **notification observer** is added on every appearance and never removed, so refreshes multiply and the dashboard itself can never be freed. And the **chart** can't work at all: its hosting controller is a local that ARC frees at the end of `viewDidLoad`, so nothing can ever give it a real total.

**The pattern underneath** is containment done by hand, differently each time: one child half added, one only as a view, one removed only as a view, and a parent forwarding callbacks UIKit already sends. The fix is to stop writing containment inline.

**How I'd fix it, in small steps:**

1. Add `embed(_:in:)` and `unembed()` helpers (add the child, place its view with constraints, `didMove`; and the reverse) and use them for the summary, the chart and the promo. That fixes the promo leak, the missing `didMove` and the chart's lifetime in one change.
2. Keep the chart's hosting controller in a property and pass it an `@Observable` spending model instead of a constant, so the chart updates when the data does. Set `sizingOptions = .intrinsicContentSize` so Auto Layout sizes it.
3. Move all layout into `viewDidLoad` with constraints against stored views: the summary pinned to the top, the chart below it, the promo below that. Delete the `viewDidLayoutSubviews` override and the frame maths.
4. Delete `summary.viewWillAppear(animated)`.
5. Observe the time-change notification once (in `viewDidLoad`, keeping the token and removing it in `deinit`, or with a `Task` over `NotificationCenter.default.notifications(named:)` cancelled in `viewDidDisappear`), capturing `self` weakly.
6. Replace the summary's `parent as!` with an `onRefresh` closure the dashboard sets when embedding it.

**Tests to add:** after `showPromo` twice, `children` contains exactly one promo and a weak reference to the first one is nil. Drive an appearance with `beginAppearanceTransition(true, animated: false)` and `endAppearanceTransition()` and assert a spy summary saw `viewWillAppear` once. Post the notification after three appearances and assert one refresh. Lay out the dashboard twice with `layoutIfNeeded()` and assert the number of constraints didn't change. Finally, a test that releases the dashboard and checks it deallocates catches the next leak of this kind.

</ReferenceReview>
