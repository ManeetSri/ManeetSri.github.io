<Brief>

A podcast app's player screen. Testers report that after closing it the episode **keeps playing**, that memory climbs every time they open an episode, and that the app sometimes crashes when an episode ends. Review the code as you would a pull request: what's wrong, what matters most, and how you'd fix it.

```swift check ios title="EpisodePlayerViewController.swift"
import AVFoundation
import UIKit

@MainActor protocol PlayerControlsDelegate {
    func controlsDidTapPlayPause(_ controls: PlayerControlsView)
}

final class PlayerControlsView: UIView {
    var delegate: PlayerControlsDelegate?
    var onScrub: ((Double) -> Void)?
}

final class EpisodePlayerViewController: UIViewController, PlayerControlsDelegate {
    let episodeID: String
    let player: AVPlayer
    let controls = PlayerControlsView()
    private var progressTimer: Timer?

    init(episodeID: String, url: URL) {
        self.episodeID = episodeID
        self.player = AVPlayer(url: url)
        super.init(nibName: nil, bundle: nil)
    }

    required init?(coder: NSCoder) { nil }

    override func viewDidLoad() {
        super.viewDidLoad()
        view.addSubview(controls)
        controls.delegate = self
        controls.onScrub = { fraction in
            let duration = self.player.currentItem?.duration.seconds ?? 0
            self.player.seek(to: CMTime(seconds: fraction * duration, preferredTimescale: 600))
        }
    }

    override func viewWillAppear(_ animated: Bool) {
        super.viewWillAppear(animated)
        NotificationCenter.default.addObserver(forName: AVPlayerItem.didPlayToEndTimeNotification, object: nil, queue: nil) { _ in
            MainActor.assumeIsolated { self.markFinished() }
        }
        progressTimer = Timer.scheduledTimer(timeInterval: 1, target: self, selector: #selector(tick), userInfo: nil, repeats: true)
    }

    @objc private func tick() {
        title = "\(Int(player.currentTime().seconds)) s"
    }

    func controlsDidTapPlayPause(_ controls: PlayerControlsView) {
        player.timeControlStatus == .playing ? player.pause() : player.play()
    }

    private func markFinished() {
        NotificationCenter.default.post(name: Notification.Name("episodeFinished"), object: nil, userInfo: ["id": episodeID])
    }
}

final class LibraryViewController: UITableViewController {
    private var played: Set<String> = []

    override func viewDidLoad() {
        super.viewDidLoad()
        NotificationCenter.default.addObserver(self, selector: #selector(episodeFinished), name: Notification.Name("episodeFinished"), object: nil)
    }

    @objc private func episodeFinished(_ notification: Notification) {
        played.insert(notification.userInfo!["episodeID"] as! String)
        tableView.reloadData()
    }
}
```

<ReferenceReview>

**Most important first.** Two crashes ship today: `MainActor.assumeIsolated` traps whenever AVFoundation posts the end-of-item notification off the main thread, and the library force-unwraps a `userInfo` key (`episodeID`) that the player never sends (it sends `id`). Fix both before anything else.

**Then the leaks, which users can hear.** The screen can't be freed for four separate reasons: the strong delegate (a cycle), the scrub closure capturing `self` (another cycle), the discarded observer token (NotificationCenter owns a block that owns `self`), and the scheduled timer (the run loop owns a timer that owns `self`). Any one of them keeps the `AVPlayer` alive, which is why the episode plays on after the screen closes. Because observers and timers are added in `viewWillAppear`, every reappearance makes it worse.

**How I'd fix it, in small steps:**

1. Make `PlayerControlsDelegate: AnyObject` and the property `weak var delegate`. That's the convention for every UIKit delegate, for this reason.
2. Capture only what the scrub closure needs: `controls.onScrub = { [player] fraction in … }`.
3. Register for the end of *this* item once, in `viewDidLoad`, with `object: player.currentItem` and `queue: .main`, and keep the token so the screen can remove the observer when it goes away. (In a task-based screen, `for await _ in NotificationCenter.default.notifications(named:object:)` in a task cancelled on disappear does the same with no token to lose.)
4. Replace the timer with `player.addPeriodicTimeObserver(forInterval:queue:using:)` using `[weak self]`, and remove the observer when the screen goes away.
5. Replace the string-named notification with a `PlaybackHistory` injected into both screens: the player calls `history.markPlayed(episodeID)`, and the library observes the history. If a notification has to stay for now, give it a `Notification.Name` constant and read the payload with `as?`, never `!`.

**Tests to add:** a leak test that creates the player screen, loads its view, runs it through `viewWillAppear` twice, drops it, and checks a `weak` reference is `nil` (this catches all four retainers); a test that finishing a *different* player item doesn't mark this episode played; and a `PlaybackHistory` test for marking and observing. In the app, the Xcode memory graph debugger shows each cycle directly.
