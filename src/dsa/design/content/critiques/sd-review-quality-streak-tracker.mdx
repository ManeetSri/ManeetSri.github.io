<Brief>

This is the streak feature of a fitness app: finish a workout and your streak, points and tomorrow's reminder update. Users keep writing to support that their 40-day streak "reset to 1", the team is scared to touch the file, and there isn't a single test for it. Review it as you would a pull request: what's wrong, what matters most, and how you'd make it testable and safe to change.

import SwiftUI
import UserNotifications

@MainActor
final class AnalyticsClient {
    static let shared = AnalyticsClient()
    func track(_ event: String, _ properties: [String: String] = [:]) {
        // Sends the event to the analytics backend
    }
}

@MainActor @Observable
final class StreakModel {
    static let shared = StreakModel()

    var streak = 0
    var points = 0
    var banner: String?

    func workoutFinished(kind: String, minutes: Int) {
        let defaults = UserDefaults.standard
        let now = Date()
        if let last = defaults.object(forKey: "lastWorkout") as? Date {
            if Calendar.current.isDateInYesterday(last) {
                streak += 1
            } else if !Calendar.current.isDateInToday(last) {
                streak = 1
            }
        } else {
            streak = 1
        }
        defaults.set(now, forKey: "lastWorkout")
        defaults.set(streak, forKey: "streak")

        if kind == "run" {
            points += minutes * 2
        } else if kind == "swim" {
            points += minutes * 3
        } else if kind == "yoga" {
            points += minutes
        }

        if streak == 7 {
            banner = "One week in a row!"
        } else if streak == 30 {
            banner = "30 days in a row!"
        }

        AnalyticsClient.shared.track("workout_finished", ["kind": kind, "streak": "\(streak)"])

        let content = UNMutableNotificationContent()
        content.title = "Keep your \(streak)-day streak going"
        var tomorrow = Calendar.current.dateComponents([.year, .month, .day], from: now.addingTimeInterval(86_400))
        tomorrow.hour = 18
        let trigger = UNCalendarNotificationTrigger(dateMatching: tomorrow, repeats: false)
        let request = UNNotificationRequest(identifier: UUID().uuidString, content: content, trigger: trigger)
        UNUserNotificationCenter.current().add(request)
    }
}

struct StreakBadge: View {
    var body: some View {
        Label("\(StreakModel.shared.streak) days", systemImage: "flame")
    }
}

<ReferenceReview>

**Most important first.** There's a real bug shipping today: the streak is never loaded, so any relaunch turns a long streak into 1 (lines 16–17 and 25). Fix that first, and fix it with a test, because it's the kind of bug that comes back.

**The design problem underneath** is that the rule users care about, "did you work out yesterday?", is buried in a method that also reads the clock, writes to disk, tracks analytics and schedules notifications. Every one of those is hidden behind a global, so the rule can't be tested on its own, and the code can't be changed without fear. Testability and maintainability are the qualities missing here, and both come from the same fix: separate the decision from the side effects, and pass dependencies in.

**How I'd fix it, in small steps** (each one shippable):

1. Extract the rule as a pure function: `StreakRule.next(current: Int, lastWorkout: Date?, now: Date, calendar: Calendar) -> Int`. Cover it with table-driven tests before changing anything else, including a workout at 23:59 followed by one at 00:01, and a gap of two days.
2. Add a `StreakStore` protocol (load and save streak, points and last workout as one value). Back it with `UserDefaults` in the app and an in-memory store in tests, and load from it in `StreakModel.init`. This fixes the reset bug.
3. Give `StreakModel` an initialiser that takes the store, a `now: () -> Date`, a `Calendar`, an `Analytics` protocol and a `ReminderScheduler` protocol. Build the real ones in the app's composition root, and keep `shared` only until the last caller is gone.
4. Replace the kind string with a `WorkoutKind` enum and its `pointsPerMinute`.
5. Make the reminder scheduler use a fixed identifier and `calendar.date(byAdding: .day, value: 1, to: now)`.
6. Pass the model into `StreakBadge`, and move milestones into a small table with localised copy.

**Tests to add:** the streak rule across today, yesterday, a gap, midnight and a time-zone change; the model restoring its streak from a store after a "relaunch" (a new model on the same store); two workouts in one day scheduling one reminder; points per kind. None of them need a simulator, the real clock or real notifications.

</ReferenceReview>
