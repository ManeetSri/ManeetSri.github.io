<Brief>

A streaming app is adding a **Family** plan next to Free and Plus. The pull request is small: it adds a `"family"` case wherever the author found a switch on the tier, and the parts it touched are collected below. It passed review once already and QA signed it off on a Plus account. Review it again, and say what the change itself tells you about the design.

```swift check ios title="FamilyPlan.swift"
import Foundation

struct Subscription {
    let tier: String  // "free", "plus", or "family" (new in this pull request)
    let renewsAt: Date?
    let seats: Int
}

struct Account {
    let id: String
    let subscription: Subscription
    let deviceCount: Int
}

struct PaywallPresenter {
    func title(for tier: String) -> String {
        switch tier {
        case "plus": return "Plus"
        case "family": return "Family"
        default: return "Free"
        }
    }

    func price(for tier: String) -> String {
        switch tier {
        case "plus": return "£4.99 a month"
        case "family": return "£7.99 a month"
        default: return "Free"
        }
    }
}

struct FeatureGate {
    func canAddDevice(_ account: Account) -> Bool {
        switch account.subscription.tier {
        case "plus": return account.deviceCount < 3
        case "family": return account.deviceCount < 3 * account.subscription.seats
        default: return account.deviceCount < 1
        }
    }

    func canDownloadOffline(_ account: Account) -> Bool {
        account.subscription.tier == "plus"
    }
}

struct SettingsViewModel {
    let account: Account

    var renewalText: String {
        let subscription = account.subscription
        guard subscription.tier != "free", let renewsAt = subscription.renewsAt else {
            return "Not subscribed"
        }
        let days = Calendar.current.dateComponents([.day], from: Date(), to: renewsAt).day ?? 0
        if days <= 7 {
            return "Renews in \(days) days"
        }
        return "Renews on " + renewsAt.formatted(date: .long, time: .omitted)
    }

    var canInviteFamily: Bool {
        account.subscription.tier == "family" && account.subscription.seats > 1
    }
}
```

<ReferenceReview>

**Most important first.** The pull request ships a bug: Family subscribers can't download (line 43). Fix it before merging, with a test that checks every entitlement for every plan, so the next miss fails a test instead of reaching a customer.

**What the change tells you.** Adding one plan meant finding every place, across three types, that reads the tier string, and one was missed. That's **shotgun surgery**, and its root is **primitive obsession**: a plan is a `String`, so the knowledge of what a plan *is* has nowhere to live except in every switch that reads it. The `default:` branches make it worse by failing quietly. Alongside it, the view model and the feature gate show **feature envy**: they compute subscription facts from the subscription's fields.

**How I'd fix it, in small steps:**

1. Characterise first: a table-driven test of every function for `"free"`, `"plus"`, `"family"` and an unknown string. It records today's behaviour, including the download bug, which you then fix in its own commit so the diff shows exactly what changed.
2. Introduce `enum Plan: String, Codable { case free, plus, family }` and decode it at the API boundary. Decide there, once, what an unknown plan means (treat it as Free *and log it*, or fail the decode).
3. Move each switch onto `Plan`, one per commit: `title`, `deviceLimit(seats:)`, `includesOfflineDownloads`, `canInviteFamily`. Write the switches without `default:`, so adding a case makes the compiler list every one.
4. Move the envious logic onto `Subscription`: `isActive`, `deviceLimit`, `daysUntilRenewal(from:calendar:)`. The view model keeps only the words.
5. Replace the price strings with `Product.displayPrice` from StoreKit 2, loaded with the products.
6. Inject `now` and a `Calendar` into the view model, and move the wording into a String Catalog with plural variants.

An enum fits here because the set of plans is small, closed and owned by the app, and you want the compiler to force a decision for each one. If plans came from the server as configuration, a `Plan` struct carrying its entitlements as data would beat both the enum and a protocol per plan.

**Tests to add:** the plan × entitlement table; decoding a known and an unknown plan; renewal text at 0, 1, 7 and 8 days with a fixed clock and calendar.
