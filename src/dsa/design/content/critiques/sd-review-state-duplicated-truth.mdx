<Brief>

A shared shopping list app. Users report that the title says "3 of 2 bought", that hiding bought items makes delete remove the wrong thing, that renaming an item does nothing, and that the home-screen widget's "items left" count is often wrong. Review the screen as you would a pull request: find every place a fact is stored twice, say what drifts and when, and plan the fix.

```swift check ios title="GroceryListView.swift"
import SwiftUI

struct GroceryItem: Identifiable, Hashable {
    let id: UUID
    var name: String
    var isBought = false
}

@Observable final class GroceryList {
    var items: [GroceryItem] = []
    var boughtCount = 0

    func toggle(_ item: GroceryItem) {
        guard let index = items.firstIndex(where: { $0.id == item.id }) else { return }
        items[index].isBought.toggle()
        boughtCount += items[index].isBought ? 1 : -1
    }

    func delete(at offsets: IndexSet) { items.remove(atOffsets: offsets) }
}

struct GroceryListView: View {
    @State private var list = GroceryList()
    @State private var showBought = true
    @State private var editing: GroceryItem?
    @AppStorage("remainingCount") private var remaining = 0

    private var visible: [GroceryItem] {
        showBought ? list.items : list.items.filter { !$0.isBought }
    }

    var body: some View {
        NavigationStack {
            List {
                FilterRow(showBought: showBought)
                ForEach(visible, id: \.self) { item in
                    Button(item.name) {
                        list.toggle(item)
                        remaining = list.items.count - list.boughtCount
                    }
                    .contextMenu { Button("Edit") { editing = item } }
                }
                .onDelete(perform: list.delete)
            }
            .navigationTitle("\(list.boughtCount) of \(list.items.count) bought")
            .sheet(item: $editing) { EditItemView(item: $0) }
        }
    }
}

struct FilterRow: View {
    @State var showBought: Bool

    var body: some View { Toggle("Show bought items", isOn: $showBought) }
}

struct EditItemView: View {
    @State var item: GroceryItem
    @Environment(\.dismiss) private var dismiss

    var body: some View {
        Form {
            TextField("Name", text: $item.name)
            Button("Save") {
                NotificationCenter.default.post(name: Notification.Name("groceryItemSaved"), object: nil)
                dismiss()
            }
        }
    }
}
```

<ReferenceReview>

**Most important first.** Two bugs destroy or lose the user's data. Deleting while bought items are hidden **removes the wrong item**, because the filtered list's offsets are applied to the full list. And **every rename is thrown away**: the edit sheet works on a copy of a copy, and Save only posts a notification nobody handles. Fix these before anything else.

**The design problem underneath** is that almost every fact on this screen is stored more than once:

- whether items are bought: in `items`, in `boughtCount` and in UserDefaults' `remainingCount`;
- the filter: in the screen and again in `FilterRow`;
- the item being edited: in the list, in `editing` and in `EditItemView`'s state;
- which row is which: by value (`id: \.self`) instead of by `id`.

Each copy has its own update path, and each bug report is one of those paths being missed.

**How I'd fix it, in small steps:**

1. Write unit tests for `GroceryList` that describe what users expect: deleting by id, counts after deleting a bought item, renaming. Several will fail today, which is the point.
2. Make `GroceryList` the single owner: `private(set) var items`, and intent methods that take ids: `toggle(id:)`, `delete(ids:)`, `rename(id:to:)`. Replace `boughtCount` with computed `boughtCount` and `remainingCount`.
3. Delete by id: `.onDelete { offsets in list.delete(ids: offsets.map { visible[$0].id }) }`.
4. Give `FilterRow` a `@Binding var showBought` and pass `$showBought`.
5. Hold `editing` as `GroceryItem.ID?`, resolve the item from the list in the sheet, and turn `EditItemView` into a draft with a commit point: it's seeded with the current name and calls `onSave(newName)`, which the screen forwards to `list.rename(id:to:)`. Delete the notification.
6. Use `ForEach(visible)` so rows are identified by `id`.
7. Move the list out of the view into an app-level store injected through the environment. If the widget needs a count, the store writes it (to the App Group container the widget reads) inside the same methods that change `items`, and reloads the widget's timeline; remove `@AppStorage("remainingCount")`.

**Tests to add:** `GroceryList` deletes the right item by id with bought items hidden; counts are right after toggling, deleting and renaming; a rename changes the item in `items`; the value written for the widget changes on every mutation. A UI test that hides bought items, swipes to delete, and checks which name disappeared.
