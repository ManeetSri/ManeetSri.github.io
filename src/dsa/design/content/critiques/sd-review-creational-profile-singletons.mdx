<Brief>

This is the profile screen of a social app, written during a rush to adopt Swift 6: the compiler complained about the singletons, so they were annotated until it stopped. QA reports that the screen sometimes crashes on a fresh install, that it stutters when it opens, and that after logging out and in as someone else, the old user's avatar and name can appear. Review it as you would a pull request: what's wrong, what matters most, and how you'd fix it.

```swift check ios title="ProfileViewController.swift"
import UIKit

struct User: Codable, Sendable {
    let id: String
    var name: String
    var avatarURL: URL
}

final class SessionManager {
    nonisolated(unsafe) static var shared = SessionManager()
    var user: User?

    func logOut() {
        UserDefaults.standard.removeObject(forKey: "token")
        SessionManager.shared = SessionManager()
    }
}

final class AvatarCache: @unchecked Sendable {
    static let shared = AvatarCache()
    private var images: [String: UIImage] = [:]

    private init() {
        let folder = FileManager.default.urls(for: .cachesDirectory, in: .userDomainMask)[0]
        let files = (try? FileManager.default.contentsOfDirectory(at: folder, includingPropertiesForKeys: nil)) ?? []
        for file in files {
            images[file.lastPathComponent] = UIImage(contentsOfFile: file.path)
        }
    }

    func image(for url: URL) -> UIImage? { images[url.lastPathComponent] }
    func store(_ image: UIImage, for url: URL) { images[url.lastPathComponent] = image }
}

final class ProfileAPI: Sendable {
    func fetchProfile() async throws -> User {
        let session = URLSession(configuration: .default)
        var request = URLRequest(url: URL(string: "https://api.example.com/me")!)
        let token = UserDefaults.standard.string(forKey: "token") ?? ""
        request.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")
        let (data, _) = try await session.data(for: request)
        return try JSONDecoder().decode(User.self, from: data)
    }
}

final class ProfileViewController: UIViewController {
    private let session = SessionManager.shared
    private lazy var avatarView = UIImageView(image: AvatarCache.shared.image(for: session.user!.avatarURL))
    private let nameLabel = UILabel()

    override func viewDidLoad() {
        super.viewDidLoad()
        view.addSubview(avatarView)
        view.addSubview(nameLabel)
        nameLabel.text = session.user?.name
        Task {
            let user = try await ProfileAPI().fetchProfile()
            session.user = user
            nameLabel.text = user.name
        }
    }

    @objc func logOutTapped() {
        session.logOut()
        navigationController?.popToRootViewController(animated: true)
    }
}
```

<ReferenceReview>

**Most important first.** Two bugs users can see. Opening the screen **crashes** whenever the profile isn't loaded yet, because the lazy `avatarView` force-unwraps `session.user` at line 48. And logging out leaves the **previous user's data** visible: `logOut()` replaces a mutable global that live screens have already copied, and the avatar cache is never cleared.

**The design problem underneath** is global access and hidden construction. The screen reaches three singletons and builds a fourth object inline; the singletons were made to compile under Swift 6 by switching the checks off (`nonisolated(unsafe)`, `@unchecked Sendable`) rather than by making them safe. Lazy creation then moves real work, a directory scan and a force unwrap, to the moment the screen opens.

**How I'd fix it, in small steps:**

1. **Stop the crash today.** Make `avatarView` a plain `let` and set its image once the user is known, with a placeholder until then.
2. **Introduce seams without changing call sites.** Extract small protocols for what the screen uses (`ProfileLoading`, `AvatarImages`, a `TokenStore`) and give the screen, or better a new `@MainActor` `ProfileModel`, initialiser parameters that default to today's instances.
3. **Write tests against those seams:** logged out (no crash, placeholder shown), loaded, and fetch failed (an error state instead of a stale name).
4. **Make the shared objects safe for real.** Turn `AvatarCache` into an actor that loads one image on demand, off the main thread, with no directory scan in `init`. Give `ProfileAPI` one injected `URLSession` and read the token from the Keychain through `TokenStore`.
5. **Create them at the composition root and remove the defaults.** The scene delegate builds one session, one cache and one API client and passes them in. Delete `SessionManager.shared`.
6. **Give per-user state a per-user lifetime.** On sign-in, the root builds a signed-in object graph (session, caches, user-scoped API client); on sign-out it throws the whole graph away and clears the user's cache directory. Nothing can keep the old user, because nothing global holds them.

**Tests to add:** the model's states with a stub `ProfileLoading` (loading, loaded, failed, logged out); a spy `AvatarImages` showing logout clears it; the API client sending the token from an injected `TokenStore`; and the composition root building a fresh graph after sign-out.

</ReferenceReview>
