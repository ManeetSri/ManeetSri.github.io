<Brief>

This is the checkout screen of a shopping app, as it stands after two years and four teams. It works, but changes to the cart, the payment provider or analytics keep breaking it, and support has reports of items vanishing from carts and of a crash when checkout is opened from a notification. Review it for **coupling**: what each part depends on, how it finds out, and what would ripple when something changes.

```swift check ios title="CheckoutViewController.swift"
import UIKit

// The vendors' SDKs, reduced to what this file calls
enum AcmePay {
    static func configure(apiKey: String) {}
    static func charge(pence: Int, paymentMethod: String, completion: @escaping @Sendable (Bool) -> Void) {}
}
enum AcmeAnalytics {
    static func logEvent(_ name: String, _ parameters: [String: Any]) {}
}

struct User { let id: String; var addresses: [String] }
struct CartItem { let name: String; let pricePence: Int }

@MainActor final class AppSession {
    static let shared = AppSession()
    var currentUser: User?
    var cartItems: [CartItem] = []
}

final class CartViewController: UIViewController {
    let badgeLabel = UILabel()
    let tableView = UITableView()
}

final class CheckoutViewController: UIViewController {
    var paymentMethodID: String!   // set by whoever pushes this screen, before it loads
    private let totalLabel = UILabel()

    override func viewDidLoad() {
        super.viewDidLoad()
        AcmePay.configure(apiKey: "pk_live_51Hx")
        let total = AppSession.shared.cartItems.reduce(0) { $0 + $1.pricePence }
        totalLabel.text = "£\(total / 100).\(total % 100)"
        view.addSubview(totalLabel)
    }

    func submitOrder(isGuest: Bool, skipValidation: Bool, fromDeepLink: Bool) {
        let user = AppSession.shared.currentUser
        if !skipValidation && !isGuest && user?.addresses.first == nil { return }
        let total = AppSession.shared.cartItems.reduce(0) { $0 + $1.pricePence }
        AcmeAnalytics.logEvent(fromDeepLink ? "checkout_dl" : "checkout_tap", ["value": total, "user": user?.id ?? "guest"])
        AcmePay.charge(pence: total, paymentMethod: paymentMethodID) { success in
            Task { @MainActor in
                guard success else { return }
                AppSession.shared.cartItems = []
                UserDefaults.standard.set(true, forKey: "has_ordered")
                let cart = self.tabBarController?.viewControllers?[2] as? CartViewController
                cart?.badgeLabel.text = "0"
                cart?.tableView.reloadData()
                self.navigationController?.popToRootViewController(animated: true)
            }
        }
    }
}
```

<ReferenceReview>

**Most important first.** Three problems cause bugs today, and none is visible from a single file. The global `AppSession` lets the cart change while a payment is in flight, and the success path then empties it, so customers lose items they added (that's the "items vanishing" report). Checkout reaches into the cart screen's subviews by tab index, so any change to the tab bar leaves the badge wrong without an error. And `paymentMethodID` is an implicitly unwrapped property that the notification path never sets, which is the crash.

**The pattern underneath** is that the screen finds its dependencies instead of being given them: a singleton for state, a tab index for the cart, a hidden configuration call for payments, vendor SDKs called by name. Every one of those is coupling that no initialiser shows.

**How I'd fix it, in small steps:**

1. Give the screen an initialiser: `init(cart: Cart, user: User?, paymentMethodID: String, payments: any PaymentProcessing, analytics: any AnalyticsTracking, source: CheckoutSource)`. The crash goes away, and every dependency is visible.
2. Make `Cart` a shared `@Observable` model, created once at launch and passed to both screens. Checkout tells it `cart.remove(paid: items)` with the items it charged for; the cart screen observes the model and updates its own badge and table. Delete the reach-in.
3. Move the charge and its rules into a `CheckoutModel` that the view controller owns, with `placeOrder()` and `placeGuestOrder()` instead of three flags. Validation always runs.
4. Configure the payment SDK once at launch, behind `PaymentProcessing` (`func charge(pence:paymentMethodID:) async throws`), with the key coming from build configuration rather than source. One adapter wraps the vendor's callback API.
5. Replace string events with `AnalyticsEvent.checkoutStarted(valuePence:source:)`, mapped to the vendor's names in one adapter.
6. Give the cart one `totalPence` and use currency formatting. Move `has_ordered` to an `OrderHistory` type that owns the key.

**Tests to add:** `CheckoutModel` with fake payments and analytics: a successful charge removes exactly the paid items and keeps one added meanwhile; a failed charge keeps the cart; guest checkout skips the address check and member checkout doesn't; the analytics event carries the entry point. A test that builds the screen from a notification route and places an order without crashing.

</ReferenceReview>
