<Brief>

A shopping app with four tabs (Home, Search, Basket, Account) has grown its navigation one screen at a time. Marketing emails use `shop://product/42` and `shop://order/A1B2C3`; the website shares `https://shop.example.com/product/42` and `https://shop.example.com/orders/A1B2C3` as universal links. Support reports crashes from "some links", links that open the app on Home, and a basket that sometimes shows two checkouts. Review the navigation as you would a pull request: what's wrong, what matters most, and how you'd restructure it.

        super.viewDidLoad()

    @objc func openProduct(_ note: Notification) {
        let product = ProductViewController()
        product.productID = note.userInfo?["id"] as! Int
        navigationController?.pushViewController(product, animated: true)
    }

    override func tableView(_ tableView: UITableView, didSelectRowAt indexPath: IndexPath) {
        let product = ProductViewController()
        product.productID = productIDs[indexPath.row]
        navigationController?.pushViewController(product, animated: true)
    }
}

final class ProductViewController: UIViewController {
    var productID = 0
    private let basket = Basket.shared

    @objc func addToBasketTapped() {
        basket.productIDs.append(productID)
        let tabs = view.window?.rootViewController as! UITabBarController
        tabs.selectedIndex = 2
        let basketStack = tabs.selectedViewController as! UINavigationController
        basketStack.pushViewController(CheckoutViewController(), animated: true)
    }
}

final class SceneDelegate: UIResponder, UIWindowSceneDelegate {
    var window: UIWindow?

    func scene(_ scene: UIScene, willConnectTo session: UISceneSession, options connectionOptions: UIScene.ConnectionOptions) {
        guard let windowScene = scene as? UIWindowScene else { return }
        window = UIWindow(windowScene: windowScene)
        window?.rootViewController = UITabBarController()
        window?.makeKeyAndVisible()
    }

    func scene(_ scene: UIScene, openURLContexts URLContexts: Set<UIOpenURLContext>) {
        guard let url = URLContexts.first?.url else { return }
        let parts = url.pathComponents
        if url.host == "product" {
            NotificationCenter.default.post(name: .openProduct, object: nil, userInfo: ["id": Int(parts[1])!])

            let tabs = window?.rootViewController as! UITabBarController
            tabs.selectedIndex = 3
            let order = OrderViewController()
            order.orderID = parts[1]
            (tabs.selectedViewController as! UINavigationController).pushViewController(order, animated: true)
        }
    }

    func scene(_ scene: UIScene, continue userActivity: NSUserActivity) {
        guard let parts = userActivity.webpageURL?.pathComponents, parts.count > 2 else { return }
        if parts[1] == "products" {
            NotificationCenter.default.post(name: .openProduct, object: nil, userInfo: ["id": Int(parts[2]) ?? 0])
        }
    }

<ReferenceReview>

**Most important first.** Three high-severity problems, all about links. Any malformed link **crashes** the app, because untrusted input is force-unwrapped (`Int(parts[1])!`, `parts[1]` on a path with no id, `as! Int`); a crash anyone can trigger with a link is a security problem as well as a quality one. Links that **launch** the app are never handled, because `scene(_:willConnectTo:options:)` ignores its connection options, which explains "opens on Home". And the two link handlers have **already drifted**: product universal links never match (`products` versus `product`), order universal links aren't handled, and bad ids crash in one path and open product 0 in the other.

**The design problem underneath** is that nobody owns navigation. Links are parsed in two places, broadcast through `NotificationCenter` to whichever screen happens to listen, and acted on by code that casts its way into the tab bar by index. Screens build each other and take singletons, so the flow is spread across every file and none of it can be tested.

**How I'd fix it, in small steps:**

1. Add an `AppRoute` enum (`.product(id:)`, `.order(id:)`, …) and one parser that accepts both URL forms, validates every field and returns `nil` on anything else. Unit-test it with good and bad links, and with a round trip from route to URL and back.
2. Route every door through it: `willConnectTo` reads `connectionOptions.urlContexts` and `userActivities`, and `openURLContexts` and `continue` call the same entry handler, which holds a route until the UI is ready.
3. Introduce an app coordinator that owns the tab bar controller (by tab identifier, not index) and a coordinator per tab owning its navigation controller. Its `open(_ route:)` dismisses anything presented, selects the tab and builds the stack with `setViewControllers(_:animated:)`.
4. Delete the `openProduct` notification: the list reports a selected product through a closure, and the Home coordinator pushes it.
5. Give screens their dependencies through their initialisers (`ProductViewController(productID:basket:)`) and outputs as closures (`onAddedToBasket`); the Basket coordinator decides whether to show checkout, once.

**Tests to add:** the parser's table of links (including `shop://product`, `shop://product/abc`, and both hosts); the coordinator's `open(_:)` against a fake navigator for "a sheet is up", "already on the Account tab" and "signed out"; and a UI test that taps a link with the app terminated, which is the case that's broken today.
