"It depends" becomes a decision once you write down what it depends on. Build the scorer behind a weighted decision matrix: options scored against weighted criteria, must-haves that knock an option out whatever its total, and a sensitivity check that tells you whether the winner would survive a small change of heart about the weights.

`QualityDecisionMatrix.decide(_:by:) throws -> Decision`

- An option's score is the **weighted mean** of its scores: Σ(weight × score) ÷ Σ weight. It stays on the same scale as the scores, so a 1–5 matrix gives totals from 1 to 5.
- An option that scores below a criterion's `minimum` is **eliminated**: it goes in `eliminated` (in input order) and isn't ranked.
- `ranking` lists the rest, highest score first. Equal scores are ranked alphabetically by name, so the result never depends on the order you typed the options in.
- Validate before scoring, and throw a `MatrixError`: `.noCriteria` for an empty list, `.invalidWeight` for the first criterion whose weight isn't a finite number above zero, `.missingScore` for the first option (then the first criterion) with no score.

`QualityDecisionMatrix.swingCriteria(_:by:change:) throws -> [String]`

- For each criterion in turn, multiply its weight by `1 + change`, and separately by `1 − change`, leaving every other weight alone. If either gives a different winner, that criterion is a **swing criterion**.
- Return the swing criteria in the order the criteria were given. With no winner (no options, or all eliminated), return `[]`.

## Examples

Criteria: Speed (weight 4), Cost (3), Safety (3). Option P scores 5, 2, 4; option Q scores 3, 5, 4.

| Call | Result |
| --- | --- |
| `decide([P, Q], by: criteria)` | ranking Q (3.9), P (3.8); nothing eliminated |
| the same, with every weight doubled | the same ranking and scores: weights are relative |
| the same, with `minimum: 3` on every criterion | P is eliminated (its Cost is 2), so the ranking is Q alone |
| `swingCriteria([P, Q], by: criteria, change: 0.25)` | `["Speed", "Cost"]`: Speed at 5 or Cost at 2.25 makes P win |
| `swingCriteria([P, Q], by: criteria, change: 0.1)` | `[]`: the decision survives a 10% nudge |
| `decide([P, Q], by: [])` | throws `MatrixError.noCriteria` |

## Constraints

- Scores can be on any scale; the tests use 1–5. Weights are positive and finite, and `0 < change < 1`.
- Criterion names are unique. An option may carry scores for criteria you weren't given; ignore them.
- Compare floating-point scores with `>` and `==` as they are: the tests are built so exact ties are real ties.

<Hints>
<Hint>
Validate everything first, in the order the errors are listed. A missing score that quietly counts as zero is the most common way a real decision matrix lies.
</Hint>
<Hint>
Sort with a comparator that checks the score first and the name second: `$0.score != $1.score ? $0.score > $1.score : $0.name < $1.name`.
</Hint>
<Hint>
`swingCriteria` can reuse `decide`: copy the criteria, replace one with a nudged weight, and compare the new winner with the original.
</Hint>

## Solutions

<Approach title="Validate, score the survivors, then re-decide with each weight nudged" time="O(c × o log o) to decide, c times that for the swing check" space="O(c + o)">

```swift
public static func decide(_ options: [Option], by criteria: [Criterion]) throws -> Decision {
    guard !criteria.isEmpty else { throw MatrixError.noCriteria }
    if let bad = criteria.first(where: { !($0.weight > 0) || !$0.weight.isFinite }) {
        throw MatrixError.invalidWeight(criterion: bad.name)
    }
    for option in options {
        if let missing = criteria.first(where: { option.scores[$0.name] == nil }) {
            throw MatrixError.missingScore(option: option.name, criterion: missing.name)
        }
    }
    let totalWeight = criteria.reduce(0) { $0 + $1.weight }
    var ranking: [Ranked] = []
    var eliminated: [String] = []
    for option in options {
        let failsMinimum = criteria.contains { criterion in
            guard let minimum = criterion.minimum else { return false }
            return option.scores[criterion.name, default: 0] < minimum
        }
        if failsMinimum {
            eliminated.append(option.name)
            continue
        }
        let weighted = criteria.reduce(0) { $0 + $1.weight * option.scores[$1.name, default: 0] }
        ranking.append(Ranked(name: option.name, score: weighted / totalWeight))
    }
    ranking.sort { $0.score != $1.score ? $0.score > $1.score : $0.name < $1.name }
    return Decision(ranking: ranking, eliminated: eliminated)
}

public static func swingCriteria(_ options: [Option], by criteria: [Criterion], change: Double) throws -> [String] {
    guard let winner = try decide(options, by: criteria).winner else { return [] }
    var swings: [String] = []
    for (index, criterion) in criteria.enumerated() {
        for factor in [1 + change, 1 - change] {
            var nudged = criteria
            nudged[index] = Criterion(criterion.name, weight: criterion.weight * factor, minimum: criterion.minimum)
            if try decide(options, by: nudged).winner != winner {
                swings.append(criterion.name)
                break
            }
        }
    }
    return swings
}
```

Must-haves are applied before scoring, not folded into the total: a weighted sum will happily let five excellent scores buy back a fatal one, which is exactly what a knockout criterion exists to stop. The swing check is the honest part of the method. When it comes back empty, the decision is robust and you can stop debating weights; when it names a criterion, that's the one conversation worth having with your team ("is offline support really worth more than migration safety?").

</Approach>
