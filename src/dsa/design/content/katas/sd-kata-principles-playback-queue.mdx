A music app's player grew by subclassing: `ShufflingPlayer`, `RepeatingPlayer`, `ShufflingRepeatingPlayer`, then `FreeTierPlayer` with a skip limit, which nobody can combine with shuffle without a fifth class. Rebuild it by composition. The player holds three parts and knows none of their concrete kinds: an **ordering**, a **repeat mode** and a **skip allowance**.

```swift
// Where the hierarchy was heading: one class per combination
class Player { /* in order, no repeat, unlimited skips */ }
class ShufflingPlayer: Player { }
class RepeatingPlayer: Player { }
class ShufflingRepeatingPlayer: ShufflingPlayer { }   // repeat logic copied from RepeatingPlayer
class FreeTierPlayer: Player { }                       // and shuffled free tier? repeating free tier?
```

Write these in `PrinciplesPlaybackQueue`:

- `InOrder` and `Shuffled(seed:)`, which conform to `Ordering`: `arrange(_:)` returns the order one pass plays in. `Shuffled` draws from `SeededGenerator(seed:)`, so a seed always gives the same order.
- `UnlimitedSkips` and `LimitedSkips(_:)`, which conform to `SkipAllowance`: `useSkip()` says whether this skip is allowed, and counts it if so.
- `Player(tracks:ordering:repeatMode:skips:)` with `current: String?`, `trackDidFinish()` and `skip() -> Bool`.

The player's rules:

- The ordering arranges the tracks **once**, when the player is created; `current` starts at the first track of that order.
- `trackDidFinish()` follows the repeat mode: `.off` moves on and ends after the last track, `.all` wraps round to the same order again, `.one` stays on the current track.
- `skip()` moves on even under `.one`, wrapping only under `.all`. It returns `false`, and changes nothing, when nothing is playing or the allowance says no.

`RepeatMode` is an enum because Apple's three modes are a closed set; orderings and allowances are protocols because new kinds are expected. The tests bring one of each that your player has never seen.

## Examples

| Player | Calls | Result |
| --- | --- | --- |
| `["Intro", "Ocean", "Lights", "Outro"]`, defaults | let it play | `Intro, Ocean, Lights, Outro`, then `current == nil` |
| same tracks, `.all` | let 6 tracks play | `Intro, Ocean, Lights, Outro, Intro, Ocean` |
| same tracks, `.one` | `trackDidFinish()` twice, then `skip()` | stays on `Intro`, then `Ocean` |
| same tracks, `LimitedSkips(2)` | `skip()` three times | `true, true, false`; `current == "Lights"` |
| `["A", "B"]`, `.off` | `skip()` three times | `true, true, false`; `current == nil` |
| 12 tracks, `Shuffled(seed: 7)` | let it play | every track once, in the same order for every player with seed 7 |

## Constraints

- Tracks are plain strings. An empty list gives a player with nothing to play.
- `LimitedSkips` with a limit of zero or less allows no skips.
- A skip refused because nothing is playing doesn't use up the allowance.
- Don't hard-code a shuffled order in your head: the tests only check that a seed is repeatable and plays every track once.

<Hints>
<Hint>
Store the arranged tracks and an optional position. `current` is `position.map { queue[$0] }`, and `nil` means the queue has ended.
</Hint>
<Hint>
Finishing and skipping both need "the position after this one", which differs only in whether `.one` applies. Write that once, as a private helper that wraps for `.all` and returns `nil` at the end otherwise.
</Hint>
<Hint>
Keep the allowance as `private var skips: any SkipAllowance`. Calling a `mutating` method on an existential stored property works in a `mutating` function. Check `position` first, so a refused skip with nothing playing never reaches the allowance.
</Hint>
</Hints>

## Solutions

<Approach title="A player that holds its parts" time="O(n) to create, O(1) per call" space="O(n)">

```swift
public struct Player {
    private let queue: [String]
    private let repeatMode: RepeatMode
    private var skips: any SkipAllowance
    private var position: Int?

    public init(tracks: [String], ordering: any Ordering = InOrder(), repeatMode: RepeatMode = .off, skips: any SkipAllowance = UnlimitedSkips()) {
        queue = ordering.arrange(tracks)
        self.repeatMode = repeatMode
        self.skips = skips
        position = queue.isEmpty ? nil : 0
    }

    public var current: String? {
        position.map { queue[$0] }
    }

    public mutating func trackDidFinish() {
        guard let position else { return }
        self.position = repeatMode == .one ? position : self.position(after: position)
    }

    public mutating func skip() -> Bool {
        guard let position, skips.useSkip() else { return false }
        self.position = self.position(after: position)
        return true
    }

    private func position(after position: Int) -> Int? {
        if position + 1 < queue.count { return position + 1 }
        return repeatMode == .all ? 0 : nil
    }
}
```

`Shuffled` is `tracks.shuffled(using: &generator)` with a `SeededGenerator`, and `LimitedSkips` counts down from its limit. Every combination of 2 orderings, 3 repeat modes and 2 allowances (12 subclasses, by the old design) is one type and three small parts. A "smart shuffle" or a parental skip limit is a new part, and `Player` doesn't change.

Notice the three choices: the ordering and the allowance are protocols because the set of kinds is open, while repeat mode is an enum because it's closed and `switch` over it stays exhaustive. `skip()` returns a `Bool` though it changes state: it's a command that reports its outcome, because the caller needs to know whether to show an "out of skips" prompt, and a separate `canSkip` question would split one decision across two calls.

</Approach>
