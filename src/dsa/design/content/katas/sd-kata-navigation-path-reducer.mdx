A shopping app has four tabs, each with its own stack of screens, and at most one sheet over them. Write its navigation as a pure function: given the current `State` and an `Action` (a tap, a link, a sign-in), update the state. Every rule that makes navigation feel right lives here, where a unit test can check it, instead of being scattered through views.

`NavigationPathReducer.reduce(_ state: inout State, _ action: Action)`

`State` holds the `selectedTab`, a path of `Screen`s for every tab in `paths` (an empty path is the tab's root), the presented `sheet`, `isSignedIn`, and a `pendingLink` waiting for sign-in. Every tab always has an entry in `paths`.

**Tab actions** apply to the selected tab, and are all ignored while a sheet is up, because the sheet covers the tabs.

| Action | Effect |
| --- | --- |
| `push(screen)` | appends `screen`, unless it's already the top screen (a double tap pushes once) |
| `pop` | removes the top screen; nothing at the root |
| `popToRoot` | empties the path |
| `replace(screens)` | sets the path to `screens` |
| `select(tab)` | switches to `tab`, keeping every tab's path; selecting the tab that's already selected pops it to its root |

**Sheets.**

| Action | Effect |
| --- | --- |
| `present(sheet)` | shows `sheet`, unless one is already up |
| `dismiss` | removes the sheet; if it was `.signIn`, the pending link is dropped too (the user gave up) |

**Links, and signing in.**

| Action | Effect |
| --- | --- |
| `open(link)` to the `.account` tab while signed out | keeps `link` as `pendingLink` and shows `.signIn` (replacing any other sheet); nothing else changes |
| any other `open(link)` | dismisses any sheet, selects `link.tab`, sets that tab's path to `link.screens`, leaves the other tabs alone, and drops any pending link |
| `signedIn` | sets `isSignedIn`, dismisses `.signIn` if it's up, then opens the pending link, if any |
| `signedOut` | clears `isSignedIn`, empties the account tab's path, drops the pending link and dismisses any sheet |

## Examples

| Actions, from `State()` | Result |
| --- | --- |
| `push(.category("shoes"))`, `push(.product(7))`, `push(.product(7))` | home: `[category shoes, product 7]` |
| `push(.product(7))`, `select(.search)`, `select(.home)`, `select(.home)` | home selected, home's path empty |
| `present(.share(productID: 7))`, `push(.reviews(productID: 7))` | the share sheet is up and home's path is still empty |
| `push(.product(7))`, `open(DeepLink(tab: .account, screens: [.orders]))` | sign-in is up, the link is pending, still on home with `[product 7]` |
| … then `signedIn` | account selected with `[orders]`, home still `[product 7]`, no sheet |
| `open(DeepLink(tab: .account, screens: [.orders]))`, `dismiss`, `signedIn` | signed in, still on home: the link was dropped |

## Constraints

- `reduce` is pure: no side effects, no clocks, nothing global. The tests compare whole `State` values.
- Never remove a key from `paths`; set a tab's path to `[]` instead. `State`'s initialiser fills in every tab, so states built different ways compare equal.
- Only the account tab needs sign-in.

<Hints>
<Hint>
Handle the five tab actions together, behind one `guard state.sheet == nil`. Inside, `let tab = state.selectedTab` and every case edits `state.paths[tab]`.
</Hint>
<Hint>
Write `open` as a private helper. `signedIn` needs it too: once the user has signed in, opening the pending link is the same as opening any link.
</Hint>
<Hint>
In the signed-out account case, return straight after setting `pendingLink` and the sheet. The user hasn't gone anywhere yet, so neither the tab nor any path should change.
</Hint>
</Hints>

## Solutions

<Approach title="One switch, a guard for the tabs, and a shared open" time="O(k) for a path of k screens" space="O(1) extra">

```swift
public static func reduce(_ state: inout State, _ action: Action) {
    switch action {
    case .push, .pop, .popToRoot, .replace, .select:
        guard state.sheet == nil else { return }   // the sheet covers the tabs
        reduceTab(&state, action)
    case .present(let sheet):
        guard state.sheet == nil else { return }
        state.sheet = sheet
    case .dismiss:
        if state.sheet == .signIn { state.pendingLink = nil }
        state.sheet = nil
    case .open(let link):
        open(link, in: &state)
    case .signedIn:
        state.isSignedIn = true
        if state.sheet == .signIn { state.sheet = nil }
        if let link = state.pendingLink {
            state.pendingLink = nil
            open(link, in: &state)
        }
    case .signedOut:
        state.isSignedIn = false
        state.paths[.account] = []
        state.pendingLink = nil
        state.sheet = nil
    }
}

private static func reduceTab(_ state: inout State, _ action: Action) {
    let tab = state.selectedTab
    switch action {
    case .push(let screen):
        guard state.paths[tab]?.last != screen else { return }
        state.paths[tab, default: []].append(screen)
    case .pop:
        _ = state.paths[tab]?.popLast()
    case .popToRoot:
        state.paths[tab] = []
    case .replace(let screens):
        state.paths[tab] = screens
    case .select(let newTab):
        if newTab == tab { state.paths[tab] = [] } else { state.selectedTab = newTab }
    default:
        break
    }
}

private static func open(_ link: DeepLink, in state: inout State) {
    if link.tab == .account && !state.isSignedIn {
        state.pendingLink = link
        state.sheet = .signIn
        return
    }
    state.pendingLink = nil
    state.sheet = nil
    state.selectedTab = link.tab
    state.paths[link.tab] = link.screens
}
```

Because navigation is a value, every rule is a one-line test, and the view layer shrinks to binding `paths[tab]` to each tab's `NavigationStack` and `sheet` to `.sheet(item:)`. The same `open` serves links, notifications, widgets and restoration, which is why "the newest intent wins" and "never push behind a sheet" are true everywhere at once.

</Approach>
