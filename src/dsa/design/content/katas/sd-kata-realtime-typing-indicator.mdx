"Ana is typing…" should appear the moment Ana starts, stay while she types, and vanish when she stops, sends, or her phone goes to sleep mid-sentence, all without a message per keystroke. Build both halves: the **sender**, which turns keystrokes into a few signals, and the **roster**, which shows who's typing and forgets anyone whose signal has gone stale.

`RealtimeTypingIndicator.Sender(refresh:idle:)` with `textChanged(_:at:)`, `messageSent()` and `tick(at:)`, and `RealtimeTypingIndicator.Roster(me:expiry:)` with `received(_:from:at:)`, `messageArrived(from:)`, `typing(at:)` and `summary(at:)`.

**Sender**

- A change to non-empty text sends `.typing` at once if the others don't already think the user is typing.
- While typing continues, it sends `.typing` again only once `refresh` has passed since the last one, so the receiver's expiry never lapses mid-sentence.
- Clearing the field sends `.stopped`, but only if a `.typing` is outstanding.
- `tick(at:)` sends `.stopped` once `idle` has passed since the last keystroke, again only if a `.typing` is outstanding.
- `messageSent()` sends nothing (the message itself clears the indicator for everyone else), and the next keystroke announces typing afresh.

**Roster**

- `.typing` from someone makes them typing until `expiry` after that signal; another `.typing` extends it.
- `.stopped`, or a message from them, clears them at once.
- Signals from `me` (the server echoing your own) are ignored.
- `typing(at:)` lists everyone still typing at that moment, sorted by name.
- `summary(at:)` is `nil` for nobody, then `"Ana is typing…"`, `"Ana and Ben are typing…"`, and for three or more `"Several people are typing…"`.

## Examples

| Calls (`refresh` 3 s, `idle` 5 s, `expiry` 8 s) | Result |
| --- | --- |
| Keystrokes every 0.5 s from 0 to 7.5 s | `.typing` at 0, 3 and 6 s; nothing else |
| `"Hi"` at 10 s, then `tick` at 14.999 s and 15 s | `nil`, then `.stopped` |
| `"H"`, then `""`, then `""` again | `.typing`, `.stopped`, `nil` |
| Roster: Ana `.typing` at 0 s, again at 6 s | Typing at 13 s, not at 14 s |
| Roster: Ben at 0 s, Ana at 0 s, Cal at 2 s; `summary` at 3 s and 9 s | `"Several people are typing…"`, then `"Cal is typing…"` |

## Constraints

- Times are offsets from a fixed start, as `Duration`, and never go backwards.
- Both types are plain values: no clocks, timers or tasks inside. The app calls `tick(at:)` from its own timer and reads the roster when it renders.
- The ellipsis in the summaries is the single character `…`.

<Hints>
<Hint>
The sender needs three pieces of state: whether a `.typing` is outstanding, when it last sent one, and when the last keystroke was.
</Hint>
<Hint>
The roster can store, per person, the moment their indicator expires. Reading filters by `now < expiresAt`, so expiry needs no timer at all.
</Hint>
</Hints>

## Solutions

<Approach title="A throttled sender and a roster of deadlines" time="O(1) per keystroke; O(n log n) to list n typists" space="O(people in the conversation)">

```swift
public mutating func textChanged(_ text: String, at now: Duration) -> Signal? {
    guard !text.isEmpty else { return stop() }
    lastKeystrokeAt = now
    if announced, let last = lastSignalAt, now - last < refresh {
        return nil
    }
    announced = true
    lastSignalAt = now
    return .typing
}

public mutating func tick(at now: Duration) -> Signal? {
    guard announced, now - lastKeystrokeAt >= idle else { return nil }
    return stop()
}

private mutating func stop() -> Signal? {
    guard announced else { return nil }
    announced = false
    lastSignalAt = nil
    return .stopped
}
```

The roster keeps `typingUntil: [String: Duration]`: `.typing` sets `now + expiry`, `.stopped` and a message remove the entry, and `typing(at:)` is `typingUntil.filter { now < $0.value }.keys.sorted()`.

The numbers are related on purpose. The expiry (8 s) is longer than two refresh intervals (3 s each) plus some latency, so one lost refresh doesn't make the indicator blink off while Ana is still typing; and because the receiver expires signals itself, the indicator is correct even when a `.stopped` never arrives because her app was suspended first. That's what at-most-once delivery looks like when it's designed for: every signal is optional, and the system converges anyway.

A long-lived roster for a busy group should also drop expired entries now and then, so the dictionary doesn't grow with everyone who ever typed.

</Approach>
