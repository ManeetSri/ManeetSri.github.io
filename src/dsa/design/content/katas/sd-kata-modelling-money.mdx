A shop app sells in several countries, and today its prices are `Double`s with a separate currency `String`. Totals are a penny out, yen show two decimal places, and a basket once added pounds to euros. Build the value object that replaces them: an exact amount in a currency, which refuses bad input on the way in and keeps its rules on the way out.

`ModellingMoney.Currency(code:)`, `ModellingMoney.Money(_:currency:)`, `adding(_:)`, `subtracting(_:)`, `multiplied(by:)`, `allocated(into:)` and `description`

The stub gives you the types, the five supported currencies (`.gbp`, `.eur`, `.usd`, `.jpy`, `.kwd`) with their decimal places, and `Money(minorUnits:currency:)`. Write the rest:

- **`Currency(code:)`** finds a supported currency by code, ignoring case and surrounding whitespace, and throws `Problem.unknownCurrency` with the code exactly as given otherwise. Currency's memberwise initialiser is private, so nobody can invent a currency with seven decimal places.
- **`Money(_ text:currency:)`** parses a plain decimal amount into whole minor units (pence, cents, yen, fils). Surrounding whitespace is ignored; then an optional `-`, one or more ASCII digits, and optionally a `.` followed by one or more digits. Fewer decimal places than the currency has are padded (`"12.5"` is 1250p); more throw `.tooPrecise`. Anything else throws `.notAnAmount`, and an amount too large for an `Int` of minor units throws `.outOfRange`. Each error carries the text exactly as given.
- **`adding(_:)` and `subtracting(_:)`** work only within one currency, and throw `.currencyMismatch(receiver's, argument's)` otherwise. **`multiplied(by:)`** multiplies by a whole quantity.
- **`allocated(into parts:)`** splits the amount into `parts` amounts that differ by at most one minor unit, larger ones first, and add up exactly to the original. Fewer than one part gives an empty array.
- **`description`** is the code, a space, then the amount with exactly the currency's decimal places: `"GBP 12.50"`, `"JPY 1200"`, `"KWD 1.250"`, `"GBP -0.05"`. It's for logs and debugging; the UI formats money with `FormatStyle` and the user's locale.

## Examples

| Call | Result |
| --- | --- |
| `try Currency(code: " gbp ")` | `.gbp` |
| `try Currency(code: "XYZ")` | throws `.unknownCurrency("XYZ")` |
| `try Money("12.5", currency: .gbp)` | 1250 minor units |
| `try Money("1.25", currency: .kwd)` | 1250 minor units (the dinar has three decimal places) |
| `try Money("12.345", currency: .gbp)` | throws `.tooPrecise("12.345")` |
| `try Money("1,000", currency: .gbp)` | throws `.notAnAmount("1,000")` |
| `try Money("99999999999999999999", currency: .gbp)` | throws `.outOfRange(…)` |
| £12.50 `adding` £0.75 | £13.25 |
| £1 `adding` $1 | throws `.currencyMismatch(.gbp, .usd)` |
| £10 `allocated(into: 3)` | £3.34, £3.33, £3.33 |
| −£10 `allocated(into: 3)` | −£3.34, −£3.33, −£3.33 |
| ¥100 `allocated(into: 3)` | ¥34, ¥33, ¥33 |

## Constraints

- Keep amounts as `Int` minor units throughout. No `Double`, and no `Decimal` built from a `Double`.
- "Digits" means ASCII `0` to `9`: `"١٢"` (Arabic-Indic digits) and `"½"` aren't amounts here. Parsing what people type in their own locale belongs to `FormatStyle` in the UI, not to this type.
- No grouping separators, no `+` sign, no currency symbols, and no spaces inside the number.
- Ordinary arithmetic on amounts in tests stays well inside `Int`'s range; only parsing has to detect overflow.

<Hints>
<Hint>
For parsing: trim, remove a leading `-` if there is one, then `split(separator: ".", maxSplits: 1, omittingEmptySubsequences: false)`. That gives one piece (no decimal point) or two, and an empty piece means `"12."` or `".5"`.
</Hint>
<Hint>
Pad the fraction with zeros up to the currency's `minorUnitDigits`, join it to the whole part, and read the result with `Int(_:)`. Because you've already checked every character is a digit, `Int(_:)` returning `nil` can only mean overflow.
</Hint>
<Hint>
For allocation, Swift's `/` and `%` truncate towards zero, so `-1000 % 3` is `-1`. Give each part `minorUnits / parts`, then add one unit in the remainder's direction to the first `abs(remainder)` parts.
</Hint>
</Hints>

## Solutions

<Approach title="Integer minor units, checked once at every way in" time="O(n) to parse n characters; O(parts) to allocate" space="O(parts)">

```swift
public init(code: String) throws {
    let normalised = code.trimmingCharacters(in: .whitespacesAndNewlines).uppercased()
    guard let match = Currency.supported.first(where: { $0.code == normalised }) else {
        throw Problem.unknownCurrency(code)
    }
    self = match
}

public init(_ text: String, currency: Currency) throws {
    var rest = Substring(text.trimmingCharacters(in: .whitespacesAndNewlines))
    let isNegative = rest.first == "-"
    if isNegative { rest = rest.dropFirst() }

    let pieces = rest.split(separator: ".", maxSplits: 1, omittingEmptySubsequences: false)
    let whole = pieces[0]
    let fraction = pieces.count == 2 ? pieces[1] : ""
    let isDigits = { (piece: Substring) in !piece.isEmpty && piece.allSatisfy { $0.isASCII && $0.isNumber } }
    guard isDigits(whole), pieces.count == 1 || isDigits(fraction) else { throw Problem.notAnAmount(text) }
    guard fraction.count <= currency.minorUnitDigits else { throw Problem.tooPrecise(text) }

    let padded = fraction + String(repeating: "0", count: currency.minorUnitDigits - fraction.count)
    guard let magnitude = Int(whole + padded) else { throw Problem.outOfRange(text) }
    self.init(minorUnits: isNegative ? -magnitude : magnitude, currency: currency)
}

public func adding(_ other: Money) throws -> Money {
    guard currency == other.currency else { throw Problem.currencyMismatch(currency, other.currency) }
    return Money(minorUnits: minorUnits + other.minorUnits, currency: currency)
}

public func allocated(into parts: Int) -> [Money] {
    guard parts >= 1 else { return [] }
    let share = minorUnits / parts
    let leftover = minorUnits % parts
    let step = leftover < 0 ? -1 : 1
    return (0..<parts).map { index in
        Money(minorUnits: share + (index < abs(leftover) ? step : 0), currency: currency)
    }
}

public var description: String {
    let sign = minorUnits < 0 ? "-" : ""
    let magnitude = minorUnits.magnitude
    let places = currency.minorUnitDigits
    guard places > 0 else { return "\(currency.code) \(sign)\(magnitude)" }
    let divisor = (0..<places).reduce(UInt(1)) { result, _ in result * 10 }
    let fraction = String(magnitude % divisor)
    let paddedFraction = String(repeating: "0", count: places - fraction.count) + fraction
    return "\(currency.code) \(sign)\(magnitude / divisor).\(paddedFraction)"
}
```

`subtracting(_:)` mirrors `adding(_:)`, and `multiplied(by:)` multiplies `minorUnits`.

Every way to make a `Money` either takes minor units you already trust or goes through the parser, and every way to combine two refuses a currency mismatch. So code that holds a `Money` never has to ask whether it's valid. `description` uses `magnitude`, an unsigned value, so even the most negative amount prints without overflowing.

Why allocate instead of dividing? `£10 / 3` has no exact answer in pence, and rounding each share gives £3.33 × 3 = £9.99: a penny vanishes, and the bill doesn't add up. Allocation (Martin Fowler's name for it) decides where the leftover pennies go, so splitting a bill, spreading a discount across order lines or paying in instalments always sums to the original. Real systems often allocate *by ratio* too, such as a discount spread across lines in proportion to their prices; it's the same idea with weights.

An `Int` of minor units holds amounts up to about 92 thousand trillion pounds, which is plenty for an app. `Decimal` is the other sound choice: it's what StoreKit uses for `Product.price`, it handles any number of decimal places, and it's slower and fussier to build correctly. Either works, as long as the currency travels with the amount.

</Approach>
