An editor's undo is a history of its document: every change can be stepped back and forward through, the Edit menu names what Undo will do, and a burst of typing undoes in one step, not one letter at a time. Build that history as a generic value type that holds snapshots of any `Equatable` document.

`DocumentEditHistory.History<Document>`, with `apply(_:actionName:coalescing:)`, `undo()`, `redo()`, `current`, `canUndo`, `canRedo`, `undoActionName` and `redoActionName`.

- `init(_ document:limit:)` starts with nothing to undo or redo. `limit` is the most changes that can be undone.
- **`apply`** makes the new document `current`, records the previous one so it can be undone under `actionName`, and clears everything that could be redone. A document equal to `current` isn't a change: nothing is recorded and redo is kept.
- **`undo()`** steps back one change and makes it redoable; **`redo()`** steps forward again. With nothing to step to, they do nothing.
- **Names.** `undoActionName` is the name of the change `undo()` would revert, and `redoActionName` the one `redo()` would reapply, or `nil`.
- **Coalescing.** With `coalescing: true`, a change joins the previous one, so a single undo reverts both, when that previous change was also coalescing, had the same name, and nothing has been undone or redone since. Otherwise it's recorded as a change of its own.
- **Limit.** When more than `limit` changes are recorded, the oldest are forgotten.

## Examples

| Steps, from `History("")` | `current` afterwards |
| --- | --- |
| apply `"Milk"`, apply `"Milk, eggs"`, undo | `"Milk"` |
| …then undo, redo | `""`, then `"Milk"` |
| apply `"a"`, apply `"ab"`, undo, apply `"ax"`, redo | `"ax"`: the new change cleared the redo history |
| apply `"H"`, `"He"`, `"Hel"`, `"Hello"`, all named Typing and coalescing, then undo | `""`: four keystrokes, one step |
| apply `"Hello"` as Bold, `"Hello world"` as Paste | `undoActionName` is `"Paste"` |
| `History(0, limit: 2)`, apply 1, 2, 3, 4, undo, undo, undo | `2`: only two changes were kept |

## Constraints

- `limit` is zero or more; negative limits behave like zero.
- `Document` is any `Equatable & Sendable` type. The tests use `String`, `Int` and a small struct.
- Keep whole snapshots, not diffs: copy-on-write makes copies of Swift strings and arrays cheap until they're changed.

<Hints>
<Hint>
Keep two stacks of entries, each a document and an action name: one for undo, one for redo. `undo()` pops from the first and pushes `current` onto the second; `redo()` does the reverse.
</Hint>
<Hint>
For coalescing, remember the name of the last change while it can still absorb the next one, and forget it (set it to `nil`) on undo, redo and any non-coalescing change.
</Hint>
<Hint>
When a coalescing change joins the open one, only `current` changes: the entry on the undo stack already holds the document from before the first keystroke.
</Hint>
</Hints>

## Solutions

<Approach title="Two stacks of snapshots, and an open group for coalescing" time="O(1) per operation, amortised" space="O(limit) snapshots">

```swift
public struct History<Document: Equatable & Sendable>: Sendable {
    private struct Entry: Sendable {
        let document: Document
        let actionName: String
    }

    public private(set) var current: Document
    public let limit: Int
    private var undoStack: [Entry] = []
    private var redoStack: [Entry] = []
    /// The name of the last change while it can still absorb the next coalescing one
    private var openGroup: String?

    public init(_ document: Document, limit: Int = 100) {
        current = document
        self.limit = max(0, limit)
    }

    public var canUndo: Bool { !undoStack.isEmpty }
    public var canRedo: Bool { !redoStack.isEmpty }
    public var undoActionName: String? { undoStack.last?.actionName }
    public var redoActionName: String? { redoStack.last?.actionName }

    public mutating func apply(_ document: Document, actionName: String, coalescing: Bool = false) {
        guard document != current else { return }
        redoStack.removeAll()
        if coalescing, openGroup == actionName, !undoStack.isEmpty {
            current = document
            return
        }
        undoStack.append(Entry(document: current, actionName: actionName))
        if undoStack.count > limit {
            undoStack.removeFirst(undoStack.count - limit)
        }
        current = document
        openGroup = coalescing ? actionName : nil
    }

    public mutating func undo() {
        guard let entry = undoStack.popLast() else { return }
        redoStack.append(Entry(document: current, actionName: entry.actionName))
        current = entry.document
        openGroup = nil
    }

    public mutating func redo() {
        guard let entry = redoStack.popLast() else { return }
        undoStack.append(Entry(document: current, actionName: entry.actionName))
        current = entry.document
        openGroup = nil
    }
}
```

The entry that undo pushes onto the redo stack keeps the *same* name as the change it reverts, which is why "Undo Paste" becomes "Redo Paste". Ending the open group on undo and redo stops a keystroke after an undo from silently merging into a change the user already stepped back from. `removeFirst` is O(n) in the stack's length, but it runs at most once per change and only at the limit; a ring buffer would make it O(1) if the limit were large. This is the same model `UndoManager` gives you with groups and action names; owning it as a value type makes it trivial to test and to keep per document.

</Approach>
