Signing in with a code sent by text message looks simple until real users meet it: they double-tap Verify, the "code sent" answer arrives after they've gone back to change the number, and someone guesses codes until they get lucky. Model the flow as an enum state machine: a pure function from the current state and an event to the next state, which refuses anything the flow doesn't allow.

`OneTimeCodeSignIn.next(_ state: State, on event: Event) -> State?`

Return the next state, or `nil` when the machine refuses the event. These are the only transitions:

| From | Event | To |
| --- | --- | --- |
| `enteringPhone` | `submitPhone(text)`, a valid number | `sendingCode(phone:)`, with the number's spaces removed |
| `sendingCode(phone)` | `codeSent` | `enteringCode(phone:attemptsLeft:)`, with `maxAttempts` (3) |
| `sendingCode` | `sendFailed` | `enteringPhone` |
| `enteringCode(phone, n)` | `submitCode(text)`, a valid code | `verifying(phone:attemptsLeft:)` with `n - 1`: submitting uses an attempt |
| `enteringCode` | `changeNumber` | `enteringPhone` |
| `verifying(phone, _)` | `codeAccepted` | `signedIn(phone:)` |
| `verifying(phone, n)` | `codeRejected` | `enteringCode(phone, n)` if `n` is above 0, otherwise `lockedOut` |

- A **valid phone number** is `+` followed by 8 to 15 digits once spaces are removed. A **valid code** is exactly six digits. Digits here means the ASCII digits `0` to `9` only.
- Every other combination of state and event returns `nil`, and so does a valid event with invalid input. `signedIn` and `lockedOut` refuse everything.

## Examples

| Call | Result |
| --- | --- |
| `next(.enteringPhone, on: .submitPhone("+44 7700 900123"))` | `.sendingCode(phone: "+447700900123")` |
| `next(.enteringPhone, on: .submitPhone("07700 900123"))` | `nil`: no country code |
| `next(.enteringCode(phone: p, attemptsLeft: 3), on: .submitCode("004213"))` | `.verifying(phone: p, attemptsLeft: 2)` |
| `next(.verifying(phone: p, attemptsLeft: 2), on: .submitCode("004213"))` | `nil`: a double tap |
| `next(.verifying(phone: p, attemptsLeft: 0), on: .codeRejected)` | `.lockedOut` |
| `next(.enteringPhone, on: .codeAccepted)` | `nil`: a late answer for a number the user abandoned |

## Constraints

- `next` is pure: no timers, no network, no stored state. The screen's shell sends the requests and turns their answers into events.
- The server enforces the real attempt limit; this machine makes sure the app never sends a guess it knows will be refused, and never sends two at once.
- Watch the digits. `Character.isNumber` is true for `٣` (Arabic-Indic three) and `３` (full-width three) too.

## Solutions

<Approach title="Switch over (state, event), refusing by default" time="O(n) to validate the input" space="O(n)">

```swift
public static func next(_ state: State, on event: Event) -> State? {
    switch (state, event) {
    case (.enteringPhone, .submitPhone(let input)):
        guard let phone = normalisedPhone(input) else { return nil }
        return .sendingCode(phone: phone)
    case (.sendingCode(let phone), .codeSent):
        return .enteringCode(phone: phone, attemptsLeft: maxAttempts)
    case (.sendingCode, .sendFailed):
        return .enteringPhone
    case (.enteringCode(let phone, let attemptsLeft), .submitCode(let code)):
        guard isCode(code) else { return nil }
        return .verifying(phone: phone, attemptsLeft: attemptsLeft - 1)
    case (.enteringCode, .changeNumber):
        return .enteringPhone
    case (.verifying(let phone, _), .codeAccepted):
        return .signedIn(phone: phone)
    case (.verifying(let phone, let attemptsLeft), .codeRejected):
        return attemptsLeft > 0 ? .enteringCode(phone: phone, attemptsLeft: attemptsLeft) : .lockedOut
    default:
        return nil
    }
}

private static let digits: ClosedRange<Character> = "0"..."9"

private static func normalisedPhone(_ input: String) -> String? {
    let compact = input.filter { $0 != " " }
    guard compact.first == "+" else { return nil }
    let number = compact.dropFirst()
    guard (8...15).contains(number.count), number.allSatisfy(digits.contains) else { return nil }
    return compact
}

private static func isCode(_ code: String) -> Bool {
    code.count == 6 && code.allSatisfy(digits.contains)
}
```

The table in the statement *is* the code: seven rows, seven cases. Reviewers can check it against a state diagram line by line, and adding a state is a deliberate act.

`default: return nil` is a trade-off. It keeps the switch short, but when you add a new event the compiler won't remind you to decide what each state does with it. With six states and seven events, listing all 42 pairs would bury the seven that matter; the tests that walk late and repeated events are what guard the defaults instead.

The double-tap and late-answer bugs disappear without any `isVerifying` flag or "ignore if cancelled" check: there's no transition for them, so they can't happen.

</Approach>
