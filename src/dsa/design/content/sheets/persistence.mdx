Which store for which data on iOS, and what each costs. The lessons are in [Local persistence options](/design/learn/sd-store-choosing) and [Persistence architecture](/design/learn/sd-persist-repository).

## Pick by the data

| Data | Store | Why |
| --- | --- | --- |
| Small settings, flags, "seen onboarding" | `UserDefaults` | Simple key-value, loaded into memory at launch. Keep it small |
| Tokens, passwords, keys | Keychain | Encrypted, survives reinstall by default, shareable through access groups |
| Encryption keys that must never leave the device | Secure Enclave (P-256 via CryptoKit) | The key can't be exported |
| One document or a small list | Codable file (JSON or property list) | Easy; write atomically; read it all at once |
| Downloaded media, re-fetchable data | Files in Caches | The system may purge them; exclude from backup |
| User-created files | Files in Documents | Backed up; visible in Files if you enable it |
| Thousands of records, queries, relationships | SQLite (GRDB), Core Data or SwiftData | Indexes, partial loads, migrations |
| Data shared with widgets and extensions | App Group container (files, SQLite, `UserDefaults(suiteName:)`) | Same container for every target in the group |
| Synced across the user's devices | CloudKit (`CKSyncEngine`) or your own backend | See [sync backends](/design/learn/sd-sync-backends) |

## The databases compared

| | SQLite with GRDB | Core Data | SwiftData | Realm |
| --- | --- | --- | --- | --- |
| Model | SQL tables, Swift records | Object graph over SQLite | `@Model` classes over Core Data | Object database |
| Concurrency | Pools with serialised writes, readers in parallel | Contexts tied to queues | Model actors and contexts | Thread-confined objects; frozen copies |
| Queries | Full SQL, FTS5 | `NSPredicate`, fetch requests | `#Predicate`, `FetchDescriptor` | Realm query language |
| Observing changes | `ValueObservation` | `NSFetchedResultsController`, notifications | `@Query` in SwiftUI | Notifications |
| Migrations | Explicit, ordered SQL migrations | Lightweight, staged or custom mapping | Schema versions and migration plans | Schema version and migration block |
| Sync | Bring your own | `NSPersistentCloudKitContainer` | CloudKit through its container | Its own (deprecated device sync) |
| Minimum iOS | any | any | 17 | any |
| Strength | Control, SQL power, predictable performance | Mature, faulting, batch operations | Least code in SwiftUI | Fast object access |
| Watch out for | You write the SQL and mapping | Context threading rules, faults | Younger; fewer escape hatches | Third-party dependency, threading model |

## File-system locations

| Directory | Backed up | Purged by the system | Use for |
| --- | --- | --- | --- |
| `Documents` | yes | no | What the user made |
| `Library/Application Support` | yes | no | Databases, app state |
| `Library/Caches` | no | yes, under storage pressure | Re-fetchable data |
| `tmp` | no | yes, at any time | Scratch files |
| App Group container | yes | no | Shared with extensions |

Set `isExcludedFromBackup` on large re-downloadable files outside Caches.

## Data protection classes

| Class | Readable | Use for |
| --- | --- | --- |
| `.complete` | only while the device is unlocked | Sensitive files that background work never needs |
| `.completeUnlessOpen` | files already open stay open after locking | Downloads that must finish after locking |
| `.completeUntilFirstUserAuthentication` (default) | after the first unlock since boot | Most app data, including what background tasks read |
| `.none` | always | Rarely justified |

Keychain items have matching accessibility values: `WhenUnlocked`, `AfterFirstUnlock`, and the `ThisDeviceOnly` variants that never migrate to a new device.

## Repository rules of thumb

- The rest of the app sees domain models, never `NSManagedObject`, `@Model` objects or rows.
- One repository per aggregate, not per table.
- Reads return values or streams of values; writes take intent ("mark read"), not whole objects.
- Migrations are tested against copies of real old databases.
- Paging from disk uses keyset queries (`WHERE date < ?`), not `OFFSET`, for large tables.
- Keep the database off the main thread; publish results to the main actor.

## Limits worth remembering

| Store | Limit |
| --- | --- |
| `UserDefaults` | No hard limit, but everything loads at launch; keep it to kilobytes |
| `NSUbiquitousKeyValueStore` | 1 MB total, 1,024 keys |
| Keychain | Small secrets only; reads are slow-ish (milliseconds) |
| CloudKit record | 1 MB of fields; larger data goes in `CKAsset` |
| App Group `UserDefaults` | Same as `UserDefaults`; writes from two processes can race |
