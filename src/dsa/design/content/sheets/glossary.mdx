The terms used in this course, in plain words. Each is defined the way the course uses it.

## A–C

| Term | Meaning |
| --- | --- |
| A/B test | Showing two variants to random groups of users and comparing a metric |
| ABR (adaptive bitrate) | A video player switching between quality levels as bandwidth changes |
| Accidental complexity | Complexity we added through our choices, as opposed to what the problem demands |
| Actor | A Swift type that protects its state by running one task at a time; callers outside use `await` |
| Actor reentrancy | While an actor awaits, other calls can run on it, so state can change across an `await` |
| ADR (architecture decision record) | A short document recording one decision, its context and its consequences |
| Afferent coupling | How many modules depend on this one (incoming) |
| Aggregate | A cluster of domain objects changed together through one root, keeping its invariants |
| APNs | Apple Push Notification service, which delivers remote notifications to devices |
| App Attest | An Apple service that lets a server check requests come from a genuine copy of your app |
| App Group | A shared container that an app and its extensions can all read and write |
| Associated type | A placeholder type in a protocol, filled in by each conforming type |
| At-least-once delivery | Every message arrives, possibly more than once; receivers must de-duplicate |
| ATS (App Transport Security) | iOS's default requirement for HTTPS with modern TLS |
| ATT (App Tracking Transparency) | The prompt required before tracking users across other companies' apps and websites |
| Availability | The fraction of time a system works, often written in "nines" |
| Backpressure | A consumer slowing down a producer that's sending faster than it can handle |
| Backoff | Waiting longer between successive retries |
| BFF (backend for frontend) | A server layer shaped for one client's screens, aggregating other services |
| Bounded context | A part of the domain with its own consistent model and language |
| Bulkhead | Isolating resources so one failing part can't exhaust everything |
| C4 model | Diagrams at four zoom levels: context, container, component, code |
| Cache-aside | The app checks the cache, and on a miss loads from the source and fills the cache |
| Cache stampede | Many requests missing the cache at once and all hitting the source |
| CAP theorem | When the network partitions, a distributed store must choose consistency or availability |
| Characterisation test | A test that pins down what existing code does today, before you change it |
| Circuit breaker | Stops calling a failing dependency for a while, then tries again carefully |
| Clean Architecture | Layers with dependencies pointing inward to the domain and use cases |
| Cohesion | How strongly the parts of a module belong together |
| Command–query separation | A method either changes state or returns data, not both |
| Composition root | The one place where the app's object graph is built and wired |
| Connascence | A measure of coupling: what must change together, and how strongly |
| Consistent hashing | Mapping keys to nodes so adding or removing a node moves few keys |
| Continuation | A bridge that lets callback-based code resume an `async` caller |
| Coordinator | An object that owns navigation for a flow, so view controllers don't push each other |
| CQRS | Separate models for writing (commands) and reading (queries) |
| CRDT | A data type whose replicas can be merged in any order and still converge |
| Cursor pagination | Fetching the next page with an opaque token from the previous one, not a page number |

## D–H

| Term | Meaning |
| --- | --- |
| Data protection class | The rule for when a file's encryption key is available (while unlocked, after first unlock…) |
| Dead-letter queue | Where messages go after failing too many times, for inspection |
| Debounce | Waiting for input to pause before acting on it |
| Delta sync | Sending only what changed since the last sync, usually with a change token |
| Dependency injection | Giving an object what it needs from outside, instead of it creating or finding it |
| Dependency inversion | High-level policy and low-level detail both depend on an abstraction the policy owns |
| Dependency rule | In Clean Architecture, source code dependencies point only inward |
| Diffable data source | A UIKit data source driven by snapshots of identifiers, which animates the changes |
| Domain event | A record that something meaningful happened in the domain ("order placed") |
| DTO (data transfer object) | A type shaped for the wire or storage, mapped to and from domain types |
| Efferent coupling | How many modules this one depends on (outgoing) |
| Entity | A domain object with an identity that persists as its attributes change |
| Error budget | How much unreliability an SLO allows, spent on releases and incidents |
| Essential complexity | Complexity that comes from the problem itself |
| ETag | A version tag for a response, used to ask "has it changed?" |
| Event sourcing | Storing the sequence of events and deriving state from them |
| Eventual consistency | Replicas may disagree for a while, but converge when updates stop |
| Exactly-once | The effect of a message happens once; in practice at-least-once plus idempotency |
| Existential (`any`) | A box that can hold any value conforming to a protocol, with dynamic dispatch |
| Facade | One simple interface in front of a complicated subsystem |
| Fan-out | Delivering one event to many recipients; on write (precomputed) or on read |
| Feature flag | A runtime switch that turns code paths on or off without a release |
| Fitness function | An automated check that an architectural property still holds |
| Functional core, imperative shell | Pure logic in the middle, side effects at the edges |
| Global actor | An actor that isolates code across many types, such as `@MainActor` |
| GRASP | Principles for assigning responsibilities to objects |
| Graceful degradation | Keeping core features working when parts of the system fail |
| Hexagonal architecture | The core talks to the world through ports; adapters implement them |
| Hitch | A frame that arrives late, so motion visibly stutters |
| HLS | HTTP Live Streaming: video cut into small segments listed in playlists |
| Hot partition | One shard receiving far more traffic than the others |

## I–O

| Term | Meaning |
| --- | --- |
| Idempotency | Doing something twice has the same effect as doing it once |
| Idempotency key | A unique id sent with a request so the server can recognise retries |
| Information hiding | Keeping a module's decisions inside it, so they can change without affecting others |
| Interceptor | A step in a request pipeline that can change requests or responses (auth, logging, retry) |
| Invariant | A condition that must always hold for a type or system |
| Jetsam | iOS ending apps to reclaim memory |
| Jitter | Randomness added to retry delays so clients don't retry in sync |
| JWT | A signed token carrying claims, such as who the user is and when it expires |
| Keyset pagination | Paging by "items after this key", stable under inserts |
| Kill switch | A remote flag that turns a feature off quickly when it misbehaves |
| Law of Demeter | Talk only to your immediate collaborators, not their collaborators |
| Leaky abstraction | An abstraction that forces callers to know the details it was meant to hide |
| Live Activity | Glanceable, updating content on the Lock Screen and Dynamic Island |
| Load balancer | Spreads requests across servers and stops sending to unhealthy ones |
| Long polling | The server holds a request open until it has news or a timeout |
| LRU | Evicting the least recently used entry first |
| Main actor | The global actor for the main thread, where UI work must happen |
| Massive View Controller | A view controller that has absorbed networking, logic and navigation |
| Mediator | An object that coordinates others so they don't refer to each other directly |
| MetricKit | Apple's framework delivering on-device performance and diagnostic reports |
| Microkernel | A small core with features added as plugins |
| Modular monolith | One deployable unit split into modules with enforced boundaries |
| MVVM | Model–View–ViewModel: a view model exposes presentation state for the view |
| Normalisation | Storing each entity once by id and referring to it elsewhere by id |
| Observer | Objects subscribing to be told when something changes |
| OIDC (OpenID Connect) | An identity layer on OAuth 2.0 that adds an ID token about the user |
| Optimistic UI | Showing the result of an action before the server confirms it |
| OR-set | A CRDT set where adds win over concurrent removes |
| Outbox | A local queue of changes waiting to be sent, kept until the server confirms |

## P–S

| Term | Meaning |
| --- | --- |
| PACELC | Even without partitions, a distributed store trades latency against consistency |
| Passkey | A phishing-resistant credential based on a key pair, synced through iCloud Keychain |
| Phased release | Rolling an App Store update out to a growing percentage of users over seven days |
| Pinning | Accepting only specific certificates or public keys for a server |
| PKCE | An OAuth extension proving the app that started sign-in is the one finishing it |
| Port | An interface the core defines for something it needs from outside |
| Presigned URL | A time-limited URL that lets a client upload or download directly from object storage |
| Primitive obsession | Using raw strings and integers where a domain type would prevent mistakes |
| Privacy manifest | A file declaring the data an app or SDK collects and its required-reason API use |
| Protocol witness | The concrete implementation a type provides for a protocol requirement |
| Pub/sub | Publishers send to topics; every subscriber to the topic receives a copy |
| QoS | Quality of service: the priority class of GCD work |
| Quorum | Enough replicas (R, W out of N) agreeing that reads see the latest write when R + W > N |
| Rate limiting | Capping how many requests a client may make in a period |
| Read-your-writes | A guarantee that you see your own updates immediately |
| Reducer | A pure function `(state, action) -> state` (plus effects, in some architectures) |
| Replication | Keeping copies of data on several machines |
| Repository | An abstraction over where data comes from, speaking the domain's language |
| Responder chain | UIKit's path for events from the first responder up through views and controllers |
| RIBs | Uber's architecture of routers, interactors and builders arranged in a tree |
| Run loop | The loop on a thread that waits for events and dispatches them |
| Saga | A multi-step business transaction with compensating steps for failures |
| Sample-ratio mismatch | Experiment groups that are not the sizes you intended, a sign of a bug |
| Scene | One instance of an app's UI, such as a window on iPad |
| SDUI (server-driven UI) | The server describes screens; the app renders them from components |
| Seam | A place where you can change behaviour without editing the code there, such as a protocol |
| Sendable | A type whose values can safely cross between concurrent contexts |
| Service locator | A global registry objects ask for dependencies (hides them; prefer injection) |
| Sharding | Splitting data across machines by a key |
| Single source of truth | Each piece of state has exactly one owner; everything else derives from it |
| Single-flight | Concurrent requests for the same thing share one in-flight call |
| SLI / SLO / SLA | What you measure / the target for it / the contract with consequences |
| SOLID | Five design principles: single responsibility, open–closed, Liskov, interface segregation, dependency inversion |
| SSE (server-sent events) | A one-way stream of events from server to client over HTTP |
| Stale-while-revalidate | Serving a cached value while fetching a fresh one in the background |
| Strangler fig | Replacing a system piece by piece, routing each part to the new version as it's ready |
| Structured concurrency | Child tasks that can't outlive their parent scope, with automatic cancellation |
| Structural identity | SwiftUI identifying a view by its position in the view tree |

## T–Z

| Term | Meaning |
| --- | --- |
| TCA | The Composable Architecture: reducers, effects and dependencies with exhaustive testing |
| Technical debt | The future cost of shortcuts taken now |
| Temporal coupling | Code that only works if things happen in a particular order |
| Test double | A stand-in for a real dependency in tests: dummy, stub, spy, mock or fake |
| Throttle | Acting at most once per interval, however often input arrives |
| Token bucket | A rate limiter that refills tokens at a fixed rate and spends one per request |
| Tombstone | A marker that an item was deleted, kept so the deletion syncs |
| TTL | Time to live: how long an entry stays valid |
| Type erasure | Hiding a concrete generic type behind a wrapper or an existential |
| Unidirectional data flow | Actions flow to state, state flows to views, never the other way |
| Universal link | An `https` link that opens your app when installed, verified by your domain |
| Use case (interactor) | One application operation, holding the rules for it |
| Value object | A domain value defined only by its attributes, such as money or an email address |
| Vector clock | Per-replica counters that tell whether two changes are ordered or concurrent |
| VIPER | View, interactor, presenter, entity, router: strict roles for each screen |
| Visibility timeout | How long a queue hides a delivered message before offering it again |
| WebSocket | A persistent two-way connection between app and server |
| Widget timeline | The entries a widget will show over time, provided ahead to WidgetKit |
| YAGNI | You aren't gonna need it: don't build for imagined future needs |
