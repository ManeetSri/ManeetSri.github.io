Methods, status codes and caching headers, with what an iOS client should do about each. The lessons are [REST for mobile](/design/learn/sd-api-rest-basics), [HTTP caching headers](/design/learn/sd-cache-http-headers) and [URLCache](/design/learn/sd-cache-urlcache).

## Methods

| Method | Use | Safe | Idempotent | Safe to retry automatically? |
| --- | --- | --- | --- | --- |
| GET | Read a resource | yes | yes | yes |
| HEAD | Headers only (size, ETag) | yes | yes | yes |
| PUT | Replace a resource at a known URL | no | yes | yes |
| DELETE | Remove a resource | no | yes | yes (a second delete may return 404) |
| POST | Create, or run an action | no | no | only with an idempotency key the server honours |
| PATCH | Partial update | no | not by default | only if the patch is idempotent or keyed |
| OPTIONS | CORS preflight, capabilities | yes | yes | yes |

## Status codes and the client's response

| Code | Meaning | What the app should do |
| --- | --- | --- |
| 200 OK | Success with a body | Decode and use |
| 201 Created | A resource was created | Use the returned resource or `Location` |
| 202 Accepted | Work queued, not done | Show pending; poll or wait for a push |
| 204 No Content | Success, no body | Don't try to decode a body |
| 206 Partial Content | A byte range was returned | Resume downloads and stream media |
| 301 / 308 | Moved permanently | URLSession follows; update stored URLs |
| 302 / 307 | Moved temporarily | URLSession follows; 307 keeps the method and body |
| 304 Not Modified | Your cached copy is still valid | Use the cache (URLCache does this for you) |
| 400 Bad Request | The request is malformed | A bug: log it, don't retry |
| 401 Unauthorized | Missing or expired credentials | Refresh the token once, replay; if that fails, sign out |
| 403 Forbidden | Authenticated but not allowed | Don't retry; explain or hide the feature |
| 404 Not Found | No such resource | Remove it locally; don't retry |
| 409 Conflict | Version conflict or duplicate | Fetch the latest and merge, or ask the user |
| 410 Gone | Removed for good | Delete locally; for an API version, force an update |
| 412 Precondition Failed | `If-Match` didn't match | Someone else changed it: refetch and merge |
| 413 Content Too Large | Body too large | Compress, chunk, or reject before uploading |
| 422 Unprocessable Content | Validation failed | Show the field errors |
| 426 Upgrade Required | This app version is too old | Show the update screen |
| 429 Too Many Requests | Rate limited | Wait for `Retry-After`, then back off with jitter |
| 500 Internal Server Error | Server bug | Retry idempotent requests with backoff, a few times |
| 502 / 504 | Gateway or upstream failure | Retry with backoff |
| 503 Service Unavailable | Overloaded or down | Respect `Retry-After`; degrade gracefully |

Retry only what's idempotent, cap the attempts, add jitter, and give up quickly when the user is waiting. See [Retry with exponential backoff and jitter](/design/learn/sd-resilience-retry-backoff).

## Caching headers

| Header | Direction | What it does |
| --- | --- | --- |
| `Cache-Control: max-age=60` | response | Fresh for 60 s; use without asking |
| `Cache-Control: no-cache` | response | Store, but revalidate before every use |
| `Cache-Control: no-store` | response | Never store (tokens, personal data) |
| `Cache-Control: private` | response | Only the device may cache it, not a CDN |
| `Cache-Control: public, s-maxage=300` | response | CDNs may cache for 300 s |
| `Cache-Control: stale-while-revalidate=30` | response | Serve stale up to 30 s while refreshing |
| `Cache-Control: immutable` | response | Never changes (versioned asset URLs) |
| `ETag: "abc123"` | response | A version tag for the representation |
| `If-None-Match: "abc123"` | request | "Send it only if it changed": 304 if not |
| `Last-Modified` / `If-Modified-Since` | both | The same with dates; weaker than ETags |
| `If-Match: "abc123"` | request | Update only if unchanged: 412 if someone else changed it |
| `Vary: Accept-Language` | response | Cache a separate copy per value of that request header |
| `Age` | response | How long a CDN has held it |
| `Expires` | response | Old absolute expiry; `max-age` wins |

**Freshness:** a response is fresh while its age is below `max-age`. Fresh means use it; stale means revalidate with `If-None-Match` and use it if the answer is 304.

**URLCache on iOS:**
- Follows these headers when the request's cache policy is `.useProtocolCachePolicy`, the default.
- Responses larger than about 5% of the disk cache aren't stored, so size it for your largest response.
- `.returnCacheDataElseLoad` ignores freshness, which is useful offline.

## Headers mobile APIs use

| Header | Purpose |
| --- | --- |
| `Authorization: Bearer <token>` | Access token. Never log it |
| `Idempotency-Key: <uuid>` | Lets the server de-duplicate a retried POST |
| `Accept-Encoding: gzip, br` | Compression (URLSession adds and decodes it) |
| `Accept-Language` | Localised content; remember `Vary` |
| `User-Agent` or `X-App-Version` | App version and build, so the server can handle old clients |
| `Retry-After` | Seconds, or a date, to wait after 429 or 503 |
| `Range: bytes=1000-` | Resume a download |
| `traceparent` | Distributed trace id from the device ([tracing](/design/learn/sd-o11y-device-tracing)) |

## HTTP versions

| | HTTP/1.1 | HTTP/2 | HTTP/3 |
| --- | --- | --- | --- |
| Transport | TCP | TCP | QUIC over UDP |
| Requests per connection | one at a time | many, multiplexed | many, multiplexed |
| Head-of-line blocking | per connection | at the TCP level | none between streams |
| Handshake (with TLS 1.3) | 2 round trips | 2 round trips | 1, or 0 on resumption |
| Network changes (Wi-Fi to cellular) | new connection | new connection | connection migration |
| URLSession | yes | yes, automatically | yes, when the server offers it |
