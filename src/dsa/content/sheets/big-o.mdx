Average-case costs unless a row says otherwise. *n* is the number of elements, *k* the key length or value range, *V* and *E* the vertices and edges of a graph. The theory is in [Complexity analysis](/dsa/learn/bigo-notation).

## Data structures

| Structure | Access by position | Search | Insert | Delete | Notes |
| --- | --- | --- | --- | --- | --- |
| Array (`[T]`) | O(1) | O(n) | O(1) amortised at the end; O(n) elsewhere | O(1) at the end; O(n) elsewhere | Contiguous memory: fast scans, cheap indexing |
| Sorted array | O(1) | O(log n) with binary search | O(n) | O(n) | Great when reads far outnumber writes |
| Singly linked list | O(n) | O(n) | O(1) at the head or after a known node | O(1) at the head or after a known node | Removing the tail is O(n) |
| Doubly linked list | O(n) | O(n) | O(1) next to a known node | O(1) for a known node | The basis of an LRU cache |
| Stack | top only | O(n) | push O(1) amortised | pop O(1) | An array with `append` and `popLast` |
| Queue (ring buffer or head index) | front only | O(n) | enqueue O(1) amortised | dequeue O(1) | Never `removeFirst()` on an array: that's O(n) |
| Deque | both ends | O(n) | O(1) amortised at either end | O(1) at either end | swift-collections has `Deque` |
| Hash map / set (`Dictionary`, `Set`) | none | O(1) average, O(n) worst | O(1) average | O(1) average | Keys must be `Hashable`; no order |
| Binary search tree (unbalanced) | none | O(log n) average, O(n) worst | same | same | Sorted input makes it a linked list |
| Balanced BST (AVL, red-black) | none | O(log n) | O(log n) | O(log n) | Keeps keys in order; Swift has none built in |
| Binary heap | min or max only | O(n) | O(log n) | extract O(log n) | Build from an array in O(n); peek is O(1) |
| Trie | none | O(k) | O(k) | O(k) | k is the key length; prefix queries in O(k) |
| Union-find | none | find ≈ O(1) | union ≈ O(1) | not supported | With path compression and union by size: O(α(n)) amortised |
| Segment tree | none | range query O(log n) | point update O(log n) | none | Build O(n); lazy propagation for range updates |
| Fenwick tree | none | prefix query O(log n) | point update O(log n) | none | Smaller and simpler than a segment tree |
| Sparse table | none | range min/max O(1) | none (static) | none | Build O(n log n) |

## Graph representations

| | Space | Is there an edge u→v? | Visit u's neighbours | Best for |
| --- | --- | --- | --- | --- |
| Adjacency list | O(V + E) | O(degree of u) | O(degree of u) | Most graphs: sparse ones |
| Adjacency matrix | O(V²) | O(1) | O(V) | Dense graphs, Floyd–Warshall |
| Edge list | O(E) | O(E) | O(E) | Kruskal, Bellman–Ford |

## Graph algorithms

| Algorithm | Time | Use it for |
| --- | --- | --- |
| BFS / DFS | O(V + E) | Reachability, components, unweighted shortest paths (BFS) |
| Topological sort | O(V + E) | Ordering dependencies in a DAG |
| Dijkstra with a heap | O((V + E) log V) | Shortest paths, no negative edges |
| Bellman–Ford | O(V · E) | Negative edges; detecting negative cycles |
| Floyd–Warshall | O(V³) | All pairs, small V |
| Kruskal / Prim | O(E log E) / O((V + E) log V) | Minimum spanning tree |

## Sorting

| Algorithm | Best | Average | Worst | Extra space | Stable | In place |
| --- | --- | --- | --- | --- | --- | --- |
| Bubble sort | O(n) | O(n²) | O(n²) | O(1) | yes | yes |
| Selection sort | O(n²) | O(n²) | O(n²) | O(1) | no | yes |
| Insertion sort | O(n) | O(n²) | O(n²) | O(1) | yes | yes |
| Merge sort | O(n log n) | O(n log n) | O(n log n) | O(n) | yes | no |
| Quick sort | O(n log n) | O(n log n) | O(n²) | O(log n) stack | no | yes |
| Heap sort | O(n log n) | O(n log n) | O(n log n) | O(1) | no | yes |
| Counting sort | O(n + k) | O(n + k) | O(n + k) | O(n + k) | yes | no |
| Radix sort (LSD) | O(d · (n + b)) | O(d · (n + b)) | O(d · (n + b)) | O(n + b) | yes | no |
| Swift `sort()` | O(n log n) | O(n log n) | O(n log n) | O(n) | yes | in place |

Swift's documentation guarantees its sort is stable. It's an adaptive merge sort (a modified Timsort), so it's also fast on input that's already nearly sorted.

## What n allows

About 10⁸ simple operations a second is a safe estimate for a judge:

| If n is at most | Aim for | Typical techniques |
| --- | --- | --- |
| 10–11 | O(n!) | Every ordering |
| 20–25 | O(2ⁿ) | Every subset, bitmasks, backtracking |
| 500 | O(n³) | Three nested loops, interval DP |
| 5,000 | O(n²) | Two nested loops, 2D DP |
| 10⁵–10⁶ | O(n log n) or O(n) | Sorting, heaps, binary search, hashing, two pointers |
| 10⁹ and up | O(log n) or O(1) | Binary search on the answer, maths |

## Swift's hidden costs

| Looks cheap | Actually | Do this instead |
| --- | --- | --- |
| `string[string.index(…, offsetBy: i)]` | O(i) per access | Convert once: `let chars = Array(string)` |
| `string.count` | O(n) | Store it, or use `chars.count` |
| `array.removeFirst()`, `insert(_, at: 0)` | O(n) | A head index, a ring buffer or a `Deque` |
| `array.contains(x)` in a loop | O(n) each, O(n²) total | Build a `Set` first |
| Mutating a copied array | Copies the whole array once | Keep one owner; pass `inout` |
| `array.map { }.filter { }.reduce { }` | Three passes, two temporary arrays | One loop, or `.lazy` |
| `Array(slice)` | O(length) | Work with indexes into the original |
