## Why it matters

A **palindrome** reads the same forwards and backwards: `"level"`, `"noon"`, `"12321"`. They're among the most common string questions in interviews, and they teach a useful habit: when something is symmetric, work outwards from its middle. Checking one palindrome is a two-pointer exercise you've already met. Finding the **longest palindrome hidden inside a string** is the real challenge, and the technique for it, **expand around centre**, turns an O(n³) search into O(n²) with no extra memory.

## Checking a palindrome

Put one pointer at each end and walk them towards each other, comparing as you go. The first mismatch means it isn't a palindrome:

```swift run
func isPalindrome(_ text: String) -> Bool {
    let chars = Array(text)
    var left = 0
    var right = chars.count - 1
    while left < right {
        if chars[left] != chars[right] {
            return false
        }
        left += 1
        right -= 1
    }
    return true
}

print(isPalindrome("racecar"), isPalindrome("abba"), isPalindrome("abca"), isPalindrome(""))
```

```output
true true false true
```

It's the opposite-ends pattern from [Opposite ends: pair sum and valid palindrome](/dsa/learn/tp-opposite-ends), on an array of characters as [Array(s) and [UInt8] for fast access](/dsa/learn/swift-string-to-array) taught. `String(text.reversed()) == text` gives the same answer in one line, but it builds a whole reversed copy and compares everything, while the pointers stop at the first mismatch.

## The longest palindromic substring

Now the harder question: what's the longest **substring** (contiguous piece) that's a palindrome? In `"abracadabra"` it's `"aca"` (and `"ada"`, which is equally long but starts later). In `"banana"` it's `"anana"`.

The brute force checks every substring: about n²/2 of them, each checked in O(n). That's **O(n³)**: for 2,000 characters, over a billion character comparisons.

```swift run
func longestPalindromeBrute(_ text: String) -> String {
    let chars = Array(text)
    var best = ""
    for start in chars.indices {
        for end in start..<chars.count {
            let piece = Array(chars[start...end])
            if piece.count > best.count && piece == piece.reversed() {
                best = String(piece)
            }
        }
    }
    return best
}

print(longestPalindromeBrute("abracadabra"))
print(longestPalindromeBrute("banana"))
```

```output
aca
anana
```

It's correct and worth keeping for testing. But it wastes effort: checking `"anana"` from scratch ignores that you already knew `"nan"` was a palindrome.

## Every palindrome has a centre

Turn the search round. Instead of checking candidates, **grow** palindromes from the middle out.

- An **odd**-length palindrome is centred on a character: `"racecar"` is centred on its `e`.
- An **even**-length palindrome is centred on the **gap** between two characters: `"abba"` is centred between its two `b`s.

A string of n characters has n characters and n − 1 gaps between neighbours: **2n − 1 centres**. From each centre, step outwards while the characters on both sides match. When they stop matching, or you hit an end, you've found the longest palindrome with that centre. The longest palindrome overall is the longest of those.

Here's every centre of `"abaab"`, with the palindrome it grows:

```swift run
let chars = Array("abaab")

func grow(_ low: Int, _ high: Int) -> String {
    var low = low
    var high = high
    while low >= 0 && high < chars.count && chars[low] == chars[high] {
        low -= 1
        high += 1
    }
    return String(chars[(low + 1)..<high])      // the last pair that matched
}

for i in chars.indices {
    print("on \(i): \"\(grow(i, i))\"", terminator: "   ")
    if i + 1 < chars.count {
        print("after \(i): \"\(grow(i, i + 1))\"")
    } else {
        print()
    }
}
```

```output
on 0: "a"   after 0: ""
on 1: "aba"   after 1: ""
on 2: "a"   after 2: "baab"
on 3: "a"   after 3: ""
on 4: "b"
```

The gap after index 2 grows `"aa"` into `"baab"`, the longest. A gap between two different characters grows nothing: the empty string.

When the loop stops, `low` and `high` point one step **beyond** the palindrome on each side, so the palindrome is `chars[(low + 1)..<high]`, of length `high - low - 1`.

## Expand around centre, in full

The real version keeps only the best start and length, not a string for every centre:

```swift run
func longestPalindrome(_ text: String) -> String {
    let chars = Array(text)
    var bestStart = 0
    var bestLength = 0

    func expand(_ low: Int, _ high: Int) {
        var low = low
        var high = high
        while low >= 0 && high < chars.count && chars[low] == chars[high] {
            low -= 1
            high += 1
        }
        if high - low - 1 > bestLength {
            bestLength = high - low - 1
            bestStart = low + 1
        }
    }

    for centre in chars.indices {
        expand(centre, centre)          // odd length
        expand(centre, centre + 1)      // even length
    }
    return String(chars[bestStart..<bestStart + bestLength])
}

print(longestPalindrome("abracadabra"))
print(longestPalindrome("noonday"))
print(longestPalindrome("banana"))
print(longestPalindrome("ab"))
print(longestPalindrome("").isEmpty)
```

```output
aca
noon
anana
a
true
```

What to notice:

- `expand(centre, centre + 1)` on the last character starts with `high` equal to `chars.count`, so the loop stops at once. No special case needed.
- Centres are tried left to right, and only a **strictly** longer palindrome replaces the best. So for `"abracadabra"`, `"aca"` is found first and `"ada"` doesn't replace it.
- `expand` is a nested function that updates `bestStart` and `bestLength` from the enclosing function, as in [A preview of memoisation](/dsa/learn/rec-memo-preview).

<Callout kind="analogy">
Think of dropping a pebble in a pond. The ripple spreads outwards from where it landed, and it keeps spreading only while the banks on both sides are the same. Expand around centre drops a pebble at every possible middle.
</Callout>

## How fast is it?

Each expansion step either matches a pair and moves outwards, or stops. The worst case is a string of one repeated letter, where every centre expands all the way to an edge:

```swift run
func comparisons(_ text: String) -> Int {
    let chars = Array(text.utf8)
    var count = 0
    func expand(_ low: Int, _ high: Int) {
        var low = low
        var high = high
        while low >= 0 && high < chars.count {
            count += 1
            if chars[low] != chars[high] {
                break
            }
            low -= 1
            high += 1
        }
    }
    for centre in chars.indices {
        expand(centre, centre)
        expand(centre, centre + 1)
    }
    return count
}

print(comparisons(String(repeating: "a", count: 1_000)))
print(comparisons(String(repeating: "abcdefghij", count: 100)))
```

```output
500500
2997
```

1,000 identical letters take 500,500 comparisons, about n²/2. Text with no palindromes longer than one letter takes about 3n: one match and one mismatch per character centre, and one mismatch per gap. So the worst case is **O(n²)** time, with **O(1)** extra space beyond the character array. For 2,000 characters that's a couple of million steps: comfortably fast.

An O(n) algorithm exists, **Manacher's algorithm**, which reuses expansions it has already done on the mirror side of a bigger palindrome. You'll meet it in M63.

## Counting palindromic substrings

The same expansion answers "how many substrings are palindromes?". Every successful step outwards finds one more palindrome, so count the steps instead of measuring them:

```swift run
func countPalindromes(_ text: String) -> Int {
    let chars = Array(text)
    var count = 0
    func expand(_ low: Int, _ high: Int) {
        var low = low
        var high = high
        while low >= 0 && high < chars.count && chars[low] == chars[high] {
            count += 1                  // chars[low...high] is a palindrome
            low -= 1
            high += 1
        }
    }
    for centre in chars.indices {
        expand(centre, centre)
        expand(centre, centre + 1)
    }
    return count
}

print(countPalindromes("abc"))
print(countPalindromes("aaa"))
print(countPalindromes("abba"))
```

```output
3
6
6
```

`"aaa"` has three `"a"`s, two `"aa"`s and one `"aaa"`. `"abba"` has four single letters, `"bb"` and `"abba"`. Substrings at different positions count separately, even when they're the same text.

<Callout kind="gotcha" title="Common mistakes">
- **Forgetting even centres.** With only `expand(i, i)`, `"abba"` gives `"a"`. Every palindrome of even length is centred on a gap.
- **Off by one after the loop.** When the loop ends, `low` and `high` have already moved past the palindrome. It's `low + 1 ..< high`, length `high - low - 1`.
- **Building a `String` at every centre.** That's O(n) work per centre on top of the expansion. Keep a start and a length, and build the string once.
- **Bytes for Unicode text.** `Array(text.utf8)` is faster, and fine when the input is ASCII. For text with accents or emoji, reversing bytes isn't reversing characters; use `Array(text)`.
</Callout>
