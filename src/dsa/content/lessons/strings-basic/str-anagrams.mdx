## Why it matters

A word game shows every word you can make from the same tiles; a spelling tool suggests rearrangements of a typo. Both group words that are **anagrams**: the same letters, the same number of times, in any order. In M08 you checked whether two words are anagrams. Grouping a whole list of them introduces one of the most useful ideas in DSA: the **canonical key**, a value that every member of a group shares, used as a dictionary key. You'll see it again and again in M24, Hashing.

## Two words: a quick recap

Two words are anagrams when their sorted letters are equal, or when their letter counts are equal:

```swift run
func isAnagram(_ a: String, _ b: String) -> Bool {
    a.sorted() == b.sorted()
}

print(isAnagram("listen", "silent"))
print(isAnagram("aab", "abb"))
```

```output
true
false
```

`a.sorted()` returns a sorted `[Character]`, so this compares two arrays. Sorting costs O(L log L) for a word of length L. The counting version from [Frequency counting with 26 slots](/dsa/learn/swift-frequency-arrays) is O(L), and that difference matters more once there are thousands of words.

## A key that every anagram shares

To group many words, you need a **key**: something you can compute from a single word, which is the same for all its anagrams and different for everything else. Then a dictionary from key to words does the grouping in one pass.

Sorting the letters gives such a key. `"stone"`, `"notes"` and `"onset"` all sort to `"enost"`, and no word that isn't their anagram does. The standard library's `Dictionary(grouping:by:)` builds the groups for you:

```swift run
let words = ["stone", "night", "notes", "thing", "onset", "tab", "bat"]
let groups = Dictionary(grouping: words) { String($0.sorted()) }

for key in groups.keys.sorted() {
    print(key, groups[key]!)
}
```

```output
abt ["tab", "bat"]
enost ["stone", "notes", "onset"]
ghint ["night", "thing"]
```

Inside each group, the words keep their input order. But the groups themselves live in a dictionary, which has no order, so the loop sorts the keys to print them the same way every time. Never print a whole dictionary when the output has to be predictable.

## Keeping groups in input order

Problems often want the groups in the order their first word appeared. Don't build the answer from a dictionary's values. Instead, map each key to the **index** of its group in a result array:

```swift run
func groupAnagrams(_ words: [String]) -> [[String]] {
    var groupIndex: [String: Int] = [:]
    var result: [[String]] = []
    for word in words {
        let key = String(word.sorted())
        if let index = groupIndex[key] {
            result[index].append(word)
        } else {
            groupIndex[key] = result.count      // the new group's position
            result.append([word])
        }
    }
    return result
}

print(groupAnagrams(["stone", "night", "notes", "thing", "onset", "tab", "bat"]))
print(groupAnagrams(["a", "a", ""]))
```

```output
[["stone", "notes", "onset"], ["night", "thing"], ["tab", "bat"]]
[["a", "a"], [""]]
```

The dictionary answers "have I seen this key, and where?", and the array keeps the order. Repeated words land in the same group, and the empty word is its own group: it sorts to the empty key.

## Counts as the key

The sorted key costs O(L log L) per word. When the problem promises lowercase letters, a 26-slot count array is an O(L) key. And in Swift, `[Int]` is `Hashable`, so the array itself can be the dictionary key:

```swift run
func letterCounts(_ word: String) -> [Int] {
    var counts = [Int](repeating: 0, count: 26)
    for byte in word.utf8 {
        counts[Int(byte - UInt8(ascii: "a"))] += 1
    }
    return counts
}

print(letterCounts("banana")[0..<3])
print(letterCounts("stone") == letterCounts("notes"))
print(letterCounts("aab") == letterCounts("abb"))

var groupIndex: [[Int]: Int] = [:]
var result: [[String]] = []
for word in ["listen", "google", "silent", "enlist", "banana"] {
    let key = letterCounts(word)
    if let index = groupIndex[key] {
        result[index].append(word)
    } else {
        groupIndex[key] = result.count
        result.append([word])
    }
}
print(result)
```

```output
[3, 1, 0]
true
false
[["listen", "silent", "enlist"], ["google"], ["banana"]]
```

In many languages you'd have to turn the counts into a string like `"1#0#2#..."` before using them as a key. Swift's arrays are hashable whenever their elements are, so you can skip that step.

## What each key costs in Swift

For n words of length up to L:

| Key | Time | Works for | Notes |
| --- | --- | --- | --- |
| `String(word.sorted())` | O(n · L log L) | any characters | sorts `Character` values, which compare Unicode-correctly, and builds a new `String` |
| 26-slot `[Int]` counts | O(n · (L + 26)) | lowercase a–z only | one pass over bytes, then hashing 26 numbers |
| `[Character: Int]` counts | O(n · L) on average | any characters | a dictionary is `Hashable` when its values are, so it can be a key too, but it's the slowest to build |

For short words, as in most interview inputs, the sorted key is perfectly fast and the clearest to read. The count key wins as words grow longer, and its cost per word doesn't depend on sorting at all. Both use O(n · L) space to store the words in their groups.

<Callout kind="gotcha" title="Swift gotcha: a Set loses the counts">
`Set(word)` looks like a tempting key, but it only records **which** letters appear, not how many times:

```swift run
print(Set("aab") == Set("abb"))
print("aab".sorted() == "abb".sorted())
```

```output
true
false
```

`"aab"` and `"abb"` aren't anagrams, but their sets are equal. A key must capture everything that makes two words anagrams: the letters **and** their counts.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **Printing or returning `dictionary.values` when order matters.** It comes out in an unpredictable order. Map keys to indexes in an array instead.
- **Forgetting case.** `"Listen"` and `"silent"` sort differently because `L` and `l` are different characters. If the problem ignores case, lowercase every word first.
- **Using byte arithmetic without the guarantee.** `byte - UInt8(ascii: "a")` traps for any byte below 97, such as a capital letter or a space.
</Callout>
