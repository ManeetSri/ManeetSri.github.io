## Why it matters

**Run-length encoding** replaces each run of repeated characters with the character and the run's length: `"aaabccdddd"` becomes `"a3b1c2d4"`. It's the simplest compression there is, and it's still used where data has long runs: fax machines, some image formats, and level maps in games. M08 built the encoder. Interview versions add three twists: counts of 10 or more, decoding, and compressing a character array **in place**. Each one is a small lesson in careful index work.

## Encoding, with long runs

The encoder from [Building strings efficiently](/dsa/learn/swift-building-strings) uses two indexes: `i` marks the start of a run and `j` runs ahead to its end. Because the count is written with `String(j - i)`, runs of 10 or more get several digits automatically:

```swift run
func encode(_ text: String) -> String {
    let chars = Array(text)
    var result = ""
    var i = 0
    while i < chars.count {
        var j = i
        while j < chars.count && chars[j] == chars[i] {
            j += 1
        }
        result.append(chars[i])
        result += String(j - i)
        i = j
    }
    return result
}

print(encode("aaabccdddd"))
print(encode(String(repeating: "z", count: 12) + "y"))
```

```output
a3b1c2d4
z12y1
```

`j` visits every character exactly once, so the nested loops are still **O(n)** in total.

## Decoding: counts can have several digits

Decoding reads a character, then **all** the digits that follow it, building the count the way [Converting characters, digits and numbers](/dsa/learn/swift-char-digit-conversion) parsed numbers: multiply what you have by 10 and add the new digit. A run is complete when the next letter arrives, or when the text ends.

```swift run
func decode(_ encoded: String) -> String {
    var result = ""
    var current: Character? = nil
    var count = 0
    for ch in encoded {
        if let digit = ch.wholeNumberValue {
            count = count * 10 + digit
        } else {
            if let letter = current {
                result += String(repeating: letter, count: count)
            }
            current = ch
            count = 0
        }
    }
    if let letter = current {
        result += String(repeating: letter, count: count)   // the last run
    }
    return result
}

print(decode("a3b1c2d4"))
print(decode("z12y1"))
print(decode("").isEmpty)
```

```output
aaabccdddd
zzzzzzzzzzzzy
true
```

What to notice:

- `current` is optional because, before the first letter, there's no run to finish.
- The last run has no letter after it to trigger it, so it's written after the loop. Forgetting this is the most common decoding bug.
- `String(repeating:count:)` accepts a `Character` and builds the run in one step.

<Callout kind="warning" title="Digits make it ambiguous">
If the original text can contain digits, plain run-length encoding breaks: does `"a12"` mean twelve `a`s, or `a`, then `1` twice? Real formats avoid this with fixed-size counts or escape characters. Interview problems usually promise letters only; check before you rely on it.
</Callout>

## Only compress when it helps

`"abc"` encodes to `"a1b1c1"`, twice as long. A common variant leaves out counts of 1 and keeps the original if the result isn't shorter:

```swift run
func compressIfShorter(_ text: String) -> String {
    let chars = Array(text)
    var result = ""
    var i = 0
    while i < chars.count {
        var j = i
        while j < chars.count && chars[j] == chars[i] {
            j += 1
        }
        result.append(chars[i])
        if j - i > 1 {
            result += String(j - i)
        }
        i = j
    }
    return result.count < chars.count ? result : text
}

print(compressIfShorter("aaabccdddd"))
print(compressIfShorter("abc"))
print(compressIfShorter("aabb"))
```

```output
a3bc2d4
abc
aabb
```

`"aabb"` compresses to `"a2b2"`, the same length, so the original wins. A decoder for this format treats a letter with no digits after it as a count of 1.

## Compressing a character array in place

The interview classic: compress a `[Character]` in place, using the "omit counts of 1" format, and return the new length. Only the first `length` characters matter afterwards.

Use the read/write pointers from [Read/write pointers](/dsa/learn/tp-read-write). `read` finds each run; `write` writes the letter and then the count's digits:

```swift run
func compress(_ chars: inout [Character]) -> Int {
    var write = 0
    var read = 0
    while read < chars.count {
        let letter = chars[read]
        var runEnd = read
        while runEnd < chars.count && chars[runEnd] == letter {
            runEnd += 1
        }
        chars[write] = letter
        write += 1
        let length = runEnd - read
        if length > 1 {
            for digit in String(length) {
                chars[write] = digit
                write += 1
            }
        }
        read = runEnd
    }
    return write
}

var chars = Array("aabbbbbbbbbbbbc")
let length = compress(&chars)
print(length, String(chars[0..<length]))
```

```output
6 a2b12c
```

Why can `write` never overwrite a character that `read` still needs? A run of length L is replaced by its letter plus the digits of L. For L = 1 that's 1 character; for L from 2 to 9 it's 2; for 10 to 99 it's 3; and so on. In every case that's **at most L**. So `write` stays at or behind the start of the current run, and the run has already been read before anything is written over it.

That's O(n) time and O(1) extra space: a few integers, plus the tiny `String(length)` for the digits.

<Callout kind="gotcha" title="Common mistakes">
- **Single-digit counts.** Writing the count as one character, `Character(String(length))`, crashes for runs of 10 or more, because `"12"` isn't one character. Write every digit of `String(length)`.
- **Forgetting the last run.** Loops that finish a run when the *next* character differs must also finish the run at the end of the input.
- **Building the result with `result = result + piece`.** That copies the whole result each time. Use `append` and `+=`, as M08 showed.
</Callout>
