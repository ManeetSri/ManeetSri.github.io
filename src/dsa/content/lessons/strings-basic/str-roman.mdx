## Why it matters

Roman numerals still turn up on clock faces, in film credits and in chapter headings. As a programming problem they're a compact lesson in two patterns that reach far beyond Rome: **parsing with one character of lookahead**, and **greedy conversion with a table**. Both directions fit in a dozen lines once you see the trick, and the round trip makes a satisfying test.

## The rules

Seven symbols, each with a value:

| I | V | X | L | C | D | M |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 5 | 10 | 50 | 100 | 500 | 1000 |

A numeral is written from the largest value to the smallest and added up: `MMXX` is 1000 + 1000 + 10 + 10 = 2020. But in `MMXXIV`, the `IV` at the end is 4, not 6. That's the **subtractive** rule: a smaller symbol written *before* a larger one is subtracted. Only six such pairs are used:

| IV | IX | XL | XC | CD | CM |
| --- | --- | --- | --- | --- | --- |
| 4 | 9 | 40 | 90 | 400 | 900 |

The standard form never repeats a symbol four times in a row, using a subtractive pair instead: 4 is `IV`, never `IIII`. With these rules, numerals cover 1 to 3999.

## Reading a numeral: look one symbol ahead

Go left to right. Add each symbol's value, **unless the next symbol is larger**, in which case subtract it. Here's `CDXLIV`:

| Symbol | C | D | X | L | I | V |
| --- | --- | --- | --- | --- | --- | --- |
| Next is larger? | yes | no | yes | no | yes | no |
| Contributes | −100 | +500 | −10 | +50 | −1 | +5 |

The total is 444. Turning the numeral into an array of numbers first makes "the next symbol" a plain index:

```swift run
func symbolValue(_ symbol: Character) -> Int {
    switch symbol {
    case "I": return 1
    case "V": return 5
    case "X": return 10
    case "L": return 50
    case "C": return 100
    case "D": return 500
    case "M": return 1000
    default: return 0
    }
}

func value(of numeral: String) -> Int {
    let values = numeral.map(symbolValue)
    var total = 0
    for index in values.indices {
        if index + 1 < values.count && values[index] < values[index + 1] {
            total -= values[index]          // a smaller symbol before a larger one
        } else {
            total += values[index]
        }
    }
    return total
}

print(value(of: "MMXXIV"))
print(value(of: "CDXLIV"))
print(value(of: "XIV"))
```

```output
2024
444
14
```

What to notice:

- `numeral.map(symbolValue)` passes the function itself to `map`, as [Functions as values](/dsa/learn/swift-function-types) showed. The result is an `[Int]`.
- `index + 1 < values.count` is checked first, so the last symbol, which has nothing after it, is never compared with a value that doesn't exist.

This "decide what to do with this item by peeking at the next one" is called **lookahead**. Parsers for numbers, dates and programming languages use it all the time.

## Writing a numeral: greedy with a table

To go the other way, repeatedly take the **largest value that still fits**, write its symbol and subtract it. The trick is to put the six subtractive pairs **in the table**, alongside the seven symbols, so 13 entries in all:

```swift run
let table: [(value: Int, symbol: String)] = [
    (1000, "M"), (900, "CM"), (500, "D"), (400, "CD"),
    (100, "C"), (90, "XC"), (50, "L"), (40, "XL"),
    (10, "X"), (9, "IX"), (5, "V"), (4, "IV"), (1, "I"),
]

func roman(from number: Int) -> String {
    var remaining = number
    var result = ""
    for (value, symbol) in table {
        while remaining >= value {
            result += symbol
            remaining -= value
        }
    }
    return result
}

print(roman(from: 2024))
print(roman(from: 444))
print(roman(from: 3888))
```

```output
MMXXIV
CDXLIV
MMMDCCCLXXXVIII
```

For 444, the largest entry that fits is 400 (`CD`), leaving 44; then 40 (`XL`), leaving 4; then 4 (`IV`). Without the pairs in the table, 444 would come out as `CCCCXXXXIIII`.

The table is an array of **tuples** with labels, from [Tuples and typealias](/dsa/learn/swift-tuples-typealias), and `for (value, symbol) in table` takes each tuple apart. An array keeps the entries in order, largest first, which a dictionary wouldn't.

`3888` gives the longest standard numeral, 15 symbols. Since the input is at most 3999, both conversions take constant time.

## Why greedy works here, and where it doesn't

"Take the biggest piece that fits" is called a **greedy** strategy. For Roman numerals it's correct because the standard form is *defined* that way: the table lists exactly the pieces the rules allow, from largest to smallest.

Greedy is not always right. Making change with coins is the classic warning:

```swift run
func greedyCoins(_ amount: Int, coins: [Int]) -> [Int] {
    var remaining = amount
    var used: [Int] = []
    for coin in coins.sorted(by: >) {
        while remaining >= coin {
            used.append(coin)
            remaining -= coin
        }
    }
    return used
}

print(greedyCoins(6, coins: [1, 3, 4]))
print(greedyCoins(6, coins: [1, 2, 5]))
```

```output
[4, 1, 1]
[5, 1]
```

With coins of 1, 3 and 4, greedy pays 6 with three coins, but `3 + 3` needs only two. With 1, 2 and 5 it happens to be optimal. Telling the two situations apart, and fixing the first with dynamic programming, is a story for Part VII.

## Testing the round trip

Two functions that undo each other test each other. Convert every number from 1 to 3999 into a numeral and back:

```swift run
let symbolValues: [Character: Int] = ["I": 1, "V": 5, "X": 10, "L": 50, "C": 100, "D": 500, "M": 1000]
let table: [(value: Int, symbol: String)] = [
    (1000, "M"), (900, "CM"), (500, "D"), (400, "CD"),
    (100, "C"), (90, "XC"), (50, "L"), (40, "XL"),
    (10, "X"), (9, "IX"), (5, "V"), (4, "IV"), (1, "I"),
]

func roman(from number: Int) -> String {
    var remaining = number
    var result = ""
    for (value, symbol) in table {
        while remaining >= value {
            result += symbol
            remaining -= value
        }
    }
    return result
}

func value(of numeral: String) -> Int {
    let values = numeral.map { symbolValues[$0]! }
    var total = 0
    for index in values.indices {
        if index + 1 < values.count && values[index] < values[index + 1] {
            total -= values[index]
        } else {
            total += values[index]
        }
    }
    return total
}

var mismatches = 0
for number in 1...3999 where value(of: roman(from: number)) != number {
    mismatches += 1
}
print("mismatches:", mismatches)
```

```output
mismatches: 0
```

A round trip can't catch every bug, since both functions could share the same mistake, so pair it with a few hand-checked examples like 4, 9, 14, 40, 444 and 3999.

<Callout kind="gotcha" title="Common mistakes">
- **Leaving the subtractive pairs out of the table.** Greedy then writes 4 as `IIII` and 900 as `DCCCC`.
- **Reading past the end.** When looking ahead, check `index + 1 < values.count` before reading `values[index + 1]`.
- **Assuming the input is valid.** This lesson's reader trusts its input; `"IIV"` would quietly give 5. If a problem might give invalid numerals, validate by converting back and comparing.
</Callout>
