## Why it matters

A user types `" 42 apples"` into a quantity field. A config file says `retries = -3`. Somewhere, code has to turn text into a number, and decide what to do about spaces, signs, junk and numbers too big to store. "String to integer" is an interview classic for exactly that reason: the loop is easy, and **the edge cases are the whole test**. Writing a parser that survives all of them, including overflow, is a skill you'll use every time you read input you don't control.

## The rules

Swift's `Int(_:)` is strict: any space, letter or overflow gives `nil`.

```swift run
print(Int("42") as Any)
print(Int(" 42") as Any)
print(Int("42 apples") as Any)
print(Int("99999999999999999999") as Any)
```

```output
Optional(42)
nil
nil
nil
```

(`as Any` tells `print` that showing an optional is intended.) This lesson writes a **forgiving** parser instead, with these rules, applied in order:

1. Skip space characters (`" "`) at the start. Only spaces: a tab is not skipped.
2. Read one optional sign, `+` or `-`.
3. Read digits `0` to `9` until the text ends or anything else appears. Ignore the rest.
4. If no digits were read, the answer is 0.
5. If the number doesn't fit in an `Int`, return `Int.max`, or `Int.min` for a negative number: **clamp** it instead of overflowing.

Before writing code, write down what the rules say for every awkward input you can think of. This table is your test list:

| Input | Result | Why |
| --- | --- | --- |
| `"42"` | 42 | the ordinary case |
| `"   -17"` | −17 | spaces, then a sign |
| `"+8 apples"` | 8 | stop at the first non-digit |
| `"apples 8"` | 0 | no digits before the junk |
| `"+-5"` | 0 | a second sign isn't a digit |
| `"-"` and `""` | 0 | no digits at all |
| `"-000042"` | −42 | leading zeros are ordinary digits |
| `"9223372036854775808"` | `Int.max` | one more than `Int.max`: clamped |
| `"-9223372036854775808"` | `Int.min` | exactly `Int.min`: fits |

## One index, one rule at a time

Work on bytes, as [Array(s) and [UInt8] for fast access](/dsa/learn/swift-string-to-array) taught: only ASCII digits, signs and spaces matter, and everything else is "something that isn't a digit". A single index moves forward through the rules:

```swift run
func parseBasic(_ text: String) -> Int {
    let bytes = Array(text.utf8)
    var index = 0

    // 1. Skip leading spaces
    while index < bytes.count && bytes[index] == UInt8(ascii: " ") {
        index += 1
    }

    // 2. One optional sign
    var negative = false
    if index < bytes.count && (bytes[index] == UInt8(ascii: "+") || bytes[index] == UInt8(ascii: "-")) {
        negative = bytes[index] == UInt8(ascii: "-")
        index += 1
    }

    // 3. Digits until anything else
    var value = 0
    while index < bytes.count && bytes[index] >= UInt8(ascii: "0") && bytes[index] <= UInt8(ascii: "9") {
        value = value * 10 + Int(bytes[index] - UInt8(ascii: "0"))
        index += 1
    }
    return negative ? -value : value
}

for text in ["42", "   -17", "+8 apples", "apples 8", "+-5", "-", ""] {
    print("[\(text)] ->", parseBasic(text))
}
```

```output
[42] -> 42
[   -17] -> -17
[+8 apples] -> 8
[apples 8] -> 0
[+-5] -> 0
[-] -> 0
[] -> 0
```

What to notice:

- Every step checks `index < bytes.count` **first**. An input can end at any point, even straight after the spaces or the sign.
- Rule 4 needs no code: if no digits are read, `value` is still 0.
- `value * 10 + digit` is the shift-and-add from [Converting characters, digits and numbers](/dsa/learn/swift-char-digit-conversion).

But give it a 20-digit number and it crashes:

```swift
print(parseBasic("99999999999999999999"))
```

```text title="What you'll see"
Swift runtime failure: arithmetic overflow
```

That's Swift's overflow trap from [Overflow traps and overflow operators](/dsa/learn/swift-overflow): `value * 10` no longer fits in 64 bits.

## Clamping with reporting arithmetic

Every integer type has methods that do the arithmetic and **report** whether it overflowed, instead of trapping: `multipliedReportingOverflow(by:)` and `addingReportingOverflow(_:)`. Each returns the wrapped `partialValue` and an `overflow` flag. Check both steps of `value * 10 + digit`, and return the limit the moment either overflows:

```swift run
func parse(_ text: String) -> Int {
    let bytes = Array(text.utf8)
    var index = 0
    while index < bytes.count && bytes[index] == UInt8(ascii: " ") {
        index += 1
    }
    var negative = false
    if index < bytes.count && (bytes[index] == UInt8(ascii: "+") || bytes[index] == UInt8(ascii: "-")) {
        negative = bytes[index] == UInt8(ascii: "-")
        index += 1
    }
    var value = 0
    while index < bytes.count && bytes[index] >= UInt8(ascii: "0") && bytes[index] <= UInt8(ascii: "9") {
        let digit = Int(bytes[index] - UInt8(ascii: "0"))
        let shifted = value.multipliedReportingOverflow(by: 10)
        let added = shifted.partialValue.addingReportingOverflow(digit)
        if shifted.overflow || added.overflow {
            return negative ? Int.min : Int.max      // clamp
        }
        value = added.partialValue
        index += 1
    }
    return negative ? -value : value
}

for text in ["9223372036854775807", "9223372036854775808", "-9223372036854775808",
             "-9223372036854775809", "  -000000000000000000000042", "123456789012345678901234567890"] {
    print("[\(text)] ->", parse(text))
}
```

```output
[9223372036854775807] -> 9223372036854775807
[9223372036854775808] -> 9223372036854775807
[-9223372036854775808] -> -9223372036854775808
[-9223372036854775809] -> -9223372036854775808
[  -000000000000000000000042] -> -42
[123456789012345678901234567890] -> 9223372036854775807
```

### The Int.min puzzle

`Int.min` is −9,223,372,036,854,775,808, but `Int.max` is only 9,223,372,036,854,775,807. The **magnitude** of `Int.min` is one too big to store as a positive `Int`. So how does the parser return `Int.min` for `"-9223372036854775808"`?

It builds the positive magnitude, and that overflows on the very last digit. Overflow means "clamp", and clamping a negative number gives `Int.min`, which happens to be exactly the right answer. Anything below `Int.min` overflows too, and clamps to the same value. And any magnitude that does fit is at most `Int.max`, so `-value` is always safe.

<Callout kind="gotcha" title="Swift gotcha: -Int.min traps">
Negating `Int.min` overflows, because its positive version doesn't exist. Code that builds the magnitude of `Int.min` and then negates it would crash. Returning the clamped limit as soon as anything overflows means `-value` is only ever applied to values that fit.
</Callout>

## Checking without the reporting methods

You can also check **before** each step that it won't overflow. `value * 10 + digit ≤ Int.max` is the same as `value ≤ (Int.max - digit) / 10`, and nothing on the right side can overflow:

```swift
let digit = Int(bytes[index] - UInt8(ascii: "0"))
if value > (Int.max - digit) / 10 {
    return negative ? Int.min : Int.max
}
value = value * 10 + digit
```

Integer division rounds down, which is exactly right here: `value` is a whole number, so `value * 10 ≤ Int.max - digit` holds precisely when `value` is at most the rounded-down quotient. Both versions are O(n) time; use whichever you can explain.

## Which characters are digits?

It's tempting to use `Character.isNumber` or `wholeNumberValue`, from [Character properties and asciiValue](/dsa/learn/swift-character-properties). But they accept digits from every writing system:

```swift run
let three: Character = "٣"
print(three.isNumber, three.wholeNumberValue ?? -1)
print(Int("٣") ?? -1)
print(Array("٣".utf8))
```

```output
true 3
-1
[217, 163]
```

`٣` is the Arabic-Indic digit three. `isNumber` says yes, but `Int(_:)` refuses it, and its UTF-8 bytes are nowhere near `"0"` (48) to `"9"` (57). When a problem says "digits", it almost always means ASCII `0` to `9`, which the byte range check tests exactly. The same goes for spaces: `Character.isWhitespace` also accepts tabs and newlines, which these rules don't skip.

<Callout kind="gotcha" title="Common mistakes">
- **Checking only one step for overflow.** `922337203685477580 * 10` fits, but adding 9 doesn't. Check both the multiply and the add.
- **Reading past the end.** After the spaces or the sign, the input may have ended. Every step needs `index < bytes.count`.
- **Accepting more than one sign.** Read at most one; a second sign is a non-digit, which ends the number.
- **Skipping all whitespace.** The rules say spaces only. Follow the problem's definition, not your own.
</Callout>

**String to integer, clamped** is this parser with all five rules and up to 200,000 characters of input. Its tests include every row of the table above and a few more: write your own list of edge cases before you look at them.

```cards
  front: "How do you add a digit to a number without risking an overflow trap?"
  back: "Use `value.multipliedReportingOverflow(by: 10)`, then `addingReportingOverflow(digit)` on its partial value, and clamp if either reports overflow. Or check `value > (Int.max - digit) / 10` first."

  front: "Why can't you store the magnitude of Int.min as a positive Int?"

  front: "Why test digits with a byte range instead of `Character.isNumber`?"

```
