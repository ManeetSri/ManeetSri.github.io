## Why it matters

Big-O and Big-Ω are like ≤ and ≥: they allow equality. Sometimes you need the strict versions, "grows strictly slower than" and "grows strictly faster than". Textbooks and papers use them all the time: "a subquadratic algorithm" means o(n²), and "sublinear extra memory" means o(n). This deep dive gives you **little-o** and **little-ω**, the one-line test for them, and a precise version of the growth ladder. You won't need them in interviews, but you'll be able to read anything written about algorithms.

## Strictly slower: little-o

Recall Big-O: f(n) is O(g(n)) if there is **some** constant c with f(n) ≤ c · g(n) for large n. Little-o flips "some" to "every":

> **f(n) is o(g(n))** if for **every** constant c greater than 0, there is an n₀ such that f(n) ≤ c · g(n) for every n ≥ n₀.

That one word makes all the difference. However tiny you make c, one thousandth, one millionth, f eventually drops below c · g and stays there. So f isn't merely bounded by g, it becomes a vanishing fraction of it.

- **n is o(n²).** Pick any c. Then n ≤ c · n² holds once n ≥ 1/c. For c = 0.001 that's n ≥ 1,000, and it works for every c.
- **3n is not o(n).** With c = 1, you'd need 3n ≤ n, which never holds. 3n is O(n), but not *strictly* smaller.

## The ratio test

Checking "for every c" directly is awkward. There's an easier, equivalent test: look at the **ratio** f(n) / g(n) as n grows.

- If the ratio heads to **0**, f is o(g).
- If it settles at a positive number, f is Θ(g).
- If it grows without limit, f is ω(g) (coming up next).

```swift run
// floor(log₂ n), by counting halvings
func log2Floor(_ n: Int) -> Int {
    var steps = 0
    var size = n
    while size > 1 {
        size /= 2
        steps += 1
    }
    return steps
}

func ratio(_ top: Int, _ bottom: Int) -> Double {
    (Double(top) / Double(bottom) * 10_000).rounded() / 10_000
}

for n in [10, 100, 1_000, 10_000] {
    print("n = \(n): (3n + 2)/n = \(ratio(3 * n + 2, n)), log n / n = \(ratio(log2Floor(n), n)), n / n² = \(ratio(n, n * n))")
}
```

```output
n = 10: (3n + 2)/n = 3.2, log n / n = 0.3, n / n² = 0.1
n = 100: (3n + 2)/n = 3.02, log n / n = 0.06, n / n² = 0.01
n = 1000: (3n + 2)/n = 3.002, log n / n = 0.009, n / n² = 0.001
n = 10000: (3n + 2)/n = 3.0002, log n / n = 0.0013, n / n² = 0.0001
```

What to notice:

- (3n + 2) / n settles at **3**, a positive constant: 3n + 2 is Θ(n), and so **not** o(n).
- log n / n and n / n² both shrink towards **0**: log n is o(n), and n is o(n²).

The ratio test explains *why* the halving loop beats any linear loop in the long run. Each time n doubles, log n grows by only 1 while n doubles, so their ratio roughly halves.

## Strictly faster: little-ω

Little-omega is the mirror image:

> **f(n) is ω(g(n))** if for every constant c greater than 0, there is an n₀ such that f(n) ≥ c · g(n) for every n ≥ n₀.

However large c is, f eventually overtakes c · g. In ratio terms, f(n) / g(n) grows without limit. So n² is ω(n), and 2ⁿ is ω(n²).

The two are linked: **f is ω(g) exactly when g is o(f).** "n² grows strictly faster than n" and "n grows strictly slower than n²" say the same thing.

## The whole family

With little-o and little-ω, the five notations line up with the five comparison operators:

| f is … of g | Ratio f/g for large n | Like |
| --- | --- | --- |
| o(g) | heads to 0 | less than |
| O(g) | stays below some constant | ≤ |
| Θ(g) | stays between two positive constants | = |
| Ω(g) | stays above some positive constant | ≥ |
| ω(g) | grows without limit | greater than |

Two consequences worth remembering:

- **o implies O, but not the other way round.** If f becomes a vanishing fraction of g, it's certainly bounded by g. But 3n is O(n) without being o(n).
- **Nothing is o of itself.** f(n) / f(n) is always 1, which never heads to 0. Likewise, a function can't be both o(g) and Ω(g).

## The growth ladder, precisely

You can now state the ordering of the common growth classes exactly. Each is little-o of the next:

1 → log n → √n → n → n log n → n² → n³ → 2ⁿ → n! → nⁿ

Two stronger facts are worth knowing:

- **Any power of n beats any power of log n.** (log n)³ is o(n^0.1), even though the right-hand side looks tiny.
- **Any exponential beats any polynomial.** n¹⁰⁰ is o(2ⁿ).

"Eventually" can take a while, though:

```swift run
func tenthPower(_ n: Int) -> Int {
    var result = 1
    for _ in 0..<10 {
        result *= n
    }
    return result
}

var n = 2
var twoToN = 4
while twoToN <= tenthPower(n) {
    n += 1
    twoToN *= 2
}
print("2ⁿ first beats n¹⁰ at n = \(n)")
print("n¹⁰ = \(tenthPower(n)), 2ⁿ = \(twoToN)")
```

```output
2ⁿ first beats n¹⁰ at n = 59
n¹⁰ = 511116753300641401, 2ⁿ = 576460752303423488
```

n¹⁰ is o(2ⁿ), but 2ⁿ only overtakes it at n = 59, when both are past 5 × 10¹⁷. Asymptotic notation is a statement about the long run, and the long run can start late.

## Not every pair compares

The ≤ and ≥ analogy has one crack. With numbers, either a ≤ b or a ≥ b. With functions, neither might hold. Take g(n) = n² and

- f(n) = n when n is even,
- f(n) = n³ when n is odd.

f keeps dipping below n² and jumping above it, so f is neither O(n²) nor Ω(n²). Running times of real algorithms are rarely this strange, but it's why the definitions talk about bounds rather than limits: the ratio f/g here never settles at all.

## Where you'll meet them

- **Subquadratic** means o(n²), **sublinear** means o(n). Binary search reads a sublinear number of elements.
- **Lower bounds.** In M31 you'll see that comparison sorting needs Ω(n log n) comparisons, so there's no o(n log n) comparison sort.
- **Precise estimates.** "The expected number of probes is 1 + o(1)" means "1, plus an amount that vanishes as n grows".

<Callout kind="tip" title="When to use which">
In interviews and code reviews, stay with Big-O and mean the tight bound. Use little-o when you need to say "strictly better", for example when arguing that an O(n log n) algorithm really does beat an O(n²) one for large inputs: n log n is o(n²).
</Callout>
