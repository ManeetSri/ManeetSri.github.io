## Why it matters

Loops you can count directly. Recursive functions are harder: the cost of `f(n)` depends on the cost of `f(n / 2)` or `f(n - 1)`, which depends on smaller calls still. The way to capture that is a **recurrence**, an equation that defines a function in terms of itself. Merge sort, binary search, tree traversals, divide and conquer and backtracking are all analysed this way. This lesson shows how to write a recurrence from code and two ways to solve one: unrolling it, and drawing a recursion tree.

## From code to recurrence

Let T(n) be the number of steps a function takes on input size n. Read it off the code:

**T(n) = (the cost of the recursive calls) + (the work done outside them)**

plus a base case, where T is a constant. Four shapes cover most of what you'll meet:

```swift
// One call on n − 1, constant work: T(n) = T(n − 1) + 1
func sumTo(_ n: Int) -> Int {
    if n == 0 { return 0 }
    return n + sumTo(n - 1)
}

// One call on n / 2, constant work: T(n) = T(n / 2) + 1
func halvings(_ n: Int) -> Int {
    if n <= 1 { return 0 }
    return 1 + halvings(n / 2)
}

// Two calls on n / 2, constant work: T(n) = 2T(n / 2) + 1
func sumRange(_ low: Int, _ high: Int) -> Int {
    if low == high { return low }
    let mid = (low + high) / 2
    return sumRange(low, mid) + sumRange(mid + 1, high)
}

// Two calls on n − 1, constant work: T(n) = 2T(n − 1) + 1
func paths(_ steps: Int) -> Int {
    if steps == 0 { return 1 }
    return paths(steps - 1) + paths(steps - 1)
}
```

Count calls (how many, and on what size) and the work around them. Merge sort, which you'll write in Part IV, splits an array into halves, sorts each recursively and merges them in O(n): **T(n) = 2T(n / 2) + n**.

We'll write n / 2 and ignore rounding. Pretending n is a power of 2 makes the algebra clean and never changes the growth class.

## Method 1: unrolling

Substitute the recurrence into itself until you spot the pattern, then jump to the base case.

**T(n) = T(n − 1) + 1**, with T(0) = 1:

```text
T(n) = T(n − 1) + 1
     = T(n − 2) + 2
     = T(n − 3) + 3
     = T(n − k) + k        ← the pattern
     = T(0) + n            ← when k = n
```

So T(n) = n + 1: **O(n)**.

**T(n) = T(n / 2) + 1**, with T(1) = 1:

```text
T(n) = T(n / 2) + 1
     = T(n / 4) + 2
     = T(n / 8) + 3
     = T(n / 2ᵏ) + k
```

The base case arrives when n / 2ᵏ = 1, which means 2ᵏ = n, so k = log₂ n. T(n) = log₂ n + 1: **O(log n)**. Each halving adds one step, exactly like a halving loop.

**T(n) = 2T(n − 1) + 1**, with T(0) = 0:

```text
T(n) = 2T(n − 1) + 1
     = 4T(n − 2) + 2 + 1
     = 8T(n − 3) + 4 + 2 + 1
     = 2ᵏ T(n − k) + (2ᵏ⁻¹ + … + 2 + 1)
     = 2ⁿ T(0) + (2ⁿ − 1)  ← when k = n
```

So T(n) = 2ⁿ − 1: **O(2ⁿ)**. The classic example is the Tower of Hanoi: to move n discs, move n − 1 aside, move the biggest, then move the n − 1 back on top.

```swift run
var moves = 0

// T(n) = 2T(n − 1) + 1: move n − 1 discs aside, move the biggest, move n − 1 back on top
func hanoi(_ discs: Int) {
    if discs == 0 {
        return
    }
    hanoi(discs - 1)
    moves += 1
    hanoi(discs - 1)
}

for discs in [1, 2, 3, 10, 20] {
    moves = 0
    hanoi(discs)
    print("n = \(discs): moves \(moves)")
}
```

```output
n = 1: moves 1
n = 2: moves 3
n = 3: moves 7
n = 10: moves 1023
n = 20: moves 1048575
```

Exactly 2ⁿ − 1 every time. Each extra disc doubles the work.

## Method 2: recursion trees

Unrolling gets messy when there are two recursive calls on n / 2. A **recursion tree** organises the work instead. Draw each call as a node, labelled with the work it does **outside** its recursive calls. Then add up each level, and add up the levels.

Here's **T(n) = 2T(n / 2) + n** for n = 8:

```text
level 0:                  8                        level total  8
level 1:          4               4                level total  8
level 2:      2       2       2       2            level total  8
level 3:    1   1   1   1   1   1   1   1          level total  8
```

- Level i has 2ⁱ nodes, each of size n / 2ⁱ, so every level adds up to **n**.
- The sizes halve until they reach 1, so there are **log₂ n + 1** levels.
- Total: n × (log₂ n + 1), which is **O(n log n)**. For n = 8 that's 8 × 4 = 32.

Change the work per node to a constant, **T(n) = 2T(n / 2) + 1**, and the same tree gives very different totals:

```text
level 0:                  1                        level total  1
level 1:          1               1                level total  2
level 2:      1       1       1       1            level total  4
level 3:    1   1   1   1   1   1   1   1          level total  8
```

The level totals double: 1 + 2 + 4 + … + n. That geometric series is 2n − 1, so it's **O(n)**. The bottom level alone, with n leaves, holds about half of all the work.

And **T(n) = T(n / 2) + n** is a single path with work n, n/2, n/4, …: another geometric series, under 2n, so **O(n)**. This time the top level holds half the work.

Those three trees show the three ways a recursion tree can balance: equal work on every level (multiply by the number of levels), work growing towards the leaves (the leaves dominate), or work shrinking towards the leaves (the root dominates). The next lesson turns that observation into a formula.

## Checking with a counting experiment

Let each function add its outside-the-calls work to a counter, and compare with the formulas:

```swift run
var work = 0

// T(n) = T(n/2) + 1
func halve(_ n: Int) {
    work += 1
    if n > 1 {
        halve(n / 2)
    }
}

// T(n) = 2T(n/2) + 1
func splitCheap(_ n: Int) {
    work += 1
    if n > 1 {
        splitCheap(n / 2)
        splitCheap(n / 2)
    }
}

// T(n) = 2T(n/2) + n
func splitAndScan(_ n: Int) {
    work += n
    if n > 1 {
        splitAndScan(n / 2)
        splitAndScan(n / 2)
    }
}

func measure(_ f: (Int) -> Void, _ n: Int) -> Int {
    work = 0
    f(n)
    return work
}

for n in [8, 64, 1_024] {
    print("n = \(n): halve \(measure(halve, n)), split cheap \(measure(splitCheap, n)), split and scan \(measure(splitAndScan, n))")
}
```

```output
n = 8: halve 4, split cheap 15, split and scan 32
n = 64: halve 7, split cheap 127, split and scan 448
n = 1024: halve 11, split cheap 2047, split and scan 11264
```

| Function | Recurrence | Exact total | Class |
| --- | --- | --- | --- |
| `halve` | T(n / 2) + 1 | log₂ n + 1 | O(log n) |
| `splitCheap` | 2T(n / 2) + 1 | 2n − 1 | O(n) |
| `splitAndScan` | 2T(n / 2) + n | n log₂ n + n | O(n log n) |

For n = 1,024: log₂ n = 10, so 11, 2,047 and 10,240 + 1,024 = 11,264. Every number matches.

## Guess and check

There's one more technique, often called the **substitution method**: guess the answer, then prove it by **induction**. Induction means showing the claim holds for the base case, and that if it holds for smaller inputs it must hold for n.

To check that T(n) = 2T(n / 2) + n is at most c · n log₂ n: assume it's true for n / 2, and substitute:

```text
T(n) = 2T(n / 2) + n
     ≤ 2 · c · (n / 2) · log₂(n / 2) + n      ← the assumption, for n / 2
     = c · n · (log₂ n − 1) + n
     = c · n log₂ n − c · n + n
     ≤ c · n log₂ n                            ← whenever c ≥ 1
```

The guess survives. This method is the most rigorous, but you need a guess first, and a recursion tree is the best way to get one.

<Callout kind="gotcha" title="Swift gotcha: hidden work in each call">
The "work outside the calls" includes everything, even work that doesn't look like work. Creating a new array for the recursive call copies it:

```swift
func sumByCopying(_ numbers: [Int]) -> Int {
    guard let first = numbers.first else { return 0 }
    return first + sumByCopying(Array(numbers.dropFirst()))  // copies n − 1 elements
}
```

That's T(n) = T(n − 1) + n, which unrolls to n + (n − 1) + … + 1: **O(n²)**, not O(n). Pass an index instead, `sumFrom(index + 1, in: numbers)`, and nothing is copied: back to O(n). Recursing on an `ArraySlice` avoids the copy too, but remember its indices don't start at 0.
</Callout>

A counting experiment shows the copies piling up:

```swift run
var copied = 0

// Recursing on a copy: each call copies the rest of the array
func sumByCopying(_ numbers: [Int]) -> Int {
    guard let first = numbers.first else {
        return 0
    }
    let rest = Array(numbers.dropFirst())
    copied += rest.count
    return first + sumByCopying(rest)
}

// Recursing with an index: nothing is copied
func sumFrom(_ index: Int, in numbers: [Int]) -> Int {
    if index == numbers.count {
        return 0
    }
    return numbers[index] + sumFrom(index + 1, in: numbers)
}

for n in [10, 100, 1_000] {
    copied = 0
    let numbers = Array(1...n)
    let first = sumByCopying(numbers)
    let second = sumFrom(0, in: numbers)
    print("n = \(n): sums \(first) and \(second), elements copied \(copied)")
}
```

```output
n = 10: sums 55 and 55, elements copied 45
n = 100: sums 5050 and 5050, elements copied 4950
n = 1000: sums 500500 and 500500, elements copied 499500
```

Same answers, but the copying version moves n(n − 1)/2 elements: the triangle again.

## Common recurrences

| Recurrence | Typical example | Solution |
| --- | --- | --- |
| T(n − 1) + O(1) | linear recursion over an array, by index | O(n) |
| T(n − 1) + O(n) | recursing on a copy of the rest | O(n²) |
| T(n / 2) + O(1) | binary search | O(log n) |
| T(n / 2) + O(n) | halving with a full scan each time | O(n) |
| 2T(n / 2) + O(1) | splitting in half with constant work | O(n) |
| 2T(n / 2) + O(n) | merge sort | O(n log n) |
| 2T(n − 1) + O(1) | Tower of Hanoi, naive subsets | O(2ⁿ) |
| T(n − 1) + T(n − 2) + O(1) | naive Fibonacci | about O(1.618ⁿ), within O(2ⁿ) |

Notice the pairs that differ only in the outside work, like 2T(n / 2) + O(1) and 2T(n / 2) + O(n). That one term changes the answer by a factor of log n.
