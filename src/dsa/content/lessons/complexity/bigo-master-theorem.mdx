## Why it matters

Divide-and-conquer algorithms split a problem into equal parts, solve each part recursively and combine the results. Their recurrences all look alike, and drawing a recursion tree for each one gets repetitive. The **Master theorem** is a ready-made answer for that whole family: read off three numbers, compare two of them, and the growth class falls out. You'll use it for merge sort, binary search, quickselect's best case, fast multiplication and more, and it's a favourite in interviews because it's quick to apply out loud.

## The shape it solves

The theorem handles recurrences of the form

**T(n) = a · T(n / b) + f(n)**

- **a**: how many recursive calls each call makes (a ≥ 1).
- **b**: how much smaller each subproblem is (b greater than 1): each call works on n / b.
- **f(n)**: the work done outside the recursive calls, splitting and combining.

| Algorithm | Recurrence | a | b | f(n) |
| --- | --- | --- | --- | --- |
| binary search | T(n / 2) + 1 | 1 | 2 | 1 |
| splitting in half, constant work | 2T(n / 2) + 1 | 2 | 2 | 1 |
| merge sort | 2T(n / 2) + n | 2 | 2 | n |

## The idea: root versus leaves

Picture the recursion tree. Level i has **aⁱ** calls, each on input size **n / bⁱ**. Two things compete:

- **The root's work**, f(n), done once at the top.
- **The leaves' work.** The tree has log_b n levels, so there are a^(log_b n) leaves. That number has a neater form: a^(log_b n) = **n^(log_b a)**. (Both sides equal 2 raised to log₂ a × log₂ n / log₂ b, so they match.)

So the number of leaves grows like n to the power **log_b a**, the **critical exponent**. Some values you'll meet:

```swift run
import Foundation

for (a, b) in [(2.0, 2.0), (3.0, 2.0), (4.0, 2.0), (7.0, 2.0), (8.0, 2.0), (9.0, 3.0)] {
    let exponent = log(a) / log(b)
    print("a = \(Int(a)), b = \(Int(b)): log_b a = \((exponent * 1_000).rounded() / 1_000)")
}
```

```output
a = 2, b = 2: log_b a = 1.0
a = 3, b = 2: log_b a = 1.585
a = 4, b = 2: log_b a = 2.0
a = 7, b = 2: log_b a = 2.807
a = 8, b = 2: log_b a = 3.0
a = 9, b = 3: log_b a = 2.0
```

The theorem compares f(n) with n^(log_b a). Whichever is polynomially bigger wins; if they're the same size, every level ties and you pay for all log n of them.

## The version you'll use most

Usually f(n) is a plain power, f(n) = n^d (with d = 0 for constant work). Then the work on level i is

aⁱ × (n / bⁱ)^d = n^d × (a / b^d)ⁱ

a geometric series with ratio **a / b^d**. Compare **a** with **b^d**:

| Case | Level totals | Result |
| --- | --- | --- |
| a less than b^d | shrink towards the leaves: the root dominates | Θ(n^d) |
| a = b^d | equal on every level | Θ(n^d log n) |
| a greater than b^d | grow towards the leaves: the leaves dominate | Θ(n^(log_b a)) |

These are the three trees from the last lesson, now with a rule attached.

### Worked examples

| Recurrence | a | b | d | a vs b^d | Result |
| --- | --- | --- | --- | --- | --- |
| T(n / 2) + 1 | 1 | 2 | 0 | 1 = 1 | Θ(log n) |
| T(n / 2) + n | 1 | 2 | 1 | 1 less than 2 | Θ(n) |
| 2T(n / 2) + 1 | 2 | 2 | 0 | 2 greater than 1 | Θ(n) |
| 2T(n / 2) + n | 2 | 2 | 1 | 2 = 2 | Θ(n log n) |
| 2T(n / 2) + n² | 2 | 2 | 2 | 2 less than 4 | Θ(n²) |
| 4T(n / 2) + n | 4 | 2 | 1 | 4 greater than 2 | Θ(n²) |
| 3T(n / 2) + n | 3 | 2 | 1 | 3 greater than 2 | Θ(n^1.585) |
| 3T(n / 3) + n | 3 | 3 | 1 | 3 = 3 | Θ(n log n) |
| 8T(n / 2) + n² | 8 | 2 | 2 | 8 greater than 4 | Θ(n³) |
| 7T(n / 2) + n² | 7 | 2 | 2 | 7 greater than 4 | Θ(n^2.807) |

A few are famous. **3T(n / 2) + n** is Karatsuba's method for multiplying huge numbers, beating the schoolbook O(n²). **8T(n / 2) + n²** is multiplying matrices by splitting them into quarters, which gains nothing over three nested loops; **7T(n / 2) + n²** is Strassen's trick of getting by with seven sub-multiplications instead of eight, which does beat n³. One fewer recursive call changes the exponent.

## Watching a change the answer

Keep b = 2 and f(n) = n, and vary only a. The theorem predicts Θ(n) for a = 1 (1 less than 2), Θ(n log n) for a = 2 (equal), and Θ(n²) for a = 4 (4 greater than 2):

```swift run
var work = 0

// T(n) = a · T(n / 2) + n
func divide(_ n: Int, into a: Int) {
    work += n
    if n > 1 {
        for _ in 0..<a {
            divide(n / 2, into: a)
        }
    }
}

for n in [64, 256, 1_024] {
    var totals: [Int] = []
    for a in [1, 2, 4] {
        work = 0
        divide(n, into: a)
        totals.append(work)
    }
    print("n = \(n): a = 1 → \(totals[0]), a = 2 → \(totals[1]), a = 4 → \(totals[2])")
}
```

```output
n = 64: a = 1 → 127, a = 2 → 448, a = 4 → 8128
n = 256: a = 1 → 511, a = 2 → 2304, a = 4 → 130816
n = 1024: a = 1 → 2047, a = 2 → 11264, a = 4 → 2096128
```

Each time n grows 4 times, the a = 1 column grows about 4 times (exactly 2n − 1), the a = 2 column a little more than 4 times (n log₂ n + n), and the a = 4 column 16 times (exactly 2n² − n). All three match the prediction.

## The general statement

When f(n) isn't a plain power, compare it with n^(log_b a) directly:

1. **Leaves win.** If f(n) is O(n^(log_b a − ε)) for some ε greater than 0, then T(n) is **Θ(n^(log_b a))**.
2. **Tie.** If f(n) is Θ(n^(log_b a)), then T(n) is **Θ(n^(log_b a) · log n)**. More generally, if f(n) is Θ(n^(log_b a) · logᵏ n) with k ≥ 0, then T(n) is Θ(n^(log_b a) · logᵏ⁺¹ n).
3. **Root wins.** If f(n) is Ω(n^(log_b a + ε)) for some ε greater than 0, **and** a · f(n / b) ≤ k · f(n) for some constant k less than 1 (the **regularity condition**: the work really does shrink down the tree), then T(n) is **Θ(f(n))**.

The ε matters. "Polynomially smaller" means smaller by a factor of at least n^ε, like n^0.5. Being smaller by only a log factor doesn't count, which is why the extended tie case exists.

## When it doesn't apply

The theorem needs equal-sized subproblems that shrink by **division**. Watch out for:

- **Subtracting instead of dividing.** T(n) = T(n − 1) + 1 and T(n) = 2T(n − 1) + 1 aren't in the form. Unroll them, as in the last lesson: O(n) and O(2ⁿ).
- **Unequal splits.** T(n) = T(n / 3) + T(2n / 3) + n has two different sizes. Use a recursion tree: each full level adds up to n, and the longest path, always taking the 2n / 3 branch, has about log n levels (in base 1.5), so it's O(n log n).
- **A changing number of calls.** T(n) = n · T(n / 2) + 1 has a that depends on n; the theorem needs a constant.
- **The gap between cases.** T(n) = 2T(n / 2) + n / log n is smaller than n, but only by a log factor, not by n^ε, so case 1 doesn't apply, and it isn't a tie either. It needs other tools (the answer is Θ(n log log n)). By contrast, 2T(n / 2) + n log n *is* covered by the extended tie case with k = 1: Θ(n log² n).

<Callout kind="tip" title="Applying it out loud">
In an interview: "a is 2, b is 2, the combine step is linear so d is 1. 2 equals 2 to the 1, so it's the balanced case: O(n log n)." Then sanity-check with the tree: log n levels, n work each. Saying both shows you understand *why*, not only the formula.
</Callout>
