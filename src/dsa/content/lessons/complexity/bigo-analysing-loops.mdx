## Why it matters

Most of the time you spend analysing code, you're analysing loops. Simple loops are easy, but loops whose bounds depend on each other, loops that halve, and loops that look nested but aren't are where people get the wrong answer, in interviews and in real code. This lesson covers every loop shape you'll meet in Part III and beyond, each with a counting experiment so you can see the formula is right rather than take it on trust.

## Single loops: what matters is how the bound grows

A loop that runs n times with a constant body is O(n). So is one that steps by 3, `stride(from: 0, to: n, by: 3)`, because n/3 passes is still a constant times n.

A loop with a **fixed** bound is O(1), however many passes it makes. Walking the 26 slots of a letter-frequency array, as in [Frequency counting with 26 slots](/dsa/learn/swift-frequency-arrays), costs 26 steps whether the text has ten characters or ten million.

The question is always: **how does the number of passes grow with n?**

## Independent nested loops: multiply

When the inner loop's range doesn't depend on the outer loop, multiply the two counts. An n-loop around an m-loop is O(n · m); an n-loop around an n-loop is O(n²); three deep is O(n³). You did this in the last lesson.

## Dependent loops: the triangle

Things get interesting when the inner loop's bound depends on the outer variable:

```swift
for i in 0..<n {
    for j in 0..<i {
        // body
    }
}
```

The inner loop runs 0 times when i = 0, once when i = 1, twice when i = 2, and so on up to n − 1 times. Drawn out for n = 5, each `*` is one run of the body:

```text
i = 0:
i = 1:  *
i = 2:  * *
i = 3:  * * *
i = 4:  * * * *
```

It's a triangle, roughly half of an n × n square. The total is 0 + 1 + 2 + … + (n − 1).

### Adding 1 + 2 + … + n

There's a lovely trick for sums like this. Write the sum twice, once forwards and once backwards, and add the columns:

```text
  S =   1   +   2   + … + (n − 1) +   n
  S =   n   + (n − 1) + … +   2   +   1
 2S = (n+1) + (n+1) + … + (n + 1) + (n+1)   ← n columns
```

Every column adds up to n + 1, and there are n columns, so 2S = n(n + 1), and

**1 + 2 + … + n = n(n + 1) / 2**

Our triangle stops at n − 1 instead of n, so it's (n − 1)n / 2. A counting experiment agrees:

```swift run
func triangleSteps(_ n: Int) -> Int {
    var steps = 0
    for i in 0..<n {
        for _ in 0..<i {
            steps += 1
        }
    }
    return steps
}

for n in [5, 10, 100, 1_000] {
    print("n = \(n): counted \(triangleSteps(n)), formula \(n * (n - 1) / 2), n² = \(n * n)")
}
```

```output
n = 5: counted 10, formula 10, n² = 25
n = 10: counted 45, formula 45, n² = 100
n = 100: counted 4950, formula 4950, n² = 10000
n = 1000: counted 499500, formula 499500, n² = 1000000
```

n(n − 1) / 2 = n²/2 − n/2. Drop the constant ½ and the smaller term, and it's **O(n²)**. Halving the work is nice, but it doesn't change the class.

The same count appears whenever you look at every **pair** once, with `for j in (i + 1)..<n` as the inner loop: n people shaking hands with everyone else make n(n − 1) / 2 handshakes.

## Halving and doubling loops: log n

A loop that cuts its variable in half each time runs about log₂ n times. So does one that doubles its variable up to n:

```swift run
func halvings(_ n: Int) -> Int {
    var steps = 0
    var size = n
    while size > 1 {
        size /= 2
        steps += 1
    }
    return steps
}

func doublings(_ n: Int) -> Int {
    var steps = 0
    var width = 1
    while width < n {
        width *= 2
        steps += 1
    }
    return steps
}

for n in [1, 2, 3, 4, 5, 1_000, 1_000_000, 1_000_000_000] {
    print("n = \(n): halvings \(halvings(n)), doublings \(doublings(n))")
}
```

```output
n = 1: halvings 0, doublings 0
n = 2: halvings 1, doublings 1
n = 3: halvings 1, doublings 2
n = 4: halvings 2, doublings 2
n = 5: halvings 2, doublings 3
n = 1000: halvings 9, doublings 10
n = 1000000: halvings 19, doublings 20
n = 1000000000: halvings 29, doublings 30
```

What to notice:

- A billion takes only 29 halvings. That's the magic of logarithms, and the reason binary search is so fast.
- The halving count is log₂ n **rounded down**, and the doubling count is log₂ n **rounded up**. For n = 1,000, log₂ n is about 9.97, so 9 and 10. The rounding never matters for Big-O: both are O(log n).

The general rule: if each pass multiplies or divides the loop variable by a constant bigger than 1, the loop is O(log n).

## Why the base doesn't matter

Dividing by 10 instead of 2 reaches 1 sooner. Does that make it a different class?

```swift run
func divisions(of n: Int, by divisor: Int) -> Int {
    var steps = 0
    var size = n
    while size > 1 {
        size /= divisor
        steps += 1
    }
    return steps
}

for n in [1_000, 1_000_000, 1_000_000_000, 1_000_000_000_000_000_000] {
    print("n = \(n): by 2 takes \(divisions(of: n, by: 2)), by 10 takes \(divisions(of: n, by: 10))")
}
```

```output
n = 1000: by 2 takes 9, by 10 takes 3
n = 1000000: by 2 takes 19, by 10 takes 6
n = 1000000000: by 2 takes 29, by 10 takes 9
n = 1000000000000000000: by 2 takes 59, by 10 takes 18
```

Dividing by 10 is always about 3.3 times quicker, at every size. A **fixed ratio** is a constant factor, and constant factors drop. In maths terms, log₁₀ n = log₂ n / log₂ 10, and log₂ 10 ≈ 3.32 is a fixed number. Every base gives the same class, so we write O(log n) without one.

## Loops and halvings combined

When halving meets a full loop, the arrangement decides the answer. These two functions look similar:

```swift run
func loopOfHalvings(_ n: Int) -> Int {
    var steps = 0
    for _ in 0..<n {
        var size = n
        while size > 1 {
            size /= 2
            steps += 1
        }
    }
    return steps
}

func shrinkingPasses(_ n: Int) -> Int {
    var steps = 0
    var size = n
    while size > 0 {
        for _ in 0..<size {
            steps += 1
        }
        size /= 2
    }
    return steps
}

for n in [1_000, 2_000, 4_000] {
    print("n = \(n): n passes of halving \(loopOfHalvings(n)), halving passes of n \(shrinkingPasses(n))")
}
```

```output
n = 1000: n passes of halving 9000, halving passes of n 1994
n = 2000: n passes of halving 20000, halving passes of n 3994
n = 4000: n passes of halving 44000, halving passes of n 7994
```

- **`loopOfHalvings`** runs a full O(log n) halving loop, n times over. That's n × log n: **O(n log n)**.
- **`shrinkingPasses`** halves the *amount of work* on each pass: n + n/2 + n/4 + … + 1. That's always a little under **2n**, so it's **O(n)**, not O(n log n).

Why under 2n? The first pass costs n. Each later pass costs half the one before: n/2, then n/4, then n/8. Each of those covers half of the distance still left to a second n, so together they creep towards n without ever reaching it. First pass n, the rest less than n: under 2n in total. Whenever each term is a fixed fraction of the one before, the total is a constant times the **first** term. This **geometric series** argument comes back for amortised analysis and for recursion trees.

## Looks nested, runs once

Here's a loop inside a loop that is still O(n). It walks runs of equal values, like 7, 7, 7 then 2, 2:

```swift run
func runSteps(_ numbers: [Int]) -> (runs: Int, innerSteps: Int) {
    var runs = 0
    var innerSteps = 0
    var start = 0
    while start < numbers.count {
        var end = start
        while end < numbers.count && numbers[end] == numbers[start] {
            end += 1
            innerSteps += 1
        }
        runs += 1
        start = end
    }
    return (runs, innerSteps)
}

print(runSteps([7, 7, 7, 2, 2, 9, 7, 7]))
print(runSteps(Array(repeating: 5, count: 1_000)))
print(runSteps(Array(0..<1_000)))
```

```output
(runs: 4, innerSteps: 8)
(runs: 1, innerSteps: 1000)
(runs: 1000, innerSteps: 1000)
```

The inner loop's total is always exactly n. The key line is `start = end`: the outer loop **jumps past** everything the inner loop has already covered, so each element is visited once in total. Whether there's one long run or a thousand short ones, the work is the same.

The lesson: count **total** work over the whole run, not "worst inner loop × outer passes". Multiplying would give n × n here, a correct upper bound but a badly loose one.

## Two more shapes

- **Square root.** `var i = 1; while i * i <= n { i += 1 }` stops when i passes √n, so it's O(√n). Checking divisors up to √n, in M15, uses this.
- **Harmonic.** An outer loop over `gap` from 1 to n, with an inner loop striding through `0..<n` by `gap`, runs n + n/2 + n/3 + … + n/n times. That sum is about n × ln n, so it's O(n log n). It turns up in sieves and in problems about multiples.

```swift run
func harmonicSteps(_ n: Int) -> Int {
    var steps = 0
    for gap in 1...n {
        for _ in stride(from: 0, to: n, by: gap) {
            steps += 1
        }
    }
    return steps
}

for n in [1_000, 10_000] {
    print("n = \(n): \(harmonicSteps(n)) steps")
}
```

```output
n = 1000: 8053 steps
n = 10000: 103643 steps
```

Ten times the input gave about 12.9 times the work: a bit more than linear, the fingerprint of n log n.

## A summary of loop shapes

| Loop shape | Body runs | Class |
| --- | --- | --- |
| `for i in 0..<n` | n | O(n) |
| fixed bound, such as `0..<26` | 26 | O(1) |
| two independent loops, n and m | n · m | O(n · m) |
| inner `0..<i` or `(i + 1)..<n` | n(n − 1) / 2 | O(n²) |
| `size /= 2` or `width *= 2` | about log₂ n | O(log n) |
| n passes of a halving loop | about n log₂ n | O(n log n) |
| passes of n, n/2, n/4, … | under 2n | O(n) |
| inner loop whose position never resets | n in total | O(n) |
| `while i * i <= n` | about √n | O(√n) |

<Callout kind="gotcha" title="Swift gotcha: empty and backwards ranges">
`for j in (i + 1)..<n` is fine when i + 1 equals n: the range is empty and the loop doesn't run. But a range whose start is **greater** than its end, such as `5..<3`, crashes with `Range requires lowerBound <= upperBound`. Counting formulas often need a separate answer for n = 0, for the same reason: check your formula at the smallest inputs.
</Callout>

## Practice

**Count the loop steps** has you turn the triangle and halving loops into exact formulas. **The biggest rise** gives you a slow, all-pairs description and asks for a one-pass O(n) version: think about what you need to remember from the elements you've already passed.

```cards
- id: triangle-loop
  front: "What's the complexity of `for i in 0..<n { for j in 0..<i { … } }`?"

  front: "What's the total of n + n/2 + n/4 + … + 1?"
  back: "Less than 2n, so O(n). When each term is a fixed fraction of the last, the total is a constant times the first term."
```
