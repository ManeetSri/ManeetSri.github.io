## Why it matters

"Show the 10 best-selling products." "Find the 5 drivers nearest the passenger." "Which 3 hashtags are trending?" Questions like these ask for the **top k** of a large, often endless, collection. Sorting everything answers them, but does far more work than needed and needs all the data at once. A heap holding just k items answers them in O(n log k) time and O(k) memory, one item at a time, so it works on a live stream. It's one of the most common interview patterns, and its central trick surprises nearly everyone the first time: to keep the k **largest**, you use a **min**-heap.

## The doorkeeper: a min-heap for the k largest

Suppose you want the 3 largest values from a stream. Keep the best 3 seen so far. When a new value arrives, the only question is: does it beat the **weakest** of the current best 3? If it does, the weakest drops out and the newcomer takes its place. If not, the newcomer can never be in the top 3, because 3 values already beat it.

So you need quick access to the weakest of the k, which for "largest" means the **smallest** of them. That's a min-heap's top. Think of it as a doorkeeper: anything no bigger than the doorkeeper is turned away. And because the heap holds exactly the k largest, its top is the **kth largest** overall, available at any moment in O(1).

```swift run
// The heap from "Build a generic Heap<T>", compacted, plus replaceTop
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    var count: Int { items.count }
    var isEmpty: Bool { items.isEmpty }
    func peek() -> Element? { items.first }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        siftDownFromTop()
        return top
    }

    /// Replaces the top (the heap must not be empty) with one sift down
    mutating func replaceTop(with element: Element) {
        items[0] = element
        siftDownFromTop()
    }

    private mutating func siftDownFromTop() {
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { return }
            items.swapAt(parent, first)
            parent = first
        }
    }
}

// The k largest values seen so far, in a min-heap: its top is the kth largest
let k = 3
var best = Heap<Int>(areInIncreasingOrder: <)
for value in [12, 5, 31, 8, 27, 19, 3, 40] {
    if best.count < k {
        best.insert(value)
    } else if value > best.peek()! {
        best.replaceTop(with: value)             // the old kth largest drops out
    }
    if best.count == k {
        print("after \(value): kth largest is \(best.peek()!)")
    } else {
        print("after \(value): fewer than \(k) values")
    }
}

var largest: [Int] = []
while let value = best.pop() {
    largest.append(value)
}
print("the \(k) largest, biggest first:", Array(largest.reversed()))
```

```output
after 12: fewer than 3 values
after 5: fewer than 3 values
after 31: kth largest is 5
after 8: kth largest is 8
after 27: kth largest is 12
after 19: kth largest is 19
after 3: kth largest is 19
after 40: kth largest is 27
the 3 largest, biggest first: [40, 31, 27]
```

What to notice:

- When 8 arrives, the best three are 5, 12 and 31. 8 beats the doorkeeper, 5, so 5 leaves. When 3 arrives, it doesn't beat 19, so nothing changes.
- `replaceTop(with:)` does "pop, then insert" with a single sift down: the new value lands on top, then sinks to its place.
- The heap never holds more than 3 values, however long the stream. Popping it at the end gives the top 3 from weakest to strongest, so the result is reversed.

The rule generalises, and it's worth memorising as a pair:

| You want | Keep a heap of size k that is | Its top is |
| --- | --- | --- |
| The k largest | a **min**-heap | the kth largest |
| The k smallest | a **max**-heap | the kth smallest |

<Callout kind="analogy">
A talent show has 3 finalist chairs. A judge keeps an eye on the weakest finalist sitting down. Each new act only has to beat that one person to take a chair, and the weakest finalist goes home. The judge never needs to rank the three seated finalists against each other.
</Callout>

## Why O(n log k)

Each of the n values costs at most one heap operation on a heap of at most k items: O(log k). So the total is O(n log k), and the memory is O(k). When k is small, log k is tiny: for the top 10 of a million values, each step is about 3 or 4 levels of sifting.

Compare the approaches from [Quickselect](/dsa/learn/sort-quickselect) and before:

| Approach | Time | Memory | Works on a stream? |
| --- | --- | --- | --- |
| Sort, then take k | O(n log n) | O(n) | No: needs all the data |
| Quickselect | O(n) expected, O(n²) worst | O(n) for a copy | No, and it rearranges the data |
| Heapify all n, pop k times | O(n + k log n) | O(n) | No |
| A heap of size k | O(n log k) | O(k) | **Yes** |

Quickselect wins for a single question over data already in memory. The size-k heap wins when data arrives over time, when memory is tight, or when k is small, and it gives the k items in order at the end, which quickselect doesn't.

## Top K frequent

"The k most common" is the same pattern after a counting pass. Count with a dictionary, as in [Counting with default: and grouping(by:)](/dsa/learn/swift-counting-grouping), then keep the k best (item, count) pairs in a heap whose top is the **worst** of them. Write one function that says what "worse" means, including how to break ties, and use it as the heap's order:

```swift run
// The heap from "Build a generic Heap<T>", compacted, plus replaceTop
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    var count: Int { items.count }
    var isEmpty: Bool { items.isEmpty }
    func peek() -> Element? { items.first }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        siftDownFromTop()
        return top
    }

    /// Replaces the top (the heap must not be empty) with one sift down
    mutating func replaceTop(with element: Element) {
        items[0] = element
        siftDownFromTop()
    }

    private mutating func siftDownFromTop() {
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { return }
            items.swapAt(parent, first)
            parent = first
        }
    }
}

func mostUsed(_ tags: [String], k: Int) -> [String] {
    var counts: [String: Int] = [:]
    for tag in tags {
        counts[tag, default: 0] += 1
    }
    // a is worse than b: fewer uses, or as many uses and later in the alphabet
    func isWorse(_ a: (tag: String, uses: Int), _ b: (tag: String, uses: Int)) -> Bool {
        a.uses != b.uses ? a.uses < b.uses : a.tag > b.tag
    }
    var best = Heap<(tag: String, uses: Int)>(areInIncreasingOrder: isWorse)    // worst on top
    for (tag, uses) in counts {
        if best.count < k {
            best.insert((tag, uses))
        } else if isWorse(best.peek()!, (tag, uses)) {
            best.replaceTop(with: (tag, uses))
        }
    }
    var result: [String] = []
    while let entry = best.pop() {
        result.append("\(entry.tag) \(entry.uses)")
    }
    return result.reversed()                     // popped worst first, so reverse
}

let tags = ["swift", "ios", "dsa", "swift", "heap", "ios", "swift", "dsa", "ui", "heap", "dsa"]
print(mostUsed(tags, k: 3))
print(mostUsed(tags, k: 1))
```

```output
["dsa 3", "swift 3", "heap 2"]
["dsa 3"]
```

Two subtleties:

- **Ties need a rule.** dsa and swift both appear 3 times; heap and ios both appear twice. Without a tie-break, which one makes the cut would depend on the dictionary's order, which changes from run to run. With "earlier in the alphabet wins", the answer is fixed.
- **Iterating a dictionary is fine here**, even though its order is random, because the heap's comparator decides the result completely. Printing the dictionary itself would not be.

The cost is O(n) to count plus O(m log k) for m distinct items. (You met a sorting version of this in M06's **Word frequency ranking**: O(m log m) instead.) There's also an O(n) **bucket** approach, as in [Bucket sort](/dsa/learn/sort-bucket): bucket c holds the items that appear c times, and you walk from the highest bucket down.

## K closest

"The k nearest drivers" is "the k smallest distances": a **max**-heap of size k, keyed by distance, so the farthest of the current k is the doorkeeper. Compare **squared** distances: x² + y² orders points exactly as the true distance does, without square roots or floating point.

```swift run
// The heap from "Build a generic Heap<T>", compacted, plus replaceTop

// The k closest points to (0, 0): a max-heap by distance, so the farthest of the k is on top
func closest(_ points: [(x: Int, y: Int)], k: Int) -> [(x: Int, y: Int)] {
    func squaredDistance(_ p: (x: Int, y: Int)) -> Int { p.x * p.x + p.y * p.y }
    var nearest = Heap<(x: Int, y: Int)>(areInIncreasingOrder: { squaredDistance($0) > squaredDistance($1) })
    for point in points {
        if nearest.count < k {
            nearest.insert(point)
        } else if squaredDistance(point) < squaredDistance(nearest.peek()!) {
            nearest.replaceTop(with: point)
        }
    }
    var result: [(x: Int, y: Int)] = []
    while let point = nearest.pop() {
        result.append(point)
    }
    return result.reversed()
}

let drivers = [(x: 3, y: 4), (x: 1, y: 1), (x: -2, y: 2), (x: 5, y: 0), (x: 0, y: -1), (x: 6, y: 6)]
for point in closest(drivers, k: 3) {
    print("(\(point.x), \(point.y)): squared distance \(point.x * point.x + point.y * point.y)")
}
```

```output
(0, -1): squared distance 1
(1, 1): squared distance 2
(-2, 2): squared distance 8
```

The comparator is `>` on distance: "a comes first when it's farther", which puts the farthest on top. In M31, **The nearest cafés** solved this with quickselect, O(n) expected but all at once. The heap version handles drivers whose positions arrive one by one.

## A bonus: sorting a nearly sorted array

If every value is at most k places from its sorted position, a heap of size k + 1 sorts it in O(n log k). Slide along the array, keeping the next k + 1 candidates in a min-heap. The smallest value overall must be among the first k + 1, so pop it into place, push the next value, and repeat:

```swift run
// The heap from "Build a generic Heap<T>", compacted, plus replaceTop
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    var count: Int { items.count }
    var isEmpty: Bool { items.isEmpty }
    func peek() -> Element? { items.first }

    mutating func insert(_ element: Element) {

        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        siftDownFromTop()
        return top
    }

    /// Replaces the top (the heap must not be empty) with one sift down
    mutating func replaceTop(with element: Element) {
        items[0] = element
        siftDownFromTop()
    }

    private mutating func siftDownFromTop() {
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent

            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { return }
            items.swapAt(parent, first)
            parent = first
        }
    }

// Sort an array where every value is at most k places from its sorted position
func sortNearlySorted(_ values: [Int], maxDistance k: Int) -> [Int] {
    var window = Heap<Int>(areInIncreasingOrder: <)
    var result: [Int] = []
    for value in values {
        window.insert(value)
        if window.count > k {                    // k + 1 candidates: the smallest is safe to place
            result.append(window.pop()!)
        }
    }
    while let value = window.pop() {
        result.append(value)
    }
    return result
}

print(sortNearlySorted([3, 1, 2, 6, 4, 5, 9, 7, 8], maxDistance: 2))
```

```output
[1, 2, 3, 4, 5, 6, 7, 8, 9]
```

In M30, **Nearly sorted array** did this with insertion sort in O(n · k). For large k, the heap is much faster.

<Callout kind="gotcha" title="The classic slips">
- **The heap points the wrong way.** A max-heap for "k largest" puts the champion on top, but the champion is the one you never need to evict. You need the weakest of the k on top.
- **Heaping everything.** Pushing all n values into a heap and popping k is correct but uses O(n) memory and O(n log n) time if you insert one by one. Cap the heap at k.
- **Forgetting the tie-break.** Without one, equal counts or distances make the answer depend on the input order, or on a dictionary's random order.
- **k larger than n.** Guard it: with fewer than k items, the heap simply holds all of them, and "the kth largest" doesn't exist yet.
</Callout>
