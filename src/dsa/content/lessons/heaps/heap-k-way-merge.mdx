## Why it matters

A web service runs on 50 servers, and each writes a log sorted by time. To investigate an outage, you need one log, in time order. A database has to sort 200 GB of rows with 8 GB of memory: it sorts memory-sized chunks, writes each to disk, then merges the sorted chunks. Search engines merge sorted lists of matching documents. All of these are the **k-way merge**: combining k sorted sequences into one. A heap holding one item per sequence does it in O(N log k) for N items in total, and it's the standard answer to the interview classic "merge k sorted lists".

## From two lists to k

You merged two sorted lists in [Merge two sorted lists](/dsa/learn/ll-merge-sorted): look at both heads, take the smaller, advance that list. With k lists, the same idea needs the **smallest of k heads** at every step. Scanning all k heads each time costs O(k) per item, O(N · k) in total. A min-heap of the heads gives the smallest in O(log k):

1. Put the first item of every non-empty list into a min-heap.
2. Pop the smallest. It's the next item of the output.
3. If the list it came from has another item, push that one.
4. Repeat until the heap is empty.

The heap never holds more than one item per list, so it never holds more than k items. Each heap entry needs to remember where it came from, so it can push its successor. With arrays, that's the list's number and the position within it:

```swift run
// The heap from "Build a generic Heap<T>", compacted, plus replaceTop
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    var count: Int { items.count }
    var isEmpty: Bool { items.isEmpty }
    func peek() -> Element? { items.first }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        siftDownFromTop()
        return top
    }

    /// Replaces the top (the heap must not be empty) with one sift down
    mutating func replaceTop(with element: Element) {
        items[0] = element
        siftDownFromTop()
    }

    private mutating func siftDownFromTop() {
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { return }
            items.swapAt(parent, first)
            parent = first
        }
    }
}

// Merge k sorted arrays: the heap holds one (value, list, position) entry per list
func mergeSorted(_ lists: [[Int]]) -> [Int] {
    var heads = Heap<(value: Int, list: Int, position: Int)>(areInIncreasingOrder: { $0.value < $1.value })
    for (list, values) in lists.enumerated() where !values.isEmpty {
        heads.insert((values[0], list, 0))
    }
    var merged: [Int] = []
    while let smallest = heads.pop() {
        merged.append(smallest.value)
        let next = smallest.position + 1
        if next < lists[smallest.list].count {
            heads.insert((lists[smallest.list][next], smallest.list, next))
        }
        print("took \(smallest.value) from list \(smallest.list); heap holds \(heads.count)")
    }
    return merged
}

print(mergeSorted([[1, 4, 9], [2, 3, 10], [], [0, 6]]))
```

```output
took 0 from list 3; heap holds 3
took 1 from list 0; heap holds 3
took 2 from list 1; heap holds 3
took 3 from list 1; heap holds 3
took 4 from list 0; heap holds 3
took 6 from list 3; heap holds 2
took 9 from list 0; heap holds 1
took 10 from list 1; heap holds 0
[0, 1, 2, 3, 4, 6, 9, 10]
```

The empty list never enters the heap. While all three non-empty lists still have items, the heap holds exactly 3: one pop, one push. It shrinks as lists run out: list 3 runs out after 6, list 0 after 9.

## Merging linked lists

With linked lists, a node already knows its successor, so the heap can hold the nodes themselves. A node is a class (a reference), so pushing it into the heap doesn't copy anything: the heap holds references to the original nodes, and merging relinks them. The comparator compares the nodes' values.

```swift run
// The heap from "Build a generic Heap<T>", compacted, plus replaceTop
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    var count: Int { items.count }
    var isEmpty: Bool { items.isEmpty }
    func peek() -> Element? { items.first }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        siftDownFromTop()
        return top
    }

    /// Replaces the top (the heap must not be empty) with one sift down
    mutating func replaceTop(with element: Element) {
        items[0] = element
        siftDownFromTop()
    }

    private mutating func siftDownFromTop() {
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { return }
            items.swapAt(parent, first)
            parent = first
        }
    }
}

final class ListNode {
    var value: Int
    var next: ListNode?
    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

/// Merges sorted lists by relinking their nodes. O(N log k).
func merge(_ lists: [ListNode?]) -> ListNode? {
    var heads = Heap<ListNode>(areInIncreasingOrder: { $0.value < $1.value })
    for case let head? in lists {                  // skip the empty lists
        heads.insert(head)
    }
    let dummy = ListNode(0)                          // a sentinel: no special case for the first node
    var tail = dummy
    while let smallest = heads.pop() {
        tail.next = smallest
        tail = smallest
        if let next = smallest.next {
            heads.insert(next)
        }
    }
    tail.next = nil
    return dummy.next
}

let lists = [makeList([1, 4, 7]), makeList([2, 2, 8]), nil, makeList([3, 4])]
print(describe(merge(lists)))
print(describe(merge([nil, nil])))
```

```output
1 -> 2 -> 2 -> 3 -> 4 -> 4 -> 7 -> 8 -> nil
nil
```

What to notice:

- `for case let head? in lists` loops over only the non-nil heads: pattern matching skips the empty lists.
- The **dummy node** from [Dummy and sentinel nodes](/dsa/learn/ll-sentinel) means the first real node needs no special case.
- `tail.next = nil` at the end is a safety line. The last node popped has no successor anyway (if it had one, that would have been pushed and popped after it), but ending the list explicitly keeps the code correct if you later change how nodes are pushed.
- Equal values (the two 4s, from different lists) may come out in either order. The values are the same either way.

DSAKit's `ListNode` is the same class with more helpers, so the practice problem's solution can push `ListNode`s into DSAKit's `Heap` directly.

## The cost, and the alternatives

Every one of the N items is pushed once and popped once, on a heap of at most k items: **O(N log k)** time and **O(k)** extra memory (the linked-list version reuses the nodes, so the output costs nothing extra).

| Approach | Time | Idea |
| --- | --- | --- |
| Concatenate and sort | O(N log N) | Ignores that the lists are sorted |
| Merge one list at a time | O(N · k) | The early items get walked again in every merge |
| Scan all k heads each step | O(N · k) | O(k) to find each minimum |
| Merge in pairs, round by round | O(N log k) | Like bottom-up merge sort: log₂ k rounds, each touching every item once |
| A heap of heads | O(N log k) | One push and one pop per item |

Merging one list at a time is the trap. With k = 1,000 lists of 100 items, the first list's items are walked about 1,000 times: around 50 million steps in total, against roughly a million heap steps (100,000 items × log₂ 1,000 ≈ 10). Pairwise merging matches the heap's bound without a heap, and it's worth mentioning in an interview. The heap version shines when the lists are **streams**: it only ever needs the current head of each.

## Where else it shows up

- **External sorting.** Sort chunks that fit in memory, write them out as sorted "runs", then k-way merge the runs, reading each one sequentially. With 25 runs, the heap holds 25 items while gigabytes flow through it.
- **Everyone's free time.** In [Interval intersections and free time](/dsa/learn/iv-intersections), each person's busy list was already sorted. A k-way merge by start time produces one sorted list of busy intervals in O(N log k), ready for the gap-finding sweep.
- **The kth smallest across sorted lists**, or in a matrix whose rows are sorted: run the merge and stop after k pops, O(k log k) if you start with only the first k rows.
- **The smallest range touching every list.** Keep one pointer per list in a min-heap, and track the largest value the pointers currently see. `[heap top, largest]` touches every list. The only way to narrow it is to advance the list holding the minimum. That's a k-way merge that stops as soon as one list runs out: the practice problem below.

<Callout kind="gotcha" title="Common mistakes">
- **Pushing nil lists.** An empty list has no head to compare. Filter them out first (`compactMap`, or `for case let head?`).
- **Pushing whole lists.** The heap must hold the current **head** of each list, then the head's successor, and so on. Pushing every node at the start works, but it's a heap of N items: O(N log N) time and O(N) memory.
- **Losing track of the source.** With arrays, a heap of bare values can't tell you which list to advance. Store (value, list, position).
- **Comparing with `<=`.** Equal values from different lists are fine in either order; the comparator only needs `<`.
</Callout>

## Practice

**Merge k sorted lists** is the linked-list version, with 10,000 lists in the biggest test: one-at-a-time merging is too slow there. **Smallest range touching every list** is the k-way merge that stops early, with a running maximum.
