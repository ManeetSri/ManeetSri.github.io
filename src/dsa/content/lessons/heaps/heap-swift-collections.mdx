## Why it matters

In an app or a server, you shouldn't ship a hand-rolled heap when a well-tested one exists. Apple's open-source **swift-collections** package (the home of the `Deque` you met in M27) has a `Heap` type, tuned and tested far beyond what a lesson can do. Knowing its API, and how it differs from the heap you built, lets you move from exercises to production code without surprises. This lesson is short: what to add, what to import, and what the methods are called.

## Adding the package

`Heap` arrived in swift-collections 1.1. In a Swift package, add the dependency and the product to your target in `Package.swift`:

```swift
// swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "Scheduler",
    dependencies: [
        .package(url: "https://github.com/apple/swift-collections.git", from: "1.1.0"),
    ],
    targets: [
        .executableTarget(
            name: "Scheduler",
            dependencies: [
                .product(name: "HeapModule", package: "swift-collections"),
            ]
        ),
    ]
)
```

In an Xcode app project, choose **File › Add Package Dependencies…**, paste the same URL, and add the `HeapModule` library (or `Collections`, which includes every module in the package) to your app target.

Then import it, either on its own or with everything else:

```swift
import HeapModule       // just Heap
// or
import Collections      // Heap, Deque, OrderedSet, OrderedDictionary and the rest
```

M64 tours the package's other structures, such as `OrderedSet` and `TreeDictionary`.

The lessons' `run` blocks are single files run with `swift file.swift`, which can't use packages, so the code in this lesson that uses `Heap` is shown without running it.

## The API

swift-collections' `Heap` is declared as `struct Heap<Element: Comparable>`: the order comes from the elements' own `<`, not from a closure. Here are the members you'll use most:

| Member | What it does | Cost |
| --- | --- | --- |
| `Heap()`, `Heap(someSequence)`, an array literal | create, with O(n) heapify for a sequence | O(1) or O(n) |
| `insert(_:)` | add one element | O(log n) |
| `insert(contentsOf:)` | add many elements | O(count + k) |
| `min`, `max` | the smallest and largest, or `nil` (properties, not methods) | O(1) |
| `popMin()`, `popMax()` | remove and return the smallest or largest, or `nil` | O(log n) |
| `removeMin()`, `removeMax()` | the same, but the heap must not be empty (it traps otherwise) | O(log n) |
| `replaceMin(with:)`, `replaceMax(with:)` | swap out the smallest or largest and return it; the heap must not be empty | O(log n) |
| `count`, `isEmpty`, `unordered` | size, and the elements in storage order | O(1) |

```swift
import HeapModule

var heap: Heap = [5, 3, 8]               // O(n) heapify
heap.insert(1)
heap.insert(contentsOf: [9, 4])

print(heap.min ?? -1)                    // 1
print(heap.max ?? -1)                    // 9
print(heap.popMin() ?? -1)               // 1
print(heap.popMax() ?? -1)               // 9
print(heap.count)                        // 4

let old = heap.replaceMin(with: 7)       // old is 3; 7 sifts into place
print(old, heap.min ?? -1)               // 3 4
```

Notice `heap.min`, without parentheses. If you find code online with `heap.min()`, it was written against a pre-release version: the methods became properties before 1.1.0 shipped.

Like DSAKit's `Heap`, it's a value type and it is **not** a `Sequence`, for the same reason: neither the storage order nor sorted order would be an honest iteration order. Pop until `nil` for sorted order, or read `unordered`.

## Both ends at once: a min-max heap

There's no separate max-heap type, because this `Heap` is a **min-max heap**: it gives O(1) access to both the smallest and the largest element, and O(log n) removal of either. It's still a complete tree in an array, but the levels alternate:

- On the **min levels** (the root's level, then every second level down), each node is ≤ everything below it.
- On the **max levels** (the root's children's level, and so on), each node is ≥ everything below it.

So the smallest element is the root, and the largest is one of the root's (at most two) children. Sifting compares grandparents and grandchildren as well as parents, which costs a little more per operation than a plain binary heap, but it means one structure answers "smallest?" and "largest?" equally fast. That's handy for problems like a bounded priority queue that must evict its **worst** item while serving its **best**.

## Custom priorities: a Comparable wrapper

Without a closure parameter, you express "order tasks by priority, then by arrival" by making the element type `Comparable`. Write `<` to compare what matters, using tuple comparison to chain the keys:

```swift run
struct Job: Comparable {
    let name: String
    let priority: Int       // 1 is the most urgent
    let arrival: Int        // breaks ties: first come, first served

    static func < (a: Job, b: Job) -> Bool {
        (a.priority, a.arrival) < (b.priority, b.arrival)
    }
}

let jobs = [
    Job(name: "backup", priority: 3, arrival: 0),
    Job(name: "email", priority: 1, arrival: 1),
    Job(name: "report", priority: 2, arrival: 2),
    Job(name: "alert", priority: 1, arrival: 3),
]
print(jobs.min()!.name)                  // what heap.min would be
print(jobs.max()!.name)                  // what heap.max would be
print(jobs.sorted().map(\.name))         // the order repeated popMin() calls would give
```

```output
email
backup
["email", "alert", "report", "backup"]
```

This file runs without the package, using the standard library's `min()`, `max()` and `sorted()`, which rely on the same `<`. Put these jobs into a `Heap<Job>` and `popMin()` hands them out in exactly the sorted order shown. The `Comparable` conformance you learned in [Equatable, Comparable and CustomStringConvertible](/dsa/learn/swift-standard-protocols) is all the heap needs.

<Callout kind="gotcha" title="Swift gotcha: == and < should agree">
`Comparable` inherits from `Equatable`, and here Swift synthesises `==` from **all** the stored properties, including `name`. Your `<` only looks at priority and arrival. That's fine as long as no two different jobs have the same priority **and** arrival. If they could, two jobs would be neither `<` nor `>` each other, yet not `==` either, which breaks the rules sorting and heaps rely on. A unique tie-breaker, like the arrival counter, keeps them consistent.
</Callout>

## Which heap when

| | DSAKit's `Heap` | swift-collections' `Heap` |
| --- | --- | --- |
| Order | a closure, chosen per heap | the element's `Comparable` conformance |
| Ends | one top (min or max, your choice) | both `min` and `max` |
| Naming | `peek()`, `pop()`, `replaceTop(with:)` | `min`, `popMin()`, `replaceMin(with:)` and the max versions |
| Best for | this course's exercises | production apps and servers |

The ideas carry over directly. "Keep a min-heap of the k largest" is `heap.insert(x)` then `if heap.count > k { heap.removeMin() }`, and "two heaps for the median" is a pair of `Heap<Int>`s where the lower half uses `max` and `popMax()`.

On interview and contest sites you often can't add packages, so check what your platform provides. If it's only the standard library, write the 30-line heap from [Build a generic `Heap<T>`](/dsa/learn/heap-build) from memory: it's worth practising until it takes five minutes.
