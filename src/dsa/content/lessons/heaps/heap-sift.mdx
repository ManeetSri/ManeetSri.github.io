## Why it matters

A heap has two rules, the heap property and the complete shape, and every change threatens one of them. Adding a value at the end keeps the shape but may break the order. Removing the root breaks the shape. Two small repair routines fix everything: **sift up** and **sift down**. Every heap operation, every priority queue, heap sort and all the patterns later in this module are built from these two loops, so it pays to know them by heart.

## Insert: append, then sift up

To add a value, put it in the only place that keeps the tree complete: the end of the array. The shape is fine, but the new value might be smaller than its parent. If it is, swap them. Now it might be smaller than its **new** parent, so check again. Stop when it's no smaller than its parent, or when it reaches the root. That's **sift up** (also called "bubble up" or "swim").

```swift run
var heap: [Int] = []

func push(_ value: Int) {
    heap.append(value)
    var child = heap.count - 1
    while child > 0 {
        let parent = (child - 1) / 2
        if heap[child] >= heap[parent] { break }      // settled: no smaller than its parent
        heap.swapAt(child, parent)
        child = parent
    }
}

for value in [5, 3, 8, 1, 9, 2] {
    push(value)
    print("push \(value): \(heap)")
}
```

```output
push 5: [5]
push 3: [3, 5]
push 8: [3, 5, 8]
push 1: [1, 3, 8, 5]
push 9: [1, 3, 8, 5, 9]
push 2: [1, 3, 2, 5, 9, 8]
```

Follow the 1. It lands at index 3, below the 5. It's smaller, so they swap, and the 1 is at index 1, below the 3. Smaller again, so they swap, and the 1 reaches the root. The 9 lands below the 3 and stays put: one comparison and done.

Why does one swap never break the rule somewhere else? When the new value moves up past its parent p, p moves down into its place. p was ≤ everything below it before, and the new value is smaller than p, so the new parent is smaller still. Only the new value's position is ever in doubt.

## Peek: the root

The smallest value is always at index 0, so looking at it is `heap.first`: O(1), and `nil` for an empty heap.

## Pop: move the last to the top, then sift down

Removing the root leaves a hole at the top. Fill it with the **last** element, because removing the last element keeps the tree complete. Now the shape is right, but the new root is probably too big. Compare it with its children. If the **smaller child** is smaller than it, swap them, and repeat from the child's position. Stop when neither child is smaller, or when it reaches a leaf. That's **sift down** (also "bubble down" or "sink").

```swift run
var heap = [1, 3, 2, 5, 9, 8]

func pop() -> Int? {
    guard !heap.isEmpty else { return nil }
    heap.swapAt(0, heap.count - 1)
    let smallest = heap.removeLast()
    var parent = 0
    while true {
        let left = 2 * parent + 1
        let right = left + 1
        var smaller = parent                          // the smallest of parent and its children
        if left < heap.count && heap[left] < heap[smaller] { smaller = left }
        if right < heap.count && heap[right] < heap[smaller] { smaller = right }
        if smaller == parent { break }                // settled: no child is smaller
        heap.swapAt(parent, smaller)
        parent = smaller
    }
    return smallest
}

while let smallest = pop() {
    print("pop \(smallest): \(heap)")
}
```

```output
pop 1: [2, 3, 8, 5, 9]
pop 2: [3, 5, 8, 9]
pop 3: [5, 9, 8]
pop 5: [8, 9]
pop 8: [9]
pop 9: []
```

In the first pop, 8 moves from the end to the root. Its children are 3 and 2; the smaller is 2, so they swap. At index 2, the 8 has no children, and it stops. The values come out in increasing order, 1, 2, 3, 5, 8, 9: popping a heap until it's empty sorts. That's the seed of heap sort, three lessons from now.

Why the **smaller** child? After the swap, that child becomes the parent of its old sibling. Being the smaller of the two, it's ≤ its sibling, so the rule holds there. Swap with the bigger child instead, and the bigger child ends up above the smaller one.

## Why both are O(log n)

Each step of sift up moves one level up, and each step of sift down moves one level down. A heap of n values has ⌊log₂ n⌋ levels below the root, so either operation makes at most that many swaps. Count them on 100,000 values, inserted in decreasing order so that every new value is the smallest so far and sifts all the way to the root:

```swift run
// Count the swaps made by pushes and pops on a min-heap
var heap: [Int] = []
var swaps = 0

func push(_ value: Int) {
    heap.append(value)
    var child = heap.count - 1
    while child > 0 && heap[child] < heap[(child - 1) / 2] {
        heap.swapAt(child, (child - 1) / 2)
        child = (child - 1) / 2
        swaps += 1
    }
}

func pop() -> Int {
    heap.swapAt(0, heap.count - 1)
    let smallest = heap.removeLast()
    var parent = 0
    while true {
        let left = 2 * parent + 1
        let right = left + 1
        var smaller = parent
        if left < heap.count && heap[left] < heap[smaller] { smaller = left }
        if right < heap.count && heap[right] < heap[smaller] { smaller = right }
        if smaller == parent { return smallest }
        heap.swapAt(parent, smaller)
        parent = smaller
        swaps += 1
    }
}

let n = 100_000
for value in stride(from: n, to: 0, by: -1) {        // each new value is the smallest so far
    push(value)
}
print("\(n) pushes: \(swaps) swaps, \(swaps / n) per push on average")

swaps = 0
var inOrder = true
for expected in 1...n where pop() != expected {
    inOrder = false
}
print("\(n) pops: \(swaps) swaps, \(swaps / n) per pop on average, in order: \(inOrder)")
```

```output
100000 pushes: 1468946 swaps, 14 per push on average
100000 pops: 1368947 swaps, 13 per pop on average, in order: true
```

The full heap is 16 levels deep (⌊log₂ 100,000⌋ = 16), and no push or pop ever made more than 16 swaps. A sorted array, by comparison, would shift about 50,000 elements per insert at this size.

## Min or max: the comparison decides

A max-heap is the same code with every comparison flipped. Rather than writing everything twice, pass the comparison in as a closure, as `sorted(by:)` does (you met it in [sorted(by:), min, max, contains and first(where:)](/dsa/learn/swift-sorting-searching-api)). The convention, borrowed from the standard library, is a closure named `areInIncreasingOrder`: it returns true when its **first** argument should be nearer the top.

```swift run
struct BinaryHeap {
    var items: [Int] = []
    let areInIncreasingOrder: (Int, Int) -> Bool     // true when the first should be nearer the top

    mutating func push(_ value: Int) {
        items.append(value)
        var child = items.count - 1
        while child > 0 {
            let parent = (child - 1) / 2
            if !areInIncreasingOrder(items[child], items[parent]) { break }
            items.swapAt(child, parent)
            child = parent
        }
    }

    mutating func pop() -> Int? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

var smallestFirst = BinaryHeap(areInIncreasingOrder: <)
var largestFirst = BinaryHeap(areInIncreasingOrder: >)
for value in [5, 3, 8, 1, 9, 2] {
    smallestFirst.push(value)
    largestFirst.push(value)
}
print(smallestFirst.items, largestFirst.items)

var ascending: [Int] = []
while let value = smallestFirst.pop() { ascending.append(value) }
var descending: [Int] = []
while let value = largestFirst.pop() { descending.append(value) }
print(ascending, descending)
```

```output
[1, 3, 2, 5, 9, 8] [9, 8, 5, 1, 3, 2]
[1, 2, 3, 5, 8, 9] [9, 8, 5, 3, 2, 1]
```

The same six values make two different arrays. In the max-heap, every parent is ≥ its children. Notice that `<` gives a **min**-heap: "a should come before b when a < b" puts the smallest on top. With `>`, the largest comes first. The closure can compare anything: tasks by deadline, points by distance, strings by length. Two lessons from now, you'll make this struct generic.

<Callout kind="analogy">
Think of a company org chart where every manager must be more senior than the people reporting to them. A new hire starts at the bottom; if they're more senior than their manager, they swap roles, and keep rising until the rule holds. When the CEO leaves, the most junior person is put in charge temporarily and keeps stepping down, swapping with their more senior report, until everyone above them outranks them.
</Callout>

<Callout kind="gotcha" title="The classic sift-down slips">
- **Always swapping with the left child.** If the right child is smaller, the left child ends up above it, and the heap is broken. Compare both children, and pick the one that should come first.
- **Forgetting `right < count`.** A node can have a left child but no right child (the last parent, when the count is even). Reading `items[right]` then crashes with "Index out of range".
- **Popping with `removeFirst()`.** It returns the right value but shifts every other element left by one, O(n), and the shifted array is no longer a heap.
- **Not stopping.** Sift down must stop as soon as no child should come first. Swapping on equal values (with `<=`) still gives a valid heap, but does pointless work.
</Callout>

**Smash the heaviest stones** needs the two largest values over and over: a max-heap, with pops and inserts. **Build a priority queue** asks you to write insert, peek and pop yourself, with a comparator; it continues through the next two lessons.

  front: "How does popping the top of a heap work?"
  back: "Swap the root with the last element and remove it, then sift the new root down: swap with whichever child should come first, while that child should come before it. O(log n)."

  front: "Why does sift down in a min-heap swap with the smaller child?"

  front: "With a closure areInIncreasingOrder, which closure gives a min-heap and which a max-heap?"
