## Why it matters

The sum tree and the minimum tree from the last lesson differ in two places: how two children combine, and what a skipped node returns. Everything else is identical. Pulling those two things out as parameters gives one `SegmentTree<Element>` that answers sums, minimums, maximums, gcds, "the cheapest day and which day it was", or the best run of profits inside a range, all with the same tested code. It's the same move [Build a generic `Heap<T>`](/dsa/learn/heap-build) made with a comparison closure, and it's the version DSAKit ships.

## What the tree needs from an operation

A segment tree never decides the order of the items: they stay in array order. But it does decide the **grouping**. The query 2...6 on 8 items is answered as `(items[2] + items[3]) + (items[4] + items[5]) + items[6]`, with the brackets chosen by the tree's blocks, not by you. So the combining function, call it `merge`, needs two properties.

**1. Associativity: the grouping doesn't change the answer.** For any a, b and c, `merge(merge(a, b), c)` must equal `merge(a, merge(b, c))`. Addition has it, and so do `min`, `max`, `gcd`, multiplication, `&`, `|`, `^` and string concatenation. Subtraction doesn't: (8 − 4) − 2 is 2, but 8 − (4 − 2) is 6.

**2. An identity: a value that changes nothing.** An `identity` with `merge(identity, x) == x` and `merge(x, identity) == x` for every x. The tree uses it for skipped nodes, empty ranges and the starting value of a running result. For `+` it's 0; for `min` it's the largest possible value; for concatenation it's the empty string.

A type with an associative operation and an identity is called a **monoid**. The word sounds abstract, but you've used dozens of them. Here are the common ones:

| Question about a range | `merge` | `identity` |
| --- | --- | --- |
| Sum | `+` | `0` |
| Product | `*` | `1` |
| Minimum | `min` | `Int.max` |
| Maximum | `max` | `Int.min` |
| Greatest common divisor | `gcd` | `0`, because gcd(0, x) = x |
| Bitwise AND of all | `&` | `-1` (every bit set) |
| Bitwise OR, XOR | `\|`, `^` | `0` |
| The text, joined | `+` on `String` | `""` |

Notice what's **not** required:

- **Commutativity.** The merge can care about order: `"ab" + "c"` isn't `"c" + "ab"`. The tree keeps items in array order, as long as the query merges left pieces before right pieces. That's the one detail the generic code below has to get right.
- **An inverse.** Prefix sums need subtraction to undo a sum. The tree never undoes anything, which is exactly why it handles `min` and `max`.

### When the operation isn't a monoid, change what you store

The average isn't associative: the average of (the average of 2 and 4) and 9 is 6, but the average of 2 and (the average of 4 and 9) is 4.25. The fix is to store something richer that *does* combine, here the pair `(sum, count)`, which merges by adding both parts, and compute the average from the pair at the end. That trick, choosing a summary of a block that two neighbouring summaries can produce, is the whole art of segment tree problems.

## The generic tree, step by step

DSAKit's `SegmentTree` uses the iterative layout from the last lesson: leaves in `storage[n..<2n]` and half-open ranges. It stores the identity and the merge alongside the array:

```swift
struct SegmentTree<Element> {
    private var storage: [Element]
    let count: Int
    private let identity: Element
    private let merge: (Element, Element) -> Element
}
```

`merge` is a stored closure, so the initialiser's parameter must be `@escaping`, as in [Escaping and non-escaping closures](/dsa/learn/swift-escaping). Slots `1..<n` start as the identity, then the build fills them from the last internal node back to the root.

The query is the one part that needs care. The bottom-up loop collects pieces from both ends of the range and works inwards. Pieces taken at the left end arrive in left-to-right order, so they go on the **right** of everything collected from the left so far. Pieces taken at the right end arrive right-to-left, so they go on the **left** of everything collected from the right. Keep two running results, then join them in the middle:

```swift run
// A generic segment tree: an associative merge and its identity, left-to-right order kept
struct SegmentTree<Element> {
    private var storage: [Element]
    let count: Int
    private let identity: Element
    private let merge: (Element, Element) -> Element

    init(_ values: [Element], identity: Element, merge: @escaping (Element, Element) -> Element) {
        count = values.count
        self.identity = identity
        self.merge = merge
        storage = Array(repeating: identity, count: values.count) + values
        for node in stride(from: count - 1, through: 1, by: -1) {
            storage[node] = merge(storage[2 * node], storage[2 * node + 1])
        }
    }

    func query(_ range: Range<Int>) -> Element {
        var left = range.lowerBound + count
        var right = range.upperBound + count
        var fromLeft = identity                   // pieces from the left end, in order
        var fromRight = identity                  // pieces from the right end, in order
        while left < right {
            if left % 2 == 1 {
                fromLeft = merge(fromLeft, storage[left])        // new piece goes after
                left += 1
            }
            if right % 2 == 1 {
                right -= 1
                fromRight = merge(storage[right], fromRight)     // new piece goes before
            }
            left /= 2
            right /= 2
        }
        return merge(fromLeft, fromRight)
    }

    mutating func update(at index: Int, to value: Element) {
        var node = index + count
        storage[node] = value
        while node > 1 {
            node /= 2
            storage[node] = merge(storage[2 * node], storage[2 * node + 1])
        }
    }
}

var sums = SegmentTree([5, 3, 7, 9, 6, 4, 1, 2], identity: 0, merge: +)
print(sums.query(2..<7))
sums.update(at: 3, to: 1)
print(sums.query(2..<7))

let highest = SegmentTree([4, -2, 8, 0, -7], identity: Int.min, merge: max)
print(highest.query(0..<2), highest.query(3..<5), highest.query(1..<1))

var words = SegmentTree(["a", "b", "c", "d", "e", "f"], identity: "", merge: +)
print(words.query(1..<5))
words.update(at: 2, to: "C")
print(words.query(0..<6))
```

```output
27
19
4 0 -9223372036854775808
bcde
abCdef
```

What to notice:

- `merge: +` and `merge: max` pass existing functions as closures. Swift picks the overload that matches `(Int, Int) -> Int` or `(String, String) -> String`.
- The empty range `1..<1` returns the identity, `Int.min`. That's correct: no element is the largest of nothing. Whether that's a sensible answer for *your* problem is your call.
- The strings come out in order. That's the real test of the two running results: a merge that cares about order would expose any mix-up immediately, while sums would hide it.

<Callout kind="warning" title="One running result is a bug that sums can't see">
If the query used a single `result` and wrote `result = merge(result, storage[right])` for right-end pieces, sums, minimums and maximums would still pass every test, because they're commutative. On six letters, the text query `1..<5` would come out as `"becd"`. When you test a generic tree, always include a merge that isn't commutative, such as concatenation.
</Callout>

## Richer summaries

The element type can be anything, including a tuple or a struct. That's where the generic tree earns its keep.

### The smallest value and where it is

Store `(price, day)` pairs and merge by keeping the cheaper one, breaking ties by the earlier day. The identity is a pair that loses every comparison:

```swift run
// A tuple monoid: the cheapest price in a range and the earliest day it happens
struct SegmentTree<Element> {
    private var storage: [Element]
    let count: Int
    private let identity: Element
    private let merge: (Element, Element) -> Element

    init(_ values: [Element], identity: Element, merge: @escaping (Element, Element) -> Element) {
        count = values.count
        self.identity = identity
        self.merge = merge
        storage = Array(repeating: identity, count: values.count) + values
        for node in stride(from: count - 1, through: 1, by: -1) {
            storage[node] = merge(storage[2 * node], storage[2 * node + 1])
        }
    }

    func query(_ range: Range<Int>) -> Element {
        var left = range.lowerBound + count, right = range.upperBound + count
        var fromLeft = identity, fromRight = identity
        while left < right {
            if left % 2 == 1 { fromLeft = merge(fromLeft, storage[left]); left += 1 }
            if right % 2 == 1 { right -= 1; fromRight = merge(storage[right], fromRight) }
            left /= 2
            right /= 2
        }
        return merge(fromLeft, fromRight)
    }
}

typealias Cheapest = (price: Int, day: Int)
func cheaper(_ a: Cheapest, _ b: Cheapest) -> Cheapest {
    if a.price != b.price { return a.price < b.price ? a : b }
    return a.day < b.day ? a : b                  // a tie goes to the earlier day
}

let prices = [7, 3, 9, 3, 5, 8]
let days = SegmentTree<Cheapest>(prices.enumerated().map { (price: $0.element, day: $0.offset) },
                                 identity: (Int.max, Int.max), merge: cheaper)
print(days.query(0..<6).day, days.query(2..<6).day, days.query(4..<6).day)
```

```output
1 3 4
```

Days 1 and 3 both cost 3. The tie-break makes the merge associative *and* deterministic: without it, which day you got back would depend on how the tree happened to group the blocks.

### No natural identity? Use an Optional

Some summaries have no value that changes nothing. Take "the best sum of a non-empty run of consecutive items inside the range", the [Kadane](/dsa/learn/arrays-kadane) question asked of a range. To combine two neighbouring blocks, each needs four numbers:

- `total`: the sum of the whole block;
- `prefix`: the best run that starts at the block's left end;
- `suffix`: the best run that ends at its right end;
- `best`: the best run anywhere inside it.

The best run of the joined block is either inside the left block, inside the right block, or crosses the middle, which means a suffix of the left plus a prefix of the right. There's no honest identity: a "nothing" block would need a best run of minus infinity. Wrapping the summary in an `Optional` solves it neatly. `nil` is the identity, and the merge returns the other side when one side is `nil`:

```swift run
// The best run inside a range: a struct summary, with nil as the identity
struct SegmentTree<Element> {
    private var storage: [Element]
    let count: Int
    private let identity: Element
    private let merge: (Element, Element) -> Element

    init(_ values: [Element], identity: Element, merge: @escaping (Element, Element) -> Element) {
        count = values.count
        self.identity = identity
        self.merge = merge
        storage = Array(repeating: identity, count: values.count) + values
        for node in stride(from: count - 1, through: 1, by: -1) {
            storage[node] = merge(storage[2 * node], storage[2 * node + 1])
        }
    }

    func query(_ range: Range<Int>) -> Element {
        var left = range.lowerBound + count, right = range.upperBound + count
        var fromLeft = identity, fromRight = identity
        while left < right {
            if left % 2 == 1 { fromLeft = merge(fromLeft, storage[left]); left += 1 }
            if right % 2 == 1 { right -= 1; fromRight = merge(storage[right], fromRight) }
            left /= 2
            right /= 2
        }
        return merge(fromLeft, fromRight)
    }
}

struct Piece {
    var total: Int                                // the whole block
    var prefix: Int                               // best run starting at its left end
    var suffix: Int                               // best run ending at its right end
    var best: Int                                 // best run anywhere inside
}

func combine(_ a: Piece?, _ b: Piece?) -> Piece? {
    guard let a else { return b }                 // nil is the identity
    guard let b else { return a }
    return Piece(total: a.total + b.total,
                 prefix: max(a.prefix, a.total + b.prefix),
                 suffix: max(b.suffix, b.total + a.suffix),
                 best: max(a.best, b.best, a.suffix + b.prefix))
}

let values = [2, -5, 3, 4, -1, 6, -8, 1]
let leaves: [Piece?] = values.map { Piece(total: $0, prefix: $0, suffix: $0, best: $0) }
let tree = SegmentTree(leaves, identity: nil, merge: combine)
print(tree.query(0..<8)!.best, tree.query(0..<2)!.best, tree.query(6..<8)!.best, tree.query(3..<7)!.best)
print(tree.query(2..<2) == nil)
```

```output
12 2 1 9
true
```

The best run of the whole array is 3 + 4 − 1 + 6 = 12. Each answer comes from O(log n) merges, and an update re-merges one path, so this handles 100,000 changes and questions where rerunning Kadane per question would be O(n) each.

## DSAKit's `SegmentTree`

The version in `dsa-swift/Sources/DSAKit/SegmentTree.swift` is the struct above with a few conveniences. Problems that `import DSAKit` can use it like this:

```swift
import DSAKit

var sums = SegmentTree([5, 3, 7, 9], identity: 0, merge: +)
sums.query(1..<3)                 // 10: any range expression works, half-open or closed
sums.query(1...3)                 // 19
sums.query(...)                   // 24: everything
sums.update(at: 2, to: 1)         // O(log n)
sums.update(at: 0, with: { $0 * 2 })
sums[2]                           // 1: the current value, O(1)
Array(sums)                       // [10, 3, 1, 9]: it's a Sequence of the current values

let lowest = SegmentTree.minimum([4, 2, 8])     // identity Int.max, merge min
let highest = SegmentTree.maximum([4, 2, 8])    // identity Int.min, merge max
let total = SegmentTree.sum([1.5, 2.25])        // any AdditiveArithmetic type
```

It's a value type, so copying a tree gives an independent tree, like copying an array.

<Callout kind="gotcha" title="Swift gotchas">
- **`min` and `max` inside a type.** In a struct or extension that has its own `min` or `max` member, a bare `min(a, b)` refers to that member and fails to compile. Write `Swift.min(a, b)`. DSAKit's code does this throughout.
- **Labelled tuples lose their labels in inference.** Without `<Cheapest>`, Swift infers the element type from the unlabelled identity `(Int.max, Int.max)` as plain `(Int, Int)`, and `.day` no longer compiles. Spell out the element type when it's a labelled tuple, or use a small struct.
- **The identity must really be one.** `0` is not the identity of `max` once values can be negative: the maximum of `[-3, -5]` would come out as 0.
</Callout>
