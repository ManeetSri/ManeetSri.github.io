## Why it matters

The last lesson found the shape: a tree of block sums, halving at each level. This lesson turns it into code you can write from memory in a contest or an interview: an array to hold the tree, a recursive **build**, a **query** that adds up a few whole blocks, and an **update** that repairs one path. Almost every range-query structure in this part of the course is a variation on these three functions, so it's worth getting them exactly right once.

## Storing the tree in an array

A segment tree is a binary tree, but it doesn't need node objects or pointers. Number the nodes the way [A complete tree in an array](/dsa/learn/heap-array-index) numbered a heap's, except **starting from 1**:

- the root is node 1;
- node k's children are nodes `2k` and `2k + 1`;
- node k's parent is node `k / 2`.

Starting from 1 makes the arithmetic one step shorter than the heap's 0-based `2i + 1` and `2i + 2`, which is why nearly every segment tree you'll read does it. Slot 0 of the array is left unused.

A node doesn't store which range it covers. The recursion works it out: node 1 covers `0...n - 1`, and a node covering `low...high` splits at `mid = (low + high) / 2`, giving its left child `low...mid` and its right child `mid + 1...high`. A node with `low == high` is a **leaf** holding a single item.

### How big must the array be?

When n is a power of two, the tree is perfect: n leaves, n − 1 internal nodes, and the largest index is `2n − 1`. For other n, the halves are uneven, some leaves sit a level deeper than others, and the numbering leaves gaps. This program finds the largest index the recursion actually uses:

```swift run
// The largest node index the recursive layout uses, for n items
func largestIndex(_ node: Int, _ low: Int, _ high: Int) -> Int {
    if low == high { return node }
    let mid = (low + high) / 2
    return max(largestIndex(2 * node, low, mid), largestIndex(2 * node + 1, mid + 1, high))
}
for n in [1, 5, 6, 8, 9, 17, 100, 1_000] {
    print("n = \(n): largest index \(largestIndex(1, 0, n - 1)), 2n = \(2 * n), 4n = \(4 * n)")
}
```

```output
n = 1: largest index 1, 2n = 2, 4n = 4
n = 5: largest index 9, 2n = 10, 4n = 20
n = 6: largest index 13, 2n = 12, 4n = 24
n = 8: largest index 15, 2n = 16, 4n = 32
n = 9: largest index 17, 2n = 18, 4n = 36
n = 17: largest index 33, 2n = 34, 4n = 68
n = 100: largest index 253, 2n = 200, 4n = 400
n = 1000: largest index 2045, 2n = 2000, 4n = 4000
```

For n = 6 and n = 100, an array of 2n would be too small and the program would crash. The safe size is **4n**: the tree's height is at most ⌈log₂ n⌉, so every index is below 2 to the power ⌈log₂ n⌉ + 1, which is less than 4n. The memory is O(n) either way, and with 100,000 items, 400,000 `Int`s is about 3 MB.

## Build: fill the tree from the leaves up

`build(node, low, high)` fills node `node`, which covers `items[low...high]`. A leaf copies its item. Any other node builds its two children first, then adds their sums.

```swift run
// Build a sum segment tree recursively, nodes numbered from 1
let items = [5, 3, 7, 9, 6, 4, 1, 2]
var tree = Array(repeating: 0, count: 4 * items.count)

func build(_ node: Int, _ low: Int, _ high: Int) {
    if low == high {
        tree[node] = items[low]                   // a leaf holds one item
        return
    }
    let mid = (low + high) / 2
    build(2 * node, low, mid)                     // left half: low...mid
    build(2 * node + 1, mid + 1, high)            // right half: mid + 1...high
    tree[node] = tree[2 * node] + tree[2 * node + 1]
}

build(1, 0, items.count - 1)
print("root:   ", tree[1])
print("level 1:", tree[2...3])
print("level 2:", tree[4...7])
print("leaves: ", tree[8...15])
```

```output
root:    37
level 1: [24, 13]
level 2: [8, 16, 10, 3]
leaves:  [5, 3, 7, 9, 6, 4, 1, 2]
```

These are exactly the block sums from the last lesson, now living at fixed indexes. Every node is visited once and does O(1) work, and there are 2n − 1 nodes, so the build is **O(n)**. Building by calling an update n times would also work, but costs O(n log n).

## Query: three cases

To find the sum of `items[left...right]`, start at the root and ask each node one question: how does my range `low...high` overlap the query?

1. **No overlap** (`right < low` or `high < left`): this node contributes nothing. Return 0.
2. **Fully covered** (`left <= low` and `high <= right`): the whole block is wanted. Return `tree[node]` without looking further down.
3. **Partial overlap**: some of the block is wanted and some isn't. Ask both children and add their answers.

```swift
func query(_ node: Int, _ low: Int, _ high: Int, _ left: Int, _ right: Int) -> Int {
    if right < low || high < left { return 0 }                  // no overlap
    if left <= low && high <= right { return tree[node] }       // fully covered
    let mid = (low + high) / 2                                  // partial: ask both halves
    return query(2 * node, low, mid, left, right)
         + query(2 * node + 1, mid + 1, high, left, right)
}
```

The first call is `query(1, 0, n - 1, left, right)`. Step through some queries and an update below. Green nodes are fully covered and used whole, amber ones are split, and red ones are skipped.

```visual segmentTree
items: [5, 3, 7, 9, 6, 4, 1, 2]
operations: [["query", 2, 6], ["update", 3, 1], ["query", 2, 6], ["query", 1, 4]]
```

### Why a query visits O(log n) nodes

A node is split (amber) only if the query range starts or ends strictly inside it. The range has two ends, so **at most two nodes per level are split**. Only split nodes have their children visited, so at most four nodes per level are visited at all, and there are about log₂ n levels: at most about 4 log₂ n nodes.

You can check the bound by counting. This program runs 10,000 random queries on a tree of 100,000 items, where ⌈log₂ 100,000⌉ = 17, so the bound is 4 × 17 = 68:

```swift run
// Count the nodes a query visits, over many ranges of a 100,000-item tree
let n = 100_000
var visited = 0
func query(_ node: Int, _ low: Int, _ high: Int, _ left: Int, _ right: Int) {
    visited += 1
    if right < low || high < left { return }
    if left <= low && high <= right { return }
    let mid = (low + high) / 2
    query(2 * node, low, mid, left, right)
    query(2 * node + 1, mid + 1, high, left, right)
}

var state: UInt64 = 7                             // a fixed seed, so every run is the same
func nextIndex() -> Int {
    state = state &* 6364136223846793005 &+ 1442695040888963407
    return Int((state >> 33) % UInt64(n))
}

var most = 0
var total = 0
for _ in 0..<10_000 {
    let a = nextIndex(), b = nextIndex()
    visited = 0
    query(1, 0, n - 1, min(a, b), max(a, b))
    most = max(most, visited)
    total += visited
}
print("most nodes visited by one query:", most)
print("average:", total / 10_000)
```

```output
most nodes visited by one query: 67
average: 59
```

Around 60 nodes, where adding up the items directly would touch about 33,000 per range on average. Notice that the count includes the red nodes: skipped nodes still cost a function call each, which is why the bound is four per level and not two.

## Update: one path down, then repair on the way up

Setting `items[index] = value` changes the leaf for `index` and every node above it, and nothing else. Walk down towards the leaf, choosing the half that contains `index`, set the leaf, and recompute each node as the recursion returns:

```swift
func update(_ node: Int, _ low: Int, _ high: Int, _ index: Int, _ value: Int) {
    if low == high {
        tree[node] = value                                       // the leaf for items[index]
        return
    }
    let mid = (low + high) / 2
    if index <= mid {
        update(2 * node, low, mid, index, value)
    } else {
        update(2 * node + 1, mid + 1, high, index, value)
    }
    tree[node] = tree[2 * node] + tree[2 * node + 1]             // repair on the way back up
}
```

One node per level: **O(log n)**. The last line is the one people forget. Without it, the leaf changes and every block above it keeps its old sum.

## The whole thing as a struct

Wrapped in a struct, the recursion's extra parameters stay private, and callers see `sum(left, right)` and `set(index, to:)`. The program then checks the tree against plain addition after 1,000 updates, comparing every range each time.

```swift run
// A sum segment tree: recursive, nodes numbered from 1, closed ranges
struct SumTree {
    private var tree: [Int]
    private let count: Int

    init(_ items: [Int]) {
        count = items.count
        tree = Array(repeating: 0, count: max(1, 4 * items.count))
        if count > 0 { build(items, 1, 0, count - 1) }
    }

    /// The sum of items[left...right].
    func sum(_ left: Int, _ right: Int) -> Int {
        query(1, 0, count - 1, left, right)
    }

    mutating func set(_ index: Int, to value: Int) {
        update(1, 0, count - 1, index, value)
    }

    private mutating func build(_ items: [Int], _ node: Int, _ low: Int, _ high: Int) {
        if low == high {
            tree[node] = items[low]
            return
        }
        let mid = (low + high) / 2
        build(items, 2 * node, low, mid)
        build(items, 2 * node + 1, mid + 1, high)
        tree[node] = tree[2 * node] + tree[2 * node + 1]
    }

    private func query(_ node: Int, _ low: Int, _ high: Int, _ left: Int, _ right: Int) -> Int {
        if right < low || high < left { return 0 }
        if left <= low && high <= right { return tree[node] }
        let mid = (low + high) / 2
        return query(2 * node, low, mid, left, right) + query(2 * node + 1, mid + 1, high, left, right)
    }

    private mutating func update(_ node: Int, _ low: Int, _ high: Int, _ index: Int, _ value: Int) {
        if low == high {
            tree[node] = value
            return
        }
        let mid = (low + high) / 2
        if index <= mid {
            update(2 * node, low, mid, index, value)
        } else {
            update(2 * node + 1, mid + 1, high, index, value)
        }
        tree[node] = tree[2 * node] + tree[2 * node + 1]
    }
}

var sums = SumTree([5, 3, 7, 9, 6, 4, 1, 2])
print(sums.sum(2, 6))
sums.set(3, to: 1)
print(sums.sum(2, 6), sums.sum(0, 7), sums.sum(4, 4))

// Check every range against plain addition, after each of 1,000 updates on 11 items
var items = [4, -2, 8, 0, 3, 3, 9, -5, 1, 6, 2]
var checked = SumTree(items)
var mismatches = 0
for step in 0..<1_000 {
    let index = (step * 7) % items.count
    let value = (step * 13) % 21 - 10
    items[index] = value
    checked.set(index, to: value)
    for left in 0..<items.count {
        for right in left..<items.count where checked.sum(left, right) != items[left...right].reduce(0, +) {
            mismatches += 1
        }
    }
}
print("mismatches:", mismatches)
```

```output
27
19 29 6
mismatches: 0
```

What to notice:

- 11 items isn't a power of two, and nothing special was needed: uneven halves are fine.
- `max(1, 4 * items.count)` keeps the array non-empty, but `sum` on an empty tree would still fail, because `count - 1` is -1. Decide what an empty tree should do before you need one; the struct in DSAKit returns the identity.
- A brute-force check like this one, on small inputs with every range compared, catches almost every off-by-one mistake. Do it whenever you write a tree from scratch.

## Minimums and maximums

Only three things in the code know the tree holds sums: the `+` that combines two children (in `build` and `update`), the `+` in `query`, and the `0` returned for no overlap. For a minimum tree, combine with `min` and return `Int.max` for no overlap. For a maximum, use `max` and `Int.min`. Those values are chosen so they never win: `min(x, Int.max)` is always x, just as `x + 0` is x.

```swift
if right < low || high < left { return Int.max }                    // can't beat anything
if left <= low && high <= right { return tree[node] }
let mid = (low + high) / 2
return min(query(2 * node, low, mid, left, right), query(2 * node + 1, mid + 1, high, left, right))
```

Returning 0 from a minimum tree is a classic bug: every range that includes a skipped node would report 0 as its minimum, unless the real minimum is negative. The next lesson names this value, the **identity**, and makes it a parameter.

## The other version: iterative, bottom-up, 2n slots

There's a second layout you'll see in a lot of competitive code. Put the n items as the leaves in `tree[n..<2n]`, and fill every internal node `k` from `n - 1` down to 1 as `tree[2k] + tree[2k + 1]`. Then there's no recursion at all:

- **Update**: set leaf `index + n`, then walk up with `node /= 2`, recomputing each parent.
- **Query** on a half-open range `left..<right`: move both ends to the leaf level, then climb. At each level, if `left` is a right child (odd), its parent would also cover something to the left of the range, so take `tree[left]` on its own and step past it. Likewise, if `right` is odd, `right - 1` is a left child whose parent would cover `right`, which is outside the range: take `tree[right - 1]` on its own. Then halve both and repeat until they meet.

This version answers range minimums, on 6 items:

```swift run
// The bottom-up segment tree: leaves in tree[n..<2n], half-open ranges, no recursion
struct MinTree {
    private var tree: [Int]
    private let n: Int

    init(_ items: [Int]) {
        n = items.count
        tree = Array(repeating: Int.max, count: n) + items           // leaves at n..<2n
        for node in stride(from: n - 1, through: 1, by: -1) {
            tree[node] = min(tree[2 * node], tree[2 * node + 1])
        }
    }

    mutating func set(_ index: Int, to value: Int) {
        var node = index + n
        tree[node] = value
        while node > 1 {
            node /= 2
            tree[node] = min(tree[2 * node], tree[2 * node + 1])
        }
    }

    func minimum(_ range: Range<Int>) -> Int {
        var left = range.lowerBound + n
        var right = range.upperBound + n
        var best = Int.max
        while left < right {
            if left % 2 == 1 {                    // a right child: its parent sticks out on the left
                best = min(best, tree[left])
                left += 1
            }
            if right % 2 == 1 {                   // right - 1 is a left child: its parent sticks out on the right
                right -= 1
                best = min(best, tree[right])
            }
            left /= 2
            right /= 2
        }
        return best
    }
}

var prices = MinTree([7, 3, 9, 3, 5, 8])
print(prices.minimum(0..<6), prices.minimum(2..<3), prices.minimum(2..<2))
prices.set(1, to: 10)
prices.set(3, to: 10)
print(prices.minimum(0..<4), prices.minimum(4..<6))
```

```output
3 9 9223372036854775807
7 5
```

The empty range `2..<2` returns `Int.max`, the identity, because the loop never runs. Six isn't a power of two, and the code still works: a few internal nodes, node 1 included, end up mixing blocks from both ends of the array, but the loop never uses them.

| | Recursive, 4n | Iterative, 2n |
| --- | --- | --- |
| Memory | 4n slots | 2n slots |
| Natural ranges | closed, `left...right` | half-open, `left..<right` |
| Speed | function calls at every node | a tight loop, usually faster |
| Extending it | easy: lazy propagation, walking down the tree | awkward beyond point updates |

This course teaches the **recursive version as the main one**, because it matches the picture, and lazy propagation, later in this module, needs its top-down shape. DSAKit's `SegmentTree` uses the iterative one, since it only does point updates and range queries, and the next lesson builds it.

<Callout kind="gotcha" title="Common mistakes">
- **An array of 2n with the recursive layout.** It works for powers of two and crashes for n = 6. Use 4n.
- **Mixing closed and half-open ranges.** The recursive version's checks (`right < low`, `left <= low`) assume `left...right`. Feeding it a half-open `right` includes one item too many. Pick one convention per tree and convert at the boundary.
- **Forgetting the repair line in `update`.** The leaf changes, the blocks above don't, and queries that use those blocks return stale sums.
- **The wrong identity.** Returning 0 for "no overlap" in a minimum tree reports 0 as the minimum of many ranges.
</Callout>
