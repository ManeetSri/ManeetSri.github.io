## Why it matters

Plenty of real values can be missing. Not everyone has a middle name. A search might find nothing. The text "hello" can't be turned into a number. Swift makes "this might be missing" part of a value's **type**, so the compiler reminds you to handle the missing case before it can crash your app. In DSA, almost every search returns "the answer, or nothing", and optionals are how Swift says that.

## The problem with made-up "nothing" values

Suppose you write code to find the position of the first negative number in a list. What should it give back when there isn't one?

Many languages use a special value, called a **sentinel**, such as `-1` or `0`:

```swift run
let temperatures = [4, 7, 12, 9]
var firstFreezingDay = -1   // -1 means "none"

for i in 0..<temperatures.count {
    if temperatures[i] < 0 {
        firstFreezingDay = i
        break
    }
}
print(firstFreezingDay)
```

```output
-1
```

It works, as long as everyone remembers that `-1` means "none". Nothing stops someone from using it as a real position, and the type, `Int`, doesn't warn them. Worse, some questions have no safe sentinel at all. What's the largest number in an empty list? `0` is wrong: it might be a real answer, and for `[-5, -2]` it isn't even in the list. You saw that bug in [the problem-solving framework](/dsa/learn/start-problem-solving).

Swift's answer is to make the *possibility* of a missing value visible in the type.

## Optional: a box that might be empty

An **optional** is like a box. Either there's a value inside, or the box is empty. An empty box is written `nil`.

You write an optional type by adding a question mark to the type: `Int?` (read "optional Int") is a box that holds an `Int` or nothing.

```swift run
var middleName: String? = nil
var luckyNumber: Int? = 7

print(middleName == nil)
print(luckyNumber == nil)

luckyNumber = nil
print(luckyNumber == nil)
```

```output
true
false
true
```

- `String?` and `Int?` are optional types. They can hold a value or `nil`.
- `== nil` and `!= nil` check whether the box is empty.
- A `var` optional can change between holding a value and being empty.

If you declare an optional `var` without a value, it starts as `nil`: `var nickname: String?` is the same as `var nickname: String? = nil`.

<Callout kind="analogy" title="The parcel box">
Think of a parcel box by your door. `Int?` is the box, not the parcel. You can see whether something's been delivered (`!= nil`), but to use what's inside you have to open the box first. The rest of this module is about safe ways to open it.
</Callout>

## Plain types can never be nil

The flip side is the important part: a type **without** a question mark can never be `nil`. A `String` always holds a string, and an `Int` always holds a number.

```swift
let name: String = nil   // error
```

```text title="What you'll see"
error: 'nil' cannot initialize specified type 'String'
```

That's a guarantee you can rely on. In some languages any value might secretly be "null", and forgetting to check crashes the program, a mistake so common that its inventor, Tony Hoare, called null references his "billion-dollar mistake". In Swift, you only have to think about missing values where the type says `?`.

## You can't use the box as if it were the value

An `Int?` is not an `Int`. You can't do arithmetic with it directly, because it might be empty:

```swift
let score: Int? = 40
print(score + 10)   // error
```

```text title="What you'll see"
error: value of optional type 'Int?' must be unwrapped to a value of type 'Int'
```

**Unwrapping** means taking the value out of the box, after dealing with the possibility that it's empty. The next lessons cover every way to do it: `if let`, `guard let`, `??`, optional chaining, and `!`. For now, just notice that Swift won't let you forget.

## Printing an optional

When you print an optional, Swift shows the box as well as what's in it:

```swift run
let found: Int? = 5
let missing: Int? = nil

print(found)
print(missing)
```

```output
Optional(5)
nil
```

Swift also gives a **warning** when it compiles this, "expression implicitly coerced from 'Int?' to 'Any'", to point out that you're printing a box, not a number. The program still runs. Warnings are worth reading, but they don't stop your code; errors do.

<Callout kind="gotcha" title="Swift gotcha: Optional(…) in your text">
The same thing happens inside string interpolation. `"Score: \(found)"` gives `Score: Optional(5)`, which is almost never what you want on screen. Unwrap the value first, as the next lessons show.
</Callout>

## Where optionals come from

You'll rarely type `Int?` yourself at first. Optionals mostly come from operations that might fail:

```swift run
let ages = ["Ana": 31, "Ben": 27]
let numbers = [8, 3, 5]
let empty: [Int] = []

print(Int("42"))       // text that is a number
print(Int("hello"))    // text that isn't
print(ages["Ana"])     // a key that exists
print(ages["Zoe"])     // a key that doesn't
print(numbers.first)
print(empty.first)
```

```output
Optional(42)
nil
Optional(31)
nil
Optional(8)
nil
```

- `Int("42")` turns text into a number. Not all text is a number, so it gives an `Int?`.
- Looking up a key in a dictionary gives an optional, because the key might not be there.
- `first` gives an array's first element, or `nil` when the array is empty.

You'll explore all of these in the last lesson of this module, *optionals from lookups and conversions*.

## Under the hood: an enum with two cases

An optional isn't magic. `Int?` is shorthand for `Optional<Int>`, an **enum**, a type whose value is one of a fixed list of cases. It has exactly two:

- `.some(value)`: the box holds a value;
- `.none`: the box is empty, which is what `nil` means.

You can even `switch` on an optional to handle both cases:

```swift run
let reply: Int? = Int("17")

switch reply {
case .some(let value):
    print("Got the number \(value)")
case .none:
    print("That wasn't a number")
}
```

```output
Got the number 17
```

`case .some(let value)` binds the value inside the box, like the value bindings you met in [switch and pattern matching](/dsa/learn/swift-switch). You'll learn about enums properly in M09. You won't often switch on an optional, because `if let` is shorter, but it's useful to know there's nothing hidden: an optional really is either "some value" or "none".
