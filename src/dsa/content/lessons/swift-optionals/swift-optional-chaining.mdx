## Why it matters

Sometimes you don't want the optional value itself, but something *about* it: the length of a name that might be missing, the first item of a list that might not exist. Optional chaining lets you ask, and gives back `nil` if any step along the way is missing, instead of crashing. iOS code is full of it, from `navigationController?.popViewController(animated: true)` to `textField.text?.isEmpty`.

## Asking an optional a question with ?.

A **property** is a value that belongs to another value, like a string's `count`. A **method** is a function that belongs to a value, like a string's `uppercased()`. Normally you reach both with a dot. On an optional, write `?.` instead:

```swift run
let nickname: String? = "maverick"
let noNickname: String? = nil

print(nickname?.count)
print(nickname?.uppercased())
print(noNickname?.count)
```

```output
Optional(8)
Optional("MAVERICK")
nil
```

Read `nickname?.count` as "if there's a nickname, its count; otherwise nil". Two things to notice:

1. If the optional holds a value, the property or method is used on it as normal.
2. The result is **always optional**. `count` is an `Int`, but `nickname?.count` is an `Int?`, because the answer depends on whether there was a nickname at all.

When the optional is nil, Swift doesn't even try to call the method. The whole expression is simply nil. Nothing crashes.

## Chains of several steps

Each `?.` is one link in a chain. If any link finds nil, the rest of the chain is skipped and the result is nil:

```swift run
let teams = [
    "red": ["Ana", "Ben"],
    "blue": [String](),
]

print(teams["red"]?.first?.count)
print(teams["blue"]?.first?.count)
print(teams["green"]?.first?.count)
```

```output
Optional(3)
nil
nil
```

`[String]()` creates an empty array of strings. Follow each line link by link:

- `teams["red"]` finds an array, its `first` is `"Ana"`, and that has 3 characters.
- `teams["blue"]` finds an array, but it's empty, so `first` is nil and the chain stops.
- `teams["green"]` finds nothing at all, so the chain stops at the first link.

Even though there are two optional steps, the result is a single `Int?`, not an optional inside an optional. Optional chaining **flattens** the result: one `?` at the end, however many links there were.

## Finishing a chain with ??

A chain gives an optional, so it pairs naturally with `??` from [the ?? operator](/dsa/learn/swift-nil-coalescing) when you want a plain value at the end:

```swift run
let searchText: String? = nil
let letterCount = searchText?.count ?? 0
print("Letters typed: \(letterCount)")

let words = ["swift", "is", "fun"]
let empty: [String] = []
print(words.last?.uppercased() ?? "nothing")
print(empty.last?.uppercased() ?? "nothing")
```

```output
Letters typed: 0
FUN
nothing
```

`searchText?.count ?? 0` reads "the length of the search text, or 0 if there's no text". This pairing, `?.` then `??`, is one of the most common lines in Swift code.

## Chaining with if let

You can also unwrap the end of a chain with `if let`. The block runs only if every link succeeded:

```swift run
let scores = ["Ana": [72, 91, 85], "Ben": [64]]

if let best = scores["Ana"]?.max() {
    print("Ana's best score: \(best)")
}
if let best = scores["Cleo"]?.max() {
    print("Cleo's best score: \(best)")
} else {
    print("No scores for Cleo")
}
```

```output
Ana's best score: 91
No scores for Cleo
```

`max()` gives the largest element of an array, or nil if it's empty. Here the chain could fail in two places, a missing name or an empty list, and one `if let` covers both.

## Changing a value through a chain

Optional chaining also works when you change something. Here `append` adds an element to the end of an array stored in a dictionary, but only if that array exists:

```swift run
var playlists = ["chill": ["Song A"], "gym": ["Song B", "Song C"]]

playlists["chill"]?.append("Song D")
playlists["party"]?.append("Song E")

print(playlists["chill"] ?? [])
print(playlists["party"] ?? [])
```

```output
["Song A", "Song D"]
[]
```

The `"chill"` playlist exists, so the song is added. There's no `"party"` playlist, so the second line quietly does nothing. It doesn't create one, and it doesn't crash. Silence is safe, but make sure it's what you want: if a missing playlist is a bug, check for it instead.

<Callout kind="gotcha" title="Swift gotcha: comparing an optional result">
`==` and `!=` work with optionals, so `name?.count == 3` is fine: it's false when `name` is nil. But `<` and `>` don't: `name?.count > 3` won't compile, with "binary operator '>' cannot be applied to operands of type 'Int?' and 'Int'". Supply a default first: `(name?.count ?? 0) > 3`.
</Callout>

```swift run
let name: String? = "Kai"

print(name?.count == 3)
print((name?.count ?? 0) > 5)
```

```output
true
false
```

## ?. versus !.

You'll soon meet `!`, which forces a value out of an optional and crashes if there isn't one. `name!.count` would crash for a nil `name`, while `name?.count` gives nil. When in doubt, choose `?.`: a nil you have to deal with is always better than a crash. The next lesson covers the few places where `!` is reasonable.
