## Why it matters

An optional is only useful once you can safely get the value out. `if let` and `guard let` are the everyday tools for that: they check whether the box has something in it and, if it does, hand you the value as a plain, non-optional constant. You'll write them constantly, in iOS code ("if the user typed a valid number…") and in DSA ("if the stack has a top element…").

## if let: unwrap when there's a value

`if let` checks an optional and, when it holds a value, puts that value in a new constant for use inside the braces:

```swift run
let input = "42"

if let number = Int(input) {
    print("You typed \(number). Doubled, that's \(number * 2).")
} else {
    print("\"\(input)\" isn't a whole number.")
}
```

```output
You typed 42. Doubled, that's 84.
```

Read it as "if there's a number in `Int(input)`, call it `number` and run this block". Inside the braces, `number` is a plain `Int`, so arithmetic works and interpolation prints `42`, not `Optional(42)`. If the box is empty, the `else` block runs instead. Change `input` to `"forty"` and you'd see `"forty" isn't a whole number.`

This is called **optional binding**: binding the value inside an optional to a new name.

## The shorthand: if let name

Very often you unwrap an optional that already has a good name, and the unwrapped value deserves the same name. Since Swift 5.7 you can write just `if let name`:

```swift run
let nickname: String? = "Mo"

if let nickname {
    print("Hi, \(nickname)!")
} else {
    print("Hi there!")
}
```

```output
Hi, Mo!
```

Inside the braces, `nickname` refers to the unwrapped `String`. Outside, it's still the optional. This is the same as the older, longer form `if let nickname = nickname`, which you'll still see in a lot of existing code.

## The unwrapped value lives inside the braces

A constant created by `if let` exists only inside its block:

```swift
if let number = Int("7") {
    print(number + 1)   // fine
}
print(number)           // error: cannot find 'number' in scope
```

That keeps things safe: you can only use `number` in the place where it's guaranteed to exist. When you need the value for the rest of a function, `guard let`, below, is the better tool.

## Several values and conditions at once

You can unwrap several optionals in one `if`, separated by commas. The block runs only if **every** one of them has a value. You can mix in ordinary `Bool` conditions too:

```swift run
let widthText = "12"
let heightText = "5"

if let width = Int(widthText), let height = Int(heightText), width > 0, height > 0 {
    print("Area: \(width * height)")
} else {
    print("Please enter two positive numbers")
}
```

```output
Area: 60
```

The parts are checked from left to right, and checking stops at the first one that fails. Later parts can use names bound by earlier ones: `width > 0` uses the `width` that was just unwrapped.

If you need to change the unwrapped value, use `if var` instead. You get a variable copy to modify; the original optional is untouched.

## guard let: unwrap or leave

`guard let` is `guard` from M03 combined with optional binding. It checks that an optional has a value, and if not, its `else` block must leave. The difference from `if let` is where the unwrapped value lives: **after** the guard, for the rest of the scope.

```swift run
func ticketMessage(seatText: String) -> String {
    guard let seat = Int(seatText) else {
        return "\"\(seatText)\" isn't a seat number"
    }
    guard seat >= 1 && seat <= 200 else {
        return "Seat \(seat) doesn't exist"
    }
    return "You're in seat \(seat), row \((seat - 1) / 20 + 1)"
}

print(ticketMessage(seatText: "57"))
print(ticketMessage(seatText: "A3"))
print(ticketMessage(seatText: "450"))
```

```output
You're in seat 57, row 3
"A3" isn't a seat number
Seat 450 doesn't exist
```

After the first guard, `seat` is a plain `Int` for the whole rest of the function. Each problem is handled at the top, and the main work sits unindented at the bottom: the early-exit style from [guard and early exit](/dsa/learn/swift-guard).

`guard let` has the same shorthand (`guard let seat else { … }`) and accepts several bindings and conditions separated by commas, just like `if let`.

### Which one?

| Use `if let` when… | Use `guard let` when… |
| --- | --- |
| you only need the value briefly | the rest of the function needs the value |
| both cases do useful work | the missing case means "stop here" |
| the code is short | there are several things to check first |

A good rule of thumb: if the `else` branch just gives up, use `guard let`.

## guard let in loops

Inside a loop, a `guard let` can `continue` past items that don't have a value:

```swift run
let entries = ["12", "seven", "30", "", "8"]
var total = 0
var skipped = 0

for entry in entries {
    guard let value = Int(entry) else {
        skipped += 1
        continue
    }
    total += value
}
print("Total: \(total), skipped: \(skipped)")
```

```output
Total: 50, skipped: 2
```

`"seven"` and the empty string aren't numbers, so they're skipped and the rest are added: 12 + 30 + 8 = 50.

## while let: keep going while there's a value

There's one more form: `while let` repeats as long as an optional keeps producing a value. It's perfect with `popLast()`, which removes and returns the last element of an array, or `nil` once the array is empty:

```swift run
var stack = [3, 8, 5]

while let top = stack.popLast() {
    print("Took \(top)")
}
print("Empty: \(stack.isEmpty)")
```

```output
Took 5
Took 8
Took 3
Empty: true
```

Taking items off the end of an array like this is exactly how a **stack** works, a structure you'll use constantly from Part III onwards. `stack` must be a `var`, because `popLast()` changes it.

<Callout kind="gotcha" title="Swift gotcha: if let x = x is not a typo">
Lines like `if let name = name` look strange at first: the same name twice. The new `name` is an unwrapped constant that **shadows** (hides) the optional inside the braces. It's deliberate, and so common that Swift added the `if let name` shorthand to save typing it.
</Callout>

The average problem below returns an optional, and the empty case is the one to guard against.

- id: if-let-shorthand
  front: "What does the shorthand `if let score { … }` mean?"
  back: "The same as `if let score = score`: inside the braces, `score` is the unwrapped value."
- id: guard-let-scope
  front: "Where can you use a value unwrapped by `guard let`?"
  back: "Everywhere after the guard, for the rest of the scope. An `if let` value only exists inside its braces."

  front: "What does `while let top = stack.popLast()` do?"
  back: "Removes and handles the last element on every pass, and stops when `popLast()` returns nil because the array is empty."
