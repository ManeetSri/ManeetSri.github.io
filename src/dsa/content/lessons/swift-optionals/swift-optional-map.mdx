## Why it matters

A common job is "if there's a value, transform it; if not, stay nil". You can do it with `if let`, but it takes several lines and a temporary variable. Optionals have two methods, `map` and `flatMap`, that do it in one expression. They're also your first taste of passing a small piece of code to a function, an idea at the heart of M06 and of modern Swift.

## The long way round

Say a user may or may not have entered a price in pence, and you want it in pounds:

```swift run
let pence: Int? = 1250

var pounds: Double? = nil
if let pence {
    pounds = Double(pence) / 100
}
print(pounds)
```

```output
Optional(12.5)
```

It works, but it's four lines and a `var` for something simple: "apply this calculation to the value, if there is one".

## map: transform the value inside the box

`map` does exactly that. You give it the transformation, and it applies it to the value inside, if there is one:

```swift run
let pence: Int? = 1250
let noPence: Int? = nil

let pounds = pence.map { Double($0) / 100 }
let noPounds = noPence.map { Double($0) / 100 }

print(pounds)
print(noPounds)
```

```output
Optional(12.5)
nil
```

The part in braces, `{ Double($0) / 100 }`, is a **closure**: a small, unnamed piece of code you hand to `map`. Inside it, `$0` stands for the value taken out of the box. You'll learn closures properly in M06; for now, read `{ Double($0) / 100 }` as "take the value, convert it to a `Double` and divide by 100".

`map` follows a simple rule:

- If the optional holds a value, `map` runs the closure on it and puts the result **back in a box**.
- If the optional is nil, `map` doesn't run the closure at all, and the result is nil.

So the result is always optional. The value inside can change type, here from `Int` to `Double`, but the box stays.

<Callout kind="analogy" title="Working through the glass">
Picture a parcel in a glass box with gloves built into the side. `map` lets you work on the parcel without taking it out. If the box is empty, your hands find nothing, and you're left with an empty box.
</Callout>

You can also name the value instead of using `$0`, which helps when the closure is longer:

```swift run
let rawName: String? = "ada lovelace"
let title = rawName.map { name in name.uppercased() + "!" }
print(title ?? "No name")
```

```output
ADA LOVELACE!
```

`name in` names the value. Then the result is finished with `??`, just like an optional chain.

## When the transformation can fail too

`map` has a problem when the closure itself returns an optional. Suppose the user's input is a `String?`, and you want to turn it into a number. `Int($0)` returns an `Int?`, so `map` wraps that in *another* box:

```swift run
let input: String? = "42"

let doubleBox = input.map { Int($0) }
print(doubleBox)
```

```output
Optional(Optional(42))
```

An optional inside an optional, `Int??`, is awkward to work with: you'd have to unwrap it twice.

## flatMap: transform and flatten

`flatMap` is for exactly this case. Use it when the closure returns an optional, and it gives back a single box:

```swift run
let goodInput: String? = "42"
let badInput: String? = "forty-two"
let noInput: String? = nil

print(goodInput.flatMap { Int($0) })
print(badInput.flatMap { Int($0) })
print(noInput.flatMap { Int($0) })
```

```output
Optional(42)
nil
nil
```

There are now two ways to end up with nil, no input at all, or input that isn't a number, and `flatMap` folds both into one plain `nil`. The result is a simple `Int?`.

The rule of thumb:

| The closure returns… | Use | Result |
| --- | --- | --- |
| a plain value, like `Double` | `map` | `Double?` |
| an optional, like `Int?` | `flatMap` | `Int?` (not `Int??`) |

## Chaining steps together

Because both return optionals, you can chain them. Each step runs only if the previous one produced a value:

```swift run
let ageText: String? = "17"

let message = ageText
    .flatMap { Int($0) }
    .map { $0 + 1 }
    .map { "Next year you'll be \($0)" }

print(message ?? "No valid age")
```

```output
Next year you'll be 18
```

Read it top to bottom: turn the text into a number (which might fail), add one, build a sentence. If any step finds nil, the rest are skipped and `??` supplies the fallback. Writing each step on its own line, starting with a dot, keeps a chain like this readable.

## How map relates to what you already know

Optional chaining is really a shorthand for a common kind of `map`. These two lines give the same `Int?`:

```swift run
let word: String? = "optional"

print(word?.count == word.map { $0.count })
print(word.map { $0.count } ?? 0)
```

```output
true
8
```

Use `?.` when you're reaching for a property or method; it's shorter. Use `map` when the transformation is anything else: arithmetic, a conversion, or passing the value to a function.

And `map` versus `if let` is a matter of taste. If you're transforming a value and keeping it optional, `map` is concise. If you need to do several things with the value, or the logic has branches, `if let` or `guard let` will read better. Clarity wins.

<Callout kind="gotcha" title="Swift gotcha: map on an optional array">
Arrays have a `map` method too (you'll meet it in M06), and it does something different: it transforms *every* element. On an `[Int]?`, `numbers.map { … }` calls the **optional's** `map`, so `$0` is the whole array. If you meant to transform each element, use `numbers?.map { … }` instead, so the chain reaches the array's own `map`.
</Callout>
