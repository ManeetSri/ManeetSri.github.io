## Why it matters

You've learned what optionals are and every way to unwrap them. This lesson is about where they actually come from in everyday code: converting text to numbers, looking things up in dictionaries, and asking arrays for their first, last, smallest or largest element, or the position of a value. These operations appear in nearly every DSA problem, so knowing which ones return optionals, and which ones crash instead, will save you from a lot of bugs.

## Converting text to numbers

`Int(someText)` returns an `Int?`, because not all text is a number. It's strict about what it accepts:

```swift run
let samples = ["42", "-7", "+15", "007", "4.2", " 42", "", "12abc", "99999999999999999999"]

for text in samples {
    if let number = Int(text) {
        print("\"\(text)\" → \(number)")
    } else {
        print("\"\(text)\" → nil")
    }
}
```

```output
"42" → 42
"-7" → -7
"+15" → 15
"007" → 7
"4.2" → nil
" 42" → nil
"" → nil
"12abc" → nil
"99999999999999999999" → nil
```

Notice what fails:

- **decimals**, like `"4.2"`: that's not a whole number;
- **spaces**, even a single leading one: you'd have to trim them first (M08 shows how);
- **empty text** and anything with extra characters;
- numbers **too big** for an `Int`: the last one is beyond `Int.max`, so you get nil rather than an overflow crash.

`Double(someText)` works the same way for decimals, and also returns an optional:

```swift run
print(Double("3.75") ?? 0)
print(Double("2") ?? 0)
print(Double("three") ?? 0)
```

```output
3.75
2.0
0.0
```

## Looking things up in a dictionary

Reading a dictionary with a key always gives an optional, because the key might not be there:

```swift run
let capitals = ["France": "Paris", "Japan": "Tokyo", "Kenya": "Nairobi"]

for country in ["Japan", "Peru"] {
    if let capital = capitals[country] {
        print("The capital of \(country) is \(capital)")
    } else {
        print("I don't know the capital of \(country)")
    }
}
```

```output
The capital of Japan is Tokyo
I don't know the capital of Peru
```

A missing key isn't an error, it's just nil. That's why dictionaries pair so well with `if let`, `guard let` and `??`.

<Callout kind="gotcha" title="Swift gotcha: arrays crash, dictionaries don't">
`capitals["Peru"]` safely gives nil. But an array's subscript is **not** optional: `numbers[10]` on a three-element array crashes with `Fatal error: Index out of range`. Before reading an index that might be invalid, check it, for example with `if index >= 0 && index < numbers.count` or `numbers.indices.contains(index)`.
</Callout>

## first, last, min and max

Arrays have several properties and methods that would have nothing to return for an empty array. All of them return optionals:

```swift run
let laps = [62, 58, 65, 57, 60]
let noLaps: [Int] = []

print(laps.first ?? -1, laps.last ?? -1)
print(laps.min() ?? -1, laps.max() ?? -1)
print(noLaps.first ?? -1, noLaps.max() ?? -1)
```

```output
62 60
57 65
-1 -1
```

- `first` and `last` are the first and last elements.
- `min()` and `max()` are the smallest and largest. (They're methods, so they have parentheses; `first` and `last` are properties, so they don't.)

These return optionals for the same reason the `largest(in:)` function in [the problem-solving framework](/dsa/learn/start-problem-solving) did: an empty array has no largest element, and Swift won't pretend it does.

Here's a typical combination: the gap between the fastest and slowest lap, with both lookups unwrapped at once:

```swift run
func spread(of times: [Int]) -> Int? {
    guard let fastest = times.min(), let slowest = times.max() else {
        return nil
    }
    return slowest - fastest
}

print(spread(of: [62, 58, 65, 57, 60]) ?? 0)
print(spread(of: []) == nil)
```

```output
8
true
```

## Finding a position: firstIndex(of:)

`firstIndex(of:)` searches an array for a value and gives back the index of the first match, or nil if the value isn't there. `lastIndex(of:)` searches from the other end:

```swift run
let queue = ["Ana", "Ben", "Cleo", "Ben"]

print(queue.firstIndex(of: "Ben") ?? -1)
print(queue.lastIndex(of: "Ben") ?? -1)
print(queue.firstIndex(of: "Zoe") ?? -1)

if let position = queue.firstIndex(of: "Cleo") {
    print("Cleo is number \(position + 1) in the queue")
}
```

```output
1
3
-1
Cleo is number 3 in the queue
```

This is exactly the "return the index, or nothing if not found" result that the sentinel `-1` tried to express in [why nil exists](/dsa/learn/swift-why-nil), with the type now saying so honestly. Under the hood, `firstIndex(of:)` is a linear search: it checks each element in turn, so it takes longer the longer the array.

## Removing safely: popLast() and removeLast()

Two methods remove the last element of an array, and they treat an empty array very differently:

- `popLast()` returns an optional: the removed element, or nil if the array was empty.
- `removeLast()` returns a plain element, and **crashes** on an empty array.

```swift run
var tasks = ["write", "test"]

print(tasks.popLast() ?? "nothing")
print(tasks.popLast() ?? "nothing")
print(tasks.popLast() ?? "nothing")
```

```output
test
write
nothing
```

If `removeLast()` were called on the now-empty array, this is what Swift would report:

```text title="What you'll see"
Fatal error: Can't remove last element from an empty collection
```

Use `removeLast()` only when you know the array isn't empty, and `popLast()` whenever it might be. The same pattern runs through Swift's standard library: when an operation can't always succeed, it either returns an optional or documents that it crashes.

## Putting it together

Here's a small program that uses several of these at once. It reads a list of scores typed as text, skips anything that isn't a whole number, and reports on the rest:

```swift run
let typed = ["78", "91", "abc", "65", "", "91"]
var scores: [Int] = []

for text in typed {
    if let score = Int(text) {
        scores.append(score)
    }
}

print("Valid scores: \(scores)")
if let best = scores.max(), let firstBest = scores.firstIndex(of: best) {
    print("Best: \(best), first scored by entry \(firstBest + 1)")
} else {
    print("No valid scores")
}
```

```output
Valid scores: [78, 91, 65, 91]
Best: 91, first scored by entry 2
```

`scores.append(score)` adds an element to the end of the array; M07 covers it. Notice that the second `let` in the `if` uses `best`, which the first one just unwrapped. Each optional gets handled exactly once, at the point where it appears, and nothing can crash.
