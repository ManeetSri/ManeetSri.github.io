## Why it matters

Almost every tree algorithm is a **traversal**, a walk that visits every node once, with a little work done at each node. The interesting decision is *when* that work happens: before a node's children are visited, between them, or after them. The three choices are called **preorder**, **inorder** and **postorder**. Pick the right one and the problem often solves itself: copying a tree, listing a binary search tree in sorted order, totting up folder sizes, evaluating a calculator expression.

## Three moments to do the work

A **depth-first** walk goes as deep as it can down one branch before backing up and trying the next. Recursion does this naturally: handle the empty tree, then recurse into the left subtree, then into the right. Between those steps, there are exactly three places where you can visit the node itself:

```swift
func walk(_ node: TreeNode?) {
    guard let node else { return }
    // 1. preorder: visit here, before either subtree
    walk(node.left)
    // 2. inorder: visit here, between the subtrees
    walk(node.right)
    // 3. postorder: visit here, after both subtrees
}
```

- **Preorder:** node, left subtree, right subtree.
- **Inorder:** left subtree, node, right subtree.
- **Postorder:** left subtree, right subtree, node.

The names say where the node goes: *pre* (before), *in* (in the middle), *post* (after). The left subtree always comes before the right.

## The three orders on the running example

```text
        1
       / \
      2   3
     / \   \
    4   5   6
       /
      7
```

| Order | Visits |
| --- | --- |
| Preorder | 1, 2, 4, 5, 7, 3, 6 |
| Inorder | 4, 2, 7, 5, 1, 3, 6 |
| Postorder | 4, 7, 5, 2, 6, 3, 1 |

Preorder starts with the root. Postorder ends with it. Inorder puts the root exactly between its left subtree (4, 2, 7, 5) and its right subtree (3, 6). Every subtree follows the same rule: in the inorder list, 2 sits between 4 and its right subtree, 7 and 5.

Step through the preorder walk and watch the call reach each node. Then try working out postorder before you look at the table:

```visual binaryTree
program: traversal
input:
  tree: [1, 2, 3, 4, 5, null, 6, null, null, 7]
  order: preorder
```

<Callout kind="tip" title="Working them out by hand">
Trace a line around the outside of the tree, starting to the left of the root and going anticlockwise, down the left side first, hugging every node and dipping into every gap. You pass each node three times: on its left, underneath it, and on its right. Write a node down when you pass its **left** side for preorder, **underneath** for inorder, and its **right** side for postorder.
</Callout>

## The code

Each traversal takes a `visit` closure and calls it with each value at its moment. The closure is the "work" slot, so one traversal serves many jobs: collect values, print, count, search. Here it collects them into arrays:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func preorder(_ node: TreeNode?, _ visit: (Int) -> Void) {
    guard let node else { return }
    visit(node.value)
    preorder(node.left, visit)
    preorder(node.right, visit)
}

func inorder(_ node: TreeNode?, _ visit: (Int) -> Void) {
    guard let node else { return }
    inorder(node.left, visit)
    visit(node.value)
    inorder(node.right, visit)
}

func postorder(_ node: TreeNode?, _ visit: (Int) -> Void) {
    guard let node else { return }
    postorder(node.left, visit)
    postorder(node.right, visit)
    visit(node.value)
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))

var pre: [Int] = []
var ino: [Int] = []
var post: [Int] = []
preorder(root) { pre.append($0) }
inorder(root) { ino.append($0) }
postorder(root) { post.append($0) }
print("preorder: ", pre)
print("inorder:  ", ino)
print("postorder:", post)

var total = 0
inorder(root) { total += $0 }
print("sum:", total)
```

```output
preorder:  [1, 2, 4, 5, 7, 3, 6]
inorder:   [4, 2, 7, 5, 1, 3, 6]
postorder: [4, 7, 5, 2, 6, 3, 1]
sum: 28
```

What to notice:

- The three functions are identical except for the position of `visit(node.value)`.
- `visit` is a **non-escaping** closure: it's only called while the traversal runs, so it can capture and change local variables like `pre` and `total` without any ceremony. ([Escaping and non-escaping closures](/dsa/learn/swift-escaping) explains the difference.)
- Every node is visited exactly once, and every `nil` child costs one quick call that returns straight away. For n nodes there are n + 1 `nil` children, so the work is O(n).

## What each order is good for

**Preorder: the node before its descendants.** Use it when a node must be handled before anything below it.

- *Copying or saving a tree.* Writing the root first means that, when you read the values back, each node exists before its children need attaching to it. Serialising a tree (M36) usually uses preorder.
- *Outlines.* A table of contents, a folder listing or a nested menu prints a heading before its contents.
- *Passing information down.* Depth, the path from the root, or a running total are known at a node before its children need them.

**Inorder: the node between its subtrees.** Its big use is **binary search trees** (M37), where everything in a node's left subtree is smaller and everything in its right subtree is bigger. Inorder then visits the values in **sorted order**. DSAKit's `TreeNode.inorder` exists mainly to check BSTs in tests.

**Postorder: the node after its descendants.** Use it when a node's answer depends on its children's answers.

- *Sizes and heights*, as in [Tree terminology](/dsa/learn/tree-terminology), and folder totals in [Trees in real code](/dsa/learn/tree-real-world).
- *Deleting a tree* by hand: free the children before the parent that refers to them.
- *Evaluating an expression*: both operands must be worked out before the operator can be applied.

## Expression trees: three orders, three notations

An arithmetic expression is a tree with operators inside and numbers at the leaves, as you saw in [Indirect enums for recursive data](/dsa/learn/swift-indirect-enums). Here's `3 * (4 + 5)`:

```text
      *
     / \
    3   +
       / \
      4   5
```

Its three traversals are three famous ways of writing expressions. Preorder gives **prefix** notation, with each operator before its operands. Inorder gives the usual **infix** notation, but without brackets. Postorder gives **postfix**, or reverse Polish notation: exactly the form [Infix to postfix and evaluating postfix](/dsa/learn/stack-expressions) evaluated with a stack.

```swift run
final class ExprNode {
    let label: String
    var left: ExprNode?
    var right: ExprNode?

    init(_ label: String, _ left: ExprNode? = nil, _ right: ExprNode? = nil) {
        self.label = label
        self.left = left
        self.right = right
    }
}

func preorder(_ node: ExprNode?) -> [String] {
    guard let node else { return [] }
    return [node.label] + preorder(node.left) + preorder(node.right)
}

func inorder(_ node: ExprNode?) -> [String] {
    guard let node else { return [] }
    return inorder(node.left) + [node.label] + inorder(node.right)
}

func postorder(_ node: ExprNode?) -> [String] {
    guard let node else { return [] }
    return postorder(node.left) + postorder(node.right) + [node.label]
}

// Postorder evaluation: both operands are known before their operator
func evaluate(_ node: ExprNode) -> Int {
    guard let left = node.left, let right = node.right else {
        return Int(node.label)!                       // a leaf holds a number
    }
    let a = evaluate(left)
    let b = evaluate(right)
    return node.label == "+" ? a + b : a * b
}

let expression = ExprNode("*", ExprNode("3"), ExprNode("+", ExprNode("4"), ExprNode("5")))
print("prefix: ", preorder(expression).joined(separator: " "))
print("infix:  ", inorder(expression).joined(separator: " "))
print("postfix:", postorder(expression).joined(separator: " "))
print("value:  ", evaluate(expression))
```

```output
prefix:  * 3 + 4 5
infix:   3 * 4 + 5
postfix: 3 4 5 + *
value:   27
```

The infix line reads as `3 * 4 + 5`, which is 17, not 27: inorder alone loses the brackets that the tree's shape kept. Prefix and postfix need no brackets at all, because the order of the operators says everything. This version builds its result by joining arrays, which is fine for a small tree. It copies values at every level, though, so for big trees prefer the `visit` closure or an `inout` array.

## Information down, answers up

Recursive traversals move information in two directions, as depth and height did in [Tree terminology](/dsa/learn/tree-terminology):

- **Down, as parameters.** A call passes something to its children: the depth, the path so far, the largest value seen on the way down. That's preorder thinking: the node uses what it was given before its children run.
- **Up, as return values.** A call returns something to its parent: a size, a height, "is this subtree balanced?". That's postorder thinking: the node combines its children's answers after they return.

Most of the problems in M36 are one or the other, and the hardest combine both: a value passed down and a different value returned up, in the same function.

## The cost: time and stack

Each traversal visits every node once: **O(n) time**. The space is the recursion's call stack, one frame for each node on the current path from the root, so **O(h)** for a tree of height h. For a balanced tree that's O(log n), only about 17 frames for 100,000 nodes. For a degenerate chain it's O(n): 100,000 nodes means 100,000 frames.

That's a problem. As [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) measured, a recursion runs out of stack after only thousands of calls inside a Swift Testing test, and around a hundred thousand on the main thread. A recursive traversal of a 100,000-level chain crashes. The next lesson rewrites all three traversals with an explicit stack, which can go as deep as memory allows.

<Callout kind="gotcha" title="Common mistakes">
- **Forgetting the base case.** Without `guard let node else { return }`, the function can't even unwrap its argument. Handle `nil` first, every time.
- **Visiting both children before an "inorder" visit.** Inorder means left, node, right. Moving `visit` after both calls quietly turns it into postorder.
- **Building arrays with `+` in a big tree.** `pre(left) + [value] + pre(right)` copies every value once per level above it: O(n log n) for a balanced tree and O(n²) for a chain. Append to one array instead.
</Callout>
