## Why it matters

Recursive traversals are short and clear, but they borrow the call stack, and the call stack is small. A lopsided tree 100,000 levels deep crashes them. The fix is the one from [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack): keep the unfinished work in an array you manage yourself. It's also a classic interview follow-up ("now do it without recursion"), and the basis of anything that needs to **pause** a traversal and resume it later, such as the BST iterator in [Floor, ceiling and a BST iterator](/dsa/learn/bst-floor-ceil-iterator). Preorder is easy, inorder takes one good idea, and postorder takes care.

## Preorder: pop, visit, push the children

Recursive preorder visits a node, then its left subtree, then its right subtree. With a stack:

1. Push the root.
2. Pop a node and visit it.
3. Push its **right** child, then its **left** child, so the left comes off first.
4. Repeat until the stack is empty.

A stack is last in, first out, so pushing right before left means the left subtree is finished completely before the right child, which has been waiting underneath, comes off. This version prints the stack after each visit:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func preorder(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack = [root].compactMap { $0 }
    while let node = stack.popLast() {
        result.append(node.value)
        if let right = node.right { stack.append(right) }      // pushed first, comes off later
        if let left = node.left { stack.append(left) }
        print("visit \(node.value), stack \(stack.map(\.value))")
    }
    return result
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
print(preorder(root))
```

```output
visit 1, stack [3, 2]
visit 2, stack [3, 5, 4]
visit 4, stack [3, 5]
visit 5, stack [3, 7]
visit 7, stack [3]
visit 3, stack [6]
visit 6, stack []
[1, 2, 4, 5, 7, 3, 6]
```

The stack's top is on the right of each printout. Notice 3 waiting at the bottom through the entire left subtree: it's the "come back to the right child later" that the recursive version kept in its call frames.

## Inorder: slide left, pop, step right

Inorder can't visit a node when it first meets it: the whole left subtree has to come first. So the node waits on the stack. The pattern:

1. **Slide left.** From `current`, push each node and move to its left child, until you fall off the bottom.
2. **Pop and visit.** The top of the stack has no unvisited left subtree left, so visit it.
3. **Step right.** Set `current` to that node's right child, and go back to step 1 for that subtree.

Keep going while there's a `current` subtree to start, or anything waiting on the stack. Step through it:

```visual binaryTree
program: iterativeInorder
input:
  tree: [1, 2, 3, 4, 5, null, 6, null, null, 7]
```

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func inorder(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack: [TreeNode] = []
    var current = root
    while current != nil || !stack.isEmpty {
        while let node = current {          // 1. slide down the left edge
            stack.append(node)
            current = node.left
        }
        let node = stack.removeLast()       // 2. its left subtree is done
        result.append(node.value)
        print("visit \(node.value), waiting \(stack.map(\.value))")
        current = node.right                // 3. now its right subtree
    }
    return result
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
print(inorder(root))
```

```output
visit 4, waiting [1, 2]
visit 2, waiting [1]
visit 7, waiting [1, 5]
visit 5, waiting [1]
visit 1, waiting []
visit 3, waiting []
visit 6, waiting []
[4, 2, 7, 5, 1, 3, 6]
```

What to notice:

- **The invariant.** Every node on the stack is waiting for its left subtree to finish, and is visited the moment that happens. `current` is the root of a subtree that hasn't been started at all.
- After visiting 2, `current` becomes 5. The slide pushes 5 and 7, and 7 is visited next, then 5. The right subtree gets the full treatment.
- **The loop condition needs both halves.** After visiting 1, the stack is empty but `current` is 3, with a whole right subtree to go. Testing only `!stack.isEmpty` would stop too early.

This is exactly DSAKit's `TreeNode.inorder`. Each node is pushed once and popped once, so it's O(n) time, and the stack never holds more than one node per level: O(h) space.

## Postorder: three ways

Postorder is the awkward one. A node must wait until **both** subtrees are done, and when you look at a node on top of the stack, you can't immediately tell whether you've just come up from its left subtree (so the right still needs doing) or from its right (so it's time to visit). Here are three ways around that.

**1. Reverse a mirrored preorder.** Preorder with the children pushed the other way round visits node, right, left. Read that backwards and you get left, right, node: postorder. It's the "two stacks" method, where the second stack is simply the result reversed. Short and hard to get wrong.

**2. One stack and a `lastVisited` pointer.** Slide left as in inorder, then *peek* at the top instead of popping. If it has a right child that isn't the node you visited last, its right subtree hasn't been done: go and do it. Otherwise, visit the node and pop it. This works because in postorder a node's right child is always the very last node visited before the node itself.

**3. A ready flag.** Push each node twice: first to expand it, and then marked "ready", so that the next time it comes off the stack it's visited. When you expand a node, push its ready entry *underneath* its children, so it only comes off after both of them are finished. That's the reminder trick from [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack).

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

// 1. Node, right, left, then reversed: left, right, node
func postorderReversed(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack = [root].compactMap { $0 }
    while let node = stack.popLast() {
        result.append(node.value)
        if let left = node.left { stack.append(left) }
        if let right = node.right { stack.append(right) }
    }
    return result.reversed()
}

// 2. Peek: go right if the right subtree isn't done yet, otherwise visit
func postorderLastVisited(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack: [TreeNode] = []
    var current = root
    var lastVisited: TreeNode? = nil
    while current != nil || !stack.isEmpty {
        while let node = current {
            stack.append(node)
            current = node.left
        }
        let top = stack[stack.count - 1]
        if let right = top.right, right !== lastVisited {
            current = right                       // its right subtree hasn't been done
        } else {
            result.append(top.value)              // both subtrees done
            lastVisited = top
            stack.removeLast()
        }
    }
    return result
}

// 3. Each node goes on twice: once to expand it, once (ready) to visit it
func postorderReady(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack: [(node: TreeNode, ready: Bool)] = root.map { [($0, false)] } ?? []
    while let (node, ready) = stack.popLast() {
        if ready {
            result.append(node.value)
            continue
        }
        stack.append((node, true))                // comes off after both children
        if let right = node.right { stack.append((right, false)) }
        if let left = node.left { stack.append((left, false)) }
    }
    return result
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
print(postorderReversed(root))
print(postorderLastVisited(root))
print(postorderReady(root))
```

```output
[4, 7, 5, 2, 6, 3, 1]
[4, 7, 5, 2, 6, 3, 1]
[4, 7, 5, 2, 6, 3, 1]
```

| Method | Extra space | Visits in order as it goes? | Notes |
| --- | --- | --- | --- |
| Reversed preorder | O(n): everything waits for the reverse | no | the easiest to get right |
| `lastVisited` | O(h) | yes | compare with `===`, not values |
| Ready flag | O(h) | yes | one loop for any order |

The ready flag generalises neatly. Where the ready entry goes among the pushes decides the order. Push it last (on top of both children) for preorder, between the right and left children for inorder, and first (underneath both) for postorder.

## Test them against the recursive versions

Iterative traversals are easy to get almost right: correct on the example you drew, wrong on a shape you didn't think of. The cure is to compare them with the recursive versions on **every** small tree shape. There are only 197 binary tree shapes with up to 6 nodes, so you can check them all:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

// Every shape of binary tree holding first...last, numbered in inorder
func allTrees(_ first: Int, _ last: Int) -> [TreeNode?] {
    if first > last { return [nil] }
    var trees: [TreeNode?] = []
    for rootValue in first...last {
        for left in allTrees(first, rootValue - 1) {
            for right in allTrees(rootValue + 1, last) {
                trees.append(TreeNode(rootValue, left: left, right: right))
            }
        }
    }
    return trees
}

func recursivePostorder(_ node: TreeNode?, into result: inout [Int]) {
    guard let node else { return }
    recursivePostorder(node.left, into: &result)
    recursivePostorder(node.right, into: &result)
    result.append(node.value)
}

func iterativePostorder(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack: [TreeNode] = []
    var current = root
    var lastVisited: TreeNode? = nil
    while current != nil || !stack.isEmpty {
        while let node = current {
            stack.append(node)
            current = node.left
        }
        let top = stack[stack.count - 1]
        if let right = top.right, right !== lastVisited {
            current = right
        } else {
            result.append(top.value)
            lastVisited = top
            stack.removeLast()
        }
    }
    return result
}

var checked = 0
var mismatches = 0
for size in 0...6 {
    for tree in allTrees(1, size) {
        var expected: [Int] = []
        recursivePostorder(tree, into: &expected)
        if iterativePostorder(tree) != expected { mismatches += 1 }
        checked += 1
    }
}
print("checked \(checked) trees, \(mismatches) mismatches")
```

```output
checked 197 trees, 0 mismatches
```

Shapes with up to 6 nodes include every awkward case: a missing left child, a missing right child, a zigzag, a node whose right child is a leaf. The same harness checks preorder and inorder too. The practice problem's tests do something similar with a different method as the reference.

## Deep trees, no problem

The stack is now an array, which lives on the heap and can grow as large as memory allows. A chain 100,000 nodes deep, which would crash the recursive version, is no trouble:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func inorder(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack: [TreeNode] = []
    var current = root
    while current != nil || !stack.isEmpty {
        while let node = current {
            stack.append(node)
            current = node.left
        }
        let node = stack.removeLast()
        result.append(node.value)
        current = node.right
    }
    return result
}

// A chain 100,000 nodes deep: every node is the left child of the one before
let root = TreeNode(1)
var bottom = root
for value in 2...100_000 {
    let next = TreeNode(value)
    bottom.left = next
    bottom = next
}
let values = inorder(root)
print(values.count, "values, first \(values.first!), last \(values.last!)")
```

```output
100000 values, first 100000, last 1
```

The space is still O(h): at one point all 100,000 nodes sit on the stack together. But 100,000 references in an array take under a megabyte, while 100,000 call frames would overflow a thread's stack many times over.

| | Recursive | Explicit stack |
| --- | --- | --- |
| Code | 4 lines, mirrors the definition | 10 to 20 lines, easier to get wrong |
| Space | O(h) call-stack frames | O(h) array entries on the heap |
| A 100,000-level chain | crashes | fine |
| Pause and resume | no | yes: keep the stack between calls |

<Callout kind="gotcha" title="Common mistakes">
- **Pushing left before right in preorder.** The stack hands back the last thing pushed, so the right subtree would come out first.
- **`while !stack.isEmpty` alone in inorder.** The stack can be empty while `current` still has a whole right subtree to do. The condition is `current != nil || !stack.isEmpty`.
- **Comparing nodes by value in postorder.** `right.value != lastVisited?.value` breaks as soon as two nodes share a value. Compare identities with `!==`.
- **Popping instead of peeking in the `lastVisited` method.** The node mustn't leave the stack until its right subtree is finished.
</Callout>
