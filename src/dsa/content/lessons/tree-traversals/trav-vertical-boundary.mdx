## Why it matters

These two are the fiddliest traversal questions that interviews ask, and they're fiddly for the same reason: the hard part isn't the walking, it's **defining exactly what the answer is**. Vertical order needs a rule for nodes that land in the same spot. Boundary traversal needs care so the corners aren't counted twice. Both reward the habit this lesson is really about: write the definition down precisely, including the ties and the edge cases, and then the code follows.

## Vertical order

Use the columns from the last lesson: the root is in column 0, a left child is one column left of its parent, and a right child one column right. Also give each node a **row**, its depth. **Vertical order** lists the columns from left to right, and each column from top to bottom:

```text
column:  -2  -1   0   1   2
                  1              row 0
                /   \
               2     3           row 1
              / \     \
             4   5     6         row 2
                /
               7                 row 3
```

For the running example that's `[[4], [2, 7], [1, 5], [3], [6]]`. Column −1 is 2 (row 1) then 7 (row 3); column 0 is 1 (row 0) then 5 (row 2).

## The tie rule

Two nodes can share a column **and** a row, like the right child of the root's left child and the left child of the root's right child. Which comes first? There are two common answers, and problems differ:

1. **Level-order ties.** Nodes in the same row and column appear in the order a level-order walk meets them: left to right.
2. **Sorted ties.** Nodes in the same row and column appear in increasing order of value.

This course's problem uses the second rule. It has one big advantage: the answer depends only on each node's position and value, so you can collect the nodes in **any** traversal order and sort them afterwards. Record a `(column, row, value)` triple for every node, then sort the triples. Swift compares tuples element by element, so sorting by `(column, row, value)` puts columns left to right, then rows top to bottom, then tied values in increasing order: exactly the definition.

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

// Every node's (column, row, value), met in level order
func cells(_ root: TreeNode?) -> [(column: Int, row: Int, value: Int)] {
    guard let root else { return [] }
    var result: [(column: Int, row: Int, value: Int)] = []
    var queue: [(node: TreeNode, column: Int, row: Int)] = [(root, 0, 0)]
    var head = 0
    while head < queue.count {
        let (node, column, row) = queue[head]
        head += 1
        result.append((column, row, node.value))
        if let left = node.left { queue.append((left, column - 1, row + 1)) }
        if let right = node.right { queue.append((right, column + 1, row + 1)) }
    }
    return result
}

// Cut a list already in column order into one array per column
func group(_ sorted: [(column: Int, row: Int, value: Int)]) -> [[Int]] {
    var columns: [[Int]] = []
    var current: Int? = nil
    for cell in sorted {
        if cell.column != current {
            columns.append([])
            current = cell.column
        }
        columns[columns.count - 1].append(cell.value)
    }
    return columns
}

func verticalSortedTies(_ root: TreeNode?) -> [[Int]] {
    group(cells(root).sorted { ($0.column, $0.row, $0.value) < ($1.column, $1.row, $1.value) })
}

func verticalLevelOrderTies(_ root: TreeNode?) -> [[Int]] {
    // Sort by column, then by position in level order, which already has rows and ties in order
    var indexed = Array(cells(root).enumerated())
    indexed.sort { ($0.element.column, $0.offset) < ($1.element.column, $1.offset) }
    return group(indexed.map(\.element))
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
print(verticalSortedTies(root))

// 9 (under 3) and 2 (under 5) share column 0 and row 2
let tied = TreeNode(8, left: TreeNode(3, right: TreeNode(9)), right: TreeNode(5, left: TreeNode(2)))
print("sorted ties:     ", verticalSortedTies(tied))
print("level-order ties:", verticalLevelOrderTies(tied))
```

```output
[[4], [2, 7], [1, 5], [3], [6]]
sorted ties:      [[3], [8, 2, 9], [5]]
level-order ties: [[3], [8, 9, 2], [5]]
```

What to notice:

- The two rules only disagree on the tie: 9 and 2, both in column 0 on row 2. Level order meets 9 first (it's under 3, on the left); sorting puts 2 first.
- For level-order ties, the code sorts by column and then by each cell's position in the level-order list. Level order already has rows top to bottom and ties left to right, so only the column order needs fixing.
- Sorting makes both versions **O(n log n)**. Level-order ties can be done in O(n) without sorting: the columns form an unbroken range, so find the smallest and largest column and drop each value into an array of buckets at index `column - smallest`, in level order.

## Boundary traversal

The **boundary** of a tree is its outline, read anticlockwise from the root. For a precise answer, define it as four pieces, in order:

1. **The root.**
2. **The left edge**, top to bottom: start at the root's left child, and from each node move to its left child, or to its right child if there's no left one. Stop **before** a leaf.
3. **The leaves**, left to right.
4. **The right edge**, bottom to top: start at the root's right child, and from each node move to its right child, or to its left child if there's no right one. Stop before a leaf.

Leaves are excluded from both edges, so each corner node is listed exactly once, with the leaves. For the running example:

```text
        1            root: 1
       / \
      2   3          left edge: 2 (its left child, 4, is a leaf)
     / \   \         right edge: 3 (its right child, 6, is a leaf)
    4   5   6
       /             leaves, left to right: 4, 7, 6
      7
```

The boundary is `[1, 2, 4, 7, 6, 3]`: the root, the left edge going down, the leaves along the bottom, the right edge coming back up. 5 isn't on the boundary at all: it's neither on an edge nor a leaf.

## The edge cases are the definition

Check each of these against the four rules before writing code:

| Tree (level order) | Boundary | Why |
| --- | --- | --- |
| `[5]` | `[5]` | the root alone; it's also a leaf, but listed once |
| `[1, nil, 2, 3, 4]` | `[1, 3, 4, 2]` | no left child, so the left edge is empty |
| `[1, 2, 3, nil, 4, nil, nil, 5, 6]` | `[1, 2, 4, 5, 6, 3]` | 2 has no left child, so the left edge turns right to 4 |
| `[1, 2, nil, 3, nil, 4]` | `[1, 2, 3, 4]` | a left chain: the edge is 2 and 3, and 4 is the leaf |

Then the code is three simple walks glued together. The edges are loops, because there's only one way down from each node. The leaves come from any depth-first traversal, which always meets leaves from left to right:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func isLeaf(_ node: TreeNode) -> Bool {
    node.left == nil && node.right == nil
}

func leaves(_ node: TreeNode?, into result: inout [Int]) {
    guard let node else { return }
    if isLeaf(node) { result.append(node.value) }
    leaves(node.left, into: &result)
    leaves(node.right, into: &result)
}

func boundary(_ root: TreeNode?) -> [Int] {
    guard let root else { return [] }
    if isLeaf(root) { return [root.value] }
    var result = [root.value]

    var next = root.left                               // the left edge, going down
    while let node = next, !isLeaf(node) {
        result.append(node.value)
        next = node.left ?? node.right
    }

    leaves(root, into: &result)                        // the bottom, left to right

    var rightEdge: [Int] = []                          // the right edge, collected going down...
    next = root.right
    while let node = next, !isLeaf(node) {
        rightEdge.append(node.value)
        next = node.right ?? node.left
    }
    return result + rightEdge.reversed()               // ...and added coming back up
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
print(boundary(root))
print(boundary(TreeNode(5)))
print(boundary(TreeNode(1, right: TreeNode(2, left: TreeNode(3), right: TreeNode(4)))))
print(boundary(TreeNode(1, left: TreeNode(2, right: TreeNode(4, left: TreeNode(5), right: TreeNode(6))), right: TreeNode(3))))
```

```output
[1, 2, 4, 7, 6, 3]
[5]
[1, 3, 4, 2]
[1, 2, 4, 5, 6, 3]
```

What to notice:

- `while let node = next, !isLeaf(node)` stops the edge **before** a leaf, so the leaf is only added by the leaf walk.
- `node.left ?? node.right` is the whole "go left, or right if there's no left" rule in one expression.
- The leaf walk starts at the root, which is safe because the root isn't a leaf by then. It's recursive, so for very deep trees, use the explicit-stack preorder from [Iterative traversals with a stack](/dsa/learn/trav-dfs-iterative) instead.
- The whole thing is **O(n)**: the edges touch at most one node per level, and the leaf walk visits every node once.

<Callout kind="gotcha" title="Common mistakes">
- **Counting a node twice.** The bottom node of each edge is a leaf; if the edge loop doesn't stop before it, it appears twice. And a root with no children must be listed once, not as both root and leaf.
- **Stopping the left edge when there's no left child.** The edge carries on through a right child. Only a leaf ends it.
- **Forgetting to reverse the right edge.** Anticlockwise means coming back **up** the right side.
- **Picking a tie rule by accident.** Vertical order without a stated tie rule has no single right answer. Decide, write it down, and test a tie.
</Callout>

**Vertical columns** uses the sorted tie rule, with lots of repeated values in its large tests. **The boundary of a tree** uses exactly the four-part definition above, including the edge-turning and root-only cases.
