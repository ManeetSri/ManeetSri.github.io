## Why it matters

Look at enough loops and you'll notice the same three shapes again and again: **transform** every element, **keep** only some elements, or **combine** all the elements into one answer. Swift gives each shape a name: `map`, `filter` and `reduce`. They're higher-order functions, so you hand them a closure that says what to do, and they handle the looping. You'll see them in every Swift codebase, from turning model data into screen text in an iOS app to preparing the input of a DSA problem in one line.

## map: transform every element

`map` calls your closure on each element and collects the results into a **new** array, in the same order. First, the loop you'd write by hand:

```swift run
let prices = [4, 10, 7]

var doubled: [Int] = []
for price in prices {
    doubled.append(price * 2)
}
print(doubled)

let alsoDoubled = prices.map { $0 * 2 }
print(alsoDoubled)
print(prices)
```

```output
[8, 20, 14]
[8, 20, 14]
[4, 10, 7]
```

What to notice:

- The closure receives one element and returns its replacement. `map` does the rest: create an empty array, loop, append.
- The result always has the **same number of elements** as the input.
- The original array is untouched. `map` returns a new array.

The closure can return a **different type** from the one it receives. Turning `Int`s into `String`s is a typical example:

```swift run
let temperatures = [18, 23, 9]
let labels = temperatures.map { "\($0)°C" }
print(labels)

let lengths = ["kiwi", "banana", "fig"].map { $0.count }
print(lengths)

let squares = (1...5).map { $0 * $0 }
print(squares)
```

```output
["18°C", "23°C", "9°C"]
[4, 6, 3]
[1, 4, 9, 16, 25]
```

`[Int]` becomes `[String]`, and `[String]` becomes `[Int]`. `map` also works on a range, which is a quick way to build an array from a formula. You met the same idea in [map and flatMap on optionals](/dsa/learn/swift-optional-map): "apply this closure to what's inside".

## filter: keep some elements

`filter` calls your closure on each element and keeps the elements for which it returns `true`:

```swift run
let scores = [72, 38, 50, 91, 45]

var passes: [Int] = []
for score in scores {
    if score >= 50 {
        passes.append(score)
    }
}
print(passes)

let alsoPasses = scores.filter { $0 >= 50 }
print(alsoPasses)

let evens = (1...10).filter { $0 % 2 == 0 }
print(evens)
```

```output
[72, 50, 91]
[72, 50, 91]
[2, 4, 6, 8, 10]
```

What to notice:

- The closure must return a `Bool`. True means keep, false means drop.
- The kept elements stay in their original order, and they're the same type as before.
- The result can have anywhere from zero elements up to all of them.

To **count** matches, you could write `scores.filter { $0 >= 50 }.count`, but that builds a whole array only to count it. Since Swift 6, arrays have `count(where:)`, which counts without building anything:

```swift run
let scores = [72, 38, 50, 91, 45]
print(scores.filter { $0 >= 50 }.count)
print(scores.count(where: { $0 >= 50 }))
```

```output
3
3
```

## reduce: combine everything into one value

`reduce` walks through the elements, carrying a running result. You give it two things:

1. an **initial value**, the result before any elements have been seen; and
2. a closure that takes the result so far and the next element, and returns the new result.

```swift run
let numbers = [3, 5, 2]

var total = 0
for number in numbers {
    total = total + number
}
print(total)

let alsoTotal = numbers.reduce(0) { runningTotal, number in
    runningTotal + number
}
print(alsoTotal)
```

```output
10
10
```

Trace it by hand to see exactly what `reduce` does:

| Step | Result so far | Next element | New result |
| --- | --- | --- | --- |
| start | `0` (initial value) | | |
| 1 | `0` | `3` | `3` |
| 2 | `3` | `5` | `8` |
| 3 | `8` | `2` | `10` |

The final result, 10, is what `reduce` returns. It's the same loop as before, with `total` renamed `runningTotal`.

### Shorter forms

The closure takes two `Int`s and returns an `Int`, which is exactly the type of the `+` operator. So you can pass the operator itself:

```swift run
let numbers = [3, 5, 2]
print(numbers.reduce(0, +))
print(numbers.reduce(1, *))
print(numbers.reduce(0) { $0 + $1 * $1 })
```

```output
10
30
38
```

- `reduce(0, +)` is the Swift idiom for a sum. Arrays have no built-in `sum()`.
- `reduce(1, *)` is a product. The initial value is 1, because starting from 0 would make everything 0.
- The last one is the sum of squares: 0 + 9 + 25 + 4.

The result doesn't have to be the same type as the elements. Its type comes from the initial value:

```swift run
let words = ["Swift", "is", "fun"]

let totalLetters = words.reduce(0) { $0 + $1.count }
print(totalLetters)

let longest = words.reduce("") { best, word in
    word.count > best.count ? word : best
}
print(longest)
```

```output
10
Swift
```

`totalLetters` starts from `0`, so the result is an `Int`, even though the elements are `String`s. `longest` starts from `""` and keeps whichever word is longer.

## Chaining them together

Each of these returns a value, so you can call the next one straight on the result. Put each step on its own line, and the chain reads like a recipe:

```swift run
let scores = [72, 38, 50, 91, 45]

let bonusTotal = scores
    .filter { $0 >= 50 }      // keep the passes: [72, 50, 91]
    .map { $0 + 5 }           // add a bonus: [77, 55, 96]
    .reduce(0, +)             // add them up
print(bonusTotal)
```

```output
228
```

Read it top to bottom: *take the scores, keep the passes, add 5 to each, total them*. The equivalent loop would mix all three ideas in one body, with an `if` and a running total.

<Callout kind="tip" title="Reading a chain">
When a chain confuses you, split it: give each step its own `let` and print it. That's also the fastest way to find which step is wrong.
</Callout>

## Spotting the shape in a loop

Turning a loop into a chain is a skill you build by asking three questions of the loop body: does it **skip** some elements, does it **change** each element, and does it **combine** them into one result? Here's a loop that adds up the squares of the odd numbers:

```swift run
let numbers = [3, 8, 5, 2, 7]

var total = 0
for number in numbers {
    if number % 2 == 1 {          // skips some elements: filter
        let square = number * number  // changes each one: map
        total += square           // combines them: reduce
    }
}
print(total)

let alsoTotal = numbers
    .filter { $0 % 2 == 1 }
    .map { $0 * $0 }
    .reduce(0, +)
print(alsoTotal)
```

```output
83
83
```

The `if` is a `filter`, the calculation is a `map`, and the running total is a `reduce`, in that order. The squares are 9, 25 and 49, which add up to 83. Once you can see the shapes, you can translate in either direction, which helps when you meet a dense chain in someone else's code and want to understand it as a loop.

### A few recipes

These come up again and again:

| Task | One way to write it |
| --- | --- |
| Sum | `numbers.reduce(0, +)` |
| Average | `Double(numbers.reduce(0, +)) / Double(numbers.count)`, checking for an empty array first |
| Count the matches | `numbers.count(where: { $0 > 0 })` |
| Total of a property | `words.map { $0.count }.reduce(0, +)` |
| Join into one string | `numbers.map { String($0) }.joined(separator: ", ")` |

The last one is how you'd print `[3, 8, 5]` as `3, 8, 5`: turn each number into a `String`, then glue them together with a separator.

## How much work is it?

Each of `map`, `filter` and `reduce` visits every element once, so each is **O(n)**. A chain of three walks the data three times and builds the arrays in between. That's still O(n) overall, and usually fine. The last lesson of this module looks at when a single loop is the better choice.

<Callout kind="gotcha" title="Swift gotcha: the initial value sets the type">
`reduce(0, …)` gives an `Int`. `reduce(0.0, …)` gives a `Double`. `reduce("", …)` gives a `String`. If Swift complains about mismatched types inside a `reduce` closure, check the initial value first.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **Expecting `map` to change the array.** It returns a new one. Write `let result = numbers.map { … }`, or assign back with `numbers = numbers.map { … }`.
- **Using `map` for side effects.** If you only want to print each element, use a `for-in` loop. `map` is for building a new array.
- **A bad initial value.** A product needs 1, not 0. A "largest so far" that starts at 0 is wrong for all-negative input, as you saw in the orientation lessons.
</Callout>
