## Why it matters

In the last lesson of M05 you passed named functions like `double` and `isGreater` to other functions. Defining a whole named function for a one-off rule gets tedious fast. A **closure** lets you write the function right where you need it. Closures are everywhere in Swift: `numbers.sorted { $0 > $1 }`, SwiftUI's `Button("Save") { save() }`, and code that runs when a download finishes. In DSA, you'll use them for custom sort orders and for the `map`, `filter` and `reduce` toolkit later in this module.

## A function without a name

A closure is a block of code that works like a function but has no name. Its full form looks like this:

```text title="The shape of a closure"
{ (parameters) -> ReturnType in
    statements
}
```

Everything goes **inside** the braces. The keyword `in` separates the closure's signature from its body.

Because a closure is a value, you can store it in a constant and call it like a function:

```swift run
let double = { (number: Int) -> Int in
    return number * 2
}

let greet = { (name: String) in
    print("Hello, \(name)!")
}

print(double(21))
greet("Maneet")
```

```output
42
Hello, Maneet!
```

What to notice:

- `double` has the type `(Int) -> Int`, exactly like a function written with `func`. Anything that accepts a function of that type accepts this closure too.
- `greet` returns nothing, so `-> Void` can be left out.
- Calls to closures never use argument labels: `double(21)`, not `double(number: 21)`.

## From the full form to the shortest

Closures shine when you pass them straight into a function. Swift can work out a lot from the context, so you can leave more and more out. Let's sort some numbers from largest to smallest using `sorted(by:)`, which needs a function of type `(Int, Int) -> Bool` that answers "should the first come before the second?".

```swift run
let numbers = [5, 2, 9, 1]

// 1. A named function
func isGreater(_ a: Int, _ b: Int) -> Bool {
    return a > b
}
print(numbers.sorted(by: isGreater))

// 2. The full closure
print(numbers.sorted(by: { (a: Int, b: Int) -> Bool in
    return a > b
}))

// 3. Swift infers the types from sorted(by:)
print(numbers.sorted(by: { a, b in return a > b }))

// 4. A single expression returns its value automatically
print(numbers.sorted(by: { a, b in a > b }))

// 5. Shorthand argument names
print(numbers.sorted(by: { $0 > $1 }))

// 6. The operator itself is a function of the right type
print(numbers.sorted(by: >))
```

```output
[9, 5, 2, 1]
[9, 5, 2, 1]
[9, 5, 2, 1]
[9, 5, 2, 1]
[9, 5, 2, 1]
[9, 5, 2, 1]
```

All six do the same thing. Step by step:

1. **A named function.** Works, but you had to invent a name for something used once.
2. **The full closure.** The same code, written inline. Parameter types, return type and `return` are all spelled out.
3. **Inferred types.** `sorted(by:)` on an `[Int]` already expects `(Int, Int) -> Bool`, so the types are redundant. `a, b in` is enough.
4. **Implicit return.** The body is one expression, so its value is returned automatically, just like a one-line function.
5. **Shorthand argument names.** Swift names the parameters `$0`, `$1`, `$2` and so on for you, so the `a, b in` part can go too.
6. **An operator.** `>` for integers is itself a function of type `(Int, Int) -> Bool`.

<Callout kind="tip" title="Which form should you use?">
Use `$0` for short, obvious closures that fit on one line: `{ $0 > $1 }`, `{ $0 * 2 }`. As soon as the body grows, or the meaning of `$0` isn't obvious, give the parameters names: `{ word, other in … }`. Clarity beats brevity.
</Callout>

## Trailing closures

When the **last** argument of a call is a closure, you can write it **after** the parentheses. This is called a **trailing closure**, and it's the style you'll see most in Swift code:

```swift run
let numbers = [5, 2, 9, 1]

let descending = numbers.sorted(by: { $0 > $1 })
let alsoDescending = numbers.sorted() { $0 > $1 }
let stillDescending = numbers.sorted { $0 > $1 }

print(descending)
print(alsoDescending)
print(stillDescending)
```

```output
[9, 5, 2, 1]
[9, 5, 2, 1]
[9, 5, 2, 1]
```

What to notice:

- With a trailing closure, the argument label (`by:`) disappears.
- If the closure is the **only** argument, you can drop the empty parentheses too. `numbers.sorted { $0 > $1 }` is the form you'll write most often.

Trailing closures are why Swift code often looks like it has custom syntax. `sorted { … }`, SwiftUI's `Button("Save") { … }` and UIKit's `UIView.animate(withDuration: 0.3) { … }` are all ordinary function calls whose last argument is a closure.

## Writing functions that take closures

Your own functions can take closures too. Any parameter with a function type can receive one:

```swift run
func repeatAction(times: Int, action: (Int) -> Void) {
    for round in 1...times {
        action(round)
    }
}

repeatAction(times: 3) { round in
    print("Round \(round)")
}

repeatAction(times: 2) {
    print("Hip hip... \($0)")
}
```

```output
Round 1
Round 2
Round 3
Hip hip... 1
Hip hip... 2
```

The caller supplies *what* happens each round, and `repeatAction` controls *when*. The first call names its parameter `round`. The second uses `$0`.

### Closures with several statements

A closure can hold several statements, just like a function. Write `return` explicitly, and name the parameters:

```swift run
let words = ["banana", "fig", "cherry", "kiwi"]

let byLength = words.sorted { first, second in
    if first.count != second.count {
        return first.count < second.count
    }
    return first < second
}
print(byLength)
```

```output
["fig", "kiwi", "banana", "cherry"]
```

This sorts by length, and breaks ties alphabetically. "banana" and "cherry" both have six letters, so the second rule decides their order. Rules like this are hard to express with `$0` and `$1`, which is why naming parameters matters as closures grow.

### Closures with no parameters

A closure that takes nothing has the type `() -> Void` when it returns nothing, and you can write it with no `in` at all:

```swift run
let sayHi = { print("Hi!") }
sayHi()
sayHi()
```

```output
Hi!
Hi!
```

## When Swift needs the types

Shortening works because Swift can work out the types from where the closure is used. `sorted(by:)` on an `[Int]` tells Swift that `$0` and `$1` are `Int`s. A closure stored in a constant on its own line has no such context:

```swift
let isLong = { $0.count > 5 }
```

```text title="What you'll see"
error: cannot infer type of closure parameter '$0' without a type annotation
```

Swift can't tell whether `$0` is a `String`, an array or something else. Give it the type, either on the constant or on the parameter:

```swift run
let isLong: (String) -> Bool = { $0.count > 5 }
let isShort = { (word: String) in word.count < 4 }

print(isLong("butterfly"), isShort("butterfly"))
print(["ox", "zebra", "elephant"].filter(isLong))
```

```output
true false
["elephant"]
```

Notice the last line: a closure stored in a constant can be passed anywhere a function of the same type is expected, exactly like a named function. `filter` keeps the elements for which the closure returns `true`, and you'll meet it properly later in this module.

<Callout kind="gotcha" title="Swift gotcha: trailing closures in conditions">
A trailing closure right after an `if`, `while` or `guard` condition is easy to misread, because the closure's braces look like the start of the statement's body:

```swift
if numbers.contains { $0 > 5 } {    // confusing
    print("Found a big one")
}
```

Swift compiles it, with a warning that the trailing closure is confusable with the body of the statement. Put the closure inside the parentheses instead: `if numbers.contains(where: { $0 > 5 }) { … }`.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: $0 or names, not both">
If you write a parameter list such as `{ a, b in … }`, you must use those names: `$0` isn't available. And a closure that uses `$1` must be one that receives at least two arguments.
</Callout>
