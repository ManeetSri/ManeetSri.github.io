## Why it matters

A closure can use the variables around it, and it **remembers** them, even after the code that created them has finished. That's how a button's action can update a counter, how a completion handler knows which item it was loading, and how a sort can rank items using a table of scores it was never passed. In DSA, closures that capture data are how you write custom orderings such as "sort these indices by the values they point to".

## Closures can see their surroundings

You saw in M05 that a nested function can use the outer function's variables. Closures do the same. Any constant or variable that's in scope where the closure is written can be used inside it:

```swift run
let passMark = 50
let scores = [72, 38, 50, 91]

for score in scores {
    let hasPassed = { score >= passMark }
    print(score, hasPassed())
}
```

```output
72 true
38 false
50 true
91 true
```

`hasPassed` takes no parameters, yet it uses both `score` and `passMark`. The closure has **captured** them.

## A capture shares the variable

When a closure captures a **variable**, it doesn't take a copy. It shares the variable itself, so changes flow both ways:

```swift run
var total = 0
let add = { (amount: Int) in
    total += amount
}

add(5)
add(10)
print(total)

total = 100
add(1)
print(total)
```

```output
15
101
```

What to notice:

- The closure changes `total`, and the code outside sees the change.
- The code outside sets `total` to 100, and the closure sees *that*: the next `add(1)` gives 101, not 16.
- There's only ever one `total`. The closure holds a reference to it.

## A counter maker

Here's where capturing becomes powerful. This function creates a variable, builds a closure that uses it, and **returns the closure**:

```swift run
func makeCounter() -> () -> Int {
    var count = 0
    return {
        count += 1
        return count
    }
}

let first = makeCounter()
let second = makeCounter()

print(first())
print(first())
print(second())
print(first())
print(second())
```

```output
1
2
1
3
2
```

Read the return type `() -> Int` as "a function that takes nothing and returns an `Int`". So `makeCounter` returns a function.

What to notice:

- Normally `count` would disappear the moment `makeCounter` returns, like any local variable. Here it lives on, because the returned closure captured it and still needs it.
- Each call to `makeCounter` runs the body again and creates a **brand new** `count`. So `first` and `second` each have their own private count, and they don't interfere.
- Nobody outside can reach `count` except by calling the closure. It's state that only the closure can see.

<Callout kind="analogy" title="A backpack">
Think of a closure as carrying a backpack. When it's created, it packs every outside variable it uses. Wherever the closure goes, even out of the function that made it, the backpack goes too, and it's the *same* variables inside, not photocopies.
</Callout>

### Closures are shared, not copied

Numbers, strings and arrays are values: assigning one to another constant copies it. Closures are different. They're **reference types**, so two names can refer to the same closure, with the same backpack:

```swift run
func makeCounter() -> () -> Int {
    var count = 0
    return {
        count += 1
        return count
    }
}

let counter = makeCounter()
let sameCounter = counter

print(counter())
print(sameCounter())
print(counter())
```

```output
1
2
3
```

`sameCounter` isn't a fresh counter. It's another name for the same closure, sharing the same `count`. To get an independent counter, call `makeCounter()` again.

## Taking a snapshot with a capture list

Sometimes you want the value a variable had **when the closure was made**, not whatever it holds later. A **capture list** in square brackets before the parameters does that:

```swift run
var level = 1

let live = { print("live: \(level)") }
let snapshot = { [level] in print("snapshot: \(level)") }

level = 5
live()
snapshot()
```

```output
live: 5
snapshot: 1
```

`[level]` copies the current value of `level` into the closure, as a constant. Later changes to the outside `level` don't reach it. You can also give the copy a new name: `[start = level]`.

## Capturing inside loops

Each pass of a `for-in` loop gets its **own** loop constant. So closures made in different passes capture different values:

```swift run
var actions: [() -> Void] = []

for number in 1...3 {
    actions.append { print("Action \(number)") }
}

for action in actions {
    action()
}
```

```output
Action 1
Action 2
Action 3
```

But if the closures capture a variable declared *outside* the loop, they all share that one variable:

```swift run
var shared = 0
var printers: [() -> Void] = []

for _ in 1...3 {
    shared += 1
    printers.append { print("Shared \(shared)") }
}

for printer in printers {
    printer()
}
```

```output
Shared 3
Shared 3
Shared 3
```

All three closures look at the same `shared`, and by the time they run it holds 3. If you wanted 1, 2 and 3, capture a snapshot with `[shared]`, or use the loop's own constant.

## Capturing in DSA: sorting by another array

A common trick is to sort **positions** instead of values. Suppose you want the indices of the scores from highest to lowest, so you know who came first. Sort the range of indices, with a closure that captures `scores` and compares the values the indices point to:

```swift run
let names = ["Ada", "Ben", "Cleo", "Dev"]
let scores = [72, 95, 64, 88]

let ranking = (0..<scores.count).sorted { scores[$0] > scores[$1] }
print(ranking)

for (place, index) in ranking.enumerated() {
    print("\(place + 1). \(names[index]) with \(scores[index])")
}
```

```output
[1, 3, 0, 2]
1. Ben with 95
2. Dev with 88
3. Ada with 72
4. Cleo with 64
```

The closure is passed pairs of indices, never scores, but it captured `scores` and uses it to decide the order. `scores` itself is never changed. (`enumerated()` pairs each element with its position: it's coming up later in this module.)

<Callout kind="note" title="Captures keep things alive">
Because a closure keeps everything it captured alive, it's possible to create a loop where an object holds a closure that holds the object, and neither is ever freed. That's called a **retain cycle**, and the fix uses a capture list like `[weak self]`. You'll meet it in M11, Memory, ARC and references. With the values used in this lesson, it can't happen.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: the variable, not the value">
A closure captures the **variable**, so it sees the value at the moment it **runs**, not when it was written. If a closure prints an "old" or "wrong" value, check whether the variable changed before the closure was called. Use a capture list, `[name]`, when you want the value frozen.
</Callout>
