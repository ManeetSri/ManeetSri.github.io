## Why it matters

Sorting and searching are the two jobs computers do most. Swift's arrays come with a ready-made toolkit for both: sort in any order you can describe, find the smallest or largest by any rule, and ask "is there one?", "which one?" and "where is it?". Every tool takes a closure, so they all work the same way. In DSA you'll reach for `sorted(by:)` constantly, often with a two-part rule like "highest score first, then alphabetical", and knowing the cost of each tool stops you from accidentally writing slow code.

## sorted and sort

`sorted()` returns a **new** array in increasing order. `sort()` rearranges the array **in place**, so it only works on a `var`:

```swift run
let scores = [72, 38, 91, 50]
let ordered = scores.sorted()
print(ordered)
print(scores)

var queue = [5, 3, 8, 1]
queue.sort()
print(queue)
```

```output
[38, 50, 72, 91]
[72, 38, 91, 50]
[1, 3, 5, 8]
```

The naming follows a Swift rule you'll see everywhere: a verb (`sort`, `reverse`) changes the value in place, and the "-ed" form (`sorted`, `reversed`) returns a new value and leaves the original alone.

Strings sort alphabetically, by comparing characters one at a time. Watch out for capitals, though:

```swift run
print(["banana", "apple", "cherry"].sorted())
print(["banana", "apple", "Cherry"].sorted())
```

```output
["apple", "banana", "cherry"]
["Cherry", "apple", "banana"]
```

Every capital letter counts as smaller than every lowercase letter, so `"Cherry"` comes first. When that matters, compare lowercased copies, as you'll see in M08.

## sorted(by:): any order you like

`sorted(by:)` and `sort(by:)` take a closure that receives two elements and answers one question: **should the first come before the second?**

```swift run
let numbers = [15, 3, 42, 8, 27]

print(numbers.sorted(by: >))
print(numbers.sorted { $0 % 10 < $1 % 10 })

let words = ["banana", "fig", "cherry", "kiwi"]
print(words.sorted { $0.count < $1.count })
```

```output
[42, 27, 15, 8, 3]
[42, 3, 15, 27, 8]
["fig", "kiwi", "banana", "cherry"]
```

What to notice:

- `>` sorts in decreasing order: "a comes before b if a is bigger".
- The second sort orders by the **last digit** (`% 10`): 2, 3, 5, 7, 8. The closure can compare anything you can compute.
- The third sorts words by length. `"banana"` and `"cherry"` are both six letters long, so this rule alone doesn't say which comes first.

### Breaking ties with a second rule

When two elements tie on the first rule, add a second. The clearest way is an `if` inside the closure:

```swift run
let words = ["pear", "fig", "plum", "apple", "kiwi"]

let ranked = words.sorted { first, second in
    if first.count != second.count {
        return first.count > second.count     // longer words first
    }
    return first < second                     // then A to Z
}
print(ranked)
```

```output
["apple", "kiwi", "pear", "plum", "fig"]
```

The three four-letter words tie on length, so the second rule puts them in alphabetical order. Notice the two rules point in **different directions**: length goes down, and the alphabet goes up. The `if` makes each direction explicit.

When both rules go the same way, there's a neat shortcut. Swift compares **tuples** element by element, left to right, like words in a dictionary. So `(a, b) < (c, d)` compares `a` with `c` first, and only looks at `b` and `d` if those tie:

```swift run
let people = [(name: "Cleo", age: 29), (name: "Ada", age: 36), (name: "Ben", age: 29)]

let byAgeThenName = people.sorted { ($0.age, $0.name) < ($1.age, $1.name) }
for person in byAgeThenName {
    print(person.name, person.age)
}
```

```output
Ben 29
Cleo 29
Ada 36
```

Cleo and Ben are both 29, so their names decide: Ben first. Tuple comparison works for tuples of up to six elements, as long as each element can be compared with `<`.

<Callout kind="gotcha" title="Swift gotcha: use <, never <=">
The closure must return `true` only when the first element **strictly** belongs before the second, and `false` for ties. Writing `$0.count <= $1.count` breaks the rule that sorting relies on, and the results can come out wrong. To sort in decreasing order, use `>`, which is also strict.
</Callout>

## min and max

`min()` and `max()` find the smallest and largest elements. They return **optionals**, because an empty array has neither:

```swift run
let temperatures = [12, -3, 25, 7]
print(temperatures.min()!, temperatures.max()!)

let nothing: [Int] = []
print(nothing.max() ?? 0)
```

```output
-3 25
0
```

To pick by a rule, use `min(by:)` and `max(by:)`. They take the **same** "should the first come before the second?" closure as `sorted(by:)`, not a "which is bigger?" closure:

```swift run
let words = ["kiwi", "fig", "banana", "plum"]

let shortest = words.min { $0.count < $1.count }
let longest = words.max { $0.count < $1.count }
print(shortest ?? "none", longest ?? "none")
```

```output
fig banana
```

Both closures use `<`. Think of `max(by:)` as "sort with this rule, then take the last element", but done in a single pass, without sorting.

<Callout kind="gotcha" title="Swift gotcha: max(by:) with >">
`words.max { $0.count > $1.count }` doesn't find the longest word: it finds the **shortest**. You've told `max` that longer words come *first* in your order, so the "largest" is the one that comes last, the shortest. Always write the increasing-order rule, and let `min` or `max` pick the end.
</Callout>

## Searching: is there one, which one, and where?

| Question | Tool | Returns |
| --- | --- | --- |
| Is this exact value present? | `contains(_:)` | `Bool` |
| Is any element like this? | `contains(where:)` | `Bool` |
| Which is the first element like this? | `first(where:)` | the element, optional |
| Where is this exact value? | `firstIndex(of:)` | an index, optional |
| Where is the first element like this? | `firstIndex(where:)` | an index, optional |
| Is every element like this? | `allSatisfy(_:)` | `Bool` |

```swift run
let scores = [72, 38, 91, 50, 38]

print(scores.contains(91))
print(scores.contains(where: { $0 < 40 }))
print(scores.first(where: { $0 > 80 }) ?? -1)
print(scores.firstIndex(of: 38) ?? -1)
print(scores.firstIndex(where: { $0 >= 50 && $0 < 60 }) ?? -1)
print(scores.allSatisfy { $0 >= 30 })
print(scores.lastIndex(of: 38) ?? -1)
```

```output
true
true
91
1
3
true
4
```

What to notice:

- The `first…` tools return optionals, because there may be no match. `?? -1` gives a fallback for printing.
- `firstIndex(of: 38)` finds the **first** 38, at index 1. `lastIndex(of:)` searches from the end instead and finds index 4. There's a `last(where:)` too.
- `allSatisfy` on an empty array returns `true`: there's no element that fails.

### They stop as soon as they know

The searching tools **stop early**. As soon as `contains(where:)` finds a match, it returns `true` without looking at the rest:

```swift run
let numbers = [4, 9, 15, 2, 30]

let hasBig = numbers.contains { number in
    print("checking \(number)")
    return number > 10
}
print(hasBig)
```

```output
checking 4
checking 9
checking 15
true
```

`2` and `30` are never checked. `first(where:)`, `firstIndex(where:)` and `allSatisfy` (which stops at the first failure) behave the same way.

## What each tool costs

| Tool | Time |
| --- | --- |
| `sorted()`, `sort()`, `sorted(by:)` | O(n log n) |
| `min()`, `max()`, `min(by:)`, `max(by:)` | O(n), always the whole array |
| `contains`, `first(where:)`, `firstIndex`, `allSatisfy` | O(n) at worst, stopping early when they can |

Sorting costs more than a single pass. So `numbers.sorted().first` for the smallest number does far more work than `numbers.min()`. Sort when you need the whole order, or when sorting makes the rest of the problem easier. You'll see why sorting costs O(n log n) in Part IV.
