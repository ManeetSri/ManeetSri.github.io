## Why it matters

Plenty of loops need more than one element at a time: the element *and* its position, an element from each of two arrays, each element and the one after it, or the elements in reverse. Swift has small, cheap tools for each of these: `enumerated`, `zip` and `reversed`. And `lazy` changes *when* a chain of `map` and `filter` does its work, so it can stop as soon as it has the answer. In DSA these turn fiddly index juggling into loops that say what they mean.

## enumerated: each element with its position

`enumerated()` pairs every element with a counter that starts at 0. Destructure each pair in the loop:

```swift run
let runners = ["Ada", "Ben", "Cleo"]

for (position, name) in runners.enumerated() {
    print("\(position + 1). \(name)")
}
```

```output
1. Ada
2. Ben
3. Cleo
```

Each pair is a tuple with the names `offset` and `element`, so you can also write `pair.offset` and `pair.element`. Destructuring with your own names, as above, is usually clearer.

`enumerated()` combines with the closure tools too. Here it finds every position where a value appears:

```swift run
let rolls = [3, 6, 2, 6, 6, 1]

let sixes = rolls.enumerated()
    .filter { $0.element == 6 }
    .map { $0.offset }
print(sixes)
```

```output
[1, 3, 4]
```

<Callout kind="gotcha" title="Swift gotcha: offset is not always an index">
`enumerated()` counts from 0, whatever the collection's real indices are. For an `Array` they're the same thing. For an **ArraySlice** they aren't: a slice of an array keeps the original array's indices, which might start at 3. You'll meet slices in M07. When you need real indices, loop over `array.indices` instead.
</Callout>

## zip: walking two sequences together

`zip(a, b)` pairs the first element of `a` with the first of `b`, the second with the second, and so on:

```swift run
let names = ["Ada", "Ben", "Cleo"]
let scores = [72, 95, 64]

for (name, score) in zip(names, scores) {
    print("\(name): \(score)")
}

let prices = [3, 10, 4]
let quantities = [2, 1, 5]
let total = zip(prices, quantities).map { $0 * $1 }.reduce(0, +)
print(total)
```

```output
Ada: 72
Ben: 95
Cleo: 64
36
```

What to notice:

- Each pair is a tuple, so you can destructure it as `(name, score)`.
- In the closure, `$0` and `$1` are the two parts of the pair. `zip(prices, quantities).map { $0 * $1 }` multiplies matching elements: 6, 10 and 20.
- No index variable, and no chance of reading `scores[i]` with the wrong `i`.

If the sequences have different lengths, `zip` **stops at the shorter one**. Extra elements in the longer sequence are silently ignored:

```swift run
let letters = ["a", "b", "c", "d"]
let numbers = [1, 2]
print(Array(zip(letters, numbers)))
```

```output
[("a", 1), ("b", 2)]
```

### Neighbours: zip with dropFirst

A favourite DSA trick: zip an array with **itself shifted by one**. `numbers.dropFirst()` is the array without its first element, so the pairs are each element and the one after it:

```swift run
let readings = [3, 5, 9, 8, 12]

let steps = zip(readings, readings.dropFirst()).map { $1 - $0 }
print(steps)

let isIncreasing = zip(readings, readings.dropFirst()).allSatisfy { $0 < $1 }
print(isIncreasing)
```

```output
[2, 4, -1, 4]
false
```

`steps` holds the change between neighbours. The dip from 9 to 8 shows up as `-1`, and it's also why `isIncreasing` is `false`. Checking whether an array is sorted, finding the biggest jump or counting how often values go up are all one line with this pattern. `dropFirst()` doesn't copy the array, so it costs nothing extra.

## reversed: back to front, without copying

`reversed()` gives you the elements in reverse order. It doesn't build a new array. It returns a lightweight **view** that reads the original from the end, so creating it is O(1):

```swift run
let countdown = [1, 2, 3, 4, 5]

for number in countdown.reversed() {
    print(number, terminator: " ")
}
print()

let backwards = Array(countdown.reversed())
print(backwards)
print(countdown)
```

```output
5 4 3 2 1
[5, 4, 3, 2, 1]
[1, 2, 3, 4, 5]
```

What to notice:

- Looping over `reversed()` is the cheapest way to go back to front.
- Printing the view directly shows its type rather than its elements, so wrap it in `Array(...)` when you need a real array.
- The original is unchanged. To reverse an array **in place**, use `reverse()` on a `var`, or write the two-index swap loop from M05.

Ranges can be reversed too: `for i in (0..<5).reversed()` counts 4, 3, 2, 1, 0, just like `stride(from: 4, through: 0, by: -1)`.

## lazy: do the work only when it's needed

Normally, each step of a chain runs **completely** before the next starts. `map` transforms every element and builds an array, and only then does `filter` begin. Watch the order with some prints:

```swift run
let numbers = [1, 2, 3, 4, 5, 6]

let firstBigSquare = numbers
    .map { number -> Int in
        print("squaring \(number)")
        return number * number
    }
    .first { $0 > 10 }
print(firstBigSquare ?? 0)
```

```output
squaring 1
squaring 2
squaring 3
squaring 4
squaring 5
squaring 6
16
```

Every number was squared, even though the answer, 16, was found at the fourth. Now add `.lazy` at the start of the chain:

```swift run
let numbers = [1, 2, 3, 4, 5, 6]

let firstBigSquare = numbers
    .lazy
    .map { number -> Int in
        print("squaring \(number)")
        return number * number
    }
    .first { $0 > 10 }
print(firstBigSquare ?? 0)
```

```output
squaring 1
squaring 2
squaring 3
squaring 4
16
```

With `lazy`, nothing runs until something asks for a value. `first(where:)` asks for elements one at a time, so each number is squared only when it's needed, and the work stops as soon as 16 passes the test. No intermediate array is built either.

With both `filter` and `map` in a lazy chain, each element travels through the **whole chain** before the next one starts. A `for-in` loop with `break` shows it clearly:

```swift run
let words = ["sun", "cloud", "rain", "storm"]

let loud = words.lazy
    .filter { word -> Bool in
        print("filter \(word)")
        return word.count > 3
    }
    .map { word -> String in
        print("map \(word)")
        return word.uppercased()
    }

print("nothing has run yet")
for word in loud {
    print("got \(word)")
    if word == "RAIN" {
        break
    }
}
```

```output
nothing has run yet
filter sun
filter cloud
map cloud
got CLOUD
filter rain
map rain
got RAIN
```

What to notice:

- Creating `loud` ran nothing at all. The work happens only when the loop asks for elements.
- `"sun"` fails the filter, so it's never mapped. `"cloud"` passes, is mapped and reaches the loop before `"rain"` is even looked at.
- After `break`, `"storm"` is never touched. Without `lazy`, the filter would have checked all four words and the map would have uppercased three of them before the loop started.

<Callout kind="gotcha" title="Swift gotcha: lazy work can run more than once">
A lazy chain doesn't remember its results. Each time you read from it, the closures run again:

```swift
let squares = [1, 2, 3].lazy.map { n -> Int in
    print("computing \(n)")
    return n * n
}
print(squares[1])   // prints "computing 2", then 4
print(squares[1])   // prints "computing 2" again, then 4
```

If you'll read the results several times, or the closures are expensive, turn the lazy chain into an array once with `Array(...)` and use that. Also keep side effects like `print` out of real lazy closures: they're here only to show the order.
</Callout>

### When to use lazy

Use `lazy` when you only need **part** of the result: the first match, the first few elements, or a loop that might `break`. For a chain whose whole result you'll use anyway, plain eager `map` and `filter` are simpler and just as fast.
