## Why it matters

Real data is messy. Some text won't convert to a number, some rows are nested inside other rows, and sometimes you want to build a whole table of counts in one pass. Three more tools handle exactly these jobs: `compactMap` drops the failures, `flatMap` flattens nested arrays, and `reduce(into:)` builds up a collection efficiently. Counting how often each value appears, the last example in this lesson, is one of the most common first steps in DSA problems.

## compactMap: transform and drop the nils

Converting a `String` to an `Int` with `Int(_:)` gives an optional, because the text might not be a number. If you `map` over some strings, you get an array of optionals:

```swift run
let entries = ["12", "seven", "5", "", "40"]

let attempts = entries.map { Int($0) }
print(attempts)

let numbers = entries.compactMap { Int($0) }
print(numbers)
```

```output
[Optional(12), nil, Optional(5), nil, Optional(40)]
[12, 5, 40]
```

What to notice:

- `map` keeps every result, so you get `[Int?]`, with `nil` where the conversion failed.
- `compactMap` unwraps the successes and **drops** the `nil`s, so you get a plain `[Int]`.
- The result can be shorter than the input, which `map` never is.

`compactMap` is "map, then throw away the failures". Use it whenever your closure returns an optional and you only care about the values that worked:

```swift run
let words = ["apple", "", "kiwi", "", "plum"]
let firstLetters = words.compactMap { $0.first }
print(firstLetters)

let maybeScores: [Int?] = [7, nil, 3, nil]
let realScores = maybeScores.compactMap { $0 }
print(realScores)
```

```output
["a", "k", "p"]
[7, 3]
```

`$0.first` is `nil` for an empty string, so those are dropped. And `compactMap { $0 }` is the standard way to strip the `nil`s out of an array of optionals.

Another everyday use: looking things up. A **dictionary** is a table of values looked up by keys, which you'll study in M07 (and use again at the end of this lesson). Looking up a key returns an optional, because the key might be missing, so `compactMap` turns a list of keys into the values that exist:

```swift run
let names = [1: "Ada", 2: "Ben", 4: "Dev"]
let requested = [4, 3, 1]
print(requested.compactMap { names[$0] })
```

```output
["Dev", "Ada"]
```

There's no entry for 3, so it's quietly skipped. Whether skipping is right depends on the problem: if a missing key is a bug, you'd rather notice it than hide it.

## flatMap: transform and flatten

Sometimes each element turns into **several** elements. With `map`, you'd get an array of arrays. `flatMap` joins them into one flat array:

```swift run
let numbers = [1, 2, 3]

let nested = numbers.map { [$0, $0 * 10] }
print(nested)

let flat = numbers.flatMap { [$0, $0 * 10] }
print(flat)
```

```output
[[1, 10], [2, 20], [3, 30]]
[1, 10, 2, 20, 3, 30]
```

If the data is *already* nested, `flatMap { $0 }` flattens it. A grid stored as rows is a common case:

```swift run
let grid = [
    [1, 2, 3],
    [4, 5],
    [],
    [6],
]

let allCells = grid.flatMap { $0 }
print(allCells)
print(grid.joined().count)
```

```output
[1, 2, 3, 4, 5, 6]
6
```

`joined()` flattens too, without needing a closure. It returns a lazy view rather than an array, which is why the example counts it instead of printing it. Wrap it in `Array(...)` when you need an actual array. You'll work with grids properly in M07.

<Callout kind="note" title="Why two names?">
Before Swift 4.1, `flatMap` also did the job of `compactMap`. That was confusing, so the "drop the nils" version was renamed. If you see old code calling `flatMap` with a closure that returns an optional, Swift warns that it's deprecated and suggests `compactMap`. Remember: **compactMap** removes `nil`s, **flatMap** removes a level of nesting.
</Callout>

## reduce(into:): building a collection

`reduce` from the last lesson returns a brand new result from each step. For a number, that's fine. For an array or a dictionary, it means building a new collection at every step, copying everything collected so far. That can turn an O(n) job into an O(n²) one.

`reduce(into:)` fixes this. Instead of returning a new result, your closure gets the result as an `inout` parameter and **changes it in place**:

```swift run
let numbers = [3, 1, 4, 1, 5]

let runningTotals = numbers.reduce(into: [Int]()) { totals, number in
    let previous = totals.last ?? 0
    totals.append(previous + number)
}
print(runningTotals)
```

```output
[3, 4, 8, 9, 14]
```

What to notice:

- The initial value is an empty array, `[Int]()`.
- The closure doesn't return anything. It appends to `totals` directly, which works because `totals` is `inout`, like the parameters from M05.
- Each entry is the sum of everything up to that point. These are called **prefix sums**, and they're a whole DSA pattern of their own in Part III.

## Counting with a dictionary

The most important use of `reduce(into:)` is counting how often each value appears. You need a **dictionary**, which you'll study properly in M07. For now, a dictionary stores **values** looked up by **keys**: here, each word is a key and its count is the value.

```swift run
let votes = ["tea", "coffee", "tea", "juice", "tea", "coffee"]

let counts = votes.reduce(into: [String: Int]()) { tally, vote in
    tally[vote, default: 0] += 1
}

for drink in counts.keys.sorted() {
    print(drink, counts[drink]!)
}
```

```output
coffee 2
juice 1
tea 3
```

What to notice:

- `[String: Int]()` is an empty dictionary from `String` keys to `Int` values.
- `tally[vote, default: 0]` reads the count for `vote`, or 0 if it hasn't been seen yet, and `+= 1` stores the new count. One line handles both the first sighting and every later one.
- The loop prints the keys in **sorted** order. A dictionary has no fixed order, so printing it directly could list the entries differently each time you run the program. Always sort the keys, or look up single entries, when the order matters.

Counting like this takes one pass over the data: O(n). Problems such as "is this word an anagram of that one?", "which number appears most often?" or "find the first unique character" all start here.

<Callout kind="gotcha" title="Swift gotcha: reduce versus reduce(into:)">
They're easy to mix up. In `reduce(0) { $0 + $1 }`, the closure **returns** the new result. In `reduce(into: [:]) { tally, x in tally[x, default: 0] += 1 }`, the closure **changes** the result and returns nothing. Use `reduce` for numbers and other small values, and `reduce(into:)` when the result is an array, dictionary or set.
</Callout>
