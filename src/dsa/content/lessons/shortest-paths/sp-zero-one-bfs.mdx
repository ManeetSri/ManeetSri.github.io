## Why it matters

Plenty of problems have only two kinds of move: free ones and ones that cost exactly 1. Walking through open floor is free, smashing a wall costs 1. Staying on the same train line is free, changing lines costs 1. Following a signpost is free, repainting it costs 1. For these graphs there's a shortest-path algorithm as fast as plain BFS, O(V + E), built on the deque you made in [Build `Deque<T>`](/dsa/learn/queue-build-deque). It's a favourite in competitive programming because it's short, fast and easy to get right.

## Why a plain queue isn't enough

BFS works because its queue is always in order of distance: everything at distance d comes out before anything at distance d + 1. With an edge of weight 1, the new vertex is one further away, so it goes to the **back** of the queue, behind the d's, exactly as in plain BFS.

An edge of weight **0** is the problem. The vertex it reaches is at distance d, the **same** as the vertex you're standing on, so it belongs with the d's at the **front**. Putting it at the back would let some d + 1 vertices come out first, and the "in order of distance" promise breaks.

A deque fixes it. It can add at either end:

- weight 0: **push to the front** (same distance as the current vertex);
- weight 1: **push to the back** (one further).

## The invariant

At every moment, the distances in the deque, read front to back, look like `d, d, …, d, d + 1, …, d + 1`: never decreasing, and spanning at most two neighbouring values. Popping the front gives a d. A 0-edge produces another d, which belongs at the front. A 1-edge produces a d + 1, which belongs at the back. Both pushes keep the shape.

So the front of the deque is always a closest unprocessed vertex, the same thing a min-heap would give you, but each operation is O(1) instead of O(log n). 0-1 BFS is Dijkstra's algorithm, which comes in the next lesson, with the heap replaced by a deque.

## 0-1 BFS in Swift

The deque below only ever pops from the front, so two arrays are enough: one holds the front part reversed, the other the back part. When the front runs out, the back is reversed into it, which is amortised O(1), like the two-stack queue from [A queue from two stacks](/dsa/learn/queue-two-stacks). Each deque entry carries the distance it was pushed with, so an entry that has been beaten since can be recognised and skipped.

```swift run
/// A deque that is popped only from the front: amortised O(1) for all three operations
struct Deque<Element> {
    private var front: [Element] = []         // stored reversed, so its last element is first in line
    private var back: [Element] = []
    var isEmpty: Bool { front.isEmpty && back.isEmpty }
    var contents: [Element] { front.reversed() + back }

    mutating func pushFront(_ element: Element) { front.append(element) }
    mutating func pushBack(_ element: Element) { back.append(element) }
    mutating func popFront() -> Element? {
        if front.isEmpty {
            front = back.reversed()
            back.removeAll()
        }
        return front.popLast()
    }
}

let names = ["S", "A", "B", "C", "T"]
// Directed edges with weight 0 or 1, as graph[from] = [(to, weight)]
let graph: [[(to: Int, weight: Int)]] = [
    [(1, 1), (2, 0)],                          // S→A 1, S→B 0
    [(4, 0)],                                  // A→T 0
    [(1, 0), (3, 1)],                          // B→A 0, B→C 1
    [(4, 0)],                                  // C→T 0
    [],
]

var distance = Array(repeating: Int.max, count: names.count)
distance[0] = 0
var deque = Deque<(vertex: Int, distance: Int)>()
deque.pushBack((0, 0))
while let (vertex, d) = deque.popFront() {
    if d > distance[vertex] {
        print("pop \(names[vertex]):\(d), stale, skip")
        continue
    }
    print("pop \(names[vertex]):\(d)")
    for (next, weight) in graph[vertex] where d + weight < distance[next] {
        distance[next] = d + weight
        if weight == 0 {
            deque.pushFront((next, d))             // as close as the current vertex: front
        } else {
            deque.pushBack((next, d + 1))          // one further: back
        }
    }
    print("   deque:", deque.contents.map { "\(names[$0.vertex]):\($0.distance)" })
}
print(zip(names, distance).map { "\($0) \($1)" })
```

```output
pop S:0
   deque: ["B:0", "A:1"]
pop B:0
   deque: ["A:0", "A:1", "C:1"]
pop A:0
   deque: ["T:0", "A:1", "C:1"]
pop T:0
   deque: ["A:1", "C:1"]
pop A:1, stale, skip
pop C:1
   deque: []
["S 0", "A 0", "B 0", "C 1", "T 0"]
```

Step through the same deque operations here:

```visual stackQueue
kind: deque
operations: ["pushBack S:0", "popFront", "pushBack A:1", "pushFront B:0", "popFront", "pushFront A:0", "pushBack C:1", "popFront", "pushFront T:0", "popFront", "popFront", "popFront"]
```

What to notice:

- A is first reached from S along a 1-edge, so it joins the back as `A:1`. Then B, at distance 0, finds a free edge to A, and `A:0` jumps in at the front.
- The old `A:1` entry is still in the deque. When it comes out, `distance[A]` is already 0, so it's **stale** and skipped. Without the check, A's edges would be relaxed again for nothing (harmless here, wasted work in general).
- At every print, the deque's distances never decrease from front to back and span at most two values.

### Why it's O(V + E)

A vertex is pushed only when its distance drops. Each edge can cause at most one push each time its start vertex is processed, and each vertex is processed (not skipped) once, because the first time it's popped its distance is already final. So there are at most V + E pushes and pops, each O(1).

<Callout kind="tip" title="With DSAKit">
In practice problems you can `import DSAKit` and use its `Deque`: `append(_:)` pushes to the back, `prepend(_:)` pushes to the front and `popFirst()` pops the front. The two-array deque above exists only so the example runs as a single file.
</Callout>

## Grids: costs on cells, not edges

In grid problems the cost often belongs to a **cell** or a **move**, not to an edge you can see. Turn it into an edge weight: "entering a wall costs 1" means every edge **into** a wall cell weighs 1, and every edge into an open cell weighs 0. Then run 0-1 BFS over cells.

Here's a grid of signposts. Each cell points `>`, `<`, `v` or `^`. Walking the way a sign points is free; walking any other way means repainting that sign, which costs 1. What's the fewest repaints to get from the top-left to the bottom-right?

```swift run
/// A deque that is popped only from the front: amortised O(1) for all three operations
struct Deque<Element> {
    private var front: [Element] = []         // stored reversed, so its last element is first in line
    private var back: [Element] = []
    var isEmpty: Bool { front.isEmpty && back.isEmpty }

    mutating func pushFront(_ element: Element) { front.append(element) }
    mutating func pushBack(_ element: Element) { back.append(element) }
    mutating func popFront() -> Element? {
        if front.isEmpty {
            front = back.reversed()
            back.removeAll()
        }
        return front.popLast()
    }
}

/// Fewest signposts to repaint so that following them leads from the top-left to the bottom-right
func fewestRepaints(_ rows: [String]) -> Int {
    let grid = rows.map { Array($0) }
    let height = grid.count, width = grid[0].count
    let moves: [(sign: Character, dr: Int, dc: Int)] = [(">", 0, 1), ("<", 0, -1), ("v", 1, 0), ("^", -1, 0)]
    var cost = Array(repeating: Array(repeating: Int.max, count: width), count: height)
    cost[0][0] = 0
    var deque = Deque<(row: Int, col: Int, cost: Int)>()
    deque.pushBack((0, 0, 0))
    while let (row, col, c) = deque.popFront() {
        if c > cost[row][col] { continue }                   // stale
        for move in moves {
            let r = row + move.dr, k = col + move.dc
            guard r >= 0, r < height, k >= 0, k < width else { continue }
            let step = grid[row][col] == move.sign ? 0 : 1   // follow the sign for free
            if c + step < cost[r][k] {
                cost[r][k] = c + step
                if step == 0 { deque.pushFront((r, k, c)) } else { deque.pushBack((r, k, c + 1)) }
            }
        }
    }
    return cost[height - 1][width - 1]
}

print(fewestRepaints([">>v", "v<<", ">>>"]))
print(fewestRepaints([">>v", "^<<", ">>>"]))
print(fewestRepaints(["<<", "<<"]))
```

```output
0
1
2
```

In the first grid the signs already snake to the corner. In the second, the `^` sends you back to the start, so one sign must change. In the last, every sign points the wrong way, and any route needs two moves against them.

The cells are the vertices, each has up to 4 edges, and every edge weighs 0 or 1. That's O(rows × columns) in total, compared with O(rows × columns × log(rows × columns)) for Dijkstra.

## Beyond 0 and 1

The trick works because only two distances are ever "live" at once. If weights are small integers from 0 to k, the same idea uses k + 1 buckets instead of a deque (**Dial's algorithm**), still without a heap. For weights that can be anything non-negative, you need Dijkstra's heap.

A related shortcut: if **every** edge has the same weight w, plain BFS works and the distance is w × (number of edges).

<Callout kind="gotcha" title="The classic slips">
- **Marking a vertex visited when it's pushed.** In plain BFS that's right. Here a vertex first reached by a 1-edge may later be reached by a 0-edge, as A was above. Decide by comparing distances, and skip stale entries when they're popped.
- **Pushing to the wrong end.** A 0-edge goes to the front, a 1-edge to the back. Swap them and the deque stops being in order.
- **`removeFirst()` on an array.** It's O(n), as you saw in [Why removeFirst() is O(n)](/dsa/learn/queue-why-not-removefirst), which turns O(V + E) into O(V²). Use a real deque.
- **Using 0-1 BFS with a weight of 2.** It silently gives wrong answers. Split a weight-2 edge into two weight-1 edges through a new vertex, or use Dijkstra.
</Callout>
