## Why it matters

Dijkstra's algorithm is the shortest-path algorithm. Internet routers run it to choose where to send packets (the OSPF protocol is Dijkstra on a map of links), route planners run souped-up versions of it on road networks, and games use it, or its cousin A*, to move characters around. In interviews it's the expected answer whenever edges have non-negative weights: "network delay", "cheapest route", "path with minimum effort". It's also a beautiful combination of two things you already know: relaxation from [Weighted graphs and the shortest-path problem](/dsa/learn/sp-weighted) and the heap from [Build a generic `Heap<T>`](/dsa/learn/heap-build).

## The greedy idea

Think of BFS as a wave spreading out from the source one edge at a time. Dijkstra is the same wave, but it spreads by **distance** instead of by number of edges: the vertices are finalised in order of how far they are from the source.

The algorithm keeps two groups of vertices:

- **settled** vertices, whose shortest distance is known for certain;
- everything else, with a tentative `distance[v]`: the best found so far, or infinity.

Then it repeats one step:

1. Pick the unsettled vertex `u` with the **smallest** tentative distance.
2. Declare it settled: its distance is final.
3. Relax every edge out of `u`.

### Why the smallest one is final

Suppose `u` has the smallest tentative distance d among the unsettled vertices. Could some other path reach `u` more cheaply? Any such path starts at the source, inside the settled group, and at some point takes its first step to an unsettled vertex x. The path has already cost at least `distance[x]` to get there, and `distance[x]` is at least d, because d was the smallest. The rest of the path, from x to `u`, adds weights that are **zero or more**, so the whole path costs at least d. Nothing beats d, so d is final.

That argument leans on one fact: **weights are never negative**. Remember it; it's the whole story of the last section.

<Callout kind="analogy">
Pour water into a network of pipes at the source. The water reaches the nearest junction first, then the next nearest, and so on. Once water has reached a junction, no later trickle can get there sooner. Dijkstra settles junctions in exactly the order the water arrives.
</Callout>

## A heap with lazy deletion

"Pick the unsettled vertex with the smallest distance" is a job for a min-heap. But there's a wrinkle: when relaxation lowers `distance[v]`, the heap may already hold an entry for `v` with the old, larger distance. Our `Heap` has no way to find that entry and change it.

The standard fix is **lazy deletion**: don't try to update the old entry. Push a **new** entry `(newDistance, v)` and leave the old one where it is. When an entry comes out of the heap, compare it with the table: if its distance is larger than `distance[v]`, it's **stale** (a better path was found after it was pushed), so skip it.

```swift run
// The heap from "Build a generic Heap<T>", cut down to what Dijkstra needs
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

let names = ["A", "B", "C", "D", "E", "F"]
var graph: [[(to: Int, weight: Int)]] = Array(repeating: [], count: names.count)
for (a, b, w) in [(0, 1, 4), (0, 2, 2), (1, 2, 1), (1, 3, 5), (2, 4, 10), (3, 4, 2), (3, 5, 6), (4, 5, 3)] {
    graph[a].append((b, w))
    graph[b].append((a, w))                    // undirected
}

func dijkstra(from source: Int) -> [Int] {
    let infinity = Int.max / 2
    var distance = Array(repeating: infinity, count: graph.count)
    distance[source] = 0
    // (distance, vertex), closest first; ties go to the smaller vertex number
    var heap = Heap<(distance: Int, vertex: Int)>(areInIncreasingOrder: { ($0.distance, $0.vertex) < ($1.distance, $1.vertex) })
    heap.insert((0, source))
    while let (d, u) = heap.pop() {
        if d > distance[u] {                   // stale: u was already settled with a smaller distance
            print("skip \(names[u]):\(d), stale")
            continue
        }
        print("settle \(names[u]) at \(d)")
        for (v, weight) in graph[u] where d + weight < distance[v] {
            distance[v] = d + weight           // relax
            heap.insert((distance[v], v))      // the old entry for v, if any, stays behind as stale
        }
    }
    return distance
}

print(dijkstra(from: 0))
```

```output
settle A at 0
settle C at 2
settle B at 3
skip B:4, stale
settle D at 8
settle E at 10
skip E:12, stale
settle F at 13
skip F:14, stale
[0, 3, 2, 8, 10, 13]
```

What to notice:

- B was first pushed as `B:4` (straight from A), then improved to 3 through C. Both entries sat in the heap; `B:3` came out first, and `B:4` was skipped later.
- The vertices are settled in order of distance: 0, 2, 3, 8, 10, 13. That's the wave.
- The heap compares `(distance, vertex)` tuples, so equal distances come out in vertex order. The distances don't depend on how ties are broken, but a fixed rule keeps the printed order predictable.
- The check `d > distance[u]` does the job of a "settled" flag: with non-negative weights, the first entry popped for a vertex always matches `distance[u]`, and every later one is larger.

<Callout kind="tip" title="Using DSAKit's Heap">
In the practice problems, `import DSAKit` and write `var heap = Heap<(distance: Int, vertex: Int)>(areInIncreasingOrder: { ($0.distance, $0.vertex) < ($1.distance, $1.vertex) })`. Comparing tuples with `<` works element by element, for tuples of up to six `Comparable` values.
</Callout>

## How fast is it?

Count the heap operations:

- Every successful relaxation pushes one entry, and each edge is relaxed at most once per time its start vertex is settled, which happens once. So there are at most E + 1 pushes, and the heap never holds more than E + 1 entries.
- Every entry is popped at most once: at most E + 1 pops.
- Each push or pop costs O(log E). Since E is at most V², log E is at most 2 log V, so that's O(log V).

Add the O(V + E) for scanning the adjacency lists, and the total is **O((V + E) log V)** time, with O(V + E) memory for the graph, the table and the heap.

| Version | Time | Best for |
| --- | --- | --- |
| Binary heap, lazy deletion (above) | O((V + E) log V) | sparse graphs: roads, networks, grids |
| No heap: scan all V for the closest each time | O(V²) | dense graphs, where E is close to V² |
| Indexed heap with decrease-key | O((V + E) log V), heap stays at V | when memory is tight |

The O(V²) version replaces the heap with a linear scan over an array of distances. When E is around V², it beats the heap's O(V² log V). The indexed heap from [d-ary heaps and indexed priority queues](/dsa/learn/heap-variants) updates entries in place instead of leaving stale ones, which keeps the heap at V entries. In practice the lazy version is simpler and usually just as fast.

## Recovering the path itself

Distances tell you how far; often you also need **which way**. Keep a `parent` array: whenever relaxation improves `distance[v]` through `u`, record `parent[v] = u`. The parents form a **shortest-path tree** rooted at the source. To read the path to a target, start at the target and follow the parents back to the source, then reverse.

If you only care about one target, you can also **stop early**: the moment the target is **popped**, its distance is final, so there's no need to settle the rest of the graph.

```swift run
// The heap from "Build a generic Heap<T>", cut down to what Dijkstra needs
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

let names = ["A", "B", "C", "D", "E", "F"]
var graph: [[(to: Int, weight: Int)]] = Array(repeating: [], count: names.count)
for (a, b, w) in [(0, 1, 4), (0, 2, 2), (1, 2, 1), (1, 3, 5), (2, 4, 10), (3, 4, 2), (3, 5, 6), (4, 5, 3)] {
    graph[a].append((b, w))
    graph[b].append((a, w))
}

/// The cheapest path from source to target as (cost, vertices), or nil if target can't be reached
func shortestPath(from source: Int, to target: Int) -> (cost: Int, path: [Int])? {
    let infinity = Int.max / 2
    var distance = Array(repeating: infinity, count: graph.count)
    var parent = Array(repeating: -1, count: graph.count)   // the vertex each best path came from
    distance[source] = 0
    var heap = Heap<(distance: Int, vertex: Int)>(areInIncreasingOrder: { ($0.distance, $0.vertex) < ($1.distance, $1.vertex) })
    heap.insert((0, source))
    while let (d, u) = heap.pop() {
        if d > distance[u] { continue }
        if u == target { break }               // popped, so final: stop early
        for (v, weight) in graph[u] where d + weight < distance[v] {
            if v == target {
                print("reached \(names[v]) via \(names[u]) with \(d + weight), not final yet")
            }
            distance[v] = d + weight
            parent[v] = u
            heap.insert((distance[v], v))
        }
    }
    guard distance[target] < infinity else { return nil }
    var path = [target]
    while path.last! != source {
        path.append(parent[path.last!])        // walk the parents back to the source
    }
    return (distance[target], path.reversed())
}

if let (cost, path) = shortestPath(from: 0, to: 5) {
    print(path.map { names[$0] }.joined(separator: " → "), "costs", cost)
}
```

```output
reached F via D with 14, not final yet
reached F via E with 13, not final yet
A → C → B → D → E → F costs 13
```

The first time F is **reached**, through D, it looks like 14. Stopping there would be wrong. Only when F is **popped** is 13 certain. The path has five edges, while A → B → D → F has three: Dijkstra cares about total weight, not edge count.

The path walk is O(length of path). The parent array costs O(V) memory and nothing extra in time, so it's worth keeping whenever a caller might ask "how?".

## Variations you'll meet

The same loop answers a surprising number of questions once you change what goes into the heap at the start or what an edge means.

**Several sources at once.** "How far is each junction from its **nearest** fire station?" Put every station in the heap at distance 0 before the loop starts. The wave then spreads from all of them together, and each junction is settled by whichever station reaches it first. Carrying a label along with each relaxation even tells you which station that is:

```swift run
// The heap from "Build a generic Heap<T>", cut down to what Dijkstra needs
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

// Junctions 0...5 joined by two-way roads (a, b, minutes). Fire stations stand at junctions 0 and 5.
let roads = [(0, 1, 4), (1, 2, 3), (2, 3, 2), (3, 4, 6), (4, 5, 1), (1, 4, 9), (2, 5, 8)]
var graph: [[(to: Int, minutes: Int)]] = Array(repeating: [], count: 6)
for (a, b, w) in roads {
    graph[a].append((b, w))
    graph[b].append((a, w))
}

let stations = [0, 5]
var minutes = Array(repeating: Int.max, count: 6)
var station = Array(repeating: -1, count: 6)     // which station's engine gets there first
var heap = Heap<(minutes: Int, junction: Int)>(areInIncreasingOrder: { ($0.minutes, $0.junction) < ($1.minutes, $1.junction) })
for source in stations {                         // every source starts in the heap at 0
    minutes[source] = 0
    station[source] = source
    heap.insert((0, source))
}
while let (time, junction) = heap.pop() {
    if time > minutes[junction] { continue }
    for (next, w) in graph[junction] where time + w < minutes[next] {
        minutes[next] = time + w
        station[next] = station[junction]        // reached through this station's region
        heap.insert((minutes[next], next))
    }
}
for junction in 0..<6 {
    print("junction \(junction): \(minutes[junction]) min from station \(station[junction])")
}
```

```output
junction 0: 0 min from station 0
junction 1: 4 min from station 0
junction 2: 7 min from station 0
junction 3: 7 min from station 5
junction 4: 1 min from station 5
junction 5: 0 min from station 5
```

It's one run of Dijkstra, not one per station: O((V + E) log V) however many stations there are. It's the weighted version of multi-source BFS from [Multi-source BFS: rotting oranges and 01 matrix](/dsa/learn/gt-multi-source).

**Distance *to* one target from everywhere.** On a directed graph, reverse every edge and run Dijkstra from the target. A path from v to the target in the original graph is a path from the target to v in the reversed one.

**Costs on vertices instead of edges.** If entering a cell or a city costs something, put that cost on every edge **into** it. The grid problems in this module all do this.

**Implicit graphs.** On a grid or a puzzle, don't build an adjacency list at all: work out a vertex's neighbours when it's popped, as in [Implicit graphs: grids and state spaces](/dsa/learn/graph-implicit).

**Different path costs.** A route's cost can be its largest step instead of its total, as long as extending a route never makes it cheaper. You'll see that in the lesson on network delay, cheapest flights and minimum effort, later in this module.

## Why negative edges break it

The proof of "the smallest one is final" said the rest of a path can only add zero or more. A negative edge lets a later step make a path **cheaper**, so a vertex settled early may have a better path that goes the long way round.

Here's a directed graph with one negative edge, B → A of −4. Dijkstra settles A at 2, straight from S. Only later does it pop B (at 5) and discover S → B → A, which costs 5 − 4 = 1. The visualiser follows the textbook rule that a settled vertex is never touched again, so the improvement never reaches C and D:

```visual graph
program: dijkstra
graph: negative
start: S
```

It ends with A 2, C 5 and D 6. The true distances are A 1, C 4 and D 5.

Our lazy version doesn't have an explicit settled flag, so it behaves a little differently, but the guarantee is just as broken:

```swift run
        var parent = 0

            let left = 2 * parent + 1

            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

let names = ["S", "A", "B", "C", "D"]
let edges = [(1, 3, 3), (3, 4, 1), (0, 1, 2), (0, 2, 5), (2, 1, -4)]   // A→C 3, C→D 1, S→A 2, S→B 5, B→A −4
var graph: [[(to: Int, weight: Int)]] = Array(repeating: [], count: names.count)
for (a, b, w) in edges {
    graph[a].append((b, w))                    // directed
}

/// Lazy Dijkstra from S. With `target`, it stops as soon as the target is popped.
func dijkstra(stoppingAt target: Int? = nil) -> (distance: [Int], processed: Int) {
    var distance = Array(repeating: Int.max / 2, count: names.count)
    distance[0] = 0
    var processed = 0
    var heap = Heap<(distance: Int, vertex: Int)>(areInIncreasingOrder: { ($0.distance, $0.vertex) < ($1.distance, $1.vertex) })
    heap.insert((0, 0))
    while let (d, u) = heap.pop() {
        if d > distance[u] { continue }
        if u == target { break }
        processed += 1
        for (v, weight) in graph[u] where d + weight < distance[v] {
            distance[v] = d + weight
            heap.insert((distance[v], v))
        }
    }
    return (distance, processed)
}

// The truth, by relaxing every edge until nothing changes
var truth = Array(repeating: Int.max / 2, count: names.count)
truth[0] = 0
for _ in 1..<names.count {
    for (a, b, w) in edges where truth[a] < Int.max / 2 && truth[a] + w < truth[b] {
        truth[b] = truth[a] + w
    }
}

print("true distances:      ", truth)
print("Dijkstra, stop at A:  A =", dijkstra(stoppingAt: 1).distance[1])
let full = dijkstra()
print("Dijkstra, no stop:   ", full.distance, "after processing", full.processed, "times for", names.count, "vertices")
```

```output
true distances:       [0, 1, 5, 4, 5]
Dijkstra, stop at A:  A = 2
Dijkstra, no stop:    [0, 1, 5, 4, 5] after processing 6 times for 5 vertices
```

- **With early exit, it's simply wrong.** A is popped at 2, so the search stops and reports 2.
- **Without early exit, it happens to recover here,** because nothing stops A from being processed a second time when `A:1` is pushed. But "popped means final" is gone, so early exit can't be trusted, and on carefully built graphs this re-processing snowballs: the number of steps can grow exponentially with V.

So the rule is firm: **Dijkstra needs every weight to be zero or more.** With negative edges, use Bellman–Ford, the next lesson. Adding a constant to every weight to make them positive doesn't work either: it penalises paths with more edges, so it changes which path is shortest.

<Callout kind="warning" title="Negative edges in undirected graphs">
An undirected edge of weight −3 can be walked there and back for −6, forever. That's a negative cycle, and shortest distances don't exist at all. Negative weights only make sense on directed edges.
</Callout>

<Callout kind="gotcha" title="The classic slips">
- **Stopping when the target is first reached.** You saw F reached at 14 and finalised at 13. Stop when the target is **popped**.
- **Marking vertices visited when they're pushed**, as in BFS. A later, better path then can't update them. Settle a vertex when it's popped.
- **Forgetting the stale check.** Without `if d > distance[u] { continue }` the answers stay correct, but stale entries relax their edges again, which can multiply the work.
- **`Int.max` as infinity.** `d + weight` from an unreached vertex can't happen in this code (only popped vertices are relaxed, and they're all reached), but in other places it can. A sentinel such as `Int.max / 2` is the safe habit.
- **Running it with negative weights.** It won't crash. It just quietly gives wrong answers.
</Callout>
