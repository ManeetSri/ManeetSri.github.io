## Why it matters

You now have seven shortest-path tools, and the wrong one is either too slow or silently wrong: Dijkstra on negative edges gives bad answers, Floyd–Warshall on 10⁵ vertices never finishes, Bellman–Ford on a big road map times out. Picking well comes down to a handful of questions about the graph, asked in the right order. This lesson turns the module into a checklist you can run in your head in an interview.

## Four questions

Ask these before writing any code.

1. **How many sources?** One source (or one pair), or every pair?
2. **What do the weights look like?** No weights (or all equal), only 0 and 1, non-negative, or some negative?
3. **Can there be cycles?** If the graph is a DAG (directed, with no cycles), a much simpler method works whatever the weights. If there are negative weights and cycles, could a cycle be negative, and does the problem want you to detect it?
4. **Is there anything extra?** A limit on edges or stops, a cost that's a maximum instead of a sum, a single target with a good distance estimate.

## The decision table

| The graph | Use | Time |
| --- | --- | --- |
| Unweighted, or every edge the same weight | BFS ([BFS and unweighted shortest paths](/dsa/learn/gt-bfs)) | O(V + E) |
| Weights only 0 and 1 | 0-1 BFS with a deque | O(V + E) |
| A DAG, any weights (even negative) | Relax in topological order | O(V + E) |
| Non-negative weights, one source | Dijkstra with a heap | O((V + E) log V) |
| Non-negative weights, one target, good heuristic | A\* | at most Dijkstra's, often far less |
| Negative weights, one source | Bellman–Ford (or SPFA) | O(V · E) |
| Need to detect a negative cycle | Bellman–Ford's extra round, or SPFA's edge count | O(V · E) |
| At most k edges or stops | Bellman–Ford with k copied rounds | O(k · E) |
| All pairs, V up to a few hundred | Floyd–Warshall | O(V³) |
| All pairs, large sparse graph, non-negative | Dijkstra from every vertex | O(V · (V + E) log V) |
| Path cost is a maximum or minimum, not a sum | Dijkstra with `max` or `min` in the relaxation | O((V + E) log V) |

Read it from the top: the first row that fits is usually the fastest correct choice. BFS beats 0-1 BFS beats Dijkstra beats Bellman–Ford, each handling more but costing more.

## DAGs: the overlooked fast case

If the graph has no cycles, there's an order in which every edge points forwards: a topological order, from [Kahn's algorithm](/dsa/learn/topo-kahn). Process the vertices in that order and relax each one's edges once. When you reach a vertex, every edge into it has already been relaxed, so its distance is final. No heap, no rounds, and negative weights are fine, because without cycles there are no negative cycles.

```swift run
// A DAG with negative edges: (from, to, weight). No cycles, so no negative cycles either.
let names = ["S", "A", "B", "C", "D"]
let edges = [(0, 1, 3), (0, 2, 6), (1, 2, -4), (1, 3, 2), (2, 3, 1), (3, 4, -2), (2, 4, 5)]
var graph: [[(to: Int, weight: Int)]] = Array(repeating: [], count: names.count)
var inDegree = Array(repeating: 0, count: names.count)
for (a, b, w) in edges {
    graph[a].append((b, w))
    inDegree[b] += 1
}

// Kahn's algorithm gives an order where every edge points forwards
var order: [Int] = []
var ready = (0..<names.count).filter { inDegree[$0] == 0 }
while let vertex = ready.popLast() {
    order.append(vertex)
    for (next, _) in graph[vertex] {
        inDegree[next] -= 1
        if inDegree[next] == 0 { ready.append(next) }
    }
}

// Relax each vertex's edges once, in that order: O(V + E), negative weights welcome
let infinity = Int.max / 2
var distance = Array(repeating: infinity, count: names.count)
distance[0] = 0
for vertex in order where distance[vertex] != infinity {
    for (next, weight) in graph[vertex] {
        distance[next] = min(distance[next], distance[vertex] + weight)
    }
}
print("order:", order.map { names[$0] }.joined(separator: " "))
print(zip(names, distance).map { "\($0) \($1)" }.joined(separator: ", "))
```

```output
order: S A B C D
S 0, A 3, B -1, C 0, D -2
```

B is cheaper through A (3 − 4 = −1) than directly (6), and that improvement flows on to C and D because they come later in the order. Dijkstra would have to be replaced by Bellman–Ford here, at O(V · E). [Longest and shortest paths in a DAG](/dsa/learn/topo-dag-paths) covers this technique in full, including longest paths (negate the weights, or use `max`), which are hard on general graphs but easy on DAGs.

Project schedules, build systems and course prerequisites are DAGs, so this case comes up more than you'd expect. Whenever a problem says "dependencies" or "must come before", check for it.

## Will it be fast enough?

A rough rule: a compiled Swift program does around 10⁸ simple steps per second (fewer in debug builds). Plug in the sizes:

| V | E | Dijkstra | Bellman–Ford | Floyd–Warshall |
| --- | --- | --- | --- | --- |
| 100 | 1,000 | instant | 10⁵: instant | 10⁶: instant |
| 10⁴ | 10⁵ | about 2 × 10⁶ | 10⁹: seconds | 10¹²: hours |
| 10⁵ | 10⁶ | about 2 × 10⁷ | 10¹¹: hopeless | hopeless |

So "negative weights on a big graph" is a warning sign: either the weights can be made non-negative, the graph is a DAG, or the intended solution is something smarter.

<Callout kind="note" title="One more tool: Johnson's algorithm">
For all pairs on a large, sparse graph with negative edges, **Johnson's algorithm** runs Bellman–Ford once from a new source connected to every vertex, uses those distances to reweight every edge so it becomes non-negative without changing which paths are shortest, then runs Dijkstra from every vertex. It's O(V · E log V). You won't need to write it in an interview, but it's good to know it exists.
</Callout>

## Worked choices

- **"Minimum number of moves for a knight to reach a square."** Every move costs 1: BFS.
- **"A metro map: riding along a line is free, changing lines costs one ticket."** Weights 0 and 1: 0-1 BFS.
- **"Delivery times between 50,000 depots and their roads, all positive."** One source, non-negative: Dijkstra.
- **"Energy use for a drone route, where descending regains energy."** Negative weights. If the route map has no cycles (always moving forwards), topological order; otherwise Bellman–Ford.
- **"Is there a sequence of trades that ends with more money than it started?"** Negative cycle detection on −log(rate) weights: Bellman–Ford from everywhere at once.
- **"A table of driving times between 150 towns."** All pairs, small V: Floyd–Warshall.
- **"A unit in a strategy game walks to the tapped tile."** One target, Manhattan or octile heuristic: A\*.
- **"Cheapest route with at most 3 connections."** Edge limit: Bellman–Ford with copied rounds, or Dijkstra on (city, flights used).

<Callout kind="gotcha" title="Choosing slips">
- **Reaching for Dijkstra by reflex.** Check for negative weights first, then check whether it's a DAG or a 0/1 graph, where something simpler is faster.
- **Floyd–Warshall because it's short.** Short code that runs for an hour is still wrong. Check V³ first.
- **Bellman–Ford on large graphs with non-negative weights.** It works, but it's O(V · E) for no reason.
- **Missing the hidden state.** A limit on stops, fuel or keys changes the graph you search, whichever algorithm you pick.
</Callout>
