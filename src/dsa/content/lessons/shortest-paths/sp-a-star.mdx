## Why it matters

When a game character walks to where you tapped, or a maps app finds a route across a city, the search has a **single target** and some sense of **direction**: the goal is over there. Dijkstra ignores that and spreads out evenly in every direction, settling thousands of places behind you before it reaches the goal in front. **A\*** (say "A star") adds a guess of the remaining distance and steers the search towards the goal, while still guaranteeing the shortest path. It's the standard pathfinding algorithm in games, and route planners build on the same idea. Apple's GameplayKit gives you ready-made pathfinding on grids and graphs (`GKGridGraph` and `findPath(from:to:)`); this lesson is how that kind of pathfinder works inside, and how to write your own when you need control over costs.

## Dijkstra spreads in every direction

On a grid where every step costs 1, Dijkstra is the same as BFS: a wave that grows evenly in all directions. Watch it fill most of the grid before it reaches G:

```visual grid
rows: ["S....#......", ".....#......", ".....#......", ".....#....#.", ".....#....#G", "..........#."]
```

Most of that work is wasted. The cells to the far left were settled only because they're close to S, even though they lead away from G.

## f = g + h

A\* changes one thing: the order in which vertices come out of the heap. For each vertex n it uses three numbers:

- **g(n)**: the cost of the best path found from the start to n, exactly as in Dijkstra;
- **h(n)**: a **heuristic**, an estimate of the cost still to go from n to the goal;
- **f(n) = g(n) + h(n)**: the estimated cost of the cheapest complete route that passes through n.

Dijkstra pops the smallest g. A\* pops the smallest **f**. A cell close to the start but on the wrong side of it has a small g and a large h, so it waits. A cell that's on the way has a modest g and a small h, so it comes out first.

With h = 0 everywhere, f = g, and A\* **is** Dijkstra. Everything you know about Dijkstra (lazy deletion, stale entries, stopping when the goal is popped) carries over unchanged.

### Manhattan distance on grids

On a grid where you move up, down, left or right and each step costs 1, the best possible guess is the **Manhattan distance**: `abs(row - goalRow) + abs(col - goalCol)`. It's the number of steps you'd need if there were no walls at all, like a taxi in a city of square blocks. Walls can only make the real distance longer, never shorter.

```swift run
// The heap from "Build a generic Heap<T>", cut down to insert and pop
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

let rows = [
    "S....#......",
    ".....#......",
    ".....#......",
    ".....#....#.",
    ".....#....#G",
    "..........#.",
]
let grid = rows.map { Array($0) }
let height = grid.count, width = grid[0].count
let start = (row: 0, col: 0), goal = (row: 4, col: 11)

/// Cheapest number of steps from start to goal. Each step costs 1; `heuristic` estimates the rest.
func search(heuristic: (Int, Int) -> Int) -> (cost: Int, expanded: [[Bool]]) {
    var best = Array(repeating: Array(repeating: Int.max, count: width), count: height)
    var expanded = Array(repeating: Array(repeating: false, count: width), count: height)
    // Entries are (f, h, row, col): smallest f = g + h first, then the one that looks closer to the goal
    var open = Heap<(f: Int, h: Int, row: Int, col: Int)>(areInIncreasingOrder: { ($0.f, $0.h, $0.row, $0.col) < ($1.f, $1.h, $1.row, $1.col) })
    best[start.row][start.col] = 0
    open.insert((heuristic(start.row, start.col), heuristic(start.row, start.col), start.row, start.col))
    while let entry = open.pop() {
        let g = entry.f - entry.h
        if g > best[entry.row][entry.col] { continue }             // stale
        expanded[entry.row][entry.col] = true
        if (entry.row, entry.col) == (goal.row, goal.col) { return (g, expanded) }
        for (dr, dc) in [(0, 1), (1, 0), (0, -1), (-1, 0)] {
            let r = entry.row + dr, c = entry.col + dc
            guard r >= 0, r < height, c >= 0, c < width, grid[r][c] != "#" else { continue }
            if g + 1 < best[r][c] {
                best[r][c] = g + 1
                let h = heuristic(r, c)
                open.insert((g + 1 + h, h, r, c))
            }
        }
    }
    return (-1, expanded)
}

func report(_ name: String, _ result: (cost: Int, expanded: [[Bool]])) {
    let count = result.expanded.joined().filter { $0 }.count
    print("\(name): cost \(result.cost), expanded \(count) cells")
    for r in 0..<height {
        print(String((0..<width).map { c in
            grid[r][c] != "." ? grid[r][c] : (result.expanded[r][c] ? "*" : ".")
        }))
    }
}

report("Dijkstra", search(heuristic: { _, _ in 0 }))
report("A* with Manhattan distance", search(heuristic: { r, c in abs(r - goal.row) + abs(c - goal.col) }))
```

What to notice:

- Both find the same cost, 21. A\* is not a guess at the answer; only the search order changes.
- Dijkstra expanded 63 of the 64 open cells. A\* skipped the whole top-right region, which looks close to G as the crow flies but would need a long way round.
- A\* still expanded much of the left side: the wall in column 5 forces every route down to the bottom row, and Manhattan distance can't see walls. On open ground, A\* with this tie-break walks almost straight to the goal. The better h predicts the real distance, the less A\* explores.
- `g` isn't stored in the heap entry: it's `f - h`, recovered when the entry is popped.

## When is A\* guaranteed to be right?

The heuristic decides everything, so it must follow rules.

**Admissible: never overestimate.** h(n) must be at most the true remaining cost from n. Then A\* returns a shortest path. The reason: while the best route hasn't been found yet, some vertex on it is waiting in the heap with f no bigger than the true answer, so the goal can't be popped with a worse cost first.

**Consistent: never drop by more than an edge costs.** For every edge u → v with weight w, `h(u) ≤ w + h(v)`, and h(goal) = 0. This is the triangle inequality for estimates. A consistent heuristic is also admissible, and it gives a stronger promise: like in Dijkstra, the first time a vertex is popped, its g is final, so each vertex is expanded once.

Manhattan distance on a 4-direction grid with unit steps is consistent: one step changes it by exactly 1.

| Moves | Step costs | A good heuristic |
| --- | --- | --- |
| 4 directions | 1 per step | Manhattan: `abs(dr) + abs(dc)` |
| 4 directions | each cell costs at least m | m × Manhattan |
| 8 directions, diagonals cost 1 | 1 per step | Chebyshev: `max(abs(dr), abs(dc))` |
| any direction, real coordinates | straight-line length | Euclidean distance |
| no idea | anything non-negative | h = 0, which is Dijkstra |

<Callout kind="note" title="What if h overestimates?">
An inadmissible heuristic can make A\* faster, but it can return a longer path. Games sometimes do this on purpose: **weighted A\*** uses f = g + w × h with w > 1, and the path it finds is at most w times the shortest. That's a fine trade for a monster chasing the player, and a bad one for a routing app.
</Callout>

### Ties

Many cells often share the same f. Among them, prefer the one with the **smaller h** (equivalently the larger g): it's further along, closer to the goal. That's why the heap above compares `(f, h, row, col)`. Without that rule, A\* on open ground can expand a whole diamond of equally good cells instead of following one path. The final row and column only make the order fixed, so the output is repeatable.

## A\* in maps and games

- **Games**: grids and navigation meshes with Manhattan, octile or Euclidean heuristics. The search runs every time a unit gets an order, so expanding fewer nodes matters.
- **Maps**: the straight-line distance between two points is an admissible guess for road distance. Real route planners add heavy precomputation on top of A\* and Dijkstra (landmark distances, contraction hierarchies) to answer continent-sized queries in milliseconds.
- **Puzzles**: the 8-puzzle with "how many tiles are out of place" or "sum of Manhattan distances of tiles" as h. Each puzzle state is a vertex in an implicit graph, like the state spaces in [State-space BFS: word ladder and open the lock](/dsa/learn/gt-state-space).

A\* answers a **single-pair** question. If you need distances from the start to everything, there's nothing to steer towards, and Dijkstra is the right tool.

<Callout kind="gotcha" title="The classic slips">
- **An h that can overestimate**, such as Manhattan distance when diagonal moves are allowed (one diagonal step covers 2 of it for a cost of 1), or Manhattan scaled by a cost bigger than the cheapest cell. The search still finishes, with a wrong answer.
- **Stopping when the goal is first pushed.** As with Dijkstra, stop when it's **popped**.
- **Marking cells closed on push.** A cheaper g may still arrive. Compare g values and skip stale entries.
- **No tie-break.** Correct, but it can expand many more cells than needed on open ground.
- **Using A\* with a heuristic of 0 and calling it fast.** That's Dijkstra with extra bookkeeping.
</Callout>
