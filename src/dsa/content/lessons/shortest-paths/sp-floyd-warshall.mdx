## Why it matters

Sometimes you need the distance between **every** pair of vertices: a mileage table in a road atlas, the latency between every pair of data centres, or "which city has the fewest neighbours within 50 km?" Running Dijkstra from every vertex works, but for small, dense graphs there's something much simpler: **Floyd–Warshall**, three nested loops and one line of relaxation. It handles negative edges, spots negative cycles, and with one small change answers "can i reach j at all?" for every pair. It's also your first taste of dynamic programming, which gets its own modules later in the course.

## The matrix and the question

Keep a V × V matrix `dist`, where `dist[i][j]` is the best known distance from i to j. Start it from the edges:

- `dist[i][i] = 0`;
- `dist[i][j] = w` for each edge i → j (the cheapest one, if there are several);
- infinity everywhere else.

Number the vertices 0 to V − 1. Floyd–Warshall then asks one question, V times over:

> Allowing vertex k as a stop **in the middle** of a path, does any pair get a shorter path?

After asking it for k = 0, then 1, then 2, and so on up to V − 1, every vertex has been allowed in the middle, so every path has been considered.

## Building the answer one middle vertex at a time

Define the meaning precisely: after round k, `dist[i][j]` is the shortest path from i to j whose **intermediate** vertices (everything except the two ends) all come from `0...k`.

How does round k improve on round k − 1? Look at the best i-to-j path that may use `0...k` in the middle. Either:

- **it doesn't use k**, so it was already found in round k − 1; or
- **it goes through k**, once (going round a loop through k again can't help without a negative cycle). Then it's a path i ⇝ k followed by k ⇝ j, and each half uses only `0...k − 1` in the middle, so both halves are already in the matrix.

So round k is one relaxation per pair: `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`.

```swift run
let infinity = Int.max / 2
let n = 4
// Directed edges (from, to, weight)
let edges = [(0, 1, 3), (0, 2, 8), (1, 2, 2), (2, 3, 1), (3, 0, 4)]

var dist = Array(repeating: Array(repeating: infinity, count: n), count: n)
for i in 0..<n {
    dist[i][i] = 0
}
for (from, to, weight) in edges {
    dist[from][to] = min(dist[from][to], weight)   // keep the cheapest of parallel edges
}

func show(_ matrix: [[Int]]) {
    for row in matrix {
        let cells = row.map { $0 == infinity ? "∞" : String($0) }
        print(cells.map { String(repeating: " ", count: 3 - $0.count) + $0 }.joined())
    }
}

for k in 0..<n {                               // k: the newest vertex allowed in the middle
    for i in 0..<n where dist[i][k] < infinity {
        for j in 0..<n where dist[k][j] < infinity && dist[i][k] + dist[k][j] < dist[i][j] {
            dist[i][j] = dist[i][k] + dist[k][j]
        }
    }
    print("allowing 0...\(k) in the middle:")
    show(dist)
}
```

Row i is "from i", column j is "to j". What to notice:

- With 0 in the middle, 3 can reach 1 and 2 through 0 (4 + 3 = 7 and 4 + 8 = 12).
- With 1 allowed too, 0 → 1 → 2 costs 5, beating the direct 8, and 3's route to 2 drops to 9.
- In the last round, vertex 3 is the bridge back to 0, so rows 1 and 2 finally fill in.
- The guards `dist[i][k] < infinity` and `dist[k][j] < infinity` skip pairs that can't use k at all. They also stop "infinity plus a negative weight" from passing as a real distance.

<Callout kind="analogy">
Think of an airline adding hub airports one at a time. With no hubs you can only fly direct. Open the first hub, and every pair checks whether connecting there beats their direct route. Open the second hub, and connections can now use either hub, including both on one trip. When every airport is a hub, every possible itinerary has been considered.
</Callout>

## Why k must be the outer loop

It's tempting to write the loops as `i`, `j`, `k`, the usual order for matrix code. Don't. The argument above needs **every** pair to have finished round k − 1 before any pair uses k. With k innermost, `dist[i][j]` gets its only chance when the matrix is still half-built:

```swift run
let infinity = Int.max / 2
let names = ["A", "B", "C", "D"]
let edges = [(0, 1, 4), (1, 3, 2), (3, 2, 3)]  // one chain: A → B → D → C

func allPairs(kOutermost: Bool) -> [[Int]] {
    let n = names.count
    var dist = Array(repeating: Array(repeating: infinity, count: n), count: n)
    for i in 0..<n {
        dist[i][i] = 0
    }
    for (from, to, weight) in edges {
        dist[from][to] = weight
    }
    for a in 0..<n {
        for b in 0..<n {
            for c in 0..<n {
                let (k, i, j) = kOutermost ? (a, b, c) : (c, a, b)   // the wrong order puts k innermost
                if dist[i][k] < infinity && dist[k][j] < infinity && dist[i][k] + dist[k][j] < dist[i][j] {
                    dist[i][j] = dist[i][k] + dist[k][j]
                }
            }
        }
    }
    return dist
}

let right = allPairs(kOutermost: true)
let wrong = allPairs(kOutermost: false)
print("A to C, k outermost:", right[0][2])
print("A to C, k innermost:", wrong[0][2] == infinity ? "∞" : String(wrong[0][2]))
```

```output
A to C, k outermost: 9
A to C, k innermost: ∞
```

The path A → B → D → C needs two middle vertices. With k innermost, the pair (A, C) is finished before B → C or A → D has been worked out, so neither "through B" nor "through D" can see the rest of the chain. Floyd–Warshall with the wrong loop order gives no error, just wrong answers.

### Why updating in place is safe

The recurrence talks about "round k − 1 values", yet the code overwrites the one matrix as it goes. That's fine, because round k never changes the two things it reads. Row k becomes `min(dist[k][j], dist[k][k] + dist[k][j])`, and `dist[k][k]` is 0, so nothing changes; column k is the same. (A negative cycle breaks this, which is exactly when the answers stop meaning anything anyway.)

## Cost, and when to choose it

Three nested loops over V vertices: **O(V³)** time and **O(V²)** memory, whatever the number of edges.

| V | V³ | Verdict |
| --- | --- | --- |
| 100 | 10⁶ | instant |
| 400 | 6.4 × 10⁷ | fine |
| 2,000 | 8 × 10⁹ | too slow |

For sparse graphs with non-negative weights, running Dijkstra from every vertex costs O(V · (V + E) log V), which is much less than V³ when E is close to V. Floyd–Warshall wins when V is small (a few hundred), when the graph is dense, when weights can be negative, or when you simply want the shortest correct code.

## Negative edges and negative cycles

Negative edges are fine: the argument never assumed weights were positive. Negative **cycles** are detected for free. If vertex i is on a negative cycle, then once all the cycle's vertices are allowed in the middle, going round the cycle and back to i costs less than 0, so `dist[i][i]` drops below zero:

```swift run
let infinity = Int.max / 2

/// Floyd–Warshall, then report which vertices sit on a negative cycle
func verticesOnNegativeCycles(_ n: Int, _ edges: [(Int, Int, Int)]) -> [Int] {
    var dist = Array(repeating: Array(repeating: infinity, count: n), count: n)
    for i in 0..<n {
        dist[i][i] = 0
    }
    for (from, to, weight) in edges {
        dist[from][to] = min(dist[from][to], weight)
    }
    for k in 0..<n {
        for i in 0..<n where dist[i][k] < infinity {
            for j in 0..<n where dist[k][j] < infinity {
                dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])
            }
        }
    }
    return (0..<n).filter { dist[$0][$0] < 0 }   // a way back to yourself that costs less than nothing
}

print(verticesOnNegativeCycles(4, [(0, 1, 2), (1, 2, -1), (2, 3, 4), (3, 1, -1)]))
print(verticesOnNegativeCycles(4, [(0, 1, 2), (1, 2, -1), (2, 3, 1), (3, 1, -1)]))
```

```output
[]
[1, 2, 3]
```

The loop 1 → 2 → 3 → 1 costs −1 + 4 − 1 = 2 in the first graph and −1 + 1 − 1 = −1 in the second. Any pair (i, j) where i can reach a vertex with `dist[k][k] < 0` and that vertex can reach j has no shortest path at all.

## Reachability: the transitive closure

Swap the numbers for Booleans, `min` for "or" and `+` for "and", and the same loops answer "can i reach j at all?" for every pair. This matrix is called the **transitive closure** of the graph.

```swift run
// Transitive closure: can i reach j at all? Same loops, with || and && instead of min and +
let n = 4
var reach = Array(repeating: Array(repeating: false, count: n), count: n)
for i in 0..<n {
    reach[i][i] = true
}
for (from, to) in [(0, 1), (1, 2), (3, 2)] {
    reach[from][to] = true
}
for k in 0..<n {
    for i in 0..<n where reach[i][k] {
        for j in 0..<n where reach[k][j] {
            reach[i][j] = true
        }
    }
}
for i in 0..<n {
    print(i, "reaches", (0..<n).filter { reach[i][$0] })
}
```

```output
0 reaches [0, 1, 2]
1 reaches [1, 2]
2 reaches [2]
3 reaches [2, 3]
```

It's O(V³) like before, and it answers any number of "is j reachable from i?" questions in O(1) each afterwards. (Prerequisite chains are a typical use: "is course 0 a prerequisite of course 2, directly or indirectly?")

### Recovering paths

To print the route as well as the distance, keep a matrix `next[i][j]`: the first step on the best path from i to j. Start with `next[i][j] = j` for every edge, and whenever going through k wins, set `next[i][j] = next[i][k]`. To print a path, start at i and keep jumping to `next[current][j]` until you arrive at j.

<Callout kind="gotcha" title="The classic slips">
- **Putting k anywhere but the outermost loop.** No error, wrong answers.
- **Forgetting `dist[i][i] = 0`.** Without it, a vertex can't serve as the start or end of a path through itself, and the negative-cycle check stops working.
- **Overwriting parallel edges.** Two edges from i to j: keep the cheaper, with `min`.
- **Adding infinity to infinity.** `Int.max / 2` has room for one addition of two infinities, but not for negative weights sneaking below it. The `< infinity` guards keep it honest.
- **Undirected input.** Set both `dist[a][b]` and `dist[b][a]`.
</Callout>
