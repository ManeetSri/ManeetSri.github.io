## Why it matters

Interviewers rarely say "run Dijkstra". They describe servers passing a signal, a traveller with a limited number of connections, or a hiker who hates steep steps, and the real test is whether you can turn the story into a graph and pick the right algorithm. This lesson works through the three most common shortest-path interview problems and the modelling decision at the heart of each: **what is a vertex, what is an edge, and what does "the cost of a path" mean?**

## Network delay: the largest shortest distance

**The story.** A network has n servers and one-way links, each with a delay in milliseconds. A signal starts at one server and spreads along every link at once. How long until every server has received it? If some server never does, report −1.

**The model.**

- Vertices: servers. Edges: the directed links, weighted by delay.
- The signal reaches each server along its **fastest** route, which is its shortest distance from the source.
- Everyone has it once the **slowest** server has it: the answer is the **largest** shortest distance.
- Delays are non-negative, so this is Dijkstra.

Here's that network, so you can watch the distances settle (the labels are arrival times):

```swift run
// The heap from "Build a generic Heap<T>", cut down to what Dijkstra needs
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

/// How long until a signal sent from `source` reaches every server, or -1 if some never hear it.
/// `links` are directed [from, to, milliseconds].
func timeToReachAll(serverCount n: Int, links: [[Int]], source: Int) -> Int {
    var graph: [[(to: Int, time: Int)]] = Array(repeating: [], count: n)
    for link in links {
        graph[link[0]].append((link[1], link[2]))
    }
    var arrival = Array(repeating: Int.max, count: n)
    arrival[source] = 0
    var heap = Heap<(time: Int, server: Int)>(areInIncreasingOrder: { ($0.time, $0.server) < ($1.time, $1.server) })
    heap.insert((0, source))
    var reached = 0
    var latest = 0
    while let (time, server) = heap.pop() {
        if time > arrival[server] { continue }
        reached += 1
        latest = time                          // popped in time order, so the last one popped is the latest
        for (next, delay) in graph[server] where time + delay < arrival[next] {
            arrival[next] = time + delay
            heap.insert((arrival[next], next))
        }
    }
    return reached == n ? latest : -1
}

let links = [[0, 1, 2], [0, 2, 5], [1, 2, 1], [1, 3, 6], [2, 3, 2], [3, 4, 1], [2, 4, 7]]
print(timeToReachAll(serverCount: 5, links: links, source: 0))
print(timeToReachAll(serverCount: 5, links: links, source: 1))
print(timeToReachAll(serverCount: 5, links: links, source: 3))
```

```output
6
-1
-1
```

What to notice:

- Server 4 hears the signal last, at 6 ms, through 0 → 1 → 2 → 3 → 4. The direct-looking 2 → 4 link (7 ms) never matters.
- From server 1, nothing leads back to server 0, so the answer is −1. Links are one-way.
- Vertices come out of the heap in order of arrival time, so the last one settled holds the answer. Counting settled vertices answers "did everyone hear it?" without a second pass.
- `Int.max` is safe as infinity here because only settled vertices, which all have real times, are relaxed.

**What interviewers probe:** that you know BFS is wrong (delays differ), that "everyone" means the maximum, the unreachable case, and the complexity, O((V + E) log V).

## Cheapest flights within k stops: a limit changes the state

**The story.** Flights between cities have prices. Find the cheapest way from city A to city B using **at most k stops** (k intermediate cities, so at most k + 1 flights), or −1 if there's none.

**The trap.** It looks like Dijkstra on price. But the cheapest way into a city might use too many stops, while a pricier way with fewer stops is the only one that can still reach B. Dijkstra settles each city once, at its cheapest price, and throws the pricier-but-shorter route away:

```swift run
// The heap from "Build a generic Heap<T>", cut down to what Dijkstra needs
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

// Flights [from, to, price]. The cheap way into city 2 uses an extra stop.
let flights = [[0, 1, 1], [1, 2, 1], [0, 2, 5], [2, 3, 1]]
let cityCount = 4

/// The trap: Dijkstra that settles each city once, by price, and refuses paths with too many flights
func naiveCheapest(from source: Int, to target: Int, maxStops: Int) -> Int {
    var settled = Array(repeating: false, count: cityCount)
    var heap = Heap<(price: Int, city: Int, flights: Int)>(areInIncreasingOrder: { ($0.price, $0.city) < ($1.price, $1.city) })
    heap.insert((0, source, 0))
    while let (price, city, used) = heap.pop() {
        if settled[city] { continue }
        settled[city] = true
        if city == target { return price }
        guard used <= maxStops else { continue }   // used + 1 flights would be too many
        for flight in flights where flight[0] == city {   // scanning the list keeps the example short
            heap.insert((price + flight[2], flight[1], used + 1))
        }
    }
    return -1
}

/// Bellman–Ford with a copy per round: maxStops + 1 rounds, one more flight each round
func roundsCheapest(from source: Int, to target: Int, maxStops: Int) -> Int {
    var price = Array(repeating: Int.max, count: cityCount)
    price[source] = 0
    for _ in 0...maxStops {
        let before = price
        for flight in flights where before[flight[0]] != Int.max {
            price[flight[1]] = min(price[flight[1]], before[flight[0]] + flight[2])
        }
    }
    return price[target] == Int.max ? -1 : price[target]
}

for stops in 0...2 {
    print("at most \(stops) stop(s): naive \(naiveCheapest(from: 0, to: 3, maxStops: stops)), rounds \(roundsCheapest(from: 0, to: 3, maxStops: stops))")
}
```

```output
at most 0 stop(s): naive -1, rounds -1
at most 1 stop(s): naive -1, rounds 6
at most 2 stop(s): naive 3, rounds 3
```

With one stop allowed, the only legal route is 0 → 2 → 3 for 5 + 1 = 6. The naive search settles city 2 at price 2 via 0 → 1 → 2, which has already used up the stop, and then discards the 5-price entry for city 2 as "already settled". It never tries 2 → 3 with a stop to spare.

**Two correct models:**

1. **Bellman–Ford with k + 1 rounds**, reading from a copy each round, as in [Bellman–Ford and negative cycles](/dsa/learn/sp-bellman-ford). O(k · E) time, O(V) memory, and the simplest to get right.
2. **Dijkstra on a bigger graph.** Make the vertex a pair **(city, flights used)**. Then "cheapest into city 2 having used 2 flights" and "cheapest into city 2 having used 1 flight" are different vertices, and neither blocks the other. The state graph has V × (k + 2) vertices, so it's O(k · E · log(k · E)), and it can stop as soon as B is popped.

This is the most important modelling idea in the module: **when a constraint matters, put it in the state.** Fuel left, keys collected, stops used: each becomes part of the vertex, as in [State-space BFS: word ladder and open the lock](/dsa/learn/gt-state-space).

**What interviewers probe:** stops versus flights (off by one), why plain Dijkstra fails, and the in-place update bug in Bellman–Ford.

## Minimum effort: a path's cost isn't always a sum

**The story.** A hiker crosses a grid of heights from the top-left to the bottom-right, moving up, down, left or right. The **effort** of a route is its single steepest step: the largest height difference between two neighbouring cells on it. Find the least possible effort.

**The model.** Vertices are cells; edges join neighbours, weighted by the height difference. But the cost of a path is now the **maximum** edge weight, not the sum. Three approaches work, and an interviewer will be pleased to hear more than one.

### 1. Dijkstra with a different "plus"

Dijkstra's proof needed one thing: extending a path never makes it cheaper. That's true for sums of non-negative weights, and it's just as true for "the largest step so far": adding a step can only keep the maximum the same or raise it. So Dijkstra works with the relaxation changed to:

```swift
let candidate = max(effort[cell], abs(height[cell] - height[next]))
if candidate < effort[next] {
    effort[next] = candidate
    heap.insert((candidate, next))
}
```

The same idea in reverse solves the classic "widest path" question: how heavy a lorry can drive from the depot to each town, if every road has a weight limit? A route's value is its **weakest** road, and you want the **largest**, so the heap becomes a max-heap and `min` replaces `max`:

```swift run
// The heap from "Build a generic Heap<T>", cut down to what Dijkstra needs
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1
            let right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { break }
            items.swapAt(parent, first)
            parent = first
        }
        return top
    }
}

// Two-way roads [a, b, weight limit in tonnes]. How heavy a lorry can drive from the depot (0) to each town?
let roads = [[0, 1, 8], [0, 2, 3], [1, 2, 6], [1, 3, 2], [2, 3, 5], [3, 4, 7]]
let townCount = 5
var graph: [[(to: Int, limit: Int)]] = Array(repeating: [], count: townCount)
for road in roads {
    graph[road[0]].append((road[1], road[2]))
    graph[road[1]].append((road[0], road[2]))
}

// The value of a route is its weakest road. Extending a route can never raise it,
// so the "settle the best one first" argument still works: pop the largest load first.
var heaviest = Array(repeating: 0, count: townCount)
heaviest[0] = Int.max                          // no limit at the depot itself
// A max-heap by load; equal loads come out in town order
var heap = Heap<(load: Int, town: Int)>(areInIncreasingOrder: { $0.load != $1.load ? $0.load > $1.load : $0.town < $1.town })
heap.insert((Int.max, 0))
while let (load, town) = heap.pop() {
    if load < heaviest[town] { continue }      // stale: a heavier lorry already gets here
    for (next, limit) in graph[town] {
        let candidate = min(load, limit)       // the route's weakest road so far
        if candidate > heaviest[next] {
            heaviest[next] = candidate
            heap.insert((candidate, next))
        }
    }
}
print(Array(heaviest.dropFirst()))
```

```output
[8, 6, 5, 5]
```

Town 2 is reachable directly over a 3-tonne road, but going round through town 1 allows 6 tonnes, because that route's weakest road is the 6-tonne one. The general rule: Dijkstra works for **any** path cost that never improves as the path grows, whether it's a sum, a maximum, or a minimum read the other way round.

### 2. Binary search on the answer

"Can the hiker get across with effort at most x?" is a yes/no question, and it's monotonic: if x works, every larger x works too. That's the pattern from [The monotonic predicate idea](/dsa/learn/bsa-idea). Binary search x between 0 and the largest height difference, and answer each question with a BFS or DFS that only uses steps of at most x. That's O(R · C · log H) for an R × C grid with heights up to H.

### 3. Union-find

Sort all the neighbour pairs by height difference and join cells in that order. The moment the start and finish cells are in the same group, the last difference added is the answer. You'll build the structure that makes "same group?" fast in [Disjoint sets and the parent array](/dsa/learn/uf-idea).

**What interviewers probe:** whether you notice the cost is a maximum, why Dijkstra still works (monotonic costs), and whether you can offer the binary-search alternative.

<Callout kind="gotcha" title="Modelling slips">
- **"Everyone receives it" means the maximum distance**, not the sum and not the distance to one target.
- **k stops means k + 1 edges.** Write it down before coding.
- **Settling by price alone when another limit applies.** Put the limit in the state, or use the round-by-round Bellman–Ford.
- **Summing when the cost is a maximum.** Read the definition of a route's cost twice.
- **Forgetting one-way links.** Network links and flights are usually directed; hiking grids aren't.
</Callout>

## Practice

**Signal spread time** and **Cheapest trip within k stops** are the two classics in full, with large tests. **Gentlest hiking route** is the minimum-effort grid. **Cheapest drive with toll vouchers** is the "put the limit in the state" idea at full strength: Dijkstra over (city, vouchers used).
