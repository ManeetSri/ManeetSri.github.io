## Why it matters

Bellman–Ford relaxes every edge in every round, even edges whose start vertex hasn't changed since the last round, which can't possibly improve anything. The **Shortest Path Faster Algorithm** (SPFA) skips that wasted work by keeping a queue of the vertices whose distance just changed. On typical graphs it's dramatically faster than Bellman–Ford, it still handles negative edges and detects negative cycles, and it's only a few lines longer. It's popular in competitive programming and in minimum-cost flow algorithms. But it has a nasty worst case, and knowing when **not** to use it matters as much as knowing how.

## Only changed vertices can help

Relaxing `u → v` can improve `v` only if `distance[u]` is better than it was the last time this edge was relaxed. So after the first pass, the only edges worth relaxing are those leaving a vertex whose distance has **changed**.

SPFA keeps exactly those vertices in a queue:

1. Put the source in the queue with distance 0.
2. Take a vertex `u` from the front and relax its outgoing edges.
3. Whenever a neighbour `v` improves, add it to the queue, unless it's already waiting there.
4. Stop when the queue is empty.

The "unless it's already waiting" part uses an `inQueue` flag per vertex. A vertex that's already in the queue will read its newest distance when its turn comes, so adding it twice would only repeat work.

```swift run
let names = ["S", "A", "B", "C", "D"]
let edges = [(1, 3, 3), (3, 4, 1), (0, 1, 2), (0, 2, 5), (2, 1, -4)]   // A→C 3, C→D 1, S→A 2, S→B 5, B→A −4
var graph: [[(to: Int, weight: Int)]] = Array(repeating: [], count: names.count)
for (a, b, w) in edges {
    graph[a].append((b, w))
}

let infinity = Int.max / 2
var distance = Array(repeating: infinity, count: names.count)
var inQueue = Array(repeating: false, count: names.count)
distance[0] = 0
var queue = [0]                                // a head index makes popping O(1)
var head = 0
inQueue[0] = true
var examined = 0
while head < queue.count {
    let u = queue[head]
    head += 1
    inQueue[u] = false
    for (v, weight) in graph[u] {
        examined += 1
        if distance[u] + weight < distance[v] {
            distance[v] = distance[u] + weight
            print("from \(names[u]): \(names[v]) improves to \(distance[v])")
            if !inQueue[v] {                   // already waiting? it will use its new distance anyway
                queue.append(v)
                inQueue[v] = true
            }
        }
    }
}
print(zip(names, distance).map { "\($0) \($1)" }.joined(separator: ", "))
print("edges examined:", examined)
```

```output
from S: A improves to 2
from S: B improves to 5
from A: C improves to 5
from B: A improves to 1
from C: D improves to 6
from A: C improves to 4
from C: D improves to 5
S 0, A 1, B 5, C 4, D 5
edges examined: 7
```

This is the graph from [Bellman–Ford and negative cycles](/dsa/learn/sp-bellman-ford). Bellman–Ford needed 3 rounds of 5 edges, 15 edge checks, to reach the same distances. SPFA examined 7, because it never touched an edge whose start hadn't changed. Notice that A joins the queue a second time, after B → A lowers it to 1, and its edge to C is relaxed again with the better value. That's the price of negative edges: a vertex can be processed more than once.

The queue here is an array with a head index, as in [A queue with a head index](/dsa/learn/queue-head-index). `removeFirst()` would make every pop O(n).

## Fast on average, slow in the worst case

On random graphs and most real ones, each vertex enters the queue only a few times, so SPFA runs in roughly O(E) time, often faster than Dijkstra.

The worst case is a different story. You can think of the queue as a sequence of **phases**: phase 1 is the source, phase 2 is everything it improved, phase 3 is everything those improved, and so on. Each phase processes each vertex at most once and does the job of one Bellman–Ford round, so there are at most V − 1 phases of O(E) work. That gives the bound **O(V · E)**, the same as Bellman–Ford, and graphs exist that reach it. A vertex can be re-queued again and again as a long chain of slightly better paths reaches it one improvement at a time.

Contest problem setters know this. They build grid-shaped graphs with carefully chosen weights that push SPFA to its worst case, and a solution that relies on its average speed times out. The practical rules:

| Weights | Use |
| --- | --- |
| All zero or more | Dijkstra, always: O((V + E) log V) guaranteed |
| Some negative, input not adversarial | SPFA is a fine, fast choice |
| Some negative, worst case must be safe | Bellman–Ford, or SPFA knowing it's O(V · E) at worst |

<Callout kind="warning" title="Heuristics don't fix the worst case">
Variants such as "Small Label First" put a vertex at the front of a deque instead of the back when its distance is smaller than the front's. They often help on typical inputs, but there are graphs that defeat each of them, and some deque variants are even exponentially slow in the worst case. Treat them as tuning, not as a guarantee.
</Callout>

## Detecting negative cycles

With a reachable negative cycle, distances keep falling forever, so the queue **never empties**. SPFA must detect the cycle or it loops forever.

The cleanest check counts edges. Keep `edgesOnPath[v]`, the number of edges in the best path found to `v`: when `u` improves `v`, set `edgesOnPath[v] = edgesOnPath[u] + 1`. A path with V or more edges must repeat a vertex, and it only got recorded because it was cheaper, so it contains a negative cycle.

```swift run
/// SPFA from source. Returns nil when a negative cycle is reachable.
func spfa(vertexCount: Int, edges: [(Int, Int, Int)], source: Int) -> [Int]? {
    var graph: [[(to: Int, weight: Int)]] = Array(repeating: [], count: vertexCount)
    for (a, b, w) in edges {
        graph[a].append((b, w))
    }
    let infinity = Int.max / 2
    var distance = Array(repeating: infinity, count: vertexCount)
    var edgesOnPath = Array(repeating: 0, count: vertexCount)   // edges in the best path found to v
    var inQueue = Array(repeating: false, count: vertexCount)
    distance[source] = 0
    var queue = [source]
    var head = 0
    inQueue[source] = true
    while head < queue.count {
        let u = queue[head]
        head += 1
        inQueue[u] = false
        for (v, weight) in graph[u] where distance[u] + weight < distance[v] {
            distance[v] = distance[u] + weight
            edgesOnPath[v] = edgesOnPath[u] + 1
            if edgesOnPath[v] >= vertexCount {           // V edges means a repeated vertex: a paying loop
                print("path to \(v) now has \(edgesOnPath[v]) edges")
                return nil
            }
            if !inQueue[v] {
                queue.append(v)
                inQueue[v] = true
            }
        }
    }
    return distance
}

print(spfa(vertexCount: 4, edges: [(0, 1, 4), (1, 2, -1), (2, 3, 2), (0, 3, 9)], source: 0) as Any)
print(spfa(vertexCount: 4, edges: [(0, 1, 1), (1, 2, 2), (2, 3, -2), (3, 1, -1)], source: 0) as Any)
```

```output
Optional([0, 4, 3, 5])
path to 1 now has 4 edges
nil
```

The second graph has the loop 1 → 2 → 3 → 1, worth 2 − 2 − 1 = −1. After one trip round it, the path to vertex 1 has 4 edges in a 4-vertex graph, which is impossible without repeating a vertex.

An older version of the check counts how many times each vertex has been **added to the queue** and reports a cycle once any count reaches V. It's also correct, but it can take much longer to trigger: the edge count catches the cycle after about one trip round it.

As with Bellman–Ford, this finds cycles **reachable from the source**. To find one anywhere, start with every vertex in the queue at distance 0.

<Callout kind="gotcha" title="The classic slips">
- **No cycle check.** With a reachable negative cycle the queue never empties and the program hangs. Always count edges (or enqueues) when weights can be negative.
- **Forgetting to clear `inQueue[u]` when `u` is popped.** Then `u` can never re-enter the queue after a later improvement, and distances come out wrong.
- **Relying on SPFA's average speed with non-negative weights.** Use Dijkstra: same simplicity, guaranteed bound.
- **`removeFirst()` on the queue.** O(n) per pop. Use a head index or a deque.
</Callout>

## Practice

**Find a profit loop** can be solved with SPFA plus the edge-count check, or with Bellman–Ford; either way, start every vertex in the queue to search the whole graph.
