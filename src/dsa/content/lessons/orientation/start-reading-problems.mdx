## Why it matters

A problem statement tells you far more than *what* to compute. The **constraints**, the small print about input sizes and values, quietly tell you how fast your solution must be, and often hint at which technique to use. Learning to read them is like getting a clue with every problem.

## The parts of a problem statement

Almost every problem has the same four parts:

1. **The task**: what to compute.
2. **Examples**: inputs with their expected outputs, often with an explanation.
3. **Constraints**: the limits, such as `1 ≤ n ≤ 100,000` or `-10⁹ ≤ nums[i] ≤ 10⁹`.
4. **Follow-ups** (sometimes): "Can you do it in O(1) extra space?"

Read all four before writing anything. Then restate the task in one sentence of your own.

## Questions to ask every time

- **Can the input be empty?** What should happen then?
- **Can values be negative, zero or repeated?**
- **Is the input sorted?** Sorted input almost always means a faster solution exists.
- **How big can the numbers get?** Large values can **overflow** an `Int` when added or multiplied.
- **What exactly should be returned?** An index or a value? The first match or any match?

<Callout kind="gotcha" title="Swift gotcha: overflow crashes">
In many languages, an integer that gets too big silently wraps around to a wrong value. In Swift, it **crashes your program**. That's safer, but it means you must notice when a sum could exceed `Int.max` (about 9.2 × 10¹⁸). You'll learn the overflow operators in Part I.
</Callout>

## Constraints tell you the target speed

A typical judge allows about **100 million simple operations per second**. Compare that with the input size and you know roughly how fast your algorithm must be, before you've designed it:

| If n is at most… | Aim for | Typical techniques |
| --- | --- | --- |
| 10 | O(n!) | try every ordering |
| 20 | O(2ⁿ) | try every subset, backtracking |
| 500 | O(n³) | three nested loops, some DP |
| 5,000 | O(n²) | two nested loops |
| 1,000,000 | O(n log n) or O(n) | sorting, one pass, hashing, two pointers |
| 10⁹ or more | O(log n) or O(1) | binary search, maths |

So if a problem says `n ≤ 100,000`, two nested loops (10 billion steps) are too slow, and you should be looking for something like O(n log n).

## Edge cases checklist

Keep this list in mind for every problem, and test each item that applies:

- Empty input · one element · two elements
- All elements the same · already sorted · sorted in reverse
- Negative numbers and zero · the largest and smallest allowed values
- Duplicates · no valid answer exists
