## Why it matters

Every practice problem in this course has **tests** waiting for you in a real Swift package. You write a solution, run one command, and the tests tell you whether it works, including on the tricky edge cases you didn't think of. That fast, honest feedback loop is how professionals work, and it beats eyeballing your own code.

## Where it lives

The package is the `dsa-swift` folder in this portfolio's repository. Open it in Terminal:

```bash
cd dsa-swift
swift build
```

The first build takes a minute. After that it only rebuilds what changed.

## What's inside

```text title="dsa-swift/"
Package.swift          the package description
Sources/
  DSAKit/              data structures you'll build during the course
  Exercises/           ← you write your solutions here
  Solutions/           reference solutions (peek only after trying!)
Tests/
  DSATests/            tests that check your Exercises
Examples/              every runnable code example from the lessons
```

Each problem is a small Swift `enum` with a `static` function, so problems never clash with each other. Here's the exercise for this lesson's problem, exactly as you'll find it in `Sources/Exercises/orientation/HelloSwift.swift`:

```swift title="Sources/Exercises/orientation/HelloSwift.swift"
public enum HelloSwift {
    /// Returns "Hello, <name>!", or "Hello, world!" when the name is empty.
    public static func greet(_ name: String) -> String {
        // Write your solution here, then run:
        // swift test --filter HelloSwiftTests
        return ""
    }
}
```

It compiles, but it returns an empty string, so its tests fail. That's on purpose: your job is to make them pass.

## The loop: edit, test, repeat

```bash
swift test --filter HelloSwiftTests
```

Before you've written anything, you'll see failures like this:

```output
✘ Test "Greets a name" recorded an issue at HelloSwiftTests.swift:11:9:
  Expectation failed: HelloSwift.greet("Maneet") == "Hello, Maneet!"
    HelloSwift.greet("Maneet") == "Hello, Maneet!" → false
      HelloSwift.greet("Maneet") → ""
✘ Suite HelloSwiftTests failed after 0.001 seconds with 3 issues.
```

Read it carefully: it shows the check that failed, what was expected (`"Hello, Maneet!"`) and, on the last line, what your code actually returned (`""`). Fix the code, run the command again, and repeat until you see:

```output
✔ Suite HelloSwiftTests passed after 0.001 seconds.
```

<Callout kind="tip">
`--filter` runs only the tests whose name matches, so you don't wait for the whole course's tests. Every problem page shows its exact command with a Copy button.
</Callout>

## Running lesson examples

Every runnable example in the lessons is also a file in `dsa-swift/Examples`. When a code block has a **Run command** button, it copies a command like this one. Run it from the `dsa-swift` folder:

```bash
swift Examples/orientation/start-problem-solving-1.swift
```

```output
Largest of [3, 9, 4] is 9
Largest of [-5, -2, -8] is -2
[] is empty
```

The output always matches the lesson: every example is run and checked before it's published.

## The rules of the reference solutions

`Sources/Solutions` holds a checked solution for every problem. All of them pass the same tests, verified with `swift test -Xswiftc -DSOLUTIONS`. Use them well:

1. **Try first.** Give a problem a real attempt, at least 20–25 minutes of honest effort, before looking.
2. **Use the hints** on the problem page before the solution. Each one gives a little more away.
3. **After looking, close it and rewrite it yourself.** Then log it as "Solved with help": the review queue will bring it back so you prove you can do it alone.

<Callout kind="gotcha" title="Swift gotcha: debug builds are slow">
`swift test` and `swift run` build in **debug** mode, which can be 10–100× slower than release for algorithm-heavy code. That's fine for correctness. When you measure speed later in the course, you'll use `swift run -c release`.
</Callout>
