## Why it matters

How far is a list from sorted? How much do two people's rankings of the same films disagree? How many players who joined after you have a lower score? All three are questions about **inversions**: pairs of positions `i < j` whose values are out of order. [Counting inversions](/dsa/learn/sort-inversions) in M31 counted them during merge sort. A Fenwick tree gives a second method that's often simpler, works while the items are still arriving, and answers the per-item version, "how many smaller items come after this one?", which is a favourite interview question.

## Inversions as prefix counts

Read the items left to right and keep a Fenwick tree of **counts by value**: slot v holds how many of the items seen so far equal v. When the next item x arrives:

- the number of earlier items is its index;
- the number of earlier items that are **at most** x is the prefix count up to x;
- so the number of earlier items **greater** than x, the inversions x completes, is the difference.

Add that to a running total, then record x by adding 1 at slot x. Each item costs one query and one update: **O(n log V)** for values from 1 to V.

## Coordinate compression

Values aren't usually 1, 2, 3. They can be negative, or as large as 10⁹, and a Fenwick tree with a slot per possible value would be enormous. But inversions only care about **comparisons**: whether one value is bigger than another, never by how much. So replace each value by its **rank** among the distinct values: the smallest becomes 1, the next 2, and so on. Order is preserved, equal values get equal ranks, and the ranks run from 1 to at most n. This is **coordinate compression**, and M62 gives it a lesson of its own.

To compress: sort the distinct values, then find each value's position with a lower-bound binary search, as in [Lower bound, upper bound, first and last occurrence](/dsa/learn/bs-bounds), or with a dictionary from value to rank. Both are O(n log n) overall.

```swift run
// Count inversions by scanning left to right with a Fenwick tree of value counts
struct Fenwick {
    private var tree: [Int]
    init(count: Int) { tree = Array(repeating: 0, count: count + 1) }

    mutating func add(_ delta: Int, at position: Int) {     // positions count from 1
        var i = position
        while i < tree.count {
            tree[i] += delta
            i += i & -i
        }
    }

    func prefixSum(_ position: Int) -> Int {                 // positions 1...position
        var i = position, total = 0
        while i > 0 {
            total += tree[i]
            i -= i & -i
        }
        return total
    }
}

// Coordinate compression: each value becomes its rank among the distinct values, counting from 1
func ranks(_ items: [Int]) -> [Int] {
    let distinct = Array(Set(items)).sorted()
    return items.map { value in
        var low = 0, high = distinct.count                   // lower bound: the first slot holding >= value
        while low < high {
            let mid = (low + high) / 2
            if distinct[mid] < value { low = mid + 1 } else { high = mid }
        }
        return low + 1
    }
}

func inversions(_ items: [Int]) -> Int {
    let rank = ranks(items)
    var seen = Fenwick(count: items.count)                   // seen counts the earlier items by rank
    var total = 0
    for (index, r) in rank.enumerated() {
        total += index - seen.prefixSum(r)                   // earlier items, minus those that are <= this one
        seen.add(1, at: r)
    }
    return total
}

let prices = [1_000_000_007, -3, 42, 42, 7, -3]
print(ranks(prices))
print(inversions(prices))

// Compare with checking every pair, on 500 small arrays
var state: UInt64 = 31
func next(_ limit: Int) -> Int {
    state = state &* 6364136223846793005 &+ 1442695040888963407
    return Int((state >> 33) % UInt64(limit))
}
var mismatches = 0
for _ in 0..<500 {
    let items = (0..<next(12)).map { _ in next(9) - 4 }
    var pairs = 0
    for i in items.indices {
        for j in items.indices where i < j && items[i] > items[j] { pairs += 1 }
    }
    if inversions(items) != pairs { mismatches += 1 }
}
print("mismatches:", mismatches)
```

```output
[4, 1, 3, 3, 2, 1]
10
mismatches: 0
```

What to notice:

- 1,000,000,007 and −3 become ranks 4 and 1. The tree needs only n slots, whatever the values are.
- The two 42s share rank 3, and neither counts against the other: `prefixSum(r)` includes equal values, so "greater" means strictly greater. That's the usual definition of an inversion.
- The check against every pair runs on 500 random arrays with lots of repeated values, which is where tie-handling mistakes hide.

## Smaller numbers after each item

The per-item question turns the scan around. For each item, how many items **to its right** are strictly smaller? Scan from right to left, so that the tree holds exactly the items after the current one. The answer for an item of rank r is the count of ranks 1 to r − 1. Then add the item and move left.

```swift run
// For each item, how many later items are smaller: scan right to left
struct Fenwick {
    private var tree: [Int]
    init(count: Int) { tree = Array(repeating: 0, count: count + 1) }

    mutating func add(_ delta: Int, at position: Int) {
        var i = position
        while i < tree.count {
            tree[i] += delta
            i += i & -i
        }
    }

    func prefixSum(_ position: Int) -> Int {
        var i = position, total = 0
        while i > 0 {
            total += tree[i]
            i -= i & -i
        }
        return total
    }
}

func smallerAfter(_ items: [Int]) -> [Int] {
    let distinct = Array(Set(items)).sorted()
    var rankOf: [Int: Int] = [:]
    for (offset, value) in distinct.enumerated() {
        rankOf[value] = offset + 1
    }
    var later = Fenwick(count: distinct.count)               // counts of the items to the right, by rank
    var result = Array(repeating: 0, count: items.count)
    for index in stride(from: items.count - 1, through: 0, by: -1) {
        let rank = rankOf[items[index]]!
        result[index] = later.prefixSum(rank - 1)            // strictly smaller: ranks 1...rank - 1
        later.add(1, at: rank)
    }
    return result
}

let counts = smallerAfter([7, 3, 9, 3, 1, 8])
print(counts, counts.reduce(0, +))
print(smallerAfter([]), smallerAfter([4, 4, 4]), smallerAfter([-5, -10, 20]))
```

```output
[3, 1, 3, 1, 0, 0] 8
[] [0, 0, 0] [1, 0, 0]
```

The per-item counts add up to 8, the number of inversions of `[7, 3, 9, 3, 1, 8]`: every inversion is counted exactly once, at its left item. This version compresses with a dictionary instead of a binary search; either works.

### Which bound, which direction

Every variant is the same loop with two choices:

| Question | Scan | Query for an item of rank r |
| --- | --- | --- |
| Earlier items greater than this one | left to right | `index − prefix(r)` |
| Earlier items smaller than this one | left to right | `prefix(r − 1)` |
| Later items smaller than this one | right to left | `prefix(r − 1)` |
| Later items at most this one | right to left | `prefix(r)` |

Getting `r` versus `r − 1` right is the whole difficulty. Decide whether equal values count, then check with an array full of duplicates.

## Merge sort or Fenwick tree?

| | Merge sort (M31) | Fenwick tree |
| --- | --- | --- |
| Time | O(n log n) | O(n log n), including compression |
| Extra memory | O(n) | O(n) |
| Per-item counts | possible, but fiddly (track original positions) | natural |
| Items arriving one at a time | needs the whole array | each new item is one query and one update |
| Also gives | the sorted array | a structure you can keep querying |

For a one-off total, both are fine. When items stream in and you need the inversion count after each one, or when you need per-item answers, the Fenwick tree is the easier tool.

<Callout kind="gotcha" title="Common mistakes">
- **Compressing to ranks from 0.** A Fenwick tree position must be at least 1. Rank from 1, or add 1 when you index the tree.
- **Using the value as the position.** With values up to 10⁹, or negative ones, you'd need a giant array or crash on a negative index. Compress first.
- **Off by one on ties.** For strictly smaller, query `rank − 1`; for at most, `rank`. An all-equal array has no inversions and every "strictly smaller" count is 0.
- **The answer's size.** n = 100,000 items can have nearly 5 × 10⁹ inversions. Swift's `Int` is 64 bits, so it's fine, but don't store the total in an `Int32`.
</Callout>

## Practice

**Disorder after each arrival** reports the inversion count after every new item, on 100,000 items with values anywhere in the `Int` range: the left-to-right scan, with compression and a running total. **Subarray sums in a band** counts pairs of prefix sums that differ by an amount within given bounds: the same left-to-right scan over compressed prefix sums, with two prefix queries per step instead of one.
