## Why it matters

A game shows "you're ranked 1,204th" as scores keep changing. A monitoring dashboard shows the median response time over the requests still in a window. A ticket system hands out the kth cheapest seat that's still free. These are **order statistics** on a collection that changes: the kth smallest value, and the rank of a value. Swift's standard library has no sorted multiset, and a sorted array costs O(n) per insertion. A Fenwick tree of **counts by value** answers both questions in O(log n), with one extra trick: a walk down the tree's powers of two called **binary lifting**.

## Counts by value

If the values are small integers, say scores from 1 to 1,000,000, keep a Fenwick tree where position v holds **how many times v is in the collection**. Then:

- **insert** v: add 1 at v;
- **remove** one copy of v: add −1 at v;
- **how many values are at most x?** `prefixSum(x)`, so the **rank** of x, its position in sorted order counting from 1, is `prefixSum(x − 1) + 1`;
- **the kth smallest value**: the smallest v with `prefixSum(v) ≥ k`.

The first three are the loops from [Point update and prefix query](/dsa/learn/bit-point-update). The last one is a search. Prefix sums of counts never decrease, because counts are never negative, so a binary search over v works: O(log n) steps, each an O(log n) prefix sum, **O(log² n)** in total. That's fine, but the tree's structure allows something better.

## Binary lifting: O(log n)

Build the answer one bit at a time, from the highest power of two down. Keep `position`, the largest value known to have **fewer than k** values at or below it, starting at 0, and `remaining`, how many more values still need to be passed.

At each step, with `step` a power of two, look at slot `position + step`. Here's the key fact: `position` is made only of bits **larger** than `step` (it's a sum of the bigger steps already taken), so `position + step` has `step` as its lowest set bit. Its slot therefore covers exactly the values `position + 1` through `position + step`, the next `step` values after `position`. One lookup tells you how many items they hold:

- **fewer than `remaining`**: the kth value is beyond them. Jump: `position += step`, and subtract their count from `remaining`;
- **at least `remaining`**: the kth value is among them. Stay, and try half the step.

When the steps run out, `position` is the largest value whose prefix count is below k, so the answer is `position + 1`. Each step is one array lookup, and there are about log₂ n steps: **O(log n)**, with no prefix-sum calls at all.

```swift run
// A multiset of small integers: counts by value in a Fenwick tree, kth smallest by binary lifting
struct ScoreBag {
    private var tree: [Int]                       // tree[v] covers the counts of values v - lowbit(v) + 1 ... v
    private(set) var count = 0                    // how many scores are in the bag

    init(maxScore: Int) {
        tree = Array(repeating: 0, count: maxScore + 1)
    }

    mutating func insert(_ score: Int) {
        change(score, by: 1)
        count += 1
    }

    mutating func remove(_ score: Int) {          // the caller checks the score is in the bag
        change(score, by: -1)
        count -= 1
    }

    private mutating func change(_ score: Int, by delta: Int) {
        var i = score
        while i < tree.count {
            tree[i] += delta
            i += i & -i
        }
    }

    /// How many scores are at most `score`.
    func countAtMost(_ score: Int) -> Int {
        var i = score, total = 0
        while i > 0 {
            total += tree[i]
            i -= i & -i
        }
        return total
    }

    /// The kth smallest score, counting from 1. Requires 1 <= k <= count.
    func kthSmallest(_ k: Int, showingSteps: Bool = false) -> Int {
        var position = 0                          // every value up to here holds fewer than k scores
        var remaining = k                         // how many more scores we still need to pass
        var step = 1
        while step * 2 < tree.count { step *= 2 }  // the largest power of two that fits
        while step > 0 {
            let next = position + step
            if next < tree.count && tree[next] < remaining {
                position = next                   // values position+1...next hold too few: skip them all
                remaining -= tree[next]
                if showingSteps { print("  jump to \(position), still need \(remaining)") }
            } else if showingSteps {
                print("  stay at \(position): values \(position + 1)...\(min(next, tree.count - 1)) are enough")
            }
            step /= 2
        }
        return position + 1                       // the first value where the running count reaches k
    }
}

var bag = ScoreBag(maxScore: 10)
for score in [4, 7, 7, 2, 9] {
    bag.insert(score)
}
print((1...bag.count).map { bag.kthSmallest($0) })
print("the 4th smallest, step by step:")
print(bag.kthSmallest(4, showingSteps: true))
bag.remove(7)
bag.insert(1)
print((1...bag.count).map { bag.kthSmallest($0) }, "median:", bag.kthSmallest((bag.count + 1) / 2))
print("scores at most 5:", bag.countAtMost(5))
```

```output
the 4th smallest, step by step:
  stay at 0: values 1...8 are enough
  jump to 4, still need 2
  jump to 6, still need 2
  stay at 6: values 7...7 are enough
7
[1, 2, 4, 7, 9] median: 4
scores at most 5: 3
```

Follow the walk for the 4th smallest of `[2, 4, 7, 7, 9]`:

- Step 8: slot 8 covers values 1–8, which hold 4 scores. That's enough, so the answer is at most 8. Stay.
- Step 4: slot 4 covers 1–4, holding 2 scores (2 and 4). Not enough: jump to 4, and 2 more are needed.
- Step 2: slot 6 covers 5–6, holding none. Jump to 6, still needing 2.
- Step 1: slot 7 covers 7–7, holding 2. Enough. Stay.

The answer is 6 + 1 = 7. Every slot the walk reads covers exactly the next block of values, which is why no prefix sum is ever recomputed.

## When values are large: compress, or know them in advance

The tree needs a position for every possible value, which is fine for values up to a few million. For values up to 10⁹, or arbitrary values:

- **If all the values are known in advance** (an offline problem, where you can read every operation first), compress them to ranks 1…m, as in [Inversions and count of smaller numbers after self](/dsa/learn/bit-inversions), and keep the counts by rank. The kth smallest rank maps back to its value through the sorted list of distinct values.
- **If they aren't**, a balanced search tree that tracks subtree sizes does the job online, or a segment tree that creates nodes only when they're needed. Both are more code.

## DSAKit's `lowerBound(prefix:)`

DSAKit's `FenwickTree` has this walk built in, with its 0-indexed positions. With counts stored at position v for each value v in `0..<count`:

```swift
import DSAKit

var counts = FenwickTree(count: 11)          // values 0...10
for score in [4, 7, 7, 2, 9] {
    counts.add(1, at: score)
}
counts.lowerBound(prefix: 1)                 // 2: the smallest score
counts.lowerBound(prefix: 4)                 // 7: the 4th smallest
counts.lowerBound(prefix: 6)                 // 11: there aren't 6 scores, so it returns count
counts.prefixSum(upTo: 7) + 1                // 3: the rank of 7 among the scores
```

`lowerBound(prefix: k)` is the smallest position whose prefix sum reaches k. It requires every element to be non-negative, which counts always are.

<Callout kind="gotcha" title="Common mistakes">
- **Starting the step too small.** The first step must be the largest power of two that fits in the tree. Start smaller and the walk can never reach the high values.
- **Comparing with `<=` instead of `<`.** Jump only while the block holds **fewer** than `remaining`. With `<=`, a block holding exactly the number still needed is skipped, and the answer comes out one block too far.
- **Forgetting the + 1.** The walk ends on the last value with too few; the kth smallest is the next one.
- **Removing a value that isn't there.** The count goes negative, prefix sums stop being monotonic, and the walk gives nonsense. Check the count first, or keep a separate count per value.
- **k out of range.** Asking for the 6th smallest of 5 values walks off the end. Check `1 <= k <= count` before searching.
</Callout>
