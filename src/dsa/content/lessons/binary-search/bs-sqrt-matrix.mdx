## Why it matters

This lesson shows binary search escaping the plain sorted array in two directions. First, it searches a range of **numbers** instead of an array: the integer square root, which turns up in geometry, prime checks and perfect-square tests, is found by searching the possible answers. Second, it searches a **grid** that's secretly a sorted list, like seats numbered row by row or a table of results laid out in pages. Both come down to the same move: describe your search space as positions 0 to n − 1 with a monotonic yes/no question, and the template from the last lessons does the rest.

## Integer square root

The integer square root of x is the largest whole number r with r × r ≤ x. For 17 it's 4, because 4 × 4 = 16 ≤ 17 but 5 × 5 = 25 > 17.

There's no array here, but there is a sorted list of candidates: the numbers 0, 1, 2, …, x. Ask each one "is your square at most x?":

| r | 0 | 1 | 2 | 3 | 4 | 5 | 6 | … | 17 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| r × r ≤ 17? | yes | yes | yes | yes | yes | no | no | … | no |

Yes, yes, …, no, no: monotonic, because squares grow as r grows. The answer is the **last yes**. A closed search can find it by remembering the best yes so far:

```swift run
func floorRoot(_ x: Int) -> Int {
    var low = 0
    var high = x
    var best = 0
    while low <= high {
        let mid = low + (high - low) / 2
        if mid * mid <= x {
            best = mid             // mid works: remember it and try bigger
            low = mid + 1
        } else {
            high = mid - 1         // mid is too big
        }
    }
    return best
}

for x in [0, 1, 15, 16, 17, 1_000_000, 2_000_000_000] {
    print("floorRoot(\(x)) = \(floorRoot(x))")
}
```

```output
floorRoot(0) = 0
floorRoot(1) = 1
floorRoot(15) = 3
floorRoot(16) = 4
floorRoot(17) = 4
floorRoot(1000000) = 1000
floorRoot(2000000000) = 44721
```

The candidates go up to x, so this takes about log₂ x passes: 31 for two billion. Counting up from 1 until the square is too big would take 44,721 passes, and for x near `Int.max`, about three billion.

Searching a range of possible answers like this is a whole technique of its own. M29, [Binary search on the answer](/dsa/learn/bsa-idea), is built on it.

## The overflow trap

That version has a bug for large x. Try `Int.max`:

```swift
print(floorRoot(Int.max))
```

```text title="What you'll see"
Swift runtime failure: arithmetic overflow
```

The first middle is about 4.6 × 10¹⁸, and squaring it gives something like 2 × 10³⁷, far beyond `Int.max`. Swift traps, exactly as [Floor and ceiling division, and overflow](/dsa/learn/math-floor-ceil-overflow) warned for square-root loops.

The fix is to compare without multiplying. For positive whole numbers, `mid <= x / mid` is true exactly when `mid * mid <= x`. Here's why: `x / mid` is x divided by mid, rounded down. A whole number like mid is at most a rounded-down value exactly when it's at most the unrounded one, and `mid ≤ x ÷ mid` means the same as `mid × mid ≤ x`. Division can't overflow, so the comparison is always safe. It mustn't divide by zero, though, so start `low` at 1 and handle 0 and 1 first:

```swift run
func floorRoot(_ x: Int) -> Int {
    if x < 2 {
        return x                   // 0 and 1 are their own roots
    }
    var low = 1
    var high = x / 2               // for x ≥ 2, the root is at most x / 2
    var passes = 0
    while low <= high {
        passes += 1
        let mid = low + (high - low) / 2
        if mid <= x / mid {
            low = mid + 1          // mid × mid ≤ x
        } else {
            high = mid - 1         // mid × mid > x
        }
    }
    print("  \(passes) passes")
    return high                    // the last value that passed
}

print(floorRoot(17))
print(floorRoot(1_000_000_000_000_000_000))
print(floorRoot(Int.max))
```

```output
  3 passes
4
  59 passes
1000000000
  62 passes
3037000499
```

This version doesn't need `best`: when the loop ends, `high` has dropped one below `low`, and every value above `high` failed while `high` itself passed. That's the closed-range invariant at work. Sixty-two passes cover every `Int`.

<Callout kind="gotcha" title="Why not use Double?">
`Int(Double(x).squareRoot())` is shorter, and it's right for small numbers. But a `Double` holds only about 16 significant digits, as [Double, Float and floating-point precision](/dsa/learn/swift-floating-point) explained, so a large `Int` gets rounded on the way in:

```swift run
let x = 999_999_999_999_999_999
let viaDouble = Int(Double(x).squareRoot())
print(viaDouble, viaDouble * viaDouble <= x)
```

```output
1000000000 false
```

`Double(x)` rounds up to exactly 10¹⁸, whose square root is exactly 10⁹, one too many. The integer search is exact for every input.
</Callout>

## A sorted grid is a sorted list

Now the grid. In this one, each row is sorted, and each row starts with a value bigger than the end of the row before:

```text
       col 0  col 1  col 2  col 3
row 0      2      4      7     11
row 1     14     18     21     25
row 2     30     33     41     49
```

Read it row by row, the row-major order from [Row-major, column-major, diagonal and snake traversals](/dsa/learn/matrix-traversals), and you get one sorted list of 12 values: 2, 4, 7, 11, 14, … 49. So number the cells 0 to 11 in that order and binary search the numbers. You never build the list. Position i lives at:

- row `i / columns`;
- column `i % columns`.

Position 6, with 4 columns, is row 6 / 4 = 1, column 6 % 4 = 2: the 21.

```swift run
func contains(_ target: Int, in grid: [[Int]]) -> Bool {
    guard let firstRow = grid.first, !firstRow.isEmpty else { return false }
    let columns = firstRow.count
    var low = 0
    var high = grid.count * columns - 1            // positions in row-major order
    while low <= high {
        let mid = low + (high - low) / 2
        let value = grid[mid / columns][mid % columns]
        print("  position \(mid) is row \(mid / columns), column \(mid % columns): \(value)")
        if value == target {
            return true
        } else if value < target {
            low = mid + 1
        } else {
            high = mid - 1
        }
    }
    return false
}

let grid = [
    [2, 4, 7, 11],
    [14, 18, 21, 25],
    [30, 33, 41, 49],
]
print(contains(21, in: grid))
print(contains(26, in: grid))
```

```output
  position 5 is row 1, column 1: 18
  position 8 is row 2, column 0: 30
  position 6 is row 1, column 2: 21
true
  position 5 is row 1, column 1: 18
  position 8 is row 2, column 0: 30
  position 6 is row 1, column 2: 21
  position 7 is row 1, column 3: 25
false
```

For a grid of m rows and n columns, that's O(log(m × n)), which is the same as O(log m + log n). A million cells take about 20 looks.

An equally good alternative is two searches: first find the row (the last row whose first value is at most the target), then search inside it. It's the same complexity with a little more code. The virtual list is worth knowing because the trick, "number the things and map each number back", works far beyond grids.

## Grids that are only sorted by row and by column

Be careful which grid you have. [Staircase search in a sorted matrix](/dsa/learn/matrix-staircase-search) worked on a grid where every row **and** every column is sorted, but rows don't continue from one another:

```text
 1   4   7  11
 2   5   8  12
 3   6   9  16
```

Read row by row, that's 1, 4, 7, 11, 2, …: not sorted, so the virtual-list search gives wrong answers. Each kind of grid has its own best method:

| The grid promises | Example | Best method | Time |
| --- | --- | --- | --- |
| each row starts after the previous one ends | the grid in this lesson | binary search as one list | O(log(m × n)) |
| every row and every column is sorted | the staircase grid | staircase from a corner | O(m + n) |
| only each row is sorted | rows of a timetable | binary search each row | O(m × log n) |

The first promise is the strongest, and the fastest search uses all of it. Read a problem's guarantee carefully before choosing.

## Practice

**Integer square root** asks for exactly this lesson's search: no `Double`, no `sqrt`, and no overflow, even for `Int.max`. **Search a fully sorted grid** returns the row and column of a target. Its large tests use grids 100,000 rows tall and 100,000 columns wide, where the staircase method, at O(m + n) per search, is far too slow.
