## Why it matters

Depth-first search gives a second way to sort a DAG, and it's a surprisingly small change to the DFS you wrote in [DFS, recursive and iterative](/dsa/learn/gt-dfs): record each vertex when its call **finishes**, then reverse the list. Add a third colour to the visited marks and the same search finds cycles, and can tell you exactly which vertices form one, which Kahn's algorithm can't. The finishing-order idea comes back in M47, where it's the first half of finding strongly connected components. It also carries a Swift-specific trap: recursion as deep as the longest path, which crashes inside tests long before your machine runs out of memory.

## Finishing order

When DFS visits a vertex, it doesn't return until it has visited everything reachable from it. So a vertex **finishes** only after every vertex it leads to has finished. Record vertices in the order they finish (post-order, as in [Preorder, inorder and postorder](/dsa/learn/trav-dfs-recursive)), and every vertex appears **after** all the vertices it points to. Reverse that list, and every vertex appears **before** them: a topological order.

Why does it hold for every edge `u → v`? When DFS examines that edge, u is in progress, and v is in one of three states:

- **Not yet visited.** DFS visits v now, inside u's call, so v finishes before u.
- **Already finished.** Then v finished before u, trivially.
- **In progress.** Then v is on the current chain of calls, so there's a path from v down to u, and the edge u → v closes a cycle. In a DAG that can't happen.

In every case allowed by a DAG, v finishes before u, so after reversing, u comes before v.

## In Swift

```swift run
let clothes = ["shirt", "tie", "jacket", "trousers", "belt", "shoes", "socks"]
let after: [String: [String]] = [
    "shirt": ["belt", "tie"], "tie": ["jacket"], "trousers": ["belt", "shoes"],
    "belt": ["jacket"], "socks": ["shoes"],
]

var visited: Set<String> = []
var finished: [String] = []

func visit(_ vertex: String) {
    visited.insert(vertex)
    for next in after[vertex, default: []] where !visited.contains(next) {
        visit(next)
    }
    finished.append(vertex)                     // everything it leads to has finished
}

for vertex in clothes where !visited.contains(vertex) {
    visit(vertex)                               // restart from every vertex not yet reached
}
print("finishing order:", finished)
print("topological order:", finished.reversed().joined(separator: " → "))
```

```output
finishing order: ["jacket", "belt", "tie", "shirt", "shoes", "trousers", "socks"]
topological order: socks → trousers → shoes → shirt → tie → belt → jacket
```

What to notice:

- **The outer loop matters.** Starting from shirt reaches belt, jacket and tie, but never trousers or socks. Restarting from every unvisited vertex covers the whole graph.
- **Jacket finishes first**, because it leads nowhere; socks finish last, because they were the last start. Reversed, socks come first.
- **The order differs from Kahn's** (shirt → trousers → socks → tie → belt → shoes → jacket), and both are valid. Check: in each, every item comes before the items that need it.
- `for … where !visited.contains(next)` checks the condition as it reaches each neighbour, so a neighbour visited during an earlier recursive call is skipped.

## Three colours for cycles

A plain visited flag can't detect cycles. In the dressing graph, when DFS from trousers reaches belt, belt is already visited, and that's fine: belt finished earlier, from shirt. Reaching a visited vertex that's **still in progress** is the problem. So give every vertex one of three colours:

- **white**: not visited yet;
- **grey**: visited, and its call is still running, so it's on the current path;
- **black**: finished.

An edge to a white vertex is explored. An edge to a black vertex is ignored. An edge to a **grey** vertex goes back up the current path: that's a cycle. And because the grey vertices are exactly the current path, you can read the cycle straight off it:

```swift run
enum Colour { case white, grey, black }

// A topological order, or the first cycle found
func dfsOrder(_ vertices: [String], _ after: [String: [String]]) -> (order: [String], cycle: [String]) {
    var colour: [String: Colour] = [:]
    for vertex in vertices {
        colour[vertex] = .white
    }
    var path: [String] = []                       // the grey vertices: the current chain of calls
    var finished: [String] = []
    var cycle: [String] = []

    func visit(_ vertex: String) {
        colour[vertex] = .grey
        path.append(vertex)
        for next in after[vertex, default: []] where cycle.isEmpty {
            switch colour[next]! {
            case .white:
                visit(next)
            case .grey:                           // an edge back into the current path
                cycle = Array(path[path.firstIndex(of: next)!...]) + [next]
            case .black:
                break                             // finished earlier: nothing new down there
            }
        }
        path.removeLast()
        colour[vertex] = .black
        finished.append(vertex)
    }

    for vertex in vertices where colour[vertex] == .white && cycle.isEmpty {
        visit(vertex)
    }
    return cycle.isEmpty ? (finished.reversed(), []) : ([], cycle)
}

let steps = ["fetch", "resolve", "compile", "link", "test", "deploy"]
var rules: [String: [String]] = [
    "fetch": ["resolve"], "resolve": ["compile"], "compile": ["link"],
    "link": ["test"], "test": ["deploy"],
]
print(dfsOrder(steps, rules).order)

rules["test"]!.insert("compile", at: 0)           // now test must also come before compile
print(dfsOrder(steps, rules).cycle.joined(separator: " → "))
```

```output
["fetch", "resolve", "compile", "link", "test", "deploy"]
compile → link → test → compile
```

When DFS reaches test, the path is fetch, resolve, compile, link, test, all grey. Test's first edge leads to compile, which is grey: the cycle is the path from compile onwards, plus compile again. Kahn's algorithm, run on the same rules in the last lesson, could only say that compile, link, test and deploy were stuck. Cycle detection with colours is covered for undirected graphs too in [Cycle detection in undirected and directed graphs](/dsa/learn/gt-cycles).

## The recursion depth caveat

The recursive version's call stack grows with the current path. On a chain of 100,000 vertices, a → b → c → …, the first call doesn't return until it's 100,000 calls deep. As [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) showed, that might survive on the main thread, but Swift Testing runs tests on threads with a much smaller stack, where a few thousand levels can crash the whole test run with an unexpected signal. That's why this course's tests keep chains shorter than 1,000 when a recursive solution is reasonable.

When the graph might be deep, there are two fixes. Use Kahn's algorithm, which has no recursion. Or keep DFS and replace the call stack with your own, as in [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack). Each stack frame needs to remember how far through its neighbour list it has got, so that it can carry on after a "call" returns:

```swift run
// Topological order by DFS with an explicit stack: no recursion, so any depth is fine
func topologicalOrder(_ n: Int, _ after: [[Int]]) -> [Int] {
    var visited = Array(repeating: false, count: n)
    var finished: [Int] = []
    finished.reserveCapacity(n)
    for start in 0..<n where !visited[start] {
        visited[start] = true
        var stack = [(vertex: start, nextIndex: 0)]     // a frame: a vertex and its progress
        while let (vertex, index) = stack.last {
            if index < after[vertex].count {
                stack[stack.count - 1].nextIndex += 1    // next time, try the following neighbour
                let next = after[vertex][index]
                if !visited[next] {
                    visited[next] = true
                    stack.append((vertex: next, nextIndex: 0))   // "call" visit(next)
                }
            } else {
                stack.removeLast()                       // "return": all its neighbours are done
                finished.append(vertex)
            }
        }
    }
    return finished.reversed()
}

// A chain 200,000 long: 0 → 1 → 2 → … → 199,999
let n = 200_000
var after = Array(repeating: [Int](), count: n)
for vertex in 0..<(n - 1) {
    after[vertex].append(vertex + 1)
}
let order = topologicalOrder(n, after)
print(order.count, Array(order.prefix(3)), order.last!)
print(topologicalOrder(4, [[1, 2], [3], [3], []]))
```

```output
200000 [0, 1, 2] 199999
[0, 2, 1, 3]
```

The stack reached 200,000 frames, but they're small tuples in an array on the heap, not function calls, so nothing overflows. Adding grey and black colours to this version works the same way as in the recursive one.

## Kahn's or DFS?

| | Kahn's algorithm | DFS |
| --- | --- | --- |
| Idea | output vertices with in-degree 0 | output vertices in reverse finishing order |
| Needs | in-degrees and a queue | colours and a stack (the call stack, or your own) |
| Detects a cycle by | outputting fewer than V vertices | an edge into a grey vertex |
| Names the cycle | no | yes: it's on the current path |
| Very deep graphs | always safe | recursion depth = longest path; use an explicit stack |
| Also gives | waves of work that can run in parallel; smallest-first order with a heap | a building block for other DFS algorithms |

Both are O(V + E). In interviews, use whichever you can write correctly under pressure, and say out loud how it detects cycles.

<Callout kind="gotcha" title="Common mistakes with DFS topological sort">
- **Recording on entry instead of on finish.** Appending when a vertex is first visited gives preorder: shirt, belt, jacket, tie… puts the jacket before the tie. Append after the loop over neighbours.
- **Forgetting to reverse.** The finishing order is a valid order for the **reversed** edges, so it looks plausible. Check one edge by hand.
- **Two colours for cycle detection.** A visited vertex might be finished (fine) or on the current path (a cycle). Only grey means a cycle.
- **Skipping the outer loop.** DFS from one vertex only reaches what's downstream of it. Restart from every unvisited vertex.
</Callout>
