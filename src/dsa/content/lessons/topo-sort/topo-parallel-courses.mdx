## Why it matters

A topological order says what to do first. Often the real question is **how long** it takes when independent work can happen at the same time. Xcode builds targets that don't depend on each other in parallel; a CI pipeline runs independent jobs side by side; a student takes several courses in one semester. With no limit on how much runs at once, the answer is the number of **waves** Kahn's algorithm makes, which is also the length of the longest chain of dependencies. "Parallel courses" and "minimum semesters" are popular interview questions built on exactly this, and the longest-chain view leads straight into the next lesson.

## Kahn's algorithm, one wave at a time

In ordinary Kahn's algorithm, newly ready vertices join the back of the queue behind the ones already waiting. Change one thing: process **all** the currently ready courses together as one semester, and collect the courses they release into a separate list for the next semester.

```swift run
func semesterPlan(_ courseCount: Int, _ prerequisites: [[Int]]) -> [[Int]]? {
    var unlocks = Array(repeating: [Int](), count: courseCount)
    var waitingOn = Array(repeating: 0, count: courseCount)
    for pair in prerequisites {                      // [before, after]
        unlocks[pair[0]].append(pair[1])
        waitingOn[pair[1]] += 1
    }
    var current = (0..<courseCount).filter { waitingOn[$0] == 0 }
    var plan: [[Int]] = []
    var taken = 0
    while !current.isEmpty {
        plan.append(current)                         // take everything that's ready, together
        taken += current.count
        var next: [Int] = []
        for course in current {
            for after in unlocks[course] {
                waitingOn[after] -= 1
                if waitingOn[after] == 0 {
                    next.append(after)               // ready next semester, not this one
                }
            }
        }
        current = next
    }
    return taken == courseCount ? plan : nil         // nil: a cycle blocks some courses
}

let names = ["Swift", "Maths", "Collections", "Recursion", "Trees", "Graphs", "Capstone"]
let prerequisites = [[0, 2], [0, 3], [1, 3], [2, 4], [3, 4], [4, 5], [1, 5], [5, 6], [2, 6]]
let plan = semesterPlan(names.count, prerequisites)!
for (index, semester) in plan.enumerated() {
    print("semester \(index + 1):", semester.map { names[$0] }.joined(separator: ", "))
}
print(semesterPlan(3, [[0, 1], [1, 2], [2, 1]]) == nil)
```

```output
semester 1: Swift, Maths
semester 2: Collections, Recursion
semester 3: Trees
semester 4: Graphs
semester 5: Capstone
true
```

Five semesters. Swift and Maths wait for nothing. Taking both releases Collections (which only needed Swift) and Recursion (which needed both). Trees needs Collections and Recursion; Graphs needs Trees and Maths; Capstone needs Graphs and Collections. Capstone is released last, in the fifth wave.

The cost is the same as plain Kahn's algorithm, O(V + E): each course is in exactly one wave, and each pair is processed once.

## Why that's the fewest possible

Two facts meet in the middle.

**No plan can beat the longest chain.** Swift → Collections → Trees → Graphs → Capstone is a chain of five courses, each a prerequisite of the next. Each one must be in a later semester than the one before it, so this chain alone needs five semesters, whatever you do with the other courses.

**The waves never use more than the longest chain.** A course joins wave k because the last of its prerequisites to be released was in wave k − 1. That prerequisite joined wave k − 1 because of one of **its** prerequisites in wave k − 2, and so on back to wave 1. Following those links gives a chain of k courses. So if the waves needed k semesters, the longest chain has at least k courses.

Together: the number of waves equals the length of the longest chain, and that's the minimum. Taking every course the moment it's allowed is never a mistake when there's no limit per semester.

## The same answer as a longest path

That last argument suggests a second way to compute it. Define a course's semester as 1 if it has no prerequisites, and otherwise 1 more than the latest semester among its prerequisites. Process the courses in a topological order, so every prerequisite is finished before the course that needs it, and push each course's semester forwards along its edges:

```swift run
let names = ["Swift", "Maths", "Collections", "Recursion", "Trees", "Graphs", "Capstone"]
let prerequisites = [[0, 2], [0, 3], [1, 3], [2, 4], [3, 4], [4, 5], [1, 5], [5, 6], [2, 6]]
var unlocks = Array(repeating: [Int](), count: names.count)
for pair in prerequisites {
    unlocks[pair[0]].append(pair[1])
}

// Every pair goes from a lower label to a higher one, so 0, 1, 2, … is a topological order here.
// In general, get one from Kahn's algorithm first.
var semester = Array(repeating: 1, count: names.count)
for course in names.indices {
    for after in unlocks[course] {
        semester[after] = max(semester[after], semester[course] + 1)
    }
}
for course in names.indices {
    print(names[course], semester[course])
}
print("fewest semesters:", semester.max()!)
```

```output
Swift 1
Maths 1
Collections 2
Recursion 2
Trees 3
Graphs 4
Capstone 5
fewest semesters: 5
```

Same numbers. Each course's semester is the number of courses on the longest chain ending at it, and the answer is the largest of them. This "relax every edge in topological order" pattern is the subject of [Longest and shortest paths in a DAG](/dsa/learn/topo-dag-paths), where the steps get weights: a course that takes three months, or a build step that takes 40 seconds.

## When there's a limit per semester

Real universities cap you at, say, four courses a semester. That small change makes the problem much harder. When more courses are ready than you can take, you must choose, and natural rules such as "take the ones with the most courses depending on them" or "take the ones on the longest remaining chain" fail on some inputs. For an arbitrary limit, no efficient algorithm is known at all. Small cases, with up to about 15 courses, are solved by trying sets of courses with bitmask dynamic programming, which comes in Part VII. If a problem says "any number of courses per semester", enjoy it: the waves are the whole answer.

<Callout kind="gotcha" title="Common mistakes with semesters">
- **Counting edges instead of courses.** A chain of three courses has two edges but needs three semesters. Count waves, starting from 1 for the first.
- **Losing the wave boundaries.** If released courses go onto the end of the list you're working through, you can't tell where one semester ends and the next begins. Collect them in a separate `next` array, or note the list's length at the start of each wave and stop there.
- **Forgetting the impossible case.** If the waves run out before every course is taken, a cycle blocks the rest: return -1 (or `nil`), not the number of waves so far.
- **Assuming a limit doesn't matter.** The waves are only optimal when any number of courses fit in a semester.
</Callout>
