## Why it matters

You're handed a dictionary from a language whose alphabet you don't know, and asked to work out the letter order from the way the words are sorted. It's a favourite hard interview problem because nothing in it says "graph": you have to see that each pair of neighbouring words reveals one fact of the form "this letter comes before that letter", that those facts are the edges of a directed graph, and that the alphabet is a topological order of it. On the way it tests careful string comparison, two separate ways the input can be impossible, and an answer with many correct forms. The same reasoning recovers any hidden order from sorted data, such as the priority order of tags from a sorted list of tickets.

## What a sorted list tells you

Dictionary order compares two words letter by letter, and the **first position where they differ** decides which comes first. If one word runs out before any difference, the shorter word comes first: "rat" before "rate".

So when a glossary lists two words in order, it tells you exactly one thing about the alphabet: at their first difference, the earlier word's letter comes before the later word's letter. Everything after that position tells you nothing, because the first difference already settled the order. And if one word is a prefix of the other, you learn nothing about letters at all.

Here's a glossary sorted under an unknown alphabet, and what each neighbouring pair reveals:

```swift run
let glossary = ["rat", "rate", "re", "tar", "tea", "ear"]
for (earlier, later) in zip(glossary, glossary.dropFirst()) {
    if let (a, b) = zip(earlier, later).first(where: { $0.0 != $0.1 }) {
        print("\(earlier), \(later): \(a) before \(b)")
    } else {
        print("\(earlier), \(later): no information about letters")
    }
}
```

```output
rat, rate: no information about letters
rate, re: a before e
re, tar: r before t
tar, tea: a before e
tea, ear: t before e
```

`zip(glossary, glossary.dropFirst())` pairs each word with the next one, and `zip(earlier, later)` walks two words side by side until the shorter runs out. `first(where:)` stops at the first pair of letters that differ.

Why only **neighbouring** words? If every neighbouring pair is in order under some alphabet, the whole list is sorted under it, because dictionary order is transitive: if w1 comes before w2 and w2 before w3, then w1 comes before w3. So a pair of words further apart can't add a constraint that the neighbouring pairs don't already imply. Comparing all pairs would cost O(n²) comparisons and find nothing new.

## Letters become a graph

Each fact "a before e" is a directed edge `a → e`. The letters are the vertices, and an alphabet consistent with the glossary is a topological order of this graph, exactly as in [Kahn's algorithm](/dsa/learn/topo-kahn).

For the glossary above, the edges are a → e (found twice), r → t and t → e. The letters are r, a, t and e. Three different alphabets fit: r a t e, a r t e and r t a e. All that's known is that r comes before t, and that a and t both come before e.

## Two ways the input can be impossible

**A contradiction.** If one pair says a before b and another says b before a, possibly through a chain of other letters, the letter graph has a cycle and no alphabet fits. Kahn's algorithm reports this the usual way: fewer letters come out than went in.

**A word before its own prefix.** If "tea" is listed before "te", no alphabet can explain it: whatever the letters mean, a word always comes after its own prefix. The pair has no differing letter, so it produces no edge, and a cycle check would never notice. You have to catch it while comparing neighbours: no difference, and the earlier word is longer, means the answer is `""`.

## Letters with no constraints

Every letter that appears in the glossary belongs in the answer, even one that never takes part in an edge. In the glossary above, every letter happened to be constrained; in `["moon"]`, none is. Seed the graph with every letter before adding edges, so unconstrained letters have in-degree 0 and come out like any other ready vertex. Seeding them **in the order they first appear**, in an array, makes the output the same on every run.

## Putting it together

```swift run
func alphabet(_ words: [String]) -> String {
    var letters: [Character] = []                     // every letter, in order of first appearance
    var after: [Character: [Character]] = [:]
    var waitingOn: [Character: Int] = [:]
    for word in words {
        for letter in word where waitingOn[letter] == nil {
            letters.append(letter)
            after[letter] = []
            waitingOn[letter] = 0
        }
    }

    var seen = Set<String>()                          // edges already added, such as "ae"
    for (earlier, later) in zip(words, words.dropFirst()) {
        guard let (a, b) = zip(earlier, later).first(where: { $0.0 != $0.1 }) else {
            if earlier.count > later.count { return "" }   // a longer word before its own prefix
            continue                                       // equal, or a prefix first: no edge
        }
        if seen.insert(String([a, b])).inserted {
            after[a]!.append(b)
            waitingOn[b]! += 1
        }
    }

    var order = letters.filter { waitingOn[$0] == 0 }
    var head = 0
    while head < order.count {
        let letter = order[head]
        head += 1
        for next in after[letter]! {
            waitingOn[next]! -= 1
            if waitingOn[next] == 0 {
                order.append(next)
            }
        }
    }
    return order.count == letters.count ? String(order) : ""   // short: the facts contradict
}

print(alphabet(["rat", "rate", "re", "tar", "tea", "ear"]))
print(alphabet(["ab", "ba", "ac"]).isEmpty)           // a before b, then b before a
print(alphabet(["tea", "te"]).isEmpty)                // a longer word before its prefix
print(alphabet(["moon"]))                             // no facts at all
```

```output
rate
true
true
mon
```

What to notice:

- **The `seen` set stops a repeated fact being added twice.** "a before e" appears twice in the glossary. Adding it twice would still work, since each copy is counted and later released, but with only 26 letters and up to 650 distinct edges, deduplicating keeps the graph small however long the glossary is.
- **`["ab", "ba", "ac"]` is a contradiction**: the first pair says a before b, the second b before a.
- **`["moon"]` returns "mon"**: each letter once, in the order they appear, because nothing constrains them. Any arrangement of m, o and n would be correct.

## Many right answers

For the glossary, the function returned "rate", but "arte" and "rtae" are equally correct. A test that compares with one string would fail correct solutions, so the tests for this lesson's problem check the answer instead: it must contain exactly the letters used, once each, and under it every word must come no later than the next one.

```swift run
func fits(_ alphabet: String, _ words: [String]) -> Bool {
    let used = Set(words.joined())
    guard alphabet.count == used.count, Set(alphabet) == used else { return false }  // each letter once
    var rank: [Character: Int] = [:]
    for (index, letter) in alphabet.enumerated() {
        rank[letter] = index
    }
    for (earlier, later) in zip(words, words.dropFirst()) {
        if let (a, b) = zip(earlier, later).first(where: { $0.0 != $0.1 }) {
            if rank[a]! > rank[b]! { return false }
        } else if earlier.count > later.count {
            return false
        }
    }
    return true
}

let glossary = ["rat", "rate", "re", "tar", "tea", "ear"]
for candidate in ["rate", "arte", "rtae", "tare", "rat"] {
    print(candidate, fits(candidate, glossary))
}
```

```output
rate true
arte true
rtae true
tare false
rat false
```

"tare" puts t before r, but "re" before "tar" says r comes first. "rat" leaves out e. The checker never needs to know which valid answer the solution chose.

## Complexity

Reading the words and comparing neighbours touches each character at most twice: O(C) for C characters in total. The letter graph has at most 26 vertices and, with duplicates removed, at most 26 × 25 = 650 edges, so Kahn's algorithm on it is effectively O(1). The memory beyond the input is O(1) too. For a larger alphabet of k symbols, add O(k + k²).

<Callout kind="gotcha" title="Common mistakes in alien dictionary">
- **An edge for every differing position.** "ab" before "ba" says a before b, and nothing about b and a in the second position. Only the first difference counts; stop there.
- **Missing the prefix case.** "tea" before "te" produces no edge, so the cycle check passes. Check for it explicitly.
- **Dropping unconstrained letters.** Seed every letter that appears, or letters that are never in an edge vanish from the answer.
- **Iterating a set or dictionary of letters.** The answer is still valid, but it changes from run to run, which makes your own debugging and tests confusing. Keep the letters in an array.
- **Comparing every pair of words.** O(n²) comparisons, and nothing learnt beyond the neighbouring pairs.
</Callout>
