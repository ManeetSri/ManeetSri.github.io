## Why it matters

"Can a student finish all these courses, given their prerequisites?" and "In what order should they take them?" are two of the most asked graph questions in interviews, usually back to back. Neither mentions graphs, which is the point: the interviewer wants to see you recognise a dependency graph, ask which way the arrows go, and reach for a topological sort. The same two questions appear wherever there are dependencies: can this package resolve, and in what order do these migrations run? This lesson solves both, and shows how to test an answer when many answers are right.

## Reading the problem

Both problems give you `courseCount` courses labelled 0 to `courseCount - 1` and a list of pairs. The pairs are where mistakes start, because problem setters use both directions:

| The statement says | The edge, as before → after |
| --- | --- |
| "pair `[a, b]`: a must be completed before b" (this course's problems) | a → b |
| "pair `[a, b]`: to take a, you must first take b" (many interview versions) | b → a |
| "b is a prerequisite of a", "a requires b" | b → a |

Read the statement, decide, and convert to your convention before doing anything else. When a problem uses the second format, flip each pair as you read it:

```swift run
// Another common format: [course, prerequisite], meaning "to take course, first take prerequisite"
let given = [[1, 0], [2, 1], [2, 0]]
let pairs = given.map { [$0[1], $0[0]] }          // flipped into [before, after]
print(pairs)
```

```output
[[0, 1], [1, 2], [0, 2]]
```

Get the direction wrong and Kahn's algorithm still runs, still detects cycles correctly (a cycle is a cycle in either direction), but returns the order backwards. So a wrong direction can pass every "can you finish?" test and fail every "what order?" test.

## Course schedule I: can you finish them all?

Every course can be completed exactly when the prerequisite graph has **no cycle**, as [DAGs and dependency ordering](/dsa/learn/topo-dags) showed. So the first question is cycle detection in a directed graph, and either algorithm from the last two lessons answers it. Kahn's algorithm does it without recursion: run it and check whether every course came out.

## Course schedule II: in what order?

The second question wants the order itself, and Kahn's algorithm already builds it. So write one function and get both answers from it:

```swift run
// Each pair is [before, after]: before must be completed first
func studyOrder(_ courseCount: Int, _ prerequisites: [[Int]]) -> [Int]? {
    var unlocks = Array(repeating: [Int](), count: courseCount)
    var waitingOn = Array(repeating: 0, count: courseCount)       // in-degrees
    for pair in prerequisites {
        unlocks[pair[0]].append(pair[1])
        waitingOn[pair[1]] += 1
    }
    var order = (0..<courseCount).filter { waitingOn[$0] == 0 }
    var head = 0
    while head < order.count {
        let course = order[head]
        head += 1
        for next in unlocks[course] {
            waitingOn[next] -= 1
            if waitingOn[next] == 0 {
                order.append(next)
            }
        }
    }
    return order.count == courseCount ? order : nil
}

func canFinish(_ courseCount: Int, _ prerequisites: [[Int]]) -> Bool {
    studyOrder(courseCount, prerequisites) != nil
}

let plans: [(courses: Int, pairs: [[Int]])] = [
    (4, [[0, 1], [0, 2], [1, 3], [2, 3]]),
    (3, [[0, 1], [1, 2], [2, 1]]),
    (3, []),
    (2, [[1, 1]]),
]
for plan in plans {
    print(canFinish(plan.courses, plan.pairs), studyOrder(plan.courses, plan.pairs) ?? [])
}
```

```output
true [0, 1, 2, 3]
false []
true [0, 1, 2]
false []
```

Line by line:

- **A diamond.** 0 unlocks 1 and 2, and 3 needs both. One valid order is 0, 1, 2, 3.
- **A cycle.** 1 and 2 require each other. Course 0 comes out, then nothing is ever ready again.
- **No prerequisites.** Every course has in-degree 0; any order works, and the queue gives 0, 1, 2.
- **A course that requires itself.** `[1, 1]` is a self-loop: course 1 waits for itself forever. Only course 0 comes out.

Interview versions usually want `[]` rather than `nil` when no order exists; `?? []` converts it. Inside your own code, an optional says "no answer" more clearly than an empty array, which could also be the correct order for zero courses.

## Testing when many answers are right

A plan usually has many valid orders, and different correct solutions return different ones: Kahn's with a queue, Kahn's with a stack, DFS. So a test that compares the result with one particular array would fail correct code. Test the **property** instead: every course appears exactly once, and every pair has its `before` ahead of its `after`.

```swift run
func isValidOrder(_ order: [Int], _ courseCount: Int, _ prerequisites: [[Int]]) -> Bool {
    guard order.count == courseCount else { return false }
    var position = Array(repeating: -1, count: courseCount)
    for (index, course) in order.enumerated() {
        guard course >= 0, course < courseCount, position[course] == -1 else { return false }  // in range, once
        position[course] = index
    }
    return prerequisites.allSatisfy { position[$0[0]] < position[$0[1]] }
}

let pairs = [[0, 1], [0, 2], [1, 3], [2, 3]]
print(isValidOrder([0, 1, 2, 3], 4, pairs), isValidOrder([0, 2, 1, 3], 4, pairs))
print(isValidOrder([0, 1, 3, 2], 4, pairs), isValidOrder([0, 1, 1, 3], 4, pairs))
```

```output
true true
false false
```

Both diamond orders pass. `[0, 1, 3, 2]` puts 3 before 2, and `[0, 1, 1, 3]` repeats course 1 and leaves out 2. The tests for this module's problems use exactly this check, on plans of up to 100,000 courses. It's O(n + p), so it's as fast as the solution it checks. This is a good habit for any problem whose statement says "return any valid answer".

## Edge cases worth a test

| Case | Expected |
| --- | --- |
| No prerequisites | can finish; any order of all courses |
| A course requires itself, `[a, a]` | can't finish |
| The same pair twice | no effect, as long as it's counted twice and released twice, which Kahn's algorithm does |
| Several separate groups of courses | every group must appear: start from all courses with in-degree 0, not only one |
| A cycle away from course 0 | still can't finish, even though course 0 is fine |
| Zero courses | can finish; the order is empty |

<Callout kind="gotcha" title="Common mistakes in course schedule">
- **The pairs the wrong way round.** Check the statement's wording and flip if needed. A backwards order passes "can you finish?" tests and fails "what order?" tests.
- **Returning a partial order.** If fewer than `courseCount` courses come out, there's no valid order at all. Return `[]`, not the courses that happened to be free.
- **Recursion on a long chain.** A recursive DFS on 100,000 courses in a single chain overflows the stack inside tests. Kahn's algorithm, or DFS with an explicit stack, is safe at any depth.
- **Comparing with one expected order** in your own tests. Validate the property instead.
</Callout>
