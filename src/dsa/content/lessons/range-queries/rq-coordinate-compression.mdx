## Why it matters

Many fast techniques index an array **by value**: a count per value in Mo's algorithm, a Fenwick tree over values for counting smaller elements, a difference array over positions on a line. They all break when values are huge: you can't allocate an array of a billion counters for 50,000 user ids, or a difference array stretching to timestamp 1,700,000,000. But with only n values, at most n of them are different, and often only their **order** matters, not their size. **Coordinate compression** replaces each value by its rank among the distinct values, 0 to k − 1, so value-indexed arrays need only k slots. It's a two-line preprocessing step that appears in a huge share of competitive programming solutions, usually unannounced.

## Ranks instead of values

To compress a list of values:

1. **Collect** every value that will ever be used as an index.
2. **Sort and dedupe** them. The result, `distinct`, has k values in increasing order.
3. **Map** each value to its position in `distinct`, its **rank**. The smallest value becomes 0, the next 1, and so on.

The ranks keep the order: if a < b then rank(a) < rank(b), and equal values get equal ranks. Anything that only compares values, such as "how many are smaller?", "which is the largest?" or "are these the same?", gives the same answer on the ranks.

```swift run
// Coordinate compression: replace each value by its rank among the distinct values
let ids = [1_000_000_000, 5, 300, 5, 42, 300, -7]

let distinct = Array(Set(ids)).sorted()          // sort and dedupe
print("distinct:", distinct)

/// The index of the first element ≥ target in a sorted array (lower bound)
func lowerBound(_ sorted: [Int], _ target: Int) -> Int {
    var low = 0
    var high = sorted.count
    while low < high {
        let mid = low + (high - low) / 2
        if sorted[mid] < target { low = mid + 1 } else { high = mid }
    }
    return low
}

let byBinarySearch = ids.map { lowerBound(distinct, $0) }
print("ranks (binary search):", byBinarySearch)

var rankOf: [Int: Int] = [:]
for (rank, value) in distinct.enumerated() {
    rankOf[value] = rank
}
let byDictionary = ids.map { rankOf[$0]! }
print("ranks (dictionary):   ", byDictionary)
print("back again:", byDictionary.map { distinct[$0] })
```

```output
distinct: [-7, 5, 42, 300, 1000000000]
ranks (binary search): [4, 1, 3, 1, 2, 3, 0]
ranks (dictionary):    [4, 1, 3, 1, 2, 3, 0]
back again: [1000000000, 5, 300, 5, 42, 300, -7]
```

What to notice:

- Seven values, five of them distinct, so the ranks run from 0 to 4. A billion becomes 4; −7 becomes 0. Negative values are no problem.
- Both 5s become 1, and both 300s become 3: equal values, equal ranks.
- `distinct` is the way back. `distinct[rank]` recovers the original value, so keep it: you'll need it whenever an answer must be reported in real values, or when **distances** matter.

### Binary search or a dictionary?

Both map a value to its rank:

| | Binary search in `distinct` | `Dictionary` from value to rank |
| --- | --- | --- |
| Per lookup | O(log k) | O(1) on average |
| Extra memory | none beyond `distinct` | k entries, with hashing overhead |
| Values not in the list | gives the rank of the next larger value | `nil` |

The dictionary is usually faster for lookups of values you compressed. Binary search has one superpower: it handles values that **weren't** collected. `lowerBound(distinct, x)` is the number of distinct values smaller than x, which is exactly what "count elements below x" queries need, even when x itself never appeared. That's [lower bound](/dsa/learn/bs-bounds) from M28, doing double duty.

`Array(Set(values)).sorted()` is the shortest way to sort and dedupe. Sorting first and dropping neighbours that equal the previous one is equally good and avoids hashing:

```swift
var distinct = values.sorted()
var kept = 0
for value in distinct where kept == 0 || value != distinct[kept - 1] {
    distinct[kept] = value
    kept += 1
}
distinct.removeLast(distinct.count - kept)
```

Either way, compression costs **O(n log n)**, dominated by the sort.

## Compressing a line: coverage with huge coordinates

The second big use is compressing **positions**. Radio transmitters along a motorway each cover a stretch `[start, end)`, with positions in metres up to two billion. What total length is covered by **at least k** transmitters?

A [difference array](/dsa/learn/prefix-difference-array) would solve it: +1 where a stretch starts, −1 where it ends, then a running sum gives the coverage at every position. But that array would have two billion entries. The fix: the coverage can only change at an endpoint. Between two neighbouring endpoints it's constant. So compress the endpoints, put the +1 and −1 on their **ranks**, sweep the ranks, and measure each piece with the **real** coordinates:

```swift run
// Total length covered by at least k half-open intervals [start, end), with huge coordinates
func lengthCovered(atLeast k: Int, _ intervals: [(start: Int, end: Int)]) -> Int {
    // 1. Compress: every endpoint, sorted and deduplicated
    let points = Array(Set(intervals.flatMap { [$0.start, $0.end] })).sorted()
    var rankOf: [Int: Int] = [:]
    for (rank, point) in points.enumerated() { rankOf[point] = rank }

    // 2. A difference array over the compressed points: +1 where an interval starts, -1 where it ends
    var change = [Int](repeating: 0, count: points.count)
    for interval in intervals {
        change[rankOf[interval.start]!] += 1
        change[rankOf[interval.end]!] -= 1
    }

    // 3. Sweep: between points[i] and points[i + 1], the coverage is constant
    var covering = 0
    var total = 0
    for i in points.indices.dropLast() {
        covering += change[i]
        if covering >= k {
            total += points[i + 1] - points[i]        // the real length, from the real coordinates
        }
    }
    return total
}

let broadcasts = [(start: 10, end: 50), (start: 30, end: 1_000_000), (start: 40, end: 60), (start: 999_990, end: 2_000_000_000)]
print(lengthCovered(atLeast: 1, broadcasts))
print(lengthCovered(atLeast: 2, broadcasts))
print(lengthCovered(atLeast: 3, broadcasts))
```

```output
1999999990
40
10
```

Eight endpoints, seven distinct, so the difference array has 7 slots instead of two billion. Each slot stands for the piece from `points[i]` to `points[i + 1]`, and its length is computed from `points`, not from the ranks. Covered twice: 30 to 60 (where the first three stretches overlap in pairs) is 30 metres, and 999,990 to 1,000,000 is 10 more, 40 in all. Covered three times: only 40 to 50.

`points.indices.dropLast()` visits every point except the last, and it's safely empty when there are no intervals at all. Writing `0..<(points.count - 1)` instead traps for an empty input, because `0..<-1` is an invalid range.

The whole thing is **O(n log n)** for n stretches, whatever the coordinates. The same shape, compress, sweep the elementary pieces, measure with real coordinates, computes the area of a union of rectangles, the busiest moment in a calendar with timestamps, and much more.

<Callout kind="analogy" title="Seat numbers instead of street addresses">
Ten guests live at addresses from 3 Oak Lane to 9,842 Main Street. To seat them in address order, you don't need a table with 9,842 chairs. Sort them, give them seats 0 to 9, and keep the guest list so you can still look up where each one lives.
</Callout>

## Compress everything you'll look up

The most common bug: compressing the array's values, and then looking up a **query value** that wasn't among them. A dictionary returns `nil` (and `!` crashes); a careless binary search returns the rank of a different value. Two safe habits:

- **Collect every value first**: array elements, query values, interval endpoints, all into one list, then compress once. Offline problems, where all queries are known up front, make this easy.
- **Or use lower bound for query values**, and think about what its answer means: the number of distinct compressed values smaller than x.

With **closed** integer intervals `[start, end]`, the coverage changes just **after** `end`, so the endpoint to compress is `end + 1`. Mixing closed and half-open intervals is an off-by-one waiting to happen; convert closed ones to half-open at the start.

<Callout kind="gotcha" title="Common mistakes">
- **Measuring with ranks.** After compression, the gap between rank 3 and rank 4 might be one metre or a billion. Lengths, areas and distances come from `distinct`.
- **Forgetting to dedupe.** Without it, two equal values get different ranks, and "how many distinct" or "equal" checks break.
- **Compressing too little.** Every value used as an index must be in the list, including query values.
- **Printing a `Set` to check your work.** Its order changes from run to run; sort it first.
</Callout>

## Practice

**Repeater coverage** is the motorway problem with a twist: it asks for the longest **unbroken** stretch covered by at least k repeaters, with positions up to two billion. **Species on trail segments**, from Mo's algorithm, needs its species ids compressed before they can index a count array.
