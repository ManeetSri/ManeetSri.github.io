## Why it matters

The **AVL tree**, named after Georgy Adelson-Velsky and Evgenii Landis who published it in 1962, was the first binary search tree that keeps itself balanced. However values arrive, its height stays below about 1.44 log2 n, so search, insert and delete are all O(log n) in the worst case, not only on average. It's the most direct answer to the chain problem from the last lesson, its code is short enough to write from memory, and it's what DSAKit's `AVLTree`, `SortedSet` and `SortedMap` are built on. Interviewers like it too: the four rotation cases are a classic whiteboard question.

## Heights and balance factors

An AVL tree is a BST in which every node also knows its **height**: the number of levels in the subtree below it, counting itself. A leaf has height 1, and the empty subtree (`nil`) has height 0. A node's height is one more than its taller child's:

```swift
node.height = 1 + max(height(node.left), height(node.right))
```

Each node stores its height in a property, so reading it is O(1). Computing it from scratch would mean visiting the whole subtree every time.

A node's **balance factor** is the height of its left subtree minus the height of its right subtree:

- **0**: both sides equally tall.
- **+1**: the left side is one level taller (the node leans left).
- **−1**: the right side is one level taller (it leans right).

The **AVL property** says that every node's balance factor is −1, 0 or +1. That's the whole rule. It doesn't say the tree is perfect, only that no node is lopsided by more than one level.

```text
        30 (+1)             30 (+2)  ← breaks the rule
       /    \               /
   20 (0)   40 (0)      20 (+1)
                         /
                      10 (0)
```

The left tree is a valid AVL tree. The right one isn't: 30's left subtree has height 2 and its right subtree height 0.

## Why an AVL tree stays short

The AVL property is local, one node at a time, so it isn't obvious that it keeps the whole tree short. Here's the argument, and it's worth following because it explains the famous 1.44.

Ask the opposite question: what's the **fewest** nodes an AVL tree of height h can have? Call it N(h). A tree of height h has a root, and one subtree of height h − 1 (otherwise the tree wouldn't be h tall). The other subtree may be at most one level shorter: height h − 2. To use as few nodes as possible, both subtrees are themselves as sparse as possible:

N(h) = N(h − 1) + N(h − 2) + 1, with N(0) = 0 and N(1) = 1.

That's the Fibonacci recurrence plus one, so N(h) grows like the Fibonacci numbers: by a factor of about 1.618, the golden ratio, per level. Compare it with the most nodes a tree of height h can hold, a perfect tree with 2ʰ − 1:

```swift run
// fewest[h]: the fewest nodes an AVL tree of height h can have
var fewest = [0, 1]
while fewest.count <= 10 {
    let h = fewest.count
    fewest.append(fewest[h - 1] + fewest[h - 2] + 1)    // root + sparsest h - 1 + sparsest h - 2
}
for h in 1...10 {
    let most = (1 << h) - 1                              // a perfect tree: 2^h - 1 nodes
    print("height \(h): fewest \(fewest[h]), most \(most)")
}

// How tall can an AVL tree with a million nodes be?
var height = 1
var smaller = 0      // fewest nodes for height - 1
var current = 1      // fewest nodes for height
while true {
    let next = current + smaller + 1
    if next > 1_000_000 { break }
    smaller = current
    current = next
    height += 1
}
print("a million nodes: at most \(height) levels, at least 20")
```

```output
height 1: fewest 1, most 1
height 2: fewest 2, most 3
height 3: fewest 4, most 7
height 4: fewest 7, most 15
height 5: fewest 12, most 31
height 6: fewest 20, most 63
height 7: fewest 33, most 127
height 8: fewest 54, most 255
height 9: fewest 88, most 511
height 10: fewest 143, most 1023
a million nodes: at most 28 levels, at least 20
```

Even the sparsest AVL trees grow exponentially with height. Turning that round: with n nodes, the height h satisfies roughly 1.618ʰ ≤ n, so h ≤ log n / log 1.618 ≈ **1.44 log2 n**. A million nodes means at most 28 levels, against 20 for a perfect tree and a million for a chain. That's what "balanced" buys.

## Inserting: the plan

Insertion has three steps:

1. **Insert as in a plain BST.** Walk down and add a new leaf (height 1).
2. **Walk back up the path,** recomputing each node's height from its children.
3. **Fix the first node that breaks the rule.** If some node's balance factor has become +2 or −2, rotate to repair it.

Only nodes on the path from the root to the new leaf can change height, because only their subtrees gained a node. So only they can become unbalanced, and walking back up that path visits every node that needs checking.

Recursion does the walking back up for free. The recursive insert from [The BST property, search and insert](/dsa/learn/bst-property-search-insert) returns the root of each subtree, and the code after the recursive call runs on the way back up, one level at a time. That's where the height update and the fix go.

## The four cases

Say node z has balance factor +2: its left side is two levels taller. Let y be its left child, the root of the tall side. There are two shapes, depending on which way y leans.

**Left-left (LL): y leans left, or is level.** The extra height is on the outside. One right rotation at z fixes it:

```text
          z (+2)                 y (0)
         /    \                /     \
     y (+1)    D            x          z
     /    \         →      / \        /  \
    x      C              A   B      C    D
   / \
  A   B
```

**Left-right (LR): y leans right.** The extra height is on the inside, under y's right child x. A right rotation at z alone would only move the problem to the other side, the bent chain from the last lesson. So first rotate **left at y**, turning it into the left-left shape, and then rotate **right at z**:

```text
       z (+2)              z                       x
      /    \              /  \                  /     \
   y (−1)   D           x     D              y          z
   /   \        →      / \          →       / \        / \
  A     x             y   C                A   B      C   D
       / \           / \
      B   C         A   B
```

The other two cases are the mirror images, for balance factor −2:

| Case | z's balance | Its tall child leans | Fix |
| --- | --- | --- | --- |
| Left-left (LL) | +2 | left, or level | rotate right at z |
| Left-right (LR) | +2 | right | rotate left at the child, then right at z |
| Right-right (RR) | −2 | right, or level | rotate left at z |
| Right-left (RL) | −2 | left | rotate right at the child, then left at z |

In every case, x, y and z end up as a little balanced triangle with the middle value on top, and the four subtrees A, B, C and D hang below in their original left-to-right order. Watch the cases happen. Inserting 10, 20, 30 triggers a right-right case; 40 and 50 trigger another; and 25 triggers a right-left case at the root:

```visual avl
values: [10, 20, 30, 40, 50, 25]
```

## The code

Here's a complete AVL insert. `rebalance` holds all four cases, and it runs on every node on the way back up:

```swift run
final class AVLNode {
    var value: Int
    var left: AVLNode?
    var right: AVLNode?
    var height = 1                       // a new node is a leaf: one level

    init(_ value: Int) { self.value = value }
}

func height(_ node: AVLNode?) -> Int {
    node?.height ?? 0                    // the empty tree has height 0
}

func balance(_ node: AVLNode) -> Int {
    height(node.left) - height(node.right)
}

func updateHeight(_ node: AVLNode) {
    node.height = 1 + max(height(node.left), height(node.right))
}

func rotateRight(_ y: AVLNode) -> AVLNode {
    let x = y.left!
    y.left = x.right
    x.right = y
    updateHeight(y)                      // y is now below x, so it goes first
    updateHeight(x)
    return x
}

func rotateLeft(_ x: AVLNode) -> AVLNode {
    let y = x.right!
    x.right = y.left
    y.left = x
    updateHeight(x)
    updateHeight(y)
    return y
}

var rotations: [String] = []             // a log, so we can see what happened

func rebalance(_ node: AVLNode) -> AVLNode {
    updateHeight(node)
    let factor = balance(node)
    if factor > 1 {                                      // left side too tall
        if balance(node.left!) < 0 {                     // …and the left child leans right
            rotations.append("LR at \(node.value)")
            node.left = rotateLeft(node.left!)
        } else {
            rotations.append("LL at \(node.value)")
        }
        return rotateRight(node)
    }
    if factor < -1 {                                     // right side too tall
        if balance(node.right!) > 0 {                    // …and the right child leans left
            rotations.append("RL at \(node.value)")
            node.right = rotateRight(node.right!)
        } else {
            rotations.append("RR at \(node.value)")
        }
        return rotateLeft(node)
    }
    return node
}

func insert(_ value: Int, into node: AVLNode?) -> AVLNode {
    guard let node else { return AVLNode(value) }
    if value < node.value {
        node.left = insert(value, into: node.left)
    } else if value > node.value {
        node.right = insert(value, into: node.right)
    } else {
        return node                                      // already there: a set stores it once
    }
    return rebalance(node)                               // on the way back up
}

func levels(_ root: AVLNode?) -> [[Int]] {
    var result: [[Int]] = []
    var level = root.map { [$0] } ?? []
    while !level.isEmpty {
        result.append(level.map { $0.value })
        level = level.flatMap { [$0.left, $0.right].compactMap { $0 } }
    }
    return result
}

var root: AVLNode? = nil
for value in [10, 20, 30, 40, 50, 25] {
    rotations.removeAll()
    root = insert(value, into: root)
    let note = rotations.first.map { "   (\($0))" } ?? ""
    print("insert \(value): \(levels(root))" + note)
}
```

```output
insert 10: [[10]]
insert 20: [[10], [20]]
insert 30: [[20], [10, 30]]   (RR at 10)
insert 40: [[20], [10, 30], [40]]
insert 50: [[20], [10, 40], [30, 50]]   (RR at 30)
insert 25: [[30], [20, 40], [10, 25, 50]]   (RL at 20)
```

What to notice:

- Every recursive call ends with `return rebalance(node)`, and the caller stores the result: `node.left = insert(…)`. If a rotation gives this subtree a new root, the parent's link is updated automatically. That's the re-attach gotcha from the last lesson, handled by the shape of the code.
- The rotations update heights **bottom-up**: the node that moved down first, then the node that moved up, because the new top's height depends on the one below it.
- `rebalance` tells the single cases from the double ones by looking at the **child's balance factor**, not at the newly inserted value. The visualiser's code compares the inserted value with the child's value instead, which also works for inserts, but only for inserts. Checking the child's balance works for deletes too, so it's the version to learn.

## One fix per insert

On insert, the first node that becomes unbalanced is the only one that ever needs fixing. Look at the left-left picture: before the insert, z's subtree had some height H. The insert made y's side one level taller, which is what pushed z to +2. After the rotation, y's new subtree has height H again, exactly what z's subtree had before the insert. Every node above sees no change in height, so none of them can have become unbalanced. The same holds for the other three cases.

So an insert does **at most one fix**: one single rotation or one double rotation. The rest of the walk up only recomputes heights. Feed an AVL tree sorted input, the worst case for a plain BST, and count:

```swift run
final class AVLNode {
    var value: Int
    var left: AVLNode?
    var right: AVLNode?
    var height = 1

    init(_ value: Int) { self.value = value }
}

func height(_ node: AVLNode?) -> Int {
    node?.height ?? 0
}

func balance(_ node: AVLNode) -> Int {
    height(node.left) - height(node.right)
}

func updateHeight(_ node: AVLNode) {
    node.height = 1 + max(height(node.left), height(node.right))
}

func rotateRight(_ y: AVLNode) -> AVLNode {
    let x = y.left!
    y.left = x.right
    x.right = y
    updateHeight(y)
    updateHeight(x)
    return x
}

func rotateLeft(_ x: AVLNode) -> AVLNode {
    let y = x.right!
    x.right = y.left
    y.left = x
    updateHeight(x)
    updateHeight(y)
    return y
}

var fixes = 0

func rebalance(_ node: AVLNode) -> AVLNode {
    updateHeight(node)
    let factor = balance(node)
    if factor > 1 {
        fixes += 1
        if balance(node.left!) < 0 { node.left = rotateLeft(node.left!) }
        return rotateRight(node)
    }
    if factor < -1 {
        fixes += 1
        if balance(node.right!) > 0 { node.right = rotateRight(node.right!) }
        return rotateLeft(node)
    }
    return node
}

func insert(_ value: Int, into node: AVLNode?) -> AVLNode {
    guard let node else { return AVLNode(value) }
    if value < node.value {
        node.left = insert(value, into: node.left)
    } else if value > node.value {
        node.right = insert(value, into: node.right)
    } else {
        return node
    }
    return rebalance(node)
}

for n in [1_000, 100_000] {
    var root: AVLNode? = nil
    fixes = 0
    for value in 1...n {
        root = insert(value, into: root)
    }
    print("\(n) sorted inserts: height \(height(root)), \(fixes) fixes")
}
```

```output
1000 sorted inserts: height 10, 990 fixes
100000 sorted inserts: height 17, 99983 fixes
```

A hundred thousand sorted values give a tree 17 levels tall: the best possible, since 2¹⁷ is the first power of two above 100,000. A plain BST would be 100,000 levels tall. And there's never more than one fix per insert: here, one on almost every insert, because sorted input keeps tipping the right side over.

## Why recursion is fine here

In [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) you saw that deep recursion can overflow the call stack, and an unbalanced BST's recursive insert can recurse n levels deep. An AVL tree's recursion is exactly as deep as the tree: at most about 1.44 log2 n levels. For 100,000 values that's at most 23 frames, and for a billion at most 42. No stack will ever notice, so the clearer recursive code is the right choice. (Iteration with an explicit stack of the path, or with parent pointers, also works; it's longer.)

## Deleting

Deletion follows the same plan: delete as in a plain BST, then rebalance every node on the way back up. The BST part is the three cases from [Deleting from a BST](/dsa/learn/bst-delete): a leaf disappears, a node with one child is replaced by that child, and a node with two children takes its **successor's** value (the smallest value in its right subtree), and the successor is deleted from the right subtree instead.

There's one difference from insertion that matters. After a delete, a rotation can leave its subtree **one level shorter** than it was before the delete. Then the node above may become unbalanced in turn, and so on up to the root. A delete can need a fix at every level: O(log n) rotations in the worst case, though usually far fewer.

Deletion also brings a shape insertion never makes: a tall child that's **level** (balance factor 0). Then a single rotation is right, which is why `rebalance` treats balance 0 like the outside case (`balance(node.left!) < 0` picks the double rotation only for a child that strictly leans inward).

Here's removal added to the same tree. The example builds the sparsest AVL tree of height 5 (12 nodes, a Fibonacci shape) and removes 12 from its short side:

```swift run
final class AVLNode {
    var value: Int                       // var: a removal can copy a successor's value in
    var left: AVLNode?
    var right: AVLNode?
    var height = 1

    init(_ value: Int) { self.value = value }
}

func height(_ node: AVLNode?) -> Int {
    node?.height ?? 0
}

func balance(_ node: AVLNode) -> Int {
    height(node.left) - height(node.right)
}

func updateHeight(_ node: AVLNode) {
    node.height = 1 + max(height(node.left), height(node.right))
}

func rotateRight(_ y: AVLNode) -> AVLNode {
    let x = y.left!
    y.left = x.right
    x.right = y
    updateHeight(y)
    updateHeight(x)
    return x
}

func rotateLeft(_ x: AVLNode) -> AVLNode {
    let y = x.right!
    x.right = y.left
    y.left = x
    updateHeight(x)
    updateHeight(y)
    return y
}

var rotations: [String] = []

func rebalance(_ node: AVLNode) -> AVLNode {
    updateHeight(node)
    let factor = balance(node)
    if factor > 1 {
        if balance(node.left!) < 0 {
            rotations.append("LR at \(node.value)")
            node.left = rotateLeft(node.left!)
        } else {
            rotations.append("LL at \(node.value)")
        }
        return rotateRight(node)
    }
    if factor < -1 {
        if balance(node.right!) > 0 {
            rotations.append("RL at \(node.value)")
            node.right = rotateRight(node.right!)
        } else {
            rotations.append("RR at \(node.value)")
        }
        return rotateLeft(node)
    }
    return node
}

func insert(_ value: Int, into node: AVLNode?) -> AVLNode {
    guard let node else { return AVLNode(value) }
    if value < node.value {
        node.left = insert(value, into: node.left)
    } else if value > node.value {
        node.right = insert(value, into: node.right)
    } else {
        return node
    }
    return rebalance(node)
}

func remove(_ value: Int, from node: AVLNode?) -> AVLNode? {
    guard let node else { return nil }                   // not in the tree
    if value < node.value {
        node.left = remove(value, from: node.left)
    } else if value > node.value {
        node.right = remove(value, from: node.right)
    } else {
        // Found it. With at most one child, the child takes its place.
        guard let left = node.left else { return node.right }
        guard let right = node.right else { return left }
        // Two children: copy the successor's value here, then remove the successor
        var successor = right
        while let smaller = successor.left {
            successor = smaller
        }
        node.value = successor.value
        node.right = remove(successor.value, from: right)
    }
    return rebalance(node)                               // every node on the way back up
}

func levels(_ root: AVLNode?) -> [[Int]] {
    var result: [[Int]] = []
    var level = root.map { [$0] } ?? []
    while !level.isEmpty {
        result.append(level.map { $0.value })
        level = level.flatMap { [$0.left, $0.right].compactMap { $0 } }
    }
    return result
}

var root: AVLNode? = nil
for value in [8, 5, 11, 3, 7, 10, 12, 2, 4, 6, 9, 1] {
    root = insert(value, into: root)
}
print("before:", levels(root))
rotations.removeAll()
root = remove(12, from: root)
print("after: ", levels(root))
print("rotations:", rotations)
rotations.removeAll()
root = remove(5, from: root)
print("remove 5:", levels(root), rotations)
```

```output
before: [[8], [5, 11], [3, 7, 10, 12], [2, 4, 6, 9], [1]]
after:  [[5], [3, 8], [2, 4, 7, 10], [1, 6, 9, 11]]
rotations: ["LL at 11", "LL at 8"]
remove 5: [[6], [3, 8], [2, 4, 7, 10], [1, 9, 11]] []
```

Removing 12 leaves 11 with only a left subtree, two levels taller than its empty right side: a left-left fix at 11. That rotation makes 11's subtree one level shorter, which tips 8 over, so there's a second left-left fix, at the root. The tree is now 4 levels tall instead of 5. Removing 5, which has two children, copies its successor 6 into its place, and nothing needs rotating.

## Complexity

| Operation | Time | Rotations |
| --- | --- | --- |
| Search, min, max, floor, ceiling | O(log n) | none |
| Insert | O(log n) | at most one single or double rotation |
| Delete | O(log n) | up to one fix per level: O(log n) |
| Build from n values | O(n log n) | |
| Space | O(n) | one extra `Int` per node for the height |

Every operation is O(log n) because it walks one root-to-leaf path, doing O(1) work (a height update, maybe a rotation) per level, and the path has at most about 1.44 log2 n levels. (Storing a two-bit balance factor instead of the height saves memory, but makes the update rules fiddlier. Storing heights is the common choice.)

## Checking an AVL tree

When you write your own, test it with a checker that recomputes everything from scratch and compares: the values strictly increase in inorder, every stored height is right, and every balance factor is −1, 0 or +1. Run it after thousands of random inserts and deletes, comparing the contents with a `Set`, and almost every bug shows up within seconds. That's exactly how DSAKit's `AVLTree` is tested.

DSAKit's version is generic over any `Comparable` element and has value semantics: copying a tree gives an independent tree, through copy-on-write as in [Writing your own copy-on-write](/dsa/learn/swift-implementing-cow).

```swift
import DSAKit

var tree: AVLTree = [50, 20, 80]
tree.insert(30)                 // true
tree.insert(30)                 // false: already there
print(tree.height)              // 3
print(tree.floor(45) ?? 0)      // 30, the largest element ≤ 45
print(Array(tree))              // [20, 30, 50, 80]
```

<Callout kind="gotcha" title="Stale heights">
Every place a node's children change, its height must be recomputed, and its children's heights must already be right. The usual slips: forgetting `updateHeight` in a rotation, updating the new top before the node that moved below it, or returning early from a recursive call (for example on a duplicate) after a change below. A stored height that's one off doesn't crash anything. It makes later rotations pick the wrong case, and the tree slowly goes lopsided. A checker catches it at once.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: max inside a Sequence">
If your tree type conforms to `Sequence`, as DSAKit's does, then inside it `max(a, b)` refers to the sequence's own `max()` method, and Swift reports an error. Write `Swift.max(a, b)` to reach the global function.
</Callout>
