## Why it matters

The most important job a queue does in DSA is **breadth-first search**, or BFS: exploring outwards from a starting point in rings, everything one step away, then everything two steps away, and so on. That order is what finds **shortest paths** when every step costs the same: the fewest moves through a maze, the quickest route across a game board, how many introductions separate two people, how long something takes to spread. M42 covers BFS properly on graphs. This lesson is a preview on a grid, to show why the queue is the essential ingredient.

## Exploring in rings

Picture dropping a stone in a pond. The ripple reaches every point 1 metre away before any point 2 metres away. BFS spreads the same way:

1. Put the start in a queue, at distance 0.
2. Dequeue a cell. For each neighbour you haven't seen yet that isn't a wall, record its distance as the current cell's distance + 1, and enqueue it.
3. Repeat until the queue is empty.

Why does this find shortest distances? Because a queue is first in, first out. All the distance-1 cells are enqueued before any distance-2 cell, so they all come out first; while they come out, they enqueue the distance-2 cells, which all come out before any distance-3 cell, and so on. The first time BFS reaches a cell, it has come by a shortest route, because every shorter route was explored earlier.

## BFS on a grid

Here `S` is the start, `T` the target and `#` a wall. Moves go up, down, left and right, using the direction arrays from [Direction arrays for grid moves](/dsa/learn/matrix-directions). The queue is an array with a head index, as in [A queue with a head index](/dsa/learn/queue-head-index), and it stores `(row, column)` pairs:

```swift run
let grid = [
    "S..#.",
    ".#...",
    ".#.#.",
    "...#T",
]
let cells = grid.map { Array($0) }
let rows = cells.count
let columns = cells[0].count
let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]     // up, down, left, right

var distance = Array(repeating: Array(repeating: -1, count: columns), count: rows)
var queue: [(Int, Int)] = [(0, 0)]                      // a head-index queue of (row, column)
var head = 0
distance[0][0] = 0

while head < queue.count {
    let (row, column) = queue[head]
    head += 1
    for (dr, dc) in directions {
        let r = row + dr
        let c = column + dc
        guard r >= 0, r < rows, c >= 0, c < columns else { continue }   // off the grid
        guard cells[r][c] != "#", distance[r][c] == -1 else { continue } // wall, or seen
        distance[r][c] = distance[row][column] + 1                       // mark as you enqueue
        queue.append((r, c))
    }
}

for r in 0..<rows {
    let line = (0..<columns).map { c in cells[r][c] == "#" ? "#" : String(distance[r][c]) }
    print(line.joined(separator: " "))
}
print("steps to T:", distance[3][4], "cells visited:", queue.count)
```

```output
0 1 2 # 6
1 # 3 4 5
2 # 4 # 6
3 4 5 # 7
steps to T: 7 cells visited: 15
```

Every number is the fewest moves from `S` to that cell. The target is 7 moves away: along the top, down through the gap, round the right-hand side. The top-right cell is 6 moves away even though it's only 4 columns from `S`, because the wall forces a detour.

What to notice:

- `distance` does two jobs: it stores the answer, and `-1` means "not seen yet".
- Each cell is enqueued **at most once**, the moment it's first seen. The queue ended up holding 15 cells: every open cell exactly once. So BFS on a grid is **O(rows × columns)**.
- The two `guard`s keep the neighbour checks readable: first stay on the grid, then skip walls and cells already seen.

Watch the ripple spread from S. Each number is a cell's distance, the blue cells are waiting in the queue, and once G is reached the path is traced back:

```visual grid

```

## Why a queue and not a stack?

Swap the queue for a stack (take cells from the back with `removeLast()`) and the same code explores **depth-first**: it follows one path as far as it goes before backing up, like the folder walk in [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack). It still visits every cell, but the first route it finds to a cell is often a long, winding one:

```swift run
// The same search on an open 3 × 3 grid, taking cells from the front (a queue) or the back (a stack)
func firstFoundDistances(useQueue: Bool) -> [[Int]] {
    let size = 3
    var distance = Array(repeating: Array(repeating: -1, count: size), count: size)
    var pending: [(Int, Int)] = [(0, 0)]
    var head = 0
    distance[0][0] = 0
    while head < pending.count {
        let (row, column) = useQueue ? pending[head] : pending.removeLast()
        if useQueue { head += 1 }
        for (dr, dc) in [(0, 1), (1, 0), (0, -1), (-1, 0)] {
            let r = row + dr
            let c = column + dc
            guard r >= 0, r < size, c >= 0, c < size, distance[r][c] == -1 else { continue }
            distance[r][c] = distance[row][column] + 1
            pending.append((r, c))
        }
    }
    return distance
}

print("queue:", firstFoundDistances(useQueue: true))
print("stack:", firstFoundDistances(useQueue: false))
```

```output
queue: [[0, 1, 2], [1, 2, 3], [2, 3, 4]]
stack: [[0, 1, 6], [1, 2, 5], [2, 3, 4]]
```

With the stack, the top-right cell is recorded as 6 moves away, though it's plainly 2. The stack went down the left side first and reached that corner the long way round. Depth-first search is useful for other things (M42 covers it alongside BFS), but for shortest paths with equal-cost steps, you need the queue's first-in, first-out order.

<Callout kind="gotcha" title="Mark cells when you enqueue them, not when you dequeue them">
If you only mark a cell as seen when it comes **out** of the queue, several neighbours can each enqueue it before that happens. On an open grid the queue fills with duplicates, and the work balloons far past one visit per cell. Mark it, here by setting its distance, the moment it goes **in**.
</Callout>

## Several starting points at once

What if there are several sources: three fires spreading through a forest, several people who know a rumour, many exits in a building? You want each cell's distance to the **nearest** source.

There's no need to run BFS once per source. Put **all** the sources in the queue at distance 0 before starting. The rings then grow from every source at once, and where two ripples meet, each cell keeps the distance from whichever reached it first, which is the nearest. This is **multi-source BFS**, and it costs the same O(rows × columns) as a single source.

When a problem asks "how many rounds until everything is reached?", process the queue **one ring at a time**: note how many cells are in the queue, dequeue exactly that many (enqueueing their neighbours as usual), and count one round. That's the shape of the practice problem.

```swift
var rounds = 0
while head < queue.count {
    let ringEnd = queue.count            // everything enqueued so far is in this ring
    while head < ringEnd {
        let (row, column) = queue[head]
        head += 1
        // …enqueue unseen neighbours…
    }
    rounds += 1
}
```

## Where BFS goes next

This lesson only scratches the surface. In M42 you'll run BFS on graphs of any shape, rebuild the actual shortest path rather than only its length, search a whole space of states (such as lock combinations) and search from both ends at once. In M44, a deque handles moves that cost either 0 or 1: cheap moves go on the front, expensive ones on the back. The engine underneath is the same: a queue, and marking things as seen the moment they join it.

**Rumour spread** is a multi-source BFS in disguise: everyone who knows a rumour tells their neighbours each minute, and you work out how many minutes until the whole office knows, or that someone never will.
