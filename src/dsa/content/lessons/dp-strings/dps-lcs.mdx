## Why it matters

Every time you look at a pull request, a diff tool has answered one question: which lines did the two versions keep in common? Everything else is shown as removed or added. The longest run of kept lines, in order, is the **longest common subsequence** (LCS) of the two files. The same table compares DNA strands, merges edits in sync tools, and sits underneath edit distance, palindromes and supersequences in the rest of this module. It's the first two-string DP, and the shape you learn here repeats in every lesson that follows.

## Subsequences, and why brute force is hopeless

A **subsequence** keeps some characters of a string in their original order and deletes the rest. They don't have to be next to each other. `"ACE"` is a subsequence of `"ABCDE"`; `"AEC"` isn't, because the order changed. You met the term in [Subarray vs subsequence vs subset](/dsa/learn/arrays-sub-definitions), and checked one with two pointers in [Read/write pointers](/dsa/learn/tp-read-write).

A **common subsequence** of two strings is a subsequence of both. The task: find the longest. For `"ABCBDAB"` and `"BDCABA"` the answer has length 4, and `"BCBA"` is one example:

| String | Keep |
| --- | --- |
| `A B C B D A B` | B, C, B, A at positions 1, 2, 3, 5 |
| `B D C A B A` | B, C, B, A at positions 0, 2, 4, 5 |

A string of n characters has 2ⁿ subsequences. Listing all of one string's and checking each against the other is hopeless past about 25 characters. You need a smarter question.

## Look at the last characters

Use [the DP recipe](/dsa/learn/dp-recipe): state, transition, base case, order, answer.

**State.** Let `L(i, j)` be the LCS length of the first i characters of a and the first j characters of b. These are **prefixes**: `L(3, 2)` compares `"ABC"` with `"BD"`.

**Transition.** Look at the last character of each prefix, `a[i - 1]` and `b[j - 1]`:

- **They match.** Use them as the last pair of the common subsequence. The rest is the best answer for the two shorter prefixes: `L(i, j) = L(i - 1, j - 1) + 1`. Taking the match is always safe: if some longest answer didn't end with this pair, you could swap its last pair for this one and lose nothing.
- **They differ.** They can't both be the last character of a common subsequence, so at least one of them isn't used. Try dropping each and keep the better: `L(i, j) = max(L(i - 1, j), L(i, j - 1))`.

**Base case.** An empty prefix shares nothing: `L(0, j) = L(i, 0) = 0`.

Written as plain recursion, that's already correct:

```swift run
var calls = 0

/// LCS length of the first i letters of a and the first j letters of b, by plain recursion
func lcs(_ a: [Character], _ b: [Character], _ i: Int, _ j: Int) -> Int {
    calls += 1
    if i == 0 || j == 0 {
        return 0                                        // an empty prefix shares nothing
    }
    if a[i - 1] == b[j - 1] {
        return lcs(a, b, i - 1, j - 1) + 1              // the last letters match: keep the pair
    }
    return max(lcs(a, b, i - 1, j), lcs(a, b, i, j - 1))   // drop the last letter of one or the other
}

for (first, second) in [("ABCBDAB", "BDCABA"), ("SWIFTLY", "SHIFTILY"), ("ABCDEFGHIJ", "KLMNOPQRST")] {
    calls = 0
    let length = lcs(Array(first), Array(second), first.count, second.count)
    print("\(first) and \(second): length \(length), \(calls) calls")
}
```

```output
ABCBDAB and BDCABA: length 4, 152 calls
SWIFTLY and SHIFTILY: length 6, 138 calls
ABCDEFGHIJ and KLMNOPQRST: length 0, 369511 calls
```

Two 10-letter strings with nothing in common take 369,511 calls, because every mismatch branches in two. But there are only 11 × 11 = 121 different `(i, j)` pairs. The same subproblems are being solved thousands of times: exactly the overlap that DP removes.

## Filling the table

**Order.** `L(i, j)` needs the cell above `(i - 1, j)`, the cell to the left `(i, j - 1)` and the diagonal `(i - 1, j - 1)`. Filling row by row, left to right, has all three ready.

**Answer.** The bottom-right cell, `L(n, m)`.

```swift run
func lcsTable(_ a: [Character], _ b: [Character]) -> [[Int]] {
    let n = a.count, m = b.count
    var table = Array(repeating: Array(repeating: 0, count: m + 1), count: n + 1)
    for i in 0...n {
        for j in 0...m {
            if i == 0 || j == 0 {
                table[i][j] = 0                                         // an empty prefix
            } else if a[i - 1] == b[j - 1] {
                table[i][j] = table[i - 1][j - 1] + 1                   // keep the matching pair
            } else {
                table[i][j] = max(table[i - 1][j], table[i][j - 1])     // drop one last letter
            }
        }
    }
    return table
}

let a = Array("ABCBDAB"), b = Array("BDCABA")
let table = lcsTable(a, b)
print("  ∅ " + b.map(String.init).joined(separator: " "))
for i in 0...a.count {
    let label = i == 0 ? "∅" : String(a[i - 1])
    print(label + " " + table[i].map(String.init).joined(separator: " "))
}
print("LCS length:", table[a.count][b.count])
```

```output
  ∅ B D C A B A
∅ 0 0 0 0 0 0 0
A 0 0 0 0 1 1 1
B 0 1 1 1 1 2 2
C 0 1 1 2 2 2 2
B 0 1 1 2 2 3 3
D 0 1 2 2 2 3 3
A 0 1 2 2 3 3 4
B 0 1 2 2 3 4 4
LCS length: 4
```

The table has one more row and column than the strings, for the empty prefixes, so **row i is about the character `a[i - 1]`**. That off-by-one is the most common bug in string DP; say it to yourself every time.

Step through the same table. The amber cell is being filled, blue cells are the ones it reads, and at the end the traceback (next section) lights up in green:

```visual dpTable
program: lcs
input:
  a: ABCBDAB
  b: BDCABA
```

What to notice:

- Values never go down as you move right or down. A longer prefix can only share more.
- A match copies the diagonal plus one; a mismatch copies the larger of above and left.
- Looping over `0...n` with the base case as the first branch is safe for empty strings. `for i in 1...n` would crash when n is 0, with `Range requires lowerBound <= upperBound`.

Time and space are both **O(n · m)**: two 2,000-character strings make 4 million cells, a fraction of a second.

## Printing the subsequence: the traceback

The table holds lengths, but every cell remembers where its value came from. Start at the bottom-right corner and walk back, as in [Reconstructing the answer, not just its value](/dsa/learn/dp-reconstruct):

- If `a[i - 1] == b[j - 1]`, this pair is in the LCS. Record the letter and step diagonally.
- Otherwise the value came from above or from the left: step towards the larger one.

Stop when either index reaches 0. The letters come out back to front, so reverse them.

```swift run
func lcsTable(_ a: [Character], _ b: [Character]) -> [[Int]] {
    let n = a.count, m = b.count
    var table = Array(repeating: Array(repeating: 0, count: m + 1), count: n + 1)
    for i in 0...n {
        for j in 0...m {
            if i == 0 || j == 0 {
                table[i][j] = 0
            } else if a[i - 1] == b[j - 1] {
                table[i][j] = table[i - 1][j - 1] + 1
            } else {
                table[i][j] = max(table[i - 1][j], table[i][j - 1])
            }
        }
    }
    return table
}

/// Walks back from the bottom-right corner, collecting matched letters. On a tie between up and
/// left, `preferUp` decides which way to go.
func longestCommonSubsequence(_ first: String, _ second: String, preferUp: Bool = true) -> String {
    let a = Array(first), b = Array(second)
    let table = lcsTable(a, b)
    var letters: [Character] = []
    var i = a.count, j = b.count
    while i > 0 && j > 0 {
        if a[i - 1] == b[j - 1] {
            letters.append(a[i - 1])            // this pair is part of the LCS
            i -= 1
            j -= 1
        } else if table[i - 1][j] > table[i][j - 1] || (table[i - 1][j] == table[i][j - 1] && preferUp) {
            i -= 1                              // the value came from above: a[i - 1] isn't used
        } else {
            j -= 1                              // it came from the left: b[j - 1] isn't used
        }
    }
    return String(letters.reversed())           // collected back to front
}

print(longestCommonSubsequence("ABCBDAB", "BDCABA"))
print(longestCommonSubsequence("ABCBDAB", "BDCABA", preferUp: false))
print(longestCommonSubsequence("SWIFTLY", "SHIFTILY"))
print(longestCommonSubsequence("kitten", "sitting"))
print(longestCommonSubsequence("abc", "xyz").isEmpty)
```

```output
BCBA
BDAB
SIFTLY
ittn
true
```

The walk takes at most n + m steps, so printing costs O(n + m) on top of the table.

### Ties: more than one right answer

When the cell above and the cell to the left hold the same value, both directions lead to a longest subsequence, just different ones. Preferring up gives `"BCBA"`; preferring left gives `"BDAB"`. Both have length 4, and both are correct. (`"BCAB"` is a third.)

So the LCS **length** is unique, but the LCS **string** isn't. Two consequences:

- A problem that asks for "an LCS" accepts any of them, and its tests should check properties (is it a subsequence of both, and is it the right length?) rather than compare with one string.
- If a problem wants a specific one, such as the alphabetically smallest, the tie rule has to be designed for that. "Prefer up" doesn't give you any particular order for free.

The number of different LCS strings can grow exponentially, so "list them all" is a backtracking problem over the table, following both directions at every tie.

## From LCS to a diff

A line diff is an LCS where the "characters" are whole lines. Lines in the LCS are unchanged; lines only in the old version were deleted, and lines only in the new one were inserted. The same walk-back prints it, with one extra rule: once one version runs out, the rest of the other is all deletions or all insertions.

```swift run
/// A line-by-line diff: "  " keeps a line, "- " deletes it, "+ " inserts one
func diff(_ old: [String], _ new: [String]) -> [String] {
    let n = old.count, m = new.count
    var table = Array(repeating: Array(repeating: 0, count: m + 1), count: n + 1)
    for i in 0...n {
        for j in 0...m {
            if i == 0 || j == 0 {
                table[i][j] = 0
            } else if old[i - 1] == new[j - 1] {
                table[i][j] = table[i - 1][j - 1] + 1
            } else {
                table[i][j] = max(table[i - 1][j], table[i][j - 1])
            }
        }
    }
    var lines: [String] = []
    var i = n, j = m
    while i > 0 || j > 0 {
        if i > 0 && j > 0 && old[i - 1] == new[j - 1] {
            lines.append("  " + old[i - 1])                     // in the LCS: unchanged
            i -= 1
            j -= 1
        } else if j > 0 && (i == 0 || table[i][j - 1] >= table[i - 1][j]) {
            lines.append("+ " + new[j - 1])                     // only in the new version
            j -= 1
        } else {
            lines.append("- " + old[i - 1])                     // only in the old version
            i -= 1
        }
    }
    return lines.reversed()
}

let before = ["buy milk", "call mum", "fix bike", "read book"]
let after = ["buy milk", "fix bike", "water plants", "read book", "sleep"]
for line in diff(before, after) {
    print(line)
}
```

```output
  buy milk
- call mum
  fix bike
+ water plants
  read book
+ sleep
```

Walking backwards, ties go left first (insertions), so in the reversed output a deletion comes before the insertion that replaces it, the way diff tools show it. Real tools such as `git diff` use faster algorithms tuned for files that are mostly unchanged, but they answer the same question.

## Saving space when you only need the length

Each row reads only the row above it. If you only want the length, keep two rows and swap them, as in [Saving space](/dsa/learn/dp-space):

```swift run
/// LCS length with two rows: each row only needs the one above it
func lcsLength(_ first: String, _ second: String) -> Int {
    let a = Array(first), b = Array(second)
    var previous = Array(repeating: 0, count: b.count + 1)
    var current = previous
    for i in 0..<a.count {                      // filling row i + 1 of the table
        for j in 0...b.count {
            if j == 0 {
                current[j] = 0
            } else if a[i] == b[j - 1] {
                current[j] = previous[j - 1] + 1
            } else {
                current[j] = max(previous[j], current[j - 1])
            }
        }
        swap(&previous, &current)
    }
    return previous[b.count]
}

print(lcsLength("ABCBDAB", "BDCABA"), lcsLength("", "abc"), lcsLength("SWIFTLY", "SHIFTILY"))
```

```output
4 0 6
```

That's O(min(n, m)) memory if you put the shorter string along the columns. The catch: the traceback needs the whole table, so printing the LCS still takes O(n · m) memory. (Hirschberg's algorithm gets both, with divide and conquer, but it's rarely needed.)

## LCS in disguise

Many problems are LCS without saying so. The tell is two sequences, an order that must be kept, and a question about what they share. The table works on any `Equatable` elements, not just characters: lines, words, numbers.

| Problem | How it's LCS |
| --- | --- |
| Fewest deletions from both strings to make them equal | delete everything outside an LCS: n + m − 2 × LCS |
| Draw lines between equal numbers in two rows, with no lines crossing; how many at most? | non-crossing lines are a common subsequence of the two arrays |
| Longest palindromic subsequence | LCS of a string and its reverse, later in this module |
| Shortest string containing both as subsequences | n + m − LCS characters, later in this module |
| Edit distance with only inserts and deletes | n + m − 2 × LCS, in two lessons |

When you meet a new two-sequence problem, ask "what would the LCS table's cells mean here?" before inventing something from scratch.

<Callout kind="gotcha" title="Common mistakes">
- **Row i is `a[i - 1]`.** The table has an extra row and column for the empty prefix. Comparing `a[i]` with `b[j]` in a table indexed from the empty prefix reads the wrong letters, or past the end.
- **Indexing a `String` directly.** `first[i]` doesn't compile. Convert once with `Array(first)`, as in [Array(s) and [UInt8] for fast access](/dsa/learn/swift-string-to-array).
- **`for i in 1...n` with an empty string.** It crashes. Loop over `0...n` and handle row 0 as the base case, or use `stride`.
- **Testing an LCS string against one expected answer.** Ties make several answers right. Check the length and that it's a subsequence of both.
- **Taking the max on a match.** When the letters match, the diagonal plus one is never worse than above or left, so `max` with them is wasted work, not wrong. Forgetting the `+ 1` is the real bug.
</Callout>
