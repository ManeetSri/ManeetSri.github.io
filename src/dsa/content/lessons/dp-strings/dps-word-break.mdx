## Why it matters

A hashtag like `#nowhereelse` has no spaces, yet people read it as words without thinking. Search engines split hashtags and domain names the same way, and text tools for languages written without spaces, such as Thai or Japanese, start by cutting text into dictionary words. The computer's version is **word break**: can this text be split into words from a dictionary, and if so, in which ways? Word break I is a one-dimensional DP. Word break II, listing every split, mixes DP with the backtracking you met in [The decision tree and the backtracking template](/dsa/learn/bk-template), and teaches an important lesson about output size.

## Word break I: can it be split?

Given a text and a list of words (each usable any number of times), decide whether the text can be cut into pieces that are all words.

Plain recursion tries every word that fits at the start, then recurses on the rest. On `"aaaa…ab"` with the words `"a"`, `"aa"` and `"aaa"`, it tries every way of cutting the a's (exponentially many) before discovering that the b can never be matched. But "can the text from position k onwards be split?" has only n + 1 different questions. That's the DP.

[The DP recipe](/dsa/learn/dp-recipe), on prefixes:

- **State.** `ok[i]` = can the first i characters be split into words?
- **Transition.** The last word of a split of the first `end` characters is `text[start..<end]` for some start. So `ok[end]` is true if, for some `start`, `ok[start]` is true **and** `text[start..<end]` is a word.
- **Base case.** `ok[0] = true`: the empty prefix is split into zero words.
- **Order.** `end` from 1 to n; each reads only smaller indices.
- **Answer.** `ok[n]`.

```swift run
/// Can `text` be split into words from `words`? ok[i] says whether its first i characters can.
func canSplit(_ text: String, _ words: [String]) -> Bool {
    let characters = Array(text)
    let dictionary = Set(words)
    let longest = words.map(\.count).max() ?? 0
    var ok = Array(repeating: false, count: characters.count + 1)
    ok[0] = true                                                 // the empty prefix: zero words
    for end in stride(from: 1, through: characters.count, by: 1) {
        for start in stride(from: end - 1, through: max(0, end - longest), by: -1) {
            if ok[start] && dictionary.contains(String(characters[start..<end])) {
                ok[end] = true                                   // a good prefix, then one word
                break
            }
        }
    }
    return ok[characters.count]
}

let words = ["ice", "cream", "icecream", "cone", "con"]
print(canSplit("icecreamcone", words))
print(canSplit("creamicecon", words))
print(canSplit("icecreamcones", words))
print(canSplit("", words))
let manyA = String(repeating: "a", count: 2_000) + "b"
print(canSplit(manyA, ["a", "aa", "aaa", "aaaa"]))
```

```output
true
true
false
true
false
```

The 2,001-character text is answered instantly. Plain recursion would still be running long after you'd given up waiting.

Step through `ok` for `"icecreamcone"`. Each cell lights up the earlier cell it builds on, and the green cells at the end mark where the words of one split end:

What to notice:

- `start` only goes back as far as the longest word. A piece longer than every dictionary word can't be a word, so there's no point building it.
- Each check builds a `String` of up to L characters and hashes it, so the whole thing costs O(n · L · L) for words of up to L characters. For a 2,000-character text and words up to 20 letters, that's under a million character steps.
- `ok` can be true for prefixes that don't lead anywhere: `"icecreamcon"` is splittable (ice, cream, con) even though the whole of `"icecreamcones"` isn't.

### Pushing forwards with a trie

The loop above pulls: for each `end`, it looks backwards for a word. You can also push: from each `start` where `ok[start]` is true, walk forwards and mark every position where a word ends. A trie, from [Replace words and longest word](/dsa/learn/trie-replace-words), finds all the words starting at a position in a single walk: follow the characters down the trie and note every end-of-word flag you pass.

```swift run
final class TrieNode {
    var children: [Character: TrieNode] = [:]
    var isWord = false
}

/// Word break pushed forwards: from every reachable start, walk the trie and mark each word end
func canSplit(_ text: String, _ words: [String]) -> Bool {
    let root = TrieNode()
    for word in words {
        var node = root
        for character in word {
            if node.children[character] == nil {
                node.children[character] = TrieNode()
            }
            node = node.children[character]!
        }
        node.isWord = true
    }
    let characters = Array(text)
    var ok = Array(repeating: false, count: characters.count + 1)
    ok[0] = true
    for start in characters.indices where ok[start] {
        var node = root
        var end = start
        while end < characters.count, let next = node.children[characters[end]] {
            node = next
            end += 1
            if node.isWord {
                ok[end] = true                     // characters[start..<end] is a word
            }
        }
    }
    return ok[characters.count]
}

let words = ["ice", "cream", "icecream", "cone", "con"]
print(canSplit("icecreamcone", words), canSplit("icecreamcones", words), canSplit("", words))
```

```output
true false true
```

Each walk stops as soon as no word continues, and builds no substrings, so the total is O(n · L) character steps. It's the "count the flags on the path" walk from the tries module, run from every reachable start.

## Word break II: every sentence

Now list every way to split the text, as sentences of words separated by spaces. With the words `no`, `now`, `where`, `here`, `w`, `he` and `re`, `"nowhere"` splits five ways, including the two readings people argue about, "now here" and "no where".

This is backtracking: choose a first word, recurse on the rest, and prepend the word to every sentence that comes back. Two DP ideas make it efficient:

- **Memoise by start position.** The sentences for `text[start...]` are the same no matter how you got to `start`, so compute them once, as in [Top-down memoisation](/dsa/learn/dp-memoisation).
- **Dead ends cost nothing twice.** A start with no way to finish returns an empty list, remembered, so it's never explored again.

```swift run
/// Every way to split `text` into words, as sentences
func allSentences(_ text: String, _ words: [String]) -> [String] {
    let characters = Array(text)
    let dictionary = Set(words)
    let longest = words.map(\.count).max() ?? 0
    var memo: [Int: [String]] = [:]                    // start → every sentence for characters[start...]

    func sentences(from start: Int) -> [String] {
        if start == characters.count {
            return [""]                                // one way to split nothing: no words
        }
        if let known = memo[start] {
            return known
        }
        var result: [String] = []
        let last = min(characters.count, start + longest)
        for end in stride(from: start + 1, through: last, by: 1) {
            let word = String(characters[start..<end])
            guard dictionary.contains(word) else { continue }
            for rest in sentences(from: end) {
                result.append(rest.isEmpty ? word : word + " " + rest)
            }
        }
        memo[start] = result
        return result
    }

    return sentences(from: 0)
}

for sentence in allSentences("nowhere", ["no", "now", "where", "here", "w", "he", "re"]).sorted() {
    print(sentence)
}
print(allSentences("icecreamcones", ["ice", "cream", "icecream", "cone"]))
for n in [5, 10, 20] {
    print(n, allSentences(String(repeating: "a", count: n), ["a", "aa"]).count)
}
print(allSentences(String(repeating: "a", count: 1_000) + "b", ["a", "aa", "aaa"]).count)
```

```output
no w he re
no w here
no where
now he re
now here
[]
5 8
10 89
20 10946
0
```

What to notice:

- The end of the text returns `[""]`, one sentence with no words, not `[]`. Returning `[]` would mean "no way to finish", and every sentence would vanish.
- The memo is a `[Int: [String]]`, read with single lookups. It's never printed, since a dictionary's order isn't fixed.
- The last line: 1,000 a's and a b, with no possible sentence. The memo means each start is explored once, so it fails fast. Without it, the recursion would try an astronomical number of splits of the a's.

## When the output itself is exponential

Look at the counts for n a's with the words `"a"` and `"aa"`: 8, 89, 10,946. They're Fibonacci numbers: a split of n a's starts with `"a"` (then n − 1 remain) or `"aa"` (then n − 2 remain). At 30 a's there are 1,346,269 sentences.

No algorithm can list a million sentences faster than it takes to write them down. So Word break II has **no polynomial-time solution in terms of the input size**: the output alone can be exponential. What you can promise is that the work is proportional to the output (plus the polynomial cost of the DP), with no wasted exploration of dead ends. That's what the memo buys.

This is worth saying out loud in an interview. "The answer can be exponentially large, so the best possible is output-sensitive; memoisation makes sure we never explore a dead end twice" shows you understand where the cost comes from.

Two practical refinements:

- **Run word break I first.** If `ok[n]` is false, return `[]` without building anything. More generally, compute which suffixes can be finished, and only recurse into those.
- **Memoise positions, not strings.** Storing lists of sentences in the memo can take a lot of memory when the output is large. An alternative stores, for each start, only the list of word ends that lead to a finish, and builds the sentences in one final backtracking pass.

<Callout kind="gotcha" title="Common mistakes">
- **`ok[0] = false`.** The empty prefix is the base case; with it false, nothing is ever splittable.
- **Building substrings longer than any word.** Cap the inner loop at the longest word. Without the cap, each step can build an O(n) string, and the DP quietly becomes O(n³).
- **Returning `[]` at the end of the text.** It must be `[""]`: one complete sentence with no more words.
- **Duplicate words in the dictionary.** Put them in a `Set` first, or the same sentence appears twice.
- **Expecting a fixed order.** Sentences can come out in any order. Sort before comparing, as the tests do.
</Callout>
