## Why it matters

`*.swift` in a terminal, `LIKE "rep?rt*"` in an `NSPredicate`, the search box that accepts `IMG_20*`: **wildcard** patterns are everywhere. Regular expressions go further, and the core of their `.` and `*` fits in one DP table too. Both are hard interview problems because the star can match any amount of text, so a naive matcher tries every amount. The table removes the guessing. The difficulty is all in the details: the empty-pattern row, the star cases and the tests.

## Wildcards: `?` and `*`

A wildcard pattern matches the **whole** text when:

- a letter matches that same letter;
- `?` matches exactly one character, whatever it is;
- `*` matches any sequence of characters, including none.

So `"*.swift"` matches `"report.swift"`, `"r*t"` matches it too (r, then anything, then t), and `"*.md"` doesn't.

### Why plain recursion struggles

The natural first attempt asks "does `text[i...]` match `pattern[j...]`?" and, at a star, tries both options: the star matches nothing, or it eats one more character and stays.

```swift run
var calls = 0

/// Plain recursion: does t[i...] match p[j...]?
func matches(_ t: [Character], _ p: [Character], _ i: Int, _ j: Int) -> Bool {
    calls += 1
    if j == p.count {
        return i == t.count                              // pattern used up: text must be too
    }
    if p[j] == "*" {
        return matches(t, p, i, j + 1)                   // the star matches nothing
            || (i < t.count && matches(t, p, i + 1, j))  // or one more character
    }
    return i < t.count && (p[j] == "?" || p[j] == t[i]) && matches(t, p, i + 1, j + 1)
}

for length in [10, 20, 40] {
    calls = 0
    let text = Array(String(repeating: "a", count: length))
    let result = matches(text, Array("*a*a*a*b"), 0, 0)
    print(length, result, calls)
}
```

```output
10 false 1122
20 false 15092
40 false 225582
```

It's correct, and it's the brute force the tests compare against. But with no b at the end, it tries every way of sharing the a's between the stars before giving up, and each extra star multiplies the work by roughly the text length. There are only 41 × 9 different `(i, j)` pairs here; the rest is repetition.

### The table

Turn it into a table on prefixes, with [the DP recipe](/dsa/learn/dp-recipe):

- **State.** `M(i, j)` = do the first i characters of the text match the first j characters of the pattern?
- **Transition**, looking at the pattern's last character `p[j - 1]`:
  - a **star**: it matches nothing, so `M(i, j - 1)`; or it swallows `t[i - 1]` and stays available for more, so `M(i - 1, j)`;
  - `?` or the same letter as `t[i - 1]`: one character for one character, `M(i - 1, j - 1)`;
  - anything else: false.
- **Base cases**, which are where bugs live:
  - `M(0, 0)` is true: the empty pattern matches the empty text;
  - `M(i, 0)` is false for i > 0: the empty pattern matches nothing else;
  - `M(0, j)`, the **empty-text row**, is true only while the pattern so far is all stars. The star rule handles it on its own: `M(0, j) = M(0, j - 1)` for a star, and false for anything else.
- **Order.** Row by row. **Answer.** `M(n, m)`.

```swift run
/// Does the whole of `text` match `pattern`? '?' matches any one character, '*' any run (even empty).
func wildcardMatch(_ text: String, _ pattern: String) -> Bool {
    let t = Array(text), p = Array(pattern)
    var match = Array(repeating: Array(repeating: false, count: p.count + 1), count: t.count + 1)
    for i in 0...t.count {
        for j in 0...p.count {
            if j == 0 {
                match[i][j] = i == 0                            // the empty pattern matches only ""
            } else if p[j - 1] == "*" {
                match[i][j] = match[i][j - 1]                   // the star matches nothing
                    || (i > 0 && match[i - 1][j])               // or it swallows t[i - 1] too
            } else if i > 0 && (p[j - 1] == "?" || p[j - 1] == t[i - 1]) {
                match[i][j] = match[i - 1][j - 1]               // one character for one character
            }
        }
    }
    return match[t.count][p.count]
}

let cases = [("report.swift", "*.swift"), ("report.swift", "*.sw?ft"), ("report.swift", "r*t"),
             ("report.swift", "*.md"), ("", "*"), ("", "?"), ("abc", "a**c"), ("abc", "")]
for (text, pattern) in cases {
    print("\"\(text)\" ~ \"\(pattern)\":", wildcardMatch(text, pattern))
}
```

```output
"report.swift" ~ "*.swift": true
"report.swift" ~ "*.sw?ft": true
"report.swift" ~ "r*t": true
"report.swift" ~ "*.md": false
"" ~ "*": true
"" ~ "?": false
"abc" ~ "a**c": true
"abc" ~ "": false
```

Here's the whole table for the text `"abcb"` and the pattern `"*?b"` (T for true):

```text
  ∅ * ? b
∅ T T . .
a . T T .
b . T T T
c . T T .
b . T T T
```

Read it like this. The empty-text row is T under ∅ and the star, then false: `"?"` needs a character. The star column is T all the way down: `"*"` matches any prefix. The b column is T exactly where the text so far ends in b with at least one character before it. The corner is T, so it matches.

The star's "swallow and stay" step, `M(i - 1, j)`, is what makes this O(n · m). The recursion tried every length for the star separately; the table asks only "one more character?", and the cell above already knows the answer for all shorter lengths.

## Regex lite: `.` and `*`

Regular expressions change the meaning of the star. In this "regex lite":

- a letter matches itself, and `.` matches any one character;
- `*` means **zero or more copies of the element before it**. So `"a*"` matches `""`, `"a"`, `"aa"` and so on, and `".*"` matches anything.

A star always follows a letter or a dot, so think of `x*` as one unit. The state is the same, `M(i, j)` on prefixes. The transitions:

- `p[j - 1]` is a **star**, so the unit is `p[j - 2]` followed by the star:
  - **zero copies**: drop the whole unit, `M(i, j - 2)`;
  - **one more copy**: if `p[j - 2]` matches `t[i - 1]` (same letter, or a dot), the unit swallows it and stays, `M(i - 1, j)`.
- `.` or the same letter: `M(i - 1, j - 1)`.
- otherwise false.

The empty-text row changes too. `M(0, j)` is true when the pattern so far is made of `x*` units that can all vanish, like `"a*b*.*"`. The zero-copies rule, `M(0, j - 2)`, handles it.

```swift run
/// Does the whole of `text` match `pattern`? '.' matches any one character, and 'x*' matches
/// zero or more copies of x (x is a letter or '.'). A '*' never starts the pattern.
func regexMatch(_ text: String, _ pattern: String) -> Bool {
    let t = Array(text), p = Array(pattern)
    var match = Array(repeating: Array(repeating: false, count: p.count + 1), count: t.count + 1)
    for i in 0...t.count {
        for j in 0...p.count {
            if j == 0 {
                match[i][j] = i == 0                             // the empty pattern matches only ""
            } else if p[j - 1] == "*" {
                let none = match[i][j - 2]                       // use x* zero times
                let oneMore = i > 0 && (p[j - 2] == "." || p[j - 2] == t[i - 1]) && match[i - 1][j]
                match[i][j] = none || oneMore
            } else if i > 0 && (p[j - 1] == "." || p[j - 1] == t[i - 1]) {
                match[i][j] = match[i - 1][j - 1]
            }
        }
    }
    return match[t.count][p.count]
}

let cases = [("colour", "colou*r"), ("color", "colou*r"), ("aab", "c*a*b"), ("swift", "s.*t"),
             ("", "a*b*"), ("ab", ".*c"), ("aaa", "a*a"), ("a", ".*..")]
for (text, pattern) in cases {
    print("\"\(text)\" ~ \"\(pattern)\":", regexMatch(text, pattern))
}
```

```output
"colour" ~ "colou*r": true
"color" ~ "colou*r": true
"aab" ~ "c*a*b": true
"swift" ~ "s.*t": true
"" ~ "a*b*": true
"ab" ~ ".*c": false
"aaa" ~ "a*a": true
"a" ~ ".*..": false
```

What to notice:

- `"colou*r"` makes the u optional: zero copies for "color", one for "colour".
- `"c*a*b"` matches `"aab"` with zero c's. That's the zero-copies rule, `M(i, j - 2)`, jumping over the whole `c*` unit.
- `p[j - 2]` is safe to read because a valid pattern never starts with a star, so a star at `j - 1` means j is at least 2.

### Side by side

| | Wildcard | Regex lite |
| --- | --- | --- |
| any one character | `?` | `.` |
| star means | any run of characters | zero or more of the previous element |
| star matches nothing | `M(i, j - 1)` | `M(i, j - 2)`, the whole unit vanishes |
| star takes one more | `M(i - 1, j)`, always allowed | `M(i - 1, j)`, only if `p[j - 2]` matches `t[i - 1]` |
| empty-text row true while | the pattern is all stars | the pattern is all `x*` units |

## Testing pattern matchers

Matchers are easy to get almost right. A list of tests worth writing every time:

- **Empties**: `("", "")` true; `("a", "")` false; `("", "a")` false; `("", "*")` true for wildcards; `("", "a*")` true for regex.
- **Only stars**: `"***"` matches everything, including `""`.
- **Stars at the edges**: `"*abc"`, `"abc*"`, and a pattern ending in `"?"` or `"."` that needs one more character than the text has.
- **Overlapping choices**: `("aaa", "a*a")` (regex), `("mama", "*ma")` (wildcard), where a greedy star that eats everything fails.
- **Brute force**: run the plain recursion against the table on thousands of random short texts and patterns over a two-letter alphabet. Small alphabets create the awkward overlaps far more often than real text.

The plain recursion above makes a perfect test oracle: slow, obviously correct, and only used on tiny inputs.

<Callout kind="gotcha" title="Common mistakes">
- **The empty-text row.** It's not all false: leading stars (wildcard) or `x*` units (regex) match the empty text. Let the star rule fill it, as the code does, instead of special-casing it.
- **Regex star with `j - 1` instead of `j - 2`.** `x*` is a two-character unit. Dropping only the star leaves an x that must match once.
- **Forgetting that the regex star needs a match to repeat.** `M(i - 1, j)` only counts if `p[j - 2]` matches `t[i - 1]`.
- **Partial matches.** These patterns must match the whole text. If a problem wants "anywhere in the text", that's a different question (wrap the wildcard pattern in stars).
- **Greedy stars.** Letting a star eat as much as possible and never backing off fails on `("mama", "*ma")`. The table tries every amount for you.
</Callout>

The wildcard problem also has a clever two-pointer solution that remembers the last star and backtracks to it; it's fast in practice but subtle to prove. The table is the version to reach for under pressure.
