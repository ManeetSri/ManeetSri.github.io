## Why it matters

Plagiarism checkers look for the longest passage two essays share word for word. Genome tools look for the longest stretch of DNA two species have in common. Both want a **substring**: characters that sit side by side in both strings, not scattered like a subsequence. The DP is a small but important twist on [the LCS table](/dsa/learn/dps-lcs): the state changes from "the best so far" to "the run ending exactly here". That "ending here" idea comes back again and again in DP.

## Substring, not subsequence

A **substring** is a contiguous piece: `"ograph"` is a substring of `"photograph"`, but `"pgrh"` is only a subsequence. For `"photograph"` and `"tomography"`:

| Question | Answer |
| --- | --- |
| Longest common subsequence | 7, for example `"tograph"` |
| Longest common substring | 6, `"ograph"` |

The substring can never be longer than the subsequence, because every common substring is also a common subsequence.

Brute force tries every substring of one string and searches for it in the other: about n²/2 substrings, each searched in O(n · m) or so. Far too slow for strings of a few thousand characters.

## The state: the run that ends here

Try copying LCS: "the longest common substring of the first i and first j characters". The transition breaks down. When `a[i - 1] == b[j - 1]`, you can only extend the best substring if it **ended** at the previous characters, and the "best so far" doesn't tell you that.

So ask a narrower question, using [the DP recipe](/dsa/learn/dp-recipe):

- **State.** `C(i, j)` = the length of the longest common substring that **ends exactly** at `a[i - 1]` and `b[j - 1]`.
- **Transition.** If the two characters match, the run ending at the previous pair grows by one: `C(i, j) = C(i - 1, j - 1) + 1`. If they differ, no common substring ends at both: `C(i, j) = 0`.
- **Base case.** Row 0 and column 0 are 0.
- **Order.** Each cell reads only its diagonal neighbour, so row by row works.
- **Answer.** The longest substring ends **somewhere**, so the answer is the largest cell anywhere in the table, not the corner.

```swift run
let a = Array("ABAB"), b = Array("BABA")
var table = Array(repeating: Array(repeating: 0, count: b.count + 1), count: a.count + 1)
for i in 0...a.count {
    for j in 0...b.count {
        if i == 0 || j == 0 {
            table[i][j] = 0
        } else if a[i - 1] == b[j - 1] {
            table[i][j] = table[i - 1][j - 1] + 1     // the common run grows by one
        } else {
            table[i][j] = 0                           // a mismatch breaks the run
        }
    }
}
print("  ∅ " + b.map(String.init).joined(separator: " "))
for i in 0...a.count {
    let label = i == 0 ? "∅" : String(a[i - 1])
    print(label + " " + table[i].map(String.init).joined(separator: " "))
}
```

```output
  ∅ B A B A
∅ 0 0 0 0 0
A 0 0 1 0 1
B 0 1 0 2 0
A 0 0 2 0 3
B 0 1 0 3 0
```

What to notice:

- Common substrings are **diagonal runs** of growing numbers: 1, 2, 3 down a diagonal is a 3-character match.
- The 3 in row A (column A) is `"ABA"` ending at `a[2]` and `b[3]`; the 3 in row B is `"BAB"`. Two different answers of the same length.
- The bottom-right cell is 0. Returning the corner, out of LCS habit, would say there's no common substring at all.

Compare with LCS: on a mismatch, LCS **carries** the best value from above or the left, because a subsequence can skip characters. A substring can't skip, so the run **resets** to 0. That one line is the whole difference.

## Tracking the best cell

To return the substring itself, remember the best length and where it ended while you fill. A substring of length L ending just before `a[end]` is `a[(end - L)..<end]`:

```swift run
/// The longest common substring. Among equally long ones, the one that ends first in `first`.
func longestCommonSubstring(_ first: String, _ second: String) -> String {
    let a = Array(first), b = Array(second)
    var table = Array(repeating: Array(repeating: 0, count: b.count + 1), count: a.count + 1)
    var bestLength = 0
    var bestEnd = 0                                   // the best run ends just before a[bestEnd]
    for i in 0...a.count {
        for j in 0...b.count {
            if i > 0 && j > 0 && a[i - 1] == b[j - 1] {
                table[i][j] = table[i - 1][j - 1] + 1
                if table[i][j] > bestLength {         // strictly longer: keep the earlier one on ties
                    bestLength = table[i][j]
                    bestEnd = i
                }
            }                                         // otherwise it stays 0
        }
    }
    return String(a[(bestEnd - bestLength)..<bestEnd])
}

print(longestCommonSubstring("photograph", "tomography"))
print(longestCommonSubstring("ABAB", "BABA"))
print(longestCommonSubstring("swift", "shift"))
print(longestCommonSubstring("abc", "xyz").isEmpty)
```

```output
ograph
ABA
ift
true
```

The table starts full of zeros, so the mismatch branch has nothing to do. The tie rule falls out of the loop order: rows are visited in order of where the substring ends in `first`, and only a strictly longer run replaces the best. So among equally long runs, the one ending (and therefore starting) earliest in `first` wins: `"ABA"` beats `"BAB"`.

When there are no common characters, `bestLength` stays 0, the slice is empty, and the empty string comes back without any special case.

## One row is enough

Each cell reads only its upper-left neighbour. With a single row, cell `j` needs the **previous** row's value at `j - 1`. If you sweep j from right to left, `row[j - 1]` hasn't been overwritten yet when you read it:

```swift run
/// Length only, with one row. j runs downwards so row[j - 1] still holds the previous row's value.
func commonSubstringLength(_ first: String, _ second: String) -> Int {
    let a = Array(first), b = Array(second)
    var row = Array(repeating: 0, count: b.count + 1)
    var best = 0
    for i in 0..<a.count {
        for j in stride(from: b.count, through: 1, by: -1) {
            row[j] = a[i] == b[j - 1] ? row[j - 1] + 1 : 0
            best = max(best, row[j])
        }
    }
    return best
}

print(commonSubstringLength("photograph", "tomography"))
print(commonSubstringLength("aaaa", "aaa"))
print(commonSubstringLength("", "abc"))
```

```output
6
3
0
```

Sweeping left to right instead would read `row[j - 1]` from the **current** row: a run that ends at the same character of a, but one character earlier in b. Runs then grow along the row instead of the diagonal. For `"a"` and `"aaa"` it reports 3, though the first string has only one character. It's the same direction trick as in [0/1 knapsack, from 2D to 1D](/dsa/learn/dpk-01): whenever a 1D DP reads "the previous row, further left", sweep right to left.

## How fast, and what's faster

The table costs **O(n · m)** time. With one row, memory is **O(m)**, plus nothing for the answer: you only store where it ends. For two strings of 2,000 characters that's 4 million cheap steps.

For very long texts (whole genomes), there are faster methods: binary search on the length with rolling hashes, or suffix structures that do it in linear time. Those belong to the advanced string algorithms of M63. For interview-sized inputs, the table is the expected answer.

<Callout kind="gotcha" title="Common mistakes">
- **Returning the corner.** The longest common substring can end anywhere; track the maximum while filling.
- **Carrying values on a mismatch.** `max(above, left)` is LCS. For substrings, a mismatch is 0.
- **Ascending j with one row.** It reads a value already overwritten in this row. Go from right to left, or keep two rows.
- **Building a `String` per cell.** Keep a length and an end index; slice once at the end.
- **Ties.** If the problem fixes which answer to return, check that your loop order and `>` versus `>=` produce exactly that one.
</Callout>
