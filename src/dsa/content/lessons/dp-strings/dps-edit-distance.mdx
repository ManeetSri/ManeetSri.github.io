## Why it matters

Type "speling" into a search box and it offers "spelling". Search your contacts for "Jonh" and John still turns up. Both measure how far apart two words are by the fewest single-character edits between them: the **edit distance**, also called **Levenshtein distance**. It powers spell checkers, fuzzy search, DNA alignment and "did you mean?" suggestions, and it's one of the most asked DP questions in interviews. The table looks like the one in [Longest common subsequence, and printing it](/dsa/learn/dps-lcs), with three arrows instead of two.

## Three operations

Turn a **source** string into a **target** string using single-character edits, each costing 1:

- **insert** a character;
- **delete** a character;
- **replace** a character with a different one.

`"kitten"` becomes `"sitting"` in three: replace k with s, replace e with i, insert g at the end. There's no way to do it in two, so the distance is 3.

Edit distance is symmetric: run the script backwards, swapping insert and delete, and you turn the target back into the source in the same number of edits.

## The state and the three arrows

Follow [the DP recipe](/dsa/learn/dp-recipe) on prefixes, as in LCS.

**State.** `D(i, j)` = the fewest edits that turn the first i characters of a into the first j characters of b.

**Transition.** Look at the last characters, `a[i - 1]` and `b[j - 1]`. Think about what the **last** edit of an optimal script does to them:

- **They match.** Leave them alone and fix the rest: `D(i - 1, j - 1)`.
- **Replace** `a[i - 1]` with `b[j - 1]`, then fix the rest: `D(i - 1, j - 1) + 1`.
- **Delete** `a[i - 1]`: turn the first i − 1 characters of a into all j of b, `D(i - 1, j) + 1`.
- **Insert** `b[j - 1]` at the end: turn all i characters of a into the first j − 1 of b, `D(i, j - 1) + 1`.

In the table, those are three arrows into cell `(i, j)`: the **diagonal** (match or replace), **from above** (delete) and **from the left** (insert).

**Base case.** This is where edit distance differs from LCS. Row 0 and column 0 aren't zero:

- `D(0, j) = j`: building j characters from nothing takes j insertions.
- `D(i, 0) = i`: reducing i characters to nothing takes i deletions.

**Order.** Row by row, left to right. **Answer.** `D(n, m)`, the corner.

When the characters match, the free diagonal is always at least as good as the other options. Neighbouring cells differ by at most 1, so `D(i - 1, j) + 1` and `D(i, j - 1) + 1` are never below `D(i - 1, j - 1)`. That's why the code can skip the minimum on a match.

```swift run
func editTable(_ a: [Character], _ b: [Character]) -> [[Int]] {
    let n = a.count, m = b.count
    var table = Array(repeating: Array(repeating: 0, count: m + 1), count: n + 1)
    for i in 0...n {
        for j in 0...m {
            if i == 0 {
                table[i][j] = j                             // build b's first j letters by inserting
            } else if j == 0 {
                table[i][j] = i                             // delete all i letters of a
            } else if a[i - 1] == b[j - 1] {
                table[i][j] = table[i - 1][j - 1]           // same letter: no edit needed
            } else {
                table[i][j] = 1 + min(table[i - 1][j - 1],  // replace a[i - 1] with b[j - 1]
                                      table[i - 1][j],      // delete a[i - 1]
                                      table[i][j - 1])      // insert b[j - 1]
            }
        }
    }
    return table
}

let a = Array("kitten"), b = Array("sitting")
let table = editTable(a, b)
print("  ∅ " + b.map(String.init).joined(separator: " "))
for i in 0...a.count {
    let label = i == 0 ? "∅" : String(a[i - 1])
    print(label + " " + table[i].map(String.init).joined(separator: " "))
}
print("distance:", table[a.count][b.count])
```

- Along the diagonal, matching letters (i, t, t, n) copy the cell up and to the left unchanged.

## Reconstructing the edits

The distance alone says "3". A spell checker that highlights the changes, or a diff that shows them, needs the edits themselves. As with the LCS traceback, start at the corner and ask which arrow explains each cell's value:

- the characters match and the value equals the diagonal: **keep**, step diagonally;
- the value is the diagonal plus 1: **replace**, step diagonally;
- the value is the cell above plus 1: **delete**, step up;
- otherwise it must be the cell to the left plus 1: **insert**, step left.

Once you reach row 0, only insertions remain; in column 0, only deletions. The steps come out last-first, so reverse them.

```swift run
func editTable(_ a: [Character], _ b: [Character]) -> [[Int]] {
    let n = a.count, m = b.count
    var table = Array(repeating: Array(repeating: 0, count: m + 1), count: n + 1)
    for i in 0...n {
        for j in 0...m {
            if i == 0 {
                table[i][j] = j
            } else if j == 0 {
                table[i][j] = i
            } else if a[i - 1] == b[j - 1] {
                table[i][j] = table[i - 1][j - 1]
            } else {
                table[i][j] = 1 + min(table[i - 1][j - 1], table[i - 1][j], table[i][j - 1])
            }
        }
    }
    return table
}

/// The edits, in order, that turn `first` into `second` with the fewest steps
func editScript(_ first: String, _ second: String) -> [String] {
    let a = Array(first), b = Array(second)
    let table = editTable(a, b)
    var steps: [String] = []
    var i = a.count, j = b.count
    while i > 0 || j > 0 {
        if i > 0 && j > 0 && a[i - 1] == b[j - 1] && table[i][j] == table[i - 1][j - 1] {
            steps.append("keep \(a[i - 1])")
            i -= 1
            j -= 1
        } else if i > 0 && j > 0 && table[i][j] == table[i - 1][j - 1] + 1 {
            steps.append("replace \(a[i - 1]) with \(b[j - 1])")
            i -= 1
            j -= 1
        } else if i > 0 && table[i][j] == table[i - 1][j] + 1 {
            steps.append("delete \(a[i - 1])")
            i -= 1
        } else {
            steps.append("insert \(b[j - 1])")
            j -= 1
        }
    }
    return steps.reversed()                           // found back to front
}

for step in editScript("kitten", "sitting") {
    print(step)
}
print("---")
print(editScript("sunday", "saturday").filter { !$0.hasPrefix("keep") })
print(editScript("", "ab"), editScript("ab", ""))
```

```output
replace k with s
keep i
keep t
keep t
replace e with i
keep n
insert g
---
["insert a", "insert t", "replace n with r"]
["insert a", "insert b"] ["delete a", "delete b"]
```

Read the script left to right across the source and it's an **alignment**: every source character is kept, replaced or deleted, and inserts slot new characters in between. Like LCS, ties mean several shortest scripts can exist. The checks above prefer keep, then replace, then delete, then insert; another order gives a different script with the same count. The `i > 0` and `j > 0` guards handle the edges, where only one kind of step is possible.

## Spell checking

A basic spell checker computes the distance from the typo to every dictionary word and suggests the closest. Two practical touches:

- **A limit.** Suggestions more than 2 edits away are rarely useful. While filling row by row, if every cell in a row is above the limit, stop: every cell in the next row is at least the smallest cell in this one, so the final answer can't come back under the limit.
- **Two rows.** Each row reads only the one above it, so the distance needs O(m) memory, not the whole table.

```swift run
/// Edit distance with two rows. Returns nil as soon as every cell in a row is above `limit`,
/// because no later row can dip below this row's smallest value.
func distance(_ first: String, _ second: String, limit: Int) -> Int? {
    let a = Array(first), b = Array(second)
    var previous = Array(0...b.count)                 // row 0: j insertions
    var current = previous
    for i in stride(from: 1, through: a.count, by: 1) {
        current[0] = i
        for j in stride(from: 1, through: b.count, by: 1) {
            if a[i - 1] == b[j - 1] {
                current[j] = previous[j - 1]
            } else {
                current[j] = 1 + min(previous[j - 1], previous[j], current[j - 1])
            }
        }
        if current.min()! > limit {
            return nil                                // too far already: give up on this word
        }
        swap(&previous, &current)
    }
    return previous[b.count] <= limit ? previous[b.count] : nil
}

func suggestions(for typo: String, from words: [String], limit: Int) -> [String] {
    let scored = words.compactMap { word in
        distance(typo, word, limit: limit).map { (word, $0) }
    }
    return scored.sorted { ($0.1, $0.0) < ($1.1, $1.0) }.map { "\($0.0) (\($0.1))" }
}

let words = ["spelling", "spell", "spilling", "selling", "sapling", "swelling", "peeling", "spring", "swift"]
print(suggestions(for: "speling", from: words, limit: 2))
print(suggestions(for: "swfit", from: words, limit: 2))
```

```output
["spelling (1)", "peeling (2)", "sapling (2)", "selling (2)", "spilling (2)", "spring (2)", "swelling (2)"]
["swift (2)"]
```

`"swfit"` to `"swift"` costs 2 with these three operations: two replacements, since swapping neighbours isn't one of them. The **Damerau–Levenshtein** distance adds "transpose two adjacent characters" as a fourth edit, costing 1, because swapped letters are the most common typo of all. It adds one more arrow, from two rows and two columns back.

Real spell checkers don't scan the whole dictionary. They first narrow it down, for example with a trie walked alongside the DP rows, or by precomputing deletions. The DP at the core stays the same.

## Variations on the costs

Change what the operations cost, and the same table answers different questions:

| Allowed edits | What the distance measures |
| --- | --- |
| insert, delete, replace (cost 1 each) | Levenshtein distance |
| insert and delete only | n + m − 2 × LCS |
| replace only, equal lengths | Hamming distance: positions that differ |
| different costs per letter pair | sequence alignment in biology |

The second row connects back to the first lesson: without replace, the cheapest route keeps an LCS and deletes or inserts everything else. For `"kitten"` and `"sitting"`, the LCS `"ittn"` has 4 letters, so it's 6 + 7 − 8 = 5 edits, two more than with replacements.

<Callout kind="gotcha" title="Common mistakes">
- **Zeros in row 0 and column 0.** Copying the LCS base case gives distance 0 between `""` and `"abc"`. The edges are j and i.
- **Mixing up the arrows.** Up is delete (a loses a character), left is insert (b gains one). Swapping them still gives the right distance, because the problem is symmetric, but the script labels every insert as a delete and the other way round.
- **Adding 1 on a match.** Matching characters are free: copy the diagonal.
- **Replacing with the same character.** A "replace" that changes nothing is really a keep; a script that counts it overstates the distance.
- **The full table when you only need the number.** Two rows are enough for the distance; keep the full table only when you need the script.
</Callout>
