## Why it matters

How many ways can you read the word "ban" in "banana", picking letters left to right? Counting the ways a pattern appears as a **subsequence** shows up in text analysis, in bioinformatics (how many ways a motif can be embedded in a sequence), and as a well-known interview problem. It's also the cleanest example of a **counting DP**, where choices are added instead of compared, and of the problem every counting DP soon hits: the numbers get too big for an `Int`.

## The question

Count the ways to choose positions in `text`, left to right, whose letters spell `word`. Two ways are different if they use a different set of positions, even when they spell the same thing (they always spell the same thing).

For `"ban"` in `"banana"` (positions 0 to 5: b a n a n a):

| b | a | n |
| --- | --- | --- |
| 0 | 1 | 2 |
| 0 | 1 | 4 |
| 0 | 3 | 4 |

Three ways. The a at position 5 never helps, because no n comes after it.

Brute force tries every subset of positions: 2ⁿ of them for a text of n letters. Again, you need a table.

## The state and the transition

Use [the DP recipe](/dsa/learn/dp-recipe) on prefixes once more.

- **State.** `W(i, j)` = the number of ways to pick the first j letters of the word out of the first i letters of the text.
- **Transition.** Decide what happens to the text's last letter, `text[i - 1]`:
  - **skip it**: all the ways that use only the first i − 1 letters, `W(i - 1, j)`;
  - **use it** as the word's last letter, allowed only if `text[i - 1] == word[j - 1]`: then the rest of the word comes from earlier letters, `W(i - 1, j - 1)`.

  Every way does exactly one of the two, so the counts **add**: `W(i, j) = W(i - 1, j) + (match ? W(i - 1, j - 1) : 0)`.
- **Base cases.** `W(i, 0) = 1`: there's exactly one way to pick the empty word, by picking nothing. `W(0, j) = 0` for j > 0: no text, no letters to pick.
- **Order.** Row by row. **Answer.** `W(n, m)`.

The base case `W(i, 0) = 1` trips people up. It isn't "zero ways"; it's the one way of choosing nothing, and every complete pick ends by reaching it. Set it to 0 and every count collapses to 0.

```swift run
/// How many ways can `word` be picked out of `text` as a subsequence?
func countWays(_ text: String, _ word: String) -> Int {
    let t = Array(text), w = Array(word)
    var ways = Array(repeating: Array(repeating: 0, count: w.count + 1), count: t.count + 1)
    for i in 0...t.count {
        for j in 0...w.count {
            if j == 0 {
                ways[i][j] = 1                                  // the empty word: pick nothing
            } else if i == 0 {
                ways[i][j] = 0                                  // no text left for a non-empty word
            } else {
                ways[i][j] = ways[i - 1][j]                     // skip t[i - 1]
                if t[i - 1] == w[j - 1] {
                    ways[i][j] += ways[i - 1][j - 1]            // or use it for w[j - 1]
                }
            }
        }
    }
    return ways[t.count][w.count]
}

print(countWays("banana", "ban"))
print(countWays("banana", "ana"))
print(countWays("banana", "nab"))
print(countWays("aaaa", "aa"))
print(countWays("swift", ""))
```

```output
3
4
0
6
1
```

`"aa"` in `"aaaa"` is 6, which is C(4, 2): any two of the four a's. With a word of repeated letters, the count is a binomial coefficient, as in [Factorials, permutations and combinations](/dsa/learn/math-counting). That's a hint of how fast these numbers grow.

Compare with LCS: the same table shape, but LCS **maximises** over the choices and this **adds** them. Optimisation DPs take `max` or `min`; counting DPs take a sum, and the sum is only right when the choices don't overlap. Here they can't: a way either uses `text[i - 1]` or it doesn't.

## One row, from the right

Row i reads only row i − 1, at j and j − 1. As in [0/1 knapsack, from 2D to 1D](/dsa/learn/dpk-01), keep a single row and sweep j from **right to left**, so `ways[j - 1]` still holds the previous row's value when you read it:

```swift run
func countWays(_ text: String, _ word: String) -> Int {
    let w = Array(word)
    var ways = Array(repeating: 0, count: w.count + 1)
    ways[0] = 1                                         // the empty word, in every row
    for letter in text {
        for j in stride(from: w.count, through: 1, by: -1) where w[j - 1] == letter {
            ways[j] += ways[j - 1]                      // using this letter as w[j - 1]
        }
    }
    return ways[w.count]
}

print(countWays("banana", "ban"), countWays("aaaa", "aa"))
```

```output
3 6
```

Sweep left to right and a single text letter could be used twice in one pick: for `"aa"` in `"a"`, `ways[1]` becomes 1 and then `ways[2]` immediately adds it, giving 1 instead of 0. Right to left means each text letter plays at most one role per pick.

## When the count doesn't fit

How many ways are there to pick 30 a's out of 70? C(70, 30) = 55,347,740,058,143,507,128, about 5.5 × 10¹⁹. `Int.max` is about 9.2 × 10¹⁸. Somewhere in the middle of the table, an addition overflows, and Swift stops the program rather than wrap around:

```text title="What you'll see"
Swift runtime failure: arithmetic overflow
```

That's the trap from [Overflow traps and overflow operators](/dsa/learn/swift-overflow). Problems with huge counts almost always say "return the answer modulo 1,000,000,007", and now you can see why: the true answer doesn't fit in 64 bits.

### Counting modulo a prime

[Modular arithmetic](/dsa/learn/math-modular-arithmetic) lets you keep every number small. Addition works modulo m: take the remainder after every addition, and the final remainder is the same as if you'd computed the huge number first.

```swift run
let modulus = 1_000_000_007

/// The number of ways, modulo 1,000,000,007
func countWays(_ text: String, _ word: String) -> Int {
    let w = Array(word)
    var ways = Array(repeating: 0, count: w.count + 1)
    ways[0] = 1
    for letter in text {
        for j in stride(from: w.count, through: 1, by: -1) where w[j - 1] == letter {
            ways[j] = (ways[j] + ways[j - 1]) % modulus     // both are below the modulus, so the sum fits
        }
    }
    return ways[w.count]
}

print(countWays("banana", "ban"))
print(countWays(String(repeating: "a", count: 70), String(repeating: "a", count: 30)))
```

```output
3
709329438
```

Why 1,000,000,007? It's a prime a little above 10⁹. Two numbers below it add to less than 2.1 × 10⁹, and multiply to less than 1.1 × 10¹⁸, so sums and products both fit in an `Int` with room to spare. Being prime matters for division with modular inverses, which you'll meet in M66. This lesson only adds, subtracts and doubles.

Two things the modulus takes away:

- **Comparisons.** `709329438` isn't "smaller" than the true count in any useful sense. You can't take the `max` of reduced numbers, so modulo only works for counting DPs, not optimisation ones.
- **Checking with small cases.** Below the modulus, the answer is the true count. Test on small inputs first, where you can count by hand.

## A cousin: distinct subsequences of one string

The other famous "distinct subsequences" problem counts how many **different** strings appear as subsequences of one text. `"aba"` has a, b, ab, aa, ba and aba: 6. Counting positions would give 7, because a appears twice.

The trick: each new letter doubles the count (every old subsequence, with or without the new letter), except that subsequences ending in this letter were already created the last time the letter appeared. Subtract the count from just before that last appearance:

```swift run
let modulus = 1_000_000_007

/// How many different non-empty strings are subsequences of `text`?
func distinctSubsequences(_ text: String) -> Int {
    var total = 1                                   // the empty subsequence, removed at the end
    var before: [Character: Int] = [:]              // total just before the letter's last use
    for letter in text {
        let previous = total
        total = (total * 2) % modulus               // every old subsequence, with and without letter
        if let repeated = before[letter] {
            total = (total - repeated + modulus) % modulus   // these were counted last time
        }
        before[letter] = previous
    }
    return (total - 1 + modulus) % modulus
}

print(distinctSubsequences("abc"))
print(distinctSubsequences("aba"))
print(distinctSubsequences("aaa"))
print(distinctSubsequences(String(repeating: "swift", count: 200)))
```

```output
7
6
3
18800875
```

Notice `+ modulus` before every `%` after a subtraction. Reduced numbers can make `total - repeated` negative even though the true count isn't, and Swift's `%` keeps the sign of the left side: `-3 % 7` is `-3`, not 4. Adding the modulus first keeps the result in range.

<Callout kind="gotcha" title="Common mistakes">
- **`W(i, 0) = 0`.** The empty word has exactly one way: pick nothing. With 0, every count is 0.
- **Taking `max` instead of adding.** That's an optimisation DP; counting adds disjoint choices.
- **Sweeping j left to right in one row.** A text letter gets used twice in one pick.
- **Overflow.** Counts grow like binomial coefficients. Reduce modulo after every addition, not once at the end.
- **Negative remainders.** After a subtraction, add the modulus before taking `%`.
</Callout>
