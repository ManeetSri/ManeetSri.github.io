## Why it matters

Two log files are merged into one by timestamp: is the merged file really just the two logs woven together, each in its own order? Two playlists are shuffled into one queue without reordering either: could this queue have come from them? That's **interleaving**, a two-string DP with a twist: there's a third string, and its position is fixed by the other two. Then **scramble strings**, a puzzle about recursively splitting and swapping, shows what happens when the state needs three numbers and plain recursion is the clearest way to write the DP. Both are favourites in competitive programming and appear in harder interviews.

## Interleaving two strings

`c` is an **interleaving** of `a` and `b` if you can build `c` by repeatedly taking the next character from either a or b, until both are used up. Each string keeps its own order; the two are woven together.

With a = `"ab"` and b = `"ac"`:

| c | Interleaving? | Why |
| --- | --- | --- |
| `"acab"` | yes | all of b (`ac`), then all of a (`ab`) |
| `"aabc"` | yes | a from a, a from b, b from a, c from b |
| `"abca"` | no | after `ab` from a, b offers only its own `a` first, not `c` |

Two quick checks rule many cases out at once: `c.count` must equal `a.count + b.count`, and c must use exactly their letters.

### Why greedy fails

The obvious approach: walk through c, and take each character from a if a's next character fits, otherwise from b.

```swift run
/// Greedy: take from `a` whenever its next letter fits. Fast, and wrong.
func greedyInterleaving(_ first: String, _ second: String, _ merged: String) -> Bool {
    let a = Array(first), b = Array(second), c = Array(merged)
    guard a.count + b.count == c.count else { return false }
    var i = 0, j = 0
    for letter in c {
        if i < a.count && a[i] == letter {
            i += 1
        } else if j < b.count && b[j] == letter {
            j += 1
        } else {
            return false
        }
    }
    return true
}
print(greedyInterleaving("ab", "ac", "acab"))
```

```output
false
```

c starts with a, and both strings start with a. Greedy takes it from a, then needs a c, which a can't give and b (still at its a) can't either. Taking the first a from b was the right choice, but nothing at that moment says so. When both strings offer the same character, you have to keep both possibilities open. That's a DP.

### The table

- **State.** `I(i, j)` = can the first i characters of a and the first j characters of b form the first i + j characters of c? Notice that c's position is **determined**: it's always i + j. That's why two indices are enough for three strings.
- **Transition.** The last character used, `c[i + j - 1]`, came either from a or from b:
  - from a: `a[i - 1] == c[i + j - 1]` and `I(i - 1, j)`;
  - from b: `b[j - 1] == c[i + j - 1]` and `I(i, j - 1)`.

  `I(i, j)` is true if either works.
- **Base case.** `I(0, 0)` is true: nothing from nothing.
- **Order.** Row by row. **Answer.** `I(n, m)`.

```swift run
/// Can `merged` be formed by interleaving `a` and `b`, keeping each one's own order?
func isInterleaving(_ first: String, _ second: String, _ merged: String) -> Bool {
    let a = Array(first), b = Array(second), c = Array(merged)
    guard a.count + b.count == c.count else { return false }
    // can[i][j]: a's first i letters and b's first j letters can form c's first i + j letters
    var can = Array(repeating: Array(repeating: false, count: b.count + 1), count: a.count + 1)
    for i in 0...a.count {
        for j in 0...b.count {
            if i == 0 && j == 0 {
                can[i][j] = true                                       // nothing from nothing
            } else {
                let fromA = i > 0 && can[i - 1][j] && a[i - 1] == c[i + j - 1]   // last letter came from a
                let fromB = j > 0 && can[i][j - 1] && b[j - 1] == c[i + j - 1]   // or from b
                can[i][j] = fromA || fromB
            }
        }
    }
    return can[a.count][b.count]
}

print(isInterleaving("ab", "ac", "acab"))
print(isInterleaving("ab", "ac", "aabc"))
print(isInterleaving("ab", "ac", "abca"))
print(isInterleaving("ab", "ac", "acba"))
print(isInterleaving("", "", ""))
print(isInterleaving("abc", "", "abc"))
```

```output
true
true
false
false
true
true
```

What to notice:

- A true cell is a **path** from the top-left corner: every step down takes a character from a, every step right takes one from b. c is an interleaving exactly when some path of matching steps reaches the bottom-right corner. It's the grid-path picture from [Unique paths I and II](/dsa/learn/dpg-unique-paths), with "is this step allowed?" decided by c.
- The length guard comes first. Without it, `c[i + j - 1]` can run past the end of a shorter c.
- Row 0 (nothing from a yet) is true only while b's prefix equals c's prefix, and column 0 likewise for a. The general rule fills them; no special code needed.

It's **O(n · m)** time. Each row reads only itself and the row above, so one row of m + 1 Booleans is enough: `can[j]` still holds the previous row's value when you read it for "from a", and `can[j - 1]` already holds this row's value for "from b". The problem's reference solution does exactly that.

A memoised recursion over `(i, j)` works just as well, and some find it easier to write. But it goes up to n + m calls deep. For two strings of 50,000 characters that's 100,000 frames, far past what [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) allows; the table has no such limit.

## Scramble strings

Here's a stranger way to mix up a string. To **scramble** it:

1. If it has one character, stop.
2. Otherwise, split it into two non-empty parts, at any point.
3. Either keep the parts in order or swap them.
4. Scramble each part, recursively.

From `"swift"`: split as `"sw"` and `"ift"`, swap to get `"ift" + "sw"`; then scramble `"ift"` by splitting it into `"i"` and `"ft"` and swapping, giving `"fti"`. The result is `"ftisw"`, a scramble of `"swift"`.

The question: given `source` and `target`, is target a scramble of source?

### Three numbers in the state

To compare two pieces, you need where each piece starts and how long it is (they're always the same length). So the state is a triple:

- **State.** `S(i, j, length)` = is `target[j..<j + length]` a scramble of `source[i..<i + length]`?
- **Transition.** Try every split point k from 1 to length − 1:
  - **kept in order**: the first k characters match the first k, and the rest match the rest: `S(i, j, k) && S(i + k, j + k, length - k)`;
  - **swapped**: source's first k characters match target's **last** k, and source's rest matches target's first `length - k`: `S(i, j + length - k, k) && S(i + k, j, length - k)`.
- **Base case.** Length 1: the two characters must be equal.
- **Answer.** `S(0, 0, n)`.

The subproblems are many but there are only about n³ of them: n starts in each string, times n lengths. Filling a three-dimensional table in the right order is fiddly (by length, shortest first), so this is a good place for **memoised recursion**: write the recurrence directly, and remember each answer.

```swift run
/// Is `target` a scramble of `source`? memo[length][i][j] remembers the answer for
/// source[i..<i + length] against target[j..<j + length]: 0 unknown, 1 yes, 2 no.
func isScramble(_ source: String, _ target: String) -> Bool {
    let s = Array(source), t = Array(target)
    let n = s.count
    guard t.count == n else { return false }
    if n == 0 { return true }
    var memo = Array(repeating: Array(repeating: Array(repeating: 0, count: n), count: n), count: n + 1)

    func check(_ i: Int, _ j: Int, _ length: Int) -> Bool {
        if length == 1 {
            return s[i] == t[j]
        }
        if memo[length][i][j] != 0 {
            return memo[length][i][j] == 1
        }
        var answer = false
        for k in 1..<length where !answer {             // split after k letters
            answer = (check(i, j, k) && check(i + k, j + k, length - k))                 // kept in order
                || (check(i, j + length - k, k) && check(i + k, j, length - k))           // swapped
        }
        memo[length][i][j] = answer ? 1 : 2
        return answer
    }

    return check(0, 0, n)
}

print(isScramble("swift", "ftisw"))
print(isScramble("swift", "tfiws"))
print(isScramble("abcd", "bdac"))
print(isScramble("abcd", "cadb"))
print(isScramble("abcd", "dcba"))
print(isScramble("ab", "ba"), isScramble("", ""), isScramble("a", "b"))

func permutations(_ items: [Character]) -> [[Character]] {
    if items.count <= 1 { return [items] }
    return items.indices.flatMap { index -> [[Character]] in
        var rest = items
        let first = rest.remove(at: index)
        return permutations(rest).map { [first] + $0 }
    }
}
for word in ["ab", "abc", "abcd", "abcde"] {
    let count = permutations(Array(word)).filter { isScramble(word, String($0)) }.count
    print(word, count)
}
```

```output
true
true
false
false
true
true true false
ab 2
abc 6
abcd 22
abcde 90
```

What to notice:

- The reverse, `"tfiws"`, is always a scramble: swap at every level.
- `"bdac"` and `"cadb"` are the only two rearrangements of `"abcd"` that aren't scrambles. A top-level split of `"abcd"` puts a front block (a, ab or abc) on one side and the matching back block on the other, so a scramble must start with the letters of a front or back block. No beginning of `"bdac"` (b, bd, bda) uses those letters. So 22 of the 24 orders are reachable. For five distinct letters it's 90 of 120, and the share keeps falling.
- `memo` uses 0 for "not computed yet", so it can be a plain `[[[Int]]]` instead of a dictionary keyed by triples.
- `where !answer` stops trying splits once one works.

There are O(n³) states and each tries O(n) splits, so it's **O(n⁴)** time and O(n³) memory. For 30 characters that's under a million steps; for 100 it's 100 million, about the practical limit.

A cheap pruning check helps a lot in practice: before trying splits, compare the letter counts of the two pieces (with a 26-slot array, as in [Frequency counting with 26 slots](/dsa/learn/swift-frequency-arrays)). If the pieces don't contain the same letters, no split can work, and you can return false at once.

<Callout kind="gotcha" title="Common mistakes">
- **Greedy interleaving.** When both strings offer the right character, you must keep both options. Use the table.
- **Skipping the length check.** If `c.count` isn't `a.count + b.count`, the answer is false, and indexing c by `i + j - 1` can crash.
- **The swapped case's indices.** Source's first k characters pair with target's **last** k: `j + length - k`, not `j + k`.
- **A memo that can't say "no".** Storing only `true` answers means every false subproblem is recomputed. Store three states: unknown, yes and no.
- **Building substrings in the recursion.** Passing `String` pieces down allocates at every call. Pass start indices and a length.
</Callout>
