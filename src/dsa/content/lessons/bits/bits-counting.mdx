## Why it matters

How many bits are set? When a number stores a set of flags, that's the size of the set. When you XOR two numbers, it's how many positions differ, which is how error-detecting codes and DNA comparisons measure distance. Chess engines count pieces this way, a whole board in one 64-bit number. Swift has fast built-in answers, and the classic way to count by hand teaches a trick, `n & (n - 1)`, that you'll use again and again.

## Swift's built-in counters

Every integer type has three counting properties:

| Property | Counts | For 12 (`...00001100`) as an `Int` |
| --- | --- | --- |
| `nonzeroBitCount` | the 1 bits | 2 |
| `trailingZeroBitCount` | the 0 bits below the lowest 1 | 2 |
| `leadingZeroBitCount` | the 0 bits above the highest 1 | 60 |

```swift run
let n = 12
print(n.nonzeroBitCount, n.trailingZeroBitCount, n.leadingZeroBitCount)
print(UInt8(12).leadingZeroBitCount)
print(0.trailingZeroBitCount, 0.leadingZeroBitCount)
print(Int.bitWidth - n.leadingZeroBitCount)
```

```output
2 2 60
4
64 64
4
```

What to notice:

- **`trailingZeroBitCount` is the position of the lowest set bit.** For 12, bit 2 is the lowest 1.
- **`leadingZeroBitCount` depends on the width.** 12 has 60 leading zeros as a 64-bit `Int` but only 4 as a `UInt8`.
- **Zero is all zeros**, so both counts equal the bit width: 64 for an `Int`.
- **`bitWidth - leadingZeroBitCount` is the number of bits needed to write a positive number.** 12 is `1100`, four bits.

The counting with `nonzeroBitCount` is often called **popcount**, short for population count. All three compile down to one or a few processor instructions, so in real code, use them.

## Counting by hand: one bit at a time

Writing your own counter is still worth doing once, because the two classic ways show two different ideas. The first looks at bit 0, adds it to the count, and shifts the next bit down:

```swift
func countOnes(_ x: UInt64) -> Int {
    var n = x
    var count = 0
    while n != 0 {
        count += Int(n & 1)
        n >>= 1
    }
    return count
}
```

It runs once for every bit up to the highest 1. For `(1 << 40) | 1`, which has only two bits set, it still goes round the loop 41 times.

## Kernighan's trick: `n & (n - 1)`

Here's a better idea, known as Kernighan's trick because it appears in the classic book on C that Brian Kernighan co-wrote. **`n & (n - 1)` is `n` with its lowest set bit cleared.**

Why? Subtracting 1 turns the lowest 1 into a 0, and every 0 below it into a 1, like 1000 − 1 = 999 in decimal. The bits above don't change. Line them up:

| | Bits |
| --- | --- |
| `n` = 180 | `10110100` |
| `n - 1` = 179 | `10110011` |
| `n & (n - 1)` = 176 | `10110000` |

Above the lowest 1, both numbers agree, so AND keeps those bits. At the lowest 1 and below, every position has a 0 in one number or the other, so AND clears them all. Try it in the playground with 180 and 179, then set `a` to another number and `b` to one less:

```visual bitPlayground
value: 180
operand: 179
operator: "&"
```

Repeat it and the set bits disappear one at a time, lowest first:

```swift run
func binary(_ x: UInt8) -> String {
    let digits = String(x, radix: 2)
    return String(repeating: "0", count: 8 - digits.count) + digits
}

var n: UInt8 = 0b1011_0100
while n != 0 {
    print(binary(n))
    n &= n - 1
}
```

```output
10110100
10110000
10100000
10000000
```

Four set bits, four rows. So counting the passes until `n` reaches 0 counts the set bits, and the loop runs once per *set* bit rather than once per bit:

```swift run
func onesByKernighan(_ x: UInt64) -> Int {
    var n = x
    var count = 0
    while n != 0 {
        n &= n - 1
        count += 1
    }
    return count
}

print(onesByKernighan(0b1011_0100))
print(onesByKernighan((1 << 40) | 1))
print(onesByKernighan(UInt64.max))
```

```output
4
2
64
```

For `(1 << 40) | 1`, that's 2 passes instead of 41. The real prize, though, isn't the speed: it's the pattern. "Clear the lowest set bit" is how you visit the bits of a mask one by one, and the next lesson builds a power-of-two test from it.

## Distance and parity

Two quick uses of counting:

- **Hamming distance**, the number of positions where two values differ, is `(a ^ b).nonzeroBitCount`. XOR marks every difference with a 1, and counting does the rest.
- **Parity**, whether the number of 1s is odd, is `x.nonzeroBitCount & 1`. Adding a parity bit to data is the simplest way to detect a single flipped bit in transmission.

```swift run
let a = 0b1011_0110
let b = 0b1001_1100
print((a ^ b).nonzeroBitCount)
print(0b1011.nonzeroBitCount & 1, 0b1001.nonzeroBitCount & 1)
```

```output
3
1 0
```

<Callout kind="gotcha" title="Swift gotcha: count bits on unsigned values">
For a negative `Int`, `n >>= 1` copies the sign bit back in, so `n` never reaches 0 and the shifting loop never ends. Kernighan's loop fails too: it eventually reaches `Int.min`, and `Int.min - 1` overflows and crashes. Convert first with `UInt64(bitPattern: n)`, or use `nonzeroBitCount`, which is fine on negative numbers: `(-1).nonzeroBitCount` is 64.
</Callout>

## Practice

Bit tallies asks for the bit count of *every* number from 0 to n, without `nonzeroBitCount`. Kernighan's loop on each number works. To go faster, notice that `i >> 1` and `i & (i - 1)` are both smaller than `i`, so their counts are already known.
