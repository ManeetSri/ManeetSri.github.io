## Why it matters

XOR has a property no other operator has: a value XORed with itself vanishes. That one fact turns some problems that seem to need a dictionary or a sort into a single pass with no extra memory. Storage systems use it too: some RAID setups keep the XOR of several disks, so if any one disk dies, XORing the survivors rebuilds it. This lesson collects the XOR tricks worth knowing, and one that's famous but best avoided.

## The rules of XOR

Four rules, each easy to check bit by bit:

| Rule | Why |
| --- | --- |
| `x ^ 0 == x` | XOR with a 0 bit leaves a bit unchanged |
| `x ^ x == 0` | every bit meets an equal bit, and equal bits give 0 |
| `a ^ b == b ^ a` | the order doesn't matter |
| `(a ^ b) ^ c == a ^ (b ^ c)` | neither does the grouping |

Put together, they say something powerful: **in a chain of XORs, equal values cancel in pairs, wherever they are, and what's left is the XOR of the values that appear an odd number of times.**

```swift run
print(5 ^ 0)
print(5 ^ 5)
print(5 ^ 3 ^ 5)
print(3 ^ 5 ^ 5)
```

```output
5
0
3
3
```

The two 5s cancel whether they're next to each other or not. In the playground, both numbers start out equal, so every bit cancels. Flip one bit of `b` and only that position survives:

```visual bitPlayground
value: 105
operand: 105
operator: "^"
```

A related rule makes XOR its own undo button: `(x ^ k) ^ k == x`. XOR with a key scrambles a value, and XOR with the same key again restores it. That's the core of the one-time pad, a cipher that's provably unbreakable when the key is truly random, as long as the message, and never reused.

## The single number

> Every value in the array appears exactly twice, except one, which appears once. Find it.

You could count with a dictionary, which uses memory for every distinct value, or sort and look for the odd one out. With XOR, the pairs cancel and only the single value is left:

```swift run
let numbers = [4, 1, 2, 1, 2]
var running = 0
for number in numbers {
    running ^= number
    print(number, running)
}
print([7, -3, 7, 9, 9].reduce(0, ^))
```

```output
4 4
1 5
2 7
1 6
2 4
-3
```

The running value wanders, 4, 5, 7, 6, then lands back on 4 once both pairs have cancelled. One pass, O(n) time, O(1) extra space. It works for negative numbers too, since XOR only sees bits, and even when the paired values appear four or six times instead of twice: any even number of copies cancels.

`reduce(0, ^)`, from M06, does the whole loop in one line: start at 0, the value that changes nothing, and XOR each element in.

## The missing number

> An array holds n different numbers taken from 0 to n, so exactly one is missing. Find it.

XOR every number from 0 to n *and* every value in the array. Each number that's present appears twice, once in the range and once in the array, and cancels. The missing one appears only once:

```swift run
func missingNumber(_ numbers: [Int]) -> Int {
    var result = numbers.count
    for (index, value) in numbers.enumerated() {
        result ^= index ^ value
    }
    return result
}

print(missingNumber([3, 0, 1]))
print(missingNumber([0, 1, 2, 4, 5]))
print(missingNumber([1]))
```

```output
2
3
0
```

The indices 0 to n − 1 cover most of the range, and `result` starts at `numbers.count`, which is n itself. So every number from 0 to n goes in exactly once, alongside every value.

You could also use the formula from M13: the sum from 0 to n is n × (n + 1) / 2, and subtracting the array's sum leaves the missing number. That's just as good here. The XOR version has one small advantage: it can never overflow, however large the numbers get, because XOR never carries into a higher bit.

### XOR from 0 to n without a loop

The XOR of all the numbers from 0 to n follows a pattern that repeats every four steps:

```swift run
var running = 0
var values: [Int] = []
for n in 0...11 {
    running ^= n
    values.append(running)
}
print(values)
```

```output
[0, 1, 3, 0, 4, 1, 7, 0, 8, 1, 11, 0]
```

When `n % 4` is 0 the result is n, when it's 1 the result is 1, when it's 2 it's n + 1, and when it's 3 it's 0. Spotting a pattern like this by printing small cases, then using it, is a technique worth remembering.

## Swapping without a temporary

Here's the famous one. Three XORs swap two variables with no third variable:

```swift run
var a = 5
var b = 9
a ^= b
b ^= a
a ^= b
print(a, b)
```

```output
9 5
```

Trace it in binary, with 5 as `0101` and 9 as `1001`:

| Step | `a` | `b` |
| --- | --- | --- |
| start | `0101` | `1001` |
| `a ^= b` | `1100` | `1001` |
| `b ^= a` | `1100` | `0101`, which is 5 |
| `a ^= b` | `1001`, which is 9 | `0101` |

After the first step, `a` holds `a ^ b`. XORing that into `b` cancels the old `b` and leaves the old `a`. XORing the new `b` into `a` cancels the old `a` and leaves the old `b`.

It's clever. **Don't use it in real code.** Here's why:

1. **It's harder to read.** `swap(&a, &b)` or `(a, b) = (b, a)` says what it does.
2. **It isn't faster.** The compiler keeps a temporary in a processor register, which costs nothing. The XOR version can even be slower, because each step has to wait for the one before.
3. **It breaks when both sides are the same thing.** If you swap an array element with itself, the first XOR sets it to 0, and it stays 0:

```swift run
func xorSwap(_ items: inout [Int], _ i: Int, _ j: Int) {
    items[i] ^= items[j]
    items[j] ^= items[i]
    items[i] ^= items[j]
}

var items = [10, 20, 30]
xorSwap(&items, 0, 2)
print(items)
xorSwap(&items, 1, 1)
print(items)
```

```output
[30, 20, 10]
[30, 0, 10]
```

Swapping index 1 with itself destroyed the 20. In algorithms like sorting, `i == j` happens all the time. Swift's `swapAt(_:_:)`, from M05, handles it correctly, and works for any element type, not just integers.

## Two smaller tricks

- **Opposite signs.** `(a ^ b) < 0` is true exactly when `a` and `b` have different signs: XOR sets the sign bit only if the two sign bits differ.
- **XOR for Bools.** Swift's `Bool` has no `^`. Use `!=` instead: `a != b` is true when exactly one of them is true, which is XOR.

<Callout kind="tip" title="When to think of XOR">
Reach for XOR when a problem says "every value appears twice except…", "find the one that's different", or "which number is missing", and especially when it asks for O(1) extra space. You'll meet its big brother, prefix XOR, in M20.
</Callout>

## Practice

Two unpaired numbers has *two* values that appear once. XORing everything leaves `a ^ b`, which isn't the answer yet. But any set bit in `a ^ b` is a position where `a` and `b` differ, and the last lesson showed how to pick one out.
