## Why it matters

Every value in a computer is stored as bits, and some of the fastest tricks in programming work on those bits directly. iOS uses bit flags for options such as `UIView.AutoresizingMask`, file formats and network protocols pack data into individual bits, and interview problems love a bit trick. To use any of them, you need to see numbers the way the machine does, including the clever way it stores negative numbers.

## Counting in base 2

In everyday decimal, each place is worth ten times the one to its right: ones, tens, hundreds. In **binary**, each place is worth *two* times the one to its right, and each digit, called a **bit**, is either 0 or 1.

Here's 13 in binary:

| Place value | 8 | 4 | 2 | 1 |
| --- | --- | --- | --- | --- |
| Bit | 1 | 1 | 0 | 1 |

8 + 4 + 1 = 13, so 13 is `1101` in binary. You met number bases in [Number systems and conversion](/dsa/learn/math-number-systems); this module works in base 2 all the time.

Bits are numbered from the right, starting at 0. **Bit k** is worth 2ᵏ: bit 0 is worth 1, bit 1 is worth 2, bit 3 is worth 8. Bit 0 is called the **lowest** or least significant bit, and it alone decides whether a number is odd.

## Binary in Swift

Swift reads binary literals that start with `0b`, and underscores can split them into readable groups. To see a number's bits, use `String(_:radix:)`, from M08:

```swift run
let thirteen = 0b1101
let pattern = 0b1010_0110

print(thirteen)
print(pattern)
print(String(13, radix: 2))
print(Int("1101", radix: 2)!)
```

```output
13
166
1101
13
```

`String(13, radix: 2)` drops leading zeros. When you're comparing bit patterns, it's much easier to read them at a fixed width, so this module often uses a small helper that pads to 8 bits:

```swift run
func binary(_ x: UInt8) -> String {
    let digits = String(x, radix: 2)
    return String(repeating: "0", count: 8 - digits.count) + digits
}

print(binary(13))
print(binary(1))
print(binary(255))
```

```output
00001101
00000001
11111111
```

## Fixed widths

A `UInt8` holds exactly 8 bits. Eight bits have 2⁸ = 256 possible patterns, from `00000000` (0) to `11111111` (255), which is why `UInt8` runs from 0 to 255. Every integer type has a fixed **bit width**: you can ask for it with `UInt8.bitWidth` (8) or `Int.bitWidth` (64).

A fixed width means there's no room to grow. Adding 1 to `11111111` needs a ninth bit, which is the overflow you met in [Overflow traps and overflow operators](/dsa/learn/swift-overflow).

## Negative numbers: two's complement

How do you store -5 with only 0s and 1s? Almost every computer uses **two's complement**, and the idea is short: **the leftmost bit's place value is negative.**

In an `Int8`, the leftmost bit, bit 7, is worth **-128** instead of +128. Every other bit keeps its usual value:

| Bits | Sum | Value |
| --- | --- | --- |
| `00000000` | 0 | 0 |
| `00000001` | 1 | 1 |
| `01111111` | 64 + 32 + 16 + 8 + 4 + 2 + 1 | 127 |
| `10000000` | -128 | -128 |
| `10000001` | -128 + 1 | -127 |
| `11111110` | -128 + 126 | -2 |
| `11111111` | -128 + 127 | -1 |

That table explains the range of `Int8` from M02. The biggest value has every bit set except the negative one: 127. The smallest has only the negative bit: -128. Any pattern starting with 1 is negative, so the leftmost bit is often called the **sign bit**.

### Why -1 is all ones

`11111111` is -128 + 127 = -1. It also *behaves* like -1: add 1 and every bit carries over, giving `1_00000000`. The ninth bit doesn't fit and falls off, leaving `00000000`, which is 0. And -1 + 1 should be 0. Remember "-1 is all ones": several tricks later in this module depend on it.

### Why computers use it

With two's complement, adding works exactly the same for negative and positive numbers. Add 5 and -3 bit by bit, as if both were ordinary unsigned numbers:

| | Bits | Value |
| --- | --- | --- |
| 5 | `00000101` | 5 |
| -3 | `11111101` | -3 |
| sum | `1_00000010`, then drop the ninth bit | 2 |

The answer is right without any special handling of the sign. The processor needs only one adding circuit for both kinds of integer.

## Negating: flip every bit, then add 1

To find the pattern for `-x`, flip every bit of `x` and add 1:

| Step | Bits | Value |
| --- | --- | --- |
| start with 5 | `00000101` | 5 |
| flip every bit | `11111010` | -6 |
| add 1 | `11111011` | -5 |

Why does it work? A number plus its flipped version is all ones: `00000101 + 11111010 = 11111111`, which is -1. So the flipped version is `-x - 1`, and adding 1 gives `-x`. Swift writes "flip every bit" as `~`, which you'll meet properly in the next lesson.

Try it below. The playground starts as an `Int8` showing 5 and its flipped version, -6. Click bits to change `a`, and switch between `UInt8` and `Int8` to see the same bits read both ways:

```visual bitPlayground

```

## Seeing the bits of a negative number

Here's a trap. `String(_:radix:)` writes a negative number as a minus sign followed by its size, not as the bits actually stored:

```swift run
func binary(_ x: UInt8) -> String {
    let digits = String(x, radix: 2)
    return String(repeating: "0", count: 8 - digits.count) + digits
}

let minusFive: Int8 = -5
print(String(minusFive, radix: 2))
print(binary(UInt8(bitPattern: minusFive)))
print(Int8(bitPattern: 0b1111_1011))
print(UInt8(bitPattern: -1))
```

```output
-101
11111011
-5
255
```

`UInt8(bitPattern:)` keeps the same 8 bits and reads them as unsigned, so you can print what's really stored. `Int8(bitPattern:)` goes the other way. Nothing about the bits changes; only how Swift interprets them.

## The odd one out: the minimum value

There are 128 negative `Int8` values but only 127 positive ones, so -128 has no positive partner. Flip `10000000` and add 1, and you get `10000000` back. In Swift, `-Int8.min` would overflow, so the program crashes.

The same is true for `Int.min`, which is -2⁶³. That's why `abs(Int.min)` crashes. If you need the size of a number that might be the minimum, `magnitude` returns it as an unsigned value: `Int8.min.magnitude` is 128 as a `UInt8`.

<Callout kind="gotcha" title="Swift gotcha: Int is 64 bits">
Everything here works the same for `Int`, just wider: 64 bits, with bit 63 worth -2⁶³. The 8-bit types are easier to draw, so this module uses them for pictures. In real code, keep using `Int` unless you have a reason to pick a sized type, and remember that `Int` and `Int8` are different types that don't mix without converting.
</Callout>
