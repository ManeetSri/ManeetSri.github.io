## Why it matters

Powers of two are the round numbers of computing. Buffer sizes, memory pages and many hash tables' capacities are powers of two, because they make the arithmetic cheap. Memory alignment, which you met in M11, rounds addresses up to one. This lesson gives you the one-line tests and tricks for working with them, including `x & -x`, which isolates a number's lowest set bit and sits at the heart of the Fenwick tree in Part VIII.

## A power of two has exactly one bit set

In binary, the powers of two are a 1 followed by zeros: 1 is `1`, 2 is `10`, 4 is `100`, 8 is `1000`. Exactly one bit is set.

From the last lesson, `n & (n - 1)` clears the lowest set bit. If `n` has only one set bit, clearing it leaves 0. So:

```swift run
func isPowerOfTwo(_ n: Int) -> Bool {
    n > 0 && n & (n - 1) == 0
}

for n in [1, 2, 6, 64, 96, 0, -8, Int.min] {
    print(n, isPowerOfTwo(n))
}
```

```output
1 true
2 true
6 false
64 true
96 false
0 false
-8 false
-9223372036854775808 false
```

The `n > 0` check isn't decoration. It does two jobs:

- **0 isn't a power of two**, but `0 & (0 - 1)` is `0 & -1`, which is 0. Without the check, 0 would pass.
- **`Int.min` would crash.** Its only set bit is the sign bit, so it looks like a power of two to the bit test, and `Int.min - 1` overflows. Because `&&` stops as soon as its left side is false, the subtraction never runs for 0 or any negative number.

`n > 0 && n.nonzeroBitCount == 1` says the same thing and reads more plainly. Both are fine. The `n & (n - 1)` version is worth knowing because the idea, "remove the lowest bit and see what's left", comes up in many other places.

## The lowest set bit: `x & -x`

`n & (n - 1)` *removes* the lowest set bit. Its partner, `x & -x`, *keeps only* the lowest set bit:

```swift run
for x in [12, 40, 7, 96] {
    print(x, x & -x)
}
```

```output
12 4
40 8
7 1
96 32
```

12 is `1100`, and its lowest set bit is worth 4. 96 is `1100000`, and its lowest set bit is worth 32. Why does this work? It comes straight from two's complement, where `-x` is "flip every bit, then add 1":

| Step | Bits | Value |
| --- | --- | --- |
| `x` | `00001100` | 12 |
| flip every bit, `~x` | `11110011` | -13 |
| add 1, giving `-x` | `11110100` | -12 |
| `x & -x` | `00000100` | 4 |

Follow the three regions of the number:

- **Below the lowest 1**, `x` has zeros. Flipping makes them ones, and adding 1 ripples through them, turning them back into zeros, like 0999 + 1 = 1000.
- **At the lowest 1**, flipping made a 0, and the ripple stops there, setting it back to 1. So `x` and `-x` both have a 1 in this position.
- **Above it**, `-x` is still the flipped `x`, so every bit is the opposite of `x`'s, and AND clears them all.

Only the lowest set bit survives. See it in the playground, which shows 12 and -12 as `Int8` values. Change `a` and set `b` to its negative to try other numbers:

```visual bitPlayground
value: 12
operand: 244
signed: true
operator: "&"
```

The two tricks fit together: `x & (x - 1)` is `x` minus `x & -x`. One gives you the rest of the number; the other gives you the bit that was removed.

<Callout kind="gotcha" title="Swift gotcha: negating can overflow">
`-x` crashes when `x` is `Int.min`, and unsigned types have no `-` at all. The safe spelling is `x & (0 &- x)`: the wrapping subtraction gives the same bits as negating, without the trap. Another option is `1 << x.trailingZeroBitCount`, which also gives 0 for `x = 0`, because shifting by the full width leaves nothing.
</Callout>

## The highest set bit, and rounding up

The highest set bit uses the count from the other end. For a positive `n`, its position is `Int.bitWidth - 1 - n.leadingZeroBitCount`, which is also log₂ n rounded down.

Rounding up to the next power of two is handy when growing a buffer: if you need room for 1,000 items, a capacity of 1,024 is the natural choice. For `n ≥ 1`, count how many bits `n - 1` needs, and shift a 1 that far:

```swift run
func highestBit(_ n: Int) -> Int {
    Int.bitWidth - 1 - n.leadingZeroBitCount
}

func nextPowerOfTwo(_ n: Int) -> Int {
    1 << (Int.bitWidth - (n - 1).leadingZeroBitCount)
}

for n in [1, 5, 8, 9, 1000] {
    print(n, highestBit(n), nextPowerOfTwo(n))
}
```

```output
1 0 1
5 2 8
8 3 8
9 3 16
1000 9 1024
```

Using `n - 1` rather than `n` is what makes an exact power of two round to itself: 8 needs no rounding, and 7 needs three bits, so the answer is `1 << 3` = 8. For `n = 1`, `n - 1` is 0, which has 64 leading zeros, so the shift is 0 and the answer is 1.

## Shortcuts for powers of two

When `m` is a power of two, `m - 1` is a run of ones: 8 − 1 = 7 is `111`. That gives three shortcuts, for non-negative `x`:

| Instead of | Write | Example with 8 |
| --- | --- | --- |
| `x % m` | `x & (m - 1)` | `x & 7` keeps the lowest three bits |
| `x / m` | `x >> k`, where `m` is 2ᵏ | `x >> 3` |
| round `x` up to a multiple of `m` | `(x + m - 1) & ~(m - 1)` | `(x + 7) & ~7` |

```swift run
for x in [13, 16, 21] {
    print(x % 8, x & 7, x / 8, x >> 3, (x + 7) & ~7)
}
```

```output
5 5 1 1 16
0 0 2 2 16
5 5 2 2 24
```

The rounding trick is how memory alignment is computed: from [MemoryLayout: size, stride and alignment](/dsa/learn/swift-memory-layout), a value with an alignment of 8 must start at an address that's a multiple of 8. It's also why hash tables like power-of-two sizes: `hash & (capacity - 1)` picks a slot more cheaply than `%`.

In everyday code, write `x % 8` and `x / 8`. The compiler makes those substitutions itself when the divisor is a constant, and the plain version says what you mean.

<Callout kind="warning" title="Only for non-negative numbers">
For negative `x`, the shortcuts give different answers: `-13 % 8` is -5, but `-13 & 7` is 3. Neither is wrong, they just answer different questions. Use the bit versions only when you know `x` isn't negative, or when the bit answer is what you want.
</Callout>
