## Why it matters

Lots of problems are about choosing: which items fit in the bag, which friends to invite, which features to switch on. When there are only a handful of things to choose from, up to about 20, you can simply try every possible choice. Bitmasks make that easy: every choice is one integer, and counting from 0 upwards visits them all, with no recursion needed. Later in the course, in Part VII, the same masks become the states of dynamic programming over subsets.

## A subset is a number

Take n items. Each one is either in a subset or out of it: that's n yes-or-no answers, which fit in n bits. Let **bit i stand for item i**: 1 means it's in, 0 means it's out.

With the items `["tea", "toast", "jam"]`:

| Mask | Bits | Subset |
| --- | --- | --- |
| 0 | `000` | nothing |
| 1 | `001` | tea |
| 5 | `101` | tea, jam |
| 6 | `110` | toast, jam |
| 7 | `111` | all three |

Every number from 0 to 2ⁿ − 1 is a different subset, and every subset is one of those numbers. With 3 items, that's the 8 masks from 0 to 7. In Swift, the range of all masks is `0..<(1 << n)`, because `1 << n` is 2ⁿ.

Notice that bits are numbered from the right, while arrays are listed from the left. Mask `001` is tea, the *first* item. Reading a mask's binary from right to left matches the array from left to right.

## Listing every subset

Loop over every mask, and for each one, check every bit to see which items it includes:

```swift run
func binary(_ mask: Int, width: Int) -> String {
    let digits = String(mask, radix: 2)
    return String(repeating: "0", count: width - digits.count) + digits
}

let items = ["tea", "toast", "jam"]
let n = items.count
for mask in 0..<(1 << n) {
    var chosen: [String] = []
    for i in 0..<n where mask & (1 << i) != 0 {
        chosen.append(items[i])
    }
    print(binary(mask, width: n), chosen)
}
```

```output
000 []
001 ["tea"]
010 ["toast"]
011 ["tea", "toast"]
100 ["jam"]
101 ["tea", "jam"]
110 ["toast", "jam"]
111 ["tea", "toast", "jam"]
```

Two loops, one bit check: that's the whole technique. The inner condition is the "check bit k" move from [Checking, setting, clearing and toggling bits](/dsa/learn/bits-single-bits).

## Trying every choice

Now put it to work. **Which combinations of these prices add up to exactly 7?** Try every subset and keep the ones that match. This time, the inner loop visits only the set bits, using two tricks from earlier lessons: `trailingZeroBitCount` finds the lowest set bit, and `rest &= rest - 1` clears it.

```swift run
let prices = [3, 1, 4, 2, 5]
let target = 7
var count = 0

for mask in 0..<(1 << prices.count) {
    var total = 0
    var chosen: [Int] = []
    var rest = mask
    while rest != 0 {
        let i = rest.trailingZeroBitCount
        total += prices[i]
        chosen.append(prices[i])
        rest &= rest - 1
    }
    if total == target {
        print(chosen)
        count += 1
    }
}
print("\(count) ways to spend exactly \(target)")
```

```output
[3, 4]
[1, 4, 2]
[2, 5]
3 ways to spend exactly 7
```

This is brute force in its purest form, and it's correct for an obvious reason: it checks every possible choice.

### How far does it scale?

There are 2ⁿ masks, and decoding each takes up to n steps, so the work is about 2ⁿ × n:

| n | 2ⁿ | 2ⁿ × n | Verdict |
| --- | --- | --- | --- |
| 10 | 1,024 | about 10⁴ | instant |
| 20 | about 10⁶ | about 2 × 10⁷ | fine |
| 25 | about 3.4 × 10⁷ | about 8 × 10⁸ | slow |
| 30 | about 10⁹ | about 3 × 10¹⁰ | far too slow |

That's the clue from [Reading constraints to guess the target complexity](/dsa/learn/algo-constraints-to-complexity): a limit like `n ≤ 20` is a strong hint that trying every subset is intended.

## Masks as sets

Since a mask *is* a set, the bitwise operators *are* set operations, each done in one instruction:

| Set operation | With masks |
| --- | --- |
| union, in a or b | `a \| b` |
| intersection, in both | `a & b` |
| difference, in a but not b | `a & ~b` |
| complement, everything not in a | `a ^ full`, where `full = (1 << n) - 1` |
| is a a subset of b? | `a & b == a` |
| size | `a.nonzeroBitCount` |

Here are two people's free days for a week, with Monday as bit 0:

```swift run
let days = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]

func dayNames(_ mask: Int) -> [String] {
    var names: [String] = []
    for i in 0..<days.count where mask & (1 << i) != 0 {
        names.append(days[i])
    }
    return names
}

let alice = 0b011_0101
let bob = 0b101_0100
let everyDay = (1 << 7) - 1

print(dayNames(alice & bob))
print(dayNames(alice | bob))
print(dayNames(alice & ~bob))
print(dayNames(alice ^ everyDay))
print((alice & bob).nonzeroBitCount)
```

```output
["Wed", "Fri"]
["Mon", "Wed", "Fri", "Sat", "Sun"]
["Mon", "Sat"]
["Tue", "Thu", "Sun"]
2
```

Compare that with `Set<String>` from M07: the same operations, but on a single integer, with no memory allocated at all. The catch is that the items must be numbered 0 to 63.

## Iterating over submasks

A **submask** of `m` is a mask that only uses bits `m` has: a subset of the subset. Sometimes you need every submask of one particular mask, such as every way to split a group. Here's the standard loop, which visits them from largest to smallest:

```swift run
func binary(_ mask: Int, width: Int) -> String {
    let digits = String(mask, radix: 2)
    return String(repeating: "0", count: width - digits.count) + digits
}

let m = 0b1011
var sub = m
while true {
    print(binary(sub, width: 4))
    if sub == 0 {
        break
    }
    sub = (sub - 1) & m
}
```

```output
1011
1010
1001
1000
0011
0010
0001
0000
```

`m` has three set bits, so it has 2³ = 8 submasks, and the loop visits exactly those. The step `(sub - 1) & m` works like counting down in binary using only `m`'s positions: subtracting 1 clears the lowest set bit of `sub` and sets every bit below it, then `& m` throws away the bits `m` doesn't allow. What's left is the next smaller submask.

Check the loop's ending carefully. The empty submask, 0, is a real subset, so it's visited before the loop stops. Without the `break`, the next step would be `(0 - 1) & m`, which is `m` again, and the loop would go round forever.

Doing this for *every* mask of n bits costs 3ⁿ steps in total, not 4ⁿ: each item is either outside `m`, inside `m` but not `sub`, or inside both. For n = 15, that's about 1.4 × 10⁷. Bitmask dynamic programming in Part VII is built on exactly this loop.

<Callout kind="gotcha" title="Swift gotcha: big n fails silently">
`1 << n` is 0 when `n` is 64 or more, because Swift's shift pushes every bit out. So `0..<(1 << 64)` is an empty range: the loop runs zero times and nothing crashes. You'd never want 2⁶⁴ masks anyway, but a silently empty loop is a nasty way to find out. If n could be large, check it first with a `precondition`.
</Callout>

Bitmask subsets asks you to return every subset of an array in mask order. Notice how the answer's order follows from counting masks from 0 upwards.

```cards
  back: "About 2ⁿ × n steps. Fine up to about n = 20; far too slow by n = 30."

  back: "Union `a | b`, intersection `a & b`, difference `a & ~b`."
- id: submask-loop
  front: "How do you visit every submask of m?"
  back: "Start at `sub = m`; after visiting, stop if `sub == 0`, otherwise `sub = (sub - 1) & m`. A mask with k bits has 2ᵏ submasks."
```
