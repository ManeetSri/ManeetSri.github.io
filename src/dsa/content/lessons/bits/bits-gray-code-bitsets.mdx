## Why it matters

This deep dive covers two ideas that go a step beyond everyday bit tricks. **Gray code** orders all n-bit numbers so that neighbours differ in exactly one bit. Sensors that report the position of a dial or a wheel use it, and so can you, to walk through every subset changing one item at a time. **Bitsets** use the bits of integers as a compact set of small numbers. They power chess engines, fast sieves for primes and the "visited" sets of graph searches, storing 64 yes-or-no answers in the space of one `Int`.

## The trouble with counting

Count from 3 to 4 in binary: `011` becomes `100`. Three bits change at once. In a computer's memory that's fine, but imagine a physical dial with three electrical contacts reading those bits. The contacts never switch at exactly the same instant, so for a split second the dial might read `111` or `000`, a position it isn't anywhere near.

**Gray code** fixes this by ordering the numbers so that each step changes exactly one bit. There's never a moment where two bits disagree about what's happening.

## Building Gray code

The i-th Gray code number is `i ^ (i >> 1)`: each bit of the result says whether that bit of `i` differs from the bit to its left.

```swift run
func binary(_ x: Int, width: Int) -> String {
    let digits = String(x, radix: 2)
    return String(repeating: "0", count: width - digits.count) + digits
}

let n = 3
var previous = 0
for i in 0..<(1 << n) {
    let gray = i ^ (i >> 1)
    let changed = (gray ^ previous).nonzeroBitCount
    print(i, binary(i, width: n), binary(gray, width: n), changed)
    previous = gray
}
```

```output
0 000 000 0
1 001 001 1
2 010 011 1
3 011 010 1
4 100 110 1
5 101 111 1
6 110 101 1
7 111 100 1
```

The last column counts the bits that changed since the previous Gray value, using the Hamming distance from [Counting bits and Kernighan's trick](/dsa/learn/bits-counting): it's always 1. The sequence even wraps around, since the last value, `100`, is one bit away from the first, `000`.

### Why only one bit changes

Going from `i` to `i + 1` flips a run of bits at the bottom: the trailing ones become zeros and the zero above them becomes a one, as in `0111` + 1 = `1000`. A Gray bit is the XOR of two neighbouring bits of `i`. Inside the flipped run, both neighbours flip, so their XOR stays the same. Above the run, nothing flips. Only at the top of the run does one neighbour flip without the other, so exactly one Gray bit changes.

That also tells you *which* bit changes on the way to step `i`: the one at position `i.trailingZeroBitCount`. You'll use that in a moment.

### Turning Gray code back into a number

To decode, XOR together every right shift of the Gray value:

```swift run
func fromGray(_ gray: Int) -> Int {
    var value = gray
    var shift = gray >> 1
    while shift != 0 {
        value ^= shift
        shift >>= 1
    }
    return value
}

print(fromGray(0b110))
print(fromGray(0b100))

var allMatch = true
for i in 0..<1024 where fromGray(i ^ (i >> 1)) != i {
    allMatch = false
}
print(allMatch)
```

```output
4
7
true
```

Each bit of the original is the XOR of all the Gray bits at or above it, and the shifts line those up. The last loop checks the round trip for every 10-bit number, which is more convincing than any single example.

## Every subset, one change at a time

In the last lesson, you tried every subset of the prices `[3, 1, 4, 2, 5]` and found the 3 that add up to 7. Each subset's total was worked out from scratch, costing up to n steps per mask.

Visit the masks in Gray code order instead, and each subset differs from the previous one by exactly one item, added or removed. So the running total needs one addition or subtraction per step:

```swift run
let prices = [3, 1, 4, 2, 5]
let target = 7
var total = 0
var count = 0

for i in 1..<(1 << prices.count) {
    let item = i.trailingZeroBitCount
    let gray = i ^ (i >> 1)
    if gray & (1 << item) != 0 {
        total += prices[item]
    } else {
        total -= prices[item]
    }
    if total == target {
        count += 1
    }
}
print(count)
```

```output
3
```

The loop starts at 1 because step 0 is the empty subset, with a total of 0, which isn't 7. The answer matches the last lesson's, but the work drops from about 2ⁿ × n steps to 2ⁿ. The same idea, changing one thing at a time and updating instead of recomputing, runs right through algorithm design.

## `UInt64` as a set

A `UInt64` has 64 bits, so it can hold any set of numbers from 0 to 63: bit `x` is 1 when `x` is in the set. Wrapping the mask moves from [Checking, setting, clearing and toggling bits](/dsa/learn/bits-single-bits) in a struct gives it a friendly interface:

```swift run
struct BitSet64 {
    private(set) var bits: UInt64 = 0

    mutating func insert(_ x: Int) {
        precondition(0..<64 ~= x, "BitSet64 holds 0 to 63")
        bits |= 1 << x
    }

    mutating func remove(_ x: Int) {
        bits &= ~(1 << x)
    }

    func contains(_ x: Int) -> Bool {
        bits & (1 << x) != 0
    }

    var count: Int {
        bits.nonzeroBitCount
    }

    func sharesNothing(with other: BitSet64) -> Bool {
        bits & other.bits == 0
    }

    var elements: [Int] {
        var result: [Int] = []
        var rest = bits
        while rest != 0 {
            result.append(rest.trailingZeroBitCount)
            rest &= rest - 1
        }
        return result
    }
}

var set = BitSet64()
for x in [5, 0, 63, 17, 5] {
    set.insert(x)
}
print(set.elements, set.count, set.contains(17), set.contains(18))
set.remove(0)
print(set.elements)

func letters(of word: String) -> BitSet64 {
    var set = BitSet64()
    for character in word {
        if let ascii = character.asciiValue {
            set.insert(Int(ascii) - 97)
        }
    }
    return set
}

let words = ["swift", "array", "queue", "heap"]
let sets = words.map(letters(of:))
for i in 0..<words.count {
    for j in (i + 1)..<words.count where sets[i].sharesNothing(with: sets[j]) {
        print(words[i], words[j])
    }
}
```

```output
[0, 5, 17, 63] 4 true false
[5, 17, 63]
swift array
swift queue
swift heap
array queue
```

What to notice:

- **Inserting 5 twice changes nothing**, just like a `Set`. Setting a bit that's already set is harmless.
- **`elements` comes out sorted**, because it reads the bits from lowest to highest, using `trailingZeroBitCount` and Kernighan's `rest &= rest - 1`.
- **"Do these words share a letter?" is one AND.** Each word becomes a set of letters, with `a` as 0 up to `z` as 25, and two words share nothing exactly when their sets AND to zero. A `Set<Character>` would compare character by character and allocate memory for every word.

The `precondition` matters. Without it, `insert(64)` would compute `1 << 64`, which is 0, and silently do nothing.

## Bigger sets: an array of words

For numbers beyond 63, use an array of `UInt64` values, each holding 64 of the bits. Number `x` lives in word `x / 64`, at bit `x % 64`. Since 64 is a power of two, those are `x >> 6` and `x & 63`, as in [Powers of two and the lowest set bit](/dsa/learn/bits-power-of-two):

```swift run
struct BitSet {
    private var words: [UInt64]

    init(capacity: Int) {
        words = Array(repeating: 0, count: (capacity + 63) / 64)
    }

    mutating func insert(_ x: Int) {
        words[x >> 6] |= 1 << (x & 63)
    }

    func contains(_ x: Int) -> Bool {
        words[x >> 6] & (1 << (x & 63)) != 0
    }

    var count: Int {
        words.reduce(0) { $0 + $1.nonzeroBitCount }
    }
}

var multiples = BitSet(capacity: 200)
for x in stride(from: 0, to: 200, by: 3) {
    multiples.insert(x)
}
print(multiples.count, multiples.contains(99), multiples.contains(100))
```

```output
67 true false
```

`(capacity + 63) / 64` rounds up, so 200 numbers need 4 words. Compare the memory for the elements themselves: 200 `Bool` values take 200 bytes, 200 `Int` values take 1,600 bytes, and this bitset takes 32 bytes. Operations on whole sets, like union and intersection, handle 64 elements per instruction.

A bitset makes the table in [Primes and the Sieve of Eratosthenes](/dsa/learn/math-primes-sieve) eight times smaller than an array of `Bool`, and you'll meet bitsets again in graph algorithms, where a set of visited nodes is checked millions of times. Swift's standard library doesn't include a bitset, which is why you build one here. Apple's Swift Collections package has a ready-made `BitSet`, and you'll look at packages like it in Part IX.

<Callout kind="gotcha" title="Swift gotcha: big shifts fail silently">
Swift's `<<` turns any shift of 64 or more into 0. That's safe, but it means a bitset with a bad index quietly ignores it instead of crashing. Check indices with `precondition` in your own bitset types, and make sure the word index `x >> 6` is in range, which the array's own bounds check will do for you.
</Callout>
