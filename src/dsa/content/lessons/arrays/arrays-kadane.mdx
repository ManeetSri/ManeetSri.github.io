## Why it matters

Given a run of daily profits and losses, which stretch of consecutive days made the most money? That's the **maximum subarray** problem, and it turns up as the brightest stretch of a signal, the best streak in a game, and, in disguise, the best time to buy and sell a stock. The obvious solution tries every stretch. **Kadane's algorithm** does it in a single pass with two variables, and the reasoning behind it is your first real taste of dynamic programming, which gets a whole family of modules in Part VII.

## The problem

Find the largest sum of a **subarray**: a non-empty run of consecutive elements. In

`[-2, 1, -3, 4, -1, 2, 1, -5, 4]`

the best run is `[4, -1, 2, 1]`, with sum 6. It includes a −1, because the 2 and 1 after it more than make up for it. That's what makes the problem interesting: you can't just keep the positive numbers, because a run has to be consecutive.

## The brute force

Try every start, and for each start extend the end one element at a time, keeping a running sum. Every subarray's sum costs O(1) to update, and there are about n²/2 subarrays, so this is **O(n²)**:

```swift run
func bestSumBruteForce(_ numbers: [Int]) -> Int {
    var best = numbers[0]
    for start in numbers.indices {
        var sum = 0
        for end in start..<numbers.count {
            sum += numbers[end]
            best = max(best, sum)
        }
    }
    return best
}

print(bestSumBruteForce([-2, 1, -3, 4, -1, 2, 1, -5, 4]))
```

```output
6
```

A version that recomputed each subarray's sum from scratch would be O(n³). For 100,000 numbers, even the O(n²) version does about 5 billion additions. It's a fine checker for small arrays, and the next lesson counts exactly how many subarrays there are.

## Kadane's idea: the best run ending here

Instead of asking "what's the best run anywhere?", ask a smaller question at each index: **what's the best run that ends exactly here?**

A run ending at index i either:

- is just `numbers[i]` on its own, or
- is the best run ending at i − 1, extended by `numbers[i]`.

Nothing else is possible: any longer run ending at i is some run ending at i − 1 plus `numbers[i]`, and the best of those uses the best run ending at i − 1. So, calling that best sum `current`:

> `current = max(numbers[i], current + numbers[i])`

In words: extend the previous run if that helps; if the previous run's sum is negative, it can only drag you down, so start fresh. The answer to the whole problem is the best `current` seen at any index, kept in `best`.

```swift run
let numbers = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
var current = numbers[0]
var best = numbers[0]
print("value", numbers[0], "current", current, "best", best)
for value in numbers.dropFirst() {
    current = max(value, current + value)
    best = max(best, current)
    print("value", value, "current", current, "best", best)
}
```

```output
value -2 current -2 best -2
value 1 current 1 best 1
value -3 current -2 best 1
value 4 current 4 best 4
value -1 current 3 best 4
value 2 current 5 best 5
value 1 current 6 best 6
value -5 current 1 best 6
value 4 current 5 best 6
```

At the 4, the previous run had sum −2, so starting fresh (4) beats extending (2). From there the run keeps growing, dips at −1, and peaks at 6. After the −5 the run is still positive, so it's extended rather than abandoned, but it never beats 6 again.

Step through it and watch the window: it restarts whenever the run so far is negative, and the best run stays highlighted.

```visual arrayTrace

```

One pass, two variables: **O(n) time, O(1) space**.

### Why it's correct

The claim is that after processing index i, `current` is the best sum of any run ending exactly at i. It's true at index 0, where the only run is `numbers[0]`. And if it's true at i − 1, the two-case argument above shows it's true at i. So it holds everywhere, by the same kind of reasoning as an induction proof. The best run in the whole array ends at *some* index, so the largest `current` ever seen, which is `best`, is its sum.

This is the shape of every dynamic programming solution you'll meet in Part VII: define a smaller question for each position ("best run ending here"), write the answer in terms of the previous position's answer, and combine.

## All-negative arrays

A popular way to write Kadane starts both variables at 0 and resets `current` to 0 whenever it goes negative. Try it on an array where everything is a loss:

```swift run
func kadaneFromZero(_ numbers: [Int]) -> Int {
    var current = 0
    var best = 0
    for value in numbers {
        current = max(0, current + value)
        best = max(best, current)
    }
    return best
}

func kadane(_ numbers: [Int]) -> Int {
    var current = numbers[0]
    var best = numbers[0]
    for value in numbers.dropFirst() {
        current = max(value, current + value)
        best = max(best, current)
    }
    return best
}

let losses = [-3, -1, -2]
print(kadaneFromZero(losses), kadane(losses))
print(kadaneFromZero([5, -9, 6]), kadane([5, -9, 6]))
```

```output
0 -1
6 6
```

The start-from-zero version answers 0 for `[-3, -1, -2]`, the sum of an **empty** run. If the problem says the run must be non-empty, that's wrong: the best you can do is the single element −1. Starting both variables at `numbers[0]` fixes it. The two versions agree whenever at least one element is non-negative.

Neither answer is wrong in every situation. Read the problem: "non-empty subarray" means start from the first element; "you may choose no elements" means 0 is allowed.

## Where is the best run?

Often you need the run itself, not just its sum. Remember where the current run started, and save the range whenever `best` improves:

```swift run
func bestSubarray(_ numbers: [Int]) -> (sum: Int, range: ClosedRange<Int>) {
    var current = numbers[0]
    var start = 0
    var best = numbers[0]
    var bestRange = 0...0
    for index in 1..<numbers.count {
        if current < 0 {              // a negative run only drags things down
            current = numbers[index]
            start = index
        } else {
            current += numbers[index]
        }
        if current > best {
            best = current
            bestRange = start...index
        }
    }
    return (best, bestRange)
}

let readings = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
let result = bestSubarray(readings)
print(result.sum, result.range, Array(readings[result.range]))
```

```output
6 3...6 [4, -1, 2, 1]
```

`if current < 0` is the same decision as `max(value, current + value)`: starting fresh wins exactly when the run so far is negative.

## Variations you'll meet

- **Best time to buy and sell once.** Turn prices into daily changes, and the best profit is the maximum subarray of the changes (or 0 if every change loses). Prices `[7, 1, 5, 3, 6, 4]` give changes `[-6, 4, -2, 3, -2]`, whose best run sums to 5: buy at 1, sell at 6.
- **Maximum product subarray.** A negative times a negative is positive, so you must track the smallest product ending here as well as the largest.
- **Circular arrays**, where a run may wrap from the end to the start. The best wrapping run is the total minus the *worst* ordinary run, which Kadane can also find by flipping `max` to `min`.

<Callout kind="gotcha" title="Swift gotcha: Int.min as a starting value can crash">
Starting with `var current = Int.min` looks like a safe "smaller than anything". But the first `current + value` with a negative `value` goes below the smallest `Int`, and Swift stops the program with an overflow error rather than wrapping round. Start from the first element instead, as this lesson does.
</Callout>
