## Why it matters

In M07 you learnt a rule of thumb: the end of an array is cheap and the front is expensive. Having built `insert` and `remove(at:)` yourself, you can now see exactly why, and put a number on it. Counting **shifted elements** turns a vague "it's slower" into a precise cost, and it's the difference between an app that handles 100 items and one that handles 100,000. This lesson counts the shifts, then shows the tricks that avoid them.

## Count the elements that move

An array has no gaps. To insert at `index`, every element from `index` to the end moves one slot right. To remove at `index`, every element after it moves one slot left. So for an array of n elements:

| Operation | Elements shifted |
| --- | --- |
| insert at `index` | n − index |
| remove at `index` | n − 1 − index |

Plug in the three positions people care about, for an array of 8 elements:

| Position | Insert shifts | Remove shifts | Cost |
| --- | --- | --- | --- |
| front (`index` 0) | 8 | 7 | O(n) |
| middle (`index` 4) | 4 | 3 | O(n) |
| end (`index` 8 for insert, 7 for remove) | 0 | 0 | O(1) |

The middle shifts half as much as the front, but half of n is still proportional to n, so it's O(n) too. Only the end is O(1). An insert at the end can still trigger a growth, so it's O(1) **amortised**, as the last lesson showed.

## Watching the shifts add up

One O(n) insert is fine. The trouble starts when you do one per element. This program builds three arrays of 1,000 numbers, inserting each new number at the front, the middle or the end, and counts every element it moves:

```swift run
// Inserts value at index by shifting by hand, and returns how many elements moved
func insert(_ value: Int, at index: Int, into numbers: inout [Int]) -> Int {
    numbers.append(0)                         // one extra slot at the end
    var moved = 0
    var position = numbers.count - 1
    while position > index {
        numbers[position] = numbers[position - 1]
        position -= 1
        moved += 1
    }
    numbers[index] = value
    return moved
}

let n = 1_000
var atFront: [Int] = []
var inMiddle: [Int] = []
var atEnd: [Int] = []
var frontMoves = 0
var middleMoves = 0
var endMoves = 0
for value in 0..<n {
    frontMoves += insert(value, at: 0, into: &atFront)
    middleMoves += insert(value, at: inMiddle.count / 2, into: &inMiddle)
    endMoves += insert(value, at: atEnd.count, into: &atEnd)
}
print("front: \(frontMoves) moves")
print("middle: \(middleMoves) moves")
print("end: \(endMoves) moves")
```

```output
front: 499500 moves
middle: 250000 moves
end: 0 moves
```

Inserting at the front moves 0, then 1, then 2, … then 999 elements. That's the triangle sum from [Analysing nested, halving and dependent loops](/dsa/learn/bigo-analysing-loops): 0 + 1 + … + (n − 1) = n(n − 1)/2, which is 499,500 for n = 1,000. Building an array this way is **O(n²)**. Ten times as many elements would mean a hundred times as many moves: about 50 million for 10,000 elements.

Inserting at the end moves nothing at all. Same result, same loop, wildly different cost.

### What about a random position?

If each insert lands at a random index, it shifts n/2 elements on average. Still O(n) each, and still O(n²) for n of them. Average-case luck doesn't rescue an operation whose cost grows with the array.

## Tricks that avoid the shifting

You can't make a front insert cheap in an array. You can usually avoid needing one.

### 1. Build at the end, then reverse once

If you need the elements in reverse order of arrival, append each one and call `reverse()` once at the end. That's n cheap appends plus one O(n) reversal: O(n) in total, instead of O(n²).

### 2. Swap-remove when order doesn't matter

To remove an element from an array whose order you don't care about, like a bag of active enemies in a game, swap it with the last element and remove the last. Nothing shifts:

```swift run
var active = ["ant", "bee", "cat", "dog", "eel"]

// O(1) removal: move the last element into the hole
func swapRemove(at index: Int, from items: inout [String]) -> String {
    items.swapAt(index, items.count - 1)
    return items.removeLast()
}

print(swapRemove(at: 1, from: &active))
print(active)
```

```output
bee
["ant", "eel", "cat", "dog"]
```

The removal is O(1), at the price of scrambling the order: `eel` jumped from the end into the gap.

### 3. Remove many elements in one pass

Calling `remove(at:)` inside a loop shifts the tail again for every removal, so removing many elements from a big array costs O(n²). `removeAll(where:)` walks the array once, sliding each element it keeps straight to its final position: O(n), however many it removes. You'll write that one-pass technique yourself two lessons from now.

```swift run
var readings = [3, -1, 4, -1, 5, -9, 2, -6]
readings.removeAll { $0 < 0 }
print(readings)
```

```output
[3, 4, 5, 2]
```

### 4. Insert a batch at once

Inserting k elements one at a time at the front shifts the tail k times. `insert(contentsOf:at:)` shifts it once, by k places, then copies the new elements in: O(n + k) instead of O(n × k).

```swift run
var playlist = ["intro", "outro"]
playlist.insert(contentsOf: ["verse", "chorus", "verse"], at: 1)
print(playlist)
```

```output
["intro", "verse", "chorus", "verse", "outro"]
```

### 5. Move a start index instead of the elements

To consume an array from the front, like a queue of jobs, don't call `removeFirst()` repeatedly. Keep an index of the next element and move it forward. Nothing shifts. [Swift's hidden costs](/dsa/learn/bigo-swift-hidden-costs) measured `removeFirst()` in a loop over 100,000 elements at 0.6 seconds, and the index version at a few hundredths of a millisecond. M27 builds proper queues on this idea.

## Swift's costs at a glance

| Operation | Cost | Why |
| --- | --- | --- |
| `numbers[i]`, read or write | O(1) | the address formula |
| `append`, `append(contentsOf:)` | O(1) amortised, per element | an occasional growth |
| `removeLast()`, `popLast()` | O(1) | nothing shifts |
| `insert(_:at:)`, `remove(at:)` | O(n − index) | the tail shifts |
| `removeFirst()`, `insert(_:at: 0)` | O(n) | everything shifts |
| `removeAll(where:)` | O(n) | one pass, however many go |
| `dropFirst(k)`, `numbers[2...]` | O(1) | a slice shares the buffer: nothing moves |

<Callout kind="gotcha" title="Swift gotcha: removeFirst() vs dropFirst()">
They sound alike but cost very differently. `removeFirst()` changes the array, shifting every remaining element: O(n). `dropFirst()` changes nothing and returns an `ArraySlice` that starts one element later: O(1). If you only need to read the rest, `dropFirst()` is the cheap one, but remember the slice keeps the original indices, as [ArraySlice and its index pitfalls](/dsa/learn/swift-array-slices) showed.
</Callout>

<Callout kind="warning" title="Hidden O(n²): find, then remove, in a loop">
`if let i = names.firstIndex(of: name) { names.remove(at: i) }` costs O(n) to find plus O(n) to shift. Doing it for each of m names is O(m × n). When you're removing many values, use `removeAll(where:)` with a `Set` of the values to remove, which is one O(n) pass.
</Callout>
