## Why it matters

Two classic problems in this lesson each look like they need a nested loop or a big table of counts, and each falls to a single pass with a couple of variables. **Leaders** teaches you to scan from the right, carrying what you've learnt about the part already seen. **Boyer–Moore majority vote** is a small, surprising algorithm with a beautiful argument for why it works, and it's the kind of reasoning interviews love: not just "what's the code" but "why is it correct". Systems that must agree on a value, like several servers voting on the latest version of some data, rely on the same idea of a majority.

## Leaders: bigger than everything to the right

An element is a **leader** if it's strictly greater than every element to its right. The last element is always a leader, because there's nothing to its right.

In `[16, 17, 4, 3, 5, 2]`, the leaders are 17, 5 and 2. The 16 isn't one: 17 sits to its right.

The brute force checks every element against everything after it: n elements, up to n comparisons each, **O(n²)**. But look at the question differently. An element is a leader exactly when it's bigger than **the largest element to its right**. Scan from the right, keep that largest value as you go, and each element needs one comparison:

```swift run
func leadersBruteForce(_ numbers: [Int]) -> [Int] {
    var result: [Int] = []
    for i in numbers.indices {
        var isLeader = true
        for j in (i + 1)..<numbers.count where numbers[j] >= numbers[i] {
            isLeader = false
        }
        if isLeader {
            result.append(numbers[i])
        }
    }
    return result
}

func leaders(_ numbers: [Int]) -> [Int] {
    guard let last = numbers.last else { return [] }
    var result = [last]                    // the last element always leads
    var largestToTheRight = last
    for value in numbers.dropLast().reversed() where value > largestToTheRight {
        result.append(value)
        largestToTheRight = value
    }
    return result.reversed()               // found right to left
}

let numbers = [16, 17, 4, 3, 5, 2]
print(leadersBruteForce(numbers))
print(leaders(numbers))
print(leaders([5, 5, 3]))
print(leaders([]))
```

```output
[17, 5, 2]
[17, 5, 2]
[5, 3]
[]
```

The single pass is **O(n) time**. Apart from the result, it uses one variable. Leaders are discovered right to left, so the result is reversed once at the end; appending and reversing is O(n), where inserting each one at the front would be O(n²).

Notice that the scan starts from the last element itself rather than from a "smallest possible" value like `Int.min`. If the last element happened to be `Int.min`, `value > Int.min` would be false and it would wrongly be left out. Starting from a real element avoids that edge case entirely.

In `[5, 5, 3]`, only the second 5 leads. The first 5 isn't *strictly* greater than the 5 after it. If a problem says "greater than or equal to", change `>` to `>=`.

<Callout kind="tip">
"Scan from the right with a running maximum" solves a family of problems: replace every element with the largest element to its right, find the best future selling price for each day, count the buildings that can see the sunset to the east. Whenever an answer depends on everything to one side, ask what single value summarises that side.
</Callout>

## The majority element

A value is the **majority** of an array if it appears **more than half** the time: more than n/2 times. `[2, 2, 1, 1, 1, 2, 2]` has majority 2 (4 out of 7). `[4, 4, 1, 1]` has none: 4 appears exactly half the time, which isn't more than half. An array can never have two majorities, because two values can't both take up more than half of it.

Three ways to find it:

| Approach | Time | Extra space |
| --- | --- | --- |
| count every value in a `[Int: Int]` dictionary | O(n) | O(n) |
| sort, then look at the middle element | O(n log n) | depends on the sort |
| Boyer–Moore voting | O(n) | O(1) |

The sorting idea works because a value filling more than half of a sorted array must cover the middle index, n / 2. Boyer–Moore beats both: linear time and only two variables.

## Boyer–Moore voting

Keep a `candidate` and a count of `votes`. Walk the array:

- If `votes` is 0, the current element becomes the candidate, with 1 vote.
- Otherwise, an element equal to the candidate adds a vote, and any other element takes one away.

Here's `[2, 2, 1, 1, 1, 2, 2]`:

| Element | What happens | `candidate` | `votes` |
| --- | --- | --- | --- |
| 2 | votes was 0: new candidate | 2 | 1 |
| 2 | matches | 2 | 2 |
| 1 | differs | 2 | 1 |
| 1 | differs | 2 | 0 |
| 1 | votes was 0: new candidate | 1 | 1 |
| 2 | differs | 1 | 0 |
| 2 | votes was 0: new candidate | 2 | 1 |

The final candidate is 2, the majority.

```swift
func majorityCandidate(_ numbers: [Int]) -> Int? {
    var candidate: Int? = nil
    var votes = 0
    for number in numbers {
        if votes == 0 {
            candidate = number
            votes = 1
        } else if number == candidate {
            votes += 1
        } else {
            votes -= 1
        }
    }
    return candidate
}
```

`candidate` is optional so that an empty array gives `nil`. Comparing `number == candidate` works because Swift can compare an `Int` with an `Int?`.

### Why it works

Every time `votes` goes down, one copy of the candidate is **cancelled out** against one element that's different from it. Think of it as pairing them off and throwing both away. Each cancelled pair contains at most one copy of the majority value.

Now suppose the array has a majority, m, appearing more than n/2 times. Each copy of m can only be cancelled by pairing it with a *different* element, and there are fewer than n/2 of those. There aren't enough other elements to cancel every copy of m, so some copies of m are never cancelled. At the end, the uncancelled elements are exactly the candidate's remaining votes, which are all copies of the candidate. Since some copies of m are among them, the candidate must be m.

<Callout kind="analogy">
Picture a hall where everyone wearing one team's colours must leave the room arm in arm with someone wearing different colours. If one team has more than half the people in the room, the other teams together can't escort all of them out. When the pairing stops, the people left standing all belong to that team.
</Callout>

### The candidate isn't always a majority

The argument starts with "suppose the array has a majority". If it doesn't, the vote still ends with some candidate; it just doesn't mean anything. In `[1, 2, 3]`, the 1 and 2 cancel and 3 is left standing, but 3 appears once out of three.

So unless a problem **guarantees** that a majority exists, make a second pass that counts the candidate and checks that the count is more than half:

```swift run
func majorityCandidate(_ numbers: [Int]) -> Int? {
    var candidate: Int? = nil
    var votes = 0
    for number in numbers {
        if votes == 0 {
            candidate = number
            votes = 1
        } else if number == candidate {
            votes += 1
        } else {
            votes -= 1
        }
    }
    return candidate
}

for numbers in [[2, 2, 1, 1, 1, 2, 2], [3, 1, 3], [1, 2, 3], [4, 4, 1, 1]] {
    if let candidate = majorityCandidate(numbers) {
        let count = numbers.filter { $0 == candidate }.count
        let verdict = count > numbers.count / 2 ? "majority" : "not a majority"
        print(numbers, "candidate", candidate, "appears", count, "times:", verdict)
    }
}
```

```output
[2, 2, 1, 1, 1, 2, 2] candidate 2 appears 4 times: majority
[3, 1, 3] candidate 3 appears 2 times: majority
[1, 2, 3] candidate 3 appears 1 times: not a majority
[4, 4, 1, 1] candidate 4 appears 2 times: not a majority
```

Both passes are O(n), so the total is still O(n). (The `filter` here builds a temporary array to keep the example short. Counting with a loop keeps the extra space at O(1).)

<Callout kind="gotcha" title="More than half, with integer division">
"More than half" is `count > numbers.count / 2`, and integer division makes it right for odd and even lengths alike. For 5 elements, `5 / 2` is 2, so 3 or more copies are needed. For 4 elements it's also 2, so again 3 or more: exactly half, 2 of 4, correctly fails. Writing `>=` would wrongly accept exactly half.
</Callout>

<Callout kind="note">
The idea stretches further. At most **two** values can each appear more than n/3 times, so keeping two candidates with two vote counts finds them in one pass, plus a second pass to check them. It's a good stretch exercise once this version feels natural.
</Callout>
