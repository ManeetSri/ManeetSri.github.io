## Why it matters

Problem statements choose their words carefully: "subarray", "substring", "subsequence", "subset". They sound interchangeable, but each describes a different set of possibilities, and their sizes are wildly different. An array of 30 elements has 465 subarrays and over a billion subsequences. Knowing which one a problem means tells you straight away whether trying everything is possible, and which techniques to reach for when it isn't.

## Three ways to take part of an array

Take `[1, 2, 3]`.

A **subarray** is a run of **consecutive** elements, in their original order. You choose where it starts and where it ends, and take everything in between: `[1]`, `[2]`, `[3]`, `[1, 2]`, `[2, 3]` and `[1, 2, 3]`. That's 6. `[1, 3]` is **not** a subarray, because it skips the 2. For strings, a subarray is called a **substring**.

A **subsequence** keeps the original order but may **skip** elements. You decide, for each element, whether to keep it. All the subarrays are subsequences, plus `[1, 3]`, plus the empty subsequence `[]`: 8 in total. `[3, 1]` is not a subsequence, because it changes the order.

A **subset** is just a **selection** of elements, where order doesn't matter at all. `{1, 3}` and `{3, 1}` are the same subset. `[1, 2, 3]` has 8 subsets, including the empty one.

| Kind | Must be consecutive? | Order matters? | Count for n elements |
| --- | --- | --- | --- |
| subarray (substring) | yes | kept | n(n + 1)/2 non-empty |
| subsequence | no | kept | 2ⁿ, including the empty one |
| subset | no | no | 2ⁿ, including the empty one |

For an array of distinct elements, subsequences and subsets line up one-to-one: both come from deciding, element by element, "in or out". The difference is how the problem treats the result. A subsequence problem cares about the order the kept elements appear in, like "the longest increasing subsequence". A subset problem only cares which elements were picked, like "pick some numbers that add up to 10".

## Counting subarrays

A subarray is fixed by its start and its end, with start ≤ end. Listing them with two loops shows the pattern:

```swift run
let numbers = [1, 2, 3]
var subarrays: [[Int]] = []
for start in numbers.indices {
    for end in start..<numbers.count {
        subarrays.append(Array(numbers[start...end]))
    }
}
print(subarrays)
print(subarrays.count, numbers.count * (numbers.count + 1) / 2)
```

```output
[[1], [1, 2], [1, 2, 3], [2], [2, 3], [3]]
6 6
```

There are n subarrays starting at index 0, n − 1 starting at index 1, and so on down to 1 starting at the last index. That's the triangle sum again: n + (n − 1) + … + 1 = **n(n + 1)/2**, which grows like n²/2.

## Counting subsequences and subsets

Each element is either in or out, independently: 2 choices, n times, so **2ⁿ** possibilities. The bitmask trick from [Bitmasks for subsets and submasks](/dsa/learn/bits-subsets) lists them all, using bit i of a number to mean "element i is in":

```swift run
let numbers = [1, 2, 3]
var subsequences: [[Int]] = []
for mask in 0..<(1 << numbers.count) {
    var picked: [Int] = []
    for index in numbers.indices where mask & (1 << index) != 0 {
        picked.append(numbers[index])
    }
    subsequences.append(picked)
}
print(subsequences)
print(subsequences.count)
```

```output
[[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]
8
```

Because the inner loop walks the indices in order, each list keeps the original order: these are subsequences. Read them as sets and they're the 8 subsets.

## Why the difference decides your approach

Put real sizes in, and the gap between n² and 2ⁿ becomes obvious:

```swift run
for n in [3, 10, 20, 50] {
    let subarrays = n * (n + 1) / 2
    let subsequences = 1 << n         // 2ⁿ
    print("n = \(n): \(subarrays) subarrays, \(subsequences) subsequences")
}
```

```output
n = 3: 6 subarrays, 8 subsequences
n = 10: 55 subarrays, 1024 subsequences
n = 20: 210 subarrays, 1048576 subsequences
n = 50: 1275 subarrays, 1125899906842624 subsequences
```

Using the rough budget from [From n to a feasible complexity](/dsa/learn/bigo-feasibility-table), about 10⁸ simple steps a second:

- **Subarray problems** with n up to a few thousand can try every subarray. At n = 100,000 there are about 5 billion, too many even to look at, so you need an O(n) or O(n log n) idea: Kadane's algorithm, prefix sums (M20) or the sliding window (M22).
- **Subsequence and subset problems** can only try everything up to about n = 20 to 25. Past that, 2ⁿ is hopeless at any speed, and you need dynamic programming or greedy reasoning from Part VII.

So when you read a problem, the word "subarray" says "a brute force is probably O(n²); look for something linear", and "subsequence" says "a brute force is exponential; look for structure".

## Spotting which one a problem means

Problems don't always use the exact word. These phrases are the usual clues:

| The problem says | It means |
| --- | --- |
| contiguous, consecutive, a window, a run, a substring | subarray |
| in order but not necessarily adjacent, delete some elements | subsequence |
| choose some, pick any, a combination, a group | subset |

<Callout kind="gotcha" title="Is the empty one allowed?">
The counts above differ by one depending on whether the empty subarray, subsequence or subset counts, and so can answers. Kadane's algorithm returns −1 for `[-3, -1, -2]` if the run must be non-empty, but 0 if an empty run is allowed. Check the statement, and if it doesn't say, ask.
</Callout>
