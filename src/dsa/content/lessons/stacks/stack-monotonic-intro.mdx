## Why it matters

"For each element, find the next one that's bigger" sounds like it needs a nested loop. A **monotonic stack** does it in a single O(n) pass. The same template answers next smaller, previous greater and previous smaller, and it's the engine behind a whole family of problems: how many days until a warmer day, the span of a stock's price, the largest rectangle in a histogram, and more. Once you recognise its shape, a class of O(n²) problems becomes O(n).

## The problem

> For each element of an array, find the **next greater element**: the first value to its right that's strictly bigger. Use −1 if there isn't one.

| items | 2 | 7 | 3 | 5 | 4 | 6 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| next greater | 7 | 8 | 5 | 6 | 6 | 8 | −1 |

The brute force looks to the right of each element until it finds something bigger:

```swift
for i in items.indices {
    for j in (i + 1)..<items.count where items[j] > items[i] {
        result[i] = items[j]
        break
    }
}
```

On a decreasing array, nothing is ever found, so every element scans all the way to the end: O(n²).

## Elements waiting for an answer

Turn the question around. Instead of each element looking forward, let each element **wait** until something bigger comes along, and let each new element answer everyone it can.

Walk left to right, keeping a stack of the elements still waiting. When a new value arrives:

1. While the element on top of the stack is **smaller** than the new value, the new value is its next greater element. Record it and pop.
2. Push the new element: it's waiting now too.

Here's the key fact: **the waiting values never increase from bottom to top.** If a smaller value were below a bigger one, the bigger one would have answered it on arrival. So when the new value meets a top that's bigger or equal, everything further down is bigger or equal as well, and the popping can stop. The stack is **monotonic**: decreasing from bottom to top.

Step through it. Watch the stack: it always reads from biggest at the bottom to smallest at the top.


In code, the stack holds **indexes**, so each answer can be written into the right position:

```swift run
func nextGreater(_ items: [Int]) -> [Int] {
    var result = Array(repeating: -1, count: items.count)
    var waiting: [Int] = []                 // indexes still looking for something bigger
    for i in items.indices {
        while let top = waiting.last, items[top] < items[i] {
            result[top] = items[i]          // items[i] answers everything smaller that waits
            waiting.removeLast()
        }
        waiting.append(i)
    }
    return result
}

print(nextGreater([2, 7, 3, 5, 4, 6, 8]))
print(nextGreater([5, 4, 3]))
print(nextGreater([]))
```

```output
[7, 8, 5, 6, 6, 8, -1]
[-1, -1, -1]
[]
```

Anything still waiting at the end never found a bigger value, so it keeps its −1. For `[5, 4, 3]`, nothing is ever popped.

**Why it's O(n).** Each index is pushed exactly once and popped at most once. However the pops are spread out, the inner `while` loop runs at most n times in total across the whole program, so the work is O(n), with O(n) space for the stack. It's the same amortised argument as asteroid collision.

## Why store indexes?

Storing values would lose information. With indexes you can:

- write the answer into `result[top]`, the right slot;
- compute **distances**, like `i - top`, which the next lesson needs for "how many days until a warmer day";
- tell apart equal values at different positions.

You can always get the value back with `items[top]`.

## Four variants, one template

Change the comparison or the direction and the same template answers four questions:

| Question | Scan | Pop while the top is | Stack from bottom to top |
| --- | --- | --- | --- |
| Next greater | left to right | smaller than the new value | decreasing |
| Next smaller | left to right | bigger than the new value | increasing |
| Previous greater | left to right | smaller than or equal to the new value | decreasing |
| Previous smaller | left to right | bigger than or equal to the new value | increasing |

For the **next** questions, the answer is recorded for each element **popped**: the new value is what it was waiting for. For the **previous** questions, the answer for the **new** element is whatever is left on top after popping: the nearest earlier element that survived.

```swift run
func previousSmaller(_ items: [Int]) -> [Int] {
    var result = Array(repeating: -1, count: items.count)
    var candidates: [Int] = []              // indexes, values increasing bottom to top
    for i in items.indices {
        while let top = candidates.last, items[top] >= items[i] {
            candidates.removeLast()          // never the answer for anything to the right again
        }
        if let top = candidates.last {
            result[i] = items[top]
        }
        candidates.append(i)
    }
    return result
}

print(previousSmaller([3, 7, 1, 7, 8, 4]))
```

```output
[-1, 3, -1, 1, 7, 1]
```

Popping is safe here because of a simple observation: once a 1 arrives, the 3 and the 7 before it can never be the "previous smaller" for anything further right. The 1 is closer and smaller, so it would always be chosen first.

## Equal values: strict or not?

With duplicates, the choice between `<` and `<=` changes the answers:

```swift run
func nextGreaterOrEqual(_ items: [Int]) -> [Int] {
    var result = Array(repeating: -1, count: items.count)
    var waiting: [Int] = []
    for i in items.indices {
        while let top = waiting.last, items[top] <= items[i] {   // <= instead of <
            result[top] = items[i]
            waiting.removeLast()
        }
        waiting.append(i)
    }
    return result
}

print(nextGreaterOrEqual([2, 2, 3]))
```

```output
[2, 3, -1]
```

With strict `<`, the first 2 waits through the second 2 and is answered by the 3, giving `[3, 3, -1]`. With `<=`, the second 2 answers the first. Read the problem carefully: "strictly greater" and "greater or equal" are different problems, and getting it wrong is the most common monotonic-stack bug. It matters even more when you count things, as the histogram lessons do.

## Circular arrays

> The array wraps around: after the last element comes the first. Find the next greater element of each, searching around the circle.

For `[1, 5, 3, 2]`, the 2 at the end wraps round and finds 5. The trick is to **walk the array twice**, using `i % n` for the index. The second lap answers elements still waiting from the first, but it pushes nothing new, because every element is already in the stack once:

```swift run
func nextGreaterCircular(_ items: [Int]) -> [Int] {
    let n = items.count
    var result = Array(repeating: -1, count: n)
    var waiting: [Int] = []
    for step in 0..<(2 * n) {
        let i = step % n
        while let top = waiting.last, items[top] < items[i] {
            result[top] = items[i]
            waiting.removeLast()
        }
        if step < n {
            waiting.append(i)             // the second lap only answers; it never waits
        }
    }
    return result
}

print(nextGreaterCircular([1, 5, 3, 2]))
print(nextGreaterCircular([4, 4, 4]))
```

```output
[5, -1, 5, 5]
[-1, -1, -1]
```

The 5 is the largest, so even after a full lap nothing beats it. Still O(n): 2n steps, and each index is pushed once and popped at most once.

## Recognising a monotonic stack problem

Reach for one when a problem asks, for each element, about the **nearest** element to one side that's **bigger or smaller**. Phrases like "next warmer day", "how far back until a higher price", "the first taller building" and "the nearest smaller bar on each side" are all this template in disguise.

<Callout kind="gotcha" title="Common mistakes">
- **Storing values instead of indexes.** You lose the position, so you can't fill `result` or measure distances.
- **The wrong comparison.** Mixing up `<` and `<=` changes the answers whenever values repeat. Decide which one the problem means before coding.
- **Pushing on the second lap of a circular array.** Elements would wait twice and be answered twice. Push only while `step < n`.
</Callout>
