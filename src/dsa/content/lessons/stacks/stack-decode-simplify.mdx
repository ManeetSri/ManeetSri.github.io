## Why it matters

Whenever text has **nesting**, a stack is the natural way to read it. Two interview favourites show the two ways a stack can be used. Decoding `"2[a3[b]]"` saves unfinished work on the stack while it reads the inside of a bracket. Simplifying a file path like `/home/user/../photos` uses the stack as the answer itself, pushing folders as you go in and popping them on `..`. Your Mac does the second every time you `cd ..` in Terminal.

## Decode string

> A string is encoded with the rule `k[text]`, meaning `text` repeated `k` times. Brackets can nest. Decode it: `"3[ab]"` becomes `"ababab"`, and `"2[a3[b]]c"` becomes `"abbbabbbc"`.

Reading left to right, you build up the current piece of text. The difficulty is the inner bracket: when `3[` arrives in `"2[a3[b]]c"`, you're in the middle of building `"a"` for the outer bracket, and you have to put it aside, decode `b` three times, then come back and carry on.

"Put it aside and come back later, most recent first" is a stack. On `[`, push what you were building and the count in front of the bracket, then start fresh. On `]`, repeat the piece you've built and glue it onto the saved text:

```swift run
func decode(_ encoded: String) -> String {
    var saved: [(prefix: String, count: Int)] = []
    var current = ""
    var count = 0
    for character in encoded {
        if let digit = character.wholeNumberValue {
            count = count * 10 + digit                 // counts can have several digits
        } else if character == "[" {
            saved.append((current, count))             // put the outer work aside
            current = ""
            count = 0
        } else if character == "]" {
            let (prefix, repeats) = saved.removeLast()
            current = prefix + String(repeating: current, count: repeats)
        } else {
            current.append(character)
        }
    }
    return current
}

for encoded in ["3[ab]", "2[a3[b]]c", "x2[yz]w", "10[z]", "plain"] {
    print("\(encoded) -> \(decode(encoded))")
}
```

```output
3[ab] -> ababab
2[a3[b]]c -> abbbabbbc
x2[yz]w -> xyzyzw
10[z] -> zzzzzzzzzz
plain -> plain
```

Trace `"2[a3[b]]c"`:

| character | action | `current` | stack |
| --- | --- | --- | --- |
| `2` | count = 2 | `""` | |
| `[` | save ("", 2) | `""` | `("", 2)` |
| `a` | append | `"a"` | `("", 2)` |
| `3` | count = 3 | `"a"` | `("", 2)` |
| `[` | save ("a", 3) | `""` | `("", 2) ("a", 3)` |
| `b` | append | `"b"` | `("", 2) ("a", 3)` |
| `]` | "a" + "bbb" | `"abbb"` | `("", 2)` |
| `]` | "" + "abbb" × 2 | `"abbbabbb"` | |
| `c` | append | `"abbbabbbc"` | |

What to notice:

- The stack holds **unfinished work**: the text before each open bracket and how many times the bracket repeats. Its height is the nesting depth.
- `count` is built digit by digit, like reading a number in the calculator, so `10[z]` works.
- `let (prefix, repeats) = saved.removeLast()` unpacks the tuple in one line.

**How long does it take?** At least as long as the output, which can be enormous: `9[9[9[a]]]` is 729 characters from 10. Each `]` also copies the saved prefix, so with deep nesting and long text in front of each bracket, a character can be copied once per level. For typical inputs, the time is close to the length of the output.

### The recursive view

The same algorithm can be written recursively: on `[`, call `decode` on the inside of the bracket, and let the call stack hold the saved prefix and count. That's often shorter to write, but deeply nested input can overflow the call stack, as [Recursion vs iteration, and tail calls](/dsa/learn/rec-vs-iteration) showed. The explicit stack has no such limit.

## Simplify a Unix path

> Turn an absolute Unix path into its simplest form. `.` means "this folder", `..` means "the parent folder", and repeated slashes count as one. The result starts with `/`, has single slashes, and no trailing slash. For example, `"/home//user/./docs/../photos/"` becomes `"/home/user/photos"`.

Here the stack **is** the answer: the list of folders from the root to where you are. Split the path on `/` and handle each part:

- empty or `.`: stay where you are;
- `..`: go up one folder, by popping, unless you're already at the root;
- anything else: go into that folder, by pushing.

```swift run
func simplify(_ path: String) -> String {
    var folders: [Substring] = []
    for part in path.split(separator: "/") {     // repeated slashes give no empty parts
        switch part {
        case ".":
            continue
        case "..":
            _ = folders.popLast()                // at the root, there's nothing to pop
        default:
            folders.append(part)
        }
    }
    return "/" + folders.joined(separator: "/")
}

for path in ["/home//user/./docs/../photos/", "/../", "/a/./b/../../c/", "/.../x", "/"] {
    print("\(path) -> \(simplify(path))")
}
```

```output
/home//user/./docs/../photos/ -> /home/user/photos
/../ -> /
/a/./b/../../c/ -> /c
/.../x -> /.../x
/ -> /
```

What to notice:

- `split(separator:)` drops empty pieces by default, so `//` and the trailing `/` disappear without any extra code.
- `popLast()` on an empty array returns `nil` instead of crashing, so `..` at the root does nothing, matching how a real shell behaves.
- `...` is an ordinary folder name. Only exactly `.` and `..` are special.
- The parts are `Substring`s, views into the original string, so no copies are made until the final `joined`.

It's O(n) for a path of length n: each part is pushed and popped at most once.

## Two ways to use a stack

These problems show the two roles a stack plays in nesting problems:

| | Decode string | Simplify path |
| --- | --- | --- |
| What's on the stack | work put aside until a bracket closes | the answer so far |
| Push when | an opening bracket starts something new | you enter a folder |
| Pop when | the bracket closes and the saved work resumes | `..` leaves a folder |

Balanced brackets and the calculators were the first kind. Asteroid collisions, in the next lesson, are the second: the stack holds the survivors.

<Callout kind="gotcha" title="Common mistakes">
- **Single-digit counts.** Reading `count = digit` instead of `count = count * 10 + digit` breaks `12[x]`.
- **Forgetting to reset.** After saving at `[`, both `current` and `count` must start again from empty and zero.
- **Popping at the root.** `removeLast()` on an empty stack crashes on paths like `/../`. Use `popLast()`.
</Callout>
