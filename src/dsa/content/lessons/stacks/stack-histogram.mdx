## Why it matters

"Largest rectangle in a histogram" is the hardest classic monotonic-stack problem, and the one interviewers use to see whether you really understand the technique rather than having memorised next greater element. It combines both directions, previous smaller and next smaller, in a single pass, and it introduces the **sentinel**, a fake element that removes an awkward special case. It's also a building block: the next lesson uses it to find the largest rectangle of 1s in a grid.

## The problem

> A histogram has bars of width 1 and the given heights, standing side by side. Find the area of the largest rectangle that fits entirely inside the bars.

For heights `[2, 1, 5, 6, 2, 3]`, the answer is 10: the bars of height 5 and 6 together hold a rectangle 5 high and 2 wide.

```text title="Heights 2 1 5 6 2 3; the best rectangle is marked with #"
      .
    # #
    # #
    # #   .
.   # # . .
. . # # . .
```

Rectangles can be wide and short too. Across all six bars, the height is limited by the shortest bar, 1, giving an area of only 6.

## Brute force: every range

Every rectangle spans some range of bars, and its height is the **shortest** bar in that range. Try every start, extend the end one bar at a time, and keep a running minimum:

```swift
var best = 0
for start in heights.indices {
    var lowest = Int.max
    for end in start..<heights.count {
        lowest = min(lowest, heights[end])
        best = max(best, lowest * (end - start + 1))
    }
}
```

That's O(n²): fine for a thousand bars, hopeless for a hundred thousand.

## Turn it around: each bar as the shortest

The best rectangle is limited by its shortest bar, so its height **equals the height of some bar**. So ask, for each bar: what's the widest rectangle in which **this** bar is the shortest?

Starting from the bar, the rectangle can stretch left and right across every bar that's at least as tall, stopping at the first **strictly shorter** bar on each side. Those two stopping points are exactly the **previous smaller** and **next smaller** elements from [Monotonic stack: next greater element](/dsa/learn/stack-monotonic-intro):

> width = nextSmallerIndex − previousSmallerIndex − 1

Use −1 when there's no shorter bar to the left, and n when there's none to the right, as if invisible walls stood immediately outside the histogram. Two monotonic-stack passes find every boundary:

```swift run
func largestAreaTwoPasses(_ heights: [Int]) -> Int {
    let n = heights.count
    var left = Array(repeating: -1, count: n)     // index of the previous shorter bar, or -1
    var right = Array(repeating: n, count: n)     // index of the next shorter bar, or n
    var stack: [Int] = []
    for i in 0..<n {
        while let top = stack.last, heights[top] >= heights[i] {
            stack.removeLast()
        }
        left[i] = stack.last ?? -1
        stack.append(i)
    }
    stack.removeAll()
    for i in stride(from: n - 1, through: 0, by: -1) {
        while let top = stack.last, heights[top] >= heights[i] {
            stack.removeLast()
        }
        right[i] = stack.last ?? n
        stack.append(i)
    }
    var best = 0
    for i in 0..<n {
        best = max(best, heights[i] * (right[i] - left[i] - 1))
    }
    print("left: ", left)
    print("right:", right)
    return best
}

print(largestAreaTwoPasses([2, 1, 5, 6, 2, 3]))
```

```output
left:  [-1, -1, 1, 2, 1, 4]
right: [1, 6, 4, 4, 6, 6]
10
```

For the bar of height 5 at index 2, the previous shorter bar is at index 1 and the next shorter is at index 4, so its rectangle is 4 − 1 − 1 = 2 bars wide: area 10. For the bar of height 1 at index 1, there are walls at −1 and 6: width 6, area 6. This is O(n) time, with three arrays of O(n) space.

## One pass: answer each bar when it's popped

Look at the first pass again. A bar is popped when a **shorter** bar arrives. At that moment, two facts are known:

- the bar arriving at index `i` is the popped bar's **next smaller**;
- the bar now underneath it on the stack is its **previous smaller**, because the stack's heights increase from bottom to top.

So the popped bar's rectangle can be measured right there, and the second pass and both arrays disappear. One problem remains: bars that are never popped, because nothing shorter comes after them. Fix that with a **sentinel**: pretend there's one more bar of height 0 at the end. It's shorter than everything, so it pops every bar left on the stack.

```swift run
func largestArea(_ heights: [Int]) -> Int {
    var rising: [Int] = []                        // bar indexes, heights increasing bottom to top
    var best = 0
    for i in 0...heights.count {
        let height = i < heights.count ? heights[i] : 0     // a sentinel bar of height 0 at the end
        while let top = rising.last, heights[top] >= height {
            rising.removeLast()
            let left = rising.last ?? -1          // the previous shorter bar
            let width = i - left - 1              // bar i is the next shorter bar
            best = max(best, heights[top] * width)
        }
        rising.append(i)
    }
    return best
}

for heights in [[2, 1, 5, 6, 2, 3], [3, 3, 3], [1, 2, 3, 4, 5], [6, 2, 5, 4, 5, 1, 6], [], [7]] {
    print(heights, largestArea(heights))
}
```

```output
[2, 1, 5, 6, 2, 3] 10
[3, 3, 3] 9
[1, 2, 3, 4, 5] 9
[6, 2, 5, 4, 5, 1, 6] 12
[] 0
[7] 7
```

| 0 | 2 | | | | | 2 |
| 1 | 1 | index 0 (2) | −1 | 1 | 2 | 1 |
| 2 | 5 | | | | | 1 5 |
| 3 | 6 | | | | | 1 5 6 |
| 4 | 2 | index 3 (6) | 2 | 1 | 6 | |

| 5 | 3 | | | | | 1 2 3 |

| | | index 4 (2) | 1 | 4 | 8 | |

The same trace, step by step. The shaded area is the rectangle measured for the popped bar (amber), bounded by its two shorter neighbours:

```visual arrayTrace

```

The best is 10. Each index is pushed once and popped at most once: **O(n) time, O(n) space**.

What to notice:

- **The loop runs to `heights.count` inclusive.** That extra step is the sentinel. It's pushed at the very end, but the loop finishes before anything reads `heights` at that index.
- **`rising.last ?? -1` is the left wall.** When the stack is empty after popping, nothing to the left is shorter, so the rectangle reaches all the way to the start.
- **The width doesn't include either boundary:** the shorter bars at `left` and `i` are excluded, giving `i - left - 1` bars.

<Callout kind="analogy">
Picture pouring a horizontal line of paint at each bar's height. It spreads sideways over every bar that's at least as tall and stops at the first shorter bar on each side. The monotonic stack finds both stopping points for every bar in one sweep.
</Callout>

## What about equal heights?

The code pops when the top is **greater than or equal** to the new height. In `[3, 3, 3]`, the first 3 is popped by the second, with a width of only 1, which undercounts it. That's fine: the **last** bar of a run of equal heights is popped with the full width, by the sentinel here, giving 3 × 3 = 9. One bar in each run of equal heights always gets the right width, and that's all the maximum needs. Popping only on strictly greater heights also works: then equal bars stay on the stack and the earliest one is measured with the full width. Either way, be consistent, and test a run of equal heights.

## Sentinels in general

A **sentinel** is a fake element added to the input so that the general case also handles the boundary. Here, a 0 at the end forces every bar to be popped, and −1 stands in for a wall at the left. You met the same idea with dummy nodes in [Dummy and sentinel nodes](/dsa/learn/ll-sentinel). The question to ask is: "what fake value would make my edge case look like every other case?"

<Callout kind="gotcha" title="Common mistakes">
- **No sentinel.** Without the final 0, an increasing histogram like `[1, 2, 3, 4, 5]` never pops anything, and the answer comes out as 0. You'd need a separate loop to empty the stack.
- **Off-by-one widths.** The width is `i - left - 1`, not `i - left` or `i - top`. When the stack is empty, `left` is −1 and the width is `i`.
- **Reading the sentinel's height from the array.** Index `heights.count` is out of range; use 0 there instead.
</Callout>

## Practice

**Largest rectangle in a histogram** asks for this algorithm on up to 100,000 bars, where the brute force needs billions of steps, and then uses it again on every row of a grid, which is the next lesson's idea.

  back: "The best rectangle's height equals some bar's height. For each bar as the shortest, its rectangle stretches between the previous and next strictly shorter bars: width = next − previous − 1."
- id: histogram-pop
  front: "In the one-pass histogram algorithm, what's known when a bar is popped?"
  back: "The arriving bar is its next shorter bar, and the bar below it on the stack (or −1) is its previous shorter bar, so its widest rectangle can be measured."
- id: histogram-sentinel
  front: "Why does the histogram algorithm add a bar of height 0 at the end?"
  back: "It's shorter than every bar, so it pops everything left on the stack and every bar's rectangle gets measured."
