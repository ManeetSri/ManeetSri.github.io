## Why it matters

A **stack** is the simplest data structure with a rule: the last thing you put in is the first thing you take out. That rule is exactly what you need whenever work has to be finished in the reverse order it was started: matching brackets, undoing edits, evaluating expressions, backtracking out of a maze, and every recursive call you've ever made. This module is a tour of the problems a stack solves. It starts by finishing the `Stack<Element>` you began in M10, turning it into a type that feels built into Swift.

## Where we left off

In [Generic types: `Stack<Element>`](/dsa/learn/swift-generic-types) you built a generic stack with `push`, `pop`, `peek`, `isEmpty` and `count`, keeping the elements in a private array. [ExpressibleByArrayLiteral](/dsa/learn/swift-array-literal) let you write `let stack: Stack = [1, 2, 3]`. And [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack) used a plain array as a stack to replace the call stack.

Here's the behaviour once more, one operation at a time:

```visual stackQueue
kind: stack
operations: ["push 4", "push 8", "push 15", "peek", "pop", "push 16", "pop", "pop"]
```

Every operation happens at the top. Nothing below the top is ever touched, which is why each operation is O(1).

## Why the top is the end of the array

The private array could keep the top at either end. Only one choice is fast:

- **Top at the end:** `append`, `popLast()` and `last` touch only the final element. O(1), or amortised O(1) for `append` when the array grows.
- **Top at the front:** `insert(_:at: 0)` and `removeFirst()` shift every other element along. O(n) for each push and pop.

A linked list, which you built in [Build `LinkedList<T>`](/dsa/learn/ll-build-singly), also gives O(1) push and pop at its head. But every push allocates a new node somewhere on the heap, and following `next` pointers jumps around memory. An array keeps the elements side by side and reuses its spare capacity, so in Swift an array-backed stack is almost always faster.

## The finished type

A finished data structure does more than work. It documents the cost of each operation, behaves like the standard library's collections, and plays well with the rest of Swift. Here are the additions:

- **`@discardableResult` on `pop()`**, so you can pop and ignore the value without a warning, as with `Array.popLast()`.
- **An array literal**, listed bottom to top: in `[4, 8, 15]`, 15 is on top.
- **`Sequence` conformance that goes top first.** Iterating should visit elements in the order `pop()` would return them, without removing anything. The array's `reversed()` view does exactly that, in O(1), without copying.
- **`CustomStringConvertible`**, so `print(stack)` shows something readable.
- **`Equatable` when the elements are.** A conditional conformance with an empty body: Swift synthesises `==` from the stored array, as long as `Element: Equatable`.

```swift run
/// A last-in, first-out stack. The top is the end of the array.
struct Stack<Element> {
    private var storage: [Element] = []

    init() {}

    /// Puts an element on top. Amortised O(1).
    mutating func push(_ element: Element) {
        storage.append(element)
    }

    /// Removes and returns the top element, or nil if empty. O(1).
    @discardableResult
    mutating func pop() -> Element? {
        storage.popLast()
    }

    /// The top element without removing it, or nil if empty. O(1).
    func peek() -> Element? {
        storage.last
    }

    var isEmpty: Bool { storage.isEmpty }
    var count: Int { storage.count }
}

extension Stack: ExpressibleByArrayLiteral {
    /// Elements are listed bottom to top: in [1, 2, 3], 3 is on top.
    init(arrayLiteral elements: Element...) {
        storage = elements
    }
}

extension Stack: Sequence {
    /// Iterates from the top down, the order pop() would return them.
    func makeIterator() -> ReversedCollection<[Element]>.Iterator {
        storage.reversed().makeIterator()
    }
}

extension Stack: CustomStringConvertible {
    var description: String {
        storage.isEmpty ? "Stack (empty)" : "Stack " + storage.map { "\($0)" }.joined(separator: " | ") + " <- top"
    }
}

extension Stack: Equatable where Element: Equatable {}

var plates: Stack = [4, 8, 15]
plates.push(16)
print(plates)
print(plates.pop() ?? -1, plates.peek() ?? -1, plates.count)
print(Array(plates))
print(plates.map { $0 * 2 })
print(plates.contains(8), plates.max() ?? 0)
print(plates == [4, 8, 15])
plates.pop()
plates.pop()
plates.pop()
print(plates, plates.isEmpty, plates.pop() == nil)
```

```output
Stack 4 | 8 | 15 | 16 <- top
16 15 3
[15, 8, 4]
[30, 16, 8]
true 15
true
Stack (empty) true true
```

What to notice:

- `Array(plates)` and `map` visit 15 first: the top. Conforming to `Sequence` with one method unlocked `map`, `contains`, `max` and everything else from [Sequence and IteratorProtocol](/dsa/learn/swift-sequence-iterator).
- `plates == [4, 8, 15]` compares with a literal, because the literal becomes a `Stack` from the context.
- The three bare `plates.pop()` calls compile without warnings, thanks to `@discardableResult`.
- `makeIterator()` returns `ReversedCollection<[Element]>.Iterator`, the iterator type of the reversed view. Swift works out the sequence's `Element` from it.

## A stack is a value

Because `Stack` is a struct holding an array, copying it gives an independent stack, and the copy is cheap until one of them changes, thanks to copy-on-write:

```swift run
struct Stack<Element> {
    private var storage: [Element] = []
    init(_ elements: [Element]) { storage = elements }
    mutating func push(_ element: Element) { storage.append(element) }
    @discardableResult mutating func pop() -> Element? { storage.popLast() }
    var bottomToTop: [Element] { storage }
}

var original = Stack(["a", "b"])
var copy = original
copy.push("c")
original.pop()
print(original.bottomToTop)
print(copy.bottomToTop)
```

```output
["a"]
["a", "b", "c"]
```

That matters for algorithms that save a snapshot of a stack and carry on changing it, such as backtracking: the snapshot can't be changed behind your back.

## Arrays as stacks

In interview code and quick scripts, most Swift programmers skip the wrapper and use an array directly. The translation is mechanical:

| Stack | Array |
| --- | --- |
| `push(x)` | `append(x)` |
| `pop()` | `popLast()` |
| `peek()` | `last` |
| `isEmpty` | `isEmpty` |
| `count` | `count` |

The rest of this module uses plain arrays inside algorithms, because that's what you'll write under time pressure. A named `Stack` type earns its place in larger code: it says what the collection is for, and it makes it impossible to reach into the middle by accident.

## The DSAKit version

The companion package's `DSAKit` module has the finished `Stack<Element>`: everything above, plus a `top` property (the same as `peek()`), `init(_:)` from any sequence, `removeAll(keepingCapacity:)`, `reserveCapacity(_:)`, and `Hashable` when the elements are. It's tested with a hundred thousand pushes, interleaved operations and copies. Problems in later modules can use it:

```swift
import DSAKit

var history: Stack<String> = []
history.push("home")
history.push("settings")
print(history.pop() ?? "")      // settings
```

<Callout kind="gotcha" title="Swift gotcha: removeLast() crashes, popLast() doesn't">
On an empty array, `removeLast()` stops the program with "Can't remove last element from an empty collection", while `popLast()` returns `nil`. Use `popLast()` whenever the stack might be empty, which in bracket-matching and expression problems is exactly the case you're testing for. `removeLast()` is fine right after checking `last`, such as in `while let top = stack.last, … { stack.removeLast() }`.
</Callout>
