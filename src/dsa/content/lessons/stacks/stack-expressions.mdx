## Why it matters

How does a calculator know that `3 + 4 * 2` is 11 and not 14? How does a compiler turn `a + b * c` into instructions? Both rearrange the expression into a form with no parentheses and no precedence rules, called **postfix**, and then evaluate it with a stack. The rearranging is done with a second stack, by an algorithm Edsger Dijkstra named the **shunting-yard algorithm**. Together they're the cleanest example of stacks doing real work, and the basis of the calculator problems in the next lesson.

## Three ways to write an expression

The way you learned at school puts each operator **between** its operands. That's **infix**. It needs precedence rules (`*` before `+`) and parentheses to override them. There are two other ways:

| infix | prefix (Polish) | postfix (reverse Polish) |
| --- | --- | --- |
| `3 + 4` | `+ 3 4` | `3 4 +` |
| `3 + 4 * 2` | `+ 3 * 4 2` | `3 4 2 * +` |
| `(3 + 4) * 2` | `* + 3 4 2` | `3 4 + 2 *` |
| `8 - 3 - 2` | `- - 8 3 2` | `8 3 - 2 -` |

In **postfix**, each operator comes **after** its two operands. Look at the second and third rows: the parentheses have vanished, and the order of the operators alone says what happens first. Postfix needs no precedence rules and no parentheses, ever. Some Hewlett-Packard calculators famously used it, and the name "reverse Polish" honours the Polish logician Jan Łukasiewicz, who invented prefix notation.

## Evaluating postfix with a stack

Read the tokens left to right:

- A **number** goes on the stack.
- An **operator** pops two numbers, applies itself, and pushes the result.

At the end, the stack holds exactly one number: the answer.

```swift run
func evaluatePostfix(_ expression: String) -> Int? {
    var values: [Int] = []
    for token in expression.split(separator: " ") {
        if let number = Int(token) {
            values.append(number)
            continue
        }
        guard let right = values.popLast(), let left = values.popLast() else {
            return nil                          // an operator without two operands
        }
        switch token {
        case "+": values.append(left + right)
        case "-": values.append(left - right)
        case "*": values.append(left * right)
        case "/": values.append(left / right)
        default: return nil                     // an unknown token
        }
    }
    return values.count == 1 ? values[0] : nil  // exactly one value must remain
}

print(evaluatePostfix("3 4 +") ?? 0)
print(evaluatePostfix("5 1 2 + 4 * + 3 -") ?? 0)
print(evaluatePostfix("8 2 /") ?? 0, evaluatePostfix("2 8 /") ?? 0)
print(evaluatePostfix("1 +") == nil, evaluatePostfix("1 2") == nil)
```

```output
7
14
4 0
true true
```

Here's the second expression, `5 1 2 + 4 * + 3 -`, step by step:

| token | action | stack after |
| --- | --- | --- |
| 5, 1, 2 | push each | `5 1 2` |
| + | 1 + 2 | `5 3` |
| 4 | push | `5 3 4` |
| * | 3 × 4 | `5 12` |
| + | 5 + 12 | `17` |
| 3 | push | `17 3` |
| - | 17 − 3 | `14` |

What to notice:

- **The right operand comes off first.** For `8 2 /`, the stack is `8 2`, so the first pop gives 2 (the right side) and the second gives 8 (the left). Getting this backwards breaks `-` and `/`: `2 8 /` is 2 ÷ 8, which is 0 in integer division.
- **Malformed input is caught by the stack.** `1 +` runs out of operands, and `1 2` leaves two values behind. Both return `nil`.
- `Int(token)` parses `"-3"` as a negative number but returns `nil` for `"-"` on its own, so negative numbers and the minus operator don't get confused.

Each token is pushed or popped a constant number of times: **O(n)** for n tokens.

## From infix to postfix: the shunting-yard algorithm

Dijkstra pictured a railway yard. Numbers go straight through to the output track. Operators wait in a siding, the **operator stack**, until it's their turn. The rules:

1. **Number:** append it to the output.
2. **Operator:** while the operator on top of the stack has **higher or equal** precedence, pop it to the output. Then push the new operator.
3. **`(`:** push it. It acts as a wall: rule 2 never pops past it.
4. **`)`:** pop operators to the output until you reach the `(`, then discard both brackets.
5. **End of input:** pop everything left to the output.

The idea behind rule 2: an operator can't be output until you know nothing after it binds more tightly. When a lower-precedence operator arrives, every waiting operator of higher or equal precedence is safe to output, because it must be applied first.

First, the expression has to be split into **tokens**: whole numbers, operators and brackets. Multi-digit numbers are collected one digit at a time:

```swift run
func tokens(_ expression: String) -> [String] {
    var result: [String] = []
    var number = ""
    for character in expression {
        if character.isWholeNumber {
            number.append(character)            // keep collecting digits
            continue
        }
        if !number.isEmpty {
            result.append(number)               // the number has ended
            number = ""
        }
        if character != " " {
            result.append(String(character))
        }
    }
    if !number.isEmpty {
        result.append(number)
    }
    return result
}

let precedence: [String: Int] = ["+": 1, "-": 1, "*": 2, "/": 2]

func toPostfix(_ expression: String) -> [String] {
    var output: [String] = []
    var operators: [String] = []
    for token in tokens(expression) {
        if let rank = precedence[token] {
            while let top = operators.last, let topRank = precedence[top], topRank >= rank {
                output.append(operators.removeLast())
            }
            operators.append(token)
        } else if token == "(" {
            operators.append(token)
        } else if token == ")" {
            while let top = operators.popLast(), top != "(" {
                output.append(top)
            }
        } else {
            output.append(token)                     // a number
        }
    }
    while let top = operators.popLast() {
        output.append(top)
    }
    return output
}

print(tokens("12/(2+4)*3"))
for expression in ["3 + 4 * 2", "(3 + 4) * 2", "8 - 3 - 2", "3 + 4 * 2 - (1 + 5)"] {
    print("\(expression)  ->  \(toPostfix(expression).joined(separator: " "))")
}
```

```output
["12", "/", "(", "2", "+", "4", ")", "*", "3"]
3 + 4 * 2  ->  3 4 2 * +
(3 + 4) * 2  ->  3 4 + 2 *
8 - 3 - 2  ->  8 3 - 2 -
3 + 4 * 2 - (1 + 5)  ->  3 4 2 * + 1 5 + -
```

Trace the last one, `3 + 4 * 2 - (1 + 5)`:

| token | rule | output | operator stack |
| --- | --- | --- | --- |
| 3 | number | `3` | |
| + | push | `3` | `+` |
| 4 | number | `3 4` | `+` |
| * | `+` is lower, so push | `3 4` | `+ *` |
| 2 | number | `3 4 2` | `+ *` |
| - | pop `*` and `+` (both ≥), push `-` | `3 4 2 * +` | `-` |
| ( | push | `3 4 2 * +` | `- (` |
| 1 | number | `3 4 2 * + 1` | `- (` |
| + | `(` is a wall, so push | `3 4 2 * + 1` | `- ( +` |
| 5 | number | `3 4 2 * + 1 5` | `- ( +` |
| ) | pop `+`, discard `(` | `3 4 2 * + 1 5 +` | `-` |
| end | pop `-` | `3 4 2 * + 1 5 + -` | |

Evaluating that postfix gives 3 + 8 − 6 = 5. The `while let … , let topRank = precedence[top]` condition stops at a `(`, because `precedence["("]` is `nil`: that's how the wall in rule 3 works in code.

## Why "higher or equal"?

`+` and `-` (and `*` and `/`) are **left-associative**: `8 - 3 - 2` means `(8 - 3) - 2 = 3`. When the second `-` arrives, the first one is waiting with *equal* precedence, and popping it first makes it apply first: `8 3 - 2 -`. If rule 2 popped only strictly higher operators, the first `-` would stay put, giving `8 3 2 - -`, which is 8 − (3 − 2) = 7. Wrong.

Exponentiation is **right-associative**: `2 ^ 3 ^ 2` means `2 ^ (3 ^ 2)`, which is 512. For a right-associative operator, pop only operators of strictly higher precedence. Swift itself has no `^` power operator, but expression parsers often support one.

## The whole pipeline

Converting and evaluating are each a single pass with a stack, so working out an infix expression this way is **O(n)** time and space. It also separates two concerns neatly: the shunting-yard handles precedence and brackets, and the evaluator only ever sees the simple postfix form. Compilers do something similar, building a tree from the tokens with the same precedence ideas; trees arrive in Part V.

<Callout kind="gotcha" title="Common mistakes">
- **Popping operands in the wrong order.** The first pop is the right operand. `left - right`, not `right - left`.
- **Treating `-` as a number.** Check for operators before parsing, or use `Int(token)`, which rejects a lone `-`.
- **Forgetting the end of input.** Operators still on the stack must be popped to the output, or `3 + 4` becomes `3 4`.
- **Unary minus.** This algorithm assumes every `-` sits between two operands. `-3 + 5` or `2 * (-1)` needs extra handling, which the next lesson shows.
</Callout>

## Practice

**A postfix calculator** asks you to write both halves, `postfix(from:)` and `evaluate(postfix:)`, and then combine them into a calculator for expressions with `+`, `-`, `*`, `/` and brackets.

```cards
- id: postfix-meaning
  front: "What is postfix notation, and why is it easy to evaluate?"
  back: "Each operator comes after its operands, as in `3 4 +`. It needs no brackets or precedence rules: push numbers, and let each operator pop two and push the result."
- id: postfix-operand-order
  front: "When evaluating postfix, which operand does the first pop give?"
  back: "The right operand. For `8 2 /`, pop 2, then 8, and compute 8 / 2."
- id: shunting-yard-rule
  front: "In the shunting-yard algorithm, what happens when an operator arrives?"
  back: "Pop operators of higher or equal precedence (for left-associative operators) from the stack to the output, stopping at a `(`, then push the new operator."
- id: shunting-yard-brackets
  front: "How does the shunting-yard algorithm handle brackets?"
  back: "Push `(` as a wall. On `)`, pop operators to the output until the `(`, then discard both."
```
