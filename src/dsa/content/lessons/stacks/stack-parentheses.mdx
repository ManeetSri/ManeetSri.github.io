## Why it matters

Every time Xcode highlights the bracket that matches the one under your cursor, or the compiler complains about a missing `}`, a stack is at work. Checking that brackets are balanced is the classic first stack problem: it's small, it shows exactly why "last in, first out" is the right rule, and its shape, push on open and pop on close, reappears in parsers, JSON validators, HTML checkers and the expression evaluators later in this module.

## One kind of bracket: a counter is enough

With only round brackets, you don't need a stack. Count how many are open: add 1 for `(`, subtract 1 for `)`. The text is balanced if the count never drops below zero and ends at zero:

```swift run
func isBalancedRound(_ text: String) -> Bool {
    var open = 0
    for character in text {
        if character == "(" {
            open += 1
        } else if character == ")" {
            open -= 1
            if open < 0 {
                return false           // a ) with nothing to close
            }
        }
    }
    return open == 0
}

for text in ["(a(b)c)", "(()", "())(", ""] {
    print(text.isEmpty ? "(empty)" : text, isBalancedRound(text))
}
```

```output
(a(b)c) true
(() false
())( false
(empty) true
```

Both checks matter. `"(()"` ends with one bracket still open. `"())("` ends at zero, but its count went negative at the third character, where a `)` arrived with nothing to close.

## Several kinds: why counting fails

Add square and curly brackets and counting breaks. Look at `"([)]"`: one of each opener and one of each closer, every count ends at zero, and yet it's wrong. The `)` arrives while the `[` is still open, and the `[` was opened more recently.

That's the key observation. **A closing bracket must match the most recently opened bracket that hasn't been closed yet.** "Most recent first" is exactly what a stack gives you.

## The stack algorithm

- An opening bracket goes on the stack.
- A closing bracket pops the top. If the stack was empty, or the top is the wrong kind, the text is unbalanced.
- Anything else is ignored.
- At the end, the stack must be empty: anything left was never closed.

```swift run
func isBalanced(_ text: String) -> Bool {
    let opener: [Character: Character] = [")": "(", "]": "[", "}": "{"]
    var open: [Character] = []
    for character in text {
        switch character {
        case "(", "[", "{":
            open.append(character)
        case ")", "]", "}":
            guard open.popLast() == opener[character] else {
                return false                     // empty stack, or the wrong kind
            }
        default:
            break                                // not a bracket
        }
    }
    return open.isEmpty
}

for text in ["{[()]}", "([)]", "if (a[i] > 0) { go() }", "((", "]"] {
    print(text, isBalanced(text))
}
```

```output
{[()]} true
([)] false
if (a[i] > 0) { go() } true
(( false
] false
```

The `guard` line does two checks in one. `open.popLast()` is `nil` when the stack is empty, and `opener[character]` is never `nil` for a closer, so comparing them catches both "nothing to close" and "wrong kind". Comparing two optionals with `==` is allowed when the wrapped type is `Equatable`.

Here's the stack for `"([)]"`:

| character | action | stack after |
| --- | --- | --- |
| `(` | push | `(` |
| `[` | push | `( [` |
| `)` | pop `[`, but `)` needs `(` | fail |

And for `"{[()]}"`, the stack grows to `{ [ (` and then each closer pops exactly the opener it needs, leaving it empty. Each character is pushed or popped at most once, so the whole check is **O(n) time and O(n) space** in the worst case, when everything is an opener.

<Callout kind="analogy">
Think of nested boxes. You can only close the box you opened last; to close an outer box, every box inside it must already be shut. The stack is the pile of open boxes, innermost on top.
</Callout>

## Saying where it went wrong

An editor needs more than `false`: it needs a position. Push each opener together with where it appeared, and report the first problem you find:

```swift run
func firstProblem(in text: String) -> String {
    let opener: [Character: Character] = [")": "(", "]": "[", "}": "{"]
    var open: [(bracket: Character, position: Int)] = []
    for (position, character) in text.enumerated() {
        switch character {
        case "(", "[", "{":
            open.append((character, position))
        case ")", "]", "}":
            guard let top = open.popLast() else {
                return "unexpected \(character) at \(position)"
            }
            if top.bracket != opener[character] {
                return "\(character) at \(position) doesn't match \(top.bracket) at \(top.position)"
            }
        default:
            break
        }
    }
    if let unclosed = open.last {
        return "\(unclosed.bracket) at \(unclosed.position) is never closed"
    }
    return "balanced"
}

for text in ["let a = [1, 2)", "f(x))", "{ if (ok) {", "[{}]"] {
    print(firstProblem(in: text))
}
```

```output
) at 13 doesn't match [ at 8
unexpected ) at 4
{ at 10 is never closed
balanced
```

The stack holds named tuples, so it carries whatever information you'll need when an opener is popped. Positions here count `Character`s from 0.

## A variation: how many brackets to add?

How few brackets must you insert into a string of round brackets to balance it? Walk through with a counter. A `)` with nothing open needs a new `(` inserted before it; every `(` still open at the end needs a `)`:

```swift run
func insertionsNeeded(_ text: String) -> Int {
    var open = 0
    var added = 0
    for character in text {
        if character == "(" {
            open += 1
        } else if character == ")" {
            if open == 0 {
                added += 1             // insert a ( to match this )
            } else {
                open -= 1
            }
        }
    }
    return added + open                // plus a ) for each one left open
}

print(insertionsNeeded("())"), insertionsNeeded("((("), insertionsNeeded(")(("), insertionsNeeded("(())"))
```

```output
1 3 3 0
```

With one kind of bracket the counter *is* the stack: it records how many openers are waiting, and since they're all the same kind, that's all there is to know.

<Callout kind="gotcha" title="Common mistakes">
- **Forgetting the final check.** `"(("` never fails during the loop. Only `open.isEmpty` at the end catches it.
- **Popping an empty stack with `removeLast()`.** A text that starts with `)` crashes. Use `popLast()` and treat `nil` as a failure.
- **Mixing up `Character` and `String`.** Looping over a `String` gives `Character`s, so the dictionary and the stack should hold `Character`. `"("` is a `Character` literal when the context expects one.
</Callout>
