## Why it matters

"Implement a basic calculator" comes up in interviews in two classic flavours. Version II has `+`, `-`, `*` and `/` but no brackets, so precedence is the challenge. Version I has brackets and minus signs but only `+` and `-`, so nesting is the challenge. The shunting-yard algorithm from the last lesson solves both, but interviewers usually want something shorter: a single pass with one small stack. These two solutions are worth knowing by heart, because they show how a stack can hold exactly the information you'll need later and nothing more.

## Calculator II: precedence without brackets

> Evaluate a string such as `"14 - 3/2"` containing non-negative integers, `+`, `-`, `*`, `/` and spaces. Division truncates towards zero.

The insight: `*` and `/` only ever affect the **most recent term**. Think of the expression as a sum of terms: `14 - 3/2` is `14 + (-(3/2))`, and `2*3*4 - 10/3` is `(2*3*4) + (-(10/3))`. So keep a stack of terms:

- After `+`, the next number starts a new term: push it.
- After `-`, push the negated number.
- After `*` or `/`, combine the number with the term on top of the stack.

At the end, add up the stack. Each operator is applied when the **next** operator arrives, because only then is its right-hand number complete. Appending a `"+"` to the input is a neat trick: it acts as a final operator that flushes the last number.

```swift run
func calculateII(_ expression: String) -> Int {
    var terms: [Int] = []
    var number = 0
    var previous: Character = "+"            // the operator before `number`
    for character in expression + "+" {
        if let digit = character.wholeNumberValue {
            number = number * 10 + digit
        } else if "+-*/".contains(character) {
            switch previous {
            case "+": terms.append(number)
            case "-": terms.append(-number)
            case "*": terms.append(terms.removeLast() * number)
            default: terms.append(terms.removeLast() / number)
            }
            previous = character
            number = 0
        }
    }
    return terms.reduce(0, +)
}

for expression in ["3+2*2", " 3/2 ", "14 - 3/2", "2*3*4 - 10/3", "7"] {
    print("\(expression) = \(calculateII(expression))")
}
```

```output
3+2*2 = 7
 3/2  = 1
14 - 3/2 = 13
2*3*4 - 10/3 = 21
7 = 7
```

Trace `14 - 3/2`:

| character | action | terms |
| --- | --- | --- |
| `14` | build the number | |
| `-` | previous was `+`: push 14 | `14` |
| `3` | build the number | `14` |
| `/` | previous was `-`: push −3 | `14 -3` |
| `2` | build the number | `14 -3` |
| final `+` | previous was `/`: −3 / 2 = −1 | `14 -1` |

The sum is 13. Two details make it right. Spaces fall through both branches and are ignored. And Swift's `/` truncates towards zero, so −3 / 2 is −1, exactly what "3/2, then subtract" needs.

### Down to O(1) space

Only the top term is ever changed, and everything below it is only ever added up. So replace the stack with two variables: `total`, the sum of finished terms, and `lastTerm`, the one still being multiplied or divided:

```swift
switch previous {
case "+": total += lastTerm; lastTerm = number
case "-": total += lastTerm; lastTerm = -number
case "*": lastTerm *= number
default: lastTerm /= number
}
// ... and at the end, return total + lastTerm
```

Same O(n) time, O(1) extra space. Interviewers often ask for this follow-up.

## Calculator I: brackets and signs

> Evaluate a string such as `"10 - (4 - (3 - 1))"` containing non-negative integers, `+`, `-`, brackets and spaces. A `-` may also negate a bracket or a number, as in `"-(2 + 3)"`.

With only `+` and `-`, every number is either added or subtracted, so keep a running `result` and the `sign` (+1 or −1) for the next number. Brackets are the complication: inside a bracket you start a fresh sum, and when it closes, that sum is combined with whatever was outside. A stack remembers the outside:

- On `(`, push the current `(result, sign)` and start afresh with `result = 0`, `sign = 1`.
- On `)`, finish the inner result, pop the saved pair, and set `result = savedResult + savedSign × inner`.

```swift run
func calculateI(_ expression: String) -> Int {
    var result = 0
    var number = 0
    var sign = 1
    var saved: [(result: Int, sign: Int)] = []
    for character in expression {
        if let digit = character.wholeNumberValue {
            number = number * 10 + digit
        } else if character == "+" || character == "-" {
            result += sign * number               // the number before this sign is complete
            number = 0
            sign = character == "+" ? 1 : -1
        } else if character == "(" {
            saved.append((result, sign))          // remember everything outside the bracket
            result = 0
            sign = 1
        } else if character == ")" {
            result += sign * number
            number = 0
            let outer = saved.removeLast()
            result = outer.result + outer.sign * result
        }
    }
    return result + sign * number
}

for expression in ["1 + 1", " 2-1 + 2 ", "(1+(4+5+2)-3)+(6+8)", "-(2 + 3) + 10", "1 - (-2)", "10 - (4 - (3 - 1))"] {
    print("\(expression) = \(calculateI(expression))")
}
```

```output
1 + 1 = 2
 2-1 + 2  = 3
(1+(4+5+2)-3)+(6+8) = 23
-(2 + 3) + 10 = 5
1 - (-2) = 3
10 - (4 - (3 - 1)) = 8
```

What to notice:

- **Unary minus works for free.** In `-(2 + 3)`, the `-` adds the empty number 0 to the result and sets `sign` to −1. The `(` saves that −1, so when the bracket closes, its 5 is subtracted.
- `1 - (-2)` works the same way: inside the bracket, `-2` is "0 minus 2".
- The stack holds one pair per open bracket, so it's O(depth) space, and the whole thing is O(n) time.

Trace `10 - (4 - (3 - 1))`: the first `(` saves (10, −1), the second saves (4, −1). The inner bracket gives 3 − 1 = 2; closing it gives 4 + (−1) × 2 = 2. Closing the outer one gives 10 + (−1) × 2 = 8.

## Both at once

A calculator with brackets **and** all four operators combines the two ideas. Three common routes:

- Convert to postfix with the shunting-yard algorithm, then evaluate it, as in the last lesson. It handles any precedence rules, and you've already written it.
- Use Calculator II's term stack, and when you meet `(`, evaluate the bracket **recursively** and treat its value as a number. The recursion's call stack replaces the explicit one.
- Keep two stacks, numbers and operators, and apply operators as soon as precedence allows. This is the shunting-yard algorithm evaluating as it goes, instead of producing output.

In an interview, say which you're choosing and why. The postfix route is the most general; the recursive route is often the shortest to write.

<Callout kind="gotcha" title="Swift gotcha: String.count inside a loop">
A common way to spot the last character is `if index == expression.count - 1`. But `String.count` walks the whole string every time, because characters have different sizes, as M08 explained. Inside a loop over the string, that makes the calculator O(n²). Appending a sentinel `"+"`, as above, or converting to an `Array` once, keeps it O(n).
</Callout>
