## Why it matters

The monotonic stack from the last lesson finds the next or previous bigger element. Real problems usually want something about that element: **how far away** it is, or **how many** elements it covers. Two classics show both. "How many days until a warmer day?" measures the distance forward to the next greater element. A stock's **span**, how many days in a row its price has been at or below today's, measures the distance back to the previous greater one, and has to be answered live, one price at a time, as a trading app would.

## Daily temperatures: distance to the next warmer day

> Given daily temperatures, for each day return how many days you'd wait for a strictly warmer one, or 0 if none comes.

| day | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| temperature | 15 | 17 | 16 | 14 | 18 | 13 |
| days to wait | 1 | 3 | 2 | 1 | 0 | 0 |

This is next greater element with one change: instead of recording the warmer **temperature**, record the **distance**, `day - waitingDay`. That's why the stack holds indexes: the index *is* the day.

Walk through it. Day 0 (15) waits. Day 1 (17) is warmer, so it answers day 0 with 1 − 0 = 1, then waits. Days 2 (16) and 3 (14) are colder than everything waiting, so they wait too: the stack holds days 1, 2, 3 with temperatures 17, 16, 14, decreasing as always. Day 4 (18) answers all three: day 3 waited 1 day, day 2 waited 2, and day 1 waited 3. Day 5 (13) waits, and the days still waiting at the end, 4 and 5, keep 0.

Here's the mirror image, so you can write the warmer version yourself in the practice problem: for each day, how many days until the **price drops**? It's the next **smaller** element, as a distance:

```swift run
func daysUntilCheaper(_ prices: [Int]) -> [Int] {
    var waits = Array(repeating: 0, count: prices.count)
    var waiting: [Int] = []                    // days whose price hasn't dropped yet
    for (day, price) in prices.enumerated() {
        while let earlier = waiting.last, prices[earlier] > price {
            waits[earlier] = day - earlier      // the distance, not the value
            waiting.removeLast()
        }
        waiting.append(day)
    }
    return waits
}

print(daysUntilCheaper([9, 8, 10, 12, 7, 11]))
```

```output
[1, 3, 2, 1, 0, 0]
```

The 8 on day 1 waits until the 7 on day 4: three days. The 7 and the 11 never see a lower price. Like every monotonic stack, this is O(n) time and O(n) space.

## Stock span: answering one day at a time

> Prices arrive one per day. After each one, report its **span**: the number of consecutive days, ending today, on which the price was less than or equal to today's.

For the prices 100, 80, 60, 70, 60, 75, 85, the spans are 1, 1, 1, 2, 1, 4, 6. On the day of 75, the run of days at or below it is 60, 70, 60 and 75 itself: 4. On the day of 85, it's everything after the 100: 6.

The span reaches back to the **previous strictly greater** price. It's a "previous greater" question, but with a twist: you don't get the whole array up front. Each answer must be given as the price arrives.

The monotonic stack handles that naturally, because it never looks ahead. Store pairs of `(price, span)`. When a new price arrives, every stored price at or below it is now **covered** by it: pop them and add their spans to its own, because each one already covered its own run of days. What's left on top is the previous greater price, where the span stops.

```swift run
struct StockSpanner {
    private var stack: [(price: Int, span: Int)] = []

    mutating func next(_ price: Int) -> Int {
        var span = 1                                   // today counts
        while let top = stack.last, top.price <= price {
            span += top.span                           // absorb the days it already covered
            stack.removeLast()
        }
        stack.append((price, span))
        return span
    }
}

var spanner = StockSpanner()
let prices = [100, 80, 60, 70, 60, 75, 85]
print(prices.map { spanner.next($0) })
```

```output
[1, 1, 1, 2, 1, 4, 6]
```

Trace the day of 75. The stack holds `(100, 1) (80, 1) (70, 2) (60, 1)`. The 60 is popped, adding 1; the 70 is popped, adding its 2 (which covered itself and the first 60). The 80 is bigger, so popping stops. The span is 1 + 1 + 2 = 4, and `(75, 4)` is pushed.

What to notice:

- **Storing spans makes this possible.** The popped prices are gone forever, but their spans carry forward the count of days they covered.
- **The cost of one call varies,** but each price is pushed once and popped at most once, so n calls cost O(n) in total: **O(1) amortised** per call, the same accounting as `Array.append`.
- `prices.map { spanner.next($0) }` calls a mutating method inside a closure. That's fine here because `spanner` is a `var` captured by the closure, as you saw in [Capturing values](/dsa/learn/swift-capturing).

### The offline version

If you do have all the prices up front, the same answer comes from the "previous greater" template with indexes: the span is `day - (index of the previous strictly greater price)`, or `day + 1` if there isn't one.

```swift run
func spans(_ prices: [Int]) -> [Int] {
    var result: [Int] = []
    var higher: [Int] = []                       // indexes with a strictly higher price, decreasing
    for (day, price) in prices.enumerated() {
        while let top = higher.last, prices[top] <= price {
            higher.removeLast()
        }
        result.append(day - (higher.last ?? -1))
        higher.append(day)
    }
    return result
}

print(spans([100, 80, 60, 70, 60, 75, 85]))
```

```output
[1, 1, 1, 2, 1, 4, 6]
```

Using −1 as the "index" of an imaginary wall before day 0 makes the first-day case fall out of the same formula. Both versions are correct; the pairs version also works when the prices stream in.

## Strictness, again

The two problems use opposite rules, and that's typical:

- Daily temperatures wants a **strictly** warmer day, so pop while the waiting temperature is `<` today's. Equal days keep waiting.
- Stock span counts days **at or below** today, so pop while the stored price is `<=` today's. Equal prices are absorbed.

Swap either comparison and the answers change whenever values repeat. When you meet a new monotonic-stack problem, write down what happens to equal values before writing any code.

<Callout kind="gotcha" title="Common mistake: recording the value instead of the distance">
Copying the next-greater code and writing `waits[earlier] = temperatures[day]` gives the warmer temperature, not the wait. The answer is `day - earlier`, which is only possible because the stack stores indexes.
</Callout>
