## Why it matters

"Design a stack that can also return its minimum in O(1)" is one of the most common design questions in interviews, and it teaches an idea far bigger than itself: **store a summary alongside each element**, so that undoing an operation also undoes its effect on the summary. The same trick gives an undo history that remembers the best score so far, or, combined with the queue made from two stacks in M27, a queue that knows its minimum.

## The goal

A stack of integers with these operations, **all O(1)**:

- `push(_:)`, `pop()` and `top`, as usual;
- `minimum`: the smallest value currently in the stack, or `nil` if it's empty.

Scanning the stack for the minimum is O(n). Keeping the stack sorted breaks the stack order. Something smarter is needed.

## The obvious attempt, and why it fails

Keep one extra variable holding the minimum and update it on each push. Pushing is easy. Popping is the problem:

```swift run
struct BrokenMinStack {
    private var items: [Int] = []
    private(set) var minimum: Int?

    mutating func push(_ value: Int) {
        items.append(value)
        minimum = min(value, minimum ?? value)
    }

    mutating func pop() -> Int? {
        items.popLast()          // but what should minimum become now?
    }
}

var broken = BrokenMinStack()
broken.push(5)
broken.push(2)
broken.push(8)
_ = broken.pop()
_ = broken.pop()                 // removes the 2
print(broken.minimum ?? 0)
```

```output
2
```

The stack now holds only 5, but it still claims the minimum is 2. When the minimum is popped, the variable has no idea what the previous minimum was. Finding it means scanning, which is O(n).

## Remember the minimum at every level

The fix: when you push a value, also record **the minimum of everything at or below it**. Each entry is a pair `(value, minimum)`. The top entry's minimum is the whole stack's minimum. And when you pop, the entry underneath already remembers the minimum as it was before, so nothing needs recomputing.

```swift run
struct MinStack {
    private var entries: [(value: Int, minimum: Int)] = []

    mutating func push(_ value: Int) {
        let minimum = min(value, entries.last?.minimum ?? value)
        entries.append((value, minimum))
    }

    @discardableResult
    mutating func pop() -> Int? {
        entries.popLast()?.value
    }

    var top: Int? { entries.last?.value }
    var minimum: Int? { entries.last?.minimum }
}

var stack = MinStack()
for value in [5, 2, 8, 1] {
    stack.push(value)
    print("push \(value): minimum \(stack.minimum!)")
}
while let value = stack.pop() {
    print("pop \(value): minimum \(stack.minimum.map(String.init) ?? "none")")
}
```

```output
push 5: minimum 5
push 2: minimum 2
push 8: minimum 2
push 1: minimum 1
pop 1: minimum 2
pop 8: minimum 2
pop 2: minimum 5
pop 5: minimum none
```

Here are the entries after the four pushes, bottom to top:

| entry | value | minimum at or below |
| --- | --- | --- |
| 0 | 5 | 5 |
| 1 | 2 | 2 |
| 2 | 8 | 2 |
| 3 | 1 | 1 |

Popping 1 exposes entry 2, which says 2. Popping down to entry 0 says 5. Each answer was written down at push time, when it was easy to work out.

What to notice:

- `entries.last?.minimum ?? value` handles the empty stack: the first value is its own minimum.
- Every operation does a constant amount of work: **O(1) time**. The price is storing two integers per element: still **O(n) space**, only twice as much.
- This works because a stack only ever changes at the top. Each entry's "minimum below me" can never go stale, because nothing below it can change while it's there.

## Saving space with a second stack

The pairs repeat the same minimum many times. A leaner version keeps a second stack holding only the minimums, and pushes onto it only when a new value is **less than or equal to** the current minimum. When a popped value equals the top of the minimum stack, pop that too:

```swift run
struct LeanMinStack {
    private var items: [Int] = []
    private var minimums: [Int] = []

    mutating func push(_ value: Int) {
        items.append(value)
        if value <= (minimums.last ?? value) {
            minimums.append(value)          // a new minimum, or a tie with it
        }
    }

    @discardableResult
    mutating func pop() -> Int? {
        guard let value = items.popLast() else {
            return nil
        }
        if value == minimums.last {
            minimums.removeLast()
        }
        return value
    }

    var minimum: Int? { minimums.last }
    var savedMinimums: Int { minimums.count }
}

var lean = LeanMinStack()
for value in [3, 7, 9, 2, 2, 6] {
    lean.push(value)
}
print(lean.minimum!, lean.savedMinimums)
lean.pop()
lean.pop()
print(lean.minimum!)
lean.pop()
print(lean.minimum!)
```

```output
2 3
2
3
```

Six values, but only three saved minimums: 3, 2 and 2. When values mostly rise, this saves a lot; in the worst case, falling values, it stores as much as the pairs version.

The `<=` matters. Both 2s were saved, so popping the first 2 left the second one as the minimum. If ties weren't saved, only the first 2 would be recorded, and popping the top 2 would remove it from `minimums`, wrongly reporting 3 while a 2 is still in the stack.

## The same idea, elsewhere

The pairs trick works for any summary that can be computed from "the new value" and "the summary of everything below":

- a **max stack**, with `max` instead of `min`;
- the **sum** or **count of negatives** below each element;
- an editor's undo stack that stores "the longest the document has been" with each edit.

It can't directly answer questions about the *middle* of the stack, and it relies on changes happening only at the top. [A queue from two stacks](/dsa/learn/queue-two-stacks) builds a queue out of two stacks; make both of them min stacks and the queue gets an O(1) minimum too.

<Callout kind="gotcha" title="Common mistake: a sentinel instead of an optional">
It's tempting to start with `var minimum = Int.max` and skip the optionals. Then an empty stack reports `Int.max` as its minimum, which is a lie, and a stack holding `Int.max` itself is indistinguishable from an empty one. Return `nil` for "no minimum", as `Array.min()` does.
</Callout>

## Practice

**Min stack** asks you to build this type with O(1) operations, tested with duplicates, `Int.min` and `Int.max`, and 200,000 operations.

```cards
- id: min-stack-pairs
  front: "How does a min stack return its minimum in O(1)?"
  back: "Each entry stores its value and the minimum of everything at or below it. The top entry's minimum is the stack's minimum, and popping exposes the previous minimum."
- id: min-stack-single-variable
  front: "Why can't a min stack keep a single `minimum` variable?"
  back: "When the minimum is popped, the variable doesn't know the previous minimum, and finding it means scanning: O(n)."
- id: lean-min-stack-equal
  front: "In the two-stack min stack, why push onto the minimum stack when the value is equal to the current minimum?"
  back: "So duplicates of the minimum are each recorded. Otherwise popping one copy would remove the minimum while another copy is still in the stack."
```
