## Why it matters

Some problems look like they need you to compare every element with every other one, until you notice that each new element only ever interacts with the **most recent survivors**. Then a stack of survivors solves them in one pass. Asteroid collision and "remove k digits" are two favourites with that shape. The second is also your first **monotonic stack**: a stack whose elements are always in sorted order, the idea the rest of this module is built on.

## Asteroid collision

> A row of asteroids moves along a line, all at the same speed. Each is a non-zero integer: its size is the absolute value, and its sign is its direction, positive for right and negative for left. When a right-mover meets a left-mover, the smaller one explodes; if they're the same size, both do. Asteroids moving the same way never meet. Return the survivors, in order.

For `[10, 2, -5]`: the −5 hits the 2 and destroys it, then hits the 10 and is destroyed. Only `[10]` survives.

### Who can collide with whom?

A collision needs a right-mover on the **left** and a left-mover on the **right**. So process the asteroids left to right, keeping a stack of everything that has survived so far:

- A right-mover can't hit anything yet. Push it.
- A left-mover hits the right-mover on top of the stack, if there is one. If it wins, that asteroid is popped and it carries on to the next one down. It keeps going until it's destroyed, or the top is a left-mover, or the stack is empty, in which case it survives and is pushed.

Left-movers already on the stack are safe forever: everything still to come is to their right, and they're moving away from it.

```swift run
func survivors(_ asteroids: [Int]) -> [Int] {
    var stack: [Int] = []
    for asteroid in asteroids {
        var alive = true
        while alive, asteroid < 0, let top = stack.last, top > 0 {
            if top < -asteroid {
                stack.removeLast()          // the right-mover explodes; keep checking
            } else if top == -asteroid {
                stack.removeLast()          // both explode
                alive = false
            } else {
                alive = false               // the left-mover explodes
            }
        }
        if alive {
            stack.append(asteroid)
        }
    }
    return stack
}

for asteroids in [[5, 10, -5], [8, -8], [10, 2, -5], [-2, -1, 1, 2], [1, -2, -2, 3], [3, 4, -10, 6]] {
    print(asteroids, "->", survivors(asteroids))
}
```

```output
[5, 10, -5] -> [5, 10]
[8, -8] -> []
[10, 2, -5] -> [10]
[-2, -1, 1, 2] -> [-2, -1, 1, 2]
[1, -2, -2, 3] -> [-2, -2, 3]
[3, 4, -10, 6] -> [-10, 6]
```

What to notice:

- `[-2, -1, 1, 2]` has no collisions at all: the left-movers are on the left, flying away.
- In `[3, 4, -10, 6]`, the −10 destroys the 4, then the 3, then finds the stack empty and survives. The 6 comes after it, moving away.
- The `while` condition chains four checks with commas: still alive, moving left, a top exists, and the top moves right. All must hold to keep fighting.

**Why it's O(n).** The inner loop looks like it could make this O(n²), but every iteration that continues pops an asteroid, and each asteroid is pushed at most once, so it can be popped at most once. Over the whole run, the inner loop does at most n pops: O(n) total, the same amortised argument as in [Amortised analysis](/dsa/learn/bigo-amortised).

## Remove k digits

> Given a string of digits and a number k, remove exactly k digits so that the remaining digits, in their original order, form the smallest possible number. Drop leading zeros, and return `"0"` if nothing is left.

For `"1432219"` with k = 3, the answer is `"1219"`.

### The greedy insight

Numbers with the same number of digits are compared from the left: the leftmost digit matters most. So scan left to right, and whenever a digit is **bigger than the digit after it**, removing it lets a smaller digit move one place left, which is always an improvement. In `"1432219"`, the 4 is followed by a 3, so the 4 should go.

A stack makes this one pass. Keep the digits you've chosen so far. When a new digit arrives, pop every kept digit that's bigger than it, as long as you still have removals left, then push it. If removals are left at the end, the kept digits never decrease from left to right, so the biggest ones are at the end: remove from there.

```swift run
func smallest(_ digits: String, removing k: Int) -> String {
    var kept: [Character] = []
    var removalsLeft = k
    for digit in digits {
        while removalsLeft > 0, let last = kept.last, last > digit {
            kept.removeLast()                   // a smaller digit can move left: drop the bigger one
            removalsLeft -= 1
        }
        kept.append(digit)
    }
    kept.removeLast(min(removalsLeft, kept.count))   // still owe removals: take them from the end
    let trimmed = kept.drop { $0 == "0" }
    return trimmed.isEmpty ? "0" : String(trimmed)
}

for (digits, k) in [("1432219", 3), ("10200", 1), ("10", 2), ("12345", 2), ("4321", 2)] {
    print("\(digits) removing \(k) -> \(smallest(digits, removing: k))")
}
```

```output
1432219 removing 3 -> 1219
10200 removing 1 -> 200
10 removing 2 -> 0
12345 removing 2 -> 123
4321 removing 2 -> 21
```

Trace `"1432219"` with k = 3:

| digit | pops | kept after | removals left |
| --- | --- | --- | --- |
| 1 | | `1` | 3 |
| 4 | | `1 4` | 3 |
| 3 | 4 | `1 3` | 2 |
| 2 | 3 | `1 2` | 1 |
| 2 | | `1 2 2` | 1 |
| 1 | 2 | `1 2 1` | 0 |
| 9 | (no removals left) | `1 2 1 9` | 0 |

What to notice:

- **Characters compare like digits.** `"4" > "3"` is `true` for `Character`s, because the digits are in order in Unicode, so there's no need to convert to `Int`.
- **Leading zeros.** `"10200"` removing the 1 leaves `"0200"`, which is the number 200. `drop(while:)` skips the leading zeros.
- **Leftover removals.** `"12345"` never pops, because it's already increasing, so both removals come off the end.
- Each digit is pushed once and popped at most once: **O(n)** time and space.

## A first monotonic stack

Look at the kept digits in that trace: whenever a digit is pushed, everything below it is smaller or equal. The stack is always **non-decreasing** from bottom to top, apart from the moments when removals run out. A stack kept in sorted order by popping anything that would break the order is called a **monotonic stack**. Asteroid collision has a similar flavour: an arriving asteroid clears away everything it can beat before settling.

The next lesson makes the monotonic stack the main event, using it to find, for every element, the next element that's bigger, in O(n).

<Callout kind="gotcha" title="Common mistakes">
- **Asteroids: letting a left-mover fight a left-mover.** Only a right-mover on the stack and an arriving left-mover can collide. Check both signs.
- **Remove k digits: forgetting the leftover removals.** On an increasing string, nothing is popped, and without the final `removeLast` the answer keeps every digit.
- **Returning an empty string.** Removing every digit, or every digit but zeros, must give `"0"`.
</Callout>
