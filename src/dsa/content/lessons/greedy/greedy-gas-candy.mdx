## Why it matters

Two interview favourites with short answers and arguments that are easy to get wrong. The **gas station** problem asks where to start a round trip so you never run out of fuel; the trick is one line of reasoning about the worst point on the route, and it turns an O(n²) search into one pass. The **candy** problem hands out rewards to a line of children with ratings; the trick is to satisfy the left neighbours and the right neighbours in two separate passes. Both are greedy in the sense of this module: each makes a choice and never looks back.

## Gas station: the problem

Stations stand on a circular road, numbered 0 to n − 1. At station i you can fill up with `fuel[i]` litres, and driving on to the next station (station 0 after the last) uses `cost[i]` litres. Your tank starts empty and has no limit. Which station can you start from to drive all the way round and back? Return −1 if none works.

The brute force tries every start and drives round: n starts × n stations, O(n²). Two facts make it O(n).

## Fact 1: the total decides whether any start works

Each station's **gain** is `fuel[i] - cost[i]`: what driving through it adds to the tank. A full lap adds up every gain, whatever the start. If the total is negative, you'd finish with less than nothing, so no start works. The surprising part is the converse: if the total is at least 0, some start **always** works.

## Fact 2: start right after the worst moment

Pretend you start at station 0 and track the tank even when it goes negative, as if fuel could be borrowed. The running total after the first k stations is a prefix sum, as in [1D prefix sums and range queries](/dsa/learn/prefix-1d). Find where it's **lowest**: the worst moment of the trip. Start from the station right after that moment.

```swift run
let fuel = [4, 1, 2, 6, 1]
let cost = [3, 4, 3, 1, 3]

var tank = 0                       // starting at station 0, allowing a negative tank
var lowest = 0
var start = 0
for i in fuel.indices {
    tank += fuel[i] - cost[i]
    print("after station \(i): \(tank)")
    if tank < lowest {
        lowest = tank
        start = i + 1              // the worst moment so far is right before station i + 1
    }
}
print(tank >= 0 ? "start at \(start)" : "impossible")
```

```output
after station 0: 1
after station 1: -2
after station 2: -3
after station 3: 2
after station 4: 0
start at 3
```

The running total bottoms out at −3, right before station 3. Starting there, the tank holds 5, 3, 4, 1 and finally 0 litres after each station: never negative.

**Why it works.** Call the lowest running total L; it happens right before station s. Starting at s instead of 0, your tank after any later station is that station's running total minus L, which is at least 0 because L is the lowest. When you wrap past the last station, the tank holds the lap total minus L. Driving on through stations 0, 1, 2 and so on then adds exactly the running totals of the original trip, and each of those is at least L, so the tank never holds less than the lap total. With a lap total of at least 0, the tank never goes negative. That's the whole proof: **if the total is enough, start right after the worst prefix.**

## The one-pass greedy

Interview solutions usually phrase the same idea as resets. Drive from a candidate start; the moment the tank goes negative at station i, no start from the candidate up to i can work, so jump the candidate to i + 1 and empty the tank.

```swift run
func circuitStart(fuel: [Int], cost: [Int]) -> Int {
    var total = 0                  // the gain over a whole lap
    var tank = 0                   // fuel since the current candidate start
    var start = 0
    for i in fuel.indices {
        let gain = fuel[i] - cost[i]
        total += gain
        tank += gain
        if tank < 0 {              // can't reach station i + 1 from `start`
            print("  stuck after station \(i): try starting at \(i + 1)")
            start = i + 1
            tank = 0
        }
    }
    return total >= 0 ? start : -1
}

print(circuitStart(fuel: [4, 1, 2, 6, 1], cost: [3, 4, 3, 1, 3]))
print(circuitStart(fuel: [2, 2], cost: [3, 2]))
```

```output
  stuck after station 1: try starting at 2
  stuck after station 2: try starting at 3
3
  stuck after station 0: try starting at 1
-1
```

**Why skipping is safe.** Say you started at s and got stuck after station i. For any station k between s and i, you arrived at k from s with a tank of at least 0, and still got stuck at i. Starting at k with an **empty** tank can only be worse, so k can't be a start either. Each reset happens exactly when the running total hits a new low, so it lands on the same station as Fact 2. And when the total is at least 0, the last candidate is never past the end: a reset at the last station would mean the total is negative.

If several stations work, both versions return the smallest one, the first time the running total reaches its lowest value.

## Candy: the problem

Children stand in a line, each with a rating. Every child gets at least one sweet, and a child with a **higher** rating than a neighbour must get **more** sweets than that neighbour. What's the fewest sweets in total?

Each child has up to two constraints, one from each side, and they pull in different directions. Trying to satisfy both at once, child by child, leads to endless fix-ups. Instead, satisfy them **one side at a time**.

## Two passes

1. **Left to right:** `left[i]` is 1, or `left[i - 1] + 1` if child i is rated higher than the child on their left. Now every left-neighbour rule holds.
2. **Right to left:** `right[i]` is 1, or `right[i + 1] + 1` if child i is rated higher than the child on their right.
3. Each child gets `max(left[i], right[i])`.

```swift run
func fewestSweets(_ ratings: [Int]) -> Int {
    let n = ratings.count
    var left = Array(repeating: 1, count: n)
    for i in stride(from: 1, to: n, by: 1) where ratings[i] > ratings[i - 1] {
        left[i] = left[i - 1] + 1
    }
    var right = Array(repeating: 1, count: n)
    for i in stride(from: n - 2, through: 0, by: -1) where ratings[i] > ratings[i + 1] {
        right[i] = right[i + 1] + 1
    }
    let sweets = (0..<n).map { max(left[$0], right[$0]) }
    print("left  ", left)
    print("right ", right)
    print("sweets", sweets)
    return sweets.reduce(0, +)
}

print(fewestSweets([2, 4, 3, 2, 1, 3, 3]))
```

```output
left   [1, 2, 1, 1, 1, 2, 1]
right  [1, 4, 3, 2, 1, 1, 1]
sweets [1, 4, 3, 2, 1, 2, 1]
14
```

The child rated 4 looks like they need only 2 sweets after the first pass. But to their right, ratings fall 3, 2, 1, and that slope needs 3, 2 and 1 sweets, so the child rated 4 needs 4. The last two children are both rated 3: equal ratings impose nothing, so one gets 2 and the other 1.

### Why it's the fewest

`left[i]` counts the children in the run of rising ratings that ends at child i. Each child in that run needs at least one more sweet than the one before, so **every** valid handout gives child i at least `left[i]` sweets. The same goes for `right[i]` from the other side. So each child needs at least `max(left[i], right[i])`, and the two-pass answer gives each child exactly that. It's also valid: if child i is rated higher than the child on their left, then `left[i]` beats the left child's `left`, and the left child's `right` is 1, because they're not rated higher than child i. Every child gets the least they could possibly get, so the total is the least.

Both passes are O(n), with O(n) memory for the two arrays. (A cleverer one-pass version counts the lengths of rising and falling slopes in O(1) memory, but the two-pass version is the one to give first.)

<Callout kind="gotcha" title="Equal ratings, and stride directions">
- **Equal neighbours have no rule between them.** Giving them the same number of sweets "to be fair" wastes sweets: in `[1, 2, 2]`, the answer is 1 + 2 + 1 = 4, not 5.
- **`stride(from: n - 2, through: 0, by: -1)`** is the backwards loop. With `n == 1` it's empty, which is right. Writing `(0...n - 2).reversed()` instead crashes when `n == 1`, because `0...-1` is an invalid range.
</Callout>

## Practice

**Fuel stops on a ring road** is the gas station problem, with up to 100,000 stations. **Fair rewards in a line** is candy; the tests compare your answer with an exhaustive search on short lines.

```cards

  back: "Exactly when the total of fuel[i] − cost[i] over the lap is at least 0."
- id: gas-start
  front: "Which station should you start from?"
  back: "The one right after the lowest point of the running total (the worst prefix). Equivalently: reset the start to i + 1 whenever the tank goes negative after station i."
- id: candy-two-passes
  front: "How does the candy problem get the fewest sweets?"
  back: "One pass from the left for left-neighbour rules, one from the right for right-neighbour rules, then each child gets the larger of the two. Each is a lower bound, so the max is the minimum."
- id: candy-equal
  front: "In candy, what rule applies between two neighbours with equal ratings?"
  back: "None. Either may get fewer sweets than the other."
```
