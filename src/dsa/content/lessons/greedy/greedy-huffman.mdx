## Why it matters

Text stored one byte per character wastes space: in English, `e` turns up far more often than `z`, yet both take 8 bits. **Huffman coding** gives frequent symbols short codes and rare symbols long ones, and it's provably the best code of its kind. It's inside the DEFLATE format used by ZIP files, gzip and PNG images, and in JPEG. It's also the crowning greedy algorithm of this module: a heap, one simple rule (merge the two lightest trees) and an exchange argument that proves the rule can't be beaten.

## Fixed-length and variable-length codes

Take the text `abracadabra`: eleven characters, five distinct symbols. A **fixed-length code** gives every symbol the same number of bits. Five symbols need 3 bits each (2 bits only cover four), so the text takes 11 × 3 = 33 bits.

But `a` appears 5 times, while `c` and `d` appear once each. If `a` had a 1-bit code, even at the cost of longer codes for `c` and `d`, the total would drop. That's a **variable-length code**, and it raises a question fixed-length codes never have: where does one code end and the next begin?

## Prefix-free codes

Here's what goes wrong with a careless variable-length code:

```swift run
let careless: [Character: String] = ["a": "0", "b": "01", "c": "1"]
func encode(_ text: String) -> String {
    text.map { careless[$0]! }.joined()
}
print(encode("ac"), encode("b"))
```

```output
01 01
```

`"ac"` and `"b"` produce the same bits, so `01` can't be decoded. The problem is that `a`'s code, `0`, is the start (a **prefix**) of `b`'s code, `01`.

A code is **prefix-free** when no symbol's code is a prefix of another's. Then decoding is unambiguous: read bits until they spell a complete code, output that symbol, and start again. (They're often called "prefix codes", which is confusing, because the point is that there are no prefixes.)

Every prefix-free code is a **binary tree**. Put the symbols at the leaves; the path from the root spells each code, with 0 for left and 1 for right. A symbol at a leaf has no other symbol below it, so no code can be a prefix of another. Decoding walks down from the root, one bit per step, and outputs a symbol each time it reaches a leaf.

The **cost** of a tree is the total number of bits for the text: each symbol's frequency times its depth, added up. Huffman's algorithm finds the tree with the lowest cost.

## Huffman's algorithm

1. Make a one-node tree for each symbol, weighted by its frequency.
2. Take the **two lightest** trees out, and join them under a new root whose weight is their sum.
3. Repeat until one tree is left.

Rare symbols get merged early, so they sink deepest and get the longest codes. Frequent symbols join late, near the root. Step through it:

```visual huffman
frequencies:
  a: 5
  b: 2
  c: 1
  d: 1
  r: 2
```

"Take the two lightest" is exactly what a min-heap does, as in [Build a generic `Heap<T>`](/dsa/learn/heap-build). Here's the whole thing: count the symbols, build the tree with a heap, read off the codes, then encode and decode the text.

```swift run
// A small binary heap, as built in M39: insert and pop are O(log n)
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool
    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }
    var count: Int { items.count }
    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }
    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1, right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { return top }
            items.swapAt(parent, first)
            parent = first
        }
    }
}

final class HuffmanNode {
    let weight: Int
    let order: Int                     // creation order, to break ties the same way every run
    let symbol: Character?             // only leaves have a symbol
    let left: HuffmanNode?
    let right: HuffmanNode?
    init(weight: Int, order: Int, symbol: Character? = nil, left: HuffmanNode? = nil, right: HuffmanNode? = nil) {
        self.weight = weight
        self.order = order
        self.symbol = symbol
        self.left = left
        self.right = right
    }
}

func buildTree(_ text: String) -> HuffmanNode? {
    var counts: [Character: Int] = [:]
    for symbol in text {
        counts[symbol, default: 0] += 1
    }
    var heap = Heap<HuffmanNode>(areInIncreasingOrder: { ($0.weight, $0.order) < ($1.weight, $1.order) })
    var made = 0
    for symbol in counts.keys.sorted() {           // sorted, so the result doesn't depend on dictionary order
        heap.insert(HuffmanNode(weight: counts[symbol]!, order: made, symbol: symbol))
        made += 1
    }
    while heap.count > 1 {
        let lightest = heap.pop()!, next = heap.pop()!
        print("merge \(lightest.weight) and \(next.weight) into \(lightest.weight + next.weight)")
        heap.insert(HuffmanNode(weight: lightest.weight + next.weight, order: made, left: lightest, right: next))
        made += 1
    }
    return heap.pop()
}

// Read each code off the path from the root: left adds a 0, right adds a 1
func codes(_ root: HuffmanNode?) -> [Character: String] {
    var table: [Character: String] = [:]
    func walk(_ node: HuffmanNode?, _ path: String) {
        guard let node else { return }
        if let symbol = node.symbol {
            table[symbol] = path.isEmpty ? "0" : path       // a lone symbol still needs one bit
            return
        }
        walk(node.left, path + "0")
        walk(node.right, path + "1")
    }
    walk(root, "")
    return table
}

// Walk down from the root, one bit per step; at a leaf, output its symbol and start again
func decode(_ bits: String, _ root: HuffmanNode) -> String {
    if let symbol = root.symbol {                         // a one-symbol tree: every bit is that symbol
        return String(repeating: symbol, count: bits.count)
    }
    var result = ""
    var node = root
    for bit in bits {
        node = (bit == "0" ? node.left : node.right)!     // inner nodes always have two children
        if let symbol = node.symbol {
            result.append(symbol)
            node = root
        }
    }
    return result
}

let text = "abracadabra"
let root = buildTree(text)!
let table = codes(root)
for symbol in table.keys.sorted() {
    print(symbol, table[symbol]!)
}
let bits = text.map { table[$0]! }.joined()
print(bits.count, "bits instead of", text.count * 3)
print(bits)
print(decode(bits, root))
```

```output
merge 1 and 1 into 2
merge 2 and 2 into 4
merge 2 and 4 into 6
merge 5 and 6 into 11
a 0
b 110
c 100
d 101
r 111
23 bits instead of 33
01101110100010101101110
abracadabra
```

`a` gets a 1-bit code and everything else 3 bits: 5 × 1 + 6 × 3 = 23 bits, against 33 for the fixed-length code. Read the first bits back by hand: `0` is a leaf, `a`; then `110` is `b`; then `111` is `r`. No lookahead is ever needed.

With k distinct symbols, building the tree does k − 1 merges of O(log k) heap work each, so O(k log k), plus O(n) to count the n characters and to encode them. The tie-break on `order` doesn't change the cost; it makes the codes the same on every run, because a heap pops equal weights in no particular order, and the dictionary's order changes between runs.

## The cost is the sum of the merges

Look at the merges printed above: 2 + 4 + 6 + 11 = 23, the same as the total bits. That's no coincidence. Each merge adds one bit to the code of every symbol inside the two trees being joined, and those symbols' frequencies add up to exactly the merged weight. So:

**total bits = the sum of the weights of all the merged nodes.**

That gives a short way to compute the cost without building any tree, using a heap of plain numbers. It also gives a way to check Huffman by brute force. Every tree can be built by some sequence of merges (join any two siblings, and repeat), so trying **every** possible merge order finds the best tree there is:

```swift run
// Huffman's cost: repeatedly merge the two lightest weights and add up every merged weight
func huffmanCost(_ weights: [Int]) -> Int {
    var forest = weights
    var cost = 0
    while forest.count > 1 {
        forest.sort()                                  // fine for a handful; a heap in real code
        let merged = forest[0] + forest[1]
        forest.removeFirst(2)
        forest.append(merged)
        cost += merged
    }
    return cost
}

// Every tree can be built by some sequence of merges, so try them all
func cheapestOfAllMerges(_ weights: [Int]) -> Int {
    if weights.count <= 1 { return 0 }
    var best = Int.max
    for i in weights.indices {
        for j in weights.indices where j > i {
            var rest = weights
            let merged = rest[i] + rest[j]
            rest.remove(at: j)
            rest.remove(at: i)
            rest.append(merged)
            best = min(best, merged + cheapestOfAllMerges(rest))
        }
    }
    return best
}

for weights in [[5, 2, 2, 1, 1], [1, 1, 1, 1], [10, 1, 1, 1], [3, 4, 5, 6, 7, 8]] {
    print(weights, "Huffman", huffmanCost(weights), "best of all", cheapestOfAllMerges(weights))
}
```

```output
[5, 2, 2, 1, 1] Huffman 23 best of all 23
[1, 1, 1, 1] Huffman 8 best of all 8
[10, 1, 1, 1] Huffman 18 best of all 18
[3, 4, 5, 6, 7, 8] Huffman 84 best of all 84
```

Four equal weights give a balanced tree, 2 bits each, 8 in total, the same as a fixed-length code: Huffman never does worse than fixed-length, and with equal frequencies it does no better. With one dominant symbol, `[10, 1, 1, 1]`, it gives the 10 a 1-bit code. Brute force agreeing is evidence. Here's the proof.

## Why merging the two lightest is optimal

Write f(s) for a symbol's frequency and depth(s) for its depth in the tree, so the cost is the sum of f(s) × depth(s). The proof has the two parts every greedy proof needs, from [The greedy choice property](/dsa/learn/greedy-idea).

### The greedy choice: the two rarest symbols can be deepest siblings

Let x and y be the two least frequent symbols. **Claim:** some optimal tree has x and y as siblings at the deepest level.

First, in an optimal tree every inner node has two children. A node with one child could be removed, moving its whole subtree up a level and shortening codes. So the deepest leaf has a sibling, and that sibling is a leaf too (anything below it would be deeper). Call these deepest siblings a and b.

Now take an optimal tree and **swap x with a**. Only those two symbols move, so the cost changes by:

```text
after − before = f(x)·depth(a) + f(a)·depth(x) − f(x)·depth(x) − f(a)·depth(a)
               = (depth(a) − depth(x)) × (f(x) − f(a))
```

The first bracket is at least 0, because a is deepest. The second is at most 0, because x is a least frequent symbol. Their product is at most 0: the swap never increases the cost. Swap y with b in the same way. Now x and y are deepest siblings, and the tree is still optimal. That's an exchange argument, the same shape as in [Proving greedy](/dsa/learn/greedy-proofs): moving a rare symbol deeper and a common one shallower never hurts.

### Optimal substructure: merging leaves the same problem

Replace x and y with a single new symbol z, with f(z) = f(x) + f(y). Take any tree for this smaller alphabet and expand the leaf z into an inner node with children x and y. x and y sit one level deeper than z did, so:

```text
cost(expanded tree) = cost(smaller tree) + f(x) + f(y)
```

The extra f(x) + f(y) is the same whichever smaller tree you started from. So the best tree for the smaller alphabet expands into the best tree, among those where x and y are siblings. By the first part, that includes an optimal tree overall.

Huffman's first merge is exactly "make the two rarest symbols siblings". After it, the merged tree acts as a single symbol z, and the algorithm solves the smaller problem the same way. By induction, the final tree is optimal.

<Callout kind="analogy">
Think of each merge as paying a toll: every symbol inside the two trees pays one bit, so the toll is the merged weight. Huffman always pays the cheapest toll available, and the exchange argument shows that putting off a cheap toll can never make the later ones cheaper.
</Callout>

## Huffman in practice

- **The decoder needs the code.** A compressed file stores the tree, or the frequencies, alongside the bits. DEFLATE uses **canonical** Huffman codes, which can be rebuilt from the code lengths alone, so only the lengths are stored.
- **Ties give different trees with the same cost.** Weights 1, 1 and 2 can give the 2 a 1-bit code and the others 2 bits each, whichever two you merge first: always 6 bits. Tests should check the cost or the prefix-free property, not exact codes.
- **Optimal among codes of whole bits per symbol.** Huffman is the best code that gives each symbol its own fixed bit pattern. Methods such as arithmetic coding, which encode whole messages rather than single symbols, can do better, especially when one symbol is very common.

<Callout kind="gotcha" title="Edge cases that break Huffman code">
- **One distinct symbol.** The tree is a single leaf with an empty path. Give it a 1-bit code, `"0"`, or encoding produces no bits at all and decoding can't tell how many symbols there were.
- **An empty text.** No symbols, no tree: return 0 bits rather than force-unwrapping a heap that's empty.
- **Dictionary order.** Iterating `counts` directly gives a different order on each run, which changes tie-breaks and therefore the codes. Sort the symbols first if you print codes or need repeatable output.
</Callout>
