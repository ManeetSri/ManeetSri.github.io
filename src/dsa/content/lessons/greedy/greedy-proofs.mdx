## Why it matters

A greedy algorithm that's wrong usually looks exactly as convincing as one that's right. The only way to tell them apart is evidence: a brute force that agrees on thousands of small inputs, and then an argument that it can't fail. Interviewers ask "why does this work?" after nearly every greedy answer, and two proof templates cover almost every case you'll meet: the **exchange argument** and **greedy stays ahead**. This lesson works through both on activity selection, then uses an exchange argument on a new problem, handing out biscuits.

## The problem: activity selection

One stage, a list of talks, each a half-open interval `[start, end)`, and you want to run as many as possible with no two overlapping. You solved this in [Non-overlapping intervals and arrows](/dsa/learn/iv-non-overlapping), as "fewest removals": sort by end, and keep each talk that starts at or after the last kept end.

```swift run
func selectTalks(_ talks: [[Int]]) -> [[Int]] {
    var kept: [[Int]] = []
    var lastEnd = Int.min
    for talk in talks.sorted(by: { $0[1] < $1[1] }) where talk[0] >= lastEnd {
        kept.append(talk)
        lastEnd = talk[1]
    }
    return kept
}

let talks = [[2, 5], [1, 3], [4, 7], [6, 9], [3, 8], [8, 10], [9, 12], [7, 11], [11, 14]]
let greedy = selectTalks(talks)
let other = [[1, 3], [3, 8], [8, 10], [11, 14]]      // another valid choice of four talks
print(greedy)
for i in greedy.indices {
    print("talk \(i + 1): greedy ends at \(greedy[i][1]), the other at \(other[i][1])")
}
```

```output
[[1, 3], [4, 7], [8, 10], [11, 14]]
talk 1: greedy ends at 3, the other at 3
talk 2: greedy ends at 7, the other at 8
talk 3: greedy ends at 10, the other at 10
talk 4: greedy ends at 14, the other at 14
```

Look at the comparison. At every position, the greedy's talk ends **no later** than the other selection's talk. That pattern is the first proof.

## Template 1: greedy stays ahead

The idea: pick a measure of progress, and show by induction that after every step, the greedy is at least as far ahead as any other solution. Then show that being ahead at every step means being at least as good at the end.

For activity selection, the measure is "when does my i-th talk end?" Ending earlier is better: it leaves more of the day free.

Let the greedy's talks be g₁, g₂, …, gₖ and any valid selection's talks be o₁, o₂, …, oₘ, both listed in order of time.

**Claim:** for every i up to k, end(gᵢ) ≤ end(oᵢ).

1. **i = 1.** The greedy's first talk ends earliest of all the talks, so end(g₁) ≤ end(o₁).
2. **From i to i + 1.** Suppose end(gᵢ) ≤ end(oᵢ). The talk oᵢ₊₁ starts at or after oᵢ ends, so it also starts at or after gᵢ ends. That means oᵢ₊₁ was still allowed when the greedy chose its next talk. The greedy picks the allowed talk that ends first, so end(gᵢ₊₁) ≤ end(oᵢ₊₁).

**Conclusion:** suppose the other selection had more talks, m > k. Then oₖ₊₁ exists, and it starts at or after oₖ ends, which is at or after gₖ ends. So it was still allowed after the greedy's last pick, and the greedy only stops when nothing is allowed. But the greedy stopped at k. That's a contradiction, so m ≤ k: no selection beats the greedy.

The induction is the "stays ahead" part. The conclusion turns "ahead at every step" into "at least as many talks". You need both halves.

## Template 2: the exchange argument

The idea: take any optimal solution, find the first place where it differs from the greedy's, and **swap** its choice for the greedy's without making it worse or invalid. Repeat until the optimal solution has become the greedy's solution. So the greedy's solution is optimal too.

You saw this proof for activity selection in M33. In short:

1. Let e be the talk that ends first, and O any best selection. Let f be O's first talk.
2. end(e) ≤ end(f), because e ends first of all.
3. Replace f with e. Every other talk in O starts at or after f ends, so also at or after e ends. O is still valid and the same size.
4. So some best selection starts with e. Remove e and every talk that overlaps it, and the same argument applies to the rest.

Every exchange argument checks the same two things after the swap: the solution is **still valid**, and it's **no worse**. Forgetting the first check is the most common mistake.

### Watch the proof break on a wrong rule

Try the same exchange for "shortest talk first" and see exactly where it fails. Let s be the shortest talk, and O a best selection without it. To swap s in, you must take out every talk in O that overlaps s. But s can sit in the middle of the day and overlap **two** talks of O: with `[1, 5)`, `[4, 7)` and `[6, 10)`, the shortest is `[4, 7)`, and it overlaps both other talks. Swapping it for one of them leaves a clash with the other, so the swap is invalid, and taking out both makes O smaller. The proof can't be completed, and that's the counterexample: shortest-first keeps one talk where two fit.

Earliest end never has this problem: e ends first, so it can only overlap talks of O at the start of the day, and O, having no overlaps, contains at most one such talk. A proof that refuses to go through is often the quickest way to find the input that breaks a rule.

## Test before you prove

Proofs take effort, so first make sure there's something to prove. This harness compares three candidate rules with a brute force that tries every subset, on 500 random sets of up to 7 talks:

```swift run
// A tiny seeded random number generator, so the tests are the same on every run
struct Seeded {
    var state: UInt64
    mutating func next(_ range: ClosedRange<Int>) -> Int {
        state = state &* 6_364_136_223_846_793_005 &+ 1_442_695_040_888_963_407
        return range.lowerBound + Int((state >> 33) % UInt64(range.count))
    }
}

func overlap(_ a: [Int], _ b: [Int]) -> Bool {
    a[0] < b[1] && b[0] < a[1]                 // half-open: touching is fine
}

// The greedy: go through the intervals in the given order, keep each one that fits with all kept so far
func greedyCount(_ ordered: [[Int]]) -> Int {
    var kept: [[Int]] = []
    for interval in ordered where kept.allSatisfy({ !overlap($0, interval) }) {
        kept.append(interval)
    }
    return kept.count
}

// Try every subset and keep the largest with no overlapping pair
func bruteForce(_ intervals: [[Int]]) -> Int {
    var best = 0
    for mask in 0..<(1 << intervals.count) {
        let chosen = intervals.indices.filter { mask & (1 << $0) != 0 }.map { intervals[$0] }
        let fits = chosen.indices.allSatisfy { i in chosen.indices.allSatisfy { j in i == j || !overlap(chosen[i], chosen[j]) } }
        if fits { best = max(best, chosen.count) }
    }
    return best
}

func test(_ name: String, order: ([[Int]]) -> [[Int]]) {
    var random = Seeded(state: 50)
    for trial in 1...500 {
        let intervals = (0..<random.next(1...7)).map { _ -> [Int] in
            let start = random.next(0...9)
            return [start, start + random.next(1...5)]
        }
        let greedy = greedyCount(order(intervals))
        let best = bruteForce(intervals)
        if greedy != best {
            print("\(name): trial \(trial) fails on \(intervals): \(greedy) instead of \(best)")
            return
        }
    }
    print("\(name): agrees on all 500 inputs")
}

test("earliest end") { $0.sorted { $0[1] < $1[1] } }
test("earliest start") { $0.sorted { $0[0] < $1[0] } }
test("shortest first") { $0.sorted { $0[1] - $0[0] < $1[1] - $1[0] } }
```

```output
earliest end: agrees on all 500 inputs
earliest start: trial 19 fails on [[4, 5], [5, 6], [3, 7]]: 1 instead of 2
shortest first: trial 87 fails on [[7, 9], [3, 4], [0, 2], [5, 8], [4, 5], [8, 10], [3, 7]]: 4 instead of 5
```

Two wrong rules are caught with a concrete failing input each, which is far more useful than a vague feeling. "Shortest first" survived 86 trials before failing, which shows why a handful of hand-made examples isn't enough: the short `[7, 9]` blocks both `[5, 8]` and `[8, 10]`. The generator is **seeded**: the same seed always produces the same inputs, so a failure can be reproduced and debugged. The companion package's tests use the same trick.

## A new proof: handing out biscuits

Each child has a **greed**: the smallest biscuit that will make them happy. Each biscuit has a size, and each child gets at most one biscuit. How many children can you make happy?

The greedy: sort both lists. Walk through the biscuits from smallest to largest, and give each one to the least greedy child still waiting, if it's big enough. A biscuit too small for that child is too small for everyone left, so skip it.

```swift run
func happyChildren(greed: [Int], biscuits: [Int]) -> Int {
    let children = greed.sorted()
    var child = 0                                   // the least greedy child still waiting
    for size in biscuits.sorted() where child < children.count {
        if size >= children[child] {
            print("biscuit \(size) -> child with greed \(children[child])")
            child += 1
        } else {
            print("biscuit \(size) is too small for anyone left")
        }
    }
    return child
}

print(happyChildren(greed: [5, 2, 8, 3], biscuits: [4, 1, 3, 9, 2]))
```

```output
biscuit 1 is too small for anyone left
biscuit 2 -> child with greed 2
biscuit 3 -> child with greed 3
biscuit 4 is too small for anyone left
biscuit 9 -> child with greed 5
3
```

The child with greed 8 goes without: only the 9 could satisfy them, and it went to the child with greed 5. Is that a mistake? Both 5 and 8 need the 9, so only one of them can be happy either way. Here's the general proof.

### The exchange argument, in two swaps

Call the least greedy child c, and the smallest biscuit that satisfies c, b. (If no biscuit satisfies c, none satisfies anyone, and the answer is 0.) The greedy gives b to c. Take any optimal handout O.

**Swap 1: make c happy.** If O leaves c hungry, take any happy child d and their biscuit. d is at least as greedy as c, so that biscuit satisfies c too. Give it to c instead of d. Still valid, same count.

**Swap 2: give c the biscuit b.** Now c has some biscuit x in O. x satisfies c, and b is the smallest that does, so x ≥ b.

- If nobody has b, give c b instead of x. Valid, same count.
- If another child d has b, swap: c takes b, and d takes x. Is d still happy? x ≥ b, and b satisfied d, so yes.

Either way, there's an optimal handout in which c gets b, exactly as the greedy does. Remove c and b, and what's left is the same problem on fewer children and biscuits, so the same argument applies to the greedy's next step. By induction, the greedy makes as many children happy as possible.

<Callout kind="tip" title="Why smallest biscuit, not biggest?">
Giving c a bigger biscuit would also make c happy, but it wastes size that a greedier child might need. Swap 2 is exactly the check that the smallest sufficient biscuit never hurts anyone else.
</Callout>

## Writing your own proof

A checklist that works for most greedy problems:

1. **State the rule exactly**, including the sort order and how ties are broken.
2. **Choose a template.** If there's a natural measure of progress (how far you've reached, when your last choice ends), try *stays ahead*. If the answer is a set or sequence where you can swap one element, try an *exchange*.
3. **For an exchange**, check that the swapped solution is still valid and no worse.
4. **For stays ahead**, prove the step-by-step claim by induction, then prove the final step from "ahead" to "at least as good".
5. **Finish with induction**: the first choice is safe, and the rest is the same problem.

<Callout kind="gotcha" title="Proof mistakes to avoid">
- **Assuming the optimal answer is unique.** Write "some optimal answer", and transform it. There may be many.
- **Swapping into something invalid.** After an exchange, re-check every constraint, not only the one you were thinking about.
- **Proving one step only.** Showing the first choice is safe isn't enough. You also need optimal substructure, so the same argument applies to every later step.
</Callout>
