## Why it matters

Two scheduling classics. **Minimum platforms** asks how many platforms a station needs so that no train waits; it's the meeting-rooms sweep from M33, with one twist about what happens when a train arrives in the same minute another leaves. **Job sequencing** picks which one-hour jobs to accept, each with a deadline and a fee, to earn the most; its greedy choice is simple, and three different data structures can make it fast, including the union-find from M45. Both are the kind of scheduling logic behind calendar apps, CI build queues and print queues.

## Minimum platforms

Each train arrives at some minute and departs at a later minute, written as `HHMM` integers, so 9:05 is `905`. A train occupies a platform from its arrival **through** its departure minute: if one train arrives at 9:15 and another departs at 9:15, both are at the station in that minute and need two platforms. What's the fewest platforms?

As with [Meeting rooms I and II](/dsa/learn/iv-meeting-rooms), the answer is the **largest number of trains at the station at the same moment**. That many platforms are needed at that moment, and that many are always enough: give each arriving train any free platform. To find the peak, sort the arrivals and the departures separately and walk them with two pointers. The only difference from meeting rooms is the tie rule: here a departure in the **same minute** doesn't free the platform yet.

```swift run
// Trains occupy a platform from arrival to departure, both minutes included (times are HHMM)
func platformsNeeded(arrivals: [Int], departures: [Int], sameMinuteFrees: Bool) -> Int {
    let arrive = arrivals.sorted()
    let depart = departures.sorted()
    var inUse = 0
    var most = 0
    var d = 0                                          // the next departure to process
    for time in arrive {
        // A platform is free once its train has left: strictly before, if the minute is shared
        while d < depart.count && (depart[d] < time || (sameMinuteFrees && depart[d] == time)) {
            inUse -= 1
            d += 1
        }
        inUse += 1
        most = max(most, inUse)
    }
    return most
}

let arrivals = [905, 910, 915, 945, 1000, 1030]
let departures = [1000, 915, 930, 1010, 1005, 1100]
print("platforms:", platformsNeeded(arrivals: arrivals, departures: departures, sameMinuteFrees: false))
print("if a departure freed the platform for the same minute:", platformsNeeded(arrivals: arrivals, departures: departures, sameMinuteFrees: true))
```

```output
platforms: 3
if a departure freed the platform for the same minute: 2
```

At 9:15, the train from 9:10 is departing as the 9:15 train arrives, and the 9:05 train is still in, so three trains are at the station at once. At 10:00 it happens again: the 9:05 train leaves as another arrives, while the 9:45 train is still in. Treating the intervals as half-open, like meetings, would wrongly say two platforms are enough.

The pairing of arrivals with departures doesn't matter: a platform is a platform, so sorting the two lists separately is fine. In the events version from [Sweep-line events](/dsa/learn/iv-sweep-line), the same rule becomes "at equal times, process arrivals **before** departures", the opposite of meetings. It's O(n log n) for the sorts, then O(n).

<Callout kind="tip" title="Which tie rule?">
Ask what the problem says about touching intervals, then pick the tie rule to match. Half-open (a meeting ending at 10 frees the room for one starting at 10): release on `<=`, or sort ends first. Closed (a train departing at 9:15 still needs its platform in that minute): release on `<`, or sort starts first.
</Callout>

## Job sequencing with deadlines

A print shop can do one job per hour, starting at hour 1. Each job takes exactly one hour, has a **deadline** (it must be done in hour d or earlier) and a **profit**, earned only if it's done in time. Which jobs should the shop accept?

The greedy has two parts:

1. **Most profitable first.** Consider jobs in order of profit, highest first.
2. **As late as possible.** Put each job in the **latest** free hour at or before its deadline. If there's none, turn the job down.

```swift run
// Each job takes one time slot and pays only if it's done in a slot at or before its deadline
let jobs = [
    (name: "logo", deadline: 2, profit: 40),
    (name: "flyer", deadline: 1, profit: 25),
    (name: "banner", deadline: 3, profit: 30),
    (name: "menu", deadline: 1, profit: 35),
    (name: "poster", deadline: 3, profit: 10),
    (name: "card", deadline: 2, profit: 20),
]

let lastSlot = jobs.map(\.deadline).max() ?? 0
var slots: [String?] = Array(repeating: nil, count: lastSlot + 1)     // slots[1...lastSlot]; 0 is unused
var total = 0
for job in jobs.sorted(by: { $0.profit > $1.profit }) {             // most profitable first
    var slot = job.deadline
    while slot >= 1 && slots[slot] != nil {                          // the latest free slot by the deadline
        slot -= 1
    }
    if slot >= 1 {
        slots[slot] = job.name
        total += job.profit
        print("\(job.name) (\(job.profit)) -> slot \(slot)")
    } else {
        print("\(job.name) (\(job.profit)) -> no free slot by \(job.deadline)")
    }
}
print(slots.dropFirst().map { $0 ?? "-" }, total)
```

```output
logo (40) -> slot 2
menu (35) -> slot 1
banner (30) -> slot 3
flyer (25) -> no free slot by 1
card (20) -> no free slot by 2
poster (10) -> no free slot by 3
["menu", "logo", "banner"] 105
```

The logo goes into hour 2, its deadline, not hour 1. That's what leaves hour 1 free for the menu, which must be done by hour 1. Had the logo taken hour 1, the menu would have been lost.

### Why both parts are safe

**As late as possible:** an earlier hour can be used by every job that could use a later one, and also by jobs with tighter deadlines. So the latest free hour is the least valuable one to use up.

**Most profitable first** is an exchange argument. Take any best schedule that doesn't include the most profitable job, j. If an hour at or before j's deadline is free, add j: more profit. If all those hours are full, swap j in for whichever job holds one of them: j earns at least as much, and it meets its deadline. Either way, some best schedule includes j, and the rest is the same problem with one fewer hour available.

The scan for a free hour can walk back over many full hours, so this version is O(n × d) for deadlines up to d. Two faster ways to make the same choices follow.

## Faster: a union-find of free hours

Think of each full hour as **pointing at the hour before it**. Then "the latest free hour at or before d" is: start at d and follow the pointers until you reach an hour that points at itself. That's `find` in a union-find, from [Disjoint sets and the parent array](/dsa/learn/uf-idea), and path compression makes long walks short the next time. Hour 0 is a sentinel meaning "no free hour". Filling hour s is one line: `parent[s] = s - 1`.

```swift run
// The most profit from one-slot jobs with deadlines, using a union-find of free slots
func bestProfit(_ jobs: [(deadline: Int, profit: Int)]) -> Int {
    let n = jobs.count
    var parent = Array(0...n)              // a free slot points at itself; 0 means "no slot"
    // The latest free slot at or before `slot`, re-pointing the path at it as we go
    func latestFree(_ slot: Int) -> Int {
        var root = slot
        while parent[root] != root { root = parent[root] }
        var current = slot
        while parent[current] != root {
            let next = parent[current]
            parent[current] = root
            current = next
        }
        return root
    }
    var total = 0
    for job in jobs.sorted(by: { $0.profit > $1.profit }) {
        let slot = latestFree(min(job.deadline, n))    // n jobs never need more than n slots
        if slot > 0 {
            parent[slot] = slot - 1                    // taken: look one slot earlier next time
            total += job.profit
        }
        print("deadline \(job.deadline), profit \(job.profit): slot \(slot), parent \(parent)")
    }
    return total
}

print(bestProfit([(2, 40), (1, 25), (3, 30), (1, 35), (3, 10), (2, 20)]))
print(bestProfit([(1_000_000_000, 5), (1, 7), (1, 3)]))
```

```output
deadline 2, profit 40: slot 2, parent [0, 1, 1, 3, 4, 5, 6]
deadline 1, profit 35: slot 1, parent [0, 0, 1, 3, 4, 5, 6]
deadline 3, profit 30: slot 3, parent [0, 0, 1, 2, 4, 5, 6]
deadline 1, profit 25: slot 0, parent [0, 0, 1, 2, 4, 5, 6]
deadline 2, profit 20: slot 0, parent [0, 0, 0, 2, 4, 5, 6]
deadline 3, profit 10: slot 0, parent [0, 0, 0, 0, 4, 5, 6]
105
deadline 1, profit 7: slot 1, parent [0, 0, 2, 3]
deadline 1000000000, profit 5: slot 3, parent [0, 0, 2, 2]
deadline 1, profit 3: slot 0, parent [0, 0, 2, 2]
12
```

Watch the job with deadline 2 and profit 20: it walks 2 → 1 → 0, finds nothing, and path compression points hour 2 straight at 0, so the next search from hour 2 or 3 is short. Capping the deadline at n matters in the second example: with six jobs, you never need more than six hours, so a deadline of a billion becomes hour 3 here, and the array stays small. Sorting dominates: O(n log n).

## Another view: a heap of accepted jobs

There's a third way, which works through the deadlines instead of the profits. Sort the jobs by deadline. Accept each one, keeping the accepted profits in a min-heap. Whenever there are more accepted jobs than hours up to the current deadline, drop the **least profitable** one, which is on top of the heap.

```swift
import DSAKit

func bestProfitByDeadline(_ jobs: [(deadline: Int, profit: Int)]) -> Int {
    var accepted = Heap<Int>.minHeap()                 // the profits of the jobs kept so far
    for job in jobs.sorted(by: { $0.deadline < $1.deadline }) {
        accepted.insert(job.profit)
        if accepted.count > job.deadline {             // too many jobs to fit by this deadline
            accepted.pop()                             // give up the least profitable one
        }
    }
    var total = 0
    while let profit = accepted.pop() { total += profit }
    return total
}
```

It relies on a neat fact: a set of one-hour jobs can all be done in time exactly when, for every hour t, at most t of them have a deadline of t or earlier. Processing deadlines in order and trimming the heap keeps that true at every step, and always trimming the cheapest job keeps the profit as high as possible. It's the same pattern as [Task scheduler, reorganise string and IPO](/dsa/learn/heap-scheduling): a heap holding the best options so far. Also O(n log n), and deadlines can be any size.

<Callout kind="gotcha" title="Things to watch">
- **Hours start at 1.** A deadline of 1 means the first hour. Keeping index 0 unused (or as the "none" sentinel) avoids off-by-one errors.
- **Huge deadlines.** Never make an array as long as the largest deadline; cap it at the number of jobs.
- **The platform tie rule.** Closed intervals release on `<`, half-open ones on `<=`. Get it backwards and every test with a shared minute fails.
</Callout>
