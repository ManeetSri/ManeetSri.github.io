## Why it matters

Often you don't need everything in order, only **one position**: the median house price, the 95th-percentile response time on a performance dashboard, the 10th fastest lap. Sorting answers those in O(n log n), but it does far more than you asked. **Quickselect** finds the kth smallest value in **O(n)** on average, by partitioning like quick sort and then throwing half the work away. The same trick finds the **k smallest** (or largest) values as a group, the "top k" questions that interviews love: the k closest points, the k most recent orders, the k cheapest flights.

## From quick sort to quickselect

Recall what one partition does: the pivot lands at its **final** index p, with smaller values to its left and the rest to its right. Now say you want the value that would be at index k after sorting:

- If p == k, the pivot **is** the answer. Stop.
- If k < p, the answer is somewhere on the left. The right side is irrelevant: forget it.
- If k > p, the answer is on the right. Forget the left side.

Quick sort recurses into **both** sides. Quickselect continues into **one**, so it doesn't even need recursion: a loop that narrows `low...high` will do. Here it finds the median of ten values, with random pivots from the seeded generator used in the last lesson:

```swift run
struct Dice {
    private var state: UInt64
    init(seed: UInt64) { state = seed }
    mutating func roll(_ range: ClosedRange<Int>) -> Int {
        state = state &* 6364136223846793005 &+ 1442695040888963407
        return range.lowerBound + Int((state >> 33) % UInt64(range.count))
    }
}

var dice = Dice(seed: 11)

func partition(_ items: inout [Int], _ low: Int, _ high: Int) -> Int {
    items.swapAt(dice.roll(low...high), high)    // a random pivot, moved to the end
    let pivot = items[high]
    var boundary = low
    for j in low..<high where items[j] < pivot {
        items.swapAt(boundary, j)
        boundary += 1
    }
    items.swapAt(boundary, high)
    return boundary
}

/// The value that would be at index k (0-based) if numbers were sorted
func quickselect(_ numbers: [Int], _ k: Int) -> Int {
    var items = numbers
    var low = 0
    var high = items.count - 1
    while true {
        let p = partition(&items, low, high)
        print("range \(low)...\(high): pivot \(items[p]) lands at index \(p)")
        if p == k {
            return items[p]
        } else if k < p {
            high = p - 1                     // the answer is on the left: forget the right
        } else {
            low = p + 1                      // the answer is on the right: forget the left
        }
    }
}

let numbers = [42, 7, 19, 88, 3, 56, 23, 71, 12, 64]
print("median:", quickselect(numbers, numbers.count / 2))
print(numbers.sorted())
```

```output
range 0...9: pivot 23 lands at index 4
range 5...9: pivot 64 lands at index 7
range 5...6: pivot 42 lands at index 5
median: 42
[3, 7, 12, 19, 23, 42, 56, 64, 71, 88]
```

The same search, step by step, with the same seeded pivots. The shaded range is the part still in play:

```visual arrayTrace

input:
  items: [42, 7, 19, 88, 3, 56, 23, 71, 12, 64]
  k: 5

```

What to notice:

- The target is index 5. The first pivot lands at 4, too far left, so the search moves right. The second lands at 7, too far right. The third lands exactly on 5.
- After three partitions, most of the array is still unsorted, and that's fine. Only index 5 is guaranteed to hold its sorted value.
- With an even count, there are two middle values; `count / 2` picks the upper one. A statistician would average the two middles, which takes two selections (or one selection and a scan for the largest value on its left).

## Why it's O(n) on average

The first partition looks at all n elements. If the pivot lands near the middle, the next round looks at about n/2, then n/4, and so on:

n + n/2 + n/4 + n/8 + … < 2n

That's the geometric series from [Series sums and logarithms](/dsa/learn/math-series-logs), and it adds up to O(n). Random pivots don't land exactly in the middle, so the real constant is a bit bigger, but the shrinking is still geometric **on average**, and the expected total is still O(n). Count it:

```swift run
// Comparisons quickselect makes to find the median, against n log₂ n for sorting
struct Dice {
    private var state: UInt64
    init(seed: UInt64) { state = seed }
    mutating func roll(_ range: ClosedRange<Int>) -> Int {
        state = state &* 6364136223846793005 &+ 1442695040888963407
        return range.lowerBound + Int((state >> 33) % UInt64(range.count))
    }
}

var dice = Dice(seed: 1)
var comparisons = 0

func partition(_ items: inout [Int], _ low: Int, _ high: Int) -> Int {
    items.swapAt(dice.roll(low...high), high)
    let pivot = items[high]
    var boundary = low
    for j in low..<high {
        comparisons += 1
        if items[j] < pivot {
            items.swapAt(boundary, j)
            boundary += 1
        }
    }
    items.swapAt(boundary, high)
    return boundary
}

func quickselect(_ numbers: [Int], _ k: Int) -> Int {
    var items = numbers
    var low = 0
    var high = items.count - 1
    while true {
        let p = partition(&items, low, high)
        if p == k { return items[p] }
        if k < p { high = p - 1 } else { low = p + 1 }
    }
}

for n in [1_000, 10_000, 100_000] {
    let numbers = (0..<n).map { ($0 * 7_919) % n }
    comparisons = 0
    let median = quickselect(numbers, n / 2)
    var log2n = 0
    while (1 << log2n) < n { log2n += 1 }
    let tenths = comparisons * 10 / n
    print("n = \(n): median \(median), \(comparisons) comparisons (\(tenths / 10).\(tenths % 10) per element); n × ⌈log₂ n⌉ = \(n * log2n)")
}
```

```output
n = 1000: median 500, 2662 comparisons (2.6 per element); n × ⌈log₂ n⌉ = 10000
n = 10000: median 5000, 30169 comparisons (3.0 per element); n × ⌈log₂ n⌉ = 140000
n = 100000: median 50000, 184453 comparisons (1.8 per element); n × ⌈log₂ n⌉ = 1700000
```

The comparisons per element stay small and roughly constant as n grows a hundredfold; they vary with the luck of the pivots. A sort's n log₂ n keeps growing: at 100,000 elements, quickselect does about a tenth of the work.

### The worst case is still O(n²)

Quickselect inherits quick sort's weakness. With a fixed last-element pivot, ask for the smallest value of a sorted array, and every pivot is the largest of its range:

```swift run
// The worst case: a fixed last-element pivot, looking for the smallest value of sorted input
var comparisons = 0

func partition(_ items: inout [Int], _ low: Int, _ high: Int) -> Int {
    let pivot = items[high]
    var boundary = low
    for j in low..<high {
        comparisons += 1
        if items[j] < pivot {
            items.swapAt(boundary, j)
            boundary += 1
        }
    }
    items.swapAt(boundary, high)
    return boundary
}

func quickselect(_ numbers: [Int], _ k: Int) -> Int {
    var items = numbers
    var low = 0
    var high = items.count - 1
    while true {
        let p = partition(&items, low, high)
        if p == k { return items[p] }
        if k < p { high = p - 1 } else { low = p + 1 }
    }
}

let n = 2_000
print(quickselect(Array(0..<n), 0), comparisons)
```

```output
0 1999000
```

n(n − 1)/2 comparisons, each round removing a single element. The fixes are the ones from [Random pivots and 3-way partitioning](/dsa/learn/sort-quick-pivots): a random pivot makes this astronomically unlikely, and a **three-way** partition stops many duplicates from causing the same thing (with all values equal, two-way quickselect is quadratic whatever the pivot). For a worst-case guarantee, the next lesson has a pivot rule that's provably good.

## Three ways to find the kth smallest

| Approach | Time | Extra space | Notes |
| --- | --- | --- | --- |
| Sort, then index | O(n log n) | O(n) for `sorted()` | Simplest. Best if you'll ask many questions about the same data. |
| A heap of size k | O(n log k) | O(k) | Works on a stream, one value at a time. You'll build heaps in M39. |
| Quickselect | O(n) expected, O(n²) worst | O(1), or O(n) to work on a copy | Fastest for a single question. Rearranges the array. |
| Median of medians | O(n) worst | O(n) as usually written | Guaranteed, but slow in practice: [the next lesson](/dsa/learn/sort-median-of-medians). |

Interviewers often accept any of these, as long as you can explain the trade-offs. Mention quickselect's O(n²) worst case and how random pivots tame it: that's what they're listening for.

## Top k by partitioning

Quickselect leaves the array in a useful state. When the value for index k − 1 lands in place, every value **before** it is smaller or equal, and every value after it is larger or equal. So the first k elements **are** the k smallest, in no particular order. One selection answers "top k" in O(n) expected time:

```swift run
// The k smallest values, in no particular order: quickselect for index k - 1, then take the prefix
struct Dice {
    private var state: UInt64
    init(seed: UInt64) { state = seed }
    mutating func roll(_ range: ClosedRange<Int>) -> Int {
        state = state &* 6364136223846793005 &+ 1442695040888963407
        return range.lowerBound + Int((state >> 33) % UInt64(range.count))
    }
}

var dice = Dice(seed: 4)

func partition(_ items: inout [Int], _ low: Int, _ high: Int) -> Int {
    items.swapAt(dice.roll(low...high), high)
    let pivot = items[high]
    var boundary = low
    for j in low..<high where items[j] < pivot {
        items.swapAt(boundary, j)
        boundary += 1
    }
    items.swapAt(boundary, high)
    return boundary
}

/// Rearranges items so the value that belongs at index k is there, with smaller-or-equal values before it
func select(_ items: inout [Int], _ k: Int) {
    var low = 0
    var high = items.count - 1
    while low < high {
        let p = partition(&items, low, high)
        if p == k { return }
        if k < p { high = p - 1 } else { low = p + 1 }
    }
}

func smallest(_ k: Int, of numbers: [Int]) -> [Int] {
    guard k > 0 else { return [] }
    var items = numbers
    select(&items, k - 1)
    return Array(items[..<k])
}

let responseTimes = [120, 35, 410, 88, 52, 230, 61, 97, 300, 44]
let fastest = smallest(4, of: responseTimes)
print(fastest)
print(fastest.sorted())
```

```output
[35, 52, 44, 61]
[35, 44, 52, 61]
```

The four fastest responses come out unordered. If you need them in order, sort just those k afterwards: O(n + k log k) in total, still far better than sorting all n when k is small. For the k **largest**, select index n − k and take the suffix, or flip the comparison.

<Callout kind="gotcha" title="0-based or 1-based k?">
"The kth smallest" in a problem statement usually counts from **1**: the 1st smallest is the minimum. Array indexes count from **0**. So the 1st smallest is at index 0, and the kth smallest at index k − 1. The kth **largest** of n values is at index n − k. Decide which one your function means, write it in the doc comment, and test k = 1 and k = n. DSAKit's `kthSmallest(_:)` takes a 0-based index; the **Kth largest value** problem counts from 1.
</Callout>

<Callout kind="gotcha" title="Quickselect rearranges its input">
Partitioning swaps elements. If the caller's array must keep its order, work on a copy, as the examples here do. Swift makes that easy: `var items = numbers` copies (lazily, thanks to copy-on-write), and the caller's array never changes.
</Callout>

## DSAKit's kthSmallest

DSAKit's version partitions three ways around random pivots, works on a copy, and returns `nil` for an index that's out of range:

```swift
import DSAKit

let lapTimes = [31, 12, 47, 12, 25]
print(lapTimes.kthSmallest(0) ?? -1)              // 12: the fastest
print(lapTimes.kthSmallest(2) ?? -1)              // 25: the third fastest
print(lapTimes.kthSmallest(0, by: >) ?? -1)       // 47: the slowest
print(lapTimes.kthSmallest(5) ?? -1)              // -1: index 5 is out of range
```
