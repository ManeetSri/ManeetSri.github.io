## Why it matters

Cycles are often bugs. Swift Package Manager refuses to build packages that depend on each other in a loop. A spreadsheet warns you about a circular reference when a cell's formula ends up depending on itself. Two threads each waiting for a lock the other holds is a deadlock: a cycle in the "waits for" graph. In a network, a cable that closes a loop is redundant. Detecting a cycle is a traversal with one extra question at each edge, but the question is different for undirected and directed graphs, and mixing them up is one of the most common graph bugs. This lesson covers both, ending with the three-colour DFS that the next module builds on.

## Undirected graphs: don't count the way you came in

In an undirected graph, a traversal from a vertex builds a tree: each vertex is reached once, along one edge from its parent. Every edge that **isn't** one of those tree edges joins two vertices that are already connected through the tree, so it closes a cycle.

So during the search, when you look at a neighbour that's already visited, ask: is it the vertex I came from? Every edge is stored in both directions, so each vertex sees its parent among its neighbours, and that isn't a cycle: it's the same edge, travelled back. Any **other** visited neighbour means a cycle.

```swift run
/// Does this undirected graph contain a cycle? A visited neighbour that isn't your parent closes one.
func hasUndirectedCycle(_ vertexCount: Int, _ edges: [[Int]]) -> Bool {
    var neighbours = Array(repeating: [Int](), count: vertexCount)
    for edge in edges {
        neighbours[edge[0]].append(edge[1])
        neighbours[edge[1]].append(edge[0])
    }
    var parent = Array(repeating: -2, count: vertexCount)   // -2: not visited, -1: no parent
    for start in 0..<vertexCount where parent[start] == -2 {
        parent[start] = -1
        var stack = [start]
        while let vertex = stack.popLast() {
            for next in neighbours[vertex] {
                if parent[next] == -2 {
                    parent[next] = vertex               // a tree edge: next is new
                    stack.append(next)
                } else if next != parent[vertex] {
                    return true                         // visited, and not the way we came in
                }
            }
        }
    }
    return false
}

let tree = [[0, 1], [0, 2], [1, 3], [1, 4], [2, 5]]
print(hasUndirectedCycle(6, tree))
print(hasUndirectedCycle(6, tree + [[4, 5]]))
print(hasUndirectedCycle(2, [[0, 1]]))
print(hasUndirectedCycle(5, [[0, 1], [2, 3], [3, 4], [4, 2]]))
print(hasUndirectedCycle(3, [[0, 1], [2, 2]]))
```

```output
false
true
false
true
true
```

What to notice:

- **The parent array is the visited mark too**: -2 means unvisited, and -1 marks a start vertex, which has no parent.
- **A single edge is not a cycle.** Without the parent check, vertex 1 would see vertex 0 as a visited neighbour and report one.
- **Adding 4–5 to the tree closes the loop** 4–1–0–2–5–4. A tree plus any one edge always has exactly one cycle.
- **The outer loop checks every piece**: the cycle 2–3–4 is in the second piece.
- **A self-loop is a cycle**: vertex 2's neighbour is itself, which isn't its parent.

<Callout kind="note" title="Parallel edges">
If the same pair of vertices can be joined by two separate edges, that's a cycle of length 2, but "skip the parent" skips both edges. In those graphs, give each edge an id and skip only the **edge** you arrived along, not every edge to the parent.
</Callout>

### Two shortcuts for undirected graphs

**Count the edges.** A connected undirected graph with V vertices is a tree, so has no cycle, exactly when it has V − 1 edges. More generally, a graph with C pieces and no cycles has exactly V − C edges, so any more than that means a cycle. If you've already counted the pieces, as in [Connected components and flood fill](/dsa/learn/gt-components), you can answer "is there a cycle?" without another search.

**Union-find.** Add the edges one at a time, tracking which vertices are connected so far. An edge whose two ends are **already** connected closes a cycle, and that edge is the redundant one. This is how M45 solves "find the redundant connection", in [Provinces, redundant connection and valid tree](/dsa/learn/uf-provinces).

## Directed graphs: the parent check isn't enough

In a directed graph, reaching a vertex you've visited before doesn't mean there's a cycle. In the diamond 0 → 1, 0 → 2, 1 → 3, 2 → 3, a DFS from 0 visits 3 through 1, then reaches 3 again through 2. There's no way to get from 3 back to anything, so there's no cycle; there are just two routes to 3.

What does make a cycle is reaching a vertex that is **still being explored**: one on the current path from the DFS's starting point, whose call hasn't returned yet. Getting back to it means you can go round in a loop. DFS tracks this with **three colours**:

| Colour | Meaning |
| --- | --- |
| white | not visited yet |
| grey | entered, but not finished: it's on the current path |
| black | finished: it and everything reachable from it have been explored |

An edge to a **grey** vertex is a **back edge**, and it closes a cycle. An edge to a **black** vertex is harmless: everything beyond it has been explored and led nowhere back. Here's the naive "visited means cycle" check next to the three-colour version:

```swift run
// Directed edges: [a, b] means a → b
func outgoing(_ vertexCount: Int, _ edges: [[Int]]) -> [[Int]] {
    var result = Array(repeating: [Int](), count: vertexCount)
    for edge in edges {
        result[edge[0]].append(edge[1])
    }
    return result
}

/// WRONG for directed graphs: treats "reached something already visited" as a cycle
func naiveHasCycle(_ vertexCount: Int, _ edges: [[Int]]) -> Bool {
    let next = outgoing(vertexCount, edges)
    var visited = Array(repeating: false, count: vertexCount)
    func visit(_ vertex: Int) -> Bool {
        visited[vertex] = true
        for neighbour in next[vertex] {
            if visited[neighbour] || visit(neighbour) { return true }
        }
        return false
    }
    for start in 0..<vertexCount where !visited[start] {
        if visit(start) { return true }
    }
    return false
}

/// Three colours: 0 white (unvisited), 1 grey (on the current path), 2 black (finished)
func hasCycle(_ vertexCount: Int, _ edges: [[Int]]) -> Bool {
    let next = outgoing(vertexCount, edges)
    var colour = Array(repeating: 0, count: vertexCount)
    func visit(_ vertex: Int) -> Bool {
        colour[vertex] = 1                              // entering: now on the path
        for neighbour in next[vertex] {
            if colour[neighbour] == 1 { return true }   // back to the current path: a cycle
            if colour[neighbour] == 0 && visit(neighbour) { return true }
        }
        colour[vertex] = 2                              // finished: everything below it is explored
        return false
    }
    for start in 0..<vertexCount where colour[start] == 0 {
        if visit(start) { return true }
    }
    return false
}

let graphs: [(String, Int, [[Int]])] = [
    ("diamond", 4, [[0, 1], [0, 2], [1, 3], [2, 3]]),
    ("triangle", 3, [[0, 1], [1, 2], [2, 0]]),
    ("self-loop", 2, [[0, 1], [1, 1]]),
    ("two ways in", 3, [[0, 2], [1, 2]]),
]
for (name, count, edges) in graphs {
    print(name, "naive:", naiveHasCycle(count, edges), "colours:", hasCycle(count, edges))
}
```

```output
diamond naive: true colours: false
triangle naive: true colours: true
self-loop naive: true colours: true
two ways in naive: true colours: false
```

The naive check cries wolf on the diamond, and on "two ways in", where 0 → 2 and 1 → 2 share a target. In the second, the DFS from 0 has already finished 2 (it's black) by the time the DFS from 1 reaches it. Everything reachable from 2 was explored while 2 was grey, so if any of it led back to a vertex on a path through 2, the cycle would have been found then. Reaching a black vertex again only means a second route in.

Why not use the undirected parent check here? Because in a directed graph, a back edge to your parent **is** a cycle: 0 → 1 and 1 → 0 go round in a loop, and the parent check would skip it. Each kind of graph needs its own rule.

## Without recursion: frames that remember where they were

The recursive version is short, but a chain of 100,000 dependencies makes it 100,000 calls deep, which crashes inside a test, as [DFS, recursive and iterative](/dsa/learn/gt-dfs) explained. The simple stack DFS from that lesson won't do here, though: three colours need to know when a vertex **finishes**, and that version forgets a vertex as soon as it's popped.

The fix is to store what a recursive call keeps in its local variables. Each stack **frame** holds a vertex and the index of the next neighbour to try. Look at the top frame: if it has neighbours left, advance its index and "call" the next one by pushing a new frame; if it has none, the vertex is finished, so colour it black and pop it. The stack then holds exactly the grey vertices, in path order.

```swift run
/// Three-colour DFS without recursion. Each frame remembers which neighbour to try next.
/// Returns whether there's a cycle, and the order in which vertices finished.
func explore(_ vertexCount: Int, _ edges: [[Int]]) -> (cycle: Bool, finished: [Int]) {
    var next = Array(repeating: [Int](), count: vertexCount)
    for edge in edges {
        next[edge[0]].append(edge[1])
    }
    var colour = Array(repeating: 0, count: vertexCount)    // 0 white, 1 grey, 2 black
    var finished: [Int] = []
    for root in 0..<vertexCount where colour[root] == 0 {
        colour[root] = 1
        var stack = [(vertex: root, index: 0)]
        while let top = stack.last {
            if top.index == next[top.vertex].count {        // no neighbours left to try
                colour[top.vertex] = 2
                finished.append(top.vertex)
                stack.removeLast()
                continue
            }
            stack[stack.count - 1].index += 1               // next time, try the one after
            let neighbour = next[top.vertex][top.index]
            if colour[neighbour] == 1 { return (true, finished) }
            if colour[neighbour] == 0 {
                colour[neighbour] = 1
                stack.append((neighbour, 0))                // "call" visit(neighbour)
            }
        }
    }
    return (false, finished)
}

let dag = explore(5, [[0, 1], [0, 2], [1, 3], [2, 3], [3, 4]])
print(dag.cycle, "finished:", dag.finished, "reversed:", Array(dag.finished.reversed()))

let count = 100_000
let chain = (0..<(count - 1)).map { [$0, $0 + 1] }
print(explore(count, chain).cycle, explore(count, chain + [[count - 1, 0]]).cycle)
```

```output
false finished: [4, 3, 1, 2, 0] reversed: [0, 2, 1, 3, 4]
false true
```

What to notice:

- **`top` is a copy** of the last frame (tuples are values), so the index has to be advanced in the array itself: `stack[stack.count - 1].index += 1`.
- **The 100,000-vertex chain is no problem**: the frames live in an array on the heap. Closing it with one edge from the last vertex back to the first makes the whole chain one big cycle, found when the DFS reaches the end.
- **The stack is the grey path.** When a back edge to a grey vertex is found, the frames from that vertex to the top are the cycle itself, in order. That's how the practice problem reports the circular dependency, not just that one exists.
- **The finishing order is useful in its own right.** A vertex finishes only after everything it points to has finished, so in a graph without cycles, the **reversed** finishing order puts every vertex before everything it points to: `0, 2, 1, 3, 4` here. That's a topological order, the subject of [Topological sort with DFS](/dsa/learn/topo-dfs) in M43. [Kahn's algorithm](/dsa/learn/topo-kahn) finds the same kind of order with a queue, and detects cycles as a side effect.

<Callout kind="gotcha" title="Cycle-detection slips">
- **"Visited" means "cycle" in a directed graph.** It doesn't: two routes to the same vertex aren't a loop. Use three colours.
- **The undirected parent check on a directed graph** misses two-vertex loops like 0 → 1 → 0.
- **Forgetting to colour vertices black.** If finished vertices stay grey, any later edge to them looks like a back edge.
- **Starting the DFS only from vertex 0.** A cycle can be in a part of the graph that vertex 0 can't reach. Loop over every white vertex.
</Callout>
