## Why it matters

Copying a graph of objects comes up whenever objects point at each other: duplicating a document whose pages link to each other, taking an undo snapshot of a model with cross-references, copying a scene graph or a social network for a test. With classes, copying the references gives you two names for the **same** objects, so a change to the "copy" changes the original. A **deep copy** makes a new object for every original and rewires all the links between the new ones. Graphs make it tricky because links can loop back, and a careless copy either never finishes or copies the same object twice. "Clone a graph" is a favourite interview question because it tests exactly that, and the fix is a BFS with a dictionary.

## Shallow and deep copies

Here's the node class this lesson uses: a value, and an array of references to neighbouring nodes.

```swift
final class Node {
    let value: Int
    var neighbours: [Node] = []
    init(_ value: Int) { self.value = value }
}
```

Assigning a class instance, or copying an array of them, copies **references**, as [Value vs reference semantics](/dsa/learn/swift-value-vs-reference) explained. `let other = node` gives a second name for the same object, and `other === node` is `true`, using the identity check from [Identity with ===](/dsa/learn/swift-identity). That's a **shallow** copy.

A **deep** copy of a graph needs:

- one new node for every node reachable from the start, each with the same value;
- each new node's neighbours pointing at the **new** nodes, in the same order;
- no original node anywhere in the copy.

## Why the obvious recursion fails

The first idea is recursive: to copy a node, make a new node and set its neighbours to copies of the original's neighbours. Try it on two nodes A and B that point at each other. Copying A copies its neighbour B, which copies its neighbour A, which copies B, and so on, forever, until the stack overflows. Even without a cycle, a node reached by two different routes (a diamond) gets copied twice, and the copy is no longer the same shape.

Both problems have the same fix, and it's the one every graph traversal uses: **remember what you've already handled**. Keep a dictionary from each original node to its copy. Before copying a node, check the dictionary; if it's there, reuse that copy.

## The dictionary's key: ObjectIdentifier

What should the dictionary's key be? Not the value: two different nodes can hold the same value, and they must stay two different nodes in the copy. And `Node` itself can't be a key, because a class isn't `Hashable` unless you make it so.

The key is the node's **identity**. `ObjectIdentifier(node)` wraps a class instance's identity in a small `Hashable` value: two `ObjectIdentifier`s are equal exactly when they come from the same object, the same test as `===`. So the dictionary is `[ObjectIdentifier: Node]`, from an original's identity to its copy.

<Callout kind="tip" title="Or make the class Hashable by identity">
If you'll use nodes as keys often, you can conform once: implement `==` with `===`, and `hash(into:)` by combining `ObjectIdentifier(self)`, as in [Custom Hashable keys](/dsa/learn/hash-custom-keys). Then `[Node: Node]` and `Set<Node>` work directly. For one algorithm, `ObjectIdentifier` keys are simpler.
</Callout>

## Cloning with BFS

The BFS version has the same shape as every BFS in this module, with the dictionary as the visited mark:

1. Make the start's copy, record it, and enqueue the start.
2. Dequeue an original. For each of its neighbours: if the neighbour has no copy yet, make one, record it and enqueue the neighbour. Then append the neighbour's copy to this node's copy's neighbours.
3. When the queue is empty, return the start's copy.

```swift run
final class Node {
    let value: Int
    var neighbours: [Node] = []
    init(_ value: Int) { self.value = value }
}

func cloneGraph(_ start: Node?) -> Node? {
    guard let start else { return nil }
    var copies: [ObjectIdentifier: Node] = [ObjectIdentifier(start): Node(start.value)]
    var queue = [start]
    var head = 0
    while head < queue.count {
        let original = queue[head]
        head += 1
        let copy = copies[ObjectIdentifier(original)]!
        for neighbour in original.neighbours {
            let key = ObjectIdentifier(neighbour)
            if copies[key] == nil {
                copies[key] = Node(neighbour.value)     // first sight: make its copy, then visit it
                queue.append(neighbour)
            }
            copy.neighbours.append(copies[key]!)        // link to the copy, never the original
        }
    }
    return copies[ObjectIdentifier(start)]
}

/// Every node reachable from start, in BFS order
func allNodes(from start: Node) -> [Node] {
    var seen: Set<ObjectIdentifier> = [ObjectIdentifier(start)]
    var queue = [start]
    var head = 0
    while head < queue.count {
        for next in queue[head].neighbours where seen.insert(ObjectIdentifier(next)).inserted {
            queue.append(next)
        }
        head += 1
    }
    return queue
}

// A square 1 – 2 – 3 – 4 – 1, a second node labelled 2 hanging off 3, and a loop from 4 to itself
let nodes = [Node(1), Node(2), Node(3), Node(4), Node(2)]
func link(_ a: Int, _ b: Int) {
    nodes[a].neighbours.append(nodes[b])
    if a != b { nodes[b].neighbours.append(nodes[a]) }
}
link(0, 1); link(1, 2); link(2, 3); link(3, 0); link(2, 4); link(3, 3)

let copy = cloneGraph(nodes[0])!
for (original, twin) in zip(allNodes(from: nodes[0]), allNodes(from: copy)) {
    print(original.value, original.neighbours.map(\.value), "→ copy:", twin.value, twin.neighbours.map(\.value))
}
let originalIDs = Set(allNodes(from: nodes[0]).map { ObjectIdentifier($0) })
let copyIDs = Set(allNodes(from: copy).map { ObjectIdentifier($0) })
print("nodes in the copy:", copyIDs.count, "shared with the original:", originalIDs.intersection(copyIDs).count)
print("copy of 4 links to itself:", copy.neighbours[1].neighbours[2] === copy.neighbours[1])
```

```output
1 [2, 4] → copy: 1 [2, 4]
2 [1, 3] → copy: 2 [1, 3]
4 [3, 1, 4] → copy: 4 [3, 1, 4]
3 [2, 4, 2] → copy: 3 [2, 4, 2]
2 [3] → copy: 2 [3]
nodes in the copy: 5 shared with the original: 0
copy of 4 links to itself: true
```

What to notice:

- **The copy has the same shape**: walking both graphs in BFS order gives the same values and the same neighbour lists, in the same order.
- **The two nodes labelled 2 stay separate.** Keyed by value, they'd have merged into one, and the copy would have 4 nodes instead of 5.
- **The loop from 4 to itself is copied as a loop on the copy**, not a link back to the original. When 4 is dequeued, its own copy is already in the dictionary.
- **No node is shared** between the original and the copy: the sets of identities don't overlap.
- **Copy first, then enqueue.** Making the copy at first sight is this algorithm's "mark on enqueue". A neighbour already in the dictionary is never enqueued again, so each original is processed once: **O(V + E)** time, and O(V) for the dictionary and queue.

## The recursive version, and its limit

The recursive DFS version is shorter, and fine for small graphs. The important line is the one that records the copy **before** recursing into the neighbours. That's what stops a cycle from recursing forever: when the recursion comes back round to this node, it finds the copy already there.

```swift
func cloneRecursively(_ node: Node, _ copies: inout [ObjectIdentifier: Node]) -> Node {
    if let existing = copies[ObjectIdentifier(node)] { return existing }
    let copy = Node(node.value)
    copies[ObjectIdentifier(node)] = copy                // record it before following any neighbour
    for neighbour in node.neighbours {
        copy.neighbours.append(cloneRecursively(neighbour, &copies))
    }
    return copy
}
```

On a long chain of nodes, though, the recursion goes as deep as the chain is long, and inside a test that crashes after a few thousand calls, as you saw in [DFS, recursive and iterative](/dsa/learn/gt-dfs). For big graphs, use the BFS.

<Callout kind="gotcha" title="Cloning slips">
- **Linking to originals.** `copy.neighbours = original.neighbours` is a shallow copy of the array: the copy's neighbours are the original nodes. Always append the neighbour's **copy**.
- **Keying by value.** Values can repeat. Use `ObjectIdentifier`.
- **Recording the copy too late.** In the recursive version, record the copy before the loop over neighbours, or a cycle recurses forever.
- **Expecting unreachable nodes to be copied.** The clone only contains what the start can reach. In a directed graph, that can be a small part of it.
</Callout>

## Memory: graphs of classes leak

Two nodes that list each other as neighbours hold strong references to each other: a **retain cycle**, as in [Retain cycles](/dsa/learn/swift-retain-cycles). Neither is ever freed, even after every variable pointing at them is gone, and the same is true of the copy. In tests and small scripts that's harmless. In an app you'd break the cycles: keep every node in an array that owns them and make neighbour links `weak` or `unowned` (see [weak and unowned references](/dsa/learn/swift-weak-unowned)), or store neighbours as indices into that array instead of as references. Many graph algorithms use plain integer indices for exactly this reason.
