## Why it matters

Plenty of questions have many starting points. How long until mould spreading from several bad oranges reaches the whole crate? How far is every house from its nearest fire station? Which phone mast is closest to each point on a map? A game's enemies all chase the player, so how far is every tile from the player, or from the nearest of several goals? Running one BFS per source repeats the same work over and over. **Multi-source BFS** puts every source in the queue at distance 0 and runs **once**, in O(rows × columns) on a grid or O(V + E) on any graph. You met the idea in [A preview of BFS](/dsa/learn/queue-bfs-preview); this lesson explains why it's correct and works through the two classic problems.

## Why one search is enough

Imagine adding one extra vertex, a **super-source**, joined by an edge to every real source. A normal single-source BFS from it would:

1. dequeue the super-source and enqueue every real source, all at distance 1;
2. then carry on exactly as BFS does, reaching every other vertex from its nearest source.

Every distance it records is the true distance to the nearest source, plus 1 for the extra edge. So skip the imaginary vertex: start with all the real sources in the queue at distance 0, which is exactly the queue BFS would have after step 1, minus that 1. Everything you know about BFS carries over. The queue still holds one distance followed by the next, the first time a cell is reached is by a shortest route **from whichever source is nearest**, and each cell is enqueued once.

<Callout kind="analogy">
Drop several stones into a pond at the same moment. Their ripples spread at the same speed, and where two ripples meet, each point of water was reached first by the ripple from the nearest stone. Nobody has to measure the distance to every stone separately.
</Callout>

## Rotting oranges: counting minutes

A crate is a grid: 0 is an empty slot, 1 a fresh orange and 2 a rotten one. Every minute, each rotten orange rots the fresh oranges directly above, below, left and right of it. How many minutes until no fresh orange is left? If some fresh orange can never be reached, the answer is -1.

Every rotten orange is a source, and each minute is one BFS level. Process the queue a level at a time, as in [BFS and unweighted shortest paths](/dsa/learn/gt-bfs), and count the levels:

```swift run
// 0 is an empty slot, 1 a fresh orange, 2 a rotten one. Each minute, rot spreads up, down, left and right.
let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

func minutesUntilAllRotten(_ crate: [[Int]]) -> Int {
    var crate = crate
    var queue: [(Int, Int)] = []
    var fresh = 0
    for row in crate.indices {
        for column in crate[row].indices {
            if crate[row][column] == 2 {
                queue.append((row, column))             // every rotten orange is a source
            } else if crate[row][column] == 1 {
                fresh += 1
            }
        }
    }
    var head = 0
    var minutes = 0
    while head < queue.count && fresh > 0 {
        let levelEnd = queue.count                      // the oranges that rotted last minute
        while head < levelEnd {
            let (row, column) = queue[head]
            head += 1
            for (dr, dc) in directions {
                let r = row + dr
                let c = column + dc
                guard r >= 0, r < crate.count, c >= 0, c < crate[r].count, crate[r][c] == 1 else { continue }
                crate[r][c] = 2                         // rots now: marked as it's enqueued
                fresh -= 1
                queue.append((r, c))
            }
        }
        minutes += 1
    }
    return fresh == 0 ? minutes : -1
}

print(minutesUntilAllRotten([[2, 1, 1, 0], [0, 1, 1, 1], [0, 0, 1, 2]]))
print(minutesUntilAllRotten([[1, 1, 1, 1, 1, 1, 1], [2, 0, 0, 0, 0, 0, 2]]))
print(minutesUntilAllRotten([[2, 1, 0, 1]]))
print(minutesUntilAllRotten([[0, 2], [2, 0]]))
```

```output
2
4
-1
0
```

What to notice:

- **Two rot sources work together.** In the second crate, the bad oranges in the bottom corners rot the top row from both ends, meeting in the middle after 4 minutes. From one corner alone it would take 7.
- **`fresh` answers the -1 case cheaply.** Count the fresh oranges first and subtract as they rot. If any are left when the queue runs dry, some orange was walled off, like the last one in the third crate.
- **The loop stops as soon as `fresh` reaches 0.** Without `&& fresh > 0`, the last level would dequeue the final oranges, rot nothing new, and still add a minute: the classic off-by-one. The same condition makes a crate with no fresh oranges, the fourth one, take 0 minutes.
- **Changing 1 to 2 is the visited mark.** A rotten orange is never enqueued again.

This is exactly [Rumour spread](/dsa/practice/rumour-spread) from M27, with oranges instead of office workers.

## Distance to the nearest zero

The other classic: given a grid of 0s and 1s, find every cell's distance to its nearest 0. The 0s are the sources. Here it's next to the slow alternative, a separate BFS from every 1 that stops at the first 0, counting how many cells each approach takes out of a queue:

```swift run
let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

// Every cell's distance to the nearest 0: all the 0s start in the queue at distance 0
func nearestZero(_ grid: [[Int]]) -> (distance: [[Int]], dequeued: Int) {
    var distance = grid.map { row in row.map { $0 == 0 ? 0 : -1 } }
    var queue: [(Int, Int)] = []
    for row in grid.indices {
        for column in grid[row].indices where grid[row][column] == 0 {
            queue.append((row, column))
        }
    }
    var head = 0
    while head < queue.count {
        let (row, column) = queue[head]
        head += 1
        for (dr, dc) in directions {
            let r = row + dr
            let c = column + dc
            guard r >= 0, r < grid.count, c >= 0, c < grid[r].count, distance[r][c] == -1 else { continue }
            distance[r][c] = distance[row][column] + 1
            queue.append((r, c))
        }
    }
    return (distance, head)
}

// The slow way, for comparison: a separate BFS from every 1, stopping at the first 0 it reaches
func dequeuedOneAtATime(_ grid: [[Int]]) -> Int {
    var total = 0
    for row in grid.indices {
        for column in grid[row].indices where grid[row][column] == 1 {
            var seen = grid.map { $0.map { _ in false } }
            seen[row][column] = true
            var queue = [(row, column)]
            var head = 0
            while head < queue.count {
                let (r, c) = queue[head]
                head += 1
                total += 1
                if grid[r][c] == 0 { break }
                for (dr, dc) in directions {
                    let nr = r + dr
                    let nc = c + dc
                    guard nr >= 0, nr < grid.count, nc >= 0, nc < grid[nr].count, !seen[nr][nc] else { continue }
                    seen[nr][nc] = true
                    queue.append((nr, nc))
                }
            }
        }
    }
    return total
}

let small = [
    [1, 1, 1, 1, 1],
    [1, 0, 1, 1, 1],
    [1, 1, 1, 1, 0],
    [1, 1, 1, 1, 1],
]
for row in nearestZero(small).distance {
    print(row)
}

var big = Array(repeating: Array(repeating: 1, count: 30), count: 30)
big[0][0] = 0
print("30 × 30, one zero: multi-source dequeues \(nearestZero(big).dequeued), one BFS per cell dequeues \(dequeuedOneAtATime(big))")
```

```output
[2, 1, 2, 3, 2]
[1, 0, 1, 2, 1]
[2, 1, 2, 1, 0]
[3, 2, 3, 2, 1]
30 × 30, one zero: multi-source dequeues 900, one BFS per cell dequeues 587729
```

The two zeros' ripples meet down the middle of the small grid: the cell at row 0, column 3 is 3 steps from the left-hand zero and only 2 from the right-hand one, and it gets 2. On the 30 × 30 grid, multi-source BFS dequeues each of the 900 cells once. The per-cell version dequeues more than half a million, and the gap grows with the square of the grid's size: on 1000 × 1000 it would be around 10¹² steps.

The distance grid starts at -1 for every 1, so it's the visited mark too, and a grid with no 0 at all simply keeps every cell at -1.

## More from the same pattern

| Question | Sources | What you read off |
| --- | --- | --- |
| Minutes until everything is reached | everything reached at minute 0 | the number of levels |
| Each cell's distance to the nearest X | every X | each cell's distance |
| The cell farthest from every X | every X | the largest distance |
| Which X is nearest to each cell | every X, each carrying its own label | the label a cell inherits from whoever reached it first |
| Rooms' distances to the nearest exit, with walls | every exit | each room's distance, with walls never enqueued |

The last two need one small change each. To know **which** source is nearest, store the source's label alongside each queued cell, and copy it into every cell that source's ripple reaches first. Walls are simply never enqueued, exactly as in a maze BFS.

<Callout kind="gotcha" title="Multi-source slips">
- **One BFS per source.** It gives the right answer, slowly: k sources cost k searches. Put them all in the queue first.
- **Adding sources as you go.** Every source must be in the queue before the first dequeue. Adding one later lets cells near it be reached late, from a farther source, with the wrong distance.
- **Counting one minute too many.** Stop once nothing is left to reach, or only count a level that actually reached something new.
- **Forgetting the impossible case.** Count what still needs reaching, and return -1 (or whatever the problem asks) if it isn't zero at the end.
</Callout>

**Steps to the nearest zero** is the second example, on grids up to 1000 × 1000, where only the multi-source version is fast enough.

```cards
  back: "Put every source in the queue at distance 0 before the search starts, then run BFS once. Each cell is first reached from its nearest source."
- id: multi-source-why
  front: "Why is multi-source BFS correct?"
  back: "It's single-source BFS from an imaginary super-source joined to every real source, with the first level skipped and every distance 1 smaller."
- id: rotting-minutes
  front: "In the rotting oranges problem, how do you avoid counting one minute too many?"
  back: "Process the queue level by level and stop as soon as no fresh oranges are left, so a final level that rots nothing isn't counted."
- id: multi-source-cost
  front: "What does multi-source BFS cost on a grid of n cells, however many sources there are?"
  back: "O(n): each cell is enqueued once. One BFS per source would cost O(k × n) for k sources, or worse."
```
