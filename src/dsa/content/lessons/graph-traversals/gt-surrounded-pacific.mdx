## Why it matters

Some questions are slow to answer forwards and quick to answer backwards. "Is this region completely surrounded?" means exploring every region and checking whether any of its cells touches the edge; "which cells are **not** surrounded?" is one search that starts from the edge. "Can rain on this square reach the sea?" means a separate search from every square; "which squares drain into the sea?" is one search that starts at the sea and climbs. This **reverse thinking** turns fiddly O(n²) solutions into short linear ones. It's how a Go program finds captured stones, how an image editor fills the holes inside a shape, and the key to two classic interview problems: surrounded regions and Pacific Atlantic water flow.

## Surrounded regions: start from the border

A board is a grid of `"X"` and `"O"`. A region of `"O"`s is **captured**, turned into `"X"`s, when it's walled in on every side: none of its cells is on the edge of the board.

The forward approach explores each region, remembers its cells, notes whether any of them is on the border, then decides. It works, but it needs a list of cells for every region and careful bookkeeping. Turn the question round: which `"O"`s **survive**? Exactly the ones connected to an `"O"` on the border. So:

1. Mark every `"O"` on the border as safe (here with `"S"`), and push them all onto one stack.
2. Search from them, marking every `"O"` you reach as safe.
3. Sweep the board. An `"O"` that's still unmarked is enclosed, so it becomes `"X"`; every `"S"` becomes `"O"` again.

```swift run
let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

func capture(_ board: [[Character]]) -> [[Character]] {
    var board = board
    let rows = board.count
    let columns = board[0].count
    // 1. Every "O" on the border is safe: mark it "S" and start the search from it
    var stack: [(Int, Int)] = []
    for row in 0..<rows {
        for column in 0..<columns where row == 0 || row == rows - 1 || column == 0 || column == columns - 1 {
            if board[row][column] == "O" {
                board[row][column] = "S"
                stack.append((row, column))
            }
        }
    }
    // 2. Anything connected to a safe "O" is safe too
    while let cell = stack.popLast() {
        for (dr, dc) in directions {
            let r = cell.0 + dr
            let c = cell.1 + dc
            guard r >= 0, r < rows, c >= 0, c < columns, board[r][c] == "O" else { continue }
            board[r][c] = "S"
            stack.append((r, c))
        }
    }
    // 3. Unmarked "O"s are enclosed: capture them, and restore the safe ones
    for row in 0..<rows {
        for column in 0..<columns {
            board[row][column] = board[row][column] == "S" ? "O" : "X"
        }
    }
    return board
}

let board = [
    "XXXXXX",
    "XOOXOX",
    "XXOXOX",
    "XOXXOO",
    "XOOXXX",
    "XXXXOX",
].map { Array($0) }

for (before, after) in zip(board, capture(board)) {
    print(String(before), " → ", String(after))
}
```

```output
XXXXXX  →  XXXXXX
XOOXOX  →  XXXXOX
XXOXOX  →  XXXXOX
XOXXOO  →  XXXXOO
XOOXXX  →  XXXXXX
XXXXOX  →  XXXXOX
```

The region down the right-hand side survives because it reaches the edge at the end of row 3. The single `"O"` at the bottom is on the edge itself. The two regions on the left are walled in, so they're captured.

What to notice:

- **All the border cells start together**, in one stack. That's a **multi-source** search: instead of one starting vertex, there are many, and the search spreads from all of them at once. The next lesson does the same with BFS to measure distances.
- **The order of the search doesn't matter**, because it only marks cells. DFS with a stack, as here, and BFS with a queue give the same board.
- **Every cell is visited a constant number of times**: once in the border loop or the search, once in the sweep. The whole thing is O(rows × columns), however many regions there are.
- **A third value, `"S"`, is the visited mark.** Safe cells are no longer `"O"`, so they're never pushed twice, and the sweep tells them apart from enclosed ones.

<Callout kind="analogy">
To find which rooms in a burning building people can escape from, you don't walk from every room looking for an exit. You stand at the exits and walk inwards: every room you can reach can reach you.
</Callout>

## Pacific Atlantic: climb from the sea

A map gives the height of every square on an island. The **Pacific** lies beyond the top and left edges, and the **Atlantic** beyond the bottom and right edges. Rain flows from a square to any neighbour (up, down, left or right) that is **no higher**, and from an edge square straight into the ocean beside it. Which squares can send rain to **both** oceans?

Forwards, you'd start a downhill search from every square and see which edges it reaches. Each search can cover most of the map, so that's O((rows × columns)²).

Backwards: rain can get from square A to the Pacific exactly when you can walk from a Pacific edge square to A, stepping only to neighbours that are **at least as high**. Climbing against the flow retraces the rain's route in reverse. So run one climbing search from all the Pacific edge squares together, and one from all the Atlantic edge squares. Each marks every square that drains into its ocean, and the answer is the squares both searches marked:

```swift run
let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]
let heights = [
    [3, 3, 4, 5, 6],
    [2, 1, 4, 3, 5],
    [4, 7, 8, 2, 4],
    [6, 5, 3, 1, 2],
]
let rows = heights.count
let columns = heights[0].count

/// Every cell whose water can reach the given edge cells, found by climbing from them
func reaches(from edge: [(Int, Int)]) -> [[Bool]] {
    var reached = Array(repeating: Array(repeating: false, count: columns), count: rows)
    var stack: [(Int, Int)] = []
    for (row, column) in edge where !reached[row][column] {
        reached[row][column] = true
        stack.append((row, column))
    }
    while let cell = stack.popLast() {
        for (dr, dc) in directions {
            let r = cell.0 + dr
            let c = cell.1 + dc
            guard r >= 0, r < rows, c >= 0, c < columns, !reached[r][c] else { continue }
            guard heights[r][c] >= heights[cell.0][cell.1] else { continue }   // climb: uphill or level
            reached[r][c] = true
            stack.append((r, c))
        }
    }
    return reached
}

let pacific = reaches(from: (0..<rows).map { ($0, 0) } + (0..<columns).map { (0, $0) })      // left and top
let atlantic = reaches(from: (0..<rows).map { ($0, columns - 1) } + (0..<columns).map { (rows - 1, $0) })  // right and bottom

var both: [[Int]] = []
for row in 0..<rows {
    var marks: [String] = []
    for column in 0..<columns {
        switch (pacific[row][column], atlantic[row][column]) {
        case (true, true):
            marks.append("B")
            both.append([row, column])
        case (true, false): marks.append("P")
        case (false, true): marks.append("A")
        case (false, false): marks.append(".")
        }
    }
    print(marks.joined(separator: " "))
}
print("both:", both)
```

```output
P P B B B
P . B A A
P B B A A
B A A A A
both: [[0, 2], [0, 3], [0, 4], [1, 2], [2, 1], [2, 2], [3, 0]]
```

Read the map: `P` drains only to the Pacific, `A` only to the Atlantic, `B` to both, and `.` to neither. Some squares worth checking by hand:

- **The 8 in the middle** is the highest point, so rain runs off it in every direction: up through 4 and 4 to the top edge (Pacific), and right to 2, then down to 1 on the bottom edge (Atlantic). `B`.
- **The 1 at row 1, column 1** is a pit: every neighbour is higher, so its rain goes nowhere. Neither search can climb **into** it, because from each neighbour the step down to 1 isn't a climb. `.`.
- **The bottom-left corner** is on the left edge and the bottom edge, so it touches both oceans directly. Corners like it are pushed by both searches, which is why the loops skip squares already marked.

<Callout kind="gotcha" title="The comparison flips when you reverse">
Rain flows from high to low, to a neighbour that is `<=` the current square. Climbing against the flow moves to a neighbour that is `>=` the current square. Writing `>` instead of `>=` forgets that rain crosses flat ground, and writing `<=` runs the search downhill from the sea, which answers a different question entirely.
</Callout>

## When to think in reverse

Look for these signs:

- **The question is about reaching a boundary or a target set** ("can it escape", "does it reach the edge", "which cells drain to X"). Start from the boundary or the target instead.
- **The forward search would run once per cell**, but the backward search can run once from all the targets together.
- **Every move can be reversed**, or you can say what the reverse move is (here, "flows down to" became "climbs up to").

The search itself is always a plain multi-source traversal, so its cost is linear in the size of the grid. You'll use the same trick in the next lesson to find each cell's distance to the nearest of many sources, and again in M43, where Kahn's algorithm starts from the tasks that depend on nothing.
