## Why it matters

Some of the best BFS problems never mention a graph. "What's the fewest number of turns to open this lock?" "Turn COLD into WARM one letter at a time." "Solve this sliding puzzle in the fewest moves." "How few knight moves from here to there?" In each, the vertices are **states** (a lock combination, a word, a board position), the edges are **moves**, and the question is a shortest path. The graph is never built. You generate each state's neighbours when you need them, as [Implicit graphs: grids and state spaces](/dsa/learn/graph-implicit) described, and BFS does the rest. Recognising a state space is the hard part; once you have, the code is the BFS you already know.

## The recipe

Every state-space search needs four decisions:

| Decision | Lock | Word ladder |
| --- | --- | --- |
| What is a state? | a 4-digit combination | a word |
| How is it stored? | an `Int` from 0 to 9,999 | a `String` |
| Which moves are allowed? | turn one wheel up or down by one | change one letter to make a listed word |
| What's off limits? | the jammed combinations | words not in the list |

Then BFS from the start state, marking states as seen when they're enqueued, until the target comes out of the queue (or the queue empties: no solution). The first time BFS reaches a state, it has used the fewest moves, for the same reason as in [BFS and unweighted shortest paths](/dsa/learn/gt-bfs).

How a state is **stored** matters. It needs to be `Hashable` to go in a `Set` or dictionary, and the smaller and simpler it is, the faster each lookup. When the states can be numbered, as lock combinations can, an array indexed by the number beats a `Set` entirely.

## Open the lock

A lock has four wheels, each showing a digit, and starts at `0000`. One move turns one wheel up or down by one, and the digits wrap: up from 9 is 0, down from 0 is 9. Some combinations jam the lock, so you must never pass through them. What's the fewest number of moves to reach the target?

A combination is a number from 0 to 9,999, and each wheel is a place value: units, tens, hundreds or thousands. Turning a wheel changes one digit, which changes the number by a multiple of that place value:

```swift run
// A lock with four wheels of digits, starting at 0000. A move turns one wheel up or down by one.
/// The combination as four digits, with leading zeros
func code(_ state: Int) -> String {
    let digits = String(state)
    return String(repeating: "0", count: 4 - digits.count) + digits
}

/// The 8 combinations one move away. Each wheel is a place value: 1, 10, 100 or 1,000.
func neighbours(of state: Int) -> [Int] {
    var result: [Int] = []
    var place = 1
    for _ in 0..<4 {
        let digit = (state / place) % 10
        for change in [1, 9] {                          // up one, or down one (adding 9 wraps 0 to 9)
            let turned = (digit + change) % 10
            result.append(state + (turned - digit) * place)
        }
        place *= 10
    }
    return result
}

func fewestTurns(to target: String, blocked: [String]) -> Int {
    var forbidden = Array(repeating: false, count: 10_000)
    for combination in blocked {
        forbidden[Int(combination)!] = true
    }
    if forbidden[0] { return -1 }                       // stuck before the first move
    var turns = Array(repeating: -1, count: 10_000)     // -1: not seen yet
    turns[0] = 0
    var queue = [0]
    var head = 0
    let goal = Int(target)!
    while head < queue.count {
        let state = queue[head]
        head += 1
        if state == goal { return turns[state] }
        for next in neighbours(of: state) where turns[next] == -1 && !forbidden[next] {
            turns[next] = turns[state] + 1
            queue.append(next)
        }
    }
    return -1
}

print(neighbours(of: 0).map(code))
print(fewestTurns(to: "1234", blocked: []))
print(fewestTurns(to: "9999", blocked: []))
print(fewestTurns(to: "1111", blocked: ["1000", "0100", "0010", "0001"]))
print(fewestTurns(to: "5555", blocked: ["4555", "6555", "5455", "5655", "5545", "5565", "5554", "5556"]))
print(fewestTurns(to: "0000", blocked: []))
```

```output
["0001", "0009", "0010", "0090", "0100", "0900", "1000", "9000"]
10
4
6
-1
0
```

What to notice:

- **Wrapping without negatives.** Turning down is written as adding 9 and taking `% 10`, so 0 goes to 9 instead of to -1, the same trick as turning left in [Direction arrays for grid moves](/dsa/learn/matrix-directions).
- **9999 is only 4 moves away**, because each wheel turns down once from 0 to 9. A search that only turned wheels upwards would say 36.
- **The blocked combinations force detours.** With every "turn one wheel up" combination jammed, `1111` takes 6 moves: down to `9000`, up on the other three wheels, then two more turns to bring the first wheel from 9 round to 1.
- **`5555` is unreachable** when all eight of its neighbours are jammed. BFS explores every combination it can reach, finds nothing, and returns -1.
- **There are only 10,000 states**, each with 8 moves, so the whole search is at most 80,000 steps. Arrays indexed by the combination replace both the visited set and the distance dictionary.

## Word ladder

Turn one word into another by changing one letter at a time, with every word along the way in a given list. Each word is a state, and two words are neighbours when they differ in exactly one position.

Finding a word's neighbours is the interesting part. Comparing it with every word in the list costs O(n) per word, so O(n²) for the whole search: too slow for tens of thousands of words. Two faster ways:

- **Try every letter.** For each of the L positions, try all 26 letters and look the result up in a `Set` of the words: 26 × L lookups per word, however long the list is.
- **Group by pattern.** Before searching, file each word under its L **wildcard patterns**: "cold" goes under `*old`, `c*ld`, `co*d` and `col*`. Words that share a pattern differ only at its `*`, so a word's neighbours are exactly the other words in its buckets.

Here's the pattern version, with parents recorded so the ladder itself can be printed:

```swift run
/// The word with each letter in turn replaced by "*": "cold" gives "*old", "c*ld", "co*d", "col*"
func patterns(of word: String) -> [String] {
    let letters = Array(word)
    return letters.indices.map { index in
        var pattern = letters
        pattern[index] = "*"
        return String(pattern)
    }
}

func ladder(from start: String, to target: String, words: [String]) -> [String] {
    var buckets: [String: [String]] = [:]               // pattern → the words that fit it
    for word in words {
        for pattern in patterns(of: word) {
            buckets[pattern, default: []].append(word)
        }
    }
    var parent: [String: String] = [start: start]      // also the visited set
    var queue = [start]
    var head = 0
    while head < queue.count && parent[target] == nil {
        let word = queue[head]
        head += 1
        for pattern in patterns(of: word) {
            for next in buckets[pattern] ?? [] where parent[next] == nil {
                parent[next] = word
                queue.append(next)
            }
        }
    }
    guard parent[target] != nil else { return [] }
    var path = [target]
    while path[path.count - 1] != start {
        path.append(parent[path[path.count - 1]]!)
    }
    return path.reversed()
}

let words = ["cold", "cord", "core", "card", "ward", "warm", "word", "worm", "wore",
             "lead", "load", "goad", "gold", "bold", "bolt"]
print(patterns(of: "cold"))
print(ladder(from: "cold", to: "warm", words: words))
print(ladder(from: "lead", to: "gold", words: words))
print(ladder(from: "bolt", to: "wore", words: words))
print(ladder(from: "cold", to: "cold", words: words))
print(ladder(from: "cold", to: "wolf", words: words))
```

```output
["*old", "c*ld", "co*d", "col*"]
["cold", "cord", "word", "ward", "warm"]
["lead", "load", "goad", "gold"]
["bolt", "bold", "cold", "cord", "word", "wore"]
["cold"]
[]
```

What to notice:

- **The graph is never stored as an adjacency list.** The buckets are a compact index from which neighbours are read on demand.
- **The parent dictionary is the visited set**, keyed by `String`. When states are strings, dictionaries and sets are the natural tools, as in [Patterns: grouping and longest consecutive sequence](/dsa/learn/hash-grouping-consecutive), where words were grouped by a key in the same way.
- **The ladders aren't unique.** bolt → bold → cold → cord → core → wore is just as short as the third ladder. BFS returns the one it finds first, which depends on the order of the list.
- **The buckets were built by looping over the array**, not over a `Set`, so the search, and the printed ladders, come out the same on every run.

A refinement for big dictionaries: once a bucket has been scanned, every word in it has a parent, so set the bucket to `nil`. No bucket is then scanned twice, which matters when many words share common patterns.

## How big is the space?

State-space BFS visits every state it can reach before the target, so its cost is roughly **(number of states) × (moves per state) × (cost of handling one state)**. That makes the size of the space the first thing to estimate:

| Puzzle | States | BFS? |
| --- | --- | --- |
| 4-wheel lock | 10,000 | instantly |
| Word ladder, 30,000 words | 30,000 | easily |
| 8-puzzle (3 × 3 sliding tiles) | 181,440 reachable | yes |
| 15-puzzle (4 × 4) | about 10¹³ | no |
| Rubik's cube | about 4.3 × 10¹⁹ | no |

When the space is too big, there are two big ideas. Searching from both ends at once, in the next lesson, shrinks the work dramatically when both the start and the target are known. Guiding the search towards the target with an estimate of the remaining distance is [A* search](/dsa/learn/sp-a-star), in M44.

<Callout kind="gotcha" title="State-space slips">
- **Forgetting the start state's own rules.** If the start is forbidden (a jammed `0000`), the answer is -1 before any move; if the start is the target, it's 0.
- **Marking forbidden states as merely "seen".** It works, but keep them separate if you also need to report or count them.
- **Storing states as large structures or strings when numbers would do.** Hashing a string costs O(L) per lookup; an array index costs O(1).
- **Building the whole graph first.** Generating the edges between all 30,000 words up front is the O(n²) step you were trying to avoid. Generate neighbours as states are dequeued.
</Callout>
