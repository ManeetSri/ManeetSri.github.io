## Why it matters

"Count the islands in this map" is probably the most asked graph question in interviews, and for good reason: it's connected components in disguise, on a grid where you have to spot the graph yourself. The same code counts the cells in a microscope image, finds the separate shapes in a drawing, or measures the rooms on a floor plan in a game. This lesson counts islands and measures them, compares two ways of remembering which cells you've seen, and explains why the recursive version that most tutorials show will crash on big maps in Swift.

## Counting islands: scan and sink

A map is a grid of land and water. Land cells that touch up, down, left or right are part of the same island. Each island is a connected component of the grid graph from [Connected components and flood fill](/dsa/learn/gt-components), so the plan is the same:

1. Scan every cell, row by row.
2. When you find land you haven't visited, it's the first cell of a new island: count it.
3. Visit the whole island from there, so none of its other cells starts another count.

The simplest way to "visit" is to **sink** the island: turn each land cell into water as you reach it. Sunk cells can't be counted again, and they're never pushed twice. Counting the cells you pop gives each island's **area** for free:

```swift run
let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

/// The area of every island, in the order the scan meets them
func islandAreas(_ map: [[Character]]) -> [Int] {
    var grid = map                                      // a copy we're free to change
    var areas: [Int] = []
    for row in grid.indices {
        for column in grid[row].indices where grid[row][column] == "#" {
            grid[row][column] = "~"                     // sink it: land becomes water
            var stack = [(row, column)]
            var area = 0
            while let cell = stack.popLast() {
                area += 1
                for (dr, dc) in directions {
                    let r = cell.0 + dr
                    let c = cell.1 + dc
                    guard r >= 0, r < grid.count, c >= 0, c < grid[r].count else { continue }
                    guard grid[r][c] == "#" else { continue }
                    grid[r][c] = "~"
                    stack.append((r, c))
                }
            }
            areas.append(area)
        }
    }
    return areas
}

let map = [
    "##..#",
    "#...#",
    "..#..",
    ".###.",
    "#....",
].map { Array($0) }

let areas = islandAreas(map)
print("islands:", areas.count)
print("areas:", areas)
print("largest:", areas.max() ?? 0)
print("map unchanged:", String(map[0]))
```

```output
islands: 4
areas: [3, 2, 4, 1]
largest: 4
map unchanged: ##..#
```

What to notice:

- **The scan meets each island at its first cell in reading order**, top row first and left to right: the L-shape in the top-left corner (3 cells), the strip down the right (2), the T-shape in the middle (4), then the single cell in the bottom-left (1).
- **`where grid[row][column] == "#"` is rechecked on every pass**, so cells sunk by an earlier island are skipped by the scan.
- **The answer to "how many" and "how big" comes from one pass.** `areas.count` is the number of islands, and `areas.max() ?? 0` handles a map with no land.
- **The cost is O(rows × columns).** The scan looks at every cell once, and each land cell is pushed and popped once, however many islands there are.

## Sinking the map, or keeping a visited grid

There are two ways to remember which cells you've seen:

| | Sink the land | A separate visited grid |
| --- | --- | --- |
| Extra memory | none beyond the copy | a `[[Bool]]` the size of the map |
| The original map | changed (in your copy) | untouched |
| Works when cells have many values | only if you have a spare value to write | always |

In many languages, sinking the input is frowned on because it destroys the caller's data. Swift is different. A function's parameters are constants, so to change the map you have to write `var grid = map`, and arrays are **values**: the copy is yours, and the caller's map is untouched, as the last line of the output shows. The price is the copy itself, made on the first write thanks to copy-on-write: O(rows × columns) time and memory, about the same as a visited grid. (An `inout` parameter is the exception: changes to it do reach the caller.)

A visited grid looks like this. Packing each cell into one `Int`, `row * columns + column`, as the tip in [Direction arrays for grid moves](/dsa/learn/matrix-directions) suggested, lets it be a flat `[Bool]`:

```swift
var visited = Array(repeating: false, count: rows * columns)
visited[row * columns + column] = true
var stack = [row * columns + column]
while let cell = stack.popLast() {
    let (r, c) = (cell / columns, cell % columns)
    // …for each land neighbour (nr, nc) not yet visited: mark it, then push nr * columns + nc
}
```

Either way, the key rule from BFS still applies: **mark a cell when you push it**, not when you pop it, so it's never in the stack twice.

## Why not recursion?

Most tutorials show island counting with a recursive DFS, and it's lovely to read:

```swift
func sink(_ grid: inout [[Character]], _ r: Int, _ c: Int) {
    guard r >= 0, r < grid.count, c >= 0, c < grid[r].count, grid[r][c] == "#" else { return }
    grid[r][c] = "~"
    sink(&grid, r - 1, c)
    sink(&grid, r + 1, c)
    sink(&grid, r, c - 1)
    sink(&grid, r, c + 1)
}
```

The trouble is how deep it goes. Each call that finds land makes another call before it returns, so the recursion is as deep as the longest path the DFS wanders down. Here's that depth, measured, for a snake-shaped island (full rows of land joined at alternate ends) and for a map that's entirely land:

```swift run
// A size × size grid whose land is one snake: full rows joined at alternate ends
func snake(_ size: Int) -> [[Bool]] {
    var land = Array(repeating: Array(repeating: false, count: size), count: size)
    for row in stride(from: 0, to: size, by: 2) {
        land[row] = Array(repeating: true, count: size)
    }
    for row in stride(from: 1, to: size, by: 2) {
        land[row][row % 4 == 1 ? size - 1 : 0] = true
    }
    return land
}

// The recursive island walk, measuring how deep the recursion gets
func deepestRecursion(_ land: [[Bool]]) -> (area: Int, depth: Int) {
    var land = land
    var area = 0
    var depth = 0
    var deepest = 0
    func visit(_ r: Int, _ c: Int) {
        guard r >= 0, r < land.count, c >= 0, c < land[r].count, land[r][c] else { return }
        land[r][c] = false
        area += 1
        depth += 1
        deepest = max(deepest, depth)
        visit(r - 1, c)
        visit(r + 1, c)
        visit(r, c - 1)
        visit(r, c + 1)
        depth -= 1
    }
    visit(0, 0)
    return (area, deepest)
}

for size in [10, 40, 100] {
    let result = deepestRecursion(snake(size))
    print("\(size) × \(size) snake: area \(result.area), recursion \(result.depth) calls deep")
}
let open = deepestRecursion(Array(repeating: Array(repeating: true, count: 100), count: 100))
print("100 × 100 all land: area \(open.area), recursion \(open.depth) calls deep")
```

```output
10 × 10 snake: area 55, recursion 55 calls deep
40 × 40 snake: area 820, recursion 820 calls deep
100 × 100 snake: area 5050, recursion 5050 calls deep
100 × 100 all land: area 10000, recursion 10000 calls deep
```

On the snake, the recursion is exactly as deep as the island is big: it can only go forwards. The open map is no better. Trying "up" first, then "down", the walk runs down the first column, up the second, down the third, and so on, and every cell ends up on one long chain of calls: 10,000 deep for a 100 × 100 map.

This script runs on the main thread, with about 8 MB of stack, so it survives. But as [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) measured, a Swift Testing test gets about 8,000 calls before it crashes. A 1000 × 1000 map, which a test or an interviewer can easily give you, needs up to a million. So in this course, **grid searches use an explicit stack or BFS**, as in the first example. They do exactly the same work, and their stack lives on the heap.

<Callout kind="tip" title="DFS or BFS for islands?">
Either. Counting and measuring only need every land cell visited once, in any order. Swap `stack.popLast()` for a head-index queue and the code above becomes a BFS with the same answers. Choose BFS when the problem also asks about distances, such as "how far is each cell from the coast?"
</Callout>

## Variations you'll meet

| Question | The twist |
| --- | --- |
| Largest island | track the maximum area, as above |
| Island perimeter | for each land cell, count its sides that face water or the edge of the map |
| Islands that don't touch the border | start from the border instead: the next lesson |
| Distinct island shapes | record each island's cells relative to its first cell, and put the shapes in a `Set` |
| Biggest island after turning one water cell into land | label each island with its area, then for each water cell add up the distinct islands next to it |
| Land appearing one cell at a time | union-find, in M45, avoids searching again after each new cell |

<Callout kind="gotcha" title="Island-counting slips">
- **Comparing with the wrong character.** A map of `"1"` and `"0"` is `[[Character]]`, so compare with `"1"`, a `Character`, not the number `1`. Converting to a `[[Bool]]` first makes the comparisons quicker and the code shorter.
- **Counting diagonal neighbours** when the problem says up, down, left and right. Use the 4-way direction array unless told otherwise.
- **Marking on pop** lets a cell be pushed by up to four neighbours. It still counts correctly if you skip already-visited cells as you pop them, but areas computed by counting pushes come out too big.
- **Forgetting the empty map.** `areas.max()` is `nil` when there's no land, and a map with no rows has no `grid[0]` to read the width from.
</Callout>
