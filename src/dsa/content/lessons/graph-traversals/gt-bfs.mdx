## Why it matters

"What's the fewest number of moves?" is one of the most common questions in DSA, and in apps: the fewest taps from one screen to another in a navigation flow, the fewest hops between two people in a contacts graph, the quickest route through a game level. When every step costs the same, **breadth-first search** (BFS) answers it, and it does so in time proportional to the size of the graph. You met BFS on a grid in [A preview of BFS](/dsa/learn/queue-bfs-preview). This lesson runs it on any graph, proves why its distances are right, and rebuilds the actual route, not only its length.

## The algorithm, on any graph

Graphs in this module are given the way [Adjacency matrix, list and edge list](/dsa/learn/graph-representations) recommends for most problems: vertices numbered `0..<n`, and an **adjacency list** `neighbours`, where `neighbours[v]` is the array of vertices joined to v. Here is the graph used throughout this lesson and the next ones:

```text
        1 ─── 3
       /     / \
      0     /   5 ─── 6 ─── 7
       \   /   /
        2 ─── 4               8   (no edges)
```

BFS from a start vertex works in three moves, exactly as on the grid:

1. Mark the start as seen, at distance 0, and put it in a queue.
2. Take the vertex at the front of the queue. For each neighbour not seen yet, give it distance + 1, mark it seen and add it to the back of the queue.
3. Repeat until the queue is empty.

```swift run
// The example graph as an adjacency list: neighbours[v] lists v's neighbours, smallest first
let edges = [[0, 1], [0, 2], [1, 3], [2, 3], [2, 4], [3, 5], [4, 5], [5, 6], [6, 7]]
let vertexCount = 9                                     // vertex 8 has no edges
var neighbours = Array(repeating: [Int](), count: vertexCount)
for edge in edges {
    neighbours[edge[0]].append(edge[1])
    neighbours[edge[1]].append(edge[0])
}
for vertex in neighbours.indices {
    neighbours[vertex].sort()
}

func bfs(from start: Int) -> (order: [Int], distance: [Int]) {
    var distance = Array(repeating: -1, count: vertexCount)   // -1: not seen yet
    distance[start] = 0
    var queue = [start]
    var head = 0
    while head < queue.count {
        let vertex = queue[head]
        head += 1
        for next in neighbours[vertex] where distance[next] == -1 {
            distance[next] = distance[vertex] + 1        // mark it the moment it's enqueued
            queue.append(next)
        }
    }
    return (queue, distance)                             // the queue holds the visiting order
}

let result = bfs(from: 0)
print("order:", result.order)
print("distance:", result.distance)
```

```output
order: [0, 1, 2, 3, 4, 5, 6, 7]
distance: [0, 1, 1, 2, 2, 3, 4, 5, -1]
```

What to notice:

- **`distance` does two jobs.** It holds the answer, and `-1` means "not seen". There's no separate visited set. When vertices aren't numbered (they're strings, or your own types made `Hashable` as in [Custom Hashable keys](/dsa/learn/hash-custom-keys)), a `Set` of seen vertices and a `[Vertex: Int]` dictionary do the same two jobs.
- **The queue is an array with a head index**, from [A queue with a head index](/dsa/learn/queue-head-index). Calling `removeFirst()` instead would shift every remaining element each time, which is O(n), as [Why removeFirst() is O(n)](/dsa/learn/queue-why-not-removefirst) showed. DSAKit's `Queue` hides the head index for you.
- **Nothing is ever removed from the array**, so when BFS ends, `queue` lists the vertices in the order they were visited.
- **Vertex 8 stays at `-1`**: BFS only reaches vertices connected to the start.

Step through it. The labels are distances, the frontier vertices are the ones waiting in the queue, and the highlighted edges are the ones each vertex was first reached along:

## Why the distances are shortest

At any moment, the queue holds vertices at distance d followed by vertices at distance d + 1, and never anything else. It starts with only the start, at distance 0. Taking a distance-d vertex off the front can only add distance-(d + 1) vertices to the back. So all the distance-d vertices leave before any distance-(d + 1) vertex, and the distances come out in order, 0, 1, 2, and so on.

Now suppose BFS first reaches a vertex v from u, so it records `distance[u] + 1`. Could there be a shorter path to v? Its last step would come from some neighbour w that is closer to the start than u. But closer vertices leave the queue earlier, so w would have been processed first, and w would have reached v first. Contradiction. **The first time BFS reaches a vertex, it has come by a shortest path.** That's why a vertex's distance is set once and never revised.

<Callout kind="analogy">
Rumours spread like BFS. Everyone you tell today hears it on day 1, everyone they tell hears it on day 2, and so on. The day someone first hears it is the length of the shortest chain of people between you and them, and hearing it again later changes nothing.
</Callout>

## Mark when you enqueue, not when you dequeue

A tempting variant marks a vertex as seen only when it comes **out** of the queue. It gives the same distances, provided it skips vertices that were already seen when they come out. But in the meantime, a vertex can be added once by every neighbour that sees it first, so the queue fills with duplicates:

```swift run
// How many times does BFS enqueue something? It depends on when vertices are marked.
func enqueueCount(_ neighbours: [[Int]], markWhenEnqueued: Bool) -> Int {
    var seen = Array(repeating: false, count: neighbours.count)
    var queue = [0]
    var head = 0
    if markWhenEnqueued { seen[0] = true }
    while head < queue.count {
        let vertex = queue[head]
        head += 1
        if !markWhenEnqueued {
            if seen[vertex] { continue }                 // a duplicate: skip it
            seen[vertex] = true
        }
        for next in neighbours[vertex] where !seen[next] {
            if markWhenEnqueued { seen[next] = true }
            queue.append(next)
        }
    }
    return queue.count
}

// A 100 × 100 grid: each cell joined to the cells above, below, left and right
let size = 100
let grid = (0..<(size * size)).map { cell -> [Int] in
    let (row, column) = (cell / size, cell % size)
    var result: [Int] = []
    if row > 0 { result.append(cell - size) }
    if row < size - 1 { result.append(cell + size) }
    if column > 0 { result.append(cell - 1) }
    if column < size - 1 { result.append(cell + 1) }
    return result
}
// 1,000 vertices, every one joined to every other
let complete = (0..<1_000).map { vertex in (0..<1_000).filter { $0 != vertex } }

for (name, graph) in [("grid", grid), ("complete", complete)] {
    let early = enqueueCount(graph, markWhenEnqueued: true)
    let late = enqueueCount(graph, markWhenEnqueued: false)
    print("\(name): \(graph.count) vertices, mark on enqueue \(early), mark on dequeue \(late)")
}
```

```output
grid: 10000 vertices, mark on enqueue 10000, mark on dequeue 19801
complete: 1000 vertices, mark on enqueue 1000, mark on dequeue 499501
```

Marking on enqueue puts every vertex in the queue exactly once. Marking on dequeue can enqueue a vertex once per edge leading to it: twice as many on the grid, and about 500 times as many on the complete graph, where the queue grows to half a million entries for 1,000 vertices. And if you also forget to skip the duplicates when they come out, each one is processed again, with its neighbours. Mark on enqueue, and the queue never holds more than V entries.

## Rebuilding the path

Distances say how far; often you need the route itself. Record each vertex's **parent**, the vertex it was first reached from. The parents form a tree of shortest paths rooted at the start (the highlighted edges in the visualiser above). To read off the path to a goal, walk from the goal up through the parents until you reach the start, then reverse:

```swift run
let edges = [[0, 1], [0, 2], [1, 3], [2, 3], [2, 4], [3, 5], [4, 5], [5, 6], [6, 7]]
let vertexCount = 9
var neighbours = Array(repeating: [Int](), count: vertexCount)
for edge in edges {
    neighbours[edge[0]].append(edge[1])
    neighbours[edge[1]].append(edge[0])
}
for vertex in neighbours.indices {
    neighbours[vertex].sort()
}

func shortestPath(from start: Int, to goal: Int) -> [Int] {
    var parent = Array(repeating: -1, count: vertexCount)   // -1: not seen yet
    parent[start] = start                               // the start is its own parent
    var queue = [start]
    var head = 0
    while head < queue.count && parent[goal] == -1 {   // stop once the goal is reached
        let vertex = queue[head]
        head += 1
        for next in neighbours[vertex] where parent[next] == -1 {
            parent[next] = vertex                       // reached next from vertex
            queue.append(next)
        }
    }
    guard parent[goal] != -1 else { return [] }        // never reached
    var path = [goal]
    while path[path.count - 1] != start {
        path.append(parent[path[path.count - 1]])      // step back towards the start
    }
    return path.reversed()
}

print(shortestPath(from: 0, to: 7))
print(shortestPath(from: 0, to: 4))
print(shortestPath(from: 7, to: 2))
print(shortestPath(from: 0, to: 8))
print(shortestPath(from: 3, to: 3))
```

```output
[0, 1, 3, 5, 6, 7]
[0, 2, 4]
[7, 6, 5, 3, 2]
[]
[3]
```

What to notice:

- **The parent array replaces the distance array** as the visited mark. Setting `parent[start] = start` marks the start and gives the walk back a place to stop.
- **The search stops early** once the goal has a parent: its path is already final, for the reason in the previous section.
- **Ties are broken by neighbour order.** From 7, the path through 4, `[7, 6, 5, 4, 2]`, is just as short. BFS returns whichever it found first, which depends on the order of each adjacency list. Problems that accept "any shortest path" are fine with that; problems that want one particular path need a rule.

## Level by level

Some questions are about whole rings: "everyone within 2 hops", "how many rounds until the rumour reaches everyone". Process the queue one level at a time, as in [Level-order traversal with a queue](/dsa/learn/trav-level-order): note where the current level ends, handle exactly those vertices, then count one level.

```swift run
let edges = [[0, 1], [0, 2], [1, 3], [2, 3], [2, 4], [3, 5], [4, 5], [5, 6], [6, 7]]
var neighbours = Array(repeating: [Int](), count: 8)
for edge in edges {
    neighbours[edge[0]].append(edge[1])
    neighbours[edge[1]].append(edge[0])
}

var seen = Array(repeating: false, count: 8)
seen[0] = true
var queue = [0]
var head = 0
var distance = 0
while head < queue.count {
    let levelEnd = queue.count                          // everything queued so far is this level
    print("distance \(distance):", queue[head..<levelEnd].sorted())
    while head < levelEnd {
        let vertex = queue[head]
        head += 1
        for next in neighbours[vertex] where !seen[next] {
            seen[next] = true
            queue.append(next)
        }
    }
    distance += 1
}
```

```output
distance 0: [0]
distance 1: [1, 2]
distance 2: [3, 4]
distance 3: [5]
distance 4: [6]
distance 5: [7]
```

## Grids, directed graphs and cost

- **Grids** are graphs whose neighbours you compute instead of store, as [Implicit graphs: grids and state spaces](/dsa/learn/graph-implicit) explains: a cell's neighbours come from a direction array, as in [Direction arrays for grid moves](/dsa/learn/matrix-directions). The BFS is unchanged. Here it finds the way from S to G and traces the path back through the parents:

```visual grid
rows: ["S.#.....", "..#.##.#", ".##..#..", "....#..G"]
```

- **Directed graphs** need no change at all: follow each vertex's outgoing edges only. The distances are then "fewest edges **from** the start", which can differ from "fewest edges **to** it".
- **Cost.** Each reachable vertex is enqueued and dequeued once, and its adjacency list is scanned once when it's dequeued. The lists hold 2E entries in total for an undirected graph (each edge appears in both endpoints' lists), so BFS is **O(V + E)** time, with O(V) extra space for the queue and the distances.

<Callout kind="gotcha" title="The classic BFS slips">
- **`removeFirst()` on an array** makes BFS O(V²) on a long queue. Use a head index or DSAKit's `Queue`.
- **Forgetting to mark the start.** Its neighbours then enqueue it again at distance 2.
- **Marking on dequeue** without skipping duplicates processes vertices many times.
- **Weights.** BFS counts edges. If edges have different costs (minutes, metres), the route with the fewest edges isn't necessarily the cheapest. That's [Dijkstra's algorithm](/dsa/learn/sp-dijkstra), in M44.
</Callout>
