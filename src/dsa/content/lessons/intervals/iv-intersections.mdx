## Why it matters

"Find a time" in a calendar app looks at everyone's schedule and shows when they're all free. A video editor needs the stretch where two clips both have footage. A monitoring tool wants the windows when two services were both down. Each of these is an **intersection** of interval lists: the times that belong to both. Interviewers like it because the efficient answer is a tidy two-pointer walk, and because "free time for everyone" combines it with the merging you already know.

## The intersection of two intervals

Start with just two intervals. Their overlap, if there is one, starts at the **later** start and ends at the **earlier** end. If that start comes after that end, they don't meet.

```swift run
// The overlap of two closed intervals, or nil if they don't meet
func intersection(_ a: [Int], _ b: [Int]) -> [Int]? {
    let start = max(a[0], b[0])     // the later start
    let end = min(a[1], b[1])       // the earlier end
    return start <= end ? [start, end] : nil
}

for (a, b) in [([1, 6], [4, 9]), ([1, 6], [2, 3]), ([1, 6], [6, 8]), ([1, 6], [7, 8])] {
    if let overlap = intersection(a, b) {
        print(a, b, "->", overlap)
    } else {
        print(a, b, "-> none")
    }
}
```

```output
[1, 6] [4, 9] -> [4, 6]
[1, 6] [2, 3] -> [2, 3]
[1, 6] [6, 8] -> [6, 6]
[1, 6] [7, 8] -> none
```

These are **closed** intervals, so `[1, 6]` and `[6, 8]` share the single point 6, and the answer is `[6, 6]`. With half-open intervals the test becomes `start < end`, and touching intervals share nothing. A zero-length overlap means something for whole seconds ("second 6 is in both"), and nothing for meetings ("from 10:00 to 10:00").

## Two sorted lists, two pointers

Now take two lists, each sorted by start, and each with no overlaps inside itself: say, the closed windows of whole seconds when two security cameras were recording. You want every window when both were recording.

Checking every window of one list against every window of the other costs O(m × n). But both lists are sorted, so walk them together with one pointer each, as you did when [merging sorted arrays](/dsa/learn/arrays-merge-sorted):

1. Record the intersection of `a[i]` and `b[j]`, if there is one.
2. Move on from whichever of the two **ends first**.

```swift run
func intersect(_ a: [[Int]], _ b: [[Int]]) -> [[Int]] {
    var result: [[Int]] = []
    var i = 0
    var j = 0
    while i < a.count && j < b.count {
        let start = max(a[i][0], b[j][0])
        let end = min(a[i][1], b[j][1])
        if start <= end {
            result.append([start, end])
        }
        // Whichever ends first can't overlap anything later in the other list
        if a[i][1] < b[j][1] {
            i += 1
        } else {
            j += 1
        }
    }
    return result
}

let frontDoor = [[0, 2], [5, 10], [13, 23], [24, 25]]
let backDoor = [[1, 5], [8, 12], [15, 24], [25, 26]]
print(intersect(frontDoor, backDoor))
```

```output
[[1, 2], [5, 5], [8, 10], [15, 23], [24, 24], [25, 25]]
```

Each step moves one pointer forwards, so the loop runs at most m + n times: **O(m + n)** time, plus the output.

Why is it safe to move on from the one that ends first? Say `a[i]` ends first, at or before `b[j]` ends. Every later window in `b` starts after `b[j]` ends, because `b`'s windows don't overlap. So every later `b` window starts after `a[i]` ends too, and `a[i]` can never meet one of them. It has nothing left to give. When both end at the same time, moving either pointer is fine; the code moves `j`, and `a[i]` is moved on at the next step after finding nothing new.

## Free time common to everyone

A harder relative: each person has a sorted list of **busy** intervals, and you want the times when **nobody** is busy. Intersecting everyone's free time works, but there's a shorter route. Somebody is busy at a moment exactly when that moment falls inside **any** busy interval, from anyone. So:

1. Pour every busy interval into one list.
2. Sort it and merge it, as in [Merge and insert intervals](/dsa/learn/iv-merge-insert).
3. The gaps between neighbouring merged blocks are free for everyone.

Meetings are half-open here, so blocks that touch, like `[12, 13)` and `[13, 14)`, leave no gap: merging them is right, because a gap of zero length isn't free time.

```swift run
func commonFreeTime(_ schedules: [[[Int]]]) -> [[Int]] {
    // 1 and 2: every busy interval in one list, sorted and merged (touching blocks join)
    let all = schedules.flatMap { $0 }.sorted { $0[0] < $1[0] }
    var busy: [[Int]] = []
    for interval in all {
        if let last = busy.last, interval[0] <= last[1] {
            busy[busy.count - 1][1] = max(last[1], interval[1])
        } else {
            busy.append(interval)
        }
    }
    // 3. The gaps between merged blocks are free for everyone
    var free: [[Int]] = []
    for i in busy.indices.dropFirst() {
        free.append([busy[i - 1][1], busy[i][0]])
    }
    return free
}

let ana = [[9, 10], [12, 13], [16, 18]]
let ben = [[9, 11], [15, 16]]
let chloe = [[10, 11], [13, 14]]
print(commonFreeTime([ana, ben, chloe]))
```

```output
[[11, 12], [14, 15]]
```

Merged, the busy time is `[9, 11)`, `[12, 14)` and `[15, 18)`, so everyone is free from 11 to 12 and from 14 to 15. For N busy intervals in total, this is O(N log N) for the sort. Each person's list is already sorted, so a k-way merge with a heap (M39) could do it in O(N log k) for k people, but the plain sort is the version to reach for first. To include the start and end of the working day, add the gaps before the first block and after the last one.

## Putting it together: the first slot that's long enough

A scheduling assistant has two people's **free** slots, half-open and sorted, and needs the earliest shared slot of at least a given length. That's the two-pointer walk again, stopping at the first overlap that's long enough:

```swift run
func firstSharedSlot(_ a: [[Int]], _ b: [[Int]], minutes: Int) -> [Int]? {
    var i = 0
    var j = 0
    while i < a.count && j < b.count {
        let start = max(a[i][0], b[j][0])
        let end = min(a[i][1], b[j][1])
        if end - start >= minutes {
            return [start, start + minutes]
        }
        if a[i][1] < b[j][1] { i += 1 } else { j += 1 }
    }
    return nil
}

let mayaFree = [[540, 600], [660, 720], [840, 960]]     // minutes after midnight
let omarFree = [[570, 615], [700, 780], [900, 1020]]
print(firstSharedSlot(mayaFree, omarFree, minutes: 30) ?? [])
print(firstSharedSlot(mayaFree, omarFree, minutes: 45) ?? [])
print(firstSharedSlot(mayaFree, omarFree, minutes: 90) ?? [])
```

```output
[570, 600]
[900, 945]
[]
```

Half-open slots make the length a plain subtraction, `end - start`, and a negative length simply means the two slots don't meet. 570 minutes after midnight is 9:30, so the 30-minute meeting goes from 9:30 to 10:00.

<Callout kind="gotcha" title="Common mistakes">
- **Moving the wrong pointer.** Moving on from the interval that starts first, or ends **later**, skips overlaps. Always move on from the one that ends first.
- **The wrong comparison for the kind of interval.** Closed intervals keep a single-point overlap with `start <= end`; half-open intervals drop it with `start < end`. Read the problem's examples to see which it wants.
- **Forgetting the lists' promises.** The two-pointer walk relies on each list being sorted with no overlaps inside it. If a list might overlap itself, merge it first.
</Callout>
