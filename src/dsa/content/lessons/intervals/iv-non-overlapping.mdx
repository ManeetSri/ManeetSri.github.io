## Why it matters

One lecture hall, a day of talk proposals, and no two talks may overlap: which talks do you accept so that as many as possible go ahead? The same question appears as booking jobs on one machine, or fitting adverts into one slot of airtime. Asked the other way round, "cancel as few as possible", it's a classic interview problem. Its answer is the first **greedy** algorithm in this course: make the choice that looks best right now, never undo it, and still end up with the best answer overall. This lesson shows the choice, the argument for why it's safe, and a close cousin about shooting balloons.

## Flip the question

"Remove as few intervals as possible so that the rest don't overlap" is the same as "keep as many as possible that don't overlap". If you can keep k of the n intervals, the answer is n − k. So focus on keeping.

In this section the intervals are **half-open**: two that only touch can both stay. A talk from 9 to 10 and one from 10 to 11 share the hall happily.

## Keep the one that ends first

Here's the greedy rule. Sort the intervals by **end**. Keep the first one. Then walk through the rest, and keep each interval that starts at or after the end of the last one you kept. Skip (remove) everything else.

```swift run
func minRemovals(_ intervals: [[Int]]) -> Int {
    let sorted = intervals.sorted { $0[1] < $1[1] }     // earliest end first
    var removals = 0
    var lastEnd = Int.min                                // the end of the last interval kept
    for interval in sorted {
        if interval[0] >= lastEnd {                      // half-open: touching is fine
            lastEnd = interval[1]
            print("keep  ", interval)
        } else {
            removals += 1
            print("remove", interval)
        }
    }
    return removals
}

print(minRemovals([[1, 3], [2, 4], [3, 5], [1, 8], [6, 7], [5, 9]]))
```

```output
keep   [1, 3]
remove [2, 4]
keep   [3, 5]
keep   [6, 7]
remove [1, 8]
remove [5, 9]
3
```

`lastEnd` starts at `Int.min`, so the first interval always fits. `[3, 5]` stays because it starts exactly when `[1, 3]` ends. Step through the same input:

```visual intervals

```

The intuition: the interval that ends first **frees the hall soonest**, leaving the most room for everything after it. Whatever else you might keep first, it would hold the hall at least as long.

## Why earliest end is safe: an exchange argument

"Leaves the most room" is a feeling, not a proof. Here's an argument you can say out loud in an interview, called an **exchange argument**: take any best answer and show it can be changed, step by step, into the greedy's answer without getting worse.

1. Let `e` be the interval that ends first. Take **any** best selection, one that keeps as many intervals as possible, and look at its first interval, `f`.
2. `f` ends no earlier than `e`, because `e` ends first of all.
3. Swap `f` for `e`. Every other interval in the selection started at or after `f` ended, so it also starts at or after `e` ends. Nothing overlaps, and the selection is the same size. So there's a best selection that starts with `e`, which is exactly what the greedy keeps.
4. Throw away `e` and everything that overlaps it. What's left is the same problem on fewer intervals, and the same argument applies to its first choice, and so on.

So the greedy keeps as many intervals as a best selection does. You'll make this kind of argument properly in the greedy module, M50.

## Why sorting by start fails

Sorting by start feels just as natural. It's wrong, and a single example shows it. One long talk starts first and swallows the whole day:

```swift run
// Keep each interval that fits after the last one kept, in the order given
func keptGreedily(_ sorted: [[Int]]) -> [[Int]] {
    var kept: [[Int]] = []
    for interval in sorted {
        if let last = kept.last, interval[0] < last[1] {
            continue                                   // overlaps the last one kept: skip it
        }
        kept.append(interval)
    }
    return kept
}

let talks = [[1, 10], [2, 4], [5, 7], [8, 9]]
print("by start:", keptGreedily(talks.sorted { $0[0] < $1[0] }))
print("by end:  ", keptGreedily(talks.sorted { $0[1] < $1[1] }))
```

```output
by start: [[1, 10]]
by end:   [[2, 4], [5, 7], [8, 9]]
```

Starting earliest says nothing about how long an interval holds the hall. Ending earliest is what matters. ("Shortest first" fails too: try it on `[[1, 5], [4, 7], [6, 10]]`, where the short middle talk blocks both others.)

<Callout kind="tip" title="A start-sorted version that works">
You can sort by start if you change what happens at a clash: when two intervals overlap, remove the one that **ends later** and keep the other. That's the same rule in disguise, and it gives the same count.
</Callout>

## Minimum arrows: the same greedy, closed intervals

A close cousin. Balloons float above a number line, and each covers a **closed** range of x values. An arrow shot straight up at position x bursts every balloon whose range includes x. What's the fewest arrows that burst them all?

Sort by end again. The first balloon to end must be hit by some arrow at or before its end, and shooting **at** its end is best: it still hits that balloon, and as many later balloons as possible. Then skip every balloon that arrow bursts, and repeat with the next one it misses.

```swift run
func minArrows(_ balloons: [[Int]]) -> Int {
    let sorted = balloons.sorted { $0[1] < $1[1] }
    var arrows = 0
    var arrowAt = Int.min
    for balloon in sorted {
        if balloon[0] > arrowAt {               // the last arrow missed this balloon
            arrows += 1
            arrowAt = balloon[1]                // shoot as far right as this balloon allows
            print("arrow at", arrowAt)
        }
    }
    return arrows
}

print(minArrows([[10, 16], [2, 8], [1, 6], [7, 12], [12, 14]]))
```

```output
arrow at 6
arrow at 12
2
```

The arrow at 12 bursts `[7, 12]`, `[10, 16]` and `[12, 14]`, which only **touches** 12. That works because the balloons are closed. The balloons that receive a new arrow never overlap each other, so no plan can use fewer arrows than there are of them, and the greedy uses exactly that many.

The two problems differ by one character:

| Problem | Intervals | Touching | Keep or shoot when |
| --- | --- | --- | --- |
| fewest removals | half-open | allowed together | `interval[0] >= lastEnd` keeps it |
| fewest arrows | closed | share an arrow | `balloon[0] > arrowAt` needs a new arrow |

<Callout kind="gotcha" title="Swift gotcha: sort with <, never <=">
The closure you pass to `sorted(by:)` must answer "does the first belong strictly before the second?", so it must return `false` for two equal elements. `{ $0[1] <= $1[1] }` breaks that rule whenever two ends are equal, and Swift's sort promises nothing about the result when the rule is broken. Always use `<`.
</Callout>
