## Why it matters

A music app's ratings matrix has a row per user and a column per song. With a million users and a million songs, that's a **trillion** cells, and each user has rated maybe fifty songs: the matrix is more than 99.99% zeros. Storing it as a 2D array is impossible; storing only the nonzero cells is easy and fast, if you choose the right layout. At the other extreme, a set of small integers (visited nodes, selected rows, permission flags, users who liked a post) can be stored as **one bit per possible member**, so that intersecting two sets of 10,000 members is 157 machine instructions. This lesson covers both: **sparse matrices**, which store only what's there, and **bitsets**, which store everything in the smallest space possible.

## Storing only the nonzeros

A matrix is **sparse** when most of its cells are zero. Graphs are the classic example: an adjacency matrix of a social network, as in [Adjacency matrix, list and edge list](/dsa/learn/graph-representations), has a row and a column per person but only a few hundred ones per row. Three layouts store only the nonzeros:

| Layout | What it stores | Good at | Weak at |
| --- | --- | --- | --- |
| Dense `[[Int]]` | every cell | any cell in O(1), small matrices | memory: rows × columns |
| Dictionary of keys, `[Int: Int]` | `row * columns + column` → value | building, and changing any cell in O(1) | walking a row in order |
| Compressed sparse row (CSR) | three arrays, described below | walking rows, matrix × vector | inserting a new nonzero: O(stored) |

A **dictionary of keys** is the natural first step: one entry per nonzero, keyed by a single `Int` that encodes the cell. (A struct with `row` and `column` as a `Hashable` key works as well.) It's ideal while the matrix is being **built**, in any order.

**CSR** is the layout for **using** it. It stores the nonzeros row by row in three arrays:

- `values`: the nonzero values, all of row 0's, then row 1's, and so on, each row's in column order;
- `columnIndices`: the column of each value;
- `rowStart`: where each row's entries begin, with one extra entry at the end, so row r's entries are positions `rowStart[r]..<rowStart[r + 1]`.

```text
matrix              values:        [5, 2, 7, 1]
[5 0 0 2]           columnIndices: [0, 3, 1, 3]
[0 0 0 0]           rowStart:      [0, 2, 2, 4]
[0 7 0 1]           row 1 is positions 2..<2: empty; row 2 is 2..<4: 7 at column 1, 1 at column 3
```

Building it is a counting job, like the counting sort from M32: count each row's nonzeros, then turn the counts into starting positions with a running total, which is a prefix sum.

```swift run
struct SeededGenerator: RandomNumberGenerator {
    var state: UInt64
    mutating func next() -> UInt64 {
        state &+= 0x9E37_79B9_7F4A_7C15
        var z = state
        z = (z ^ (z >> 30)) &* 0xBF58_476D_1CE4_E5B9
        z = (z ^ (z >> 27)) &* 0x94D0_49BB_1331_11EB
        return z ^ (z >> 31)
    }
}

// Compressed sparse row: the nonzero values row by row, their columns, and where each row starts
struct CSRMatrix {
    let rows: Int
    let columns: Int
    private(set) var values: [Int] = []
    private(set) var columnIndices: [Int] = []
    private(set) var rowStart: [Int]             // row r's entries are at rowStart[r]..<rowStart[r + 1]

    init(rows: Int, columns: Int, entries: [Int: Int]) {   // entries: row * columns + column → value
        self.rows = rows
        self.columns = columns
        rowStart = Array(repeating: 0, count: rows + 1)
        for key in entries.keys.sorted() {       // sorted keys are in row order, then column order
            values.append(entries[key]!)
            columnIndices.append(key % columns)
            rowStart[key / columns + 1] += 1     // count entries per row…
        }
        for r in 0..<rows {
            rowStart[r + 1] += rowStart[r]       // …then turn the counts into starting positions
        }
    }

    func value(_ row: Int, _ column: Int) -> Int {
        for k in rowStart[row]..<rowStart[row + 1] where columnIndices[k] == column {
            return values[k]
        }
        return 0
    }

    // Matrix × vector, touching only the stored entries
    func multiply(_ vector: [Int]) -> [Int] {
        (0..<rows).map { r in
            (rowStart[r]..<rowStart[r + 1]).reduce(0) { $0 + values[$1] * vector[columnIndices[$1]] }
        }
    }
}

// 1,000 users × 1,000 songs; each user has rated a few songs (1 to 5 stars)
let n = 1_000
var generator = SeededGenerator(state: 3)
var ratings: [Int: Int] = [:]                    // dictionary of keys: row * n + column → value
for user in 0..<n {
    for _ in 0..<3 {
        let song = Int(generator.next() % UInt64(n))
        ratings[user * n + song] = Int(generator.next() % 5) + 1
    }
}
let csr = CSRMatrix(rows: n, columns: n, entries: ratings)
print("cells:", n * n, " stored:", csr.values.count, " CSR arrays:",
      csr.values.count + csr.columnIndices.count + csr.rowStart.count, "Ints")

let row0 = csr.rowStart[0]..<csr.rowStart[1]
print("user 0 rated songs", row0.map { csr.columnIndices[$0] }, "with stars", row0.map { csr.values[$0] })
print("user 0, song 366:", csr.value(0, 366), " song 365:", csr.value(0, 365))

// The same matrix stored densely: every cell, mostly zeros
var dense = Array(repeating: Array(repeating: 0, count: n), count: n)
for (key, stars) in ratings {
    dense[key / n][key % n] = stars
}

// Weight each song and score every user: dense touches every cell, CSR only the ratings
let weights = (0..<n).map { $0 % 7 }
let sparseScores = csr.multiply(weights)
let denseScores = dense.map { row in zip(row, weights).reduce(0) { $0 + $1.0 * $1.1 } }
print("same scores:", sparseScores == denseScores, " dense multiplications:", n * n,
      " sparse:", csr.values.count)
```

```output
cells: 1000000  stored: 2994  CSR arrays: 6989 Ints
user 0 rated songs [53, 366, 729] with stars [2, 1, 3]
user 0, song 366: 1  song 365: 0
same scores: true  dense multiplications: 1000000  sparse: 2994
```

What to notice:

- **2,994 nonzeros instead of a million cells.** (Each user rated 3 random songs; a few picked the same song twice, which overwrote the first rating.) The CSR's three arrays hold under 7,000 `Int`s.
- **A row is a contiguous slice.** User 0's ratings are positions `rowStart[0]..<rowStart[1]` of two arrays, already sorted by column: no searching, no hashing.
- **Matrix × vector costs one multiplication per nonzero**: 2,994 instead of a million, with identical results. This operation is at the heart of recommendation systems, PageRank and physics simulations.
- **Sorting the keys put the entries in row order**, because `row * n + column` sorts by row first and then by column.
- **Reading one cell walks its row**, which is short in a sparse matrix. Binary search inside the row would make it O(log k) for rows with many entries.

**CSC** (compressed sparse column) is the same idea by columns, for when you walk columns instead. And the adjacency lists you've used for graphs since M41 are a close cousin of CSR: one short list per row. Packing all those lists into one array with a start index per node is exactly CSR, and it's how fast graph libraries store big graphs.

## Bitsets: one bit per possible member

In [Gray code and UInt64 bitsets](/dsa/learn/bits-gray-code-bitsets) you built a bitset: a set of the numbers `0..<capacity` stored as an array of `UInt64` **words**, with number x at bit `x & 63` of word `x >> 6`. Insert and contains are one shift, one mask and one OR or AND.

The real power is in **whole-set operations, a word at a time**. Each `UInt64` operation handles 64 members at once:

| Set operation | Word by word |
| --- | --- |
| union, A ∪ B | `a \| b` |
| intersection, A ∩ B | `a & b` |
| difference, A − B | `a & ~b` |
| size | sum of `nonzeroBitCount` |
| members in order | `trailingZeroBitCount`, then clear the lowest bit with `w & (w - 1)` |
| add s to every member | shift every bit up by s, carrying bits between words |

Here's one byte of two bitsets: the first holds 1, 2, 4, 5 and 7, the second 0, 1, 5 and 6. Switch the operator between `&` and `|` to see their intersection and union. A `UInt64` word does the same for 64 members in a single instruction.

```visual bitPlayground
value: 182
operand: 99
operator: "&"
```

The shift in the last row deserves a closer look. Shifting a bitset up by s moves bit i to bit i + s. Across words, each new word takes the old word `s >> 6` positions lower, shifted up by `s & 63` bits, plus the bits that overflowed from the word below it. It turns some dynamic programming into bit operations: in **subset sum** (which totals can some of the weights make?), the reachable totals after adding a weight w are the old totals plus the old totals shifted up by w. You'll meet the DP version in [Subset sum and equal partition](/dsa/learn/dpk-subset-sum); with a bitset, each weight is one shift and one OR over the whole set.

```swift run
// A set of the numbers 0..<capacity: one bit each, packed into UInt64 words
struct BitSet {
    let capacity: Int
    private(set) var words: [UInt64]

    init(capacity: Int) {
        self.capacity = capacity
        words = Array(repeating: 0, count: (capacity + 63) / 64)
    }

    mutating func insert(_ x: Int) {
        words[x >> 6] |= 1 << (x & 63)
    }

    func contains(_ x: Int) -> Bool {
        words[x >> 6] & (1 << (x & 63)) != 0
    }

    // Whole-set operations work on 64 numbers at a time
    func union(_ other: BitSet) -> BitSet { combined(with: other) { $0 | $1 } }
    func intersection(_ other: BitSet) -> BitSet { combined(with: other) { $0 & $1 } }
    func subtracting(_ other: BitSet) -> BitSet { combined(with: other) { $0 & ~$1 } }

    private func combined(with other: BitSet, _ operation: (UInt64, UInt64) -> UInt64) -> BitSet {
        var result = self
        for i in words.indices {
            result.words[i] = operation(words[i], other.words[i])
        }
        return result
    }

    var count: Int {
        words.reduce(0) { $0 + $1.nonzeroBitCount }
    }

    // The members in increasing order: jump straight from one set bit to the next
    var elements: [Int] {
        var result: [Int] = []
        for (i, word) in words.enumerated() {
            var rest = word
            while rest != 0 {
                result.append(i * 64 + rest.trailingZeroBitCount)
                rest &= rest - 1                 // clear the lowest set bit
            }
        }
        return result
    }

    // Every member x becomes x + s; members pushed past capacity fall off
    func shiftedUp(by s: Int) -> BitSet {
        var result = BitSet(capacity: capacity)
        let wordShift = s >> 6
        let bitShift = s & 63
        for i in stride(from: words.count - 1, through: wordShift, by: -1) {
            var word = words[i - wordShift] << bitShift
            if i - wordShift > 0 {
                word |= words[i - wordShift - 1] >> (64 - bitShift)   // bits carried from below
            }
            result.words[i] = word
        }
        let spare = words.count * 64 - capacity  // bits past the end must stay 0
        if spare > 0 {
            result.words[words.count - 1] &= ~UInt64(0) >> spare
        }
        return result
    }
}

// Which of 10,000 users liked post A, post B?
var likedA = BitSet(capacity: 10_000)
var likedB = BitSet(capacity: 10_000)
for user in stride(from: 0, to: 10_000, by: 3) { likedA.insert(user) }
for user in stride(from: 0, to: 10_000, by: 5) { likedB.insert(user) }
print("A:", likedA.count, " B:", likedB.count, " both:", likedA.intersection(likedB).count,
      " either:", likedA.union(likedB).count, " A only:", likedA.subtracting(likedB).count)
print("first users who liked both:", Array(likedA.intersection(likedB).elements.prefix(5)))
print("words per set:", likedA.words.count, "instead of", likedA.count, "Ints in an array")

// Subset sums: which totals can some of these weights make? Each weight shifts and ORs the set.
var reachable = BitSet(capacity: 31)
reachable.insert(0)
for weight in [3, 5, 7, 11] {
    reachable = reachable.union(reachable.shiftedUp(by: weight))
}
print("sums up to 30:", reachable.elements)

var wide = BitSet(capacity: 200)
wide.insert(60)
wide.insert(130)
print("60 and 130 shifted up by 10:", wide.shiftedUp(by: 10).elements, " by 70:", wide.shiftedUp(by: 70).elements)
```

```output
A: 3334  B: 2000  both: 667  either: 4667  A only: 2667
first users who liked both: [0, 15, 30, 45, 60]
words per set: 157 instead of 3334 Ints in an array
sums up to 30: [0, 3, 5, 7, 8, 10, 11, 12, 14, 15, 16, 18, 19, 21, 23, 26]
60 and 130 shifted up by 10: [70, 140]  by 70: [130]
```

What to notice:

- **Intersection, union and difference each looped over 157 words**, not 10,000 members. The users who liked both are the multiples of 15, as they should be.
- **`elements` skips empty space.** `trailingZeroBitCount` jumps straight to the next member, and `rest &= rest - 1` clears it, so the loop runs once per member plus once per word.
- **Subset sums come out of four shift-and-OR steps.** 26 is 3 + 5 + 7 + 11; 24 is missing because no combination of these weights makes it.
- **Shifting by 70 crossed a word boundary**: 60 moved from word 0 to word 2, into bit 2 of it (130 = 128 + 2), while 130 + 70 = 200 fell off the end.
- **The tail of the last word is cleared.** Capacity 200 uses 4 words, 256 bits; without the mask, 200 would linger in bits that aren't part of the set, and `count` would include it.

### Which set of integers?

| Representation | Memory for members in `0..<n` | Membership | Union of two sets |
| --- | --- | --- | --- |
| `Set<Int>` | proportional to the number of members | O(1) average | O(size of both) |
| `[Bool]` | n bytes | O(1) | O(n) |
| bitset of `UInt64` words | n / 8 bytes | O(1) | O(n / 64) |
| Foundation's `IndexSet` | proportional to the number of runs | O(log runs) | depends on runs |

A bitset wins when the members are dense in a known range, or when you do whole-set operations often. A `Set<Int>` wins when the range is huge and the members few: a bitset over all `Int`s would need 2⁶⁴ bits. Foundation's `IndexSet` stores **ranges** of consecutive integers, which is compact for things like the selected rows of a table, where members come in runs.

Swift's standard library has no bitset type. Apple's swift-collections package has one, `BitSet`, in its BitCollections module, along with `BitArray`, a compact array of `Bool`. Part IX looks at packages like these; for interviews and contests, the 40-line struct above is what you'd write.

<Callout kind="gotcha" title="Swift gotcha: >> and &>> disagree at 64">
`shiftedUp` relies on Swift's **smart shift**: for a `UInt64`, `word >> 64` is 0, because shifting out every bit leaves nothing. When `bitShift` is 0, `words[...] >> (64 - bitShift)` is exactly that, and correctly carries nothing. The **masking shift** `&>>` reduces the amount modulo 64 first, so `word &>> 64` is `word &>> 0`, the word unchanged, and the carry would OR a whole word into the wrong place. Masking shifts are slightly faster and appear in performance-tuned code; when the amount can reach 64, use the smart shift or handle that case separately.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **Dirty tail bits.** Any operation that can set bits past `capacity`, such as a shift, a complement (`~`) or "insert everything", must clear the unused top bits of the last word, or `count` and `elements` report members that aren't there.
- **Combining bitsets of different capacities.** Word-by-word operations assume both sets have the same number of words. Check, or pad the shorter one.
- **Inserting into CSR.** CSR is built once and read many times. Adding a nonzero shifts every later entry: collect changes in a dictionary of keys and rebuild.
</Callout>
