## Why it matters

"Can it be done?" often turns into "**in how many ways**?" How many playlists from these songs last exactly an hour? How many ways can a shop's stock be bundled to hit a price? And a classic interview puzzle: put a `+` or `-` in front of each number so the expression equals a target, and count the ways. The DP is the subset sum table again, with `+` where `||` was. This lesson covers that change, two traps it brings (zeros and huge counts), and the algebra that turns the plus/minus puzzle into a plain subset count.

## Counting instead of checking

Change what a cell means: `ways[s]` is the **number** of subsets of the numbers so far that add up to exactly `s`.

- **Transition.** For a new number `x`, the subsets making `s` are those that leave `x` out (`ways[s]` of them) plus those that put `x` in. Each of the second kind is a subset making `s - x` with `x` added, so there are `ways[s - x]` of them: `ways[s] += ways[s - x]`.
- **Base case.** `ways[0] = 1`. There's exactly one subset adding up to 0: the empty one. Get this wrong and every count is 0.
- **Order.** Sums from high to low within each number, as always for "each number at most once".

```swift run
/// How many subsets of `numbers` (each used at most once) add up to each sum from 0 to target?
func subsetCounts(_ numbers: [Int], target: Int) -> [Int] {
    var ways = Array(repeating: 0, count: target + 1)
    ways[0] = 1                                          // one way to make 0: take nothing
    for x in numbers {
        for s in stride(from: target, through: x, by: -1) {
            ways[s] += ways[s - x]                       // every way to make s - x, plus x
        }
        print("after \(x):", ways)
    }
    return ways
}

let ways = subsetCounts([2, 3, 5, 1], target: 6)
print("subsets adding up to 6:", ways[6])
```

```output
after 2: [1, 0, 1, 0, 0, 0, 0]
after 3: [1, 0, 1, 1, 0, 1, 0]
after 5: [1, 0, 1, 1, 0, 2, 0]
after 1: [1, 1, 1, 2, 1, 2, 2]
subsets adding up to 6: 2
```

What to notice:

- After 5, `ways[5]` is 2: the subsets \{2, 3\} and \{5\}.
- After 1, `ways[6]` is 2: \{5, 1\} and \{2, 3, 1\}. Each comes from a way to make 5, plus the 1.
- It's still O(n · T) time and O(T) memory. Counting costs no more than checking.

## Zeros: each one doubles the count

A zero can be in a subset or not without changing its sum. So every subset that makes `s` comes in two versions, with and without the zero, and **each zero doubles every count**, including `ways[0]`.

The DP gets this right on its own, as long as the inner loop goes all the way down to `s = 0` when `x` is 0. `stride(from: target, through: 0, by: -1)` does include 0, and the update becomes `ways[s] += ways[s]`, a doubling. Here it is against a brute-force count:

```swift run
func countSubsets(_ numbers: [Int], target: Int) -> Int {
    var ways = Array(repeating: 0, count: target + 1)
    ways[0] = 1
    for x in numbers {
        for s in stride(from: target, through: x, by: -1) {   // for x = 0 this reaches s = 0 too
            ways[s] += ways[s - x]
        }
    }
    return ways[target]
}

/// Brute force: try every subset as a bitmask
func countByTrying(_ numbers: [Int], target: Int) -> Int {
    var count = 0
    for mask in 0..<(1 << numbers.count) {
        let sum = numbers.indices.filter { mask & (1 << $0) != 0 }.map { numbers[$0] }.reduce(0, +)
        if sum == target { count += 1 }
    }
    return count
}

print(countSubsets([0, 0, 1], target: 1), countByTrying([0, 0, 1], target: 1))
print(countSubsets([0, 0, 1], target: 0), countByTrying([0, 0, 1], target: 0))
print(countSubsets([3, 0, 2, 1], target: 3), countByTrying([3, 0, 2, 1], target: 3))
```

```output
4 4
4 4
4 4
```

With \{0, 0, 1\}, the subsets making 1 are \{1\}, \{first 0, 1\}, \{second 0, 1\} and \{both 0s, 1\}. The two zeros are different items, even though they look the same, so all four count.

The bugs creep in when code "optimises" the loop. Starting sums at 1, or skipping zeros because "they don't change anything", undercounts by a factor of 2 for every zero. Tests for counting problems should always include zeros.

## When counts get huge: modulo

Counts of subsets grow like 2ⁿ. A hundred 1s have C(100, 50) subsets adding up to 50, about 10²⁹, far beyond `Int.max` (about 9.2 × 10¹⁸). Swift doesn't wrap around on overflow: it **stops the program**. So problems with big counts ask for the answer **modulo** a prime, usually 1,000,000,007.

The rule from [Modular arithmetic](/dsa/learn/math-modular-arithmetic) is that you may reduce after every addition. Both values are below the modulus, so their sum is below 2 × 10⁹ and fits easily:

```swift run
let mod = 1_000_000_007

/// Subsets adding up to target, counted modulo 1,000,000,007
func countSubsets(_ numbers: [Int], target: Int) -> Int {
    var ways = Array(repeating: 0, count: target + 1)
    ways[0] = 1
    for x in numbers {
        for s in stride(from: target, through: x, by: -1) {
            ways[s] = (ways[s] + ways[s - x]) % mod      // both are below mod, so the sum fits easily
        }
    }
    return ways[target]
}

let hundredOnes = Array(repeating: 1, count: 100)
print(countSubsets(hundredOnes, target: 50))             // C(100, 50), about 1.0 × 10²⁹, reduced
print(countSubsets(Array(repeating: 1, count: 20), target: 10))   // C(20, 10) is small enough to see whole
```

```output
538992043
184756
```

## Target sum: plus or minus

Here's the puzzle. Put `+` or `-` in front of each number. How many sign patterns make the expression equal `target`? With \{1, 1, 2, 3\} and target 1, three patterns work: `+1 -1 -2 +3`, `-1 +1 -2 +3` and `+1 +1 +2 -3`.

Brute force tries all 2ⁿ sign patterns. The DP comes from a little algebra. Call the sum of the numbers with a plus sign `P`, and the sum of the ones with a minus sign `M`. Then:

- `P - M = target`, because that's the expression;
- `P + M = total`, because every number has exactly one sign.

Add the two equations: `2P = total + target`, so **`P = (total + target) / 2`**. Choosing the plus-numbers is choosing a subset with sum `P`, and the minus-numbers are whatever is left. So the number of sign patterns is the number of subsets adding up to `P`, which is the counting DP from above.

Two checks come first. If `total + target` is odd, `P` isn't a whole number, so there are no ways. And if the target is beyond `total` in either direction, it can't be reached at all.

```swift run
func countSubsets(_ numbers: [Int], target: Int) -> Int {
    var ways = Array(repeating: 0, count: target + 1)
    ways[0] = 1
    for x in numbers {
        for s in stride(from: target, through: x, by: -1) {
            ways[s] += ways[s - x]
        }
    }
    return ways[target]
}

/// Ways to put + or - in front of every number so the expression equals target
func signWays(_ numbers: [Int], target: Int) -> Int {
    let total = numbers.reduce(0, +)
    // plus - minus = target and plus + minus = total, so plus = (total + target) / 2
    if abs(target) > total || (total + target) % 2 != 0 { return 0 }
    return countSubsets(numbers, target: (total + target) / 2)
}

/// Brute force: bit i of the mask set means numbers[i] gets a plus sign
func signWaysByTrying(_ numbers: [Int], target: Int) -> Int {
    var count = 0
    for mask in 0..<(1 << numbers.count) {
        var value = 0
        for i in numbers.indices {
            value += mask & (1 << i) != 0 ? numbers[i] : -numbers[i]
        }
        if value == target { count += 1 }
    }
    return count
}

let numbers = [1, 1, 2, 3]
for target in [1, 3, -3, 7, 2] {
    print("target \(target): DP \(signWays(numbers, target: target)), brute force \(signWaysByTrying(numbers, target: target))")
}
```

```output
target 1: DP 3, brute force 3
target 3: DP 2, brute force 2
target -3: DP 2, brute force 2
target 7: DP 1, brute force 1
target 2: DP 0, brute force 0
```

What to notice:

- Target 7 is the total: only "all plus" works, and `P = 7` has one subset, everything.
- Targets 3 and −3 have the same count. Flipping every sign turns one into the other.
- Target 2 is impossible: the total is 7, so every sign pattern gives an odd result.
- Zeros work exactly as before. Each zero can be `+0` or `-0`, which doubles the count, and the counting DP doubles it too.

There's also a direct DP over the running value, from −total to +total, with an offset so the indexes start at 0. It works, but it needs a table twice as wide and the offset arithmetic is easy to get wrong. The transformation is the version to know.

<Callout kind="gotcha" title="Swift gotcha: % keeps the sign">
In Swift, `-3 % 2` is `-1`, not `1`: the remainder takes the sign of the left-hand number. A parity test written as `(total + target) % 2 == 1` misses odd negative values. Write `% 2 != 0`, or rule out negative values first, as `signWays` does with `abs(target) > total`.
</Callout>

## Common mistakes

- **`ways[0] = 0`.** The empty subset counts. Start with 1.
- **Skipping zeros.** Each zero doubles the count. Let the loop run down to `s = 0`.
- **Forgetting the modulus until the end.** By then the program has already crashed on overflow. Reduce after every addition.
- **Missing the parity and range checks** in target sum, which leads to a negative or fractional `P`, and an out-of-range index.

## Practice

**Plus or minus to hit the target** uses everything here: the transformation to a subset count, zeros that double the answer, and a modulus because 200 numbers have 2²⁰⁰ sign patterns. Do the algebra on paper first, then check your parity and range tests against negative targets.
