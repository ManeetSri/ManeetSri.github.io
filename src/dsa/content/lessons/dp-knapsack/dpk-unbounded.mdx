## Why it matters

Some resources don't run out. A sawmill can cut as many 2-metre planks as the log allows. A cloud provider sells as many small instances as you like. A shop sells unlimited packs of each size. When every item can be taken **any number of times**, you have the **unbounded knapsack**. The DP barely changes: one loop flips direction. Understanding exactly why it flips is what lets you write either version without hesitating, and it sets up coin change in the next lesson.

## What changes when copies are unlimited

Go back to the 2D recurrence from [0/1 knapsack, from 2D to 1D](/dsa/learn/dpk-01). In the 0/1 version, taking item `i` leaves the **first `i - 1` items** for the rest of the room, because item `i` is used up:

```swift
best[i][w] = max(best[i - 1][w], best[i - 1][w - weight] + value)    // 0/1: take it, then it's gone
```

With unlimited copies, taking one copy of item `i` leaves the **first `i` items**, including item `i` itself, because more copies may follow:

```swift
best[i][w] = max(best[i - 1][w], best[i][w - weight] + value)        // unbounded: take one, more may follow
```

One index changes: the take option reads the **current** row instead of the row above. That's the only difference between the two problems.

## The loop flips

Now compress to one row, as before. The 0/1 take option needs `best[w - weight]` from the **old** row, so you went right to left to avoid overwriting it first. The unbounded take option needs `best[w - weight]` from the **new** row, the one that already includes this item. Going **left to right** gives exactly that: `w - weight` is to the left of `w`, so it has already been updated in this pass.

The left-to-right loop that was a bug in the 0/1 knapsack is the correct algorithm here. Same items, both directions:

```swift run
// The same items, packed two ways. Weights 3 and 4 with values 5 and 7, capacity 10.
let weights = [3, 4]
let values = [5, 7]
let capacity = 10

func pack(copiesAllowed: Bool) -> [Int] {
    var best = Array(repeating: 0, count: capacity + 1)
    for (weight, value) in zip(weights, values) {
        let rooms = copiesAllowed ? Array(stride(from: weight, through: capacity, by: 1))   // left to right
                                  : Array(stride(from: capacity, through: weight, by: -1))  // right to left
        for w in rooms {
            best[w] = max(best[w], best[w - weight] + value)
        }
    }
    return best
}

print("0/1:      ", pack(copiesAllowed: false))
print("unbounded:", pack(copiesAllowed: true))
```

```output
0/1:       [0, 0, 0, 5, 7, 7, 7, 12, 12, 12, 12]
unbounded: [0, 0, 0, 5, 7, 7, 10, 12, 14, 15, 17]
```

What to notice:

- Up to room 5 the rows agree: only one item fits at a time.
- Room 6 is where they split. 0/1 can't take two 3s, so it's stuck at 7. Unbounded takes 3 + 3 for 10.
- Room 10 unbounded is 3 + 3 + 4, worth 5 + 5 + 7 = 17. The 0/1 best is 3 + 4 = 12.

<Callout kind="tip" title="A rule you can check in your head">
**Right to left: each item once. Left to right: each item any number of times.** If you forget which is which, test with one item and a room that fits two copies. If the answer counts the item twice, you have the unbounded loop.
</Callout>

### Another way to write it

For the unbounded knapsack there's a second natural formulation. Ask "what's the **last** item I packed?" instead of "do I use item `i`?":

```swift
// best[w] = the most value from room w, with unlimited copies of everything
for w in stride(from: 1, through: capacity, by: 1) {
    for (weight, value) in zip(weights, values) where weight <= w {
        best[w] = max(best[w], best[w - weight] + value)    // pack this item last
    }
}
```

Room outer, items inner. Since every item can be packed again, `best[w - weight]` may contain anything, which is fine. For a **maximum** (or a minimum), both loop orders give the same answer: the best collection of items is the best collection whatever order you imagine packing it in. Hold on to that sentence, because for **counting** the two orders give different answers, and that's the trap in the next lesson.

## Rod cutting

Here's the classic unbounded knapsack in disguise. A rod of length `n` can be cut into pieces of whole lengths, and a piece of length `k` sells for `prices[k - 1]`. How should you cut it to earn the most?

Each piece length is an item: its weight is its length, its value is its price, and you can cut as many pieces of each length as fit. The rod's length is the capacity. Since every length from 1 up has a price, the rod is always fully used.

The DP reads naturally in the "last piece" form: `best[len]` is the most a rod of length `len` earns, and the first piece cut off has some length `piece`, leaving a rod of `len - piece` that you cut as well as possible. Record which piece won, and you can list the cuts afterwards:

```swift run
// prices[k - 1] is what a piece of length k sells for
let prices = [2, 5, 9, 11, 14, 17, 20, 22]
let rodLength = 8

var best = Array(repeating: 0, count: rodLength + 1)      // best[len]: the most a rod of length len earns
var firstPiece = Array(repeating: 0, count: rodLength + 1) // the piece cut first in that best plan
for len in 1...rodLength {
    for piece in 1...min(len, prices.count) where prices[piece - 1] + best[len - piece] > best[len] {
        best[len] = prices[piece - 1] + best[len - piece]   // sell one piece, cut the rest as well as possible
        firstPiece[len] = piece
    }
}
print("best:      ", best)
print("first cut: ", firstPiece)

var pieces: [Int] = []
var left = rodLength
while left > 0 {
    pieces.append(firstPiece[left])
    left -= firstPiece[left]
}
print("cut \(rodLength) into \(pieces) for \(best[rodLength])")
```

```output
best:       [0, 2, 5, 9, 11, 14, 18, 20, 23]
first cut:  [0, 1, 2, 3, 1, 2, 3, 1, 2]
cut 8 into [2, 3, 3] for 23
```

What to notice:

- Selling the whole rod of 8 earns 22, but cutting it into 2 + 3 + 3 earns 5 + 9 + 9 = 23. A length-3 piece is the best value per metre (3 each), and the leftover 2 is worth more as one piece (5) than as two 1s (4).
- `best[6] = 18` is two 3s. `best[8]` builds on it: a 2 first, then `best[6]`.
- Following `firstPiece` from 8 gives 2, then from 6 gives 3, then from 3 gives 3. That's reconstruction with a one-dimensional "choice" array, which works here because each state has only one predecessor to remember.
- The work is O(n²) for a rod of length n with a price for every length: n lengths, up to n pieces each. In general it's O(W · k) for capacity W and k item types.

<Callout kind="note" title="When some lengths can't be sold">
If only some piece lengths have buyers, start every `best[len]` at 0 and let unsold leftovers be waste: the "at most" knapsack. If the rod must be used up exactly, start with `best[0] = 0` and everything else impossible, as in the "exactly" note in the 0/1 lesson.
</Callout>

## The 0/1 and unbounded versions side by side

| | 0/1 knapsack | Unbounded knapsack |
| --- | --- | --- |
| Each item | at most once | any number of times |
| 2D take option | `best[i - 1][w - weight]` | `best[i][w - weight]` |
| One-row inner loop | right to left | left to right |
| Loop order (items, rooms) | items must be outer | either order, for a max or min |
| Examples | subset sum, partition, target sum | rod cutting, fewest coins |

<Callout kind="gotcha" title="Traps in the unbounded knapsack">
- **Writing the 0/1 loop out of habit.** Right to left forbids the second copy, and the answer comes out too small without any error.
- **An item with weight 0 and positive value.** With unlimited copies, the value is unbounded. Filter such items out, or treat the input as invalid.
- **`1...min(len, prices.count)`** is safe only because `len` is at least 1 there. If a range could start above its end, use `stride`, which is empty instead of crashing.
</Callout>
