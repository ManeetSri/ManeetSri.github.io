## Why it matters

You have a limited budget and a pile of things competing for it. Which features fit in a two-week sprint? Which images should an app bundle when the download must stay under 200 MB? Which jobs should a server run in the next hour of CPU time? Each thing either goes in whole or stays out, and you want the most value for the budget. That's the **0/1 knapsack**, and it's the parent of this whole module: subset sum, equal partition, target sum, coin change and the rest are knapsacks in disguise. Learn this one properly, including the one-row version and its loop direction, and the others become small variations.

## The problem

You have `n` items. Item `i` has a **weight** `weights[i]` and a **value** `values[i]`. Your bag holds a total weight of at most `capacity`. Choose items so their total weight fits and their total value is as large as possible. Each item can be taken **once or not at all**: that's what "0/1" means, a 0 or a 1 for each item.

This lesson uses four items and a capacity of 7:

| index | weight | value |
| --- | --- | --- |
| 0 | 1 | 1 |
| 1 | 3 | 4 |
| 2 | 4 | 5 |
| 3 | 5 | 7 |

In [When greedy fails](/dsa/learn/greedy-counterexamples) you saw that "best value per unit of weight first" can go wrong. It goes wrong here too: it takes item 3 (7 for 5, the best ratio), then only item 0 fits, for a total of 8. Items 1 and 2 together weigh exactly 7 and are worth 9. The fractional version, where you may take part of an item, is greedy ([Activity selection and fractional knapsack](/dsa/learn/greedy-activity-selection)). The 0/1 version needs something stronger.

## Brute force: every subset

Each item is in or out, so there are 2ⁿ choices. A bitmask lists them all, exactly as in [Bitmasks for subsets and submasks](/dsa/learn/bits-subsets):

```swift run
let weights = [1, 3, 4, 5]
let values = [1, 4, 5, 7]
let capacity = 7
let n = weights.count

var bestValue = 0
var bestMask = 0
for mask in 0..<(1 << n) {                          // every subset, as a bitmask
    var weight = 0
    var value = 0
    for i in 0..<n where mask & (1 << i) != 0 {
        weight += weights[i]
        value += values[i]
    }
    if weight <= capacity && value > bestValue {
        bestValue = value
        bestMask = mask
    }
}
print("subsets tried:", 1 << n)
print("best value:", bestValue)
print("items:", (0..<n).filter { bestMask & (1 << $0) != 0 })
```

```output
subsets tried: 16
best value: 9
items: [1, 2]
```

That's correct, and it's the referee you'll use in tests. But with 40 items it's a trillion subsets. Many of them share the same situation: "I've decided about the first few items, and I have 3 units of room left." Whatever got you there, the best way to finish is the same. Overlapping subproblems: time for DP.

## The recipe, applied

Use the five steps from [The DP recipe](/dsa/learn/dp-recipe):

- **State.** `best[i][w]` is the most value you can get using **only the first `i` items**, with room `w`.
- **Transition.** Look at item `i` (index `i - 1` in the arrays). Either you skip it, and the best is `best[i - 1][w]`; or it fits (`weights[i - 1] ≤ w`) and you take it, which leaves room `w - weights[i - 1]` for the first `i - 1` items: `best[i - 1][w - weights[i - 1]] + values[i - 1]`. Take the larger.
- **Base case.** With no items, the value is 0 for every room: `best[0][w] = 0`.
- **Order.** Row `i` only reads row `i - 1`, so fill the rows from top to bottom.
- **Answer.** `best[n][capacity]`.

The key point is in the take option: it reads the row **above**. Having taken item `i`, you only have the first `i - 1` items left to choose from. That's what stops an item being used twice.

```swift run
let weights = [1, 3, 4, 5]
let values = [1, 4, 5, 7]
let capacity = 7
let n = weights.count

// best[i][w]: the most value using only the first i items, with room w
var best = Array(repeating: Array(repeating: 0, count: capacity + 1), count: n + 1)
for i in 1...n {
    let weight = weights[i - 1]                     // item i lives at index i - 1
    let value = values[i - 1]
    for w in 0...capacity {
        best[i][w] = best[i - 1][w]                 // skip item i
        if weight <= w {                            // or take it, if it fits
            best[i][w] = max(best[i][w], best[i - 1][w - weight] + value)
        }
    }
}

print("room:    ", (0...capacity).map { String($0) }.joined(separator: "  "))
for i in 0...n {
    print("first \(i): ", best[i].map { String($0) }.joined(separator: "  "))
}
print("answer:", best[n][capacity])
```

```output
room:     0  1  2  3  4  5  6  7
first 0:  0  0  0  0  0  0  0  0
first 1:  0  1  1  1  1  1  1  1
first 2:  0  1  1  4  5  5  5  5
first 3:  0  1  1  4  5  6  6  9
first 4:  0  1  1  4  5  7  8  9
answer: 9
```

Step through the same table. The amber cell is being filled, and the blue cells are what it reads: the cell straight above (skip) and the cell above and to the left by the item's weight (take).

```visual dpTable
program: knapsack
input:
  weights: [1, 3, 4, 5]
  values: [1, 4, 5, 7]
  capacity: 7
```

What to notice:

- Every cell looks only at the row above. That's why the rows can be filled one at a time.
- Row 3, room 7 is where the answer appears: skip gives 5, take gives `best[2][3] + 5 = 4 + 5 = 9`.
- Row 4 adds item 3 (weight 5, value 7). It improves rooms 5 and 6, but not room 7: taking it there leaves room 2, worth only 1, and 7 + 1 = 8 is less than 9.
- Each row is never worse than the row above, and each row never decreases from left to right. More items or more room can't hurt.

## Which items? Walking back through the table

The table holds more than the answer. Start at the bottom-right cell. If `best[i][w]` equals the cell above it, item `i` wasn't needed: move up. If it's bigger, item `i` was taken: record it, subtract its weight from the room, and move up. This is the backtracking idea from [Reconstructing the answer, not just its value](/dsa/learn/dp-reconstruct).

```swift run
let weights = [1, 3, 4, 5]
let values = [1, 4, 5, 7]
let capacity = 7
let n = weights.count

var best = Array(repeating: Array(repeating: 0, count: capacity + 1), count: n + 1)
for i in 1...n {
    for w in 0...capacity {
        best[i][w] = best[i - 1][w]
        if weights[i - 1] <= w {
            best[i][w] = max(best[i][w], best[i - 1][w - weights[i - 1]] + values[i - 1])
        }
    }
}

// Walk back from the answer cell. If the row above has the same value, item i wasn't needed.
var chosen: [Int] = []
var w = capacity
for i in stride(from: n, through: 1, by: -1) {
    if best[i][w] == best[i - 1][w] {
        print("row \(i), room \(w): \(best[i][w]) is also above, so skip index \(i - 1)")
    } else {
        print("row \(i), room \(w): \(best[i][w]) beats \(best[i - 1][w]) above, so take index \(i - 1)")
        chosen.append(i - 1)
        w -= weights[i - 1]
    }
}
chosen.reverse()
print("indices:", chosen)
print("weight", chosen.map { weights[$0] }.reduce(0, +), "value", chosen.map { values[$0] }.reduce(0, +))
```

```output
row 4, room 7: 9 is also above, so skip index 3
row 3, room 7: 9 beats 5 above, so take index 2
row 2, room 3: 4 beats 1 above, so take index 1
row 1, room 0: 0 is also above, so skip index 0
indices: [1, 2]
weight 7 value 9
```

When skipping and taking give the same value, this walk prefers skipping. Either choice leads to a correct best answer; a problem that wants one particular answer among ties tells you which.

## What it costs

There are `(n + 1) × (capacity + 1)` cells and each takes O(1), so the time is **O(n · W)**, where W is the capacity, and the table takes O(n · W) memory too.

That looks polynomial, but look at what W is: a **number** in the input, not a count of things. Writing W down takes only a few digits, yet each extra digit makes the table ten times wider. An algorithm like this, polynomial in the numeric value rather than in the length of the input, is called **pseudo-polynomial**. In practice: 100 items with capacity 10⁵ is 10⁷ cells, which is instant. Capacity 10⁹ is hopeless, and you'd need a different idea (for example, swapping the roles of weight and value when values are small).

## From two rows to one

Row `i` reads only row `i - 1`. So, as [Saving space](/dsa/learn/dp-space) suggests, you could keep only two rows. You can go further: keep **one** row and overwrite it in place, item by item. After processing item `i`, `best[w]` holds what `best[i][w]` held.

There's one catch. When you update `best[w]`, the take option needs `best[w - weight]` from the **previous** row, meaning "without this item". If you've already overwritten `best[w - weight]` during this item's pass, you're reading "with this item", and the item gets used twice.

### The trace that shows the trap

Here's a single item, weight 2 and value 3, with capacity 6. It may be packed once, so the right answer for every room of at least 2 is 3. Watch what each direction does:

```swift run
// One item: weight 2, value 3. Capacity 6. It may be packed at most once.
let weight = 2
let value = 3
let capacity = 6

func pass(rightToLeft: Bool) {
    var best = Array(repeating: 0, count: capacity + 1)
    let rooms = rightToLeft ? Array(stride(from: capacity, through: weight, by: -1)) : Array(weight...capacity)
    for w in rooms {
        let candidate = best[w - weight] + value
        print("  best[\(w)] = max(\(best[w]), best[\(w - weight)] + \(value)) = \(max(best[w], candidate))")
        best[w] = max(best[w], candidate)
    }
    print("  row:", best)
}

print("left to right:")
pass(rightToLeft: false)
print("right to left:")
pass(rightToLeft: true)
```

```output
left to right:
  best[2] = max(0, best[0] + 3) = 3
  best[3] = max(0, best[1] + 3) = 3
  best[4] = max(0, best[2] + 3) = 6
  best[5] = max(0, best[3] + 3) = 6
  best[6] = max(0, best[4] + 3) = 9
  row: [0, 0, 3, 3, 6, 6, 9]
right to left:
  best[6] = max(0, best[4] + 3) = 3
  best[5] = max(0, best[3] + 3) = 3
  best[4] = max(0, best[2] + 3) = 3
  best[3] = max(0, best[1] + 3) = 3
  best[2] = max(0, best[0] + 3) = 3
  row: [0, 0, 3, 3, 3, 3, 3]
```

Left to right, `best[4]` reads `best[2]`, which was set to 3 a moment ago, **in this same pass**. So `best[4]` means "the item, plus the item again", and `best[6]` packs it three times. There's no crash and no warning. The code quietly solves a different problem, the **unbounded** knapsack, where every item has unlimited copies. (That's a real problem, and you'll use exactly this left-to-right loop for it in [Unbounded knapsack and rod cutting](/dsa/learn/dpk-unbounded).)

Right to left, `best[w - weight]` sits to the left of `w`, and nothing to the left has been touched yet in this pass. It still holds the previous row's value: "without this item". That's the 2D recurrence, exactly.

<Callout kind="analogy">
Think of rewriting a row of numbers on a whiteboard, where each new number is based on one further left. If you work left to right, you erase the old numbers before you've read them, and you end up building on your own new work. Work right to left and every number you read is still the old one.
</Callout>

### The one-row knapsack

```swift run
/// 0/1 knapsack in one row: O(n × capacity) time, O(capacity) memory
func knapsack(_ weights: [Int], _ values: [Int], _ capacity: Int) -> Int {
    var best = Array(repeating: 0, count: capacity + 1)   // best[w]: the most value with room w
    for (weight, value) in zip(weights, values) {
        // Right to left, so best[w - weight] still means "without this item"
        for w in stride(from: capacity, through: weight, by: -1) {
            best[w] = max(best[w], best[w - weight] + value)
        }
        print("after weight \(weight):", best)
    }
    return best[capacity]
}

print(knapsack([1, 3, 4, 5], [1, 4, 5, 7], 7))
print(knapsack([10], [99], 7))       // too heavy: the stride is empty, nothing breaks
```

```output
after weight 1: [0, 1, 1, 1, 1, 1, 1, 1]
after weight 3: [0, 1, 1, 4, 5, 5, 5, 5]
after weight 4: [0, 1, 1, 4, 5, 6, 6, 9]
after weight 5: [0, 1, 1, 4, 5, 7, 8, 9]
9
after weight 10: [0, 0, 0, 0, 0, 0, 0, 0]
0
```

After each item, the row matches the matching row of the 2D table. The loop also stops at `weight` instead of 0: rooms smaller than the item can't take it, so they keep their old value, which is what "skip" would give anyway.

The price of one row is the reconstruction. The walk-back needs to compare a row with the row above, and the one-row version has thrown those rows away. When you need the chosen items, keep the 2D table (or at least a 2D table of "taken" flags).

<Callout kind="gotcha" title="Swift gotcha: reversed ranges crash when the item doesn't fit">
`for w in (weight...capacity).reversed()` reads nicely, but if an item is heavier than the whole bag, `weight...capacity` is an invalid range and the program stops:

```text title="What you'll see"
Fatal error: Range requires lowerBound <= upperBound
```

`stride(from: capacity, through: weight, by: -1)` is empty in that case, and the loop does nothing. Use `stride`, or skip items with `weight > capacity` first.
</Callout>

## Common mistakes

- **Iterating left to right in the one-row version.** It turns 0/1 into unbounded, silently. Check with one item and a capacity that holds two copies of it.
- **Mixing up item numbers and indexes.** In the 2D table, row `i` is about the item at index `i - 1`. Name it once (`let weight = weights[i - 1]`) and use the name.
- **"At most" or "exactly"?** Starting the row at all zeros means "fits in at most w". If the bag must be filled **exactly**, start with `best[0] = 0` and every other room at "impossible" (a very negative number, or an optional), so that only real combinations build up from 0.
- **Expecting reconstruction from one row.** Keep the table if you need the items.
