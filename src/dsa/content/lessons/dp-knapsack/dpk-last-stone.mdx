## Why it matters

This is a famous interview question because it hides its knapsack well. The story is about smashing stones together, there's no capacity and no values, and the natural first idea (simulate it, perhaps greedily) goes nowhere. The trick is to notice that every smash is secretly a plus or minus sign, which turns the whole game into "split the stones into two piles as evenly as possible". Spotting that kind of reformulation is the skill this lesson trains, and the same move turns up in load balancing, splitting work between two people, and any "minimise the difference" puzzle.

## The game

You have a row of stones with positive weights. A turn is: pick **any two** stones and smash them together.

- If they weigh the same, both are destroyed.
- Otherwise the lighter one is destroyed, and the heavier one is left weighing the **difference**.

Keep going until at most one stone is left. What is the **smallest** weight it can have (0 if nothing is left)?

You may have met a cousin of this in the heaps module, [Smash the heaviest stones](/dsa/practice/smash-heaviest-stones), where each turn **must** smash the two heaviest. There the process is fixed and a heap simulates it. Here you choose the pairs, and the choice is everything.

## Every smash is a sign

Smash `a` and `b` with `a ≥ b`, and you get `a - b`. Smash that with `c` and you get `|a - b - c|` or `c - a + b`, depending on which is heavier. Keep going and a pattern appears: the final weight is always the original weights with a `+` or `-` in front of each, added up. A stone with `+` is in one pile, a stone with `-` in the other, and the final stone is the **difference between the two piles' totals**.

So every possible ending is some pile difference. Is every pile difference a possible ending? Try it on five stones, with brute force on both sides:

```swift run
/// Every final weight you can end with, by trying every order of smashes (fine for a handful of stones)
func allEndings(_ stones: [Int]) -> Set<Int> {
    if stones.count <= 1 { return [stones.first ?? 0] }
    var endings: Set<Int> = []
    for i in stones.indices {
        for j in stones.indices where j > i {
            var rest = stones
            rest.remove(at: j)                           // remove the later index first
            rest.remove(at: i)
            let leftover = abs(stones[i] - stones[j])
            endings.formUnion(allEndings(leftover > 0 ? rest + [leftover] : rest))
        }
    }
    return endings
}

let stones = [8, 3, 12, 5, 9]
print("every possible ending:", allEndings(stones).sorted())

// Every split into two piles, as a bitmask: bit i set puts stone i in the first pile
let total = stones.reduce(0, +)
var differences: Set<Int> = []
for mask in 0..<(1 << stones.count) {
    let first = stones.indices.filter { mask & (1 << $0) != 0 }.map { stones[$0] }.reduce(0, +)
    differences.insert(abs(total - 2 * first))
}
print("every pile difference:", differences.sorted())
```

```output
every possible ending: [3, 5, 7, 9, 11]
every pile difference: [3, 5, 7, 9, 11, 13, 15, 19, 21, 27, 31, 37]
```

Not every difference is reachable: you can't end with 37, "all stones in one pile", because smashing always subtracts something. But the **smallest** values agree, and the smallest is all the question asks for. Both lists start at 3.

## Why the smallest difference is always reachable

Take the split with the smallest difference, here \{12, 5\} (17) and \{8, 3, 9\} (20). Now play the game like this: smash one stone from each pile, and put whatever is left back on the pile of the heavier stone.

```swift run
// Two piles from the DP: 12 + 5 = 17 and 8 + 3 + 9 = 20. Smash one stone from each pile at a time,
// and put whatever is left back on the pile of the heavier stone.
var heavier = [8, 3, 9]
var lighter = [12, 5]
while !heavier.isEmpty && !lighter.isEmpty {
    let a = heavier.removeLast()
    let b = lighter.removeLast()
    if a > b {
        heavier.append(a - b)
    } else if b > a {
        lighter.append(b - a)
    }
    let gap = heavier.reduce(0, +) - lighter.reduce(0, +)
    print("smash \(a) and \(b): piles \(heavier) and \(lighter), gap \(gap)")
}
```

```output
smash 9 and 5: piles [8, 3, 4] and [12], gap 3
smash 4 and 12: piles [8, 3] and [8], gap 3
smash 3 and 8: piles [8] and [5], gap 3
smash 8 and 5: piles [3] and [], gap 3
```

The gap never changes. Smashing `a` against `b` takes the smaller of the two away from **both** piles, so the difference between them stays the same. When one pile runs out, the other holds stones adding up to the gap. If it holds a single stone, you're done. If it holds several, smashing them together can only lower the total, yet every ending is a pile difference and none is below the minimum. Either way, you finish at exactly the smallest difference.

## The knapsack inside

So the question is now: split the stones into two piles to make `|pileA - pileB|` as small as possible. With `S` the total and `P` the lighter pile's total, the difference is `S - 2P`. To make it small, make `P` as **large** as possible while keeping `P ≤ S / 2`.

That's subset sum from [Subset sum and equal partition](/dsa/learn/dpk-subset-sum): find every reachable sum up to `S / 2`, and take the largest one.

```swift run
/// The lightest stone that can be left: the total minus twice the heaviest pile that's at most half
func smallestLeftover(_ stones: [Int]) -> Int {
    let total = stones.reduce(0, +)
    let half = total / 2
    var reachable = Array(repeating: false, count: half + 1)
    reachable[0] = true
    for stone in stones where stone <= half {
        for s in stride(from: half, through: stone, by: -1) where reachable[s - stone] {
            reachable[s] = true
        }
    }
    let lighterPile = (0...half).last { reachable[$0] }!     // reachable[0] is true, so there is one
    return total - 2 * lighterPile
}

print(smallestLeftover([8, 3, 12, 5, 9]))
print(smallestLeftover([6, 2, 9, 4, 3]))
print(smallestLeftover([1, 2, 4, 8, 16]))
print(smallestLeftover([7]))
```

```output
3
0
1
7
```

What to notice:

- \{8, 3, 12, 5, 9\} totals 37, so half is 18. No subset makes 18, but 12 + 5 makes 17, so the lighter pile is 17 and the answer is 37 − 34 = 3.
- \{6, 2, 9, 4, 3\} totals 24, and 6 + 2 + 4 = 12, so the piles balance perfectly.
- \{1, 2, 4, 8, 16\}: the 16 alone outweighs the rest (15), so the best is 16 against 15.
- A stone heavier than half can never be in the lighter pile, so the loop skips it. It goes in the heavier pile automatically.
- Time O(n · S), memory O(S). With 30 stones of weight up to 100, that's a row of about 1,500 cells. Brute force over all 2³⁰ splits would be a billion.

## Saying it in an interview

The jump from "smashing" to "two piles" is the whole problem, so say it out loud:

1. **Model.** "Each stone ends up added or subtracted, so the final weight is the difference between two piles."
2. **Check the claim.** "The smallest difference is reachable: smash across the piles and the gap stays fixed." A sentence is enough; offer the details if asked.
3. **Reduce.** "Minimise `S - 2P` with `P ≤ S / 2`: the largest reachable subset sum up to half. That's 0/1 subset sum."
4. **Code it** with one Boolean row, right to left.
5. **Complexity.** O(n · S) time, O(S) space.

The same family shares this shape: equal partition asks whether the difference can be 0, target sum counts the sign patterns that give one particular difference, and this problem minimises it.

<Callout kind="gotcha" title="Common slips">
- **Returning the pile instead of the difference.** The answer is `total - 2 * lighterPile`, not `lighterPile`.
- **Simulating greedily.** Always smashing the two heaviest is a different game. On \{2, 2, 2, 3, 3\} it smashes the 3s, then two 2s, and leaves a 2. Piles \{3, 3\} and \{2, 2, 2\} show that 0 was possible.
- **Looping upwards** in the subset sum, which reuses a stone.
- **Searching above half.** Sums above `S / 2` give the same differences as their complements below it, so they add nothing.
</Callout>
