## Why it matters

Can these video files fill a 4,700 MB disc exactly? Can six friends' restaurant bills be split into two payments of the same size? Can a batch of jobs be shared between two identical servers so they finish together? Each asks whether some of the numbers add up to a target. That's **subset sum**, the knapsack with the values taken away: you no longer care how much something is worth, only whether a total can be reached at all. Its most famous form, splitting numbers into two equal halves, is an interview favourite.

## From knapsack to yes or no

Take the one-row knapsack from [0/1 knapsack, from 2D to 1D](/dsa/learn/dpk-01) and change what a cell holds:

- **State.** `reachable[s]` is `true` when some of the numbers seen so far, each used at most once, add up to exactly `s`.
- **Transition.** For a new number `x`, the sum `s` becomes reachable if it already was (leave `x` out), or if `s - x` was reachable (put `x` in): `reachable[s] = reachable[s] || reachable[s - x]`.
- **Base case.** `reachable[0] = true`: the empty subset adds up to 0. Every other sum starts `false`.
- **Order.** One number at a time, and within each number, sums from high to low, so that `reachable[s - x]` still means "without `x`". It's the same right-to-left rule, for the same reason.
- **Answer.** `reachable[target]`.

Here are the sums reachable from 3, 5, 9 and 4, growing one number at a time:

```swift run
/// reachable[s] is true when some of `numbers`, each used at most once, add up to exactly s
func reachableSums(_ numbers: [Int], upTo limit: Int) -> [Bool] {
    var reachable = Array(repeating: false, count: limit + 1)
    reachable[0] = true                                  // the empty subset makes 0
    for x in numbers {
        // Right to left, so reachable[s - x] still means "without x"
        for s in stride(from: limit, through: x, by: -1) where reachable[s - x] {
            reachable[s] = true
        }
        print("after \(x):", (0...limit).filter { reachable[$0] })
    }
    return reachable
}

let reachable = reachableSums([3, 5, 9, 4], upTo: 13)
print("12?", reachable[12], " 11?", reachable[11])
```

```output
after 3: [0, 3]
after 5: [0, 3, 5, 8]
after 9: [0, 3, 5, 8, 9, 12]
after 4: [0, 3, 4, 5, 7, 8, 9, 12, 13]
12? true  11? false
```

What to notice:

- Each number adds a shifted copy of the current set: after 5, the new sums are the old ones plus 5 (0 + 5 and 3 + 5).
- 14, 17 and 21 are reachable too, but the array stops at the limit. Sums above the target never help you reach the target, since every number is positive, so there's no need to store them.
- The work is O(n · T) for n numbers and target T, and the memory is O(T).

## Equal partition: the sum/2 trick

Now the interview version: can the numbers be split into **two groups with equal sums**? Every number must go in one group or the other.

It sounds like a two-sided problem, but it isn't. If the total is `S`, each group must add up to `S / 2`. Find one subset that adds up to `S / 2` and you're done: the numbers you didn't pick add up to `S - S / 2 = S / 2` automatically. So equal partition is subset sum with target `S / 2`.

Two quick checks come first:

- If `S` is **odd**, no split exists. Return `false` without any DP.
- If one number is **bigger than `S / 2`**, its group already outweighs everything else. Return `false`.

```swift run
/// Can `numbers` (all positive) be split into two groups with equal sums?
func canSplitEvenly(_ numbers: [Int]) -> Bool {
    let total = numbers.reduce(0, +)
    if total % 2 != 0 { return false }                   // an odd total can't be halved
    let half = total / 2
    if numbers.contains(where: { $0 > half }) { return false }   // one number outweighs the rest
    var reachable = Array(repeating: false, count: half + 1)
    reachable[0] = true
    for x in numbers {
        for s in stride(from: half, through: x, by: -1) where reachable[s - x] {
            reachable[s] = true
        }
        if reachable[half] { return true }               // one group found; the rest is the other
    }
    return false
}

print(canSplitEvenly([4, 7, 2, 5, 6]))      // total 24: 4 + 2 + 6 = 12 = 7 + 5
print(canSplitEvenly([3, 5, 9, 4, 1]))      // total 22, but nothing makes 11
print(canSplitEvenly([2, 3, 4]))            // total 9 is odd
print(canSplitEvenly([1, 2, 9]))            // 9 is more than half of 12
```

```output
true
false
false
false
```

The early `return true` inside the loop is a small bonus: once half is reachable, later numbers can't make it unreachable again.

<Callout kind="note" title="Which numbers go in each group?">
The yes/no answer doesn't say. To list a group, keep the 2D table and walk back as in [0/1 knapsack, from 2D to 1D](/dsa/learn/dpk-01). A lighter trick also works with one row: store, for each sum, the index of the number that first made it reachable. Walking back from `S / 2` and subtracting those numbers visits strictly earlier indexes each step, so no number is used twice.
</Callout>

## Aside: 64 sums at a time with a bitset

Look again at what one number does to the reachable set: every reachable `s` makes `s + x` reachable. If the set is stored as **bits**, with bit `s` set when `s` is reachable, that's a single operation: `bits = bits | (bits << x)`. Shift the whole set up by `x`, then combine it with the old one.

For sums above 63 you need several `UInt64` words, like the bitset from [Gray code and UInt64 bitsets](/dsa/learn/bits-gray-code-bitsets). Shifting across words means each word takes bits from the word `x / 64` below it, plus a few carried bits from the word under that. Working from the top word down keeps it in place, for the same reason as right to left.

```swift run
/// Reachable subset sums as bits: bit s is 1 when some subset adds up to s
struct SumBits {
    var words: [UInt64]

    init(limit: Int) {
        words = Array(repeating: 0, count: limit / 64 + 1)
        words[0] = 1                                     // only sum 0 to begin with
    }

    func contains(_ s: Int) -> Bool {
        (words[s >> 6] >> UInt64(s & 63)) & 1 == 1
    }

    /// Adds x to every reachable sum at once: bits = bits | (bits << x), one word at a time
    mutating func add(_ x: Int) {
        let wordShift = x >> 6
        let bitShift = UInt64(x & 63)
        for i in stride(from: words.count - 1, through: wordShift, by: -1) {   // top down, like right to left
            var shifted = words[i - wordShift] << bitShift
            if bitShift > 0 && i - wordShift > 0 {
                shifted |= words[i - wordShift - 1] >> (64 - bitShift)          // bits carried from the word below
            }
            words[i] |= shifted
        }
    }
}

var small = SumBits(limit: 13)
for x in [3, 5, 9, 4] {
    small.add(x)
}
print((0...13).filter { small.contains($0) })

// A bigger split: 200 numbers from 1 to 300, compared with the Bool array
let numbers = (1...200).map { ($0 * 7_919) % 300 + 1 }
let half = numbers.reduce(0, +) / 2
var bits = SumBits(limit: half)
var reachable = Array(repeating: false, count: half + 1)
reachable[0] = true
for x in numbers {
    bits.add(x)
    for s in stride(from: half, through: x, by: -1) where reachable[s - x] {
        reachable[s] = true
    }
}
print("total \(numbers.reduce(0, +)), half \(half): bits say \(bits.contains(half)), Bools say \(reachable[half])")
print("cells updated per number: \(half + 1) Bools or \(bits.words.count) words")
```

```output
[0, 3, 4, 5, 7, 8, 9, 12, 13]
total 30500, half 15250: bits say true, Bools say true
cells updated per number: 15251 Bools or 239 words
```

Same answers, with about 64 times fewer updates: O(n · T / 64). It's still O(n · T) on paper, but a factor of 64 is the difference between a second and a sixtieth of a second. Competitive programmers use this constantly; in C++ it's one line with `std::bitset`. For interviews, the Bool array is what's expected, and mentioning the bitset is a nice extra.

<Callout kind="gotcha" title="Traps in subset sum">
- **Looping upwards.** `for s in stride(from: x, through: half, by: 1)` lets one number count twice: with only the number 3, it would mark 3, then 6, then 9 as reachable.
- **Forgetting `reachable[0] = true`.** Without it nothing is ever reachable.
- **Negative numbers.** An index can't be negative. Shift every sum by an offset (the total of the negatives), or rethink the problem; the problems in this module use non-negative numbers.
- **Odd totals.** `total / 2` rounds down in Swift, so with total 9 you'd look for 4 and might wrongly say yes. Check `total % 2 != 0` first.
</Callout>

## Practice

**Split into two equal-sum halves** is the partition check, with inputs big enough that brute force over subsets won't finish. Try the early exits, then the DP.

```cards
- id: partition-half
  front: "How does equal partition become subset sum?"
  back: "If the total S is even, look for a subset adding up to S / 2. The numbers left over add up to S / 2 as well. An odd total means no split."

  front: "How does a bitset speed up subset sum?"
  back: "Store reachable sums as bits; adding a number x is `bits |= bits << x`, which updates 64 sums per word, for O(n · T / 64)."
```
