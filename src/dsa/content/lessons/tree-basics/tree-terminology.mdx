## Why it matters

Arrays, linked lists, stacks and queues all keep things in a line. A lot of real data isn't a line. Folders contain folders. A screen's views contain views. A company has managers with teams who have teams. Those are **trees**, and so are the data structures in the rest of Part V: binary search trees, heaps and tries. You've already drawn one, too: the recursion trees in [Recursion trees and their complexity](/dsa/learn/rec-recursion-trees). Before you can write tree code, you need the words people use to talk about trees, used precisely.

## What a tree is

A tree is a set of **nodes** joined by **edges**, with three rules:

- One node is the **root**, at the top.
- Every other node has exactly one node directly above it.
- Following those links upwards from any node always ends at the root. There are no loops.

Here's the tree this module and the next use as a running example. Each circle is a node holding a number, and each line is an edge:

```text
        1
       / \
      2   3
     / \   \
    4   5   6
       /
      7
```

Computer scientists draw trees upside down: the root at the top and the branches growing downwards. Every node except the root has one edge going up, so a tree with n nodes always has exactly n − 1 edges. This one has 7 nodes and 6 edges.

<Callout kind="analogy">
A family tree, drawn from one ancestor downwards, is a good picture. The vocabulary comes straight from it: parent, child, sibling, ancestor, descendant. The one difference is that in a tree, everyone has exactly one parent.
</Callout>

## Family words

| Term | Meaning | In the example |
| --- | --- | --- |
| **root** | the one node with no parent | 1 |
| **parent** | the node directly above | 2 is the parent of 4 and 5 |
| **child** | a node directly below | 4 and 5 are the children of 2 |
| **siblings** | nodes with the same parent | 4 and 5; also 2 and 3 |
| **leaf** | a node with no children | 4, 7 and 6 |
| **internal node** | a node with at least one child | 1, 2, 3 and 5 |
| **ancestor** | a node on the path up to the root | 5, 2 and 1 are the ancestors of 7 |
| **descendant** | a node somewhere below | 4, 5 and 7 are the descendants of 2 |
| **subtree** | a node together with all its descendants | the subtree rooted at 2 is 2, 4, 5 and 7 |
| **path** | a chain of edges between two nodes | 4 → 2 → 5 → 7 has 3 edges |

Two of these trip people up. A **leaf** has no children at all: 5 is on the bottom row of 2's family, but it has a child, 7, so it isn't a leaf. And a root with no children is both the root and a leaf.

The **subtree** idea is the most important one in this module. Pick any node and ignore everything above it: what's left is a tree in its own right, with that node as its root. The subtree rooted at 2 looks like this:

```text
      2
     / \
    4   5
       /
      7
```

So every tree is a root with smaller trees hanging off it. That's why trees and recursion fit together so well.

## Depth, levels and height

Three measurements describe where a node sits and how tall a tree is.

**Depth** is how far a node is below the root, counted in edges. The root has depth 0, its children depth 1, their children depth 2. Nodes with the same depth form a **level**. In the example, level 0 is 1; level 1 is 2 and 3; level 2 is 4, 5 and 6; level 3 is 7.

**Height** measures from the other end. In this course, the height of a tree is the **number of levels** it has. The example has levels 0 to 3, so its height is 4. A single node has height 1, and the empty tree has height 0. DSAKit's `TreeNode.height` counts the same way.

The height of a node is the height of its subtree: 4 levels for 1, 3 for 2, 2 for 5, 1 for each leaf.

| Node | Depth (edges from the root) | Height (levels in its subtree) |
| --- | --- | --- |
| 1 | 0 | 4 |
| 2 | 1 | 3 |
| 3 | 1 | 2 |
| 5 | 2 | 2 |
| 4, 6 | 2 | 1 |
| 7 | 3 | 1 |

Because depth starts at 0 and height counts levels, a tree's height is always its greatest depth plus one: here, 3 + 1 = 4.

<Callout kind="note" title="The other convention">
Many textbooks measure height in **edges** instead: the number of edges on the longest path from the node down to a leaf. Then a single node has height 0, the empty tree −1, and the example tree 3. Neither is wrong, but mixing them causes off-by-one bugs. When a problem says "the maximum depth of a tree", it almost always means the number of nodes on the longest path from the root down, which is this course's height. Check the examples whenever you're unsure.
</Callout>

## Binary and N-ary trees

The **degree** of a node is how many children it has. When every node has at most two children, the tree is a **binary tree**, and the two children have names: the **left child** and the **right child**. The running example is a binary tree.

Left and right are positions, not mere labels. A node with one child has either a left child or a right child, and those are different trees:

```text
    1          1
   /            \
  2              2
```

When a node can have any number of children, the tree is an **N-ary tree**. A folder can hold any number of subfolders, so a file system is an N-ary tree. You'll meet them in [N-ary trees](/dsa/learn/tree-nary). Most of Part V is about binary trees.

## Trees are recursive

Here's a definition of a binary tree that uses itself:

> A binary tree is either **empty**, or a **root** node with a **left** binary tree and a **right** binary tree.

That definition is the recipe for almost every tree function you'll write. Handle the empty tree, which is the base case. Otherwise, ask the same question of the left and right subtrees and combine their answers with the root. It's the same three-part recipe as in [Indirect enums for recursive data](/dsa/learn/swift-indirect-enums).

Here's the running example built from a small `TreeNode` class (the next lessons explain it fully), with three measurements written that way:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

// The number of nodes: the root, plus everything in each subtree
func size(_ node: TreeNode?) -> Int {
    guard let node else { return 0 }
    return 1 + size(node.left) + size(node.right)
}

// The number of levels: the root's level, plus the taller subtree
func height(_ node: TreeNode?) -> Int {
    guard let node else { return 0 }
    return 1 + max(height(node.left), height(node.right))
}

// A leaf counts 1; anything else adds up its subtrees
func leaves(_ node: TreeNode?) -> Int {
    guard let node else { return 0 }
    if node.left == nil && node.right == nil { return 1 }
    return leaves(node.left) + leaves(node.right)
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))

print("size \(size(root)), height \(height(root)), leaves \(leaves(root))")
print("subtree at 2: size \(size(root.left)), height \(height(root.left))")
print("empty tree: size \(size(nil)), height \(height(nil))")
```

```output
size 7, height 4, leaves 3
subtree at 2: size 4, height 3
empty tree: size 0, height 0
```

What to notice:

- Each function starts with the empty tree, `nil`, and returns its answer for it. Every recursive call eventually reaches a `nil` child, so that's where each recursion stops.
- `root.left` is itself a tree, so the same functions measure the subtree rooted at 2 with no changes.
- The empty tree has height 0 in this convention, and a leaf has height 1 + max(0, 0) = 1.

## Depth travels down, height comes up

Depth and height are worked out in opposite directions. A node's depth depends on what's **above** it, so you pass it down: each child is one deeper than its parent. A node's height depends on what's **below** it, so it comes back up from the children as a return value. This version prints every node's depth by handing `depth + 1` to each child:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func printDepths(_ node: TreeNode?, depth: Int) {
    guard let node else { return }
    let kind = node.left == nil && node.right == nil ? "leaf" : "internal"
    print(String(repeating: "  ", count: depth) + "\(node.value): depth \(depth), \(kind)")
    printDepths(node.left, depth: depth + 1)
    printDepths(node.right, depth: depth + 1)
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
printDepths(root, depth: 0)
```

```output
1: depth 0, internal
  2: depth 1, internal
    4: depth 2, leaf
    5: depth 2, internal
      7: depth 3, leaf
  3: depth 1, internal
    6: depth 2, leaf
```

The indentation is the depth, which makes the shape easy to see. You'll use both directions constantly: information passed down as parameters, and answers returned up from the subtrees.

<Callout kind="gotcha" title="Common mistakes">
- **Mixing conventions.** Decide whether height counts levels or edges before you write the base case. Here, the empty tree is 0 and a leaf is 1. In the edges convention, a leaf is 0 and the empty tree is −1.
- **Calling a node with one child a leaf.** A leaf has *no* children. Test `node.left == nil && node.right == nil`, not `||`.
- **Forgetting the empty tree.** `nil` is a valid tree: zero nodes, zero leaves, height 0. Every function should handle it, and most handle it first.
</Callout>

## Practice

**Tree census** asks for a tree's size, its number of leaves and the depth of a given value: the vocabulary of this lesson turned into three short recursions.

```cards
- id: tree-leaf
  front: "What is a leaf in a tree?"
  back: "A node with no children at all. A node with one child is not a leaf, and a root with no children is both the root and a leaf."
- id: tree-depth-height
  front: "In this course, what are a node's depth and a tree's height?"
  back: "Depth is the number of edges from the root (the root has depth 0). Height is the number of levels (a single node has height 1, the empty tree 0), as DSAKit's `TreeNode.height` counts."
- id: tree-subtree
  front: "Why does recursion fit trees so naturally?"
  back: "Any node with its descendants is a tree in its own right. So a tree is empty, or a root with a left subtree and a right subtree, and a function can ask the same question of each subtree."
- id: tree-edges
  front: "How many edges does a tree with n nodes have?"
  back: "n − 1: every node except the root has exactly one edge going up to its parent."
```
