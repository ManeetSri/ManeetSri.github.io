## Why it matters

When a tree algorithm goes wrong, the first thing you want is to **see the tree**. But `print(root)` on a plain class shows only its type name, something like `main.TreeNode`, which tells you nothing. A few lines of code that print a tree's shape will save you more debugging time than anything else in this part. This lesson builds three: level by level, sideways with indentation, and sideways with connecting lines, which is what DSAKit's `diagram` draws.

## Level by level

The simplest picture prints each level on its own line. Keep the current level's nodes in an array; the next level is all of their children, left to right:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func printLevels(_ root: TreeNode?) {
    var level = [root].compactMap { $0 }
    while !level.isEmpty {
        print(level.map { String($0.value) }.joined(separator: " "))
        level = level.flatMap { [$0.left, $0.right].compactMap { $0 } }
    }
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
printLevels(root)
```

```output
1
2 3
4 5 6
7
```

This shows the depth of every node, but not who belongs to whom: from the output alone, 7 could be the child of 4, 5 or 6. `[root].compactMap { $0 }` turns an optional root into an array of zero or one nodes, so the empty tree prints nothing. You'll study this level-by-level walk properly in [Level-order traversal with a queue](/dsa/learn/trav-level-order).

## Sideways, with indentation

To show the parent links too, draw the tree **on its side**, with the root on the left. Print the right subtree first, then the node, then the left subtree, and indent each node by its depth. Tilt your head to the left and the tree is the usual way up:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func printSideways(_ node: TreeNode?, depth: Int = 0) {
    guard let node else { return }
    printSideways(node.right, depth: depth + 1)       // the right subtree goes above
    print(String(repeating: "    ", count: depth) + String(node.value))
    printSideways(node.left, depth: depth + 1)        // the left subtree goes below
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
printSideways(root)
```

```output
        6
    3
1
        5
            7
    2
        4
```

What to notice:

- Each node's children sit one indent further right, one above it (the right child) and one below (the left child). 7 is clearly under 5, not under 4.
- The order of the lines is right subtree, node, left subtree: inorder, backwards. You'll meet inorder properly in [Preorder, inorder and postorder](/dsa/learn/trav-dfs-recursive).
- It works for any value width, because indentation only depends on depth. A wide tree gets taller on the page, not wider, so it never wraps.

## Sideways, with connectors

Indentation alone can be hard to follow when the tree is big. Adding lines that join each node to its parent makes it easy to read. Each line gets a **prefix** made of `│` (a branch passing through) and spaces, then a connector: `┌──` for a right child, which is above its parent, and `└──` for a left child, below its parent.

The trick is deciding when a column needs a `│`. A right child is above its parent, so the lines between it and its parent are its **left** subtree: those need the bar. A left child is below its parent, so its **right** subtree needs the bar. Each call passes down two extra prefixes, one for the subtree above and one for the subtree below:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func draw(_ node: TreeNode, prefix: String = "", connector: String = "",
          above: String = "", below: String = "") {
    if let right = node.right {
        draw(right, prefix: prefix + above, connector: "┌── ", above: "    ", below: "│   ")
    }
    print(prefix + connector + String(node.value))
    if let left = node.left {
        draw(left, prefix: prefix + below, connector: "└── ", above: "│   ", below: "    ")
    }
}

let root = TreeNode(1,
                    left: TreeNode(2, left: TreeNode(4), right: TreeNode(5, left: TreeNode(7))),
                    right: TreeNode(3, right: TreeNode(6)))
draw(root)
print()
draw(TreeNode(100, left: TreeNode(7), right: TreeNode(2500, left: TreeNode(3), right: TreeNode(41))))
```

```output
    ┌── 6
┌── 3
1
│   ┌── 5
│   │   └── 7
└── 2
    └── 4

    ┌── 41
┌── 2500
│   └── 3
100
└── 7
```

Follow the bar in the first column: it runs from `1` down to `└── 2`, joining the root to its left child, past 2's right subtree (5 and 7) in between. Each connector starts directly under or over the first character of its parent's value, so values of any width line up, as the second tree shows.

## DSAKit's diagram

DSAKit's `TreeNode` has this drawing built in as the `diagram` property. It's written with a loop and an explicit stack instead of recursion, so it can't overflow the stack on a deep tree:

```swift
import DSAKit

let root = TreeNode.make([1, 2, 3, 4, 5, nil, 6, nil, nil, 7])!
print(root.diagram)       // the same drawing as above
print(root)               // [1, 2, 3, 4, 5, nil, 6, nil, nil, 7]
```

`print(root)` gives the level-order array instead, because `TreeNode` conforms to `CustomStringConvertible`, from [Equatable, Comparable and CustomStringConvertible](/dsa/learn/swift-standard-protocols). Its `description` is what `print` uses. Use the array when you want to paste a tree into a test, and the diagram when you want to see it.

Both work in the debugger, too. Stopped at a breakpoint, as in [Debugging with breakpoints and LLDB](/dsa/learn/swift-lldb), `po root` shows the description, and `expression print(root.diagram)` draws the tree in the console.

<Callout kind="tip" title="A debugging habit">
When a tree test fails, print the input with `diagram`, work out the answer by hand from the drawing, and only then look at what your code returned. Most tree bugs are obvious once the picture is in front of you: a child on the wrong side, a level skipped, a leaf counted twice.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **Printing a huge tree.** A sideways drawing has one line per node, and its lines get wider with depth. A 100,000-node tree prints 100,000 lines; a 100,000-level chain makes lines 400,000 characters wide. For big trees, print `count`, `height` or the first few levels instead.
- **Swapping the halves.** Print right, node, left for a drawing that reads correctly when tilted to the left. Printing left first mirrors the tree.
- **Recursion on deep trees.** The recursive printers here are fine for trees you can read. DSAKit's `diagram` uses a loop, so even a deep tree can't crash it.
</Callout>
