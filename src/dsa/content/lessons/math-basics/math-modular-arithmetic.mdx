## Why it matters

Sooner or later a problem will say "the answer may be very large, so return it modulo 1,000,000,007". Counting paths, arrangements or subsets produces numbers with hundreds of digits, and no `Int` can hold them. **Modular arithmetic** lets you compute the *remainder* of that huge answer without ever building the huge number. The same ideas run hash functions, circular buffers, checksums like the last digit of an ISBN, and the cryptography that secures your network calls.

## Arithmetic on a clock

You already do modular arithmetic when you read a clock. It's 10 o'clock; what time is it 5 hours later? Not 15, but 3. A 12-hour clock throws away whole multiples of 12 and keeps the remainder:

```swift run
print((10 + 5) % 12)
print(17 % 12, 5 % 12)
```

```output
3
5 5
```

**a mod m** means the remainder when a is divided by m, a number from 0 to m − 1. The number m is the **modulus**. In Swift it's `a % m`, as long as a isn't negative (more on that soon).

17 and 5 leave the same remainder when divided by 12. Mathematicians write this as 17 ≡ 5 (mod 12), read "17 is congruent to 5 modulo 12". Another way to say it: m divides the difference, since 17 − 5 = 12. On the clock, 17 and 5 are the same position.

## The three rules

Here's the fact that makes everything work. To find the remainder of a sum, difference or product, you can **reduce the inputs first**:

```text
(a + b) mod m  =  ((a mod m) + (b mod m)) mod m
(a − b) mod m  =  ((a mod m) − (b mod m)) mod m
(a × b) mod m  =  ((a mod m) × (b mod m)) mod m
```

Try it with a = 17, b = 25 and m = 12. Reduced, a is 5 and b is 1:

```swift run
let a = 17, b = 25, m = 12
print((a + b) % m, ((a % m) + (b % m)) % m)
print((a * b) % m, ((a % m) * (b % m)) % m)
```

```output
6 6
5 5
```

42 mod 12 is 6, and so is (5 + 1) mod 12. 425 mod 12 is 5, and so is (5 × 1) mod 12.

**Why it works.** Write a = 12q + 5 and b = 12r + 1, where q and r are whole numbers. Multiply them out:

```text
a × b = 144qr + 12q + 60r + 5  =  12 × (12qr + q + 5r) + 5
```

Everything except the 5 × 1 is a multiple of 12, and multiples of 12 vanish when you take the remainder. The same happens with addition and subtraction.

## Reduce after every step

The rules mean you can take `% m` after **every** operation, and every value stays below m. The final remainder comes out the same as if you'd computed the giant number and reduced it once at the end.

25! is about 1.55 × 10²⁵, far too big for an `Int`. Its remainder modulo 1,000,000,007 is easy:

```swift run
let mod = 1_000_000_007
var factorial = 1
for i in 1...25 {
    factorial = factorial * i % mod
}
print(factorial)
```

```output
440732388
```

`*` and `%` have the same precedence and work left to right, so `factorial * i % mod` means `(factorial * i) % mod`. Since `factorial` is always below the modulus and `i` is at most 25, the product never comes close to overflowing.

Another handy view: modulo a power of 10 keeps the last digits. 2¹⁰⁰ has 31 digits, but its last three are easy to find:

```swift run
var power = 1
for _ in 1...100 {
    power = power * 2 % 1000
}
print(power)
```

```output
376
```

## Why 1,000,000,007?

Problem setters love the modulus 10⁹ + 7, and it's worth knowing why:

- **It's prime.** That makes division possible in modular arithmetic, using a "modular inverse", which you'll learn in M66. It also spreads values evenly in hashing.
- **Reduced values fit in 32 bits.** Every remainder is below 2³⁰.
- **Products of two reduced values fit in an `Int`.** Each is below 10⁹ + 7, so the product is below about 10¹⁸, comfortably under `Int.max`, which is about 9.2 × 10¹⁸. One multiplication, then `%`, is always safe.

You'll also see 998,244,353, another prime a little under 10⁹, chosen for reasons that matter in M66.

## Negative numbers

Subtraction can make a value negative, and Swift's `%` keeps the sign of the left-hand number, as you saw in [Arithmetic, integer division and remainder](/dsa/learn/swift-arithmetic). That gives a remainder outside the range 0 to m − 1:

```swift run
let m = 12
let a = 3, b = 10
print((a - b) % m)
print((a - b + m) % m)
print(((-7 % 5) + 5) % 5)
```

```output
-7
5
3
```

Two standard fixes:

- When a and b are **already reduced** (both from 0 to m − 1), a − b is more than −m, so adding m once is enough: `(a - b + m) % m`.
- For **any** integer x, `((x % m) + m) % m` always lands in 0 to m − 1.

Python's `%` always returns a non-negative result for a positive modulus, so solutions translated from Python often miss this. In Swift, every subtraction in modular code needs the fix.

## Division is the exception

The rules cover +, − and ×, but **not** division:

```swift run
print((12 / 4) % 5)
print((12 % 5) / (4 % 5))
```

```output
3
0
```

The right answer is 3, but reducing first gives 2 / 4, which integer division turns into 0. Dividing in modular arithmetic means multiplying by a modular inverse, which is part of M66. Until then, there are two ways round it:

- **Divide before reducing**, while the numbers are still exact. For n(n + 1) / 2 modulo m, halve whichever of n and n + 1 is even, then reduce and multiply.
- **Avoid division altogether.** You'll compute combinations with Pascal's triangle, which only adds, in *Factorials, permutations and combinations*, two lessons from now.

## Multiplying without overflow

The safe rule: **reduce both operands below m first, and make sure (m − 1)² fits in an `Int`.** That holds for any m up to about 3 × 10⁹, which covers 10⁹ + 7. Keeping m below 2³¹ is an easy rule of thumb: the product is then below 2⁶², with room to spare.

When m is bigger, say 10¹², two reduced values can still overflow when multiplied. `multipliedReportingOverflow` from [Overflow traps and overflow operators](/dsa/learn/swift-overflow) tells you when that happens:

```swift run
let mod = 1_000_000_007
let check = (mod - 1).multipliedReportingOverflow(by: mod - 1)
print(check.overflow, check.partialValue)

let big = 999_999_999_999
print(big.multipliedReportingOverflow(by: big).overflow)
```

```output
false 1000000012000000036
true
```

For a large modulus, Swift has an exact way through. `multipliedFullWidth(by:)` returns the full 128-bit product as two halves, and `dividingFullWidth(_:)` divides that 128-bit value by m:

```swift run
func mulMod(_ a: Int, _ b: Int, _ m: Int) -> Int {
    let product = a.multipliedFullWidth(by: b)
    return m.dividingFullWidth(product).remainder
}

print(mulMod(999_999_999_999, 999_999_999_999, 1_000_000_000_007))
```

```output
64
```

It assumes a and b are non-negative and already below m, so the quotient fits in an `Int`. The next lesson shows another way, multiplying by repeated doubling, which needs only addition.

## Modular arithmetic in hashing

A **hash function** turns data into a number. A classic one for strings treats the characters as digits in base 31 and reduces as it goes. It's the same "shift left and add" loop that read numbers in [Number systems and conversion](/dsa/learn/math-number-systems):

```swift run
let mod = 1_000_000_007
var hash = 0
for byte in "abc".utf8 {
    hash = (hash * 31 + Int(byte)) % mod
}
print(hash)
print(97 * 31 * 31 + 98 * 31 + 99)
```

```output
96354
96354
```

The modulus keeps the hash a manageable size however long the string is. Hash functions are the subject of M24, and rolling hashes, which update a hash as a window slides along a string, come in M63.

<Callout kind="gotcha" title="Common mistakes in modular code">
- **Forgetting to reduce the inputs.** If a value can start larger than m, or negative, reduce it first, or the "operands below m" safety rule doesn't hold.
- **Subtracting without the fix.** In Swift, `(a - b) % m` can be negative. Write `(a - b + m) % m`.
- **Reducing too late.** `a * b * c % m` multiplies all three before reducing, which can overflow. Write `a * b % m * c % m`.
- **Dividing.** `(x / y) % m` is fine on exact values, but `(x % m) / (y % m)` is wrong.
</Callout>
