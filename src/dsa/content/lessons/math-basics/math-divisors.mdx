## Why it matters

Laying out 36 photos in a perfect grid means picking a number of columns that divides 36 evenly. Splitting a bill, scheduling repeating events and simplifying fractions all ask the same question: which numbers divide this one? Divisors also lead straight to primes, GCD and factorisation, the next three lessons. The headline idea is a beautiful one: you only need to check up to the **square root** of n, which turns a hopeless O(n) loop into a fast O(√n) one.

## What a divisor is

A whole number d **divides** n when n splits into d equal groups with nothing left over. In Swift terms, `n % d == 0`. Then d is a **divisor** (or factor) of n, and n is a **multiple** of d.

- The divisors of 12 are 1, 2, 3, 4, 6 and 12.
- 1 and n itself divide every n.
- No divisor of a positive n is bigger than n.

In this lesson, n is a positive whole number. Divisors of 0 and of negative numbers are rarely needed in DSA.

## Brute force: try everything

The obvious way to find every divisor is to try each candidate from 1 to n:

```swift run
let n = 36
var found: [Int] = []
for d in 1...n where n % d == 0 {
    found.append(d)
}
print(found)
```

```output
[1, 2, 3, 4, 6, 9, 12, 18, 36]
```

That's O(n): one check per candidate. It's fine for 36, but suppose n is 10¹². At around 10⁸ simple steps per second, from the feasibility table in [From n to a feasible complexity](/dsa/learn/bigo-feasibility-table), it would take hours. We need to skip most of the candidates.

## Divisors come in pairs

Look at the divisors of 36 again. Every time d divides 36, so does `36 / d`. They pair up:

| d | 36 / d | d × (36 / d) |
| --- | --- | --- |
| 1 | 36 | 36 |
| 2 | 18 | 36 |
| 3 | 12 | 36 |
| 4 | 9 | 36 |
| 6 | 6 | 36 |

In every pair, one number is at most 6, and 6 is √36. That's no accident:

> If d × e = n, then d and e can't **both** be bigger than √n, because then d × e would be bigger than √n × √n = n.

So the smaller partner of every pair is at most √n. Find all the divisors up to √n, and each one hands you its partner, `n / d`, for free. For n = 10¹², that's a million checks instead of a trillion.

<Callout kind="analogy">
Think of arranging n chairs in a rectangle. A 4 × 9 rectangle and a 9 × 4 rectangle are the same shape turned sideways. Once you've tried every width up to the square's side, every other width is one you've already seen, turned round.
</Callout>

## The O(√n) loop

Loop `i` upwards while `i * i <= n`, which is the same as `i <= √n` without any square roots. Each time `i` divides `n`, record both `i` and `n / i`:

```swift run
func divisors(of n: Int) -> [Int] {
    var small: [Int] = []
    var large: [Int] = []
    var i = 1
    while i * i <= n {
        if n % i == 0 {
            small.append(i)
            if i != n / i {
                large.append(n / i)
            }
        }
        i += 1
    }
    return small + large.reversed()
}

print(divisors(of: 36))
print(divisors(of: 28))
print(divisors(of: 13))
print(divisors(of: 1))
```

```output
[1, 2, 3, 4, 6, 9, 12, 18, 36]
[1, 2, 4, 7, 14, 28]
[1, 13]
[1]
```

What to notice:

- **The perfect-square check.** For 36, `i = 6` pairs with `36 / 6`, which is also 6. Without `if i != n / i`, 6 would appear twice.
- **The order.** Small divisors come out in increasing order and their partners in *decreasing* order, so reversing `large` before joining gives a sorted list with no sorting step.
- **Primes.** 13 has only the pair (1, 13). The loop stops after `i = 3`, because 4 × 4 is more than 13.

Here's how many passes each approach takes for a million:

```swift run
let n = 1_000_000
var brute = 0
for _ in 1...n {
    brute += 1
}
var smart = 0
var i = 1
while i * i <= n {
    smart += 1
    i += 1
}
print(brute, smart)
```

```output
1000000 1000
```

A thousand times fewer, and the gap widens as n grows. That's the difference between O(n) and O(√n).

## Counting and adding divisors

Often you need only how many divisors there are, or their sum. Same loop, different bookkeeping. Here the sum finds **perfect numbers**, which equal the sum of their divisors other than themselves (6 = 1 + 2 + 3):

```swift run
func divisorSum(_ n: Int) -> Int {
    var total = 0
    var i = 1
    while i * i <= n {
        if n % i == 0 {
            total += i
            if i != n / i {
                total += n / i
            }
        }
        i += 1
    }
    return total
}

print(divisorSum(12))
print((2...10_000).filter { divisorSum($0) - $0 == $0 })
```

```output
28
[6, 28, 496, 8128]
```

1 + 2 + 3 + 4 + 6 + 12 = 28. Subtracting `$0` leaves out the number itself.

Two lessons from now, in *Prime factorisation*, you'll see an even faster way to count divisors, straight from a number's prime factors.

## Divisors of every number up to N

Sometimes you need divisor counts for *all* numbers from 1 to N. Running the √n loop for each costs about N√N. Turn it around instead: rather than asking "what divides n?", ask "what is d a multiple of?". Each d adds itself to all of its multiples:

```swift run
let limit = 12
var counts = Array(repeating: 0, count: limit + 1)
for d in 1...limit {
    for multiple in stride(from: d, through: limit, by: d) {
        counts[multiple] += 1
    }
}
print(Array(counts[1...]))
```

```output
[1, 2, 2, 3, 2, 4, 2, 4, 3, 4, 2, 6]
```

The inner loop runs N/1 + N/2 + N/3 + … + N/N times in total. That sum is about N ln N, so the whole thing is O(N log N). You'll see why in *Series sums and logarithms*, later in this module, and the same "mark the multiples" idea powers the Sieve of Eratosthenes in the next lesson.

<Callout kind="gotcha" title="Swift gotcha: square roots and overflow">
- **Prefer `i * i <= n` to a `Double` square root.** `Double` has only about 16 significant digits, so `Int(Double(999_999_999_999_999_999).squareRoot())` gives 1000000000, one too many. Integer comparisons are always exact.
- **Near `Int.max`, `i * i` itself overflows.** For n close to 9.2 × 10¹⁸, the loop eventually computes 3037000500 × 3037000500, which traps. If n can be that large, write the condition as `i <= n / i`, which never multiplies.
</Callout>
