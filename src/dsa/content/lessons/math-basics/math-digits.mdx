## Why it matters

Card numbers carry a check digit, ISBNs have a checksum, and a PIN pad might reject 1111 as too easy to guess. All of those look at the digits of a number one at a time. In DSA, digit problems are favourite warm-ups: reverse a number, check whether it reads the same both ways, add up its digits. They all come from one small loop, and doing them **without** turning the number into a string is the usual requirement, because it shows you understand how numbers work.

## The peel loop

You've met this loop in [while and repeat-while](/dsa/learn/swift-while). For a non-negative `n`:

- `n % 10` is the last digit;
- `n / 10` is the number with that digit removed.

Repeat until `n` reaches 0, and you visit every digit from right to left:

```swift run
var n = 4721
var digitSum = 0
while n > 0 {
    let digit = n % 10
    print(digit, terminator: " ")
    digitSum += digit
    n /= 10
}
print()
print("Sum:", digitSum)
```

```output
1 2 7 4
Sum: 14
```

Every digit problem in this lesson is a variation on those few lines. What changes is what you do with each `digit`.

The loop runs once per digit. A number `n` has about log₁₀ n digits, so this is O(log n) time and O(1) space. Even `Int.max` has only 19 digits.

## Counting digits

To count digits, add 1 per pass instead of adding the digit. One case needs care: 0 has one digit, but `while n > 0` would never run for it. `repeat-while` runs the body once before checking:

```swift run
func digitCount(_ number: Int) -> Int {
    var n = number
    var count = 0
    repeat {
        count += 1
        n /= 10
    } while n != 0
    return count
}

print(digitCount(4721), digitCount(0), digitCount(-305))
```

```output
4 1 3
```

Using `n != 0` instead of `n > 0` makes it work for negative numbers too, since `-305 / 10` is -30, then -3, then 0.

## Reversing a number

To reverse, build a new number as you peel the old one. Each digit you take off the right of `n` goes on the right of `reversed`, after shifting `reversed` one place left by multiplying by 10. Step through it:

```visual traceTable
program: reverseDigits
input: { number: 1234 }
```

Here it is as a function:

```swift run
func reverse(_ number: Int) -> Int {
    var n = number
    var reversed = 0
    while n > 0 {
        reversed = reversed * 10 + n % 10
        n /= 10
    }
    return reversed
}

print(reverse(1234))
print(reverse(1200))
```

```output
4321
21
```

Trailing zeros vanish: 1200 reversed is 0021, which as a number is 21.

### Reversing can overflow

`1_999_999_999_999_999_999` fits comfortably in an `Int`. Its reverse, 9,999,999,999,999,999,991, doesn't: it's bigger than `Int.max`, which is about 9.22 × 10¹⁸. The `reverse` function above traps on its last pass:

```text title="What you'll see"
Swift runtime failure: arithmetic overflow
```

If the input can be that large, check each step with the reporting methods from [Overflow traps and overflow operators](/dsa/learn/swift-overflow), and return `nil` when the answer won't fit:

```swift run
func safeReverse(_ number: Int) -> Int? {
    var n = number
    var reversed = 0
    while n > 0 {
        let shifted = reversed.multipliedReportingOverflow(by: 10)
        if shifted.overflow { return nil }
        let added = shifted.partialValue.addingReportingOverflow(n % 10)
        if added.overflow { return nil }
        reversed = added.partialValue
        n /= 10
    }
    return reversed
}

print(safeReverse(1230) ?? -1)
print(safeReverse(1_999_999_999_999_999_999) ?? -1)
```

```output
321
-1
```

## Palindrome numbers

A **palindrome** reads the same forwards and backwards: 121, 4554, 7. The direct test is "is `n` equal to its reverse?". Two details:

- Negative numbers are never palindromes, because `-121` backwards is `121-`.
- The check needs the *original* value, so reverse a copy.

There's a neater version that also can't overflow. Reverse only the right **half** of the digits, and stop when the reversed half catches up with what's left:

```swift run
func isPalindrome(_ number: Int) -> Bool {
    if number < 0 || (number % 10 == 0 && number != 0) {
        return false
    }
    var n = number
    var half = 0
    while n > half {
        half = half * 10 + n % 10
        n /= 10
    }
    return n == half || n == half / 10
}

for x in [1221, 12321, 123, 10, 0, -121] {
    print(x, isPalindrome(x))
}
```

```output
1221 true
12321 true
123 false
10 false
0 true
-121 false
```

For 1221: `n` and `half` go (122, 1), then (12, 12). Now `n > half` is false, and they're equal, so it's a palindrome. For 12321 they end as (12, 123); the middle digit, 3, sits on the end of `half`, so `half / 10` drops it before comparing.

Numbers ending in 0 need the special case at the top. A palindrome would have to start with 0 too, and only 0 itself does.

## Armstrong numbers

153 has a curious property. It has three digits, and the sum of each digit cubed gives the number back: 1³ + 5³ + 3³ = 1 + 125 + 27 = 153. A number with k digits that equals the sum of its digits each raised to the power k is an **Armstrong number**.

Checking one takes two passes over the digits: one to count them, one to add up the powers. Swift has no integer power operator, so a small loop does that job:

```swift run
func digitCount(_ number: Int) -> Int {
    var n = number
    var count = 0
    repeat {
        count += 1
        n /= 10
    } while n != 0
    return count
}

func power(_ base: Int, _ exponent: Int) -> Int {
    var result = 1
    for _ in 0..<exponent {
        result *= base
    }
    return result
}

func isArmstrong(_ number: Int) -> Bool {
    let k = digitCount(number)
    var n = number
    var total = 0
    while n > 0 {
        total += power(n % 10, k)
        n /= 10
    }
    return total == number
}

print((1...10_000).filter(isArmstrong))
```

```output
[1, 2, 3, 4, 5, 6, 7, 8, 9, 153, 370, 371, 407, 1634, 8208, 9474]
```

Every single-digit number qualifies, since 7¹ is 7. Then they get rare quickly. Breaking a problem into small helpers like `digitCount` and `power` keeps each piece easy to check. Later in this module, in *Fast exponentiation*, you'll write a much faster `power`.

## Digits from the left

The peel loop gives digits right to left. To get them left to right without reversing, find the place value of the first digit, then divide by smaller and smaller powers of 10:

```swift run
let n = 4721
var place = 1
while place <= n / 10 {
    place *= 10
}
while place > 0 {
    print(n / place % 10, terminator: " ")
    place /= 10
}
print()
```

```output
4 7 2 1
```

The first loop grows `place` to 1,000, the largest power of 10 that's at most `n`. Writing `place <= n / 10` rather than `place * 10 <= n` means `place` is never multiplied past `n`, which keeps it safe from overflow even near `Int.max`. Then `n / place % 10` picks out each digit: 4721 / 1000 is 4, 4721 / 100 % 10 is 7, and so on.

## Building a number from digits

Going from digits back to a number is the parsing loop again: shift left, add the digit.

```swift run
let digits = [4, 7, 2, 1]
var value = 0
for digit in digits {
    value = value * 10 + digit
}
print(value)
```

```output
4721
```

## Negative numbers

Swift's `%` keeps the sign of the left-hand number, so the digits of a negative number come out negative:

```swift run
print(-472 % 10, -472 / 10)
print(abs(-472) % 10)
```

```output
-2 -47
2
```

The usual fix is to work with `abs(n)` and deal with the sign separately. One value breaks this: `abs(Int.min)` traps, because +9,223,372,036,854,775,808 is one more than `Int.max`. If `Int.min` is possible, use `n.magnitude` instead, which returns a `UInt` that has room for it.

<Callout kind="gotcha" title="Common mistakes with digit loops">
- **Destroying the input.** The loop changes `n`, so copy the parameter into a `var` first and keep the original for comparisons.
- **Forgetting 0.** `while n > 0` never runs for 0. Decide what 0 should give, and use `repeat-while` if it needs one pass.
- **Negative numbers.** `n % 10` is negative for negative `n`, and `while n > 0` skips them entirely.
</Callout>
