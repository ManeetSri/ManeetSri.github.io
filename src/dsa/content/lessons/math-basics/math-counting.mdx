## Why it matters

How many four-digit PINs are there? In how many orders can a playlist of 10 songs play? How many different 5-card hands can you deal? Counting questions like these are everywhere in DSA. They tell you how big a brute-force search really is: trying every ordering of 15 items is over a trillion cases, which rules it out. And many problems ask you to count ways directly, "modulo 10⁹ + 7". This lesson gives you the counting toolkit: the product rule, factorials, permutations, combinations and Pascal's triangle.

## Two counting rules

**The product rule.** If one choice has a options and a second, independent choice has b options, together there are a × b possibilities. Three shirts and four pairs of trousers make 3 × 4 = 12 outfits:

```swift run
let shirts = ["red", "blue", "white"]
let trousers = ["jeans", "chinos", "shorts", "cords"]
var outfits = 0
for _ in shirts {
    for _ in trousers {
        outfits += 1
    }
}
print(outfits)
```

```output
12
```

Nested loops are the product rule in code. A four-digit PIN is four choices of 10 digits each: 10 × 10 × 10 × 10 = 10,000.

**The sum rule.** If you choose from one group *or* another, with no overlap, add the sizes. A café offering 5 hot drinks or 3 cold ones has 5 + 3 = 8 drinks to choose from.

## Factorials: arranging everything

In how many orders can you line up 3 books, A, B and C? There are 3 choices for the first position, then 2 left for the second, then 1 for the last: 3 × 2 × 1 = 6.

```text
ABC  ACB  BAC  BCA  CAB  CBA
```

That product is **n factorial**, written n!:

```text
n! = n × (n − 1) × (n − 2) × … × 2 × 1
```

By convention **0! = 1**: there's exactly one way to arrange nothing. It also keeps the formulas below working at the edges.

Factorials grow astonishingly fast:

| n | n! |
| --- | --- |
| 5 | 120 |
| 10 | 3,628,800 |
| 13 | 6,227,020,800 |
| 20 | 2,432,902,008,176,640,000 |

So fast that 21! doesn't fit in an `Int`:

```swift run
var factorial = 1
var n = 1
while true {
    let next = factorial.multipliedReportingOverflow(by: n + 1)
    if next.overflow {
        print("\(n + 1)! overflows")
        break
    }
    factorial = next.partialValue
    n += 1
}
print("\(n)! = \(factorial)")
```

```output
21! overflows
20! = 2432902008176640000
```

This is why the O(n!) row of the feasibility table stops at about n = 10. Ten items have 3.6 million orderings; fifteen have 1.3 trillion.

## Permutations: arranging some

Eight runners race. How many ways can gold, silver and bronze be awarded? 8 choices for gold, then 7 for silver, then 6 for bronze: 8 × 7 × 6 = 336. An ordered selection like this is a **permutation**, and the number of ways to arrange k items chosen from n is:

```text
P(n, k) = n × (n − 1) × … × (n − k + 1)      (k numbers multiplied)
        = n! / (n − k)!
```

The factorial form is neat on paper, but don't compute it that way. For P(30, 2) = 870, the factorial form needs 30!, which overflows. Multiply the k numbers directly instead.

## Combinations: choosing a group

Now the order doesn't matter. How many ways can you pick 2 people from 5 (A to E) to form a team? Listing them:

```text
AB  AC  AD  AE  BC  BD  BE  CD  CE  DE
```

Ten. Compare with permutations: P(5, 2) = 20 counts AB and BA separately. Every team of 2 was counted 2! = 2 times. In general each group of k shows up k! times among the permutations, so:

```text
C(n, k) = P(n, k) / k! = n! / (k! × (n − k)!)
```

C(n, k) is read "n choose k" and also written as nCr. Some values to know:

- C(n, 0) = C(n, n) = 1: one way to choose nothing, or everything.
- C(n, 1) = n.
- **Symmetry:** C(n, k) = C(n, n − k). Choosing 2 to be on the team is the same as choosing 3 to leave out.
- C(n, k) = 0 when k is greater than n or negative.

There are C(52, 5) = 2,598,960 different 5-card poker hands.

## Computing C(n, k) without factorials

The factorial formula overflows for n above 20, even when the answer is small. The **multiplicative formula** builds the answer one step at a time:

```swift run
func choose(_ n: Int, _ k: Int) -> Int {
    if k < 0 || k > n {
        return 0
    }
    let k = min(k, n - k)
    var result = 1
    for i in 0..<k {
        result = result * (n - i) / (i + 1)
    }
    return result
}

print(choose(5, 2), choose(52, 5), choose(10, 0), choose(4, 7))
print(choose(60, 30))
```

```output
10 2598960 1 0
118264581564861424
```

What to notice:

- After each pass, `result` is exactly C(n, i + 1), a whole number, so the division never loses anything. Multiplying first and dividing second is essential: `(n - i) / (i + 1)` on its own would truncate.
- `min(k, n - k)` uses symmetry to do as few passes as possible. C(100, 98) takes 2 passes, not 98.

It still has a weak spot: `result * (n - i)` is bigger than the answer. C(62, 31) is about 4.7 × 10¹⁷, which fits easily, but the multiplication on the way there overflows. For larger values, use Pascal's triangle.

## Pascal's triangle

Write a 1 at the top. Each row starts and ends with 1, and every other entry is the **sum of the two entries above it**:

```text
row 0:          1
row 1:         1 1
row 2:        1 2 1
row 3:       1 3 3 1
row 4:      1 4 6 4 1
row 5:    1 5 10 10 5 1
```

Entry k of row n (both counting from 0) is exactly C(n, k). Row 5 says C(5, 2) = 10, matching the teams above. The rule behind it is **Pascal's rule**:

```text
C(n, k) = C(n − 1, k − 1) + C(n − 1, k)
```

Here's why. Pick any one of the n items, say Alice. Every group of k either includes Alice or doesn't:

- **With Alice:** choose the other k − 1 members from the remaining n − 1 people. That's C(n − 1, k − 1).
- **Without Alice:** choose all k from the remaining n − 1. That's C(n − 1, k).

No group is in both cases, so by the sum rule they add up. This style of argument, "split on one item: in or out", is the seed of dynamic programming, which you'll meet in Part VII.

```swift run
var row = [1]
for _ in 0..<6 {
    print(row)
    var next = [1]
    for i in 1..<row.count {
        next.append(row[i - 1] + row[i])
    }
    next.append(1)
    row = next
}
```

```output
[1]
[1, 1]
[1, 2, 1]
[1, 3, 3, 1]
[1, 4, 6, 4, 1]
[1, 5, 10, 10, 5, 1]
```

Building the triangle uses **only addition**, and every value along the way is no bigger than the final answers. So it's exact all the way to row 66, whose middle entry is about 7.2 × 10¹⁸. The multiplicative formula gave up at 62.

Each row also adds up to a power of two: row 4 sums to 16 = 2⁴. That makes sense, because summing C(n, k) over every k counts all subsets of n items, and each item is either in or out: 2 × 2 × … × 2 = 2ⁿ subsets. You'll generate subsets with bitmasks in M16.

## C(n, k) modulo a prime

Counting problems often want C(n, k) modulo 1,000,000,007 for n in the thousands, where the true values have hundreds of digits. Pascal's rule only adds, so reduce after each addition:

```swift run
let mod = 1_000_000_007
let size = 1000
var c = Array(repeating: Array(repeating: 0, count: size + 1), count: size + 1)
for n in 0...size {
    c[n][0] = 1
    if n > 0 {
        for k in 1...n {
            c[n][k] = (c[n - 1][k - 1] + c[n - 1][k]) % mod
        }
    }
}
print(c[10][3], c[1000][1], c[1000][500])
```

```output
120 1000 159835829
```

The table has about half a million useful cells, so it takes O(n²) time and space, which is fine for n up to a few thousand. After that, every C(n, k) is an O(1) lookup. Entries with k greater than n stay 0, which is exactly right.

This works where the multiplicative formula can't, because modular arithmetic doesn't allow the division by `i + 1`. For n up to 10⁶, there's a faster method using factorials and modular inverses, which you'll learn in M66.

<Callout kind="gotcha" title="Common mistakes when counting">
- **Computing n! / (k! × (n − k)!) literally.** It overflows for any n above 20. Use the multiplicative formula or Pascal's triangle.
- **Dividing before multiplying.** `result * ((n - i) / (i + 1))` truncates. Multiply first, then divide.
- **Mixing up order.** If swapping two chosen items gives a different outcome (podium places, passwords), count permutations. If not (teams, hands of cards), count combinations.
</Callout>
