## Why it matters

Some of the most useful facts in computing are things that *must* happen. If a string has more than 26 lowercase letters, one of them repeats, so a "are all letters unique?" check can answer instantly. If a sequence can only take 100 different values, it starts repeating within 101 steps, which is how cycle detection and hash collisions are reasoned about. Both come from one almost obvious idea, the **pigeonhole principle**. It rarely writes code for you, but it tells you when a duplicate, a collision or a repeat is guaranteed, and that often unlocks a fast solution.

## The principle

> If you put n + 1 pigeons into n holes, at least one hole holds two or more pigeons.

That's it. If every hole held at most one pigeon, there would be at most n pigeons, but there are n + 1.

It sounds too simple to be useful, yet it gives instant answers:

- Among any 13 people, two were born in the same month. There are only 12 months.
- Among 367 people, two share a birthday, even counting 29 February.
- A drawer holds black, white and grey socks. Take out 4 socks in the dark and you're certain to have a matching pair, since 4 socks go into 3 colours.

Notice what it doesn't say: *which* hole, or *which* two pigeons. It proves that something exists without finding it. In algorithms, that's often enough to justify an early exit or to guarantee that a search will succeed.

## The general version

With more pigeons, you can say more. If N items go into k boxes, some box holds at least ⌈N / k⌉ items, the ceiling from the [previous lesson](/dsa/learn/math-floor-ceil-overflow).

Put 100 people into 12 birth months: some month has at least ⌈100 / 12⌉ = 9 people. If every month had 8 or fewer, there would be at most 96 people.

## Guaranteed duplicates

An array of n + 1 numbers, each between 1 and n, **must** contain a duplicate: n + 1 values, but only n possible values. A classic interview problem asks you to find it. One straightforward way uses an array of flags, one per possible value:

```swift run
func firstDuplicate(_ numbers: [Int]) -> Int? {
    var seen = Array(repeating: false, count: numbers.count)
    for x in numbers {
        if seen[x] {
            return x
        }
        seen[x] = true
    }
    return nil
}

print(firstDuplicate([3, 1, 4, 2, 4]) ?? -1)
```

```output
4
```

Five numbers from 1 to 4, so a repeat was certain. That's O(n) time and O(n) space. A cleverer O(1)-space solution treats the array as a linked structure and uses cycle detection, which you'll learn in M25. Its correctness depends on the pigeonhole principle too.

## Early exits

How do you check that a word of lowercase letters has no repeated letter? There are only 26 letters, so **any word longer than 26 letters must repeat one**. That check costs O(1) and can skip the work entirely:

```swift run
func hasAllUniqueLetters(_ word: String) -> Bool {
    let letters = Array(word.utf8)
    if letters.count > 26 {
        return false
    }
    var seen = Array(repeating: false, count: 26)
    for byte in letters {
        let index = Int(byte - 97)
        if seen[index] {
            return false
        }
        seen[index] = true
    }
    return true
}

print(hasAllUniqueLetters("swift"), hasAllUniqueLetters("hello"))
print(hasAllUniqueLetters("abcdefghijklmnopqrstuvwxyza"))
```

```output
true false
false
```

It also means the main loop runs at most 26 times, so the whole function is O(1) whatever the input length. The same reasoning applies to any small alphabet: digits, days of the week, the 128 ASCII characters.

## Remainders always collide

Divide any n + 1 whole numbers by n. There are only n possible remainders, 0 to n − 1, so two of the numbers share a remainder, which means their difference is a multiple of n.

That leads to a lovely guarantee. **Given any n non-negative whole numbers, some non-empty run of consecutive ones adds up to a multiple of n.** Here's why. Take the running totals: 0 (nothing yet), then the first number, then the first two, and so on. That's n + 1 totals, but only n remainders modulo n, so two totals share a remainder. The numbers between those two positions add up to their difference, which is a multiple of n.

The proof is also an algorithm. Remember where each remainder first appeared, and stop at the first repeat:

```swift run
func blockDivisibleByCount(_ numbers: [Int]) -> (start: Int, end: Int) {
    let n = numbers.count
    var firstSeen = Array(repeating: -1, count: n)
    firstSeen[0] = 0
    var total = 0
    for (i, value) in numbers.enumerated() {
        total = (total + value) % n
        if firstSeen[total] != -1 {
            return (firstSeen[total], i)
        }
        firstSeen[total] = i + 1
    }
    return (-1, -1)
}

let numbers = [3, 4, 1, 7, 2]
let block = blockDivisibleByCount(numbers)
print(block.start, block.end, numbers[block.start...block.end])
```

```output
1 2 [4, 1]
```

The running totals modulo 5 go 0, 3, 2, then 8 % 5 = 3, a repeat. The numbers after the first 3 and up to the second, 4 and 1, add up to 5. The pigeonhole principle guarantees the loop always returns before running out, so the `(-1, -1)` line is never reached for a non-empty array. This "running totals plus remainders" idea is a key pattern in M20, prefix sums.

## Sequences must repeat

Suppose each value in a sequence is computed from the one before, and there are only m possible values. Within m + 1 steps, some value appears twice, and from then on the sequence goes round the same loop forever.

The last two digits of the powers of 7 are a good example. There are only 100 possible endings, so they must repeat:

```swift run
var value = 7
var seen: [Int] = []
while !seen.contains(value) {
    seen.append(value)
    value = value * 7 % 100
}
print(seen, value)
```

```output
[7, 49, 43, 1] 7
```

7, 49, 343 and 2,401 end in 07, 49, 43 and 01, and then 16,807 ends in 07 again. The cycle has length 4, so 7¹⁰⁰ ends in 01, the same as 7⁴.

This is also why a `while` loop over a finite set of states either stops or cycles, and why following `next` pointers in a linked list either reaches the end or loops. You'll detect those loops with fast and slow pointers in M25.

<Callout kind="gotcha" title="Off by one">
n pigeons in n holes *don't* force a collision: each could have its own hole. The guarantee needs **more** items than boxes. When you use the principle, count both carefully, including edge values like 0 and the full alphabet.
</Callout>
