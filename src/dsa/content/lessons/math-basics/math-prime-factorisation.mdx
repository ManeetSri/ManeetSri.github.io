## Why it matters

Primes are to whole numbers what atoms are to molecules: everything else is built from them. Breaking a number into its prime factors answers a surprising number of questions at once. How many divisors does it have? What does it share with another number? Is it a perfect square? How many zeros are on the end of 100 factorial? The security of RSA encryption rests on the fact that nobody knows a fast way to factorise huge numbers. For the sizes in DSA problems, though, you can do it quickly, with trial division up to √n.

## Every number is a product of primes

Keep splitting a composite number into smaller factors and you always end up with primes:

```text
360 = 36 × 10
    = (4 × 9) × (2 × 5)
    = 2 × 2 × 3 × 3 × 2 × 5
    = 2³ × 3² × 5
```

The **fundamental theorem of arithmetic** says that every whole number from 2 upwards can be written as a product of primes in **exactly one way**, apart from the order. Start with 360 = 4 × 90 or 360 = 8 × 45 and you still reach 2³ × 3² × 5.

This is also why 1 isn't counted as a prime. If it were, 360 = 2³ × 3² × 5 × 1 × 1 would be another factorisation, and "exactly one way" would be false.

We write a factorisation as pairs of **(prime, exponent)**: 360 is (2, 3), (3, 2), (5, 1). The number 1 has no prime factors at all, so its list is empty.

## Trial division

To factorise n, try divisors d = 2, 3, 4, … in order. Whenever d divides n, divide it out **as many times as it goes**, counting as you go. Here's 360:

| d | What happens | n afterwards |
| --- | --- | --- |
| 2 | 360 → 180 → 90 → 45: three 2s | 45 |
| 3 | 45 → 15 → 5: two 3s | 5 |
| 4 | 4 × 4 = 16 is more than 5, so stop | 5 |
| | 5 is left over and bigger than 1, so it's a prime factor | |

Two ideas make this work.

**Every d that divides is prime.** By the time d reaches 4, all the 2s are gone, so 4 can't divide what's left. The same goes for 6, 8, 9 and every other composite: its prime factors were divided out earlier. So you never need a list of primes. Composite values of d never divide.

**Stop at √n, and keep what's left.** If no d up to √n divides the current n, then n has no factor that small, so it must be prime (or 1). That's the leftover 5 above. Forgetting this last step is the most common bug in factorisation code.

```swift run
func primeFactors(of number: Int) -> [(prime: Int, exponent: Int)] {
    var n = number
    var factors: [(prime: Int, exponent: Int)] = []
    var d = 2
    while d * d <= n {
        if n % d == 0 {
            var exponent = 0
            while n % d == 0 {
                n /= d
                exponent += 1
            }
            factors.append((prime: d, exponent: exponent))
        }
        d += 1
    }
    if n > 1 {
        factors.append((prime: n, exponent: 1))
    }
    return factors
}

for x in [360, 97, 1, 600_851_475_143] {
    let parts = primeFactors(of: x).map { "\($0.prime)^\($0.exponent)" }
    print(x, "=", parts.joined(separator: " × "))
}
```

```output
360 = 2^3 × 3^2 × 5^1
97 = 97^1
1 =
600851475143 = 71^1 × 839^1 × 1471^1 × 6857^1
```

What to notice:

- The condition `d * d <= n` uses the **current**, shrinking n. Once the small factors are divided out, the loop can stop much sooner.
- 97 is prime: no d up to 9 divides it, so the whole of 97 is the leftover.
- 1 gives an empty list, which `joined` turns into an empty string.
- The return type is an array of **named tuples**, from [Tuples and typealias](/dsa/learn/swift-tuples-typealias), so callers can write `factor.prime` and `factor.exponent`.

## How long does it take?

The worst case is when n is prime, or has a large prime factor, and the loop runs all the way to √n. That's **O(√n)**. For n up to 10¹², that's at most a million passes. When n has small factors, it shrinks fast and finishes far sooner: 2⁴⁰ takes 40 divisions and is done.

You can halve the work by handling 2 on its own and then trying only odd d, as `isPrime` did in the previous lesson. The complexity stays O(√n).

## What a factorisation tells you

### How many divisors

Every divisor of 360 = 2³ × 3² × 5 is made by choosing how many of each prime to use: 0 to 3 twos, 0 to 2 threes, and 0 or 1 five. Each choice gives a different divisor, so:

```text
number of divisors = (3 + 1) × (2 + 1) × (1 + 1) = 4 × 3 × 2 = 24
```

In general, add 1 to each exponent and multiply.

```swift run
let exponents = [3, 2, 1]
let choices = exponents.map { $0 + 1 }
print(choices, choices.reduce(1, *))
```

```output
[4, 3, 2] 24
```

### GCD and LCM

Line two factorisations up side by side. The gcd takes the **smaller** exponent of each prime, and the lcm takes the **larger**:

| Prime | 360 | 84 | gcd: min | lcm: max |
| --- | --- | --- | --- | --- |
| 2 | 3 | 2 | 2 | 3 |
| 3 | 2 | 1 | 1 | 2 |
| 5 | 1 | 0 | 0 | 1 |
| 7 | 0 | 1 | 0 | 1 |

So gcd(360, 84) = 2² × 3 = 12, and lcm(360, 84) = 2³ × 3² × 5 × 7 = 2,520. It's a nice way to *see* why gcd × lcm = a × b: min plus max of two exponents is their sum. To compute a gcd, though, Euclid's algorithm is much faster, because it doesn't need to factorise anything.

### Perfect squares

A number is a perfect square exactly when **every exponent is even**. 3600 = 2⁴ × 3² × 5² is 60². 360 isn't a square, because its exponents 3, 2 and 1 aren't all even.

## Trailing zeros of n!

n! ("n factorial") is 1 × 2 × 3 × … × n, which you'll meet properly in *Factorials, permutations and combinations*, later in this module. How many zeros does 100! end with? Computing 100! is hopeless: it has 158 digits. Factorisation gives a shortcut.

Each trailing zero comes from a factor of 10, which is 2 × 5. A factorial has far more 2s than 5s, so **the number of zeros is the number of 5s** in its prime factorisation. Count them:

- every multiple of 5 up to n gives one 5: there are n / 5 of them;
- every multiple of 25 gives a second 5: n / 25 more;
- every multiple of 125 gives a third, and so on.

```swift run
func trailingZerosOfFactorial(_ n: Int) -> Int {
    var count = 0
    var power = 5
    while power <= n {
        count += n / power
        power *= 5
    }
    return count
}

print(trailingZerosOfFactorial(10))
print(trailingZerosOfFactorial(25))
print(trailingZerosOfFactorial(100))
print(trailingZerosOfFactorial(1_000_000_000))
```

```output
2
6
24
249999998
```

10! = 3,628,800 has two zeros: one from 5 and one from 10. For 100!, that's 20 + 4 = 24. The loop runs once per power of 5, so it's O(log n): about 13 passes for a billion.

## Factorising many numbers: the smallest-prime-factor sieve

If you need to factorise lots of numbers, all up to some N, change the sieve from the last lesson slightly. Instead of a `Bool`, store each number's **smallest prime factor**. Then you can factorise any k by dividing by its smallest prime factor again and again:

```swift run
let limit = 100
var spf = Array(0...limit)
var p = 2
while p * p <= limit {
    if spf[p] == p {
        for m in stride(from: p * p, through: limit, by: p) where spf[m] == m {
            spf[m] = p
        }
    }
    p += 1
}

func factor(_ number: Int) -> [Int] {
    var n = number
    var result: [Int] = []
    while n > 1 {
        result.append(spf[n])
        n /= spf[n]
    }
    return result
}

print(spf[91], spf[97])
print(factor(84), factor(97), factor(64))
```

```output
7 97
[2, 2, 3, 7] [97] [2, 2, 2, 2, 2, 2]
```

`spf` starts as 0, 1, 2, …, N, meaning "my smallest prime factor is me". A prime p then claims every multiple that hasn't been claimed by a smaller prime. Afterwards, `spf[k] == k` exactly when k is prime.

The sieve costs O(N log log N) once. After that, each factorisation takes only O(log k), since every division at least halves k.

<Callout kind="gotcha" title="Common mistakes">
- **Losing the last prime.** After the loop, if `n > 1`, it's a prime factor. Without that check, 360 loses its 5 and 97 loses everything.
- **Using `if` instead of `while`.** `if n % d == 0 { n /= d }` removes only one copy of d, so 8 would wrongly report a single 2.
- **Comparing with the original n.** Looping to the square root of the *original* number still works, but wastes time after the small factors are gone.
</Callout>
