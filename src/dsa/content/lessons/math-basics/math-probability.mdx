## Why it matters

Why is a Swift `Dictionary` lookup called O(1) when, in the worst case, it can be slower? Why does quick sort pick its pivot at random? The answers are about **probability** and **expected value**: what usually happens, and what happens on average. You'll see "expected O(1)" and "expected O(n log n)" throughout the course, and some problems ask for an expected value directly. This lesson keeps things concrete. Every example counts outcomes exactly, with whole numbers and fractions, so you can check each answer in Swift without any randomness.

## Probability is counting

When every outcome is **equally likely**, the probability of an event is:

```text
P(event) = number of outcomes where it happens / total number of outcomes
```

A fair die has 6 equally likely faces, and 3 of them are even, so P(even) = 3/6 = 1/2. A probability is always between 0 (impossible) and 1 (certain).

With two dice there are 6 × 6 = 36 equally likely outcomes, by the product rule from [Factorials, permutations and combinations](/dsa/learn/math-counting). How many add up to 7? You could list them by hand, or let nested loops count:

```swift run
func gcd(_ a: Int, _ b: Int) -> Int {
    b == 0 ? a : gcd(b, a % b)
}

func fraction(_ top: Int, _ bottom: Int) -> String {
    let g = gcd(top, bottom)
    return "\(top / g)/\(bottom / g)"
}

var sevens = 0
var total = 0
for first in 1...6 {
    for second in 1...6 {
        total += 1
        if first + second == 7 {
            sevens += 1
        }
    }
}
print(sevens, total, fraction(sevens, total))
```

```output
6 36 1/6
```

Six outcomes give 7: (1, 6), (2, 5), (3, 4), (4, 3), (5, 2) and (6, 1). So P(sum is 7) = 6/36 = 1/6. The `fraction` helper reduces the answer with the gcd from [GCD, LCM and Euclid's algorithm](/dsa/learn/math-gcd-lcm), keeping it exact.

Counting every outcome like this is called **enumeration**. It's slow for big problems, but it's a perfect way to check a formula on a small case.

## Three rules

**Complement.** The probability that something does *not* happen is 1 minus the probability that it does. P(not a six) = 1 − 1/6 = 5/6.

**Independent events multiply.** Two events are **independent** when one doesn't affect the other, like two separate dice. Then the chance of both is the product: P(two sixes) = 1/6 × 1/6 = 1/36.

**Mutually exclusive events add.** If two events can't both happen, the chance of one or the other is the sum. P(rolling a 1 or a 2) = 1/6 + 1/6 = 1/3.

The complement rule is the secret to every "at least one" question. What's the chance of at least one six in four rolls? Counting the ways to get one six, two sixes and so on is messy. The complement is easy: "no sixes at all" means four independent non-sixes, (5/6)⁴ = 625/1296. So:

```text
P(at least one six) = 1 − 625/1296 = 671/1296   (about 0.518)
```

Enumeration agrees. Four nested loops visit all 6⁴ = 1,296 outcomes:

```swift run
var atLeastOneSix = 0
var outcomes = 0
for a in 1...6 {
    for b in 1...6 {
        for c in 1...6 {
            for d in 1...6 {
                outcomes += 1
                if a == 6 || b == 6 || c == 6 || d == 6 {
                    atLeastOneSix += 1
                }
            }
        }
    }
}
print(atLeastOneSix, outcomes)
print(outcomes - 5 * 5 * 5 * 5)
```

```output
671 1296
671
```

## Expected value

The **expected value** of something random is its long-run average: what you'd get on average if you repeated the experiment many times. Multiply each possible value by its probability and add:

```text
E = value₁ × P(value₁) + value₂ × P(value₂) + …
```

For one die, each face has probability 1/6:

```text
E = (1 + 2 + 3 + 4 + 5 + 6) × 1/6 = 21/6 = 7/2 = 3.5
```

The expected value doesn't have to be a possible outcome: you can't roll 3.5. It's an average.

```swift run
func gcd(_ a: Int, _ b: Int) -> Int {
    b == 0 ? a : gcd(b, a % b)
}

func fraction(_ top: Int, _ bottom: Int) -> String {
    let g = gcd(top, bottom)
    return "\(top / g)/\(bottom / g)"
}

let faces = Array(1...6)
print(fraction(faces.reduce(0, +), faces.count))
```

```output
7/2
```

Expected value is how you judge a bet. A game costs 4 points to play, and pays out whatever the die shows. On average you win 3.5 points, so on average you lose half a point every time you play.

## Linearity of expectation

Here's the most useful fact about expected values:

> The expected value of a sum is the sum of the expected values. E(X + Y) = E(X) + E(Y).

It holds **even when X and Y depend on each other**, which makes it far more powerful than it first looks. The expected total of two dice is 3.5 + 3.5 = 7, no table needed.

A harder example. Shuffle n cards numbered 0 to n − 1. On average, how many end up in their original position? Working through every arrangement sounds awful. Instead, look at one card at a time: card i lands in position i with probability 1/n. The expected count for that card alone is 1/n. Add up all n cards: n × 1/n = **1**, whatever n is.

That's surprising enough to check. This enumerates every ordering of n cards, using recursion from [A first look at recursion](/dsa/learn/swift-first-recursion), and counts the cards that stay put:

```swift run
func gcd(_ a: Int, _ b: Int) -> Int {
    b == 0 ? a : gcd(b, a % b)
}

func fraction(_ top: Int, _ bottom: Int) -> String {
    let g = gcd(top, bottom)
    return "\(top / g)/\(bottom / g)"
}

func permutations(_ items: [Int]) -> [[Int]] {
    if items.count <= 1 {
        return [items]
    }
    var result: [[Int]] = []
    for (i, item) in items.enumerated() {
        var rest = items
        rest.remove(at: i)
        for tail in permutations(rest) {
            result.append([item] + tail)
        }
    }
    return result
}

for n in 2...5 {
    let all = permutations(Array(0..<n))
    var stayed = 0
    for order in all {
        for i in 0..<n where order[i] == i {
            stayed += 1
        }
    }
    print(n, all.count, stayed, fraction(stayed, all.count))
}
```

```output
2 2 2 1/1
3 6 6 1/1
4 24 24 1/1
5 120 120 1/1
```

For 5 cards, the 120 orderings have 120 cards in place between them: exactly 1 per ordering on average. Linearity of expectation is the standard tool for analysing randomised algorithms, including quick sort with random pivots in Part IV.

## Waiting for a success

If each attempt succeeds with probability p, independently, how many attempts do you expect to need? The answer is **1/p**. A six comes up with probability 1/6, so on average it takes 6 rolls.

Here's a short reason. Let E be the expected number of rolls. You always make one roll. With probability 1 − p it fails, and you're back where you started, expecting E more. So E = 1 + (1 − p) × E. Solving gives p × E = 1, so E = 1/p.

That gives a famous result, the **coupon collector** problem. How many rolls, on average, until you've seen all six faces? The first roll always shows a new face. Then a new face has probability 5/6, so you expect 6/5 rolls to get one. Then 6/4, 6/3, 6/2 and finally 6/1:

```text
6/6 + 6/5 + 6/4 + 6/3 + 6/2 + 6/1 = 6 × (1 + 1/2 + 1/3 + 1/4 + 1/5 + 1/6) = 147/10 = 14.7
```

That bracket is the harmonic series from [Series sums and logarithms](/dsa/learn/math-series-logs). With n faces, the expected wait is about n ln n.

## Why collisions come early

How many people do you need in a room before there's a better than even chance that two share a birthday? Most people guess about 180. The answer is **23**. Use the complement: the chance that all 23 birthdays are different is 365/365 × 364/365 × … × 343/365.

```swift run
import Foundation

var allDifferent = 1.0
for i in 0..<23 {
    allDifferent *= Double(365 - i) / 365
}
print(String(format: "%.3f", 1 - allDifferent))
```

```output
0.507
```

`String(format:)` rounds the `Double` to three decimal places, so the printed result is the same every time. In general, with m equally likely slots, you expect the first collision after only about √m items. That's why a hash table **must** handle collisions, even when it has far more slots than keys: you'll see how in M24.

<Callout kind="gotcha" title="Common mistakes">
- **Integer division.** `let p = 3 / 6` is 0, because both are `Int`. Keep the numerator and denominator as separate integers, or convert with `Double(3) / Double(6)`.
- **Adding overlapping events.** P(even or greater than 3) isn't 1/2 + 1/2 = 1, because 4 and 6 are counted twice. Count the outcomes directly: 2, 4, 5 and 6 give 4/6.
- **Assuming independence.** Drawing two cards *without* putting the first back isn't independent: the second draw depends on the first.
</Callout>
