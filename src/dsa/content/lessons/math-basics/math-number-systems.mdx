## Why it matters

Computers store every number as a pattern of 0s and 1s, so binary sits underneath everything you write. You'll see other bases too: hexadecimal colours like `#FF8800` in an iOS design file, memory addresses in the debugger, and file sizes in powers of two. In DSA, base conversion is a classic warm-up problem, and the bit tricks in M16 only make sense once binary feels familiar. Best of all, converting between bases uses the same `%` and `/` loop you already know.

## Place value: what a number really is

When you write 4,721, each digit's position gives it a value. Reading from the right, the places are worth 1, 10, 100 and 1,000:

```text
4721 = 4 × 1000 + 7 × 100 + 2 × 10 + 1 × 1
```

That's **base 10**, or decimal. It has ten digits, 0 to 9, and each place is worth ten times the place to its right. Nothing about the number itself is special to 10. We use it because we have ten fingers.

Any whole number from 2 upwards can be a base. In **base b**:

- the digits run from 0 up to `b - 1`;
- the places, from the right, are worth 1, b, b², b³ and so on.

When a number could be read in more than one base, a small subscript says which: 101₂ is binary, 101₁₀ is decimal.

## Binary: base 2

Binary has only two digits, 0 and 1, and its places are worth 1, 2, 4, 8, 16, 32… Each place is double the one to its right. To read a binary number, add up the places that hold a 1:

| Place value | 32 | 16 | 8 | 4 | 2 | 1 |
| --- | --- | --- | --- | --- | --- | --- |
| Digit of 101101₂ | 1 | 0 | 1 | 1 | 0 | 1 |

32 + 8 + 4 + 1 = 45. So 101101₂ is 45.

Counting in binary works like a mileage counter with only two digits per wheel. When a place passes 1, it rolls back to 0 and carries into the next place:

| Decimal | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Binary | 0 | 1 | 10 | 11 | 100 | 101 | 110 | 111 | 1000 |

Each binary digit is a **bit**. Eight bits make a **byte**, which is exactly what a `UInt8` holds: from 00000000 (0) to 11111111 (255). Click the cells below to switch bits on and off, and watch the decimal and hexadecimal values change:

```visual bitPlayground

```

The playground can also combine two values with an operator. Ignore that for now: M16 is all about it.

## Decimal to binary: divide by 2 and keep the remainders

Going the other way, from 45 to binary, uses repeated division. Divide by 2, write down the remainder, and carry on with the quotient until it reaches 0:

| Step | n | n / 2 | n % 2 |
| --- | --- | --- | --- |
| 1 | 45 | 22 | 1 |
| 2 | 22 | 11 | 0 |
| 3 | 11 | 5 | 1 |
| 4 | 5 | 2 | 1 |
| 5 | 2 | 1 | 0 |
| 6 | 1 | 0 | 1 |

Read the remainders from the **bottom up**: 101101. That matches the table above.

Why does it work? In decimal, `n % 10` is the last digit and `n / 10` removes it. In binary, `n % 2` is the last binary digit and `n / 2` removes it. The remainders come out last digit first, which is why you read them in reverse. The same loop converts to any base: divide by 8 for octal, by 16 for hexadecimal.

## Octal and hexadecimal

**Hexadecimal** (hex) is base 16. It needs sixteen digits, so after 0 to 9 it borrows letters: A is 10, B is 11, up to F, which is 15. The places are worth 1, 16, 256, 4,096…

```text
2D₁₆ = 2 × 16 + 13 × 1 = 45
```

Hex is popular because it's a compact way to write binary. One hex digit covers exactly four bits, since 16 is 2⁴. To convert, split the binary number into groups of four from the right:

```text
45 = 0010 1101₂
       2    D    →  2D₁₆
```

**Octal** is base 8, with digits 0 to 7. One octal digit covers three bits: 101 101₂ is 55₈. Octal is rare today; you'll mostly see it in Unix file permissions like `chmod 755`.

| Decimal | Binary | Hex |
| --- | --- | --- |
| 9 | 1001 | 9 |
| 10 | 1010 | A |
| 12 | 1100 | C |
| 15 | 1111 | F |
| 16 | 10000 | 10 |
| 255 | 11111111 | FF |

A colour like `#FF8800` is three bytes in hex: red FF (255), green 88 (136) and blue 00 (0).

## Writing numbers in other bases in Swift

Swift lets you write a number literal in binary, octal or hex with a prefix. Underscores can group digits anywhere, and Swift ignores them:

```swift run
let mask = 0b1011
let permissions = 0o755
let orange = 0xFF8800
let million = 1_000_000
print(mask, permissions, orange, million)
print(0b0010_1101 == 45)
```

```output
11 493 16746496 1000000
true
```

The prefix only changes how *you* write the value. The `Int` stored is the same, and `print` always shows decimal.

## Converting with the standard library

You met these in [Converting characters, digits and numbers](/dsa/learn/swift-char-digit-conversion). `String(_:radix:)` writes a number in any base from 2 to 36, and `Int(_:radix:)` reads one back. Reading can fail, so it returns an optional:

```swift run
print(String(45, radix: 2))
print(String(45, radix: 16))
print(String(45, radix: 16, uppercase: true))
print(Int("101101", radix: 2) ?? -1)
print(Int("2D", radix: 16) ?? -1)
print(Int("12", radix: 2) ?? -1)
print(String(-10, radix: 2))
```

```output
101101
2d
2D
45
45
-1
-1010
```

Notice the last two lines. `"12"` isn't valid binary, because 2 isn't a binary digit, so `Int` returns `nil`. And a negative number gets a minus sign in front. That's not how the computer actually stores negative numbers, which is a scheme called two's complement that M16 explains.

## Writing the conversion yourself

Interviewers like to ask for conversion without `radix:`, and the code is a good use of the division loop. To write `n` in base `base`, peel off the last digit with `%`, drop it with `/`, and reverse at the end:

```swift run
let symbols = Array("0123456789abcdef")

func toBase(_ number: Int, _ base: Int) -> String {
    var n = number
    var digits: [Character] = []
    repeat {
        digits.append(symbols[n % base])
        n /= base
    } while n > 0
    return String(digits.reversed())
}

print(toBase(45, 2))
print(toBase(45, 16))
print(toBase(0, 2))
```

```output
101101
2d
0
```

`repeat-while` makes sure 0 still produces one digit, `"0"`. The `symbols` array turns a digit value like 13 into the character `d`.

Reading a string in some base is the parsing loop from M08, with `base` in place of 10. Each new digit shifts the value so far one place left (multiply by the base) and adds itself:

```swift run
func fromBase(_ text: String, _ base: Int) -> Int? {
    var value = 0
    for ch in text {
        guard let digit = ch.hexDigitValue, digit < base else { return nil }
        value = value * base + digit
    }
    return value
}

print(fromBase("101101", 2) ?? -1)
print(fromBase("2d", 16) ?? -1)
print(fromBase("19", 8) ?? -1)
```

```output
45
45
-1
```

`Character.hexDigitValue` gives 0 to 15 for `0`–`9`, `a`–`f` and `A`–`F`, and `nil` for anything else, so this version handles bases up to 16. The `digit < base` check rejects `9` in octal. For `"101101"`, `value` goes 1, 2, 5, 11, 22, 45: double and add, six times.

Both functions do one step per digit. A number `n` has about log₂ n binary digits, so converting it takes O(log n) time. You'll see exactly why in *Series sums and logarithms*, later in this module.

## How many values fit in k digits?

With k digits in base b you can write b^k different values, from 0 up to `b^k - 1`. Three decimal digits give 1,000 values, 000 to 999. In binary:

| Bits | Values | Largest unsigned value |
| --- | --- | --- |
| 8 | 256 | 255 |
| 16 | 65,536 | 65,535 |
| 32 | about 4.3 billion | 4,294,967,295 |
| 64 | about 1.8 × 10¹⁹ | 18,446,744,073,709,551,615 |

That's where the limits of `UInt8`, `UInt32` and `UInt64` come from. It also tells you that a million needs 20 bits, because 2²⁰ is 1,048,576.

<Callout kind="gotcha" title="Swift gotcha: Int(_:radix:) is strict">
`Int("0x2D", radix: 16)` is `nil`: the `0x` prefix is for literals in code, not for parsing. Spaces also give `nil`, and so does any digit that's too big for the base, like `"8"` in octal. A leading `-` is allowed, and so are leading zeros: `Int("0042", radix: 10)` is 42.
</Callout>
