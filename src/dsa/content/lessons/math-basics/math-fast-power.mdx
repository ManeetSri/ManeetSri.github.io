## Why it matters

"Compute 2 to the power 10¹⁸, modulo 10⁹ + 7." Multiplying by 2 a quintillion times would take centuries. **Fast exponentiation**, also called binary exponentiation or exponentiation by squaring, does it in about 60 steps. It's at the heart of RSA encryption, it's how you'll divide in modular arithmetic in M66, and the same idea computes the billionth Fibonacci number almost instantly with matrices. It's also a perfect example of an O(log n) algorithm: doubling your way to the answer instead of crawling.

## The slow way

Swift has no integer power operator, so the obvious version multiplies in a loop:

```swift run
func slowPower(_ base: Int, _ exponent: Int) -> Int {
    var result = 1
    for _ in 0..<exponent {
        result *= base
    }
    return result
}

print(slowPower(3, 4), slowPower(2, 10), slowPower(7, 0))
```

```output
81 1024 1
```

That's one multiplication per unit of exponent, so O(b) for an exponent b. Fine for b = 10, hopeless for b = 10¹⁸. Note that anything to the power 0 is 1, which is why `result` starts at 1.

## Squaring skips ahead

Squaring doubles the exponent in a single multiplication:

```text
3¹ → 3² → 3⁴ → 3⁸ → 3¹⁶
     (3¹)²  (3²)²  (3⁴)²  (3⁸)²
```

Four multiplications reach 3¹⁶, where the slow loop needs fifteen. Each squaring doubles the exponent, so after k squarings you've reached the power 2^k.

That only gives exponents that are powers of two. For any other exponent, use **binary**, from [Number systems and conversion](/dsa/learn/math-number-systems). 13 is 1101₂, which is 8 + 4 + 1, so:

```text
3¹³ = 3⁸ × 3⁴ × 3¹
```

Square your way through 3¹, 3², 3⁴, 3⁸, and multiply together the ones where the exponent has a 1 bit. That's the whole algorithm.

## The recursive view

Here's the same idea as a recursive rule, which is often the easiest way to remember it:

- if n is even, xⁿ = (x^(n/2))²;
- if n is odd, xⁿ = x × (x^(n/2))², using integer division for n / 2;
- x⁰ = 1.

```swift run
func power(_ x: Int, _ n: Int) -> Int {
    if n == 0 {
        return 1
    }
    let half = power(x, n / 2)
    return n % 2 == 0 ? half * half : half * half * x
}

print(power(3, 13), power(2, 10))
```

```output
1594323 1024
```

Each call halves n: power(3, 13) calls power(3, 6), which calls power(3, 3), then power(3, 1), then power(3, 0). That's about log₂ n calls. Computing `half` once and using it twice is essential. Writing `power(x, n / 2) * power(x, n / 2)` would make two calls each time, and the total work would grow back to O(n).

## The iterative version

The loop version reads the exponent's bits from right to left with `% 2` and `/ 2`, exactly like converting to binary. `square` holds 3¹, 3², 3⁴, 3⁸ in turn, and whenever the current bit is 1, it's multiplied into the result:

```swift run
func power(_ base: Int, _ exponent: Int) -> Int {
    var result = 1
    var square = base
    var e = exponent
    while e > 0 {
        if e % 2 == 1 {
            result *= square
        }
        e /= 2
        if e > 0 {
            square *= square
        }
    }
    return result
}

print(power(3, 13), power(2, 62), power(-2, 5))
```

```output
1594323 4611686018427387904 -32
```

Here's the trace for 3¹³, with e = 13 = 1101₂:

| e at the start | Lowest bit | square | result afterwards |
| --- | --- | --- | --- |
| 13 | 1 | 3 | 3 |
| 6 | 0 | 9 | 3 |
| 3 | 1 | 81 | 3 × 81 = 243 |
| 1 | 1 | 6,561 | 243 × 6,561 = 1,594,323 |

The bits of 13, read from the right, are 1, 0, 1, 1, so the result collects 3¹, 3⁴ and 3⁸.

### Why `if e > 0` before squaring?

Without that check, the loop squares one extra time after it has finished with the last bit. The result doesn't need that square, but computing it can overflow. For 2⁶², the unneeded square is 2⁶⁴, which doesn't fit in an `Int`, so the program would trap even though the answer, 2⁶², fits:

```text title="What you'll see without the check"
Swift runtime failure: arithmetic overflow
```

In the modular version below, everything stays below m, so the extra square is harmless and the check isn't needed.

## Modular fast power

Combine this with [Modular arithmetic](/dsa/learn/math-modular-arithmetic): reduce after every multiplication, and the numbers never grow beyond m.

```swift run
func modPow(_ base: Int, _ exponent: Int, _ m: Int) -> Int {
    var result = 1 % m
    var square = ((base % m) + m) % m
    var e = exponent
    while e > 0 {
        if e % 2 == 1 {
            result = result * square % m
        }
        square = square * square % m
        e /= 2
    }
    return result
}

print(modPow(2, 1_000_000_000_000_000_000, 1_000_000_007))
print(modPow(3, 200, 1000))
print(modPow(-2, 3, 5))
print(modPow(10, 0, 1))
```

```output
719476260
1
2
0
```

What to notice:

- **`((base % m) + m) % m`** reduces the base first and fixes negatives. (−2)³ = −8, and −8 modulo 5 is 2.
- **`1 % m`** rather than 1 handles m = 1, where every remainder is 0.
- **Operands stay below m**, so with m below 2³¹, `result * square` and `square * square` can't overflow.
- 3²⁰⁰ ends in …001, so its remainder modulo 1,000 is 1.

## How fast is it?

The loop runs once per bit of the exponent, and halving b each time gives about log₂ b passes, each with at most two multiplications. So fast power is **O(log b)**:

| Exponent b | Slow loop | Fast power |
| --- | --- | --- |
| 1,000 | 1,000 multiplications | at most 20 |
| 10⁹ | 10⁹ multiplications | at most 60 |
| 10¹⁸ | 10¹⁸ multiplications | at most 120 |

Doubling the exponent adds only one more pass. That's the power of halving, which you'll lean on again in binary search.

## The same trick with addition

Nothing in the algorithm is specific to multiplication. Swap × for + and 1 for 0, and you get **multiplication by repeated doubling**: a × b computed with O(log b) additions. That's useful for a × b modulo a huge m, where the product itself would overflow but a sum of two values below m wouldn't:

```swift run
func mulMod(_ a: Int, _ b: Int, _ m: Int) -> Int {
    var result = 0
    var doubled = a % m
    var times = b
    while times > 0 {
        if times % 2 == 1 {
            result = (result + doubled) % m
        }
        doubled = (doubled + doubled) % m
        times /= 2
    }
    return result
}

print(mulMod(999_999_999_999, 999_999_999_999, 1_000_000_000_007))
```

```output
64
```

It works whenever 2m fits in an `Int`, so for m up to about 4.6 × 10¹⁸. It's slower than one multiplication, but it never overflows. The pattern "combine pieces for each 1 bit, double for each step" turns up again in M47 as **binary lifting**, for jumping up a tree in big steps.

The same is true of anything you can multiply: matrices too. Raising a small matrix to the power n with this algorithm gives the nth Fibonacci number in O(log n) steps, as you'll preview in *Matrix basics*, the last lesson of this module.

<Callout kind="gotcha" title="Swift gotcha: pow works on Double">
Foundation's `pow(3.0, 34.0)` returns a `Double`, which only has 53 bits of precision. `Int(pow(3.0, 34.0))` gives 16677181699666570, but the exact answer is 16677181699666569. For whole-number powers, write your own integer `power`, and for anything modular, always use `modPow`.
</Callout>
