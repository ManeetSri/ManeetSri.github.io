## Why it matters

Lots of data is numbered from 1 to n: seat numbers, ticket numbers, page numbers, the IDs of the n players in a game. When an array is supposed to hold exactly those numbers, you know the sorted answer before you start: 1 goes at index 0, 2 at index 1, and n at index n − 1. **Cyclic sort** uses that to sort in O(n) time and O(1) extra memory, by sending each value straight to its home. Better still, once everything that can go home has gone home, the values that **don't** fit show you exactly what's missing and what's repeated. That makes it the go-to pattern for a whole family of interview problems: the missing number, all missing numbers, the duplicate, all duplicates, and the "set mismatch" with one of each.

## Every value has a home

If an array holds the numbers 1 to n, each exactly once, then the value v belongs at index **v − 1**. No comparisons are needed to work that out. So walk through the array, and while the value at index i isn't at home, swap it into its home. The value that comes back from the swap might not be home either, so look at index i again. Only when index i holds the right value do you move on:

```swift run
func cyclicSort(_ numbers: inout [Int]) {
    var i = 0
    while i < numbers.count {
        let home = numbers[i] - 1                 // where numbers[i] belongs
        if numbers[i] != numbers[home] {
            numbers.swapAt(i, home)
            print("send \(numbers[home]) to index \(home):", numbers)
        } else {
            i += 1                                // index i is settled: move on
        }
    }
}

var seats = [3, 5, 2, 1, 4]
cyclicSort(&seats)
```

```output
send 3 to index 2: [2, 5, 3, 1, 4]
send 2 to index 1: [5, 2, 3, 1, 4]
send 5 to index 4: [4, 2, 3, 1, 5]
send 4 to index 3: [1, 2, 3, 4, 5]
```

Step through it. Amber is the value that just came back to index i, and green values are home:

```visual arrayTrace
program: cyclicSort
input:
  items: [3, 5, 2, 1, 4]
```

All four swaps happened while i was 0. Each swap sent one value home, and brought back a value that belonged somewhere else. When 1 finally arrived at index 0, it was home, and i walked through the rest of the array without another swap: every value was already in place.

<Callout kind="analogy">
Imagine a row of numbered lockers, with everyone's bag in the wrong one. Open locker 1, take out the bag, and carry it to its owner's locker. Swap it for the bag in there, and carry that one home too. Keep going until you're holding the bag that belongs in locker 1. Then move on to locker 2, which may already be sorted.
</Callout>

## Why it's O(n)

The `while` loop can stay on the same i for many steps, so it might look like it could be slow. Count the two kinds of step:

- **A swap** puts one value in its home, and a value at home is never moved again (the check `numbers[i] != numbers[home]` refuses to swap it). So there are at most n swaps in total.
- **A move on** (`i += 1`) happens exactly n times.

That's at most 2n steps: **O(n)** time, and the only extra memory is `i` and `home`: **O(1)**. Count them on 10,000 mixed-up values:

```swift run
var numbers = (0..<10_000).map { ($0 * 7_919) % 10_000 + 1 }     // 1 to 10,000, mixed up
var swaps = 0
var steps = 0
var i = 0
while i < numbers.count {
    steps += 1
    let home = numbers[i] - 1
    if numbers[i] != numbers[home] {
        numbers.swapAt(i, home)
        swaps += 1
    } else {
        i += 1
    }
}
print("swaps:", swaps, "steps:", steps, "sorted:", numbers == Array(1...10_000))
```

```output
swaps: 9863 steps: 19863 sorted: true
```

Steps are exactly swaps plus n, as promised.

### Cycles, and the fewest swaps

Why "cyclic"? In `[3, 5, 2, 1, 4]`, follow where each value wants to go: index 0 holds 3, which wants index 2; index 2 holds 2, which wants index 1; index 1 holds 5, which wants index 4; index 4 holds 4, which wants index 3; and index 3 holds 1, which wants index 0, where you started. The values form a **cycle**, and sorting it took 4 swaps for 5 values. In general, a cycle of length L takes L − 1 swaps, so cyclic sort makes **n minus the number of cycles** swaps. (The 10,000 values above form 137 cycles, hence 9,863 swaps.) No method can do it in fewer: a single swap can split one cycle into two at most, and a sorted array is n cycles of length 1. So cyclic sort also answers "what's the fewest swaps that sorts this?", which is one of this lesson's practice problems.

## Repeats and gaps

Now the interesting part. Suppose the values are still between 1 and n, but some appear twice and others not at all. Then two copies of a value compete for one home. The first gets it; when the second comes along, `numbers[i] != numbers[home]` is false, because its home already holds an equal value. So it stays where it is and i moves on.

When the loop finishes, every value that appears is at home, and the leftover copies sit in the homes of the missing values. One scan reads off both:

```swift run
func missingAndRepeated(_ input: [Int]) -> (missing: [Int], repeated: [Int]) {
    var numbers = input                           // work on a copy, leaving the caller's array alone
    var i = 0
    while i < numbers.count {
        let home = numbers[i] - 1
        if numbers[i] != numbers[home] {
            numbers.swapAt(i, home)
        } else {
            i += 1
        }
    }
    print("after cyclic sort:", numbers)
    var missing: [Int] = []
    var repeated: [Int] = []
    for index in numbers.indices where numbers[index] != index + 1 {
        missing.append(index + 1)                 // nobody lives here…
        repeated.append(numbers[index])           // …except a spare copy
    }
    return (missing, repeated)
}

let result = missingAndRepeated([5, 3, 1, 3, 6, 1])
print("missing:", result.missing, "repeated:", result.repeated)
```

```output
after cyclic sort: [1, 1, 3, 3, 5, 6]
missing: [2, 4] repeated: [1, 3]
```

Index 1 should hold 2, but holds a spare 1. Index 3 should hold 4, but holds a spare 3. So 2 and 4 are missing, and 1 and 3 are repeated. When values can appear more than twice, a repeated value can show up at several wrong indexes, so collect the repeats in a set or skip ones you've already reported.

## The family of problems

Every problem in the family is one cyclic sort, then a different question for the final scan:

| Problem | The values | After cyclic sort, look for |
| --- | --- | --- |
| All missing numbers | n values from 1 to n, with repeats | each index i where the value isn't i + 1: i + 1 is missing |
| All duplicates | n values from 1 to n, some twice | the values sitting at those wrong indexes |
| Set mismatch | 1 to n with one value doubled and one missing | the single wrong index: its value is doubled, i + 1 is missing |
| Find the duplicate | n + 1 values from 1 to n | stop as soon as a value's home already holds a copy of it |
| The missing number | n different values from 0 to n | value v belongs at index v; the first index i not holding i is missing |

Two of these deserve a closer look.

### The missing number, from 0 to n

With values from 0 to n in an array of n slots, value v belongs at index v. But the value n has no home: index n doesn't exist. So leave it wherever it lands. After sorting, the first index i that doesn't hold i is the missing number, and if every index is right, the missing number is n:

```swift run
func missingNumber(_ input: [Int]) -> Int {
    var numbers = input
    var i = 0
    while i < numbers.count {
        let home = numbers[i]                     // value v belongs at index v
        if home < numbers.count && numbers[i] != numbers[home] {
            numbers.swapAt(i, home)
        } else {
            i += 1                                // already home, or it's n, which has no home
        }
    }
    for index in numbers.indices where numbers[index] != index {
        return index
    }
    return numbers.count
}

print(missingNumber([4, 0, 3, 1]))
print(missingNumber([1, 0]))
```

```output
2
2
```

For exactly one missing number, the XOR or sum trick from [XOR tricks](/dsa/learn/bits-xor-tricks) is simpler and doesn't rearrange anything. Cyclic sort earns its keep when several numbers are missing, or when you need the duplicates too.

### Find the duplicate

Put n + 1 values from 1 to n into an array, and the [pigeonhole principle](/dsa/learn/math-pigeonhole) says some value must repeat. Cyclic sort finds it the moment two copies collide:

```swift run
func findDuplicate(_ input: [Int]) -> Int? {
    var numbers = input
    var i = 0
    while i < numbers.count {
        let home = numbers[i] - 1
        if home == i {
            i += 1                                // already home
        } else if numbers[home] == numbers[i] {
            return numbers[i]                     // its home is taken by a copy of itself
        } else {
            numbers.swapAt(i, home)
        }
    }
    return nil
}

print(findDuplicate([2, 5, 1, 4, 5, 3]) ?? 0)
print(findDuplicate([1, 4, 4, 2, 4]) ?? 0)
```

```output
5
4
```

If you're not allowed to rearrange the array at all and must still use O(1) memory, there's a beautiful alternative: treat each value as a "next" pointer to an index, and the duplicate is where the resulting linked list loops back on itself. Floyd's cycle detection from [Fast and slow pointers](/dsa/learn/ll-fast-slow) finds it.

## It rearranges the caller's data

Cyclic sort works by swapping the input's values around. That's what makes it O(1) memory, but it means the caller's array changes. You have three options:

- **Take the array `inout`**, so the caller knowingly hands it over to be rearranged. That's the honest O(1)-memory version, and the practice problems use it.
- **Work on a copy**, as most examples above do with `var numbers = input`. Swift's arrays are copied lazily, so the copy happens on the first swap, and it costs O(n) memory. At that point, a plain array of n + 1 `Bool` flags would work just as well and might be clearer.
- **Restore it afterwards**, if the original order matters and memory is tight. That's rarely worth the effort.

<Callout kind="gotcha" title="Swift gotcha: check the value, not the index">
It's tempting to write the swap condition as `if home != i`: "swap if this value isn't at its home index". With repeats, that loops forever. On `[1, 1]`, at i = 1 the value 1 has home 0, which isn't 1, so it swaps index 1 with index 0, which also holds a 1. Nothing changes, and it swaps again, and again. Compare the **values**, `numbers[i] != numbers[home]`: when the home already holds an equal value, there's nothing to gain, so move on.

And never trust the input blindly: a 0 or a value above n gives an index out of range. When the input might contain such values, check the range first, as next lesson's problem does.
</Callout>
