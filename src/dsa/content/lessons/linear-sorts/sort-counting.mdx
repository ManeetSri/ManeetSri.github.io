## Why it matters

M31's [lower bound lesson](/dsa/learn/sort-lower-bound) shows that every comparison sort needs about n log n comparisons in the worst case. That limit only applies to sorts that learn by comparing. If the keys are small integers, like exam scores out of 100, ages, star ratings, days of the week or letters, you can skip comparing altogether: count how many of each key there are, and the sorted order falls out. That's **counting sort**, and it runs in O(n + k), where k is the number of possible keys. It's also the building block for radix sort, next lesson, and the stable placement trick it uses turns up all over DSA.

## Counting instead of comparing

Suppose every value is between 0 and some small maximum. Make an array of counters, one per possible value. Walk the input once, adding 1 to each value's counter. Then walk the counters in order, writing each value out as many times as it was counted:

```swift run
func countingSort(_ items: [Int], maxValue: Int) -> [Int] {
    var counts = [Int](repeating: 0, count: maxValue + 1)
    for value in items {
        counts[value] += 1
    }
    print("counts:", counts)
    var sorted: [Int] = []
    for value in 0...maxValue {
        sorted += Array(repeating: value, count: counts[value])
    }
    return sorted
}

print(countingSort([4, 2, 2, 8, 3, 3, 1], maxValue: 8))
```

```output
counts: [0, 1, 2, 2, 1, 0, 0, 0, 1]
[1, 2, 2, 3, 3, 4, 8]
```

`counts[2]` is 2 because 2 appears twice. Reading the counts from left to right gives the values in increasing order, because the array's own indexes are in order. Not a single comparison between two elements happened. It's the [26 slots trick](/dsa/learn/swift-frequency-arrays) from M08, used to sort instead of to count.

Step through it: a counting pass, then a writing pass.

## O(n + k), and why k matters

There are two loops:

- counting walks the n input values: O(n);
- writing walks all k counters, and writes n values in total: O(n + k).

So counting sort is **O(n + k)** time, with O(k) memory for the counters. When k is small, or at least not much bigger than n, that's linear. A million exam scores out of 100 means a million increments and 101 counters: far faster than any comparison sort.

But k is the catch. Ten numbers that happen to be up to a billion need a billion counters: 8 GB of memory, almost all of them zero, to sort ten numbers. Counting sort is only a good idea when the **range** of keys is small. A good rule of thumb: use it when k is no more than a small multiple of n.

| Data | n | k | Counting sort? |
| --- | --- | --- | --- |
| exam scores out of 100 | 1,000,000 | 101 | yes |
| ages of app users | 50,000 | about 120 | yes |
| letters of a word | 30 | 26 | yes |
| 10 phone numbers | 10 | 10 billion | no |
| prices in pence, up to £10,000 | 500 | 1,000,001 | probably not |

## Negative numbers: shift by the minimum

Counters are indexed from 0, so a value of −3 has nowhere to go. The fix is to count in slot `value - min` instead. The smallest value lands in slot 0, and the counts array needs `max - min + 1` slots, the size of the range:

```swift run
func countingSort(_ items: [Int]) -> [Int] {
    guard let low = items.min(), let high = items.max() else { return [] }
    var counts = [Int](repeating: 0, count: high - low + 1)
    for value in items {
        counts[value - low] += 1                 // the smallest value goes in slot 0
    }
    var sorted: [Int] = []
    sorted.reserveCapacity(items.count)
    for (offset, times) in counts.enumerated() {
        sorted += Array(repeating: low + offset, count: times)
    }
    return sorted
}

let overnightLows = [3, -2, 0, -2, 5, 1]
print(countingSort(overnightLows))
print(countingSort([]))
```

```output
[-2, -2, 0, 1, 3, 5]
[]
```

The range here is −2 to 5, so there are 8 counters. Shifting also helps when the values are big but close together: years from 1990 to 2030 need 41 counters, not 2,031.

## Sorting records: stable placement with prefix sums

The version above rebuilds the values from the counts. That's fine for plain numbers, because one 3 is as good as another. Records are different: you need to move the **records themselves**, and you want equal keys to keep their input order. Here's the stable version, in three steps:

1. **Count** each key.
2. **Turn the counts into starting positions.** Records with key 0 start at position 0. Records with key 1 start right after all the key-0 records, and so on. Each start is the total of the counts before it: a running total, exactly the prefix sums of [1D prefix sums](/dsa/learn/prefix-1d), shifted one place so it excludes the key itself.
3. **Place** the records. Walk the input in order. Put each record at its key's next free position, then move that position on by one.

```swift run
struct Parcel {
    let id: String
    let service: Int        // 0 express, 1 standard, 2 economy
}

func sortByService(_ parcels: [Parcel], services: Int) -> [Parcel] {
    // 1. Count each key
    var next = [Int](repeating: 0, count: services)
    for parcel in parcels {
        next[parcel.service] += 1
    }
    print("counts:", next)
    // 2. Turn the counts into starting positions: the total of the counts before each key
    var total = 0
    for key in 0..<services {
        let count = next[key]
        next[key] = total
        total += count
    }
    print("starts:", next)
    // 3. Place each parcel at its key's next free position, in input order
    var result = parcels                         // placeholder values: every slot gets overwritten
    for parcel in parcels {
        result[next[parcel.service]] = parcel
        next[parcel.service] += 1
    }
    return result
}

let parcels = [
    Parcel(id: "A", service: 1), Parcel(id: "B", service: 0), Parcel(id: "C", service: 2),
    Parcel(id: "D", service: 1), Parcel(id: "E", service: 0), Parcel(id: "F", service: 1),
]
let sorted = sortByService(parcels, services: 3)
print(sorted.map { "\($0.id)\($0.service)" })
```

```output
counts: [2, 3, 1]
starts: [0, 2, 5]
["B0", "E0", "A1", "D1", "F1", "C2"]
```

What to notice:

- Two express parcels go in positions 0 and 1, so standard starts at 2. Three standard parcels take 2, 3 and 4, so economy starts at 5.
- Within each service, the parcels are in input order: A before D before F. They were placed in the order they were read, each one after the last. That's what makes this version **stable**.
- It's still O(n + k): one pass to count, one over the k keys, one to place.
- `var result = parcels` is a quick way to get an array of the right size and type. Every slot is overwritten in step 3.

Textbooks often write step 2 as an *inclusive* running total and walk the input **backwards** in step 3, placing each record at the end of its key's block. It's the same algorithm seen from the other end, and also stable.

This stable version is the one radix sort is built on.

## Letters: 26 slots

Sorting the letters of a lowercase word is counting sort with k = 26. It's O(n) instead of the O(n log n) of `sorted()`, and it gives a handy key for spotting anagrams, as in [Anagrams and group anagrams](/dsa/learn/str-anagrams):

```swift run
func sortedLetters(_ word: String) -> String {
    var counts = [Int](repeating: 0, count: 26)
    for letter in word {
        counts[Int(letter.asciiValue! - 97)] += 1     // lowercase a to z only
    }
    var result = ""
    for slot in 0..<26 where counts[slot] > 0 {
        let letter = Character(UnicodeScalar(UInt8(97 + slot)))
        result += String(repeating: letter, count: counts[slot])
    }
    return result
}

print(sortedLetters("banana"))
print(sortedLetters("listen") == sortedLetters("silent"))
```

```output
aaabnn
true
```

## DSAKit's countingSorted

Your package has `countingSorted()` on `[Int]`, in `dsa-swift/Sources/DSAKit/LinearSorts.swift`. It returns a new sorted array, handles negative numbers by shifting by the minimum, and refuses, with a clear precondition failure, a range too wide to count.

```swift
import DSAKit

let scores = [88, 92, 75, 88, 100, 61]
print(scores.countingSorted())                 // [61, 75, 88, 88, 92, 100]
print([3, -1, 2, -1].countingSorted())         // [-1, -1, 2, 3]
```

<Callout kind="gotcha" title="Swift gotcha: the range itself can overflow">
`high - low + 1` is an `Int` calculation, and for values spread across the whole `Int` range it doesn't fit: `[Int.min, Int.max]` makes it overflow, and Swift stops the program. Long before that, a range of a few billion would ask for gigabytes of counters. Check the range first, and use radix sort or the standard library's sort when it's wide.
</Callout>
