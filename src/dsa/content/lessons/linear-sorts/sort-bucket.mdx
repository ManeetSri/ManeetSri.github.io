## Why it matters

Counting sort gives every possible key its own slot. **Bucket sort** gives each slot a whole **range** of keys instead: spread the values across a row of buckets, sort each bucket (they're small), and read the buckets out in order. When the values are spread evenly, every bucket holds only a few, and the whole sort takes O(n) on average. The same idea of "drop each item in a bucket by a number you can compute" is how hash tables work, as [Collisions](/dsa/learn/hash-collisions) showed, and it solves "find the k most frequent items" in O(n) without any sorting at all.

## Spreading values across buckets

The classic setting is n values spread evenly between 0 and 1, such as random numbers or percentages written as fractions. Make n buckets. Bucket 0 takes values from 0 up to 1/n, bucket 1 the next 1/n, and so on. A value v goes in bucket `Int(v * Double(n))`. Then sort each bucket with insertion sort, which is ideal for a handful of elements, and join the buckets together:

```swift run
func insertionSort(_ items: inout [Double]) {
    guard items.count > 1 else { return }
    for i in 1..<items.count {
        let key = items[i]
        var gap = i
        while gap > 0 && items[gap - 1] > key {
            items[gap] = items[gap - 1]
            gap -= 1
        }
        items[gap] = key
    }
}

func bucketSort(_ values: [Double]) -> [Double] {
    let n = values.count
    guard n > 1 else { return values }
    var buckets = [[Double]](repeating: [], count: n)
    for value in values {
        buckets[Int(value * Double(n))].append(value)      // a value in [0, 1) lands in 0 to n - 1
    }
    for (index, bucket) in buckets.enumerated() where !bucket.isEmpty {
        print("bucket \(index):", bucket)
    }
    var result: [Double] = []
    for var bucket in buckets {
        insertionSort(&bucket)
        result += bucket
    }
    return result
}

print(bucketSort([0.42, 0.32, 0.23, 0.52, 0.25, 0.47, 0.51, 0.08]))
```

```output
bucket 0: [0.08]
bucket 1: [0.23]
bucket 2: [0.32, 0.25]
bucket 3: [0.42, 0.47]
bucket 4: [0.52, 0.51]
[0.08, 0.23, 0.25, 0.32, 0.42, 0.47, 0.51, 0.52]
```

What to notice:

- With 8 values, each bucket covers an eighth: bucket 2 is 0.25 up to 0.375, so it holds 0.32 and 0.25.
- Every value in bucket 2 is smaller than every value in bucket 3. So once each bucket is sorted, reading them in order gives a sorted whole. No merging needed.
- The buckets are tiny, so sorting each one is quick. `for var bucket in buckets` gives a mutable copy of each bucket to sort.

## O(n) on average, O(n²) at worst

Spreading the values is O(n), and so is joining the buckets. The question is how long sorting the buckets takes.

- **Evenly spread values.** Each bucket holds about one value on average. A bucket with b values costs about b² to insertion-sort, and even counting the unlucky buckets that get two or three, the total stays proportional to n. So bucket sort is **O(n) on average**, when the values are uniformly spread.
- **Clustered values.** If every value falls between 0.50 and 0.51, they all land in one bucket, and bucket sort becomes insertion sort on the whole array: **O(n²)** in the worst case.

You can cap the worst case by sorting each bucket with `sort()` instead, making it O(n log n). But the real lesson is that bucket sort's speed depends on **knowing how your data is spread**. Counting sort and radix sort don't care how the values are distributed; bucket sort does.

## Other ranges

Values don't have to lie between 0 and 1. For integers from `low` to `high`, spread them across m buckets with:

```swift
let bucket = (value - low) * m / (high - low + 1)          // 0 to m - 1
```

Each bucket then covers an equal slice of the range. Choose m around n, so that evenly spread values give about one per bucket. (For huge ranges, `(value - low) * m` can overflow; dividing first, or using a `Double`, avoids that.)

## Bucketing by frequency: the k most frequent without a heap

Here's bucketing at its most useful. Given a list of words, return the k that appear most often. Sorting all the distinct words by their counts works, at O(m log m) for m distinct words. But look at the counts themselves: every count is between 1 and n, the number of words. That's a small range, so put the words in **buckets indexed by count**, and walk the buckets from n down to 1:

```swift run
func topFrequent(_ words: [String], k: Int) -> [String] {
    var counts: [String: Int] = [:]
    var firstSeen: [String] = []                 // each word once, in order of first appearance
    for word in words {
        if counts[word] == nil { firstSeen.append(word) }
        counts[word, default: 0] += 1
    }
    // buckets[f] holds the words that appear exactly f times
    var buckets = [[String]](repeating: [], count: words.count + 1)
    for word in firstSeen {
        buckets[counts[word]!].append(word)
    }
    var result: [String] = []
    for frequency in stride(from: words.count, through: 1, by: -1) {
        for word in buckets[frequency] where result.count < k {
            result.append(word)
        }
    }
    return result
}

let tags = ["swift", "ios", "swift", "dsa", "ios", "swift", "ui", "dsa", "ios"]
print(topFrequent(tags, k: 2))
print(topFrequent(tags, k: 3))
```

```output
["swift", "ios"]
["swift", "ios", "dsa"]
```

What to notice:

- Counting uses a dictionary, the frequency map from [frequency maps and two sum](/dsa/learn/hash-frequency-two-sum). That's O(n).
- `buckets[3]` holds `["swift", "ios"]`, `buckets[2]` holds `["dsa"]` and `buckets[1]` holds `["ui"]`. There are n + 1 buckets, most of them empty, and walking them all is O(n).
- The words are dropped into buckets in order of first appearance, not by looping over the dictionary, whose order changes from run to run. That makes ties come out in a predictable order: "swift" before "ios".
- In total it's **O(n)**. A heap, which you'll meet in M39, solves the same problem in O(n log k), and is the better tool when the counts arrive as a stream.

## When to use bucket sort

- Values you know are spread **evenly** over a known range: random numbers, hash values, readings from a sensor with a known range.
- Splitting a big job into independent pieces: each bucket can be sorted separately, even on a different machine, then the results joined. Large-scale sorting systems use this idea.
- Ranking by a count or score with a **small range**, as in the frequency buckets above.
- Bucket boundaries also carry information on their own. The widest gap between sorted neighbours can be found with buckets alone, without sorting, by the [pigeonhole principle](/dsa/learn/math-pigeonhole): that's this lesson's hard practice problem.

<Callout kind="gotcha" title="Swift gotcha: a value of exactly 1.0 has no bucket">
`Int(value * Double(n))` maps the range from 0 up to (but not including) 1 onto buckets 0 to n − 1. A value of exactly 1.0 gives bucket n, one past the end, and the program stops with "Index out of range". If your data can include the top of its range, clamp the index: `min(Int(value * Double(n)), n - 1)`. A negative value is worse still: it gives a negative index. Check your data's real range before trusting the formula.
</Callout>
