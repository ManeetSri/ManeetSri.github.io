## Why it matters

So far, every problem has asked you to *minimise* something. Now flip it: **maximise the minimum**. Place k charging points along a motorway so the closest pair is as far apart as possible. Spread k reminders through a day so no two are too close together. Space adverts in a feed so they're never bunched up. The classic interview versions are the aggressive cows problem and the "magnetic force between balls" problem, which are the same problem. This is the "largest x that works" form from [The monotonic predicate idea](/dsa/learn/bsa-idea), with one new step: sort first.

## The problem

A farmer has stalls along a straight barn at positions such as `[3, 14, 1, 9, 6, 17]`, all different and in no particular order. The cows are aggressive and fight when they're close, so the farmer puts c of them in different stalls, keeping the **closest pair as far apart as possible**. What's that largest possible minimum distance?

With 3 cows, putting them at 1, 9 and 17 gives distances 8 and 8, so the closest pair is 8 apart. You can't do better: three cows make two gaps, and the stalls only span 16, so the smaller gap is at most 8.

## Flip it into a yes/no question

Ask of each candidate distance d: **can c cows be placed so that every pair is at least d apart?**

- A small d is easy: with d = 1, any c distinct stalls will do.
- A huge d is impossible.
- And if d works, every smaller d works too, with the very same placement.

So the predicate reads true, true, …, true, false, false, …: it's monotonic, and the answer is its **last true**.

## The check: place greedily from the left

Sort the stalls. Put the first cow in the leftmost stall. Then walk right, and put each next cow in the first stall that's at least d past the previous cow. If you place c cows, d works.

```swift run
func cowsPlaced(_ sortedStalls: [Int], gap: Int) -> [Int] {
    var chosen = [sortedStalls[0]]
    for stall in sortedStalls.dropFirst() where stall - chosen[chosen.count - 1] >= gap {
        chosen.append(stall)
    }
    return chosen
}

let stalls = [3, 14, 1, 9, 6, 17].sorted()
print(stalls)
for gap in [3, 5, 8, 9] {
    let chosen = cowsPlaced(stalls, gap: gap)
    print("gap \(gap): \(chosen.count) cows at \(chosen)")
}
```

```output
[1, 3, 6, 9, 14, 17]
gap 3: 5 cows at [1, 6, 9, 14, 17]
gap 5: 3 cows at [1, 6, 14]
gap 8: 3 cows at [1, 9, 17]
gap 9: 2 cows at [1, 14]
```

With 3 cows, gaps 3, 5 and 8 work, and 9 doesn't: the answer is 8. With 4 cows, gap 3 works but 5 doesn't.

Why is this greedy placement the best possible? It's "greedy stays ahead" once more, as in [Capacity to ship packages](/dsa/learn/bsa-shipping). Take any placement with every pair at least d apart, sorted from left to right. Greedy's first cow is in the leftmost stall, so it's at or to the left of the other placement's first cow. If greedy's cow number i is at or to the left of the other's cow number i, then the other's next cow is at least d past that, so it's a stall greedy is allowed to use too, and greedy takes the first such stall. So greedy's cow i + 1 is at or to the left of the other's. Greedy is never further right, so it fits at least as many cows.

## Honest bounds

**Low is 1.** The stalls are at different whole-number positions, so any c of them are at least 1 apart. (The problem promises c is at most the number of stalls.)

**High** could be the whole span, last stall minus first, which is the answer when c = 2. But you can do better with the [pigeonhole principle](/dsa/learn/math-pigeonhole): c cows make c − 1 gaps, and those gaps add up to at most the span. So the smallest gap is at most span / (c − 1), and anything bigger certainly fails.

## The solution

To find the last true, search for the **first gap that fails** and subtract 1. One past the pigeonhole bound is a gap that's known to fail, so it can be the top of the half-open range:

```swift run
func canPlace(_ cows: Int, in sortedStalls: [Int], gap: Int) -> Bool {
    var placed = 1
    var last = sortedStalls[0]
    for stall in sortedStalls.dropFirst() where stall - last >= gap {
        placed += 1
        last = stall
    }
    return placed >= cows
}

func largestMinimumGap(_ stalls: [Int], cows: Int) -> Int {
    let sorted = stalls.sorted()
    let span = sorted[sorted.count - 1] - sorted[0]
    var low = 1                                  // a gap of 1 always works
    var high = span / (cows - 1) + 1             // a gap this big always fails
    while low < high {
        let mid = low + (high - low) / 2
        if canPlace(cows, in: sorted, gap: mid) {
            low = mid + 1                        // mid works: the first failure is later
        } else {
            high = mid                           // mid fails: it could be the first failure
        }
    }
    return low - 1                               // the last gap that works
}

let stalls = [3, 14, 1, 9, 6, 17]
print(largestMinimumGap(stalls, cows: 2))
print(largestMinimumGap(stalls, cows: 3))
print(largestMinimumGap(stalls, cows: 4))
print(largestMinimumGap(stalls, cows: 6))
```

```output
16
8
3
2
```

What to notice:

- The branches look mirrored compared with the minimum problems: a **working** mid moves `low` up. That's because the predicate being searched is "fails", and a working mid means the first failure is further right.
- With all 6 cows, every stall is used, and the answer is the smallest distance between neighbours, 3 − 1 = 2.
- Sorting costs O(n log n). The search makes about log₂(span / (c − 1)) checks of O(n) each. In total, **O(n log n + n log(span))** time, and O(n) space for the sorted copy.

## Magnetic force between balls

The other famous version: baskets at given positions, m balls, and the magnetic force between two balls is the distance between their baskets. Place the balls to make the smallest force as large as possible. It's the same problem with the same code: baskets are stalls, balls are cows.

Many tutorials write this search in the closed style, with `while low <= high` and a separate `answer` variable updated whenever mid works. That's correct too. What matters is choosing one style and keeping its invariant straight, rather than mixing the two.

<Callout kind="tip" title="Say the predicate out loud">
In an interview, the hard part of this problem is spotting it. Saying "if a gap of d works, any smaller gap works too, so I can binary search on d" shows the interviewer you've seen the structure, before you write any code.
</Callout>

<Callout kind="gotcha" title="Forgetting to sort">
The greedy check walks the stalls from left to right, so they must be sorted. On the unsorted `[3, 14, 1, 9, 6, 17]` with gap 8, it places cows at 3 and 14, then never looks back at stall 1, and wrongly reports that gap 8 fails for 3 cows.
</Callout>
