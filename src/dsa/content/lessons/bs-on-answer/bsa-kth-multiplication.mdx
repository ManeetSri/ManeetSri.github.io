## Why it matters

"Find the kth smallest" is easy when you can list everything and sort it. But some collections are far too big to list: every product in a huge times table, every pairwise distance between a million points, every sum of one item from each of two long lists. Binary search on the answer handles these with a different question. Instead of *listing* values, it only needs to **count** how many values are at most x, and counting is often far easier than listing. This lesson's classic problem, the kth smallest number in a multiplication table, is a favourite in contests, and the same idea finds the kth smallest value in a sorted matrix.

## The problem

An m × n multiplication table has the value i × j in row i and column j, with both counting from 1. Here's the 3 × 4 table:

```text
      1   2   3   4
 1    1   2   3   4
 2    2   4   6   8
 3    3   6   9  12
```

List all m × n values in increasing order, **keeping duplicates**: 1, 2, 2, 3, 3, 4, 4, 6, 6, 8, 9, 12. The task is to return the kth value in that list. For k = 7 it's 4, and for k = 8 it's 6.

The brute force builds every value and sorts them: O(mn log(mn)) time and O(mn) memory. For a 30,000 × 30,000 table, that's 900 million values, over 7 GB of `Int`s, before sorting even starts.

## Counting instead of listing

How many entries of the table are at most x? Look at one row at a time. Row i holds i, 2i, 3i, …, n × i: the multiples of i. The multiples of i up to x number ⌊x / i⌋, but the row stops after n of them. So row i has **min(x / i, n)** entries that are ≤ x, and the whole table has the sum of that over the m rows. One count costs O(m).

```swift run
func entries(atMost x: Int, rows m: Int, columns n: Int) -> Int {
    var count = 0
    for i in 1...m {
        count += min(x / i, n)       // the multiples of i up to x, but at most n of them
    }
    return count
}

print((1...12).map { entries(atMost: $0, rows: 3, columns: 4) })
```

```output
[1, 3, 5, 7, 7, 9, 9, 10, 11, 11, 11, 12]
```

The counts for x = 1 to 12 never go down, because a bigger x can only include more entries. So "at least k entries are ≤ x" is false, …, false, true, …, true: a monotonic predicate.

And the kth smallest value v is exactly the **first x where the count reaches k**:

- At v itself, the count is at least k: v and everything before it in the sorted list are ≤ v.
- At any x smaller than v, every entry ≤ x comes before position k in the sorted list, so there are at most k − 1 of them.

## Why the answer is always in the table

The search tries every whole number from 1 to m × n, and many of them aren't in the table at all: 5, 7, 10 and 11 aren't in the 3 × 4 table. Could the search return one of them?

No. Suppose it returns x. Then count(x − 1) < k ≤ count(x), so the count **went up** between x − 1 and x. The count only goes up when x reaches a value that's in the table, so some entry equals x.

You can see it in the counts above. For k = 7, count(4) = 7 and count(5) = 7. Both are at least 7, but the search wants the *first* such x, and that's 4, which is in the table. The number 5 can never be a first true, because its count is the same as 4's.

<Callout kind="note" title="Why counting is easier than listing">
Counting entries ≤ x needs one division per row: O(m), with no memory. Listing them would need every value, and sorting them would need O(mn log(mn)). Binary search on the answer turns "find the kth" into about log₂(mn) counts.
</Callout>

## The solution

```swift run
func entries(atMost x: Int, rows m: Int, columns n: Int) -> Int {
    var count = 0
    for i in 1...m {
        count += min(x / i, n)
    }
    return count
}

func kthSmallest(rows m: Int, columns n: Int, k: Int) -> Int {
    var low = 1
    var high = m * n                     // the largest entry
    while low < high {
        let mid = low + (high - low) / 2
        if entries(atMost: mid, rows: m, columns: n) >= k {
            high = mid
        } else {
            low = mid + 1
        }
    }
    return low
}

print((1...12).map { kthSmallest(rows: 3, columns: 4, k: $0) })
print(kthSmallest(rows: 30_000, columns: 30_000, k: 450_000_000))
```

```output
[1, 2, 2, 3, 3, 4, 4, 6, 6, 8, 9, 12]
168028638
```

The first line rebuilds the sorted list from the 3 × 4 table, one search per k. The second finds the median of a 30,000 × 30,000 table without building it: about 30 counts of 30,000 rows each. The median is around 168 million, far below the halfway value of 450 million, because small products turn up much more often than big ones.

**Complexity:** about log₂(mn) checks of O(m) each, so O(m log(mn)) time and O(1) space. Two easy improvements:

- The table is symmetric, since i × j = j × i, so loop over the **shorter** side: O(min(m, n) × log(mn)).
- Once x / i is 0, every later row starts above x too, so you can stop the loop early.

## The same idea in a sorted matrix

A related classic: an n × n matrix whose rows and columns are each sorted in increasing order. Find its kth smallest value.

Counting entries ≤ x is the staircase walk from [Staircase search in a sorted matrix](/dsa/learn/matrix-staircase-search). Start at the bottom-left corner. If the entry is ≤ x, then so is everything above it in that column: add them all and move right. Otherwise, move up. Each step leaves a row or a column, so a count costs O(n).

```swift run
func countAtMost(_ x: Int, in matrix: [[Int]]) -> Int {
    var count = 0
    var row = matrix.count - 1
    var column = 0
    while row >= 0 && column < matrix[0].count {
        if matrix[row][column] <= x {
            count += row + 1             // this entry and everything above it
            column += 1
        } else {
            row -= 1
        }
    }
    return count
}

func kthSmallest(in matrix: [[Int]], k: Int) -> Int {
    var low = matrix[0][0]                                   // the smallest entry
    var high = matrix[matrix.count - 1][matrix[0].count - 1] // the largest entry
    while low < high {
        let mid = low + (high - low) / 2
        if countAtMost(mid, in: matrix) >= k {
            high = mid
        } else {
            low = mid + 1
        }
    }
    return low
}

let matrix = [
    [2, 5, 9],
    [4, 7, 13],
    [8, 11, 15],
]
print((1...9).map { kthSmallest(in: matrix, k: $0) })
```

```output
[2, 4, 5, 7, 8, 9, 11, 13, 15]
```

The same argument shows the answer is always an entry of the matrix, and the total is O(n log(max − min)). Another approach takes k values out of a min-heap, which you'll meet in Part V. That's better when k is small; binary search wins when k is large or the values span a modest range.

Counting searches like this appear in other "kth" problems too. For the kth smallest distance between pairs in an array, sort the array, then count the pairs at distance ≤ d with two pointers in O(n), and binary search on d.

<Callout kind="gotcha" title="Counting mistakes">
**Forgetting the cap.** Row i has ⌊x / i⌋ multiples of i up to x, but only n columns. Without `min(x / i, n)`, row 1 alone would count x entries for a large x.

**Using `> k` instead of `>= k`.** The kth smallest is the first x with *at least* k entries ≤ it. With `> k`, the search finds the (k + 1)th smallest instead, which is wrong whenever the two differ.

**Expecting distinct values.** Duplicates count separately: in the 3 × 4 table, 2, 3, 4 and 6 each appear twice. "The kth smallest distinct value" is a different problem.
</Callout>

**The kth entry of a times table** is this problem, with tables of up to 100,000 × 100,000. Its 10 billion entries would never fit in memory, so counting is the only way. Test your count against a sorted brute force on small tables first.
