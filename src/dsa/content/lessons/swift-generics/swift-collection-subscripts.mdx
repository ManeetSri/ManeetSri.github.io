## Why it matters

`numbers[2]`, `ages["Maneet"]`, `grid[row][column]`: square brackets are **subscripts**, and you can give your own types them. Going one step further, conforming to **`Collection`** makes a type indexable, safely re-traversable, and gives it `count`, `first`, `firstIndex(of:)`, slicing and every `Sequence` ability. Your data structures will feel exactly like the built-in ones.

## Subscripts

A **subscript** is declared like a computed property with parameters. It can have a getter and an optional setter. Here's a tic-tac-toe board that stores its nine cells in one flat array but lets you use row and column:

```swift run
struct Board {
    private var cells = Array(repeating: Character("."), count: 9)

    subscript(row: Int, column: Int) -> Character {
        get {
            cells[row * 3 + column]
        }
        set {
            cells[row * 3 + column] = newValue
        }
    }

    var picture: String {
        stride(from: 0, to: 9, by: 3)
            .map { String(cells[$0..<$0 + 3]) }
            .joined(separator: "\n")
    }
}

var board = Board()
board[1, 1] = "X"
board[0, 2] = "O"
board[2, 0] = "X"
print(board[1, 1])
print(board.picture)
```

```output
X
..O
.X.
X..
```

What to notice:

- `subscript(row: Int, column: Int) -> Character` declares it; you use it as `board[1, 1]`. There's no `func` and no name: the brackets are the name.
- Unlike functions, subscript parameters have **no argument labels** by default. You write `board[1, 1]`, not `board[row: 1, column: 1]`.
- The setter receives the assigned value as `newValue`, just like a computed property's setter.
- **Row-major storage**: row `r`, column `c` lives at index `r × width + c` in the flat array. Row 1, column 1 is index 4, the centre. One flat array is often faster than an array of arrays, and you'll see this trick again in grid and matrix problems.

### Read-only and labelled subscripts

A subscript with only a getter can drop the `get` keyword, like a read-only computed property. If you *want* a label, write it explicitly before the parameter name. Here's a popular helper that returns `nil` instead of crashing when an index is out of range:

```swift run
extension Array {
    subscript(safe index: Int) -> Element? {
        indices.contains(index) ? self[index] : nil
    }
}

let scores = [70, 85, 92]
print(scores[safe: 1] ?? -1)
print(scores[safe: 10] ?? -1)
print(scores[safe: -1] ?? -1)
```

```output
85
-1
-1
```

`safe index: Int` gives the parameter the label `safe` and the internal name `index`. A type can have several subscripts as long as their parameters differ, which is how `Array` has both `numbers[2]` and `numbers[1...3]`.

## Collection conformance

A `Sequence` can only promise one pass, front to back. A **`Collection`** promises more: you can visit its elements as many times as you like, and you can jump straight to any element by its **index**. To conform, a type provides four things:

| Requirement | Meaning |
| --- | --- |
| `startIndex` | the index of the first element |
| `endIndex` | the position **one past** the last element |
| `index(after:)` | the index that follows a given one |
| `subscript(position:)` | the element at a given index |

Here's a playlist that wraps a private array and conforms:

```swift run
struct Playlist: Collection {
    private var songs: [String]

    init(_ songs: [String]) {
        self.songs = songs
    }

    var startIndex: Int { 0 }
    var endIndex: Int { songs.count }

    func index(after i: Int) -> Int {
        i + 1
    }

    subscript(position: Int) -> String {
        songs[position]
    }
}

let mix = Playlist(["Blue", "Hey Jude", "Imagine", "Yesterday"])
print(mix.count, mix.isEmpty)
print(mix[2])
print(mix.first ?? "")
print(mix.firstIndex(of: "Imagine") ?? -1)
print(mix.map { $0.count })
print(Array(mix.dropFirst(2)))
print(mix.sorted(by: >))
```

```output
4 false
Imagine
Blue
2
[4, 8, 7, 9]
["Imagine", "Yesterday"]
["Yesterday", "Imagine", "Hey Jude", "Blue"]
```

Four short members gave `Playlist` `count`, `isEmpty`, `first`, `firstIndex(of:)`, slicing with `dropFirst`, and everything from `Sequence`. Swift even supplies the iterator: `Collection` builds one from `startIndex`, `index(after:)` and the subscript, so `for song in mix` works without you writing `makeIterator()`.

### endIndex is one past the end

`endIndex` isn't the last element's index. It's the position just after it, the same idea as the half-open range `0..<count`. That makes two things simple:

- A collection is empty exactly when `startIndex == endIndex`.
- A loop runs `while index != endIndex`, never reading `endIndex` itself.

Reading `mix[mix.endIndex]` crashes with an index out of range, just like `numbers[numbers.count]`.

### Indices don't have to be Int

`Playlist` uses `Int` indices because it wraps an array. But `Index` is an associated type: each collection chooses its own. `String` uses `String.Index`, as you saw in M08, because finding the nth character means walking through variable-width characters. A linked list could use a reference to a node as its index. Whatever the index type, the four requirements stay the same.

## Going further: random access

Plain `Collection` can only move **forwards**, one index at a time. Two refinements add more:

- **`BidirectionalCollection`** adds `index(before:)`, which unlocks `last` and an efficient `reversed()`.
- **`RandomAccessCollection`** promises that jumping any distance is O(1). With `Int` indices Swift supplies that automatically, and `count` becomes O(1) too instead of counting step by step.

```swift run
struct Playlist: Collection {
    private var songs: [String]
    init(_ songs: [String]) { self.songs = songs }
    var startIndex: Int { 0 }
    var endIndex: Int { songs.count }
    func index(after i: Int) -> Int { i + 1 }
    subscript(position: Int) -> String { songs[position] }
}

extension Playlist: BidirectionalCollection, RandomAccessCollection {
    func index(before i: Int) -> Int {
        i - 1
    }
}

let mix = Playlist(["Blue", "Hey Jude", "Imagine"])
print(mix.last ?? "")
print(Array(mix.reversed()))
print(mix.indices)
```

```output
Imagine
["Imagine", "Hey Jude", "Blue"]
0..<3
```

`Array` is a `RandomAccessCollection`, which is why `numbers[i]` and `numbers.count` are O(1). Binary search, in Part IV, needs exactly this ability to jump to the middle.

<Callout kind="gotcha" title="Swift gotcha: subscript labels are opt-in">
`subscript(row: Int, column: Int)` is called as `board[1, 1]`. The names `row` and `column` are only used inside. If you want callers to write labels, spell them out twice, as with `subscript(safe index: Int)`, which is called as `scores[safe: 1]`.
</Callout>
