## Why it matters

You can write `let primes: Set = [2, 3, 5]` even though `Set` isn't an array. That's because `Set` adopts a protocol that lets it be created from square-bracket syntax. Your own types can do the same, so a test or example can say `let stack: Stack = [1, 2, 3]` instead of three `push` calls. It's a small feature, but it makes your data structures feel built in.

## What a literal is

A **literal** is a value written directly in code:

| Literal | Example |
| --- | --- |
| integer | `42` |
| floating-point | `3.5` |
| string | `"hello"` |
| Boolean | `true` |
| array | `[1, 2, 3]` |
| dictionary | `["a": 1]` |
| nil | `nil` |

A literal on its own has a default type: `[1, 2, 3]` becomes an `Array<Int>`. But if the context asks for a different type, Swift asks that type to build itself from the literal, through a protocol named **`ExpressibleBy…Literal`**. That's how this works:

```swift run
let primes: Set = [2, 3, 5, 3]
let ratio: Double = 4
let maybe: Int? = nil

print(primes.count)
print(ratio)
print(maybe == nil)
```

```output
3
4.0
true
```

`Set` conforms to `ExpressibleByArrayLiteral`, `Double` to `ExpressibleByIntegerLiteral`, and `Optional` to `ExpressibleByNilLiteral`. Nothing is converted after the fact: each type builds itself directly from the literal.

## ExpressibleByArrayLiteral

The protocol has one requirement, an initialiser that receives the literal's elements:

```swift
init(arrayLiteral elements: ArrayLiteralElement...)
```

`ArrayLiteralElement` is an associated type: the type of the items between the brackets. The `...` makes `elements` a **variadic** parameter, as you saw in M05, so inside the initialiser `elements` is an ordinary array.

Here's the stack from earlier in this module, with array-literal support added in an extension:

```swift run
struct Stack<Element> {
    private var items: [Element] = []

    mutating func push(_ item: Element) {
        items.append(item)
    }

    mutating func pop() -> Element? {
        items.popLast()
    }

    var count: Int {
        items.count
    }
}

extension Stack: ExpressibleByArrayLiteral {
    init(arrayLiteral elements: Element...) {
        items = elements
    }
}

var stack: Stack = [1, 2, 3]
print(stack.count)
print(stack.pop() ?? 0)

var empty: Stack<String> = []
empty.push("only")
print(empty.count)
```

```output
3
3
1
```

What to notice:

- `let stack: Stack = [1, 2, 3]` didn't name the element type. Swift worked out `Stack<Int>` from the literal's contents.
- The literal's elements become the stack from bottom to top, so `3`, the last element, is on top. Decide and document this order for your own types: "the last element is the top" matches how `push` would have built it.
- The `init` lives in an **extension**, so the stack keeps its other initialisers, including the free `init()` that `Stack<Int>()` uses.
- `[]` works too, as long as the type says what the elements are.

### Literals as arguments

Wherever a parameter's type adopts the protocol, you can pass a literal directly. This is where it shines, in tests and small examples:

```swift run
struct Stack<Element> {
    private var items: [Element] = []
    mutating func pop() -> Element? { items.popLast() }
    func peek() -> Element? { items.last }
}

extension Stack: ExpressibleByArrayLiteral {
    init(arrayLiteral elements: Element...) {
        items = elements
    }
}

func describeTop(of stack: Stack<String>) -> String {
    "Top: \(stack.peek() ?? "nothing")"
}

print(describeTop(of: ["plates", "cups", "bowls"]))
print(describeTop(of: []))
```

```output
Top: bowls
Top: nothing
```

## Other literal protocols

Each kind of literal has its own protocol. They all work the same way: one initialiser that receives the literal.

| Protocol | Initialiser | Lets you write |
| --- | --- | --- |
| `ExpressibleByArrayLiteral` | `init(arrayLiteral:)` | `let s: Stack = [1, 2]` |
| `ExpressibleByDictionaryLiteral` | `init(dictionaryLiteral:)` | `let m: MyMap = ["a": 1]` |
| `ExpressibleByIntegerLiteral` | `init(integerLiteral:)` | `let price: Money = 5` |
| `ExpressibleByStringLiteral` | `init(stringLiteral:)` | `let tag: Tag = "swift"` |

For example, a money type that stores pennies but can be written as a whole number of pounds:

```swift run
struct Money: ExpressibleByIntegerLiteral {
    var pennies: Int

    init(integerLiteral pounds: Int) {
        pennies = pounds * 100
    }
}

let price: Money = 5
print(price.pennies)
```

```output
500
```

Use literal protocols where the meaning is obvious. A stack, queue, heap or set "made of these elements" is a natural fit. A literal that hides a surprising conversion is not: `let price: Money = 5` is fine only if everyone reading knows it means pounds.

<Callout kind="gotcha" title="Swift gotcha: a literal needs a type context">
`let stack = [1, 2, 3]` is still a plain `Array<Int>`. Swift uses your type only when the context asks for it: a type annotation (`let stack: Stack = [1, 2, 3]`), a parameter type, or a return type. Without one, the literal falls back to its default type.
</Callout>
