## Why it matters

This is the lesson where you build your first real data structure. A **stack** is one of the most useful structures in computing: undo buttons, the browser's back button, checking brackets, evaluating expressions and depth-first search all use one. A **generic type** lets you write it once as `Stack<Element>` and then have a stack of integers, of characters, of grid cells, of anything.

## What a stack is

A stack keeps items in a pile. You can only add to the top and remove from the top, so the last item in is always the first item out. That's called **LIFO**: last in, first out.

<Callout kind="analogy">
A stack of plates in a cupboard. You put clean plates on top and take plates from the top. Getting to the bottom plate means removing every plate above it first.
</Callout>

A stack offers a small set of operations:

| Operation | What it does |
| --- | --- |
| `push(x)` | put `x` on top |
| `pop()` | remove the top item and return it (or `nil` if empty) |
| `peek()` | look at the top item without removing it |
| `isEmpty` | whether there are no items |
| `count` | how many items there are |

The top of the stack is the most recent item, so a stack naturally answers "what was the last thing I did?", which is why undo uses one.

## A stack of integers

Start with a concrete version. An array stores the items, with the **end** of the array as the top, because adding and removing at the end of an array is fast:

```swift run
struct IntStack {
    private var items: [Int] = []

    mutating func push(_ item: Int) {
        items.append(item)
    }

    mutating func pop() -> Int? {
        items.popLast()
    }

    func peek() -> Int? {
        items.last
    }

    var isEmpty: Bool {
        items.isEmpty
    }

    var count: Int {
        items.count
    }
}

var stack = IntStack()
stack.push(1)
stack.push(2)
stack.push(3)
print(stack.peek() ?? -1)
print(stack.pop() ?? -1)
print(stack.pop() ?? -1)
print(stack.count, stack.isEmpty)
```

```output
3
3
2
1 false
```

Everything you learned in M09 is here: a `private` array hides the storage (so nobody can sneak an item into the middle), `mutating` methods change it, and computed properties report on it. `popLast()` returns `nil` on an empty array instead of crashing, which is exactly what `pop()` should do.

## Making it generic

Nothing in `IntStack` depends on the items being integers. Replace `Int` with a type parameter, and the stack works for any element type:

```swift run
struct Stack<Element> {
    private var items: [Element] = []

    mutating func push(_ item: Element) {
        items.append(item)
    }

    mutating func pop() -> Element? {
        items.popLast()
    }

    func peek() -> Element? {
        items.last
    }

    var isEmpty: Bool {
        items.isEmpty
    }

    var count: Int {
        items.count
    }
}

var numbers = Stack<Int>()
numbers.push(10)
numbers.push(20)
print(numbers.pop() ?? 0)

var words = Stack<String>()
words.push("first")
words.push("second")
print(words.peek() ?? "")
print(words.count)
```

```output
20
second
2
```

What to notice:

- `struct Stack<Element>` declares a **generic type**. `Element` is its type parameter, used everywhere `Int` used to be.
- `Stack<Int>()` and `Stack<String>()` create two different concrete types from one definition. A `Stack<Int>` only accepts `Int`s: pushing a string onto it is a compile error.
- The methods need no angle brackets of their own. Inside the type, `Element` is already known.

`Element` is the same name the standard library uses for `Array<Element>` and `Set<Element>`.

## Using the stack

### Reversing

Push everything, then pop everything: the order comes out reversed, because the last item pushed is the first popped.

```swift run
struct Stack<Element> {
    private var items: [Element] = []
    mutating func push(_ item: Element) { items.append(item) }
    mutating func pop() -> Element? { items.popLast() }
    var isEmpty: Bool { items.isEmpty }
}

func reversed(_ text: String) -> String {
    var stack = Stack<Character>()
    for character in text {
        stack.push(character)
    }
    var result = ""
    while let character = stack.pop() {
        result.append(character)
    }
    return result
}

print(reversed("stressed"))
```

```output
desserts
```

`while let character = stack.pop()` keeps going until `pop()` returns `nil`: "pop until empty" in one line.

### An undo history

```swift run
struct Stack<Element> {
    private var items: [Element] = []
    mutating func push(_ item: Element) { items.append(item) }
    mutating func pop() -> Element? { items.popLast() }
    func peek() -> Element? { items.last }
}

var history = Stack<String>()
var document = ""

for edit in ["Hello", ", world", "!!!"] {
    history.push(document)
    document += edit
}
print(document)

if let previous = history.pop() {
    document = previous
}
print(document)
if let previous = history.pop() {
    document = previous
}
print(document)
```

```output
Hello, world!!!
Hello, world
Hello
```

Before each edit, the current document is pushed. Undo pops the most recent saved version. Because the undo history is a stack, undo always goes back one step at a time, in reverse order.

## Extending a generic type

Extensions work on generic types too, and `Element` is available inside them. A conformance to `CustomStringConvertible` makes the stack print nicely:

```swift run
struct Stack<Element> {
    private var items: [Element] = []
    mutating func push(_ item: Element) { items.append(item) }
    mutating func pop() -> Element? { items.popLast() }

    var bottomToTop: [Element] {
        items
    }
}

extension Stack: CustomStringConvertible {
    var description: String {
        "Stack " + bottomToTop.map { "\($0)" }.joined(separator: " | ") + " <- top"
    }
}

extension Stack where Element: Equatable {
    func contains(_ item: Element) -> Bool {
        bottomToTop.contains(item)
    }
}

var stack = Stack<Int>()
for value in [4, 8, 15] {
    stack.push(value)
}
print(stack)
print(stack.contains(8))
```

```output
Stack 4 | 8 | 15 <- top
true
```

The second extension has a `where` clause: `contains` exists only for stacks whose elements are `Equatable`, because checking membership needs `==`. A `Stack<Int>` gets it. A stack of some type without `==` simply doesn't have the method. This is exactly how `Array` offers `contains(_:)` only when its elements are `Equatable`.

## How fast is it?

| Operation | Time |
| --- | --- |
| `push` | O(1) on average |
| `pop`, `peek`, `isEmpty`, `count` | O(1) |

Why "on average" for `push`? An array reserves some spare room. When it fills up, `append` moves everything to a bigger block of memory, which costs O(n) that one time. But the array doubles its room each time, so those moves are rare, and averaged over many pushes the cost per push is constant. This is called **amortised O(1)**, and you'll prove it when you build a dynamic array in Part III.

Earlier you saw a stack that inserted at the **front** of its array. Every push and pop there shifts all the other items, O(n) each. Same operations, very different speed: putting the top at the end is the whole trick.

## Generic types with more than one parameter

A type can have several type parameters, separated by commas:

```swift run
struct Pair<First, Second> {
    var first: First
    var second: Second

    func swapped() -> Pair<Second, First> {
        Pair<Second, First>(first: second, second: first)
    }
}

let entry = Pair(first: "age", second: 30)
let flipped = entry.swapped()
print(entry.first, entry.second)
print(flipped.first, flipped.second)
```

```output
age 30
30 age
```

Here Swift inferred `Pair<String, Int>` from the memberwise initialiser's arguments. `Dictionary<Key, Value>` is the standard library's best-known two-parameter generic type.

<Callout kind="gotcha" title="Swift gotcha: Stack() needs to know its Element">
`var stack = Stack()` doesn't compile: `error: generic parameter 'Element' could not be inferred`. An empty stack gives Swift no clue what it will hold. Write `Stack<Int>()`, or annotate the variable: `var stack: Stack<Int> = Stack()`.
</Callout>
