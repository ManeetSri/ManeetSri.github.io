## Why it matters

An **extension** adds new abilities to a type that already exists, even one you didn't write, like `Int` or `String`. Combined with protocols, extensions let one piece of code give dozens of types a feature at once. That's how every array, set, range and string gets `map`, `filter` and `contains` without each one implementing them. In your own DSA code, extensions keep helpers tidy and let your data structures adopt protocols cleanly.

## Extending a type you didn't write

Write `extension`, the type's name, and then the new members:

```swift run
extension Int {
    var isEven: Bool {
        self % 2 == 0
    }

    func squared() -> Int {
        self * self
    }

    mutating func double() {
        self *= 2
    }
}

print(7.isEven)
print(12.squared())
var score = 21
score.double()
print(score)
```

```output
false
144
42
```

What to notice:

- Inside an extension of `Int`, `self` is the integer itself.
- `7.isEven` reads naturally: the new property looks exactly like a built-in one.
- `double()` is `mutating` because `Int` is a struct and the method changes it.

Strings work the same way. Here's a helper you might use in string problems:

```swift run
extension String {
    var isPalindrome: Bool {
        let characters = Array(self)
        return characters == characters.reversed()
    }
}

print("level".isPalindrome)
print("swift".isPalindrome)
```

```output
true
false
```

`Array(self)` turns the string into an array of characters, as you learned in M08.

## Extending your own types

Extensions are also a way to **organise** your own types. A common style is to keep the stored properties in the main declaration and group related methods into extensions:

```swift run
struct Point {
    var x: Int
    var y: Int
}

extension Point {
    init(both value: Int) {
        self.init(x: value, y: value)
    }

    func manhattanDistance(to other: Point) -> Int {
        abs(x - other.x) + abs(y - other.y)
    }
}

let a = Point(x: 1, y: 2)
let b = Point(both: 5)
print(a.manhattanDistance(to: b))
```

```output
7
```

Remember the M09 gotcha: writing an `init` inside a struct removes its memberwise initialiser. An `init` written **in an extension** doesn't, so `Point(x: 1, y: 2)` and `Point(both: 5)` both work here.

## Adding protocol conformance

An extension can make a type conform to a protocol, even a type you didn't write. This is a tidy way to keep each conformance in its own block:

```swift run
protocol Describable {
    func describe() -> String
}

struct Point {
    var x: Int
    var y: Int
}

extension Point: Describable {
    func describe() -> String {
        "(\(x), \(y))"
    }
}

extension Int: Describable {
    func describe() -> String {
        "the number \(self)"
    }
}

let things: [any Describable] = [Point(x: 3, y: 4), 42]
for thing in things {
    print(thing.describe())
}
```

```output
(3, 4)
the number 42
```

`Int` now conforms to a protocol that you wrote. Its authors never imagined `Describable`, and they didn't need to.

## What extensions can't do

Extensions add behaviour, not storage:

```swift
extension Int {
    var label: String = ""
}
```

```text title="What you'll see"
error: extensions must not contain stored properties
```

An extension can add computed properties, methods, initialisers, subscripts and nested types, and it can add protocol conformance. It can't add stored properties, and it can't override a method the type already has: existing behaviour stays as it was.

## Protocol extensions: default implementations

Now the powerful part. You can extend a **protocol**. Every method you write there is automatically available to every conforming type:

```swift run
protocol Greeter {
    var name: String { get }
    func greet() -> String
}

extension Greeter {
    func greet() -> String {
        "Hello, I'm \(name)."
    }

    func greetTwice() -> String {
        greet() + " " + greet()
    }
}

struct Person: Greeter {
    var name: String
}

struct Robot: Greeter {
    var name: String

    func greet() -> String {
        "BEEP. UNIT \(name) ONLINE."
    }
}

print(Person(name: "Maneet").greet())
print(Robot(name: "R2").greet())
print(Person(name: "Ada").greetTwice())
```

```output
Hello, I'm Maneet.
BEEP. UNIT R2 ONLINE.
Hello, I'm Ada. Hello, I'm Ada.
```

What to notice:

- `Person` conforms with only a `name`. It gets `greet()` from the protocol extension: a **default implementation**.
- `Robot` provides its own `greet()`, which replaces the default.
- `greetTwice()` isn't a requirement at all. It's a bonus method that every `Greeter` gets for free, written once, in terms of the requirements.

This is exactly how the standard library works. The `Sequence` protocol needs only one thing from a conforming type (you'll write it later in this module), and a protocol extension supplies `map`, `filter`, `reduce`, `contains`, `min`, `max` and dozens more. Every array, set, range and string shares that one implementation.

## Constrained extensions

You can limit an extension to types that meet a condition, using `where`. Here, only arrays of `Int` get a `total`:

```swift run
extension Array where Element == Int {
    var total: Int {
        reduce(0, +)
    }
}

print([3, 4, 5].total)
```

```output
12
```

`["a", "b"].total` wouldn't compile, because the condition `Element == Int` isn't met. You'll write conditions like this often once generics arrive later in this module, for example "only when the elements can be compared".

<Callout kind="gotcha" title="Swift gotcha: extension-only methods aren't replaced through the protocol">
A method that's only in a protocol extension, and isn't listed as a requirement, is chosen by the variable's declared type, not the value's real type. If `Dog` defines its own `intro()`, but `intro()` isn't a protocol requirement, then calling it through an `any Animal` runs the extension's version, not the dog's. If conforming types should be able to replace a method, list it as a requirement in the protocol, as `greet()` is above.
</Callout>
