## Why it matters

`for-in` works with arrays, ranges, strings, sets, dictionaries and `stride`. That's not because Swift knows about each one: they all conform to one protocol, **`Sequence`**. Make your own type a `Sequence` and it works in `for-in` too, and gains `map`, `filter`, `reduce`, `contains`, `max` and dozens more for free. Later you'll make linked lists and trees loopable this way, so that `for value in tree` visits every node.

## What for-in really does

When you write a `for-in` loop, Swift quietly rewrites it. It asks the sequence for an **iterator**, then calls the iterator's `next()` method over and over until it returns `nil`:

```swift run
let numbers = [10, 20, 30]

for number in numbers {
    print(number)
}

var iterator = numbers.makeIterator()
while let number = iterator.next() {
    print(number)
}
```

```output
10
20
30
10
20
30
```

The two loops do exactly the same thing. The second one is roughly what Swift turns the first one into. So two pieces are involved:

- An **iterator** produces values one at a time. Each call to `next()` returns the next value, or `nil` when there are no more.
- A **sequence** is anything that can hand out an iterator, via `makeIterator()`.

## IteratorProtocol

An iterator conforms to `IteratorProtocol`, which has one requirement:

```swift
protocol IteratorProtocol {
    associatedtype Element
    mutating func next() -> Element?
}
```

`Element` is an associated type, as in the previous lesson: each iterator decides what it produces. `next()` is `mutating` because an iterator must remember how far it has got, and moving forward changes that.

Here's an iterator that counts down to 1:

```swift run
struct CountdownIterator: IteratorProtocol {
    var current: Int

    mutating func next() -> Int? {
        guard current > 0 else {
            return nil
        }
        defer { current -= 1 }
        return current
    }
}

var countdown = CountdownIterator(current: 3)
print(countdown.next() ?? 0)
print(countdown.next() ?? 0)
print(countdown.next() ?? 0)
print(countdown.next() == nil)
```

```output
3
2
1
true
```

`defer { current -= 1 }` runs as the function exits, *after* the return value has been worked out. So `next()` returns the current number and then moves on. You could equally store the value in a constant, decrement, and return the constant. Swift's `defer` is covered fully in M12.

## Sequence

A sequence conforms to `Sequence` by providing `makeIterator()`. Here's a `Countdown` that can be used in a `for-in` loop:

```swift run
struct CountdownIterator: IteratorProtocol {
    var current: Int

    mutating func next() -> Int? {
        guard current > 0 else {
            return nil
        }
        defer { current -= 1 }
        return current
    }
}

struct Countdown: Sequence {
    let start: Int

    func makeIterator() -> CountdownIterator {
        CountdownIterator(current: start)
    }
}

for number in Countdown(start: 5) {
    print(number, terminator: " ")
}
print("Liftoff!")
```

```output
5 4 3 2 1 Liftoff!
```

What to notice:

- `Countdown` describes the whole countdown. It never changes. Each call to `makeIterator()` creates a fresh iterator that starts from the top.
- Swift infers the sequence's `Element` (`Int`) from the iterator's `next()`.
- Splitting the job like this keeps each part simple: the sequence knows *what* to produce, and the iterator knows *where it's up to*.

## Free abilities

`Sequence` comes with a huge protocol extension. Conforming with that one method unlocks everything you learned in M06:

```swift run
struct CountdownIterator: IteratorProtocol {
    var current: Int
    mutating func next() -> Int? {
        guard current > 0 else { return nil }
        defer { current -= 1 }
        return current
    }
}

struct Countdown: Sequence {
    let start: Int
    func makeIterator() -> CountdownIterator {
        CountdownIterator(current: start)
    }
}

let launch = Countdown(start: 5)
print(Array(launch))
print(launch.map { $0 * 10 })
print(launch.filter { $0.isMultiple(of: 2) })
print(launch.reduce(0, +))
print(launch.contains(3), launch.max() ?? 0)
for (index, value) in launch.enumerated() where index < 2 {
    print(index, value)
}
```

```output
[5, 4, 3, 2, 1]
[50, 40, 30, 20, 10]
[4, 2]
15
true 5
0 5
1 4
```

Every one of those calls was written once, in an extension of `Sequence`, in terms of `makeIterator()` and `next()`. Your type wrote none of them.

## A type that is its own iterator

For simple sequences you can merge the two parts. If a type conforms to both `Sequence` and `IteratorProtocol`, Swift provides `makeIterator()` automatically, returning a copy of the value itself:

```swift run
struct Countdown: Sequence, IteratorProtocol {
    var current: Int

    mutating func next() -> Int? {
        guard current > 0 else {
            return nil
        }
        defer { current -= 1 }
        return current
    }
}

let fromThree = Countdown(current: 3)
print(Array(fromThree))
print(Array(fromThree))
```

```output
[3, 2, 1]
[3, 2, 1]
```

Notice the second `Array(fromThree)` still gives `[3, 2, 1]`. Because `Countdown` is a struct, each loop works on its own **copy**, so `fromThree` itself never changes. That's value semantics from M09 keeping you safe. A class that is its own iterator would be used up after one pass.

## Infinite sequences

A sequence doesn't have to end. If `next()` never returns `nil`, the sequence goes on forever. That's fine as long as you only take what you need:

```swift run
struct PowersOfTwo: Sequence, IteratorProtocol {
    var current = 1

    mutating func next() -> Int? {
        defer { current *= 2 }
        return current
    }
}

print(Array(PowersOfTwo().prefix(6)))
for power in PowersOfTwo() {
    if power > 100 {
        break
    }
    print(power, terminator: " ")
}
print()
print(PowersOfTwo().first { $0 > 1_000 } ?? 0)
```

```output
[1, 2, 4, 8, 16, 32]
1 2 4 8 16 32 64 
1024
```

`prefix(6)` takes only the first six values, and `first(where:)` stops at the first match, so neither runs forever. (Left running for long enough, the doubling would eventually overflow `Int` and crash.)

<Callout kind="gotcha" title="Swift gotcha: never collect an infinite sequence">
`Array(PowersOfTwo())`, `PowersOfTwo().map { … }` and `reduce` try to visit every element. On an infinite sequence they never finish, or here, crash on overflow. Always cut an infinite sequence down first, with `prefix`, `first(where:)` or a `break`.
</Callout>

## sequence(first:next:): a sequence without a new type

For one-off sequences, the standard library's `sequence(first:next:)` function builds one from a starting value and a closure that produces the next value from the previous one. Returning `nil` ends it:

```swift run
let tripling = sequence(first: 1) { $0 * 3 }
print(Array(tripling.prefix(while: { $0 < 100 })))

final class Node {
    let value: Int
    var next: Node?

    init(_ value: Int, next: Node? = nil) {
        self.value = value
        self.next = next
    }
}

let head = Node(1, next: Node(2, next: Node(3)))
let values = sequence(first: head) { $0.next }.map { $0.value }
print(values)
```

```output
[1, 3, 9, 27, 81]
[1, 2, 3]
```

The second use is worth remembering. `sequence(first: head) { $0.next }` walks a linked list: it starts at the head and follows `next` until it reaches `nil`. In two lines you get every node, ready for `map`, `filter` or `for-in`. You'll walk lists like this in M25.

## Sequences can be single-pass

One last detail. `Sequence` promises only that you can iterate **at least once**. Some sequences, such as one reading lines from a file as they arrive, can't restart. Code that needs to loop over the same values twice, or jump to a position, needs the stronger promise of **`Collection`**, which is the next lesson.
