## Why it matters

So far every value you've used came from Swift: `Int`, `String`, `Array`. Real programs need their own kinds of value: a point on a map, a song in a playlist, an edge in a graph. A **struct** lets you build one, with a name, its own data and its own behaviour. Every data structure in this course, from a stack to a heap, is a type you'll build this way.

## Defining a struct

A struct groups related values under one name. Each value inside is a **property**:

```swift run
struct Point {
    var x: Int
    var y: Int
}

let start = Point(x: 3, y: 4)
print(start.x)
print(start.y)
print(start)
```

```output
3
4
Point(x: 3, y: 4)
```

What to notice:

- `struct Point { … }` defines a new **type**. Type names use UpperCamelCase, like `Int` and `String`.
- `x` and `y` are **stored properties**: each `Point` stores its own `x` and `y`.
- `Point(x: 3, y: 4)` creates an **instance**, one actual point. You can make as many as you like from the same definition.
- You read a property with a dot: `start.x`. That's the same dot you've used for `numbers.count`.
- `print` shows a struct's name and properties, which is handy while debugging.

<Callout kind="analogy">
A struct definition is a blank form with labelled boxes. Each instance is one filled-in copy of that form.
</Callout>

## The memberwise initialiser

You never wrote `Point(x:y:)`. Swift wrote it for you. An **initialiser** is the code that creates an instance, and for structs Swift generates a **memberwise initialiser** with one labelled parameter per stored property, in the order you declared them.

Give a property a default value and its parameter becomes optional:

```swift run
struct Song {
    var title: String
    var artist: String
    var plays = 0
}

let fresh = Song(title: "Blue", artist: "Joni")
let favourite = Song(title: "Hey Jude", artist: "The Beatles", plays: 120)
print(fresh.plays)
print(favourite.plays)
```

```output
0
120
```

`plays` has a default of `0`, so you can leave it out. Swift infers its type, `Int`, from the default.

## Changing properties

A property declared with `var` can change, but only if the instance itself is stored in a `var`:

```swift run
struct Counter {
    var count = 0
}

var clicks = Counter()
clicks.count += 1
clicks.count += 1
print(clicks.count)
```

```output
2
```

When every property has a default, the memberwise initialiser can be called with no arguments at all: `Counter()`.

Store the instance in a `let` and the whole thing is frozen, even its `var` properties:

```swift
let fixed = Counter()
fixed.count = 5
```

```text title="What you'll see"
error: cannot assign to property: 'fixed' is a 'let' constant
```

That's a compile error, not a crash: Swift refuses to build the program. It's the same rule you met for arrays: a `let` array can't be appended to. Properties declared with `let` never change once the instance is created, whether the instance is in a `let` or a `var`.

## Computed properties

Some values can be worked out from others. A **computed property** has no storage of its own. It runs a little code every time you read it:

```swift run
struct Rectangle {
    var width: Int
    var height: Int

    var area: Int {
        width * height
    }

    var isSquare: Bool {
        width == height
    }
}

var box = Rectangle(width: 4, height: 3)
print(box.area)
print(box.isSquare)
box.width = 3
print(box.area)
print(box.isSquare)
```

```output
12
false
9
true
```

After `box.width = 3`, the area updates by itself, because it's recalculated on every read. A stored `area` would have gone stale.

A computed property:

- must be declared with `var` (its value can differ between reads), and needs an explicit type;
- isn't part of the memberwise initialiser, because there's nothing to store;
- uses a one-expression body without `return`, the same shortcut you met for functions.

### Computed properties you can set

A computed property can also have a **setter**, which turns a new value into changes to the stored properties. Inside `set`, the incoming value is called `newValue`:

```swift run
struct Duration {
    var totalSeconds: Int

    var minutes: Int {
        get { totalSeconds / 60 }
        set { totalSeconds = newValue * 60 + totalSeconds % 60 }
    }
}

var run = Duration(totalSeconds: 135)
print(run.minutes)
run.minutes = 5
print(run.totalSeconds)
```

```output
2
315
```

Reading `minutes` divides by 60 (integer division drops the remainder). Setting it to `5` keeps the 15 leftover seconds and replaces the minutes, giving 315.

## Methods

A **method** is a function that belongs to a type. You write it inside the struct and call it with a dot:

```swift run
struct Point {
    var x: Double
    var y: Double

    func distance(to other: Point) -> Double {
        let dx = other.x - x
        let dy = other.y - y
        return (dx * dx + dy * dy).squareRoot()
    }

    func describe() -> String {
        "(\(x), \(y))"
    }
}

let home = Point(x: 0, y: 0)
let shop = Point(x: 3, y: 4)
print(home.distance(to: shop))
print(shop.describe())
```

```output
5.0
(3.0, 4.0)
```

What to notice:

- Inside a method, `x` and `y` mean *this* instance's properties. You can also write `self.x`: **`self`** is the instance the method was called on. You only need `self` when a parameter has the same name as a property.
- `distance(to:)` uses an argument label, exactly like the functions in M05.
- `.squareRoot()` is a method on `Double` from the standard library. No import needed.

The methods above only *read* the point. A method that changes a property needs one extra keyword, `mutating`, which is the subject of the next lesson.

## Structs are everywhere

Here's a surprise: `Int`, `Double`, `Bool`, `String`, `Array` and `Dictionary` are all structs in Swift's standard library. When you write `numbers.count` or `name.isEmpty`, you're reading a computed property. When you call `numbers.append(5)`, you're calling a method. Your own structs work exactly the same way.

### Why not a tuple?

In M02 you grouped values with tuples, like `(x: 3, y: 4)`. Tuples are fine for a quick, one-off pair, such as returning two values from a function. Reach for a struct when the data has a meaning worth naming:

| | Tuple | Struct |
| --- | --- | --- |
| Has a type name | no | yes |
| Can have methods and computed properties | no | yes |
| Can adopt protocols (M10), e.g. to go in a `Set` | no | yes |
| Best for | a quick pair from a function | anything you pass around |

<Callout kind="note" title="The DSA connection">
A data structure is a type with stored data plus methods that keep it organised. In M10 you'll write `struct Stack` with a private array and `push` and `pop` methods. Graph problems use small structs like `struct Edge { var from: Int; var to: Int; var weight: Int }`. Everything starts with what you've learned here.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: a let instance freezes everything">
For a struct, `let` means the *whole value* is constant, including its `var` properties. If you need to change a property, store the instance in a `var`. You'll see in the classes lessons that this rule is different for classes.
</Callout>
