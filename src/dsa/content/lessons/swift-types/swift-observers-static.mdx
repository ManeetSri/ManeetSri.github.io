## Why it matters

Two more tools round out what a type can contain. **Property observers** run code automatically whenever a property changes, which is perfect for logging, keeping limits or tracking a running best. **Static members** belong to the type itself rather than to any one instance: `Int.max` is one you already know. Static members also explain the curious shape of every problem in the companion package.

## Property observers

A stored property can have two observers:

- **`willSet`** runs just *before* the new value is stored. The incoming value is called `newValue`.
- **`didSet`** runs just *after*. The value it replaced is called `oldValue`.

```swift run
struct Thermostat {
    var target: Int {
        willSet {
            print("About to change from \(target) to \(newValue)")
        }
        didSet {
            print("Changed from \(oldValue) to \(target)")
        }
    }
}

var home = Thermostat(target: 20)
home.target = 22
home.target += 1
```

```output
About to change from 20 to 22
Changed from 20 to 22
About to change from 22 to 23
Changed from 22 to 23
```

What to notice:

- Observers go in braces after the property's type, and they're attached to a **stored** property: `target` still holds a value.
- `home.target += 1` triggers them too. Any change does.
- Creating the thermostat with `Thermostat(target: 20)` printed nothing. Observers **don't run during initialisation**, only for changes made afterwards.

`didSet` is used far more often than `willSet`. You can have either one, or both.

### Keeping a value in range

Inside `didSet` you may assign to the property again, and doing so doesn't trigger the observer a second time. That makes clamping easy:

```swift run
struct Volume {
    var level = 5 {
        didSet {
            if level > 10 {
                level = 10
            } else if level < 0 {
                level = 0
            }
        }
    }
}

var speaker = Volume()
speaker.level = 14
print(speaker.level)
speaker.level -= 20
print(speaker.level)
```

```output
10
0
```

### Tracking a running best

Observers can also keep a second property in sync. Here, `best` always holds the highest score ever set, with no extra work at each call site:

```swift run
struct ScoreTracker {
    private(set) var best = 0
    var current = 0 {
        didSet {
            if current > best {
                best = current
            }
        }
    }
}

var game = ScoreTracker()
for score in [12, 40, 7, 33] {
    game.current = score
}
print(game.current, game.best)
```

```output
33 40
```

`private(set)` means code outside the type can read `best` but not change it, so nothing can break the "best is the highest so far" rule. You'll see it properly in the next lesson, on access control.

<Callout kind="tip" title="Observer or computed property?">
Use a **computed property** when a value can always be worked out from others, like `area` from width and height. Use an **observer** when you need to *react* to a change: print it, clamp it, or update something that can't be recomputed later, such as the best score ever seen.
</Callout>

## Static properties

Every property so far has belonged to an instance: each `Point` has its own `x`. A **static property** belongs to the type and exists exactly once, however many instances there are. You access it through the type name:

```swift run
struct Point {
    var x: Int
    var y: Int

    static let origin = Point(x: 0, y: 0)
    static var created = 0

    init(x: Int, y: Int) {
        self.x = x
        self.y = y
        Point.created += 1
    }
}

let a = Point(x: 3, y: 4)
let b = Point(x: -1, y: 2)
print(Point.origin)
print(Point.created)
print(a.x + b.x)
```

```output
Point(x: 0, y: 0)
3
2
```

`Point.created` is 3, not 2: creating `origin` ran the initialiser too. Swift creates a static property the first time it's used, which here was `print(Point.origin)`. That happened before `created` was read, so it was counted.

You've been using static properties since M02:

| Expression | What it is |
| --- | --- |
| `Int.max`, `Int.min` | static properties of `Int` |
| `Double.pi`, `Double.infinity` | static properties of `Double` |
| `Point.origin` | your own static property |

`Int.max` is a common starting value when searching for a minimum: anything real is smaller.

## Static methods

A **static method** is called on the type, not an instance. A common use is a **factory method**: a named way to create instances.

```swift run
struct Temperature {
    var celsius: Double

    static func fromFahrenheit(_ degrees: Double) -> Temperature {
        Temperature(celsius: (degrees - 32) * 5 / 9)
    }

    static func warmest(_ readings: [Temperature]) -> Temperature? {
        readings.max { $0.celsius < $1.celsius }
    }
}

let readings = [Temperature(celsius: 18), Temperature.fromFahrenheit(77), Temperature(celsius: 21)]
if let hottest = Temperature.warmest(readings) {
    print(hottest.celsius)
}
```

```output
25.0
```

Inside a static method there's no instance, so there's no instance `self` with properties to read. Everything it needs comes in through its parameters or other static members.

In a class, you may see `class func` instead of `static func`. The difference: a subclass can override a `class func`, but never a `static func`.

## Enums as namespaces

Now look again at a companion-package problem:

```swift
public enum LargestElement {
    public static func largest(in numbers: [Int]) -> Int? {
        // ...
    }
}
```

`LargestElement` is an enum with **no cases**. A caseless enum can never be instantiated, because there's no case to create. It works purely as a **namespace**: a named box for static functions. You call `LargestElement.largest(in:)` through the type, and two problems can both have a function called `largest` without clashing, because each lives in its own box. The `public` keywords are the subject of the next lesson.

<Callout kind="gotcha" title="Swift gotcha: observers don't fire in init">
Setting a property inside an initialiser doesn't run its `willSet` or `didSet`. If an observer clamps a value, an initialiser can still store an out-of-range value unless it clamps too. The same goes for default values.
</Callout>
