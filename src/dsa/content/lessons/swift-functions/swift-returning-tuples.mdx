## Why it matters

A function can only `return` one thing. Often you want two: the smallest *and* the largest value, a quotient *and* a remainder, a count of passes *and* fails. You met **tuples** in [Tuples and typealias](/dsa/learn/swift-tuples-typealias). Returning a tuple bundles several values into that one thing, so a single pass over the data can hand back everything it found.

## Returning a tuple

Write a tuple type after the arrow and return a tuple value:

```swift run
func divide(_ dividend: Int, by divisor: Int) -> (quotient: Int, remainder: Int) {
    (dividend / divisor, dividend % divisor)
}

let result = divide(17, by: 5)
print(result.quotient)
print(result.remainder)
print(result)
```

```output
3
2
(quotient: 3, remainder: 2)
```

What to notice:

- The return type names each part: `(quotient: Int, remainder: Int)`. These are **named tuple** elements.
- The function can return a plain `(3, 2)`. Swift matches the values to the names by position.
- The caller reads the parts by name, `result.quotient`, which is much clearer than `result.0`.
- Printing a named tuple shows the names too.

Swift's integers have this exact function built in as `17.quotientAndRemainder(dividingBy: 5)`, which returns the same named tuple.

## Taking a tuple apart

You can unpack a returned tuple straight into separate constants. This is called **destructuring**:

```swift run
func divide(_ dividend: Int, by divisor: Int) -> (quotient: Int, remainder: Int) {
    (dividend / divisor, dividend % divisor)
}

let (hours, minutes) = divide(135, by: 60)
print("\(hours)h \(minutes)m")

let (_, leftover) = divide(20, by: 6)
print(leftover)
```

```output
2h 15m
2
```

The names you choose when destructuring don't have to match the tuple's names: they're new constants, matched by position. `_` skips a part you don't need.

## Several results from one pass

This is where tuples earn their place in DSA. Suppose you want to know how many numbers are even and how many are odd. Two separate functions would each walk the whole array. One function can count both as it goes:

```swift run
func countParity(of numbers: [Int]) -> (evens: Int, odds: Int) {
    var evens = 0
    var odds = 0
    for number in numbers {
        if number % 2 == 0 {
            evens += 1
        } else {
            odds += 1
        }
    }
    return (evens, odds)
}

let counts = countParity(of: [3, 8, 6, 1, 4])
print("Evens: \(counts.evens), odds: \(counts.odds)")
```

```output
Evens: 3, odds: 2
```

One loop, two answers. The same idea gives you the smallest and largest value together, the sum and the count for an average, or the best value and *where* it was found.

## When there might be no answer

What should a function return for an empty array? Often there's no sensible pair of values. Make the whole tuple **optional** by putting `?` after the parentheses:

```swift run
func firstAndLast(of numbers: [Int]) -> (first: Int, last: Int)? {
    guard let first = numbers.first, let last = numbers.last else {
        return nil
    }
    return (first, last)
}

if let ends = firstAndLast(of: [5, 9, 2]) {
    print("Starts with \(ends.first), ends with \(ends.last)")
}

if firstAndLast(of: []) == nil {
    print("No ends to report")
}
```

```output
Starts with 5, ends with 2
No ends to report
```

What to notice:

- `(first: Int, last: Int)?` means "either a pair of `Int`s, or `nil`". The `?` applies to the whole tuple.
- `guard let` unwraps both optionals at once and returns `nil` if either is missing, as in M04.
- The caller unwraps the result with `if let` before reading `.first` and `.last`.

### Where it was found, and what it was

DSA problems often want *where* something is as well as *what* it is. A tuple returns both:

```swift run
func largestWithIndex(in numbers: [Int]) -> (index: Int, value: Int)? {
    guard !numbers.isEmpty else { return nil }
    var best = (index: 0, value: numbers[0])
    for index in 1..<numbers.count {
        if numbers[index] > best.value {
            best = (index: index, value: numbers[index])
        }
    }
    return best
}

if let best = largestWithIndex(in: [12, 40, 7, 40, 3]) {
    print("\(best.value) at index \(best.index)")
}
```

```output
40 at index 1
```

What to notice:

- The tuple is also handy *inside* the function: `best` holds the index and the value together, so they can never get out of step.
- `>` rather than `>=` means the **first** 40 wins. If the problem wanted the last one, `>=` would give index 3. Ties are exactly the kind of detail a problem statement should tell you, and the kind of edge case to test.
- The loop starts at index 1, because index 0 is already in `best`. For a one-element array, `1..<1` is empty, so the loop simply doesn't run.

## Naming tuple types with typealias

If the same tuple type appears in several places, give it a name with `typealias`:

```swift run
typealias Bounds = (low: Int, high: Int)

func widen(_ range: Bounds, by amount: Int) -> Bounds {
    (range.low - amount, range.high + amount)
}

let wider = widen((low: 3, high: 7), by: 2)
print(wider.low, wider.high)
```

```output
1 9
```

`Bounds` is only a nickname: it's exactly the same type as `(low: Int, high: Int)`.

<Callout kind="note" title="Tuple or struct?">
Tuples are perfect for a quick bundle of two or three values returned from one function. If the bundle has many fields, is passed around widely or needs behaviour of its own, a **struct** is better. You'll build structs in M09.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: names come from the return type">
Inside the function, `return (evens, odds)` works because Swift matches by position. If you return `(odds, evens)` by mistake, Swift can't catch it, since both are `Int`, and the caller gets the values swapped. Writing `return (evens: evens, odds: odds)` makes the intent explicit: if the names you write don't match the return type, Swift warns you or refuses to compile.
</Callout>
