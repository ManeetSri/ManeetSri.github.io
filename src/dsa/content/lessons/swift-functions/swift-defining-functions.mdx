## Why it matters

Every program bigger than a few lines is built from functions. In an iOS app, the code that runs when a screen appears or a button is tapped lives in a function. In DSA, every solution you write *is* a function: it takes the input, works out the answer and hands it back, and the tests call it to check you got it right.

## What a function is

A **function** is a named block of code that you can run whenever you want, as many times as you want. You've been using them since your first line of Swift: `print` is a function that someone else wrote.

<Callout kind="analogy" title="A recipe card">
A function is like a recipe card. Writing the card doesn't cook anything. Cooking happens each time someone picks up the card and follows it. Writing the card once means you never have to explain the recipe again.
</Callout>

Writing the card is called **defining** the function. Following it is called **calling** the function.

## Defining and calling

You define a function with the keyword `func`, a name, a pair of parentheses and a body in braces:

```swift run
func sayHello() {
    print("Hello!")
    print("Welcome to Swift.")
}

print("Before")
sayHello()
sayHello()
print("After")
```

```output
Before
Hello!
Welcome to Swift.
Hello!
Welcome to Swift.
After
```

What to notice:

- The definition alone prints nothing. The body runs only when you **call** the function by writing its name followed by `()`.
- Each call runs the whole body from top to bottom, then the program carries on from where the call was.
- Function names follow the same rules as variable names: lowerCamelCase, and usually a verb, because a function *does* something.

## Parameters: giving a function input

A function that always does exactly the same thing is limited. **Parameters** let the caller hand values in. You list each one inside the parentheses with a name and a type:

```swift run
func greet(name: String) {
    print("Hello, \(name)!")
}

func describe(name: String, age: Int) {
    print("\(name) is \(age) years old.")
}

greet(name: "Maneet")
greet(name: "Ada")
describe(name: "Grace", age: 85)
```

```output
Hello, Maneet!
Hello, Ada!
Grace is 85 years old.
```

What to notice:

- Inside the function, `name` behaves like a constant holding whatever the caller passed.
- When you call the function, you write the parameter name before each value: `greet(name: "Maneet")`. Swift insists on this. It makes calls read clearly, and you'll learn to customise these names in the next lesson.
- Several parameters are separated by commas, and you pass the values in the same order.

The values you pass in a call are called **arguments**. So `name` is a parameter, and `"Maneet"` is the argument passed for it.

## Return values: getting an answer back

Printing is handy for learning, but most useful functions **compute** something and give it back to the caller. You declare what type comes back with an arrow, `->`, after the parameters, and hand the value back with `return`:

```swift run
func square(number: Int) -> Int {
    let result = number * number
    return result
}

let nine = square(number: 3)
print(nine)
print(square(number: 4) + square(number: 5))
print("Twelve squared is \(square(number: 12))")
```

```output
9
41
Twelve squared is 144
```

What to notice:

- `-> Int` promises that every call produces an `Int`. Swift checks this promise.
- A call to `square(number: 3)` *is* a value of type `Int`. You can store it, add it to things or put it straight into string interpolation.
- The function doesn't print anything. It hands its answer back and lets the caller decide what to do with it. That makes it easy to test and reuse.

### `return` stops the function

`return` doesn't only hand back a value. It ends the function immediately, so a function can have several `return` statements on different paths:

```swift run
func sign(of number: Int) -> String {
    if number > 0 {
        return "positive"
    }
    if number < 0 {
        return "negative"
    }
    return "zero"
}

print(sign(of: 8))
print(sign(of: -3))
print(sign(of: 0))
```

```output
positive
negative
zero
```

When `number` is 8, the first `return` runs and the rest of the body is skipped. You can read this as "decide, then leave". (The `of` in `sign(of:)` is a label for the call site, which you'll meet properly in the next lesson.)

### One-line functions

If the whole body is a single expression, you can leave out `return`. Swift returns the value of that expression for you:

```swift run
func double(number: Int) -> Int {
    number * 2
}

func isEven(number: Int) -> Bool {
    number % 2 == 0
}

print(double(number: 21))
print(isEven(number: 7))
```

```output
42
false
```

This is called an **implicit return**. As soon as the body has more than one statement, write `return` yourself.

## Functions that return nothing

A function without `->` returns nothing. Swift calls this type `Void`. You can still use a bare `return` to leave early, which pairs nicely with `guard`:

```swift run
func printReceipt(total: Int) {
    guard total > 0 else {
        print("Nothing to pay.")
        return
    }
    print("Please pay £\(total).")
}

printReceipt(total: 0)
printReceipt(total: 12)
```

```output
Nothing to pay.
Please pay £12.
```

`guard` checks the condition, and when it fails, the `else` block must leave the function. That's exactly what a bare `return` does here.

## Ignoring a result on purpose

If you call a function that returns a value and do nothing with it, Swift warns you, because forgetting a result is usually a bug:

```text title="What you'll see"
warning: result of call to 'square(number:)' is unused
```

If you really don't need the value, assign it to `_`, which means "throw this away":

```swift
_ = square(number: 3)
```

A few functions are mostly called for what they *do*, with the returned value as an occasional extra. Their authors mark them with `@discardableResult`, which turns the warning off:

```swift run
var log: [String] = []

@discardableResult
func record(message: String) -> Int {
    log.append(message)
    return log.count
}

record(message: "Started")
record(message: "Loaded data")
let entries = record(message: "Finished")
print(entries)
```

```output
3
```

You'll rarely need `@discardableResult` yourself. It's worth recognising because you'll see it in Apple's code and in the documentation.

<Callout kind="gotcha" title="Swift gotcha: every path must return">
If a function promises a value with `->`, *every* path through it must reach a `return`. This version forgets the zero case, and Swift refuses to compile it:

```swift
func sign(of number: Int) -> Int {
    if number > 0 {
        return 1
    } else if number < 0 {
        return -1
    }
}
```

```text title="What you'll see"
error: missing return in global function expected to return 'Int'
```

Add a final `return 0`, or turn the last branch into a plain `else`.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: parameters are constants">
You can't change a parameter inside the function. `number += 1` gives `error: left side of mutating operator isn't mutable: 'number' is a 'let' constant`. If you need a changeable copy, write `var current = number` and change that. Later in this module you'll meet `inout`, for when a function really should change the caller's variable.
</Callout>

## Functions in DSA

Every practice problem gives you a function to fill in, such as `LargestElement.largest(in:)`. The `public static` in front of it and the `enum` around it are packaging that lets the tests reach your code. Inside, it's an ordinary function: parameters in, `return` out. Good solutions are like `square(number:)`: they don't print, they don't depend on anything outside their parameters, and they return their answer. Functions like that are easy to test and easy to trust.
