## Why it matters

Many of the most important algorithms rearrange an array **in place**: reversing it, sorting it, moving all the zeros to the end, partitioning it around a pivot. "In place" means the algorithm changes the array it was given, using only a few extra variables, instead of building a second array. Swift's tool for a function that changes the caller's variable is `inout`, and its tools for rearranging are `swap` and `swapAt`. This lesson gives you all three, and finishes with the classic in-place reversal that you'll reuse again and again.

## Parameters are copies

As you saw in [Defining and calling functions](/dsa/learn/swift-defining-functions), a parameter is a constant. Even if you copy it into a `var` and change the copy, the caller's value is untouched:

```swift run
func resetFirst(_ scores: [Int]) {
    var copy = scores
    copy[0] = 0
    print("Inside: \(copy)")
}

var myScores = [7, 9, 4]
resetFirst(myScores)
print("Outside: \(myScores)")
```

```output
Inside: [0, 9, 4]
Outside: [7, 9, 4]
```

What to notice:

- The function got its own copy of the array. Changing it had no effect on `myScores`.
- This is deliberate. In Swift, arrays, strings, numbers and tuples are **values**: passing one around hands over a copy, never a shared original. (Swift makes those copies cheap behind the scenes, as you'll see in M07.)

Most of the time this is exactly what you want: calling a function can't secretly change your data. But an in-place algorithm *must* change the caller's array. That's what `inout` is for.

## inout parameters

Write `inout` before a parameter's type, and the function can change the caller's variable. The caller marks the argument with `&`:

```swift run
func double(_ number: inout Int) {
    number *= 2
}

var price = 15
double(&price)
print(price)
double(&price)
print(price)
```

```output
30
60
```

What to notice:

- Inside the function, `number` is now changeable, and the change reaches `price`.
- The `&` at the call site is required. It's a visible warning to anyone reading the call: *this variable may be changed*.

Swift describes `inout` as **copy-in, copy-out**. When the call starts, the value is copied in. The function works on it. When the function returns, the final value is copied back out into the caller's variable. You can picture it as handing someone your notebook to edit and getting it back with their changes.

### The rules

- You can only pass a **variable**. A `let` constant or a literal like `double(&5)` is rejected, because there'd be nowhere to copy the result back to.
- The `&` is always required, and it only appears in front of `inout` arguments.
- An `inout` parameter can't have a default value.
- You can't pass the same variable to two `inout` parameters in one call, such as `swap(&a, &a)`. Swift reports `inout arguments are not allowed to alias each other`.

Arrays work exactly like numbers here:

```swift run
func addBonus(_ bonus: Int, to scores: inout [Int]) {
    for index in 0..<scores.count {
        scores[index] += bonus
    }
}

var scores = [60, 72, 55]
addBonus(5, to: &scores)
print(scores)
```

```output
[65, 77, 60]
```

## swap: exchanging two variables

Exchanging two values is so common that Swift provides `swap(_:_:)`. Both parameters are `inout`:

```swift run
var left = "apple"
var right = "banana"
swap(&left, &right)
print(left, right)
```

```output
banana apple
```

Without `swap`, you'd need a temporary variable, or Swift's tuple trick:

```swift run
var a = 1
var b = 2

// With a temporary variable
let temp = a
a = b
b = temp
print(a, b)

// With a tuple: both values on the right are read before either is assigned
(a, b) = (b, a)
print(a, b)
```

```output
2 1
1 2
```

The temporary is the classic version you'll see in every language. Without it, `a = b` would overwrite `a` before you'd saved it.

## swapAt: exchanging two array elements

To exchange two elements of an array, use the array's own `swapAt(_:_:)` method with the two indices:

```swift run
var letters = ["a", "b", "c", "d"]
letters.swapAt(0, 3)
print(letters)
letters.swapAt(1, 2)
print(letters)
letters.swapAt(2, 2)
print(letters)
```

```output
["d", "b", "c", "a"]
["d", "c", "b", "a"]
["d", "c", "b", "a"]
```

Swapping an index with itself is allowed and does nothing, which saves you writing a special case.

<Callout kind="gotcha" title="Swift gotcha: swap can't take two elements of the same array">
In many languages you'd write `swap(&numbers[i], &numbers[j])`. In Swift, that doesn't compile:

```text title="What you'll see"
error: overlapping accesses to 'numbers', but modification requires exclusive access; consider calling MutableCollection.swapAt(_:_:)
```

Swift's **exclusivity rule** says that while something is being changed through an `inout` argument, nothing else may access it at the same time. Both arguments are parts of the same array, so the two changes would overlap. The error message even tells you the fix: `numbers.swapAt(i, j)`.
</Callout>

## Reversing an array in place

Here's the payoff. To reverse an array without building a new one, use **two indices**: `left` starts at the beginning and `right` at the end. Swap the elements they point at, then move both towards the middle. Stop when they meet.

```swift run
func reverseInPlace(_ numbers: inout [Int]) {
    var left = 0
    var right = numbers.count - 1
    while left < right {
        numbers.swapAt(left, right)
        print("Swapped indices \(left) and \(right): \(numbers)")
        left += 1
        right -= 1
    }
}

var values = [1, 2, 3, 4, 5]
reverseInPlace(&values)
print(values)
```

```output
Swapped indices 0 and 4: [5, 2, 3, 4, 1]
Swapped indices 1 and 3: [5, 4, 3, 2, 1]
[5, 4, 3, 2, 1]
```

Trace it by hand with `[1, 2, 3, 4, 5]`:

| Step | `left` | `right` | Array after the swap |
| --- | --- | --- | --- |
| 1 | 0 | 4 | `[5, 2, 3, 4, 1]` |
| 2 | 1 | 3 | `[5, 4, 3, 2, 1]` |
| check | 2 | 2 | `left < right` is false, so stop |

What to notice:

- The middle element of an odd-length array never moves, and doesn't need to.
- For an even-length array such as `[1, 2, 3, 4]`, the indices cross: after swapping 1 with 2, `left` is 2 and `right` is 1, and the loop stops.
- For an empty array, `right` starts at `-1`. `0 < -1` is false, so the loop never runs and nothing goes wrong. A one-element array is just as safe. Always check these edge cases.

### Why in place matters

Each element is swapped at most once, so the work grows in step with the array: **O(n) time**. The only extra memory is two `Int`s, however big the array is: **O(1) extra space**. A version that builds a new reversed array also takes O(n) time, but it needs a whole second array, **O(n) extra space**. When an interview problem says "do it in place" or "use O(1) extra space", this two-index pattern is usually the starting point. You'll meet it again as the **two pointers** pattern in Part III.

Swift's arrays already have both versions built in: `numbers.reverse()` reverses in place, and `numbers.reversed()` gives you a reversed view without changing the original. Writing your own once is how you learn the pattern that powers far trickier algorithms.

<Callout kind="note" title="Mutating methods are inout in disguise">
Methods like `append(_:)`, `swapAt(_:_:)`, `reverse()` and `sort()` change the array they're called on. That's why they only work on a `var`: calling `swapAt` on a `let` array is an error, for the same reason `double(&5)` is. You'll write your own mutating methods in M09.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **Forgetting `&`.** `double(price)` fails with an error asking you to add `&`.
- **Passing a constant.** `let price = 15` then `double(&price)` fails: declare it with `var`.
- **Expecting a copy to change the caller.** Without `inout`, `var copy = scores` inside the function only changes the copy.
</Callout>
