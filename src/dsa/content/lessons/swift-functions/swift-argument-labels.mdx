## Why it matters

Swift code is meant to read like a sentence where it's used: `numbers.insert(5, at: 0)`, `names.firstIndex(of: "Ada")`, `stride(from: 10, to: 0, by: -2)`. Those little words, `at`, `of`, `from`, are **argument labels**. Apple's whole API is designed around them, so reading the documentation, and writing functions other people (and future you) can read, depends on understanding them.

## Two names for every parameter

In the last lesson, the name you wrote in the call was the same as the name used inside the function: `greet(name: "Maneet")` and `print("Hello, \(name)!")`. That's Swift's default, but each parameter actually has **two** names:

- The **argument label** is used by the *caller*, at the call site.
- The **parameter name** is used *inside* the function body.

Write the label first, then the parameter name:

```swift run
func move(from start: Int, to end: Int) {
    let distance = end - start
    print("Moving \(distance) steps from \(start) to \(end)")
}

move(from: 3, to: 10)
```

```output
Moving 7 steps from 3 to 10
```

What to notice:

- The call reads naturally: *move from 3 to 10*.
- Inside, `from` and `to` would be odd names for values, so the body uses `start` and `end` instead.
- When you write only one name, as in `name: String`, that single name serves as both the label and the parameter name.

<Callout kind="analogy" title="The front door and the kitchen">
The argument label is the name on the front door, the one visitors see. The parameter name is what the family calls the room inside. They can match, but they don't have to.
</Callout>

## Leaving the label out with `_`

Sometimes a label adds nothing. `square(number: 4)` says "number" twice, since the function name already tells you what goes in. An underscore, `_`, as the label means "no label at the call site":

```swift run
func square(_ number: Int) -> Int {
    number * number
}

func larger(_ a: Int, _ b: Int) -> Int {
    a > b ? a : b
}

print(square(4))
print(larger(7, 12))
```

```output
16
12
```

Inside the function, the parameter is still called `number`, or `a` and `b`. Only the caller's view changes.

Swift's own functions do the same: `print(x)`, `abs(-3)`, `max(a, b)`. A label is left out when:

- the function name already describes the first argument, as in `square(4)` or `print("Hi")`; or
- the arguments are equal partners that play the same role, as in `larger(7, 12)` or `max(a, b)`.

You can mix labelled and unlabelled parameters. A very common shape is "first argument unlabelled, the rest labelled":

```swift run
func repeatText(_ text: String, times count: Int) -> String {
    var result = ""
    for _ in 0..<count {
        result += text
    }
    return result
}

print(repeatText("ab", times: 3))
```

```output
ababab
```

`repeatText("ab", times: 3)` reads as a phrase. Compare it with `repeatText(text: "ab", count: 3)`, which is correct Swift but reads like a form being filled in.

## How functions are named in documentation

Documentation, error messages and this console refer to a function by its name plus its labels, each followed by a colon, with `_` for a missing label:

| Definition | Full name |
| --- | --- |
| `func move(from start: Int, to end: Int)` | `move(from:to:)` |
| `func square(_ number: Int) -> Int` | `square(_:)` |
| `func repeatText(_ text: String, times count: Int)` | `repeatText(_:times:)` |
| `func greet(name: String)` | `greet(name:)` |

The number of colons is the number of arguments. So when the standard library says `swapAt(_:_:)`, you know it takes two unlabelled arguments, and when a problem says `LargestElement.largest(in:)`, you call it as `largest(in: numbers)`.

## The same name, different labels

Labels are part of a function's identity. Two functions can share a base name if their labels differ, and Swift picks the right one from the call:

```swift run
func area(width: Int, height: Int) -> Int {
    width * height
}

func area(side: Int) -> Int {
    side * side
}

print(area(width: 3, height: 4))
print(area(side: 5))
```

```output
12
25
```

These are two separate functions, `area(width:height:)` and `area(side:)`. Defining several functions with one name is called **overloading**. Use it when the functions really do the same job in different ways.

## Naming functions the Swift way

Apple publishes the **Swift API Design Guidelines**, and the standard library follows them closely. The main ideas:

1. **Clarity at the point of use matters most.** Judge a name by how the *call* reads, not the definition.
2. **Read like an English phrase.** `insert(5, at: 0)` reads as "insert 5 at 0".
3. **Use prepositions as labels** when the argument plays that role: `from:`, `to:`, `in:`, `of:`, `at:`, `by:`, `with:`.
4. **Omit needless words.** Don't repeat the type or what the base name already says.
5. **Name by effect.** Functions that do something are verbs (`sort()`, `append(_:)`). Functions that answer a yes/no question read like a statement: `isEmpty`, `contains(_:)`, `isEven(_:)`.

| Unclear | Better | Why |
| --- | --- | --- |
| `squareNumber(number: 4)` | `square(4)` | "number" is said twice |
| `find(x: 3, a: list)` | `firstIndex(of: 3, in: list)` | labels say what each value is |
| `check(n: 7)` | `isPrime(7)` | the name says what's checked, and reads as a question |
| `distance(a: 2, b: 9)` | `distance(from: 2, to: 9)` | which is the start and which the end? |

In DSA you'll write signatures like `binarySearch(for target: Int, in numbers: [Int]) -> Int?`. The call `binarySearch(for: 7, in: sorted)` is self-explanatory, which matters when you come back to the code a week later.

<Callout kind="gotcha" title="Swift gotcha: labels aren't optional">
If a function has a label, you must write it, and in the defined order. Calling `square(number:)` as `square(4)` fails with `error: missing argument label 'number:' in call`. The fix is either to write the label, or to change the definition to `_ number` if the label really adds nothing.
</Callout>

<Callout kind="tip">
When you can't decide whether to drop a label, say the call out loud. If a word sounds repeated or missing, change the label.
</Callout>
