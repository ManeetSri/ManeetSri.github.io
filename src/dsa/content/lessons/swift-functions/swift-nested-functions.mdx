## Why it matters

Some helper functions only make sense inside one other function. A bounds check for one particular array, a small formatting step, a recursive search through one grid: nobody else should call them, and they need the outer function's data. Swift lets you define a function **inside** another function. In DSA you'll see this constantly, for example a solution function with a `dfs` helper nested inside it that can see the grid without being handed it on every call.

## A function inside a function

Define a nested function exactly like any other, but inside the outer function's body:

```swift run
func printReport(for scores: [Int]) {
    func label(for score: Int) -> String {
        if score >= 70 {
            return "distinction"
        } else if score >= 40 {
            return "pass"
        } else {
            return "fail"
        }
    }

    for score in scores {
        print("\(score): \(label(for: score))")
    }
}

printReport(for: [82, 45, 12])
```

```output
82: distinction
45: pass
12: fail
```

What to notice:

- `label(for:)` is an ordinary function, with parameters and a return type.
- It only exists inside `printReport(for:)`. Outside, the name means nothing: calling `label(for: 50)` at the top level fails with `error: cannot find 'label' in scope`.
- It's clearest to define nested functions near the top of the outer function, before the code that calls them, so a reader meets the helper first.

Hiding helpers like this keeps the rest of your program tidy. The helper can have a short, specific name like `label` without clashing with anything else.

## Capturing the outer function's values

A nested function can **see** the outer function's parameters and local variables, and use them directly, without having them passed in. This is called **capturing**.

Here's a DSA-flavoured example. A **peak** is a number bigger than both of its neighbours. The first and last numbers have only one neighbour each, so let's treat anything outside the array as height 0. A nested helper hides that boundary check:

```swift run
func countPeaks(in heights: [Int]) -> Int {
    // Positions outside the array count as height 0
    func height(at index: Int) -> Int {
        if index < 0 || index >= heights.count {
            return 0
        }
        return heights[index]
    }

    var peaks = 0
    for index in 0..<heights.count {
        let current = heights[index]
        if current > height(at: index - 1) && current > height(at: index + 1) {
            peaks += 1
        }
    }
    return peaks
}

print(countPeaks(in: [1, 3, 2, 5, 4]))
print(countPeaks(in: [4, 1, 1, 2]))
print(countPeaks(in: []))
```

```output
2
2
0
```

What to notice:

- `height(at:)` uses `heights`, the outer function's parameter, without taking it as a parameter of its own.
- The main loop reads cleanly: "bigger than the height on the left and the height on the right". The fiddly boundary rule lives in one place.
- Without the helper, the loop would need special cases for the first and last index. Off-by-one bugs love special cases.

### Changing captured variables

A nested function can also **change** the outer function's variables:

```swift run
func makeTea() {
    var stepNumber = 0

    func step(_ instruction: String) {
        stepNumber += 1
        print("\(stepNumber). \(instruction)")
    }

    step("Boil the kettle")
    step("Add a tea bag")
    step("Pour and wait three minutes")
    print("Done in \(stepNumber) steps")
}

makeTea()
```

```output
1. Boil the kettle
2. Add a tea bag
3. Pour and wait three minutes
Done in 3 steps
```

`step` shares `stepNumber` with `makeTea`. Each call adds one, and when `makeTea` reads it at the end, it sees 3.

### Helpers for in-place work

A nested function can even capture an `inout` parameter, as long as it's only used while the outer function runs. That makes a neat pattern for in-place algorithms: write the general tool once, then call it on different parts of the array.

```swift run
func reverseEachHalf(_ numbers: inout [Int]) {
    // Reverses numbers[start...end] in place
    func reverse(from start: Int, to end: Int) {
        var left = start
        var right = end
        while left < right {
            numbers.swapAt(left, right)
            left += 1
            right -= 1
        }
    }

    let middle = numbers.count / 2
    reverse(from: 0, to: middle - 1)
    reverse(from: middle, to: numbers.count - 1)
}

var values = [1, 2, 3, 4, 5, 6]
reverseEachHalf(&values)
print(values)
```

```output
[3, 2, 1, 6, 5, 4]
```

This is the reversal from [inout, swap and swapAt](/dsa/learn/swift-inout-swap), generalised to any stretch of the array. The helper reaches `numbers` by capturing it, so each call only needs the two positions.

## Why nest a helper?

| Reason | What it buys you |
| --- | --- |
| Hiding | The helper can't be called from anywhere it doesn't belong, and its name can't clash. |
| Capturing | It reads the outer data directly, so calls stay short: `height(at: i)` rather than `height(at: i, in: heights)`. |
| Reading in one place | Everything the solution needs is inside one function. |

Nesting isn't always right. If a helper would be useful elsewhere, make it a normal top-level function. If the outer function grows long enough that you're scrolling to find its real work, pull helpers out.

Nested functions can also call themselves. You'll meet that idea, **recursion**, in the last lesson of this module, and many tree and graph solutions are written as a short outer function with a recursive helper nested inside.

<Callout kind="gotcha" title="Swift gotcha: a capture shares the variable, it doesn't copy it">
A nested function doesn't take a snapshot of an outer variable when it's defined. It uses the variable itself, so it always sees the **current** value:

```swift
func demo() {
    var count = 0
    func show() { print(count) }
    count = 3
    show()      // prints 3, not 0
    count = 7
    show()      // prints 7
}
```

That's usually what you want, but it surprises people who expect the value at the moment the helper was written. You'll see the same rule for closures in M06.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: a parameter hides an outer name">
If a nested function has a parameter with the same name as an outer variable, the parameter wins inside the nested function, and the outer variable is hidden:

```swift run
func report(total: Int) {
    func describe(total: Int) -> String {
        "total is \(total)"
    }
    print(describe(total: 99))
    print("the outer total is \(total)")
}

report(total: 5)
```

```output
total is 99
the outer total is 5
```

Inside `describe`, `total` means its own parameter, 99. This is called **shadowing**. It's legal, but it makes code easy to misread, so give the nested function's parameters different names from the outer variables it might capture.
</Callout>
