## Why it matters

You've already used both features without knowing it. `print` accepts any number of values, and it has a `separator` and a `terminator` that you can set but usually don't. **Default parameters** keep calls short for the common case, and **variadic parameters** let a caller pass as many values as they like.

## Default parameter values

Give a parameter a value with `=` in the definition, and callers can leave that argument out:

```swift run
func greet(_ name: String, greeting: String = "Hello") {
    print("\(greeting), \(name)!")
}

greet("Maneet")
greet("Ada", greeting: "Good morning")
```

```output
Hello, Maneet!
Good morning, Ada!
```

What to notice:

- The first call skips `greeting`, so it gets the default, `"Hello"`.
- The second call passes its own value, which replaces the default for that call only.
- Callers who don't care never need to know the parameter exists.

You can have several defaults and skip any of them. The labels make it clear which ones you're setting:

```swift run
func power(_ base: Int, exponent: Int = 2, verbose: Bool = false) -> Int {
    var result = 1
    for _ in 0..<exponent {
        result *= base
    }
    if verbose {
        print("\(base) to the power \(exponent) is \(result)")
    }
    return result
}

print(power(5))
print(power(2, exponent: 10))
_ = power(3, verbose: true)
```

```output
25
1024
3 to the power 2 is 9
```

The last call skips `exponent` but sets `verbose`. That's allowed because the label `verbose:` tells Swift which parameter the value belongs to. The arguments you *do* pass still have to be in the defined order.

<Callout kind="tip">
Put parameters with defaults **after** the ones without. Then every call starts with the essential values, and the optional tweaks come at the end, like `print`'s `separator:` and `terminator:`.
</Callout>

### Where defaults help in DSA

Defaults are useful for "usually zero" starting points. A function that searches part of an array can default to searching all of it:

```swift run
func indexOf(_ target: Int, in numbers: [Int], startingAt start: Int = 0) -> Int? {
    var index = start
    while index < numbers.count {
        if numbers[index] == target {
            return index
        }
        index += 1
    }
    return nil
}

let numbers = [4, 7, 4, 9]
print(indexOf(4, in: numbers) ?? -1)
print(indexOf(4, in: numbers, startingAt: 1) ?? -1)
print(indexOf(8, in: numbers) ?? -1)
```

```output
0
2
-1
```

Most callers want the whole array and never mention `startingAt`. A caller that needs to continue a search from a later position can pass it. The return type is `Int?` because the target might not be there, and `?? -1` turns a missing result into `-1` for printing, as you saw in M04.

### Defaults instead of extra functions

Without defaults, you'd need a separate function for every combination of optional settings. With them, one function covers every case:

```swift run
func formatPrice(_ pence: Int, currency: String = "£", showPence: Bool = true) -> String {
    let pounds = pence / 100
    let remainder = pence % 100
    guard showPence else {
        return "\(currency)\(pounds)"
    }
    let penceText = remainder < 10 ? "0\(remainder)" : "\(remainder)"
    return "\(currency)\(pounds).\(penceText)"
}

print(formatPrice(1250))
print(formatPrice(1205, showPence: false))
print(formatPrice(999, currency: "€"))
```

```output
£12.50
£12
€9.99
```

Two settings with defaults give four combinations, all from one function, and a call that only cares about the price stays as short as `formatPrice(1250)`. When you add a new setting with a default later, every existing call keeps working unchanged.

## Variadic parameters

A **variadic** parameter accepts zero or more values of one type. Write `...` after the type:

```swift run
func sum(_ numbers: Int...) -> Int {
    var total = 0
    for number in numbers {
        total += number
    }
    return total
}

print(sum(1, 2, 3))
print(sum(10))
print(sum())
```

```output
6
10
0
```

What to notice:

- The caller passes values separated by commas, as many as they like, including none.
- Inside the function, `numbers` is an ordinary array, `[Int]`. You can loop over it, count it or index it.
- `print` works the same way. Its definition starts `print(_ items: Any...)`, which is why `print("a", "b", 3)` prints `a b 3`.

A variadic parameter can be combined with others, including defaults:

```swift run
func average(of values: Double..., roundedTo places: Int = 2) -> Double {
    guard !values.isEmpty else { return 0 }
    var total = 0.0
    for value in values {
        total += value
    }
    let mean = total / Double(values.count)
    var scale = 1.0
    for _ in 0..<places {
        scale *= 10
    }
    return (mean * scale).rounded() / scale
}

print(average(of: 1, 2, 2))
print(average(of: 1, 2, 2, roundedTo: 0))
```

```output
1.67
2.0
```

The label `roundedTo:` tells Swift where the list of values ends.

<Callout kind="gotcha" title="Swift gotcha: you can't pass an array to a variadic parameter">
Inside the function, a variadic parameter is an array, but you can't pass an array *in*:

```swift
let list = [1, 2, 3]
print(sum(list))
```

```text title="What you'll see"
error: cannot pass array of type '[Int]' as variadic arguments of type 'Int'
```

In DSA your data almost always arrives as an array, so solutions take `[Int]`, not `Int...`. If you want both styles, write the array version and have a small variadic function call it.
</Callout>

<Callout kind="note">
A default value is worked out afresh on each call that leaves it out, and it can't refer to the function's other parameters. Keep defaults simple: a number, a string, `false`, an empty array.
</Callout>
