## Why it matters

"Two players take turns; who wins with perfect play?" is a whole genre of contest and interview problems. For small games you can search every position, as in [Stone games and minimax DP](/dsa/learn/dpi-stone-games). But when the position splits into many independent parts (several piles, several boards, several tokens), the number of combined positions explodes. **Sprague–Grundy theory** sidesteps the explosion: it gives each part a single number, its **Grundy number**, and the whole position is a win exactly when the XOR of those numbers isn't 0. The game of **Nim** is where it starts, and XOR, from [XOR tricks](/dsa/learn/bits-xor-tricks), turns out to be the perfect tool.

## Impartial games and the last-move rule

This lesson is about **impartial games**:

- two players move alternately;
- the moves available depend only on the position, not on whose turn it is (in chess, you can only move your own pieces, so chess isn't impartial);
- every game ends after finitely many moves, with no draws;
- under **normal play**, the player who can't move **loses**. Equivalently, whoever makes the last move wins.

Every position is then one of two kinds:

- a **P-position**, where the **P**revious player (the one who just moved) wins: the player to move loses with perfect play;
- an **N-position**, where the **N**ext player, the one to move, wins.

Two rules sort every position, working back from the end:

1. A position with no moves is a P-position: the player to move has already lost.
2. A position is an N-position if **some** move leads to a P-position, and a P-position if **every** move leads to an N-position.

It's the same reasoning as "win if you can hand your opponent a losing position", which is all minimax is.

## One pile, take 1 to 3

A single pile of n stones; a move removes 1, 2 or 3. Apply the rules from 0 upwards:

```swift run
// One pile, take 1, 2 or 3 stones; whoever takes the last stone wins.
// A position wins if some move leads to a losing position for the opponent.
var wins = [false]                       // 0 stones: no move, so the player to move has lost
for n in 1...12 {
    wins.append([1, 2, 3].contains { $0 <= n && !wins[n - $0] })
}
print((0...12).filter { !wins[$0] })     // the losing positions
```

```output
[0, 4, 8, 12]
```

The P-positions are the multiples of 4. The strategy follows: always leave your opponent a multiple of 4. Whatever they take, 1 to 3, you take the rest of the 4. From a multiple of 4 itself, there's no good move, so you hope your opponent slips.

## Nim

**Nim** has several piles. A move takes any positive number of stones from **one** pile. With piles 3, 4 and 5, can the first player win?

The answer, found by Charles Bouton in 1901, is a single XOR:

> A Nim position is a P-position exactly when the **XOR of the pile sizes is 0**.

For 3, 4 and 5: 3 ^ 4 = 7, and 7 ^ 5 = 2. Step through that last XOR bit by bit:

```visual bitPlayground
value: 7
operand: 5
operator: "^"
```

XOR adds each column of bits without carrying: a column with an odd number of 1s gives 1. The total is 2, not 0, so the first player wins.

### Why the XOR rule works

Three facts prove it, matching the two rules for P- and N-positions:

1. **The end has XOR 0.** All piles empty: 0 ^ 0 ^ … = 0, and it's a P-position.
2. **From XOR 0, every move gives a non-zero XOR.** A move changes exactly one pile, from x to some other y. The new total is the old one with x replaced by y, which is total ^ x ^ y = 0 ^ x ^ y, and that's 0 only if x = y. So the opponent always receives a non-zero XOR.
3. **From a non-zero XOR, some move gives XOR 0.** Let X be the total, and look at its highest 1 bit. Some pile has a 1 in that bit position, or the column couldn't add up to 1. Shrink that pile from x to x ^ X. That turns off the high bit and only changes lower bits, so x ^ X is smaller than x: a legal move. And the new total is X ^ x ^ (x ^ X) = 0.

So the player facing a non-zero XOR can always hand back XOR 0, and the player facing XOR 0 can never do the same. Eventually the piles run out with the XOR-0 player to move, and they lose.

```swift run
// Nim: the player to move wins exactly when the XOR of the piles isn't 0
func winningMove(_ piles: [Int]) -> (pile: Int, take: Int)? {
    let total = piles.reduce(0, ^)
    if total == 0 { return nil }                     // every move hands the opponent a non-zero XOR
    for (i, pile) in piles.enumerated() where pile ^ total < pile {
        return (i, pile - (pile ^ total))            // shrink this pile to pile ^ total
    }
    return nil                                       // unreachable: some pile has total's top bit
}

print([3, 4, 5].reduce(0, ^), winningMove([3, 4, 5])!)
print([1, 4, 5].reduce(0, ^), winningMove([1, 4, 5]) as Any)
print(winningMove([10, 7, 12, 2])!)
```

```output
2 (pile: 0, take: 2)
0 nil
(pile: 0, take: 1)
```

From 3, 4, 5 the winning move takes 2 from the first pile, leaving 1, 4, 5, whose XOR is 0. `pile ^ total < pile` is the test from fact 3: it's true exactly for the piles that have the total's highest bit.

A rule this surprising deserves a check. Here's a brute-force search over every three-pile position up to 5 stones each, memoised like any game DP, compared with the XOR rule:

```swift run
// Brute force: search every move of three-pile Nim, remembering each position's result
var memo: [[Int]: Bool] = [:]
func playerToMoveWins(_ piles: [Int]) -> Bool {
    if let known = memo[piles] { return known }
    var result = false
    for i in piles.indices where !result {
        for take in stride(from: 1, through: piles[i], by: 1) {
            var next = piles
            next[i] -= take
            if !playerToMoveWins(next) {
                result = true
                break
            }
        }
    }
    memo[piles] = result
    return result
}

var positions = 0
var agree = 0
for a in 0...5 {
    for b in 0...5 {
        for c in 0...5 {
            positions += 1
            if playerToMoveWins([a, b, c]) == ((a ^ b ^ c) != 0) { agree += 1 }
        }
    }
}
print(positions, agree)
```

```output
216 216
```

All 216 positions agree. The search visits every position; the XOR rule answers each in O(number of piles).

## Grundy numbers and mex

Nim is special because a pile can shrink to *any* smaller size. Most games are more restrictive. To handle them, give every position a number.

The **mex** (minimum excludant) of a set of non-negative integers is the smallest non-negative integer **not** in it: mex of \{0, 1, 3\} is 2, mex of \{1, 2\} is 0, and the mex of the empty set is 0.

The **Grundy number** of a position is the mex of the Grundy numbers of the positions it can move to:

```text
g(position) = mex { g(next) : next is reachable in one move }
```

A position with no moves gets mex of nothing, 0. Then g = 0 exactly for P-positions: a position has g = 0 when no move reaches a 0, and g is positive when some move does, which are the two rules from earlier. For a single Nim pile of n stones, the moves reach every size from 0 to n − 1, so g(n) = n.

Here's a game where a move removes 1, 3 or 4 stones from a single pile:

```swift run
// The minimum excludant: the smallest non-negative integer not in the list
func mex(_ values: [Int]) -> Int {
    var seen = Array(repeating: false, count: values.count + 1)
    for v in values where v < seen.count { seen[v] = true }
    return seen.firstIndex(of: false)!
}

// Grundy numbers for one pile when a move removes 1, 3 or 4 stones
let moves = [1, 3, 4]
var grundy: [Int] = []
for n in 0...20 {
    grundy.append(mex(moves.filter { $0 <= n }.map { grundy[n - $0] }))
}
print(grundy)
print(mex([0, 1, 3]), mex([1, 2]), mex([]))
// A sum of three such piles: XOR their Grundy numbers
let piles = [5, 6, 9]
print(piles.map { grundy[$0] }, piles.map { grundy[$0] }.reduce(0, ^))
```

```output
[0, 1, 0, 1, 2, 3, 2, 0, 1, 0, 1, 2, 3, 2, 0, 1, 0, 1, 2, 3, 2]
2 0 0
[3, 2, 0] 1
```

What to notice:

- **The mex helper only needs values.count + 1 slots.** With k options, at least one of 0 to k is missing, so the mex is at most k, and bigger values can be ignored.
- **The Grundy numbers repeat with period 7**: 0, 1, 0, 1, 2, 3, 2. Subtraction games always become periodic eventually, which is handy for huge piles, but don't assume a period without computing far enough to see it.
- **The losing single piles are 0, 2, 7, 9, 14, 16, …**, the places where g = 0.

## The Sprague–Grundy theorem

The last line of that example XORed three Grundy numbers. Why is that allowed? Because of the theorem at the heart of this lesson, proved independently by Roland Sprague and Patrick Grundy in the 1930s:

> Every impartial game position behaves exactly like a single Nim pile whose size is its Grundy number. In a **sum of games**, where each move is made in one component of your choice, the Grundy number of the whole is the **XOR** of the components' Grundy numbers.

Here's why. A component with Grundy number g can move to positions with every Grundy value 0, 1, …, g − 1 (that's what mex means), exactly like a Nim pile of size g. It might also be able to move to some values *above* g, which a Nim pile can't. But those moves don't help: if a player moves a component up from g to some bigger value, the opponent can move it straight back down to g, since a position with a bigger Grundy number can reach every smaller value, g included. So the sum plays like Nim on the Grundy numbers, and Nim is won by XOR.

For the piles 5, 6 and 9 in the 1-3-4 game, the Grundy numbers are 3, 2 and 0, and 3 ^ 2 ^ 0 = 1, so the first player wins. To find the move, make the XOR 0: the pile of 5 (g = 3) needs to become a position with g = 3 ^ 1 = 2. From 5, removing 1 reaches 4, whose Grundy number is 2. After that the total is 2 ^ 2 ^ 0 = 0.

## Games that split

The theorem gets more powerful when a move can **split** one part into several. The result of a split is itself a sum of games, so its Grundy number is the XOR of the parts. Take **Lasker's Nim**: a move either removes any number of stones from one pile, or splits one pile into two non-empty piles.

```swift run
func mex(_ values: [Int]) -> Int {
    var seen = Array(repeating: false, count: values.count + 1)
    for v in values where v < seen.count { seen[v] = true }
    return seen.firstIndex(of: false)!
}

// Lasker's Nim: take any number of stones from one pile, or split one pile into two non-empty piles
var grundy = [0]
for n in 1...16 {
    var options: [Int] = []
    for take in 1...n {
        options.append(grundy[n - take])              // a single smaller pile
    }
    var a = 1
    while a <= n - a {
        options.append(grundy[a] ^ grundy[n - a])     // two piles: a sum of games, so XOR
        a += 1
    }
    grundy.append(mex(options))
}
print(grundy)

// Check the theorem by brute force: search every position of up to three piles of at most 6
var memo: [[Int]: Bool] = [:]
func wins(_ position: [Int]) -> Bool {
    let piles = position.filter { $0 > 0 }.sorted()
    if let known = memo[piles] { return known }
    var result = false
    search: for (i, pile) in piles.enumerated() {
        var rest = piles
        rest.remove(at: i)
        for take in stride(from: 1, through: pile, by: 1) where !wins(rest + [pile - take]) {
            result = true
            break search
        }
        var a = 1
        while a <= pile - a {
            if !wins(rest + [a, pile - a]) {
                result = true
                break search
            }
            a += 1
        }
    }
    memo[piles] = result
    return result
}

var checked = 0
var agree = 0
for x in 0...6 {
    for y in x...6 {
        for z in y...6 {
            checked += 1
            if wins([x, y, z]) == (grundy[x] ^ grundy[y] ^ grundy[z] != 0) { agree += 1 }
        }
    }
}
print(checked, agree)
```

```output
[0, 1, 2, 4, 3, 5, 6, 8, 7, 9, 10, 12, 11, 13, 14, 16, 15]
84 84
```

The Grundy numbers are almost the pile sizes, except that each pair 4k + 3 and 4k + 4 is swapped: g(3) = 4, g(4) = 3, g(7) = 8. The brute force stores positions as sorted lists of non-empty piles, so equal positions share one memo entry, and splitting can grow a position to many piles. It agrees with the XOR of Grundy numbers on every one of the 84 starting positions.

## The recipe

1. **Split the position into independent components**: piles, boards, tokens that never interact.
2. **Compute each component's Grundy number** with a mex over its moves, by DP from small positions up, or by memoised recursion. A move that splits a component contributes the XOR of the pieces.
3. **XOR the components' numbers.** Non-zero means the player to move wins.
4. **To play the winning move**, find a component whose Grundy number g has the total's highest bit, and move it to a position with Grundy number g ^ total.

The cost is the work to fill the Grundy table, the number of states times the number of moves from each, plus O(1) per component. For a pile game with piles up to M and splits allowed, that's about M²/2 split options in total, tiny compared with searching combined positions.

<Callout kind="note" title="Misère play">
If the player who makes the last move **loses** instead (misère play), the theory changes. For Nim the fix is small: play exactly as in normal Nim, except when your move would leave only piles of size 1, leave an odd number of them. For most other games misère play is much harder, and Sprague–Grundy doesn't apply directly. Read the rules carefully.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **XORing the pile sizes in a game that isn't Nim.** The XOR rule applies to Grundy numbers. Only in plain Nim are they equal to the pile sizes. In the 1-3-4 game, a single pile of 2 is a loss even though 2 isn't 0.
- **A mex array that's too small.** A position with k options has a Grundy number of at most k, but an XOR of two Grundy numbers can be bigger than either. Size the array by the number of options, and ignore larger values.
- **Partisan games.** If the players have different moves (chess, or a game where each player owns some piles), Sprague–Grundy doesn't apply. Use minimax over the actual positions.
- **Counting splits twice.** Splitting n into a and n − a and into n − a and a is the same move. Loop a only up to n / 2, or the option list double-counts. That doesn't change the mex, but it wastes time.
</Callout>

## Practice

**Remove or split** is a pile game with a twist: a move either removes one of a given set of sizes from a pile, or splits a pile into two non-empty piles of **different** sizes. With up to 10,000 piles of up to 2,000 stones, only Sprague–Grundy is fast enough. Its tests compare your answers with a full game search on small positions, so a wrong mex or a missing option shows up quickly.
