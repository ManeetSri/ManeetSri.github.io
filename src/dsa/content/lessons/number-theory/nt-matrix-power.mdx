## Why it matters

Plenty of problems boil down to "apply the same step n times", where n is 10¹⁸: the nth term of a recurrence, the number of ways to tile a 2 × n strip, the number of length-n strings that avoid a pattern, or the number of routes of exactly n hops through a network. Looping n times is out of the question. When each step is a **linear** function of a small state, the step is a matrix, n steps are a matrix power, and [Fast exponentiation](/dsa/learn/math-fast-power) computes that power in O(log n) multiplications. You previewed this with Fibonacci in [Matrix basics](/dsa/learn/math-matrices); this lesson turns it into a method you can apply to any linear recurrence, with constants, running sums and graphs along the way.

## The idea: a step is a matrix

In [Matrix basics](/dsa/learn/math-matrices), multiplying the pair (F(n + 1), F(n)) by the matrix `[[1, 1], [1, 0]]` gave (F(n + 2), F(n + 1)): one step of the Fibonacci rule. In general, suppose your process keeps a **state vector** v, and one step replaces it with M × v for a fixed matrix M. Then

```text
after n steps:   M × M × … × M × v  =  Mⁿ × v
```

Matrix multiplication is **associative**, (A × B) × C = A × (B × C), even though it isn't commutative. That's all fast power needs: it never reorders factors, it only groups them differently. So the square-and-multiply loop works on matrices exactly as on numbers, with the **identity matrix** I in place of 1. [Fast power as divide and conquer](/dsa/learn/dc-fast-power) showed the same algorithm as halving the problem; here the "numbers" being multiplied are k × k matrices.

## The companion matrix

Take a linear recurrence of order k, each term a fixed combination of the k before it:

```text
a(n) = c₁ × a(n − 1) + c₂ × a(n − 2) + … + c_k × a(n − k)
```

Keep the last k terms as the state, newest first: v = [a(n − 1), a(n − 2), …, a(n − k)]. One step must produce [a(n), a(n − 1), …, a(n − k + 1)]:

- the new first entry is the recurrence itself, so the first row of M is the coefficients c₁, …, c_k;
- every other entry is an old entry moved down one place, so the rows below are a shifted identity, a single 1 just left of the diagonal.

That matrix is called the **companion matrix**. For the **tribonacci** numbers, T(n) = T(n − 1) + T(n − 2) + T(n − 3), starting 0, 1, 1:

```text
| T(n)     |     | 1  1  1 |   | T(n − 1) |
| T(n − 1) |  =  | 1  0  0 | × | T(n − 2) |
| T(n − 2) |     | 0  1  0 |   | T(n − 3) |
```

Start from [T(2), T(1), T(0)] = [1, 1, 0]. After n − 2 steps, the first entry is T(n).

## A k × k power, modulo p

Here's a general version: multiplication for any compatible shapes, the identity, and fast power. Everything is reduced modulo 1,000,000,007.

```swift run
let mod = 1_000_000_007
typealias Matrix = [[Int]]

func multiply(_ a: Matrix, _ b: Matrix) -> Matrix {
    let n = a.count, inner = b.count, m = b[0].count
    var c = Array(repeating: Array(repeating: 0, count: m), count: n)
    for i in 0..<n {
        for t in 0..<inner where a[i][t] != 0 {
            for j in 0..<m {
                c[i][j] = (c[i][j] + a[i][t] * b[t][j]) % mod   // reduce every product before the next one is added
            }
        }
    }
    return c
}

func identity(_ size: Int) -> Matrix {
    (0..<size).map { i in (0..<size).map { j in i == j ? 1 : 0 } }
}

func power(_ base: Matrix, _ exponent: Int) -> Matrix {
    var result = identity(base.count)
    var square = base
    var e = exponent
    while e > 0 {
        if e & 1 == 1 { result = multiply(result, square) }
        square = multiply(square, square)
        e >>= 1
    }
    return result
}

// Tribonacci: T(n) = T(n-1) + T(n-2) + T(n-3), starting 0, 1, 1
let step: Matrix = [[1, 1, 1],
                    [1, 0, 0],
                    [0, 1, 0]]
func tribonacci(_ n: Int) -> Int {
    if n < 3 { return [0, 1, 1][n] }
    let m = power(step, n - 2)
    let start: Matrix = [[1], [1], [0]]            // [T(2), T(1), T(0)] as a column
    return multiply(m, start)[0][0]
}

var slow = [0, 1, 1]
while slow.count < 15 { slow.append(slow[slow.count - 1] + slow[slow.count - 2] + slow[slow.count - 3]) }
print(slow)
print((0..<15).map(tribonacci))
print(tribonacci(1_000_000_000_000_000_000))
```

```output
[0, 1, 1, 2, 4, 7, 13, 24, 44, 81, 149, 274, 504, 927, 1705]
[0, 1, 1, 2, 4, 7, 13, 24, 44, 81, 149, 274, 504, 927, 1705]
926781415
```

What to notice:

- **Check against the slow loop first.** The first 15 terms match, so the matrix and the starting vector are right. Only then trust the answer for 10¹⁸.
- **The start vector is a column**, a matrix with one column, so the same `multiply` handles it. Writing [[1], [1], [0]] rather than [1, 1, 0] keeps the shapes honest.
- **Small n is handled separately.** The power is n − 2, which only makes sense from n = 2 up. Terms already in the start vector are returned directly.
- **The loop order is i, t, j.** It computes the same sums as i, j, t, but walks along rows of b, which is friendlier to memory, and the `where a[i][t] != 0` skips work for the many zeros in a companion matrix.
- **Order inside fast power doesn't matter here.** `result` and `square` are both powers of the same matrix, and powers of one matrix do commute, so `multiply(result, square)` and `multiply(square, result)` are equal.

## Overflow: reduce every product

Each entry of a product is a sum of k terms a[i][t] × b[t][j]. Modulo 1,000,000,007, each term is below about 10¹⁸, and `Int.max` is about 9.2 × 10¹⁸. So adding nine unreduced products still fits, but ten don't, and a 10 × 10 matrix would trap:

```text title="What you'll see summing ten products before reducing"
Swift runtime failure: arithmetic overflow
```

With a modulus near 2³¹, like 2,147,483,647, a single product can be about 4.6 × 10¹⁸, so two of them only just fit and three overflow. The safe habit is the one in the code above: **reduce after every product**, so the running sum is always below the modulus before the next product is added.

## Beyond pure recurrences

The trick extends to anything you can make linear by adding entries to the state.

**A constant term.** For a(n) = a(n − 1) + a(n − 2) + 1, carry a constant 1 along in the state: [a(n − 1), a(n − 2), 1]. Its row in the matrix is [0, 0, 1], so it stays 1, and the first row is [1, 1, 1] to add it in.

**A running sum.** To get S(n) = F(0) + F(1) + … + F(n) for the Fibonacci numbers, carry S along: from [F(n + 1), F(n), S(n)], the next state is [F(n + 2), F(n + 1), S(n) + F(n + 1)]. Each new entry is a combination of old ones, so it's a matrix:

```text
| F(n + 2)     |     | 1  1  0 |   | F(n + 1) |
| F(n + 1)     |  =  | 1  0  0 | × | F(n)     |
| S(n + 1)     |     | 1  0  1 |   | S(n)     |
```

## Counting walks in a graph

Here's a different kind of state. Take a graph's **adjacency matrix** A from [Adjacency matrix, list and edge list](/dsa/learn/graph-representations): A[i][j] is 1 when there's an edge from i to j. Then **(Aᴸ)[i][j] is the number of walks of exactly L edges from i to j**. A walk of length L + 1 from i to j is a walk of length L from i to some t, followed by an edge from t to j, and summing over t is exactly the entry of Aᴸ × A. Walks may revisit vertices, so this counts routes, not simple paths.

The next example uses both ideas. A triangle, where each vertex joins the other two, has a known formula for closed walks: (2ᴸ + 2 × (−1)ᴸ) / 3 from a vertex back to itself. The division by 3 becomes a Fermat inverse from [Fermat's little theorem and CRT](/dsa/learn/nt-fermat-crt):

```swift run
let mod = 1_000_000_007
typealias Matrix = [[Int]]

func multiply(_ a: Matrix, _ b: Matrix) -> Matrix {
    var c = Array(repeating: Array(repeating: 0, count: b[0].count), count: a.count)
    for i in 0..<a.count {
        for t in 0..<b.count {
            for j in 0..<b[0].count {
                c[i][j] = (c[i][j] + a[i][t] * b[t][j]) % mod
            }
        }
    }
    return c
}

func power(_ base: Matrix, _ exponent: Int) -> Matrix {
    var result = (0..<base.count).map { i in (0..<base.count).map { j in i == j ? 1 : 0 } }
    var square = base
    var e = exponent
    while e > 0 {
        if e & 1 == 1 { result = multiply(result, square) }
        square = multiply(square, square)
        e >>= 1
    }
    return result
}

func modPow(_ base: Int, _ exponent: Int) -> Int {
    var result = 1, square = base % mod, e = exponent
    while e > 0 {
        if e & 1 == 1 { result = result * square % mod }
        square = square * square % mod
        e >>= 1
    }
    return result
}

// Walks in a triangle: every vertex joined to the other two
let triangle: Matrix = [[0, 1, 1], [1, 0, 1], [1, 1, 0]]
print(power(triangle, 4))
let n = 1_000_000_000_000_000_000
let walks = power(triangle, n)[0][0]
// closed form (2^n + 2·(-1)^n) / 3, dividing by 3 with a Fermat inverse
let formula = (modPow(2, n) + (n % 2 == 0 ? 2 : mod - 2)) % mod * modPow(3, mod - 2) % mod
print(walks, formula)

// The running sum of Fibonacci numbers, carried along as a third entry of the state
let fibWithSum: Matrix = [[1, 1, 0],
                          [1, 0, 0],
                          [1, 0, 1]]
for steps in [5, 10] {
    let state = multiply(power(fibWithSum, steps), [[1], [0], [0]])   // start: [F(1), F(0), S(0)]
    print(steps, state.map { $0[0] })
}
let big = multiply(power(fibWithSum, n), [[1], [0], [0]]).map { $0[0] }
let fibPlus2 = power([[1, 1], [1, 0]], n + 2)[0][1]
print(big[2], (fibPlus2 - 1 + mod) % mod)
```

```output
[[6, 5, 5], [5, 6, 5], [5, 5, 6]]
906492092 906492092
5 [8, 5, 12]
10 [89, 55, 143]
889840848 889840848
```

What to notice:

- **6 closed walks of length 4** from each corner of the triangle: (16 + 2) / 3 = 6. The matrix power and the closed form agree for L = 10¹⁸ as well.
- **The running sum works**: after 5 steps the state is [F(6), F(5), S(5)] = [8, 5, 12], and 0 + 1 + 1 + 2 + 3 + 5 = 12.
- **A second check for free.** The Fibonacci sum has its own closed form, S(n) = F(n + 2) − 1, and the last line confirms it at n = 10¹⁸. When two independent methods agree on a huge input, you can be confident in both.

## How fast is it?

Each multiplication of k × k matrices costs k³ multiply-adds, and fast power does at most 2 log₂ n of them:

| Method | Cost | k = 3, n = 10¹⁸ |
| --- | --- | --- |
| step the recurrence n times | O(k × n) | 3 × 10¹⁸: never finishes |
| matrix power | O(k³ log n) | about 27 × 120 ≈ 3,200 multiply-adds |

The k³ grows quickly, though. For k = 100, each multiplication is a million operations and the whole power about 10⁸, still fine. Beyond a few hundred, there are faster methods that work with polynomials of degree k instead of k × k matrices, but matrix power covers almost every contest problem.

<Callout kind="gotcha" title="Common mistakes">
- **An off-by-one power.** If the start vector holds terms up to a(k − 1), reaching a(n) takes n − k + 1 steps. Check the first few terms against a plain loop before trusting a huge n.
- **Forgetting small n.** For n below k the answer is in the start vector, and a power of n − k + 1 would be negative.
- **Starting from 0 instead of I.** The empty product of matrices is the identity, just as the empty product of numbers is 1. A zero matrix stays zero.
- **Negative coefficients.** Reduce them into 0 to p − 1 first with `((c % p) + p) % p`, as in [Modular arithmetic](/dsa/learn/math-modular-arithmetic). The safe-product rule assumes non-negative values below p.
</Callout>
