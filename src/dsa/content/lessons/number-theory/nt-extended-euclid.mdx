## Why it matters

In [Modular arithmetic](/dsa/learn/math-modular-arithmetic) you could add, subtract and multiply modulo m, but division broke. That hurts, because counting formulas are full of division: n! / (k! (n − k)!), n(n + 1) / 2, a probability written as p / q. The fix is to multiply by a **modular inverse** instead of dividing, and the tool that finds inverses is the **extended Euclidean algorithm**: Euclid's gcd loop with two extra pieces of bookkeeping. It's how RSA computes its private key, it powers the Chinese remainder theorem in the next lesson, and it solves equations like "which step lands on b?" for anything that wraps around, from circular buffers to clock arithmetic.

## Euclid, one more time

You met Euclid's algorithm in [GCD, LCM and Euclid's algorithm](/dsa/learn/math-gcd-lcm). It rests on one fact, gcd(a, b) = gcd(b, a % b), and stops when the second number reaches 0. Here it is on the pair this lesson uses throughout, 240 and 46:

```visual traceTable
program: gcd
input: { first: 240, second: 46 }
```

Each pass writes the larger number as a multiple of the smaller plus a remainder:

```text
240 = 5 × 46 + 10
 46 = 4 × 10 + 6
 10 = 1 × 6  + 4
  6 = 1 × 4  + 2
  4 = 2 × 2  + 0      so gcd(240, 46) = 2
```

Plain Euclid throws those quotients (5, 4, 1, 1, 2) away. The extended version keeps them, and uses them to answer a sharper question.

## Bézout's identity

Here's a fact that looks like a party trick and turns out to be the key to modular division:

> For any integers a and b, there are integers x and y with **ax + by = gcd(a, b)**.

This is **Bézout's identity**, and x and y are called **Bézout coefficients**. For 240 and 46:

```text
240 × (−9) + 46 × 47 = −2160 + 2162 = 2
```

One of the coefficients is usually negative. They aren't unique either: adding 46 / 2 = 23 to x and subtracting 240 / 2 = 120 from y gives another pair, 240 × 14 + 46 × (−73) = 2.

Why should it be true? Every number of the form ax + by is a multiple of gcd(a, b), since g divides both a and b. Euclid's remainders are all of that form: 10 = 240 − 5 × 46, then 6 = 46 − 4 × 10, and so on, each a combination of the two before it. The last non-zero remainder is the gcd, so the gcd is a combination of a and b too. Turning that argument into code is the extended Euclidean algorithm.

### Why you care

Suppose gcd(a, m) = 1. Bézout gives ax + my = 1. Look at that modulo m: the term my is a multiple of m, so it vanishes, leaving

```text
a × x ≡ 1 (mod m)
```

So x is a number that undoes multiplication by a: the **inverse** of a modulo m. Finding Bézout coefficients is finding inverses.

## Working backwards: the recursive version

Euclid's recursion says gcd(a, b) = gcd(b, a % b). Suppose the recursive call has already found coefficients for the smaller pair:

```text
b × x₁ + (a % b) × y₁ = g
```

In Swift, `a % b` is a − (a / b) × b for non-negative a and b, with `/` rounding down. Substitute that in and collect the a terms and the b terms:

```text
b × x₁ + (a − (a / b) × b) × y₁ = g
a × y₁ + b × (x₁ − (a / b) × y₁) = g
```

So the coefficients for (a, b) are x = y₁ and y = x₁ − (a / b) × y₁. The base case is gcd(a, 0) = a, which is a × 1 + 0 × 0, so (x, y) = (1, 0).

```swift run
// Recursive extended Euclid: returns (g, x, y) with a·x + b·y = g = gcd(a, b)
func extendedGCD(_ a: Int, _ b: Int) -> (g: Int, x: Int, y: Int) {
    if b == 0 {
        return (a, 1, 0)
    }
    let (g, x1, y1) = extendedGCD(b, a % b)
    return (g, y1, x1 - (a / b) * y1)
}

let (g, x, y) = extendedGCD(240, 46)
print(g, x, y)
print(240 * x + 46 * y)
print(extendedGCD(46, 240))
print(extendedGCD(17, 5))
```

```output
2 -9 47
2
(g: 2, x: 47, y: -9)
(g: 1, x: -2, y: 7)
```

Here's how the answer is built on the way back up. Each row uses the row below it:

| Call | a / b | Returns (x, y) | Check |
| --- | --- | --- | --- |
| (4, 2) → (2, 0) | 2 | (0, 1) | 4 × 0 + 2 × 1 = 2 |
| (6, 4) | 1 | (1, 0 − 1 × 1) = (1, −1) | 6 − 4 = 2 |
| (10, 6) | 1 | (−1, 1 − 1 × (−1)) = (−1, 2) | −10 + 12 = 2 |
| (46, 10) | 4 | (2, −1 − 4 × 2) = (2, −9) | 92 − 90 = 2 |
| (240, 46) | 5 | (−9, 2 − 5 × (−9)) = (−9, 47) | −2160 + 2162 = 2 |

The last line, 17 × (−2) + 5 × 7 = 1, says that −2 is an inverse of 17 modulo 5, and 7 is an inverse of 5 modulo 17. Check the second: 5 × 7 = 35 = 2 × 17 + 1.

## The iterative version

Recursion depth here is only about 2 log₂ of the smaller number, so the recursive version is perfectly safe. But the loop version is the one competitive programmers keep in their heads, and it shows *why* the algorithm works.

Keep three columns, r, s and t, with the promise that every row satisfies **r = 240 × s + 46 × t**. The first two rows are free: 240 = 240 × 1 + 46 × 0 and 46 = 240 × 0 + 46 × 1. After that, each new row is "the row two above, minus q times the row above", where q is Euclid's quotient. Subtracting rows keeps the promise, and the r column does exactly what Euclid does:

| q | r | s | t | Check: 240s + 46t |
| --- | --- | --- | --- | --- |
| | 240 | 1 | 0 | 240 |
| | 46 | 0 | 1 | 46 |
| 5 | 10 | 1 | −5 | 240 − 230 = 10 |
| 4 | 6 | −4 | 21 | −960 + 966 = 6 |
| 1 | 4 | 5 | −26 | 1200 − 1196 = 4 |
| 1 | 2 | −9 | 47 | −2160 + 2162 = 2 |
| 2 | 0 | 23 | −120 | 5520 − 5520 = 0 |

When r reaches 0, the row above it holds the gcd and its coefficients: 2, −9 and 47, the same answer as the recursion. (The final row is a bonus: 23 and −120 are 46 / 2 and −240 / 2, the step between one Bézout pair and the next.)

The code only ever needs the last two rows, so it keeps them as pairs and updates each pair with one tuple assignment, exactly like `(a, b) = (b, a % b)` in plain Euclid:

```swift run
// Iterative extended Euclid. Invariants: oldR = a·oldS + b·oldT and r = a·s + b·t
func extendedGCD(_ a: Int, _ b: Int) -> (g: Int, x: Int, y: Int) {
    var (oldR, r) = (a, b)
    var (oldS, s) = (1, 0)
    var (oldT, t) = (0, 1)
    while r != 0 {
        let q = oldR / r
        (oldR, r) = (r, oldR - q * r)
        (oldS, s) = (s, oldS - q * s)
        (oldT, t) = (t, oldT - q * t)
    }
    return (oldR, oldS, oldT)
}

print(extendedGCD(240, 46))
print(extendedGCD(1_000_000_000_000_000_000, 999_999_999_999_999_989))
```

```output
(g: 2, x: -9, y: 47)
(g: 1, x: -90909090909090908, y: 90909090909090909)
```

What to notice:

- **`oldR - q * r` is `oldR % r`.** The r column is plain Euclid; the s and t columns just follow along.
- **It runs in O(log min(a, b)) passes**, the same as Euclid, because it *is* Euclid.
- **The coefficients stay small.** For positive a and b, the x it returns is at most b / g in size and y at most a / g. That's why the second line works at all: the inputs are near 10¹⁸, but nothing inside the loop overflows. If they did overflow, Swift would trap rather than quietly give a wrong answer.

## The modular inverse

The **inverse of a modulo m**, written a⁻¹, is a number x with a × x ≡ 1 (mod m). Modulo 7, the inverse of 3 is 5, because 3 × 5 = 15 = 2 × 7 + 1.

**a has an inverse modulo m exactly when gcd(a, m) = 1.** Both directions are short:

- If gcd(a, m) = 1, extended Euclid gives ax + my = 1, and x is the inverse, as you saw above.
- If g = gcd(a, m) is bigger than 1, then a × x − 1 would have to be a multiple of m, say a × x − 1 = m × k. But g divides a × x and m × k, so it divides their difference, which is 1. No number bigger than 1 divides 1, so there's no inverse.

So 4 has no inverse modulo 6: 4x is always even, and an even number is never 1 more than a multiple of 6. When m is prime, every a from 1 to m − 1 is coprime to it, so **every non-zero value has an inverse modulo a prime**. That's the deeper reason problem setters love the prime 1,000,000,007.

The x that extended Euclid returns can be negative, so normalise it into 0 to m − 1 with the same fix you used for negative remainders:

```swift run
func extendedGCD(_ a: Int, _ b: Int) -> (g: Int, x: Int, y: Int) {
    var (oldR, r) = (a, b)
    var (oldS, s) = (1, 0)
    var (oldT, t) = (0, 1)
    while r != 0 {
        let q = oldR / r
        (oldR, r) = (r, oldR - q * r)
        (oldS, s) = (s, oldS - q * s)
        (oldT, t) = (t, oldT - q * t)
    }
    return (oldR, oldS, oldT)
}

// The inverse of a modulo m, or nil when gcd(a, m) isn't 1
func modInverse(_ a: Int, _ m: Int) -> Int? {
    let reduced = ((a % m) + m) % m
    let (g, x, _) = extendedGCD(reduced, m)
    guard g == 1 else { return nil }
    return ((x % m) + m) % m
}

print(modInverse(3, 11) as Any, modInverse(6, 9) as Any, modInverse(-3, 11) as Any)
print((1..<7).map { modInverse($0, 7)! })
let big = 1_000_000_007
let inverse = modInverse(123_456_789, big)!
print(inverse, 123_456_789 * inverse % big)
print(modInverse(5, 1) as Any)
```

```output
Optional(4) nil Optional(7)
[1, 4, 5, 2, 3, 6]
18633540 1
Optional(0)
```

What to notice:

- **3 × 4 = 12 ≡ 1 (mod 11)**, and −3 ≡ 8, whose inverse is 7: 8 × 7 = 56 = 5 × 11 + 1. Reducing a first makes negative inputs work.
- **6 and 9 share the factor 3**, so there's no inverse, and the function says so with `nil` instead of returning garbage.
- **Modulo 7, inverses pair up**: 2 and 4 are each other's inverse, and so are 3 and 5. 1 and 6 are their own inverses, because 6 ≡ −1 and (−1) × (−1) = 1.
- **The inverse is unique modulo m.** If x and x′ both work, then x ≡ x × (a × x′) = (x × a) × x′ ≡ x′. So "the" inverse means the one in 0 to m − 1.
- **Modulo 1**, everything is 0, including 1, so 0 counts as an inverse. It's a harmless edge case, but tests like to include it.

## Dividing modulo m

To compute (x / y) mod m, multiply x by y⁻¹ instead. When y really does divide x, this gives the same remainder as the exact quotient, because y × (x / y) = x, and multiplying both sides by y⁻¹ gives x / y ≡ x × y⁻¹.

Two examples. The first is the division that broke in [Modular arithmetic](/dsa/learn/math-modular-arithmetic): (12 / 4) mod 5 should be 3. The second is the sum 1 + 2 + … + n = n(n + 1) / 2 for n = 10¹⁸, where n(n + 1) is about 10³⁶ and can't be computed at all, let alone halved.

```swift run
func extendedGCD(_ a: Int, _ b: Int) -> (g: Int, x: Int, y: Int) {
    var (oldR, r) = (a, b)
    var (oldS, s) = (1, 0)
    var (oldT, t) = (0, 1)
    while r != 0 {
        let q = oldR / r
        (oldR, r) = (r, oldR - q * r)
        (oldS, s) = (s, oldS - q * s)
        (oldT, t) = (t, oldT - q * t)
    }
    return (oldR, oldS, oldT)
}

func modInverse(_ a: Int, _ m: Int) -> Int? {
    let (g, x, _) = extendedGCD(((a % m) + m) % m, m)
    return g == 1 ? ((x % m) + m) % m : nil
}

let p = 1_000_000_007
// (12 / 4) mod 5, the example that broke in Modular arithmetic
print(12 % 5 * modInverse(4, 5)! % 5)

// 1 + 2 + … + n = n(n + 1) / 2, modulo p, for n = 10¹⁸
let n = 1_000_000_000_000_000_000
let half = modInverse(2, p)!
print(half)
print(n % p * ((n + 1) % p) % p * half % p)

// Check on a small n where the exact answer fits
let small = 1_000_000
print(small * (small + 1) / 2 % p, small % p * ((small + 1) % p) % p * half % p)
```

```output
3
500000004
1225
496500 496500
```

The inverse of 2 modulo 1,000,000,007 is 500,000,004, because 2 × 500,000,004 = 1,000,000,008 ≡ 1. It's worth recognising: if an answer you print is around 5 × 10⁸, it's often "something over 2". The 1225 looks suspicious but is right: 10⁹ ≡ −7, so 10¹⁸ ≡ 49 and 10¹⁸ + 1 ≡ 50, and 49 × 50 / 2 = 1225.

<Callout kind="warning" title="Modular division only means something when it's allowed">
x × y⁻¹ always produces *some* remainder, even when y doesn't divide x. Modulo 7, "1 / 2" is 4, because 2 × 4 ≡ 1. That's a perfectly good modular answer, and it's what a problem means when it asks for a fraction p / q "modulo 1,000,000,007". It just isn't the remainder of any whole number 1 / 2. And when y shares a factor with m, there's no inverse, so you can't divide by y at all.
</Callout>

## Solving a · x ≡ b (mod m)

An inverse solves a × x ≡ 1. The same machinery solves the general **linear congruence** a × x ≡ b (mod m): which x, from 0 to m − 1, makes a × x leave remainder b? On a circular track of m positions, it asks how many steps of length a take you from position 0 to position b.

Let g = gcd(a, m).

1. **Solvable only if g divides b.** a × x and m are both multiples of g, so a × x − b can be a multiple of m only if b is a multiple of g. For 6x ≡ 5 (mod 10), g = 2 doesn't divide 5: 6x is always even, and an even number is never 5 more than a multiple of 10.
2. **Divide everything by g.** For 6x ≡ 4 (mod 10), g = 2, which leaves 3x ≡ 2 (mod 5). Now 3 and 5 are coprime.
3. **Multiply by the inverse.** 3⁻¹ ≡ 2 (mod 5), so x ≡ 2 × 2 = 4 (mod 5).
4. **Lift back.** x ≡ 4 (mod 5) means x is 4 or 9 modulo 10: g solutions, spaced m / g apart. Check: 6 × 4 = 24 ≡ 4 and 6 × 9 = 54 ≡ 4.

The smallest solution is the one from step 3, which is already below m / g.

There's an overflow trap when m is large. Step 3 multiplies two numbers that can each be close to m / g. With m up to 10¹⁸ that product needs 120 bits, so use the full-width multiply from [Modular arithmetic](/dsa/learn/math-modular-arithmetic), `m.dividingFullWidth(a.multipliedFullWidth(by: b)).remainder`, rather than `a * b % m`, which traps.

<Callout kind="gotcha" title="Common mistakes">
- **Returning the raw x.** Extended Euclid's x is often negative. Normalise it with `((x % m) + m) % m` before using it as an inverse.
- **Assuming an inverse exists.** It exists only when gcd(a, m) = 1. Return an optional, or check, instead of using the result blindly.
- **Forgetting to reduce a first.** a can be negative or bigger than m. Reduce it into 0 to m − 1, then run extended Euclid.
- **Using `abs` on extreme values.** `abs(Int.min)` traps, because `Int.max` is one smaller in size. Inputs up to ±10¹⁸ are safe; the full 64-bit range isn't.
</Callout>
