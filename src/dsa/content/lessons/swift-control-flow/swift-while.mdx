## Why it matters

A `for-in` loop is perfect when you know what you're looping over. Sometimes you don't: keep halving until you reach 1, keep reading digits until none are left, keep retrying until a download succeeds. A `while` loop repeats *as long as a condition stays true*. Some of the most important algorithms you'll learn, like binary search, are `while` loops at heart.

## The while loop

A `while` loop checks its condition, runs its body if the condition is true, then checks again, over and over:

```swift run
var balance = 100
var years = 0

while balance < 200 {
    balance = balance * 110 / 100
    years += 1
}
print("After \(years) years the balance is \(balance)")
```

```output
After 8 years the balance is 212
```

The balance grows by 10% a year (with whole numbers, so any fraction is dropped). We don't know in advance how many years it takes to double; the loop finds out. Each time round:

1. Swift checks `balance < 200`.
2. If it's true, the body runs, and then it goes back to step 1.
3. If it's false, the loop ends and the program continues after the closing brace.

Because the condition is checked *first*, a `while` loop whose condition starts out false never runs its body at all.

## Something must change

The body of a `while` loop must eventually make the condition false. If nothing changes, the loop runs forever:

```swift
var count = 0
while count < 5 {
    print(count)
    // forgot: count += 1
}
```

This **infinite loop** prints `0` until you stop it. In Terminal, press Control-C to stop a program that's stuck.

Before you run a `while` loop, ask two questions:

1. What makes the condition false?
2. Does every pass move closer to that?

## Halving until there's nothing left

How many times can you halve 100 (dropping any remainder) before you reach 1?

```swift run
var n = 100
var steps = 0

while n > 1 {
    n /= 2
    steps += 1
}
print("Halved \(steps) times")
```

```output
Halved 6 times
```

100 → 50 → 25 → 12 → 6 → 3 → 1: six steps. Try a million and it takes only 19. Halving shrinks things incredibly fast, and that's the secret behind binary search and the **logarithm** you'll meet in Part II. Keep this little loop in mind.

## Taking a number apart, digit by digit

Integer division and remainder from M02 let a `while` loop peel the digits off a number from the right:

- `n % 10` is the last digit: `4721 % 10` is `1`.
- `n / 10` drops the last digit: `4721 / 10` is `472`.

Repeat until nothing is left:

```swift run
var n = 4721
var digitSum = 0

while n > 0 {
    let lastDigit = n % 10
    digitSum += lastDigit
    n /= 10
}
print("Digit sum: \(digitSum)")
```

```output
Digit sum: 14
```

| Pass | `n` before | `lastDigit` | `digitSum` after | `n` after |
| --- | --- | --- | --- | --- |
| 1 | 4721 | 1 | 1 | 472 |
| 2 | 472 | 2 | 3 | 47 |
| 3 | 47 | 7 | 10 | 4 |
| 4 | 4 | 4 | 14 | 0 |

A table like this, with a row per pass and a column per variable, is a **trace table**. It's the best way to understand or debug a loop, and you'll practise it properly in the last lesson of this module, *nested loops and trace tables*.

The same idea reverses a number, by building a new one digit by digit:

```swift run
var n = 1230
var reversed = 0

while n > 0 {
    reversed = reversed * 10 + n % 10
    n /= 10
}
print(reversed)
```

```output
321
```

The trailing zero of 1230 becomes a leading zero of `0321`, which as a number is just 321.

## repeat-while: at least once

A `repeat-while` loop checks its condition at the **end** instead of the start. So its body always runs at least once:

```swift run
var countdown = 0

while countdown > 0 {
    print("while:", countdown)
    countdown -= 1
}

repeat {
    print("repeat:", countdown)
    countdown -= 1
} while countdown > 0
```

```output
repeat: 0
```

`countdown` starts at 0, so the `while` loop's condition is false straight away and its body never runs. The `repeat` body runs once, *then* checks `countdown > 0`, which is false, and stops.

That "at least once" is exactly what you need when the first pass must happen before there's anything to check. Counting the digits of a number is the classic example: 0 has one digit, but `while n > 0` would never run for it. You'll use this in the practice problem.

Here's another: the famous **Collatz** sequence. Start with any positive number. If it's even, halve it; if it's odd, multiply by 3 and add 1. Repeat until you reach 1. Nobody has ever found a number that doesn't eventually get there, yet nobody has proved they all do.

```swift run
var n = 6
var path = "\(n)"

repeat {
    if n % 2 == 0 {
        n /= 2
    } else {
        n = 3 * n + 1
    }
    path += " → \(n)"
} while n != 1

print(path)
```

```output
6 → 3 → 10 → 5 → 16 → 8 → 4 → 2 → 1
```

## for-in or while?

| Use `for-in` when… | Use `while` when… |
| --- | --- |
| you know the range or collection | you stop when a condition changes |
| "for each item" | "until something happens" |
| the counter changes by a fixed step | the next value depends on the current one |

If you can write it as a `for-in` loop, do: the loop variable is managed for you, and it can't run forever. Reach for `while` when the number of passes depends on what happens inside the loop.

<Callout kind="gotcha" title="Swift gotcha: no C-style for loops">
Swift has no `for (i = 0; i < n; i++)` loop and no `++` operator. Use `for i in 0..<n` for counting, `stride` for other steps, and `while` with `i += 1` when you need full control over the counter.
</Callout>
