## Why it matters

Put one loop inside another and you can visit every cell of a grid, every pair of items in a list, or every row and column of a table. Nested loops power game boards, image filters and calendar views. In DSA, they're the first tool for comparing items with each other, and the first place where a solution can quietly become slow. They're also where bugs hide, so this lesson teaches the most useful debugging skill there is: tracing variables by hand.

## A loop inside a loop

When a loop sits inside another, the **inner loop runs all the way through for every single pass of the outer loop**:

```swift run
for row in 1...3 {
    for column in 1...2 {
        print("row \(row), column \(column)")
    }
}
```

```output
row 1, column 1
row 1, column 2
row 2, column 1
row 2, column 2
row 3, column 1
row 3, column 2
```

Think of a clock. The minute hand (the inner loop) goes all the way round for each step of the hour hand (the outer loop). The outer loop ran 3 times and the inner loop ran 2 times *per outer pass*, so the inner body ran 3 × 2 = 6 times.

<Callout kind="analogy" title="Reading a book">
The outer loop is the pages, and the inner loop is the lines on each page. You read every line of page 1 before you turn to page 2.
</Callout>

## Building rows of output

To print a grid, build each row as a string in the inner loop, then print it when the row is complete, in the outer loop:

```swift run
for row in 1...4 {
    var line = ""
    for _ in 1...row {
        line += "*"
    }
    print(line)
}
```

```output
*
**
***
****
```

Notice that the inner loop's range, `1...row`, depends on the outer loop's variable. Row 1 gets one star, row 4 gets four. Most patterns come from choosing how the inner range depends on the row.

You could also use `print("*", terminator: "")` inside the inner loop and a plain `print()` after it. Building a string first is usually easier to get right, and it's the shape you'll need for the practice problem, which returns the rows instead of printing them.

Counting the other way flips the triangle:

```swift run
for row in stride(from: 4, through: 1, by: -1) {
    var line = ""
    for column in 1...row {
        line += "\(column)"
    }
    print(line)
}
```

```output
1234
123
12
1
```

### Right-aligned shapes

To push a shape to the right, start each row with some padding. With `n` rows, row `r` needs `n - r` padding characters, then `r` stars. Here the padding is dots so you can see it:

```swift run
let n = 4
for row in 1...n {
    var line = ""
    for _ in 0..<(n - row) {
        line += "."
    }
    for _ in 1...row {
        line += "#"
    }
    print(line)
}
```

```output
...#
..##
.###
####
```

Two inner loops in a row, one after the other, both inside the outer loop. On the last row, `n - row` is 0, and `0..<0` is an empty range, so no padding is added. That's another reason half-open ranges are so handy.

## A multiplication table

A times table is a grid where each cell is `row × column`. The only extra work is lining the columns up. `String(repeating:count:)` makes a string of repeated characters, which is enough to pad each number to the same width:

```swift run
let size = 5

for row in 1...size {
    var line = ""
    for column in 1...size {
        let product = "\(row * column)"
        let padding = String(repeating: " ", count: 4 - product.count)
        line += padding + product
    }
    print(line)
}
```

```output
   1   2   3   4   5
   2   4   6   8  10
   3   6   9  12  15
   4   8  12  16  20
   5  10  15  20  25
```

Every cell is 4 characters wide: a two-digit product gets 2 spaces in front, a one-digit product gets 3. The columns line up because every cell has the same width.

## Comparing every pair

Many problems ask about **pairs** of items: is there a pair that adds up to a target? Which two points are closest? The direct approach compares each item with every item after it:

```swift run
let prices = [2, 7, 4, 5, 3]
let budget = 9
var pairs = 0

for i in 0..<prices.count {
    for j in (i + 1)..<prices.count {
        if prices[i] + prices[j] == budget {
            print("\(prices[i]) + \(prices[j])")
            pairs += 1
        }
    }
}
print("Pairs that cost exactly \(budget): \(pairs)")
```

```output
2 + 7
4 + 5
Pairs that cost exactly 9: 2
```

Starting the inner loop at `i + 1` does two jobs: it never pairs an item with itself, and it never counts the same pair twice (2 + 7 and 7 + 2). On the last pass, `i + 1` equals `prices.count`, so the inner range is empty and does nothing.

### How much work is that?

For 5 prices, the inner body runs 4 + 3 + 2 + 1 = 10 times. For `n` items it runs about n² / 2 times. That's fine for 5 items, and for 1,000 items (half a million checks). For 100,000 items it's five *billion*, far too slow.

| Loops | Inner body runs | Grows like |
| --- | --- | --- |
| one loop over n | n times | n |
| two nested loops over n | n × n times | n² |
| inner loop from `i + 1` | n × (n − 1) / 2 times | n² |

This is your first taste of **time complexity**. A pair of nested loops over the same data usually means O(n²), which you'll learn to spot, and often beat, in Part II. Later in the course you'll solve this exact pairs problem in a single pass.

## Trace tables

A **trace table** follows a program step by step on paper. Each column is a variable, and you write a new row every time something changes. It's slow, and it's the single most reliable way to understand what a loop really does, as opposed to what you *meant* it to do.

Here's a small nested loop. Before reading on, try to predict what it prints:

```swift
var total = 0
for i in 1...3 {
    for j in 1...i {
        total += j
    }
}
print(total)
```

Trace it, one row per pass of the inner body:

| Step | `i` | `j` | `total` after |
| --- | --- | --- | --- |
| 1 | 1 | 1 | 1 |
| 2 | 2 | 1 | 2 |
| 3 | 2 | 2 | 4 |
| 4 | 3 | 1 | 5 |
| 5 | 3 | 2 | 7 |
| 6 | 3 | 3 | 10 |

So it prints `10`. The table also shows things a quick read can miss: the inner loop runs once, then twice, then three times, because its range depends on `i`.

### Letting the program write the table

When a loop misbehaves, you can make the computer produce the trace table for you. Add a `print` that shows every variable you care about, at the point where they change:

```swift run
var total = 0
for i in 1...3 {
    for j in 1...i {
        total += j
        print("i = \(i), j = \(j), total = \(total)")
    }
}
```

```output
i = 1, j = 1, total = 1
i = 2, j = 1, total = 2
i = 2, j = 2, total = 4
i = 3, j = 1, total = 5
i = 3, j = 2, total = 7
i = 3, j = 3, total = 10
```

Compare the printed rows with the table you predicted. The first row that differs is where your understanding and the code part ways, and that's where the bug is. Delete the debugging `print`s once you've found it. In M12 you'll learn to do the same with a debugger, but tracing by hand never stops being useful, especially in interviews, where there's no computer to ask.

<Callout kind="tip" title="How to trace well">
Write the columns before you start: every variable the loop changes, plus the loop variables. Add a row each time the innermost body runs. Check the boundaries carefully: what happens on the first pass, the last pass, and when a range is empty?
</Callout>

## Common mistakes

<Callout kind="gotcha" title="Swift gotcha: using the wrong loop variable">
Inside the inner loop, it's easy to type `i` where you meant `j`. Both are valid `Int`s, so Swift can't warn you. Descriptive names like `row` and `column` make this mistake much harder to make.
</Callout>

- **Resetting in the wrong place.** In the star pattern, `var line = ""` sits *inside* the outer loop, so each row starts empty. Move it above the outer loop and every row would include all the stars before it.
- **Off-by-one inner ranges.** `0..<row` and `1...row` both run `row` times, but `0...row` runs `row + 1` times. When a pattern has one character too many, check the inner range first.
- **Forgetting the cost.** Two nested loops over a big input can be far too slow. Always ask how many times the innermost line runs.
