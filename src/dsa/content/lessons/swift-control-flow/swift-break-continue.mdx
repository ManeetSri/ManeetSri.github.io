## Why it matters

Loops don't always need to run to the end. Once a search finds what it's looking for, carrying on wastes time. Some items should be skipped entirely. `break` and `continue` give you that control, and labelled statements extend it to loops inside loops. In DSA, stopping a search early is often the difference between a fast solution and a slow one.

## break: stop the loop now

`break` ends the loop immediately. The program carries on after the loop's closing brace:

```swift run
let numbers = [4, 9, 15, 22, 31, 40]
var firstOver20 = -1

for n in numbers {
    if n > 20 {
        firstOver20 = n
        break
    }
    print("Checked \(n)")
}
print("First number over 20: \(firstOver20)")
```

```output
Checked 4
Checked 9
Checked 15
First number over 20: 22
```

Once 22 is found, there's no point looking at 31 or 40. Without `break`, the loop would also overwrite `firstOver20` with 31, then 40, and give the wrong answer.

Using `-1` to mean "not found" works here because every number is positive, but it's fragile. In M04 you'll meet optionals, Swift's proper way to say "there might be no answer".

### Searching with a flag

A common shape is a `Bool` **flag** that starts `false` and is set to `true` when the search succeeds:

```swift run
let guests = ["Ana", "Ben", "Cleo", "Dev"]
let lookingFor = "Cleo"
var found = false
var checks = 0

for guest in guests {
    checks += 1
    if guest == lookingFor {
        found = true
        break
    }
}
print(found ? "\(lookingFor) is on the list" : "\(lookingFor) isn't invited")
print("Checks needed: \(checks)")
```

```output
Cleo is on the list
Checks needed: 3
```

This is a **linear search**. In the worst case, when the guest isn't there, it checks every element. With `break`, it stops as soon as it can.

## continue: skip to the next pass

`continue` skips the rest of the current pass and jumps straight to the next one. The loop itself keeps going:

```swift run
let readings = [12, -1, 8, -1, 15]
var total = 0
var valid = 0

for reading in readings {
    if reading < 0 {
        continue // -1 means the sensor failed: skip it
    }
    total += reading
    valid += 1
}
print("Average of \(valid) readings: \(total / valid)")
```

```output
Average of 3 readings: 11
```

The `-1` readings never reach `total += reading`. The average is 35 / 3, which is 11 in integer division.

`continue` is handy when you want to deal with the unusual cases at the top of the loop and keep the main work unindented below them.

### for-in with where

When the condition only decides which items to visit, a `where` clause on the loop says it more directly:

```swift run
var total = 0
for n in 1...20 where n % 3 == 0 {
    total += n
}
print(total)
```

```output
63
```

The body only runs for 3, 6, 9, 12, 15 and 18, which add up to 63. It means the same as an `if n % 3 != 0 { continue }` at the top of the loop.

## break and continue in while loops

Both work in `while` and `repeat-while` loops too. A common pattern is a loop whose condition is always true, with a `break` deciding when to stop:

```swift run
var n = 27
var steps = 0

while true {
    if n == 1 {
        break
    }
    n = n % 2 == 0 ? n / 2 : 3 * n + 1
    steps += 1
}
print("27 reaches 1 after \(steps) steps")
```

```output
27 reaches 1 after 111 steps
```

That's the Collatz sequence from the last lesson, and 27 takes a surprisingly long road. Use `while true` sparingly: when the stopping condition fits naturally in the `while` line, put it there, so a reader can see at a glance when the loop ends.

<Callout kind="warning" title="continue in a while loop">
In a `while` loop, `continue` jumps straight back to the condition. If the code that moves the loop forward (like `i += 1`) comes after the `continue`, it's skipped, and the loop can run forever. Update the counter before you `continue`, or use a `for-in` loop.
</Callout>

## Loops inside loops: labelled statements

A `break` only exits the **innermost** loop it's in. When one loop sits inside another, that's often not what you want. Here we look for the first pair of numbers, one from each list, that adds up to 10:

```swift run
let first = [1, 4, 6, 8]
let second = [2, 5, 6]

for a in first {
    for b in second {
        if a + b == 10 {
            print("Found \(a) + \(b)")
            break
        }
    }
}
```

```output
Found 4 + 6
Found 8 + 2
```

We wanted only the first pair, but got two. The `break` after `4 + 6` ended the *inner* loop only. The outer loop carried on with `a = 6` (no match) and `a = 8`, where it found `8 + 2`.

To stop **everything** after the first match, give the outer loop a **label** and break out of it by name:

```swift run
let first = [1, 4, 6, 8]
let second = [2, 5, 6]

search: for a in first {
    for b in second {
        if a + b == 10 {
            print("Found \(a) + \(b)")
            break search
        }
    }
}
print("Search finished")
```

```output
Found 4 + 6
Search finished
```

Now the search stops at the first match. The label is any name followed by a colon, written before the loop: `search:`. Then `break search` ends that loop, from however deep inside it you are.

`continue` takes a label too. `continue rows` abandons the current pass of the inner loop *and* the rest of the outer pass, and moves to the outer loop's next item:

```swift run
let grid = [
    [3, 7, 2],
    [5, -1, 9],
    [8, 4, 6],
]

rows: for row in 0..<grid.count {
    var rowTotal = 0
    for value in grid[row] {
        if value < 0 {
            print("Row \(row) has a bad value, skipping it")
            continue rows
        }
        rowTotal += value
    }
    print("Row \(row) total: \(rowTotal)")
}
```

```output
Row 0 total: 12
Row 1 has a bad value, skipping it
Row 2 total: 18
```

`grid` is an array of arrays, a table with rows and columns. You'll study these in M07.

## break inside a switch

Inside a `switch`, `break` ends the *switch*, not the loop around it. That catches people out:

```swift run
let commands = ["go", "go", "stop", "go"]
var moves = 0

loop: for command in commands {
    switch command {
    case "go":
        moves += 1
    case "stop":
        break loop
    default:
        break
    }
}
print("Moves before stopping: \(moves)")
```

```output
Moves before stopping: 2
```

A plain `break` in the `"stop"` case would only end the switch, and the loop would carry on to the last `"go"`, giving 3. The label makes it leave the loop.

<Callout kind="gotcha" title="Swift gotcha: break in a switch">
In a `switch` that's inside a loop, a plain `break` exits only the switch. To leave the loop from inside a case, label the loop and write `break label`.
</Callout>
