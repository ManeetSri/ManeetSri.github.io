## Why it matters

Every useful program makes decisions. An app shows the sign-in screen if nobody is signed in, and a red badge if there are unread messages. Algorithms are built from the same small decisions: "is this number bigger than the best so far?" is an `if`. This lesson teaches you to write them clearly and in the right order.

## Your first if

An `if` statement runs a block of code only when a condition is true:

```swift run
let temperature = 31

if temperature > 30 {
    print("It's hot. Drink some water.")
}
print("Done checking.")
```

```output
It's hot. Drink some water.
Done checking.
```

Read it as a sentence: *if the temperature is greater than 30, print the warning*. It has three parts:

1. the keyword `if`;
2. a **condition**, an expression that is either `true` or `false` (a `Bool`, from M02);
3. a block of code in braces, `{` and `}`, that runs only when the condition is true.

The last `print` is outside the braces, so it always runs. Change `temperature` to `20` and only `Done checking.` appears.

Notice what Swift doesn't need: there are no parentheses around the condition. You *can* write `if (temperature > 30)`, but Swift style leaves them out.

## else: the other path

Often you want one thing to happen when the condition is true and something else when it's false. That's what `else` is for:

```swift run
let age = 15

if age >= 18 {
    print("You can vote.")
} else {
    print("Not yet. \(18 - age) years to go.")
}
```

```output
Not yet. 3 years to go.
```

Exactly one of the two blocks runs, never both and never neither.

## else if: more than two paths

When there are several possibilities, chain them with `else if`. Swift checks the conditions **from top to bottom** and runs the first block whose condition is true. Once one block has run, the rest are skipped.

```swift run
let battery = 42

if battery >= 80 {
    print("Full enough")
} else if battery >= 20 {
    print("Fine for today")
} else if battery > 0 {
    print("Charge soon")
} else {
    print("Flat")
}
```

```output
Fine for today
```

`42 >= 80` is false, so Swift moves on. `42 >= 20` is true, so it prints `Fine for today` and skips everything below, including `battery > 0`, which was also true.

The final `else` is optional. Without it, a chain where no condition matches simply does nothing.

### Order matters

Because the first match wins, the order of your conditions changes the result. Here's a bug that's easy to write:

```swift run
let score = 95

if score >= 50 {
    print("Pass")
} else if score >= 90 {
    print("Distinction")
}
```

```output
Pass
```

A score of 95 deserves a distinction, but `score >= 50` is checked first, matches, and the second branch never gets a chance. The fix is to put the **strictest** condition first:

```swift run
let score = 95

if score >= 90 {
    print("Distinction")
} else if score >= 50 {
    print("Pass")
} else {
    print("Try again")
}
```

```output
Distinction
```

<Callout kind="tip">
When your conditions are ranges of the same number, order them from the most specific to the least, or from highest to lowest. Then each `else if` can rely on the earlier ones having failed: the second branch above already knows `score` is below 90.
</Callout>

## Combining conditions

The logical operators from M02 let one `if` check several things at once. `&&` means "and", `||` means "or" and `!` means "not".

```swift run
let isWeekend = true
let isRaining = false

if isWeekend && !isRaining {
    print("Go to the park")
}
if !isWeekend || isRaining {
    print("Stay in")
}
```

```output
Go to the park
```

You could also put one `if` inside another, called **nesting**. These two are the same:

```swift
if isWeekend {
    if !isRaining {
        print("Go to the park")
    }
}

if isWeekend && !isRaining {
    print("Go to the park")
}
```

Prefer the flat version when it reads naturally. Every level of nesting is one more thing to keep in your head.

Divisibility checks are a common use of combined conditions. A number is divisible by `d` when the remainder, `n % d`, is zero:

```swift run
let n = 21

if n % 3 == 0 && n % 7 == 0 {
    print("\(n) is divisible by both 3 and 7")
} else if n % 3 == 0 || n % 7 == 0 {
    print("\(n) is divisible by one of them")
} else {
    print("\(n) is divisible by neither")
}
```

```output
21 is divisible by both 3 and 7
```

The "both" case comes first. If the "either" case came first, it would also match 21 and hide the more specific answer: the same ordering lesson as before.

## Conditions must be Bool

In some languages, `if count` means "if count isn't zero". Swift refuses this. A condition must be a real `Bool`:

```swift
let count = 3
if count {          // error
    print("Not empty")
}
```

```text title="What you'll see"
error: type 'Int' cannot be used as a boolean; test for '!= 0' instead
```

Write what you mean: `if count != 0`. It's one of many places where Swift makes you say exactly what you mean, so the reader never has to guess.

<Callout kind="gotcha" title="Swift gotcha: braces are never optional">
In C or JavaScript you can leave out the braces when the body is one line. Swift always requires them, even for a single statement. That rules out a whole family of bugs where a second line looks like it's inside an `if` but isn't.
</Callout>

## Choosing a value with if

A very common job for `if` is to pick a value. You can declare a constant without a value first, and give it one in each branch:

```swift run
let hour = 14
let greeting: String

if hour < 12 {
    greeting = "Good morning"
} else if hour < 18 {
    greeting = "Good afternoon"
} else {
    greeting = "Good evening"
}
print(greeting)
```

```output
Good afternoon
```

Swift checks that **every** path gives `greeting` exactly one value before it's used. If you forget the final `else`, it won't compile, because `greeting` might never be set.

Since Swift 5.9 you can also use `if` as an **expression** that produces a value directly. Each branch must be a single value, and the `else` is required:

```swift run
let stock = 0
let label = if stock == 0 { "Sold out" } else { "In stock" }
print(label)
```

```output
Sold out
```

For two choices this does the same job as the ternary operator from M02, `stock == 0 ? "Sold out" : "In stock"`. Use whichever reads more clearly. With three or more branches, the `if` expression is usually easier to read than nested ternaries.

## Where decisions show up in DSA

You've already seen one: the `if number > best` inside `largest(in:)` in [the problem-solving framework](/dsa/learn/start-problem-solving). Almost every algorithm you'll write has decisions like these at its heart:

- **Edge cases first:** if the input is empty, return straight away.
- **Comparisons:** if this element is smaller than the current minimum, remember it.
- **Rules:** if a year is divisible by 4 but not by 100, or it's divisible by 400, it's a leap year.

Getting the order of the checks right, and covering every case, is most of the work.
