## Why it matters

When one value can lead to many different outcomes, a long `if` / `else if` chain gets hard to read. A `switch` lists every outcome side by side, and Swift checks that you haven't forgotten any. In iOS code you'll switch on which tab was tapped or what state a download is in. In DSA you'll switch on characters while parsing, on directions while walking a grid, and on ranges of values while classifying them.

## A first switch

A `switch` compares one value against a list of **cases**, and runs the first case that matches:

```swift run
let day = 3

switch day {
case 1:
    print("Monday")
case 2:
    print("Tuesday")
case 3:
    print("Wednesday")
default:
    print("Some other day")
}
```

```output
Wednesday
```

The value after `switch` is what's being examined. Each `case` gives a pattern to compare it with, followed by a colon and the code to run. `default` matches anything the cases above it didn't.

## Every possibility must be covered

A Swift `switch` must be **exhaustive**: whatever the value is, some case has to match. An `Int` could be any of billions of numbers, so a switch on an `Int` almost always needs a `default`. Leave it out and the code won't compile:

```swift
let day = 3
switch day {
case 1:
    print("Monday")
}
```

```text title="What you'll see"
error: switch must be exhaustive
```

This is a feature. When every value has to go somewhere, you can't accidentally forget the "anything else" case.

For a `Bool`, there are only two possible values, so `true` and `false` cover everything and no `default` is needed:

```swift run
let isMember = true

switch isMember {
case true:
    print("Welcome back")
case false:
    print("Sign up for free")
}
```

```output
Welcome back
```

You'll see the same idea with enums in M09: list every case and the compiler knows you've covered them all.

## No falling through

In C, Java and JavaScript, a case keeps running into the next one unless you write `break`. Forgetting `break` is a classic bug. Swift turns that around: **a case stops at its end**. Only one case ever runs, and you never need `break` to stop it.

The flip side: every case must contain at least one statement. If a case should do nothing, write `break` to say so on purpose:

```swift run
let code = 0

switch code {
case 0:
    break // nothing to report
case 1:
    print("Warning")
default:
    print("Error \(code)")
}
print("Finished")
```

```output
Finished
```

## Several patterns in one case

Because cases don't fall through, you can't stack empty cases on top of each other as C does. Instead, list several patterns in **one** case, separated by commas. The case matches if any of them does:

```swift run
let letter: Character = "e"

switch letter {
case "a", "e", "i", "o", "u":
    print("\(letter) is a vowel")
case "y":
    print("\(letter) is sometimes a vowel")
default:
    print("\(letter) is a consonant")
}
```

```output
e is a vowel
```

Switches work on any value Swift can compare: `Int`, `Character`, `String`, `Bool`, `Double` and more.

## Matching ranges

A case can be a range from M02. This is where `switch` really beats a chain of `if`s:

```swift run
let distance = 7

switch distance {
case 0:
    print("You're here")
case 1...5:
    print("A short walk")
case 6...20:
    print("Take a bike")
default:
    print("Take the train")
}
```

```output
Take a bike
```

`1...5` matches 1, 2, 3, 4 and 5. Swift checks cases from top to bottom, so if ranges overlapped, the first matching case would win, exactly as with `else if`.

**One-sided ranges** handle "everything below" or "everything from here up". `..<0` means any number below zero, and `100...` means 100 or more:

```swift run
let temperature = -4

switch temperature {
case ..<0:
    print("Freezing")
case 0..<15:
    print("Cold")
case 15..<25:
    print("Mild")
case 25...:
    print("Hot")
default:
    print("Unreachable")
}
```

```output
Freezing
```

Those four ranges cover every `Int`, but the compiler can't work that out for ranges, so a `default` is still required. Here it can never run.

## Matching tuples

A tuple from M02 groups values together, and you can switch on a tuple to match several values at once. Use `_`, the **wildcard**, for "any value here":

```swift run
let point = (0, 5)

switch point {
case (0, 0):
    print("At the origin")
case (_, 0):
    print("On the x-axis")
case (0, _):
    print("On the y-axis")
case (-2...2, -2...2):
    print("Close to the origin")
default:
    print("Somewhere else")
}
```

```output
On the y-axis
```

`(_, 0)` reads "any x, with y equal to 0". Each part of a tuple pattern can be a value, a range or a wildcard.

A tuple of `Bool`s is a neat way to replace nested `if`s. Since each `Bool` has only two values, Swift can see that these four cases cover everything, so no `default` is needed:

```swift run
let hasTicket = true
let hasID = false

switch (hasTicket, hasID) {
case (true, true):
    print("Board the plane")
case (true, false):
    print("Show some ID first")
case (false, true):
    print("Buy a ticket first")
case (false, false):
    print("Buy a ticket and bring ID")
}
```

```output
Show some ID first
```

## Binding values with let

Sometimes you want to *use* part of the value that matched. Writing `let name` in a pattern **binds** that part to a new constant you can use inside the case:

```swift run
let point = (3, 0)

switch point {
case (let x, 0):
    print("On the x-axis at x = \(x)")
case (0, let y):
    print("On the y-axis at y = \(y)")
case let (x, y):
    print("At (\(x), \(y))")
}
```

```output
On the x-axis at x = 3
```

`case (let x, 0)` matches any point whose y is 0 and captures its x. `case let (x, y)` binds both parts, so it matches *everything*: it acts as the default, and Swift accepts the switch as exhaustive without one.

## Adding conditions with where

A `where` clause adds an extra condition to a case. The case only matches if the pattern matches **and** the condition is true:

```swift run
let point = (4, -4)

switch point {
case let (x, y) where x == y:
    print("On the line y = x")
case let (x, y) where x == -y:
    print("On the line y = -x")
case let (x, y):
    print("(\(x), \(y)) is on neither line")
}
```

```output
On the line y = -x
```

`where` works with single values too. Binding the whole value and testing it is a common way to sort numbers into groups:

```swift run
let numbers = [7, 12, -3, 0]

for n in numbers {
    switch n {
    case 0:
        print("\(n) is zero")
    case let x where x < 0:
        print("\(x) is negative")
    case let x where x % 2 == 0:
        print("\(x) is even")
    default:
        print("\(n) is odd")
    }
}
```

```output
7 is odd
12 is even
-3 is negative
0 is zero
```

The `for n in numbers` line runs the switch once for each number in the list. You'll meet these loops properly two lessons from now, in *for-in loops over ranges and collections*.

## switch as an expression

Like `if`, a `switch` can produce a value directly (since Swift 5.9). Each case must be a single value:

```swift run
let score = 68

let grade = switch score {
case 90...100: "A"
case 70..<90: "B"
case 50..<70: "C"
default: "F"
}
print(grade)
```

```output
C
```

This is handy whenever every case exists only to choose a value. If the cases need several statements, declare the constant first and assign it in each case, as you saw with `if`.

## fallthrough, rarely

If you really do want a case to continue into the next one, write `fallthrough` at the end of it. It runs the next case's code *without* checking its pattern:

```swift run
let n = 5
var description = "\(n) is"

switch n {
case 2, 3, 5, 7:
    description += " a prime number, and also"
    fallthrough
default:
    description += " an integer."
}
print(description)
```

```output
5 is a prime number, and also an integer.
```

You'll almost never need it. Listing several patterns in one case covers nearly every situation where other languages rely on falling through.

## Swift gotchas

<Callout kind="gotcha" title="Swift gotcha: no implicit fallthrough">
If you come from another language, don't write `break` at the end of every case: it's unnecessary. And don't stack empty cases expecting them to share code; Swift reports "'case' label in a 'switch' must have at least one executable statement". Write `case 1, 2, 3:` instead.
</Callout>

- **The first matching case wins.** Put specific cases (like `0`) before general ones (like `let x where x % 2 == 0`), just as with `else if`.
- **`default` must be able to catch the rest.** It usually goes last, because cases are tried from top to bottom.
- **Bindings live inside their case.** The `x` from `case let x where …` can't be used after the switch.

## if or switch?

| Use `if` when… | Use `switch` when… |
| --- | --- |
| there are one or two outcomes | there are three or more outcomes |
| conditions test different things | you're examining **one** value |
| a simple yes/no check | you want ranges, tuples or bindings |
