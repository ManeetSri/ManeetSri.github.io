## Why it matters

Ranges count up by one. Real loops often need something else: every second element, a countdown, or a walk from the end of an array back to the start. In DSA, walking backwards is everywhere: processing an array from the right, filling a table from the end, or moving a pointer towards the front. `stride` and `reversed()` are the two tools for it.

## stride(from:to:by:)

`stride(from:to:by:)` produces numbers starting at `from`, adding `by` each time, and stopping **before** it reaches `to`:

```swift run
for n in stride(from: 0, to: 10, by: 2) {
    print(n, terminator: " ")
}
print()
```

```output
0 2 4 6 8
```

`print(n, terminator: " ")` prints a space instead of a new line after each number, so they all land on one line. The final `print()` ends that line.

Think of `to:` as the half-open range `..<`: the end value is never included. Here 10 isn't printed, even though the count lands on it exactly.

## stride(from:through:by:)

`stride(from:through:by:)` is the closed version, like `...`. It **includes** the end value, if the count lands on it:

```swift run
for n in stride(from: 0, through: 10, by: 2) {
    print(n, terminator: " ")
}
print()

for n in stride(from: 0, through: 10, by: 3) {
    print(n, terminator: " ")
}
print()
```

```output
0 2 4 6 8 10
0 3 6 9
```

The second loop stops at 9: the next value, 12, would pass 10, and the count never lands exactly on 10. `through:` means "up to and including, if you hit it", not "always finish on this number".

| You write | You get | Like |
| --- | --- | --- |
| `stride(from: 1, to: 9, by: 3)` | 1, 4, 7 | `..<` |
| `stride(from: 1, through: 10, by: 3)` | 1, 4, 7, 10 | `...` |

<Callout kind="tip">
A memory hook: you walk *to* the door and stop before it; you walk *through* the door and end up on the other side.
</Callout>

## Counting backwards

Give `by:` a negative number and the stride counts down. Now `from:` is the bigger number:

```swift run
for n in stride(from: 10, through: 0, by: -2) {
    print(n, terminator: " ")
}
print()

for n in stride(from: 5, to: 0, by: -1) {
    print(n, terminator: " ")
}
print("Lift off")
```

```output
10 8 6 4 2 0
5 4 3 2 1 Lift off
```

The `to:` and `through:` rules are the same, just in the other direction: `to: 0` stops before 0, and `through: 0` includes it.

### reversed()

For the common case of counting down by one, you can also take a range and reverse it:

```swift run
for n in (1...5).reversed() {
    print(n, terminator: " ")
}
print()
```

```output
5 4 3 2 1
```

The parentheses matter: `(1...5).reversed()` reverses the range, while `1...5.reversed()` tries to reverse the number 5, which doesn't compile.

### A range can't count down

`for n in 5...1` looks like a countdown, but a range must go from small to large. It compiles, then crashes when it runs. This is what Swift reports:

```text title="What you'll see"
Fatal error: Range requires lowerBound <= upperBound
```

<Callout kind="gotcha" title="Swift gotcha: no backwards ranges">
To count down, use `(1...5).reversed()` or `stride(from: 5, through: 1, by: -1)`. Writing `5...1` is always a bug, even though it compiles.
</Callout>

## Walking an array backwards

To visit an array from its last element to its first, you need the indices `count - 1` down to `0`. Either tool works:

```swift run
let letters = ["a", "b", "c", "d"]

var backwards = ""
for i in stride(from: letters.count - 1, through: 0, by: -1) {
    backwards += letters[i]
}
print(backwards)

var everyOther = ""
for i in stride(from: 0, to: letters.count, by: 2) {
    everyOther += letters[i]
}
print(everyOther)

for i in letters.indices.reversed() {
    print(i, letters[i])
}
```

```output
dcba
ac
3 d
2 c
1 b
0 a
```

`letters.indices` is the range `0..<letters.count`, so `letters.indices.reversed()` is 3, 2, 1, 0. It reads clearly and can never produce an index that's out of bounds.

Both versions are also safe for an **empty** array. With no elements, `stride(from: -1, through: 0, by: -1)` produces nothing, because it starts *below* where it should finish, and `indices.reversed()` is empty too. Compare that with `(0...letters.count - 1).reversed()`, which would crash on an empty array, exactly as the closed range did in the last lesson.

## Strides with decimals

`stride` also works with `Double`, which a range can't step through:

```swift run
for x in stride(from: 0.0, through: 1.0, by: 0.25) {
    print(x, terminator: " ")
}
print()
```

```output
0.0 0.25 0.5 0.75 1.0
```

Steps like `0.25` are exact in binary, so this lands on `1.0` precisely. With steps like `0.1`, floating-point rounding (from M02) can make the last value miss the end. For anything that must be exact, loop over integers and divide.
