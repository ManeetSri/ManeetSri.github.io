## Why it matters

A loop repeats a block of code, and the `for-in` loop repeats it once for each item in a sequence. It's how an app draws every message in a chat, and how almost every algorithm in this course walks through its data: visit each element, look at it, decide something. If you can write a loop confidently, you can write a linear scan, the most common pattern in DSA.

## Looping over a range

The simplest loop runs once for each number in a range:

```swift run
for number in 1...5 {
    print("Counting: \(number)")
}
print("Lift off")
```

```output
Counting: 1
Counting: 2
Counting: 3
Counting: 4
Counting: 5
Lift off
```

Read it as "for each number in 1 through 5, run the block". Each time round the loop, called an **iteration** or a **pass**, `number` holds the next value from the range. When the range runs out, the program carries on after the closing brace.

Both kinds of range from M02 work:

- `1...5` is a **closed range**: 1, 2, 3, 4, 5.
- `0..<5` is a **half-open range**: 0, 1, 2, 3, 4. It stops *before* 5.

Half-open ranges are the natural fit for positions in a list, because the first position is 0, as you'll see in a moment.

`number` is a brand new constant on each pass. You can read it but not change it: writing `number += 1` inside the loop is an error, because it's a `let`.

## Building up a result

A loop on its own only repeats things. It becomes powerful when it **accumulates** a result in a variable declared before the loop:

```swift run
var total = 0
for n in 1...100 {
    total += n
}
print("1 + 2 + … + 100 = \(total)")
```

```output
1 + 2 + … + 100 = 5050
```

This shape, a variable before the loop and an update inside it, is called an **accumulator**. You'll use it to count things, find the biggest value, build strings and much more:

```swift run
var evenCount = 0
var squares = ""

for n in 1...6 {
    if n % 2 == 0 {
        evenCount += 1
    }
    squares += "\(n * n) "
}
print("Evens: \(evenCount)")
print("Squares: \(squares)")
```

```output
Evens: 3
Squares: 1 4 9 16 25 36
```

## When you don't need the value: _

Sometimes you only want to repeat something a number of times and never use the counter. Write `_` instead of a name, and Swift won't make you invent one:

```swift run
var line = ""
for _ in 1...3 {
    line += "Hip hip hooray! "
}
print(line)
```

```output
Hip hip hooray! Hip hip hooray! Hip hip hooray!
```

If you name the variable and never use it, Swift warns you and suggests `_`.

## Looping over an array

An **array** is an ordered list of values in square brackets, like `[3, 9, 4]` or `["Ana", "Ben"]`. You'll study arrays in depth in M07, but looping over one is easy: the loop variable takes each element in turn, in order.

```swift run
let fruits = ["apple", "banana", "cherry"]

for fruit in fruits {
    print("I like \(fruit)")
}
```

```output
I like apple
I like banana
I like cherry
```

A good habit: name the array as a plural and the loop variable as the singular, `for fruit in fruits`. The line then reads like English.

### Looping over positions

Each element has a position called its **index**, starting at 0. `fruits[0]` is `"apple"` and `fruits.count` is the number of elements, 3. When you need the position as well as the value, loop over the indices with a half-open range:

```swift run
let temperatures = [18, 21, 17, 24]

for i in 0..<temperatures.count {
    print("Day \(i + 1): \(temperatures[i])°")
}
```

```output
Day 1: 18°
Day 2: 21°
Day 3: 17°
Day 4: 24°
```

`0..<temperatures.count` is `0..<4`: exactly the valid indices 0, 1, 2 and 3. That's why half-open ranges and arrays go so well together.

When you want both the index and the value, `enumerated()` gives you pairs. You'll meet it properly in M06; here's a preview:

```swift run
let podium = ["Ana", "Ben", "Cleo"]

for (index, name) in podium.enumerated() {
    print("\(index + 1). \(name)")
}
```

```output
1. Ana
2. Ben
3. Cleo
```

<Callout kind="gotcha" title="Swift gotcha: closed ranges and empty arrays">
`for i in 0...array.count - 1` looks fine until the array is empty. Then the range is `0...-1`, and Swift crashes with `Range requires lowerBound <= upperBound`. `0..<array.count` becomes `0..<0`, which is simply empty, so the loop runs zero times. Prefer the half-open range, or `array.indices`, which means the same thing.
</Callout>

## Looping over a string

A string is a sequence of characters, so a `for-in` loop visits each one:

```swift run
var vowels = 0
for character in "programming" {
    if "aeiou".contains(character) {
        vowels += 1
    }
}
print("Vowels: \(vowels)")
```

```output
Vowels: 3
```

Strings have some surprises in Swift, which M08 covers. Looping over their characters like this is always safe.

## Looping over a dictionary

A **dictionary** stores values under keys, like a phone book that maps names to numbers. It's written with colons, `["Ana": 92, "Ben": 78]`, and M07 covers it in depth. Looping over a dictionary gives you each entry as a `(key, value)` pair, which you can split into two names:

```swift
let scores = ["Ana": 92, "Ben": 78, "Cleo": 85]

for (name, score) in scores {
    print("\(name) scored \(score)")
}
```

This works, but there's a catch: **a dictionary has no order**. The entries can come out in a different order each time you run the program. That's fine for adding up totals, but confusing when printing, and it makes output impossible to test. To get a stable order, sort the entries by key first:

```swift run
let scores = ["Ana": 92, "Ben": 78, "Cleo": 85]

for (name, score) in scores.sorted(by: <) {
    print("\(name) scored \(score)")
}

var total = 0
for (_, score) in scores {
    total += score
}
print("Total: \(total)")
```

```output
Ana scored 92
Ben scored 78
Cleo scored 85
Total: 255
```

`scores.sorted(by: <)` returns the entries as an array, in increasing order of key. The total doesn't depend on order, so that loop can use the dictionary directly, with `_` for the name it doesn't need.

<Callout kind="warning" title="Never rely on dictionary order">
Code that happens to print a dictionary in the order you typed it may print it differently tomorrow. Whenever order matters, sort the keys or entries first.
</Callout>

## Loops are how algorithms walk data

Here's the `largest(in:)` idea from [the problem-solving framework](/dsa/learn/start-problem-solving) written with what you now know. One loop, one accumulator, one decision:

```swift run
let readings = [12, 47, 8, 47, 30]
var largest = readings[0]
var position = 0

for i in 0..<readings.count {
    if readings[i] > largest {
        largest = readings[i]
        position = i
    }
}
print("Largest is \(largest), first seen at index \(position)")
```

```output
Largest is 47, first seen at index 1
```

Notice the `>`: the second 47 is not *greater* than the first, so `position` stays at 1. Changing it to `>=` would report the last 47 instead. Small details like this decide whether an answer is right.

Every element is visited once, so the work grows in step with the length of the array. That's the **linear scan**, and you'll write hundreds of them.
