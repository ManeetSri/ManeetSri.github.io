## Why it matters

`Bool` is the type behind every decision a program makes: whether a user is logged in, whether a number is even, whether a search has found its target. `Character` and `String` hold text, and text problems are a huge part of DSA: palindromes, anagrams, counting letters. Swift's strings work differently from most languages, so this lesson gives you the basics now, and M08 goes deep.

## Bool: true or false

A `Bool` has exactly two possible values, `true` and `false`. The name honours George Boole, who worked out the algebra of true and false in the 1800s.

```swift run
let isLoggedIn = true
let hasUnreadMessages = false
print(isLoggedIn, hasUnreadMessages)
```

```output
true false
```

You'll rarely type `true` or `false` directly. Most booleans come from **comparisons**, which ask a question and answer with a `Bool`:

```swift run
let age = 20
let isAdult = age >= 18
let isTeenager = age >= 13 && age <= 19
print(isAdult)
print(isTeenager)
```

```output
true
false
```

`>=` means "greater than or equal to" and `&&` means "and". You'll learn the full set in *Comparison and logical operators*, later in this module. In M03, booleans decide which code runs with `if`.

### Flipping a Bool

`!` in front of a `Bool` gives the opposite value: `!true` is `false`. A `var` Bool can also flip itself with `toggle()`:

```swift run
var isPlaying = false
isPlaying.toggle()
print(isPlaying)
print(!isPlaying)
```

```output
true
false
```

`toggle()` is a **method**: a function that belongs to a value, called with a dot after it. You'll meet many methods in this lesson.

### Booleans as flags

In algorithms, a `Bool` often works as a **flag**: a variable that starts one way and flips when something happens. "Have I found the target yet?" starts as `false` and becomes `true` the moment you find it:

```swift
var foundTarget = false
// ... look through the data; when you spot the target:
foundTarget = true
```

You'll write this pattern inside loops from M03 onwards. Name flags so they read as a yes-or-no question, like `foundTarget`, `isSorted` or `hasDuplicate`, as you learnt in [Naming things well](/dsa/learn/swift-naming).

## Character: a single character

A `Character` holds exactly one character: a letter, a digit, a symbol, a space or even an emoji. A literal in double quotes is a `String` by default, so you **must annotate** a `Character`:

```swift run
let grade: Character = "A"
let digit: Character = "7"
print(grade, digit)
print(type(of: grade))
```

```output
A 7
Character
```

Without `: Character`, Swift would infer `String`, even for a single letter. `"7"` is a character that looks like a digit, not the number 7. Turning one into the other is a conversion you'll learn in M08.

## String: text

A `String` is a sequence of characters. Here are the operations you'll use most:

```swift run
let word = "Swift"
print(word.count)
print(word.isEmpty)
print(word.uppercased())
print(word.lowercased())
print(word.hasPrefix("Sw"))
print(word.hasSuffix("ift"))
print(word.contains("if"))
```

```output
5
false
SWIFT
swift
true
true
true
```

| Operation | Gives you |
| --- | --- |
| `s.count` | the number of characters, an `Int` |
| `s.isEmpty` | `true` if there are no characters |
| `s.uppercased()`, `s.lowercased()` | a new string in capitals or small letters |
| `s.hasPrefix(p)`, `s.hasSuffix(p)` | whether `s` starts or ends with `p` |
| `s.contains(p)` | whether `p` appears anywhere in `s` |

`count` and `isEmpty` are **properties**, read without parentheses. The others are methods, which need parentheses. `uppercased()` doesn't change `word`; it returns a *new* string, which is why `word` itself is still `"Swift"`.

<Callout kind="tip">
To check whether a string is empty, use `s.isEmpty` rather than `s.count == 0`. It reads better, and for strings it's faster, because `count` has to walk through every character to count them.
</Callout>

## Building strings

A `var` string can grow. Use `+` to join strings, `+=` to add to the end, and `append` to add a single character:

```swift run
var greeting = "Hello"
greeting += ", Maneet"
let exclamation: Character = "!"
greeting.append(exclamation)
print(greeting)
print(greeting == "Hello, Maneet!")
```

```output
Hello, Maneet!
true
```

`==` compares two strings character by character. It's case-sensitive, so `"swift" == "Swift"` is `false`. When case shouldn't matter, compare `a.lowercased() == b.lowercased()`.

A space is a character too, so `" ".isEmpty` is `false` and `" ".count` is 1. Text typed by a user often has spaces at the ends, which is why "empty" checks in apps usually trim them first. You'll learn trimming in M08.

## Strings are values

When you assign a string to another name, Swift gives the new name its **own copy**. Changing one doesn't change the other:

```swift run
let original = "Swift"
var copy = original
copy += "!"
print(original)
print(copy)
```

```output
Swift
Swift!
```

This is called **value semantics**, and `Int`, `Double`, `Bool` and `Character` behave the same way. It means a string you pass around can never be changed behind your back. Swift makes the copying cheap with a trick you'll study in M09. Arrays and dictionaries are values too, which you'll explore in M07.

## Why you can't write word[0]

In most languages you can grab the first character with `word[0]`. In Swift, that's a compile error:

```swift
let word = "Swift"
print(word[0])
```

```text title="What you'll see"
error: 'subscript(_:)' is unavailable: cannot subscript String with an Int, use a String.Index instead.
```

Swift strings fully support Unicode, where one visible character, like an emoji or an accented letter, can take a different amount of memory from the next. So Swift can't jump straight to "character number 5" without walking through the earlier ones, and it refuses to pretend otherwise.

For now, `word.first` and `word.last` give you the first and last characters. They come back as **optionals**, because an empty string has no first character. You'll learn optionals in M04 and the full story of string indexes in M08, along with the standard fix for algorithm problems: converting a string to an array of characters.

<Callout kind="gotcha" title="Swift gotcha: count isn't free">
For an array, `count` is instant. For a `String`, it walks the whole string, because characters can vary in size. Calling `s.count` inside a loop that runs once per character can make an algorithm much slower than it looks. M08 shows the patterns that avoid this.
</Callout>
