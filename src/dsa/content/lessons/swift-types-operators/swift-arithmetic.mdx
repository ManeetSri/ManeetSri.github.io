## Why it matters

Arithmetic looks like the easiest part of programming, but two operators, integer division `/` and remainder `%`, quietly power a huge number of algorithms. They pull the digits out of a number, find the middle of a list in binary search, wrap a position back to the start of a circular buffer, and test whether a number is even. They also have rules that differ from school maths, especially for negative numbers. Get them exactly right now and a whole family of problems becomes easy.

## The basic operators

| Operator | Meaning | Example | Result |
| --- | --- | --- | --- |
| `+` | add | `7 + 2` | `9` |
| `-` | subtract | `7 - 2` | `5` |
| `*` | multiply | `7 * 2` | `14` |
| `/` | divide | `7 / 2` | `3` |
| `%` | remainder | `7 % 2` | `1` |

Both sides of an operator must have the **same type**. `Int` with `Int` gives an `Int`; `Double` with `Double` gives a `Double`. Mixing them is a compile error, as you saw in [Converting between types](/dsa/learn/swift-type-conversion).

## Order of operations

Swift follows the same order as school maths: `*`, `/` and `%` happen before `+` and `-`. Operators of the same level work from **left to right**. Parentheses override everything.

```swift run
print(2 + 3 * 4)
print((2 + 3) * 4)
print(10 - 4 - 3)
print(20 / 4 / 5)
```

```output
14
20
3
1
```

`10 - 4 - 3` is `(10 - 4) - 3`, which is 3, not `10 - (4 - 3)`, which would be 9. When in doubt, add parentheses. They cost nothing and make your intent obvious to the next reader.

## Integer division drops the remainder

When both values are `Int`, `/` gives a whole-number answer and **throws away the remainder**. It doesn't round:

```swift run
print(7 / 2)
print(9 / 10)
print(-7 / 2)
print(7.0 / 2.0)
```

```output
3
0
-3
3.5
```

- `7 / 2` is 3.5 in maths, and Swift drops the `.5`, leaving 3.
- `9 / 10` is 0.9, which becomes 0.
- `-7 / 2` is -3.5, which becomes -3. Integer division **truncates towards zero**, just like `Int(-3.5)`.
- With `Double` values, `/` keeps the fraction.

This is often exactly what you want. "How many full boxes of 6 can I fill with 20 eggs?" is `20 / 6`, which is 3.

## The remainder operator %

`%` gives what's **left over** after integer division. `17 % 5` is 2, because 5 goes into 17 three times (15), with 2 left over.

Division and remainder always fit together like this:

```text
a == (a / b) * b + a % b
17 == (17 / 5) * 5 + 17 % 5  →  17 == 3 * 5 + 2
```

`%` is the most useful operator you might not have used before:

- **Even or odd:** `n % 2` is 0 for even numbers.
- **Every nth thing:** `day % 7 == 0` is true on every seventh day.
- **The last digit:** `n % 10` is the last digit of a non-negative number.
- **Wrapping around:** `(position + 1) % count` goes back to 0 after the last position.

Swift also offers `n.isMultiple(of: 2)`, which reads well and handles negative numbers correctly.

## Negative numbers and %

Here's where Swift differs from school maths, and from some other languages such as Python. In Swift, **the result of `%` takes the sign of the left-hand number** (the dividend):

```swift run
print(-7 % 3)
print(7 % -3)
print(-7 / 3)
```

```output
-1
1
-2
```

`-7 / 3` truncates -2.33… towards zero, giving -2. Then the identity forces the remainder: -7 = (-2 × 3) + (-1). So `-7 % 3` is -1, not 2 as you might expect from a clock.

That matters whenever you wrap around backwards, for example moving left from position 0. The fix is a standard formula that always gives a result from 0 up to `m - 1`:

```swift run
let position = -7
let count = 3
let wrapped = ((position % count) + count) % count
print(wrapped)
```

```output
2
```

`position % count` is -1. Adding `count` makes it 2. The final `% count` handles the case where the first remainder was already positive, so the formula works for every input.

<Callout kind="gotcha" title="Swift gotcha: checking for odd numbers">
`n % 2 == 1` looks like a test for odd numbers, but it's **false for negative odd numbers**, because `-3 % 2` is -1. Use `n % 2 != 0` or `!n.isMultiple(of: 2)` instead. This bug appears in real code surprisingly often.
</Callout>

## % only works on integers

`7.5 % 2` is a compile error in Swift: `'%' is unavailable: For floating point numbers use truncatingRemainder instead`. For doubles, write `(7.5).truncatingRemainder(dividingBy: 2)`, which gives `1.5`. You'll rarely need it in DSA.

## Updating a variable: compound assignment

Changing a variable by some amount is so common that Swift has shortcuts, called **compound assignment** operators:

```swift run
var score = 10
score += 5
score -= 3
score *= 2
print(score)
score /= 5
score %= 3
print(score)
```

```output
24
1
```

`score += 5` means exactly `score = score + 5`. There's one for each operator: `+=`, `-=`, `*=`, `/=` and `%=`.

Swift has **no** `++` or `--`. Writing `count++` gives `cannot find operator '++' in scope; did you mean '+= 1'?`. Use `count += 1`.

## DSA patterns built on / and %

### Taking a number apart, digit by digit

`n % 10` gives the last digit, and `n / 10` removes it. Repeat, and you visit every digit from right to left:

```swift run
let number = 472
print(number % 10)
let rest = number / 10
print(rest % 10)
print(rest / 10)
```

```output
2
7
4
```

With a loop (M03), this becomes the standard way to sum digits, reverse a number or check whether it's a palindrome, all without converting it to text.

### Finding the middle

Binary search, which you'll master in Part IV, repeatedly looks at the middle of a range of positions:

```swift
let low = 3
let high = 8
let mid = low + (high - low) / 2   // 5
```

Integer division gives a whole-number position automatically. The `low + (high - low) / 2` form, rather than `(low + high) / 2`, avoids adding two large numbers, which you'll understand after the next lesson, on overflow.

### Dividing and rounding up

How many pages do you need for 10 items, 3 per page? `10 / 3` is 3, which leaves an item over. The integer-only trick for rounding up is `(a + b - 1) / b`:

```swift run
let items = 10
let perPage = 3
print(items / perPage)
print((items + perPage - 1) / perPage)
```

```output
3
4
```

Adding `perPage - 1` before dividing pushes any partial page over into a full one, without touching `Double` at all.

## Division by zero crashes

Dividing an integer by zero has no answer, and Swift won't guess. If the zero is written directly in your code, it's a compile error, `division by zero`. If it only appears while the program runs, the program crashes:

```swift
let people = 0
let share = 12 / people
```

```text title="What you'll see"
Fatal error: Division by zero
```

The same goes for `%`. Whenever a divisor could be zero, such as the number of items in a list that might be empty, check it first. You'll learn how with `if` and `guard` in M03.
