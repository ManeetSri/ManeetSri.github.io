## Why it matters

Swift never converts one type to another behind your back. That's a safety feature, but it means you'll write conversions all the time: turning a count into a `Double` to compute an average, turning a `Double` back into an `Int` to use as a position, or turning text typed by a user into a number. Each conversion has rules about what happens to the fractional part or to text that isn't a number. Knowing them prevents a whole category of quiet bugs.

## Converting by creating a new value

Every conversion in Swift looks the same: write the type you want, and put the value in parentheses. `Double(5)` creates a new `Double` from the `Int` 5.

```swift run
let count = 7
let total = 23
let average = Double(total) / Double(count)
print(Double(count))
print(average)
```

```output
7.0
3.2857142857142856
```

This syntax is called an **initialiser**: it creates a new value of a type. The original value isn't changed; `count` is still the `Int` 7.

## Double to Int: the fraction is dropped

Going from `Double` to `Int` is where you need to be careful. `Int(...)` doesn't round. It **truncates**: it chops off the fractional part, moving towards zero.

```swift run
print(Int(3.9))
print(Int(3.1))
print(Int(-3.9))
```

```output
3
3
-3
```

`3.9` becomes `3`, not `4`. And `-3.9` becomes `-3`, because truncation moves towards zero, which for negative numbers means upwards.

## Rounding first

If you want proper rounding, round the `Double` *before* converting it. `.rounded()` rounds to the nearest whole number, with halves going away from zero, the way you learnt at school:

```swift run
print((2.4).rounded())
print((2.5).rounded())
print((-2.5).rounded())
print(Int((3.7).rounded()))
```

```output
2.0
3.0
-3.0
4
```

Notice that `.rounded()` still gives a `Double`, such as `3.0`. Wrap it in `Int(...)` when you need an `Int`.

You can choose other rounding rules by passing one to `rounded(_:)`:

| Rule | `2.5` becomes | `-2.5` becomes | Meaning |
| --- | --- | --- | --- |
| `.rounded()` | `3.0` | `-3.0` | nearest, halves away from zero |
| `.rounded(.down)` | `2.0` | `-3.0` | towards minus infinity |
| `.rounded(.up)` | `3.0` | `-2.0` | towards plus infinity |
| `.rounded(.towardZero)` | `2.0` | `-2.0` | chop off the fraction |
| `.rounded(.toNearestOrEven)` | `2.0` | `-2.0` | nearest, halves to the even neighbour |

`.rounded(.up)` is useful in DSA for "how many boxes do I need?" questions: 10 items in boxes of 3 need `(10.0 / 3.0).rounded(.up)`, which is `4.0`. You'll also learn an integer-only trick for this in the next lesson.

## Between integer types

You convert between integer types in the same way: `Int(someInt64)`, `Int8(someInt)`, `UInt8(someInt)`. As long as the value fits in the new type, it's exact:

```swift run
let small: Int8 = 100
let big = Int(small) + 1_000
let byte = UInt8(200)
print(big, byte)
```

```output
1100 200
```

But if the value **doesn't fit**, the program crashes:

```swift
let tooBig = 300
let byte = UInt8(tooBig)
```

```text title="What you'll see"
Fatal error: Not enough bits to represent the passed value
```

`UInt8` stops at 255. Swift would rather crash than quietly give you a wrong number. When you're not sure a value fits, `UInt8(clamping: 300)` caps it at the nearest limit, giving 255, and `UInt8(exactly: 300)` gives back "no value" instead of crashing. That "maybe a value" result is an optional, coming up in M04.

## Numbers to strings and back

Turning a number into text always works:

```swift run
let score = 42
let label = String(score)
print(label + " points")
print("\(score) points")
```

```output
42 points
42 points
```

`String(score)` and interpolation both work. Interpolation is usually neater.

Going the other way is different, because not every string is a number. `Int("42")` can succeed, but what should `Int("hello")` give? Swift's answer is that converting a `String` to a number gives an **optional**: either a number, or `nil`, meaning "no value".

```swift run
let typed = "42"
let notANumber = "hello"
print(Int(typed) == 42)
print(Int(notANumber) == nil)
print(Int("4.2") == nil)
```

```output
true
true
true
```

`"4.2"` isn't a valid `Int` either, though `Double("4.2")` would work. If you print `Int(typed)` directly, you'll see `Optional(42)`, along with a compiler warning that you probably meant to unwrap it first. Unwrapping is exactly what M04 is about. For now, remember that **text to number can fail**, so Swift makes you deal with the failure.

<Callout kind="gotcha" title="Swift gotcha: converting doubles that don't fit">
`Int(someDouble)` crashes if the `Double` is too large for an `Int`, or is infinity or NaN. Swift reports, for example, `Fatal error: Double value cannot be converted to Int because it is either infinite or NaN`. If a value might come from a division by zero or a huge calculation, check it before converting.
</Callout>

## Conversions at a glance

| From → to | How | What can go wrong |
| --- | --- | --- |
| `Int` → `Double` | `Double(n)` | nothing for everyday sizes; beyond about 9 × 10¹⁵, precision is lost |
| `Double` → `Int` | `Int(d)` | drops the fraction; crashes for infinity, NaN or huge values |
| `Int` → `Int8`, `UInt8`… | `Int8(n)` | crashes if the value doesn't fit |
| number → `String` | `String(n)` or `"\(n)"` | nothing |
| `String` → number | `Int(s)`, `Double(s)` | gives an optional: `nil` if the text isn't a number |

When you mix types in a calculation, convert **towards the type that keeps more information**. Turning an `Int` into a `Double` is safe; turning a `Double` into an `Int` throws the fraction away. So `Double(count) * price` is usually right, and `count * Int(price)` is usually a bug: a price of 2.99 would become 2.

## Choosing conversions in DSA

A few patterns come up constantly:

- **Averages:** convert *before* dividing, `Double(sum) / Double(count)`, so the fraction survives.
- **Positions from maths:** if a formula gives a `Double`, decide how to round it, then convert with `Int(...)`. Positions in a list must be `Int`.
- **Input as text:** problems that read input from text need `Int(line)`, which gives an optional. You'll handle that in M12.

  front: "How do you round 3.7 to the nearest `Int`?"
