## Why it matters

Every decision a program makes comes down to a question with a yes-or-no answer. Is the password long enough? Has the search found its target? Is this number bigger than the best one so far? Comparison operators ask those questions, and logical operators combine them. In DSA, conditions like `left < right` and `target > middleValue` steer almost every loop and every binary search you'll write.

## Comparison operators

A comparison asks a question about two values and answers with a `Bool`:

| Operator | Asks | Example | Result |
| --- | --- | --- | --- |
| `==` | equal to? | `3 == 3` | `true` |
| `!=` | not equal to? | `3 != 4` | `true` |
| `<` | less than? | `5 < 2` | `false` |
| `>` | greater than? | `5 > 2` | `true` |
| `<=` | less than or equal to? | `2 <= 2` | `true` |
| `>=` | greater than or equal to? | `1 >= 2` | `false` |

```swift run
let score = 72
let passMark = 50
print(score >= passMark)
print(score == 100)
print(score != passMark)
```

```output
true
false
true
```

Remember that `==` compares and `=` assigns, as you saw in [Constants and variables: let vs var](/dsa/learn/swift-let-var). Both sides of a comparison must have the same type, just like arithmetic.

### Comparing strings

Strings compare character by character, using each character's position in Unicode. For lowercase words, that's alphabetical order:

```swift run
print("apple" < "banana")
print("app" < "apple")
print("Zebra" < "apple")
print("10" < "9")
```

```output
true
true
true
true
```

The last two are traps. Every uppercase letter comes before every lowercase letter, so `"Zebra"` sorts before `"apple"`. And `"10" < "9"` is `true` because these are strings: the first characters are compared, and `"1"` comes before `"9"`. To compare numbers, convert them to numbers first.

## Logical operators: and, or, not

Logical operators combine `Bool` values into a new `Bool`:

- `a && b` (**and**) is `true` only when **both** are true.
- `a || b` (**or**) is `true` when **at least one** is true.
- `!a` (**not**) flips the value.

| `a` | `b` | a and b | a or b |
| --- | --- | --- | --- |
| `true` | `true` | `true` | `true` |
| `true` | `false` | `false` | `true` |
| `false` | `true` | `false` | `true` |
| `false` | `false` | `false` | `false` |

```swift run
let temperature = 31
let isRaining = false
let isHot = temperature > 30
print(isHot && !isRaining)
print(isHot || isRaining)
let age = 25
print(age >= 18 && age < 65)
```

```output
true
true
true
```

`age >= 18 && age < 65` is how you check that a value lies between two limits. You'll see this pattern constantly, often as `index >= 0 && index < count` to check that a position is valid.

## Short-circuit evaluation

Swift evaluates `&&` and `||` from left to right, and **stops as soon as it knows the answer**:

- For `a && b`, if `a` is `false`, the whole thing must be `false`, so `b` is never evaluated.
- For `a || b`, if `a` is `true`, the whole thing must be `true`, so `b` is never evaluated.

This is called **short-circuiting**, and it's more than a speed-up. It lets the left side protect the right side:

```swift run
let count = 0
let total = 50
let averageIsHigh = count != 0 && total / count > 10
print(averageIsHigh)
```

```output
false
```

`count != 0` is `false`, so Swift never runs `total / count`, and there's no division by zero. Swap the two sides, as in `total / count > 10 && count != 0`, and the division runs first and crashes with `Fatal error: Division by zero`. **Put the safety check first.**

In DSA you'll write guards like this all the time: `index < count && numbers[index] > 0` checks that a position exists before looking at what's there.

## Combining conditions clearly

When `&&` and `||` appear together, `&&` is applied first, the same way `*` comes before `+`. And `!` applies before both:

```swift run
print(true || false && false)
print((true || false) && false)
```

```output
true
false
```

The first line means `true || (false && false)`, which is `true`. The parentheses in the second line change the meaning completely. Don't make readers remember these rules: **use parentheses whenever you mix `&&` and `||`**. Long conditions also read better when you give the parts names:

```swift
let isWeekend = true
let hasHoliday = false
let isWorking = false
let canSleepIn = (isWeekend || hasHoliday) && !isWorking
```

## Simplifying conditions

Two habits keep conditions short and clear.

**Don't compare a `Bool` with `true` or `false`.** It's already a yes-or-no value:

```swift
let isReady = true
let canStart = isReady == true   // works, but says "is it true that it's true?"
let canStartNow = isReady        // the same value, clearer
let mustWait = !isReady          // instead of isReady == false
```

**Flip a whole condition with De Morgan's laws.** Putting `!` in front of a combined condition flips each part *and* swaps `&&` with `||`:

- `!(a && b)` is the same as `!a || !b`: "not both" means "at least one isn't".
- `!(a || b)` is the same as `!a && !b`: "neither" means "both aren't".

```swift run
let isWeekend = true
let isSunny = false
print(!(isWeekend && isSunny), !isWeekend || !isSunny)
print(!(isWeekend || isSunny), !isWeekend && !isSunny)
```

```output
true true
false false
```

Each line prints the same value twice, because the two forms always agree. These laws are handy when you need the opposite of a loop's condition, such as "keep going while not found and not at the end".

## min and max

Two built-in functions come up constantly alongside comparisons. `min` returns the smallest of its values and `max` the largest:

```swift run
print(min(3, 9))
print(max(3, 9))
print(min(4, 1, 8))
```

```output
3
9
1
```

Keeping a running best, such as "the largest number seen so far", is often written as `best = max(best, number)`. You'll use that in loops from M03 onwards.

<Callout kind="gotcha" title="Swift gotcha: no chained comparisons">
Maths lets you write 1 < x < 5. Swift doesn't:

```swift
let x = 3
print(1 < x < 5)
```

```text title="What you'll see"
error: adjacent operators are in non-associative precedence group 'ComparisonPrecedence'
```

Write `1 < x && x < 5`, or use a range as in `(2...4).contains(x)`. Ranges are in the next lesson, *The ternary operator and ranges*.
</Callout>
