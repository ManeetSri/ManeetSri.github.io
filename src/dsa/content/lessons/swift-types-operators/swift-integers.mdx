## Why it matters

Whole numbers are everywhere in algorithms: counts, positions in a list, sums, scores and IDs. Almost every problem you'll solve uses `Int`. Knowing exactly how big an `Int` can get tells you when a sum is safe and when it might overflow. Knowing why Swift has other integer types, and why you'll rarely need them, saves you from a lot of fiddly conversion code.

## Int: Swift's whole number

`Int` holds whole numbers, positive or negative, with no fractional part. A whole-number literal is inferred as an `Int`, as you saw in [Type inference and type annotations](/dsa/learn/swift-type-inference):

```swift run
let temperature = -3
let followers = 1_250_000
let year = 2026
print(temperature, followers, year)
```

```output
-3 1250000 2026
```

The underscores in `1_250_000` are only there to help you read the number. Swift ignores them, just as you'd write commas on paper. Use them for any number with more than four or five digits.

## How big can an Int be?

A computer stores numbers in **bits**, each one a 0 or a 1. On every modern iPhone, iPad and Mac, an `Int` uses 64 bits. That gives a huge but **limited** range, and Swift will tell you the limits:

```swift run
print(Int.min)
print(Int.max)
```

```output
-9223372036854775808
9223372036854775807
```

That's about ±9.2 × 10¹⁸, or nine quintillion. `Int.min` and `Int.max` are **properties** of the `Int` type: values that belong to the type itself, which you reach with a dot.

For DSA, the useful rule of thumb is that **an Int holds up to about 9 × 10¹⁸**. A typical problem says values go up to 10⁹ and there are up to 10⁵ of them. Their sum is at most 10¹⁴, which fits easily. The product of two values up to 10⁹ is up to 10¹⁸, which still just fits. Multiply three, and you've gone too far.

## Sized integers: Int8 to Int64

Swift also has integer types with a fixed number of bits. The number in the name is the bit count:

| Type | Bits | Smallest | Largest |
| --- | --- | --- | --- |
| `Int8` | 8 | -128 | 127 |
| `Int16` | 16 | -32,768 | 32,767 |
| `Int32` | 32 | about -2.1 × 10⁹ | about 2.1 × 10⁹ |
| `Int64` | 64 | about -9.2 × 10¹⁸ | about 9.2 × 10¹⁸ |

Each has its own `.min` and `.max`:

```swift run
print(Int8.min, Int8.max)
print(Int16.min, Int16.max)
print(Int32.min, Int32.max)
```

```output
-128 127
-32768 32767
-2147483648 2147483647
```

### When a literal doesn't fit

If you write a number that's too big for the type you asked for, Swift catches it before the program runs:

```swift
let small: Int8 = 200
```

```text title="What you'll see"
error: integer literal '200' overflows when stored into 'Int8'
```

That's the compiler checking ranges for you. When a value only becomes too big *while* the program runs, Swift stops the program instead, as you'll see in *Overflow traps and overflow operators*, later in this module.

### Why those numbers?

With *n* bits there are 2ⁿ different patterns of 0s and 1s. Eight bits give 2⁸ = 256 patterns. A **signed** type, one that allows negative numbers, splits them between negatives and the rest: 128 negatives (-128 to -1), then zero and 127 positives. That's why the maximum is one less than the size of the minimum.

<Callout kind="analogy">
Think of a car's mileage counter with a fixed number of digits. A three-digit counter can show 000 to 999 and nothing beyond. Integer types are counters with a fixed number of binary digits, so each has a largest value it can hold.
</Callout>

## Unsigned integers: UInt and UInt8

**Unsigned** types hold only zero and positive numbers. Without negatives, all the patterns go to positive values, so the maximum roughly doubles:

```swift run
print(UInt8.min, UInt8.max)
print(UInt.max)
```

```output
0 255
18446744073709551615
```

There's a `UInt` matching `Int`, plus `UInt8`, `UInt16`, `UInt32` and `UInt64`. `UInt8` is a **byte**, the basic unit of computer memory. You'll meet it in M08, where treating text as bytes makes string algorithms much faster.

## Use Int by default

With so many types, which should you use? Almost always **`Int`**, even for values that can never be negative, like a count. Apple's own guidance says the same, for practical reasons:

- The standard library uses `Int` everywhere. The number of items in a list is an `Int`, and positions in a list are `Int`.
- Swift never mixes integer types by itself, so using other types means writing conversions all over your code.
- An `Int` is so large that you rarely need anything bigger.

Reach for a sized or unsigned type only when you have a specific reason, such as working with raw bytes (`UInt8`) or matching a file format.

<Callout kind="gotcha" title="Swift gotcha: Int and Int64 are different types">
On a 64-bit Mac, `Int` and `Int64` have exactly the same range, but they're still **different types**, so Swift won't combine them:

```swift
let a: Int = 1
let b: Int64 = 2
print(a + b)
```

```text title="What you'll see"
error: binary operator '+' cannot be applied to operands of type 'Int' and 'Int64'
```

Convert one of them, as in `a + Int(b)`. You'll learn conversions in *Converting between types*, later in this module.
</Callout>

## Writing integers in other bases

Now and then, it's clearer to write a number in another base. A prefix tells Swift which:

```swift run
let fromBinary = 0b1010
let fromHex = 0xFF
print(fromBinary, fromHex)
```

```output
10 255
```

`0b` means binary (base 2) and `0x` means hexadecimal (base 16). They're still ordinary `Int` values, and `print` shows them in decimal. You'll use binary literals in Part II's lessons on bit manipulation.
