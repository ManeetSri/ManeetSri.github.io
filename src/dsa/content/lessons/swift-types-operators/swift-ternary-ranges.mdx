## Why it matters

Two small pieces of syntax show up all over Swift code. The **ternary operator** picks one of two values in a single expression, perfect for "1 item" versus "3 items" in a label. **Ranges** describe a run of consecutive values, like 1 to 10. You'll use ranges to repeat code a set number of times in M03, to take slices of arrays in M07, and to describe the part of a list a binary search is still looking at.

## The ternary operator

The ternary operator chooses between two values based on a condition:

```text
condition ? valueIfTrue : valueIfFalse
```

Read it as a question: "Is the condition true? If so, this value; otherwise, that one."

```swift run
let temperature = 35
let advice = temperature > 30 ? "Stay inside" : "Go for a walk"
print(advice)

let a = 8
let b = 13
let larger = a > b ? a : b
print(larger)
```

```output
Stay inside
13
```

It's called *ternary* because it takes three parts: the condition, and the two values. It's the only operator in Swift with three parts.

### A classic use: getting the words right

The ternary operator shines inside string interpolation, where you need a value, not a full statement:

```swift run
let count = 1
print("You have \(count) \(count == 1 ? "message" : "messages").")
let total = 3
print("You have \(total) \(total == 1 ? "message" : "messages").")
```

```output
You have 1 message.
You have 3 messages.
```

### Rules and good taste

- Both values must have the **same type**. `isReady ? "Go" : 0` doesn't compile, since a `String` and an `Int` can't share one result.
- Keep it short. A ternary is great for choosing between two simple values.
- **Don't nest them.** `a > b ? (a > c ? a : c) : (b > c ? b : c)` works, but almost nobody can read it at a glance. When there are more than two outcomes, use `if` or `switch`, which you'll learn in M03.

## Closed ranges: `a...b`

A **range** is a run of consecutive values between two ends. The **closed range** operator, three dots, includes **both** ends:

```swift run
let dice = 1...6
print(dice.count)
print(dice.contains(6))
print(dice.contains(7))
print(dice.lowerBound, dice.upperBound)
```

```output
6
true
false
1 6
```

`1...6` holds 1, 2, 3, 4, 5 and 6: six values. `lowerBound` and `upperBound` are its two ends. `contains` asks whether a value falls inside, which is often clearer than writing two comparisons: `(1...6).contains(roll)` instead of `roll >= 1 && roll <= 6`.

## Half-open ranges: `a..<b`

The **half-open range** operator, `..<`, includes the lower end but **stops just before** the upper end:

```swift run
let positions = 0..<4
print(positions.count)
print(positions.contains(3))
print(positions.contains(4))
print(positions.upperBound)
```

```output
4
true
false
4
```

`0..<4` holds 0, 1, 2 and 3. Its `upperBound` is 4, but 4 isn't in the range.

Half-open ranges exist because positions in a list start at **0**. A list of 4 items has positions 0, 1, 2 and 3, which is exactly `0..<4`, or `0..<count` in general. That's why you'll write half-open ranges far more often than closed ones in DSA code.

| Range | Values | `count` |
| --- | --- | --- |
| `1...5` | 1, 2, 3, 4, 5 | 5 |
| `1..<5` | 1, 2, 3, 4 | 4 |
| `0..<0` | none: an empty range | 0 |
| `3...3` | just 3 | 1 |

A half-open range with equal ends, like `5..<5`, is **empty**, and `isEmpty` tells you so. Empty ranges are perfectly valid, which is handy: a loop over `0..<count` simply runs zero times when there are no items.

<Callout kind="tip">
A quick way to count: `a..<b` has `b - a` values, and `a...b` has `b - a + 1`. Mistakes of exactly one, called **off-by-one errors**, are among the most common bugs in algorithms, and choosing the right range operator prevents many of them.
</Callout>

## One-sided ranges

Leave out one end and you get a **one-sided range**, which keeps going as far as possible in that direction:

```swift run
let adults = 18...
let children = ..<13
let smallNumbers = ...10
print(adults.contains(97))
print(children.contains(13))
print(smallNumbers.contains(-1000))
```

```output
true
false
true
```

- `18...` means 18 and everything above.
- `..<13` means everything below 13.
- `...10` means everything up to and including 10.

Their most common use is slicing an array: taking part of it from some position to the end, or from the start to some position. Here's a preview of what M07 covers properly:

```swift run
let letters = ["a", "b", "c", "d", "e"]
print(letters[1...3])
print(letters[2...])
print(letters[..<2])
```

```output
["b", "c", "d"]
["c", "d", "e"]
["a", "b"]
```

## Ranges as a search window

Many algorithms keep track of the part of a list they still need to look at, often called a **window**. Binary search, for example, starts with the whole list and repeatedly cuts the window in half. A half-open range describes a window neatly:

```swift run
let low = 3
let high = 11
let window = low..<high
print(window.count)
print(window.isEmpty)
print(low + (high - low) / 2)
```

```output
8
false
7
```

The window `3..<11` covers positions 3 to 10: that's `high - low`, 8 positions. Its middle is position 7, using the overflow-safe formula from [Arithmetic, integer division and remainder](/dsa/learn/swift-arithmetic). As the search narrows, `low` and `high` move towards each other. When they meet, the window `low..<high` is empty and the search is over. You'll see this exact shape in Part IV.

## Ranges of other types

Ranges work with any values that can be compared, not just `Int`:

```swift run
let probability = 0.0...1.0
print(probability.contains(0.25))
let lowercase: ClosedRange<Character> = "a"..."z"
print(lowercase.contains("q"))
print(lowercase.contains("Q"))
```

```output
true
true
false
```

The type of `1...5` is written `ClosedRange<Int>`: a closed range of `Int` values. `1..<5` is a `Range<Int>`. The angle brackets say what kind of value the range holds, and you'll learn how they work in M10. For now, you'll recognise these names in function signatures, such as the clamping problem below. Only integer ranges have a `count`, since you can't count every number between 0.0 and 1.0.

<Callout kind="gotcha" title="Swift gotcha: backwards ranges crash">
A range's lower end can't be above its upper end. `5...1` doesn't count down. It compiles, then crashes when the program runs:

```text title="What you'll see"
Fatal error: Range requires lowerBound <= upperBound
```

To count down, you'll use `reversed()` or `stride`, which you'll meet in M03.
</Callout>
