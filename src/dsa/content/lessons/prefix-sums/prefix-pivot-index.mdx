## Why it matters

Where should you split a playlist, or a queue of jobs, so both halves take the same time? Where does a beam balance? The **pivot index** (also called the equilibrium index) is the position where everything to its left sums to the same as everything to its right. It's a short problem with a useful lesson: once you know the **total**, the right-hand side is the total minus the left side, so you don't need a prefix array at all. One running sum and one subtraction replace the second sweep.

## The problem

> Return the leftmost index `i` where the sum of the elements before `i` equals the sum of the elements after `i`. The element at `i` belongs to neither side. Return `nil` if there's no such index.

| Input | Output | Why |
| --- | --- | --- |
| `[2, 3, -1, 8, 4]` | `3` | left `2 + 3 + -1 = 4`, right `4` |
| `[3, -3, 7]` | `2` | left `3 + -3 = 0`, right is empty, so `0` |
| `[1, 2, 3]` | `nil` | no index balances |
| `[5]` | `0` | both sides are empty |

An empty side sums to 0. That's why the second example works at the last index, and why a single element is always its own pivot.

## Brute force

For each index, add up the left side and the right side separately:

```swift run
func pivotSlowly(_ numbers: [Int]) -> Int? {
    for i in numbers.indices {
        let left = numbers[..<i].reduce(0, +)
        let right = numbers[(i + 1)...].reduce(0, +)
        if left == right {
            return i
        }
    }
    return nil
}

print(pivotSlowly([2, 3, -1, 8, 4]) as Any)
print(pivotSlowly([1, 2, 3]) as Any)
```

```output
Optional(3)
nil
```

Each index re-adds almost the whole array: O(n²). The `as Any` stops Swift warning that you're printing an optional, which is why you see `Optional(3)`.

## With a prefix array

Prefix sums from [1D prefix sums](/dsa/learn/prefix-1d) make each side O(1):

- the left side is `prefix[i]`, the first `i` elements;
- the right side is `prefix[n] − prefix[i + 1]`, everything after index `i`.

That's O(n) time, but it builds an array of n + 1 values.

## One running sum

Notice that you only ever read `prefix[i]` in order, from left to right, plus `prefix[n]`, the total. So keep the total and a running left sum:

> right side = total − left side − `numbers[i]`

```swift run
func pivotIndex(_ numbers: [Int]) -> Int? {
    let total = numbers.reduce(0, +)
    var leftSum = 0
    for (i, value) in numbers.enumerated() {
        let rightSum = total - leftSum - value
        if leftSum == rightSum {
            return i
        }
        leftSum += value               // only now does value join the left side
    }
    return nil
}

print(pivotIndex([2, 3, -1, 8, 4]) as Any)
print(pivotIndex([3, -3, 7]) as Any)
print(pivotIndex([1, 2, 3]) as Any)
print(pivotIndex([5]) as Any)
print(pivotIndex([0, 0, 0]) as Any)
print(pivotIndex([]) as Any)
```

```output
Optional(3)
Optional(2)
nil
Optional(0)
Optional(0)
nil
```

Two passes (one for the total, one to search) and two variables: **O(n) time, O(1) extra space**.

What to notice:

- **Check before you add.** At index `i`, `leftSum` must cover only the elements before `i`. Adding `value` first would put `numbers[i]` on the left, the same use-before-include rule as in [Product of array except self](/dsa/learn/prefix-product-except-self).
- **Returning at the first match** gives the leftmost pivot. With negatives or zeros there can be several: every index of `[0, 0, 0]` balances.
- **The edges work without special cases.** At index 0, `leftSum` is 0. At the last index, the right side is `total − leftSum − value`, which is 0.

## A variation: cutting between elements

A close cousin asks whether you can cut the array into two non-empty parts **with no element left out**, so both parts have the same sum. Now the cut falls *between* elements. The left part's sum must be exactly half the total, which means the total must be even:

```swift run
func equalSplit(_ numbers: [Int]) -> Int? {
    let total = numbers.reduce(0, +)
    guard total % 2 == 0 else { return nil }
    var leftSum = 0
    for i in 0..<max(numbers.count - 1, 0) {   // the right part must keep at least one element
        leftSum += numbers[i]
        if leftSum == total / 2 {
            return i + 1                       // the right part starts here
        }
    }
    return nil
}

print(equalSplit([3, 1, 2, 2]) as Any)
print(equalSplit([1, 2, 4]) as Any)
print(equalSplit([4, -4]) as Any)
```

```output
Optional(2)
nil
nil
```

`[3, 1 | 2, 2]` splits into two parts of 4. `[1, 2, 4]` has an odd total, so it can't split. `[4, -4]` has total 0, but neither non-empty split works: 4 on the left, −4 on the right. Read the statement carefully: "pivot element excluded" and "cut between elements" are different problems.

<Callout kind="gotcha" title="Common mistakes">
- **Including the pivot in a side.** The pivot belongs to neither side: `right = total − left − numbers[i]`.
- **Assuming one answer.** Negatives and zeros allow several pivots, so the statement says which to return. Here it's the leftmost.
- **Assuming the sums only grow.** With negative numbers, `leftSum` can go down, so you can't stop early when it "passes" the right side.
</Callout>
