## Why it matters

Prefix sums make range **queries** cheap. Difference arrays make range **updates** cheap. Think of a calendar app working out how many events overlap each hour, a festival adding three volunteers to every day from Tuesday to Friday, or a game applying a +5 bonus to every tile in a stretch of the map. When there are thousands of such updates over thousands of positions, updating every position each time is O(n) per update. A difference array makes each update O(1), and you read the final values with a single prefix sum at the end.

## The slow way

Here's the problem. You have an array of `count` zeros and a list of updates, each saying "add `amount` to every position from `first` through `last`". Return the final array.

```swift run
func applySlowly(count: Int, updates: [(first: Int, last: Int, amount: Int)]) -> [Int] {
    var values = Array(repeating: 0, count: count)
    for update in updates {
        for index in update.first...update.last {
            values[index] += update.amount
        }
    }
    return values
}

print(applySlowly(count: 6, updates: [(1, 3, 5), (2, 5, 2), (0, 1, 10)]))
```

```output
[10, 15, 7, 7, 2, 2]
```

With m updates that each cover up to n positions, this is O(n × m). For 100,000 updates over 100,000 days, that's up to 10¹⁰ steps.

## Record where things change

Look at the answer `[10, 15, 7, 7, 2, 2]` and ask a different question: **how much does each value differ from the one before it?**

| index | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| value | 10 | 15 | 7 | 7 | 2 | 2 |
| change from the previous | +10 | +5 | −8 | 0 | −5 | 0 |

That bottom row is the **difference array**: `diff[i] = values[i] − values[i − 1]`, with `diff[0] = values[0]`. Running a prefix sum over it adds the changes back up and rebuilds the original values: `10, 10 + 5, 15 − 8`, and so on.

So prefix sums and differences undo each other. You can store an array as its changes, and a prefix sum turns the changes back into values:

```swift run
let values = [4, 4, 7, 7, 7, 2]

var diff = [values[0]]
for index in 1..<values.count {
    diff.append(values[index] - values[index - 1])
}
print(diff)

var rebuilt: [Int] = []
var running = 0
for change in diff {
    running += change
    rebuilt.append(running)
}
print(rebuilt)
```

```output
[4, 0, 3, 0, 0, -5]
[4, 4, 7, 7, 7, 2]
```

Runs of equal values become runs of zeros in `diff`. A change only shows up at the **edges** of each run.

## A range update touches two slots

Now the useful part. Adding `amount` to every position from `first` through `last` only changes the differences at two edges:

- At `first`, the value jumps up by `amount` compared with the one before it: `diff[first] += amount`.
- At `last + 1`, the value drops back down: `diff[last + 1] -= amount`.
- Everywhere in between, neighbours both went up by the same amount, so their difference is unchanged.

Two O(1) writes per update, however long the range. Then one prefix sum at the end turns the differences into values:

```swift run
func applyUpdates(count: Int, updates: [(first: Int, last: Int, amount: Int)]) -> [Int] {
    var diff = Array(repeating: 0, count: count + 1)   // one spare slot for last + 1
    for update in updates {
        diff[update.first] += update.amount
        diff[update.last + 1] -= update.amount
    }
    print("diff:", diff)

    var values: [Int] = []
    var running = 0
    for index in 0..<count {
        running += diff[index]
        values.append(running)
    }
    return values
}

print(applyUpdates(count: 6, updates: [(1, 3, 5), (2, 5, 2), (0, 1, 10)]))
```

```output
diff: [10, 5, -8, 0, -5, 0, -2]
[10, 15, 7, 7, 2, 2]
```

Same answer as the slow version. Notice the spare slot at index 6: the update `(2, 5, 2)` ends at the last position, so it writes `-2` at `diff[6]`. Giving `diff` one extra slot means you never need an `if last + 1 < count` check. It's the same idea as the sentinel in [1D prefix sums](/dsa/learn/prefix-1d). The final loop never reads that slot.

Here's how the three updates build `diff`, starting from all zeros:

| after update | `diff` |
| --- | --- |
| (none) | `[0, 0, 0, 0, 0, 0, 0]` |
| `(1, 3, 5)` | `[0, 5, 0, 0, -5, 0, 0]` |
| `(2, 5, 2)` | `[0, 5, 2, 0, -5, 0, -2]` |
| `(0, 1, 10)` | `[10, 5, -8, 0, -5, 0, -2]` |

The cost: **O(n + m)** time for m updates over n positions, and O(n) space.

## Counting overlaps

A difference array with `+1` and `−1` counts how many ranges cover each position. Say you have meetings in whole hours, written as half-open ranges like `9..<11` (9:00 to 11:00). How many meetings are running at once in the busiest hour?

```swift run
let meetings = [9..<11, 10..<12, 10..<11, 13..<15]

var diff = Array(repeating: 0, count: 25)
for meeting in meetings {
    diff[meeting.lowerBound] += 1     // a meeting starts
    diff[meeting.upperBound] -= 1     // and stops being counted at its end hour
}

var running = 0
var busiestHour = 0
var most = 0
for hour in 0..<24 {
    running += diff[hour]
    if running > most {
        most = running
        busiestHour = hour
    }
}
print("busiest hour \(busiestHour):00 with \(most) meetings")
```

```output
busiest hour 10:00 with 3 meetings
```

With a half-open range, the `−1` goes at `upperBound` itself rather than one past it, because the end hour isn't included. Get this right for whichever kind of range your problem uses: it's the most common bug with difference arrays.

## Updating an existing array

If the array doesn't start as zeros, there are two equally good routes, both O(n + m):

- Build the array's own difference array first (as above), apply the updates to it, then prefix-sum it back into values.
- Or apply the updates to an all-zero `diff` as usual, so its prefix sums are each position's total **increase**, and add those increases to the original values.

## The catch: batch first, read later

A difference array is fast because it postpones the work. In the middle of the updates, `diff` doesn't hold the real values, so reading "what's at index 3 right now?" would need a prefix sum, O(n). The pattern fits when **all the updates come first and all the reads come after**.

| Situation | Tool |
| --- | --- |
| Many range queries, no updates | prefix sums |
| Many range updates, then read everything | difference array |
| Updates and queries mixed together | Fenwick tree or segment tree (Part VIII) |

<Callout kind="gotcha" title="Common mistakes">
- **No spare slot.** With `diff` the same size as the array, an update ending at the last index writes past the end and crashes. Make it `count + 1`.
- **The wrong end.** Inclusive `first...last` puts the `−amount` at `last + 1`. Half-open `first..<end` puts it at `end`.
- **Forgetting the final pass.** `diff` holds changes, not values. Nothing is finished until you've run the prefix sum.
</Callout>

**Volunteer roster** gives you a festival's pledges, each adding some volunteers to a run of days, and asks for the total on every day. The days are numbered from 1, so you'll need to translate them to array indexes as well: decide where that happens before you write any code.

```cards
- id: range-update
  front: "How do you add `v` to every position from `first` through `last` with a difference array?"
  back: "`diff[first] += v` and `diff[last + 1] -= v`, then one prefix sum at the end. Two writes per update, whatever the length."
- id: diff-when
  front: "When does a difference array fit a problem?"
  back: "When there are many range updates and you only need the values after all of them. Reads in the middle would cost O(n) each."

  front: "Why give the difference array `count + 1` slots?"
  back: "So an update that ends at the last index can write its `-v` at `last + 1` without a bounds check."
```
