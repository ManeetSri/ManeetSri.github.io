## Why it matters

This is one of the most-asked array questions in interviews: for each position, the product of every **other** element, without using division. It looks like a trick question, but it teaches two habits you'll use again and again: building information **from both ends** (a prefix from the left and a suffix from the right), and saving memory by **reusing the output array** as working space. The same left-and-right shape solves trapping rain water in the next module.

## The problem

> Given an array of integers, return an array where position `i` holds the product of every element except `numbers[i]`. Don't use division.

| Input | Output |
| --- | --- |
| `[2, 3, 4, 5]` | `[60, 40, 30, 24]` |
| `[1, 0, 3, 4]` | `[0, 12, 0, 0]` |

For the first, position 0 is `3 × 4 × 5 = 60`, position 1 is `2 × 4 × 5 = 40`, and so on. The brute force multiplies the other n − 1 elements for each position: O(n²).

## Why not divide?

The obvious shortcut: multiply everything once, then divide by each element. It's O(n), and it fails on the second example. The total is 0, and position 1 asks for `0 / 0`:

```swift
func productsByDivision(_ numbers: [Int]) -> [Int] {
    let total = numbers.reduce(1, *)
    return numbers.map { total / $0 }
}

print(productsByDivision([1, 0, 3, 4]))
```

```text title="What you'll see"
Fatal error: Division by zero
```

That's what Swift reports when an integer is divided by zero. Even with special cases for one zero and for two, interviewers usually ban division outright, to see whether you know the real technique. As [Prefix XOR](/dsa/learn/prefix-xor) showed, multiplication's undo, division, doesn't work past a zero.

## Left products and right products

Split "everything except position `i`" into two parts:

> product except `i` = (product of everything **left** of `i`) × (product of everything **right** of `i`)

Both parts are prefix-style arrays:

- `left[i]` is the product of `numbers[0..<i]`. It starts at `1`, the product of nothing, in the same way that a prefix sum starts at 0.
- `right[i]` is the product of `numbers[(i + 1)...]`, built the same way from the other end.

```swift run
let numbers = [2, 3, 4, 5]
let n = numbers.count

var left = Array(repeating: 1, count: n)
for i in 1..<n {
    left[i] = left[i - 1] * numbers[i - 1]
}

var right = Array(repeating: 1, count: n)
for i in stride(from: n - 2, through: 0, by: -1) {
    right[i] = right[i + 1] * numbers[i + 1]
}

var answer: [Int] = []
for i in 0..<n {
    answer.append(left[i] * right[i])
}
print("left:  ", left)
print("right: ", right)
print("answer:", answer)
```

```output
left:   [1, 2, 6, 24]
right:  [60, 20, 5, 1]
answer: [60, 40, 30, 24]
```

Position 2: everything to its left is `2 × 3 = 6`, everything to its right is `5`, and `6 × 5 = 30`. The `1` at each edge plays the sentinel role: nothing to the left of position 0, nothing to the right of the last position. `stride(from:through:by:)` from [stride and counting backwards](/dsa/learn/swift-stride) walks right to left.

This is O(n) time, with two extra arrays: O(n) extra space.

## O(1) extra space

Can you avoid the two extra arrays? Two observations:

1. Write the left products **straight into the answer array**. It has to exist anyway.
2. You never need the whole `right` array at once, only `right[i]` at position `i`. Sweep from the right with one running variable, `suffix`, and multiply it into the answer as you go.

```swift run
func productsExceptSelf(_ numbers: [Int]) -> [Int] {
    let n = numbers.count
    var answer = Array(repeating: 1, count: n)

    // Pass 1: answer[i] = product of everything left of i
    var prefix = 1
    for i in 0..<n {
        answer[i] = prefix
        prefix *= numbers[i]
    }

    // Pass 2: multiply in the product of everything right of i
    var suffix = 1
    for i in stride(from: n - 1, through: 0, by: -1) {
        answer[i] *= suffix
        suffix *= numbers[i]
    }
    return answer
}

print(productsExceptSelf([2, 3, 4, 5]))
print(productsExceptSelf([1, 0, 3, 4]))
print(productsExceptSelf([0, 2, 0]))
print(productsExceptSelf([-1, 2, -3]))
```

```output
[60, 40, 30, 24]
[0, 12, 0, 0]
[0, 0, 0]
[-6, 3, -2]
```

What to notice:

- In each pass, the position is **used before** its own number is multiplied in. That's what keeps `numbers[i]` out of `answer[i]`. Swap the two lines in either loop and every answer includes its own element.
- Zeros need no special case. With one zero, every other position's product includes it and becomes 0, while the zero's own position gets the product of everything else. With two zeros, every position includes at least one.
- The answer array doesn't count as extra space. By convention, "O(1) extra space" means memory **beyond the output** you were asked to return. Here that's two `Int` variables.

## The left-and-right pattern

Whenever position `i` depends on "everything to its left" and "everything to its right", think of two sweeps:

| Problem | Left sweep | Right sweep | Combine |
| --- | --- | --- | --- |
| Product except self | product so far | product so far | multiply |
| [Pivot index](/dsa/learn/prefix-pivot-index) | sum so far | total minus the left sum | compare |
| Trapping rain water (M21) | tallest so far | tallest so far | the smaller one, minus the height |

The next lesson turns the pivot index into one sweep, by working out the right side from the total instead of sweeping for it.

<Callout kind="gotcha" title="Swift gotcha: products overflow quickly">
Products grow far faster than sums. `20!` is about 2.4 × 10¹⁸ and fits in an `Int`, but `21!` doesn't, and Swift **stops the program** on overflow rather than wrapping round. Interview versions guarantee the answers fit. If yours doesn't, `multipliedReportingOverflow(by:)` lets you detect it, as [the overflow checklist](/dsa/learn/math-floor-ceil-overflow) showed.
</Callout>

## Practice

**Product of everything else** asks for this exactly, in O(n) time without division. Get the two-array version working first, then fold it into the answer array. Test with zero, one and two zeros, and with negatives.

```cards

  back: "Multiply the product of everything to its left by the product of everything to its right: a prefix product and a suffix product."
- id: product-except-no-division
  front: "Why does the divide-the-total approach fail?"
  back: "A zero in the array makes the total 0, and dividing by the zero's own position crashes with division by zero."
- id: product-except-space
  front: "How does product except self get down to O(1) extra space?"
  back: "Store the left products in the answer array, then sweep from the right with one running `suffix` variable, multiplying it in. The output array doesn't count as extra space."
- id: use-before-multiply
  front: "In each sweep, why is `answer[i]` set before `numbers[i]` is multiplied into the running product?"
  back: "So the running product covers only the elements strictly before (or after) `i`, keeping `numbers[i]` out of its own answer."
```
