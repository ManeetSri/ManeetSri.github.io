## Why it matters

Every frame a game draws pushes thousands of points through a chain of transformation matrices: scale, rotate, project. Machine learning libraries multiply long chains of matrices all day. The result doesn't depend on how you bracket the chain, but the **work** does, sometimes by a factor of hundreds. Finding the cheapest bracketing is the textbook example of **interval DP**: a DP whose state is a range `i...j`, filled from short ranges to long ones. Every lesson in this module is a variation on the pattern you'll learn here.

## What multiplying matrices costs

A **matrix** is a grid of numbers with some rows and columns; "a 2 × 3 matrix" has 2 rows and 3 columns. You can multiply a p × q matrix by a q × r matrix (the inner sizes must match), and the result is p × r. Each of its p · r entries is a sum of q products, so the whole multiplication takes **p · q · r** scalar multiplications.

You don't need to remember how the entries are computed for this lesson, only the count. Here it is in code, for a 2 × 3 matrix times a 3 × 2 matrix:

```swift run
func multiply(_ a: [[Int]], _ b: [[Int]]) -> (product: [[Int]], multiplications: Int) {
    let rows = a.count, inner = b.count, cols = b[0].count
    var product = Array(repeating: Array(repeating: 0, count: cols), count: rows)
    var multiplications = 0
    for r in 0..<rows {
        for c in 0..<cols {
            for k in 0..<inner {                       // row r of a times column c of b
                product[r][c] += a[r][k] * b[k][c]
                multiplications += 1
            }
        }
    }
    return (product, multiplications)
}

let result = multiply([[1, 2, 3], [4, 5, 6]], [[1, 0], [0, 1], [2, 2]])
print(result.product)
print(result.multiplications)
```

```output
[[7, 8], [16, 17]]
12
```

2 · 3 · 2 = 12 multiplications, and a 2 × 2 result.

## The order changes the cost

Matrix multiplication is **associative**: `(AB)C` and `A(BC)` give the same matrix. They don't cost the same. Take A as 10 × 30, B as 30 × 5 and C as 5 × 60:

| Bracketing | First product | Second product | Total |
| --- | --- | --- | --- |
| `(AB)C` | AB: 10 · 30 · 5 = 1,500, giving 10 × 5 | (AB)C: 10 · 5 · 60 = 3,000 | **4,500** |
| `A(BC)` | BC: 30 · 5 · 60 = 9,000, giving 30 × 60 | A(BC): 10 · 30 · 60 = 18,000 | **27,000** |

Six times the work for the same answer. Multiplying A by B first shrinks everything to a thin 10 × 5 matrix, while BC builds a big 30 × 60 one.

**The problem:** given a chain of matrices, find the fewest scalar multiplications needed to compute the product.

The sizes come as one array, `dims`, where matrix i is `dims[i] × dims[i + 1]`. The chain above is `[10, 30, 5, 60]`: three matrices, four numbers. Neighbours share a size, so one array describes the whole chain.

## Too many bracketings to try

How many ways can you bracket n matrices? Two matrices have one way, three have two, four have five. The counts are the **Catalan numbers**, and they explode:

| Matrices | Bracketings |
| --- | --- |
| 4 | 5 |
| 10 | 4,862 |
| 20 | 1,767,263,190 |

Trying them all is out. But the bracketings share a lot of structure, which is exactly what DP feeds on.

## Think about the last multiplication

However you bracket the chain `A1 … An`, **some** multiplication happens last. It multiplies the product of a left part, `A1 … Ak`, by the product of a right part, `Ak+1 … An`. And the best way to compute the whole chain with its last split at k uses the best way to compute each part, because the two parts don't interact until that final multiplication. That's optimal substructure.

The parts are themselves ranges of the chain, so the state is a range:

> `cost[i][j]` is the fewest multiplications needed to compute the product of matrices i through j.

Now follow [the DP recipe](/dsa/learn/dp-recipe):

- **Transition:** try every split k from i to j − 1. The left product is `dims[i] × dims[k + 1]`, the right is `dims[k + 1] × dims[j + 1]`, so the final multiplication costs `dims[i] · dims[k + 1] · dims[j + 1]`:

  `cost[i][j] = min over k of cost[i][k] + cost[k + 1][j] + dims[i] · dims[k + 1] · dims[j + 1]`

- **Base case:** `cost[i][i] = 0`. A single matrix needs no multiplying.
- **Order:** every range must come after the shorter ranges inside it. More on this below.
- **Answer:** `cost[0][n - 1]`, the whole chain.

## Filling the table by length

The natural "row by row, left to right" order doesn't work here. `cost[0][3]` needs `cost[1][3]` and `cost[2][3]`, which are in **later** rows. What every range needs is shorter ranges, so fill by **length**: first all ranges of two matrices, then all of three, and so on. In the table, that's one diagonal at a time, moving up and to the right.

| Pass | Cells filled |
| --- | --- |
| length 1 (base) | `[0][0]`, `[1][1]`, `[2][2]`, `[3][3]` |
| length 2 | `[0][1]`, `[1][2]`, `[2][3]` |
| length 3 | `[0][2]`, `[1][3]` |
| length 4 | `[0][3]`, the answer |

```swift run
func cheapestChain(_ dims: [Int]) -> [[Int]] {
    let n = dims.count - 1                                          // matrix i is dims[i] × dims[i + 1]
    var cost = Array(repeating: Array(repeating: 0, count: n), count: n)
    if n < 2 { return cost }
    for length in 2...n {                                           // shorter ranges first
        for i in 0...(n - length) {
            let j = i + length - 1
            cost[i][j] = Int.max
            for k in i..<j {                                        // last multiplication: (i...k)(k+1...j)
                let total = cost[i][k] + cost[k + 1][j] + dims[i] * dims[k + 1] * dims[j + 1]
                cost[i][j] = min(cost[i][j], total)
            }
        }
    }
    return cost
}

let cost = cheapestChain([10, 30, 5, 60, 10])
for row in cost {
    print(row)
}
print("whole chain:", cost[0][3])
```

```output
[0, 1500, 4500, 5000]
[0, 0, 9000, 4500]
[0, 0, 0, 3000]
[0, 0, 0, 0]
whole chain: 5000
```

Only the upper triangle is used: a range needs i ≤ j. Step through the same chain. The amber cell is the range being solved, and the blue cells are the two parts of its best split:

What to notice:

- `cost[0][2]` is the example from earlier: 4,500, splitting after A2.
- For the whole chain, splitting in the middle wins: `(A1 A2)(A3 A4)` costs 1,500 + 3,000 + 10 · 5 · 10 = 5,000. Neither `cost[0][2]` nor `cost[1][3]` alone points there; only trying every split finds it.
- `cost[i][j] = Int.max` is a placeholder that the first split always replaces. It's never added to anything, so it can't overflow.

## The same thing, top-down

If the fill order feels slippery, write the recurrence as a memoised recursion, as in [Top-down memoisation](/dsa/learn/dp-memoisation). The recursion asks for smaller ranges itself, so the order takes care of itself:

```swift run
func cheapestChainMemo(_ dims: [Int]) -> Int {
    let n = dims.count - 1
    var memo = Array(repeating: Array(repeating: -1, count: n), count: n)   // -1: not solved yet

    func best(_ i: Int, _ j: Int) -> Int {
        if i == j { return 0 }
        if memo[i][j] != -1 { return memo[i][j] }
        var answer = Int.max
        for k in i..<j {
            answer = min(answer, best(i, k) + best(k + 1, j) + dims[i] * dims[k + 1] * dims[j + 1])
        }
        memo[i][j] = answer
        return answer
    }

    return best(0, n - 1)
}

print(cheapestChainMemo([10, 30, 5, 60, 10]))
print(cheapestChainMemo([10, 30, 5, 60]))
```

```output
5000
4500
```

Both versions do the same work. The bottom-up one avoids deep recursion and is usually a little faster; the top-down one is often quicker to write correctly.

## Recovering the bracketing

The cost alone rarely satisfies anyone: you want the bracketing. As in [Reconstructing the answer, not just its value](/dsa/learn/dp-reconstruct), remember each choice. Store the best k for each range in `split[i][j]`, then rebuild the brackets recursively: a range is either one matrix, or its left part and right part in brackets.

```swift run
func bestBracketing(_ dims: [Int]) -> String {
    let n = dims.count - 1
    var cost = Array(repeating: Array(repeating: 0, count: n), count: n)
    var split = Array(repeating: Array(repeating: 0, count: n), count: n)   // the best k for each range
    if n >= 2 {
        for length in 2...n {
            for i in 0...(n - length) {
                let j = i + length - 1
                cost[i][j] = Int.max
                for k in i..<j {
                    let total = cost[i][k] + cost[k + 1][j] + dims[i] * dims[k + 1] * dims[j + 1]
                    if total < cost[i][j] {
                        cost[i][j] = total
                        split[i][j] = k
                    }
                }
            }
        }
    }

    func bracket(_ i: Int, _ j: Int) -> String {
        if i == j { return "A\(i + 1)" }
        let k = split[i][j]
        return "(" + bracket(i, k) + " " + bracket(k + 1, j) + ")"
    }

    return bracket(0, n - 1)
}

print(bestBracketing([10, 30, 5, 60, 10]))
print(bestBracketing([10, 30, 5, 60]))
print(bestBracketing([40, 20, 30, 10, 30]))
print(bestBracketing([7, 3]))
```

```output
((A1 A2) (A3 A4))
((A1 A2) A3)
((A1 (A2 A3)) A4)
A1
```

The rebuild visits each range in the final bracketing once, so it costs O(n) after the table is built.

## Cost

There are about n²/2 ranges, and each tries up to n splits: **O(n³)** time and **O(n²)** memory.

| Matrices | about n³/6 | Verdict |
| --- | --- | --- |
| 100 | 170,000 | instant |
| 500 | 2 × 10⁷ | fine |
| 3,000 | 4.5 × 10⁹ | too slow |

That's a useful rule of thumb: when the input is a few hundred elements and the problem is about **ranges**, O(n³) interval DP is often the intended solution. (Some interval DPs can be sped up to O(n²) with Knuth's optimisation, which you'll meet in [Monotonic queue, convex hull trick, Knuth and D&C optimisations](/dsa/learn/dpa-optimisations).)

## The interval DP template

Strip away the matrices and this is what's left:

```swift
for length in 2...n {                     // shorter ranges first
    for i in 0...(n - length) {
        let j = i + length - 1
        dp[i][j] = worstValue             // Int.max when minimising, Int.min when maximising
        for k in i..<j {                  // the choice that splits i...j
            dp[i][j] = better(dp[i][j], combine(dp[i][k], dp[k + 1][j], joinCost(i, k, j)))
        }
    }
}
```

Suspect interval DP when:

- the answer for a whole sequence is built from answers for **contiguous pieces**;
- an operation **merges neighbours**, or removing an element changes who its neighbours are;
- the question asks for the best way to bracket, split, merge or remove things in a line;
- n is in the hundreds, which is about what O(n³) allows.

The hard part is always the same: deciding what the splitting choice k **means** so that the two sides become independent. For matrices, it's the last multiplication. The rest of this module is mostly about finding that choice in disguise.

<Callout kind="gotcha" title="Common mistakes">
- **Filling row by row.** `cost[i][j]` needs `cost[k + 1][j]` from later rows. Fill by length, or loop i downwards from n − 1 with j upwards from i + 1.
- **Getting the cost of the join wrong.** It's `dims[i] * dims[k + 1] * dims[j + 1]`: the left part's rows, the shared size, the right part's columns. `dims[k]` is a classic slip.
- **Mixing up counts.** `dims` has n + 1 numbers for n matrices.
- **Forgetting the single-matrix chain.** `2...n` traps when n is 1, because a range whose lower bound is above its upper bound crashes. Handle n < 2 first.
</Callout>
