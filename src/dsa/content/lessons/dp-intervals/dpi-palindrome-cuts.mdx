## Why it matters

In [Palindrome partitioning and IP addresses](/dsa/learn/bk-partitioning) you listed **every** way to split a string into palindromes with backtracking. There can be exponentially many. Asking only for the **fewest cuts** changes everything: it becomes an O(n²) DP. Along the way you'll build a table of which substrings are palindromes, a tool that turns up in many string problems, and you'll see when an interval DP can shrink to a one-dimensional one.

## The problem

Cut a string into pieces so that every piece is a palindrome, reading the same forwards and backwards. Use as few cuts as possible. Single letters are palindromes, so an answer always exists: at worst, cut between every pair of letters.

- `"noonabbad"` needs 2 cuts: `noon | abba | d`.
- `"racecarannakayak"` needs 2: `racecar | anna | kayak`.
- `"abcd"` needs 3: every letter on its own.
- `"level"` needs 0: it's already a palindrome.

## A first attempt: interval DP

The previous lessons suggest a range state: the fewest cuts for `s[i...j]`. If that piece is a palindrome, 0; otherwise, try every place k to make a cut and solve both sides:

```text
cuts[i][j] = 0                                                   if s[i...j] is a palindrome
cuts[i][j] = min over k from i to j - 1 of cuts[i][k] + 1 + cuts[k + 1][j]   otherwise
```

That's correct, but it's O(n³), and if `isPalindrome` checks characters one by one it's O(n⁴). Both problems have fixes.

## Step 1: a table of palindromes

Checking a substring by walking inwards from both ends costs O(n) each time. Instead, precompute the answer for every substring at once. A substring is a palindrome when its two end characters match **and** what's between them is a palindrome:

> `isPal[i][j] = s[i] == s[j] && (j - i < 2 || isPal[i + 1][j - 1])`

The `j - i < 2` part covers substrings of length 1 and 2, whose insides are empty. `isPal[i][j]` depends on `isPal[i + 1][j - 1]`, a row **below** it, so fill rows from the bottom up, with i going downwards. (Filling by length works too, just as in [Matrix chain multiplication](/dsa/learn/dpi-matrix-chain).)

```swift run
func palindromeTable(_ text: String) -> [[Bool]] {
    let s = Array(text)                                  // O(1) access by position
    let n = s.count
    var isPal = Array(repeating: Array(repeating: false, count: n), count: n)
    for i in stride(from: n - 1, through: 0, by: -1) {   // row i + 1 must be ready before row i
        for j in i..<n {
            isPal[i][j] = s[i] == s[j] && (j - i < 2 || isPal[i + 1][j - 1])
        }
    }
    return isPal
}

for row in palindromeTable("abba") {
    print(row.map { $0 ? "T" : "." }.joined(separator: " "))
}
```

```output
T . . T
. T T .
. . T .
. . . T
```

Row i, column j says whether `s[i...j]` is a palindrome. The diagonal is all single letters. `"bb"` at row 1, column 2 is a palindrome, and so `"abba"` in the top-right corner is one too: matching ends around a palindromic middle. That's **O(n²)** time and memory, and every later check is an O(1) lookup. (Expanding around each centre, from [Palindromes and expand-around-centre](/dsa/learn/str-palindromes), fills the same table in the same time.)

## Step 2: think about the last piece

Now the cuts. In any valid split of the prefix `s[0...j]`, the **last piece** is some palindrome `s[i...j]`. Everything before it, `s[0...i - 1]`, is itself split into palindromes, and should use as few cuts as possible. So:

> `cuts[j]` is the fewest cuts that split `s[0...j]` into palindromes.

- If `s[0...j]` is a palindrome, `cuts[j] = 0`.
- Otherwise, `cuts[j] = min over i in 1...j with isPal[i][j] of cuts[i - 1] + 1`: the best split of what comes before the last piece, plus one cut in front of it.
- The answer is `cuts[n - 1]`.

Only the **left** end of the last piece varies; the right end is always j. So the state needs one index, not two. Remembering where each best last piece starts lets you print the pieces too:

```swift run
func fewestCuts(_ text: String) -> (cuts: Int, pieces: [String]) {
    let s = Array(text)
    let n = s.count
    guard n > 0 else { return (0, []) }
    var isPal = Array(repeating: Array(repeating: false, count: n), count: n)
    for i in stride(from: n - 1, through: 0, by: -1) {
        for j in i..<n {
            isPal[i][j] = s[i] == s[j] && (j - i < 2 || isPal[i + 1][j - 1])
        }
    }

    var cuts = Array(repeating: 0, count: n)       // cuts[j]: fewest cuts for s[0...j]
    var start = Array(repeating: 0, count: n)      // where the best last piece of s[0...j] begins
    for j in 0..<n where !isPal[0][j] {            // a palindromic prefix needs no cuts
        cuts[j] = Int.max
        for i in 1...j where isPal[i][j] && cuts[i - 1] + 1 < cuts[j] {
            cuts[j] = cuts[i - 1] + 1
            start[j] = i
        }
    }

    var pieces: [String] = []
    var end = n - 1
    while end >= 0 {                               // peel off last pieces, right to left
        pieces.append(String(s[start[end]...end]))
        end = start[end] - 1
    }
    return (cuts[n - 1], pieces.reversed())
}

for text in ["noonabbad", "racecarannakayak", "abcbm", "abcd", "level"] {
    print(text, fewestCuts(text))
}
```

```output
noonabbad (cuts: 2, pieces: ["noon", "abba", "d"])
racecarannakayak (cuts: 2, pieces: ["racecar", "anna", "kayak"])
abcbm (cuts: 2, pieces: ["a", "bcb", "m"])
abcd (cuts: 3, pieces: ["a", "b", "c", "d"])
level (cuts: 0, pieces: ["level"])
```

What to notice:

- `cuts[j] = Int.max` is safe: single letters are palindromes, so `i = j` always offers a real value and replaces it. `Int.max` is never added to.
- When `j` is 0, `s[0...0]` is a palindrome, so the `where` clause skips it and the empty range `1...0` is never built.
- Pieces = cuts + 1, always.

Both steps are O(n²), so the whole solution is **O(n²)** time and memory. For a 2,000-letter string that's 4 million table cells: instant.

## When interval DP shrinks to one dimension

Why could this problem drop an index when matrix chain couldn't? In matrix chain, the last multiplication joins two parts that are **both** arbitrary ranges, so the state needs both ends. Here, a split of a prefix always ends with one piece, and what remains is always another **prefix**. Prefixes need only one number to describe.

That's worth checking every time you write an interval DP: if every choice peels a piece off one end and leaves a prefix (or a suffix), a 1D state is enough, and you save a factor of n.

## Saving memory by expanding around centres

The n × n table is the memory hog. You can avoid it. Process palindromes by their centres, from left to right, and update `cuts` as each palindrome is discovered. A palindrome `s[l...r]` offers `cuts[r] = cuts[l - 1] + 1`, or 0 if `l == 0`. Every palindrome that ends at `l - 1` has its centre further left, so it has already been processed and `cuts[l - 1]` is final.

```swift run
func fewestCutsCompact(_ text: String) -> Int {
    let s = Array(text)
    let n = s.count
    guard n > 0 else { return 0 }
    var cuts = Array(0..<n)                        // worst case: cut before every letter but the first
    for centre in 0..<n {
        for (startLeft, startRight) in [(centre, centre), (centre, centre + 1)] {   // odd, then even length
            var l = startLeft
            var r = startRight
            while l >= 0 && r < n && s[l] == s[r] {
                cuts[r] = min(cuts[r], l == 0 ? 0 : cuts[l - 1] + 1)
                l -= 1
                r += 1
            }
        }
    }
    return cuts[n - 1]
}

print(fewestCutsCompact("noonabbad"), fewestCutsCompact("racecarannakayak"), fewestCutsCompact("abcd"))
```

```output
2 2 3
```

Still O(n²) time, but only O(n) memory.

<Callout kind="gotcha" title="Common mistakes">
- **Filling `isPal` with i going upwards.** `isPal[i][j]` reads row i + 1, which wouldn't be ready yet.
- **Indexing a `String` with integers.** Swift strings don't allow `text[3]`. Convert once with `Array(text)`.
- **Answering pieces instead of cuts.** The number of cuts is one less than the number of pieces.
- **Checking palindromes on the fly inside the cuts loop.** That's O(n) per check and O(n³) overall. Precompute.
</Callout>
