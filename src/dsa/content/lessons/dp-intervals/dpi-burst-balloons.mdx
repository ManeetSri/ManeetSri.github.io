## Why it matters

Burst balloons has a reputation as one of the hardest common interview DPs, and almost all of the difficulty is in one idea: instead of asking what happens **first**, ask what happens **last**. Once you've seen that trick, it unlocks a whole class of "remove things from a line and score by the neighbours" problems. It's also [Matrix chain multiplication](/dsa/learn/dpi-matrix-chain) in disguise, which you'll see by the end.

## The game

A row of balloons each carries a number. When you pop a balloon, you score its number times the numbers of its **current** left and right neighbours. A missing neighbour, past either end of the row, counts as 1. The popped balloon disappears, so its two neighbours become next to each other. You pop every balloon, in any order you like. What's the highest total score?

Take `[4, 2, 6]`. There are six orders:

| Order | Scores | Total |
| --- | --- | --- |
| 4, 2, 6 | 1·4·2 = 8, then 1·2·6 = 12, then 1·6·1 = 6 | 26 |
| 4, 6, 2 | 8, then 2·6·1 = 12, then 2 | 22 |
| 2, 4, 6 | 4·2·6 = 48, then 1·4·6 = 24, then 6 | **78** |
| 2, 6, 4 | 48, then 4·6·1 = 24, then 4 | 76 |
| 6, 4, 2 | 2·6·1 = 12, then 1·4·2 = 8, then 2 | 22 |
| 6, 2, 4 | 12, then 4·2·1 = 8, then 4 | 24 |

Popping the small 2 first, while the big 4 and 6 are both beside it, wins. With n balloons there are n! orders, so trying them all stops being possible at around 10 balloons.

## Why "which one first?" doesn't split

The DP instinct is to choose something and split the rest into independent subproblems. Try choosing the **first** balloon to pop, k. What's left is the part to its left and the part to its right. But they aren't independent. Once k is gone, the last balloon of the left part and the first balloon of the right part are neighbours, so popping either one later scores using the other. The two halves are tangled together, and no table indexed by ranges can describe them.

## Choose the last balloon instead

Now ask which balloon is popped **last** among some range. Suppose the balloons strictly between positions `left` and `right` are the ones being popped, while `left` and `right` themselves stay put until afterwards; think of them as **walls**. If k is the last balloon popped between the walls:

- When k is popped, everything else between the walls is already gone, so its neighbours are exactly the two walls. It scores `values[left] · values[k] · values[right]`, whatever happened before.
- Until then, k is still standing. It acts as a wall between the balloons on its left and the balloons on its right, so no balloon on one side is ever next to a balloon on the other. The two sides are **independent**: the best for `(left, k)` plus the best for `(k, right)`.

That gives a clean interval DP over **open** ranges, where the two ends are walls:

> `best[left][right]` is the highest score from popping every balloon strictly between positions `left` and `right`, while those two stay.

- **Transition:** `best[left][right] = max over left < k < right of best[left][k] + best[k][right] + values[left] · values[k] · values[right]`.
- **Base case:** when `right == left + 1`, there's nothing between them: 0.
- **Order:** by gap, `right - left`, from small to large.
- **Answer:** the range whose walls are the two ends.

## Padding with 1s

The real row has no walls at its ends, only the rule that a missing neighbour counts as 1. So add them: put an imaginary balloon worth 1 at each end, `values = [1] + balloons + [1]`. Those two are never popped, and they score exactly like a missing neighbour. The answer is `best[0][n + 1]` for n real balloons.

Here it is, also remembering which balloon went last in each range so the order can be rebuilt:

```swift run
func bestPopping(_ balloons: [Int]) -> (score: Int, order: [Int]) {
    let values = [1] + balloons + [1]                    // walls worth 1 at both ends
    let n = values.count
    var best = Array(repeating: Array(repeating: 0, count: n), count: n)
    var lastPopped = Array(repeating: Array(repeating: -1, count: n), count: n)
    if n >= 3 {
        for gap in 2..<n {                               // narrow ranges first
            for left in 0..<(n - gap) {
                let right = left + gap
                for last in (left + 1)..<right {         // the last balloon popped between the walls
                    let total = best[left][last] + best[last][right] + values[left] * values[last] * values[right]
                    if lastPopped[left][right] == -1 || total > best[left][right] {
                        best[left][right] = total
                        lastPopped[left][right] = last
                    }
                }
            }
        }
    }

    // Pop everything left of the last balloon, then everything right of it, then the balloon itself
    func order(_ left: Int, _ right: Int) -> [Int] {
        guard right - left >= 2 else { return [] }
        let last = lastPopped[left][right]
        return order(left, last) + order(last, right) + [values[last]]
    }

    return (best[0][n - 1], order(0, n - 1))
}

print(bestPopping([4, 2, 6]))
print(bestPopping([7, 1, 8, 2]))
print(bestPopping([]))
```

```output
(score: 78, order: [2, 4, 6])
(score: 189, order: [1, 8, 2, 7])
(score: 0, order: [])
```

Check the second one by hand: pop 1 for 7·1·8 = 56, then 8 for 7·8·2 = 112, then 2 for 7·2·1 = 14, and finally 7 for 1·7·1 = 7. That's 189.

What to notice:

- The walls are **outside** the range: `last` runs over `(left + 1)..<right`, never touching `left` or `right`.
- The order comes out backwards from how you'd think of it: the DP decides the last pop of the whole row first, then the last pop of each side, and so on. The `order` function turns that into a forwards popping order.
- The `lastPopped[left][right] == -1` check makes sure a choice is recorded even if every total is 0, which happens when balloons are worth 0.

## Trust, but check

A DP built on a clever insight deserves a test against brute force. This one tries every order directly, popping each balloon in turn and recursing on what's left:

```swift run
func bruteForce(_ balloons: [Int]) -> Int {
    var best = 0
    for i in balloons.indices {
        let left = i > 0 ? balloons[i - 1] : 1
        let right = i < balloons.count - 1 ? balloons[i + 1] : 1
        var rest = balloons
        rest.remove(at: i)
        best = max(best, left * balloons[i] * right + bruteForce(rest))
    }
    return best
}

func maxScore(_ balloons: [Int]) -> Int {
    let values = [1] + balloons + [1]
    let n = values.count
    var best = Array(repeating: Array(repeating: 0, count: n), count: n)
    if n < 3 { return 0 }
    for gap in 2..<n {
        for left in 0..<(n - gap) {
            let right = left + gap
            for last in (left + 1)..<right {
                best[left][right] = max(best[left][right], best[left][last] + best[last][right] + values[left] * values[last] * values[right])
            }
        }
    }
    return best[0][n - 1]
}

for balloons in [[4, 2, 6], [7, 1, 8, 2], [3, 0, 5, 1, 4], [9], [2, 2, 2, 2, 2, 2]] {
    print(balloons, bruteForce(balloons), maxScore(balloons))
}
```

```output
[4, 2, 6] 78 78
[7, 1, 8, 2] 189 189
[3, 0, 5, 1, 4] 96 96
[9] 9 9
[2, 2, 2, 2, 2, 2] 38 38
```

The brute force is O(n!), so it's only for tiny inputs, but agreement on a handful of awkward cases (a zero, one balloon, all equal) is strong evidence. The tests for this module's problems work the same way.

## It's matrix chain in disguise

Compare the recurrences. In matrix chain, matrix t is `dims[t] × dims[t + 1]`, so the matrices from a to b − 1 multiply out to `dims[a] × dims[b]`. Splitting them at c, into a to c − 1 and c to b − 1, makes the last multiplication cost `dims[a] · dims[c] · dims[b]`. Burst balloons splits the balloons between walls `left` and `right` at the last balloon k and scores `values[left] · values[k] · values[right]`. Same shape, same O(n³) loops; matrix chain takes the minimum, burst balloons the maximum.

In matrix chain the split was "the **last** multiplication". Here it's "the **last** pop". In both, choosing what happens last is what makes the two sides independent.

| Matrices or balloons | Ranges | Splits per range | Work |
| --- | --- | --- | --- |
| 100 | about 5,000 | up to 100 | instant |
| 500 | about 125,000 | up to 500 | about 2 × 10⁷, fine |

<Callout kind="gotcha" title="Common mistakes">
- **Choosing the first balloon.** The halves aren't independent, so the recurrence is wrong. Choose the last.
- **Closed ranges.** If `left` and `right` are themselves popped in the range, their neighbours aren't known. Keep the walls outside.
- **Forgetting the padding.** Without the two 1s, the ends have no walls and the scores at the edges are wrong.
- **Starting the gap at 1.** A gap of 1 has nothing between the walls. Start at 2.
</Callout>

**Popping bubbles for points** is this game. Write the brute force first on paper, convince yourself why "first" fails, then build the table over open ranges.

```cards
  back: "Popping the first makes its two sides neighbours, so they aren't independent. The last balloon stays standing as a wall, so the sides are independent and its neighbours at the end are the range's walls."
- id: balloons-recurrence
  front: "What is the burst balloons recurrence?"
  back: "With `values = [1] + balloons + [1]`: `best[l][r] = max over l < k < r of best[l][k] + best[k][r] + values[l] · values[k] · values[r]`, and `best[l][l + 1] = 0`."
- id: balloons-padding
  front: "Why pad the balloons with a 1 at each end?"
  back: "A missing neighbour scores as 1, so two never-popped balloons worth 1 act as walls and make the ends work like every other range."
- id: balloons-mcm
  front: "How is burst balloons related to matrix chain multiplication?"
  back: "It's the same recurrence on the padded values, maximised instead of minimised: the last pop plays the part of the last multiplication."
```
