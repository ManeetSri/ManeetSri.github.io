## Why it matters

Chess engines, the computer player in a noughts-and-crosses app, and every "can the first player force a win?" puzzle rest on one idea: **assume your opponent plays as well as you do**, and choose the move that's best against their best reply. That's **minimax**. When the game is played on a row and each move takes something from one end, the positions are ranges, and minimax becomes an interval DP with a single, elegant line of recurrence.

## The game

A row of coins lies on the table, each worth some amount. Two players take turns. On each turn, a player takes **one coin from either end** of the row. When the row is empty, whoever has collected more wins. Both players play perfectly. By how much does the first player win (or lose)?

## Greedy loses

The obvious strategy is to take the bigger end. Here it is for both players on `[3, 9, 1, 2]`:

```swift run
func greedyGame(_ coins: [Int]) -> (first: Int, second: Int) {
    var left = 0
    var right = coins.count - 1
    var scores = [0, 0]
    var player = 0
    while left <= right {
        if coins[left] >= coins[right] {          // take the bigger end
            scores[player] += coins[left]
            left += 1
        } else {
            scores[player] += coins[right]
            right -= 1
        }
        player = 1 - player
    }
    return (scores[0], scores[1])
}

print(greedyGame([3, 9, 1, 2]))
```

```output
(first: 5, second: 10)
```

The first player grabs 3, which hands the 9 to the opponent. Taking the **smaller** end, 2, is much better: the row becomes `[3, 9, 1]`, and whichever end the opponent takes, the 9 becomes available to the first player. That line ends 11 to 4. Good moves depend on what they leave for the other player, so greed fails, as it did in [When greedy fails](/dsa/learn/greedy-counterexamples).

## Think in score differences

Here's the trick that makes the DP tidy. Don't track two scores. Track one number, the **margin**: the mover's total minus the other player's total, from here to the end of the game.

> `margin[i][j]` is the best margin the player **about to move** can guarantee on coins i...j.

Suppose you're to move on coins i...j:

- **Take the left coin.** You gain `coins[i]`. Then your opponent moves on i + 1...j, where by definition they can get a margin of `margin[i + 1][j]` over you. Their margin is your loss, so your margin is `coins[i] - margin[i + 1][j]`.
- **Take the right coin.** Likewise, `coins[j] - margin[i][j - 1]`.

You pick the better one:

> `margin[i][j] = max(coins[i] - margin[i + 1][j], coins[j] - margin[i][j - 1])`

with `margin[i][i] = coins[i]`: one coin left, you take it.

The minus sign is the whole of game theory in one character. Because the margin is always measured from the **mover's** point of view, the same table serves both players, and "my opponent tries to maximise their margin" automatically means "my opponent tries to minimise mine". This form of minimax is sometimes called **negamax**.

Notice what the state **doesn't** include: the scores so far. The coins already taken can't affect which coins remain or how the rest of the game goes, and a margin from here onwards adds to whatever lead you already have. That's why the range alone is enough.

## The table

Each range needs the two ranges one coin shorter, so fill i from the bottom up and j from left to right, or by length:

```swift run
func bestMargin(_ coins: [Int]) -> Int {
    let n = coins.count
    guard n > 0 else { return 0 }
    var margin = Array(repeating: Array(repeating: 0, count: n), count: n)
    for i in stride(from: n - 1, through: 0, by: -1) {
        margin[i][i] = coins[i]                               // one coin left: take it
        for j in stride(from: i + 1, to: n, by: 1) {
            let takeLeft = coins[i] - margin[i + 1][j]        // the opponent then moves on i+1...j
            let takeRight = coins[j] - margin[i][j - 1]       // or on i...j-1
            margin[i][j] = max(takeLeft, takeRight)
        }
    }
    for row in margin {
        print(row)
    }
    return margin[0][n - 1]
}

let coins = [3, 9, 1, 2]
let margin = bestMargin(coins)
let total = coins.reduce(0, +)
print("margin:", margin, "first player:", (total + margin) / 2, "second player:", (total - margin) / 2)
```

```output
[3, 6, -5, 7]
[0, 9, 8, 8]
[0, 0, 1, 1]
[0, 0, 0, 2]
margin: 7 first player: 11 second player: 4
```

What to notice:

- `margin[0][2]` is −5: on `[3, 9, 1]` the mover loses by 5, because whichever end they take, the 9 goes to the opponent. That's exactly the position the first player creates by taking the 2, and why `margin[0][3] = 2 - (-5) = 7`.
- The two scores come back from the margin and the total: their sum is `total` and their difference is `margin`, so the first player has `(total + margin) / 2`.
- The first player wins if the margin is positive, ties if it's 0, and loses if it's negative.
- That's **O(n²)** time and memory. Row i only reads row i + 1 and itself, so one array of length n is enough if memory matters, as in [Saving space](/dsa/learn/dp-space).

## Game theory intuition

Picture every possible play as a tree: the root is the full row, each position has two children (take left, take right), and the leaves are empty rows. Minimax evaluates the tree from the leaves up. At each position, the mover picks the child that's best for them, knowing the value of each child already assumes perfect play below it. This is called **backward induction**.

The tree has 2ⁿ leaves, but only about n²/2 different positions, because a position is a range. The same range is reached by many different move sequences: taking left then right leaves the same row as taking right then left. Memoising positions instead of exploring paths is what turns an exponential game tree into a quadratic DP, just as in [Overlapping subproblems and optimal substructure](/dsa/learn/dp-what-is-dp).

## A neat fact for an even number of coins

With an **even** number of coins, the first player can never lose. Colour the positions alternately: even indexes and odd indexes. At the start, the two end coins have different colours, so the first player can take whichever colour they like. After that, the opponent is always left facing one end of each colour, and whatever they take, the first player can take the other coin of their chosen colour from the newly exposed end. So the first player can collect **every** coin of one colour, and picks the colour with the larger total.

For `[4, 7, 2, 9, 5, 1]`, the even positions hold 4 + 2 + 5 = 11 and the odd positions hold 7 + 9 + 1 = 17, so the first player can guarantee a margin of at least 6. The DP confirms that 6 is the best possible here, but in general the DP can do better than the colouring strategy, and it also handles odd lengths, where the colouring trick doesn't apply.

## Variant: taking from the front only

Many versions change the moves. A common one: the coins are in a row, and each turn a player takes **one, two or three** coins from the **front**. Now the position is "how many coins have been taken", a suffix, so the DP is one-dimensional. The negamax rule is the same:

> `best[i] = max over t in 1...3 of (coins[i] + … + coins[i + t - 1]) - best[i + t]`

```swift run
func takeOneToThree(_ coins: [Int]) -> Int {
    let n = coins.count
    var best = Array(repeating: 0, count: n + 1)          // best[n]: no coins left, margin 0
    for i in stride(from: n - 1, through: 0, by: -1) {
        best[i] = Int.min
        var taken = 0
        for t in 1...3 where i + t <= n {
            taken += coins[i + t - 1]
            best[i] = max(best[i], taken - best[i + t])   // take t coins, then the opponent moves
        }
    }
    return best[0]
}

print(takeOneToThree([5, -3, 8, 1, 1]))
print(takeOneToThree([2, 4, -1, 6]))
```

```output
8
1
```

Coins can be negative here, so sometimes the best move is to take more than you'd like to push a bad coin onto your opponent. The DP doesn't need to know that; it compares every option against the best reply.

<Callout kind="gotcha" title="Common mistakes">
- **Adding instead of subtracting.** `coins[i] + margin[i + 1][j]` treats the opponent's margin as yours. The recurrence subtracts.
- **Tracking two scores in the state.** It works but makes the state bigger and the code harder. The margin carries all you need.
- **Assuming the opponent is greedy.** Minimax assumes a perfect opponent; against a weaker one you'll still do at least as well as the DP promises.
- **Filling rows from the top.** `margin[i][j]` reads row i + 1, so i goes downwards.
</Callout>
