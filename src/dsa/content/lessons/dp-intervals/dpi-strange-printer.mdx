## Why it matters

Some interval DPs don't split a range at an arbitrary point. They split where two **equal** things can share one action. The strange printer is the classic example: a printer that can only print runs of one character, where printing two equal letters in one sweep saves a turn. The same "merge equal characters across a gap" idea drives a family of hard contest problems about removing or painting blocks. It's also a good workout in arguing **why** a recurrence covers every optimal plan.

## The printer

A printer starts with a blank line. Each **turn**, it prints one character over any contiguous stretch of positions, covering whatever was there. What is the fewest turns that produce a given target string?

Take `"abcba"`. Three turns are enough:

```text
turn 1:  a a a a a      print "a" over all five positions
turn 2:  a b b b a      print "b" over positions 1 to 3
turn 3:  a b c b a      print "c" over position 2
```

Printing letter by letter would take five. Here the two a's share a turn, and so do the two b's. No plan does it in two (a brute-force search over every possible pair of turns confirms it).

## Step 0: collapse repeated letters

`"aaabbb"` takes the same number of turns as `"ab"`: two. Any turn that colours one letter of a run can be stretched to colour the whole run, so a run of equal letters never costs more than one letter. Collapsing runs first, so `"aaabbb"` becomes `"ab"`, keeps the table small and makes the reasoning cleaner. From here on, assume no two neighbouring letters are equal.

## The leftmost letter

Let `turns[i][j]` be the fewest turns to print `s[i...j]` on a blank stretch. Look at its **leftmost** letter, `s[i]`.

Some turn gives position i its final letter; call it the **i-turn**. You can assume it's the **first** turn. Any earlier turn that overlaps the i-turn's stretch gets covered by it there anyway, so trim that earlier turn back until it no longer overlaps (or drop it, if nothing is left). Now nothing before the i-turn touches its stretch, and it can move to the front without changing the result.

So the first turn prints `s[i]` over a stretch starting at i, and every other turn paints on top of it. Two cases:

1. **The i-turn stays visible only at position i.** Everything else it painted is covered later, so it might as well print position i alone: 1 turn, plus printing `s[i + 1...j]` separately. That's `1 + turns[i + 1][j]`.
2. **It also stays visible further right.** Let k be the **first** position after i where it shows, so `s[k] == s[i]`. Every position between i and k is covered later, by turns that can't reach i or k without hiding the i-turn there. So those turns stay strictly between i and k, and they print `s[i + 1...k - 1]` on their own: `turns[i + 1][k - 1]` turns at least. The i-turn, cut down to start at k, together with all the remaining turns, prints `s[k...j]`: `turns[k][j]` turns at least. That's `turns[i + 1][k - 1] + turns[k][j]`, and you can achieve it: print `s[k...j]` with its own first turn stretched left to cover i, then print the middle on top.

Putting the cases together:

> `turns[i][j] = min(1 + turns[i + 1][j], min over i < k ≤ j with s[k] == s[i] of turns[i + 1][k - 1] + turns[k][j])`

with `turns[i][i] = 1` and an empty range costing 0.

The second case is where the saving happens: `s[i]` "rides along" with an equal letter further right. For `"abcba"`, the a at position 0 rides with the a at position 4, giving `turns[1][3] + turns[4][4]`, which is the 2 turns for `"bcb"` plus 1.

<Callout kind="analogy">
Think of painting a fence with a roller that can only do one colour per stroke. If two boards far apart need the same colour, one long stroke can do both, and you paint the boards in between afterwards. The question at each step is which later board, if any, your first board should share a stroke with.
</Callout>

## The code

`turns[i][j]` reads row i + 1 and rows k > i, so fill i from the bottom up, and j from left to right within each row:

```swift run
func fewestTurns(_ text: String) -> Int {
    var s: [Character] = []
    for letter in text where s.last != letter {
        s.append(letter)                                         // collapse runs: "aaabbb" → "ab"
    }
    let n = s.count
    if n == 0 { return 0 }
    var turns = Array(repeating: Array(repeating: 0, count: n), count: n)
    for i in stride(from: n - 1, through: 0, by: -1) {
        turns[i][i] = 1
        for j in stride(from: i + 1, to: n, by: 1) {
            turns[i][j] = 1 + turns[i + 1][j]                    // s[i] gets a turn of its own
            for k in stride(from: i + 1, through: j, by: 1) where s[k] == s[i] {
                let between = k - 1 >= i + 1 ? turns[i + 1][k - 1] : 0
                turns[i][j] = min(turns[i][j], between + turns[k][j])   // s[i] rides along with s[k]
            }
        }
    }
    return turns[0][n - 1]
}

for target in ["abcba", "aaabbb", "abab", "abcabc", "banana", "xyzzyx", ""] {
    print("\"\(target)\":", fewestTurns(target))
}
```

```output
"abcba": 3
"aaabbb": 2
"abab": 3
"abcabc": 5
"banana": 4
"xyzzyx": 3
"": 0
```

What to notice:

- `stride(from: i + 1, to: n, by: 1)` is empty when i is the last index. A closed range such as `(i + 1)...(n - 1)` would crash there, so strides are a safe habit in interval loops.
- `between` is 0 when k is right next to i: there's nothing in between to print.
- `"banana"` takes 4: the b, one sweep of a's across `anana`, then each n on its own. The two n's could share a turn, but then the a between them would need reprinting, which saves nothing.
- In `"abcabc"`, only one pair of equal letters can usefully share a turn, so it's 6 − 1 = 5.

## Why the argument covers every plan

Interval DPs are only right if the recurrence is neither too optimistic nor too pessimistic. Here, each case describes a plan that really works, so the true answer is never more than the recurrence. And the argument above shows that **every** plan, once its i-turn is moved to the front, falls into one of the cases and uses at least that many turns, so the true answer is never less. Both halves together prove the recurrence. Most interval DP proofs have exactly this shape: "every plan splits like this" and "every split gives a plan".

The step that needed care was choosing k as the **first** visible position after i. That's what guarantees no turn crosses from the middle part to the right part. Later visible positions are handled inside `turns[k][j]`, where the same argument runs again.

## Cost

O(n²) ranges, each trying up to n partners k: **O(n³)** time and **O(n²)** memory. With up to 200 letters, that's about 8 million steps at most.

## Harder cousins

Problems where you remove blocks and score by how many equal blocks you remove together (sometimes called "remove boxes") push this idea further. Equal blocks can be merged across a gap, just as here, but the score depends on **how many** have been gathered, so the state needs a third number: how many copies of `s[i]` are already attached. That's O(n⁴) and a good challenge once this lesson feels comfortable.

<Callout kind="gotcha" title="Common mistakes">
- **Only merging neighbouring equal letters.** The saving comes from equal letters with **other letters between them**.
- **Pairing `s[i]` with an unequal `s[k]`.** Only an equal letter can share the turn.
- **Filling i upwards.** `turns[i][j]` needs rows below i.
- **Reading `turns[i + 1][k - 1]` when k is i + 1.** That range is empty: use 0.
</Callout>
