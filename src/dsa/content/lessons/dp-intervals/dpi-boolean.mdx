## Why it matters

A compiler reading `a & b | c` has to decide which operator binds first, and different groupings can give different answers. Boolean parenthesisation asks: over **all** the ways to bracket an expression, how many make it true? It's a counting interval DP, and it teaches a lesson that reaches far beyond this problem: when one number per state isn't enough for the transition, **carry two**. Contest problems use this pattern constantly.

## The problem

An expression alternates symbols and operators. Symbols are `T` (true) and `F` (false). Operators are `&` (and), `|` (or) and `^` (xor: true when exactly one side is true). Count the ways to fully bracket the expression so that it evaluates to true.

Take `T^T&F|T`. With four symbols there are five bracketings:

| Bracketing | Working | Result |
| --- | --- | --- |
| `((T^T)&F)\|T` | `(F&F)\|T = F\|T` | true |
| `(T^(T&F))\|T` | `(T^F)\|T = T\|T` | true |
| `(T^T)&(F\|T)` | `F&T` | false |
| `T^((T&F)\|T)` | `T^(F\|T) = T^T` | false |
| `T^(T&(F\|T))` | `T^(T&T) = T^T` | false |

So the answer is 2. With 15 operators there are almost 10 million bracketings, so listing them is out.

## Split at the last operator

This is [Matrix chain multiplication](/dsa/learn/dpi-matrix-chain) again. Every bracketing of symbols i through j has a **last operator** to be evaluated, at some position k between symbol k and symbol k + 1. It combines the value of symbols i...k with the value of symbols k + 1...j, and the two sides are bracketed independently. So the number of bracketings that split at k is (ways for the left) × (ways for the right), and the total is a sum over k.

But "ways for the left" to do **what**? That depends on the operator:

- `L & R` is true when **both** sides are true.
- `L | R` is false when **both** sides are false, and true otherwise.
- `L ^ R` is true when one side is true and the other is false, so you need the ways the left is **false**, too.

A single count per range, "ways to be true", can't answer the `^` case or the `|` case. So keep two counts per range:

> `t[i][j]` is the number of bracketings of symbols i...j that evaluate to true, and `f[i][j]` the number that evaluate to false.

## Combining counts

For a split at operator k, write lt, lf for the left side's true and false counts and rt, rf for the right side's. Every pairing of a left bracketing with a right bracketing gives one bracketing of the whole range, so there are `(lt + lf) × (rt + rf)` of them in total. They divide up like this:

| Operator | Adds to the true count | Adds to the false count |
| --- | --- | --- |
| `&` | lt · rt | lt · rf + lf · rt + lf · rf |
| `\|` | lt · rt + lt · rf + lf · rt | lf · rf |
| `^` | lt · rf + lf · rt | lt · rt + lf · rf |

The base case is a single symbol: `T` has one true bracketing and no false ones, `F` the opposite. Fill by length, as in every interval DP so far, and the answer is `t[0][n - 1]`.

```swift run
func countWays(_ expression: String) -> (trueWays: Int, falseWays: Int) {
    let tokens = Array(expression)                                   // symbol, operator, symbol, …
    let symbols = stride(from: 0, to: tokens.count, by: 2).map { tokens[$0] == "T" }
    let operators = stride(from: 1, to: tokens.count, by: 2).map { tokens[$0] }
    let n = symbols.count
    var t = Array(repeating: Array(repeating: 0, count: n), count: n)
    var f = Array(repeating: Array(repeating: 0, count: n), count: n)
    for i in 0..<n {
        t[i][i] = symbols[i] ? 1 : 0
        f[i][i] = symbols[i] ? 0 : 1
    }
    if n >= 2 {
        for length in 2...n {
            for i in 0...(n - length) {
                let j = i + length - 1
                for k in i..<j {                                     // operators[k] is evaluated last
                    let (lt, lf, rt, rf) = (t[i][k], f[i][k], t[k + 1][j], f[k + 1][j])
                    switch operators[k] {
                    case "&":
                        t[i][j] += lt * rt
                        f[i][j] += lt * rf + lf * rt + lf * rf
                    case "|":
                        t[i][j] += lt * rt + lt * rf + lf * rt
                        f[i][j] += lf * rf
                    default:                                         // "^"
                        t[i][j] += lt * rf + lf * rt
                        f[i][j] += lt * rt + lf * rf
                    }
                }
            }
        }
    }
    return (t[0][n - 1], f[0][n - 1])
}

print(countWays("T^T&F|T"))
print(countWays("T|F&F^T"))
print(countWays("T"))
```

```output
(trueWays: 2, falseWays: 3)
(trueWays: 4, falseWays: 1)
(trueWays: 1, falseWays: 0)
```

What to notice:

- Symbols sit at even positions and operators at odd ones, so `stride(from:to:by:)` separates them. Operator k sits between symbols k and k + 1, which is why the split index and the operator index are the same.
- The `switch` needs a `default` because `operators` holds `Character` values, and the compiler can't know only three appear.
- The counts for the left and right sides are **multiplied**: each left bracketing pairs with each right bracketing. In matrix chain they were **added**, because costs add up. Counting turns sums into products.

## A built-in check

Every bracketing is either true or false, so `t[i][j] + f[i][j]` must equal the total number of bracketings of that range. That's the Catalan number for the number of operators: 1, 1, 2, 5, 14, 42, … for 0, 1, 2, 3, 4, 5 operators. A quick test catches a slip in the combining table:

```swift run
func totalBracketings(_ operatorCount: Int) -> Int {
    var catalan = [1]
    for size in stride(from: 1, through: operatorCount, by: 1) {
        var total = 0
        for left in 0..<size {
            total += catalan[left] * catalan[size - 1 - left]   // operators on each side of the last one
        }
        catalan.append(total)
    }
    return catalan[operatorCount]
}

print(2 + 3 == totalBracketings(3))   // T^T&F|T has 3 operators: 2 true and 3 false bracketings
print(totalBracketings(5))            // every expression with 5 operators has this many
```

```output
true
42
```

The Catalan recurrence is itself the same split: choose the last operator, then bracket the left and right sides independently.

## Huge counts and the modulo

Catalan numbers grow roughly like 4ⁿ, so with 36 operators the counts overflow `Int`. Contest versions ask for the answer modulo a number such as 1,000,000,007. Reduce after each step:

```swift
let mod = 1_000_000_007
t[i][j] = (t[i][j] + lt * rf % mod + lf * rt % mod) % mod
```

Each count is below the modulus, so a product of two is below 10¹⁸ and fits in an `Int` before reducing. That's also why the table above lists all three false cases for `&` instead of computing "total minus true": subtraction under a modulo can go negative.

<Callout kind="gotcha" title="Swift gotcha: % keeps the sign">
In Swift, `-3 % 5` is `-3`, not `2`. If you ever subtract under a modulo, write `(a - b + mod) % mod`, or add up the cases you want instead of subtracting the ones you don't.
</Callout>

## The same split, different payloads

The structure of this problem, "pick the last operator, combine the two sides", answers several questions depending on what each range stores:

| Each range stores | Question answered |
| --- | --- |
| the cheapest cost | matrix chain |
| counts of true and false | boolean parenthesisation |
| the list of every possible value | all results of bracketing an arithmetic expression |
| the largest and smallest value | the biggest result of bracketing an expression with `+`, `-` and `*` |

The last row needs both extremes for the same reason this lesson needed both counts: a maximum of `a * b` can come from two minimums, when both are negative.

<Callout kind="gotcha" title="Common mistakes">
- **Keeping only the true count.** `^` and `|` need the false counts of their sides too.
- **Adding instead of multiplying.** Left and right bracketings pair up, so their counts multiply.
- **Off-by-one between symbols and operators.** With n symbols there are n − 1 operators, and operator k joins symbols k and k + 1.
- **Overflow.** Counts grow exponentially; use a modulo when the problem asks for one.
</Callout>
