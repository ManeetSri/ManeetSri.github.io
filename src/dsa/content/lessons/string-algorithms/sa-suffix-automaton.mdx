## Why it matters

The suffix trie from [Radix trees and suffix tries](/dsa/learn/trie-radix) holds every substring of a text, one path each, but it needs O(n²) nodes. The **suffix automaton** holds exactly the same set of substrings in **at most 2n − 1 states**, and it's built online, one character at a time, in O(n). It's the smallest automaton that recognises every substring of a text, and it answers many of the same questions as a suffix array (distinct substrings, longest common substring, occurrence counts), often with shorter code once you have it. This deep dive explains what its states mean, builds one by hand, and uses it to count distinct substrings.

## Merging the suffix trie

Walk the suffix trie of `abb`. Its paths from the root spell the substrings `a`, `ab`, `abb`, `b` and `bb`. Look at what can *follow* each one, to the end of the text:

| Substring | Where it ends in `abb` (0-based) | What can follow it |
| --- | --- | --- |
| a | 0 | `b`, `bb` |
| ab | 1 | `b` |
| b | 1, 2 | `b`, or nothing |
| bb | 2 | nothing |
| abb | 2 | nothing |

`bb` and `abb` behave identically: they end in the same place, so whatever continues one continues the other. A trie keeps them as two separate nodes. An automaton can merge them into one **state**, because a state only needs to know what can come next.

That's the defining idea. For a substring t, let **endpos(t)** be the set of positions where its occurrences end. Two substrings belong to the same state of the suffix automaton exactly when they have the **same endpos**. For `abb`, the classes are \{a\}, \{ab\}, \{b\}, \{bb, abb\}, plus the start state for the empty string: five states, against six nodes in the suffix trie. On longer texts the saving is dramatic: O(n) states against O(n²) nodes.

Two facts about a state make the structure work:

- **Its strings are suffixes of each other, with consecutive lengths.** If `abb` ends wherever `bb` ends, then `bb` is a suffix of `abb`. A state holds its longest string and its suffixes down to some length: all lengths from `len(link) + 1` up to `len`.
- **The suffix link.** Keep cutting characters off the front of a state's longest string, and at some point the endpos set grows: the shorter string also occurs somewhere else. The state of that first shorter suffix is the state's **suffix link**. For \{bb, abb\}, cutting to `b` adds the end position 1, so the link points to the state of `b`.

So each state stores only two numbers, `len` (the length of its longest string) and `link`, plus its transitions. The strings it holds are implied: the suffixes of its longest string with lengths from `len[link] + 1` to `len`.

## Building it one character at a time

The construction keeps `last`, the state holding the whole text read so far. To add a character c:

1. **Create a state `cur`** for the new, longer text, with `len[cur] = len[last] + 1`.
2. **Walk the suffix links from `last`**, adding a transition on c to `cur` from every state that doesn't have one. Each of those states holds suffixes of the old text that have never been followed by c before, so their extension by c ends only at the new last position, which is `cur`'s endpos.
3. **If the walk falls off the start state**, c has never been seen before, and `cur`'s link is the start state.
4. **Otherwise it stopped at a state p that already has a transition on c**, to some q. If `len[q] == len[p] + 1`, q holds exactly the right strings, and `cur`'s link is q.
5. **Otherwise, q holds too much.** Some of q's strings, the longer ones, aren't suffixes of the new text, so their endpos didn't gain the new position, while the shorter ones did. q has to be split: make a **clone** of q with `len[p] + 1`, the same transitions and the same link. Redirect the c-transitions that pointed to q (from p and further down its link chain) to the clone, and point both q's and `cur`'s links at the clone.

Here's `abb`, step by step:

| Add | What happens | States afterwards |
| --- | --- | --- |
| a | state 1 (len 1); start gets a → 1; link(1) = start | start, 1 = \{a\} |
| b | state 2 (len 2); 1 gets b → 2, start gets b → 2; link(2) = start | 2 = \{ab, b\} |
| b | state 3 (len 3); 2 gets b → 3; start already has b → 2, but len(2) = 2 ≠ 0 + 1, so clone 2 as state 4 (len 1); start's b now goes to 4; link(2) = link(3) = 4 | 2 = \{ab\}, 3 = \{abb, bb\}, 4 = \{b\} |

The clone in the last step is the endpos idea at work. After `ab`, the strings `ab` and `b` both ended only at position 1, so they shared state 2. Reading the second `b`, `b` gains a new end position (2) but `ab` doesn't, so they can't share a state any more. The clone takes the shorter strings, `b`, and the original keeps `ab`.

```swift run
// A suffix automaton, built one character at a time
struct SuffixAutomaton {
    var len = [0]                       // the length of the longest string in each state
    var link = [-1]                     // suffix links; the start state has none
    var next: [[UInt8: Int]] = [[:]]    // transitions
    var end = [-1]                      // an end position of the state's strings (for printing)
    var last = 0                        // the state holding the whole text read so far

    mutating func extend(_ c: UInt8) {
        let cur = len.count
        len.append(len[last] + 1)
        link.append(0)
        next.append([:])
        end.append(len[cur] - 1)
        var p = last
        while p != -1 && next[p][c] == nil {    // every suffix with no c-transition gets one, to cur
            next[p][c] = cur
            p = link[p]
        }
        if p != -1 {
            let q = next[p][c]!
            if len[p] + 1 == len[q] {
                link[cur] = q                   // q holds exactly the right strings
            } else {
                let clone = len.count           // q holds too much: split off the shorter strings
                len.append(len[p] + 1)
                link.append(link[q])
                next.append(next[q])
                end.append(end[q])
                while p != -1 && next[p][c] == q {
                    next[p][c] = clone
                    p = link[p]
                }
                link[q] = clone
                link[cur] = clone
            }
        }
        last = cur
    }
}

let text = Array("abb".utf8)
var automaton = SuffixAutomaton()
for c in text { automaton.extend(c) }
for v in automaton.len.indices.dropFirst() {
    let longest = automaton.len[v], shortest = automaton.len[automaton.link[v]] + 1
    let strings = (shortest...longest).map { String(decoding: text[(automaton.end[v] - $0 + 1)...automaton.end[v]], as: UTF8.self) }
    let moves = automaton.next[v].keys.sorted().map { "\(Character(UnicodeScalar($0)))→\(automaton.next[v][$0]!)" }
    print("state \(v): len \(longest), link \(automaton.link[v]), holds \(strings), moves \(moves)")
}
print("start moves:", automaton.next[0].keys.sorted().map { "\(Character(UnicodeScalar($0)))→\(automaton.next[0][$0]!)" })
```

```output
state 1: len 1, link 0, holds ["a"], moves ["b→2"]
state 2: len 2, link 4, holds ["ab"], moves ["b→3"]
state 3: len 3, link 4, holds ["bb", "abb"], moves []
state 4: len 1, link 0, holds ["b"], moves ["b→3"]
start moves: ["a→1", "b→4"]
```

Check it against the definition: every path from the start spells a substring, and every substring has exactly one path. `b` goes start → 4; `bb` goes start → 4 → 3; `abb` goes start → 1 → 2 → 3. Both `bb` and `abb` end in state 3, the state that holds them both. The transitions are printed from sorted keys, never by printing a dictionary.

The `end` array is only there so the example can print each state's strings. The algorithm itself needs only `len`, `link` and `next`.

## How big, and how fast

- **States:** at most 2n − 1 for n ≥ 2. Each step adds `cur` and at most one clone.
- **Transitions:** at most 3n − 4.
- **Time:** O(n) in total for a fixed alphabet (with dictionaries, O(n) expected). Both walks along suffix links look like they could be long, but they're amortised, like KMP's fallbacks: every step of the first walk adds a transition, and there are at most 3n − 4 of those, and a similar counting argument on how deep `last` sits in the suffix-link tree bounds the redirect walk.

## Counting distinct substrings

Every distinct substring lives in exactly one state, and a state holds `len[v] - len[link[v]]` of them (the lengths from `len[link] + 1` to `len`). So the number of distinct substrings is a sum over the states:

> distinct substrings = sum over states v ≠ start of (len[v] − len[link[v]])

For `abb`: 1 + 1 + 2 + 1 = 5. Checked against brute force, with the state counts showing the 2n − 1 bound:

```swift run
struct SuffixAutomaton {
    var len = [0], link = [-1]
    var next: [[UInt8: Int]] = [[:]]
    var last = 0

    mutating func extend(_ c: UInt8) {
        let cur = len.count
        len.append(len[last] + 1); link.append(0); next.append([:])
        var p = last
        while p != -1 && next[p][c] == nil { next[p][c] = cur; p = link[p] }
        if p != -1 {
            let q = next[p][c]!
            if len[p] + 1 == len[q] {
                link[cur] = q
            } else {
                let clone = len.count
                len.append(len[p] + 1); link.append(link[q]); next.append(next[q])
                while p != -1 && next[p][c] == q { next[p][c] = clone; p = link[p] }
                link[q] = clone
                link[cur] = clone
            }
        }
        last = cur
    }

    // Each state holds the lengths len[link] + 1 ... len: that many distinct substrings
    var distinctSubstrings: Int {
        len.indices.dropFirst().reduce(0) { $0 + len[$1] - len[link[$1]] }
    }
}

for word in ["abb", "banana", "aaaa", "mississippi"] {
    var automaton = SuffixAutomaton()
    for c in word.utf8 { automaton.extend(c) }
    let s = Array(word.utf8)
    var brute = Set<ArraySlice<UInt8>>()
    for a in s.indices { for b in (a + 1)...s.count { brute.insert(s[a..<b]) } }
    print(word, "states:", automaton.len.count, "distinct:", automaton.distinctSubstrings, "brute force:", brute.count)
}

// 20,000 made-up letters from a, b and c, the same every run
var seed = 8
var automaton = SuffixAutomaton()
for _ in 0..<20_000 {
    seed = (seed * 1_103_515_245 + 12_345) % 2_147_483_648
    automaton.extend(97 + UInt8((seed >> 16) % 3))
}
print("n = 20000 states:", automaton.len.count, "(at most 2n - 1 = 39999)", "distinct:", automaton.distinctSubstrings)
```

```output
abb states: 5 distinct: 5 brute force: 5
banana states: 10 distinct: 15 brute force: 15
aaaa states: 5 distinct: 4 brute force: 4
mississippi states: 18 distinct: 53 brute force: 53
n = 20000 states: 34769 (at most 2n - 1 = 39999) distinct: 199847638
```

Nearly 200 million distinct substrings, held in under 35,000 states. A suffix trie of the same text would need a node for each of them.

## What else it answers

Each of these is a short walk or a pass over the states:

- **Is p a substring?** Follow transitions from the start, one per character of p. O(|p|).
- **How often does a substring occur?** That's the size of its state's endpos set. Give every non-clone state a count of 1, then add counts up the suffix-link tree, longest states first, the same "sum over the failure tree" as in [Aho–Corasick](/dsa/learn/sa-aho-corasick).
- **Longest common substring of two strings.** Build the automaton of the first, then walk the second through it, keeping the current state and matched length; on a missing transition, follow suffix links (shortening the match) until one exists. The longest match seen is the answer, in O(n + m).
- **The k-th smallest distinct substring.** Count the paths out of every state (a DP over the automaton, which is a DAG), then walk down choosing letters in order.

| | Suffix trie | Suffix array + LCP | Suffix automaton |
| --- | --- | --- | --- |
| Size | O(n²) nodes | 2n integers | at most 2n − 1 states, 3n − 4 transitions |
| Build | O(n²) | O(n log n) | O(n), online |
| Distinct substrings | count the nodes | n(n + 1)/2 − sum of lcp | sum of len − len(link) |
| Substring query | O(m) walk | O(m log n) binary search | O(m) walk |
| Easiest to get right | yes | fairly | the clone step takes care |

<Callout kind="gotcha" title="Common suffix automaton mistakes">
**A clone that doesn't copy everything.** The clone needs q's transitions *and* q's suffix link. Copying only the transitions leaves its link at the start state and breaks every later step.

**Redirecting too much.** Only transitions on c that point **to q** move to the clone, and the walk stops at the first state where the c-transition goes elsewhere. Redirecting every state on the chain corrupts the automaton.

**Counting the start state.** The start state holds only the empty string. Sum over the other states, or the distinct count includes a bogus term.

**Memory with dictionaries.** A dictionary per state is flexible, but 2n small dictionaries are heavy. For lowercase-only input, a flat `[Int32]` table of 26 entries per state is faster and more compact.
</Callout>
