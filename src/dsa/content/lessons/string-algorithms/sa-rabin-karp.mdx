## Why it matters

KMP and the Z-algorithm compare characters cleverly. **Rabin–Karp** takes a different road: turn each window of the text into a number, a **hash**, and compare numbers instead of strings. The trick that makes it fast is the **rolling hash**: sliding the window one step updates the hash in O(1), however long the window is. Plagiarism detectors use it to find shared passages, `rsync` uses a rolling checksum to find which blocks of a file changed, backup tools use it to split files into chunks, and it searches for many patterns of the same length in a single pass, where KMP needs one pass each. Rolling hashes also power the next big idea in this module: comparing any two substrings in O(1), in [Comparing substrings in O(1) with hashes](/dsa/learn/sa-substring-hashing).

## Fingerprints instead of strings

You've met the polynomial hash twice: in [Modular arithmetic](/dsa/learn/math-modular-arithmetic) and in [Hash functions](/dsa/learn/hash-functions). Treat the characters as the digits of a number in base B and reduce modulo M as you go (Horner's rule):

> hash(s) = (s₀ · B^(m−1) + s₁ · B^(m−2) + … + s_(m−1)) mod M

The idea of Rabin–Karp: compute the pattern's hash once, then the hash of every m-character window of the text. Where the hashes differ, the strings certainly differ, and you've ruled out that window with one comparison of two integers. Where they're equal, the strings are *probably* equal, and you check.

Computing each window's hash from scratch is O(m), so that alone gives nothing over naive matching. What makes it work is updating the hash as the window slides.

## Rolling a window

Forget the modulus for a moment and use base 10, so the hash of a window of digits is the number it spells. Slide a 4-digit window along `31415926`. Going from `3141` to `1415` takes three steps: remove the leading digit's contribution (3 × 1000), shift what's left one place (× 10), and add the new digit (5):

> (3141 − 3 × 1000) × 10 + 5 = 1415

```swift run
// Windows of 4 digits as numbers: drop the leading digit, shift, add the new one
let digits = "31415926".map { $0.wholeNumberValue! }
let m = 4
var window = 0
for k in 0..<m {
    window = window * 10 + digits[k]
}
print(window)
let high = 1_000                                    // 10^(m - 1): the place value of the leading digit
for i in m..<digits.count {
    window = (window - digits[i - m] * high) * 10 + digits[i]
    print(window)
}
```

```output
3141
1415
4159
1592
5926
```

Each slide costs three arithmetic operations, whatever m is. It's the same idea as the running sum in [Fixed-size windows](/dsa/learn/sw-fixed): instead of recomputing the window, subtract what leaves and add what arrives. A sum doesn't care about order, so `ab` and `ba` would look the same; the place values make the hash depend on order.

With characters, the "digits" are byte values (97 for `a`), the base is bigger than any character, and the number would overflow after a dozen characters, so every step is taken modulo M. The update becomes:

> h = ((h − leaving · B^(m−1)) · B + arriving) mod M

where B^(m−1) mod M is computed once, before the loop. The subtraction can go negative, so add M before taking the remainder, as [Modular arithmetic](/dsa/learn/math-modular-arithmetic) showed.

## Rabin–Karp

Put it together. Hash the pattern and the first window, then slide. On every hash match, **verify** by comparing the characters, because different strings can share a hash. This version takes the modulus as a parameter, so you can see what a bad one does:

```swift run
// Rabin–Karp with a modulus that fits comfortably in Int
func rabinKarp(_ pattern: [UInt8], in text: [UInt8], modulus: Int) -> (matches: [Int], hashHits: Int) {
    let m = pattern.count, n = text.count
    guard m > 0, m <= n else { return ([], 0) }
    let base = 131
    var high = 1                                    // base^(m - 1) % modulus
    for _ in 1..<m { high = high * base % modulus }
    var patternHash = 0, windowHash = 0
    for k in 0..<m {
        patternHash = (patternHash * base + Int(pattern[k])) % modulus
        windowHash = (windowHash * base + Int(text[k])) % modulus
    }
    var matches: [Int] = []
    var hashHits = 0
    for start in 0...(n - m) {
        if start > 0 {                              // roll: remove text[start - 1], add text[start + m - 1]
            windowHash = (windowHash - Int(text[start - 1]) * high % modulus + modulus) % modulus
            windowHash = (windowHash * base + Int(text[start + m - 1])) % modulus
        }
        if windowHash == patternHash {
            hashHits += 1
            if text[start..<(start + m)].elementsEqual(pattern) {   // verify: hashes can collide
                matches.append(start)
            }
        }
    }
    return (matches, hashHits)
}

// 5,000 made-up lowercase letters, the same every run
var seed = 63
var text: [UInt8] = []
for _ in 0..<5_000 {
    seed = (seed * 1_103_515_245 + 12_345) % 2_147_483_648
    text.append(97 + UInt8((seed >> 16) % 26))
}
let pattern = Array(text[1234..<1240])
print("pattern:", String(decoding: pattern, as: UTF8.self))
for modulus in [101, 1_000_000_007] {
    let result = rabinKarp(pattern, in: text, modulus: modulus)
    print("modulus \(modulus): matches \(result.matches), hash hits \(result.hashHits)")
}
print(rabinKarp(Array("aa".utf8), in: Array("aaaa".utf8), modulus: 1_000_000_007).matches)
```

```output
pattern: xauevr
modulus 101: matches [1234], hash hits 54
modulus 1000000007: matches [1234], hash hits 1
[0, 1, 2]
```

With M = 101, there are only 101 possible hash values, so about one window in a hundred hashes to the pattern's value by accident: 53 **false alarms** (spurious hits), each costing an m-character check. With M = 10⁹ + 7, the only hash hit is the real match. Both give the right answer, because both verify.

### What it costs

Hashing the pattern and the first window is O(m), and each of the n − m slides is O(1). Each verification costs O(m). Real matches have to be verified anyway (you're reporting them), and with a good modulus false alarms are rare, so the expected cost is **O(n + m)**, plus O(m) per match reported. The worst case is still O(n · m): if almost every window is a real match (a thousand `a`s searched for in a million `a`s), or if someone has engineered collisions.

That gives you a choice:

- **Verify every hit** and Rabin–Karp is always right, and usually fast. (An algorithm like this is called *Las Vegas*: the answer is guaranteed, the running time is a matter of chance.)
- **Trust the hash** and skip verification, and it's always O(n + m), but very occasionally wrong (*Monte Carlo*). With a large enough modulus, "occasionally" can be made rarer than a hardware fault, and many competitive programmers do exactly this. M67 comes back to these two kinds of randomised algorithm in more depth.

## How likely is a collision?

Two different strings collide when their hashes are equal mod M. If the base B is chosen **at random**, the chance is at most L / M for strings of length L: the difference of the two hashes is a polynomial in B of degree below L, and modulo a prime such a polynomial has fewer than L roots. For L = 100,000:

| Modulus | Chance one comparison collides |
| --- | --- |
| 10⁹ + 7 | about 1 in 10,000 |
| 2⁶¹ − 1 | about 1 in 23 trillion |

One in ten thousand per comparison is far too high if you're making a hundred thousand comparisons, and some problems (finding any two equal substrings among many, as in [Comparing substrings in O(1) with hashes](/dsa/learn/sa-substring-hashing)) compare every hash with every other, which is much worse. So for serious use, you want a modulus near 2⁶¹, or two hashes at once.

The randomness matters too. A fixed, well-known base lets someone build two strings that collide, the same attack as hash flooding in [Hashing pitfalls](/dsa/learn/hash-pitfalls). Pick the base at random when the program starts, for example `UInt64.random(in: 256..<mersenne)`, and nobody can plan a collision in advance. The examples in this module use a fixed base so their output is the same every run.

## A big modulus in Swift

M = 10⁹ + 7 is easy: both operands stay below 2³⁰, so every product fits in an `Int`, as you saw in M15. A modulus near 2⁶¹ is harder. Two values below 2⁶¹ multiply to something up to 2¹²², which no 64-bit integer holds, and Swift traps on overflow.

The standard choice is the **Mersenne prime** M = 2⁶¹ − 1, because reducing modulo it needs no division. Get the full 128-bit product with `multipliedFullWidth(by:)`, which returns it as two 64-bit halves. Then use the fact that 2⁶¹ ≡ 1 (mod 2⁶¹ − 1): split the product into its bits above position 61 and its lowest 61 bits, and add the two parts. That sum is congruent to the product and is below 2⁶², so one subtraction finishes the job.

```swift run
let mersenne: UInt64 = (1 << 61) - 1               // 2^61 − 1, a prime

// a × b mod 2^61 − 1, for a and b below the modulus, with no overflow
func mulMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    let (high, low) = a.multipliedFullWidth(by: b)  // the exact product is high · 2^64 + low
    let top = (high << 3) | (low >> 61)             // the product's bits from 61 up
    let bottom = low & mersenne                     // its lowest 61 bits
    let sum = top + bottom                          // 2^61 ≡ 1, so product ≡ top + bottom
    return sum >= mersenne ? sum - mersenne : sum
}

// The same answer the slow, obviously right way: a 128-bit division
func slowMulMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    mersenne.dividingFullWidth(a.multipliedFullWidth(by: b)).remainder
}

let values: [UInt64] = [0, 1, 2, 131, 1_000_000_007, mersenne - 2, mersenne - 1]
var agree = 0
for a in values {
    for b in values where mulMod(a, b) == slowMulMod(a, b) {
        agree += 1
    }
}
print("agree on \(agree) of \(values.count * values.count) pairs")
print(mulMod(mersenne - 1, mersenne - 1))           // (−1) × (−1) = 1
print(mulMod(123_456_789_012, 987_654_321_098))
```

```output
agree on 49 of 49 pairs
1
1958652374963740247
```

Why `(high << 3) | (low >> 61)`? The product is high · 2⁶⁴ + low, and 2⁶⁴ = 2⁶¹ · 2³, so the part above bit 61 is high · 8 plus the top 3 bits of low. The two pieces don't overlap, so `|` joins them. `dividingFullWidth` (from M15) gives the same answer but divides, which is much slower; it's here as the check.

Addition needs care too: two values below M add to less than 2⁶², so one conditional subtraction reduces them. Subtraction is the dangerous one in `UInt64`: `a - b` with `b > a` **traps**, it doesn't wrap. Write it as `a >= b ? a - b : a + mersenne - b`.

### Why not let UInt64 wrap around?

Swift's overflow operators `&*` and `&+`, from [Overflow traps and overflow operators](/dsa/learn/swift-overflow), never trap: they wrap around, which is arithmetic modulo 2⁶⁴. So `h = h &* base &+ c` is a polynomial hash mod 2⁶⁴, with no `%` at all, and it's very fast. It's tempting. Don't. 2⁶⁴ isn't prime, and there's a famous family of strings that defeats it for **every** odd base (and even bases are worse). The Thue–Morse string starts as `a` and repeatedly appends a copy of itself with `a` and `b` swapped: `a`, `ab`, `abba`, `abbabaab`, … At length 2048, the string and its swapped twin always collide mod 2⁶⁴:

```swift run
// Thue–Morse: start with "a", then repeatedly append a copy with a and b swapped
var first: [UInt8] = [97]
for _ in 0..<11 {
    first += first.map { $0 == 97 ? UInt8(98) : UInt8(97) }
}
let second: [UInt8] = first.map { $0 == 97 ? 98 : 97 }   // the same string with a and b swapped
print("length:", first.count, "equal strings:", first == second)

// Tempting: let UInt64 wrap around, which is arithmetic mod 2^64
func wrappingHash(_ s: [UInt8], base: UInt64) -> UInt64 {
    var h: UInt64 = 0
    for c in s { h = h &* base &+ UInt64(c) }
    return h
}

let mersenne: UInt64 = (1 << 61) - 1
func mulMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    let (high, low) = a.multipliedFullWidth(by: b)
    let sum = ((high << 3) | (low >> 61)) + (low & mersenne)
    return sum >= mersenne ? sum - mersenne : sum
}
func primeHash(_ s: [UInt8], base: UInt64) -> UInt64 {
    var h: UInt64 = 0
    for c in s {
        h = mulMod(h, base) + UInt64(c)
        if h >= mersenne { h -= mersenne }
    }
    return h
}

for base: UInt64 in [131, 1_000_003, 911_382_323] {
    print("base \(base): mod 2^64 equal:", wrappingHash(first, base: base) == wrappingHash(second, base: base),
          "mod 2^61 - 1 equal:", primeHash(first, base: base) == primeHash(second, base: base))
}
```

```output
length: 2048 equal strings: false
base 131: mod 2^64 equal: true mod 2^61 - 1 equal: false
base 1000003: mod 2^64 equal: true mod 2^61 - 1 equal: false
base 911382323: mod 2^64 equal: true mod 2^61 - 1 equal: false
```

Different strings, equal hashes, whatever the base. The reason, in brief: the difference between the two hashes factors into terms like B − 1, B² − 1, B⁴ − 1, … and for odd B each contributes more factors of 2, until the product is divisible by 2⁶⁴. Problem setters know this and put such strings in their tests. A prime modulus has no such weakness.

### Two hashes at once

The other classic fix is **double hashing**: keep two hashes with different moduli, say 10⁹ + 7 and 998,244,353, and treat the pair as the fingerprint. Each fits in `Int` arithmetic with no 128-bit tricks, and for random bases the collision chances multiply, to about 1 in 10¹⁸ per comparison for short strings. It costs twice the arithmetic.

```swift
// One step of a double hash: both parts in plain Int arithmetic
let (m1, m2) = (1_000_000_007, 998_244_353)
let (b1, b2) = (131, 137)
var pair = (0, 0)
for byte in "hello".utf8 {
    pair = ((pair.0 * b1 + Int(byte)) % m1, (pair.1 * b2 + Int(byte)) % m2)
}
```

Either approach is fine. This module uses 2⁶¹ − 1: one number per fingerprint is simpler to store in a `Set` or `Dictionary`.

## Many patterns at once

Here's where Rabin–Karp beats KMP. Given k patterns, all of length m, put their hashes in a dictionary, roll one window along the text, and look each window's hash up. That's **one pass**, O(n + k · m) expected, instead of k passes:

```swift run
let mersenne: UInt64 = (1 << 61) - 1
func mulMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    let (high, low) = a.multipliedFullWidth(by: b)
    let sum = ((high << 3) | (low >> 61)) + (low & mersenne)
    return sum >= mersenne ? sum - mersenne : sum
}
func addMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    let sum = a + b                                 // both below 2^61, so no overflow
    return sum >= mersenne ? sum - mersenne : sum
}
func subMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    a >= b ? a - b : a + mersenne - b               // never goes below zero, which would trap
}

let base: UInt64 = 1_000_003                        // real code: UInt64.random(in: 256..<mersenne)

func hash(_ s: ArraySlice<UInt8>) -> UInt64 {
    s.reduce(0) { addMod(mulMod($0, base), UInt64($1)) }
}

// Every occurrence of several patterns of the same length, in one pass over the text
func findAll(_ patterns: [String], in text: String) -> [String: [Int]] {
    let t = Array(text.utf8)
    let m = patterns[0].utf8.count
    var wanted: [UInt64: [String]] = [:]             // hash → the patterns with that hash
    for p in patterns { wanted[hash(ArraySlice(p.utf8)), default: []].append(p) }
    var found: [String: [Int]] = [:]
    guard m <= t.count else { return found }
    var high: UInt64 = 1                            // base^(m - 1)
    for _ in 1..<m { high = mulMod(high, base) }
    var h = hash(t[0..<m])
    for start in 0...(t.count - m) {
        if start > 0 {
            h = subMod(h, mulMod(UInt64(t[start - 1]), high))
            h = addMod(mulMod(h, base), UInt64(t[start + m - 1]))
        }
        for p in wanted[h] ?? [] where t[start..<(start + m)].elementsEqual(p.utf8) {
            found[p, default: []].append(start)
        }
    }
    return found
}

let text = "the cat and the dog saw an owl; the cat ran"
let found = findAll(["cat", "dog", "owl", "eel"], in: text)
for word in ["cat", "dog", "owl", "eel"] {
    print(word, found[word] ?? [])
}
```

```output
cat [4, 36]
dog [16]
owl [27]
eel []
```

The dictionary maps a hash to a *list* of patterns, so two patterns that happen to share a hash both get checked. The output is printed word by word in a fixed order, never by printing the dictionary itself, whose order changes between runs. For patterns of *different* lengths you'd need one rolling hash per length; [Aho–Corasick](/dsa/learn/sa-aho-corasick) handles any mix of lengths in one pass.

<Callout kind="gotcha" title="Swift gotchas in rolling hashes">
**`UInt64` subtraction traps.** `h - leaving * high` goes below zero whenever the leaving term is bigger, and unsigned arithmetic stops the program rather than wrapping. Add the modulus first: `a >= b ? a - b : a + mersenne - b`.

**`Int` overflow with a big modulus.** `h * base % modulus` is safe for 10⁹ + 7, not for 2⁶¹ − 1. Use `multipliedFullWidth` there.

**Forgetting to precompute B^(m−1).** Recomputing the leading place value at every slide makes each slide O(m) again, or O(log m) with fast power. Compute it once.

**A character worth 0.** If a character maps to 0, putting extra copies of it in front of a string doesn't change the hash, just as 042 and 42 are the same number. Bytes of text are never 0 in practice, but if you map letters to 0...25, add 1.

**Hashing `Character`s.** A `Character` isn't a number. Hash `Array(text.utf8)` bytes, or map each distinct `Character` to an integer id first.
</Callout>
