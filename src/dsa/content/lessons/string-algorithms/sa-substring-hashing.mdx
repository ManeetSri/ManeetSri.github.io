## Why it matters

Rabin–Karp rolled one hash along a text. A small step further gives a tool you'll use constantly in competitive programming: after O(n) preparation, the hash of **any** substring in O(1). That means "are these two slices equal?" in O(1), the longest common prefix of any two suffixes in O(log n), and with binary search on the answer, the longest repeated substring or the longest common substring of two strings in O(n log n), with a fraction of the code a suffix array needs. Version-control tools and deduplicating storage compare chunks by their fingerprints in the same spirit. The price is a tiny chance of being wrong, which this lesson measures rather than waves away.

## Prefix hashes and powers

Take the polynomial hash from [Rabin–Karp and rolling hashes](/dsa/learn/sa-rabin-karp), modulo M = 2⁶¹ − 1, and store it for **every prefix**:

> prefix[0] = 0, and prefix[i + 1] = prefix[i] · B + s[i] (mod M)

So prefix[i] is the hash of `s[0..<i]`. Store the powers of the base too: power[i] = Bⁱ.

Now look at the hash of `s[a..<b]`. Write prefix[b] out in full: it's s₀ · B^(b−1) + … + s_(b−1). The first a terms are exactly prefix[a], shifted up by b − a places, that is, multiplied by B^(b−a). Subtract them, and what's left is the hash of `s[a..<b]` on its own:

> hash(a, b) = prefix[b] − prefix[a] · power[b − a] (mod M)

It's the same picture as prefix sums from [1D prefix sums and range queries](/dsa/learn/prefix-1d), with one twist: a sum doesn't care where its terms are, but a polynomial hash does, so the earlier part has to be shifted to line up before subtracting. One multiplication and one subtraction: **O(1)** for any slice.

```swift run
let mersenne: UInt64 = (1 << 61) - 1
func mulMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    let (high, low) = a.multipliedFullWidth(by: b)
    let sum = ((high << 3) | (low >> 61)) + (low & mersenne)
    return sum >= mersenne ? sum - mersenne : sum
}

// Prefix hashes and powers: after O(n) preparation, the hash of any slice in O(1)
struct SubstringHashes {
    private var prefix: [UInt64]                    // prefix[i] = hash of s[0..<i]
    private var power: [UInt64]                     // power[i] = base^i
    init(_ s: [UInt8], base: UInt64) {
        prefix = [UInt64](repeating: 0, count: s.count + 1)
        power = [UInt64](repeating: 1, count: s.count + 1)
        for i in s.indices {
            let next = mulMod(prefix[i], base) + UInt64(s[i])
            prefix[i + 1] = next >= mersenne ? next - mersenne : next
            power[i + 1] = mulMod(power[i], base)
        }
    }

    // The hash of s[a..<b]: prefix[b] minus prefix[a] shifted up by b - a places
    func hash(_ a: Int, _ b: Int) -> UInt64 {
        let shifted = mulMod(prefix[a], power[b - a])
        return prefix[b] >= shifted ? prefix[b] - shifted : prefix[b] + mersenne - shifted
    }
}

let text = Array("abracadabra".utf8)
let hashes = SubstringHashes(text, base: 1_000_003)
print(hashes.hash(0, 4) == hashes.hash(7, 11))     // abra and abra
print(hashes.hash(0, 1) == hashes.hash(3, 4))      // a and a
print(hashes.hash(1, 4) == hashes.hash(8, 11))     // bra and bra
print(hashes.hash(0, 4) == hashes.hash(1, 5))      // abra and brac
let whole = SubstringHashes(Array("abra".utf8), base: 1_000_003)
print(whole.hash(0, 4) == hashes.hash(7, 11))      // the same text in another string, the same hash
```

```output
true
true
true
false
true
```

What to notice:

- The arrays have n + 1 entries, so `hash(a, b)` works for any `0 <= a <= b <= n`, including the empty slice (`a == b`), whose hash is 0.
- A slice's hash doesn't depend on where it sits, or even which string it's in, as long as both strings use the same base. The last line compares a slice of one string with the whole of another. That's what lets you compare substrings of two different texts.
- The subtraction is written to never go below zero, because `UInt64` subtraction traps rather than wrapping.

**Equal hashes mean equal slices, almost certainly.** Different hashes prove the slices differ. Equal hashes could, very rarely, be a collision. With a random base and M = 2⁶¹ − 1, the chance for two slices of length L is at most L / M, about 1 in 23 trillion for L = 100,000. When a wrong answer would be costly, verify an equal-hash result by comparing characters, or use two hashes.

## The longest common prefix in O(log n)

How many characters do the suffixes starting at i and j share? Comparing character by character is O(n). With O(1) slice equality, **binary search on the length**: if the first L characters agree, so do the first L − 1, and if they don't, nor do the first L + 1. That's a monotonic predicate, the setup from [The monotonic predicate idea](/dsa/learn/bsa-idea), so the longest length that agrees takes O(log n) hash comparisons.

And once you have the common prefix, comparing two suffixes in dictionary order is one more character comparison: skip what they share and look at the first difference. That's enough to sort all suffixes with any comparison sort, building a suffix array in O(n log² n) with nothing but hashes:

```swift run
let mersenne: UInt64 = (1 << 61) - 1
func mulMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    let (high, low) = a.multipliedFullWidth(by: b)
    let sum = ((high << 3) | (low >> 61)) + (low & mersenne)
    return sum >= mersenne ? sum - mersenne : sum
}

struct SubstringHashes {
    private var prefix: [UInt64], power: [UInt64]
    init(_ s: [UInt8], base: UInt64) {
        prefix = [UInt64](repeating: 0, count: s.count + 1)
        power = [UInt64](repeating: 1, count: s.count + 1)
        for i in s.indices {
            let next = mulMod(prefix[i], base) + UInt64(s[i])
            prefix[i + 1] = next >= mersenne ? next - mersenne : next
            power[i + 1] = mulMod(power[i], base)
        }
    }
    func hash(_ a: Int, _ b: Int) -> UInt64 {
        let shifted = mulMod(prefix[a], power[b - a])
        return prefix[b] >= shifted ? prefix[b] - shifted : prefix[b] + mersenne - shifted
    }
}

let text = Array("mississippi".utf8)
let hashes = SubstringHashes(text, base: 1_000_003)

// The longest common prefix of the suffixes at i and j, by binary search on its length
func lcp(_ i: Int, _ j: Int) -> Int {
    var low = 0, high = text.count - max(i, j)     // the answer is in low...high
    while low < high {
        let mid = (low + high + 1) / 2
        if hashes.hash(i, i + mid) == hashes.hash(j, j + mid) {
            low = mid                               // the first mid characters agree
        } else {
            high = mid - 1
        }
    }
    return low
}

// Compare two suffixes: skip their common prefix, then look at one character
func suffixPrecedes(_ i: Int, _ j: Int) -> Bool {
    let common = lcp(i, j)
    if i + common == text.count { return j + common < text.count }   // i ran out first
    if j + common == text.count { return false }
    return text[i + common] < text[j + common]
}

print(lcp(1, 4), lcp(2, 5), lcp(0, 1))             // issi…/issi…, ssi…/ssi…, m…/i…
let sa = text.indices.sorted(by: suffixPrecedes)
print(sa)
print(sa == text.indices.sorted { text[$0...].lexicographicallyPrecedes(text[$1...]) })
```

```output
4 3 0
[10, 7, 4, 1, 0, 9, 8, 6, 3, 5, 2]
true
```

The binary search uses the "upper middle" `(low + high + 1) / 2`, because the true branch sets `low = mid`; with the lower middle, `low = mid` could leave the range unchanged and loop forever. The same comparison works between substrings of two *different* strings, if both are hashed with the same base.

## Binary search on the answer, with a set of hashes

Many "longest substring such that…" questions have a monotonic shape. The **longest repeated substring** is one: if some substring of length L occurs twice, its first L − 1 characters occur twice too. So binary search on L, and test a length by hashing every window of that length into a `Set`, looking for a hash seen before. Each test is O(n), so the whole search is **O(n log n)**:

```swift run
let mersenne: UInt64 = (1 << 61) - 1
func mulMod(_ a: UInt64, _ b: UInt64) -> UInt64 {
    let (high, low) = a.multipliedFullWidth(by: b)
    let sum = ((high << 3) | (low >> 61)) + (low & mersenne)
    return sum >= mersenne ? sum - mersenne : sum
}

struct SubstringHashes {
    private var prefix: [UInt64], power: [UInt64]
    init(_ s: [UInt8], base: UInt64) {
        prefix = [UInt64](repeating: 0, count: s.count + 1)
        power = [UInt64](repeating: 1, count: s.count + 1)
        for i in s.indices {
            let next = mulMod(prefix[i], base) + UInt64(s[i])
            prefix[i + 1] = next >= mersenne ? next - mersenne : next
            power[i + 1] = mulMod(power[i], base)
        }
    }
    func hash(_ a: Int, _ b: Int) -> UInt64 {
        let shifted = mulMod(prefix[a], power[b - a])
        return prefix[b] >= shifted ? prefix[b] - shifted : prefix[b] + mersenne - shifted
    }
}

// Where does some substring of this length occur twice? nil if none does.
func repeatStart(_ length: Int, _ text: [UInt8], _ hashes: SubstringHashes) -> Int? {
    var seen = Set<UInt64>()
    for start in 0...(text.count - length) {
        if !seen.insert(hashes.hash(start, start + length)).inserted {
            return start
        }
    }
    return nil
}

// If some length repeats, every shorter length does too, so binary search for the longest
func longestRepeat(_ word: String) -> String {
    let text = Array(word.utf8)
    let hashes = SubstringHashes(text, base: 1_000_003)
    var low = 0, high = text.count - 1                  // the answer is in low...high
    while low < high {
        let mid = (low + high + 1) / 2
        if repeatStart(mid, text, hashes) != nil { low = mid } else { high = mid - 1 }
    }
    guard low > 0, let start = repeatStart(low, text, hashes) else { return "" }
    return String(decoding: text[start..<(start + low)], as: UTF8.self)
}

for word in ["banana", "abracadabra", "mississippi", "abcd", "aaaa"] {
    print(word, "\"\(longestRepeat(word))\"")
}
```

```output
banana "ana"
abracadabra "abra"
mississippi "issi"
abcd ""
aaaa "aaa"
```

The same pattern solves the **longest common substring of two strings**: for a length L, put the hashes of all of the first string's windows of length L in a set, then check the second string's windows against it. Both strings must be hashed with the same base. That's O((n + m) log(min(n, m))), against O(n · m) for the dynamic programming of [Longest common substring](/dsa/learn/dps-common-substring), and it's the idea behind one of this lesson's problems.

## Many hashes in one set: the birthday problem

Comparing two particular slices is very safe. Putting a hundred thousand hashes in a set and asking whether *any two* are equal is a different question, and much riskier. With k values spread over M possible hashes, the expected number of colliding pairs is about k² / (2M): the **birthday problem**, the reason that 23 people are enough for a better-than-even chance of two sharing a birthday. For k = 100,000 and M = 10⁹ + 7, that's about 5 collisions. You can watch it happen:

```swift run
// 100,000 windows of 20 random letters: almost all different. How many hash values do they get?
var seed = 54
var text: [Int] = []
for _ in 0..<100_019 {
    seed = (seed * 1_103_515_245 + 12_345) % 2_147_483_648
    text.append(97 + (seed >> 16) % 26)
}
let length = 20, base = 131

func windowHashes(modulus: Int) -> Set<Int> {
    var high = 1
    for _ in 1..<length { high = high * base % modulus }
    var h = 0
    for k in 0..<length { h = (h * base + text[k]) % modulus }
    var hashes: Set<Int> = [h]
    for start in 1...(text.count - length) {
        h = (h - text[start - 1] * high % modulus + modulus) % modulus
        h = (h * base + text[start + length - 1]) % modulus
        hashes.insert(h)
    }
    return hashes
}

var windows = Set<ArraySlice<Int>>()
for start in 0...(text.count - length) { windows.insert(text[start..<(start + length)]) }
print("different windows:", windows.count)
print("different hashes mod 1,000,000,007:", windowHashes(modulus: 1_000_000_007).count)
print("different hashes mod 2,147,483,647:", windowHashes(modulus: 2_147_483_647).count)
```

```output
different windows: 100000
different hashes mod 1,000,000,007: 99996
different hashes mod 2,147,483,647: 99999
```

A hundred thousand different windows, but only 99,996 different hashes modulo 10⁹ + 7: four times, two different windows shared a hash. In the longest-repeat search above, any one of those would be reported as a repeat that isn't there. With M = 2⁶¹ − 1, the expected number of collisions among 10⁵ values is about 2 × 10⁻⁹: this is exactly why this module uses a 61-bit modulus. If you must use a small modulus, use two of them, or verify each "found" answer by comparing characters, which is cheap when it happens once.

## The toolkit, and when to use it

| Question | With prefix hashes | Cost |
| --- | --- | --- |
| Is `s[a..<b]` equal to `t[c..<d]`? | compare two hashes | O(1) |
| Longest common prefix of two suffixes | binary search on the length | O(log n) |
| Compare two substrings in dictionary order | common prefix, then one character | O(log n) |
| Is `s[a..<b]` a palindrome? | compare with the hash of the reversed string's matching slice | O(1) |
| Longest repeated substring | binary search on the length, set of hashes | O(n log n) |
| Longest common substring of two strings | the same, across two strings | O((n + m) log n) |

Hashing is usually the fastest to write and the most flexible: it works on any pair of slices, from any strings. Suffix arrays and automata are exact, never wrong, and can be faster when one structure answers many questions. In a contest or an interview with tight time, hashing with a 61-bit modulus is a very good default.

<Callout kind="gotcha" title="Common substring-hashing mistakes">
**Off-by-one in the prefix array.** prefix has n + 1 entries, and `hash(a, b)` covers `a..<b`. Mixing in closed ranges, `a...b`, shifts everything by one and gives hashes that never match.

**Forgetting to shift before subtracting.** `prefix[b] - prefix[a]` is a prefix-sum habit. For a polynomial hash, the earlier part must be multiplied by `power[b - a]` first.

**Different bases for two strings.** Slices of two strings compare correctly only if both were hashed with the same base and modulus. Pick the base once and pass it to both.

**Trusting a small modulus with a set.** One comparison mod 10⁹ + 7 is fairly safe; a hundred thousand hashes in one set will collide. Use 2⁶¹ − 1 or two moduli.

**`UInt64` subtraction.** `prefix[b] - shifted` traps when `shifted` is larger. Add the modulus first.
</Callout>
