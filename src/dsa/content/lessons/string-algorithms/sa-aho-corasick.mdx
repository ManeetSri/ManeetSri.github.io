## Why it matters

KMP finds one pattern in O(n + m). But a chat filter has a list of thousands of banned words, an antivirus scanner has hundreds of thousands of virus signatures, and `grep -F -f words.txt` searches for every line of a file at once. Running KMP once per pattern costs O(k · n) for k patterns, and Rabin–Karp only helps when the patterns all have the same length. The **Aho–Corasick** algorithm finds every occurrence of every pattern in **one pass** over the text, in O(n + total pattern length + number of matches). It's a trie of the patterns, from [Build a Trie](/dsa/learn/trie-build), with KMP's fallback idea added to every node.

## A trie that knows where to fall back

Start with an ordinary trie of the patterns. Here's the classic example, with the patterns `he`, `she`, `his` and `hers`:

```visual trie
words: [he, she, his, hers]
prefix: he
```

Walking the trie letter by letter along the text works until a letter has no child. Reading `shers`, you'd go s → sh → she, and then there's no `r` below `she`. Starting again from the root at the next text position would re-read text, which is exactly what made naive matching slow.

KMP's answer was: fall back to the longest border, the longest proper suffix of what you've matched that's also a prefix of the pattern. Aho–Corasick does the same, except "a prefix of the pattern" becomes "a node of the trie", a prefix of *some* pattern:

> The **failure link** of node v points to the node for the longest proper suffix of v's string that is also in the trie (the root if there's none).

For `she`, the proper suffixes are `he` and `e`. `he` is in the trie, so `she`'s failure link points at `he`. After reading `she`, if the next letter is `r`, you continue from `he`, and `her` exists: that's how `hers` is found inside `shers`. Here are all the links for the four patterns:

| Node | Failure link | Why |
| --- | --- | --- |
| h, s, he, hi, her | root | none of their proper suffixes start a pattern |
| sh | h | `h` is a suffix of `sh` and a node |
| his | s | `s` is a suffix of `his` and a node |
| she | he | `he` is a suffix of `she` and a node |
| hers | s | `rs` isn't a node, but `s` is |

## Building the links with BFS

A node's failure link always points to a **shallower** node, because it's a proper suffix. So if you compute links in order of depth, the link you need is always ready. That's breadth-first search, as in [BFS and unweighted shortest paths](/dsa/learn/gt-bfs): the root's children link to the root, and then, for each node v taken from the queue and each child u reached by letter c:

> link[u] = the node reached from link[v] by c.

The longest suffix of v's string that's in the trie is link[v]; extend it by c, and if that child doesn't exist, fall further back along links until it does or you reach the root. KMP's `while` loop, in a trie.

There's a neat way to avoid that inner loop. When v has **no** child for c, fill the hole: set `next[v][c]` to wherever `next[link[v]][c]` goes. Since link[v] is shallower, its row is already complete when v is processed. After the BFS, `next` is a complete table, an **automaton**: from any node, any letter leads somewhere in one step, and both building and matching are free of fallback loops.

When the scan is at a node, the patterns that end at the current text position are the ones ending at that node **and at every node down its failure chain**. At `she`, the patterns `she` and `he` both end. So each node also gets an **output link**: the nearest node down its failure chain where some pattern ends. Following output links visits only nodes that report something.

```swift run
// Aho–Corasick for lowercase patterns: a trie, failure links by BFS, and a complete transition table
struct Automaton {
    var next: [[Int]] = [[Int](repeating: -1, count: 26)]   // next[node][letter]
    var link: [Int] = []                                     // failure links
    var ends: [[Int]] = [[]]                                 // patterns that end exactly at each node
    var name: [String] = [""]                                // the string each node spells (for printing)
    var order: [Int] = []                                    // nodes in BFS order, root excluded

    init(_ patterns: [String]) {
        for (index, word) in patterns.enumerated() {         // 1. an ordinary trie of the patterns
            var node = 0
            for byte in word.utf8 {
                let c = Int(byte - 97)
                if next[node][c] == -1 {
                    next[node][c] = next.count
                    next.append([Int](repeating: -1, count: 26))
                    ends.append([])
                    name.append(name[node] + String(UnicodeScalar(byte)))
                }
                node = next[node][c]
            }
            ends[node].append(index)
        }
        link = [Int](repeating: 0, count: next.count)
        for c in 0..<26 {                                    // 2. BFS, starting from the root's children
            if next[0][c] == -1 {
                next[0][c] = 0                               // a missing letter at the root stays at the root
            } else {
                order.append(next[0][c])                     // depth-1 nodes link to the root
            }
        }
        var head = 0
        while head < order.count {
            let v = order[head]
            head += 1
            for c in 0..<26 {
                let child = next[v][c]
                if child != -1 {
                    link[child] = next[link[v]][c]           // v's longest suffix in the trie, plus c
                    order.append(child)
                } else {
                    next[v][c] = next[link[v]][c]            // no child: go where the failure link goes
                }
            }
        }
    }
}

let patterns = ["he", "she", "his", "hers"]
let automaton = Automaton(patterns)
for v in automaton.order {
    let target = automaton.link[v]
    print(automaton.name[v], "->", target == 0 ? "(root)" : automaton.name[target])
}

// Output links: the nearest node down the failure chain where some pattern ends
var outputLink = [Int](repeating: 0, count: automaton.next.count)
for v in automaton.order {
    let target = automaton.link[v]
    outputLink[v] = automaton.ends[target].isEmpty ? outputLink[target] : target
}

let text = Array("ahishers".utf8)
var node = 0
for (i, byte) in text.enumerated() {
    node = automaton.next[node][Int(byte - 97)]          // one table lookup per character
    var v = automaton.ends[node].isEmpty ? outputLink[node] : node
    while v != 0 {                                       // every pattern ending here
        for index in automaton.ends[v] {
            print("\(patterns[index]) at \(i - patterns[index].count + 1)")
        }
        v = outputLink[v]
    }
}

// Counting each pattern without walking output links: count visits, then push counts up the links
func counts(in text: String) -> [Int] {
    var visits = [Int](repeating: 0, count: automaton.next.count)
    var node = 0
    for byte in text.utf8 {
        node = automaton.next[node][Int(byte - 97)]
        visits[node] += 1
    }
    for v in automaton.order.reversed() {                // deepest first, so each total is complete
        visits[automaton.link[v]] += visits[v]           // reaching v also means reaching its suffix
    }
    var result = [Int](repeating: 0, count: patterns.count)
    for v in automaton.order {
        for index in automaton.ends[v] { result[index] = visits[v] }
    }
    return result
}
print(patterns, counts(in: "ahishers"), counts(in: "shehershishe"))
```

| i | Letter | Node after | Reports |
| --- | --- | --- | --- |
| 0 | a | root | |

## Counting without walking the chains

Output links make reporting cheap when matches are few. But some questions ask how many times each pattern occurs, and then the number of matches can explode. With the patterns `a`, `aa`, `aaa`, …, up to 300 `a`s and a text of 100,000 `a`s, almost every position ends 300 patterns: 30 million matches to walk through.

The last function above counts without walking anything. Every time the scan *visits* a node, the pattern ending there occurs once, and so does every pattern down its failure chain. So count visits per node, then push each node's count onto its failure link, deepest nodes first (reverse BFS order), so that every count is complete before it's passed on. Afterwards, a node's total is the number of times its string occurred in the text. The failure links form a tree rooted at the root (every node has exactly one link, pointing shallower), and this is a sum over that **failure tree**. It's O(n + number of nodes), however many matches there are.

## What it costs

| Step | Time |
| --- | --- |
| Building the trie | O(L), for total pattern length L |
| BFS and the completed table | O(L · σ), for an alphabet of σ letters |
| Scanning the text | O(n), one table lookup per character |
| Reporting every match through output links | O(number of matches) |
| Counting every pattern with the failure tree | O(L) after the scan |

With a 26-letter alphabet, the table is 26 integers per node. For a large alphabet, such as all of Unicode, store children in dictionaries and use the fallback `while` loop at scan time instead of completing the table: the scan is still O(n) amortised, by KMP's argument.

<Callout kind="gotcha" title="Common Aho–Corasick mistakes">
**Computing links in DFS order.** A node's link comes from its parent's link, which must already be finished. Depth-first order can visit a deep node before the shallower node its link depends on. Use BFS.

**Linking the root's children to themselves.** A depth-1 node's only proper suffix is the empty string, so its link is the root. The general rule would give `next[0][c]`, the node itself, so handle depth 1 first.

**Reporting only the patterns at the current node.** At `she`, the pattern `he` ends too, but it ends at a different node. Follow the output links, or sum over the failure tree.

**Duplicate patterns.** The same word given twice ends at the same node. Store a list of pattern indexes per node, as `ends` does, not a single index.
</Callout>
