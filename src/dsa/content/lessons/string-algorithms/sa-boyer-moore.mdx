## Why it matters

KMP's guarantee is that it walks through the text once, never going back. **Boyer–Moore** does something that sounds impossible: on ordinary text it reads only a *fraction* of the characters, skipping over most of the text without looking at it. The longer the pattern, the bigger the skips. That's why variants of it sit inside GNU `grep` and many text editors' find commands, and C++ ships it in its standard library as `std::boyer_moore_searcher`. This deep dive builds the part that does the skipping, the **bad-character rule**, measures how much it skips, and shows the input that defeats it.

## Compare from the right

Line the pattern up under the text as usual, but compare its characters **from the right end to the left**. The interesting moment is a mismatch. Say the text character under the pattern's position j doesn't match `pattern[j]`. Call it the **bad character**. Any alignment that could succeed must put a *matching* character of the pattern under it. So:

- **If the bad character doesn't occur in the pattern at all**, no alignment that covers it can work. Shift the pattern completely past it.
- **If it does occur**, shift so that its **last occurrence** in the pattern lines up under it. That's the smallest shift that puts a matching character under the bad one: any smaller shift leaves a different pattern character there, which can't match, and lining up an earlier occurrence would shift further and could jump over a real match.

Here's the pattern `example` searched for in `here is a simple example` (spaces shown as `_`):

```text
text      h e r e _ i s _ a _ s i m p l e _ e x a m p l e
s = 0     e x a m p l e                                       s isn't in the pattern: shift 7
s = 7                   e x a m p l e                         p is: shift 2 to line it up
s = 9                       e x a m p l e                     i isn't: shift past it, 3
s = 12                            e x a m p l e               x is: shift 5 to line it up
s = 17                                      e x a m p l e     match
```

At s = 0, the very first comparison is the pattern's `e` against the text's `s`, and `s` isn't anywhere in `example`, so seven alignments are ruled out at once without reading the six text characters before it. At s = 9, four characters match from the right (`mple`), then `i` fails against `a`; `i` isn't in the pattern either, so the pattern jumps past it. Five alignments are tried in all, out of 18 possible, and 11 of the 24 text characters are never read at all.

## The last-occurrence table

The rule needs, for every character c, the index of its last occurrence in the pattern, or −1 if it doesn't occur. For bytes that's a 256-entry array, filled in one pass over the pattern, so later occurrences overwrite earlier ones.

If the mismatch is at pattern position j and the bad character's last occurrence is at k, the shift that lines them up is j − k. That can be zero or negative, when the last occurrence is to the *right* of j (it's somewhere in the part that already matched). Then the rule has nothing useful to say, so shift by 1. Hence `max(1, j - last[bad])`.

```swift run
// Boyer–Moore with the bad-character rule: compare right to left, and skip on a mismatch
func boyerMoore(_ pattern: [UInt8], in text: [UInt8], trace: Bool = false) -> [Int] {
    let m = pattern.count, n = text.count
    guard m > 0, m <= n else { return [] }
    var last = [Int](repeating: -1, count: 256)         // last[c]: where byte c last occurs in the pattern
    for (k, c) in pattern.enumerated() {
        last[Int(c)] = k
    }
    var result: [Int] = []
    var s = 0                                           // the pattern's first character is under text[s]
    while s <= n - m {
        var j = m - 1
        while j >= 0 && pattern[j] == text[s + j] {
            j -= 1                                      // right to left
        }
        if j < 0 {
            result.append(s)
            s += s + m < n ? m - last[Int(text[s + m])] : 1     // line up the next text character
        } else {
            let bad = text[s + j]
            let shift = max(1, j - last[Int(bad)])      // line up the bad character's last occurrence
            if trace {
                print("s = \(s): mismatch at j = \(j) on '\(Character(UnicodeScalar(bad)))', shift \(shift)")
            }
            s += shift
        }
    }
    return result
}

let text = Array("here is a simple example".utf8)
print(boyerMoore(Array("example".utf8), in: text, trace: true))
print(boyerMoore(Array("aa".utf8), in: Array("aaaa".utf8)), boyerMoore(Array("abra".utf8), in: Array("abracadabra".utf8)))
```

```output
s = 0: mismatch at j = 6 on 's', shift 7
s = 7: mismatch at j = 6 on 'p', shift 2
s = 9: mismatch at j = 2 on 'i', shift 3
s = 12: mismatch at j = 6 on 'x', shift 5
[17]
[0, 1, 2] [0, 7]
```

After a full match, the code looks at the text character just past the pattern, `text[s + m]`: the next alignment that can succeed must put a matching pattern character under it, so it shifts by m minus that character's last occurrence. That's at least 1, so overlapping matches like `aa` in `aaaa` are still found.

## Why it's sublinear in practice

Each mismatch on the first comparison, with a character that's absent from the pattern, skips m positions after reading **one** character. On natural-language text with a pattern of a dozen letters, most text characters aren't in the pattern, or occur only near its start, so most shifts are long. The expected number of comparisons is roughly n / m: the longer the pattern, the faster the search. That's the opposite of naive matching, where longer patterns can only make things slower.

Counting comparisons on English text, against naive matching and KMP:

```swift run
// Character comparisons for naive matching, KMP and Boyer–Moore's bad-character rule: counted, not timed
func naive(_ p: [UInt8], _ t: [UInt8]) -> Int {
    var count = 0
    for s in 0...(t.count - p.count) {
        for k in p.indices {
            count += 1
            if t[s + k] != p[k] { break }
        }
    }
    return count
}

func kmp(_ p: [UInt8], _ t: [UInt8]) -> Int {
    var pi = [Int](repeating: 0, count: p.count)
    var k = 0
    for i in p.indices.dropFirst() {
        while k > 0 && p[i] != p[k] { k = pi[k - 1] }
        if p[i] == p[k] { k += 1 }
        pi[i] = k
    }
    var count = 0, j = 0
    for c in t {
        while j > 0 && c != p[j] { count += 1; j = pi[j - 1] }
        count += 1
        if c == p[j] { j += 1 }
        if j == p.count { j = pi[j - 1] }
    }
    return count
}

func badCharacter(_ p: [UInt8], _ t: [UInt8]) -> Int {
    let m = p.count, n = t.count
    var last = [Int](repeating: -1, count: 256)
    for (k, c) in p.enumerated() { last[Int(c)] = k }
    var count = 0, s = 0
    while s <= n - m {
        var j = m - 1
        while j >= 0 {
            count += 1
            if p[j] != t[s + j] { break }
            j -= 1
        }
        if j < 0 {
            s += s + m < n ? m - last[Int(t[s + m])] : 1
        } else {
            s += max(1, j - last[Int(t[s + j])])
        }
    }
    return count
}

let text = Array(String(repeating: "the quick brown fox jumps over the lazy dog ", count: 230).utf8)
print("n =", text.count)
for word in ["lazy", "lazy cat", "the lazy brown cat", "a fox that jumps over cats"] {
    let p = Array(word.utf8)
    print("\"\(word)\": naive \(naive(p, text)), KMP \(kmp(p, text)), Boyer–Moore \(badCharacter(p, text))")
}
let aaa = Array(String(repeating: "a", count: 10_000).utf8)
let bad = Array(("b" + String(repeating: "a", count: 99)).utf8)
print("a's with \"baaa…a\": naive \(naive(bad, aaa)), KMP \(kmp(bad, aaa)), Boyer–Moore \(badCharacter(bad, aaa))")
```

```output
n = 10120
"lazy": naive 10807, KMP 10120, Boyer–Moore 3220
"lazy cat": naive 11263, KMP 10350, Boyer–Moore 1382
"the lazy brown cat": naive 13084, KMP 10580, Boyer–Moore 804
"a fox that jumps over cats": naive 10324, KMP 10350, Boyer–Moore 691
a's with "baaa…a": naive 9901, KMP 10000, Boyer–Moore 990100
```

What to notice:

- Naive matching and KMP both make about n comparisons on English, whatever the pattern. Boyer–Moore makes fewer as the pattern grows: from about n / 3 with a 4-letter pattern to about n / 15 with a 26-letter one.
- The last line is the catch. On a text of `a`s with the pattern `b` followed by 99 `a`s, comparing from the right matches 99 characters at every alignment before failing on the `b`, and then the bad character `a` occurs at the pattern's last position, so the rule allows a shift of only 1. That's **O(n · m)**: a hundred times more than naive matching, which fails on its very first comparison here.

## The good-suffix rule, and full Boyer–Moore

The full Boyer–Moore algorithm adds a second rule. When a mismatch happens after some characters have matched from the right, that matched part, the **good suffix**, is known text. The good-suffix rule shifts the pattern to the next place where that suffix occurs again in the pattern (preceded by a different character), or where a prefix of the pattern matches the end of it. Its table is computed from the pattern in O(m), using borders, the same idea as KMP's prefix function.

On each mismatch, the algorithm shifts by the **larger** of the two rules' suggestions. In the example above, the good suffix of 99 `a`s, preceded by a `b` in the pattern, occurs nowhere else, so the good-suffix rule shifts by m at once. With both rules (and a refinement called the Galil rule, which avoids re-checking a known match), Boyer–Moore is **O(n + m)** in the worst case and still sublinear on typical text. The good-suffix table is fiddly to get right, which is why many practical implementations use a simplification instead.

### Horspool's simplification

**Boyer–Moore–Horspool** drops the good-suffix rule and simplifies the bad-character rule: whatever happened, shift according to the text character under the pattern's **last** position. Its table stores, for each character, the distance from its last occurrence in `pattern[0..<(m - 1)]` to the end, or m if it doesn't occur there:

```swift
var shift = [Int](repeating: m, count: 256)
for k in 0..<(m - 1) {
    shift[Int(pattern[k])] = m - 1 - k          // later occurrences overwrite earlier ones
}
// After comparing the alignment at s, whether it matched or not:
s += shift[Int(text[s + m - 1])]
```

The shift is always at least 1, so there's no `max`, no special case after a match, and the inner loop can compare in any order. It has the same O(n · m) worst case and similar speed in practice, and it's a dozen lines.

## When to use which

| | KMP | Boyer–Moore (bad character) | Full Boyer–Moore |
| --- | --- | --- | --- |
| Worst case | O(n + m) | O(n · m) | O(n + m) |
| Typical text, long pattern | about n comparisons | about n / m | about n / m |
| Reads the text | one pass, left to right | skips most of it | skips most of it |
| Works on a stream | yes | no: it needs to look ahead | no |
| Complexity to write | short | short | long and fiddly |

For an interview or a contest, KMP or the Z-algorithm is the safe choice: linear in every case, and short. Boyer–Moore earns its place in tools that search large, ordinary texts for user-typed patterns, where the typical case is what matters and the input isn't adversarial.

<Callout kind="gotcha" title="Common Boyer–Moore mistakes">
**Shifting by `j - last[bad]` without the `max`.** When the bad character's last occurrence is to the right of j, that's zero or negative: the pattern stands still or moves backwards, and the loop never ends.

**Using the first occurrence instead of the last.** Lining up the first occurrence can shift too far and skip a real match. The table must hold the *rightmost* index, so fill it left to right and let later occurrences overwrite.

**Including the last character in Horspool's table.** If `pattern[m - 1]` sets its own entry, its shift becomes 0 and the search stalls. Horspool's loop runs to `m - 2`.

**A 256-entry table for Characters.** The table is indexed by byte. For `[Character]`, use a dictionary from `Character` to its last index, with a default of −1.
</Callout>
