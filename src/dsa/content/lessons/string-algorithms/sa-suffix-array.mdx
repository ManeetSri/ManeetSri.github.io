## Why it matters

[Radix trees and suffix tries](/dsa/learn/trie-radix) showed that every substring of a text is a prefix of one of its suffixes, and that putting all the suffixes in a trie answers substring questions instantly, at the cost of O(n²) nodes. The **suffix array** keeps the power and drops the cost: it's nothing more than the starting positions of the suffixes, **sorted**. One array of n integers, built in O(n log n), and with its companion, the **LCP array**, it counts distinct substrings, finds the longest repeated substring, finds the longest common substring of two strings, and searches for any pattern by binary search. Genome tools index whole chromosomes this way, the Burrows–Wheeler transform behind `bzip2` is read straight off a suffix array, and full-text search engines use it when they need every occurrence of every phrase.

## Sorting the suffixes

The suffixes of `banana` are `banana`, `anana`, `nana`, `ana`, `na` and `a`, starting at positions 0 to 5. Sort them alphabetically and write down where each one starts:

| Sorted position p | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| Suffix | a | ana | anana | banana | na | nana |
| Starts at, sa[p] | 5 | 3 | 1 | 0 | 4 | 2 |

The suffix array is the bottom row: `[5, 3, 1, 0, 4, 2]`. Shorter suffixes sort before longer ones they're a prefix of (`a` before `ana`), as in a dictionary.

The direct way to build it is to sort the positions, comparing the suffixes they start. Swift's `lexicographicallyPrecedes(_:)` compares two sequences in dictionary order, and `text[i...]` is an `ArraySlice` that shares the array's storage, so no suffix is copied:

```swift run
// The suffix array the obvious way: sort the starting positions by the suffixes they start
let text = Array("banana".utf8)
let sa = text.indices.sorted { text[$0...].lexicographicallyPrecedes(text[$1...]) }
print(sa)
for start in sa {
    print(start, String(decoding: text[start...], as: UTF8.self))
}
```

```output
[5, 3, 1, 0, 4, 2]
5 a
3 ana
1 anana
0 banana
4 na
2 nana
```

That's fine for short texts, but each comparison can read O(n) characters, so the sort is O(n² log n) in the worst case. On 100,000 copies of `a`, every pair of suffixes agrees for as long as the shorter one lasts, and the sort makes about 1.7 million comparisons averaging tens of thousands of characters each. You need something smarter.

## Prefix doubling

The idea: sort the suffixes by their first character, then by their first 2 characters, then 4, then 8, and so on, each round using the previous round's work. After about log₂ n rounds you're comparing more characters than any suffix has, so they're fully sorted.

What makes each round cheap is a **rank**: after sorting by the first k characters, give every suffix a number such that two suffixes get the same rank exactly when their first k characters are equal, and a smaller rank when they come first. Now look at the first 2k characters of the suffix starting at i. They're its first k characters followed by the first k characters of the suffix starting at **i + k**. So comparing the first 2k characters of two suffixes is comparing a **pair of ranks**:

> key(i) = (rank[i], rank[i + k]), with −1 for the second part when i + k runs off the end.

The −1 makes a suffix that ends early sort first, exactly as `a` sorts before `ana`. Comparing two pairs is O(1), so each round is one sort with O(1) comparisons. For `banana`:

| Suffix starts at | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| First 2 characters | ba | an | na | an | na | a |
| Rank | 2 | 1 | 3 | 1 | 3 | 0 |
| First 4 characters | bana | anan | nana | ana | na | a |
| Pair used (rank[i], rank[i + 2]) | (2, 3) | (1, 1) | (3, 3) | (1, 0) | (3, −1) | (0, −1) |
| Rank | 3 | 2 | 5 | 1 | 4 | 0 |

After the round with 4 characters, every rank is different, so the order is final, and the algorithm stops early. Notice how `ana` (start 3) and `anan` (start 1) were tied at rank 1 after two characters, and the pair broke the tie: the suffix two places later was `a` (rank 0) for one and `an` (rank 1) for the other.

```swift run
// Prefix doubling: sort by the first 1, 2, 4, 8, … characters, using the ranks from the round before
func suffixArray(_ s: [UInt8], trace: Bool = false) -> [Int] {
    let n = s.count
    guard n > 1 else { return Array(0..<n) }
    var sa = Array(0..<n)
    var rank = s.map { Int($0) }                // round 0: rank by the first character
    var newRank = [Int](repeating: 0, count: n)
    var k = 1
    while true {
        // Each suffix's first 2k characters = its first k, then the first k of the suffix k later
        func key(_ i: Int) -> (Int, Int) { (rank[i], i + k < n ? rank[i + k] : -1) }
        sa.sort { key($0) < key($1) }
        newRank[sa[0]] = 0
        for p in 1..<n {
            newRank[sa[p]] = newRank[sa[p - 1]] + (key(sa[p - 1]) < key(sa[p]) ? 1 : 0)
        }
        rank = newRank
        if trace { print("first \(2 * k) characters, ranks:", rank) }
        if rank[sa[n - 1]] == n - 1 { break }   // every rank different: fully sorted
        k *= 2
    }
    return sa
}

print(suffixArray(Array("banana".utf8), trace: true))
```

```output
first 2 characters, ranks: [2, 1, 3, 1, 3, 0]
first 4 characters, ranks: [3, 2, 5, 1, 4, 0]
[5, 3, 1, 0, 4, 2]
```

What to notice:

- The first round uses the bytes themselves as ranks. They don't need to be 0, 1, 2, …; they only need to be in the right order.
- New ranks come from walking the freshly sorted array: same key as the suffix before means same rank, a bigger key means the next rank. Swift compares tuples element by element with `<`, which is exactly the order wanted.
- The loop stops as soon as the largest rank is n − 1, which means all n ranks are different.

There are at most about log₂ n rounds, each an O(n log n) sort, so this is **O(n log² n)**. For n = 100,000 that's about 30 million key comparisons: perfectly fine, and the version most people write in a contest.

### From O(n log² n) to O(n log n)

The keys in each round are pairs of ranks, and ranks are small integers below n. That's the situation [Radix sort](/dsa/learn/sort-radix) handles in linear time: sort by the second part, then do a **stable** [counting sort](/dsa/learn/sort-counting) by the first part. And the sort by the second part comes for free: the previous round's suffix array already lists suffixes in order of their rank, so suffix i + k appears in order of `rank[i + k]`, and stepping each entry back by k gives the starting positions in order of their second key.

The standard implementation adds a **sentinel** character, smaller than every real character, to the end and sorts the text's **cyclic shifts**, wrapping round instead of running off the end. With a unique smallest character at the end, comparing two cyclic shifts always stops at the sentinel, so the order of the shifts is the order of the suffixes. The wrap-around avoids every "is i + k past the end?" test:

```swift run
// O(n log n): the same doubling, with each round's sort done by counting sort in O(n)
func suffixArray(_ text: [UInt8]) -> [Int] {
    let s = text.map { Int($0) + 1 } + [0]          // a sentinel 0, smaller than every character
    let n = s.count
    var sa = [Int](repeating: 0, count: n)
    var rank = [Int](repeating: 0, count: n)
    var count = [Int](repeating: 0, count: max(257, n))
    for c in s { count[c] += 1 }                    // round 0: counting sort by one character
    for c in count.indices.dropFirst() { count[c] += count[c - 1] }
    for i in stride(from: n - 1, through: 0, by: -1) {
        count[s[i]] -= 1
        sa[count[s[i]]] = i
    }
    var classes = 1
    for p in 1..<n {
        if s[sa[p]] != s[sa[p - 1]] { classes += 1 }
        rank[sa[p]] = classes - 1
    }
    var shifted = [Int](repeating: 0, count: n)
    var newRank = [Int](repeating: 0, count: n)
    var k = 1
    while classes < n {
        // Already sorted by the second half: start each suffix k places earlier (wrapping round)
        for p in 0..<n { shifted[p] = (sa[p] - k + n) % n }
        // A stable counting sort by the first half's rank
        count = [Int](repeating: 0, count: classes)
        for i in shifted { count[rank[i]] += 1 }
        for c in count.indices.dropFirst() { count[c] += count[c - 1] }
        for i in shifted.reversed() {
            count[rank[i]] -= 1
            sa[count[rank[i]]] = i
        }
        newRank[sa[0]] = 0
        classes = 1
        for p in 1..<n {
            let current = (rank[sa[p]], rank[(sa[p] + k) % n])
            let previous = (rank[sa[p - 1]], rank[(sa[p - 1] + k) % n])
            if current != previous { classes += 1 }
            newRank[sa[p]] = classes - 1
        }
        swap(&rank, &newRank)
        k *= 2
    }
    return Array(sa.dropFirst())                    // the sentinel's suffix always sorts first
}

// Check it against plain sorting on many small strings, the same every run
var seed = 5
func nextNumber(below limit: Int) -> Int {
    seed = (seed * 1_103_515_245 + 12_345) % 2_147_483_648
    return (seed >> 16) % limit
}
var agree = 0
for _ in 0..<300 {
    let text = (0..<nextNumber(below: 30)).map { _ in UInt8(97 + nextNumber(below: 3)) }
    let slow = text.indices.sorted { text[$0...].lexicographicallyPrecedes(text[$1...]) }
    if suffixArray(text) == slow { agree += 1 }
}
print("agree on \(agree) of 300 random strings")
print(suffixArray(Array("banana".utf8)), suffixArray([]), suffixArray(Array("a".utf8)))
let long = (0..<100_000).map { _ in UInt8(97 + nextNumber(below: 2)) }
let sa = suffixArray(long)
let ordered = sa.indices.dropFirst().allSatisfy { long[sa[$0 - 1]...].lexicographicallyPrecedes(long[sa[$0]...]) }
print("100,000 characters:", sa.count, "suffixes, every neighbouring pair in order:", ordered)
```

```output
agree on 300 of 300 random strings
[5, 3, 1, 0, 4, 2] [] [0]
100,000 characters: 100000 suffixes, every neighbouring pair in order: true
```

Each round is now O(n), so the whole build is **O(n log n)**. The check at the end is the testing habit from [Build a Trie](/dsa/learn/trie-build): compare a clever implementation with an obviously correct one on many small random inputs, where bugs show up quickly. (There are even O(n) algorithms, SA-IS and DC3. They're intricate, and O(n log n) is almost always enough.)

## Searching with a suffix array

Every occurrence of a pattern P starts some suffix that **begins with P**, and because the suffixes are sorted, all of those sit in one unbroken block of the suffix array. Two binary searches, as in [Lower bound, upper bound, first and last occurrence](/dsa/learn/bs-bounds), find the block's two ends. Each step compares P with a suffix cut to P's length:

```swift run
// Every suffix that starts with the pattern sits in one block of the suffix array
let text = Array("mississippi".utf8)
let sa = text.indices.sorted { text[$0...].lexicographicallyPrecedes(text[$1...]) }

// The first position in sa whose suffix, cut to the pattern's length, is not below the pattern
// (or, with strict, is above it)
func boundary(_ pattern: [UInt8], strict: Bool) -> Int {
    var low = 0, high = sa.count
    while low < high {
        let mid = (low + high) / 2
        let start = sa[mid]
        let prefix = text[start..<min(start + pattern.count, text.count)]
        let goRight = strict ? !pattern.lexicographicallyPrecedes(prefix)
                             : prefix.lexicographicallyPrecedes(pattern)
        if goRight { low = mid + 1 } else { high = mid }
    }
    return low
}

for word in ["ssi", "i", "issip", "pp", "x"] {
    let p = Array(word.utf8)
    let first = boundary(p, strict: false), end = boundary(p, strict: true)
    print(word, "found at", sa[first..<end].sorted())
}
```

```output
ssi found at [2, 5]
i found at [1, 4, 7, 10]
issip found at [4]
pp found at [8]
x found at []
```

Each search is O(m log n), for a pattern of length m. That's the suffix trie's "build once, query many times" power, from an array of n integers instead of O(n²) nodes.

## The LCP array

Sorting puts suffixes that share a long start next to each other. The **LCP array** records how much each suffix shares with the one just before it in sorted order:

> lcp[p] = the length of the longest common prefix of the suffixes starting at sa[p − 1] and sa[p], with lcp[0] = 0.

| p | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| Suffix | a | ana | anana | banana | na | nana |
| lcp[p] | 0 | 1 | 3 | 0 | 0 | 2 |

`ana` and `anana` share 3 characters, `na` and `nana` share 2. Neighbours are enough: the longest common prefix of *any* two suffixes is the minimum of the lcp values between their positions, because in sorted order a shared start can only shrink as you move away. With a sparse table, from [Sparse tables and O(1) RMQ](/dsa/learn/rq-sparse-table), that's an O(1) query for any pair.

### Kasai's algorithm

Comparing each neighbouring pair from scratch is O(n²) on `aaaa…a`. **Kasai's algorithm** computes the whole array in O(n), with one observation. Process the suffixes in **text order**: the suffix at 0, then at 1, then at 2. Suppose the suffix at i shares h characters with its predecessor in sorted order, the suffix at j. Drop the first character of both: the suffix at i + 1 shares h − 1 characters with the suffix at j + 1, and that suffix sorts before i + 1. Its actual predecessor sits between them in sorted order, so shares **at least** h − 1 characters too. So the next lcp is at least h − 1, and the comparison can start there instead of at 0.

```swift run
// Kasai's algorithm: lcp[p] = the longest common prefix of the suffixes at sa[p - 1] and sa[p]
func lcpArray(_ s: [UInt8], _ sa: [Int]) -> [Int] {
    let n = s.count
    var rank = [Int](repeating: 0, count: n)        // rank[i] = where suffix i sits in sa
    for (p, start) in sa.enumerated() { rank[start] = p }
    var lcp = [Int](repeating: 0, count: n)
    var h = 0
    for i in 0..<n {                                // suffixes in text order, longest first
        if rank[i] == 0 {
            h = 0                                   // the smallest suffix has no neighbour before it
            continue
        }
        let j = sa[rank[i] - 1]                     // the suffix just before i in sorted order
        while i + h < n && j + h < n && s[i + h] == s[j + h] {
            h += 1
        }
        lcp[rank[i]] = h
        if h > 0 { h -= 1 }                         // suffix i + 1 keeps at least h - 1 of it
    }
    return lcp
}

let text = Array("banana".utf8)
let sa = text.indices.sorted { text[$0...].lexicographicallyPrecedes(text[$1...]) }
let lcp = lcpArray(text, sa)
for p in sa.indices {
    print(lcp[p], String(decoding: text[sa[p]...], as: UTF8.self))
}
```

```output
0 a
1 ana
3 anana
0 banana
0 na
2 nana
```

Here's the order Kasai works in, for `banana`:

| i | Suffix | Its predecessor in sorted order | h starts at | lcp found |
| --- | --- | --- | --- | --- |
| 0 | banana | anana | 0 | 0 |
| 1 | anana | ana | 0 | 3 |
| 2 | nana | na | 2 | 2 |
| 3 | ana | a | 1 | 1 |
| 4 | na | banana | 0 | 0 |
| 5 | a | none: it's the smallest | | 0 |

At i = 2, h starts at 2 because `anana` shared 3 with its predecessor, and indeed `nana` shares 2 with `na` without comparing those two characters again.

**Why it's O(n):** h goes down by at most 1 per suffix (plus the resets at rank 0, which only happen once), never goes below 0, and never exceeds n. So it rises at most about 2n times in total, and each rise is one comparison. That's the same amortised argument as KMP's.

## What the two arrays answer

**Distinct substrings.** Every substring is a prefix of some suffix. Walk the suffixes in sorted order. The suffix at sa[p] has n − sa[p] prefixes, and the ones that already appeared as prefixes of an earlier suffix are exactly its first lcp[p]: sharing a start with any earlier suffix means sharing it with the neighbour, since shared starts only shrink with distance. So it adds n − sa[p] − lcp[p] new substrings, and adding these up over every suffix gives:

> distinct substrings = n(n + 1)/2 − (sum of lcp)

For `banana`: 21 − (1 + 3 + 2) = 15.

**The longest repeated substring.** A substring occurs twice exactly when two suffixes start with it, and the two that share the most are neighbours. So it's the **largest lcp value**, read from the suffix at that position. Occurrences may overlap: in `aaaa`, it's `aaa`.

```swift run
func suffixArray(_ s: [UInt8]) -> [Int] {
    let n = s.count
    guard n > 1 else { return Array(0..<n) }
    var sa = Array(0..<n)
    var rank = s.map { Int($0) }
    var newRank = [Int](repeating: 0, count: n)
    var k = 1
    while true {
        func key(_ i: Int) -> (Int, Int) { (rank[i], i + k < n ? rank[i + k] : -1) }
        sa.sort { key($0) < key($1) }
        newRank[sa[0]] = 0
        for p in 1..<n { newRank[sa[p]] = newRank[sa[p - 1]] + (key(sa[p - 1]) < key(sa[p]) ? 1 : 0) }
        rank = newRank
        if rank[sa[n - 1]] == n - 1 { break }
        k *= 2
    }
    return sa
}

func lcpArray(_ s: [UInt8], _ sa: [Int]) -> [Int] {
    let n = s.count
    var rank = [Int](repeating: 0, count: n)
    for (p, start) in sa.enumerated() { rank[start] = p }
    var lcp = [Int](repeating: 0, count: n)
    var h = 0
    for i in 0..<n {
        if rank[i] == 0 { h = 0; continue }
        let j = sa[rank[i] - 1]
        while i + h < n && j + h < n && s[i + h] == s[j + h] { h += 1 }
        lcp[rank[i]] = h
        if h > 0 { h -= 1 }
    }
    return lcp
}

for word in ["banana", "abab", "aaaa", "mississippi"] {
    let s = Array(word.utf8)
    let sa = suffixArray(s)
    let lcp = lcpArray(s, sa)
    let n = s.count
    let distinct = n * (n + 1) / 2 - lcp.reduce(0, +)
    let best = lcp.indices.max { lcp[$0] < lcp[$1] }!        // the first largest LCP
    let repeated = String(decoding: s[sa[best]..<(sa[best] + lcp[best])], as: UTF8.self)
    var brute = Set<ArraySlice<UInt8>>()                      // check: every substring in a set
    for a in 0..<n { for b in (a + 1)...n { brute.insert(s[a..<b]) } }
    print(word, "distinct:", distinct, "(brute force \(brute.count))", "longest repeat: \"\(repeated)\"")
}
```

```output
banana distinct: 15 (brute force 15) longest repeat: "ana"
abab distinct: 7 (brute force 7) longest repeat: "ab"
aaaa distinct: 4 (brute force 4) longest repeat: "aaa"
mississippi distinct: 53 (brute force 53) longest repeat: "issi"
```

The `Set` holds slices, which compare by their elements, so it's an honest brute-force check. It only prints a count, never the set itself.

**The longest common substring of two strings.** Join them with a separator that occurs in neither, `first + [separator] + second`, and build both arrays. A common substring is a shared prefix of two suffixes, one starting in each string. Among neighbouring suffixes from *different* strings, the largest lcp is the answer, and the separator stops any lcp from running across the join. That's O((n + m) log(n + m)), against O(n · m) for the dynamic programming of [Longest common substring](/dsa/learn/dps-common-substring).

| Question | From the arrays | Cost after building |
| --- | --- | --- |
| Does P occur, and where? | binary search for P's block | O(m log n) |
| How many distinct substrings? | n(n + 1)/2 − sum of lcp | O(n) |
| Longest repeated substring | largest lcp | O(n) |
| Longest common substring of A and B | largest lcp between neighbours from different strings | O(n) |
| Longest common prefix of any two suffixes | minimum lcp between them | O(1) with a sparse table |

<Callout kind="gotcha" title="Common suffix array mistakes">
**Copying suffixes to sort them.** `String(text[i...])` or `Array(text[i...])` copies the suffix: O(n²) memory before you've compared anything. Slices share storage; compare them with `lexicographicallyPrecedes`.

**Ranks that run off the end.** In prefix doubling, `rank[i + k]` crashes when `i + k >= n`. Use −1 there, or add a sentinel and wrap round, as the counting-sort version does.

**An unstable sort in the O(n log n) version.** The counting sort by the first rank must keep the order from the second key, so it fills each bucket from the back while walking the shifted array backwards. A forward walk filling from the back breaks it.

**Mixing up the two indexes.** `sa[p]` turns a sorted position into a text position; `rank[i]` turns a text position back into a sorted position. lcp is indexed by sorted position. Name your variables p and i, and keep them straight.

**Overflow in the distinct count.** n(n + 1)/2 for n = 100,000 is about 5 × 10⁹. That fits in Swift's 64-bit `Int`, but not in an `Int32`.
</Callout>
