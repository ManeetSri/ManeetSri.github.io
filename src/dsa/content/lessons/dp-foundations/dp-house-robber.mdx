## Why it matters

The staircase had no real decisions: every route was just a different sequence of moves. House robber has the decision at the heart of a huge number of DP problems: **take this item, or skip it**, where taking it rules something else out. The same shape decides which non-overlapping ad slots to sell, which adjacent shifts a nurse can work, and which features to ship when some can't go together. It's also the first problem in this module where an obvious greedy idea gives the wrong answer.

## The problem

A row of houses stands along a street, and `houses[i]` is the cash in house i. You can rob any houses you like, except that robbing **two neighbours** sets off the alarm. What's the most you can take?

For `[5, 8, 6, 1, 2, 9]`, the best is 20: houses 0, 2 and 5, for 5 + 6 + 9.

## Two greedy ideas, both wrong

Before the DP, see why simpler ideas fail. Here are two greedy strategies, against a brute force that tries every plan:

```swift run
/// Greedy: keep taking the richest house that doesn't sit next to one already taken
func richestFirst(_ houses: [Int]) -> Int {
    var taken = Array(repeating: false, count: houses.count)
    var total = 0
    for i in houses.indices.sorted(by: { houses[$0] > houses[$1] }) {
        let leftFree = i == 0 || !taken[i - 1]
        let rightFree = i == houses.count - 1 || !taken[i + 1]
        if leftFree && rightFree {
            taken[i] = true
            total += houses[i]
        }
    }
    return total
}

/// Take every other house: the better of the even positions and the odd positions
func everyOther(_ houses: [Int]) -> Int {
    let even = houses.indices.filter { $0 % 2 == 0 }.map { houses[$0] }.reduce(0, +)
    let odd = houses.indices.filter { $0 % 2 == 1 }.map { houses[$0] }.reduce(0, +)
    return max(even, odd)
}

/// Try every plan: rob house i or not, never two neighbours
func bestOfAll(_ houses: [Int], from i: Int = 0) -> Int {
    if i >= houses.count {
        return 0
    }
    return max(bestOfAll(houses, from: i + 1), houses[i] + bestOfAll(houses, from: i + 2))
}

for street in [[3, 4, 3], [5, 1, 1, 5], [5, 8, 6, 1, 2, 9]] {
    print(street, "richest first:", richestFirst(street), "every other:", everyOther(street), "best:", bestOfAll(street))
}
```

```output
[3, 4, 3] richest first: 4 every other: 6 best: 6
[5, 1, 1, 5] richest first: 10 every other: 6 best: 10
[5, 8, 6, 1, 2, 9] richest first: 18 every other: 18 best: 20
```

Taking the richest house first grabs the 4 in `[3, 4, 3]` and blocks both 3s. Taking every other house can't skip **two** houses in a row, which `[5, 1, 1, 5]` needs. On the last street both fail. A good plan needs to weigh each house against its neighbours, in context, which is exactly what DP does.

The brute force is right, but it's the same exponential recursion shape as Fibonacci: `bestOfAll(from: i)` calls `from: i + 1` and `from: i + 2`. Overlapping subproblems again.

## The recipe

1. **State.** `best[i]` = the most you can take from the **first i houses** (houses 0 to i − 1).
2. **Transition.** Decide about the last of those houses, house i − 1:
   - **skip it**: the best from the first i − 1 houses, `best[i − 1]`;
   - **rob it**: then house i − 2 is off limits, so add its cash to the best from the first i − 2 houses, `best[i − 2] + houses[i − 1]`.

   Take the larger: `best[i] = max(best[i − 1], best[i − 2] + houses[i − 1])`.
3. **Base case.** `best[0] = 0` (no houses), and `best[1] = houses[0]` (one house: rob it), which the transition also gives if you treat `best[−1]` as 0.
4. **Order.** Upwards.
5. **Answer.** `best[n]`.

Optimal substructure holds by cut and paste: if the best plan robs house i − 1, the rest of it must be a best plan for the first i − 2 houses, or you could swap in a better one.

At the end, the visualiser walks back through the table to find which houses were robbed. You'll learn that walk in [Reconstructing the answer, not just its value](/dsa/learn/dp-reconstruct). In code:

```swift run
func rob(_ houses: [Int]) -> Int {
    let n = houses.count
    // 1. State: best[i] = the most you can take from the first i houses
    var best = Array(repeating: 0, count: n + 1)
    // 3. Base case: best[0] = 0 (no houses), already in place
    // 4. Order: upwards
    for i in stride(from: 1, through: n, by: 1) {
        // 2. Transition: leave house i - 1 alone, or rob it and skip its neighbour
        let skip = best[i - 1]
        let take = (i >= 2 ? best[i - 2] : 0) + houses[i - 1]
        best[i] = max(skip, take)
    }
    print("best:", best)
    // 5. Answer: all n houses considered
    return best[n]
}

print(rob([5, 8, 6, 1, 2, 9]))
print(rob([5, 1, 1, 5]))
```

```output
best: [0, 5, 8, 11, 11, 13, 20]
20
best: [0, 5, 5, 6, 10]
10
```

Notice `best[4] = 11` equals `best[3]`: with four houses, robbing house 3 (cash 1) doesn't beat leaving it alone. That's a skip, and it's what lets the final plan pass over two houses in a row when it pays.

**Cost:** O(n) time. And `best[i]` reads only the two entries before it, so it rolls down to two variables, exactly like `fib`.

## House robber II: a circle of houses

Now the houses stand in a **circle**: the last house is next to the first. Everything else is the same.

The circle breaks the DP, because "the first i houses" is no longer a simple row: whether you may rob the last house depends on a decision made at the very start. The fix is a case split. Any valid plan can't rob both house 0 and house n − 1, so **at least one of them is left alone**:

- **House 0 is left alone.** Then the rest, houses 1 to n − 1, is an ordinary row: house n − 1's neighbour across the circle is safe.
- **House n − 1 is left alone.** Then houses 0 to n − 2 form an ordinary row.

Every valid plan falls into at least one case (a plan robbing neither falls into both, which is harmless when taking a maximum). So the answer is the better of two ordinary house-robber runs:

```swift run
/// House robber with two rolling variables
func rob(_ houses: ArraySlice<Int>) -> Int {
    var (twoBack, oneBack) = (0, 0)              // the best from the houses before the previous one, and before this one
    for value in houses {                        // no indexes, so a slice's indexes can't trip us up
        (twoBack, oneBack) = (oneBack, max(oneBack, twoBack + value))
    }
    return oneBack
}

/// The houses stand in a circle, so the first and last are neighbours
func robCircle(_ houses: [Int]) -> Int {
    if houses.count == 1 {
        return houses[0]
    }
    let firstLeftAlone = rob(houses.dropFirst())   // houses 1...n - 1
    let lastLeftAlone = rob(houses.dropLast())     // houses 0...n - 2
    return max(firstLeftAlone, lastLeftAlone)
}

let street = [5, 8, 6, 1, 2, 9]
print("in a row:", rob(street[...]))
print("in a circle:", robCircle(street))
print(robCircle([7, 2, 4, 9]), robCircle([4]), robCircle([]))
```

```output
in a row: 20
in a circle: 18
11 4 0
```

On the circular street, the row's best plan (houses 0, 2 and 5) is now illegal, because houses 0 and 5 are neighbours. The best is 8 + 1 + 9, from the "house 0 left alone" run. For `[7, 2, 4, 9]`, the 7 and the 9 can't both be taken; 7 + 4 = 11 beats 2 + 9.

What to notice:

- **`dropFirst()` and `dropLast()` return `ArraySlice`s**, views into the original array with no copying. As [ArraySlice and its index pitfalls](/dsa/learn/swift-array-slices) warned, a slice keeps the original indexes, so `houses.dropFirst()[0]` crashes. Looping with `for value in houses` uses no indexes at all, which sidesteps the trap. (`street[...]` turns a whole array into a slice.)
- **One house is a special case.** Both runs would be empty, and return 0, but a single house has no neighbours at all, so it can be robbed. With no houses at all, the answer is 0.
- **The cost is still O(n)**: two passes instead of one.

"Split on what happens at the troublesome spot, solve each case as an easier problem, and combine" is a trick worth remembering. It turns a cycle into rows here, and it comes back whenever a single constraint spoils an otherwise simple DP.

<Callout kind="gotcha" title="Robber slips">
- **Treating the circle as a row** and returning the row's answer: it may rob both ends.
- **Forgetting the one-house circle**: both runs are empty, so the answer comes out 0 instead of the house's cash.
- **Indexing a slice from 0**: `dropFirst()` keeps the original indexes. Loop over the values, or convert with `Array(...)`.
- **Assuming you must alternate**: the best plan sometimes skips two houses in a row, as `[5, 1, 1, 5]` shows.
</Callout>
