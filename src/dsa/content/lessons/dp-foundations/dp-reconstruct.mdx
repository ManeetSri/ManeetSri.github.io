## Why it matters

"The best haul is 20" is rarely the whole answer. A satnav must show the route, not just its length. A diff tool must show which lines changed, not just how many. A spell-checker must show the corrected word. Every DP so far has produced a **value**. This lesson recovers the **choices** behind it: which houses, which stairs. The technique is the same for every DP in the course, and it's why "print the actual solution" is such a common follow-up question in interviews.

## Walking back through the table

A filled DP table already knows the answer's history. Each entry was chosen from a few options, and you can ask, afterwards, which option produced it.

For house robber, `best[i] = max(best[i − 1], best[i − 2] + houses[i − 1])`. Start at the answer, `best[n]`, and ask:

- if `best[i] == best[i − 1]`, skipping house i − 1 gives the same total, so a best plan **skips** it: move to `i − 1`;
- otherwise the total must have come from **robbing** house i − 1: record it, and move to `i − 2`, because its neighbour can't have been robbed.

Stop when you reach the start. The houses come out in reverse order, so reverse them at the end:

```swift run
/// The best haul, and which houses to rob to get it
func robPlan(_ houses: [Int]) -> (total: Int, robbed: [Int]) {
    let n = houses.count
    // best[i] = the most from the first i houses
    var best = Array(repeating: 0, count: n + 1)
    for i in stride(from: 1, through: n, by: 1) {
        best[i] = max(best[i - 1], (i >= 2 ? best[i - 2] : 0) + houses[i - 1])
    }
    // Walk back from the answer, asking which option produced each entry
    var robbed: [Int] = []
    var i = n
    while i >= 1 {
        if best[i] == best[i - 1] {
            i -= 1                     // skipping house i - 1 gives the same total: it wasn't robbed
        } else {
            robbed.append(i - 1)       // house i - 1 was robbed, so its neighbour wasn't
            i -= 2
        }
    }
    return (best[n], robbed.reversed())
}

let plan = robPlan([5, 8, 6, 1, 2, 9])
print("take", plan.total, "from houses", plan.robbed)
print(robPlan([5, 1, 1, 5]).robbed, robPlan([7]).robbed, robPlan([]).robbed)
```

```output
take 20 from houses [0, 2, 5]
[0, 3] [0] []
```

The table for `[5, 8, 6, 1, 2, 9]` is `[0, 5, 8, 11, 11, 13, 20]`. From `best[6] = 20`, which differs from `best[5] = 13`, house 5 was robbed: jump to `best[4] = 11`. That equals `best[3]`, so house 3 was skipped. `best[3] = 11` differs from `best[2] = 8`, so house 2 was robbed: jump to `best[1] = 5`, which differs from `best[0]`, so house 0 was robbed. Houses 0, 2 and 5.

The walk costs O(n), on top of the O(n) fill. It's exactly what the house-robber visualiser did at the end of [House robber I and II](/dsa/learn/dp-house-robber).

## Recording choices as you go

Re-deriving each decision works, but it repeats the transition's logic, and with many options it gets fiddly. The alternative is to **record the decision when you make it**, in a second array:

- a **choice array** stores which option won, such as `took[i]: Bool`;
- a **parent array** stores which state the winner came from, such as `from[i] = i − 2`.

Then the walk back just follows the record. Here's the cheapest climb from [Climbing stairs and min-cost stairs](/dsa/learn/dp-stairs), with a parent array, listing the stairs it stands on:

```swift run
/// The cheapest climb (start on stair 0 or 1, climb 1 or 2, a toll on every stair you stand on),
/// and the stairs it stands on
func cheapestRoute(_ tolls: [Int]) -> (cost: Int, stairs: [Int]) {
    let n = tolls.count
    var reach = Array(repeating: 0, count: n + 1)   // reach[i]: the cheapest cost to arrive at position i
    var from = Array(repeating: -1, count: n + 1)   // from[i]: the stair that cheapest arrival came from
    for i in stride(from: 2, through: n, by: 1) {
        let oneUp = reach[i - 1] + tolls[i - 1]
        let twoUp = reach[i - 2] + tolls[i - 2]
        if oneUp <= twoUp {
            reach[i] = oneUp
            from[i] = i - 1
        } else {
            reach[i] = twoUp
            from[i] = i - 2
        }
    }
    // Follow the parent links from the landing back to a starting stair
    var stairs: [Int] = []
    var position = n
    while from[position] != -1 {
        position = from[position]
        stairs.append(position)
    }
    return (reach[n], stairs.reversed())
}

print(cheapestRoute([3, 8, 2, 9, 4, 1, 7]))
print(cheapestRoute([5, 1, 5, 1, 5]))
```

```output
(cost: 10, stairs: [0, 2, 4, 5])
(cost: 2, stairs: [1, 3])
```

`from` starts at −1, meaning "no parent". Positions 0 and 1 keep it, because they're starting points, so the walk stops as soon as it reaches one. This is the same idea as the `previous` array that recovered paths in [Longest and shortest paths in a DAG](/dsa/learn/topo-dag-paths) and in BFS: a DP **is** a path through the subproblem DAG, and a parent array remembers it.

<Callout kind="tip" title="Which to use">
Re-deriving needs no extra memory and is fine when there are two or three options. A choice or parent array costs one entry per state but makes the walk trivial, and it's the only practical way when the transition has many options (like perfect squares, which square was last?) or when the comparison would be expensive to repeat.
</Callout>

## Saving space, and its limits

The last lesson said reconstruction stops you rolling the table. That's true of the **values**, but not of the decisions. You can roll the values down to two variables and keep only a compact record of what was chosen:

```swift run
/// House robber with rolling values, but one Bool per house recording the decision
func robPlan(_ houses: [Int]) -> [Int] {
    let n = houses.count
    var took = Array(repeating: false, count: n + 1)   // took[i]: did the best for the first i houses rob house i - 1?
    var (twoBack, oneBack) = (0, 0)
    for i in stride(from: 1, through: n, by: 1) {
        let take = twoBack + houses[i - 1]
        took[i] = take > oneBack
        (twoBack, oneBack) = (oneBack, max(oneBack, take))
    }
    var robbed: [Int] = []
    var i = n
    while i >= 1 {
        if took[i] {
            robbed.append(i - 1)
            i -= 2
        } else {
            i -= 1
        }
    }
    return robbed.reversed()
}

print(robPlan([5, 8, 6, 1, 2, 9]))
```

```output
[0, 2, 5]
```

A `Bool` takes one byte against an `Int`'s eight. For a 2D table the saving is the same idea at a bigger scale: an `n × m` grid of small "which way" codes instead of `Int`s. You'll do exactly this when printing a longest common subsequence in [Longest common subsequence, and printing it](/dsa/learn/dps-lcs).

What you **can't** do is keep only the last row of decisions. The walk back visits states from the end all the way to the start, so every state on the way needs its decision available.

## When there's more than one best answer

Many problems have several optimal solutions. Which one the walk finds depends on how it settles **ties**. For the street `[2, 3, 1]`, robbing house 1 alone and robbing houses 0 and 2 both give 3. Walking back and skipping on ties finds `[1]`. If the problem wants a particular one, such as "the best plan that robs the earliest houses", tie-breaking alone may not be enough. The reliable way is to build the table **backwards**, then walk **forwards**, making the preferred choice at each step whenever it can still reach the best total:

```swift run
/// Backwards: fill "the first i houses", then walk back from the end, skipping on ties
func walkBackPlan(_ houses: [Int]) -> [Int] {
    let n = houses.count
    var best = Array(repeating: 0, count: n + 1)
    for i in stride(from: 1, through: n, by: 1) {
        best[i] = max(best[i - 1], (i >= 2 ? best[i - 2] : 0) + houses[i - 1])
    }
    var robbed: [Int] = []
    var i = n
    while i >= 1 {
        if best[i] == best[i - 1] {
            i -= 1
        } else {
            robbed.append(i - 1)
            i -= 2
        }
    }
    return robbed.reversed()
}

/// Forwards: fill "houses i to the end", then walk forwards from house 0, robbing whenever that still
/// reaches the best total. This gives the best plan whose list of houses comes first in dictionary order.
func earliestPlan(_ houses: [Int]) -> [Int] {
    let n = houses.count
    var fromHere = Array(repeating: 0, count: n + 2)   // fromHere[i]: the most from houses i...n - 1
    for i in stride(from: n - 1, through: 0, by: -1) {
        fromHere[i] = max(fromHere[i + 1], houses[i] + fromHere[i + 2])
    }
    var robbed: [Int] = []
    var i = 0
    while i < n {
        if houses[i] + fromHere[i + 2] == fromHere[i] {
            robbed.append(i)
            i += 2
        } else {
            i += 1
        }
    }
    return robbed
}

for street in [[2, 3, 1], [1, 1, 1, 2, 1], [5, 8, 6, 1, 2, 9]] {
    print(street, "walk back:", walkBackPlan(street), "earliest:", earliestPlan(street))
}
```

```output
[2, 3, 1] walk back: [1] earliest: [0, 2]
[1, 1, 1, 2, 1] walk back: [0, 3] earliest: [0, 2, 4]
[5, 8, 6, 1, 2, 9] walk back: [0, 2, 5] earliest: [0, 2, 5]
```

Why does the forward walk work? `fromHere[i]` knows the best total still available from house i onwards. At each house, "rob it" is safe exactly when `houses[i] + fromHere[i + 2]` still equals that best, so the walk can take the earliest house possible at every step without ever losing the optimum. A walk back from the end makes its choices **last house first**, so it can only control the end of the list. When the order of choices matters, the walk must start at the end of the list you care about, which means the table must be built from the other end.

Two related warnings:

- **One plan is cheap; all plans are not.** A walk finds one best solution in O(n). Listing **every** best solution means branching at every tie, and there can be exponentially many: a street of 2n houses of equal value has n + 1 best plans, and other patterns grow much faster. That's backtracking, not DP.
- **Top-down works too.** With a memo, start from the top state and, at each step, recompute which option matches the memoised value, then move to that subproblem. It's the same walk, reading the memo instead of a table.

<Callout kind="gotcha" title="Reconstruction slips">
- **Forgetting to reverse.** Walking back collects choices last first.
- **Walking off the start.** Stop at the base case: `i >= 1` here, or a parent of −1.
- **Jumping by the wrong amount.** After robbing house i − 1, the next state is `i − 2`, not `i − 1`, or you'd consider its neighbour.
- **Comparing the wrong values.** The walk must use exactly the same transition as the fill, including the same tie-breaking, or it can step into a state that wasn't on any best path.
</Callout>
