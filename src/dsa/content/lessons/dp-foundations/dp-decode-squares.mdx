## Why it matters

Two classics that stretch the recipe in different directions. **Decode ways** is a counting DP whose transition has conditions: an option is only allowed when the digits fit, and a single `0` can wipe out every decoding. It's the model for parsing problems, such as splitting text into valid words. **Perfect squares** is an optimising DP where the last choice can be any of many sizes, used as often as you like. That "unbounded" shape is the heart of coin change and the knapsack family in M53.

## Decode ways

A message was written with letters encoded as numbers, A = 1, B = 2, and so on up to Z = 26, and then the numbers were run together into one string of digits. How many different messages could it have been?

`"2611"` could be 2 6 1 1 (BFAA), 26 1 1 (ZAA), 2 6 11 (BFK) or 26 11 (ZK): four decodings.

1. **State.** `ways[i]` = the number of ways to decode the **first i digits**.
2. **Transition.** The last letter used either:
   - **one digit**, the i-th, which must be 1 to 9 (there's no letter 0): add `ways[i − 1]`;
   - **two digits**, the (i − 1)-th and i-th, which together must be 10 to 26: add `ways[i − 2]`.

   Each option is only counted when its condition holds. The two options end in different-sized last letters, so they never describe the same decoding, and adding is safe.
3. **Base case.** `ways[0] = 1`: the empty prefix has one decoding, the empty message.
4. **Order.** Left to right.
5. **Answer.** `ways[n]`.

```swift run
/// The decoding counts for every prefix of a digit string, with A = 1, B = 2, ..., Z = 26
func decodeTable(_ message: String) -> [Int] {
    let digits = message.compactMap { $0.wholeNumberValue }
    let n = digits.count
    // 1. State: ways[i] = the number of ways to decode the first i digits
    var ways = Array(repeating: 0, count: n + 1)
    // 3. Base case: the empty message has one decoding, the empty word
    ways[0] = 1
    // 4. Order: left to right
    for i in stride(from: 1, through: n, by: 1) {
        // 2. Transition: the last letter used one digit (1 to 9) ...
        if digits[i - 1] != 0 {
            ways[i] += ways[i - 1]
        }
        // ... or two digits (10 to 26)
        if i >= 2 {
            let pair = digits[i - 2] * 10 + digits[i - 1]
            if pair >= 10 && pair <= 26 {
                ways[i] += ways[i - 2]
            }
        }
    }
    // 5. Answer: the last entry
    return ways
}

print("2611:", decodeTable("2611"))
print("1201:", decodeTable("1201"))
for message in ["10", "100", "06", "301", "2525", "1111"] {
    print(message, "->", decodeTable(message).last!)
}
```

```output
2611: [1, 1, 2, 2, 4]
1201: [1, 1, 2, 1, 1]
10 -> 1
100 -> 0
06 -> 0
301 -> 0
2525 -> 4
1111 -> 5
```

Follow `"2611"`: one digit has one reading; `"26"` has two (2 6, or Z); `"261"` still has two, because 61 is too big to be a letter; and `"2611"` adds both options, 2 + 2 = 4.

### The zero traps

Most wrong answers to decode ways come from `0`, which can never start a letter or stand alone. It's only legal as the second digit of 10 or 20:

| Digits | Decodings | Why |
| --- | --- | --- |
| `"10"` | 1 | the 0 is used up by J (10) |
| `"100"` | 0 | the last 0 has nothing to pair with: 00 isn't a letter |
| `"06"` | 0 | a leading 0 can't start a letter, and 06 isn't 6 |
| `"301"` | 0 | 30 is too big, and 0 can't stand alone |
| `"1201"` | 1 | only 1 20 1 works: 12 would strand the 0 |

The two conditions handle all of these with no special cases: `digits[i - 1] != 0` refuses a lone 0, and `pair >= 10` refuses "pairs" that start with 0, like 06. Once some `ways[i]` is 0, nothing later can build on that prefix. In `"1201"`, `ways[3] = 1` comes only through 20, and from there the 1 has one reading.

**Cost:** O(n) time. Each entry reads the two before it, so it rolls down to two variables. For long messages the counts explode like Fibonacci (a string of n ones has `fib(n + 1)` decodings), so problems ask for the count modulo 1,000,000,007.

<Callout kind="gotcha" title="Swift gotcha: work on digits, not on the String">
Swift strings can't be indexed with integers, as you saw in [String.Index and why s[i] does not exist](/dsa/learn/swift-string-index). Convert once, at the start: `message.compactMap { $0.wholeNumberValue }` gives `[Int]`, and `Array(message.utf8)` gives bytes, where a digit is its byte minus 48, the code for `"0"`. Then the DP indexes an array in O(1). Reaching for `message[message.index(message.startIndex, offsetBy: i)]` inside the loop makes every access O(n), and the whole DP O(n²).
</Callout>

## Perfect squares

What's the fewest perfect squares (1, 4, 9, 16, ...) that add up to n? 12 is 4 + 4 + 4: three squares. 13 is 4 + 9: two.

1. **State.** `fewest[t]` = the fewest perfect squares that add up to exactly t.
2. **Transition.** The last square in the sum could be any square that fits, `s = r²` with `s ≤ t`, leaving t − s to be made from as few squares as possible: `fewest[t] = 1 + min over every such s of fewest[t − s]`.
3. **Base case.** `fewest[0] = 0`: no squares.
4. **Order.** Upwards, because every option reads a smaller total.
5. **Answer.** `fewest[n]`.

```swift run
/// The fewest perfect squares (1, 4, 9, 16, ...) that add up to n
func fewestSquares(_ n: Int) -> Int {
    // 1. State: fewest[t] = the fewest perfect squares that add up to t
    var fewest = Array(repeating: Int.max, count: n + 1)
    // 3. Base case: 0 is the sum of no squares
    fewest[0] = 0
    // 4. Order: upwards, because fewest[t] reads smaller totals
    for t in stride(from: 1, through: n, by: 1) {
        // 2. Transition: try every square that fits as the last one
        var root = 1
        while root * root <= t {
            fewest[t] = min(fewest[t], fewest[t - root * root] + 1)
            root += 1
        }
    }
    // 5. Answer
    return fewest[n]
}

print((1...20).map(fewestSquares))
print(fewestSquares(12), fewestSquares(13), fewestSquares(9_999))
```

```output
[1, 2, 3, 1, 2, 3, 4, 2, 1, 2, 3, 3, 2, 3, 4, 1, 2, 2, 3, 2]
3 2 4
```

`Int.max` stands for "not worked out yet", but adding 1 to it never happens: 1 is a square, so `fewest[t - 1]` is always a real number by the time it's read, and every total can be made.

### Unbounded choices

Two things set this apart from everything earlier in the module:

- **The last choice has many sizes**, about √t of them, not just one or two. So the cost is O(n √n): about a million steps for n = 10,000.
- **Each square can be used any number of times.** `fewest[t − 4]` may itself have used a 4. Nothing in the state records which squares are used up, because nothing is. That's what "unbounded" means, and it's exactly the shape of making change from unlimited coins, where the coins are 1, 4, 9, 16 and so on.

Greedy, "take the biggest square that fits", fails here, just as it fails for awkward coin sets. For 12 it takes 9, then is stuck with 1 + 1 + 1: four squares instead of three. Step through the change-making table with coins 1, 4 and 9 to watch DP find the 4 + 4 + 4:

```visual dpTable

  coins: [1, 4, 9]
  amount: 12
```

Each amber cell reads the cells one coin back (blue) and takes the best plus one. You'll meet the full coin change problem in [Coin change I and II](/dsa/learn/dpk-coin-change).

<Callout kind="note" title="A theorem as a test">
In 1770 Lagrange proved that every positive whole number is a sum of at most **four** squares, so `fewestSquares` only ever returns 1, 2, 3 or 4. Legendre later pinned down exactly which numbers need four: those of the form 4ᵃ × (8b + 7), such as 7, 15, 28 and 9,999. It's a handy independent check for a DP like this one, even though the DP doesn't need it.
</Callout>

## Practice

**Decode digit messages** is decode ways on messages up to 100,000 digits long, with the count modulo 1,000,000,007. **Fewest square panels** is perfect squares. **Smudged digit messages** is the hard one: some digits are unreadable and could be anything, so each option counts how many digits it could have been.

```cards
  back: "`fewest[t] = 1 + min(fewest[t − s])` over squares s ≤ t, with `fewest[0] = 0`. O(n √n) time."
- id: unbounded
  front: "What makes perfect squares an 'unbounded' DP?"
  back: "Each square can be used any number of times, so the state needs no record of what's been used: `fewest[t − s]` may use s again. It's coin change with coins 1, 4, 9, 16, ..."
```
