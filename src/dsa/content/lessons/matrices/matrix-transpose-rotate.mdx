## Why it matters

Turn your phone sideways and the photo rotates. Press a key in a falling-blocks game and the piece turns. Under the hood, both rotate a grid of values by a quarter turn. Doing it with a second grid is straightforward; doing it **in place**, with no second grid, is a classic interview question with a lovely answer: a rotation is two simple flips, one after the other. You met the transpose in [Matrix basics](/dsa/learn/math-matrices), building a new matrix. This lesson does it in place and builds rotations from it.

## Where every cell goes

For an n × n grid, here's where the cell in row r, column c ends up:

| Move | (r, c) goes to |
| --- | --- |
| transpose (flip over the main diagonal) | (c, r) |
| rotate 90° clockwise | (c, n − 1 − r) |
| rotate 90° counterclockwise | (n − 1 − c, r) |
| rotate 180° | (n − 1 − r, n − 1 − c) |

Check the clockwise rule on a picture. Turning `[[1, 2, 3], [4, 5, 6], [7, 8, 9]]` clockwise makes the left column, read upwards, into the top row: `[7, 4, 1]`. The 7 is at (2, 0), and the rule sends it to (0, 3 − 1 − 2) = (0, 0). It works.

## The easy way: a new grid

With the rule, rotating into a new grid is one loop. This works for any rectangle: an m × n grid turns into an n × m one.

```swift run
func rotatedClockwise(_ grid: [[Int]]) -> [[Int]] {
    let rows = grid.count
    let columns = grid.first?.count ?? 0
    var result = Array(repeating: Array(repeating: 0, count: rows), count: columns)
    for r in 0..<rows {
        for c in 0..<columns {
            result[c][rows - 1 - r] = grid[r][c]
        }
    }
    return result
}

let wide = [[1, 2, 3], [4, 5, 6]]
for row in rotatedClockwise(wide) {
    print(row)
}
```

```output
[4, 1]
[5, 2]
[6, 3]
```

**O(m × n) time**, and the new grid is **O(m × n) extra space**. For a 4,000 × 4,000 photo, that's a second 16-million-pixel buffer. An in-place rotation avoids it, but only for square grids: a rectangle changes shape when it turns, so its values can't stay in the same rows and columns.

## Transposing in place

The transpose swaps each cell (r, c) with its mirror (c, r). Cells on the main diagonal, where r equals c, stay put. The catch: if you loop over **every** cell, each pair is swapped twice, once from each side, and you end up exactly where you started. So only visit cells **above** the diagonal, where c is greater than r:

```swift run
func transposeInPlace(_ grid: inout [[Int]]) {
    let n = grid.count
    for r in 0..<n {
        for c in (r + 1)..<n {           // only cells above the main diagonal
            let saved = grid[r][c]
            grid[r][c] = grid[c][r]
            grid[c][r] = saved
        }
    }
}

var square = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
transposeInPlace(&square)
for row in square {
    print(row)
}
```

```output
[1, 4, 7]
[2, 5, 8]
[3, 6, 9]
```

That's n(n − 1)/2 swaps: **O(n²) time, O(1) extra space**. When `r` is the last row, `(r + 1)..<n` is the empty range `n..<n`, so the loop is safe all the way down.

<Callout kind="gotcha" title="Swift gotcha: no swap across two rows">
`swap(&grid[r][c], &grid[c][r])` looks like the obvious way to exchange two cells, but it doesn't compile:

```text title="What you'll see"
error: overlapping accesses to 'grid', but modification requires exclusive access; consider copying to a local variable
```

Both arguments are inside `grid`, and the exclusivity rule from [inout, swap and swapAt](/dsa/learn/swift-inout-swap) forbids two overlapping changes to one variable. `swapAt` doesn't help either, because the cells are in different inner arrays. A temporary variable, as above, does the job.
</Callout>

## A rotation is two flips

Now the key idea. A clockwise quarter turn is:

1. **Transpose**: flip over the main diagonal.
2. **Reverse each row**: flip left to right.

Follow it on the 3 × 3 grid:

| Step | Grid |
| --- | --- |
| start | `[1, 2, 3]` `[4, 5, 6]` `[7, 8, 9]` |
| transpose | `[1, 4, 7]` `[2, 5, 8]` `[3, 6, 9]` |
| reverse each row | `[7, 4, 1]` `[8, 5, 2]` `[9, 6, 3]` |

That's the clockwise rotation. You can also check it with the rules: the transpose sends (r, c) to (c, r), and reversing a row sends column j to column n − 1 − j, so the cell ends at (c, n − 1 − r), which is exactly the clockwise rule from the table.

Watch both flips happen in place:

```visual matrix
program: rotate
input:
  grid: [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
```

Flip in other combinations and you get the other turns:

- **Counterclockwise**: transpose, then flip top to bottom by reversing the **order of the rows**.
- **180°**: reverse the order of the rows, then reverse each row. No transpose needed.

```swift run
func transposeInPlace(_ grid: inout [[Int]]) {
    let n = grid.count
    for r in 0..<n {
        for c in (r + 1)..<n {
            let saved = grid[r][c]
            grid[r][c] = grid[c][r]
            grid[c][r] = saved
        }
    }
}

func rotateCounterclockwise(_ grid: inout [[Int]]) {
    transposeInPlace(&grid)
    grid.reverse()                      // flip top to bottom
}

func rotateHalfTurn(_ grid: inout [[Int]]) {
    grid.reverse()
    for r in grid.indices {
        grid[r].reverse()
    }
}

var square = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
rotateCounterclockwise(&square)
print(square)

var board = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
rotateHalfTurn(&board)
print(board)
```

```output
[[3, 6, 9], [2, 5, 8], [1, 4, 7]]
[[9, 8, 7], [6, 5, 4], [3, 2, 1]]
```

`grid.reverse()` reverses the order of the **rows**, not the values inside them. Each row is an array, so this swaps whole rows, which costs O(1) per swap: Swift only exchanges the rows' references to their storage, not their contents.

All of these are **O(n²) time** with **O(1) extra space**.

## The other in-place method: rotating the rings

There's a second in-place approach, worth knowing about. Work one ring at a time, from the outside in, like the spiral in the last lesson. In each ring, four cells form a cycle under rotation: a top cell moves to the right side, that one to the bottom, that one to the left, and that one back to the top. Save one, shift the other three round, put the saved one in place, and repeat for every position along the ring's side.

Each cell moves exactly once, so it does fewer writes than transpose-then-reverse. But keeping four sets of indices straight is much more error-prone, which is why most people prefer the two flips in an interview.

<Callout kind="warning" title="Transposing every cell undoes itself">
A transpose loop over all `c` instead of `c > r` swaps each pair twice and leaves the grid unchanged. It's a silent bug, and it passes any test whose grid is symmetric. Test with a grid like `[[1, 2], [3, 4]]`, where the answer must change.
</Callout>

## Practice

**Rotate a square grid** asks for the clockwise rotation, in place. You have the transpose; work out what comes after it, and test sizes 1, 2, 3 and 4, since odd and even grids behave differently along the middle.

```cards

  back: "To (c, n − 1 − r)."
- id: transpose-in-place
  front: "How do you transpose a square grid in place?"
  back: "Swap `grid[r][c]` with `grid[c][r]` for every cell above the main diagonal (c > r), using a temporary variable. Visiting every cell would swap each pair twice."
- id: rotate-two-flips
  front: "How do you rotate a square grid 90° clockwise in place?"
  back: "Transpose it, then reverse each row. For counterclockwise, transpose and then reverse the order of the rows."
- id: rotate-rectangle
  front: "Why can't a non-square grid be rotated in place?"
  back: "Rotating an m × n grid gives an n × m grid, so the values can't stay in the same rows and columns. You build a new grid instead."
```
