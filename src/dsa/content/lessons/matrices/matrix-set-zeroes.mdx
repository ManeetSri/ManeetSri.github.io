## Why it matters

The task sounds almost too simple: wherever a grid holds a 0, set that cell's whole row and whole column to 0. Yet it's a favourite interview question, because the obvious code is wrong, the first fix uses extra memory, and the best answer stores its notes **inside the grid itself**. That last idea, using the input as your scratch space, comes back in the Game of Life at the end of this module and in several clever array problems later on.

## The problem

Given

```text
1 1 1
1 0 1
1 1 1
```

the single 0 clears the middle row and the middle column:

```text
1 0 1
0 0 0
1 0 1
```

Only zeroes in the **original** grid count. A cell that becomes 0 because of another zero doesn't spread any further.

## The obvious code is wrong

Scan the grid, and the moment you find a 0, clear its row and column:

```swift run
var grid = [
    [1, 1, 1],
    [1, 0, 1],
    [1, 1, 1],
]
let rows = grid.count
let columns = grid[0].count
for r in 0..<rows {
    for c in 0..<columns where grid[r][c] == 0 {
        for k in 0..<columns {
            grid[r][k] = 0
        }
        for k in 0..<rows {
            grid[k][c] = 0
        }
    }
}
for row in grid {
    print(row)
}
```

```output
[1, 0, 0]
[0, 0, 0]
[0, 0, 0]
```

The scan keeps going after the first clear, and finds the **new** zeroes it just wrote. Each one clears another row and column, which creates more zeroes, and the damage cascades. Writing while you're still reading is the bug. You can't tell a zero you wrote from one that was there originally.

The fix in every version below is the same: **first find all the original zeroes, then write.**

## Fix 1: marker arrays

Two arrays of `Bool` record which rows and which columns need clearing. The first pass only reads the grid and fills in the markers. The second pass only writes, clearing every cell whose row or column is marked:

```swift run
func spreadZeroes(_ grid: inout [[Int]]) {
    guard let columns = grid.first?.count else { return }
    var zeroRow = Array(repeating: false, count: grid.count)
    var zeroColumn = Array(repeating: false, count: columns)
    for r in grid.indices {
        for c in 0..<columns where grid[r][c] == 0 {
            zeroRow[r] = true
            zeroColumn[c] = true
        }
    }
    for r in grid.indices {
        for c in 0..<columns where zeroRow[r] || zeroColumn[c] {
            grid[r][c] = 0
        }
    }
}

var grid = [[1, 1, 1], [1, 0, 1], [1, 1, 1]]
spreadZeroes(&grid)
for row in grid {
    print(row)
}

var other = [[0, 2, 3, 0], [4, 5, 6, 7], [8, 9, 1, 2]]
spreadZeroes(&other)
for row in other {
    print(row)
}
```

```output
[1, 0, 1]
[0, 0, 0]
[1, 0, 1]
[0, 0, 0, 0]
[0, 5, 6, 0]
[0, 9, 1, 0]
```

**O(m × n) time** and **O(m + n) extra space** for an m × n grid. That's already much better than copying the whole grid, which would be O(m × n) space. For most real code, this is the version to write: it's clear and obviously correct.

## Fix 2: store the markers in the grid

Can you get rid of the two arrays? Look at what they hold: one flag per row and one per column. The grid already has a column with one cell per row, its **first column**, and a row with one cell per column, its **first row**. Use them as the marker arrays:

- `grid[r][0] == 0` means "clear row r".
- `grid[0][c] == 0` means "clear column c".

Writing a 0 marker into `grid[r][0]` is harmless, because if row r has a zero, that cell is going to be cleared anyway. The same goes for `grid[0][c]`.

There's one complication. The first row and first column are now doing two jobs: they hold markers for everyone else, but they're also ordinary cells that might need clearing themselves. A 0 in the first row could mean "column c has a zero somewhere", or it could be an original zero, meaning row 0 itself must be cleared. To keep those apart, check the first row and column **before** writing any markers, and remember the answers in two `Bool`s.

The whole method, in order:

1. Set `zeroFirstRow` if row 0 contains a 0, and `zeroFirstColumn` if column 0 contains a 0.
2. For every cell **outside** the first row and column that holds a 0, mark its row and column: `grid[r][0] = 0` and `grid[0][c] = 0`.
3. For every cell outside the first row and column, clear it if its row or column is marked.
4. Last of all, clear row 0 if `zeroFirstRow`, and column 0 if `zeroFirstColumn`.

Here it is on a 3 × 4 grid with zeroes at (1, 1) and (2, 3). Neither flag is set, because the first row and column contain no zeroes.

| After step | Grid |
| --- | --- |
| start | `1 2 3 4` / `5 0 7 8` / `9 10 11 0` |
| 2: mark | `1 0 3 0` / `0 0 7 8` / `0 10 11 0` |
| 3: clear marked inner cells | `1 0 3 0` / `0 0 0 0` / `0 0 0 0` |
| 4: flags | unchanged: neither flag is set |

Rows 1 and 2 and columns 1 and 3 are cleared, and the markers in the first row happen to be exactly the right final values.

Why does step 4 have to come last? Suppose the first row held an original 0 and you cleared the whole row before step 3. Every `grid[0][c]` would be 0, every column would look marked, and step 3 would wipe out the entire grid. The markers must be read before the first row and column are overwritten.

This version is **O(m × n) time** with **O(1) extra space**: two `Bool`s, however large the grid.

| Version | Extra space |
| --- | --- |
| copy the grid, read the copy | O(m × n) |
| marker arrays | O(m + n) |
| first row and column as markers | O(1) |

<Callout kind="gotcha" title="One cell, two jobs">
`grid[0][0]` sits in both the first row and the first column. If you try to use it as the marker for row 0 *and* column 0, you can't tell which one it means. That's why this lesson keeps two separate flags. Some solutions use `grid[0][0]` for one and a single flag for the other, which also works, but needs care about which is cleared first.
</Callout>

<Callout kind="tip">
"Can I store this in the input itself?" is a question worth asking whenever a problem says O(1) extra space. Cells you're going to overwrite anyway, spare bits in each value, or the sign of each number can all hold information temporarily. The Game of Life lesson uses spare bits.
</Callout>
