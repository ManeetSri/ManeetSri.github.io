## Why it matters

`[[Int]]` is a fine adjacency list when the vertices are numbered 0 to n − 1. Real graphs rarely are: their vertices are city names, package targets, grid cells or user IDs. In this lesson you'll build a reusable, generic `Graph<Vertex: Hashable>` that works for any of them, directed or undirected, weighted or not. It's the version that ships in DSAKit, and building it forces every design question a graph type raises: how to store edges, what a repeated edge means, how to keep output reproducible, and what each operation costs. Interviewers ask for exactly this kind of class to see whether you can make those decisions out loud.

## The design decisions

| Decision | Choice | Why |
| --- | --- | --- |
| Vertex type | generic, any `Hashable` | strings, numbers and your own structs all work as dictionary keys |
| Storage | adjacency lists in a dictionary keyed by vertex | O(V + E) memory, and neighbours in O(degree) |
| Directed or not | chosen once, in `init`, and stored in a `let` | one type serves both, and it can't change halfway |
| Weights | `Int`, 1 unless given | an unweighted graph is a graph whose weights are all 1 |
| A repeated edge | replaces the weight; never stored twice | `edgeCount` stays honest, as with a matrix cell |
| Order | vertices and neighbours in insertion order | the same code always prints the same output |
| Value or reference | a struct | copies are independent, like `Array` and `Dictionary` |

`Hashable` is the constraint from [Hashable and hash(into:)](/dsa/learn/swift-hashable): it's what a type needs to be a dictionary key or a set member, and the graph keys everything by vertex. The generic syntax is the one from [Generic functions and constraints](/dsa/learn/swift-generic-functions).

## Step 1: the storage

Five stored properties do the job:

```swift
struct Graph<Vertex: Hashable> {
    let isDirected: Bool
    private(set) var vertices: [Vertex] = []           // every vertex, in insertion order
    private(set) var edgeCount = 0
    private var targets: [Vertex: [Vertex]] = [:]      // the adjacency lists
    private var weights: [Vertex: [Vertex: Int]] = [:] // weights[u][v] is the edge u → v
    private var incoming: [Vertex: Int] = [:]          // in-degrees

    init(directed: Bool) {
        isDirected = directed
    }
}
```

Each one earns its place:

- **`targets`** is the adjacency list: for each vertex, the vertices its edges point to, in the order the edges were added.
- **`weights`** answers "is there an edge from u to v, and what does it weigh?" in O(1). Without it, spotting a repeated edge means walking u's list. With a vertex of 100,000 neighbours, that's 100,000 steps for every new edge.
- **`vertices`** keeps insertion order. A dictionary's keys come out in a different order each time the program runs, so looping over `targets.keys` would make every traversal's output change from run to run. An array beside the dictionary fixes that for the cost of one append per vertex.
- **`incoming`** counts edges arriving at each vertex, kept up to date as edges come and go, so `inDegree(of:)` is O(1) instead of a scan of every list.
- **`private(set)`** lets callers read `vertices` and `edgeCount` but not change them, so nothing outside can break the bookkeeping.

## Step 2: adding vertices

A vertex gets an empty list, an empty weight table and an in-degree of 0, unless it's already there:

```swift
@discardableResult
mutating func addVertex(_ vertex: Vertex) -> Bool {
    guard targets[vertex] == nil else { return false }
    targets[vertex] = []
    weights[vertex] = [:]
    incoming[vertex] = 0
    vertices.append(vertex)
    return true
}
```

It returns whether the vertex was new, and `@discardableResult` means callers who don't care can ignore that without a warning. Every step is O(1) on average.

## Step 3: adding edges

An undirected edge is two one-way edges, so write the one-way version once as a private helper and call it twice:

```swift
@discardableResult
private mutating func link(_ from: Vertex, _ to: Vertex, _ weight: Int) -> Bool {
    let isNew = weights[from]!.updateValue(weight, forKey: to) == nil
    if isNew {
        targets[from]!.append(to)
        incoming[to]! += 1
    }
    return isNew
}

@discardableResult
mutating func addEdge(from: Vertex, to: Vertex, weight: Int = 1) -> Bool {
    addVertex(from)
    addVertex(to)
    let isNew = link(from, to, weight)
    if !isDirected && from != to {
        link(to, from, weight)                         // the way back, unless it's a self-loop
    }
    if isNew {
        edgeCount += 1
    }
    return isNew
}
```

The details carry the design:

- **`updateValue(_:forKey:)` does two jobs.** It stores the new weight and returns the old one, or `nil` if the key was new. So one call both sets the weight and says whether this edge existed. If it did, the weight is replaced and the list is left alone: the edge keeps its place.
- **`weights[from]!.updateValue(...)` changes the inner dictionary in place.** The `!` unwraps the stored value for mutation; it doesn't copy it out. It can't crash, because `addVertex` ran first.
- **Missing vertices are added**, `from` before `to`, so building a graph from an edge list needs no separate vertex step.
- **A self-loop is stored once.** For an undirected edge from a vertex to itself, the way back is the same entry, so there's nothing more to add.
- **`edgeCount` goes up once per new edge**, even though an undirected edge sits in two lists.

## Step 4: reading the graph

```swift
func contains(_ vertex: Vertex) -> Bool {
    targets[vertex] != nil
}

func neighbors(of vertex: Vertex) -> [(vertex: Vertex, weight: Int)] {
    guard let list = targets[vertex], let weight = weights[vertex] else { return [] }
    return list.map { (vertex: $0, weight: weight[$0]!) }
}

func outDegree(of vertex: Vertex) -> Int { targets[vertex]?.count ?? 0 }
func inDegree(of vertex: Vertex) -> Int { incoming[vertex] ?? 0 }
func degree(of vertex: Vertex) -> Int {
    isDirected ? inDegree(of: vertex) + outDegree(of: vertex) : outDegree(of: vertex)
}
```

`neighbors(of:)` returns labelled tuples, so a caller can write `for (next, weight) in graph.neighbors(of: city)`. Asking about a vertex that isn't in the graph gives an empty list and degree 0 rather than a crash: graph algorithms ask about many vertices, and a crash in the middle of a search is a poor way to learn one was missing.

The degree follows [Graph terminology](/dsa/learn/graph-terminology): neighbours for an undirected graph, and in plus out for a directed one.

## Step 5: removing edges

Removal undoes `link` for each direction. The weight table says whether the edge exists; the list is where the work is, because finding an entry in an array means scanning it:

```swift
@discardableResult
private mutating func unlink(_ from: Vertex, _ to: Vertex) -> Bool {
    guard weights[from]?.removeValue(forKey: to) != nil else { return false }
    targets[from]!.remove(at: targets[from]!.firstIndex(of: to)!)
    incoming[to]! -= 1
    return true
}
```

That makes `removeEdge` O(degree), and `remove(at:)` keeps the other neighbours in their order. Both vertices stay in the graph. Removing edges is much rarer than adding them in algorithms, so trading a slower removal for O(1) adds and lookups is the right way round.

## The whole graph

Here it is in one piece, with `removeEdge`, a `description` and a demonstration:

```swift run
struct Graph<Vertex: Hashable> {
    let isDirected: Bool
    private(set) var vertices: [Vertex] = []           // every vertex, in insertion order
    private(set) var edgeCount = 0
    private var targets: [Vertex: [Vertex]] = [:]      // the adjacency lists
    private var weights: [Vertex: [Vertex: Int]] = [:] // weights[u][v] is the edge u → v
    private var incoming: [Vertex: Int] = [:]          // in-degrees

    init(directed: Bool) {
        isDirected = directed
    }

    func contains(_ vertex: Vertex) -> Bool {
        targets[vertex] != nil
    }

    @discardableResult
    mutating func addVertex(_ vertex: Vertex) -> Bool {
        guard targets[vertex] == nil else { return false }
        targets[vertex] = []
        weights[vertex] = [:]
        incoming[vertex] = 0
        vertices.append(vertex)
        return true
    }

    @discardableResult
    mutating func addEdge(from: Vertex, to: Vertex, weight: Int = 1) -> Bool {
        addVertex(from)
        addVertex(to)
        let isNew = link(from, to, weight)
        if !isDirected && from != to {
            link(to, from, weight)                     // the way back, unless it's a self-loop
        }
        if isNew {
            edgeCount += 1
        }
        return isNew
    }

    @discardableResult
    mutating func removeEdge(from: Vertex, to: Vertex) -> Bool {
        guard unlink(from, to) else { return false }
        if !isDirected && from != to {
            unlink(to, from)
        }
        edgeCount -= 1
        return true
    }

    func neighbors(of vertex: Vertex) -> [(vertex: Vertex, weight: Int)] {
        guard let list = targets[vertex], let weight = weights[vertex] else { return [] }
        return list.map { (vertex: $0, weight: weight[$0]!) }
    }

    func outDegree(of vertex: Vertex) -> Int { targets[vertex]?.count ?? 0 }
    func inDegree(of vertex: Vertex) -> Int { incoming[vertex] ?? 0 }
    func degree(of vertex: Vertex) -> Int {
        isDirected ? inDegree(of: vertex) + outDegree(of: vertex) : outDegree(of: vertex)
    }

    @discardableResult
    private mutating func link(_ from: Vertex, _ to: Vertex, _ weight: Int) -> Bool {
        let isNew = weights[from]!.updateValue(weight, forKey: to) == nil
        if isNew {
            targets[from]!.append(to)
            incoming[to]! += 1
        }
        return isNew
    }

    @discardableResult
    private mutating func unlink(_ from: Vertex, _ to: Vertex) -> Bool {
        guard weights[from]?.removeValue(forKey: to) != nil else { return false }
        targets[from]!.remove(at: targets[from]!.firstIndex(of: to)!)
        incoming[to]! -= 1
        return true
    }
}

extension Graph: CustomStringConvertible {
    var description: String {
        let arrow = isDirected ? "->" : "--"
        var lines = ["Graph(\(isDirected ? "directed" : "undirected"), \(vertices.count) vertices, \(edgeCount) edges)"]
        for vertex in vertices {
            let listed = neighbors(of: vertex).map { $0.weight == 1 ? "\($0.vertex)" : "\($0.vertex)(\($0.weight))" }
            lines.append("\(vertex) \(arrow) \(listed.isEmpty ? "(none)" : listed.joined(separator: ", "))")
        }
        return lines.joined(separator: "\n")
    }
}

var roads = Graph<String>(directed: false)
roads.addEdge(from: "Leeds", to: "York", weight: 40)
roads.addEdge(from: "Leeds", to: "Hull", weight: 95)
roads.addEdge(from: "York", to: "Hull", weight: 61)
roads.addVertex("Whitby")
print(roads)
print("Hull:", roads.neighbors(of: "Hull"))
print("new edge?", roads.addEdge(from: "Hull", to: "Leeds", weight: 90), "edges:", roads.edgeCount)
print("Leeds:", roads.neighbors(of: "Leeds").map { "\($0.vertex) \($0.weight)" })

var recipe = Graph<String>(directed: true)
recipe.addEdge(from: "shop", to: "cook")
recipe.addEdge(from: "cook", to: "eat")
recipe.addEdge(from: "shop", to: "eat")
for step in recipe.vertices {
    print(step, "in:", recipe.inDegree(of: step), "out:", recipe.outDegree(of: step))
}

var draft = recipe                                     // a copy: Graph is a struct
draft.removeEdge(from: "shop", to: "eat")
print("recipe:", recipe.edgeCount, "edges, draft:", draft.edgeCount, "edges")
```

```output
Graph(undirected, 4 vertices, 3 edges)
Leeds -- York(40), Hull(95)
York -- Leeds(40), Hull(61)
Hull -- Leeds(95), York(61)
Whitby -- (none)
Hull: [(vertex: "Leeds", weight: 95), (vertex: "York", weight: 61)]
new edge? false edges: 3
Leeds: ["York 40", "Hull 90"]
shop in: 0 out: 2
cook in: 1 out: 1
eat in: 2 out: 0
recipe: 3 edges, draft: 2 edges
```

What to notice:

- **The undirected edge Leeds–York appears in both lists**, yet `edgeCount` is 3, not 6.
- **Adding Hull–Leeds again found the edge added as Leeds–Hull** and only changed its weight, to 90, in both lists. Hull stays second in Leeds's list.
- **Whitby has no edges** but is still a vertex. A plain dictionary of lists would only have listed it if you remembered to insert an empty list.
- **Every line comes out in insertion order**, so this program prints the same thing every time you run it.
- **`draft` is an independent copy.** Removing an edge from it left `recipe` alone, because every stored property is a value type. That's [Collections are values](/dsa/learn/swift-collections-are-values) applied to a whole graph, and copying is cheap until one of the copies changes.

## The costs

| Operation | Time |
| --- | --- |
| `addVertex`, `addEdge`, `contains` | O(1) on average |
| `outDegree`, `inDegree`, `degree` | O(1) |
| `neighbors(of:)` | O(degree), to build the array of pairs |
| `removeEdge` | O(degree of the endpoints) |
| Memory | O(V + E) |

"On average" is the usual dictionary caveat from [Hash functions](/dsa/learn/hash-functions): with a reasonable hash, lookups are O(1).

## Testing a type like this

A handful of hand-picked cases won't find the subtle bugs: a self-loop counted twice, an in-degree that drifts after a removal, a duplicate edge that sneaks into a list. DSAKit's tests do what you did for heaps in [Build a generic `Heap<T>`](/dsa/learn/heap-build): they run 20,000 random adds and removals on the graph and, side by side, on a slow and obvious **model** (a dictionary of dictionaries), then check that both agree on every vertex's neighbours, weights and degrees. They also add 100,000 edges to a single vertex and then add them all again, which is fast only if repeated edges are found in O(1).

## DSAKit's Graph

DSAKit's `Graph` is this lesson's type with a few extras. It groups each vertex's list, weights and in-degree into one record, so a vertex costs one dictionary entry instead of three:

| Member | What it does | Cost |
| --- | --- | --- |
| `Graph<V>(directed:)` | an empty graph | O(1) |
| `init(directed:edges:)`, `init(directed:weightedEdges:)` | from `(from, to)` pairs or `(from, to, weight)` triples | O(V + E) |
| `addVertex(_:)`, `addEdge(from:to:weight:)` | add; true if something new was added | O(1) average |
| `removeEdge(from:to:)` | remove; true if the edge was there | O(degree) |
| `neighbors(of:)` | `(vertex:, weight:)` pairs, in insertion order | O(degree) |
| `adjacentVertices(of:)` | the neighbours without weights | O(1) |
| `vertices`, `vertexCount`, `edgeCount`, `isEmpty` | what's in the graph | O(1) |
| `contains(_:)`, `containsEdge(from:to:)`, `weight(from:to:)` | lookups | O(1) average |
| `outDegree(of:)`, `inDegree(of:)`, `degree(of:)` | degrees | O(1) |
| `edges` | every edge once, as an edge list | O(V + E) |

```swift
import DSAKit

let prerequisites = Graph<String>(directed: true, edges: [("Swift basics", "Generics"), ("Generics", "Graphs")])
prerequisites.inDegree(of: "Graphs")                        // 1
prerequisites.containsEdge(from: "Graphs", to: "Generics")  // false: edges have a direction
for (next, _) in prerequisites.neighbors(of: "Swift basics") {
    print(next)                                             // Generics
}
```

Two spelling notes. The method is `neighbors`, the American spelling that Swift's own APIs use; the lessons' prose keeps British "neighbours". And the graph deliberately has **no** `bfs()` or `topologicalSort()`: you'll write those yourself in the next modules, on top of `neighbors(of:)`, which is how they appear in interviews.

<Callout kind="gotcha" title="Swift gotchas in a graph type">
- **Looping over the dictionary.** `for vertex in targets.keys` visits vertices in a different order on every run, so a search prints different results each time. Loop over the `vertices` array.
- **Force-unwrapping a lookup for an unknown vertex.** `targets[vertex]!` crashes for a vertex that was never added. Use `targets[vertex] ?? []` in anything callers can reach.
- **Checking for duplicates by scanning.** `targets[from]!.contains(to)` is O(degree), and makes building a graph with a big hub O(E²). Keep a dictionary or set beside the list.
- **A class by accident.** If `Graph` were a class, `var draft = recipe` would share one graph, and removing an edge from the draft would change the recipe too.
</Callout>
