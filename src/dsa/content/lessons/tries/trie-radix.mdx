## Why it matters

A plain trie spends one node on every character, even where nothing branches: a lone word like "internationalisation" is a chain of 20 nodes, each with a single child. A **radix tree** (also called a compressed trie, or a Patricia trie) squeezes those chains into single edges labelled with whole strings. It's the version real systems use: routers matching network addresses, web frameworks matching URL paths, and the Linux kernel indexing cached file pages. Then there's the **suffix trie**, which stores every suffix of one text so that any substring can be found in time proportional to its own length. It's beautiful, it's expensive, and it leads straight to some of the most powerful string structures there are.

## Chains of single children

Build a plain trie from eight words that start alike, and count the nodes that have exactly one child and don't end a word. Those nodes make no decisions: the path through them has only one way to go.

```swift run
final class TrieNode {
    var children: [Character: TrieNode] = [:]
    var isWord = false
}

let words = ["in", "into", "integer", "integral", "internal", "internet", "interval", "interview"]
let root = TrieNode()
for word in words {
    var node = root
    for character in word {
        if node.children[character] == nil {
            node.children[character] = TrieNode()
        }
        node = node.children[character]!
    }
    node.isWord = true
}

var nodes = 0
var chainNodes = 0                               // one child, and no word ends here
var pending = [root]
while let node = pending.popLast() {
    for child in node.children.values {
        nodes += 1
        if child.children.count == 1 && !child.isWord {
            chainNodes += 1
        }
        pending.append(child)
    }
}
print("letters:", words.reduce(0) { $0 + $1.count })
print("trie nodes:", nodes)
print("nodes with one child and no word:", chainNodes)
```

```output
letters: 54
trie nodes: 23
nodes with one child and no word: 9
```

Sharing already cut 54 letters down to 23 nodes, but 9 of those 23 only pass you along. In real word lists, where most words end in a long unshared tail, the share of such nodes is much higher, and every one of them is an object with its own dictionary.

## The radix tree: edges with labels

Merge every chain into one edge, and label the edge with the string it spells. After that, every node except the root either has two or more children or ends a word. The labels of a node's children all start with different characters, so a child can still be found by its first character.

Inserting a word is a walk with one new case. Compare the rest of the word with the label of the child it should go to:

- **No child starts with the next character**: add one leaf whose label is the whole rest of the word.
- **The whole label matches**: go down to that child, and continue with what's left of the word.
- **Only part of the label matches**: **split the edge**. A new node takes the shared part of the label, the old child keeps the rest of its label and hangs below the new node, and the word continues from the new node.

Here's the split in code, and the tree it builds:

```swift run
final class RadixNode {
    var label: String                            // the characters on the edge into this node
    var children: [Character: RadixNode] = [:]   // keyed by the first character of each child's label
    var isWord = false

    init(_ label: String) {
        self.label = label
    }
}

func sharedLength(_ a: Substring, _ b: Substring) -> Int {
    var length = 0
    for (x, y) in zip(a, b) {
        if x != y { break }
        length += 1
    }
    return length
}

func insert(_ word: String, into root: RadixNode) {
    var node = root
    var rest = Substring(word)
    while let first = rest.first {
        guard let child = node.children[first] else {
            let leaf = RadixNode(String(rest))   // nothing shares this start: one edge for all of it
            leaf.isWord = true
            node.children[first] = leaf
            return
        }
        let shared = sharedLength(child.label[...], rest)
        if shared < child.label.count {
            // The edge only partly matches: split it, with a new node for the shared part
            let middle = RadixNode(String(child.label.prefix(shared)))
            child.label = String(child.label.dropFirst(shared))
            middle.children[child.label.first!] = child
            node.children[first] = middle
            node = middle
        } else {
            node = child                         // the whole edge matches: go down it
        }
        rest = rest.dropFirst(shared)
    }
    node.isWord = true
}

func contains(_ word: String, in root: RadixNode) -> Bool {
    var node = root
    var rest = Substring(word)
    while let first = rest.first {
        guard let child = node.children[first], rest.hasPrefix(child.label) else { return false }
        rest = rest.dropFirst(child.label.count)
        node = child
    }
    return node.isWord
}

func show(_ node: RadixNode, depth: Int) {
    for key in node.children.keys.sorted() {
        let child = node.children[key]!
        print(String(repeating: "  ", count: depth) + child.label + (child.isWord ? "  (word)" : ""))
        show(child, depth: depth + 1)
    }
}

let root = RadixNode("")
for word in ["in", "into", "integer", "integral", "internal", "internet", "interval", "interview"] {
    insert(word, into: root)
}
show(root, depth: 0)
print(contains("internet", in: root), contains("inter", in: root), contains("integers", in: root))
```

```output
in  (word)
  t
    e
      g
        er  (word)
        ral  (word)
      r
        n
          al  (word)
          et  (word)
        v
          al  (word)
          iew  (word)
    o  (word)
true false false
```

Fourteen nodes instead of 23, and the long tails "ral", "iew" and "er" are single edges. Every node shown either branches or ends a word. "inter" isn't found: its path ends at the node for "inter", which exists because of the split, but no word ends there.

What to notice in the code:

- `child.label[...]` turns the label into a `Substring`, and `rest.dropFirst(shared)` moves along the word without copying it, as in [Substring and memory](/dsa/learn/swift-substring).
- When "integer" arrived after "into", the edge "to" was split into "t", with "o" and "eger" below it. Later words split again: "integral" split "eger" into "eg" and "er", and "internal" split "eg" into "e" and "g".
- `contains` must check the **whole label** with `hasPrefix`, not only its first character.

**How many nodes?** A radix tree with w words has at most w leaves, and every internal node branches at least two ways or ends a word, so it has fewer than 2w nodes below the root, whatever the words' lengths. A plain trie can need one node per letter. The price: labels are strings, and insertion has the split case. Production radix trees avoid copying labels by storing each label as a start and end index into a stored key, or packing nodes into compact byte layouts.

## Suffix tries: every substring at once

Now a different question. You have one long text, such as a genome or a book, and many queries of the form "does p appear anywhere in the text?". Searching from scratch costs O(n × |p|) per query with the naive matching from [Naive pattern matching](/dsa/learn/str-naive-matching).

The key observation: **every substring is a prefix of some suffix**. "nan" appears in "banana" because it's the start of the suffix "nana". So insert all n suffixes of the text into a trie, a **suffix trie**, and then every substring query is a prefix walk: O(|p|), however long the text.

Each node of a suffix trie spells exactly one distinct substring of the text, so it has one node per distinct substring. That's the catch. A text of length n has up to n(n + 1)/2 distinct substrings, so the trie can have **O(n²) nodes**. Count them for made-up DNA:

```swift run
final class Node {
    var children: [Character: Node] = [:]
}

func suffixTrieNodes(_ text: String) -> Int {
    let letters = Array(text)
    let root = Node()
    var nodes = 0
    for start in letters.indices {               // insert the suffix starting at each position
        var node = root
        for character in letters[start...] {
            if node.children[character] == nil {
                node.children[character] = Node()
                nodes += 1
            }
            node = node.children[character]!
        }
    }
    return nodes
}

// Made-up DNA, the same every run
var seed = 11
let bases = Array("acgt")
func dna(_ length: Int) -> String {
    var text = ""
    for _ in 0..<length {
        seed = (seed * 1_103_515_245 + 12_345) % 2_147_483_648
        text.append(bases[(seed >> 16) % 4])
    }
    return text
}

for n in [100, 200, 400] {
    let nodes = suffixTrieNodes(dna(n))
    print("n = \(n): \(nodes) nodes, n(n + 1)/2 = \(n * (n + 1) / 2)")
}
print("all a's, n = 400:", suffixTrieNodes(String(repeating: "a", count: 400)), "nodes")
```

```output
n = 100: 4802 nodes, n(n + 1)/2 = 5050
n = 200: 19495 nodes, n(n + 1)/2 = 20100
n = 400: 78827 nodes, n(n + 1)/2 = 80200
all a's, n = 400: 400 nodes
```

Doubling the text roughly quadruples the nodes, and random text gets close to the maximum: almost every substring longer than a few letters appears only once. (A text of one repeated letter is the opposite extreme: its suffixes are all prefixes of one another, so it needs only n nodes.) A real genome has billions of letters, and n² nodes is out of the question. Building the trie is O(n²) time as well.

## Where this leads

Two ideas tame the suffix trie, and both come later in the course:

- **Compress it.** A radix tree of the suffixes is a **suffix tree**. It has n leaves, one per suffix (with an end marker added so no suffix is a prefix of another), so it has fewer than 2n nodes. Store each edge label as a pair of indexes into the text rather than a copy, and it takes O(n) space. Clever algorithms, such as Ukkonen's, even build it in O(n) time, though they're intricate.
- **Replace it.** A **suffix array** is nothing more than the starting positions of the suffixes, sorted. It's far smaller and simpler to build, in O(n log n), and binary search over it answers substring queries. A **suffix automaton** packs all the substrings into at most 2n states. Both appear in the string algorithms module of Part VIII, along with **Aho–Corasick**, which adds "failure links" to an ordinary trie of patterns so that one pass over a text finds every occurrence of every pattern.

For a text of a few thousand letters, though, the plain suffix trie is perfectly practical, and the simplest of them all to write.

<Callout kind="gotcha" title="Splitting an edge">
The split is where radix tree bugs live. After the shared part moves to the new middle node, the old child's label must lose exactly that part, and the old child must be re-filed under the **first character of its shortened label**, not its old one. Then the parent's entry must point at the middle node. Draw the before and after for "into" then "integer" before writing the code, and test words that are prefixes of each other in both orders ("in" then "into", and "into" then "in").
</Callout>
