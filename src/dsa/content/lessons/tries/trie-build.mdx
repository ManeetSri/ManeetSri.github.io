## Why it matters

Last lesson showed what a trie looks like. This one builds a complete `Trie` class with the three classic operations: **insert** a word, **search** for a whole word, and check whether any word **starts with** a prefix. "Implement a trie" is one of the most common interview design questions, and the class you write here is the base for everything else in this module: counting, deleting, autocomplete and word search. Along the way you'll weigh a real design decision, how each node should store its children, and measure it.

## The node is a class

Each node needs its children and an end-of-word flag:

```swift
final class Node {
    var children: [Character: Node] = [:]
    var isWord = false
}
```

Why a class rather than a struct? Every operation walks down the tree with a variable, `var node = root`, then `node = child`, and `insert` changes the nodes it passes. With a class, `node` refers to the real node inside the tree, so changing `node.children` changes the tree. With a struct, `var node = root` makes a **copy**, and changes land on the copy:

```swift run
struct StructNode {
    var children: [Character: StructNode] = [:]
    var isWord = false
}

var root = StructNode()
var node = root                          // a copy of root, not root itself
node.children["c"] = StructNode()
print("root has", root.children.count, "children; the copy has", node.children.count)
```

```output
root has 0 children; the copy has 1
```

This is the difference between value and reference semantics from [Value vs reference semantics](/dsa/learn/swift-value-vs-reference), and the same choice you met in [TreeNode in Swift: class vs indirect enum](/dsa/learn/tree-node-swift). A struct trie can be made to work, by rebuilding the path recursively with `inout`, but a class says what you mean: there is one node for each prefix, and everyone who reaches it sees the same node. Mark it `final`, since nothing subclasses it.

## insert

Start at the root. For each character, move to the child for that character, creating the child first if it's missing. After the last character, set the flag:

```swift
func insert(_ word: String) {
    var node = root
    for character in word {
        if let next = node.children[character] {
            node = next                          // the prefix already exists: share it
        } else {
            let next = Node()
            node.children[character] = next      // a new branch starts here
            node = next
        }
    }
    node.isWord = true
}
```

Each character costs one dictionary lookup and at most one insertion, so inserting a word of length L is **O(L)**. Inserting a word that's already there walks the same path, creates nothing, and sets a flag that was already set: harmless.

Trace four inserts into an empty trie:

| Insert | The walk | New nodes | Flag set on |
| --- | --- | --- | --- |
| car | c, a and r are all missing | 3 | car |
| cart | c, a and r exist; t is missing below car | 1 | cart |
| cat | c and a exist; there's no t below ca yet | 1 | cat |
| car again | every node exists | 0 | car, which was already set |

Notice the two different "t" nodes: one below "car" (for cart) and one below "ca" (for cat). A node is identified by its whole path from the root, not by its character.

`for character in word` steps through the word's `Character` values, so "café" takes four steps, and an emoji is one step. That's the Unicode-correct behaviour from [Unicode and grapheme clusters](/dsa/learn/swift-unicode), and it comes free with `Character` keys.

## search and startsWith

Both make the same walk without creating anything. If a child is missing along the way, no stored word starts like that, and both answers are false. The difference is the last step:

- **search** asks whether the word itself was inserted, so it returns the final node's `isWord`.
- **startsWith** only asks whether the path exists, so reaching the end at all means yes.

Write the walk once, as a helper that returns the node a string leads to, or `nil`:

```swift
private func node(for text: String) -> Node? {
    var node = root
    for character in text {
        guard let next = node.children[character] else { return nil }
        node = next
    }
    return node
}

func search(_ word: String) -> Bool {
    node(for: word)?.isWord ?? false
}

func startsWith(_ prefix: String) -> Bool {
    node(for: prefix) != nil
}
```

`node(for: word)?.isWord` is optional chaining: if the walk fell off, the whole expression is `nil`, and `?? false` turns that into `false`. Both are **O(L)** for a string of length L.

## The whole class

Put together, with the node type nested inside so its short name can't clash with anything else:

```swift run
final class Trie {
    final class Node {
        var children: [Character: Node] = [:]
        var isWord = false
    }

    private let root = Node()

    func insert(_ word: String) {
        var node = root
        for character in word {
            if let next = node.children[character] {
                node = next
            } else {
                let next = Node()
                node.children[character] = next
                node = next
            }
        }
        node.isWord = true
    }

    func search(_ word: String) -> Bool {
        node(for: word)?.isWord ?? false
    }

    func startsWith(_ prefix: String) -> Bool {
        node(for: prefix) != nil
    }

    private func node(for text: String) -> Node? {
        var node = root
        for character in text {
            guard let next = node.children[character] else { return nil }
            node = next
        }
        return node
    }
}

let trie = Trie()
for word in ["apple", "app", "apply", "ape"] {
    trie.insert(word)
}
for query in ["app", "appl", "apple", "apt", "b"] {
    print(query, "search:", trie.search(query), "startsWith:", trie.startsWith(query))
}
```

```output
app search: true startsWith: true
appl search: false startsWith: true
apple search: true startsWith: true
apt search: false startsWith: false
b search: false startsWith: false
```

What to notice:

- "appl" is a prefix of "apple" and "apply" but not a word, so `search` says false and `startsWith` says true.
- "apt" shares "ap" with the stored words, but there's no "t" child below "ap", so the walk falls off after two steps.
- `root` is a `let`. The trie always keeps the same root object; only that object's contents change. That's allowed because `Node` is a class.

## Edge cases worth knowing

**The empty string.** Inserting `""` walks zero characters and sets the flag on the root itself. Then `search("")` is true. And `startsWith("")` is always true in the class above, even for an empty trie, because the walk never fails. Whether that's right depends on what you want "starts with" to mean: some designs say the empty prefix matches only when the trie holds at least one word. Decide, and test it.

**Case and other differences.** "Car" and "car" are different paths, because "C" and "c" are different characters. If case shouldn't matter, lowercase every word before inserting and every query before searching. The trie stores exactly what you give it.

```swift run
final class Node {
    var children: [Character: Node] = [:]
    var isWord = false
}

let root = Node()

func insert(_ word: String) {
    var node = root
    for character in word {
        if node.children[character] == nil {
            node.children[character] = Node()
        }
        node = node.children[character]!
    }
    node.isWord = true
}

func search(_ word: String) -> Bool {
    var node = root
    for character in word {
        guard let next = node.children[character] else { return false }
        node = next
    }
    return node.isWord
}

print(search(""))                 // nothing inserted yet
insert("")
print(search(""))                 // the root itself is now marked
insert("Car")
print(search("car"), search("Car"))
insert("Dog".lowercased())        // normalise words going in…
print(search("DOG".lowercased())) // …and queries too
```

```output
false
true
false true
true
```

## Checking it against a Set

A trie has a few moving parts, and small hand-written tests can miss a slip like a missing flag on one path. A strong habit is to test a data structure against a **model**: a simpler structure that's obviously correct, even if it's slow. For a trie, the model is a `Set` of the words plus a `Set` of all their prefixes. Run thousands of random operations on both, and count disagreements:

```swift run
final class Trie {
    final class Node {
        var children: [Character: Node] = [:]
        var isWord = false
    }

    private let root = Node()

    func insert(_ word: String) {
        var node = root
        for character in word {
            if let next = node.children[character] {
                node = next
            } else {
                let next = Node()
                node.children[character] = next
                node = next
            }
        }
        node.isWord = true
    }

    func search(_ word: String) -> Bool {
        node(for: word)?.isWord ?? false
    }

    func startsWith(_ prefix: String) -> Bool {
        node(for: prefix) != nil
    }

    private func node(for text: String) -> Node? {
        var node = root
        for character in text {
            guard let next = node.children[character] else { return nil }
            node = next
        }
        return node
    }
}

// Short random words from three letters, so many share prefixes; the same every run
var seed = 40
func nextNumber(below limit: Int) -> Int {
    seed = (seed * 1_103_515_245 + 12_345) % 2_147_483_648
    return (seed >> 16) % limit
}
let letters = Array("abc")
func randomWord() -> String {
    String((0...nextNumber(below: 5)).map { _ in letters[nextNumber(below: 3)] })
}

let trie = Trie()
var words = Set<String>()                        // the model: obviously correct, if slow for prefixes
var prefixes = Set<String>()
var checks = 0
var mismatches = 0
for _ in 0..<2_000 {
    let word = randomWord()
    if nextNumber(below: 2) == 0 {
        trie.insert(word)
        words.insert(word)
        for length in 1...word.count {
            prefixes.insert(String(word.prefix(length)))
        }
    } else {
        checks += 2
        if trie.search(word) != words.contains(word) { mismatches += 1 }
        if trie.startsWith(word) != prefixes.contains(word) { mismatches += 1 }
    }
}
print("distinct words:", words.count, "checks:", checks, "mismatches:", mismatches)
```

```output
distinct words: 249 checks: 2072 mismatches: 0
```

Three letters and short words are deliberate: with so few possibilities, queries often hit stored words, their prefixes and near misses, which is where bugs hide. With random 10-letter words, almost every query would be a plain miss. The random numbers come from a fixed formula and seed, so every run makes the same "random" choices, and a failure can be reproduced. The tests for this module's problems, and for DSAKit's `Trie`, work exactly this way.

## When a Set is the better choice

If all you ever ask is "is this exact word stored?", use a `Set<String>`. It's one line, it stores one entry per word instead of up to one node per letter (each node a separate object with its own dictionary), and lookups are O(L) on average too. If the word list never changes, a sorted array with binary search, as in [Lower bound, upper bound, first and last occurrence](/dsa/learn/bs-bounds), answers prefix questions compactly as well.

Reach for a trie when prefixes are the point and the words change: counting or listing the words under a prefix, suggesting completions as someone types, or walking a word letter by letter and reacting at each step, as the rest of this module does.

## Children: a dictionary or an array of 26?

Many interview problems promise "lowercase English letters only". Then each node can keep a fixed array of 26 optional children, one slot per letter, instead of a dictionary:

```swift
final class Node {
    var children = [Node?](repeating: nil, count: 26)
    var isWord = false
}

func insert(_ word: String) {
    var node = root
    for byte in word.utf8 {
        let slot = Int(byte - 97)                // "a" is 97, so a → 0, b → 1, … z → 25
        if node.children[slot] == nil {
            node.children[slot] = Node()
        }
        node = node.children[slot]!
    }
    node.isWord = true
}
```

`word.utf8` hands over the bytes directly, as in [Array(s) and [UInt8] for fast access](/dsa/learn/swift-string-to-array), and the slot is the same "letter minus 97" trick as [Frequency counting with 26 slots](/dsa/learn/swift-frequency-arrays). Both versions are O(L) per operation. The differences are in the constant factors and the memory.

**Speed.** An array step is one subtraction and one index. A dictionary step hashes the `Character`, which means looking at its Unicode scalars, then probes a table. Both are O(1), but the array does less work per step, and its slots are already in alphabetical order, which you'll use for autocomplete.

**Memory.** Every array node reserves 26 slots, whether it uses them or not. Most nodes are near the bottom of the trie, where they have one child or none. Count the slots for 2,000 made-up words:

```swift run
final class ArrayNode {
    var children = [ArrayNode?](repeating: nil, count: 26)
    var isWord = false
}

// 2,000 made-up lowercase words of 3 to 8 letters, the same every run
var seed = 2_024
func nextNumber(below limit: Int) -> Int {
    seed = (seed * 1_103_515_245 + 12_345) % 2_147_483_648
    return (seed >> 16) % limit
}
let alphabet = Array("abcdefghijklmnopqrstuvwxyz".utf8)
var words: [[UInt8]] = []
for _ in 0..<2_000 {
    words.append((0..<(3 + nextNumber(below: 6))).map { _ in alphabet[nextNumber(below: 26)] })
}

let root = ArrayNode()
var nodes = 1                                    // the root
for word in words {
    var node = root
    for byte in word {
        let slot = Int(byte - 97)
        if node.children[slot] == nil {
            node.children[slot] = ArrayNode()
            nodes += 1
        }
        node = node.children[slot]!
    }
    node.isWord = true
}

let slots = 26 * nodes
let used = nodes - 1                             // every node but the root fills one slot
print("nodes:", nodes)
print("child slots:", slots, "in use:", used)
print("share in use:", used * 100 / slots, "percent")
print("bytes per slot:", MemoryLayout<ArrayNode?>.size)
```

```output
nodes: 7534
child slots: 195884 in use: 7533
share in use: 3 percent
bytes per slot: 8
```

Fewer than 4 slots in every 100 hold a child. The other 188,351 are `nil`, 8 bytes each: about 1.5 MB holding nothing. The dictionary version stores only the 7,533 children that exist, each as a key and a reference, plus some spare room so hashing works well. (Each non-empty dictionary also carries a small fixed overhead, so near the top of a busy trie, where nodes have many children, the array can win on memory too.)

| | `[Character: Node]` | 26-slot array |
| --- | --- | --- |
| Characters | any Unicode text | lowercase a–z only |
| Work per step | hash and probe | subtract and index |
| Memory per node | only the children it has | always 26 slots |
| Children in sorted order | no: sort the keys | yes, for free |

The rule of thumb: for an interview problem that promises lowercase letters, the array is the classic answer, and it's quick to write. For real text, such as names, search queries or anything with accents or emoji, use the dictionary. Counting nodes and slots, as above, tells you more than a stopwatch would: it says why one uses more memory, and the answer doesn't change from one machine to the next.

## DSAKit's Trie

The companion package's `Trie` is the finished version of this lesson, with the extras from the rest of the module:

```swift
import DSAKit

var words: Trie = ["car", "cart", "cat", "dog"]
words.insert("care")                  // true: it's new
words.contains("car")                 // true (the lesson calls this search)
words.hasPrefix("ca")                 // true (startsWith)
words.count(withPrefix: "car")        // 3: car, care, cart
words.words(withPrefix: "car")        // ["car", "care", "cart"]
words.remove("cart")                  // true, and the unused node is removed
```

It uses `Character` keys, so any Unicode word works, and it's a **struct** whose nodes are classes, guarded by copy-on-write: copying a `Trie` gives an independent trie, and the nodes are only duplicated when one copy changes. That's the technique from [Writing your own copy-on-write](/dsa/learn/swift-implementing-cow). The `count(withPrefix:)` and `remove` methods come from the next lesson.

## The costs

| Operation | Time | Notes |
| --- | --- | --- |
| `insert` | O(L) | creates at most L nodes |
| `search` | O(L) | checks the flag at the end |
| `startsWith` | O(L) | only checks that the path exists |
| Memory | O(total letters) | less when words share prefixes |

None of these mention n, the number of words. That's the point of a trie.

<Callout kind="gotcha" title="Swift gotchas in a trie">
**Forgetting the flag.** An `insert` that creates the path but never sets `isWord = true` makes `startsWith` work and `search` always fail. Test both.

**Bytes for non-letters.** `Int(byte - 97)` assumes lowercase a–z. A capital letter (byte 65) makes the `UInt8` subtraction overflow and crash; an opening brace, `{` (byte 123), gives slot 26, out of range. Use the byte version only when the input is promised, and the dictionary otherwise.

**Struct nodes.** If `Node` is a struct, `var node = root` copies it, inserts change the copy, and the trie stays empty without any error. Use a class.
</Callout>
