## Why it matters

Autocomplete is everywhere in apps: a city picker that narrows as you type, a contacts search, an emoji picker, a code editor's completions, the keyboard's suggestions above the letters. Under each one is the same question, "which words start with what's been typed, and which few should be shown?" A trie answers the first half by walking to the prefix's node. This lesson adds the second half: listing the words below that node in a sensible order, stopping after a few, ranking them by popularity, and updating them keystroke by keystroke without starting over.

## Every word under a prefix, in order

Once you're at the node for "car", every stored word that starts with "car" is that node's own word (if "car" is one) or a word somewhere below it. So: walk to the node, then do a depth-first search below it, recording each word you pass.

The order of that search decides the order of the results. Do it like this:

1. record the current node's word first, if it is one;
2. then visit the children in sorted order of their characters.

That produces the words **alphabetically**. A word comes before its own extensions ("car" before "card"), which step 1 guarantees. And every word under the "d" branch comes before every word under the "e" branch, because "card" < "care" is decided by that one character, which step 2 guarantees. It's the preorder traversal from [Preorder, inorder and postorder](/dsa/learn/trav-dfs-recursive), applied to a tree with many children.

Here it is, building each word in a `path` string as the search goes down: append a character before visiting a child, remove it after.

```swift run
final class Node {
    var children: [Character: Node] = [:]
    var isWord = false
}

let root = Node()

func insert(_ word: String) {
    var node = root
    for character in word {
        if node.children[character] == nil {
            node.children[character] = Node()
        }
        node = node.children[character]!
    }
    node.isWord = true
}

func collect(_ node: Node, _ path: inout String, _ found: inout [String], _ limit: Int) {
    if found.count == limit { return }
    if node.isWord {
        found.append(path)
    }
    for character in node.children.keys.sorted() {
        path.append(character)
        collect(node.children[character]!, &path, &found, limit)
        path.removeLast()
    }
}

func words(withPrefix prefix: String, limit: Int = Int.max) -> [String] {
    var node = root
    for character in prefix {
        guard let next = node.children[character] else { return [] }
        node = next
    }
    var found: [String] = []
    var path = prefix
    collect(node, &path, &found, limit)
    return found
}

for word in ["cart", "car", "careful", "cat", "card", "do", "care", "catalog", "dog"] {
    insert(word)
}
print(words(withPrefix: "car"))
print(words(withPrefix: "ca", limit: 3))
print(words(withPrefix: "d"))
print(words(withPrefix: "x"))
```

```output
["car", "card", "care", "careful", "cart"]
["car", "card", "care"]
["do", "dog"]
[]
```

What to notice:

- The words went in jumbled, and came out sorted.
- `node.children.keys.sorted()` is essential. A dictionary's order changes from run to run, so without sorting, the suggestions would shuffle every time the app launched. With the 26-slot array children from [Build a Trie: insert, search, startsWith](/dsa/learn/trie-build), the slots are already in order.
- Building the word in one `path` buffer, appending and removing a character at a time, avoids making a new string at every node.

Watch the walk to the prefix and the words collected below it:

```visual trie

prefix: car
```

## Stopping early

A search box shows a handful of suggestions, not hundreds. The `limit` parameter stops the search as soon as enough words are found: `collect` returns straight away once `found` is full, so the rest of the subtree is never visited.

That changes the cost. Listing **all** m words under a prefix is O(L + the size of the subtree). Listing the first k is O(L + the nodes visited before the k-th word), which, for short words, is roughly O(L + k × average word length), however many words the prefix has. The prefix "s" might have 50,000 completions, and finding the first five still takes a moment.

DSAKit's `Trie` has the same parameter: `words(withPrefix: "s", limit: 5)`.

## Ranking by popularity

Alphabetical order is predictable, but people usually want the most likely words first. Give each word a count, such as how often it's been chosen, and store it at the word's node instead of a plain flag (0 means "not a word"). Then collect every completion with its count, sort, and keep the top k:

```swift run
final class Node {
    var children: [Character: Node] = [:]
    var frequency = 0                            // 0: no word ends here
}

let root = Node()

func insert(_ word: String, frequency: Int) {
    var node = root
    for character in word {
        if node.children[character] == nil {
            node.children[character] = Node()
        }
        node = node.children[character]!
    }
    node.frequency = frequency
}

func collect(_ node: Node, _ path: inout String, _ found: inout [(word: String, frequency: Int)]) {
    if node.frequency > 0 {
        found.append((path, node.frequency))
    }
    for character in node.children.keys.sorted() {
        path.append(character)
        collect(node.children[character]!, &path, &found)
        path.removeLast()
    }
}

func top(_ k: Int, withPrefix prefix: String) -> [String] {
    var node = root
    for character in prefix {
        guard let next = node.children[character] else { return [] }
        node = next
    }
    var found: [(word: String, frequency: Int)] = []
    var path = prefix
    collect(node, &path, &found)
    found.sort { $0.frequency != $1.frequency ? $0.frequency > $1.frequency : $0.word < $1.word }
    return found.prefix(k).map { $0.word }
}

let history = [("car", 120), ("card", 45), ("care", 300), ("careful", 45), ("cart", 80), ("cat", 500), ("catalog", 12)]
for (word, count) in history {
    insert(word, frequency: count)
}
print(top(3, withPrefix: "ca"))
print(top(5, withPrefix: "car"))
```

```output
["cat", "care", "car"]
["care", "car", "cart", "card", "careful"]
```

The sort puts higher counts first and breaks ties alphabetically, so "card" and "careful", both chosen 45 times, always come out in the same order. Without a tie-break, equal counts could swap between runs.

This costs O(m log m) for m completions, because every completion is collected and sorted. Three ways to do better, in increasing order of effort:

- **A heap of size k**: keep only the k best seen so far, as in [Top K, kth largest and K closest](/dsa/learn/heap-top-k). That's O(m log k) instead of O(m log m).
- **Best k at every node**: when building the trie, store at each node the k most popular words below it. A query then walks to the prefix's node and reads its list, O(L). The price is k extra entries per node, and an insert or count change must update the lists along its path.
- **Both at scale**: real search engines precompute the lists, and add a lot more besides: ranking signals, spelling correction and sharding across machines. That's a system design topic, covered near the end of the course.

## Search as you type

As someone types, each keystroke adds one character to the prefix. Walking from the root every time repeats the earlier steps. Instead, keep the node you've reached and step to its child for the new character: O(1) per keystroke to move, plus the cost of collecting suggestions.

Backspace needs the previous node again. Keep the nodes you've passed on a stack (an array), push on each keystroke and pop on backspace. If the typed text falls off the trie, there's no node to push, so count how many characters are "lost" instead, and pop those first on backspace:

```swift run
final class Node {
    var children: [Character: Node] = [:]
    var isWord = false
}

let root = Node()
for word in ["cab", "car", "card", "care", "cart", "cat", "dog"] {
    var node = root
    for character in word {
        if node.children[character] == nil {
            node.children[character] = Node()
        }
        node = node.children[character]!
    }
    node.isWord = true
}

func firstWords(under node: Node, path: String, limit: Int) -> [String] {
    var found: [String] = []
    var pending = [(node, path)]                 // a stack, so the search is depth first
    while let (current, word) = pending.popLast(), found.count < limit {
        if current.isWord {
            found.append(word)
        }
        for character in current.children.keys.sorted().reversed() {
            pending.append((current.children[character]!, word + String(character)))
        }
    }
    return found
}

var stack = [root]                               // stack.last is the node for the text typed so far
var typed = ""
var lost = 0                                     // characters typed after falling off the trie
for key in ["c", "a", "r", "⌫", "t", "x", "⌫"] {
    if key == "⌫" {
        typed.removeLast()
        if lost > 0 { lost -= 1 } else { stack.removeLast() }
    } else {
        typed += key
        if lost == 0, let next = stack.last!.children[Character(key)] {
            stack.append(next)
        } else {
            lost += 1
        }
    }
    let shown = lost > 0 ? [] : firstWords(under: stack.last!, path: typed, limit: 3)
    print("typed \"\(typed)\":", shown)
}
```

```output
typed "c": ["cab", "car", "card"]
typed "ca": ["cab", "car", "card"]
typed "car": ["car", "card", "care"]
typed "ca": ["cab", "car", "card"]
typed "cat": ["cat"]
typed "catx": []
typed "cat": ["cat"]
```

What to notice:

- Each keystroke moved one node down or up the stack. Nothing ever walked from the root again.
- `firstWords` does the same depth-first search as before, but with an explicit stack instead of recursion. Pushing the children in **reverse** sorted order makes the smallest come off the stack first, so the words still come out alphabetically.
- After "catx" fell off the trie, the backspace only undid the lost character, and "cat" was back with its suggestion.

In a SwiftUI app, the simplest version doesn't even need the stack: DSAKit's `Trie` is fast enough to walk from the root on every change, because the walk is O(L) and the limit stops the collection early.

```swift
import SwiftUI
import DSAKit

struct CityPicker: View {
    let cities: Trie                             // built once, from lowercased names
    @State private var query = ""

    var body: some View {
        NavigationStack {
            List(cities.words(withPrefix: query.lowercased(), limit: 10), id: \.self) { city in
                Text(city)
            }
            .searchable(text: $query)
        }
    }
}
```

Normalise both sides the same way. If the names went in lowercased, lowercase the query. If accents shouldn't matter, so that "sao" finds "são paulo", strip them from both before inserting and searching.

<Callout kind="gotcha" title="Autocomplete slips">
**Unsorted children.** Iterating `node.children` directly gives a different order each run. Sort the keys, or use 26-slot arrays.

**Forgetting the prefix itself.** If the typed text is a word, it's a completion too, and it comes first alphabetically. Check the prefix node's own flag before its children.

**No tie-break.** When ranking by count, equal counts need a second rule, such as alphabetical order, or the suggestions can swap places between runs.
</Callout>
