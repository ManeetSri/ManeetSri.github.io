## Why it matters

Tries aren't only for words. Write each number in binary, and it's a word over a two-letter alphabet, 0 and 1. A trie of those bit strings, a **binary trie**, answers questions about bits that would otherwise need every pair of numbers compared. The classic one is "what's the largest XOR of two numbers in this array?", a staple of competitive programming, where it turns an O(n²) search into O(31 × n). The same structure sits inside network routers, matching addresses bit by bit.

## The top bit wins

Recall from [The bitwise operators and masking shifts](/dsa/learn/bits-operators) that `a ^ b` has a 1 in every bit where a and b differ. Try 12 and 19, and toggle bits to see how the result changes:

```visual bitPlayground
value: 12
operand: 19
operator: "^"
```

To make `x ^ y` as large as possible, which bits matter most? A 1 in bit k is worth 2^k, and all the bits below it together are worth at most 2^k − 1. So **one higher bit beats every lower bit combined**: 16, which is `10000`, is bigger than 15, which is `01111`.

That gives a greedy rule for finding the best partner y for a number x. First, make bit 30 differ from x's bit 30, if any number allows it. Among those numbers, make bit 29 differ if possible. And so on down to bit 0. Each choice is safe, because no amount of lower bits could make up for giving up a higher one.

The rule needs a way to ask, at each step, "among the numbers still in the running, does any have this bit equal to 0? equal to 1?" That's exactly what a binary trie answers.

## A binary trie

Store each number as a path of bits, from the **highest bit down**: the root's children are "bit 30 is 0" and "bit 30 is 1", their children split on bit 29, and so on. Every number takes the same number of steps, 31 for values below 2³¹, so leading zeros are part of the path. Numbers with the same high bits share the top of their paths, exactly as words with the same first letters do.

Each node has only two children, so an array of two optional nodes is enough:

```swift run
final class Node {
    var children: [Node?] = [nil, nil]           // children[0] for a 0 bit, children[1] for a 1 bit
}

let width = 5                                    // small numbers, so bits 4 down to 0 are enough
func binary(_ x: Int) -> String {
    let digits = String(x, radix: 2)
    return String(repeating: "0", count: width - digits.count) + digits
}

let root = Node()
for x in [12, 7, 19, 4, 30] {
    var node = root
    for bit in stride(from: width - 1, through: 0, by: -1) {
        let b = (x >> bit) & 1
        if node.children[b] == nil {
            node.children[b] = Node()
        }
        node = node.children[b]!
    }
}

// The best partner for 7: at each bit, take the opposite of 7's bit if it exists
let x = 7
var node = root
var partner = 0
print("x =", binary(x))
for bit in stride(from: width - 1, through: 0, by: -1) {
    let b = (x >> bit) & 1
    if let opposite = node.children[1 - b] {
        partner |= (1 - b) << bit
        node = opposite
        print("bit \(bit): x has \(b), took \(1 - b): the bits differ")
    } else {
        partner |= b << bit
        node = node.children[b]!
        print("bit \(bit): x has \(b), only \(b) exists: the bits match")
    }
}
print("partner =", binary(partner), "which is", partner)
print("x ^ partner =", binary(x ^ partner), "which is", x ^ partner)
```

```output
x = 00111
bit 4: x has 0, took 1: the bits differ
bit 3: x has 0, took 1: the bits differ
bit 2: x has 1, only 1 exists: the bits match
bit 1: x has 1, only 1 exists: the bits match
bit 0: x has 1, took 0: the bits differ
partner = 11110 which is 30
x ^ partner = 11001 which is 25
```

Follow the choices. At bit 4, 7 has a 0, and two numbers, 19 (`10011`) and 30 (`11110`), have a 1 there, so the walk takes the 1 branch. At bit 3, 30 has a 1 and 19 doesn't, so the walk follows 30. From then on only 30 is left, and the walk takes whatever it can. The best partner for 7 is 30, and no other choice could beat 25: 7 ^ 19 is only 20.

`(x >> bit) & 1` reads one bit, as in [Checking, setting, clearing and toggling bits](/dsa/learn/bits-single-bits), and `partner |= 1 << bit` sets one.

## The largest XOR of a pair

Now the whole problem. For each number x: insert it into the trie, then ask for its best partner among everything inserted so far. Inserting first means the trie is never empty, so the walk always succeeds; at worst it finds x itself, giving 0. Every pair gets considered, because whichever of the two comes later finds the earlier one in the trie.

```swift run
final class Node {
    var children: [Node?] = [nil, nil]
}

let highestBit = 30                              // numbers below 2^31 use bits 30 down to 0

func insert(_ x: Int, into root: Node) {
    var node = root
    for bit in stride(from: highestBit, through: 0, by: -1) {
        let b = (x >> bit) & 1
        if node.children[b] == nil {
            node.children[b] = Node()
        }
        node = node.children[b]!
    }
}

func bestXor(with x: Int, in root: Node) -> Int {
    var node = root
    var result = 0
    for bit in stride(from: highestBit, through: 0, by: -1) {
        let b = (x >> bit) & 1
        if let opposite = node.children[1 - b] {
            result |= 1 << bit                   // the bits differ: this bit of the XOR is 1
            node = opposite
        } else {
            node = node.children[b]!             // forced to match: this bit of the XOR is 0
        }
    }
    return result
}

func largestXor(_ numbers: [Int]) -> Int {
    let root = Node()
    var best = 0
    for x in numbers {
        insert(x, into: root)                    // insert first, so the walk always succeeds
        best = max(best, bestXor(with: x, in: root))
    }
    return best
}

print(largestXor([12, 7, 19, 4, 30]))
print(largestXor([1_000_000_007, 123_456_789, 987_654_321]))
print(largestXor([42]))
```

```output
31
1032168868
0
```

The first answer is 12 ^ 19: `01100` and `10011` differ in all five bits. Each number costs 31 steps to insert and 31 to query, so the whole thing is **O(31 × n)** time, and the trie has at most 31 × n + 1 nodes. For 100,000 numbers that's about 6 million steps, against 5 billion pairs for the brute force.

### Faster in practice: a flat array

Creating a class instance for every node is slow when there are millions of them. Competitive programmers store the trie in one array instead: node k's children live at indexes `2 * k` and `2 * k + 1`, and 0 means "no child", which is safe because the root, node 0, is never anyone's child.

```swift
var children = [0, 0]                            // the root's two child slots
for bit in stride(from: 30, through: 0, by: -1) {
    let slot = 2 * node + ((x >> bit) & 1)
    if children[slot] == 0 {
        children[slot] = children.count / 2      // the next free node number
        children.append(0)
        children.append(0)
    }
    node = children[slot]
}
```

Same algorithm, same O(31 × n), but no objects, no reference counting, and the nodes sit together in memory.

## Variations

The binary trie handles a whole family of XOR questions:

- **Largest XOR of a subarray.** The XOR of `numbers[i..<j]` is `prefix[j] ^ prefix[i]`, using the prefix XORs from [Prefix XOR](/dsa/learn/prefix-xor). So it's the largest XOR of a pair of prefix values: insert `prefix[0] = 0` first, then each prefix in turn.
- **Largest XOR with a limit.** For queries like "the best partner for x among numbers at most m", sort the queries by m and the numbers in increasing order, then insert numbers only as m grows. Answering queries in a convenient order rather than the order given is called answering them **offline**.
- **Counting pairs with XOR below k.** Store at each node how many numbers pass through it, as in [Deleting and counting prefixes](/dsa/learn/trie-delete-count), and walk down choosing branches by the bits of k.
- **Removing numbers.** The same pass counts let you delete a number and prune its branch.

<Callout kind="gotcha" title="Bits, widths and signs">
**Start from the top bit.** Inserting bits from bit 0 upwards builds a trie where the first decision is the least important one, and the greedy walk gives wrong answers. Always go from the highest bit down.

**Use enough bits, and the same number for everyone.** If values go up to 2³¹ − 1, use bits 30 down to 0. Starting at bit 20 would silently ignore the high bits of large numbers.

**Negative numbers.** In two's complement, a negative Int has its sign bit set, as [Binary and two's complement](/dsa/learn/bits-binary-twos-complement) explains, so it would sort as a huge number in this trie. Problems usually promise non-negative values. If not, work with the bits as unsigned values, for example via `UInt32(bitPattern:)` on an `Int32`.

**Parentheses.** In Swift, `&` has the same precedence as `*`, so `2 * node + (x >> bit) & 1` happens to group as intended, while the same text in C would not. Write `2 * node + ((x >> bit) & 1)` so no one has to remember.
</Callout>
