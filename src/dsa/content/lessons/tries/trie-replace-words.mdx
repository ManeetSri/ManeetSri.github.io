## Why it matters

Search engines shorten words to a common root, so that "running", "runner" and "runs" all match "run". Network routers pick, for each packet, the most specific route whose address prefix matches. A word game asks for the longest word you can grow one letter at a time. All three walk a word down a trie and watch the end-of-word flags as they pass. This lesson works through two classic interview problems built on that move, and the family of variations around them.

## Replace words with their shortest root

The task: given a list of roots and a sentence, replace every word with the shortest root it starts with, and leave words with no matching root alone. With roots "un", "unhap", "run" and "runner", the sentence "the unhappy runners were unlucky" becomes "the un run were un".

**With a set.** Put the roots in a `Set`. For each word, try its prefixes from shortest to longest, and stop at the first one in the set. Each check builds and hashes a prefix of up to L letters, and a word has L prefixes, so one word costs O(L²).

**With a trie.** Put the roots in a trie. Then walk each word down it, one letter at a time:

- if the node you reach ends a root, that's the shortest root, because it's the first one on the path: stop, and use it;
- if there's no child for the next letter, no root can match: keep the word;
- if the word runs out first, no root is short enough: keep the word.

```swift run
final class Node {
    var children: [Character: Node] = [:]
    var isRoot = false
}

func replaceWithRoots(_ sentence: String, roots: [String]) -> String {
    let trie = Node()
    for root in roots {
        var node = trie
        for character in root {
            if node.children[character] == nil {
                node.children[character] = Node()
            }
            node = node.children[character]!
        }
        node.isRoot = true
    }

    var result: [String] = []
    for word in sentence.split(separator: " ") {
        var node = trie
        var prefix = ""
        var replacement = String(word)
        for character in word {
            guard let next = node.children[character] else { break }    // no root goes this way
            node = next
            prefix.append(character)
            if node.isRoot {
                replacement = prefix                                     // the first root on the path
                break
            }
        }
        result.append(replacement)
    }
    return result.joined(separator: " ")
}

print(replaceWithRoots("the unhappy runners were unlucky", roots: ["un", "unhap", "run", "runner"]))
print(replaceWithRoots("swiftly swimming swans", roots: ["swim", "swift"]))
print(replaceWithRoots("a ab abc", roots: ["abc", "ab"]))
```

```output
the un run were un
swift swim swans
a ab ab
```

What to notice:

- "unhappy" passes the root "un" after two letters and stops there. The longer root "unhap" is never reached.
- "swans" shares "sw" with both roots, but there's no "a" child below "sw", so the walk falls off and the word stays.
- "a" stays as it is: the only roots are longer than the word itself.

Every letter of every root is inserted once, and every letter of the sentence is looked at at most once: **O(total length of the roots + length of the sentence)**. No prefix strings are built and hashed along the way.

## Longest word built one letter at a time

The task: given a list of words, find the longest one that can be built by starting from a one-letter word and adding one letter at a time to the end, with every step also in the list. Ties go to the alphabetically smallest word. From w, wo, wor, worl, world, a, ap, app, appl, apple and apply, three five-letter words can be built: apple, apply and world. The answer is "apple".

Think of it in trie terms. A word can be built exactly when **every node on its path ends a word**: "world" needs w, wo, wor and worl to be words. So search the trie depth first, but only step into a child that is itself a word. Every node the search reaches is a buildable word, and the deepest one wins:

```swift run
final class Node {
    var children: [Character: Node] = [:]
    var word: String?                            // the word that ends here, if any
}

func longestLadderWord(_ words: [String]) -> String {
    let root = Node()
    for word in words {
        var node = root
        for character in word {
            if node.children[character] == nil {
                node.children[character] = Node()
            }
            node = node.children[character]!
        }
        node.word = word
    }

    var best = ""
    func explore(_ node: Node) {
        for character in node.children.keys.sorted() {
            let child = node.children[character]!
            guard let word = child.word else { continue }    // a missing rung: go no further
            if word.count > best.count {
                best = word                                  // strictly longer only, so ties keep the earlier word
            }
            explore(child)
        }
    }
    explore(root)
    return best
}

print(longestLadderWord(["w", "wo", "wor", "worl", "world", "a", "ap", "app", "appl", "apple", "apply"]))
print(longestLadderWord(["m", "mo", "moo", "moon", "moonlight", "s", "su", "sun"]))
print(longestLadderWord(["to", "top"]).isEmpty)
```

```output
apple
moon
true
```

In the last call there's no one-letter word to start from, so nothing can be built, and the answer is the empty string.

How the tie-break works: children are visited in sorted order, so among words of the same length, the alphabetically smallest is reached first. Replacing `best` only when a word is **strictly** longer keeps that first one. "apply" and "world" are found later and are no longer, so "apple" stays.

The cost is **O(total letters)**: building the trie, then a search that visits each node at most once. With very tall ladders (thousands of letters), the recursion gets as deep as the longest word, so an explicit stack is safer, as [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) explains.

### Without a trie

There's a neat alternative. In sorted order, every prefix of a word comes before the word itself ("app" < "appl" < "apple"). So walk the sorted words, and keep a set of the buildable ones: a word is buildable if it has one letter, or if it is a buildable word plus one letter.

```swift
func longestLadderWord(_ words: [String]) -> String {
    var buildable = Set<String>()
    var best = ""
    for word in Set(words).sorted() where word.count == 1 || buildable.contains(String(word.dropLast())) {
        buildable.insert(word)
        if word.count > best.count {
            best = word
        }
    }
    return best
}
```

That's O(n log n × L) for the sort, and shorter to write. In an interview, either is a good answer. Mentioning both, and why the sort works, is better.

## Walking a word down a trie

Both problems walk something down the trie and react to the flags they pass. Change the reaction, and you get a whole family of problems:

| Question about a query word | During the walk |
| --- | --- |
| Shortest stored word it starts with | stop at the **first** flag |
| Longest stored word it starts with | remember the **last** flag; stop when you fall off |
| Does it start with any stored word? | any flag at all on the path |
| How many of its prefixes are stored words? | count the flags on the path |

The second row is **longest-prefix match**, and it's how routers forward packets: each route is an address prefix, and the most specific matching route wins. Routers store the routes in a binary trie, one level per bit of the address. You'll build a binary trie for a different question, the largest XOR of two numbers, later in this module.

<Callout kind="gotcha" title="First flag or last flag?">
"Shortest root" means stopping at the first end-of-word on the path. Walking all the way down and taking the deepest flag finds the **longest** root instead, which passes small tests where each word matches only one root, and fails as soon as roots are nested, like "un" and "unhap". Write a test with nested roots on purpose.
</Callout>
