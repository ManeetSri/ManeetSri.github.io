## Why it matters

Word games like Boggle and word-hunt puzzles hide words in a grid of letters, traced from cell to neighbouring cell. Finding one word is a grid search. Finding every word from a dictionary of thousands is a different problem, and searching for them one at a time repeats the same work over and over. Combining a trie with a backtracking grid search fixes that, and it's one of the best-known hard interview problems because it joins two ideas so neatly.

## One word at a time

A word is traced by starting on a cell with its first letter, then stepping up, down, left or right for each next letter, never using a cell twice in the same word. Searching for one word is a depth-first search from every cell:

```swift
func trace(_ letters: [Character], _ row: Int, _ column: Int, _ index: Int) -> Bool {
    guard row >= 0, row < rows, column >= 0, column < columns,
          !used[row][column], board[row][column] == letters[index] else { return false }
    if index == letters.count - 1 { return true }       // matched the last letter
    used[row][column] = true                            // choose this cell
    defer { used[row][column] = false }                 // and un-choose it on the way back
    return trace(letters, row - 1, column, index + 1) || trace(letters, row, column + 1, index + 1)
        || trace(letters, row + 1, column, index + 1) || trace(letters, row, column - 1, index + 1)
}
```

Marking a cell, exploring, then unmarking it is **backtracking**: try a choice, explore everything that follows from it, and undo it before trying the next. Part VII gives backtracking a whole module. The neighbours are the four moves from [Direction arrays for grid moves](/dsa/learn/matrix-directions).

How much work is it? From a starting cell, the first step has 4 directions and each later step at most 3, since the cell you came from is used. So one word of length L costs up to **O(cells × 4 × 3^(L − 1))**. In practice, mismatched letters cut most paths short.

Now take 10,000 words. Searching for each separately means 10,000 searches, and words like "stare", "start" and "stark" each re-explore every "s-t-a-r" path in the grid. Worse, a search for a word that isn't there explores every path that matches its beginning before giving up.

## Let the trie lead

Put all the words in a trie, and search the grid **once** from every cell, walking the trie alongside:

- From the root, a cell holding "c" is only worth entering if the root has a "c" child. If not, no word starts here, and the search stops at once.
- After entering it, a neighbouring cell holding "a" is only worth entering if the "c" node has an "a" child. And so on.
- Whenever you reach a node where a word ends, you've traced that word.

So every path explored is a prefix of at least one word, and words with a shared prefix share the exploration. Store each word at the node where it ends, so finding it needs no string building.

```swift run
final class Node {
    var children: [Character: Node] = [:]
    var word: String?                                   // the word that ends here, if any
}

func findWords(_ board: [[Character]], _ words: [String]) -> [String] {
    let root = Node()
    for word in words {
        var node = root
        for character in word {
            if node.children[character] == nil {
                node.children[character] = Node()
            }
            node = node.children[character]!
        }
        node.word = word
    }

    var grid = board
    let rows = grid.count
    let columns = grid[0].count
    var found: [String] = []

    func search(_ row: Int, _ column: Int, _ parent: Node) {
        guard row >= 0, row < rows, column >= 0, column < columns else { return }
        let letter = grid[row][column]
        guard let node = parent.children[letter] else { return }    // no word continues this way
        if let word = node.word {
            found.append(word)
            node.word = nil                             // report each word once
        }
        grid[row][column] = "#"                         // used on this path
        for (dr, dc) in [(-1, 0), (0, 1), (1, 0), (0, -1)] {
            search(row + dr, column + dc, node)
        }
        grid[row][column] = letter                      // free again for other paths
        if node.word == nil && node.children.isEmpty {
            parent.children[letter] = nil               // prune: nothing left to find below here
        }
    }

    for row in 0..<rows {
        for column in 0..<columns {
            search(row, column, root)
        }
    }
    return found.sorted()
}

let board: [[Character]] = [
    ["c", "a", "t", "s"],
    ["o", "r", "e", "h"],
    ["d", "e", "a", "t"],
    ["s", "n", "o", "w"],
]
let words = ["cat", "cats", "care", "core", "code", "heat", "hat", "snow", "seat", "tea", "rate", "dent", "tears"]
print(findWords(board, words))
```

```output
["care", "cat", "cats", "code", "core", "heat", "rate", "snow", "tea"]
```

"cat" and "cats" were found on the same path: the search reached the "cat" node, recorded it, and carried on to the "s". "hat" fails because no "a" touches the "h", and "dent" fails because no "t" touches the "n".

## Three details that make it work

**Report each word once.** A word might be traceable along several paths, or from several starting cells. Setting `node.word = nil` after recording it means the second path finds nothing to report. (Sorting at the end gives the answer in a fixed order.)

**Mark used cells in place.** Instead of a separate grid of `Bool`s, overwrite the cell's letter with "#" while it's on the current path, and put the letter back afterwards. No word contains "#", so the trie lookup `parent.children[letter]` fails on a used cell, and that one `guard` handles both "no word goes this way" and "already used". The letter must go back **after** all four directions are explored, not before.

**Prune finished branches.** Once a node has no word left and no children, nothing below it can ever be found. Removing it from its parent means later searches skip it entirely. As words are found, the trie shrinks, and the search with it.

Pruning matters most when the grid matches many paths. Count the calls to `search` on a 5 × 5 grid of a's, looking for the words a, aa, aaa and so on up to ten a's:

```swift run
final class Node {
    var children: [Character: Node] = [:]
    var word: String?
}

func countCalls(_ board: [[Character]], _ words: [String], prune: Bool) -> (found: Int, calls: Int) {
    let root = Node()
    for word in words {
        var node = root
        for character in word {
            if node.children[character] == nil {
                node.children[character] = Node()
            }
            node = node.children[character]!
        }
        node.word = word
    }
    var grid = board
    let rows = grid.count
    let columns = grid[0].count
    var found = 0
    var calls = 0

    func search(_ row: Int, _ column: Int, _ parent: Node) {
        calls += 1
        guard row >= 0, row < rows, column >= 0, column < columns else { return }
        let letter = grid[row][column]
        guard let node = parent.children[letter] else { return }
        if node.word != nil {
            found += 1
            node.word = nil
        }
        grid[row][column] = "#"
        for (dr, dc) in [(-1, 0), (0, 1), (1, 0), (0, -1)] {
            search(row + dr, column + dc, node)
        }
        grid[row][column] = letter
        if prune && node.word == nil && node.children.isEmpty {
            parent.children[letter] = nil
        }
    }
    for row in 0..<rows {
        for column in 0..<columns {
            search(row, column, root)
        }
    }
    return (found, calls)
}

let board = Array(repeating: Array(repeating: Character("a"), count: 5), count: 5)
let words = (1...10).map { String(repeating: "a", count: $0) }
let without = countCalls(board, words, prune: false)
let with = countCalls(board, words, prune: true)
print("without pruning:", without.found, "words,", without.calls, "calls")
print("with pruning:", with.found, "words,", with.calls, "calls")
```

```output
without pruning: 10 words, 226685 calls
with pruning: 10 words, 65 calls
```

Both find all ten words on the very first path. Without pruning, the search then keeps exploring every path of a's from every cell, because the trie still has nodes all the way down, even though their words are gone. With pruning, the empty branch is cut on the way back from the first path, and every later search stops immediately.

## The cost

Building the trie is O(total letters in the words). The search is still **O(cells × 4 × 3^(L − 1))** in the worst case, where L is the length of the longest word: a grid and a dictionary can be built to match a huge number of paths. But the trie means each path is explored once for all words, every path explored is the start of a real word, and pruning removes branches as soon as they're used up. On real boards and dictionaries, that's the difference between a search that takes minutes and one that's instant.

<Callout kind="gotcha" title="The classic slips">
**Restoring the cell too early.** Putting the letter back before exploring the neighbours lets the path walk back onto it, so "aba" would be found on a board with only one "a".

**Reporting a word twice.** Without clearing `node.word`, a word reachable along two paths is appended twice. Clear it, or collect into a set.

**Byte children and the "#" mark.** With 26-slot array children, compute the slot only after checking for the mark: `Int(letter - 97)` on "#" (byte 35) overflows. With dictionary children, as above, "#" has no child at all.
</Callout>
