## Why it matters

Type "ca" into the search field of the Contacts app, and names starting with "ca" appear straight away. Your keyboard's word suggestions, a spell checker, the address bar finishing a URL, and a router choosing where to send a network packet all ask the same kind of question: **which stored words start with this?** A **trie**, or prefix tree, answers it in time that depends only on the length of what you typed, not on how many words are stored. It's the last tree of Part V, and the first one built around strings.

## Prefix questions are awkward for the structures you know

A **prefix** of a word is any run of letters from its start: "c", "ca" and "car" are prefixes of "cart". (A word counts as a prefix of itself.) Here are three ways to answer "which words start with `ca`?" with what you know so far:

- **An array of words.** Check every word with `hasPrefix`. That's O(n × L) for n words of up to L letters, every single time.
- **A `Set` of words.** Perfect for "is `cart` a word?", which costs O(L) on average, as you saw in [Hash functions](/dsa/learn/hash-functions). But a set has no idea which words start with "ca": you're back to checking all of them. You could add **every prefix** of every word to a second set, but that only answers yes or no, and it stores up to L strings per word.
- **A sorted array.** All words starting with "ca" sit side by side, and the binary search from [Lower bound, upper bound, first and last occurrence](/dsa/learn/bs-bounds) finds where they begin in O(L log n). That's a genuinely good answer. Its weakness is change: inserting a word into a sorted array shifts everything after it, O(n).

A trie gets O(L) for lookups, prefix questions and insertions alike.

## One node per prefix

The idea: **words that start the same way share the same path**. The root stands for the empty prefix. Each edge below a node adds one character. So every node stands for exactly one prefix, spelled by the edges from the root down to it.

Step through the words car, cat, cart, care, dog and do going in, then a search for the prefix "car":

```visual trie
words: [car, cat, cart, care, dog, do]
prefix: car
```

Notice that "cat" only needed one new node: "c" and "ca" were already there from "car". And "do" needed none at all: its path already existed because of "dog". All that changed was a mark on the last node.

The name comes from re*trie*val. Many people pronounce it "try", to keep it apart from "tree".

## What a node stores

Each node holds two things:

1. **Its children**: a way to find the child for each next character. In Swift, a dictionary from `Character` to node does the job.
2. **An end-of-word flag**, saying whether a stored word ends exactly here.

The flag is essential. In the trie above, the nodes for "ca" and "car" both exist, but only "car" is a word. Without the flag, the trie couldn't tell them apart. And "car" is a word even though its node has a child: words can end in the middle of the tree, not only at leaves.

Here's a trie in a few lines of Swift. Nodes are a class, because each node is shared with its parent and is changed in place as words go in; you'll see why that matters next lesson. `show` prints each node indented under its parent, visiting children in sorted order:

```swift run
final class TrieNode {
    var children: [Character: TrieNode] = [:]
    var isWord = false
}

let root = TrieNode()

func insert(_ word: String) {
    var node = root
    for character in word {
        if node.children[character] == nil {
            node.children[character] = TrieNode()
        }
        node = node.children[character]!
    }
    node.isWord = true
}

func show(_ node: TrieNode, depth: Int) {
    for character in node.children.keys.sorted() {
        let child = node.children[character]!
        let mark = child.isWord ? "  (word)" : ""
        print(String(repeating: "  ", count: depth) + String(character) + mark)
        show(child, depth: depth + 1)
    }
}

for word in ["car", "cat", "cart", "dog", "do"] {
    insert(word)
}
show(root, depth: 0)
```

```output
c
  a
    r  (word)
      t  (word)
    t  (word)
d
  o  (word)
    g  (word)
```

What to notice:

- `insert` walks down one character at a time, creating a child only when it's missing, then sets the flag on the last node.
- "ca" has a node but no "(word)" mark, while "do" has both a mark and a child.
- `show` sorts the keys before printing, because a dictionary's order changes from run to run. You'll lean on that sorted order for autocomplete later in this module.

## Why prefix questions cost O(length)

To check whether any word starts with "car", start at the root and follow the edge for "c", then "a", then "r". If an edge is missing, no stored word starts that way. If all three exist, at least one does. Either way, that's at most three steps, one per character, and the number of stored words never comes into it.

Count the steps on 1,000 words, against checking an array one word at a time:

```swift run
final class TrieNode {
    var children: [Character: TrieNode] = [:]
    var isWord = false
}

let root = TrieNode()
var words: [String] = []
let letters = Array("abcdefghij")
for first in letters {
    for second in letters {
        for third in letters {
            words.append(String([first, second, third]))     // every 3-letter string from a to j
        }
    }
}
for word in words {
    var node = root
    for character in word {
        if node.children[character] == nil {
            node.children[character] = TrieNode()
        }
        node = node.children[character]!
    }
    node.isWord = true
}

func trieSteps(_ word: String) -> Int {
    var node = root
    var steps = 0
    for character in word {
        guard let next = node.children[character] else { break }
        node = next
        steps += 1
    }
    return steps
}

print(words.count, "words")
print("trie steps to find jig:", trieSteps("jig"))
print("array comparisons to find jig:", words.firstIndex(of: "jig")! + 1)
print("trie steps to reject zzz:", trieSteps("zzz"))
```

```output
1000 words
trie steps to find jig: 3
array comparisons to find jig: 987
trie steps to reject zzz: 0
```

Three steps either way, and "zzz" is rejected without a single step down, because the root has no "z" child. With a million words, it would still be three steps.

## Sharing saves memory, too

Each node stands for one distinct prefix, so a trie has **one node per distinct prefix** of the stored words, plus the root. When words share beginnings, that's far fewer nodes than letters:

```swift run
let words = ["car", "cat", "cart", "care", "card", "dog", "do", "dot"]
var prefixes = Set<String>()
for word in words {
    for length in 1...word.count {
        prefixes.insert(String(word.prefix(length)))
    }
}
print("letters:", words.reduce(0) { $0 + $1.count })
print("nodes below the root:", prefixes.count)
```

```output
letters: 26
nodes below the root: 11
```

The worst case is words that share nothing, like "dog" and "cat": then there's a node for every letter, O(total letters). Real vocabularies share a lot. English words pile up under prefixes like "re", "un" and "con".

<Callout kind="gotcha" title="A node existing doesn't make it a word">
The most common trie bug is treating "there's a node for this" as "this is a word". After inserting only "cart", the nodes for "c", "ca" and "car" all exist. A search for the word "car" must check the end-of-word flag on the last node. A search for the prefix "car" mustn't. Next lesson builds both, side by side.
</Callout>
