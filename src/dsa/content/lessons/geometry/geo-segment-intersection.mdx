## Why it matters

Do two roads on a map cross? Does a bullet's path hit a wall? Does the edge you're drawing in a diagram tool cut through another one? Does a robot's straight-line move clip an obstacle? Each is the same question: **do two segments intersect?** It's also a building block for the rest of this module, from point-in-polygon tests to sweep lines. The test itself is four orientations from [Cross product and orientation](/dsa/learn/geo-cross-orientation). The special cases around it are where the bugs live, so this lesson takes them one at a time.

## Segments, not lines

A **segment** from a to b is every point a + t(b − a) with t from 0 to 1: it starts at a and stops at b. A **line** through a and b goes on for ever in both directions. Two lines that aren't parallel always meet somewhere. Two segments only meet if that somewhere is on both of them, which is what makes the question interesting.

## The general case: each one straddles the other

Segments AB and CD cross at a single point in the middle of both exactly when:

- C and D are on **opposite sides** of the line through A and B, and
- A and B are on opposite sides of the line through C and D.

```text
         C                                 C
         |                                 |
  A -----+----- B             A ----- B    |
         |                                 |
         D                                 D

  each segment straddles        CD straddles line AB (extended),
  the other's line: they cross  but A and B are both left of CD
```

One test isn't enough, as the right-hand picture shows: line AB, extended, does pass between C and D, but it gets there only after B has ended.

In code, "opposite sides" means two orientations with opposite signs. Take the four:

- `o1 = orientation(a, b, c)` and `o2 = orientation(a, b, d)`: where C and D are, relative to line AB;
- `o3 = orientation(c, d, a)` and `o4 = orientation(c, d, b)`: where A and B are, relative to line CD.

Each is −1, 0 or 1. They cross properly when `o1 * o2 < 0 && o3 * o4 < 0`: in each pair, one is 1 and the other −1. Multiplying the **signs** is safe. Multiplying the raw cross products, each up to 8 × 10¹⁸, would overflow.

## The special cases: touching

If an orientation is zero, an endpoint lies on the other segment's **line**. It might be on the segment itself (a T-junction, or a shared end) or beyond one of its ends. Because the point is already known to be on the line, "on the segment" just means "inside the rectangle the segment's ends span", its **bounding box**:

```swift
/// For p already known to be collinear with a and b: is it between them?
func within(_ p: Point, _ a: Point, _ b: Point) -> Bool {
    min(a.x, b.x) <= p.x && p.x <= max(a.x, b.x) && min(a.y, b.y) <= p.y && p.y <= max(a.y, b.y)
}
```

For a vertical or horizontal segment the box is flat, a line one point wide, and the check still works. So the whole test is the proper-crossing check plus four touching checks:

```swift run
struct Point {
    var x: Int
    var y: Int

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    func cross(_ other: Point) -> Int {
        x * other.y - y * other.x
    }
}

extension Point {
    init(_ x: Int, _ y: Int) {
        self.init(x: x, y: y)
    }
}

func orientation(_ a: Point, _ b: Point, _ c: Point) -> Int {
    let cross = (b - a).cross(c - a)
    return cross > 0 ? 1 : (cross < 0 ? -1 : 0)
}

/// For p already known to be collinear with a and b: is it between them?
func within(_ p: Point, _ a: Point, _ b: Point) -> Bool {
    min(a.x, b.x) <= p.x && p.x <= max(a.x, b.x) && min(a.y, b.y) <= p.y && p.y <= max(a.y, b.y)
}

/// Do segments ab and cd share at least one point?
func segmentsIntersect(_ a: Point, _ b: Point, _ c: Point, _ d: Point) -> Bool {
    let o1 = orientation(a, b, c), o2 = orientation(a, b, d)
    let o3 = orientation(c, d, a), o4 = orientation(c, d, b)
    if o1 * o2 < 0 && o3 * o4 < 0 { return true }       // a proper crossing
    if o1 == 0 && within(c, a, b) { return true }       // c lies on ab
    if o2 == 0 && within(d, a, b) { return true }       // d lies on ab
    if o3 == 0 && within(a, c, d) { return true }       // a lies on cd
    if o4 == 0 && within(b, c, d) { return true }       // b lies on cd
    return false
}

let cases: [(String, [Point])] = [
    ("crossing", [Point(0, 0), Point(4, 4), Point(0, 4), Point(4, 0)]),
    ("T-junction", [Point(0, 0), Point(4, 0), Point(2, 0), Point(2, 3)]),
    ("shared end", [Point(0, 0), Point(4, 0), Point(4, 0), Point(6, 2)]),
    ("near miss", [Point(0, 0), Point(4, 4), Point(5, 0), Point(5, 9)]),
    ("parallel", [Point(0, 0), Point(4, 0), Point(0, 1), Point(4, 1)]),
    ("collinear, overlapping", [Point(0, 0), Point(4, 0), Point(3, 0), Point(7, 0)]),
    ("collinear, with a gap", [Point(0, 0), Point(4, 0), Point(5, 0), Point(7, 0)]),
    ("a single point on ab", [Point(0, 0), Point(4, 4), Point(1, 1), Point(1, 1)]),
]
for (label, p) in cases {
    print("\(label): \(segmentsIntersect(p[0], p[1], p[2], p[3]))")
}
```

```output
crossing: true
T-junction: true
shared end: true
near miss: false
parallel: false
collinear, overlapping: true
collinear, with a gap: false
a single point on ab: true
```

The near miss is the right-hand picture above: (5, 0) and (5, 9) straddle the line y = x, but A and B are both to the left of the vertical segment, so `o3 * o4` is positive. The `init(_:_:)` in an extension keeps the memberwise `Point(x:y:)` and adds a shorter spelling for the table.

## Collinear segments

When all four orientations are zero, both segments lie on one line. The proper-crossing test can't help (every product is 0), and the segments might overlap, touch end to end, or have a gap between them. The four touching checks cover all of it: if two collinear segments share any point at all, then at least one of the four endpoints lies on the other segment. With a gap, none does, and the answer is false.

Segments that are a single point (a = b) need no special code either. Every orientation that starts `orientation(a, a, …)` is 0, so `within(c, a, a)` asks whether c is a, and `orientation(c, d, a)` with `within(a, c, d)` asks whether a lies on cd. That's the last case in the table.

## Where do they cross?

Sometimes you need the crossing point itself. Write the segments as A + t·r and C + u·s, where r = B − A and s = D − C. Where they meet, A + t·r = C + u·s. Take the cross product of both sides with s; since cross(s, s) = 0, the u term vanishes, and with q = C − A:

t = cross(q, s) / cross(r, s) and, the same way, u = cross(q, r) / cross(r, s)

If cross(r, s) is 0, the segments are parallel, and there's no single crossing point: either none, or a collinear overlap. Otherwise they cross when t and u are both between 0 and 1. Both are fractions of exact `Int`s, so the check can stay exact: make the denominator positive, then compare the numerators with 0 and with it. Only the final coordinates need `Double`.

```swift run
import Foundation

struct Point {
    var x: Int
    var y: Int

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    func cross(_ other: Point) -> Int {
        x * other.y - y * other.x
    }
}

/// The single point where segments ab and cd cross, or nil if they're parallel or the lines
/// cross outside either segment
func crossingPoint(_ a: Point, _ b: Point, _ c: Point, _ d: Point) -> (x: Double, y: Double)? {
    let r = b - a, s = d - c, q = c - a
    var denominator = r.cross(s)
    if denominator == 0 { return nil }                      // parallel: no single crossing
    var tTop = q.cross(s), uTop = q.cross(r)
    if denominator < 0 {
        (denominator, tTop, uTop) = (-denominator, -tTop, -uTop)
    }
    // t = tTop / denominator and u = uTop / denominator must both be between 0 and 1
    guard 0 <= tTop && tTop <= denominator && 0 <= uTop && uTop <= denominator else { return nil }
    let t = Double(tTop) / Double(denominator)              // the only division, at the very end
    return (Double(a.x) + t * Double(r.x), Double(a.y) + t * Double(r.y))
}

let tests = [
    (Point(x: 0, y: 0), Point(x: 3, y: 3), Point(x: 0, y: 2), Point(x: 4, y: 0)),
    (Point(x: 0, y: 0), Point(x: 5, y: 2), Point(x: 1, y: 3), Point(x: 4, y: -1)),
    (Point(x: 0, y: 0), Point(x: 2, y: 2), Point(x: 3, y: 0), Point(x: 4, y: -1)),
    (Point(x: 0, y: 0), Point(x: 4, y: 0), Point(x: 1, y: 0), Point(x: 6, y: 0)),
]
for (a, b, c, d) in tests {
    if let p = crossingPoint(a, b, c, d) {
        print(String(format: "(%.3f, %.3f)", p.x, p.y))
    } else {
        print("no single crossing")
    }
}
```

```output
(1.333, 1.333)
(2.500, 1.000)
no single crossing
no single crossing
```

The first pair meets at t = 4/9 along the first segment: (4/3, 4/3). In the third, the lines meet at (1.5, 1.5), which is on the first segment but not on the second (u is negative). The fourth pair is collinear, so the formula has nothing to divide by.

## Crossing or touching: decide the rule first

Problems mean different things by "intersect", so read the statement before you write the test:

| The question | Keep | Typical use |
| --- | --- | --- |
| Do they share any point? | proper crossing and all four touching checks | collisions, "does this path hit that wall" |
| Do they cross properly? | the proper-crossing check only | checking a polygon for self-crossings, where neighbouring edges always share a corner |
| How do they meet? | all of it, plus the collinear interval | none, one point, or an overlapping stretch |

<Callout kind="gotcha" title="Segment intersection slips">
- **Multiplying cross products instead of signs.** `cross1 * cross2 < 0` overflows once coordinates reach the millions or so. Reduce each to −1, 0 or 1 first.
- **Only the proper-crossing test.** `o1 * o2 < 0 && o3 * o4 < 0` alone says false for T-junctions, shared ends and collinear overlaps.
- **The bounding box on its own.** A point inside the box isn't necessarily on the segment; the box test means "between" only once orientation is 0.
- **Slopes.** Writing lines as y = mx + c breaks on vertical segments and brings `Double` rounding into a yes-or-no question.
- **Testing only one way round.** CD straddling line AB proves nothing until AB straddles line CD too.
</Callout>

## Practice

**Segment contact** asks how two segments meet: not at all, at exactly one point, or along an overlapping stretch. It's this lesson's test plus the collinear case done carefully. **Gap between two pipes** measures the shortest distance between two segments: 0 when they touch, otherwise a point-to-segment distance from the first lesson. Its tests come back in the last lesson of this module, on comparing `Double`s.
