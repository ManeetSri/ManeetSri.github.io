## Why it matters

Every geometry problem, from "do these two roads cross?" to "fence in these trees", is built from a handful of operations on points: subtract two of them, scale one, take a dot or a cross product. On iOS you meet the same ideas in CoreGraphics (`CGPoint`, `CGVector`, `CGRect`), in SpriteKit physics and whenever you check whether a tap landed inside a custom shape. This module builds a small geometry toolkit in Swift, one lesson at a time, and keeps it exact by using whole numbers wherever it can. This lesson lays the foundation: a `Point` type with operators, the dot product, and lengths.

## Points and vectors

A **point** is a place: (4, 3) is four units right of the origin (0, 0) and three up. A **vector** is a movement: "three right and two up", wherever you start from. Both are written as an (x, y) pair, and subtraction connects them: the vector from A to B is B − A.

```text
y
3   .   .   .   .   B
2   .   .   .   .   .
1   .   A   .   .   .
0   .   .   .   .   .
    0   1   2   3   4   x

A = (1, 1)   B = (4, 3)   B − A = (3, 2): three right, two up
```

Four rules cover almost everything:

| Operation | Gives | Meaning |
| --- | --- | --- |
| point − point | vector | the movement from one to the other |
| point + vector | point | where you land after the movement |
| vector + vector | vector | one movement, then the other |
| number × vector | vector | the same direction, stretched; a negative number reverses it |

Both are (x, y) pairs, so competitive programmers usually use one type for both, and this module does too, calling it `Point`. Whether a value means a place or a movement is clear from how it's used. Apple's CoreGraphics keeps them apart, as `CGPoint` and `CGVector`, which is a fine choice for an app.

## A Point type with operators

A [struct](/dsa/learn/swift-structs) holds the two coordinates. Operators make the formulas read like the maths. You wrote `==` and `<` as static functions in [Equatable, Comparable and CustomStringConvertible](/dsa/learn/swift-standard-protocols); `+`, `-` and `*` work the same way: a `static func` whose name is the symbol. Writing your own version of an operator for a new type is called **operator overloading**. A **prefix** operator, like the minus in `-v`, needs the `prefix` keyword.

```swift run
struct Point: Hashable {
    var x: Int
    var y: Int

    static func + (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x + rhs.x, y: lhs.y + rhs.y)
    }

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    static func * (scale: Int, p: Point) -> Point {
        Point(x: scale * p.x, y: scale * p.y)
    }

    static prefix func - (p: Point) -> Point {
        Point(x: -p.x, y: -p.y)
    }
}

let a = Point(x: 1, y: 1)
let b = Point(x: 4, y: 3)
let move = b - a
print(move)
print(a + 2 * move)
print(-move)
print(a + move == b)
let visited: Set<Point> = [a, b, a + move]
print(visited.count)
```

```output
Point(x: 3, y: 2)
Point(x: 7, y: 5)
Point(x: -3, y: -2)
true
2
```

What to notice:

- `2 * move` works because this `*` takes the `Int` on the left. `move * 2` doesn't compile until you add a second overload with the parameters the other way round.
- Swift tells the two minuses apart by position: `b - a` calls the two-argument `-`, and `-move` calls the prefix one.
- `Hashable`, which includes `Equatable`, is written for you from the two stored properties. That gives `==`, and lets points go in a `Set` or be `Dictionary` keys, as in [Hashable and hash(into:)](/dsa/learn/swift-hashable). `a + move` is the same point as `b`, so the set holds two points, not three.

<Callout kind="tip" title="Why bother with operators?">
Geometry formulas written out coordinate by coordinate are where sign slips hide: `a.x - b.y` instead of `a.x - b.x`. With operators, each formula is as short as the maths, and the coordinate arithmetic is written once, inside the type, where it's easy to check.
</Callout>

## Int or Double coordinates?

Most problems give whole-number coordinates. Keep them as `Int`. Adding, subtracting and multiplying whole numbers is exact, so "is this exactly zero?" means what it says. With `Double`, `0.1 + 0.2` isn't `0.3`, as [Double, Float and floating-point precision](/dsa/learn/swift-floating-point) showed, and geometry is full of exactly-zero questions: are these three points on one line? Is this point on that edge? Are these two directions perpendicular?

So the rule for this module is:

- Make **decisions** (signs, comparisons, equality) with `Int`.
- Use `Double` only for **results** that genuinely aren't whole: lengths, angles and intersection points.
- Never compare two computed `Double`s with `==`. The last lesson of this module is about what to do instead.

The one danger with `Int` is size. Coordinates up to 10⁹ make each product up to 10¹⁸, and `Int.max` is about 9.2 × 10¹⁸. The next lesson works out exactly how much room that leaves.

## The dot product

The **dot product** of two vectors multiplies them coordinate by coordinate and adds the results: a · b = a.x × b.x + a.y × b.y. It turns two vectors into one number. Geometrically, a · b = |a| × |b| × cos θ, where |a| is a's length and θ is the angle between them. You rarely need the cosine. The **sign** does most of the work:

| a · b | Angle between a and b | Meaning |
| --- | --- | --- |
| positive | less than 90° | roughly the same way |
| zero | exactly 90° | perpendicular |
| negative | more than 90° | roughly opposite ways |

Computed with `Int`, zero really does mean perpendicular, not "nearly".

```swift run
struct Point {
    var x: Int
    var y: Int

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    func dot(_ other: Point) -> Int {
        x * other.x + y * other.y
    }
}

// A triangle has a right angle at b when the two sides leaving b are perpendicular
func isRightAngle(at b: Point, _ a: Point, _ c: Point) -> Bool {
    (a - b).dot(c - b) == 0
}
print(isRightAngle(at: Point(x: 0, y: 0), Point(x: 3, y: 0), Point(x: 0, y: 4)))
print(isRightAngle(at: Point(x: 1, y: 1), Point(x: 3, y: 2), Point(x: 0, y: 3)))
print(isRightAngle(at: Point(x: 1, y: 1), Point(x: 3, y: 2), Point(x: 0, y: 4)))

// A guard stands at (2, 2), facing along (1, 1). Is each visitor in front of the guard, or behind?
let guardPosition = Point(x: 2, y: 2)
let facing = Point(x: 1, y: 1)
for visitor in [Point(x: 5, y: 3), Point(x: 0, y: 1), Point(x: 3, y: 1)] {
    let d = facing.dot(visitor - guardPosition)
    print(visitor.x, visitor.y, d > 0 ? "in front" : (d < 0 ? "behind" : "level"))
}
```

```output
true
true
false
5 3 in front
0 1 behind
3 1 level
```

The second triangle is a tilted right angle: the sides leaving (1, 1) are (2, 1) and (−1, 2), and 2 × (−1) + 1 × 2 = 0. The guard check is how games decide whether an enemy is in the player's field of view, with no angles or trigonometry at all.

### How far along: projection

The dot product also measures how far one vector reaches along another. Take a segment from a to b and a point p. The number (p − a) · (b − a) is positive when p is "ahead of" a in the direction of b, and it equals |b − a|² exactly when p is level with b. Divide it by |b − a|² and you get t, the fraction of the way from a to b where p's **foot** falls (the closest point on the line through a and b):

- t ≤ 0: the foot is at or before a, so a is the closest point of the segment;
- t ≥ 1: at or past b, so b is the closest;
- in between: the foot, a + t(b − a), is on the segment.

The first two decisions need no division at all: compare `(p - a).dot(b - a)` with 0 and with `(b - a).dot(b - a)`.

## Length and distance

A vector's length comes from Pythagoras: |v| = √(v.x² + v.y²), and the distance between two points is the length of their difference. The square root makes it a `Double`. But to **compare** distances you don't need it: if one squared length is smaller, so is the length. Squared lengths stay exact `Int`s.

```swift run
import Foundation

struct Point {
    var x: Int
    var y: Int

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    func dot(_ other: Point) -> Int { x * other.x + y * other.y }
    var squaredLength: Int { dot(self) }
    var length: Double { Double(squaredLength).squareRoot() }
}

let home = Point(x: 0, y: 0)
let cafes = [Point(x: 4, y: 7), Point(x: -6, y: 5), Point(x: 8, y: -1)]
// Comparing squared distances needs no square roots, and stays exact
let nearest = cafes.min { ($0 - home).squaredLength < ($1 - home).squaredLength }!
print(nearest, (nearest - home).squaredLength)
print(String(format: "%.4f", (nearest - home).length))

// The distance from p to the segment from a to b
func distance(from p: Point, toSegmentFrom a: Point, to b: Point) -> Double {
    let ab = b - a
    let along = (p - a).dot(ab)
    if along <= 0 { return (p - a).length }                  // the foot is at or before a
    if along >= ab.squaredLength { return (p - b).length }   // at or past b
    let t = Double(along) / Double(ab.squaredLength)
    let dx = Double(p.x) - (Double(a.x) + t * Double(ab.x))  // p minus its foot
    let dy = Double(p.y) - (Double(a.y) + t * Double(ab.y))
    return (dx * dx + dy * dy).squareRoot()
}
let a = Point(x: 0, y: 0), b = Point(x: 6, y: 0)
for p in [Point(x: 2, y: 3), Point(x: -3, y: 4), Point(x: 7, y: 1)] {
    print(String(format: "%.4f", distance(from: p, toSegmentFrom: a, to: b)))
}
```

```output
Point(x: -6, y: 5) 61
7.8102
3.0000
5.0000
1.4142
```

What to notice:

- The cafés at (4, 7) and (8, −1) are both at squared distance 65, and (−6, 5) wins with 61. Only the final answer, √61, needed a `Double`.
- `String(format:)` comes from Foundation, hence the `import`. It rounds to a fixed number of decimals, which is how this module prints every `Double`.
- (2, 3) projects onto the segment at (2, 0), 3 away. (−3, 4) projects before a, so the answer is its distance to a. (7, 1) projects past b, so it's its distance to b, √2.

## Quarter turns

Turning a vector a quarter-turn **counterclockwise** (to the left) maps (x, y) to (−y, x); clockwise maps it to (y, −x). East (1, 0) turns left to north (0, 1). Both are exact in `Int`, and a vector's dot product with its own quarter-turn is x × (−y) + y × x = 0, so they're always perpendicular. That's the quickest way to get a **normal**, a vector at right angles to an edge.

```swift
extension Point {
    var turnedLeft: Point { Point(x: -y, y: x) }    // a quarter-turn counterclockwise
    var turnedRight: Point { Point(x: y, y: -x) }   // a quarter-turn clockwise
}
```

<Callout kind="gotcha" title="Swift gotchas in geometry code">
- **`^` isn't "to the power of".** In Swift it's the bitwise XOR from M16, so `x ^ 2` compiles and gives nonsense. Write `x * x`.
- **Int and Double don't mix.** `Double(p.x) * 0.5` is fine; `p.x * 0.5` doesn't compile. Convert explicitly, and only at the end.
- **Operand order matters.** With only `static func * (scale: Int, p: Point)`, the expression `move * 2` fails with "binary operator '*' cannot be applied to operands of type 'Point' and 'Int'". Add the mirror-image overload if you want both.
- **Squares overflow first.** `x * x` traps for `x` above about 3 × 10⁹, and a squared distance needs room for two squares added together.
</Callout>
