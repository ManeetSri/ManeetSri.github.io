## Why it matters

Which two aircraft on the radar are closest together? Which two delivery drivers are near enough to swap a parcel? Which two entries in a star catalogue are so close they're probably the same star? Checking every pair is O(n²): fine for a thousand points, hopeless for a hundred thousand. [Closest pair of points](/dsa/learn/dc-closest-pair) in Part VII solves this by divide and conquer. This lesson solves it a different way, with a **sweep line**, the technique from [Sweep-line events](/dsa/learn/iv-sweep-line) with a second dimension to manage. It's the same O(n log n), and the sweep's shape (sort, then one pass with an ordered structure) is exactly what the next lesson uses for segments and rectangles.

## Start with brute force

Every pair, measured as a **squared** distance, so it stays an exact `Int` and no square root is needed to compare, as in [the first lesson](/dsa/learn/geo-points-vectors):

```swift
func bruteForce(_ points: [Point]) -> Int {
    var best = Int.max
    for i in points.indices {
        for j in points.indices where j > i {
            let dx = points[i].x - points[j].x, dy = points[i].y - points[j].y
            best = min(best, dx * dx + dy * dy)
        }
    }
    return best
}
```

It's obviously right, which makes it the perfect thing to test a faster version against. For 100,000 points it measures about 5 × 10⁹ pairs.

## The sweep idea

Sort the points by x, and visit them in that order, as if a vertical line were sweeping from left to right. Keep `best`, the smallest squared distance found so far; call its square root d.

When the line reaches a point p, which earlier points could possibly beat `best`? Only points closer than d to p. That rules out two kinds of point at once:

- anything more than d to the **left** of p: its x-distance alone is already too big;
- anything more than d **above or below** p.

So every candidate lies in a box d wide and 2d tall, just behind the sweep line:

```text
           p.x − d       p.x
              |           |
   p.y + d    +-----------+
              |           |
              |           p        only points in this box
              |           |        can beat best
   p.y − d    +-----------+
              |           |
      too far left     the sweep line
```

That gives the sweep its two parts.

1. **A window that slides.** Keep the points whose x is within d of the sweep line. As the line moves right, points fall off the left end; a left pointer moves forward past them, like the variable-size windows of [A sliding window template and its invariants](/dsa/learn/sw-template). `best` only ever shrinks, so a point that falls out never needs to come back.
2. **A range query by y.** Keep the window **ordered by y** in a balanced binary search tree, an ordered set like the one in [Build an ordered set and map in Swift](/dsa/learn/bal-ordered-map). Then "every window point with y between p.y − d and p.y + d" is one range query, O(log n + k) for k results.

### Why the box holds only a few points

Every two points in the window are at least d apart, or `best` would already be smaller. Cut the d × 2d box into eight squares, d/2 on a side. The farthest apart two points in one square can be is its diagonal, d/√2, which is less than d, so each square holds at most one window point. At most 8 points, then (a tighter argument gets it to 6, but any constant will do).

So each point does O(log n) work to insert itself, remove the points that fall out, and run its range query, plus a constant number of distance checks. With the sort, that's **O(n log n)** in all.

## The details that make it exact

- **Squared distances throughout.** `best` is an `Int`. The box's half-height is the integer square root of `best`: the largest whole number whose square is at most `best`. A point with |dy| bigger than that has dy² > `best`, so it can't win.
- **Evict on `≥`.** A point exactly √best to the left can only tie, never beat, so it can go.
- **Unique keys.** Order the window by (y, x), not by y alone. Two points with the same y would otherwise count as one in a set.
- **Duplicates.** Two points on the same spot are distance 0 apart, and nothing beats 0, so stop there.

## The code

A balanced tree isn't available in a single-file Swift program without writing one, so this version keeps the window in a **sorted array** and uses binary search ([lower bound](/dsa/learn/bs-bounds)) to find where entries go. It prints what each point checks:

```swift run
struct Point {
    var x: Int
    var y: Int
}

/// The largest r with r * r ≤ value
func integerSquareRoot(_ value: Int) -> Int {
    var root = Int(Double(value).squareRoot())
    while root * root > value { root -= 1 }
    while (root + 1) * (root + 1) <= value { root += 1 }
    return root
}

/// The first index of `window`, sorted by (y, x), whose entry is at least `key`
func lowerBound(_ window: [(Int, Int)], _ key: (Int, Int)) -> Int {
    var low = 0, high = window.count
    while low < high {
        let mid = (low + high) / 2
        if window[mid] < key { low = mid + 1 } else { high = mid }
    }
    return low
}

func squaredDistance(_ a: Point, _ b: Point) -> Int {
    (a.x - b.x) * (a.x - b.x) + (a.y - b.y) * (a.y - b.y)
}

/// The smallest squared distance between two of at least two points
func closestPair(_ input: [Point]) -> Int {
    let points = input.sorted { ($0.x, $0.y) < ($1.x, $1.y) }
    var best = squaredDistance(points[0], points[1])
    var window: [(Int, Int)] = []          // (y, x) of the points near the sweep line, sorted
    var left = 0
    for p in points {
        if best == 0 { return 0 }          // two points on one spot: nothing beats that
        // Points at least √best to the left can't beat best, for p or for anything after it
        while (p.x - points[left].x) * (p.x - points[left].x) >= best {
            window.remove(at: lowerBound(window, (points[left].y, points[left].x)))
            left += 1
        }
        // Only points within √best above or below can beat best
        let reach = integerSquareRoot(best)
        var i = lowerBound(window, (p.y - reach, Int.min))
        var checked: [String] = []
        while i < window.count && window[i].0 <= p.y + reach {
            let q = Point(x: window[i].1, y: window[i].0)
            checked.append("(\(q.x), \(q.y))")
            best = min(best, squaredDistance(p, q))
            i += 1
        }
        window.insert((p.y, p.x), at: lowerBound(window, (p.y, p.x)))
        print("(\(p.x), \(p.y)): checked \(checked.isEmpty ? "nothing" : checked.joined(separator: " ")), best \(best)")
    }
    return best
}

let points = [Point(x: 1, y: 9), Point(x: 2, y: 3), Point(x: 4, y: 7), Point(x: 5, y: 1),
              Point(x: 7, y: 5), Point(x: 8, y: 8), Point(x: 9, y: 2), Point(x: 10, y: 6)]
print("closest:", closestPair(points))
```

```output
(1, 9): checked nothing, best 37
(2, 3): checked (1, 9), best 37
(4, 7): checked (2, 3) (1, 9), best 13
(5, 1): checked (2, 3), best 13
(7, 5): checked (4, 7), best 13
(8, 8): checked (7, 5), best 10
(9, 2): checked (7, 5), best 10
(10, 6): checked (7, 5) (8, 8), best 8
closest: 8
```

Follow (5, 1). By then `best` is 13, so the box reaches √13 ≈ 3.6 each way, and the integer square root rounds that down to 3. (1, 9) is 4 to the left, and 16 ≥ 13, so it's evicted. Of the rest, only (2, 3) has a y within 3 of 1. Each point checks at most two others, even though the window could have held more.

`best` starts as the distance between the first two points, rather than `Int.max`, for a reason: the integer square root of `Int.max` would compute `(root + 1) * (root + 1)` past the top of `Int` and trap.

### The same loop with an ordered set

The sorted array keeps the demo short, but inserting into or removing from the middle of an array shifts everything after it: O(n) each. If every point has the same x, nothing ever leaves the window and the sweep becomes O(n²). In the companion package, DSAKit's `SortedSet` (the one you built in M38) makes each step O(log n):

```swift
import DSAKit

struct Key: Comparable {                   // the window's order: by y, then x
    var y: Int
    var x: Int
    static func < (lhs: Key, rhs: Key) -> Bool { (lhs.y, lhs.x) < (rhs.y, rhs.x) }
}

var window = SortedSet<Key>()
// evict:   window.remove(Key(y: points[left].y, x: points[left].x))
// query:   window.elements(in: Key(y: p.y - reach, x: Int.min)...Key(y: p.y + reach, x: Int.max))
// insert:  window.insert(Key(y: p.y, x: p.x))
```

## A tempting shortcut, and why it fails

There's a popular simplification: sort by x, and for each point scan backwards through the earlier points while their x-distance squared is less than `best`. No tree, no window bookkeeping, and on random points it's fast. But give it points that all share one x (a column of sensors along a wall, say) and the x-distance is always 0, so every point scans every earlier one: **O(n²)** again. The y-range query is what protects the real sweep from that input.

| | Divide and conquer | Sweep line |
| --- | --- | --- |
| Idea | split by x, solve both halves, check a narrow strip round the split | one pass left to right, with a window ordered by y |
| Extra structure | none beyond arrays | an ordered set |
| Time | O(n log n) | O(n log n) |
| Leads on to | other divide-and-conquer problems | other sweeps: segment crossings, rectangle unions |

There's also a randomised method, using a hash grid, that runs in O(n) expected time. You'll meet that style of algorithm in M67.

<Callout kind="gotcha" title="Closest-pair slips">
- **Squaring overflows late.** With coordinates up to 10⁹, a squared distance can reach 8 × 10¹⁸: two squares of 4 × 10¹⁸, just under `Int.max`. Larger coordinates need wider arithmetic.
- **Comparing square roots.** `Double` distances can tie or misorder after rounding. Compare squared `Int`s; take a root only to print.
- **Ordering the window by y alone.** Points with equal y collide in a set. Use (y, x).
- **Forgetting to remove evicted points from the set.** Moving the left pointer isn't enough; the tree must forget them too, or the range query finds them.
</Callout>
