## Why it matters

Polygons are how shapes get described to a computer: a plot of land, a country's border, a lasso selection in a photo editor, the geofence that triggers a reminder when you arrive somewhere, the outline of a sprite. Two questions come up again and again: **how big is it?** and **is this point inside it?** Both have short, exact answers built on the cross product from [Cross product and orientation](/dsa/learn/geo-cross-orientation).

## A polygon is an array of corners

Store a polygon as its corners (**vertices**) in order. Each corner joins the next with an edge, and the last corner joins back to the first. A **simple** polygon is one whose edges don't cross each other. The corners can run counterclockwise or clockwise, and good code accepts either.

The closing edge is the one people forget. Index it with `(i + 1) % n`, so corner n − 1 pairs with corner 0.

## Area: the shoelace formula

Twice the area of a polygon with corners p₀, p₁, …, pₙ₋₁ is the sum of the cross products of neighbouring corners:

2 × area = cross(p₀, p₁) + cross(p₁, p₂) + … + cross(pₙ₋₁, p₀)

The result is **signed**: positive when the corners run counterclockwise, negative when they run clockwise. Take the absolute value for the area, or keep the sign when you need to know which way a polygon goes.

Why it works: cross(pᵢ, pᵢ₊₁) is twice the signed area of the triangle formed by the origin and that edge. Walking round the polygon, each of those triangles is added or subtracted depending on which way the edge goes past the origin. Any region outside the polygon is swept once each way and cancels; the inside is left counted exactly once. (The name comes from writing the coordinates in two columns: the cross-multiplications zigzag between them like laces on a shoe.)

```swift run
struct Point {
    var x: Int
    var y: Int

    func cross(_ other: Point) -> Int {
        x * other.y - y * other.x
    }
}

extension Point {
    init(_ x: Int, _ y: Int) {
        self.init(x: x, y: y)
    }
}

/// Twice the signed area: positive if the corners run counterclockwise, negative if clockwise
func twiceSignedArea(_ corners: [Point]) -> Int {
    var total = 0
    for i in corners.indices {
        total += corners[i].cross(corners[(i + 1) % corners.count])
    }
    return total
}

/// The area itself, from twice the area: a whole number or a half
func describe(_ twiceArea: Int) -> String {
    let doubled = abs(twiceArea)
    return "\(doubled / 2)" + (doubled % 2 == 1 ? ".5" : "")
}

let lShape = [Point(0, 0), Point(6, 0), Point(6, 2), Point(2, 2), Point(2, 6), Point(0, 6)]
let triangle = [Point(0, 0), Point(5, 0), Point(2, 3)]
print(twiceSignedArea(lShape), describe(twiceSignedArea(lShape)))
print(twiceSignedArea(lShape.reversed()), describe(twiceSignedArea(lShape.reversed())))
print(twiceSignedArea(triangle), describe(twiceSignedArea(triangle)))
```

```output
40 20
-40 20
15 7.5
```

What to notice:

- The L-shape has a **reflex** corner (a dent) at (2, 2), and the formula doesn't care: concave polygons work as well as convex ones. Its area is 6 × 2 + 2 × 4 = 20.
- Reversing the corners flips the sign and nothing else.
- Twice the area of a polygon with whole-number corners is always a whole number, so `Int` holds it exactly. The real area is that or a half, like the triangle's 7.5.
- The perimeter, if you need it, is the sum of the edge lengths, `Double`s from the [first lesson](/dsa/learn/geo-points-vectors).

## Counting grid points: Pick's theorem

When every corner has whole-number coordinates, there's a beautiful link between area and **grid points** (points with whole-number coordinates). Let I be the number of grid points strictly inside, and B the number on the boundary. **Pick's theorem** says:

area = I + B / 2 − 1, so I = (2 × area − B + 2) / 2

B is easy to count. An edge from (x₁, y₁) to (x₂, y₂) passes through gcd(|x₂ − x₁|, |y₂ − y₁|) + 1 grid points, counting both ends. That's [the GCD](/dsa/learn/math-gcd-lcm) at work: the edge steps in gcd equal hops from one grid point to the next. Summing just the gcd for each edge counts every boundary point once, because each corner is the start of exactly one edge.

```text
4  o
3  o  o
2  o  ·  o          the triangle (0, 0), (4, 0), (0, 4)
1  o  ·  ·  o       o on the boundary: B = 4 + 4 + gcd(4, 4) = 12
0  o  o  o  o  o    · strictly inside: I = (16 − 12 + 2) / 2 = 3
   0  1  2  3  4
```

```swift run
func gcd(_ a: Int, _ b: Int) -> Int {
    b == 0 ? a : gcd(b, a % b)
}

/// Grid points strictly inside and on the boundary of a polygon with whole-number corners
func gridPoints(_ corners: [(x: Int, y: Int)]) -> (inside: Int, boundary: Int) {
    var twiceArea = 0
    var boundary = 0
    for i in corners.indices {
        let a = corners[i], b = corners[(i + 1) % corners.count]
        twiceArea += a.x * b.y - a.y * b.x
        boundary += gcd(abs(b.x - a.x), abs(b.y - a.y))
    }
    return ((abs(twiceArea) - boundary + 2) / 2, boundary)
}

print(gridPoints([(0, 0), (4, 0), (0, 4)]))
print(gridPoints([(0, 0), (6, 0), (6, 2), (2, 2), (2, 6), (0, 6)]))
print(gridPoints([(0, 0), (1_000_000, 0), (0, 1_000_000)]))
```

```output
(inside: 3, boundary: 12)
(inside: 9, boundary: 24)
(inside: 499998500001, boundary: 3000000)
```

The last triangle contains about half a trillion grid points, and counting them took three loop passes. Checking them one at a time would take hours.

## Is a point inside? Ray casting

Stand at the point and walk to the right, for ever. Each time you cross an edge you switch between inside and outside, and far enough to the right you're certainly outside. So: **count the edges a rightward ray crosses. Odd means inside, even means outside.** This is **ray casting**, also called the crossing-number or even-odd test.

```text
y
5  +-----+     +-----+
4  |     |     |     |
3  |     |  q  |  r  |      q in the notch: its ray crosses 2 edges, so outside
2  |     +-----+     |      r in the right arm: 1 edge, so inside
1  |                 |
0  +-----------------+
   0     2     4     6   x
```

The awkward moments are a ray that passes exactly through a corner, or runs along a horizontal edge. One rule settles both: **count an edge only when one end is strictly above the ray and the other isn't**, which in code is `(a.y > p.y) != (b.y > p.y)`. Where the boundary passes through a corner from below to above, exactly one of its two edges counts. At a peak or a valley, both count or neither does, which keeps the parity right. Horizontal edges never count.

Then, is that edge's crossing to the right of the point? You could compute its x-coordinate, but that divides. Orientation answers it exactly instead: for an edge going **up** from a to b, the crossing is to the right of p exactly when p is to the **left** of the edge; for an edge going down, when p is to its right.

Points **on** the boundary need deciding separately, and first, because parity says nothing reliable about them. A point is on an edge when its orientation is 0 and it's inside the edge's bounding box, as in [Segment intersection](/dsa/learn/geo-segment-intersection).

```swift run
struct Point {
    var x: Int
    var y: Int

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    func cross(_ other: Point) -> Int {
        x * other.y - y * other.x
    }
}

extension Point {
    init(_ x: Int, _ y: Int) {
        self.init(x: x, y: y)
    }
}

/// 1 inside, 0 on the boundary, -1 outside
func locate(_ p: Point, in polygon: [Point]) -> Int {
    var inside = false
    for i in polygon.indices {
        let a = polygon[i], b = polygon[(i + 1) % polygon.count]
        let turn = (b - a).cross(p - a)                      // positive: p is left of a → b
        if turn == 0 && min(a.x, b.x) <= p.x && p.x <= max(a.x, b.x)
            && min(a.y, b.y) <= p.y && p.y <= max(a.y, b.y) {
            return 0                                         // on this edge
        }
        if (a.y > p.y) != (b.y > p.y) {                      // the edge straddles the ray's line
            let crossesToTheRight = b.y > a.y ? turn > 0 : turn < 0
            if crossesToTheRight {
                inside.toggle()
            }
        }
    }
    return inside ? 1 : -1
}

let uShape = [Point(0, 0), Point(6, 0), Point(6, 5), Point(4, 5), Point(4, 2), Point(2, 2), Point(2, 5), Point(0, 5)]
for p in [Point(1, 1), Point(3, 3), Point(5, 3), Point(3, 2), Point(3, 5), Point(-1, 2), Point(6, 5)] {
    let place = ["outside", "on the boundary", "inside"][locate(p, in: uShape) + 1]
    print("(\(p.x), \(p.y)) is \(place)")
}
```

```output
(1, 1) is inside
(3, 3) is outside
(5, 3) is inside
(3, 2) is on the boundary
(3, 5) is outside
(-1, 2) is outside
(6, 5) is on the boundary
```

(3, 5) and (−1, 2) are the nasty ones: their rays run along horizontal edges and through corners. The half-open rule gives the right answer for both without any special cases. Each query looks at every edge once: **O(n)** for n corners.

## The winding number

Ray casting asks "how many crossings?". The **winding number** asks "how many times does the boundary wind around the point, counterclockwise?". It uses the same edges, but with signs: +1 for an upward edge with the point on its left, −1 for a downward edge with the point on its right. A non-zero total means inside.

For a simple polygon the two always agree: the winding number is ±1 inside and 0 outside. They differ for shapes that cross themselves. A five-pointed star drawn in one stroke goes round its centre **twice**: two crossings, so ray casting says outside, while the winding number, 2, says inside.

```swift run
struct Point {
    var x: Int
    var y: Int

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    func cross(_ other: Point) -> Int {
        x * other.y - y * other.x
    }
}

extension Point {
    init(_ x: Int, _ y: Int) {
        self.init(x: x, y: y)
    }
}

func windingNumber(of p: Point, in polygon: [Point]) -> Int {
    var winding = 0
    for i in polygon.indices {
        let a = polygon[i], b = polygon[(i + 1) % polygon.count]
        let turn = (b - a).cross(p - a)
        if a.y <= p.y && b.y > p.y && turn > 0 { winding += 1 }     // upward, p on its left
        if a.y > p.y && b.y <= p.y && turn < 0 { winding -= 1 }     // downward, p on its right
    }
    return winding
}

func oddCrossings(of p: Point, in polygon: [Point]) -> Bool {
    var inside = false
    for i in polygon.indices {
        let a = polygon[i], b = polygon[(i + 1) % polygon.count]
        let turn = (b - a).cross(p - a)
        if (a.y > p.y) != (b.y > p.y) && (b.y > a.y ? turn > 0 : turn < 0) {
            inside.toggle()
        }
    }
    return inside
}

// A five-pointed star drawn in one stroke, visiting every second corner of a pentagon
let star = [Point(0, 10), Point(-6, -8), Point(10, 3), Point(-10, 3), Point(6, -8)]
for p in [Point(0, 0), Point(0, 7), Point(12, 0)] {
    let parity = oddCrossings(of: p, in: star) ? "inside" : "outside"
    print("(\(p.x), \(p.y)): winding number \(windingNumber(of: p, in: star)), crossings say \(parity)")
}
```

```output
(0, 0): winding number 2, crossings say outside
(0, 7): winding number 1, crossings say inside
(12, 0): winding number 0, crossings say outside
```

You've seen this difference if you've filled a path on iOS. CoreGraphics' fill rules are `CGPathFillRule.winding` (non-zero winding, the default) and `.evenOdd` (ray casting), and SwiftUI's `FillStyle(eoFill:)` picks between them. With the even-odd rule, the star's centre is a hole.

<Callout kind="gotcha" title="Polygon pitfalls">
- **The closing edge.** Forget `pₙ₋₁ → p₀` and the area is wrong and point tests go haywire. Use `(i + 1) % n`.
- **A repeated first corner.** Some formats, GeoJSON for one, repeat the first corner at the end to close the ring. The shoelace sum doesn't mind (that edge adds 0), but drop it before anything that assumes neighbouring corners differ.
- **Boundary points.** Decide what "on the edge" should return, and check it before the parity count.
- **A running total that overflows.** With coordinates up to 10⁹, one shoelace term can reach 2 × 10¹⁸, and the running sum can pass `Int.max` partway round even though the final area fits. The wrapping operators `&+` and `&-` from [Overflow traps and overflow operators](/dsa/learn/swift-overflow) fix it: arithmetic that wraps round still ends on exactly the right total when that total fits.
</Callout>
