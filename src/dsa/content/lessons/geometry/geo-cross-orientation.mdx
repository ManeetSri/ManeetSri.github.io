## Why it matters

One small formula, the **cross product**, answers the question "which way?". Does this path turn left or right? Is that point to the left of the road or the right? Are these three points on one line? Almost every algorithm in this module is built on it: segment intersection, polygon area, point in polygon, convex hulls. Apps ask the same questions: a navigation app announcing "turn left", a drawing app deciding which side of a stroke a tap fell on, a game steering a character towards a target. With whole-number coordinates the answer is exact, needs no trigonometry and costs two multiplications.

## The 2D cross product

For two vectors a and b, the cross product is:

cross(a, b) = a.x × b.y − a.y × b.x

(In 3D the cross product is a vector. For flat vectors, (a.x, a.y, 0) and (b.x, b.y, 0), it points straight out of the page, and this number is its only non-zero coordinate. So in 2D, people keep just the number.)

It means something you can draw: **the signed area of the parallelogram with sides a and b**.

```text
y
2       b-----------a+b
1     /           /
0   o-----------a
    0   1   2   3   4   x

a = (3, 0), b = (1, 2): base 3, height 2, area 6
cross(a, b) = 3 × 2 − 0 × 1 = 6
```

Swap the order and the area stays the same size, but the sign flips: cross(b, a) = 1 × 0 − 2 × 3 = −6. That sign is the useful part:

| cross(a, b) | Turning from a to b, the short way | Example with a = (3, 0) |
| --- | --- | --- |
| positive | counterclockwise: a left turn | b = (1, 2) gives 6 |
| negative | clockwise: a right turn | b = (2, −1) gives −3 |
| zero | no turn: a and b are parallel | b = (6, 0) or (−3, 0) give 0 |

Zero means the parallelogram is flat: b points the same way as a, or exactly the opposite way.

```swift run
struct Point {
    var x: Int
    var y: Int

    func cross(_ other: Point) -> Int {
        x * other.y - y * other.x
    }
}

let a = Point(x: 3, y: 0)
let others = [("(1, 2)", Point(x: 1, y: 2)), ("(2, -1)", Point(x: 2, y: -1)),
              ("(6, 0)", Point(x: 6, y: 0)), ("(-3, 0)", Point(x: -3, y: 0))]
for (label, b) in others {
    print("b = \(label): cross(a, b) = \(a.cross(b)), cross(b, a) = \(b.cross(a))")
}
```

```output
b = (1, 2): cross(a, b) = 6, cross(b, a) = -6
b = (2, -1): cross(a, b) = -3, cross(b, a) = 3
b = (6, 0): cross(a, b) = 0, cross(b, a) = 0
b = (-3, 0): cross(a, b) = 0, cross(b, a) = 0
```

A triangle is half a parallelogram, so the triangle with sides a and b has area |cross(a, b)| / 2. Halving can leave a fraction, so geometry code usually keeps **twice the area** as an `Int` and halves only when it prints.

Compare it with the dot product from the [previous lesson](/dsa/learn/geo-points-vectors): the dot product is zero for perpendicular vectors and measures "how much the same way"; the cross product is zero for parallel ones and measures "how much it turns". Between them, they describe the angle completely.

## Orientation of three points

Now use three points. Walk from a to b, then on to c. Do you turn left, turn right, or carry straight on? Measure both legs from a and take the cross product:

orientation(a, b, c) = cross(b − a, c − a)

```text
                c   (a left turn: positive)
               /
  a --------- b
               \
                c   (a right turn: negative)
```

- **Positive:** c is to the left of the line from a to b, and a → b → c runs counterclockwise.
- **Negative:** c is to the right, and the three run clockwise.
- **Zero:** a, b and c are **collinear**: on one line.

Code usually reduces it to its sign, −1, 0 or 1, because the sign is all the later algorithms need, and small numbers are safe to combine.

```swift run
struct Point {
    var x: Int
    var y: Int

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    func cross(_ other: Point) -> Int {
        x * other.y - y * other.x
    }
}

/// 1 if a → b → c turns left (counterclockwise), -1 if it turns right, 0 if the three are collinear
func orientation(_ a: Point, _ b: Point, _ c: Point) -> Int {
    let cross = (b - a).cross(c - a)
    return cross > 0 ? 1 : (cross < 0 ? -1 : 0)
}

let a = Point(x: 0, y: 0), b = Point(x: 4, y: 2)
for c in [Point(x: 1, y: 3), Point(x: 5, y: 0), Point(x: 8, y: 4), Point(x: -2, y: -1), Point(x: 2, y: 2)] {
    let side = ["right of", "on", "left of"][orientation(a, b, c) + 1]
    print("(\(c.x), \(c.y)) is \(side) the line through a and b")
}
```

```output
(1, 3) is left of the line through a and b
(5, 0) is right of the line through a and b
(8, 4) is on the line through a and b
(-2, -1) is on the line through a and b
(2, 2) is left of the line through a and b
```

Notice (−2, −1). It's behind a, nowhere near the segment from a to b, yet orientation calls it collinear, because the **line** through a and b goes on for ever in both directions. Whether a point lies on the **segment** needs one more check, and that's the next lesson.

## Three things orientation gives you at once

### Is a shape convex?

A polygon is **convex** when it has no dents: walk round its corners and every turn goes the same way. One right turn among left turns is a dent. Straight-on corners (zero) are allowed.

```swift run
struct Point {
    var x: Int
    var y: Int

    static func - (lhs: Point, rhs: Point) -> Point {
        Point(x: lhs.x - rhs.x, y: lhs.y - rhs.y)
    }

    func cross(_ other: Point) -> Int {
        x * other.y - y * other.x
    }
}

func orientation(_ a: Point, _ b: Point, _ c: Point) -> Int {
    let cross = (b - a).cross(c - a)
    return cross > 0 ? 1 : (cross < 0 ? -1 : 0)
}

/// For a polygon that doesn't cross itself: are all its turns the same way?
func isConvex(_ corners: [Point]) -> Bool {
    var sawLeft = false
    var sawRight = false
    let n = corners.count
    for i in 0..<n {
        let turn = orientation(corners[i], corners[(i + 1) % n], corners[(i + 2) % n])
        if turn > 0 { sawLeft = true }
        if turn < 0 { sawRight = true }
    }
    return !(sawLeft && sawRight)
}

let square = [Point(x: 0, y: 0), Point(x: 4, y: 0), Point(x: 4, y: 4), Point(x: 0, y: 4)]
let arrowhead = [Point(x: 0, y: 0), Point(x: 4, y: 2), Point(x: 0, y: 4), Point(x: 1, y: 2)]
let withStraight = [Point(x: 0, y: 0), Point(x: 2, y: 0), Point(x: 4, y: 0), Point(x: 2, y: 3)]
print(isConvex(square), isConvex(arrowhead), isConvex(withStraight))
```

```output
true false true
```

The arrowhead turns left at three corners and right at (1, 2), its dent. The last shape goes straight through (2, 0), which is fine. `% n` wraps the indexes round, so the last corners pair up with the first ones. One caution: the check assumes the polygon doesn't cross itself. A five-pointed star drawn in one stroke turns left at every corner, and it certainly isn't convex.

### Triangle area, exactly

Twice the area of triangle abc is |orientation's cross product|, before you take the sign. The next lessons build polygon area out of exactly these triangles.

### Collinear, without slopes

The classic way to test "are these three points on one line?" compares slopes, (y₂ − y₁) / (x₂ − x₁). That divides, which brings in `Double` rounding, and it crashes or needs a special case for vertical lines, whose slope doesn't exist. `orientation(a, b, c) == 0` handles every line, vertical ones included, with two exact multiplications.

## How big can the numbers get?

Every coordinate of the input is between −C and C. Then every difference, like b.x − a.x, is at most 2C in size, each product at most 4C², and the cross product, one product minus another, at most 8C². `Int.max` is about 9.22 × 10¹⁸.

| Largest coordinate C | Largest cross product, 8C² | Fits in Int? |
| --- | --- | --- |
| 10⁶ | 8 × 10¹² | easily |
| 10⁹ | 8 × 10¹⁸ | just |
| 2 × 10⁹ | 3.2 × 10¹⁹ | no |

That's why so many problems promise coordinates up to 10⁹: the cross product just fits. Beyond that, a multiplication traps, and the program stops:

```text title="What you'll see"
Swift runtime failure: arithmetic overflow
```

When the inputs really are bigger, you don't need the cross product's value, only its sign, so compare its two products instead of subtracting them. `multipliedFullWidth(by:)` returns the exact product of two `Int`s as a pair of halves: `high`, the top 64 bits (signed), and `low`, the bottom 64 bits (unsigned). Tuples compare from left to right, so comparing `(high, low)` pairs compares the full 128-bit products.

```swift run
/// The sign of ax * by - ay * bx for any Int inputs. The two products are compared at full width
/// (128 bits), so nothing overflows.
func crossSign(_ ax: Int, _ ay: Int, _ bx: Int, _ by: Int) -> Int {
    let left = ax.multipliedFullWidth(by: by)
    let right = ay.multipliedFullWidth(by: bx)
    if (left.high, left.low) > (right.high, right.low) { return 1 }
    if (left.high, left.low) < (right.high, right.low) { return -1 }
    return 0
}

let big = 4_000_000_000
print(crossSign(big, big - 1, big + 1, big))      // each product is about 1.6 × 10¹⁹
print(crossSign(big, big, big + 1, big + 1))      // parallel
print(crossSign(3, 0, 1, 2))
```

```output
1
0
1
```

The first pair of products, 4 × 10⁹ × 4 × 10⁹ and (4 × 10⁹ − 1)(4 × 10⁹ + 1), differ by exactly 1, and the full-width comparison still sees it. Swift 6 also adds an `Int128` type, on macOS 15 and iOS 18 or later, which makes this a plain subtraction.

<Callout kind="gotcha" title="Orientation slips">
- **Screens are upside down.** UIKit and SwiftUI put the origin at the top left with y growing *downwards*. The same formula then gives the opposite answer: positive means clockwise as you see it. SpriteKit scenes, like the maths here, have y growing upwards.
- **Order matters.** Swapping any two of a, b and c flips the sign. Decide what "positive" means in your function's doc comment and stick to it.
- **Reduce to a sign before combining.** Two cross products can each be near 8 × 10¹⁸, so multiplying them to compare signs overflows. Multiply the signs (−1, 0 or 1) instead.
- **Doubles are never exactly collinear.** With `Double` coordinates a cross product of `1e-17` isn't zero. The last lesson of this module deals with that.
</Callout>

## Practice

**Waypoint turns** labels every turn of a route as left, right, straight on or a U-turn: the cross product picks left or right, and when it's zero, the dot product tells straight on from doubling back. The coordinates go up to 10⁹, so check your products against the table above. If you want more, **[Most points on one line](/dsa/practice/most-points-on-line)** from the hashing module is a good revisit: orientation is the exact collinearity test to check your answers against.
