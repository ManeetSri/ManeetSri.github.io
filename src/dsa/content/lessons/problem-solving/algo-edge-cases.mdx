## Why it matters

Most wrong answers aren't wrong on the normal case. They're wrong on an empty list, a single element, a repeated value or a huge number, and in Swift many of those mistakes don't give a wrong answer, they crash. M00 gave you a list of edge cases. This lesson shows what each one tends to break, and how to turn the list into tests you run every time.

## The checklist

An **edge case** is an input at the boundary of what's allowed: the smallest, the largest, the emptiest, the most repetitive. Go through this list for every problem:

| Case | Example | What it tends to break |
| --- | --- | --- |
| Empty | `[]`, `""` | `numbers[0]`, `first!`, ranges like `1..<0`, dividing by the count |
| One element | `[7]` | anything about pairs, or a "second" anything |
| Duplicates | `[4, 4, 2]` | `>` versus `>=`, counting *different* values |
| Negatives and zero | `[-5, -2]`, `0` | starting a best value at 0, odd and even tests, digit loops |
| Extremes | `Int.max`, `10⁹` | overflow when adding, multiplying or subtracting |
| Already sorted or reversed | `[1, 2, 3]`, `[3, 2, 1]` | early exits, loops that assume some disorder |
| No answer | nothing matches | what to return: `nil`, `-1` or an empty array |

Not every row applies to every problem, and the constraints rule some out. If they say `1 ≤ n`, the input is never empty. That's one more reason to read them first, as the next lesson explains.

## A worked example: the spread of a list

The **spread** of a list is its largest value minus its smallest. Here's a first attempt:

```swift
func spread(_ numbers: [Int]) -> Int {
    numbers.max()! - numbers.min()!
}
```

It works for `[3, 9, 4]`, giving 6. Now walk the checklist:

- **Empty.** `numbers.max()` is `nil`, and the force unwrap crashes. There's no sensible spread of nothing, so this is really the "no answer" case: return `nil`, making the result `Int?`.
- **One element.** `[7]` gives 7 − 7 = 0. Fine.
- **Duplicates.** `[4, 4]` gives 0. Fine.
- **Negatives.** `[-5, -2]` gives -2 − (-5) = 3. Fine.
- **Extremes.** With values up to 10⁹, the spread is at most 2 × 10⁹, which fits easily in an `Int`. If values could be anything, `Int.max - Int.min` would overflow and crash. The constraints tell you which world you're in.
- **Sorted.** Makes no difference here.

Only the empty case needed a change:

```swift run
func spread(_ numbers: [Int]) -> Int? {
    guard let smallest = numbers.min(), let largest = numbers.max() else {
        return nil
    }
    return largest - smallest
}

let cases: [[Int]] = [[], [7], [4, 4], [-5, -2], [1_000_000_000, -1_000_000_000]]
for numbers in cases {
    if let answer = spread(numbers) {
        print(numbers, "has spread", answer)
    } else {
        print(numbers, "has no spread")
    }
}
```

```output
[] has no spread
[7] has spread 0
[4, 4] has spread 0
[-5, -2] has spread 3
[1000000000, -1000000000] has spread 2000000000
```

The checklist took a minute and found the one crash. That's the usual return on the investment.

## Negative numbers: a classic trap

Here's a check for odd numbers that looks fine:

```swift
func isOdd(_ n: Int) -> Bool {
    n % 2 == 1
}
```

Try a negative number:

```swift run
print(7 % 2)
print(-7 % 2)
print(-7 % 2 != 0)
```

```output
1
-1
true
```

In Swift, the remainder takes the sign of the number being divided, so `-7 % 2` is -1, not 1, and `isOdd(-7)` returns `false`. Testing `n % 2 != 0` works for every integer. You'd never find this bug testing only positive numbers, which is exactly why "negatives" is on the list.

## Turning the checklist into tests

Edge cases are most useful written down as tests, so they're checked every time the code changes. With Swift Testing, from M12, a table of cases is short:

```swift
@Test("Spread edge cases", arguments: [
    ([Int](), nil),
    ([7], 0),
    ([4, 4], 0),
    ([-5, -2], 3),
    ([1_000_000_000, -1_000_000_000], 2_000_000_000),
] as [([Int], Int?)])
func spreadEdges(numbers: [Int], expected: Int?) {
    #expect(spread(numbers) == expected)
}
```

Each row is one item from the checklist. The tests that come with this course's problems are built the same way, which is why a solution that passes the examples in a statement can still fail its tests.

<Callout kind="gotcha" title="Swift gotcha: where edge cases crash">
Swift stops your program rather than return garbage. The usual edge-case crashes are:

- `numbers[0]`, `numbers.first!` or `numbers.max()!` on an empty array;
- a range like `1..<numbers.count` when the array is empty;
- dividing by `numbers.count` to take an average of nothing;
- `abs(Int.min)` or `-Int.min`, which have no positive `Int` to land on.

When you see one of these in your code, ask which input could reach it.
</Callout>

## A habit, not a phase

Use the checklist at three moments: while you're working through examples before coding, when you write the code's first line (what does the empty case return?), and when you write tests. It takes seconds once it's familiar.
