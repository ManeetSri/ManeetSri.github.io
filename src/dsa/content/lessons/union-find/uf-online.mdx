## Why it matters

A map app shows flood zones as rain falls. A game reveals the board tile by tile and needs to know which regions have joined. A spreadsheet checks that a list of constraints can all hold at once. These problems are **online**: the input arrives piece by piece, and you need an answer after every piece. Rerunning a full search each time is far too slow, and union-find, which only ever merges, fits them perfectly. This lesson covers the two classic interview versions: islands that rise from the sea one cell at a time, and deciding whether a set of equalities and inequalities can all be true.

## Offline and online

In [Number of islands and island area](/dsa/learn/gt-islands) you counted islands in a finished grid: one flood fill over every cell, O(rows · columns). That's an **offline** problem: all the input is there before you answer.

Now the grid starts as all water, and cells turn into land one at a time. After each new cell, how many islands are there? Rerunning the flood fill after every addition costs O(rows · columns) each time. On a 300 × 300 grid where every cell eventually rises, that's 90,000 flood fills of up to 90,000 cells: about 8 billion steps.

Union-find handles each new cell with at most four unions. The whole sequence of k additions costs O(rows · columns + k α), essentially linear.

## Islands rising, one cell at a time

Give every cell an index, `row * columns + column`, so a rows × columns grid is a union-find over `rows * columns` elements. Keep a count of islands. When a water cell becomes land:

1. It's a brand-new island of one cell: add one to the count.
2. Look at its four neighbours (up, down, left, right). For each one that's already land, union the two cells. Every union that **returns true** merged two different islands, so subtract one.

If the cell was already land, nothing changes.

```swift run
// The UnionFind from "Path compression and union by rank"
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        return true
    }
}

let rows = 4
let columns = 5
var islands = UnionFind(count: rows * columns)
var isLand = Array(repeating: false, count: rows * columns)
var count = 0

func addLand(_ row: Int, _ column: Int) -> Int {
    let cell = row * columns + column
    if isLand[cell] { return count }                  // already land: nothing changes
    isLand[cell] = true
    count += 1                                        // a brand-new island of one cell
    for (dr, dc) in [(-1, 0), (1, 0), (0, -1), (0, 1)] {
        let r = row + dr
        let c = column + dc
        guard r >= 0, r < rows, c >= 0, c < columns, isLand[r * columns + c] else { continue }
        if islands.union(cell, r * columns + c) {
            count -= 1                                // two islands became one
        }
    }
    return count
}

for (row, column) in [(0, 0), (0, 2), (1, 1), (2, 3), (0, 1), (2, 2), (1, 2), (0, 0), (3, 4)] {
    print("land at (\(row), \(column)) -> islands: \(addLand(row, column))")
}
for row in 0..<rows {
    print((0..<columns).map { isLand[row * columns + $0] ? "#" : "." }.joined())
}
```

```output
land at (0, 0) -> islands: 1
land at (0, 2) -> islands: 2
land at (1, 1) -> islands: 3
land at (2, 3) -> islands: 4
land at (0, 1) -> islands: 2
land at (2, 2) -> islands: 2
land at (1, 2) -> islands: 1
land at (0, 0) -> islands: 1
land at (3, 4) -> islands: 2
###..
.##..
..##.
....#
```

What to notice:

- **(0, 1) joins three islands at once.** It starts as a fourth island (count 5), then its unions with (0, 0), (0, 2) and (1, 1) each return true: 5 − 3 = 2.
- **(1, 2) shows why the Bool matters.** Its first two unions, with (0, 2) above and (2, 2) below, join two islands into one. Its third neighbour, (1, 1), is already in that same island by then, so that union returns false and the count stays at 1. Subtracting one per land neighbour would have given 0.
- **(0, 0) a second time** changes nothing, and **(3, 4)** touches (2, 3) only diagonally, which doesn't count, so it's a new island.

When the grid has no fixed size, or is too big to allocate, create elements only as cells appear: a dictionary from (row, column) to index, and DSAKit's `addElement()` to make a new singleton set for each new cell.

## Can the equations all hold?

You're given equations between variables, each either `a == b` or `a != b`. Can you give every variable an integer so that all of them are true at once?

Equality and inequality behave very differently:

- **Equality is transitive.** `a == b` and `b == c` force `a == c`. So the equalities split the variables into groups that must all share one value: exactly union-find's disjoint sets.
- **Inequality isn't.** `a != b` and `b != c` say nothing about a and c. An inequality never forces anything; it can only be **broken**, when its two sides are forced into the same group.

So the algorithm has two passes:

1. Union the two sides of every `==` equation.
2. For every `!=` equation, if its two sides are now connected, the system is contradictory. Otherwise, give each group its own number and every equation holds.

```swift run
// The UnionFind from "Path compression and union by rank"
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    @discardableResult
    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        return true
    }
}

func canAllHold(_ equations: [(String, String, String)]) -> Bool {
    var indexOf: [String: Int] = [:]
    for (left, _, right) in equations {
        for name in [left, right] where indexOf[name] == nil {
            indexOf[name] = indexOf.count
        }
    }
    var groups = UnionFind(count: indexOf.count)
    for (left, op, right) in equations where op == "==" {
        groups.union(indexOf[left]!, indexOf[right]!)            // pass 1: equalities
    }
    for (left, op, right) in equations where op == "!=" {
        if groups.find(indexOf[left]!) == groups.find(indexOf[right]!) {
            print("  broken: \(left) != \(right)")
            return false                                          // pass 2: inequalities
        }
    }
    return true
}

print(canAllHold([("a", "==", "b"), ("b", "!=", "c"), ("c", "==", "d")]))
print(canAllHold([("x", "!=", "z"), ("x", "==", "y"), ("y", "==", "z")]))
print(canAllHold([("p", "!=", "q"), ("q", "!=", "r"), ("r", "!=", "p")]))
print(canAllHold([("n", "!=", "n")]))
```

```output
true
  broken: x != z
false
true
  broken: n != n
false
```

The second system shows why the passes must be separate. `x != z` comes first, when x and z are still apart, so checking it straight away would pass it. Only after `x == y` and `y == z` does it become clear that x and z must be equal. With all the equalities in first, every inequality is checked against the final groups.

The third system is satisfiable even though every pair is unequal: 1, 2 and 3 will do. And `n != n` can never hold, because a variable is always in its own group.

The cost, for m equations, is O(m α(m)) plus the dictionary work: linear in practice.

## When things can also come apart

Union-find only ever merges. If land could sink back into the sea, or an equation could be withdrawn, a set would have to split, and union-find has no way to do that.

One escape works when you know every change in advance: process them **in reverse**. Start from the final state, then walk backwards through the changes, so that every removal becomes an addition. Record the answers as you go and reverse them at the end. This **offline reversal** trick turns "edges keep disappearing" into "edges keep appearing", which union-find handles. The next lesson shows another tool, a union-find that can undo its most recent unions.

<Callout kind="gotcha" title="Common mistakes">
- **The wrong index formula.** A cell is `row * columns + column`. Using rows instead of columns maps different cells to the same index unless the grid is square.
- **Counting a repeated cell twice.** Check `isLand` first: a cell that's already land is not a new island.
- **Subtracting one per land neighbour.** Two neighbours can already be in the same island. Subtract only when `union` returns true.
- **Checking an inequality early.** Do every `==` before any `!=`, or a later equality can break an inequality you already passed.
</Callout>
