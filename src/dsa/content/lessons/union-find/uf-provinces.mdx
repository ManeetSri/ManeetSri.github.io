## Why it matters

Three of the most common union-find questions are really one idea seen from different sides. How many separate groups are there? Which link was one too many? Do these links form a tree? Network tools ask them about cables, social apps about friendships, and build systems about module links. Each is a few lines on top of the union-find you just built, and each depends on the one fact that `union` reports: **did these two already belong together?**

## Counting groups

Every element starts in a group of its own, so there are n groups. A union that joins two different groups leaves one fewer. A union inside a group changes nothing. So the number of groups is n minus the number of unions that returned true, which is exactly what `componentCount` tracks.

```swift run
// The UnionFind from the last lesson
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]
    private(set) var componentCount: Int

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
        componentCount = count
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    @discardableResult
    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        componentCount -= 1
        return true
    }
}

let friendships = [[0, 1], [2, 3], [1, 4], [5, 6], [4, 0]]
var people = UnionFind(count: 8)
for pair in friendships {
    let joined = people.union(pair[0], pair[1])
    print("\(pair[0])–\(pair[1]):", joined ? "two groups join" : "already one group", "->", people.componentCount, "groups")
}
```

```output
0–1: two groups join -> 7 groups
2–3: two groups join -> 6 groups
1–4: two groups join -> 5 groups
5–6: two groups join -> 4 groups
4–0: already one group -> 4 groups
```

The four groups are \{0, 1, 4\}, \{2, 3\}, \{5, 6\} and \{7\}. Person 7 has no friends at all and still counts as a group.

A DFS from [Connected components and flood fill](/dsa/learn/gt-components) gives the same answer in O(V + E). Union-find does it in O(V + E α(V)), effectively the same, but it reads the pairs straight from the list: no adjacency list to build, and the count is up to date after every pair.

Sometimes the friendships come as an n × n matrix, where `matrix[i][j] == 1` means i and j are friends. Visit each pair once, with j above i:

```swift
for i in 0..<n {
    for j in (i + 1)..<n where matrix[i][j] == 1 {
        people.union(i, j)
    }
}
```

That's O(n²) to read the matrix, whatever the structure does.

## The link that closes a cycle

A network of n computers was wired as a tree: every computer reachable, no loops, n − 1 cables. Then someone added one more cable. Which cable can you remove to get a tree back?

A tree plus one edge has exactly **one cycle**, and removing any edge on that cycle restores a tree. To pick one answer, problems usually ask for the cycle edge that comes **latest** in the input. Union-find finds it in a single pass: add the cables in order, and the first one whose ends are already connected is the answer.

Why is the first failing union the latest edge of the cycle? Every cable before it joined two separate groups, so those cables contain no cycle at all. The failing cable joins two computers that are already connected, so it closes a cycle made of itself and earlier cables. That's the one cycle, and this cable comes after all its other edges.

```swift run
// The UnionFind from the last lesson
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        return true
    }
}

func extraCable(_ cables: [[Int]]) -> [Int] {
    var network = UnionFind(count: cables.count)      // n cables for n computers
    for cable in cables {
        if !network.union(cable[0], cable[1]) {
            return cable                               // its ends were already connected
        }
    }
    return []
}

print(extraCable([[0, 1], [1, 2], [3, 4], [2, 3], [4, 1]]))
print(extraCable([[0, 1], [0, 2], [2, 1], [1, 3]]))
```

```output
[4, 1]
[2, 1]
```

In the first network, the cycle is 1–2–3–4–1. Cables 0–1, 1–2, 3–4 and 2–3 each join two groups; 4–1 finds 4 and 1 already connected. Watch the same unions, including the one that returns false:

```visual unionFind

operations: ["union 0 1", "union 1 2", "union 3 4", "union 2 3", "union 4 1"]
```

### Cycle detection in undirected graphs

This is a general tool: **an undirected graph has a cycle exactly when some union returns false**. It's the union-find version of the DFS check in [Cycle detection in undirected and directed graphs](/dsa/learn/gt-cycles), and it's the heart of Kruskal's algorithm in the next module.

<Callout kind="warning" title="Not for directed graphs">
Union-find ignores direction. With the edges a → b, b → c and a → c there's no directed cycle (you can never get back to a), but the third union finds a and c already connected. For directed graphs, use the DFS colouring check or [Kahn's algorithm](/dsa/learn/topo-kahn).
</Callout>

## Is it a tree?

A **tree** on n nodes is connected and has no cycles. Checking both sounds like two jobs, but a counting fact makes it one.

Think about adding edges one at a time with union-find. An edge that joins two groups lowers the number of groups by one. An edge inside a group closes a cycle. So if a graph has **no cycles**, every edge lowered the count, and with E edges there are n − E groups. That gives:

- no cycle and **n − 1 edges** means n − (n − 1) = 1 group: connected, so a tree;
- fewer than n − 1 edges can never connect n nodes;
- more than n − 1 edges must contain a cycle.

So the check is: exactly n − 1 edges, and no union returns false.

```swift run
// The UnionFind from the last lesson
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        return true
    }
}

func isTree(_ n: Int, _ links: [[Int]]) -> Bool {
    guard links.count == n - 1 else { return false }
    var nodes = UnionFind(count: n)
    for link in links where !nodes.union(link[0], link[1]) {
        return false                       // this link closes a cycle
    }
    return true
}

print(isTree(5, [[0, 1], [0, 2], [2, 3], [2, 4]]))
print(isTree(5, [[0, 1], [1, 2], [2, 0], [3, 4]]))
print(isTree(4, [[0, 1], [2, 3]]))
print(isTree(1, []))
```

```output
true
false
false
true
```

The second graph has the right number of edges, 4, but 2–0 closes a cycle, and that leaves 3–4 as a separate piece. The third has too few edges to be connected. A single node with no edges is a tree.

<Callout kind="gotcha" title="Edge cases that catch people out">
- **The same link twice.** The second copy finds its ends already connected: a cycle of length 2. That's right: two cables between the same computers form a loop.
- **A link from a node to itself.** `union(a, a)` returns false, so it counts as a cycle too.
- **Skipping the count check.** Without it, `isTree(4, [[0, 1], [2, 3]])` sees no cycle and wrongly says yes.
- **n cables for n computers.** In the extra-cable problem the computers are numbered up to `cables.count - 1`: size the union-find by the number of cables, not the largest label plus one, unless the statement says otherwise.
</Callout>
