## Why it matters

The parent-array union-find from the last lesson is correct but can degrade into chains, making each operation O(n). Two small changes fix it. **Union by size** stops tall trees from forming, and **path compression** flattens whatever paths find walks. Each takes a few lines. Together they make union-find one of the fastest data structures there is: any realistic sequence of operations costs a small constant per operation. This is the version you'll write in interviews, the one DSAKit ships, and the one Kruskal's algorithm relies on.

## Union by size: the smaller tree goes underneath

When union joins two trees, one root must go under the other. The naive version always chose the same way round, whatever the trees looked like. Instead, keep a `size` for every root, the number of elements in its tree, and always hang the **smaller** tree under the **larger** root:

```swift
mutating func union(_ a: Int, _ b: Int) -> Bool {
    var rootA = find(a)
    var rootB = find(b)
    if rootA == rootB { return false }
    if size[rootA] < size[rootB] {
        swap(&rootA, &rootB)          // now rootA's tree is the larger one
    }
    parent[rootB] = rootA             // the smaller tree goes under the larger root
    size[rootA] += size[rootB]
    return true
}
```

Only roots' sizes matter, so only `size[rootA]` is updated. The old `size[rootB]` is never read again.

### Why the trees stay shallow

Follow a single element x. Its depth only grows when its tree is hung under another root, and that only happens when its tree is the smaller one (or equal). So every time x gets one step deeper, the tree it belongs to at least **doubles** in size. A tree can't double more than log₂ n times before it holds all n elements. So no element is ever deeper than log₂ n: for a million elements, at most 19 links from the root.

The chain order that ruined the naive version now builds a star, and even the worst order, merging equal-sized trees in rounds, only reaches log₂ n:

```swift run
struct SizedUnionFind {
    var parent: [Int]
    var size: [Int]

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
    }

    func find(_ x: Int) -> Int {
        var node = x
        while parent[node] != node { node = parent[node] }
        return node
    }

    func depth(_ x: Int) -> Int {
        var node = x
        var links = 0
        while parent[node] != node {
            node = parent[node]
            links += 1
        }
        return links
    }

    mutating func union(_ a: Int, _ b: Int) {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
    }
}

var chain = SizedUnionFind(count: 1_024)
for i in 0..<1_023 {
    chain.union(i, i + 1)                 // the order that built a chain before
}
print("chain order: the deepest node is at depth", (0..<1_024).map { chain.depth($0) }.max()!)

var rounds = SizedUnionFind(count: 1_024)
var step = 1
while step < 1_024 {                      // pairs, then pairs of pairs, and so on
    for i in stride(from: 0, to: 1_024, by: 2 * step) {
        rounds.union(i, i + step)
    }
    step *= 2
}
print("equal merges in rounds: the deepest node is at depth", (0..<1_024).map { rounds.depth($0) }.max()!)
```

```output
chain order: the deepest node is at depth 1
equal merges in rounds: the deepest node is at depth 10
```

With 1,024 elements, log₂ n is 10, so the bound is exact: union by size alone guarantees O(log n) per find, in the worst case.

### Union by rank

Many textbooks use **rank** instead of size. A root's rank is an upper bound on its tree's height: the lower-rank root goes underneath, and when two ranks are equal, one root's rank goes up by one. It gives the same log₂ n guarantee and fits in a smaller number. Size has one big advantage: it answers "how big is this group?" for free, which many problems ask. DSAKit uses size; either is fine in an interview.

## Path compression: flatten as you go

union by size keeps trees short. **Path compression** makes them flatter still. When find walks from x up to the root, every node it passes has the same root. So after finding it, walk the path a second time and point every node **straight at the root**. The next find from any of them takes one step.

```swift
mutating func find(_ x: Int) -> Int {
    var root = x
    while parent[root] != root {          // first pass: walk up to the root
        root = parent[root]
    }
    var node = x
    while node != root {                  // second pass: point each node at the root
        let next = parent[node]
        parent[node] = root
        node = next
    }
    return root
}
```

Notice `let next = parent[node]` before overwriting `parent[node]`: without it, you'd lose the way up. A popular one-pass variant, **path halving**, points every node at its grandparent as it climbs:

```swift
mutating func find(_ x: Int) -> Int {
    var node = x
    while parent[node] != node {
        parent[node] = parent[parent[node]]   // skip a level
        node = parent[node]
    }
    return node
}
```

Here's what each does to a chain of six:

```swift run
func compressed(_ start: [Int], from x: Int) -> [Int] {
    var parent = start
    var root = x
    while parent[root] != root { root = parent[root] }
    var node = x
    while node != root {
        let next = parent[node]
        parent[node] = root
        node = next
    }
    return parent
}

func halved(_ start: [Int], from x: Int) -> [Int] {
    var parent = start
    var node = x
    while parent[node] != node {
        parent[node] = parent[parent[node]]
        node = parent[node]
    }
    return parent
}

let chain = [1, 2, 3, 4, 5, 5]            // 0 → 1 → 2 → 3 → 4 → 5
print("before:     ", chain)
print("compression:", compressed(chain, from: 0))
print("halving:    ", halved(chain, from: 0))
```

```output
before:      [1, 2, 3, 4, 5, 5]
compression: [5, 5, 5, 5, 5, 5]
halving:     [2, 2, 4, 4, 5, 5]
```

Compression flattens the whole path in one go. Halving does half the work now and halves the path's length; repeated finds finish the job. Both give the same long-run bound.

### Why not the recursive one-liner?

You'll often see path compression written recursively:

```swift
mutating func find(_ x: Int) -> Int {
    if parent[x] != x { parent[x] = find(parent[x]) }
    return parent[x]
}
```

It's elegant, and with union by size the depth is at most log₂ n, so it's safe. But it uses one stack frame per level. Without union by size, or on a structure built some other way, a chain of a million nodes means a million nested calls, and the program crashes, as in [Stack depth limits in Swift](/dsa/learn/rec-stack-limits). The loop version can't overflow, so prefer it. You met this trade-off in [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack): here the loop is no harder to write.

## How fast is it? Counting steps

| Version | Cost per operation |
| --- | --- |
| Neither | O(n) in the worst case |
| Union by size (or rank) only | O(log n) in the worst case |
| Path compression only | O(log n) amortised |
| Both | O(α(n)) amortised |

**Amortised** means averaged over a whole sequence of operations, as in [Amortised analysis](/dsa/learn/bigo-amortised): one find might still walk log n links, but it flattens the path so that later finds are cheap, and the total for m operations is at most m times the bound.

**α(n)** is the **inverse Ackermann function**. The Ackermann function grows so absurdly fast that its inverse barely grows at all: α(n) is at most 4 for any n you could ever store in a computer. Robert Tarjan proved the O(m α(n)) bound in 1975, and later work showed that no union-find can do better. The proof is long and you don't need it. What you need is the conclusion: **treat each operation as O(1) in practice**, and say "amortised inverse Ackermann" if asked for the exact bound.

Timings are noisy, so count the work instead. This runs the same operations, a chain of unions and then a seeded mix of 10,000 unions and 10,000 pairs of finds, on all four versions, and counts every parent link that find follows:

```swift run
struct CountingUnionFind {
    var parent: [Int]
    var size: [Int]
    let bySize: Bool
    let compress: Bool
    var steps = 0                                // parent links followed, in total

    init(count: Int, bySize: Bool, compress: Bool) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
        self.bySize = bySize
        self.compress = compress
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root {
            root = parent[root]
            steps += 1
        }
        if compress {
            var node = x
            while node != root {
                let next = parent[node]
                parent[node] = root
                node = next
            }
        }
        return root
    }

    mutating func union(_ a: Int, _ b: Int) {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return }
        if bySize && size[rootA] > size[rootB] {
            swap(&rootA, &rootB)                 // make rootA the smaller tree
        }
        parent[rootA] = rootB
        size[rootB] += size[rootA]
    }
}

// The same operations for every version: unions that build a chain, then a seeded mix
var seed: UInt64 = 2024
func random(below limit: Int) -> Int {
    seed = seed &* 6364136223846793005 &+ 1442695040888963407
    return Int((seed >> 33) % UInt64(limit))
}
let n = 4_096
let chain = (0..<(n / 2 - 1)).map { (union: true, a: $0, b: $0 + 1) }
let mix = (0..<20_000).map { step in (union: step % 2 == 0, a: random(below: n), b: random(below: n)) }

for (name, bySize, compress) in [("naive", false, false), ("union by size", true, false),
                                 ("path compression", false, true), ("both", true, true)] {
    var sets = CountingUnionFind(count: n, bySize: bySize, compress: compress)
    for operation in chain + mix {
        if operation.union {
            sets.union(operation.a, operation.b)
        } else {
            _ = sets.find(operation.a)
            _ = sets.find(operation.b)
        }
    }
    print("\(name): \(sets.steps) steps")
}
```

```output
naive: 39083821 steps
union by size: 40130 steps
path compression: 90720 steps
both: 38008 steps
```

The naive version follows about 39 million links: each find on the chain walks about a thousand. Either fix alone brings that down a thousandfold, to a handful of links per find. Together they're the best of all, and the guarantee holds whatever order the operations come in.

## The complete union-find

Here is the whole structure, with a running count of sets and a way to ask for a set's size:

```swift run
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]
    private(set) var componentCount: Int

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
        componentCount = count
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }   // walk up to the root
        var node = x
        while node != root {                                 // path compression
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    @discardableResult
    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }                   // already in one set
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA                                // smaller tree under the larger
        size[rootA] += size[rootB]
        componentCount -= 1
        return true
    }

    mutating func connected(_ a: Int, _ b: Int) -> Bool {
        find(a) == find(b)
    }

    mutating func size(ofSetContaining x: Int) -> Int {
        size[find(x)]
    }
}

var sets = UnionFind(count: 8)
for (a, b) in [(0, 1), (2, 3), (1, 3), (4, 5), (6, 7), (5, 7)] {
    sets.union(a, b)
}
print("sets:", sets.componentCount)
print("0 and 2 together?", sets.connected(0, 2))
print("3 and 4 together?", sets.connected(3, 4))
print("size of 6's set:", sets.size(ofSetContaining: 6))
print("union(0, 3) joined anything?", sets.union(0, 3))
```

```output
sets: 2
0 and 2 together? true
3 and 4 together? false
size of 6's set: 4
union(0, 3) joined anything? false
```

`@discardableResult` lets you call `sets.union(a, b)` as a statement when you don't care about the answer, without a warning.

### Why find is mutating

find answers a question, yet it changes the array: path compression rewrites parents. In a struct, that makes it `mutating`, and so are `connected` and `size(ofSetContaining:)`, which call it. The consequence is that you can't ask questions of a `let`:

```swift
let frozen = UnionFind(count: 3)
frozen.connected(0, 1)      // error: cannot use mutating member on immutable value
```

The alternative would be to hide the arrays inside a class, so find could change them through a reference. But then copying a union-find would share its storage, and changing the copy would change the original. Keeping a struct, with value semantics from [Value vs reference semantics](/dsa/learn/swift-value-vs-reference), is the more Swift-like choice: hold it in a `var`, and every copy is independent.

## DSAKit's UnionFind

DSAKit's `UnionFind` is this structure, documented and tested against the slow labels model with thousands of random operations, plus a chain of unions over a million elements:

| Member | What it does | Cost |
| --- | --- | --- |
| `UnionFind(count:)` | n elements, 0 to n − 1, each in its own set | O(n) |
| `find(_:)` | the root of x's set (mutating: compresses the path) | amortised O(α(n)) |
| `union(_:_:)` | join two sets; false if they were already one | amortised O(α(n)) |
| `connected(_:_:)` | are they in the same set? (mutating) | amortised O(α(n)) |
| `size(ofSetContaining:)` | the number of elements in x's set (mutating) | amortised O(α(n)) |
| `componentCount`, `count` | the number of sets, and of elements | O(1) |
| `addElement()` | a new singleton set; returns its index | amortised O(1) |
| `groups()` | every set as sorted elements, in a fixed order | O(n α(n)) |

```swift
import DSAKit

var network = UnionFind(count: 5)
network.union(0, 1)
network.union(3, 4)
print(network.componentCount)          // 3
print(network.groups())                // [[0, 1], [2], [3, 4]]
```

<Callout kind="gotcha" title="Common mistakes">
- **Calling find on a `let`.** It's mutating, so the compiler refuses. Use `var`.
- **Updating the wrong size.** After the swap, `rootA` is the bigger root: add `size[rootB]` into `size[rootA]`, not the other way round.
- **Losing the path while compressing.** Save `parent[node]` before overwriting it.
- **Mixing rank and size.** Pick one. Rank isn't the tree's real height once compression has run, and that's fine: never try to update ranks during find.
</Callout>
