## Why it matters

Type "speling" and your phone underlines it and offers "spelling". Behind that are two questions: *is this a word?*, which a hash set answers instantly, and *which real words are closest?*, which is harder. Comparing the typo with every word in a 100,000-word dictionary means 100,000 edit-distance computations per misspelling. A **BK-tree** cuts that down by using the one property edit distance shares with physical distance, the **triangle inequality**, to skip whole branches of the dictionary. In this project you build a spell checker on that idea, with suggestions ranked by distance and then by how common each word is, inside a SwiftUI editor that underlines mistakes and learns new words. Then you compare it with UIKit's own `UITextChecker`.

## What you'll build

- `SpellCore`, a package with edit distances (Levenshtein, then Damerau–Levenshtein for swapped letters), a `BKTree`, and a `SpellChecker` that finds misspelled words and ranks suggestions.
- A SwiftUI editor that underlines unknown words, offers suggestions when you tap one, and has a "Learn" button that adds a word to a personal dictionary saved on the device.

Budget about two hours.

## The architecture

```text
 text ─▶ tokenise into words ─▶ for each word:
                                   known? Set<String> lookup, O(length) ──▶ yes: fine
                                   │ no
                                   ▼
                     BKTree.search(word, tolerance: 2) ──▶ candidates with distances
                                   │
                                   ▼
                 rank: distance, then frequency, then alphabetical ──▶ top 3 suggestions
```

Two structures, two jobs:

- **A `Set<String>` answers "is it a word?"** Every word in a document needs this check, so it must be fast, and hashing makes it O(length of the word).
- **The BK-tree answers "what's close?"**, only for the few words that fail the first check.

How a BK-tree works: pick any word as the root. Every other word hangs below it on an edge labelled with its distance from the root, and a word whose edge is already taken goes down that edge and repeats the process one level lower. To search for words within `t` edits of a query `q`: compute `d`, the distance from `q` to the node. If `d ≤ t`, the node matches. Then, by the triangle inequality, any word `w` below the child on edge `e` has `distance(q, w) ≥ |e − d|`. So only children with `|e − d| ≤ t` can contain matches: all the others are skipped, with everything below them.

```text
                  book                    inserted in the order
          1 /     2 |     \ 4              book, books, moon, cake, boo, boon
        books      moon     cake
      2 /
      boo                 boo is 1 from book, but edge 1 is taken, so it goes
    1 /                   down to books (distance 2); boon goes down to boo
    boon
```

Searching for "bopk" with `t = 1`: its distance to "book" is 1, so "book" matches, and only edges 0 to 2 can lead to more matches. "cake" on edge 4, and everything that will ever be inserted below it, is skipped without computing a single distance there.

## Milestones

### 1. Distances you trust

Write Levenshtein distance with two rows, as in [Edit distance](/dsa/learn/dps-edit-distance), plus the early exit when a whole row exceeds the limit.

- **Acceptance:** agrees with the full-table version on 10,000 seeded random pairs; known values like kitten → sitting (3) and "" → "abc" (3) pass.
- **Exercises:** dynamic programming, and saving space with two rows.

### 2. A brute-force checker

Load the dictionary into a `Set` and a frequency table. For each unknown word, compute the distance to **every** dictionary word and rank those within 2 by distance, then frequency, then alphabetically.

- **Acceptance:** correct suggestions for a list of 50 common typos; the time per misspelling measured in a release build, as the baseline.
- **Exercises:** a slow, obviously correct oracle, kept for the tests.

### 3. The BK-tree

Insert every dictionary word, then search with the triangle-inequality rule.

- **Acceptance:** for 1,000 seeded typos (dictionary words with one or two random edits), the BK-tree returns exactly the brute-force candidates; you've measured the fraction of distances it computes for tolerance 1 and 2.
- **Exercises:** pruning a search with a metric, and why the pruning weakens as the tolerance grows.

### 4. Swapped letters

"teh" is one keystroke-swap from "the", but Levenshtein calls it 2. Add the true Damerau–Levenshtein distance, which counts swapping two neighbours as one edit. Make the distance a parameter of the tree, `BKTree(distance:)`, and build it with the new one.

- **Acceptance:** "teh" suggests "the" first; a test checks the triangle inequality on 10,000 random triples of short strings.
- **Exercises:** what makes a distance a metric, and why the BK-tree depends on it (see the gotcha below).

### 5. The editor

A `TextEditor` for writing, with a preview below it that underlines unknown words in red. Tapping a word in the preview shows its suggestions; choosing one replaces it in the text. "Learn" adds the word to a personal dictionary that's saved and inserted into the set and the tree at launch.

- **Acceptance:** misspellings are underlined as you type; learned words stop being underlined and survive a relaunch.
- **Exercises:** incremental updates: a BK-tree insert costs one distance per level, so learning a word is cheap.

### 6. Compare with UITextChecker

UIKit ships a spell checker: `UITextChecker`'s `rangeOfMisspelledWord(in:range:startingAt:wrap:language:)` finds unknown words, and `guesses(forWordRange:in:language:)` suggests corrections. Run both checkers on the same paragraphs.

- **Acceptance:** written notes on where they differ, and why: dictionary size, ranking, keyboard-aware typo models.
- **Exercises:** judging your algorithm against a production one.

## Key code: a BK-tree with ranked suggestions

The tree stores its nodes in arrays; each node's children are a dictionary from edge distance to child index. The search counts how many distances it computes, to compare with the 30 a brute-force scan would need.

```swift run
/// Levenshtein distance with two rows: insertions, deletions and replacements each cost 1
func editDistance(_ a: [Character], _ b: [Character]) -> Int {
    var previous = Array(0...b.count)
    var current = previous
    for i in stride(from: 1, through: a.count, by: 1) {
        current[0] = i
        for j in stride(from: 1, through: b.count, by: 1) {
            current[j] = a[i - 1] == b[j - 1]
                ? previous[j - 1]
                : 1 + min(previous[j - 1], previous[j], current[j - 1])
        }
        swap(&previous, &current)
    }
    return previous[b.count]
}

/// A BK-tree: each child hangs off its parent on an edge labelled with their distance.
/// Nodes live in arrays and point to each other by index.
struct BKTree {
    private var words: [[Character]] = []
    private var children: [[Int: Int]] = []        // edge distance -> child node
    private(set) var distancesComputed = 0

    var count: Int { words.count }

    mutating func insert(_ word: String) {
        let letters = Array(word)
        guard !words.isEmpty else {
            words.append(letters)
            children.append([:])
            return
        }
        var node = 0
        while true {
            let d = editDistance(letters, words[node])
            if d == 0 { return }                         // already stored
            if let child = children[node][d] {
                node = child                             // follow the edge with the same distance
            } else {
                words.append(letters)
                children.append([:])
                children[node][d] = words.count - 1
                return
            }
        }
    }

    /// Every stored word within `tolerance` edits of `query`
    mutating func search(_ query: String, tolerance: Int) -> [(word: String, distance: Int)] {
        guard !words.isEmpty else { return [] }
        let letters = Array(query)
        var found: [(word: String, distance: Int)] = []
        var stack = [0]
        while let node = stack.popLast() {
            let d = editDistance(letters, words[node])
            distancesComputed += 1
            if d <= tolerance {
                found.append((String(words[node]), d))
            }
            // Triangle inequality: a match under a child on edge e has |e - d| <= tolerance
            for (edge, child) in children[node] where abs(edge - d) <= tolerance {
                stack.append(child)
            }
        }
        return found
    }
}

let frequency = [
    "the": 5000, "would": 1500, "they": 1800, "then": 2000, "them": 900, "these": 700, "three": 400,
    "ten": 300, "tea": 150, "help": 500, "held": 200, "hello": 120, "hell": 60, "yellow": 90,
    "spring": 110, "string": 130, "shift": 140, "swift": 60, "spell": 70, "spelling": 40, "selling": 80,
    "swelling": 15, "spilling": 10, "work": 900, "world": 700, "word": 600, "wood": 160, "lord": 45,
    "ward": 35, "sword": 30,
]

var tree = BKTree()
for word in frequency.keys.sorted() {
    tree.insert(word)
}

/// Closest first; among equal distances, the more common word first; then alphabetical
func suggestions(for typo: String, limit: Int = 3) -> String {
    let before = tree.distancesComputed
    let ranked = tree.search(typo, tolerance: 2).sorted {
        ($0.distance, -frequency[$0.word]!, $0.word) < ($1.distance, -frequency[$1.word]!, $1.word)
    }
    let shown = ranked.prefix(limit).map { "\($0.word) (\($0.distance))" }.joined(separator: ", ")
    return "\(typo): \(shown)  [\(tree.distancesComputed - before) of \(tree.count) distances]"
}

for typo in ["teh", "helo", "speling", "wrod", "swfit", "thier"] {
    print(suggestions(for: typo))
}
```

What to notice:

- **The ranking does what it says.** "helo" has three candidates at distance 1, ordered by frequency: help (500), held (200), hello (120).
- **"teh" gets the wrong first suggestion.** To Levenshtein, "teh" → "the" is two replacements, so "ten" and "tea", one edit away, win. That's milestone 4.
- **The tree skipped 6 to 15 of the 30 distances.** That's modest: with a tolerance of 2, the window `|e − d| ≤ 2` covers five edge values, and short words only have a handful of possible distances anyway. The savings grow with the dictionary and shrink with the tolerance, which is why milestone 3 asks you to measure both on a real word list.
- **Results come back in tree order and are then sorted**, so the order in which children are visited, a dictionary's order, never shows in the output. Only the count of distances matters, and that's the same whatever the order.

<Callout kind="gotcha" title="Not every distance with swaps is a metric">

The common "Damerau–Levenshtein" found in many code samples is really **optimal string alignment** (OSA): it adds swaps, but forbids editing a pair again after swapping it. OSA breaks the triangle inequality, and a BK-tree built on it can silently miss suggestions, because its pruning rule assumes the inequality holds. The true Damerau–Levenshtein distance keeps track of the last row where each character appeared, and is a metric.

</Callout>

```swift run
/// Optimal string alignment: Levenshtein plus "swap two neighbours" for 1, but no substring
/// may be edited again after a swap
func osa(_ a: [Character], _ b: [Character]) -> Int {
    var d = Array(repeating: Array(repeating: 0, count: b.count + 1), count: a.count + 1)
    for i in 0...a.count { d[i][0] = i }
    for j in 0...b.count { d[0][j] = j }
    for i in stride(from: 1, through: a.count, by: 1) {
        for j in stride(from: 1, through: b.count, by: 1) {
            let cost = a[i - 1] == b[j - 1] ? 0 : 1
            d[i][j] = min(d[i - 1][j] + 1, d[i][j - 1] + 1, d[i - 1][j - 1] + cost)
            if i > 1, j > 1, a[i - 1] == b[j - 2], a[i - 2] == b[j - 1] {
                d[i][j] = min(d[i][j], d[i - 2][j - 2] + 1)
            }
        }
    }
    return d[a.count][b.count]
}

/// True Damerau–Levenshtein (Lowrance–Wagner): swaps may be edited further, and it's a metric
func damerau(_ a: [Character], _ b: [Character]) -> Int {
    let far = a.count + b.count
    var d = Array(repeating: Array(repeating: 0, count: b.count + 2), count: a.count + 2)
    d[0][0] = far
    for i in 0...a.count { d[i + 1][0] = far; d[i + 1][1] = i }
    for j in 0...b.count { d[0][j + 1] = far; d[1][j + 1] = j }
    var lastRow: [Character: Int] = [:]                  // the last row where each character appeared in a
    for i in stride(from: 1, through: a.count, by: 1) {
        var lastMatchColumn = 0
        for j in stride(from: 1, through: b.count, by: 1) {
            let k = lastRow[b[j - 1]] ?? 0
            let l = lastMatchColumn
            var cost = 1
            if a[i - 1] == b[j - 1] {
                cost = 0
                lastMatchColumn = j
            }
            d[i + 1][j + 1] = min(d[i][j] + cost,             // match or replace
                                  d[i + 1][j] + 1,            // insert
                                  d[i][j + 1] + 1,            // delete
                                  d[k][l] + (i - k - 1) + 1 + (j - l - 1))   // swap, with edits between
        }
        lastRow[a[i - 1]] = i
    }
    return d[a.count + 1][b.count + 1]
}

for (name, distance) in [("OSA", osa), ("Damerau", damerau)] {
    let ca = distance(Array("CA"), Array("AC")), ac = distance(Array("AC"), Array("ABC"))
    let direct = distance(Array("CA"), Array("ABC"))
    print("\(name): CA→AC \(ca), AC→ABC \(ac), CA→ABC \(direct)", direct <= ca + ac ? "ok" : "breaks the triangle inequality")
}
print("teh→the:", damerau(Array("teh"), Array("the")), "| wrod→word:", damerau(Array("wrod"), Array("word")))
```

```output
OSA: CA→AC 1, AC→ABC 1, CA→ABC 3 breaks the triangle inequality
Damerau: CA→AC 1, AC→ABC 1, CA→ABC 2 ok
teh→the: 1 | wrod→word: 1
```

OSA says CA → ABC costs 3, yet CA → AC → ABC costs 1 + 1. The true distance finds the 2: swap, then insert B between the swapped letters. Build the tree with `damerau`, and "teh" and "wrod" now sit one edit from "the" and "word".

## The SwiftUI layer

```swift title="EditorScreen.swift"
import SwiftUI
import SpellCore

struct EditorScreen: View {
    let checker: SpellChecker
    @State private var text = ""
    @State private var selected: Misspelling?

    var body: some View {
        VStack(alignment: .leading) {
            TextEditor(text: $text)
                .frame(minHeight: 200)
                .border(.secondary)
            Text(underlined(text))
                .font(.body)
                .onTapGesture { selected = checker.misspellings(in: text).first }
        }
        .padding()
        .sheet(item: $selected) { misspelling in
            List(checker.suggestions(for: misspelling.word), id: \.self) { suggestion in
                Button(suggestion) {
                    text.replaceSubrange(misspelling.range, with: suggestion)
                    selected = nil
                }
            }
        }
    }

    private func underlined(_ text: String) -> AttributedString {
        var styled = AttributedString(text)
        for misspelling in checker.misspellings(in: text) {
            if let range = Range(misspelling.range, in: styled) {
                styled[range].underlineStyle = .single
                styled[range].foregroundColor = .red
            }
        }
        return styled
    }
}
```

Here `Misspelling` is an `Identifiable` struct holding a word and its `Range<String.Index>` in the text. A finished app lets you tap the exact word you mean; start with the first misspelling, then improve it.

```swift title="Tokeniser.swift"
import Foundation

func words(in text: String) -> [(word: String, range: Range<String.Index>)] {
    var result: [(String, Range<String.Index>)] = []
    text.enumerateSubstrings(in: text.startIndex..., options: .byWords) { word, range, _, _ in
        if let word { result.append((word.lowercased(), range)) }
    }
    return result
}

@testable import SpellCore

@Suite struct BKTreeTests {
    @Test("Known distances", arguments: [("kitten", "sitting", 3), ("", "abc", 3), ("abc", "abc", 0), ("teh", "the", 1), ("ca", "abc", 2)])

    @Test("The BK-tree finds exactly what brute force finds")
    func matchesBruteForce() {
        var random = SeededGenerator(seed: 3)
        let dictionary = loadTestWords()                      // test helpers: a few thousand words,
        var tree = BKTree(distance: damerau)
        dictionary.forEach { tree.insert($0) }
        for _ in 0..<1_000 {
            let typo = randomEdits(of: dictionary.randomElement(using: &random)!, count: 2, using: &random)  // and typos
            let expected = Set(dictionary.filter { damerau(Array(typo), Array($0)) <= 2 })
            #expect(Set(tree.search(typo, tolerance: 2).map(\.word)) == expected)
        }
    }

    @Test("Damerau–Levenshtein obeys the triangle inequality")
    func triangle() {
        var random = SeededGenerator(seed: 9)
        for _ in 0..<10_000 {
            let a = randomWord(maxLength: 5, letters: "abc", using: &random)
            let b = randomEdit(of: a, using: &random)       // one swap, insertion, deletion or replacement
            let c = randomEdit(of: b, using: &random)
            #expect(damerau(a, c) <= damerau(a, b) + damerau(b, c))
        }
    }
}
```

Three unrelated random words almost never break OSA's triangle inequality: a failure needs a swap with another edit right next to it, like CA, AC, ABC. So the test builds `b` from `a`, and `c` from `b`, with one random edit each, on a three-letter alphabet where repeated letters are common. Swap `damerau` for `osa` and the test fails dozens of times in 10,000 triples, which proves it can catch the bug. Also test: an empty tree returns no suggestions, inserting a duplicate doesn't add a node, and tolerance 0 finds only exact matches.

## Stretch goals

- **A better ranking.** Distance-then-frequency is a rough version of the *noisy channel model*: pick the word w that maximises P(w) × P(typo | w). Estimate P(typo | w) from the kind of edit (letters next to each other on the keyboard are likelier replacements) and compare suggestions.
- **Walk a trie instead.** Compute one row of the edit-distance table per trie node while walking down; a whole subtree is skipped once a row's minimum exceeds the tolerance. Compare its speed with the BK-tree on your dictionary.
- **Symmetric deletes.** Precompute every word with up to two letters deleted, in a dictionary from deletion to words. A typo's own deletions then find candidates by lookup alone. Fast, but measure the memory.
- **Context.** "Their going" is spelled correctly and still wrong. Use word-pair frequencies to flag unlikely pairs.
