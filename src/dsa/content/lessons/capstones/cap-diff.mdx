## Why it matters

You read diffs every day: in pull requests, in `git diff`, in Xcode's source control comparison. A diff answers "what's the smallest set of line insertions and deletions that turns this file into that one?", and it's the longest common subsequence problem in disguise. In [Longest common subsequence, and printing it](/dsa/learn/dps-lcs) you built a diff from the LCS table, which costs O(n × m) time **and memory**: two 10,000-line files need a table of 100 million cells. Real tools use **Myers' algorithm**, which runs in O((n + m) × D), where D is the number of changed lines, so it's fast exactly when files are similar, which they nearly always are. The same question shows up in iOS: diffable data sources and SwiftUI's lists work out what changed between two snapshots, and the standard library's `difference(from:)` gives you an edit script for any two collections. In this project you build a diff tool with both algorithms and real unified diff output.

## The architecture

```text
 old file, new file ─▶ split into lines ─▶ (optional) map each distinct line to an Int
                                │
                                ▼
            trim the common prefix and suffix (cheap, often most of the file)
                                │
                                ▼
           myersDiff(a, b) ─▶ [Edit]: keep / delete / insert, in order
                                │
               ┌────────────────┴─────────────────┐
               ▼                                  ▼
  unifiedDiff: hunks with context        apply(edits, to: a) == b   (the test oracle)
```

The idea behind Myers: picture the **edit graph**, a grid with the old file along the top (x) and the new file down the side (y). Moving right deletes a line of the old file, moving down inserts a line of the new one, and wherever the lines match, a diagonal step is free. A diff is a path from the top-left corner to the bottom-right, and the shortest diff is the path with the fewest non-diagonal steps. For ABCABBA against CBABAC, a `╲` marks each place where a diagonal step is free:

```text
 old (x) →  A  B  C  A  B  B  A
 new (y) ↓
      C           ╲
      B        ╲        ╲  ╲
      A     ╲        ╲        ╲
      B        ╲        ╲  ╲
      A     ╲        ╲        ╲
      C           ╲
```

Myers explores this graph breadth-first by **number of edits**. For D = 0, 1, 2, …, it records, on each diagonal k = x − y, the furthest point reachable with D edits, sliding down every run of free diagonals (a **snake**) as it goes. The first D at which the bottom-right corner is reached is the length of the shortest edit script. Each round touches at most D + 1 diagonals, so the whole search is O((n + m) × D).

## Milestones

### 1. The LCS diff

Port the diff from [Longest common subsequence, and printing it](/dsa/learn/dps-lcs) to work on `[String]` lines, returning `[Edit]` values instead of printed text.

- **Acceptance:** applying its edits to the old lines gives the new lines, for 1,000 seeded random pairs; you've worked out the table's memory for two 10,000-line files (about 800 MB of `Int`s).
- **Exercises:** the DP you already know, as the reference the faster algorithm must agree with.

### 2. Myers, the length only

Write the forward search: the array `v` of furthest x per diagonal, the choice between stepping down from diagonal k + 1 and right from k − 1, and the snake.

- **Acceptance:** D equals n + m − 2 × LCS on 1,000 seeded random pairs over a small alphabet (where ties are common).
- **Exercises:** BFS by layers of cost, and the trick of storing only the frontier: one number per diagonal.

### 3. Myers, the edit script

Save a copy of `v` before each round, then walk back from the bottom-right corner: in round d, the copy says whether you arrived from diagonal k + 1 (an insertion) or k − 1 (a deletion), and the snake before it is a run of kept lines.

- **Acceptance:** `apply(myersDiff(a, b), to: a) == b`, and the number of non-keep edits is D, for 1,000 seeded pairs.
- **Exercises:** reconstructing a path from saved state, as in [Reconstructing the answer, not just its value](/dsa/learn/dp-reconstruct).

### 4. Unified output

Number each edit with the old and new line positions it sits at, take `context` lines around every change, and merge ranges that touch into hunks with `@@ -start,count +start,count @@` headers.

- **Acceptance:** `patch -o out.txt old.txt < your.diff` produces a file identical to the new one, on several real pairs of Swift files; a file compared with itself prints nothing.
- **Exercises:** interval merging, as in [Merge and insert intervals](/dsa/learn/iv-merge-insert).

### 5. Make it fast on real files

Three changes that real tools make: strip the common prefix and suffix before running Myers; map every distinct line to an `Int` with a dictionary, so comparisons are integer comparisons; and build the tool in release mode.

- **Acceptance:** two 50,000-line files with 20 changed lines diff in well under a second; the LCS version on the same files runs out of patience, or memory.
- **Exercises:** O((n + m) × D) in practice: small D is the common case.

### 6. A viewer (optional)

A SwiftUI view, on macOS or iPad, that shows the unified diff with old and new line numbers in the margin, deletions in red and insertions in green, and lets you jump between hunks.

- **Acceptance:** the viewer and the command-line tool show the same hunks for the same files.
- **Exercises:** reusing one core behind two interfaces.

## Key code: Myers' diff and unified hunks

The forward search fills `v` round by round and saves a copy before each; the walk back reads those copies to recover the path. The LCS table checks D, and `unifiedDiff` turns the edits into hunks with one line of context.

```swift run
enum Edit<Element> {
    case keep(Element)
    case delete(Element)
    case insert(Element)
}

/// Myers' O(ND) diff: the shortest edit script turning `a` into `b`.
/// v[k] holds the furthest x reached on diagonal k = x - y; trace keeps v before each round.
func myersDiff<Element: Equatable>(_ a: [Element], _ b: [Element]) -> [Edit<Element>] {
    let n = a.count, m = b.count, most = n + m
    guard most > 0 else { return [] }
    let offset = most                                   // diagonals run from -most to most
    var v = Array(repeating: 0, count: 2 * most + 2)
    var trace: [[Int]] = []
    rounds: for d in 0...most {
        trace.append(v)
        for k in stride(from: -d, through: d, by: 2) {
            var x: Int
            if k == -d || (k != d && v[offset + k - 1] < v[offset + k + 1]) {
                x = v[offset + k + 1]                   // step down from diagonal k + 1: an insertion
            } else {
                x = v[offset + k - 1] + 1               // step right from diagonal k - 1: a deletion
            }
            var y = x - k
            while x < n && y < m && a[x] == b[y] {      // then slide down the snake of matches for free
                x += 1
                y += 1
            }
            v[offset + k] = x
            if x >= n && y >= m { break rounds }
        }
    }
    // Walk back from (n, m), asking each round which neighbouring diagonal we came from
    var edits: [Edit<Element>] = []
    var x = n, y = m
    for d in stride(from: trace.count - 1, through: 0, by: -1) {
        let v = trace[d]
        let k = x - y
        let previousK = (k == -d || (k != d && v[offset + k - 1] < v[offset + k + 1])) ? k + 1 : k - 1
        let previousX = v[offset + previousK]
        let previousY = previousX - previousK
        while x > previousX && y > previousY {         // the snake, backwards
            edits.append(.keep(a[x - 1]))
            x -= 1
            y -= 1
        }
        if d > 0 {
            if x == previousX {
                edits.append(.insert(b[y - 1]))
            } else {
                edits.append(.delete(a[x - 1]))
            }
        }
        (x, y) = (previousX, previousY)
    }
    return edits.reversed()
}

/// The LCS length by the classic table, to cross-check: D = n + m - 2 × LCS
func lcsLength<Element: Equatable>(_ a: [Element], _ b: [Element]) -> Int {
    var table = Array(repeating: Array(repeating: 0, count: b.count + 1), count: a.count + 1)
    for i in stride(from: 1, through: a.count, by: 1) {
        for j in stride(from: 1, through: b.count, by: 1) {
            table[i][j] = a[i - 1] == b[j - 1] ? table[i - 1][j - 1] + 1 : max(table[i - 1][j], table[i][j - 1])
        }
    }
    return table[a.count][b.count]
}

/// A unified diff: changed lines, with `context` unchanged lines around them, grouped into hunks
func unifiedDiff(_ old: [String], _ new: [String], oldName: String, newName: String, context: Int) -> [String] {
    var rows: [(edit: Edit<String>, old: Int, new: Int)] = []    // each edit, with the line indexes it sits at
    var i = 0, j = 0
    for edit in myersDiff(old, new) {
        rows.append((edit, i, j))
        switch edit {
        case .keep: (i, j) = (i + 1, j + 1)
        case .delete: i += 1
        case .insert: j += 1
        }
    }
    func isChange(_ edit: Edit<String>) -> Bool {
        if case .keep = edit { return false }
        return true
    }
    var hunks: [ClosedRange<Int>] = []
    for index in rows.indices where isChange(rows[index].edit) {
        let range = max(index - context, 0)...min(index + context, rows.count - 1)
        if let last = hunks.last, range.lowerBound <= last.upperBound + 1 {
            hunks[hunks.count - 1] = last.lowerBound...range.upperBound   // contexts touch: one hunk
        } else {
            hunks.append(range)
        }
    }
    guard !hunks.isEmpty else { return [] }
    /// "start,count" with 1-based lines; a single line is just "start"; an empty side names the line before
    func span(_ start: Int, _ count: Int) -> String {
        count == 1 ? "\(start + 1)" : "\(count == 0 ? start : start + 1),\(count)"
    }
    var lines = ["--- \(oldName)", "+++ \(newName)"]
    for hunk in hunks {
        let slice = rows[hunk]
        let oldCount = slice.filter { if case .insert = $0.edit { return false } else { return true } }.count
        let newCount = slice.filter { if case .delete = $0.edit { return false } else { return true } }.count
        lines.append("@@ -\(span(slice.first!.old, oldCount)) +\(span(slice.first!.new, newCount)) @@")
        for row in slice {
            switch row.edit {
            case .keep(let text): lines.append(" " + text)
            case .delete(let text): lines.append("-" + text)
            case .insert(let text): lines.append("+" + text)
            }
        }
    }
    return lines
}

func describe(_ edits: [Edit<Character>]) -> String {
    edits.map { edit in
        switch edit {
        case .keep(let c): return " \(c)"
        case .delete(let c): return "-\(c)"
        case .insert(let c): return "+\(c)"
        }
    }.joined(separator: " ")
}

let a = Array("ABCABBA"), b = Array("CBABAC")
let script = myersDiff(a, b)
let changes = script.filter { if case .keep = $0 { return false } else { return true } }.count
print(describe(script))
print("D =", changes, "| n + m - 2 × LCS =", a.count + b.count - 2 * lcsLength(a, b))

for (old, new) in [("", "abc"), ("abc", ""), ("same", "same"), ("kitten", "sitting")] {
    let edits = myersDiff(Array(old), Array(new))
    print("\"\(old)\" → \"\(new)\":", describe(edits))
}
```

What to notice:

- **D = 5, exactly n + m − 2 × LCS.** The LCS of ABCABBA and CBABAC has length 4, so 7 + 6 − 8 = 5 edits. Myers found it without building a table.
- **Deletions come before insertions** wherever both are possible ("-A -B C +B"), because the forward search prefers stepping right (deleting) when two diagonals tie. That's the order people expect when a line is replaced: the old version, then the new one.
- **The degenerate cases work**: empty to something, something to empty, and identical inputs, where D = 0 and the first snake runs straight from corner to corner.
- **Two hunks, not one.** With one line of context, the changes near the top and the one near the bottom are separated by six unchanged lines, more than the two that one line of context on each side could cover, so they become separate hunks. With `context: 3`, the default of `diff -u` and `git diff`, the two contexts would meet and the hunks would merge into one.
- **Hunk headers count lines on each side.** The first hunk covers 4 old lines from line 3, and 6 new lines from line 3. When one side of a hunk is empty, the convention names the line *before* it, with a count of 0.

## The command-line layer

```swift title="Sources/sdiff/SDiff.swift"
import ArgumentParser
import DiffCore
import Foundation

@main
struct SDiff: ParsableCommand {
    static let configuration = CommandConfiguration(abstract: "Show the differences between two text files.")

    @Argument(help: "The original file.") var old: String
    @Argument(help: "The changed file.") var new: String
    @Option(help: "Unchanged lines to show around each change.") var context = 3

    func run() throws {
        let oldLines = try String(contentsOfFile: old, encoding: .utf8).components(separatedBy: "\n")
        let newLines = try String(contentsOfFile: new, encoding: .utf8).components(separatedBy: "\n")
        let output = unifiedDiff(oldLines, newLines, oldName: old, newName: new, context: context)
        output.forEach { print($0) }
        if !output.isEmpty { throw ExitCode(1) }       // like diff: 0 means identical, 1 means different
    }
}
```

`diff` exits with status 0 when files are identical and 1 when they differ, so scripts can use it as a test. `ExitCode(1)` from Argument Parser does exactly that without printing an error.

```swift title="Tests/DiffCoreTests/MyersTests.swift"
import Testing
@testable import DiffCore

@Suite struct MyersTests {
    @Test("Myers agrees with the LCS bound and its edits apply", arguments: Array(1...20) as [UInt64])
    func agreesWithLCS(seed: UInt64) {
        var random = SeededGenerator(seed: seed)
        for _ in 0..<100 {
            let a = (0..<Int.random(in: 0...15, using: &random)).map { _ in Int.random(in: 0...3, using: &random) }
            let b = (0..<Int.random(in: 0...15, using: &random)).map { _ in Int.random(in: 0...3, using: &random) }
            let edits = myersDiff(a, b)
            let changes = edits.filter { if case .keep = $0 { return false } else { return true } }.count
            #expect(changes == a.count + b.count - 2 * lcsLength(a, b))
            #expect(apply(edits, to: a) == b)
        }
    }

    @Test("Identical files produce no hunks")
    func identical() {
        let lines = ["a", "b", "c"]
        #expect(unifiedDiff(lines, lines, oldName: "x", newName: "y", context: 3).isEmpty)
    }
}
```

A four-letter alphabet and short arrays make repeated elements, and therefore ties between equally short scripts, very common; that's where off-by-one errors in `v` hide. More to cover:

- **Hunk headers**: an insertion at the very top (`@@ -0,0 +1 @@`), a deletion of the last line, and a single-line change (`@@ -5 +5 @@`).
- **Context merging**: two changes separated by exactly `2 × context` unchanged lines form one hunk; one more line splits them.
- **A second opinion:** Swift's `b.difference(from: a)` returns a `CollectionDifference` of removals and insertions. Its change count equals your D on random inputs, which makes it a handy cross-check.

## Stretch goals

- **Linear space.** The trace costs O((n + m) × D) memory. Myers' paper also gives a divide-and-conquer version: find the *middle snake* by searching forwards and backwards at once, then recurse on the two halves, using O(n + m) memory. It's what GNU diff uses.
- **Patience diff.** Take the lines that appear exactly once in each file, find the longest increasing subsequence of their positions (patience sorting, from [LIS in O(n log n) with patience sorting](/dsa/learn/lis-n-log-n)), and use those as anchors, diffing the gaps between them recursively. It often lines up function boundaries better than Myers; `git diff --patience` uses it.
- **Word-level diffs** inside changed lines: run the same algorithm on words to highlight exactly what changed in a modified line.
- **Three-way merge.** Given a common ancestor and two edited versions, combine non-overlapping changes and mark conflicts, as `git merge` does.
