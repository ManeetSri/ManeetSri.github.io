## Why it matters

Maps apps answer "how do I get there?" in a blink, over road networks with millions of intersections. At their heart is the algorithm you already know: [Dijkstra's algorithm](/dsa/learn/sp-dijkstra), sped up by [A\* search](/dsa/learn/sp-a-star), which uses the straight-line distance to the destination to explore towards it rather than in every direction. Apple's MapKit can ask Apple's servers for directions, but plenty of apps need their own routing: a campus or hospital map, hiking trails, an indoor venue, a game world, or any route that has to work offline or optimise something a general maps service doesn't know about. In this project you build a route planner for a small road network, show the route on a SwiftUI `Map`, switch between shortest and fastest, and measure how much work A\* saves.

## What you'll build

- `RoutingCore`, a package with a road graph loaded from JSON, Dijkstra and A\* with path reconstruction, distance and travel-time costs, and heuristics that are provably admissible.
- A SwiftUI app with a `Map`: tap near two places to choose a start and a destination, see the route drawn as a polyline, its length and time, and how many places each algorithm expanded.

Budget about two and a half hours.

## The architecture

```text
 roads.json ─▶ RoadGraph: places (id, name, latitude, longitude), adjacency lists of roads
                          (to, metres, speed limit, one-way?)
                                    │
           tap on Map ─▶ nearest place ─▶ Router.route(from:to:cost:algorithm:)
                                    │            │
                                    │      heap of (f = g + h, h, place); best g per place;
                                    │      previous place, for the path
                                    ▼            ▼
                     Route: places, metres, seconds, expanded count
                                    │
                                    ▼
             Map { Marker(...) ; MapPolyline(route coordinates) } + stats panel
```

- **Places and roads, not pixels.** The graph is a list of places with coordinates and, for each place, the roads leaving it. One-way streets are roads listed in one direction only.
- **The cost is a choice.** "Shortest" uses each road's length in metres; "fastest" uses its length divided by its speed limit, in seconds. The algorithm doesn't change; the edge weights and the heuristic do.
- **The heuristic must never overestimate.** For distance, the straight line to the destination works, because no road route is shorter than a straight line. For time, divide that distance by the **fastest** speed limit anywhere in the graph. Dividing by a slower speed would overestimate on fast roads, and A\* could return a slower route.

## Milestones

### 1. The road graph

Define `Place` and `Road`, load them from JSON with `Codable`, and validate as you load: every road's ends exist, no length is negative, and every road is at least as long as the straight line between its ends. Make the data yourself for a neighbourhood you know, or export a small area from OpenStreetMap, keeping only intersections and the road segments between them; its licence asks you to credit "© OpenStreetMap contributors".

- **Acceptance:** the graph loads, and validation catches a deliberately broken file with a message naming the bad road.
- **Exercises:** graph representation with adjacency lists, and checking inputs before trusting them.

### 2. Dijkstra, with the path

Dijkstra with a binary heap, lazy deletion of stale entries, and a `previous` array to rebuild the path.

- **Acceptance:** on 100 seeded random graphs, its distances match Bellman–Ford's; an unreachable destination returns `nil`; start equal to destination gives a route of length 0.
- **Exercises:** the greedy invariant: when a place is popped with its best distance, that distance is final.

### 3. A\* with a straight-line heuristic

Add a heuristic parameter: Dijkstra is A\* with a heuristic of zero. Use the straight-line distance to the destination, and count the places each run expands.

- **Acceptance:** A\* and Dijkstra return the same length on every test graph; a test checks the heuristic is **consistent** on every road (`h(u) ≤ length(u, v) + h(v)`); A\* expands fewer places on routes that cross the map.
- **Exercises:** admissible and consistent heuristics, and why consistency means each place is expanded only once.

### 4. Shortest or fastest

Give each road a speed limit and add a travel-time cost. The heuristic becomes the straight-line distance divided by the fastest speed limit in the graph.

- **Acceptance:** on a map with a fast ring road, "fastest" takes it and "shortest" cuts through town; A\* and Dijkstra agree in both modes.
- **Exercises:** a cost function as a design decision, and keeping a heuristic admissible when the units change.

### 5. The map

A SwiftUI `Map` with a marker per place, the route as a polyline, and a stats panel. Tapping the map finds the nearest place to the tapped coordinate: start, then destination.

- **Acceptance:** tap, tap, and the route appears with its length, time and expanded count for both algorithms; changing the cost mode redraws it.
- **Exercises:** nearest-neighbour search: a linear scan is fine for a few hundred places; a k-d tree, from [k-d trees and quadtrees](/dsa/learn/as-kd-quadtree), for many thousands.

### 6. Compare with MapKit's directions

MapKit's `MKDirections` sends a request with a source and destination map item, and a transport type such as walking or driving, to Apple's servers. It returns routes, each with its distance in metres, an expected travel time and a polyline. Request a walking route between the same two real places and draw it next to yours.

- **Acceptance:** a short note, for three trips, on how the distances differ and why: your graph's detail, one-way streets, paths you didn't include.
- **Exercises:** judging your own model against a production system.

## Key code: Dijkstra, A\* and an over-confident A\*

A small town of 15 places and 21 roads, with lengths in metres. One function runs all three searches: the heuristic is multiplied by 0 for Dijkstra, by 1 for A\*, and by 3 for an A\* that trusts its estimate too much. Before searching, it checks that the straight-line heuristic is consistent on every road.

```swift run
// The heap from "Build a generic Heap<T>", cut down to insert and pop
struct Heap<Element> {
    private var items: [Element] = []
    private let areInIncreasingOrder: (Element, Element) -> Bool

    init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
        self.areInIncreasingOrder = areInIncreasingOrder
    }

    mutating func insert(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0 && areInIncreasingOrder(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let top = items.removeLast()
        var parent = 0
        while true {
            let left = 2 * parent + 1, right = left + 1
            var first = parent
            if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
            if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
            if first == parent { return top }
            items.swapAt(parent, first)
            parent = first
        }
    }
}

/// A place, in metres east (x) and north (y) of the town hall
struct Place {
    let name: String
    let x: Double
    let y: Double
}

let places = [
    Place(name: "Home", x: 0, y: 300), Place(name: "Westgate", x: -200, y: 300), Place(name: "Farm", x: -100, y: 0),
    Place(name: "School", x: 100, y: 100), Place(name: "Bakery", x: 100, y: 500), Place(name: "Park", x: 300, y: 300),
    Place(name: "Library", x: 200, y: 600), Place(name: "Market", x: 400, y: 500), Place(name: "Station", x: 500, y: 0),
    Place(name: "Bridge", x: 500, y: 300), Place(name: "Museum", x: 700, y: 500), Place(name: "Hospital", x: 700, y: 100),
    Place(name: "Harbour", x: 900, y: 300), Place(name: "Lake", x: -300, y: 500), Place(name: "Mill", x: -400, y: 100),
]
// Road lengths in metres. Roads bend, so each is at least the straight-line distance between its ends.
let roads = [
    ("Home", "Westgate", 221), ("Westgate", "Farm", 380), ("Home", "School", 246), ("Home", "Bakery", 258),
    ("Home", "Park", 315), ("School", "Station", 454), ("Bakery", "Library", 156), ("Library", "Market", 246),
    ("Park", "Market", 269), ("Park", "Bridge", 221), ("Bridge", "Museum", 340), ("Bridge", "Hospital", 326),
    ("Station", "Hospital", 235), ("Market", "Museum", 330), ("Museum", "Harbour", 354), ("Hospital", "Harbour", 340),
    ("Farm", "School", 246), ("Bridge", "Harbour", 700), ("Westgate", "Lake", 246), ("Westgate", "Mill", 326),
    ("Mill", "Farm", 348),
]

let id = Dictionary(uniqueKeysWithValues: places.enumerated().map { ($1.name, $0) })
var neighbours = Array(repeating: [(to: Int, metres: Int)](), count: places.count)
for (a, b, metres) in roads {
    neighbours[id[a]!].append((id[b]!, metres))
    neighbours[id[b]!].append((id[a]!, metres))
}

/// The straight-line distance, rounded down: never more than the length of any road route
func straightLine(_ a: Int, _ b: Int) -> Int {
    let dx = places[a].x - places[b].x, dy = places[a].y - places[b].y
    return Int((dx * dx + dy * dy).squareRoot())
}

/// Weight 0 is Dijkstra, 1 is A*, more than 1 trusts the estimate too much
func route(from start: String, to goal: String, heuristicWeight: Int) -> (metres: Int, path: [String], expanded: [String]) {
    let source = id[start]!, target = id[goal]!
    var best = Array(repeating: Int.max, count: places.count)
    var previous = Array(repeating: -1, count: places.count)
    var expanded: [String] = []
    // Entries are (f, h, place): smallest f = g + weight × h first, then the one that looks closer
    var open = Heap<(f: Int, h: Int, place: Int)>(areInIncreasingOrder: { ($0.f, $0.h, $0.place) < ($1.f, $1.h, $1.place) })
    best[source] = 0
    open.insert((heuristicWeight * straightLine(source, target), straightLine(source, target), source))
    while let entry = open.pop() {
        let g = entry.f - heuristicWeight * entry.h
        if g > best[entry.place] { continue }                  // a stale entry: a shorter way was found
        expanded.append(places[entry.place].name)
        if entry.place == target { break }
        for (next, metres) in neighbours[entry.place] where g + metres < best[next] {
            best[next] = g + metres
            previous[next] = entry.place
            let h = straightLine(next, target)
            open.insert((g + metres + heuristicWeight * h, h, next))
        }
    }
    var path: [String] = []
    var step = target
    while step != -1 {
        path.append(places[step].name)
        step = previous[step]
    }
    return (best[target], path.reversed(), expanded)
}

let goal = id["Harbour"]!
let consistent = roads.allSatisfy { a, b, metres in
    straightLine(id[a]!, goal) <= metres + straightLine(id[b]!, goal) && straightLine(id[b]!, goal) <= metres + straightLine(id[a]!, goal)
}
print("heuristic consistent on all \(roads.count) roads:", consistent)

let dijkstra = route(from: "Home", to: "Harbour", heuristicWeight: 0)
let aStar = route(from: "Home", to: "Harbour", heuristicWeight: 1)
let greedy = route(from: "Home", to: "Harbour", heuristicWeight: 3)
for (name, result) in [("Dijkstra", dijkstra), ("A*", aStar), ("A* with 3h", greedy)] {
    print("\(name): \(result.metres) m via \(result.path.joined(separator: " → ")), expanded \(result.expanded.count)")
}
print("A* never expanded:", Set(dijkstra.expanded).subtracting(aStar.expanded).sorted().joined(separator: ", "))
```

```output
heuristic consistent on all 21 roads: true
Dijkstra: 1202 m via Home → Park → Bridge → Hospital → Harbour, expanded 15
A*: 1202 m via Home → Park → Bridge → Hospital → Harbour, expanded 11
A* with 3h: 1236 m via Home → Park → Bridge → Harbour, expanded 4
A* never expanded: Farm, Lake, Mill, Westgate
```

What to notice:

- **Dijkstra and A\* find the same 1,202-metre route.** A\* changes the order of exploration, not the answer, as long as the heuristic never overestimates.
- **A\* expanded 11 places instead of 15.** Westgate, Lake, Mill and Farm are close to Home but on the far side from the Harbour. Dijkstra had to settle them, because they're nearer than the Harbour; A\* saw that `g + h` for each of them already exceeded the route it would find, so it never looked. On a real road network with thousands of places, the saving is far larger.
- **Multiplying the heuristic by 3 broke the guarantee.** That search expanded only 4 places, but it took the winding 700-metre coast road from the Bridge because the estimate made the Harbour look almost reached, and it arrived 34 metres longer. Weighted A\* is a real technique when speed matters more than the best answer, but it's a trade-off you should make on purpose.
- **Rounding down keeps the heuristic safe.** `Int(...)` truncates, so the straight-line estimate can only shrink. Rounding to the nearest metre could make it exceed a road that's exactly straight, and with it, the consistency check.

## The SwiftUI layer

```swift title="RouteMapView.swift"
import MapKit
import RoutingCore
import SwiftUI

struct RouteMapView: View {
    let graph: RoadGraph
    @State private var start: Place?
    @State private var destination: Place?
    @State private var route: Route?
    @State private var fastest = false

    var body: some View {
        MapReader { proxy in
            Map {
                ForEach(graph.places) { place in
                    Marker(place.name, coordinate: place.coordinate)
                        .tint(place == start ? .green : place == destination ? .red : .gray)
                }
                if let route {
                    MapPolyline(coordinates: route.places.map(\.coordinate))
                        .stroke(.blue, lineWidth: 5)
                }
            }
            .onTapGesture { point in
                guard let coordinate = proxy.convert(point, from: .local) else { return }
                choose(graph.nearestPlace(to: coordinate))
            }
        }
        .safeAreaInset(edge: .bottom) {
            StatsPanel(route: route, fastest: $fastest)
        }
        .onChange(of: fastest) { recompute() }
    }

    private func choose(_ place: Place) {
        if start == nil || destination != nil {
            (start, destination, route) = (place, nil, nil)
        } else {
            destination = place
            recompute()
        }
    }

    private func recompute() {
        guard let start, let destination else { return }
        route = Router(graph: graph).route(from: start, to: destination, cost: fastest ? .time : .distance)
    }
}
```

`MapReader` gives you a proxy that converts a tap's screen point into a map coordinate; the graph then finds its nearest place. `Place` is `Identifiable` and `Equatable`, and has a `coordinate` property of type `CLLocationCoordinate2D`.

Distances between coordinates come from the haversine formula, the great-circle distance on a sphere. For a city-sized map it's accurate to a fraction of a percent, and, as long as the road lengths in your data were measured the same way, it's an admissible heuristic:

```swift title="Geo.swift"
import CoreLocation
import Foundation

/// Metres along the Earth's surface between two coordinates
func haversine(_ a: CLLocationCoordinate2D, _ b: CLLocationCoordinate2D) -> Double {
    let radius = 6_371_000.0
    let dLatitude = (b.latitude - a.latitude) * .pi / 180
    let dLongitude = (b.longitude - a.longitude) * .pi / 180
    let h = sin(dLatitude / 2) * sin(dLatitude / 2)
        + cos(a.latitude * .pi / 180) * cos(b.latitude * .pi / 180) * sin(dLongitude / 2) * sin(dLongitude / 2)
    return 2 * radius * asin(min(1, h.squareRoot()))
}
```

import Testing
@testable import RoutingCore

@Suite struct RouterTests {
    @Test("A* agrees with Dijkstra on random towns", arguments: Array(1...50) as [UInt64])
    func aStarMatchesDijkstra(seed: UInt64) {
        var random = SeededGenerator(seed: seed)
        let graph = RoadGraph.randomTown(places: 40, roads: 90, using: &random)   // lengths ≥ straight lines
        let router = Router(graph: graph)
        for _ in 0..<20 {
            let a = graph.places.randomElement(using: &random)!, b = graph.places.randomElement(using: &random)!
            let slow = router.route(from: a, to: b, cost: .distance, algorithm: .dijkstra)
            let fast = router.route(from: a, to: b, cost: .distance, algorithm: .aStar)
            #expect(slow?.metres == fast?.metres)
            #expect((fast?.expanded ?? 0) <= (slow?.expanded ?? 0))
        }
    }

    @Test("The time heuristic is consistent on every road")
    func timeHeuristicIsConsistent() throws {
        let graph = try RoadGraph.load(named: "roads")
        for goal in graph.places {
            for road in graph.roads {
                #expect(graph.timeEstimate(road.from, goal) <= road.seconds + graph.timeEstimate(road.to, goal) + 1e-9)
            }
        }
    }
}

## Stretch goals

- **Bidirectional search.** Run Dijkstra from both ends and stop when the two frontiers meet properly, as in [Bidirectional BFS](/dsa/learn/gt-bidirectional); on large graphs it expands roughly half as many places.
- **Landmarks (ALT).** Precompute the distance from a few landmark places to every place. By the triangle inequality, `|d(L, goal) − d(L, v)|` is a lower bound on `d(v, goal)` for every landmark L, and the largest of them is a much sharper heuristic than the straight line.
- **Turn costs.** Penalise left turns or U-turns by searching over (place, arriving road) pairs instead of places alone.
- **Alternatives.** Offer a second route that shares little with the first, by penalising the first route's roads and searching again.
- **What real routers do.** Services that route across continents precompute shortcuts, for example with *contraction hierarchies*, so each query explores only a few hundred nodes. Read about the idea and estimate what it would cost to precompute for your graph.
