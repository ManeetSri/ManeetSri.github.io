## Why it matters

Bubble sort is the simplest sort to write, and nobody uses it in production code. It's still worth an evening. Its ideas come back again and again: comparing neighbours, a pass over the data, an invariant that grows by one element per pass, and stopping early when there's nothing left to do. It's also the cleanest way to meet **inversions**, the measure of "how unsorted" an array is that explains the cost of every simple sort.

## One pass: the largest value bubbles to the end

Walk along the array comparing each pair of **neighbours**. If the left one is bigger, swap them. That's one **pass**:

```swift run
var items = [5, 1, 4, 2, 8, 3]
for j in 0..<(items.count - 1) {
    let left = items[j]
    let right = items[j + 1]
    if left > right {
        items.swapAt(j, j + 1)
        print("\(left) > \(right): swap ->", items)
    } else {
        print("\(left) ≤ \(right): keep ->", items)
    }
}
```

```output
5 > 1: swap -> [1, 5, 4, 2, 8, 3]
5 > 4: swap -> [1, 4, 5, 2, 8, 3]
5 > 2: swap -> [1, 4, 2, 5, 8, 3]
5 ≤ 8: keep -> [1, 4, 2, 5, 8, 3]
8 > 3: swap -> [1, 4, 2, 5, 3, 8]
```

Follow the 5: it's carried right, swap after swap, until it meets the bigger 8. Then the 8 is carried the rest of the way. Whatever the largest value is, once the pass reaches it, it wins every comparison and travels to the very end. Like a bubble rising through water, which is where the name comes from.

So after one pass, the largest value is in its final place. After a second pass, the second largest is next to it. After pass p, the last p positions hold the p largest values, in order, and never move again. That's the **invariant** (the fact that stays true after every pass, as in [loop invariants](/dsa/learn/algo-invariants)), and it means each pass can stop one position earlier than the last.

## The code, with an early exit

If a pass makes **no swaps**, every neighbouring pair is in order, so the whole array is sorted. There's no point making more passes. A `swapped` flag catches that:

```swift run
func bubbleSort(_ items: inout [Int]) {
    guard items.count > 1 else { return }
    for pass in 0..<(items.count - 1) {
        var swapped = false
        for j in 0..<(items.count - 1 - pass) {      // the last `pass` positions are final
            if items[j] > items[j + 1] {
                items.swapAt(j, j + 1)
                swapped = true
            }
        }
        print("after pass \(pass + 1):", items)
        if !swapped { return }                       // no swaps: already sorted
    }
}

var numbers = [5, 1, 4, 2, 8, 3]
bubbleSort(&numbers)
```

```output
after pass 1: [1, 4, 2, 5, 3, 8]
after pass 2: [1, 2, 4, 3, 5, 8]
after pass 3: [1, 2, 3, 4, 5, 8]
after pass 4: [1, 2, 3, 4, 5, 8]
```

The array was sorted after pass 3, but the code can't know that until a pass finds nothing to swap. Pass 4 is that check. Without the flag, it would have run a fifth pass for nothing.

What to notice:

- There are at most n − 1 passes: once n − 1 values are in their final places, the last one must be too.
- The inner loop's upper bound is `items.count - 1 - pass`, so `items[j + 1]` never goes past the end, and the final tail is skipped.
- `swapAt` swaps two elements of an array in place, as you saw in [inout and swapping](/dsa/learn/swift-inout-swap).

## Inversions: how unsorted is an array?

An **inversion** is a pair of positions that are in the wrong order: a bigger value somewhere to the left of a smaller one. `[1, 2, 3]` has none. `[3, 1, 2]` has two: (3, 1) and (3, 2). A reversed array of n values has every pair the wrong way round, which is n(n − 1)/2 inversions, the most possible.

Here's the key fact: **swapping two neighbours that are out of order removes exactly one inversion.** The two values swap places, but their order relative to every other value stays the same. So bubble sort makes exactly as many swaps as the array has inversions. Count both the comparisons and the swaps for 100 values in different orders:

```swift run
func bubbleCounts(_ input: [Int]) -> (comparisons: Int, swaps: Int) {
    var items = input
    var comparisons = 0
    var swaps = 0
    guard items.count > 1 else { return (0, 0) }
    for pass in 0..<(items.count - 1) {
        var swapped = false
        for j in 0..<(items.count - 1 - pass) {
            comparisons += 1
            if items[j] > items[j + 1] {
                items.swapAt(j, j + 1)
                swaps += 1
                swapped = true
            }
        }
        if !swapped { break }
    }
    return (comparisons, swaps)
}

let n = 100
print("sorted:", bubbleCounts(Array(0..<n)))
print("reversed:", bubbleCounts(Array((0..<n).reversed())))
print("big value first:", bubbleCounts([n] + Array(1..<n)))
print("small value last:", bubbleCounts(Array(1..<n) + [0]))
```

```output
sorted: (comparisons: 99, swaps: 0)
reversed: (comparisons: 4950, swaps: 4950)
big value first: (comparisons: 197, swaps: 99)
small value last: (comparisons: 4950, swaps: 99)
```

Read the four lines:

- **Sorted:** one pass of n − 1 comparisons, no swaps, stop. That's the **best case, O(n)**, and it only happens thanks to the early exit.
- **Reversed:** every pass is full and every comparison swaps: n(n − 1)/2 of each. That's the **worst case, O(n²)**.
- On **average**, a shuffled array has about half the maximum inversions, n(n − 1)/4, so bubble sort averages O(n²) swaps too.
- The last two lines are the surprise. Both arrays have exactly 99 inversions, but one costs 197 comparisons and the other 4,950.

## Rabbits and turtles

Why the difference? A big value near the start is a **rabbit**: once a pass reaches it, it's carried right in a single pass, all the way to where it belongs. A small value near the end is a **turtle**: in each pass it's swapped with the one bubble passing over it, so it moves **one place left per pass**. The 0 at the end of `[1, 2, …, 99, 0]` needs 99 passes to crawl home, and each pass compares almost the whole array.

So the number of passes isn't decided by how many inversions there are, but by **how far the furthest turtle has to travel left**. That one fact is enough to predict exactly how many passes bubble sort needs without running it. It's the idea behind this lesson's practice problem.

A variant called **cocktail shaker sort** alternates passes left-to-right and right-to-left, so turtles get carried quickly too. It helps on some inputs, but it's still O(n²) in the worst case.

## Stable, in-place, adaptive

| Property | Bubble sort |
| --- | --- |
| Comparisons | O(n) best (sorted), O(n²) average and worst |
| Swaps | exactly the number of inversions: 0 to n(n − 1)/2 |
| Extra memory | O(1): in-place |
| Stable | yes: it only swaps neighbours when the left one is **strictly** bigger |
| Adaptive | yes, thanks to the early exit |
| Online | no: each pass needs the whole array |

Stability comes from the `>`. Two equal neighbours are never swapped, and a value can only move past another by being swapped with it, so equal values can never cross. Change it to `>=` and equal neighbours swap on every pass: the result is still sorted, but no longer stable, and it makes extra swaps for nothing.

<Callout kind="gotcha" title="Swift gotcha: a range that runs backwards crashes">
Without the `guard`, sorting an empty array evaluates `0..<(items.count - 1)`, which is `0..<-1`. Swift won't even create a range whose upper bound is below its lower bound:

```text title="What you'll see"
Fatal error: Range requires lowerBound <= upperBound
```

That's what Swift reports, and it stops the program. Guard against tiny arrays first, or loop with `while` and a condition that's simply false when there's nothing to do.
</Callout>

**Bubble sort's busy passes** asks how many passes of bubble sort make at least one swap, for arrays far too big to simulate. The rabbits-and-turtles idea above is the whole key, plus one sort you already have.

```cards
  front: "Why does bubble sort's best case need a `swapped` flag?"
  back: "A pass with no swaps proves the array is sorted. Without the flag it makes all n − 1 passes, O(n²), even on sorted input; with it, sorted input costs one pass, O(n)."
- id: inversions
  front: "What is an inversion, and how many swaps does bubble sort make?"
  back: "A pair of positions where a bigger value is left of a smaller one. Each neighbour swap removes exactly one, so bubble sort swaps exactly once per inversion."
- id: turtles
  front: "Why is a small value at the end slow for bubble sort?"
  back: "It moves only one place left per pass, so it needs as many passes as the distance it must travel. Big values move right quickly, in a single pass."
```
