## Why it matters

"Count the letters" is the first step of a surprising number of string problems: anagrams, the first unique character, whether one word can be built from another's letters, the longest substring with some property, and many more you'll meet in M22 and M23. In M07 you counted with a dictionary. When the input is limited to the 26 lowercase English letters, which interview problems very often promise, a plain array of 26 counters is simpler, faster and easier to compare. It's one of the most-used tricks in string DSA.

## The idea: one slot per letter

Make an array of 26 zeros. Slot 0 counts `a`, slot 1 counts `b`, and so on up to slot 25 for `z`:

| slot | 0 | 1 | 2 | … | 13 | … | 25 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| letter | a | b | c | … | n | … | z |

To find a letter's slot, use the ASCII trick from the character properties lesson: lowercase letters have consecutive codes starting at 97, so subtracting 97 gives 0 to 25.

```swift run
let word = "banana"
var counts = [Int](repeating: 0, count: 26)

for ch in word {
    let slot = Int(ch.asciiValue! - 97)
    counts[slot] += 1
}

print(counts[0], counts[1], counts[13], counts[25])
```

```output
3 1 2 0
```

What to notice:

- `[Int](repeating: 0, count: 26)` is the same as `Array(repeating: 0, count: 26)` from M07, with the type written out.
- `ch.asciiValue!` force-unwraps. That's acceptable here **only** because the problem guarantees lowercase letters, so `asciiValue` can never be `nil`. You met this "force unwrap when you can prove it's safe" idea in M04.
- `ch.asciiValue! - 97` is subtraction on `UInt8` values, and `Int(...)` turns the result into an index.

<Callout kind="analogy">
Picture 26 jars on a shelf, labelled a to z. Counting a word means dropping a marble in the right jar for each letter. With a dictionary you'd first have to find (or create) each jar by name. With the shelf, you know exactly where jar `n` is: it's the 14th one along.
</Callout>

## Turning slots back into letters

To print or rebuild letters from the counts, go the other way: slot + 97 is the ASCII code, and `UnicodeScalar` turns a code into a character:

```swift run
let word = "banana"
var counts = [Int](repeating: 0, count: 26)
for ch in word {
    counts[Int(ch.asciiValue! - 97)] += 1
}

for slot in 0..<26 where counts[slot] > 0 {
    let letter = Character(UnicodeScalar(UInt8(97 + slot)))
    print(letter, counts[slot])
}
```

```output
a 3
b 1
n 2
```

Unlike a dictionary, the array has an order built in, so the letters come out alphabetically for free. No sorting needed.

## Even faster with bytes

For lowercase ASCII input, you can skip `Character` altogether and loop over the UTF-8 bytes, as in the `[UInt8]` lesson. Each byte already **is** the ASCII code:

```swift run
func letterCounts(_ text: String) -> [Int] {
    var counts = [Int](repeating: 0, count: 26)
    for byte in text.utf8 {
        counts[Int(byte - 97)] += 1
    }
    return counts
}

let counts = letterCounts("mississippi")
print(counts[8], counts[18], counts[15], counts[12])
```

```output
4 4 2 1
```

Looping over `text.utf8` doesn't even need an array: you're reading the string's bytes directly.

## Comparing counts with ==

Arrays of `Int` can be compared with `==`, which checks every slot. Two words with the same letters in the same quantities produce equal count arrays, and comparing them takes exactly 26 steps, however long the words are:

```swift run
func letterCounts(_ text: String) -> [Int] {
    var counts = [Int](repeating: 0, count: 26)
    for byte in text.utf8 {
        counts[Int(byte - 97)] += 1
    }
    return counts
}

print(letterCounts("stop") == letterCounts("post"))
print(letterCounts("abc") == letterCounts("abd"))
```

```output
true
false
```

You'll put this to work in the practice problem.

## Counting up and down

Sometimes you don't need two arrays. Count one string **up** and the other **down**, and check what's left. Can a note be written using only the letters cut out of a magazine, each letter used at most once?

```swift run
func canBuild(_ note: String, from magazine: String) -> Bool {
    var available = [Int](repeating: 0, count: 26)
    for byte in magazine.utf8 {
        available[Int(byte - 97)] += 1
    }
    for byte in note.utf8 {
        let slot = Int(byte - 97)
        available[slot] -= 1
        if available[slot] < 0 {
            return false
        }
    }
    return true
}

print(canBuild("aab", from: "baa"))
print(canBuild("aa", from: "ab"))
```

```output
true
false
```

The moment a count goes negative, the note needs a letter the magazine has run out of, so you can stop early.

## Counting, then scanning

Like the first-unique example in M07, finding the first character that appears exactly once takes two passes: count everything, then walk the string in order and check each count.

```swift run
func firstUniqueIndex(_ text: String) -> Int? {
    let bytes = Array(text.utf8)
    var counts = [Int](repeating: 0, count: 26)
    for byte in bytes {
        counts[Int(byte - 97)] += 1
    }
    for (i, byte) in bytes.enumerated() where counts[Int(byte - 97)] == 1 {
        return i
    }
    return nil
}

print(firstUniqueIndex("swiss") ?? -1)
print(firstUniqueIndex("level") ?? -1)
print(firstUniqueIndex("aabb") ?? -1)
```

```output
1
2
-1
```

In `"swiss"`, `s` appears three times, so the first unique character is `w`, at index 1. In `"level"`, only the `v` at index 2 is unique.

## Why an array beats a dictionary here

| | `[Int]` with 26 slots | `[Character: Int]` |
| --- | --- | --- |
| Finding a slot | subtract 97 | hash the character |
| Memory | always 26 numbers | grows with distinct letters |
| Order | alphabetical, built in | none: must sort |
| Comparing two | `==`, 26 steps | `==`, works but slower |
| Works for | lowercase a–z only | any characters |

Both give O(n) counting. The array does less work per character and uses **O(1) extra space**: 26 counters, no matter how long the input. That constant size is why you'll often see "O(1) space" in the analysis of these solutions.

If the input is "any ASCII character", the same idea works with **128** slots, indexed by the byte value directly, with no subtraction. Only reach for a dictionary when the alphabet is large or unknown, such as arbitrary Unicode.

<Callout kind="gotcha" title="Swift gotcha: the 26-slot trick only works for a to z">
An uppercase letter, space or digit breaks it. For `"A"`, `asciiValue! - 97` is 65 − 97 in `UInt8`, which can't be negative, so Swift stops with an arithmetic overflow. Even with `Int(asciiValue!) - 97` you'd get `-32`, and `counts[-32]` crashes with `Fatal error: Index out of range`. Only use 26 slots when the constraints promise lowercase English letters, or lowercase and filter the input first.
</Callout>
