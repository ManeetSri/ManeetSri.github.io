## Why it matters

Swift strings behave differently from strings in almost every other language. You can't write `s[0]`, `count` takes time to compute, and an emoji can be "one character" while taking 25 bytes. None of this is Swift being awkward: it's Swift being **correct** about human text, including accents, emoji and every writing system on Earth. Once you see why, the rules in the rest of this module make sense, and you'll know exactly which tools make string problems fast.

## From symbols to numbers to bytes

Computers store numbers, not letters. So every symbol needs a number. **Unicode** is the worldwide standard that assigns one: `A` is 65, `é` is 233, `€` is 8364 and `😀` is 128512. Each of these numbers is called a **Unicode scalar** (you'll also hear "code point"). They're usually written in hexadecimal, like U+0041 for `A`.

Those numbers still need to be stored as bytes. The most common way is **UTF-8**, which uses between one and four bytes per scalar: small numbers take one byte, bigger ones take more.

```swift run
for text in ["A", "é", "€", "😀"] {
    print(text, text.unicodeScalars.count, text.utf8.count)
}
```

```output
A 1 1
é 1 2
€ 1 3
😀 1 4
```

Each line is one scalar, but they take 1, 2, 3 and 4 bytes. So you can't find "the fifth symbol" by jumping to the fifth byte: you have to walk through the bytes to know where each symbol starts.

The first 128 scalars, numbered 0 to 127, are called **ASCII**: the English letters, digits, space and common punctuation. Each ASCII symbol takes exactly one byte in UTF-8. Remember that, because most interview problems promise ASCII input, and that promise unlocks the fastest techniques in this module.

## One letter, two spellings

Here's where it gets interesting. Unicode has two ways to write `é`:

1. As a single scalar, U+00E9, "e with acute accent".
2. As two scalars: a plain `e` (U+0065) followed by U+0301, a **combining** accent that attaches itself to the letter before it.

On screen they look identical. Swift's `\u{...}` escape lets you write a scalar by its hexadecimal number, so you can build both:

```swift run
let precomposed = "caf\u{E9}"
let decomposed = "cafe\u{301}"

print(precomposed, decomposed)
print(precomposed == decomposed)
print(precomposed.count, decomposed.count)
print(precomposed.unicodeScalars.count, decomposed.unicodeScalars.count)
print(precomposed.utf8.count, decomposed.utf8.count)
```

```output
café café
true
4 4
4 5
5 6
```

What to notice:

- Swift says the two strings are **equal**, because they mean the same text. Unicode calls this **canonical equivalence**, and Swift's `==` respects it.
- Both have a `count` of **4**: c, a, f, é. That's how many characters a reader sees.
- Underneath, they have different numbers of scalars (4 and 5) and bytes (5 and 6).

Many languages would say these strings are different and have lengths 4 and 5. Swift counts what a human would count.

## Grapheme clusters: what Swift calls a Character

What a reader sees as a single character is called a **grapheme cluster**: one or more scalars that display as one symbol. A Swift `Character` is exactly one grapheme cluster. That's why `e` plus a combining accent is one `Character`.

Emoji push this much further:

```swift run
let samples = ["👍", "👍🏽", "🇯🇵", "👨‍👩‍👧‍👦"]
for emoji in samples {
    print(emoji, emoji.count, emoji.unicodeScalars.count, emoji.utf8.count)
}
```

```output
👍 1 1 4
👍🏽 1 2 8
🇯🇵 1 2 8
👨‍👩‍👧‍👦 1 7 25
```

- The thumbs up with a skin tone is the thumb plus a skin-tone modifier: two scalars.
- A flag is two "regional indicator" letters, here J and P.
- The family is four people joined by three invisible "zero-width joiner" scalars: seven scalars and 25 bytes.

Every one of them has a `count` of 1, because each looks like one character.

<Callout kind="analogy">
Think of a `Character` as a Lego model and scalars as the bricks. A simple letter is a single brick. An accented letter is two bricks snapped together. The family emoji is seven bricks. `count` counts finished models, not bricks.
</Callout>

## Four ways to measure a string

A Swift `String` offers several **views** of the same text, each counting a different unit:

| View | Counts | `"naïve 👋🏾"` |
| --- | --- | --- |
| `s.count` | Characters (grapheme clusters) | 7 |
| `s.unicodeScalars.count` | Unicode scalars | 8 |
| `s.utf16.count` | UTF-16 code units | 10 |
| `s.utf8.count` | UTF-8 bytes | 15 |

```swift run
let word = "naïve 👋🏾"
print(word.count)
print(word.unicodeScalars.count)
print(word.utf16.count)
print(word.utf8.count)
```

```output
7
8
10
15
```

`utf16` matters in iOS work: older Apple APIs (anything with `NSString` or `NSRange`, such as text fields and attributed strings) measure text in UTF-16 units. If a character limit or a highlighted range comes out wrong around emoji, a mix-up between `count` and `utf16.count` is the usual cause.

## Why count isn't free

To count characters, Swift must find where each grapheme cluster ends. Clusters can be any number of scalars long, so the only way is to walk through the whole string. That makes `count` an **O(n)** operation on a `String`, unlike an array's O(1) `count`.

```swift
// Calls count, an O(n) walk, on every pass: O(n²) in total
var i = 0
while i < text.count {
    i += 1
}

// Work it out once
let length = text.count
```

Two habits follow:

- Use `isEmpty`, not `count == 0`. It only has to check whether there's a first character.
- If you need the count more than once, store it in a constant.

For pure ASCII text, every character is one scalar and one byte, so `count` and `utf8.count` agree:

```swift run
let ascii = "hello"
print(ascii.count, ascii.utf8.count)
```

```output
5 5
```

Reading `utf8.count` is O(1) for a native Swift string, so for ASCII-only input it's the fast way to get the length.

<Callout kind="gotcha" title="Swift gotcha: equal strings, different byte counts">
Two strings can be `==` and still have different `utf8.count` values, as `café` showed. If you compare or hash strings by their raw bytes yourself, you can treat equal text as different. Stick to `==` for comparing text, and only work with raw bytes when the input is guaranteed ASCII.
</Callout>
