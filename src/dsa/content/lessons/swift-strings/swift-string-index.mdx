## Why it matters

The first thing almost everyone tries with a Swift string is `word[0]`, and it doesn't compile. It's the most famous Swift surprise, and it trips people up in every interview. This lesson explains why integer indexing is missing, how Swift's real string indexes work, and which loops quietly turn an O(n) solution into an O(n²) one.

## The error everyone meets

```swift
let word = "swift"
print(word[0])
```

```text title="What you'll see"
error: 'subscript(_:)' is unavailable: cannot subscript String with an Int, use a String.Index instead.
```

That's a compile error, so the program never runs. Swift's message is unusually helpful: it tells you exactly what to use instead, a `String.Index`.

## Why Swift refuses

In the last lesson you saw that a `Character` can be anything from 1 byte (`a`) to 25 bytes (a family emoji). So where does the fifth character start? There's no way to know without walking from the beginning, measuring each character as you go.

An array can jump straight to element 5 because every element is the same size. A string can't. If Swift allowed `word[5]`, it would *look* like a constant-time array access while secretly doing an O(n) walk. Put that inside a loop and you'd have an O(n²) algorithm hiding behind innocent-looking code.

So Swift makes the cost visible. To get a position in a string, you ask for it explicitly, and the method names tell you what you're paying.

## String.Index: a position in a string

A `String.Index` is an opaque position inside one particular string. "Opaque" means you can't do arithmetic on it, like `index + 1`; instead, you ask the string to move it for you.

Every string has two special indexes:

- `startIndex`, the position of the first character.
- `endIndex`, the position **one past** the last character. It isn't a valid position to read from.

```swift run
let word = "swift"

let first = word[word.startIndex]
print(first)

let second = word.index(after: word.startIndex)
print(word[second])

let last = word.index(before: word.endIndex)
print(word[last])
```

```output
s
w
t
```

- `index(after:)` moves one character forward.
- `index(before:)` moves one character back. Stepping back from `endIndex` lands on the last character.

<Callout kind="analogy">
Think of reading a book where some words are one letter long and some fill a whole line. You can't say "go to the 500th word" and jump there; you have to count from a bookmark. A `String.Index` is that bookmark, and `index(after:)` slides it forward one word.
</Callout>

## Jumping several characters: offsetBy

`index(_:offsetBy:)` moves an index by a number of characters. A negative offset moves backwards.

```swift run
let word = "swift"
let fourth = word.index(word.startIndex, offsetBy: 3)
print(word[fourth])

let secondLast = word.index(word.endIndex, offsetBy: -2)
print(word[secondLast])
```

```output
f
f
```

Moving past either end crashes, like reading past the end of an array. When an offset might be too big, use the `limitedBy:` version, which returns an optional:

```swift run
let word = "swift"
if let far = word.index(word.startIndex, offsetBy: 10, limitedBy: word.endIndex) {
    print(word[far])
} else {
    print("too far")
}
```

```output
too far
```

Here's the important part: **`index(_:offsetBy:)` costs O(k) for an offset of k**. It really does walk k characters. The name doesn't hide it, and you shouldn't either.

## Ranges of indexes

You can make ranges out of string indexes, as with integer ranges, and subscript the string with them:

```swift run
let word = "swift"
let second = word.index(after: word.startIndex)
let last = word.index(before: word.endIndex)

print(word[second..<last])
print(word[...second])
print(word[last...])
```

```output
wif
sw
t
```

The result of a range subscript is a `Substring`, a view into the original string. You'll meet it properly two lessons from now.

## Finding positions

You rarely build indexes by counting. More often you **find** them. `firstIndex(of:)` and `lastIndex(of:)` return an optional index, and you can slice around it:

```swift run
let email = "maneet@example.com"
if let at = email.firstIndex(of: "@") {
    print(email[..<at])
    print(email[email.index(after: at)...])
    print(email.distance(from: email.startIndex, to: at))
}
```

```output
maneet
example.com
6
```

`distance(from:to:)` converts a pair of indexes back into a number of characters. Like `offsetBy`, it walks the characters in between, so it's O(k) too.

## Walking a string with indexes

When you need positions, keep an index and move it with `index(after:)`. Each step is O(1), so a full walk is O(n), even with multi-byte characters:

```swift run
let text = "héllo👋"
var i = text.startIndex
while i < text.endIndex {
    print(text[i], terminator: " ")
    i = text.index(after: i)
}
print()
```

```output
h é l l o 👋
```

Indexes are **comparable**, so `i < text.endIndex` works.

Two indexes moving towards each other give a palindrome check, a classic **two-pointer** algorithm you'll study in M21:

```swift run
func isPalindrome(_ text: String) -> Bool {
    guard !text.isEmpty else { return true }
    var left = text.startIndex
    var right = text.index(before: text.endIndex)
    while left < right {
        if text[left] != text[right] {
            return false
        }
        left = text.index(after: left)
        right = text.index(before: right)
    }
    return true
}

print(isPalindrome("racecar"))
print(isPalindrome("swift"))
print(isPalindrome("abba"))
print(isPalindrome(""))
```

```output
true
false
true
true
```

The `guard` matters: for an empty string, `index(before: endIndex)` would step before the start and crash.

## The O(n²) trap

Here's the loop people write when they miss `word[i]`:

```swift
for i in 0..<text.count {
    let character = text[text.index(text.startIndex, offsetBy: i)]
    // use character
}
```

It works, but each `offsetBy: i` walks `i` characters from the start. Summed over the whole loop that's 0 + 1 + 2 + … + (n − 1), about n²/2 steps, plus an O(n) `count`. For a 100,000-character string that's around five billion steps. Interview judges time out on exactly this.

The fixes, from simplest to most flexible:

1. **Loop over the characters directly.** `for character in text` is O(n).
2. **Need the position number too?** `for (i, character) in text.enumerated()` gives an integer offset and the character, still O(n).
3. **Need to move both ways or jump around?** Keep a `String.Index` and step it, as above.
4. **Need `chars[i]`-style random access?** Convert to an array once, which is the next lesson.

```swift run
for (i, character) in "abc".enumerated() {
    print(i, character)
}
```

```output
0 a
1 b
2 c
```

<Callout kind="gotcha" title="Swift gotcha: endIndex is not the last character">
`text[text.endIndex]` crashes with `Fatal error: String index is out of bounds`. `endIndex` is one past the end, in the same way that `count` is one past an array's last index. The last character is at `text.index(before: text.endIndex)`, and only if the string isn't empty.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: indexes belong to one string">
An index from one string isn't meaningful in another, even if the two look similar. Using it can give the wrong character or crash. Always get indexes from the string you're going to subscript.
</Callout>
