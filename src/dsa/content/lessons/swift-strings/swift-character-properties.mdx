## Why it matters

String problems are full of small questions about single characters. Is this a letter or a digit? Is it a space? Should "A" count the same as "a"? Which letter of the alphabet is it? Swift's `Character` type answers all of these with built-in properties, and one of them, `asciiValue`, turns letters into numbers you can do arithmetic with. That's the key to the fast counting and shifting techniques in the rest of this module.

## Asking what kind of character it is

Every `Character` has a set of `Bool` properties that describe it:

```swift run
let samples: [Character] = ["a", "Z", "7", "!", "é"]
for ch in samples {
    print(ch, ch.isLetter, ch.isNumber, ch.isUppercase, ch.isPunctuation)
}
```

```output
a true false false false
Z true false true false
7 false true false false
! false false false true
é true false false false
```

The ones you'll use most:

| Property | True for | Examples |
| --- | --- | --- |
| `isLetter` | letters in any alphabet | `a`, `Z`, `é`, `ж` |
| `isNumber` | anything numeric | `7`, `½`, `٣` |
| `isWholeNumber` | digits with a whole-number value | `7`, `٣` (not `½`) |
| `isUppercase` / `isLowercase` | cased letters | `Z` / `a` |
| `isWhitespace` | spaces, tabs, newlines | `" "`, `"\t"`, `"\n"` |
| `isPunctuation` | punctuation marks | `!`, `,`, `?` |
| `isASCII` | the 128 ASCII characters | `a`, `7`, `!` (not `é`) |

Classifying every character of a string is a simple loop:

```swift run
let password = "Sw1ft rocks!"
var letters = 0
var digits = 0
var spaces = 0
var others = 0

for ch in password {
    if ch.isLetter {
        letters += 1
    } else if ch.isNumber {
        digits += 1
    } else if ch.isWhitespace {
        spaces += 1
    } else {
        others += 1
    }
}
print(letters, digits, spaces, others)
```

```output
9 1 1 1
```

### Filtering a string

`filter` works on strings, and on a `String` it returns a `String`. Combine it with a property to keep only the characters you want:

```swift run
let messy = "Hello, World! 2024"
print(messy.filter { $0.isLetter })
print(messy.filter { $0.isNumber })
print(messy.filter { !$0.isWhitespace })
```

```output
HelloWorld
2024
Hello,World!2024
```

## Changing case

`lowercased()` and `uppercased()` work on whole strings, and on single characters too. But there's a catch with characters:

```swift run
let letter: Character = "Q"
let lower = letter.lowercased()
print(lower, type(of: lower))

let lowerChar = Character(letter.lowercased())
print(lowerChar, type(of: lowerChar))
```

```output
q String
q Character
```

`Character.lowercased()` returns a **String**, not a `Character`. To get a `Character` back, wrap it: `Character(letter.lowercased())`.

Why a `String`? Because changing case can change the number of characters. The German letter `ß` becomes `SS` in uppercase:

```swift run
let sharpS: Character = "ß"
print(sharpS.uppercased(), sharpS.uppercased().count)
```

```output
SS 2
```

Two characters can't fit in one `Character`, so Swift returns a `String` to be safe. (Wrapping that in `Character(...)` would crash, but for the English letters in interview problems, case changes are always one character to one.)

### Comparing without caring about case

To compare case-insensitively, lowercase both sides:

```swift run
print("Hello".lowercased() == "hELLO".lowercased())

let a: Character = "A"
let b: Character = "a"
print(a == b)
print(a.lowercased() == b.lowercased())
```

```output
true
false
true
```

`"A"` and `"a"` are different characters, so `==` says `false`. Lowercasing both first makes the comparison ignore case.

## asciiValue: characters as numbers

Every ASCII character has a number from 0 to 127. `asciiValue` gives it to you as a `UInt8?`: an optional, because characters outside ASCII have no ASCII value.

```swift run
let samples: [Character] = ["a", "b", "z", "A", "Z", "0", "9", "é"]
for ch in samples {
    if let code = ch.asciiValue {
        print(ch, code)
    } else {
        print(ch, "no ASCII value")
    }
}
```

```output
a 97
b 98
z 122
A 65
Z 90
0 48
9 57
é no ASCII value
```

The layout of ASCII is worth memorising, because it's what makes letter arithmetic work:

| Characters | Codes |
| --- | --- |
| space | 32 |
| `0` to `9` | 48 to 57 |
| `A` to `Z` | 65 to 90 |
| `a` to `z` | 97 to 122 |

The letters are **consecutive**. So subtracting the code of `a` from any lowercase letter's code gives its position in the alphabet, from 0 to 25:

```swift run
let letters: [Character] = ["a", "d", "z"]
for letter in letters {
    if let code = letter.asciiValue {
        print(letter, Int(code) - 97)
    }
}
```

```output
a 0
d 3
z 25
```

This "letter to position" trick is the heart of frequency counting with 26 slots, later in this module. Converting with `Int(code)` before subtracting keeps the arithmetic in ordinary `Int` values.

<Callout kind="gotcha" title="Swift gotcha: UInt8 subtraction can crash">
`asciiValue` is a `UInt8`, which can't be negative. `Character("A").asciiValue! - 97` would be 65 − 97, a negative number, so Swift stops the program with an arithmetic overflow, as you saw in M02. Convert first, `Int(code) - 97`, when the result might be negative, or make sure the character really is a lowercase letter before subtracting.
</Callout>

## Unicode-aware or ASCII-only?

Swift's properties understand all of Unicode. That's usually what you want in an app, but it can surprise you in a puzzle:

```swift run
let samples: [Character] = ["é", "½", "٣"]
for ch in samples {
    print(ch, ch.isLetter, ch.isNumber, ch.isASCII)
}
```

```output
é true false false
½ false true false
٣ false true false
```

`é` is a letter, and `½` and the Arabic-Indic digit `٣` are numbers. If a problem means "only a to z", say so in code. Character ranges work, because characters are `Comparable`:

```swift run
let samples: [Character] = ["m", "M", "é"]
for ch in samples {
    print(ch, ("a"..."z").contains(ch), ch.isASCII && ch.isLetter)
}
```

```output
m true true
M false true
é false false
```

`("a"..."z").contains(ch)` is true only for lowercase English letters. `ch.isASCII && ch.isLetter` accepts both cases of English letters and rejects accented ones.

<Callout kind="tip">
Read the constraints. "s consists of lowercase English letters" means you can use `asciiValue!` and position arithmetic freely. "s may contain any printable characters" means check with `isLetter` or `isASCII` first.
</Callout>
