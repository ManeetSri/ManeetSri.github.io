## Why it matters

Many problems sit on the border between text and numbers: add two numbers given as strings, sum the digits of a number, parse "42" without `Int(_:)`, shift letters through the alphabet, or print a number in binary. Swift keeps `Character`, `String` and `Int` strictly separate, so you need to know the handful of conversions that cross between them. This lesson collects them in one place.

## Character to digit

There are three ways to turn the character `"7"` into the number `7`:

```swift run
let seven: Character = "7"

print(seven.wholeNumberValue ?? -1)
print(Int(String(seven)) ?? -1)
print(Int(seven.asciiValue! - 48))

let letter: Character = "x"
print(letter.wholeNumberValue ?? -1)
```

```output
7
7
7
-1
```

1. **`wholeNumberValue`** returns an `Int?`: the digit's value, or `nil` if the character isn't a digit. It's the clearest option.
2. **`Int(String(ch))`** turns the character into a one-character string, then parses it. `Int` has no initialiser that takes a `Character`, which is why the `String(...)` step is needed.
3. **ASCII arithmetic**: the digits `0` to `9` have codes 48 to 57, so subtracting 48 gives the value. Fast, but only safe when you know the character is an ASCII digit.

Summing the digits in a string is a natural use of the first:

```swift run
func digitSum(_ text: String) -> Int {
    var total = 0
    for ch in text {
        if let digit = ch.wholeNumberValue {
            total += digit
        }
    }
    return total
}

print(digitSum("a1b2c3"))
print(digitSum("2024"))
```

```output
6
8
```

<Callout kind="gotcha" title="Swift gotcha: Int(ch) doesn't compile">
`Int(someCharacter)` gives "no exact matches in call to initializer", because `Int` can parse a `String` or `Substring` but not a `Character`. Use `ch.wholeNumberValue` or `Int(String(ch))`. Also note that `wholeNumberValue` is Unicode-aware: the Arabic-Indic digit `٣` gives `3`, while `Int(String("٣"))` gives `nil`, because `Int` only accepts the ASCII digits 0 to 9.
</Callout>

## Number to digits

To get the digits of an `Int`, either go through its text or use arithmetic:

```swift run
let n = 9045
print(String(n).compactMap { $0.wholeNumberValue })

var remaining = 9045
var digits: [Int] = []
while remaining > 0 {
    digits.append(remaining % 10)
    remaining /= 10
}
print(digits)
print(Array(digits.reversed()))
```

```output
[9, 0, 4, 5]
[5, 4, 0, 9]
[9, 0, 4, 5]
```

The arithmetic version uses `% 10` to read the last digit and `/= 10` to drop it, so the digits come out last-first. It needs no strings at all, which makes it the usual choice in maths-flavoured problems (M15). Careful with `0`: the `while` loop never runs, so it produces an empty array, and negative numbers need their sign handled first.

## String to Int

`Int(_:)` parses a whole string and returns an optional, because the text might not be a valid number:

```swift run
print(Int("123") ?? -1)
print(Int("-45") ?? 0)
print(Int("12a") ?? -1)
print(Int("") ?? -1)
print(Int(" 5") ?? -1)
```

```output
123
-45
-1
-1
-1
```

It's strict: a leading `-` or `+` is fine, but letters, an empty string and even surrounding spaces make it return `nil`. Trim first if the input might have spaces.

### Parsing it yourself

Interviewers sometimes ask you to parse without `Int(_:)`. The idea: for each digit, shift what you have so far one place left (multiply by 10) and add the new digit.

```swift run
func parse(_ text: String) -> Int {
    var value = 0
    for ch in text {
        value = value * 10 + ch.wholeNumberValue!
    }
    return value
}

print(parse("4096"))
```

```output
4096
```

For `"4096"`, `value` goes 4, 40 + 0 = 40, 400 + 9 = 409, 4090 + 6 = 4096. The force unwrap assumes every character is a digit. A full version handles signs, spaces and overflow, which M23 covers.

## Int to String, and other bases

```swift run
print(String(42))
print(String(-7) + "!")
print("\(3 + 4)")

print(String(10, radix: 2))
print(String(255, radix: 16))
print(Int("1010", radix: 2) ?? -1)
print(Int("ff", radix: 16) ?? -1)
```

```output
42
-7!
7
1010
ff
10
255
```

`String(n)` and interpolation both turn a number into text. `radix:` switches the base: 2 for binary, 16 for hexadecimal. Binary strings are a handy way to look at bits, which you'll do a lot of in M16.

## Code to Character

To go from a number to a character, build a `UnicodeScalar` from the code, then a `Character` from the scalar:

```swift run
print(Character(UnicodeScalar(97)))

let code: UInt8 = 99
print(Character(UnicodeScalar(code)))

let position = 2
print(Character(UnicodeScalar(UInt8(97 + position))))
```

```output
a
c
c
```

The input type matters:

- With a `UInt8`, or a literal like `97` that Swift can treat as one, `UnicodeScalar(...)` always succeeds, since every byte value is a valid scalar.
- With an `Int` or `UInt32`, `UnicodeScalar(...)` returns an **optional**, because some numbers aren't valid scalars. That's why the last line converts `97 + position` with `UInt8(...)` first.

For digits, the easy route goes through a string: `Character(String(5))` is the character `"5"`.

## Shifting letters

Put the pieces together and you can move through the alphabet. Turn the letter into a position 0 to 25, do arithmetic, wrap with `% 26`, and turn it back:

```swift run
func nextLetter(_ ch: Character) -> Character {
    let position = Int(ch.asciiValue! - 97)
    let next = (position + 1) % 26
    return Character(UnicodeScalar(UInt8(97 + next)))
}

print(nextLetter("a"), nextLetter("y"), nextLetter("z"))
```

```output
b z a
```

`% 26` makes `z` wrap round to `a`. This letter → number → letter round trip is the core of every cipher-style problem.

<Callout kind="gotcha" title="Swift gotcha: % with negative numbers">
Swift's `%` keeps the sign of the left-hand side: `-7 % 26` is `-7`, not `19`. If a shift can be negative, `((x % 26) + 26) % 26` always lands in `0..<26`. You'll need this for the practice problem.
</Callout>

## Practice

**Caesar shift** moves every lowercase letter by `k` places. `k` can be negative or enormous, and anything that isn't a lowercase letter must come through unchanged.
