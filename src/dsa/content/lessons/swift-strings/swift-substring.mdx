## Why it matters

Every time you take part of a string, with `prefix`, `dropFirst`, a range of indexes or `split`, Swift hands you a `Substring` rather than a `String`. Substrings make slicing fast, because nothing is copied. But they're a different type, so they cause confusing compile errors, and keeping one around can hold on to far more memory than you'd guess. If the `ArraySlice` lesson in M07 made sense, this one will feel familiar: `Substring` is to `String` what `ArraySlice` is to `Array`.

## Where Substrings come from

```swift run
let sentence = "Swift strings are clever"
let firstWord = sentence.prefix(5)

print(firstWord)
print(type(of: firstWord))
print(type(of: sentence.dropFirst(6)))
print(type(of: sentence.split(separator: " ")))
```

```output
Swift
Substring
Substring
Array<Substring>
```

All of these produce substrings:

- `prefix(_:)`, `suffix(_:)`, `dropFirst(_:)` and `dropLast(_:)`.
- Subscripting with a range of indexes, like `sentence[start..<end]`.
- `split(separator:)`, which returns an array of substrings (the next lesson covers it).

## A Substring shares the original's storage

A `Substring` doesn't copy any characters. It points into the original string's storage and remembers where its part starts and ends. That makes creating one **O(1)**, no matter how long it is.

<Callout kind="analogy">
A substring is like a bookmark range: "pages 12 to 15 of this book". Making the note is instant and costs no paper. A `String` copy is a photocopy of those pages: it takes time and paper, but it no longer needs the original book.
</Callout>

Because it's a view into the original, a substring also keeps the **original's indexes**, as `ArraySlice` did:

```swift run
let sentence = "Swift strings are clever"
let middle = sentence.dropFirst(6).prefix(7)

print(middle)
print(middle.startIndex == sentence.index(sentence.startIndex, offsetBy: 6))
print(sentence[middle.startIndex])
```

```output
strings
true
s
```

The substring's `startIndex` is a position in `sentence`, so you can even use it to subscript `sentence`. (Since strings don't have integer indexes, this pitfall bites less often than with `ArraySlice`, but it's the same idea.)

## Substrings do (almost) everything Strings do

You can loop over a substring, count it, compare it, uppercase it, convert it to an array, and call most of the methods you know from `String`:

```swift run
let words = "Swift strings are clever".split(separator: " ")
let word = words[1]

print(word.uppercased())
print(word.count)
print(word.hasPrefix("str"))
print(word == "strings")
print(Array(word.prefix(3)))
```

```output
STRINGS
7
true
true
["s", "t", "r"]
```

That works because both types share a protocol called `StringProtocol`, which you'll understand properly in M10. For now: if a method works on a `String`, it very likely works on a `Substring` too.

## Converting with String(...)

The difference shows up when something asks specifically for a `String`. A function with a `String` parameter won't accept a `Substring`:

```swift
func shout(_ text: String) -> String {
    text.uppercased() + "!"
}
let sentence = "hello world"
print(shout(sentence.prefix(5)))
```

```text title="What you'll see"
error: cannot convert value of type 'String.SubSequence' (aka 'Substring') to expected argument type 'String'
```

That's a compile error. `String.SubSequence` is another name for `Substring`. The fix is to convert explicitly, which copies the characters into a new, independent string:

```swift run
func shout(_ text: String) -> String {
    text.uppercased() + "!"
}

let sentence = "hello world"
let first = String(sentence.prefix(5))
print(shout(first))
print(type(of: first))
```

```output
HELLO!
String
```

`String(substring)` costs O(k) for k characters. Swift makes you write it on purpose, so that copies never happen behind your back.

## The memory trap

Sharing storage has a hidden consequence: as long as a substring exists, the **entire original string** stays in memory, even if the substring is tiny.

Imagine reading a 10 MB log file into one string and keeping the date from the start of each line:

```swift
var dates: [Substring] = []
// for each line of a huge log:
//     dates.append(line.prefix(10))
```

Each date is only 10 characters, but each `Substring` keeps its whole line, and through it the whole file, alive. The fix is to convert anything you keep for a long time:

```swift run
let line = "2024-06-15 ERROR disk full"
var dates: [String] = []

if let space = line.firstIndex(of: " ") {
    let date = line[..<space]
    dates.append(String(date))
}
print(dates)
```

```output
["2024-06-15"]
```

Now `dates` holds its own small copy, and the original line can be freed once nothing else uses it.

<Callout kind="tip">
A simple rule: use substrings freely inside a function, while you're working. Convert to `String` when you **store** a piece (in a property, a dictionary or an array that outlives the function) or **return** it from a function that promises a `String`.
</Callout>

## Changing a Substring

A `var` substring can be changed, and, like `ArraySlice`, it gets its own copy on the first change, so the original is never affected:

```swift run
let sentence = "Swift strings"
var word = sentence.prefix(5)
word.append("y")
print(word)
print(sentence)
```

```output
Swifty
Swift strings
```

In practice, you'll rarely modify substrings. Convert to a `String` (or to an array of characters) when you want to build something new.

<Callout kind="gotcha" title="Swift gotcha: Substring in dictionaries and sets">
`[Substring: Int]` and `[String: Int]` are different types. If you count words from `split` directly, your keys are substrings and every key keeps the original text alive. For counts you'll keep or return, convert each piece: `counts[String(word), default: 0] += 1`.
</Callout>
