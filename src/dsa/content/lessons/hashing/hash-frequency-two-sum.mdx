## Why it matters

Most hashing solutions are one of a handful of patterns, and the first two do most of the work: **count things** in a frequency map, and **remember what you've seen** so you can ask "have I met the partner of this value before?". Together they turn many O(n²) "check every pair" solutions into a single O(n) pass. Two sum, the most famous interview question of all, is the second pattern in its purest form.

## Frequency maps: count first, then ask

A **frequency map** is a dictionary from each value to how many times it appears. You built them in [Counting with default: and grouping(by:)](/dsa/learn/swift-counting-grouping):

```swift
counts[value, default: 0] += 1
```

The pattern is always the same: one pass to count, then answer the question from the counts. Building the map is O(n) and each question is O(1), where comparing elements pairwise would be O(n²).

Here's a classic. Can you write a note by cutting letters out of a magazine, using each printed letter at most once?

```swift run
func canWrite(_ note: String, from magazine: String) -> Bool {
    var available: [Character: Int] = [:]
    for letter in magazine {
        available[letter, default: 0] += 1         // count what the magazine offers
    }
    for letter in note {
        available[letter, default: 0] -= 1         // spend one
        if available[letter]! < 0 {
            return false                           // spent more than there were
        }
    }
    return true
}

print(canWrite("meet at ten", from: "the tame cat sat on a mat at ten"))
print(canWrite("see you", from: "yes, you can"))
```

```output
true
false
```

The note "see you" needs three `e`s and the magazine has only one. With m magazine letters and k note letters, this is O(m + k). The force unwrap is safe because the line before it has stored a value for `letter`.

## Counting pairs as you go

A frequency map can also be built *while* you answer, which is where it gets powerful. How many pairs of positions `i < j` have `numbers[i] + numbers[j] == target`?

Walk left to right. When you reach a number, every **earlier** copy of `target - number` makes a pair with it. So keep counts of what you've seen so far, and add the partner's count before counting the current number:

```swift run
func countPairs(_ numbers: [Int], summingTo target: Int) -> Int {
    var seen: [Int: Int] = [:]          // value -> how many times it has appeared so far
    var pairs = 0
    for number in numbers {
        pairs += seen[target - number, default: 0]
        seen[number, default: 0] += 1
    }
    return pairs
}

print(countPairs([1, 5, 3, 3, 3], summingTo: 6))
print(countPairs([2, 2, 2, 2], summingTo: 4))
print(countPairs([1, 2, 3], summingTo: 10))
```

```output
4
6
0
```

For `[1, 5, 3, 3, 3]`: the 5 pairs with the earlier 1, the second 3 with the first, and the third 3 with both earlier ones: 1 + 1 + 2 = 4. The order of the two lines inside the loop matters. Counting first would let a 3 pair with itself.

## Two sum

> Given an array of integers and a target, find the **positions** of two different elements that add up to the target.

The array isn't sorted, and you need the original indexes.

### Brute force: O(n²)

Try every pair:

```swift
for j in numbers.indices {
    for i in 0..<j where numbers[i] + numbers[j] == target {
        return (i, j)
    }
}
```

Correct, but 100,000 numbers means about 5 billion pairs.

### Sorting: O(n log n), but the indexes are lost

On a sorted array, [Opposite ends: pair sum and valid palindrome](/dsa/learn/tp-opposite-ends) finds a pair in O(n) with two pointers. Sorting first costs O(n log n) and scrambles the positions, so you'd have to sort pairs of (value, original index) to recover them. It works, but there's something better.

### One pass with a dictionary: O(n)

Instead of searching for a partner, **remember** where every value appeared. For each number, its partner is `target - number`. If the partner has already been seen, you're done; otherwise record this number's index and move on:

```swift run
func twoSum(_ numbers: [Int], _ target: Int) -> (Int, Int)? {
    var indexOf: [Int: Int] = [:]            // value -> an index where it appeared
    for (index, number) in numbers.enumerated() {
        if let partner = indexOf[target - number] {
            return (partner, index)
        }
        indexOf[number] = index              // record it only after checking
    }
    return nil
}

if let (i, j) = twoSum([8, 3, 11, 5, 1], 16) {
    print(i, j)
}
if let (i, j) = twoSum([3, 3], 6) {
    print(i, j)
}
print(twoSum([3, 5], 6) == nil)
```

```output
2 3
0 1
true
```

Trace the first call, with target 16:

| index | number | looking for | `indexOf` before | result |
| --- | --- | --- | --- | --- |
| 0 | 8 | 8 | empty | record 8 → 0 |
| 1 | 3 | 13 | 8 → 0 | record 3 → 1 |
| 2 | 11 | 5 | 8 → 0, 3 → 1 | record 11 → 2 |
| 3 | 5 | 11 | 8 → 0, 3 → 1, 11 → 2 | found: (2, 3) |

What to notice:

- **Check before recording.** For `[3, 5]` with target 6, the 3 looks for another 3. If it recorded itself first, it would find itself and wrongly return `(0, 0)`.
- **Duplicates still work.** For `[3, 3]`, the first 3 is recorded, then the second finds it.
- Each element costs one lookup and one insert, both O(1) on average: **O(n) time, O(n) extra space**.

`if let (i, j) = …` unpacks the returned tuple straight into two constants.

## What should the map remember?

The trick in every one of these problems is choosing the dictionary's **value**:

| Question | Key | Value |
| --- | --- | --- |
| Can I build this from those letters? | letter | count |
| How many pairs sum to k? | value | count so far |
| Where's a partner for two sum? | value | an index |
| Is there a repeat within distance d? | value | **last** index seen |
| Does some subarray sum to k? | running sum | count so far |

The last row is the prefix-sum version, from [Prefix sum + hashmap: subarray sum equals k](/dsa/learn/prefix-hashmap). The fourth is worth a closer look: a repeat close by only needs the **most recent** copy of each value, because an older copy can only be further away.

```swift run
func hasRepeat(in values: [Int], within distance: Int) -> Bool {
    var lastSeen: [Int: Int] = [:]
    for (index, value) in values.enumerated() {
        if let previous = lastSeen[value], index - previous <= distance {
            return true
        }
        lastSeen[value] = index              // overwrite: the newest copy is the closest
    }
    return false
}

print(hasRepeat(in: [4, 1, 7, 4], within: 3))
print(hasRepeat(in: [4, 1, 7, 4], within: 2))
```

```output
true
false
```

Here, overwriting the old index is exactly right. In two sum, overwriting is harmless too, since any earlier copy makes a valid pair. Ask yourself, for each problem, whether you need the first, the last, or all of them.

## The cost: memory

These solutions trade space for time: the dictionary can hold all n values. That's almost always a good deal. When memory really is tight and the input can be reordered, sorting plus two pointers uses O(1) extra space at the price of O(n log n) time.

<Callout kind="gotcha" title="Swift gotcha: a lookup is an optional">
`indexOf[target - number]` is an `Int?`, `nil` when the partner hasn't been seen. Unwrap it with `if let`. Writing `indexOf[target - number]!` crashes on the first number without a partner. And when the stored index can legitimately be 0, never test it with something like `?? 0` and then compare with 0: a partner at index 0 would look like "not found".
</Callout>
