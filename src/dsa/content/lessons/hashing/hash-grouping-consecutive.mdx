## Why it matters

Two more patterns complete the everyday hashing toolkit. **Grouping** puts items into buckets by a key you design, and it's how you find duplicate accounts, cluster anagrams or organise orders by month. **Set membership** answers "is this value here?" in O(1), which lets you find the longest run of consecutive numbers in an unsorted array in O(n), faster than sorting. Both appear constantly in interviews, and both come down to choosing the right key.

## Grouping: a dictionary of lists

To group items, compute a **key** for each one and append the item to that key's list. Items that should end up together must get equal keys, and items that shouldn't must get different keys. The key is a **canonical form**: one standard representation shared by everything in the group.

You've seen this already. [Counting with default: and grouping(by:)](/dsa/learn/swift-counting-grouping) grouped words by length, and [Anagrams and group anagrams](/dsa/learn/str-anagrams) groups words that are anagrams of each other. The skill is designing the key.

### Designing a key: duplicate accounts

A sign-up form wants to catch people who register twice. Email providers ignore case, and many ignore everything after a `+` in the part before the `@`, so `Asha@mail.com` and `asha+shop@mail.com` reach the same inbox. The canonical form lowercases the address and drops the `+` part.

The groups should also come out in the order their first member signed up. A dictionary's order is arbitrary, so instead of a dictionary of lists, keep the lists in an array and use the dictionary to remember **which position** each key's group occupies:

```swift run
func normalised(_ email: String) -> String {
    let parts = email.lowercased().split(separator: "@", maxSplits: 1)
    guard parts.count == 2 else {
        return email.lowercased()
    }
    let local = parts[0].split(separator: "+", maxSplits: 1, omittingEmptySubsequences: false)[0]
    return local + "@" + parts[1]
}

let signUps = ["Asha@mail.com", "ben@site.org", "asha+shop@mail.com", "BEN@site.org", "cleo@mail.com", "asha@MAIL.com"]

var groupIndex: [String: Int] = [:]      // key -> position of its group in `groups`
var groups: [[String]] = []
for email in signUps {
    let key = normalised(email)
    if let index = groupIndex[key] {
        groups[index].append(email)
    } else {
        groupIndex[key] = groups.count   // a new group goes at the end
        groups.append([email])
    }
}
for group in groups {
    print(group)
}
```

```output
["Asha@mail.com", "asha+shop@mail.com", "asha@MAIL.com"]
["ben@site.org", "BEN@site.org"]
["cleo@mail.com"]
```

What to notice:

- The original addresses are kept; only the **key** is normalised.
- Each email costs one key computation and one dictionary operation, so grouping n emails is O(total length).
- The output order is the order of first appearance, and it's the same every run, because it comes from the array, not the dictionary.

### Keys with several parts

When the key has several parts, make it a small `Hashable` struct, as in [Custom Hashable keys](/dsa/learn/hash-custom-keys). Here orders are grouped by month with `Dictionary(grouping:by:)`, then printed in date order by sorting the keys:

```swift run
struct Month: Hashable {
    let year: Int
    let month: Int
}

struct Order {
    let id: Int
    let year: Int
    let month: Int
    let total: Int
}

let orders = [
    Order(id: 1, year: 2026, month: 3, total: 40),
    Order(id: 2, year: 2026, month: 4, total: 15),
    Order(id: 3, year: 2026, month: 3, total: 25),
    Order(id: 4, year: 2025, month: 12, total: 60),
]

let byMonth = Dictionary(grouping: orders, by: { Month(year: $0.year, month: $0.month) })
for key in byMonth.keys.sorted(by: { ($0.year, $0.month) < ($1.year, $1.month) }) {
    let totals = byMonth[key]!.map { $0.total }
    print("\(key.year)-\(key.month): \(totals.reduce(0, +))")
}
```

```output
2025-12: 60
2026-3: 65
2026-4: 15
```

Tuples can't be dictionary keys, but they *can* be compared with `<`, element by element, which makes the sort a one-liner. The force unwrap is safe because every key in `byMonth.keys` has a group.

## Longest consecutive sequence

> Given an unsorted array of integers, find the length of the longest run of consecutive values, such as 1, 2, 3, 4, that all appear in it. The values can be in any order.

For `[12, 4, 200, 1, 3, 2]`, the answer is 4, from 1, 2, 3 and 4.

### Sorting first: O(n log n)

Sort, remove duplicates, and scan for the longest stretch where each value is one more than the last. That's correct and a fine first answer, but the sort costs O(n log n). Can hashing do better?

### Only start counting at the start of a run

Put every value in a `Set`. Now "is 5 here?" is O(1). A naive idea is to count upwards from every value, but in a run of length k that repeats work: counting from 1 walks 1, 2, 3, 4; counting from 2 walks 2, 3, 4 again; and so on. On one long run, that's O(n²).

The fix is one check. A value `x` **starts** a run only if `x - 1` is missing. Count upwards only from starts:

```swift run
func longestRun(_ numbers: [Int]) -> Int {
    let present = Set(numbers)
    var longest = 0
    for start in present where !present.contains(start - 1) {
        var length = 1
        while present.contains(start + length) {
            length += 1
        }
        longest = max(longest, length)
    }
    return longest
}

print(longestRun([12, 4, 200, 1, 3, 2]))
print(longestRun([7, 7, 8, 9, 9, 20]))
print(longestRun([]))
```

```output
4
3
0
```

In the first array, the starts are 1, 12 and 200, because 0, 11 and 199 are missing. Counting from 1 finds 2, 3 and 4. Counting from 12 and from 200 stops at once. The values 2, 3 and 4 are never starts, so nobody counts from them.

**Why it's O(n).** The `for` loop visits each distinct value once. The `while` loop only ever walks *within* a run, and each run is walked exactly once, from its start. So across the whole program, the `while` loop steps over each value at most once. That's O(n) work for the loops and O(n) to build the set, on average.

<Callout kind="gotcha" title="Common mistake: looping over the array instead of the set">
If you write `for start in numbers`, a start that appears many times is walked from many times. Count the steps of the inner loop both ways for an array with a thousand extra copies of 0 in front of a run from 0 to 999:

```swift run
var steps = 0

func walkFromEach(_ starts: [Int], in present: Set<Int>) {
    for start in starts where !present.contains(start - 1) {
        var next = start + 1
        while present.contains(next) {
            steps += 1
            next += 1
        }
    }
}

let numbers = Array(repeating: 0, count: 1_000) + Array(0..<1_000)
let present = Set(numbers)

walkFromEach(numbers, in: present)
print("looping over the array:", steps)
steps = 0
walkFromEach(Array(present), in: present)
print("looping over the set:", steps)
```

```output
looping over the array: 999999
looping over the set: 999
```

Every one of the 1,001 zeros walks the whole run. Looping over the set visits each value once, so duplicates can't cause repeated walks.
</Callout>

## The shape of set-membership solutions

Longest consecutive sequence is one example of a wider idea: put the values in a set, then ask questions about **neighbours** that don't exist in the array's order. Is `x + 1` here? Is `target - x` here? Is this cell's neighbour here? Each question costs O(1), so a pass that asks a few per element stays O(n). You'll see the same move with visited sets in graph searches later in the course.
