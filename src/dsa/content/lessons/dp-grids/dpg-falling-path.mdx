## Why it matters

A skier goes down a slope row by row, and at each row can carry straight on or drift one column left or right. Seam carving, the image-resizing trick that removes the least noticeable column of pixels from a photo, is exactly this: find the cheapest top-to-bottom path where each step moves at most one column sideways. It's the minimum path sum again, with two changes that trip people up: a cell now has **three** possible parents, and the path can start and end **anywhere** along the top and bottom rows.

## The problem

An n-column grid of numbers (they may be negative). A falling path starts at any cell in the top row, and from (r, c) moves to one of (r + 1, c − 1), (r + 1, c) or (r + 1, c + 1), staying inside the grid. Find the smallest total of a falling path that reaches the bottom row.

```text
row 0:   4   1   6   3
row 1:   2   8   5   7
row 2:   9   3   1   4
row 3:   6   2   7   5
```

Picking the smallest number in each row doesn't work, because consecutive picks must be within one column of each other. Taking 1 in row 0 and then 2 in row 1 is fine (one column left), but 1 in row 2 is two columns away from that 2.

## Three parents

Look at the last step into (r, c). It came from one of the cells directly above: above-left, above, or above-right. The path up to that cell should be the cheapest possible, so:

| Step | Minimum falling path |
| --- | --- |
| State | `best[r][c]` = the cheapest falling path that ends at (r, c) |
| Transition | `best[r][c] = grid[r][c] + min(best[r − 1][c − 1], best[r − 1][c], best[r − 1][c + 1])`, using only parents that exist |
| Base case | `best[0][c] = grid[0][c]`: a path may start at any top cell |
| Order | row by row |
| Answer | the minimum of the last row: a path may end anywhere |

The **boundaries** are the fiddly part. Column 0 has no above-left parent, and column n − 1 has no above-right one. Rather than three `if` statements, take the range of columns above that can reach c: from `max(0, c - 1)` through `min(n - 1, c + 1)`. In the first column that's two parents; in the middle, three; in a one-column grid, just one.

```swift run
let slope = [
    [4, 1, 6, 3],
    [2, 8, 5, 7],
    [9, 3, 1, 4],
    [6, 2, 7, 5],
]

func cheapestFall(_ grid: [[Int]]) -> Int {
    let cols = grid[0].count
    var previous = grid[0]                     // a path that starts in row 0 costs just its first cell
    print(previous)
    for r in 1..<grid.count {
        var current = Array(repeating: 0, count: cols)
        for c in 0..<cols {
            let parents = max(0, c - 1)...min(cols - 1, c + 1)   // up to three cells above can reach (r, c)
            current[c] = grid[r][c] + previous[parents].min()!
        }
        previous = current
        print(previous)
    }
    return previous.min()!
}

print("cheapest fall:", cheapestFall(slope))
```

```output
[4, 1, 6, 3]
[3, 9, 6, 10]
[12, 6, 7, 10]
[12, 8, 13, 12]
cheapest fall: 8
```

Each printed line is one row of `best`. Follow the 8 back up: 2 in row 3 came from the 6 above it (row 2, column 1), which came from the 3 at row 1, column 0, which came from the 1 at the top. The path is 1 → 2 → 3 → 2.

What to notice:

- `previous[parents]` is an `ArraySlice` of up to three values, and `.min()!` is safe because the range is never empty.
- Negative numbers need no special care. Unlike Dijkstra, a DP filled in a valid order doesn't mind negative costs, because no cell is "settled" early on a guess.
- The cost is O(rows × cols) time: three comparisons per cell.

## Why one row isn't enough this time

In the previous two lessons, a single array worked because each cell read "above" (not yet overwritten) and "left" (already overwritten, and that's what we wanted). Here a cell reads above-left, above and above-right, all from the **previous** row. Update one array left to right, and when you reach column c, column c − 1 already holds the **new** row's value:

```swift run
let slope = [
    [4, 1, 6, 3],
    [2, 8, 5, 7],
    [9, 3, 1, 4],
    [6, 2, 7, 5],
]

func twoRows(_ grid: [[Int]]) -> Int {
    let cols = grid[0].count
    var previous = grid[0]
    for r in 1..<grid.count {
        var current = Array(repeating: 0, count: cols)
        for c in 0..<cols {
            current[c] = grid[r][c] + previous[max(0, c - 1)...min(cols - 1, c + 1)].min()!
        }
        previous = current
    }
    return previous.min()!
}

func oneRowInPlace(_ grid: [[Int]]) -> Int {
    let cols = grid[0].count
    var best = grid[0]
    for r in 1..<grid.count {
        for c in 0..<cols {
            // Bug: best[c - 1] has already been overwritten with this row's value
            best[c] = grid[r][c] + best[max(0, c - 1)...min(cols - 1, c + 1)].min()!
        }
    }
    return best.min()!
}

print("two rows:", twoRows(slope))
print("one row, in place:", oneRowInPlace(slope))
```

```output
two rows: 8
one row, in place: 11
```

The in-place version quietly mixes two rows. Use two arrays, `previous` and `current`, and swap them each row: O(cols) memory, which is still tiny. (You could save the overwritten value in a variable, as the next-but-one lesson does with its diagonal, but two arrays are clearer and the cost is the same.)

<Callout kind="tip" title="The rolling-array rule">
Before rolling a table into one array, list which cells each cell reads. If any of them is **to the left in the previous row**, it gets overwritten before you need it. Keep two rows, or save that value in a variable before overwriting it.
</Callout>

## Getting the path, not just the cost

The cost alone is often the whole question. When you need the columns too, keep the full `best` table (O(rows × cols) memory) and walk up from the cheapest cell of the last row. At each step, move to whichever of the up-to-three parents has `best[r − 1][parent] == best[r][c] − grid[r][c]`. Seam carving does exactly this to find the pixels to remove.

Alternatively, fill **bottom-up**: let `best[r][c]` be the cheapest way from (r, c) down to the bottom. Then the answer is the minimum of row 0, and you can walk **forwards** from that start, always stepping to the child with the smallest `best`, which prints the path in order. Either direction is a correct DP; pick the one that makes the output easiest.

## A wider family

The same pattern turns up whenever "the next row" depends on a window of columns in the previous row:

- **A wider drift.** If the skier may move up to k columns sideways, each cell takes the minimum over a window of 2k + 1 parents. Done naively that's O(rows × cols × k); a sliding-window minimum brings it back to O(rows × cols).
- **No repeats.** If a path must change column every row (never the same column twice in a row), each cell needs the minimum over **every other** column. Done naively that's O(rows × cols²), and there's a neat trick using the smallest and second-smallest values of the previous row. You'll meet it in M57 as the paint house problem.

<Callout kind="gotcha" title="Common mistakes">
- **Returning `best[rows − 1][0]` or the bottom-right cell.** A falling path can end in any column. Take the minimum of the whole last row.
- **Starting with zeros instead of the top row.** Row 0 is the base case: each top cell costs itself.
- **Building the range as `c - 1...c + 1` without clamping.** At column 0 that reads index −1 and crashes. Clamp with `max(0, c - 1)` and `min(cols - 1, c + 1)`.
- **One array, updated in place.** It mixes two rows, as shown above, and gives wrong answers with no crash.
</Callout>
