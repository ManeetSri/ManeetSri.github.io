## Why it matters

Programs need to remember things: a user's name, a running total, the position you've reached in a list. Swift gives you two ways to store a value, and choosing between them is one of the first decisions you make on almost every line. In algorithms, the split is especially clear: the input usually stays fixed, while counters, totals and positions change as you go. Getting this right lets the compiler catch a whole family of bugs for you.

## Giving a value a name with let

`let` creates a **constant**: a name for a value that will never change.

```swift run
let daysInWeek = 7
let city = "Pune"
print(daysInWeek)
print("I live in \(city).")
```

```output
7
I live in Pune.
```

Read `let daysInWeek = 7` as "let `daysInWeek` be 7". The `=` here means **assign**: store the value on the right under the name on the left. It isn't the maths "equals", which asks whether two things are the same. Swift writes that as `==`, which you'll meet in M02.

<Callout kind="analogy">
Think of a labelled box. `let` puts a value in the box, writes a label on it and seals it. You can look inside as often as you like, but you can't swap the contents. `var` makes a box with a lid you can open, so you can replace what's inside, though it must always be the same kind of thing.
</Callout>

## Values that change: var

`var` creates a **variable**: a name whose value can be replaced later.

```swift run
var score = 0
print("Start: \(score)")
score = 10
print("After the first level: \(score)")
score = score + 5
print("After a bonus: \(score)")
```

```output
Start: 0
After the first level: 10
After a bonus: 15
```

Notice there's no `var` on the later lines. You declare a name **once**, then assign to it as often as you need.

`score = score + 5` looks odd if you read `=` as "equals". Read it as an instruction instead: work out `score + 5` using the current value (10), then store the result (15) back in `score`. The right side is always worked out first. M02 shows a shorter way to write it: `score += 5`.

## Swift stops you changing a constant

If you try to assign a new value to a `let`, the program won't compile:

```swift
let maximumLives = 3
maximumLives = 4
```

```text title="What you'll see"
error: cannot assign to value: 'maximumLives' is a 'let' constant
note: change 'let' to 'var' to make it mutable
```

That's the point of `let`. If a value is never supposed to change, Swift guarantees it won't, even by accident hundreds of lines later. **Mutable** means "can be changed", so a `var` is mutable and a `let` isn't.

## Prefer let

Start every declaration with `let`. Switch to `var` only when you actually need to change the value. This is the standard style in Swift, for good reasons:

- Code is easier to read: when you see `let`, you know the value is the same everywhere below.
- Fewer bugs: you can't overwrite something by mistake.
- The compiler helps. Inside a function, if you declare a `var` and never change it, Swift warns you:

```text title="What you'll see"
warning: variable 'x' was never mutated; consider changing to 'let' constant
```

A **warning** doesn't stop the program from running, unlike an error, but it's worth fixing. Treat warnings as Swift pointing at something you probably didn't mean.

## A variable keeps its type

A variable's *value* can change, but its *kind* of value can't. A variable that holds a whole number always holds a whole number:

```swift
var score = 10
score = "ten"
```

```text title="What you'll see"
error: cannot assign value of type 'String' to type 'Int'
```

`Int` is Swift's name for whole numbers and `String` is its name for text. These names are called **types**. You'll learn how Swift decides a value's type in *Type inference and type annotations*, the last lesson of this module.

## Declaring now, assigning later

You can declare a constant first and give it its value later, as long as you give it a value exactly once before you use it. You have to say what type it will hold, since there's no value yet for Swift to look at:

```swift run
let message: String
message = "Assigned once, later on."
print(message)
```

```output
Assigned once, later on.
```

Using it before it has a value is a compile error, `constant 'message' used before being initialized`. Swift never lets you read a value that hasn't been set. This pattern becomes useful once you can make decisions with `if` in M03: you can set the constant to one value or another depending on a condition.

## One name, one declaration

Within the same part of a program, each name can only be declared once:

```swift
let total = 10
let total = 20
```

```text title="What you'll see"
error: invalid redeclaration of 'total'
```

If you need the value to change, make it a `var` and assign to it. If you need a second value, give it a different, descriptive name.

## Tracing variables by hand

Algorithms are mostly about variables changing step by step. A **trace table** records the value of each variable after every line, so you can follow the program exactly as the computer does:

```swift run
var total = 0
total = total + 4
total = total + 7
total = total * 2
print(total)
```

```output
22
```

| After line | `total` |
| --- | --- |
| 1 | 0 |
| 2 | 4 |
| 3 | 11 |
| 4 | 22 |

Making tables like this feels slow at first. It's also how you'll understand every loop in M03 and most of the algorithms after that, so it's worth practising now on short code.

<Callout kind="gotcha" title="Swift gotcha: assignment isn't comparison">
`=` stores a value; it never asks a question. Writing `a = b` doesn't check whether `a` and `b` match: it tries to copy `b` into `a`. To compare, Swift uses `==`, as in `a == b`. Mixing them up is one of the most common beginner mistakes in every language.
</Callout>
