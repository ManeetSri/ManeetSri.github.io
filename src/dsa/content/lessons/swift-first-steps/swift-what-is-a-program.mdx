## Why it matters

Every app on your phone, from a calculator to a banking app, is a program: a list of instructions that a computer follows exactly. Before you can write algorithms, you need a clear picture of what the computer actually does with your code. It reads your instructions in order, does precisely what they say, and nothing more. Once that model is solid, everything else in this course builds on it.

## A program is a list of instructions

A **program** is a sequence of instructions, written in a language the computer can understand. Each instruction is small and precise: store this number, add these two numbers, show this text on the screen.

<Callout kind="analogy">
A program is like a recipe. A recipe lists steps in order: preheat the oven, mix the flour and eggs, bake for 20 minutes. The cook follows them one at a time. A computer is a very fast cook with no common sense at all: it follows every step literally, even when a step is obviously wrong.
</Callout>

That last point matters. If a recipe said "add 200 kg of sugar", a human cook would notice the mistake. A computer would try. When a program does something surprising, it's almost always doing exactly what it was told. Learning to program is largely learning to say precisely what you mean.

## Your first Swift program

Here is a complete Swift program. It's one line long:

```swift run
print("Hello, Maneet!")
```

```output
Hello, Maneet!
```

Three things are going on:

- `print` is a **function**: a named action that Swift already knows how to do. It shows text in the console, the output area at the bottom of Xcode or in Terminal.
- The parentheses `( )` hold what you give to `print`.
- `"Hello, Maneet!"` is a **string**: a piece of text. The double quotes mark where the text starts and ends. They aren't printed.

## Top to bottom, one line at a time

When a program has several instructions, Swift runs them **in order, from top to bottom**. Each line finishes before the next one starts.

```swift run
print("Preheat the oven.")
print("Mix the flour and eggs.")
print("Bake for 20 minutes.")
```

```output
Preheat the oven.
Mix the flour and eggs.
Bake for 20 minutes.
```

Swap two lines and the output swaps too. The order you write instructions in *is* the order they happen. Later you'll learn ways to skip lines (decisions) and repeat lines (loops) in M03, but the default is always top to bottom.

<Callout kind="tip">
When you read code, read it the way the computer does: one line at a time, from the top, keeping track of what has happened so far. This habit, called **tracing**, is the single most useful skill for understanding algorithms.
</Callout>

## Input, processing, output

Almost every program has the same shape:

1. **Input**: the data it starts with.
2. **Processing**: the steps that work on that data.
3. **Output**: the result.

A calculator's input is the numbers you type, the processing is the arithmetic, and the output is the answer on screen. A maps app's input is where you are and where you're going, and its output is a route.

Here is a tiny program with all three parts:

```swift run
let pricePerTicket = 12
let tickets = 3
let total = pricePerTicket * tickets
print("Total: \(total)")
```

```output
Total: 36
```

- **Input:** the first two lines store a ticket price and a number of tickets. `let` gives a value a name. You'll learn it properly later in this module.
- **Processing:** the third line multiplies them. In Swift, `*` means multiply.
- **Output:** the last line prints the result. The `\(total)` part puts the value of `total` into the text. That's **string interpolation**, which has a lesson of its own later in this module.

This shape is exactly what an **algorithm** is: a precise recipe that turns an input into an output. In the practice problems, the input arrives as values given to a function, and your output is the value you give back. The tests check that the right input produces the right output.

## Statements and expressions

Two words you'll see often:

- A **statement** is a complete instruction that *does* something, like `print("Hi")` or `let tickets = 3`. In Swift, each statement usually sits on its own line. You don't need a semicolon at the end.
- An **expression** is a piece of code that *produces a value*, like `12 * 3`, `"Hello"` or `total`.

Expressions can go anywhere a value is expected, including inside `print`:

```swift run
print(12 * 3)
print(100 - 1)
print("Swift")
```

```output
36
99
Swift
```

Notice that `print(12 * 3)` prints `36`, not `12 * 3`. Swift works out the expression first, then prints the result. Put it in quotes, as `"12 * 3"`, and it becomes text, printed exactly as written.

## From your code to a running program

The text you write is called **source code**. A computer's processor can't read Swift directly. It only understands very simple machine instructions. A program called the **compiler** translates your Swift into those machine instructions.

The compiler also *checks* your code before anything runs. If something doesn't make sense, it refuses to continue and tells you what's wrong. That's a **compile error**:

```swift
prnt("Hello")
```

```text title="What you'll see"
error: cannot find 'prnt' in scope
```

A typo in `print` means Swift has no idea what `prnt` is, so the program never starts. That might feel strict, but it's a gift: the compiler catches mistakes in seconds that might otherwise only show up when a user taps a button.

Some problems can only be found while the program runs, such as dividing by zero. Those are **runtime errors**, and in Swift they usually stop the program immediately, which is called a **crash** or **trap**. You'll meet several in M02.

| Kind of error | When it's found | Example |
| --- | --- | --- |
| Compile error | Before the program runs | A misspelled name |
| Runtime error | While the program runs | Dividing by zero |

<Callout kind="gotcha" title="Swift gotcha: exact spelling and straight quotes">
Swift is **case-sensitive**: `Print("Hi")` fails with `cannot find 'Print' in scope`, because the function is `print`. Strings also need straight double quotes, `"like this"`. Curly quotes, which notes apps and chat apps often insert, give `unicode curly quote found, replace with '"'`. If you copy code from a message, check the quotes.
</Callout>

## Reading error messages

Error messages look scary at first, but they're precise. A full message shows the file, line and column, then the problem:

```text title="What you'll see"
hello.swift:1:1: error: cannot find 'prnt' in scope
```

Read it as: in `hello.swift`, line 1, column 1, Swift can't find anything called `prnt`. Always read the **first** error first. One mistake can cause several follow-on errors, and fixing the first often fixes the rest.
