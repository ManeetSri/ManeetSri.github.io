## Why it matters

Games roll dice, networks drop packets, randomised algorithms flip coins, and a loot box gives you a random item. The questions that follow are "what's the chance of…?" and "on average, how many tries until…?". When the process has a small number of situations it can be in, a DP over those situations answers both exactly. The table holds `Double`s instead of `Int`s, and the transitions are weighted by probabilities, but everything from [The DP recipe: state, transition, base, order, answer](/dsa/learn/dp-recipe) carries over. This lesson builds on [Probability and expected value](/dsa/learn/math-probability), which introduced expected value and linearity of expectation.

## Probabilities flow forwards

Roll three fair six-sided dice. What's the chance the total is 10? You could list all 216 outcomes, but with 20 dice that's 3.6 × 10¹⁵. Instead, keep the **distribution** after each die:

> `chance[k][t]` = the probability that the first k dice add up to t.

- **Base:** with no dice, the total is 0 for certain: `chance[0][0] = 1`.
- **Transition:** each face 1 to 6 has probability 1/6, so `chance[k][t]` adds `chance[k − 1][t − face] / 6` for every face.
- **Order:** die by die. Only the previous row is needed, so one array that's replaced each round is enough, as in [Saving space](/dsa/learn/dp-space).

This is the counting DP for dice totals, with every count divided by 6 at each step. Probabilities **flow forwards**: each state hands its probability on to the states it can lead to, split by how likely each step is.

```swift run
import Foundation

// chance[total]: the probability that the dice rolled so far add up to total
func diceSums(dice: Int, faces: Int) -> [Double] {
    var chance = [1.0]                                    // no dice yet: a total of 0 for certain
    for _ in 0..<dice {
        var next = [Double](repeating: 0, count: chance.count + faces)
        for (total, p) in chance.enumerated() where p > 0 {
            for face in 1...faces {
                next[total + face] += p / Double(faces)   // each face is equally likely
            }
        }
        chance = next
    }
    return chance
}

let three = diceSums(dice: 3, faces: 6)
for total in [3, 4, 10, 11, 18] {
    print(total, String(format: "%.4f", three[total]))
}
print("all together:", String(format: "%.4f", three.reduce(0, +)))
let atLeast15 = three[15...].reduce(0, +)
print("15 or more:", String(format: "%.4f", atLeast15))
```

```output
3 0.0046
4 0.0139
10 0.1250
11 0.1250
18 0.0046
all together: 1.0000
15 or more: 0.0926
```

What to notice:

- A total of 3 needs 1-1-1, one outcome in 216: 0.0046. A total of 10 has 27 outcomes: exactly 0.125.
- The probabilities add up to 1, a cheap sanity check worth running on any probability DP.
- `String(format: "%.4f", x)` prints a `Double` rounded to four decimal places. It needs `import Foundation`. Printing a raw `Double` shows up to 17 significant digits, and the last few depend on rounding along the way, so fix the decimals whenever you print one.
- The work is dice × totals × faces: for 20 dice, 20 × 120 × 6, about 14,000 steps instead of 3.6 × 10¹⁵ outcomes.

## Expected values flow backwards

Now a board game. You start on square 0 and roll a die each turn, moving forward by the number rolled. How many rolls, on average, until you reach square 20 or beyond?

Define the expected value from each square onwards:

> `expected[s]` = the average number of rolls still needed, starting from square s.

- **Base:** from square 20 or beyond, no more rolls: `expected[s] = 0`.
- **Transition:** one roll, then you're on square s + 1 to s + 6, each with probability 1/6: `expected[s] = 1 + (expected[s + 1] + … + expected[s + 6]) / 6`.
- **Order:** each square depends on **later** squares, so fill from square 19 down to 0.

This is the expected value rule from M15, E = Σ p · (value), applied one step at a time: the expected future is the probability-weighted average of the expected futures you might land in. Expectations **flow backwards**, from the end states where the answer is known.

```swift run
import Foundation

// Expected number of rolls of a fair die to get from square 0 to square goal or beyond
func expectedRolls(goal: Int) -> [Double] {
    var expected = [Double](repeating: 0, count: goal + 6)   // squares at or past the goal need 0 more rolls
    for square in stride(from: goal - 1, through: 0, by: -1) {   // backwards: later squares are known
        var sum = 0.0
        for face in 1...6 {
            sum += expected[square + face]
        }
        expected[square] = 1 + sum / 6                       // one roll, then wherever it lands
    }
    return expected
}

let board = expectedRolls(goal: 20)
print("from 0:", String(format: "%.4f", board[0]))
print("from 19:", String(format: "%.4f", board[19]))
print("from 15:", String(format: "%.4f", board[15]))

// Rolling a 6 now wastes the turn: expected[s] = 1 + (1/6)·expected[s] + (1/6)·(the other five)
func expectedRollsWastedSix(goal: Int) -> Double {
    var expected = [Double](repeating: 0, count: goal + 6)
    for square in stride(from: goal - 1, through: 0, by: -1) {
        var sum = 0.0
        for face in 1...5 {
            sum += expected[square + face]
        }
        expected[square] = (1 + sum / 6) / (1 - 1.0 / 6)     // solved for expected[s]
    }
    return expected[0]
}
print("wasted sixes:", String(format: "%.4f", expectedRollsWastedSix(goal: 20)))
```

```output
from 0: 6.1902
from 19: 1.0000
from 15: 1.8526
wasted sixes: 8.5335
```

A roll averages 3.5, and 20 / 3.5 ≈ 5.7, but the answer is a little more, 6.19, because the last roll usually overshoots. From square 19, any roll finishes: exactly 1.

### A state that can lead back to itself

The second function changes the rules: rolling a 6 wastes the turn, so you **stay on the same square**. Now `expected[s]` appears on both sides:

> expected[s] = 1 + (1/6) · expected[s] + (1/6) · (expected[s + 1] + … + expected[s + 5])

[DP on DAGs](/dsa/learn/dpa-dags) said a state that depends on itself breaks the fill order. A **direct** self-loop with a known probability doesn't, because it's one equation in one unknown. Move the self term to the left and divide:

> expected[s] = (1 + (1/6) · (the other five)) / (1 − 1/6)

Every state on the right is still a later square, so the backwards order still works. The answer rises to 8.53: moves now average only 2.5 squares per roll.

Longer cycles, say squares that send you back to square 3, need a system of equations solved together, which is beyond plain DP.

### Collecting every face

The same trick answers a classic: how many rolls, on average, until every face of a die has appeared? The state is how many **different** faces you've seen. With k seen, a roll repeats an old face with probability k/6 (you stay) or shows a new one with probability (6 − k)/6 (you move to k + 1).

```swift run
import Foundation

// Expected rolls of a fair die until every face has shown up at least once
// expected[k] = rolls still needed when k different faces have been seen
var expected = [Double](repeating: 0, count: 7)          // expected[6] = 0: done
for seen in stride(from: 5, through: 0, by: -1) {
    let repeatChance = Double(seen) / 6                   // an old face: stay at `seen`
    let newChance = 1 - repeatChance                      // a new face: move to seen + 1
    // expected[seen] = 1 + repeatChance · expected[seen] + newChance · expected[seen + 1], solved for expected[seen]
    expected[seen] = (1 + newChance * expected[seen + 1]) / (1 - repeatChance)
}
print(expected.map { String(format: "%.2f", $0) })
print("formula 6 · (1 + 1/2 + … + 1/6):", String(format: "%.2f", 6 * (1...6).reduce(0.0) { $0 + 1 / Double($1) }))
```

```output
["14.70", "13.70", "12.50", "11.00", "9.00", "6.00", "0.00"]
formula 6 · (1 + 1/2 + … + 1/6): 14.70
```

With 5 faces seen, you wait for one specific face, which takes 6 rolls on average, as in "waiting for a success" from M15. Solving the recurrence gives the formula 6 · (1 + 1/2 + … + 1/6) = 14.7. This is the **coupon collector** problem. When the faces aren't equally likely, "how many seen" is no longer enough, because it matters **which** ones you have: the state becomes a bitmask of the faces seen, as in this lesson's practice problem.

## Linearity of expectation: sometimes no DP at all

Here's a question with an obvious DP: after rolling a die k times, how many **different** faces do you expect to have seen? The state "how many different faces so far" with forward probabilities works. But linearity of expectation from M15 says the expected value of a sum is the sum of the expected values, **even when the parts depend on each other**. Count 1 for each face that shows up at least once. Face 1 is missing from all k rolls with probability (5/6)ᵏ, so it appears with probability 1 − (5/6)ᵏ. The same goes for every face, so the expected count is 6 · (1 − (5/6)ᵏ).

```swift run
import Foundation

// Expected number of distinct faces seen after k rolls of a fair die, two ways

// 1. DP over states: chance[d] = probability of having seen exactly d different faces so far
func distinctByDP(rolls: Int) -> Double {
    var chance = [Double](repeating: 0, count: 7)
    chance[0] = 1
    for _ in 0..<rolls {
        var next = [Double](repeating: 0, count: 7)
        for seen in 0...6 where chance[seen] > 0 {
            next[seen] += chance[seen] * Double(seen) / 6          // an old face
            if seen < 6 {
                next[seen + 1] += chance[seen] * Double(6 - seen) / 6   // a new face
            }
        }
        chance = next
    }
    return (0...6).reduce(0.0) { $0 + Double($1) * chance[$1] }
}

// 2. Linearity of expectation: add up, for each face, the probability that it shows up at least once
func distinctByLinearity(rolls: Int) -> Double {
    6 * (1 - pow(5.0 / 6, Double(rolls)))
}

for rolls in [1, 2, 6, 20] {
    print(rolls, String(format: "%.6f", distinctByDP(rolls: rolls)), String(format: "%.6f", distinctByLinearity(rolls: rolls)))
}
```

```output
1 1.000000 1.000000
2 1.833333 1.833333
6 3.990612 3.990612
20 5.843496 5.843496
```

Both columns agree. Six rolls show only about 4 different faces on average. Before setting up a probability DP for an **expected count**, ask whether the count is a sum of yes-or-no events whose probabilities you can find one at a time. If so, linearity gives the answer in a line.

## Swift gotchas and common mistakes

<Callout kind="gotcha" title="Swift gotcha: never compare Doubles with ==">
`0.1 + 0.2 == 0.3` is `false` in Swift, as in every language with binary floating point. Probability DPs add many small numbers, so test with a tolerance: `abs(answer - expected) < 1e-9`, or a relative one, `abs(answer - expected) <= 1e-9 * max(1, abs(expected))`, when answers can be large.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: integer division in probabilities">
`1 / 6` with two `Int`s is 0. Write `1.0 / 6`, or convert first with `Double(seen) / 6`. A probability DP full of zeros usually means an integer division crept in.
</Callout>

- **Forwards for "what's the chance", backwards for "how long on average".** Probabilities start at the start state (probability 1) and spread out. Expected values start at the end states (value 0) and work back.
- **Check the probabilities sum to 1** at each step, or that an expectation looks the right size. They're cheap checks that catch a missing state or a wrong weight.

## Practice

**Filling the sticker album** asks for the expected number of packs to collect every sticker when some stickers are rarer than others. That's the coupon collector with unequal chances: the state is the bitmask of stickers you have, every pack either repeats one you have (a self-loop) or adds a new one, and the answer is accurate to a millionth.
