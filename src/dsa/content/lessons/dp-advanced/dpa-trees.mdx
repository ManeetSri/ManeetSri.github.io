## Why it matters

A tree is the friendliest shape a DP can have. Every subtree is a smaller copy of the problem, no two subtrees overlap, and a post-order walk visits children before their parent, which is exactly the order a DP table needs. Questions like "pick the most valuable set of nodes with no two neighbours", "how far apart are the two most distant nodes" or "the cheapest way to cover every edge" all fall to the same pattern: each node combines a few numbers from its children and hands a few numbers up. You've already done this by hand in [Maximum path sum](/dsa/learn/bt-max-path-sum). This lesson turns it into a method, extends it to trees with any number of children, and makes it safe for trees 100,000 levels deep.

## The recipe on a tree

Run [The DP recipe: state, transition, base, order, answer](/dsa/learn/dp-recipe) with a tree in mind and most of its questions answer themselves:

| Step | On a tree |
| --- | --- |
| State | one or more numbers per node, about **its subtree** only |
| Transition | combine the children's numbers into the node's |
| Base case | the empty subtree (or a leaf) |
| Order | post-order: children before parents |
| Answer | the root's numbers, or the best value recorded at any node |

The only real decision is the state: **what does a parent need to know about each child's subtree?** Often one number isn't enough, and the fix is to return a small tuple instead of a single value.

## House robber on a tree

In [House robber I and II](/dsa/learn/dp-house-robber), a thief robs houses along a street and can't rob two neighbours. Now the houses are the nodes of a binary tree, and the alarm links each house to its parent and its children. Pick a set of nodes with no two joined by an edge, and make their total as large as possible.

```text
          6
        /   \
       4     9
      / \     \
     7   2     1
        / \
       5   8
```

The best haul is 7 + 5 + 8 + 9 = 29. Notice that it skips the root, skips 4, but takes the 9 one level up from the 7. No simple rule like "take every other level" finds it: the levels alternate to 6 + 10 = 16 or 13 + 13 = 26.

### Why one number per node isn't enough

A first attempt returns "the best total for this subtree". To decide about a node, you'd compare taking it (its value plus the best of its four grandchildren's subtrees) with skipping it (the best of its two children's subtrees). That's correct, but each node is asked for its answer by its parent **and** by its grandparent, and each of those asks again on its own behalf. The calls multiply:

```swift run
// One number per node: "the best for this subtree". Correct, but it calls grandchildren again and again.
var naiveCalls = 0
func robNaive(_ node: TreeNode?) -> Int {
    naiveCalls += 1
    guard let node else { return 0 }
    var takeIt = node.value
    for child in [node.left, node.right] {
        if let child {
            takeIt += robNaive(child.left) + robNaive(child.right)   // grandchildren
        }
    }
    let skipIt = robNaive(node.left) + robNaive(node.right)           // children
    return max(takeIt, skipIt)
}

var pairCalls = 0
func robPair(_ node: TreeNode?) -> (taken: Int, skipped: Int) {
    pairCalls += 1
    guard let node else { return (0, 0) }
    let left = robPair(node.left)
    let right = robPair(node.right)
    return (node.value + left.skipped + right.skipped,
            max(left.taken, left.skipped) + max(right.taken, right.skipped))
}

// A perfect tree with 10 levels: 1,023 nodes, numbered 1, 2, 3, … in the order they're built
func perfect(_ levels: Int, _ next: inout Int) -> TreeNode? {
    if levels == 0 { return nil }
    let node = TreeNode(next)
    next += 1
    node.left = perfect(levels - 1, &next)
    node.right = perfect(levels - 1, &next)
    return node
}
var counter = 1
let tree = perfect(10, &counter)!
let fast = robPair(tree)
print("naive:", robNaive(tree), "with", naiveCalls, "calls")
print("pairs:", max(fast.taken, fast.skipped), "with", pairCalls, "calls")

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}
```

```output
naive: 350151 with 131891 calls
pairs: 350151 with 2047 calls
```

Both get the same answer, but the naive version makes 131,891 calls for 1,023 nodes. Each extra level roughly doubles the nodes and more than triples the naive calls. You could fix it with a memo dictionary keyed by node, but there's a neater way.

### Return both answers

Let each node report **two** numbers about its subtree:

- `taken`: the best total if this node is robbed. Then neither child may be: `value + left.skipped + right.skipped`.
- `skipped`: the best total if this node is left alone. Then each child is free to go either way: `max(left.taken, left.skipped) + max(right.taken, right.skipped)`.

An empty subtree reports `(0, 0)`. The answer is the larger of the root's two numbers. Every node is visited once, so it's **O(n)**, and the "memo" is the return value itself.

```swift run
// House robber on a tree: every node returns two answers for its subtree
func robTree(_ node: TreeNode?) -> (taken: Int, skipped: Int) {
    guard let node else { return (0, 0) }                  // an empty subtree is worth nothing
    let left = robTree(node.left)
    let right = robTree(node.right)
    let taken = node.value + left.skipped + right.skipped   // take it: both children must be skipped
    let skipped = max(left.taken, left.skipped) + max(right.taken, right.skipped)  // skip it: children are free
    print("\(node.value): taken \(taken), skipped \(skipped)")
    return (taken, skipped)
}

let street = TreeNode.make([6, 4, 9, 7, 2, nil, 1, nil, nil, 5, 8])!
let answer = robTree(street)
print("best:", max(answer.taken, answer.skipped))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
7: taken 7, skipped 0
5: taken 5, skipped 0
8: taken 8, skipped 0
2: taken 2, skipped 13
4: taken 17, skipped 20
1: taken 1, skipped 0
9: taken 9, skipped 1
6: taken 27, skipped 29
best: 29
```

Read it bottom-up. Node 2 is worth 2 if taken, or 13 if skipped (its children 5 and 8 both go). Node 4 is worth 17 if taken (4 plus 2's skipped 13) but 20 if skipped (7 plus 2's best, 13). At the root, taking 6 gives 6 + 20 + 1 = 27, and skipping it gives 20 + 9 = 29.

This is the state-machine idea from [From state diagrams to transitions](/dsa/learn/dpsm-state-diagrams) moved onto a tree: each node is in one of two states, and the transition says which child states each one allows.

## Two more classics

### Maximum independent set and vertex cover

An **independent set** is a set of nodes with no two joined by an edge. House robber is the weighted version; with every value 1, it's the largest independent set, which in general graphs is NP-hard but on trees is one O(n) pass.

Its partner is the **minimum vertex cover**: the fewest nodes such that every edge touches at least one of them. The nodes left out of a cover form an independent set, and the other way round, so on any graph the smallest cover is n minus the largest independent set. On a tree you can also DP it directly with the same two states: a node in the cover lets its children go either way, and a node outside the cover forces every child in.

### Tree diameter, as a DP

The **diameter** is the longest path between any two nodes. You built it in [Depth and diameter](/dsa/learn/bt-depth-diameter) with the pattern "return one thing, record another". In DP terms, the state is "the longest path going down from this node", and the thing recorded is the best path that bends at the node: its two longest downward branches joined together. Step through it again: each node's returned height appears beside it, and the best bend is kept on the side.

```visual binaryTree

```

## Trees with any number of children

Real trees rarely arrive as `TreeNode`s. A company hierarchy, a file system or a road network with no loops usually comes as **n nodes and n − 1 edges**, with no say over which node is the root. Store it as an adjacency list, as in [Adjacency matrix, list and edge list](/dsa/learn/graph-representations), and pick any node as the root: 0 is the usual choice.

The edges are undirected, so each one is stored in both directions. A DFS from the root would walk straight back up to the parent and loop forever, so pass the parent along and skip it. That's the only change: a tree DFS needs no visited array, because the parent is the only already-visited neighbour a node can have.

```swift run
// A general tree as an adjacency list: roads [a, b, length] between n towns
let n = 8
let roads = [[0, 1, 4], [0, 2, 1], [1, 3, 2], [1, 4, 7], [2, 5, 3], [5, 6, 6], [5, 7, 2]]
var neighbours = [[(to: Int, length: Int)]](repeating: [], count: n)
for road in roads {
    neighbours[road[0]].append((road[1], road[2]))
    neighbours[road[1]].append((road[0], road[2]))      // undirected: store both directions
}

// Largest set of towns with no two joined by a road: (best with v in, best with v out)
func independent(_ v: Int, _ parent: Int) -> (with: Int, without: Int) {
    var with = 1
    var without = 0
    for (child, _) in neighbours[v] where child != parent {   // never walk back up
        let sub = independent(child, v)
        with += sub.without
        without += max(sub.with, sub.without)
    }
    return (with, without)
}
let set = independent(0, -1)
print("largest independent set:", max(set.with, set.without))

// Diameter: return the longest path going down from v, record the best path bending at v
var diameter = 0
func longestDown(_ v: Int, _ parent: Int) -> Int {
    var first = 0, second = 0                  // the two longest downward paths through different children
    for (child, length) in neighbours[v] where child != parent {
        let path = longestDown(child, v) + length
        if path > first {
            second = first
            first = path
        } else if path > second {
            second = path
        }
    }
    diameter = max(diameter, first + second)
    return first
}
_ = longestDown(0, -1)
print("diameter:", diameter)
```

```output
largest independent set: 5
diameter: 21
```

What to notice:

- With many children, the transitions become **sums over children** (independent set) or **the top two over children** (diameter), but the shape is unchanged.
- Keeping the two largest values in one pass, with `first` and `second`, avoids sorting the children. The diameter here is 4 → 1 → 0 → 2 → 5 → 6: 7 + 4 + 1 + 3 + 6 = 21, bending at town 0, where the two longest branches are 11 (down to 4) and 10 (down to 6).
- The root's parent is passed as `-1`, which works because no node is numbered -1.

## Deep trees: post-order without recursion

Both functions above recurse once per level. A tree that's a long chain, 100,000 nodes in a line, makes that 100,000 calls deep, and as [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) showed, a test thread's stack gives out after a few thousand. Graph problems turn up chains like that all the time.

The fix is simpler than a full explicit-stack simulation from [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack). A tree DP only needs **some** order in which every child comes before its parent. So:

1. Walk the tree once from the root with an explicit stack (or a queue), recording each node's parent and the order nodes are first reached. In that order, every parent appears before its children.
2. Go through the order **backwards**. Now every child comes before its parent, which is all post-order ever promised. Each node pushes its finished numbers into its parent's.

```swift run
// Tree DP without recursion: list the nodes parents-first, then fill the table in reverse
func largestIndependentSet(_ n: Int, _ edges: [[Int]]) -> Int {
    var neighbours = [[Int]](repeating: [], count: n)
    for edge in edges {
        neighbours[edge[0]].append(edge[1])
        neighbours[edge[1]].append(edge[0])
    }
    // 1. A DFS with an explicit stack records each node's parent and an order where parents come first
    var parent = [Int](repeating: -1, count: n)
    var order: [Int] = []
    var stack = [0]
    var seen = [Bool](repeating: false, count: n)
    seen[0] = true
    while let v = stack.popLast() {
        order.append(v)
        for w in neighbours[v] where !seen[w] {
            seen[w] = true
            parent[w] = v
            stack.append(w)
        }
    }
    // 2. Reversed, that order puts every child before its parent: exactly what post-order guarantees
    var with = [Int](repeating: 1, count: n)
    var without = [Int](repeating: 0, count: n)
    for v in order.reversed() {
        let p = parent[v]
        if p >= 0 {                                   // hand v's finished answer up to its parent
            with[p] += without[v]
            without[p] += max(with[v], without[v])
        }
    }
    return max(with[0], without[0])
}

print(largestIndependentSet(8, [[0, 1], [0, 2], [1, 3], [1, 4], [2, 5], [5, 6], [5, 7]]))
let chain = (1..<200_000).map { [$0 - 1, $0] }
print(largestIndependentSet(200_000, chain))
let star = (1..<200_000).map { [0, $0] }
print(largestIndependentSet(200_000, star))
```

```output
5
100000
199999
```

The DP tables become arrays indexed by node, `with[v]` and `without[v]`, instead of return values. The chain of 200,000 alternates in and out, and the star takes every leaf. Nothing recursed, so nothing can overflow.

<Callout kind="tip" title="Push up or pull down">
The loop above **pushes**: when a node is finished, it adds itself into its parent. You can also **pull**: when a node is processed, it reads all its children's finished values. Both work in reverse order. Pushing needs only the `parent` array; pulling needs the child lists. Use whichever makes the transition easier to write.
</Callout>

## Swift gotchas and common mistakes

<Callout kind="gotcha" title="Forgetting the parent check">
In an undirected adjacency list, a node's parent is also one of its neighbours. Without `where child != parent`, the DFS bounces between the two forever, and Swift stops with a stack overflow. In the iterative version, a `seen` array (or the same parent check) does the job.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: name your tuple fields">
`(Int, Int)` invites mixing up `.0` and `.1`, and the compiler can't help: both are `Int`. A labelled tuple such as `(taken: Int, skipped: Int)` makes the transition read like the maths and makes a swap obvious. A tiny `struct` works too, when the state grows past two or three numbers.
</Callout>

- **Rooting matters for the code, not the answer.** Any node can be the root of an unrooted tree, and the answer to "best independent set" or "diameter" doesn't depend on the choice. Questions that ask for an answer *for every possible root* need the next lesson's technique.
- **Leaves need no special case.** A leaf's loop over children runs zero times, so it keeps its starting values, `(1, 0)` here, which are exactly right.
