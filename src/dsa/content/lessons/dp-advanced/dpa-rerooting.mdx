## Why it matters

Some tree questions want an answer **for every node as the root**. Where should a delivery hub go so the total driving to every shop is smallest? How far is each server from the most distant one in a tree-shaped network? Running a tree DP from each node in turn costs O(n) per root, O(n²) in all, which is ten billion steps for 100,000 nodes. **Rerooting** gets every answer in O(n): one DP pass down the tree, then a second pass that slides the root from each node to its neighbours, fixing up the answer as it goes.

## The problem: sum of distances

Take an unweighted tree with n nodes. For every node v, find the sum of its distances to all the other nodes. Here's the tree this lesson uses, rooted at 0:

```text
        0
       / \
      1   2
         / \
        3   4
           / \
          5   6
```

From node 0 the distances are 1, 1, 2, 2, 3 and 3, so its sum is 12. From node 2 they're 1 (to 0), 2 (to 1), 1, 1, 2 and 2, a sum of 9. A BFS from every node finds all seven sums in O(n²). Let's do better.

## Pass 1, downwards: answers for the subtrees

First, a normal tree DP from the root, computing two numbers per node:

- `size[v]`: how many nodes are in v's subtree, including v.
- `down[v]`: the sum of distances from v to the nodes **in its subtree**.

For a child c of v, every node in c's subtree is one step further from v than from c. So c contributes `down[c] + size[c]` to `down[v]`. Leaves have size 1 and down 0. After this pass, `down[root]` is the root's real answer, because the root's subtree is the whole tree. For every other node, `down` only counts the part of the tree below it.

## Pass 2, upwards: move the root one edge at a time

Now suppose you know the full answer for a node p, and c is one of its children. What changes if the meeting point moves from p to c?

- The `size[c]` nodes in c's subtree each get **one step closer**.
- The other `n - size[c]` nodes each get **one step further**.

So

> answer[c] = answer[p] − size[c] + (n − size[c])

That's O(1) per edge. Start from `answer[root] = down[root]` and apply the rule from parents to children, so every parent's answer is ready before its children need it.

```swift run
// Sum of distances from every node to all the others: one pass down, one pass up
func distanceSums(_ n: Int, _ edges: [[Int]]) -> [Int] {
    var neighbours = [[Int]](repeating: [], count: n)
    for edge in edges {
        neighbours[edge[0]].append(edge[1])
        neighbours[edge[1]].append(edge[0])
    }
    // Root the tree at 0: parents, and an order with every parent before its children
    var parent = [Int](repeating: -1, count: n)
    var order = [0]
    var head = 0
    while head < order.count {
        let v = order[head]
        head += 1
        for w in neighbours[v] where w != parent[v] {
            parent[w] = v
            order.append(w)
        }
    }

    // Down pass, children first: size of each subtree, and the sum of distances from v into its subtree
    var size = [Int](repeating: 1, count: n)
    var down = [Int](repeating: 0, count: n)
    for v in order.reversed() where parent[v] >= 0 {
        size[parent[v]] += size[v]
        down[parent[v]] += down[v] + size[v]      // every node below v is one step further from the parent
    }
    print("size:", size)
    print("down:", down)

    // Up pass, parents first: move the root from p to its child v
    var answer = [Int](repeating: 0, count: n)
    answer[0] = down[0]
    for v in order where parent[v] >= 0 {
        answer[v] = answer[parent[v]] - size[v] + (n - size[v])
    }
    return answer
}

let edges = [[0, 1], [0, 2], [2, 3], [2, 4], [4, 5], [4, 6]]
print("answer:", distanceSums(7, edges))
```

```output
size: [7, 1, 5, 1, 3, 1, 1]
down: [12, 0, 6, 0, 2, 0, 0]
answer: [12, 17, 9, 14, 10, 15, 15]
```

Check one by hand. Moving from 0 to 2: the five nodes under 2 get closer and the other two get further, so 12 − 5 + 2 = 9, as computed earlier. Moving from 2 on to 4: 9 − 3 + 4 = 10. Node 1, a leaf next to the root, is the worst meeting point: 12 − 1 + 6 = 17.

What to notice:

- Both passes reuse **one order**, the BFS order from the root. Backwards it's a valid post-order for the down pass, and forwards it puts parents first for the up pass. No recursion, so a chain of 100,000 nodes is fine.
- The whole thing is **O(n)** time and space: three linear loops.
- The answer can be large. A chain of n nodes has an end-to-end sum of about n²/2, which is 5 × 10⁹ for n = 100,000: fine in a 64-bit `Int`, too big for `Int32`.

## The general recipe

Rerooting works whenever you can answer two questions about your DP:

1. **Down:** how does a node's subtree value combine its children's values? That's an ordinary tree DP.
2. **Up:** if a child c leaves p's subtree and p becomes c's child instead, what does p look like from c's side? That's p's answer **with c's contribution taken out**, plus whatever lies above p.

For sums, taking a contribution out is a subtraction, which is why the distance formula is so short. For maximums you can't subtract: knowing the largest of a set doesn't tell you the largest once one element is removed. The standard trick is to keep the **top two** values and remember which child gave the top one. If c gave the maximum, use the second; otherwise, use the maximum.

Here it is for "the distance from every node to the farthest node". `up[v]` is the longest path that starts at v and leaves through its parent: one step to the parent, then the best of continuing up from there or going down into one of the parent's **other** children.

```swift run
// Distance to the farthest node, for every node: max isn't reversible, so keep the top two
func farthest(_ n: Int, _ edges: [[Int]]) -> [Int] {
    var neighbours = [[Int]](repeating: [], count: n)
    for edge in edges {
        neighbours[edge[0]].append(edge[1])
        neighbours[edge[1]].append(edge[0])
    }
    var parent = [Int](repeating: -1, count: n)
    var order = [0]
    var head = 0
    while head < order.count {
        let v = order[head]
        head += 1
        for w in neighbours[v] where w != parent[v] {
            parent[w] = v
            order.append(w)
        }
    }

    // Down pass: the longest and second-longest paths down, through different children
    var first = [Int](repeating: 0, count: n)
    var second = [Int](repeating: 0, count: n)
    var firstChild = [Int](repeating: -1, count: n)     // which child the longest one goes through
    for v in order.reversed() where parent[v] >= 0 {
        let p = parent[v], path = first[v] + 1
        if path > first[p] {
            second[p] = first[p]
            first[p] = path
            firstChild[p] = v
        } else if path > second[p] {
            second[p] = path
        }
    }

    // Up pass: up[v] is the longest path that starts at v and leaves through its parent
    var up = [Int](repeating: 0, count: n)
    for v in order where parent[v] >= 0 {
        let p = parent[v]
        let bestDownAvoidingV = firstChild[p] == v ? second[p] : first[p]
        up[v] = 1 + max(up[p], bestDownAvoidingV)
    }
    return (0..<n).map { max(first[$0], up[$0]) }
}

print(farthest(7, [[0, 1], [0, 2], [2, 3], [2, 4], [4, 5], [4, 6]]))
```

```output
[3, 4, 2, 3, 3, 4, 4]
```

Node 2 is the **centre** of this tree: everything is within 2 steps of it. Nodes 1, 5 and 6 are the ends of the longest paths, 4 steps apart. That 4 is the diameter, the largest value in the list.

<Callout kind="analogy" title="Moving house in a small town">
You know the total walking distance from your old house to all your friends. You move one street over. You don't need to re-walk to everyone: the friends on the far side of that street are now one block closer, and everyone else is one block further. Count both groups and adjust.
</Callout>

## Swift gotchas and common mistakes

<Callout kind="gotcha" title="Using down where you need the full answer">
In the up pass, `answer[c]` must be built from `answer[p]`, the parent's **full** answer, not `down[p]`. `down[p]` ignores everything above p, so every node outside p's subtree would go missing. Only the root's `down` is a full answer.
</Callout>

<Callout kind="gotcha" title="The two passes go in opposite directions">
The down pass needs children before parents (the order reversed). The up pass needs parents before children (the order as it is). Running the up pass backwards reads parents' answers before they exist, and Swift happily uses the zeros the array started with. The result compiles, runs, and is wrong.
</Callout>

- **Weighted edges** change the step from 1 to the edge's length w: c's subtree gets w closer and the rest gets w further, so `answer[c] = answer[p] + w · (n − 2 · size[c])`. The down pass adds `down[c] + w · size[c]`.
- **Don't recurse** for big trees. Both passes are loops over an order array, which is the same trick as at the end of [DP on trees](/dsa/learn/dpa-trees).
