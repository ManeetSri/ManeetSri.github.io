## Why it matters

Suppose every item has a set of features, stored as a bitmask, and for **every** possible set you want to know how many items fit inside it: how many recipes can be cooked with exactly these ingredients in the cupboard, how many volunteers have no skill outside this list, how many pairs of items share no feature at all. Looping over every submask of every mask, as in [Bitmasks for subsets and submasks](/dsa/learn/bits-subsets), costs 3ⁿ. **Sum over subsets** (SOS) DP computes all 2ⁿ answers in **n · 2ⁿ** steps: for 20 bits, 21 million instead of 3.5 billion. It's a short loop with a surprisingly deep idea behind it: a prefix sum in n dimensions.

## The problem

You're given a value for every mask of n bits, `value[mask]`. For every mask, find

> `f[mask]` = the sum of `value[sub]` over every submask `sub` of `mask`.

A submask uses only bits that `mask` has, so `0b101` has submasks `0b000`, `0b001`, `0b100` and `0b101`. The value table is often a count: `value[m]` = how many items have exactly feature set m. Then `f[mask]` counts the items whose features all lie inside `mask`.

The direct way visits every (mask, submask) pair. Each bit is outside the mask, in the mask only, or in both, so that's 3ⁿ pairs.

## One bit at a time

Here's the idea. Think of each mask as a point in an n-dimensional grid where every side has length 2: bit i is the point's coordinate along axis i, 0 or 1. A submask is a point that's **at most as large in every coordinate**. So `f` is exactly a prefix sum, "add up everything below and to the left", in n dimensions.

You already know how to build a 2D prefix sum one axis at a time: first sum along every row, then sum those results down every column, as in [2D prefix sums and difference arrays](/dsa/learn/prefix-2d). SOS does the same along each of the n axes in turn:

> For each bit i, for every mask that has bit i set: `f[mask] += f[mask ^ (1 << i)]`.

`mask ^ (1 << i)` is the same mask with bit i turned off, its neighbour one step down along axis i. After handling bits 0 to i, `f[mask]` holds the sum over submasks that may differ from `mask` **only in bits 0 to i**. After the last bit, they may differ anywhere, which is every submask.

Below, 13 (`0b1101`) is XORed with `1 << 2`, which is 4. The result, 9 (`0b1001`), is the neighbour that the pass for bit 2 adds into `f[13]`. Click the bits to try other masks.

Here are both methods side by side:

```swift run
// For every mask, add up value[sub] over all its submasks: the slow way and the SOS way
func slowSubmaskSums(_ value: [Int], bits n: Int) -> (sums: [Int], steps: Int) {
    var sums = [Int](repeating: 0, count: 1 << n)
    var steps = 0
    for mask in 0..<(1 << n) {
        var sub = mask
        while true {
            sums[mask] += value[sub]
            steps += 1
            if sub == 0 { break }
            sub = (sub - 1) & mask
        }
    }
    return (sums, steps)
}

func sosSums(_ value: [Int], bits n: Int) -> (sums: [Int], steps: Int) {
    var f = value
    var steps = 0
    for bit in 0..<n {                                 // let submasks differ in this bit too
        for mask in 0..<(1 << n) where mask & (1 << bit) != 0 {
            f[mask] += f[mask ^ (1 << bit)]            // add the same mask with this bit turned off
            steps += 1
        }
    }
    return (f, steps)
}

let small = [1, 2, 3, 4, 5, 6, 7, 8]                  // value[mask] for the 8 masks of 3 bits
print(slowSubmaskSums(small, bits: 3).sums)
print(sosSums(small, bits: 3).sums)

let n = 14
let value = (0..<(1 << n)).map { ($0 * 37 + 11) % 100 }
let slow = slowSubmaskSums(value, bits: n)
let fast = sosSums(value, bits: n)
print("same answers:", slow.sums == fast.sums)
print("steps:", slow.steps, "vs", fast.steps)
```

```output
[1, 3, 4, 10, 6, 14, 16, 36]
[1, 3, 4, 10, 6, 14, 16, 36]
same answers: true
steps: 4782969 vs 114688
```

Check one entry. Mask `0b011` (3) has submasks 0, 1, 2 and 3, with values 1, 2, 3 and 4: total 10. Mask `0b111` (7) has all eight: 1 + 2 + … + 8 = 36. For 14 bits the slow way takes 3¹⁴ = 4,782,969 steps, and SOS takes 14 × 2¹³ = 114,688: half the masks have each bit set, so each of the n passes does 2ⁿ⁻¹ additions.

### Why each submask is counted exactly once

Follow one submask `sub` of `mask`. They differ in some set of bits, all of which `mask` has and `sub` doesn't. During the pass for each of those bits, in increasing order, the contribution moves up by turning that bit on, and there's only **one** way to do that: the bits are switched on in a fixed order, one per pass. So `value[sub]` reaches `f[mask]` along exactly one route, and is added exactly once. That's the same reason a 2D prefix sum done row-then-column doesn't double count.

It also explains why the update can be done **in place**: during the pass for bit i, `f[mask ^ (1 << i)]` doesn't have bit i, so this pass never changes it. Whether the loop reaches it before or after `mask` makes no difference.

## Counting pairs that share nothing

Here's the classic use. Given n numbers, each a mask over k bits, count the pairs whose AND is 0: the pairs that share no set bit.

For a number x, a partner y must have no bit that x has. That means y must be a submask of `full ^ x`, the complement of x. So:

1. `count[m]` = how many numbers equal m.
2. SOS turns that into `count[m]` = how many numbers are submasks of m.
3. Each x has `count[full ^ x]` partners.

Adding those up counts every pair twice (once from each end), and also counts each 0 pairing with itself (0 & 0 is 0), so subtract the zeros and halve.

```swift run
// How many pairs i < j have numbers[i] & numbers[j] == 0? Every number uses only the low `bits` bits.
func disjointPairs(_ numbers: [Int], bits n: Int) -> Int {
    let full = (1 << n) - 1
    var count = [Int](repeating: 0, count: 1 << n)
    for x in numbers { count[x] += 1 }
    // SOS: afterwards count[mask] = how many numbers are submasks of mask
    for bit in 0..<n {
        for mask in 0...full where mask & (1 << bit) != 0 {
            count[mask] += count[mask ^ (1 << bit)]
        }
    }
    var ordered = 0
    for x in numbers {
        ordered += count[full ^ x]                    // partners must avoid every bit of x
    }
    let zeros = numbers.filter { $0 == 0 }.count      // 0 & 0 == 0: each zero counted itself as a partner
    return (ordered - zeros) / 2                      // each pair was counted from both ends
}

func bruteForce(_ numbers: [Int]) -> Int {
    var pairs = 0
    for i in 0..<numbers.count {
        for j in (i + 1)..<numbers.count where numbers[i] & numbers[j] == 0 {
            pairs += 1
        }
    }
    return pairs
}

let numbers = [0b0011, 0b0100, 0b1000, 0b1100, 0b0001, 0b0000, 0b0110]
print(disjointPairs(numbers, bits: 4), bruteForce(numbers))
let many = (0..<2_000).map { ($0 * 7_919 + 13) % 1_024 }
print(disjointPairs(many, bits: 10), bruteForce(many))
```

```output
15 15
112793 112793
```

The brute force is O(n²), two million pair checks for 2,000 numbers. SOS is O(k · 2ᵏ + n) whatever n is: with 100,000 numbers over 16 bits, that's about a million steps instead of five billion pair checks.

## Variations

**Sums over supersets.** To add up `value[sup]` over every **superset** of each mask (masks that contain it), flip the direction: for every mask **without** bit i, `f[mask] += f[mask | (1 << i)]`. "How many items have at least these features" is a superset sum.

**Undoing it.** If you're given the submask sums f and want the original values back, run the same loops with `-=` instead of `+=`. Each pass undoes one axis of the prefix sum. This inverse is the **Möbius transform**, and it's inclusion–exclusion done for every mask at once: for example, "how many items have **exactly** these features" from "how many have at least these".

**Other operations.** Nothing in the argument needs addition specifically. Replace `+=` with `max` and you get the largest value over every submask, for instance the best item that fits inside each feature set. Any operation where combining in any order gives the same result works.

| Want, for every mask | Loop over masks | Update |
| --- | --- | --- |
| sum over submasks | with bit i | `f[mask] += f[mask ^ (1 << i)]` |
| sum over supersets | without bit i | `f[mask] += f[mask \| (1 << i)]` |
| undo a submask sum | with bit i | `f[mask] -= f[mask ^ (1 << i)]` |
| best over submasks | with bit i | `f[mask] = max(f[mask], f[mask ^ (1 << i)])` |

<Callout kind="analogy" title="Prefix sums in a hypercube">
A 1D prefix sum adds everything to the left. A 2D one adds everything left and below, built a row pass then a column pass. A mask of n bits is a corner of an n-dimensional cube, and its submasks are the corners "below and to the left" in every direction. SOS is the n-pass version, one pass per direction.
</Callout>

## Swift gotchas and common mistakes

<Callout kind="gotcha" title="The bit loop goes outside">
`for bit` must be the **outer** loop and `for mask` the inner one. Swap them and each mask finishes all its bits before its submasks are complete, so some submasks are missed and others counted twice. The answer is wrong with no error, which is why the run example compares against the slow method.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: debug builds are slow">
SOS over 20 bits is 21 million additions. In an optimised build that's a few milliseconds, but `swift test` builds without optimisation, where each array access is checked and nothing is inlined, and the same loop can take many seconds. Keep this in mind when you time your own tests: the practice problem's tests stop at 16 bits for this reason.
</Callout>

- **Size the table from the bit count**, not from the largest value: with k bits, every complement `full ^ x` must be a valid index, so the table needs `1 << k` entries.
- **Pairs need care at the diagonal.** Counting partners for every element includes the element itself whenever it's a partner of itself (here, only 0). Subtract those before halving.
