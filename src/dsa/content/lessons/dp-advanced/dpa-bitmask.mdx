## Why it matters

Some problems ask you to choose an **order** or a **matching** for a small group of things: the order to visit 15 delivery stops, which of 12 engineers takes which of 12 tickets, how to split 14 tasks into work sessions. Trying every order costs n!, which is hopeless past about 11. But very often the future depends only on **which** things you've used so far, not the order you used them in. Then a bitmask can stand for that set, and the DP has 2ⁿ states instead of n! orders. For n = 15 that's 32,768 against 1.3 trillion. You met the idea once already, in [Hamiltonian paths and TSP](/dsa/learn/ag-hamiltonian). This lesson makes it a general tool.

## When a set can be the state

A bitmask DP fits when three things hold:

1. **n is small**, roughly 20 at most. The table has 2ⁿ entries, possibly times n.
2. **The future depends only on the set used so far**, maybe plus one extra fact such as "where am I standing now".
3. **Every step adds to the set**, so a state's mask only grows.

The masks are the ones from [Bitmasks for subsets and submasks](/dsa/learn/bits-subsets): bit i is 1 when item i is in the set. Point 3 gives the order for free. Adding an item sets a bit, which makes the mask **larger as a number**. So a loop over masks from 0 up to 2ⁿ − 1 always finishes a state before any state it leads to.

How big can n be? It depends on how much work each state does:

| n | 2ⁿ | 2ⁿ · n | 2ⁿ · n² | 3ⁿ |
| --- | --- | --- | --- | --- |
| 10 | 1,024 | 10,240 | 102,400 | 59,049 |
| 15 | 32,768 | 491,520 | 7.4 million | 14 million |
| 16 | 65,536 | 1 million | 16.8 million | 43 million |
| 20 | 1 million | 21 million | 420 million | 3.5 billion |

A few hundred million simple steps is about the limit for a fast program, so O(2ⁿ · n²) means n up to 16 or so, O(2ⁿ · n) stretches to 20, and O(3ⁿ) stops near 15.

## Paths through every item: `dp[mask][last]`

The travelling salesperson DP from M47 is the model for all "visit everything once" problems:

> `best[mask][last]` = the cheapest way to visit exactly the items in `mask`, ending at `last`.

The `last` part is there because the cost of the next step depends on where you are. Two half-finished routes through the same stops are interchangeable **only if they end at the same stop**.

M47 built the closed tour, starting and ending at city 0. Here's the other common variant, an **open path** that may start and end anywhere. Two things change:

- **Base case:** every single item can start the path, so `best[1 << v][v] = 0` for every v.
- **Answer:** no return trip, so take the smallest `best[full][last]` over every `last`.

```swift run
// Shortest route through every checkpoint once, starting and ending anywhere (no return trip)
func shortestRoute(_ distance: [[Int]]) -> Int {
    let n = distance.count
    let full = 1 << n
    let unreached = Int.max / 2
    // best[mask * n + last]: shortest path visiting exactly the checkpoints in mask, ending at last
    var best = [Int](repeating: unreached, count: full * n)
    for v in 0..<n {
        best[(1 << v) * n + v] = 0                  // a path can start at any checkpoint
    }
    for mask in 1..<full {
        for last in 0..<n where mask & (1 << last) != 0 {
            let here = best[mask * n + last]
            if here == unreached { continue }
            for next in 0..<n where mask & (1 << next) == 0 {
                let grown = (mask | (1 << next)) * n + next
                best[grown] = min(best[grown], here + distance[last][next])
            }
        }
    }
    return (0..<n).map { best[(full - 1) * n + $0] }.min()!
}

let distance = [
    [0, 12, 10, 19, 8],
    [12, 0, 3, 7, 2],
    [10, 3, 0, 6, 20],
    [19, 7, 6, 0, 4],
    [8, 2, 20, 4, 0],
]
print("open route:", shortestRoute(distance))
```

```output
open route: 19
```

These are the five cities from M47, whose best closed tour was 32. Without the return trip, 0 → 4 → 1 → 2 → 3 costs 8 + 2 + 3 + 6 = 19.

What to notice:

- The table is **one flat array**, indexed by `mask * n + last`. It's the same as `best[mask][last]`, without 2ⁿ separate inner arrays.
- The transitions **push** forward: each finished state offers itself to every state one item bigger. You could equally **pull**: for each `(mask, last)`, look back at `mask` without `last` and every possible previous item. Both visit the same 2ⁿ · n² pairs.
- **O(2ⁿ · n²) time, O(2ⁿ · n) memory.**

Plenty of problems are TSP in disguise. Gluing words into the shortest string that contains them all is one: the "distance" from word a to word b is how many letters b adds after a, once their overlap is shared. This lesson's first practice problem is exactly that.

## Assignment: when the mask already tells you who's next

Now a different shape. There are n workers and n jobs, and worker i doing job j costs `cost[i][j]`. Every worker gets one job and every job gets one worker. Find the cheapest assignment.

Trying every permutation is n!. For a DP, process the **workers in a fixed order**, 0 first, then 1, and so on, and let the mask record which **jobs** are taken:

> `best[mask]` = the cheapest way to give workers 0, 1, …, k − 1 the jobs in `mask`, where k is the number of 1 bits in `mask`.

There's no need for a second index saying which worker is next: if the mask has k jobs taken, workers 0 to k − 1 have them, so worker k is next. The count of set bits, the **popcount**, is `mask.nonzeroBitCount` in Swift, from [Counting bits and Kernighan's trick](/dsa/learn/bits-counting). Each state tries every free job for worker k, so it's **O(2ⁿ · n)** time and O(2ⁿ) memory.

```swift run
// Assignment: worker i doing job j costs cost[i][j]. Every worker gets one job, every job one worker.
func cheapestAssignment(_ cost: [[Int]]) -> Int {
    let n = cost.count
    let unreached = Int.max / 2
    var best = [Int](repeating: unreached, count: 1 << n)
    best[0] = 0                                       // nobody assigned, nothing spent
    for mask in 0..<(1 << n) where best[mask] < unreached {
        let worker = mask.nonzeroBitCount             // workers 0..<worker already have the jobs in mask
        if worker == n { continue }
        for job in 0..<n where mask & (1 << job) == 0 {
            let grown = mask | (1 << job)
            best[grown] = min(best[grown], best[mask] + cost[worker][job])
        }
    }
    return best[(1 << n) - 1]
}

// Brute force for checking: try every permutation of jobs
func bruteForce(_ cost: [[Int]]) -> Int {
    let n = cost.count
    var used = [Bool](repeating: false, count: n)
    func assign(_ worker: Int) -> Int {
        if worker == n { return 0 }
        var best = Int.max
        for job in 0..<n where !used[job] {
            used[job] = true
            best = min(best, cost[worker][job] + assign(worker + 1))
            used[job] = false
        }
        return best
    }
    return assign(0)
}

let cost = [
    [9, 2, 7, 8],
    [6, 4, 3, 7],
    [5, 8, 1, 8],
    [7, 6, 9, 4],
]
print(cheapestAssignment(cost), bruteForce(cost))

// 12 workers: 4,096 masks instead of 479,001,600 permutations
let big = (0..<12).map { i in (0..<12).map { j in (i * 37 + j * 91 + i * j * 11) % 50 + 1 } }
print(cheapestAssignment(big))
let eight = (0..<8).map { i in (0..<8).map { j in (i * 37 + j * 91 + i * j * 11) % 50 + 1 } }
print(cheapestAssignment(eight), bruteForce(eight))
```

```output
13 13
75
59 59
```

The four-worker answer is worker 0 → job 1 (2), worker 1 → job 0 (6), worker 2 → job 2 (1) and worker 3 → job 3 (4): 13. The DP agrees with the brute force at 4 and 8 workers, and at 12 it checks 4,096 masks where the brute force would try 479 million orders.

Compare the two shapes:

| | TSP | Assignment |
| --- | --- | --- |
| State | `best[mask][last]` | `best[mask]` |
| Why the extra index? | the next cost depends on where you stand | the next worker is fixed by the popcount |
| Time | O(2ⁿ · n²) | O(2ⁿ · n) |

The trick in the assignment DP, **fixing the order of one side so the mask's size says where you are**, turns up constantly. If there are more jobs than workers, say n workers and m ≥ n jobs, the same DP works over masks of m jobs: stop at masks with n bits set and take the cheapest. (For large n, assignment has a polynomial algorithm too, the Hungarian algorithm, but the bitmask DP is far shorter to write when n is small.)

## Splitting a set into groups: submasks

A third shape asks you to **partition** the items: split tasks into the fewest work sessions of at most `limit` minutes, split people into teams, pack items into bins. Here a state is a set of items still to handle, and a transition removes a whole **group** at once. The groups are submasks, so the loop from [Bitmasks for subsets and submasks](/dsa/learn/bits-subsets) does the work:

> `sessions[mask]` = the fewest sessions that finish exactly the tasks in `mask` = 1 + the smallest `sessions[mask ^ sub]` over every non-empty submask `sub` of `mask` that fits in one session.

`mask ^ sub` removes the group's bits, leaving a smaller mask that's already been filled. A helper table `total[mask]` holds each set's total minutes, built in O(2ⁿ) by taking off the lowest set bit: `mask & (mask - 1)` clears it, and `mask.trailingZeroBitCount` says which task it was.

```swift run
// Fewest work sessions of at most `limit` minutes to finish every task (each task in one session)
func fewestSessions(_ tasks: [Int], limit: Int) -> Int {
    let n = tasks.count
    let full = 1 << n
    // total[mask]: minutes for the tasks in mask, built from a smaller mask plus its lowest task
    var total = [Int](repeating: 0, count: full)
    for mask in 1..<full {
        let low = mask.trailingZeroBitCount
        total[mask] = total[mask & (mask - 1)] + tasks[low]
    }
    var sessions = [Int](repeating: Int.max, count: full)
    sessions[0] = 0
    var steps = 0
    for mask in 1..<full {
        // Try every non-empty submask as one session's worth of tasks
        var sub = mask
        while sub > 0 {
            steps += 1
            if total[sub] <= limit && sessions[mask ^ sub] != Int.max {
                sessions[mask] = min(sessions[mask], sessions[mask ^ sub] + 1)
            }
            sub = (sub - 1) & mask
        }
    }
    print("submask steps:", steps)
    return sessions[full - 1]
}

print(fewestSessions([3, 1, 3, 1, 1], limit: 8))
print(fewestSessions([5, 4, 3, 3, 2, 2, 2, 1, 6, 4], limit: 10))
```

```output
submask steps: 211
2
submask steps: 58025
4
```

The step counts are 3ⁿ − 2ⁿ: 211 for n = 5 and 58,025 for n = 10. Each task is outside the mask, in the mask but not the submask, or in both, which gives 3ⁿ (mask, submask) pairs, less the 2ⁿ empty submasks the loop skips. The second example's tasks total 32 minutes, so 4 sessions of 10 is the best possible, and the DP finds a way.

<Callout kind="tip" title="Halving the submask loop">
Every partition is found many times, once for each order its groups could be removed in. Requiring `sub` to contain the lowest set bit of `mask` (the first remaining task must be in this session) finds each partition once and roughly halves the work. It's still O(3ⁿ), so it only helps by a constant factor.
</Callout>

## Which side goes in the mask

Constraints usually tell you what to put in the mask: look for the one quantity that's small. "Up to 16 cities", "at most 12 workers", "no more than 10 people" are invitations. Everything else must be handled another way, usually by **processing it in order**, one item at a time, as the assignment DP processes workers.

That matters when the two sides are lopsided. Say 10 volunteers each need one time slot from their own list of acceptable slots, there are 40 slots, and a slot holds at most one volunteer. How many ways are there to place everyone? A mask over 40 slots would have 2⁴⁰ states, a trillion. A mask over the 10 volunteers has 1,024. So go through the **slots** in order, and let the mask record which **volunteers** are placed. Each slot either stays empty or goes to one volunteer who wants it and is still waiting:

```swift run
// Each volunteer needs one time slot from their own list, and a slot fits one volunteer at most.
// Count the ways to place everyone. Few volunteers, many slots: the mask is over the volunteers.
func placements(volunteers: [[Int]], slots: Int) -> Int {
    let n = volunteers.count
    var wants = [[Int]](repeating: [], count: slots)     // wants[slot]: the volunteers who can take it
    for (person, list) in volunteers.enumerated() {
        for slot in list { wants[slot].append(person) }
    }
    // ways[mask]: ways to place exactly the volunteers in mask using the slots handled so far
    var ways = [Int](repeating: 0, count: 1 << n)
    ways[0] = 1
    for slot in 0..<slots {
        var next = ways                                   // the slot stays empty
        for mask in 0..<(1 << n) where ways[mask] > 0 {
            for person in wants[slot] where mask & (1 << person) == 0 {
                next[mask | (1 << person)] += ways[mask]  // or it goes to someone still waiting
            }
        }
        ways = next
    }
    return ways[(1 << n) - 1]
}

print(placements(volunteers: [[0, 1], [1, 2], [0, 2, 3]], slots: 4))
let many = (0..<10).map { person in (0..<40).filter { ($0 * 7 + person * 3) % 5 < 2 } }
print(placements(volunteers: many, slots: 40))
```

```output
5
393657012224
```

The first answer is small enough to check by hand: volunteer 0 takes slot 0 or 1, volunteer 1 slot 1 or 2, volunteer 2 slot 0, 2 or 3, all different, and five combinations work. The second takes 40 slots × 1,024 masks × a few volunteers per slot, well under a million steps, even though the count itself is nearly 400 billion. (Counts that big usually come with "modulo 1,000,000,007", which you'll handle in [Counting with modulo](/dsa/learn/dpa-counting-mod).)

The slot loop is the outer one, and each slot builds a fresh `next` table from `ways`, so a slot is used at most once. It's the same trick as the 0/1 knapsack in [0/1 knapsack, from 2D to 1D](/dsa/learn/dpk-01): each item is offered exactly once, to every state.

## Swift gotchas and common mistakes

<Callout kind="gotcha" title="Swift gotcha: the sentinel overflows">
`Int.max + cost` crashes, because Swift traps on overflow. Either use a large-but-safe "unreached" such as `Int.max / 2`, or skip unreached states before adding, as every example here does. With `Int.max` as the marker, as in `fewestSessions`, the `!= Int.max` check must come before the `+ 1`.
</Callout>

<Callout kind="gotcha" title="Swift gotcha: memory for 2ⁿ · n">
`best` for n = 20 with a `last` index is 2²⁰ × 20 ≈ 21 million `Int`s, 168 MB. Check the size before you allocate: drop the `last` index if the problem allows it (as assignment does), or store `Int32` when the values fit, which halves it.
</Callout>

- **Count the states you actually need.** In TSP from a fixed start, masks without the start bit are never reached, so `where mask & 1 == 1` skips half the work. In assignment, every mask is reachable.
- **Loop order matters only for pulls.** Pushing from mask to bigger masks and pulling from smaller masks both work with an increasing loop. A decreasing loop breaks both.
- **`1 << n` for n ≥ 64 is 0**, as M16 warned, and the loops run zero times without complaint. With a 2ⁿ table, n that large is impossible anyway, so add a `precondition(n <= 20)` if input sizes are in doubt.
