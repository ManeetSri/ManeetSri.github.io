## Why it matters

In this course, tests call your functions directly. Competitive programming sites such as AtCoder and Kattis, and some interview platforms such as HackerRank, work differently: they hand your program its input as plain text and read what it prints. Command-line tools you write for yourself work the same way. Swift reads that text with one function, `readLine()`.

## Standard input

Every program running in Terminal has a **standard input**: a stream of text it can read. Normally that's whatever you type. You can also feed it a file with `<`, or the output of another command with `|` (a **pipe**):

```bash
swift sum.swift                  # type the input yourself
swift sum.swift < input.txt      # read input.txt as if you'd typed it
echo "3 4" | swift sum.swift     # pipe in the text "3 4"
```

Judges use the second form: your program reads the test file as its standard input.

## readLine()

`readLine()` reads one line of standard input and returns it **without** the newline at the end. Its return type is `String?`: when there's no more input, called the **end of file** or **EOF**, it returns `nil`.

```swift title="sum.swift"
print("Type two numbers separated by a space:")
if let line = readLine() {
    let numbers = line.split(separator: " ").compactMap { Int($0) }
    if numbers.count == 2 {
        print("Sum: \(numbers[0] + numbers[1])")
    } else {
        print("I need exactly two numbers")
    }
}
```

```text title="A session in Terminal"
$ swift sum.swift
Type two numbers separated by a space:
3 4
Sum: 7
```

The program waits at `readLine()` until you press Return. The lesson pages can't run code that waits for input, which is why these examples have no Run button.

## From a line to numbers

A line arrives as one `String`, so you have to cut it up and convert it, using tools from M06 and M08:

- **`line.split(separator: " ")`** cuts the line at spaces and returns an array of `Substring` pieces. Repeated spaces don't create empty pieces: `"3  4"` still gives two.
- **`Int(piece)`** converts a piece, giving `nil` if it isn't a valid whole number. It works directly on a `Substring`.
- **`compactMap { Int($0) }`** converts every piece and quietly drops the ones that fail; **`map { Int($0)! }`** crashes on a bad piece instead.

For a single number on its own line, `Int(line)` is enough.

## A known number of lines

Most judge inputs start by saying how many lines follow. Read that first, then loop:

```swift title="scores.swift"
let count = Int(readLine()!)!
var best = Int.min
for _ in 0..<count {
    let parts = readLine()!.split(separator: " ")
    let name = parts[0]
    let score = Int(parts[1])!
    if score > best {
        best = score
        print("New best: \(name) with \(score)")
    }
}
```

```text title="input.txt"
3
asha 72
ravi 91
meera 85
```

```text title="Running it"
$ swift scores.swift < input.txt
New best: asha with 72
New best: ravi with 91
```

Notice the force unwraps (`!`). On a judge, the input is guaranteed to match the format in the problem statement, so unwrapping is the normal, accepted style there. In an app, where input comes from people, you'd use `if let` or `guard let` instead, as [Force unwrapping, and when it is fine](/dsa/learn/swift-force-unwrap) explains.

## Reading until the input ends

When you don't know how many lines are coming, loop until `readLine()` returns `nil`:

```swift title="total.swift"
var total = 0
var lines = 0
while let line = readLine() {
    for piece in line.split(separator: " ") {
        if let number = Int(piece) {
            total += number
        }
    }
    lines += 1
}
print("Read \(lines) lines, total \(total)")
```

```text title="Running it on a file with lines 1 2 3, 4 5, a blank line, and 6"
$ swift total.swift < numbers.txt
Read 4 lines, total 21
```

`while let` (M04) keeps going as long as there's another line. A blank line is not the end: it comes back as an empty string `""`, which splits into no pieces. When you're typing input yourself, press **Control-D** on a new line to signal the end.

## Test with a file, not your keyboard

Typing the same input every time you change your code is slow and error-prone. Save the problem's sample input in a file and redirect it:

```bash
swift solution.swift < sample1.txt
```

Compare what's printed with the sample output in the problem. Keep one file per sample, and add your own files for edge cases.

<Callout kind="gotcha" title="Swift gotchas with input">
- **Unwrapping past the end crashes.** If your loop reads more lines than the input has, `readLine()!` crashes with "Unexpectedly found nil while unwrapping an Optional value". Check your loop counts against the input format.
- **Spaces break `Int(line)`.** `Int(" 5")` is `nil`. Split first, or trim the line.
- **`split(separator: " ")` ignores tabs.** For input separated by tabs or mixed spacing, use `line.split { $0.isWhitespace }`.
- **Windows line endings are handled.** `readLine()` removes both `"\n"` and `"\r\n"`, so files saved on Windows read correctly.
</Callout>
