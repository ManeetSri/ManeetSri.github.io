## Why it matters

Things go wrong: a line of input isn't a number, a file is missing, a server sends back nonsense. An optional can say "there's no value", but not *why*. Swift's **errors** carry the reason, and the language makes you deal with them on purpose. You'll see them everywhere in iOS, from decoding JSON to reading files, and in this course whenever you parse or validate input before running an algorithm on it.

## Describing what went wrong

An error is any type that conforms to the `Error` protocol (M10). The protocol has no requirements, so conforming is one word. An enum is the natural fit, with one case per thing that can go wrong, and associated values (M09) for the details:

```swift
enum AgeError: Error {
    case empty
    case notANumber(String)
    case outOfRange(Int)
}
```

## Throwing an error

A function that can fail is marked `throws`, after its parameter list. Inside it, `throw` stops the function immediately and hands the error back to the caller, much like `return` hands back a value:

```swift
func parseAge(_ text: String) throws -> Int {
    if text.isEmpty {
        throw AgeError.empty
    }
    guard let age = Int(text) else {
        throw AgeError.notANumber(text)
    }
    guard age >= 0 && age <= 150 else {
        throw AgeError.outOfRange(age)
    }
    return age
}
```

Each `throw` describes exactly what was wrong with the input. The happy path, at the bottom, only runs when every check has passed: the same early-exit shape `guard` gave you in M03.

## Catching errors with do and catch

To call a throwing function you write `try` in front of the call. That word marks every place where control might jump away because of an error. Then you either handle the error or pass it on.

To handle it, put the call in a `do` block followed by one or more `catch` clauses:

```swift run
enum AgeError: Error {
    case empty
    case notANumber(String)
    case outOfRange(Int)
}

func parseAge(_ text: String) throws -> Int {
    if text.isEmpty {
        throw AgeError.empty
    }
    guard let age = Int(text) else {
        throw AgeError.notANumber(text)
    }
    guard age >= 0 && age <= 150 else {
        throw AgeError.outOfRange(age)
    }
    return age
}

for input in ["42", "", "forty", "200"] {
    do {
        let age = try parseAge(input)
        print("Age: \(age)")
    } catch AgeError.empty {
        print("Please type an age")
    } catch AgeError.notANumber(let text) {
        print("'\(text)' isn't a number")
    } catch {
        print("Something else went wrong: \(error)")
    }
}
```

```output
Age: 42
Please type an age
'forty' isn't a number
Something else went wrong: outOfRange(200)
```

What to notice:

- When `parseAge` throws, the rest of the `do` block is skipped. "Age:" is only printed on success.
- `catch` clauses are patterns, like `switch` cases (M03). Swift tries them in order and runs the first that matches. `let text` pulls out the associated value.
- The last `catch` has no pattern, so it catches everything else. Inside it, Swift gives you the error as a constant named `error`.
- Printing an enum error shows its case and values, like `outOfRange(200)`.

## Passing errors on

A throwing function doesn't have to catch the errors of the functions it calls. If it uses `try` without a `do`, any error passes straight up to *its* caller. This is called **propagating** the error:

```swift run
enum AgeError: Error {
    case empty
    case notANumber(String)
}

func parseAge(_ text: String) throws -> Int {
    if text.isEmpty { throw AgeError.empty }
    guard let age = Int(text) else { throw AgeError.notANumber(text) }
    return age
}

func totalAge(of texts: [String]) throws -> Int {
    var total = 0
    for text in texts {
        total += try parseAge(text)    // an error here leaves totalAge immediately
    }
    return total
}

do {
    print(try totalAge(of: ["30", "12"]))
    print(try totalAge(of: ["30", "x", "12"]))
    print("never printed")
} catch {
    print("Failed: \(error)")
}
```

```output
42
Failed: notANumber("x")
```

`totalAge` doesn't know what to do about bad input, so it lets the error travel up to the code that called it. The second call stops at `"x"` and never reaches `"12"`. Deciding *where* to handle an error is part of designing your functions: handle it where you can actually do something useful about it.

## try? and try!

Two shorter forms turn an error into something else.

**`try?`** turns the result into an optional: the value if the call succeeds, `nil` if it throws. You lose the reason, so use it when you don't care why something failed:

```swift run
enum AgeError: Error {
    case notANumber(String)
}

func parseAge(_ text: String) throws -> Int {
    guard let age = Int(text) else { throw AgeError.notANumber(text) }
    return age
}

let a = (try? parseAge("7")) ?? 0
let b = (try? parseAge("seven")) ?? 0
print(a, b)

if let age = try? parseAge("19") {
    print("Got \(age)")
}
```

```output
7 0
Got 19
```

Everything you learned about optionals in M04 now applies: `??` gives a default, and `if let` runs code only on success.

**`try!`** says "I'm certain this can't fail". If it does throw, the program crashes:

```swift
let age = try! parseAge("seven")
```

```text title="What you'll see"
ages/ages.swift:10: Fatal error: 'try!' expression unexpectedly raised an error: ages.AgeError.notANumber("seven")
```

That's what Swift reports when this runs as `swift ages.swift`: the file and line, then the error, with the module name `ages` in front of the type. Use `try!` as rarely as you'd force-unwrap: only when failure would mean your own code is broken.

## Result: an error you can store

Sometimes you want to keep a success-or-failure outcome as a value: in an array, in a property, or to hand to a completion handler later. Swift's `Result` type is an enum with two cases, `.success(value)` and `.failure(error)`. You write its two types in angle brackets: `Result<Int, AgeError>`.

```swift run
enum AgeError: Error {
    case empty
    case notANumber(String)
}

func checkedAge(_ text: String) -> Result<Int, AgeError> {
    if text.isEmpty { return .failure(.empty) }
    guard let age = Int(text) else { return .failure(.notANumber(text)) }
    return .success(age)
}

let results = ["8", "", "x", "21"].map(checkedAge)
for result in results {
    switch result {
    case .success(let age):
        print("ok \(age)")
    case .failure(let error):
        print("failed: \(error)")
    }
}

let ages = results.compactMap { try? $0.get() }
print(ages)
```

```output
ok 8
failed: empty
failed: notANumber("x")
ok 21
[8, 21]
```

- `checkedAge` doesn't throw. It *returns* the failure, so callers never need `try` to call it.
- You read a `Result` with `switch`, like any enum.
- `get()` converts back the other way: it returns the value or throws the error. Here `try?` plus `compactMap` (M06) keeps only the successes.
- `Result { try parseAge(text) }` wraps a throwing call into a `Result` in one line.

## Optional, error or crash?

| Situation | Use | Example |
| --- | --- | --- |
| Absence is normal and the reason is obvious | optional | a dictionary lookup, `Int("x")` |
| The caller may want to react to *why* it failed | `throws` | parsing input, opening a file |
| An outcome to store or pass along | `Result` | a list of per-line parse results |
| The program itself has a bug | crash | covered in the next lesson |

<Callout kind="note" title="Typed throws">
Swift 6 lets a function name the one error type it throws: `func parseAge(_ text: String) throws(AgeError) -> Int`. Then `error` inside a `catch` already has that type. Plain `throws` is still the most common form, and it's what this course uses.
</Callout>

<Callout kind="gotcha" title="Swift gotchas with errors">
- **Every throwing call needs `try`.** Forgetting it is a compile error: "call can throw, but it is not marked with 'try' and the error is not handled".
- **Catches must cover everything** unless the surrounding function itself `throws`. A `do` with only specific patterns, inside a non-throwing function, fails with "errors thrown from here are not handled because the enclosing catch is not exhaustive". Add a final plain `catch`.
- **Mind the brackets with `try?`.** Write `(try? parseAge(s)) ?? 0`. The brackets make it clear the default applies to the whole call.
</Callout>
