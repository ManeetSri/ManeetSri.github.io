## Why it matters

Place n queens on an n × n chessboard so that no two attack each other: no shared row, column or diagonal. It's been the showcase puzzle for backtracking since the 1800s, and for good reason. It's a tiny **constraint satisfaction problem**: give each variable (here, each row's queen) a value so that no rule is broken, the same shape as timetabling, assigning registers in a compiler, or colouring a map. Solving it well teaches three things you'll use again: choose the decisions so that some rules hold automatically, check the remaining rules in O(1) with lookup tables, and count without building answers when counting is all you need.

## Choosing the right decision

How should the search decide where the queens go? The choice of decision changes the size of the tree enormously. For the standard 8 × 8 board:

| Decide… | Leaves | For n = 8 |
| --- | --- | --- |
| any 8 of the 64 squares | C(64, 8) | about 4.4 billion |
| a column for each row | 8⁸ | 16,777,216 |
| a column for each row, all different | 8! | 40,320 |

No two queens can share a row, and there are n queens and n rows, so **every row holds exactly one queen**. Deciding "which column for row 0, then row 1, …" builds that rule into the shape of the tree: rows can never clash. Keeping the columns different turns nⁿ into n!. And checking diagonals the moment a queen is placed cuts the tree much further, as you'll see below.

The state is the list of columns chosen so far, one per row. The choices for the next row are its n columns. The constraint: the column and both diagonals through the square must be free. The goal: a queen in every row.

## Diagonals as numbers

Checking a square against every queen already placed costs O(n). It's faster to keep a table of which columns and diagonals are taken, but that needs a way to number the diagonals. Look at `row - column` and `row + column` on a 4 × 4 board:

```text
   row - column          row + column
  0  -1  -2  -3         0   1   2   3
  1   0  -1  -2         1   2   3   4
  2   1   0  -1         2   3   4   5
  3   2   1   0         3   4   5   6
```

- Along each **down-right diagonal** (`\`), `row - column` stays the same. It runs from −(n − 1) to n − 1, so adding n − 1 turns it into an array index from 0 to 2n − 2.
- Along each **down-left diagonal** (`/`), `row + column` stays the same, from 0 to 2n − 2.

So three Bool arrays describe everything that's attacked: `columnTaken` (n entries), `downTaken` for down-right diagonals and `upTaken` for down-left diagonals (2n − 1 entries each). Checking a square is three lookups.

## Listing every solution

```swift run
func solveQueens(_ n: Int) -> [[Int]] {
    var queenColumn: [Int] = []                                  // queenColumn[row]: that row's queen
    var columnTaken = Array(repeating: false, count: n)
    var downTaken = Array(repeating: false, count: 2 * n - 1)    // "\" diagonals: row - column + n - 1
    var upTaken = Array(repeating: false, count: 2 * n - 1)      // "/" diagonals: row + column
    var solutions: [[Int]] = []

    func place(_ row: Int) {
        if row == n {
            solutions.append(queenColumn)
            return
        }
        for column in 0..<n {
            let down = row - column + n - 1
            let up = row + column
            if columnTaken[column] || downTaken[down] || upTaken[up] { continue }   // attacked
            queenColumn.append(column)                           // choose
            columnTaken[column] = true
            downTaken[down] = true
            upTaken[up] = true
            place(row + 1)                                       // explore
            queenColumn.removeLast()                             // unchoose all four
            columnTaken[column] = false
            downTaken[down] = false
            upTaken[up] = false
        }
    }

    place(0)
    return solutions
}

func draw(_ columns: [Int]) {
    for column in columns {
        print(columns.indices.map { $0 == column ? "Q" : "." }.joined(separator: " "))
    }
}

let four = solveQueens(4)
print(four)
draw(four[0])
let eight = solveQueens(8)
print(eight.count, "solutions for 8 queens; the first is", eight[0])
```

```output
[[1, 3, 0, 2], [2, 0, 3, 1]]
. Q . .
. . . Q
Q . . .
. . Q .
92 solutions for 8 queens; the first is [0, 4, 7, 5, 2, 6, 1, 3]
```

Step through the search for n = 4. Crossed squares are attacked by the highlighted queens; when a row has no safe square left, the queen above is lifted and moved right:

```visual nQueens
n: 4
all: true
```

What to notice:

- **The first attempt fails.** With a queen at column 0 of row 0, every placement of rows 1 and 2 leaves row 3 (or row 2) with nothing safe. Only after backing all the way up and moving the first queen to column 1 does a solution appear.
- **The two solutions are mirror images** of each other. Every solution's mirror is a solution too, which gives a classic speed-up: only try columns in the left half of row 0, then double the count (taking care with the middle column when n is odd).
- **Each choose step sets four things**, so each unchoose step clears the same four.

## Counting instead of listing

If the question is "how many?", building boards is wasted work. Let each call **return** the number of solutions in its subtree, and add up the children:

```swift run
func countQueens(_ n: Int) -> (solutions: Int, nodes: Int) {
    var columnTaken = Array(repeating: false, count: n)
    var downTaken = Array(repeating: false, count: 2 * n - 1)
    var upTaken = Array(repeating: false, count: 2 * n - 1)
    var nodes = 0

    func place(_ row: Int) -> Int {
        nodes += 1
        if row == n { return 1 }                                 // one complete board
        var total = 0
        for column in 0..<n where !columnTaken[column] && !downTaken[row - column + n - 1] && !upTaken[row + column] {
            columnTaken[column] = true
            downTaken[row - column + n - 1] = true
            upTaken[row + column] = true
            total += place(row + 1)
            columnTaken[column] = false
            downTaken[row - column + n - 1] = false
            upTaken[row + column] = false
        }
        return total
    }

    let solutions = place(0)
    return (solutions, nodes)
}

for n in 4...10 {
    let (solutions, nodes) = countQueens(n)
    print("n = \(n): \(solutions) solutions, \(nodes) nodes")
}
```

```output
n = 4: 2 solutions, 17 nodes
n = 5: 10 solutions, 54 nodes
n = 6: 4 solutions, 153 nodes
n = 7: 40 solutions, 552 nodes
n = 8: 92 solutions, 2057 nodes
n = 9: 352 solutions, 8394 nodes
n = 10: 724 solutions, 35539 nodes
```

For n = 8, the search visits 2,057 nodes, against 40,320 complete permutations and 16.7 million column assignments. For n = 10 it's 35,539 nodes against 3.6 million permutations. Checking the diagonals at every level, rather than at the leaves, is what does that. The count still grows exponentially, so it's the pruning that buys you a few extra sizes of board, not a change of complexity class. Nobody knows a formula for the number of solutions; it has only been found by enormous searches.

## Bitmasks: the fast version

The three Bool arrays can be replaced by three integers, using bit c for column c (see [Powers of two and the lowest set bit](/dsa/learn/bits-power-of-two)). The trick is to keep them **relative to the current row**:

- `columns` has a bit set for every column already holding a queen.
- `downRight` has a bit for every square in this row attacked along a down-right diagonal. Moving down a row, each of those attacks moves one column right: shift it left by one (bit c becomes bit c + 1).
- `downLeft` is the same for down-left diagonals, whose attacks move one column left: shift right by one.

The free squares in the row are then `full & ~(columns | downRight | downLeft)`, where `full` has the low n bits set:

```swift run
func countQueensFast(_ n: Int) -> Int {
    let full = (1 << n) - 1                                      // n ones: every column

    func place(_ columns: Int, _ downRight: Int, _ downLeft: Int) -> Int {
        if columns == full { return 1 }                          // a queen in every column, so every row
        var total = 0
        var free = full & ~(columns | downRight | downLeft)
        while free != 0 {
            let square = free & -free                            // the lowest free column
            free &= free - 1                                     // cross it off
            total += place(columns | square, ((downRight | square) << 1) & full, (downLeft | square) >> 1)
        }
        return total
    }

    return place(0, 0, 0)
}

print((1...12).map(countQueensFast))
```

```output
[1, 0, 0, 2, 10, 4, 40, 92, 352, 724, 2680, 14200]
```

What to notice:

- **No unchoose step.** The masks are passed as parameters, so each call gets its own copies: this is the copy-per-call style, and it's cheap because the state is three integers.
- **`free & -free` keeps only the lowest set bit**, and `free &= free - 1` clears it, the two tricks from M16. The loop visits only the free columns, never the attacked ones.
- **`& full` trims bits shifted past the board's edge.** A down-right attack from the last column would otherwise land on an imaginary column n.

The tree is the same as before, so the number of nodes doesn't change. Each node is far cheaper: a few machine instructions instead of array lookups and writes.

<Callout kind="gotcha" title="Common mistakes">
- **Indexing `row - column` directly.** It's negative for squares right of the main diagonal, and a negative index crashes. Add n − 1.
- **Sizing the diagonal arrays n instead of 2n − 1.** A board has 2n − 1 diagonals in each direction.
- **Clearing only some of the marks** on the way back. Column, both diagonals and the path all need restoring.
- **Listing when you should count.** For n = 14 there are 365,596 solutions; storing them all as boards of strings is a lot of memory for an answer that's one number.
- **Shifting the wrong way.** If the bitmask version gives wrong counts, swap the shifts and test against the small known values: 1, 0, 0, 2, 10, 4, 40, 92.
</Callout>
