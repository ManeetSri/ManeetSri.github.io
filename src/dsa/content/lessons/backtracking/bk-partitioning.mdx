## Why it matters

Plenty of input arrives with its separators missing. A log line lost the dots from an IP address. A sentence lost its spaces and must be split back into words. A hashtag needs splitting into the words it's made of. Each of these is a **partitioning** problem: cut a string into consecutive pieces so that every piece is valid. The decision at each step is *where to cut next*, and checking each piece the moment it's cut is the pruning. This lesson does two interview classics, palindrome partitioning and restoring IP addresses, and adds a small table that previews dynamic programming.

## Partitioning is choosing cut positions

A string of n characters has n − 1 gaps between them, and a partition decides, for each gap, whether to cut there. So there are 2ⁿ⁻¹ ways to partition it. "abc" has four: a|b|c, a|bc, ab|c and abc.

As a decision tree: the state is the position where the next piece starts. The choices are where that piece **ends**. Each choice is only allowed if the piece is valid, and then the search continues from the position after it. Reaching the end of the string means every piece was valid: record the plan.

**Palindrome partitioning** asks for every way to cut a string into pieces that each read the same backwards:

```swift run
func isPalindrome(_ letters: [Character], _ from: Int, _ to: Int) -> Bool {
    var left = from
    var right = to
    while left < right {
        if letters[left] != letters[right] { return false }
        left += 1
        right -= 1
    }
    return true
}

func palindromeCuts(_ text: String) -> [[String]] {
    let letters = Array(text)
    var pieces: [String] = []
    var result: [[String]] = []

    func explore(from start: Int) {
        if start == letters.count {                      // every piece was a palindrome
            result.append(pieces)
            return
        }
        for end in start..<letters.count where isPalindrome(letters, start, end) {
            pieces.append(String(letters[start...end]))  // cut after `end`
            explore(from: end + 1)
            pieces.removeLast()                          // undo the cut
        }
    }

    explore(from: 0)
    return result
}

for plan in palindromeCuts("level") {
    print(plan.joined(separator: " | "))
}
print(palindromeCuts("aaaa").count, "plans for aaaa")
```

```output
l | e | v | e | l
l | eve | l
level
8 plans for aaaa
```

What to notice:

- **The validity check is the pruning.** From the start of "level", the pieces "le", "lev" and "leve" aren't palindromes, so those branches are never entered. Only "l" and "level" survive as first pieces.
- **The worst case is still exponential.** In "aaaa" every piece is a palindrome, so all 2³ = 8 plans are answers. A string of n equal letters has 2ⁿ⁻¹, and writing them out alone costs O(n · 2ⁿ).
- **`Array(text)` first.** Swift strings can't be indexed by integers, so the solution works on an array of `Character` and turns slices back into `String` only when a piece is kept.

## Precomputing the palindromes: a first taste of DP

`isPalindrome` costs O(n) per call, and the search asks about the same slices over and over: in "aaaa…", the slice from position 2 to 3 is checked once for every way of cutting the letters before it. Better to answer every "is this slice a palindrome?" question once, up front, in a table.

The trick is that a longer slice's answer comes from a shorter slice's answer. `letters[i...j]` is a palindrome exactly when its two end letters match **and** the slice inside them, `letters[i + 1...j - 1]`, is a palindrome (or is too short to matter: 0 or 1 letters). Filling i from right to left guarantees that row i + 1 is finished before row i needs it:

```swift run
func palindromeTable(_ letters: [Character]) -> [[Bool]] {
    let n = letters.count
    var isPalindrome = Array(repeating: Array(repeating: false, count: n), count: n)
    for i in stride(from: n - 1, through: 0, by: -1) {
        for j in i..<n where letters[i] == letters[j] && (j - i < 2 || isPalindrome[i + 1][j - 1]) {
            isPalindrome[i][j] = true
        }
    }
    return isPalindrome
}

let letters = Array("abaab")
let table = palindromeTable(letters)
for i in 0..<letters.count {
    let row = (0..<letters.count).map { j in j < i ? " " : (table[i][j] ? "T" : ".") }
    print(letters[i], row.joined(separator: " "))
}
```

```output
a T . T . .
b   T . . T
a     T T .
a       T .
b         T
```

Row i, column j says whether `letters[i...j]` is a palindrome: "aba" (row 0, column 2) and "baab" (row 1, column 4) are. Building the table costs O(n²) time and memory, once. After that, every check in the search is a lookup, `table[start][end]`, in O(1).

Solving a big question from the answers to smaller ones, each computed once and stored, is **dynamic programming**, which gets its own modules starting with [Overlapping subproblems and optimal substructure](/dsa/learn/dp-what-is-dp). And if a problem asks only for the **fewest** pieces rather than every plan, there's no need to list plans at all: [Palindrome partitioning: minimum cuts](/dsa/learn/dpi-palindrome-cuts) does it with DP alone.

## Restoring IP addresses

An IPv4 address is four numbers separated by dots, like 192.168.1.1. Suppose the dots were lost and only "19216811" is left. Which addresses could it have been? Each of the four parts must be:

- 1 to 3 digits long,
- between 0 and 255,
- without a leading zero: "0" is fine, but "01" and "00" are not.

The decision tree has 4 levels (one per part) and at most 3 choices per level (the part's length), so at most 3⁴ = 81 leaves. Two kinds of pruning keep it far smaller than that:

- **Piece validity:** an invalid part ends that branch. And because a longer part is bigger, or still has its leading zero, the loop can `break` rather than `continue`.
- **Length bounds:** with k parts left, the remaining digits must number between k and 3k. Too few or too many, and no choice of lengths can work.

```swift run
func restoreAddresses(_ digits: String) -> [String] {
    let digits = Array(digits)
    var parts: [String] = []
    var result: [String] = []

    func explore(from start: Int) {
        let partsLeft = 4 - parts.count
        let digitsLeft = digits.count - start
        if partsLeft == 0 {
            if digitsLeft == 0 { result.append(parts.joined(separator: ".")) }
            return
        }
        if digitsLeft < partsLeft || digitsLeft > 3 * partsLeft { return }   // can't share them out
        for length in 1...min(3, digitsLeft) {
            let part = String(digits[start..<(start + length)])
            if length > 1 && part.first == "0" { break }   // leading zero, and longer parts keep it
            if Int(part)! > 255 { break }                  // longer parts are bigger still
            parts.append(part)                             // choose
            explore(from: start + length)                  // explore
            parts.removeLast()                             // unchoose
        }
    }

    explore(from: 0)
    return result
}

print(restoreAddresses("19216811"))
print(restoreAddresses("0000"))
print(restoreAddresses("100100"))
print(restoreAddresses("1234567890123"))
```

```output
["1.92.168.11", "19.2.168.11", "19.21.68.11", "19.216.8.11", "19.216.81.1", "192.1.68.11", "192.16.8.11", "192.16.81.1", "192.168.1.1"]
["0.0.0.0"]
["1.0.0.100", "10.0.10.0", "100.1.0.0"]
[]
```

Thirteen digits can't fit in four parts of at most three, so the length bound rejects the last input at the root without trying anything. `Int(part)!` is safe here because the input is all digits; with untrusted input, check first.

The same "choose where the next piece ends" shape lists every way to split text into dictionary words: replace the palindrome check with "is this piece in the dictionary?". [Word break I and II](/dsa/learn/dps-word-break) does that, adding memoisation for the counting version.

<Callout kind="gotcha" title="Common mistakes">
- **Slicing past the end.** `digits[start..<(start + length)]` crashes if fewer than `length` digits are left. Capping the loop at `min(3, digitsLeft)` prevents it.
- **Forgetting the leading-zero rule.** "010" is not a valid part, though `Int("010")` happily returns 10.
- **Using `continue` where `break` is right, or the reverse.** `break` is only correct when every later choice in the loop is bound to fail too, as with longer parts here. When in doubt, `continue` is always safe, only slower.
- **Recomputing palindromes from scratch at every node** on long inputs. Build the O(n²) table once.
</Callout>
