## Why it matters

Old phone keypads put three or four letters on each digit, and predictive text had to turn "4663" into "good", "home" and "gone". Code that generates test inputs, such as every well-formed expression up to some size, faces the same task: build every string that follows a rule. This lesson covers the two classic string-building problems. In the first, every branch is valid and backtracking only has to enumerate them. In the second, almost every string is invalid, and the art is a pruning rule that **never builds an invalid prefix** in the first place.

## Phone letters: one level per digit

Each digit is a level of the decision tree, and each letter on its key is a branch:

```swift run
let keypad: [Character: String] = [
    "2": "abc", "3": "def", "4": "ghi", "5": "jkl",
    "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz",
]

func letterCombinations(_ digits: String) -> [String] {
    let digits = Array(digits)
    guard !digits.isEmpty else { return [] }
    var word: [Character] = []
    var result: [String] = []

    func explore(_ index: Int) {
        if index == digits.count {               // a letter for every digit
            result.append(String(word))
            return
        }
        for letter in keypad[digits[index]]! {
            word.append(letter)                  // choose
            explore(index + 1)                   // explore
            word.removeLast()                    // unchoose
        }
    }

    explore(0)
    return result
}

print(letterCombinations("28"))
print(letterCombinations("79").count, letterCombinations("").count)
```

```output
["at", "au", "av", "bt", "bu", "bv", "ct", "cu", "cv"]
16 0
```

What to notice:

- **Nothing to prune.** Every path reaches a leaf and every leaf is an answer, so the work is proportional to the output: 3 or 4 branches per digit, up to 4ⁿ words of length n, so O(n · 4ⁿ) to build them all.
- **The word is built as `[Character]`** and turned into a `String` only at the leaves. Appending and removing the last element of an array are both O(1). (`String` has `append` and `removeLast()` too, and they work fine here; the array makes the cost obvious.)
- **Empty input returns an empty list.** That's this problem's convention. Some versions want `[""]`, the one way to type nothing. Read the statement.

The keypad is only ever read by key, never printed whole, so the output is the same on every run.

When every branch is valid and there's no pruning to do, a plain loop builds the same list, one digit at a time:

```swift
var words = [""]
for digit in digits {
    words = words.flatMap { word in keypad[digit]!.map { word + String($0) } }
}
```

Backtracking earns its keep when some branches must be cut. That's the next problem.

## Balanced brackets: let the counts prune

Generate every **balanced** string of n pairs of brackets: every ")" closes an earlier unmatched "(", and nothing is left open at the end. For n = 3 there are five: `((()))`, `(()())`, `(())()`, `()(())` and `()()()`.

The brute-force way builds all 2²ⁿ strings of "(" and ")" and checks each. For n = 3 that's 64 strings for 5 answers, and for n = 10 over a million strings for 16,796.

Instead, track two counts as you build: how many "(" and how many ")" are placed so far. Then two rules decide what may come next:

- **"(" is allowed while `open < n`.** There are only n to place.
- **")" is allowed while `close < open`.** It needs an unmatched "(" to close.

Any prefix built by those rules can still be completed into a balanced string, so **every leaf is an answer** and nothing is ever thrown away:

```swift run
func balancedBrackets(_ n: Int) -> [String] {
    var current: [Character] = []
    var result: [String] = []

    func explore(open: Int, close: Int) {
        if current.count == 2 * n {
            result.append(String(current))
            return
        }
        if open < n {                            // room for another "("
            current.append("(")
            explore(open: open + 1, close: close)
            current.removeLast()
        }
        if close < open {                        // an unmatched "(" to close
            current.append(")")
            explore(open: open, close: close + 1)
            current.removeLast()
        }
    }

    explore(open: 0, close: 0)
    return result
}

print(balancedBrackets(3))
```

```output
["((()))", "(()())", "(())()", "()(())", "()()()"]
```

Here's the whole tree for n = 2. The root can't start with ")" (nothing to close), and "((" can't add a third "(":

```text
                 ""
                 |
                "("
             /       \
          "(("       "()"
            |          |
          "(()"      "()("
            |          |
         "(())"     "()()"
```

The two counts are passed as parameters, so only `current` needs undoing. The choices here aren't a loop over candidates but two `if`s: one per kind of bracket. That's still choose, explore, unchoose, twice.

## How many: the Catalan numbers

Count the leaves and the nodes for a few sizes, and compare with the brute-force 2²ⁿ:

```swift run
func countBalanced(_ n: Int) -> (strings: Int, nodes: Int) {
    var strings = 0
    var nodes = 0
    func explore(open: Int, close: Int) {
        nodes += 1
        if open + close == 2 * n {
            strings += 1
            return
        }
        if open < n { explore(open: open + 1, close: close) }
        if close < open { explore(open: open, close: close + 1) }
    }
    explore(open: 0, close: 0)
    return (strings, nodes)
}

for n in [3, 6, 10] {
    let (strings, nodes) = countBalanced(n)
    print("n = \(n): \(strings) balanced, \(nodes) nodes, \(1 << (2 * n)) raw strings")
}
```

```output
n = 3: 5 balanced, 22 nodes, 64 raw strings
n = 6: 132 balanced, 625 nodes, 4096 raw strings
n = 10: 16796 balanced, 82499 nodes, 1048576 raw strings
```

The counts 1, 1, 2, 5, 14, 42, 132, … are the **Catalan numbers**. The nth one is Cₙ = C(2n, n) ÷ (n + 1): for n = 3, that's 20 ÷ 4 = 5. They grow exponentially (roughly like 4ⁿ divided by n to the power 1.5), but they're a tiny fraction of 4ⁿ, and the search tree is only about five times bigger than the number of answers. That's the best case for backtracking: no dead ends, so the work is proportional to what you output.

Catalan numbers turn up all over computer science, because they count anything that splits as "one thing, then an inside part, then the rest". A balanced string is "(" + a balanced inside + ")" + a balanced rest, so Cₙ₊₁ = C₀Cₙ + C₁Cₙ₋₁ + … + CₙC₀. The same numbers count the shapes of binary trees with n nodes, the ways to bracket a product of n + 1 matrices (the starting point of [Matrix chain multiplication](/dsa/learn/dpi-matrix-chain)), and the ways to cut a polygon into triangles.

<Callout kind="gotcha" title="Common mistakes">
- **Checking balance only at the end.** It gives the right answer, but explores all 4ⁿ strings to find a tiny fraction of them.
- **Allowing ")" while `close < n`.** That builds prefixes like "())", which can never be completed. The rule is `close < open`.
- **Building with `String` concatenation in the parameter, like `explore(current + "(")`.** It's correct (copy-per-call state), but makes a new string at every node. Fine for small n; the shared array is cheaper.
- **Forcing a `Dictionary` lookup with `!`** on input that might hold a "0", "1" or another character with no letters. The problems here promise digits 2 to 9; real input might not.
</Callout>
