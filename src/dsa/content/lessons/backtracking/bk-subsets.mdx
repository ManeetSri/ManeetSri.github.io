## Why it matters

Which toppings to add, which files to back up, which items fit in the bag: whenever you choose some of a collection, you're choosing a **subset**. Listing every subset is the brute-force starting point for a lot of problems (later in Part VII, dynamic programming makes many of them fast), and it's the simplest real use of the backtracking template. The interesting part comes when the input has **repeats**, like a price list with two items at 5: then the obvious code lists the same subset twice, and fixing that properly teaches a trick you'll reuse in permutations and combinations.

## Two decision trees for the same answers

### In or out

The tree from the last lesson's visual: each level decides one item, in or out. After n decisions you're at a leaf, and each leaf is one subset.

```swift run
func subsetsInOrOut(_ items: [Int]) -> [[Int]] {
    var chosen: [Int] = []
    var result: [[Int]] = []

    func explore(_ index: Int) {
        if index == items.count {                // every item decided
            result.append(chosen)
            return
        }
        chosen.append(items[index])              // in
        explore(index + 1)
        chosen.removeLast()                      // back out of "in"
        explore(index + 1)                       // out
    }

    explore(0)
    return result
}

print(subsetsInOrOut([1, 2, 3]))
```

```output
[[1, 2, 3], [1, 2], [1, 3], [1], [2, 3], [2], [3], []]
```

There are two choices per level, so 2ⁿ leaves, and 2ⁿ⁺¹ − 1 nodes in all.

### Choose the next item

A second tree gives the same subsets in a different shape. Here **every node is a subset**, and a node's children each add one more item, always taken from **further right** than anything already chosen:

```text
                 []
          /       |      \
       [1]       [2]     [3]
      /   \       |
  [1,2]  [1,3]  [2,3]
    |
 [1,2,3]
```

In code, a loop over the possible next items replaces the two calls, and a `start` index says where the possibilities begin:

```swift run
func subsetsByNextItem(_ items: [Int]) -> [[Int]] {
    var chosen: [Int] = []
    var result: [[Int]] = []

    func explore(from start: Int) {
        result.append(chosen)                    // every node is an answer
        for i in start..<items.count {
            chosen.append(items[i])              // choose items[i] as the next item
            explore(from: i + 1)                 // only items to its right after it
            chosen.removeLast()                  // unchoose
        }
    }

    explore(from: 0)
    return result
}

print(subsetsByNextItem([1, 2, 3]))
```

```output
[[], [1], [1, 2], [1, 2, 3], [1, 3], [2], [2, 3], [3]]
```

What to notice:

- **The start index prevents reorderings.** \{1, 2\} and \{2, 1\} are the same subset. Because the next item always comes from the right, every subset is built in exactly one order: increasing index. After choosing 2, item 1 is no longer on offer.
- **This tree has exactly 2ⁿ nodes**, one per subset, with no "undecided" nodes in between.
- **Both cost O(n · 2ⁿ)** overall, because each of the 2ⁿ answers takes up to n steps to copy.

The "choose the next item" shape is the one to learn well. Recording only the nodes of size k gives the combinations of the next-but-one lesson, and the duplicate trick below only works cleanly in this shape.

## Duplicates: when the input repeats

Run either function on `[1, 2, 2]` and you get 8 subsets, but only 6 are different: \{2\} and \{1, 2\} each appear twice. Step through the in-or-out tree and watch the repeated leaves:

```visual subsetsTree
program: subsets
items: [1, 2, 2]
```

Collecting the answers in a `Set` would hide the problem, but the search still does all the work: 20 copies of the same price give 2²⁰ ≈ a million leaves for only 21 different answers. The real fix is to never grow a repeated subtree.

**Sort first, then skip equal siblings.** In the "choose the next item" tree, the children of a node are the possible next items. If two of those candidates have the same value, choosing either one leads to the same subsets. So at each level, only the **first** of a run of equal values is tried:

```swift run
func subsetsWithRepeats(_ items: [Int]) -> [[Int]] {
    let sorted = items.sorted()                  // equal values side by side
    var chosen: [Int] = []
    var result: [[Int]] = []

    func explore(from start: Int) {
        result.append(chosen)
        for i in start..<sorted.count {
            if i > start && sorted[i] == sorted[i - 1] { continue }   // equal sibling: same subtree again
            chosen.append(sorted[i])
            explore(from: i + 1)
            chosen.removeLast()
        }
    }

    explore(from: 0)
    return result
}

print(subsetsWithRepeats([2, 1, 2]))
print(subsetsWithRepeats([3, 3, 3]))
```

```output
[[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
[[], [3], [3, 3], [3, 3, 3]]
```

Why it works, using `[1, 2, 2]`:

- At the root, the candidates are 1, the first 2 and the second 2. The second 2 is skipped: the first 2's subtree already holds \{2\} and \{2, 2\}, and the second 2 could only produce \{2\} again.
- Under \{2\} (the first 2), the next candidates start at the second 2. Now `i == start`, so it's **not** skipped, and \{2, 2\} is built. The rule skips equal **siblings** (candidates at the same level), never equal values along one path.
- Sorting matters because "equal" can only be spotted by comparing a value with its neighbour.

In the in-or-out tree, the matching rule is: **if you leave a value out, leave out all its remaining copies too**, by jumping past them in the "out" call:

```swift
var next = index + 1
while next < sorted.count && sorted[next] == sorted[index] {
    next += 1
}
explore(next)                                    // the "out" branch skips every copy
```

There's a quick way to count the answers, which also makes a good check on your code. Group equal values: if a value appears c times, a subset can take 0, 1, …, c copies of it, which is c + 1 options. Multiply the options together. `[1, 2, 2]` has (1 + 1) × (2 + 1) = 6 different subsets, and twelve 7s with twelve 3s have 13 × 13 = 169.

## The bitmask way, and when backtracking wins

[Bitmasks for subsets and submasks](/dsa/learn/bits-subsets) listed subsets with no recursion at all: count `mask` from 0 to 2ⁿ − 1 and read bit i as "item i is in". Each mask is one leaf of the in-or-out tree, with bit i recording the decision made at level i.

Masks are compact and fast when you really do need to look at every subset, and n is at most about 20. But a mask loop can't **prune**: it visits every subset even when a few chosen items have already broken the rules. Backtracking can stop a branch early. Here's the count of subsets of ten prices that fit a budget of 12, both ways:

```swift run
let prices = [8, 3, 5, 9, 4, 7, 6, 2, 10, 1]
let budget = 12

// Bitmasks: look at all 2^n subsets and keep the affordable ones
var affordableByMask = 0
for mask in 0..<(1 << prices.count) {
    var total = 0
    for i in prices.indices where mask & (1 << i) != 0 {
        total += prices[i]
    }
    if total <= budget {
        affordableByMask += 1
    }
}
print("masks checked:", 1 << prices.count, "affordable:", affordableByMask)

// Backtracking over the sorted prices: a branch stops when the next price doesn't fit
let sorted = prices.sorted()
var nodes = 0
func explore(from start: Int, spent: Int) {
    nodes += 1                                   // every node is an affordable subset
    for i in start..<sorted.count {
        if spent + sorted[i] > budget { break }  // sorted, so every later price is too big as well
        explore(from: i + 1, spent: spent + sorted[i])
    }
}
explore(from: 0, spent: 0)
print("nodes visited:", nodes)
```

```output
masks checked: 1024 affordable: 67
nodes visited: 67
```

Backtracking touched only the 67 answers. The mask loop checked all 1,024 subsets, and with 30 prices it would check over a billion. Sorting is what turned "this price doesn't fit" into "nothing after it fits either", so one `break` cuts a whole run of siblings. You'll use the same move for combination sums.

<Callout kind="gotcha" title="Common mistakes">
- **Skipping with `i > 0` instead of `i > start`.** That also skips the first candidate at a level when it equals the item chosen one level above it, so \{2, 2\} disappears.
- **Forgetting to sort.** The skip rule compares neighbours, so equal values must be next to each other.
- **Deduplicating with a `Set<[Int]>` of unsorted subsets.** `[1, 2]` and `[2, 1]` are different arrays. If you must use a set, sort each subset first, and accept that you've done all 2ⁿ units of work anyway.
- **`for i in start..<items.count` when `start` is past the end.** A range like `3..<3` is empty and fine, but `4..<3` crashes. With `i + 1` as the next start, `start` never goes past `items.count`.
</Callout>
