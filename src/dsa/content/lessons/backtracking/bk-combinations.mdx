## Why it matters

Pick 3 players from a squad of 10. Find every set of stamps that makes up the postage exactly. List the ways to spend a voucher on items from a menu. These are **combinations**: choices where order doesn't matter, often with a target to hit. They're a favourite in interviews because the classic versions, combination sum I, II and III, each change one small detail of the problem, and the code changes in exactly one or two lines each time. Learn which line goes with which detail, and you can write any of them in minutes.

## Choosing k of n

A combination of k items is a subset of size k. So take the "choose the next item" tree from [Subsets, with and without duplicates](/dsa/learn/bk-subsets) and record only the nodes at depth k:

```swift run
func combinations(_ items: [Int], choose k: Int, pruned: Bool) -> (result: [[Int]], nodes: Int) {
    var chosen: [Int] = []
    var result: [[Int]] = []
    var nodes = 0

    func explore(from start: Int) {
        nodes += 1
        if chosen.count == k {
            result.append(chosen)
            return
        }
        for i in start..<items.count {
            // Not enough items left to reach k? Then no later i can either.
            if pruned && items.count - i < k - chosen.count { break }
            chosen.append(items[i])
            explore(from: i + 1)
            chosen.removeLast()
        }
    }

    explore(from: 0)
    return (result, nodes)
}

print(combinations([1, 2, 3, 4], choose: 2, pruned: true).result)
let digits = Array(1...10)
let plain = combinations(digits, choose: 7, pruned: false)
let cut = combinations(digits, choose: 7, pruned: true)
print("7 of 10:", plain.result.count, "combinations,", plain.nodes, "nodes without pruning,", cut.nodes, "with")
```

```output
[[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]]
7 of 10: 120 combinations, 968 nodes without pruning, 330 with
```

There are C(n, k) = n! ÷ (k! × (n − k)!) combinations, the "n choose k" from [Factorials, permutations and combinations](/dsa/learn/math-counting). The pruning line is a **feasibility check**: if you still need 3 more items and only 2 are left, this branch can never finish, and neither can any branch that starts further right. Without it, the search wanders down branches like `[8, 9, 10]` that can't reach 7 items, and visits almost three times as many nodes.

## Combination sum I: reuse allowed

Now a target. Given distinct positive candidates, find every combination that adds up to `target`, where **each candidate can be used any number of times**. With candidates \{2, 3, 5\} and target 8, the answers are 2 + 2 + 2 + 2, 2 + 3 + 3 and 3 + 5.

Two changes to the template:

- **Recurse with `i`, not `i + 1`.** The next item may be the same candidate again. It still can't be an *earlier* candidate, so every combination is built in non-decreasing order, once.
- **Sort, then `break` as soon as a candidate is bigger than what's left.** Every candidate after it is bigger still, so the rest of the loop is pointless. This is the pruning that keeps the tree small.

Step through it. The red nodes are candidates that were cut off before being explored:

```visual subsetsTree

```

```swift run
func combinationSum(_ candidates: [Int], _ target: Int) -> [[Int]] {
    let sorted = candidates.sorted()
    var chosen: [Int] = []
    var result: [[Int]] = []

    func explore(from start: Int, remaining: Int) {
        if remaining == 0 {
            result.append(chosen)
            return
        }
        for i in start..<sorted.count {
            if sorted[i] > remaining { break }                  // sorted: the rest are too big as well
            chosen.append(sorted[i])
            explore(from: i, remaining: remaining - sorted[i])  // i, not i + 1: it may be used again
            chosen.removeLast()
        }
    }

    explore(from: 0, remaining: target)
    return result
}

print(combinationSum([5, 2, 3], 8))
print(combinationSum([4, 6], 9))
```

```output
[[2, 2, 2, 2], [2, 3, 3], [3, 5]]
[]
```

What to notice:

- **`remaining` is a parameter,** so subtracting is undone automatically when the call returns. Only `chosen` needs an explicit unchoose.
- **No "below zero" base case is needed.** The `break` stops before `remaining` could go negative. Without sorting you'd have to recurse and check `remaining < 0` instead, exploring one wasted level for every candidate.
- **The depth is at most target ÷ smallest candidate,** because every level subtracts at least the smallest candidate.

## Combination sum II: each item once, and repeats in the input

Change two details: the candidates may contain **repeated values**, and each one can be used **at most once**. With `[4, 1, 2, 4, 3, 1]` and target 6, using the first 4 or the second 4 must not count as two different answers.

That's exactly the situation from subsets with repeats, so the same two moves apply: recurse with `i + 1`, and skip equal siblings.

```swift run
func combinationSumOnce(_ candidates: [Int], _ target: Int) -> [[Int]] {
    let sorted = candidates.sorted()
    var chosen: [Int] = []
    var result: [[Int]] = []

    func explore(from start: Int, remaining: Int) {
        if remaining == 0 {
            result.append(chosen)
            return
        }
        for i in start..<sorted.count {
            if i > start && sorted[i] == sorted[i - 1] { continue }   // equal sibling: same subtree
            if sorted[i] > remaining { break }
            chosen.append(sorted[i])
            explore(from: i + 1, remaining: remaining - sorted[i])    // i + 1: each item once
            chosen.removeLast()
        }
    }

    explore(from: 0, remaining: target)
    return result
}

print(combinationSumOnce([4, 1, 2, 4, 3, 1], 6))
```

```output
[[1, 1, 4], [1, 2, 3], [2, 4]]
```

`[1, 1, 4]` is allowed: the second 1 is chosen one level deeper, where it's the first candidate (`i == start`), so it isn't skipped. But only one `[2, 4]` appears, because the second 4 is skipped as an equal sibling of the first.

## Combination sum III: k distinct digits

One more twist: use exactly k **different digits from 1 to 9** that add up to n. The candidates are fixed and distinct, each is used once, and the length is fixed too. That gives room for two **bounds**, which cut a branch when even the best case can't work:

- **Too small to reach the sum:** if the `need` largest digits, 9 + 8 + …, add up to less than what's left, stop.
- **Too big already:** if the `need` smallest digits from here, d + (d + 1) + …, add up to more than what's left, then trying a bigger d is even worse: break.

```swift run
func digitCombinations(count k: Int, sum target: Int) -> [[Int]] {
    var chosen: [Int] = []
    var result: [[Int]] = []
    var nodes = 0

    func explore(from start: Int, remaining: Int) {
        nodes += 1
        let need = k - chosen.count
        if need == 0 {
            if remaining == 0 { result.append(chosen) }
            return
        }
        if need * 9 - need * (need - 1) / 2 < remaining { return }   // 9 + 8 + … (need digits) can't reach it
        for digit in start..<10 {
            if need * digit + need * (need - 1) / 2 > remaining { break }   // digit + (digit + 1) + … overshoots
            chosen.append(digit)
            explore(from: digit + 1, remaining: remaining - digit)
            chosen.removeLast()
        }
    }

    explore(from: 1, remaining: target)
    print("  \(nodes) nodes")
    return result
}

print(digitCombinations(count: 3, sum: 9))
print(digitCombinations(count: 4, sum: 30))
```

```output
  13 nodes
[[1, 2, 6], [1, 3, 5], [2, 3, 4]]
  10 nodes
[[6, 7, 8, 9]]
```

Without the bounds, the tree for 4 digits would have 1 + 9 + 36 + 84 + 126 = 256 nodes: every increasing list of up to 4 digits. With them, the search for a sum of 30 tries 1 to 5 as the first digit, sees at once that three more digits can add at most 9 + 8 + 7 = 24, which isn't enough, and then walks straight to `[6, 7, 8, 9]`: 10 nodes. Notice the loop is `start..<10`, not `start...9`: when `start` is 10, the half-open range is empty, but `10...9` would crash.

## One table for the whole family

| Problem | Input values | Reuse? | Recurse with | Extra rule |
| --- | --- | --- | --- | --- |
| Subsets | distinct | no | `i + 1` | none |
| Subsets with repeats | repeated | no | `i + 1` | skip equal siblings |
| k of n | distinct | no | `i + 1` | stop at depth k; enough left? |
| Combination sum I | distinct | yes | `i` | sorted: break when too big |
| Combination sum II | repeated | no | `i + 1` | skip equal siblings; break when too big |
| Combination sum III | digits 1–9 | no | `i + 1` | bounds on the smallest and largest sums |

If a problem only asks **how many** combinations reach the target, not what they are, you don't need to list them: [Coin change I and II](/dsa/learn/dpk-coin-change) counts them with dynamic programming. The last lesson of this module shows how the backtracking here turns into that DP.

<Callout kind="gotcha" title="Common mistakes">
- **Recursing with `i + 1` when reuse is allowed,** or with `i` when it isn't. One character decides which problem you've solved.
- **Starting every loop at 0.** Then `[2, 3, 3]`, `[3, 2, 3]` and `[3, 3, 2]` all appear. Combinations need the start index.
- **`break` without sorting.** On unsorted candidates, one big value would stop the loop before smaller ones later in the array are tried.
- **Zero or negative candidates.** With reuse allowed, a 0 lets the search pick it forever and never finish. The `break` trick also assumes positive values. Check the constraints.
</Callout>

## Practice

**Postage stamp combinations** is combination sum I: unlimited stamps of each value, and every multiset that makes the postage exactly.

```cards

  back: "The index passed down: `explore(from: i, …)` allows the same candidate again; `explore(from: i + 1, …)` uses each one at most once."
- id: comb-break-sorted
  front: "Why sort candidates in combination sum, and what does it allow?"
  back: "Once a candidate is bigger than what's left, every later one is too, so the loop can `break` instead of trying them all."
- id: comb-sum-two
  front: "What two rules make combination sum II produce each combination once?"
  back: "Recurse with `i + 1` (each item once), and after sorting skip `i > start && a[i] == a[i - 1]` (equal siblings)."
- id: comb-feasibility
  front: "What feasibility check prunes \"choose k of n\"?"
  back: "Stop when fewer items are left than you still need: `items.count - i < k - chosen.count`."
```
