## Why it matters

"What's the length?" is rarely the end of an interview question. The follow-ups are "now show me one" and "how many are there?" A fitness app that highlights your longest streak of improving times needs the actual days, not just the count. Both follow-ups are standard DP add-ons, and LIS is the cleanest place to learn them. Printing uses the parent pointers from [Reconstructing the answer, not just its value](/dsa/learn/dp-reconstruct); counting carries a second number alongside each length.

## Printing one LIS with parent pointers

In the O(n²) DP, `length[i]` is improved by some earlier index j. Remember which one:

> `parent[i]` is the index before i in the best run ending at i, or −1 if i starts its run.

Once the table is full, find where a longest run ends, then walk the parents backwards. The walk visits the run from the end to the start, so reverse it at the end:

```swift run
func oneLongestIncreasing(_ items: [Int]) -> [Int] {
    guard !items.isEmpty else { return [] }
    var length = Array(repeating: 1, count: items.count)
    var parent = Array(repeating: -1, count: items.count)   // the index before i in its best run
    for i in items.indices {
        for j in 0..<i where items[j] < items[i] && length[j] + 1 > length[i] {
            length[i] = length[j] + 1
            parent[i] = j
        }
    }
    var end = 0
    for i in items.indices where length[i] > length[end] {
        end = i                                              // the first index with the best length
    }
    var run: [Int] = []
    var index = end
    while index != -1 {
        run.append(items[index])
        index = parent[index]
    }
    return run.reversed()
}

print(oneLongestIncreasing([10, 9, 2, 5, 3, 7, 101, 18]))
print(oneLongestIncreasing([3, 4, 5, 1, 2]))
print(oneLongestIncreasing([5, 4, 3]))
```

```output
[2, 5, 7, 101]
[3, 4, 5]
[5]
```

What to notice:

- The update uses `length[j] + 1 > length[i]`, strictly greater. So among equally good predecessors, the **first** one wins. For 7, both 5 and 3 give length 3, and 5 comes first, which is why the answer has 5 and not 3.
- The search for `end` also keeps the first best index, so the run ends at 101 rather than 18. Several answers are valid; your choices of `>` or `>=` decide which one you get.
- Following parents costs O(LIS length), nothing compared with building the table.

## Printing in O(n log n)

The tails algorithm can print a subsequence too. Store **indexes** in `tails` instead of values, and give each element a parent: whatever index was the tail one position to its left when it arrived. That's exactly the back pointer from the patience sorting proof in the last lesson.

```swift run
func oneLongestIncreasingFast(_ items: [Int]) -> [Int] {
    var tails: [Int] = []                                    // indexes now, not values
    var parent = Array(repeating: -1, count: items.count)
    for (i, x) in items.enumerated() {
        var low = 0
        var high = tails.count
        while low < high {                                   // lower bound on items[tails[...]]
            let mid = low + (high - low) / 2
            if items[tails[mid]] >= x {
                high = mid
            } else {
                low = mid + 1
            }
        }
        if low > 0 {
            parent[i] = tails[low - 1]                       // x extends the run that ends there
        }
        if low == tails.count {
            tails.append(i)
        } else {
            tails[low] = i
        }
    }
    var run: [Int] = []
    var index = tails.last ?? -1
    while index != -1 {
        run.append(items[index])
        index = parent[index]
    }
    return run.reversed()
}

print(oneLongestIncreasingFast([3, 4, 5, 1, 2]))
print(oneLongestIncreasingFast([10, 9, 2, 5, 3, 7, 101, 18]))
```

```output
[3, 4, 5]
[2, 3, 7, 18]
```

The tails for `[3, 4, 5, 1, 2]` end up pointing at the values `[1, 2, 5]`, which isn't a subsequence. But the last tail is the 5, and its parent chain still leads back through 4 to 3, because `parent` was recorded when each element arrived. Later replacements in `tails` never touch an existing chain.

## Counting the longest subsequences

Now count them. For `[3, 1, 4, 2, 5]` the LIS length is 3, and there are three of them: `[3, 4, 5]`, `[1, 4, 5]` and `[1, 2, 5]`.

Carry two numbers per index:

- `length[i]`: the best length of a run ending at i, as before;
- `count[i]`: **how many** runs of that best length end at i.

For each j before i with `items[j] < items[i]`, the runs ending at j, extended by `items[i]`, have length `length[j] + 1`. Compare it with the best so far:

- **Longer** than `length[i]`: a new best. Set `length[i]` to it, and `count[i] = count[j]`, throwing away the old count, which was for shorter runs.
- **Equal** to `length[i]`: more ways to reach the same best. Add: `count[i] += count[j]`.
- **Shorter**: these runs don't matter for i.

The answer adds up `count[i]` over every i whose `length[i]` equals the overall best.

```swift run
func countLongestIncreasing(_ items: [Int]) -> (length: Int, count: Int) {
    var length = Array(repeating: 1, count: items.count)
    var count = Array(repeating: 1, count: items.count)     // how many runs of the best length end at i
    for i in items.indices {
        for j in 0..<i where items[j] < items[i] {
            if length[j] + 1 > length[i] {
                length[i] = length[j] + 1                   // a longer run: start counting afresh
                count[i] = count[j]
            } else if length[j] + 1 == length[i] {
                count[i] += count[j]                        // another way to the same best length
            }
        }
    }
    let best = length.max() ?? 0
    var total = 0
    for i in items.indices where length[i] == best {
        total += count[i]
    }
    return (best, total)
}

print(countLongestIncreasing([3, 1, 4, 2, 5]))
print(countLongestIncreasing([1, 3, 5, 4, 7]))
print(countLongestIncreasing([2, 2, 2, 2, 2]))
print(countLongestIncreasing([]))
```

```output
(length: 3, count: 3)
(length: 4, count: 2)
(length: 1, count: 5)
(length: 0, count: 0)
```

Here are the two rows for `[3, 1, 4, 2, 5]`:

| index | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| item | 3 | 1 | 4 | 2 | 5 |
| length | 1 | 1 | 2 | 2 | 3 |
| count | 1 | 1 | 2 | 1 | 3 |

4 can follow 3 or 1, both of length 1, so two runs of length 2 end at it. 2 can only follow 1. And 5 can follow 4 (two runs of length 2) or 2 (one run), all giving length 3: 2 + 1 = 3 runs.

### What exactly is being counted?

For `[2, 2, 2, 2, 2]` the answer is 5: each single element is a run of length 1. The count is of **index sets**, not distinct lists of values. `[1, 2, 2]` has two LIS, both reading `[1, 2]`, because they use different 2s. That's the usual meaning, and it's what the DP gives. Counting distinct value lists is a different, harder problem.

### How big can the count get?

Very big. In `[2, 1, 4, 3, 6, 5, …]`, every pair offers two choices, so n elements give 2^(n/2) longest subsequences. With 130 elements that's beyond `Int.max`. Problems either promise the answer fits in an `Int` or ask for it modulo a prime such as 1,000,000,007. In the second case, reduce with `%` after every addition.

Counting in O(n log n) is possible too. It needs a structure that answers "the best (length, count) among all values below x" quickly, such as a Fenwick tree over the values, which you'll meet in M61.

<Callout kind="gotcha" title="Common mistakes">
- **Adding counts on a strictly longer run.** A longer run makes the old count meaningless: replace it, don't add to it.
- **Summing only the last index, or only one index.** Several indexes can end a longest run. Add the counts of all of them.
- **Starting counts at 0.** Each element on its own is one run of length 1, so every count starts at 1.
- **Reversing too early.** Following parents yields the run from its end, so reverse once at the very end.
</Callout>

**How many longest rising subsequences** is the counting DP, with values that can repeat. Watch for equal values: they never extend each other in a strictly increasing run.
