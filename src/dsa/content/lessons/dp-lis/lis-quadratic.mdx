## Why it matters

A share price wobbles up and down all year. On how many days, not necessarily consecutive, could you have seen each closing price beat the last one you looked at? A diff tool comparing two versions of a file looks for the longest run of lines that kept their order. Both are the **longest increasing subsequence** problem, LIS for short. It's one of the most asked DP problems, and its solution is the template for a whole family you'll meet in this module: nesting boxes, word chains, divisible sets and score-maximising subsequences.

## Subsequences, not subarrays

A **subsequence** keeps some of the elements in their original order and may skip any of the others. A **subarray** has to be contiguous. Take the readings `[10, 9, 2, 5, 3, 7, 101, 18]`:

- `[2, 5, 7, 101]` is a subsequence (indexes 2, 3, 5 and 6), and it's increasing.
- `[2, 3, 7, 18]` is another increasing subsequence of the same length.
- `[5, 2]` is a subsequence, but it isn't increasing.
- `[7, 5]` isn't a subsequence at all: 7 comes after 5 in the array.

In this module, **increasing** means **strictly** increasing: each element is bigger than the one before it. Here the longest increasing subsequence has length 4, and there are several of them. The question usually asks for the length.

An array of n elements has 2ⁿ subsequences, because each element is either in or out. Checking them all is hopeless beyond about 25 elements, so we need DP.

## Finding a state that works

Following [the DP recipe](/dsa/learn/dp-recipe), the first job is to choose a state. The obvious one, "the LIS of the first i elements", is a dead end. Suppose you know the first five elements have an LIS of length 3. Can element 6 extend it? That depends on the value the subsequence **ended** on, and the state doesn't record it. Different subsequences of length 3 can end on different values.

So pin the ending down:

> `length[i]` is the length of the longest increasing subsequence that **ends exactly at index i**.

Now extending is easy to reason about. An increasing subsequence that ends at i is either `items[i]` on its own, or an increasing subsequence that ends at some earlier index j with `items[j] < items[i]`, followed by `items[i]`. The rest of the recipe follows:

- **Transition:** `length[i] = 1 + max(length[j])` over every `j < i` with `items[j] < items[i]`, or 1 if there's no such j.
- **Base case:** every element alone is an increasing subsequence of length 1, so each `length[i]` starts at 1.
- **Order:** left to right, because `length[i]` only looks at smaller indexes.
- **Answer:** the **largest** `length[i]`, because the best subsequence can end anywhere.

```swift run
func longestIncreasing(_ items: [Int]) -> Int {
    var length = Array(repeating: 1, count: items.count)   // each element alone
    for i in items.indices {
        for j in 0..<i where items[j] < items[i] {
            length[i] = max(length[i], length[j] + 1)       // extend the best run ending at j
        }
    }
    print("length:", length)
    return length.max() ?? 0                                // the best run can end anywhere
}

print(longestIncreasing([10, 9, 2, 5, 3, 7, 101, 18]))
print(longestIncreasing([1, 2, 3, 0]))
print(longestIncreasing([]))
```

```output
length: [1, 1, 1, 2, 2, 3, 4, 4]
4
length: [1, 2, 3, 1]
3
length: []
0
```

Step through the first example. The amber cell is the one being filled, and the blue cells are the earlier, smaller elements it can extend:

What to notice:

- 7, at index 5, can follow 2 (length 1), 5 (length 2) or 3 (length 2). The best it can do is 2 + 1 = 3.
- 101 and 18 both extend the run ending at 7, so both get length 4. Two different longest subsequences end in different places.
- In the second example, the last entry is 1, but the answer is 3. The answer is the maximum, not the last cell.
- The empty array returns 0 thanks to `?? 0`, because `max()` of an empty array is `nil`.

## LIS is a longest path in a DAG

Here's another way to see the same DP. Make each index a vertex, and draw an edge from j to i whenever `j < i` and `items[j] < items[i]`. Edges only go left to right, so there are no cycles: it's a DAG. An increasing subsequence is a path, and the LIS is the **longest path**, counting vertices.

That's exactly the problem from [Longest and shortest paths in a DAG](/dsa/learn/topo-dag-paths), and the index order is already a topological order. So the O(n²) DP is DAG longest path with the edges worked out on the fly.

This view explains the whole module. Every variant changes what an edge means: "this box fits inside that one", "this word is that word plus one letter", "this number divides that one". The DP stays the same.

## Changing one comparison

Because the edge rule is one comparison, the same code answers several questions. Pass the rule in as a closure:

```swift run
func longestChain(_ items: [Int], canFollow: (Int, Int) -> Bool) -> Int {
    var length = Array(repeating: 1, count: items.count)
    for i in items.indices {
        for j in 0..<i where canFollow(items[j], items[i]) {
            length[i] = max(length[i], length[j] + 1)
        }
    }
    return length.max() ?? 0
}

let readings = [3, 3, 1, 2, 2, 5, 4]
print("strictly increasing:", longestChain(readings) { $0 < $1 })
print("non-decreasing:", longestChain(readings) { $0 <= $1 })
print("strictly decreasing:", longestChain(readings) { $0 > $1 })
```

```output
strictly increasing: 3
non-decreasing: 4
strictly decreasing: 2
```

`[1, 2, 5]` is the longest strictly increasing subsequence. Allowing equal neighbours lets `[1, 2, 2, 5]` count. The longest strictly decreasing subsequences, such as `[3, 1]` and `[5, 4]`, have only two elements.

| Question | Condition for j to come before i |
| --- | --- |
| Strictly increasing | `items[j] < items[i]` |
| Non-decreasing | `items[j] <= items[i]` |
| Strictly decreasing | `items[j] > items[i]` |
| Any rule at all | `canFollow(items[j], items[i])` |

## How fast is it?

The inner loop runs i times for each i, so about n²/2 comparisons in total: **O(n²)** time and **O(n)** memory.

| n | about n²/2 | Verdict |
| --- | --- | --- |
| 1,000 | 500,000 | instant |
| 10,000 | 5 × 10⁷ | fine in a release build |
| 100,000 | 5 × 10⁹ | far too slow |

The next lesson finds the length in O(n log n). The O(n²) version is still worth knowing well, because it works for **any** rule between j and i. The faster trick only works when "can follow" means comparing one value.

<Callout kind="gotcha" title="Common mistakes">
- **Returning `length[n - 1]`.** The longest subsequence doesn't have to end at the last element. Return the maximum.
- **Starting every length at 0.** An element on its own is a subsequence of length 1.
- **Mixing up strict and non-strict.** Read the problem carefully: "increasing" usually means strictly, so use `<`.
- **Confusing it with the longest increasing subarray.** A contiguous run is a one-pass O(n) problem: count up while each element beats the last, and reset when it doesn't.
</Callout>
