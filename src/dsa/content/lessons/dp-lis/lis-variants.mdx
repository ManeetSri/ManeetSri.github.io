## Why it matters

Once you can see LIS as "the longest chain where each element may follow the one before", you start spotting it everywhere. A route over hills that climbs and then descends. A set of numbers where every pair divides evenly, like screen sizes that scale cleanly. Words that grow one letter at a time, the kind of puzzle a word game app might generate. This lesson solves three of them with the same O(n²) DP from [LIS in O(n²)](/dsa/learn/lis-quadratic), changing only the rule, the order, or the number of passes.

## Bitonic: up, then down

A **bitonic** subsequence strictly rises and then strictly falls, like a mountain profile: `[1, 4, 8, 6, 2]`. Either part may be empty, so a purely increasing or purely decreasing subsequence also counts. What's the longest one?

Every bitonic subsequence has a peak. If the peak is at index i, the best you can do is the longest increasing subsequence **ending** at i, joined to the longest decreasing subsequence **starting** at i. That suggests two passes:

- `rise[i]`: the LIS ending at i, computed left to right, exactly as before.
- `fall[i]`: the longest decreasing subsequence starting at i. Computed right to left, it's the same DP mirrored: an LIS of the reversed array.

The peak is counted in both, so the answer is the largest `rise[i] + fall[i] - 1`.

```swift run
func longestBitonic(_ items: [Int]) -> Int {
    let n = items.count
    var rise = Array(repeating: 1, count: n)   // longest increasing run ending at i
    var fall = Array(repeating: 1, count: n)   // longest decreasing run starting at i
    for i in 0..<n {
        for j in 0..<i where items[j] < items[i] {
            rise[i] = max(rise[i], rise[j] + 1)
        }
    }
    for i in stride(from: n - 1, through: 0, by: -1) {
        for j in (i + 1)..<n where items[j] < items[i] {
            fall[i] = max(fall[i], fall[j] + 1)
        }
    }
    print("rise:", rise)
    print("fall:", fall)
    var best = 0
    for i in 0..<n {
        best = max(best, rise[i] + fall[i] - 1)   // the peak is in both halves
    }
    return best
}

print(longestBitonic([2, 7, 3, 9, 5, 6, 4, 1]))
print(longestBitonic([5, 4, 3, 2]))
```

```output
rise: [1, 2, 2, 3, 3, 4, 3, 1]
fall: [2, 4, 2, 4, 3, 3, 2, 1]
6
rise: [1, 1, 1, 1]
fall: [4, 3, 2, 1]
4
```

With the peak at 9 (index 3), `rise` is 3 (`[2, 7, 9]` or `[2, 3, 9]`) and `fall` is 4 (`[9, 5, 4, 1]`), giving 3 + 4 − 1 = 6. The peak at 6 ties it: `[2, 3, 5, 6, 4, 1]`.

What to notice:

- In `stride(from: n - 1, through: 0, by: -1)`, `through` includes 0. For the inner loop, `(i + 1)..<n` is an empty range when i is the last index, which is fine.
- A common variant asks for the fewest removals to make a "mountain array", which must rise **and** fall. That's n minus the best `rise[i] + fall[i] - 1` over peaks with both `rise[i]` and `fall[i]` at least 2.
- Both passes use the O(n log n) trick too, if the input is large: the LIS of the prefix ending at i is the position where i landed in `tails`, plus one.

## Largest divisible subset

Given distinct positive numbers, find the largest subset in which, for **every pair**, the larger is divisible by the smaller. In `[9, 4, 18, 2, 3, 36, 8]`, the answer is `[3, 9, 18, 36]`.

"Every pair" sounds like it needs checking all pairs. Sorting removes that worry. Divisibility is **transitive**: if a divides b and b divides c, then a divides c. So in a sorted list, if each element divides the next, every pair works. The problem becomes a chain where j can come before i when `sorted[i] % sorted[j] == 0`. That's LIS with a different rule, plus the parent pointers from [Printing and counting LIS](/dsa/learn/lis-print-count) to return the set itself:

```swift run
func largestDivisibleSubset(_ numbers: [Int]) -> [Int] {
    let sorted = numbers.sorted()
    guard !sorted.isEmpty else { return [] }
    var size = Array(repeating: 1, count: sorted.count)     // the biggest chain ending at i
    var parent = Array(repeating: -1, count: sorted.count)
    var end = 0
    for i in sorted.indices {
        for j in 0..<i where sorted[i] % sorted[j] == 0 && size[j] + 1 > size[i] {
            size[i] = size[j] + 1
            parent[i] = j
        }
        if size[i] > size[end] {
            end = i
        }
    }
    var subset: [Int] = []
    var index = end
    while index != -1 {
        subset.append(sorted[index])
        index = parent[index]
    }
    return subset.reversed()
}

print(largestDivisibleSubset([9, 4, 18, 2, 3, 36, 8]))
print(largestDivisibleSubset([5, 7, 11]))
```

```output
[3, 9, 18, 36]
[5]
```

Why no O(n log n) here? The tails trick works because "can follow" compares one sortable value, so a lower ending is always better. With divisibility, 4 isn't a "better" ending than 9: 8 can follow 4 but not 9, and 18 can follow 9 but not 4. There's no single order of endings, so it's O(n²).

## Word growth chains

A word b **grows from** a word a if you can insert exactly one letter anywhere in a to get b: "cat" grows into "cart" and "chat". Given a list of words, find the longest chain where each word grows from the one before.

This is still an LIS, but checking every pair of words is slow and fiddly. Two observations make it neat:

- **Order:** a word can only grow from a word one letter shorter. Process words **by length**, and everything a word could grow from has already been handled. Sorting by length is a topological order, just as index order was for plain LIS.
- **Transition:** instead of looking at every earlier word, look at the few words this one could have come from. Delete each letter in turn and look the result up in a dictionary of chain lengths.

```swift run
func longestWordChain(_ words: [String]) -> Int {
    var best: [String: Int] = [:]                 // the longest chain ending at each word seen so far
    var answer = 0
    for word in words.sorted(by: { $0.count < $1.count }) {
        var chain = 1
        let letters = Array(word)
        for skip in letters.indices {
            var shorter = letters
            shorter.remove(at: skip)              // the word with one letter deleted
            if let before = best[String(shorter)] {
                chain = max(chain, before + 1)
            }
        }
        best[word] = chain
        answer = max(answer, chain)
    }
    print("chart:", best["chart", default: 0], "dog:", best["dog", default: 0])
    return answer
}

print(longestWordChain(["chart", "a", "cat", "dog", "at", "cart", "do", "chat", "art"]))
```

```output
chart: 5 dog: 2
5
```

"a" → "at" → "cat" → "cart" → "chart" is one chain of 5, and "cat" → "chat" → "chart" gives another route to the same length. "dog" only grows from "do".

With n words of up to L letters, each word tries L deletions, and building each shorter string costs O(L): **O(n · L²)** after an O(n log n) sort. That beats O(n² · L) for comparing every pair whenever there are many short words.

## The pattern

| Problem | Order to process | j may come before i when | Cost |
| --- | --- | --- | --- |
| LIS | index order | `items[j] < items[i]` | O(n²), or O(n log n) |
| Bitonic | both directions | smaller on the way in and on the way out | O(n²), or O(n log n) |
| Divisible subset | sorted ascending | `sorted[i] % sorted[j] == 0` | O(n²) |
| Envelopes | width, ties by height descending | smaller in both | O(n log n) |
| Word chain | by length | j is i with one letter removed | O(n · L²) |

Each time, you choose an order in which every possible predecessor comes first, and a rule for "may come before". That's longest path in a DAG, worked out on the fly.

<Callout kind="gotcha" title="Common mistakes">
- **Forgetting to sort for divisible subsets.** Without sorting, "each divides the next" doesn't give "every pair divides".
- **Counting the bitonic peak twice.** Subtract 1 from `rise[i] + fall[i]`.
- **Comparing every pair of words.** It's correct but slow; generate the possible predecessors instead.
- **Deleting characters by `String.Index` arithmetic in a loop.** Converting to `Array(word)` once makes deletion by integer position simple.
</Callout>
