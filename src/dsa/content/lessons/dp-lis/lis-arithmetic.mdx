## Why it matters

Two more members of the LIS family turn up often in contests and occasionally in interviews. The first changes **what you maximise**: the total of the values instead of how many there are. The second changes **what "may follow" means**: every step must be the same size, as in a regular timetable or evenly spaced frames in an animation. That second one needs a state with two parts, an index and a difference, and Swift dictionaries make it short to write.

## Maximum-sum increasing subsequence

Find the increasing subsequence with the **largest total**. It needn't be the longest. In `[4, 101, 2, 3, 100, 5, 6, 7]`, the longest increasing subsequence is `[2, 3, 5, 6, 7]`, which adds up to only 23. The best total is 105, from `[4, 101]` or `[2, 3, 100]`.

Keep the shape of the O(n²) DP and change what each cell stores:

> `best[i]` is the largest total of an increasing subsequence ending exactly at index i.

- **Base:** `items[i]` on its own, so `best` starts as a copy of `items`.
- **Transition:** `best[i] = max(best[i], best[j] + items[i])` for each `j < i` with `items[j] < items[i]`.
- **Answer:** the maximum of `best`.

```swift run
func maxSumIncreasing(_ items: [Int]) -> Int {
    var best = items                                   // each element alone
    for i in items.indices {
        for j in 0..<i where items[j] < items[i] {
            best[i] = max(best[i], best[j] + items[i])
        }
    }
    print("best:", best)
    return best.max() ?? 0
}

print(maxSumIncreasing([4, 101, 2, 3, 100, 5, 6, 7]))
```

```output
best: [4, 105, 2, 5, 105, 10, 16, 23]
105
```

What to notice:

- The run ending at 7 is the longest, but `best` there is only 23.
- If values can be negative, starting from `items` is still right: a negative element alone is a valid subsequence, and the answer may be negative.
- The patience trick doesn't apply: tails assumes a lower ending is always better, but here a run with a higher ending might have a much larger total. An O(n log n) version exists using a Fenwick tree that stores "the best total among values below x", which you'll meet in M61.

## Longest arithmetic subsequence

An **arithmetic** subsequence has the same difference between every pair of neighbours: `[1, 7, 13, 19]` steps by 6, `[9, 7, 5]` by −2, and `[5, 5, 5]` by 0. Find the longest one.

Try the usual state, "longest arithmetic subsequence ending at i". It doesn't work, because whether `items[i]` can extend a subsequence ending at j depends on that subsequence's **difference**, and different subsequences ending at j can have different differences. The fix is the same as in the first lesson of this module: put the missing information into the state.

> `ending[i][d]` is the length of the longest arithmetic subsequence ending at index i with difference d.

- **Transition:** for each `j < i`, let `d = items[i] - items[j]`. Then `items[i]` extends the best run ending at j with difference d: `ending[i][d] = ending[j][d] + 1`. If j has no run with difference d, the pair (j, i) starts one of length 2.
- **Answer:** the largest value anywhere. Any two elements form an arithmetic subsequence, so with at least two elements the answer is at least 2.

The differences can be anything, and only a few of them occur at each index, so each index gets a **dictionary** from difference to length rather than a huge array:

```swift run
func longestArithmetic(_ items: [Int]) -> Int {
    guard items.count > 2 else { return items.count }
    var ending = Array(repeating: [Int: Int](), count: items.count)   // ending[i][d]: run length
    var best = 2
    for i in items.indices {
        for j in 0..<i {
            let step = items[i] - items[j]
            let length = ending[j][step, default: 1] + 1     // j alone counts as a run of 1
            ending[i][step] = max(ending[i][step, default: 0], length)
            best = max(best, length)
        }
    }
    return best
}

print(longestArithmetic([1, 7, 10, 13, 14, 19]))
print(longestArithmetic([9, 4, 7, 2, 10]))
print(longestArithmetic([5, 5, 5, 5]))
```

```output
4
3
4
```

`[1, 7, 13, 19]` steps by 6, `[4, 7, 10]` by 3, and four 5s step by 0.

What to notice:

- `ending[j][step, default: 1]` reads "j alone is a run of length 1", so a pair with no earlier run becomes 1 + 1 = 2 without a special case.
- The `max` handles repeated values: two earlier equal elements give the same step, and you keep the longer run.
- There are about n²/2 pairs, and each one does a dictionary lookup and an update: **O(n²)** time and up to O(n²) dictionary entries. For n = 1,000 that's half a million entries, which is fine. For much larger n, it's the memory that hurts first.

<Callout kind="tip" title="When the values are small">
If every value is between 0 and 500, every difference is between −500 and 500. Then an array of 1,001 counters per index, indexed by `step + 500`, replaces the dictionary. It's the same DP, often several times faster, because array indexing skips hashing.
</Callout>

## When the difference is given

A common easier version fixes the difference in advance: "the longest subsequence that steps by exactly `step`". Now the state is simpler. Process elements left to right, and keep one dictionary keyed by **value**:

> `best[x]` is the longest run with the given step that ends with the value x, among the elements seen so far.

Each new x extends the run ending at `x - step`, if there is one:

```swift run
func longestWithStep(_ items: [Int], step: Int) -> Int {
    var best: [Int: Int] = [:]
    var answer = 0
    for x in items {
        let length = best[x - step, default: 0] + 1
        best[x] = length                        // a later x is always at least as good
        answer = max(answer, length)
    }
    return answer
}

print(longestWithStep([1, 5, 7, 8, 5, 3, 4, 2, 1], step: -2))
print(longestWithStep([3, 6, 9, 4, 12, 15], step: 3))
```

```output
4
5
```

That's **O(n)**: one dictionary lookup per element. It works because the earlier element is determined: x can only follow the value `x - step`. Overwriting `best[x]` is safe because a later copy of x has seen everything an earlier copy had, plus more.

## Counting arithmetic subsequences

Contests also ask how many arithmetic subsequences of length at least 3 there are. Replace "longest" with "how many" in the state, as in [Printing and counting LIS](/dsa/learn/lis-print-count):

> `ending[i][d]` is the number of subsequences of length **at least 2** that end at i with difference d.

Each pair (j, i) with difference d creates one new subsequence of length 2, the pair itself, plus one longer subsequence for each of the `ending[j][d]` subsequences ending at j. Those longer ones have length at least 3, so they are exactly the ones to add to the answer:

```swift run
func countArithmeticSubsequences(_ items: [Int]) -> Int {
    var ending = Array(repeating: [Int: Int](), count: items.count)
    var total = 0
    for i in items.indices {
        for j in 0..<i {
            let step = items[i] - items[j]
            let before = ending[j][step, default: 0]   // runs of length 2 or more ending at j
            total += before                            // each grows to length 3 or more
            ending[i][step, default: 0] += before + 1  // plus the new pair (j, i)
        }
    }
    return total
}

print(countArithmeticSubsequences([2, 4, 6, 8, 10]))
print(countArithmeticSubsequences([7, 7, 7, 7, 7]))
```

```output
7
16
```

For `[2, 4, 6, 8, 10]`: three of length 3, two of length 4 and one of length 5 stepping by 2, plus `[2, 6, 10]` stepping by 4. For five 7s, every choice of 3, 4 or 5 positions works: 10 + 5 + 1 = 16.

<Callout kind="gotcha" title="Swift gotchas">
- **`dict[key, default: 0] += 1` updates in place.** It's the idiomatic way to bump a counter that may not exist yet.
- **Never print a whole dictionary.** Its order changes from run to run. Print single lookups or sorted keys.
- **Differences can overflow.** `items[i] - items[j]` overflows if values are near `Int.max` and `Int.min`. Normal constraints, such as values up to 10⁹, are nowhere near.
- **An array of n dictionaries is n separate hash tables.** Creating them all up front with `Array(repeating:count:)` is fine; each one only allocates storage when its first key arrives.
</Callout>
