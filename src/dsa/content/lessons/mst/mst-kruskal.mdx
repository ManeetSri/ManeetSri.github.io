## Why it matters

Kruskal's algorithm is the MST algorithm most people reach for first, because it's the easiest to write correctly: sort the edges, then take each one that doesn't close a cycle. It works straight from a list of edges, with no adjacency list, and it's where the union-find from M45 earns its place: "would this edge close a cycle?" is exactly the question `union` answers. Joseph Kruskal published it in 1956, and it's still the standard answer to "connect everything as cheaply as possible" in interviews and contests.

## The idea: lightest first, skip anything that closes a cycle

1. Sort all the edges by weight, lightest first.
2. Go through them in that order. Take an edge if its two ends aren't connected yet; skip it if they are, because it would close a cycle.
3. Stop after taking V − 1 edges.

At every moment the chosen edges form a forest: separate little trees that merge as edges are taken. Each taken edge joins two trees into one, and after V − 1 of them, one tree spans everything.

Union-find tracks the trees. `union(u, v)` returning true means "u and v were in different trees, and now they're joined": take the edge. Returning false means "already connected": skip it.

## Why it's correct

Kruskal never looks ahead, yet it always builds an MST. The cut property from [Spanning trees and the cut property](/dsa/learn/mst-definition) explains why.

Suppose Kruskal is about to take edge e, joining u's tree to v's tree. Consider the cut that separates **u's tree** from everything else. e crosses it. Could a lighter edge cross it too? Every lighter edge has already been considered:

- if it was taken, it now lies inside some tree, so it doesn't cross between u's tree and the rest;
- if it was skipped, its ends were already in one tree, so it doesn't cross either.

So no lighter edge crosses this cut: e is a lightest crossing edge, and the cut property says it's safe. None of the edges chosen so far cross the cut either, so the recipe from the last lesson applies at every step.

The skipped edges are explained by the cycle property: each one closes a cycle whose other edges are all lighter or equal, because they were taken earlier. It's the heaviest on that cycle, so leaving it out never costs anything.

## The code

```swift run
// The UnionFind from M45
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        return true
    }
}

typealias Edge = (from: Int, to: Int, weight: Int)

/// The MST's total weight and edges, or nil if the graph isn't connected
func kruskal(vertexCount: Int, edges: [Edge], names: [String]) -> (total: Int, tree: [Edge])? {
    var trees = UnionFind(count: vertexCount)
    var chosen: [Edge] = []
    var total = 0
    for edge in edges.sorted(by: { $0.weight < $1.weight }) {
        let label = "\(names[edge.from])\(names[edge.to]) \(edge.weight)"
        if trees.union(edge.from, edge.to) {
            chosen.append(edge)
            total += edge.weight
            print(label + ": take it")
            if chosen.count == vertexCount - 1 { break }     // the tree is complete
        } else {
            print(label + ": skip, its ends are already connected")
        }
    }
    guard chosen.count == vertexCount - 1 else { return nil }    // the graph isn't connected
    return (total, chosen)
}

let names = ["A", "B", "C", "D", "E", "F"]
let edges: [Edge] = [(0, 1, 4), (0, 2, 2), (1, 2, 1), (1, 3, 5), (2, 4, 10), (3, 4, 2), (3, 5, 6), (4, 5, 3)]
if let mst = kruskal(vertexCount: 6, edges: edges, names: names) {
    print("total weight:", mst.total)
}
```

```output
BC 1: take it
AC 2: take it
DE 2: take it
EF 3: take it
AB 4: skip, its ends are already connected
BD 5: take it
total weight: 13
```

Here are the groups after each step, which is all union-find has to keep track of:

| Edge | Decision | Groups afterwards |
| --- | --- | --- |
| BC 1 | take | \{B, C\} \{A\} \{D\} \{E\} \{F\} |
| AC 2 | take | \{A, B, C\} \{D\} \{E\} \{F\} |
| DE 2 | take | \{A, B, C\} \{D, E\} \{F\} |
| EF 3 | take | \{A, B, C\} \{D, E, F\} |
| AB 4 | skip: A and B are both in \{A, B, C\} | unchanged |
| BD 5 | take | \{A, B, C, D, E, F\}: done |

What to notice:

- **AC and DE both weigh 2.** Swift's sort is stable, as [How Swift sorts, and sorting custom types](/dsa/learn/sort-swift-sort) explains, so they stay in input order. Either order gives an MST of weight 13.
- **AB is the only edge skipped.** By then A, B and C are already joined through BC and AC.
- **The loop stops at BD**, the fifth edge taken. CE (10) and DF (6) are never even looked at. On a big graph, stopping early can skip most of the edges.
- **Returning nil** signals a disconnected graph: the edges ran out before V − 1 were taken.

## What it costs

| Step | Cost |
| --- | --- |
| Sorting E edges | O(E log E) |
| At most E unions | O(E α(V)), effectively O(E) |
| Total | **O(E log E)** time, O(V + E) space |

Sorting dominates. A simple graph has at most V² edges, so log E ≤ 2 log V, and O(E log E) is the same as **O(E log V)**: you'll see both written. If the edges arrive already sorted, or the weights are small integers you can sort in linear time with [Counting sort](/dsa/learn/sort-counting), Kruskal is nearly linear.

## When the graph isn't connected

If the loop runs out of edges before taking V − 1, there's no spanning tree. The chosen edges still form a **minimum spanning forest**, one MST per component, and the number of components is V minus the number of edges taken. Whether to return the forest, nil or −1 depends on the problem.

## Variations

**Maximum spanning tree.** Sort heaviest first. Everything else is unchanged: the proof only relied on taking edges in order.

**Clustering.** Stop Kruskal early, when exactly k groups remain. The edges taken joined the closest pairs first, so the k groups are natural clusters, and the next edge Kruskal would have taken is the **spacing**: the smallest distance between two different clusters. No other way of splitting into k groups has a larger spacing. This is called **single-linkage clustering**.

```swift run
// The UnionFind from M45, with a count of groups
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]
    private(set) var componentCount: Int

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
        componentCount = count
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        componentCount -= 1
        return true
    }
}

let names = ["A", "B", "C", "D", "E", "F"]
let edges = [(0, 1, 4), (0, 2, 2), (1, 2, 1), (1, 3, 5), (2, 4, 10), (3, 4, 2), (3, 5, 6), (4, 5, 3)]
let k = 2
var groups = UnionFind(count: names.count)
for (a, b, weight) in edges.sorted(by: { $0.2 < $1.2 }) {
    if groups.componentCount == k {
        if groups.find(a) != groups.find(b) {          // the first edge that would join two clusters
            print("spacing:", weight, "(\(names[a])\(names[b]))")
            break
        }
        continue
    }
    _ = groups.union(a, b)
}
for root in Set(names.indices.map { groups.find($0) }).sorted() {
    print(names.indices.filter { groups.find($0) == root }.map { names[$0] }.joined(separator: " "))
}
```

```output
spacing: 5 (BD)
A B C
D E F
```

Two clusters, \{A, B, C\} and \{D, E, F\}, and the closest they come is the BD edge of weight 5: the same cut you met in the last lesson.

<Callout kind="gotcha" title="Common mistakes">
- **Sorting by the wrong field.** With tuples `(from, to, weight)`, sort by `.weight` or `$0.2`, not `$0.0`.
- **Taking every edge.** Check what `union` returns. Without that check, you add cycle-closing edges and the "tree" has more than V − 1 edges.
- **The wrong vertex count.** If vertices are numbered 1 to n, make the union-find size n + 1, or subtract one from every label.
- **Assuming the graph is connected.** Count the edges taken. Fewer than V − 1 means no spanning tree.
</Callout>
