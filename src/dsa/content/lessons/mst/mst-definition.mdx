## Why it matters

A council wants fibre between six towns. Every possible cable route has a cost, and the only requirement is that every town can reach every other, directly or through other towns. What's the cheapest set of cables? That's a **minimum spanning tree** (MST), and the same question appears when laying pipes, power lines and circuit tracks, when grouping similar photos into clusters, and as a building block for harder problems, such as finding good approximate routes for a travelling salesperson. This lesson defines MSTs and proves the two facts every MST algorithm relies on, the **cut property** and the **cycle property**. The next three lessons turn them into Kruskal's, Prim's and Borůvka's algorithms.

## Spanning trees

Start with a connected, undirected graph with weights on its edges, as in [Weighted graphs and the shortest-path problem](/dsa/learn/sp-weighted). A **spanning tree** is a set of its edges that connects every vertex and contains no cycle. "Spanning" means it reaches every vertex; "tree" means no cycles. From [Provinces, redundant connection and valid tree](/dsa/learn/uf-provinces) you know such a set has exactly **V − 1 edges**.

A **minimum spanning tree** is a spanning tree whose total weight is as small as possible. Here's the graph used throughout this module:

```text
          B ---5--- D
        / |         | \
      4   1         2   6
     /    |         |     \
    A     |         |      F
     \    |         |     /
      2   |         |   3
        \ |         | /
          C ---10-- E
```

| Edge | AB | AC | BC | BD | CE | DE | DF | EF |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Weight | 4 | 2 | 1 | 5 | 10 | 2 | 6 | 3 |

Six vertices, so every spanning tree has five edges. With only eight edges, you can try every set of five and keep the ones that are spanning trees:

```swift run
typealias Edge = (from: String, to: String, weight: Int)

/// True when the chosen edges connect all the vertices with no cycle
func isSpanningTree(_ chosen: [Edge], _ vertices: [String]) -> Bool {
    var parent = Dictionary(uniqueKeysWithValues: vertices.map { ($0, $0) })
    func root(_ x: String) -> String {
        var x = x
        while parent[x]! != x { x = parent[x]! }
        return x
    }
    for edge in chosen {
        let (rootA, rootB) = (root(edge.from), root(edge.to))
        if rootA == rootB { return false }          // this edge would close a cycle
        parent[rootA] = rootB
    }
    return chosen.count == vertices.count - 1      // no cycle and V − 1 edges: connected
}

/// Tries every set of V − 1 edges and reports the spanning trees and the lightest ones
func survey(_ vertices: [String], _ edges: [Edge]) {
    var trees = 0
    var best = Int.max
    var lightest: [[Edge]] = []
    for mask in 0..<(1 << edges.count) where mask.nonzeroBitCount == vertices.count - 1 {
        let chosen = edges.indices.filter { mask & (1 << $0) != 0 }.map { edges[$0] }
        guard isSpanningTree(chosen, vertices) else { continue }
        trees += 1
        let weight = chosen.reduce(0) { $0 + $1.weight }
        if weight < best {
            best = weight
            lightest = [chosen]
        } else if weight == best {
            lightest.append(chosen)
        }
    }
    print("\(trees) spanning trees; lightest weight \(best), reached by \(lightest.count)")
    for tree in lightest {
        print("  " + tree.map { "\($0.from)\($0.to) \($0.weight)" }.joined(separator: ", "))
    }
}

survey(["A", "B", "C", "D", "E", "F"],
       [("A", "B", 4), ("A", "C", 2), ("B", "C", 1), ("B", "D", 5),
        ("C", "E", 10), ("D", "E", 2), ("D", "F", 6), ("E", "F", 3)])
survey(["P", "Q", "R", "S"], [("P", "Q", 1), ("Q", "R", 1), ("R", "S", 1), ("S", "P", 1), ("P", "R", 2)])
```

```output
30 spanning trees; lightest weight 13, reached by 1
  AC 2, BC 1, BD 5, DE 2, EF 3
8 spanning trees; lightest weight 3, reached by 4
  PQ 1, QR 1, RS 1
  PQ 1, QR 1, SP 1
  PQ 1, RS 1, SP 1
  QR 1, RS 1, SP 1
```

The first graph has 30 spanning trees and exactly one MST, weighing 13. The second, a square of four equal edges plus a heavier diagonal, has **four** MSTs, all weighing 3. The loop walks every subset as a bitmask, as in [Bitmasks for subsets and submasks](/dsa/learn/bits-subsets): bit i set means edge i is chosen, and `nonzeroBitCount` keeps only the masks with V − 1 bits.

Trying every subset is exponential: a complete graph on n vertices has n^(n − 2) spanning trees (Cayley's formula), so 10 towns would mean 100 million. You need a smarter idea.

If the graph isn't connected, it has no spanning tree. The best you can do is a **minimum spanning forest**: an MST for each component.

## Cuts and the cut property

A **cut** splits the vertices into two non-empty groups. An edge **crosses** the cut when its ends are in different groups. Any spanning tree must use at least one crossing edge, or the two groups would never be connected.

**The cut property.** For any cut, a lightest edge crossing it belongs to some MST. If it's the only lightest crossing edge, it belongs to every MST.

Try it on the graph. Cut \{A, B, C\} from \{D, E, F\}: the crossing edges are BD (5) and CE (10). The lightest, BD, is in the MST. Cut \{A\} from the rest: AB (4) and AC (2) cross, and AC is in the MST. Whatever cut you pick, its lightest crossing edge is in the tree.

### Why it's true

This is an **exchange argument**: take any MST that doesn't use the edge, and swap the edge in without making things worse.

1. Let e be a lightest edge crossing the cut, and let T be an MST that doesn't contain e.
2. T connects everything, so it already has a path between e's two ends. Adding e to T creates a **cycle**: that path plus e.
3. The cycle starts on one side of the cut, crosses over through e, and must get back to where it started. So it crosses the cut at least once more, through some edge f of T.
4. f crosses the cut, and e is a lightest crossing edge, so weight(f) ≥ weight(e).
5. Remove f from T and add e. Removing an edge from a cycle doesn't disconnect anything, so the result is still a spanning tree, and its weight is weight(T) − weight(f) + weight(e) ≤ weight(T).

So the new tree is also an MST, and it contains e. If e is **strictly** lighter than every other crossing edge, then weight(f) > weight(e), and the new tree would be lighter than T, which is impossible because T was minimum. So in that case every MST must already contain e.

<Callout kind="analogy">
Two villages on opposite banks of a river must be joined by at least one bridge. Whatever else the network looks like, it's never worse to make that bridge the cheapest one available.
</Callout>

## The cycle property

**The cycle property.** For any cycle, if one edge is strictly heavier than all the others on that cycle, it belongs to no MST.

The reason mirrors the cut property. If an MST used that heaviest edge e, removing e would split the tree into two parts: a cut. The rest of the cycle still runs from one part to the other, so some other cycle edge f crosses that cut. Swapping e out for the lighter f gives a lighter spanning tree, which is impossible.

On our graph, the cycle A–B–C has weights 4, 1 and 2, so AB is out. The cycle B–D–E–C has 5, 2, 10 and 1, so CE is out. The cycle D–E–F has 2, 3 and 6, so DF is out. Remove those three from the eight edges and exactly the five MST edges remain.

## When is the MST unique?

**If all the edge weights are different, there is exactly one MST.** Suppose there were two, T₁ and T₂. Take the lightest edge e that's in one but not the other, say in T₁. Adding e to T₂ makes a cycle. That cycle has an edge f that isn't in T₁ (or T₁ would contain a cycle). f is in T₂ but not T₁, so f is heavier than e, because e was the lightest such edge and weights are distinct. Then T₂ minus f plus e is lighter than T₂: a contradiction.

With equal weights, several MSTs can exist, like the four in the square above. They always have the **same total weight**. So when a test checks an MST, it should compare totals or check properties, not demand one particular set of edges.

## One recipe, three algorithms

The cut property gives a recipe for building an MST greedily:

1. Start with no edges chosen.
2. Pick a cut that none of the chosen edges cross. Add a lightest edge crossing it. It's **safe**: some MST contains everything chosen so far plus this edge.
3. Repeat until V − 1 edges are chosen.

Greedy algorithms often fail, but this one provably can't: every step keeps the chosen edges inside some MST. The three classic algorithms differ only in which cut they pick:

| Algorithm | The cut it uses | Data structure |
| --- | --- | --- |
| Kruskal | around one of the two groups the next-lightest edge would join | sorting and union-find |
| Prim | the tree grown so far versus everything else | a heap, or a plain array |
| Borůvka | every group's own cut, all at once | rounds over the edge list |

## MSTs are not shortest paths

The most common confusion in this module: an MST minimises the **total** weight of the whole network, not the distance between any particular pair. Take a triangle with AB = 2, BC = 2 and AC = 3. The MST is AB and BC, weighing 4. But in that tree, getting from A to C costs 4, while the direct edge costs 3. The shortest paths from A, as [Dijkstra's algorithm](/dsa/learn/sp-dijkstra) finds them, use AB and AC, weighing 5 in total.

| | Minimises | Answer for the triangle |
| --- | --- | --- |
| MST | the sum of all chosen edges | AB, BC: total 4 |
| Shortest-path tree from A | each vertex's distance from A | AB, AC: total 5 |

Two more differences: MST algorithms only **compare** weights, so negative weights are fine, unlike Dijkstra. And a **maximum** spanning tree comes from the same algorithms with the comparisons reversed.

<Callout kind="gotcha" title="Things to watch">
- **MSTs are for undirected graphs.** The directed version, a minimum arborescence, needs a different algorithm (Chu–Liu/Edmonds).
- **A disconnected graph has no spanning tree.** Decide what to return: a forest, or a signal such as −1.
- **Ties allow several correct answers.** Check the total weight, not the exact edges.
</Callout>
