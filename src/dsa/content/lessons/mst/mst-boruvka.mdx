## Why it matters

Borůvka's algorithm is the oldest MST algorithm: Otakar Borůvka published it in 1926 to plan an efficient electricity network for Moravia, two decades before the first electronic computers. It works in **rounds**, and in each round every group of vertices acts on its own, which makes it the natural MST algorithm for parallel and distributed machines, such as GPUs and clusters processing graphs with billions of edges. It's also a building block of the fastest known MST algorithms. You're unlikely to need it in an interview, but it completes the picture: three algorithms, three ways of choosing cuts, one cut property.

## The idea: everyone picks at once

Start with every vertex as its own component. Then repeat rounds until one component is left:

1. For **every** component, find its **cheapest outgoing edge**: the lightest edge with exactly one end inside the component.
2. Add all of those edges at once, merging the components they join.

Each chosen edge is a lightest edge crossing the cut between its component and everything else, so the cut property from [Spanning trees and the cut property](/dsa/learn/mst-definition) says it's safe. Kruskal uses one cut at a time, chosen by the global order of edges. Prim always uses the cut around its single tree. Borůvka uses **every component's cut in the same round**.

Two components often pick the same edge. In this module's graph, B's cheapest edge is BC and C's is BC too. Union-find takes care of it: the second union of the pair returns false and nothing happens.

## Ties can make a cycle

Adding many edges at once has one danger. Take a triangle where every edge weighs 1. A picks AB, B picks BC, and C picks CA, each a perfectly good "cheapest" edge. Add all three and you have a cycle.

The fix is to make every comparison strict: compare edges by **weight, then by their position in the edge list**. Now no two edges tie, so there's exactly one MST under this order, and every component's cheapest edge belongs to it. Edges of one MST can never form a cycle. In the triangle, with the edges listed AB, BC, CA, A and B both pick AB, the earliest of their edges, and C picks BC. AB and BC form no cycle, and they finish the tree in one round.

## Why there are only log V rounds

In each round, every component merges with at least one other, through its own chosen edge. So the number of components at least **halves** every round. Starting from V components, there can be at most log₂ V rounds before one is left.

Each round scans all E edges once, doing two finds per edge: O(E α(V)). So the total is **O(E log V)**, the same as Kruskal and heap Prim, with no sorting and no heap.

## The code

Each round, an array `cheapest` holds, for each component's root, the index of its lightest outgoing edge found so far. One pass over the edges fills it; then the chosen edges are unioned.

```swift run
// The UnionFind from M45, with a count of components
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]
    private(set) var componentCount: Int

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
        componentCount = count
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        componentCount -= 1
        return true
    }
}

func boruvka(_ names: [String], _ edges: [(Int, Int, Int)], listEdges: Bool = true) -> Int? {
    /// Edge a comes before edge b: by weight, then by position in the list, so no two edges tie
    func lighter(_ a: Int, _ b: Int) -> Bool {
        edges[a].2 != edges[b].2 ? edges[a].2 < edges[b].2 : a < b
    }
    var sets = UnionFind(count: names.count)
    var total = 0
    var round = 0
    while sets.componentCount > 1 {
        round += 1
        // cheapest[root]: the index of the lightest edge leaving that root's component, or -1
        var cheapest = Array(repeating: -1, count: names.count)
        for index in edges.indices {
            let rootA = sets.find(edges[index].0)
            let rootB = sets.find(edges[index].1)
            if rootA == rootB { continue }                   // inside one component
            for root in [rootA, rootB] where cheapest[root] == -1 || lighter(index, cheapest[root]) {
                cheapest[root] = index
            }
        }
        let chosen = Set(cheapest.filter { $0 >= 0 }).sorted()
        if chosen.isEmpty { return nil }                     // no edge leaves any component
        var added: [String] = []
        for index in chosen where sets.union(edges[index].0, edges[index].1) {
            total += edges[index].2
            added.append("\(names[edges[index].0])\(names[edges[index].1]) \(edges[index].2)")
        }
        let what = listEdges ? added.joined(separator: ", ") : "\(added.count) edge\(added.count == 1 ? "" : "s")"
        print("round \(round): add \(what); \(sets.componentCount) left")
    }
    return total
}

let names = ["A", "B", "C", "D", "E", "F"]
let edges = [(0, 1, 4), (0, 2, 2), (1, 2, 1), (1, 3, 5), (2, 4, 10), (3, 4, 2), (3, 5, 6), (4, 5, 3)]
print("total weight:", boruvka(names, edges)!)

// 16 vertices in a ring, each joined to the next, with weights 1 to 16 in a scrambled order
let ring = (0..<16).map { "v\($0)" }
let ringEdges = (0..<16).map { ($0, ($0 + 1) % 16, ($0 * 7) % 16 + 1) }
print("ring total:", boruvka(ring, ringEdges, listEdges: false)!)
```

```output
round 1: add AC 2, BC 1, DE 2, EF 3; 2 left
round 2: add BD 5; 1 left
total weight: 13
round 1: add 9 edges; 7 left
round 2: add 5 edges; 2 left
round 3: add 1 edge; 1 left
ring total: 120
```

On this module's graph, round 1 does almost everything. A picks AC; B and C both pick BC; D and E both pick DE; F picks EF. That leaves \{A, B, C\} and \{D, E, F\}, and both pick BD in round 2. The total, 13, matches Kruskal and Prim.

The ring of 16 vertices shows the halving: 16 components, then 7, then 2, then 1, in three rounds, never more than log₂ 16 = 4. Its weights are 1 to 16 in a scrambled order, and the MST is the whole ring except the heaviest edge: 1 + 2 + … + 15 = 120.

What to notice:

- **`find` is called fresh in every round.** Components change between rounds, so roots from the previous round can be out of date.
- **`Set(...).sorted()`** removes the edges picked twice and fixes the order of the unions, so the output is the same on every run.
- **An empty `chosen`** means no edge leaves any component: the graph is disconnected, and there's no spanning tree.

## Why it suits parallel machines

Inside a round, each component's search for its cheapest edge doesn't depend on any other component. Split the edges across many processors, let each find the cheapest outgoing edge it sees for each component, and combine the answers with a "take the lighter" step. Then merge, and **contract** each component into a single vertex, so the next round works on a smaller graph. Kruskal, by contrast, must look at edges in one global order, and Prim grows one tree one vertex at a time: both are inherently step by step.

That's why distributed graph systems and GPU libraries compute MSTs with Borůvka-style rounds. It's also why Borůvka appears inside the fastest known MST algorithm, a randomised one by Karger, Klein and Tarjan (1995) that runs in expected O(E) time: Borůvka rounds shrink the graph quickly, and random sampling throws away edges that can't be in the MST.

## All three side by side

| | Kruskal | Prim (heap) | Borůvka |
| --- | --- | --- | --- |
| Cut used | around a group the next-lightest edge joins | the one growing tree | every component's, each round |
| Data structures | sorting, union-find | heap, adjacency lists | union-find (or relabelling) |
| Time | O(E log E) | O(E log V) | O(E log V) |
| Steps | E edges in global order | V vertices, one at a time | at most log₂ V rounds |
| Strength | simplest from an edge list | grows locally; O(V²) array version for dense graphs | parallel and distributed |

<Callout kind="gotcha" title="Common mistakes">
- **Comparing by weight alone.** With equal weights, components can pick edges that form a cycle. Break ties by edge index, or by any fixed order.
- **Using stale roots.** Call `find` during each round's scan, not with labels saved from an earlier round.
- **Looping forever on a disconnected graph.** If no component has an outgoing edge, stop: there's no spanning tree.
</Callout>
