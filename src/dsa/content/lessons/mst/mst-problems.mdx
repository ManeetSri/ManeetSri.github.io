## Why it matters

In interviews, MST problems rarely say "minimum spanning tree". They say "connect all the points", "lay cables so every office is reachable", or "each house needs water". The work is in recognising the shape, choosing between Kruskal and Prim, and sometimes reshaping the graph so a standard algorithm applies. This lesson covers the patterns that come up again and again: the dense "connect all points" graph, the "impossible" case, the virtual-vertex trick, bottleneck paths, and, as an advanced aside, which edges every MST must use.

## Recognising an MST problem

| The problem says | It's probably |
| --- | --- |
| connect everything, at minimum **total** cost | an MST |
| every node must be reachable, directly or indirectly | an MST (or a spanning forest) |
| return −1 if it can't be done | an MST with a connectivity check |
| the shortest or cheapest route **from A to B** | shortest paths, not an MST |
| minimise the **largest** single step between A and B | a bottleneck path: an MST works |

The words "total" and "every" point to an MST. A single source or a single pair points to [Dijkstra's algorithm](/dsa/learn/sp-dijkstra).

## Connect all points

You're given points on a grid. Joining two points with a wire costs their **Manhattan distance**, |x₁ − x₂| + |y₁ − y₂|. What's the cheapest way to connect them all?

Every pair of points can be joined, so this is a **complete graph**: n points give n(n − 1) / 2 possible edges. Kruskal would build them all and sort them: about 2 million edges for 2,000 points, O(n² log n) time and O(n²) memory. The array version of Prim from [Prim's algorithm](/dsa/learn/mst-prim) is the right tool. It's O(n²), the best possible when there are n² edges, and it computes each distance only when it needs it, so it uses O(n) memory:

```swift run
/// The cheapest way to wire every point together, where a wire costs the Manhattan distance.
/// O(n²) Prim that computes each distance when it needs it: no edge list at all.
func connectAll(_ points: [(x: Int, y: Int)]) -> Int {
    let n = points.count
    var inTree = Array(repeating: false, count: n)
    var cheapest = Array(repeating: Int.max, count: n)
    cheapest[0] = 0
    var total = 0
    for _ in 0..<n {
        var next = -1
        for v in 0..<n where !inTree[v] && (next == -1 || cheapest[v] < cheapest[next]) {
            next = v
        }
        inTree[next] = true
        total += cheapest[next]
        for v in 0..<n where !inTree[v] {
            let distance = abs(points[v].x - points[next].x) + abs(points[v].y - points[next].y)
            cheapest[v] = min(cheapest[v], distance)
        }
    }
    return total
}

let lamps = [(x: 1, y: 1), (x: 4, y: 1), (x: 4, y: 5), (x: 0, y: 6), (x: 8, y: 3)]
print("cheapest wiring:", connectAll(lamps))
for n in [5, 2_000] {
    print("\(n) points: Kruskal would build \(n * (n - 1) / 2) edges; this keeps \(n) numbers")
}
```

```output
cheapest wiring: 18
5 points: Kruskal would build 10 edges; this keeps 5 numbers
2000 points: Kruskal would build 1999000 edges; this keeps 2000 numbers
```

The tree uses the wires of length 3, 4, 5 and 6. Notice there's no "unreachable" check: in a complete graph every point can always be reached.

In an interview, say why you chose this version: "The graph is complete, so E is about n². Array Prim is O(n²) with no edge list, which beats sorting n² edges."

## Connect the cities, or report that you can't

The other common shape gives you an **explicit** list of possible connections, each with a cost, and asks for the cheapest network, or −1 if some city can't be reached. The graph is usually sparse, and it arrives as an edge list, so Kruskal from [Kruskal's algorithm](/dsa/learn/mst-kruskal) fits directly: sort, union, and count the edges taken. Fewer than n − 1 means −1. That's the practice problem **The cheapest cable network**.

## The virtual vertex trick

Some problems mix two kinds of cost. Each house can **dig its own well** at some cost, or be **piped** to another house that already has water. What's the cheapest way to get water to every house?

There's no MST here yet: a house with a well needs no pipe at all. The trick is to add one **virtual vertex**, 0, standing for the ground water. Digging a well at house i becomes an edge 0–i whose weight is the well's cost. Now every house must be connected to vertex 0, through pipes or directly, and the cheapest way to do that is an MST on n + 1 vertices.

```swift run
// The UnionFind from M45
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]

    init(count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA
        size[rootA] += size[rootB]
        return true
    }
}

/// Houses 1...n. Each can dig its own well, or be piped to another house that has water.
func cheapestWater(wellCost: [Int], pipes: [(Int, Int, Int)]) -> Int {
    let n = wellCost.count
    // Vertex 0 is the ground water: digging a well at house i is an edge 0–i
    var edges = pipes
    for house in 1...n {
        edges.append((0, house, wellCost[house - 1]))
    }
    var sets = UnionFind(count: n + 1)
    var total = 0
    for (a, b, cost) in edges.sorted(by: { $0.2 < $1.2 }) where sets.union(a, b) {
        print(a == 0 ? "dig a well at house \(b): \(cost)" : "pipe \(a)–\(b): \(cost)")
        total += cost
    }
    return total
}

print("total:", cheapestWater(wellCost: [5, 4, 6, 9], pipes: [(1, 2, 2), (2, 3, 3), (3, 4, 7), (1, 4, 8)]))
```

```output
pipe 1–2: 2
pipe 2–3: 3
dig a well at house 2: 4
pipe 3–4: 7
total: 16
```

One well, at the house where digging is cheapest, feeds houses 1 to 3 through pipes, and the 7-unit pipe to house 4 beats its own 9-unit well. The same trick handles "each city can build its own airport or connect by road", and any problem where a vertex can be served "from outside" at a price.

## Bottleneck paths

An MST has a bonus property. For any two vertices, the path between them **in the MST** has the smallest possible **largest edge** of any path between them in the graph. This is called a **minimum bottleneck path**.

That gives a second way to solve problems like "Path with minimum effort" from [Network delay, cheapest flights and minimum effort](/dsa/learn/sp-problems), where a path's cost is its single worst step. Run Kruskal, but stop as soon as the start and the end are connected. The edge that connected them is the answer:

```swift
var sets = UnionFind(count: vertexCount)
for edge in edges.sorted(by: { $0.weight < $1.weight }) {
    sets.union(edge.from, edge.to)
    if sets.connected(start, end) {
        return edge.weight            // the smallest possible worst step
    }
}
```

On this module's graph, A and F become connected when BD (5) is added, so the best possible worst step from A to F is 5, along A–C–B–D–E–F. A modified Dijkstra gets the same answer; Kruskal is often shorter to write.

## Which edges does every MST need?

An advanced follow-up, and the hard practice problem: classify each edge.

- **Critical:** every MST uses it. Removing it makes the best spanning tree heavier, or impossible.
- **Pseudo-critical:** some MSTs use it, but not all.
- **Neither:** no MST uses it.

On this module's graph all the weights are distinct, so the MST is unique: its five edges are critical, and AB, CE and DF are neither. On the square from [Spanning trees and the cut property](/dsa/learn/mst-definition), with four sides of weight 1 and a diagonal of weight 2, every side is pseudo-critical: each of the four MSTs leaves out a different side. A **bridge**, an edge whose removal disconnects the graph, is always critical, however heavy it is.

A direct method uses Kruskal as a tool. Find the MST weight once. Then for each edge:

1. Run Kruskal **without** it. If the result is heavier, or the graph falls apart, the edge is critical.
2. Otherwise, run Kruskal with the edge **forced in first**. If the result still has the minimum weight, some MST uses it: it's pseudo-critical. If not, it's neither.

Sort the edges once and reuse the order, and each test is one near-linear pass: O(E² α(V)) in total, fine for a few hundred edges. A faster O(E log E) method processes equal-weight edges as a group and looks for bridges among them, with the technique from [Bridges and articulation points](/dsa/learn/ag-bridges).

<Callout kind="tip" title="An interview checklist for MST problems">
- Say why it's an MST: "connect everything at minimum total cost".
- Ask whether the graph is guaranteed to be connected, and what to return if it isn't.
- Choose: an edge list or a sparse graph means Kruskal; a complete or dense graph means array Prim.
- If some vertices can be served "on their own" at a cost, add a virtual vertex.
- State the cost: O(E log E) for Kruskal, O(V²) for array Prim.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **Building all n² edges for points.** It works for small inputs, but costs O(n²) memory and a big sort. Array Prim avoids both.
- **Euclidean distances as floating point.** If the cost is straight-line distance, compare squared distances while choosing, or accept small rounding in the total. Manhattan distances stay as integers.
- **Forgetting the virtual vertex in the count.** With n houses plus the ground water there are n + 1 vertices, so the tree has n edges.
</Callout>

## Practice

**Connect every point** is the first section, up to 2,000 points. **The cheapest cable network** is the second, with −1 for impossible networks. **Critical and optional links** is the last section, checked against a brute force that lists every spanning tree.

- id: mstp-virtual

  front: "What extra property do MST paths have?"
