## Why it matters

A health app shows your average steps over the last 7 days. A video player watches the average frame time over the last 60 frames, so it can tell when the app starts to stutter. Both look at a **window**: a fixed number of neighbouring values that moves along as new values arrive. In DSA, any question about "k consecutive elements" is a window question, and the trick in this lesson turns an O(n · k) brute force into a single O(n) pass. It's the first of the sliding window patterns that fill this module.

## Windows: k neighbours at a time

A **window** of size k is a stretch of k neighbouring elements, `items[start..<start + k]`. In an array of n elements there are n − k + 1 of them: the first starts at index 0, the last at index n − k.

```swift run
let items = [2, 1, 5, 1, 3, 2]
let k = 3
for start in 0...(items.count - k) {
    let window = Array(items[start..<start + k])
    print(start, window, window.reduce(0, +))
}
```

```output
0 [2, 1, 5] 8
1 [1, 5, 1] 7
2 [5, 1, 3] 9
3 [1, 3, 2] 6
```

Six elements and windows of three give 6 − 3 + 1 = 4 windows. The largest sum is 9, from `[5, 1, 3]`. Windows are always **contiguous**: no gaps, no skipping. ([Subarray vs subsequence vs subset](/dsa/learn/arrays-sub-definitions) has the vocabulary.)

## The brute force adds too much

The obvious way to find the largest window sum is the loop above: build each window's sum from scratch. Each window costs k additions, and there are n − k + 1 windows, so the total is about n · k. Count them:

```swift run
func maxWindowSumBrute(_ items: [Int], _ k: Int) -> (best: Int, additions: Int) {
    var best = Int.min
    var additions = 0
    for start in 0...(items.count - k) {
        var sum = 0
        for index in start..<start + k {
            sum += items[index]
            additions += 1
        }
        best = max(best, sum)
    }
    return (best, additions)
}

let numbers = (0..<10_000).map { ($0 * 37) % 101 }
let result = maxWindowSumBrute(numbers, 1_000)
print(result.best, result.additions)
```

```output
50080 9001000
```

Nine million additions for ten thousand numbers. With k = n/2 the cost is about n²/4: quadratic.

## Slide instead of starting again

Look at two neighbouring windows: `[2, 1, 5]` and `[1, 5, 1]`. They share `1, 5`. Moving one step to the right only changes two things: the 2 **leaves** on the left and a 1 **enters** on the right. So the new sum is the old sum, minus the leaving element, plus the entering one:

> next sum = sum − items[right − k] + items[right]

That's two operations per step, whatever k is. Only the first window needs to be added up in full.

```swift run
func maxWindowSum(_ items: [Int], _ k: Int) -> (best: Int, operations: Int) {
    var windowSum = 0
    var operations = 0
    for index in 0..<k {
        windowSum += items[index]
        operations += 1
    }
    var best = windowSum
    for right in k..<items.count {
        windowSum += items[right] - items[right - k]   // one in, one out
        operations += 2
        best = max(best, windowSum)
    }
    return (best, operations)
}

let numbers = (0..<10_000).map { ($0 * 37) % 101 }
let result = maxWindowSum(numbers, 1_000)
print(result.best, result.operations)
```

```output
50080 19000
```

The same answer with 19,000 operations instead of 9 million: k for the first window, then 2 for each of the remaining n − k steps. That's **O(n)**, and O(1) extra space.

<Callout kind="analogy">
Think of a train of k carriages rolling along a platform of numbered tiles. To know which tiles are under the train, you don't re-read the whole train at every step. One tile appears under the front carriage, and one is freed behind the last.
</Callout>

## One loop, no off-by-one errors

The two-loop version above works, but it has two places to get an index wrong. A single loop over `right`, the index of the element entering, does everything:

| Question | Answer |
| --- | --- |
| Which element enters? | `items[right]` |
| Which element leaves? | `items[right - k]`, once `right ≥ k` |
| Where does the window start? | `right - k + 1` |
| When is the first window full? | when `right == k - 1` |

```swift run
func windowSums(_ items: [Int], _ k: Int) -> [Int] {
    var sums: [Int] = []
    var windowSum = 0
    for right in 0..<items.count {
        windowSum += items[right]             // entering
        if right >= k {
            windowSum -= items[right - k]     // leaving
        }
        if right >= k - 1 {
            sums.append(windowSum)            // a full window ends at right
        }
    }
    return sums
}

print(windowSums([2, 1, 5, 1, 3, 2], 3))
print(windowSums([4, 4], 3))
```

```output
[8, 7, 9, 6]
[]
```

What to notice:

- **Add, remove, record**, in that order, on every pass. You'll see this shape again and again.
- When k is bigger than the array, no window is ever full, so the result is empty. There's no slice that could go out of range.

## Averages and counts

The same idea works for anything you can **undo**. A moving average is a window sum divided by k. Keep the sum as an `Int` and divide only when you need the average:

```swift run
let temperatures = [10, 12, 9, 13, 16, 14, 11]
let k = 4
var windowSum = 0
var averages: [Double] = []
for right in 0..<temperatures.count {
    windowSum += temperatures[right]
    if right >= k {
        windowSum -= temperatures[right - k]
    }
    if right >= k - 1 {
        averages.append(Double(windowSum) / Double(k))
    }
}
print(averages)
```

```output
[11.0, 12.5, 13.0, 13.5]
```

Counting works the same way: a counter goes up when a matching element enters and down when one leaves. Here's the most vowels in any 4 letters in a row:

```swift run
func maxVowels(in text: String, k: Int) -> Int {
    let chars = Array(text)
    let vowels: Set<Character> = ["a", "e", "i", "o", "u"]
    var count = 0
    var best = 0
    for right in 0..<chars.count {
        if vowels.contains(chars[right]) {
            count += 1
        }
        if right >= k && vowels.contains(chars[right - k]) {
            count -= 1
        }
        if right >= k - 1 {
            best = max(best, count)
        }
    }
    return best
}

print(maxVowels(in: "beautifulday", k: 4))
print(maxVowels(in: "rhythm", k: 3))
```

```output
3
0
```

As M08 taught, the string becomes an array first, so `chars[right - k]` is O(1).

## What a window can't undo: the maximum

Sums and counts slide cheaply because subtraction undoes addition. The **largest** value in each window is different. When the largest element leaves, what's the new largest? Nothing you've stored tells you, so you'd rescan the window: O(k) per step, and O(n · k) in all.

There is an O(n) way, using a double-ended queue that keeps only the elements that could still become the maximum. You'll build it in M27, Queues and deques.

<Callout kind="gotcha" title="Swift gotcha: slices and division">
- `items[0..<k]` traps if `k` is bigger than `items.count`. Check first, or use the single-loop shape, which never slices.
- `windowSum / k` on `Int` values drops the fraction: `7 / 2` is `3`. Convert first: `Double(windowSum) / Double(k)`.
- To find the best **average**, compare the **sums**. All windows have the same k, so the largest sum has the largest average, and integer comparisons are exact.
</Callout>
