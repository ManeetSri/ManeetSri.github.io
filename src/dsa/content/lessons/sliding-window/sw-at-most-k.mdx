## Why it matters

The windows so far found **one** best stretch: the longest, the shortest. Another family of problems asks you to **count** stretches: how many subarrays have exactly k different values, or exactly k odd numbers, or a sum of exactly S. An analytics dashboard counting browsing sessions that touched exactly three different pages is the same question. "Exactly" turns out to be awkward for a window, but "at most" is easy, and one subtraction connects them. It's a short trick with a big payoff in hard interview questions.

## Counting windows instead of measuring them

Start with the easy version: count the subarrays of `values` with **at most** k distinct values.

Run the usual longest-window loop: grow on the right, and shrink from the left while there are more than k distinct values. After the shrink, `values[left...right]` is the **longest** valid subarray ending at `right`. Every shorter subarray ending at `right` sits inside it, so it's valid too: fewer elements can't mean more distinct values. Those subarrays start at `left`, `left + 1`, …, `right`, so there are **right − left + 1** of them.

```swift run
func countAtMost(_ values: [Int], _ k: Int) -> Int {
    var counts: [Int: Int] = [:]
    var left = 0
    var total = 0
    for right in 0..<values.count {
        counts[values[right], default: 0] += 1
        while counts.count > k {
            let leaving = values[left]
            counts[leaving, default: 0] -= 1
            if counts[leaving] == 0 {
                counts[leaving] = nil          // so counts.count is the number of distinct values
            }
            left += 1
        }
        print("right \(right): starts \(left)...\(right) work, adding \(right - left + 1)")
        total += right - left + 1
    }
    return total
}

print(countAtMost([1, 2, 1, 3], 2))
```

```output
right 0: starts 0...0 work, adding 1
right 1: starts 0...1 work, adding 2
right 2: starts 0...2 work, adding 3
right 3: starts 2...3 work, adding 2
8
```

When `3` arrives, the window `[1, 2, 1, 3]` has three distinct values, so it drops `1` and `2` from the left until only `[1, 3]` is left. Every subarray is counted once, by its right end.

Setting a count to `nil` removes the key, as M07 showed, so `counts.count` stays equal to the number of distinct values in the window.

## Why "exactly" breaks the window

Now try **exactly** k = 2 distinct values in `[4, 4, 7, 4, 9]`. Fix the right end at the `9` (index 4) and look at every start:

| start | subarray | distinct | exactly 2? |
| --- | --- | --- | --- |
| 0 | `[4, 4, 7, 4, 9]` | 3 | no |
| 1 | `[4, 7, 4, 9]` | 3 | no |
| 2 | `[7, 4, 9]` | 3 | no |
| 3 | `[4, 9]` | 2 | yes |
| 4 | `[9]` | 1 | no |

Start too far left and there are too many values; start too far right and there are too few. The good starts form a range **in the middle**, bounded on both sides. A window has one `left` pointer, which can mark one boundary, not two. "At most k" works because its good starts run all the way to `right`.

## The subtraction trick

Every subarray with at most k distinct values has either exactly k, or at most k − 1. So:

> exactly(k) = atMost(k) − atMost(k − 1)

Two easy windows, one subtraction:

```swift run
func atMost(_ values: [Int], _ k: Int) -> Int {
    guard k > 0 else { return 0 }
    var counts: [Int: Int] = [:]
    var left = 0
    var total = 0
    for right in 0..<values.count {
        counts[values[right], default: 0] += 1
        while counts.count > k {
            let leaving = values[left]
            counts[leaving, default: 0] -= 1
            if counts[leaving] == 0 {
                counts[leaving] = nil
            }
            left += 1
        }
        total += right - left + 1
    }
    return total
}

func exactly(_ values: [Int], _ k: Int) -> Int {
    atMost(values, k) - atMost(values, k - 1)
}

func exactlyBrute(_ values: [Int], _ k: Int) -> Int {
    var total = 0
    for start in values.indices {
        var seen = Set<Int>()
        for end in start..<values.count {
            seen.insert(values[end])
            if seen.count == k {
                total += 1
            }
        }
    }
    return total
}

let values = [4, 4, 7, 4, 9]
print(atMost(values, 2), atMost(values, 1), exactly(values, 2))
print(exactlyBrute(values, 2))
print(exactly([5, 5, 5], 1), exactly([1, 2, 3], 4))
```

```output
12 6 6
6
6 0
```

Of the 15 subarrays of `[4, 4, 7, 4, 9]`, 12 have at most two distinct values and 6 have at most one, so 6 have exactly two. The brute force agrees.

Each `atMost` call is one O(n) window pass, so `exactly` is **O(n)** time, plus O(k) space for the dictionary.

## The same trick for sums and odd numbers

The trick works whenever "at most" is a valid window, which means whenever the rule is monotonic. Counting subarrays of a 0/1 array whose sum is exactly S is the same idea with a sum instead of a dictionary:

```swift run
func sumAtMost(_ bits: [Int], _ limit: Int) -> Int {
    guard limit >= 0 else { return 0 }
    var left = 0
    var sum = 0
    var total = 0
    for right in 0..<bits.count {
        sum += bits[right]
        while sum > limit {
            sum -= bits[left]
            left += 1
        }
        total += right - left + 1
    }
    return total
}

func sumExactly(_ bits: [Int], _ target: Int) -> Int {
    sumAtMost(bits, target) - sumAtMost(bits, target - 1)
}

print(sumExactly([1, 0, 1, 0, 1], 2))
print(sumExactly([0, 0, 0], 0))

// Exactly k odd numbers: turn each number into 1 if odd, 0 if even
let numbers = [3, 8, 5, 6, 7, 2]
print(sumExactly(numbers.map { $0 % 2 == 0 ? 0 : 1 }, 2))
```

```output
4
6
6
```

The last one asks how many subarrays of `[3, 8, 5, 6, 7, 2]` contain exactly two odd numbers. Mapping each number to 1 (odd) or 0 (even) turns it into a sum question.

The `guard limit >= 0` matters. With a target of 0, the second call asks for sums of at most −1. No window qualifies, but without the guard the shrink loop would keep going after the window is empty, because `0 > -1` stays true, and `left` would run off the end of the array.

<Callout kind="note" title="Another route for sums">
For "subarrays with sum exactly S", prefix sums with a dictionary, from [Prefix sum + hashmap: subarray sum equals k](/dsa/learn/prefix-hashmap), also work, and they handle negative numbers, which the window can't. The at-most trick shines for rules like "distinct values" that prefix sums can't express.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **Leaving zero counts in the dictionary.** `counts.count` would include values that have left the window. Remove a key when its count reaches 0.
- **No guard for impossible limits.** `atMost(k - 1)` with k = 0, or a sum limit of −1, must return 0 straight away, not run a window that can never be valid.
- **Adding 1 per valid window instead of `right - left + 1`.** Each step counts *every* valid subarray ending at `right`, not only the longest.
</Callout>
