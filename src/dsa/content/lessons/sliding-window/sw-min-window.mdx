## Why it matters

When a search engine shows a snippet under a result, it often picks the shortest passage of the page that contains all your search words. That's the **minimum window substring** problem: the shortest stretch of a text that contains every character of a pattern, with repeats. It's the classic "hard" sliding window question, and it needs everything this module has built so far: a variable window that finds the **shortest** valid stretch, and **counts** of what's inside it, with a counter that keeps the validity check O(1).

## The problem

Given `text` and `pattern`, find the shortest substring of `text` that **covers** `pattern`: for every character, the window holds at least as many copies as the pattern does. If several windows are equally short, return the leftmost; if none exists, return `""`.

| `text` | `pattern` | Answer |
| --- | --- | --- |
| `"BANANABREAD"` | `"ABD"` | `"BREAD"` |
| `"xaybzaxb"` | `"aab"` | `"aybza"` |
| `"a"` | `"A"` | `""` |

In the second example the window needs **two** `a`s and a `b`. Case matters: `A` and `a` are different characters.

## Covering is monotonic

Before writing code, check that a window can work at all. It can, because covering behaves like a sum of positive numbers:

- If `text[left...right]` covers the pattern, so does every bigger window containing it. Adding characters never removes copies.
- If it doesn't cover the pattern, neither does any smaller window inside it.

That's the monotonic property from [Minimum size subarray sum](/dsa/learn/sw-min-size-subarray), so the same shape applies: **grow** on the right until the window covers the pattern, then **shrink** from the left for as long as it still does, recording each window on the way.

The only new part is checking "does it cover?" quickly. Comparing every count on every step would cost O(alphabet) per step. Instead, keep a counter, as with `matches` in the last lesson.

## Counting satisfied characters

Keep three things, using 128-slot arrays because the input is ASCII letters:

- `need[c]`: how many copies of `c` the pattern has. Fixed.
- `have[c]`: how many copies of `c` the window has.
- `satisfied`: how many **distinct** pattern characters have `have[c] ≥ need[c]`.

The window covers the pattern when `satisfied` equals `required`, the number of distinct characters in the pattern. Because `have[c]` only ever changes by one, a character becomes satisfied exactly when `have[c]` rises **to** `need[c]`, and stops being satisfied exactly when it falls from `need[c]` to one below. Those two moments are the only times `satisfied` changes.

```swift run
func minWindow(_ text: String, _ pattern: String) -> String {
    let t = Array(text.utf8)
    let p = Array(pattern.utf8)
    guard !p.isEmpty else { return "" }
    var need = [Int](repeating: 0, count: 128)
    for byte in p {
        need[Int(byte)] += 1
    }
    let required = need.filter { $0 > 0 }.count   // distinct characters to cover
    var have = [Int](repeating: 0, count: 128)
    var satisfied = 0
    var left = 0
    var bestStart = 0
    var bestLength = Int.max
    for right in 0..<t.count {
        let entering = Int(t[right])
        have[entering] += 1
        if need[entering] > 0 && have[entering] == need[entering] {
            satisfied += 1                         // reached exactly what's needed
        }
        while satisfied == required {
            if right - left + 1 < bestLength {
                bestLength = right - left + 1
                bestStart = left
            }
            let leaving = Int(t[left])
            if need[leaving] > 0 && have[leaving] == need[leaving] {
                satisfied -= 1                     // about to drop below what's needed
            }
            have[leaving] -= 1
            left += 1
        }
    }
    guard bestLength != Int.max else { return "" }
    return String(decoding: t[bestStart..<bestStart + bestLength], as: UTF8.self)
}

print(minWindow("BANANABREAD", "ABD"))
print(minWindow("xaybzaxb", "aab"))
print(minWindow("a", "A").isEmpty)
```

```output
BREAD
aybza
true
```

Characters the pattern doesn't use, like `N` and `R` here, are still counted in `have`, but `need` is 0 for them, so they never touch `satisfied`.

### Watching it work

Here's every window the shrink loop records for `"BANANABREAD"`, with the best so far:

```swift run

    have[entering] += 1
    if need[entering] > 0 && have[entering] == need[entering] {
        satisfied += 1
    }
    while satisfied == required {
        bestLength = min(bestLength, right - left + 1)
        print(String(decoding: t[left...right], as: UTF8.self), "best", bestLength)
        let leaving = Int(t[left])
        if need[leaving] > 0 && have[leaving] == need[leaving] {
            satisfied -= 1
        }
        have[leaving] -= 1
        left += 1
    }
}
```

```output
BANANABREAD best 11
ANANABREAD best 10
NANABREAD best 9
ANABREAD best 8
NABREAD best 7
ABREAD best 6
BREAD best 5
```

The only `D` is the last character, so nothing covers the pattern until `right` reaches it. Then the window squeezes in from the left. Dropping the first `B` is fine, because another `B` is still inside; the `A`s and `N`s go too. When the window is `"BREAD"`, dropping its `B` would leave no `B`, so `satisfied` falls and the shrinking stops.

## Remember positions, build once

Notice that the function records `bestStart` and `bestLength`, not the substring itself. Building a `String` every time a better window turns up would copy up to n characters each time: O(n²) in the worst case. Two integers cost nothing to update, and the one `String(decoding:as:)` at the end is O(answer length).

And because only a **strictly** shorter window replaces the best, the first of several equally short windows is the one that's kept. That's the "leftmost" rule, for free.

## A leaner version: one array and a missing counter

There's a compact form you'll often see. Use a single array where `need[c]` starts as the pattern's count and **goes down** as the window takes copies of `c`. It can go negative, meaning the window has spares. And keep `missing`: how many pattern characters, counting repeats, the window still lacks.

- A character enters: if `need[c] > 0`, it was still wanted, so `missing -= 1`. Then `need[c] -= 1`.
- A character leaves: `need[c] += 1`. If now `need[c] > 0`, the window has lost a copy it needed, so `missing += 1`.

```swift run
func minWindow(_ text: String, _ pattern: String) -> String {
    let t = Array(text.utf8)
    let p = Array(pattern.utf8)
    guard !p.isEmpty, p.count <= t.count else { return "" }
    var need = [Int](repeating: 0, count: 128)
    for byte in p {
        need[Int(byte)] += 1
    }
    var missing = p.count
    var left = 0
    var bestStart = 0
    var bestLength = Int.max
    for right in 0..<t.count {
        let entering = Int(t[right])
        if need[entering] > 0 {
            missing -= 1
        }
        need[entering] -= 1
        while missing == 0 {
            if right - left + 1 < bestLength {
                bestLength = right - left + 1
                bestStart = left
            }
            let leaving = Int(t[left])
            need[leaving] += 1
            if need[leaving] > 0 {
                missing += 1
            }
            left += 1
        }
    }
    guard bestLength != Int.max else { return "" }
    return String(decoding: t[bestStart..<bestStart + bestLength], as: UTF8.self)
}

print(minWindow("SWIFTLYSWIFT", "WIT"))
print(minWindow("helloworld", "lol"))
print(minWindow("abc", "d").isEmpty)
```

```output
WIFT
llo
true
```

It does exactly the same job with one array instead of two. The first version is easier to reason about; the second is shorter. Both are correct, so write whichever you can explain.

## How fast is it?

- **Time: O(n + m).** Counting the pattern is O(m). In the main loop, `right` moves n times and `left` at most n times, each move O(1).
- **Space: O(1)** extra, besides the byte arrays: 128 counters, whatever the input size.

For text that isn't ASCII, swap the arrays for `[Character: Int]` dictionaries and `Array(text)`. The logic doesn't change; each step becomes O(1) on average instead of always.

<Callout kind="gotcha" title="Common mistakes">
- **Counting a character as satisfied on every copy.** Update `satisfied` only when `have[c]` hits `need[c]` exactly. Testing `have[c] >= need[c]` would add one for every extra copy, and the window would think it's complete too early.
- **Shrinking with `if`.** After the window first covers the pattern, it can usually lose several characters from the left. Use `while`.
- **Recording after removing.** Record the window first, then remove `t[left]`; the removal may break it.
- **Building the answer inside the loop.** Keep a start and a length, and make the `String` once at the end.
</Callout>
