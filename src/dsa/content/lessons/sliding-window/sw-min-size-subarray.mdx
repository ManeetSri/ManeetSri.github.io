## Why it matters

"What's the fewest consecutive days it took to save £500?" "What's the shortest stretch of a workout that burned 300 calories?" These ask for the **shortest** window that reaches a goal. It's the mirror image of the last lesson's longest window, and it brings out the condition that every variable window depends on: growing the window must always push it one way, and shrinking it the other. For sums, that means the numbers must be positive, and seeing why is as useful as the algorithm itself.

## The problem

Given an array of **positive** integers and a `target`, find the length of the shortest contiguous stretch whose sum is at least `target`. If no stretch gets there, the answer is 0.

For `[1, 4, 2, 2, 3, 1, 5]` and a target of 8, the answer is 3: `4 + 2 + 2 = 8`. No two neighbours reach 8.

Checking every start and every end is O(n²). A window does it in one pass.

## Grow until it's enough, then shrink while it still is

The plan has two moves:

1. **Grow:** move `right` forward and add the new value to the sum.
2. **Shrink:** while the sum is at least `target`, the window is a candidate. Record its length, then drop `items[left]` and move `left` forward, to see whether a shorter window still works.

```swift run
func shortestWindow(_ items: [Int], atLeast target: Int) -> Int {
    var left = 0
    var sum = 0
    var best = Int.max
    for right in 0..<items.count {
        sum += items[right]
        while sum >= target {
            best = min(best, right - left + 1)
            sum -= items[left]
            left += 1
        }
    }
    return best == Int.max ? 0 : best
}

print(shortestWindow([1, 4, 2, 2, 3, 1, 5], atLeast: 8))
print(shortestWindow([5, 1, 3, 5, 10, 7, 4, 9, 2, 8], atLeast: 15))
print(shortestWindow([1, 1, 1], atLeast: 10))
```

```output
3
2
0
```

`Int.max` stands for "nothing found yet", since no real length can be that big. The last line turns it into the 0 the problem asks for.

Watch it run. The window stretches right until its sum reaches 8, then squeezes in from the left as far as it can:

Here's every window the loop records, to see the pattern in text:

```swift run
let items = [1, 4, 2, 2, 3, 1, 5]
let target = 8
var left = 0
var sum = 0
for right in 0..<items.count {
    sum += items[right]
    while sum >= target {
        print("[\(left)...\(right)] sum \(sum), length \(right - left + 1)")
        sum -= items[left]
        left += 1
    }
}
```

```output
[0...3] sum 9, length 4
[1...3] sum 8, length 3
[2...5] sum 8, length 4
[3...6] sum 11, length 4
[4...6] sum 9, length 3
```

Both `left` and `right` only move forward, so the loop does at most 2n steps: **O(n)** time and O(1) space.

## Where you record decides what you find

Compare this with the last lesson. The two loops look alike, but they record at different moments:

| Looking for | Shrink while… | Record… |
| --- | --- | --- |
| the **longest** valid window | the window is **invalid** | after the shrinking, when it's valid again |
| the **shortest** valid window | the window is **valid** | inside the shrinking, before each removal |

For the longest, you want the window as big as it can be while staying valid. For the shortest, every valid window is a candidate, and you squeeze it to find the smallest.

## Why the numbers must be positive

The window throws possibilities away without checking them. Two facts make that safe, and both rely on every value being positive:

- **Adding a value raises the sum.** So once `[left...right]` reaches the target, extending it further only makes it longer. Nothing better starts at `left`, and `left` can move on.
- **Removing a value lowers the sum.** So if `[left...right]` is below the target, every shorter window ending at `right` is below it too. There's no need to try them.

This property, that growing always helps and shrinking always hurts, is called **monotonicity**. Break it with a negative number and the window gives the wrong answer:

```swift run
func shortestWindow(_ items: [Int], atLeast target: Int) -> Int {
    var left = 0
    var sum = 0
    var best = Int.max
    for right in 0..<items.count {
        sum += items[right]
        while sum >= target {
            best = min(best, right - left + 1)
            sum -= items[left]
            left += 1
        }
    }
    return best == Int.max ? 0 : best
}

func shortestBrute(_ items: [Int], atLeast target: Int) -> Int {
    var best = 0
    for start in items.indices {
        var sum = 0
        for end in start..<items.count {
            sum += items[end]
            if sum >= target && (best == 0 || end - start + 1 < best) {
                best = end - start + 1
            }
        }
    }
    return best
}

print(shortestWindow([1, -5, 6], atLeast: 6))
print(shortestBrute([1, -5, 6], atLeast: 6))
```

```output
0
1
```

The window's sum goes 1, then −4, then 2: never 6, so it never shrinks. But dropping the first two values would *raise* the sum to 6. With negatives, shrinking can help, and the window's reasoning collapses.

Zeros are fine, though: with non-negative values, growing never lowers the sum and shrinking never raises it, which is all the argument needs.

<Callout kind="note" title="When the numbers can be negative">
For "sum exactly k" with any signs, use prefix sums and a dictionary, from [Prefix sum + hashmap: subarray sum equals k](/dsa/learn/prefix-hashmap). For "shortest with sum at least k" with negatives, the answer combines prefix sums with a monotonic deque, which you'll meet in M27.
</Callout>

## The mirror problem: longest within a budget

Flip the question: the longest stretch of days whose spending stays **at most** a budget. Now the window is valid while the sum is small, so you shrink while it's too big and record afterwards, the longest-window shape:

```swift run
func longestWithinBudget(_ costs: [Int], budget: Int) -> Int {
    var left = 0
    var sum = 0
    var best = 0
    for right in 0..<costs.count {
        sum += costs[right]
        while sum > budget {
            sum -= costs[left]
            left += 1
        }
        best = max(best, right - left + 1)
    }
    return best
}

print(longestWithinBudget([3, 1, 2, 7, 1, 1, 2], budget: 5))
print(longestWithinBudget([9, 9], budget: 5))
```

```output
3
0
```

When a single cost is bigger than the whole budget, like the 7 or the 9s, the window shrinks until it's empty: `left` ends one past `right`, and `right - left + 1` is 0. That's correct, and no special case is needed.

<Callout kind="gotcha" title="Common mistakes">
- **Using `if` instead of `while` for the shrink.** One removal may not be enough: after adding a big value, the window can often lose several from the left and still reach the target.
- **Starting `best` at 0 for a minimum.** `min(0, length)` is always 0. Start at `Int.max` (or `items.count + 1`) and convert at the end.
- **Using the window on negative numbers.** Check the constraints first. If values can be negative, a sum window isn't monotonic.
</Callout>
