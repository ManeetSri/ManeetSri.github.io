## Why it matters

So far each window has tracked one number: a sum or a length. Many windows need to know **what's inside** them instead: which letters, and how many of each. Word games check whether a run of tiles spells a rearrangement of a word; DNA tools look for a stretch with a given mix of bases. The classic interview version is **permutation in string**: does a text contain some rearrangement of a pattern as a contiguous piece? It combines a fixed-size window with the 26-slot counts from M08, plus one new idea, a counter that makes comparing counts O(1).

## The problem

Given `pattern` and `text`, both made of lowercase letters, decide whether some stretch of `text` is an **anagram** (a rearrangement, or permutation) of `pattern`: the same letters, the same number of times, in any order.

`"whatspot"` contains an anagram of `"tops"`, in fact two: `"tspo"` and, one step later, `"spot"`. `"stoop"` doesn't: its windows of four are `"stoo"` and `"toop"`, and neither has a `p` *and* only one `o`.

An anagram of the pattern has exactly the pattern's length, m. So this is a **fixed-size window** of length m sliding along the text.

## Brute force: sort every window

Two strings are anagrams when their sorted letters are equal. Sort the pattern once, then sort each window and compare:

```swift run
func containsAnagramBrute(_ pattern: String, in text: String) -> Bool {
    let p = Array(pattern).sorted()
    let t = Array(text)
    guard p.count <= t.count else { return false }
    for start in 0...(t.count - p.count) {
        if t[start..<start + p.count].sorted() == p {
            return true
        }
    }
    return false
}

print(containsAnagramBrute("tops", in: "whatspot"))
print(containsAnagramBrute("tops", in: "stoop"))
```

```output
true
false
```

Each window costs a sort, O(m log m), so the whole search is O(n · m log m). With a pattern of 50,000 letters, that's hopeless.

## Counts can slide

From [Frequency counting with 26 slots](/dsa/learn/swift-frequency-arrays): two words are anagrams exactly when their 26-slot letter counts are equal. Keep `need`, the pattern's counts, and `have`, the current window's counts.

When the window slides one step, only **two** counts change: the entering letter's goes up by one, the leaving letter's goes down by one. There's no need to recount the window.

```swift run
func containsAnagram(_ pattern: String, in text: String) -> Bool {
    let p = Array(pattern.utf8)
    let t = Array(text.utf8)
    let m = p.count
    guard m <= t.count else { return false }
    let a = UInt8(ascii: "a")
    var need = [Int](repeating: 0, count: 26)
    var have = [Int](repeating: 0, count: 26)
    for byte in p {
        need[Int(byte - a)] += 1
    }
    for right in 0..<t.count {
        have[Int(t[right] - a)] += 1             // entering
        if right >= m {
            have[Int(t[right - m] - a)] -= 1     // leaving
        }
        if right >= m - 1 && have == need {
            return true
        }
    }
    return false
}

print(containsAnagram("tops", in: "whatspot"))
print(containsAnagram("tops", in: "stoop"))
print(containsAnagram("ab", in: "a"))
```

```output
true
false
false
```

This is the single-loop shape from [Fixed-size windows](/dsa/learn/sw-fixed): enter, leave once `right ≥ m`, check once the window is full. Each step does O(1) count updates plus one `==`, which compares 26 slots. That's O(26 · n), and since 26 is a constant, **O(n)**. For most purposes, this version is all you need.

## A matches counter: O(1) per step

Comparing 26 slots on every step is still wasted effort when only two slots changed. Keep one more number:

> `matches` is how many of the 26 slots have `have[slot] == need[slot]`.

The window is an anagram exactly when `matches == 26`. When one slot changes, only that slot's agreement can change, so you update `matches` around it:

1. **Before** the change: if the slot agreed, it's about to stop agreeing, so `matches -= 1`.
2. Change the count.
3. **After** the change: if the slot agrees now, `matches += 1`.

If the slot agreed before and after (impossible here, since the count changed) or neither, the two steps cancel out or do nothing. Doing both checks every time means you never have to think about which case you're in.

What does `matches` start at? Before any letter enters, `have` is all zeros. Every letter the pattern **doesn't** use already agrees, because both counts are 0. So `matches` starts at the number of zero slots in `need`, not at 0.

Here it is with a trace, so you can watch `matches` move:

```swift run
func anagramTrace(_ pattern: String, in text: String) {
    let p = Array(pattern.utf8)
    let t = Array(text.utf8)
    let m = p.count
    let a = UInt8(ascii: "a")
    var need = [Int](repeating: 0, count: 26)
    var have = [Int](repeating: 0, count: 26)
    for byte in p {
        need[Int(byte - a)] += 1
    }
    var matches = 0
    for slot in 0..<26 where need[slot] == 0 {
        matches += 1
    }
    print("before any letters: matches \(matches)")

    func change(_ slot: Int, by delta: Int) {
        if have[slot] == need[slot] { matches -= 1 }   // it agreed before
        have[slot] += delta
        if have[slot] == need[slot] { matches += 1 }   // it agrees now
    }

    for right in 0..<t.count {
        change(Int(t[right] - a), by: 1)
        if right >= m {
            change(Int(t[right - m] - a), by: -1)
        }
        if right >= m - 1 {
            let window = String(decoding: t[(right - m + 1)...right], as: UTF8.self)
            print(window, "matches", matches, matches == 26 ? "anagram" : "")
        }
    }
}

anagramTrace("tops", in: "whatspot")
```

```output
before any letters: matches 22
what matches 20
hats matches 22
atsp matches 24
tspo matches 26 anagram
spot matches 26 anagram
```

`"tops"` uses 4 different letters, so 22 slots agree from the start. In `"what"`, the `w`, `h` and `a` each break a zero slot (down to 19), and the `t` fixes the `t` slot (up to 20). Each of the next slides brings in a letter the pattern needs and drops one it doesn't, fixing two slots at a time, until `"tspo"` reaches 26. The last slide brings in a second `t` and drops the first, so the `t` slot stops agreeing and agrees again: still 26.

`change` is a **nested function** that captures `have`, `need` and `matches`, as in [A preview of memoisation](/dsa/learn/rec-memo-preview). It keeps the before-and-after logic in one place, so the entering and leaving updates can't drift apart.

## Which version should you write?

| Version | Time | When to use it |
| --- | --- | --- |
| Sort each window | O(n · m log m) | as a brute force for testing |
| Slide counts, compare with `==` | O(26 · n) | almost always: short and clear |
| Slide counts with `matches` | O(n + m) | when the alphabet is large, or an interviewer asks for O(1) per step |

With a bigger alphabet, say all 128 ASCII characters or a dictionary of arbitrary `Character` values, comparing everything each step gets more expensive, and the `matches` idea matters more. The next lesson uses the same idea with a twist: it counts only the characters the pattern needs.

<Callout kind="gotcha" title="Common mistakes">
- **Starting `matches` at 0.** Before the window holds anything, every slot the pattern doesn't use already agrees. Start at the number of zero slots in `need`.
- **Updating `matches` on only one side of the change.** Check before *and* after. Skipping the "before" check lets `matches` count a slot that has stopped agreeing.
- **Removing too early.** The leaving letter is `t[right - m]`, and it only exists once `right ≥ m`. Check `right ≥ m - 1` before reading the answer.
- **Byte arithmetic on the wrong input.** `byte - UInt8(ascii: "a")` is only a slot from 0 to 25 for lowercase letters. A capital letter makes it trap, because `UInt8` can't go below zero.
</Callout>
