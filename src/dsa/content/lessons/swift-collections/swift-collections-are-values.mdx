## Why it matters

In Swift, assigning an array to another variable, or passing it to a function, gives the receiver its **own** array. Change one, and the other stays exactly as it was. That sounds like a small detail, but it removes a whole family of bugs where one part of a program quietly changes data another part depends on. It also matters for algorithms: backtracking, saving snapshots of a board, and passing a grid to a helper all behave differently in Swift than in Python, Java or JavaScript.

## Assignment makes a copy

```swift run
let original = [1, 2, 3]
var copy = original
copy.append(4)
copy[0] = 100

print(original)
print(copy)
```

```output
[1, 2, 3]
[100, 2, 3, 4]
```

`var copy = original` gave `copy` its own array. Appending to it and changing its first element left `original` untouched. Types that behave like this are called **value types**: the variable holds the value itself, like an `Int` does. You'd never expect `var b = a; b += 1` to change `a` when they're numbers, and Swift arrays work the same way.

<Callout kind="note">
Many popular languages do the opposite. In Python, Java and JavaScript, `b = a` for a list makes `b` a second name for the **same** list, so appending through `b` changes `a` too. Those lists are **reference types**. If you read solutions written in those languages, remember that Swift copies where they share.
</Callout>

The same rule applies to every standard collection, and to `String`:

```swift run
var settings = ["sound": true]
let backup = settings
settings["sound"] = false
print(backup["sound"] ?? false, settings["sound"] ?? false)

let firstSet: Set = [1]
var secondSet = firstSet
secondSet.insert(2)
print(firstSet.count, secondSet.count)

let greeting = "Hello"
var shout = greeting
shout += "!"
print(greeting, shout)
```

```output
true false
1 2
Hello Hello!
```

## Functions get their own copy

When you pass an array to a function, the function receives a copy, and inside the function the parameter is a constant. So a function can't change the caller's array by accident:

```swift
func addZero(_ numbers: [Int]) {
    numbers.append(0)
}
```

```text title="What you'll see"
error: cannot use mutating member on immutable value: 'numbers' is a 'let' constant
```

That's a compile error: Swift refuses to build it. You have two good options.

**Option 1: return a new array.** Make a `var` copy inside the function, change it, and return it. The caller decides what to do with the result.

```swift run
func addBonus(_ scores: [Int]) -> [Int] {
    var adjusted = scores
    for i in adjusted.indices {
        adjusted[i] += 5
    }
    return adjusted
}

let scores = [70, 80]
let boosted = addBonus(scores)
print(scores, boosted)
```

```output
[70, 80] [75, 85]
```

**Option 2: use inout.** You met `inout` in M05. It explicitly lets a function change the caller's variable, and the `&` at the call site makes that visible:

```swift run
func addBonus(_ scores: inout [Int]) {
    for i in scores.indices {
        scores[i] += 5
    }
}

var mine = [70, 80]
addBonus(&mine)
print(mine)
```

```output
[75, 85]
```

In-place algorithms like sorting and reversing use `inout` (or are mutating methods), because they're meant to change the array they're given. Either way, the change is never a surprise: you can see it in the function's signature and at the call.

## Nested collections copy all the way down

A grid is an array of arrays. Copying the grid copies its rows as well, so changing a cell in one copy never shows up in the other:

```swift run
var board = [[0, 0], [0, 0]]
let saved = board
board[0][1] = 9
print(saved)
print(board)
```

```output
[[0, 0], [0, 0]]
[[0, 9], [0, 0]]
```

This is also why `Array(repeating: Array(repeating: 0, count: 3), count: 3)` in the 2D arrays lesson made three independent rows.

### Snapshots for free

Value semantics makes saving a history of states trivial. Each `append` stores the state **as it was at that moment**:

```swift run
var history: [[Int]] = []
var state = [0, 0, 0]

for step in 0..<3 {
    state[step] = 1
    history.append(state)
}

for snapshot in history {
    print(snapshot)
}
```

```output
[1, 0, 0]
[1, 1, 0]
[1, 1, 1]
```

In a language where arrays are shared, all three entries would be the same array, and you'd see `[1, 1, 1]` three times. You'll rely on this in backtracking (M48), where each partial answer you record must not change afterwards.

## Copying is cheap: copy-on-write

If every assignment copied every element, passing a million-element array to a function would be slow. Swift avoids that with **copy-on-write**. When you assign an array, both variables quietly **share** the same storage. The real copy happens only at the moment one of them is changed, and only if the storage is still shared.

<Callout kind="analogy">
Two students share one textbook while they're only reading it. The moment one wants to scribble notes in the margin, they get their own copy first, so the other's book stays clean.
</Callout>

So:

- Assigning or passing an array is O(1): no elements are copied.
- The first change to a shared array costs O(n), once, to make the private copy.
- Changes after that are normal speed, because the storage isn't shared any more.

You saw this already with `ArraySlice`, which shares the array's storage until you modify it. You'll look at how copy-on-write works in M09 and write your own in M11.

## Looping while changing the same array

Value semantics has a surprising effect on `for-in` loops. The loop works through the array **as it was when the loop started**, so changing the array inside the loop is safe:

```swift run
var numbers = [1, 2, 3]
for number in numbers {
    numbers.append(number * 10)
}
print(numbers)
```

```output
[1, 2, 3, 10, 20, 30]
```

The loop ran three times, not forever, because it was iterating over the original three-element value. This is different from the index loop in the array mutation lesson, where `numbers[i]` reads the **current** array and can run off its end.

<Callout kind="gotcha" title="Swift gotcha: let freezes everything">
A `let` array can't change at all: no appending, no removing, and no assigning to an element, even inside a grid. `let grid = [[0]]; grid[0][0] = 1` doesn't compile. If you need to change it, it must be a `var`.
</Callout>

<Callout kind="note">
When an array holds **class instances**, which you'll meet in M09, copying the array copies the references, not the objects. Both arrays then point at the same objects. Everything in this lesson is about collections of values like `Int`, `String` and other collections, which is what DSA code mostly uses.
</Callout>
