## Why it matters

Lots of data comes in rows and columns: a chess board, a spreadsheet, the pixels of an image, a map of land and water, a seating plan. In DSA, grids are everywhere, from "count the islands" to the tables that dynamic programming fills in. Swift has no special grid type. You build one from what you already know: an array whose elements are arrays.

## An array of arrays

A 2D array, or **grid**, is an array of rows, where each row is itself an array. Its type is `[[Int]]`: "an array of arrays of Int".

```swift run
let grid = [
    [1, 2, 3],
    [4, 5, 6],
]

print(grid[0])
print(grid[1][2])
print(grid.count, grid[0].count)
```

```output
[1, 2, 3]
6
2 3
```

Read `grid[1][2]` from left to right:

1. `grid[1]` picks row 1, the array `[4, 5, 6]`.
2. `[2]` picks index 2 of that row: `6`.

So the first index is always the **row** and the second is the **column**. The number of rows is `grid.count`, and the number of columns is the length of a row, `grid[0].count`.

| | col 0 | col 1 | col 2 |
| --- | --- | --- | --- |
| **row 0** | 1 | 2 | 3 |
| **row 1** | 4 | 5 | 6 |

<Callout kind="gotcha" title="Swift gotcha: row first, then column">
It's tempting to think in (x, y) coordinates, where x is horizontal and comes first. In a grid, `grid[r][c]` puts the **row** (the vertical position) first. Name your variables `row` and `col`, or `r` and `c`, never `x` and `y`, and this mistake mostly disappears.
</Callout>

## Making a grid of a given size

To make an empty board with `rows` rows and `cols` columns, nest `Array(repeating:count:)`. The inner call makes one row; the outer call repeats that row:

```swift run
let rows = 3
let cols = 4
var board = Array(repeating: Array(repeating: 0, count: cols), count: rows)
board[1][2] = 7

for row in board {
    print(row)
}
```

```output
[0, 0, 0, 0]
[0, 0, 7, 0]
[0, 0, 0, 0]
```

Only one cell changed. Each row is its own independent array, because Swift arrays are **values**: repeating a row makes separate copies, not three names for one shared row. (In some languages, such as Python, the same-looking code creates rows that are secretly shared, a classic bug. Swift doesn't have it. You'll see why in the lesson on collections being values.)

Read the nesting order carefully: the **inner** count is the number of columns, and the **outer** count is the number of rows.

## Visiting every cell

Two nested loops visit every cell, row by row. You practised nested loops in M03; here they are on a grid:

```swift run
let grid = [
    [3, 8, 1],
    [9, 2, 7],
]

for r in 0..<grid.count {
    for c in 0..<grid[r].count {
        print("(\(r), \(c)) = \(grid[r][c])")
    }
}
```

```output
(0, 0) = 3
(0, 1) = 8
(0, 2) = 1
(1, 0) = 9
(1, 1) = 2
(1, 2) = 7
```

This order, finishing one row before moving to the next, is called **row-major** order. When you only need the values, `for row in grid { for value in row { ... } }` is shorter.

### Row and column totals

Summing a row is easy, because a row is an array. Summing a column takes a loop over rows:

```swift run
let grid = [
    [1, 2, 3],
    [4, 5, 6],
]

let rowSums = grid.map { $0.reduce(0, +) }
print(rowSums)

var colSums = Array(repeating: 0, count: grid[0].count)
for r in 0..<grid.count {
    for c in 0..<grid[r].count {
        colSums[c] += grid[r][c]
    }
}
print(colSums)
```

```output
[6, 15]
[5, 7, 9]
```

A grid with `r` rows and `c` columns has `r × c` cells, so visiting them all takes O(r × c) time.

## Looking at neighbours

Many grid problems ask about a cell's neighbours: the cells directly above, below, left and right. Rather than writing four `if` statements, store the four **directions** as (row change, column change) tuples, which you met in M02:

```swift run
let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

func landNeighbours(_ grid: [[Int]], _ row: Int, _ col: Int) -> Int {
    var count = 0
    for (dr, dc) in directions {
        let r = row + dr
        let c = col + dc
        if r >= 0 && r < grid.count && c >= 0 && c < grid[r].count && grid[r][c] == 1 {
            count += 1
        }
    }
    return count
}

let map = [
    [0, 1, 0],
    [1, 1, 1],
    [0, 1, 0],
]
print(landNeighbours(map, 1, 1))
print(landNeighbours(map, 0, 0))
print(landNeighbours(map, 0, 1))
```

```output
4
2
1
```

What to notice:

- The **bounds check** comes before `grid[r][c]`. Cells on the edge have neighbours that fall off the grid, at row `-1` or column `3`, and reading those would crash.
- `&&` stops at the first `false`, which is called **short-circuiting**. So `grid[r][c]` is only read once `r` and `c` are known to be valid.

This exact loop, with a directions array and a bounds check, is the core of the grid searches (BFS and DFS) you'll write in later parts.

## Grids don't have to be rectangular

Nothing forces every row to have the same length. An array of arrays can be **jagged**:

```swift run
let triangle = [
    [1],
    [1, 1],
    [1, 2, 1],
    [1, 3, 3, 1],
]
for row in triangle {
    print(row.count, row)
}
```

```output
1 [1]
2 [1, 1]
3 [1, 2, 1]
4 [1, 3, 3, 1]
```

Jagged arrays are useful (this one is the start of Pascal's triangle), but they mean `grid[0].count` isn't always the length of every row. That's why the loops above use `grid[r].count` for the inner bound: it's correct for both shapes.

<Callout kind="gotcha" title="Swift gotcha: empty grids">
`grid[0].count` crashes when the grid has no rows. If a problem allows an empty grid, check first: `guard let cols = grid.first?.count else { return ... }` gives you the column count and handles the empty case in one line.
</Callout>
