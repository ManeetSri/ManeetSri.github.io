## Why it matters

Choosing the right structure is half of solving a DSA problem. The same task can take a second with a set and an hour with an array. Swift's standard library gives you three general-purpose collections, and this lesson is about picking between them quickly. It also lists what Swift *doesn't* include, because a big part of this course is building those missing structures yourself.

## The three collections side by side

| | Array | Set | Dictionary |
| --- | --- | --- | --- |
| Holds | values in order | unique values | key → value pairs |
| Order | yes, by index | none | none |
| Duplicates | allowed | no | keys unique |
| Read by position | O(1) | no positions | no positions |
| "Is x in it?" | O(n) | O(1) average | O(1) average, by key |
| Add an element | O(1) at the end | O(1) average | O(1) average |
| Elements must be | anything | Hashable | keys Hashable |

The "average" next to set and dictionary costs is the price of hashing, which you'll study in M24. In practice, treat them as O(1).

## Three questions that decide

Ask these in order:

1. **Do I need to look something up by a key?** A name to a score, a word to a count, a node to its neighbours. Use a **dictionary**.
2. **Do I only care whether something is present, or need uniqueness?** Visited cells, seen numbers, banned words. Use a **set**.
3. **Otherwise**, especially if order or position matters, or values repeat: use an **array**.

Some quick examples:

| Task | Choice | Why |
| --- | --- | --- |
| The scores of a game, in the order they happened | Array | order matters, repeats allowed |
| Which usernames are already taken | Set | only membership matters |
| How many times each word appears | Dictionary | word → count |
| The cells of a maze you've already visited | Set | fast "seen it?" checks |
| Students grouped by class | Dictionary | class → array of students |

Often the answer is **two collections working together**. In the sets lesson, a set remembered what you'd seen while an array kept the order. In the counting lesson, a dictionary held the counts while the original array supplied the order. When one collection can't do everything, combine two.

<Callout kind="tip">
When a solution feels slow, look for a `contains` or `firstIndex(of:)` call on an array inside a loop. That's an O(n) search repeated n times, O(n²) in total. Swapping the array for a set or dictionary is often the whole optimisation.
</Callout>

## What Swift doesn't give you

Other languages ship more structures in their standard library. Swift keeps its standard library small. Here's what's missing, and what you'll do instead.

### Stack: use an array

A **stack** is last in, first out, like a pile of plates. You only ever add or remove at the top. An array already does this efficiently, because the end of an array is cheap:

```swift run
var undoStack: [String] = []
undoStack.append("open file")
undoStack.append("type text")
undoStack.append("bold")

print("top: \(undoStack.last ?? "empty")")
while let action = undoStack.popLast() {
    print("undo \(action)")
}
```

```output
top: bold
undo bold
undo type text
undo open file
```

`append` pushes, `popLast()` pops and `last` peeks. All three are O(1). You'll wrap this in a proper `Stack` type in M10 and use stacks for real problems in M26.

### Queue: not removeFirst()

A **queue** is first in, first out, like a line at a shop. The obvious array version uses `removeFirst()`, but that shifts every remaining element: O(n) per removal. A simple fix is to leave elements in place and move a `head` index forward instead:

```swift run
var line = ["Ada", "Grace", "Linus"]
var head = 0
line.append("Tim")

while head < line.count {
    print("serving \(line[head])")
    head += 1
}
```

```output
serving Ada
serving Grace
serving Linus
serving Tim
```

Every step is now O(1). The served people still take up memory, which a proper queue fixes. You'll build real queues and deques (double-ended queues) in M27.

### The rest of the list

| Missing structure | What it's for | Where you'll build it |
| --- | --- | --- |
| Linked list | cheap insertion in the middle | M25 |
| Deque | fast adds and removes at both ends | M27 |
| Heap / priority queue | always get the smallest (or largest) quickly | M39 |
| Sorted map / sorted set | keys kept in order, "next bigger key" queries | M37–M38 |
| Ordered dictionary or set | remember insertion order | combine a dictionary and an array |

### The swift-collections package

Apple publishes an open-source package called **swift-collections** that adds `Deque`, `Heap`, `OrderedSet`, `OrderedDictionary` and more. They're excellent and well tested, and you'll meet them in M69. But most interview platforms and competitive programming judges don't let you add packages, so you need to be able to build these yourself. That's what Parts III to V of this course are for.

<Callout kind="gotcha" title="Swift gotcha: choosing by habit">
Coming from other languages, it's tempting to use an array for everything because it's familiar. Ask the three questions every time. A `Set` or `Dictionary` costs one extra line to create and can save you from an O(n²) solution.
</Callout>
