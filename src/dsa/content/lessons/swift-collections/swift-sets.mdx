## Why it matters

"Have I seen this before?" is one of the most common questions an algorithm asks: have I visited this cell, used this number, met this word? An array answers it by checking every element, which gets slow as the array grows. A **set** answers it almost instantly, however many values it holds. In apps, sets track things like the selected rows in a list or the tags on a photo. In DSA, they're the first tool you'll reach for to remove duplicates and speed up lookups.

## What a set is

A **set** is a collection of **unique** values with **no order**. Adding a value that's already there does nothing, and there's no first or second element, so there are no indexes.

To make a set from a literal you must say it's a set, because the same brackets would otherwise make an array. Writing `Set` without the element type lets Swift infer it:

```swift run
let numbers: Set = [3, 1, 4, 1, 5, 9, 2, 6, 5]
print(numbers.count)
print(numbers.sorted())
```

```output
7
[1, 2, 3, 4, 5, 6, 9]
```

Nine values went in, but the repeated `1` and `5` were kept only once, so the set has seven. `sorted()` returns an **array** of the set's values in ascending order, which is how you should print a set.

Other ways to create one:

```swift
var tags = Set<String>()                  // an empty set of String
let fromArray = Set([2, 2, 3])            // {2, 3}: duplicates dropped
let letters = Set("mississippi")          // the characters m, i, s, p
```

<Callout kind="gotcha" title="Swift gotcha: never rely on a set's order">
`print(numbers)` on a set prints its values in an order that looks random, and it can **change from one run of the program to the next**. Swift does this on purpose. If you need an order, sort: `numbers.sorted()`. Every example in this course prints sets sorted, so the output is always the same.
</Callout>

## Why sets are fast: hashing, briefly

Here's the idea behind a set's speed. When you insert a value, Swift computes a **hash**: a number worked out from the value itself. That number tells the set roughly where in its storage to put the value. To check for a value later, Swift computes the same hash and looks in that one place, instead of searching everywhere.

<Callout kind="analogy">
An array is a pile of letters you have to sort through one by one. A set is a wall of pigeonholes labelled by surname: to find a letter for "Hopper" you go straight to the H box.
</Callout>

So checking whether a set contains a value takes about the same time whether it holds ten values or ten million: **O(1) on average**. For an array, `contains` must look at every element in the worst case: **O(n)**. You'll learn exactly how hashing works, and why it's "on average", in M24.

### Elements must be Hashable

Because of hashing, a set can only hold values Swift knows how to hash. Such types are called **Hashable**. `Int`, `Double`, `String`, `Character` and `Bool` all are, and so are arrays of them. Tuples are **not**: `Set<(Int, Int)>` doesn't compile. In M10 you'll learn to make your own types Hashable, which is the usual fix when you want a set of grid positions.

## Inserting, checking and removing

```swift run
var tags = Set<String>()
tags.insert("swift")
tags.insert("ios")
tags.insert("swift")
print(tags.count)

print(tags.contains("ios"))
print(tags.contains("android"))

let removed = tags.remove("ios")
print(removed ?? "nothing")
print(tags.remove("android") ?? "nothing")
print(tags.count)
```

```output
2
true
false
ios
nothing
1
```

- `insert(_:)` adds a value. Inserting `"swift"` a second time changed nothing.
- `contains(_:)` asks whether a value is present.
- `remove(_:)` removes a value and returns it as an optional: `nil` if it wasn't there.

`insert` also tells you whether the value was new. It returns a tuple, and its `inserted` part is `true` only the first time:

```swift run
var seen = Set<Int>()
print(seen.insert(7).inserted)
print(seen.insert(7).inserted)
```

```output
true
false
```

That's handy when you want to insert and check in one step.

## The "seen" pattern

Here's the pattern that makes sets so useful in DSA. Walk through the input once, and keep a set of everything you've seen so far. This function finds the first value that appears twice:

```swift run
func firstRepeat(_ numbers: [Int]) -> Int? {
    var seen = Set<Int>()
    for number in numbers {
        if seen.contains(number) {
            return number
        }
        seen.insert(number)
    }
    return nil
}

print(firstRepeat([4, 2, 7, 2, 4]) ?? -1)
print(firstRepeat([1, 2, 3]) ?? -1)
```

```output
2
-1
```

Without a set, you'd compare every number with every number before it: about n² steps for n numbers. With a set, each check is O(1) on average, so the whole function is **O(n)**. For 100,000 numbers that's the difference between ten billion steps and a hundred thousand.

## Set algebra

Sets come with operations borrowed from maths. Each returns a new set:

```swift run
let backend: Set = ["Ada", "Grace", "Linus"]
let frontend: Set = ["Grace", "Tim", "Linus", "Margaret"]

print(backend.union(frontend).sorted())
print(backend.intersection(frontend).sorted())
print(backend.subtracting(frontend).sorted())
print(backend.symmetricDifference(frontend).sorted())
```

```output
["Ada", "Grace", "Linus", "Margaret", "Tim"]
["Grace", "Linus"]
["Ada"]
["Ada", "Margaret", "Tim"]
```

| Operation | Gives you | Here |
| --- | --- | --- |
| `a.union(b)` | everything in either | all five people |
| `a.intersection(b)` | only what's in both | works on both teams |
| `a.subtracting(b)` | in `a` but not in `b` | backend only |
| `a.symmetricDifference(b)` | in exactly one of them | on one team only |

Each one also has a mutating version that changes the set in place: `formUnion`, `formIntersection`, `subtract` and `formSymmetricDifference`.

There are also questions you can ask about two sets:

```swift run
let small: Set = [1, 2]
let big: Set = [1, 2, 3]
print(small.isSubset(of: big))
print(big.isSuperset(of: small))
print(small.isDisjoint(with: [7, 8]))
print(Set([1, 2, 3]) == Set([3, 2, 1]))
```

```output
true
true
true
true
```

Two sets are equal when they hold the same values. Order doesn't exist, so it can't matter.

<Callout kind="tip">
The set operations accept arrays too: `backend.intersection(["Ada", "Tim"])` works without converting the array to a set first.
</Callout>

## Sets and arrays together

You'll often move between the two. `Set(array)` drops duplicates; `set.sorted()` or `Array(set)` gives an array back. But a set forgets the original order. If you need unique values **in the order they first appeared**, use a set to remember what you've seen and an array to collect the results. That's exactly the practice problem below.
