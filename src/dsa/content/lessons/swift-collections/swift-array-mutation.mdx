## Why it matters

Most solutions build their answer as they go: collect the matching items, push a value, pop the latest one, drop what you no longer need. Knowing how to add and remove elements, and which of those operations are cheap, is the difference between a solution that flies and one that crawls. Appending to and removing from the end of an array is also exactly how you'll build a **stack** later in the course.

## Arrays you can change must be var

An array declared with `let` is frozen: you can't add, remove or replace anything. To change an array, declare it with `var`. Every method in this lesson changes the array it's called on, which Swift calls **mutating** it.

## Adding to the end: append

`append(_:)` adds one element to the end. `append(contentsOf:)` adds every element of another array. The `+=` operator does the same as `append(contentsOf:)`.

```swift run
var tasks = ["wake up"]
tasks.append("coffee")
tasks.append(contentsOf: ["code", "lunch"])
tasks += ["more code"]
print(tasks)
print(tasks.count)
```

```output
["wake up", "coffee", "code", "lunch", "more code"]
5
```

Building a result with `append` inside a loop is one of the most common patterns you'll write:

```swift run
let readings = [12, -3, 8, -1, 0, 5]
var positives: [Int] = []
for reading in readings {
    if reading > 0 {
        positives.append(reading)
    }
}
print(positives)
```

```output
[12, 8, 5]
```

(You could write this with `filter` from M06. Both are fine; the loop version is easier to extend when the logic grows.)

## Inserting in the middle: insert(_:at:)

`insert(_:at:)` puts a new element at an index. Everything from that index onwards moves one place to the right to make room. The index can be anything from `0` to `count`; inserting at `count` is the same as appending.

```swift run
var letters = ["a", "c", "d"]
letters.insert("b", at: 1)
print(letters)
letters.insert("z", at: 0)
print(letters)
letters.insert("e", at: letters.count)
print(letters)
```

```output
["a", "b", "c", "d"]
["z", "a", "b", "c", "d"]
["z", "a", "b", "c", "d", "e"]
```

## Removing elements

There are several ways to remove, and most of them **return** the element they removed, so you can use it:

```swift run
var stack = [10, 20, 30, 40, 50]

let removed = stack.remove(at: 1)
print(removed, stack)

let last = stack.removeLast()
print(last, stack)

let first = stack.removeFirst()
print(first, stack)

stack.removeAll()
print(stack, stack.isEmpty)
```

```output
20 [10, 30, 40, 50]
50 [10, 30, 40]
10 [30, 40]
[] true
```

- `remove(at:)` removes the element at an index; everything after it moves one place left.
- `removeLast()` and `removeFirst()` remove from either end.
- `removeAll()` empties the array.

To remove every element that matches a condition, pass a closure to `removeAll(where:)`:

```swift run
var numbers = [3, 8, 1, 6, 7, 2]
numbers.removeAll(where: { $0 % 2 == 0 })
print(numbers)
```

```output
[3, 1, 7]
```

## Removing from an empty array crashes

`removeLast()` and `removeFirst()` assume there is something to remove:

```swift
var empty: [Int] = []
empty.removeLast()
```

```text title="What you'll see"
Fatal error: Can't remove last element from an empty collection
```

That's what Swift reports. When the array might be empty, use `popLast()`. It returns an optional: the removed element, or `nil` if there was nothing to remove.

```swift run
var history = ["home", "search"]
while let page = history.popLast() {
    print("Back from \(page)")
}
print(history.popLast() ?? "nothing left")
```

```output
Back from search
Back from home
nothing left
```

`while let` keeps looping as long as `popLast()` returns a value. This "pop until empty" loop is the heart of many stack algorithms you'll write later.

## Changing the order in place

In M06 you met `sorted()` and `reversed()`, which return a **new** array and leave the original alone. Their mutating twins, `sort()` and `reverse()`, rearrange the array itself. You also met `swapAt(_:_:)` in M05.

```swift run
var ranks = [3, 1, 2]
let ordered = ranks.sorted()
print(ranks, ordered)

ranks.sort()
print(ranks)

ranks.reverse()
print(ranks)

ranks.swapAt(0, 2)
print(ranks)
```

```output
[3, 1, 2] [1, 2, 3]
[1, 2, 3]
[3, 2, 1]
[1, 2, 3]
```

The naming rule is worth learning once: a verb (`sort`, `reverse`) changes the array; a past participle (`sorted`, `reversed`) gives you a new value.

## Some operations cost more than others

All of these methods give the right answer, but they don't all take the same time.

<Callout kind="analogy">
Picture people standing in a line in numbered spots. Someone joining or leaving at the **back** affects nobody else. Someone pushing in at the **front** makes every person shuffle one spot back, and someone leaving the front makes everyone shuffle forward. With five people that's nothing. With a million, it's a million moves.
</Callout>

| Operation | Work done | Cost |
| --- | --- | --- |
| `append`, `removeLast`, `popLast` | touches only the end | fast: O(1) |
| `insert(_:at: 0)`, `removeFirst()` | moves every element | slow: O(n) |
| `insert`/`remove(at:)` in the middle | moves everything after the index | O(n) |

O(n) means the time grows in step with the number of elements, n. One `removeFirst()` on a small array is fine. Calling it inside a loop over a big array repeats that O(n) shuffle n times, and the work explodes. You'll measure and prove these costs properly in M14 and M18. For now, remember the rule: **the end of an array is cheap, the front is expensive.**

<Callout kind="gotcha" title="Swift gotcha: removing while looping over indices">
This looks reasonable but crashes:

```swift
var values = [1, 2, 3, 4]
for i in values.indices {
    if values[i] % 2 == 0 {
        values.remove(at: i)
    }
}
```

`values.indices` is worked out once, as `0..<4`, before the loop starts. After the first removal the array only has three elements, so `values[3]` is out of range. Use `removeAll(where:)`, or build a new array with `filter`, instead of removing inside an index loop.
</Callout>
