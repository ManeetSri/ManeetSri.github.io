## Why it matters

Trees and graphs are where interview problems stop looking like arrays: org charts, file systems, road maps, friend networks, course catalogues, mazes. Yet nearly all of them reduce to five moves: a DFS that carries answers up or context down, a BFS that spreads out level by level, a walk down a BST, a topological sort, and union-find. This lesson gives each as a template with its invariant and its usual bugs, in the order you'd reach for them. The [Code templates](/dsa/sheets/templates) sheet has the bare versions, including Dijkstra.

## Tree DFS: answers up, context down

**Use it when** the question is about a tree and each node's answer depends on its subtrees (heights, sizes, sums, "is it balanced?") or on the path from the root (the largest value above, the sum so far, the depth). Learn it in [Preorder, inorder and postorder](/dsa/learn/trav-dfs-recursive), [Depth and diameter](/dsa/learn/bt-depth-diameter) and [Good nodes and root-to-leaf numbers](/dsa/learn/bt-good-nodes).

Ask one question before writing anything: **does information flow up or down?**

- **Up (postorder):** the function *returns* what the parent needs, computed from the children's return values. If the overall answer isn't that return value, track it in a variable outside, updated at every node.
- **Down (preorder):** the function *takes a parameter* carrying what the path from the root knows, and passes an updated copy to each child.

```swift run
// Tree DFS in both directions: answers flowing up, and context flowing down
final class TreeNode {
    let value: Int
    var left: TreeNode?
    var right: TreeNode?
    init(_ value: Int) { self.value = value }
}

// Build a tree from a level-order list with nil gaps
func makeTree(_ values: [Int?]) -> TreeNode? {
    guard let first = values.first, let rootValue = first else { return nil }
    let root = TreeNode(rootValue)
    var queue = [root]
    var head = 0
    var i = 1
    while i < values.count {
        let parent = queue[head]
        head += 1
        if let value = values[i] {
            parent.left = TreeNode(value)
            queue.append(parent.left!)
        }
        if i + 1 < values.count, let value = values[i + 1] {
            parent.right = TreeNode(value)
            queue.append(parent.right!)
        }
        i += 2
    }
    return root
}

// Up: each call returns its subtree's height; the best path through any node is tracked on the side
func diameter(_ root: TreeNode?) -> Int {
    var best = 0                                  // the longest path, in edges, seen so far
    func height(_ node: TreeNode?) -> Int {
        guard let node else { return 0 }
        let left = height(node.left)
        let right = height(node.right)
        best = max(best, left + right)            // the path that bends at this node
        return 1 + max(left, right)               // what the parent needs from this subtree
    }
    _ = height(root)
    return best
}

// Down: each call receives what the path from the root knows (here, the largest value on it)
func goodNodes(_ root: TreeNode?) -> Int {
    func count(_ node: TreeNode?, _ largestAbove: Int) -> Int {
        guard let node else { return 0 }
        let good = node.value >= largestAbove ? 1 : 0
        let largest = max(largestAbove, node.value)
        return good + count(node.left, largest) + count(node.right, largest)
    }
    return count(root, Int.min)
}

let tree = makeTree([3, 1, 4, 3, nil, 1, 5])
print(diameter(tree), goodNodes(tree))
print(diameter(makeTree([1, 2, 3, 4, 5, nil, 6, nil, nil, 7])), goodNodes(makeTree([2, 2, 1])))
```

```output
4 4
5 2
```

```visual binaryTree
program: diameter
input:
  tree: [3, 1, 4, 3, null, 1, 5]
```

**The invariant (up):** `height(node)` returns the height of `node`'s subtree, and when it returns, `best` already accounts for every path that bends at a node inside that subtree. **The invariant (down):** `largestAbove` is the largest value on the path from the root to the node's parent.

**Common bugs:**

- Returning the global answer instead of what the parent needs. The diameter's recursion returns a *height*; the diameter itself lives in `best`.
- Counting nodes when the question counts edges, or the reverse. Here an empty tree has height 0, a leaf height 1, and the diameter counts edges, so it's `left + right`.
- Deep recursion. A tree shaped like a linked list with 10⁵ nodes recurses 10⁵ deep, which can overflow the stack, as [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) showed. Use an explicit stack for such inputs.

## Level-order BFS and walking a BST

**Use it when** the question mentions levels, depth, "closest to the root", or a view from one side: BFS by level. And when the tree is a **binary search tree**, every comparison tells you which subtree to skip, so searches, inserts and common ancestors take O(height). Learn them in [Level-order traversal](/dsa/learn/trav-level-order), [Zigzag and the side views](/dsa/learn/trav-zigzag-views), [Kth smallest and LCA in a BST](/dsa/learn/bst-kth-lca) and [Validate a BST](/dsa/learn/bst-validate).

```swift run
// Level-order BFS one level at a time, and walking a BST by its ordering
final class TreeNode {
    let value: Int
    var left: TreeNode?
    var right: TreeNode?
    init(_ value: Int, _ left: TreeNode? = nil, _ right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

// Level by level: at the top of each round, the queue holds exactly one whole level
func levels(_ root: TreeNode?) -> [[Int]] {
    guard let root else { return [] }
    var result: [[Int]] = []
    var level = [root]
    while !level.isEmpty {
        result.append(level.map { $0.value })
        var next: [TreeNode] = []
        for node in level {
            if let left = node.left { next.append(left) }
            if let right = node.right { next.append(right) }
        }
        level = next
    }
    return result
}

// BST: smaller values go left, so one comparison discards a whole subtree
func lowestCommonAncestor(_ root: TreeNode?, _ p: Int, _ q: Int) -> Int? {
    var node = root
    while let current = node {
        if p < current.value && q < current.value {
            node = current.left                   // both in the left subtree
        } else if p > current.value && q > current.value {
            node = current.right                  // both in the right subtree
        } else {
            return current.value                  // they split here (or one of them is here)
        }
    }
    return nil
}

// Validate: every node must fit the range its ancestors allow
func isValidBST(_ node: TreeNode?, _ low: Int = Int.min, _ high: Int = Int.max) -> Bool {
    guard let node else { return true }
    guard low < node.value, node.value < high else { return false }
    return isValidBST(node.left, low, node.value) && isValidBST(node.right, node.value, high)
}

//        8
//      /   \
//     3     10
//    / \      \
//   1   6      14
//      / \
//     4   7
let bst = TreeNode(8, TreeNode(3, TreeNode(1), TreeNode(6, TreeNode(4), TreeNode(7))), TreeNode(10, nil, TreeNode(14)))
print(levels(bst))
print(lowestCommonAncestor(bst, 4, 7)!, lowestCommonAncestor(bst, 4, 14)!, lowestCommonAncestor(bst, 3, 7)!)
print(isValidBST(bst), isValidBST(TreeNode(8, TreeNode(3, nil, TreeNode(9)), nil)))
```

```output
[[8], [3, 10], [1, 6, 14], [4, 7]]
6 8 3
true false
```

**The invariants:** in `levels`, the array `level` holds exactly one whole level at the top of each round, so processing it and building `next` moves down one level. In the BST walk, both targets are always inside the current node's subtree. In `isValidBST`, `low` and `high` are the tightest bounds the ancestors impose: the 9 in the second check is right of 3 but inside 8's left subtree, so it must be below 8.

**Common bugs:**

- Validating a BST by comparing each node only with its children. The 9 above passes that check and is still in the wrong place. Pass the bounds down.
- Mixing levels in BFS by processing nodes as they're added. Take the level's nodes first, or record `queue.count` before the inner loop.
- Using `Int.min` and `Int.max` as bounds when node values can *be* those numbers. Use optional bounds, `Int?`, for full generality.

## BFS on a graph: fewest edges

**Use it when** you need the fewest steps, moves or hops, and every step costs the same. The vertices might be cities, grid cells, words or puzzle states. With several starting points, such as every rotten orange or every exit, put them **all** in the queue at distance 0. Learn it in [BFS and unweighted shortest paths](/dsa/learn/gt-bfs) and [Multi-source BFS](/dsa/learn/gt-multi-source).

**The invariant:** the queue holds vertices in order of distance, never more than one apart, so the first time a vertex is reached is along a shortest path. Marking it **when it's queued** (not when it's dequeued) stops it from being queued twice.

```swift run
// BFS: fewest edges from one source (or many), with the path rebuilt from parent links
func adjacency(_ count: Int, _ edges: [(Int, Int)]) -> [[Int]] {
    var neighbours = Array(repeating: [Int](), count: count)
    for (a, b) in edges {
        neighbours[a].append(b)
        neighbours[b].append(a)                   // drop this line for one-way edges
    }
    return neighbours
}

func bfs(_ neighbours: [[Int]], from sources: [Int]) -> (distance: [Int], parent: [Int]) {
    var distance = Array(repeating: -1, count: neighbours.count)   // -1: not reached yet
    var parent = Array(repeating: -1, count: neighbours.count)
    var queue = sources
    var head = 0
    for source in sources { distance[source] = 0 }
    while head < queue.count {
        let node = queue[head]
        head += 1
        for next in neighbours[node] where distance[next] == -1 {
            distance[next] = distance[node] + 1   // mark when queued, never twice
            parent[next] = node
            queue.append(next)
        }
    }
    return (distance, parent)
}

func path(to target: Int, _ parent: [Int]) -> [Int] {
    var route = [target]
    while parent[route[route.count - 1]] != -1 {
        route.append(parent[route[route.count - 1]])
    }
    return route.reversed()
}

let graph = adjacency(7, [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4), (4, 5), (2, 6)])
let (distance, parent) = bfs(graph, from: [0])
print(distance)
print(path(to: 5, parent))
print(bfs(graph, from: [5, 6]).distance)          // multi-source: distance to the nearer of 5 and 6
```

```output
[0, 1, 1, 2, 3, 4, 2]
[0, 1, 3, 4, 5]
[2, 3, 1, 2, 1, 0, 0]
```

`parent` records which vertex discovered each one, so walking it backwards from the target and reversing gives an actual shortest path. The multi-source call gives every vertex its distance to the *nearest* source, in one pass.

**Common bugs:**

- Marking vertices as visited when dequeued. A vertex can then be queued many times, which wastes time and, in weighted variants, gives wrong answers.
- `queue.removeFirst()`, which is O(n) per call. Use a head index.
- BFS on a weighted graph. It counts edges, not costs. With weights 0 and 1 use [0-1 BFS](/dsa/learn/sp-zero-one-bfs); with other non-negative weights, [Dijkstra](/dsa/learn/sp-dijkstra).

## DFS on a grid: components and flood fill

**Use it when** you need to explore everything connected to a cell or vertex: count islands, measure regions, fill an area, find connected components. Order doesn't matter, only reachability, so DFS and BFS both work. An explicit stack avoids recursion limits on big grids. Learn it in [Connected components and flood fill](/dsa/learn/gt-components), [Number of islands](/dsa/learn/gt-islands) and [Direction arrays](/dsa/learn/matrix-directions).

```swift run
// DFS on a grid with an explicit stack: count the islands and measure the largest
func islands(_ grid: [[Character]]) -> (count: Int, largest: Int) {
    let rows = grid.count
    let cols = grid.first?.count ?? 0
    var seen = Array(repeating: Array(repeating: false, count: cols), count: rows)
    let moves = [(1, 0), (-1, 0), (0, 1), (0, -1)]
    var count = 0
    var largest = 0
    for row in 0..<rows {
        for col in 0..<cols where grid[row][col] == "#" && !seen[row][col] {
            count += 1                            // a new island starts here
            var size = 0
            var stack = [(row, col)]
            seen[row][col] = true                 // mark when pushed, so nothing is pushed twice
            while let (r, c) = stack.popLast() {
                size += 1
                for (dr, dc) in moves {
                    let nr = r + dr
                    let nc = c + dc
                    guard nr >= 0, nr < rows, nc >= 0, nc < cols,
                          grid[nr][nc] == "#", !seen[nr][nc] else { continue }
                    seen[nr][nc] = true
                    stack.append((nr, nc))
                }
            }
            largest = max(largest, size)
        }
    }
    return (count, largest)
}

let map = ["##..#", "#...#", "..#..", "##.##"].map { Array($0) }
print(islands(map))
```

```output
(count: 5, largest: 3)
```

**The invariant:** every cell on the stack is land, belongs to the current island, and is already marked as seen. Each land cell is pushed exactly once, so the whole grid costs O(rows × cols).

**Common bugs:**

- Checking bounds after indexing. `grid[nr][nc]` with `nr = -1` crashes, so the `guard` tests the bounds first, and Swift's `,` in a condition list stops at the first false.
- Treating diagonal cells as neighbours (or not) without reading the statement. The direction array is where that decision lives.
- Recursing on a 1,000 × 1,000 grid of land: a million nested calls. Use the stack.

## Topological sort

**Use it when** tasks have "must come before" rules: prerequisites, build steps, recipe stages, the letters of an alien alphabet. You want an order that respects every rule, to know whether one exists (a cycle makes it impossible), or the fewest rounds when independent tasks can run together. Learn it in [Kahn's algorithm](/dsa/learn/topo-kahn), [Course schedule I and II](/dsa/learn/topo-course-schedule) and [Parallel courses and levels](/dsa/learn/topo-parallel-courses).

**The invariant:** `inDegree[v]` counts `v`'s prerequisites that haven't been taken yet, and `ready` holds exactly the vertices whose count is 0. Taking a vertex can only make its successors ready.

```swift run
// Kahn's algorithm in waves: an order that respects every "before → after" edge, and how many rounds it takes
func waves(_ count: Int, _ edges: [(before: Int, after: Int)]) -> [[Int]]? {
    var outgoing = Array(repeating: [Int](), count: count)
    var inDegree = Array(repeating: 0, count: count)     // unfinished prerequisites of each node
    for edge in edges {
        outgoing[edge.before].append(edge.after)
        inDegree[edge.after] += 1
    }
    var ready = (0..<count).filter { inDegree[$0] == 0 }
    var result: [[Int]] = []
    var done = 0
    while !ready.isEmpty {
        result.append(ready)
        done += ready.count
        var next: [Int] = []
        for node in ready {
            for after in outgoing[node] {
                inDegree[after] -= 1
                if inDegree[after] == 0 { next.append(after) }   // its last prerequisite just finished
            }
        }
        ready = next
    }
    return done == count ? result : nil           // anything left over is stuck in a cycle
}

// Courses 0...5: 0 and 1 have no prerequisites, 2 needs 0, 3 needs 0 and 1, 4 needs 2 and 3, 5 needs 3
let plan = waves(6, [(0, 2), (0, 3), (1, 3), (2, 4), (3, 4), (3, 5)])!
print(plan, "takes", plan.count, "semesters")
print(waves(3, [(0, 1), (1, 2), (2, 1)]) == nil)
```

```output
[[0, 1], [2, 3], [4, 5]] takes 3 semesters
true
```

Processing a whole wave at a time gives the levels: each wave is everything that can run once the previous waves are done, so the number of waves is the fewest semesters. For one flat order, take vertices one at a time from `ready`, in any order.

**Common bugs:**

- Reversing the edges. Decide "before → after" when reading the input, and convert every pair to it on the first line. An edge the wrong way round still gives *an* order, but backwards.
- Forgetting the cycle check. If fewer than `count` vertices come out, the rest wait on each other forever.
- Counting duplicate edges once in `outgoing` but twice in `inDegree`, or the other way round. Build both in the same loop.

## Union-find

**Use it when** groups only ever **merge**: friend circles forming, accounts sharing an email, cables joining computers, islands appearing. It answers "are these two connected?" and "how many groups?" in near-constant time per operation, and `union` returning false spots an edge that closes a cycle. Learn it in [Disjoint sets](/dsa/learn/uf-idea), [Path compression and union by rank](/dsa/learn/uf-optimisations) and [Provinces, redundant connection and valid tree](/dsa/learn/uf-provinces).

**The invariant:** two elements are in the same group exactly when `find` gives the same root. Path compression and union by size never change which group an element is in; they only keep the trees shallow.

```swift run
// Union-find: groups that only ever merge, with near-constant time per operation
struct UnionFind {
    private var parent: [Int]
    private var size: [Int]
    private(set) var groups: Int

    init(_ count: Int) {
        parent = Array(0..<count)
        size = Array(repeating: 1, count: count)
        groups = count
    }

    mutating func find(_ x: Int) -> Int {
        var root = x
        while parent[root] != root { root = parent[root] }
        var node = x
        while node != root {                      // path compression: point everything at the root
            let next = parent[node]
            parent[node] = root
            node = next
        }
        return root
    }

    @discardableResult
    mutating func union(_ a: Int, _ b: Int) -> Bool {
        var rootA = find(a)
        var rootB = find(b)
        if rootA == rootB { return false }        // already together: this edge closes a cycle
        if size[rootA] < size[rootB] { swap(&rootA, &rootB) }
        parent[rootB] = rootA                     // union by size: the smaller tree goes under
        size[rootA] += size[rootB]
        groups -= 1
        return true
    }
}

var network = UnionFind(6)
for (a, b) in [(0, 1), (1, 2), (3, 4), (2, 0), (4, 5)] {
    let joined = network.union(a, b)
    print("link \(a)-\(b):", joined ? "joined" : "redundant", "· groups:", network.groups)
}
print(network.find(0) == network.find(2), network.find(0) == network.find(5))
```

```output
link 0-1: joined · groups: 5
link 1-2: joined · groups: 4
link 3-4: joined · groups: 3
link 2-0: redundant · groups: 3
link 4-5: joined · groups: 2
true false
```

**Common bugs:**

- Comparing `parent[a] == parent[b]` instead of `find(a) == find(b)`. A parent is only a root after compression.
- Linking `a` under `b` instead of root under root, which leaves part of a group behind.
- Expecting it to delete edges. Union-find can't split a group. If edges disappear, process the changes in reverse so they become additions, as in [Number of islands II](/dsa/learn/uf-online).

## Which one?

| The problem | Template | Time |
| --- | --- | --- |
| a value per subtree, or the best path through a node | tree DFS, answers up | O(n) |
| depends on the path from the root | tree DFS, context down | O(n) |
| levels, depth, side views | level-order BFS | O(n) |
| search, floor, ancestor in a BST | walk left or right | O(height) |
| fewest steps, equal costs | BFS (multi-source for many starts) | O(V + E) |
| cheapest path with costs | Dijkstra, on the [Code templates](/dsa/sheets/templates) sheet | O((V + E) log V) |
| everything connected to something | DFS or BFS flood fill | O(V + E) |
| an order under "before" rules, rounds, cycle check | Kahn's algorithm | O(V + E) |
| groups merging over time, cycle on adding an edge | union-find | about O(1) per operation |
| connect everything at least cost | Kruskal (sort edges + union-find) | O(E log E) |

The last row shows templates combining: [Kruskal's algorithm](/dsa/learn/mst-kruskal) is a sort followed by union-find, rejecting every edge whose `union` returns false. For the full graph decision table, including flows, matchings and strongly connected components, see [Which graph algorithm when](/dsa/learn/ag-which-algorithm).
