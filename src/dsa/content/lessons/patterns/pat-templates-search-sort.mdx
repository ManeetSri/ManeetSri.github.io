## Why it matters

Binary search, intervals and heaps are the "sort it, then be clever" family. Each turns a problem that looks like it needs every pair, every time step or every candidate into something that takes O(log n) per question, or O(n log n) in total. They also share a habit: the hard part is rarely the code, which is short, but the **boundaries**. Is the range closed or half-open? Does an interval ending at 10 overlap one starting at 10? Is the heap a min-heap or a max-heap? This lesson gives each template with its invariant, so those choices stop being guesses. The skeletons are on the [Code templates](/dsa/sheets/templates) sheet.

## Lower and upper bound

**Use it when** the input is sorted and you need a position: where a value is, where it would go, how many values fall in a range. Classic "is it there?" binary search is a special case. Learn it in [Lower bound, upper bound, first and last occurrence](/dsa/learn/bs-bounds) and [Invariants and off-by-one](/dsa/learn/bs-invariants).

**The invariant:** the answer is always in `low...high`. Everything before `low` is too small, and everything from `high` on is big enough. Each step shrinks the range, and the loop stops when `low == high`: the one index left is the answer. Using the half-open range `0..<count`, with `high = items.count` meaning "past the end", means "not found" needs no special value.

```swift run
// Lower and upper bound on a half-open range, and what they give you
func lowerBound(_ items: [Int], _ target: Int) -> Int {
    var low = 0
    var high = items.count                        // the answer is somewhere in low...high
    while low < high {
        let mid = low + (high - low) / 2
        if items[mid] < target {
            low = mid + 1                         // mid and everything before it is too small
        } else {
            high = mid                            // mid might be the answer; keep it
        }
    }
    return low                                    // the first index with items[index] >= target
}

func upperBound(_ items: [Int], _ target: Int) -> Int {
    var low = 0
    var high = items.count
    while low < high {
        let mid = low + (high - low) / 2
        if items[mid] <= target { low = mid + 1 } else { high = mid }
    }
    return low                                    // the first index with items[index] > target
}

let scores = [10, 20, 20, 20, 35, 40, 40, 55]
let first = lowerBound(scores, 20)
let last = upperBound(scores, 20) - 1
print("20 appears at \(first)...\(last)")
let at30 = lowerBound(scores, 30)
print("30 present?", at30 < scores.count && scores[at30] == 30)
print("scores from 20 to 40:", upperBound(scores, 40) - lowerBound(scores, 20))
print("insert 60 at", lowerBound(scores, 60))
```

```output
20 appears at 1...3
30 present? false
scores from 20 to 40: 6
insert 60 at 8
```

The two functions differ in one character: `<` finds the first index with a value **at least** the target, and `<=` the first with a value **greater** than it. Between them they answer the common questions: first occurrence, last occurrence (`upperBound - 1`), count of a value (`upperBound - lowerBound`), count in a range, and the insert position that keeps the array sorted.

**Common bugs:**

- Mixing styles: `while low <= high` with `high = mid` loops forever. Pick one convention, half-open with `low < high` here, and keep all three lines consistent.
- Trusting `lowerBound` to mean "found". It returns a position even when the value is missing: check `index < items.count && items[index] == target`.
- Writing `(low + high) / 2` in languages where it can overflow. In Swift it would need about 4.6 × 10¹⁸ elements, but `low + (high - low) / 2` is the habit worth keeping.

## Binary search on any monotonic condition

**Use it when** there's a condition on positions that's false, false, …, true, true: "is this build broken?", "is this value at most the last one?" (a rotated array), "is the slope going down?" (a peak). Lower bound is the special case where the condition is `items[i] >= target`. Learn it in [Rotated sorted arrays](/dsa/learn/bs-rotated) and [partitioningIndex](/dsa/learn/bs-partitioning-index).

**The invariant:** the first true position is in `low...high`, with `high = count` standing for "never true".

```swift run
// Binary search on any monotonic condition over indexes: false, false, ..., true, true
func firstTrue(_ count: Int, _ condition: (Int) -> Bool) -> Int {
    var low = 0
    var high = count                              // count means "never true"
    while low < high {
        let mid = low + (high - low) / 2
        if condition(mid) { high = mid } else { low = mid + 1 }
    }
    return low
}

// The smallest value in a sorted array that was rotated: the first index whose value is at most the last
let rotated = [30, 40, 50, 5, 10, 20]
let smallest = firstTrue(rotated.count) { rotated[$0] <= rotated[rotated.count - 1] }
print("minimum \(rotated[smallest]) at index \(smallest)")

// The first build that fails its tests (builds 0..<8, failing from build 5 on)
let firstBad = firstTrue(8) { build in build >= 5 }
print("first bad build:", firstBad)
```

```output
minimum 5 at index 3
first bad build: 5
```

The skill is finding the condition. For the rotated array, "is this value at most the last value?" is false on the left part (30, 40, 50) and true on the right part (5, 10, 20), so the first true index is the smallest value.

**Common bugs:** a condition that isn't monotonic (true, false, true), which makes the search return nonsense without any error. Check it on a small example by writing the condition's value under each position.

## Binary search on the answer

**Use it when** the question asks for the smallest (or largest) **value** that makes something possible, and checking one candidate is quick: the smallest capacity, the slowest speed, the largest minimum gap. The search is over answers, not over array positions. Learn it in [The monotonic predicate idea](/dsa/learn/bsa-idea), [Capacity to ship packages](/dsa/learn/bsa-shipping) and [Aggressive cows](/dsa/learn/bsa-aggressive-cows).

**The invariant:** the answer is in `low...high`. For "smallest that works", every value below `low` fails; for "largest that works", every value above `high` fails. The check, `works`, is usually a greedy pass in O(n).

```swift run
// Binary search on the answer: the smallest value that works, and the largest value that works

// Smallest daily capacity that ships every parcel, in order, within `days` days
func smallestCapacity(_ weights: [Int], days: Int) -> Int {
    func works(_ capacity: Int) -> Bool {         // greedy check: fill each day as far as it goes
        var used = 1
        var load = 0
        for weight in weights {
            if load + weight > capacity {
                used += 1
                load = 0
            }
            load += weight
        }
        return used <= days
    }
    var low = weights.max()!                      // smaller can't carry the heaviest parcel
    var high = weights.reduce(0, +)               // one day carries everything
    while low < high {
        let mid = low + (high - low) / 2
        if works(mid) { high = mid } else { low = mid + 1 }
    }
    return low
}

// Largest minimum gap when placing `count` sensors at some of the sorted positions
func largestGap(_ positions: [Int], count: Int) -> Int {
    func works(_ gap: Int) -> Bool {              // greedy check: place each sensor as early as allowed
        var placed = 1
        var last = positions[0]
        for position in positions.dropFirst() where position - last >= gap {
            placed += 1
            last = position
        }
        return placed >= count
    }
    var low = 0                                   // a gap of 0 always works
    var high = positions[positions.count - 1] - positions[0]
    while low < high {
        let mid = low + (high - low + 1) / 2      // round up, or low = mid could loop forever
        if works(mid) { low = mid } else { high = mid - 1 }
    }
    return low
}

print(smallestCapacity([4, 8, 2, 6, 5, 3, 7], days: 3))
print(largestGap([1, 2, 4, 8, 9], count: 3))
```

```output
13
3
```

The "largest" version rounds `mid` **up**. With `low = mid` on success, rounding down would leave `low` unchanged when `high = low + 1`, and the loop would never end.

For answers that are real numbers, such as a speed in km/h to two decimal places, loop a fixed number of times instead of `while low < high`: 100 halvings shrink any range far below `Double` precision, as [nth roots and binary search on real numbers](/dsa/learn/bsa-real-numbers) shows.

**Common bugs:**

- Bounds that exclude the answer. For shipping, `low` must be the heaviest parcel, not 1 or 0, or the check is asked about impossible capacities. And `high` must be a value that surely works.
- A check that overflows when the candidate is huge. Stop counting once you've seen enough, as in [Earliest minute for the bakery order](/dsa/practice/bakery-order-deadline).
- Searching the answer when the condition isn't monotonic. Ask: if `x` works, does every bigger `x` work too?

## Intervals: sort, then sweep

**Use it when** the input is a list of ranges: meetings, bookings, talks, shifts. Almost every interval problem starts by sorting, and the question decides the sort key. Learn it in [Merge and insert intervals](/dsa/learn/iv-merge-insert), [Non-overlapping intervals](/dsa/learn/iv-non-overlapping), [Meeting rooms](/dsa/learn/iv-meeting-rooms) and [Sweep-line events](/dsa/learn/iv-sweep-line).

| Question | Sort by | Then |
| --- | --- | --- |
| merge overlaps, total covered length | start | extend the last merged interval or start a new one |
| most intervals with no overlap, fewest to remove | end | keep each interval that starts after the last kept one ends |
| most open at once, rooms needed | events: (time, +1 or −1) | running total of open intervals |
| common free time, intersections of two lists | start (or already sorted) | two pointers over both lists |

```swift run
// Three interval templates. Intervals are [start, end] pairs.

// 1. Merge: sort by start, then extend the last merged interval or start a new one
func merge(_ intervals: [[Int]]) -> [[Int]] {
    var merged: [[Int]] = []
    for interval in intervals.sorted(by: { $0[0] < $1[0] }) {
        if let last = merged.last, interval[0] <= last[1] {
            merged[merged.count - 1][1] = max(last[1], interval[1])   // overlaps: extend
        } else {
            merged.append(interval)
        }
    }
    return merged
}

// 2. Most non-overlapping: sort by end, keep each interval that starts after the last kept one ends
func mostNonOverlapping(_ intervals: [[Int]]) -> Int {
    var kept = 0
    var lastEnd = Int.min
    for interval in intervals.sorted(by: { $0[1] < $1[1] }) where interval[0] >= lastEnd {
        kept += 1                                 // touching ends are fine: [1, 3] then [3, 5]
        lastEnd = interval[1]
    }
    return kept                                   // fewest to remove: intervals.count - kept
}

// 3. Sweep line: the most intervals open at once (meeting rooms), half-open [start, end)
func mostAtOnce(_ intervals: [[Int]]) -> Int {
    var events: [(time: Int, change: Int)] = []
    for interval in intervals {
        events.append((interval[0], 1))
        events.append((interval[1], -1))
    }
    // At equal times, -1 sorts before +1: a meeting ending at 10 frees its room for one starting at 10
    events.sort { ($0.time, $0.change) < ($1.time, $1.change) }
    var open = 0
    var most = 0
    for event in events {
        open += event.change
        most = max(most, open)
    }
    return most
}

let talks = [[9, 11], [1, 3], [2, 6], [8, 10], [15, 18], [10, 12]]
print(merge(talks))
print(mostNonOverlapping(talks))
print(mostAtOnce(talks))
```

```output
[[1, 6], [8, 12], [15, 18]]
4
2
```

**The invariants:** merging keeps `merged` sorted and non-overlapping, so only its *last* interval can overlap the next one. The greedy keeps intervals that are compatible, with the last kept one ending as early as possible, which leaves the most room for the rest: the exchange argument from [Proving greedy](/dsa/learn/greedy-proofs). The sweep's running total is exactly the number of intervals open just after each event.

**Common bugs:**

- Comparing with the previous *input* interval instead of the last *merged* one. After `[1, 10]` and `[2, 3]`, the next interval must be compared with 10.
- Not deciding whether ends are inclusive. `merge` above treats `[8, 10]` and `[10, 12]` as touching and merges them; the sweep treats intervals as half-open, so a meeting ending at 10 frees its room for one starting at 10. Read the statement, then choose the comparison and the tie-break to match.
- Sorting by start for the "most non-overlapping" greedy. A long interval that starts first would block many short ones; sorting by end is what makes the greedy safe.

## Heaps: top k, k-way merge and two heaps

**Use it when** you repeatedly need the smallest or largest of a changing collection: the k largest, the next event in time order, the median so far. Swift's standard library has no heap, so you bring your own (or use DSAKit's, or the swift-collections package, from [swift-collections Heap](/dsa/learn/heap-swift-collections)). Learn the patterns in [Top K](/dsa/learn/heap-top-k), [Merge k sorted lists](/dsa/learn/heap-k-way-merge) and [Two heaps](/dsa/learn/heap-two-heaps).

The program below brings a small heap ordered by any rule, then uses it three ways:

```swift run
// A small binary heap: `isHigher(a, b)` says whether a belongs nearer the top than b
struct Heap<Element> {
    private var items: [Element] = []
    private let isHigher: (Element, Element) -> Bool
    init(_ isHigher: @escaping (Element, Element) -> Bool) { self.isHigher = isHigher }

    var count: Int { items.count }
    var top: Element? { items.first }

    mutating func push(_ element: Element) {
        items.append(element)
        var child = items.count - 1
        while child > 0, isHigher(items[child], items[(child - 1) / 2]) {
            items.swapAt(child, (child - 1) / 2)
            child = (child - 1) / 2
        }
    }

    mutating func pop() -> Element? {
        guard !items.isEmpty else { return nil }
        items.swapAt(0, items.count - 1)
        let removed = items.removeLast()
        var parent = 0
        while true {
            var best = parent
            for child in [2 * parent + 1, 2 * parent + 2] where child < items.count && isHigher(items[child], items[best]) {
                best = child
            }
            if best == parent { return removed }
            items.swapAt(parent, best)
            parent = best
        }
    }
}

// Top k: a MIN-heap of the k largest so far; the smallest of them sits on top, ready to be beaten
func largest(_ k: Int, of items: [Int]) -> [Int] {
    var heap = Heap<Int>(<)
    for value in items {
        heap.push(value)
        if heap.count > k { _ = heap.pop() }      // drop the smallest: it isn't in the top k
    }
    var result: [Int] = []
    while let value = heap.pop() { result.append(value) }
    return result.reversed()                      // largest first
}

// K-way merge: the heap holds the smallest unused value of each list, with where it came from
func mergeSorted(_ lists: [[Int]]) -> [Int] {
    var heap = Heap<(value: Int, list: Int, index: Int)>({ $0.value < $1.value })
    for (list, values) in lists.enumerated() where !values.isEmpty {
        heap.push((values[0], list, 0))
    }
    var merged: [Int] = []
    while let (value, list, index) = heap.pop() {
        merged.append(value)
        if index + 1 < lists[list].count {        // replace it with the next value from the same list
            heap.push((lists[list][index + 1], list, index + 1))
        }
    }
    return merged
}

// Two heaps: the running median. `lower` is a max-heap of the smaller half, `upper` a min-heap of the rest
func runningMedians(_ stream: [Int]) -> [Double] {
    var lower = Heap<Int>(>)
    var upper = Heap<Int>(<)
    var medians: [Double] = []
    for value in stream {
        if let top = lower.top, value > top { upper.push(value) } else { lower.push(value) }
        // Rebalance so lower has the same number as upper, or one more
        if lower.count > upper.count + 1 { upper.push(lower.pop()!) }
        if upper.count > lower.count { lower.push(upper.pop()!) }
        medians.append(lower.count > upper.count ? Double(lower.top!) : Double(lower.top! + upper.top!) / 2)
    }
    return medians
}

print(largest(3, of: [5, 1, 9, 3, 7, 9, 2]))
print(mergeSorted([[1, 4, 9], [2, 3, 10], [], [5]]))
print(runningMedians([5, 15, 1, 3, 8]))
```

```output
[9, 9, 7]
[1, 2, 3, 4, 5, 9, 10]
[5.0, 10.0, 5.0, 4.0, 5.0]
```

**The invariants:**

- **Top k:** the heap holds the k largest values seen so far, and its top is the smallest of them, the one a new value has to beat. That's why the k *largest* need a *min*-heap. Each value costs O(log k), so the whole pass is O(n log k).
- **K-way merge:** the heap holds the smallest unused value of each list. The overall smallest is on top, and when it's taken, the next value from the *same* list replaces it. O(N log k) for N values in k lists.
- **Two heaps:** `lower` holds the smaller half and `upper` the larger half, every value in `lower` is at most every value in `upper`, and `lower` has the same count as `upper` or one more. The median is then on top of one or both heaps.

**Common bugs:**

- The wrong heap direction. Say out loud what the top should be ("the smallest of the k largest") before choosing `<` or `>`.
- Forgetting to pop when the heap grows past k, which keeps every value and costs O(n log n).
- In the k-way merge, pushing the next value from the wrong list. Keep the list number and index with each value.
- In two heaps, rebalancing before adding, or forgetting one direction of the rebalance.

<Callout kind="tip" title="Quickselect: the k-th value without a heap">
If you need only the k-th smallest value of an array you're allowed to rearrange, and not a stream, [Quickselect](/dsa/learn/sort-quickselect) does it in O(n) on average by partitioning around random pivots and recursing into one side. A heap is the better choice when values arrive over time, when you need all k values in order, or when the worst case matters.
</Callout>

## Choosing among them

| Signal | Template |
| --- | --- |
| sorted input, find a position or count a range | lower and upper bound |
| a yes/no condition on positions that flips once | binary search on the condition |
| "smallest x that works", "largest minimum" | binary search on the answer |
| ranges that may overlap | sort by start or end, then sweep |
| "how many at the same time" | sweep line over +1/−1 events |
| k largest, k closest, k most frequent | heap of size k (or quickselect) |
| merge many sorted sources | k-way merge with a heap |
| median or balance of a stream | two heaps |
