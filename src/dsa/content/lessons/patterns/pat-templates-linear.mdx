## Why it matters

Arrays and strings make up most interview problems, and most of those fall to a handful of linear-time patterns: pointers, windows, prefix sums and stacks. You learned each in its own module. This lesson lines them up side by side, each as a short template you can write from memory, with the **invariant** that makes it correct and the **bugs** people actually write. The [Code templates](/dsa/sheets/templates) sheet has the bare skeletons; here you get the variations and the reasons.

## How to read a template

Every template below comes in four parts:

- **Use it when:** the signals in a problem that call for it.
- **The invariant:** the promise that's true after every step of the loop. If you can say it, you can place every line of the template, and you can check your own code.
- **The code**, run on a small input so you can see what it does.
- **Common bugs:** the mistakes that compile, run and give wrong answers.

Don't memorise the code character by character. Memorise the invariant, and rebuild the code from it.

## Two pointers from opposite ends

**Use it when** the input is sorted (or you can sort it) and you want a pair, or the problem is symmetric, like a palindrome. One pointer starts at each end and they walk towards each other. Learn it in [Opposite ends](/dsa/learn/tp-opposite-ends) and [Why two pointers work](/dsa/learn/tp-why-it-works).

**The invariant:** no pair that uses an index outside `left...right` can be the answer. Each move discards one element *together with every partner it has left*, which is why one pass is enough. The move rule is the only part that changes between problems:

```swift run
// Opposite ends: the pair rule decides which pointer moves
func pairWithSum(_ sorted: [Int], _ target: Int) -> (Int, Int)? {
    var left = 0
    var right = sorted.count - 1
    while left < right {                          // two different elements
        let sum = sorted[left] + sorted[right]
        if sum == target { return (left, right) }
        if sum < target {
            left += 1                             // sorted[left] is too small for every partner left
        } else {
            right -= 1                            // sorted[right] is too big for every partner left
        }
    }
    return nil
}

func mostWater(_ heights: [Int]) -> Int {
    var left = 0
    var right = heights.count - 1
    var best = 0
    while left < right {
        let area = min(heights[left], heights[right]) * (right - left)
        best = max(best, area)
        if heights[left] < heights[right] {
            left += 1                             // the shorter wall can't do better with anyone nearer
        } else {
            right -= 1
        }
    }
    return best
}

print(pairWithSum([1, 3, 4, 6, 8, 11], 10) ?? (-1, -1))
print(pairWithSum([2, 5], 4) == nil)
print(mostWater([1, 8, 6, 2, 5, 4, 8, 3, 7]))
```

```output
(2, 3)
true
49
```

**Common bugs:**

- `while left <= right` pairs an element with itself.
- Forgetting the input must be sorted. If the problem wants original indexes, sorting loses them: sort pairs of (value, index), or use a dictionary instead, as in [two sum](/dsa/learn/hash-frequency-two-sum).
- Moving the pointer that can't help. Before writing the move, say which element is ruled out and why.

## Read and write pointers

**Use it when** you must filter, compact or deduplicate an array **in place**. Both pointers move left to right: `read` looks at every element, and `write` marks where the next kept element goes. Learn it in [Read/write pointers](/dsa/learn/tp-read-write).

**The invariant:** `items[0..<write]` holds exactly the elements kept so far, in their original order.

```swift run
// Read/write pointers: keep each value at most twice, in place, in a sorted array
func keepAtMostTwo(_ items: inout [Int]) -> Int {
    var write = 0
    for read in items.indices {
        // Keep items[read] unless the last two kept values already equal it
        if write < 2 || items[read] != items[write - 2] {
            items[write] = items[read]
            write += 1
        }
    }
    return write                                  // items[0..<write] is the result
}

var scores = [1, 1, 1, 2, 2, 3, 3, 3, 3, 4]
let kept = keepAtMostTwo(&scores)
print(kept, Array(scores[0..<kept]))
```

```output
7 [1, 1, 2, 2, 3, 3, 4]
```

**Common bugs:**

- Comparing with `items[read - 1]` instead of the *kept* values, `items[write - 1]` or `items[write - 2]`. The element before `read` may already have been overwritten.
- Returning `write - 1`. `write` is a count, so it's already the length.
- Forgetting `inout` (and `&` at the call), so the function edits a copy.

## Fast and slow pointers

**Use it when** the input is a linked list (or a "next index" array) and you need the middle, a cycle, or the start of a cycle, with O(1) extra memory. Learn it in [Fast and slow pointers](/dsa/learn/ll-fast-slow).

**The invariant:** after k steps, slow has moved k nodes and fast 2k. So when fast reaches the end, slow is halfway; and inside a cycle, fast gains one node per step and must land on slow.

```swift run
// Fast and slow pointers on a linked list
final class Node {
    let value: Int
    var next: Node?
    init(_ value: Int) { self.value = value }
}

func makeList(_ values: [Int]) -> Node? {
    let dummy = Node(0)
    var tail = dummy
    for value in values {
        tail.next = Node(value)
        tail = tail.next!
    }
    return dummy.next
}

func middle(_ head: Node?) -> Node? {
    var slow = head
    var fast = head
    while let next = fast?.next {                 // fast can take two steps
        slow = slow?.next
        fast = next.next
    }
    return slow                                   // the second middle for even lengths
}

func hasCycle(_ head: Node?) -> Bool {
    var slow = head
    var fast = head
    while let next = fast?.next {
        slow = slow?.next
        fast = next.next
        if slow === fast { return true }          // identity, not equal values
    }
    return false
}

print(middle(makeList([1, 2, 3, 4, 5]))!.value)
print(middle(makeList([1, 2, 3, 4, 5, 6]))!.value)
let looped = makeList([1, 2, 3, 4])
looped!.next!.next!.next!.next = looped!.next     // 4 points back to 2
print(hasCycle(looped), hasCycle(makeList([1, 2, 3])))
```

```output
3
4
true false
```

**Common bugs:**

- Comparing values (`==`) instead of identity (`===`). Two different nodes can hold the same value.
- Getting the even-length middle wrong for the problem. This loop gives the second middle; starting `fast` at `head?.next` gives the first.
- Unwrapping `fast!.next!` without checking, which crashes at the end of the list.

## Fixed-size windows

**Use it when** the problem asks about every run of exactly `k` consecutive elements: the best total, an average, whether a window is an anagram of something. Learn it in [Fixed-size windows](/dsa/learn/sw-fixed).

**The invariant:** once `right ≥ k - 1`, the state describes exactly `items[right - k + 1...right]`.

```swift run
// Fixed-size window: the best total of any k consecutive values
func bestWindowSum(_ items: [Int], _ k: Int) -> Int? {
    guard k > 0, k <= items.count else { return nil }
    var sum = 0
    var best = Int.min
    for right in items.indices {
        sum += items[right]                       // grow
        if right >= k {
            sum -= items[right - k]               // the element that just left
        }
        if right >= k - 1 {
            best = max(best, sum)                 // a full window: items[right - k + 1...right]
        }
    }
    return best
}

print(bestWindowSum([4, -1, 3, 5, -2, 6, 1], 3) ?? "none")
print(bestWindowSum([-5, -2, -7], 2) ?? "none")
print(bestWindowSum([1, 2], 3) ?? "none")
```

```output
9
-7
none
```

**Common bugs:**

- Recording before the first window is full, or starting `best` at 0, which is wrong when every total is negative.
- Removing `items[right - k + 1]`, which is still inside the window. The element leaving is `items[right - k]`.

## Variable windows: longest and shortest

**Use it when** the problem asks for the longest or shortest *contiguous* stretch satisfying a rule, and the rule is **monotonic**: shrinking a valid window keeps it valid (for "longest"), or growing a goal-reaching window keeps it reaching (for "shortest"). Learn it in [A sliding window template](/dsa/learn/sw-template).

**The invariant (longest):** after the shrink loop, `items[left...right]` is valid, and it's the longest valid window ending at `right`. **The invariant (shortest):** inside the shrink loop, every window is a candidate, and `left` never passes a start that could still give a shorter answer.

```swift run
// Variable window, longest: the longest run of 1s if you may flip at most k zeros
func longestWithFlips(_ bits: [Int], _ k: Int) -> Int {
    var zeros = 0                                 // the window's state
    var left = 0
    var best = 0
    for right in bits.indices {
        if bits[right] == 0 { zeros += 1 }        // 1. grow
        while zeros > k {                         // 2. shrink while invalid
            if bits[left] == 0 { zeros -= 1 }
            left += 1
        }
        best = max(best, right - left + 1)        // 3. record the valid window
    }
    return best
}

// Variable window, shortest: the shortest run of positive values adding up to at least target
func shortestReaching(_ items: [Int], _ target: Int) -> Int {
    var sum = 0
    var left = 0
    var best = Int.max
    for right in items.indices {
        sum += items[right]
        while sum >= target {                     // shrink while the goal is still reached
            best = min(best, right - left + 1)    // record before removing
            sum -= items[left]
            left += 1
        }
    }
    return best == Int.max ? 0 : best
}

print(longestWithFlips([1, 1, 0, 0, 1, 1, 1, 0, 1, 0, 1], 2))
print(longestWithFlips([0, 0, 0], 0))
print(shortestReaching([2, 1, 5, 2, 3, 2], 7))
print(shortestReaching([1, 1, 1], 5))
```

```output
7
0
2
0
```

The two functions differ in exactly two places: the loop condition (shrink while *invalid* versus shrink while the goal is *met*) and where the answer is recorded (after the loop versus inside it). Everything else, the state and how it's updated, is shared.

**Common bugs:**

- Recording a "longest" answer before shrinking, which counts an invalid window.
- Forgetting to undo the state when `left` moves, so the counts drift.
- Using a window on sums with **negative numbers**. Adding a negative value lowers the sum, so validity isn't monotonic. Use prefix sums instead (below).
- Treating "exactly k" as a window rule. Count `atMost(k) - atMost(k - 1)` instead, from [The at-most-K trick](/dsa/learn/sw-at-most-k).

## Monotonic deque: the maximum of every window

**Use it when** a window question needs the **maximum or minimum** inside the window. A sum can be undone when an element leaves; a maximum can't, so the window needs help. Learn it in [Monotonic deque](/dsa/learn/queue-monotonic-deque).

**The invariant:** the deque holds indexes inside the window whose values *decrease* from front to back. The front is the window's maximum. Anything smaller than a newer element is removed, because it can never be a maximum again: the newer one is bigger and stays longer.

```visual arrayTrace
program: windowMax
input:
  items: [1, 3, -1, -3, 5, 3, 6, 7]
  k: 3
```

```swift run
// Monotonic deque: the maximum of every window of size k
func windowMaximums(_ items: [Int], _ k: Int) -> [Int] {
    var deque: [Int] = []                         // indexes; their values decrease from front to back
    var head = 0                                  // deque[head...] is live, so popping the front is O(1)
    var result: [Int] = []
    for right in items.indices {
        // Smaller values behind the newcomer can never be a maximum again
        while deque.count > head, items[deque[deque.count - 1]] <= items[right] {
            deque.removeLast()
        }
        deque.append(right)
        if deque[head] <= right - k { head += 1 } // the front has left the window
        if right >= k - 1 { result.append(items[deque[head]]) }
    }
    return result
}

print(windowMaximums([1, 3, -1, -3, 5, 3, 6, 7], 3))
print(windowMaximums([9, 8, 7, 6], 2))
```

```output
[3, 3, 5, 5, 6, 7]
[9, 8, 7]
```

**Common bugs:**

- Storing values instead of indexes. You then can't tell when the front has slid out of the window.
- Using `removeFirst()` on an array, which is O(n). A head index, or a real deque, keeps it O(1).

## Prefix sums for range totals

**Use it when** you need the total of many different ranges of an array that doesn't change. Pay O(n) once, then answer each range in O(1). Learn it in [1D prefix sums](/dsa/learn/prefix-1d), and the grid version in [2D prefix sums](/dsa/learn/prefix-2d).

**The invariant:** `prefix[i]` is the total of `items[0..<i]`. The leading 0 makes `prefix` one longer than `items`, and makes every range a single subtraction with no special case at index 0.

```swift run
// Prefix sums: build once, then any range total in O(1)
func prefixSums(_ items: [Int]) -> [Int] {
    var prefix = [0]                              // prefix[i] is the total of items[0..<i]
    prefix.reserveCapacity(items.count + 1)
    for value in items {
        prefix.append(prefix[prefix.count - 1] + value)
    }
    return prefix
}

let steps = [3, 1, 4, 1, 5, 9, 2, 6]
let prefix = prefixSums(steps)
func total(_ from: Int, _ to: Int) -> Int {      // items[from...to], both included
    prefix[to + 1] - prefix[from]
}
print(prefix)
print(total(2, 5), total(0, 7), total(3, 3))
```

```output
[0, 3, 4, 8, 9, 14, 23, 25, 31]
19 31 1
```

**Common bugs:**

- Off by one: the total of `items[from...to]` is `prefix[to + 1] - prefix[from]`, not `prefix[to] - prefix[from]`.
- Updating `items` after building `prefix`. The prefix array goes stale. If values change between queries, you need a Fenwick or segment tree, which arrive in Part VIII.

## Prefix sums with a dictionary

**Use it when** you need subarrays with an exact sum, and values can be negative, or a condition you can turn into one, such as "equally many 0s and 1s" (count 0 as −1). Learn it in [Prefix sum + hashmap](/dsa/learn/prefix-hashmap).

**The invariant:** when you're at index `i`, the dictionary holds the prefix sums that end *before* `i`. A subarray ending at `i` sums to `k` exactly when some earlier prefix equals `prefix - k`. Count earlier prefixes to count subarrays; remember each prefix's **first** position to find the longest.

```swift run
// Prefix sums + dictionary: count, and find the longest, subarrays adding up to k
func countSumming(to k: Int, in items: [Int]) -> Int {
    var seen: [Int: Int] = [0: 1]                 // prefix value → how many times so far
    var prefix = 0
    var count = 0
    for value in items {
        prefix += value
        count += seen[prefix - k, default: 0]     // look up first...
        seen[prefix, default: 0] += 1             // ...then record
    }
    return count
}

func longestSumming(to k: Int, in items: [Int]) -> Int {
    var first: [Int: Int] = [0: -1]               // prefix value → first index it appeared after
    var prefix = 0
    var best = 0
    for (i, value) in items.enumerated() {
        prefix += value
        if let start = first[prefix - k] {
            best = max(best, i - start)
        }
        if first[prefix] == nil {                 // keep the earliest: never overwrite
            first[prefix] = i
        }
    }
    return best
}

let changes = [2, -1, 1, 3, -3, 0, 2, -2]
print(countSumming(to: 0, in: changes), longestSumming(to: 0, in: changes))
print(countSumming(to: 3, in: changes), longestSumming(to: 3, in: changes))
```

```output
10 7
3 5
```

**Common bugs:**

- Leaving out the seed (`[0: 1]` for counting, `[0: -1]` for longest). Subarrays that start at index 0 are then missed.
- Recording before looking up. With `k = 0`, every position would match itself and count an empty subarray.
- Overwriting the first position, which shortens the "longest" answers.

## Difference arrays for range updates

**Use it when** many updates each add a value to a whole range, and you only need the final array. It's prefix sums run backwards. Learn it in [Difference arrays](/dsa/learn/prefix-difference-array).

**The invariant:** the running total of `difference[0...i]` is the final value at `i`. An update to `from...to` touches only two slots: `+v` where it starts and `-v` right after it ends.

```swift run
// Difference array: many range additions, then one pass to read the result
func applyBookings(_ count: Int, _ bookings: [(from: Int, to: Int, seats: Int)]) -> [Int] {
    var difference = Array(repeating: 0, count: count + 1)   // one extra slot for to + 1
    for booking in bookings {
        difference[booking.from] += booking.seats            // starts here
        difference[booking.to + 1] -= booking.seats          // stops after `to`
    }
    var result: [Int] = []
    var running = 0
    for i in 0..<count {
        running += difference[i]
        result.append(running)
    }
    return result
}

print(applyBookings(6, [(0, 2, 10), (1, 4, 5), (4, 5, 3)]))
```

```output
[10, 15, 15, 5, 8, 3]
```

**Common bugs:** sizing `difference` as `count`, so `to + 1` overflows the array when a range ends at the last index; and forgetting the final running-total pass.

## Stacks for nesting

**Use it when** things open and close in nested order: brackets, tags, folders in a path, "undo". The most recent unfinished thing is always the one to finish next, which is exactly what a stack gives you. Learn it in [Balanced parentheses](/dsa/learn/stack-parentheses) and [Decode string and simplify path](/dsa/learn/stack-decode-simplify).

**The invariant:** the stack holds the openers that haven't been closed yet, innermost on top.

```swift run
// A stack for nesting: are the brackets balanced?
func isBalanced(_ text: String) -> Bool {
    let opener: [Character: Character] = [")": "(", "]": "[", "}": "{"]
    var stack: [Character] = []
    for character in text {
        if let needed = opener[character] {       // a closer
            guard stack.popLast() == needed else { return false }
        } else if "([{".contains(character) {     // an opener
            stack.append(character)
        }
    }
    return stack.isEmpty                          // nothing left unclosed
}

for text in ["a[b(c)]{d}", "(]", "((x)", "x)"] {
    print(text, isBalanced(text))
}
```

```output
a[b(c)]{d} true
(] false
((x) false
x) false
```

`popLast()` returns `nil` on an empty stack, and `nil == "("` is false, so a closer with nothing open fails safely. `removeLast()` would crash there instead.

**Common bugs:** popping an empty stack, and forgetting the final `isEmpty` check, which is what catches `"((x)"`.

## Monotonic stacks

**Use it when** each element needs its **next or previous greater or smaller** element: days until a warmer day, the span of a stock price, the widest rectangle in a histogram. Learn it in [Monotonic stack](/dsa/learn/stack-monotonic-intro) and [Largest rectangle in a histogram](/dsa/learn/stack-histogram).

**The invariant:** the stack holds the indexes whose answer isn't known yet, and their values are sorted (never rising, for "next greater"). When a new element breaks the order, everything it pops has found its answer: the new element.

```swift run
// Monotonic stack: how many days until a warmer one, and the nearest smaller value to the left
func daysUntilWarmer(_ temperatures: [Int]) -> [Int] {
    var wait = Array(repeating: 0, count: temperatures.count)
    var stack: [Int] = []                         // indexes still waiting; temperatures never rise going up
    for today in temperatures.indices {
        while let last = stack.last, temperatures[last] < temperatures[today] {
            stack.removeLast()
            wait[last] = today - last             // today is the answer for `last`
        }
        stack.append(today)
    }
    return wait                                   // anything left on the stack keeps 0
}

func previousSmaller(_ items: [Int]) -> [Int] {
    var result = Array(repeating: -1, count: items.count)
    var stack: [Int] = []                         // values strictly increase going up
    for i in items.indices {
        while let last = stack.last, items[last] >= items[i] {
            stack.removeLast()                    // can never be anyone's previous smaller again
        }
        if let last = stack.last { result[i] = items[last] }
        stack.append(i)
    }
    return result
}

print(daysUntilWarmer([15, 14, 16, 13, 12, 18, 17]))
print(previousSmaller([4, 6, 5, 2, 7, 5]))
```

```output
[2, 1, 3, 2, 1, 0, 0]
[-1, 4, 4, -1, 2, 2]
```

There are four variants, and they differ only in the comparison and in when you read the answer:

| You want | Pop while the top is… | Answer is read |
| --- | --- | --- |
| next greater | smaller than the new element | for each popped index |
| next smaller | greater than the new element | for each popped index |
| previous greater | smaller than or equal to the new element | from the top, after popping |
| previous smaller | greater than or equal to the new element | from the top, after popping |

**Common bugs:**

- `<` versus `<=` when values repeat. Decide whether "greater" means strictly greater, and test with duplicates.
- Pushing values instead of indexes, when the answer is a distance.
- Forgetting the elements left on the stack at the end: they have no answer, so they keep the default.

## Choosing among them

| Signal | Template |
| --- | --- |
| sorted input, a pair or a palindrome | opposite-end pointers |
| filter or deduplicate in place | read/write pointers |
| linked list: middle or cycle | fast and slow pointers |
| every run of exactly k | fixed window |
| longest or shortest run, monotonic rule | variable window |
| max or min of every window | monotonic deque |
| many range totals, no updates | prefix sums |
| exact sums with negatives, or "balanced" counts | prefix sums + dictionary |
| many range additions, read once | difference array |
| nested opening and closing | stack |
| next or previous greater or smaller | monotonic stack |

<Callout kind="gotcha" title="Swift gotchas across these templates">
- **Indexing a `String`.** None of these templates index a `String` directly: Swift strings aren't random access. Convert first with `Array(text)` (or `Array(text.utf8)` for ASCII speed), as in [Array(s) and \[UInt8\] for fast access](/dsa/learn/swift-string-to-array).
- **`removeFirst()` is O(n)** on an array. Use a head index, or `popLast()` when the order allows.
- **`Int.max` as "no answer yet"** is fine for minimums, but never add to it: `Int.max + 1` crashes.
</Callout>
