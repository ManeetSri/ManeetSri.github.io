## Why it matters

Recursion is how you'll walk trees, explore graphs, generate every arrangement in backtracking, split problems in divide and conquer and write dynamic programming top-down. In app code it shows up whenever data contains smaller copies of itself: folders inside folders, views inside views, comments with replies that have replies. This module turns the first look you had in M05 into a tool you can reach for with confidence.

## Where you are

In [A first look at recursion](/dsa/learn/swift-first-recursion) you met the two essential parts:

- a **base case** that answers directly, without calling the function again;
- a **recursive case** that does a little work and calls the same function on a **smaller** input.

You also saw that every call gets its own stack frame, and that a recursion with no base case crashes. This lesson is about the skill that comes next: looking at a new problem and *finding* the recursion in it.

## Thinking recursively: three questions

When you suspect a problem is recursive, ask three questions, in this order:

1. **What's the smallest version I can answer straight away?** That's your base case. Typical answers: `n == 0`, an empty array, a single character, a folder with nothing inside.
2. **If someone handed me the answer to a slightly smaller version, how would I build my answer from it?** That's the heart of the recursive case.
3. **How do I make the input smaller, so that it's guaranteed to reach the base case?** Subtract one, divide by ten, move an index along, take a child.

Here's the method on a fresh problem: count the digits of a whole number.

1. Smallest version: a number below 10 has exactly one digit.
2. If I knew how many digits `n / 10` has (that's `n` with its last digit chopped off), my answer is one more than that.
3. Dividing by 10 makes the number smaller, so it must eventually drop below 10.

The code is those three answers, written down:

```swift run
func digitCount(_ n: Int) -> Int {
    if n < 10 {
        return 1                      // base case: a single digit
    }
    return 1 + digitCount(n / 10)     // drop the last digit, count the rest
}

print(digitCount(7))
print(digitCount(2026))
print(digitCount(1_000_000))
```

```output
1
4
7
```

`digitCount(2026)` becomes `1 + digitCount(202)`, then `1 + 1 + digitCount(20)`, then `1 + 1 + 1 + digitCount(2)`, which is the base case. The answer is 4. (The function assumes `n ≥ 0`: a negative number is below 10, so it would wrongly report one digit.)

## Trust the recursive call

The hardest part of recursion isn't the code. It's resisting the urge to trace every call in your head. For a recursion 1,000 calls deep, you can't, and you don't need to.

Instead, write down the function's **promise** in one sentence: "`digitCount(n)` returns how many digits `n` has, for any `n ≥ 0`." Then, while writing the recursive case, *assume the promise already holds for smaller inputs*. If `digitCount(202)` really does return 3, then `1 + digitCount(202)` really is 4. That assumption is safe as long as two things are true:

- the base case keeps the promise on its own;
- every recursive call is on a smaller input, so the calls must eventually reach the base case.

Mathematicians call this argument **induction**. Programmers often call it the recursive leap of faith. It's not really faith: it's the same reasoning that proves the function correct.

<Callout kind="analogy" title="A manager who delegates">
Picture a manager asked to count the digits on a long serial number. She covers the last digit with her thumb and hands the rest to an assistant: "How many digits here?" She doesn't care how the assistant works it out. When the answer comes back, she adds one for the digit under her thumb. The assistant does exactly the same with *their* assistant, until someone is handed a single digit and answers "one" without asking anyone.
</Callout>

## Choosing the base case

A base case has one job: stop every input that should stop. Three habits help.

**Catch everything, not one exact value.** Prefer `n <= 0` to `n == 0` when negative inputs are possible, so a bad input stops instead of running forever.

**Some functions need more than one base case.** Here's a check for whether a number is a power of two, which you met from the bit-manipulation side in M16. A power of two can be halved again and again until it reaches exactly 1, with every halving exact:

```swift run
func isPowerOfTwo(_ n: Int) -> Bool {
    if n == 1 {
        return true                       // 2⁰
    }
    if n < 1 || n % 2 == 1 {
        return false                      // zero, negatives and odd numbers
    }
    return isPowerOfTwo(n / 2)
}

for n in [1, 2, 6, 64, 96, 0, -8] {
    print(n, isPowerOfTwo(n))
}
```

```output
1 true
2 true
6 false
64 true
96 false
0 false
-8 false
```

There are two ways to stop: reaching 1 means yes, and anything that can't be halved exactly means no. The **order** matters: 1 is odd, so the `n == 1` check must come before the odd check. 96 halves to 48, 24, 12, 6 and then 3, which is odd, so the answer is `false`.

**"Smaller" doesn't always mean subtracting one.** Euclid's algorithm for the greatest common divisor, from M15, is naturally recursive. The gcd of `a` and `b` is the gcd of `b` and `a % b`, and the gcd of any number and 0 is that number:

```swift run
func gcd(_ a: Int, _ b: Int) -> Int {
    if b == 0 {
        return a
    }
    return gcd(b, a % b)
}

print(gcd(48, 18))
print(gcd(17, 5))
print(gcd(10, 0))
```

```output
6
1
10
```

What gets smaller here is the second argument: `a % b` is always less than `b`, so it must reach 0. `gcd(48, 18)` calls `gcd(18, 12)`, then `gcd(12, 6)`, then `gcd(6, 0)`, which returns 6.

## Recursive data, recursive code

Some data is defined in terms of itself. A folder holds files and **other folders**. An expression tree from [Indirect enums for recursive data](/dsa/learn/swift-indirect-enums) holds smaller expressions. When the data has that shape, the code that processes it almost always has the same shape:

```swift run
struct Folder {
    let name: String
    let files: Int
    let subfolders: [Folder]
}

func totalFiles(in folder: Folder) -> Int {
    var total = folder.files
    for subfolder in folder.subfolders {
        total += totalFiles(in: subfolder)
    }
    return total
}

let photos = Folder(name: "Photos", files: 120, subfolders: [
    Folder(name: "2025", files: 40, subfolders: []),
    Folder(name: "2026", files: 15, subfolders: [
        Folder(name: "Holiday", files: 60, subfolders: []),
    ]),
])
print(totalFiles(in: photos))
```

```output
235
```

What to notice:

- A struct can hold an **array** of itself, because the array stores its elements elsewhere in memory. It can't hold a plain `Folder` property: as you saw in M09, a value containing a whole copy of itself would need infinite space.
- There's no `if` for the base case. A folder with no subfolders runs the loop zero times and returns its own count. The base case is still there; it's hidden in the empty loop.
- "Smaller" means a subfolder, which is part of the folder you started with. Since the structure is finite, the calls must end.

## When recursion goes wrong

Almost every broken recursion is one of four mistakes:

| Mistake | Example | What happens |
| --- | --- | --- |
| No base case | forgetting the `if` entirely | stack overflow |
| Base case can be skipped | stepping by 2 towards `n == 0` from an odd `n` | stack overflow |
| Input doesn't shrink | calling `f(n)` from inside `f(n)` | stack overflow |
| Shrinks the wrong way | calling `f(n + 1)` when the base case is at 0 | stack overflow |

The second one is the sneakiest, because the base case *looks* fine:

```swift
func countDownByTwo(from n: Int) {
    if n == 0 {
        return
    }
    print(n)
    countDownByTwo(from: n - 2)
}

countDownByTwo(from: 5)
```

```text title="What you'll see"
5
3
1
-1
-3
...
```

From 5 the values go 3, 1, −1, and never land on 0. It prints numbers until the stack runs out and the program crashes. Changing the base case to `n <= 0` fixes it for every input.

<Callout kind="gotcha" title="Check the promise at the edges">
Before trusting a recursive function, call it in your head on the smallest inputs: 0, 1, an empty array, a single character. If the base case doesn't give the right answer there, nothing built on top of it will. Most recursion bugs sit right at the bottom.
</Callout>
