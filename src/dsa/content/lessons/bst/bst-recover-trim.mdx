## Why it matters

Three interview favourites, each a small twist on a traversal you already know. **Recovering** a tree where two values were swapped is the inorder "drops" idea from [Validate a BST](/dsa/learn/bst-validate), pushed one step further. **Trimming** a tree to a range shows how the BST property lets you throw away whole subtrees without looking inside them. And the **greater-sum tree** walks the values in decreasing order with a running total. Together they cover the three ways BST problems usually use the ordering: inorder is sorted, comparisons rule out subtrees, and reverse inorder is sorted backwards.

## Recover a BST with two swapped values

Someone swapped the values of two nodes, and the tree is no longer a BST. Put it right by swapping them back, without moving any nodes.

Start from what you know: the inorder sequence of a correct BST is sorted. Swapping two values in the tree swaps two values in that sequence. So the question becomes: in a sorted list with two values swapped, how do you find them?

Look for **drops**: places where a value is smaller than the one before it.

```text
neighbours swapped:   1  2  4  3  5  6      one drop:  4 > 3
far apart swapped:    1  5  3  4  2  6      two drops: 5 > 3 and 4 > 2
```

- When the two swapped values were **next to each other** in sorted order, there's one drop, and the two values at it are the culprits: 4 and 3.
- When they were **further apart**, there are two drops. The bigger value at the first drop moved too early (5), and the smaller value at the last drop moved too late (2).

One rule covers both: **the first culprit is the bigger value at the first drop; the second is the smaller value at the last drop.** With one drop, "first" and "last" are the same drop.

So do an inorder walk, keeping a reference to the previous node. At each drop, set `first` if it's still empty, and set `second` every time. At the end, swap their values:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func recover(_ root: TreeNode?) {
    var first: TreeNode? = nil
    var second: TreeNode? = nil
    var previous: TreeNode? = nil
    var stack: [TreeNode] = []
    var current = root
    while current != nil || !stack.isEmpty {
        while let node = current {
            stack.append(node)
            current = node.left
        }
        let node = stack.removeLast()
        if let previous, previous.value > node.value {      // a drop
            if first == nil {
                first = previous
            }
            second = node
        }
        previous = node
        current = node.right
    }
    if let first, let second {
        print("swapping \(first.value) and \(second.value) back")
        (first.value, second.value) = (second.value, first.value)
    }
}

func inorder(_ node: TreeNode?) -> [Int] {
    guard let node else { return [] }
    return inorder(node.left) + [node.value] + inorder(node.right)
}

// 50, 30, 70, 20, 40, 60, 80 with 30 and 40 swapped (neighbours in sorted order)
let near = TreeNode(50, left: TreeNode(40, left: TreeNode(20), right: TreeNode(30)),
                        right: TreeNode(70, left: TreeNode(60), right: TreeNode(80)))
print(inorder(near))
recover(near)
print(inorder(near))

// The same tree with 20 and 70 swapped (far apart)
let far = TreeNode(50, left: TreeNode(30, left: TreeNode(70), right: TreeNode(40)),
                       right: TreeNode(20, left: TreeNode(60), right: TreeNode(80)))
print(inorder(far))
recover(far)
print(inorder(far))
```

```output
[20, 40, 30, 50, 60, 70, 80]
swapping 40 and 30 back
[20, 30, 40, 50, 60, 70, 80]
[70, 30, 40, 50, 60, 20, 80]
swapping 70 and 20 back
[20, 30, 40, 50, 60, 70, 80]
```

What to notice:

- In the second tree the drops are 70 > 30 (first drop: take 70) and 60 > 20 (last drop: take 20).
- The walk keeps **nodes**, not values, so it can change them at the end. Only two values change; every node stays where it was.
- One inorder walk: **O(n)** time, and O(h) for the stack. [Morris traversal](/dsa/learn/trav-morris) can do the same walk in O(1) extra space, by temporarily threading right pointers back up the tree.

<Callout kind="gotcha" title="Set second at every drop">
A common slip records `second` only at the second drop. With neighbours swapped there is no second drop, so `second` stays `nil` and nothing is fixed. Setting `second = node` at **every** drop handles both cases: with one drop it's that drop's smaller value; with two, the second drop overwrites it.
</Callout>

## Trim a BST to a range

Given a range `low...high`, remove every node whose value lies outside it, and keep everything else in the same relative arrangement: if one surviving node was below another, it still is. Return the new root, which may be a different node.

The BST property makes this fast. At each node:

- **too small** (`value < low`): the node is out, and so is its whole **left** subtree, which is even smaller. Only the right subtree can hold survivors, so the answer for this subtree is the trimmed right subtree.
- **too big** (`value > high`): the node and its whole right subtree are out. Return the trimmed left subtree.
- **in range**: keep the node, trim both children, and re-link them.

It's the "return the new subtree root" pattern from [Deleting from a BST](/dsa/learn/bst-delete) again:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func trim(_ node: TreeNode?, to range: ClosedRange<Int>) -> TreeNode? {
    guard let node else { return nil }
    if node.value < range.lowerBound {
        return trim(node.right, to: range)            // node and its left subtree are all too small
    }
    if node.value > range.upperBound {
        return trim(node.left, to: range)             // node and its right subtree are all too big
    }
    node.left = trim(node.left, to: range)
    node.right = trim(node.right, to: range)
    return node
}

func draw(_ node: TreeNode?, _ indent: String = "") {
    guard let node else { return }
    draw(node.right, indent + "    ")
    print(indent + String(node.value))
    draw(node.left, indent + "    ")
}

func sample() -> TreeNode {
    TreeNode(50,
             left: TreeNode(30, left: TreeNode(20), right: TreeNode(40, left: TreeNode(35))),
             right: TreeNode(70, left: TreeNode(60, right: TreeNode(65)), right: TreeNode(80)))
}

print("trim to 33...65:")
draw(trim(sample(), to: 33...65))
print("trim to 55...100:")
draw(trim(sample(), to: 55...100))
```

```output
trim to 33...65:
        65
    60
50
    40
        35
trim to 55...100:
    80
70
        65
    60
```

What to notice:

- In the first trim, 30 is too small, so it's replaced by its trimmed right subtree, 40 with 35. 20 vanishes without ever being visited. On the right, 70 is too big and is replaced by its trimmed left subtree, 60 with 65.
- In the second, the root itself is too small, so the answer is the trimmed right subtree, and 70 becomes the new root. That's why the function returns a node.
- Discarded subtrees are never visited, so the cost is at most O(n), and often much less. The recursion is O(h) deep.

## The greater-sum tree

Replace every value with the sum of all values in the tree that are **greater than or equal to it**. The largest value keeps its own value; the next one adds the largest; and so on down.

That's a running total over the values in **decreasing** order. Reverse inorder (right subtree, node, left subtree) visits them in exactly that order, so keep a total, add each value to it, and write the total back:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func greaterSumTree(_ root: TreeNode?) {
    var total = 0
    func walk(_ node: TreeNode?) {
        guard let node else { return }
        walk(node.right)                              // bigger values first
        total += node.value
        node.value = total
        walk(node.left)
    }
    walk(root)
}

func inorder(_ node: TreeNode?) -> [Int] {
    guard let node else { return [] }
    return inorder(node.left) + [node.value] + inorder(node.right)
}

let root = TreeNode(4, left: TreeNode(2, left: TreeNode(1), right: TreeNode(3)),
                       right: TreeNode(6, left: TreeNode(5), right: TreeNode(7)))
print(inorder(root))
greaterSumTree(root)
print(inorder(root))
print(root.value)
```

```output
[1, 2, 3, 4, 5, 6, 7]
[28, 27, 25, 22, 18, 13, 7]
22
```

7 stays 7, 6 becomes 6 + 7 = 13, 5 becomes 18, and the root 4 becomes 4 + 5 + 6 + 7 = 22. One walk: O(n) time, O(h) stack. A variant asks for the sum of values **strictly** greater: write the total back **before** adding the node's own value.

Notice the result's inorder sequence is **decreasing**, so it's no longer a BST. That's expected: the problem asks for new values in the same shape, not a search tree.

<Callout kind="gotcha" title="Captured state in a nested function">
`walk` is a nested function that changes `total`, a variable of the function around it. Swift allows this: the nested function captures `total` by reference, so every call sees and updates the same variable, as with closures in [Capturing values](/dsa/learn/swift-capturing). A separate top-level function would need `total` passed as an `inout` parameter instead.
</Callout>

## Practice

**Repair a BST with two swapped values** is the first problem here. Before coding, write out the inorder sequence of the examples, mark the drops, and check that "bigger value at the first drop, smaller value at the last drop" picks the right two. The tests try every pair of swapped values in a small tree, including neighbours and the root.

```cards
- id: recover-one-drop
  front: "When does a BST with two swapped values show only one drop in its inorder sequence?"

  front: "When trimming a BST to low...high, what happens at a node smaller than low?"
  back: "The node and its whole left subtree are out. The result for that subtree is the trimmed right subtree."
- id: greater-sum
  front: "How do you turn a BST into a greater-sum tree?"
  back: "Walk in reverse inorder (right, node, left), keeping a running total; add each value to the total and write the total back into the node."
```
