## Why it matters

"What's the earliest meeting today?" is a minimum. "Which meeting comes right after this one?" is a successor. Ordered data is useful precisely because you can ask about neighbours, not only whether a value exists, and a BST answers these questions by walking one path, in O(h). You've already used one of them: deletion's two-child case needs the smallest value in the right subtree. This lesson covers all four, and two ways to find a successor: one for trees whose nodes know their parent, and one for trees whose nodes don't.

## Min and max: keep going one way

Everything smaller than a node is to its left. So the smallest value in the whole tree is found by going left from the root until there's no left child. The largest is found by going right:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func minimum(_ root: TreeNode?) -> TreeNode? {
    guard var node = root else { return nil }
    while let left = node.left {
        node = left
    }
    return node
}

func maximum(_ root: TreeNode?) -> TreeNode? {
    guard var node = root else { return nil }
    while let right = node.right {
        node = right
    }
    return node
}

let root = TreeNode(50,
                    left: TreeNode(30, left: TreeNode(20), right: TreeNode(40, left: TreeNode(35))),
                    right: TreeNode(70, left: TreeNode(60, right: TreeNode(65)), right: TreeNode(80)))
print(minimum(root)?.value as Any, maximum(root)?.value as Any)
print(minimum(root.right)?.value as Any)           // the smallest in 50's right subtree
print(minimum(nil)?.value as Any)
```

```output
Optional(20) Optional(80)
Optional(60)
nil
```

What to notice:

- The minimum is the **leftmost** node, not necessarily a leaf: it can have a right child. In a tree built from 20 then 25, the minimum 20 has 25 as its right child.
- `minimum(root.right)` works on any subtree. That's the successor search inside delete.
- Both take O(h): one step per level.

## Successor and predecessor

The **successor** of a value is the next one up in sorted order: the value that comes straight after it in an inorder walk. The **predecessor** is the one straight before. In the tree above, sorted order is 20, 30, 35, 40, 50, 60, 65, 70, 80, so the successor of 40 is 50 and the predecessor of 60 is 50. The maximum has no successor, and the minimum has no predecessor.

You could do an inorder walk and stop one step after the value, but that's O(n). The tree's shape gives an O(h) answer, and it splits into two cases.

**Case 1: the node has a right subtree.** Everything in it is bigger than the node, and it's the closest bigger stuff: anything bigger outside it is also bigger than the whole subtree. So the successor is the **minimum of the right subtree**. The successor of 30 is the minimum of \{40, 35\}: 35.

**Case 2: no right subtree.** Then nothing below is bigger. Look upwards. Climb from the node towards the root: while you're climbing up from a **right** child, the parent is smaller (you were in its right subtree), so keep going. The first time you climb up from a **left** child, that parent is bigger than everything you've passed, and it's the successor. The successor of 40 climbs 40 → 30 (from a right child: 30 is smaller) → 50 (from a left child): 50. If you reach the root without ever climbing from a left child, the node was the maximum.

The predecessor is the mirror image: the maximum of the left subtree, or else the first ancestor you reach by climbing up from a **right** child.

## With parent pointers

Case 2 climbs upwards, so the simplest version gives every node a link to its parent. That link must be `weak`. A parent already holds a strong reference to its child; a strong reference back would make a retain cycle, and ARC would never free the tree ([weak and unowned references](/dsa/learn/swift-weak-unowned)).

```swift run
final class Node {
    var value: Int
    var left: Node?
    var right: Node?
    weak var parent: Node?                     // weak: the parent already owns this node

    init(_ value: Int) {
        self.value = value
    }
}

func insert(_ value: Int, into root: Node?) -> Node {
    let fresh = Node(value)
    guard let root else { return fresh }
    var node = root
    while true {
        if value < node.value {
            guard let left = node.left else { node.left = fresh; break }
            node = left
        } else {                               // bigger (this example has no repeats)
            guard let right = node.right else { node.right = fresh; break }
            node = right
        }
    }
    fresh.parent = node
    return root
}

func successor(of node: Node) -> Node? {
    if var next = node.right {                 // case 1: the minimum of the right subtree
        while let left = next.left {
            next = left
        }
        return next
    }
    var child = node                           // case 2: climb until we come up from a left child
    while let parent = child.parent {
        if parent.left === child {
            return parent
        }
        child = parent
    }
    return nil                                 // we were the maximum
}

func find(_ value: Int, in root: Node) -> Node? {
    var current: Node? = root
    while let node = current, node.value != value {
        current = value < node.value ? node.left : node.right
    }
    return current
}

var root: Node? = nil
for value in [50, 30, 70, 20, 40, 60, 80, 35, 65] {
    root = insert(value, into: root)
}
for value in [30, 40, 65, 80] {
    let next = successor(of: find(value, in: root!)!)
    print("after \(value):", next.map { String($0.value) } ?? "none")
}
```

```output
after 30: 35
after 40: 50
after 65: 70
after 80: none
```

65 has no right child, and it's the right child of 60, so the climb passes 60 and continues to 70, where it arrives from a left child. 80 climbs all the way from right children and runs out of parents.

What to notice:

- `parent.left === child` compares **identity** with `===`: the question is "is this very node the left child?", not "do they hold equal values?".
- Every insert and delete now has to keep `parent` correct as well as `left` and `right`: more bookkeeping, more room for bugs.
- Walking from any node to its successor is O(h). Walking through **all** nodes this way costs O(n) in total, because each edge is crossed at most twice, once down and once up.

## Without parent pointers: walk from the root

The `TreeNode` in this course has no parent link. You can still find the successor of a value, because the ancestors you'd climb through are exactly the nodes on the path from the root. Walk down from the root as if searching for the value. **Every time you go left, the node you leave is bigger than the value: remember it as a candidate.** Each later candidate is smaller than the earlier ones (you went left of them), so the last one remembered is the closest. When you reach the node itself, if it has a right subtree, the minimum there beats every candidate.

There's an even simpler way to say it: the successor of `x` is **the smallest value bigger than `x`**. You can find that without caring whether `x` is in the tree:

```swift run
final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

// The smallest value bigger than x, or nil
func successor(of x: Int, in root: TreeNode?) -> Int? {
    var best: Int? = nil
    var current = root
    while let node = current {
        if node.value > x {
            best = node.value                  // a candidate; look for a smaller one on the left
            current = node.left
        } else {
            current = node.right               // too small (or equal): the answer is to the right
        }
    }
    return best
}

// The biggest value smaller than x, or nil
func predecessor(of x: Int, in root: TreeNode?) -> Int? {
    var best: Int? = nil
    var current = root
    while let node = current {
        if node.value < x {
            best = node.value
            current = node.right
        } else {
            current = node.left
        }
    }
    return best
}

let root = TreeNode(50,
                    left: TreeNode(30, left: TreeNode(20), right: TreeNode(40, left: TreeNode(35))),
                    right: TreeNode(70, left: TreeNode(60, right: TreeNode(65)), right: TreeNode(80)))
for x in [40, 65, 80, 45, 10] {
    print(x, "successor:", successor(of: x, in: root) as Any, "predecessor:", predecessor(of: x, in: root) as Any)
}
```

```output
40 successor: Optional(50) predecessor: Optional(35)
65 successor: Optional(70) predecessor: Optional(60)
80 successor: nil predecessor: Optional(70)
45 successor: Optional(50) predecessor: Optional(40)
10 successor: Optional(20) predecessor: nil
```

What to notice:

- One loop, no special cases. When `x` is in the tree and has a right subtree, the walk goes right at `x` and then left all the way: the minimum of the right subtree, case 1, found naturally.
- 45 isn't in the tree, and the answer still makes sense: 50 is the smallest value bigger than 45. This is a "nearest neighbour" query, and it's the idea behind floor and ceiling in [Floor, ceiling and a BST iterator](/dsa/learn/bst-floor-ceil-iterator).
- O(h) time and O(1) space, and the tree needs no parent pointers.

<Callout kind="gotcha" title="Swift gotcha: a strong parent link leaks the whole tree">
Declare `var parent: Node?` without `weak` and every parent–child pair forms a retain cycle. Setting `root = nil` then frees nothing: each node is kept alive by its children, which are kept alive by it. `weak var parent: Node?` doesn't keep the parent alive, and becomes `nil` on its own if the parent is freed. It must be an optional `var`, because ARC needs to be able to set it to `nil`.
</Callout>

## Choosing a version

| | Parent pointers | Walk from the root |
| --- | --- | --- |
| Successor of a node you already hold | O(h), climbs from the node | needs the node's value; O(h) from the root |
| Extra memory | one weak pointer per node | none |
| Insert and delete | must keep `parent` correct | unchanged |
| Value not in the tree | not applicable | works: "smallest bigger than x" |

Most interview problems give you a `TreeNode` without a parent, so the walk from the root is the one to know by heart. Parent pointers appear in some problem variants and in real tree libraries, where they make stepping through the tree cheap.
