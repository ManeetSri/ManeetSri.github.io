## Why it matters

"Which people are exactly two steps away from me in this family tree?" sounds easy until you notice that a tree's links only point **down**. Some of those people are cousins, reached by going up first. The fix, recording every node's parent so you can move in any direction, turns the tree into a **graph**, and from then on a breadth-first search does the work. It's your first step towards the graph algorithms of a later part. The second problem, the width of a tree's widest level, is what you need to lay out a tree diagram such as an org chart, and it hides a Swift trap: numbers that silently grow until they overflow.

## Nodes at distance K

> Given a target node and a number k, find every node exactly k edges away from the target, in any direction.

```text
            7
          /   \
         3     9
        / \     \
       1   5     12
          / \
         4   6
```

From 5: at distance 1 are 3, 4 and 6. At distance 2 are 1 and 7. At distance 3 is 9, and at distance 4 is 12. Only 4 and 6 are below 5; everything else is reached by going **up** through 3 first.

### Step 1: record every parent

One walk over the tree records each node's parent in a dictionary. As in [Lowest common ancestor](/dsa/learn/bt-lca), the keys are `ObjectIdentifier`s, because a class isn't `Hashable`. Now every node has up to three neighbours: left, right and parent. That's an **undirected graph**: you can walk any edge both ways.

### Step 2: search outwards from the target

A breadth-first search, from [A preview of BFS](/dsa/learn/queue-bfs-preview), visits nodes in order of distance from where it starts. Run it from the target, one round per distance: round 1 finds every node at distance 1, round 2 everything at distance 2, and so on. After k rounds, the current frontier is the answer.

A **visited** set stops the search from walking straight back: from 5 the search reaches 3, and 3's neighbours include 5 again.

Here's that search on the tree drawn as a graph. Each label is a node's distance from 5:


And in Swift, with `TreeNode`:

```swift run
func values(atDistance k: Int, from target: TreeNode, in root: TreeNode) -> [Int] {
    // 1. Every node's parent, so the search can go up as well as down
    var parent: [ObjectIdentifier: TreeNode] = [:]
    var pending = [root]
    while let node = pending.popLast() {
        for child in [node.left, node.right] {
            if let child {
                parent[ObjectIdentifier(child)] = node
                pending.append(child)
            }
        }
    }
    // 2. Breadth-first search from the target, one distance per round
    var visited: Set<ObjectIdentifier> = [ObjectIdentifier(target)]
    var frontier = [target]                             // every node at the current distance
    var distance = 0
    while distance < k && !frontier.isEmpty {
        var next: [TreeNode] = []
        for node in frontier {
            for neighbour in [node.left, node.right, parent[ObjectIdentifier(node)]] {
                if let neighbour, visited.insert(ObjectIdentifier(neighbour)).inserted {
                    next.append(neighbour)
                }
            }
        }
        frontier = next
        distance += 1
    }
    return frontier.map(\.value).sorted()
}

let tree = TreeNode.make([7, 3, 9, 1, 5, nil, 12, nil, nil, 4, 6])!
let five = tree.left!.right!
for k in 0...5 {
    print("distance \(k) from 5:", values(atDistance: k, from: five, in: tree))
}

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
distance 0 from 5: [5]
distance 1 from 5: [3, 4, 6]
distance 2 from 5: [1, 7]
distance 3 from 5: [9]
distance 4 from 5: [12]
distance 5 from 5: []
```

What to notice:

- **`visited.insert(…).inserted`** adds the node and reports whether it was new, in one step, as in [Sets and set algebra](/dsa/learn/swift-sets).
- **The frontier is a whole level of the search.** Building `next` from `frontier` round by round means no queue is needed, and the round number is the distance.
- **The answer is sorted**, because the order a search meets nodes in depends on the order of the neighbours, and sorting makes the output easy to check.
- Building the parent map and searching are both **O(n)** time and O(n) space.

There's also a way without the parent map: a recursion that returns "how far below me is the target?" (or "not here"), and, at each ancestor on the way up, collects the nodes k − d levels down its **other** side. It's O(n) too, with less memory but more cases to get right. The parent map is the version to reach for first: it turns an unfamiliar tree problem into a plain graph search.

## Maximum width

> The width of a level is the number of places from its leftmost node to its rightmost node, **counting the gaps** where a complete tree would have nodes. Find the widest level.

```text
          1
        /   \
       2     3
      /       \
     4   .  .  5
```

The last level has only two nodes, but they're four places apart, counting the two empty places between them: width 4.

### Give every node a place number

Number the places as a complete tree would, level by level, as in [A complete tree in an array](/dsa/learn/heap-array-index). Starting from 0 at each level's left edge:

- the root is at place 0;
- the children of a node at place p are at places **2p** and **2p + 1**.

Then a level's width is `last place − first place + 1`. A level-order walk that carries each node's place does it.

### The overflow trap

Places double at every level. Down a chain of right children they go 0, 1, 3, 7, 15, …, 2^d − 1. A chain only 64 levels deep is enough to go past the largest `Int`:

```swift run
// Place numbers down a chain of right children, watching for overflow
var place = 0
for level in 1..<100 {
    let (doubled, overflowed) = place.multipliedReportingOverflow(by: 2)
    let (next, overflowedAgain) = doubled.addingReportingOverflow(1)
    if overflowed || overflowedAgain {
        print("level \(level): the place number no longer fits in an Int")
        break
    }
    place = next
}
print(place == Int.max)
```

```output
level 64: the place number no longer fits in an Int
true
```

In ordinary arithmetic, `2 * place + 1` on that line would stop the program: Swift traps on overflow rather than wrapping round. A tree 64 levels deep is nothing unusual: a chain of 100 nodes is one.

The fix is to **renormalise** each level: before computing the children's places, subtract the level's first place from every place on it. Each level then starts at 0, and its places stay below twice the previous level's width, however deep the tree goes. Widths don't change, because subtracting the same amount from every place on a level keeps the gaps the same.

```swift run
func maximumWidth(_ root: TreeNode?) -> Int {
    guard let root else { return 0 }
    var level: [(node: TreeNode, place: Int)] = [(root, 0)]
    var widest = 0
    while let first = level.first, let last = level.last {
        widest = max(widest, last.place - first.place + 1)
        var below: [(node: TreeNode, place: Int)] = []
        for (node, place) in level {
            let offset = place - first.place            // renormalise: this level now starts at 0
            if let left = node.left { below.append((left, 2 * offset)) }
            if let right = node.right { below.append((right, 2 * offset + 1)) }
        }
        level = below
    }
    return widest
}

print(maximumWidth(TreeNode.make([1, 2, 3, 4, nil, nil, 5])))
print(maximumWidth(TreeNode.make([7, 3, 9, 1, 5, nil, 12, nil, nil, 4, 6])))

// A chain of 200 right children, then two leaves at the bottom
var chainTop = TreeNode(0, left: TreeNode(-1), right: TreeNode(-2))
for value in 1...200 {
    chainTop = TreeNode(value, right: chainTop)
}
print(maximumWidth(chainTop))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {

        let root = TreeNode(rootValue)

        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {

                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
4
4
2
```

What to notice:

- **`while let first = level.first, let last = level.last`** stops when a level is empty and hands over both ends at once.
- **Only the places are renormalised, never the width.** A level whose nodes really are 2^40 places apart has width 2^40; the renormalising only stops the numbers from growing for no reason.
- The walk visits each node once: **O(n)** time, and O(w) space for the widest level.

<Callout kind="gotcha" title="Three slips in these two problems">
**Searching without a visited set.** Parent and child are neighbours both ways, so a search without one bounces between them for ever, or reports the target as being at distance 2 from itself.

**Counting only the nodes.** The width counts empty places between the ends of a level. A level with nodes at places 0 and 3 has width 4, not 2.

**Place numbers from the root.** Without renormalising, places overflow `Int` in trees deeper than about 63 levels, and Swift stops the program.
</Callout>
