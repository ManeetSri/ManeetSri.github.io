## Why it matters

Which is the deepest folder that contains both of these files? Which view is the nearest one that contains both of these buttons, so a tap position in one can be converted into the other's coordinates? Where did these two Git branches split? All three ask for a **lowest common ancestor** (LCA). It's one of the most asked tree questions in interviews, and it has two good answers: a recursion where each call reports what it found, and a climb up parent pointers that turns into a problem you've already solved on linked lists.

## What the lowest common ancestor is

A node's **ancestors** are the nodes on the path from the root down to it. By convention, a node counts as **its own** ancestor. The **common** ancestors of two nodes p and q are the nodes on both paths: the root, and every node down to where the two paths split. The **lowest** common ancestor is the deepest of them, the node where the paths split.

```text
            10
           /  \
          4    7
         / \    \
        1   9    3
           / \
          5   8
```

| p | q | LCA | Why |
| --- | --- | --- | --- |
| 5 | 8 | 9 | the paths split below 9 |
| 5 | 1 | 4 | 5 is under 4's right side, 1 under its left |
| 5 | 3 | 10 | they're on different sides of the root |
| 9 | 8 | 9 | 9 is an ancestor of 8, and of itself |

Two details shape the code. First, p and q are **nodes**, not values: two different nodes could hold the same value, so compare with `===`, as in [Identity with ===](/dsa/learn/swift-identity). Second, this lesson assumes both nodes **are in the tree**. You'll see below what goes wrong if they might not be.

## The recursive solution

Ask every subtree one question: "what did you find?" The answer is one of three things:

- `nil`: neither p nor q is in this subtree;
- p or q: one of them is here (or both are, with the one returned on top);
- the LCA: both are here, and this is the node where they meet.

The rules, for a call on `root`:

1. If `root` is `nil`, return `nil`.
2. If `root` is p or q, return `root` straight away.
3. Otherwise ask both children.
4. If **both** children found something, p is on one side and q on the other, so `root` is where their paths split: return `root`.
5. Otherwise pass up whatever the one side found, or `nil`.

```swift run
func lowestCommonAncestor(_ root: TreeNode?, _ p: TreeNode, _ q: TreeNode) -> TreeNode? {
    guard let root else { return nil }
    if root === p || root === q { return root }
    let left = lowestCommonAncestor(root.left, p, q)
    let right = lowestCommonAncestor(root.right, p, q)
    if left != nil && right != nil { return root }   // p and q are on different sides
    return left ?? right
}

let tree = TreeNode.make([10, 4, 7, 1, 9, nil, 3, nil, nil, 5, 8])!
for (p, q) in [(5, 8), (5, 1), (5, 3), (9, 8), (7, 7)] {
    let answer = lowestCommonAncestor(tree, tree.find(p)!, tree.find(q)!)
    print("LCA of \(p) and \(q):", answer!.value)
}

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// The first node holding value, searching level by level, like find in DSAKit
    func find(_ value: Int) -> TreeNode? {
        var queue = [self]
        var head = 0
        while head < queue.count {
            let node = queue[head]
            head += 1
            if node.value == value { return node }
            if let left = node.left { queue.append(left) }
            if let right = node.right { queue.append(right) }
        }
        return nil
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
LCA of 5 and 8: 9
LCA of 5 and 1: 4
LCA of 5 and 3: 10
LCA of 9 and 8: 9
LCA of 7 and 7: 7
```

Step through the case of 5 and 3. Each node shows what its call returned:

```visual binaryTree
program: lca
input:
  tree: [10, 4, 7, 1, 9, null, 3, null, null, 5, 8]
  p: 5
  q: 3
```

What to notice:

- **Information flows up**, like `height`. A found node is passed up unchanged until it meets the other one at the split point. From there, the LCA itself is passed up the rest of the way, because the other side of every ancestor above returns `nil`.
- **Rule 2 stops early, and that's correct.** For 9 and 8, the call on 9 returns 9 without looking below. If 8 is under 9, then 9 is the answer. If 8 were somewhere else, the other side of some ancestor would find it, and rule 4 would fire there instead.
- **Each node is visited at most once**: O(n) time, O(h) stack space.

## The assumption: both nodes are in the tree

Rule 2 trusts that the other node exists. If q isn't in the tree at all, the function still returns p, which isn't a common ancestor of anything. When you can't be sure, check first: count how many of p and q a walk finds, and only trust the answer if it's both. Every problem that uses this algorithm should say whether the nodes are guaranteed to be present, and this module's problem does.

## With parent pointers: climb instead

Some trees store a link from each node to its **parent**, as `UIView` does with `superview`. Then you can climb from p and q towards the root without searching at all:

1. Walk up from p to the root, putting every node into a set: p's ancestors.
2. Walk up from q until you reach a node in that set. That's the LCA.

`TreeNode` has no parent link, but one walk over the tree can record every node's parent in a dictionary. A class isn't `Hashable`, so the keys are `ObjectIdentifier`s, Swift's identity for an object:

```swift run
func parents(of root: TreeNode) -> [ObjectIdentifier: TreeNode] {
    var parent: [ObjectIdentifier: TreeNode] = [:]
    var pending = [root]
    while let node = pending.popLast() {
        for child in [node.left, node.right] {
            if let child {
                parent[ObjectIdentifier(child)] = node
                pending.append(child)
            }
        }
    }
    return parent
}

func climbingLCA(_ p: TreeNode, _ q: TreeNode, parent: [ObjectIdentifier: TreeNode]) -> TreeNode {
    var ancestors: Set<ObjectIdentifier> = []
    var node: TreeNode? = p
    while let current = node {                          // p and everything above it
        ancestors.insert(ObjectIdentifier(current))
        node = parent[ObjectIdentifier(current)]
    }
    var climber = q
    while !ancestors.contains(ObjectIdentifier(climber)) {
        climber = parent[ObjectIdentifier(climber)]!    // the root is in the set, so this stops
    }
    return climber
}

let tree = TreeNode.make([10, 4, 7, 1, 9, nil, 3, nil, nil, 5, 8])!
let parent = parents(of: tree)
for (p, q) in [(5, 8), (5, 1), (5, 3), (9, 8)] {
    print("LCA of \(p) and \(q):", climbingLCA(tree.find(p)!, tree.find(q)!, parent: parent).value)
}

    static func make(_ levelOrder: [Int?]) -> TreeNode? {

            head += 1

                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)

            index += 1
        }
        return root
    }
}
```

```output
LCA of 5 and 8: 9
LCA of 5 and 1: 4
LCA of 5 and 3: 10
LCA of 9 and 8: 9
```

Building the parent map is O(n), once. After that each query costs only O(h): two climbs. That pays off when one tree gets many queries.

Now look at the two climbs from a different angle. The path from p up to the root is a linked list whose `next` is the parent, and so is the path from q. The two lists **merge** at the LCA and share everything above it. So the LCA is the **intersection of two linked lists**, from [Palindrome list and intersection](/dsa/learn/ll-palindrome-intersection), and the same trick works with O(1) extra space: find both depths, move the deeper node up until they're level, then move both up together until they meet.

<Callout kind="gotcha" title="Swift gotcha: a strong parent link leaks">
If you add a `parent` property to your own node class, make it `weak var parent: Node?`. A child is held by its parent's `left` or `right`; if the child also held its parent strongly, the two would keep each other alive for ever, as in [weak and unowned references](/dsa/learn/swift-weak-unowned). It's why `UIView.superview` doesn't keep a view's parent alive.
</Callout>

## More queries, other trees

- **A binary search tree** can do better: the values say which side p and q are on, so the search walks one path. You'll see it in [Kth smallest and LCA in a BST](/dsa/learn/bst-kth-lca).
- **Thousands of queries on one huge tree** call for preprocessing that answers each query in O(log n) or even O(1). A later module on advanced tree techniques covers it.
