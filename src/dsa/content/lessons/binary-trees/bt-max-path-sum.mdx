## Why it matters

This is the hardest member of the "bent path" family and one of the best-known hard interview problems. It uses exactly the pattern from [Depth and diameter](/dsa/learn/bt-depth-diameter), return one thing and record another, but values can now be **negative**. That adds two decisions the diameter never needed: when to leave a branch off, and what to do when every value is negative. Get those two right and the code is ten lines.

## The problem

A **path** is a sequence of nodes joined by edges, with no node used twice and at least one node. It can start and end anywhere. Its **sum** is the total of its values. Find the largest path sum in the tree.

```text
            5
          /   \
        -6     4
        / \     \
       8   3    -9
               /  \
              7    2
```

In level order, `[5, -6, 4, 8, 3, nil, -9, nil, nil, nil, nil, 7, 2]`. The best path is 8 → −6 → 5 → 4, with sum 11. Notice that it goes **through** −6: losing 6 is worth it to reach the 8 and join the right side. But it stops at 4 rather than continuing to −9 and 7: that would add −9 + 7 = −2.

## Two quantities per node

As with the diameter, every path has one highest node, where it bends. And as with the diameter, there are two different things to know about each node:

- **gain(node)**: the best sum of a path that **starts at the node and goes straight down** one side, or stops at the node itself. This is the only kind of path a parent can extend: a parent can attach itself to the top of it.
- **through(node)**: the best sum of a path whose **highest node** is this node. It may use both sides.

They're built from the children's gains:

> through(node) = node.value + max(0, gain(left)) + max(0, gain(right))
>
> gain(node) = node.value + max(0, gain(left), gain(right))

The `max(0, …)` is the new idea. If the best a branch can offer is negative, a path is better off not entering it at all: it stops at the node instead. A missing child offers 0 for the same reason.

The answer is the largest **through** value over all nodes. So each call **returns** its gain to its parent and **records** its through value in `best`.

## The code

```swift run
func maximumPathSum(_ root: TreeNode) -> Int {
    var best = root.value                               // any single node is a path
    func gain(_ node: TreeNode?) -> Int {
        guard let node else { return 0 }
        let left = max(0, gain(node.left))              // a negative branch is left off
        let right = max(0, gain(node.right))
        let through = node.value + left + right         // the best path bending here
        best = max(best, through)
        print("\(node.value): gains \(left) and \(right), through \(through), returns \(node.value + max(left, right))")
        return node.value + max(left, right)            // a parent can extend only one side
    }
    _ = gain(root)
    return best
}

let tree = TreeNode.make([5, -6, 4, 8, 3, nil, -9, nil, nil, nil, nil, 7, 2])!
print("best:", maximumPathSum(tree))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
8: gains 0 and 0, through 8, returns 8
3: gains 0 and 0, through 3, returns 3
-6: gains 8 and 3, through 5, returns 2
7: gains 0 and 0, through 7, returns 7
2: gains 0 and 0, through 2, returns 2
-9: gains 7 and 2, through 0, returns -2
4: gains 0 and 0, through 4, returns 4
5: gains 2 and 4, through 11, returns 9
best: 11
```

Follow the numbers up from the leaves:

- **−6** gets gains 8 and 3. A path bending at −6 is worth 8 − 6 + 3 = 5, but it can only offer its parent one side: −6 + 8 = 2. That's still positive, so it's worth taking.
- **−9** offers its parent −9 + 7 = −2. Its parent, 4, clamps that to 0: the path stops at 4.
- **5** combines 2 from the left and 4 from the right: 11, the best.

It's one postorder pass: **O(n)** time and O(h) stack space.

## Negative values: the two traps

**Starting `best` at 0.** If every value is negative, the best path is the single largest value, which is below 0. A `best` that starts at 0 would report a path with no nodes. Start from a real path instead: the root's value, as above, or `Int.min`.

**Clamping the wrong thing.** The `max(0, …)` applies to the **children's** gains, never to the node's own value. A path must contain at least one node, so `through` always includes `node.value`, even when it's negative. On `[-3, -1, -2]`, the root's through value is −3, each leaf's is its own value, and the answer is −1.

```swift run
func maximumPathSum(_ root: TreeNode) -> Int {
    var best = root.value
    func gain(_ node: TreeNode?) -> Int {
        guard let node else { return 0 }
        let left = max(0, gain(node.left))
        let right = max(0, gain(node.right))
        best = max(best, node.value + left + right)
        return node.value + max(left, right)
    }
    _ = gain(root)
    return best
}

print(maximumPathSum(TreeNode(-3, left: TreeNode(-1), right: TreeNode(-2))))
print(maximumPathSum(TreeNode(2, left: TreeNode(-1))))
print(maximumPathSum(TreeNode(1, left: TreeNode(10, left: TreeNode(10), right: TreeNode(10)), right: TreeNode(10))))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}
```

```output
-1
2
31
```

The last tree shows why a parent may extend only one side. Its four 10s can't all be on one path: 10 → 10 → 1 → 10 uses three of them (31), or 10 → 10 → 10 bending at the left child uses three (30). Taking all four would need a fork at the left child.

## Testing it: a brute force on small trees

When the fast version is subtle, test it against a slow one you trust, as in [Brute force first](/dsa/learn/algo-brute-force-first). Here, the slow version treats the tree as a network: record every node's parent, then from **every** node walk outwards in all directions (left, right and up), never going back the way you came, and track the largest running total. That's O(n²), fine for trees of 40 nodes, and it shares no ideas with the gain formula, so a bug in one is unlikely to hide in the other. The tests for this lesson's problem do exactly that on 400 random trees.

<Callout kind="gotcha" title="Swift gotcha: Int.min as a starting value">
`Int.min` is safe as the first value of `best`, because `best` is only ever compared. It isn't safe as a **gain**. If an empty subtree returned `Int.min` instead of 0, then `node.value + Int.min` would overflow for any negative value, and Swift stops the program on overflow, as in [Floor and ceiling division, and overflow](/dsa/learn/math-floor-ceil-overflow). Return 0 for a missing child: "go nowhere" adds nothing.
</Callout>
