## Why it matters

Mirroring a tree is what happens to a screen's layout in a right-to-left language such as Arabic or Hebrew: the whole view hierarchy flips, left for right, all the way down. It's also the most famous five-line tree problem in interviews. The second problem here, "is this small tree somewhere inside that big one?", is the tree version of searching for a word in a text. Compilers ask it to spot repeated expressions, and version control systems like Git answer a cousin of it by giving every folder a hash. It builds directly on the same-tree check from [Balanced, same and symmetric trees](/dsa/learn/bt-balanced-same-symmetric).

## Inverting a tree

To **invert** (or mirror) a tree, swap the left and right children of **every** node:

```text
       4                   4
      / \                 / \
     2   7      →        7   2
    / \   \             /   / \
   1   3   9           9   3   1
```

Swapping only the root's children isn't enough: 2's children would still be in their old order. But "swap my children, then invert each child" is a complete recursive description:

```swift run
@discardableResult
func invert(_ node: TreeNode?) -> TreeNode? {
    guard let node else { return nil }
    (node.left, node.right) = (node.right, node.left)   // swap the two children
    invert(node.left)
    invert(node.right)
    return node
}

let tree = TreeNode.make([4, 2, 7, 1, 3, nil, 9])
print(invert(tree)!)
invert(tree)
print(tree!)

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode: CustomStringConvertible {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// The tree in level order, such as [4, 2, 7, nil, 3], like DSAKit's description
    var description: String {
        var result: [String] = []
        var queue: [TreeNode?] = [self]
        var head = 0
        while head < queue.count {
            let node = queue[head]
            head += 1
            result.append(node.map { String($0.value) } ?? "nil")
            if let node {
                queue.append(node.left)
                queue.append(node.right)
            }
        }
        while result.last == "nil" {
            result.removeLast()
        }
        return "[" + result.joined(separator: ", ") + "]"
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
[4, 7, 2, 9, nil, 3, 1]
[4, 2, 7, 1, 3, nil, 9]
```

This example's trailer has one more member, `description`, so `print` shows a whole tree in level order, the way DSAKit's `TreeNode` does.

What to notice:

- **The tuple assignment swaps in one step.** `(node.left, node.right) = (node.right, node.left)` reads both old values before writing either. Writing `node.left = node.right` on its own line first would lose the old left child.
- **Order doesn't matter.** Swapping before the recursive calls (preorder) or after them (postorder) both work, because each node's swap is independent of the others. Inverting twice gives back the original.
- **It changes the tree in place.** `TreeNode` is a class, so everyone holding a reference to these nodes sees the mirrored tree, as in [Value vs reference semantics](/dsa/learn/swift-value-vs-reference). No nodes are created.
- **`@discardableResult`** lets a caller ignore the returned root without a warning, as the second call does.
- It's O(n) time and O(h) stack space.

For a tree that might be very deep, the same swaps work with a loop. Any order of visiting works, so a plain stack will do:

```swift
func invertWithStack(_ root: TreeNode?) {
    var pending: [TreeNode] = root.map { [$0] } ?? []
    while let node = pending.popLast() {
        (node.left, node.right) = (node.right, node.left)
        if let left = node.left { pending.append(left) }
        if let right = node.right { pending.append(right) }
    }
}
```

If you need the original as well as the mirror, copy first. A copy is the same recursion, building new nodes: `TreeNode(node.value, left: copy(node.left), right: copy(node.right))`.

## Is one tree inside another?

A tree `pattern` is a **subtree** of `tree` when some node of `tree`, together with **everything below it**, is exactly `pattern`: same shape, same values.

```text
 tree:      7        pattern:   2
           / \                 / \
          2   9               1   5
         / \
        1   5
```

Here the answer is yes: the node holding 2 matches. But "everything below it" is strict. If the 5 in `tree` had a child, the 2 there would no longer match, because the pattern's 5 is a leaf. A pattern also can't match "the top part" of a subtree.

### Brute force: try every node

The same-tree check from the last lesson does the hard part. Try it at every node of the big tree:

```swift run
var comparisons = 0

func isSame(_ a: TreeNode?, _ b: TreeNode?) -> Bool {
    comparisons += 1
    switch (a, b) {
    case (nil, nil):
        return true
    case let (a?, b?):
        return a.value == b.value && isSame(a.left, b.left) && isSame(a.right, b.right)
    default:
        return false
    }
}

func contains(_ pattern: TreeNode?, in tree: TreeNode?) -> Bool {
    guard let pattern else { return true }              // the empty tree is inside every tree
    guard let tree else { return false }
    return isSame(tree, pattern)
        || contains(pattern, in: tree.left)
        || contains(pattern, in: tree.right)
}

let tree = TreeNode.make([7, 2, 9, 1, 5])
print(contains(TreeNode.make([2, 1, 5]), in: tree))
print(contains(TreeNode.make([2, 1]), in: tree))
print(contains(TreeNode.make([9]), in: tree))

// The worst case: 1,023 zeros, and a pattern of 7 zeros whose last leaf is 1
let zeros = TreeNode.make(Array(repeating: 0, count: 1_023))
comparisons = 0
print(contains(TreeNode.make([0, 0, 0, 0, 0, 0, 1]), in: zeros), "after", comparisons, "comparisons")
```


`[2, 1]` fails because the tree's 2 also has a right child, 5. `[9]` succeeds because 9 is a leaf.

With n nodes in the big tree and m in the pattern, each of the n attempts can compare up to m nodes before it finds a difference: **O(m · n)** in the worst case. The zeros show that worst case: almost every attempt gets deep into the pattern before the final 1 lets it down. On ordinary data it's much faster, because most attempts fail at the very first value.

## Faster: give every subtree a name

To beat O(m · n), stop comparing subtrees node by node and compare something short instead. Two ideas work.

**Serialise and search.** Write each tree as a string that records its shape, such as its preorder with a marker for every missing child, as you'll do in [Serialise and deserialise](/dsa/learn/bt-serialize). A subtree is then a stretch of consecutive characters, so the question becomes "is one string inside the other?" A linear-time string search, which a later module on string matching builds, answers that in O(m + n). Put a separator around every value, so that `,2,` can't be found inside `,12,`.

**Number every distinct subtree.** Walk both trees in postorder and give each subtree an ID number. A subtree is fully described by three things: its root value, its left subtree's ID and its right subtree's ID. A dictionary from that triple to an ID hands out a new number the first time a triple appears, and the same number every time after. Two subtrees get the same ID exactly when they're identical, with no node-by-node comparison at all:

```swift run
struct Shape: Hashable {
    let value: Int
    let left: Int                                       // the left subtree's ID; 0 is the empty tree
    let right: Int
}

func containsByIDs(_ pattern: TreeNode?, in tree: TreeNode?) -> Bool {
    guard pattern != nil else { return true }
    var ids: [Shape: Int] = [:]                         // every distinct subtree seen so far
    var idsInTree: Set<Int> = []
    var recording = true
    func id(of node: TreeNode?) -> Int {
        guard let node else { return 0 }
        let shape = Shape(value: node.value, left: id(of: node.left), right: id(of: node.right))
        let number: Int
        if let known = ids[shape] {
            number = known
        } else {
            number = ids.count + 1
            ids[shape] = number
        }
        if recording {
            idsInTree.insert(number)
        }
        return number
    }
    _ = id(of: tree)
    recording = false
    return idsInTree.contains(id(of: pattern))
}

let tree = TreeNode.make([7, 2, 9, 1, 5])
print(containsByIDs(TreeNode.make([2, 1, 5]), in: tree))
print(containsByIDs(TreeNode.make([2, 1]), in: tree))

let zeros = TreeNode.make(Array(repeating: 0, count: 1_023))
print(containsByIDs(TreeNode.make([0, 0, 0, 0, 0, 0, 1]), in: zeros))
print(containsByIDs(TreeNode.make([0, 0, 0, 0, 0, 0, 0]), in: zeros))
```

```output
true
false
false

```

Each node does a constant amount of work plus one dictionary lookup, so it's **O(m + n)** on average. The all-zeros tree has only ten distinct subtrees (one for each height), so `ids` stays tiny.

That's the same idea that Git uses for folders: a folder's ID is a hash of its contents, including its subfolders' IDs, so identical folders anywhere get identical IDs. This version is exact rather than a hash because the dictionary checks each triple in full.

<Callout kind="gotcha" title="Two classic slips">
**Swapping with two separate assignments.** `node.left = node.right` followed by `node.right = node.left` sets both children to the old right child. Save the old left first, or use the tuple assignment.

**Checking only the top of the subtree.** A match must cover everything below the node. A check that stops when the pattern runs out, without asking whether the tree runs out at the same place, wrongly reports `[2, 1]` inside the example tree.
</Callout>
