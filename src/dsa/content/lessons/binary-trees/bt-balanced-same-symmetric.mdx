## Why it matters

A search tree is only fast while it stays **balanced**: shallow, with every part about as deep as every other. The balanced trees of M38 exist to keep that promise, and checking it is a classic interview question with a trap in it. Comparing two trees node by node is just as common: it's how a UI framework tells whether a view hierarchy changed, and how a snapshot test decides whether output matches. This lesson builds three checks, each a few lines of recursion, and makes the first one O(n) with a Swift optional.

## What "balanced" means

A binary tree is **height-balanced** when, at **every** node, the heights of its left and right subtrees differ by at most 1. The empty tree is balanced.

"Every node" is the part people miss. This tree looks fine from the root, where both sides have height 3, but it isn't balanced:

```text
          1
        /   \
       2     2
      /       \
     3         3
    /           \
   4             4
```

At the left 2, the left subtree has height 2 and the right subtree is empty, height 0. They differ by 2, so the whole tree fails.

## Top-down: correct, but it measures again and again

The definition turns straight into code: check the root's two heights, then check both subtrees the same way. It uses `height` from [Depth and diameter](/dsa/learn/bt-depth-diameter).

```swift
func isBalancedTopDown(_ node: TreeNode?) -> Bool {
    guard let node else { return true }
    return abs(height(node.left) - height(node.right)) <= 1
        && isBalancedTopDown(node.left)
        && isBalancedTopDown(node.right)
}
```

It's correct, but every node's height is measured by the root, then again by its next ancestor down, and again by each ancestor after that. In a balanced tree each node has about log₂ n ancestors, so the total is **O(n log n)**. It's the same waste as the first-attempt diameter, and the fix is the same: get each height once, on the way back up.

## Bottom-up: one pass, with an optional height

Make a single function that returns a subtree's height **if it's balanced**, and `nil` if it finds a problem anywhere inside it. A Swift optional is a natural way to say "there's no sensible height to report". (In languages without optionals, people return −1 as a special signal, a **sentinel**. `nil` says the same thing, and the compiler makes you handle it.)

```swift run
var heightCalls = 0

func height(_ node: TreeNode?) -> Int {
    heightCalls += 1
    guard let node else { return 0 }
    return 1 + max(height(node.left), height(node.right))
}

func isBalancedTopDown(_ node: TreeNode?) -> Bool {
    guard let node else { return true }
    return abs(height(node.left) - height(node.right)) <= 1
        && isBalancedTopDown(node.left)
        && isBalancedTopDown(node.right)
}

var checkedCalls = 0

/// The height of node's subtree, or nil if some subtree inside it is unbalanced
func checkedHeight(_ node: TreeNode?) -> Int? {
    checkedCalls += 1
    guard let node else { return 0 }
    guard let left = checkedHeight(node.left),
          let right = checkedHeight(node.right),
          abs(left - right) <= 1 else { return nil }
    return 1 + max(left, right)
}

func isBalanced(_ root: TreeNode?) -> Bool {
    checkedHeight(root) != nil
}

print(isBalanced(TreeNode.make([1, 2, 3, 4, 5, nil, 6])))
print(isBalanced(TreeNode.make([1, 2, 2, 3, nil, nil, 3, 4, nil, nil, 4])))
print(isBalanced(nil))

let perfect = TreeNode.make(Array(1...16_383))      // 14 full levels
checkedCalls = 0
print(isBalancedTopDown(perfect), "with", heightCalls, "calls to height")
print(isBalanced(perfect), "with", checkedCalls, "calls to checkedHeight")

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
true
false
true
true with 425986 calls to height
true with 32767 calls to checkedHeight
```

The bottom-up version makes one call per node and one per missing child: 2n + 1 calls, **O(n)**. The top-down version makes thirteen times as many on this tree, and the gap grows with the height.

What to notice:

- **The `guard` does three jobs.** It unwraps both heights, checks the difference, and bails out with `nil` if anything fails. Because `guard let` conditions run left to right, an unbalanced left subtree means the right subtree is never even visited.
- **`nil` travels all the way up.** Once one call returns `nil`, its parent's `guard let` fails, so the parent returns `nil` too, and so on to the root.
- This is a cousin of last lesson's pattern. Each call returns what its parent needs, a height. Here the "answer" fits inside the return value itself, as `nil`, so nothing needs recording on the side.

## Are two trees the same?

Two trees are the **same** when they have the same shape and the same values in the same places. Recursively: both are empty, or both have a root, the roots hold equal values, the left subtrees are the same, and the right subtrees are the same.

Switching on a pair of optionals covers the cases neatly:

```swift run
func isSame(_ a: TreeNode?, _ b: TreeNode?) -> Bool {
    switch (a, b) {
    case (nil, nil):
        return true                                     // both empty
    case let (a?, b?):
        return a.value == b.value && isSame(a.left, b.left) && isSame(a.right, b.right)
    default:
        return false                                    // one is empty and the other isn't
    }
}

let first = TreeNode.make([1, 2, 3])
let second = TreeNode.make([1, 2, 3])
print(isSame(first, second), first === second)
print(isSame(TreeNode.make([1, 2]), TreeNode.make([1, nil, 2])))
print(isSame(nil, nil))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {

        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit

                parents.append(parent.left!)

            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {

                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }

```

```output
true false
false
true
```

What to notice:

- `case let (a?, b?)` matches only when **both** are non-nil, and unwraps them. `default` catches the two mixed cases.
- `&&` stops at the first `false`, so the comparison ends at the first difference. Comparing values first is cheapest, so it goes first.
- It's O(n) for trees of n nodes, or less when they differ early.
- `first === second` is `false`: they're two separate sets of nodes. `===` asks "are these the same object?", as in [Identity with ===](/dsa/learn/swift-identity). `isSame` asks "do these look the same?"

`[1, 2]` and `[1, nil, 2]` hold the same values in the same preorder, 1 then 2, but 2 is a left child in one and a right child in the other. A list of values alone doesn't pin down a tree's shape. Remember that: it's the central problem of [Serialise and deserialise](/dsa/learn/bt-serialize).

<Callout kind="gotcha" title="Swift gotcha: classes aren't Equatable">
`a == b` doesn't compile for two `TreeNode` values: a class gets `===` for free, but `==` only if you write it. You could add `extension TreeNode: Equatable` whose `==` calls `isSame`, but then `==` quietly costs O(n), which surprises readers. A named function is clearer. For a quick check in a test, `a?.levelOrder == b?.levelOrder` works too, because DSAKit's level order includes a `nil` for every missing child.
</Callout>

## Is a tree its own mirror?

A tree is **symmetric** when its left half is the mirror image of its right half:

```text
        1
       / \
      2   2
     / \ / \
    3  4 4  3
```

Two subtrees are mirrors when their roots match, the **outside** pair matches (left's left with right's right) and the **inside** pair matches (left's right with right's left). It's `isSame` with the children crossed over:

```swift run
func areMirrors(_ a: TreeNode?, _ b: TreeNode?) -> Bool {
    switch (a, b) {
    case (nil, nil):
        return true
    case let (a?, b?):
        return a.value == b.value && areMirrors(a.left, b.right) && areMirrors(a.right, b.left)
    default:
        return false
    }
}

func isSymmetric(_ root: TreeNode?) -> Bool {
    areMirrors(root?.left, root?.right)
}

print(isSymmetric(TreeNode.make([1, 2, 2, 3, 4, 4, 3])))
print(isSymmetric(TreeNode.make([1, 2, 2, nil, 3, nil, 3])))
print(isSymmetric(TreeNode.make([7])))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {

                parents.append(parent.right!)

            index += 1
        }
        return root

}
```

```output
true
false
true
```

The second tree has 3 as the **right** child of both 2s. A mirror would need the left 2's 3 on its right and the right 2's 3 on its left, so it fails.

`root?.left` is optional chaining, from [Optional chaining](/dsa/learn/swift-optional-chaining): for the empty tree it gives `nil, nil`, which counts as symmetric.

The same check works without recursion. Keep a stack of pairs that should mirror each other, and push the outside and inside pairs of every matching pair:

```swift
func isSymmetricWithStack(_ root: TreeNode?) -> Bool {
    var pairs: [(TreeNode?, TreeNode?)] = [(root?.left, root?.right)]
    while let (a, b) = pairs.popLast() {
        if a == nil && b == nil { continue }
        guard let a, let b, a.value == b.value else { return false }
        pairs.append((a.left, b.right))                 // outside pair
        pairs.append((a.right, b.left))                 // inside pair
    }
    return true
}
```
