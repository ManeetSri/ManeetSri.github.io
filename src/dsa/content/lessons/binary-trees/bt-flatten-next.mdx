## Why it matters

An outline view, such as a sidebar of folders or a table of contents with nested sections, shows a tree as a list of rows, top to bottom, in preorder. **Flattening** a tree into that list, in place, is the tree cousin of reversing a linked list: no new nodes, only rewired links. The second problem, giving every node a `next` link to its neighbour on the same level, turns each level into a linked list. Then something neat happens: a level you've linked can be walked without a queue, and used to link the level below, in O(1) extra space.

## Flattening a tree into a list

> Rewire the tree in place so that it becomes a chain along `right` links in **preorder**: every `left` is `nil`, and each node's `right` is the node after it in preorder.

```text
        1                1
       / \                \
      2   6                2
     / \   \      →         \
    3   4   7                3
       /                      \
      5                        4 → 5 → 6 → 7, all on right links
```

The preorder is 1, 2, 3, 4, 5, 6, 7, so that's the order of the chain.

### First idea: collect, then relink

Walk the tree in preorder and put the nodes in an array. Then link each node to the next one: `nodes[i].left = nil` and `nodes[i].right = nodes[i + 1]`. It's O(n) time, and obviously correct, but it uses O(n) extra memory for the array. Good enough to start, and to test the better versions against.

### Second idea: flatten each side, then splice

Flatten the left subtree and the right subtree first. Each becomes a chain. Then splice: the node's chain is the node, then the left chain, then the right chain. To splice, you need the **last** node of the left chain, its tail. So let each call return the tail of the chain it made:

```swift
/// Flattens node's subtree and returns the last node of the resulting chain
func flattenReturningTail(_ node: TreeNode?) -> TreeNode? {
    guard let node else { return nil }
    let leftTail = flattenReturningTail(node.left)
    let rightTail = flattenReturningTail(node.right)
    if let leftTail {
        leftTail.right = node.right                     // left chain, then right chain
        node.right = node.left                          // node, then left chain
        node.left = nil
    }
    return rightTail ?? leftTail ?? node                // the chain ends with the right side, if any
}
```

It's another "return what the parent needs" recursion: here, the parent needs the tail. O(n) time, O(h) stack.

### Third idea: a loop with O(1) extra space

Look at a node with a left subtree. In preorder, the node is followed by its whole left subtree, and the left subtree's preorder **ends at its rightmost node**: start at the left child and keep going right. That rightmost node must be followed by the node's right subtree.

So, at each node with a left child:

1. find the rightmost node of the left subtree;
2. hang the node's right subtree off it;
3. move the left subtree over to the right, and clear `left`.

Then move down the `right` link and repeat. No stack, no array:

```swift run
func flatten(_ root: TreeNode?) {
    var current = root
    while let node = current {
        if let left = node.left {
            var last = left                             // the end of the left subtree's preorder
            while let next = last.right {
                last = next
            }
            last.right = node.right                     // right subtree goes after the left subtree
            node.right = left                           // left subtree goes right after node
            node.left = nil
        }
        current = node.right
    }
}

func chain(_ root: TreeNode?) -> [Int] {
    var values: [Int] = []
    var node = root
    while let current = node {
        values.append(current.value)
        node = current.right
    }
    return values
}

let tree = TreeNode.make([1, 2, 6, 3, 4, nil, 7, nil, nil, 5])
flatten(tree)
print(chain(tree))
print(tree!.left == nil, tree!.right!.left == nil)

let leaning = TreeNode(3, left: TreeNode(2, left: TreeNode(1)))
flatten(leaning)
print(chain(leaning))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
[1, 2, 3, 4, 5, 6, 7]
true true
[3, 2, 1]
```

What to notice:

- **Order of the three assignments.** `last.right = node.right` must come before `node.right = left`, or the old right subtree is lost. Then `node.left = nil` finishes the move.
- **The inner loop looks expensive, but isn't.** Each node is walked over by "find the rightmost node" at most once in the whole run: it's on the right edge of exactly one left subtree. So the total is **O(n)** time, with **O(1)** extra space.
- This "find the rightmost node of the left subtree" step is the heart of [Morris traversal](/dsa/learn/trav-morris), which uses it to walk a tree without a stack.

## Linking each level with next pointers

> Give every node a `next` link to the node directly to its right on the **same level**, or `nil` for the last node of each level.

`TreeNode` has no `next`, so this needs a node type of its own. The problem in this lesson nests one inside its enum, called `LevelNode`:

```text
        1 → nil
       / \
      2 → 3 → nil
     / \    \
    4 → 5 →  7 → nil
```

Notice 5 → 7: the link jumps over the gap where 3's left child would be. Links connect **cousins** as well as siblings.

### With a queue

A level-order walk, from [Level-order traversal with a queue](/dsa/learn/trav-level-order), already visits each level from left to right. Link each node to the one after it in its level. That's O(n) time and O(w) extra space for the queue, where w is the widest level: up to about n / 2.

### With the level above: O(1) extra space

Once a level is linked, it **is** a linked list: start at its first node and follow `next`. Walking it visits every node of that level, and so every child on the level below, in left-to-right order. That's exactly the order to link them in.

So: walk the current level along `next`, and append each child you meet to a new list for the level below. A **dummy** node at the front of that list, as in [Dummy and sentinel nodes](/dsa/learn/ll-sentinel), means the first child needs no special case. When the walk ends, the level below is linked, and `dummy.next` is its first node.

```swift run
final class LevelNode {
    var value: Int
    var left: LevelNode?
    var right: LevelNode?
    var next: LevelNode?                                // the node to the right on the same level

    init(_ value: Int, left: LevelNode? = nil, right: LevelNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}

func linkLevels(_ root: LevelNode?) {
    var levelStart = root
    while let start = levelStart {
        let dummy = LevelNode(0)                        // the level below gets linked up behind this
        var tail = dummy
        var current: LevelNode? = start
        while let node = current {                      // walk this level along its next links
            if let left = node.left {
                tail.next = left
                tail = left
            }
            if let right = node.right {
                tail.next = right
                tail = right
            }
            current = node.next
        }
        levelStart = dummy.next                         // the first node of the level below
    }
}

// The tree from the drawing: 1 has children 2 and 3; 2 has 4 and 5; 3 has only a right child, 7
let root = LevelNode(1, left: LevelNode(2, left: LevelNode(4), right: LevelNode(5)),
                     right: LevelNode(3, right: LevelNode(7)))
linkLevels(root)

// Print each level by following the next links
var levelStart: LevelNode? = root
while let start = levelStart {
    var values: [Int] = []
    var nextStart: LevelNode? = nil
    var node: LevelNode? = start
    while let current = node {
        values.append(current.value)
        nextStart = nextStart ?? current.left ?? current.right
        node = current.next
    }
    print(values)
    levelStart = nextStart
}
```

```output
[1]
[2, 3]
[4, 5, 7]
```

What to notice:

- **Level 0 is linked from the start**: a single node with `next` already `nil`. Each pass of the outer loop uses one linked level to link the next one.
- **The dummy node** saves an `if` for "is this the first child of the level?". A new dummy per level costs O(1) each time.
- Every node is appended once and walked once: **O(n)** time, and **O(1)** extra space besides the tree.
- `next` is an ordinary strong reference. That's safe here: it only points sideways, never back up to an ancestor, so it can't create a cycle of references that keeps the tree alive.

When the tree is **perfect**, every node has two children and there are no gaps, so a shorter version works: `node.left.next = node.right`, and `node.right.next = node.next?.left`. The dummy-node version handles every shape, perfect or not.

<Callout kind="gotcha" title="Three slips when rewiring">
**Leaving `left` set when flattening.** The chain must use only `right` links. A left link left behind means the "list" still branches, and a later walk may visit nodes twice.

**Overwriting a link before saving it.** In the flatten loop, hang the old right subtree off the left subtree's last node **before** replacing `node.right`.

**Stopping at the first gap.** With gaps, the next node on a level may be a cousin several parents away. Following the level above along `next` finds it; looking only at your own parent's children doesn't.
</Callout>

## Practice

**Flatten a tree and link its levels** asks for both: `flatten` on a `TreeNode`, and `linkLevels` on the nested `LevelNode` type, for trees of any shape. Its tests check that the original nodes are reused in preorder and that every `next` points at the right neighbour, up to 150,000 nodes.
