## Why it matters

Many tree questions are really about **paths from the root**: is this node the largest so far on its way down? What number do the digits on this path spell? What's left of a budget after the categories above? Each one passes a small piece of state down the tree, updating it at every node, exactly as [Path sum I, II and III](/dsa/learn/bt-path-sums) passed down a running total. This lesson practises that top-down shape on two classic problems and turns it into a template you can reuse.

## Good nodes

A node is **good** when no node on the path from the root down to it holds a **larger** value. The root is always good: there's nothing above it. In the array world, this is [Record breakers](/dsa/practice/record-breakers) from M13, except that each path down the tree is its own list of scores, and equal values count as good here.

```text
          4
        /   \
       2     6
      / \   / \
     5   1 6   3
        /
       7
```

| Node | Path from the root | Good? |
| --- | --- | --- |
| 4 | 4 | yes, the root |
| 2 | 4, 2 | no: 4 is larger |
| 5 | 4, 2, 5 | yes |
| 1 | 4, 2, 1 | no |
| 7 | 4, 2, 1, 7 | yes |
| 6 (right child of 4) | 4, 6 | yes |
| 6 (left child of 6) | 4, 6, 6 | yes: equal is fine |
| 3 | 4, 6, 3 | no |

Five good nodes. Notice that a node is compared only with its own **ancestors**. The 5 is good even though the 6 elsewhere in the tree is larger.

### Pass the largest value down

Each node needs one fact about its ancestors: the largest value among them. So pass that down as a parameter. A node is good if its value is at least that large, and its children receive the larger of the two:

```swift run
func goodNodeCount(_ root: TreeNode?) -> Int {
    func count(_ node: TreeNode?, highestAbove: Int) -> Int {
        guard let node else { return 0 }
        let good = node.value >= highestAbove ? 1 : 0
        let highest = max(highestAbove, node.value)     // what this node's children see above them
        return good + count(node.left, highestAbove: highest) + count(node.right, highestAbove: highest)
    }
    return count(root, highestAbove: Int.min)           // nothing above the root
}

print(goodNodeCount(TreeNode.make([4, 2, 6, 5, 1, 6, 3, nil, nil, 7])))
print(goodNodeCount(TreeNode.make([9, 8, 7, 6, 5])))
print(goodNodeCount(TreeNode.make([1, nil, 2, nil, 3])))
print(goodNodeCount(nil))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
5
1
3
0
```

What to notice:

- **`Int.min` for the root** means "nothing above", so the root is always good. It's only compared, never added to, so it can't overflow.
- **No undo step.** Path sum II had to `removeLast()` from a shared array on the way out. Here the state is an `Int` parameter: each call has its own copy, and the parent's copy is untouched when a child changes its own. Value types make top-down state effortless.
- It's **O(n)** time and O(h) stack space.

## Root-to-leaf numbers

Now every node holds a **digit** from 0 to 9, and each path from the root to a leaf spells a number, the root's digit first. Find the sum of those numbers.

```text
        3
       / \
      9   0
         / \
        5   1
```

The paths spell 39, 305 and 301, so the sum is 645.

The state to pass down is **the number spelled so far**. Adding a digit on the right is the trick from [Digit manipulation](/dsa/learn/math-digits): multiply by 10 and add it. At a leaf, the number is complete.

```swift run
func pathNumberSum(_ root: TreeNode?) -> Int {
    func sum(_ node: TreeNode?, spelledAbove: Int) -> Int {
        guard let node else { return 0 }
        let number = spelledAbove * 10 + node.value     // add this digit on the right
        if node.left == nil && node.right == nil {
            return number                               // a leaf completes one number
        }
        return sum(node.left, spelledAbove: number) + sum(node.right, spelledAbove: number)
    }
    return sum(root, spelledAbove: 0)
}

print(pathNumberSum(TreeNode.make([3, 9, 0, nil, nil, 5, 1])))
print(pathNumberSum(TreeNode.make([1, 2])))
print(pathNumberSum(TreeNode.make([0, 1, 0])))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

    var value: Int
    var left: TreeNode?
    var right: TreeNode?

        self.left = left
        self.right = right
    }

                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
645
12
1
```

What to notice:

- **The leaf test again.** `[1, 2]` gives 12, not 12 + 1: the root has a child, so it isn't the end of a path. Testing for `nil` instead of for a leaf would count the root's missing right child as the end of a number.
- **Leading zeros vanish**, as they should: in `[0, 1, 0]` the paths spell 01 and 00, which are 1 and 0.
- **Watch the size.** Each level adds a digit, so a path 19 digits long is beyond `Int`'s largest value, about 9.2 × 10^18. Problems keep trees shallow, or ask for the answer modulo some number, as in [Modular arithmetic](/dsa/learn/math-modular-arithmetic).

## A template for top-down state

Both solutions, and the path sums before them, have the same shape:

```swift
func walk(_ node: TreeNode?, _ stateAbove: State) -> Answer {
    guard let node else { return emptyAnswer }
    let state = update(stateAbove, with: node)          // what this node's children will see
    if node.left == nil && node.right == nil {
        return answer(atLeafWith: state)                // only for root-to-leaf questions
    }
    return combine(walk(node.left, state), walk(node.right, state))
}
```

Only the state changes from problem to problem:

| Problem | State passed down | Update at each node |
| --- | --- | --- |
| Path sum I | the amount still needed | subtract the value |
| Good nodes | the largest value above | take the max |
| Root-to-leaf numbers | the number spelled so far | times 10, plus the digit |
| Longest increasing path down | the current run's length and last value | extend the run or restart it |
| Paths whose digits could be rearranged into a palindrome | which digits have appeared an odd number of times, as a bitmask | toggle the digit's bit |

That last one combines this template with [XOR tricks](/dsa/learn/bits-xor-tricks): a path can be rearranged into a palindrome when at most one digit appears an odd number of times, that is, when the mask has at most one bit set.

For a tree too deep for recursion, keep the same state in an explicit stack of pairs instead, as in [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack):

```swift
func goodNodeCountWithStack(_ root: TreeNode?) -> Int {
    var count = 0
    var pending: [(node: TreeNode, highestAbove: Int)] = root.map { [($0, Int.min)] } ?? []
    while let (node, highestAbove) = pending.popLast() {
        if node.value >= highestAbove { count += 1 }
        let highest = max(highestAbove, node.value)
        if let left = node.left { pending.append((left, highest)) }
        if let right = node.right { pending.append((right, highest)) }
    }
    return count
}
```

Each stack entry carries its own copy of the state, so the order the pairs come off the stack doesn't matter.

<Callout kind="gotcha" title="Strictly larger, or larger or equal?">
Read the definition carefully. Here a node is good unless something above it is **strictly larger**, so `node.value >= highestAbove`. Record breakers in M13 needed a score **strictly greater** than everything before it, which is `>`. One character changes the answer on any tree with repeated values.
</Callout>

## Practice

**Good nodes and path numbers** asks for both functions. The good-node tests use trees of up to 150,000 nodes with values across the whole `Int` range; the path-number tests use trees up to 12 levels deep, so every number fits comfortably.

```cards

  front: "How do you count good nodes (no larger value above them) in a binary tree?"
  back: "Pass the largest value seen so far down as a parameter, starting at Int.min. A node is good if its value ≥ that maximum; its children get max(maximum, value)."
- id: path-numbers-state
  front: "How do you sum the numbers spelled by root-to-leaf digit paths?"
  back: "Pass the number spelled so far down: number = above × 10 + digit. A leaf returns its number; other nodes return the sum of their children's results."
- id: top-down-no-undo
  front: "Why do good nodes and path numbers need no backtracking step?"
  back: "Their state is an Int parameter, a value. Each call has its own copy, so a child's update never affects its parent or siblings."
```
