## Why it matters

Give someone two traversals of a tree, and they can rebuild the tree exactly. It's a favourite interview question because it tests whether you know what each traversal really says: preorder and postorder reveal **which node is the root**, and inorder reveals **what's on each side** of it. The first working answer is usually O(n²). Turning it into O(n) with a dictionary and a moving index is the part interviewers look for, and the same divide-at-the-root idea reappears whenever a parser turns text back into a tree.

## What each traversal tells you

From [Preorder, inorder and postorder](/dsa/learn/trav-dfs-recursive):

| Traversal | Order | What it gives away |
| --- | --- | --- |
| Preorder | root, left subtree, right subtree | the **first** value is the root |
| Inorder | left subtree, root, right subtree | everything **before** the root is on the left |
| Postorder | left subtree, right subtree, root | the **last** value is the root |

Here's the tree for this lesson, with its three traversals:

```text
          7
         / \
        3   9
       / \    \
      5   1    2
         /
        8
```

| Traversal | Values |
| --- | --- |
| Preorder | 7, 3, 5, 1, 8, 9, 2 |
| Inorder | 5, 3, 8, 1, 7, 9, 2 |
| Postorder | 5, 8, 1, 3, 2, 9, 7 |

All the values are different. That matters, as you'll see at the end.

## Rebuilding by hand

Start with the preorder and inorder.

1. The preorder starts with **7**, so 7 is the root.
2. Find 7 in the inorder: `5, 3, 8, 1` **7** `9, 2`. The four values before it form the left subtree, and the two after it form the right subtree.
3. In the preorder, the root is followed by the whole left subtree and then the whole right subtree. The left subtree has four values, so they're the next four: `3, 5, 1, 8`. The right subtree is the rest: `9, 2`.
4. Now repeat for each side. The left side has preorder `3, 5, 1, 8` and inorder `5, 3, 8, 1`: its root is 3, with `5` on its left and `8, 1` on its right. And so on, until every part is empty.

Every step is the same question on a smaller piece, so it's a recursion.

## First version: slices

Slices of the two arrays describe each piece directly, as in [ArraySlice and its index pitfalls](/dsa/learn/swift-array-slices):

```swift
func build(_ preorder: ArraySlice<Int>, _ inorder: ArraySlice<Int>) -> TreeNode? {
    guard let rootValue = preorder.first else { return nil }
    let middle = inorder.firstIndex(of: rootValue)!                 // a linear search
    let leftCount = middle - inorder.startIndex                     // slices keep their original indices
    let node = TreeNode(rootValue)
    node.left = build(preorder.dropFirst().prefix(leftCount), inorder[inorder.startIndex..<middle])
    node.right = build(preorder.dropFirst(1 + leftCount), inorder[(middle + 1)...])
    return node
}
```

It's correct, and slices don't copy anything. But `firstIndex(of:)` searches the inorder piece from the start. On a balanced tree the pieces halve, so that's O(n log n) overall. On a tree that leans all one way, each search scans nearly everything that's left: **O(n²)**.

Notice `inorder.startIndex`: a slice keeps the indices of the array it came from, so the left subtree's size is `middle - inorder.startIndex`, not `middle`.

## O(n): a dictionary and a moving index

Two changes remove the waste.

**Find the root in O(1).** Before starting, build a dictionary from each value to its index in the inorder. Every "where is the root?" becomes one lookup.

**Never slice the preorder.** The tree is built root first, then the whole left subtree, then the whole right subtree: that's preorder! So the preorder values are needed in exactly the order they appear. One index, `next`, can walk along it, moving on by one each time a node is created.

The recursion then only needs to know which stretch of the **inorder** it's building, as a half-open range `low..<high` of indices:

```swift run
func fromPreorder(_ preorder: [Int], inorder: [Int]) -> TreeNode? {
    var position: [Int: Int] = [:]
    for (index, value) in inorder.enumerated() {
        position[value] = index
    }
    var next = 0                                        // preorder[next] is the next root to place
    func build(_ low: Int, _ high: Int) -> TreeNode? {  // the subtree whose inorder is inorder[low..<high]
        guard low < high else { return nil }
        let node = TreeNode(preorder[next])
        next += 1
        let middle = position[node.value]!
        node.left = build(low, middle)                  // the left subtree's values come next in preorder
        node.right = build(middle + 1, high)
        return node
    }
    return build(0, inorder.count)
}

func fromPostorder(_ postorder: [Int], inorder: [Int]) -> TreeNode? {
    var position: [Int: Int] = [:]
    for (index, value) in inorder.enumerated() {
        position[value] = index
    }
    var next = postorder.count - 1                      // walk the postorder backwards
    func build(_ low: Int, _ high: Int) -> TreeNode? {
        guard low < high else { return nil }
        let node = TreeNode(postorder[next])
        next -= 1
        let middle = position[node.value]!
        node.right = build(middle + 1, high)            // backwards, the right subtree comes first
        node.left = build(low, middle)
        return node
    }
    return build(0, inorder.count)
}

let inorder = [5, 3, 8, 1, 7, 9, 2]
print(fromPreorder([7, 3, 5, 1, 8, 9, 2], inorder: inorder)!)
print(fromPostorder([5, 8, 1, 3, 2, 9, 7], inorder: inorder)!)
print(fromPreorder([1, 2], inorder: [2, 1])!, fromPreorder([1, 2], inorder: [1, 2])!)

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode: CustomStringConvertible {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// The tree in level order, such as [4, 2, 7, nil, 3], like DSAKit's description
    var description: String {
        var result: [String] = []
        var queue: [TreeNode?] = [self]
        var head = 0
        while head < queue.count {
            let node = queue[head]
            head += 1
            result.append(node.map { String($0.value) } ?? "nil")
            if let node {
                queue.append(node.left)
                queue.append(node.right)
            }
        }
        while result.last == "nil" {
            result.removeLast()
        }
        return "[" + result.joined(separator: ", ") + "]"
    }
}
```

```output
[7, 3, 9, 5, 1, nil, 2, nil, nil, 8]
[7, 3, 9, 5, 1, nil, 2, nil, nil, 8]
[1, 2] [1, nil, 2]
```

What to notice:

- **The order of the two recursive calls matters.** With preorder, `next` must reach the whole left subtree before the right one, so `build` makes the left call first. With postorder read backwards, the order is root, **right**, left, so the right call comes first. Swap them and the values land in the wrong places.
- **`low..<high` is half-open**, as in [Invariants and off-by-one: closed vs half-open](/dsa/learn/bs-invariants). The empty piece is `low == high`, and the two sides of `middle` are `low..<middle` and `(middle + 1)..<high`.
- **The force unwrap `position[node.value]!` is safe** only because both arrays come from the same tree. With bad input it crashes, which is arguably the right reaction.
- **The last line shows inorder doing its job.** The same preorder, `1, 2`, gives 2 as a left child when the inorder is `2, 1`, and as a right child when it's `1, 2`.
- Each node costs O(1): **O(n)** time, plus O(n) for the dictionary. The recursion is as deep as the tree.

## When two traversals aren't enough

**Preorder and postorder** can't always do it. For preorder `1, 2` and postorder `2, 1`, 2 could be the left child or the right child: neither traversal separates left from right when a node has only one child. (If every node has zero or two children, a **full** tree, they are enough.) Inorder is the traversal that splits left from right, so the reliable pairs are preorder with inorder, and postorder with inorder.

**Repeated values** break even those. With preorder `1, 1` and inorder `1, 1`, the second 1 could be the root's left child or its right child, and both trees give the same traversals. Finding "the root's position in the inorder" only makes sense when every value appears once. That's why problems of this kind promise distinct values.

<Callout kind="gotcha" title="Two slips with slices and indices">
**Treating a slice's indices as starting at 0.** In the slice version, `middle` is an index into the original array. `middle - inorder.startIndex` is the left subtree's size; `middle` alone is only right for the very first call.

**Searching the whole inorder.** `inorder.firstIndex(of:)` on the full array, rather than the current piece, still finds the right index when values are distinct, but costs O(n) every time: O(n²) even for a balanced tree.
</Callout>

## Practice

**Rebuild a tree from two traversals** asks for both versions: preorder with inorder, and postorder with inorder. Its tests rebuild 400 random trees, a perfect tree of 131,071 nodes and a random tree of 150,000 nodes, and compare level orders.

```cards
- id: construct-roles
  front: "When rebuilding a tree from preorder and inorder, what does each traversal tell you?"
  back: "The preorder's first value is the root. Its position in the inorder splits the remaining values into the left subtree (before it) and the right subtree (after it)."
- id: construct-index-map
  front: "How do you make tree construction from preorder and inorder O(n)?"
  back: "A dictionary from value to inorder index finds each root in O(1), and one index walks the preorder in order as nodes are created. Recurse on inorder ranges."
- id: construct-postorder
  front: "How does building from postorder and inorder differ?"
  back: "Read the postorder backwards: root, then right subtree, then left. So build the right subtree before the left."
- id: construct-limits
  front: "When can't two traversals rebuild a unique tree?"
  back: "Preorder with postorder, when some node has one child (left or right is ambiguous), and any pair when values repeat."
```
