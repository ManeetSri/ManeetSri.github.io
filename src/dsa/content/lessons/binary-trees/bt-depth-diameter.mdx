## Why it matters

How deep is this view hierarchy? How many folders down is the deepest file? Is this tree shallow enough to search quickly? All three ask for a tree's **height**. Height is also the first step to a harder question: what is the longest path between any two nodes, the tree's **diameter**? Solving that in one pass teaches the pattern behind half of this module: each call **returns** one thing to its parent and **records** another on the side.

## Height, recursively

As in [Tree terminology](/dsa/learn/tree-terminology), height here counts **levels**: the empty tree has height 0, a single node has height 1, and each extra level adds 1. That matches DSAKit's `height`. (Some books count edges instead, which is one less. Path lengths in this lesson, such as the diameter, do count edges.)

The definition is recursive. A tree's height is 1, for its root, plus the height of its taller subtree. The empty tree has height 0, and that's the base case. Here's the tree this lesson uses:

```text
        1
       / \
      2   3
     / \   \
    4   5   6
       /
      7
```

```swift run
func height(_ node: TreeNode?) -> Int {
    guard let node else { return 0 }                    // the empty tree
    return 1 + max(height(node.left), height(node.right))
}

let tree = TreeNode.make([1, 2, 3, 4, 5, nil, 6, nil, nil, 7])
print(height(tree))
print(height(tree?.right))
print(height(nil))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }

    /// Builds a tree from its level order, with nil for a missing child, like TreeNode.make in DSAKit
    static func make(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]
        var head = 0
        var index = 1
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                parent.left = TreeNode(value)
                parents.append(parent.left!)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                parent.right = TreeNode(value)
                parents.append(parent.right!)
            }
            index += 1
        }
        return root
    }
}
```

```output
4
2
0
```

Every runnable example in this module ends with that cut-down copy of DSAKit's `TreeNode` and its `make`, which builds a tree from level order as in [Building a tree from a level-order array](/dsa/learn/tree-build-level-order). Swift lets a file use a type that's declared further down, so the interesting code can come first. In the companion package, `import DSAKit` gives you the real one.

What to notice:

- `guard let node else { return 0 }` handles the empty tree, and also every missing child. A leaf's two calls on `nil` both return 0, so a leaf has height 1.
- The function never looks further than one level down. It trusts the two recursive calls, exactly as in [Base case and recursive case](/dsa/learn/rec-what-is-recursion).
- The work happens **after** both calls return: it's a postorder walk, as in [Preorder, inorder and postorder](/dsa/learn/trav-dfs-recursive). Information flows up from the leaves.
- Each node is visited once, so it's O(n). The call stack holds one frame per level, so the extra space is O(h): O(log n) for a balanced tree, but O(n) for a tree that's one long chain.

That last point matters. A chain of 100,000 nodes means 100,000 nested calls, which overflows the stack, as you saw in [Stack depth limits in Swift](/dsa/learn/rec-stack-limits). For trees that might be that deep, count levels with a level-order walk instead, as in [Level-order traversal with a queue](/dsa/learn/trav-level-order). That's how DSAKit's `height` works:

```swift
func heightByLevels(_ root: TreeNode?) -> Int {
    var level: [TreeNode] = root.map { [$0] } ?? []
    var levels = 0
    while !level.isEmpty {
        levels += 1
        level = level.flatMap { [$0.left, $0.right].compactMap { $0 } }    // the next level down
    }
    return levels
}
```

## The minimum depth trap

The **minimum depth** is the number of levels from the root down to the **nearest leaf**. It looks like height with `min` instead of `max`, but that version has a bug:

```swift run
func wrongMinDepth(_ node: TreeNode?) -> Int {
    guard let node else { return 0 }
    return 1 + min(wrongMinDepth(node.left), wrongMinDepth(node.right))
}

func minDepth(_ node: TreeNode?) -> Int {
    guard let node else { return 0 }
    switch (node.left, node.right) {
    case (nil, nil):
        return 1                                        // a leaf
    case (let child?, nil), (nil, let child?):
        return 1 + minDepth(child)                      // only one way down
    case (let left?, let right?):
        return 1 + min(minDepth(left), minDepth(right))
    }
}

// 1 has only a right child, 2, and 2 has a leaf, 3
let lopsided = TreeNode(1, right: TreeNode(2, right: TreeNode(3)))
print(wrongMinDepth(lopsided), minDepth(lopsided))

// MARK: - The TreeNode from DSAKit, cut down so this file runs on its own

final class TreeNode {
    var value: Int
    var left: TreeNode?
    var right: TreeNode?

    init(_ value: Int, left: TreeNode? = nil, right: TreeNode? = nil) {
        self.value = value
        self.left = left
        self.right = right
    }
}
```

```output
1 3
```

The root's missing left child returns 0, and `min` picks it. But a missing child isn't a leaf: the only leaf in that tree is 3, three levels down. When one side is empty, the nearest leaf must be on the other side. (A level-order walk also works well here: it can stop at the first leaf it meets.)

## The diameter

The **diameter** is the number of edges on the longest path between any two nodes. A path never visits a node twice, and it can start and end anywhere. In the tree above, it's 7 → 5 → 2 → 1 → 3 → 6: 5 edges.

The key observation: every path has exactly one **highest** node, the one nearest the root. The path climbs up to it from one side and goes down the other side, or it simply starts there and goes down. Picture it as the place where the path **bends**.

How long can a path that bends at node X be? It goes as deep as possible into X's left subtree and as deep as possible into its right subtree. If the left subtree has height 3, its deepest node is 3 edges below X. So:

> longest path bending at X = height(X.left) + height(X.right) edges

and the diameter is the largest of those over every node X.

The best bend isn't always at the root. In this tree, the root has nothing on its right, and the longest path, 5 → 3 → 2 → 4 → 6, bends at 2:

```text
        1
       /
      2
     / \
    3   4
   /     \
  5       6
```

### A first attempt: heights at every node

Turn that formula straight into code: at each node, work out both heights, then recurse into the children to look for better bends below.

```swift run
var heightCalls = 0

func height(_ node: TreeNode?) -> Int {
    heightCalls += 1
    guard let node else { return 0 }
    return 1 + max(height(node.left), height(node.right))
}

func slowDiameter(_ node: TreeNode?) -> Int {
    guard let node else { return 0 }
    let bendingHere = height(node.left) + height(node.right)
    return max(bendingHere, slowDiameter(node.left), slowDiameter(node.right))
}

print(slowDiameter(TreeNode.make([1, 2, 3, 4, 5, nil, 6, nil, nil, 7])))
print(slowDiameter(TreeNode.make([1, 2, nil, 3, 4, 5, nil, nil, 6])))

// A chain of 1,000 nodes, each the left child of the next
var chain: TreeNode? = nil
for value in 1...1_000 {
    chain = TreeNode(value, left: chain)
}
heightCalls = 0
print(slowDiameter(chain), "after", heightCalls, "calls to height")
```

The answers are right, but look at the cost. Each node measures the heights below it from scratch, and then its children measure again, and their children again. On the chain of 1,000 nodes, that's about a million calls, roughly n²: **O(n²)**. (On a balanced tree it's O(n log n), still more than needed.)

### One pass: return the height, record the best bend

Here's the fix. To compute a node's height, the recursion already has both children's heights in hand. That's everything the bend formula needs. So while each call works out its height, it can check the path bending at its node, for free, and keep the best one seen in a variable outside the recursion:

```swift run
func diameter(_ root: TreeNode?) -> Int {
    var best = 0
    func height(_ node: TreeNode?) -> Int {
        guard let node else { return 0 }
        let left = height(node.left)
        let right = height(node.right)
        best = max(best, left + right)       // the longest path through node, in edges
        return 1 + max(left, right)
    }
    _ = height(root)
    return best
}

print(diameter(TreeNode.make([1, 2, 3, 4, 5, nil, 6, nil, nil, 7])))
print(diameter(TreeNode.make([1, 2, nil, 3, 4, 5, nil, nil, 6])))
print(diameter(TreeNode.make([8])))
print(diameter(nil))
```

What to notice:

- `height` is a **nested function** that reads and changes `best`, a variable of the outer function, as in [Nested helper functions](/dsa/learn/swift-nested-functions). Each call to `diameter` gets a fresh `best`.
- The value a call **returns** (its height) is what its parent needs. The value it **records** (the best bend) is what the question asks. They're different, and that's the whole trick.
- `_ = height(root)` throws away the root's height: only the side effect on `best` matters.
- Every node is visited once: **O(n)** time, and O(h) stack space.

## The pattern: return one thing, record another

This shape comes back again and again, so it deserves a name: **return a height, update a global best**. The tell-tale sign is a question about a path that can **bend**, while a parent can only extend a path that goes **straight down** one side. The parent can't use a bent path: it would have to fork. So:

- **return** the best straight-down quantity, the one a parent can extend;
- **record** the best bent quantity, the answer, in a variable outside the recursion.

| Problem | Each call returns | Each call records |
| --- | --- | --- |
| Diameter | its height | left height + right height |
| [Maximum path sum](/dsa/learn/bt-max-path-sum) | the best sum going straight down | the best sum bending here |
| Longest path of equal values | the longest equal run going down | the longest equal run bending here |

You'll meet the same idea again in a later module on tree dynamic programming, where each call returns a small summary of its subtree.

If you'd rather not have a variable outside the recursion, return both numbers in a tuple, as in [Returning several values with tuples](/dsa/learn/swift-returning-tuples). It's the same algorithm:

```swift
func heightAndDiameter(_ node: TreeNode?) -> (height: Int, diameter: Int) {
    guard let node else { return (0, 0) }
    let left = heightAndDiameter(node.left)
    let right = heightAndDiameter(node.right)
    let bendingHere = left.height + right.height
    return (1 + max(left.height, right.height), max(bendingHere, left.diameter, right.diameter))
}
```

<Callout kind="gotcha" title="Edges or nodes?">
This lesson's diameter counts **edges**, so a single node has diameter 0 and the bend formula is `left + right`. Some problems count **nodes** on the path instead: that's one more, `left + right + 1`. Check which one a problem asks for before you write the formula, and test it on a single node.
</Callout>
