## Why it matters

In [Kadane's maximum subarray](/dsa/learn/arrays-kadane) you found the best run of consecutive values in one O(n) pass. This lesson solves the same problem by divide and conquer, in O(n log n). That's slower, so why bother? Because its combine step, the run that **crosses the middle**, is the clearest example of the reasoning you'll need for harder problems like the closest pair of points. And a small upgrade turns it into a summary that can be merged, which is exactly what the segment trees of Part VIII store to answer "best run between positions i and j" in a changing array, something Kadane can't do.

## Three places the best run can be

Split the array at the middle. The best run (a non-empty stretch of consecutive values, as in M18) is in exactly one of three places:

1. entirely in the **left** half;
2. entirely in the **right** half;
3. **crossing** the middle: it starts in the left half and ends in the right half.

Cases 1 and 2 are the same problem on half the array: solve them recursively. Case 3 is the combine step, and it's where the thinking happens.

## The crossing sum

A run that crosses the middle includes the last element of the left half, at `mid - 1`, and the first element of the right half, at `mid`. So it's made of two pieces that can be chosen **separately**:

- the best run that **ends** at `mid - 1`, growing leftwards;
- the best run that **starts** at `mid`, growing rightwards.

Neither choice affects the other, so the best crossing run is the best left piece plus the best right piece. Each piece is one scan outwards from the middle, keeping the best running sum.

Take the array from M18, `[-2, 1, -3, 4, -1, 2, 1, -5, 4]`, split into `[-2, 1, -3, 4]` and `[-1, 2, 1, -5, 4]`:

| Leftwards from 4 | 4 | 4 − 3 | + 1 | − 2 |
| --- | --- | --- | --- | --- |
| running sum | **4** | 1 | 2 | 0 |

| Rightwards from −1 | −1 | + 2 | + 1 | − 5 | + 4 |
| --- | --- | --- | --- | --- | --- |
| running sum | −1 | 1 | **2** | −3 | 1 |

The best left piece is `[4]`, with sum 4, and the best right piece is `[-1, 2, 1]`, with sum 2. Together they make `[4, -1, 2, 1]`, with sum 6: the answer you found with Kadane.

## The whole algorithm

```swift run
// The best run that crosses the middle: the best run ending at mid - 1 plus the best run starting at mid
func crossingSum(_ numbers: [Int], _ low: Int, _ mid: Int, _ high: Int) -> Int {
    var sum = 0
    var bestLeft = numbers[mid - 1]
    for index in stride(from: mid - 1, through: low, by: -1) {   // grow leftwards from the middle
        sum += numbers[index]
        bestLeft = max(bestLeft, sum)
    }
    sum = 0
    var bestRight = numbers[mid]
    for index in mid..<high {                                    // grow rightwards from the middle
        sum += numbers[index]
        bestRight = max(bestRight, sum)
    }
    return bestLeft + bestRight
}

func bestSum(_ numbers: [Int], _ low: Int, _ high: Int) -> Int {
    if high - low == 1 {
        return numbers[low]                     // one element: the only run is itself
    }
    let mid = low + (high - low) / 2
    let left = bestSum(numbers, low, mid)
    let right = bestSum(numbers, mid, high)
    let crossing = crossingSum(numbers, low, mid, high)
    let best = max(left, right, crossing)
    print("\(Array(numbers[low..<high])): left \(left), right \(right), crossing \(crossing) → \(best)")
    return best
}

let numbers = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
print("answer:", bestSum(numbers, 0, numbers.count))
```

```output
[-2, 1]: left -2, right 1, crossing -1 → 1
[-3, 4]: left -3, right 4, crossing 1 → 4
[-2, 1, -3, 4]: left 1, right 4, crossing 2 → 4
[-1, 2]: left -1, right 2, crossing 1 → 2
[-5, 4]: left -5, right 4, crossing -1 → 4
[1, -5, 4]: left 1, right 4, crossing 0 → 4
[-1, 2, 1, -5, 4]: left 2, right 4, crossing 3 → 4
[-2, 1, -3, 4, -1, 2, 1, -5, 4]: left 4, right 4, crossing 6 → 6
answer: 6
```

What to notice:

- Most ranges are won by one side. Only the very last combine finds that crossing beats both halves.
- A crossing run of `[1, -5, 4]` is forced to include both the 1 and the −5, so its best is 0. That's fine: a run that doesn't need the −5 is covered by case 1 or case 2.
- The crossing scans start from `numbers[mid - 1]` and `numbers[mid]`, not from 0. Starting from 0 would allow **empty** pieces: for `[-3, -1]`, both pieces would come out as 0, the "crossing" run would be empty, and the answer would be 0 instead of −1.

## Cost, and a fair comparison

Each call does two recursive calls on halves, plus scans that touch every element of its range once: T(n) = 2T(n / 2) + n, the same recurrence as merge sort, so **O(n log n)**. Kadane is O(n). Both give the same answers, as a check on 1,000 random arrays confirms:

```swift run
var additions = 0

func crossingSum(_ numbers: [Int], _ low: Int, _ mid: Int, _ high: Int) -> Int {
    var sum = 0
    var bestLeft = numbers[mid - 1]
    for index in stride(from: mid - 1, through: low, by: -1) {
        sum += numbers[index]
        bestLeft = max(bestLeft, sum)
    }
    sum = 0
    var bestRight = numbers[mid]
    for index in mid..<high {
        sum += numbers[index]
        bestRight = max(bestRight, sum)
    }
    additions += high - low
    return bestLeft + bestRight
}

func bestSum(_ numbers: [Int], _ low: Int, _ high: Int) -> Int {
    if high - low == 1 {
        return numbers[low]
    }
    let mid = low + (high - low) / 2
    return max(bestSum(numbers, low, mid), bestSum(numbers, mid, high), crossingSum(numbers, low, mid, high))
}

func kadane(_ numbers: [Int]) -> Int {
    var current = numbers[0]
    var best = numbers[0]
    for value in numbers.dropFirst() {
        additions += 1
        current = max(value, current + value)
        best = max(best, current)
    }
    return best
}

// A small seeded generator, so the "random" arrays are the same on every run
var seed: UInt64 = 2_024
func nextRandom(_ range: ClosedRange<Int>) -> Int {
    seed = seed &* 6_364_136_223_846_793_005 &+ 1_442_695_040_888_963_407
    return range.lowerBound + Int((seed >> 33) % UInt64(range.count))
}

var agree = 0
for _ in 0..<1_000 {
    let numbers = (0..<nextRandom(1...30)).map { _ in nextRandom(-20...20) }
    if bestSum(numbers, 0, numbers.count) == kadane(numbers) {
        agree += 1
    }
}
print("agree on \(agree) of 1000 random arrays")

for n in [1_000, 100_000] {
    let numbers = (0..<n).map { _ in nextRandom(-100...100) }
    additions = 0
    let split = bestSum(numbers, 0, n)
    let splitWork = additions
    additions = 0
    let scan = kadane(numbers)
    print("n = \(n): both find \(split == scan ? "the same sum" : "different sums"); divide and conquer \(splitWork) additions, Kadane \(additions)")
}
```

```output
agree on 1000 of 1000 random arrays
n = 1000: both find the same sum; divide and conquer 9976 additions, Kadane 999
n = 100000: both find the same sum; divide and conquer 1668928 additions, Kadane 99999
```

At 100,000 values, the divide-and-conquer version does about 17 times more work: log₂ of 100,000 is about 17. In an interview, Kadane is the answer you lead with. The divide-and-conquer version is the classic follow-up question: "can you solve it another way?"

## Getting back to O(n): return four numbers

The crossing scans are the expensive part: they look at every element again at every level. Can each half tell you its best suffix and best prefix directly, instead of you rescanning? Yes, if each call returns a **summary** of its range, as in the previous lesson's smallest-and-largest pair:

| Field | Meaning |
| --- | --- |
| `total` | the sum of the whole range |
| `prefix` | the best run that starts at the range's left end |
| `suffix` | the best run that ends at the range's right end |
| `best` | the best run anywhere in the range |

Two summaries combine in O(1). The whole range's best prefix either stays inside the left half, or takes all of the left half and continues into the right: `max(left.prefix, left.total + right.prefix)`. The best suffix is the mirror image. And the best run is the best of the left's best, the right's best, and the crossing run, which is now simply `left.suffix + right.prefix`.

```swift run
// Four numbers per range make the combine step O(1)
struct Summary {
    let total: Int      // the sum of the whole range
    let prefix: Int     // the best run that starts at the range's left end
    let suffix: Int     // the best run that ends at the range's right end
    let best: Int       // the best run anywhere in the range
}

func combine(_ left: Summary, _ right: Summary) -> Summary {
    Summary(
        total: left.total + right.total,
        prefix: max(left.prefix, left.total + right.prefix),
        suffix: max(right.suffix, right.total + left.suffix),
        best: max(left.best, right.best, left.suffix + right.prefix)
    )
}

func summarise(_ numbers: [Int], _ low: Int, _ high: Int) -> Summary {
    if high - low == 1 {
        let value = numbers[low]
        return Summary(total: value, prefix: value, suffix: value, best: value)
    }
    let mid = low + (high - low) / 2
    return combine(summarise(numbers, low, mid), summarise(numbers, mid, high))
}

let left = summarise([-2, 1, -3, 4], 0, 4)
let right = summarise([-1, 2, 1, -5, 4], 0, 5)
print("left: ", left.total, left.prefix, left.suffix, left.best)
print("right:", right.total, right.prefix, right.suffix, right.best)
let whole = combine(left, right)
print("whole:", whole.total, whole.prefix, whole.suffix, whole.best)
print(summarise([-3, -1, -2], 0, 3).best)
```

```output
left:  0 0 4 4
right: 1 2 4 4
whole: 1 2 5 6
-1
```

Now T(n) = 2T(n / 2) + 1, which is **O(n)**, matching Kadane. In the combined line, the best suffix is 5: all of the right half (total 1) plus the left's best suffix (4), which is `[4, -1, 2, 1, -5, 4]`. And the all-negative array correctly gives −1, because every field of a single element is that element.

Why keep a summary when Kadane already exists? Because summaries can be combined in **any** grouping. Store one per block of an array, and when a value changes, only the summaries above it need recombining. That's the segment tree of Part VIII, and it answers "best run inside positions i to j" in O(log n) per question, even while the array changes. The same independence lets separate processor cores summarise separate chunks, with one cheap combine at the end.

<Callout kind="gotcha" title="Common mistakes">
- **Letting a crossing piece be empty.** Start `bestLeft` and `bestRight` from the elements next to the middle, not from 0, or a "crossing" run can quietly be all on one side, or empty, and all-negative inputs give 0.
- **Scanning the crossing pieces from the outside in.** The left piece must **end** at `mid - 1`, so it grows leftwards from there. Scanning from `low` towards the middle finds the best prefix instead, which isn't attached to the middle.
- **Combining the prefix with `right.prefix` alone.** A prefix that continues into the right half has to include the **whole** left half: `left.total + right.prefix`.
</Callout>
