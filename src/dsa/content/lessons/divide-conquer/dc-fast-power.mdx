## Why it matters

[Fast exponentiation](/dsa/learn/math-fast-power) in M15 computed huge powers in O(log n) steps. It's divide and conquer in its purest form: one subproblem of half the size, solved once and used twice. Seeing it that way explains why one small slip turns it back into O(n), why the recursive and loop versions are the same algorithm, and why it works for anything you can multiply, from remainders in cryptography to matrices that compute the billionth Fibonacci number.

## One half, used twice

To compute xⁿ, divide n in half, conquer x^(n/2) recursively, and combine by squaring, with one extra x when n is odd:

- x⁰ = 1;
- xⁿ = (x^(n/2))² if n is even;
- xⁿ = (x^(n/2))² · x if n is odd (with n/2 rounded down).

The two halves of the product are **the same subproblem**, so you solve it once. Compare three ways to write it, counting calls. All three work modulo 1,000,000,007, as in [Modular arithmetic](/dsa/learn/math-modular-arithmetic), so nothing overflows:

```swift run
let m = 1_000_000_007
var calls = 0

// Decrease by one: x^n = x · x^(n - 1)
func powerByOne(_ x: Int, _ n: Int) -> Int {
    calls += 1
    return n == 0 ? 1 : x * powerByOne(x, n - 1) % m
}

// Two calls on n / 2: correct, but it recomputes the same half
func powerTwice(_ x: Int, _ n: Int) -> Int {
    calls += 1
    if n == 0 { return 1 }
    let square = powerTwice(x, n / 2) * powerTwice(x, n / 2) % m
    return n % 2 == 0 ? square : square * x % m
}

// One call on n / 2, used twice
func power(_ x: Int, _ n: Int) -> Int {
    calls += 1
    if n == 0 { return 1 }
    let half = power(x, n / 2)
    let square = half * half % m
    return n % 2 == 0 ? square : square * x % m
}

for n in [10, 1_000, 10_000] {
    var counts: [Int] = []
    var answers: [Int] = []
    for method in [powerByOne, powerTwice, power] {
        calls = 0
        answers.append(method(3, n))
        counts.append(calls)
    }
    let agree = Set(answers).count == 1 ? "agree" : "disagree"
    print("n = \(n): by one \(counts[0]) calls, two halves \(counts[1]), one half \(counts[2]); answers \(agree)")
}
```

```output
n = 10: by one 11 calls, two halves 31, one half 5; answers agree
n = 1000: by one 1001 calls, two halves 2047, one half 11; answers agree
n = 10000: by one 10001 calls, two halves 32767, one half 15; answers agree
```

Write each as a recurrence and the counts make sense:

| Version | Recurrence | Cost |
| --- | --- | --- |
| decrease by one | T(n) = T(n − 1) + 1 | O(n) |
| two calls on half | T(n) = 2T(n / 2) + 1 | O(n) |
| one call on half | T(n) = T(n / 2) + 1 | O(log n) |

The two-call version halves n, yet it's no faster than the plain loop. Its recursion tree doubles in width at every level, so after log₂ n levels it has about n leaves; the Master theorem calls that "the leaves win". It's the overlapping-subproblems trap from the first lesson in miniature: the same half, solved twice, at every level. Storing it in `half` is all the "memory" fast power needs.

<Callout kind="gotcha" title="Swift gotcha: the recursion can be too deep, but not here">
`powerByOne(3, 10_000_000)` would make ten million nested calls and overflow the call stack. The halving version is only about log₂ n deep, 60 calls for n = 10¹⁸, so recursion is perfectly safe for it.
</Callout>

## Top-down recursion, top-down loop

M15's loop read the exponent's bits from the **bottom**, squaring a running power of x. The recursion works from the **top**. Each call strips the last bit off n (that's `n / 2`) on the way down, and on the way back up it squares, multiplying by x when the stripped bit was 1. The same steps make a loop with no call stack: read n's bits from the most significant end.

```swift run
// Top-down: the recursion halves n on the way down and builds the answer on the way back up
func power(_ x: Int, _ n: Int) -> Int {
    if n == 0 { return 1 }
    let half = power(x, n / 2)
    let result = n % 2 == 0 ? half * half : half * half * x
    print("power(\(x), \(n)) = \(result)")
    return result
}

// The same steps as a loop: read n's bits from the top, squaring for each bit and multiplying for each 1
func powerFromTop(_ x: Int, _ n: Int) -> Int {
    var result = 1
    var exponent = 0                              // result is always x^exponent
    for bit in String(n, radix: 2) {
        result *= result                          // doubles the exponent
        exponent *= 2
        if bit == "1" {
            result *= x                           // adds one to the exponent
            exponent += 1
        }
        print("bit \(bit): \(x)^\(exponent) = \(result)")
    }
    return result
}

print(String(13, radix: 2))
_ = power(3, 13)
_ = powerFromTop(3, 13)
```

```output
1101
power(3, 1) = 3
power(3, 3) = 27
power(3, 6) = 729
power(3, 13) = 1594323
bit 1: 3^1 = 3
bit 1: 3^3 = 27
bit 0: 3^6 = 729
bit 1: 3^13 = 1594323
```

The exponents 1, 3, 6, 13 are 1, 11, 110 and 1101 in binary: the leading bits of 13, one more each step. Both versions do the same multiplications in the same order. Doubling the exponent shifts its binary form one place left, and the extra x sets the new last bit.

Nothing here depends on base 2. In base 10, appending a digit d to the exponent turns xᵉ into x^(10e + d) = (xᵉ)¹⁰ · x^d. So an exponent given as a string of thousands of decimal digits, far too big for any `Int`, can be handled one digit at a time. That's this lesson's practice problem.

## Anything you can multiply

Fast power never used anything special about numbers. It needs two things:

- **Associativity:** (ab)c = a(bc), so the n copies of x can be grouped as two halves.
- **An identity**, a "1" to return when n = 0.

It doesn't need ab = ba. Matrix multiplication is associative but not commutative, and the 2 × 2 identity matrix plays the part of 1. Raising the matrix `[[1, 1], [1, 0]]` to the power n gives `[[F(n + 1), F(n)], [F(n), F(n - 1)]]`, where F is the Fibonacci sequence, so fast power finds Fibonacci numbers in O(log n) matrix multiplications, as [Matrix basics](/dsa/learn/math-matrices) previewed:

```swift run
// Fibonacci numbers by fast power of the matrix [[1, 1], [1, 0]], modulo m
typealias Matrix2 = (a: Int, b: Int, c: Int, d: Int)     // [[a, b], [c, d]]
let m = 1_000_000_007

func multiply(_ p: Matrix2, _ q: Matrix2) -> Matrix2 {
    (a: (p.a * q.a + p.b * q.c) % m, b: (p.a * q.b + p.b * q.d) % m,
     c: (p.c * q.a + p.d * q.c) % m, d: (p.c * q.b + p.d * q.d) % m)
}

func power(_ matrix: Matrix2, _ n: Int) -> Matrix2 {
    if n == 0 {
        return (a: 1, b: 0, c: 0, d: 1)                    // the identity matrix: "multiply by nothing"
    }
    let half = power(matrix, n / 2)
    let square = multiply(half, half)
    return n % 2 == 0 ? square : multiply(square, matrix)
}

// [[1, 1], [1, 0]] to the power n is [[F(n + 1), F(n)], [F(n), F(n - 1)]]
func fibonacci(_ n: Int) -> Int {
    power((a: 1, b: 1, c: 1, d: 0), n).b
}

print(fibonacci(10), fibonacci(50))
print(fibonacci(1_000_000_000_000_000_000))
```

```output
55 586268941
209783453
```

F(10) is 55. F(50) is 12,586,269,025, whose remainder modulo 1,000,000,007 is 586,268,941. And F(10¹⁸) modulo 1,000,000,007 takes about 60 levels of recursion, where adding up the sequence term by term would never finish.

The same idea powers [LCA with binary lifting](/dsa/learn/ag-lca-binary-lifting) in M47: "jump 2^k steps up the tree" is a step function composed with itself, and composing functions is associative too.

<Callout kind="gotcha" title="Common mistakes">
- **Calling the half twice.** `power(x, n / 2) * power(x, n / 2)` is correct and O(n). Store the half in a constant.
- **Overflowing the square.** Reduce modulo m after every multiplication. With m below about 3 × 10⁹, the product of two remainders fits in an `Int`.
- **The wrong identity.** For matrices, n = 0 must return the identity matrix, not a matrix of ones.
</Callout>
