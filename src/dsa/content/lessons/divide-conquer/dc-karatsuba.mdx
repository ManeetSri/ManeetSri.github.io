## Why it matters

An `Int` holds about 19 digits. Encryption keys are numbers with hundreds of digits, and record-setting calculations of π use trillions. Programs that need numbers that big store them as arrays of digits and do the arithmetic themselves, and multiplication is the expensive part: the method you learned at school is O(n²) for two n-digit numbers. In 1960, Anatoly Karatsuba, a 23-year-old student in Moscow, found a divide-and-conquer method that needs only **three** half-size multiplications instead of four, and runs in O(n^1.585). Arbitrary-precision libraries in many languages switch to it once numbers get long enough.

## Numbers as digit arrays

Store a big number as an array of decimal digits, **least significant first**: 1234 becomes `[4, 3, 2, 1]`. That order makes carrying easy, because carries move towards higher indices, and the array can grow at its end.

Schoolbook multiplication multiplies every digit of one number by every digit of the other and adds each product into position `i + j`, carrying as it goes. Two n-digit numbers need n² digit products: **O(n²)**. For a million digits that's 10¹² products.

## Splitting in half doesn't help on its own

Split each number into a high half and a low half of m digits each:

- x = x₁ · 10^m + x₀
- y = y₁ · 10^m + y₀

For 1234 with m = 2, that's x₁ = 12 and x₀ = 34. Multiplying out:

x · y = **x₁y₁** · 10^(2m) + (**x₁y₀** + **x₀y₁**) · 10^m + **x₀y₀**

Multiplying by a power of 10 is only shifting digits, which is cheap. So one n-digit product becomes **four** products of n/2 digits, plus O(n) additions and shifts. That's T(n) = 4T(n / 2) + n, and by the [Master theorem](/dsa/learn/bigo-master-theorem) (a = 4 is greater than b^d = 2) it's Θ(n²). Dividing gained nothing: four quarter-size jobs are as much work as the original.

## Karatsuba's trick: three products

You don't need x₁y₀ and x₀y₁ separately, only their **sum**. Multiply the sums of the halves:

(x₁ + x₀)(y₁ + y₀) = x₁y₁ + x₁y₀ + x₀y₁ + x₀y₀

You're computing x₁y₁ and x₀y₀ anyway, so subtract them:

x₁y₀ + x₀y₁ = (x₁ + x₀)(y₁ + y₀) − x₁y₁ − x₀y₀

Three multiplications instead of four, paid for with a few extra additions and subtractions, which are only O(n). Try it on numbers small enough for `Int`:

```swift run
// Karatsuba on numbers small enough for Int, printing the pieces of the top-level split
func powerOfTen(_ exponent: Int) -> Int {
    var result = 1
    for _ in 0..<exponent {
        result *= 10
    }
    return result
}

func karatsuba(_ x: Int, _ y: Int, show: Bool = false) -> Int {
    if x < 10 || y < 10 {
        return x * y                                    // a single digit: multiply directly
    }
    let m = max(String(x).count, String(y).count) / 2
    let base = powerOfTen(m)
    let (x1, x0) = x.quotientAndRemainder(dividingBy: base)
    let (y1, y0) = y.quotientAndRemainder(dividingBy: base)
    let high = karatsuba(x1, y1)                         // x1 · y1
    let low = karatsuba(x0, y0)                          // x0 · y0
    let middle = karatsuba(x1 + x0, y1 + y0) - high - low    // x1 · y0 + x0 · y1, with one product
    if show {
        print("x1 = \(x1), x0 = \(x0), y1 = \(y1), y0 = \(y0)")
        print("high = \(high), low = \(low), middle = (\(x1 + x0) × \(y1 + y0)) - \(high) - \(low) = \(middle)")
    }
    return high * base * base + middle * base + low
}

let product = karatsuba(1234, 5678, show: true)
print(product, product == 1234 * 5678)
```

```output
x1 = 12, x0 = 34, y1 = 56, y0 = 78
high = 672, low = 2652, middle = (46 × 134) - 672 - 2652 = 2840
7006652 true
```

Check the middle term by hand: 12 × 78 + 34 × 56 = 936 + 1,904 = 2,840. Then 672 · 10⁴ + 2,840 · 10² + 2,652 = 6,720,000 + 284,000 + 2,652 = 7,006,652. Each of the three smaller products is computed the same way, recursively, until one side is a single digit.

## Why three beats four

The recurrence is now T(n) = 3T(n / 2) + n. Here a = 3 is greater than b^d = 2, so the leaves dominate and T(n) = Θ(n^(log₂ 3)) ≈ **Θ(n^1.585)**.

Picture the recursion tree. With four products, level k has 4^k calls on n/2^k digits, and the bottom level has n² single-digit products. With three, the bottom level has only 3^(log₂ n) = n^(log₂ 3) of them. One fewer product per call compounds at every level:

| Digits | n² | n^1.585 |
| --- | --- | --- |
| 1,000 | 1,000,000 | about 57,000 |
| 1,000,000 | 10¹² | about 3 × 10⁹ |

## On digit arrays

Here's the real thing, working on digit arrays of any length. It splits off the m lowest digits, recurses three times, and recombines with additions and shifts. Below a **cutoff** length it falls back to schoolbook, which is faster for short numbers because it has no overhead:

```swift run
// Big numbers as arrays of decimal digits, least significant first: 1234 is [4, 3, 2, 1]
var digitProducts = 0                                    // single-digit multiplications performed

func digits(_ text: String) -> [Int] {
    text.reversed().map { Int(String($0))! }
}

func text(_ digits: [Int]) -> String {
    digits.reversed().map(String.init).joined()
}

func trimmed(_ number: [Int]) -> [Int] {                 // drop leading zeros, keeping at least one digit
    var number = number
    while number.count > 1 && number.last == 0 {
        number.removeLast()
    }
    return number
}

func add(_ a: [Int], _ b: [Int]) -> [Int] {
    var result: [Int] = []
    var carry = 0
    for i in 0..<max(a.count, b.count) {
        let sum = (i < a.count ? a[i] : 0) + (i < b.count ? b[i] : 0) + carry
        result.append(sum % 10)
        carry = sum / 10
    }
    if carry > 0 {
        result.append(carry)
    }
    return result
}

func subtract(_ a: [Int], _ b: [Int]) -> [Int] {        // a - b, where a ≥ b
    var result: [Int] = []
    var borrow = 0
    for i in 0..<a.count {
        var difference = a[i] - borrow - (i < b.count ? b[i] : 0)
        borrow = difference < 0 ? 1 : 0
        if difference < 0 {
            difference += 10
        }
        result.append(difference)
    }
    return trimmed(result)
}

func shifted(_ a: [Int], by places: Int) -> [Int] {     // multiply by 10^places
    a == [0] ? a : Array(repeating: 0, count: places) + a
}

func schoolbook(_ a: [Int], _ b: [Int]) -> [Int] {
    var result = Array(repeating: 0, count: a.count + b.count)
    for i in a.indices {
        var carry = 0
        for j in b.indices {
            digitProducts += 1
            let current = result[i + j] + a[i] * b[j] + carry
            result[i + j] = current % 10
            carry = current / 10
        }
        result[i + b.count] += carry
    }
    return trimmed(result)
}

func karatsuba(_ a: [Int], _ b: [Int], cutoff: Int) -> [Int] {
    if a.count <= cutoff || b.count <= cutoff {
        return schoolbook(a, b)                          // small enough: the plain method is faster
    }
    let m = max(a.count, b.count) / 2                    // split off the m lowest digits
    let a0 = trimmed(Array(a.prefix(m))), a1 = a.count > m ? Array(a.dropFirst(m)) : [0]
    let b0 = trimmed(Array(b.prefix(m))), b1 = b.count > m ? Array(b.dropFirst(m)) : [0]
    let high = karatsuba(a1, b1, cutoff: cutoff)
    let low = karatsuba(a0, b0, cutoff: cutoff)
    let both = karatsuba(add(a1, a0), add(b1, b0), cutoff: cutoff)
    let middle = subtract(subtract(both, high), low)
    return trimmed(add(add(shifted(high, by: 2 * m), shifted(middle, by: m)), low))
}

let x = digits("12345678901234567890")
let y = digits("98765432109876543210")
print(text(karatsuba(x, y, cutoff: 4)))

// Count digit products on random numbers, recursing all the way down to single digits
var seed: UInt64 = 1_960
func randomDigits(_ count: Int) -> [Int] {
    var result: [Int] = []
    for _ in 0..<count {
        seed = seed &* 6_364_136_223_846_793_005 &+ 1_442_695_040_888_963_407
        result.append(Int((seed >> 33) % 10))
    }
    result[count - 1] = max(result[count - 1], 1)        // no leading zero
    return result
}

for n in [64, 256, 1_024] {
    let a = randomDigits(n), b = randomDigits(n)
    digitProducts = 0
    let plain = schoolbook(a, b)
    let plainCount = digitProducts
    digitProducts = 0
    let fast = karatsuba(a, b, cutoff: 1)
    print("\(n) digits: \(plain == fast ? "same product" : "different!"), schoolbook \(plainCount), Karatsuba \(digitProducts) digit products")
}
```

```output
1219326311370217952237463801111263526900
64 digits: same product, schoolbook 4096, Karatsuba 1196 digit products
256 digits: same product, schoolbook 65536, Karatsuba 10823 digit products
1024 digits: same product, schoolbook 1048576, Karatsuba 99321 digit products
```

What to notice:

- **Each time n grows 4 times**, schoolbook does 16 times the products, and Karatsuba about 9 times: 4^1.585 is 9. At 1,024 digits it does about a tenth of the work.
- **Uneven halves.** The split point m comes from the **longer** number. If the shorter one has m digits or fewer, its high half is `[0]`, and the recursion still works.
- **The sums can carry.** x₁ + x₀ may have m + 1 digits, which is why the measured counts sit a little above the ideal 3^(log₂ n).
- **The subtractions never go negative**, because the middle term x₁y₀ + x₀y₁ can't be negative. So `subtract` only needs to handle a ≥ b.

## From digits to real big integers

Real big-integer code makes two changes, and keeps the algorithm the same:

- **A bigger base.** Instead of one decimal digit per element, each element (a **limb**) holds a much bigger chunk, such as 9 decimal digits (base 10⁹) or 32 bits. A product of two limbs still fits in 64 bits, and there are far fewer limbs to multiply. Base 10 in this lesson is only for readability.
- **A tuned cutoff.** Karatsuba's extra additions and allocations only pay off for long numbers, so libraries use schoolbook below a threshold of a few dozen limbs, and Karatsuba above it.

For gigantic numbers, libraries move on again: **Toom–Cook** splits into three parts with five products (about n^1.465), and methods built on the fast Fourier transform reach O(n log n). Swift's standard library has no arbitrary-size integer type, so programs that need one use a package, and every serious package uses these ideas.

<Callout kind="gotcha" title="Common mistakes">
- **Subtracting only one product.** The middle term is `both - high - low`. Forgetting either subtraction gives a number that's too big, and small tests may not catch it.
- **Shifting by the wrong amount.** The high product shifts by 2m, the middle by m, where m is the number of digits in the **low** halves, not half of the shorter number.
- **Leading zeros.** A low half like `[0, 0, 5]` (the number 500) is fine, but a result like `[2, 1, 0, 0]` must be trimmed to `[2, 1]` before printing, or you'll print "0012".
- **No cutoff.** Recursing down to single digits is correct but slow. Switch to schoolbook for short inputs.
</Callout>
