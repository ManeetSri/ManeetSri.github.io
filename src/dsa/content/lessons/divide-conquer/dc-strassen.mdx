## Why it matters

Matrix multiplication is everywhere: every 3D transform in a game or an iOS animation, every layer of a neural network, and graph questions such as counting paths of length k. The method from [Matrix basics](/dsa/learn/math-matrices) takes n³ multiplications for two n × n matrices, and for a long time everyone assumed that was the best possible. In 1969, Volker Strassen showed that a 2 × 2 multiplication can be done with **7** multiplications instead of 8. Applied recursively to blocks, that gives **O(n^2.807)**. This lesson is about the idea, and about why the fastest real-world libraries usually don't use it.

## The standard method

Entry (i, j) of C = A × B is row i of A times column j of B: multiply matching entries and add them up. For n × n matrices that's n multiplications per entry and n² entries, so **n³ multiplications**. For 2 × 2 matrices:

| Entry | Formula |
| --- | --- |
| C₁₁ | A₁₁B₁₁ + A₁₂B₂₁ |
| C₁₂ | A₁₁B₁₂ + A₁₂B₂₂ |
| C₂₁ | A₂₁B₁₁ + A₂₂B₂₁ |
| C₂₂ | A₂₁B₁₂ + A₂₂B₂₂ |

That's 8 multiplications and 4 additions.

## Blocks: the same formulas, one level up

Split each n × n matrix into four **blocks** of size n/2 × n/2. The four formulas above still hold, with each letter now standing for a block, each product a block multiplication and each sum a block addition. So one n × n product becomes **8** half-size products plus 4 block additions, each costing (n/2)² additions:

T(n) = 8T(n / 2) + n²

By the [Master theorem](/dsa/learn/bigo-master-theorem), a = 8 is greater than b^d = 4, so T(n) = Θ(n^(log₂ 8)) = **Θ(n³)**. Exactly like splitting numbers into halves before Karatsuba, dividing alone gains nothing. The question is whether fewer than 8 products can do the job.

## Seven products

Strassen found seven products, each a sum of A's blocks times a sum of B's blocks, from which all four entries of C can be assembled with additions and subtractions only:

| Product | Definition |
| --- | --- |
| M₁ | (A₁₁ + A₂₂)(B₁₁ + B₂₂) |
| M₂ | (A₂₁ + A₂₂) B₁₁ |
| M₃ | A₁₁ (B₁₂ − B₂₂) |
| M₄ | A₂₂ (B₂₁ − B₁₁) |
| M₅ | (A₁₁ + A₁₂) B₂₂ |
| M₆ | (A₂₁ − A₁₁)(B₁₁ + B₁₂) |
| M₇ | (A₁₂ − A₂₂)(B₂₁ + B₂₂) |

| Entry | Assembled from |
| --- | --- |
| C₁₁ | M₁ + M₄ − M₅ + M₇ |
| C₁₂ | M₃ + M₅ |
| C₂₁ | M₂ + M₄ |
| C₂₂ | M₁ − M₂ + M₃ + M₆ |

Try it on numbers first:

```swift run
// Strassen's seven products for one 2 × 2 multiplication
let (a11, a12, a21, a22) = (1, 2, 3, 4)
let (b11, b12, b21, b22) = (5, 6, 7, 8)

let m1 = (a11 + a22) * (b11 + b22)
let m2 = (a21 + a22) * b11
let m3 = a11 * (b12 - b22)
let m4 = a22 * (b21 - b11)
let m5 = (a11 + a12) * b22
let m6 = (a21 - a11) * (b11 + b12)
let m7 = (a12 - a22) * (b21 + b22)
print("M1...M7:", m1, m2, m3, m4, m5, m6, m7)

let strassen = [[m1 + m4 - m5 + m7, m3 + m5], [m2 + m4, m1 - m2 + m3 + m6]]
let standard = [[a11 * b11 + a12 * b21, a11 * b12 + a12 * b22], [a21 * b11 + a22 * b21, a21 * b12 + a22 * b22]]
print("Strassen:", strassen)
print("standard:", standard)
```

```output
M1...M7: 65 35 -2 8 24 22 -30
Strassen: [[19, 22], [43, 50]]
standard: [[19, 22], [43, 50]]
```

### Why the formulas are right

Check C₁₂ by expanding: M₃ + M₅ = A₁₁B₁₂ − A₁₁B₂₂ + A₁₁B₂₂ + A₁₂B₂₂ = A₁₁B₁₂ + A₁₂B₂₂. The A₁₁B₂₂ terms cancel, leaving exactly the standard formula.

C₁₁ takes more cancelling. Expanding each product:

- M₁ = A₁₁B₁₁ + A₁₁B₂₂ + A₂₂B₁₁ + A₂₂B₂₂
- M₄ = A₂₂B₂₁ − A₂₂B₁₁
- −M₅ = −A₁₁B₂₂ − A₁₂B₂₂
- M₇ = A₁₂B₂₁ + A₁₂B₂₂ − A₂₂B₂₁ − A₂₂B₂₂

Adding them, every term cancels in pairs except **A₁₁B₁₁ + A₁₂B₂₁**, which is C₁₁. C₂₁ and C₂₂ work out the same way.

One more detail makes the recursion legal. Matrix multiplication isn't commutative: for blocks, XY and YX are usually different. Look at the expansions again: every product keeps its A block on the left and its B block on the right. Strassen's formulas never swap the order of a product, so they hold when the entries are blocks, and the seven block products can themselves be computed with Strassen.

## The recursive algorithm

For n a power of two, split both matrices into quarters, form the seven products recursively, and assemble C. This version counts its work against the standard method's:

```swift run
typealias Matrix = [[Int]]

var multiplications = 0
var additions = 0                                        // additions and subtractions

func standard(_ a: Matrix, _ b: Matrix) -> Matrix {
    let n = a.count
    var c = Array(repeating: Array(repeating: 0, count: n), count: n)
    for i in 0..<n {
        for j in 0..<n {
            for k in 0..<n {
                multiplications += 1
                additions += 1
                c[i][j] += a[i][k] * b[k][j]
            }
        }
    }
    return c
}

func add(_ a: Matrix, _ b: Matrix) -> Matrix {
    additions += a.count * a.count
    return zip(a, b).map { zip($0, $1).map(+) }
}

func subtract(_ a: Matrix, _ b: Matrix) -> Matrix {
    additions += a.count * a.count
    return zip(a, b).map { zip($0, $1).map(-) }
}

func quarter(_ m: Matrix, _ row: Int, _ column: Int) -> Matrix {   // the half-size block at (row, column)
    let half = m.count / 2
    return m[row..<(row + half)].map { Array($0[column..<(column + half)]) }
}

func joined(_ c11: Matrix, _ c12: Matrix, _ c21: Matrix, _ c22: Matrix) -> Matrix {
    zip(c11, c12).map { $0 + $1 } + zip(c21, c22).map { $0 + $1 }
}

// Strassen's algorithm, for n a power of two, recursing all the way down to single numbers
func strassen(_ a: Matrix, _ b: Matrix) -> Matrix {
    let n = a.count
    if n == 1 {
        multiplications += 1
        return [[a[0][0] * b[0][0]]]
    }
    let h = n / 2
    let (a11, a12, a21, a22) = (quarter(a, 0, 0), quarter(a, 0, h), quarter(a, h, 0), quarter(a, h, h))
    let (b11, b12, b21, b22) = (quarter(b, 0, 0), quarter(b, 0, h), quarter(b, h, 0), quarter(b, h, h))
    let m1 = strassen(add(a11, a22), add(b11, b22))
    let m2 = strassen(add(a21, a22), b11)
    let m3 = strassen(a11, subtract(b12, b22))
    let m4 = strassen(a22, subtract(b21, b11))
    let m5 = strassen(add(a11, a12), b22)
    let m6 = strassen(subtract(a21, a11), add(b11, b12))
    let m7 = strassen(subtract(a12, a22), add(b21, b22))
    return joined(add(subtract(add(m1, m4), m5), m7), add(m3, m5),
                  add(m2, m4), add(add(subtract(m1, m2), m3), m6))
}

// Fill an n × n matrix with small numbers that look random but are the same on every run
func sample(_ n: Int, _ salt: Int) -> Matrix {
    (0..<n).map { i in (0..<n).map { j in (i * 7 + j * 3 + salt) % 10 - 4 } }
}

for n in [2, 4, 8, 16, 32] {
    let a = sample(n, 1), b = sample(n, 5)
    (multiplications, additions) = (0, 0)
    let plain = standard(a, b)
    let plainCounts = (multiplications, additions)
    (multiplications, additions) = (0, 0)
    let fast = strassen(a, b)
    print("n = \(n): \(plain == fast ? "same" : "different!"), standard \(plainCounts.0) × and \(plainCounts.1) +, Strassen \(multiplications) × and \(additions) +")
}
```

```output
n = 2: same, standard 8 × and 8 +, Strassen 7 × and 18 +
n = 4: same, standard 64 × and 64 +, Strassen 49 × and 198 +
n = 8: same, standard 512 × and 512 +, Strassen 343 × and 1674 +
n = 16: same, standard 4096 × and 4096 +, Strassen 2401 × and 12870 +
n = 32: same, standard 32768 × and 32768 +, Strassen 16807 × and 94698 +
```

The multiplications follow 8^k against 7^k exactly: each doubling of n multiplies the standard count by 8 and Strassen's by 7. But look at the additions. Each level does 18 block additions instead of 4, and at these sizes that more than cancels the saved multiplications.

## The cost

Seven half-size products plus 18 additions of (n/2) × (n/2) blocks:

T(n) = 7T(n / 2) + O(n²)

Now a = 7 is still greater than b^d = 4, so the leaves dominate: T(n) = Θ(n^(log₂ 7)) ≈ **Θ(n^2.807)**. As with Karatsuba, one fewer subproblem changes the exponent, and the extra additions only affect the constant. Counting multiplications alone, the saving grows with n:

| n | n³ | n^2.807 |
| --- | --- | --- |
| 32 | 32,768 | 16,807 |
| 1,024 | about 1.1 × 10⁹ | about 2.8 × 10⁸ |
| 32,768 | about 3.5 × 10¹³ | about 4.7 × 10¹² |

Counting every operation, the version above, which recurses down to single numbers, only overtakes the standard method at around n = 1,024. That's why practical versions stop recursing at a **cutoff** and multiply small blocks the standard way.

## Why it's rarely used in practice

Strassen's algorithm is a landmark, yet the matrix routines you'll actually call, such as those in Apple's Accelerate framework, are built on carefully tuned versions of the standard method. The reasons:

- **The crossover is high.** Extra additions, temporary blocks and the memory to hold them mean it only wins for large matrices, and even then by a modest factor.
- **Hardware loves the standard method.** Its regular loops can be arranged to reuse data in the processor's cache and to multiply several numbers per instruction. Tuned this way, three nested loops run close to the chip's peak speed. Strassen's scattered additions are harder to tune.
- **Rounding error.** With `Double`, Strassen adds and subtracts entries from different parts of the matrices, so large values can swallow small ones before they cancel.
- **Awkward sizes.** Matrices that aren't a power of two in size need padding with zeros, or special handling of odd rows and columns.

Here's the rounding problem in miniature, computing one entry both ways:

```swift run
// One entry of a 2 × 2 product, with Doubles: C22 = A21 · B12 + A22 · B22
let (a11, a21, a22) = (1e16, 0.0, 1.0)      // A12 and B21 aren't needed for C22
let (b11, b12, b22) = (0.0, 0.0, 1.0)

let standard = a21 * b12 + a22 * b22

let m1 = (a11 + a22) * (b11 + b22)        // 1e16 + 1 rounds to 1e16: the 1 is lost here
let m2 = (a21 + a22) * b11
let m3 = a11 * (b12 - b22)
let m6 = (a21 - a11) * (b11 + b12)
let strassen = m1 - m2 + m3 + m6

print("standard:", standard)
print("Strassen:", strassen)
```

```output
standard: 1.0
Strassen: 0.0
```

The true answer is 1. Strassen's C₂₂ adds A₁₁ to A₂₂ inside M₁, and a `Double` near 10¹⁶ can't hold that extra 1, so the answer comes out as 0. The standard formula never mixes A₁₁ into C₂₂ at all. Real data is rarely this extreme, but Strassen's error bounds are measurably weaker.

It does earn its place with exact arithmetic, such as integers or remainders modulo a prime, where rounding can't happen, and for very large matrices. Its real legacy is theoretical: it started a race to lower the exponent of matrix multiplication, which now stands at about 2.37. Those later algorithms have constants so enormous that nobody runs them; they're sometimes called **galactic algorithms**.

<Callout kind="gotcha" title="Common mistakes">
- **A sign slip in one formula.** Every mistake in the seven products or four sums gives a wrong answer that looks plausible. Test against the standard method on small matrices, as the example does.
- **Recursing down to single numbers.** For a 2 × 2 of plain numbers, Strassen does 7 multiplications and 18 additions instead of 8 and 4. Stop at a cutoff size and switch to the standard method.
- **Assuming it's faster because the exponent is smaller.** Big-O describes growth, not speed at the sizes you have. Measure before choosing it.
</Callout>
