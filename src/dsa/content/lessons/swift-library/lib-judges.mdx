## Why it matters

The last two lessons showed packages that make Swift feel complete. Then you open a coding interview, or a contest, and none of it is there. Knowing in advance what each setting allows saves you from writing `import Collections` and watching it fail with the clock running. It also changes what you practise: the structures you can't import are the ones you must be able to write quickly from memory.

## What online judges give you

An **online judge** is a site that compiles your code, runs it against hidden tests and gives a verdict. They come in two styles:

- **Function-style** (as on LeetCode-like sites): you fill in a method on a class they provide. They parse the input, call your method and compare its return value. Types such as `TreeNode` or `ListNode` are usually defined for you, in their own shape.
- **Input-output style** (as on Codeforces-like and many contest sites): your program reads standard input and prints to standard output. You parse everything yourself; the next lesson's template is built for this.

Either way, your code is **one file of plain Swift**. You can't add a `Package.swift`, so swift-algorithms and swift-collections are out. In general you get the standard library, and usually Foundation too, but the details differ from site to site and change over time, so **check the judge's environment** before relying on anything. Most judges have a help or FAQ page that lists:

| Check | Why it matters |
| --- | --- |
| The Swift version | A judge on an older Swift rejects newer syntax. If it's behind, avoid recent features, such as `if let value {` shorthand (Swift 5.7) or typed `throws` (Swift 6). |
| Whether Foundation is available | `FileHandle` for fast input, `String(format:)`, `sqrt` and `pow` come from Foundation; `squareRoot()` doesn't need it. |
| The compiler flags | Most compile with optimisation (`-O`). If one doesn't, Swift is much slower there, and plain arrays beat clever abstractions. |
| Time and memory limits | Swift is fast when optimised, but its startup and `String` handling cost more than C++'s. |
| What's predefined | On function-style sites, `TreeNode` may have `val` instead of `value`, and its properties may be optionals of a class you can't change. |

If a site doesn't say, submit a tiny program that prints something only a newer Swift can compile, and see whether it's accepted. That's quicker than discovering the answer mid-contest.

## What to do in an interview

Interviewers know Swift has no heap, deque or ordered map built in. What they want to see is judgement: you know what exists, and you can build what's missing. A good pattern has three steps:

1. **Say what you'd use in production.** "In an app I'd import `Deque` from swift-collections."
2. **Ask whether you need to write it.** "Shall I write a small queue, or can I assume one exists?" For a problem where the heap isn't the point, such as Dijkstra, many interviewers will let you assume one with a stated API. Others will want it written. Either answer is fine; asking shows you know it's a real question in Swift.
3. **If you write it, write the minimal version** that gives the right complexity, and move on.

Here's the kind of minimal version that step 3 means. It's [A queue with a head index](/dsa/learn/queue-head-index) in about a dozen lines, used for BFS:

```swift run
// "In production I'd use Deque from swift-collections. Here's a queue with a head index:
// enqueue and dequeue are O(1), and the array is never shifted."
struct Queue<Element> {
    private var items: [Element] = []
    private var head = 0

    var isEmpty: Bool { head == items.count }

    mutating func enqueue(_ item: Element) {
        items.append(item)
    }

    mutating func dequeue() -> Element? {
        guard head < items.count else { return nil }
        defer { head += 1 }
        return items[head]
    }
}

func distances(from start: Int, in graph: [[Int]]) -> [Int] {
    var distance = Array(repeating: -1, count: graph.count)
    distance[start] = 0
    var queue = Queue<Int>()
    queue.enqueue(start)
    while let node = queue.dequeue() {
        for next in graph[node] where distance[next] == -1 {
            distance[next] = distance[node] + 1
            queue.enqueue(next)
        }
    }
    return distance
}

let graph = [[1, 2], [0, 3], [0, 3], [1, 2, 4], [3], []]
print(distances(from: 0, in: graph))
```

```output
[0, 1, 1, 2, 3, -1]
```

It never frees the dequeued slots, which is fine for one BFS and worth saying out loud. Mentioning a trade-off before the interviewer asks is a strong signal.

## DSAKit as your own toolbox

DSAKit is code you understand line by line, which makes it more useful than any package in the settings that ban packages:

- **Contests.** Many contest rules allow code you wrote before the contest, as long as it's yours. Check each contest's rules, then keep a file of your own snippets, such as the heap, union-find and the scanner from the next lesson, ready to paste above `main`. Pasting your own tested heap beats rewriting one at speed.
- **Function-style practice sites.** You can paste the pieces you need into the editor along with your solution, since it's all one file.
- **Interviews.** You can't paste anything, so the toolbox becomes a checklist of what to rewrite. Practise rewriting each piece from memory until it's routine.
- **Apps.** Use the packages. DSAKit taught you what they cost; you don't need to ship it.

## Where you are, and what you can use

| Setting | Packages? | What to do |
| --- | --- | --- |
| Your app or server | yes | swift-collections and swift-algorithms |
| A take-home exercise | usually; ask | a package is fine if you'd defend it in review |
| Function-style judge | no | standard library, plus your own pasted helpers |
| Input-output contest | no | a fast-input template, plus your own pre-written code if the rules allow it |
| Live interview | no | say what you'd import, ask, then write the minimal version |

<Callout kind="tip" title="Know the standard library cold">
The settings that ban packages still give you the whole standard library. `sort(by:)`, `partition(by:)`, `zip(a, a.dropFirst())`, `Dictionary(grouping:by:)` and `Set.insert(_:).inserted` cover a surprising amount of what packages offer. Everything in [Standard library algorithms](/dsa/learn/lib-stdlib-algorithms) is fair game anywhere Swift runs.
</Callout>
