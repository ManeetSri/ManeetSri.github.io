## Why it matters

The standard library stops short of many algorithms you reach for daily: "every pair of these", "each element with the next one", "this array in groups of four", "the unique values, in order". Apple's open-source **swift-algorithms** package fills those gaps with small, generic, well-tested methods that work on any collection. You've already met three of them: `rotate(toStartAt:)` in Part III, `permutations()` alongside next permutation, and `partitioningIndex(where:)` in [partitioningIndex in swift-algorithms](/dsa/learn/bs-partitioning-index). This lesson tours the rest of the useful ones, says what each costs, and shows how to get the same result without the package when you can't use it.

## Adding the package

You saw this in [partitioningIndex in swift-algorithms](/dsa/learn/bs-partitioning-index); here it is again for reference. In a Swift package, add the dependency and the `Algorithms` product:

```swift
// swift-tools-version: 6.0
import PackageDescription

let package = Package(
    name: "Planner",
    dependencies: [
        .package(url: "https://github.com/apple/swift-algorithms", from: "1.2.0"),
    ],
    targets: [
        .executableTarget(
            name: "Planner",
            dependencies: [
                .product(name: "Algorithms", package: "swift-algorithms"),
            ]
        ),
    ]
)
```

In an Xcode app, use **File ▸ Add Package Dependencies…** with the same URL and add **Algorithms** to your target. Then write `import Algorithms` at the top of a file. At the time of writing the latest release is 1.2.1, and `from: "1.2.0"` accepts it and any later 1.x.

As before, the lessons' `run` blocks are single files that can't import packages. Code that uses the package is shown without `run`, with what it produces in comments; where the behaviour is worth seeing, a `run` block builds the same result from the standard library.

## Combinatorics: choosing and arranging

Four methods enumerate choices, which is what brute force and many backtracking problems need:

```swift
import Algorithms

let toppings = ["ham", "olive", "pepper", "onion"]

toppings.combinations(ofCount: 2)        // [ham, olive], [ham, pepper], [ham, onion],
                                         // [olive, pepper], [olive, onion], [pepper, onion]
toppings.combinations(ofCount: 2).count  // 6, computed as "4 choose 2" without generating any
toppings.combinations(ofCount: 1...2)    // all singles, then all pairs

[10, 20, 30].permutations()              // [10, 20, 30], [10, 30, 20], [20, 10, 30],
                                         // [20, 30, 10], [30, 10, 20], [30, 20, 10]
[10, 20, 30].permutations(ofCount: 2)    // [10, 20], [10, 30], [20, 10], [20, 30], [30, 10], [30, 20]

[20, 10, 10].permutations()              // 6 arrangements, with every one repeated twice
[20, 10, 10].uniquePermutations()        // [20, 10, 10], [10, 20, 10], [10, 10, 20]

product(["S", "M"], ["red", "blue"])     // (S, red), (S, blue), (M, red), (M, blue)
```

What to notice:

- **Each combination or permutation is an `[Element]`**, and they're produced **one at a time** as you iterate. Looping over all 184,756 ways to choose 10 of 20 items never holds more than one of them in memory. Calling `Array(...)` on the result would.
- **The order follows positions, not values.** Combinations and permutations come out in lexicographic order of the original **indexes**. `[3, 1, 2].permutations()` starts with `[3, 1, 2]`, not `[1, 2, 3]`. Sort the input first if you want the output in value order.
- **Equal values are still different positions.** `permutations()` on `[20, 10, 10]` gives each arrangement twice. `uniquePermutations()` skips the repeats; it needs `Hashable` elements to spot them.
- **`product(_:_:)` is a free function**, not a method: every pairing as a tuple, with the first sequence on the outside, like two nested `for` loops.
- **`combinations(ofCount:)` with a count larger than the collection** produces nothing, rather than crashing.

The cost is in the size of the answer. There are C(n, k) combinations and n! permutations, and each one takes O(k) or O(n) work to produce. Creating the sequence is O(1); `uniquePermutations()` spends O(n) first to group equal elements.

Here is a stand-in for `combinations(ofCount:)` with the same order. It's the choose-explore-unchoose recursion you'll study properly in [The decision tree and the backtracking template](/dsa/learn/bk-template):

```swift run
// A stand-in for swift-algorithms' combinations(ofCount:), in the same order
func combinations<T>(of items: [T], count: Int) -> [[T]] {
    var result: [[T]] = []
    var chosen: [T] = []
    func choose(from start: Int) {
        if chosen.count == count {
            result.append(chosen)
            return
        }
        guard start < items.count else { return }
        for index in start..<items.count {
            chosen.append(items[index])
            choose(from: index + 1)
            chosen.removeLast()
        }
    }
    choose(from: 0)
    return result
}

let toppings = ["ham", "olive", "pepper", "onion"]
for pair in combinations(of: toppings, count: 2) {
    print(pair)
}
print(combinations(of: toppings, count: 3).count)
print(combinations(of: toppings, count: 5).count)
print(combinations(of: [3, 1, 2], count: 2))
```

```output
["ham", "olive"]
["ham", "pepper"]
["ham", "onion"]
["olive", "pepper"]
["olive", "onion"]
["pepper", "onion"]
4
0
[[3, 1], [3, 2], [1, 2]]
```

The last line shows the "positions, not values" rule: 3 comes first because it's at index 0. Unlike the package, this stand-in builds every answer in an array, so it uses memory for all of them.

## Sliding views: windows, chunks and pairs

Four methods look at a collection a few elements at a time:

```swift
import Algorithms

let steps = [4, 7, 5, 9, 12, 11]

steps.windows(ofCount: 3)        // [4, 7, 5], [7, 5, 9], [5, 9, 12], [9, 12, 11]  (overlapping)
steps.windows(ofCount: 9)        // empty: no window that long
steps.chunks(ofCount: 4)         // [4, 7, 5, 9], [12, 11]  (the last chunk is shorter)
steps.adjacentPairs()            // (4, 7), (7, 5), (5, 9), (9, 12), (12, 11)
steps.striding(by: 2)            // 4, 5, 12: every second element, from the first
"swift".windows(ofCount: 2)      // "sw", "wi", "if", "ft"
```

- **Windows and chunks are slices** of the original collection, not new arrays, so making each one is O(1). Remember that slices keep the parent's indexes.
- **They work on any collection**, including `String`, whose windows are `Substring`s.
- **`adjacentPairs()` gives tuples**, which makes "differences between neighbours" or "is it sorted?" a one-liner: `steps.adjacentPairs().allSatisfy { $0 <= $1 }`.
- **Creating the view is O(1)** on random-access collections; `windows(ofCount: k)` on a collection that can only walk forward spends O(k) finding the first window. Walking all of them is O(n).

On an array, the standard library gets you the same results with a little index arithmetic:

```swift run
let steps = [4, 7, 5, 9, 12, 11]

// windows(ofCount: 3): every run of 3 neighbours, as slices
let windows = steps.indices.dropLast(2).map { steps[$0..<($0 + 3)] }
print(windows.map { $0.reduce(0, +) })

// chunks(ofCount: 4): consecutive groups of 4, the last one shorter
let chunks = stride(from: 0, to: steps.count, by: 4).map { steps[$0..<min($0 + 4, steps.count)] }
print(chunks.map(Array.init))

// adjacentPairs(): each element with the next one
let rises = zip(steps, steps.dropFirst()).map { $1 - $0 }
print(rises)

// striding(by: 2): every second element, starting with the first
print(stride(from: 0, to: steps.count, by: 2).map { steps[$0] })
```

```output
[16, 21, 26, 32]
[[4, 7, 5, 9], [12, 11]]
[3, -2, 4, 3, -1]
[4, 5, 12]
```

`zip(steps, steps.dropFirst())` is worth memorising: it's `adjacentPairs()` in the standard library, it works on any sequence, and it allocates nothing. Notice, though, that summing every window costs O(n · k). For window sums on large inputs, the running-sum technique from M22's sliding window lessons is O(n). The package makes code shorter; it doesn't change the algorithm you need.

The stand-ins above lean on `Int` indexes starting at 0. Writing versions that work on **any** collection, `String` and slices included, is this lesson's practice problem.

## Uniqueness and extremes

```swift
import Algorithms

let visits = ["home", "search", "home", "cart", "search", "pay"]
Array(visits.uniqued())                  // ["home", "search", "cart", "pay"]: the first of each
visits.uniqued(on: \.count)              // ["home", "search", "pay"]: the first of each length

[7, 1, 6, 2, 8, 3, 9].minAndMax()        // (min: 1, max: 9), or nil when empty
[7, 1, 6, 2, 8, 3, 9].min(count: 3)      // [1, 2, 3], sorted
[7, 1, 6, 2, 8, 3, 9].max(count: 2)      // [8, 9]

var numbers = [10, 20, 30, 40, 50, 60, 70, 80]
let split = numbers.stablePartition { $0.isMultiple(of: 20) }
// numbers is [10, 30, 50, 70, 20, 40, 60, 80] and split is 4
let parts = [10, 25, 30, 45].partitioned { $0 > 28 }
// parts.falseElements is [10, 25], parts.trueElements is [30, 45]
```

- **`uniqued()`** keeps the **first** occurrence of each value, in the original order, using a `Set` behind the scenes: O(n) on average, and it needs `Hashable` elements. It returns a lazy sequence, so wrap it in `Array(...)` when you want an array. **`uniqued(on:)`** deduplicates by a key you choose and returns an array.
- **`minAndMax()`** finds both in one pass and returns an optional tuple. It's still O(n); it saves comparisons by looking at elements two at a time.
- **`min(count:)` and `max(count:)`** return the k smallest or largest in sorted order. For small k they're close to O(n); for k above about a tenth of n they fall back to sorting, O(n log n). A heap of size k ([Top K, kth largest and K closest](/dsa/learn/heap-top-k)) is the hand-written equivalent.
- **`stablePartition(by:)`** is `partition(by:)` that keeps the order on both sides. It works in place in O(n log n). **`partitioned(by:)`** returns two new arrays in O(n) instead. **`partitioningIndex(where:)`** finds the split in an already partitioned collection, in O(log n), as you saw in M28.

The standard library versions of the first two are short enough to write in an interview:

```swift run
// uniqued(): keep the first of each value, in order
var seen = Set<String>()
let visits = ["home", "search", "home", "cart", "search", "pay"]
let firstVisits = visits.filter { seen.insert($0).inserted }
print(firstVisits)

// uniqued(on:): keep the first element for each key
var seenLengths = Set<Int>()
print(visits.filter { seenLengths.insert($0.count).inserted })

// minAndMax(): both extremes in one pass
func minAndMax(_ values: [Int]) -> (min: Int, max: Int)? {
    guard var low = values.first else { return nil }
    var high = low
    for value in values.dropFirst() {
        low = min(low, value)
        high = max(high, value)
    }
    return (low, high)
}
if let range = minAndMax([7, 1, 6, 2, 8, 3, 9]) {
    print(range.min, range.max)
}
print(minAndMax([]) == nil)
```

```output
["home", "search", "cart", "pay"]
["home", "search", "pay"]
1 9
true
```

`Set.insert` returns a tuple whose `inserted` is `false` when the value was already there, so `filter` keeps exactly the first sightings.

## Small utilities: cycled and indexed

```swift
import Algorithms

let colours = ["red", "green", "blue"]
colours.cycled().prefix(7)           // red, green, blue, red, green, blue, red
colours.cycled(times: 2)             // the three colours twice: a finite collection

let scores = [55, 72, 91, 64, 88]
for (index, score) in scores[2...].indexed() {
    print(index, score)              // 2 91, then 3 64, then 4 88: the slice's real indexes
}
```

- **`cycled()` is infinite.** Always limit it with `prefix`, `zip` or a `break`. Zipping a finite sequence with a cycled one is a neat way to deal cards round-robin or assign colours to rows.
- **`indexed()`** pairs each element with its **real index**, labelled `index` and `element`. `enumerated()` counts from 0 whatever the indexes are, which is wrong for slices and for collections whose indexes aren't `Int`s, such as `String`.

Both are easy to reproduce without the package:

```swift run
let colours = ["red", "green", "blue"]

// cycled(): repeat forever; here, as many as you take
let stripes = (0..<7).map { colours[$0 % colours.count] }
print(stripes)

// indexed(): real indexes, even on a slice
let scores = [55, 72, 91, 64, 88]
let lastThree = scores[2...]
for (offset, score) in lastThree.enumerated() {
    print("enumerated", offset, score)
}
for (index, score) in zip(lastThree.indices, lastThree) {
    print("indexed", index, score)
}
```

```output
["red", "green", "blue", "red", "green", "blue", "red"]
enumerated 0 91
enumerated 1 64
enumerated 2 88
indexed 2 91
indexed 3 64
indexed 4 88
```

Using an `enumerated()` offset to subscript the slice would read the wrong elements, or crash: `lastThree[0]` is out of bounds. `zip(c.indices, c)` is the standard library's `indexed()`.

## The cheat table

| Method | Gives | Cost |
| --- | --- | --- |
| `combinations(ofCount: k)` | each k-element choice, as an array, in index order | O(1) to make, O(k) per answer |
| `permutations(ofCount:)` | each arrangement, in index order | O(1) to make, O(n) per answer |
| `uniquePermutations()` | arrangements without repeats (`Hashable`) | O(n) to make, O(n) per answer |
| `product(a, b)` | every pair, a on the outside | O(1) to make |
| `windows(ofCount: k)` | overlapping slices of length k | O(1) each on arrays |
| `chunks(ofCount: k)` | consecutive slices, the last may be shorter | O(n) in total |
| `adjacentPairs()` | `(element, next)` tuples | O(1) each |
| `striding(by: k)` | every k-th element from the first | O(1) each on arrays |
| `uniqued()`, `uniqued(on:)` | first occurrences, in order (`Hashable`) | O(n) |
| `minAndMax()` | both extremes, or `nil` | O(n) |
| `min(count:)`, `max(count:)` | the k smallest or largest, sorted | about O(n) for small k |
| `stablePartition(by:)` | partition that keeps order; returns the split | O(n log n), in place |
| `partitioned(by:)` | two arrays: false elements, true elements | O(n) |
| `partitioningIndex(where:)` | the first index where the predicate is true | O(log n) on arrays |
| `cycled()`, `cycled(times:)` | repeat forever, or n times | O(1) to make |
| `indexed()` | `(index, element)` with real indexes | O(1) each |

<Callout kind="gotcha" title="Gotchas with swift-algorithms">
- **Lazy results don't print nicely.** Most methods return a lightweight view type. Wrap it in `Array(...)` to print it or to keep the results, and remember that a lazy chain recomputes each time you iterate it.
- **Name clashes.** If you write your own `windows(ofCount:)` extension in a project that also imports Algorithms, calls become ambiguous. That's why DSAKit calls its binary search `partitionPoint(where:)`, not `partitioningIndex(where:)`.
- **The package doesn't change the complexity of the problem.** Enumerating all combinations is still exponential, and summing every window is still O(n · k). Use these to write the obvious algorithm faster, then still ask whether there's a better one.
</Callout>
