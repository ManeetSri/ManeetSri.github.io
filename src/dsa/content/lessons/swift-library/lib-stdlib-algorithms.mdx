## Why it matters

Swift's standard library already contains dozens of small, well-tested algorithms: searches, partitions, groupings, slices from either end. In app code they make a view model's filtering and grouping read like a sentence. In DSA they save you from rewriting a loop you've written fifty times, and from the off-by-one bugs that come with it. You met most of them one by one in Part I. This lesson gathers them in one place, adds the few you haven't used yet, and puts a **cost** next to each one, because a one-line call can still hide an O(n) scan inside a loop.

Throughout, **n** is the number of elements in the collection, and **k** is a count you pass in.

## Searching and checking

These all walk the collection from the front and stop as soon as they know the answer. You met most of them in [sorted(by:), min, max, contains and first(where:)](/dsa/learn/swift-sorting-searching-api).

```swift run
let temperatures = [18, 21, 25, 19, 30, 27, 16]

print(temperatures.contains { $0 > 28 })
print(temperatures.allSatisfy { $0 > 10 })
print([Int]().allSatisfy { $0 > 100 })
print(temperatures.first { $0 > 24 } ?? -1)
print(temperatures.firstIndex { $0 > 24 } ?? -1)
print(temperatures.lastIndex { $0 > 24 } ?? -1)
print(temperatures.firstIndex(of: 19) ?? -1)

struct City {
    let name: String
    let population: Int
}

let cities = [
    City(name: "Leeds", population: 812_000),
    City(name: "York", population: 202_000),
    City(name: "Bristol", population: 472_000),
]
print(cities.min { $0.population < $1.population }!.name)
print(cities.max { $0.population < $1.population }!.name)
print(cities.max { $0.population > $1.population }!.name)
```

```output
true
true
true
25
2
5
3
York
Leeds
York
```

What to notice:

- **`allSatisfy` on an empty collection is `true`.** No element breaks the rule, so the rule holds. That's the same logic as "every unicorn in this room is purple". It's also the opposite of `contains(where:)`, which is `false` when empty. The two are linked: `allSatisfy(p)` is the same as `!contains { !p($0) }`.
- **`lastIndex(where:)` searches from the back**, so it needs a `BidirectionalCollection`, which `Array` and `String` are.
- **`min(by:)` and `max(by:)` both take "are these in increasing order?"** The closure is always a less-than. The last line passes `>` to `max(by:)` and gets the **smallest** city: a classic bug. To get the largest, keep `<` and call `max`.
- Every one of these is O(n) in the worst case, and they all return optionals (or an empty answer) when nothing matches.

## Reordering in place

These change a `var` collection without making a new one.

```swift run
var scores = [42, 7, 88, 15, 63, 91, 30]
let pivot = scores.partition { $0 >= 50 }
print(pivot)
print(scores)
print(scores[..<pivot].sorted(), scores[pivot...].sorted())

var steps = ["write", "test", "ship", "plan"]
steps.swapAt(0, 3)
print(steps)

var readings = [3, -1, 4, -1, 5, -9, 2]
readings.removeAll { $0 < 0 }
print(readings)
readings.reverse()
print(readings)
```

```output
4
[42, 7, 30, 15, 63, 91, 88]
[7, 15, 30, 42] [63, 88, 91]
["plan", "test", "ship", "write"]
[3, 4, 5, 2]
[2, 5, 4, 3]
```

- **`partition(by:)`** moves every element that matches the predicate to the back and returns the index where they start. Its parameter is named `belongsInSecondPartition`, which is exactly what the closure answers. It's O(n), with one pass from each end like the Hoare partition from quick sort, so it is **not stable**: look where 30 and 88 ended up. Only "which side" is promised, never the order inside a side. If you need the original order kept, that's a **stable partition**, which is this lesson's practice problem.
- **`swapAt(_:_:)`** swaps two positions in O(1). You met it in [inout, swap and swapAt](/dsa/learn/swift-inout-swap).
- **`removeAll(where:)`** removes every match in a single O(n) pass, and the survivors **keep their order**. Calling `remove(at:)` in a loop does the same job in O(n²), because every removal shifts the rest of the array.
- **`reverse()`** reverses in place in O(n). Its sibling `reversed()` (no `-ed` on the mutating one, `-ed` on the copy, as with `sort` and `sorted`) returns a reversed **view** in O(1), as you saw in [enumerated, zip, reversed and lazy](/dsa/learn/swift-enumerated-zip).

## Building and reshaping

These build something new from a collection.

```swift run
let fruit = ["apple", "avocado", "banana", "blueberry", "cherry"]
let byLetter = Dictionary(grouping: fruit) { $0.first! }
for letter in byLetter.keys.sorted() {
    print(letter, byLetter[letter]!)
}

let lengthCounts = fruit.reduce(into: [Int: Int]()) { counts, word in
    counts[word.count, default: 0] += 1
}
print(lengthCounts.keys.sorted().map { "\($0) letters: \(lengthCounts[$0]!)" })

let names = ["Ada", "Ben", "Cy"]
let ages = [36, 29, 41, 50]
for (name, age) in zip(names, ages) {
    print(name, age)
}

print(Array(stride(from: 10, to: 0, by: -3)))
print(Array(stride(from: 0.0, through: 1.0, by: 0.25)))

let row = "id,,name,score"
print(row.split(separator: ","))
print(row.split(separator: ",", omittingEmptySubsequences: false))
print(["a", "b", "c"].joined(separator: "-"))
print(Array([[1, 2], [3], [4, 5]].joined()))

let grid = Array(repeating: Array(repeating: 0, count: 3), count: 2)
print(grid)
```

```output
a ["apple", "avocado"]
b ["banana", "blueberry"]
c ["cherry"]
["5 letters: 1", "6 letters: 2", "7 letters: 1", "9 letters: 1"]
Ada 36
Ben 29
Cy 41
[10, 7, 4, 1]
[0.0, 0.25, 0.5, 0.75, 1.0]
["id", "name", "score"]
["id", "", "name", "score"]
a-b-c
[1, 2, 3, 4, 5]
[[0, 0, 0], [0, 0, 0]]
```

- **`Dictionary(grouping:by:)`** and **`reduce(into:)`** are both one O(n) pass (plus whatever your closure costs). [Counting with default: and grouping(by:)](/dsa/learn/swift-counting-grouping) and [compactMap, flatMap and reduce(into:)](/dsa/learn/swift-compactmap-flatmap) covered them; notice the output prints sorted keys, never the whole dictionary.
- **`zip`** stops at the shorter sequence: 50 has no name, so it's dropped silently.
- **`stride(from:to:by:)`** stops **before** the end, `stride(from:through:by:)` may land **on** it. Both are O(1) to create, like a range. [stride and counting backwards](/dsa/learn/swift-stride) has the details.
- **`split`** drops empty pieces unless you pass `omittingEmptySubsequences: false`. For CSV-like data with empty fields, that flag is the difference between a correct parse and columns that shift. The pieces are `Substring`s, which share the original string's memory.
- **`joined(separator:)`** glues strings; plain **`joined()`** flattens a collection of collections, lazily, so it's wrapped in `Array(...)` to print.
- **`Array(repeating:count:)`** is O(count). A grid built from it is safe, because arrays are values: each row is its own copy.

## Slices from the ends

`prefix`, `suffix` and `drop` take or skip elements at either end and hand you a **slice**: no copying.

```swift run
let laps = [3, 8, 12, 15, 9, 4, 20]
print(laps.prefix(3), laps.suffix(2))
print(laps.dropFirst(5), laps.dropLast(5))
print(laps.prefix { $0 < 14 }, laps.drop { $0 < 14 })
print(laps.prefix(100).count)
let tail = laps.suffix(2)
print(tail.startIndex, tail[5])

var calls = 0
let firstBig = (1...1_000_000).lazy
    .map { number -> Int in
        calls += 1
        return number * number
    }
    .first { $0 > 50 }
print(firstBig ?? -1, calls)
```

```output
[3, 8, 12] [4, 20]
[4, 20] [3, 8]
[3, 8, 12] [15, 9, 4, 20]
7
5 4
64 8
```

- On an `Array` (any `RandomAccessCollection`), `prefix(k)`, `suffix(k)`, `dropFirst(k)` and `dropLast(k)` are **O(1)**: the slice is a view with two indexes. On a collection that can only walk forward they cost up to O(k) or O(n).
- `prefix(while:)` and `drop(while:)` stop at the **first** element that fails the test. Note that 9 and 4 come after 15, so they're not in the prefix even though they're under 14.
- **Asking for too many is fine.** `prefix(100)` on seven elements returns all seven, unlike subscripting `laps[0..<100]`, which crashes.
- **Slices keep their parent's indexes**: `tail` starts at index 5. That's the pitfall from [ArraySlice and its index pitfalls](/dsa/learn/swift-array-slices).
- The last block is **`lazy`** from M06: the squares are computed only until `first(where:)` is satisfied, so 8 calls instead of a million.

## The cheat table

| Call | What it does | Cost |
| --- | --- | --- |
| `sort()`, `sorted()`, `sorted(by:)` | stable sort, in place or as a copy | O(n log n) |
| `min()`, `max()`, `min(by:)`, `max(by:)` | one pass; the closure is a less-than | O(n) |
| `contains(_:)`, `contains(where:)`, `allSatisfy` | stop at the first match or failure | O(n) |
| `first(where:)`, `firstIndex(of:)`, `firstIndex(where:)` | search from the front | O(n) |
| `lastIndex(of:)`, `lastIndex(where:)` | search from the back | O(n) |
| `partition(by:)` | matches to the back, returns where they start; unstable | O(n) |
| `swapAt(_:_:)` | swap two positions | O(1) |
| `removeAll(where:)` | remove every match, keep the order of the rest | O(n) |
| `reverse()` / `reversed()` | in place / a reversed view | O(n) / O(1) |
| `reduce(_:_:)`, `reduce(into:_:)` | fold into one value | O(n) |
| `Dictionary(grouping:by:)` | group into arrays by a key | O(n) |
| `zip(a, b)` | pairs, up to the shorter length | O(1) to make, O(min) to walk |
| `stride(from:to:by:)` | numbers with a step | O(1) to make |
| `split(separator:)` | pieces between separators, as slices | O(n) |
| `joined()`, `joined(separator:)` | flatten or glue | O(total length) |
| `prefix(k)`, `suffix(k)`, `dropFirst(k)`, `dropLast(k)` | slices from the ends | O(1) on arrays |
| `prefix(while:)`, `drop(while:)` | up to the first failure | O(length of the prefix) |
| `lazy` | defer `map` and `filter` until a value is needed | O(1) to make |
| `Array(repeating:count:)` | a filled array | O(count) |

Two warnings about the table. First, the cost is per call: `firstIndex(of:)` inside a loop over the same array is O(n²), the "hidden nested loop" from [When a plain loop is clearer or faster](/dsa/learn/swift-loop-or-hof). Second, `contains(_:)` on a `Set` is O(1) on average; on an `Array` it's a linear scan. If you're checking membership repeatedly, build a `Set` once.

<Callout kind="gotcha" title="Swift gotcha: Array(repeating:) and classes">
`Array(repeating: value, count: n)` stores `value` n times. For a struct that's n independent copies. For a **class** instance, it's n references to **one** object:

```swift run
final class Counter {
    var value = 0
}

let shared = Array(repeating: Counter(), count: 3)
shared[0].value += 1
print(shared.map(\.value))

let separate = (0..<3).map { _ in Counter() }
separate[0].value += 1
print(separate.map(\.value))
```

```output
[1, 1, 1]
[1, 0, 0]
```

`Counter()` runs once, and all three slots point at it. To get separate objects, run the initialiser once per slot, as `map` does. This bites with graph nodes and tree nodes built from a class.
</Callout>

## Practice

**Stable partition** asks you to write the version of `partition(by:)` that keeps the original order on both sides, which `partition(by:)` itself doesn't promise. It's a small function you'll find yourself wanting again, and it's in swift-algorithms too, as the next lesson shows.

```cards
- id: stdlib-allsatisfy-empty
  front: "What does `allSatisfy` return for an empty collection, and why?"
  back: "`true`: no element breaks the rule. `contains(where:)` returns `false` for an empty collection."
- id: stdlib-partition
  front: "What does `partition(by:)` do, and what doesn't it promise?"
  back: "Moves the elements that match to the back in O(n) and returns the index where they start. It doesn't keep the original order on either side: it isn't stable."
- id: stdlib-max-by
  front: "Which comparison do you pass to `max(by:)` to get the largest element?"
  back: "A less-than, the same as for `min(by:)`: `max { $0.x < $1.x }`. Passing `>` gives the smallest."
- id: stdlib-prefix-cost
  front: "What do `prefix(k)` and `dropFirst(k)` cost on an Array, and what do they return?"
  back: "O(1): they return an ArraySlice view that keeps the array's indexes. Asking for more elements than exist is safe."
```
