## Why it matters

Most people make the same few mistakes over and over: the empty input, the off-by-one at the end of a window, the pattern chosen from a keyword. Solving more problems doesn't fix them by itself, because each new problem hides the old mistake in a new place. What fixes them is noticing the pattern in your own mistakes and turning each one into a habit. Twenty minutes once a week is enough, and the console already collects nearly everything you need.

## Where your mistakes collect

You've been leaving a trail since M00. Here's where each part of it lives:

| What | Where you write it | Where you review it |
| --- | --- | --- |
| Problem notes | The Notes box on each problem page | Notes page, "Problem notes" |
| Lesson notes | "Your notes" at the end of each lesson | Notes page, "Lesson notes" |
| Confusing lessons | The flag button at the top of a lesson | Notes page, "Flagged as confusing" |
| Lessons to revisit | The bookmark button beside it | Notes page, "Bookmarked" |
| Forgotten ideas | Missed quiz questions and lapsed cards | Review page, with "forgotten N×" on repeats |
| Shaky problems | Attempts logged as "Didn't finish" or "Solved with help", or rated Again or Hard | Notes page, "Mistakes log" (and the Practice page's Status filter) |
| Mock notes | "What to practise next" in the rubric | Shown under "Past mocks" on the Mock page; copy it into the problem's notes to keep it with the problem |

The Notes page gathers most of this in one place. At the top, its **Mistakes log** is built for you from what you've already recorded: problems that aren't solid yet, mocks that scored under 2.5 or weren't finished (with their weakest rubric criterion), and lessons where you missed quiz questions the first time. Mock notes appear under "Past mocks" on the Mock page; to keep one with its problem, follow the link and copy it into the problem's Notes box.

## Tagging mistakes

The Mistakes log tells you *where* things went wrong. To see *why*, and spot patterns, mistakes need labels. Start each mistake in a problem's notes with a tag in square brackets, from a short fixed list:

| Tag | The mistake |
| --- | --- |
| `[understand]` | Misread the problem or what to return |
| `[edge]` | Missed an edge case |
| `[off-by-one]` | A bound, an index or a loop ran one too far or short |
| `[pattern]` | Chose the wrong technique, or missed its precondition |
| `[swift]` | A Swift trap: indexing, overflow, `removeFirst()`, optionals |
| `[complexity]` | Too slow, or stated the cost wrongly |
| `[time]` | Ran out of time, or spent it badly |
| `[communication]` | Went silent, or didn't explain |

For example: "`[edge]` crashed on an empty array: `1..<n` with n = 0." One line per mistake, with the specific detail, is enough.

Then keep the summary in one place: **this lesson's "Your notes" box is your weekly summary.** Each week, add a line with the date, your top tag and the habit you're working on. It shows on the Notes page under "Lesson notes", most recently updated first, so it's always near the top.

With tags, counting is mechanical. Here's the weekly tally as code, on five notes:

```swift run
let notes = [
    "[edge] empty array crashed the 1..<n loop",
    "[off-by-one] window shrank one step too far; [swift] used removeFirst in BFS",
    "[edge] forgot a tree with a single node",
    "[pattern] tried a sliding window with negative numbers",
    "[edge] counted duplicates twice",
]

// Count every [tag] in every note
var counts: [String: Int] = [:]
for note in notes {
    var rest = Substring(note)
    while let open = rest.firstIndex(of: "["), let close = rest[open...].firstIndex(of: "]") {
        let tag = String(rest[rest.index(after: open)..<close])
        counts[tag, default: 0] += 1
        rest = rest[rest.index(after: close)...]
    }
}

// Most frequent first; ties alphabetical, so the order is always the same
let ranked = counts.sorted { $0.value != $1.value ? $0.value > $1.value : $0.key < $1.key }
for (tag, count) in ranked {
    print(tag, count)
}
```

```output
edge 3
off-by-one 1
pattern 1
swift 1
```

This week's answer is obvious: edge cases. You'll do the tally by eye, but the idea is the same: the biggest count is next week's focus.

## The weekly routine

Pick a fixed slot, the same day each week, and go through these steps:

| Minutes | Step | Where |
| --- | --- | --- |
| 0–4 | Read the problem notes you wrote this week; tag any untagged mistakes | Notes page |
| 4–7 | Tally the tags, choose the top one, and add a dated line to your weekly summary | This lesson's notes |
| 7–10 | Open one flagged lesson, reread the confusing section, retry its quiz; unflag it once it's clear | Notes page, then the lesson |
| 10–15 | Clear the cards that are due; note any marked "forgotten 2×" or more | Review page |
| 15–20 | Choose two problems to re-solve this week: due ones, or "Solved with help" | Practice page, Status filter |

Finish by writing the top mistake as **one habit you'll say out loud** in your next mock, such as "Before I say done, I run the edge-case checklist." Then, when you score that mock, check whether you did it.

## From mistake to habit

Each tag has a habit that fixes it, and most of them are lessons you've already done:

| Tag | The habit |
| --- | --- |
| `[understand]` | Restate the problem and write one example before any code ([Clarifying questions](/dsa/learn/int-clarifying)) |
| `[edge]` | Walk the [edge-case checklist](/dsa/learn/algo-edge-cases) out loud during testing |
| `[off-by-one]` | Trace the first and last pass of every loop ([Dry runs and trace tables](/dsa/learn/algo-dry-runs)) |
| `[pattern]` | Name the repeated work, then check the pattern's preconditions ([From brute force to optimal](/dsa/learn/int-optimising)) |
| `[swift]` | Reread [Swift interview gotchas](/dsa/learn/int-swift-gotchas) before mocks |
| `[complexity]` | State the cost of every loop and structure as you write it |
| `[time]` | Use the 15- and 35-minute checkpoints ([The 45-minute structure](/dsa/learn/int-structure)) |
| `[communication]` | Record a mock and listen to two minutes of it ([Thinking out loud](/dsa/learn/int-thinking-aloud)) |

Work on one habit at a time. When a tag hasn't appeared for two or three weeks, move to the next one.

<Callout kind="tip" title="Forgotten cards are mistakes too">
A card marked "forgotten 2×" or more on the Review page is a fact that won't stick. Rather than rating it Again for the third time, open its lesson, reread that section, and write the idea in your own words in the lesson's notes. Rewording is often what makes it stick.
</Callout>

<Callout kind="gotcha" title="Review mistakes">
- **Vague notes.** "Messed up" can't be counted or fixed. Write what broke and why.
- **Reviewing everything.** Twenty minutes is for patterns, not for redoing the week. Pick the top mistake.
- **Too many habits at once.** One focus per week actually changes behaviour; five don't.
- **Never unflagging.** Flags you've already resolved hide the ones that still need attention.
</Callout>
