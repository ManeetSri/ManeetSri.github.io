## Why it matters

"Remove the nth node from the end" looks like it needs the list's length first. A second pointer kept a fixed distance ahead does it in one pass, and the same **gap** trick finds the kth-from-last element of anything you can only walk forwards: a stream of log lines, a chain of view controllers, a singly linked list. It's also a tidy workout for the dummy node from [Dummy and sentinel nodes](/dsa/learn/ll-sentinel), because sometimes the node to remove is the head.

## The task

Counting from the end, the last node is number 1, the one before it is number 2, and so on. Remove node `n` and return the head of what's left:

| List | n | Result |
| --- | --- | --- |
| `1 -> 2 -> 3 -> 4 -> 5` | 2 | `1 -> 2 -> 3 -> 5` |
| `1 -> 2 -> 3 -> 4 -> 5` | 1 | `1 -> 2 -> 3 -> 4` |
| `1 -> 2 -> 3 -> 4 -> 5` | 5 | `2 -> 3 -> 4 -> 5` |
| `9` | 1 | empty |

The third row removes the head, and the last row removes the only node. Any solution has to handle both.

## Two passes: count, then walk

The straightforward way: walk the whole list to count its `length`. Counting from the front starting at 0, the nth node from the end is at position `length - n`. To unlink it you need the node **before** it. With a dummy in front of the head, that node always exists, even when the target is the head itself:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func removeTwoPass(_ head: ListNode?, nthFromEnd n: Int) -> ListNode? {
    var length = 0
    var current = head
    while let node = current {
        length += 1
        current = node.next
    }

    let dummy = ListNode(0, next: head)
    var before = dummy
    for _ in 0..<(length - n) {        // the dummy is one step before position 0
        before = before.next!
    }
    before.next = before.next?.next
    return dummy.next
}

print(describe(removeTwoPass(makeList([1, 2, 3, 4, 5]), nthFromEnd: 2)))
print(describe(removeTwoPass(makeList([1, 2, 3, 4, 5]), nthFromEnd: 5)))
print(describe(removeTwoPass(makeList([9]), nthFromEnd: 1)))
```

```output
1 -> 2 -> 3 -> 5 -> nil
2 -> 3 -> 4 -> 5 -> nil
nil
```

Starting at the dummy, `length - n` steps land on the node just before position `length - n`. That's O(n) time and O(1) space: perfectly good. The one-pass version below is the classic follow-up.

## One pass with a gap

Use two pointers, `lead` and `trail`, both starting at the dummy:

1. Move `lead` forward `n` steps on its own. Now `lead` is exactly `n` nodes **ahead** of `trail`.
2. Move both together, one step at a time, until `lead` is on the last node (`lead.next == nil`).
3. The gap is still `n`, so `trail` is `n` nodes before the last node. That makes `trail.next` the nth node from the end. Skip it.

Here's the state for `1 -> 2 -> 3 -> 4 -> 5` with `n = 2` (D is the dummy):

| Moment | `trail` | `lead` |
| --- | --- | --- |
| start | D | D |
| after the head start of 2 | D | 2 |
| move together | 1 | 3 |
| move together | 2 | 4 |
| move together | 3 | 5 (the last node: stop) |

`trail` is on 3, so `trail.next`, the 4, is removed. The 4 is indeed second from the end.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func removeOnePass(_ head: ListNode?, nthFromEnd n: Int) -> ListNode? {
    let dummy = ListNode(0, next: head)
    var lead = dummy
    for _ in 0..<n {
        guard let next = lead.next else {
            return head                 // fewer than n nodes: nothing to remove
        }
        lead = next
    }
    var trail = dummy
    while let next = lead.next {
        lead = next
        trail = trail.next!
    }
    trail.next = trail.next?.next       // skip the nth node from the end
    return dummy.next
}

print(describe(removeOnePass(makeList([1, 2, 3, 4, 5]), nthFromEnd: 2)))
print(describe(removeOnePass(makeList([1, 2, 3, 4, 5]), nthFromEnd: 1)))
print(describe(removeOnePass(makeList([1, 2, 3, 4, 5]), nthFromEnd: 5)))
print(describe(removeOnePass(makeList([9]), nthFromEnd: 1)))
print(describe(removeOnePass(makeList([1, 2]), nthFromEnd: 3)))
```

```output
1 -> 2 -> 3 -> 5 -> nil
1 -> 2 -> 3 -> 4 -> nil
2 -> 3 -> 4 -> 5 -> nil
nil
1 -> 2 -> nil
```

What to notice:

- Starting both pointers at the **dummy** is what makes `n = length` work. `lead` uses up its whole head start reaching the last node, `trail` never moves off the dummy, and `dummy.next`, the head, is skipped.
- `trail.next!` is safe: `trail` is always behind `lead`, which hasn't run out of nodes.
- If `n` is larger than the list, `lead` runs out during its head start. This version returns the list unchanged; a precondition would also be reasonable, as long as the choice is documented.

Is one pass really better than two? Both are O(n) time and O(1) space; the one-pass version visits each node about once with each pointer, so the total work is similar. Its real advantage shows when the data arrives as a stream and you can't go back for a second pass.

<Callout kind="analogy" title="A measuring stick">
Hold a stick n nodes long against the list, with its back end on the dummy. Slide it along until its front end touches the last node. Its back end is now just before the node you want.
</Callout>

## Finding instead of removing

The same gap finds the kth node from the end without changing anything. Start `lead` and `trail` at the **head** this time, give `lead` a head start of `k` steps, then move both until `lead` falls off the end (`lead == nil`). `trail` is then exactly `k` nodes from the end:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func kthFromEnd(_ head: ListNode?, k: Int) -> Int? {
    var lead = head
    for _ in 0..<k {
        guard let node = lead else { return nil }
        lead = node.next
    }
    var trail = head
    while let node = lead {
        lead = node.next
        trail = trail?.next
    }
    return trail?.value
}

let list = makeList([10, 20, 30, 40, 50])
print(kthFromEnd(list, k: 1) ?? -1)
print(kthFromEnd(list, k: 3) ?? -1)
print(kthFromEnd(list, k: 5) ?? -1)
print(kthFromEnd(list, k: 6) ?? -1)
```

```output
50
30
10
-1
```

Compare the two versions and you'll see the classic off-by-one choice. To **remove** a node you need the one before it, so you start at the dummy and stop when `lead` is on the last node. To **find** a node you need the node itself, so you start at the head and stop when `lead` is `nil`. Both keep a gap of exactly `n`; they differ only in where they start and stop.

## Fast–slow vs gap

You now have two flavours of two pointers on a list:

| Flavour | Pointers move | Finds |
| --- | --- | --- |
| Fast and slow | at speeds 2 and 1 | the middle, a cycle |
| Gap | at the same speed, a fixed distance apart | the kth from the end |

<Callout kind="gotcha" title="Common mistakes">
- **Starting at the head when removing.** Then removing the head (`n` equal to the length) has no node before it. Start at a dummy.
- **Stopping one node late.** For removal, stop when `lead.next` is `nil`, not when `lead` is. Otherwise `trail` lands *on* the target instead of before it.
- **Trusting `n`.** Decide what happens when `n` is 0 or bigger than the list, and make sure the head start can't force-unwrap `nil`.
</Callout>

```cards
  front: "Why do both pointers start at a dummy node when removing the nth from the end?"

  front: "How does finding the kth from the end differ from removing it?"

```
