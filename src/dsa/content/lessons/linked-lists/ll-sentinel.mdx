## Why it matters

In list code, the head is awkward. Every other node has a node in front of it whose `next` you can change; the head doesn't, so removing or replacing it needs its own branch. A **dummy node**, a spare node placed in front of the head, gives the head a node in front of it too. The special case disappears, and with it a whole family of bugs. You'll use this trick in most of the problems in this module.

## The head special case

Here's a task: remove every node holding a given value. Removing a middle node means pointing the node before it past it. But if the head itself matches, there's no node before it, so the head has to move instead, possibly several times:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func removeAll(_ target: Int, from head: ListNode?) -> ListNode? {
    var head = head
    // Special case: matching nodes at the front move the head
    while let first = head, first.value == target {
        head = first.next
    }
    // General case: every remaining node has a node before it
    var previous = head
    while let node = previous?.next {
        if node.value == target {
            previous?.next = node.next
        } else {
            previous = node
        }
    }
    return head
}

print(describe(removeAll(7, from: makeList([7, 7, 1, 7, 2, 7]))))
print(describe(removeAll(7, from: makeList([7, 7]))))
```

```output
1 -> 2 -> nil
nil
```

It works, but there are two loops doing nearly the same job, and the optional chaining (`previous?.next`) exists only because `previous` might be `nil` when the whole list was removed.

## A dummy node in front

Put a dummy node in front of the head. Now **every** real node has a node before it, so one loop handles them all. At the end, the real list starts at `dummy.next`:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func removeAll(_ target: Int, from head: ListNode?) -> ListNode? {
    let dummy = ListNode(0, next: head)
    var previous = dummy
    while let node = previous.next {
        if node.value == target {
            previous.next = node.next      // skip it; previous stays put
        } else {
            previous = node                // keep it; move along
        }
    }
    return dummy.next
}

print(describe(removeAll(7, from: makeList([7, 7, 1, 7, 2, 7]))))
print(describe(removeAll(7, from: makeList([7, 7]))))
print(describe(removeAll(7, from: makeList([]))))
```

```output
1 -> 2 -> nil
nil
nil
```

What to notice:

- `previous` is never `nil`: it starts at the dummy, a real node. No optional chaining.
- When a node is removed, `previous` stays where it is, because its new `next` hasn't been checked yet. That's what makes runs of matches like `7, 7` work.
- The dummy's value, `0`, is never read. Any value would do.
- The function returns `dummy.next`, which is the new head, or `nil` if everything went. The dummy is a local constant, so ARC frees it when the function returns.

<Callout kind="analogy" title="A handle on a chain">
Holding a chain by its first link means you can't easily swap that link out. Clip a spare handle on in front and you can replace any link, including the first, in exactly the same way, then unclip the handle at the end.
</Callout>

## Building a new list with a dummy and a tail

The second classic use: building a list one node at a time. Start with a dummy and a `tail` pointer at it, and always attach to `tail`. There's no "is this the first node?" check, because there's always a node to attach to.

Here's **partition**: rearrange a list so every value below a pivot comes before every other value, keeping the original order within each group. It builds two lists, each with its own dummy, then joins them:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func partition(_ head: ListNode?, around pivot: Int) -> ListNode? {
    let smallDummy = ListNode(0)
    let largeDummy = ListNode(0)
    var smallTail = smallDummy
    var largeTail = largeDummy

    var current = head
    while let node = current {
        current = node.next
        if node.value < pivot {
            smallTail.next = node
            smallTail = node
        } else {
            largeTail.next = node
            largeTail = node
        }
    }
    largeTail.next = nil               // the last node might still point somewhere
    smallTail.next = largeDummy.next   // join the two lists
    return smallDummy.next
}

print(describe(partition(makeList([5, 1, 8, 3, 9, 2]), around: 5)))
print(describe(partition(makeList([9, 8, 7]), around: 5)))
print(describe(partition(makeList([1, 2]), around: 5)))
```

```output
1 -> 3 -> 2 -> 5 -> 8 -> 9 -> nil
9 -> 8 -> 7 -> nil
1 -> 2 -> nil
```

The nodes are reused, not copied: each one is moved onto the end of one of the two chains. The dummies mean neither chain ever needs an "is it empty?" check, even when one stays empty, as in the last two examples.

The line `largeTail.next = nil` matters. In the first example the last large node is `9`, which originally pointed at `2`. Without that line, `9` would still point at `2`, which now sits earlier in the result, and the list would loop forever.

## Sentinels at both ends

A dummy node at the front is often called a **sentinel**: a node that stands guard at the edge of the list so code never falls off it. Doubly linked lists, where each node also points backwards, go further and keep a permanent sentinel at **each** end. Then every real node has a real neighbour on both sides, and inserting or removing never checks for `nil`. You'll build one in [Doubly linked and circular lists](/dsa/learn/ll-doubly-circular), and the LRU cache later in this module is built on one.

<Callout kind="gotcha" title="Common mistakes with dummy nodes">
- **Returning the dummy.** The answer is `dummy.next`. Returning `dummy` adds a stray `0` to the front of the list.
- **Generic lists need a value.** For a `LinkedList<Element>`, the dummy needs *some* `Element` to hold. Borrow an existing value (the head's, say), or give the node an optional value. For `ListNode` holding `Int`, `0` is fine.
- **A dangling last node.** When you move nodes onto a new tail, finish with `tail.next = nil`, or the old link may survive and create a cycle.
</Callout>

## Practice

Three problems lean on dummy nodes. **A linked list from scratch** has `removeAll(equalTo:)`, the first example above as a method. **Remove the kth node from the end** must sometimes remove the head. **Merge two sorted lists** builds its answer with a dummy and a tail.
