## Why it matters

Interviewers love list problems that rearrange nodes without creating new ones, because they test whether you can rewire references confidently. This lesson covers three favourites: **reorder** (interleave the front and the back), **rotate** (move the last k nodes to the front) and **odd-even** (all the odd positions, then all the even ones). Each one is solved by the same strategy: split the list into pieces, change the pieces with tools you already have, and splice them back together. All three run in O(n) time with O(1) extra space.

## Reorder: front, back, front, back

Rearrange `L0, L1, L2, …, Ln` into `L0, Ln, L1, Ln−1, L2, …`: the first node, then the last, then the second, then the second-to-last, and so on.

```text
1 -> 2 -> 3 -> 4 -> 5     becomes    1 -> 5 -> 2 -> 4 -> 3
1 -> 2 -> 3 -> 4          becomes    1 -> 4 -> 2 -> 3
```

The back half is needed in reverse order, and a singly linked list can't walk backwards. So build the solution from three tools:

1. **Split** at the first middle, using fast and slow pointers from [Fast and slow pointers](/dsa/learn/ll-fast-slow).
2. **Reverse** the second half, from [Reverse a list](/dsa/learn/ll-reverse): `4 -> 5` becomes `5 -> 4`.
3. **Weave** the two halves together, one node from each in turn.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func reverse(_ head: ListNode?) -> ListNode? {
    var previous: ListNode? = nil
    var current = head
    while let node = current {
        let next = node.next
        node.next = previous
        previous = node
        current = next
    }
    return previous
}

func reorder(_ head: ListNode?) {
    guard let head else { return }

    // 1. Split after the first middle
    var slow = head
    var fast = head
    while let next = fast.next?.next {
        slow = slow.next!
        fast = next
    }
    var back = reverse(slow.next)     // 2. reverse the back half
    slow.next = nil

    // 3. Weave: front node, back node, front node, ...
    var front: ListNode? = head
    while let f = front, let b = back {
        let frontNext = f.next
        let backNext = b.next
        f.next = b
        b.next = frontNext
        front = frontNext
        back = backNext
    }
}

for values in [[1, 2, 3, 4, 5], [1, 2, 3, 4], [1, 2], [1]] {
    let list = makeList(values)
    reorder(list)
    print(describe(list))
}
```

```output
1 -> 5 -> 2 -> 4 -> 3 -> nil
1 -> 4 -> 2 -> 3 -> nil
1 -> 2 -> nil
1 -> nil
```

What to notice:

- `reorder` returns nothing: the head stays the head, so the caller's reference is still correct. It changes the list **in place**.
- Splitting at the first middle makes the front half the same length as the back half or one longer. Weaving stops when the back half runs out; any extra front node is already last, and `slow.next = nil` made sure it ends the list.
- The weave saves both `next` references before changing anything, the same discipline as reversing.

## Rotate: move the last k nodes to the front

Rotating right by k moves each node k places towards the end, with nodes that fall off the end wrapping round to the front:

```text
1 -> 2 -> 3 -> 4 -> 5, k = 2     becomes    4 -> 5 -> 1 -> 2 -> 3
```

Shifting nodes one at a time, k times, would cost O(n · k). Instead, notice that the result is the same chain of nodes, just starting at a different place. So:

1. Walk to the tail, counting the length `n`.
2. Rotating by `n` changes nothing, so reduce `k` to `k % n`. If that's 0, you're done.
3. Join the tail to the head, making the list a **ring**.
4. The new tail is `n - k - 1` steps from the old head. The new head is the node after it. Cut the ring there.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func rotateRight(_ head: ListNode?, by k: Int) -> ListNode? {
    guard let head else { return nil }

    var tail = head
    var length = 1
    while let next = tail.next {
        tail = next
        length += 1
    }

    let shift = k % length
    if shift == 0 {
        return head
    }

    tail.next = head                     // close the ring
    var newTail = head
    for _ in 0..<(length - shift - 1) {
        newTail = newTail.next!
    }
    let newHead = newTail.next
    newTail.next = nil                   // cut it open again
    return newHead
}

print(describe(rotateRight(makeList([1, 2, 3, 4, 5]), by: 2)))
print(describe(rotateRight(makeList([1, 2, 3, 4, 5]), by: 7)))
print(describe(rotateRight(makeList([1, 2, 3]), by: 3)))
print(describe(rotateRight(makeList([1, 2]), by: 1)))
```

```output
4 -> 5 -> 1 -> 2 -> 3 -> nil
4 -> 5 -> 1 -> 2 -> 3 -> nil
1 -> 2 -> 3 -> nil
2 -> 1 -> nil
```

Rotating 5 nodes by 7 is the same as rotating by 2, which is why `k % length` matters: without it, a huge `k` such as a billion would mean a billion steps. The ring exists only for a moment, between closing it and cutting it, so nothing leaks. Compare this with [Reverse and rotate in place](/dsa/learn/arrays-reverse-rotate), where an array needed three reversals: a list rotates by relinking two references.

## Odd-even: odd positions first

Group the nodes at odd positions (1st, 3rd, 5th, …) before the nodes at even positions, keeping the order within each group. Positions, not values:

```text
1 -> 2 -> 3 -> 4 -> 5      becomes    1 -> 3 -> 5 -> 2 -> 4
10 -> 20 -> 30 -> 40       becomes    10 -> 30 -> 20 -> 40
```

Build two chains as you walk, unzipping the list. `odd` follows the odd positions and `even` the even ones. Remember where the even chain starts, because at the end the odd chain's last node must point at it:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func oddEven(_ head: ListNode?) -> ListNode? {
    guard let head else { return nil }
    var odd = head
    let evenHead = head.next
    var even = evenHead

    while let e = even, let nextOdd = e.next {
        odd.next = nextOdd              // odd skips over the even node
        odd = nextOdd
        e.next = nextOdd.next           // even skips over the next odd node
        even = e.next
    }
    odd.next = evenHead                 // odd chain, then even chain
    return head
}

print(describe(oddEven(makeList([1, 2, 3, 4, 5]))))
print(describe(oddEven(makeList([10, 20, 30, 40]))))
print(describe(oddEven(makeList([7]))))
```

```output
1 -> 3 -> 5 -> 2 -> 4 -> nil
10 -> 30 -> 20 -> 40 -> nil
7 -> nil
```

The loop runs while there's an even node with an odd node after it. When it ends, the even chain already finishes in `nil`: either the last even node's `next` was set to `nil`, or there was no node after it to begin with. Only the odd chain needs its end connected.

## The common pattern

All three problems follow the same shape:

| Problem | Split into | Transform | Splice |
| --- | --- | --- | --- |
| Reorder | front half, back half | reverse the back | weave alternately |
| Rotate | the last k nodes, the rest | nothing | swap their order via a ring |
| Odd-even | odd positions, even positions | nothing | odd chain then even chain |

When a list problem looks complicated, ask what pieces the answer is made of. Usually each piece is a split, a reverse or a merge you've already written, and the hard part is only the bookkeeping where pieces join.

<Callout kind="gotcha" title="Common mistakes">
- **Forgetting to cut.** After splitting, the end of the first piece must point at `nil`, or the pieces are still joined and later steps build a cycle.
- **Rotating without `% length`.** It's slow for large `k`, and `k` equal to the length should change nothing.
- **Losing the even head.** In odd-even, save `head.next` before the loop starts rewiring; afterwards it's too late to find.
- **Positions vs values.** "Odd" means the 1st, 3rd, 5th node, whatever the values are.
</Callout>
