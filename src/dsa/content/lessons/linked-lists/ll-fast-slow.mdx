## Why it matters

Some questions about a list seem to need its length, or a record of every node visited. Where's the middle? Does the list loop back on itself? Two pointers moving at **different speeds** answer both in one pass with O(1) extra space. The pattern is called **fast and slow pointers** (or the tortoise and the hare), and it reappears in palindrome checks, list sorting and even array problems that secretly describe a linked structure.

## Two pointers, two speeds

Start two references at the head. On every step, `slow` moves one node and `fast` moves two. That's the whole technique. What makes it useful is what the gap between them tells you:

- after `k` steps, `slow` has covered `k` nodes and `fast` has covered `2k`;
- so when `fast` reaches the end, `slow` is halfway;
- and if there's no end, because the list loops, `fast` laps `slow` and they meet.

## Finding the middle

Keep stepping while `fast` can still take two steps. When it can't, `slow` is at the middle:

```visual linkedList
program: middle
input:
  values: [3, 8, 1, 9, 4, 7, 6]
```

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func middle(_ head: ListNode?) -> ListNode? {
    var slow = head
    var fast = head
    while let next = fast?.next {     // fast can take a second step
        slow = slow?.next
        fast = next.next
    }
    return slow
}

print(middle(makeList([1, 2, 3, 4, 5]))?.value ?? -1)
print(middle(makeList([1, 2, 3, 4, 5, 6]))?.value ?? -1)
print(middle(makeList([1]))?.value ?? -1)
print(middle(makeList([]))?.value ?? -1)
```

```output
3
4
1
-1
```

With an odd length there's one true middle. With an even length there are two, and this version returns the **second** one: 4 out of `1 2 3 4 5 6`. That's because `fast` stops on `nil` after jumping past the last node.

Sometimes you want the **first** middle instead, for example to split a list into two halves where the first half is never shorter. Stop one step earlier, when `fast` can't take *two more* steps:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func firstMiddle(_ head: ListNode?) -> ListNode? {
    var slow = head
    var fast = head
    while let next = fast?.next?.next {
        slow = slow?.next
        fast = next
    }
    return slow
}

print(firstMiddle(makeList([1, 2, 3, 4, 5]))?.value ?? -1)
print(firstMiddle(makeList([1, 2, 3, 4, 5, 6]))?.value ?? -1)
print(firstMiddle(makeList([1, 2]))?.value ?? -1)
```

```output
3
3
1
```

Both run in O(n) time with two references. The obvious alternative, counting the nodes and then walking half that number again, is also O(n), but takes one and a half passes and doesn't extend to cycles.

## Cycles

A list has a **cycle** when some node's `next` points back to an earlier node. Then there's no `nil` at the end: following `next` goes round and round forever.

```text
1 -> 2 -> 3 -> 4 -> 5 -> 6
          ^              |
          |______________|        (6 points back to 3)
```

A cycle breaks every loop you've written so far: `while let node = current` never stops. In Swift there's a second problem: the nodes in a loop hold strong references to each other, so they form a retain cycle ([Retain cycles](/dsa/learn/swift-retain-cycles)) and are never freed unless you break the loop yourself.

Detecting one sounds like it needs a record of every node seen. Fast and slow pointers do it with two references.

## Floyd's cycle detection

Run the same two pointers. If the list ends, `fast` reaches `nil` and there's no cycle. If there's a cycle, both pointers eventually enter it and go round. Inside the loop, `fast` gains exactly one node on `slow` with every step, so it must eventually land on the same node:

```visual linkedList
program: cycle
input:
  values: [1, 2, 3, 4, 5, 6]
  loopTo: 2
```

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

/// Builds a list whose last node points back at the node at `index`, or ends in nil.
func makeList(_ values: [Int], loopingTo index: Int? = nil) -> ListNode? {
    let nodes = values.map { ListNode($0) }
    for i in nodes.indices.dropLast() {
        nodes[i].next = nodes[i + 1]
    }
    if let index {
        nodes.last?.next = nodes[index]
    }
    return nodes.first
}

func hasCycle(_ head: ListNode?) -> Bool {
    var slow = head
    var fast = head
    while let next = fast?.next {
        slow = slow?.next
        fast = next.next
        if fast != nil && fast === slow {
            return true
        }
    }
    return false
}

let looped = makeList([1, 2, 3, 4, 5, 6], loopingTo: 2)
print(hasCycle(looped))
print(hasCycle(makeList([1, 2, 3, 4, 5, 6])))
print(hasCycle(makeList([7], loopingTo: 0)))
print(hasCycle(nil))

looped?.next?.next?.next?.next?.next?.next = nil   // break the loop so ARC can free it
```

```output
true
false
true
false
```

What to notice:

- The check comes **after** moving. Both pointers start on the head, so checking first would report a cycle immediately.
- `===` asks "same node?". Two different nodes may hold the same value, so comparing values would be wrong, and `ListNode` isn't `Equatable` anyway.
- `fast != nil` stops two `nil`s from counting as a meeting.
- A single node pointing at itself is a cycle too.

### Why fast can't jump over slow

You might worry that `fast`, moving two at a time, could leap straight past `slow` without landing on it. It can't. Once both are inside the cycle, measure the gap as the number of steps `fast` is behind `slow` going round. Each step, `slow` moves 1 and `fast` moves 2, so the gap shrinks by exactly 1. A gap that shrinks by 1 each time must pass through 0, and 0 means they're on the same node.

How long does it take? `slow` enters the cycle within n steps, and from then on the gap, which is less than the cycle's length, closes within one lap of the cycle. So detection is O(n) time and O(1) space.

<Callout kind="analogy" title="Runners on a track">
Two runners on a circular track, one twice as fast as the other, will meet again however the track is shaped. On a straight road that ends, the faster runner just reaches the finish first.
</Callout>

## Where does the cycle start?

Knowing there's a cycle is often not enough. You might need the **entry**: the first node that's part of the loop, the node 3 in the picture. Floyd's method has a remarkable second phase:

1. Find the meeting point with fast and slow pointers.
2. Put one pointer back at the head and leave the other at the meeting point.
3. Move **both one step at a time**. The node where they meet is the entry.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int], loopingTo index: Int? = nil) -> ListNode? {
    let nodes = values.map { ListNode($0) }
    for i in nodes.indices.dropLast() {
        nodes[i].next = nodes[i + 1]
    }
    if let index {
        nodes.last?.next = nodes[index]
    }
    return nodes.first
}

func cycleEntry(_ head: ListNode?) -> ListNode? {
    var slow = head
    var fast = head
    while let next = fast?.next {
        slow = slow?.next
        fast = next.next
        if let meeting = fast, meeting === slow {
            // Phase 2: one pointer from the head, one from the meeting point, both at speed 1
            var outside = head!
            var inside = meeting
            while outside !== inside {
                outside = outside.next!
                inside = inside.next!
            }
            return outside
        }
    }
    return nil
}

print(cycleEntry(makeList([1, 2, 3, 4, 5, 6], loopingTo: 2))?.value ?? -1)
print(cycleEntry(makeList([1, 2, 3, 4, 5, 6], loopingTo: 0))?.value ?? -1)
print(cycleEntry(makeList([1, 2, 3, 4, 5, 6], loopingTo: 5))?.value ?? -1)
print(cycleEntry(makeList([1, 2, 3, 4, 5, 6]))?.value ?? -1)
```

```output
3
1
6
-1
```

The force unwraps in phase 2 are safe: both pointers walk a path that leads into the cycle, so neither can reach `nil`. (These examples leave their cycles in place, which is fine in a short script; in real code, break them.)

### Why the meeting point leads to the entry

It looks like magic, but it's a few lines of counting. Name three distances:

- `a`: the steps from the head to the entry (the nodes before the loop);
- `c`: the number of nodes in the cycle;
- `b`: how many steps past the entry the meeting point is.

When they meet, say `slow` has taken `s` steps. `fast` has taken `2s`. They're on the same node, so the extra `s` steps that `fast` took must have been whole laps of the cycle: **`s` is a multiple of `c`**.

`slow` got to the meeting point by walking `a` steps to the entry, then going round to a node `b` steps past it, perhaps after some whole laps. So `s` is `a + b` plus some whole laps. Since `s` and the whole laps are both multiples of `c`, **`a + b` is a multiple of `c` too**. In other words, starting at the meeting point, which is `b` steps into the cycle, and walking `a` more steps takes you `a + b` steps round: a whole number of laps, which ends exactly at the entry.

So a pointer starting at the meeting point needs `a` steps to reach the entry, and so does a pointer starting at the head. Move them together and they arrive at the entry on the same step. They can't meet sooner, because the head pointer only enters the cycle at step `a`.

Check it with the first example, `1 2 3 4 5 6` looping back to 3:

| Quantity | Value |
| --- | --- |
| `a`, head to entry | 2 (from node 1 to node 3) |
| `c`, cycle length | 4 (nodes 3, 4, 5, 6) |
| meeting point | node 5, after `s = 4` steps (a multiple of 4) |
| `b`, entry to meeting point | 2 (from 3 to 5) |
| from node 5, walk `a = 2` | 6, then 3: the entry |
| from the head, walk `a = 2` | 2, then 3: the entry |

Two more facts fall out cheaply. Once you have the meeting point, walk round from it until you return, counting steps, and you have the **cycle length** `c`. And the number of distinct nodes in the whole list is `a + c`.

## The simpler way, with a set

If O(n) extra space is acceptable, there's a more obvious method: remember every node you visit, and report the first one you see twice. A node's identity can go in a `Set` as an `ObjectIdentifier`, as in [Identity with ===](/dsa/learn/swift-identity):

```swift
func cycleEntryWithSet(_ head: ListNode?) -> ListNode? {
    var seen = Set<ObjectIdentifier>()
    var current = head
    while let node = current {
        if !seen.insert(ObjectIdentifier(node)).inserted {
            return node              // visited before: this is where the loop starts
        }
        current = node.next
    }
    return nil
}
```

It's O(n) time too, and much easier to get right. It's a good first answer in an interview; Floyd's method is the follow-up when they ask for O(1) space.

<Callout kind="gotcha" title="Common mistakes">
- **Checking before moving.** Both pointers start at the head, so `slow === fast` is true before the first step.
- **Comparing values.** Use `===`. A list like `4 -> 4 -> 4` has equal values in different nodes.
- **Unsafe double steps.** `fast.next.next` crashes when `fast.next` is `nil`. Optional chaining, `fast?.next?.next`, or `while let next = fast?.next`, keeps every step safe.
- **Leaking test lists.** A list with a cycle is a retain cycle. Break the loop (`last.next = nil`) when you're done with it.
</Callout>
