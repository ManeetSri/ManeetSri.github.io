## Why it matters

Reversing a linked list is the most famous list problem there is, and not just because interviewers love it. It's a building block: checking for a palindrome, reordering a list, reversing in groups and adding numbers stored in lists all reverse part of a list along the way. It's also the cleanest exercise in the core skill of this module, changing arrows without losing anything.

## Turn every arrow around

Reversing doesn't move any values and doesn't create any nodes. It turns every `next` arrow to point the other way, and makes the old last node the new head:

```text
before:  1 -> 2 -> 3 -> 4 -> nil
after:   nil <- 1 <- 2 <- 3 <- 4      (4 is the new head)
```

The difficulty is that a singly linked node only knows the node **after** it. The moment you point node 2 back at node 1, you've overwritten the only reference to node 3. So before turning an arrow around, you must save where it pointed.

## Three pointers

Walk the list with three references:

- `previous`: the part already reversed (it starts as `nil`, the end of the reversed list);
- `current`: the node being turned around;
- `next`: the rest of the list, saved before `current.next` is overwritten.

For each node, do four things in this order: save `next`, point `current` back at `previous`, then move `previous` and `current` one step along. Step through it here:

```visual linkedList
program: reverse
input:
  values: [1, 2, 3, 4, 5]
```

In Swift:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func reverse(_ head: ListNode?) -> ListNode? {
    var previous: ListNode? = nil
    var current = head
    while let node = current {
        let next = node.next      // save the rest of the list
        node.next = previous      // turn this arrow around
        previous = node           // the reversed part now starts here
        current = next            // carry on with the rest
    }
    return previous               // the old last node
}

print(describe(reverse(makeList([1, 2, 3, 4, 5]))))
print(describe(reverse(makeList([7]))))
print(describe(reverse(makeList([]))))
```

```output
5 -> 4 -> 3 -> 2 -> 1 -> nil
7 -> nil
nil
```

When the loop ends, `current` is `nil` and `previous` holds the last node that was turned around: the new head. The empty list and the one-node list need no special code: the loop runs zero or one times.

Here's the state after each pass for `1 -> 2 -> 3`, the way you learned in [Dry runs and trace tables](/dsa/learn/algo-dry-runs):

| After pass | `previous` (reversed part) | `current` (still to do) |
| --- | --- | --- |
| start | nil | 1 -> 2 -> 3 |
| 1 | 1 -> nil | 2 -> 3 |
| 2 | 2 -> 1 -> nil | 3 |
| 3 | 3 -> 2 -> 1 -> nil | nil |

The **invariant**: `previous` is always the reversed version of the nodes visited so far, and `current` is the untouched rest. Each pass moves one node from the second to the front of the first. It's O(n) time, one pass, and O(1) extra space: three references, however long the list.

## The recursive version

Recursion gives a different way to think about it, using the recipe from [Base case and recursive case](/dsa/learn/rec-what-is-recursion):

- **Base case:** an empty list or a single node is already reversed.
- **Recursive case:** reverse everything after the head. The head's old `next` node is now the **last** node of that reversed part, so hook the head on after it, and make the head point at `nil`.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func reverseRecursively(_ head: ListNode?) -> ListNode? {
    guard let head, let second = head.next else {
        return head                       // empty or one node
    }
    let newHead = reverseRecursively(second)   // 2 -> 3 -> 4 becomes 4 -> 3 -> 2
    second.next = head                    // second is the last node now: 4 -> 3 -> 2 -> 1
    head.next = nil                       // and head ends the list
    return newHead
}

print(describe(reverseRecursively(makeList([1, 2, 3, 4]))))
print(describe(reverseRecursively(makeList([1, 2]))))
```

```output
4 -> 3 -> 2 -> 1 -> nil
2 -> 1 -> nil
```

Follow it for `1 -> 2 -> 3 -> 4`. The call for node 1 asks for `2 -> 3 -> 4` to be reversed and gets back `4 -> 3 -> 2`, where node 2 is now last and still points at `nil`. Node 1 kept its reference to node 2 in `second`, so `second.next = head` puts 1 on the end. `newHead`, node 4, is handed all the way back up unchanged.

The line `head.next = nil` is easy to forget. Without it, node 1 would still point at node 2 while node 2 points at node 1: a two-node cycle at the end of the list.

<Callout kind="warning" title="One stack frame per node">
The recursive version is elegant, but it goes one call deep per node, so its space is O(n) on the call stack, as in [Stack depth limits in Swift](/dsa/learn/rec-stack-limits). In a debug build inside a test, where threads get small stacks, it overflowed for lists of about 3,000 nodes when this lesson was written. Run as a script on the main thread, 50,000 nodes were fine and 100,000 crashed. The loop handles millions. For lists of unknown length, use the loop.
</Callout>

## Reversing part of a list

A common variation reverses only the nodes from position `from` to position `to`, leaving the rest in place. It combines two ideas you already have: a dummy node, in case the part starts at the head, and the three-pointer loop, run for a fixed number of steps.

```text
from 2 to 4:   1 -> 2 -> [3 -> 4 -> 5] -> 6 -> 7
becomes:       1 -> 2 -> [5 -> 4 -> 3] -> 6 -> 7
```

Two nodes need reconnecting afterwards: the node just **before** the part must point at the part's new first node, and the part's old first node, now its last, must point at whatever came after the part.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

/// Reverses positions from...to (counting from 0). Assumes 0 ≤ from ≤ to < the list's length.
func reverse(_ head: ListNode?, from: Int, to: Int) -> ListNode? {
    let dummy = ListNode(0, next: head)
    var before = dummy
    for _ in 0..<from {
        before = before.next!
    }

    let partFirst = before.next!          // will end up last in the part
    var previous: ListNode? = nil
    var current: ListNode? = partFirst
    for _ in from...to {
        let node = current!
        let next = node.next
        node.next = previous
        previous = node
        current = next
    }

    before.next = previous                // the node before the part -> new first
    partFirst.next = current              // new last -> whatever followed the part
    return dummy.next
}

print(describe(reverse(makeList([1, 2, 3, 4, 5, 6, 7]), from: 2, to: 4)))
print(describe(reverse(makeList([1, 2, 3, 4]), from: 0, to: 1)))
print(describe(reverse(makeList([1, 2, 3]), from: 0, to: 2)))
print(describe(reverse(makeList([1, 2, 3]), from: 1, to: 1)))
```

```output
1 -> 2 -> 5 -> 4 -> 3 -> 6 -> 7 -> nil
2 -> 1 -> 3 -> 4 -> nil
3 -> 2 -> 1 -> nil
1 -> 2 -> 3 -> nil
```

When the loop finishes, `previous` is the part's new first node and `current` is the first node after the part (or `nil`). Keep this shape in mind: [Reverse in k-groups](/dsa/learn/ll-reverse-k-group) runs it over and over along the list.

<Callout kind="gotcha" title="Common mistakes">
- **Overwriting before saving.** `node.next = previous` destroys the only reference to the rest of the list. Save `let next = node.next` first.
- **Returning the old head.** After reversing, the old head is the *last* node. Return `previous`, the old last node.
- **Forgetting `head.next = nil` in the recursion.** The old head would still point at its old neighbour, making a cycle.
- **Recursing over long lists.** One frame per node: fine for a few hundred nodes, a crash for a hundred thousand.
</Callout>

## Practice

**Reverse a linked list** asks for both versions. The loop is tested on 100,000 nodes; the recursion only on lists of up to 1,000 nodes, for the reason above. The tests also check that you reused the original nodes rather than building new ones.

```cards
- id: ll-reverse-pointers
  front: "What are the three pointers in an iterative list reversal, and what does each mean?"
  back: "`previous` is the reversed part so far (starting at `nil`), `current` is the node being turned around, and `next` saves the rest of the list before `current.next` is overwritten."
- id: ll-reverse-order
  front: "What are the four steps of each pass when reversing a list?"
  back: "Save `next = node.next`, point `node.next` at `previous`, move `previous` to the node, move `current` to `next`. Return `previous` at the end."
- id: ll-reverse-recursive
  front: "How does the recursive reversal attach the head after reversing the rest?"
  back: "The head's old `next` node is now the last node of the reversed rest, so set `second.next = head`, then `head.next = nil` to end the list."
- id: ll-reverse-space
  front: "What extra space do the iterative and recursive reversals use?"
  back: "Iterative: O(1), three references. Recursive: O(n), one stack frame per node, so long lists can overflow the stack."
```
