## Why it matters

A singly linked list can only go forwards, so removing a node means first finding the node *before* it. Give every node a second reference, back to its predecessor, and you get a **doubly linked list**: removal of any node you hold becomes O(1), and you can walk in both directions. That's what powers a browser's back and forward history, undo and redo, and the LRU cache in the next lesson. Join the last node back to the first and you get a **circular list**, the natural shape for anything that takes turns. In Swift, both need care with memory, which is where M11 pays off.

## Two references per node

A doubly linked node has `next` and `previous`. You saw in [weak and unowned references](/dsa/learn/swift-weak-unowned) why `previous` must be **weak**: if both directions were strong, every pair of neighbours would hold each other alive, and no node would ever be freed. The rule is that `next` owns the rest of the list and `previous` only points back.

```swift
final class DNode {
    var value: Int
    var next: DNode?
    weak var previous: DNode?

    init(_ value: Int) {
        self.value = value
    }
}
```

Each node now costs one more reference, and every insert or remove must update links in both directions. In return:

| Operation | Singly linked | Doubly linked |
| --- | --- | --- |
| Remove a node you hold | O(n): find the node before it first | O(1) |
| Insert before a node you hold | O(n) | O(1) |
| Walk backwards | impossible | O(n) |
| Remove the last node (with a tail reference) | O(n) | O(1) |

## Sentinels at both ends

With `nil` at both ends, every insert and remove has to ask "is there a node before me? after me?". Put a permanent **sentinel** node at each end, as previewed in [Dummy and sentinel nodes](/dsa/learn/ll-sentinel), and every real node always has a real neighbour on both sides. The empty list is just the two sentinels pointing at each other:

```text
empty:      [head] <-> [tail]
three:      [head] <-> 1 <-> 2 <-> 3 <-> [tail]
```

Now there's exactly one way to insert (between two nodes) and one way to remove (join a node's two neighbours), with no special cases at all:

```swift run
final class DNode {
    var value: Int
    var next: DNode?
    weak var previous: DNode?

    init(_ value: Int) {
        self.value = value
    }
}

final class DoublyLinkedList {
    private let head = DNode(0)        // sentinel before the first real node
    private let tail = DNode(0)        // sentinel after the last real node

    init() {
        head.next = tail
        tail.previous = head
    }

    /// Links a new node in straight after `node` and returns it. O(1).
    @discardableResult
    func insert(_ value: Int, after node: DNode) -> DNode {
        let fresh = DNode(value)
        let following = node.next!
        fresh.previous = node
        fresh.next = following
        node.next = fresh
        following.previous = fresh
        return fresh
    }

    @discardableResult
    func pushFront(_ value: Int) -> DNode {
        insert(value, after: head)
    }

    @discardableResult
    func pushBack(_ value: Int) -> DNode {
        insert(value, after: tail.previous!)
    }

    /// Unlinks a real node by joining its neighbours. O(1).
    func remove(_ node: DNode) {
        let before = node.previous!
        let after = node.next!
        before.next = after
        after.previous = before
        node.next = nil
        node.previous = nil
    }

    var forwards: [Int] {
        var result: [Int] = []
        var current = head.next!
        while current !== tail {
            result.append(current.value)
            current = current.next!
        }
        return result
    }

    var backwards: [Int] {
        var result: [Int] = []
        var current = tail.previous!
        while current !== head {
            result.append(current.value)
            current = current.previous!
        }
        return result
    }
}

let list = DoublyLinkedList()
list.pushBack(1)
let two = list.pushBack(2)
list.pushBack(3)
list.pushFront(0)
print(list.forwards, list.backwards)

list.remove(two)                      // O(1): no search for the node before it
print(list.forwards)

list.insert(9, after: list.pushFront(-1))
print(list.forwards, list.backwards)
```

```output
[0, 1, 2, 3] [3, 2, 1, 0]
[0, 1, 3]
[-1, 9, 0, 1, 3] [3, 1, 0, 9, -1]
```

What to notice:

- `insert` changes four references and `remove` changes two (then clears the removed node's own). Every link has a partner going the other way, and both must change together. Walking the list backwards after each change is a good test that you got them all.
- `remove(two)` needed nothing but the node itself. That's the operation an LRU cache does on every lookup.
- `pushFront` and `pushBack` return the new node, so callers can keep a handle on it for a later O(1) removal.
- The force unwraps are safe because of the sentinels: a real node always has both neighbours.

The sentinels' values, `0`, are never read. For a generic list you'd need some value of the element type, or a node with an optional value.

## Circular lists

In a **circular** list, the last node's `next` points back to the first instead of `nil`. There's no end, only a current position. It fits anything that takes turns: players around a table, tasks shared out round-robin, a playlist on repeat.

Keeping a reference to the **last** node is the useful trick: its `next` is the first node, so one reference gives you both ends.

The classic demonstration is the **Josephus problem**. People stand in a circle; counting round, every kth person leaves, and the circle closes up. Who's left?

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func josephus(people n: Int, every k: Int) -> (order: [Int], survivor: Int) {
    // Build the circle 1 -> 2 -> ... -> n -> back to 1
    let first = ListNode(1)
    var last = first
    for value in stride(from: 2, through: n, by: 1) {
        last.next = ListNode(value)
        last = last.next!
    }
    last.next = first

    var order: [Int] = []
    var before = last                      // the node just before the next person counted
    while before.next !== before {         // more than one person left
        for _ in 0..<(k - 1) {
            before = before.next!
        }
        let leaving = before.next!
        order.append(leaving.value)
        before.next = leaving.next         // close the circle over the gap
    }
    let survivor = before.value
    before.next = nil                      // break the final loop so ARC can free the node
    return (order, survivor)
}

let result = josephus(people: 7, every: 3)
print(result.order, result.survivor)
print(josephus(people: 5, every: 2).survivor)
print(josephus(people: 1, every: 4).survivor)
```

```output
[3, 6, 2, 7, 5, 1] 4
3
1
```

What to notice:

- The loop never tests for `nil`, because there isn't one. It stops when the last person's `next` is themselves: a one-node circle points at itself.
- `before` trails one node behind, because removing from a singly linked list needs the node before.
- `before.next = nil` at the end matters in Swift. A circular list is a ring of strong references, which is a retain cycle: even the last node, pointing at itself, keeps itself alive. A circle you build, you must break.

<Callout kind="warning" title="Walking a circular list">
The usual `while let node = current` walk never ends on a circular list. Remember where you started and stop when you get back there: `repeat { … } while current !== start`. If you're not sure whether a list is circular, Floyd's cycle check from [Fast and slow pointers](/dsa/learn/ll-fast-slow) will tell you.
</Callout>

## Choosing a shape

| Shape | Good at | Watch out for |
| --- | --- | --- |
| Singly linked | stacks, simple queues, most interview problems | removing needs the node before |
| Doubly linked | removing or moving any node in O(1), walking backwards | four links per insert; `previous` must be weak |
| Circular singly | round-robin turns, rotation without copying | no `nil` to stop at; break the ring when done |
| Circular doubly | both ends in O(1) from one reference | all of the above |

Swift's own collections don't use any of these: `Array`, `Dictionary` and `Set` are built on contiguous buffers, and a **ring buffer**, an array used circularly, gives a fast double-ended queue without any nodes. You'll build one in [Ring buffers](/dsa/learn/queue-ring-buffer). Linked shapes earn their place when you need stable references to elements that move or vanish, as in the LRU cache next.

<Callout kind="gotcha" title="Common mistakes">
- **A strong `previous`.** Every pair of neighbours becomes a retain cycle and the list leaks. `next` strong, `previous` weak.
- **Updating only one direction.** After `node.next = fresh`, also set `fresh.previous`, `fresh.next` and the old neighbour's `previous`. Check by walking backwards.
- **Forgetting the removed node's links.** Clear its `next` and `previous` so it can't be used to reach back into the list by mistake.
- **Leaking a circle.** Break a circular list (`last.next = nil`) before letting go of it.
</Callout>
