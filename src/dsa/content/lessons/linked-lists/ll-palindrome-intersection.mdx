## Why it matters

These two classics each combine techniques you already have into something new. Checking whether a list is a **palindrome** in O(1) space uses the middle, a reversal and a careful clean-up. Finding where two lists **intersect** is a question about identity rather than values, with one of the prettiest two-pointer tricks there is. Both teach a habit worth keeping: when a function only *answers a question*, it should leave the data as it found it.

## Is the list a palindrome?

A palindrome reads the same in both directions: `1 -> 2 -> 3 -> 2 -> 1`, or `4 -> 4`. With an array you'd compare the first element with the last, the second with the second-to-last, and so on. A singly linked list can't walk backwards, so the direct approach doesn't work.

### The easy way: copy the values out

Copy the values into an array, then compare it with its reverse:

```swift
func isPalindromeWithArray(_ head: ListNode?) -> Bool {
    var values: [Int] = []
    var current = head
    while let node = current {
        values.append(node.value)
        current = node.next
    }
    return values == values.reversed()
}
```

O(n) time and O(n) extra space. It's correct, simple, and a fine first answer. The follow-up question is always: can you do it in O(1) space?

### In O(1) space: reverse the second half

If the second half of the list were reversed, you could walk it forwards alongside the first half. So:

1. Find the end of the first half with fast and slow pointers (the **first** middle, from [Fast and slow pointers](/dsa/learn/ll-fast-slow)).
2. Reverse everything after it, using the loop from [Reverse a list](/dsa/learn/ll-reverse).
3. Walk the first half and the reversed second half together, comparing values.
4. Reverse the second half again and reattach it, so the list is back as it was.

```text
1 -> 2 -> 3 -> 2 -> 1        first half ends at 3
1 -> 2 -> 3    1 -> 2        second half (2 -> 1) reversed
compare 1/1, 2/2: a palindrome. Then put the second half back.
```

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func reverse(_ head: ListNode?) -> ListNode? {
    var previous: ListNode? = nil
    var current = head
    while let node = current {
        let next = node.next
        node.next = previous
        previous = node
        current = next
    }
    return previous
}

func isPalindrome(_ head: ListNode?) -> Bool {
    guard let head else { return true }

    var firstHalfEnd = head                       // the first middle
    var fast = head
    while let next = fast.next?.next {
        firstHalfEnd = firstHalfEnd.next!
        fast = next
    }

    let secondHalf = reverse(firstHalfEnd.next)
    var left: ListNode? = head
    var right = secondHalf
    var matches = true
    while let r = right, let l = left {
        if l.value != r.value {
            matches = false
            break
        }
        left = l.next
        right = r.next
    }

    firstHalfEnd.next = reverse(secondHalf)       // restore the list
    return matches
}

for values in [[1, 2, 3, 2, 1], [4, 4], [1, 2, 2, 1], [1, 2, 3], [7]] {
    let list = makeList(values)
    print(values, isPalindrome(list), describe(list))
}
```

```output
[1, 2, 3, 2, 1] true 1 -> 2 -> 3 -> 2 -> 1 -> nil
[4, 4] true 4 -> 4 -> nil
[1, 2, 2, 1] true 1 -> 2 -> 2 -> 1 -> nil
[1, 2, 3] false 1 -> 2 -> 3 -> nil
[7] true 7 -> nil
```

What to notice:

- With an odd length, the middle node stays in the first half and is never compared. It doesn't need to be: it matches itself.
- The comparison loop stops when the **second** half runs out. The first half is the same length or one longer, and it still ends in a link to the old second half, so stopping on the shorter one is what keeps it correct.
- The function doesn't `return false` from inside the loop. It records the answer, breaks out, and restores the list first. The printed lists show that every list came back unchanged.

Time is O(n): a half pass to find the middle, and a few more passes over half the list. Extra space is O(1).

<Callout kind="warning" title="Don't leave a question's data rearranged">
`isPalindrome` sounds like it only reads the list. A caller would be very surprised to find half of it reversed afterwards, and if the list were being read elsewhere at the same time, it would see a broken list mid-check. When you must change data to answer a question, put it back. The problem for this lesson tests exactly that.
</Callout>

## Where do two lists meet?

Two singly linked lists can **share** a tail: from some node on, they're the same nodes. Picture a Y on its side:

```text
A:  a1 -> a2 \
              c1 -> c2 -> c3 -> nil
B:  b1 -> b2 -> b3 /
```

The task: return the first shared node (`c1`), or `nil` if the lists never meet. This is a question about **identity**. Two lists can both contain the value 8 in different nodes without intersecting, so values tell you nothing; compare nodes with `===`. Notice also that once two lists meet, they can never separate again: each node has only one `next`.

Shared tails are real: two versions of a persistent list share their common part (you'll see this at the end of the module), and the same pattern appears with tree nodes sharing an ancestor.

### With a set

Remember every node of `A`, then walk `B` until you reach one you've seen. `ObjectIdentifier` turns a node's identity into a hashable value, as in [Identity with ===](/dsa/learn/swift-identity):

```swift
func intersectionWithSet(_ a: ListNode?, _ b: ListNode?) -> ListNode? {
    var seen = Set<ObjectIdentifier>()
    var current = a
    while let node = current {
        seen.insert(ObjectIdentifier(node))
        current = node.next
    }
    current = b
    while let node = current {
        if seen.contains(ObjectIdentifier(node)) {
            return node
        }
        current = node.next
    }
    return nil
}
```

O(m + n) time, O(m) extra space.

### In O(1) space: switch heads

The difficulty is that the lists may have different lengths before they meet, so two pointers walking side by side reach the shared part at different times. You could count both lengths and give the pointer on the longer list a head start of the difference. But there's a slicker way.

Start pointer `p` at `A` and `q` at `B`, and step both one node at a time. When `p` falls off the end of `A`, send it to the head of `B`; when `q` falls off the end of `B`, send it to the head of `A`. They meet at the intersection.

Why? Say `A` has `a` nodes before the shared part, `B` has `b`, and the shared part has `c`. By the time `p` has walked all of `A` and then the start of `B`, it has taken `a + c + b` steps to reach `c1`. `q` has walked all of `B` and the start of `A`: `b + c + a` steps. The same number! (Each also spends one step on `nil` when it switches, which doesn't change the comparison.) Both pointers cover both "private" parts plus the shared part once, so they arrive at `c1` on the same step.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func intersection(_ a: ListNode?, _ b: ListNode?) -> ListNode? {
    var p = a
    var q = b
    while p !== q {
        p = (p == nil) ? b : p?.next
        q = (q == nil) ? a : q?.next
    }
    return p
}

// Build the Y: A = 4 -> 1 -> [8 -> 5 -> 2], B = 6 -> 0 -> 3 -> [8 -> 5 -> 2]
let shared = ListNode(8, next: ListNode(5, next: ListNode(2)))
let a = ListNode(4, next: ListNode(1, next: shared))
let b = ListNode(6, next: ListNode(0, next: ListNode(3, next: shared)))

let meet = intersection(a, b)
print(meet?.value ?? -1, meet === shared)

// Same values, but separate nodes: no intersection
let c = ListNode(8, next: ListNode(5, next: ListNode(2)))
print(intersection(a, c)?.value ?? -1)
print(intersection(a, a)?.value ?? -1)
```

```output
8 true
-1
4
```

And if the lists never meet? Then `p` walks `m + n` nodes in total (all of `A`, then all of `B`) and `q` walks `n + m`. Both reach `nil` on the same step, `p !== q` becomes false because `nil` is identical to `nil`, and the function returns `nil`. No special case needed.

The cost is O(m + n) time, since each pointer walks at most both lists once, and O(1) space.

<Callout kind="analogy" title="Two walkers, one route each">
Two friends start on different streets that join into one road. Each agrees to walk their own street, then the other's street, then the road. Their routes have the same total length, so they reach the start of the shared road at the same moment.
</Callout>

<Callout kind="gotcha" title="Common mistakes">
- **Comparing values.** Intersection is about identical nodes. Use `===`; equal values can sit in different nodes.
- **Switching too early.** Send a pointer to the other head when it *is* `nil`, not when its `next` is `nil`. Otherwise it skips the step where both are `nil`, and two lists that never meet loop forever.
- **Returning early from the palindrome loop.** Break out and restore the list first.
- **Comparing the wrong halves.** Stop when the reversed second half runs out; the first half may be one node longer.
</Callout>
