## Why it matters

An `Int` tops out at about 9.2 quintillion. To add numbers with hundreds of digits, you store the digits yourself, and a linked list of digits is one natural way. "Add two numbers stored as lists" is also one of the most-asked interview questions, because it checks three things at once: building a list with a dummy and a tail, walking two lists of different lengths together, and carrying, the rule you learned at primary school, without dropping the last carry.

## Digits stored backwards

Each node holds one digit, 0 to 9, and the list starts with the **least significant** digit, the units:

```text
342  is stored as  2 -> 4 -> 3
465  is stored as  5 -> 6 -> 4
```

Backwards looks odd, but it's exactly the order you add in. Column addition starts at the units, then the tens, then the hundreds, carrying as it goes. With the units at the head, walking the lists from the front visits the columns in the right order:

```text
    3 4 2        2 -> 4 -> 3
  + 4 6 5      + 5 -> 6 -> 4
  -------      -------------
    8 0 7        7 -> 0 -> 8
```

Column by column: 2 + 5 = 7. Then 4 + 6 = 10, so write 0 and carry 1. Then 3 + 4 + 1 = 8.

## Adding column by column

For each column, add the two digits and the carry from the previous column:

- the new digit is `sum % 10`;
- the carry into the next column is `sum / 10`, which is 0 or 1.

The lists can have different lengths, so a list that has run out counts as 0. And keep going while there's a carry, even after both lists have ended: 99 + 1 needs a new hundreds digit.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func add(_ first: ListNode?, _ second: ListNode?) -> ListNode? {
    let dummy = ListNode(0)
    var tail = dummy
    var a = first
    var b = second
    var carry = 0
    while a != nil || b != nil || carry > 0 {
        let sum = (a?.value ?? 0) + (b?.value ?? 0) + carry
        tail.next = ListNode(sum % 10)
        tail = tail.next!
        carry = sum / 10
        a = a?.next
        b = b?.next
    }
    return dummy.next
}

print(describe(add(makeList([2, 4, 3]), makeList([5, 6, 4]))))       // 342 + 465
print(describe(add(makeList([9, 9]), makeList([1]))))                // 99 + 1
print(describe(add(makeList([9, 9, 9, 9, 9, 9, 9]), makeList([9, 9, 9, 9]))))
print(describe(add(makeList([0]), makeList([0]))))
```

```output
7 -> 0 -> 8 -> nil
0 -> 0 -> 1 -> nil
8 -> 9 -> 9 -> 9 -> 0 -> 0 -> 0 -> 1 -> nil
0 -> nil
```

What to notice:

- `a?.value ?? 0` reads a digit, or 0 when that list has run out. Optional chaining from [Optional chaining](/dsa/learn/swift-optional-chaining) keeps the loop free of special cases, and `a = a?.next` stays `nil` once `a` is `nil`.
- `carry > 0` in the loop condition is what produces the extra digit in 99 + 1 = 100.
- The answer is built from **new** nodes. The inputs are numbers the caller may still need, so this function doesn't change them.

Reading the third line backwards: 9,999,999 + 9,999 = 10,009,998.

With lists of lengths m and n, the loop runs about `max(m, n)` times, plus one for a final carry: O(max(m, n)) time. The result has at most `max(m, n) + 1` nodes.

<Callout kind="tip" title="Checking with small numbers">
To test code like this, convert small `Int`s to digit lists and back: the digits of 342, least significant first, come from repeatedly taking `% 10` and dividing by 10, as in [Digit manipulation](/dsa/learn/math-digits). Then compare `add` with Swift's `+` on lots of pairs. Once it matches, trust it with numbers far too big for an `Int`.
</Callout>

## Numbers far beyond Int

Because each column only ever adds two digits and a carry, nothing overflows, however long the numbers are. Here are two 30-digit numbers, built from strings:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

/// The digits of a decimal string, least significant first.
func digitList(_ text: String) -> ListNode? {
    var head: ListNode? = nil
    for character in text {                     // most significant first...
        head = ListNode(character.wholeNumberValue!, next: head)   // ...so prepending reverses
    }
    return head
}

/// The number as a string, most significant digit first.
func text(of head: ListNode?) -> String {
    var digits: [String] = []
    var current = head
    while let node = current {
        digits.append(String(node.value))
        current = node.next
    }
    return digits.reversed().joined()
}

func add(_ first: ListNode?, _ second: ListNode?) -> ListNode? {
    let dummy = ListNode(0)
    var tail = dummy
    var a = first
    var b = second
    var carry = 0
    while a != nil || b != nil || carry > 0 {
        let sum = (a?.value ?? 0) + (b?.value ?? 0) + carry
        tail.next = ListNode(sum % 10)
        tail = tail.next!
        carry = sum / 10
        a = a?.next
        b = b?.next
    }
    return dummy.next
}

let big = digitList("987654321098765432109876543210")
let other = digitList("123456789012345678901234567890")
print(text(of: add(big, other)))
```

```output
1111111110111111111011111111100
```

Prepending each character as you read the string left to right is a neat trick: the first digit read ends up last, so the list comes out least significant first without a separate reverse. The same column-by-column idea on strings is in [Add and multiply strings](/dsa/learn/str-big-number-arithmetic).

## When the digits come the other way round

A common follow-up stores the **most** significant digit first: 342 as `3 -> 4 -> 2`. Now the units are at the far end, and a singly linked list can't walk backwards. Three ways out:

1. **Reverse both lists, add, reverse the result.** O(m + n) time. Neat, but it changes the inputs unless you reverse them back afterwards.
2. **Push the digits onto two stacks**, then pop them to add from the units upwards, prepending each new digit to the answer. O(m + n) extra space, inputs untouched. You'll build stacks in the next module.
3. **Recurse to the end**, adding on the way back up. One frame per digit, so only for short numbers.

Here's the first, built from pieces you already have:

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func reverse(_ head: ListNode?) -> ListNode? {
    var previous: ListNode? = nil
    var current = head
    while let node = current {
        let next = node.next
        node.next = previous
        previous = node
        current = next
    }
    return previous
}

func add(_ first: ListNode?, _ second: ListNode?) -> ListNode? {
    let dummy = ListNode(0)
    var tail = dummy
    var a = first
    var b = second
    var carry = 0
    while a != nil || b != nil || carry > 0 {
        let sum = (a?.value ?? 0) + (b?.value ?? 0) + carry
        tail.next = ListNode(sum % 10)
        tail = tail.next!
        carry = sum / 10
        a = a?.next
        b = b?.next
    }
    return dummy.next
}

func addForwards(_ first: ListNode?, _ second: ListNode?) -> ListNode? {
    let a = reverse(first)
    let b = reverse(second)
    let sum = reverse(add(a, b))
    _ = reverse(a)                  // put the inputs back the way they were
    _ = reverse(b)
    return sum
}

let x = makeList([7, 2, 4, 3])      // 7243
let y = makeList([5, 6, 4])         // 564
print(describe(addForwards(x, y)))
print(describe(x), describe(y))
```

```output
7 -> 8 -> 0 -> 7 -> nil
7 -> 2 -> 4 -> 3 -> nil 5 -> 6 -> 4 -> nil
```

7243 + 564 = 7807, and both inputs came back unchanged. `a` is the head of the reversed first list, so reversing it again restores the original order, with `x` back at the front. `add` built new nodes, so it never disturbed `a` or `b`.

<Callout kind="gotcha" title="Common mistakes">
- **Dropping the last carry.** Stopping when both lists end gives 99 + 1 = 00. Keep looping while `carry > 0`.
- **Stopping at the shorter list.** Treat a finished list as zeros until both have ended.
- **Changing the inputs.** The numbers belong to the caller. Build new nodes for the answer, or restore anything you reversed.
- **Forgetting it's backwards.** `2 -> 4 -> 3` is 342, not 243. Test with numbers whose digits differ.
</Callout>
