## Why it matters

Reversing a list in groups of k is a well-known "hard" interview problem, but it contains no new idea. It's the partial reversal from [Reverse a list, iteratively and recursively](/dsa/learn/ll-reverse), repeated along the list, with careful bookkeeping where each group joins its neighbours. That makes it the perfect test of whether you can keep several references straight at once. The same group-by-group rewiring shows up when data is processed in fixed-size blocks, such as packets or pages.

## The task

Reverse each run of k consecutive nodes, starting from the front. If fewer than k nodes are left at the end, leave them as they are. Move the nodes themselves; don't just swap values.

```text
k = 3:  1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7 -> 8
        [3 -> 2 -> 1] -> [6 -> 5 -> 4] -> 7 -> 8      (7, 8 are fewer than 3: unchanged)

k = 2:  1 -> 2 -> 3 -> 4 -> 5
        [2 -> 1] -> [4 -> 3] -> 5
```

With k = 1 nothing changes, and with k equal to the length the whole list is reversed.

## Four references per group

Use a dummy node in front of the head, because the first group's reversal changes the head. Then, for each group, keep track of four nodes:

- `groupBefore`: the node just before the group. At first it's the dummy.
- `groupFirst`: the group's first node. After reversal it will be the group's **last**.
- `groupLast`: the group's last node. After reversal it will be the group's **first**.
- `after`: the node just after the group, where the rest of the list continues.

For each group:

1. **Look ahead.** Walk k steps from `groupBefore`. If the list runs out first, fewer than k nodes remain: stop.
2. **Reverse** the k nodes. Start the reversal with `previous = after` instead of `nil`, so the group's new last node (the old `groupFirst`) automatically points at the rest of the list.
3. **Reconnect the front.** `groupBefore.next = groupLast`: the node before the group now leads into the reversed group.
4. **Move on.** The old `groupFirst` is now the last node of this group, so it becomes the next `groupBefore`.

Here's the state at the start of each group for `1 2 3 4 5 6 7 8` and k = 3 (D is the dummy):

| Group | `groupBefore` | the group | `after` | list afterwards |
| --- | --- | --- | --- | --- |
| 1 | D | 1, 2, 3 | 4 | 3 2 1 4 5 6 7 8 |
| 2 | 1 | 4, 5, 6 | 7 | 3 2 1 6 5 4 7 8 |
| 3 | 4 | 7, 8 (only 2) | | unchanged: stop |

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func reverseInGroups(_ head: ListNode?, k: Int) -> ListNode? {
    guard k > 1 else { return head }
    let dummy = ListNode(0, next: head)
    var groupBefore = dummy

    while true {
        // 1. Look ahead: is there a whole group?
        var probe: ListNode? = groupBefore
        for _ in 0..<k {
            probe = probe?.next
        }
        guard let groupLast = probe else { break }

        let groupFirst = groupBefore.next!
        let after = groupLast.next

        // 2. Reverse exactly k nodes, starting the reversed chain at `after`
        var previous = after
        var current: ListNode? = groupFirst
        for _ in 0..<k {
            let node = current!
            let next = node.next
            node.next = previous
            previous = node
            current = next
        }

        // 3. Reconnect the front, 4. move on
        groupBefore.next = groupLast
        groupBefore = groupFirst
    }
    return dummy.next
}

print(describe(reverseInGroups(makeList([1, 2, 3, 4, 5, 6, 7, 8]), k: 3)))
print(describe(reverseInGroups(makeList([1, 2, 3, 4, 5]), k: 2)))
print(describe(reverseInGroups(makeList([1, 2, 3, 4]), k: 4)))
print(describe(reverseInGroups(makeList([1, 2, 3]), k: 4)))
print(describe(reverseInGroups(makeList([1, 2, 3]), k: 1)))
```

```output
3 -> 2 -> 1 -> 6 -> 5 -> 4 -> 7 -> 8 -> nil
2 -> 1 -> 4 -> 3 -> 5 -> nil
4 -> 3 -> 2 -> 1 -> nil
1 -> 2 -> 3 -> nil
1 -> 2 -> 3 -> nil
```

What to notice:

- Looking ahead **before** reversing is what leaves a short final group untouched. Reversing first and then discovering the group was short would mean reversing it back.
- Starting with `previous = after` saves a separate step. The first node turned around, `groupFirst`, is pointed at `after`, so the back end of the group is connected the moment the reversal begins.
- The force unwraps are safe: the look-ahead has just proved that k nodes exist after `groupBefore`.

### Why it's correct

The loop keeps an **invariant**, in the sense of [Loop invariants and correctness](/dsa/learn/algo-invariants): everything from the dummy up to `groupBefore` is finished, and `groupBefore.next` is the first node not yet processed. It's true at the start, when nothing is finished and `groupBefore` is the dummy. Each pass reverses one group, links it in after `groupBefore` and moves `groupBefore` to the group's new end, so it stays true. When the look-ahead fails, every whole group is finished and the short remainder is still attached after `groupBefore`, untouched.

### How fast is it?

Each node is visited twice: once by the look-ahead and once by the reversal. That's O(n) time. Only a handful of references are used, so the extra space is O(1), however large k or the list is.

## The recursive version

Recursion gives a compact alternative: reverse the first group, then let a recursive call handle the rest, and attach its result to the end of the first group.

```swift run
final class ListNode {
    var value: Int
    var next: ListNode?

    init(_ value: Int, next: ListNode? = nil) {
        self.value = value
        self.next = next
    }
}

func makeList(_ values: [Int]) -> ListNode? {
    var head: ListNode? = nil
    for value in values.reversed() {
        head = ListNode(value, next: head)
    }
    return head
}

func describe(_ head: ListNode?) -> String {
    var parts: [String] = []
    var current = head
    while let node = current {
        parts.append(String(node.value))
        current = node.next
    }
    parts.append("nil")
    return parts.joined(separator: " -> ")
}

func reverseInGroupsRecursively(_ head: ListNode?, k: Int) -> ListNode? {
    // Is there a whole group? Find the node after it.
    var after = head
    for _ in 0..<k {
        guard let node = after else { return head }   // too short: leave it
        after = node.next
    }
    // Reverse the group onto the already-processed rest of the list
    var previous = reverseInGroupsRecursively(after, k: k)
    var current = head
    for _ in 0..<k {
        let node = current!
        let next = node.next
        node.next = previous
        previous = node
        current = next
    }
    return previous
}

print(describe(reverseInGroupsRecursively(makeList([1, 2, 3, 4, 5, 6, 7, 8]), k: 3)))
```

```output
3 -> 2 -> 1 -> 6 -> 5 -> 4 -> 7 -> 8 -> nil
```

Here the rest of the list is processed first, so the group can be reversed straight onto it. The recursion is one call per **group**, about n / k deep. That's fine for large k, but with k = 2 on 100,000 nodes it's 50,000 frames, enough to crash inside a test. The loop version has no such limit.

## Variations

Once the four-reference shape is comfortable, the usual variations are small changes:

| Variation | Change |
| --- | --- |
| Reverse the short final group too | when the look-ahead fails, reverse whatever is left |
| Reverse every other group | after reversing a group, skip the next k nodes untouched |
| Groups of growing size (1, 2, 3, …) | increase k after each group |
| Reverse from the end | count the length, then skip `length % k` nodes first |

<Callout kind="gotcha" title="Common mistakes">
- **Reversing a short final group.** Look ahead first; stop if fewer than k nodes remain.
- **Reconnecting only one end.** Each group joins the list at two places: `groupBefore.next` at the front, and the old first node's `next` at the back. Starting the reversal at `after` handles the back; don't forget the front.
- **Moving `groupBefore` to the wrong node.** After reversal, the group's last node is the old `groupFirst`, not `groupLast`.
- **Swapping values instead of nodes.** It might pass a quick check, but the problem asks you to move nodes, and in real code nodes often carry more than one value.
</Callout>
