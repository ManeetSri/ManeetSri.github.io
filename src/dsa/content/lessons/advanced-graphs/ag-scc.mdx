## Why it matters

In a directed graph, "connected" splits into a stronger question: can you get from A to B **and back**? Groups of vertices where the answer is yes for every pair are the **strongly connected components** (SCCs). They're the cycles of a dependency graph that a build system has to reject (Swift packages can't depend on each other in a loop), groups of mutually recursive functions in a compiler's call graph, and clusters of accounts that all follow each other in a social network. Shrinking each component to a single vertex turns any directed graph into a DAG, which unlocks everything you know about DAGs, and 2-SAT, later in this module, is built on SCCs. This lesson builds both classic linear-time algorithms, Kosaraju's and Tarjan's, and then makes them safe for deep graphs.

## Mutually reachable

Two vertices u and v are **strongly connected** when there's a path from u to v and a path from v to u. Every vertex is strongly connected to itself (the empty path). The relation is symmetric by definition, and it's transitive: if u and v are, and v and w are, you can go u → v → w and back w → v → u. A relation with those three properties splits the vertices into groups, so **every vertex belongs to exactly one SCC**: the largest group in which every pair is mutually reachable.

Here's the graph this lesson uses throughout, with 8 vertices and 12 one-way edges, listed by where they start. The visualiser further down draws it.

| From | To |
| --- | --- |
| 0 | 1, 7 |
| 1 | 2, 3 |
| 2 | 0, 4 |
| 3 | 4 |
| 4 | 5 |
| 5 | 3, 6 |
| 6 | 7 |
| 7 | 6 |

Its SCCs are `{0, 1, 2}` (the cycle 0 → 1 → 2 → 0), `{3, 4, 5}` (the cycle 3 → 4 → 5 → 3) and `{6, 7}`. Vertex 1 reaches 3, but nothing in `{3, 4, 5}` leads back to 1, so they're in different components.

A vertex on no cycle at all is a component on its own. In a DAG every SCC is a single vertex, which is another way of saying a DAG has no cycles.

## The condensation is a DAG

Squash each SCC into one vertex, and keep an edge from component X to component Y whenever some edge goes from a vertex in X to a vertex in Y. The result is the **condensation** of the graph. For the graph above:

```text
   {0, 1, 2} ──────► {3, 4, 5} ──────► {6, 7}
        │                                 ▲
        └─────────────────────────────────┘
```

The two edges 1 → 3 and 2 → 4 both become one edge between the first two components.

**The condensation never has a cycle.** If it had one, say X → Y → X, then every vertex of X could reach every vertex of Y and back, so X and Y would be one component, not two. So the condensation is a DAG, and it has a topological order, as in [DAGs and dependency ordering](/dsa/learn/topo-dags). Many hard-looking problems on directed graphs become easy this way: find the SCCs, condense, then do DP over the DAG.

The obvious way to find SCCs is to run a search forwards and backwards from every vertex, O(V · (V + E)). Both algorithms below do it in **O(V + E)**, with one or two depth-first searches.

## Kosaraju's algorithm: two passes

Kosaraju's algorithm uses two DFS passes and the **reversed graph**, the same vertices with every edge pointing the other way. Reversing edges doesn't change the SCCs: a cycle reversed is still a cycle.

1. **Pass 1:** run DFS over the whole graph (from every unvisited vertex in turn), and record each vertex at the moment it **finishes**, when every edge out of it has been explored. This is the finishing order you met in [Topological sort with DFS](/dsa/learn/topo-dfs).
2. **Pass 2:** go through the vertices in **reverse finishing order**, latest finisher first. From each vertex not yet claimed, search the reversed graph. Everything that search reaches, and hasn't been claimed already, is one SCC.

Step through both passes on the lesson's graph. In pass 1, watch the call stack: a vertex finishes when it leaves the stack. In pass 2, each search stays trapped inside one component.

### Why the latest finisher is the right place to start

Think about the condensation. Suppose there's an edge from component X to component Y. Then **some vertex of X finishes after every vertex of Y.** Either the DFS entered X first, and then it reached all of Y before leaving that first vertex of X; or it entered Y first, and then it finished all of Y without ever reaching X (Y can't reach X, or they'd be one component), and X finishes later.

So the vertex that finishes last of all lies in a component that no other component points into: a **source** of the condensation. In the reversed graph, that component becomes a **sink**: no edge leaves it. A search from there can't escape, and it reaches exactly its own component. Claim it, and the next unclaimed latest finisher is in a source of what remains. Repeat until everything is claimed.

### The code

```swift run
// Kosaraju's algorithm: a DFS that records finishing order, then a second pass on the reversed graph
func stronglyConnectedComponents(_ n: Int, _ edges: [[Int]]) -> [[Int]] {
    var graph = [[Int]](repeating: [], count: n)
    var reversed = [[Int]](repeating: [], count: n)
    for edge in edges {
        graph[edge[0]].append(edge[1])
        reversed[edge[1]].append(edge[0])          // the same edge, pointing the other way
    }

    // Pass 1: DFS over the whole graph, recording each vertex as it finishes
    var visited = [Bool](repeating: false, count: n)
    var finished: [Int] = []
    func firstPass(_ v: Int) {
        visited[v] = true
        for w in graph[v] where !visited[w] {
            firstPass(w)
        }
        finished.append(v)                         // everything reachable from v is done
    }
    for v in 0..<n where !visited[v] {
        firstPass(v)
    }
    print("finishing order:", finished)

    // Pass 2: on the reversed graph, latest finisher first. Each search claims one component.
    var claimed = [Bool](repeating: false, count: n)
    var components: [[Int]] = []
    func secondPass(_ v: Int) {
        claimed[v] = true
        components[components.count - 1].append(v)
        for w in reversed[v] where !claimed[w] {
            secondPass(w)
        }
    }
    for v in finished.reversed() where !claimed[v] {
        components.append([])
        secondPass(v)
    }
    return components
}

let edges = [[0, 1], [0, 7], [1, 2], [1, 3], [2, 0], [2, 4], [3, 4], [4, 5], [5, 3], [5, 6], [6, 7], [7, 6]]
let components = stronglyConnectedComponents(8, edges)
print("components:", components)
print("sorted:", components.map { $0.sorted() })
```

```output
finishing order: [3, 7, 6, 5, 4, 2, 1, 0]
components: [[0, 2, 1], [4, 3, 5], [6, 7]]
sorted: [[0, 1, 2], [3, 4, 5], [6, 7]]
```

What to notice:

- Vertex 0 finishes last, and it's in `{0, 1, 2}`, the source of the condensation. Searching the reversed graph from 0 finds 2, then 1, and then nothing else, because no edge enters `{0, 1, 2}` from outside, so no reversed edge leaves it.
- The next unclaimed vertex in reverse finishing order is 4, then 6. The components come out in **topological order** of the condensation: sources first.
- Pass 2 only needs to know *which* vertices each search reaches, not the order. A BFS, or any traversal, works there too. Only pass 1 has to be a DFS.
- Each pass touches every vertex and edge once, plus building the reversed graph: **O(V + E)** time and space.

<Callout kind="gotcha" title="Two common Kosaraju mistakes">
**Using discovery order instead of finishing order.** The vertex you *visit* first proves nothing; the one that *finishes* last is guaranteed to be in a source component. Record the vertex after its loop over neighbours, not before.

**Searching the original graph in pass 2.** From the latest finisher, the original edges lead out of its component into everything downstream, so one search would swallow several components. Pass 2 must follow the reversed edges.
</Callout>

## Tarjan's algorithm: one pass

Tarjan's algorithm finds the same components with a **single** DFS and no reversed graph. It's a little harder to understand, and it's the one you'll see most often in competitive programming. It gives every vertex two numbers:

- `index[v]`: when v was discovered: 0 for the first vertex visited, 1 for the next, and so on.
- `low[v]`, the **low-link**: the smallest index v can reach by going down DFS tree edges from v and then following at most one more edge to a vertex that's still **on the stack**.

The stack is the key. Tarjan pushes every vertex onto a stack when it's discovered, and keeps it there until its whole component is found. The vertices on the stack are the ones whose components are still open. (It's an ordinary stack, as in [Build `Stack<T>`](/dsa/learn/stack-build), separate from the call stack of the recursion.)

When v finishes, one comparison decides everything:

- If `low[v] < index[v]`, something below v reaches back above v to a vertex still on the stack. v belongs to that older vertex's component. Leave it on the stack.
- If `low[v] == index[v]`, nothing reachable from v gets back above it. v is the **root** of its component, the first vertex of it the DFS discovered, and the component is v plus everything above v on the stack. Pop them all off.

The `onStack` check matters. An edge to a vertex whose component is already finished and popped (a cross edge into an earlier component) must be ignored: that vertex can't reach back to v, or it would still be open.

```swift run
// Tarjan's algorithm: one DFS, a discovery index and a low-link per vertex, and a stack
func tarjan(_ n: Int, _ edges: [[Int]]) -> [[Int]] {
    var graph = [[Int]](repeating: [], count: n)
    for edge in edges {
        graph[edge[0]].append(edge[1])
    }
    var index = [Int](repeating: -1, count: n)     // discovery order; -1 means not visited yet
    var low = [Int](repeating: 0, count: n)
    var onStack = [Bool](repeating: false, count: n)
    var stack: [Int] = []
    var nextIndex = 0
    var components: [[Int]] = []

    func visit(_ v: Int) {
        index[v] = nextIndex
        low[v] = nextIndex
        nextIndex += 1
        stack.append(v)
        onStack[v] = true
        for w in graph[v] {
            if index[w] == -1 {
                visit(w)                           // a tree edge
                low[v] = min(low[v], low[w])
            } else if onStack[w] {
                low[v] = min(low[v], index[w])     // an edge back into an unfinished component
            }                                      // otherwise w's component is finished: ignore it
        }
        if low[v] == index[v] {                    // v is the first vertex of its component
            var component: [Int] = []
            while true {
                let w = stack.removeLast()
                onStack[w] = false
                component.append(w)
                if w == v { break }
            }
            print("\(v) closes \(component.sorted()); stack left: \(stack)")
            components.append(component)
        }
    }

    for v in 0..<n where index[v] == -1 {
        visit(v)
    }
    print("index:", index)
    print("low:  ", low)
    return components
}

let edges = [[0, 1], [0, 7], [1, 2], [1, 3], [2, 0], [2, 4], [3, 4], [4, 5], [5, 3], [5, 6], [6, 7], [7, 6]]
print(tarjan(8, edges).map { $0.sorted() })
```

```output
6 closes [6, 7]; stack left: [0, 1, 2, 4, 5, 3]
4 closes [3, 4, 5]; stack left: [0, 1, 2]
0 closes [0, 1, 2]; stack left: []
index: [0, 1, 2, 5, 3, 4, 6, 7]
low:   [0, 0, 0, 3, 3, 3, 6, 6]
[[6, 7], [3, 4, 5], [0, 1, 2]]
```

### Tracing it

The DFS visits 0, 1, 2, 4, 5, 3, 6, 7 in that order, so those get indexes 0 to 7. Here's what happens, step by step:

| Step | What happens | Stack after |
| --- | --- | --- |
| Visit 0, 1, 2 | indexes 0, 1, 2 | 0 1 2 |
| 2 → 0 | 0 is on the stack: `low[2] = 0` | 0 1 2 |
| Visit 4, 5, 3 (via 2 → 4) | indexes 3, 4, 5 | 0 1 2 4 5 3 |
| 3 → 4 | 4 is on the stack: `low[3] = 3` | |
| 3 finishes | `low[3] = 3`, not its index 5: stays | |
| Back in 5 | `low[5] = min(4, low[3]) = 3` | |
| Visit 6, 7 (via 5 → 6) | indexes 6, 7 | 0 1 2 4 5 3 6 7 |
| 7 → 6 | 6 is on the stack: `low[7] = 6` | |
| 7 finishes | 6 ≠ 7: stays | |
| 6 finishes | `low[6] = 6` = its index: **pop 7, 6** | 0 1 2 4 5 3 |
| 5 finishes | `low[5] = 3`, not 4: stays | |
| 4 finishes | `low[4] = 3` = its index: **pop 3, 5, 4** | 0 1 2 |
| Back in 2, then 1 | `low` 0 flows up; 1 → 3 points at a popped vertex: ignored | |
| 0 finishes | 0 → 7 is ignored too; `low[0] = 0`: **pop 2, 1, 0** | empty |

Notice the edge 1 → 3. When 1 looks at it, vertex 3 has already been popped as part of `{3, 4, 5}`, so the edge is ignored. Here it wouldn't matter (`low[1]` is already 0), but in general an edge into a finished component can carry a smaller index than the current vertex's, and using it would drag the low-link down and merge two components that aren't strongly connected.

### Components come out sinks first

Tarjan closes `{6, 7}` first, then `{3, 4, 5}`, then `{0, 1, 2}`: **reverse topological order** of the condensation, the opposite of Kosaraju. That's no accident. A component is closed only when its root finishes, after everything reachable from it, so every component it points into has already been closed. You'll use this in 2-SAT, where the order of the components decides the answer.

| | Kosaraju | Tarjan |
| --- | --- | --- |
| DFS passes | two | one |
| Extra memory | the reversed graph | `index`, `low`, `onStack` and a stack |
| Order components come out | topological (sources first) | reverse topological (sinks first) |
| Time | O(V + E) | O(V + E) |

## Building the condensation

With a component number for every vertex, the condensation takes one loop over the edges. Kosaraju's components are numbered in topological order, which is handy here. Many questions about the original graph are now questions about a small DAG. For example, the fewest one-way edges you'd need to add to make the whole graph strongly connected is the larger of the number of sources and the number of sinks of the condensation (or 0, if it's already one component).

```swift run
// Component ids from Kosaraju (topological order), then the condensation DAG
func componentIds(_ n: Int, _ edges: [[Int]]) -> [Int] {
    var graph = [[Int]](repeating: [], count: n)
    var reversed = [[Int]](repeating: [], count: n)
    for edge in edges {
        graph[edge[0]].append(edge[1])
        reversed[edge[1]].append(edge[0])
    }
    var visited = [Bool](repeating: false, count: n)
    var finished: [Int] = []
    func firstPass(_ v: Int) {
        visited[v] = true
        for w in graph[v] where !visited[w] { firstPass(w) }
        finished.append(v)
    }
    for v in 0..<n where !visited[v] { firstPass(v) }

    var component = [Int](repeating: -1, count: n)
    var count = 0
    func secondPass(_ v: Int) {
        component[v] = count
        for w in reversed[v] where component[w] == -1 { secondPass(w) }
    }
    for v in finished.reversed() where component[v] == -1 {
        secondPass(v)
        count += 1
    }
    return component
}

let n = 8
let edges = [[0, 1], [0, 7], [1, 2], [1, 3], [2, 0], [2, 4], [3, 4], [4, 5], [5, 3], [5, 6], [6, 7], [7, 6]]
let component = componentIds(n, edges)
let count = component.max()! + 1
print("component of each vertex:", component)

// One edge between two components, however many original edges join them
var dagEdges = Set<[Int]>()
for edge in edges where component[edge[0]] != component[edge[1]] {
    dagEdges.insert([component[edge[0]], component[edge[1]]])
}
print("condensation edges:", dagEdges.sorted { $0.lexicographicallyPrecedes($1) })

var inDegree = [Int](repeating: 0, count: count)
var outDegree = [Int](repeating: 0, count: count)
for edge in dagEdges {
    outDegree[edge[0]] += 1
    inDegree[edge[1]] += 1
}
let sources = (0..<count).filter { inDegree[$0] == 0 }
let sinks = (0..<count).filter { outDegree[$0] == 0 }
print("sources:", sources, "sinks:", sinks)
print("one-way edges to add to make it strongly connected:", count == 1 ? 0 : max(sources.count, sinks.count))
```

```output
component of each vertex: [0, 0, 0, 1, 1, 1, 2, 2]
condensation edges: [[0, 1], [0, 2], [1, 2]]
sources: [0] sinks: [2]
one-way edges to add to make it strongly connected: 1
```

One edge from component 2 back to component 0, say 7 → 0, would close the loop. The `Set` removes the duplicate edge between components 0 and 1, and it's sorted before printing, because a `Set`'s order changes from run to run.

## Deep graphs: drop the recursion

Both algorithms as written recurse once per vertex along a path. A one-way chain of 100,000 vertices means a recursion 100,000 calls deep. That's fine on the main thread, but inside `swift test`, where each test runs on a thread with a much smaller stack, it crashes, exactly as [Stack depth limits in Swift](/dsa/learn/rec-stack-limits) warned. Graph problems hit this constantly, because real graphs have long paths. The fix is the one from [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack): keep the call stack yourself, in an array.

Each recursive call of Tarjan's `visit` remembers two things: which vertex it's working on, and how far through that vertex's edges it has got. So that's a frame: `(vertex, next)`. Then:

- **The call** becomes: set up the new vertex's index and low-link, and push a frame `(w, 0)`.
- **The loop over edges** becomes: look at the top frame; if it has an edge left, advance `next` and handle that edge.
- **The return** becomes: when the top frame has no edges left, pop it, then do the work that came after the recursive call: update the parent's low-link, which is now the new top frame, and close the component if `low == index`.

```swift run
// Tarjan's algorithm with an explicit stack of frames instead of recursion
func countComponents(_ n: Int, _ graph: [[Int]]) -> Int {
    var index = [Int](repeating: -1, count: n)
    var low = [Int](repeating: 0, count: n)
    var onStack = [Bool](repeating: false, count: n)
    var stack: [Int] = []
    var frames: [(vertex: Int, next: Int)] = []    // what each recursive call would have remembered
    var nextIndex = 0
    var components = 0

    for start in 0..<n where index[start] == -1 {
        index[start] = nextIndex
        low[start] = nextIndex
        nextIndex += 1
        stack.append(start)
        onStack[start] = true
        frames.append((start, 0))

        while let frame = frames.last {
            let v = frame.vertex
            if frame.next < graph[v].count {
                frames[frames.count - 1].next += 1     // come back to the next edge later
                let w = graph[v][frame.next]
                if index[w] == -1 {                    // the recursive call, as a push
                    index[w] = nextIndex
                    low[w] = nextIndex
                    nextIndex += 1
                    stack.append(w)
                    onStack[w] = true
                    frames.append((w, 0))
                } else if onStack[w] {
                    low[v] = min(low[v], index[w])
                }
            } else {                                   // the return, as a pop
                frames.removeLast()
                if let parent = frames.last?.vertex {
                    low[parent] = min(low[parent], low[v])
                }
                if low[v] == index[v] {
                    components += 1
                    while true {
                        let w = stack.removeLast()
                        onStack[w] = false
                        if w == v { break }
                    }
                }
            }
        }
    }
    return components
}

let n = 200_000
var chain = [[Int]](repeating: [], count: n)
for v in 0..<(n - 1) {
    chain[v].append(v + 1)
}
print("a chain of 200,000:", countComponents(n, chain))
chain[n - 1].append(0)
print("the same chain closed into a ring:", countComponents(n, chain))
let small = [[1, 7], [2, 3], [0, 4], [4], [5], [3, 6], [7], [6]]
print("the lesson's graph:", countComponents(8, small))
```

```output
a chain of 200,000: 200000
the same chain closed into a ring: 1
the lesson's graph: 3
```

The frames array grows to 200,000 entries on the chain, but that's heap memory, which has room for millions. The algorithm is unchanged, so it's still O(V + E).

For Kosaraju, only pass 1 needs this treatment, because only pass 1 cares about finishing order. Pass 2 can be a plain stack-based search with no frames at all.

<Callout kind="gotcha" title="Swift gotcha: updating the top frame">
`frames.last` gives you a **copy** of the top frame, because tuples are value types. `frame.next += 1` would change only the copy, and the loop would try the same edge forever. Write through the array instead: `frames[frames.count - 1].next += 1`. The code above reads the edge to handle from the copy, `frame.next`, and advances the stored counter so the next look starts one edge further on.
</Callout>
