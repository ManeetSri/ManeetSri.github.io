## Why it matters

A snow plough should clear every street in town without driving any street twice. A pen plotter should draw a figure without lifting the pen. Genome assemblers stitch millions of short DNA reads into one sequence by walking a graph whose edges are the overlaps. All three ask for a walk that uses **every edge exactly once**: an **Euler path**. Unlike most "visit everything" questions, this one has a fast answer, O(E), thanks to a simple degree test and a neat algorithm by Hierholzer. Its most famous interview form is rebuilding a trip from a pile of tickets, which is this lesson's practice problem.

## Every edge exactly once

In 1736, Leonhard Euler was asked whether you could walk through the city of Königsberg crossing each of its seven bridges exactly once. He showed you couldn't, and the argument started graph theory. Here are the definitions:

- An **Euler path** is a walk that uses every edge of the graph exactly once. Vertices may be visited many times.
- An **Euler circuit** is an Euler path that ends where it started.

Euler's insight was about degrees. Every time a walk passes *through* a vertex, it uses two of that vertex's edges: one in, one out. So at every vertex except the start and the end, the walk uses edges in pairs.

| Graph | Euler circuit exists when | Euler path exists when |
| --- | --- | --- |
| Undirected | every vertex has even degree | exactly 0 or 2 vertices have odd degree; with 2, start at one and finish at the other |
| Directed | every vertex has in-degree = out-degree | as for a circuit, or one vertex has out = in + 1 (the start), one has in = out + 1 (the end), and every other vertex is balanced |

Both rows have a second condition: **all the edges must be in one connected piece**. Two separate triangles have even degrees everywhere but no single walk covers both. Isolated vertices with no edges don't matter.

Königsberg's four land masses had degrees 5, 3, 3 and 3. Four odd vertices: no Euler path.

## A house in one stroke

Children's puzzle: draw this house without lifting your pen or going over a line twice.

```text
          4
        /   \
      3 ───── 2
      │ ╲   ╱ │
      │   ╳   │
      │ ╱   ╲ │
      0 ───── 1
```

Vertices 0 and 1 have degree 3; the others have even degree. Exactly two odd vertices, so there's an Euler path, and it must start at one of the bottom corners and finish at the other.

## Hierholzer's algorithm

The obvious approach, walking along unused edges until you're stuck, can fail: you can strand edges behind you. In the house, starting 0 → 1 → 2 → 0 → 3 → 1 leaves you at 1 with nothing left to walk, while 2 → 3, 3 → 4 and 4 → 2 are still undrawn.

Hierholzer's fix is beautifully lazy. Walk until you're stuck, and **record vertices only as you back out of them**:

1. Keep a stack of vertices, starting with the start vertex.
2. Look at the vertex on top. If it has an unused edge, mark the edge used, walk it, and push the vertex at its other end.
3. If it has no unused edge left, pop it and append it to the path.
4. When the stack is empty, reverse the path.

Why does this work? The first time you get stuck, you must be at the **end** of the Euler path: with the degree conditions, every other vertex can always be left again after being entered. So the first vertex appended is correct as the last vertex. Then you back up to the most recent vertex that still has unused edges, and walk a detour from it. Every detour is a loop that returns to where it began (again, by the degrees), and appending vertices as you back out splices each loop into the path at exactly the right place. It's a post-order: a vertex is written down only after everything walked from it has been.

For an undirected graph, each edge sits in two adjacency lists, so mark edges used by **id**, and keep a pointer `next[v]` per vertex that skips edges already walked from the other end:

```swift run
let edges = [[0, 1], [1, 2], [2, 3], [3, 0], [0, 2], [1, 3], [3, 4], [4, 2]]
let n = 5
var adjacency = [[(to: Int, id: Int)]](repeating: [], count: n)
for (id, edge) in edges.enumerated() {
    adjacency[edge[0]].append((edge[1], id))
    adjacency[edge[1]].append((edge[0], id))
}

// Degree check: an Euler path needs 0 or 2 vertices of odd degree
let odd = (0..<n).filter { adjacency[$0].count % 2 == 1 }
print("degrees:", adjacency.map { $0.count }, "odd:", odd)
let start = odd.first ?? 0                     // start at an odd vertex if there is one

// Hierholzer's algorithm with a stack. `next[v]` skips edges already used from v's side.
var used = [Bool](repeating: false, count: edges.count)
var next = [Int](repeating: 0, count: n)
var stack = [start]
var path: [Int] = []
while let v = stack.last {
    while next[v] < adjacency[v].count && used[adjacency[v][next[v]].id] {
        next[v] += 1                           // this edge was walked from the other end
    }
    if next[v] < adjacency[v].count {
        let (w, id) = adjacency[v][next[v]]
        used[id] = true
        stack.append(w)                        // walk the edge
    } else {
        path.append(stack.removeLast())        // stuck: v is the last vertex among those left
    }
}
print("path:", Array(path.reversed()))
print("edges used:", path.count - 1, "of", edges.count)
```

```output
degrees: [3, 3, 4, 4, 2] odd: [0, 1]
path: [0, 1, 2, 3, 0, 2, 4, 3, 1]
edges used: 8 of 8
```

The path starts at 0, ends at 1, and walks all eight lines once. The final check matters: if the edges weren't all connected, the walk would cover only the start's piece, and `path.count - 1` would come up short. Each edge is walked once and each `next` pointer only moves forward, so the whole thing is **O(V + E)**.

## Reconstructing an itinerary

Now the interview version. You have a pile of tickets `[from, to]`, all from one trip that started at a known airport. Rebuild the route, and if several fit, return the one that's alphabetically smallest airport by airport. Tickets are directed edges, the route is an Euler path, and "smallest" means: at every airport, **take the alphabetically smallest unused ticket**.

Greedy alone fails. With tickets HUB → ASH, HUB → CAL and CAL → HUB, the smallest first move is HUB → ASH, and ASH is a dead end with two tickets still unused. Hierholzer's algorithm with smallest-first choices handles it, because the dead end is simply popped first and so lands **last** in the reversed route:

```swift run
// Hierholzer's algorithm on tickets: always fly the smallest unused ticket
func itinerary(_ tickets: [[String]], from start: String) -> [String] {
    var departures: [String: [String]] = [:]
    for ticket in tickets {
        departures[ticket[0], default: []].append(ticket[1])
    }
    departures = departures.mapValues { $0.sorted(by: >) }   // smallest last, for popLast()

    var stack = [start]
    var route: [String] = []
    while let airport = stack.last {
        if let next = departures[airport]?.popLast() {
            stack.append(next)
            print("fly \(airport) → \(next)    stack: \(stack.joined(separator: " "))")
        } else {
            route.append(stack.removeLast())
            print("stuck at \(airport)      route so far: \(route.joined(separator: " "))")
        }
    }
    return route.reversed()
}

let tickets = [["HUB", "ASH"], ["HUB", "CAL"], ["CAL", "HUB"]]
print(itinerary(tickets, from: "HUB"))
```

```output
fly HUB → ASH    stack: HUB ASH
stuck at ASH      route so far: ASH
fly HUB → CAL    stack: HUB CAL
fly CAL → HUB    stack: HUB CAL HUB
stuck at HUB      route so far: ASH HUB
stuck at CAL      route so far: ASH HUB CAL
stuck at HUB      route so far: ASH HUB CAL HUB
["HUB", "CAL", "HUB", "ASH"]
```

Follow the trace. The walk dead-ends at ASH at once, so ASH is written down first and becomes the final stop. Back at HUB, the detour HUB → CAL → HUB is walked and spliced in before it. Why is the result the *smallest* route? At each airport the algorithm commits to the smallest ticket that can still be followed by a complete route; a ticket that leads into a dead end too early is the one the post-order moves to the end, which is exactly where the smallest valid route must put it.

Two details make it fast. Each airport's destinations are sorted **largest first**, so `popLast()` hands out the smallest in O(1); removing from the front with `removeFirst()` would cost O(k) every time. And `departures[airport]?.popLast()` both mutates the array inside the dictionary and returns `nil` when an airport has no tickets left or never had any. Sorting dominates: **O(E log E)**.

## Which way round?

Before running Hierholzer on a directed graph, the degree test tells you whether a path exists and where it must start:

```swift run
// Where must an Euler path start in a directed graph, if one exists?
func eulerStart(_ n: Int, _ edges: [[Int]]) -> Int? {
    var outDegree = [Int](repeating: 0, count: n)
    var inDegree = [Int](repeating: 0, count: n)
    for edge in edges {
        outDegree[edge[0]] += 1
        inDegree[edge[1]] += 1
    }
    var starts: [Int] = []
    var ends = 0
    for v in 0..<n {
        switch outDegree[v] - inDegree[v] {
        case 0: continue
        case 1: starts.append(v)
        case -1: ends += 1
        default: return nil                    // too unbalanced for any Euler path
        }
    }
    if starts.isEmpty && ends == 0 {           // balanced: a circuit, so start anywhere with an edge
        return (0..<n).first { outDegree[$0] > 0 } ?? 0
    }
    return starts.count == 1 && ends == 1 ? starts[0] : nil
}

print(eulerStart(4, [[0, 1], [1, 2], [2, 0], [2, 3]]) as Any)
print(eulerStart(3, [[0, 1], [1, 2], [2, 0]]) as Any)
print(eulerStart(3, [[0, 1], [0, 2]]) as Any)
```

```output
Optional(2)
Optional(0)
nil
```

In the first graph, vertex 2 has one more edge out than in, and vertex 3 one more in than out, so the path must run from 2 to 3: 2 → 0 → 1 → 2 → 3. The second is a balanced cycle. In the third, vertex 0 has two more out than in, so no single walk can use both its edges. (Connectivity still needs its own check, such as comparing the walk's length with E + 1 afterwards.)

<Callout kind="gotcha" title="Common mistakes">
- **Greedy without the post-order.** Appending each airport as you *arrive* gives the greedy route, which breaks on dead ends. Append as you *leave*, then reverse.
- **Recursion depth.** The recursive form of Hierholzer (visit every unused edge, then append the vertex) is three lines long, and it recurses once per edge along the current walk. A 20,000-ticket trip is 20,000 calls deep, which crashes inside a test. The stack version above is just as short.
- **Throwing away duplicate tickets.** Two identical tickets are two edges, and both must be used. Store destinations in an array, not a `Set`.
- **Forgetting the undirected double entry.** In an undirected graph each edge appears in two lists. Mark edges used by id, or you'll walk each one twice.
</Callout>
