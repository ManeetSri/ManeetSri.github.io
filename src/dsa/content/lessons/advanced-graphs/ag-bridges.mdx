## Why it matters

Network engineers ask one question again and again: **which single failure splits the network?** A cable whose loss cuts some servers off from others is a **bridge**. A router, airport or power substation whose loss does the same is an **articulation point**. Finding them tells you where redundancy is missing: where to lay a second cable, or which hub needs a backup. The same ideas find single points of failure in road maps, supply chains and microservice dependencies. In this lesson, one DFS finds every bridge and articulation point in O(V + E), using a low-link much like Tarjan's from [the previous lesson](/dsa/learn/ag-scc), adapted to undirected graphs.

## Single points of failure

Take an undirected graph. Removing something **disconnects** it if afterwards there are more connected components than before (components as in [Connected components and flood fill](/dsa/learn/gt-components)).

- A **bridge** is an edge whose removal disconnects the graph.
- An **articulation point** (or cut vertex) is a vertex whose removal, together with all its edges, disconnects the graph.

Here's the graph this lesson uses, with 8 vertices and 9 edges:

```text
   0 ───── 1 ───── 3 ───── 4
    \     /         \     /
     \   /           \   /
       2               5 ───── 6 ───── 7
```

Its bridges are 1–3, 5–6 and 6–7. Its articulation points are 1, 3, 5 and 6: removing 1 cuts 0 and 2 off from the rest, removing 6 strands 7, and so on. Vertex 7 isn't one: removing a vertex at the end of a line leaves the rest connected.

One fact makes bridges easier to think about: **an edge is a bridge exactly when it lies on no cycle.** If an edge u–v is on a cycle, the rest of the cycle is another way from u to v, so removing the edge disconnects nothing. If it's on no cycle, the edge is the only way between its two sides.

The brute force removes each edge (or vertex) in turn and counts components with a BFS: O(E · (V + E)) for bridges. For a network with 100,000 cables, that's ten billion steps. One DFS does it all.

## What a DFS tree looks like in an undirected graph

Run DFS on an undirected graph, as in [DFS, recursive and iterative](/dsa/learn/gt-dfs). The edges it follows to new vertices form a **DFS tree**. Every other edge connects a vertex to one of its **ancestors** in that tree: a **back edge**. There are no edges between separate branches. The reason: when DFS is at u, it explores every unvisited neighbour of u before leaving u. So if u and v are joined by an edge, whichever is discovered first is still being explored when the other is discovered, which makes it an ancestor.

That's the whole picture: tree edges going down, back edges going up. (In [cycle detection](/dsa/learn/gt-cycles), every back edge closes a cycle.) Step through the DFS on the lesson's graph, starting from 0, and watch the numbers: each is the order in which a vertex is discovered.

The DFS goes 0 → 1 → 2, backs up to 1, then 3 → 4 → 5 → 6 → 7. The tree edges are 0–1, 1–2, 1–3, 3–4, 4–5, 5–6 and 6–7. The two edges left over, 2–0 and 5–3, are back edges, and each closes a cycle: 0–1–2 and 3–4–5.

## Discovery times and low-links

Number the vertices in the order DFS discovers them: `disc[v]`. (The visualiser counts from 1; the code below counts from 0.) Then define the **low-link**:

> `low[v]` is the smallest discovery time reachable from v by going down tree edges into v's subtree, then following **at most one back edge** up.

It answers the question "how high can v's subtree climb without using the edge to v's parent?" In code, it's computed bottom-up as the DFS returns:

- start with `low[u] = disc[u]`;
- for each back edge u–v (v already discovered): `low[u] = min(low[u], disc[v])`;
- after returning from each child v: `low[u] = min(low[u], low[v])`.

On the lesson's graph:

| Vertex | `disc` | `low` | Why |
| --- | --- | --- | --- |
| 0 | 0 | 0 | itself |
| 1 | 1 | 0 | its child 2 has a back edge to 0 |
| 2 | 2 | 0 | back edge 2–0 |
| 3 | 3 | 3 | its subtree's best is the back edge 5–3 |
| 4 | 4 | 3 | its child 5 reaches 3 |
| 5 | 5 | 3 | back edge 5–3 |
| 6 | 6 | 6 | nothing below 6 climbs higher |
| 7 | 7 | 7 | a leaf with no back edges |

## The two tests

Look at each tree edge from a parent u down to a child v.

**Bridge test: `low[v] > disc[u]`.** Then nothing in v's subtree can reach u or anything above it, except through the edge u–v. Remove that edge and the subtree is cut off. If instead `low[v] ≤ disc[u]`, some back edge from the subtree lands on u or higher, which closes a cycle through u–v, so it isn't a bridge.

**Articulation test, for a non-root u: `low[v] ≥ disc[u]`.** Now v's subtree can climb to u itself, but no higher. Removing the *edge* wouldn't cut it off, since a back edge lands on u, but removing the *vertex* u removes that landing spot too, and the subtree is stranded. One such child is enough to make u an articulation point.

Notice the difference: `>` for bridges, `≥` for articulation points.

**The root is special.** Nothing is above the root, so `low[v] ≥ disc[root]` is true for every child and proves nothing. Instead: **the root is an articulation point exactly when it has two or more children in the DFS tree.** With two children, there's no edge between their subtrees (no edges between branches, remember), so the root is their only link. With one child, removing the root leaves that one subtree, still connected.

Applying the tests to every tree edge:

| Tree edge u–v | `low[v]` vs `disc[u]` | Bridge? | Makes u a cut vertex? |
| --- | --- | --- | --- |
| 0–1 | 0 vs 0 | no | 0 is the root, with one child: no |
| 1–2 | 0 vs 1 | no | no |
| 1–3 | 3 vs 1 | **yes** | **yes** |
| 3–4 | 3 vs 3 | no | **yes**: 3 ≥ 3 |
| 4–5 | 3 vs 4 | no | no |
| 5–6 | 6 vs 5 | **yes** | **yes** |
| 6–7 | 7 vs 6 | **yes** | **yes** |

Vertex 3 is the interesting row: 3–4 isn't a bridge, because the triangle 3–4–5 gives another way round, but the best 4's subtree can do is climb back to 3 itself, so removing vertex 3 strands 4, 5, 6 and 7.

## The code

The adjacency list stores each edge's **id** next to the neighbour, for a reason the next section explains.

```swift run
// Bridges and articulation points with discovery times and low-links
func cutEdgesAndVertices(_ n: Int, _ edges: [[Int]]) -> (bridges: [[Int]], cutVertices: [Int]) {
    var adjacency = [[(to: Int, id: Int)]](repeating: [], count: n)
    for (id, edge) in edges.enumerated() {
        adjacency[edge[0]].append((edge[1], id))
        adjacency[edge[1]].append((edge[0], id))
    }
    var disc = [Int](repeating: -1, count: n)      // discovery time; -1 means not visited yet
    var low = [Int](repeating: 0, count: n)
    var timer = 0
    var bridges: [[Int]] = []
    var isCut = [Bool](repeating: false, count: n)

    func visit(_ u: Int, arrivedBy edge: Int) {
        disc[u] = timer
        low[u] = timer
        timer += 1
        var children = 0
        for (v, id) in adjacency[u] where id != edge {    // skip only the edge we came in on
            if disc[v] == -1 {
                children += 1
                visit(v, arrivedBy: id)
                low[u] = min(low[u], low[v])
                if low[v] > disc[u] { bridges.append([u, v]) }
                if edge != -1 && low[v] >= disc[u] { isCut[u] = true }
            } else {
                low[u] = min(low[u], disc[v])             // a back edge to an ancestor
            }
        }
        if edge == -1 && children >= 2 { isCut[u] = true } // the root: two or more DFS children
    }

    for v in 0..<n where disc[v] == -1 {
        visit(v, arrivedBy: -1)
    }
    print("disc:", disc)
    print("low: ", low)
    return (bridges, (0..<n).filter { isCut[$0] })
}

let edges = [[0, 1], [0, 2], [1, 2], [1, 3], [3, 4], [3, 5], [4, 5], [5, 6], [6, 7]]
let result = cutEdgesAndVertices(8, edges)
print("bridges:", result.bridges)
print("articulation points:", result.cutVertices)
```

```output
disc: [0, 1, 2, 3, 4, 5, 6, 7]
low:  [0, 0, 0, 3, 3, 3, 6, 7]
bridges: [[6, 7], [5, 6], [1, 3]]
articulation points: [1, 3, 5, 6]
```

What to notice:

- Bridges are found deepest first, as the recursion unwinds: 6–7, then 5–6, then 1–3.
- `edge == -1` marks the root of each DFS tree. The loop at the bottom starts a new tree in every component, so a disconnected graph works too.
- When 3 looks at its neighbour 5, vertex 5 is already discovered: it's 3's *descendant*, reached through 4. That edge is seen again from the top, and `min(low[3], disc[5])` changes nothing, since 5 was discovered after 3. Back edges only help when they point up.
- Each vertex and edge is handled a constant number of times: **O(V + E)**.

## Multi-edges: skip the edge, not the parent

When u looks at its neighbours, it mustn't treat the tree edge back to its parent as a back edge: that would give every vertex `low ≤ disc[parent]`, and no edge would ever be a bridge. Many write-ups skip it by checking "is this neighbour my parent?" That breaks as soon as two vertices are joined by **two** edges, like a data centre with a doubled cable. The second cable is a genuine way back, so neither copy is a bridge. Skipping by the parent's number throws the second cable away too:

```swift run
// Two ways to avoid walking straight back to the parent
func bridges(_ n: Int, _ edges: [[Int]], skipParentVertex: Bool) -> [[Int]] {
    var adjacency = [[(to: Int, id: Int)]](repeating: [], count: n)
    for (id, edge) in edges.enumerated() {
        adjacency[edge[0]].append((edge[1], id))
        adjacency[edge[1]].append((edge[0], id))
    }
    var disc = [Int](repeating: -1, count: n)
    var low = [Int](repeating: 0, count: n)
    var timer = 0
    var found: [[Int]] = []

    func visit(_ u: Int, parent: Int, arrivedBy edge: Int) {
        disc[u] = timer
        low[u] = timer
        timer += 1
        for (v, id) in adjacency[u] {
            if skipParentVertex ? v == parent : id == edge { continue }
            if disc[v] == -1 {
                visit(v, parent: u, arrivedBy: id)
                low[u] = min(low[u], low[v])
                if low[v] > disc[u] { found.append([u, v]) }
            } else {
                low[u] = min(low[u], disc[v])
            }
        }
    }
    for v in 0..<n where disc[v] == -1 {
        visit(v, parent: -1, arrivedBy: -1)
    }
    return found
}

let doubled = [[0, 1], [0, 1], [1, 2]]               // two cables between 0 and 1
print("skip the parent vertex:", bridges(3, doubled, skipParentVertex: true))
print("skip the edge's id:    ", bridges(3, doubled, skipParentVertex: false))
```

```output
skip the parent vertex: [[1, 2], [0, 1]]
skip the edge's id:     [[1, 2]]
```

Skipping by id ignores only the one cable the DFS arrived on, so the second 0–1 cable counts as a back edge and gives `low[1] = 0`. If a problem promises no repeated edges, skipping the parent vertex is fine, but the id version costs nothing extra and is always right.

## Deep graphs: the iterative version

Like Tarjan's SCC algorithm, this DFS recurses once per vertex along a path, so a line of 100,000 servers crashes it inside a test. The conversion is the same as in [Strongly connected components](/dsa/learn/ag-scc): a frame holds what each call remembered (the vertex, the edge it arrived by, and the next neighbour to try), and the work after the recursive call moves to the moment a frame is popped. At that moment the parent is the new top frame, so that's where the parent's low-link is updated and both tests run. The root's children are counted when they're pushed.

```swift run
// Bridges and articulation points with an explicit stack of frames
func cutEdgesAndVertices(_ n: Int, _ edges: [[Int]]) -> (bridges: Int, cutVertices: Int) {
    var adjacency = [[(to: Int, id: Int)]](repeating: [], count: n)
    for (id, edge) in edges.enumerated() {
        adjacency[edge[0]].append((edge[1], id))
        adjacency[edge[1]].append((edge[0], id))
    }
    var disc = [Int](repeating: -1, count: n)
    var low = [Int](repeating: 0, count: n)
    var isCut = [Bool](repeating: false, count: n)
    var timer = 0
    var bridges = 0
    var frames: [(vertex: Int, arrivedBy: Int, next: Int)] = []

    for root in 0..<n where disc[root] == -1 {
        disc[root] = timer
        low[root] = timer
        timer += 1
        var rootChildren = 0
        frames.append((root, -1, 0))
        while let frame = frames.last {
            let u = frame.vertex
            if frame.next < adjacency[u].count {
                frames[frames.count - 1].next += 1
                let (v, id) = adjacency[u][frame.next]
                if id == frame.arrivedBy { continue }
                if disc[v] == -1 {                      // the recursive call
                    if u == root { rootChildren += 1 }
                    disc[v] = timer
                    low[v] = timer
                    timer += 1
                    frames.append((v, id, 0))
                } else {
                    low[u] = min(low[u], disc[v])
                }
            } else {                                    // the return: the parent is the new top
                frames.removeLast()
                guard let parent = frames.last?.vertex else { continue }
                low[parent] = min(low[parent], low[u])
                if low[u] > disc[parent] { bridges += 1 }
                if parent != root && low[u] >= disc[parent] { isCut[parent] = true }
            }
        }
        if rootChildren >= 2 { isCut[root] = true }
    }
    return (bridges, isCut.filter { $0 }.count)
}

let n = 200_000
let line = (0..<(n - 1)).map { [$0, $0 + 1] }
print("a line of 200,000:", cutEdgesAndVertices(n, line))
print("closed into a ring:", cutEdgesAndVertices(n, line + [[n - 1, 0]]))
let lesson = [[0, 1], [0, 2], [1, 2], [1, 3], [3, 4], [3, 5], [4, 5], [5, 6], [6, 7]]
print("the lesson's graph:", cutEdgesAndVertices(8, lesson))
```

```output
a line of 200,000: (bridges: 199999, cutVertices: 199998)
closed into a ring: (bridges: 0, cutVertices: 0)
the lesson's graph: (bridges: 3, cutVertices: 4)
```

On the line every edge is a bridge and every vertex except the two ends is a cut vertex. Close it into a ring and every edge lies on the one big cycle, so there are none of either.

## What comes next: 2-edge-connected pieces

Delete every bridge, and the components that remain are the **2-edge-connected components**: inside each, every pair of vertices is joined by two paths that share no edge, so no single cable failure separates them. Shrink each piece to one vertex and the bridges join them into a tree, the **bridge tree**. It's the undirected cousin of the condensation from the SCC lesson: questions like "how many cables must fail to cut A off from B?" become questions about paths in a tree. The vertex version, splitting a graph at its articulation points into **biconnected components**, uses the same low-links with a stack of edges.

<Callout kind="gotcha" title="Common mistakes">
- **Skipping the parent vertex instead of the edge.** Correct only when the graph has no parallel edges.
- **Mixing up the comparisons.** Bridges need `low[v] > disc[u]`; articulation points need `low[v] ≥ disc[u]`. Swapping them reports 3–4 as a bridge, or misses vertex 3 as a cut vertex.

- **Forgetting the root.** Applying the `≥` test at the root marks every root with at least one child as an articulation point. Count its DFS children instead.
- **Updating `low[u]` only from back edges.** The `min` with each child's `low` after the recursive call is what carries a back edge's reach up the tree.
- **Deep recursion.** A long path means a deep recursion. In tests, use frames.
</Callout>
