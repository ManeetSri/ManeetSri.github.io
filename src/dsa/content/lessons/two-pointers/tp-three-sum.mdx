## Why it matters

3Sum is the most famous two-pointer problem, and one of the most common interview questions of all. It's worth learning well because of how it's built: it **reduces** a new problem to one you've already solved. Fix one number, and what's left is pair sum in a sorted array, from [Opposite ends: pair sum and valid palindrome](/dsa/learn/tp-opposite-ends). The same move turns 4Sum into 3Sum, and kSum into (k − 1)Sum. The fiddly part, avoiding duplicate answers, is a skill every "return all the combinations" problem needs.

## The problem

> Given an array of integers, return every **distinct** triplet of values `[a, b, c]`, taken from three different positions, with `a + b + c == 0`.

For `[-2, 0, 1, 1, 2, -1, -4, 2]`, the answer is:

```text
[-4, 2, 2]   [-2, 0, 2]   [-2, 1, 1]   [-1, 0, 1]
```

Two details in that statement shape everything:

- **Values, not positions.** You return the numbers themselves, so you're free to sort the array first.
- **Distinct triplets.** There are two 2s in the input, and `-2 + 0 + 2` could use either one, but `[-2, 0, 2]` appears once in the answer.

## Brute force

Three nested loops try every triple of positions, O(n³). To remove duplicates, sort each triplet and put it in a `Set`, so `[2, -2, 0]` and `[0, 2, -2]` become the same `[-2, 0, 2]`:

```swift run
func threeSumSlowly(_ numbers: [Int]) -> [[Int]] {
    var found = Set<[Int]>()
    let n = numbers.count
    for i in 0..<n {
        for j in (i + 1)..<n {
            for k in (j + 1)..<n where numbers[i] + numbers[j] + numbers[k] == 0 {
                found.insert([numbers[i], numbers[j], numbers[k]].sorted())
            }
        }
    }
    return found.sorted { $0.lexicographicallyPrecedes($1) }
}

print(threeSumSlowly([-2, 0, 1, 1, 2, -1, -4, 2]))
```

```output
[[-4, 2, 2], [-2, 0, 2], [-2, 1, 1], [-1, 0, 1]]
```

A `Set` has no order, so the result is sorted before printing: `lexicographicallyPrecedes` compares two arrays element by element, the way a dictionary orders words.

## Sort, fix one, then pair sum

Sort the array. Then, for each position `i`, look for two values **to its right** that add up to `-nums[i]`. That's pair sum in a sorted range, so two pointers find every such pair in O(n):

```text
sorted:  -4  -2  -1   0   1   1   2   2
          i   L                       R      need L + R = 4
```

- Sum of the three too small: move `left` right.
- Too big: move `right` left.
- Exactly zero: record the triplet, and move **both** pointers, because there may be more pairs for this `i`.

Searching only to the right of `i` means every triplet is found exactly once, from its smallest position. With n choices of `i` and O(n) work for each, the total is **O(n²)**, plus O(n log n) for the sort, which is smaller.

## Skipping duplicates

Sorting puts equal values next to each other, which makes duplicates easy to skip in two places:

1. **The fixed number.** If `nums[i] == nums[i - 1]`, every triplet starting with this value was already found in the previous pass. Skip this `i`.
2. **After a match.** Once you've recorded `[nums[i], nums[left], nums[right]]`, move `left` past every copy of `nums[left]`. Otherwise the next pass would find the same triplet again.

```swift run
func threeSum(_ numbers: [Int]) -> [[Int]] {
    let nums = numbers.sorted()
    var result: [[Int]] = []
    for i in nums.indices {
        if i > 0 && nums[i] == nums[i - 1] {
            continue                          // same fixed value as last time
        }
        if nums[i] > 0 {
            break                             // everything to the right is positive too
        }
        var left = i + 1
        var right = nums.count - 1
        while left < right {
            let sum = nums[i] + nums[left] + nums[right]
            if sum < 0 {
                left += 1
            } else if sum > 0 {
                right -= 1
            } else {
                result.append([nums[i], nums[left], nums[right]])
                left += 1
                right -= 1
                while left < right && nums[left] == nums[left - 1] {
                    left += 1                 // skip copies of the value just used
                }
            }
        }
    }
    return result
}

print(threeSum([-2, 0, 1, 1, 2, -1, -4, 2]))
print(threeSum([0, 0, 0, 0]))
print(threeSum([3, -1, -1, 0, 1, -2, 2]))
print(threeSum([1, 2, 3]))
```

```output
[[-4, 2, 2], [-2, 0, 2], [-2, 1, 1], [-1, 0, 1]]
[[0, 0, 0]]
[[-2, -1, 3], [-2, 0, 2], [-1, -1, 2], [-1, 0, 1]]
[]
```

What to notice:

- **Compare with the previous value, not the next.** `nums[i] == nums[i - 1]` skips an `i` only after its value has had a full pass. Comparing with `nums[i + 1]` would skip the *first* copy, and `[-1, -1, 2]` in the third example would be lost, because it needs both −1s.
- **The early `break`.** Once the fixed number is positive, the two numbers to its right are at least as big, so no sum can reach zero. It's an optimisation, not needed for correctness.
- **The answers come out sorted**, both inside each triplet and in the list, because the array was sorted. That's handy for testing.
- **Skipping on the right too?** You could also move `right` past copies of `nums[right]`. It isn't required: if `left` has moved to a new value and `right` still holds the old one, the sum can't be zero again, so the loop moves `right` on the next pass anyway.

## 4Sum: one more loop

> Return every distinct quadruplet with `a + b + c + d == target`.

Fix **two** numbers with nested loops, then run pair sum on the rest. Each loop skips duplicates of its own value in the same way:

```swift run
func fourSum(_ numbers: [Int], _ target: Int) -> [[Int]] {
    let nums = numbers.sorted()
    let n = nums.count
    var result: [[Int]] = []
    for a in 0..<n {
        if a > 0 && nums[a] == nums[a - 1] { continue }
        for b in (a + 1)..<n {
            if b > a + 1 && nums[b] == nums[b - 1] { continue }
            var left = b + 1
            var right = n - 1
            while left < right {
                let sum = nums[a] + nums[b] + nums[left] + nums[right]
                if sum < target {
                    left += 1
                } else if sum > target {
                    right -= 1
                } else {
                    result.append([nums[a], nums[b], nums[left], nums[right]])
                    left += 1
                    right -= 1
                    while left < right && nums[left] == nums[left - 1] { left += 1 }
                }
            }
        }
    }
    return result
}

print(fourSum([2, -1, 0, 1, -2, 0, 3], 2))
print(fourSum([1, 1, 1, 1, 1], 4))
```

```output
[[-2, -1, 2, 3], [-2, 0, 1, 3], [-1, 0, 0, 3], [-1, 0, 1, 2]]
[[1, 1, 1, 1]]
```

The second loop's skip says `b > a + 1`, not `b > 0`: the first `b` for each `a` must always run, even if it equals `nums[a]`. That's what lets `[1, 1, 1, 1]` use four 1s.

The cost is **O(n³)**: O(n²) pairs of fixed numbers, each with an O(n) pair search. The pattern generalises: kSum fixes k − 2 numbers and costs O(nᵏ⁻¹). A recursive version that peels off one number at a time handles any k, and it's a nice exercise once recursion over arrays feels natural.

<Callout kind="gotcha" title="Swift gotcha: big sums">
With values up to 10⁹, four of them add up to 4 × 10⁹, which overflows a 32-bit integer. Swift's `Int` is 64 bits on every platform you'll use, so it's fine here, but in a language with 32-bit `int`, 4Sum is a classic overflow bug. If you ever use `Int32` to save memory, remember the sums.
</Callout>

## A variation: the closest sum

**3Sum closest** asks for the triplet sum nearest to a target, rather than exactly equal. Same loops, but instead of collecting matches, keep the best sum so far, and stop early if you hit the target exactly:

```swift run
func threeSumClosest(_ numbers: [Int], _ target: Int) -> Int {
    let nums = numbers.sorted()
    var best = nums[0] + nums[1] + nums[2]
    for i in 0..<(nums.count - 2) {
        var left = i + 1
        var right = nums.count - 1
        while left < right {
            let sum = nums[i] + nums[left] + nums[right]
            if abs(sum - target) < abs(best - target) {
                best = sum
            }
            if sum < target {
                left += 1
            } else if sum > target {
                right -= 1
            } else {
                return sum
            }
        }
    }
    return best
}

print(threeSumClosest([4, -3, 1, 9, -6], 5))
```

```output
4
```

There's no duplicate skipping, because only one number is returned. The function assumes at least three numbers; a real solution would check that first.

## Common mistakes

- **Not sorting.** Two pointers need a sorted range. Sorting is allowed because the answer is values, not positions.
- **Skipping with `i + 1`.** Compare each fixed value with the one before it, so the first copy always gets its pass.
- **Stopping after the first match for an `i`.** One fixed number can belong to several triplets. Move both pointers and keep going.
- **Forgetting the inner skip.** Without it, `[-2, 0, 2]` comes out twice for an input with two 2s and two 0s.
