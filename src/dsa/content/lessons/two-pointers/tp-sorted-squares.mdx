## Why it matters

Squaring every number of a sorted array sounds trivial, and the obvious answer, square then sort, is O(n log n). But the input is already sorted, and throwing that away is wasteful. With two pointers you can build the sorted squares in O(n). The lesson behind it is general: when the answer's **extreme** values are easy to find (here, at the two ends), build the answer from the extreme inwards, **filling the result from the back**.

## The problem

> Given an array sorted in non-decreasing order, which may contain negatives, return the squares of its elements, also sorted in non-decreasing order.

| Input | Output |
| --- | --- |
| `[-7, -3, -1, 2, 4, 6]` | `[1, 4, 9, 16, 36, 49]` |
| `[-5, -4, -2]` | `[4, 16, 25]` |
| `[0, 3, 8]` | `[0, 9, 64]` |

## Why squaring breaks the order

If every number were non-negative, squaring would keep the order: bigger numbers have bigger squares. Negative numbers spoil it. −7 is the smallest value, but its square, 49, is the largest. Squaring sorts by **distance from zero**, not by value.

The simplest fix is to square, then sort:

```swift run
let numbers = [-7, -3, -1, 2, 4, 6]
print(numbers.map { $0 * $0 })
print(numbers.map { $0 * $0 }.sorted())
```

```output
[49, 9, 1, 4, 16, 36]
[1, 4, 9, 16, 36, 49]
```

Correct, and O(n log n). The squares in the first line aren't random, though. They go **down** and then **up**: 49, 9, 1, then 4, 16, 36. The negatives give a decreasing run and the rest give an increasing run. The smallest square sits somewhere in the middle, but the **largest** is always at one of the two ends.

## Fill from the back

That suggests the plan:

1. Put `left` at the first element and `right` at the last.
2. The bigger of their two squares is the biggest square left anywhere. Write it into the **last empty slot** of the result.
3. Move that pointer inwards, and step the write position back one slot.
4. Repeat until the pointers cross.

```swift run
func sortedSquares(_ sorted: [Int]) -> [Int] {
    var result = Array(repeating: 0, count: sorted.count)
    var left = 0
    var right = sorted.count - 1
    var write = sorted.count - 1             // the next slot to fill, from the back
    while left <= right {
        let leftSquare = sorted[left] * sorted[left]
        let rightSquare = sorted[right] * sorted[right]
        if leftSquare > rightSquare {
            result[write] = leftSquare
            left += 1
        } else {
            result[write] = rightSquare
            right -= 1
        }
        write -= 1
    }
    return result
}

print(sortedSquares([-7, -3, -1, 2, 4, 6]))
print(sortedSquares([-5, -4, -2]))
print(sortedSquares([0, 3, 8]))
print(sortedSquares([-2, -2, 2]))
print(sortedSquares([]))
```

```output
[1, 4, 9, 16, 36, 49]
[4, 16, 25]
[0, 9, 64]
[4, 4, 4]
[]
```

Here's the first example, step by step:

| `left` | `right` | squares compared | written | at slot |
| --- | --- | --- | --- | --- |
| 0 (−7) | 5 (6) | 49 vs 36 | 49 | 5 |
| 1 (−3) | 5 (6) | 9 vs 36 | 36 | 4 |
| 1 (−3) | 4 (4) | 9 vs 16 | 16 | 3 |
| 1 (−3) | 3 (2) | 9 vs 4 | 9 | 2 |
| 2 (−1) | 3 (2) | 1 vs 4 | 4 | 1 |
| 2 (−1) | 2 (−1) | 1 vs 1 | 1 | 0 |

Each element is written exactly once: **O(n) time**. Apart from the result itself, it uses three integers: O(1) extra space.

What to notice:

- **`left <= right`, not `left < right`.** In pair sum, the pointers stopped before meeting because an element can't pair with itself. Here, every element must be written, including the last one, when both pointers sit on it. With `<`, the smallest square is never written and slot 0 keeps its placeholder 0.
- **Ties don't matter.** When the two squares are equal, as with −2 and 2, either can go first: the values written are the same.
- **Why the back?** The smallest square is somewhere in the middle, and finding it would mean searching. The largest is always at one of the two ends, where the pointers already are.

## Another way: merge outwards

You could also find where the negatives end, then walk outwards from that point with one pointer going left through the negatives and one going right through the rest. Both runs of squares increase as you move away from zero, so you merge two sorted runs, like merging two sorted arrays in [Merge sorted arrays](/dsa/learn/arrays-merge-sorted). It's also O(n), but finding the starting point and handling the edges takes more code. Filling from the back needs no starting point at all.

The fill-from-the-back trick appears elsewhere too. When you merge two sorted arrays **in place**, into the first array that has spare room at its end, you also fill from the back, so you never overwrite an element you haven't used yet.

<Callout kind="gotcha" title="Swift gotcha: squares can overflow">
`x * x` overflows when `x` is beyond about ±3 × 10⁹, and Swift stops the program rather than giving a wrong answer. The problem's constraints keep the values small, so it's not an issue here. Note also that `abs(Int.min)` itself traps, because `Int.min` has no positive counterpart. Comparing squares, as above, sidesteps `abs` entirely.
</Callout>
