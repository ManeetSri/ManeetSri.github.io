## Why it matters

In pair sum, sorting told you which pointer to move. Container with most water has no sorting at all, yet two pointers still solve it in O(n). The reason is a short, satisfying proof, and learning to make that kind of argument is the real skill here. Interviewers love this problem precisely because the code is ten lines and the question "why is that correct?" separates people who memorised it from people who understand it.

## The problem

> You're given the heights of vertical walls standing at positions 0, 1, 2, …, in a row. Choose two walls. Together with the ground, they hold water up to the height of the **shorter** wall, across the distance between them. Return the most water any two walls can hold.

For walls at positions `i` and `j`, with `i < j`:

> water = `min(heights[i], heights[j]) × (j − i)`

The walls in between don't get in the way. Only the two you choose matter.

For `[3, 7, 2, 5, 4, 8, 3, 6]`, the best pair is the walls at positions 1 (height 7) and 7 (height 6): `min(7, 6) × 6 = 36`.

## Brute force

Every pair, O(n²):

```swift run
func mostWaterSlowly(_ heights: [Int]) -> Int {
    var best = 0
    for i in heights.indices {
        for j in (i + 1)..<heights.count {
            best = max(best, min(heights[i], heights[j]) * (j - i))
        }
    }
    return best
}

print(mostWaterSlowly([3, 7, 2, 5, 4, 8, 3, 6]))
```

```output
36
```

For 100,000 walls that's about 5 × 10⁹ pairs. Too slow, but it's the oracle you'll test the fast version against. (Notice `(i + 1)..<heights.count`: when `i` is the last index, that's an empty range, not a crash.)

## Start wide, move the shorter wall

Start with the **widest** container: the first wall and the last wall. Every other container is narrower. To have any chance of holding more, a narrower container must be **taller**.

Now the decision: which wall do you give up? The water level is set by the shorter wall. Moving the taller wall inwards can't raise the level above the shorter one, and it makes the container narrower, so it can only do worse. Moving the shorter wall is the only move that might find a taller wall and raise the level.

```swift run
func mostWater(_ heights: [Int]) -> Int {
    var left = 0
    var right = heights.count - 1
    var best = 0
    while left < right {
        let water = min(heights[left], heights[right]) * (right - left)
        print("left \(left) (height \(heights[left])), right \(right) (height \(heights[right])): water \(water)")
        best = max(best, water)
        if heights[left] < heights[right] {
            left += 1
        } else {
            right -= 1
        }
    }
    return best
}

print(mostWater([3, 7, 2, 5, 4, 8, 3, 6]))
```

```output
left 0 (height 3), right 7 (height 6): water 21
left 1 (height 7), right 7 (height 6): water 36
left 1 (height 7), right 6 (height 3): water 15
left 1 (height 7), right 5 (height 8): water 28
left 2 (height 2), right 5 (height 8): water 6
left 3 (height 5), right 5 (height 8): water 10
left 4 (height 4), right 5 (height 8): water 4
36
```

## Why it never skips the best container

The intuition above is good, but "can only do worse" needs a proof. Here it is.

Suppose `heights[left] ≤ heights[right]`, so the algorithm discards `left`. Think about **every** container that uses wall `left` with some other wall `k` that's still in play, so `left < k ≤ right`:

1. **Its width** is `k − left`, which is at most `right − left`, the current width.
2. **Its height** is `min(heights[left], heights[k])`, which is at most `heights[left]`, and that's the current height, because `left` is the shorter wall.

Smaller or equal width, smaller or equal height: none of those containers can beat the one just measured. So wall `left` has already been paired with its best remaining partner, and dropping it can't lose the answer. The case `heights[right] < heights[left]` is the mirror image.

Every step discards one wall whose best container has already been measured. After n − 1 steps every wall is gone, so the best container overall must have been measured along the way.

<Callout kind="analogy">
Think of the shorter wall as the weakest link. As long as it's in the container, the water can't rise above it. Keeping it and moving the other wall only makes the container narrower around the same weak link.
</Callout>

## Moving the taller wall really does fail

It's worth seeing the wrong choice go wrong. Here are both strategies on `[2, 9, 9, 3]`, where the best container is the two 9s, side by side, holding 9:

```swift run
func mostWater(_ heights: [Int], moveShorter: Bool) -> Int {
    var left = 0
    var right = heights.count - 1
    var best = 0
    while left < right {
        best = max(best, min(heights[left], heights[right]) * (right - left))
        let leftIsShorter = heights[left] < heights[right]
        if leftIsShorter == moveShorter {
            left += 1
        } else {
            right -= 1
        }
    }
    return best
}

print("move the shorter wall:", mostWater([2, 9, 9, 3], moveShorter: true))
print("move the taller wall: ", mostWater([2, 9, 9, 3], moveShorter: false))
```

```output
move the shorter wall: 9
move the taller wall:  6
```

Moving the taller wall keeps the height-2 wall forever, so every container it measures is at most 2 high, and the pair of 9s is never measured together.

## What about equal heights?

When `heights[left] == heights[right]`, the code above moves `right`, and that's fine. Apply the proof to either wall: every other container using it is no wider and no taller than the current one. So either can go. Some solutions move both at once, which is also correct.

<Callout kind="gotcha" title="Common mistakes">
- **Measuring the walls in between.** The water depends only on the two chosen walls. Don't take a minimum over the whole range: that's a different problem, trapping rain water, later in this module.
- **Off-by-one width.** The width is `right − left`, not `right − left + 1`. Two walls next to each other are 1 apart.
- **Moving the taller wall.** It looks harmless and gives the right answer on many examples, but it isn't correct, as `[2, 9, 9, 3]` shows. Test against the brute force.
</Callout>
