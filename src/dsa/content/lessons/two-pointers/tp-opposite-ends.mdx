## Why it matters

Many array and string problems ask about **pairs**: two values that add up to something, or two characters that should match. Checking every pair is O(n²). When the data has the right shape, usually sorted, two indexes that start at **opposite ends** and walk towards each other check everything that matters in a single O(n) pass, with O(1) extra memory. It's the first of three pointer patterns in this module, and you've already used it: reversing an array in place in [inout, swap and swapAt](/dsa/learn/swift-inout-swap) is two pointers from opposite ends.

## The shape of the pattern

Every opposite-ends algorithm has the same skeleton:

```swift
var left = 0
var right = items.count - 1
while left < right {
    // look at items[left] and items[right]
    // then move left forward, right backward, or both
}
```

- `left` starts at the first index and only moves right. `right` starts at the last index and only moves left.
- The loop stops when they meet, so together they take at most n steps: **O(n)**.
- The skill is in the middle: deciding, from only two elements, **which pointer can safely move**.

When you reverse an array, both pointers move every time, because each pair is finished once it's swapped. The interesting problems are the ones where you move only one.

## Pair sum in a sorted array

> Given a **sorted** array and a target, find two different positions whose values add up to the target.

The brute force tries every pair, O(n²). A `Set` of values seen so far would take O(n) time but O(n) extra space. Sorting gives you a better option.

Put `left` at the smallest value and `right` at the largest, and look at their sum:

- **Equal to the target:** done.
- **Too small:** the only way to get a bigger sum is a bigger value, so move `left` right.
- **Too big:** you need a smaller value, so move `right` left.

Step through it. Watch which pointer moves, and why:

```visual arrayTrace

input:
  items: [1, 3, 4, 6, 8, 11, 14]
  target: 14
```

```swift run
func pairWithSum(_ items: [Int], _ target: Int) -> (Int, Int)? {
    var left = 0
    var right = items.count - 1
    while left < right {
        let sum = items[left] + items[right]
        if sum == target {
            return (left, right)
        } else if sum < target {
            left += 1
        } else {
            right -= 1
        }
    }
    return nil
}

let items = [1, 3, 4, 6, 8, 11, 14]
for target in [14, 19, 2] {
    if let (i, j) = pairWithSum(items, target) {
        print("target \(target): items[\(i)] + items[\(j)] = \(items[i]) + \(items[j])")
    } else {
        print("target \(target): no pair")
    }
}
```

```output
target 14: items[1] + items[5] = 3 + 11
target 19: items[4] + items[5] = 8 + 11
target 2: no pair
```

O(n) time, O(1) extra space. Target 2 shows the pointers meeting without a match: `1 + 3` is already too big, so `right` walks all the way down.

## Why moving one pointer is safe

The worry with any pointer algorithm is: did we skip the answer? Here's the argument for the "too small" case.

Suppose `items[left] + items[right]` is less than the target. `items[right]` is the largest value still in play, because everything to its right was already ruled out. So `items[left]` plus **any** remaining partner is at most this sum, which is too small. `items[left]` can't be part of any answer, so dropping it loses nothing.

The "too big" case is the mirror image: `items[left]` is the smallest value still in play, so `items[right]` plus anything is too big, and `items[right]` can go.

Each step **eliminates one element** that provably can't be in a solution. That's the whole secret of two pointers, and [Why two pointers work](/dsa/learn/tp-why-it-works) at the end of this module looks at it as a picture.

<Callout kind="note">
This only works because the array is **sorted**. On `[8, 1, 14, 3]`, the left pointer's value isn't the smallest in play, so "too small, move left" might throw away the very value you need. For an unsorted array, either sort it first (if you only need the values, not their original positions) or use a dictionary of values you've seen, which M24 covers.
</Callout>

## Valid palindrome, skipping what doesn't count

A palindrome reads the same both ways, so it's a natural two-pointer problem: compare the first character with the last, the second with the second-to-last, and so on. Real text adds a twist. In `"Step on no pets!"`, the spaces, the capital S and the `!` shouldn't count.

In M08's [Letters-only palindrome](/dsa/practice/letter-palindrome) problem, you first built a cleaned-up array of letters, then compared. Two pointers can skip the characters that don't count **as they go**, with no cleaned copy at all:

```swift run
func isPalindrome(_ text: String) -> Bool {
    let characters = Array(text)
    var left = 0
    var right = characters.count - 1
    while left < right {
        let a = characters[left]
        let b = characters[right]
        if !(a.isLetter || a.isNumber) {
            left += 1                      // skip it, and look again
        } else if !(b.isLetter || b.isNumber) {
            right -= 1
        } else if a.lowercased() != b.lowercased() {
            return false
        } else {
            left += 1
            right -= 1
        }
    }
    return true
}

for text in ["Step on no pets!", "Was it a rat I saw?", "No lemon, no melon", "Swift", "", "1a2"] {
    print("\"\(text)\":", isPalindrome(text))
}
```

```output
"Step on no pets!": true
"Was it a rat I saw?": true
"No lemon, no melon": true
"Swift": false
"": true
"1a2": false
```

What to notice:

- **`Array(text)` first.** Swift strings can't be indexed by an `Int`, as [String.Index and why s[i] does not exist](/dsa/learn/swift-string-index) explained. An array of `Character`s gives O(1) access by position.
- **One step per pass.** Each pass of the loop does exactly one thing: skip on the left, skip on the right, fail, or match both. Because the `while left < right` check runs before every step, a skip can never run past the other pointer.
- **Lowercasing.** `Character` has `lowercased()`, which returns a `String`, so `"S".lowercased() == "s".lowercased()` compares `"s"` with `"s"`. The character properties come from [Character properties and asciiValue](/dsa/learn/swift-character-properties).
- **Edge cases for free.** For an empty string, `right` is `-1`, the loop never runs, and the answer is `true`. With an odd count, the middle character is never compared with anything, which is right: it matches itself.

<Callout kind="gotcha" title="Inner skip loops need their own bounds check">
A common way to write the skipping is with inner loops: `while !characters[left].isLetter { left += 1 }`. On text like `"!!!"`, that runs straight off the end of the array and crashes with an index out of range. If you use inner loops, every one needs `left < right` in its condition too: `while left < right && !characters[left].isLetter`. The one-step-per-pass version above avoids the problem entirely.
</Callout>

## Common mistakes

- **`left <= right` instead of `left < right`.** For pair sum, `left == right` would pair an element with itself. For palindromes, it compares the middle character with itself, which is harmless but pointless.
- **Moving the wrong pointer.** Sum too small means *increase* it: move `left` towards the bigger values. Write the reason next to each branch until it's automatic.
- **Forgetting the precondition.** Opposite-end pair sum needs sorted input. If the problem doesn't promise it, you have to sort, or pick a different technique.
