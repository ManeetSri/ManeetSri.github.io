## Why it matters

"Given a stock's daily prices, what's the most you could have made?" is a family of interview questions, and the family is the point. Each member adds one rule: one trade only, as many as you like, at most two, a cooldown after selling, a fee per trade. The first two have short, clever answers. This lesson solves them that way, then solves them **again** with a tiny state machine: two numbers per day. The clever answers don't stretch to the harder rules. The state machine does, and the rest of this module is built on it.

## The rules

You have a list of daily prices. On any day you may buy one share (if you hold none) or sell the share you hold. You can't sell before you buy, and you hold at most one share at a time. Profit is what you sell for minus what you paid. Doing nothing is allowed, so the answer is never negative.

## Stock I: one trade

With exactly one buy and one later sell, the best trade sells on some day at `price`, having bought at the **cheapest price on any earlier day** (or the same day, for no profit). So walk through the days keeping the cheapest price so far, and ask each day: "if I sold today, what would I make?"

```swift run
func bestSingleTrade(_ prices: [Int]) -> Int {
    var cheapest = Int.max      // the lowest price seen so far: the best day to have bought
    var best = 0                // no trade at all is allowed, so profit never goes below 0
    for (day, price) in prices.enumerated() {
        cheapest = min(cheapest, price)
        best = max(best, price - cheapest)          // sell today, having bought at the cheapest
        print("day \(day): price \(price), cheapest \(cheapest), best \(best)")
    }
    return best
}

print(bestSingleTrade([9, 4, 7, 2, 8, 5]))
```

```output
day 0: price 9, cheapest 9, best 0
day 1: price 4, cheapest 4, best 0
day 2: price 7, cheapest 4, best 3
day 3: price 2, cheapest 2, best 3
day 4: price 8, cheapest 2, best 6
day 5: price 5, cheapest 2, best 6
6
```

Buy at 2, sell at 8. O(n) time, O(1) memory. Two details:

- `cheapest` is updated **before** computing today's profit, so `price - cheapest` is never negative and never overflows (`Int.max` is replaced on day 0).
- The highest price (9) comes before the lowest (2), so "max minus min" would be wrong. Order matters, and the running minimum respects it.

This is the same answer as the maximum subarray of the **daily changes**, which [Kadane's maximum subarray](/dsa/learn/arrays-kadane) mentioned: a trade from day i to day j earns the sum of the changes between them.

## Stock II: as many trades as you like

Now you can trade any number of times, still holding at most one share, and you may sell and buy again on the same day. The answer is surprisingly simple: **bank every rise**. Whenever tomorrow's price is higher than today's, add the difference.

```swift run
func bestManyTrades(_ prices: [Int]) -> Int {
    var profit = 0
    for day in prices.indices.dropFirst() where prices[day] > prices[day - 1] {
        profit += prices[day] - prices[day - 1]      // bank every rise
    }
    return profit
}

print(bestManyTrades([9, 4, 7, 2, 8, 5]))
print(bestManyTrades([1, 2, 3, 4, 5]))
print(bestManyTrades([6, 5, 4]))
print(bestManyTrades([]))
```

```output
9
4
0
0
```

Why is that the best? Any single trade, buy on day i and sell on day j, earns `prices[j] − prices[i]`, which is the sum of the daily changes from i to j. Some of those changes may be negative. Taking only the **positive** daily changes, each as its own one-day trade, earns at least as much as any plan, since a plan's profit is a sum of daily changes over the days it holds a share, and dropping the negative ones can only help. And it's achievable: buy before each rise, sell after it.

This is a greedy argument, like the ones in [The greedy choice property](/dsa/learn/greedy-idea). Notice what it relies on: trades are free and unlimited. On `[1, 2, 3, 4, 5]` it banks four rises of 1, the same as one trade from 1 to 5. Add a fee per trade and that's four fees instead of one, and the greedy breaks. Limit the number of trades and it breaks too.

## The same two answers as a state machine

Here's a way of thinking that survives every rule change. At the end of each day you are in one of two **states**:

- **hold**: you own a share;
- **free**: you own nothing.

Keep, for each state, the **best profit you could have so far while ending today in that state**. (Profit while holding counts the purchase price as spent, so it's usually negative.) Each day, every state is reached from yesterday's states by one action:

- **free today**: you were free and did nothing, or you held and **sold** at today's price.
- **hold today**: you held and did nothing, or you were free and **bought** at today's price.

```swift run
// Two states at the end of each day: holding a share, or free (holding nothing)
func trades(_ prices: [Int], unlimited: Bool) -> Int {
    var hold = Int.min / 2     // best profit while holding: impossible before day 0
    var free = 0               // best profit while holding nothing
    for price in prices {
        let freeYesterday = free
        free = max(free, hold + price)                                // rest, or sell
        hold = max(hold, (unlimited ? freeYesterday : 0) - price)     // keep, or buy
    }
    return free
}

for prices in [[9, 4, 7, 2, 8, 5], [1, 2, 3, 4, 5], [6, 5, 4]] {
    print(prices, "once:", trades(prices, unlimited: false), "many:", trades(prices, unlimited: true))
}
```

```output
[9, 4, 7, 2, 8, 5] once: 6 many: 9
[1, 2, 3, 4, 5] once: 4 many: 4
[6, 5, 4] once: 0 many: 0
```

The only difference between Stock I and Stock II is **what a buy starts from**:

- With unlimited trades, you buy using whatever profit you've banked: `freeYesterday - price`.
- With one trade, a buy must be your first and only one, so it starts from zero profit: `0 - price`. Selling still moves you to free, but because no later buy uses that profit, there's never a second trade.

What to notice:

- `hold` starts at `Int.min / 2`, meaning "impossible": you can't own a share before day 0. Half of `Int.min` leaves room to add a price without overflowing; `Int.min + price` would be fine but `Int.min - price` would crash, and halving is the habit that always works.
- The answer is `free`, never `hold`: ending with an unsold share is never better than not buying it.
- `freeYesterday` makes every update read **yesterday's** values. For Stock II it happens not to matter (selling and rebuying on the same day earns nothing), but in the next lessons it does, so it's worth doing from the start.

Two states, two arrows into each, O(n) time and O(1) memory. The next lesson turns this into a method: draw the states, draw the arrows, and the code writes itself.

<Callout kind="gotcha" title="Common mistakes">
- **Max minus min.** The highest price may come before the lowest. Use the running minimum.
- **Starting `hold` at 0.** That claims you own a share for free. Use a large negative value, or `-prices[0]` after checking the array isn't empty.
- **Returning `max(hold, free)`.** An unsold share is worth nothing to the answer. Return `free`.
- **Empty or one-day input.** No trade is possible: the answer is 0. All three versions above handle it.
</Callout>
