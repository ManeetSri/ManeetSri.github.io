## Why it matters

State machines aren't only about money. Colouring a row of houses so that no two neighbours match is a machine whose states are the colours. Cleaning up a binary string so that all its 0s come before its 1s is a machine with two states, "still in the 0s" and "into the 1s". The first problem also teaches a trick that turns O(n · k²) into O(n · k): when every state needs "the best of all the **other** states", keep just the best and the second best.

## Paint house

A street has n houses in a row, and k paint colours. Painting house i with colour c costs `costs[i][c]`. No two neighbouring houses may have the same colour. What's the cheapest way to paint them all?

Greedy (the cheapest colour for each house in turn) fails quickly. With costs `[[1, 2], [1, 10]]`, greedy paints house 0 colour 0 for 1, which forces colour 1 on house 1 for 10: total 11. Painting house 0 colour 1 for 2 and house 1 colour 0 for 1 costs 3.

### The machine

The state is **the colour of the current house**. From any colour you can move to any other colour, but not to the same one: k states, and every arrow exists except the self-loops. Reading off the arrows:

> `best[i][c] = costs[i][c] + min` of `best[i − 1][d]` over every colour d ≠ c

| Step | Paint house |
| --- | --- |
| State | `best[i][c]` = the cheapest way to paint houses 0...i with house i in colour c |
| Transition | `costs[i][c]` + the cheapest previous colour other than c |
| Base case | `best[0][c] = costs[0][c]` |
| Order | house by house |
| Answer | the minimum of the last house's row |

Done literally, each of the k colours scans the k previous colours: O(k²) per house, O(n · k²) in total.

### Best and second best

Here's the observation. For colour c, "the cheapest previous colour other than c" is:

- the **cheapest** previous colour, unless that cheapest colour **is** c;
- in which case, the **second cheapest**.

So scan the previous house once to find the lowest total, which colour gave it, and the second-lowest total. Then each colour's update is O(1):

```swift run
let costs = [
    [7, 3, 8, 6],
    [5, 6, 2, 9],
    [4, 9, 6, 5],
    [8, 1, 7, 3],
]

// O(n · k²): for each colour, look at every other colour of the previous house
func cheapestSlow(_ costs: [[Int]]) -> Int {
    var previous = costs[0]
    for house in costs.dropFirst() {
        previous = house.indices.map { colour in
            house[colour] + previous.indices.filter { $0 != colour }.map { previous[$0] }.min()!
        }
    }
    return previous.min()!
}

// O(n · k): only the cheapest and second cheapest of the previous house can ever be needed
func cheapestFast(_ costs: [[Int]]) -> Int {
    var previous = costs[0]
    for house in costs.dropFirst() {
        var lowest = Int.max, secondLowest = Int.max, lowestColour = -1
        for (colour, total) in previous.enumerated() {
            if total < lowest {
                (secondLowest, lowest, lowestColour) = (lowest, total, colour)
            } else if total < secondLowest {
                secondLowest = total
            }
        }
        previous = house.enumerated().map { colour, cost in
            cost + (colour == lowestColour ? secondLowest : lowest)
        }
        print(previous)
    }
    return previous.min()!
}

print(cheapestSlow(costs))
print(cheapestFast(costs))
```

```output
10
[8, 12, 5, 12]
[9, 14, 14, 10]
[18, 10, 16, 12]
10
```

Each printed row is one house's `best`. The cheapest painting costs 10: colour 1 (3), colour 2 (2), colour 0 (4), colour 1 (1).

What to notice:

- **Ties are fine.** If two colours share the lowest total, the second-lowest equals the lowest, so whichever colour is recorded as `lowestColour` still gets the right value from the other.
- **One colour is a trap.** With k = 1, `secondLowest` stays `Int.max`, and `cost + Int.max` crashes. With one colour, two or more houses can't be painted at all; check for that before the loop.
- The cost is O(n · k) time and O(k) memory: one scan of the previous row, then one pass to build the new row.

The same "best and second best" trick answers any DP whose transition says "the best of every other state": a falling path that must change column every row, choosing a different supplier from last month, and so on.

## Monotone flips

A string of `0`s and `1`s. You may flip any character (0 to 1 or 1 to 0). What's the fewest flips that makes the string **monotone increasing**, meaning every `0` comes before every `1`? For example `00110` needs one flip (its last character, giving `00111`), and `11100` needs two (its two 0s, giving `11111`). All 0s or all 1s count as monotone.

### Two states

Read the string left to right. A monotone result is some 0s, then some 1s. At each character you're in one of two states:

- **zeros**: everything so far has become `0`;
- **ones**: you've already switched to the `1`s part.

From zeros you can stay in zeros or switch to ones. From ones you can only stay in ones: there's no arrow back, because a `0` after a `1` is exactly what's forbidden. Each arrow costs one flip if the character doesn't match the state it lands in:

```text
   stay: +1 if "1"                      stay: +1 if "0"
    ┌────────┐                           ┌────────┐
    │        ▼     switch: +1 if "0"     │        ▼
  ┌────────────┐ ──────────────────────▶ ┌────────────┐
  │   zeros    │                         │    ones    │
  └────────────┘                         └────────────┘
```

Reading off the arrows into each state:

- `zeros = zeros + (1 if the character is "1")`
- `ones = min(zeros, ones) + (1 if the character is "0")`

```swift run
func traceFlips(_ bits: String) {
    var zeros = 0, ones = 0
    print("start: zeros \(zeros), ones \(ones)")
    for bit in bits {
        let (oldZeros, oldOnes) = (zeros, ones)
        zeros = oldZeros + (bit == "1" ? 1 : 0)
        ones = min(oldZeros, oldOnes) + (bit == "0" ? 1 : 0)
        print("\(bit): zeros \(zeros), ones \(ones)")
    }
}

traceFlips("010110")
```

```output
start: zeros 0, ones 0
0: zeros 0, ones 1
1: zeros 1, ones 0
0: zeros 1, ones 1
1: zeros 2, ones 1
1: zeros 3, ones 1
0: zeros 3, ones 2
```

The answer is `min(zeros, ones)` at the end: 2 (for instance `000111`, flipping the second and last characters). Both states start at 0, since the empty string is monotone in either form.

A compact version without the snapshot, since in each branch only one line reads a changed value:

```swift run
func minimumFlips(_ bits: String) -> Int {
    var zeros = 0    // fewest flips so far if everything so far becomes 0
    var ones = 0     // fewest flips so far if we've already switched to the 1s part
    for bit in bits {
        if bit == "0" {
            ones = min(zeros, ones) + 1     // a 0 in the 1s part must flip
        } else {
            ones = min(zeros, ones)         // switch here, or stay: this 1 is fine
            zeros += 1                      // a 1 in the 0s part must flip
        }
    }
    return min(zeros, ones)
}

for bits in ["00110", "010110", "11100", "0000", ""] {
    print("\"\(bits)\"", minimumFlips(bits))
}
```

```output
"00110" 1
"010110" 2
"11100" 2
"0000" 0
"" 0
```

In the `"1"` branch, `ones` is updated **before** `zeros` changes, so it reads yesterday's `zeros`. Swap those two lines and it breaks. The snapshot version is safer while you're learning.

### A second view: try every split

A monotone result is decided by where the 1s start. For each split position, the flips needed are the 1s **before** the split (they must become 0) plus the 0s **after** it (they must become 1). Keeping running counts gives every split in one pass, like the prefix sums in [1D prefix sums and range queries](/dsa/learn/prefix-1d):

```swift run
// Try every split: 0s before position `split`, 1s from there on
func minimumFlipsBySplit(_ bits: String) -> Int {
    let digits = Array(bits)
    var onesBefore = 0                                   // 1s left of the split must become 0
    var zerosAfter = digits.filter { $0 == "0" }.count   // 0s right of the split must become 1
    var best = zerosAfter                                // split at 0: everything becomes 1
    for digit in digits {
        if digit == "1" {
            onesBefore += 1
        } else {
            zerosAfter -= 1
        }
        best = min(best, onesBefore + zerosAfter)
    }
    return best
}

for bits in ["00110", "010110", "11100", "0000", ""] {
    print("\"\(bits)\"", minimumFlipsBySplit(bits))
}
```

```output
"00110" 1
"010110" 2
"11100" 2
"0000" 0
"" 0
```

Same answers, also O(n). The two views are the same computation seen differently: the machine's `ones` state is the best split so far, and its `zeros` state is the running count of 1s. Having two methods is useful for testing one against the other.

<Callout kind="gotcha" title="Swift gotchas">
- **Iterate characters, not indexes.** `for bit in bits` gives each `Character`; `bits[i]` with an `Int` doesn't compile, because Swift strings aren't indexed by integers.
- **Compare with `"0"` and `"1"`.** Those are `Character` literals here, not the numbers 0 and 1.
- **Paint house with one colour.** `Int.max` as the second best overflows when added. Handle k = 1 separately.
- **Paint house with no houses.** `costs[0]` crashes on an empty array; return 0 first.
</Callout>

**Paint the houses** has many colours, so the O(n · k²) version is too slow for its biggest tests. **Fewest flips to sort a switch row** is monotone flips: solve it with the machine, and use the split method to check.
