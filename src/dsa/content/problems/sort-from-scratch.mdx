Sort an array of integers into increasing order, in O(n log n) time, **without** the standard library's `sort()` or `sorted()` and without DSAKit's sorts. Merge sort and quick sort are both fine.

`SortFromScratch.sorted(_ numbers: [Int]) -> [Int]`

Return a new array. The tests include 100,000 numbers that are already sorted, reversed, all equal, or only two different values, so the sort must stay fast on all of them.

## Examples

| `numbers` | Returns |
| --- | --- |
| `[5, 2, 9, 1, 5, 6]` | `[1, 2, 5, 5, 6, 9]` |
| `[3, -1, 0, -7, 3]` | `[-7, -1, 0, 3, 3]` |
| `[4, 3, 2, 1]` | `[1, 2, 3, 4]` |
| `[2, 2, 2]` | `[2, 2, 2]` |
| `[7]` | `[7]` |
| `[]` | `[]` |

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- Any `Int` values, including `Int.min` and `Int.max`, with duplicates.
- O(n log n) time: an O(n²) sort such as insertion sort takes billions of steps on the large tests.

<Hints>
<Hint>
Merge sort is the safe choice: O(n log n) on every input. Sort the left half, sort the right half, then merge the two sorted halves by repeatedly taking the smaller front element.
</Hint>
<Hint>
Recurse on index ranges `low..<high` of one array instead of slicing out copies. Make one scratch buffer the size of the array at the start, and let every merge use the part of it that matches its range.
</Hint>
<Hint>
If you choose quick sort, a fixed pivot (first or last element) makes sorted input O(n²), and a two-way partition makes 100,000 equal values O(n²) too. Use a random pivot and a three-way partition: smaller, equal, larger.
</Hint>
</Hints>

## Solutions

<Approach title="Top-down merge sort with one buffer" time="O(n log n)" space="O(n)">

There are about log₂ n levels of halving, and the merges on each level touch every element once. The buffer is made once and shared, so the only allocations are the result and the buffer. Checking whether the halves are already in order across the middle skips the merge entirely, which makes sorted input O(n).

```swift
public enum SortFromScratch {
    public static func sorted(_ numbers: [Int]) -> [Int] {
        var items = numbers
        var buffer = numbers                             // scratch space for every merge
        mergeSort(&items, &buffer, 0, items.count)
        return items
    }

    /// Sorts items[low..<high].
    private static func mergeSort(_ items: inout [Int], _ buffer: inout [Int], _ low: Int, _ high: Int) {
        guard high - low > 1 else { return }
        let mid = low + (high - low) / 2
        mergeSort(&items, &buffer, low, mid)
        mergeSort(&items, &buffer, mid, high)
        if items[mid - 1] <= items[mid] { return }       // already in order: nothing to merge
        for index in low..<high {
            buffer[index] = items[index]
        }
        var left = low
        var right = mid
        for write in low..<high {
            if right == high || (left < mid && buffer[left] <= buffer[right]) {
                items[write] = buffer[left]              // ties take the left value: stable
                left += 1
            } else {
                items[write] = buffer[right]
                right += 1
            }
        }
    }
}
```

</Approach>

<Approach title="Quick sort with random pivots and three-way partitioning" time="O(n log n) expected" space="O(log n)">

A random pivot makes the O(n²) worst case astronomically unlikely on any input, including sorted input. The three-way partition puts every copy of the pivot in its final place at once, so 100,000 equal values take a single pass. Recursing into the smaller side and looping on the larger keeps the recursion depth at O(log n).

```swift
public enum SortFromScratch {
    public static func sorted(_ numbers: [Int]) -> [Int] {
        var items = numbers
        quickSort(&items, 0, items.count)
        return items
    }

    /// Sorts items[low..<high].
    private static func quickSort(_ items: inout [Int], _ low: Int, _ high: Int) {
        var low = low
        var high = high
        while high - low > 1 {
            let pivot = items[Int.random(in: low..<high)]
            var less = low, scan = low, greater = high
            while scan < greater {
                if items[scan] < pivot {
                    items.swapAt(less, scan)
                    less += 1
                    scan += 1
                } else if items[scan] > pivot {
                    greater -= 1
                    items.swapAt(scan, greater)
                } else {
                    scan += 1
                }
            }
            // low..<less is smaller, less..<greater equal (done), greater..<high larger
            if less - low < high - greater {
                quickSort(&items, low, less)
                low = greater
            } else {
                quickSort(&items, greater, high)
                high = less
            }
        }
    }
}
```

</Approach>
