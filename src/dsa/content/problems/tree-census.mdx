Count the nodes in a binary tree, count its leaves, and find how deep a given value sits. Three small questions that use the vocabulary from the lesson, and three short recursions.

`TreeCensus.size(_ root: TreeNode?) -> Int`, `TreeCensus.leaves(_ root: TreeNode?) -> Int` and `TreeCensus.depth(of value: Int, in root: TreeNode?) -> Int?`

A leaf is a node with no children. Depth is measured in edges from the root, so the root has depth 0, its children depth 1, and so on. `depth(of:in:)` returns `nil` when no node holds the value. Write `size` yourself rather than calling DSAKit's `count`.

## Examples

Trees are written in level order, as `TreeNode.make` reads them.

| Tree | `size` | `leaves` | `depth(of:)` |
| --- | --- | --- | --- |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `7` | `3` (4, 7 and 6) | of 7: `3` |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `7` | `3` | of 1: `0` |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `7` | `3` | of 9: `nil` |
| `[1, nil, 2, nil, 3, nil, 4]` | `4` | `1` | of 4: `3` |
| `[42]` | `1` | `1` | of 42: `0` |
| `[]` (the empty tree) | `0` | `0` | of 1: `nil` |

In the first tree, 5 has a child (7), so it isn't a leaf, even though 4 and 6 on the same level are. A single node is both the root and a leaf.

## Constraints

- `0 ≤` number of nodes `≤ 131,071`
- Trees in the tests are at most 500 levels deep, so recursion is fine.
- Values are distinct.

<Hints>
<Hint>
Every answer for a tree is built from the answers for its two subtrees. For size: an empty tree has 0 nodes; otherwise it's 1 for the root plus the sizes of the left and right subtrees.
</Hint>
<Hint>
For leaves, the empty tree has none, and a node whose `left` and `right` are both `nil` is exactly one leaf. Any other node: add up its subtrees' leaves. Don't count the root itself in that case.
</Hint>
<Hint>
For depth, if the root holds the value, the answer is 0. Otherwise look in the left subtree, then the right. If the value is found at depth d inside a subtree, it's at depth d + 1 from here. The `??` operator chains the two searches neatly.
</Hint>
</Hints>

## Solutions

<Approach title="Recursion on the subtrees" time="O(n)" space="O(h)">

Each function handles the empty tree first, then combines the answers from the two subtrees. Every node is visited once, and the recursion is as deep as the tree is tall.

```swift
public enum TreeCensus {
    public static func size(_ root: TreeNode?) -> Int {
        guard let root else { return 0 }
        return 1 + size(root.left) + size(root.right)
    }

    public static func leaves(_ root: TreeNode?) -> Int {
        guard let root else { return 0 }
        if root.left == nil && root.right == nil {
            return 1
        }
        return leaves(root.left) + leaves(root.right)
    }

    public static func depth(of value: Int, in root: TreeNode?) -> Int? {
        guard let root else { return nil }
        if root.value == value {
            return 0
        }
        if let below = depth(of: value, in: root.left) ?? depth(of: value, in: root.right) {
            return below + 1
        }
        return nil
    }
}
```

`depth(of:in:)` only searches the right subtree when the left one comes back `nil`, because `??` evaluates its right side only when it needs to.

</Approach>

<Approach title="Level by level with a queue" time="O(n)" space="O(w)">

Depth is "which level is it on?", so a level-by-level walk answers it directly, with no recursion at all. Process one whole level at a time and count the levels as you go; w is the widest level.

```swift
public static func depth(of value: Int, in root: TreeNode?) -> Int? {
    var level = [root].compactMap { $0 }
    var depth = 0
    while !level.isEmpty {
        if level.contains(where: { $0.value == value }) {
            return depth
        }
        level = level.flatMap { [$0.left, $0.right].compactMap { $0 } }
        depth += 1
    }
    return nil
}
```

You'll meet this level-by-level pattern properly in M35. It also stops as soon as it finds the value, without searching deeper levels.

</Approach>
