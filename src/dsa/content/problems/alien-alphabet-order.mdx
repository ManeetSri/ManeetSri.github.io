Archaeologists found a glossary in an unknown language written with lowercase Latin letters. The glossary is sorted in dictionary order, but under the language's own alphabet, which nobody knows. Given its words in order, return a string holding every letter that appears in them, each once, in an order consistent with the glossary. If no alphabet could produce this glossary, return `""`. When several alphabets fit, any of them is accepted.

`AlienAlphabetOrder.alphabet(_ words: [String]) -> String`

Dictionary order works as in English: compare two words letter by letter, and the first position where they differ decides. If one word runs out first with no difference, the shorter word comes first, so "app" must come before "apple".

## Examples

| `words` | One correct answer | Why |
| --- | --- | --- |
| `["bdc", "bda", "cb", "cab", "ad"]` | `"bcad"` | c before a, b before c, b before a; d is unconstrained, so `"dbca"` is fine too |
| `["xy", "xz", "yx", "yz", "z"]` | `"xyz"` | the only alphabet that fits |
| `["kite"]` | `"kite"` | one word tells you nothing: any order of its letters |
| `["ba", "ab", "bb"]` | `""` | b before a, then a before b |
| `["apple", "app"]` | `""` | a word can't come after a longer word it begins |

## Constraints

- `1 ≤ words.count ≤ 20,000`, and each word has 1 to 20 lowercase letters from a to z.
- Words may repeat; equal neighbours are fine.
- The tests check your answer's properties rather than comparing it with one string: it holds exactly the letters used, each once, and under it every word comes before or equals the next. One test sorts 20,000 random words under a scrambled alphabet.

<Hints>
<Hint>
Only **neighbouring** words carry information, and only at their **first** difference. In "cab" then "ad", c comes before a. The letters after that difference say nothing, because the first difference already decided the order.
</Hint>
<Hint>
Each first difference is an edge between two letters. Topologically sort the letters with Kahn's algorithm, including the letters that never appear in an edge: they have in-degree 0 and can go anywhere.
</Hint>
<Hint>
Two ways to fail: a cycle among the letters (Kahn's algorithm outputs fewer letters than exist), or a pair of neighbours with no difference where the first word is longer, like "apple" then "app". Check the second while you build the edges.
</Hint>
</Hints>

## Solutions

<Approach title="Edges from first differences, then Kahn's algorithm" time="O(C)" space="O(1) beyond the input">

C is the total number of characters. There are at most 26 letters and 26 × 25 edges, so the graph is tiny; reading the words is the real cost. Letters are seeded in the order they first appear, which makes the output the same on every run.

```swift
public enum AlienAlphabetOrder {
    public static func alphabet(_ words: [String]) -> String {
        var letters: [Character] = []                     // every letter, in order of first appearance
        var after: [Character: [Character]] = [:]         // edges: key comes before each value
        var waitingOn: [Character: Int] = [:]             // in-degrees
        for word in words {
            for letter in word where waitingOn[letter] == nil {
                waitingOn[letter] = 0
                after[letter] = []
                letters.append(letter)
            }
        }

        var seen = Set<String>()                          // edges already added, as two-letter keys
        for (earlier, later) in zip(words, words.dropFirst()) {
            guard let (first, second) = firstDifference(earlier, later) else {
                if earlier.count > later.count { return "" }      // "apple" before "app": impossible
                continue                                          // equal, or a prefix first: no info
            }
            if seen.insert(String([first, second])).inserted {
                after[first]!.append(second)
                waitingOn[second]! += 1
            }
        }

        var order = letters.filter { waitingOn[$0] == 0 }
        var head = 0
        while head < order.count {
            let letter = order[head]
            head += 1
            for next in after[letter]! {
                waitingOn[next]! -= 1
                if waitingOn[next] == 0 {
                    order.append(next)
                }
            }
        }
        return order.count == letters.count ? String(order) : ""
    }

    private static func firstDifference(_ a: String, _ b: String) -> (Character, Character)? {
        for (x, y) in zip(a, b) where x != y {
            return (x, y)
        }
        return nil
    }
}
```

`zip(words, words.dropFirst())` pairs each word with the next one. The `seen` set stops the same edge being counted twice; without it, repeated edges would still work, since each is subtracted as often as it was added, but the in-degrees would be larger than they need to be.

</Approach>

<Approach title="Depth-first search over the letters" time="O(C)" space="O(1) beyond the input">

Build the same edges, then run a three-colour DFS over the letters and reverse the finishing order, returning `""` on a grey letter. With at most 26 letters the recursion is never deep, so this is as safe here as Kahn's algorithm.

</Approach>
