Numbers are stacked in a triangle: row 0 has one number, row 1 has two, and row i has i + 1. A path starts at the apex and moves down one row at a time; from position j of a row it may step to position j or position j + 1 of the next row. Return the smallest total of a path from the apex to the bottom row. Numbers may be negative.

`TriangleDescentCost.cheapest(_ triangle: [[Int]]) -> Int`

## Examples

| `triangle` | Output |
| --- | --- |
| `[[5], [4, 7], [9, 8, 1], [2, 6, 3, 4]]` | `16` |
| `[[2], [-1, 5], [4, -6, 1]]` | `-5` |
| `[[1], [2, 3]]` | `3` |
| `[[-3]]` | `-3` |

In the first example the cheapest path is 5 → 7 → 1 → 3. Always stepping to the smaller number below (5 → 4 → 8 → 3) costs 20. In the second, 2 → −1 → −6 = −5.

## Constraints

- `1 ≤ triangle.count ≤ 1,000`, and row i has exactly i + 1 numbers.
- `-10,000 ≤ triangle[i][j] ≤ 10,000`
- The tests use 1,000 rows, which have 2⁹⁹⁹ paths.
- Aim for O(rows) extra memory.

<Hints>
<Hint>
The cheapest path through position (r, j) continues with the cheapest path from one of its two children. Which end of the triangle has exactly one answer?
</Hint>
<Hint>
Let `best[j]` be the cheapest way from position j of a row down to the bottom. For the bottom row it's the row itself. Each row above is `triangle[r][j] + min(best[j], best[j + 1])`.
</Hint>
<Hint>
Going left to right, `best[j + 1]` hasn't been overwritten yet when you update `best[j]`, so a single array works. The answer is `best[0]`.
</Hint>
</Hints>

## Solutions

<Approach title="Top-down, then the minimum of the last row" time="O(rows²)" space="O(rows)">

Fill from the apex: `cost[j]` is the cheapest way from the apex down to position j. Position j's parents are positions j − 1 and j of the row above, except that the left end has no j − 1 and the right end has no j. At the end, take the minimum of the bottom row. Correct, with two edge cases and a final scan.

</Approach>

<Approach title="Bottom-up, one array" time="O(rows²)" space="O(rows)">

Fill from the base instead. Every position has exactly two children, so there are no edge cases, and the apex holds the single answer. O(rows²) is the number of entries in the triangle, so every number is looked at once.

```swift
public enum TriangleDescentCost {
    public static func cheapest(_ triangle: [[Int]]) -> Int {
        guard var best = triangle.last else { return 0 }
        for r in stride(from: triangle.count - 2, through: 0, by: -1) {
            for i in 0...r {
                best[i] = triangle[r][i] + min(best[i], best[i + 1])
            }
        }
        return best[0]
    }
}
```

With a single row, the loop doesn't run and the answer is that one number. Negative values need no special handling: each position is computed once from positions that are already final.

</Approach>
