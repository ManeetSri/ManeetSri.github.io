Three short functions, each practising one recursive move. Write all three with recursion, not loops: that's the skill being trained.

`RecursionWarmups.bounce(from n: Int) -> [Int]`, `RecursionWarmups.power(_ base: Int, _ exponent: Int) -> Int` and `RecursionWarmups.count(of character: Character, in text: String) -> Int`

1. **`bounce(from:)`** returns the numbers from `n` down to 0 and back up to `n`. Each call should add its own number both **before** and **after** the smaller call.
2. **`power(_:_:)`** returns `base` raised to `exponent`, by **halving** the exponent at each call, so the number of calls grows with log₂ of the exponent rather than with the exponent itself. Anything raised to the power 0 is 1, including 0.
3. **`count(of:in:)`** returns how many times `character` appears in `text`, by recursing over an **index** into `Array(text)`. Characters must match exactly, so `"S"` and `"s"` are different.

## Examples

| Call | Returns |
| --- | --- |
| `bounce(from: 0)` | `[0]` |
| `bounce(from: 2)` | `[2, 1, 0, 1, 2]` |
| `power(2, 10)` | `1024` |
| `power(3, 13)` | `1594323` |
| `power(-2, 3)` | `-8` |
| `power(0, 0)` | `1` |
| `count(of: "a", in: "banana")` | `3` |
| `count(of: "é", in: "café crème")` | `1` |
| `count(of: "a", in: "")` | `0` |

## Constraints

- `0 ≤ n ≤ 500` for `bounce`.
- `0 ≤ exponent ≤ 1,000`, and the answer always fits in an `Int`. Large exponents only appear with a base of −1, 0 or 1.
- `0 ≤ text.count ≤ 1,000` for `count`.

<Hints>
<Hint>
`bounce`: the smallest case is `n == 0`, which gives `[0]`. For larger `n`, the answer is `n`, then the bounce from `n - 1`, then `n` again. To avoid building new arrays at every level, give a nested helper one shared `result` array to append to.
</Hint>
<Hint>
`power`: compute `power(base, exponent / 2)` **once** and store it. If the exponent is even, the answer is that half squared; if it's odd, multiply by `base` once more.
</Hint>
<Hint>
`count`: turn the string into `let chars = Array(text)` once, then recurse on a position. When the position reaches `chars.count`, there's nothing left to count. Otherwise, add 1 if `chars[index]` matches, plus the count from `index + 1`.
</Hint>
</Hints>

## Solutions

<Approach title="Straightforward recursion with copying" time="O(n²) for bounce and count" space="O(n²)">

The most literal versions build new arrays and strings at every level. They pass, but `[n] + bounce(n - 1) + [n]` copies the whole inner bounce, and `String(text.dropFirst())` copies the rest of the string, at every call. That's the O(n²) trap from [Recursion over arrays with indices](/dsa/learn/rec-arrays). The power function makes one call per unit of exponent: O(e) calls instead of O(log e).

```swift
public static func bounce(from n: Int) -> [Int] {
    if n == 0 {
        return [0]
    }
    return [n] + bounce(from: n - 1) + [n]
}

public static func power(_ base: Int, _ exponent: Int) -> Int {
    if exponent == 0 {
        return 1
    }
    return base * power(base, exponent - 1)
}

public static func count(of character: Character, in text: String) -> Int {
    guard let first = text.first else {
        return 0
    }
    return (first == character ? 1 : 0) + count(of: character, in: String(text.dropFirst()))
}
```

</Approach>

<Approach title="Shared array, halving and an index" time="O(n), O(log e) and O(n)" space="O(n), O(log e) and O(n)">

`bounce` appends into one array: once on the way down, and again as each call returns. `power` stores the half so it's computed once. `count` walks an index through an array of characters made once at the start. The space in each case is the depth of the recursion (plus the result for `bounce`).

```swift
public enum RecursionWarmups {
    public static func bounce(from n: Int) -> [Int] {
        var result: [Int] = []
        func walk(_ k: Int) {
            result.append(k)            // on the way down
            if k == 0 {
                return
            }
            walk(k - 1)
            result.append(k)            // on the way back up
        }
        walk(n)
        return result
    }

    public static func power(_ base: Int, _ exponent: Int) -> Int {
        if exponent == 0 {
            return 1
        }
        let half = power(base, exponent / 2)
        if exponent % 2 == 0 {
            return half * half
        }
        return half * half * base
    }

    public static func count(of character: Character, in text: String) -> Int {
        let chars = Array(text)
        func countFrom(_ index: Int) -> Int {
            if index == chars.count {
                return 0
            }
            let here = chars[index] == character ? 1 : 0
            return here + countFrom(index + 1)
        }
        return countFrom(0)
    }
}
```

Why multiply `half * half * base` rather than square the base and halve the exponent, as in `power(base * base, exponent / 2)`? That version squares the base one more time than it needs to at the bottom of the recursion, and for `power(2, 62)` that last unneeded square, 2⁶⁴, overflows `Int` and crashes even though the answer fits.

</Approach>
