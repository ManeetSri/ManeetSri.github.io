Swift's `/` truncates towards zero, which is neither floor nor ceiling once signs are mixed. Write integer floor and ceiling division that are exact for **every** pair of `Int` values, plus the matching "position within the block", without overflowing and without converting to `Double`.

`RoundingDivision.floorQuotient(_ a: Int, _ b: Int) -> Int` returns ⌊a / b⌋.

`RoundingDivision.ceilingQuotient(_ a: Int, _ b: Int) -> Int` returns ⌈a / b⌉.

`RoundingDivision.offset(_ a: Int, within b: Int) -> Int` returns where a sits inside its block of size b: the value in `0..<b` that equals a − b × ⌊a / b⌋.

## Examples

| a | b | `floorQuotient` | `ceilingQuotient` | `offset(a, within: b)` |
| --- | --- | --- | --- | --- |
| `7` | `2` | `3` | `4` | `1` |
| `-7` | `2` | `-4` | `-3` | `1` |
| `7` | `-2` | `-4` | `-3` | (b must be positive) |
| `-6` | `3` | `-2` | `-2` | `0` |
| `-1` | `10` | `-1` | `0` | `9` |
| `Int.max` | `2` | `4611686018427387903` | `4611686018427387904` | `1` |

## Constraints

- `b ≠ 0`, and a, b are any `Int` values except a = `Int.min` with b = −1, whose quotient doesn't fit.
- For `offset`, `b ≥ 1`.
- No `Double`: values above 2⁵³ don't survive the conversion.

<Hints>
<Hint>
Start from Swift's truncated quotient `a / b` and its remainder `a % b`. When the remainder is 0, the division is exact and all three roundings agree.
</Hint>
<Hint>
When it isn't exact: if a and b have opposite signs, the true answer is negative and truncation rounded it **up**, so the floor is one less. If they have the same sign, the answer is positive and truncation rounded down, so the ceiling is one more. `(a < 0) != (b < 0)` checks for opposite signs.
</Hint>
<Hint>
The textbook offset, `((a % b) + b) % b`, adds b to the remainder, which overflows when b is close to `Int.max`. Instead, only add b when the remainder is negative: then it's between −b and 0, and adding b lands safely in `0..<b`. Likewise avoid `(a + b - 1) / b` for the ceiling.
</Hint>
</Hints>

## Solutions

<Approach title="Correct the truncated quotient" time="O(1)" space="O(1)">

Every function starts from Swift's own `/` and `%`, which never overflow for the allowed inputs, and makes a correction of at most one. Nothing is ever added to a large number except that correction, and an exact floor or ceiling always fits because it lies between the truncated quotient and a value one away from it in a direction that stays in range.

```swift
public enum RoundingDivision {
    public static func floorQuotient(_ a: Int, _ b: Int) -> Int {
        let q = a / b
        if a % b != 0 && (a < 0) != (b < 0) {
            return q - 1
        }
        return q
    }

    public static func ceilingQuotient(_ a: Int, _ b: Int) -> Int {
        let q = a / b
        if a % b != 0 && (a < 0) == (b < 0) {
            return q + 1
        }
        return q
    }

    public static func offset(_ a: Int, within b: Int) -> Int {
        let r = a % b
        return r < 0 ? r + b : r
    }
}
```

`offset(5, within: Int.max)` is 5, and `offset(-5, within: Int.max)` is `Int.max - 5`: the textbook formula would crash on the first and the `Double` route would get the second wrong. Floor division and the offset always fit together: `floorQuotient(a, b) * b + offset(a, within: b) == a` whenever b is positive and the product fits.

</Approach>
