A spice stall has a sack of each good: `weights[i]` kilograms of good i, worth `values[i]` for the whole sack. Anything can be scooped by the kilogram, or by any fraction of one, at the same price per kilogram as its sack. Your bag holds `capacity` kilograms. Return the most valuable bagful you can take.

`SpiceMarketBagful.bestValue(weights: [Int], values: [Int], capacity: Int) -> Double`

## Examples

| `weights` | `values` | `capacity` | Output |
| --- | --- | --- | --- |
| `[4, 6, 5, 8]` | `[20, 18, 35, 8]` | `10` | `58.0` |
| `[3, 2]` | `[10, 7]` | `2` | `7.0` |
| `[6, 5, 5]` | `[30, 20, 20]` | `10` | `46.0` |
| `[3]` | `[10]` | `1` | `3.333…` |
| `[4, 6, 5, 8]` | `[20, 18, 35, 8]` | `100` | `81.0` |
| `[]` | `[]` | `10` | `0.0` |

The first is the lesson's stall: all the cocoa, all the tea, and 1 kg of coffee. In the second, the 2 kg sack is worth 3.5 per kilogram and the 3 kg sack 3.33, so the bag takes the whole 2 kg sack. In the third, the lamp, rug and vase from the lesson can now be split: the lamp and 4 kg of the rug.

Answers are compared with a tolerance of one part in a million.

## Constraints

- `0 ≤ weights.count == values.count ≤ 200,000`
- `1 ≤ weights[i] ≤ 1,000,000`, `0 ≤ values[i] ≤ 10,000,000` and `0 ≤ capacity ≤ 10¹⁵`.
- The tests use 200,000 goods.

<Hints>
<Hint>
Because you can take any fraction, a kilogram of a good is worth its value per kilogram, wherever it ends up in the bag. Which kilograms would you want first?
</Hint>
<Hint>
The densest first: sort by value per kilogram, highest first. Take each sack whole while it fits; the first one that doesn't fit, take as much of it as fits, and stop.
</Hint>
<Hint>
Compare densities without dividing integers: good a is denser than good b exactly when `values[a] * weights[b] > values[b] * weights[a]`. With `Int` division, 10 / 3 and 7 / 2 are both 3, and the second example comes out wrong.
</Hint>
</Hints>

## Solutions

<Approach title="Sort by density and fill" time="O(n log n)" space="O(n)">

The exchange argument from the lesson: take any best bagful that holds less of the densest good than it could, alongside a kilogram of something less dense. Swapping that kilogram for one of the densest good keeps the weight and doesn't lower the value. So some best bagful takes as much of the densest good as possible, and what's left is the same problem with a smaller bag. Sorting the indexes, rather than building pairs, keeps the two arrays untouched.

```swift
public enum SpiceMarketBagful {
    public static func bestValue(weights: [Int], values: [Int], capacity: Int) -> Double {
        let densestFirst = weights.indices.sorted { values[$0] * weights[$1] > values[$1] * weights[$0] }
        var room = capacity
        var total = 0.0
        for good in densestFirst {
            if room == 0 { break }
            let take = min(weights[good], room)
            total += Double(values[good]) * Double(take) / Double(weights[good])
            room -= take
        }
        return total
    }
}
```

The cross-multiplied products are at most 10¹³, far inside `Int`. Only the final value is a `Double`, and multiplying before dividing keeps a whole sack exact: `Double(20) * 4 / 4` is exactly `20.0`. Goods with equal densities can come out of the sort in either order, which doesn't change the total.

</Approach>
