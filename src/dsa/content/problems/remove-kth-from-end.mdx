Remove the kth node counting from the end of a list (k = 1 is the last node) and return the head of the list that's left. Unlink the node; keep all the other original nodes.

`RemoveKthFromEnd.removing(_ head: ListNode?, kthFromEnd k: Int) -> ListNode?`

## Examples

| List | k | Result |
| --- | --- | --- |
| `1 -> 2 -> 3 -> 4 -> 5` | 2 | `1 -> 2 -> 3 -> 5` |
| `1 -> 2 -> 3 -> 4 -> 5` | 1 | `1 -> 2 -> 3 -> 4` |
| `1 -> 2 -> 3 -> 4 -> 5` | 5 | `2 -> 3 -> 4 -> 5` |
| `4` | 1 | empty (`nil`) |

## Constraints

- 1 to 100,000 nodes.
- `1 ≤ k ≤` the number of nodes.
- Try for a single pass over the list.

<Hints>
<Hint>
Two passes work: count the nodes, then the node to remove is at position `count - k` from the front (counting from 0). To unlink it you need the node before it, which doesn't exist when the head itself is removed, unless you put a dummy node in front.
</Hint>
<Hint>
For one pass, start two pointers at the dummy. Move the first one k steps ahead on its own, then move both together until the first one is on the last node.
</Hint>
<Hint>
At that point the second pointer is just before the kth node from the end, because the gap between them is still k. Skip the node after it with `trail.next = trail.next?.next`, and return `dummy.next`.
</Hint>
</Hints>

## Solutions

<Approach title="Count, then walk" time="O(n)" space="O(1)">

The first pass finds the length. Starting from a dummy node, `length - k` steps reach the node just before the target, which works even when the target is the head.

```swift
public static func removing(_ head: ListNode?, kthFromEnd k: Int) -> ListNode? {
    var length = 0
    var current = head
    while let node = current {
        length += 1
        current = node.next
    }
    let dummy = ListNode(0, next: head)
    var before = dummy
    for _ in 0..<(length - k) {
        before = before.next!
    }
    before.next = before.next?.next
    return dummy.next
}
```

</Approach>

<Approach title="One pass with a gap of k" time="O(n)" space="O(1)">

Keeping the leading pointer exactly k nodes ahead turns "k from the end" into "where the trailing pointer is when the leading one reaches the end". Starting both at a dummy is what makes removing the head (k equal to the length) work: the trailing pointer never leaves the dummy.

```swift
import DSAKit

public enum RemoveKthFromEnd {
    public static func removing(_ head: ListNode?, kthFromEnd k: Int) -> ListNode? {
        let dummy = ListNode(0, next: head)
        var lead: ListNode = dummy
        for _ in 0..<k {
            lead = lead.next!         // k ≤ the length, so these k steps exist
        }
        var trail: ListNode = dummy
        while let next = lead.next {
            lead = next
            trail = trail.next!
        }
        trail.next = trail.next?.next  // trail is just before the kth node from the end
        return dummy.next
    }
}
```

</Approach>
