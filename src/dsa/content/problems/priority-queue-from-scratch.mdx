Build a priority queue as a binary heap stored in an array. A closure decides the order: `areInIncreasingOrder(a, b)` is true when `a` should be nearer the top than `b`, so `<` gives a min-heap and `>` a max-heap. Lay the tree out level by level with 0-based index maths: the children of index `i` are at `2i + 1` and `2i + 2`.

`PriorityQueueFromScratch.PriorityQueue<Element>`, with `init(areInIncreasingOrder:)`, `init(_ elements: [Element], areInIncreasingOrder:)`, `count`, `isEmpty`, `unordered` (the array itself), `peek()`, `insert(_:)` and `pop() -> Element?`

`insert` and `pop` must be O(log n), `peek` O(1), and building from an array O(n). Don't use DSAKit's `Heap`: this is the place to write your own.

## Examples

| Code | Result |
| --- | --- |
| `var q = PriorityQueue<Int>(areInIncreasingOrder: <)`, insert 5, 3, 8, 1 | `q.unordered` is `[1, 3, 8, 5]`, `q.peek()` is `1` |
| then `q.pop()` | returns `1`; `q.unordered` is `[3, 5, 8]` |
| `PriorityQueue([4, 9, 4, 1], areInIncreasingOrder: >)`, popping until nil | `9, 4, 4, 1` |
| An empty queue's `pop()` and `peek()` | `nil` |

Tuples work too: a queue of `(minutes: Int, name: String)` ordered by `{ $0.minutes < $1.minutes }` pops the quickest errand first.

## Constraints

- Up to 100,000 elements. The tests insert 100,000 values in decreasing order, so an O(n) insert, such as keeping a sorted array, is too slow.
- After every operation, `unordered` must be a valid heap: no element comes before its parent at `(i - 1) / 2`.
- Copies must be independent (a struct holding an array gives you that for free).

<Hints>
<Hint>
Store two things: an array of elements and the comparator. The comparator is kept after `init` returns, so its parameter must be `@escaping`.
</Hint>
<Hint>
`insert` appends to the array, then **sifts up**: while the new element should come before its parent at `(child - 1) / 2`, swap them. `pop` swaps the root with the last element, removes the last, then **sifts down** from the root: swap with whichever child should come first, while that child should come before the element.
</Hint>
<Hint>
For the array initialiser, copy the array, then sift down every parent, starting from the last one at `count / 2 - 1` and working back to index 0. When you sift down index i, both of its subtrees are already heaps.
</Hint>
</Hints>

## Solutions

<Approach title="Sift up, sift down and bottom-up heapify" time="O(log n) insert and pop, O(n) build" space="O(n)">

```swift
public enum PriorityQueueFromScratch {
    public struct PriorityQueue<Element> {
        private var items: [Element] = []
        private let areInIncreasingOrder: (Element, Element) -> Bool

        public init(areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
            self.areInIncreasingOrder = areInIncreasingOrder
        }

        public init(_ elements: [Element], areInIncreasingOrder: @escaping (Element, Element) -> Bool) {
            self.items = elements
            self.areInIncreasingOrder = areInIncreasingOrder
            for index in stride(from: items.count / 2 - 1, through: 0, by: -1) {
                siftDown(from: index)
            }
        }

        public var count: Int { items.count }
        public var isEmpty: Bool { items.isEmpty }
        public var unordered: [Element] { items }

        public func peek() -> Element? {
            items.first
        }

        public mutating func insert(_ element: Element) {
            items.append(element)
            var child = items.count - 1
            while child > 0 {
                let parent = (child - 1) / 2
                guard areInIncreasingOrder(items[child], items[parent]) else { break }
                items.swapAt(child, parent)
                child = parent
            }
        }

        public mutating func pop() -> Element? {
            guard !items.isEmpty else { return nil }
            items.swapAt(0, items.count - 1)
            let top = items.removeLast()
            siftDown(from: 0)
            return top
        }

        private mutating func siftDown(from index: Int) {
            var parent = index
            while true {
                let left = 2 * parent + 1
                let right = left + 1
                var first = parent
                if left < items.count && areInIncreasingOrder(items[left], items[first]) { first = left }
                if right < items.count && areInIncreasingOrder(items[right], items[first]) { first = right }
                if first == parent { return }
                items.swapAt(parent, first)
                parent = first
            }
        }
    }
}
```

`stride(from: -1, through: 0, by: -1)` is empty, so building from an empty or one-element array does nothing, as it should. Each sift follows one path between the root and a leaf, at most ⌊log₂ n⌋ swaps.

</Approach>
