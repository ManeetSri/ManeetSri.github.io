A row of solar panels is being switched on: panel i comes online on day `onlineDay[i]` and stays online. A block is `blockSize` adjacent online panels, and no panel can belong to two blocks. Return the earliest day on which `blocks` blocks can be formed, or −1 if that never happens.

`PanelBlocksDay.earliestDay(onlineDay: [Int], blocks: Int, blockSize: Int) -> Int`

## Examples

| `onlineDay` | `blocks` | `blockSize` | Output |
| --- | --- | --- | --- |
| `[5, 1, 4, 6, 2, 3]` | `2` | `2` | `4` |
| `[5, 1, 4, 6, 2, 3]` | `3` | `2` | `6` |
| `[5, 1, 4, 6, 2, 3]` | `1` | `6` | `6` |
| `[5, 1, 4, 6, 2, 3]` | `4` | `2` | `-1` |
| `[1, 1, 1, 9, 9]` | `2` | `2` | `9` |
| `[1, 2, 3]` | `10000000000` | `10000000000` | `-1` |

In the first example, on day 4 the panels online are, writing `x` for online, `.xx.xx`: two blocks of 2. On day 3 the row is `.x..xx`, which holds only one. In the fifth example, the run of three panels online from day 1 holds just one block of 2, because a panel can't be shared. The last example asks for far more panels than exist.

## Constraints

- `1 ≤ onlineDay.count ≤ 100,000`
- `1 ≤ onlineDay[i] ≤ 10⁹`
- `1 ≤ blocks ≤ 10¹⁰` and `1 ≤ blockSize ≤ 10¹⁰`, so `blocks × blockSize` can be far larger than `Int.max`.

<Hints>
<Hint>
For a fixed day, count the blocks in one pass: keep the length of the current run of online panels. When it reaches `blockSize`, count a block and reset the run to 0. An offline panel also resets it.
</Hint>
<Hint>
A later day only switches more panels on, so the number of blocks never drops. Binary search the days between the earliest and the latest switch-on day for the first day with enough blocks.
</Hint>
<Hint>
If `blocks × blockSize` is more than the number of panels, return −1 before searching. Don't multiply, because the product can overflow and crash: for positive whole numbers, that test is the same as `blocks > onlineDay.count / blockSize`.
</Hint>
</Hints>

## Solutions

<Approach title="Check every switch-on day in order" time="O(n²)" space="O(n)">

The block count only changes on days when some panel comes online, so the answer, if there is one, is one of those days. Sort the distinct days and check each in turn. It's simple and correct, but with 100,000 different days it makes up to 100,000 passes over the row.

```swift
public static func earliestDay(onlineDay: [Int], blocks: Int, blockSize: Int) -> Int {
    for day in Set(onlineDay).sorted() where blocksReady(onlineDay, on: day, blockSize: blockSize) >= blocks {
        return day
    }
    return -1
}
```

`blocksReady` is the counting pass from the next approach. This version needs no separate impossible check, because it simply runs out of days.

</Approach>

<Approach title="Binary search on the day" time="O(n log D)" space="O(1)">

Rule out the impossible case first, without multiplying. Then search between the earliest and latest switch-on days, D being the largest. By the latest day every panel is online, the whole row is one run, and since `blocks × blockSize ≤ n` that's enough, so the search always lands on a real answer.

```swift
public enum PanelBlocksDay {
    public static func earliestDay(onlineDay: [Int], blocks: Int, blockSize: Int) -> Int {
        guard blocks <= onlineDay.count / blockSize else { return -1 }
        var low = onlineDay.min()!
        var high = onlineDay.max()!                      // every panel is on: enough for all blocks
        while low < high {
            let mid = low + (high - low) / 2
            if blocksReady(onlineDay, on: mid, blockSize: blockSize) >= blocks {
                high = mid
            } else {
                low = mid + 1
            }
        }
        return low
    }

    /// How many separate blocks of `blockSize` adjacent online panels there are on `day`.
    private static func blocksReady(_ onlineDay: [Int], on day: Int, blockSize: Int) -> Int {
        var blocks = 0
        var run = 0
        for switchOn in onlineDay {
            if switchOn <= day {
                run += 1
                if run == blockSize {
                    blocks += 1
                    run = 0                              // these panels are used up
                }
            } else {
                run = 0                                  // an offline panel breaks the run
            }
        }
        return blocks
    }
}
```

Without the guard, the search would return the latest day for an impossible request, because a binary search always returns *some* candidate. This is the classic "minimum days to make bouquets" problem.

</Approach>
