A degree has `courseCount` courses, labelled 0 to `courseCount - 1`. Each pair `[before, after]` means course `before` must be completed before course `after`. Return an order to take **every** course, each exactly once, that respects every pair. If no such order exists, return `[]`. When several orders work, any of them is accepted.

`CourseStudyOrder.order(courseCount: Int, prerequisites: [[Int]]) -> [Int]`

This is a topological sort of the graph with an edge `before → after` for each pair.

## Examples

| `courseCount` | `prerequisites` | One correct answer | Others |
| --- | --- | --- | --- |
| 2 | `[[1, 0]]` | `[1, 0]` | none |
| 4 | `[[3, 1], [3, 2], [1, 0], [2, 0]]` | `[3, 1, 2, 0]` | `[3, 2, 1, 0]` |
| 3 | `[]` | `[0, 1, 2]` | any arrangement |
| 2 | `[[0, 1], [1, 0]]` | `[]` | none: a cycle |
| 1 | `[[0, 0]]` | `[]` | none: a course that requires itself |

## Constraints

- `0 ≤ courseCount ≤ 100,000` and `0 ≤ prerequisites.count ≤ 200,000`. With no courses, return `[]`.
- Labels are in range. A pair may appear more than once.
- The tests check your order's properties rather than comparing it with one answer: every course appears once, and each `before` comes ahead of its `after`. They use 100,000 courses, with prerequisite chains shorter than 1,000.

<Hints>
<Hint>
A course can go first if it has no prerequisites: its in-degree is 0. Once it's placed, it no longer holds anything back.
</Hint>
<Hint>
Kahn's algorithm: put every course with in-degree 0 in a queue. Take one, append it to the answer, and subtract 1 from the in-degree of each course it unlocks; any that reach 0 join the queue.
</Hint>
<Hint>
If the answer ends up with fewer than `courseCount` courses, the rest are stuck in or behind a cycle: return `[]`. The answer array can be the queue itself, read with a head index.
</Hint>
</Hints>

## Solutions

<Approach title="Kahn's algorithm" time="O(n + p)" space="O(n + p)">

Each course enters the order once, and each pair is looked at once when its `before` course is taken.

```swift
public enum CourseStudyOrder {
    public static func order(courseCount: Int, prerequisites: [[Int]]) -> [Int] {
        var unlocks = Array(repeating: [Int](), count: courseCount)
        var waitingOn = Array(repeating: 0, count: courseCount)
        for pair in prerequisites {
            unlocks[pair[0]].append(pair[1])
            waitingOn[pair[1]] += 1
        }
        var order = (0..<courseCount).filter { waitingOn[$0] == 0 }
        var head = 0                                                 // order doubles as the queue
        while head < order.count {
            let course = order[head]
            head += 1
            for next in unlocks[course] {
                waitingOn[next] -= 1
                if waitingOn[next] == 0 {
                    order.append(next)
                }
            }
        }
        return order.count == courseCount ? order : []
    }
}
```

A course joins only when every course it depends on is already in the order, which is exactly what makes the order valid.

</Approach>

<Approach title="Depth-first search, reversed finishing order" time="O(n + p)" space="O(n + p)">

Run a three-colour DFS from every unvisited course, appending each course when it **finishes**, after everything it unlocks has finished. Reversing that list puts every course before the courses it unlocks. Meeting a grey course means a cycle: return `[]`.

```swift
var colour = Array(repeating: 0, count: courseCount)        // 0 white, 1 grey, 2 black
var finished: [Int] = []
func visit(_ course: Int) -> Bool {                         // false if it finds a cycle
    colour[course] = 1
    for next in unlocks[course] {
        if colour[next] == 1 { return false }
        if colour[next] == 0 && !visit(next) { return false }
    }
    colour[course] = 2
    finished.append(course)
    return true
}
for course in 0..<courseCount where colour[course] == 0 {
    if !visit(course) { return [] }
}
return finished.reversed()
```

The recursion depth is the length of the longest path followed, fine for these tests but not for a chain of 100,000 courses.

</Approach>
