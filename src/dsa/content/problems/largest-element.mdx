Given an array of whole numbers, return the largest one, or `nil` if the array is empty.

`LargestElement.largest(in numbers: [Int]) -> Int?`

Solve it **without** using the built-in `max()`. Writing the loop yourself is the point.

## Examples

| Input | Output |
| --- | --- |
| `[3, 9, 4]` | `9` |
| `[-5, -2, -8]` | `-2` |
| `[7]` | `7` |
| `[]` | `nil` |

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- `-10⁹ ≤ numbers[i] ≤ 10⁹`

<Hints>
<Hint>
Keep track of the largest number seen so far as you walk through the array once.
</Hint>
<Hint>
What should the "largest so far" start as? Not `0`: think about `[-5, -2, -8]`. The first element is a safe start.
</Hint>
<Hint>
`guard var best = numbers.first else { return nil }` handles the empty array and gives you a starting value in one line.
</Hint>
</Hints>

## Solutions

<Approach title="Brute force: sort, then take the last" time="O(n log n)" space="O(n)">

Sorting puts the largest number at the end. It's correct but does far more work than needed, since it orders *everything* just to find one value.

```swift
public static func largest(in numbers: [Int]) -> Int? {
    numbers.sorted().last
}
```

</Approach>

<Approach title="One pass, remembering the best" time="O(n)" space="O(1)">

Walk through once, replacing `best` whenever a bigger number appears. Starting from the first element handles all-negative arrays, and `guard` handles the empty one.

```swift
public enum LargestElement {
    public static func largest(in numbers: [Int]) -> Int? {
        guard var best = numbers.first else { return nil }
        for number in numbers.dropFirst() where number > best {
            best = number
        }
        return best
    }
}
```

`dropFirst()` skips the element we started with. It's a view of the array, not a copy, so it costs no extra space.

</Approach>
