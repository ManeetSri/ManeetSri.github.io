Each contact card is an array of strings: a person's name, then one or more email addresses. Two cards belong to the same person if they share at least one email, and so does any card linked to them through a chain of shared emails. Merge the cards: return one card per person, with the name first and then all of that person's emails, each once, in sorted order. Sort the merged cards by name, and cards with the same name by their first email.

`ContactCardMerge.merge(_ cards: [[String]]) -> [[String]]`

Cards that share an email always have the same name. Two people with the same name are still different people unless their cards are linked by an email.

## Examples

| `cards` | Returns |
| --- | --- |
| `[["Priya", "priya@home.net", "p.shah@work.com"], ["Tom", "tom@mail.org"], ["Priya", "priya.s@uni.edu"], ["Priya", "p.shah@work.com", "shah.p@club.org"], ["Tom", "tommy@games.io", "tom@mail.org"]]` | `[["Priya", "p.shah@work.com", "priya@home.net", "shah.p@club.org"], ["Priya", "priya.s@uni.edu"], ["Tom", "tom@mail.org", "tommy@games.io"]]` |
| `[["Ana", "a@x.com", "b@x.com"], ["Ana", "c@x.com", "d@x.com"], ["Ana", "b@x.com", "c@x.com"]]` | `[["Ana", "a@x.com", "b@x.com", "c@x.com", "d@x.com"]]` |
| `[["Sam", "sam1@x.com"], ["Sam", "sam0@x.com"]]` | `[["Sam", "sam0@x.com"], ["Sam", "sam1@x.com"]]` |
| `[["Lee", "lee@x.com", "lee@x.com"]]` | `[["Lee", "lee@x.com"]]` |

In the second example, the first two cards share nothing, but the third links them.

## Constraints

- `0 ≤ cards.count ≤ 20,000`, each card has a name and between 1 and 10 emails, and there are at most 100,000 emails in total.
- Sort with Swift's `<` on `String`. For the lowercase emails in the tests, that's alphabetical order.
- The tests include 20,000 shuffled cards that merge into 200 people, and random cards checked against a slow merge.

## Solutions

<Approach title="Merge until nothing changes" time="O(n² · k) per pass" space="O(E)">

Keep a list of people, each a name and a set of emails. Repeatedly find two people whose sets intersect and merge them, until no pair intersects. It's obviously right, and the tests use it as a model for small inputs, but it compares every pair of cards on every pass.

</Approach>

<Approach title="Union-find over email indexes" time="O(E log E)" space="O(E)">

Index the emails, union each card's emails with its first, group by root, then sort. The unions are near-linear in E, the total number of emails, so sorting dominates.

```swift
import DSAKit

public enum ContactCardMerge {
    public static func merge(_ cards: [[String]]) -> [[String]] {
        var indexOf: [String: Int] = [:]
        var emails: [String] = []
        var ownerOf: [String] = []
        for card in cards {
            for email in card.dropFirst() where indexOf[email] == nil {
                indexOf[email] = emails.count
                emails.append(email)
                ownerOf.append(card[0])
            }
        }

        var sets = UnionFind(count: emails.count)
        for card in cards where card.count > 1 {
            let first = indexOf[card[1]]!
            for email in card.dropFirst(2) {
                sets.union(first, indexOf[email]!)
            }
        }

        var emailsOfRoot: [Int: [String]] = [:]
        for (index, email) in emails.enumerated() {
            emailsOfRoot[sets.find(index), default: []].append(email)
        }
        let merged = emailsOfRoot.map { root, group in [ownerOf[root]] + group.sorted() }
        return merged.sorted { $0[0] != $1[0] ? $0[0] < $1[0] : $0[1] < $1[1] }
    }
}
```

Each email gets one index however many cards it's on, so repeats disappear without a separate deduplication step. You can also make the cards the elements instead: keep a dictionary from each email to the first card that had it, and union later cards with that one.

</Approach>
