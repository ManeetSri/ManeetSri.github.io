A print dialog shows the pages you picked in a compact form, such as `1...3, 5, 7, 8`. Write the function that builds that text from any list of numbers. It's short to write and easy to get wrong, so this problem is about the testing routine: list the edge cases before you code, and check each one.

`CompactNumberRanges.summary(_ values: [Int]) -> String`

Take the distinct values in increasing order and split them into runs of consecutive integers. Write a run of three or more as `first...last`, a run of two as `a, b`, and a single value as itself. Join the pieces with `", "`. The input can be in any order and can hold duplicates; an empty array gives `""`.

## Examples

| `values` | Output | Why |
| --- | --- | --- |
| `[1, 2, 3, 5, 7, 8]` | `"1...3, 5, 7, 8"` | a run of three, a single value, a run of two |
| `[8, 3, 1, 2, 2, 7]` | `"1...3, 7, 8"` | order and duplicates don't matter |
| `[-3, -1, -2, 1]` | `"-3...-1, 1"` | negative numbers |
| `[10, 12, 14]` | `"10, 12, 14"` | no two are consecutive |
| `[6, 6, 6]` | `"6"` | one distinct value |
| `[]` | `""` | |
| `[Int.max, Int.max - 1]` | `"9223372036854775806, 9223372036854775807"` | the top of `Int` |
| `[Int.min, Int.max]` | `"-9223372036854775808, 9223372036854775807"` | not consecutive, and far apart |

## Constraints

- `0 ≤ values.count ≤ 200,000`.
- Any `Int` values, including `Int.min` and `Int.max`.

<Hints>
<Hint>
Before writing code, run the edge-case checklist and write the cases down: empty, one value, all equal, duplicates inside a run, unsorted, negatives, runs of exactly two, and values at `Int.min` and `Int.max`. Each one is a test in the suite.
</Hint>
<Hint>
Sort, then walk the values keeping the current run's start and end. Skip a value equal to the run's end (a duplicate). Close the run when the next value isn't exactly one more than the end, and once more after the loop: the last run is the one that's easiest to forget.
</Hint>
<Hint>
"Exactly one more" is where overflow hides. `end + 1 == value` traps when `end` is `Int.max`, and `value - end == 1` traps for `Int.min` and `Int.max`. Check `end < Int.max` before adding.
</Hint>
</Hints>

## Solutions

<Approach title="Sort, then one pass with a run start and end" time="O(n log n)" space="O(n)">

Each line here answers one of the edge cases: the `guard` handles the empty array, `where value != runEnd` skips duplicates, the `Int.max` checks keep the comparison from overflowing, and the final `closeRun()` handles the last run.

```swift
public enum CompactNumberRanges {
    public static func summary(_ values: [Int]) -> String {
        let sorted = values.sorted()
        guard var runStart = sorted.first else { return "" }
        var runEnd = runStart
        var parts: [String] = []

        func closeRun() {
            if runStart == runEnd {
                parts.append("\(runStart)")
            } else if runStart < Int.max && runStart + 1 == runEnd {
                parts.append("\(runStart), \(runEnd)")          // a run of two is written as two values
            } else {
                parts.append("\(runStart)...\(runEnd)")
            }
        }

        for value in sorted.dropFirst() where value != runEnd {   // equal values are duplicates
            if runEnd < Int.max && runEnd + 1 == value {
                runEnd = value
            } else {
                closeRun()
                runStart = value
                runEnd = value
            }
        }
        closeRun()
        return parts.joined(separator: ", ")
    }
}
```

The trace worth doing by hand is `[1, 2, 2, 3, 5]`, because it has a duplicate inside a run and a run that ends the array. The quick checks worth writing, if your editor runs code, are the last two examples: an implementation that passes every small case can still crash at `Int.max`. And a stress test against a slow version (put the values in a `Set`, and start a run at every value whose predecessor is missing) finds the rest.

</Approach>
