A trading app lets you select any stretch of days on a price chart and shows its **swing**: the highest price in the stretch minus the lowest. Given the daily prices and a list of queries `[left, right]` (days counted from 0, both ends included), return the swing for every query, in order.

`PriceSwingQueries.swings(prices: [Int], queries: [[Int]]) -> [Int]`

## Examples

| `prices` | `queries` | Output |
| --- | --- | --- |
| `[7, 2, 9, 4, 8, 1, 6, 3]` | `[[0, 7], [2, 4], [5, 5], [3, 6]]` | `[8, 5, 0, 7]` |
| `[10, 1, 10]` | `[[0, 1], [1, 2], [0, 2]]` | `[9, 9, 9]` |
| `[3, 3, 3]` | `[[0, 2], [1, 2]]` | `[0, 0]` |
| `[5]` | `[[0, 0]]` | `[0]` |
| `[4, 7]` | `[]` | `[]` |

In the first example, days 2 to 4 have prices 9, 4 and 8, so the swing is 9 − 4 = 5. A single day always has a swing of 0.

## Constraints

- `1 ≤ prices.count ≤ 100,000` and `0 ≤ queries.count ≤ 100,000`
- `0 ≤ prices[i] ≤ 1,000,000,000`
- Every query has `0 ≤ left ≤ right < prices.count`.
- The prices never change between queries.
- The tests ask 100,000 queries over 100,000 prices, most of them covering a large part of the chart. Scanning each range is billions of steps: too slow.

<Hints>
<Hint>
The prices never change, and there are many queries. Do some work up front so each query is cheap.
</Hint>
<Hint>
The swing is a maximum minus a minimum. Both are idempotent: looking at a price twice doesn't change either. Which structure answers range minimums in O(1)?
</Hint>
<Hint>
Build two sparse tables, one for minimums and one for maximums. For a query of length `len`, take the largest power of two 2^k ≤ len, and combine the block of length 2^k starting at `left` with the one ending at `right`, in each table.
</Hint>
</Hints>

## Solutions

<Approach title="Scan each range" time="O(n · q)" space="O(1) extra">

For each query, walk from `left` to `right`, tracking the largest and smallest price. It's correct and simple, and it's what the tests use to check a sample of your answers, but 100,000 long ranges make it far too slow.

</Approach>

<Approach title="Two sparse tables" time="O(n log n + q)" space="O(n log n)">

`low[j][i]` and `high[j][i]` hold the minimum and maximum of the 2^j prices starting at day i. Each level comes from the one below in O(n). A query looks up ⌊log₂ len⌋ in a precomputed table and combines two overlapping blocks per table, which is harmless for `min` and `max`.

```swift
public enum PriceSwingQueries {
    public static func swings(prices: [Int], queries: [[Int]]) -> [Int] {
        let n = prices.count
        var floorLog = [Int](repeating: 0, count: n + 1)       // floorLog[x] = ⌊log₂ x⌋
        if n >= 2 {
            for x in 2...n {
                floorLog[x] = floorLog[x / 2] + 1
            }
        }

        var low = [prices]
        var high = [prices]
        var j = 1
        while (1 << j) <= n {
            let half = 1 << (j - 1)
            let previousLow = low[j - 1]
            let previousHigh = high[j - 1]
            let count = n - (1 << j) + 1
            low.append((0..<count).map { min(previousLow[$0], previousLow[$0 + half]) })
            high.append((0..<count).map { max(previousHigh[$0], previousHigh[$0 + half]) })
            j += 1
        }

        return queries.map { query in
            let left = query[0], right = query[1]
            let k = floorLog[right - left + 1]
            let other = right - (1 << k) + 1                     // the block that ends at right
            return max(high[k][left], high[k][other]) - min(low[k][left], low[k][other])
        }
    }
}
```

One table holding `(low: Int, high: Int)` pairs also works and halves the number of arrays. With DSAKit you could write `SparseTable.minimum(prices)` and `SparseTable.maximum(prices)`, but build it yourself first: that's the exercise.

</Approach>
