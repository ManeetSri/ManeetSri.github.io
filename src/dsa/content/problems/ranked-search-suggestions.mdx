Build the engine behind a search box. It knows how many times each phrase has been searched. As the user types, character by character, it suggests the most popular phrases that start with what has been typed so far. When the user submits a search, that phrase's count goes up by one (a brand-new phrase starts at 1), so the suggestions learn.

`RankedSearchSuggestions.Engine` (a class), with `init(history:limit:)`, `query`, `type(_:) -> [String]`, `submit()`, `clear()` and `suggestions(for:) -> [String]`

- `init(history: [String: Int], limit: Int = 3)`: every phrase in `history` with its count. Suggestions hold at most `limit` phrases.
- **Ranking:** higher count first; equal counts in alphabetical order (Swift's `<` on `String`).
- `type(_ character: Character)` adds the character to `query` and returns the suggestions for the new query.
- `submit()` records one more search for `query` (doing nothing if it's empty) and starts a new, empty query. `clear()` starts a new query without recording anything.
- `suggestions(for: prefix)` answers for any prefix, without touching `query`. The prefix `""` matches every phrase.
- `type(_:)` should be O(1) apart from copying the at most `limit` results, however many phrases match.

## Examples

`Engine(history: ["swift": 5, "swiftui": 9, "switch": 2, "sweater": 5, "struct": 7])`, then:

| Call | Result |
| --- | --- |
| `type("s")` | `["swiftui", "struct", "sweater"]` |
| `type("w")` | `["swiftui", "sweater", "swift"]` |
| `type("i")` | `["swiftui", "swift", "switch"]` |
| `type("f")` | `["swiftui", "swift"]` |
| `type("x")` | `[]`: no phrase starts with "swifx" |
| `submit()`, then `suggestions(for: "swif")` | `["swiftui", "swift", "swifx"]` |

"sweater" and "swift" both have 5, so "sweater" comes first alphabetically. After the submit, "swifx" is a phrase with count 1.

With `["map": 3, "max": 3]`, typing "m" suggests `["map", "max"]`. Typing "max" and submitting makes its count 4, so typing "m" afterwards suggests `["max", "map"]`.

## Constraints

- Up to 20,000 phrases, each 1 to 30 characters of lowercase letters and spaces; counts from 1 to 1,000,000.
- `1 ≤ limit ≤ 10`.
- Up to 40,000 calls to `type`, with a submit every few characters.

<Hints>
<Hint>
Start from the trie in [Autocomplete](/dsa/learn/trie-autocomplete). Keep the node for the current query as you type, so each keystroke is one step down instead of a walk from the root. Once the query has no node, it stays without one until `submit()` or `clear()`.
</Hint>
<Hint>
Collecting and sorting every phrase below the node on each keystroke is slow for short prefixes, which match thousands of phrases. Instead, let every node **cache** its best `limit` phrases, with their counts, best first. Then a keystroke's answer is already waiting at the node.
</Hint>
<Hint>
Keeping the caches right: counts only go up, and a phrase can only appear in the caches of its own prefixes, which are exactly the nodes on its path. So when a phrase's count rises (in `init` or on `submit`), walk its path, creating nodes, and at each node update the phrase's entry or add it, re-sort the few entries, and drop the last if there are more than `limit`.
</Hint>
</Hints>

## Solutions

<Approach title="Collect and sort below the node on every keystroke" time="O(m log m) per keystroke for m matches" space="O(total characters)">

A plain trie with a count at each phrase's last node. Each keystroke walks to the query's node, collects every phrase below it with its count, sorts, and keeps the first `limit`. Submitting is a cheap count update. With 20,000 phrases, the first keystroke alone can collect thousands of them.

```swift
public func type(_ character: Character) -> [String] {
    typed.append(character)
    current = current?.children[character]
    guard let node = current else { return [] }
    var found: [(phrase: String, count: Int)] = []
    collect(node, path: typed, into: &found)          // depth-first, as in the trie lessons
    found.sort { $0.count != $1.count ? $0.count > $1.count : $0.phrase < $1.phrase }
    return found.prefix(limit).map(\.phrase)
}
```

</Approach>

<Approach title="A top-limit cache at every node" time="O(1) per keystroke, O(L × limit log limit) per submit" space="O(total characters × limit)">

The work moves from reading to writing: a submit updates up to L + 1 small caches, and every keystroke after that is a single dictionary step. That's the right trade for a search box, where keystrokes vastly outnumber submits.

```swift
public enum RankedSearchSuggestions {
    public final class Engine {
        private final class Node {
            var children: [Character: Node] = [:]
            var best: [(phrase: String, count: Int)] = []     // at most `limit`, best first
        }

        private let limit: Int
        private let root = Node()
        private var counts: [String: Int] = [:]
        private var typed = ""
        private var current: Node?                 // the node for `typed`, or nil if nothing matches

        public init(history: [String: Int], limit: Int = 3) {
            precondition(limit > 0, "Show at least one suggestion")
            self.limit = limit
            for (phrase, count) in history where !phrase.isEmpty && count > 0 {
                add(count, to: phrase)
            }
            current = root
        }

        public var query: String {
            typed
        }

        public func type(_ character: Character) -> [String] {
            typed.append(character)
            current = current?.children[character]         // nil stays nil: no phrase matches
            return current?.best.map(\.phrase) ?? []
        }

        public func submit() {
            guard !typed.isEmpty else { return }
            add(1, to: typed)
            clear()
        }

        public func clear() {
            typed = ""
            current = root
        }

        public func suggestions(for prefix: String) -> [String] {
            var node = root
            for character in prefix {
                guard let next = node.children[character] else { return [] }
                node = next
            }
            return node.best.map(\.phrase)
        }

        /// Raises the phrase's count, then offers it to every cache on its path, creating nodes.
        private func add(_ amount: Int, to phrase: String) {
            counts[phrase, default: 0] += amount
            let count = counts[phrase]!
            var node = root
            offer(phrase, count, to: node)
            for character in phrase {
                if let next = node.children[character] {
                    node = next
                } else {
                    let made = Node()
                    node.children[character] = made
                    node = made
                }
                offer(phrase, count, to: node)
            }
        }

        /// Only this phrase's count changed, and only upwards, so the rest of the cache keeps its
        /// order: update or add it, re-sort the few entries, and drop the worst if there are too many.
        private func offer(_ phrase: String, _ count: Int, to node: Node) {
            if let index = node.best.firstIndex(where: { $0.phrase == phrase }) {
                node.best[index].count = count
            } else {
                node.best.append((phrase, count))
            }
            node.best.sort { $0.count != $1.count ? $0.count > $1.count : $0.phrase < $1.phrase }
            if node.best.count > limit {
                node.best.removeLast()
            }
        }
    }
}
```

The root's cache answers the empty prefix. Iterating over `history` visits its phrases in an unpredictable order, but that doesn't matter: once every phrase has been offered, each cache holds the true top `limit`, because the ranking breaks every tie.

</Approach>
