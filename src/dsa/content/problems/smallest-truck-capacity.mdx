Parcels wait at a depot in a fixed line, and one truck leaves each day. The truck takes parcels from the front of the line, in order, and leaves as soon as the next parcel would take its load over its capacity. Parcels can't be reordered or split. Return the smallest capacity that clears every parcel within `days` days.

`SmallestTruckCapacity.minimumCapacity(parcels: [Int], days: Int) -> Int`

## Examples

| `parcels` | `days` | Output |
| --- | --- | --- |
| `[3, 8, 1, 5, 6, 2]` | `2` | `13` |
| `[3, 8, 1, 5, 6, 2]` | `3` | `11` |
| `[3, 8, 1, 5, 6, 2]` | `1` | `25` |
| `[3, 8, 1, 5, 6, 2]` | `6` | `8` |
| `[1, 1, 9, 9]` | `2` | `11` |
| `[9, 1, 1, 9]` | `2` | `10` |

With capacity 11 and 3 days, the truck carries [3, 8], then [1, 5], then [6, 2]. With capacity 10, it would need four days: [3], [8, 1], [5], [6, 2]. The last two examples hold the same weights in different orders, and need different capacities.

## Constraints

- `1 ≤ parcels.count ≤ 100,000`
- `1 ≤ parcels[i] ≤ 10⁹`
- `1 ≤ days ≤ 100,000`, and `days` may be more than the number of parcels.

<Hints>
<Hint>
For one capacity, simulate the loading: keep a running load, and start a new day whenever the next parcel won't fit. Count the days. This greedy loading is the best any plan can do for that capacity.
</Hint>
<Hint>
A bigger truck never needs more days, so "clears the line within `days` days" is monotonic in the capacity. Binary search for the smallest capacity where it's true.
</Hint>
<Hint>
The capacity can't be less than the heaviest parcel, or that parcel never leaves. Start there. A capacity equal to the total weight clears everything on day 1, so that's a safe top.
</Hint>
</Hints>

## Solutions

<Approach title="Try every capacity from the heaviest parcel up" time="O(n · S)" space="O(1)">

Starting at the heaviest parcel, try each capacity in turn until the greedy day count fits. S is the total weight. It works for tiny weights, but with weights up to a billion it could try trillions of capacities.

```swift
public static func minimumCapacity(parcels: [Int], days: Int) -> Int {
    var capacity = parcels.max()!
    while daysNeeded(parcels, capacity: capacity) > days {
        capacity += 1
    }
    return capacity
}
```

`daysNeeded` is the greedy count from the next approach.

</Approach>

<Approach title="Binary search on the capacity" time="O(n log S)" space="O(1)">

Search between the heaviest parcel and the total weight for the first capacity whose greedy day count fits. Both bounds are honest: nothing below the heaviest parcel can work, and the total always does. The lower bound also keeps the day count correct, because the simple loading loop assumes every parcel fits on an empty truck.

```swift
public enum SmallestTruckCapacity {
    public static func minimumCapacity(parcels: [Int], days: Int) -> Int {
        var low = parcels.max()!
        var high = parcels.reduce(0, +)
        while low < high {
            let mid = low + (high - low) / 2
            if daysNeeded(parcels, capacity: mid) <= days {
                high = mid
            } else {
                low = mid + 1
            }
        }
        return low
    }

    /// Days the greedy loading takes. Needs capacity ≥ the heaviest parcel.
    private static func daysNeeded(_ parcels: [Int], capacity: Int) -> Int {
        var days = 1
        var load = 0
        for weight in parcels {
            if load + weight > capacity {            // doesn't fit: it goes on tomorrow's truck
                days += 1
                load = 0
            }
            load += weight
        }
        return days
    }
}
```

The total weight is at most 10¹⁴, which fits in an `Int`, so the search makes at most about 47 checks.

</Approach>
