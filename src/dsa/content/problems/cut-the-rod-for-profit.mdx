A sawmill has one rod of length `length`. Buyers have made offers: `offers[i] = [pieceLength, price]` means a buyer pays `price` for every piece of exactly `pieceLength`, and will take as many such pieces as you cut. Pieces must have whole lengths, and any rod left over is waste worth nothing. Return the most money the rod can earn.

`RodCutForProfit.bestPrice(length: Int, offers: [[Int]]) -> Int`

## Examples

| `length` | `offers` | Output |
| --- | --- | --- |
| `7` | `[[2, 5], [3, 9]]` | `19` |
| `10` | `[[4, 9]]` | `18` |
| `9` | `[[4, 10], [5, 13]]` | `23` |
| `5` | `[[6, 100]]` | `0` |
| `6` | `[[3, 4], [3, 7]]` | `14` |

In the first example, cutting 3 + 2 + 2 earns 9 + 5 + 5 = 19, more than 3 + 3 (18, with 1 wasted). In the second, two pieces of 4 earn 18 and 2 is wasted. In the fourth, the only buyer wants pieces longer than the rod. In the last, two buyers want the same length, so sell to the one paying more.

## Constraints

- `0 ≤ length ≤ 100,000`
- `1 ≤ offers.count ≤ 50`
- `1 ≤ pieceLength ≤ 100,000` and `0 ≤ price ≤ 1,000,000`
- The tests cut a rod of 100,000 with 50 offers.

<Hints>
<Hint>
Each offer can be used any number of times. Which knapsack is that?
</Hint>
<Hint>
Unbounded: the rod's length is the capacity, each offer is an item with weight `pieceLength` and value `price`. Let `best[w]` be the most that `w` units of rod can earn. Since waste is allowed, every `best[w]` starts at 0.
</Hint>
<Hint>
For each offer, sweep `w` from `pieceLength` up to `length` (left to right, so the offer can be used again) and set `best[w] = max(best[w], best[w - pieceLength] + price)`.
</Hint>
</Hints>

## Solutions

<Approach title="Try every count of every offer" time="exponential" space="O(offers)">

Recursively choose how many pieces of the first offer to cut, then the second, and so on. It checks every plan, which is fine for a rod of 20 and far too slow for 100,000.

</Approach>

<Approach title="Unbounded knapsack" time="O(length · offers)" space="O(length)">

Process the offers one at a time, with the room loop running left to right so that `best[w - pieceLength]` may already include this offer. Starting every cell at 0 means leftover rod is allowed. Offers longer than the rod are skipped, which also keeps the `stride` from being asked to run backwards.

```swift
public enum RodCutForProfit {
    public static func bestPrice(length: Int, offers: [[Int]]) -> Int {
        var best = Array(repeating: 0, count: length + 1)
        for offer in offers where offer[0] <= length {
            let piece = offer[0]
            let price = offer[1]
            for w in stride(from: piece, through: length, by: 1) {    // left to right: reuse allowed
                best[w] = max(best[w], best[w - piece] + price)
            }
        }
        return best[length]
    }
}
```

The answer can be as large as 100,000 pieces at 1,000,000 each, 10¹¹, which fits easily in an `Int`. Duplicate offers for the same length need no special handling: the better one wins the `max`.

</Approach>
