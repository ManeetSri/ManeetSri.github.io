An arcade has a machine that takes a token worth `n`. It either pays out `n` coins, or hands back three new tokens worth `n / 2`, `n / 3` and `n / 4`, each rounded down. New tokens can go back into the machine in the same way, and a token worth 0 is worthless. Starting with a single token worth `token`, return the most coins you can end up with.

`TokenExchangeMachine.mostCoins(token: Int) -> Int`

## Examples

| `token` | Output | Why |
| --- | --- | --- |
| `24` | `27` | exchange it for 12, 8 and 6; exchange the 12 for 6, 4 and 3; cash everything: 6 + 4 + 3 + 8 + 6 |
| `11` | `11` | 5 + 3 + 2 is only 10, so cash it straight away |
| `100` | `120` | |
| `1` | `1` | exchanging gives tokens worth 0, 0 and 0 |
| `0` | `0` | |
| `1000000000000` | `7828351122081` | |

## Constraints

- `0 ≤ token ≤ 1,000,000,000,000` (10¹²)
- The answer fits in an `Int`.
- The tests use tokens worth up to 10¹², so neither an array with one entry per value nor the plain recursion will work.

<Hints>
<Hint>
For one token, there are only two choices: cash it, or exchange it and do the best you can with each of the three new tokens. So best(n) = the larger of n and best(n / 2) + best(n / 3) + best(n / 4).
</Hint>
<Hint>
That recursion asks about the same values many times: n / 2 / 3 and n / 3 / 2 are the same number. But you can't make an array of 10¹² entries. Which kind of memo only stores the keys that are actually reached?
</Hint>
<Hint>
A dictionary `[Int: Int]`, in a wrapper function with a nested recursive helper. Repeated division only ever reaches a few hundred different values, and each call at least halves n, so the recursion is only about 40 levels deep: safe even in a test.
</Hint>
</Hints>

## Solutions

<Approach title="Plain recursion" time="more than O(n)" space="O(log n)">

The recurrence written directly. It's correct, but each call makes three more, and the number of calls grows slightly faster than n itself: trillions of calls for the largest tokens.

```swift
public static func mostCoins(token: Int) -> Int {
    if token == 0 {
        return 0
    }
    return max(token, mostCoins(token: token / 2) + mostCoins(token: token / 3) + mostCoins(token: token / 4))
}
```

</Approach>

<Approach title="Memoised with a dictionary" time="O(log² n)" space="O(log² n)">

The same recursion with a dictionary memo, following [Top-down memoisation](/dsa/learn/dp-memoisation). Dividing by 4 is dividing by 2 twice, so every value reached is n divided by some 2ᵃ × 3ᵇ, rounded down: at most about 40 × 26 different keys for n = 10¹². This is a case where top-down beats bottom-up outright: a table would need an entry for every value up to n, but the recursion only visits the few it needs.

```swift
public enum TokenExchangeMachine {
    public static func mostCoins(token: Int) -> Int {
        var memo: [Int: Int] = [0: 0]

        func best(_ value: Int) -> Int {
            if let known = memo[value] {
                return known
            }
            let exchanged = best(value / 2) + best(value / 3) + best(value / 4)
            let result = max(value, exchanged)
            memo[value] = result
            return result
        }

        return best(token)
    }
}
```

Putting the base case into the memo (`[0: 0]`) saves a separate `if`. Below 12, exchanging never gains anything (11 becomes 5 + 3 + 2 = 10, and 10 becomes exactly 10), so you could also stop the recursion early with `if value < 12 { return value }`.

</Approach>
