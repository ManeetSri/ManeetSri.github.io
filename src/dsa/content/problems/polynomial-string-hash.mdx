Implement the polynomial string hash from the lesson, for any base and modulus, then use it to see how a list of words spreads across buckets.

`PolynomialStringHash.hash(of text: String, base: Int, modulus: Int) -> Int` and `PolynomialStringHash.bucketSizes(for words: [String], bucketCount: Int) -> [Int]`

**Part 1: the hash.** Start with h = 0. For each Unicode scalar of `text` in order, with value c, set h = (h × base + c) % modulus. Return h.

**Part 2: buckets.** Put each word in bucket `hash(of: word, base: 31, modulus: bucketCount)`. Return an array of `bucketCount` numbers: how many words landed in bucket 0, bucket 1, and so on.

## Examples

| Call | Result |
| --- | --- |
| `hash(of: "ab", base: 31, modulus: 1_000_000_007)` | `3105` (97 × 31 + 98) |
| `hash(of: "abc", base: 10, modulus: 1_000)` | `779` |
| `hash(of: "", base: 31, modulus: 13)` | `0` |
| `bucketSizes(for: ["stop", "pots", "tops", "spot", "opts", "post"], bucketCount: 8)` | `[2, 0, 2, 0, 0, 0, 2, 0]` |
| `bucketSizes(for: [], bucketCount: 3)` | `[0, 0, 0]` |

The fourth example shows a weakness: with base 31 and 8 buckets, these anagrams still pair up. Try 7 or 11 buckets and they spread out more.

## Constraints

- `text.unicodeScalars.count ≤ 100,000`
- `1 ≤ base ≤ 1,000,000` and `1 ≤ modulus ≤ 1,000,000,007`
- `1 ≤ bucketCount ≤ 100,000` and `words.count ≤ 10,000`
- Your hash must never overflow, whatever the length of the text.

<Hints>
<Hint>
Loop over `text.unicodeScalars` and use `Int(scalar.value)` for each scalar's number.
</Hint>
<Hint>
If you compute the whole polynomial first and take the remainder at the end, a long string overflows `Int` and crashes. Take the remainder after every step: then h stays below the modulus, so h × base + c is at most about 10¹⁵, far inside `Int`'s range.
</Hint>
<Hint>
For the buckets, start with `Array(repeating: 0, count: bucketCount)` and add 1 at each word's hash.
</Hint>
</Hints>

## Solutions

<Approach title="Horner's rule with a remainder at every step" time="O(n) per hash; O(total letters + bucketCount) for the buckets" space="O(1) for the hash; O(bucketCount) for the buckets">

Multiplying by the base before adding each scalar is Horner's rule: it evaluates s₀ × baseⁿ⁻¹ + s₁ × baseⁿ⁻² + … + sₙ₋₁ without computing any powers. Because (a × b + c) % m gives the same result whether or not you reduce a first, taking the remainder every step gives the same answer as reducing once at the end, without the overflow.

```swift
public enum PolynomialStringHash {
    public static func hash(of text: String, base: Int, modulus: Int) -> Int {
        var hash = 0
        for scalar in text.unicodeScalars {
            hash = (hash * base + Int(scalar.value)) % modulus
        }
        return hash
    }

    public static func bucketSizes(for words: [String], bucketCount: Int) -> [Int] {
        var sizes = Array(repeating: 0, count: bucketCount)
        for word in words {
            sizes[hash(of: word, base: 31, modulus: bucketCount)] += 1
        }
        return sizes
    }
}
```

All the values involved are non-negative, so `%` never produces a negative index here.

</Approach>
