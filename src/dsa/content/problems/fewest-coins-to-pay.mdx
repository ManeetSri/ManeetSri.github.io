You have unlimited coins of each value in `coins`. Return the **fewest** coins that add up to exactly `amount`, or `-1` if no combination of coins makes it.

`FewestCoinsToPay.fewest(coins: [Int], amount: Int) -> Int`

## Examples

| `coins` | `amount` | Output |
| --- | --- | --- |
| `[1, 5, 6, 9]` | `11` | `2` |
| `[5, 7]` | `24` | `4` |
| `[4, 6]` | `9` | `-1` |
| `[3]` | `0` | `0` |
| `[10, 1]` | `13` | `4` |

In the first example, 5 + 6 = 11. Taking the biggest coin first gives 9 + 1 + 1, three coins. In the second, 7 + 7 + 5 + 5; biggest-first takes three 7s and gets stuck at 3. In the third, every coin is even. Paying 0 needs no coins.

## Constraints

- `1 ≤ coins.count ≤ 20`
- `1 ≤ coins[i] ≤ 100,000`
- `0 ≤ amount ≤ 100,000`

<Hints>
<Hint>
Biggest coin first is wrong for many coin systems. Think about the **last** coin of the best payment instead.
</Hint>
<Hint>
If the last coin is `c`, the rest is the best payment for `amount - c`. So `fewest[t] = 1 + min(fewest[t - c])` over the coins `c ≤ t`, with `fewest[0] = 0`.
</Hint>
<Hint>
Mark impossible totals with `amount + 1`: no real answer uses that many coins, and adding 1 to it can't overflow, unlike `Int.max`.
</Hint>
</Hints>

## Solutions

<Approach title="Try every count of every coin" time="exponential" space="O(coins)">

Recursively choose how many of the first coin to use, then the second, and keep the smallest total that makes the amount exactly. Correct, and useful for testing small amounts, but the number of combinations explodes.

</Approach>

<Approach title="DP over the amount" time="O(amount · coins)" space="O(amount)">

Fill `fewest` from 0 up to the amount. Each total tries every coin as its last coin. The loop order doesn't matter for a minimum: whichever order you imagine the coins being paid in, a collection of coins has the same size.

```swift
public enum FewestCoinsToPay {
    public static func fewest(coins: [Int], amount: Int) -> Int {
        let impossible = amount + 1
        var fewest = Array(repeating: impossible, count: amount + 1)
        fewest[0] = 0
        for total in stride(from: 1, through: amount, by: 1) {
            for coin in coins where coin <= total {
                fewest[total] = min(fewest[total], fewest[total - coin] + 1)
            }
        }
        return fewest[amount] == impossible ? -1 : fewest[amount]
    }
}
```

`stride(from: 1, through: amount, by: 1)` is empty for amount 0, so the answer is `fewest[0] = 0` without a special case.

</Approach>

<Approach title="Breadth-first search over amounts" time="O(amount · coins)" space="O(amount)">

Think of every total from 0 to `amount` as a vertex, with an edge from `t` to `t + c` for each coin. The fewest coins is then the length of the shortest path from 0 to `amount`, which BFS finds level by level. It does the same amount of work as the DP and is a nice way to check it.

</Approach>
