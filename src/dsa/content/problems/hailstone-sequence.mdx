The **hailstone sequence** starting from a positive whole number follows one rule: if the number is even, halve it; if it's odd, multiply by 3 and add 1. Repeat until you reach 1. The numbers rise and fall like hailstones in a cloud before finally landing at 1. (That every start reaches 1 is a famous unproven idea called the Collatz conjecture, but it's been checked far beyond the numbers here.)

Make the sequence work with `for-in` by finishing its iterator, then use it to answer two questions.

`HailstoneSequence.Hailstone.Iterator.next() -> Int?`, `HailstoneSequence.stepsToOne(from start: Int) -> Int` and `HailstoneSequence.peak(from start: Int) -> Int`

- `Hailstone(start:)` and its `makeIterator()` are already written. The iterator stores `upcoming`, the value its next call will return (`nil` once finished). Write `next()`: return `upcoming`, and work out the value after it. The sequence includes the start and ends with 1.
- `stepsToOne(from:)` returns how many rule applications it takes to reach 1.
- `peak(from:)` returns the largest value in the sequence.

Try to use `Hailstone` in both functions rather than repeating the rule.

## Examples

| Code | Result |
| --- | --- |
| `Array(Hailstone(start: 6))` | `[6, 3, 10, 5, 16, 8, 4, 2, 1]` |
| `Array(Hailstone(start: 1))` | `[1]` |
| `stepsToOne(from: 6)` | `8` |
| `stepsToOne(from: 27)` | `111` |
| `peak(from: 7)` | `52` |
| `peak(from: 27)` | `9232` |

## Constraints

- `1 ≤ start ≤ 1,000,000`
- The values can climb into the tens of billions, which fits in an `Int`.
- Looping over the same `Hailstone` twice must give the same values both times.

<Hints>
<Hint>
In `next()`, use `guard let value = upcoming else { return nil }`. Then set `upcoming` to the value after `value`, and return `value`.
</Hint>
<Hint>
When `value` is 1, the sequence ends: set `upcoming` to `nil`, so the following call returns `nil`. Otherwise apply the rule; `value.isMultiple(of: 2)` tells you whether it's even.
</Hint>
<Hint>
A sequence of L values has L − 1 steps, so `stepsToOne` can count the values in a `for-in` loop and subtract one. Since `Hailstone` is a `Sequence`, `peak` can be `Hailstone(start: start).max()`.
</Hint>
</Hints>

## Solutions

<Approach title="An iterator that remembers the next value" time="O(L) for a sequence of L values" space="O(1)">

The iterator holds just one number, the one it will return next. Each call returns it and computes its successor. Because the sequence is a `Sequence`, the two questions are short loops or a single `max()`, and nothing is stored along the way.

```swift
public enum HailstoneSequence {
    public struct Hailstone: Sequence {
        public let start: Int

        public init(start: Int) {
            self.start = start
        }

        public func makeIterator() -> Iterator {
            Iterator(upcoming: start)
        }

        public struct Iterator: IteratorProtocol {
            var upcoming: Int?

            public mutating func next() -> Int? {
                guard let value = upcoming else { return nil }
                if value == 1 {
                    upcoming = nil
                } else if value.isMultiple(of: 2) {
                    upcoming = value / 2
                } else {
                    upcoming = 3 * value + 1
                }
                return value
            }
        }
    }

    public static func stepsToOne(from start: Int) -> Int {
        var steps = -1
        for _ in Hailstone(start: start) {
            steps += 1
        }
        return steps
    }

    public static func peak(from start: Int) -> Int {
        Hailstone(start: start).max() ?? start
    }
}
```

`Hailstone` itself never changes: each `for-in` loop gets a fresh iterator from `makeIterator()`, which is why looping twice gives the same result. Starting `steps` at −1 means the first value, the start itself, isn't counted as a step.

</Approach>
