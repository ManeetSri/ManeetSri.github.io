A spell checker stores its dictionary of n words in a binary search tree that never changes, so it can be built once in the best possible shape. From a log of past lookups it knows two things. `hits[i]` is how many lookups found word i (the words are in sorted order). `misses[g]` is how many looked for a word that **isn't** in the dictionary and falls in gap g: before the first word for g = 0, between words g − 1 and g, or after the last word for g = n.

A lookup costs one comparison for each word it visits on its way down, counting the root. So finding a word at depth d costs d, and a miss costs the depth of the last word it was compared with, where it falls off the tree. Return the smallest total cost of all the logged lookups, over every BST that holds the n words.

`SpellcheckLookupTree.cheapestCost(hits: [Int], misses: [Int]) -> Int`

## Examples

| `hits` | `misses` | Output |
| --- | --- | --- |
| `[4, 2, 6, 3]` | `[0, 0, 0, 0, 0]` | `26` |
| `[1, 1]` | `[0, 0, 10]` | `13` |
| `[3]` | `[1, 2]` | `6` |
| `[0, 0, 0]` | `[1, 1, 1, 1]` | `8` |
| `[]` | `[7]` | `0` |

The first is the lesson's example, with no misses. In the second, the two words are equally popular, but ten lookups fall after the last one. With word 1 at the root, those misses stop after one comparison: 1 + 2 for the hits plus 10 for the misses gives 13. With word 0 at the root they'd need two each, for 23. In the fourth, only misses are logged, and the balanced tree sends each of them past exactly two words. An empty dictionary makes no comparisons at all.

## Constraints

- `0 ≤ hits.count ≤ 300` and `misses.count == hits.count + 1`.
- `0 ≤ hits[i], misses[g] ≤ 1,000,000`.
- The tests try every tree shape for small dictionaries and use up to 255 words, so an O(n³) DP with prefix sums is fast enough, and an O(n⁴) one isn't.

<Hints>
<Hint>
As in the lesson, any subtree holds a contiguous range of words, say words `i..<j`. Which gaps does it hold? Every miss that falls between two of its words, or just outside them, ends inside it: gaps `i...j`.
</Hint>
<Hint>
Choose a root r for words `i..<j`. Its left subtree holds words `i..<r` with gaps `i...r`, its right subtree words `r + 1..<j` with gaps `r + 1...j`, and every lookup that ends anywhere in the range pays one comparison at r. So `cost[i][j] = min over r of cost[i][r] + cost[r + 1][j]`, plus the range's weight.
</Hint>
<Hint>
The weight of words `i..<j` is `hits[i] + … + hits[j − 1]` plus `misses[i] + … + misses[j]`: one more gap than words. An empty range, `cost[i][i]`, is 0, because a miss that reaches it has already been charged for every comparison it made. Use two prefix-sum arrays to get each weight in O(1).
</Hint>
</Hints>

## Solutions

<Approach title="Try every tree" time="exponential" space="O(n)">

Recursively try every root for every range, passing the depth down and charging each word its depth times its hits and each empty gap the depth of its parent. It's a direct definition of the cost and makes a good test, but the number of BSTs on n keys is the Catalan number, about 10¹⁴⁹ for 255 words.

</Approach>

<Approach title="Interval DP over half-open ranges" time="O(n³)" space="O(n²)">

The only change from the lesson's DP is the weight. Half-open ranges make the gaps line up neatly: words `i..<j` own gaps `i...j`, so the weight uses `missPrefix[j + 1] − missPrefix[i]`.

```swift
public enum SpellcheckLookupTree {
    public static func cheapestCost(hits: [Int], misses: [Int]) -> Int {
        let n = hits.count
        var hitPrefix = [0]                                   // hitPrefix[i]: hits[0] + … + hits[i - 1]
        for h in hits { hitPrefix.append(hitPrefix.last! + h) }
        var missPrefix = [0]
        for m in misses { missPrefix.append(missPrefix.last! + m) }
        /// Every search ending in keys i..<j or gaps i...j
        func weight(_ i: Int, _ j: Int) -> Int {
            hitPrefix[j] - hitPrefix[i] + missPrefix[j + 1] - missPrefix[i]
        }
        var cost = Array(repeating: Array(repeating: 0, count: n + 1), count: n + 1)
        for length in stride(from: 1, through: n, by: 1) {
            for i in 0...(n - length) {
                let j = i + length
                var best = Int.max
                for r in i..<j {
                    best = min(best, cost[i][r] + cost[r + 1][j])   // left: i..<r, right: r + 1..<j
                }
                cost[i][j] = best + weight(i, j)
            }
        }
        return cost[0][n]
    }
}
```

With no words, the loops never run and `cost[0][0]` is 0, which is right: there's nothing to compare with. Why is a miss charged correctly? Each range's weight includes every miss that ends inside it, once per range on the miss's path that has a root, which is exactly once per word it's compared with. The largest possible total is 601 counts of 10⁶ lookups, each costing at most 300 comparisons: under 2 × 10¹¹, far inside `Int`.

</Approach>
