A street has houses in a row and a choice of paint colours. `costs[i][c]` is the cost of painting house i with colour c. No two neighbouring houses may be the same colour. Return the cheapest total cost of painting every house, `0` if there are no houses, or `-1` if it can't be done.

`HousePaintingCost.minimumCost(_ costs: [[Int]]) -> Int`

## Examples

| `costs` | Output |
| --- | --- |
| `[[7, 3, 8, 6], [5, 6, 2, 9], [4, 9, 6, 5], [8, 1, 7, 3]]` | `10` |
| `[[1, 2], [1, 10]]` | `3` |
| `[[4, 2, 7]]` | `2` |
| `[[5], [3]]` | `-1` |
| `[]` | `0` |

In the first example, the colours 1, 2, 0, 1 cost 3 + 2 + 4 + 1. In the second, the cheapest colour for the first house (1) forces a cost of 10 on the second; starting with the 2 is better. In the fourth, with only one colour, two neighbours can't differ.

## Constraints

- `0 ≤ costs.count ≤ 2,000` houses, and `1 ≤ costs[i].count ≤ 500` colours, the same for every house.
- `0 ≤ costs[i][c] ≤ 10,000`
- The tests use 2,000 houses with 500 colours, where checking every pair of colours for every house takes 500 million steps.

<Hints>
<Hint>
The state is the colour of the current house. `best[c]` = `costs[i][c]` + the cheapest total for the previous house in any colour other than c.
</Hint>
<Hint>
Done directly, that's O(k) per colour and O(k²) per house. But "the cheapest of every other colour" can only be one of two values. Which two?
</Hint>
<Hint>
Find the previous house's lowest total, the colour that gave it, and the second-lowest total. Colour c adds the lowest, unless c is that colour, in which case the second-lowest. Handle a single colour separately.
</Hint>
</Hints>

## Solutions

<Approach title="Every other colour, directly" time="O(n × k²)" space="O(k)">

For each house and colour, scan the previous house's totals for every other colour. It's the plain DP and it's correct, but 2,000 × 500 × 500 is too slow.

</Approach>

<Approach title="Best and second best" time="O(n × k)" space="O(k)">

One scan of the previous totals finds everything each colour needs. Ties work out: if two colours share the lowest total, the second-lowest equals it.

```swift
public enum HousePaintingCost {
    public static func minimumCost(_ costs: [[Int]]) -> Int {
        guard var previous = costs.first else { return 0 }
        if previous.count == 1 {
            return costs.count == 1 ? previous[0] : -1        // one colour can't paint two neighbours
        }
        for house in costs.dropFirst() {
            var lowest = Int.max, secondLowest = Int.max, lowestColour = -1
            for (colour, total) in previous.enumerated() {
                if total < lowest {
                    (secondLowest, lowest, lowestColour) = (lowest, total, colour)
                } else if total < secondLowest {
                    secondLowest = total
                }
            }
            for colour in house.indices {
                previous[colour] = house[colour] + (colour == lowestColour ? secondLowest : lowest)
            }
        }
        return previous.min()!
    }
}
```

The single-colour check matters twice over: it gives the `-1`, and it stops `secondLowest` from staying `Int.max`, which would overflow when added to a cost.

</Approach>
