A nested list holds numbers and other nested lists, to any depth. Build an iterator that hands out its numbers one at a time, left to right, **lazily**: creating the iterator does no work, and each call does only what it needs to reach the next number. It also offers `peek()`, a look at the next number that doesn't consume it.

`LazyNestedIterator.Flattener`, conforming to `IteratorProtocol` and `Sequence`, with `init(_ items: [Item])`, `peek() -> Int?` and `next() -> Int?`

`Item` is given: `enum Item { case number(Int), list([Item]) }`.

- `next()` returns the next number and moves past it, or `nil` once there are none left (and on every call after that).
- `peek()` returns what `next()` would return, without moving. Calling it twice in a row returns the same number.
- `init` must be O(1). Over a whole pass, the work must be O(total number of items, counting every list), and the extra memory O(depth of nesting).

## Examples

Writing `[1, [2, [3, []], 4], [], 5]` for `[.number(1), .list([.number(2), …]), …]`:

| Items | Calls | Results |
| --- | --- | --- |
| `[1, [2, [3, []], 4], [], 5]` | `next()` until `nil` | `1, 2, 3, 4, 5, nil` |
| `[[], 4, [[5]], []]` | `peek()`, `peek()`, `next()`, `peek()`, `next()`, `peek()` | `4, 4, 4, 5, 5, nil` |
| `[[], [[]], [[[]]]]` | `next()` | `nil` |
| `[3, [1, [4]], 1, [5]]` | `Array(Flattener(items))` | `[3, 1, 4, 1, 5]` |

The second row shows the point of `peek()`: it can be called any number of times, and the number stays until `next()` takes it. Empty lists, however deeply nested, produce nothing.

## Constraints

- Up to 300,000 items in total, nested up to 500 deep.
- Lists can be empty, and a list can contain thousands of empty lists in a row.
- One test creates thousands of iterators over 200,000 numbers and takes only the first two from each, so flattening everything in `init` is too slow.

<Hints>
<Hint>
An eager flatten is a recursive walk. To pause in the middle of it, keep the walk's state yourself: a stack of frames, each holding one list and the position of its next unvisited item. The top frame is the list you're currently inside.
</Hint>
<Hint>
Write one private helper, `settle()`, that moves until the top frame points at a number: if the top list is used up, pop it; if the item at its position is a list, step past it in the parent and push a frame for the inner list. Stop when the top frame points at a number, or when the stack is empty.
</Hint>
<Hint>
Then `peek()` is "settle, then read the number at the top frame's position", and `next()` is "peek, then advance the top frame's position". Because `settle()` stops **at** a number without consuming it, calling `peek()` again settles nothing and returns the same number.
</Hint>
</Hints>

## Solutions

<Approach title="Flatten everything in init" time="O(n) init, O(1) per call" space="O(n)">

The tempting version: walk the whole structure recursively in `init`, store every number in an array, and hand them out with an index. It's correct, but it does all the work up front even if the caller wants only the first number, it holds a copy of every number, and its recursion depth is the nesting depth. Here it fails the "does no work up front" test.

```swift
public init(_ items: [Item]) {
    func walk(_ items: [Item]) {
        for item in items {
            switch item {
            case .number(let value): numbers.append(value)
            case .list(let inner): walk(inner)
            }
        }
    }
    walk(items)
}
```

</Approach>

<Approach title="A stack of (list, position) frames" time="O(1) init, amortised O(1) per number" space="O(depth)">

The stack replaces the recursion. Arrays are copy-on-write, so pushing a frame for an inner list shares its storage rather than copying it. Each item is stepped over exactly once in a whole pass, which is why the loop in `settle()` costs O(1) per item on average even though one call can skip thousands of empty lists.

```swift
public enum LazyNestedIterator {
    public enum Item: Equatable {
        case number(Int)
        case list([Item])
    }

    public struct Flattener: IteratorProtocol, Sequence {
        private var frames: [(items: [Item], position: Int)]

        public init(_ items: [Item]) {
            frames = [(items, 0)]
        }

        /// Leaves the top frame pointing at a number, or empties the stack if none are left.
        private mutating func settle() {
            while let top = frames.last {
                if top.position == top.items.count {
                    frames.removeLast()                         // this list is finished
                    continue
                }
                switch top.items[top.position] {
                case .number:
                    return
                case .list(let inner):
                    frames[frames.count - 1].position += 1      // step past the list in its parent,
                    frames.append((inner, 0))                   // then into it
                }
            }
        }

        public mutating func peek() -> Int? {
            settle()
            guard let top = frames.last, case .number(let value) = top.items[top.position] else {
                return nil
            }
            return value
        }

        public mutating func next() -> Int? {
            guard let value = peek() else { return nil }
            frames[frames.count - 1].position += 1              // consume it
            return value
        }
    }
}
```

Advancing the parent's position **before** pushing the inner list matters: when the inner list is used up and popped, the parent is already pointing past it.

</Approach>
