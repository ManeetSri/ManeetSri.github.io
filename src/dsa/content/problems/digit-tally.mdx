Count how many digits a whole number has. A minus sign isn't a digit, and 0 has one digit.

`DigitTally.count(of number: Int) -> Int`

Solve it with a loop and arithmetic, without converting the number to a `String`.

## Examples

| Input | Output |
| --- | --- |
| `4721` | `4` |
| `100` | `3` |
| `7` | `1` |
| `0` | `1` |
| `-305` | `3` |

## Constraints

- `-10¹⁸ ≤ number ≤ 10¹⁸`

<Hints>
<Hint>
`n / 10` removes the last digit of a number. Count how many times you can do that before nothing is left.
</Hint>
<Hint>
`while n != 0` never runs for 0, which would give 0 digits. Which loop always runs at least once?
</Hint>
<Hint>
You don't need to remove the minus sign. In Swift, `-305 / 10` is `-30`: integer division moves negative numbers towards zero too, so the loop ends at 0 either way.
</Hint>
</Hints>

## Solutions

<Approach title="Divide by 10 until nothing is left" time="O(d)" space="O(1)">

Each pass removes one digit and counts it. `repeat-while` runs the body before checking, so 0 counts as one digit without a special case. The condition `remaining != 0`, rather than `remaining > 0`, works for negative numbers as well.

```swift
public enum DigitTally {
    public static func count(of number: Int) -> Int {
        var remaining = number
        var digits = 0
        repeat {
            digits += 1
            remaining /= 10
        } while remaining != 0
        return digits
    }
}
```

The loop runs once per digit, d times, and a 64-bit `Int` has at most 19 digits, so it's always fast.

</Approach>

<Approach title="A while loop with a guard" time="O(d)" space="O(1)">

With a plain `while` loop, handle 0 first, since the loop would never run for it:

```swift
public static func count(of number: Int) -> Int {
    guard number != 0 else { return 1 }
    var remaining = number
    var digits = 0
    while remaining != 0 {
        digits += 1
        remaining /= 10
    }
    return digits
}
```

Avoid `abs(number)` or `-number` to remove the sign: for the smallest possible `Int`, flipping the sign overflows and crashes. Dividing never does.

</Approach>
