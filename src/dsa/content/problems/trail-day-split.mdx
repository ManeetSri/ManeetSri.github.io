A long-distance trail is a sequence of stages with given lengths in kilometres. Plan it as exactly `days` days of walking: each day covers one or more whole stages, in order, and every stage is walked. Return the smallest possible length of the longest day. If there are fewer stages than days, some day would have nothing to walk, so return −1.

`TrailDaySplit.shortestLongestDay(stages: [Int], days: Int) -> Int`

## Examples

| `stages` | `days` | Output |
| --- | --- | --- |
| `[12, 5, 7, 10, 3, 9]` | `3` | `17` |
| `[12, 5, 7, 10, 3, 9]` | `2` | `24` |
| `[12, 5, 7, 10, 3, 9]` | `6` | `12` |
| `[12, 5, 7, 10, 3, 9]` | `7` | `-1` |
| `[1, 1, 1, 1, 20]` | `2` | `20` |
| `[1, 1, 1, 1]` | `3` | `2` |

In the first example, the days [12, 5], [7, 10] and [3, 9] are 17, 17 and 12 km long. No plan keeps every day to 16 km. In the last example, the plan [1, 1], [1], [1] has a longest day of 2: every day must walk at least one stage, so you can't put all four stages on one day and leave two days empty.

## Constraints

- `1 ≤ stages.count ≤ 100,000`
- `1 ≤ stages[i] ≤ 10⁹`
- `1 ≤ days ≤ 100,000`

<Hints>
<Hint>
Start with a brute force that tries every way to place the cuts between days (recursion works well). It's far too slow for 100,000 stages, but you'll want it to check a faster solution on small trails.
</Hint>
<Hint>
Ask a yes/no question instead: can the trail be walked with no day longer than x? Walk greedily: keep adding stages to today while they fit within x, then start a new day. The number of days this needs is the fewest possible for that x, and it never grows as x grows.
</Hint>
<Hint>
Greedy may need fewer days than `days`. That's fine as long as there are at least `days` stages: you can split any day that has two or more stages, which never makes a day longer. Binary search x between the longest stage and the whole trail's length.
</Hint>
</Hints>

## Solutions

<Approach title="Try every split" time="O(C(n − 1, days − 1) · n)" space="O(days) for the recursion">

Choose where the first day ends, leaving at least one stage for each remaining day, and split the rest recursively. Keep the best largest day. The number of splits grows explosively: about 1.7 × 10¹² for 100 stages and 10 days.

```swift
public static func shortestLongestDay(stages: [Int], days: Int) -> Int {
    guard days <= stages.count else { return -1 }
    return best(stages, from: 0, days: days)
}

private static func best(_ stages: [Int], from start: Int, days: Int) -> Int {
    if days == 1 { return stages[start...].reduce(0, +) }
    var answer = Int.max
    var today = 0
    for end in start...(stages.count - days) {
        today += stages[end]
        answer = min(answer, max(today, best(stages, from: end + 1, days: days - 1)))
    }
    return answer
}
```

</Approach>

<Approach title="Binary search on the longest day, with a greedy check" time="O(n log S)" space="O(1)">

The longest day is at least the longest stage, and at most the total length S. For a limit in between, the greedy walk gives the fewest days that respect it: each greedy day ends at or after the matching day of any other plan, so greedy is never behind. If greedy needs at most `days` days, an exact plan exists too, by splitting days until there are enough. So "fits in at most `days` days" is the monotonic predicate, and the answer is its first true.

```swift
public enum TrailDaySplit {
    public static func shortestLongestDay(stages: [Int], days: Int) -> Int {
        guard days <= stages.count else { return -1 }    // someone would walk nothing
        var low = stages.max()!                          // the longest stage happens on some day
        var high = stages.reduce(0, +)                   // one day walks the whole trail
        while low < high {
            let mid = low + (high - low) / 2
            if daysNeeded(stages, limit: mid) <= days {
                high = mid
            } else {
                low = mid + 1
            }
        }
        return low
    }

    /// Days the greedy plan needs when no day may exceed `limit`. Needs limit ≥ the longest stage.
    private static func daysNeeded(_ stages: [Int], limit: Int) -> Int {
        var days = 1
        var today = 0
        for length in stages {
            if today + length > limit {
                days += 1
                today = 0
            }
            today += length
        }
        return days
    }
}
```

This is the split array largest sum problem, also known as book allocation. Checking `daysNeeded == days` instead of `<= days` would break it: a generous limit needs fewer greedy days, and the search would wrongly reject it.

</Approach>
