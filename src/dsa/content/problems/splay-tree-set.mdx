A spell checker looks up the same few hundred words over and over. Build it a **splay tree**: a set of `Int`s that moves every key it touches to the root, so recently used keys stay cheap to reach.

`SplayingSet.SplaySet`, a class with `root`, `count`, `contains(_:)`, `insert(_:)` and `remove(_:)`. `Node` (with `key`, `left` and `right`), `sortedKeys` and `height` are written for you.

What each operation must leave behind (the tests check these exactly):

- **`contains(k)`** returns whether `k` is in the set, and splays: afterwards the root is the node holding `k`, or, if `k` is missing, the **last node visited** while searching for it.
- **`insert(k)`** returns `true` if `k` was new. Either way, `k` is at the root afterwards.
- **`remove(k)`** returns `true` if `k` was there. On a miss, it splays the last node visited, like `contains`. On a hit, it splays `k` to the root, removes it, and joins the two subtrees by splaying the largest key of the left subtree to its root and hanging the right subtree there. So if any smaller key exists, the new root is the largest key smaller than `k`.

Splaying must use the real **zig, zig-zig and zig-zag** steps: in a zig-zig, rotate at the grandparent first. Simply rotating the key up one level at a time ("move to root") passes the rules above but fails the tests, because it leaves long paths in place.

## Examples

| Code | Result |
| --- | --- |
| insert 1, 2, …, 500 in order | each insert puts its key at the root, so the tree is a chain 500 tall with 500 at the root |
| then `contains(1)` | `true`; 1 is the root, and the tree is now about 250 tall: zig-zigs halve the path |
| then `contains(2)` | `true`; 2 is the root, and the tree is about 125 tall |
| a set holding 10, 20, 30; `contains(25)` | `false`; the root is now 20 or 30, whichever the search for 25 reached last |
| a set holding 10, 20, 30; `remove(20)` | `true`; the root is 10 and `sortedKeys` is `[10, 30]` |
| `insert(5)` twice | `true`, then `false`; `count` is 1 |

## Constraints

- Up to 200,000 operations, with keys of any `Int`.
- The tests build chains up to 500 nodes deep. A recursive splay makes one call per two levels, which is fine at that depth; a top-down splay, which needs no recursion at all, is what production code uses.
- Each operation should be O(log n) amortised.

<Hint>
Write `rotateLeft` and `rotateRight` that take a subtree's root and return the new root, then a `splay(_ node: Node?, _ key: Int) -> Node?` that returns the root of the same subtree with `key`, or the last node on its search path, on top. The lesson's recursive version handles two levels per call.
</Hint>
<Hint>
Each case looks two steps down. If the key is in the left child's left subtree (zig-zig), splay it to the top of that grandchild subtree, rotate right at the root, then rotate right again. If it's in the left child's right subtree (zig-zag), splay it there, rotate left at the child, then right at the root. If the left child is missing, stop: the root is the last node visited. Mirror everything for the right side.
</Hint>
<Hint>
With `splay` done, the rest is short. `contains`: splay, then compare the root's key. `insert`: splay the key, and if the root isn't it, make a new node whose children are the root and one of the root's subtrees, so the new key sits on top. `remove`: splay the key; if found, splay the same key again in the left subtree, which brings its largest key up with no right child, and attach the right subtree there.
</Hint>

## Solutions

<Approach title="Recursive bottom-up splaying" time="O(log n) amortised" space="O(h) stack">

This is the lesson's `splay`, wrapped in a class. Every operation, hit or miss, ends with a splay, which is what the amortised analysis needs: a long search path is always shortened, so its cost is paid for by the potential it releases.

```swift
public enum SplayingSet {
    public final class Node {
        public let key: Int
        public var left: Node?
        public var right: Node?
        public init(_ key: Int) { self.key = key }
    }

    public final class SplaySet {
        public private(set) var root: Node?
        public private(set) var count = 0

        public init() {}

        public func contains(_ key: Int) -> Bool {
            root = Self.splay(root, key)
            return root?.key == key
        }

        @discardableResult
        public func insert(_ key: Int) -> Bool {
            guard let top = Self.splay(root, key) else {
                root = Node(key)
                count = 1
                return true
            }
            if top.key == key { root = top; return false }
            let node = Node(key)
            if key < top.key {
                node.left = top.left                     // smaller keys stay on the left
                node.right = top
                top.left = nil
            } else {
                node.right = top.right
                node.left = top
                top.right = nil
            }
            root = node
            count += 1
            return true
        }

        @discardableResult
        public func remove(_ key: Int) -> Bool {
            root = Self.splay(root, key)
            guard let top = root, top.key == key else { return false }
            if let left = top.left {
                let joined = Self.splay(left, key)!      // the largest key of the left subtree…
                joined.right = top.right                 // …has no right child: hang the right subtree there
                root = joined
            } else {
                root = top.right
            }
            count -= 1
            return true
        }

        private static func rotateRight(_ y: Node) -> Node {
            let x = y.left!
            y.left = x.right
            x.right = y
            return x
        }

        private static func rotateLeft(_ x: Node) -> Node {
            let y = x.right!
            x.right = y.left
            y.left = x
            return y
        }

        /// Brings key, or the last node on its search path, to the top of this subtree.
        private static func splay(_ root: Node?, _ key: Int) -> Node? {
            guard let root, root.key != key else { return root }
            if key < root.key {
                guard let child = root.left else { return root }
                if key < child.key {                                       // zig-zig
                    child.left = splay(child.left, key)
                    let lifted = rotateRight(root)                         // grandparent first
                    return lifted.left == nil ? lifted : rotateRight(lifted)
                } else if key > child.key {                                // zig-zag
                    child.right = splay(child.right, key)
                    if child.right != nil { root.left = rotateLeft(child) }
                    return root.left == nil ? root : rotateRight(root)
                }
                return rotateRight(root)                                   // zig
            } else {
                guard let child = root.right else { return root }
                if key > child.key {
                    child.right = splay(child.right, key)
                    let lifted = rotateLeft(root)
                    return lifted.right == nil ? lifted : rotateLeft(lifted)
                } else if key < child.key {
                    child.left = splay(child.left, key)
                    if child.left != nil { root.right = rotateRight(child) }
                    return root.right == nil ? root : rotateLeft(root)
                }
                return rotateLeft(root)
            }
        }
    }
}
```

In `remove`, splaying for `key` inside the left subtree, where every key is smaller, always ends at its largest key. That node can't have a right child, so the right subtree drops neatly into the gap. The written-for-you parts (`sortedKeys`, `height` and `Node`'s loop-based cleanup) are left out here.

</Approach>
