A weather service runs a long row of rain gauges, numbered from 0. Readings get corrected one gauge at a time, and analysts keep asking two questions about a stretch of gauges: the **total** rainfall, and the **heaviest** single reading. Build a structure that handles both, with every operation in about O(√n).

`RainGaugeBlocks.Gauges`, a class with `init(readings: [Int])`, `set(_ index: Int, to reading: Int)`, `total(_ left: Int, _ right: Int) -> Int` and `heaviest(_ left: Int, _ right: Int) -> Int`

Ranges include both ends.

## Examples

Each row starts from `readings` and runs the operations in order.

| `readings` | Operations | Results |
| --- | --- | --- |
| `[4, 8, 1, 7, 3, 9, 2, 6, 5, 0]` | `total(1, 8)`, `heaviest(1, 8)`, `set(5, to: 20)`, `total(1, 8)`, `heaviest(0, 4)`, `heaviest(4, 9)` | `41`, `9`, `52`, `8`, `20` |
| `[3, 3, 3]` | `set(1, to: 0)`, `total(0, 2)`, `heaviest(1, 1)`, `heaviest(0, 2)` | `6`, `0`, `3` |
| `[12]` | `heaviest(0, 0)`, `set(0, to: 5)`, `total(0, 0)` | `12`, `5` |

In the first example, if gauge 5 were then set to 1, the heaviest of 4...9 would drop from 20 to 6: lowering a reading can change a stretch's heaviest value.

## Constraints

- `1 ≤ readings.count ≤ 100,000`, and up to 100,000 operations in total
- `0 ≤ reading ≤ 1,000,000`
- Every index is in range, and every query has `left ≤ right`.
- The tests use 20,000 gauges and 20,000 mixed operations, most of the queries covering long stretches, so scanning each query's range is too slow.

<Hints>
<Hint>
Cut the gauges into blocks of about √n and store a total and a maximum for each block. A query takes whole blocks from their summaries and only scans the loose gauges at its two ends.
</Hint>
<Hint>
Updating a block's total is easy: add the difference between the new and old reading. The maximum is harder. If you lower the block's largest reading, which one is the new largest?
</Hint>
<Hint>
For the maximum, recompute the block from scratch after each `set`: O(√n). Watch the last block, which may be shorter than the others.
</Hint>
</Hints>

## Solutions

<Approach title="Scan every query" time="O(1) set, O(n) per query" space="O(n)">

Store the readings in an array, overwrite on `set`, and loop over `left...right` for each query. With 13,000 long queries, each scanned twice (once per question), this is hundreds of millions of steps.

</Approach>

<Approach title="Sqrt decomposition" time="O(√n) per operation" space="O(n)">

Each block keeps its total and its maximum. `set` fixes the total with the difference and rebuilds the maximum by scanning its block. A query walks from `left`, taking a whole block's summary whenever it stands at the start of a block that fits, and single readings otherwise.

```swift
public enum RainGaugeBlocks {
    public final class Gauges {
        private var readings: [Int]
        private var blockTotal: [Int]
        private var blockMax: [Int]
        private let blockSize: Int

        public init(readings: [Int]) {
            self.readings = readings
            var size = 1
            while size * size < readings.count { size += 1 }
            blockSize = size
            let blockCount = (readings.count + size - 1) / size
            blockTotal = [Int](repeating: 0, count: blockCount)
            blockMax = [Int](repeating: Int.min, count: blockCount)
            for (i, reading) in readings.enumerated() {
                blockTotal[i / size] += reading
                blockMax[i / size] = max(blockMax[i / size], reading)
            }
        }

        public func set(_ index: Int, to reading: Int) {
            let block = index / blockSize
            blockTotal[block] += reading - readings[index]
            readings[index] = reading
            let start = block * blockSize
            let end = min(start + blockSize, readings.count)
            blockMax[block] = readings[start..<end].max()!
        }

        public func total(_ left: Int, _ right: Int) -> Int {
            var sum = 0
            var i = left
            while i <= right {
                if i % blockSize == 0 && i + blockSize - 1 <= right {
                    sum += blockTotal[i / blockSize]
                    i += blockSize
                } else {
                    sum += readings[i]
                    i += 1
                }
            }
            return sum
        }

        public func heaviest(_ left: Int, _ right: Int) -> Int {
            var best = Int.min
            var i = left
            while i <= right {
                if i % blockSize == 0 && i + blockSize - 1 <= right {
                    best = max(best, blockMax[i / blockSize])
                    i += blockSize
                } else {
                    best = max(best, readings[i])
                    i += 1
                }
            }
            return best
        }
    }
}
```

A segment tree storing (total, maximum) pairs would make every operation O(log n). Sqrt decomposition gives up a little speed for code with no tree indexing at all.

</Approach>
