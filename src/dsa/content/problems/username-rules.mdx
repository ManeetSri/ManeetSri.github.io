A sign-up screen checks a username before sending it to the server. Return `true` only when the username follows **every** rule:

1. It isn't empty.
2. It has at most 15 characters.
3. It contains no space characters (`" "`).
4. It doesn't start with an underscore, `_`.
5. It isn't `admin` in any mix of capitals and small letters, so `"Admin"` and `"ADMIN"` are refused too.

`UsernameRules.isValid(_ username: String) -> Bool`

Two operators you'll study properly later in this module: `<=` means "less than or equal to", and `!=` means "not equal to".

## Examples

| Input | Output | Why |
| --- | --- | --- |
| `"maneet_s"` | `true` | follows every rule |
| `""` | `false` | empty |
| `"swift dev"` | `false` | contains a space |
| `"_hidden"` | `false` | starts with an underscore |
| `"AdMiN"` | `false` | it's `admin` in disguise |
| `"administrator"` | `true` | only `admin` itself is reserved |
| `"abcdefghijklmnop"` | `false` | 16 characters, one too many |

## Constraints

- `username` has at most 100 characters, of any kind.
- Characters are counted the way `count` counts them, so an emoji such as `"🦊"` is one character.
- Only the space character counts as a space for rule 3.

<Hints>
<Hint>
Each rule is one small `Bool` expression using something from the lesson: `isEmpty`, `count`, `contains`, `hasPrefix` or `lowercased()`.
</Hint>
<Hint>
Join the rules with `&&`: the whole expression is `true` only when every part is. Some rules are naturally written the wrong way round, like "contains a space"; put `!` in front to flip them: `!username.contains(" ")`.
</Hint>
<Hint>
For rule 5, lower-case the username and compare it with `"admin"`: `username.lowercased() != "admin"`. Don't forget rule 1: without it, `""` would pass every other rule.
</Hint>
</Hints>

## Solutions

<Approach title="One expression, one rule per line" time="O(n)" space="O(n)">

Each line of the expression is one rule, in the order the statement lists them. `&&` also stops as soon as one part is `false`, so an empty username is rejected without checking anything else.

```swift
public enum UsernameRules {
    public static func isValid(_ username: String) -> Bool {
        return !username.isEmpty
            && username.count <= 15
            && !username.contains(" ")
            && !username.hasPrefix("_")
            && username.lowercased() != "admin"
    }
}
```

`count`, `contains` and `lowercased()` each walk through the characters, so the time grows with the length *n*. `lowercased()` builds a new string, which is the O(n) space.

</Approach>

<Approach title="Name each rule first" time="O(n)" space="O(n)">

Giving each rule a `Bool` constant with a yes-or-no name, as you learnt in *Naming things well*, makes the final line read like the specification. It's longer, but each rule can be checked on its own.

```swift
public enum UsernameRules {
    public static func isValid(_ username: String) -> Bool {
        let hasCharacters = !username.isEmpty
        let isShortEnough = username.count <= 15
        let hasNoSpaces = !username.contains(" ")
        let startsWell = !username.hasPrefix("_")
        let isNotReserved = username.lowercased() != "admin"
        return hasCharacters && isShortEnough && hasNoSpaces && startsWell && isNotReserved
    }
}
```

This version always works out all five rules, even when the first already fails. For a username of at most 100 characters, the difference doesn't matter.

</Approach>
