An orchard has a tree at every point with whole-number coordinates. A fence is built along a simple polygon whose corners are such points, and the trees standing on the fence line are cut down. How many trees are left strictly inside the fence?

`OrchardTreesInside.treesInside(_ fence: [[Int]]) -> Int`

`fence` lists the corners in order, clockwise or counterclockwise, each as `[x, y]`. The fence closes from the last corner back to the first.

## Examples

| `fence` | Output |
| --- | --- |
| `[[0, 0], [4, 0], [4, 4], [0, 4]]` | `9` |
| `[[0, 0], [4, 0], [0, 4]]` | `3` |
| `[[0, 0], [5, 0], [0, 1]]` | `0` |
| `[[0, 0], [6, 0], [6, 2], [2, 2], [2, 6], [0, 6]]` | `9` |
| `[[0, 0], [2, 0], [4, 0], [4, 3], [0, 3]]` | `6` |
| `[[0, 0], [1000000, 0], [0, 1000000]]` | `499998500001` |

The first fence is a 4 × 4 square with a 3 × 3 block of trees inside. The third is a thin triangle: every tree near it is on the fence or outside. The fourth is L-shaped. The fifth has a corner, (2, 0), in the middle of a straight side. The last has about half a trillion trees inside: far too many to count one by one.

## Constraints

- `3 ≤ fence.count ≤ 100,000`
- `-10⁶ ≤ x, y ≤ 10⁶`
- The fence doesn't cross or touch itself, encloses a positive area, and no two consecutive corners are the same. Three consecutive corners may lie on one line.

<Hints>
<Hint>
Checking every grid point in the bounding box is far too slow for the last example. Look for a formula that links the fence's area to the trees inside it and on it.
</Hint>
<Hint>
Pick's theorem: for a polygon with grid-point corners, area = I + B/2 − 1, where I is the number of grid points strictly inside and B the number on the boundary. The shoelace formula gives twice the area exactly.
</Hint>
<Hint>
A side from (x₁, y₁) to (x₂, y₂) passes through gcd(|x₂ − x₁|, |y₂ − y₁|) + 1 grid points, both ends included. Add up just the gcd for each side and each boundary point is counted once. Then I = (2 × area − B + 2) / 2.
</Hint>
</Hints>

## Solutions

<Approach title="Check every grid point" time="O(n · W · H)" space="O(1)">

For every grid point in the bounding box, W wide and H tall, run a point-in-polygon test and count the ones strictly inside. It's a good way to check a faster solution on small fences, and hopeless for a field a million wide.

</Approach>

<Approach title="Shoelace, gcd and Pick's theorem" time="O(n log C)" space="O(1)">

One pass over the sides gives both twice the area and the boundary count; Pick's theorem does the rest. Coordinates up to 10⁶ keep every product and sum far below `Int.max`. Each gcd takes O(log C) steps for coordinates up to C.

```swift
public enum OrchardTreesInside {
    static func gcd(_ a: Int, _ b: Int) -> Int {
        var (a, b) = (a, b)
        while b != 0 {
            (a, b) = (b, a % b)
        }
        return a
    }

    public static func treesInside(_ fence: [[Int]]) -> Int {
        let n = fence.count
        var twiceArea = 0
        var boundary = 0
        for i in 0..<n {
            let a = fence[i], b = fence[(i + 1) % n]
            twiceArea += a[0] * b[1] - a[1] * b[0]
            boundary += gcd(abs(b[0] - a[0]), abs(b[1] - a[1]))
        }
        return (abs(twiceArea) - boundary + 2) / 2
    }
}
```

The absolute value makes the corners' direction irrelevant. A corner in the middle of a straight side changes nothing: the two shorter sides add the same area and the same gcd total as the one long side would.

</Approach>
