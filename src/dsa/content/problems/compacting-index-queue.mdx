Build a queue on an array with a head index, so that dequeuing never shifts the waiting items, and make it give memory back. A plain head-index queue keeps every served item in a dead slot forever; yours must stay within a fixed multiple of the number of items actually waiting.

`CompactingIndexQueue.TicketQueue<Element>`, with `init()`, `enqueue(_:)`, `dequeue() -> Element?`, `peek() -> Element?`, `count: Int`, `isEmpty: Bool` and `slotCount: Int`

`slotCount` is how many slots the backing array holds right now, live and dead together. The rules:

- `dequeue()` removes and returns the item that has waited longest, and `peek()` returns it without removing it. Both return `nil` for an empty queue.
- After every operation, `slotCount ≤ 2 × count + 16`.
- Whenever a dequeue empties the queue, `slotCount` drops to 0.
- Every operation is O(1) amortised.

## Examples

| Code | Result |
| --- | --- |
| enqueue `"Ana"`, `"Ben"`, `"Cleo"`, then `dequeue()` | `"Ana"` |
| then `peek()` and `count` | `"Ben"` and `2` |
| enqueue 1, 2, 3, then dequeue three times | `1`, `2`, `3`, and `slotCount` is `0` |
| `TicketQueue<Int>().dequeue()` | `nil` |
| enqueue 3 items, then enqueue one and dequeue one 1,000 times | `count` is `3` and `slotCount` is at most `22` |

Without any clean-up, the last example would leave 1,003 slots in the array for 3 waiting items.

## Constraints

- Up to 300,000 operations in any mix, with up to 50,000 items waiting at once.
- Don't use `removeFirst()` on every dequeue: that's O(n) per call.
- Copying a queue gives an independent queue, as with any struct.

<Hints>
<Hint>
Store `items: [Element]` and `head: Int`, the position of the front. Enqueue appends; dequeue reads `items[head]` and adds 1 to `head`. The waiting items are `items[head...]`, so `count` is `items.count - head`, and `slotCount` is `items.count`.
</Hint>
<Hint>
Two clean-ups after a dequeue. If `head` has reached `items.count`, everything is dead: `removeAll(keepingCapacity: true)` and set `head` to 0. Otherwise, if the dead slots are at least half the array, remove them all at once with `removeFirst(head)` and set `head` to 0.
</Hint>
<Hint>
Compacting only when `head * 2 >= items.count` means it moves no more items than there are dead slots, and every dead slot came from one dequeue since the last compaction. So the total moves never exceed the number of dequeues: O(1) amortised. Only compact once `head` is at least 16, or tiny queues compact over and over for nothing, and the `+ 16` in the rule gives you that room.
</Hint>
</Hints>

## Solutions

<Approach title="A head index with no clean-up" time="O(1) per operation" space="O(every item ever enqueued)">

Fast, but the array only ever grows. It breaks the `slotCount` rule as soon as more than about 16 items have been served without the queue emptying.

```swift
public mutating func dequeue() -> Element? {
    guard head < items.count else { return nil }
    head += 1
    return items[head - 1]
}
```

</Approach>

<Approach title="Reset when empty, compact when half dead" time="O(1) amortised" space="O(count)">

The reset handles queues that drain, for free. Compaction handles queues that never drain, and by waiting until half the slots are dead it keeps both the array's size and the total work in check.

```swift
public enum CompactingIndexQueue {
    public struct TicketQueue<Element> {
        private var items: [Element] = []
        private var head = 0                     // the position of the front item

        public init() {}

        public var count: Int { items.count - head }

        public var isEmpty: Bool { head == items.count }

        public var slotCount: Int { items.count }

        public mutating func enqueue(_ element: Element) {
            items.append(element)
        }

        public mutating func dequeue() -> Element? {
            guard head < items.count else { return nil }
            let element = items[head]
            head += 1
            if head == items.count {
                items.removeAll(keepingCapacity: true)     // all dead: start afresh
                head = 0
            } else if head >= 16 && head * 2 >= items.count {
                items.removeFirst(head)                    // drop the dead half in one go
                head = 0
            }
            return element
        }

        public func peek() -> Element? {
            head < items.count ? items[head] : nil
        }
    }
}
```

Why the rule holds: after a dequeue, either `head < 16`, or the dead slots are fewer than the live ones (`head < count`). Either way `items.count = head + count` is less than `2 × count + 16`, and an enqueue adds one to both sides.

</Approach>
