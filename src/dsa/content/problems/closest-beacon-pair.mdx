Rescue beacons have been dropped across a mountain range, and two that are too close together interfere with each other. Find how close the closest two are.

`ClosestBeaconPair.smallestSquaredDistance(_ beacons: [[Int]]) -> Int`

Each beacon is `[x, y]`, and two beacons may land on the same spot. Return the smallest **squared** distance, (x₁ − x₂)² + (y₁ − y₂)², over all pairs of different beacons. Squared distances are whole numbers, so the answer is exact.

## Examples

| `beacons` | Output |
| --- | --- |
| `[[0, 0], [5, 5], [1, 2], [9, 0]]` | `5` |
| `[[3, 4], [0, 0]]` | `25` |
| `[[1, 1], [7, 3], [1, 1], [4, 4]]` | `0` |
| `[[0, 0], [10, 0], [20, 0], [21, 0], [40, 0]]` | `1` |
| `[[-1000000000, -1000000000], [1000000000, 1000000000]]` | `8000000000000000000` |

In the first example, (0, 0) and (1, 2) are closest: 1² + 2² = 5. In the third, two beacons share a spot. The last answer, 8 × 10¹⁸, still fits in an `Int`.

## Constraints

- `2 ≤ beacons.count ≤ 100,000`
- `-10⁹ ≤ x, y ≤ 10⁹`
- The tests include 100,000 beacons, so checking every pair (about 5 × 10⁹ of them) is too slow. They also include 100,000 beacons on a single vertical line.

`import DSAKit` is already in the exercise file, so `SortedSet` is available.

<Hints>
<Hint>
Sort the beacons by x and visit them in that order, keeping `best`, the smallest squared distance so far. When you reach a beacon, which earlier beacons could beat `best`? Only those less than √best to its left.
</Hint>
<Hint>
Keep those nearby beacons in a window, dropping beacons from the left end as the sweep moves on. But a window alone isn't enough: on the vertical-line test, every beacon stays in it. You also need only the beacons within √best above or below.
</Hint>
<Hint>
Keep the window in a `SortedSet` ordered by `(y, x)`, so one range query finds the beacons with y between `p.y - r` and `p.y + r`, where r is the integer square root of `best`. Only a handful can be in that range. Stop at once if `best` reaches 0.
</Hint>
</Hints>

## Solutions

<Approach title="Every pair" time="O(n²)" space="O(1)">

Two nested loops, the smaller squared distance each time. Correct and useful for testing, but about 5 × 10⁹ pairs for 100,000 beacons.

</Approach>

<Approach title="Sort by x, scan back while close in x" time="O(n²) worst case" space="O(n)">

After sorting by x, compare each beacon only with earlier ones whose x-distance squared is less than `best`, stopping at the first that's too far. On scattered beacons it's fast. On the vertical-line test every x-distance is 0, so every beacon scans every earlier one.

</Approach>

<Approach title="Sweep with an ordered window" time="O(n log n)" space="O(n)">

The sweep from the lesson: a left pointer evicts beacons that are too far left, and a `SortedSet` keyed by `(y, x)` answers the range query. Each beacon is inserted and evicted once and runs one range query, all O(log n), and the range holds only a constant number of beacons.

```swift
import DSAKit

public enum ClosestBeaconPair {
    struct Point {
        var x: Int
        var y: Int
    }

    struct Key: Comparable {
        var y: Int
        var x: Int
        static func < (lhs: Key, rhs: Key) -> Bool { (lhs.y, lhs.x) < (rhs.y, rhs.x) }
    }

    static func squaredDistance(_ a: Point, _ b: Point) -> Int {
        (a.x - b.x) * (a.x - b.x) + (a.y - b.y) * (a.y - b.y)
    }

    static func integerSquareRoot(_ value: Int) -> Int {
        var root = Int(Double(value).squareRoot())
        while root * root > value { root -= 1 }
        while (root + 1) * (root + 1) <= value { root += 1 }
        return root
    }

    public static func smallestSquaredDistance(_ beacons: [[Int]]) -> Int {
        let points = beacons.map { Point(x: $0[0], y: $0[1]) }.sorted { ($0.x, $0.y) < ($1.x, $1.y) }
        var best = squaredDistance(points[0], points[1])
        var window = SortedSet<Key>()
        var left = 0
        for p in points {
            if best == 0 {
                return 0
            }
            while (p.x - points[left].x) * (p.x - points[left].x) >= best {
                window.remove(Key(y: points[left].y, x: points[left].x))   // too far left to help
                left += 1
            }
            let reach = integerSquareRoot(best)
            let low = Key(y: p.y - reach, x: Int.min), high = Key(y: p.y + reach, x: Int.max)
            for q in window.elements(in: low...high) {
                best = min(best, squaredDistance(p, Point(x: q.x, y: q.y)))
            }
            window.insert(Key(y: p.y, x: p.x))
        }
        return best
    }
}
```

Starting `best` at the first two beacons' distance, rather than `Int.max`, keeps `integerSquareRoot` from overflowing. Because the loop returns as soon as two beacons coincide, the set never needs to hold the same key twice.

</Approach>
