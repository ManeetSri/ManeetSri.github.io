A family tree is stored as a `parents` array: `parents[i]` is the parent of person i, and the one person with no parent (the root) has −1. The root's depth is 0, and everyone else is one deeper than their parent. Return every person's depth.

The obvious recursion is correct, but it isn't safe:

```swift
func depth(of person: Int, _ parents: [Int]) -> Int {
    let parent = parents[person]
    if parent == -1 {
        return 0
    }
    return 1 + depth(of: parent, parents)
}
```

When the tree is one long chain, a person at depth 200,000 needs 200,000 frames at once, and calling it for every person repeats the same climbs over and over.

`ParentChainDepths.depths(_ parents: [Int]) -> [Int]`

## Examples

| `parents` | Output | Why |
| --- | --- | --- |
| `[-1, 0, 0, 1, 1, 3]` | `[0, 1, 1, 2, 2, 3]` | person 5's chain is 5 → 3 → 1 → 0 |
| `[2, 2, -1, 0]` | `[1, 1, 0, 2]` | the root doesn't have to be person 0 |
| `[-1]` | `[0]` | |
| `[1, 2, 3, -1]` | `[3, 2, 1, 0]` | a chain listed from the bottom up |

## Constraints

- `1 ≤ parents.count ≤ 2 × 10⁵`.
- Exactly one entry is −1, every other entry is a valid index, and following parents always reaches the root (there are no cycles).
- The tests include a single chain of 200,000 people. Take O(n) time in total, and don't recurse once per level: a test's stack runs out after a few thousand frames.

<Hints>
<Hint>
Remember answers: keep a `depth` array with −1 for "not known yet". Once a person's depth is known, anyone below them can stop climbing there instead of going all the way to the root.
</Hint>
<Hint>
For each person whose depth isn't known, climb with a loop instead of recursion: collect the people you pass in an ordinary array, `path`, until you reach someone whose depth is known, or the root. That array lives on the heap, so it can be as long as it needs to be.
</Hint>
<Hint>
Then walk `path` backwards, from the person nearest the known one to the person you started from, giving each one a depth one more than the person above them. Every person is added to a path once and given a depth once, so the whole thing is O(n).
</Hint>
</Hints>

## Solutions

<Approach title="Recurse for each person" time="O(n²) for a chain" space="O(n) stack">

Calling the recursion from the statement for every person is correct, but on a chain it climbs about n² / 2 steps in total, and the deepest call needs n frames: with 200,000 people that crashes inside a test. Adding a memo array fixes the time but not the depth: the very first call can still be 200,000 frames deep.

</Approach>

<Approach title="Climb with a loop, then fill in on the way back" time="O(n)" space="O(n)">

This is the "explicit stack" rescue from the lesson on stack limits. The pending work, the people whose depths are waiting on someone above them, goes into the `path` array instead of into stack frames. Climbing stops at the first known depth, so no person is climbed past twice.

```swift
public enum ParentChainDepths {
    public static func depths(_ parents: [Int]) -> [Int] {
        var depth = Array(repeating: -1, count: parents.count)
        for start in 0..<parents.count where depth[start] == -1 {
            var path: [Int] = []
            var person = start
            while person != -1 && depth[person] == -1 {
                path.append(person)
                person = parents[person]
            }
            var known = person == -1 ? -1 : depth[person]
            for waiting in path.reversed() {
                known += 1
                depth[waiting] = known
            }
        }
        return depth
    }
}
```

When the climb reaches past the root, `person` is −1 and the root, the last one on the path, gets depth −1 + 1 = 0. When it stops at someone already known, the path continues from their depth.

Another way is to turn the parent array into lists of children and visit the tree from the root with a queue, level by level: also O(n), and also free of recursion. You'll meet that breadth-first search properly in Part III and Part VI.

</Approach>
