You have a handful of letter tiles, given as the string `tiles`. Tiles with the same letter look identical. Return every different way to lay **all** the tiles in a row, each arrangement once.

`DistinctTileArrangements.arrangements(of tiles: String) -> [String]`

The arrangements may come in any order: the tests sort them before comparing.

## Examples

| `tiles` | Output |
| --- | --- |
| `"TOT"` | `["OTT", "TOT", "TTO"]` |
| `"ABC"` | `["ABC", "ACB", "BAC", "BCA", "CAB", "CBA"]` |
| `"QQQQ"` | `["QQQQ"]` |
| `"ABAB"` | `["AABB", "ABAB", "ABBA", "BAAB", "BABA", "BBAA"]` |

"TOT" has 3! = 6 orderings of its tiles, but swapping the two Ts changes nothing, so only 3 arrangements are different.

## Constraints

- `1 ≤ tiles.count ≤ 12`, uppercase letters `A` to `Z`.
- The answer has at most 50,000 arrangements.
- The tests include nine A tiles with three B tiles (12! ≈ 479 million orderings, only 220 different) and MISSISSIPPI (about 40 million orderings, 34,650 different). Generating every ordering and removing repeats is far too slow.

<Hints>
<Hint>
Without repeated letters this is plain permutations: fill the positions left to right, choosing any tile not used yet, with a `used` array.
</Hint>
<Hint>
Sort the tiles so equal letters sit together. A repeat happens when the same letter is tried twice in the same position.
</Hint>
<Hint>
Always use equal tiles from left to right: skip tile `i` if it equals tile `i - 1` and tile `i - 1` is still unused. Or count the letters and let each level choose a distinct letter that still has tiles left.
</Hint>
</Hints>

## Solutions

<Approach title="Every ordering, then remove repeats" time="O(n · n!)" space="O(n · n!)">

Generate all n! orderings and keep the distinct ones in a `Set<String>`. Correct, but the work is n! whatever the answer: 479 million orderings for 220 arrangements.

</Approach>

<Approach title="Used array, equal tiles in order" time="O(n · A), A = number of arrangements" space="O(n) besides the output">

Sort the tiles, then search with a `used` array. A copy is skipped while its equal neighbour on the left is still unused: that neighbour has already been tried in this position, so this copy would grow the same subtree. Every prefix the search builds is a different one, so the work is proportional to the answer.

```swift
public enum DistinctTileArrangements {
    public static func arrangements(of tiles: String) -> [String] {
        let letters = tiles.sorted()
        var used = Array(repeating: false, count: letters.count)
        var current: [Character] = []
        var result: [String] = []

        func explore() {
            if current.count == letters.count {
                result.append(String(current))
                return
            }
            for i in letters.indices where !used[i] {
                if i > 0 && letters[i] == letters[i - 1] && !used[i - 1] { continue }
                used[i] = true                                      // choose
                current.append(letters[i])
                explore()                                           // explore
                current.removeLast()                                // unchoose
                used[i] = false
            }
        }

        explore()
        return result
    }
}
```

`tiles.sorted()` returns a sorted `[Character]`, ready for indexing. The number of arrangements is n! divided by c! for each letter that appears c times, so MISSISSIPPI has 11! ÷ (4! × 4! × 2!) = 34,650.

</Approach>
