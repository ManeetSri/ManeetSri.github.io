Write the five small helpers that every Fenwick tree is made of: the lowest set bit, the range a slot is responsible for, the slots a prefix query reads, the slots an update touches, and the slots a **range** query really needs once the slots its two prefix queries share have cancelled out.

`FenwickSlotWalks.lowbit(_:)`, `FenwickSlotWalks.responsibility(of:)`, `FenwickSlotWalks.queryPath(to:)`, `FenwickSlotWalks.updatePath(from:size:)` and `FenwickSlotWalks.rangeSlots(from:through:) -> (add: [Int], subtract: [Int])`

Positions and slots count from 1, as in a Fenwick tree.

- `lowbit(i)` is the lowest set bit of i.
- `responsibility(of: i)` is the closed range of positions slot i covers: the `lowbit(i)` positions ending at i.
- `queryPath(to: i)` lists the slots a prefix query for positions 1 through i reads, in the order the walk visits them. It's empty for i = 0.
- `updatePath(from: i, size: n)` lists the slots that change when position i changes, in a Fenwick array of n slots, in the order the walk visits them.
- `rangeSlots(from: l, through: r)` answers "which slots does the sum of positions l through r need?". The sum is `prefix(r) − prefix(l − 1)`, but the two walks usually end on the same slots, and those cancel. Return the slots to **add** (from r's walk) and to **subtract** (from l − 1's walk), each in visiting order, leaving out every slot that both walks read.

## Examples

| Call | Output |
| --- | --- |
| `lowbit(12)`, `lowbit(7)`, `lowbit(64)` | `4`, `1`, `64` |
| `responsibility(of: 12)` | `9...12` |
| `queryPath(to: 13)` | `[13, 12, 8]` |
| `updatePath(from: 5, size: 16)` | `[5, 6, 8, 16]` |
| `updatePath(from: 3, size: 6)` | `[3, 4]` |
| `rangeSlots(from: 13, through: 15)` | `(add: [15, 14], subtract: [])` |
| `rangeSlots(from: 6, through: 13)` | `(add: [13, 12, 8], subtract: [5, 4])` |
| `rangeSlots(from: 1, through: 6)` | `(add: [6, 4], subtract: [])` |

For 13 through 15, the walks are `[15, 14, 12, 8]` and `[12, 8]`. Slots 12 and 8 appear in both, so they cancel: slot 15 covers 15 and slot 14 covers 13...14, which is exactly the range. For 6 through 13, the walks `[13, 12, 8]` and `[5, 4]` share nothing.

## Constraints

- `1 ≤ i ≤ 10¹⁸` for `lowbit` and `responsibility`, and `0 ≤ i ≤ 10¹⁸` for `queryPath`.
- `1 ≤ i ≤ n ≤ 10¹⁸` for `updatePath`.
- `1 ≤ l ≤ r ≤ 10¹⁸` for `rangeSlots`.
- Every walk takes O(log i) steps. With indexes this large, anything that loops over positions one at a time never finishes.

<Hints>
<Hint>
`i & -i` is the lowest set bit, and slot i covers `(i - lowbit(i) + 1)...i`. The query walk strips the lowest set bit (`i -= i & -i`) until it reaches 0; the update walk adds it (`i += i & -i`) until it passes n.
</Hint>
<Hint>
Both prefix walks only ever go down, and once they land on the same slot, they visit exactly the same slots from then on, because each step depends only on the current slot. So the slots they share are a common tail.
</Hint>
<Hint>
Walk both at once: keep `a = r` and `b = l - 1`. While `a != b`, step whichever is larger, recording it in `add` or `subtract`. When they meet (at worst at 0), everything left is shared and cancels.
</Hint>
</Hints>

## Solutions

<Approach title="The two walks, and walking both at once" time="O(log r)" space="O(log r)">

```swift
public enum FenwickSlotWalks {
    public static func lowbit(_ i: Int) -> Int {
        i & -i
    }

    public static func responsibility(of i: Int) -> ClosedRange<Int> {
        (i - lowbit(i) + 1)...i
    }

    public static func queryPath(to i: Int) -> [Int] {
        var path: [Int] = []
        var slot = i
        while slot > 0 {
            path.append(slot)
            slot -= lowbit(slot)
        }
        return path
    }

    public static func updatePath(from i: Int, size n: Int) -> [Int] {
        var path: [Int] = []
        var slot = i
        while slot <= n {
            path.append(slot)
            slot += lowbit(slot)
        }
        return path
    }

    public static func rangeSlots(from l: Int, through r: Int) -> (add: [Int], subtract: [Int]) {
        var add: [Int] = []
        var subtract: [Int] = []
        var a = r
        var b = l - 1
        while a != b {
            if a > b {
                add.append(a)
                a -= lowbit(a)
            } else {
                subtract.append(b)
                b -= lowbit(b)
            }
        }
        return (add, subtract)
    }
}
```

Stepping the larger index is safe: if both walks pass through some slot c, each walk stays above c until it lands on it, so neither can jump past the meeting point. Each step removes a set bit from one index, so the loop runs at most about 2 log₂ r times. With n up to 10¹⁸, `slot += lowbit(slot)` stays below 2 × 10¹⁸, well inside `Int`.

</Approach>

<Approach title="Two full walks, then remove the common tail" time="O(log r)" space="O(log r)">

Compute `queryPath(to: r)` and `queryPath(to: l - 1)` in full. Both end with the same slots, so drop elements from the back of both while their last elements are equal. What's left is the answer. It's as fast, and it makes the "common tail" idea very visible.

</Approach>
