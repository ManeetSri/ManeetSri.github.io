Here's a small recursive function that makes two calls, each on a smaller number:

```swift
func probe(_ n: Int) {
    if n == 0 {
        return
    }
    probe(n / 2)
    probe(n / 3)
}
```

Record what its call stack looks like as it runs. Describe a stack by the arguments of the frames alive on it, from the bottom (the first call) to the top (the call running now).

`CallStackSnapshots.snapshots(_ n: Int) -> [[Int]]` returns the stack at the moment each call **starts**, just after its frame is pushed, in the order the calls start.

`CallStackSnapshots.returnOrder(_ n: Int) -> [Int]` returns the argument of each call in the order the calls **return**.

## Examples

| Call | Output |
| --- | --- |
| `snapshots(0)` | `[[0]]` |
| `snapshots(1)` | `[[1], [1, 0], [1, 0]]` |
| `snapshots(2)` | `[[2], [2, 1], [2, 1, 0], [2, 1, 0], [2, 0]]` |
| `returnOrder(1)` | `[0, 0, 1]` |
| `returnOrder(2)` | `[0, 0, 1, 0, 2]` |
| `returnOrder(6)` | `[0, 0, 1, 0, 0, 1, 3, 0, 0, 1, 0, 2, 6]` |

In `snapshots(2)`, the call `probe(1)` finishes completely, popping both of its `probe(0)` calls, before `probe(2)` makes its second call, `probe(0)`. That's why the last snapshot is `[2, 0]`.

## Constraints

- `0 ≤ n ≤ 10⁴`. `probe(10_000)` makes 3,927 calls and never has more than 15 frames alive, so recursing is safe here.

<Hint>
Take the snapshot right after pushing, before the base case check, so that base-case calls are recorded too. Append `n` to the return order right after popping, which is the moment the call finishes.
</Hint>
<Hint>
`defer` is handy: write `defer { stack.removeLast(); order.append(n) }` straight after the push, and it runs whichever way the call ends.
</Hint>

## Solutions

<Approach title="Mirror the call stack in an array" time="O(calls × depth)" space="O(calls × depth) for the snapshots">

The real call stack and the array move in lockstep: every push of a frame is an `append`, every pop is a `removeLast`. Because the array is shared, every snapshot shows exactly the path from the first call down to the current one. Calls return in the reverse order of how deep they are along that path: a call can't return until everything it started has returned.

```swift
public enum CallStackSnapshots {
    static func trace(_ n: Int) -> (snapshots: [[Int]], order: [Int]) {
        var stack: [Int] = []
        var snapshots: [[Int]] = []
        var order: [Int] = []

        func probe(_ n: Int) {
            stack.append(n)
            snapshots.append(stack)
            defer {
                stack.removeLast()
                order.append(n)
            }
            if n == 0 {
                return
            }
            probe(n / 2)
            probe(n / 3)
        }

        probe(n)
        return (snapshots, order)
    }

    public static func snapshots(_ n: Int) -> [[Int]] {
        trace(n).snapshots
    }

    public static func returnOrder(_ n: Int) -> [Int] {
        trace(n).order
    }
}
```

The longest snapshot is the recursion's stack space. It's about log₂ n frames, because the deepest path keeps halving, even though the number of calls grows much faster.

</Approach>
