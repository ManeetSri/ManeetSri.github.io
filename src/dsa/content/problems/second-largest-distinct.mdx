Return the second-largest **distinct** value in the array: the largest value that is strictly smaller than the maximum. If there's no such value, because the array is empty or every value is the same, return `nil`.

`SecondLargestDistinct.secondLargest(in numbers: [Int]) -> Int?`

Get a correct version first, then aim for a single pass with O(1) extra space.

## Examples

| Input | Output |
| --- | --- |
| `[4, 9, 7]` | `7` |
| `[9, 4, 9, 7]` | `7` |
| `[5, 5, 5]` | `nil` |
| `[-3, -8]` | `-8` |
| `[6]` | `nil` |
| `[]` | `nil` |

In the second example, the second 9 doesn't count: it's the same value as the largest.

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- `-10⁹ ≤ numbers[i] ≤ 10⁹`

</Hint>
<Hint>
A brute force: remove duplicates with a `Set`, sort what's left, and take the second from the end if there is one.
</Hint>
<Hint>
For one pass, keep `largest` and `second` as optionals. A value bigger than `largest` pushes the old largest down into `second`. A value equal to `largest` changes nothing. A value strictly between them replaces `second`.
</Hint>

## Solutions

<Approach title="Remove duplicates, then sort" time="O(n log n)" space="O(n)">

A `Set` keeps one copy of each value, so after sorting, the last element is the largest and the one before it is the second-largest distinct value. `dropLast().last` is `nil` when there are fewer than two distinct values.

```swift
public static func secondLargest(in numbers: [Int]) -> Int? {
    Set(numbers).sorted().dropLast().last
}
```

It's short and obviously correct, which makes it a good baseline to test the faster version against.

</Approach>

<Approach title="One pass, keeping the top two" time="O(n)" space="O(1)">

The invariant: after each value, `largest` is the largest value seen, and `second` is the largest seen value that's strictly smaller than `largest`, or `nil` if there isn't one yet.

- A new largest pushes the old one down: `second` becomes the old `largest`.
- A value equal to `largest` is a duplicate, so nothing changes.
- A value below `largest` but above `second` becomes the new `second`.

```swift
public enum SecondLargestDistinct {
    public static func secondLargest(in numbers: [Int]) -> Int? {
        var largest: Int? = nil
        var second: Int? = nil
        for number in numbers {
            guard let top = largest else {
                largest = number
                continue
            }
            if number > top {
                second = top
                largest = number
            } else if number < top && (second == nil || number > second!) {
                second = number
            }
        }
        return second
    }
}
```

Using optionals rather than a starting value like `Int.min` means no value is ever mistaken for "nothing yet". The force unwrap is safe because `||` only looks at its right side when `second` isn't `nil`.

</Approach>
