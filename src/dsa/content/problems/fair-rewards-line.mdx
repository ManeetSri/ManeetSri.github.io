Children stand in a line after a quiz, each with a score. A teacher hands out stickers with two rules: every child gets at least one sticker, and a child who scored **higher** than a neighbour gets **more** stickers than that neighbour. Return the fewest stickers the teacher needs.

`FairRewardsLine.fewestRewards(_ ratings: [Int]) -> Int`

## Examples

| `ratings` | Output | Stickers |
| --- | --- | --- |
| `[2, 4, 3, 2, 1, 3, 3]` | `14` | `1, 4, 3, 2, 1, 2, 1` |
| `[1, 3, 2, 1]` | `7` | `1, 3, 2, 1` |
| `[1, 2, 2]` | `4` | `1, 2, 1` |
| `[3, 3, 3]` | `3` | equal scores need nothing extra |
| `[5, 3, 1, 3, 5]` | `11` | `3, 2, 1, 2, 3` |
| `[7]` | `1` | |

Two neighbours with **equal** scores have no rule between them: either may get fewer stickers.

## Constraints

- `1 ≤ ratings.count ≤ 100,000` and `0 ≤ ratings[i] ≤ 10⁹`
- The tests compare your answer with an exhaustive search over every handout on short lines, and include lines of 100,000 children that rise or fall the whole way.

<Hints>
<Hint>
Each child is constrained by the child on their left and the child on their right, and fixing one side can break the other. Try handling the two sides separately.
</Hint>
<Hint>
Going left to right, give each child 1, or one more than the child on their left if they scored higher. That satisfies every left-neighbour rule. Do the same from right to left.
</Hint>
<Hint>
Each pass gives a number that every valid handout must reach for that child: the length of the rising run ending there, from that side. Give each child the larger of their two numbers, and add them up.
</Hint>
</Hints>

## Solutions

<Approach title="Fix broken rules until none are left" time="O(n²)" space="O(n)">

Start everyone at 1 and keep sweeping the line, raising any child who breaks a rule to one more than the neighbour they must beat. Values only go up, and each is raised only as far as it must be, so it settles on the smallest valid handout. But a long falling slope can need a sweep for every child, so it's O(n²) in the worst case.

```swift
public static func fewestRewards(_ ratings: [Int]) -> Int {
    var rewards = Array(repeating: 1, count: ratings.count)
    var changed = true
    while changed {
        changed = false
        for i in ratings.indices {
            if i > 0 && ratings[i] > ratings[i - 1] && rewards[i] <= rewards[i - 1] {
                rewards[i] = rewards[i - 1] + 1
                changed = true
            }
            if i + 1 < ratings.count && ratings[i] > ratings[i + 1] && rewards[i] <= rewards[i + 1] {
                rewards[i] = rewards[i + 1] + 1
                changed = true
            }
        }
    }
    return rewards.reduce(0, +)
}
```

</Approach>

<Approach title="Two passes" time="O(n)" space="O(n)">

The left pass computes, for each child, how long the run of rising scores ending at them is: every child in that run needs one more than the one before, so any valid handout gives this child at least that many. The right pass does the same from the other side. The larger of the two meets both rules: if a child beats their left neighbour, their left count is bigger than the neighbour's, and the neighbour's right count is 1. So every child gets the least they could possibly get. The second pass can keep its count in one variable instead of a second array.

```swift
public enum FairRewardsLine {
    public static func fewestRewards(_ ratings: [Int]) -> Int {
        let n = ratings.count
        var rewards = Array(repeating: 1, count: n)
        for i in stride(from: 1, to: n, by: 1) where ratings[i] > ratings[i - 1] {
            rewards[i] = rewards[i - 1] + 1
        }
        var fromRight = 1                  // what the right-neighbour rule alone needs for child i
        var total = n > 0 ? rewards[n - 1] : 0
        for i in stride(from: n - 2, through: 0, by: -1) {
            fromRight = ratings[i] > ratings[i + 1] ? fromRight + 1 : 1
            rewards[i] = max(rewards[i], fromRight)
            total += rewards[i]
        }
        return total
    }
}
```

</Approach>
