Remove exactly `k` digits from a number written as a string, keeping the rest in order, so that what's left is as small as possible.

`SmallestAfterRemovals.smallest(_ digits: String, removing k: Int) -> String`

Return the result without leading zeros. If nothing is left, or only zeros, return `"0"`.

## Examples

| `digits` | `k` | Result |
| --- | --- | --- |
| `"4721"` | `1` | `"421"` |
| `"1593"` | `2` | `"13"` |
| `"10200"` | `1` | `"200"` |
| `"123456"` | `3` | `"123"` |
| `"345"` | `3` | `"0"` |
| `"2024"` | `0` | `"2024"` |

In the third example, removing the 1 leaves `"0200"`, which is written `"200"`.

## Constraints

- `1 ≤ digits.count ≤ 100,000`, and `digits` contains only `0` to `9`.
- `0 ≤ k ≤ digits.count`
- Aim for O(n).

<Hints>
<Hint>
Numbers of the same length are compared from the left, so the leftmost digits matter most. When should a digit be removed?
</Hint>
<Hint>
When the digit after it is smaller: removing it moves the smaller digit one place left. Keep the digits you've chosen on a stack, and before pushing a new digit, pop kept digits bigger than it while removals are left.
</Hint>
<Hint>
If removals are left at the end, the kept digits never decrease, so take them off the end. Then drop leading zeros, and return `"0"` if nothing is left.
</Hint>
</Hints>

## Solutions

<Approach title="Greedy with a monotonic stack" time="O(n)" space="O(n)">

The stack of kept digits stays non-decreasing from bottom to top while removals remain, which is why leftover removals come off the end. `Character`s compare like the digits they show, since `"0"` to `"9"` are in order.

```swift
public enum SmallestAfterRemovals {
    public static func smallest(_ digits: String, removing k: Int) -> String {
        var kept: [Character] = []
        var removalsLeft = k
        for digit in digits {
            while removalsLeft > 0, let last = kept.last, last > digit {
                kept.removeLast()
                removalsLeft -= 1
            }
            kept.append(digit)
        }
        kept.removeLast(min(removalsLeft, kept.count))
        let trimmed = kept.drop { $0 == "0" }
        return trimmed.isEmpty ? "0" : String(trimmed)
    }
}
```

**Why greedy is right.** Suppose some kept digit is bigger than the digit right after it. Removing it makes that position smaller and leaves everything to its left unchanged, so the result beats any answer that keeps it. Making the leftmost such improvement first, as many times as allowed, can't be beaten. Each digit is pushed once and popped at most once.

</Approach>
