You have a budget of steps, say 10⁸ for about one second. For an algorithm in a given growth class, how big an input can it handle within that budget? Return the **largest** n ≥ 0 whose step count is at most `budget`, using these exact step counts:

| `Growth` | Steps for input size n |
| --- | --- |
| `.linear` | n |
| `.linearithmic` | n × ⌊log₂ n⌋, which is 0 for n = 0 and n = 1 |
| `.quadratic` | n² |
| `.cubic` | n³ |
| `.exponential` | 2ⁿ |
| `.factorial` | n!, with 0! = 1 |

`BudgetInputSize.largestInput(for growth: Growth, budget: Int) -> Int`

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `largestInput(for: .linear, budget: 100_000_000)` | `100000000` | one step per element |
| `largestInput(for: .linearithmic, budget: 100_000_000)` | `4545454` | 4,545,454 × 22 = 99,999,988 |
| `largestInput(for: .quadratic, budget: 100_000_000)` | `10000` | 10,000² = 10⁸ exactly |
| `largestInput(for: .cubic, budget: 100_000_000)` | `464` | 464³ = 99,897,344 and 465³ is over |
| `largestInput(for: .exponential, budget: 100_000_000)` | `26` | 2²⁶ = 67,108,864 and 2²⁷ is over |
| `largestInput(for: .factorial, budget: 100_000_000)` | `11` | 11! = 39,916,800 and 12! is over |
| `largestInput(for: .exponential, budget: 1)` | `0` | 2⁰ = 1 fits, 2¹ = 2 doesn't |

With a budget 1,000 times bigger, 10¹¹, the answers are 10¹¹, 3,225,806,451, 316,227, 4,641, 36 and 14: the quadratic algorithm handles about 31 times more data, and the exponential one just 10 more elements.

## Constraints

- `1 ≤ budget ≤ 10¹²`.
- A loop that tries n = 1, 2, 3, … is fine for every class except `.linear` and `.linearithmic`, whose answers can be in the tens of billions.
- Every step count you need to check fits in an `Int`, as long as you stop as soon as one is over the budget.

<Hints>
<Hint>
For `.quadratic`, `.cubic`, `.exponential` and `.factorial`, grow n one at a time while the **next** n still fits: `while (n + 1) * (n + 1) <= budget`. With a budget of at most 10¹², that's at most a million passes. For `.exponential` and `.factorial`, keep a running power or product instead of recomputing it each time.
</Hint>
<Hint>
`.linear` needs no loop. For `.linearithmic`, ⌊log₂ n⌋ is the same number k for every n from 2ᵏ up to 2ᵏ⁺¹ − 1. Within that band the step count is just n × k, so the biggest n in the band that fits is `budget / k`, if that's still inside the band.
</Hint>
<Hint>
For `.linearithmic`, go through the bands k = 1, 2, 3, …. If `budget / k` is at least 2ᵏ, then the band has room: the best n so far is the smaller of `budget / k` and 2ᵏ⁺¹ − 1, and you move on to the next band. Otherwise the budget runs out before this band starts, so stop. Start with n = 1, which costs 0 steps.
</Hint>
</Hints>

## Solutions

<Approach title="Try every n" time="O(answer)" space="O(1)">

Keep increasing n while the next size still fits. It's exactly right, and fast for the fast-growing classes, but for `.linear` and `.linearithmic` with a budget of 10¹² it would need tens of billions of passes.

```swift
public static func largestInput(for growth: Growth, budget: Int) -> Int {
    var n = 0
    while steps(growth, n + 1) <= budget {
        n += 1
    }
    return n
}
```

`steps` would compute the table above. Even writing it is awkward: 2ⁿ and n! overflow long before n reaches a billion.

</Approach>

<Approach title="Short loops, and whole bands for n log n" time="O(budget^(1/2)) at worst" space="O(1)">

`.linear` is the budget itself. The fast-growing classes take short loops: at most 10⁶ passes for `.quadratic`, 10⁴ for `.cubic`, about 40 for `.exponential` and 15 for `.factorial`. Each loop checks the next size before moving to it, so it never computes a step count far over the budget.

For `.linearithmic`, the trick from the hint: within the band 2ᵏ to 2ᵏ⁺¹ − 1, ⌊log₂ n⌋ is k, so the step count is n × k, and the band's biggest affordable n is `budget / k`. About 40 bands cover every budget.

```swift
public enum BudgetInputSize {
    public enum Growth: CaseIterable {
        case linear, linearithmic, quadratic, cubic, exponential, factorial
    }

    public static func largestInput(for growth: Growth, budget: Int) -> Int {
        switch growth {
        case .linear:
            return budget
        case .linearithmic:
            var best = 1
            var k = 1
            while budget / k >= 1 << k {
                best = min(budget / k, (1 << (k + 1)) - 1)
                k += 1
            }
            return best
        case .quadratic:
            var n = 0
            while (n + 1) * (n + 1) <= budget {
                n += 1
            }
            return n
        case .cubic:
            var n = 0
            while (n + 1) * (n + 1) * (n + 1) <= budget {
                n += 1
            }
            return n
        case .exponential:
            var n = 0
            var power = 1
            while power * 2 <= budget {
                power *= 2
                n += 1
            }
            return n
        case .factorial:
            var n = 1
            var product = 1
            while product * (n + 1) <= budget {
                product *= n + 1
                n += 1
            }
            return n
        }
    }
}
```

The answers make the lesson's point with real numbers: multiplying the budget by 1,000 multiplies the linear answer by 1,000, the quadratic one by about 31, and adds 10 to the exponential one.

</Approach>
