A travel site shows, for every possible trip of consecutive days, the cheapest daily rate during that trip. For a report, it needs the sum of those cheapest rates over **all** contiguous trips. Given the daily rates, return that sum.

`RunMinimumTotal.total(_ rates: [Int]) -> Int`

A list of n days has n(n + 1) / 2 trips: every choice of a first and a last day, with the first no later than the last.

## Examples

| `rates` | Output |
| --- | --- |
| `[3, 1, 2, 4]` | `17` |
| `[1, 2, 3]` | `10` |
| `[2, 2, 2]` | `12` |
| `[5]` | `5` |
| `[]` | `0` |

For `[3, 1, 2, 4]`, the ten trips have cheapest rates 3, 1, 2 and 4 (one day each), 1, 1 and 2 (two days), 1 and 1 (three days) and 1 (all four): 17 in total. In `[2, 2, 2]`, all six trips have a cheapest rate of 2.

## Constraints

- `0 ≤ rates.count ≤ 100,000`, and every rate is between 1 and 10,000. The answer fits in an `Int`.
- The tests use 100,000 days, which is 5 × 10⁹ trips: listing them is far too slow.

<Hints>
<Hint>
Turn the sum around: instead of finding each trip's cheapest day, ask for each day how many trips it's the cheapest day of. Day i contributes `rates[i] × (number of trips whose minimum is day i)`.
</Hint>
<Hint>
Day i is the minimum of a trip exactly when the trip starts after the nearest earlier day with a lower rate, and ends before the nearest later day with a lower rate. If those are `left` positions and `right` positions away, there are `left × right` such trips. Equal rates need care: treat ties as "lower" on one side only (say, strictly lower on the left, lower or equal on the right), so a trip with two equal minimums is counted once.
</Hint>
<Hint>
Both nearest-lower distances come from a monotonic stack of indexes with increasing rates, in one pass each way, or in one pass: when day j pops day i off the stack because `rates[j] <= rates[i]`, j is i's next lower-or-equal day, and the element below i on the stack is its previous strictly lower day.
</Hint>
</Hints>

## Solutions

<Approach title="Every trip, with a running minimum" time="O(n²)" space="O(1)">

For each first day, walk the last day forward keeping a running minimum and add it each time. It's simple and the tests use it on small inputs, but 100,000 days means 5 × 10⁹ steps.

</Approach>

<Approach title="Each day's share, from a monotonic stack" time="O(n)" space="O(n)">

```swift
public enum RunMinimumTotal {
    public static func total(_ rates: [Int]) -> Int {
        let n = rates.count
        var previousLower = [Int](repeating: -1, count: n)    // nearest earlier index with a strictly lower rate
        var nextLowerOrEqual = [Int](repeating: n, count: n)  // nearest later index with a lower or equal rate
        var stack: [Int] = []                                // indexes, rates increasing upwards
        for j in 0..<n {
            while let top = stack.last, rates[j] <= rates[top] {
                nextLowerOrEqual[top] = j
                stack.removeLast()
            }
            previousLower[j] = stack.last ?? -1
            stack.append(j)
        }
        var sum = 0
        for i in 0..<n {
            sum += rates[i] * (i - previousLower[i]) * (nextLowerOrEqual[i] - i)
        }
        return sum
    }
}
```

Each index is pushed and popped once, so the pass is O(n). The tie rule, strictly lower on the left but lower-or-equal on the right, gives every trip exactly one "owner": among equal minimums, the rightmost one, because every earlier equal day's trips are cut off at that day. Without it, `[2, 2, 2]` would count some trips two or three times.

</Approach>
