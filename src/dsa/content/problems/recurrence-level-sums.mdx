A divide-and-conquer algorithm does T(n) = a · T(n / b) + n^d work, with T(1) = 1, for n a power of b. Compute that work exactly, and say which Master theorem case it falls into, so you can watch the numbers agree with the prediction.

`RecurrenceLevelSums.work(n: Int, a: Int, b: Int, d: Int) -> Int` returns T(n) exactly.

`RecurrenceLevelSums.predictedCase(a: Int, b: Int, d: Int) -> MasterCase` returns `.rootDominates` when a is less than bᵈ (the answer is Θ(nᵈ)), `.balanced` when a equals bᵈ (Θ(nᵈ log n)), and `.leavesDominate` when a is greater than bᵈ (Θ(n^(log_b a))).

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `work(n: 8, a: 2, b: 2, d: 1)` | `32` | levels of 8, 2 × 4, 4 × 2 and 8 × 1: merge sort's n log n + n |
| `work(n: 64, a: 1, b: 2, d: 1)` | `127` | 64 + 32 + … + 1 = 2n − 1 |
| `work(n: 64, a: 4, b: 2, d: 1)` | `8128` | 2n² − n |
| `work(n: 27, a: 2, b: 3, d: 1)` | `65` | 27 + 2 × 9 + 4 × 3 + 8 × 1 |
| `predictedCase(a: 2, b: 2, d: 1)` | `.balanced` | 2 = 2¹ |
| `predictedCase(a: 1, b: 2, d: 1)` | `.rootDominates` | 1 is less than 2¹ |
| `predictedCase(a: 4, b: 2, d: 1)` | `.leavesDominate` | 4 is greater than 2¹ |

## Constraints

- `1 ≤ a ≤ 16`, `2 ≤ b ≤ 10`, `0 ≤ d ≤ 3`.
- n is a power of b (including b⁰ = 1), at most 10¹⁸, and T(n) fits in an `Int`.
- Running the recursion can take far too long: `work(n: 1 << 30, a: 4, b: 2, d: 1)` would make over 10¹⁸ calls.

<Hints>
<Hint>
Picture the recursion tree. Level 0 is one call on size n. Level 1 is a calls on size n / b. Level i is aⁱ calls, each on size n / bⁱ, and each doing (n / bⁱ)ᵈ work of its own. The last level is the one where the size reaches 1.
</Hint>
<Hint>
So T(n) is the sum over the levels of aⁱ × (n / bⁱ)ᵈ. There are only about log_b n + 1 levels, at most 61. Walk down them with two running values: the number of calls on the level (multiply by a each step) and the size (divide by b).
</Hint>
<Hint>
Each level's total is at most T(n), so it fits in an `Int`. Just don't compute anything for a level below the last one: stop as soon as the size is 1. For `predictedCase`, compute bᵈ with a small loop and compare it with a.
</Hint>
</Hints>

## Solutions

<Approach title="Run the recursion" time="O(number of calls)" space="O(log n)">

The direct translation is correct, and fine for small inputs, but it makes 1 + a + a² + … calls. When the leaves dominate, that's as much as the answer itself, which can be 10¹⁸.

```swift
public static func work(n: Int, a: Int, b: Int, d: Int) -> Int {
    if n == 1 {
        return 1
    }
    var own = 1
    for _ in 0..<d {
        own *= n
    }
    var total = own
    for _ in 0..<a {
        total += work(n: n / b, a: a, b: b, d: d)
    }
    return total
}
```

</Approach>

<Approach title="Add up the recursion tree level by level" time="O(log n)" space="O(1)">

All aⁱ calls on level i have the same size, so the level's work is aⁱ × (n / bⁱ)ᵈ, one multiplication instead of aⁱ calls. Summing the levels is exactly the recursion-tree method that the Master theorem packages up. The ratio between consecutive levels is a / bᵈ, which is why comparing a with bᵈ predicts where the work concentrates.

```swift
public enum RecurrenceLevelSums {
    public enum MasterCase: Equatable {
        case rootDominates, balanced, leavesDominate
    }

    static func power(_ base: Int, _ exponent: Int) -> Int {
        var result = 1
        for _ in 0..<exponent {
            result *= base
        }
        return result
    }

    public static func work(n: Int, a: Int, b: Int, d: Int) -> Int {
        var total = 0
        var calls = 1
        var size = n
        while true {
            total += calls * power(size, d)
            if size == 1 {
                return total
            }
            calls *= a
            size /= b
        }
    }

    public static func predictedCase(a: Int, b: Int, d: Int) -> MasterCase {
        let split = power(b, d)
        if a < split { return .rootDominates }
        if a == split { return .balanced }
        return .leavesDominate
    }
}
```

The exact numbers back up the prediction. Multiplying n by b multiplies T(n) by about bᵈ when the root dominates, by a little more than bᵈ when the levels are balanced (one extra level), and by about a when the leaves dominate.

</Approach>
