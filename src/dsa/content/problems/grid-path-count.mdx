A delivery robot sits in the top-left cell of a grid with `rows` rows and `columns` columns. It needs to reach the bottom-right cell, and it can only move one cell **right** or one cell **down** at a time. Return how many different routes it could take.

`GridPathCount.paths(rows: Int, columns: Int) -> Int`

The plain recursion from [Multiple recursion and exponential blow-up](/dsa/learn/rec-multiple-recursion) gives the right answers, but it's far too slow for the larger grids in the tests. Make it fast with memoisation.

## Examples

| `rows` | `columns` | Output | Why |
| --- | --- | --- | --- |
| `1` | `1` | `1` | already there: the empty route |
| `1` | `5` | `1` | straight along the only row |
| `2` | `2` | `2` | right then down, or down then right |
| `3` | `3` | `6` | |
| `3` | `7` | `28` | |
| `30` | `30` | `30067266499541040` | |

## Constraints

- `1 ≤ rows ≤ 30`
- `1 ≤ columns ≤ 30`
- The answer always fits in an `Int`.

<Hints>
<Hint>
Every route begins with a move down or a move right. After a move down, what's left is a route through a grid with one fewer row; after a move right, one fewer column. A grid with a single row or column has exactly one route.
</Hint>
<Hint>
That recursion asks about the same smaller grids again and again: both "down, right" and "right, down" lead to the grid with one fewer row and one fewer column. Store each answer the first time you compute it.
</Hint>
<Hint>
The key is the pair `(rows, columns)`. Tuples can't be dictionary keys, so define a tiny `struct Size: Hashable` with both numbers, keep `var cache: [Size: Int]` in the outer function, and put the recursion in a nested helper that checks and fills the cache.
</Hint>
</Hints>

## Solutions

<Approach title="Plain recursion" time="about 2 × answer calls" space="O(rows + columns)">

Correct and clearly mirrors the reasoning, but every leaf of the recursion tree returns 1, so it makes about twice as many calls as there are routes. A 16 × 16 grid has 155,117,520 routes; a 30 × 30 grid has about 3 × 10¹⁶. This version passes the small tests and never finishes the big ones.

```swift
public static func paths(rows: Int, columns: Int) -> Int {
    if rows == 1 || columns == 1 {
        return 1
    }
    return paths(rows: rows - 1, columns: columns) + paths(rows: rows, columns: columns - 1)
}
```

</Approach>

<Approach title="Memoised recursion" time="O(rows × columns)" space="O(rows × columns)">

The same recursion with a cache, following the recipe from [A preview of memoisation](/dsa/learn/rec-memo-preview). There are only `rows × columns` different grids the recursion can ask about, and each is now computed once with O(1) work. The recursion is at most `rows + columns` calls deep.

```swift
public enum GridPathCount {
    private struct Size: Hashable {
        let rows: Int
        let columns: Int
    }

    public static func paths(rows: Int, columns: Int) -> Int {
        var cache: [Size: Int] = [:]

        func count(_ rows: Int, _ columns: Int) -> Int {
            if rows == 1 || columns == 1 {
                return 1
            }
            let key = Size(rows: rows, columns: columns)
            if let known = cache[key] {
                return known
            }
            let result = count(rows - 1, columns) + count(rows, columns - 1)
            cache[key] = result
            return result
        }

        return count(rows, columns)
    }
}
```

</Approach>

<Approach title="Counting with combinations" time="O(min(rows, columns))" space="O(1)">

Every route is exactly `rows − 1` moves down and `columns − 1` moves right, in some order. Choosing which of the `rows + columns − 2` moves are the downward ones picks the route, so the answer is the number of combinations C(rows + columns − 2, rows − 1), from [Factorials, permutations and combinations](/dsa/learn/math-counting).

Computing factorials directly would overflow, so build the combination up one factor at a time. After step `i`, `result` holds C(n − k + i, i), a whole number, so each division is exact, and the intermediate products stay within `Int` for these sizes.

```swift
public static func paths(rows: Int, columns: Int) -> Int {
    let n = rows + columns - 2
    let k = min(rows, columns) - 1
    var result = 1
    if k > 0 {
        for i in 1...k {
            result = result * (n - k + i) / i
        }
    }
    return result
}
```

This is the fastest version, but it depends on spotting the maths. Memoisation works even when the grid has blocked cells or other twists that break the formula, which is why it's the technique to learn first. You'll meet this exact grid again in M52, solved bottom-up.

</Approach>
