An **inversion** is a pair of positions i < j where the earlier value is bigger: `numbers[i] > numbers[j]`. Count the inversions in an array. A sorted array has none; a reversed one has as many as possible.

`InversionCount.count(in numbers: [Int]) -> Int`

Equal values are not an inversion. Aim for O(n log n): the tests include 100,000 numbers, where checking every pair means 5 billion comparisons.

## Examples

| `numbers` | Returns | The inversions |
| --- | --- | --- |
| `[4, 1, 3, 2]` | `4` | (4, 1), (4, 3), (4, 2), (3, 2) |
| `[2, 4, 1, 3, 5]` | `3` | (2, 1), (4, 1), (4, 3) |
| `[1, 2, 3, 4]` | `0` | none |
| `[5, 4, 3, 2, 1]` | `10` | every pair |
| `[3, 3, 1]` | `2` | each 3 with the 1 |
| `[]` | `0` | none |

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- Any `Int` values, with duplicates.
- The answer can be close to n² / 2, about 5 × 10⁹ for the largest inputs. That fits easily in a 64-bit `Int`, but not in an `Int32`.

<Hints>
<Hint>
Write the O(n²) version first: two nested loops counting the pairs. It's a perfect checker for the fast version on small inputs.
</Hint>
<Hint>
Split the array into halves. Every inversion is inside the left half, inside the right half, or "across": a value in the left half bigger than a value in the right half. Count the first two kinds recursively. The across kind is easy to count once both halves are sorted.
</Hint>
<Hint>
Merge the sorted halves. Whenever you take a value from the right half, it's smaller than every value still waiting in the left half, so add `mid - left` in one step. On a tie, take the left value first, and count nothing.
</Hint>
</Hints>

## Solutions

<Approach title="Check every pair" time="O(n²)" space="O(1)">

Fine for a few thousand numbers, and the reference you test the fast version against. For 100,000 numbers it makes about 5 billion comparisons.

```swift
public static func count(in numbers: [Int]) -> Int {
    var count = 0
    for i in numbers.indices {
        for j in (i + 1)..<numbers.count where numbers[i] > numbers[j] {
            count += 1
        }
    }
    return count
}
```

</Approach>

<Approach title="Count while merge sorting" time="O(n log n)" space="O(n)">

Sorting each half doesn't change how many across pairs there are: it only reorders values within a half, and "left value bigger than right value" doesn't depend on order. During the merge, a value taken from the right half jumps ahead of everything left in the left half, and each of those jumps is exactly one inversion.

```swift
public enum InversionCount {
    public static func count(in numbers: [Int]) -> Int {
        var items = numbers
        var buffer = numbers
        return sortAndCount(&items, &buffer, 0, items.count)
    }

    /// Sorts items[low..<high] and returns the number of inversions it held.
    private static func sortAndCount(_ items: inout [Int], _ buffer: inout [Int], _ low: Int, _ high: Int) -> Int {
        guard high - low > 1 else { return 0 }
        let mid = low + (high - low) / 2
        var inversions = sortAndCount(&items, &buffer, low, mid) + sortAndCount(&items, &buffer, mid, high)
        for index in low..<high {
            buffer[index] = items[index]
        }
        var left = low
        var right = mid
        for write in low..<high {
            if right == high || (left < mid && buffer[left] <= buffer[right]) {
                items[write] = buffer[left]
                left += 1
            } else {
                items[write] = buffer[right]
                right += 1
                inversions += mid - left                 // smaller than everything left in the left half
            }
        }
        return inversions
    }
}
```

The `<=` matters: if a tie took the right value, it would count the equal left values as inversions.

</Approach>
