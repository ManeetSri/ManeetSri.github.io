A list may loop back on itself: following `next` from some node leads back to an earlier node, forever. Write one function that says whether the list has such a cycle, and another that returns the first node of the cycle, the node where the loop begins. Don't change the list.

`CycleEntryPoint.hasCycle(_ head: ListNode?) -> Bool` and `CycleEntryPoint.entry(_ head: ListNode?) -> ListNode?`

`entry` returns `nil` when the list ends in `nil`. The tests check that it returns the very node (compared with `===`), not just a node with the same value.

## Examples

| List | `hasCycle` | `entry` |
| --- | --- | --- |
| `1 2 3 4 5 6`, last node points back to the 3 | `true` | the node holding 3 |
| `1 2 3 4 5 6`, last node points back to the 1 | `true` | the head |
| `9`, pointing at itself | `true` | the 9 |
| `1 2 3`, ending in `nil` | `false` | `nil` |
| empty | `false` | `nil` |

DSAKit's `ListNode.make(_:loopingTo:)` builds lists like these for your own experiments: `ListNode.make([1, 2, 3, 4, 5, 6], loopingTo: 2)` makes the first one.

## Constraints

- Up to 100,000 nodes.
- Values can repeat, so they can't identify a node.
- Aim for O(n) time and O(1) extra space. A `Set` of visited nodes is a fine first version.

<Hints>
<Hint>
A first version: walk the list, remembering every node you've seen in a `Set<ObjectIdentifier>`. The first node you meet a second time is the entry; reaching `nil` means there's no cycle.
</Hint>
<Hint>
For O(1) space, move a slow pointer one step and a fast pointer two steps at a time. If fast reaches `nil`, there's no cycle. If they ever land on the same node, there is one. Compare after moving, not before: they both start at the head.
</Hint>
<Hint>
From the meeting point, the entry is exactly as many steps away (going round the loop) as it is from the head. So put one pointer back at the head, leave the other at the meeting point, and move both one step at a time until they meet.
</Hint>
</Hints>

## Solutions

<Approach title="Remember every node" time="O(n)" space="O(n)">

`Set.insert` returns whether the element was new, so a node whose identifier was already in the set is the first node visited twice: the cycle's entry.

```swift
public static func entry(_ head: ListNode?) -> ListNode? {
    var seen = Set<ObjectIdentifier>()
    var current = head
    while let node = current {
        if !seen.insert(ObjectIdentifier(node)).inserted {
            return node
        }
        current = node.next
    }
    return nil
}

public static func hasCycle(_ head: ListNode?) -> Bool {
    entry(head) != nil
}
```

</Approach>

<Approach title="Floyd's tortoise and hare" time="O(n)" space="O(1)">

Inside a cycle, fast gains exactly one node on slow per step, so it can't jump over it: they must meet. If `a` is the distance from the head to the entry and the cycle has `c` nodes, slow has walked a multiple of `c` steps when they meet, which puts the meeting point exactly `a` steps (round the loop) before the entry. Two pointers moving at the same speed, one from the head and one from the meeting point, therefore arrive at the entry together.

```swift
import DSAKit

public enum CycleEntryPoint {
    /// The node where slow and fast meet, or nil if fast runs off the end.
    private static func meetingPoint(_ head: ListNode?) -> ListNode? {
        var slow = head
        var fast = head
        while let next = fast?.next {
            slow = slow?.next
            fast = next.next
            if let fast, fast === slow {
                return fast
            }
        }
        return nil
    }

    public static func hasCycle(_ head: ListNode?) -> Bool {
        meetingPoint(head) != nil
    }

    public static func entry(_ head: ListNode?) -> ListNode? {
        guard var inside = meetingPoint(head), var outside = head else {
            return nil
        }
        while outside !== inside {
            outside = outside.next!   // both are on the path into the cycle, so never nil
            inside = inside.next!
        }
        return outside
    }
}
```

Neither function changes a single `next` reference, so the list is left exactly as it was.

</Approach>
