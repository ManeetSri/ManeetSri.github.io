Bars of width 1 stand side by side, with the given heights. When it rains, water collects in the dips between bars. Return the total number of units of water trapped.

`TrappedRainwater.trappedWater(heights: [Int]) -> Int`

The water above one bar rises to the lower of the tallest bar on its left and the tallest bar on its right, counting the bar itself in both, so the water there is that level minus the bar's own height.

## Examples

| `heights` | Output |
| --- | --- |
| `[4, 1, 3, 0, 2, 5, 1, 2]` | `11` |
| `[3, 0, 1, 0, 2]` | `5` |
| `[5, 2, 5]` | `3` |
| `[0, 4, 0, 0, 4, 0]` | `8` |
| `[1, 2, 3]` | `0` |
| `[]` | `0` |

In the first example, the positions hold 0, 3, 1, 4, 2, 0, 1 and 0 units. In the fourth, the water between the two 4s is 4 deep over two positions, and nothing is held outside them.

## Constraints

- `0 ≤ heights.count ≤ 100,000`
- `0 ≤ heights[i] ≤ 100,000`
- Aim for O(n) time; for the full solution, O(1) extra space. The answer fits in an `Int`.

<Hints>
<Hint>
Work one position at a time. The brute force scans left and right from every bar for the tallest bars, which is O(n²).
</Hint>
<Hint>
The tallest bar on the left of each position is a running maximum from the left; the tallest on the right is a running maximum from the right. Two arrays of maximums give an O(n) solution with O(n) space.
</Hint>
<Hint>
For O(1) space, move two pointers inwards, each keeping the tallest bar it has seen. If `leftMax <= rightMax`, the water at `left` is exactly `leftMax - heights[left]`: the true tallest bar on its right is at least `rightMax`. Settle that position and move `left`; otherwise settle `right`. Visit every position, including the one where the pointers meet.
</Hint>
</Hints>

## Solutions

<Approach title="Scan both ways at every bar" time="O(n²)" space="O(1)">

```swift
public static func trappedWater(heights: [Int]) -> Int {
    var total = 0
    for i in heights.indices {
        let level = min(heights[...i].max()!, heights[i...].max()!)
        total += level - heights[i]
    }
    return total
}
```

Both slices include `heights[i]`, so neither is empty, the force unwraps are safe, and the water is never negative.

</Approach>

<Approach title="Prefix and suffix maximums" time="O(n)" space="O(n)">

The repeated scans compute running maximums from scratch. Precompute them once from each end, then combine them position by position.

```swift
public static func trappedWater(heights: [Int]) -> Int {
    let n = heights.count
    guard n > 0 else { return 0 }
    var leftMax = heights
    var rightMax = heights
    for i in stride(from: 1, to: n, by: 1) {
        leftMax[i] = max(leftMax[i - 1], heights[i])
    }
    for i in stride(from: n - 2, through: 0, by: -1) {
        rightMax[i] = max(rightMax[i + 1], heights[i])
    }
    var total = 0
    for i in 0..<n {
        total += min(leftMax[i], rightMax[i]) - heights[i]
    }
    return total
}
```

Starting both arrays as copies of `heights` sets their end values for free.

</Approach>

<Approach title="Two pointers with running maximums" time="O(n)" space="O(1)">

You never need both maximums at a position, only the smaller one. `leftMax` is exact for the left pointer's position, because it has seen every bar to the left. `rightMax` can only underestimate the true tallest bar on the right of `left`. So when `leftMax <= rightMax`, the smaller one is certainly `leftMax`, and the water at `left` is settled. The other side is the mirror image.

```swift
public enum TrappedRainwater {
    public static func trappedWater(heights: [Int]) -> Int {
        var left = 0
        var right = heights.count - 1
        var leftMax = 0
        var rightMax = 0
        var total = 0
        while left <= right {
            leftMax = max(leftMax, heights[left])
            rightMax = max(rightMax, heights[right])
            if leftMax <= rightMax {
                total += leftMax - heights[left]
                left += 1
            } else {
                total += rightMax - heights[right]
                right -= 1
            }
        }
        return total
    }
}
```

Each pointer updates its maximum before using it, so the bar underneath is always included and the water is never negative. An empty array never enters the loop. A monotonic stack gives a third O(n) solution, which M26 covers.

</Approach>
