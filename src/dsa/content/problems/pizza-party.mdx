You're organising a pizza party. Write two small calculations: what the pizzas cost, and how many slices each person gets.

- `PizzaParty.cost(pizzas: Int, pricePerPizza: Double) -> Double` returns the total cost.
- `PizzaParty.slicesPerPerson(slices: Int, people: Int) -> Double` returns each person's share when the slices are split equally, **including any fraction of a slice**.

Both mix whole numbers and decimals, so you'll need to convert types yourself.

## Examples

| Call | Returns |
| --- | --- |
| `cost(pizzas: 3, pricePerPizza: 8.5)` | `25.5` |
| `cost(pizzas: 0, pricePerPizza: 9.99)` | `0.0` |
| `slicesPerPerson(slices: 16, people: 4)` | `4.0` |
| `slicesPerPerson(slices: 7, people: 2)` | `3.5` |
| `slicesPerPerson(slices: 8, people: 3)` | `2.6666666666666665` |

## Constraints

- `0 ≤ pizzas ≤ 1,000` and `0 ≤ pricePerPizza ≤ 1,000`
- `0 ≤ slices ≤ 10,000` and `1 ≤ people ≤ 1,000`
- Results are checked to within a tiny tolerance, so the last digit of a `Double` doesn't matter.

<Hints>
<Hint>
`pizzas * pricePerPizza` won't compile: `*` needs two values of the same type. Which one should change?
</Hint>
<Hint>
`Double(pizzas)` makes a `Double` from an `Int`. For the slices, both values are `Int`, but the answer must keep its fraction.
</Hint>
<Hint>
`Double(slices / people)` gives `3.0` for 7 slices and 2 people, because `slices / people` is whole-number division done first. Convert **before** dividing: `Double(slices) / Double(people)`.
</Hint>
</Hints>

## Solutions

<Approach title="Convert, then calculate" time="O(1)" space="O(1)">

Swift never mixes `Int` and `Double` by itself, so each function converts its `Int` values with `Double(...)` before doing the arithmetic.

```swift
public enum PizzaParty {
    public static func cost(pizzas: Int, pricePerPizza: Double) -> Double {
        return Double(pizzas) * pricePerPizza
    }

    public static func slicesPerPerson(slices: Int, people: Int) -> Double {
        return Double(slices) / Double(people)
    }
}
```

The order matters in the second function. Converting first means the division happens between two `Double` values and keeps the fraction. Each function does a fixed amount of work whatever the inputs, so both are O(1).

</Approach>
