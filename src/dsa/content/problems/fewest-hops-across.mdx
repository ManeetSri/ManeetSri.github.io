Stepping stones cross a river in a straight line, numbered from `0` (your bank) to the last stone (the far bank). `steps[i]` is the longest hop you can make from stone `i`: from it you can land on any stone from `i + 1` to `i + steps[i]`. Return the fewest hops that take you from stone 0 to the last stone, or `-1` if the far bank can't be reached.

`FewestHopsAcross.fewestHops(_ steps: [Int]) -> Int`

## Examples

| `steps` | Output | Why |
| --- | --- | --- |
| `[2, 3, 1, 1, 4, 2, 1, 3, 1]` | `3` | for example 0 → 1 → 4 → 8 |
| `[1, 1, 1]` | `2` | one stone at a time |
| `[5]` | `0` | you're already on the last stone |
| `[1, 0, 4]` | `-1` | stone 1 is a dead end, and stone 0 can't hop past it |
| `[3, 0, 0, 1]` | `1` | straight from 0 to 3 |

## Constraints

- `1 ≤ steps.count ≤ 100,000` and `0 ≤ steps[i] ≤ 100,000`
- A stone with `steps[i] == 0` can be landed on but not left.
- The tests include 100,000 stones that can each hop to the far bank, so trying every possible hop from every stone is far too slow.

<Hints>
<Hint>
With 0 hops you can stand only on stone 0. With 1 hop, on stones 1 to `steps[0]`. What does the set of stones reachable in exactly 2 hops look like?
</Hint>
<Hint>
The stones reachable in k hops always form one unbroken range, right after the range for k − 1 hops. They're the levels of a breadth-first search, so you only need to know where each range ends.
</Hint>
<Hint>
Walk the stones once, keeping `farthest` (the farthest any stone seen so far can reach) and `rangeEnd` (the end of the current range). When `i == rangeEnd`, count a hop and set `rangeEnd = farthest`, unless `farthest` hasn't moved past `i`, which means you're stuck. Stop before the last stone.
</Hint>
</Hints>

## Solutions

<Approach title="Breadth-first search over the stones" time="O(n · s)" space="O(n)">

Treat each stone as a vertex with an edge to every stone it can hop to, and run BFS from stone 0, as in M42. It's correct, but with long hops there are up to n² edges to look at: about five billion for the largest tests.

```swift
public static func fewestHops(_ steps: [Int]) -> Int {
    let n = steps.count
    var distance = Array(repeating: -1, count: n)
    distance[0] = 0
    var queue = [0]
    var head = 0
    while head < queue.count {
        let stone = queue[head]
        head += 1
        for next in stride(from: stone + 1, through: min(stone + steps[stone], n - 1), by: 1) where distance[next] == -1 {
            distance[next] = distance[stone] + 1
            queue.append(next)
        }
    }
    return distance[n - 1]
}
```

</Approach>

<Approach title="Greedy ranges" time="O(n)" space="O(1)">

Each BFS level is a contiguous range, so two numbers replace the queue. After k hops, `rangeEnd` is the farthest stone any route of k hops can reach: a route of k + 1 hops makes its last hop from a stone in ranges 0 to k, and `farthest` is the best of those. So the first range that contains the last stone gives the fewest hops.

```swift
public enum FewestHopsAcross {
    public static func fewestHops(_ steps: [Int]) -> Int {
        var hops = 0
        var rangeEnd = 0                 // the last stone reachable with `hops` hops
        var farthest = 0                 // the farthest any stone seen so far can reach
        for i in 0..<(steps.count - 1) {
            farthest = max(farthest, i + steps[i])
            if i == rangeEnd {
                if farthest <= i { return -1 }      // nothing in this range gets past it
                hops += 1
                rangeEnd = farthest
            }
        }
        return hops
    }
}
```

The loop stops before the last stone: if it visited the last stone when that stone is exactly the end of a range, it would count a hop that's never taken.

</Approach>
