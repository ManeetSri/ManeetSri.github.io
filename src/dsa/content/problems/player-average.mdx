A score book maps each player's name to the list of their scores. Work out one player's average score, or `nil` if there's nothing to average.

`PlayerAverage.average(for player: String, in scores: [String: [Int]]) -> Double?`

Return `nil` when the player isn't in the book **or** is in the book with an empty list of scores.

## Examples

With `scores = ["Ana": [70, 80, 90], "Dev": [7, 8], "Cleo": []]`:

| Player | Output | Why |
| --- | --- | --- |
| `"Ana"` | `80.0` | (70 + 80 + 90) / 3 |
| `"Dev"` | `7.5` | keep the fraction |
| `"Cleo"` | `nil` | listed, but no scores |
| `"Zoe"` | `nil` | not in the book |

## Constraints

- The book has at most 1,000 players, each with at most 10,000 scores.
- `-10⁶ ≤ score ≤ 10⁶`
- Names are case-sensitive: `"ana"` is not `"Ana"`.

<Hints>
<Hint>
Looking up `scores[player]` gives an optional, `[Int]?`. It's nil when the player isn't listed.
</Hint>
<Hint>
Both "missing" cases mean "stop and return nil". One `guard let` can unwrap the lookup *and* check that the list isn't empty, with a comma between the two.
</Hint>
<Hint>
Add the scores up as an `Int`, then convert before dividing: `Double(total) / Double(count)`. Dividing two `Int`s would drop the fraction.
</Hint>
</Hints>

## Solutions

<Approach title="guard let, then add up" time="O(k)" space="O(1)">

`guard let playerScores = scores[player], !playerScores.isEmpty` handles both ways of having nothing to average in one place. After it, `playerScores` is a plain, non-empty array, so the division is safe.

```swift
public enum PlayerAverage {
    public static func average(for player: String, in scores: [String: [Int]]) -> Double? {
        guard let playerScores = scores[player], !playerScores.isEmpty else {
            return nil
        }
        var total = 0
        for score in playerScores {
            total += score
        }
        return Double(total) / Double(playerScores.count)
    }
}
```

The lookup is quick, and the loop visits each of the player's k scores once. Without the emptiness check, an empty list would divide 0 by 0, which for `Double`s gives `nan` ("not a number") rather than a helpful answer.

</Approach>
