A video page shows "views in the last five minutes". Build the counter behind it. Views arrive in batches, and a single batch can hold millions of views, so storing one entry per view is out of the question.

`BucketedViewCounter.Counter`, with `init(window:)`, `record(_ views: Int = 1, at time: Int)` and `count(at time: Int) -> Int`

- Times are whole seconds. The times passed to `record` and `count` never decrease from one call to the next (equal times are fine).
- `count(at: t)` is the total views recorded at seconds `t - window + 1` through `t`, both included.
- Both methods should be amortised O(1), whatever the number of views, using O(window) memory at most.

## Examples

With `var counter = Counter(window: 5)`:

| Calls | Result |
| --- | --- |
| `record(at: 1)`, `record(at: 2)`, `record(4, at: 2)`, `record(at: 6)` | |
| `count(at: 6)` | `6`: seconds 2 to 6 hold 1 + 4 + 1 |
| `count(at: 7)` | `1`: seconds 3 to 7 hold only the view at 6 |
| `count(at: 11)` | `0` |
| `Counter(window: 300)`: `record(50, at: 0)`, `record(7, at: 1_000_000_000)`, then `count(at: 1_000_000_000)` | `7` |

## Constraints

- `1 ≤ window ≤ 100,000`; `0 ≤ time ≤ 2,000,000,000`.
- `1 ≤ views ≤ 1,000,000` per call, and the total fits comfortably in an `Int`.
- Up to 200,000 calls. One test records a million views per call for 20,000 seconds.

<Hints>
<Hint>
You met the per-hit version in [Stream problems: first unique, moving average](/dsa/learn/queue-streams): a queue of timestamps, oldest first, dropping from the front anything at or before `t - window`. What goes wrong with a million views in one call?
</Hint>
<Hint>
Group views by second. Keep a queue of `(time, views)` buckets, oldest first. Views at the same second as the newest bucket join that bucket; otherwise a new bucket goes on the back. The queue never holds more than `window` buckets.
</Hint>
<Hint>
Summing the buckets on every `count` would be O(window). Keep a running `total` instead: add when recording, subtract when a bucket expires off the front. Both `record` and `count` should expire old buckets first. DSAKit's `Deque` makes a good queue: `import DSAKit`.
</Hint>
</Hints>

## Solutions

<Approach title="A ring of window slots, summed on each count" time="O(1) record, O(window) count" space="O(window)">

An array of `window` slots, where second `t` lives in slot `t % window` along with the time it belongs to, so a slot left over from an older second can be recognised and reset. Recording is O(1), and memory is fixed. But `count` has to visit every slot to add up the ones still inside the window, which is too slow with a large window and many queries.

```swift
public mutating func count(at time: Int) -> Int {
    var total = 0
    for slot in slots where slot.time > time - window {
        total += slot.views
    }
    return total
}
```

</Approach>

<Approach title="A queue of per-second buckets and a running total" time="amortised O(1)" space="O(window)">

Each second with views gets one bucket, however many views it had. Buckets join at the back and leave from the front, each exactly once, so the expiry loop costs O(1) per bucket over the counter's life.

```swift
import DSAKit

public enum BucketedViewCounter {
    public struct Counter {
        private let window: Int
        private var buckets = Deque<(time: Int, views: Int)>()
        private var total = 0

        public init(window: Int) {
            precondition(window > 0, "The window must be at least one second")
            self.window = window
        }

        public mutating func record(_ views: Int = 1, at time: Int) {
            expire(at: time)
            if let last = buckets.last, last.time == time {
                buckets[buckets.count - 1].views += views     // same second: grow its bucket
            } else {
                buckets.append((time, views))
            }
            total += views
        }

        public mutating func count(at time: Int) -> Int {
            expire(at: time)
            return total
        }

        /// Drops every bucket at or before `time - window`: it can never count again.
        private mutating func expire(at time: Int) {
            while let oldest = buckets.first, oldest.time <= time - window {
                total -= oldest.views
                buckets.popFirst()
            }
        }
    }
}
```

Expiring in `record` as well as `count` keeps memory bounded even if nobody ever asks for a count.

</Approach>
