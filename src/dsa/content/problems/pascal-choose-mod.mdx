Build rows of Pascal's triangle with every entry taken modulo 1,000,000,007, and use them to answer "n choose k" questions: the number of ways to pick k items from n when order doesn't matter.

`PascalChoose.row(_ n: Int) -> [Int]`

`PascalChoose.choose(_ n: Int, _ k: Int) -> Int`

`row(n)` returns row n of the triangle, counting from row 0, which is `[1]`. It has n + 1 entries, the kth being C(n, k) modulo 1,000,000,007. `choose(n, k)` returns that single entry, or 0 when k is negative or bigger than n, because there's no way to choose that many.

The true values get huge: C(1000, 500) has about 300 digits. Pascal's rule only adds, so you can reduce as you go and never divide.

## Examples

| Call | Returns | Why |
| --- | --- | --- |
| `row(0)` | `[1]` | the top of the triangle |
| `row(5)` | `[1, 5, 10, 10, 5, 1]` | each entry is the sum of the two above |
| `choose(5, 2)` | `10` | 10 ways to pick 2 of 5 |
| `choose(52, 5)` | `2598960` | five-card hands from a deck |
| `choose(1000, 500)` | `159835829` | the remainder of a 300-digit number |
| `choose(4, 7)` | `0` | you can't choose 7 from 4 |

## Constraints

- `0 ≤ n ≤ 1000`
- `k` can be any `Int` in `choose(_:_:)`.
- Every returned value is from 0 to 1,000,000,006.

<Hints>
<Hint>
Each row starts and ends with 1. Every other entry is the sum of the two entries diagonally above it: `next[k] = previous[k - 1] + previous[k]`.
</Hint>
<Hint>
Build the rows one at a time, keeping only the previous one, and take `% 1_000_000_007` after each addition. Two values below the modulus add up to less than 2.1 × 10⁹, so nothing overflows.
</Hint>
<Hint>
For `choose`, deal with k outside 0 to n first, then look up `row(n)[k]`. Don't try the factorial formula: it needs division, which doesn't survive taking remainders.
</Hint>
</Hints>

## Solutions

<Approach title="The factorial formula (doesn't work)" time="O(n)" space="O(1)">

C(n, k) = n! / (k! × (n − k)!) looks direct, but n! overflows for n above 20. Taking remainders first doesn't help either, because remainders can't be divided: (a / b) % m isn't (a % m) / (b % m). Making division work needs modular inverses, which come in M66. Pascal's triangle avoids division completely.

</Approach>

<Approach title="Pascal's triangle, row by row" time="O(n²)" space="O(n)">

Start from `[1]` and apply Pascal's rule n times. Each new row is one longer than the last. Only the previous row is needed, so the memory is O(n), and the n rows of up to n + 1 entries make O(n²) additions: about half a million for n = 1000.

```swift
public enum PascalChoose {
    private static let mod = 1_000_000_007

    public static func row(_ n: Int) -> [Int] {
        var current = [1]
        for _ in 0..<n {
            var next = [1]
            for k in 1..<current.count {
                next.append((current[k - 1] + current[k]) % mod)
            }
            next.append(1)
            current = next
        }
        return current
    }

    public static func choose(_ n: Int, _ k: Int) -> Int {
        guard k >= 0 && k <= n else { return 0 }
        return row(n)[k]
    }
}
```

Why does Pascal's rule hold? Pick one particular item. Every group of k either includes it, leaving k − 1 to choose from the other n − 1, or leaves it out, so all k come from the other n − 1. The two cases never overlap, so C(n, k) = C(n − 1, k − 1) + C(n − 1, k).

If you need many `choose` answers, build the whole triangle once as a 2D array, then answer each question in O(1). That's O(n²) memory instead of O(n), a fair trade for a million lookups.

</Approach>
