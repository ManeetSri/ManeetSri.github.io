A nested list holds numbers and other nested lists, to any depth. Write two recursive functions: one that pulls out every number in left-to-right order, and one that measures how deeply the list is nested.

`NestedListFlatten.flatten(_ item: Item) -> [Int]` and `NestedListFlatten.depth(_ item: Item) -> Int`

```swift
public indirect enum Item: Equatable {
    case number(Int)
    case list([Item])
}
```

The depth rules:

- A number on its own has depth 0.
- A list has depth one more than the deepest thing inside it.
- An empty list has depth 1: it's a list, with nothing inside.

## Examples

The middle column writes each item in a shorter bracket form.

| Item | Short form | `flatten` | `depth` |
| --- | --- | --- | --- |
| `.number(5)` | `5` | `[5]` | `0` |
| `.list([])` | `[]` | `[]` | `1` |
| `.list([.number(3), .number(-1), .number(4)])` | `[3, -1, 4]` | `[3, -1, 4]` | `1` |
| `.list([.number(1), .list([.number(2), .list([.number(3)])]), .number(4)])` | `[1, [2, [3]], 4]` | `[1, 2, 3, 4]` | `3` |
| `.list([.list([.list([])])])` | `[[[]]]` | `[]` | `3` |

## Constraints

- At most 10,000 items in total, numbers and lists together.
- Nesting is at most 100 levels deep.
- Numbers can be any `Int`.

<Hints>
<Hint>
Answer the three questions. What's the smallest item you can handle directly? A `.number`. How does a list's answer come from its items' answers? Combine them. Each item is smaller than the list holding it, so the recursion ends.
</Hint>
<Hint>
Use `switch` with one case per enum case, as in M09's expression trees. For `flatten`, a number gives a one-element array; a list gives its items' results joined in order. For `depth`, a list is `1 +` the largest depth among its items, or `1 + 0` when it's empty.
</Hint>
<Hint>
Joining arrays at every level copies numbers over and over. Instead, keep one `result` array outside a nested helper, and have the helper append each number it meets.
</Hint>
</Hints>

## Solutions

<Approach title="Recursion, joining results" time="O(n × d)" space="O(n)">

The most direct translation: a number becomes `[value]`, and a list joins its items' arrays. It's correct and easy to read, but every level copies all the numbers beneath it into a new array, so a number nested d levels deep is copied d times.

```swift
public static func flatten(_ item: Item) -> [Int] {
    switch item {
    case .number(let value):
        return [value]
    case .list(let items):
        var result: [Int] = []
        for child in items {
            result += flatten(child)
        }
        return result
    }
}
```

</Approach>

<Approach title="Recursion into one shared array" time="O(n)" space="O(d)">

A nested helper appends each number straight into a single `result` array, so nothing is copied. `depth` keeps the largest depth among a list's items. An empty list never enters its loop, which is the hidden base case: `deepest` stays 0 and the answer is 1. Both functions visit each item once, and the stack is as deep as the nesting.

```swift
public enum NestedListFlatten {
    public indirect enum Item: Equatable {
        case number(Int)
        case list([Item])
    }

    public static func flatten(_ item: Item) -> [Int] {
        var result: [Int] = []
        func collect(_ item: Item) {
            switch item {
            case .number(let value):
                result.append(value)
            case .list(let items):
                for child in items {
                    collect(child)
                }
            }
        }
        collect(item)
        return result
    }

    public static func depth(_ item: Item) -> Int {
        switch item {
        case .number:
            return 0
        case .list(let items):
            var deepest = 0
            for child in items {
                deepest = max(deepest, depth(child))
            }
            return 1 + deepest
        }
    }
}
```

</Approach>

<Approach title="An explicit stack, no recursion" time="O(n)" space="O(n)">

The technique from [Turning recursion into an explicit stack](/dsa/learn/rec-explicit-stack). The stack holds items still to visit. Push a list's items in **reverse**, so the first item is popped first and the numbers come out left to right. For `depth`, push each item with its depth alongside.

```swift
public static func flatten(_ item: Item) -> [Int] {
    var result: [Int] = []
    var stack = [item]
    while let next = stack.popLast() {
        switch next {
        case .number(let value):
            result.append(value)
        case .list(let items):
            stack.append(contentsOf: items.reversed())
        }
    }
    return result
}

public static func depth(_ item: Item) -> Int {
    var deepest = 0
    var stack = [(item, 0)]
    while let (next, level) = stack.popLast() {
        if case .list(let items) = next {
            deepest = max(deepest, level + 1)
            for child in items {
                stack.append((child, level + 1))
            }
        }
    }
    return deepest
}
```

The order doesn't matter for `depth`, so its items are pushed as they are. The stack can hold up to n items at once, more than the recursion's O(d) frames, but it lives on the heap, so even absurdly deep nesting can't overflow the call stack.

</Approach>
