A puzzle site gets four kinds of counting question, all modulo the prime 1,000,000,007, and they turn out to be the same sequence in disguise, each with its own offset. Answer a whole batch of them.

`CatalanDisguises.answers(_ questions: [CatalanDisguises.Question]) -> [Int]`

`Question` is an enum the stub defines:

- `.bracketStrings(pairs: n)`: strings of n `(` and n `)` in which no prefix has more `)` than `(`.
- `.treeShapes(nodes: n)`: shapes of binary trees with n nodes, where every node has an optional left and an optional right child, and left and right are different.
- `.triangulations(sides: s)`: ways to cut a convex polygon with s corners into triangles using diagonals that don't cross. s is at least 3.
- `.matrixOrders(matrices: m)`: ways to fully bracket a product of m matrices, that is, orders in which to do the m − 1 multiplications. m is at least 1.

Return the answers in order, each modulo 1,000,000,007.

## Examples

| `questions` | Output |
| --- | --- |
| `[.bracketStrings(pairs: 3), .treeShapes(nodes: 4)]` | `[5, 14]` |
| `[.triangulations(sides: 6), .triangulations(sides: 3)]` | `[14, 1]` |
| `[.matrixOrders(matrices: 4), .matrixOrders(matrices: 1)]` | `[5, 1]` |
| `[.bracketStrings(pairs: 0), .treeShapes(nodes: 0)]` | `[1, 1]` |
| `[.bracketStrings(pairs: 35), .treeShapes(nodes: 1_000_000)]` | `[93302951, 70646122]` |
| `[]` | `[]` |

With 3 pairs the strings are `((()))`, `(()())`, `(())()`, `()(())` and `()()()`. A hexagon has 14 triangulations, the same number as tree shapes with 4 nodes. Four matrices A, B, C and D can be multiplied as ((AB)C)D, (A(BC))D, (AB)(CD), A((BC)D) and A(B(CD)). C₃₅ is 3,116,285,494,907,301,262, which still fits in an `Int` but is reported modulo 1,000,000,007; C₃₆ no longer fits.

## Constraints

- Up to 100,000 questions.
- `0 ≤ pairs, nodes ≤ 1,000,000`, `3 ≤ sides ≤ 1,000,002` and `1 ≤ matrices ≤ 1,000,001`.
- The tests ask about sizes near a million, so the O(n²) recurrence is far too slow. Neither may you compute anything from scratch per question: precompute once, up to the largest size in the batch.

<Hints>
<Hint>
Count small cases by hand or with a brute force: 1, 1, 2, 5, 14 is the Catalan sequence. The work is in the offsets. A polygon with s corners has C(s − 2) triangulations: fix one side, and the triangle on it splits the rest into two smaller polygons. m matrices have C(m − 1) bracketings: the last multiplication splits them into two groups.
</Hint>
<Hint>
The closed form is Cₙ = C(2n, n) / (n + 1). Modulo a prime you can't divide the reduced value by n + 1. Multiply by its inverse instead, which Fermat's little theorem gives as (n + 1)^(p − 2) mod p, or use inverse factorials.
</Hint>
<Hint>
Find the largest n the batch needs, then build `factorial[0...2n]` and `inverseFactorial[0...2n]` once: compute the inverse of `factorial[2n]` with one modular power, then walk down with `inverseFactorial[i - 1] = inverseFactorial[i] * i % p`. Then Cₙ = (2n)! · (n!)⁻¹ · ((n + 1)!)⁻¹, three multiplications per question.
</Hint>
</Hints>

## Solutions

<Approach title="The recurrence" time="O(N²)" space="O(N)">

`C(0) = 1` and `C(n + 1) = Σ C(i) · C(n − i)` for i from 0 to n, reducing as you go. It's how the tests check small sizes, and it's what you'd write first, but for n near a million it's 5 × 10¹¹ steps.

</Approach>

<Approach title="Factorials and inverse factorials, once per batch" time="O(N + q)" space="O(N)">

```swift
public enum CatalanDisguises {
    public enum Question: Equatable {
        case bracketStrings(pairs: Int)
        case treeShapes(nodes: Int)
        case triangulations(sides: Int)
        case matrixOrders(matrices: Int)
    }

    private static let p = 1_000_000_007

    private static func index(of question: Question) -> Int {
        switch question {
        case .bracketStrings(let pairs): return pairs
        case .treeShapes(let nodes): return nodes
        case .triangulations(let sides): return sides - 2
        case .matrixOrders(let matrices): return matrices - 1
        }
    }

    private static func power(_ base: Int, _ exponent: Int) -> Int {
        var result = 1, base = base % p, exponent = exponent
        while exponent > 0 {
            if exponent & 1 == 1 { result = result * base % p }
            base = base * base % p
            exponent >>= 1
        }
        return result
    }

    public static func answers(_ questions: [Question]) -> [Int] {
        let indexes = questions.map(index(of:))
        let top = 2 * (indexes.max() ?? 0) + 1
        var factorial = [Int](repeating: 1, count: top + 1)
        for i in stride(from: 1, through: top, by: 1) { factorial[i] = factorial[i - 1] * i % p }
        var inverse = [Int](repeating: 1, count: top + 1)
        inverse[top] = power(factorial[top], p - 2)
        for i in stride(from: top, through: 1, by: -1) { inverse[i - 1] = inverse[i] * i % p }
        return indexes.map { n in factorial[2 * n] * inverse[n] % p * inverse[n + 1] % p }
    }
}
```

C(2n, n) / (n + 1) is (2n)! / (n! · n! · (n + 1)), and n! · (n + 1) = (n + 1)!, so one inverse factorial of each replaces the division. Every product is of two numbers below 10⁹ + 7, so it fits in an `Int` before reducing.

</Approach>
