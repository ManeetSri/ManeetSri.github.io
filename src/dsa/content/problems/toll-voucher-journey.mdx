You're driving from city `0` to city `cityCount - 1`. Two-way roads `[a, b, toll]` join the cities, and each charges its toll every time you use it. You also hold `vouchers` vouchers: each lets you drive along one road once for free. Return the smallest total toll for the journey, or `-1` if the destination can't be reached.

`TollVoucherJourney.cheapestCost(cityCount: Int, roads: [[Int]], vouchers: Int) -> Int`

## Examples

| `cityCount` | `roads` | `vouchers` | Output |
| --- | --- | --- | --- |
| `4` | `[[0, 1, 10], [1, 3, 10], [0, 2, 1], [2, 3, 30]]` | `0` | `20` |
| `4` | `[[0, 1, 10], [1, 3, 10], [0, 2, 1], [2, 3, 30]]` | `1` | `1` |
| `4` | `[[0, 1, 10], [1, 3, 10], [0, 2, 1], [2, 3, 30]]` | `2` | `0` |
| `4` | `[[0, 1, 50], [1, 3, 2], [0, 2, 10], [2, 3, 10]]` | `1` | `2` |
| `3` | `[[0, 1, 4]]` | `3` | `-1` |
| `1` | `[]` | `2` | `0` |

With no vouchers, the first map's cheapest route is 0 → 1 → 3 for 20. With one voucher, the dearer route 0 → 2 → 3 becomes the best: use the voucher on the 30 and pay 1. In the fourth map, the cheapest route without vouchers (0 → 2 → 3, for 20) isn't the one to spend the voucher on: 0 → 1 → 3 with the 50 free costs only 2.

## Constraints

- `1 ≤ cityCount ≤ 10,000` and `0 ≤ roads.count ≤ 50,000`
- `0 ≤ a, b < cityCount`, `0 ≤ toll ≤ 10,000`. There may be several roads between two cities, and a road may loop back to its own city.
- `0 ≤ vouchers ≤ 10`
- The tests use 10,000 cities and about 40,000 roads with up to 10 vouchers.

<Hint>
Finding the cheapest route first and then spending the vouchers on its dearest roads doesn't work: look at the fourth example. The vouchers change which route is best.
</Hint>
<Hint>
Put the vouchers into the state. A vertex is now (city, vouchers used so far), so there are `cityCount × (vouchers + 1)` of them.
</Hint>
<Hint>
From (city, used), a road with toll t leads to (next, used) at cost t, and, if `used < vouchers`, to (next, used + 1) at cost 0. All costs are non-negative, so run Dijkstra over these states and stop the first time any state of the destination is popped.
</Hint>

## Solutions

<Approach title="Try every set of free roads" time="O(2ᵐ · n · m)" space="O(n)">

For every choice of at most `vouchers` roads to make free, compute the cheapest route with those tolls set to 0. The best over all choices is the answer. It's a useful check on tiny inputs and hopeless beyond about 20 roads.

</Approach>

<Approach title="Dijkstra over (city, vouchers used)" time="O(m · k · log(n · k))" space="O(n · k)">

Here k is `vouchers + 1`. Each state is stored at index `city * k + used`, so the distance table is one flat array. Using a voucher never costs anything, but it moves you to a layer with fewer vouchers left, which is what stops the search from using more than you have.

```swift
import DSAKit

public enum TollVoucherJourney {
    public static func cheapestCost(cityCount n: Int, roads: [[Int]], vouchers k: Int) -> Int {
        var graph: [[(to: Int, toll: Int)]] = Array(repeating: [], count: n)
        for road in roads {
            graph[road[0]].append((road[1], road[2]))
            graph[road[1]].append((road[0], road[2]))
        }
        let layers = k + 1
        var cost = Array(repeating: Int.max, count: n * layers)   // state (city, used) at city * layers + used
        cost[0] = 0
        var heap = Heap<(cost: Int, city: Int, used: Int)>(areInIncreasingOrder: { $0.cost < $1.cost })
        heap.insert((0, 0, 0))
        while let (current, city, used) = heap.pop() {
            if current > cost[city * layers + used] { continue }  // stale entry
            if city == n - 1 { return current }
            for (next, toll) in graph[city] {
                let paid = next * layers + used
                if current + toll < cost[paid] {
                    cost[paid] = current + toll
                    heap.insert((current + toll, next, used))
                }
                if used < k && current < cost[paid + 1] {          // spend a voucher on this road
                    cost[paid + 1] = current
                    heap.insert((current, next, used + 1))
                }
            }
        }
        return -1
    }
}
```

The first destination state to be popped is the cheapest over every number of vouchers used, because Dijkstra pops states in order of cost. This "layered graph" trick works for any limited resource: discounts, boosts, or edges you may traverse backwards a few times.

</Approach>
