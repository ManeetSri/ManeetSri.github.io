A fitness app shows your best stretch of `k` days in a row: the `k` consecutive daily scores with the highest average. Given the scores and `k`, return that best average.

`BestAverageWindow.maxAverage(_ values: [Int], k: Int) -> Double`

Aim for a single pass that doesn't re-add every window from scratch.

## Examples

| `values` | `k` | Output |
| --- | --- | --- |
| `[4, -2, 7, 3, -6, 10, 1]` | `2` | `5.5` |
| `[4, -2, 7, 3, -6, 10, 1]` | `4` | `3.5` |
| `[1, 2, 3, 4]` | `4` | `2.5` |
| `[-3, -1, -4]` | `1` | `-1.0` |

In the first example, the pairs sum to 2, 5, 10, −3, 4 and 11. The best is `10 + 1 = 11`, an average of 5.5. In the second, the best four in a row are `7, 3, -6, 10`, which sum to 14.

## Constraints

- `1 ≤ k ≤ values.count ≤ 100,000`
- `-10,000 ≤ values[i] ≤ 10,000`
- Answers within `10⁻⁹` of the exact average are accepted.

<Hints>
<Hint>
All windows have the same length, so the window with the best average is the window with the best **sum**. Work with whole-number sums and divide once at the very end.
</Hint>
<Hint>
Neighbouring windows share all but two values. Moving one step right adds `values[right]` and drops `values[right - k]`.
</Hint>
<Hint>
Sum the first `k` values to get the first window, then loop `right` from `k` to the end, updating the sum with one addition and one subtraction and keeping the best.
</Hint>
</Hints>

## Solutions

<Approach title="Re-sum every window" time="O(n · k)" space="O(1)">

Try every start, add up the `k` values from there, and keep the largest sum. It's correct, but with `n = 100,000` and `k = 50,000` it adds about 2.5 billion numbers.

```swift
public static func maxAverage(_ values: [Int], k: Int) -> Double {
    var best = Int.min
    for start in 0...(values.count - k) {
        var sum = 0
        for index in start..<start + k {
            sum += values[index]
        }
        best = max(best, sum)
    }
    return Double(best) / Double(k)
}
```

</Approach>

<Approach title="Sliding window" time="O(n)" space="O(1)">

Keep the sum of the current window. Sliding one step right adds the value that enters and subtracts the value that leaves, so each step costs O(1) no matter how big `k` is.

```swift
public enum BestAverageWindow {
    public static func maxAverage(_ values: [Int], k: Int) -> Double {
        var windowSum = 0
        for index in 0..<k {
            windowSum += values[index]
        }
        var best = windowSum
        for right in k..<values.count {
            windowSum += values[right] - values[right - k]
            best = max(best, windowSum)
        }
        return Double(best) / Double(k)
    }
}
```

Dividing only at the end keeps every comparison exact. If you averaged each window as a `Double`, rounding could, in rare cases, make two equal windows compare as different.

</Approach>
