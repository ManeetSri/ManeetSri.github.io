Build a table that answers "what's the sum of this range?" for an array of integers, like M20's range-sum table, except that the array keeps changing: any element can be edited between questions, and every answer must include every edit made so far.

`EditableRangeSums.Table`, with `init(_ values: [Int])`, `update(at index: Int, to value: Int)` and `sum(from start: Int, through end: Int) -> Int`

A sum covers `values[start...end]`, inclusive at both ends. `update` is `mutating`, so the table is stored in a `var`.

## Examples

Starting from `[4, -1, 6, 2, 5]`, one call after another on the same table:

| Call | Output | Array afterwards |
| --- | --- | --- |
| `sum(from: 0, through: 4)` | `16` | `[4, -1, 6, 2, 5]` |
| `sum(from: 1, through: 3)` | `7` | unchanged |
| `update(at: 2, to: 0)` | | `[4, -1, 0, 2, 5]` |
| `sum(from: 1, through: 3)` | `1` | unchanged |
| `update(at: 0, to: -10)` | | `[-10, -1, 0, 2, 5]` |
| `sum(from: 0, through: 1)` | `-11` | unchanged |
| `sum(from: 4, through: 4)` | `5` | unchanged |

## Constraints

- `1 ≤ values.count ≤ 100,000`
- `-10⁹ ≤` every value, old or new, `≤ 10⁹`
- Every call has `0 ≤ start ≤ end < values.count` and `0 ≤ index < values.count`.
- Up to 100,000 calls, edits and sums mixed in any order. The tests use 100,000 values with wide ranges, so O(n) for either operation is too slow.

<Hints>
<Hint>
A prefix-sum array makes every sum O(1), but one edit near the front changes almost every prefix value. Adding up the range on each call makes edits O(1) and sums O(n). You need both operations to be cheap.
</Hint>
<Hint>
Store the sums of blocks: the whole array, its two halves, their halves, and so on down to single values. Each value lies in about log₂ n blocks, and any range is made of at most two whole blocks per level.
</Hint>
<Hint>
That's a segment tree. With the values as the leaves of an array `tree[n..<2n]` and `tree[k] = tree[2k] + tree[2k + 1]` for the rest, an edit rewrites a leaf and walks up with `k /= 2`, and a sum climbs from both ends of the range together.
</Hint>
</Hints>

## Solutions

<Approach title="Recursive segment tree" time="O(n) to build, O(log n) per call" space="O(n)">

The version from [Build, query and update](/dsa/learn/seg-build-query-update): nodes numbered from 1 with children `2k` and `2k + 1`, an array of 4n, and three overlap cases in the query.

```swift
public enum EditableRangeSums {
    public struct Table {
        private var tree: [Int]
        private let count: Int

        public init(_ values: [Int]) {
            count = values.count
            tree = Array(repeating: 0, count: 4 * values.count)
            build(values, 1, 0, count - 1)
        }

        public mutating func update(at index: Int, to value: Int) {
            update(1, 0, count - 1, index, value)
        }

        public func sum(from start: Int, through end: Int) -> Int {
            query(1, 0, count - 1, start, end)
        }

        private mutating func build(_ values: [Int], _ node: Int, _ low: Int, _ high: Int) {
            if low == high {
                tree[node] = values[low]
                return
            }
            let mid = (low + high) / 2
            build(values, 2 * node, low, mid)
            build(values, 2 * node + 1, mid + 1, high)
            tree[node] = tree[2 * node] + tree[2 * node + 1]
        }

        private mutating func update(_ node: Int, _ low: Int, _ high: Int, _ index: Int, _ value: Int) {
            if low == high {
                tree[node] = value
                return
            }
            let mid = (low + high) / 2
            if index <= mid {
                update(2 * node, low, mid, index, value)
            } else {
                update(2 * node + 1, mid + 1, high, index, value)
            }
            tree[node] = tree[2 * node] + tree[2 * node + 1]
        }

        private func query(_ node: Int, _ low: Int, _ high: Int, _ left: Int, _ right: Int) -> Int {
            if right < low || high < left { return 0 }
            if left <= low && high <= right { return tree[node] }
            let mid = (low + high) / 2
            return query(2 * node, low, mid, left, right) + query(2 * node + 1, mid + 1, high, left, right)
        }
    }
}
```

</Approach>

<Approach title="Bottom-up segment tree" time="O(n) to build, O(log n) per call" space="O(n)">

The iterative layout: leaves in `tree[n..<2n]`, no recursion, and half the memory. The sum converts the inclusive range to the half-open `start..<end + 1` that the loop expects.

```swift
public enum EditableRangeSums {
    public struct Table {
        private var tree: [Int]
        private let count: Int

        public init(_ values: [Int]) {
            count = values.count
            tree = Array(repeating: 0, count: values.count) + values
            for node in stride(from: count - 1, through: 1, by: -1) {
                tree[node] = tree[2 * node] + tree[2 * node + 1]
            }
        }

        public mutating func update(at index: Int, to value: Int) {
            var node = index + count
            tree[node] = value
            while node > 1 {
                node /= 2
                tree[node] = tree[2 * node] + tree[2 * node + 1]
            }
        }

        public func sum(from start: Int, through end: Int) -> Int {
            var left = start + count
            var right = end + count + 1                 // half-open inside: start..<end + 1
            var total = 0
            while left < right {
                if left % 2 == 1 {                      // a right child: take it alone
                    total += tree[left]
                    left += 1
                }
                if right % 2 == 1 {                     // right - 1 is a left child: take it alone
                    right -= 1
                    total += tree[right]
                }
                left /= 2
                right /= 2
            }
            return total
        }
    }
}
```

A Fenwick tree, which M61 builds, also solves this in O(log n) per call: an edit becomes an addition of the difference between the new value and the old one.

</Approach>
