A hotel safe takes a code of exactly `length` digits, each from 0 to 9, and leading zeros are allowed. The manufacturer forbids two neighbouring digits from being equal, and this model also requires the digits to add up to `digitSum`. Return every allowed code, as strings, in increasing order.

`SafeDialCodes.codes(length: Int, digitSum: Int) -> [String]`

## Examples

| `length` | `digitSum` | Output |
| --- | --- | --- |
| `2` | `1` | `["01", "10"]` |
| `4` | `3` | `["0102", "0120", "0201", "0210", "1020", "2010"]` |
| `2` | `17` | `["89", "98"]` |
| `2` | `18` | `[]` |
| `12` | `6` | `["010101010101", "101010101010"]` |

In the second example, `"0030"` and `"1200"` add up to 3 but have equal neighbours. In the fourth, the only two digits that add up to 18 are 9 and 9. In the last, twelve digits adding up to only 6 can't have two zeros side by side, so zeros and ones must alternate.

## Constraints

- `1 ≤ length ≤ 12` and `0 ≤ digitSum ≤ 108`.
- The tests never expect more than a few thousand codes.
- They do ask for twelve-digit codes with very small sums (such as 5 or 8) and very large ones (such as 101 or 103). The whole decision tree has about 3 × 10¹¹ leaves, so a branch that can no longer succeed must be cut off before you explore it.

</Hint>
<Hint>
Use the template: for each allowed digit, append it (choose), recurse (explore), then remove it (unchoose). Pass the running sum as a parameter, so it needs no undo. Trying digits from 0 up gives the codes in increasing order with no sorting.
</Hint>
<Hint>
Prune with the sum in both directions, before the recursive call. If the sum so far already passes `digitSum`, every bigger digit would too, so `break`. If even 9s in every remaining position couldn't bring the sum up to `digitSum`, skip the digit.
</Hint>

## Solutions

<Approach title="Every code, then filter" time="O(10^length · length)" space="O(length)">

Count from 0 to 10^length − 1, write each number with leading zeros, and keep the codes that pass both rules. For `length` up to 6 that's fine. For 12 it's a trillion codes.

</Approach>

<Approach title="Backtracking with pruning" time="proportional to the branches that can still succeed" space="O(length) plus the output">

The state is the shared `code` array, restored after every call, and the running sum, copied down as a parameter. Both prunes run before the recursive call, so a doomed branch is never entered.

```swift
public enum SafeDialCodes {
    public static func codes(length: Int, digitSum: Int) -> [String] {
        var code: [Int] = []                                  // the state: the path from the root
        var found: [String] = []
        func explore(_ sum: Int) {
            if code.count == length {                         // goal: a complete code
                if sum == digitSum { found.append(code.map(String.init).joined()) }
                return
            }
            let remainingAfter = length - code.count - 1      // digits still to choose after this one
            for digit in 0...9 where digit != code.last {
                let newSum = sum + digit
                if newSum > digitSum { break }                // bigger digits only overshoot further
                if newSum + 9 * remainingAfter < digitSum { continue }   // can't catch up any more
                code.append(digit)                            // choose
                explore(newSum)                               // explore
                code.removeLast()                             // unchoose
            }
        }
        explore(0)
        return found
    }
}
```

`digit != code.last` compares an `Int` with an `Int?`: for the first digit `code.last` is `nil`, so every digit is allowed. The second prune pretends every later digit can be 9, which ignores the neighbour rule, so it's only an upper bound. That's still safe: it never cuts off a branch that could succeed, and it's enough to make the twelve-digit cases instant.

</Approach>
