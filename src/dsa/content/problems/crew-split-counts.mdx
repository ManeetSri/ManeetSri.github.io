A project lead has n distinct tasks and keeps asking the same four kinds of counting question. Build a planner that precomputes tables once and then answers each question instantly, modulo the prime 1,000,000,007.

`CrewSplitCounts.Planner`, with `init(maxTasks: Int)`, `unnamedCrews(tasks:crews:) -> Int`, `namedCrews(tasks:crews:) -> Int`, `anyCrews(tasks:) -> Int` and `roundTables(people:tables:) -> Int`

- `unnamedCrews(tasks: n, crews: k)`: the ways to split n tasks into exactly k crews, every crew doing at least one task, where the crews have no names, so only who works with whom matters.
- `namedCrews(tasks: n, crews: k)`: the same, but the k crews are named (Red, Blue, …), so swapping two crews' tasks gives a different plan.
- `anyCrews(tasks: n)`: the ways to split n tasks into crews when the number of crews is up to you.
- `roundTables(people: n, tables: k)`: the ways to seat n people at exactly k identical round tables with nobody's table empty. Two seatings are the same if every person has the same left-hand neighbour in both.

Every answer is taken modulo 1,000,000,007. Zero tasks split into zero crews in exactly one way (nobody does anything), and in no way into any positive number of crews; n > 0 tasks can't be split into 0 crews, or into more crews than tasks.

## Examples

With `Planner(maxTasks: 10)`:

| Call | Output |
| --- | --- |
| `unnamedCrews(tasks: 4, crews: 2)` | `7` |
| `namedCrews(tasks: 4, crews: 2)` | `14` |
| `anyCrews(tasks: 4)` | `15` |
| `roundTables(people: 4, tables: 2)` | `11` |
| `unnamedCrews(tasks: 7, crews: 3)` | `301` |
| `anyCrews(tasks: 0)` | `1` |
| `unnamedCrews(tasks: 3, crews: 5)` | `0` |
| `roundTables(people: 6, tables: 1)` | `120` |

Four tasks into two unnamed crews: one crew takes a single task (4 ways) or the crews take two each (3 ways), so 7. Naming the crews doubles that to 14. Allowing any number of crews adds the splits into 1, 3 and 4 crews: 1 + 7 + 6 + 1 = 15. Six people at one round table: fix one person's seat, then arrange the other five, 5! = 120.

## Constraints

- `0 ≤ maxTasks ≤ 1,000`.
- Every query has `0 ≤ n ≤ maxTasks` and `0 ≤ k ≤ maxTasks`.
- Building the planner may take O(maxTasks²) time and memory. Every query must be O(1): the tests ask hundreds of thousands of them.

<Hints>
<Hint>
Three of these have names: Stirling numbers of the second kind S(n, k) for unnamed crews, Bell numbers for any number of crews, and unsigned Stirling numbers of the first kind c(n, k) for round tables. Named crews are S(n, k) times the k! ways to hand out the names.
</Hint>
<Hint>
Ask what happens to task n. Alone in a crew: the others form k − 1 crews. Joining one of the k crews the others formed: k choices. So `S(n, k) = k · S(n − 1, k) + S(n − 1, k − 1)`. For tables, person n either sits alone or sits immediately to the left of one of the other n − 1 people: `c(n, k) = (n − 1) · c(n − 1, k) + c(n − 1, k − 1)`. Both start from `S(0, 0) = c(0, 0) = 1`.
</Hint>
<Hint>
Fill both tables row by row in the initialiser, reducing modulo 1,000,000,007 after every multiplication and addition. The Bell number for n is the sum of row n of the S table, and k! comes from a factorial table. Store all of it; each query is then a lookup.
</Hint>
</Hints>

## Solutions

<Approach title="Two Stirling tables, built once" time="O(N²) to build, O(1) per query" space="O(N²)">

```swift
public enum CrewSplitCounts {
    public struct Planner {
        private static let modulus = 1_000_000_007
        private var second: [[Int]]                 // S(n, k), Stirling numbers of the second kind
        private var first: [[Int]]                  // c(n, k), unsigned, of the first kind
        private var bell: [Int]
        private var factorial: [Int]

        public init(maxTasks: Int) {
            let p = Planner.modulus, size = maxTasks + 1
            second = Array(repeating: Array(repeating: 0, count: size), count: size)
            first = second
            second[0][0] = 1
            first[0][0] = 1
            for n in stride(from: 1, through: maxTasks, by: 1) {
                for k in 1...n {
                    second[n][k] = (k * second[n - 1][k] + second[n - 1][k - 1]) % p
                    first[n][k] = ((n - 1) * first[n - 1][k] + first[n - 1][k - 1]) % p
                }
            }
            bell = second.map { row in row.reduce(0) { ($0 + $1) % p } }
            factorial = [1]
            for k in stride(from: 1, through: maxTasks, by: 1) {
                factorial.append(factorial[k - 1] * k % p)
            }
        }

        public func unnamedCrews(tasks n: Int, crews k: Int) -> Int { second[n][k] }
        public func namedCrews(tasks n: Int, crews k: Int) -> Int { second[n][k] * factorial[k] % Planner.modulus }
        public func anyCrews(tasks n: Int) -> Int { bell[n] }
        public func roundTables(people n: Int, tables k: Int) -> Int { first[n][k] }
    }
}
```

Entries with k > n are never written, so they stay 0, and so do the entries with k = 0 below row 0. Every product is of two numbers below about 10⁹, which fits easily in a 64-bit `Int` before it's reduced.

</Approach>

<Approach title="Inclusion–exclusion for named crews" time="O(k log n) per query" space="O(1)">

Named crews are the onto functions from tasks to crews, which the next lesson counts directly: Σ (−1)^j · C(k, j) · (k − j)^n for j from 0 to k. It's a good check on the table, but at O(k log n) per query it's too slow for hundreds of thousands of questions.

</Approach>
