A database engine stores an index as a B-tree whose nodes hold at most `maxKeys` keys. Insert `keys` in order into an empty tree, splitting nodes exactly as described below, and return the finished tree level by level.

`BTreeLevelsBuilder.levels(afterInserting keys: [Int], maxKeys: Int) -> [[[Int]]]`

**The rules**, as in [B-trees and B+ trees](/dsa/learn/bal-b-trees):

- A new key goes into the **leaf** where a search for it ends, in sorted position. A key that's already in the tree is ignored.
- When a node ends up with `maxKeys + 1` keys, it **splits**: the key at index `count / 2` moves up into the parent, the keys before it stay in this node, and the keys after it move to a new node just to its right. An internal node's children are divided the same way: the first `count / 2 + 1` stay, the rest move.
- The parent now has one more key and may split in turn. If the root splits, the middle key becomes a new root with two children.

Return one array per level, top first. Each level lists its nodes from left to right, and each node is its keys in increasing order. With no keys, there are no levels.

## Examples

| `keys` | `maxKeys` | Output |
| --- | --- | --- |
| `[1, 2, 3, 4]` | `3` | `[[[3]], [[1, 2], [4]]]` |
| `[1, 2, …, 13]` | `3` | `[[[9]], [[3, 6], [12]], [[1, 2], [4, 5], [7, 8], [10, 11], [13]]]` |
| `[10, 20, 30]` | `2` | `[[[20]], [[10], [30]]]` |
| `[5, 1, 9, 5]` | `4` | `[[[1, 5, 9]]]` (the second 5 is ignored) |
| `[]` | `3` | `[]` |

In the second example, inserting 13 overflows the leaf `[10 11 12 13]`, which sends 12 up into the root `[3 6 9 12]`. That overflows too, so 9 becomes a new root: one insert, two splits.

## Constraints

- `0 ≤ keys.count ≤ 100,000`, and `2 ≤ maxKeys ≤ 100`.
- Keys can be any `Int`.

<Hints>
<Hint>
Use a small node class holding a sorted `keys` array and a `children` array (empty for a leaf). To find where a key goes in a node, find the first key that's ≥ it: if it's equal, the key is a duplicate; otherwise its index is also the child to follow.
</Hint>
<Hint>
Write the insert recursively, so the split can happen on the way back up. The recursive call inserts into a subtree and returns either nothing, or the `(median, newRightNode)` pair from a split. The caller inserts the median into its own keys at the child's position, and the new node into its children just after it, then checks whether it has overflowed itself.
</Hint>
<Hint>
At the top, if the root returned a split, make a new root holding just the median, with the old root and the new node as its children. Finally, read the levels with a breadth-first walk: the next level is every node's children, in order.
</Hint>
</Hints>

## Solutions

<Approach title="Recursive insert, splitting on the way up" time="O(n × maxKeys × log n)" space="O(n)">

Each insert walks one root-to-leaf path, O(log n) nodes, and inserting into a node's sorted array costs O(maxKeys). A split moves half a node into a new one, and splits are rare: most inserts just add a key to a leaf. The tree grows only when the root splits, which is why every leaf is always at the same depth.

```swift
public enum BTreeLevelsBuilder {
    private final class Node {
        var keys: [Int] = []
        var children: [Node] = []                        // empty for a leaf
    }

    public static func levels(afterInserting keys: [Int], maxKeys: Int) -> [[[Int]]] {
        guard !keys.isEmpty else { return [] }
        var root = Node()
        for key in keys {
            if let (median, right) = insert(key, into: root, maxKeys: maxKeys) {
                let newRoot = Node()                     // the root split: grow at the top
                newRoot.keys = [median]
                newRoot.children = [root, right]
                root = newRoot
            }
        }
        var result: [[[Int]]] = []
        var level = [root]
        while !level.isEmpty {
            result.append(level.map(\.keys))
            level = level.flatMap(\.children)
        }
        return result
    }

    /// Inserts key below node; if node overflows, splits it and returns the median and the new right half.
    private static func insert(_ key: Int, into node: Node, maxKeys: Int) -> (Int, Node)? {
        var low = 0                                      // the first key ≥ key, by binary search
        var high = node.keys.count
        while low < high {
            let mid = (low + high) / 2
            if node.keys[mid] < key { low = mid + 1 } else { high = mid }
        }
        if low < node.keys.count && node.keys[low] == key { return nil }      // already there
        if node.children.isEmpty {
            node.keys.insert(key, at: low)
        } else if let (median, right) = insert(key, into: node.children[low], maxKeys: maxKeys) {
            node.keys.insert(median, at: low)            // take in the child's median…
            node.children.insert(right, at: low + 1)     // …and its new right half
        }
        guard node.keys.count > maxKeys else { return nil }
        let mid = node.keys.count / 2
        let median = node.keys[mid]
        let right = Node()
        right.keys = Array(node.keys[(mid + 1)...])
        node.keys.removeSubrange(mid...)
        if !node.children.isEmpty {
            right.children = Array(node.children[(mid + 1)...])
            node.children.removeSubrange((mid + 1)...)
        }
        return (median, right)
    }
}
```

The recursion is only as deep as the tree, which with `maxKeys` of 2 and 100,000 keys is at most 17 levels. Real databases pick `maxKeys` in the hundreds so that one node fills one disk page, and then even a billion keys fit in four levels.

</Approach>
