A print shop has a queue of jobs, each a number of pages. The printer runs at a speed you choose, a whole number of pages per minute, and works on one job at a time. Each minute, it prints up to that many pages of the current job. If the job finishes partway through a minute, the printer sits idle until the minute ends, and starts the next job on the next minute. Return the slowest speed that finishes every job within `minutes` minutes.

`MinimumPrintSpeed.slowestSpeed(jobs: [Int], minutes: Int) -> Int`

## Examples

| `jobs` | `minutes` | Output |
| --- | --- | --- |
| `[10, 3, 7]` | `5` | `5` |
| `[10, 3, 7]` | `3` | `10` |
| `[30, 11, 23, 4, 20]` | `6` | `23` |
| `[1, 1, 1, 1]` | `4` | `1` |
| `[1000000000]` | `2` | `500000000` |

In the first example, speed 5 takes 2 + 1 + 2 = 5 minutes. Speed 4 takes 3 + 1 + 2 = 6, one minute too many. In the second, every job must finish in a single minute, so the speed must match the largest job.

## Constraints

- `1 ≤ jobs.count ≤ 100,000`
- `1 ≤ jobs[i] ≤ 10⁹`
- `jobs.count ≤ minutes ≤ 10⁹`, so some speed always works.

<Hints>
<Hint>
At speed s, a job of p pages takes ⌈p / s⌉ minutes. Compute it with whole numbers as `(p + s - 1) / s`. Write a function that adds this up over every job, and check it by hand on the first example.
</Hint>
<Hint>
A faster speed never takes more minutes, so "finishes in time" is false for slow speeds and true from some speed on. You want the first speed where it's true: binary search on the speed.
</Hint>
<Hint>
The slowest possible speed is 1. At a speed equal to the largest job, every job takes exactly one minute, which always fits, because `minutes` is at least the number of jobs. Search between those two, and stop adding minutes as soon as the total passes the limit.
</Hint>
</Hints>

## Solutions

<Approach title="Try every speed from 1 up" time="O(n · M)" space="O(1)">

Check speeds 1, 2, 3, … in turn and return the first that finishes in time. M is the largest job, the fastest speed that could ever be needed. It's correct and a good checker for small inputs, but with jobs of a billion pages and plenty of time it can try hundreds of millions of speeds, each costing a pass over the jobs.

```swift
public static func slowestSpeed(jobs: [Int], minutes: Int) -> Int {
    var speed = 1
    while jobs.reduce(0, { $0 + ($1 + speed - 1) / speed }) > minutes {
        speed += 1
    }
    return speed
}
```

</Approach>

<Approach title="Binary search on the speed" time="O(n log M)" space="O(1)">

"Finishes within the limit" is monotonic in the speed, so search the speeds 1 to `jobs.max()` for the first that works. The largest job is a speed that's known to work, so it can start as `high`: if nothing slower works, the loop stops there. Each check is one pass over the jobs, and it returns early once the total is already too big, which also rules out any chance of overflow.

```swift
public enum MinimumPrintSpeed {
    public static func slowestSpeed(jobs: [Int], minutes: Int) -> Int {
        var low = 1
        var high = jobs.max()!                       // always works, because minutes ≥ jobs.count
        while low < high {
            let mid = low + (high - low) / 2
            if finishes(jobs, speed: mid, within: minutes) {
                high = mid                           // mid works: the answer is mid or slower
            } else {
                low = mid + 1                        // mid is too slow
            }
        }
        return low
    }

    /// True if every job is printed within `limit` minutes at `speed` pages per minute.
    private static func finishes(_ jobs: [Int], speed: Int, within limit: Int) -> Bool {
        var total = 0
        for pages in jobs {
            total += (pages + speed - 1) / speed     // ⌈pages / speed⌉ without Double
            if total > limit { return false }        // stop early: already too slow
        }
        return true
    }
}
```

The search makes about log₂(10⁹) ≈ 30 checks, however large the jobs are.

</Approach>
