Return a tree's values level by level: one array per level, from the root down, each read left to right. Then do the same from the bottom up, and for an N-ary tree.

`LevelOrderGroups.levels(_ root: TreeNode?) -> [[Int]]`, `LevelOrderGroups.levelsBottomUp(_ root: TreeNode?) -> [[Int]]` and `LevelOrderGroups.naryLevels(_ root: Node?) -> [[Int]]`

`levelsBottomUp` lists the deepest level first, but each level still reads left to right. The N-ary node type is nested in the problem's enum: `Node(value, children: [Node])`, with `value` and `children` properties. The empty tree has no levels: `[]`.

## Examples

| Tree | `levels` | `levelsBottomUp` |
| --- | --- | --- |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `[[1], [2, 3], [4, 5, 6], [7]]` | `[[7], [4, 5, 6], [2, 3], [1]]` |
| `[3, 9, 20, nil, nil, 15, 7]` | `[[3], [9, 20], [15, 7]]` | `[[15, 7], [9, 20], [3]]` |
| `[1, nil, 2, nil, 3]` | `[[1], [2], [3]]` | `[[3], [2], [1]]` |
| `[]` | `[]` | `[]` |

For an N-ary tree where 1 has children 2, 3 and 4, 2 has children 5 and 6, and 4 has a child 7, `naryLevels` gives `[[1], [2, 3, 4], [5, 6, 7]]`.

## Constraints

- `0 ≤` number of nodes `≤ 100,001`
- Trees can be 100,000 levels deep, so walk them with a loop.

<Hints>
<Hint>
Breadth-first search visits nodes in exactly this order. The question is only how to tell where one level ends and the next begins.
</Hint>
<Hint>
Keep the whole current level in an array. Build the next level from its children, left child before right, node by node. Record the current level's values, then move on to the next level, until a level is empty.
</Hint>
<Hint>
Bottom up is top down, reversed: `Array(levels(root).reversed())`. For the N-ary version, the next level is every child of every node on this level, in order: `level.flatMap(\.children)`.
</Hint>
</Hints>

## Solutions

<Approach title="One level at a time" time="O(n)" space="O(w)">

`level` holds every node on the current level, left to right; their children, in order, are the next level. Each node is handled once, and at most two levels are held at any moment, so the space is O(w) for the widest level w.

```swift
public static func levels(_ root: TreeNode?) -> [[Int]] {
    var result: [[Int]] = []
    var level = [root].compactMap { $0 }
    while !level.isEmpty {
        result.append(level.map(\.value))
        var next: [TreeNode] = []
        for node in level {
            if let left = node.left { next.append(left) }
            if let right = node.right { next.append(right) }
        }
        level = next
    }
    return result
}

public static func levelsBottomUp(_ root: TreeNode?) -> [[Int]] {
    Array(levels(root).reversed())
}

public static func naryLevels(_ root: Node?) -> [[Int]] {
    var result: [[Int]] = []
    var level = [root].compactMap { $0 }
    while !level.isEmpty {
        result.append(level.map(\.value))
        level = level.flatMap(\.children)
    }
    return result
}
```

`[root].compactMap { $0 }` turns an optional root into an array of zero or one nodes, so the empty tree needs no special case.

</Approach>

<Approach title="One queue, counting each level" time="O(n)" space="O(w)">

The classic single-queue version. At the start of each round, the queue holds exactly one level, so its size says how many nodes to take before the level is complete. A head index keeps taking from the front O(1).

```swift
public static func levels(_ root: TreeNode?) -> [[Int]] {
    guard let root else { return [] }
    var result: [[Int]] = []
    var queue = [root]
    var head = 0
    while head < queue.count {
        let levelEnd = queue.count                // everything queued so far is this level
        var values: [Int] = []
        while head < levelEnd {
            let node = queue[head]
            head += 1
            values.append(node.value)
            if let left = node.left { queue.append(left) }
            if let right = node.right { queue.append(right) }
        }
        result.append(values)
    }
    return result
}
```

This keeps every node in `queue` until the end, so it uses O(n) memory; the two-array version lets each finished level go.

</Approach>
