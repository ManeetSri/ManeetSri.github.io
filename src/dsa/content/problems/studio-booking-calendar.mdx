A recording studio takes bookings one at a time. Each booking is a half-open time range `start..<end`: it includes `start` but not `end`, so a session ending at 10 and another starting at 10 don't clash. Accept a booking only if it overlaps no booking accepted so far, and say whether you did.

`StudioBookingCalendar.Schedule`, with `init()`, `book(start:end:) -> Bool` and `count: Int`

`book` returns `true` and records the booking, or returns `false` and changes nothing. `count` is the number of bookings accepted. Aim for O(log n) per booking. In the examples, `book(10, 20)` is short for `book(start: 10, end: 20)`.

## Examples

| Calls on a new schedule | Results |
| --- | --- |
| `book(10, 20)`, `book(15, 25)`, `book(20, 30)` | `true`, `false`, `true` |
| …then `book(5, 10)`, `book(8, 12)`, `book(30, 31)` | `true`, `false`, `true` |
| `book(0, 10)`, `book(20, 30)`, `book(10, 20)` | `true`, `true`, `true` |
| `book(10, 20)`, `book(12, 18)` | `true`, `false` |
| `book(10, 20)`, `book(5, 25)` | `true`, `false` |

In the second row, `8..<12` overlaps both `5..<10` and `10..<20`. In the third, `10..<20` fits the gap exactly. In the last two, the second booking sits inside the first, or covers it completely: both clash.

## Constraints

- `start < end`, and times can be any `Int`, including negatives.
- Up to 150,000 calls to `book`.

<Hints>
<Hint>
Two half-open ranges `a..<b` and `c..<d` overlap exactly when `a < d && c < b`. Checking the new booking against every accepted one works, but it's O(n) per call: about 10¹⁰ comparisons over 150,000 calls.
</Hint>
<Hint>
The accepted bookings never overlap, so sorted by start time they're also sorted by end time. A new booking can only clash with its two neighbours in that order: the last booking starting at or before its start, and the first booking starting at or after it.
</Hint>
<Hint>
Those neighbours are the floor and the ceiling of the new start, in a sorted map from start to end. The earlier one clashes if it ends after the new start; the later one clashes if it starts before the new end. DSAKit's `SortedMap` has `floor(_:)` and `ceiling(_:)`, and the stub already imports DSAKit.
</Hint>
</Hints>

## Solutions

<Approach title="Check every booking" time="O(n) per call" space="O(n)">

Keep an array of accepted bookings and test the new one against each. It's the clearest version, and a perfect checker for a faster one on small inputs, but 150,000 calls make it far too slow.

```swift
public struct Schedule {
    private var bookings: [(start: Int, end: Int)] = []

    public init() {}

    public mutating func book(start: Int, end: Int) -> Bool {
        if bookings.contains(where: { $0.start < end && start < $0.end }) {
            return false
        }
        bookings.append((start, end))
        return true
    }

    public var count: Int {
        bookings.count
    }
}
```

</Approach>

<Approach title="A sorted array and binary search" time="O(log n) to check, O(n) to insert" space="O(n)">

Keep the bookings sorted by start. Binary search for the first booking starting at or after the new start (the lower bound from [Lower bound, upper bound, first and last occurrence](/dsa/learn/bs-bounds)); the booking immediately before that position is the other neighbour. Checking is O(log n), but `insert(_:at:)` shifts everything after the new position. The shifting is a fast memory copy, so this often passes in practice, but it's O(n²) in the worst case overall.

```swift
public struct Schedule {
    private var starts: [Int] = []
    private var ends: [Int] = []

    public init() {}

    public mutating func book(start: Int, end: Int) -> Bool {
        var low = 0
        var high = starts.count
        while low < high {                            // first index whose start is ≥ start
            let mid = low + (high - low) / 2
            if starts[mid] < start { low = mid + 1 } else { high = mid }
        }
        if low > 0 && ends[low - 1] > start { return false }               // earlier one runs on
        if low < starts.count && starts[low] < end { return false }        // later one starts too soon
        starts.insert(start, at: low)
        ends.insert(end, at: low)
        return true
    }

    public var count: Int {
        starts.count
    }
}
```

</Approach>

<Approach title="Floor and ceiling in a sorted map" time="O(log n) per call" space="O(n)">

A `SortedMap` from start to end finds both neighbours in O(log n) and inserts in O(log n), with no shifting. This is exactly the situation balanced trees exist for: order queries mixed with inserts.

```swift
import DSAKit

public enum StudioBookingCalendar {
    public struct Schedule {
        private var endsByStart = SortedMap<Int, Int>()

        public init() {}

        public mutating func book(start: Int, end: Int) -> Bool {
            if let before = endsByStart.floor(start), before.value > start {
                return false                                 // the earlier booking runs past our start
            }
            if let after = endsByStart.ceiling(start), after.key < end {
                return false                                 // the later booking starts before our end
            }
            endsByStart[start] = end
            return true
        }

        public var count: Int {
            endsByStart.count
        }
    }
}
```

`floor(start)` includes a booking that starts at exactly the same time, which always clashes, since bookings are never empty. `ceiling(start)` would find that same booking too, so either check catches it.

</Approach>
