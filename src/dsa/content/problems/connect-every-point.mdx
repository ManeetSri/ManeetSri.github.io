You're given points on a grid, each `[x, y]`. A wire between two points costs their **Manhattan distance**, `|x1 - x2| + |y1 - y2|`. Wires can run between any two points. Return the smallest total cost of wires that connects every point to every other, directly or through other points.

`PointConnector.minimumCost(_ points: [[Int]]) -> Int`

## Examples

| `points` | Returns | Why |
| --- | --- | --- |
| `[[0, 0], [1, 1], [3, 0]]` | 5 | wires of 2 and 3 |
| `[[0, 0], [4, 0], [0, 3], [4, 3]]` | 10 | 3 + 3 + 4 |
| `[[-2, 1], [1, 1], [1, -3], [6, 0]]` | 13 | 3 + 4 + 6 |
| `[[5, 5], [5, 6], [5, 7], [5, 8]]` | 3 | a straight line |
| `[[7, -3]]` | 0 | nothing to connect |

## Constraints

- `1 ≤ points.count ≤ 2,000`, and all points are different.
- `-10⁹ ≤ x, y ≤ 10⁹`, so a single distance fits comfortably in an `Int`.
- The tests include 2,000 shuffled points on a line and a 40 × 40 grid of points. With 2,000 points there are about 2 million possible wires.

<Hints>
<Hint>
Every pair of points could be wired, so this is a minimum spanning tree on a complete graph. How many edges does that graph have?
</Hint>
<Hint>
About n² / 2. Building and sorting them all for Kruskal works but costs O(n² log n) time and O(n²) memory. Which MST algorithm is O(n²) on a dense graph?
</Hint>
<Hint>
The array version of Prim: keep `cheapest[v]`, the cheapest known wire from the tree to each outside point. Each round, add the outside point with the smallest value, then update the others using their distance to it, computed on the spot.
</Hint>
</Hints>

## Solutions

<Approach title="Kruskal over every pair" time="O(n² log n)" space="O(n²)">

Make an edge for every pair of points, sort them by distance, and run Kruskal with union-find. It's correct and short, and the tests use it as a model on small inputs, but 2,000 points mean about 2 million edges to store and sort.

</Approach>

<Approach title="Prim with an array" time="O(n²)" space="O(n)">

No edge list at all: each distance is computed when it's needed. n rounds, each scanning the n points twice.

```swift
public enum PointConnector {
    public static func minimumCost(_ points: [[Int]]) -> Int {
        let n = points.count
        guard n > 1 else { return 0 }
        var inTree = Array(repeating: false, count: n)
        var cheapest = Array(repeating: Int.max, count: n)
        cheapest[0] = 0
        var total = 0
        for _ in 0..<n {
            var next = -1
            for v in 0..<n where !inTree[v] && (next == -1 || cheapest[v] < cheapest[next]) {
                next = v
            }
            inTree[next] = true
            total += cheapest[next]
            for v in 0..<n where !inTree[v] {
                let distance = abs(points[v][0] - points[next][0]) + abs(points[v][1] - points[next][1])
                if distance < cheapest[v] {
                    cheapest[v] = distance
                }
            }
        }
        return total
    }
}
```

On a complete graph, O(n²) is optimal: any algorithm has to consider every pair at least once. A heap-based Prim would be O(n² log n) here.

</Approach>
