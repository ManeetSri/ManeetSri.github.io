Traders, numbered `0` to `traderCount - 1`, offer one-way trades. A trade `[from, to, cost]` passes goods from `from` to `to` at that cost; a negative cost means the trade makes money. Find a **profit loop**: distinct traders `[t0, t1, …, tk]` with trades `t0 → t1 → … → tk → t0` whose costs add up to less than zero. Return any such loop, starting anywhere along it, or `[]` if none exists.

`ProfitLoopFinder.findLoop(traderCount: Int, trades: [[Int]]) -> [Int]`

## Examples

| `traderCount` | `trades` | Output (one possibility) |
| --- | --- | --- |
| `3` | `[[0, 1, 4], [1, 2, -1], [2, 0, -4]]` | `[0, 1, 2]` |
| `3` | `[[0, 1, 4], [1, 2, -1], [2, 0, -2]]` | `[]` |
| `5` | `[[0, 1, 2], [1, 2, 2], [3, 4, -3], [4, 3, 1]]` | `[3, 4]` |
| `1` | `[[0, 0, -1]]` | `[0]` |
| `2` | `[[0, 1, 3], [1, 0, -3]]` | `[]` |

The first loop totals 4 − 1 − 4 = −1. The second totals 1, so it loses money. In the third, the loop 3 → 4 → 3 can't be reached from trader 0, and it still counts. A trader can trade with themselves, as in the fourth. In the last, the loop totals exactly 0, which isn't a profit.

`[1, 2, 0]` or `[2, 0, 1]` would be just as correct for the first example. The tests check that your loop is real: distinct traders, a trade for each step including the last one back to the start, and a negative total.

## Constraints

- `1 ≤ traderCount ≤ 2,000` and `0 ≤ trades.count ≤ 10,000`
- `0 ≤ from, to < traderCount`, and `-2,000,000 ≤ cost ≤ 2,000,000`
- There may be several trades between the same two traders. If you use one of them, any of them will do as long as the loop is negative using the cheapest.
- The tests hide a 40-trader loop among 1,500 traders and 8,000 trades, many of which are individually profitable without forming a profit loop.

<Hints>
<Hint>
A profit loop is a negative cycle. Bellman–Ford detects one with an extra round. But it only finds cycles reachable from its source, and the loop could be anywhere.
</Hint>
<Hint>
Start every trader at distance 0, as if a new trader had a free trade to each of them. Record `parent[v] = u` whenever a trade u → v improves v. If round `traderCount` still improves some trader v, a profit loop exists.
</Hint>
<Hint>
v might be *after* the loop rather than on it. Walking parents back `traderCount` times from v is guaranteed to land on the loop. From there, keep following parents until you return to where you started: that's the loop, in reverse.
</Hint>
</Hints>

## Solutions

<Approach title="Floyd–Warshall" time="O(n³)" space="O(n²)">

After Floyd–Warshall, a trader with `dist[i][i] < 0` is on a profit loop, and a `next` matrix rebuilds the loop. It's fine for a few hundred traders, but 2,000³ is eight billion steps.

</Approach>

<Approach title="Bellman–Ford from everyone, then walk the parents" time="O(n · m)" space="O(n)">

Run n rounds; if one is quiet, there's no loop. If round n improves a trader, step back n parents to be sure you're on the loop, then collect it.

```swift
public enum ProfitLoopFinder {
    public static func findLoop(traderCount n: Int, trades: [[Int]]) -> [Int] {
        var balance = Array(repeating: 0, count: n)
        var parent = Array(repeating: -1, count: n)
        var improved = -1
        for _ in 0..<n {                                // n − 1 rounds, plus one to detect a loop
            improved = -1
            for trade in trades where balance[trade[0]] + trade[2] < balance[trade[1]] {
                balance[trade[1]] = balance[trade[0]] + trade[2]
                parent[trade[1]] = trade[0]
                improved = trade[1]
            }
            if improved == -1 { return [] }             // a quiet round: no loop can pay
        }
        var trader = improved
        for _ in 0..<n {
            trader = parent[trader]                     // step back until we're inside the loop
        }
        var loop = [trader]
        var current = parent[trader]
        while current != trader {
            loop.append(current)
            current = parent[current]
        }
        return loop.reversed()                          // parents point backwards along the loop
    }
}
```

Why n steps back is enough: the parent pointers lead backwards along improving trades, and any chain of n parents must repeat a trader, so it has entered a cycle of parents. A cycle in the parent pointers is always a negative cycle. Starting everyone at 0 replaces the imaginary extra trader, which is why n rounds (not n + 1) are enough.

</Approach>

<Approach title="SPFA with edge counts" time="O(n · m) worst case" space="O(n + m)">

Put every trader in the queue at distance 0. Track how many trades the best path to each trader uses; when one reaches n, that trader's parent chain contains a loop. Walk back and collect it exactly as above. On typical inputs this examines far fewer trades than Bellman–Ford.

</Approach>
