Given an array of values, decide whether two of them are close **both** in position and in size: at different indexes i and j with `abs(i - j) <= k` and `abs(values[i] - values[j]) <= t`.

`NearbyCloseValues.exists(in values: [Int], maxIndexGap k: Int, maxValueGap t: Int) -> Bool`

Aim for better than O(n · k): the tests use windows as wide as the whole array.

## Examples

| `values` | `k` | `t` | Output |
| --- | --- | --- | --- |
| `[8, 3, 14, 6]` | `3` | `2` | `true` |
| `[8, 3, 14, 6]` | `2` | `2` | `false` |
| `[1, 9, 17, 25, 2]` | `4` | `1` | `true` |
| `[1, 9, 17, 25, 2]` | `3` | `1` | `false` |
| `[5, 5]` | `1` | `0` | `true` |
| `[4, -4, 4]` | `1` | `7` | `false` |

In the first example, 8 and 6 differ by 2 and are 3 places apart. With `k = 2` they're too far apart, and no other pair is within 2 of each other. In the last example, the two 4s are equal but 2 places apart, and the neighbours differ by 8.

## Constraints

- `0 ≤ values.count ≤ 60,000`
- `-1,000,000,000 ≤ values[i] ≤ 1,000,000,000`
- `0 ≤ k ≤ 60,000` and `0 ≤ t ≤ 2,000,000,000`

<Hints>
<Hint>
Scan from left to right. When you reach index i, the only partners that matter are the up to k values before it: a window that slides along the array. The brute force checks every value in the window, O(k) each time. What would you need to check only the window values nearest to `values[i]` in size?
</Hint>
<Hint>
Keep the window's values in a sorted set. Among them, the best candidate is the smallest value that's at least `values[i] - t`: its ceiling. If that exists and is at most `values[i] + t`, you've found a pair; if not, nothing in the window is within t. Then insert `values[i]`, and remove the value that has fallen k places behind.
</Hint>
<Hint>
Repeated values are fine without a multiset: if a value repeats inside the window, the ceiling finds the earlier copy (a gap of 0 is within any t) and you return before inserting it twice. For an O(n) alternative, put each value into a bucket of width t + 1. Two values in one bucket are always within t, so each bucket holds at most one window value, and only the two neighbouring buckets need a closer look.
</Hint>
</Hints>

## Solutions

<Approach title="Check every pair in the window" time="O(n · k)" space="O(1)">

For each index, compare with the next k values. Correct and simple, and with k as wide as the array it's quadratic: about 1.8 billion comparisons at the largest size.

```swift
public static func exists(in values: [Int], maxIndexGap k: Int, maxValueGap t: Int) -> Bool {
    for i in values.indices {
        for j in (i + 1)..<min(values.count, i + k + 1) where abs(values[i] - values[j]) <= t {
            return true
        }
    }
    return false
}
```

</Approach>

<Approach title="A sliding window in a sorted set" time="O(n log k)" space="O(k)">

The window holds the last k values in a `SortedSet`. For each new value x, one `ceiling` query finds the window value nearest to x from above x − t, and a single comparison says whether it's close enough. Every step is one query, one insert and one removal, each O(log k).

```swift
import DSAKit

public enum NearbyCloseValues {
    public static func exists(in values: [Int], maxIndexGap k: Int, maxValueGap t: Int) -> Bool {
        guard k > 0 else { return false }
        var window = SortedSet<Int>()
        for (i, x) in values.enumerated() {
            if let nearest = window.ceiling(x - t), nearest <= x + t {
                return true
            }
            window.insert(x)
            if i >= k {
                window.remove(values[i - k])                 // keep only the last k values
            }
        }
        return false
    }
}
```

Why is the ceiling of x − t enough? Any window value within t of x lies in `(x - t)...(x + t)`. The ceiling is the smallest window value at or above the bottom of that range, so if anything is in the range, the ceiling is, and if the ceiling is above x + t, the range is empty. The constraints keep `x - t` and `x + t` well within `Int`'s range.

</Approach>

<Approach title="Buckets of width t + 1" time="O(n)" space="O(k)">

Cut the number line into buckets of width t + 1: bucket b holds the values from b(t + 1) to b(t + 1) + t. Any two values in the same bucket are within t, so if a new value's bucket is already occupied, you're done. Otherwise each bucket holds at most one window value, and a close partner can only be in the bucket immediately below or above, so check those two. A `Dictionary` from bucket number to value makes every step O(1) on average.

```swift
public static func exists(in values: [Int], maxIndexGap k: Int, maxValueGap t: Int) -> Bool {
    guard k > 0 else { return false }
    let width = t + 1
    // Floor division, so -1 lands in bucket -1 rather than bucket 0
    func bucket(_ x: Int) -> Int {
        x >= 0 ? x / width : (x + 1) / width - 1
    }
    var window: [Int: Int] = [:]                  // bucket → the one window value in it
    for (i, x) in values.enumerated() {
        let b = bucket(x)
        if window[b] != nil { return true }       // same bucket: within t
        if let below = window[b - 1], x - below <= t { return true }
        if let above = window[b + 1], above - x <= t { return true }
        window[b] = x
        if i >= k {
            window[bucket(values[i - k])] = nil   // the value k places back leaves the window
        }
    }
    return false
}
```

Swift's `/` rounds towards zero, so −1 / 5 is 0, which would put −1 in the same bucket as 4. The `bucket` function rounds down instead, as in [Floor and ceiling division, and overflow](/dsa/learn/math-floor-ceil-overflow).

</Approach>
