Bubble sort makes passes over an array. Each pass walks from left to right and swaps every pair of neighbours whose left value is strictly bigger than the right one. Passes repeat until one makes no swap. Given an array, return how many passes **make at least one swap**, without running bubble sort: the arrays are far too long for that.

`BubblePassCount.busyPasses(_ numbers: [Int]) -> Int`

A sorted array needs no busy passes, so the answer for it is 0.

## Examples

| `numbers` | Returns |
| --- | --- |
| `[5, 1, 4, 2, 8, 3]` | `3` |
| `[2, 3, 4, 5, 6, 1]` | `5` |
| `[6, 1, 2, 3, 4, 5]` | `1` |
| `[3, 3, 1]` | `2` |
| `[1, 2, 3]` | `0` |
| `[]` | `0` |

In the first example, bubble sort's passes give `[1, 4, 2, 5, 3, 8]`, then `[1, 2, 4, 3, 5, 8]`, then `[1, 2, 3, 4, 5, 8]`, and a fourth pass finds nothing to swap. In the second, the 1 creeps one place left per pass; in the third, the 6 is carried to the end in a single pass.

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- Values can be any `Int`, and may repeat.
- Simulating bubble sort is O(n²) passes and comparisons: far too slow for the large tests. Aim for O(n log n).

<Hints>
<Hint>
In one pass, how far can a value move **left**? Think about the one big value being carried right past it.
</Hint>
<Hint>
Every value that has a bigger value somewhere to its left moves exactly one place left per pass. So the number of busy passes is the furthest distance any value has to travel left to reach its place in the sorted array.
</Hint>
<Hint>
Work out where each value ends up by sorting its index. Equal values never swap, so they keep their order: sort the indexes by `(value, index)`. The answer is the largest `originalIndex - sortedIndex`, or 0.
</Hint>
</Hints>

## Solutions

<Approach title="Simulate it" time="O(n²)" space="O(n)">

Run bubble sort on a copy and count the passes that swap. It's correct, and a good way to check your fast solution on small arrays, but a reversed array of 100,000 values needs almost 5 billion comparisons.

```swift
public static func busyPasses(_ numbers: [Int]) -> Int {
    var items = numbers
    var busy = 0
    while true {
        var swapped = false
        for j in items.indices.dropLast() where items[j] > items[j + 1] {
            items.swapAt(j, j + 1)
            swapped = true
        }
        if !swapped { return busy }
        busy += 1
    }
}
```

</Approach>

<Approach title="Furthest distance left" time="O(n log n)" space="O(n)">

Take a value x with at least one bigger value to its left. During a pass, the value being carried right when it reaches x is the largest of everything to x's left, which is bigger than x, so the two swap and x moves exactly one place left. Values with nothing bigger to their left never move left. So a value that must end up d places further left needs exactly d passes, and the busiest passes are set by the value with the furthest to go. (Values only move right by being carried, which never costs extra passes.)

The sorted position of each value comes from sorting the indexes. Bubble sort never swaps equal values, so equal values keep their order, and the sort must break ties by index:

```swift
public enum BubblePassCount {
    public static func busyPasses(_ numbers: [Int]) -> Int {
        // order[p] is the original index of the value that ends up at position p
        let order = numbers.indices.sorted { (numbers[$0], $0) < (numbers[$1], $1) }
        var passes = 0
        for (sortedIndex, originalIndex) in order.enumerated() {
            passes = max(passes, originalIndex - sortedIndex)
        }
        return passes
    }
}
```

Swift's `sorted(by:)` is already stable, so comparing `numbers[$0] < numbers[$1]` alone would also work; the tuple makes the tie-break explicit. A value that moves right gives a negative difference, which `max` ignores, and starting from 0 handles sorted and empty arrays.

</Approach>
