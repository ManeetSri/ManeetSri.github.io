Before adding or multiplying two big numbers, find out whether the answer will fit in an `Int`. Your functions must **never crash**, whatever the inputs.

- `OverflowCheck.additionOverflows(_ a: Int, _ b: Int) -> Bool` returns `true` if `a + b` would overflow.
- `OverflowCheck.multiplicationOverflows(_ a: Int, _ b: Int) -> Bool` returns `true` if `a * b` would overflow.

## Examples

| Call | Returns | Why |
| --- | --- | --- |
| `additionOverflows(2, 3)` | `false` | 5 fits easily |
| `additionOverflows(Int.max, 1)` | `true` | one past the largest `Int` |
| `additionOverflows(Int.max, Int.min)` | `false` | the result is -1 |
| `multiplicationOverflows(1_000_000_000, 1_000_000_000)` | `false` | 10¹⁸ still fits |
| `multiplicationOverflows(Int.min, -1)` | `true` | the answer would be one more than `Int.max` |

## Constraints

- `a` and `b` can be any `Int` values, from `Int.min` to `Int.max`.
- Writing `a + b` or `a * b` directly crashes the tests when the answer doesn't fit, so don't.

<Hints>
<Hint>
You can't compute `a + b` and then check it: by then the program has already trapped.
</Hint>
<Hint>
Every integer type has methods that compute a result *and* report whether it overflowed, without crashing.
</Hint>
<Hint>
`a.addingReportingOverflow(b)` gives back a tuple with `partialValue` and `overflow`. You only need `.overflow`. Multiplication uses `a.multipliedReportingOverflow(by: b)`.
</Hint>
</Hints>

## Solutions

<Approach title="Ask Swift to report the overflow" time="O(1)" space="O(1)">

The reporting methods do the arithmetic with wrapping, so they never trap, and also tell you whether the true answer fitted.

```swift
public enum OverflowCheck {
    public static func additionOverflows(_ a: Int, _ b: Int) -> Bool {
        return a.addingReportingOverflow(b).overflow
    }

    public static func multiplicationOverflows(_ a: Int, _ b: Int) -> Bool {
        return a.multipliedReportingOverflow(by: b).overflow
    }
}
```

`Int.min * -1` is the sneaky case. `Int.min` is one further from zero than `Int.max`, so flipping its sign can't fit. The reporting method knows; a hand-written check easily forgets it.

</Approach>

<Approach title="Compare against the limits first" time="O(1)" space="O(1)">

For addition, you can also reason about the limits directly. Adding a positive `b` overflows exactly when `a` is bigger than `Int.max - b`, and that subtraction can't overflow because `b` is positive. Negative `b` mirrors it with `Int.min`. This uses `if`, which you'll meet in M03:

```swift
public static func additionOverflows(_ a: Int, _ b: Int) -> Bool {
    if b > 0 {
        return a > Int.max - b
    } else {
        return a < Int.min - b
    }
}
```

It's a good exercise in reasoning about limits, and it's how you'd do it in a language without reporting methods. In Swift, the first approach is shorter and harder to get wrong, especially for multiplication.

</Approach>
