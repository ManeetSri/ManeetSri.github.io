Given points on a grid, find the largest number of them that lie on one straight line.

`CollinearPoints.maxOnOneLine(_ points: [[Int]]) -> Int`

Each point is `[x, y]`. Points can repeat, and every copy counts: three copies of the same point are three points on any line through it.

## Examples

| `points` | Result |
| --- | --- |
| `[[0, 0], [1, 1], [2, 2], [3, 1], [5, 5]]` | `4` |
| `[[0, 0], [0, 7], [0, -3], [1, 1]]` | `3` |
| `[[0, 0], [1, 2], [2, 1]]` | `2` |
| `[[2, 3], [2, 3], [2, 3]]` | `3` |
| `[[4, -2]]` | `1` |
| `[]` | `0` |

The first example's line is y = x. The second is the vertical line x = 0, which has no slope at all.

## Constraints

- `0 ≤ points.count ≤ 1,000`
- `-10⁹ ≤ x, y ≤ 10⁹`
- Aim for O(n²) on average. Checking every triple of points, O(n³), is too slow for 1,000 points.
- Slopes as `Double` are not exact enough: a test has two lines whose slopes differ by about 10⁻¹⁸.

<Hints>
<Hint>
Fix one point as an anchor. Every other point on a line through it has the same direction from the anchor. Group the other points by direction and the biggest group, plus the anchor, is the best line through it.
</Hint>
<Hint>
Represent a direction exactly as a step (dx, dy) divided by the gcd of their absolute values, from M15. Then (2, 4) and (3, 6) both become (1, 2).
</Hint>
<Hint>
(1, −2) and (−1, 2) point opposite ways along the same line. Fix the sign, for example so dx is positive, or dx is 0 and dy is positive. Count copies of the anchor separately: they have no direction, and they belong to every line through it.
</Hint>
</Hints>

## Solutions

<Approach title="Group by exact direction from each anchor" time="O(n²) average" space="O(n)">

A small `Hashable` struct holds the reduced, sign-fixed step, so equal directions are equal keys. Every line is found from its first point in the array, so each anchor only needs to look at the points after it, which halves the work.

```swift
public enum CollinearPoints {
    private struct Direction: Hashable {
        let dx: Int
        let dy: Int

        init(dx: Int, dy: Int) {
            var divisor = Self.gcd(abs(dx), abs(dy))
            if dx < 0 || (dx == 0 && dy < 0) {
                divisor = -divisor        // point rightwards, or straight up
            }
            self.dx = dx / divisor
            self.dy = dy / divisor
        }

        private static func gcd(_ a: Int, _ b: Int) -> Int {
            b == 0 ? a : gcd(b, a % b)
        }
    }

    public static func maxOnOneLine(_ points: [[Int]]) -> Int {
        guard points.count > 2 else {
            return points.count
        }
        var best = 0
        for anchor in points.indices {
            var counts: [Direction: Int] = [:]
            var copies = 1
            var biggestGroup = 0
            for other in (anchor + 1)..<points.count {
                let dx = points[other][0] - points[anchor][0]
                let dy = points[other][1] - points[anchor][1]
                if dx == 0 && dy == 0 {
                    copies += 1
                    continue
                }
                let direction = Direction(dx: dx, dy: dy)
                counts[direction, default: 0] += 1
                biggestGroup = max(biggestGroup, counts[direction]!)
            }
            best = max(best, copies + biggestGroup)
        }
        return best
    }
}
```

The gcd is never 0 here, because the copies were handled first, so dx and dy can't both be 0. Differences of coordinates up to 10⁹ fit easily in `Int`.

</Approach>

<Approach title="Why not a Double slope?" time="O(n²)" space="O(n)">

Grouping by `Double(dy) / Double(dx)` looks simpler, but it has three problems. Vertical lines divide by zero. `0.0` and `-0.0` would need care. And worst, a `Double` keeps only about 16 significant digits, so different slopes can round to the same value: 999,999,999 / 1,000,000,000 and 999,999,998 / 999,999,999 are equal as `Double`s, which would merge two different lines. This is the floating-point pitfall from the hashing pitfalls lesson; the reduced fraction is exact.

</Approach>
