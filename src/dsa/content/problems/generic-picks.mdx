Write two generic functions that work with any suitable element type: one finds the largest item, the other finds the item that appears most often. Give each the weakest constraint it needs.

`GenericPicks.largest<T: Comparable>(_ items: [T]) -> T?` and `GenericPicks.mostFrequent<T: Hashable>(_ items: [T]) -> T?`

- Both return `nil` for an empty array.
- If several items are equally frequent, `mostFrequent` returns the one whose **first appearance** comes earliest in the array.
- Both must work for any conforming type: `Int`, `String`, `Character`, `Bool`, and your own types.

## Examples

| Call | Result |
| --- | --- |
| `largest([3, 9, 4])` | `9` |
| `largest(["pear", "apple", "zucchini"])` | `"zucchini"` |
| `largest([Int]())` | `nil` |
| `mostFrequent([1, 3, 3, 2, 1, 3])` | `3` |
| `mostFrequent(["b", "a", "a", "b"])` | `"b"`: both appear twice, and `"b"` appears first |
| `mostFrequent(Array("mississippi"))` | `"i"`: `i` and `s` both appear 4 times, and `i` appears first |

## Constraints

- `0 ≤ items.count ≤ 100,000`
- Aim for O(n) time for both functions.

<Hints>
<Hint>
`largest` is the "best so far" loop from the orientation module, with `Int` replaced by `T`. The `Comparable` constraint is what lets you write `item > best`.
</Hint>
<Hint>
For `mostFrequent`, count with a dictionary `[T: Int]`, using `counts[item, default: 0] += 1`. Dictionary keys must be `Hashable`, which is why `T` needs that constraint.
</Hint>
<Hint>
To break ties by first appearance, don't loop over the dictionary: its order is unpredictable. Loop over `items` again, in order, and replace the best only when an item's count is **strictly** greater.
</Hint>
</Hints>

## Solutions

<Approach title="A counting dictionary, then a second pass in order" time="O(n)" space="O(k) for k distinct items">

`largest` needs only ordering, so `Comparable` is enough. `mostFrequent` counts every item in a dictionary, then walks the original array so that ties resolve in favour of whichever appeared first.

```swift
public enum GenericPicks {
    public static func largest<T: Comparable>(_ items: [T]) -> T? {
        guard var best = items.first else { return nil }
        for item in items.dropFirst() where item > best {
            best = item
        }
        return best
    }

    public static func mostFrequent<T: Hashable>(_ items: [T]) -> T? {
        var counts: [T: Int] = [:]
        for item in items {
            counts[item, default: 0] += 1
        }
        var best: T?
        var bestCount = 0
        for item in items {
            let count = counts[item, default: 0]
            if count > bestCount {
                best = item
                bestCount = count
            }
        }
        return best
    }
}
```

The second loop visits the first occurrence of each value before any later one. With `>` rather than `>=`, a later value with the same count never replaces an earlier one. `items.max()` would also do for `largest`, but writing it yourself is the point here.

</Approach>
