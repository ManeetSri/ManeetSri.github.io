You have unlimited coins of each distinct value in `coins`. Count the different **collections** of coins that add up to exactly `amount`. The order doesn't matter: 1 + 2 and 2 + 1 are the same collection. Return the count modulo 1,000,000,007.

`ChangeMakingWays.count(coins: [Int], amount: Int) -> Int`

## Examples

| `coins` | `amount` | Output |
| --- | --- | --- |
| `[1, 2, 3]` | `4` | `4` |
| `[2, 3]` | `12` | `3` |
| `[2, 5]` | `3` | `0` |
| `[5]` | `0` | `1` |
| `[10, 20, 50]` | `100` | `10` |

The first example's collections are 1+1+1+1, 1+1+2, 2+2 and 1+3. In the second, 12 is six 2s, three 2s and two 3s, or four 3s. There's exactly one way to pay 0: with no coins.

## Constraints

- `1 ≤ coins.count ≤ 50`, and the values are distinct
- `1 ≤ coins[i] ≤ 10,000`
- `0 ≤ amount ≤ 100,000`
- The tests check large amounts where the order of the loops makes a big difference.

<Hints>
<Hint>
`ways[0] = 1`, and a payment of `t` that ends with coin `c` comes from a payment of `t - c`. But if you let every coin be "the last one" for every total, 1 + 3 and 3 + 1 are both counted.
</Hint>
<Hint>
Fix an order for the coins in every payment: all the first coin value, then all the second, and so on. Then each collection is built exactly once.
</Hint>
<Hint>
Put the coins in the **outer** loop and the totals in the inner loop, going up: `ways[t] += ways[t - coin]` for `t` from `coin` to `amount`. Reduce modulo 1,000,000,007 after each addition.
</Hint>
</Hints>

## Solutions

<Approach title="Try every count of every coin" time="exponential" space="O(coins)">

Recursively choose how many of the first coin to use, then the second, and count the choices that make the amount. Choosing counts per coin value counts collections, not sequences, so it's correct, but far too slow for large amounts.

</Approach>

<Approach title="Coins outer, totals inner" time="O(amount · coins)" space="O(amount)">

While the outer loop is on a coin, only that coin and the ones before it exist. So every collection is built in one fixed order, its smallest-index coins first, and counted once. Swapping the loops (totals outer, coins inner) would count ordered sequences instead: for coins 1, 2 and 3 and amount 4, that gives 7 instead of 4.

```swift
public enum ChangeMakingWays {
    public static func count(coins: [Int], amount: Int) -> Int {
        let mod = 1_000_000_007
        var ways = Array(repeating: 0, count: amount + 1)
        ways[0] = 1
        for coin in coins where coin <= amount {
            for total in stride(from: coin, through: amount, by: 1) {
                ways[total] = (ways[total] + ways[total - coin]) % mod
            }
        }
        return ways[amount]
    }
}
```

Both values in each addition are below the modulus, so the sum stays below 2 × 10⁹ and can't overflow.

</Approach>
