Timings are noisy, so a team benchmarks its data structures by **counting operations** (comparisons, probes, allocations) instead of reading a clock. The counts still vary from run to run, because the inputs are random, so the harness needs the same habits as a timing harness: warm-up runs, many samples, medians rather than averages, a checksum that keeps every result alive, and a rule for when a difference is real. Build it.

`OperationCountBench.measure(warmUp:samples:_:) -> OperationCountBench.Measurement`, `OperationCountBench.verdict(before:after:) -> OperationCountBench.Verdict` and `OperationCountBench.growthExponent(costs:) -> Double`

- **`measure`** calls `work` exactly `warmUp + samples` times, in order: first the warm-up calls, then the samples. Each call returns `(operations, result)`. The `Measurement` holds `median`, the operation count at index `samples / 2` once the samples' counts are sorted; `fewest`, the smallest sample count; and `checksum`, every call's `result` (warm-up calls included) added together with wrap-around. Warm-up counts are never part of the median or the fewest.
- **`verdict`** compares two versions' sample counts. For each version, its median is the element at index `count / 2` after sorting, and its spread is `sorted[(3 * count) / 4] - sorted[count / 4]`. If the medians differ by no more than the larger of the two spreads, the verdict is `.noDifference`. Otherwise it's `.faster` if `after`'s median is lower, `.slower` if it's higher.
- **`growthExponent`** takes the median cost at sizes n, 2n, 4n, … (each size double the last). Work out each cost's ratio to the one before it, take the median ratio (with an even number of ratios, the mean of the middle two), and return its base-2 logarithm: about 1 for linear work, 2 for quadratic.

## Examples

| Call | Output |
| --- | --- |
| `measure(warmUp: 2, samples: 5)` where the calls return operations `900, 800,` then `50, 40, 700, 45, 42` and results `1, 2, 3, 4, 5, 6, 7` | `Measurement(median: 45, fewest: 40, checksum: 28)` |
| `verdict(before: [124, 121, 126, 122, 123], after: [119, 125, 120, 122, 121])` | `.noDifference` |
| `verdict(before: [100, 102, 98, 101, 99], after: [60, 61, 59, 62, 60])` | `.faster` |
| `verdict(before: [10, 10, 10], after: [12, 12, 12])` | `.slower` |
| `growthExponent(costs: [1900, 7800, 31500, 125000])` | about `2.01` |
| `growthExponent(costs: [100, 200, 400, 5000, 1600, 3200])` | `1.0` |

In the first example, the 900 and 800 of the warm-up are ignored, the samples sort to 40, 42, 45, 50, 700, and the 700 (an interrupted run) doesn't move the median. In the first verdict, the medians are 123 and 121, but both versions' own samples spread by 2, so a gap of 2 isn't evidence. In the last example, one measurement (5,000) was disturbed; the ratios are 2, 2, 12.5, 0.32 and 2, and their median, 2, ignores it.

## Constraints

- `0 ≤ warmUp ≤ 1,000` and `1 ≤ samples ≤ 1,001`. Results can be any `Int`, so add them with wrap-around: a plain `+` can overflow and crash the test run.
- `verdict` gets two non-empty arrays of counts, at most 100,000 each.
- `growthExponent` gets at least two costs, all positive.

<Hints>
<Hint>
`measure` is the lesson's harness with a counter in place of the clock: a loop for the warm-up that only folds results into the checksum, then a loop that also appends each sample's operation count to an array. Sort that array once at the end.
</Hint>
<Hint>
Use `&+=` for the checksum. Its job is to depend on every result, so the optimiser can't skip any call; whether it wraps around doesn't matter.
</Hint>
<Hint>
For the exponent, compute the ratios as `Double`s, sort them, pick the middle (or average the two middle ones), and use `log2` from Foundation. The median, rather than the mean, is what makes one disturbed measurement harmless.
</Hint>
</Hints>

## Solutions

<Approach title="A counting harness with medians" time="O(s log s) for s samples" space="O(s)">

```swift
import Foundation

public enum OperationCountBench {
    public struct Measurement: Equatable {
        public let median: Int, fewest: Int, checksum: Int
        public init(median: Int, fewest: Int, checksum: Int) {
            self.median = median; self.fewest = fewest; self.checksum = checksum
        }
    }

    public enum Verdict: Equatable { case faster, slower, noDifference }

    public static func measure(warmUp: Int, samples: Int, _ work: () -> (operations: Int, result: Int)) -> Measurement {
        var checksum = 0
        for _ in 0..<warmUp {
            checksum &+= work().result
        }
        var counts: [Int] = []
        counts.reserveCapacity(samples)
        for _ in 0..<samples {
            let run = work()
            checksum &+= run.result
            counts.append(run.operations)
        }
        counts.sort()
        return Measurement(median: counts[samples / 2], fewest: counts[0], checksum: checksum)
    }

    public static func verdict(before: [Int], after: [Int]) -> Verdict {
        func summary(_ values: [Int]) -> (median: Int, spread: Int) {
            let sorted = values.sorted()
            return (sorted[sorted.count / 2], sorted[(3 * sorted.count) / 4] - sorted[sorted.count / 4])
        }
        let old = summary(before), new = summary(after)
        let gap = new.median - old.median
        if abs(gap) <= max(old.spread, new.spread) { return .noDifference }
        return gap < 0 ? .faster : .slower
    }

    public static func growthExponent(costs: [Int]) -> Double {
        let ratios = zip(costs.dropFirst(), costs).map { Double($0) / Double($1) }.sorted()
        let middle = ratios.count / 2
        let median = ratios.count.isMultiple(of: 2) ? (ratios[middle - 1] + ratios[middle]) / 2 : ratios[middle]
        return log2(median)
    }
}
```

Every piece answers one of the lesson's failure modes: the warm-up absorbs one-off costs, the median ignores disturbed runs, the checksum keeps the work observable, and the verdict refuses to call a difference that's smaller than each version's own noise.

</Approach>
