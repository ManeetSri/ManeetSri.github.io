Build a set of `Int`s the way Swift's own `Set` stores them: one flat array of slots, open addressing with linear probing, and **backward-shift deletion** instead of tombstones.

`BackshiftProbeSet.ProbeSet`, with `init(capacity:)`, `insert(_:) -> Bool`, `contains(_:) -> Bool`, `remove(_:) -> Bool`, `count: Int`, `capacity: Int` and `slots: [Int?]`

The rules, which make the layout exact so the tests can check it:

- `init(capacity:)` makes an empty table of `capacity` slots, a power of two. `slots` is the table as it is now, with `nil` for an empty slot, and `capacity` is its size.
- A key's **home** is `key & (capacity - 1)`. Real sets hash the key first; here the key is its own hash, so you can predict where everything goes.
- `insert(_:)` returns `false` and changes nothing if the key is already there. Otherwise, if storing it would make `count` more than three quarters of `capacity` (that is, `(count + 1) * 4 > capacity * 3`), first double the capacity and re-insert every key, visiting the old slots from 0 upwards. Then put the key in the first empty slot at or after its home, wrapping round from the last slot to slot 0, and return `true`.
- `remove(_:)` returns `false` if the key isn't there. Otherwise it empties the key's slot and repairs the run with a backward shift: walk forward from the hole until an empty slot, and move back into the hole any key whose home is at or before the hole (measuring forwards, with wrap-around); that key's old slot becomes the new hole. The table never shrinks.

## Examples

| Code | `slots` afterwards |
| --- | --- |
| capacity 8, insert 8, 16, 1, 24 | `[8, 16, 1, 24, nil, nil, nil, nil]` |
| then remove 16 | `[8, 1, 24, nil, nil, nil, nil, nil]` |
| capacity 8, insert 8, 1, 9, 2, then remove 8 | `[nil, 1, 9, 2, nil, nil, nil, nil]` |
| capacity 8, insert 7, 15, 23, then remove 7 | `[23, nil, nil, nil, nil, nil, nil, 15]` |
| capacity 4, insert 1, 5, 9, 2 | `[nil, 1, 9, 2, nil, 5, nil, nil]` |

In the second row, 1 (home 1) moves back into the hole at slot 1, then 24 (home 0) into the new hole at slot 2. In the third, nothing moves: 1, 9 and 2 are all at or after their homes, and slot 0 is before every one of them. In the fourth, the run wraps round the end, and both keys shift back across it. In the last, inserting 2 would make 4 keys in 4 slots, so the table first doubles to 8 and re-inserts 1, 5 and 9 in that order, and then 2 lands in slot 3.

## Constraints

- `capacity` is a power of two from 1 to 1,024. Keys are any `Int`, including negatives.
- Up to 100,000 operations, each O(1) on average.
- Don't use `Set` or `Dictionary`.

<Hints>
<Hint>
Store `slots` and `count`. With a power-of-two capacity, `index & (capacity - 1)` is the same as `index % capacity` for non-negative numbers, and it also gives a valid slot for negative keys. A probe moves to `(index + 1) & (capacity - 1)`. The table is never full, so a probe always reaches an empty slot.
</Hint>
<Hint>
Searching and inserting both walk from the home slot: searching stops at the key (found) or at an empty slot (not there); inserting stops at the first empty slot. To grow, keep the old slots, replace them with twice as many empty ones, and insert each old key again, because every home changes when the capacity does.
</Hint>
<Hint>
For the backward shift, a candidate at slot `next` may move into the hole if `(next - home) & mask >= (next - hole) & mask`: its distance from its home is at least its distance from the hole, so the hole lies on its probe path. Keep walking after a key that can't move, because a later key might still belong in the hole.
</Hint>
</Hints>

## Solutions

<Approach title="Tombstones" time="O(1) average, slowing as tombstones pile up" space="O(capacity)">

The approach from the collisions lesson marks a removed slot as deleted instead of emptying it, so searches carry on past it. It works, but it can't produce the `slots` this problem asks for, and tombstones make every later search longer until the next rebuild. Simply setting the slot to `nil` instead is wrong: a key further along the run becomes unreachable, because searches stop at the hole.

</Approach>

<Approach title="Linear probing with backward-shift deletion" time="O(1) average" space="O(capacity)">

After a removal, every key left in the run must still be reachable from its home without crossing an empty slot. The backward shift keeps that true: a key moves only into a hole that lies on its own probe path, and the walk ends at the first empty slot, where the run ends.

```swift
public enum BackshiftProbeSet {
    public struct ProbeSet {
        public private(set) var slots: [Int?]
        public private(set) var count = 0

        public init(capacity: Int) {
            slots = Array(repeating: nil, count: capacity)
        }

        public var capacity: Int { slots.count }

        private var mask: Int { slots.count - 1 }

        private func home(_ key: Int) -> Int { key & mask }

        private func slot(of key: Int) -> Int? {
            var index = home(key)
            while let stored = slots[index] {
                if stored == key { return index }
                index = (index + 1) & mask
            }
            return nil
        }

        public func contains(_ key: Int) -> Bool {
            slot(of: key) != nil
        }

        @discardableResult
        public mutating func insert(_ key: Int) -> Bool {
            guard slot(of: key) == nil else { return false }
            if (count + 1) * 4 > capacity * 3 {
                let old = slots
                slots = Array(repeating: nil, count: old.count * 2)
                for case let stored? in old {
                    place(stored)
                }
            }
            place(key)
            count += 1
            return true
        }

        private mutating func place(_ key: Int) {
            var index = home(key)
            while slots[index] != nil {
                index = (index + 1) & mask
            }
            slots[index] = key
        }

        @discardableResult
        public mutating func remove(_ key: Int) -> Bool {
            guard var hole = slot(of: key) else { return false }
            slots[hole] = nil
            count -= 1
            var next = (hole + 1) & mask
            while let candidate = slots[next] {              // stop at the end of the run
                let fromHome = (next - home(candidate)) & mask
                let fromHole = (next - hole) & mask
                if fromHome >= fromHole {                    // the hole is on its probe path
                    slots[hole] = candidate
                    slots[next] = nil
                    hole = next
                }
                next = (next + 1) & mask
            }
            return true
        }
    }
}
```

Masking a negative difference with `& mask` gives the forward distance with wrap-around, the same as adding `capacity` before taking `%`. Doubling the capacity is always enough room: the table is at most three quarters full before an insert, so it's at most about three eighths full after doubling.

</Approach>
