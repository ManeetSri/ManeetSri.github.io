Convert temperatures between degrees Celsius and degrees Fahrenheit, in both directions.

- `TemperatureConverter.fahrenheit(fromCelsius celsius: Double) -> Double`
- `TemperatureConverter.celsius(fromFahrenheit fahrenheit: Double) -> Double`

The formulas are:

- Fahrenheit = Celsius × 9 ÷ 5 + 32
- Celsius = (Fahrenheit − 32) × 5 ÷ 9

## Examples

| Call | Returns |
| --- | --- |
| `fahrenheit(fromCelsius: 0)` | `32.0` |
| `fahrenheit(fromCelsius: 100)` | `212.0` |
| `fahrenheit(fromCelsius: 37)` | about `98.6` |
| `celsius(fromFahrenheit: -40)` | `-40.0` |
| `celsius(fromFahrenheit: 98.6)` | about `37.0` |

## Constraints

- `-1,000 ≤ celsius, fahrenheit ≤ 10,000`
- Answers are checked to within `1e-9`, as recommended in the lesson. `98.59999999999999` counts as `98.6`.

## Solutions

<Approach title="Translate the formulas" time="O(1)" space="O(1)">

Each conversion is one line of arithmetic on `Double` values.

```swift
public enum TemperatureConverter {
    public static func fahrenheit(fromCelsius celsius: Double) -> Double {
        return celsius * 9 / 5 + 32
    }

    public static func celsius(fromFahrenheit fahrenheit: Double) -> Double {
        return (fahrenheit - 32) * 5 / 9
    }
}
```

Without the parentheses, `fahrenheit - 32 * 5 / 9` would do the multiplication and division first, which is a different calculation. And because the inputs are `Double`, `5 / 9` style division keeps its fraction. If they were `Int` values, `5 / 9` would be `0` and every answer would be wrong.

The exact last digits can differ depending on the order of operations, for example `celsius * 1.8 + 32` versus `celsius * 9 / 5 + 32`. That's floating point at work, and it's why the tests compare with a tolerance rather than `==`.

</Approach>
