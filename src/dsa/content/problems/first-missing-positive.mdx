Return the **smallest positive integer** (1, 2, 3, …) that doesn't appear in an unsorted array. The values can be anything: zero, negative, repeated, or enormous. You may rearrange or change the array.

`FirstMissingPositive.find(in numbers: inout [Int]) -> Int`

Aim for O(n) time and O(1) extra space.

## Examples

| `numbers` | Returns |
| --- | --- |
| `[7, 3, -2, 1, 9, 2]` | `4` |
| `[2, 1, 3]` | `4` |
| `[0, -5, 8]` | `1` |
| `[1, 1]` | `2` |
| `[Int.max, 2, 1]` | `3` |
| `[]` | `1` |

In the first example 1, 2 and 3 are present, and 4 is the first one that isn't. The 7 and 9 don't matter.

## Constraints

- `0 ≤ numbers.count ≤ 200,000`
- `Int.min ≤ numbers[i] ≤ Int.max`

<Hints>
<Hint>
With n values, the answer is between 1 and n + 1. Why? So which values can you ignore completely?
</Hint>
<Hint>
Cyclic sort, but only for values from 1 to n: send each one to index v − 1, unless that index already holds v. Leave everything else where it lands.
</Hint>
<Hint>
Check the range **before** using `numbers[value - 1]`, so out-of-range values are never used as indexes and `value - 1` never overflows for `Int.min`. Then the first index i that doesn't hold i + 1 gives the answer, or n + 1 if they all do.
</Hint>
</Hints>

## Solutions

<Approach title="Flags for 1 to n" time="O(n)" space="O(n)">

Only 1 to n can matter, so keep one `Bool` per candidate. This is the clearest O(n) solution, and the right one when you can't modify the input.

```swift
public static func find(in numbers: inout [Int]) -> Int {
    let n = numbers.count
    var present = [Bool](repeating: false, count: n + 2)
    for value in numbers where value >= 1 && value <= n {
        present[value] = true
    }
    var candidate = 1
    while present[candidate] {
        candidate += 1
    }
    return candidate
}
```

`present[n + 1]` is always false, so the loop always stops by n + 1.

</Approach>

<Approach title="Cyclic sort, ignoring out-of-range values" time="O(n)" space="O(1)">

The array itself becomes the flags: after sorting, index i holds i + 1 exactly when i + 1 is present.

```swift
public enum FirstMissingPositive {
    public static func find(in numbers: inout [Int]) -> Int {
        let n = numbers.count
        var i = 0
        while i < n {
            let value = numbers[i]
            if value >= 1 && value <= n && numbers[value - 1] != value {
                numbers.swapAt(i, value - 1)              // send it home
            } else {
                i += 1                                    // out of range, a spare copy, or home
            }
        }
        for index in 0..<n where numbers[index] != index + 1 {
            return index + 1
        }
        return n + 1
    }
}
```

Every swap puts one value home for good, so there are at most n swaps plus n moves of i. The condition `numbers[value - 1] != value` compares values, so a repeated value never swaps with its own copy.

</Approach>

<Approach title="Sign marking" time="O(n)" space="O(1)">

Use each element's sign as the flag: "is i + 1 present?" becomes "is `numbers[i]` negative?". First replace everything outside 1 to n with n + 1, so all values are positive and `abs` is safe. Then each value v from 1 to n makes index v − 1 negative.

```swift
public static func find(in numbers: inout [Int]) -> Int {
    let n = numbers.count
    for i in 0..<n where numbers[i] < 1 || numbers[i] > n {
        numbers[i] = n + 1
    }
    for i in 0..<n {
        let value = abs(numbers[i])
        if value <= n && numbers[value - 1] > 0 {
            numbers[value - 1] = -numbers[value - 1]
        }
    }
    for i in 0..<n where numbers[i] > 0 {
        return i + 1
    }
    return n + 1
}
```

It never moves a value, but it leaves the array full of minus signs. Both O(1) versions change the caller's data, which is why the parameter is `inout`.

</Approach>
