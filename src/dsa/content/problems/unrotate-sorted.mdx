Someone took a sorted array and rotated it: they moved some number of elements from the front to the back, keeping their order. Put it back in sorted order, **in place**, using O(1) extra space.

`UnrotateSorted.unrotate(_ numbers: inout [Int])`

You aren't told how far it was rotated. The original was sorted in non-decreasing order, so values can repeat.

## Examples

| `numbers` before | `numbers` after |
| --- | --- |
| `[4, 5, 6, 1, 2, 3]` | `[1, 2, 3, 4, 5, 6]` |
| `[9, 2, 4, 7]` | `[2, 4, 7, 9]` |
| `[3, 3, 1, 2, 2]` | `[1, 2, 2, 3, 3]` |
| `[10, 20, 30]` | `[10, 20, 30]` |
| `[]` | `[]` |

The fourth array was rotated by 0 steps (or by 3), so it's already sorted.

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- `numbers` is always some rotation of a non-decreasing array.
- O(n) time and O(1) extra space: no second array, and no sorting.

<Hints>
<Hint>
Walk a sorted array left to right and each value is at least the one before it. In a rotated one, there's exactly one place where that fails: the "drop", where the largest value is followed by the smallest. Unless there's no drop at all.
</Hint>
<Hint>
If the drop is between index `i` and `i + 1`, then `numbers[(i + 1)...]` belongs at the front. That's a rotation to the left by `i + 1` steps.
</Hint>
<Hint>
Rotating left uses the same three reversals as rotating right, in a different order: reverse `numbers[0...i]`, reverse `numbers[(i + 1)...]`, then reverse the whole array.
</Hint>
</Hints>

## Solutions

<Approach title="Sort it again" time="O(n log n)" space="O(n)">

`numbers.sort()` gives the right answer. It's a good check for your real solution, but it ignores everything you know about the input, and Swift's sort uses O(n) extra memory.

```swift
public static func unrotate(_ numbers: inout [Int]) {
    numbers.sort()
}
```

</Approach>

<Approach title="Find the drop, then rotate with three reversals" time="O(n)" space="O(1)">

One scan finds the drop. If there isn't one, the array is already sorted. Otherwise everything after the drop moves to the front: a left rotation by `drop + 1`, done with three in-place reversals.

```swift
public enum UnrotateSorted {
    public static func unrotate(_ numbers: inout [Int]) {
        let count = numbers.count
        guard count > 1 else { return }

        // Find the drop. With no drop the array is already sorted.
        var drop: Int? = nil
        for index in 0..<(count - 1) where numbers[index] > numbers[index + 1] {
            drop = index
            break
        }
        guard let last = drop else { return }

        // Reverses numbers[low...high] in place
        func reverse(_ low: Int, _ high: Int) {
            var left = low
            var right = high
            while left < right {
                numbers.swapAt(left, right)
                left += 1
                right -= 1
            }
        }

        // Rotating left by `last + 1`: reverse both parts, then the whole array
        reverse(0, last)
        reverse(last + 1, count - 1)
        reverse(0, count - 1)
    }
}
```

Repeated values don't cause trouble. The test is strictly greater than, so equal neighbours never look like a drop, and an array of identical values has no drop at all.

</Approach>
