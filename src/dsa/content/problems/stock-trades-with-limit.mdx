`prices[i]` is a share's price on day i. You may complete at most `maxTrades` trades, where a trade is buying one share and selling it on a later day. You can hold at most one share at a time, and you may sell and buy again on the same day. Return the largest total profit.

`StockTradesWithLimit.maxProfit(_ prices: [Int], maxTrades: Int) -> Int`

## Examples

| `prices` | `maxTrades` | Output |
| --- | --- | --- |
| `[2, 6, 3, 1, 5, 4, 8, 2]` | `1` | `7` |
| `[2, 6, 3, 1, 5, 4, 8, 2]` | `2` | `11` |
| `[2, 6, 3, 1, 5, 4, 8, 2]` | `3` | `12` |
| `[5, 4, 3]` | `2` | `0` |
| `[3, 8, 2, 5, 1, 4]` | `1000000000` | `11` |

With one trade, buy at 1 and sell at 8. With two, add 2 → 6. With three, split 1 → 8 into 1 → 5 and 4 → 8, banking every rise. In the last example the limit is far more than six days could ever use.

## Constraints

- `0 ≤ prices.count ≤ 100,000` and `0 ≤ prices[i] ≤ 10,000`
- `0 ≤ maxTrades ≤ 1,000,000,000`
- When `maxTrades` is less than `prices.count / 2`, `prices.count × maxTrades ≤ 2,000,000`.
- The tests include 100,000 days with a limit of a billion, so don't allocate anything of size `maxTrades` without thinking.

<Hints>
<Hint>
For each trade t, you're either holding its share or have finished it. That's two states per trade, chained: finishing trade t − 1 is where trade t starts.
</Hint>
<Hint>
`buy[t] = max(buy[t], sell[t − 1] − price)` and `sell[t] = max(sell[t], buy[t] + price)`, with `sell[0] = 0`. The answer is `sell[maxTrades]`.
</Hint>
<Hint>
An optimal plan never needs more than `prices.count / 2` trades: two trades that share a day can merge. Above that, the limit can't bind, so bank every rise.
</Hint>
</Hints>

## Solutions

<Approach title="Try every plan" time="O(3ⁿ)" space="O(n)">

On each day, wait, buy (if a trade is left) or sell (if holding). It's a useful brute force on ten or so days, nothing more.

</Approach>

<Approach title="A chain of states, with a shortcut" time="O(n × min(k, n / 2))" space="O(min(k, n / 2))">

For small limits, run the chain of k pairs of states. Updating in place is safe here, because reading a value already updated today only adds same-day buy-and-sell moves, which earn nothing. For a limit of at least `n / 2`, sum every rise instead.

```swift
public enum StockTradesWithLimit {
    public static func maxProfit(_ prices: [Int], maxTrades: Int) -> Int {
        guard maxTrades > 0, prices.count >= 2 else { return 0 }
        if maxTrades >= prices.count / 2 {
            var profit = 0
            for day in 1..<prices.count {
                profit += max(0, prices[day] - prices[day - 1])
            }
            return profit
        }
        var buy = Array(repeating: Int.min / 2, count: maxTrades + 1)
        var sell = Array(repeating: 0, count: maxTrades + 1)        // sell[0] = 0: no trades yet
        for price in prices {
            for t in 1...maxTrades {
                buy[t] = max(buy[t], sell[t - 1] - price)
                sell[t] = max(sell[t], buy[t] + price)
            }
        }
        return sell[maxTrades]
    }
}
```

The guard handles a limit of 0, where `1...0` would crash, and lists too short to trade. `Int.min / 2` stands for "not holding yet" and leaves room to add a price.

</Approach>
