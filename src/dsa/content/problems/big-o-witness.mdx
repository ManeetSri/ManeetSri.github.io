To prove that a step count f(n) is O(g(n)), you pick a constant c and then need a starting point n₀ with f(n) ≤ c · g(n) for **every** n ≥ n₀. Given the coefficients of f and your chosen c, return the **smallest** n₀ (at least 1) that works, or `nil` if no n₀ works for that c.

`BigOWitness.linearStart(a: Int, b: Int, c: Int) -> Int?` handles f(n) = a·n + b against g(n) = n.

`BigOWitness.quadraticStart(a: Int, b: Int, k: Int, c: Int) -> Int?` handles f(n) = a·n² + b·n + k against g(n) = n².

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `linearStart(a: 3, b: 2, c: 4)` | `2` | 3n + 2 ≤ 4n is the same as 2 ≤ n |
| `linearStart(a: 2, b: 100, c: 3)` | `100` | 2n + 100 ≤ 3n once n ≥ 100 |
| `linearStart(a: 3, b: 2, c: 10)` | `1` | it already holds at n = 1 |
| `linearStart(a: 3, b: 2, c: 3)` | `nil` | 3n + 2 is always bigger than 3n |
| `quadraticStart(a: 1, b: 10, k: 0, c: 2)` | `10` | n² + 10n ≤ 2n² is the same as 10 ≤ n |
| `quadraticStart(a: 2, b: 3, k: 5, c: 3)` | `5` | n² ≥ 3n + 5 first holds at n = 5: 25 ≥ 20 |
| `quadraticStart(a: 4, b: 0, k: 0, c: 1)` | `nil` | 4n² never fits under n² |

## Constraints

- `linearStart`: `1 ≤ a, c ≤ 10⁶` and `0 ≤ b ≤ 10¹⁸`. Answer in O(1): trying n = 1, 2, 3, … could take 10¹⁸ steps.
- `quadraticStart`: `1 ≤ a, c ≤ 1000` and `0 ≤ b, k ≤ 10⁶`. Trying n = 1, 2, 3, … is fine here.
- The lower-order coefficients `b` and `k` are never negative.

<Hints>
<Hint>
Start with the easy verdicts. If c is smaller than a, the leading term a·n (or a·n²) eventually beats c·n (or c·n²), so no n₀ exists. If c equals a, the leading terms cancel, and what's left must be at most 0 for every n.
</Hint>
<Hint>
Linear, with c bigger than a: a·n + b ≤ c·n is the same as b ≤ (c − a)·n. So n has to be at least b / (c − a), rounded **up**. Don't forget that n₀ is at least 1, which matters when b is 0.
</Hint>
<Hint>
Quadratic, with c bigger than a: the condition is (c − a)·n² ≥ b·n + k. Divide both sides by n: (c − a)·n ≥ b + k / n. As n grows, the left side grows and the right side shrinks, so once the condition holds it holds for every larger n. That means the first n where it holds is the answer, and a simple loop finds it.
</Hint>
</Hints>

## Solutions

<Approach title="Try each n in turn" time="O(n₀)" space="O(1)">

Check n = 1, 2, 3, … until the inequality holds. Because the lower-order terms are never negative, the inequality never fails again after the first n where it holds (see the third hint), so the first success is the answer. This is all `quadraticStart` needs, but for `linearStart` the answer can be 10¹⁸.

```swift
public static func linearStart(a: Int, b: Int, c: Int) -> Int? {
    if c < a { return nil }
    if c == a { return b == 0 ? 1 : nil }
    var n = 1
    while a * n + b > c * n {
        n += 1
    }
    return n
}
```

</Approach>

<Approach title="Solve the inequality" time="O(1) and O(n₀)" space="O(1)">

For the linear case, rearrange instead of searching. With c bigger than a, a·n + b ≤ c·n means n ≥ b / (c − a), so the smallest whole n is that division rounded up, and at least 1. Rounding up uses the remainder rather than `(b + gap - 1) / gap`, which would also work here but adds two numbers that can be large.

The quadratic case keeps the loop. Its answer is at most around b + √k + 1, about a million steps at worst.

```swift
public enum BigOWitness {
    public static func linearStart(a: Int, b: Int, c: Int) -> Int? {
        if c < a { return nil }
        if c == a { return b == 0 ? 1 : nil }
        let gap = c - a
        let start = b / gap + (b % gap == 0 ? 0 : 1)
        return max(1, start)
    }

    public static func quadraticStart(a: Int, b: Int, k: Int, c: Int) -> Int? {
        if c < a { return nil }
        if c == a { return b == 0 && k == 0 ? 1 : nil }
        let gap = c - a
        var n = 1
        while gap * n * n < b * n + k {
            n += 1
        }
        return n
    }
}
```

When no n₀ exists, that's exactly the situation from the lesson where c is too small: with c less than a, a·n eventually overtakes c·n however much head start you give it. A bigger c always works for these functions, which is why they're O(n) and O(n²).

</Approach>
