A combinatorics service receives a batch of queries. Each query `[n, k]` asks for C(n, k), the number of ways to choose k items from n, modulo the prime 1,000,000,007. Return the answers in the same order. When k is negative or greater than n, there are no ways, so the answer is 0.

`BinomialQueryBank.answers(_ queries: [[Int]]) -> [Int]`

## Examples

| `queries` | Output |
| --- | --- |
| `[[5, 2], [10, 3], [7, 9], [0, 0], [7, -1]]` | `[10, 120, 0, 1, 0]` |
| `[[1000, 500]]` | `[159835829]` |
| `[[1_000_000, 500_000], [1_000_000, 1]]` | `[996692777, 1000000]` |
| `[]` | `[]` |

## Constraints

- `0 ≤ queries.count ≤ 100,000`
- Each query is `[n, k]` with `0 ≤ n ≤ 1,000,000` and `-1,000,005 ≤ k ≤ 1,000,005`
- The tests send 100,000 queries with n up to a million. Pascal's triangle would need 5 × 10¹¹ cells, and a separate O(k) loop per query up to 5 × 10¹⁰ steps.

<Hints>
<Hint>
C(n, k) = n! / (k! × (n − k)!). Modulo a prime, dividing means multiplying by an inverse, so precompute the factorials and the inverses of the factorials, up to the largest n in the batch.
</Hint>
<Hint>
You only need one modular inverse. Compute invFact[N] = fact[N]^(p − 2) with fast power, by Fermat's little theorem. Then walk down: invFact[i − 1] = invFact[i] × i, because 1/(i − 1)! = i/i!.
</Hint>
<Hint>
Each answer is fact[n] × invFact[k] × invFact[n − k], reducing after each multiplication so two values below 10⁹ + 7 are multiplied at a time. Check the range of k before indexing.
</Hint>
</Hints>

## Solutions

<Approach title="One loop per query" time="O(Σ k + q log p)" space="O(1)">

For each query, multiply n(n − 1)…(n − k + 1) and k! modulo p, then divide with one Fermat inverse. It's correct, and fine for a few queries with small k, but 100,000 queries with k around 500,000 is far too much work.

</Approach>

<Approach title="Factorial and inverse factorial tables" time="O(N + log p + q)" space="O(N)">

Build both tables once, up to the largest n asked about, then answer every query with three lookups.

```swift
public enum BinomialQueryBank {
    private static let mod = 1_000_000_007

    public static func answers(_ queries: [[Int]]) -> [Int] {
        let limit = queries.map { $0[0] }.max() ?? 0
        var fact = Array(repeating: 1, count: limit + 1)
        for i in stride(from: 1, through: limit, by: 1) {
            fact[i] = fact[i - 1] * i % mod
        }
        var invFact = Array(repeating: 1, count: limit + 1)
        invFact[limit] = power(fact[limit], mod - 2)
        for i in stride(from: limit, to: 0, by: -1) {
            invFact[i - 1] = invFact[i] * i % mod      // 1/(i − 1)! = i · 1/i!
        }
        return queries.map { query in
            let (n, k) = (query[0], query[1])
            guard k >= 0, k <= n else { return 0 }
            return fact[n] * invFact[k] % mod * invFact[n - k] % mod
        }
    }

    private static func power(_ base: Int, _ exponent: Int) -> Int {
        var result = 1
        var square = base % mod
        var e = exponent
        while e > 0 {
            if e & 1 == 1 { result = result * square % mod }
            square = square * square % mod
            e >>= 1
        }
        return result
    }
}
```

`stride(from: 1, through: limit, by: 1)` is used instead of `1...limit` because `1...0` would crash when every query has n = 0, while the stride is simply empty.

</Approach>
