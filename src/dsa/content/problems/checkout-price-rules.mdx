A shop's checkout applies discount rules to a price in pennies. Every rule promises the same two things, a label and a way to change a price, so the rules are described by a protocol. Make three types keep that promise, then write two functions that work with any mix of rules.

`CheckoutPriceRules.PercentOff`, `AmountOff` and `PriceCap`, plus `CheckoutPriceRules.finalPrice(of:applying:)` and `CheckoutPriceRules.bestSingleRule(for:from:)`

The protocol is already written:

```swift
public protocol PriceRule {
    var label: String { get }
    func apply(to pennies: Int) -> Int
}
```

| Type | `label` | `apply(to:)` |
| --- | --- | --- |
| `PercentOff(percent: 10)` | `"10% off"` | takes 10% off, rounding the discount **down** to a whole penny |
| `AmountOff(amount: 250)` | `"250p off"` | takes 250 off, but never goes below 0 |
| `PriceCap(cap: 500)` | `"at most 500p"` | lowers any price above 500 to 500 |

- **`finalPrice(of:applying:)`** applies the rules in order, each to the result of the one before.
- **`bestSingleRule(for:from:)`** returns the label of the rule that, used on its own, gives the lowest price. On a tie it returns the earliest such rule, and with no rules it returns `nil`.

## Examples

| Call | Result |
| --- | --- |
| `PercentOff(percent: 10).apply(to: 999)` | `900` (the discount, 99.9, rounds down to 99) |
| `AmountOff(amount: 250).apply(to: 100)` | `0` |
| `finalPrice(of: 1000, applying: [PercentOff(percent: 10), AmountOff(amount: 250)])` | `650` |
| `finalPrice(of: 1000, applying: [AmountOff(amount: 250), PercentOff(percent: 10)])` | `675` |
| `bestSingleRule(for: 1000, from: [PercentOff(percent: 10), AmountOff(amount: 250), PriceCap(cap: 800)])` | `"250p off"` |
| `bestSingleRule(for: 1000, from: [AmountOff(amount: 100), PercentOff(percent: 10)])` | `"100p off"` (a tie at 900) |

## Constraints

- Prices and amounts are between 0 and 1,000,000, and percentages between 0 and 100.
- Up to 10,000 rules.
- The tests also use a rule type of their own, so the two functions may only use what the protocol promises.

<Hints>
<Hint>
Integer division already rounds down, so the discount is `pennies * percent / 100`, and the new price is `pennies` minus that. `max(0, …)` and `min(…, …)` handle the other two rules.
</Hint>
<Hint>
`label` is a `{ get }` requirement, so a computed property such as `public var label: String { "\(percent)% off" }` satisfies it.
</Hint>
<Hint>
For `bestSingleRule`, keep the best label and price so far, and replace them only when a rule gives a strictly lower price. That keeps the earliest rule on a tie.
</Hint>
</Hints>

## Solutions

<Approach title="Three conformances, two protocol-only functions" time="O(k) for k rules" space="O(1)">

Each type keeps the promise in its own way. The two functions take `[any PriceRule]`, so they can only call `label` and `apply(to:)`, which is exactly why a brand-new rule type, like the one in the tests, works with them unchanged.

```swift
public enum CheckoutPriceRules {
    public protocol PriceRule {
        var label: String { get }
        func apply(to pennies: Int) -> Int
    }

    public struct PercentOff: PriceRule {
        public let percent: Int

        public init(percent: Int) {
            self.percent = percent
        }

        public var label: String {
            "\(percent)% off"
        }

        public func apply(to pennies: Int) -> Int {
            pennies - pennies * percent / 100
        }
    }

    public struct AmountOff: PriceRule {
        public let amount: Int

        public init(amount: Int) {
            self.amount = amount
        }

        public var label: String {
            "\(amount)p off"
        }

        public func apply(to pennies: Int) -> Int {
            max(0, pennies - amount)
        }
    }

    public struct PriceCap: PriceRule {
        public let cap: Int

        public init(cap: Int) {
            self.cap = cap
        }

        public var label: String {
            "at most \(cap)p"
        }

        public func apply(to pennies: Int) -> Int {
            min(pennies, cap)
        }
    }

    public static func finalPrice(of pennies: Int, applying rules: [any PriceRule]) -> Int {
        var price = pennies
        for rule in rules {
            price = rule.apply(to: price)
        }
        return price
    }

    public static func bestSingleRule(for pennies: Int, from rules: [any PriceRule]) -> String? {
        var best: (label: String, price: Int)?
        for rule in rules {
            let price = rule.apply(to: pennies)
            if best == nil || price < best!.price {
                best = (rule.label, price)
            }
        }
        return best?.label
    }
}
```

The order of rules matters because each one sees the price the previous one left: a percentage taken after a fixed amount saves less than one taken before it.

</Approach>
