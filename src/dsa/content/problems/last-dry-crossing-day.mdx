A field of `rows × cols` square cells starts completely dry. Each day, one more cell floods and stays underwater: on day `d` (counting from 1), the cell `floods[d - 1] = [row, col]` floods. A hiker wants to cross the field from north to south: start on any dry cell in the top row, step up, down, left or right between dry cells, and reach any cell in the bottom row. Return the largest `d` such that the hiker can still cross after the first `d` floods, where `d = 0` means before anything has flooded.

`LastDryCrossingDay.lastDay(rows: Int, cols: Int, floods: [[Int]]) -> Int`

## Examples

| `rows` | `cols` | `floods` | Output |
| --- | --- | --- | --- |
| `2` | `2` | `[[0, 0], [0, 1], [1, 0], [1, 1]]` | `1` |
| `3` | `3` | `[[1, 1], [0, 0], [2, 2], [1, 0], [0, 2], [1, 2]]` | `2` |
| `2` | `2` | `[[0, 0]]` | `1` |
| `1` | `1` | `[[0, 0]]` | `0` |

In the first example, after day 1 the hiker can still go from `[0, 1]` down to `[1, 1]`, but after day 2 the whole top row is underwater. In the second, after two floods the route `[0, 2] → [1, 2] → [2, 2]` is open, and the third flood closes it with no other way round. In the third, the field can still be crossed after the only flood, so the answer is `floods.count`.

## Constraints

- `1 ≤ rows`, `1 ≤ cols` and `rows × cols ≤ 100,000`
- `0 ≤ floods.count ≤ rows × cols`, every `[row, col]` is inside the field, and no cell floods twice.
- The tests flood a 300 × 300 field cell by cell, so running a full search after every flood, O((rows × cols)²), is too slow.

<Hints>
<Hint>
Checking one day is a BFS or DFS from the dry top-row cells. And once the field can't be crossed, it never can again: more water never opens a route. What does that monotonic yes, yes, …, no, no suggest?
</Hint>
<Hint>
Binary search on the day, with a BFS for each guess: O(cells · log cells), which passes. For a different route, think about connectivity: "is the top connected to the bottom?" is a union-find question, but union-find can only join sets, never split them.
</Hint>
<Hint>
So run time backwards. Start from the field after every flood, then dry the cells out in reverse order: drying only ever joins cells. Add two extra elements for "the top row" and "the bottom row", and join every dry cell in those rows to them. The first time top and bottom connect, going backwards, gives the answer.
</Hint>
</Hints>

## Solutions

<Approach title="Binary search on the day, BFS to check" time="O(rc · log rc)" space="O(rc)">

Write `canCross(after: d)`: mark the first `d` floods, then BFS from every dry top-row cell and see whether any bottom-row cell is reached. It's true for `d = 0` and turns false at some point (or never), so binary search for the last true value, as in [The monotonic predicate idea](/dsa/learn/bsa-idea). About 17 BFS runs on 100,000 cells is quick.

</Approach>

<Approach title="Union-find, backwards in time" time="O(rc · α(rc))" space="O(rc)">

Flooding removes cells, and union-find can't remove anything. Played backwards, the same story only adds cells. Two virtual elements, `top` and `bottom`, stand for the edges of the field, so "can the hiker cross?" becomes one `connected` call.

```swift
import DSAKit

public enum LastDryCrossingDay {
    public static func lastDay(rows: Int, cols: Int, floods: [[Int]]) -> Int {
        let cells = rows * cols
        let top = cells
        let bottom = cells + 1
        var sets = UnionFind(count: cells + 2)
        var dry = Array(repeating: true, count: cells)
        for flood in floods {
            dry[flood[0] * cols + flood[1]] = false
        }

        func join(_ cell: Int) {
            let row = cell / cols
            let col = cell % cols
            if row == 0 { sets.union(cell, top) }
            if row == rows - 1 { sets.union(cell, bottom) }
            if row > 0, dry[cell - cols] { sets.union(cell, cell - cols) }
            if row < rows - 1, dry[cell + cols] { sets.union(cell, cell + cols) }
            if col > 0, dry[cell - 1] { sets.union(cell, cell - 1) }
            if col < cols - 1, dry[cell + 1] { sets.union(cell, cell + 1) }
        }

        for cell in 0..<cells where dry[cell] {
            join(cell)
        }
        if sets.connected(top, bottom) { return floods.count }

        for day in stride(from: floods.count, through: 1, by: -1) {
            let cell = floods[day - 1][0] * cols + floods[day - 1][1]
            dry[cell] = true
            join(cell)
            if sets.connected(top, bottom) { return day - 1 }
        }
        return 0
    }
}
```

Drying the cell from day `d` gives the field as it was after `d - 1` floods, which is why a connection there returns `d - 1`. The final `return 0` is never reached, because a completely dry field can always be crossed.

Two tricks from different lessons meet here: processing changes in reverse so deletions become additions, from [Number of islands II and equation satisfiability](/dsa/learn/uf-online), and an extra element that stands for a whole side of the field, like the virtual vertex in [Connect all points and other MST problems](/dsa/learn/mst-problems).

</Approach>
