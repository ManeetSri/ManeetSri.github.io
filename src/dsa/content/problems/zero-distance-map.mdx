Given a grid of 0s and 1s, return a grid of the same shape in which every cell holds the fewest steps (up, down, left or right) from that cell to the nearest 0. Cells that are 0 hold 0. If the grid contains no 0 at all, every cell holds `-1`.

`ZeroDistanceMap.distances(_ grid: [[Int]]) -> [[Int]]`

## Examples

| `grid` | Returns |
| --- | --- |
| `[[0, 0, 0], [0, 1, 0], [1, 1, 1]]` | `[[0, 0, 0], [0, 1, 0], [1, 2, 1]]` |
| `[[1, 1, 1], [1, 0, 1], [1, 1, 1]]` | `[[2, 1, 2], [1, 0, 1], [2, 1, 2]]` |
| `[[0, 1, 1, 1, 1, 1, 0]]` | `[[0, 1, 2, 3, 2, 1, 0]]` |
| `[[1, 1], [1, 1]]` | `[[-1, -1], [-1, -1]]` |
| `[]` | `[]` |

In the first example, the bottom-middle cell is two steps from the nearest 0, straight up. In the third, the two 0s at the ends race towards the middle, and the middle cell is 3 steps from either.

## Constraints

- `0 ≤ rows, columns ≤ 1,000`, every row has the same length, and every cell is 0 or 1.
- The tests include a 1000 × 1000 grid with a single 0 in one corner. A separate BFS from every 1 would take about 10¹² steps there.

<Hints>
<Hint>
A BFS from one cell finds its nearest 0, but doing that for every cell repeats the same work over and over.
</Hint>
<Hint>
Turn it round: the 0s are the sources. Put **every** 0 in the queue at distance 0 before the BFS starts, and let the rings grow from all of them at once.
</Hint>
<Hint>
Start every other cell at `-1`, meaning "not reached yet". When you first reach a cell, set its distance to its neighbour's + 1 and enqueue it. If there are no 0s, the queue starts empty and every `-1` stays.
</Hint>
</Hints>

## Solutions

<Approach title="BFS from every 1" time="O((rows × columns)²)" space="O(rows × columns)">

For each 1, run a BFS that stops at the first 0 it reaches. Correct, and fine for tiny grids, but on a grid with one 0 in a corner every one of those searches sweeps most of the grid.

</Approach>

<Approach title="Multi-source BFS from every 0" time="O(rows × columns)" space="O(rows × columns)">

All the 0s enter the queue together, so each cell is first reached from its nearest 0, and each cell is enqueued once. The distance grid is also the visited mark.

```swift
public enum ZeroDistanceMap {
    private static let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    public static func distances(_ grid: [[Int]]) -> [[Int]] {
        var distance = grid.map { row in row.map { $0 == 0 ? 0 : -1 } }
        var queue: [(Int, Int)] = []
        for row in grid.indices {
            for column in grid[row].indices where grid[row][column] == 0 {
                queue.append((row, column))
            }
        }
        var head = 0
        while head < queue.count {
            let (row, column) = queue[head]
            head += 1
            for (dr, dc) in directions {
                let r = row + dr
                let c = column + dc
                guard r >= 0, r < distance.count, c >= 0, c < distance[r].count else { continue }
                guard distance[r][c] == -1 else { continue }
                distance[r][c] = distance[row][column] + 1
                queue.append((r, c))
            }
        }
        return distance
    }
}
```

There's also a neat two-pass method for this exact problem, because a grid with no walls makes distances simple: sweep from the top-left taking the best of the cells above and to the left, then from the bottom-right taking the best of the cells below and to the right. That's dynamic programming, which arrives in Part VII. Multi-source BFS is the method that still works when walls appear.

</Approach>
