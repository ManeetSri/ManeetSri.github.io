Find the largest sum you can get by adding up a run of consecutive elements: a non-empty subarray.

`MaximumSubarraySum.bestSum(in numbers: [Int]) -> Int`

## Examples

| `numbers` | Result | Best run |
| --- | --- | --- |
| `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` | `6` | `[4, -1, 2, 1]` |
| `[3, -1, 4]` | `6` | the whole array |
| `[5, -9, 6]` | `6` | `[6]` |
| `[2, 3, 4]` | `9` | the whole array |
| `[-3, -1, -2]` | `-1` | `[-1]` |

The run must contain at least one element, so when every value is negative, the answer is the largest single value.

## Constraints

- `1 ≤ numbers.count ≤ 100,000`
- `-10⁹ ≤ numbers[i] ≤ 10⁹`, so a sum fits comfortably in an `Int`.
- Trying every subarray is O(n²) at best, about 5 billion sums for the largest input. Aim for O(n).

<Hints>
<Hint>
A brute force tries every start, and for each start extends the end one step at a time, keeping a running sum. That's O(n²): fine as a checker for small arrays.
</Hint>
<Hint>
Think about the best run that **ends** at index `i`. Either it's `numbers[i]` alone, or it's the best run ending at `i - 1` with `numbers[i]` added. Which is bigger?
</Hint>
<Hint>
Keep `current`, the best sum of a run ending here, and `best`, the best seen anywhere. Start both at `numbers[0]`, not at 0, or an all-negative array will wrongly give 0.
</Hint>
</Hints>

## Solutions

<Approach title="Every start, growing end" time="O(n²)" space="O(1)">

For each start, extend the run one element at a time and keep its running sum, so each subarray's sum costs O(1) to update. There are n(n + 1)/2 subarrays, so this is quadratic.

```swift
public static func bestSum(in numbers: [Int]) -> Int {
    var best = Int.min
    for start in numbers.indices {
        var sum = 0
        for end in start..<numbers.count {
            sum += numbers[end]
            best = max(best, sum)
        }
    }
    return best
}
```

</Approach>

<Approach title="Kadane's algorithm" time="O(n)" space="O(1)">

The best run ending at each element either extends the previous run or starts fresh. Extending only helps if the previous run's sum is positive, so `max(number, current + number)` makes the choice. The overall answer is the best of these.

```swift
public enum MaximumSubarraySum {
    public static func bestSum(in numbers: [Int]) -> Int {
        var current = numbers[0]
        var best = numbers[0]
        for number in numbers.dropFirst() {
            current = max(number, current + number)
            best = max(best, current)
        }
        return best
    }
}
```

`numbers[0]` is safe because the array is never empty. If a problem allowed an empty array, or allowed choosing an empty run with sum 0, you'd need to say what to return and handle it before the loop.

</Approach>
