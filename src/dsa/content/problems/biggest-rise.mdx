A sensor records readings in time order. Return the **biggest rise** from an earlier reading to a later one: the largest value of `readings[j] - readings[i]` with `i < j`. If the readings only ever fall, the answer is the smallest fall, which is negative. With fewer than two readings there's no pair at all, so return `nil`.

`BiggestRise.biggestRise(in readings: [Int]) -> Int?`

The direct way checks every pair: about n²/2 subtractions. For 100,000 readings that's 5 billion, far over budget. Find an O(n) solution.

## Examples

| Input | Output | Why |
| --- | --- | --- |
| `[4, 1, 7, 3, 9, 2]` | `8` | from 1 up to 9 |
| `[100, 50, 60, 1]` | `10` | from 50 up to 60; 100 comes before 1, so 99 doesn't count |
| `[9, 7, 4, 1]` | `-2` | always falling: the smallest fall is 9 to 7 |
| `[5, 5, 5]` | `0` | |
| `[42]` | `nil` | no pair |

## Constraints

- `0 ≤ readings.count ≤ 100,000`
- `-10⁹ ≤ readings[i] ≤ 10⁹`

<Hints>
<Hint>
Turn it around: fix the **later** reading, at index j. Which earlier reading gives the biggest rise to it?
</Hint>
<Hint>
The smallest reading before j. So walk from left to right, keeping the smallest reading seen so far, and compare each new reading with it.
</Hint>
<Hint>
Order matters at each step: first compare the current reading with the smallest **earlier** one, then update the smallest. Start `best` at `readings[1] - readings[0]`, not at 0, or all-falling inputs will wrongly give 0.
</Hint>
</Hints>

## Solutions

<Approach title="Brute force: every pair" time="O(n²)" space="O(1)">

Try every earlier index i with every later index j and keep the best difference. It's correct, and a good way to check a faster version on small inputs, but for 100,000 readings it does about 5 × 10⁹ subtractions.

```swift
public static func biggestRise(in readings: [Int]) -> Int? {
    var best: Int?
    for i in 0..<readings.count {
        for j in (i + 1)..<readings.count {
            let rise = readings[j] - readings[i]
            best = max(best ?? rise, rise)
        }
    }
    return best
}
```

</Approach>

<Approach title="One pass, remembering the lowest so far" time="O(n)" space="O(1)">

For each reading, the best rise that *ends* there starts from the lowest reading before it. So one pass is enough, as long as you remember that lowest reading. The inner loop of the brute force was searching for it again and again; one variable replaces the whole loop.

```swift
public enum BiggestRise {
    public static func biggestRise(in readings: [Int]) -> Int? {
        guard readings.count >= 2 else { return nil }
        var lowest = readings[0]
        var best = readings[1] - readings[0]
        for reading in readings.dropFirst() {
            best = max(best, reading - lowest)
            lowest = min(lowest, reading)
        }
        return best
    }
}
```

The differences reach at most 2 × 10⁹ in size, so there's no risk of overflow.

</Approach>
