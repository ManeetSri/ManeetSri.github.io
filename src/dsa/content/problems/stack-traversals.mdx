Return the values of a binary tree in preorder, inorder and postorder again, this time **without recursion**: use a loop and an array as an explicit stack. The tests include chains 100,000 nodes deep, which would overflow the call stack of a recursive version.

`StackTraversals.preorder(_ root: TreeNode?) -> [Int]`, `StackTraversals.inorder(_ root: TreeNode?) -> [Int]` and `StackTraversals.postorder(_ root: TreeNode?) -> [Int]`

The orders are the same as in the recursive problem: node–left–right, left–node–right and left–right–node. Don't change the tree, and don't use DSAKit's `inorder` property.

## Examples

| Tree (level order) | Preorder | Inorder | Postorder |
| --- | --- | --- | --- |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `[1, 2, 4, 5, 7, 3, 6]` | `[4, 2, 7, 5, 1, 3, 6]` | `[4, 7, 5, 2, 6, 3, 1]` |
| `[8, 3, 10, 1, 6, nil, 14, nil, nil, 4, 7, 13]` | `[8, 3, 1, 6, 4, 7, 10, 14, 13]` | `[1, 3, 4, 6, 7, 8, 10, 13, 14]` | `[1, 4, 7, 6, 3, 13, 14, 10, 8]` |
| `[3, 2, nil, 1]` | `[3, 2, 1]` | `[1, 2, 3]` | `[1, 2, 3]` |
| `[]` | `[]` | `[]` | `[]` |

## Constraints

- `0 ≤` number of nodes `≤ 100,000`
- Trees can be 100,000 levels deep. A recursive solution will crash the whole test run with a signal rather than fail politely.

<Hints>
<Hint>
Preorder is the easiest. Start with the root on the stack. Pop a node, record it, then push its children. A stack hands things back in reverse, so push the right child first and the left second.
</Hint>
<Hint>
Inorder: keep a `current` pointer. While `current` isn't `nil`, push it and move to its left child. When you can't go further left, pop a node, record it, and set `current` to its right child. Loop while `current != nil || !stack.isEmpty`.
</Hint>
<Hint>
Postorder, the easy way: preorder with the children pushed the other way round gives node–right–left, and reversing that gives left–right–node. The one-stack way: slide left as in inorder, then peek at the top. If it has a right child you haven't finished yet, go there; otherwise record it and pop it. A `lastVisited` reference, compared with `===`, tells you whether the right child is finished.
</Hint>
</Hints>

## Solutions

<Approach title="One stack each" time="O(n)" space="O(h)">

Each traversal keeps its unfinished work in an array. A deep tree costs heap memory, which is plentiful, instead of call-stack frames, which aren't.

```swift
public enum StackTraversals {
    public static func preorder(_ root: TreeNode?) -> [Int] {
        var result: [Int] = []
        var stack = [root].compactMap { $0 }
        while let node = stack.popLast() {
            result.append(node.value)
            if let right = node.right { stack.append(right) }
            if let left = node.left { stack.append(left) }
        }
        return result
    }

    public static func inorder(_ root: TreeNode?) -> [Int] {
        var result: [Int] = []
        var stack: [TreeNode] = []
        var current = root
        while current != nil || !stack.isEmpty {
            while let node = current {                // everything down the left edge waits its turn
                stack.append(node)
                current = node.left
            }
            let node = stack.removeLast()             // its left subtree is done
            result.append(node.value)
            current = node.right
        }
        return result
    }

    public static func postorder(_ root: TreeNode?) -> [Int] {
        var result: [Int] = []
        var stack: [TreeNode] = []
        var current = root
        var lastVisited: TreeNode? = nil
        while current != nil || !stack.isEmpty {
            while let node = current {
                stack.append(node)
                current = node.left
            }
            let top = stack[stack.count - 1]          // left subtree done; what about the right?
            if let right = top.right, right !== lastVisited {
                current = right                       // not started yet: go and do it
            } else {
                result.append(top.value)              // no right subtree, or just finished it
                lastVisited = top
                stack.removeLast()
            }
        }
        return result
    }
}
```

In postorder, a node's right child is always the last node recorded before the node itself, so `right !== lastVisited` means "the right subtree hasn't been done yet".

</Approach>

<Approach title="Postorder as a reversed preorder" time="O(n)" space="O(n)">

Run preorder but push the left child before the right, so it records node–right–left. Reversed, that's exactly left–right–node. The second "stack" is the result array, read backwards.

```swift
public static func postorder(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack = [root].compactMap { $0 }
    while let node = stack.popLast() {
        result.append(node.value)
        if let left = node.left { stack.append(left) }
        if let right = node.right { stack.append(right) }
    }
    return result.reversed()
}
```

Short and hard to get wrong. Its drawback is that it can't hand out values one at a time as it goes, because nothing is in the right order until the end.

</Approach>

<Approach title="A ready flag for any order" time="O(n)" space="O(h)">

Push each node twice: once to expand it and once, marked ready, to record it. Where the ready entry goes among the children decides the order, so one loop does all three; this one is postorder.

```swift
public static func postorder(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    var stack: [(node: TreeNode, ready: Bool)] = root.map { [($0, false)] } ?? []
    while let (node, ready) = stack.popLast() {
        if ready {
            result.append(node.value)
            continue
        }
        stack.append((node, true))                    // comes off after both children
        if let right = node.right { stack.append((right, false)) }
        if let left = node.left { stack.append((left, false)) }
    }
    return result
}
```

For inorder, push the right child, then the ready entry, then the left child. For preorder, push the ready entry last.

</Approach>
