A hiking app records the change in height over each stretch of a trail, in metres. Return the largest total change over a non-empty run of consecutive stretches: the trail's best climb. Solve it by divide and conquer, splitting the stretches in half.

`CrossingSumSubarray.bestSum(_ numbers: [Int]) -> Int`

## Examples

| `numbers` | Output | Best run |
| --- | --- | --- |
| `[4, -6, 3, 5, -1, 2, -8, 4]` | `9` | `[3, 5, -1, 2]` |
| `[-7, -3, -9]` | `-3` | `[-3]` |
| `[5]` | `5` | `[5]` |
| `[2, -1, 2, -1, 2]` | `4` | the whole trail |
| `[-2, 6, -9, 6, -2]` | `6` | either `[6]` |

The run must contain at least one stretch, so on a trail that only goes down, the answer is the gentlest single drop.

## Constraints

- `1 ≤ numbers.count ≤ 100,000`
- `-10,000 ≤ numbers[i] ≤ 10,000`
- The tests compare your answer with Kadane's on arrays of up to 100,000 values, so trying every run (O(n²)) is too slow.

<Hints>
<Hint>
Split at the middle. The best run is entirely in the left half, entirely in the right half, or it crosses the middle. The first two are the same problem on half the array.
</Hint>
<Hint>
A crossing run is the best run that **ends** at `mid - 1` plus the best run that **starts** at `mid`. Find each with one scan outwards from the middle, keeping the best running sum.
</Hint>
<Hint>
Start each scan's best from the element next to the middle, not from 0, or a "crossing" run could be empty and an all-negative trail would give 0. A range of one element is its own answer.
</Hint>
</Hints>

## Solutions

<Approach title="Crossing sums" time="O(n log n)" space="O(log n)">

Recurse on both halves, compute the crossing sum with two outward scans, and return the largest of the three. Each level of the recursion scans every element once, and there are about log₂ n levels.

```swift
public enum CrossingSumSubarray {
    public static func bestSum(_ numbers: [Int]) -> Int {
        bestSum(numbers, 0, numbers.count)
    }

    private static func bestSum(_ numbers: [Int], _ low: Int, _ high: Int) -> Int {
        if high - low == 1 {
            return numbers[low]
        }
        let mid = low + (high - low) / 2
        var sum = 0
        var bestLeft = numbers[mid - 1]
        for index in stride(from: mid - 1, through: low, by: -1) {
            sum += numbers[index]
            bestLeft = max(bestLeft, sum)
        }
        sum = 0
        var bestRight = numbers[mid]
        for index in mid..<high {
            sum += numbers[index]
            bestRight = max(bestRight, sum)
        }
        return max(bestSum(numbers, low, mid), bestSum(numbers, mid, high), bestLeft + bestRight)
    }
}
```

The space is the recursion stack: about log₂ n calls deep, because every call halves its range.

</Approach>

<Approach title="Four-number summaries" time="O(n)" space="O(log n)">

Make each call return its range's total, best prefix, best suffix and best run. Two summaries combine in O(1), so the recurrence drops to T(n) = 2T(n/2) + 1.

```swift
public enum CrossingSumSubarray {
    private struct Summary {
        let total: Int, prefix: Int, suffix: Int, best: Int
    }

    public static func bestSum(_ numbers: [Int]) -> Int {
        summarise(numbers, 0, numbers.count).best
    }

    private static func summarise(_ numbers: [Int], _ low: Int, _ high: Int) -> Summary {
        if high - low == 1 {
            let value = numbers[low]
            return Summary(total: value, prefix: value, suffix: value, best: value)
        }
        let mid = low + (high - low) / 2
        let left = summarise(numbers, low, mid)
        let right = summarise(numbers, mid, high)
        return Summary(
            total: left.total + right.total,
            prefix: max(left.prefix, left.total + right.prefix),
            suffix: max(right.suffix, right.total + left.suffix),
            best: max(left.best, right.best, left.suffix + right.prefix)
        )
    }
}
```

Kadane's single pass, from [Maximum subarray sum](/dsa/practice/maximum-subarray-sum), is also O(n) and needs no recursion at all. The summary version's strength is that summaries of separate blocks can be combined in any grouping.

</Approach>
