A print server runs one job per time slot. Each job has a **kind**, such as `"report"` or `"photo"`, and two jobs of the same kind need at least `cooldown` slots between them: other jobs, or idle slots when nothing is allowed to run. The jobs can run in any order. Return the fewest slots needed to run every job, counting idle slots.

`CooldownScheduler.fewestSlots(_ jobs: [String], cooldown: Int) -> Int`

## Examples

Single letters stand for kinds here, so `"AAABBB"` means `["A", "A", "A", "B", "B", "B"]`.

| `jobs` | `cooldown` | Returns | One best order |
| --- | --- | --- | --- |
| `"AAABBB"` | `2` | `8` | A B _ A B _ A B |
| `"AAABBB"` | `0` | `6` | A A A B B B |
| `"AAAABC"` | `2` | `10` | A B C A _ _ A _ _ A |
| `"AAABBBCCD"` | `2` | `9` | A B C A B C A B D |
| `"AA"` | `5` | `7` | A _ _ _ _ _ A |
| `["report", "photo", "report", "invoice", "report"]` | `1` | `5` | report photo report invoice report |

## Constraints

- `0 ≤ jobs.count ≤ 100,000`, with up to 100,000 different kinds.
- `0 ≤ cooldown ≤ 100`

<Hints>
<Hint>
Think about the kind with the most jobs. Its jobs must be spread out, so it decides how long the schedule has to be. Which kind should run next, when several are allowed?
</Hint>
<Hint>
Greedy: in each slot, run the allowed kind with the **most jobs left**. Keep the allowed kinds' counts in a max-heap. A kind that has just run waits in a queue, with the slot when it's allowed again.
</Hint>
<Hint>
Kinds join the waiting queue in the order they ran, so the queue is sorted by ready time: before each slot, move every ready kind from the front of the queue back into the heap. If the heap is empty but the queue isn't, the server idles: jump straight to the front's ready slot.
</Hint>
</Hints>

## Solutions

<Approach title="Simulate with a heap and a waiting queue" time="O(n log m)" space="O(m)">

For n jobs of m kinds. Kind names only matter for counting, so the heap holds plain counts.

```swift
import DSAKit

public enum CooldownScheduler {
    public static func fewestSlots(_ jobs: [String], cooldown: Int) -> Int {
        var remaining: [String: Int] = [:]
        for job in jobs {
            remaining[job, default: 0] += 1
        }
        var ready = Heap.maxHeap(remaining.values)       // jobs left per allowed kind
        var cooling = Deque<(left: Int, readyAt: Int)>()
        var slot = 0                                     // the next slot to fill
        while !ready.isEmpty || !cooling.isEmpty {
            if ready.isEmpty, let next = cooling.first, next.readyAt > slot {
                slot = next.readyAt                      // idle until a kind is allowed again
            }
            while let next = cooling.first, next.readyAt <= slot {
                ready.insert(next.left)
                cooling.popFirst()
            }
            let left = ready.pop()! - 1                  // run one job of the busiest kind
            if left > 0 {
                cooling.append((left, slot + cooldown + 1))
            }
            slot += 1
        }
        return slot
    }
}
```

</Approach>

<Approach title="Count the frame of the busiest kind" time="O(n)" space="O(m)">

Say the busiest kind has `most` jobs, and `busiest` kinds have that many. Lay its jobs out with `cooldown` slots after each, except the last: that's `most - 1` frames of `cooldown + 1` slots, followed by one slot for each of the busiest kinds. Every other job fits into the gaps. If there are more jobs than gaps, no idle slot is needed at all, and the answer is simply the number of jobs.

```swift
public static func fewestSlots(_ jobs: [String], cooldown: Int) -> Int {
    let counts = Dictionary(jobs.map { ($0, 1) }, uniquingKeysWith: +).values
    guard let most = counts.max() else { return 0 }
    let busiest = counts.filter { $0 == most }.count
    return max(jobs.count, (most - 1) * (cooldown + 1) + busiest)
}
```

The formula is shorter, but the simulation is the one that adapts when the rules change, for example when you need the actual order.

</Approach>
