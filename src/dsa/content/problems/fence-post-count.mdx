A fence has a post every metre, including one at each end. Work out how many posts two kinds of fence need. The arithmetic is tiny; the real task is the **comment**. Each answer hides a reason that the code alone can't show, which is exactly what a comment is for.

- `FencePostCount.straight(metres: Int) -> Int` returns the posts for a straight fence `metres` long.
- `FencePostCount.closedPen(length: Int, width: Int) -> Int` returns the posts for a rectangular pen, fenced all the way round.

Start by reading the doc comments (`///`) in the exercise file: they're the specification. When your answers pass, add a short comment beside each one explaining **why** it isn't simply the number of metres. The tests can't check comments, so compare yours with the ones in the solutions.

## Examples

| Call | Returns | Why |
| --- | --- | --- |
| `straight(metres: 3)` | `4` | posts at 0, 1, 2 and 3 metres |
| `straight(metres: 1)` | `2` | one at each end |
| `closedPen(length: 3, width: 2)` | `10` | 10 metres of fence all the way round |
| `closedPen(length: 1, width: 1)` | `4` | one post at each corner |

## Constraints

- `1 ≤ metres, length, width ≤ 1,000,000`
- Every length is a whole number of metres, so posts always land exactly on the corners of a pen.

## Solutions

<Approach title="Count the gaps, then explain why" time="O(1)" space="O(1)">

Each line of code is short, and each comment says something the code can't: where the extra post comes from, and why the pen doesn't get one.

```swift
public enum FencePostCount {
    public static func straight(metres: Int) -> Int {
        return metres + 1 // each metre is a gap between two posts, so there's one post more than metres
    }

    public static func closedPen(length: Int, width: Int) -> Int {
        // The fence ends where it started, so the last gap reuses the first post: posts = metres round.
        return 2 * (length + width)
    }
}
```

Compare those comments with ones that only repeat the code:

```swift
return metres + 1 // add one to metres
return 2 * (length + width) // multiply the sum by 2
```

They're accurate but useless: anyone reading the code can already see the `+ 1`. The good comments answer the question a reader would actually ask, "why one more?", and would save someone from "fixing" the `+ 1` away.

</Approach>
