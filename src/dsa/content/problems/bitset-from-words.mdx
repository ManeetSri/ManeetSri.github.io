Swift's standard library has no bitset, so build one: a set of the numbers `0..<capacity` stored one bit each in `UInt64` words, with whole-set operations that work 64 numbers at a time. Then use it to find every total a subset of weights can make.

`BitSetFromWords.Bits`, a struct with `init(capacity:)`, `capacity`, `words`, `insert(_:)`, `remove(_:)`, `contains(_:)`, `count`, `elements`, `next(atOrAfter:)`, `formUnion(_:)`, `formIntersection(_:)`, `subtract(_:)` and `shiftedUp(by:)`; plus `BitSetFromWords.reachableSums(weights:limit:) -> [Int]`

- **Layout.** `words` has `(capacity + 63) / 64` elements. Number x is bit `x % 64` of `words[x / 64]`. Bits past `capacity` in the last word are always 0.
- `insert(_:)` and `remove(_:)` take a number in `0..<capacity`; removing a number that isn't there does nothing. `contains(_:)` is `false` for any number outside `0..<capacity`.
- `count` is the number of members; `elements` lists them in increasing order.
- `next(atOrAfter: x)` returns the smallest member ≥ x, or `nil`. x may be negative or past the end.
- `formUnion`, `formIntersection` and `subtract` change the set in place, using another set with the same capacity.
- `shiftedUp(by: s)` (s ≥ 0) returns a set with the same capacity in which every member x becomes x + s; members that would reach `capacity` or beyond are dropped.
- `reachableSums(weights:limit:)` returns every total from 0 to `limit` that some subset of the weights adds up to, each weight used at most once, in increasing order. The empty subset makes 0. Weights are positive.

## Examples

| Code | Result |
| --- | --- |
| `words` after inserting 0, 5, 63, 64, 130 and 199 into `Bits(capacity: 200)` | `[0x8000_0000_0000_0021, 1, 4, 128]` |
| members 60 and 130 of a capacity-200 set, `shiftedUp(by: 10)` | members 70 and 140 |
| the same set, `shiftedUp(by: 70)` | member 130 (200 falls off the end) |
| `next(atOrAfter: 66)` on members 3, 64, 65 and 200 (capacity 300) | `200` |
| `reachableSums(weights: [3, 5, 7, 11], limit: 30)` | `[0, 3, 5, 7, 8, 10, 11, 12, 14, 15, 16, 18, 19, 21, 23, 26]` |
| `reachableSums(weights: [2, 2, 2], limit: 10)` | `[0, 2, 4, 6]` |

## Constraints

- `0 ≤ capacity ≤ 10,000,000`.
- Set operations, `count` and `elements` should cost O(capacity / 64) word operations (plus one step per member for `elements`), not O(capacity).
- The tests run `reachableSums` on 2,000 weights with a limit of 100,000. A `Set<Int>` of reachable totals would make hundreds of millions of insertions.

<Hints>
<Hint>
`x >> 6` is x / 64 and `x & 63` is x % 64. Set a bit with `|= 1 << UInt64(x & 63)`, clear it with `&= ~(1 << UInt64(x & 63))`, and test it with `&` and `!= 0`. Union, intersection and difference are `|`, `&` and `& ~`, word by word.
</Hint>
<Hint>
For `elements` and `next(atOrAfter:)`, jump between set bits: `word.trailingZeroBitCount` is the position of the lowest set bit, and `word &= word - 1` clears it. In `next`, mask off the bits below x in its first word with `word & (~0 << UInt64(x & 63))`, then move on to whole words.
</Hint>
<Hint>
Shifting by s moves each word `s >> 6` places up, shifted left by `b = s & 63` bits, and ORs in the top b bits of the word below it, `below >> (64 - b)`. When b is 0 there's nothing to carry: skip it, or rely on Swift's `>>`, which gives 0 for a shift of 64 (the masking `&>>` does not). Afterwards, clear the bits past `capacity` in the last word. Subset sums: start with a set holding only 0 and, for each weight w, OR the set with itself shifted up by w.
</Hint>
</Hints>

## Solutions

<Approach title="Set of totals" time="O(n · limit)" space="O(limit)">

Keep a `Set<Int>` of reachable totals and, for each weight, add `total + w` for every total so far that stays within the limit. It's the same idea as the bitset version, one total at a time, with hashing for each: with 2,000 weights and 100,000 possible totals, that's up to 200 million insertions.

</Approach>

<Approach title="Bitset of UInt64 words" time="O(capacity / 64) per set operation; O(n · limit / 64) for subset sums" space="O(capacity / 64)">

Each word operation handles 64 numbers, and subset sums become one shift and one OR per weight.

```swift
public enum BitSetFromWords {
    public struct Bits: Equatable {
        public let capacity: Int
        public private(set) var words: [UInt64]

        public init(capacity: Int) {
            self.capacity = max(0, capacity)
            words = Array(repeating: 0, count: (self.capacity + 63) / 64)
        }

        public mutating func insert(_ x: Int) {
            precondition(x >= 0 && x < capacity, "\(x) is outside 0..<\(capacity)")
            words[x >> 6] |= 1 << UInt64(x & 63)
        }

        public mutating func remove(_ x: Int) {
            precondition(x >= 0 && x < capacity, "\(x) is outside 0..<\(capacity)")
            words[x >> 6] &= ~(1 << UInt64(x & 63))
        }

        public func contains(_ x: Int) -> Bool {
            x >= 0 && x < capacity && words[x >> 6] & (1 << UInt64(x & 63)) != 0
        }

        public var count: Int {
            words.reduce(0) { $0 + $1.nonzeroBitCount }
        }

        public var elements: [Int] {
            var result: [Int] = []
            for (i, word) in words.enumerated() {
                var rest = word
                while rest != 0 {
                    result.append(i << 6 + rest.trailingZeroBitCount)
                    rest &= rest - 1
                }
            }
            return result
        }

        public func next(atOrAfter x: Int) -> Int? {
            let start = max(0, x)
            guard start < capacity else { return nil }
            var i = start >> 6
            var word = words[i] & (~0 << UInt64(start & 63))     // ignore bits below start
            while true {
                if word != 0 { return i << 6 + word.trailingZeroBitCount }
                i += 1
                guard i < words.count else { return nil }
                word = words[i]
            }
        }

        public mutating func formUnion(_ other: Bits) {
            precondition(capacity == other.capacity, "Capacities must match")
            for i in words.indices { words[i] |= other.words[i] }
        }

        public mutating func formIntersection(_ other: Bits) {
            precondition(capacity == other.capacity, "Capacities must match")
            for i in words.indices { words[i] &= other.words[i] }
        }

        public mutating func subtract(_ other: Bits) {
            precondition(capacity == other.capacity, "Capacities must match")
            for i in words.indices { words[i] &= ~other.words[i] }
        }

        public func shiftedUp(by s: Int) -> Bits {
            precondition(s >= 0, "Shift by a non-negative amount")
            var result = Bits(capacity: capacity)
            let wordShift = s >> 6
            let bitShift = UInt64(s & 63)
            guard wordShift < words.count else { return result }
            for i in stride(from: words.count - 1, through: wordShift, by: -1) {
                var word = words[i - wordShift] << bitShift
                if bitShift > 0 && i - wordShift > 0 {
                    word |= words[i - wordShift - 1] >> (64 - bitShift)
                }
                result.words[i] = word
            }
            let spare = words.count * 64 - capacity
            if spare > 0 {
                result.words[words.count - 1] &= ~UInt64(0) >> UInt64(spare)
            }
            return result
        }
    }

    public static func reachableSums(weights: [Int], limit: Int) -> [Int] {
        guard limit >= 0 else { return [] }
        var reachable = Bits(capacity: limit + 1)
        reachable.insert(0)
        for weight in weights where weight <= limit {
            reachable.formUnion(reachable.shiftedUp(by: weight))
        }
        return reachable.elements
    }
}
```

`i << 6 + t` reads as `(i << 6) + t`: in Swift, shifts bind more tightly than addition, the opposite of C. The shift loop runs from the top word down, but since it writes into a fresh `result`, the order doesn't matter here; shifting **in place** would need the top-down order, so each word is read before it's overwritten.

</Approach>
