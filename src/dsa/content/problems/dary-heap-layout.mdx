A network router's event queue does far more inserts than pops, so it uses a **d-ary min-heap**: every node has up to d children, which makes the tree shorter and inserts cheaper. Build one, following the rules below exactly, because the tests check the array itself after every operation.

`DaryHeapLayout.DaryMinHeap`, a struct with `init(arity:)`, `init(arity:items:)`, `count`, `storage`, `peek()`, `push(_:)` and `pop()`.

The heap is stored level by level in `storage`, 0-based. The children of index i are `d * i + 1` through `d * i + d`, and the parent of i > 0 is `(i - 1) / d`.

- **push:** append the value, then **sift up**: while it's strictly smaller than its parent, swap them.
- **pop:** return `nil` if empty. Otherwise swap the root with the last element, remove and return the last (the old root), then **sift down** from the root: find the smallest of the node's children (the leftmost if several tie), and if it's strictly smaller than the node, swap them and continue from there.
- **init(arity:items:)** builds the heap in O(n) by bottom-up heapify: copy `items`, then sift down every index that has children, from the last parent, `(count - 2) / d`, back to 0.
- **peek()** returns the root, or `nil`.

## Examples

| Code | `storage` afterwards | Result |
| --- | --- | --- |
| `var h = DaryMinHeap(arity: 3)`; push 9, 7, 8, 6 | `[6, 9, 8, 7]` | 7 rose above 9, then 6 rose above 7; the root has three children |
| then push 5 | `[5, 6, 8, 7, 9]` | 5 lands at index 4, under 9, and rises twice |
| then `pop()` | `[6, 9, 8, 7]` | returns `5`; 9 moves to the root and swaps with its smallest child, 6 |
| `DaryMinHeap(arity: 4, items: [9, 3, 7, 1, 8, 2])` | `[1, 2, 7, 9, 8, 3]` | index 1 sifts down first, then the root |
| `DaryMinHeap(arity: 2)` then `pop()` and `peek()` | `[]` | both `nil` |

## Constraints

- `2 ≤ arity ≤ 16`, values can be any `Int`, duplicates allowed.
- Up to 200,000 operations; `init(arity:items:)` gets up to 200,000 items and must be O(n).
- It's a struct, so copies must be independent.

<Hints>
<Hint>
Only the index maths changes from a binary heap: replace every 2 with `d`. The first child of i is `d * i + 1`, and the children run up to `min(d * i + d, count - 1)`. A node has children exactly when `d * i + 1 < count`.
</Hint>
<Hint>
For sift down, scan the children with a loop, keeping the index of the smallest so far and replacing it only when a child is **strictly** smaller: that's what makes the leftmost win a tie. Then compare that child with the node, again strictly.
</Hint>
<Hint>
For the heapify, the last element's parent, `(count - 2) / d`, is the last index with any children. Sift down from there back to 0. Guard against `count < 2`, where there's nothing to do (and `(count - 2) / d` would be 0 or negative).
</Hint>
</Hints>

## Solutions

<Approach title="A d-ary heap in an array" time="O(log_d n) push, O(d log_d n) pop, O(n) build" space="O(n)">

Sift up compares with one parent per level, and there are only about log_d n levels, so a bigger d makes pushes cheaper. Sift down compares d children per level, so pops get dearer. Bottom-up heapify is O(n) for any d, for the same reason as in a binary heap: most nodes are near the bottom, where sift down has little distance to travel.

```swift
public enum DaryHeapLayout {
    public struct DaryMinHeap {
        public let arity: Int
        public private(set) var storage: [Int] = []

        public init(arity: Int) {
            self.arity = arity
        }

        public init(arity: Int, items: [Int]) {
            self.arity = arity
            storage = items
            guard storage.count >= 2 else { return }
            for index in stride(from: (storage.count - 2) / arity, through: 0, by: -1) {
                siftDown(from: index)
            }
        }

        public var count: Int { storage.count }

        public func peek() -> Int? { storage.first }

        public mutating func push(_ value: Int) {
            storage.append(value)
            var child = storage.count - 1
            while child > 0 {
                let parent = (child - 1) / arity
                guard storage[child] < storage[parent] else { return }
                storage.swapAt(child, parent)
                child = parent
            }
        }

        public mutating func pop() -> Int? {
            guard !storage.isEmpty else { return nil }
            storage.swapAt(0, storage.count - 1)
            let top = storage.removeLast()
            siftDown(from: 0)
            return top
        }

        private mutating func siftDown(from start: Int) {
            var parent = start
            while true {
                let firstChild = arity * parent + 1
                guard firstChild < storage.count else { return }
                var smallest = firstChild                    // the leftmost smallest child
                for child in (firstChild + 1)..<Swift.min(firstChild + arity, storage.count)
                where storage[child] < storage[smallest] {
                    smallest = child
                }
                guard storage[smallest] < storage[parent] else { return }
                storage.swapAt(parent, smallest)
                parent = smallest
            }
        }
    }
}
```

With d = 4, a node's children sit side by side in the array, so finding the smallest touches one small block of memory, which is a large part of why 4-ary heaps are popular in practice.

</Approach>
