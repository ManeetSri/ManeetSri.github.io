Given an array of integers, which may include negatives and zeros, answer two questions about its **subarrays**, the non-empty runs of neighbouring elements:

1. How many subarrays add up to exactly `target`?
2. How long is the longest subarray that adds up to exactly `target`? Return `0` if there's none.

`TargetSumSubarrays.count(in numbers: [Int], summingTo target: Int) -> Int`

`TargetSumSubarrays.longest(in numbers: [Int], summingTo target: Int) -> Int`

## Examples

| `numbers` | `target` | `count` | `longest` |
| --- | --- | --- | --- |
| `[1, 2, -1, 3, -2, 2]` | `3` | `4` | `5` |
| `[1, -1, 1, -1]` | `0` | `4` | `4` |
| `[4, -3, 2]` | `3` | `1` | `3` |
| `[0, 0, 0]` | `0` | `6` | `3` |
| `[2, 2, 2]` | `5` | `0` | `0` |
| `[]` | `0` | `0` | `0` |

In the first example, the four subarrays are `[1, 2]`, `[1, 2, -1, 3, -2]`, `[3]` and `[3, -2, 2]`. The longest is the second, with 5 elements. Two subarrays at different positions count separately even if they hold the same values.

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- `-10⁴ ≤ numbers[i] ≤ 10⁴` and `-10⁹ ≤ target ≤ 10⁹`
- Both answers fit in an `Int`. Aim for O(n) time for each function.

<Hint>
Write the O(n²) version first: for every start, extend the end one step at a time with a running sum. Keep it to test the fast version against. Then notice that a sliding window can't work here, because the numbers can be negative.
</Hint>
<Hint>
A subarray from position `i` to position `j` sums to `target` when `prefix[j] - prefix[i] == target`, so `prefix[i] == prefix[j] - target`. Walking left to right, the subarrays ending here correspond to earlier prefix values equal to `running - target`.
</Hint>
<Hint>
For `count`, keep a dictionary from prefix value to how many times you've seen it, starting with `[0: 1]`. Look up `running - target` before recording `running`. For `longest`, store the **first** position where each prefix value appeared instead, starting with `[0: 0]`, and never overwrite an entry.
</Hint>
</Hints>

## Solutions

<Approach title="Every start, extending the end" time="O(n²)" space="O(1)">

From each start, keep a running sum while the end moves right, so every subarray is checked in O(1). This is the brute force to test against.

```swift
public static func count(in numbers: [Int], summingTo target: Int) -> Int {
    var total = 0
    for start in numbers.indices {
        var sum = 0
        for end in start..<numbers.count {
            sum += numbers[end]
            if sum == target {
                total += 1
            }
        }
    }
    return total
}
```

`longest` is the same loop, keeping the largest `end - start + 1` instead of counting.

</Approach>

<Approach title="Prefix sums and a dictionary" time="O(n)" space="O(n)">

A subarray ending at the current position sums to `target` exactly when an earlier prefix value equals `running - target`. For the count, the dictionary records how many times each prefix value has appeared. The seed `[0: 1]` is the empty prefix, which matches subarrays starting at index 0. Looking up before recording stops the current prefix from pairing with itself.

For the longest, the dictionary records where each prefix value **first** appeared, as a prefix position (the number of elements consumed), so the seed is `[0: 0]`. An earlier start means a longer subarray, so a value that comes up again keeps its first position.

```swift
public enum TargetSumSubarrays {
    public static func count(in numbers: [Int], summingTo target: Int) -> Int {
        var seen: [Int: Int] = [0: 1]
        var running = 0
        var total = 0
        for value in numbers {
            running += value
            total += seen[running - target, default: 0]
            seen[running, default: 0] += 1
        }
        return total
    }

    public static func longest(in numbers: [Int], summingTo target: Int) -> Int {
        var firstSeen: [Int: Int] = [0: 0]
        var running = 0
        var best = 0
        for (index, value) in numbers.enumerated() {
            running += value
            let end = index + 1
            if let start = firstSeen[running - target] {
                best = max(best, end - start)
            }
            if firstSeen[running] == nil {
                firstSeen[running] = end
            }
        }
        return best
    }
}
```

With all zeros and a target of 0, every one of the n(n + 1)/2 subarrays counts: that's why the count needs an `Int`, and why the dictionary stores counts rather than a yes or no.

</Approach>
