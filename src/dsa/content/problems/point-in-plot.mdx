A farm's plot is a simple polygon on a map, and a list of sensors has been placed around it. For each sensor, report whether it's inside the plot, on its boundary, or outside.

`PlotPointLocator.locate(_ plot: [[Int]], _ queries: [[Int]]) -> [Int]`

`plot` lists the corners in order, clockwise or counterclockwise, each as `[x, y]`, and closes from the last corner back to the first. Return one number per query, in the same order: `1` strictly inside, `0` on the boundary (an edge or a corner), `-1` outside.

## Examples

The plot `[[0, 0], [6, 0], [6, 5], [4, 5], [4, 2], [2, 2], [2, 5], [0, 5]]` is U-shaped: two arms of height 5 with a notch between x = 2 and x = 4 above y = 2.

| Query | Output | Why |
| --- | --- | --- |
| `[1, 1]` | `1` | in the left arm |
| `[3, 3]` | `-1` | in the notch |
| `[3, 2]` | `0` | on the bottom of the notch |
| `[6, 5]` | `0` | a corner |
| `[3, 5]` | `-1` | level with the tops of both arms, in the notch |
| `[-1, 2]` | `-1` | level with the notch's bottom edge, outside |
| `[5, 2]` | `1` | in the right arm |

So `locate(plot, [[1, 1], [3, 3], [3, 2], [6, 5], [3, 5], [-1, 2], [5, 2]])` returns `[1, -1, 0, 0, -1, -1, 1]`.

## Constraints

- `3 ≤ plot.count ≤ 2,000` and `0 ≤ queries.count ≤ 2,000`
- `-10⁹ ≤ x, y ≤ 10⁹` for corners and queries
- The plot doesn't cross or touch itself, encloses a positive area, and no two consecutive corners are the same.
- A test puts queries about 3.5 × 10⁻¹⁰ to either side of a long edge, so computing crossing points as `Double`s isn't precise enough.

<Hints>
<Hint>
Deal with the boundary first: a query is on an edge when its orientation relative to the edge is 0 and it lies inside the edge's bounding box.
</Hint>
<Hint>
Otherwise, cast a ray from the query to the right and count the edges it crosses: odd means inside. To handle rays through corners and along horizontal edges, count an edge only when exactly one of its ends is strictly above the query: `(a.y > p.y) != (b.y > p.y)`.
</Hint>
<Hint>
Is the crossing to the right of the query? For an edge going up, exactly when the query is to the edge's left (positive orientation); for an edge going down, exactly when it's to the right. No division needed.
</Hint>
</Hints>

## Solutions

<Approach title="Ray casting with a Double crossing point" time="O(n · q)" space="O(q)">

Compute where each straddling edge meets the ray's line, `a.x + (p.y - a.y) * (b.x - a.x) / (b.y - a.y)`, as a `Double`, and compare it with `p.x`. The structure is right, but near 10⁹ neighbouring `Double`s are about 10⁻⁷ apart, so a query a fraction of a unit from an edge can land on the wrong side.

</Approach>

<Approach title="Ray casting with exact orientation" time="O(n · q)" space="O(q)">

The same ray, with the "is it to the right?" question answered by the sign of an `Int` cross product. Each product of coordinate differences is at most 4 × 10¹⁸, so the cross product fits.

```swift
public enum PlotPointLocator {
    struct Point {
        var x: Int
        var y: Int
    }

    static func place(of p: Point, in polygon: [Point]) -> Int {
        var inside = false
        var a = polygon[polygon.count - 1]
        for b in polygon {
            let cross = (b.x - a.x) * (p.y - a.y) - (b.y - a.y) * (p.x - a.x)
            if cross == 0 && min(a.x, b.x) <= p.x && p.x <= max(a.x, b.x)
                && min(a.y, b.y) <= p.y && p.y <= max(a.y, b.y) {
                return 0                                    // on this edge
            }
            if (a.y > p.y) != (b.y > p.y) && (b.y > a.y) == (cross > 0) {
                inside.toggle()                             // the edge crosses the ray to the right of p
            }
            a = b
        }
        return inside ? 1 : -1
    }

    public static func locate(_ plot: [[Int]], _ queries: [[Int]]) -> [Int] {
        let polygon = plot.map { Point(x: $0[0], y: $0[1]) }
        return queries.map { place(of: Point(x: $0[0], y: $0[1]), in: polygon) }
    }
}
```

Starting `a` at the last corner makes the loop cover the closing edge without any index arithmetic. In the straddling branch the cross product is never 0, since a query on that edge's line within its height would already have been reported as on the boundary.

</Approach>
