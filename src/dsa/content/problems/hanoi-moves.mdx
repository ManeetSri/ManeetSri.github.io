Three pegs stand in a row, numbered 1, 2 and 3. Peg 1 holds a stack of disks, numbered 1 (the smallest, on top) to `disks` (the largest, at the bottom). Return the shortest list of moves that carries the whole stack to peg 3, following the rules:

- Move one disk at a time, always the top disk of a peg.
- Never put a disk on top of a smaller one.

`HanoiMoves.moves(disks: Int) -> [Move]`

```swift
public struct Move: Equatable {
    public let disk: Int    // which disk moves
    public let from: Int    // the peg it leaves: 1, 2 or 3
    public let to: Int      // the peg it lands on
}
```

The `Move` type is already written in the exercise file, with an initialiser `Move(disk:from:to:)`. The tests replay your moves on three pegs and check that every move is legal, that all the disks end up on peg 3, and that you used the fewest possible moves, 2ⁿ − 1 for n disks.

## Examples

| `disks` | Moves |
| --- | --- |
| `0` | none |
| `1` | disk 1: 1 → 3 |
| `2` | disk 1: 1 → 2, disk 2: 1 → 3, disk 1: 2 → 3 |
| `3` | disk 1: 1 → 3, disk 2: 1 → 2, disk 1: 3 → 2, disk 3: 1 → 3, disk 1: 2 → 1, disk 2: 2 → 3, disk 1: 1 → 3 |

## Constraints

- `0 ≤ disks ≤ 16`, so at most 65,535 moves.

<Hints>
<Hint>
Don't think about individual moves. Think about the largest disk. It has to move from peg 1 to peg 3 at some point, and at that moment every other disk must be out of the way, on the spare peg.
</Hint>
<Hint>
So: move `disks - 1` disks from the start peg to the spare peg, move the largest disk, then move the `disks - 1` disks from the spare peg onto it. The two smaller jobs are the same problem with different pegs. Write a helper that takes the number of disks and all three pegs: `from`, `to` and `via`.
</Hint>
<Hint>
The base case is zero disks: do nothing. Keep one `result` array outside the helper and append each move to it, rather than joining arrays returned by each call. The disk moved in the middle step of `solve(n, …)` is disk `n`.
</Hint>
</Hints>

## Solutions

<Approach title="Recursion on the largest disk" time="O(2ⁿ)" space="O(n)">

The helper `solve(n, from:to:via:)` moves the top `n` disks of peg `from` to peg `to`, using `via` as the spare. It clears the way, moves disk `n`, and rebuilds on top of it. Notice how the pegs swap roles in the two recursive calls.

The running time is exponential, but that's unavoidable: the answer itself has 2ⁿ − 1 moves, and you have to produce every one. Since the moves follow moves(n) = 2 × moves(n − 1) + 1, no shorter list exists. The recursion is only n deep, one frame per disk.

```swift
public static func moves(disks: Int) -> [Move] {
    var result: [Move] = []
    func solve(_ n: Int, from: Int, to: Int, via: Int) {
        if n == 0 {
            return                                      // nothing to move
        }
        solve(n - 1, from: from, to: via, via: to)      // clear the way
        result.append(Move(disk: n, from: from, to: to))
        solve(n - 1, from: via, to: to, via: from)      // stack them back on top
    }
    solve(disks, from: 1, to: 3, via: 2)
    return result
}
```

</Approach>

<Approach title="The same recursion, returning arrays" time="O(n × 2ⁿ)" space="O(2ⁿ)">

You can also have each call return its own list of moves and join them: the moves for n − 1 disks, then the big move, then the moves for the other n − 1. It reads closer to the three-sentence description, but every level copies all the moves below it into a new array, which adds a factor of n.

```swift
public static func moves(disks: Int) -> [Move] {
    func solve(_ n: Int, from: Int, to: Int, via: Int) -> [Move] {
        if n == 0 {
            return []
        }
        return solve(n - 1, from: from, to: via, via: to)
            + [Move(disk: n, from: from, to: to)]
            + solve(n - 1, from: via, to: to, via: from)
    }
    return solve(disks, from: 1, to: 3, via: 2)
}
```

</Approach>
