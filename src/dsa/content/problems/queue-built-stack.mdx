Build a last-in, first-out stack whose only storage is queues: DSAKit's `Queue`, used only through `enqueue`, `dequeue`, `peek`, `count` and `isEmpty`. No arrays, and no looping over a queue's contents. Besides the queues, you may keep one extra element. `push` and `top` must be O(1); `pop` may be O(n).

`QueueBuiltStack.QueueStack<Element>`, with `init()`, `push(_:)`, `pop() -> Element?`, `top() -> Element?`, `count: Int` and `isEmpty: Bool`

`pop()` removes and returns the element pushed most recently, and `top()` returns it without removing it. Both return `nil` when the stack is empty.

## Examples

| Code | Result |
| --- | --- |
| push 1, 2, 3, then `pop()` | `3` |
| push 1, 2, 3, `pop()`, then `top()` | `2` |
| push 1, 2, `pop()`, push 4, then pop until empty | `4`, `1`, then `nil` |
| push `"a"`, `"b"`, then `count` | `2` |
| `QueueStack<Int>().top()` | `nil` |

## Constraints

- Up to 50,000 operations, with up to 20,000 pushes in a row, each followed by a `top()`. A push that rotates the whole queue would make about 200 million moves over those pushes.
- The tests only pop a handful of times from very large stacks.
- Copying a stack gives an independent stack, as with any struct.

<Hints>
<Hint>
A queue hands out its oldest element and a stack needs its newest, so one of push and pop has to move elements around. Since push must be O(1), push is a plain `enqueue`, and pop does the moving.
</Hint>
<Hint>
To pop, dequeue all but the last element from the main queue and enqueue each one onto a helper queue. The one left is the newest: dequeue and return it. Then swap the two queues' roles with `swap(&main, &helper)`.
</Hint>
<Hint>
For an O(1) `top()`, keep the newest element in your one extra property. A push sets it. During a pop, the last element moved to the helper queue is the new newest, so update it as you move them.
</Hint>
</Hints>

## Solutions

<Approach title="One queue, rotate on push" time="O(n) push, O(1) pop and top" space="O(n)">

Keep the newest element at the front of a single queue. To push, enqueue the new element and then rotate every older one behind it. It's the neatest version, but every push moves the whole stack, which this problem's push limit rules out.

```swift
public mutating func push(_ element: Element) {
    queue.enqueue(element)
    for _ in 0..<(queue.count - 1) {
        queue.enqueue(queue.dequeue()!)
    }
}
```

</Approach>

<Approach title="Two queues, move on pop" time="O(1) push and top, O(n) pop" space="O(n)">

Elements wait in arrival order in `main`. A pop moves all but the newest across to `helper`, takes the newest, and swaps the queues. Moving between queues keeps the order, so nothing is ever settled for good, and every later pop moves the remaining elements again. That's why a stack built from queues never gets amortised O(1) for both operations.

```swift
import DSAKit

public enum QueueBuiltStack {
    public struct QueueStack<Element> {
        private var main = Queue<Element>()
        private var helper = Queue<Element>()
        private var newest: Element?             // the top, so top() is O(1)

        public init() {}

        public var count: Int { main.count }

        public var isEmpty: Bool { main.isEmpty }

        public mutating func push(_ element: Element) {
            main.enqueue(element)
            newest = element
        }

        public mutating func pop() -> Element? {
            guard !main.isEmpty else { return nil }
            newest = nil
            while main.count > 1 {
                let element = main.dequeue()!
                helper.enqueue(element)
                newest = element                 // the last one moved will be the new top
            }
            let popped = main.dequeue()
            swap(&main, &helper)
            return popped
        }

        public func top() -> Element? {
            newest
        }
    }
}
```

When the stack holds one element, the loop doesn't run, so `newest` stays `nil` and the stack is correctly empty afterwards.

</Approach>
