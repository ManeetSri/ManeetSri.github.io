Every step count in this problem is a single term of the form

coefficient × baseⁿ × n^power × (log n)^logPower

so 5n² is `Term(coefficient: 5, power: 2)`, 2ⁿ is `Term(base: 2)` and n log n is `Term(power: 1, logPower: 1)`. A `base` of 1 means there's no exponential part. Compare terms the way the ratio test does, and sort a list of them up the growth ladder.

`GrowthTermOrder.relation(_ f: Term, _ g: Term) -> Relation` returns `.littleO` when f grows strictly slower than g (f / g heads to 0), `.theta` when they grow at the same rate (f / g settles at a positive constant), and `.littleOmega` when f grows strictly faster.

`GrowthTermOrder.ladder(_ terms: [Term]) -> [Term]` returns the terms from slowest-growing to fastest-growing. Terms that grow at the same rate keep their original order.

## Examples

| f | g | `relation(f, g)` | Why |
| --- | --- | --- | --- |
| n | n² | `.littleO` | n / n² = 1/n heads to 0 |
| 3n | n | `.theta` | the ratio is always 3 |
| (log n)³ | n | `.littleO` | any power of n beats any power of log n |
| n¹⁰ | 2ⁿ | `.littleO` | any exponential beats any polynomial |
| 3ⁿ | 2ⁿ · n⁵ | `.littleOmega` | (3/2)ⁿ beats n⁵ |
| 1 | 500 | `.theta` | both are constants |

`ladder` of n², log n, 2ⁿ, n log n, 1 and n gives 1, log n, n, n log n, n², 2ⁿ.

## Constraints

- `1 ≤ coefficient ≤ 10⁹`, `1 ≤ base ≤ 100`, `0 ≤ power, logPower ≤ 100`.
- `ladder` gets at most 10⁴ terms.

<Hints>
<Hint>
The coefficient never matters: multiplying by a constant can't change whether a ratio heads to 0, settles, or grows without limit. That's why 3n is Θ(n) and not o(n).
</Hint>
<Hint>
Compare the parts from strongest to weakest. A bigger base wins outright, whatever the powers: (3/2)ⁿ beats any power of n. If the bases are equal, they cancel in the ratio, and a bigger power of n wins, whatever the log powers. Only if both of those are equal do the log powers decide.
</Hint>
<Hint>
So the growth of a term is the triple (base, power, logPower), compared like words in a dictionary: first entries first. For `ladder`, sort by that triple, and break ties by each term's original position so equal-growth terms stay in order.
</Hint>

## Solutions

<Approach title="Compare (base, power, logPower) in order" time="O(1) per comparison, O(t log t) for the ladder" space="O(t)">

The ratio of two terms is (c₁ / c₂) × (b₁ / b₂)ⁿ × n^(p₁ − p₂) × (log n)^(q₁ − q₂). If the bases differ, the exponential part decides: (b₁ / b₂)ⁿ heads to 0 or grows without limit faster than any power of n or log n can fight back. If the bases are equal, that part is 1, and n^(p₁ − p₂) decides in the same way over the log part. If those are equal too, the log part decides, and if everything is equal the ratio is the constant c₁ / c₂.

Swift compares tuples left to right, which is exactly that order. For `ladder`, pairing each term with its index and sorting by (base, power, logPower, index) keeps equal-growth terms in their original order without relying on the sort being stable.

```swift
public enum GrowthTermOrder {
    public struct Term: Equatable {
        public var coefficient: Int
        public var base: Int
        public var power: Int
        public var logPower: Int

        public init(coefficient: Int = 1, base: Int = 1, power: Int = 0, logPower: Int = 0) {
            self.coefficient = coefficient
            self.base = base
            self.power = power
            self.logPower = logPower
        }
    }

    public enum Relation: Equatable {
        case littleO, theta, littleOmega
    }

    static func growth(_ term: Term) -> (Int, Int, Int) {
        (term.base, term.power, term.logPower)
    }

    public static func relation(_ f: Term, _ g: Term) -> Relation {
        if growth(f) < growth(g) { return .littleO }
        if growth(f) > growth(g) { return .littleOmega }
        return .theta
    }

    public static func ladder(_ terms: [Term]) -> [Term] {
        let ordered = terms.enumerated().sorted { first, second in
            let (a, b) = (first.element, second.element)
            return (a.base, a.power, a.logPower, first.offset) < (b.base, b.power, b.logPower, second.offset)
        }
        return ordered.map { $0.element }
    }
}
```

The comparison is the precise growth ladder from the lesson: 1 → log n → n → n log n → n² → … → 2ⁿ, where each step is little-o of the next and a constant factor never moves a term to a different rung.

</Approach>
