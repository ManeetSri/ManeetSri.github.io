Write the function a routing library would call when it doesn't know what kind of graph it's been given. The graph has `nodes` nodes, numbered `0` to `nodes - 1`, and one-way edges `[from, to, weight]`. Pick the **first** method in this list whose condition the graph meets, run it, and return both the method and the shortest distance from `source` to every node (`nil` for a node that can't be reached):

| Method | Use it when |
| --- | --- |
| `.bfs` | there are no edges, or every edge has the same weight and it's at least 1 |
| `.zeroOneBFS` | every weight is 0 or 1 |
| `.dagOrder` | the graph has no directed cycle (an edge from a node to itself counts as one) |
| `.dijkstra` | every weight is at least 0 |
| `.bellmanFord` | anything else |

`ShortestPathDispatcher.route(nodes: Int, edges: [[Int]], source: Int) -> (method: ShortestPathDispatcher.Method, distances: [Int?])`

`Method` is an enum with those five cases, already declared in the exercise file. Inputs that reach `.bellmanFord` never contain a negative cycle.

## Examples

| `nodes` | `edges` | `source` | `method` | `distances` |
| --- | --- | --- | --- | --- |
| `4` | `[[0, 1, 5], [1, 2, 5], [0, 2, 5], [2, 3, 5]]` | `0` | `.bfs` | `[0, 5, 5, 10]` |
| `4` | `[[0, 1, 0], [1, 2, 1], [0, 2, 1], [2, 3, 0], [3, 1, 0]]` | `0` | `.zeroOneBFS` | `[0, 0, 1, 1]` |
| `5` | `[[0, 1, 3], [0, 2, 6], [1, 2, -4], [1, 3, 2], [2, 3, 1], [3, 4, -2], [2, 4, 5]]` | `0` | `.dagOrder` | `[0, 3, -1, 0, -2]` |
| `3` | `[[0, 1, 4], [1, 0, 4], [1, 2, 3], [0, 2, 9]]` | `0` | `.dijkstra` | `[0, 4, 7]` |
| `3` | `[[0, 1, 4], [1, 2, -2], [2, 1, 3], [0, 2, 5]]` | `0` | `.bellmanFord` | `[0, 4, 2]` |
| `3` | `[]` | `1` | `.bfs` | `[nil, 0, nil]` |
| `2` | `[[0, 1, 0]]` | `0` | `.zeroOneBFS` | `[0, 0]` |

The third is the DAG from the lesson: it has negative edges, but no cycles, so relaxing in topological order handles it in O(V + E). In the fourth, 0 and 1 point at each other, so it isn't a DAG. In the fifth, the cycle 1 → 2 → 1 weighs −2 + 3 = 1, so it isn't negative. The last has every weight equal, but 0 isn't at least 1, so the second row is the first that fits.

## Constraints

- `1 ≤ nodes ≤ 101,000` and `0 ≤ edges.count ≤ 300,000`, with `0 ≤ from, to < nodes` and `-1,000,000 ≤ weight ≤ 1,000,000`. There can be several edges between the same two nodes.
- Graphs that need `.bellmanFord` have at most 300 nodes and 3,000 edges.
- The tests include a DAG of 20,000 nodes with negative weights, and a graph of 30,000 nodes with cycles and weights from 0 to 9, both with their edges listed in an order that makes Bellman–Ford take thousands of rounds. Each method has to be the right one, and run at its own speed.

<Hint>
Answer the questions in the table's order, and stop at the first yes. The weight questions need one pass over the edges. The cycle question is Kahn's algorithm: if it can't output every node, there's a cycle. And if there isn't, it has already given you the order to relax in.
</Hint>
<Hint>
Each method in a sentence. BFS: the first visit is the fewest hops, so the distance is hops × the weight. 0-1 BFS: pop from the front of a deque, push across a 0-edge to the front and a 1-edge to the back. DAG: relax each node's edges once, in topological order, skipping unreached nodes. Dijkstra: a min-heap of (distance, node) with stale entries skipped. Bellman–Ford: rounds over every edge until one changes nothing.
</Hint>
<Hint>
Keep one sentinel for "not reached", such as `Int.max / 2`, and never relax an edge out of a node that still has it: with negative weights, "infinity minus 3" would look like a real distance. Turn the sentinel into `nil` only at the end.
</Hint>
</Hints>

## Solutions

<Approach title="Bellman–Ford for everything" time="O(nodes · edges)" space="O(nodes + edges)">

Bellman–Ford gives correct distances on every input here, because none has a negative cycle. But it isn't what the table says for most of them, and on the large DAG and the large cyclic graph, whose edges are listed against the direction information flows, it needs thousands of rounds of hundreds of thousands of edges.

</Approach>

<Approach title="Classify, then dispatch" time="O(nodes + edges) to classify, then each method's own time" space="O(nodes + edges)">

The checks run in the table's order, and each branch hands off to a small function for its method. Kahn's algorithm is run only when the weight checks have failed, and its output is reused as the relaxation order.

```swift
import DSAKit

public enum ShortestPathDispatcher {
    public enum Method: Sendable, CaseIterable {
        case bfs
        case zeroOneBFS
        case dagOrder
        case dijkstra
        case bellmanFord
    }

    private typealias Graph = [[(to: Int, weight: Int)]]
    private static let infinity = Int.max / 2                // "not reached", with room to add a weight

    public static func route(nodes: Int, edges: [[Int]], source: Int) -> (method: Method, distances: [Int?]) {
        var graph: Graph = Array(repeating: [], count: nodes)
        for edge in edges {
            graph[edge[0]].append((edge[1], edge[2]))
        }
        let weights = edges.map { $0[2] }
        var distance = Array(repeating: infinity, count: nodes)
        distance[source] = 0
        let method: Method

        if weights.isEmpty || (weights[0] >= 1 && weights.allSatisfy { $0 == weights[0] }) {
            method = .bfs
            bfs(graph, from: source, weight: weights.first ?? 1, &distance)
        } else if weights.allSatisfy({ $0 == 0 || $0 == 1 }) {
            method = .zeroOneBFS
            zeroOneBFS(graph, from: source, &distance)
        } else if let order = topologicalOrder(graph) {
            method = .dagOrder
            for node in order where distance[node] != infinity {
                for (next, weight) in graph[node] {
                    distance[next] = min(distance[next], distance[node] + weight)
                }
            }
        } else if weights.allSatisfy({ $0 >= 0 }) {
            method = .dijkstra
            dijkstra(graph, from: source, &distance)
        } else {
            method = .bellmanFord
            bellmanFord(edges, nodes: nodes, &distance)
        }
        return (method, distance.map { $0 == infinity ? nil : $0 })
    }

    /// Every edge costs `weight`: the first visit is the fewest hops, so distance is hops × weight
    private static func bfs(_ graph: Graph, from source: Int, weight: Int, _ distance: inout [Int]) {
        var queue = [source]
        var head = 0
        while head < queue.count {
            let node = queue[head]
            head += 1
            for (next, _) in graph[node] where distance[next] == infinity {
                distance[next] = distance[node] + weight
                queue.append(next)
            }
        }
    }

    /// Weights 0 and 1: a 0-edge goes to the front of the deque, a 1-edge to the back
    private static func zeroOneBFS(_ graph: Graph, from source: Int, _ distance: inout [Int]) {
        var deque = Deque([source])
        while let node = deque.popFirst() {
            for (next, weight) in graph[node] where distance[node] + weight < distance[next] {
                distance[next] = distance[node] + weight
                if weight == 0 { deque.prepend(next) } else { deque.append(next) }
            }
        }
    }

    /// Kahn's algorithm: an order in which every edge points forwards, or nil if there's a cycle
    private static func topologicalOrder(_ graph: Graph) -> [Int]? {
        var inDegree = Array(repeating: 0, count: graph.count)
        for edges in graph {
            for (next, _) in edges { inDegree[next] += 1 }
        }
        var order = graph.indices.filter { inDegree[$0] == 0 }
        var head = 0
        while head < order.count {
            let node = order[head]
            head += 1
            for (next, _) in graph[node] {
                inDegree[next] -= 1
                if inDegree[next] == 0 { order.append(next) }
            }
        }
        return order.count == graph.count ? order : nil
    }

    /// Non-negative weights: settle the closest node first, skipping stale heap entries
    private static func dijkstra(_ graph: Graph, from source: Int, _ distance: inout [Int]) {
        var heap = Heap<(distance: Int, node: Int)>(areInIncreasingOrder: { $0.distance < $1.distance })
        heap.insert((0, source))
        while let (best, node) = heap.pop() {
            if best > distance[node] { continue }
            for (next, weight) in graph[node] where best + weight < distance[next] {
                distance[next] = best + weight
                heap.insert((distance[next], next))
            }
        }
    }

    /// Negative weights but no negative cycle: at most nodes - 1 rounds, stopping when nothing changes
    private static func bellmanFord(_ edges: [[Int]], nodes: Int, _ distance: inout [Int]) {
        for _ in 0..<max(nodes - 1, 0) {
            var changed = false
            for edge in edges where distance[edge[0]] != infinity && distance[edge[0]] + edge[2] < distance[edge[1]] {
                distance[edge[1]] = distance[edge[0]] + edge[2]
                changed = true
            }
            if !changed { break }
        }
    }
}
```

The `.bfs` row needs `weights[0] >= 1`: with every weight 0, all distances are 0, which BFS's "hops × weight" also gets right, but the table sends it to the next row, and the tests check the method too. A bare trailing closure in an `if` condition, as in `if weights.allSatisfy { $0 >= 0 } {`, makes Swift warn that it's confusable with the body of the statement. That's why the other branches pass their closures in parentheses; the first one is already inside a pair.

</Approach>
