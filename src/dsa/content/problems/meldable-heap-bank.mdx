A ride-hailing service keeps one min-heap of waiting fares per city zone. When two zones merge for the night, their queues must merge too, and they merge constantly. Build a bank of heaps where **meld**, combining one heap into another, is cheap.

`MeldableHeapBank.HeapBank`, a struct with `init(count:)`, `size(of:)`, `min(of:)`, `push(_:onto:)`, `popMin(from:)` and `meld(_:into:)`.

- `init(count: n)` creates heaps numbered `0..<n`, all empty.
- `push(value, onto: h)` adds a value to heap `h`; `popMin(from: h)` removes and returns its smallest value, or `nil` if it's empty; `min(of: h)` reads the smallest without removing it; `size(of: h)` counts its values.
- `meld(s, into: t)` moves every value of heap `s` into heap `t`, leaving `s` empty. Melding a heap into itself does nothing.

Concatenating two binary heaps' arrays and re-heapifying costs O(n) per meld. Aim for O(log n) or better per operation (amortised is fine): a **pairing heap** melds in O(1), and a **binomial heap** in O(log n).

## Examples

| Code | Result |
| --- | --- |
| `var bank = HeapBank(count: 3)`; push 5, 1, 9 onto heap 0; push 4, 7 onto heap 1 | `min(of: 0)` is `1`, `min(of: 1)` is `4` |
| `bank.meld(0, into: 1)` | `size(of: 1)` is `5`, `size(of: 0)` is `0`, `min(of: 1)` is `1` |
| `popMin(from: 1)` three times | `1`, `4`, `5` |
| `popMin(from: 0)`, `min(of: 2)` | `nil`, `nil` |
| `meld(1, into: 1)` | nothing changes |

## Constraints

- `1 ≤ count ≤ 100,000`, and every heap number passed in is in `0..<count`.
- Up to 300,000 operations in total, with values of any `Int`, duplicates allowed.
- The tests meld 100,000 heaps one after another, so a meld that copies the larger heap is too slow.
- A pointer-based tree here can become a chain 100,000 nodes deep (push values in decreasing order), and Swift releases a chain of class instances one nested call per node, which can overflow the stack. Storing nodes in arrays and linking them by index avoids this.

<Hints>
<Hint>
A pairing heap is a single heap-ordered tree in which a node can have any number of children. **Melding** two of them is one comparison: the root with the larger value becomes the newest child of the other root. `push` is a meld with a one-node heap, and the minimum is always the root.
</Hint>
<Hint>
Store nodes in parallel arrays: `value`, `firstChild` and `nextSibling` (−1 for none), so a node's children form a linked list. Each heap number then just needs a root index and a size. Linking root b under root a is `nextSibling[b] = firstChild[a]; firstChild[a] = b`.
</Hint>
<Hint>
**popMin** removes the root, leaving a list of child subtrees to combine into one. Do it in two passes: meld them in pairs from left to right (first with second, third with fourth, …), then meld those results together from right to left. This two-pass rule is what gives the pairing heap its O(log n) amortised pop.
</Hint>
</Hints>

## Solutions

<Approach title="Small into large" time="O(log² n) amortised per meld" space="O(n)">

Keep an ordinary binary heap for each number, and when melding, always pour the **smaller** heap into the larger one, swapping them first if needed. Each value moves only when its heap at least doubles in size, so it moves at most log₂ n times, each move costing an O(log n) insert. It's a classic trick and good enough here, but every meld still touches every value of the smaller heap.

```swift
public mutating func meld(_ source: Int, into target: Int) {
    guard source != target else { return }
    if heaps[source].count > heaps[target].count { heaps.swapAt(source, target) }
    for value in heaps[source].unordered { heaps[target].insert(value) }
    heaps[source] = Heap.minHeap([])
}
```

</Approach>

<Approach title="Pairing heaps in arrays" time="O(1) push, meld and min; O(log n) amortised popMin" space="O(n)">

All nodes live in three arrays shared by every heap, so melding never copies anything: it compares two roots and changes two links. Removing the minimum does the deferred work, combining the root's children with the two-pass rule.

```swift
public enum MeldableHeapBank {
    public struct HeapBank {
        private var value: [Int] = []                    // node storage, shared by every heap
        private var firstChild: [Int] = []
        private var nextSibling: [Int] = []
        private var root: [Int]                          // each heap's root node, or -1
        private var sizes: [Int]

        public init(count: Int) {
            root = Array(repeating: -1, count: count)
            sizes = Array(repeating: 0, count: count)
        }

        public func size(of heap: Int) -> Int { sizes[heap] }

        public func min(of heap: Int) -> Int? {
            root[heap] < 0 ? nil : value[root[heap]]
        }

        public mutating func push(_ newValue: Int, onto heap: Int) {
            value.append(newValue)
            firstChild.append(-1)
            nextSibling.append(-1)
            root[heap] = link(root[heap], value.count - 1)
            sizes[heap] += 1
        }

        public mutating func meld(_ source: Int, into target: Int) {
            guard source != target else { return }
            root[target] = link(root[target], root[source])
            sizes[target] += sizes[source]
            root[source] = -1
            sizes[source] = 0
        }

        public mutating func popMin(from heap: Int) -> Int? {
            let top = root[heap]
            guard top >= 0 else { return nil }
            var children: [Int] = []                     // detach the root's children
            var child = firstChild[top]
            while child >= 0 {
                let next = nextSibling[child]
                nextSibling[child] = -1
                children.append(child)
                child = next
            }
            var pairs: [Int] = []                        // pass 1: meld in pairs, left to right
            var i = 0
            while i < children.count {
                pairs.append(i + 1 < children.count ? link(children[i], children[i + 1]) : children[i])
                i += 2
            }
            var combined = -1                            // pass 2: meld the pairs, right to left
            for tree in pairs.reversed() {
                combined = link(tree, combined)
            }
            root[heap] = combined
            sizes[heap] -= 1
            return value[top]
        }

        /// Melds two trees given by their roots (-1 for empty), returning the new root.
        private mutating func link(_ a: Int, _ b: Int) -> Int {
            if a < 0 { return b }
            if b < 0 { return a }
            let (top, other) = value[b] < value[a] ? (b, a) : (a, b)
            nextSibling[other] = firstChild[top]         // other becomes top's newest child
            firstChild[top] = other
            return top
        }
    }
}
```

Popped nodes are simply left unused in the arrays, which keeps the code short; a long-running service would recycle them through a free list. The pairing heap's exact amortised bound for decrease-key took decades to pin down, but for push, meld and pop it's simple and, in practice, often the fastest mergeable heap there is.

</Approach>
