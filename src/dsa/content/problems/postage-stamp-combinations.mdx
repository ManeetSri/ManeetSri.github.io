A post office sells stamps in the values listed in `stamps`, all different, and has an unlimited supply of each. Return every different collection of stamps whose values add up to exactly `postage`. A collection is a multiset: the order of the stamps doesn't matter, but a value may appear several times.

`PostageStampCombinations.combinations(stamps: [Int], postage: Int) -> [[Int]]`

The collections may come in any order, and so may the stamps inside each one: the tests sort both before comparing.

## Examples

| `stamps` | `postage` | Output |
| --- | --- | --- |
| `[4, 6, 9]` | `12` | `[[4, 4, 4], [6, 6]]` |
| `[3, 5, 8]` | `16` | `[[3, 3, 5, 5], [3, 5, 8], [8, 8]]` |
| `[2, 5]` | `11` | `[[2, 2, 2, 5]]` |
| `[5]` | `3` | `[]` |

In the second example, `[3, 5, 8]` and `[8, 5, 3]` are the same collection, so it's listed once.

## Constraints

- `1 ≤ stamps.count ≤ 30`, with distinct values, `2 ≤ stamps[i] ≤ 60`.
- `1 ≤ postage ≤ 60`.
- The tests have at most a few thousand collections; the largest has 1,966.

<Hints>
<Hint>
Build a collection one stamp at a time, keeping track of how much postage is still to pay. When that reaches 0, record the collection.
</Hint>
<Hint>
To avoid listing the same collection in different orders, only ever add stamps in non-decreasing order: each level chooses from the current stamp onwards, never an earlier one. Passing the same index down again is what allows a stamp to be reused.
</Hint>
<Hint>
Sort the stamps first. Then, as soon as a stamp is worth more than what's left to pay, every later stamp is too, and the loop can stop.
</Hint>
</Hints>

## Solutions

<Approach title="Backtracking with reuse and pruning" time="proportional to the pruned tree" space="O(postage / smallest stamp)">

This is combination sum with reuse. The loop starts at `start`, so every collection is built in non-decreasing order and appears once; the recursive call passes `i` rather than `i + 1`, so the same stamp may come next. Sorting makes the `break` valid, which keeps the search from trying stamps that can't fit.

```swift
public enum PostageStampCombinations {
    public static func combinations(stamps: [Int], postage: Int) -> [[Int]] {
        let sorted = stamps.sorted()
        var result: [[Int]] = []
        var chosen: [Int] = []

        func explore(from start: Int, remaining: Int) {
            if remaining == 0 {
                result.append(chosen)
                return
            }
            for i in start..<sorted.count {
                if sorted[i] > remaining { break }                  // sorted: the rest are too big
                chosen.append(sorted[i])                            // choose
                explore(from: i, remaining: remaining - sorted[i])  // i again: reuse is allowed
                chosen.removeLast()                                 // unchoose
            }
        }

        explore(from: 0, remaining: postage)
        return result
    }
}
```

The recursion is at most postage ÷ smallest stamp levels deep, 30 here. If you only needed the **number** of collections, coin-change dynamic programming would count them without listing any.

</Approach>
