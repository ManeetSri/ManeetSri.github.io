A board is a grid of `"X"` and `"O"` cells. A **region** is a group of `"O"`s joined up, down, left or right. A region is **enclosed** when none of its cells lies on the board's border, so it's walled in by `"X"`s on every side. Return the board with every enclosed region captured: all of its cells turned into `"X"`.

`EnclosedRegionCapture.capture(_ board: [[Character]]) -> [[Character]]`

## Examples

The tests build each board from strings, one per row.

| `board` | Returns |
| --- | --- |
| `["XXXX", "XOOX", "XXOX", "XOXX"]` | `["XXXX", "XXXX", "XXXX", "XOXX"]` |
| `["XOXX", "XOXX", "XXXX", "XOOX", "XXXX"]` | `["XOXX", "XOXX", "XXXX", "XXXX", "XXXX"]` |
| `["XXXX", "XOXX", "XXOX", "XXXO"]` | `["XXXX", "XXXX", "XXXX", "XXXO"]` |
| `["OOO", "OOO", "OOO"]` | `["OOO", "OOO", "OOO"]` |
| `[]` | `[]` |

In the first example, the three `"O"`s in the middle are enclosed and get captured, but the one on the bottom edge survives. In the second, the top region touches the border through its top cell, so both of its cells survive. In the third, the `"O"`s touch the corner `"O"` only diagonally, which doesn't connect them.

## Constraints

- `0 ≤ rows, columns ≤ 1,000`, every row has the same length, and every cell is `"X"` or `"O"`.
- The tests include a 1000 × 1000 board holding one region of nearly a million cells, and a snake-shaped region of about 500,000 cells, both with and without a gap to the border. Use an explicit stack or BFS: recursion that deep crashes the test thread.

<Hints>
<Hint>
You could explore each region and check whether any of its cells is on the border. But think in reverse: which `"O"`s survive? Exactly those connected to an `"O"` on the border.
</Hint>
<Hint>
Push every `"O"` on the border onto one stack, marking each as safe with a third character such as `"S"`, then spread from them through neighbouring `"O"`s, marking those safe too.
</Hint>
<Hint>
After the search, sweep the board once: every `"O"` left unmarked is enclosed and becomes `"X"`, and every `"S"` becomes `"O"` again.
</Hint>
</Hints>

## Solutions

<Approach title="Explore each region, then decide" time="O(rows × columns)" space="O(rows × columns)">

Scan for unvisited `"O"`s. From each, collect its whole region with a BFS, noting whether any cell is on the border. If none is, turn the collected cells into `"X"`. Every cell is visited once, so it's linear too, but it needs a visited grid and a list of cells per region, and the "touches the border" bookkeeping is easy to get wrong.

</Approach>

<Approach title="Mark the survivors from the border" time="O(rows × columns)" space="O(rows × columns)">

All the border `"O"`s start the search together, like the sources of a multi-source BFS. The search only marks cells, so DFS order is fine.

```swift
public enum EnclosedRegionCapture {
    private static let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    public static func capture(_ board: [[Character]]) -> [[Character]] {
        var board = board
        guard let columns = board.first?.count, columns > 0 else { return board }
        let rows = board.count

        var stack: [(Int, Int)] = []
        for row in 0..<rows {
            for column in 0..<columns where row == 0 || row == rows - 1 || column == 0 || column == columns - 1 {
                if board[row][column] == "O" {
                    board[row][column] = "S"
                    stack.append((row, column))
                }
            }
        }
        while let cell = stack.popLast() {
            for (dr, dc) in directions {
                let r = cell.0 + dr
                let c = cell.1 + dc
                guard r >= 0, r < rows, c >= 0, c < columns, board[r][c] == "O" else { continue }
                board[r][c] = "S"                        // safe: connected to the border
                stack.append((r, c))
            }
        }

        for row in 0..<rows {
            for column in 0..<columns {
                board[row][column] = board[row][column] == "S" ? "O" : "X"
            }
        }
        return board
    }
}
```

The `where` clause picks out the border cells. Looping over the four edges separately is a little faster, but has to avoid visiting the corners twice.

</Approach>
