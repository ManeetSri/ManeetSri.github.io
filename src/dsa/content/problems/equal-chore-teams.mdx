A household has a list of chores, each taking a whole number of minutes, and wants to split them among k teams so that **every team works exactly the same total time**. Every chore goes to exactly one team. Return a team number for each chore, or `nil` if no fair split exists.

`EqualChoreTeams.assign(_ minutes: [Int], teams k: Int) -> [Int]?`

The result has one entry per chore, a team number from 0 to k − 1, and every team's chores add up to the same total. Any fair split is accepted.

## Examples

| `minutes` | `k` | Output |
| --- | --- | --- |
| `[4, 3, 2, 3, 5, 2, 1]` | `4` | a fair split, such as `[1, 2, 2, 3, 0, 3, 1]` |
| `[1, 2, 3, 4]` | `3` | `nil` |
| `[2, 2, 2, 2, 3, 4, 5]` | `4` | `nil` |
| `[6]` | `1` | `[0]` |
| `[1, 1, 1, 1]` | `4` | `[0, 1, 2, 3]`, or any other order |

In the first example the total is 20, so each of the four teams needs 5 minutes: the 5-minute chore alone, 4 + 1, 3 + 2 and 3 + 2. In the second, 10 minutes can't be shared equally by three teams. In the third, the total is 20 again, but the 4-minute chore would need a 1-minute partner, and there isn't one.

## Constraints

- `1 ≤ minutes.count ≤ 16`, `1 ≤ k ≤ minutes.count`, and every chore takes between 1 and 10,000 minutes.
- The tests include lists of 16 chores with no fair split, where trying every way to hand out the chores, kⁿ of them, is far too slow.

<Hints>
<Hint>
Quick rejections first: the total must divide by k, and no single chore may take longer than total / k. After that it's a search, filling one team at a time up to the target.
</Hint>
<Hint>
Backtracking: try chores from longest to shortest, placing each in a team that still has room, and undo on failure. Two prunings make it fast: if a chore doesn't fit in an empty team, it won't fit in any other empty team either, so stop after trying the first empty one; and skip a team whose current total equals one you already tried for this chore.
</Hint>
<Hint>
Or use a bitmask over the chores. Fill the teams one after another, so the state is only "which chores are used": `fill[mask]` is how full the current team is, or −1 if `mask` can't be reached. From a reachable mask, add any unused chore that fits in the current team's remaining room (the fill wraps to 0 when a team reaches the target). Remember which chore led to each mask, and walk back from the full mask to hand out team numbers. That's O(2ⁿ · n).
</Hint>
</Hints>

## Solutions

<Approach title="Backtracking with pruning" time="exponential, fast with pruning" space="O(n + k)">

Sort the chores longest first, keep the k team totals, and place one chore at a time into a team with room, undoing on the way back. Placing long chores first fails fast, and the two prunings from the hints remove the k! symmetric orders of the teams. It's the "choose, explore, unchoose" template.

</Approach>

<Approach title="A DP over subsets, filling teams in order" time="O(2ⁿ · n)" space="O(2ⁿ)">

```swift
public enum EqualChoreTeams {
    public static func assign(_ minutes: [Int], teams k: Int) -> [Int]? {
        let n = minutes.count
        let total = minutes.reduce(0, +)
        guard total % k == 0 else { return nil }
        let target = total / k
        guard minutes.allSatisfy({ $0 <= target }) else { return nil }

        let full = (1 << n) - 1
        var fill = [Int](repeating: -1, count: 1 << n)     // fill of the team being built, or −1
        var lastChore = [Int](repeating: -1, count: 1 << n)
        fill[0] = 0
        for mask in 0..<full where fill[mask] >= 0 {
            for chore in 0..<n where mask & (1 << chore) == 0 && fill[mask] + minutes[chore] <= target {
                let next = mask | (1 << chore)
                if fill[next] < 0 {
                    fill[next] = (fill[mask] + minutes[chore]) % target
                    lastChore[next] = chore
                }
            }
        }
        guard fill[full] == 0 else { return nil }

        // Walk back from the full mask to recover the order the chores were added in
        var order: [Int] = []
        var mask = full
        while mask != 0 {
            order.append(lastChore[mask])
            mask &= ~(1 << lastChore[mask])
        }
        var teams = [Int](repeating: 0, count: n)
        var used = 0
        for chore in order.reversed() {
            teams[chore] = used / target                 // teams fill up one after another
            used += minutes[chore]
        }
        return teams
    }
}
```

Filling teams in a fixed order means a set of used chores determines everything: the number of full teams is `sum / target`, and the current team's fill is `sum % target`. That's why one number per mask is enough, and why the walk back can hand out team numbers from running totals. Every reachable mask's fill never passes the target, so each team gets exactly `target` minutes.

</Approach>
