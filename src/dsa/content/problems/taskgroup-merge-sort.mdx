Write a merge sort that uses several cores. Arrays of more than `threshold` elements are split in half; the two halves are sorted **concurrently**, in child tasks, by the same function; then the sorted halves are merged. Arrays of `threshold` elements or fewer are sorted directly. Also write the merge itself.

`TaskGroupMergeSort.merge(_ first: [Int], _ second: [Int]) -> [Int]`

`TaskGroupMergeSort.sorted(_ items: [Int], threshold: Int) async -> [Int]`

## Examples

| Call | Output |
| --- | --- |
| `merge([1, 4, 9], [2, 3, 10, 11])` | `[1, 2, 3, 4, 9, 10, 11]` |
| `merge([], [5, 6])` | `[5, 6]` |
| `sorted([5, 3, 8, 1, 9, 2], threshold: 1)` | `[1, 2, 3, 5, 8, 9]` |
| `sorted([5, 3, 8, 1, 9, 2], threshold: 100)` | `[1, 2, 3, 5, 8, 9]`, sorted directly without splitting |
| `sorted([], threshold: 4)` | `[]` |

With `threshold: 1`, every array of two or more elements is split, so the recursion goes all the way down to single elements. That's correct, but slow: it's in the tests to check correctness, not as a recommendation.

## Constraints

- `0 ≤ items.count ≤ 200,000`, any `Int` values, duplicates allowed.
- `threshold ≥ 1`.
- The result must equal `items.sorted()`. The tests check only correctness, never speed.

<Hints>
<Hint>
Start with `merge`: two indexes, take the smaller front element each step, then append whatever is left of either array, as in [Merge sort, top-down and bottom-up](/dsa/learn/sort-merge).
</Hint>
<Hint>
In `sorted`, return `items.sorted()` when `items.count <= threshold`. Otherwise copy the halves into two arrays, `Array(items[..<middle])` and `Array(items[middle...])`, so each child task owns its data.
</Hint>
<Hint>
Add two child tasks to a `withTaskGroup`. They can finish in either order, so make each return a tuple saying which half it sorted, then merge the two in the right order. `async let` for each half also works and is shorter.
</Hint>
</Hints>

## Solutions

<Approach title="Recursive split with a task group" time="O(n log n) work" space="O(n log n) in copies over the recursion">

Each level of the recursion does O(n) work in copying and merging, and there are log(n / threshold) levels of splitting. With enough cores, the two halves at each level run at the same time, so the longest chain of sequential work is dominated by the merges on the way back up, the last of which handles all n elements on one core.

```swift
public enum TaskGroupMergeSort {
    public static func merge(_ first: [Int], _ second: [Int]) -> [Int] {
        var result: [Int] = []
        result.reserveCapacity(first.count + second.count)
        var i = 0
        var j = 0
        while i < first.count && j < second.count {
            if second[j] < first[i] {
                result.append(second[j])
                j += 1
            } else {
                result.append(first[i])
                i += 1
            }
        }
        result.append(contentsOf: first[i...])
        result.append(contentsOf: second[j...])
        return result
    }

    public static func sorted(_ items: [Int], threshold: Int) async -> [Int] {
        if items.count <= max(threshold, 1) {
            return items.sorted()
        }
        let middle = items.count / 2
        let left = Array(items[..<middle])
        let right = Array(items[middle...])
        return await withTaskGroup(of: (isLeft: Bool, sorted: [Int]).self) { group in
            group.addTask { (true, await TaskGroupMergeSort.sorted(left, threshold: threshold)) }
            group.addTask { (false, await TaskGroupMergeSort.sorted(right, threshold: threshold)) }
            var sortedLeft: [Int] = []
            var sortedRight: [Int] = []
            for await half in group {
                if half.isLeft {
                    sortedLeft = half.sorted
                } else {
                    sortedRight = half.sorted
                }
            }
            return merge(sortedLeft, sortedRight)
        }
    }
}
```

`TaskGroupMergeSort.sorted` is written out in full inside the closures, because a bare `sorted(...)` there could be confused with the standard library's `sorted()` method.

</Approach>

<Approach title="async let" time="O(n log n) work" space="O(n log n) in copies over the recursion">

For exactly two pieces, `async let` starts both child tasks without a group, and awaiting them by name removes the bookkeeping about which half finished first.

```swift
public static func sorted(_ items: [Int], threshold: Int) async -> [Int] {
    if items.count <= max(threshold, 1) {
        return items.sorted()
    }
    let middle = items.count / 2
    async let left = TaskGroupMergeSort.sorted(Array(items[..<middle]), threshold: threshold)
    async let right = TaskGroupMergeSort.sorted(Array(items[middle...]), threshold: threshold)
    return merge(await left, await right)
}
```

</Approach>
