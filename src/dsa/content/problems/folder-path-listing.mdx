A file browser needs the full path of every folder, one per line, like a recursive directory listing. Folder `0` is the root, and every other folder's parent has a smaller number. Return the listing as one string: each folder's names from the root joined by `/`, every line ending in `"\n"`, with a folder's line before its subfolders' lines and subfolders in number order.

`FolderPathListing.listing(names: [String], parents: [Int]) -> String`

## Examples

| `names` | `parents` | Output |
| --- | --- | --- |
| `["home"]` | `[-1]` | `"home\n"` |
| `["home", "docs", "pics", "cv"]` | `[-1, 0, 0, 1]` | `"home\nhome/docs\nhome/docs/cv\nhome/pics\n"` |
| `["a", "b", "c", "d"]` | `[-1, 0, 1, 2]` | `"a\na/b\na/b/c\na/b/c/d\n"` |
| `["r", "a", "b", "a1", "b1", "a2"]` | `[-1, 0, 0, 1, 2, 1]` | `"r\nr/a\nr/a/a1\nr/a/a2\nr/b\nr/b/b1\n"` |

In the last example, `a2` was added after `b1`, but it's listed under `a`, straight after `a1`: a folder's whole subtree comes before its next sibling.

## Constraints

- `1 ≤ names.count ≤ 100,000`, and `parents.count == names.count`
- `parents[0] == -1`, and `0 ≤ parents[i] < i` for every other folder
- Names are 1 to 10 characters from `a`–`z`, `0`–`9`, `.`, `-` and `_`
- The tests include a chain of 3,000 folders, each inside the last, whose listing is about 22 million characters. An approach that rebuilds each path from scratch, or builds the output by repeated `result = result + line`, does far more copying than that and is too slow. A chain that deep can also overflow the call stack if you recurse once per level.

<Hints>
<Hint>
Each folder's path is its parent's path plus `/` and its own name. You never need to walk up to the root: if you visit folders depth first, the current path is always "the parent's path, then one more name".
</Hint>
<Hint>
Keep one buffer holding the current path. When you visit a folder, cut the buffer back to its parent's path length and append `/name`; then append the whole buffer and a newline to the output. Since parents come before children, one pass over the folders gives every path's length.
</Hint>
<Hint>
Work in UTF-8 bytes: a `[UInt8]` path buffer and a `[UInt8]` output, converted once at the end with `String(decoding:as:)`. You can even compute the exact output size first (each path's length plus one) and `reserveCapacity` it. Use an explicit stack for the depth-first walk, pushing children in reverse so the smallest number comes off first.
</Hint>
</Hints>

## Solutions

<Approach title="Walk up to the root for every folder" time="O(n · d²)" space="O(n · d)">

For each folder, follow `parents` to the root, prepending each name. It's correct, but a folder at depth d does d prepends, each copying the whole path built so far, and the listing needs the folders in depth-first order anyway. On the 3,000-deep chain this copies tens of billions of characters.

```swift
var path = names[folder]
var current = parents[folder]
while current != -1 {
    path = names[current] + "/" + path      // copies the whole path every time
    current = parents[current]
}
```

</Approach>

<Approach title="Recursion, passing the path down" time="O(n + output)" space="O(output)">

Visit folders depth first and pass each child `path + "/" + name`. Every path is built once from its parent's, so the work is proportional to the output, and `lines.joined()` builds the result in one go. It's fine for shallow trees, but a 3,000-level chain means 3,000 nested calls, which can overflow the smaller stacks that tests run on ([Stack depth limits in Swift](/dsa/learn/rec-stack-limits)).

```swift
func visit(_ folder: Int, _ path: String) {
    lines.append(path)
    for child in children[folder] {
        visit(child, path + "/" + names[child])
    }
}
```

</Approach>

<Approach title="One path buffer, an explicit stack and a reserved output" time="O(n + output)" space="O(n + output)">

Store children as one flat array (start offsets plus targets, built by counting, so they stay in number order). Compute every path length in one forward pass, which also gives the exact output size, and reserve it once. Then walk depth first with an explicit stack, keeping the current path in a single byte buffer: trim it to the parent's length, append `/name`, and copy it into the output. Nothing is ever rebuilt and the output never reallocates.

```swift
public enum FolderPathListing {
    public static func listing(names: [String], parents: [Int]) -> String {
        let n = names.count
        guard n > 0 else { return "" }
        let nameBytes = names.map { Array($0.utf8) }

        // Children in index order, stored as one flat array (start offsets plus targets)
        var childCount = Array(repeating: 0, count: n + 1)
        for folder in 1..<n {
            childCount[parents[folder] + 1] += 1
        }
        for index in 1...n {
            childCount[index] += childCount[index - 1]
        }
        var start = childCount                       // start[f]..<start[f + 1] are f's children
        var children = Array(repeating: 0, count: max(n - 1, 0))
        for folder in 1..<n {
            children[start[parents[folder]]] = folder
            start[parents[folder]] += 1
        }
        start = childCount

        // Path lengths, and the exact output size: every path plus its newline
        var pathLength = Array(repeating: 0, count: n)
        pathLength[0] = nameBytes[0].count
        var total = pathLength[0] + 1
        for folder in 1..<n {
            pathLength[folder] = pathLength[parents[folder]] + 1 + nameBytes[folder].count
            total += pathLength[folder] + 1
        }

        var output: [UInt8] = []
        output.reserveCapacity(total)
        var path: [UInt8] = []
        path.reserveCapacity(pathLength.max() ?? 0)

        var stack = [0]
        while let folder = stack.popLast() {
            let parentLength = folder == 0 ? 0 : pathLength[parents[folder]]
            path.removeLast(path.count - parentLength)      // back up to the parent's path
            if folder != 0 {
                path.append(UInt8(ascii: "/"))
            }
            path.append(contentsOf: nameBytes[folder])
            output.append(contentsOf: path)
            output.append(UInt8(ascii: "\n"))
            var child = start[folder + 1]
            while child > start[folder] {                   // reversed: smallest comes off first
                child -= 1
                stack.append(children[child])
            }
        }
        return String(decoding: output, as: UTF8.self)
    }
}
```

When a folder comes off the stack, the path buffer always begins with its parent's path: either the parent was the previous folder visited, or the previous folder was somewhere inside an earlier sibling's subtree, which shares that prefix. `removeLast(_:)` keeps the buffer's capacity, so the path buffer never reallocates either.

</Approach>
