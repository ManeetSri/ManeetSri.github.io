A circular track has `m` positions, numbered 0 to m − 1. Each step moves you `a` positions forward (backward if `a` is negative), wrapping round. Return the smallest number of steps `x`, from 0 to m − 1, that takes you from position 0 to position `b`: the smallest x with a·x ≡ b (mod m). Return `nil` if no number of steps ever lands on b.

`LinearCongruenceSolver.smallestSolution(a: Int, b: Int, modulus m: Int) -> Int?`

`b` can be negative or bigger than m too: position b means the remainder of b modulo m, from 0 to m − 1.

## Examples

| `a` | `b` | `m` | Output | Why |
| --- | --- | --- | --- | --- |
| `6` | `4` | `10` | `4` | 6 × 4 = 24 ≡ 4; x = 9 also works, but 4 is smaller |
| `6` | `5` | `10` | `nil` | 6x is always even, and so is 10, so the remainder is never 5 |
| `3` | `1` | `11` | `4` | 3 × 4 = 12 ≡ 1: the inverse of 3 |
| `-3` | `1` | `11` | `7` | −3 ≡ 8, and 8 × 7 = 56 ≡ 1 |
| `0` | `0` | `7` | `0` | zero steps already lands on 0 |
| `5` | `3` | `1` | `0` | with one position, everything is position 0 |

## Constraints

- `1 ≤ m ≤ 10¹⁸`
- `-10¹⁸ ≤ a, b ≤ 10¹⁸`
- The tests include moduli near 10¹⁸, so any product of two numbers near m overflows `Int`.

<Hints>
<Hint>
Reduce a and b into 0 to m − 1 first. Then think about g = gcd(a, m). a·x and m are both multiples of g, so what must be true of b for a solution to exist?
</Hint>
<Hint>
If g divides b, divide a, b and m by g. Now a and m are coprime, so a has an inverse modulo m / g, and the extended Euclidean algorithm finds it. In fact, the same call that computes g gives you the inverse: if a·x + m·y = g, then (a/g)·x ≡ 1 (mod m/g).
</Hint>
<Hint>
The answer is (b/g) × inverse, reduced modulo m/g. Both factors can be near 10¹⁸, so `*` traps: use `multipliedFullWidth(by:)` and `dividingFullWidth(_:)`. The result is already the smallest solution, because every solution is it plus a multiple of m/g.
</Hint>
</Hints>

## Solutions

<Approach title="Try every x" time="O(m)" space="O(1)">

Check x = 0, 1, 2, … until a·x leaves remainder b. It's a correct reference for small m, but m can be 10¹⁸, and a·x overflows long before then unless you keep reducing.

```swift
public static func smallestSolution(a: Int, b: Int, modulus m: Int) -> Int? {
    let a = ((a % m) + m) % m
    let b = ((b % m) + m) % m
    var position = 0                       // a·x mod m, updated by adding a each step
    for x in 0..<m {
        if position == b { return x }
        position = (position + a) % m      // stays below 2m, so it never overflows
    }
    return nil
}
```

</Approach>

<Approach title="Extended Euclid and a 128-bit product" time="O(log m)" space="O(1)">

With g = gcd(a, m), a solution exists exactly when g divides b. Then (a/g)·x ≡ b/g (mod m/g) with a/g invertible, and extended Euclid's coefficient x is that inverse. The final product needs the full 128 bits.

```swift
public enum LinearCongruenceSolver {
    public static func smallestSolution(a: Int, b: Int, modulus m: Int) -> Int? {
        let a = ((a % m) + m) % m
        let b = ((b % m) + m) % m
        let (g, x, _) = extendedGCD(a, m)              // a·x + m·y = g
        guard b % g == 0 else { return nil }
        let step = m / g                                // solutions repeat every m / g
        let inverse = ((x % step) + step) % step        // (a / g)·x ≡ 1 (mod m / g)
        return mulMod(b / g, inverse, step)
    }

    private static func extendedGCD(_ a: Int, _ b: Int) -> (g: Int, x: Int, y: Int) {
        var (oldR, r) = (a, b)
        var (oldS, s) = (1, 0)
        var (oldT, t) = (0, 1)
        while r != 0 {
            let q = oldR / r
            (oldR, r) = (r, oldR - q * r)
            (oldS, s) = (s, oldS - q * s)
            (oldT, t) = (t, oldT - q * t)
        }
        return (oldR, oldS, oldT)
    }

    private static func mulMod(_ a: Int, _ b: Int, _ m: Int) -> Int {
        m.dividingFullWidth(a.multipliedFullWidth(by: b)).remainder
    }
}
```

When a is 0, extended Euclid returns g = m: then only b = 0 works, and the answer is 0. When m is 1, everything reduces to 0 and the answer is 0. Neither needs special code.

</Approach>
