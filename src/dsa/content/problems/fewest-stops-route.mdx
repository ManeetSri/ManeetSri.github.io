A rail network has `stations` stations, numbered from 0. Each link `[a, b]` is a direct line between stations a and b that runs both ways. Plan a journey from `start` to `goal` that uses the fewest links, and return it as the list of every station on the way, from `start` to `goal`.

If several routes tie for fewest links, return any one of them. If `goal` can't be reached, return `[]`. If `start` is `goal`, the route is just `[start]`.

`StationHopRoute.route(stations: Int, links: [[Int]], from start: Int, to goal: Int) -> [Int]`

## Examples

| `stations` | `links` | From → to | Returns |
| --- | --- | --- | --- |
| `6` | `[[0, 1], [1, 2], [2, 3], [0, 4], [4, 3], [3, 5]]` | `0 → 5` | `[0, 4, 3, 5]` |
| `6` | the same | `5 → 1` | `[5, 3, 2, 1]` |
| `4` | `[[0, 1], [1, 3], [0, 2], [2, 3]]` | `0 → 3` | `[0, 1, 3]` or `[0, 2, 3]` |
| `4` | `[[0, 1], [2, 3]]` | `0 → 3` | `[]` |
| `3` | `[[0, 1], [1, 2]]` | `1 → 1` | `[1]` |

In the first example, 0 → 1 → 2 → 3 → 5 also works but uses four links; going through 4 needs only three.

## Constraints

- `1 ≤ stations ≤ 100,000`, with up to 200,000 links.
- `start` and `goal` are valid stations. Links may be repeated, and a link may join a station to itself.
- The tests include a line of 100,000 stations and a 300 × 300 grid of stations crossed corner to corner, where thousands of routes tie. Any shortest route is accepted.

<Hints>
<Hint>
Every link costs the same, one stop, so BFS from `start` reaches stations in order of how many links away they are. The first time it reaches `goal`, it has come by a shortest route.
</Hint>
<Hint>
BFS gives distances. To get the route itself, record each station's **parent**: the station it was first reached from. An array of `-1`s works as both the parent record and the visited mark.
</Hint>
<Hint>
Walk back from `goal` through the parents until you reach `start`, then reverse the list. You can stop the BFS as soon as `goal` has a parent.
</Hint>
</Hints>

## Solutions

<Approach title="BFS with a parent array" time="O(stations + links)" space="O(stations + links)">

Build an adjacency list, run BFS from `start` with a head-index queue, and set `parent[next]` the moment `next` is enqueued. `parent[start] = start` marks the start as visited and tells the walk back where to stop.

```swift
public enum StationHopRoute {
    public static func route(stations: Int, links: [[Int]], from start: Int, to goal: Int) -> [Int] {
        var neighbours = Array(repeating: [Int](), count: stations)
        for link in links {
            neighbours[link[0]].append(link[1])
            neighbours[link[1]].append(link[0])
        }

        var parent = Array(repeating: -1, count: stations)
        parent[start] = start
        var queue = [start]
        var head = 0
        while head < queue.count && parent[goal] == -1 {
            let station = queue[head]
            head += 1
            for next in neighbours[station] where parent[next] == -1 {
                parent[next] = station                   // mark when enqueued
                queue.append(next)
            }
        }
        guard parent[goal] != -1 else { return [] }

        var route = [goal]
        while route[route.count - 1] != start {
            route.append(parent[route[route.count - 1]])
        }
        return route.reversed()
    }
}
```

A small trick avoids the reversal: run the BFS from `goal` instead. The links run both ways, so the parents then point **towards** `goal`, and walking them from `start` lists the route in the right order.

</Approach>
