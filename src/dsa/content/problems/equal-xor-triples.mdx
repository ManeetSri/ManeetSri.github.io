Cut a stretch of `items` into two touching pieces whose XORs are equal, and count every way to do it. A way is a triple of indexes `(i, j, k)` with `0 ≤ i < j ≤ k < items.count`: the left piece is `items[i..<j]` and the right piece is `items[j...k]`. Count the triples where the XOR of the left piece equals the XOR of the right piece.

`EqualXorTriples.count(in items: [Int]) -> Int`

## Examples

| `items` | Output |
| --- | --- |
| `[6, 2, 4, 6]` | `4` |
| `[1, 2, 3]` | `2` |
| `[3, 3]` | `1` |
| `[0, 0, 0]` | `4` |
| `[5, 9, 12, 1, 1]` | `7` |
| `[4]` | `0` |

In the first example the four triples are `(0, 1, 2)`: `6` and `2 ^ 4`; `(0, 2, 2)`: `6 ^ 2` and `4`; `(1, 2, 3)`: `2` and `4 ^ 6`; and `(1, 3, 3)`: `2 ^ 4` and `6`. Each piece has at least one item, and `j` can equal `k`, so the right piece can be a single item.

## Constraints

- `1 ≤ items.count ≤ 100,000`
- `0 ≤ items[i] ≤ 1,000,000,000`
- The answer fits in an `Int`: it's at most about 1.7 × 10¹⁴. Trying every pair of start and end is O(n²), about 5 billion pairs at the largest size.

<Hints>
<Hint>
If two values are equal, their XOR is 0. So the left piece and the right piece have equal XORs exactly when the whole stretch `items[i...k]` has XOR 0.
</Hint>
<Hint>
With a prefix XOR array, `items[i...k]` has XOR 0 when `prefixXor[i] == prefixXor[k + 1]`. And for such a stretch, **every** cut point `j` from `i + 1` to `k` works: that's `k - i` triples from one stretch.
</Hint>
<Hint>
So you need the sum of `p - q - 1` over every pair of prefix positions `q < p` with equal prefix values. Walk the positions once, and keep a dictionary from each prefix value to how many times you've seen it and the sum of the positions where you saw it. The pairs ending at position `p` add `seen × (p - 1) - sumOfPositions`.
</Hint>
</Hints>

## Solutions

<Approach title="Every zero-XOR stretch" time="O(n²)" space="O(1)">

Fix the start `i`, extend the end `k` one item at a time while keeping the running XOR, and whenever it's 0, add the `k - i` cut points. Much better than trying every triple, which would be O(n³), but still too slow for 100,000 items.

```swift
public static func count(in items: [Int]) -> Int {
    var total = 0
    for i in items.indices {
        var running = 0
        for k in i..<items.count {
            running ^= items[k]
            if running == 0 {
                total += k - i
            }
        }
    }
    return total
}
```

</Approach>

<Approach title="Prefix XOR with a dictionary" time="O(n)" space="O(n)">

Position `p` runs from 1 to n, and `running` is `prefixXor[p]`. Every earlier position `q` with the same prefix value marks a zero-XOR stretch `items[q..<p]` with `p - q - 1` cut points. Summing `p - q - 1` over all those `q` is `seen × (p - 1) - sumOfPositions`, so a count and a sum per prefix value are all you need. Position 0, with prefix value 0, is in the dictionary before the loop starts, like the `[0: 1]` seed in the lesson.

```swift
public enum EqualXorTriples {
    public static func count(in items: [Int]) -> Int {
        var seen: [Int: (count: Int, positionSum: Int)] = [0: (1, 0)]
        var running = 0
        var total = 0
        for (index, value) in items.enumerated() {
            running ^= value
            let position = index + 1
            let earlier = seen[running, default: (0, 0)]
            total += earlier.count * (position - 1) - earlier.positionSum
            seen[running] = (earlier.count + 1, earlier.positionSum + position)
        }
        return total
    }
}
```

</Approach>
