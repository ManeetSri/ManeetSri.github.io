You're given an array of linked lists, each sorted in ascending order. Merge them all into **one** sorted list and return its head. Reuse the existing nodes: relink them rather than creating new ones. Any of the lists may be empty (`nil`), and so may the array.

`MergeKSortedLists.merge(_ lists: [ListNode?]) -> ListNode?`

`ListNode` is DSAKit's shared node, with `value` and `next`. Aim for O(N log k) for N nodes in k lists.

## Examples

| `lists` | Returns |
| --- | --- |
| `[1 → 4 → 7, 2 → 5 → 8, 3 → 6 → 9]` | `1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9` |
| `[2 → 6, 1 → 3 → 4 → 10, 5]` | `1 → 2 → 3 → 4 → 5 → 6 → 10` |
| `[1 → 1 → 3, 1 → 2, 3 → 3]` | `1 → 1 → 1 → 2 → 3 → 3 → 3` |
| `[nil, 2 → 3, nil, 1]` | `1 → 2 → 3` |
| `[]` or `[nil, nil]` | `nil` |

## Constraints

- `0 ≤ k ≤ 10,000` lists, with up to 100,000 nodes in total.
- Node values are any `Int`s, and each list is sorted in ascending order.
- The tests merge 10,000 lists of 10 nodes. Merging them one at a time into a growing result walks the result k times, O(N · k): about half a billion steps.

<Hints>
<Hint>
The smallest node of all is the head of one of the lists. After you take it, the next smallest is again the head of one of the lists: the one you took from has a new head.
</Hint>
<Hint>
Keep the current heads in a min-heap ordered by value: `Heap(lists.compactMap { $0 }, areInIncreasingOrder: { $0.value < $1.value })`. Pop the smallest, link it on, and push its `next` if there is one.
</Hint>
<Hint>
A dummy head node (from [Dummy and sentinel nodes](/dsa/learn/ll-sentinel)) saves special-casing the first node. Set the last node's `next` to `nil` at the end, so nothing is left dangling.
</Hint>
</Hints>

## Solutions

<Approach title="Merge one list at a time" time="O(N · k)" space="O(1)">

Merge the first two lists with the two-list merge from M25, then merge the third into the result, and so on. The early nodes are walked again in every merge, so with k equal lists the total is about N · k / 2.

</Approach>

<Approach title="Merge in pairs" time="O(N log k)" space="O(log k) or O(1)">

Merge lists 0 and 1, 2 and 3, and so on, halving the number of lists each round, exactly like bottom-up merge sort. Every node takes part in log₂ k merges. It needs no heap, and it's a good answer to mention in an interview.

</Approach>

<Approach title="A min-heap of the current heads" time="O(N log k)" space="O(k)">

The heap holds at most one node per list, so each of the N pops and pushes is O(log k).

```swift
import DSAKit

public enum MergeKSortedLists {
    public static func merge(_ lists: [ListNode?]) -> ListNode? {
        var heads = Heap(lists.compactMap { $0 }, areInIncreasingOrder: { $0.value < $1.value })
        let dummy = ListNode(0)
        var tail = dummy
        while let smallest = heads.pop() {
            tail.next = smallest
            tail = smallest
            if let next = smallest.next {
                heads.insert(next)
            }
        }
        tail.next = nil
        return dummy.next
    }
}
```

`compactMap` drops the empty lists, and building the heap from them is O(k). Nodes with equal values may come from any list first, which doesn't change the merged values.

</Approach>
