A shop has `n` kinds of item. Kind `i` weighs `weights[i]`, is worth `values[i]`, and there are `stock[i]` identical copies of it. Choose how many copies of each kind to take, between 0 and its stock, so that the total weight is at most `capacity` and the total value is as large as possible. Return that value.

`LimitedStockKnapsack.bestValue(weights: [Int], values: [Int], stock: [Int], capacity: Int) -> Int`

## Examples

| `weights` | `values` | `stock` | `capacity` | Output |
| --- | --- | --- | --- | --- |
| `[2, 3]` | `[3, 5]` | `[3, 1]` | `9` | `14` |
| `[5]` | `[9]` | `[10]` | `23` | `36` |
| `[5]` | `[9]` | `[2]` | `23` | `18` |
| `[4, 1]` | `[7, 1]` | `[0, 3]` | `8` | `3` |

In the first example, all 3 copies of the first kind and the single copy of the second weigh 9 and are worth 14. In the second, only 4 copies fit; in the third, only 2 are in stock. In the last, the valuable kind is sold out.

## Constraints

- `1 ≤ n ≤ 60`, and `values.count == stock.count == weights.count`
- `1 ≤ weights[i] ≤ 10,000` and `0 ≤ values[i] ≤ 10,000`
- `0 ≤ stock[i] ≤ 100,000`
- `0 ≤ capacity ≤ 10,000`
- The tests have light items with stocks of 100,000, so treating every copy as a separate item is far too slow.

<Hints>
<Hint>
With stock 1 this is the 0/1 knapsack. With unlimited stock it's the unbounded one. Treating each copy as its own 0/1 item is correct, but it can mean millions of items.
</Hint>
<Hint>
You never need more than `capacity / weights[i]` copies of kind `i`. That helps, but light items can still have thousands of usable copies.
</Hint>
<Hint>
Bundle the copies: 1, 2, 4, 8, … while they fit in the stock, plus one bundle with whatever is left. Any count from 0 to the stock is a sum of some bundles. Make each bundle one 0/1 item (multiply its weight and value by its size) and run the right-to-left knapsack over the bundles.
</Hint>
</Hints>

## Solutions

<Approach title="One 0/1 item per copy" time="O(capacity · Σ stock)" space="O(capacity)">

Unpack each kind into `min(stock[i], capacity / weights[i])` identical items and run the one-row 0/1 knapsack. It's correct, since 0/1 can take any number of identical copies. But with 60 light kinds, there can be hundreds of thousands of copies, each sweeping 10,000 cells.

</Approach>

<Approach title="Binary splitting" time="O(capacity · Σ log stock)" space="O(capacity)">

Split each capped stock into bundles of 1, 2, 4, … copies plus a remainder. Subsets of the bundles make every count from 0 to the stock, and nothing more, so a 0/1 knapsack over the bundles is exactly the bounded knapsack. Each kind becomes about log₂ of its stock bundles: at most 14 for a stock of 10,000.

```swift
public enum LimitedStockKnapsack {
    public static func bestValue(weights: [Int], values: [Int], stock: [Int], capacity: Int) -> Int {
        var best = Array(repeating: 0, count: capacity + 1)
        for kind in weights.indices {
            var left = min(stock[kind], capacity / weights[kind])
            var size = 1
            while left > 0 {
                let bundle = min(size, left)                         // 1, 2, 4, … then the remainder
                let weight = bundle * weights[kind]
                let value = bundle * values[kind]
                for w in stride(from: capacity, through: weight, by: -1) {
                    best[w] = max(best[w], best[w - weight] + value)
                }
                left -= bundle
                size *= 2
            }
        }
        return best[capacity]
    }
}
```

`min(size, left)` produces the powers of two while they fit and then the remainder, in one loop. The cap `capacity / weights[kind]` guarantees every bundle fits in the bag, so the stride never runs backwards. The bundles must use the right-to-left loop: each one is taken once or not at all.

</Approach>

<Approach title="Monotonic deque" time="O(n · capacity)" space="O(capacity)">

For a kind of weight `w`, the rooms with the same remainder mod `w` only take from each other, and each room wants the best of the last `stock + 1` rooms in its chain (adjusted by value). That's a sliding window maximum, which a monotonic deque answers in O(1) per room. It's faster in theory and much fiddlier to write; binary splitting is plenty here.

</Approach>
