Two players share some piles of stones and take turns. On a turn, a player picks one pile and does one of two things:

- **remove** exactly s stones from it, for some s in `removals` (s must be no more than the pile), or
- **split** it into two non-empty piles of **different** sizes.

A player with no legal move loses. Return whether the player who moves first can force a win.

`PileSplitGame.firstPlayerWins(piles: [Int], removals: [Int]) -> Bool`

## Examples

| `piles` | `removals` | Output | Why |
| --- | --- | --- | --- |
| `[3]` | `[]` | `true` | split 3 into 1 and 2; neither can be split again |
| `[4]` | `[]` | `false` | 4 can only become 1 and 3, and then the other player splits the 3 |
| `[1, 2]` | `[]` | `false` | no pile can be split into two different sizes |
| `[3, 6]` | `[]` | `false` | |
| `[2]` | `[1]` | `false` | take 1, and the other player takes the last stone |
| `[3]` | `[1]` | `true` | take 1 to leave a pile of 2, which loses for the other player |
| `[0, 0]` | `[1, 2]` | `false` | no stones, no moves |

## Constraints

- `1 ≤ piles.count ≤ 10,000`, and `0 ≤ piles[i] ≤ 2,000`
- `0 ≤ removals.count ≤ 10`, with distinct values from 1 to 2,000
- The tests compare with a full search of every position for small games, then use 10,000 piles of up to 2,000 stones.

<Hints>
<Hint>
The piles never interact, so the whole position is a sum of single-pile games. By the Sprague–Grundy theorem, the first player wins exactly when the XOR of the piles' Grundy numbers isn't 0.
</Hint>
<Hint>
A pile's Grundy number is the mex, the smallest non-negative integer missing, of the Grundy numbers of the positions it can move to. Removing s stones leads to one pile, g(n − s). A split into a and n − a leads to two piles, a sum of games, so its value is g(a) XOR g(n − a).
</Hint>
<Hint>
Fill g from 0 up to the largest pile. For splits, loop a from 1 while a is less than n − a, which lists each split once and skips equal halves. Mark the option values in an array to find the mex, and remember an XOR can be bigger than either of its inputs.
</Hint>
</Hints>

## Solutions

<Approach title="Search every position" time="exponential" space="exponential">

Treat the sorted list of non-empty piles as the state, and memoise "does the player to move win?" over every move. It's how the tests check small cases, but splits keep creating new piles, and ten thousand piles have far too many combined positions.

</Approach>

<Approach title="Grundy numbers and XOR" time="O(M² + M · r + piles)" space="O(M)">

Fill in each pile size's Grundy number once, then XOR over the piles. M is the largest pile and r the number of removal sizes.

```swift
public enum PileSplitGame {
    public static func firstPlayerWins(piles: [Int], removals: [Int]) -> Bool {
        let largest = piles.max() ?? 0
        var grundy = Array(repeating: 0, count: largest + 1)
        // seenAt[v] == n means value v is an option of n. A pile has fewer than removals.count + largest
        // options, so its mex, and every Grundy number, is below that.
        var seenAt = Array(repeating: -1, count: removals.count + largest + 2)
        for n in stride(from: 1, through: largest, by: 1) {
            for s in removals where s <= n {
                seenAt[grundy[n - s]] = n
            }
            var a = 1
            while a < n - a {
                let v = grundy[a] ^ grundy[n - a]          // XOR can exceed both, so check the range
                if v < seenAt.count { seenAt[v] = n }
                a += 1
            }
            var mex = 0
            while seenAt[mex] == n { mex += 1 }
            grundy[n] = mex
        }
        return piles.reduce(0) { $0 ^ grundy[$1] } != 0
    }
}
```

Stamping `seenAt[v] = n` instead of clearing a Boolean array for every n avoids O(M) work per pile size: an entry counts as marked only if it holds the current n.

</Approach>
