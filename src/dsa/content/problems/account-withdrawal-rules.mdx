A bank offers three kinds of account that differ only in when you may take money out. Finish the `Account` class, then give its two subclasses their own rules by overriding methods, so that one call works for every kind of account.

`AccountWithdrawalRules.Account`, `OverdraftAccount` and `SavingsAccount`, with `kind()`, `withdraw(_:)`, `statement()`, `startNewMonth()` and `AccountWithdrawalRules.withdrawFromEach(_:amount:)`

The starter code gives you the properties, the initialisers and `deposit(_:)`. The rules:

- **`Account`**: `kind()` is `"Account"`. `withdraw(_:)` succeeds when the amount is positive and no more than the balance. On success it lowers the balance and returns `true`; otherwise it changes nothing and returns `false`.
- **`OverdraftAccount`**: `kind()` is `"Overdraft"`. A positive amount may be withdrawn as long as the balance afterwards is at least `-limit`.
- **`SavingsAccount`** (a `final` class): `kind()` is `"Savings"`. It follows the plain rule, but allows at most three successful withdrawals a month. Refused withdrawals don't count. `startNewMonth()` resets `withdrawalsThisMonth` to 0.
- **`statement()`**, written once in `Account`, returns `"<kind>: <owner> has <balance>"`, such as `"Overdraft: Ravi has -40"`.
- **`withdrawFromEach(_:amount:)`** tries to withdraw the amount from every account in the array, each with its own rule, and returns how many succeeded.

## Examples

| Code | Result |
| --- | --- |
| `Account(owner: "Asha", balance: 100)`, then `withdraw(30)`, then `withdraw(80)` | `true`, then `false`; the balance is 70 |
| `OverdraftAccount(owner: "Ravi", balance: 20, limit: 50)`, then `withdraw(60)` | `true`; the balance is -40 |
| a savings account with 1,000, then four withdrawals of 10 | `true`, `true`, `true`, `false`; the balance is 970 |
| `statement()` on the overdraft account above | `"Overdraft: Ravi has -40"` |
| `withdrawFromEach([plain 40, overdraft 0 with limit 100, savings 60], amount: 50)` | `2` |

## Constraints

- Balances, limits and amounts stay well within `Int`.
- Override methods in the subclasses rather than checking the type of the account with `is` or `as?`.

<Hints>
<Hint>
Write `kind()` and `statement()` in `Account` first. Because `statement()` calls `kind()`, and Swift runs the version belonging to the real object, each subclass gets the right statement as soon as it overrides `kind()`.
</Hint>
<Hint>
In `OverdraftAccount`, write `override public func withdraw(_ amount: Int) -> Bool` with its own check: `amount > 0` and `balance - amount >= -limit`.
</Hint>
<Hint>
`SavingsAccount` adds a rule on top of the plain one, so its `withdraw` first refuses when `withdrawalsThisMonth` is already 3, then calls `super.withdraw(amount)`. Count the withdrawal only when `super` returns `true`.
</Hint>
</Hints>

## Solutions

<Approach title="Override only what differs" time="O(1) per withdrawal, O(n) for withdrawFromEach" space="O(1)">

Each subclass replaces only the behaviour that's different. The savings account reuses the plain rule through `super`, so it can't drift out of step with `Account`. `withdrawFromEach` never asks what kind of account it has: the call `account.withdraw(amount)` runs the right rule by itself, which is polymorphism.

```swift
public enum AccountWithdrawalRules {
    public class Account {
        public let owner: String
        public var balance: Int

        public init(owner: String, balance: Int) {
            self.owner = owner
            self.balance = balance
        }

        public func deposit(_ amount: Int) {
            if amount > 0 {
                balance += amount
            }
        }

        public func kind() -> String {
            "Account"
        }

        public func withdraw(_ amount: Int) -> Bool {
            guard amount > 0, amount <= balance else {
                return false
            }
            balance -= amount
            return true
        }

        public func statement() -> String {
            "\(kind()): \(owner) has \(balance)"
        }
    }

    public class OverdraftAccount: Account {
        public let limit: Int

        public init(owner: String, balance: Int, limit: Int) {
            self.limit = limit
            super.init(owner: owner, balance: balance)
        }

        override public func kind() -> String {
            "Overdraft"
        }

        override public func withdraw(_ amount: Int) -> Bool {
            guard amount > 0, balance - amount >= -limit else {
                return false
            }
            balance -= amount
            return true
        }
    }

    public final class SavingsAccount: Account {
        public var withdrawalsThisMonth = 0

        override public func kind() -> String {
            "Savings"
        }

        override public func withdraw(_ amount: Int) -> Bool {
            guard withdrawalsThisMonth < 3 else {
                return false
            }
            if super.withdraw(amount) {
                withdrawalsThisMonth += 1
                return true
            }
            return false
        }

        public func startNewMonth() {
            withdrawalsThisMonth = 0
        }
    }

    public static func withdrawFromEach(_ accounts: [Account], amount: Int) -> Int {
        var succeeded = 0
        for account in accounts where account.withdraw(amount) {
            succeeded += 1
        }
        return succeeded
    }
}
```

`SavingsAccount` inherits `Account`'s initialiser unchanged, because its only new property has a default value.

</Approach>
