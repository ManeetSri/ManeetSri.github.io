A hiker crosses a grid of heights from the top-left cell to the bottom-right cell, moving up, down, left or right. The **effort** of a route is its single steepest step: the largest height difference between two neighbouring cells along it. Return the smallest effort any route can have.

`GentlestHikingRoute.minimumEffort(_ heights: [[Int]]) -> Int`

## Examples

| `heights` | Output |
| --- | --- |
| `[[1, 4, 2], [3, 8, 2], [5, 3, 1]]` | `2` |
| `[[1, 10], [2, 3]]` | `1` |
| `[[10, 1], [1, 10]]` | `9` |
| `[[1, 2, 3]]` | `1` |
| `[[5]]` | `0` |

In the first grid, going down the left side and along the bottom visits heights 1, 3, 5, 3, 1, so every step is 2. The start's neighbours are 3 and 4 away, so no route can do better. In the third, every route has to step between 1 and 10 at some point.

## Constraints

- `1 ≤ rows, columns ≤ 300`
- `0 ≤ heights[r][c] ≤ 1,000,000`
- The tests use a 300 × 300 grid.

<Hints>
<Hint>
This is a shortest-path problem where a route's cost is the **largest** step, not the sum of steps. Does adding a step to a route ever make that cost smaller?
</Hint>
<Hint>
It doesn't, and that's all Dijkstra needs. Relax with `max(effort so far, height difference)` instead of `+`, and pop the cell with the smallest effort first.
</Hint>
<Hint>
Alternatively, ask "can I cross with effort at most x?" It's monotonic in x, so binary search x and answer each question with a BFS that only takes steps of at most x.
</Hint>
</Hints>

## Solutions

<Approach title="Binary search on the effort" time="O(R · C · log H)" space="O(R · C)">

The answer lies between 0 and the difference between the highest and lowest cells, H. For a guess x, a BFS from the start that only uses steps of at most x tells you whether the bottom-right cell can be reached. Find the smallest x that works, as in [The monotonic predicate idea](/dsa/learn/bsa-idea).

</Approach>

<Approach title="Dijkstra with max instead of plus" time="O(R · C · log(R · C))" space="O(R · C)">

```swift
import DSAKit

public enum GentlestHikingRoute {
    public static func minimumEffort(_ heights: [[Int]]) -> Int {
        let rows = heights.count, cols = heights[0].count
        var effort = Array(repeating: Array(repeating: Int.max, count: cols), count: rows)
        effort[0][0] = 0
        var heap = Heap<(effort: Int, row: Int, col: Int)>(areInIncreasingOrder: { $0.effort < $1.effort })
        heap.insert((0, 0, 0))
        let steps = [(0, 1), (1, 0), (0, -1), (-1, 0)]
        while let (current, row, col) = heap.pop() {
            if current > effort[row][col] { continue }  // stale entry
            if row == rows - 1 && col == cols - 1 { return current }
            for (dr, dc) in steps {
                let r = row + dr, c = col + dc
                guard r >= 0, r < rows, c >= 0, c < cols else { continue }
                let candidate = max(current, abs(heights[r][c] - heights[row][col]))
                if candidate < effort[r][c] {
                    effort[r][c] = candidate
                    heap.insert((candidate, r, c))
                }
            }
        }
        return effort[rows - 1][cols - 1]
    }
}
```

When a cell is popped, every other way to it has an effort at least as large, because extending a route never lowers its steepest step. So stopping at the goal's first pop is safe.

</Approach>

<Approach title="Union-find over sorted steps" time="O(R · C · log(R · C))" space="O(R · C)">

List every pair of neighbouring cells with its height difference, sort the pairs, and join them in that order with a disjoint-set structure. As soon as the start and the goal are in the same set, the difference just added is the answer. You'll build the structure in M45.

</Approach>
