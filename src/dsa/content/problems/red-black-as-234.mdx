Every red-black tree is a 2-3-4 tree in disguise: glue each red node to its black parent, and each black node with its red children becomes one 2-, 3- or 4-node. Given a valid red-black tree, return the 2-3-4 tree it encodes, level by level.

`RedBlackToTwoThreeFour.levels(of root: RedBlackToTwoThreeFour.Node?) -> [[[Int]]]`

`Node` is written for you: `value`, `isRed`, `left` and `right`, with `init(_ value: Int, red: Bool = false, left: Node? = nil, right: Node? = nil)`. Return one array per level of the 2-3-4 tree, top level first. Each level lists its nodes from left to right, and each node is the array of its keys in increasing order. The empty tree has no levels.

## Examples

Red-black trees are shown level by level, with R or B after each value.

| Red-black tree | Output |
| --- | --- |
| `40B / 20R 60B / 10B 30B 50R 70R / 5R 15R 25R` | `[[[20, 40]], [[5, 10, 15], [25, 30], [50, 60, 70]]]` |
| `4B / 2B 6B / 1B 3B 5B 8R / 7B 9B / 10R` | `[[[4]], [[2], [6, 8]], [[1], [3], [5], [7], [9, 10]]]` |
| `2B / 1R 3R` | `[[[1, 2, 3]]]` |
| `1B / nil 2R` (a 3-node leaning right) | `[[[1, 2]]]` |
| `7B` | `[[[7]]]` |
| an empty tree | `[]` |

## Constraints

- The input is always a valid red-black tree, with distinct values and at most 100,000 nodes. A 3-node can lean either way.
- Don't change the tree.

<Hints>
<Hint>
Every 2-3-4 node starts at a **black** red-black node. Its keys are: its left child's value if that child is red, then its own value, then its right child's value if that child is red. Writing them in that order keeps them sorted, because it's an inorder walk of the little cluster.
</Hint>
<Hint>
The cluster's children, in order, are: the left red child's two children (or the left child itself, if it's black), then the right red child's two children (or the right child itself). Those are all black nodes, or all `nil` at the bottom level.
</Hint>
<Hint>
Now it's a level-order traversal, with clusters instead of nodes: keep the current level's black nodes in an array, turn each into its keys, and gather their non-nil cluster children, left to right, as the next level.
</Hint>
</Hints>

## Solutions

<Approach title="Level order over clusters" time="O(n)" space="O(n)">

Each black node, together with its red children, is one 2-3-4 node, so a breadth-first walk that only stops at black nodes visits the 2-3-4 tree level by level. Every red-black node is looked at a constant number of times.

```swift
public enum RedBlackToTwoThreeFour {
    public final class Node {
        public var value: Int
        public var isRed: Bool
        public var left: Node?
        public var right: Node?

        public init(_ value: Int, red: Bool = false, left: Node? = nil, right: Node? = nil) {
            self.value = value
            self.isRed = red
            self.left = left
            self.right = right
        }
    }

    public static func levels(of root: Node?) -> [[[Int]]] {
        var result: [[[Int]]] = []
        var level = [root].compactMap { $0 }                     // black nodes: one per 2-3-4 node
        while !level.isEmpty {
            var keys: [[Int]] = []
            var next: [Node] = []
            for black in level {
                var cluster: [Int] = []
                var children: [Node?] = []
                if let left = black.left, left.isRed {
                    cluster.append(left.value)                   // a red left child joins the cluster
                    children += [left.left, left.right]
                } else {
                    children.append(black.left)
                }
                cluster.append(black.value)
                if let right = black.right, right.isRed {
                    cluster.append(right.value)                  // so does a red right child
                    children += [right.left, right.right]
                } else {
                    children.append(black.right)
                }
                keys.append(cluster)
                next += children.compactMap { $0 }               // black, or nil at the bottom
            }
            result.append(keys)
            level = next
        }
        return result
    }
}
```

The number of levels it returns is the tree's black-height, which is why every root-to-nil path of a red-black tree passes the same number of black nodes: each path passes through one black node per 2-3-4 level, and all 2-3-4 leaves are at the same depth.

</Approach>
