A delivery robot moves around a warehouse floor plan of open cells (`.`) and walls (`#`), one step up, down, left or right at a time. The plan is fixed, and the robot asks for the fewest steps between two open cells many thousands of times, mostly between cells close together. Build a `Router` that answers each query in time proportional to the part of the grid it explores, not to the size of the whole grid.

`RepeatedGridRoutes.Router(grid: [String])` and `router.distance(fromRow: Int, fromColumn: Int, toRow: Int, toColumn: Int) -> Int`

`distance` returns the fewest steps, `0` when the two cells are the same, and `-1` when the target can't be reached. It's `mutating`, so the router can reuse its own buffers between queries.

## Examples

With this grid:

```text
....
.##.
...#
#...
```

| Query (from → to) | Output |
| --- | --- |
| `(0, 0)` → `(3, 3)` | `6` |
| `(0, 3)` → `(3, 3)` | `9` |
| `(1, 0)` → `(2, 2)` | `3` |
| `(2, 1)` → `(2, 1)` | `0` |

From `(0, 3)`, the wall at `(2, 3)` blocks the short way down, so the robot goes back along the top row and around: 9 steps. In the grid `[".#.", "##.", "..."]`, cell `(0, 0)` is walled in, so any query to or from it returns `-1`.

## Constraints

- `1 ≤ rows, columns ≤ 1,000`; every string has the same length.
- Both cells in a query are open and inside the grid.
- Up to 20,000 queries per router. The tests ask 20,000 queries on a 1000 × 1000 grid, almost all between cells at most 4 steps apart. Allocating or clearing a grid-sized array for each query costs a million writes per query, 20 billion in all, and is far too slow; so is searching the whole grid when the target is close.

<Hints>
<Hint>
Each query is an ordinary breadth-first search ([BFS and unweighted shortest paths](/dsa/learn/gt-bfs)), and it can stop the moment it reaches the target. For a nearby target, that's a few dozen cells. The problem is everything that happens *around* the search.
</Hint>
<Hint>
Do all allocation in `init`: the grid as a flat `[Bool]` (cell `r * columns + c`), a distance array, and a queue array with room for every cell. Reset the queue with `head = 0` and `tail = 0` instead of creating a new one.
</Hint>
<Hint>
To avoid clearing "visited" marks, store a stamp per cell instead. Keep a counter that increases by one for each query; a cell is visited in this query exactly when its stamp equals the counter. Starting a new query then costs O(1).
</Hint>
</Hints>

## Solutions

<Approach title="A fresh BFS for every query" time="O(rows × columns) per query" space="O(rows × columns)">

Create a distance array of `rows × columns` entries, all -1, then search. It's correct, and the search itself stops early, but creating and filling the array costs a million writes per query on a 1000 × 1000 grid. Profiling it in [Instruments: Time Profiler and Allocations](/dsa/learn/fs-instruments) shows about nine-tenths of the time spent filling memory.

```swift
var distanceTo = Array(repeating: -1, count: rows * columns)     // every query
```

</Approach>

<Approach title="Reused buffers and visit stamps" time="O(rows × columns) once, then O(cells explored) per query" space="O(rows × columns)">

Everything grid-sized is created once. Each query takes a new stamp, so old marks are stale without being touched, and the queue is a preallocated array with head and tail indices. The search stops as soon as it finds the target, so a short query explores only a small diamond of cells around its start.

```swift
public enum RepeatedGridRoutes {
    public struct Router {
        private let rows: Int
        private let columns: Int
        private let open: [Bool]
        private var stamp: [Int]
        private var distanceTo: [Int32]
        private var queue: [Int32]
        private var currentStamp = 0

        public init(grid: [String]) {
            rows = grid.count
            columns = grid.first?.utf8.count ?? 0
            var open: [Bool] = []
            open.reserveCapacity(rows * columns)
            for line in grid {
                for byte in line.utf8 {
                    open.append(byte != UInt8(ascii: "#"))
                }
            }
            self.open = open
            stamp = Array(repeating: 0, count: rows * columns)
            distanceTo = Array(repeating: 0, count: rows * columns)
            queue = Array(repeating: 0, count: rows * columns)
        }

        public mutating func distance(fromRow: Int, fromColumn: Int, toRow: Int, toColumn: Int) -> Int {
            let start = fromRow * columns + fromColumn
            let target = toRow * columns + toColumn
            if start == target { return 0 }

            currentStamp += 1
            let round = currentStamp
            stamp[start] = round
            distanceTo[start] = 0
            queue[0] = Int32(start)
            var head = 0
            var tail = 1

            while head < tail {
                let cell = Int(queue[head])
                head += 1
                let row = cell / columns
                let column = cell % columns
                let nextDistance = distanceTo[cell] + 1
                for direction in 0..<4 {
                    let neighbour: Int
                    switch direction {
                    case 0:
                        guard row > 0 else { continue }
                        neighbour = cell - columns              // up
                    case 1:
                        guard row < rows - 1 else { continue }
                        neighbour = cell + columns              // down
                    case 2:
                        guard column > 0 else { continue }
                        neighbour = cell - 1                    // left
                    default:
                        guard column < columns - 1 else { continue }
                        neighbour = cell + 1                    // right
                    }
                    guard open[neighbour], stamp[neighbour] != round else { continue }
                    if neighbour == target { return Int(nextDistance) }
                    stamp[neighbour] = round
                    distanceTo[neighbour] = nextDistance
                    queue[tail] = Int32(neighbour)
                    tail += 1
                }
            }
            return -1
        }
    }
}
```

Each cell enters the queue at most once per query, so the queue never needs more than `rows × columns` slots. The neighbours are listed with a `switch` rather than an array literal of four offsets, which can create a small array for every cell visited, certainly in the debug builds your tests use. The stamp is an `Int`, so it can't run out: even a billion queries are nowhere near `Int.max`.

</Approach>
