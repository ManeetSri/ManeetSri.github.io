Return the **kth largest** value in an array: the value that would be in position k if the array were sorted from largest to smallest, counting from 1. Duplicates count separately, so in `[5, 8, 8, 3]` the second largest is 8.

`KthLargestValue.kthLargest(in numbers: [Int], k: Int) -> Int`

Sorting first works in O(n log n). Aim for O(n) on average with quickselect, and make sure it stays fast on the large tests: 100,000 numbers already in order, and 100,000 copies of a single value.

## Examples

| `numbers` | `k` | Returns |
| --- | --- | --- |
| `[7, 2, 9, 4, 6]` | `1` | `9` |
| `[7, 2, 9, 4, 6]` | `2` | `7` |
| `[7, 2, 9, 4, 6]` | `5` | `2` |
| `[5, 8, 8, 3, 8, 1]` | `3` | `8` |
| `[5, 8, 8, 3, 8, 1]` | `4` | `5` |
| `[-4, -9, -1, -6]` | `2` | `-4` |

## Constraints

- `1 ≤ numbers.count ≤ 100,000`
- `1 ≤ k ≤ numbers.count`
- Any `Int` values, with many duplicates possible.

<Hints>
<Hint>
Turn it into a question about indexes. In increasing order, the kth largest of n values sits at index `n - k`. Now you want "the value that would be at index t after sorting", without sorting.
</Hint>
<Hint>
Partition around a pivot, as quick sort does. If index t is in the "smaller" part, the answer is in there, and you can throw the rest away; likewise for the "larger" part. Only one side survives each round, so the work shrinks quickly: n + n/2 + n/4 + … on average.
</Hint>
<Hint>
Pick the pivot at random, so sorted input isn't a worst case. Partition three ways, into smaller, equal and larger: if t falls among the copies of the pivot, the pivot is the answer, and 100,000 equal values finish in one pass.
</Hint>
</Hints>

## Solutions

<Approach title="Sort, then index" time="O(n log n)" space="O(n)">

Short and always correct, and fast enough for these limits. It does more work than needed: it puts every value in order when you only want one.

```swift
public static func kthLargest(in numbers: [Int], k: Int) -> Int {
    numbers.sorted(by: >)[k - 1]
}
```

</Approach>

<Approach title="Quickselect with a three-way partition" time="O(n) expected" space="O(n)">

Each round partitions the surviving range around a random pivot and keeps only the part that holds index `n - k`. A random pivot usually lands well inside the range, so on average the range shrinks by a constant fraction each round, and the work is a shrinking series like n + n/2 + n/4 + …, which is O(n). A fixed pivot would make sorted input take n rounds of O(n) each, and a two-way partition would do the same for all-equal input.

```swift
public enum KthLargestValue {
    public static func kthLargest(in numbers: [Int], k: Int) -> Int {
        var items = numbers
        let target = items.count - k                     // its index in increasing order
        var low = 0
        var high = items.count                           // the answer is somewhere in low..<high
        while true {
            let pivot = items[Int.random(in: low..<high)]
            var less = low                               // low..<less: smaller than the pivot
            var scan = low                               // less..<scan: equal to it
            var greater = high                           // greater..<high: larger than it
            while scan < greater {
                if items[scan] < pivot {
                    items.swapAt(less, scan)
                    less += 1
                    scan += 1
                } else if items[scan] > pivot {
                    greater -= 1
                    items.swapAt(scan, greater)
                } else {
                    scan += 1
                }
            }
            if target < less {
                high = less
            } else if target >= greater {
                low = greater
            } else {
                return pivot
            }
        }
    }
}
```

The loop always ends: the equal block holds at least the pivot itself, so every round either returns or shrinks the range.

</Approach>
