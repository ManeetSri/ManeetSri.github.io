A database column holds at most `maxBytes` bytes of UTF-8 text. Cut a string down to fit: return the longest beginning of `text` that takes at most `maxBytes` bytes in UTF-8 and is made of **whole characters**. Never cut a character in half, even if some of its bytes would fit.

`ByteBudgetPrefix.prefix(of text: String, maxBytes: Int) -> String`

## Examples

| `text` | `maxBytes` | Output | Why |
| --- | --- | --- | --- |
| `"hello"` | `3` | `"hel"` | ASCII letters take 1 byte each |
| `"café"` | `4` | `"caf"` | `é` takes 2 bytes, and 3 + 2 is more than 4 |
| `"café"` | `5` | `"café"` | exactly 5 bytes |
| `"ok👍🏽"` | `9` | `"ok"` | the thumbs up with a skin tone takes 8 bytes |
| `"ok👍🏽"` | `10` | `"ok👍🏽"` | 2 + 8 bytes |
| `"cafe\u{301}"` | `5` | `"caf"` | here `é` is `e` plus a combining accent: one character, 3 bytes |
| `"abc"` | `0` | `""` | nothing fits |

The `"cafe\u{301}"` row is the tricky one. Cutting after the `e` would fit in 4 bytes, but it would split the character `é` in two, turning it into a plain `e`. The whole `é` needs 3 bytes, and 3 + 3 is more than 5.

## Constraints

- `0 ≤ text.utf8.count ≤ 100,000`
- `0 ≤ maxBytes ≤ 1,000,000`
- `text` can contain any Unicode: accents, combining marks, flags and emoji.

<Hints>
<Hint>
A `Character` is a whole grapheme cluster, so looping with `for character in text` can never split one. You only need to know how many bytes each character takes.
</Hint>
<Hint>
`String(character).utf8.count` is the number of UTF-8 bytes in one character. (`character.utf8.count` works too.) Keep a running total of the bytes you've used.
</Hint>
<Hint>
Before taking a character, check whether it still fits: if the total so far plus its size is more than `maxBytes`, stop. Characters after it don't matter, even small ones: the answer must be a beginning of `text`.
</Hint>
</Hints>

## Solutions

<Approach title="Walk the characters, count the bytes" time="O(n)" space="O(n)">

Go through the string one `Character` at a time, which keeps every grapheme cluster in one piece. Add each character's UTF-8 size to a running total, and stop at the first character that would go over the budget.

```swift
public static func prefix(of text: String, maxBytes: Int) -> String {
    var result = ""
    var used = 0
    for character in text {
        let size = String(character).utf8.count
        if used + size > maxBytes {
            break
        }
        used += size
        result.append(character)
    }
    return result
}
```

Here n is the length of `text` in bytes. Every byte is looked at a constant number of times, and the result can be as long as `text`.

Notice that this never compares `text.count` with `maxBytes`. The number of characters says nothing about the number of bytes: `"👨‍👩‍👧‍👦"` is one character and 25 bytes.

</Approach>

<Approach title="Find where to cut, then slice once" time="O(n)" space="O(n)">

Instead of building a new string character by character, find the index where the cut goes and slice there. `text.indices` gives the position of each character, so remember the index just past the last character that fits.

```swift
public enum ByteBudgetPrefix {
    public static func prefix(of text: String, maxBytes: Int) -> String {
        if text.utf8.count <= maxBytes {
            return text
        }
        var used = 0
        var end = text.startIndex
        for index in text.indices {
            let size = String(text[index]).utf8.count
            if used + size > maxBytes {
                break
            }
            used += size
            end = text.index(after: index)
        }
        return String(text[..<end])
    }
}
```

The first line is a shortcut: `utf8.count` is O(1) for a native Swift string, so text that already fits comes back without any walking. `text[..<end]` is a `Substring`, so `String(...)` turns it into the `String` the function promises; you'll look at that conversion properly in the Substring lesson.

</Approach>
