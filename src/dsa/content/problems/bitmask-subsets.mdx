Return every subset of `items`. Subset number `m`, counting from 0, contains `items[i]` exactly when bit `i` of `m` is 1, and lists its items in their original order. So the answer holds 2ⁿ subsets, starting with the empty one.

`BitmaskSubsets.subsets(of items: [Int]) -> [[Int]]`

## Examples

| Input | Output |
| --- | --- |
| `[7, 8]` | `[[], [7], [8], [7, 8]]` |
| `[1, 2, 3]` | `[[], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]]` |
| `[]` | `[[]]` |
| `[5, 5]` | `[[], [5], [5], [5, 5]]` |

In the second example, subset 5 is `101` in binary, so it holds items 0 and 2: `[1, 3]`. Repeated values are still different positions, so `[5, 5]` has four subsets.

## Constraints

- `0 ≤ items.count ≤ 16`

<Hints>
<Hint>
Loop `mask` over `0..<(1 << items.count)`. For an empty array that's `0..<1`: one mask, the empty subset, which is exactly right.
</Hint>
<Hint>
For each mask, check every `i` from 0 to `items.count - 1` and append `items[i]` when bit `i` is set. Checking `i` in increasing order keeps the items in their original order.
</Hint>
<Hint>
There's also a way without masks: start with `[[]]`, and for each item, add a copy of every subset so far with that item appended. It produces exactly the same order. Can you see why?
</Hint>
</Hints>

## Solutions

<Approach title="Count through the masks" time="O(2ⁿ · n)" space="O(2ⁿ · n)">

Every number from 0 to 2ⁿ − 1 is one subset. Decode each by checking its bits from 0 upwards. The answer itself holds 2ⁿ subsets of up to n items, so the time and space can't be smaller than that.

```swift
public enum BitmaskSubsets {
    public static func subsets(of items: [Int]) -> [[Int]] {
        var result: [[Int]] = []
        for mask in 0..<(1 << items.count) {
            var subset: [Int] = []
            for i in 0..<items.count where mask & (1 << i) != 0 {
                subset.append(items[i])
            }
            result.append(subset)
        }
        return result
    }
}
```

For 16 items that's 65,536 subsets. A few more items and the answer would no longer fit comfortably in memory, which is why subset problems usually process each mask as they go instead of storing them all.

</Approach>

<Approach title="Double the list for each item" time="O(2ⁿ · n)" space="O(2ⁿ · n)">

Start with just the empty subset. Each new item doubles the list: every existing subset stays, and a copy with the item appended goes on the end.

```swift
public static func subsets(of items: [Int]) -> [[Int]] {
    var result: [[Int]] = [[]]
    for item in items {
        result += result.map { $0 + [item] }
    }
    return result
}
```

Why is the order the same as counting masks? After handling items 0 to `i - 1`, the list holds masks 0 to 2ⁱ − 1 in order. The copies with item `i` added are masks 2ⁱ to 2ⁱ⁺¹ − 1, the same subsets with bit `i` switched on, in the same order. You'll see this "include it or not" idea again as recursion and backtracking in M17 and Part VII.

</Approach>
