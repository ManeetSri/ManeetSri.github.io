A warehouse labels its shelves 1 to n. A robot inspects every shelf whose label is divisible by at least one number in `divisors`. Return how many shelves it inspects.

`AnyDivisorCounter.count(upTo n: Int, divisors: [Int]) -> Int`

The divisors are any positive numbers: they may repeat, divide one another, or be far larger than n.

## Examples

| `n` | `divisors` | Output | Why |
| --- | --- | --- | --- |
| `100` | `[2, 3, 5]` | `74` | 50 + 33 + 20 − 16 − 10 − 6 + 3 |
| `10` | `[4, 6]` | `3` | 4, 6 and 8 |
| `30` | `[6, 10, 15]` | `8` | 6, 10, 12, 15, 18, 20, 24, 30 |
| `60` | `[2, 4, 8]` | `30` | every multiple of 4 or 8 is already a multiple of 2 |
| `20` | `[1, 7]` | `20` | everything is divisible by 1 |
| `1_000_000_000_000_000_000` | `[1_000_000_000_000_000_000, 999_999_999_999_999_999]` | `2` | each divides only itself, and they share no multiple up to n |

## Constraints

- `1 ≤ n ≤ 10¹⁸`
- `1 ≤ divisors.count ≤ 20`
- `1 ≤ divisors[i] ≤ 10¹⁸`
- The tests use n = 10¹⁸ with the first 20 primes, whose product overflows `Int` long before you've multiplied them all.

<Hints>
<Hint>
Inclusion–exclusion: add the counts for single divisors, subtract the counts for pairs, add the counts for triples, and so on. The numbers up to n divisible by every divisor in a group are exactly the multiples of the group's lcm, and there are n / lcm of them.
</Hint>
<Hint>
Use the lcm, not the product: the numbers divisible by both 4 and 6 are the multiples of 12. Compute it one divisor at a time with lcm(a, d) = a / gcd(a, d) × d, dividing first.
</Hint>
<Hint>
If a group's lcm is bigger than n, its count is 0, and so is every larger group containing it, because adding divisors only makes the lcm bigger. Build groups depth first, and skip a branch as soon as the lcm passes n, or as soon as `multipliedReportingOverflow` reports that it doesn't even fit.
</Hint>
</Hints>

## Solutions

<Approach title="Check every shelf" time="O(n · k)" space="O(1)">

Loop over 1 to n and test each label against every divisor. It's the obvious reference for small n, and hopeless for n = 10¹⁸.

</Approach>

<Approach title="Inclusion–exclusion with lcms and pruning" time="O(2ᵏ log n) worst case" space="O(k)">

A depth-first search adds one divisor at a time to the current group, carrying its lcm and its size, which decides the sign.

```swift
public enum AnyDivisorCounter {
    public static func count(upTo n: Int, divisors: [Int]) -> Int {
        var total = 0
        func explore(from start: Int, lcm: Int, size: Int) {
            for i in start..<divisors.count {
                let d = divisors[i]
                let next = (lcm / gcd(lcm, d)).multipliedReportingOverflow(by: d)
                if next.overflow || next.partialValue > n { continue }   // this branch adds nothing
                total += (size % 2 == 0 ? 1 : -1) * (n / next.partialValue)
                explore(from: i + 1, lcm: next.partialValue, size: size + 1)
            }
        }
        explore(from: 0, lcm: 1, size: 0)
        return total
    }

    private static func gcd(_ a: Int, _ b: Int) -> Int {
        var (a, b) = (a, b)
        while b != 0 { (a, b) = (b, a % b) }
        return a
    }
}
```

`size` is the size of the group before adding divisor i, so the new group of size + 1 is added when `size` is even. Repeated divisors are handled automatically: the lcm doesn't change, and the plus and minus terms cancel exactly. You could also remove duplicates and any divisor that's a multiple of another one first, which makes the search smaller.

</Approach>
