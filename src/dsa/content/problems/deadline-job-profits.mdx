A print shop can do one job per hour, starting at hour 1. Each job is a pair `[deadline, profit]`: it takes exactly one hour, and it pays its profit only if it's done in hour `deadline` or earlier. Choose which jobs to take, and when, to earn as much as possible. Return the largest total profit.

`DeadlineJobProfits.maxProfit(_ jobs: [[Int]]) -> Int`

## Examples

| `jobs` | Output | Why |
| --- | --- | --- |
| `[[2, 40], [1, 25], [3, 30], [1, 35], [3, 10], [2, 20]]` | `105` | 35 in hour 1, 40 in hour 2, 30 in hour 3 |
| `[[1, 10], [2, 50], [2, 30], [1, 40]]` | `90` | 40 in hour 1, 50 in hour 2 |
| `[[1000000000, 5], [1, 7], [1, 3]]` | `12` | 7 in hour 1, 5 any time after |
| `[[3, 1], [3, 2], [3, 3], [3, 4]]` | `9` | only three hours before the deadline |
| `[]` | `0` | |

## Constraints

- `0 ≤ jobs.count ≤ 100,000`
- `1 ≤ deadline ≤ 10⁹` and `1 ≤ profit ≤ 1,000,000`
- Deadlines can be far larger than the number of jobs, so an array with one entry per hour up to the largest deadline won't fit in memory.
- The tests compare your answer with trying every subset of jobs on small inputs.

<Hints>
<Hint>
Think about the most profitable job. Is there a best schedule that includes it? And if you take it, which hour should it use, so that it gets in the way of as few other jobs as possible?
</Hint>
<Hint>
Consider jobs from most to least profitable, and put each one in the **latest** free hour at or before its deadline, or turn it down. With n jobs, you never need more than n hours, so cap every deadline at n.
</Hint>
<Hint>
Finding the latest free hour by walking back one hour at a time is too slow. Make each full hour point at the hour before it, and follow the pointers with union-find's `find`, using hour 0 to mean "none". Or turn it around: go through jobs by deadline, keep the accepted profits in a min-heap, and drop the smallest whenever there are more jobs than hours.
</Hint>
</Hints>

## Solutions

<Approach title="Try every subset" time="O(2ⁿ · n log n)" space="O(n)">

A set of jobs can all be done in time exactly when, sorted by deadline, the i-th job (counting from 1) has a deadline of at least i: doing them in deadline order is never worse than any other order. Try every subset and keep the most profitable that fits.

```swift
public static func maxProfit(_ jobs: [[Int]]) -> Int {
    var best = 0
    for mask in 0..<(1 << jobs.count) {
        let chosen = jobs.indices.filter { mask & (1 << $0) != 0 }.map { jobs[$0] }
        let deadlines = chosen.map { $0[0] }.sorted()
        if deadlines.indices.allSatisfy({ deadlines[$0] >= $0 + 1 }) {
            best = max(best, chosen.reduce(0) { $0 + $1[1] })
        }
    }
    return best
}
```

</Approach>

<Approach title="Most profitable first, with a union-find of free hours" time="O(n log n)" space="O(n)">

Some best schedule includes the most profitable job: if every hour up to its deadline is full, swap it in for any job there, which can only raise the profit. Putting it in the latest free hour keeps earlier hours, which more jobs can use, free. The union-find finds that hour quickly: a full hour points at the hour before it, and path compression flattens long chains of full hours.

```swift
public enum DeadlineJobProfits {
    public static func maxProfit(_ jobs: [[Int]]) -> Int {
        let n = jobs.count
        var parent = Array(0...n)                  // a free hour points at itself
        func latestFree(_ hour: Int) -> Int {
            var root = hour
            while parent[root] != root { root = parent[root] }
            var current = hour
            while parent[current] != root {        // path compression
                let next = parent[current]
                parent[current] = root
                current = next
            }
            return root
        }
        var total = 0
        for job in jobs.sorted(by: { $0[1] > $1[1] }) {
            let hour = latestFree(min(job[0], n))
            if hour > 0 {
                parent[hour] = hour - 1            // full: look one hour earlier next time
                total += job[1]
            }
        }
        return total
    }
}
```

</Approach>

<Approach title="By deadline, with a min-heap" time="O(n log n)" space="O(n)">

Go through the jobs in order of deadline, accepting each one and pushing its profit into a min-heap. If the heap now holds more jobs than the current deadline allows, the accepted jobs can't all fit, so drop the least profitable one. The heap always holds a set of jobs that fits, as profitable as possible.

```swift
import DSAKit

public enum DeadlineJobProfits {
    public static func maxProfit(_ jobs: [[Int]]) -> Int {
        var accepted = Heap<Int>.minHeap()
        for job in jobs.sorted(by: { $0[0] < $1[0] }) {
            accepted.insert(job[1])
            if accepted.count > job[0] {
                accepted.pop()                     // give up the least profitable job so far
            }
        }
        return accepted.unordered.reduce(0, +)
    }
}
```

</Approach>
