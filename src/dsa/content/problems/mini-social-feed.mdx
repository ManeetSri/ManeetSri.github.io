Build the core of a tiny social network. Users publish posts and follow each other, and each user's home feed shows the newest posts from themselves and everyone they follow. The feed also supports infinite scrolling: given the last post on screen, it returns the page of posts immediately older than it.

`MiniSocialFeed.Network`, with `init()`, `post(_:by:)`, `follow(follower:followee:)`, `unfollow(follower:followee:)` and `feed(for:limit:olderThan:) -> [Int]`

- `post(_ postID: Int, by user: Int)` publishes a post. Post ids are never reused. "Newer" means posted later: the order of the `post` calls.
- `follow` and `unfollow` change who `follower` follows. Following yourself, following someone twice, or unfollowing someone you don't follow changes nothing. Everyone always sees their own posts.
- `feed(for: user, limit: 10, olderThan: nil)` returns the ids of the `limit` newest posts by `user` and by everyone `user` follows **now**, newest first. After an unfollow, that person's old posts disappear from the feed; after following again, they come back.
- With `olderThan: cursor`, only posts published before the post `cursor` count. `cursor` is always the id of an existing post.
- For a user following f people, `feed` should be about O(f log n + limit × log f): it must not slow down because people the user doesn't follow post a lot.

## Examples

| Calls on a new `Network` | `feed(for: 1)` afterwards |
| --- | --- |
| `post(101, by: 1)` | `[101]` |
| `follow(follower: 1, followee: 2)`, `post(201, by: 2)`, `post(102, by: 1)`, `post(202, by: 2)` | `[202, 102, 201, 101]` |
| `unfollow(follower: 1, followee: 2)` | `[102, 101]` |
| `follow(follower: 1, followee: 2)` again | `[202, 102, 201, 101]` |

Paging: user 3 posts ids 1 to 25. `feed(for: 3, limit: 5)` is `[25, 24, 23, 22, 21]`, and `feed(for: 3, limit: 5, olderThan: 21)` is `[20, 19, 18, 17, 16]`. Repeating with the last id of each page eventually returns `[]`.

## Constraints

- Up to 200,000 posts and 1,000 users; a user can follow hundreds of others.
- `0 ≤ limit ≤ 1,000`; ids are any `Int`s.
- One test has a user who follows two quiet people while 200,000 posts arrive from everyone else, and then reads the feed 20,000 times.

Store the follow graph as `[Int: Set<Int>]`, and each user's posts as their own array of `(time, id)` pairs, stamped by one global counter that goes up with every post. Each user's array is then sorted by time, newest at the end. Keep a dictionary from post id to time as well, for the cursor.

<Hint>
A feed merges several sorted arrays, newest first, and stops after `limit` posts: the k-way merge from [Merge k sorted lists](/dsa/learn/heap-k-way-merge), in reverse. Put the newest post of each author (the user plus their followees) into a heap ordered by time, newest on top. Pop the top, then push that author's next older post. DSAKit's `Heap` works: `import DSAKit`.
</Hint>
<Hint>
For a cursor, look up the cursor post's time, and find in each author's array where the posts older than it end: a binary search, such as DSAKit's `partitionPoint(where:)`, for the first post with `time >= cursorTime`. Start that author at the position immediately before it.
</Hint>

## Solutions

<Approach title="Scan every post from the newest" time="O(total posts) per feed" space="O(posts)">

Keep every post in one global array and walk it backwards, keeping posts whose author the user can see, until `limit` are found. It's short and correct, and fast when the user follows most of the busy posters. But for a user who follows a few quiet people, it walks past almost every post in the network on every refresh.

```swift
public func feed(for user: Int, limit: Int = 10, olderThan cursor: Int? = nil) -> [Int] {
    let visible = (following[user] ?? []).union([user])
    var index = (cursor.flatMap { positionOfPost[$0] } ?? allPosts.count) - 1
    var result: [Int] = []
    while index >= 0 && result.count < limit {
        if visible.contains(allPosts[index].user) { result.append(allPosts[index].id) }
        index -= 1
    }
    return result
}
```

</Approach>

<Approach title="Per-user timelines merged with a heap" time="O(f log n + f + limit × log f) per feed" space="O(posts + follows)">

The heap holds at most one entry per author, so it never grows past f + 1. Building it with heapify from the starting entries is O(f), each pop and push is O(log f), and the binary searches for a cursor add O(log n) per author.

```swift
import DSAKit

public enum MiniSocialFeed {
    public struct Network {
        private var following: [Int: Set<Int>] = [:]
        private var posts: [Int: [(time: Int, id: Int)]] = [:]
        private var timeOfPost: [Int: Int] = [:]
        private var clock = 0

        public init() {}

        public mutating func post(_ postID: Int, by user: Int) {
            posts[user, default: []].append((clock, postID))
            timeOfPost[postID] = clock
            clock += 1
        }

        public mutating func follow(follower: Int, followee: Int) {
            guard follower != followee else { return }          // everyone sees their own posts anyway
            following[follower, default: []].insert(followee)
        }

        public mutating func unfollow(follower: Int, followee: Int) {
            following[follower]?.remove(followee)
        }

        public func feed(for user: Int, limit: Int = 10, olderThan cursor: Int? = nil) -> [Int] {
            guard limit > 0 else { return [] }
            let cutoff = cursor.map { timeOfPost[$0] ?? Int.min } ?? Int.max
            var authors = following[user] ?? []
            authors.insert(user)

            // One entry per author: the position of their newest post older than the cutoff
            var starts: [(time: Int, author: Int, position: Int)] = []
            for author in authors {
                guard let list = posts[author] else { continue }
                let end = list.partitionPoint { $0.time >= cutoff }
                if end > 0 {
                    starts.append((list[end - 1].time, author, end - 1))
                }
            }
            var newest = Heap(starts, areInIncreasingOrder: { $0.time > $1.time })   // O(f) heapify

            var result: [Int] = []
            while result.count < limit, let top = newest.pop() {
                let list = posts[top.author]!
                result.append(list[top.position].id)
                if top.position > 0 {
                    newest.insert((list[top.position - 1].time, top.author, top.position - 1))
                }
            }
            return result
        }
    }
}
```

This is the **pull** model: the feed is assembled when it's read. Real networks often **push** instead, copying each new post into every follower's stored feed when it's published, which makes reading O(limit) but makes a post by someone with millions of followers very expensive. The lesson compares the two.

</Approach>
