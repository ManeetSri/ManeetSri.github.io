Values arrive one at a time. After each arrival, report how out of order everything so far is, measured as the number of **inversions**: pairs where an earlier arrival is strictly greater than a later one. Element i of the result is the number of inversions among `values[0...i]`.

`ArrivalDisorder.inversionCounts(_ values: [Int]) -> [Int]`

## Examples

| `values` | Output |
| --- | --- |
| `[3, 1, 2, 5, 4, 1]` | `[0, 1, 2, 2, 3, 7]` |
| `[4, 3, 2, 1]` | `[0, 1, 3, 6]` |
| `[1, 2, 3, 4]` | `[0, 0, 0, 0]` |
| `[2, 2, 2]` | `[0, 0, 0]` |
| `[]` | `[]` |

In the first example, the 1 at index 1 is smaller than the 3 before it: one inversion. The 2 adds one more (3 is before it), the 5 adds none, the 4 adds one (the 5), and the final 1 adds four: 3, 2, 5 and 4 are all greater, but the earlier 1 isn't, because equal values don't count.

## Constraints

- `0 ≤ values.count ≤ 100,000`
- Values can be any `Int`.
- The counts can reach about 5 × 10⁹, so they need 64-bit `Int`s, which Swift's `Int` is.
- The tests use 100,000 values, so comparing each new value with every earlier one is too slow.

<Hints>
<Hint>
The new inversions when x arrives at index i are the earlier values strictly greater than x. There are i earlier values, so that's i minus the number of earlier values that are at most x.
</Hint>
<Hint>
"How many of the values seen so far are at most x?" is a prefix count over values. A Fenwick tree indexed by value answers it in O(log n), and recording x is adding 1 at x.
</Hint>
<Hint>
Values can be huge or negative, but only their order matters. Replace each by its rank among the distinct values (coordinate compression), counting from 1, and index the tree by rank.
</Hint>
</Hints>

## Solutions

<Approach title="Compare with every earlier value" time="O(n²)" space="O(n)">

For each new value, count the earlier values greater than it and add to a running total. Simple and clearly right, but 100,000 values is five billion comparisons.

```swift
public static func inversionCounts(_ values: [Int]) -> [Int] {
    var total = 0
    return values.indices.map { j in
        for i in 0..<j where values[i] > values[j] {
            total += 1
        }
        return total
    }
}
```

</Approach>

<Approach title="Coordinate compression and a Fenwick tree" time="O(n log n)" space="O(n)">

The left-to-right scan from [Inversions and count of smaller numbers after self](/dsa/learn/bit-inversions), reporting the running total after every value instead of only at the end. The tree counts arrivals by rank; `atMost` is the prefix count up to the new value's rank, which includes equal values, so only strictly greater ones become inversions.

```swift
public enum ArrivalDisorder {
    public static func inversionCounts(_ values: [Int]) -> [Int] {
        let distinct = Array(Set(values)).sorted()
        var rankOf: [Int: Int] = [:]
        for (offset, value) in distinct.enumerated() {
            rankOf[value] = offset + 1
        }

        var tree = Array(repeating: 0, count: distinct.count + 1)   // counts by rank, 1-indexed
        var total = 0
        var result: [Int] = []
        result.reserveCapacity(values.count)
        for (index, value) in values.enumerated() {
            let rank = rankOf[value]!
            var atMost = 0                                         // earlier items with rank <= this one
            var i = rank
            while i > 0 {
                atMost += tree[i]
                i -= i & -i
            }
            total += index - atMost                                // the earlier items that are greater
            result.append(total)
            i = rank
            while i < tree.count {
                tree[i] += 1
                i += i & -i
            }
        }
        return result
    }
}
```

Merge sort, from [Counting inversions](/dsa/learn/sort-inversions), finds the final total in O(n log n) too, but it needs the whole array at once: it can't easily report the count after each arrival. The Fenwick tree can, and if the values were known to be small, it wouldn't even need them in advance.

</Approach>
