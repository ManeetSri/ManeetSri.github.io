Write three functions that round a whole number to a multiple of `step`: down, up and to the nearest. They share the base name `rounded`, and their argument labels say which is which, so each call reads like a phrase: `rounded(17, downToMultipleOf: 5)` is 15.

`MultipleRounding.rounded(_ value: Int, downToMultipleOf step: Int) -> Int`, `MultipleRounding.rounded(_ value: Int, upToMultipleOf step: Int) -> Int` and `MultipleRounding.rounded(_ value: Int, toNearestMultipleOf step: Int) -> Int`

- **Down** gives the largest multiple of `step` that is less than or equal to `value`.
- **Up** gives the smallest multiple of `step` that is greater than or equal to `value`.
- **Nearest** gives whichever of those two is closer to `value`. When they're equally close, it gives the larger one.

A value that is already a multiple of `step` comes back unchanged from all three.

## Examples

| Call | Result |
| --- | --- |
| `rounded(17, downToMultipleOf: 5)` | `15` |
| `rounded(17, upToMultipleOf: 5)` | `20` |
| `rounded(17, toNearestMultipleOf: 5)` | `15` |
| `rounded(18, toNearestMultipleOf: 5)` | `20` |
| `rounded(15, toNearestMultipleOf: 10)` | `20` (a tie goes up) |
| `rounded(-7, downToMultipleOf: 5)` | `-10` |
| `rounded(-7, upToMultipleOf: 5)` | `-5` |
| `rounded(-15, toNearestMultipleOf: 10)` | `-10` (a tie goes up, towards the larger number) |
| `rounded(30, upToMultipleOf: 6)` | `30` |

"Down" means towards smaller numbers, so rounding `-7` down gives `-10`, not `-5`.

## Constraints

- `-1,000,000,000 ≤ value ≤ 1,000,000,000`
- `1 ≤ step ≤ 1,000,000,000`

<Hints>
<Hint>
Write the "down" function first. The other two can call it: inside the type, `rounded(value, downToMultipleOf: step)` picks that function because of its label.
</Hint>
<Hint>
`value % step` is how far `value` sits above a multiple, but only for values that aren't negative. Swift's `%` keeps the sign of the left side, so `-7 % 5` is `-2`, and `-7 - (-2)` is `-5`: that rounds towards zero, not down. When the remainder is negative, go down one more `step`.
</Hint>
<Hint>
Once you have the multiple below, the multiple above is the same number when `value` is already a multiple, and `step` more otherwise. For "nearest", compare `value - down` with `up - value`, and pick `down` only when it's strictly closer.
</Hint>
</Hints>

## Solutions

<Approach title="Build everything on rounding down" time="O(1)" space="O(1)">

Rounding down is the only one with a trap, the sign of `%` for negative values, so solve it once and reuse it. Rounding up adds one `step` unless the value is already a multiple, and rounding to the nearest compares the distances to the two candidates.

```swift
public enum MultipleRounding {
    public static func rounded(_ value: Int, downToMultipleOf step: Int) -> Int {
        let remainder = value % step
        if remainder < 0 {
            return value - remainder - step
        }
        return value - remainder
    }

    public static func rounded(_ value: Int, upToMultipleOf step: Int) -> Int {
        let down = rounded(value, downToMultipleOf: step)
        return down == value ? value : down + step
    }

    public static func rounded(_ value: Int, toNearestMultipleOf step: Int) -> Int {
        let down = rounded(value, downToMultipleOf: step)
        let up = rounded(value, upToMultipleOf: step)
        return value - down < up - value ? down : up
    }
}
```

Check the trap with `-7` and a step of 5: the remainder is `-2`, which is negative, so the result is `-7 + 2 - 5`, which is `-10`. For `17` the remainder is `2`, so the result is `15`.

These are three different functions, `rounded(_:downToMultipleOf:)`, `rounded(_:upToMultipleOf:)` and `rounded(_:toNearestMultipleOf:)`. Swift tells them apart by their labels alone, which is why the calls inside the bodies need no special syntax.

</Approach>
