Linear search walks through `items` from the front, comparing each element with the target, and stops at the first match. If the target isn't there, it compares against every element. Given the items and a list of queries, work out how many comparisons each query costs, and report the **best case**, the **worst case** and the **total** over all queries (the average is the total divided by the number of queries).

`SearchCaseTally.tally(items: [Int], queries: [Int]) -> Tally`

`Tally` has three properties: `best`, `worst` and `total`.

## Examples

| `items` | `queries` | Output | Why |
| --- | --- | --- | --- |
| `[4, 8, 15, 16, 23, 42]` | `[4, 42, 7, 16]` | best 1, worst 6, total 17 | 1, 6, 6 (7 is missing), 4 |
| `[5, 3, 5, 3]` | `[3, 5, 9]` | best 1, worst 4, total 7 | 2, 1, 4: the search stops at the first 5 and the first 3 |
| `[]` | `[1, 2]` | best 0, worst 0, total 0 | there's nothing to compare against |

## Constraints

- `0 ≤ items.count ≤ 10⁵`, `1 ≤ queries.count ≤ 10⁵`.
- Values are any `Int`, and `items` can contain duplicates.
- Running the search for every query could take 10¹⁰ comparisons in total. Find each query's cost without searching.

<Hints>
<Hint>
A query's cost depends on only one thing: the position of the **first** element equal to it. If that's index i, the search makes i + 1 comparisons. If there's no such element, it makes `items.count`.
</Hint>
<Hint>
Walk through `items` once, recording the first index of every value in a dictionary. Only record a value the first time you see it, so later duplicates don't overwrite it.
</Hint>
<Hint>
Then each query is one dictionary lookup: `firstIndex[query].map { $0 + 1 } ?? items.count`. Track the smallest, the largest and the running total as you go. Start `best` at `Int.max` and `worst` at 0, since there's always at least one query.
</Hint>
</Hints>

## Solutions

<Approach title="Run every search" time="O(n · q)" space="O(1)">

Simulate linear search for each query and count. It's the definition, and a good check, but with 10⁵ items and 10⁵ missing queries it does 10¹⁰ comparisons.

```swift
public static func tally(items: [Int], queries: [Int]) -> Tally {
    var costs: [Int] = []
    for query in queries {
        var comparisons = 0
        for item in items {
            comparisons += 1
            if item == query { break }
        }
        costs.append(comparisons)
    }
    return Tally(best: costs.min()!, worst: costs.max()!, total: costs.reduce(0, +))
}
```

</Approach>

<Approach title="Look up the first position" time="O(n + q) on average" space="O(n)">

One pass over `items` stores where each value first appears. After that, a query's cost is a single lookup. This is the "trading space for time" move from the space lesson, and it turns an O(n · q) tally into O(n + q).

```swift
public enum SearchCaseTally {
    public struct Tally: Equatable {
        public var best: Int
        public var worst: Int
        public var total: Int

        public init(best: Int, worst: Int, total: Int) {
            self.best = best
            self.worst = worst
            self.total = total
        }
    }

    public static func tally(items: [Int], queries: [Int]) -> Tally {
        var firstIndex: [Int: Int] = [:]
        for (index, item) in items.enumerated() where firstIndex[item] == nil {
            firstIndex[item] = index
        }
        var result = Tally(best: Int.max, worst: 0, total: 0)
        for query in queries {
            let cost = firstIndex[query].map { $0 + 1 } ?? items.count
            result.best = min(result.best, cost)
            result.worst = max(result.worst, cost)
            result.total += cost
        }
        return result
    }
}
```

The worst case is always a missing target, or one whose first copy is last. When every query is missing, best, worst and average all equal n: the cases only differ when the inputs do.

</Approach>
