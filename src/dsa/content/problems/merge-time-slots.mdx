A shared calendar gathers everyone's busy slots for the day, in no particular order. Merge every group of slots that overlap or touch into a single slot, and return the merged slots sorted by start.

`MergeTimeSlots.merge(_ slots: [[Int]]) -> [[Int]]`

Each slot is a pair `[start, end]`, and slots are **closed**: a slot includes both its ends. So `[9, 10]` and `[10, 11]` touch at 10 and merge into `[9, 11]`, while `[1, 2]` and `[3, 4]` stay apart.

## Examples

| `slots` | Output |
| --- | --- |
| `[[9, 12], [1, 4], [3, 6], [12, 14], [20, 22]]` | `[[1, 6], [9, 14], [20, 22]]` |
| `[[5, 9], [6, 7]]` | `[[5, 9]]` |
| `[[1, 2], [3, 4]]` | `[[1, 2], [3, 4]]` |
| `[[4, 4], [4, 6]]` | `[[4, 6]]` |
| `[]` | `[]` |

In the first example, `[1, 4]` and `[3, 6]` overlap, and `[9, 12]` and `[12, 14]` touch at 12. In the second, `[6, 7]` lies entirely inside `[5, 9]`.

## Constraints

- `0 ≤ slots.count ≤ 200,000`
- Each slot has exactly two values, with `start ≤ end`, both between −10⁹ and 10⁹.
- Aim for O(n log n) time. Comparing every pair of slots could take 2 × 10¹⁰ steps.

<Hints>
<Hint>
Sort the slots by start. Once they're sorted, where in the list can the slots that overlap a given slot be?
</Hint>
<Hint>
Walk the sorted slots while building the merged list. Compare each slot with the **last merged** slot, not with the slot before it in the input: after `[1, 10]` and `[2, 3]`, the next slot must be compared with 10.
</Hint>
<Hint>
If the slot starts at or before the last merged slot's end, stretch that end to the larger of the two ends (the slot might sit entirely inside). Otherwise, append it as a new merged slot. To change the last merged slot in place, write through the array: `merged[merged.count - 1][1] = …`.
</Hint>
</Hints>

## Solutions

<Approach title="Sort by start, then one pass" time="O(n log n)" space="O(n)">

After sorting by start, every slot that overlaps the merged slot being built comes straight after it. As soon as a slot starts after the current end, every later slot starts later still, so the current merged slot is finished and the new one begins.

```swift
public enum MergeTimeSlots {
    public static func merge(_ slots: [[Int]]) -> [[Int]] {
        let sorted = slots.sorted { $0[0] < $1[0] }
        var merged: [[Int]] = []
        merged.reserveCapacity(sorted.count)
        for slot in sorted {
            if let last = merged.last, slot[0] <= last[1] {
                merged[merged.count - 1][1] = max(last[1], slot[1])   // overlap or touch: stretch
            } else {
                merged.append(slot)                                   // a gap: a new merged slot
            }
        }
        return merged
    }
}
```

`if let last = merged.last, …` covers the first slot, when there's nothing to compare with yet. `last` is a copy, which is fine for reading; the write goes through `merged[merged.count - 1]` so that it changes the array itself. The `<=` is what makes touching slots merge: for half-open slots, where touching doesn't count as overlapping, it would be `<`.

</Approach>
