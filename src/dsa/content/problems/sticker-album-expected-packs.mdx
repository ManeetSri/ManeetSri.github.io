A sticker album has one space for each of `weights.count` stickers. Each pack you open holds a single sticker, and it's sticker i with probability `weights[i] / (sum of all weights)`, independently of every other pack. Rare stickers have small weights. Return the expected number of packs you'll open before every sticker has turned up at least once.

`StickerAlbumExpectedPacks.expectedPacks(weights: [Int]) -> Double`

## Examples

| `weights` | Output |
| --- | --- |
| `[5]` | `1.0` |
| `[1, 1]` | `3.0` |
| `[1, 3]` | `4.333333…` (13/3) |
| `[2, 2, 2]` | `5.5` |
| `[1, 1, 1, 1, 1, 1]` | `14.7` |

With one sticker, the first pack finishes the album. With two equally likely stickers, the first pack gives you one, and then you wait for the other, which takes 2 packs on average: 3 in all. With six equal stickers, this is waiting to see every face of a die, 6 · (1 + 1/2 + … + 1/6) = 14.7.

## Constraints

- `1 ≤ weights.count ≤ 16`
- `1 ≤ weights[i] ≤ 1,000`
- Answers are checked to within a millionth of their size, so ordinary `Double` arithmetic is fine.

<Hints>
<Hint>
When the stickers are equally likely, "how many different stickers do I have" is enough to describe where you are. Why isn't it enough when they aren't?
</Hint>
<Hint>
Use the set of stickers you have, as a bitmask. Let `expected[mask]` be the packs still to open from there, with `expected[full] = 0`. The next pack either repeats a sticker in `mask` or brings a new sticker i.
</Hint>
<Hint>
With `have` the total probability of the stickers in `mask`: `expected[mask] = 1 + have · expected[mask] + Σ p[i] · expected[mask | (1 << i)]` over the missing i. Solve that for `expected[mask]`, and fill the masks from largest to smallest.
</Hint>
</Hints>

## Solutions

<Approach title="Expected-value DP over the collected set" time="O(2ⁿ · n)" space="O(2ⁿ)">

Repeats keep you in the same state, which is a self-loop: `expected[mask]` appears on both sides of its own equation. Moving it to the left gives `expected[mask] = (1 + Σ p[i] · expected[mask | (1 << i)]) / (1 − have)`. Everything on the right is a bigger mask, so a loop from `full - 1` down to 0 always has what it needs. The `have` table is built in O(2ⁿ) by adding each mask's lowest sticker to the mask without it.

```swift
public enum StickerAlbumExpectedPacks {
    public static func expectedPacks(weights: [Int]) -> Double {
        let n = weights.count
        let total = Double(weights.reduce(0, +))
        let p = weights.map { Double($0) / total }
        let full = (1 << n) - 1

        var have = [Double](repeating: 0, count: full + 1)    // probability of a sticker already in mask
        for mask in 1...full {
            have[mask] = have[mask & (mask - 1)] + p[mask.trailingZeroBitCount]
        }

        var expected = [Double](repeating: 0, count: full + 1)
        for mask in stride(from: full - 1, through: 0, by: -1) {
            var sum = 1.0
            for i in 0..<n where mask & (1 << i) == 0 {
                sum += p[i] * expected[mask | (1 << i)]
            }
            expected[mask] = sum / (1 - have[mask])
        }
        return expected[0]
    }
}
```

`1 - have[mask]` is never 0 for `mask` below `full`, because at least one sticker with a positive weight is still missing.

</Approach>

<Approach title="Inclusion–exclusion" time="O(2ⁿ · n)" space="O(1)">

There's also a formula. The packs needed is the largest of the waiting times for each sticker, and inclusion–exclusion over sets of stickers turns that into a sum: over every non-empty set S, add `1 / P(S)` when S has an odd number of stickers and subtract it when even, where `P(S)` is the chance a pack is in S. The tests use this formula to check your answer. It's elegant, but the DP is the method that carries over to processes with more complicated rules.

</Approach>
