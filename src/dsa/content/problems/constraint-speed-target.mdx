A problem's constraints tell you how fast your solution has to be. Turn the lesson's table into code: given the largest input size `n` that a problem allows, return the slowest complexity that would still pass.

`ConstraintSpeedTarget.aim(forMaxN maxN: Int) -> String`

Use exactly these rows. "At most" includes the limit itself:

| If `maxN` is at most… | Return |
| --- | --- |
| 10 | `"O(n!)"` |
| 20 | `"O(2^n)"` |
| 500 | `"O(n^3)"` |
| 5,000 | `"O(n^2)"` |
| 1,000,000 | `"O(n log n)"` |
| anything larger | `"O(log n)"` |

Powers are written with `^` so you can type them. The lesson's table jumps from 1,000,000 to 10⁹; this problem closes the gap, so **every** size above 1,000,000 gives `"O(log n)"`.

If you're brand new to Swift, read this statement now, as practice at reading problems, and come back to code it after M03, where you'll learn `if` and `switch`.

## Examples

| Call | Returns | Why |
| --- | --- | --- |
| `aim(forMaxN: 8)` | `"O(n!)"` | 8 is at most 10 |
| `aim(forMaxN: 20)` | `"O(2^n)"` | the limit itself counts |
| `aim(forMaxN: 21)` | `"O(n^3)"` | one past 20 moves down a row |
| `aim(forMaxN: 100_000)` | `"O(n log n)"` | the most common size in interviews |
| `aim(forMaxN: 1_000_001)` | `"O(log n)"` | everything above 1,000,000 |

## Constraints

- `1 ≤ maxN ≤ 10¹⁸`
- The returned text must match exactly, including the space in `"O(n log n)"` and the capital `O`.

<Hints>
<Hint>
Check the limits from the smallest upwards. The first row whose limit is at least `maxN` is the answer.
</Hint>
<Hint>
"At most 20" means `maxN <= 20`, not `maxN < 20`. The boundaries are where careless readings go wrong, so try 20 and 21 by hand.
</Hint>
<Hint>
An `if … else if … else` chain from 10 up to 1,000,000 works. So does a `switch` whose cases are one-sided ranges such as `case ...10:`, because a `switch` takes the first case that matches.
</Hint>
</Hints>

## Solutions

<Approach title="An if chain, smallest limit first" time="O(1)" space="O(1)">

Because the limits are checked in increasing order, reaching a later line means every smaller limit has already been ruled out. So each condition only needs one comparison.

```swift
public enum ConstraintSpeedTarget {
    public static func aim(forMaxN maxN: Int) -> String {
        if maxN <= 10 {
            return "O(n!)"
        } else if maxN <= 20 {
            return "O(2^n)"
        } else if maxN <= 500 {
            return "O(n^3)"
        } else if maxN <= 5_000 {
            return "O(n^2)"
        } else if maxN <= 1_000_000 {
            return "O(n log n)"
        } else {
            return "O(log n)"
        }
    }
}
```

</Approach>

<Approach title="A switch over one-sided ranges" time="O(1)" space="O(1)">

`...10` is the range of every number up to and including 10. A `switch` tries its cases from the top and stops at the first match, so `case ...20:` only ever sees numbers above 10.

```swift
public enum ConstraintSpeedTarget {
    public static func aim(forMaxN maxN: Int) -> String {
        switch maxN {
        case ...10: return "O(n!)"
        case ...20: return "O(2^n)"
        case ...500: return "O(n^3)"
        case ...5_000: return "O(n^2)"
        case ...1_000_000: return "O(n log n)"
        default: return "O(log n)"
        }
    }
}
```

Both versions read like the table. Notice how the problem's wording ("at most", "anything larger") decided `<=` rather than `<`, and what happens in the gap the lesson's table left open.

</Approach>
