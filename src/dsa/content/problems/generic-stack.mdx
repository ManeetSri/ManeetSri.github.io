Build a generic stack, then use it to apply a list of edits that includes undo.

`GenericStack.Stack<Element>`, with `init()`, `push(_:)`, `pop() -> Element?`, `peek() -> Element?`, `isEmpty: Bool` and `count: Int`, and `GenericStack.finalText(after edits: [String]) -> String`

**Part 1: the stack.** The last element pushed is the first popped. `pop()` removes and returns the top element; `peek()` returns it without removing it. Both return `nil` when the stack is empty. Add whatever private storage you need.

**Part 2: undo.** Each edit is either a word to add, or the exact text `"UNDO"`, which removes the most recently added word that's still there. An `"UNDO"` with no words left does nothing. Return the remaining words in the order they were added, joined by single spaces, or `""` if none remain. Use your `Stack<String>`.

## Examples

| Code | Result |
| --- | --- |
| push 1, push 2, push 3, then `pop()` | `3` |
| push `"a"`, push `"b"`, then `peek()` and `count` | `"b"` and `2` |
| `Stack<Int>().pop()` | `nil` |
| `finalText(after: ["I", "love", "Swift", "UNDO", "DSA"])` | `"I love DSA"` |
| `finalText(after: ["one", "two", "UNDO", "UNDO", "three"])` | `"three"` |
| `finalText(after: ["UNDO", "hello"])` | `"hello"` |

## Constraints

- A stack may hold up to 100,000 elements. `push` should be O(1) on average, and `pop`, `peek`, `isEmpty` and `count` O(1).
- `0 ≤ edits.count ≤ 10,000`
- Copying a stack gives an independent stack, as with any struct.

<Hints>
<Hint>
Store the elements in a `private var items: [Element] = []`. Which end of the array should be the top, so that adding and removing never shifts the other elements?
</Hint>
<Hint>
The end. `append`, `popLast()` and `last` do exactly what `push`, `pop` and `peek` need, and `popLast()` already returns `nil` for an empty array.
</Hint>
<Hint>
For `finalText`, push each word and pop on `"UNDO"`. At the end, popping everything gives the words newest first, so reverse them before `joined(separator: " ")`.
</Hint>
</Hints>

## Solutions

<Approach title="The end of an array as the top" time="O(1) per operation, O(n) for finalText" space="O(n)">

Every stack operation maps onto an array operation at the end, so nothing ever shifts. `finalText` is a direct use of the stack: undo is "take back the most recent thing", which is exactly what `pop` does.

```swift
public enum GenericStack {
    public struct Stack<Element> {
        private var items: [Element] = []

        public init() {}

        public mutating func push(_ element: Element) {
            items.append(element)
        }

        public mutating func pop() -> Element? {
            items.popLast()
        }

        public func peek() -> Element? {
            items.last
        }

        public var isEmpty: Bool {
            items.isEmpty
        }

        public var count: Int {
            items.count
        }
    }

    public static func finalText(after edits: [String]) -> String {
        var words = Stack<String>()
        for edit in edits {
            if edit == "UNDO" {
                _ = words.pop()
            } else {
                words.push(edit)
            }
        }
        var newestFirst: [String] = []
        while let word = words.pop() {
            newestFirst.append(word)
        }
        return newestFirst.reversed().joined(separator: " ")
    }
}
```

`_ = words.pop()` says "pop, and I don't need the value". An undo on an empty stack pops `nil`, which is ignored, so no special case is needed. Using the **front** of the array as the top would also pass the small tests, but every push and pop would shift all the other elements: O(n) each instead of O(1).

</Approach>
