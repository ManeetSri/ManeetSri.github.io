A chat app keeps a list of banned words. Given the list and a message, return how many times each word occurs in the message, in the same order as `words`. Occurrences may overlap, and a word inside another word still counts: in `"ushers"`, both `he` and `she` occur.

`BannedWordSweep.counts(of words: [String], in message: String) -> [Int]`

## Examples

| `words` | `message` | Output |
| --- | --- | --- |
| `["he", "she", "his", "hers"]` | `"ahishers"` | `[1, 1, 1, 1]` |
| `["he", "she", "his", "hers"]` | `"shehershishe"` | `[3, 2, 1, 1]` |
| `["a", "aa", "aaa"]` | `"aaaa"` | `[4, 3, 2]` |
| `["cat", "cat"]` | `"catcat"` | `[2, 2]` |
| `["toolong"]` | `"short"` | `[0]` |
| `[]` | `"anything"` | `[]` |

A word listed twice gets its count twice.

## Constraints

- Every word and the message hold lowercase letters, a to z. No word is empty.
- `0 ≤ words.count ≤ 10,000`, and the words' lengths add up to at most 100,000.
- `0 ≤ message.count ≤ 100,000`
- The tests include the 400 words `a`, `aa`, …, up to 400 `a`s, in a message of 100,000 `a`s: about 40 million occurrences to count. Searching for each word separately is O(n) per word at best, and listing every occurrence one by one is slow too.

<Hints>
<Hint>
Searching for each word on its own repeats the same work for words that share letters. Put all the words in one trie, and walk the message through it once.
</Hint>
<Hint>
When the next letter has no child, don't restart: follow a **failure link** to the node for the longest suffix of what you've read that is still in the trie, as KMP does with one pattern. Build the links in BFS order, so each node's link comes from its parent's link.
</Hint>
<Hint>
Reaching a node means its word ends here, and so does every word down its failure chain. Instead of walking the chain at every letter, count how often each node is reached, then add each node's count to its failure link's, deepest nodes first. A word's answer is the total at its end node.
</Hint>
</Hints>

## Solutions

<Approach title="Search for each word separately" time="O(k · n) or worse" space="O(1)">

KMP once per word is O(n + |word|) each: 10,000 words in a 100,000-letter message is a billion steps, and naive matching is worse. Fine for a handful of words.

</Approach>

<Approach title="Aho–Corasick, counting over the failure tree" time="O(L · 26 + n)" space="O(L · 26)">

Build the trie with a flat 26-slot table per node, compute failure links by BFS while filling missing children, so the scan is one table lookup per letter, then count visits and push them up the failure links in reverse BFS order.

```swift
public enum BannedWordSweep {
    public static func counts(of words: [String], in message: String) -> [Int] {
        var next = [Int32](repeating: -1, count: 26)
        var nodes = 1
        var endNode = [Int](repeating: 0, count: words.count)
        for (index, word) in words.enumerated() {
            var node = 0
            for byte in word.utf8 {
                let slot = 26 * node + Int(byte - 97)
                if next[slot] == -1 {
                    next[slot] = Int32(nodes)
                    nodes += 1
                    next.append(contentsOf: repeatElement(-1, count: 26))
                }
                node = Int(next[slot])
            }
            endNode[index] = node
        }

        var link = [Int](repeating: 0, count: nodes)
        var order: [Int] = []
        for c in 0..<26 {
            if next[c] == -1 {
                next[c] = 0
            } else {
                order.append(Int(next[c]))
            }
        }
        var head = 0
        while head < order.count {
            let v = order[head]
            head += 1
            for c in 0..<26 {
                let child = Int(next[26 * v + c])
                let fallback = next[26 * link[v] + c]
                if child != -1 {
                    link[child] = Int(fallback)
                    order.append(child)
                } else {
                    next[26 * v + c] = fallback
                }
            }
        }

        var visits = [Int](repeating: 0, count: nodes)
        var node = 0
        for byte in message.utf8 {
            node = Int(next[26 * node + Int(byte - 97)])
            visits[node] += 1
        }
        for v in order.reversed() {
            visits[link[v]] += visits[v]
        }
        return endNode.map { visits[$0] }
    }
}
```

Duplicate words end at the same node, so they read the same total. The time doesn't depend on how many occurrences there are: 40 million matches cost nothing extra.

</Approach>

<Approach title="Aho–Corasick with output links" time="O(L · 26 + n + occurrences)" space="O(L · 26)">

Give every node an output link, the nearest node down its failure chain where a word ends, and at each letter walk the output links from the current node, adding 1 to each word found. That's the version to use when you need each occurrence's *position*, not just counts. Here it walks about 40 million links on the nested-words test, which works but is far slower than summing over the failure tree.

</Approach>
