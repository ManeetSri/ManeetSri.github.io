A bag holds whole numbers from 1 to 1,000,000, duplicates allowed, and starts empty. Numbers are put in and taken out, and in between you're asked for the kth smallest number in the bag. Answer every question.

`ChangingBagKth.process(_ operations: [[Int]]) -> [Int]`

Each operation is one of:

- `[0, x]`: put one x in the bag;
- `[1, x]`: take one x out, if the bag has one; if it doesn't, nothing happens;
- `[2, k]`: ask for the kth smallest number in the bag, counting from 1, with duplicates counted separately, or `-1` if the bag holds fewer than k numbers.

Return the answers to the questions, in order.

## Examples

`[[0, 5], [0, 2], [0, 9], [2, 2], [0, 2], [2, 2], [1, 2], [1, 7], [2, 3], [2, 4]]` gives `[5, 2, 9, -1]`:

| Operation | Bag afterwards, sorted | Output |
| --- | --- | --- |
| `[0, 5]`, `[0, 2]`, `[0, 9]` | 2, 5, 9 | |
| `[2, 2]` | | `5` |
| `[0, 2]` | 2, 2, 5, 9 | |
| `[2, 2]` | | `2` |
| `[1, 2]` | 2, 5, 9 | |
| `[1, 7]` | 2, 5, 9 (there's no 7) | |
| `[2, 3]` | | `9` |
| `[2, 4]` | | `-1` |

## Constraints

- Up to 200,000 operations.
- `1 ≤ x ≤ 1,000,000` and `1 ≤ k ≤ 200,000`.
- The tests keep up to about 130,000 numbers in the bag, so a sorted array, which shifts elements on every insertion and removal, is too slow.

<Hints>
<Hint>
The numbers are small enough to index an array. Keep `count[x]`, how many copies of x are in the bag. The kth smallest is the first x where `count[1] + … + count[x]` reaches k.
</Hint>
<Hint>
Running totals of counts that change: a Fenwick tree indexed by value. Putting x in adds 1 at x; taking it out adds −1. Keep the plain counts too, so you can tell whether a removal is possible.
</Hint>
<Hint>
To find the first x whose prefix count reaches k, binary search over x (each step a prefix sum, O(log² V) in total), or walk down the tree's powers of two: from the largest power of two down, jump over the next block of values whenever its slot holds fewer than the numbers you still need.
</Hint>
</Hints>

## Solutions

<Approach title="A sorted array" time="O(n) per change, O(1) per question" space="O(n)">

Insert each number in its sorted place, remove one copy by finding it, and read the kth element directly. Simple, but each insertion and removal shifts up to the whole array.

```swift
public static func process(_ operations: [[Int]]) -> [Int] {
    var bag: [Int] = []
    var answers: [Int] = []
    for operation in operations {
        switch operation[0] {
        case 0:
            let position = bag.firstIndex { $0 > operation[1] } ?? bag.count
            bag.insert(operation[1], at: position)
        case 1:
            if let position = bag.firstIndex(of: operation[1]) { bag.remove(at: position) }
        default:
            answers.append(operation[1] <= bag.count ? bag[operation[1] - 1] : -1)
        }
    }
    return answers
}
```

</Approach>

<Approach title="Fenwick tree of counts, with binary lifting" time="O(log V) per operation" space="O(V)">

The structure from [Order statistics with a BIT](/dsa/learn/bit-order-statistics), with V = 1,000,000. `position` is always the largest value known to have fewer than k numbers at or below it; the slot `position + step` covers exactly the next `step` values, so one lookup decides whether to jump over them.

```swift
public enum ChangingBagKth {
    private static let largestValue = 1_000_000

    public static func process(_ operations: [[Int]]) -> [Int] {
        var tree = Array(repeating: 0, count: largestValue + 1)   // 1-indexed by value
        var copies = Array(repeating: 0, count: largestValue + 1)
        var size = 0
        var highestStep = 1
        while highestStep * 2 <= largestValue { highestStep *= 2 }

        func change(_ value: Int, by delta: Int) {
            var i = value
            while i <= largestValue {
                tree[i] += delta
                i += i & -i
            }
        }

        var answers: [Int] = []
        for operation in operations {
            switch operation[0] {
            case 0:
                change(operation[1], by: 1)
                copies[operation[1]] += 1
                size += 1
            case 1:
                guard copies[operation[1]] > 0 else { continue }  // not in the bag: nothing happens
                change(operation[1], by: -1)
                copies[operation[1]] -= 1
                size -= 1
            default:
                let k = operation[1]
                guard k <= size else {
                    answers.append(-1)
                    continue
                }
                var position = 0, remaining = k, step = highestStep
                while step > 0 {
                    let next = position + step
                    if next <= largestValue && tree[next] < remaining {
                        position = next                           // values up to next hold too few
                        remaining -= tree[next]
                    }
                    step /= 2
                }
                answers.append(position + 1)
            }
        }
        return answers
    }
}
```

With DSAKit, `FenwickTree(count: 1_000_001)` indexed directly by value does the same job: `add(1, at: x)`, `add(-1, at: x)`, and `lowerBound(prefix: k)` for the kth smallest.

</Approach>
