A region has `towns` towns, numbered `0` to `towns - 1`, and two-way roads: `roads[i] = [a, b]` joins towns a and b. During a storm, roads close one at a time. `closures[k]` is the index in `roads` of the k-th road to close; no road closes twice, and roads that never appear stay open. The emergency service needs to know, after every closure, how many separate **groups** of towns there are: towns in the same group can still reach each other by open roads, and towns in different groups can't. Return those counts, one per closure.

`StormRoadClosures.groupsAfterEachClosure(towns: Int, roads: [[Int]], closures: [Int]) -> [Int]`

## Examples

| `towns` | `roads` | `closures` | Output |
| --- | --- | --- | --- |
| `4` | `[[0, 1], [1, 2], [2, 3], [3, 0]]` | `[0, 2, 1]` | `[1, 2, 3]` |
| `3` | `[[0, 1], [0, 1], [1, 2]]` | `[0, 2, 1]` | `[1, 2, 3]` |
| `6` | `[[0, 1], [1, 2], [3, 4], [4, 5], [2, 3]]` | `[4, 0, 3]` | `[2, 3, 4]` |
| `3` | `[[0, 0], [1, 2]]` | `[0]` | `[2]` |
| `5` | `[[0, 1], [2, 3]]` | `[]` | `[]` |

In the first, the four towns form a ring, so losing one road still leaves everyone connected. In the second, two roads join towns 0 and 1, and closing one of them changes nothing. In the fourth, the closed road led from town 0 back to itself.

## Constraints

- `1 ≤ towns ≤ 100,000` and `0 ≤ roads.count ≤ 200,000`, with `0 ≤ a, b < towns`. Two towns can have several roads between them, and a road can lead from a town to itself.
- `0 ≤ closures.count ≤ roads.count`, and the entries of `closures` are distinct indexes of `roads`.
- The tests close all 200,000 roads of a network with 100,000 towns, so counting the groups again after every closure is far too slow.

<Hints>
<Hint>
"How many groups?" while the network changes is a union-find question. But union-find can only **join** groups. It has no way to split one when a road disappears. Can you turn the closures into joins?
</Hint>
<Hint>
Run the storm backwards. After the last closure, the open roads are the ones not in `closures` at all. Build that network first. Then reopen the closed roads in reverse order: each reopening is a union.
</Hint>
<Hint>
Just before you reopen road `closures[k]`, the network is exactly the one right after closure k happened, so record the component count then. Fill the answer from the back, with a counter in the union-find that drops by one whenever a union joins two different groups.
</Hint>
</Hints>

## Solutions

<Approach title="Recount after every closure" time="O(closures · (towns + roads))" space="O(towns + roads)">

After each closure, run a BFS or DFS over the open roads and count the groups. It's direct and correct, and it's how the tests check small storms. With 200,000 closures of a network that size, it's around 60 billion steps.

</Approach>

<Approach title="Reverse time and use union-find" time="O((towns + roads) α(towns))" space="O(towns + roads)">

This is the trap from the lesson's list: union-find can't delete edges, so process the deletions in reverse, where they become additions. Every road is unioned once, either at the start (if it never closes) or when its closure is undone.

```swift
import DSAKit

public enum StormRoadClosures {
    public static func groupsAfterEachClosure(towns: Int, roads: [[Int]], closures: [Int]) -> [Int] {
        var closes = Array(repeating: false, count: roads.count)
        for road in closures {
            closes[road] = true
        }
        var groups = UnionFind(count: towns)
        for (index, road) in roads.enumerated() where !closes[index] {
            groups.union(road[0], road[1])                       // roads still open after the storm
        }
        var answer = Array(repeating: 0, count: closures.count)
        for k in stride(from: closures.count - 1, through: 0, by: -1) {
            answer[k] = groups.componentCount                    // the network just after closure k
            let road = roads[closures[k]]
            groups.union(road[0], road[1])                       // undo closure k
        }
        return answer
    }
}
```

DSAKit's `UnionFind` keeps `componentCount` up to date, and its `union` is `@discardableResult`, so the calls that ignore its result compile without a warning. `stride(from:through:by:)` with an empty `closures` produces no steps, so that case needs no special handling. This "offline" trick needs every closure known in advance: if they arrived live, you'd need a much heavier structure.

</Approach>
