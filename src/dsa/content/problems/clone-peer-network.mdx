In a peer-to-peer network, each peer has a label and an ordered list of links to other peers:

```swift
public final class Peer {           // nested inside PeerNetworkClone
    public var label: Int
    public var links: [Peer]
}
```

Given one peer, return a **deep copy** of the network reachable from it. Every reachable peer is copied exactly once, each copy has the same label as its original, and its links point to the **copies** of the original's links, in the same order. The copy must be made entirely of new `Peer` objects: no original peer may appear in it. Return the copy of the peer you were given, or `nil` if you were given `nil`.

Links may be one-way or two-way, they may form cycles, a peer may link to itself, and **labels don't have to be unique**.

`PeerNetworkClone.clone(_ start: Peer?) -> Peer?`

## Examples

| Network, starting at the first peer listed | The copy |
| --- | --- |
| A square: 1 links to 2 and 4, 2 to 1 and 3, 3 to 2 and 4, 4 to 3 and 1 | four new peers in the same square, the copy of 1 linking to the copies of 2 and 4, in that order |
| 10 → 20 → 30 → 10, and 40 → 10 (all one-way) | three new peers in a one-way loop; 40 can't be reached from 10, so it isn't copied |
| A single peer labelled 3 that links to itself | one new peer labelled 3 that links to itself, not to the original |
| Four peers all labelled 7 | four separate new peers labelled 7 |
| `nil` | `nil` |

## Constraints

- Up to 100,000 peers and 200,000 links are reachable from `start`.
- The tests check the copy by walking it side by side with the original, so the order of each peer's links matters.
- The tests include a ring of 100,000 peers and a one-way chain of 100,000 peers. A recursive copy would go 100,000 calls deep and crash the test thread: use BFS or an explicit stack.

<Hints>
<Hint>
Copying a peer means copying its links, which means copying their links, which may lead back to the first peer. Make each copy only once, and remember which copy belongs to which original in a dictionary.
</Hint>
<Hint>
`Peer` is a class and isn't `Hashable`, and labels can repeat, so neither can be the dictionary's key. Use `ObjectIdentifier(peer)`, which is unique to each object.
</Hint>
<Hint>
BFS over the original: make a peer's copy the moment you first see it (that's also its visited mark) and enqueue the original. When you dequeue an original, append the copies of its links to its copy's `links`.
</Hint>
</Hints>

## Solutions

<Approach title="Recursive DFS with a dictionary" time="O(peers + links)" space="O(peers)">

To copy a peer: if it already has a copy, return that. Otherwise make the copy, record it **before** recursing (so a link back to this peer finds it), then copy each link. Recording first is what stops cycles from recursing forever. It's elegant, but a chain of 100,000 peers is 100,000 nested calls.

```swift
public static func clone(_ start: Peer?) -> Peer? {
    guard let start else { return nil }
    var copies: [ObjectIdentifier: Peer] = [:]
    func copy(_ peer: Peer) -> Peer {
        if let existing = copies[ObjectIdentifier(peer)] { return existing }
        let twin = Peer(peer.label)
        copies[ObjectIdentifier(peer)] = twin            // record it before following any link
        twin.links = peer.links.map { copy($0) }
        return twin
    }
    return copy(start)
}
```

</Approach>

<Approach title="BFS with a dictionary" time="O(peers + links)" space="O(peers)">

The same dictionary, filled level by level from a head-index queue, with no recursion at all.

```swift
public enum PeerNetworkClone {
    public final class Peer {
        public var label: Int
        public var links: [Peer]

        public init(_ label: Int, links: [Peer] = []) {
            self.label = label
            self.links = links
        }
    }

    public static func clone(_ start: Peer?) -> Peer? {
        guard let start else { return nil }
        var copies: [ObjectIdentifier: Peer] = [ObjectIdentifier(start): Peer(start.label)]
        var queue = [start]
        var head = 0
        while head < queue.count {
            let original = queue[head]
            head += 1
            let copy = copies[ObjectIdentifier(original)]!
            for link in original.links {
                let id = ObjectIdentifier(link)
                if copies[id] == nil {
                    copies[id] = Peer(link.label)        // copy on first sight: the visited mark
                    queue.append(link)
                }
                copy.links.append(copies[id]!)
            }
        }
        return copies[ObjectIdentifier(start)]
    }
}
```

An `ObjectIdentifier` is only meaningful while its object is alive. That's safe here because every original stays alive in the network (and in the queue) for the whole copy.

Links that form loops are strong reference cycles, as in [Retain cycles](/dsa/learn/swift-retain-cycles), so neither network is freed on its own. The tests break every link when they finish. A real app would make one side of each pair `weak`, or keep all the peers in an array that owns them.

</Approach>
