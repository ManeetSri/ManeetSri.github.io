A staircase has stairs numbered 1 to `stairs`, with the ground as stair 0. Each move climbs exactly one of the sizes listed in `steps`, and you may never land on a stair listed in `broken` (stepping over one is fine). Return how many different sequences of moves take you from the ground to exactly the top stair, modulo 1,000,000,007.

`StairClimbWays.count(stairs: Int, steps: [Int], broken: [Int]) -> Int`

## Examples

| `stairs` | `steps` | `broken` | Output | Why |
| --- | --- | --- | --- | --- |
| `4` | `[1, 2]` | `[]` | `5` | 1+1+1+1, 1+1+2, 1+2+1, 2+1+1, 2+2 |
| `4` | `[1, 2]` | `[2]` | `1` | only 1+2+1 avoids stair 2 |
| `10` | `[2, 5]` | `[]` | `2` | five 2s, or two 5s |
| `7` | `[2, 4]` | `[]` | `0` | even steps never reach an odd stair |
| `0` | `[3]` | `[]` | `1` | already at the top: the empty climb |
| `50` | `[1, 2]` | `[]` | `365010934` | the true count, about 2 × 10¹⁰, modulo 1,000,000,007 |

The order of moves matters: 1+2 and 2+1 are different climbs.

## Constraints

- `0 ≤ stairs ≤ 100,000`
- `1 ≤ steps.count ≤ 20`, the sizes are different, and `1 ≤ steps[i] ≤ 100,000`
- `broken` holds different stairs, each strictly between the ground and the top: `1 ≤ broken[i] < stairs`
- The counts grow exponentially, so reduce modulo 1,000,000,007 as you go.

<Hints>
<Hint>
Let `ways[i]` be the number of ways to stand on stair i. What could the last move onto stair i have been?
</Hint>
<Hint>
It was one of the step sizes s, from stair i − s, so `ways[i]` adds up `ways[i − s]` for every s that fits. The ground gives `ways[0] = 1`. A broken stair can't be stood on, so its count stays 0, and nothing can build on it.
</Hint>
<Hint>
Mark the broken stairs in a `[Bool]` first, so checking one is O(1). Then fill `ways` upwards, taking `% 1_000_000_007` after every addition so the numbers never get near `Int.max`.
</Hint>
</Hints>

## Solutions

<Approach title="Try every climb" time="exponential" space="O(stairs)">

Recursion that tries each step size from each stair. It's a good way to check small cases by hand, but the number of climbs grows exponentially, and the recursion is as deep as the staircase.

```swift
public static func count(stairs: Int, steps: [Int], broken: [Int]) -> Int {
    let blocked = Set(broken)
    func climb(from position: Int) -> Int {
        if position == stairs {
            return 1
        }
        var total = 0
        for step in steps where position + step <= stairs && !blocked.contains(position + step) {
            total = (total + climb(from: position + step)) % 1_000_000_007
        }
        return total
    }
    return climb(from: 0)
}
```

</Approach>

<Approach title="Bottom-up counting" time="O(stairs · steps.count)" space="O(stairs)">

Set out with the five steps of [The DP recipe](/dsa/learn/dp-recipe). **State:** `ways[i]`, the number of ways to stand on stair i. **Transition:** the sum of `ways[i − s]` over the step sizes that fit, or 0 for a broken stair. **Base case:** `ways[0] = 1`. **Order:** upwards. **Answer:** `ways[stairs]`.

```swift
public enum StairClimbWays {
    public static func count(stairs: Int, steps: [Int], broken: [Int]) -> Int {
        let modulus = 1_000_000_007
        var isBroken = Array(repeating: false, count: stairs + 1)
        for stair in broken {
            isBroken[stair] = true
        }
        var ways = Array(repeating: 0, count: stairs + 1)
        ways[0] = 1
        for i in stride(from: 1, through: stairs, by: 1) where !isBroken[i] {
            for step in steps where step <= i {
                ways[i] = (ways[i] + ways[i - step]) % modulus
            }
        }
        return ways[stairs]
    }
}
```

Each value stays below 1,000,000,007, so adding two of them can't overflow. `stride(from:through:by:)` is simply empty when `stairs` is 0, where `1...0` would crash.

</Approach>
