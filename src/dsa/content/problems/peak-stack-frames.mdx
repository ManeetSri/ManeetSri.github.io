A recursion's stack space is the largest number of frames alive **at the same moment**, not the number of calls. For each recursion below, return that peak, counting the first call as one frame. Don't run the recursion: the inputs go up to 10¹⁸.

`PeakStackFrames.rangeSumFrames(_ n: Int) -> Int` is for the range-halving sum, started as `sumRange(1, n)`:

```swift
func sumRange(_ low: Int, _ high: Int) -> Int {
    if low == high {
        return low
    }
    let mid = (low + high) / 2
    return sumRange(low, mid) + sumRange(mid + 1, high)
}
```

`PeakStackFrames.trimFrames(_ n: Int) -> Int` is for this lopsided recursion, started as `trim(n)`:

```swift
func trim(_ n: Int) {
    if n <= 1 {
        return
    }
    trim(n / 3)
    trim(n - 2)
}
```

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `rangeSumFrames(1)` | `1` | the first call is a base case |
| `rangeSumFrames(5)` | `4` | ranges of 5, then 3, then 2, then 1 numbers |
| `rangeSumFrames(1000)` | `11` | |
| `trimFrames(1)` | `1` | |
| `trimFrames(4)` | `3` | `trim(4)`, `trim(2)`, `trim(0)` |
| `trimFrames(10)` | `6` | although `trim(10)` makes 17 calls in total |

## Constraints

- `rangeSumFrames`: `1 ≤ n ≤ 10¹⁸`.
- `trimFrames`: `0 ≤ n ≤ 10¹⁸`.
- Answer each in O(log n) steps or fewer.

<Hints>
<Hint>
Only one path of calls is on the stack at a time: from the first call down to whichever call is running. So the peak is the length of the **longest** path from the first call to a base case. When a call makes two recursive calls, the longer path goes through whichever one leads deeper.
</Hint>
<Hint>
`sumRange` on k numbers calls itself on ⌈k/2⌉ numbers (the left half gets the extra one) and on ⌊k/2⌋. The bigger half is never shallower, so follow it: k, ⌈k/2⌉, ⌈k/4⌉, … until 1. Count the sizes on that path. Rounding up is `(k + 1) / 2`.
</Hint>
<Hint>
For `trim`, compare the two children: n − 2 is at least n / 3 for every n ≥ 2, and a bigger argument never leads to a shallower recursion. So the deepest path is n, n − 2, n − 4, … until the argument is 0 or 1. How many steps is that?
</Hint>
</Hints>

## Solutions

<Approach title="Instrument the recursion" time="as long as the recursion takes" space="O(peak)">

Add a depth counter, as in the space lesson: increase it when a call starts, decrease it when the call ends, and remember the largest value. It's the right way to check a formula, but `sumRange(1, 10¹⁸)` makes about 2 × 10¹⁸ calls, and `trim` makes even more relative to its input: `trim(200)` already makes 23,639 calls.

```swift
func trimPeak(_ n: Int) -> Int {
    var depth = 0
    var peak = 0
    func trim(_ n: Int) {
        depth += 1
        peak = max(peak, depth)
        defer { depth -= 1 }
        if n <= 1 { return }
        trim(n / 3)
        trim(n - 2)
    }
    trim(n)
    return peak
}
```

</Approach>

<Approach title="Follow the deepest path" time="O(log n) and O(1)" space="O(1)">

For `sumRange`, the deepest path keeps the bigger half each time: k becomes ⌈k/2⌉ until it reaches 1. Walking that path takes about log₂ n steps, so 10¹⁸ needs only 61 frames. That matches the lesson's measurements: 4 frames for 8 numbers, 8 for 100, 11 for 1,000.

For `trim`, the deepest path subtracts 2 each time, so it visits n, n − 2, …, down to 1 or 0: that's n / 2 calls after the first one. The `n / 3` branch makes the recursion slow, but it never makes it deeper.

```swift
public enum PeakStackFrames {
    public static func rangeSumFrames(_ n: Int) -> Int {
        var frames = 1
        var size = n
        while size > 1 {
            size = (size + 1) / 2
            frames += 1
        }
        return frames
    }

    public static func trimFrames(_ n: Int) -> Int {
        n / 2 + 1
    }
}
```

`rangeSumFrames(n)` is ⌈log₂ n⌉ + 1, and `trimFrames(n)` is O(n). Both recursions make far more calls than their peak, which is the lesson's point: time adds up every call, but space only counts the frames alive together.

</Approach>
