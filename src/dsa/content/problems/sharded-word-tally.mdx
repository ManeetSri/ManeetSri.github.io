Count how often each word appears across a collection of documents, counting the documents in parallel. A word is a maximal run of letters (`Character.isLetter`), compared in lowercase. Count each document in its own child task of a task group, without sharing a dictionary between tasks, then combine the results. Also return the `k` most frequent words, most frequent first, with ties broken alphabetically.

`ShardedWordTally.counts(in documents: [String]) async -> [String: Int]`

`ShardedWordTally.topWords(in documents: [String], count k: Int) async -> [String]`

## Examples

| `documents` | `counts` | `topWords`, `k = 3` |
| --- | --- | --- |
| `["The cat sat.", "the CAT ran", "A dog; a cat!"]` | cat 3, the 2, a 2, sat 1, ran 1, dog 1 | `["cat", "a", "the"]` |
| `["pear apple", "fig pear", "apple fig", "kiwi"]` | apple 2, fig 2, pear 2, kiwi 1 | `["apple", "fig", "pear"]` |
| `["well-known\nfacts", "it's 2pm"]` | well, known, facts, it, s, pm: 1 each | `["facts", "it", "known"]` |
| `[]` | empty | `[]` |

In the first example, "the" and "a" both appear twice, so they're ordered alphabetically after "cat". In the third, hyphens, apostrophes, digits and line breaks all separate words.

## Constraints

- `0 ≤ documents.count ≤ 200`, each up to a few thousand characters.
- `k ≥ 0`. If there are fewer than `k` different words, return them all.
- The result must not depend on the order the child tasks finish in. The tests compare against a sequential count.

<Hints>
<Hint>
`document.split(whereSeparator: { !$0.isLetter })` gives the words of one document as `Substring`s. Lowercase each one before counting.
</Hint>
<Hint>
Use `withTaskGroup(of: [String: Int].self)`. Each child builds and returns a dictionary of its own. Writing to one shared dictionary from the children would be a data race.
</Hint>
<Hint>
In the parent, `for await partial in group { total.merge(partial, uniquingKeysWith: +) }` combines the counts one result at a time. For `topWords`, sort the merged entries by count descending, then word ascending, with a tuple comparison as in [How Swift sorts, and sorting custom types](/dsa/learn/sort-swift-sort).
</Hint>
</Hints>

## Solutions

<Approach title="One dictionary per child, merged by the parent" time="O(C + u log u)" space="O(u) per task">

C is the total number of characters and u the number of distinct words. Each child task owns its dictionary, so nothing is shared while the counting runs; the parent is the only task that touches the combined dictionary, and it receives the partial counts one at a time. Merging is commutative, so the order the children finish in can't change the answer.

```swift
public enum ShardedWordTally {
    public static func counts(in documents: [String]) async -> [String: Int] {
        await withTaskGroup(of: [String: Int].self) { group in
            for document in documents {
                group.addTask {
                    var local: [String: Int] = [:]
                    for word in document.split(whereSeparator: { !$0.isLetter }) {
                        local[word.lowercased(), default: 0] += 1
                    }
                    return local
                }
            }
            var total: [String: Int] = [:]
            for await partial in group {
                total.merge(partial, uniquingKeysWith: +)
            }
            return total
        }
    }

    public static func topWords(in documents: [String], count k: Int) async -> [String] {
        let totals = await counts(in: documents)
        let ranked = totals.sorted { ($1.value, $0.key) < ($0.value, $1.key) }
        return ranked.prefix(k).map(\.key)
    }
}
```

The sort's closure puts `$1.value` first on the left to make counts go **down**, while `$0.key` on the left keeps words going **up**: the mixed-direction trick from M31. For a large vocabulary and a small k, a heap of size k would avoid sorting every word, as in [Top K, kth largest and K closest](/dsa/learn/heap-top-k).

</Approach>
