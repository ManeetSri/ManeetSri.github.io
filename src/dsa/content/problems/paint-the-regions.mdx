A map has `n` regions, numbered 0 to n − 1. Paint each region one of `m` colours, numbered 0 to m − 1, so that no two regions sharing a border get the same colour. Return one valid colouring, or `nil` if `m` colours aren't enough.

`RegionPainter.colour(_ n: Int, _ borders: [[Int]], colours m: Int) -> [Int]?`

Each border is `[a, b]` with `a ≠ b`. When several colourings work, return any of them: the tests check the rules, not particular colours.

## Examples

| `n` | `borders` | `m` | Returns |
| --- | --- | --- | --- |
| `3` | `[[0, 1], [1, 2], [2, 0]]` | `3` | `[0, 1, 2]`, or any other order of the three colours |
| `4` | `[[0, 1], [1, 2], [2, 3], [3, 0]]` | `2` | `[0, 1, 0, 1]` or `[1, 0, 1, 0]` |
| `4` | `[[0, 1], [0, 2], [0, 3], [1, 2], [1, 3], [2, 3]]` | `3` | `nil`: every region borders the other three |
| `5` | `[[0, 1], [1, 2], [2, 3], [3, 4], [4, 0]]` | `2` | `nil`: a ring of five can't alternate |

## Constraints

- `1 ≤ n ≤ 16` and `0 ≤ m ≤ 6`.
- Trying all mⁿ colourings and checking each one is up to 4¹⁶ ≈ 4 billion for 16 regions and 4 colours. Backtracking rejects a bad colour as soon as it's placed, and the tests are sized so that it finishes quickly.

<Hints>
<Hint>
Colour the regions in order. For each region, try every colour that none of its already-coloured neighbours uses, and move on to the next region.
</Hint>
<Hint>
When a region has no colour left to try, undo it and go back to the previous region's next option. If region 0 runs out of options, return `nil`.
</Hint>
<Hint>
The colours are interchangeable: swapping every 0 with every 1 in a valid colouring gives another valid one. So a region never needs a colour more than one higher than the largest used so far. This cuts the search a lot when the answer is `nil`.
</Hint>
</Hints>

## Solutions

<Approach title="Every colouring" time="O(mⁿ · E)" space="O(n)">

Count through all mⁿ colourings like a number in base m and check every border. It's correct, but it can't stop early: a clash between regions 0 and 1 is only noticed after all the colourings of the other regions have been tried.

</Approach>

<Approach title="Backtracking with symmetry breaking" time="O(mⁿ) worst case" space="O(n + E)">

The recursion places one region per level, so it's at most 16 calls deep.

```swift
public enum RegionPainter {
    public static func colour(_ n: Int, _ borders: [[Int]], colours m: Int) -> [Int]? {
        var neighbours = [[Int]](repeating: [], count: n)
        for border in borders {
            neighbours[border[0]].append(border[1])
            neighbours[border[1]].append(border[0])
        }
        var colour = [Int](repeating: -1, count: n)

        func paint(_ region: Int, highestUsed: Int) -> Bool {
            if region == n { return true }
            for c in 0..<min(m, highestUsed + 2) {
                if neighbours[region].contains(where: { colour[$0] == c }) { continue }
                colour[region] = c
                if paint(region + 1, highestUsed: max(highestUsed, c)) { return true }
            }
            colour[region] = -1                        // undo before backing up
            return false
        }

        return paint(0, highestUsed: -1) ? colour : nil
    }
}
```

`highestUsed + 2` lets the region reuse any colour so far or open exactly one new one. Without that limit the code is still correct, only slower on impossible maps. Colouring the regions with the most borders first is another good speed-up: they're the most constrained, so dead ends show up sooner.

</Approach>
