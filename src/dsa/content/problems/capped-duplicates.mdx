`numbers` is sorted in non-decreasing order. Rearrange it **in place** so that its first `k` elements keep at most `limit` copies of each value, still in sorted order, and return `k`. Whatever is left from index `k` onwards doesn't matter. Use O(1) extra space.

`CappedDuplicates.compact(_ numbers: inout [Int], keeping limit: Int) -> Int`

## Examples

| `numbers` | `limit` | Returns | First `k` elements |
| --- | --- | --- | --- |
| `[1, 1, 1, 2, 2, 3]` | `2` | `5` | `[1, 1, 2, 2, 3]` |
| `[4, 4, 4, 4, 5, 6, 6, 6]` | `2` | `5` | `[4, 4, 5, 6, 6]` |
| `[1, 1, 2, 3, 3, 3]` | `1` | `3` | `[1, 2, 3]` |
| `[7, 7, 7, 7, 7]` | `3` | `3` | `[7, 7, 7]` |
| `[1, 2, 2]` | `5` | `3` | `[1, 2, 2]` |
| `[]` | `2` | `0` | `[]` |

## Constraints

- `0 ≤ numbers.count ≤ 100,000`, sorted in non-decreasing order
- `-10⁹ ≤ numbers[i] ≤ 10⁹` and `1 ≤ limit ≤ 100,000`
- O(n) time and O(1) extra space. Calling `remove(at:)` for each extra copy is O(n²).

<Hints>
<Hint>
Use read and write pointers. `write` is the next slot to fill, and `numbers[0..<write]` is the answer so far. The first `limit` elements are always kept.
</Hint>
<Hint>
With a limit of 1, you keep a value when it differs from the last kept element, `numbers[write - 1]`. With a limit of 2, which kept element tells you that two copies are already kept?
</Hint>
<Hint>
Keep `numbers[read]` when `write < limit` or `numbers[read] != numbers[write - limit]`. Because the kept part is sorted, if the element `limit` slots back is the same value, so is everything after it: there are already `limit` copies. Compare with kept elements, not with `numbers[read - limit]`, which may have been overwritten.
</Hint>
</Hints>

## Solutions

<Approach title="Count each run" time="O(n)" space="O(1)">

Walk through the array, counting how many times the current value has appeared in a row, and copy it forward while the count is within the limit. It works, but it needs a separate counter that resets at each new value.

```swift
public static func compact(_ numbers: inout [Int], keeping limit: Int) -> Int {
    var write = 0
    var run = 0
    for read in numbers.indices {
        run = (read > 0 && numbers[read] == numbers[read - 1]) ? run + 1 : 1
        if run <= limit {
            numbers[write] = numbers[read]
            write += 1
        }
    }
    return write
}
```

Reading `numbers[read - 1]` is safe even though the array is being overwritten: if nothing has been dropped yet, that slot was overwritten with its own value, and otherwise `write` hasn't reached it yet. That's a subtle argument, and it fails for `numbers[read - 2]`, which is why the next approach compares with kept elements instead.

</Approach>

<Approach title="Compare with the kept element limit slots back" time="O(n)" space="O(1)">

The invariant: `numbers[0..<write]` holds the kept elements so far, sorted, with at most `limit` copies of each. A new element can join unless the last `limit` kept elements are all equal to it, and in a sorted kept part, that's the same as the one `limit` slots back being equal to it.

```swift
public enum CappedDuplicates {
    public static func compact(_ numbers: inout [Int], keeping limit: Int) -> Int {
        var write = 0
        for read in numbers.indices {
            if write < limit || numbers[read] != numbers[write - limit] {
                numbers[write] = numbers[read]
                write += 1
            }
        }
        return write
    }
}
```

The `write < limit` check comes first, so `numbers[write - limit]` is only read when `write - limit` is a real index.

</Approach>
