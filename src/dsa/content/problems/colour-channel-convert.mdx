A colour on screen is made of red, green and blue **channels**, each stored as a `UInt8` from 0 to 255. Write the two conversions a photo editor needs: brightening a channel by a factor, and checking a channel value that someone typed into a text field.

- `ColourChannelConvert.brightened(_ channel: UInt8, by factor: Double) -> UInt8` multiplies the channel by `factor`, rounds to the nearest whole number (halves go up, as `.rounded()` does) and caps the result at 255.
- `ColourChannelConvert.isValidChannel(_ text: String) -> Bool` returns `true` when the text is a whole number from 0 to 255, written in a form Swift's integer conversions accept. So `"+7"` and `"007"` are fine, but `" 7"`, `"7.0"`, `""` and `"256"` aren't.

## Examples

| Call | Returns | Why |
| --- | --- | --- |
| `brightened(100, by: 1.5)` | `150` | 100 × 1.5 |
| `brightened(101, by: 0.5)` | `51` | 50.5 rounds up; `Int(50.5)` on its own would give 50 |
| `brightened(200, by: 2.0)` | `255` | 400 is capped at 255 |
| `brightened(80, by: 0.0)` | `0` | a factor of 0 turns the channel off |
| `isValidChannel("128")` | `true` | a whole number in range |
| `isValidChannel("256")` | `false` | one too big for a channel |
| `isValidChannel("-1")` | `false` | channels can't be negative |
| `isValidChannel("12.5")` | `false` | not a whole number |

## Constraints

- `0.0 ≤ factor ≤ 10.0`
- `text` has at most 20 characters and may contain anything.
- Neither function may crash, whatever its input.

<Hints>
<Hint>
Swift won't multiply a `UInt8` by a `Double`. Convert first: `Double(channel) * factor`.
</Hint>
<Hint>
Round with `.rounded()` *before* converting back, because `Int(...)` truncates. Then, instead of `UInt8(...)`, which crashes for 400, use `UInt8(clamping:)`, which caps anything above 255.
</Hint>
<Hint>
Every integer type can be created from text, not only `Int`, and the result is `nil` when the text isn't a number **or doesn't fit the type**. `UInt8("256")` and `UInt8("-1")` are both nil, so `UInt8(text) != nil` is the whole check.
</Hint>
</Hints>

## Solutions

<Approach title="Convert, round, clamp; let UInt8 judge the text" time="O(1)" space="O(1)">

Brightening is a chain of conversions, each chosen deliberately: up to `Double` so the factor can apply, `.rounded()` so 50.5 becomes 51 rather than 50, down to `Int`, and finally `UInt8(clamping:)` so that a bright result is capped rather than crashing.

For the text, `UInt8(text)` does all the work. It rejects anything that isn't a whole number, *and* anything outside 0 to 255, because those don't fit in a `UInt8`.

```swift
public enum ColourChannelConvert {
    public static func brightened(_ channel: UInt8, by factor: Double) -> UInt8 {
        let scaled = (Double(channel) * factor).rounded()
        return UInt8(clamping: Int(scaled))
    }

    public static func isValidChannel(_ text: String) -> Bool {
        return UInt8(text) != nil
    }
}
```

`Int(scaled)` is safe here: with a factor of at most 10, `scaled` is never more than 2,550, nowhere near the limits of an `Int`.

</Approach>

<Approach title="Check the range yourself" time="O(1)" space="O(1)">

Once you've met `if let` in M04, you can convert to an `Int` and test the range explicitly. It's longer, but works for any range, not only one that matches a type:

```swift
public static func isValidChannel(_ text: String) -> Bool {
    if let value = Int(text) {
        return value >= 0 && value <= 255
    }
    return false
}
```

A number too big even for an `Int`, such as `"99999999999999999999"`, makes `Int(text)` nil, so it's rejected without any risk of overflow.

</Approach>
