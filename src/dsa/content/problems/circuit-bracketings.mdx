A logic circuit is written as a string that alternates symbols and operators. The symbols are `T` (true) and `F` (false). The operators are `&` (and), `|` (or), `^` (xor: true when exactly one side is true) and `>` (implies: false only when the left side is true and the right side is false). Count the ways to fully bracket the expression so that it evaluates to `wanted`, and return the count modulo 1,000,000,007.

`CircuitBracketings.count(_ expression: String, wanted: Bool) -> Int`

## Examples

| `expression` | `wanted` | Output |
| --- | --- | --- |
| `"T^T&F\|T"` | `true` | `2` |
| `"T^T&F\|T"` | `false` | `3` |
| `"F>T>F"` | `true` | `1` |
| `"T>F>F"` | `true` | `2` |
| `"T>F"` | `true` | `0` |
| `"T"` | `false` | `0` |

The first two are the lesson's example: of its five bracketings, two are true and three false. In the third, `(F>T)>F` is `T>F`, which is false, but `F>(T>F)` is `F>F`, which is true. Unlike the other three operators, `>` cares which side is which.

## Constraints

- `expression` has between 1 and 150 symbols, with exactly one operator between each pair of neighbouring symbols, and nothing else.
- With 150 symbols there are more than 10⁸⁰ bracketings, so the counts must be reduced modulo 1,000,000,007 as you go.

<Hints>
<Hint>
Every bracketing of symbols i...j has an operator that's evaluated last. It splits the range into a left part and a right part that are bracketed independently. That's the interval DP from the lesson.
</Hint>
<Hint>
Keep two counts per range, `t[i][j]` and `f[i][j]`. For a split at operator k, each left bracketing pairs with each right one, so the four combinations contribute `lt · rt`, `lt · rf`, `lf · rt` and `lf · rf` bracketings. The operator decides which of those four are true.
</Hint>
<Hint>
For `>`, three of the four combinations are true: everything except a true left with a false right. Reduce every product modulo 1,000,000,007 before adding it, and add up the cases you want rather than subtracting the ones you don't, so nothing goes negative.
</Hint>
</Hints>

## Solutions

<Approach title="Try every bracketing" time="exponential" space="O(n)">

Recursively list the value of every bracketing of each range and count the trues. With 150 symbols that's more bracketings than there are atoms in the universe.

</Approach>

<Approach title="Interval DP with a true and a false count" time="O(n³)" space="O(n²)">

The four products of a split are the four kinds of pairing, so each operator's row of the combining table is just a choice of which pairings make it true. Ranges are filled by length, so both halves of every split are ready when they're needed.

```swift
public enum CircuitBracketings {
    public static func count(_ expression: String, wanted: Bool) -> Int {
        let mod = 1_000_000_007
        let tokens = Array(expression)                               // symbol, operator, symbol, …
        let symbols = stride(from: 0, to: tokens.count, by: 2).map { tokens[$0] == "T" }
        let operators = stride(from: 1, to: tokens.count, by: 2).map { tokens[$0] }
        let n = symbols.count
        var t = Array(repeating: Array(repeating: 0, count: n), count: n)
        var f = Array(repeating: Array(repeating: 0, count: n), count: n)
        for i in 0..<n {
            t[i][i] = symbols[i] ? 1 : 0
            f[i][i] = symbols[i] ? 0 : 1
        }
        for length in stride(from: 2, through: n, by: 1) {
            for i in 0...(n - length) {
                let j = i + length - 1
                var trueWays = 0
                var falseWays = 0
                for k in i..<j {                                     // operators[k] is evaluated last
                    let (lt, lf, rt, rf) = (t[i][k], f[i][k], t[k + 1][j], f[k + 1][j])
                    let (tt, tf, ft, ff) = (lt * rt % mod, lt * rf % mod, lf * rt % mod, lf * rf % mod)
                    switch operators[k] {
                    case "&":
                        trueWays += tt
                        falseWays += tf + ft + ff
                    case "|":
                        trueWays += tt + tf + ft
                        falseWays += ff
                    case "^":
                        trueWays += tf + ft
                        falseWays += tt + ff
                    default:                                         // ">": false only for true > false
                        trueWays += tt + ft + ff
                        falseWays += tf
                    }
                    trueWays %= mod
                    falseWays %= mod
                }
                t[i][j] = trueWays
                f[i][j] = falseWays
            }
        }
        return wanted ? t[0][n - 1] : f[0][n - 1]
    }
}
```

Each stored count is below the modulus, about 10⁹, so a product of two is below 10¹⁸ and fits in an `Int` before it's reduced. Adding three reduced products to a running total stays below 4 × 10⁹, also safe. `stride(from: 2, through: n, by: 1)` makes no steps for a single symbol, where `2...n` would crash. A quick test of your table: `t + f` for the whole expression must equal the Catalan number for its number of operators, modulo the prime.

</Approach>
