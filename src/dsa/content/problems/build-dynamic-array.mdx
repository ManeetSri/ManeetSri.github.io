Build your own growable array. It keeps its elements in a fixed-size buffer of optionals, and when the buffer is full it allocates one twice the size and copies everything across, exactly as the lesson describes.

`BuildDynamicArray.DynamicArray<Element>`, with `init()`, `count: Int`, `capacity: Int`, `isEmpty: Bool`, `append(_:)`, `insert(_:at:)`, `remove(at:) -> Element`, `popLast() -> Element?` and `subscript(index: Int) -> Element` (get and set)

The stub gives you `private var buffer: [Element?] = []`. The buffer's size **is** the capacity, so never call `buffer.append`: when every slot is in use, make a new buffer yourself.

- A new array has capacity 0. When `append` or `insert` finds the buffer full, the capacity doubles first, from 0 to 1, then 2, 4, 8 and so on.
- `insert(_:at:)` accepts any index from `0` to `count`, and shifts the later elements one place right.
- `remove(at:)` accepts any index from `0` to `count - 1`, shifts the later elements one place left, and returns the removed element.
- `popLast()` returns `nil` when the array is empty.
- Removing never shrinks the capacity, but it must set the freed slot back to `nil`, so the array stops holding on to the removed element.

## Examples

| Code | Result |
| --- | --- |
| A new array | `count` 0, `capacity` 0, `isEmpty` true |
| Append 1 to 9, checking `capacity` after each | 1, 2, 4, 4, 8, 8, 8, 8, 16 |
| Append 1, 2, 3, 4, then `insert(9, at: 1)` | elements 1, 9, 2, 3, 4 |
| Append 1 to 5, then `remove(at: 2)` | returns 3; elements 1, 2, 4, 5; capacity still 8 |
| Append 10, 20, then `array[1] = 99` | elements 10, 99 |
| `popLast()` on an empty array | `nil` |

## Constraints

- Up to 100,000 elements. `append` must be amortised O(1); subscripts, `count`, `capacity` and `popLast()` O(1); `insert` and `remove` O(n).
- Indices passed to the subscript, `insert` and `remove` are always valid.
- A copy of a `DynamicArray` is independent, as with any struct.

<Hints>
<Hint>
You need one more stored property besides the buffer: the number of slots in use. `capacity` is then `buffer.count`, and slots `0..<count` hold elements.
</Hint>
<Hint>
Write one private helper that grows a full buffer: create `[Element?](repeating: nil, count: max(1, capacity * 2))`, copy slots `0..<count` across, and replace the old buffer. Call it at the start of both `append` and `insert`.
</Hint>
<Hint>
To insert at `index`, move elements one place right starting from the **back**, slot `count - 1` into slot `count`, down to `index`. Going front to back would overwrite elements before they've moved. Removing is the mirror image: move left, front to back, then set the last used slot to `nil`.
</Hint>
</Hints>

## Solutions

<Approach title="A buffer of optionals that doubles" time="O(1) amortised append, O(n) insert and remove" space="O(n)">

Slots `0..<count` of the buffer hold the elements and the rest hold `nil`. Doubling keeps the total copying for n appends below 2n, which is why `append` is O(1) amortised. Inserting and removing shift every element after the index, so they cost O(n − index).

```swift
public enum BuildDynamicArray {
    public struct DynamicArray<Element> {
        private var buffer: [Element?] = []
        private var storedCount = 0

        public init() {}

        public var count: Int {
            storedCount
        }

        public var capacity: Int {
            buffer.count
        }

        public var isEmpty: Bool {
            storedCount == 0
        }

        public mutating func append(_ element: Element) {
            growIfFull()
            buffer[storedCount] = element
            storedCount += 1
        }

        public mutating func insert(_ element: Element, at index: Int) {
            precondition(index >= 0 && index <= storedCount, "Index out of range")
            growIfFull()
            // Shift from the back, so nothing is overwritten before it has moved
            var position = storedCount
            while position > index {
                buffer[position] = buffer[position - 1]
                position -= 1
            }
            buffer[index] = element
            storedCount += 1
        }

        public mutating func remove(at index: Int) -> Element {
            precondition(index >= 0 && index < storedCount, "Index out of range")
            let removed = buffer[index]!
            for position in index..<(storedCount - 1) {
                buffer[position] = buffer[position + 1]
            }
            buffer[storedCount - 1] = nil     // let go of the old last element
            storedCount -= 1
            return removed
        }

        public mutating func popLast() -> Element? {
            guard storedCount > 0 else { return nil }
            storedCount -= 1
            let removed = buffer[storedCount]
            buffer[storedCount] = nil
            return removed
        }

        public subscript(index: Int) -> Element {
            get {
                precondition(index >= 0 && index < storedCount, "Index out of range")
                return buffer[index]!
            }
            set {
                precondition(index >= 0 && index < storedCount, "Index out of range")
                buffer[index] = newValue
            }
        }

        // Doubles the capacity (0 becomes 1) when every slot is in use, copying each element across
        private mutating func growIfFull() {
            guard storedCount == buffer.count else { return }
            var bigger = [Element?](repeating: nil, count: max(1, buffer.count * 2))
            for position in 0..<storedCount {
                bigger[position] = buffer[position]
            }
            buffer = bigger
        }
    }
}
```

The force unwraps are safe because slots below `storedCount` always hold an element. The stored count is called `storedCount` so it doesn't clash with the public `count` property; a `public private(set) var count = 0` would work just as well.

</Approach>
