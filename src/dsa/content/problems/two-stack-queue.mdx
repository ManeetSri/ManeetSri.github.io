Build a first-in, first-out queue using two stacks as its only storage. Each stack is an array used only at its end: `append`, `popLast()` and `last`, plus `first`, `isEmpty` and `count`. Every operation must be O(1) amortised.

`TwoStackQueueDesign.TwoStackQueue<Element>`, with `init()`, `enqueue(_:)`, `dequeue() -> Element?`, `peek() -> Element?`, `isEmpty: Bool` and `count: Int`

`dequeue()` removes and returns the element that has waited longest; `peek()` returns it without removing it. Both return `nil` when the queue is empty. Add whatever private storage you need.

## Examples

| Code | Result |
| --- | --- |
| enqueue 1, 2, 3, then `dequeue()` | `1` |
| enqueue 1, 2, `dequeue()`, enqueue 3, then `peek()` | `2` |
| enqueue `"a"`, `"b"`, then `count` | `2` |
| `TwoStackQueue<Int>().dequeue()` | `nil` |
| enqueue 5, 6, `dequeue()`, enqueue 7, then dequeue until empty | `6`, `7`, then `nil` |

## Constraints

- Up to 200,000 operations in any mix. Any sequence of m operations must take O(m) time in total.
- Copying a queue gives an independent queue, as with any struct.

<Hints>
<Hint>
Call the stacks `inbox` and `outbox`. New elements always go onto `inbox`. Where is the oldest element when `outbox` is empty, and how can popping and pushing bring it to the top of a stack?
</Hint>
<Hint>
Popping everything off `inbox` and pushing it onto `outbox` reverses the order, so the oldest element ends up on top of `outbox`. Only do this when `outbox` is empty: anything already in `outbox` is older than everything in `inbox`.
</Hint>
<Hint>
For `peek()`, the front is `outbox.last` if `outbox` has anything, and otherwise the bottom of `inbox`, which is `inbox.first`. `count` is the two counts added together.
</Hint>
</Hints>

## Solutions

<Approach title="Pour on every dequeue" time="O(n) per dequeue" space="O(n)">

A first attempt keeps `inbox` as "the real queue": for each dequeue, pour everything into `outbox`, pop the top, and pour the rest back. It gives the right answers, and it's a useful check on small cases.

```swift
public mutating func dequeue() -> Element? {
    while let element = inbox.popLast() { outbox.append(element) }
    let front = outbox.popLast()
    while let element = outbox.popLast() { inbox.append(element) }
    return front
}
```

Every dequeue moves every element twice, so a queue holding n elements pays O(n) per dequeue, and the 200,000-operation test takes a long time.

</Approach>

<Approach title="Pour only when the outbox is empty" time="O(1) amortised per operation" space="O(n)">

Leave elements in `outbox` until it runs dry. Then every element follows the same path exactly once: pushed onto `inbox`, moved to `outbox`, popped from `outbox`. That's at most four stack operations per element over its whole life, so any m operations cost O(m) in total, even though one dequeue that pours can cost O(n) on its own.

```swift
public enum TwoStackQueueDesign {
    public struct TwoStackQueue<Element> {
        private var inbox: [Element] = []     // newest on top (the end)
        private var outbox: [Element] = []    // oldest on top (the end)

        public init() {}

        public mutating func enqueue(_ element: Element) {
            inbox.append(element)
        }

        public mutating func dequeue() -> Element? {
            if outbox.isEmpty {
                while let element = inbox.popLast() {
                    outbox.append(element)    // pouring reverses the order
                }
            }
            return outbox.popLast()
        }

        public func peek() -> Element? {
            outbox.last ?? inbox.first
        }

        public var isEmpty: Bool {
            inbox.isEmpty && outbox.isEmpty
        }

        public var count: Int {
            inbox.count + outbox.count
        }
    }
}
```

An empty queue needs no special case: the pour moves nothing, and `outbox.popLast()` returns `nil`.

</Approach>
