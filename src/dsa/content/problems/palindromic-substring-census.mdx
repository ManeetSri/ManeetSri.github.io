Count how many substrings of `text` are palindromes. Substrings at different positions count separately, even when they spell the same letters.

`PalindromeCensus.count(in text: String) -> Int`

This is the counting problem from [Palindromes and expand-around-centre](/dsa/learn/str-palindromes), at a size where the quadratic method no longer works.

## Examples

| `text` | Output |
| --- | --- |
| `"abc"` | `3` |
| `"aaa"` | `6` |
| `"abba"` | `6` |
| `"abaaba"` | `11` |
| `"racecar"` | `10` |
| `""` | `0` |

`"aaa"` has three `a`s, two `aa`s and one `aaa`. `"abba"` has its four letters, `bb` and `abba`.

## Constraints

- `text` holds 0 to 200,000 lowercase letters, a to z.
- The answer fits in an `Int`: at most n(n + 1)/2, about 2 × 10¹⁰.
- The tests include 200,000 copies of one letter. Expanding around every centre does one step per palindrome found, so that's 20 billion steps.

<Hints>
<Hint>
Expand-around-centre wastes work inside long palindromes: the right half of a palindrome is a mirror image of its left half, so the palindromes centred in the right half mirror ones you've already measured on the left.
</Hint>
<Hint>
Manacher's algorithm uses exactly that. Put a separator around every letter so every palindrome has a single centre, keep the palindrome reaching furthest right, and start each new radius at what its mirror says (capped at the right edge) before comparing.
</Hint>
<Hint>
In the separated string, a centre with radius r holds (r + 1) / 2 palindromes of the original text: lengths r, r − 2, … down to 1 or 2. Add that up over every centre.
</Hint>
</Hints>

## Solutions

<Approach title="Expand around every centre" time="O(n²)" space="O(1)">

The M23 method: grow a palindrome from each of the 2n − 1 centres, counting one per successful step. On random text palindromes are short and it's fast, but 200,000 copies of one letter make it do 20 billion steps.

</Approach>

<Approach title="Manacher's algorithm" time="O(n)" space="O(n)">

Compute every radius with the mirror trick, and add up the palindromes at each centre as you go.

```swift
public enum PalindromeCensus {
    public static func count(in text: String) -> Int {
        let s = Array(text.utf8)
        var t = [Int](repeating: -1, count: 2 * s.count + 1)
        for (k, c) in s.enumerated() {
            t[2 * k + 1] = Int(c)
        }
        let n = t.count
        var rad = [Int](repeating: 0, count: n)
        var centre = 0, right = 0
        var total = 0
        for i in 0..<n {
            if i < right {
                rad[i] = min(rad[2 * centre - i], right - i)
            }
            while i - rad[i] - 1 >= 0 && i + rad[i] + 1 < n && t[i - rad[i] - 1] == t[i + rad[i] + 1] {
                rad[i] += 1
            }
            if i + rad[i] > right {
                centre = i
                right = i + rad[i]
            }
            total += (rad[i] + 1) / 2
        }
        return total
    }
}
```

Every successful comparison pushes `right` further, and `right` never comes back, so there are at most about 2n of them however long the palindromes are.

</Approach>

<Approach title="Binary search with hashes at every centre" time="O(n log n)" space="O(n)">

At each centre, the palindrome radius is monotonic: if radius r works, so does every smaller one. So binary search the radius, checking "is this slice a palindrome?" by comparing a forward hash of the slice with a hash of the matching slice of the reversed text, as in [Comparing substrings in O(1) with hashes](/dsa/learn/sa-substring-hashing). That's O(log n) O(1) checks per centre. It's slower than Manacher and relies on hashing, but it reuses a tool you may already have written.

</Approach>
