Find the shortest distance, in edges, from `source` to every node of a directed graph, working level by level in parallel. `graph[v]` lists the nodes that `v` has edges to; nodes that can't be reached get `-1`. Split each level's frontier into chunks of at most `chunkSize` nodes, gather each chunk's undiscovered neighbours in its own child task of a task group, and let the parent decide which of them form the next level.

`FrontierParallelBFS.distances(graph: [[Int]], source: Int, chunkSize: Int) async -> [Int]`

## Examples

| `graph` | `source` | `chunkSize` | Output |
| --- | --- | --- | --- |
| `[[1, 2], [3], [3, 4], [5], [5], [], [0]]` | `0` | `2` | `[0, 1, 1, 2, 2, 3, -1]` |
| the same | `6` | `1` | `[1, 2, 2, 3, 3, 4, 0]` |
| the same | `5` | `64` | `[-1, -1, -1, -1, -1, 0, -1]` |
| `[[1, 1, 1, 0], [2, 2], [1, 0], []]` | `0` | `1` | `[0, 1, 2, -1]` |
| `[[]]` | `0` | `1` | `[0]` |

In the first example, nodes 1 and 2 form level 1. Both have an edge to node 3, so node 3 is reported twice when level 1 is expanded, but it's at distance 2 and appears in the next frontier once. Nothing links to node 6. In the fourth, repeated edges and edges back to the source change nothing.

## Constraints

- `1 ≤ graph.count ≤ 20,000`, with up to 100,000 edges in total; `0 ≤ source < graph.count`.
- Self-loops and repeated edges are allowed.
- `chunkSize ≥ 1`. The answer must not depend on it, or on the order child tasks finish in. The tests compare against ordinary sequential BFS, including on a path of 5,000 nodes, where every level has one node.

<Hints>
<Hint>
Every node in a frontier is at the same distance, so you can expand them in any order. Keep `distance` (with -1 for undiscovered) and a `frontier` array, starting with only `source`, and loop until the frontier is empty.
</Hint>
<Hint>
For each chunk, add a child task that reads `graph` and the current `distance` and returns the neighbours it found with `distance == -1`. The children must not write anything. Tag each result with its chunk number so the parent can process them in a fixed order.
</Hint>
<Hint>
The parent walks the returned lists and, for each node still at -1, sets its distance to the current level plus one and appends it to the next frontier. A node reported by two chunks is then added only once. Doing the gathering in a separate function means the children have released `distance` before the parent writes, so the writes don't copy the array.
</Hint>
</Hints>

## Solutions

<Approach title="Level-synchronous BFS with a task group per level" time="O(V + E) work" space="O(V + E)">

Each edge is looked at once, when its source node is in a frontier, and each node is assigned once. On top of that, every level costs one round of child tasks, which is why a long, thin graph gains nothing from this approach.

```swift
public enum FrontierParallelBFS {
    public static func distances(graph: [[Int]], source: Int, chunkSize: Int) async -> [Int] {
        var distance = Array(repeating: -1, count: graph.count)
        distance[source] = 0
        var frontier = [source]
        var level = 0
        while !frontier.isEmpty {
            let candidates = await gatherNeighbours(of: frontier, graph: graph, distance: distance, chunkSize: chunkSize)
            var next: [Int] = []
            for list in candidates {
                for node in list where distance[node] == -1 {
                    distance[node] = level + 1
                    next.append(node)
                }
            }
            frontier = next
            level += 1
        }
        return distance
    }

    private static func gatherNeighbours(of frontier: [Int], graph: [[Int]], distance: [Int], chunkSize: Int) async -> [[Int]] {
        let size = max(chunkSize, 1)
        let chunkCount = (frontier.count + size - 1) / size
        return await withTaskGroup(of: (chunk: Int, found: [Int]).self) { group in
            for chunk in 0..<chunkCount {
                let nodes = frontier[(chunk * size)..<min((chunk + 1) * size, frontier.count)]
                group.addTask {
                    var found: [Int] = []
                    for node in nodes {
                        for next in graph[node] where distance[next] == -1 {
                            found.append(next)
                        }
                    }
                    return (chunk, found)
                }
            }
            var byChunk = Array(repeating: [Int](), count: chunkCount)
            for await result in group {
                byChunk[result.chunk] = result.found
            }
            return byChunk
        }
    }
}
```

The children capture `graph`, `distance` and their slice of the frontier, all value types that the parent doesn't change while they run, so there's no data race. The distances alone don't depend on the order the chunks are processed in; processing them in chunk order also makes each next frontier come out in the same order on every run, which makes the code easier to debug.

</Approach>
