Towns `0` to `n - 1` are joined by `n - 1` two-way roads, each given as `[a, b, length]`, and together they form a tree: there's exactly one route between any two towns. Everyone in every town is invited to a meeting. For each town t, work out the total distance everyone else would travel if the meeting were held at t: the sum, over all other towns, of the length of the route from there to t. Return those totals as an array indexed by town.

`GatheringCostEveryTown.totalTravel(n: Int, roads: [[Int]]) -> [Int]`

## Examples

| `n` | `roads` | Output |
| --- | --- | --- |
| `4` | `[[0, 1, 2], [1, 2, 3], [1, 3, 1]]` | `[10, 6, 12, 8]` |
| `5` | `[[0, 1, 1], [0, 2, 1], [0, 3, 1], [0, 4, 1]]` | `[4, 7, 7, 7, 7]` |
| `2` | `[[0, 1, 5]]` | `[5, 5]` |
| `1` | `[]` | `[0]` |

In the first example, from town 0 the routes are 2 (to town 1), 5 (to town 2, through town 1) and 3 (to town 3): 10 in all. Town 1, in the middle, is the cheapest meeting place. In the second, the hub is 1 from everyone, and each outer town is 1 from the hub and 2 from the other three.

## Constraints

- `1 ≤ n ≤ 100,000`, and `roads` has exactly `n - 1` entries that connect every town.
- `0 ≤ a, b < n`, and `1 ≤ length ≤ 10,000`
- One test is a single chain of 100,000 towns. A recursive DFS goes 100,000 calls deep there, which crashes inside the test runner, so walk the tree with a loop.
- The tests also try a random tree and a star of 100,000 towns, so running a search from every town, O(n²), is too slow.

<Hints>
<Hint>
Root the tree at town 0. For every town v, work out how many towns are in its subtree, and the total distance from those towns to v. One pass from the leaves up does both.
</Hint>
<Hint>
The root's subtree is the whole tree, so its total is its answer. Now move the meeting point from a town p across a road of length w to its child c. Which towns get closer, which get further, and by how much?
</Hint>
<Hint>
The `size[c]` towns in c's subtree each get w closer, and the other `n - size[c]` each get w further: `answer[c] = answer[p] + w · (n - 2 · size[c])`. Use one BFS order for both passes: backwards for the first, forwards for the second.
</Hint>
</Hints>

## Solutions

<Approach title="A search from every town" time="O(n²)" space="O(n)">

For each town, walk the whole tree from it with a stack, adding up distances. It's simple and clearly correct, and the tests use it on small trees. With 100,000 towns it's ten billion steps.

</Approach>

<Approach title="Rerooting: one pass down, one pass up" time="O(n)" space="O(n)">

A BFS from town 0 records each town's parent, the length of the road to it, and an order with every parent before its children. The down pass, in reverse order, builds `size` and `down` (the total distance from the towns below v up to v). The up pass, in forward order, moves the meeting point across each road in O(1).

```swift
public enum GatheringCostEveryTown {
    public static func totalTravel(n: Int, roads: [[Int]]) -> [Int] {
        var neighbours = [[(to: Int, length: Int)]](repeating: [], count: n)
        for road in roads {
            neighbours[road[0]].append((road[1], road[2]))
            neighbours[road[1]].append((road[0], road[2]))
        }
        var parent = [Int](repeating: -1, count: n)
        var lengthUp = [Int](repeating: 0, count: n)       // length of the road from v to its parent
        var order = [0]
        var head = 0
        while head < order.count {
            let v = order[head]
            head += 1
            for (w, length) in neighbours[v] where w != parent[v] {
                parent[w] = v
                lengthUp[w] = length
                order.append(w)
            }
        }

        var size = [Int](repeating: 1, count: n)
        var down = [Int](repeating: 0, count: n)
        for v in order.reversed() where parent[v] >= 0 {
            size[parent[v]] += size[v]
            down[parent[v]] += down[v] + lengthUp[v] * size[v]
        }

        var answer = [Int](repeating: 0, count: n)
        answer[0] = down[0]
        for v in order where parent[v] >= 0 {
            answer[v] = answer[parent[v]] + lengthUp[v] * (n - 2 * size[v])
        }
        return answer
    }
}
```

The totals can reach about 5 × 10¹³ (a chain of 100,000 towns with roads of length 10,000), which fits comfortably in an `Int`.

</Approach>
