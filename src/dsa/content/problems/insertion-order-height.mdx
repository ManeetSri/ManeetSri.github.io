A support desk files tickets into a plain (unbalanced) binary search tree keyed by ticket number, in the order the tickets arrive. Before trusting it, they want to know how tall the tree will get. Given the insertion order, return the **height** of the BST it builds: the number of levels, so 0 for no values and 1 for a single value.

`InsertionOrderHeight.height(afterInserting values: [Int]) -> Int`

The obvious answer is to build the tree and measure it, but on sorted input, the most common input of all, that takes O(n²) time. Aim for O(n log n) whatever the order.

## Examples

| `values` | Output | Why |
| --- | --- | --- |
| `[4, 2, 6, 1, 3, 5, 7]` | `3` | the middle first: a perfect tree |
| `[1, 2, 3, 4, 5]` | `5` | sorted: a chain hanging to the right |
| `[1, 7, 2, 6, 3, 5, 4]` | `7` | a zigzag is a chain too |
| `[50, 30, 70, 40, 35]` | `4` | 35 goes left of 40, which is right of 30 |
| `[9]` | `1` | one node |
| `[]` | `0` | no tree |

## Constraints

- `0 ≤ values.count ≤ 200,000`, and the values are distinct.
- Values can be any `Int`.
- The tests include 200,000 values in sorted order, reversed order and zigzag order: building the tree node by node takes about 2 × 10¹⁰ steps on those.

<Hints>
<Hint>
Where does a new value x end up? Its parent is one of its two neighbours in sorted order among the values inserted so far: the largest smaller value (its predecessor) or the smallest larger one (its successor). Of those two, the parent is the one that's deeper in the tree, because that's the one the search reaches last.
</Hint>
<Hint>
So depth(x) = 1 + the larger of depth(predecessor) and depth(successor), counting a missing neighbour as depth 0. The height is the largest depth. All you need is each value's neighbours at the moment it was inserted.
</Hint>
<Hint>
Finding "neighbours among the values inserted so far" is easier **backwards**. Sort all the values and link each to the next and previous in sorted order, a doubly linked list held in two arrays. Now remove values in **reverse** insertion order: just before you remove x, the only values still in the list are those inserted before it, so its list neighbours are exactly its predecessor and successor. Record them, unlink x, and carry on. Then compute the depths in forward order.
</Hint>
</Hints>

## Solutions

<Approach title="Build it and measure" time="O(n × h), O(n²) worst case" space="O(n)">

Insert each value with a loop, tracking how deep it lands. The nodes live in arrays of child positions, so even a 200,000-node chain is no trouble to store or release. It's what the tree would really do, and it's quick for shuffled input, where h is about log n. For sorted input every insert walks the whole chain.

```swift
public static func height(afterInserting values: [Int]) -> Int {
    var left: [Int] = []                                     // child positions in values; -1 for none
    var right: [Int] = []
    var height = 0
    for (index, value) in values.enumerated() {
        left.append(-1)
        right.append(-1)
        var depth = 1
        if index > 0 {
            var node = 0                                     // values[0] is the root
            while true {
                depth += 1
                if value < values[node] {
                    if left[node] < 0 { left[node] = index; break }
                    node = left[node]
                } else {
                    if right[node] < 0 { right[node] = index; break }
                    node = right[node]
                }
            }
        }
        height = max(height, depth)
    }
    return height
}
```

</Approach>

<Approach title="Neighbours in sorted order, found backwards" time="O(n log n)" space="O(n)">

Sorting gives each value's rank. A doubly linked list over the ranks, stored as `previous` and `next` arrays, lets the reverse pass find and unlink neighbours in O(1). The forward pass then fills in depths: each value's neighbours were inserted earlier, so their depths are already known.

```swift
public enum InsertionOrderHeight {
    public static func height(afterInserting values: [Int]) -> Int {
        let n = values.count
        guard n > 0 else { return 0 }
        // rank[i] is the position of values[i] in sorted order
        let byValue = values.indices.sorted { values[$0] < values[$1] }
        var rank = [Int](repeating: 0, count: n)
        for (position, index) in byValue.enumerated() { rank[index] = position }

        // A doubly linked list of ranks; -1 means "no neighbour"
        var previous = Array(-1..<(n - 1))
        var next = Array(1...n)
        next[n - 1] = -1

        // Remove in reverse insertion order: the neighbours left are the ones inserted earlier
        var predecessor = [Int](repeating: -1, count: n)
        var successor = [Int](repeating: -1, count: n)
        for index in stride(from: n - 1, through: 0, by: -1) {
            let r = rank[index]
            predecessor[r] = previous[r]
            successor[r] = next[r]
            if previous[r] >= 0 { next[previous[r]] = next[r] }
            if next[r] >= 0 { previous[next[r]] = previous[r] }
        }

        // Forward: the parent is the deeper neighbour
        var depth = [Int](repeating: 0, count: n)                // by rank; 0 = not inserted yet
        var height = 0
        for index in 0..<n {
            let r = rank[index]
            let below = max(predecessor[r] >= 0 ? depth[predecessor[r]] : 0,
                            successor[r] >= 0 ? depth[successor[r]] : 0)
            depth[r] = below + 1
            height = max(height, depth[r])
        }
        return height
    }
}
```

This works even though no tree is ever built: the shape of a BST is completely decided by the insertion order, and the neighbour rule captures it. In M38 you'll meet ordered sets with O(log n) predecessor and successor queries, which answer the same question online, one value at a time.

</Approach>
