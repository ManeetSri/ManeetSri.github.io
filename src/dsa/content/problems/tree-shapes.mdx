Given a binary tree, say whether it's full, perfect, complete and degenerate. Each is a yes-or-no question about its shape, and a tree can be several at once.

`TreeShapes.isFull(_:)`, `TreeShapes.isPerfect(_:)`, `TreeShapes.isComplete(_:)` and `TreeShapes.isDegenerate(_:)`, each taking a `TreeNode?` and returning `Bool`.

- **Full:** every node has either no children or two.
- **Perfect:** every node that isn't a leaf has two children, and all the leaves are on the same level.
- **Complete:** every level is completely filled except possibly the last, and the last level's nodes are packed to the left.
- **Degenerate:** no node has two children, so the tree is one chain.

The empty tree counts as all four, and so does a single node.

## Examples

| Tree (level order) | Full | Perfect | Complete | Degenerate |
| --- | --- | --- | --- | --- |
| `[1, 2, 3, 4, 5, 6, 7]` | yes | yes | yes | no |
| `[1, 2, 3, 4, 5]` | yes | no | yes | no |
| `[1, 2, 3, 4]` | no | no | yes | no |
| `[1, 2, 3, nil, nil, 4, 5]` | yes | no | no | no |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | no | no | no | no |
| `[1, 2]` | no | no | yes | yes |
| `[1, nil, 2]` | no | no | no | yes |
| `[1]` | yes | yes | yes | yes |

`[1, 2, 3, 4, 5]` is full (2 has two children and 3 has none) but not perfect: its leaves are on two different levels. `[1, nil, 2]` isn't complete, because its only child is on the right, leaving a gap on the left.

## Constraints

- `0 ≤` number of nodes `≤ 131,071`
- Trees in the tests are at most 500 levels deep.

<Hints>
<Hint>
Full and degenerate only look at each node's own children. Visit every node (recursion is fine) and fail as soon as a node has exactly one child (full) or two children (degenerate). Degenerate is even simpler: there's only ever one way down.
</Hint>
<Hint>
For perfect, walk level by level. Each level must hold exactly twice as many nodes as the level above, until you reach a level where every node is a leaf, which must be the last. Another route: a tree with height h is perfect exactly when it has 2^h − 1 nodes.
</Hint>
<Hint>
For complete, walk in level order but queue the `nil` children too, as `TreeNode?`. In a complete tree, all the real nodes come before the first `nil`. So once you've met a `nil`, meeting a real node means the tree isn't complete.
</Hint>
</Hints>

## Solutions

<Approach title="One walk per shape" time="O(n)" space="O(n)">

Each check visits every node at most once, and none of them recurses, so tall trees are no trouble.

```swift
public enum TreeShapes {
    public static func isFull(_ root: TreeNode?) -> Bool {
        var stack = [root].compactMap { $0 }
        while let node = stack.popLast() {
            switch (node.left, node.right) {
            case (nil, nil):
                continue
            case let (left?, right?):
                stack.append(left)
                stack.append(right)
            default:
                return false                      // exactly one child
            }
        }
        return true
    }

    public static func isPerfect(_ root: TreeNode?) -> Bool {
        guard let root else { return true }
        var level = [root]
        while true {
            var next: [TreeNode] = []
            for node in level {
                if let left = node.left { next.append(left) }
                if let right = node.right { next.append(right) }
            }
            if next.isEmpty {
                return true                       // every node on this level is a leaf
            }
            if next.count != 2 * level.count {
                return false                      // someone above has fewer than two children
            }
            level = next
        }
    }

    public static func isComplete(_ root: TreeNode?) -> Bool {
        var queue: [TreeNode?] = [root]
        var head = 0
        var seenGap = false
        while head < queue.count {
            let node = queue[head]
            head += 1
            if let node {
                if seenGap {
                    return false                  // a real node after a gap
                }
                queue.append(node.left)
                queue.append(node.right)
            } else {
                seenGap = true
            }
        }
        return true
    }

    public static func isDegenerate(_ root: TreeNode?) -> Bool {
        var current = root
        while let node = current {
            if node.left != nil && node.right != nil {
                return false
            }
            current = node.left ?? node.right
        }
        return true
    }
}
```

The `switch` on a pair of optionals in `isFull` reads like the definition: `(nil, nil)` is a leaf, `(left?, right?)` matches when both children exist, and anything else is a single child.

</Approach>

<Approach title="Perfect by counting" time="O(n)" space="O(h)">

A perfect tree of height h has exactly 2^h − 1 nodes, and no other shape of that height has as many. So measure both and compare. This version recurses, which is fine for the depths in this problem.

```swift
public static func isPerfect(_ root: TreeNode?) -> Bool {
    func size(_ node: TreeNode?) -> Int {
        guard let node else { return 0 }
        return 1 + size(node.left) + size(node.right)
    }
    func height(_ node: TreeNode?) -> Int {
        guard let node else { return 0 }
        return 1 + max(height(node.left), height(node.right))
    }
    return size(root) == (1 << height(root)) - 1
}
```

`1 << h` is 2^h, from the bit-shifting lessons. For the empty tree, both sides are 0.

</Approach>
