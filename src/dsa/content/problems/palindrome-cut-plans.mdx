A **palindrome** reads the same forwards and backwards, like `noon` or `eye`. Return every way to cut `text` into consecutive pieces so that every piece is a palindrome. Each plan lists its pieces in order, and joining them gives back `text`.

`PalindromeCutPlans.plans(_ text: String) -> [[String]]`

The plans may come in any order: the tests sort them before comparing.

## Examples

| `text` | Output |
| --- | --- |
| `"noon"` | `[["n", "o", "o", "n"], ["n", "oo", "n"], ["noon"]]` |
| `"eye"` | `[["e", "y", "e"], ["eye"]]` |
| `"abc"` | `[["a", "b", "c"]]` |
| `"x"` | `[["x"]]` |

A single letter is always a palindrome, so cutting between every letter always works: there's at least one plan.

## Constraints

- `1 ≤ text.count ≤ 24`, lowercase letters `a` to `z`.
- The answer has at most 40,000 plans.
- The tests include a 24-letter string with no repeated letters: 2²³ ≈ 8.4 million ways to cut, but only one plan. Trying every set of cuts is far too slow; check each piece as you cut it.

<Hints>
<Hint>
Think of the decision at each step as "where does the next piece end?". From position `start`, try every `end` where `text[start...end]` is a palindrome, and continue from `end + 1`. Reaching the end of the string completes a plan.
</Hint>
<Hint>
Work on `Array(text)`, because Swift strings can't be indexed by integers. Keep the pieces so far in an array: append, recurse, remove.
</Hint>
<Hint>
The same slices are checked again and again. A table `isPalindrome[i][j]` answers them all in O(n²) up front: a slice is a palindrome when its end letters match and the slice inside them is one too.
</Hint>
</Hints>

## Solutions

<Approach title="Every set of cuts" time="O(n · 2ⁿ)" space="O(n)">

Each of the n − 1 gaps is cut or not, so loop over all 2ⁿ⁻¹ bitmasks, split the string, and keep the plan if every piece is a palindrome. It never skips a hopeless prefix: for 24 distinct letters, it checks 8.4 million plans to find one.

</Approach>

<Approach title="Backtracking over cut positions, with a palindrome table" time="O(n²) plus O(n) per plan" space="O(n²)">

First fill the table, row by row from the bottom, so the inside slice is always ready. Then backtrack: from each start, only palindromic pieces are chosen, so every branch the search enters leads to at least one plan (the rest can always be cut into single letters).

```swift
public enum PalindromeCutPlans {
    public static func plans(_ text: String) -> [[String]] {
        let letters = Array(text)
        let n = letters.count
        var isPalindrome = Array(repeating: Array(repeating: false, count: n), count: n)
        for i in stride(from: n - 1, through: 0, by: -1) {
            for j in i..<n where letters[i] == letters[j] && (j - i < 2 || isPalindrome[i + 1][j - 1]) {
                isPalindrome[i][j] = true
            }
        }

        var result: [[String]] = []
        var pieces: [String] = []

        func explore(from start: Int) {
            if start == n {
                result.append(pieces)
                return
            }
            for end in start..<n where isPalindrome[start][end] {
                pieces.append(String(letters[start...end]))         // cut after `end`
                explore(from: end + 1)
                pieces.removeLast()                                 // undo the cut
            }
        }

        explore(from: 0)
        return result
    }
}
```

A string of 16 equal letters has 2¹⁵ = 32,768 plans, all valid, so the output itself can be exponential. Checking each piece with a loop instead of the table also passes the tests; the table matters more for long strings with many palindromes.

</Approach>
