Remove a value from a binary search tree and return the root of what's left. The result must still be a binary search tree, and it mustn't be taller than the tree you started with.

`BSTDeleteNode.remove(_ value: Int, from root: TreeNode?) -> TreeNode?`

The root you return may be a different node from the one you were given (for example, when the root itself is removed), or `nil` if the tree becomes empty. If `value` isn't in the tree, return it unchanged.

## Examples

The tree `[50, 30, 70, 20, 40, 60, 80, nil, nil, 35, 45, nil, 65, 75]` has 50 at the root; 35 and 45 under 40; 65 as the right child of 60; and 75 as the left child of 80.

| Remove | Result (level order) |
| --- | --- |
| `20` (a leaf) | `[50, 30, 70, nil, 40, 60, 80, 35, 45, nil, 65, 75]` |
| `60` (one child) | `[50, 30, 70, 20, 40, 65, 80, nil, nil, 35, 45, nil, nil, 75]` |
| `30` (two children) | `[50, 35, 70, 20, 40, 60, 80, nil, nil, nil, 45, nil, 65, 75]` |
| `33` (not there) | unchanged |
| `7` from `[7]` | `nil` (the empty tree) |

When a node has two children there's more than one correct answer. The table shows the result of copying in the **successor**, the next value up (35 for 30). Using the **predecessor**, the next value down (20 for 30), is equally correct. The tests accept any valid result.

## Constraints

- `0 ≤` number of nodes `≤ 200,000`
- `root` is a valid binary search tree with no repeated values.
- Trees in the tests are at most 1,000 levels deep, so recursion is fine.

<Hints>
<Hint>
Find the node first, walking left or right as in a search. Then think about its children. With none, the parent should point at `nil` instead. With one, the parent can point straight at that child: every value below it is still on the correct side of the parent.
</Hint>
<Hint>
With two children, don't move nodes: move a value. The smallest value in the right subtree (go right once, then left as far as possible) is bigger than everything on the left and smaller than everything else on the right, so it can take the node's place. Copy it in, then delete that value from the right subtree.
</Hint>
<Hint>
Recursion makes the re-linking painless: have every call return the root of its subtree after the deletion, and write `node.left = remove(value, from: node.left)`. The node being removed returns its replacement: `node.right`, `node.left`, or itself with a new value.
</Hint>
</Hints>

## Solutions

<Approach title="Recursion that returns the new subtree root" time="O(h)" space="O(h)">

Every call returns the root of its subtree after the deletion, so each parent re-links whatever comes back, and the case where the root itself goes needs no special code. The successor has no left child (otherwise that child would be smaller), so deleting it from the right subtree is always the easy case. h is the height. Nothing gets taller: the only node that disappears is a leaf or a node replaced by its single child.

```swift
public enum BSTDeleteNode {
    public static func remove(_ value: Int, from root: TreeNode?) -> TreeNode? {
        guard let node = root else { return nil }
        if value < node.value {
            node.left = remove(value, from: node.left)
        } else if value > node.value {
            node.right = remove(value, from: node.right)
        } else {
            guard let left = node.left else { return node.right }    // no children, or only a right one
            guard let right = node.right else { return left }        // only a left child
            var successor = right
            while let smaller = successor.left {
                successor = smaller
            }
            node.value = successor.value
            node.right = remove(successor.value, from: right)
        }
        return node
    }
}
```

</Approach>

<Approach title="Loops with a parent pointer" time="O(h)" space="O(1)">

The same cases without recursion. Walk down remembering the parent. For two children, find the successor and its parent, copy the value up, and splice the successor out: its parent adopts its right child. Then one helper re-links a node with at most one child.

```swift
public static func remove(_ value: Int, from root: TreeNode?) -> TreeNode? {
    var parent: TreeNode? = nil
    var current = root
    while let node = current, node.value != value {
        parent = node
        current = value < node.value ? node.left : node.right
    }
    guard var target = current else { return root }        // not there
    if let right = target.right, target.left != nil {
        var successorParent = target
        var successor = right
        while let smaller = successor.left {
            successorParent = successor
            successor = smaller
        }
        target.value = successor.value
        parent = successorParent                           // now remove the successor instead
        target = successor
    }
    let child = target.left ?? target.right                // at most one child left
    guard let parent else { return child }                 // removing the root
    if parent.left === target {
        parent.left = child
    } else {
        parent.right = child
    }
    return root
}
```

</Approach>
