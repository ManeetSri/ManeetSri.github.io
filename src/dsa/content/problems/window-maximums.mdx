Given an array of values and a window size `k`, return the largest value in every window of `k` consecutive values: the window starting at index 0, then the one starting at index 1, and so on, `values.count - k + 1` answers in all.

`WindowMaximums.maxima(in values: [Int], windowSize k: Int) -> [Int]`

Aim for O(n) time, whatever the size of `k`.

## Examples

| `values` | `k` | Output |
| --- | --- | --- |
| `[4, 2, 12, 3, 1, 8, 5]` | `3` | `[12, 12, 12, 8, 8]` |
| `[1, 3, 2, 5, 4]` | `2` | `[3, 3, 5, 5]` |
| `[10, 1, 2, 3, 4]` | `3` | `[10, 3, 4]` |
| `[5, 5, 5, 5]` | `2` | `[5, 5, 5]` |
| `[3, -1, 4]` | `1` | `[3, -1, 4]` |
| `[3, 8, -2, 8, 1]` | `5` | `[8]` |

In the third example, 10 is the maximum of the first window only. Once the window has moved past it, it no longer counts.

## Constraints

- `1 ≤ values.count ≤ 200,000`
- `1 ≤ k ≤ values.count`
- Any `Int` values, including negatives, duplicates, `Int.min` and `Int.max`.

<Hints>
<Hint>
Start with the brute force: `values[start..<(start + k)].max()!` for each start. It's O(n · k), which is too slow when both are large, but it's the perfect checker for a faster version on small inputs.
</Hint>
<Hint>
When a new value arrives, any older value in the window that's no bigger can never be a maximum again: it leaves the window first, and until then the new value is there too. Throw such values away. What's left, from oldest to newest, is decreasing, so the oldest survivor is the maximum.
</Hint>
<Hint>
Keep the survivors' **indexes** in a deque. For each index i: pop the front if it's i − k or earlier (it has left the window); pop from the back while the back value is ≤ `values[i]`; push i at the back; and once i ≥ k − 1, record the front's value. DSAKit's `Deque` is imported in the stub, or use an array with a head index, since you only ever add at the back.
</Hint>
</Hints>

## Solutions

<Approach title="Take each window's maximum" time="O(n · k)" space="O(1) besides the result">

Each window is scanned from scratch. With n = 200,000 and k = 20,000, that's about 3.6 billion comparisons.

```swift
public static func maxima(in values: [Int], windowSize k: Int) -> [Int] {
    (0...(values.count - k)).map { start in values[start..<(start + k)].max()! }
}
```

The force unwrap is safe because every window holds k ≥ 1 values.

</Approach>

<Approach title="Monotonic deque" time="O(n)" space="O(k)">

The deque holds indexes whose values strictly decrease from front to back, so the front is always the current window's maximum. A single step's `while` loop can pop many indexes, but every index is pushed once and popped at most once, from the back (a bigger value arrived) or from the front (it expired). That's at most 2n deque operations in total.

```swift
import DSAKit

public enum WindowMaximums {
    public static func maxima(in values: [Int], windowSize k: Int) -> [Int] {
        var result: [Int] = []
        result.reserveCapacity(Swift.max(0, values.count - k + 1))
        var window = Deque<Int>()                    // indexes, values decreasing front to back
        for i in values.indices {
            if let front = window.first, front <= i - k {
                window.popFirst()
            }
            while let back = window.last, values[back] <= values[i] {
                window.popLast()
            }
            window.append(i)
            if i >= k - 1 {
                result.append(values[window.first!])
            }
        }
        return result
    }
}
```

Storing indexes rather than values is what makes the expiry check possible, and it handles duplicates without any special care. The force unwrap is safe because `i` has already been appended.

</Approach>
