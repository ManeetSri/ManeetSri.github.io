Elements of a stream arrive one at a time. At any moment, report the element that appeared **earliest** among those seen **exactly once** so far, or `nil` if every element seen has been repeated.

`FirstUniqueInStream.UniqueWatcher<Element: Hashable>`, with `init()`, `add(_ element: Element)` and `firstUnique: Element?`

`add` must be O(1) amortised (counting dictionary operations as O(1)), and `firstUnique` O(1).

## Examples

Each row adds the characters one by one and reads `firstUnique` after each, writing `#` for `nil`.

| Stream | Answers |
| --- | --- |
| `"aabcbd"` | `a # b b c c` |
| `"abacbd"` | `a a b b c c` |
| `"swiss"` | `s s s w w` |
| `"abba"` | `a a a #` |
| `"abcabc"` | `a a a b c #` |

In `"aabcbd"`, the second `a` leaves nothing unique (`#`). Then `b` is first, until its second copy arrives and `c` takes over.

## Constraints

- Up to 200,000 calls to `add`.
- Elements can be any `Hashable` type: characters, numbers, strings.

<Hints>
<Hint>
Counting is the easy part: a `[Element: Int]` dictionary tells you whether an element has appeared once or more. The hard part is finding the *earliest* one-timer without scanning everything seen so far.
</Hint>
<Hint>
Keep a queue of elements in the order they **first** appeared. The answer is the first element in that queue whose count is still 1. Once an element at the front has been repeated, can it ever be the answer again?
</Hint>
<Hint>
No: counts only go up. So after each `add`, drop elements from the front while their count is more than 1, and the front is the answer. Repeated elements further back can stay until they reach the front. Each element joins and leaves the queue at most once.
</Hint>
</Hints>

## Solutions

<Approach title="Scan from the start every time" time="O(n) per query" space="O(n)">

Keep every element in arrival order, plus the counts, and look for the first element whose count is 1. Simple and correct, but with 100,000 distinct elements followed by their repeats, each query rescans a long run of repeated elements: O(n²) over the stream.

```swift
public var firstUnique: Element? {
    history.first { counts[$0] == 1 }
}
```

</Approach>

<Approach title="Counts plus a queue of candidates" time="O(1) amortised per element" space="O(distinct elements)">

The queue holds first appearances, oldest first. After each arrival, repeated elements are cleaned off the front, so the front is always the earliest element still seen exactly once. This is **lazy deletion**: a repeated element in the middle of the queue stays put until it reaches the front, so no operation ever has to search the queue.

```swift
public enum FirstUniqueInStream {
    public struct UniqueWatcher<Element: Hashable> {
        private var counts: [Element: Int] = [:]
        private var candidates: [Element] = []      // first appearances, oldest first
        private var head = 0

        public init() {}

        public mutating func add(_ element: Element) {
            counts[element, default: 0] += 1
            if counts[element] == 1 {
                candidates.append(element)
            }
            // A repeated element at the front can never be unique again
            while head < candidates.count && counts[candidates[head], default: 0] > 1 {
                head += 1
            }
            // Release the dead prefix once it's at least half the array
            if head >= 64 && head * 2 >= candidates.count {
                candidates.removeFirst(head)
                head = 0
            }
        }

        public var firstUnique: Element? {
            head < candidates.count ? candidates[head] : nil
        }
    }
}
```

The `while` loop can run many times in one call, but each element is appended once and passed over by `head` once, so the loop's work over the whole stream is O(n). The compaction is the one from the head-index queue lesson: it moves at most as many elements as `head` has passed, so it's amortised O(1) too.

</Approach>
