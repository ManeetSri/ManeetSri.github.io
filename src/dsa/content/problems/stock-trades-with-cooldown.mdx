`prices[i]` is a share's price on day i. You may make as many trades as you like, holding at most one share at a time: buy one share, sell it on a later day, and so on. After a sale, you must wait a day: you can't buy on the day right after you sell. Return the largest total profit you can make, or `0` if trading can't help.

`StockTradesWithCooldown.maxProfit(_ prices: [Int]) -> Int`

## Examples

| `prices` | Output |
| --- | --- |
| `[3, 1, 4, 2, 5, 0, 3]` | `6` |
| `[1, 3, 1, 3]` | `2` |
| `[2, 9, 1, 8, 3, 7]` | `11` |
| `[5, 4, 3, 2]` | `0` |
| `[]` | `0` |

In the first example, buy at 1 and sell at 4, wait a day, then buy at 0 and sell at 3. In the second, selling at 3 on day 1 makes day 2 a waiting day, so the second 1 can't be bought: one trade of 2 is the best. In the third, 2 → 9 and then 3 → 7; without the waiting day, 1 → 8 would fit in too.

## Constraints

- `0 ≤ prices.count ≤ 100,000`
- `0 ≤ prices[i] ≤ 10,000`
- The tests use 100,000 days.

<Hints>
<Hint>
At the end of each day you're in one of a few situations. Holding a share is one. Holding nothing splits into two, because of the cooldown. What are they?
</Hint>
<Hint>
Three states: hold, sold (sold today, so tomorrow you can't buy) and rest (holding nothing, free to buy). Draw the arrows between them, with what each does to your profit.
</Hint>
<Hint>
`hold = max(hold, rest − price)`, `sold = hold + price`, `rest = max(rest, sold)`, all using yesterday's values. Before day 0, holding is impossible. The answer is `max(sold, rest)`.
</Hint>
</Hints>

## Solutions

<Approach title="Best profit from each day on" time="O(n²)" space="O(n)">

Let `free[i]` be the best profit from day i to the end, holding nothing and allowed to buy. Either wait (`free[i + 1]`), or buy on day i, sell on some later day j, and continue from `free[j + 2]`, skipping the waiting day. Trying every j makes this quadratic: fine for a few thousand days, too slow for 100,000.

</Approach>

<Approach title="Three-state machine" time="O(n)" space="O(1)">

Each state's new value is the best over the arrows into it. There's no arrow from sold to hold, which is exactly the cooldown. A tuple assignment computes all three new values from yesterday's before storing any of them.

```swift
public enum StockTradesWithCooldown {
    public static func maxProfit(_ prices: [Int]) -> Int {
        var hold = Int.min / 2      // impossible before day 0
        var sold = 0
        var rest = 0
        for price in prices {
            (hold, sold, rest) = (max(hold, rest - price), hold + price, max(rest, sold))
        }
        return max(sold, rest)
    }
}
```

Updating the three variables one after another in separate statements is the classic bug: `rest` would read today's `sold`, letting a buy happen the day after a sale. `[1, 3, 1, 3]` catches it (the answer is 2, not 4).

</Approach>
