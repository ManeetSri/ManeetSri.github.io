You're writing the paint bucket tool for a drawing app. An image is a grid of colour numbers. Clicking a pixel repaints it with the new colour, along with every pixel joined to it by a chain of same-coloured neighbours (up, down, left or right; diagonals don't count). Return the repainted image.

`PaintBucketFill.fill(_ image: [[Int]], row: Int, column: Int, with colour: Int) -> [[Int]]`

## Examples

| `image` | Click at | `colour` | Returns |
| --- | --- | --- | --- |
| `[[1, 1, 0], [1, 0, 1], [1, 1, 1]]` | `0, 0` | `2` | `[[2, 2, 0], [2, 0, 2], [2, 2, 2]]` |
| `[[1, 0, 0], [1, 1, 0], [0, 0, 1]]` | `0, 1` | `4` | `[[1, 4, 4], [1, 1, 4], [0, 0, 1]]` |
| `[[0, 1], [1, 0]]` | `0, 0` | `5` | `[[5, 1], [1, 0]]` |
| `[[3, 3], [3, 3]]` | `1, 1` | `3` | `[[3, 3], [3, 3]]` |

In the first example, every 1 is connected to the top-left pixel, so they all become 2. The 0 in the top-right corner is cut off from the 0 in the middle, and neither is a 1, so both stay. In the third, the bottom-right 0 only touches the clicked pixel diagonally, so it keeps its colour.

## Constraints

- `1 ≤ rows, columns ≤ 1,000`, and every row has the same length.
- `(row, column)` is inside the image. Colours are any `Int`s.
- The tests include a 1000 × 1000 image whose region is a one-pixel-wide snake of 500,500 pixels. A recursive fill would go about 500,000 calls deep and crash the test thread, which has a small stack (see [Stack depth limits in Swift](/dsa/learn/rec-stack-limits)). Use an explicit stack or a queue.

<Hints>
<Hint>
This is a graph search on a grid: pixels are vertices, and same-coloured neighbours are joined by an edge. Read the clicked pixel's original colour before changing anything.
</Hint>
<Hint>
Keep a stack of pixels to visit. Repaint a pixel the moment you push it: its new colour then doubles as the "visited" mark, because only pixels that still have the original colour are pushed.
</Hint>
<Hint>
What if the new colour is the same as the original? Repainted pixels would still look unvisited, and the loop would never end. Return the image unchanged straight away in that case.
</Hint>
</Hints>

## Solutions

<Approach title="Recursive flood fill" time="O(rows × columns)" space="O(rows × columns)">

Repaint the pixel, then fill from each neighbour that still has the original colour. It's short and correct, but every pixel in a long thin region adds a call to the stack, so the snake test crashes it.

```swift
public static func fill(_ image: [[Int]], row: Int, column: Int, with colour: Int) -> [[Int]] {
    var image = image
    let original = image[row][column]
    if original == colour { return image }
    func paint(_ r: Int, _ c: Int) {
        guard r >= 0, r < image.count, c >= 0, c < image[r].count, image[r][c] == original else { return }
        image[r][c] = colour
        paint(r - 1, c)
        paint(r + 1, c)
        paint(r, c - 1)
        paint(r, c + 1)
    }
    paint(row, column)
    return image
}
```

</Approach>

<Approach title="Iterative DFS with an explicit stack" time="O(rows × columns)" space="O(rows × columns)">

The same search, with the call stack replaced by an array. Each pixel is pushed at most once, because it's repainted as it's pushed and only pixels with the original colour qualify.

```swift
public enum PaintBucketFill {
    private static let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]

    public static func fill(_ image: [[Int]], row: Int, column: Int, with colour: Int) -> [[Int]] {
        var image = image
        let original = image[row][column]
        if original == colour { return image }
        image[row][column] = colour
        var stack = [(row, column)]
        while let cell = stack.popLast() {
            for (dr, dc) in directions {
                let r = cell.0 + dr
                let c = cell.1 + dc
                guard r >= 0, r < image.count, c >= 0, c < image[r].count else { continue }
                guard image[r][c] == original else { continue }
                image[r][c] = colour                     // repaint as it's pushed: never pushed twice
                stack.append((r, c))
            }
        }
        return image
    }
}
```

Swapping `popLast()` for a head-index queue turns this into a BFS. The result is identical: a fill only cares about which pixels are reachable, not the order they're reached in.

</Approach>
