A charity pairs up volunteers so that each pair covers as much ground as possible, and the best pairs share no skill at all. There are `skillCount` skills, and each volunteer's skills are a bitmask: bit s is set when they have skill s. Return how many pairs of different volunteers `i < j` have no skill in common, that is, `skills[i] & skills[j] == 0`.

`DisjointSkillPairs.countPairs(_ skills: [Int], skillCount: Int) -> Int`

## Examples

| `skills` | `skillCount` | Output |
| --- | --- | --- |
| `[0b011, 0b100, 0b110, 0b001]` | `3` | `3` |
| `[0b1010, 0b0101, 0b1111, 0b0000]` | `4` | `4` |
| `[0, 0, 0]` | `2` | `3` |
| `[1, 1, 1]` | `1` | `0` |
| `[]` | `4` | `0` |

In the first example, the disjoint pairs are `011` with `100`, `100` with `001`, and `110` with `001`. In the second, the volunteer with no skills pairs with all three others, and `1010` pairs with `0101`. In the third, volunteers with no skills share nothing, so all three pairs count.

## Constraints

- `1 ≤ skillCount ≤ 16`
- `0 ≤ skills.count ≤ 100,000`, and every value is in `0..<(1 << skillCount)`.
- The tests use 100,000 volunteers, so checking every pair (five billion of them) is far too slow.

<Hints>
<Hint>
Fix one volunteer with skills x. Their partner must not have any skill x has. Describe the set of allowed partner masks using `full = (1 << skillCount) - 1`.
</Hint>
<Hint>
The partner's mask must be a submask of `full ^ x`. So if you knew, for every mask m, how many volunteers' masks are submasks of m, each volunteer's partner count would be one lookup.
</Hint>
<Hint>
Count each exact mask, then run sum over subsets: for each bit, every mask containing it adds the count of the same mask without it. Add up `count[full ^ x]` over all volunteers, subtract the volunteers with no skills (each counted itself), and halve, because every pair was counted from both ends.
</Hint>
</Hints>

## Solutions

<Approach title="Check every pair" time="O(n²)" space="O(1)">

Two loops and an `&`. Correct, and the tests use it on small groups, but 100,000 volunteers make five billion pairs.

</Approach>

<Approach title="Sum over subsets" time="O(k · 2ᵏ + n)" space="O(2ᵏ)">

With k skills, SOS fills the submask counts in k passes over 2ᵏ masks, whatever the number of volunteers.

```swift
public enum DisjointSkillPairs {
    public static func countPairs(_ skills: [Int], skillCount: Int) -> Int {
        let size = 1 << skillCount
        let full = size - 1
        var count = [Int](repeating: 0, count: size)
        for x in skills { count[x] += 1 }
        for bit in 0..<skillCount {
            for mask in 0..<size where mask & (1 << bit) != 0 {
                count[mask] += count[mask ^ (1 << bit)]
            }
        }
        var ordered = 0
        for x in skills {
            ordered += count[full ^ x]
        }
        let noSkills = skills.filter { $0 == 0 }.count
        return (ordered - noSkills) / 2
    }
}
```

The only volunteer who can be their own partner is one with no skills, since `x & x` is `x`. That's why exactly the zeros are subtracted before halving. The answer can reach about 5 × 10⁹, which needs a 64-bit `Int`.

</Approach>
