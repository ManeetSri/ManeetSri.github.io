A feed screen refreshes: the server sends the new list of post ids, and the table view should animate only what changed instead of reloading everything. Work out the batch update: which old rows to delete and which new rows to insert, using as few changes as possible. Rows that stay keep their order, so a row that moved counts as one deletion plus one insertion.

`TableRowDiff.changes(from old: [String], to new: [String]) -> Changes`, where `Changes` has `deletions: [Int]` and `insertions: [Int]`

`deletions` are indexes into `old` and `insertions` are indexes into `new`, both in increasing order: exactly what `performBatchUpdates` expects. Ids are unique within each list. When several answers have the fewest changes, any of them is accepted.

## Examples

| `old` | `new` | `deletions` | `insertions` |
| --- | --- | --- | --- |
| `["a", "b", "c", "d"]` | `["a", "c", "d", "e"]` | `[1]` | `[3]` |
| `[]` | `["x", "y"]` | `[]` | `[0, 1]` |
| `["a", "b", "c"]` | `["c", "a", "b"]` | `[2]` | `[0]` |
| `["h", "a", "b", "f"]` | `["h", "n", "a", "f", "t"]` | `[2]` | `[1, 4]` |
| `["a", "b"]` | `["b", "a"]` | `[0]` or `[1]` | `[1]` or `[0]` |

In the third example, keeping `a` and `b` and moving `c` costs two changes; keeping only `c` would cost four. In the last, you can keep either row, but not both: deleting `a` and re-inserting it at index 1 is as good as doing the same with `b`.

## Constraints

- `0 ≤ old.count, new.count ≤ 2,000`
- Ids are unique within each list; the same id can appear in both.
- The tests diff two lists of 2,000 rows, so an O(n · m) algorithm is fine, but trying subsets is not.

## Solutions

<Approach title="Longest common subsequence" time="O(n · m)" space="O(n · m)">

The table is flattened into one array, which is faster than an array of arrays. `keep[(i + 1) * width + j] >= keep[i * width + j + 1]` asks: if I give up `old[i]`, do I lose anything? If not, it's a deletion.

```swift
public enum TableRowDiff {
    public struct Changes: Equatable, CustomStringConvertible {
        public var deletions: [Int]
        public var insertions: [Int]

        public init(deletions: [Int], insertions: [Int]) {
            self.deletions = deletions
            self.insertions = insertions
        }

        public var description: String { "deletions \(deletions), insertions \(insertions)" }
    }

    public static func changes(from old: [String], to new: [String]) -> Changes {
        let n = old.count, m = new.count
        let width = m + 1
        var keep = Array(repeating: 0, count: (n + 1) * width)
        for i in stride(from: n - 1, through: 0, by: -1) {
            for j in stride(from: m - 1, through: 0, by: -1) {
                keep[i * width + j] = old[i] == new[j]
                    ? keep[(i + 1) * width + j + 1] + 1
                    : max(keep[(i + 1) * width + j], keep[i * width + j + 1])
            }
        }

        var changes = Changes(deletions: [], insertions: [])
        var i = 0, j = 0
        while i < n && j < m {
            if old[i] == new[j] {
                i += 1
                j += 1
            } else if keep[(i + 1) * width + j] >= keep[i * width + j + 1] {
                changes.deletions.append(i)      // skipping old[i] loses nothing
                i += 1
            } else {
                changes.insertions.append(j)
                j += 1
            }
        }
        changes.deletions += Array(i..<n)
        changes.insertions += Array(j..<m)
        return changes
    }
}
```

`stride(from: n - 1, through: 0, by: -1)` is empty when `n` is 0, where `(n - 1)...0` would crash.

</Approach>

<Approach title="Unique ids: longest increasing subsequence" time="O((n + m) log n)" space="O(n + m)">

Because ids are unique, each new row matches at most one old position. Write down, in new order, the old position of every row that exists in both lists. Rows that can stay together must have increasing old positions, so the rows to keep are a **longest increasing subsequence** of those positions, found with patience sorting as in [LIS in O(n log n) with patience sorting](/dsa/learn/lis-n-log-n).

```swift
public static func changes(from old: [String], to new: [String]) -> Changes {
    let position = Dictionary(uniqueKeysWithValues: old.enumerated().map { ($1, $0) })
    // tails[k]: index into `new` of the smallest-ending increasing run of length k + 1
    var tails: [Int] = []
    var previous = Array(repeating: -1, count: new.count)
    for (j, id) in new.enumerated() {
        guard let value = position[id] else { continue }
        var low = 0, high = tails.count
        while low < high {
            let mid = (low + high) / 2
            if position[new[tails[mid]]]! < value { low = mid + 1 } else { high = mid }
        }
        if low > 0 { previous[j] = tails[low - 1] }
        if low == tails.count { tails.append(j) } else { tails[low] = j }
    }
    var keptNew = Set<Int>()
    var j = tails.last ?? -1
    while j >= 0 {
        keptNew.insert(j)
        j = previous[j]
    }
    let keptOld = Set(keptNew.map { position[new[$0]]! })
    return Changes(deletions: old.indices.filter { !keptOld.contains($0) },
                   insertions: new.indices.filter { !keptNew.contains($0) })
}
```

This is the core of the "patience diff" idea that Git offers as an option. Swift's own `new.difference(from: old)` returns a `CollectionDifference` built with Myers' algorithm, a cleverer way to find a shortest edit script for any lists, duplicates included. Real diff tools also report *moves* separately, so a moved row can slide into place rather than vanish and reappear.

</Approach>
