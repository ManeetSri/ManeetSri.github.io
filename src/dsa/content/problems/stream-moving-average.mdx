Values arrive one at a time, like readings from a sensor. After each one, return the average of the most recent `windowSize` values, or of every value so far while fewer than `windowSize` have arrived.

`StreamMovingAverage.MovingAverage`, with `init(windowSize: Int)` and `next(_ value: Int) -> Double`

Each call to `next` must be O(1), however large the window is.

## Examples

| Window size | Values passed to `next`, in order | Results |
| --- | --- | --- |
| 3 | 10, 20, 30, 40, 50, 0 | 10.0, 15.0, 20.0, 30.0, 40.0, 30.0 |
| 2 | 4, 8, 6, 2 | 4.0, 6.0, 7.0, 4.0 |
| 1 | 5, -3, 9 | 5.0, -3.0, 9.0 |
| 4 | 1, 2 | 1.0, 1.5 |

In the first example, when 40 arrives, 10 drops out of the window: (20 + 30 + 40) / 3 = 30.0.

## Constraints

- `1 ≤ windowSize ≤ 100,000`
- `-10⁹ ≤ value ≤ 10⁹`
- Up to 1,000,000 calls to `next`. Results are checked to within a tiny tolerance.

<Hints>
<Hint>
Adding up the whole window on every call is O(windowSize). Instead, keep a running `sum`. What changes when a new value arrives and the window is already full?
</Hint>
<Hint>
Add the new value to the sum, and subtract the value that falls out of the window. To know which value that is, keep the last `windowSize` values in a queue, oldest first.
</Hint>
<Hint>
A ring buffer of exactly `windowSize` slots is ideal: the new value overwrites the oldest one's slot. Keep `head` (the oldest value's slot) and `count`. Keep the sum as an `Int`, which is exact, and convert to `Double` only when dividing.
</Hint>
</Hints>

## Solutions

<Approach title="Sum the window every time" time="O(windowSize) per value" space="O(windowSize)">

Keep the values in an array, drop the oldest when there are too many, and add up what's left. With a window of 5,000 and a million values, that's billions of additions, and the `removeFirst()` shifts the whole window too.

```swift
public mutating func next(_ value: Int) -> Double {
    values.append(value)
    if values.count > windowSize {
        values.removeFirst()
    }
    return Double(values.reduce(0, +)) / Double(values.count)
}
```

</Approach>

<Approach title="A ring buffer and a running sum" time="O(1) per value" space="O(windowSize)">

The window is a ring of `windowSize` slots. Until it fills, each value goes into the next free slot. Once it's full, each value replaces the oldest one: subtract the old value from the sum, write the new one in its slot, and move `head` round.

```swift
public enum StreamMovingAverage {
    public struct MovingAverage {
        private var window: [Int]
        private var head = 0              // the slot of the oldest value
        private var count = 0
        private var sum = 0

        public init(windowSize: Int) {
            precondition(windowSize > 0, "The window must hold at least one value")
            window = Array(repeating: 0, count: windowSize)
        }

        public mutating func next(_ value: Int) -> Double {
            if count == window.count {
                sum -= window[head]                       // the oldest value leaves…
                window[head] = value                      // …and the new one takes its slot
                head = (head + 1) % window.count
            } else {
                window[(head + count) % window.count] = value
                count += 1
            }
            sum += value
            return Double(sum) / Double(count)
        }
    }
}
```

The sum of up to 100,000 values of up to 10⁹ each is at most 10¹⁴, well within an `Int`. A running `Double` sum would slowly drift as rounding errors pile up; the `Int` sum stays exact forever.

</Approach>
