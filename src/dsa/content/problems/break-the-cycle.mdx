An owner and a pet each need to know about the other. Finish `adopt` so it links them in both directions, and fix the classes so the pair never forms a retain cycle.

`PetAdoption.Owner.adopt(_ newPet: PetAdoption.Pet)`

The rules:

- After `owner.adopt(pet)`, `owner.pet` is `pet` and `pet.owner` is `owner`.
- An owner keeps its pet alive. A pet must **not** keep its owner alive: when the owner is freed, `pet.owner` becomes `nil`.
- If the owner already had a different pet, that pet's `owner` becomes `nil`.
- If the pet already had a different owner, that owner's `pet` becomes `nil`.

## Examples

| Code | Afterwards |
| --- | --- |
| `asha.adopt(pepper)` | `asha.pet` is Pepper, `pepper.owner` is Asha |
| `asha.adopt(pepper)`, then `ravi.adopt(pepper)` | `asha.pet` is `nil`, `ravi.pet` is Pepper, `pepper.owner` is Ravi |
| `asha.adopt(pepper)`, then `asha.adopt(mango)` | `pepper.owner` is `nil`, `asha.pet` is Mango |
| Asha adopts Pepper, then every variable holding Asha goes away | Asha is freed and `pepper.owner` is `nil` |

## Constraints

- Change the declaration of exactly one of the two properties; keep both names and types otherwise.
- The tests check for leaks by holding `weak` references to your objects and checking they become `nil`.

<Hint>
The owner owns the pet, so `Owner.pet` stays strong. The back-reference, `Pet.owner`, should be `weak`. It's already optional, as a weak reference must be.
</Hint>
<Hint>
In `adopt`, clear the old links first: set your current pet's `owner` to `nil`, and set the new pet's current owner's `pet` to `nil`. Then set both new links. Optional chaining (`pet?.owner = nil`) handles the cases where there's nothing to clear.
</Hint>
</Hints>

## Solutions

<Approach title="Weak back-reference, clear old links first" time="O(1)" space="O(1)">

Making `owner` weak breaks the cycle: the pet can still reach its owner, but doesn't keep it alive, and Swift sets the reference to `nil` when the owner is freed. `adopt` unhooks any old relationships before creating the new one, so no object is left pointing at someone who has moved on.

```swift
public enum PetAdoption {
    public final class Owner {
        public let name: String
        public var pet: Pet?

        public init(name: String) {
            self.name = name
        }

        public func adopt(_ newPet: Pet) {
            pet?.owner = nil          // my previous pet no longer has an owner
            newPet.owner?.pet = nil   // the pet's previous owner no longer has a pet
            pet = newPet
            newPet.owner = self
        }
    }

    public final class Pet {
        public let name: String
        public weak var owner: Owner?

        public init(name: String) {
            self.name = name
        }
    }
}
```

Adopting the same pet twice still works: the first line clears the pet's `owner`, the second finds no owner to clear, and the last two lines restore both links.

</Approach>
