Two straight cables are laid across a circuit board. Decide how they meet: not at all, at exactly one point, or along a shared stretch.

`SegmentContact.contact(_ first: [[Int]], _ second: [[Int]]) -> SegmentContact.Contact`

Each cable is a segment `[[x1, y1], [x2, y2]]`, ends included. Its two ends may be the same point, in which case the cable is a single point. The answer is one of:

- `.disjoint`: no point in common;
- `.point`: exactly one point in common, whether they cross, touch, or share an end;
- `.overlap`: infinitely many points in common, which only happens when they lie along the same line and overlap for a positive length.

## Examples

| `first` | `second` | Output |
| --- | --- | --- |
| `[[0, 0], [4, 4]]` | `[[0, 4], [4, 0]]` | `.point` |
| `[[0, 0], [4, 0]]` | `[[2, 0], [2, 5]]` | `.point` |
| `[[0, 0], [4, 0]]` | `[[2, 0], [9, 0]]` | `.overlap` |
| `[[0, 0], [4, 0]]` | `[[4, 0], [9, 0]]` | `.point` |
| `[[0, 0], [4, 0]]` | `[[5, 0], [9, 0]]` | `.disjoint` |
| `[[0, 0], [4, 4]]` | `[[5, 0], [5, 9]]` | `.disjoint` |
| `[[1, 1], [1, 1]]` | `[[0, 0], [2, 2]]` | `.point` |

The second example is a T-junction. In the fourth, the cables lie along one line but only touch end to end. In the sixth, the vertical cable crosses the line y = x at (5, 5), beyond the end of the first cable.

## Constraints

- `-10⁹ ≤ x, y ≤ 10⁹`
- A cross product of coordinate differences can approach 8 × 10¹⁸. That fits in an `Int`, but the product of two of them doesn't.

<Hints>
<Hint>
Compute the four orientations: where each end of the second cable lies relative to the line through the first, and the other way round. Reduce each to its sign, -1, 0 or 1, before combining them.
</Hint>
<Hint>
If each cable's ends are strictly on opposite sides of the other's line, they cross at one point. If all four orientations are 0, every end is on one line, including the case where a cable is a single point.
</Hint>
<Hint>
On one line, the cables are intervals. Points on a line are ordered by `(x, y)`, so intersect the two intervals `[min, max]` in that order: compare the larger of the two minimums with the smaller of the two maximums. Otherwise, they share at most one point, and they share one exactly when an end of one lies on the other: orientation 0 and inside its bounding box.
</Hint>
</Hints>

## Solutions

<Approach title="Solve for the crossing with fractions" time="O(1)" space="O(1)">

Write the cables as A + t·r and C + u·s and solve for t and u with cross products, keeping them as exact fractions and checking both are between 0 and 1. Parallel cables (cross(r, s) = 0) and single-point cables each need their own branch, and collinear cables need projecting onto r with the dot product. It works, but it's three special cases deep, which is where bugs hide.

</Approach>

<Approach title="Orientation signs, then intervals on a line" time="O(1)" space="O(1)">

The standard segment test from the lesson, with the all-collinear case answered by interval overlap instead of a yes or no.

```swift
public enum SegmentContact {
    public enum Contact: Equatable, Sendable {
        case disjoint, point, overlap
    }

    struct Point: Comparable {
        var x: Int
        var y: Int
        static func < (lhs: Point, rhs: Point) -> Bool { (lhs.x, lhs.y) < (rhs.x, rhs.y) }
    }

    static func orientation(_ a: Point, _ b: Point, _ c: Point) -> Int {
        let cross = (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x)
        return cross > 0 ? 1 : (cross < 0 ? -1 : 0)
    }

    static func within(_ p: Point, _ a: Point, _ b: Point) -> Bool {
        min(a.x, b.x) <= p.x && p.x <= max(a.x, b.x) && min(a.y, b.y) <= p.y && p.y <= max(a.y, b.y)
    }

    public static func contact(_ first: [[Int]], _ second: [[Int]]) -> Contact {
        let a = Point(x: first[0][0], y: first[0][1]), b = Point(x: first[1][0], y: first[1][1])
        let c = Point(x: second[0][0], y: second[0][1]), d = Point(x: second[1][0], y: second[1][1])
        let o1 = orientation(a, b, c), o2 = orientation(a, b, d)
        let o3 = orientation(c, d, a), o4 = orientation(c, d, b)
        if o1 * o2 < 0 && o3 * o4 < 0 {
            return .point                                   // a proper crossing
        }
        if o1 == 0 && o2 == 0 && o3 == 0 && o4 == 0 {       // all on one line
            let low = max(min(a, b), min(c, d))
            let high = min(max(a, b), max(c, d))
            if low < high { return .overlap }
            return low == high ? .point : .disjoint
        }
        let touches = (o1 == 0 && within(c, a, b)) || (o2 == 0 && within(d, a, b))
            || (o3 == 0 && within(a, c, d)) || (o4 == 0 && within(b, c, d))
        return touches ? .point : .disjoint
    }
}
```

Why `(x, y)` order works on any line: along a line that isn't vertical, x always increases in one direction, and along a vertical line x is fixed and y does the ordering. If a cable is a single point, the two orientations measured from it are always 0. The other two are 0 exactly when the point lies on the other cable's line, and then the interval code handles it like any other interval; otherwise the touching checks correctly find nothing.

</Approach>
