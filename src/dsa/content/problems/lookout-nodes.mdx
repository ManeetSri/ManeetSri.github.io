On a mountain trail map stored as a binary tree, a node is a **lookout** if its value (an altitude) is strictly greater than every one of its ancestors **and** strictly greater than every one of its descendants. Count the lookouts.

`LookoutNodes.count(in root: TreeNode?) -> Int`

The root has no ancestors and a leaf has no descendants, so for them only the other half of the rule matters: a lone node is a lookout. Each node needs something from above and something from below, so this is a "down and up at once" problem: choose your traversal with that in mind, and with the depth of the trees in the constraints.

## Examples

| Tree (level order) | Output | Lookouts |
| --- | --- | --- |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `3` | 4, 7 and 6: each beats everything above it and is a leaf |
| `[10, 4, 3]` | `1` | 10 beats both descendants and has no ancestors |
| `[5, 3, 8, 1, 4, 7, 9]` | `1` | only 9; 8 beats 5 above it but not 9 below |
| `[5, 5]` | `0` | strictly greater: neither 5 beats the other |
| `[7]` | `1` | a lone node |
| `[]` | `0` | no nodes |

## Constraints

- `0 ≤` number of nodes `≤ 100,000`
- Trees can be chains 100,000 levels deep, so recursion will crash the test run. Use a loop.
- Values can be any `Int`.

<Hints>
<Hint>
Split the rule in two. "Greater than every ancestor" needs the largest value **above** the node: pass it down, as preorder does. "Greater than every descendant" needs the largest value **below** it: return it up, as postorder does. Write the recursive version first, with one parameter and one return value, to get the logic right.
</Hint>
<Hint>
To remove the recursion, keep an explicit stack of frames. Each frame needs the node, the largest value above it, and whether its children have been handled yet. The first time you pop a node, push it back marked "children done", then push its children with the larger of the two values as their "largest above".
</Hint>
<Hint>
Children finish before their parent, so their answers (each subtree's largest value) can go on a second stack. When a node comes off marked "children done", pop one answer per child it has, decide whether it's a lookout, and push its own subtree's largest value.
</Hint>
</Hints>

## Solutions

<Approach title="Down and up, recursively" time="O(n)" space="O(h) call stack">

The largest ancestor comes down as a parameter, and the largest value in each subtree goes back up as the return value. Clear and short, but it recurses once per level, so a 100,000-level chain overflows the stack.

```swift
public static func count(in root: TreeNode?) -> Int {
    var lookouts = 0
    // Returns the largest value in node's subtree, or Int.min for no node
    func walk(_ node: TreeNode?, _ largestAbove: Int?) -> Int {
        guard let node else { return Int.min }
        let above = max(largestAbove ?? Int.min, node.value)
        let largestBelow = max(walk(node.left, above), walk(node.right, above))
        let beatsAbove = largestAbove.map { node.value > $0 } ?? true
        let beatsBelow = (node.left == nil && node.right == nil) || node.value > largestBelow
        if beatsAbove && beatsBelow { lookouts += 1 }
        return max(node.value, largestBelow)
    }
    _ = walk(root, nil)
    return lookouts
}
```

`Int?` for the largest ancestor, and the explicit leaf check, avoid treating `Int.min` as a real value: a root holding `Int.min` is still a lookout if it has no children.

</Approach>

<Approach title="Down and up, with explicit stacks" time="O(n)" space="O(h) heap memory">

The same logic as a loop. Frames carry the downward information. A second stack collects the upward answers: when a node's children are done, their subtree maxima sit on top of it, one per child.

```swift
import DSAKit

public enum LookoutNodes {
    public static func count(in root: TreeNode?) -> Int {
        guard let root else { return 0 }
        var lookouts = 0
        var frames: [(node: TreeNode, largestAbove: Int?, childrenDone: Bool)] = [(root, nil, false)]
        var subtreeMax: [Int] = []                     // answers coming back up
        while let (node, largestAbove, childrenDone) = frames.popLast() {
            if !childrenDone {
                frames.append((node, largestAbove, true))           // come back after the children
                let above = max(largestAbove ?? Int.min, node.value)
                if let left = node.left { frames.append((left, above, false)) }
                if let right = node.right { frames.append((right, above, false)) }
                continue
            }
            var largestBelow: Int? = nil
            let childCount = (node.left == nil ? 0 : 1) + (node.right == nil ? 0 : 1)
            for _ in 0..<childCount {                               // one answer per child
                let below = subtreeMax.removeLast()
                largestBelow = max(largestBelow ?? below, below)
            }
            let beatsAbove = largestAbove.map { node.value > $0 } ?? true
            let beatsBelow = largestBelow.map { node.value > $0 } ?? true
            if beatsAbove && beatsBelow { lookouts += 1 }
            subtreeMax.append(max(node.value, largestBelow ?? node.value))
        }
        return lookouts
    }
}
```

Every node is pushed twice and popped twice, so it's O(n), and the stacks live in heap memory, which a deep chain can't exhaust. When a problem needs information in both directions, ask separately what comes down and what goes up: those are the parameter and the return value, or here, the frame and the answer stack.

</Approach>
