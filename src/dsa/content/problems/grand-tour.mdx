A touring band plans a grand tour of `n` cities. It starts in city 0, plays every other city exactly once, and comes home to city 0. `distance[i][j]` is the length of the road from city i to city j, and the road back from j to i may be a different length. Return the length of the shortest possible tour.

`GrandTourPlanner.shortestTour(_ distance: [[Int]]) -> Int`

## Examples

| `distance` | Returns |
| --- | --- |
| `[[0, 3, 8, 5], [3, 0, 4, 9], [8, 4, 0, 2], [5, 9, 2, 0]]` | `14`: 0 → 1 → 2 → 3 → 0 is 3 + 4 + 2 + 5 |
| `[[0, 1, 10], [10, 0, 1], [1, 10, 0]]` | `3`: 0 → 1 → 2 → 0; the other direction costs 30 |
| `[[0, 5], [7, 0]]` | `12` |
| `[[0]]` | `0`: a tour of one city goes nowhere |

## Constraints

- `1 ≤ n ≤ 12`, `distance` is n × n, and `distance[i][i] == 0`.
- `0 ≤ distance[i][j] ≤ 1,000,000`. Distances don't have to obey the triangle inequality: a detour can be shorter than the direct road.
- Trying every order of the other cities is 11! ≈ 40 million tours for 12 cities, each costing up to 12 additions, and the tests do that six times. The bitmask DP needs about 600,000 steps per map.

<Hints>
<Hint>
Two partial tours that start at city 0, have visited the same set of cities and stand in the same city can be finished in exactly the same ways. Only the shorter one matters.
</Hint>
<Hint>
Let `best[mask][last]` be the length of the shortest path that starts at city 0, visits exactly the cities in `mask`, and ends at `last`. Start from `best[1][0] = 0` (only city 0 visited) and extend each path by one unvisited city at a time.
</Hint>
<Hint>
A bigger mask always comes from a smaller one, so looping over masks in increasing order fills every state before it's used. The answer is the smallest `best[full][last] + distance[last][0]`, where `full` is `(1 << n) - 1`.
</Hint>
</Hints>

## Solutions

<Approach title="Every order of the cities" time="O(n! · n)" space="O(n)">

Fix city 0 at the start and try all (n − 1)! orders of the rest, by recursion or by stepping through permutations, adding up each tour. It's the clearest correct answer and a good checker for small maps, but 12 cities already means about 40 million tours.

</Approach>

<Approach title="Held–Karp bitmask DP" time="O(2ⁿ · n²)" space="O(2ⁿ · n)">

The table has 2ⁿ masks times n end cities, and each state tries up to n next cities. Storing it as one flat array indexed by `mask * n + last` keeps it compact and fast.

```swift
public enum GrandTourPlanner {
    public static func shortestTour(_ distance: [[Int]]) -> Int {
        let n = distance.count
        if n <= 1 { return 0 }
        let full = 1 << n
        let unreached = Int.max / 2
        var best = [Int](repeating: unreached, count: full * n)
        best[1 * n + 0] = 0                            // at city 0, having visited only city 0

        for mask in 1..<full where mask & 1 == 1 {     // every path starts at city 0
            for last in 0..<n where mask & (1 << last) != 0 {
                let cost = best[mask * n + last]
                if cost == unreached { continue }
                for next in 0..<n where mask & (1 << next) == 0 {
                    let state = (mask | (1 << next)) * n + next
                    let candidate = cost + distance[last][next]
                    if candidate < best[state] {
                        best[state] = candidate
                    }
                }
            }
        }

        var shortest = unreached
        for last in 1..<n {
            shortest = min(shortest, best[(full - 1) * n + last] + distance[last][0])
        }
        return shortest
    }
}
```

`Int.max / 2` marks a state that hasn't been reached, and it's small enough that adding a distance to it can't overflow. Masks without city 0 are skipped, since every path starts there. You'll see this pattern again, with more variations, in the bitmask DP lesson of M58.


</Approach>
