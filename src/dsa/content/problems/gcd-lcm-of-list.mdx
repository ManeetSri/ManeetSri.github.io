Given a list of positive whole numbers, return their greatest common divisor, and their least common multiple. The lcm can get enormous, so return `nil` for it whenever it's bigger than `Int.max`.

`ListGcdLcm.gcd(of numbers: [Int]) -> Int`

`ListGcdLcm.lcm(of numbers: [Int]) -> Int?`

Write your own `gcd` helper with Euclid's algorithm: Swift doesn't have one built in.

## Examples

| Input | `gcd(of:)` | `lcm(of:)` |
| --- | --- | --- |
| `[12, 18, 30]` | `6` | `180` |
| `[4, 6, 8]` | `2` | `24` |
| `[7]` | `7` | `7` |
| `[1_000_000_000, 999_999_999]` | `1` | `999999999000000000` |
| `[1, 2, 3, …, 43]` | `1` | `nil`, since the true lcm is about 9.4 × 10¹⁸ |

## Constraints

- `1 ≤ numbers.count ≤ 100,000`
- `1 ≤ numbers[i] ≤ 1,000,000,000`

<Hints>
<Hint>
Both answers can be built up one number at a time: gcd(a, b, c) = gcd(gcd(a, b), c), and the same for lcm. What should the running gcd start at? What should the running lcm start at?
</Hint>
<Hint>
gcd(0, x) = x, so the gcd can start at 0. lcm(1, x) = x, so the lcm can start at 1. For two numbers, lcm(a, b) = a / gcd(a, b) * b. Divide first, so the intermediate value is never bigger than the answer.
</Hint>
<Hint>
Even dividing first, the multiplication overflows when the true lcm doesn't fit. Use `multipliedReportingOverflow(by:)` and return `nil` as soon as `overflow` is true.
</Hint>
</Hints>

## Solutions

<Approach title="Fold with Euclid, checking each multiplication" time="O(n log M)" space="O(1)">

Both answers fold over the list. The gcd starts at 0 and the lcm at 1, since those leave the first number unchanged. Each step costs one Euclid call, which is O(log M) for values up to M.

```swift
public enum ListGcdLcm {
    public static func gcd(of numbers: [Int]) -> Int {
        numbers.reduce(0, gcd)
    }

    public static func lcm(of numbers: [Int]) -> Int? {
        var result = 1
        for number in numbers {
            let step = (result / gcd(result, number)).multipliedReportingOverflow(by: number)
            if step.overflow {
                return nil
            }
            result = step.partialValue
        }
        return result
    }

    private static func gcd(_ first: Int, _ second: Int) -> Int {
        var a = first
        var b = second
        while b != 0 {
            (a, b) = (b, a % b)
        }
        return a
    }
}
```

Two small improvements are possible. The gcd loop can stop as soon as the running value is 1, since it can't get any smaller. And once the lcm overflows, there's no point looking further, which the early `return nil` already handles.

Why check the multiplication rather than compare with `Int.max` afterwards? Because by then it's too late: a plain `*` that overflows traps immediately. `multipliedReportingOverflow` gives you the chance to react.

</Approach>
