A map app has thousands of pins, and every tap asks "which pin is closest to here?". Given the pins and a batch of tap positions, return the index of the nearest pin for each tap, fast enough for tens of thousands of each.

`NearestMapPin.nearest(pins: [[Int]], queries: [[Int]]) -> [Int]`

- Each pin and each query is `[x, y]`.
- For each query, return the index of the pin with the smallest Euclidean distance to it. If several pins are equally near, return the **smallest** index among them.

## Examples

| `pins` | `queries` | Output |
| --- | --- | --- |
| `[[0, 0], [10, 0], [0, 10]]` | `[[1, 1], [9, 2], [2, 7], [100, 100]]` | `[0, 1, 2, 1]` |
| `[[0, 0], [2, 0]]` | `[[1, 0], [1, 5], [3, 0]]` | `[0, 0, 1]` |
| `[[4, 4], [4, 4], [1, 1]]` | `[[4, 4], [3, 3], [2, 2]]` | `[0, 0, 2]` |
| `[[5, 5]]` | `[]` | `[]` |

In the first example, (100, 100) is equally far from (10, 0) and (0, 10), so the answer is the smaller index, 1. In the second, (1, 0) and (1, 5) are equally far from both pins.

## Constraints

- `1 ≤ pins.count ≤ 50,000` and `0 ≤ queries.count ≤ 50,000`.
- Coordinates are between −1,000,000 and 1,000,000, so squared distances fit easily in an `Int`.
- Pins may repeat, and may all lie on one line.
- The tests use 30,000 pins and 30,000 queries. Checking every pin for every query is 900 million distance calculations.

<Hints>
<Hint>
Compare squared distances, `dx * dx + dy * dy`, in integers: no square roots, no rounding. To handle ties, compare (distance, index) pairs.
</Hint>
<Hint>
Build a k-d tree: split the pins at the median by x, then each half at its median by y, alternating by depth. You can store it implicitly: an array of pin indices where the node for positions `lo..<hi` is at the middle, with the smaller half before it. Sorting each range by the current coordinate works; quickselect, which only puts the median in place, builds it faster.
</Hint>
<Hint>
Search the side of the split the query is on first, then the other side only if the squared gap to the splitting line is less than the best squared distance so far. Ties make that subtle: if the gap equals the best distance, a pin on the other side could tie it with a smaller index. Either search the other side when the gap is less than **or equal to** the best distance, or, faster on repeated pins, store each subtree's smallest pin index and search it only when that index could win.
</Hint>
</Hints>

## Solutions

<Approach title="Check every pin" time="O(pins × queries)" space="O(1) extra">

For each query, loop over the pins and keep the best (squared distance, index) pair. It's three lines and clearly right, so it's what the tests compare against on small inputs, but 30,000 × 30,000 is far too much.

</Approach>

<Approach title="Implicit k-d tree with tie-aware pruning" time="O(n log n) to build; close to O(log n) per query" space="O(n)">

Quickselect places each range's median at the middle in O(range) on average, so the whole build is O(n log n). Each node also records the smallest pin index in its subtree, which lets the search skip a far side that could only tie with a larger index.

```swift
public enum NearestMapPin {
    public static func nearest(pins: [[Int]], queries: [[Int]]) -> [Int] {
        let xs = pins.map { $0[0] }
        let ys = pins.map { $0[1] }
        var order = Array(pins.indices)
        var smallestBelow = Array(repeating: Int.max, count: pins.count)   // by node position

        // Rearranges order[lo..<hi] so the median (by key, then index) is at the middle, with smaller
        // pins before it and larger ones after: quickselect, O(hi - lo) on average.
        func placeMedian(_ lo: Int, _ hi: Int, _ keys: [Int]) {
            func less(_ a: Int, _ b: Int) -> Bool { keys[a] != keys[b] ? keys[a] < keys[b] : a < b }
            let target = (lo + hi) / 2
            var low = lo, high = hi - 1
            while low < high {
                let pivot = order[(low + high) / 2]
                var i = low, j = high
                while i <= j {
                    while less(order[i], pivot) { i += 1 }
                    while less(pivot, order[j]) { j -= 1 }
                    if i <= j {
                        order.swapAt(i, j)
                        i += 1
                        j -= 1
                    }
                }
                if target <= j { high = j } else if target >= i { low = i } else { return }
            }
        }

        func build(_ lo: Int, _ hi: Int, _ depth: Int) -> Int {
            guard lo < hi else { return Int.max }
            placeMedian(lo, hi, depth % 2 == 0 ? xs : ys)
            let mid = (lo + hi) / 2
            let smallest = min(order[mid], build(lo, mid, depth + 1), build(mid + 1, hi, depth + 1))
            smallestBelow[mid] = smallest
            return smallest
        }
        _ = build(0, pins.count, 0)

        return queries.map { query in
            let qx = query[0], qy = query[1]
            var bestDistance = Int.max
            var bestIndex = Int.max

            func search(_ lo: Int, _ hi: Int, _ depth: Int) {
                guard lo < hi else { return }
                let mid = (lo + hi) / 2
                let pin = order[mid]
                let dx = xs[pin] - qx, dy = ys[pin] - qy
                let distance = dx * dx + dy * dy
                if distance < bestDistance || (distance == bestDistance && pin < bestIndex) {
                    bestDistance = distance
                    bestIndex = pin
                }
                let gap = depth % 2 == 0 ? qx - xs[pin] : qy - ys[pin]
                let (nearLo, nearHi, farLo, farHi) = gap < 0 ? (lo, mid, mid + 1, hi) : (mid + 1, hi, lo, mid)
                search(nearLo, nearHi, depth + 1)
                guard farLo < farHi else { return }
                let gapSquared = gap * gap
                if gapSquared < bestDistance || (gapSquared == bestDistance && smallestBelow[(farLo + farHi) / 2] < bestIndex) {
                    search(farLo, farHi, depth + 1)
                }
            }
            search(0, pins.count, 0)
            return bestIndex
        }
    }
}
```

Why is the gap a safe bound when equal coordinates can land on either side? Every pin before the middle has a coordinate ≤ the median's, and every pin after it has one ≥ the median's. If the query is at or beyond the median, every pin on the far side is at least the gap away along that axis, and so at least that far away in total. The same holds the other way round.

</Approach>
