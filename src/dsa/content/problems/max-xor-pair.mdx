Return the largest value of `numbers[i] ^ numbers[j]`, the bitwise XOR of two numbers from the array. Positions i and j may be the same, which gives 0, so the answer is never negative.

`MaxXorPair.largestXor(in numbers: [Int]) -> Int`

Aim for O(31 × n): checking every pair is far too slow for 50,000 numbers.

## Examples

| `numbers` | Output |
| --- | --- |
| `[6, 13, 9, 20, 3]` | `29` |
| `[8, 1, 2, 12]` | `14` |
| `[1, 2]` | `3` |
| `[4, 4, 4]` | `0` |
| `[7]` | `0` |
| `[0, 2147483647]` | `2147483647` |

In the first example, 9 is `01001` and 20 is `10100` in binary. They differ in four of those five bits, including the highest, so their XOR is `11101`, which is 29.

## Constraints

- `1 ≤ numbers.count ≤ 100,000`
- `0 ≤ numbers[i] ≤ 2,147,483,647`, which is 2³¹ − 1, so every number fits in bits 30 down to 0.
- The tests include 50,000 numbers.

<Hints>
<Hint>
A 1 in bit k is worth 2^k, which is more than all the lower bits put together (2^k − 1). So the best partner for x is the one that differs from x in the highest bit possible, then the next highest, and so on: a greedy choice, from the top bit down.
</Hint>
<Hint>
Store every number in a binary trie: each number is a path of 31 steps from the root, choosing child 0 or child 1 for bits 30 down to 0. To find x's best partner, walk down from the root, taking the child with the opposite bit to x's whenever it exists, and the other child when it doesn't.
</Hint>
<Hint>
Each time you take the opposite bit, that bit of the XOR is 1, so add `1 << bit` to the result. Insert each number before querying it, and the walk always succeeds: at worst it finds x itself.
</Hint>
</Hints>

## Solutions

<Approach title="Every pair" time="O(n²)" space="O(1)">

Simple and correct, and the right tool for checking a faster answer on small inputs. For 50,000 numbers it makes 1.25 billion comparisons.

```swift
public enum MaxXorPair {
    public static func largestXor(in numbers: [Int]) -> Int {
        var best = 0
        for i in numbers.indices {
            for j in (i + 1)..<numbers.count {
                best = max(best, numbers[i] ^ numbers[j])
            }
        }
        return best
    }
}
```

</Approach>

<Approach title="A binary trie in a flat array" time="O(31 × n)" space="O(31 × n)">

Each number adds at most 31 nodes, and each query takes 31 steps. Storing the trie in one array keeps it fast: node k's two children live at indexes 2k and 2k + 1, and 0 means "no child", which is safe because the root, node 0, is never anyone's child.

```swift
public enum MaxXorPair {
    public static func largestXor(in numbers: [Int]) -> Int {
        var children = [0, 0]                            // the root's two child slots
        var best = 0
        for x in numbers {
            var node = 0
            for bit in stride(from: 30, through: 0, by: -1) {
                let slot = 2 * node + ((x >> bit) & 1)
                if children[slot] == 0 {
                    children[slot] = children.count / 2  // the next free node number
                    children.append(0)
                    children.append(0)
                }
                node = children[slot]
            }

            node = 0
            var value = 0
            for bit in stride(from: 30, through: 0, by: -1) {
                let opposite = 1 - ((x >> bit) & 1)
                if children[2 * node + opposite] != 0 {
                    value |= 1 << bit                    // this bit of the XOR is 1
                    node = children[2 * node + opposite]
                } else {
                    node = children[2 * node + 1 - opposite]
                }
            }
            best = max(best, value)
        }
        return best
    }
}
```

`(x >> bit) & 1` reads bit `bit` of x, as in [Checking, setting, clearing and toggling bits](/dsa/learn/bits-single-bits). A version with a `Node` class holding two optional children works the same way; the flat array avoids allocating 31 objects per number.

</Approach>

<Approach title="Prefixes in a set, one bit at a time" time="O(31 × n)" space="O(n)">

Decide the answer's bits from the top. Suppose the bits above bit k are settled. Try setting bit k too, and ask whether two numbers can produce that much. Keep only each number's bits from 30 down to k (its prefix) in a set. Two prefixes a and b with a ^ b equal to the candidate exist exactly when some a has a ^ candidate in the set, because XOR undoes itself.

```swift
public enum MaxXorPair {
    public static func largestXor(in numbers: [Int]) -> Int {
        var answer = 0
        var mask = 0
        for bit in stride(from: 30, through: 0, by: -1) {
            mask |= 1 << bit
            let prefixes = Set(numbers.map { $0 & mask })
            let candidate = answer | (1 << bit)
            if prefixes.contains(where: { prefixes.contains($0 ^ candidate) }) {
                answer = candidate
            }
        }
        return answer
    }
}
```

It uses the same greedy idea as the trie, but asks the question about all numbers at once for each bit, instead of for each number across all bits.

</Approach>
