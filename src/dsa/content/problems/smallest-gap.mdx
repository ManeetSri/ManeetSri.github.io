Return the smallest gap between two values at different positions in the array. The gap between `a` and `b` is the absolute difference `abs(a - b)`, so it's never negative.

`SmallestGap.smallestGap(in numbers: [Int]) -> Int`

Start with the brute force, then check the constraints: is it fast enough?

## Examples

| Input | Output |
| --- | --- |
| `[9, 2, 14, 5]` | `3` |
| `[40, 10, 24, 22]` | `2` |
| `[4, 7, 4]` | `0` |
| `[-7, 3]` | `10` |

In the first example, 2 and 5 are closest. In the third, the two 4s have a gap of 0.

## Constraints

- `2 ≤ numbers.count ≤ 2,000`
- `-10⁹ ≤ numbers[i] ≤ 10⁹`

<Hints>
<Hint>
The brute force checks every pair of positions `i < j`. How many pairs are there for 2,000 numbers, and how does that compare with a budget of about 10⁸ steps?
</Hint>
<Hint>
Keep the smallest gap seen so far. Start it at `Int.max`, so the first real gap replaces it. `abs(numbers[i] - numbers[j])` can't overflow here, since the largest possible gap is 2 × 10⁹.
</Hint>
<Hint>
For a faster version: after sorting, the closest pair must sit next to each other. (If a value sat between them, it would be closer to both.) So only neighbours need comparing.
</Hint>
</Hints>

## Solutions

<Approach title="Brute force: every pair" time="O(n²)" space="O(1)">

Compare each value with every value after it. For n = 2,000 that's about 2 million pairs, comfortably fast, so this is a complete answer for these constraints.

```swift
public enum SmallestGap {
    public static func smallestGap(in numbers: [Int]) -> Int {
        var smallest = Int.max
        for i in 0..<numbers.count {
            for j in (i + 1)..<numbers.count {
                smallest = min(smallest, abs(numbers[i] - numbers[j]))
            }
        }
        return smallest
    }
}
```

On the last pass of the outer loop, `i + 1` equals `numbers.count`, so the inner range is empty, which is fine.

</Approach>

<Approach title="Sort, then compare neighbours" time="O(n log n)" space="O(n)">

Sorting puts close values next to each other. If `a ≤ b ≤ c`, the gap from `a` to `c` is at least the gap from `a` to `b`, so the smallest gap is always between neighbours.

```swift
public static func smallestGap(in numbers: [Int]) -> Int {
    let sorted = numbers.sorted()
    var smallest = Int.max
    for i in 1..<sorted.count {
        smallest = min(smallest, sorted[i] - sorted[i - 1])
    }
    return smallest
}
```

Neighbours in sorted order never give a negative difference, so `abs` isn't needed. This version would still be fast for a million numbers. A good habit is to keep the brute force and check that both agree on many small arrays.

</Approach>
