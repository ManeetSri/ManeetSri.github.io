An office has a day of meetings, each with a start and an end time. Every meeting needs a room to itself for as long as it runs. Return the fewest rooms that can hold all of them.

`RoomsNeeded.minimumRooms(_ meetings: [[Int]]) -> Int`

Meetings are half-open pairs `[start, end)`: when one meeting ends at 11 and another starts at 11, the second can use the first one's room.

## Examples

| `meetings` | Output |
| --- | --- |
| `[[9, 12], [10, 11], [11, 13], [12, 14]]` | `2` |
| `[[0, 5], [1, 6], [2, 7]]` | `3` |
| `[[1, 3], [3, 5], [5, 7]]` | `1` |
| `[[4, 9]]` | `1` |
| `[]` | `0` |

In the first example, `[10, 11]` ends just as `[11, 13]` starts, and `[9, 12]` ends just as `[12, 14]` starts, so at most two meetings run at the same moment.

## Constraints

- `0 ≤ meetings.count ≤ 100,000`
- Each meeting has `start < end`, with values between −10⁹ and 10⁹.
- Aim for O(n log n) time.

<Hints>
<Hint>
The fewest rooms is the largest number of meetings running at the same moment. At that moment each needs its own room; and handing every starting meeting any free room never needs more.
</Hint>
<Hint>
To count meetings in progress, you don't need to know which meeting is which, only when meetings start and when they end. Try sorting the start times and the end times as two separate arrays.
</Hint>
<Hint>
Walk the sorted starts. Before counting each start, release every meeting whose end is at or before it: `<=`, because meetings are half-open. Track the most rooms ever in use. (Or make a +1 event at each start and a −1 event at each end, sort the `(time, change)` tuples, and keep a running total.)
</Hint>
</Hints>

## Solutions

<Approach title="Sorted starts and ends, two pointers" time="O(n log n)" space="O(n)">

`e` points at the next end time not yet released. Each pointer only moves forwards, so after the two sorts the walk is O(n).

```swift
public enum RoomsNeeded {
    public static func minimumRooms(_ meetings: [[Int]]) -> Int {
        let starts = meetings.map { $0[0] }.sorted()
        let ends = meetings.map { $0[1] }.sorted()
        var inUse = 0
        var most = 0
        var e = 0
        for start in starts {
            while e < ends.count && ends[e] <= start {   // ended by now: its room is free
                inUse -= 1
                e += 1
            }
            inUse += 1
            most = max(most, inUse)
        }
        return most
    }
}
```

With `ends[e] < start`, a meeting ending at 11 wouldn't free its room for one starting at 11, and the third example would need 2 rooms.

</Approach>

<Approach title="A sweep of +1 and −1 events" time="O(n log n)" space="O(n)">

Each meeting adds one room at its start and frees one at its end. Swift compares tuples element by element, so at the same time `(11, -1)` sorts before `(11, 1)`: ends come first, exactly as half-open meetings need.

```swift
public static func minimumRooms(_ meetings: [[Int]]) -> Int {
    var events: [(time: Int, change: Int)] = []
    for meeting in meetings {
        events.append((meeting[0], 1))
        events.append((meeting[1], -1))
    }
    events.sort { ($0.time, $0.change) < ($1.time, $1.change) }
    var inUse = 0
    var most = 0
    for event in events {
        inUse += event.change
        most = max(most, inUse)
    }
    return most
}
```

A third approach sorts the meetings by start and keeps the end times of the rooms in use in a min-heap, reusing the room that frees up first. It's also O(n log n), and it says which room each meeting gets. Heaps arrive in M39.

</Approach>
