A hiking park has junctions `0` to `n - 1` and one-way trails between them, each given as `[from, to]`. The trails never lead back to a junction you've already left, so the map is a DAG. Count the different routes from `start` to `finish`, and return the count modulo 1,000,000,007. Two trails joining the same pair of junctions are different trails, so they make different routes. If `start` and `finish` are the same junction, the route that uses no trails counts as one.

`TrailRouteCount.countRoutes(n: Int, trails: [[Int]], start: Int, finish: Int) -> Int`

## Examples

| `n` | `trails` | `start` | `finish` | Output |
| --- | --- | --- | --- | --- |
| `5` | `[[0, 1], [0, 2], [1, 3], [2, 3], [3, 4], [1, 4]]` | `0` | `4` | `3` |
| `3` | `[[0, 1], [0, 1], [1, 2]]` | `0` | `2` | `2` |
| `3` | `[[1, 0], [2, 1]]` | `0` | `2` | `0` |
| `4` | `[[0, 1], [2, 3]]` | `2` | `2` | `1` |

In the first example the routes are 0 → 1 → 4, 0 → 1 → 3 → 4 and 0 → 2 → 3 → 4. In the second, either of the two trails from 0 to 1 can be used. In the third, the trails all point the wrong way.

## Constraints

- `1 ≤ n ≤ 100,000` and `0 ≤ trails.count ≤ 200,000`
- `0 ≤ from, to < n`, `from ≠ to`, and the trails contain no cycle.
- One test is a chain of 100,000 junctions with two trails at every step, so the true count is 2⁹⁹⁹⁹⁹: reduce as you go. A recursive search would also go 100,000 calls deep there and crash inside the test runner.

<Hints>
<Hint>
Every route into a junction v arrives along exactly one last trail u → v. So the routes to v are the routes to each u, added up over v's incoming trails.
</Hint>
<Hint>
For that sum to be ready, every u must be finished before v. That's a topological order, and Kahn's algorithm gives one with a loop instead of recursion.
</Hint>
<Hint>
Set `ways[start] = 1`. Go through the junctions in Kahn's order, and for each trail u → v out of the junction u you've just taken from the queue, do `ways[v] = (ways[v] + ways[u]) % 1_000_000_007`. Junctions before `start` in the order have 0 ways, which is right.
</Hint>
</Hints>

## Solutions

<Approach title="Walk every route" time="exponential" space="O(n)">

A DFS from `start` that counts each arrival at `finish`. The tests use it on maps of up to 9 junctions. The number of routes can double at every step, so it can't handle the big tests.

</Approach>

<Approach title="Count along a topological order" time="O(n + m)" space="O(n + m)">

Kahn's algorithm, with the DP folded into it: when a junction leaves the queue, everything that leads into it has already been counted, so its count is final and it can be pushed along its outgoing trails.

```swift
public enum TrailRouteCount {
    public static func countRoutes(n: Int, trails: [[Int]], start: Int, finish: Int) -> Int {
        let mod = 1_000_000_007
        var outgoing = [[Int]](repeating: [], count: n)
        var inDegree = [Int](repeating: 0, count: n)
        for trail in trails {
            outgoing[trail[0]].append(trail[1])
            inDegree[trail[1]] += 1
        }
        var order = (0..<n).filter { inDegree[$0] == 0 }
        var ways = [Int](repeating: 0, count: n)
        ways[start] = 1
        var head = 0
        while head < order.count {
            let u = order[head]
            head += 1
            for v in outgoing[u] {
                ways[v] = (ways[v] + ways[u]) % mod     // ways[u] is final: everything into u came earlier
                inDegree[v] -= 1
                if inDegree[v] == 0 { order.append(v) }
            }
        }
        return ways[finish]
    }
}
```

Two reduced counts add up to less than 2.1 × 10⁹, far below `Int.max`, so reducing after each addition is enough. A memoised DFS from `start` gives the same answers, but it recurses once per junction along the longest route.

</Approach>
