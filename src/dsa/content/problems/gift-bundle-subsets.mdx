A gift shop sells items whose prices are listed in `prices`, and some prices appear more than once. A **bundle** is any selection of the items, from none at all to all of them. Two bundles count as the same if they contain the same prices the same number of times. Return every different bundle, each as the list of its prices.

`GiftBundleSubsets.bundles(_ prices: [Int]) -> [[Int]]`

The bundles may come in any order, and so may the prices inside each bundle: the tests sort both before comparing.

## Examples

| `prices` | Output |
| --- | --- |
| `[5, 8, 5]` | `[[], [5], [5, 5], [5, 5, 8], [5, 8], [8]]` |
| `[4, 4, 4]` | `[[], [4], [4, 4], [4, 4, 4]]` |
| `[9]` | `[[], [9]]` |
| `[]` | `[[]]` |

In the first example there are 2³ = 8 ways to pick items, but picking the first 5 or the second 5 gives the same bundle, so only 6 are different.

## Constraints

- `0 ≤ prices.count ≤ 24` and `1 ≤ prices[i] ≤ 1,000`.
- The answer has at most 70,000 bundles.
- The tests include 24 prices made of twelve 7s and twelve 3s: only 13 × 13 = 169 different bundles, out of 2²⁴ ≈ 16.8 million ways to pick items. Generating every pick and removing repeats afterwards is far too slow.

<Hints>
<Hint>
Without repeats this is plain subsets. Use the "choose the next item" tree: every node is a bundle, and its children each add one item from further right.
</Hint>
<Hint>
Sort the prices so that equal ones sit next to each other. A repeated bundle appears when two children of the same node add the same price.
</Hint>
<Hint>
In the loop over the next item, skip index `i` when `i > start` and `prices[i] == prices[i - 1]`. The first copy at each level is always allowed, so bundles like `[5, 5]` are still built.
</Hint>
</Hints>

## Solutions

<Approach title="Every pick, then remove repeats" time="O(n · 2ⁿ)" space="O(n · 2ⁿ)">

Loop over all 2ⁿ bitmasks, build each subset, sort it, and insert it into a `Set<[Int]>`. It's correct, and fine for small inputs, but it always does 2ⁿ units of work: over 16 million subsets for the 24-price test, for 169 answers.

</Approach>

<Approach title="Backtracking, skipping equal siblings" time="O(n · 2ⁿ) worst case, O(n) per bundle" space="O(n) besides the output">

Sort, then explore the "choose the next item" tree. Every node is recorded as a bundle. At each level only the first of a run of equal prices is tried, because a later copy would grow exactly the same subtree. The search builds each different bundle once, so its work is proportional to the size of the answer.

```swift
public enum GiftBundleSubsets {
    public static func bundles(_ prices: [Int]) -> [[Int]] {
        let sorted = prices.sorted()
        var result: [[Int]] = []
        var bundle: [Int] = []

        func explore(from start: Int) {
            result.append(bundle)                                   // every node is a bundle
            for i in start..<sorted.count {
                if i > start && sorted[i] == sorted[i - 1] { continue }   // equal sibling: same subtree
                bundle.append(sorted[i])                            // choose
                explore(from: i + 1)                                // explore
                bundle.removeLast()                                 // unchoose
            }
        }

        explore(from: 0)
        return result
    }
}
```

The number of different bundles is the product of (count + 1) over the distinct prices, which is a handy check: `[5, 8, 5]` gives 3 × 2 = 6.

</Approach>
