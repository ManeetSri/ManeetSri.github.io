A small studio starts with `start` in the bank and can take on at most `k` contracts, one after another. Contract `i` can only start when the studio has at least `requirements[i]` in the bank, a credit check that doesn't spend anything, and it adds `profits[i]` when it's finished. Each contract can be taken once. Return the most money the studio can end up with.

`CapitalProjects.bestFinalCapital(start: Int, maxContracts k: Int, requirements: [Int], profits: [Int]) -> Int`

## Examples

| `start` | `k` | `requirements` | `profits` | Returns |
| --- | --- | --- | --- | --- |
| `0` | `2` | `[0, 1, 1]` | `[1, 2, 3]` | `4` |
| `0` | `3` | `[0, 1, 2]` | `[1, 2, 3]` | `6` |
| `2` | `2` | `[0, 0, 3]` | `[1, 1, 50]` | `53` |
| `5` | `1` | `[10, 20]` | `[100, 100]` | `5` |
| `10` | `2` | `[0, 5, 10, 12]` | `[0, 0, 1, 7]` | `11` |

In the first row, only contract 0 is affordable at first. It brings the bank to 1, which unlocks contracts 1 and 2; contract 2 pays more, for 4. In the fourth, nothing is affordable, so the studio keeps its 5.

## Constraints

- `0 ≤ requirements.count == profits.count ≤ 100,000`, `0 ≤ k ≤ 100,000`
- `0 ≤ start, requirements[i] ≤ 1,000,000,000`, `0 ≤ profits[i] ≤ 10,000`
- Scanning every contract to pick each of k contracts is O(n · k), ten billion steps at the largest size.

<Hints>
<Hint>
Money never goes down. So a contract that's affordable now stays affordable. Among the contracts you can afford right now, which one should you take?
</Hint>
<Hint>
The most profitable one. It leaves you with the most money, which can only unlock more contracts, and every other affordable contract is still available afterwards. So the greedy choice never hurts.
</Hint>
<Hint>
Sort the contracts by requirement. Keep a pointer into that order and a max-heap of profits. Before each pick, move every contract whose requirement you now meet into the heap. Pop the best profit. If the heap is empty, stop early: nothing will ever become affordable.
</Hint>
</Hints>

## Solutions

<Approach title="Scan for the best affordable contract each time" time="O(n · k)" space="O(n)">

Each round, look at every unused contract and take the most profitable one you can afford. Correct, because it makes the same greedy choice, but each of the k rounds scans all n contracts.

</Approach>

<Approach title="Sort by requirement, then a max-heap of profits" time="O(n log n)" space="O(n)">

Every contract enters the heap at most once and leaves it at most once.

```swift
import DSAKit

public enum CapitalProjects {
    public static func bestFinalCapital(start: Int, maxContracts k: Int, requirements: [Int], profits: [Int]) -> Int {
        let byRequirement = requirements.indices.sorted { requirements[$0] < requirements[$1] }
        var affordable = Heap<Int>.maxHeap()         // profits of contracts we can take now
        var capital = start
        var nextContract = 0
        for _ in 0..<k {
            while nextContract < byRequirement.count && requirements[byRequirement[nextContract]] <= capital {
                affordable.insert(profits[byRequirement[nextContract]])
                nextContract += 1
            }
            guard let profit = affordable.pop() else { break }
            capital += profit
        }
        return capital
    }
}
```

Sorting the indexes, rather than pairs, keeps each contract's requirement and profit together without building a new array of tuples.

</Approach>
