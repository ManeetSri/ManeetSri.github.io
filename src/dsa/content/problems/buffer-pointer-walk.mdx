Get comfortable reading pointer code by writing three small functions with it: one that reads through a buffer pointer, one that writes through a mutable one, and one that steps a plain pointer along with arithmetic.

`BufferPointerWalk.sum(_:)`, `BufferPointerWalk.reverseInPlace(_:)` and `BufferPointerWalk.sample(_:every:)`

- **`sum(_:)`** returns the sum of the numbers, reading them inside `withUnsafeBufferPointer`.
- **`reverseInPlace(_:)`** reverses the caller's array, swapping elements inside `withUnsafeMutableBufferPointer`.
- **`sample(_:every:)`** returns the elements at indices 0, `step`, 2 × `step` and so on, reading each one through the buffer's `baseAddress` with pointer arithmetic, `(base + offset).pointee`.

No pointer may leave its closure: each function returns plain values.

## Examples

| Call | Result |
| --- | --- |
| `sum([3, 1, 4, 1, 5])` | `14` |
| `sum([])` | `0` |
| `var a = [1, 2, 3, 4]`, then `reverseInPlace(&a)` | `a` is `[4, 3, 2, 1]` |
| `sample([10, 11, 12, 13, 14, 15, 16], every: 3)` | `[10, 13, 16]` |
| `sample([10, 11, 12], every: 5)` | `[10]` |
| `sample([], every: 2)` | `[]` |

## Constraints

- Up to 100,000 numbers. Sums fit in an `Int`.
- `step` is at least 1.
- The tests check results, not how you got them, but the point is to practise the pointer APIs.

<Hints>
<Hint>
Whatever the closure returns becomes the result of `withUnsafeBufferPointer`, so `sum` can be `numbers.withUnsafeBufferPointer { buffer in ... }` with a loop inside that returns the total. A buffer pointer is a collection, so `for value in buffer` works.
</Hint>
<Hint>
For the reverse, start `left` at 0 and `right` at `buffer.count - 1`, and while `left < right` call `buffer.swapAt(left, right)` and move both towards the middle. The array must be passed as `inout` for the mutable buffer to write into it.
</Hint>
<Hint>
`buffer.baseAddress` is optional because an empty array may have no memory at all, so `guard let base = buffer.baseAddress else { return [] }`. Then step `offset` by `step` while it's below `buffer.count`, reading `(base + offset).pointee`.
</Hint>
</Hints>

## Solutions

<Approach title="Borrow the memory inside each closure" time="O(n)" space="O(1) extra, plus the sampled result">

Each function does its work inside the closure and returns ordinary values, so the pointer never outlives the memory it points at. `base + offset` moves forward `offset` *elements*, not bytes: Swift multiplies by `Int`'s stride for you.

```swift
public enum BufferPointerWalk {
    public static func sum(_ numbers: [Int]) -> Int {
        numbers.withUnsafeBufferPointer { buffer in
            var total = 0
            for value in buffer {
                total += value
            }
            return total
        }
    }

    public static func reverseInPlace(_ numbers: inout [Int]) {
        numbers.withUnsafeMutableBufferPointer { buffer in
            var left = 0
            var right = buffer.count - 1
            while left < right {
                buffer.swapAt(left, right)
                left += 1
                right -= 1
            }
        }
    }

    public static func sample(_ numbers: [Int], every step: Int) -> [Int] {
        numbers.withUnsafeBufferPointer { buffer in
            guard let base = buffer.baseAddress else {
                return []
            }
            var picked: [Int] = []
            var offset = 0
            while offset < buffer.count {
                picked.append((base + offset).pointee)
                offset += step
            }
            return picked
        }
    }
}
```

In safe Swift these would be `numbers.reduce(0, +)`, `numbers.reverse()` and a `stride(from:to:by:)` loop, and in everyday code you should write those. The pointer versions can skip bounds checks in an optimised build, which only matters in a hot loop you've measured.

</Approach>
