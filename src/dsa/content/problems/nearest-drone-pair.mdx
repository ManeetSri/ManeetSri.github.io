A light show holds its drones still at fixed spots on a flat grid, and the safety check needs to know how close the two nearest drones are. Each drone's position is `[x, y]`. Return the **squared** distance between the two drones that are closest together. Two drones can share a spot, which gives 0.

`NearestDronePair.smallestSquaredDistance(_ drones: [[Int]]) -> Int`

## Examples

| `drones` | Output |
| --- | --- |
| `[[0, 0], [7, 2], [3, 4], [10, 10]]` | `20` |
| `[[2, -3], [2, -3], [9, 9]]` | `0` |
| `[[-5, 0], [0, 0], [5, 0], [10, 0]]` | `25` |
| `[[-1000000000, -1000000000], [1000000000, 1000000000]]` | `8000000000000000000` |

In the first example, (7, 2) and (3, 4) are 4 apart across and 2 apart up, so their squared distance is 16 + 4 = 20. The next closest pair, (0, 0) and (3, 4), gives 25. In the last example the drones sit in opposite corners of the allowed area.

## Constraints

- `2 ≤ drones.count ≤ 100,000`, and each drone is `[x, y]`.
- `-10⁹ ≤ x, y ≤ 10⁹`
- Squared distances reach 8 × 10¹⁸. That still fits in an `Int`, but not exactly in a `Double`, so stay with whole numbers.
- The tests use up to 30,000 drones, including drones all in one line, so checking every pair (O(n²)) is too slow.

<Hints>
<Hint>
Sort by x and split into a left half and a right half. Solve each half recursively, and let `best` be the smaller answer. Only a pair with one drone on each side can still beat it.
</Hint>
<Hint>
Such a pair has both drones close to the dividing line: `dx * dx < best`. Put those drones in y order, and compare each with the drones after it only while `dy * dy < best`. Each drone needs at most a handful of comparisons.
</Hint>
<Hint>
Sorting the strip at every level costs an extra log factor. Instead, make each call leave its range sorted by y, merging the two halves as merge sort does. Remember the dividing line's x **before** the recursive calls reorder the range.
</Hint>
</Hints>

## Solutions

<Approach title="Check every pair" time="O(n²)" space="O(1)">

Compute the squared distance for every pair and keep the smallest. It's the checker you should test against on small inputs, but 30,000 drones means 450 million pairs.

</Approach>

<Approach title="Divide and conquer, sorting each strip" time="O(n log² n)" space="O(n)">

Split by x, solve both halves, then collect the strip, sort it by y, and scan it. Each level sorts strips that add up to n drones, so T(n) = 2T(n/2) + n log n, which is O(n log² n). That's already fast enough for these tests, and it's a good stepping stone to the version below.

</Approach>

<Approach title="Divide and conquer, merging by y" time="O(n log n)" space="O(n)">

Each call returns its range sorted by y, so the strip comes out in y order without sorting. Converting `[[Int]]` into an array of small structs first keeps the inner loops fast.

```swift
public enum NearestDronePair {
    private struct Point {
        let x: Int
        let y: Int
    }

    public static func smallestSquaredDistance(_ drones: [[Int]]) -> Int {
        var points = drones.map { Point(x: $0[0], y: $0[1]) }
        points.sort { $0.x != $1.x ? $0.x < $1.x : $0.y < $1.y }
        var buffer = points
        var strip: [Point] = []
        strip.reserveCapacity(points.count)
        return closest(&points, &buffer, &strip, 0, points.count)
    }

    private static func squaredDistance(_ a: Point, _ b: Point) -> Int {
        let dx = a.x - b.x
        let dy = a.y - b.y
        return dx * dx + dy * dy
    }

    /// The smallest squared distance in points[low..<high], which arrive sorted by x and leave sorted by y.
    private static func closest(_ points: inout [Point], _ buffer: inout [Point], _ strip: inout [Point],
                                _ low: Int, _ high: Int) -> Int {
        if high - low <= 3 {
            var best = Int.max
            for i in low..<high {
                for j in (i + 1)..<high {
                    best = min(best, squaredDistance(points[i], points[j]))
                }
            }
            points[low..<high].sort { $0.y < $1.y }
            return best
        }
        let mid = low + (high - low) / 2
        let lineX = points[mid].x                         // before the calls re-sort the range by y
        var best = min(closest(&points, &buffer, &strip, low, mid), closest(&points, &buffer, &strip, mid, high))

        for index in low..<high {
            buffer[index] = points[index]
        }
        var left = low
        var right = mid
        for write in low..<high {
            if right == high || (left < mid && buffer[left].y <= buffer[right].y) {
                points[write] = buffer[left]
                left += 1
            } else {
                points[write] = buffer[right]
                right += 1
            }
        }

        strip.removeAll(keepingCapacity: true)
        for index in low..<high {
            let dx = points[index].x - lineX
            if dx * dx < best {
                strip.append(points[index])
            }
        }
        for i in strip.indices {
            var j = i + 1
            while j < strip.count {
                let dy = strip[j].y - strip[i].y
                if dy * dy >= best { break }
                best = min(best, squaredDistance(strip[i], strip[j]))
                j += 1
            }
        }
        return best
    }
}
```

One `strip` array is shared by every call. That's safe because a call only uses it after both of its recursive calls have finished with it.

</Approach>
