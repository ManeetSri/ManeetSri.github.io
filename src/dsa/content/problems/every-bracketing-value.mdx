A calculator expression is made of whole numbers joined by `+`, `-` and `*`, with no brackets. Bracket it fully in every possible way, so that each operator joins exactly two things, and return the value of each bracketing, sorted from smallest to largest. Different bracketings that happen to give the same value each get their own entry.

`BracketingOutcomes.allValues(_ expression: String) -> [Int]`

## Examples

| `expression` | Output |
| --- | --- |
| `"5-1-2"` | `[2, 6]` |
| `"3*4+2"` | `[14, 18]` |
| `"6-2*3+1"` | `[-2, -1, 1, 13, 16]` |
| `"2+2+2"` | `[6, 6]` |
| `"7"` | `[7]` |

`"5-1-2"` can be bracketed as (5 − 1) − 2 = 2 or 5 − (1 − 2) = 6. `"6-2*3+1"` has five bracketings, such as (6 − 2) × (3 + 1) = 16 and 6 − ((2 × 3) + 1) = −1. Both bracketings of `"2+2+2"` give 6, so 6 appears twice.

## Constraints

- The expression has 1 to 11 numbers, each from 0 to 30, written without leading zeros.
- Operators are `+`, `-` and `*`, with no spaces. Ordinary precedence doesn't apply: only the brackets decide the order.
- With 10 operators there are 16,796 bracketings, and every value fits easily in an `Int`.

<Hints>
<Hint>
In any full bracketing, exactly one operator is applied **last**. Everything to its left is bracketed somehow, and so is everything to its right.
</Hint>
<Hint>
So try each operator as the last one: get every value of the left part and every value of the right part recursively, and combine every left value with every right value. A single number has just one value.
</Hint>
<Hint>
Parse the string into an array of numbers and an array of operators first, then recurse on ranges of numbers `first...last`. The same range turns up under many different splits, so you can remember each range's list.
</Hint>
</Hints>

## Solutions

<Approach title="Divide on the last operator" time="O(Cₖ log Cₖ)" space="O(Cₖ)">

Here k is the number of operators and Cₖ is the kth Catalan number (1, 1, 2, 5, 14, 42, …), the number of bracketings. The output alone has Cₖ values, and sorting them dominates.

Each call splits at every operator in turn, solves the two sides independently and combines all pairs. That's divide and conquer with more than one way to divide.

```swift
public enum BracketingOutcomes {
    public static func allValues(_ expression: String) -> [Int] {
        var numbers: [Int] = []
        var operators: [Character] = []
        var current = 0
        for character in expression {
            if let digit = character.wholeNumberValue {
                current = current * 10 + digit
            } else {
                numbers.append(current)
                operators.append(character)
                current = 0
            }
        }
        numbers.append(current)

        func values(_ first: Int, _ last: Int) -> [Int] {
            if first == last {
                return [numbers[first]]
            }
            var result: [Int] = []
            for split in first..<last {                 // operators[split] is applied last
                let left = values(first, split)
                let right = values(split + 1, last)
                for a in left {
                    for b in right {
                        switch operators[split] {
                        case "+": result.append(a + b)
                        case "-": result.append(a - b)
                        default: result.append(a * b)
                        }
                    }
                }
            }
            return result
        }

        return values(0, numbers.count - 1).sorted()
    }
}
```

Call each side once per split and keep its list in a constant, as here. Calling `values(split + 1, last)` inside the loop over `a` would rebuild the right side once for every left value.

</Approach>

<Approach title="Remember each range" time="O(Cₖ log Cₖ)" space="O(Cₖ)">

The range of numbers 2...4 is needed when splitting 0...4 at operator 1, and again when splitting 1...4 at operator 1, and so on. Storing each range's list in a table indexed by `first` and `last` builds every list once.

```swift
public enum BracketingOutcomes {
    public static func allValues(_ expression: String) -> [Int] {
        var numbers: [Int] = []
        var operators: [Character] = []
        var current = 0
        for character in expression {
            if let digit = character.wholeNumberValue {
                current = current * 10 + digit
            } else {
                numbers.append(current)
                operators.append(character)
                current = 0
            }
        }
        numbers.append(current)

        var memo: [[[Int]?]] = Array(repeating: Array(repeating: nil, count: numbers.count), count: numbers.count)

        func values(_ first: Int, _ last: Int) -> [Int] {
            if let known = memo[first][last] {
                return known
            }
            if first == last {
                return [numbers[first]]
            }
            var result: [Int] = []
            for split in first..<last {
                let left = values(first, split)
                let right = values(split + 1, last)
                for a in left {
                    for b in right {
                        switch operators[split] {
                        case "+": result.append(a + b)
                        case "-": result.append(a - b)
                        default: result.append(a * b)
                        }
                    }
                }
            }
            memo[first][last] = result
            return result
        }

        return values(0, numbers.count - 1).sorted()
    }
}
```

Here it only saves a constant factor, because the final list of Cₖ values dominates either way. But overlapping subproblems are the signal for dynamic programming. If the question asked only for the **largest** value, each range would need just its largest and smallest values (a subtraction or a product of negatives can turn a smallest into a largest), and remembering those per range gives an O(k³) algorithm, where the plain recursion stays exponential.

</Approach>
