Rangers walk a trail with `n` survey points, numbered from 0, and record the id of the bird species seen at each one. Biologists then ask about many segments of the trail: for each segment `[left, right]` (both ends included), how many **different** species were seen there? Return the answers in the order the segments are given.

`TrailSpeciesCounter.distinctSpecies(sightings: [Int], segments: [[Int]]) -> [Int]`

## Examples

| `sightings` | `segments` | Output |
| --- | --- | --- |
| `[3, 1, 3, 2, 1, 3, 4, 2]` | `[[0, 4], [5, 7], [1, 3], [2, 6], [0, 7]]` | `[3, 3, 3, 4, 4]` |
| `[900000000, 5, 900000000, 5]` | `[[0, 3], [1, 2], [3, 3]]` | `[2, 2, 1]` |
| `[7, 7, 7, 7]` | `[[0, 3], [2, 2]]` | `[1, 1]` |
| `[1, 2, 3]` | `[]` | `[]` |

In the first example, points 2 to 6 saw species 3, 2, 1, 3 and 4: four different ones. The second shows that species ids can be huge.

## Constraints

- `1 ≤ sightings.count ≤ 50,000` and `0 ≤ segments.count ≤ 50,000`
- `0 ≤ sightings[i] ≤ 1,000,000,000`
- Every segment has `0 ≤ left ≤ right < sightings.count`.
- The tests use 30,000 points and 30,000 segments, many of them long. Building a `Set` for each segment is about a billion insertions: too slow.

<Hints>
<Hint>
You know every segment before you answer any of them, so you may answer them in any order you like, as long as each answer goes back to its segment's position.
</Hint>
<Hint>
Keep a window with a count for each species and the number of species with a count above zero. Moving either end by one point updates both in O(1). Mo's algorithm orders the segments so the window's total travel is O((n + q)√n). The counts need an array indexed by species: compress the ids to 0 to k − 1 first.
</Hint>
<Hint>
Sort segment numbers by (left / blockSize, right), with blockSize ≈ √n. Grow the window's ends before shrinking them, and write each answer to `answers[segmentNumber]`.
</Hint>
</Hints>

## Solutions

<Approach title="A set per segment" time="O(n · q)" space="O(n)">

For each segment, insert its species into a `Set` and return the set's count. Correct, and fine for a handful of segments; with 30,000 long ones it's hundreds of millions of hash insertions.

</Approach>

<Approach title="Mo's algorithm with compressed ids" time="O((n + q)√n + q log q)" space="O(n + q)">

Compress the ids so they can index a count array, sort the segment numbers into Mo's order, and slide one window through them.

```swift
public enum TrailSpeciesCounter {
    public static func distinctSpecies(sightings: [Int], segments: [[Int]]) -> [Int] {
        // Compress species ids to 0..<k
        let distinctIds = Array(Set(sightings)).sorted()
        var rankOf: [Int: Int] = [:]
        for (rank, id) in distinctIds.enumerated() { rankOf[id] = rank }
        let species = sightings.map { rankOf[$0]! }

        var blockSize = 1
        while blockSize * blockSize < species.count { blockSize += 1 }
        let order = segments.indices.sorted { a, b in
            let blockA = segments[a][0] / blockSize, blockB = segments[b][0] / blockSize
            return blockA != blockB ? blockA < blockB : segments[a][1] < segments[b][1]
        }

        var count = [Int](repeating: 0, count: distinctIds.count)
        var distinct = 0
        var answers = [Int](repeating: 0, count: segments.count)
        var currentLeft = 0
        var currentRight = -1
        for q in order {
            let left = segments[q][0], right = segments[q][1]
            while currentLeft > left {
                currentLeft -= 1
                count[species[currentLeft]] += 1
                if count[species[currentLeft]] == 1 { distinct += 1 }
            }
            while currentRight < right {
                currentRight += 1
                count[species[currentRight]] += 1
                if count[species[currentRight]] == 1 { distinct += 1 }
            }
            while currentLeft < left {
                count[species[currentLeft]] -= 1
                if count[species[currentLeft]] == 0 { distinct -= 1 }
                currentLeft += 1
            }
            while currentRight > right {
                count[species[currentRight]] -= 1
                if count[species[currentRight]] == 0 { distinct -= 1 }
                currentRight -= 1
            }
            answers[q] = distinct
        }
        return answers
    }
}
```

</Approach>

<Approach title="Offline sweep with a Fenwick tree" time="O((n + q) log n)" space="O(n + q)">

Sort the segments by right end and sweep the points from left to right. Keep a Fenwick tree with a 1 at only the **latest** point seen so far for each species: when a species reappears, move its 1 from its previous point to the current one. When the sweep reaches a segment's right end, every species seen in the segment has exactly one 1 inside `left...right` (at its latest sighting), and species not seen there have none. So the answer is the number of 1s in `left...right`.

```swift
public enum TrailSpeciesCounter {
    public static func distinctSpecies(sightings: [Int], segments: [[Int]]) -> [Int] {
        let n = sightings.count
        var tree = [Int](repeating: 0, count: n + 1)
        func add(_ index: Int, _ delta: Int) {
            var i = index + 1
            while i <= n { tree[i] += delta; i += i & -i }
        }
        func prefix(_ count: Int) -> Int {
            var i = count, total = 0
            while i > 0 { total += tree[i]; i -= i & -i }
            return total
        }

        let order = segments.indices.sorted { segments[$0][1] < segments[$1][1] }
        var latest: [Int: Int] = [:]                 // species -> the latest point it was seen at
        var answers = [Int](repeating: 0, count: segments.count)
        var point = -1
        for q in order {
            let left = segments[q][0], right = segments[q][1]
            while point < right {
                point += 1
                if let previous = latest[sightings[point]] { add(previous, -1) }
                add(point, 1)
                latest[sightings[point]] = point
            }
            answers[q] = prefix(right + 1) - prefix(left)
        }
        return answers
    }
}
```

This one doesn't even need compression, because the dictionary is only touched once per point. It's the faster method; Mo's algorithm is the more general one, since it works for any answer that can be updated as points enter and leave.

</Approach>
