You may insert characters anywhere in a string. What's the fewest insertions that turn it into a palindrome, a string that reads the same backwards? Return that number, and the length of the string's longest palindromic subsequence, which is the key to it.

`PalindromeByInsertions.longestPalindromicSubsequence(_ text: String) -> Int`

`PalindromeByInsertions.fewestInsertions(_ text: String) -> Int`

## Examples

| `text` | Longest palindromic subsequence | Fewest insertions |
| --- | --- | --- |
| `"race"` | `1` | `3` (`"racecar"`) |
| `"abca"` | `3` (`"aba"` or `"aca"`) | `1` (`"abcba"`) |
| `"banana"` | `5` (`"anana"`) | `1` (`"bananab"`) |
| `"character"` | `5` (`"carac"`) | `4` |
| `"noon"` | `4` | `0` |
| `""` | `0` | `0` |

## Constraints

- `text` has 0 to 2,000 characters. Compare `Character`s.
- The tests include random strings of 2,000 characters.

<Hints>
<Hint>
Keep the letters of a longest palindromic subsequence where they are. Every other letter needs a partner inserted in the mirror position. So the insertions are the length minus the LPS.
</Hint>
<Hint>
For the LPS, let `P(i, j)` be the answer inside `text[i...j]`. If the two ends match, they wrap the best inside: `P(i + 1, j - 1) + 2`. Otherwise drop one end: `max(P(i + 1, j), P(i, j - 1))`. One character gives 1.
</Hint>
<Hint>
`P(i, j)` reads row `i + 1`, so fill i from `n - 1` down to 0, and j from `i + 1` upwards. Alternatively, the LPS has the same length as the LCS of the text and its reverse.
</Hint>
</Hints>

## Solutions

<Approach title="LCS with the reverse" time="O(n²)" space="O(n)">

A palindromic subsequence of the text is also a subsequence of the reversed text, so the LPS length equals `LCS(text, reversed(text))`. With two rows, that's O(n) memory. It's how the tests compute their reference for long strings.

</Approach>

<Approach title="Interval DP" time="O(n²)" space="O(n²)">

Fill the upper triangle bottom-up. Cells below the diagonal stay 0 and stand for empty ranges, which is exactly what two equal neighbours need.

```swift
public enum PalindromeByInsertions {
    public static func longestPalindromicSubsequence(_ text: String) -> Int {
        let s = Array(text)
        let n = s.count
        if n == 0 { return 0 }
        var best = Array(repeating: Array(repeating: 0, count: n), count: n)
        for i in stride(from: n - 1, through: 0, by: -1) {
            best[i][i] = 1
            for j in stride(from: i + 1, to: n, by: 1) {
                if s[i] == s[j] {
                    best[i][j] = best[i + 1][j - 1] + 2
                } else {
                    best[i][j] = max(best[i + 1][j], best[i][j - 1])
                }
            }
        }
        return best[0][n - 1]
    }

    public static func fewestInsertions(_ text: String) -> Int {
        text.count - longestPalindromicSubsequence(text)
    }
}
```

Why can't fewer insertions work? In the finished palindrome, original letters paired with original letters (plus a possible centre) form a palindromic subsequence of the text, so at most LPS letters avoid needing an inserted partner.

</Approach>
