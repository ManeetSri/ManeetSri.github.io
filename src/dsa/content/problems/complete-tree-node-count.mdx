Count the nodes of a **complete** binary tree: every level is full except perhaps the last, and the last level's nodes are as far left as possible. Do it faster than visiting every node.

`CompleteTreeNodeCount.count(_ root: TreeNode?) -> Int`

`TreeNode` comes from DSAKit. Trees are written in level order, the way `TreeNode.make` takes them; any level-order array without gaps describes a complete tree.

## Examples

| `root` | Output |
| --- | --- |
| `[1, 2, 3, 4, 5, 6]` | `6` |
| `[1, 2, 3, 4, 5, 6, 7]` | `7` |
| `[1, 2, 3, 4]` | `4` |
| `[1]` | `1` |
| `[]` | `0` |

## Constraints

- The tree is always complete.
- The real trees in the tests have up to 300,000 nodes. The largest tests describe trees of up to 400 million nodes, built cheaply by sharing identical subtrees. Code that only reads the tree can't tell, but a solution that visits every node takes several seconds there.
- Aim for O(log² n).

<Hints>
<Hint>
Walk down the leftmost edge and the rightmost edge, counting levels. If they're equal, the last level is full: the tree is perfect and has 2^h − 1 nodes, which is `(1 << h) - 1`.
</Hint>
<Hint>
If they differ, count the two subtrees and add 1. In a complete tree, at least one of the root's subtrees is perfect, so that call answers straight away, and only one path down the tree needs real work.
</Hint>
<Hint>
Another route: the last level's nodes fill a prefix of its places. Binary search for the first missing place; to test place k, walk down using k's binary digits, 0 for left and 1 for right.
</Hint>
</Hints>

## Solutions

<Approach title="Count every node" time="O(n)" space="O(h)">

Correct for any tree, but it ignores the shape, and the largest tests make it slow.

```swift
public static func count(_ root: TreeNode?) -> Int {
    guard let root else { return 0 }
    return 1 + count(root.left) + count(root.right)
}
```

</Approach>

<Approach title="Binary search on the last level" time="O(log² n)" space="O(1)">

With h levels, the last level has places 0 to 2^(h−1) − 1, and the nodes present are a prefix of them. About h checks, each walking h levels.

```swift
public static func count(_ root: TreeNode?) -> Int {
    guard let root else { return 0 }
    var levels = 0
    var node: TreeNode? = root
    while let current = node {
        levels += 1
        node = current.left
    }
    func exists(_ place: Int) -> Bool {
        var node: TreeNode? = root
        for bit in stride(from: levels - 2, through: 0, by: -1) {
            node = (place >> bit) & 1 == 0 ? node?.left : node?.right
        }
        return node != nil
    }
    var low = 0                                      // places before low exist
    var high = 1 << (levels - 1)                     // places from high onwards don't
    while low < high {
        let mid = low + (high - low) / 2
        if exists(mid) { low = mid + 1 } else { high = mid }
    }
    return (1 << (levels - 1)) - 1 + low
}
```

</Approach>

<Approach title="Perfect subtrees answer at once" time="O(log² n)" space="O(log n)">

Equal edge lengths mean a perfect tree. Otherwise one subtree is perfect and returns after two short walks, so the recursion follows one path: O(log n) levels, O(log n) work each.

```swift
import DSAKit

public enum CompleteTreeNodeCount {
    public static func count(_ root: TreeNode?) -> Int {
        guard let root else { return 0 }
        var leftLevels = 0
        var node: TreeNode? = root
        while let current = node {
            leftLevels += 1
            node = current.left
        }
        var rightLevels = 0
        node = root
        while let current = node {
            rightLevels += 1
            node = current.right
        }
        if leftLevels == rightLevels {
            return (1 << leftLevels) - 1             // perfect: every level is full
        }
        return 1 + count(root.left) + count(root.right)
    }
}
```

</Approach>
