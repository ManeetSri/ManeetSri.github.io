A sensor archive streams its readings in non-decreasing order, but it won't say how many there are. You can ask for the reading at any index with `value(i)`, which returns `nil` once `i` is past the end. Return the **first index whose reading is at least `target`**, or `nil` if every reading is smaller (or there are none).

`GallopingLowerBound.firstIndex(atLeast target: Int, reading value: (Int) -> Int?) -> Int?`

Every call to `value` is a slow network read, so make as few as you can. If the answer is index p (or the archive has p readings and all are smaller), use O(log p) reads: the tests allow `2 × (bit length of p + 1) + 4`, about twice log₂ p, whatever the archive's size.

## Examples

| Readings (hidden behind `value`) | `target` | Output | Why |
| --- | --- | --- | --- |
| `[3, 6, 9, 12, 15, 18]` | `10` | `3` | 12 is the first reading ≥ 10 |
| `[3, 6, 9, 12, 15, 18]` | `9` | `2` | an exact match counts |
| `[3, 6, 9, 12, 15, 18]` | `-5` | `0` | every reading is ≥ −5 |
| `[3, 6, 9, 12, 15, 18]` | `19` | `nil` | every reading is smaller |
| `[1, 4, 4, 4, 4, 7]` | `4` | `1` | the first of the duplicates |
| `[]` | `0` | `nil` | `value(0)` is already `nil` |

## Constraints

- `0 ≤` number of readings `≤ 100,000,000`, and the readings are in non-decreasing order.
- `value(i)` returns `nil` for every `i ≥` the number of readings. Never ask for a negative index.
- Readings and `target` can be any `Int`.

<Hints>
<Hint>
Binary search needs a `high`, and you don't have one. Find one by galloping: read index 1, 2, 4, 8, … until the reading there is at least `target`, or `nil`. Both of those mean the answer is at or before that index.
</Hint>
<Hint>
When you stop at index `bound`, the previous index you read, `bound / 2`, had a reading below `target`. So the answer lies in `bound / 2 + 1 ... bound`. Check index 0 on its own first, so that range always makes sense.
</Hint>
<Hint>
Finish with a lower-bound search over that range, treating `nil` like a reading that's too big: if `value(mid)` is a reading below `target`, the answer is after mid; otherwise it's mid or before. At the end, the position you land on is the answer, unless reading it gives `nil`.
</Hint>
</Hints>

## Solutions

<Approach title="Read one by one" time="O(p) reads" space="O(1)">

Walk forwards from index 0 until a reading is at least `target`, or the readings run out.

```swift
public static func firstIndex(atLeast target: Int, reading value: (Int) -> Int?) -> Int? {
    var i = 0
    while let reading = value(i) {
        if reading >= target { return i }
        i += 1
    }
    return nil
}
```

Correct, and fine for an answer near the front, but an answer at index 50,000,000 costs fifty million network reads.

</Approach>

<Approach title="Gallop, then binary search" time="O(log p) reads" space="O(1)">

Galloping doubles the bound until it reaches or passes the answer, which takes about log₂ p reads. The answer is then trapped in a range about p/2 long, and a lower-bound binary search over that range takes about log₂ p more. A `nil` reading behaves like a reading that's too big, because it's past the end, so the search needs no special case except at the very end.

```swift
public enum GallopingLowerBound {
    public static func firstIndex(atLeast target: Int, reading value: (Int) -> Int?) -> Int? {
        guard let first = value(0) else { return nil }          // no readings at all
        if first >= target { return 0 }
        // 1. Gallop: index bound / 2 is known to be below target
        var bound = 1
        while let reading = value(bound), reading < target {
            bound *= 2
        }
        // 2. The answer is in (bound / 2, bound]. Find the first index that is nil or ≥ target.
        var low = bound / 2 + 1
        var high = bound
        while low < high {
            let mid = low + (high - low) / 2
            if let reading = value(mid), reading < target {
                low = mid + 1                                    // a real reading, still too small
            } else {
                high = mid                                       // big enough, or past the end
            }
        }
        return value(low) == nil ? nil : low                     // past the end means "none"
    }
}
```

This is the exponential search from the lesson, turned into a lower bound. The cost depends on where the answer is, not on how many readings exist, which is exactly what an endless or unknown-length source needs.

</Approach>
