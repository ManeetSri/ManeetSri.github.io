Cities are numbered 0 to n − 1. Each option `[a, b, cost]` is a cable that could be laid between cities a and b for that cost. Choose cables so that every city can reach every other, directly or through other cities, at the smallest total cost, and return that cost. If no choice of cables connects every city, return −1.

`CheapestCableNetwork.minimumCost(_ n: Int, _ options: [[Int]]) -> Int`

## Examples

| `n` | `options` | Returns | Why |
| --- | --- | --- | --- |
| 4 | `[[0, 1, 3], [1, 2, 1], [2, 3, 4], [0, 3, 2], [0, 2, 5]]` | 6 | cables 1–2, 0–3 and 0–1 |
| 3 | `[[0, 1, 4], [1, 2, 4], [0, 2, 4]]` | 8 | any two of the three |
| 2 | `[[0, 1, 7], [1, 0, 3]]` | 3 | the cheaper of two options for one pair |
| 3 | `[[0, 1, 5]]` | −1 | city 2 can't be reached |
| 1 | `[]` | 0 | one city needs no cables |

## Constraints

- `1 ≤ n ≤ 20,000` and `0 ≤ options.count ≤ 100,000`.
- `0 ≤ cost ≤ 10,000`. The two cities of an option may be any cities in `0..<n`, and the same pair can appear more than once.
- The tests include 20,000 cities with 100,000 shuffled options, and random networks checked against Prim's algorithm.

## Solutions

<Approach title="Prim on a cost matrix" time="O(n²)" space="O(n²)">

Keep the cheapest option for each pair in an n × n matrix and run the array version of Prim. If some city is never reachable, return −1. Fine for small n, but 20,000 cities would need a 400-million-entry matrix.

</Approach>

<Approach title="Kruskal with union-find" time="O(E log E)" space="O(n + E)">

Sort the E options by cost, then take each one whose cities aren't connected yet. Stop after n − 1 cables.

```swift
import DSAKit

public enum CheapestCableNetwork {
    public static func minimumCost(_ n: Int, _ options: [[Int]]) -> Int {
        var cities = UnionFind(count: n)
        var total = 0
        var cables = 0
        for option in options.sorted(by: { $0[2] < $1[2] }) where cables < n - 1 {
            if cities.union(option[0], option[1]) {
                total += option[2]
                cables += 1
            }
        }
        return cables == n - 1 ? total : -1
    }
}
```

The `where cables < n - 1` clause skips the rest of the work once the network is complete. The sort dominates the cost; the unions are near-linear.

</Approach>
