A savings club keeps one balance per member, and an auditor must be able to look at **any past version** of the ledger. Every deposit (or withdrawal) creates a new version from an existing one, which need not be the latest: an auditor can say "start from version 3 and add 50 to member 7" to explore what-if histories, while every version stays readable. Each version answers two questions: the total held by a range of members, and the first member at which the running total, counted from member 0, reaches a target.

`VersionedLedgerSums.Ledger`, with `init(_ balances: [Int])`, `versionCount: Int`, `deposit(_ amount: Int, into index: Int, basedOn version: Int) -> Int`, `total(from left: Int, through right: Int, in version: Int) -> Int` and `firstReaching(_ target: Int, in version: Int) -> Int?`

- The initial balances are version 0. Each `deposit` makes the next version number (1, 2, 3, …), equal to version `version` with `amount` added to `balances[index]`, and returns that number. The base version is unchanged.
- `total` is the sum of `balances[left...right]` in that version.
- `firstReaching` is the smallest index i for which `balances[0] + … + balances[i] ≥ target` in that version, or `nil` if even the whole ledger falls short.

## Examples

Start with `Ledger([5, 3, 7, 9])`, then:

| Call | Output | Balances of the new version |
| --- | --- | --- |
| `deposit(2, into: 1, basedOn: 0)` | `1` | `[5, 5, 7, 9]` |
| `deposit(-5, into: 0, basedOn: 1)` | `2` | `[0, 5, 7, 9]` |
| `deposit(10, into: 3, basedOn: 0)` | `3` | `[5, 3, 7, 19]` |

| Query | Output |
| --- | --- |
| `total(from: 0, through: 3, in: 0)` | `24` |
| `total(from: 0, through: 3, in: 1)` | `26` |
| `total(from: 1, through: 2, in: 2)` | `12` |
| `total(from: 0, through: 3, in: 3)` | `34` |
| `firstReaching(8, in: 0)` | `1` |
| `firstReaching(8, in: 2)` | `2` |
| `firstReaching(30, in: 3)` | `3` |
| `firstReaching(30, in: 0)` | `nil` |
| `versionCount` | `4` |

Version 3 branches from version 0, so it doesn't contain the changes made in versions 1 and 2. In version 0 the running totals are 5, 8, 15, 24, so 8 is first reached at index 1.

## Constraints

- `1 ≤ balances.count ≤ 100,000`, and up to 100,000 deposits and 100,000 queries in any order.
- Every `version` passed in already exists, and every index is in range.
- Every balance is between 0 and 10¹² in **every** version: a withdrawal (a negative amount) never takes a balance below 0.
- Deposits and queries must each be O(log n). The tests make 100,000 deposits on 100,000 members, so copying the balances for each version is far too slow.

<Hints>
<Hint>
A point update in a sum segment tree changes only the nodes on one root-to-leaf path. Instead of changing them, make new copies of those nodes, each pointing at the old tree's child on the side that didn't change. The new root is the new version; the old root still describes the old one.
</Hint>
<Hint>
Explicit child links make the sharing possible: keep the nodes in three parallel arrays, `lefts`, `rights` and `sums`, append new nodes and never overwrite one. Keep `roots[v]` for each version v.
</Hint>
<Hint>
Because every balance is non-negative, the running total only grows, so `firstReaching` can walk down from the root: if the left child's sum is at least the target, go left; otherwise subtract it from the target and go right. If the root's sum is below the target, the answer is `nil`.
</Hint>
</Hints>

## Solutions

<Approach title="Copy the balances for every version" time="O(n) per deposit" space="O(n) per version">

Keep an array of arrays, append a modified copy for each deposit, and answer queries by scanning. It's the reference the tests use on small inputs. With 100,000 members and 100,000 deposits it would copy 10¹⁰ numbers.

</Approach>

<Approach title="A persistent sum tree, walking down for the running total" time="O(log n) per operation" space="O(n + q log n)">

```swift
public enum VersionedLedgerSums {
    public struct Ledger {
        private var lefts = [Int](), rights = [Int](), sums = [Int]()
        private var roots: [Int] = []
        private let count: Int

        public init(_ balances: [Int]) {
            count = balances.count
            roots.append(build(balances, 0, count - 1))
        }

        public var versionCount: Int { roots.count }

        private mutating func makeNode(_ left: Int, _ right: Int, _ sum: Int) -> Int {
            lefts.append(left); rights.append(right); sums.append(sum)
            return sums.count - 1
        }

        private mutating func build(_ balances: [Int], _ low: Int, _ high: Int) -> Int {
            if low == high { return makeNode(-1, -1, balances[low]) }
            let mid = (low + high) / 2
            let left = build(balances, low, mid), right = build(balances, mid + 1, high)
            return makeNode(left, right, sums[left] + sums[right])
        }

        public mutating func deposit(_ amount: Int, into index: Int, basedOn version: Int) -> Int {
            roots.append(added(amount, at: index, to: roots[version], 0, count - 1))
            return roots.count - 1
        }

        // A NEW node for this block; the old one is never changed
        private mutating func added(_ amount: Int, at index: Int, to node: Int, _ low: Int, _ high: Int) -> Int {
            if low == high { return makeNode(-1, -1, sums[node] + amount) }
            let mid = (low + high) / 2
            var left = lefts[node], right = rights[node]
            if index <= mid {
                left = added(amount, at: index, to: left, low, mid)
            } else {
                right = added(amount, at: index, to: right, mid + 1, high)
            }
            return makeNode(left, right, sums[left] + sums[right])
        }

        public func total(from left: Int, through right: Int, in version: Int) -> Int {
            sum(roots[version], 0, count - 1, left, right)
        }

        private func sum(_ node: Int, _ low: Int, _ high: Int, _ left: Int, _ right: Int) -> Int {
            if right < low || high < left { return 0 }
            if left <= low && high <= right { return sums[node] }
            let mid = (low + high) / 2
            return sum(lefts[node], low, mid, left, right) + sum(rights[node], mid + 1, high, left, right)
        }

        public func firstReaching(_ target: Int, in version: Int) -> Int? {
            var node = roots[version]
            guard sums[node] >= target else { return nil }
            var low = 0, high = count - 1, target = target
            while low < high {
                let mid = (low + high) / 2
                if sums[lefts[node]] >= target {
                    node = lefts[node]; high = mid
                } else {
                    target -= sums[lefts[node]]
                    node = rights[node]; low = mid + 1
                }
            }
            return low
        }
    }
}
```

Each deposit appends about log₂ n + 1 nodes and changes none, so all earlier versions stay valid, including the one it branched from. The walk in `firstReaching` is the same one a segment tree uses to find a position; it needs non-negative balances so that "the left half already reaches the target" is a safe reason to go left.

</Approach>
