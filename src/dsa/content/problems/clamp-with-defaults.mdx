Limit a number to a range: values below the range become its lower bound, values above it become its upper bound, and values inside it are returned unchanged. Most callers want the range 0 to 100, so make those the defaults.

`ClampWithDefaults.clamp(_ value: Int, lower: Int = 0, upper: Int = 100) -> Int`

## Examples

| Call | Returns | Why |
| --- | --- | --- |
| `clamp(42)` | `42` | inside the default range 0…100 |
| `clamp(150)` | `100` | above the default upper bound |
| `clamp(-5)` | `0` | below the default lower bound |
| `clamp(5, lower: 10)` | `10` | custom lower bound, default upper bound |
| `clamp(5, upper: 3)` | `3` | default lower bound, custom upper bound |
| `clamp(-20, lower: -10, upper: 10)` | `-10` | both bounds custom |

## Constraints

- `lower ≤ upper` always holds.
- `value`, `lower` and `upper` can be any `Int`, including negative numbers.
- Don't use the built-in `min` and `max` functions. Writing the comparisons yourself is the point.

<Hints>
<Hint>
The signature already contains the defaults. Your job is only the body: the tests will call it with and without `lower:` and `upper:`.
</Hint>
<Hint>
There are three cases: below `lower`, above `upper`, or in between. Each one can `return` straight away.
</Hint>
</Hints>

## Solutions

<Approach title="Two comparisons" time="O(1)" space="O(1)">

Check the two ways the value can be outside the range, and return early from each. Anything that gets past both checks is already inside the range.

```swift
public enum ClampWithDefaults {
    public static func clamp(_ value: Int, lower: Int = 0, upper: Int = 100) -> Int {
        if value < lower {
            return lower
        }
        if value > upper {
            return upper
        }
        return value
    }
}
```

Once you've met `min` and `max`, the same idea fits on one line: `min(max(value, lower), upper)`. Read it from the inside out: first raise the value to at least `lower`, then cap it at `upper`.

</Approach>
