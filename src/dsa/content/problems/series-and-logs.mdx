Three small tools from the series lesson, each with a trap near the top of the `Int` range. Write them so they never overflow when the answer fits, and never touch floating point.

`SeriesAndLogs.arithmeticSum(first: Int, step: Int, count: Int) -> Int` returns first + (first + step) + (first + 2·step) + …, with `count` terms.

`SeriesAndLogs.geometricSum(ratio: Int, terms: Int) -> Int` returns 1 + r + r² + … + r^(terms − 1).

`SeriesAndLogs.floorLog(_ n: Int, base: Int) -> Int` returns ⌊log_base n⌋: how many times you can divide n by `base` before it drops below `base`.

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `arithmeticSum(first: 1, step: 1, count: 100)` | `5050` | Gauss's sum |
| `arithmeticSum(first: 3, step: 4, count: 10)` | `210` | 3 + 7 + … + 39 |
| `arithmeticSum(first: 10, step: -3, count: 5)` | `20` | 10 + 7 + 4 + 1 − 2 |
| `geometricSum(ratio: 2, terms: 4)` | `15` | 1 + 2 + 4 + 8 |
| `geometricSum(ratio: 2, terms: 63)` | `9223372036854775807` | 2⁶³ − 1, which is `Int.max` |
| `floorLog(1000, base: 10)` | `3` | exactly 10³ |
| `floorLog(999, base: 10)` | `2` | |
| `floorLog(1, base: 2)` | `0` | |

## Constraints

- `arithmeticSum`: `|first|, |step| ≤ 10⁹`, `0 ≤ count ≤ 4 × 10⁹`, and the answer fits in an `Int`. Answer in O(1).
- `geometricSum`: `2 ≤ ratio ≤ 10⁹`, `0 ≤ terms`, and the answer fits in an `Int`.
- `floorLog`: `1 ≤ n ≤ Int.max` and `2 ≤ base ≤ 10⁹`.

<Hints>
<Hint>
The pairing trick gives count × (first + last) / 2, where last = first + (count − 1) × step. But for count = 4 × 10⁹, count × (first + last) is about 1.6 × 10¹⁹, too big for an `Int`, even though half of it fits. One of the two factors is always even: halve that one **before** multiplying.
</Hint>
<Hint>
The closed form (rᵏ − 1) / (r − 1) needs rᵏ, which can overflow even when the sum fits: for r = 2 and 63 terms the sum is `Int.max`, but 2⁶³ isn't an `Int`. Add the terms one at a time instead, and only compute the next power if there's another term to add.
</Hint>
<Hint>
For `floorLog`, multiplying a power up until it passes n overflows when n is near `Int.max`. Divide n down instead: `while n >= base { n /= base; count += 1 }`. And avoid `log10` and friends, which can land a hair below a whole number and truncate wrongly.
</Hint>
</Hints>

## Solutions

<Approach title="Add every term" time="O(count)" space="O(1)">

A loop is the obvious way to add an arithmetic series, but with 4 × 10⁹ terms it's far too slow. For the geometric series a loop is the right idea, as long as it's careful at the end.

</Approach>

<Approach title="Halve first, stop early, divide down" time="O(1), O(terms) and O(log n)" space="O(1)">

**Arithmetic.** The sum is count × (2·first + (count − 1)·step) / 2. If `count` is odd, then count − 1 is even, so the second factor is even. Either way one factor is even, and halving it first keeps every intermediate value no bigger than the answer. The second factor is at most about 4 × 10¹⁸ in size here, which still fits.

**Geometric.** Add the terms in a loop, and move to the next power only when another term is coming. That way the loop never computes the power one past the last term, which is exactly the one that overflows in the `Int.max` example. At most 63 terms can fit, so the loop is short.

**Logarithm.** Dividing never overflows, and each division is one step of the logarithm.

```swift
public enum SeriesAndLogs {
    public static func arithmeticSum(first: Int, step: Int, count: Int) -> Int {
        let pairSum = 2 * first + (count - 1) * step
        if count % 2 == 0 {
            return (count / 2) * pairSum
        }
        return count * (pairSum / 2)
    }

    public static func geometricSum(ratio: Int, terms: Int) -> Int {
        var total = 0
        var term = 1
        for index in 0..<terms {
            total += term
            if index < terms - 1 {
                term *= ratio
            }
        }
        return total
    }

    public static func floorLog(_ n: Int, base: Int) -> Int {
        var rest = n
        var count = 0
        while rest >= base {
            rest /= base
            count += 1
        }
        return count
    }
}
```

For `count` = 0 the arithmetic formula gives 0 × (something) = 0, so no special case is needed.

</Approach>
