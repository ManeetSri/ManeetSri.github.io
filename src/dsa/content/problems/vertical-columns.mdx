Imagine dropping a vertical line through each column of a binary tree and reading the nodes it passes. Return the columns from left to right, each read from top to bottom.

`VerticalColumns.columns(_ root: TreeNode?) -> [[Int]]`

Give every node a column and a row: the root is in column 0, row 0. A left child is one column to the left and one row down; a right child is one column to the right and one row down. Within a column, nodes go in order of row, top first. Nodes on the **same row and column** go in increasing order of value. The empty tree gives `[]`.

## Examples

| Tree (level order) | Output |
| --- | --- |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `[[4], [2, 7], [1, 5], [3], [6]]` |
| `[3, 9, 20, nil, nil, 15, 7]` | `[[9], [3, 15], [20], [7]]` |
| `[8, 3, 5, nil, 9, 2]` | `[[3], [8, 2, 9], [5]]` |
| `[100, 5, 7, nil, 1]` | `[[5], [100, 1], [7]]` |
| `[1, 2, nil, 3]` | `[[3], [2], [1]]` |
| `[7]` | `[[7]]` |

In the first tree, 5 (the right child of 2) is in column 0, under the root, and 7 (the left child of 5) is back in column −1. In `[8, 3, 5, nil, 9, 2]`, 9 and 2 are both on row 2 of column 0, so they're sorted: 2 before 9, even though 9 comes first in level order. In `[100, 5, 7, nil, 1]`, 100 comes before 1 because its row is higher; values only break ties within a row.

## Constraints

- `0 ≤` number of nodes `≤ 100,000`
- Values can repeat and can be negative.
- Trees in the tests are at most 200 levels deep, so recursion is fine.

<Hints>
<Hint>
Any traversal can work out each node's (column, row): pass them down, or store them in the queue next to each node. Collect a (column, row, value) triple for every node.
</Hint>
<Hint>
Swift tuples of comparable values can be compared with `<`, element by element. So sorting the triples with `{ ($0.column, $0.row, $0.value) < ($1.column, $1.row, $1.value) }` puts them in exactly the required order.
</Hint>
<Hint>
After sorting, walk the triples and start a new inner array whenever the column changes. Another route: group the (row, value) pairs in a dictionary keyed by column, then visit the columns in sorted key order and sort each column's pairs on their own.
</Hint>
</Hints>

## Solutions

<Approach title="Sort every (column, row, value)" time="O(n log n)" space="O(n)">

One breadth-first walk records each node's position, one sort orders everything, and one pass cuts the sorted list into columns.

```swift
public static func columns(_ root: TreeNode?) -> [[Int]] {
    guard let root else { return [] }
    var entries: [(column: Int, row: Int, value: Int)] = []
    var queue: [(node: TreeNode, column: Int, row: Int)] = [(root, 0, 0)]
    var head = 0
    while head < queue.count {
        let (node, column, row) = queue[head]
        head += 1
        entries.append((column, row, node.value))
        if let left = node.left { queue.append((left, column - 1, row + 1)) }
        if let right = node.right { queue.append((right, column + 1, row + 1)) }
    }

    entries.sort { ($0.column, $0.row, $0.value) < ($1.column, $1.row, $1.value) }

    var result: [[Int]] = []
    var currentColumn: Int? = nil
    for entry in entries {
        if entry.column != currentColumn {
            result.append([])                     // a new column starts
            currentColumn = entry.column
        }
        result[result.count - 1].append(entry.value)
    }
    return result
}
```

</Approach>

<Approach title="Columns in a dictionary" time="O(n log n)" space="O(n)">

Columns are a contiguous range of integers, but you don't know the range in advance, so a dictionary keyed by column collects each column's (row, value) pairs. The keys are sorted once, and each column is sorted on its own.

```swift
public static func columns(_ root: TreeNode?) -> [[Int]] {
    var byColumn: [Int: [(row: Int, value: Int)]] = [:]
    func walk(_ node: TreeNode?, column: Int, row: Int) {
        guard let node else { return }
        byColumn[column, default: []].append((row, node.value))
        walk(node.left, column: column - 1, row: row + 1)
        walk(node.right, column: column + 1, row: row + 1)
    }
    walk(root, column: 0, row: 0)
    return byColumn.keys.sorted().map { column in
        byColumn[column]!.sorted { ($0.row, $0.value) < ($1.row, $1.value) }.map(\.value)
    }
}
```

Sorting many small columns is a little faster than one big sort, and a dictionary's keys come out in no particular order, which is why they're sorted before use.

</Approach>
