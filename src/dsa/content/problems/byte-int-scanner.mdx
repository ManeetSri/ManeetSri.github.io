Write the heart of a fast input reader: given the raw ASCII bytes of some input, read the integers out of it one at a time, without creating any strings.

`ByteIntScanner.Reader.nextInt() -> Int?` and `ByteIntScanner.integers(in bytes: [UInt8]) -> [Int]`

- **`nextInt()`** skips any whitespace (bytes with codes of 32 or less: spaces, tabs, newlines and carriage returns), then reads one integer: an optional `-` followed by digits. It returns `nil` when only whitespace, or nothing, is left.
- **`integers(in:)`** returns every integer in the bytes, in order.

The input is well-formed: it contains only digits, whitespace, and `-` signs placed directly before a number's digits.

## Examples

Bytes are shown as the text they encode.

| Bytes | `integers(in:)` |
| --- | --- |
| `"3 9 4"` | `[3, 9, 4]` |
| `"10\n-3\n7\n"` | `[10, -3, 7]` |
| `"  1   2\t\t3  "` | `[1, 2, 3]` |
| `"5\r\n6\r\n"` | `[5, 6]` |
| `"007 -0"` | `[7, 0]` |
| `""` or `" \n "` | `[]` |

A `Reader` made from `"4\n10 -3\n"` returns `4`, `10`, `-3`, then `nil` on every later call.

## Constraints

- `0 ≤ bytes.count ≤ 2 × 10⁶`
- Every number is between -10¹⁸ and 10¹⁸.

<Hints>
<Hint>
Keep a `position` in the reader. Each call first moves it past bytes that are `<= 32`. If it reaches the end, return `nil`.
</Hint>
<Hint>
If the byte at `position` is `UInt8(ascii: "-")`, remember the sign and step over it. Then, while the byte is between `UInt8(ascii: "0")` and `UInt8(ascii: "9")`, do `value = value * 10 + Int(byte - UInt8(ascii: "0"))`.
</Hint>
<Hint>
`integers(in:)` makes a `Reader` and calls `nextInt()` in a `while let` loop until it returns `nil`.
</Hint>
</Hints>

## Solutions

<Approach title="Brute force: through strings" time="O(n)" space="O(n)">

Turning the bytes back into a `String` and splitting it works, and is the readable choice for small inputs. It creates a string and a `Substring` per number, which is exactly the work a fast reader exists to avoid.

```swift
public static func integers(in bytes: [UInt8]) -> [Int] {
    let text = String(decoding: bytes, as: UTF8.self)
    return text.split(whereSeparator: { $0.isWhitespace }).map { Int($0)! }
}
```

</Approach>

<Approach title="Scan the bytes once" time="O(n)" space="O(1)">

Each byte is examined once, and the reader needs no extra memory beyond its position; `integers(in:)` needs room for its result.

```swift
public enum ByteIntScanner {
    public struct Reader {
        private let bytes: [UInt8]
        private var position = 0

        public init(_ bytes: [UInt8]) {
            self.bytes = bytes
        }

        public mutating func nextInt() -> Int? {
            while position < bytes.count && bytes[position] <= 32 {
                position += 1
            }
            guard position < bytes.count else { return nil }

            var isNegative = false
            if bytes[position] == UInt8(ascii: "-") {
                isNegative = true
                position += 1
            }
            var value = 0
            while position < bytes.count,
                  bytes[position] >= UInt8(ascii: "0"),
                  bytes[position] <= UInt8(ascii: "9") {
                value = value * 10 + Int(bytes[position] - UInt8(ascii: "0"))
                position += 1
            }
            return isNegative ? -value : value
        }
    }

    public static func integers(in bytes: [UInt8]) -> [Int] {
        var reader = Reader(bytes)
        var result: [Int] = []
        while let number = reader.nextInt() {
            result.append(number)
        }
        return result
    }
}
```

`nextInt()` is `mutating` because it moves `position`, which is why the reader must be a `var`. In a judge solution, you'd create the reader from `[UInt8](FileHandle.standardInput.readDataToEndOfFile())`.

</Approach>
