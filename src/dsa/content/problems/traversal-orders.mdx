Return the values of a binary tree in preorder, inorder and postorder, each written recursively. They differ only in when a node's own value is recorded: before its subtrees, between them, or after them.

`TraversalOrders.preorder(_ root: TreeNode?) -> [Int]`, `TraversalOrders.inorder(_ root: TreeNode?) -> [Int]` and `TraversalOrders.postorder(_ root: TreeNode?) -> [Int]`

- **Preorder:** the node, then its left subtree, then its right subtree.
- **Inorder:** the left subtree, then the node, then the right subtree.
- **Postorder:** the left subtree, then the right subtree, then the node.

The empty tree gives `[]` in every order. Write `inorder` yourself rather than using DSAKit's `inorder` property.

## Examples

| Tree (level order) | Preorder | Inorder | Postorder |
| --- | --- | --- | --- |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `[1, 2, 4, 5, 7, 3, 6]` | `[4, 2, 7, 5, 1, 3, 6]` | `[4, 7, 5, 2, 6, 3, 1]` |
| `[8, 3, 10, 1, 6, nil, 14, nil, nil, 4, 7, 13]` | `[8, 3, 1, 6, 4, 7, 10, 14, 13]` | `[1, 3, 4, 6, 7, 8, 10, 13, 14]` | `[1, 4, 7, 6, 3, 13, 14, 10, 8]` |
| `[1, nil, 2, nil, 3]` | `[1, 2, 3]` | `[1, 2, 3]` | `[3, 2, 1]` |
| `[5]` | `[5]` | `[5]` | `[5]` |

The second tree is a binary search tree, so its inorder comes out sorted.

## Constraints

- `0 ≤` number of nodes `≤ 131,071`
- Trees in the tests are at most 500 levels deep, so recursion is safe.

<Hints>
<Hint>
Each order is the same three lines in a different arrangement: recurse left, recurse right, record the value. Start with the empty tree: there's nothing to record.
</Hint>
<Hint>
Returning `preorder(left) + preorder(right)` from every call builds and copies lots of small arrays. Instead, write a nested function that appends to one `result` array declared in the outer function. Nested functions can change variables they capture.
</Hint>
</Hints>

## Solutions

<Approach title="A nested helper appending to one array" time="O(n)" space="O(h)">

The helper has a base case for `nil` and otherwise makes two recursive calls, with the append in the order's position. Every node is visited once; the recursion is as deep as the tree is tall.

```swift
public enum TraversalOrders {
    public static func preorder(_ root: TreeNode?) -> [Int] {
        var result: [Int] = []
        func walk(_ node: TreeNode?) {
            guard let node else { return }
            result.append(node.value)             // before the children
            walk(node.left)
            walk(node.right)
        }
        walk(root)
        return result
    }

    public static func inorder(_ root: TreeNode?) -> [Int] {
        var result: [Int] = []
        func walk(_ node: TreeNode?) {
            guard let node else { return }
            walk(node.left)
            result.append(node.value)             // between the children
            walk(node.right)
        }
        walk(root)
        return result
    }

    public static func postorder(_ root: TreeNode?) -> [Int] {
        var result: [Int] = []
        func walk(_ node: TreeNode?) {
            guard let node else { return }
            walk(node.left)
            walk(node.right)
            result.append(node.value)             // after the children
        }
        walk(root)
        return result
    }
}
```

</Approach>

<Approach title="Concatenating arrays" time="O(n · h)" space="O(n)">

The shortest version returns arrays and joins them. It reads exactly like the definitions, but every level copies the values below it again, so a node at depth d is copied d times.

```swift
public static func preorder(_ root: TreeNode?) -> [Int] {
    guard let root else { return [] }
    return [root.value] + preorder(root.left) + preorder(root.right)
}

public static func inorder(_ root: TreeNode?) -> [Int] {
    guard let root else { return [] }
    return inorder(root.left) + [root.value] + inorder(root.right)
}

public static func postorder(_ root: TreeNode?) -> [Int] {
    guard let root else { return [] }
    return postorder(root.left) + postorder(root.right) + [root.value]
}
```

For a balanced tree that's O(n log n); for a chain it's O(n²). Fine for a quick check, but prefer the helper.

</Approach>
