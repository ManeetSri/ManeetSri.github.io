Two lists are each sorted in ascending order. Join them into one sorted list by relinking their nodes, and return its head. When values are equal, nodes from the first list come before nodes from the second.

`MergeSortedLists.merged(_ first: ListNode?, _ second: ListNode?) -> ListNode?`

## Examples

| `first` | `second` | Result |
| --- | --- | --- |
| `1 -> 4 -> 6` | `2 -> 3 -> 7 -> 8` | `1 -> 2 -> 3 -> 4 -> 6 -> 7 -> 8` |
| `2 -> 2 -> 5` | `2 -> 5 -> 5` | `2 -> 2 -> 2 -> 5 -> 5 -> 5` |
| `1 -> 2` | empty | `1 -> 2` |
| empty | empty | empty |

In the second example, the two 2s from `first` come before the 2 from `second`.

## Constraints

- Each list has 0 to 50,000 nodes.
- Values are any `Int`, and each list is sorted, possibly with repeats.
- Reuse the nodes; don't create new ones (a single dummy node is fine).

<Hints>
<Hint>
The smallest value overall is at the front of one of the two lists. Take whichever front node is smaller, and repeat with what's left.
</Hint>
<Hint>
Build the result with a dummy node and a `tail` reference that always points at the last node attached. That way, attaching the first node needs no special case. Compare with `<=` so the first list wins ties.
</Hint>
<Hint>
When one list runs out, the rest of the other is already sorted and no smaller than anything attached, so attach it with one assignment. Avoid a recursive merge: with 100,000 nodes in total it would need 100,000 stack frames.
</Hint>
</Hints>

## Solutions

<Approach title="Collect, sort, rebuild" time="O(n log n)" space="O(n)">

Gathering every value into an array, sorting it and building a new list gives the right values. But it ignores the fact that the lists are already sorted, and it creates new nodes, which the tests reject. It's a useful reference to test a better version against.

```swift
public static func merged(_ first: ListNode?, _ second: ListNode?) -> ListNode? {
    ListNode.make(((first?.values ?? []) + (second?.values ?? [])).sorted())
}
```

</Approach>

<Approach title="Dummy head and tail" time="O(n + m)" space="O(1)">

Each pass attaches one node to the tail and advances the list it came from. Once either list is empty, `a ?? b` attaches whatever remains.

```swift
import DSAKit

public enum MergeSortedLists {
    public static func merged(_ first: ListNode?, _ second: ListNode?) -> ListNode? {
        let dummy = ListNode(0)
        var tail = dummy
        var a = first
        var b = second
        while let left = a, let right = b {
            if left.value <= right.value {
                tail.next = left
                a = left.next
            } else {
                tail.next = right
                b = right.next
            }
            tail = tail.next!
        }
        tail.next = a ?? b             // one list is empty; the other is already sorted
        return dummy.next
    }
}
```

`<=` keeps the merge stable: on ties the node from `first` goes first, so equal values keep their original order.

</Approach>
