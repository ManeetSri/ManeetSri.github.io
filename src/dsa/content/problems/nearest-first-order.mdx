Sort some numbers by how close they are to a target, closest first. When two numbers are equally close, the smaller one comes first. Keep every number, including repeats.

`NearestFirstOrder.sorted(_ numbers: [Int], around target: Int) -> [Int]`

## Examples

| `numbers` | `target` | Output |
| --- | --- | --- |
| `[1, 9, 4, 6, 5]` | `5` | `[5, 4, 6, 1, 9]` |
| `[10, -2, 3]` | `0` | `[-2, 3, 10]` |
| `[7, 3, 7, 3]` | `5` | `[3, 3, 7, 7]` |
| `[20, 30]` | `100` | `[30, 20]` |
| `[]` | `4` | `[]` |

In the first example, 4 and 6 are both 1 away from 5, so the smaller, 4, goes first. 1 and 9 are both 4 away, so 1 goes before 9.

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- `-1,000,000 ≤ numbers[i], target ≤ 1,000,000`

<Hints>
<Hint>
`numbers.sorted(by:)` takes a closure that answers one question about two numbers: should the first come before the second? Write that closure as a trailing closure: `numbers.sorted { first, second in … }`.
</Hint>
<Hint>
A closure can use `target` directly, because it's written inside the function where `target` exists. The distance of a number from the target is `abs(number - target)`.
</Hint>
<Hint>
The closure needs two rules, so give its parameters names and write `return` yourself. If the two distances differ, the smaller distance goes first. Otherwise, the smaller number goes first.
</Hint>
</Hints>

## Solutions

<Approach title="A closure with two rules" time="O(n log n)" space="O(n)">

`sorted` does the sorting; all you supply is the rule for comparing two numbers. The rule needs several statements, so the closure names its parameters instead of using `$0` and `$1`, and spells out each `return`. It's written as a trailing closure, so the `by:` label disappears.

```swift
public enum NearestFirstOrder {
    public static func sorted(_ numbers: [Int], around target: Int) -> [Int] {
        numbers.sorted { first, second in
            let firstDistance = abs(first - target)
            let secondDistance = abs(second - target)
            if firstDistance != secondDistance {
                return firstDistance < secondDistance
            }
            return first < second
        }
    }
}
```

The function's body is a single expression, the call to `sorted`, so the function itself can leave out `return`. The closure inside has several statements, so it can't.

Sorting is O(n log n), which you'll see properly in M31. The new array takes O(n) space; `numbers` is left as it was.

</Approach>

<Approach title="Compare tuples" time="O(n log n)" space="O(n)">

Swift can compare tuples with `<`, element by element: it compares the first elements, and only if they're equal moves on to the second. That's exactly "by distance, then by value", so the whole rule fits in one line with shorthand names.

```swift
public static func sorted(_ numbers: [Int], around target: Int) -> [Int] {
    numbers.sorted { (abs($0 - target), $0) < (abs($1 - target), $1) }
}
```

It's shorter, but the reader has to know how tuple comparison works. The first version says the two rules in plain steps. Both are fine; pick the one you'd rather read in a week.

</Approach>
