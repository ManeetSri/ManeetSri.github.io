An airport shuttle drives one way along a road with stops numbered 0, 1, 2 and so on. Each booked trip says how many passengers get on, where, and where they get off. Can a shuttle with `capacity` seats carry every trip without ever having more than `capacity` passengers on board?

`ShuttleCapacity.canCarryAll(_ trips: [[Int]], capacity: Int) -> Bool`

Each trip is `[passengers, pickUp, dropOff]`. At every stop, the riders getting off leave before anyone new gets on, so seats freed at a stop can go to passengers boarding there.

## Examples

| `trips` | `capacity` | Output |
| --- | --- | --- |
| `[[2, 1, 5], [3, 3, 7]]` | `4` | `false` |
| `[[2, 1, 5], [3, 3, 7]]` | `5` | `true` |
| `[[2, 1, 5], [3, 5, 7]]` | `3` | `true` |
| `[[4, 0, 2], [4, 1, 3], [4, 2, 4]]` | `7` | `false` |
| `[]` | `0` | `true` |

In the first two examples, 5 people are on board between stops 3 and 5. In the third, the 2 riders leave at stop 5 before the 3 new ones board there, so there are never more than 3.

## Constraints

- `0 ≤ trips.count ≤ 100,000`
- `1 ≤ passengers ≤ 100` and `0 ≤ pickUp < dropOff ≤ 100,000`
- `0 ≤ capacity ≤ 10⁷`
- Aim for O(n + S) time, where S is the last drop-off stop, or O(n log n). Adding each trip to every stop it passes could take 5 × 10⁹ steps.

<Hints>
<Hint>
A trip only changes the number on board in two places: up by `passengers` at `pickUp`, and back down at `dropOff`.
</Hint>
<Hint>
The stop numbers are small enough to index an array. Record each trip's two changes in it, a difference array, then run a sum along the stops to get the load after each one.
</Hint>
<Hint>
Put the `-passengers` at `dropOff` itself, not `dropOff + 1`: those riders are gone by the time the shuttle is at that stop. Check the running sum after every stop.
</Hint>
</Hints>

## Solutions

<Approach title="A difference array over the stops" time="O(n + S)" space="O(S)">

A rider is on board for the half-open stretch `[pickUp, dropOff)`. Because the running sum reads the load only after **all** the changes at a stop, riders leaving and boarding at the same stop are handled correctly with no extra care.

```swift
public enum ShuttleCapacity {
    public static func canCarryAll(_ trips: [[Int]], capacity: Int) -> Bool {
        let lastStop = trips.map { $0[2] }.max() ?? 0
        var change = Array(repeating: 0, count: lastStop + 1)
        for trip in trips {
            change[trip[1]] += trip[0]     // board
            change[trip[2]] -= trip[0]     // gone by this stop
        }
        var onBoard = 0
        for delta in change {
            onBoard += delta
            if onBoard > capacity {
                return false
            }
        }
        return true
    }
}
```

</Approach>

<Approach title="Sorted events" time="O(n log n)" space="O(n)">

If the stop numbers were huge, say distances in metres along a motorway, an array indexed by stop wouldn't fit. Sort the changes instead. Leaving is negative and boarding positive, so sorting `(stop, change)` tuples puts the riders leaving first at each stop.

```swift
public static func canCarryAll(_ trips: [[Int]], capacity: Int) -> Bool {
    var events: [(stop: Int, change: Int)] = []
    for trip in trips {
        events.append((trip[1], trip[0]))
        events.append((trip[2], -trip[0]))
    }
    events.sort { ($0.stop, $0.change) < ($1.stop, $1.change) }
    var onBoard = 0
    for event in events {
        onBoard += event.change
        if onBoard > capacity {
            return false
        }
    }
    return true
}
```

Checking after every single event is safe here: within a stop, all the leaving comes before any boarding, so the load only rises towards that stop's final value.

</Approach>
