A village of `peopleCount` people, labelled 0 to `peopleCount - 1`, is looking for its archivist. The archivist is trusted by **every** other villager and trusts **nobody**. You're given the trust relationships as pairs `[a, b]`, meaning a trusts b. Return the archivist's label, or -1 if nobody fits.

`TrustedArchivist.find(peopleCount: Int, trusts: [[Int]]) -> Int`

Read each pair as a directed edge a → b. The archivist is then a vertex with a particular in-degree and out-degree.

## Examples

| `peopleCount` | `trusts` | Returns | Why |
| --- | --- | --- | --- |
| 3 | `[[0, 2], [1, 2]]` | 2 | 0 and 1 trust 2, and 2 trusts nobody |
| 3 | `[[0, 2], [1, 2], [2, 0]]` | -1 | 2 trusts 0, so 2 isn't the archivist |
| 4 | `[[0, 3], [1, 3], [2, 3], [0, 1]]` | 3 | other trusts don't matter |
| 4 | `[[0, 3], [1, 3]]` | -1 | 2 doesn't trust 3 |
| 1 | `[]` | 0 | a lone villager is trusted by all 0 others |

## Constraints

- `1 ≤ peopleCount ≤ 100,000` and `0 ≤ trusts.count ≤ 200,000`.
- Every pair has two different labels in range, and no pair appears twice.
- There's at most one archivist: two people can't both be trusted by everyone and trust nobody, since each would have to trust the other.
- The tests include a village of 100,000 people, so checking every pair for every person, O(n · t), is far too slow.

<Hints>
<Hint>
In graph words: the archivist has in-degree `peopleCount - 1` and out-degree 0. You don't need an adjacency list, only the two counts for each person.
</Hint>
<Hint>
Make two arrays of zeros, one entry per person. For each pair `[a, b]`, add 1 to a's out-degree and 1 to b's in-degree. Then look for the person whose counts match.
</Hint>
<Hint>
One array is enough: add 1 for each trust received and subtract 1 for each trust given. Only the archivist can reach `peopleCount - 1`, because that needs n − 1 trusts received and none given.
</Hint>
</Hints>

## Solutions

<Approach title="Count in-degrees and out-degrees" time="O(n + t)" space="O(n)">

One pass over the t pairs fills both arrays, and one pass over the n people checks them.

```swift
public enum TrustedArchivist {
    public static func find(peopleCount: Int, trusts: [[Int]]) -> Int {
        var trustedBy = Array(repeating: 0, count: peopleCount)      // in-degree
        var trustsOthers = Array(repeating: 0, count: peopleCount)   // out-degree
        for pair in trusts {
            trustsOthers[pair[0]] += 1
            trustedBy[pair[1]] += 1
        }
        for person in 0..<peopleCount where trustedBy[person] == peopleCount - 1 && trustsOthers[person] == 0 {
            return person
        }
        return -1
    }
}
```

</Approach>

<Approach title="One score per person" time="O(n + t)" space="O(n)">

Keep `score[person]`: +1 for every trust received, −1 for every trust given. A person who trusts anyone can't reach n − 1, because at most n − 1 people can trust them. So the archivist is the one person whose score is exactly `peopleCount - 1`.

```swift
var score = Array(repeating: 0, count: peopleCount)
for pair in trusts {
    score[pair[0]] -= 1
    score[pair[1]] += 1
}
return score.firstIndex(of: peopleCount - 1) ?? -1
```

This relies on the promise that no pair appears twice. With repeated pairs, someone could collect n − 1 "trusts" from fewer people.

</Approach>
