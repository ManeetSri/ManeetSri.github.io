A function is described as a list of **blocks** that run one after another. Each block is a list of **layers**, outermost first, wrapped around a body that does O(1) work. Apply the Big-O rules to find the function's complexity, written as n^power × (log n)^logPower.

| `Layer` | Means | Cost |
| --- | --- | --- |
| `.linear` | a loop with n passes | n |
| `.halving` | a loop that halves a size of n until it reaches 1 | log n |
| `.fixed(k)` | a loop with exactly k passes, whatever n is | k, a constant |
| `.sort` | a call to `sorted()` on the n-element input | n log n |

A layer runs everything inside it once per pass, so the costs in a block **multiply**. Blocks run in sequence, so their costs **add**, and only the dominant one survives.

`LoopNestBound.bound(_ blocks: [[Layer]]) -> Bound`

`Bound` has two properties, `power` and `logPower`: O(n² log n) is `Bound(power: 2, logPower: 1)`, and O(1) is `Bound(power: 0, logPower: 0)`.

## Examples

| `blocks` | Output | Reads as |
| --- | --- | --- |
| `[[.linear, .linear], [.linear]]` | `Bound(power: 2, logPower: 0)` | n² + n is O(n²) |
| `[[.sort], [.linear]]` | `Bound(power: 1, logPower: 1)` | n log n + n is O(n log n) |
| `[[.halving, .fixed(100)]]` | `Bound(power: 0, logPower: 1)` | 100 log n is O(log n) |
| `[[.linear, .sort]]` | `Bound(power: 2, logPower: 1)` | sorting inside a loop is O(n² log n) |
| `[[.halving, .halving], [.linear]]` | `Bound(power: 1, logPower: 0)` | log² n + n is O(n) |
| `[]` | `Bound(power: 0, logPower: 0)` | no work at all is O(1) |

## Constraints

- At most 1,000 blocks, each with at most 50 layers.
- `1 ≤ k ≤ 10⁹` for `.fixed(k)`.

## Solutions

<Approach title="Add exponents within a block, keep the largest block" time="O(total layers)" space="O(1)">

Rule 4 (nested code multiplies) turns each block into a sum of exponents: every `.linear` adds a power of n, every `.halving` a power of log n, `.sort` adds one of each, and `.fixed` adds nothing because of Rule 1 (drop constant factors). Rule 3 adds the blocks, and Rule 2 keeps only the dominant term. Comparing `(power, logPower)` as a tuple compares the power first, which is right because any power of n beats any power of log n.

```swift
public enum LoopNestBound {
    public enum Layer: Equatable {
        case linear
        case halving
        case fixed(Int)
        case sort
    }

    public struct Bound: Equatable {
        public var power: Int
        public var logPower: Int

        public init(power: Int, logPower: Int) {
            self.power = power
            self.logPower = logPower
        }
    }

    public static func bound(_ blocks: [[Layer]]) -> Bound {
        var best = Bound(power: 0, logPower: 0)
        for block in blocks {
            var cost = Bound(power: 0, logPower: 0)
            for layer in block {
                switch layer {
                case .linear:
                    cost.power += 1
                case .halving:
                    cost.logPower += 1
                case .fixed:
                    break
                case .sort:
                    cost.power += 1
                    cost.logPower += 1
                }
            }
            if (cost.power, cost.logPower) > (best.power, best.logPower) {
                best = cost
            }
        }
        return best
    }
}
```

Notice that `[[.fixed(1_000_000_000)]]` is O(1), and `[[.halving, .halving, .halving], [.linear]]` is O(n): constant factors vanish, and any power of n eventually outgrows any power of log n.

</Approach>
