Here's a model of a growable array. It starts empty, with room for **1** element. Each append checks whether the array is full (its count equals its capacity). If it is, the array first moves to a bigger block of memory, **copying every element it already holds**, and then writes the new element.

Return the total number of elements copied over `n` appends, for two ways of growing:

- **Doubling:** the new capacity is twice the old one.
- **Fixed step:** the new capacity is the old one plus `step`.

`GrowthCopies.copiesWhenDoubling(appends n: Int) -> Int`

`GrowthCopies.copiesWhenGrowing(by step: Int, appends n: Int) -> Int`

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `copiesWhenDoubling(appends: 1)` | `0` | the first element fits |
| `copiesWhenDoubling(appends: 5)` | `7` | growths when holding 1, 2 and 4: 1 + 2 + 4 |
| `copiesWhenDoubling(appends: 1000)` | `1023` | |
| `copiesWhenGrowing(by: 3, appends: 8)` | `12` | capacities 1, 4, 7, 10: growths when holding 1, 4 and 7 |
| `copiesWhenGrowing(by: 10, appends: 1000)` | `49600` | |

## Constraints

- Doubling: `0 ≤ n ≤ 10¹⁸`.
- Fixed step: `0 ≤ n ≤ 10⁹` and `1 ≤ step ≤ 10⁹`. Answer in O(1): with `step` = 1 and a billion appends, even one loop pass per growth would be a billion passes.
- Neither function may simulate every append. Every answer fits in an `Int`.

<Hints>
<Hint>
Simulate small cases by hand, writing down the capacity after each append. A growth happens when an append finds the array full, so the array is holding exactly `capacity` elements, and that's how many get copied.
</Hint>
<Hint>
Doubling: growths happen when the array holds 1, 2, 4, 8, … elements, as long as there's another append to come, so as long as that number is less than n. A loop over the growths, adding each capacity, takes only about log₂ n passes. Fixed step: growth number m (counting from 0) happens when the array holds 1 + m × step elements, again as long as that's less than n.
</Hint>
<Hint>
For the fixed step, the last growth is number M = (n − 2) / step, for n ≥ 2. The copies are (1 + 0·step) + (1 + 1·step) + … + (1 + M·step) = (M + 1) + step × (0 + 1 + … + M). Use the triangle formula for the last part. For n = 0 or 1, nothing is ever copied.
</Hint>
</Hints>

## Solutions

<Approach title="Simulate every append" time="O(n)" space="O(1)">

Follow the model exactly, one append at a time. It's the best way to check a formula on small inputs, but for 10¹⁸ appends it would never finish.

```swift
public static func copiesWhenGrowing(by step: Int, appends n: Int) -> Int {
    var capacity = 1
    var copies = 0
    for count in 0..<n where count == capacity {
        copies += count
        capacity += step
    }
    return copies
}
```

</Approach>

<Approach title="Add up the growths directly" time="O(log n) and O(1)" space="O(1)">

**Doubling.** The array is full when it holds 1, 2, 4, … elements, and a growth happens there only if another append is coming, so for capacities less than n. Loop over those capacities and add them. The total is 1 + 2 + 4 + … + 2ᵏ, a geometric series that's always less than 2n: the reason doubling gives amortised O(1) appends.

**Fixed step.** The growths happen when the array holds 1, 1 + step, 1 + 2·step, …, up to the last one below n, which is number M = (n − 2) / step. Adding up M + 1 terms of the form 1 + m·step gives (M + 1) + step × M(M + 1) / 2. That's about n² / (2 · step): quadratic, which is why growing by a fixed amount is a bad idea.

```swift
public enum GrowthCopies {
    public static func copiesWhenDoubling(appends n: Int) -> Int {
        var capacity = 1
        var copies = 0
        while capacity < n {
            copies += capacity
            capacity *= 2
        }
        return copies
    }

    public static func copiesWhenGrowing(by step: Int, appends n: Int) -> Int {
        guard n >= 2 else { return 0 }
        let last = (n - 2) / step
        let growths = last + 1
        return growths + step * (last * growths / 2)
    }
}
```

`last * growths` is a product of two consecutive whole numbers, so it's always even and dividing by 2 is exact. Dividing before multiplying by `step` also keeps the intermediate value small enough for an `Int`.

</Approach>
