Two questions about root-to-node paths in a binary tree:

- `GoodNodesAndNumbers.goodNodeCount(_ root: TreeNode?) -> Int`: how many nodes are **good**. A node is good when no node on the path from the root down to it has a **larger** value. The root is always good.
- `GoodNodesAndNumbers.pathNumberSum(_ root: TreeNode?) -> Int`: every node holds a digit from 0 to 9, and each path from the root to a leaf spells a number, the root's digit first. Return the sum of those numbers, or 0 for the empty tree.

`TreeNode` comes from DSAKit. Trees are written in level order, the way `TreeNode.make` takes them.

## Examples

| Call | Output |
| --- | --- |
| `goodNodeCount([5, 3, 8, 6, 2, 7, 9])` | `4` |
| `goodNodeCount([2, 2, 1, 2])` | `3` |
| `goodNodeCount([-1, -5, 0])` | `2` |
| `goodNodeCount([])` | `0` |
| `pathNumberSum([4, 0, 7, 2, 9])` | `858` |
| `pathNumberSum([0, 1])` | `1` |
| `pathNumberSum([1, 0, nil, 0, nil, 5])` | `1005` |
| `pathNumberSum([])` | `0` |

In `[5, 3, 8, 6, 2, 7, 9]`, the good nodes are 5, 8, 9 and the 6 under 3: nothing above 6 (5 and 3) is larger. In `[2, 2, 1, 2]`, equal values count as good. `[4, 0, 7, 2, 9]` spells 402, 409 and 47.

## Constraints

- `goodNodeCount`: at most 150,000 nodes, at most 50 levels deep, values are any `Int`.
- `pathNumberSum`: every value is a digit from 0 to 9, and trees are at most 12 levels deep, so every number fits easily in an `Int`.

<Hints>
<Hint>
Both questions need one fact about a node's ancestors, so pass it down as a parameter: the largest value above, or the number spelled so far.
</Hint>
<Hint>
For good nodes, start with `Int.min` above the root. A node is good if its value is at least the largest value above it, and its children see the larger of the two.
</Hint>
<Hint>
For path numbers, the number so far becomes `above * 10 + digit` at each node. Only a leaf, with no children at all, completes a number; a node with one child doesn't.
</Hint>
</Hints>

## Solutions

<Approach title="Pass the state down" time="O(n)" space="O(h)">

Each call receives its ancestors' summary as an `Int` parameter, so there's nothing to undo on the way back up.

```swift
import DSAKit

public enum GoodNodesAndNumbers {
    public static func goodNodeCount(_ root: TreeNode?) -> Int {
        func count(_ node: TreeNode?, highestAbove: Int) -> Int {
            guard let node else { return 0 }
            let good = node.value >= highestAbove ? 1 : 0
            let highest = max(highestAbove, node.value)
            return good + count(node.left, highestAbove: highest) + count(node.right, highestAbove: highest)
        }
        return count(root, highestAbove: Int.min)
    }

    public static func pathNumberSum(_ root: TreeNode?) -> Int {
        func sum(_ node: TreeNode?, spelledAbove: Int) -> Int {
            guard let node else { return 0 }
            let number = spelledAbove * 10 + node.value
            if node.left == nil && node.right == nil {
                return number                        // a leaf ends one number
            }
            return sum(node.left, spelledAbove: number) + sum(node.right, spelledAbove: number)
        }
        return sum(root, spelledAbove: 0)
    }
}
```

</Approach>

<Approach title="An explicit stack of (node, state) pairs" time="O(n)" space="O(n)">

The same idea without recursion, for trees too deep for the call stack. Each entry carries its own copy of the state, so the order they're processed in doesn't matter.

```swift
public static func goodNodeCount(_ root: TreeNode?) -> Int {
    var count = 0
    var pending: [(node: TreeNode, highestAbove: Int)] = root.map { [($0, Int.min)] } ?? []
    while let (node, highestAbove) = pending.popLast() {
        if node.value >= highestAbove { count += 1 }
        let highest = max(highestAbove, node.value)
        if let left = node.left { pending.append((left, highest)) }
        if let right = node.right { pending.append((right, highest)) }
    }
    return count
}
```

</Approach>
