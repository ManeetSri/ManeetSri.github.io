You're given a slice of an array, and you need the **index** of its largest element. Return the index the slice itself uses, which is the element's index in the original array, not its position counted from 0 within the slice. If the largest value appears more than once, return the smallest such index. Return `nil` for an empty slice.

`SliceLargestIndex.indexOfLargest(in window: ArraySlice<Int>) -> Int?`

## Examples

With `numbers = [4, 8, 1, 9, 3, 9, 2]`:

| Call | Slice | Output |
| --- | --- | --- |
| `indexOfLargest(in: numbers[2...5])` | `[1, 9, 3, 9]` | `3` |
| `indexOfLargest(in: numbers[4...])` | `[3, 9, 2]` | `5` |
| `indexOfLargest(in: numbers[..<3])` | `[4, 8, 1]` | `1` |
| `indexOfLargest(in: numbers[6...])` | `[2]` | `6` |
| `indexOfLargest(in: numbers[3..<3])` | `[]` | `nil` |

In the second example, 9 is the **second** element of the slice, but the answer is `5`, not `1`: that's where it sits in `numbers`, and `numbers[4...][5]` reads that 9. In the first example both 9s count as largest, and the earlier one, at index 3, wins.

## Constraints

- The slice has `0` to `100,000` elements.
- `-1,000,000,000 ≤ window[i] ≤ 1,000,000,000`
- The slice may be a slice of a slice, so don't assume anything about where its indexes start.

<Hints>
<Hint>
A slice keeps the original array's indexes. Its first element is at `window.startIndex`, which is only `0` if the slice starts at the beginning of the array.
</Hint>
<Hint>
Loop over `window.indices`, not `0..<window.count`. The indices are the real ones, so `window[i]` is always safe and `i` is already the answer you want to return.
</Hint>
<Hint>
Guard against the empty slice first, then start the best index at `window.startIndex`. Move it only when you find a value **strictly** bigger, so ties keep the earlier index.
</Hint>
</Hints>

## Solutions

<Approach title="Loop over the slice's own indices" time="O(k)" space="O(1)">

`window.indices` is the range of indexes the slice really uses, such as `2..<6`. Looping over it reads every element safely, and the index of the best element is already in the original array's numbering, so there's nothing to convert. The slice is never copied: this reads the original array's storage directly.

```swift
public enum SliceLargestIndex {
    public static func indexOfLargest(in window: ArraySlice<Int>) -> Int? {
        guard !window.isEmpty else { return nil }
        var best = window.startIndex
        for i in window.indices where window[i] > window[best] {
            best = i
        }
        return best
    }
}
```

Here k is the number of elements in the slice, which can be far fewer than the whole array has.

</Approach>

<Approach title="Find the value, then its index" time="O(k)" space="O(1)">

Two library calls do the same job in two passes. `max()` finds the largest value, and `firstIndex(of:)` finds where it first appears. Called on a slice, `firstIndex(of:)` returns the slice's own index, so again there's nothing to convert.

```swift
public static func indexOfLargest(in window: ArraySlice<Int>) -> Int? {
    guard let largest = window.max() else { return nil }
    return window.firstIndex(of: largest)
}
```

**The trap to avoid:** converting with `Array(window)` and searching that. The new array is renumbered from 0, so you'd get the position within the slice, `1` instead of `5` in the second example. If you do convert, add `window.startIndex` back before returning.

</Approach>
