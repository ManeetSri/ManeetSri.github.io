A greenhouse sensor logs one temperature reading a minute. The grower wants the longest run of consecutive readings that stayed **steady**: the highest and lowest reading in the run differ by at most `tolerance`. Return the length of the longest such run.

`LongestSteadyStretch.longest(_ readings: [Int], tolerance: Int) -> Int`

## Examples

| `readings` | `tolerance` | Output |
| --- | --- | --- |
| `[8, 2, 4, 7]` | `4` | `2` |
| `[10, 1, 2, 4, 7, 2]` | `5` | `4` |
| `[4, 2, 2, 2, 4, 4, 2, 2]` | `0` | `3` |
| `[5]` | `0` | `1` |
| `[]` | `3` | `0` |

In the second example, the run `[2, 4, 7, 2]` has highest 7 and lowest 2, a difference of exactly 5. Adding the 1 before it would make the difference 6.

## Constraints

- `0 ≤ readings.count ≤ 200,000`, readings between −10⁹ and 10⁹, and `0 ≤ tolerance ≤ 2 × 10⁹`.
- The tests include 200,000 readings, so checking every run, or rescanning a run to find its highest and lowest reading, is too slow.

<Hints>
<Hint>
If a run is steady, every shorter run inside it is steady too. That's the property that lets one pass with two moving ends find the longest one: extend the right end, and move the left end forward only while the run is too wide.
</Hint>
<Hint>
The hard part is knowing the run's highest and lowest reading as both ends move. You need the maximum and the minimum of a window that slides, and grows and shrinks.
</Hint>
<Hint>
Keep two deques of indexes: one with decreasing readings (its front is the window's maximum) and one with increasing readings (its front is the minimum). When a reading arrives, pop from the back of each deque anything it makes useless, then push it. While `readings[maxFront] − readings[minFront] > tolerance`, move the left end past whichever front is older, popping it off.
</Hint>
</Hints>

## Solutions

<Approach title="Check every run" time="O(n²)" space="O(1)">

For each start, extend to the right keeping a running highest and lowest, and stop once they differ by more than the tolerance. It's correct and it's what the tests compare against on small inputs, but 200,000 equal readings make it 2 × 10¹⁰ steps.

</Approach>

<Approach title="A variable window with two monotonic deques" time="O(n)" space="O(n)">

```swift
public enum LongestSteadyStretch {
    public static func longest(_ readings: [Int], tolerance: Int) -> Int {
        var highs: [Int] = [], highHead = 0      // indexes, readings decreasing from highHead on
        var lows: [Int] = [], lowHead = 0        // indexes, readings increasing from lowHead on
        var left = 0
        var best = 0
        for right in readings.indices {
            while highs.count > highHead && readings[highs[highs.count - 1]] <= readings[right] { highs.removeLast() }
            highs.append(right)
            while lows.count > lowHead && readings[lows[lows.count - 1]] >= readings[right] { lows.removeLast() }
            lows.append(right)
            while readings[highs[highHead]] - readings[lows[lowHead]] > tolerance {
                left += 1                           // shrink until the window is steady again
                if highs[highHead] < left { highHead += 1 }
                if lows[lowHead] < left { lowHead += 1 }
            }
            best = max(best, right - left + 1)
        }
        return best
    }
}
```

The arrays with head indexes act as deques: pushes and pops at the back are O(1), and the front only ever moves forward, so `removeFirst()` (O(n)) is never needed. Every index is pushed and popped at most once per deque, and `left` only moves forward, so the whole pass is O(n). Recording `best` after the shrinking loop is the "longest window" form of the template: the window is valid at that point.

</Approach>
