A film crew has `workers` people and there are `jobs` jobs on set today, both numbered from 0. `canDo[w]` lists the jobs worker w is qualified for. Each worker can take at most one job, and each job needs at most one worker. Give as many workers a job as possible, and return, for each worker, the job they get or `-1` for none.

`CrewJobMatching.assign(workers: Int, jobs: Int, canDo: [[Int]]) -> [Int]`

When several best assignments exist, return any of them: the tests check that every assignment is allowed, that no job is given twice, and that the number of workers with a job is the largest possible.

## Examples

| `workers`, `jobs` | `canDo` | Returns |
| --- | --- | --- |
| `2`, `2` | `[[0, 1], [0]]` | `[1, 0]` |
| `3`, `2` | `[[0], [0, 1], [1]]` | 2 workers placed, e.g. `[0, 1, -1]` or `[0, -1, 1]` |
| `5`, `5` | `[[0, 1], [1, 2], [2, 3], [3, 4], [0]]` | `[1, 2, 3, 4, 0]` |
| `3`, `3` | `[[], [], []]` | `[-1, -1, -1]` |

In the first example, giving worker 0 job 0 (the first on their list) would leave worker 1 with nothing. In the third, worker 4 can only do job 0, so everyone else has to take their second choice.

## Constraints

- `1 ≤ workers, jobs ≤ 500`, with up to 4,000 qualifications in total. A worker's list may repeat a job.
- Handing each worker the first free job on their list isn't always best, as the first example shows.
- The recursion in Kuhn's algorithm is at most one call per worker deep, and the tests keep it under 400.

<Hints>
<Hint>
Workers and jobs form a bipartite graph, and you want a maximum matching. When a worker's jobs are all taken, the worker can still get one if a current holder can move to another job, possibly by bumping someone else in turn.
</Hint>
<Hint>
That chain of moves is an augmenting path. Search for it with DFS: `findJob(for: w)` tries each of w's jobs; a job works if it's free, or if `findJob(for: holder)` succeeds for its current holder. If it works, give the job to w.
</Hint>
<Hint>
Mark each job as seen when you try it within one worker's search, so the search can't loop. Stamping `seen[job]` with the worker's number saves clearing an array for every worker.
</Hint>
</Hints>

## Solutions

<Approach title="Every possible assignment" time="exponential" space="O(workers)">

For each worker in turn, try every free job on their list and also "no job", and keep the best total. It's a handy checker for a handful of workers and hopeless beyond that.

</Approach>

<Approach title="Kuhn's algorithm" time="O(V · E)" space="O(V + E)">

One augmenting-path search per worker. A matching with no augmenting path left is maximum, which is Berge's theorem from the lesson.

```swift
public enum CrewJobMatching {
    public static func assign(workers: Int, jobs: Int, canDo: [[Int]]) -> [Int] {
        var workerOfJob = [Int](repeating: -1, count: jobs)
        var seen = [Int](repeating: -1, count: jobs)

        func findJob(for worker: Int, round: Int) -> Bool {
            for job in canDo[worker] where seen[job] != round {
                seen[job] = round
                if workerOfJob[job] == -1 || findJob(for: workerOfJob[job], round: round) {
                    workerOfJob[job] = worker              // flip this edge of the augmenting path
                    return true
                }
            }
            return false
        }

        for worker in 0..<workers {
            _ = findJob(for: worker, round: worker)
        }

        var jobOfWorker = [Int](repeating: -1, count: workers)
        for job in 0..<jobs where workerOfJob[job] != -1 {
            jobOfWorker[workerOfJob[job]] = job
        }
        return jobOfWorker
    }
}
```

A worker whose search fails in their own round can't gain a job later either, so one pass over the workers is enough.

</Approach>

<Approach title="Max flow" time="O(V · E²) with Edmonds–Karp" space="O(V + E)">

Add a source joined to every worker and a sink joined from every job, and give every edge capacity 1, including each worker → job edge. The maximum flow equals the maximum matching, and the worker → job edges carrying flow are the assignment. Each augmenting path in the flow network is exactly an augmenting path of the matching, so this does the same work as Kuhn's algorithm with more bookkeeping. Hopcroft–Karp finds many shortest augmenting paths per round and runs in O(E √V), which matters for much larger graphs than these.

</Approach>
