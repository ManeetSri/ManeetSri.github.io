A map app knows where the cafés are, as (x, y) positions relative to you at (0, 0). Return the indexes of the `k` cafés closest to you, measured in a straight line, in any order. When several cafés are the same distance away and there's only room for some of them, any of them may be chosen.

`NearestCafes.nearest(_ cafes: [(x: Int, y: Int)], count k: Int) -> [Int]`

You only need the k nearest as a group, not in order. Aim for O(n) on average.

## Examples

| `cafes` | `k` | Returns |
| --- | --- | --- |
| `[(3, 4), (-1, 1), (6, -2), (0, -2)]` | `1` | `[1]` |
| `[(3, 4), (-1, 1), (6, -2), (0, -2)]` | `2` | `[1, 3]`, in either order |
| `[(3, 4), (-1, 1), (6, -2), (0, -2)]` | `3` | `[0, 1, 3]`, in any order |
| `[(2, 0), (0, 2), (1, 0), (-2, 0)]` | `2` | `2` and any one of `0`, `1`, `3` |
| `[(5, 5)]` | `1` | `[0]` |

In the first map the squared distances are 25, 2, 40 and 4. In the fourth, café 2 is 1 away, and three cafés tie at 2 away for the remaining place.

## Constraints

- `1 ≤ k ≤ cafes.count ≤ 100,000`
- `-10,000 ≤ x, y ≤ 10,000`
- Many cafés can be exactly the same distance away: the tests include 100,000 cafés that all are.

<Hints>
<Hint>
Compare squared distances, `x * x + y * y`. They put the cafés in the same order as the real distances, with no square roots and no floating-point rounding. With these limits the largest is 200,000,000, which fits in an `Int`.
</Hint>
<Hint>
Sorting the indexes by distance and taking the first k works in O(n log n). To do better, use quickselect on an array of indexes: partition it around a pivot distance, and keep partitioning only the side that contains position k.
</Hint>
<Hint>
Partition three ways (nearer, same distance, further) around a random pivot. Once position k falls inside the pivot's block, or at either edge of it, the first k indexes are an answer. Two-way partitioning on 100,000 equal distances is quadratic.
</Hint>
</Hints>

## Solutions

<Approach title="Sort the indexes by distance" time="O(n log n)" space="O(n)">

Clear and quick to write. It orders all n cafés when only the boundary between the k nearest and the rest matters.

```swift
public static func nearest(_ cafes: [(x: Int, y: Int)], count k: Int) -> [Int] {
    let distance = cafes.map { $0.x * $0.x + $0.y * $0.y }
    let order = cafes.indices.sorted { distance[$0] < distance[$1] }
    return Array(order[..<k])
}
```

</Approach>

<Approach title="Quickselect on indexes" time="O(n) expected" space="O(n)">

After a three-way partition, everything before `less` is nearer than the pivot, `less..<greater` is the same distance, and everything from `greater` on is further. If k is below `less`, the cut is among the nearer cafés; if above `greater`, among the further ones. Otherwise the first k indexes are the nearer cafés plus some of the tied ones, which is a correct answer.

```swift
public enum NearestCafes {
    public static func nearest(_ cafes: [(x: Int, y: Int)], count k: Int) -> [Int] {
        let distance = cafes.map { $0.x * $0.x + $0.y * $0.y }
        var order = Array(cafes.indices)
        var low = 0
        var high = order.count
        while low < high {
            let pivot = distance[order[Int.random(in: low..<high)]]
            var less = low                               // low..<less: nearer than the pivot
            var scan = low                               // less..<scan: the same distance
            var greater = high                           // greater..<high: further away
            while scan < greater {
                let d = distance[order[scan]]
                if d < pivot {
                    order.swapAt(less, scan)
                    less += 1
                    scan += 1
                } else if d > pivot {
                    greater -= 1
                    order.swapAt(scan, greater)
                } else {
                    scan += 1
                }
            }
            if k < less {
                high = less                              // the cut is among the nearer cafés
            } else if k > greater {
                low = greater                            // the cut is among the further cafés
            } else {
                break                                    // order[..<k] is k nearest cafés
            }
        }
        return Array(order[..<k])
    }
}
```

A heap of size k is a third good answer, O(n log k), and it works on a stream of cafés too. You'll build heaps in Part V.

</Approach>
