A path in a binary tree is a sequence of nodes joined by edges, using no node twice and at least one node. It can start and end anywhere. Return the largest sum of values along any path, or `nil` for the empty tree.

`RichestTreePath.maximumPathSum(_ root: TreeNode?) -> Int?`

`TreeNode` comes from DSAKit. Trees are written in level order, with `nil` for a missing child, the way `TreeNode.make` takes them.

## Examples

| `root` | Output |
| --- | --- |
| `[-8, 4, 12, nil, nil, 6, 9]` | `27` |
| `[1, 2, 3]` | `6` |
| `[2, -1]` | `2` |
| `[-5, -2, -7]` | `-2` |
| `[-3]` | `-3` |
| `[]` | `nil` |

In the first tree, the best path is 6 → 12 → 9, which bends at 12 and leaves out the root: adding −8 and 4 would only lower it. When every value is negative, the best path is the single largest value.

## Constraints

- The tree has at most 150,000 nodes and is at most 50 levels deep.
- `-1,000 ≤ value ≤ 1,000`.
- Aim for O(n).

<Hints>
<Hint>
Every path has one highest node, where it bends. The best path bending at a node takes the node's value, plus the best that each side can add, but a side only joins if it adds something positive.
</Hint>
<Hint>
A parent can only extend a path that goes straight down one side. So let each call return its gain, `value + max(0, left gain, right gain)`, and record `value + max(0, left gain) + max(0, right gain)` in a variable outside the recursion.
</Hint>
<Hint>
Don't start the best at 0: with all values negative, no path reaches 0. Start it at the root's value. And return 0, not `Int.min`, for an empty subtree: adding `Int.min` to a negative value overflows.
</Hint>
</Hints>

## Solutions

<Approach title="Brute force: walk out from every node" time="O(n²)" space="O(n)">

Record every node's parent, so the tree can be walked in any direction. Then from each node, explore every path outwards (to the left child, the right child and the parent, never straight back), tracking the best running total. It's far too slow for big trees, but it shares no ideas with the fast version, which makes it an excellent test.

```swift
public static func maximumPathSum(_ root: TreeNode?) -> Int? {
    guard let root else { return nil }
    var all = [root]
    var parent: [ObjectIdentifier: TreeNode] = [:]
    var index = 0
    while index < all.count {
        let node = all[index]
        index += 1
        for child in [node.left, node.right].compactMap({ $0 }) {
            parent[ObjectIdentifier(child)] = node
            all.append(child)
        }
    }
    var best = Int.min
    for start in all {
        var pending: [(node: TreeNode, from: TreeNode?, sum: Int)] = [(start, nil, start.value)]
        while let (node, from, sum) = pending.popLast() {
            best = max(best, sum)
            for neighbour in [node.left, node.right, parent[ObjectIdentifier(node)]] {
                if let neighbour, neighbour !== from {
                    pending.append((neighbour, node, sum + neighbour.value))
                }
            }
        }
    }
    return best
}
```

</Approach>

<Approach title="Return the gain, record the bend" time="O(n)" space="O(h)">

The same shape as the diameter: each call returns what a parent can extend and records the answer on the side. `max(0, …)` leaves off any branch that would lower the sum.

```swift
import DSAKit

public enum RichestTreePath {
    public static func maximumPathSum(_ root: TreeNode?) -> Int? {
        guard let root else { return nil }
        var best = root.value                        // any single node is a path
        func gain(_ node: TreeNode?) -> Int {
            guard let node else { return 0 }
            let left = max(0, gain(node.left))
            let right = max(0, gain(node.right))
            best = max(best, node.value + left + right)
            return node.value + max(left, right)
        }
        _ = gain(root)
        return best
    }
}
```

</Approach>
