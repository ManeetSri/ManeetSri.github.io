A drone survey marks circular patches of a field that its sprayers cover. The patches overlap in complicated ways, so instead of working out the exact covered area, estimate it by **Monte Carlo sampling**, and report the estimate with its **standard error**, so whoever reads it knows how far to trust it.

`CircleCoverEstimate.estimate(circles: [[Double]], samples: Int, using generator: inout some RandomNumberGenerator) -> (area: Double, standardError: Double)`

Each circle is `[x, y, r]`: its centre and radius. Follow these steps:

1. Find the bounding box of all the circles: from the smallest `x - r` to the largest `x + r`, and from the smallest `y - r` to the largest `y + r`. Call its area B.
2. Draw `samples` points uniformly in the box, each as `Double.random(in: minX..<maxX, using: &generator)` and then the same for y. A point is covered if it's inside or on at least one circle.
3. With h covered points out of N, let p = h / N. The estimate is B · p, and its standard error is B · √(p(1 − p) / N).

If there are no circles, or `samples` is 0, return `(0, 0)`.

## Examples

Estimates are random, so each example shows what you should expect rather than an exact number.

| `circles` | `samples` | Output |
| --- | --- | --- |
| `[[0, 0, 1]]` | `200_000` | area about 3.14 (π), standard error about 0.0037 |
| `[[0, 0, 1], [1, 0, 1]]` | `200_000` | area about 5.055, standard error about 0.0049 |
| `[[0, 0, 2], [0.5, 0, 0.5]]` | `100_000` | area about 12.57 (4π: the small circle is inside the big one) |
| `[]` | `1_000` | `(0.0, 0.0)` |

For the unit circle, the box is 2 × 2, so B = 4 and the true p is π / 4 ≈ 0.785. The standard error is 4 · √(0.785 · 0.215 / 200,000) ≈ 0.0037: the estimate will usually be within about 0.004 of π, and almost never more than 0.02 away. For the two overlapping circles, the exact union is 2π minus the lens they share, 2π − (2π/3 − √3/2) ≈ 5.055.

## Constraints

- `0 ≤ circles.count ≤ 50`, and every radius is positive. Coordinates and radii are at most 1,000 in size.
- `0 ≤ samples ≤ 1,000,000`.
- O(samples × circles) time. Draw every random number from `generator`.
- The tests check that the true area is within five standard errors of your estimate, that your standard error matches the theory to within 10%, and that quadrupling the samples halves it. With a seeded generator, the same call must give the same result every time.

<Hints>
<Hint>
Sampling the bounding box instead of some fixed square keeps p as large as possible, which keeps the relative error small. Compute the four box edges in one pass over the circles.
</Hint>
<Hint>
Test coverage with squared distances, `dx * dx + dy * dy <= r * r`, so there's no square root per point, and stop checking circles as soon as one covers the point.
</Hint>
<Hint>
Each sample is a coin that comes up "covered" with probability p, so the count of hits has variance N · p(1 − p), and p̂ = h / N has variance p(1 − p) / N. Scaling by B gives the standard error. Use your estimate p̂ in place of the unknown p: that's what the formula in the statement does.
</Hint>
</Hints>

## Solutions

<Approach title="Sample the bounding box" time="O(samples × circles)" space="O(1)">

```swift
public enum CircleCoverEstimate {
    public static func estimate(circles: [[Double]], samples: Int, using generator: inout some RandomNumberGenerator) -> (area: Double, standardError: Double) {
        guard !circles.isEmpty, samples > 0 else { return (0, 0) }
        var minX = Double.infinity, maxX = -Double.infinity
        var minY = Double.infinity, maxY = -Double.infinity
        for circle in circles {
            minX = min(minX, circle[0] - circle[2]); maxX = max(maxX, circle[0] + circle[2])
            minY = min(minY, circle[1] - circle[2]); maxY = max(maxY, circle[1] + circle[2])
        }
        var hits = 0
        for _ in 0..<samples {
            let x = Double.random(in: minX..<maxX, using: &generator)
            let y = Double.random(in: minY..<maxY, using: &generator)
            if circles.contains(where: { c in
                let dx = x - c[0], dy = y - c[1]
                return dx * dx + dy * dy <= c[2] * c[2]
            }) {
                hits += 1
            }
        }
        let box = (maxX - minX) * (maxY - minY)
        let p = Double(hits) / Double(samples)
        return (box * p, box * (p * (1 - p) / Double(samples)).squareRoot())
    }
}
```

The error shrinks like 1/√N: four times the samples for half the error, a hundred times for one more correct digit. That's slow, but it doesn't care how complicated the shape is, which is the point. The standard error is the honest way to report the result: "5.054 ± 0.005" says far more than "5.054".

</Approach>

<Approach title="Exact geometry" time="depends on the shapes" space="O(1)">

For one or two circles there are formulas: πr², and for two, the sum minus the lens they share. For many circles the union's boundary is a chain of arcs, which can be computed exactly (Green's theorem over the arcs on the boundary) but takes careful geometry. Monte Carlo gives a trustworthy estimate in a dozen lines, and it's how the tests' expected values were checked.

</Approach>
