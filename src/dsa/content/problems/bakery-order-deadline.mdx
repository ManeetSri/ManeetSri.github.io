A bakery has a row of ovens. Oven `i` takes `bakeTimes[i]` minutes to bake one batch, and it starts the next batch the moment one comes out. Every oven starts at minute 0. A café has ordered `batches` batches. Return the earliest whole minute by which at least that many batches are finished, counting all the ovens together.

`BakeryOrderDeadline.earliestMinute(bakeTimes: [Int], batches: Int) -> Int`

## Examples

| `bakeTimes` | `batches` | Output |
| --- | --- | --- |
| `[3, 5]` | `4` | `9` |
| `[2]` | `5` | `10` |
| `[4, 4, 4]` | `3` | `4` |
| `[7, 2, 9]` | `10` | `14` |

In the first example, by minute 9 the 3-minute oven has finished three batches (at 3, 6 and 9) and the 5-minute oven one (at 5): four in all. At minute 8 there are only three. In the last, by minute 14 the ovens have finished 2, 7 and 1 batches.

## Constraints

- `1 ≤ bakeTimes.count ≤ 100,000`
- `1 ≤ bakeTimes[i] ≤ 1,000,000`
- `1 ≤ batches ≤ 1,000,000,000,000` (10¹²)
- The answer always fits in an `Int`. The tests use 100,000 ovens and an order of 10¹² batches, so handing out batches one at a time is far too slow.

<Hints>
<Hint>
Simulating the ovens batch by batch, perhaps with a heap of "next finish times", is correct. How many steps would 10¹² batches take?
</Hint>
<Hint>
Turn the question round. Given a minute `t`, can you tell quickly whether the order is done by then? Oven `i` has finished `t / bakeTimes[i]` batches (integer division). And if minute `t` is enough, is minute `t + 1`?
</Hint>
<Hint>
"Enough by minute t" goes false, false, …, true, true, so binary search for the first true. The fastest oven alone finishes the order by `fastest × batches`, which makes a safe upper bound. While counting, stop as soon as the total reaches `batches`, so the sum can't overflow.
</Hint>
</Hints>

## Solutions

<Approach title="Simulate with a heap" time="O(batches · log n)" space="O(n)">

Keep a min-heap of each oven's next finish time. Pop the earliest, count a batch, and push that oven's following finish time, until the order is complete. It mirrors the story exactly, which is what makes it tempting, but 10¹² pops won't finish in your lifetime.

</Approach>

<Approach title="Binary search on the answer" time="O(n log(fastest · batches))" space="O(1)">

The answer is a number in a known range, and checking a guess costs one pass over the ovens. That's the shape from [The monotonic predicate idea](/dsa/learn/bsa-idea).

```swift
public enum BakeryOrderDeadline {
    public static func earliestMinute(bakeTimes: [Int], batches: Int) -> Int {
        guard let fastest = bakeTimes.min() else { return 0 }

        func enough(_ minute: Int) -> Bool {
            var done = 0
            for time in bakeTimes {
                done += minute / time
                if done >= batches { return true }
            }
            return false
        }

        var low = 1
        var high = fastest * batches          // the fastest oven alone is enough by then
        while low < high {
            let mid = low + (high - low) / 2
            if enough(mid) {
                high = mid
            } else {
                low = mid + 1
            }
        }
        return low
    }
}
```

The range has up to 10¹⁸ values, so the search takes about 60 checks of 100,000 ovens each: 6 million steps.

The early `return true` matters if you pick a looser upper bound. With `high` set to the *slowest* oven times the order, a guess can be 5 × 10¹⁷, and 100,000 one-minute ovens would then add up to 5 × 10²², far past `Int.max`. Swift stops the program on overflow rather than wrapping, as [Overflow traps and overflow operators](/dsa/learn/swift-overflow) showed.

</Approach>
