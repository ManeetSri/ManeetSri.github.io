A network of n computers, numbered 0 to n − 1, was wired as a tree: every computer could reach every other, with no loops. Then one extra cable was added. You're given all n cables, each `[a, b]`, in the order they were laid. Return the cable to remove so that the rest form a tree again. If several cables would work, return the one that comes **last** in the list. Return it exactly as given.

`ExtraCable.find(_ cables: [[Int]]) -> [Int]`

## Examples

| `cables` | Returns | Why |
| --- | --- | --- |
| `[[0, 1], [1, 2], [2, 0]]` | `[2, 0]` | all three are on the loop; [2, 0] is last |
| `[[0, 1], [1, 2], [2, 3], [3, 1], [0, 4]]` | `[3, 1]` | the loop is 1–2–3; [0, 4] isn't on it |
| `[[1, 0], [2, 0], [3, 1], [2, 3]]` | `[2, 3]` | the loop uses all four cables |
| `[[0, 1], [1, 0]]` | `[1, 0]` | two cables between the same pair form a loop |

## Constraints

- `2 ≤ n ≤ 100,000`, where n is `cables.count`.
- Each cable joins two different computers in `0..<n`. The cables are a tree plus exactly one extra cable, which may duplicate an existing one.
- The tests include 100,000 computers wired in one big loop.

<Hints>
<Hint>
A tree plus one cable has exactly one loop, and removing any cable on the loop leaves a tree. So the question is: which cable on the loop comes last?
</Hint>
<Hint>
Lay the cables in order. Every cable before the loop is complete joins two computers that couldn't reach each other yet. The cable that completes the loop is the first one whose ends could already reach each other.
</Hint>
<Hint>
Union-find answers "could these two already reach each other?" with `union` returning false.
</Hint>
</Hints>

## Solutions

<Approach title="Try removing each cable" time="O(n²)" space="O(n)">

From the last cable backwards, remove it and check with a BFS whether the rest form a tree. The first that works is the answer. Correct, but each check is O(n), and there can be n of them.

</Approach>

<Approach title="The first union that fails" time="O(n α(n))" space="O(n)">

Every cable before the loop closes joins two separate groups, so it can't be on a loop. The first cable whose ends are already connected closes the one loop, and all the loop's other cables came before it, so it's the latest one on the loop.

```swift
import DSAKit

public enum ExtraCable {
    public static func find(_ cables: [[Int]]) -> [Int] {
        var network = UnionFind(count: cables.count)
        for cable in cables where !network.union(cable[0], cable[1]) {
            return cable
        }
        return []
    }
}
```

The final `return []` never runs for valid input: the extra cable always makes some union fail.

</Approach>
