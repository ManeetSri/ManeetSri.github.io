A worker claims that it multiplied two n × n matrices, A and B, and got C. Recomputing A × B takes O(n³). Check the claim in O(n²) per trial with **Freivalds' algorithm**, and when the claim is false, return the proof: a vector that exposes it.

`FreivaldsProductCheck.findWitness(_ a: [[Int]], _ b: [[Int]], _ c: [[Int]], trials: Int, using generator: inout some RandomNumberGenerator) -> [Int]?`

Each trial draws a vector r of n entries, each 0 or 1 with equal chance, from `generator`, and compares A(Br) with Cr. If they differ, r is a **witness**: return it at once. If all `trials` trials agree, return `nil`, meaning "probably correct".

## Examples

With `a = [[2, 0, 1], [1, 3, 0], [0, 1, 4]]` and `b = [[1, 2, 0], [0, 1, 1], [3, 0, 2]]`, the true product is `[[5, 4, 2], [1, 5, 3], [12, 1, 9]]`.

| `c` | `trials` | Output |
| --- | --- | --- |
| the true product | `20` | `nil`, always |
| the true product with `c[1][2] = 4` | `20` | a witness, such as `[0, 1, 1]` (almost surely) |
| the true product with `c[1][2] = 4` | `1` | a witness half the time, `nil` the other half |
| anything | `0` | `nil` |

With the wrong entry in column 2, a trial exposes it exactly when r has a 1 in position 2, so each trial catches it with probability 1/2, and twenty trials all miss it with probability 2⁻²⁰, about one in a million. For r = `[0, 1, 1]`: Br = `[2, 2, 2]`, A(Br) = `[6, 8, 10]`, but Cr = `[6, 9, 10]` with the wrong C.

## Constraints

- `1 ≤ n ≤ 300`, the three matrices are n × n, and every entry is between −1,000 and 1,000 in A and B and between −10⁹ and 10⁹ in C.
- `0 ≤ trials ≤ 60`.
- Each trial must be O(n²): three matrix-vector products. Never compute A × B.
- A returned vector must really be a witness: n entries, each 0 or 1, with A(Br) ≠ Cr. The tests check that every vector you return proves the claim false, and that single trials catch a one-entry error about half the time, so the vector must be random, not fixed.

<Hints>
<Hint>
Matrix-vector products are O(n²): entry i of Mv is the sum of `M[i][j] * v[j]` over j. Compute `Br` first, then `A` times that, and separately `Cr`. Associativity is the whole trick: A(Br) = (AB)r, without ever forming AB.
</Hint>
<Hint>
If AB = C, every trial agrees, so a correct C is never rejected. If AB ≠ C, let D = AB − C, with a nonzero entry in some column j. Pair each vector with the one that differs only in position j: their products Dr differ by column j of D, which isn't zero, so at most one of each pair hides the error. At least half of all vectors are witnesses.
</Hint>
<Hint>
Draw each entry with `Int.random(in: 0...1, using: &generator)` or `Bool.random(using: &generator)`. Create the vector inside the trial loop, so each trial is independent: repeating the same vector would make extra trials worthless.
</Hint>
</Hints>

## Solutions

<Approach title="Multiply and compare" time="O(n³)" space="O(n²)">

Compute A × B with three nested loops and compare it with C entry by entry. It's always right, and at n = 300 it's 27 million multiplications, against about 270,000 per Freivalds trial. It also doesn't produce a witness vector.

</Approach>

<Approach title="Freivalds' random vectors" time="O(trials · n²)" space="O(n)">

```swift
public enum FreivaldsProductCheck {
    private static func times(_ m: [[Int]], _ v: [Int]) -> [Int] {
        m.map { row in
            var total = 0
            for (x, y) in zip(row, v) { total += x * y }
            return total
        }
    }

    public static func findWitness(_ a: [[Int]], _ b: [[Int]], _ c: [[Int]], trials: Int, using generator: inout some RandomNumberGenerator) -> [Int]? {
        let n = a.count
        for _ in 0..<max(0, trials) {
            let r = (0..<n).map { _ in Int.random(in: 0...1, using: &generator) }
            if times(a, times(b, r)) != times(c, r) {
                return r                   // a proof that A × B ≠ C
            }
        }
        return nil
    }
}
```

The error is one-sided: a witness is certain, while `nil` can be wrong, with probability at most 2^(−trials). Repeating independent trials is what shrinks that chance, which is why each trial draws a fresh vector.

</Approach>
