A `Container` protocol describes anything you can add items to and read them back from, by position. Its item type is an associated type, so each conforming type picks its own. Build two shelves that conform, then write generic functions that work with any container at all.

`AssociatedItemContainers.Shelf`, `DistinctShelf`, and the generic functions `items(of:)`, `lastItem(of:)`, `occurrences(of:in:)`, `holdSameItems(_:_:)` and `addAll(_:to:)`

The protocol is in the starter code:

```swift
public protocol Container {
    associatedtype Item
    mutating func add(_ item: Item)
    var count: Int { get }
    func item(at index: Int) -> Item?
}
```

`item(at:)` returns the item at that position, where 0 is the first one kept, or `nil` for a position that doesn't exist (including negative ones).

- **`Shelf<Element>`** keeps every item, in the order added.
- **`DistinctShelf<Element: Hashable>`** keeps each distinct item once, in the order first added. Adding an item it already holds does nothing.
- **`items(of:)`** returns every item, in order, and **`lastItem(of:)`** the last one, or `nil` when the container is empty.
- **`occurrences(of:in:)`** counts the items equal to a target. It needs `C.Item: Equatable`.
- **`holdSameItems(_:_:)`** is `true` when two containers, possibly of different types, hold equal items in the same order.
- **`addAll(_:to:)`** offers each item in an array to an `inout` container, in order, so the container's own rules decide what it keeps.

## Examples

| Code | Result |
| --- | --- |
| a `Shelf<String>` after adding `"tea"`, `"cake"`, `"tea"` | `count` is 3; `item(at: 2)` is `"tea"`; `item(at: 3)` is `nil` |
| a `DistinctShelf<Int>` after adding 3, 1, 3, 4, 1, 5 | `items(of:)` gives `[3, 1, 4, 5]` |
| `occurrences(of: "x", in: shelf)` for a shelf of `"x"`, `"y"`, `"x"`, `"x"` | `3` |
| `holdSameItems(shelf, distinct)` for a shelf of 1, 2, 3 and a distinct shelf given 1, 2, 2, 3, 1 | `true` |
| `lastItem(of: Shelf<Int>())` | `nil` |

## Constraints

- Up to 100,000 items.
- The tests also define a container of their own whose `Item` is `Character`, so the generic functions may only use `add`, `count` and `item(at:)`.

<Hints>
<Hint>
Inside each shelf, keep a `private var items: [Element] = []`. You never write `Item` anywhere: Swift works out that `Item` is `Element` from the parameter of your `add` method. `items.indices.contains(index)` checks a position safely.
</Hint>
<Hint>
For `DistinctShelf`, keep a `Set<Element>` beside the array. `set.insert(item).inserted` tells you whether the item was new, so you know whether to append it.
</Hint>
<Hint>
In the generic functions, `C.Item` names the container's item type. Loop over `0..<container.count` and read each `container.item(at:)`. For two containers, the constraints `where C1.Item == C2.Item, C1.Item: Equatable` let you compare their items with `!=`.
</Hint>
</Hints>

## Solutions

<Approach title="Two conformances and generic functions over C.Item" time="O(1) per add, O(n) per generic function" space="O(n)">

Each shelf chooses its item type implicitly, through its methods. The generic functions don't know or care which container they get; they only use the three requirements, and talk about the item type as `C.Item`. The `where` clause on `holdSameItems` lets the two containers be different types, as long as they hold the same kind of item.

```swift
public enum AssociatedItemContainers {
    public protocol Container {
        associatedtype Item
        mutating func add(_ item: Item)
        var count: Int { get }
        func item(at index: Int) -> Item?
    }

    public struct Shelf<Element>: Container {
        private var items: [Element] = []

        public init() {}

        public mutating func add(_ item: Element) {
            items.append(item)
        }

        public var count: Int {
            items.count
        }

        public func item(at index: Int) -> Element? {
            items.indices.contains(index) ? items[index] : nil
        }
    }

    public struct DistinctShelf<Element: Hashable>: Container {
        private var items: [Element] = []
        private var held: Set<Element> = []

        public init() {}

        public mutating func add(_ item: Element) {
            if held.insert(item).inserted {
                items.append(item)
            }
        }

        public var count: Int {
            items.count
        }

        public func item(at index: Int) -> Element? {
            items.indices.contains(index) ? items[index] : nil
        }
    }

    public static func items<C: Container>(of container: C) -> [C.Item] {
        var result: [C.Item] = []
        for index in 0..<container.count {
            if let item = container.item(at: index) {
                result.append(item)
            }
        }
        return result
    }

    public static func lastItem<C: Container>(of container: C) -> C.Item? {
        container.item(at: container.count - 1)
    }

    public static func occurrences<C: Container>(of target: C.Item, in container: C) -> Int
        where C.Item: Equatable {
        var found = 0
        for index in 0..<container.count where container.item(at: index) == target {
            found += 1
        }
        return found
    }

    public static func holdSameItems<C1: Container, C2: Container>(_ first: C1, _ second: C2) -> Bool
        where C1.Item == C2.Item, C1.Item: Equatable {
        guard first.count == second.count else {
            return false
        }
        for index in 0..<first.count where first.item(at: index) != second.item(at: index) {
            return false
        }
        return true
    }

    public static func addAll<C: Container>(_ items: [C.Item], to container: inout C) {
        for item in items {
            container.add(item)
        }
    }
}
```

`lastItem` works for an empty container too: `item(at: -1)` returns `nil` rather than crashing, which is one reason this protocol's `item(at:)` returns an optional.

</Approach>
