Before running a big selection job, a scheduler wants to know how much work randomised quickselect will do **on average**. Compute two exact expectations for finding the value of rank t among n distinct values: the expected number of comparisons, and the expected number of partitions.

`QuickselectComparisonForecast.expectedComparisons(count:targetRank:) -> Double` and `QuickselectComparisonForecast.expectedPartitions(count:targetRank:) -> Double`

The quickselect being forecast works on a range of the array that always contains the target. Each round picks a pivot uniformly at random from the current range and partitions the range around it, comparing **every other element of the range** with the pivot exactly once (the Lomuto partition). That's one partition, and range size − 1 comparisons. If the pivot is the target, it stops; otherwise it keeps the side that holds the target. A range of one element still counts as one partition, with 0 comparisons. Ranks count from 0, so `targetRank: 0` asks for the smallest value.

The expectation is over the pivot choices. Since the values are distinct, only their ranks matter, so the answers depend only on n and t.

## Examples

| Call | Output |
| --- | --- |
| `expectedComparisons(count: 3, targetRank: 1)` | `2.6666…` (8 / 3) |
| `expectedComparisons(count: 2, targetRank: 0)` | `1.0` |
| `expectedComparisons(count: 1, targetRank: 0)` | `0.0` |
| `expectedComparisons(count: 1000, targetRank: 0)` | about `1985.03` |
| `expectedComparisons(count: 1000, targetRank: 500)` | about `3336.33` |
| `expectedPartitions(count: 3, targetRank: 1)` | `2.0` |
| `expectedPartitions(count: 4, targetRank: 0)` | `2.0833…` (1 + 1/2 + 1/3 + 1/4) |

For three values looking for the middle one: the first partition makes 2 comparisons. With probability 1/3 the pivot is the middle value and the search stops. Otherwise the range keeps two values, the next partition makes 1 comparison, and either finds the target or leaves a range of one. So the comparisons are 2, 3 or 3, each with probability 1/3: 8 / 3 on average. The partitions number 1 when the first pivot is the target; otherwise 2 or 3, each with probability 1/2, depending on whether the second pivot is the target. That's 1/3 · 1 + 2/3 · 2.5 = 2.

## Constraints

- `1 ≤ count ≤ 1,000,000` and `0 ≤ targetRank < count`.
- Answers within a relative error of 10⁻⁹ pass.
- Both must be O(n). The tests ask about a million values, where summing over all pairs of values, O(n²), never finishes.

<Hints>
<Hint>
Use indicators. Two ranks a < b are compared exactly when one of them is the **first** pivot chosen from the span of ranks between `min(a, t)` and `max(b, t)`: until then both are still in the range, and any other first pivot from that span separates them or throws both away. Every rank in the span is equally likely to go first, so the probability is 2 / (span length). For partitions, rank j is a pivot exactly when it's the first chosen between j and t: probability 1 / (|j − t| + 1).
</Hint>
<Hint>
The partitions sum is already O(n). For comparisons, split the pairs by where they sit relative to t. If `b ≤ t`, the span is `t − a + 1`, and there are `t − a` choices of b for each a. If `a ≥ t`, the span is `b − t + 1`, with `b − t` choices of a for each b. Both become sums over a single distance d of `2d / (d + 1)`.
</Hint>
<Hint>
The remaining pairs straddle t: `a < t < b`, with span `b − a + 1`. Group them by d = b − a. For each d from 2 to n − 1, a ranges from `max(0, t − d + 1)` to `min(t − 1, n − 1 − d)`; add `2 · count / (d + 1)` when that range isn't empty. Three loops of length at most n.
</Hint>
</Hints>

## Solutions

<Approach title="Sum over every pair" time="O(n²)" space="O(1)">

Add `2 / (max(b, t) − min(a, t) + 1)` for every pair a < b. It's the formula from the lesson written straight down, and the tests use it on small inputs, but a million values means 5 × 10¹¹ pairs.

</Approach>

<Approach title="Group the pairs by distance" time="O(n)" space="O(1)">

```swift
public enum QuickselectComparisonForecast {
    public static func expectedComparisons(count n: Int, targetRank t: Int) -> Double {
        var total = 0.0
        // Both at or below t, or both at or above t: the span is set by the one further from t
        for d in stride(from: 1, through: t, by: 1) {
            total += 2.0 * Double(d) / Double(d + 1)
        }
        for d in stride(from: 1, through: n - 1 - t, by: 1) {
            total += 2.0 * Double(d) / Double(d + 1)
        }
        // One on each side of t: the span is the pair's own distance
        for d in stride(from: 2, through: n - 1, by: 1) {
            let low = max(0, t - d + 1), high = min(t - 1, n - 1 - d)
            if high >= low {
                total += 2.0 * Double(high - low + 1) / Double(d + 1)
            }
        }
        return total
    }

    public static func expectedPartitions(count n: Int, targetRank t: Int) -> Double {
        var total = 0.0
        for j in 0..<n {
            total += 1.0 / Double(abs(j - t) + 1)
        }
        return total
    }
}
```

Linearity of expectation does the heavy lifting: the expected total is the sum of each indicator's probability, however dependent the indicators are. For t = 0 the comparisons collapse to 2(n − Hₙ), about 2n, and for the median they approach 2n(1 + ln 2) ≈ 3.39n. The partitions come to H(t + 1) + H(n − t) − 1, about 2 ln n for the median: O(log n) rounds.

</Approach>

<Approach title="A closed form with harmonic numbers" time="O(n), or O(1) with a table" space="O(1)">

Summing the three groups exactly gives Knuth's formula: with k = t + 1, the expected comparisons are 2((n + 1)Hₙ − (n + 3 − k)H(n + 1 − k) − (k + 2)H(k) + n + 3), where H(m) is the mth harmonic number. Computing the harmonic numbers is O(n), or O(1) per query once they're tabulated.

</Approach>
