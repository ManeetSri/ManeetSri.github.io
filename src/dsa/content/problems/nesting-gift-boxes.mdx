A shop sells flat gift boxes in many sizes. Each box is given as `[side, side]`, the two sides of its base, in either order. A box fits inside another if, turned whichever way suits, **both** of its sides are strictly smaller than the other box's sides. Heights don't matter. Return the largest number of boxes you can nest, each one inside the next.

`NestingGiftBoxes.deepestNesting(_ boxes: [[Int]]) -> Int`

## Examples

| `boxes` | Output | Why |
| --- | --- | --- |
| `[[5, 4], [6, 4], [6, 7], [2, 3]]` | `3` | `[2, 3]` inside `[5, 4]` inside `[6, 7]` |
| `[[8, 3], [4, 9]]` | `2` | turn the first to `3 × 8`; it fits inside `4 × 9` |
| `[[3, 8], [9, 2], [4, 7]]` | `1` | each box is too long or too narrow for the others |
| `[[4, 4], [4, 5], [4, 6], [4, 7]]` | `1` | every box has a side of exactly 4 |
| `[]` | `0` | |

## Constraints

- `0 ≤ boxes.count ≤ 100,000`, and each box has exactly two sides.
- `1 ≤ side ≤ 1,000,000,000`
- Several boxes may have the same size.
- The tests use 100,000 boxes, so an O(n²) solution is too slow.

<Hints>
<Hint>
Turning first: if box a can be turned to fit inside box b at all, it fits when both are turned with their shorter side first. So write every box as (short, long), and forget about turning.
</Hint>
<Hint>
Now it's Russian doll envelopes. Sort by the shorter side, and the problem becomes a longest strictly increasing subsequence of the longer sides, except for boxes whose shorter sides are equal.
</Hint>
<Hint>
Break ties in the shorter side by sorting the longer side **descending**. Then a strictly increasing subsequence can take at most one box per shorter side. Finish with the O(n log n) LIS using a lower bound.
</Hint>
</Hints>

## Solutions

<Approach title="Sort, then the O(n²) chain DP" time="O(n²)" space="O(n)">

After turning each box short side first and sorting by the shorter side, run the longest-chain DP with a check that both sides are strictly smaller. It's correct for any ties, but 100,000 boxes is far too many.

```swift
public enum NestingGiftBoxes {
    public static func deepestNesting(_ boxes: [[Int]]) -> Int {
        let sorted = boxes.map { (short: min($0[0], $0[1]), long: max($0[0], $0[1])) }.sorted { $0.short < $1.short }
        var depth = Array(repeating: 1, count: sorted.count)
        for i in sorted.indices {
            for j in 0..<i where sorted[j].short < sorted[i].short && sorted[j].long < sorted[i].long {
                depth[i] = max(depth[i], depth[j] + 1)
            }
        }
        return depth.max() ?? 0
    }
}
```

</Approach>

<Approach title="Turn, sort with the tie trick, then patience sorting" time="O(n log n)" space="O(n)">

Sorting equal shorter sides by the longer side descending means that, within each group, the longer sides go down, so a strictly rising run can't use two boxes from one group. Every rising run of longer sides is then a real nesting, and every nesting appears as a rising run.

```swift
public enum NestingGiftBoxes {
    public static func deepestNesting(_ boxes: [[Int]]) -> Int {
        let turned = boxes.map { (short: min($0[0], $0[1]), long: max($0[0], $0[1])) }
        let longSides = turned
            .sorted { $0.short != $1.short ? $0.short < $1.short : $0.long > $1.long }
            .map(\.long)
        var tails: [Int] = []
        for side in longSides {
            var low = 0
            var high = tails.count
            while low < high {                          // the first tail >= side
                let mid = low + (high - low) / 2
                if tails[mid] >= side {
                    high = mid
                } else {
                    low = mid + 1
                }
            }
            if low == tails.count {
                tails.append(side)
            } else {
                tails[low] = side
            }
        }
        return tails.count
    }
}
```

Sorting ties by the longer side ascending is the classic slip: `[[4, 4], [4, 5], [4, 6], [4, 7]]` would then give 4 instead of 1.

</Approach>
