A charity is choosing which fundraising drives to run. Drive `i` needs `needs[i]` volunteers and raises `raises[i]`. A **plan** is any set of drives, including the empty set. Count the plans that need at most `volunteers` people in total **and** raise at least `goal` in total. Return the count modulo 1,000,000,007.

`CharityDrivePlans.count(volunteers: Int, goal: Int, needs: [Int], raises: [Int]) -> Int`

## Examples

| `volunteers` | `goal` | `needs` | `raises` | Output |
| --- | --- | --- | --- | --- |
| `5` | `3` | `[2, 2]` | `[2, 3]` | `2` |
| `6` | `4` | `[3, 3, 3]` | `[2, 2, 2]` | `3` |
| `3` | `0` | `[2, 2]` | `[0, 0]` | `3` |
| `10` | `50` | `[1, 1]` | `[20, 20]` | `0` |

In the first example, the second drive alone raises 3, and both drives together raise 5 with 4 volunteers. In the second, any two drives work, but all three need 9 volunteers. In the third, the goal is 0, so the empty plan and each single drive count, while both drives together need 4 volunteers. In the last, everything together raises only 40.

## Constraints

- `1 ≤ volunteers ≤ 100` and `0 ≤ goal ≤ 100`
- `1 ≤ needs.count ≤ 100`, and `raises.count == needs.count`
- `1 ≤ needs[i] ≤ 100` and `0 ≤ raises[i] ≤ 100`
- Answers are taken modulo 1,000,000,007. With 100 drives there are 2¹⁰⁰ plans.

<Hints>
<Hint>
Two dimensions: volunteers is a budget (at most), money is a target (at least). Raising the goal, or the goal plus 50, counts the same.
</Hint>
<Hint>
Clamp the money: keep columns 0 to `goal`, and send any total of `goal` or more to column `goal`. Let `ways[v][f]` count plans with at most `v` volunteers whose clamped money is `f`. The empty plan fits every budget, so `ways[v][0] = 1` for every `v`.
</Hint>
<Hint>
For each drive, loop `v` from `volunteers` down to its need and `f` from `goal` down to 0, and add `ways[v - need][f]` into `ways[v][min(goal, f + raise)]`. The answer is `ways[volunteers][goal]`.
</Hint>
</Hints>

## Solutions

<Approach title="Try every plan" time="O(2ⁿ · n)" space="O(n)">

A bitmask chooses the drives. Add up the volunteers and money and count the plans that qualify. Fine for 15 drives, not for 100.

</Approach>

<Approach title="Counting knapsack with a clamped dimension" time="O(n · volunteers · goal)" space="O(volunteers · goal)">

Each drive is a 0/1 item with two dimensions. Volunteers work like an ordinary capacity. Money only matters up to the goal, so clamp it, and column `goal` means "goal or more". Several money columns can land in the clamped one, so each update **pushes** from `f` into `min(goal, f + raise)` rather than pulling.

```swift
public enum CharityDrivePlans {
    public static func count(volunteers: Int, goal: Int, needs: [Int], raises: [Int]) -> Int {
        let mod = 1_000_000_007
        var ways = Array(repeating: Array(repeating: 0, count: goal + 1), count: volunteers + 1)
        for v in 0...volunteers {
            ways[v][0] = 1
        }
        for (need, raise) in zip(needs, raises) where need <= volunteers {
            for v in stride(from: volunteers, through: need, by: -1) {
                for f in stride(from: goal, through: 0, by: -1) {
                    let capped = min(goal, f + raise)
                    ways[v][capped] = (ways[v][capped] + ways[v - need][f]) % mod
                }
            }
        }
        return ways[volunteers][goal]
    }
}
```

Updating in place is safe because every read comes from row `v - need`, a smaller row that the downward outer loop hasn't reached yet in this drive's pass, so it still holds the counts without this drive. Starting `ways[v][0] = 1` in every row makes each row mean "at most `v` volunteers", so the answer is a single cell rather than a sum over rows.

</Approach>
