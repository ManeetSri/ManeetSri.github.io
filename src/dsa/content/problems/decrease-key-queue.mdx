A delivery app tracks the best known arrival time for each of its towns, numbered `0..<capacity`, and keeps revising them as faster routes turn up. Build the **indexed priority queue** it needs: a min-heap of town ids that can find any queued id instantly, so its key can be changed or the id removed in O(log n).

`DecreaseKeyQueue.IndexedQueue`, a struct with `init(capacity:)`, `count`, `isEmpty`, `contains(_:)`, `key(of:)`, `peek()`, `push(_:key:)`, `remove(_:)` and `popMin()`.

- `push(id, key: k)` queues `id` with key `k`, or, if it's already queued, **changes** its key to `k`, which may be smaller or larger than before.
- `remove(id)` takes `id` out of the queue, returning `true` if it was queued.
- `peek()` and `popMin()` return the queued `(id, key)` with the smallest key; between equal keys, the smaller id comes first. Both return `nil` when the queue is empty.
- `key(of: id)` is the queued key, or `nil` if `id` isn't queued.

`contains`, `key(of:)` and `peek` must be O(1); `push`, `remove` and `popMin` O(log n).

## Examples

| Code | Result |
| --- | --- |
| `IndexedQueue(capacity: 5)`; push ids 0, 1, 2, 3, 4 with keys 0, 7, 9, 14, 20 | `peek()` is `(0, 0)` |
| `popMin()` | `(0, 0)`; `contains(0)` is now `false` |
| `push(2, key: 5)`, then `push(4, key: 11)` | lowers town 2's key to 5 and town 4's to 11 |
| `popMin()` | `(2, 5)`: 2 overtook 1, whose key is 7 |
| `push(1, key: 30)` | raises 1's key; `peek()` is now `(4, 11)` |
| `remove(3)`, then `remove(3)` | `true`, then `false`; `count` is 2 |
| push ids 3 and 0, both with key 8, into an empty queue | `popMin()` gives `(0, 8)`: equal keys go by id |

## Constraints

- `1 ≤ capacity ≤ 200,000`, and every id passed in is in `0..<capacity`. Keys can be any `Int`.
- Up to 400,000 operations. The tests change keys 200,000 times in a queue of 50,000 ids, so searching the heap for an id is far too slow.
- It's a struct: copies must be independent (arrays inside give you that for free).

<Hints>
<Hint>
Keep three arrays: `heap`, the ids in heap order; `keys`, indexed by id; and `position`, where `position[id]` is the index of `id` in `heap`, or `-1` when it isn't queued. Compare heap entries by `(keys[id], id)`: Swift compares tuples left to right, which gives the tie-break for free.
</Hint>
<Hint>
Route **every** swap through one helper that swaps two heap entries and updates both ids' positions. Sift up and sift down are the usual loops, calling that helper. Then `contains` and `key(of:)` are just lookups.
</Hint>
<Hint>
Changing a key: store the new key, then sift the id up **and** down from its position; only one of them will move it. Removing: swap the id with the last heap entry, drop the last entry, mark the id's position `-1`, and sift the entry that moved into the hole up and down. `popMin` is "remove whatever is at index 0".
</Hint>
</Hints>

## Solutions

<Approach title="Search the heap for the id" time="O(n) to change a key" space="O(n)">

A plain heap of `(key, id)` pairs can do everything except find an id: changing or removing one means scanning the array for it, O(n), before sifting. With 50,000 queued ids and 200,000 changes, that's billions of steps, which is exactly why indexed heaps exist.

```swift
// Inside a plain heap of (key, id) pairs: the O(n) search that the position array replaces
if let index = heap.firstIndex(where: { $0.id == id }) {
    heap[index].key = newKey
    siftUp(from: index)
    siftDown(from: index)
}
```

</Approach>

<Approach title="Indexed binary heap" time="O(log n) push, remove and popMin; O(1) lookups" space="O(capacity)">

The `position` array is the index that makes every id findable in O(1). Because all swaps go through `swapAt`, it can never fall out of step with the heap.

```swift
public enum DecreaseKeyQueue {
    public struct IndexedQueue {
        private var heap: [Int] = []                     // ids, in heap order
        private var keys: [Int]                          // keys[id], meaningful while id is queued
        private var position: [Int]                      // index of id in heap, or -1

        public init(capacity: Int) {
            keys = Array(repeating: 0, count: capacity)
            position = Array(repeating: -1, count: capacity)
        }

        public var count: Int { heap.count }
        public var isEmpty: Bool { heap.isEmpty }

        public func contains(_ id: Int) -> Bool { position[id] >= 0 }

        public func key(of id: Int) -> Int? { contains(id) ? keys[id] : nil }

        public func peek() -> (id: Int, key: Int)? {
            heap.first.map { ($0, keys[$0]) }
        }

        public mutating func push(_ id: Int, key: Int) {
            keys[id] = key
            if position[id] < 0 {
                heap.append(id)
                position[id] = heap.count - 1
            }
            siftUp(from: position[id])                   // a smaller key moves up…
            siftDown(from: position[id])                 // …a larger one down
        }

        @discardableResult
        public mutating func remove(_ id: Int) -> Bool {
            let index = position[id]
            guard index >= 0 else { return false }
            swapAt(index, heap.count - 1)                 // move it to the end and drop it
            heap.removeLast()
            position[id] = -1
            if index < heap.count {                      // fix the entry that took its place
                let moved = heap[index]
                siftUp(from: index)
                siftDown(from: position[moved])
            }
            return true
        }

        public mutating func popMin() -> (id: Int, key: Int)? {
            guard let top = heap.first else { return nil }
            remove(top)
            return (top, keys[top])
        }

        /// True when the entry at heap index i should be nearer the top than the one at j.
        private func comesFirst(_ i: Int, _ j: Int) -> Bool {
            (keys[heap[i]], heap[i]) < (keys[heap[j]], heap[j])
        }

        /// The only place entries move, so positions always stay correct.
        private mutating func swapAt(_ i: Int, _ j: Int) {
            heap.swapAt(i, j)
            position[heap[i]] = i
            position[heap[j]] = j
        }

        private mutating func siftUp(from start: Int) {
            var child = start
            while child > 0 {
                let parent = (child - 1) / 2
                guard comesFirst(child, parent) else { return }
                swapAt(child, parent)
                child = parent
            }
        }

        private mutating func siftDown(from start: Int) {
            var parent = start
            while true {
                let left = 2 * parent + 1
                var best = parent
                if left < heap.count && comesFirst(left, best) { best = left }
                if left + 1 < heap.count && comesFirst(left + 1, best) { best = left + 1 }
                if best == parent { return }
                swapAt(parent, best)
                parent = best
            }
        }
    }
}
```

In `remove`, the entry moved into the hole came from the bottom of the heap, so it may be too big for its new place or, if it came from another branch, too small: sifting both ways covers both cases. This is the structure Dijkstra's algorithm and Prim's algorithm use when they lower tentative distances in place, as you'll see in M44 and M46.

</Approach>
