A binary search tree was correct until someone swapped the values of exactly two of its nodes. Put them back, changing values only: every node must stay where it is.

`BSTRecoverSwapped.repair(_ root: TreeNode?)`

The function changes the tree in place and returns nothing. Aim for O(n) time and O(h) extra space, where h is the height.

## Examples

| Tree before (level order) | After `repair` |
| --- | --- |
| `[40, 20, 60, 10, 30, 50, 70, nil, 15, nil, nil, 45]` with 30 and 60 swapped: `[40, 20, 30, 10, 60, 50, 70, nil, 15, nil, nil, 45]` | `[40, 20, 60, 10, 30, 50, 70, nil, 15, nil, nil, 45]` |
| `[1, 2]` (2 is the left child of 1) | `[2, 1]` |
| `[3, 1, 4, nil, nil, 2]` | `[2, 1, 4, nil, nil, 3]` |
| `[2, 3, 1]` | `[2, 1, 3]` |

In `[3, 1, 4, nil, nil, 2]`, the root 3 and the leaf 2 were swapped: 2 sits in the root's right subtree, below 4, but it's smaller than the root.

## Constraints

- `2 ≤` number of nodes `≤ 200,000`
- Before the swap the tree was a valid BST with no repeated values.
- Exactly two nodes have had their values swapped.
- Trees in the tests are at most 1,000 levels deep, so recursion is fine.

<Hints>
<Hint>
Write down the inorder traversal of a correct BST: it's sorted. Now swap two of its values. What does the sequence look like, and how can you spot the two culprits?
</Hint>
<Hint>
Look for **drops**, places where a value is smaller than the one before it. Swapping two values that are neighbours in sorted order makes one drop: `1 2 4 3 5`. Swapping values further apart makes two: `1 5 3 4 2`. The first culprit is the bigger value at the first drop; the second is the smaller value at the last drop.
</Hint>
<Hint>
Do the inorder walk keeping a reference to the previously visited node. At each drop, set `first` if it's still `nil`, and always set `second` to the current node. When the walk ends, swap `first.value` and `second.value`.
</Hint>
</Hints>

## Solutions

<Approach title="Collect, sort and write back" time="O(n log n)" space="O(n)">

Collect the nodes in inorder, sort their values, and write the sorted values back into the nodes in the same order. Simple and correct, but it ignores the fact that only two values are out of place.

```swift
public static func repair(_ root: TreeNode?) {
    var nodes: [TreeNode] = []
    func walk(_ node: TreeNode?) {
        guard let node else { return }
        walk(node.left)
        nodes.append(node)
        walk(node.right)
    }
    walk(root)
    for (node, value) in zip(nodes, nodes.map(\.value).sorted()) {
        node.value = value
    }
}
```

</Approach>

<Approach title="Find the drops during one inorder walk" time="O(n)" space="O(h)">

One iterative inorder walk, comparing each node with the previous one. Neighbouring values produce a single drop, so `first` and `second` both come from it; distant values produce two drops, and `second` is overwritten by the later one.

```swift
public enum BSTRecoverSwapped {
    public static func repair(_ root: TreeNode?) {
        var first: TreeNode? = nil
        var second: TreeNode? = nil
        var previous: TreeNode? = nil
        var stack: [TreeNode] = []
        var current = root
        while current != nil || !stack.isEmpty {
            while let node = current {
                stack.append(node)
                current = node.left
            }
            let node = stack.removeLast()
            if let previous, previous.value > node.value {
                if first == nil {
                    first = previous
                }
                second = node
            }
            previous = node
            current = node.right
        }
        if let first, let second {
            (first.value, second.value) = (second.value, first.value)
        }
    }
}
```

[Morris traversal](/dsa/learn/trav-morris), an optional lesson in M35, does the same walk in O(1) extra space by temporarily threading right pointers back up the tree.

</Approach>
