An arithmetic expression is stored as a tree, using an indirect enum. Write one function that works out its value and another that turns it back into fully bracketed text.

`ArithmeticTree.evaluate(_ expression: Expr) -> Int` and `ArithmeticTree.render(_ expression: Expr) -> String`

```swift
public indirect enum Expr {
    case number(Int)
    case add(Expr, Expr)
    case subtract(Expr, Expr)
    case multiply(Expr, Expr)
    case negate(Expr)
}
```

Rendering rules:

- A number is written as its digits, with a minus sign if it's negative: `7`, `-3`.
- `add`, `subtract` and `multiply` are written as `(left op right)`, with brackets and a space on each side of `+`, `-` or `*`.
- `negate` is written as `-` followed straight away by its expression: `-5`, `-(1 + 2)`.

## Examples

| Expression | `evaluate` | `render` |
| --- | --- | --- |
| `.number(7)` | `7` | `"7"` |
| `.add(.number(2), .multiply(.number(3), .number(4)))` | `14` | `"(2 + (3 * 4))"` |
| `.multiply(.add(.number(2), .number(3)), .number(4))` | `20` | `"((2 + 3) * 4)"` |
| `.subtract(.number(10), .subtract(.number(4), .number(1)))` | `7` | `"(10 - (4 - 1))"` |
| `.negate(.add(.number(1), .number(2)))` | `-3` | `"-(1 + 2)"` |
| `.subtract(.number(10), .negate(.number(2)))` | `12` | `"(10 - -2)"` |

## Constraints

- A tree has at most 1,001 numbers. `evaluate` is tested on trees up to 1,001 levels deep, and `render` on trees up to 101 levels deep.
- Every intermediate result fits comfortably in an `Int`.

<Hints>
<Hint>
Each function is one `switch` with five cases, one per enum case. What's the base case, the one that doesn't need recursion?
</Hint>
<Hint>
For `.add(left, right)`, the value is `evaluate(left) + evaluate(right)`. Bind both children with `case let .add(left, right):`. `negate` has only one child.
</Hint>
<Hint>
`render` has the same shape. For a binary case, build `"(\(render(left)) + \(render(right)))"`. For a number, `String(value)` already includes the minus sign.
</Hint>
</Hints>

## Solutions

<Approach title="One recursive switch per function" time="O(n)" space="O(h)">

Both functions follow the tree recipe: a number is the base case, and every other case recurses into its children and combines their results. Each node is visited once, so the time is O(n) for n nodes. The recursion goes as deep as the tree's height h, which is the extra space.

```swift
public enum ArithmeticTree {
    public indirect enum Expr {
        case number(Int)
        case add(Expr, Expr)
        case subtract(Expr, Expr)
        case multiply(Expr, Expr)
        case negate(Expr)
    }

    public static func evaluate(_ expression: Expr) -> Int {
        switch expression {
        case .number(let value):
            return value
        case let .add(left, right):
            return evaluate(left) + evaluate(right)
        case let .subtract(left, right):
            return evaluate(left) - evaluate(right)
        case let .multiply(left, right):
            return evaluate(left) * evaluate(right)
        case .negate(let inner):
            return -evaluate(inner)
        }
    }

    public static func render(_ expression: Expr) -> String {
        switch expression {
        case .number(let value):
            return String(value)
        case let .add(left, right):
            return "(\(render(left)) + \(render(right)))"
        case let .subtract(left, right):
            return "(\(render(left)) - \(render(right)))"
        case let .multiply(left, right):
            return "(\(render(left)) * \(render(right)))"
        case .negate(let inner):
            return "-" + render(inner)
        }
    }
}
```

Notice there are no precedence rules anywhere: the tree's shape already says what happens first. Subtraction is the case to be careful with, because `left - right` and `right - left` differ. Always evaluate the left child on the left.

</Approach>
