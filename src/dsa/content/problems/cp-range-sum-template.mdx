This is a contest problem with its input and output handed to you as data. The input file holds `n` and `q`, then `n` integers, then `q` queries, each a pair `l r`. For each query, the answer is the sum of the values from position `l` to position `r`, counting from 1 and including both ends. Return the complete output: every answer followed by a newline. In a contest the bytes would come from `FileHandle.standardInput.readDataToEndOfFile()` and you'd print the result once; here the tests pass the bytes in and compare the string you return.

`TemplateQueryRunner.run(_ input: [UInt8]) -> String`

## Examples

| Input text | Output text |
| --- | --- |
| `5 3` ⏎ `4 -2 7 1 10` ⏎ `1 3` ⏎ `2 5` ⏎ `4 4` | `9` ⏎ `16` ⏎ `1` ⏎ |
| `1 2` ⏎ `-1000000000` ⏎ `1 1` ⏎ `1 1` | `-1000000000` ⏎ `-1000000000` ⏎ |
| `3 0` ⏎ `1 2 3` | the empty string |

(⏎ stands for a newline, `"\n"`.) In the first example, positions 1 to 3 hold 4, −2 and 7, which sum to 9; positions 2 to 5 sum to 16; position 4 alone is 1. Every answer, including the last, ends with `"\n"`.

## Constraints

- `1 ≤ n ≤ 200,000` and `0 ≤ q ≤ 200,000`
- `-10⁹ ≤ value ≤ 10⁹`, and `1 ≤ l ≤ r ≤ n`
- Tokens are separated by any bytes at or below ASCII 32: spaces, tabs, `"\n"` and `"\r\n"` line endings, blank lines. The input may or may not end with a newline.
- The tests use 200,000 values and 200,000 queries, so both reading and answering must be linear: no `split` on a giant `String` per query, and no loop over the range per query.

<Hints>
<Hint>
Start from the template's `FastReader`: skip bytes at or below 32, read an optional `-`, then accumulate digits with `value * 10 + Int(byte - 48)`. Give it an initialiser that takes the byte array.
</Hint>
<Hint>
A loop that adds up positions l to r is O(n) per query, 4 × 10¹⁰ steps in the worst case. Build prefix sums once, where `prefix[i]` is the sum of the first i values, so each query is `prefix[r] - prefix[l - 1]`, as in [1D prefix sums and range queries](/dsa/learn/prefix-1d).
</Hint>
<Hint>
Collect the output in one `String` with `+=`, as the template's `OutputBuffer` does, and return it at the end. The largest possible sum, 2 × 10¹⁴, fits easily in an `Int`.
</Hint>
</Hints>

## Solutions

<Approach title="Byte scanner, prefix sums and one output string" time="O(bytes + n + q)" space="O(n)">

Each byte of input is examined a constant number of times, each query is one subtraction, and the answers are appended to a single string, which is the template's "print once" applied to a return value.

```swift
public enum TemplateQueryRunner {
    struct Reader {
        private let bytes: [UInt8]
        private var position = 0

        init(_ bytes: [UInt8]) {
            self.bytes = bytes
        }

        mutating func int() -> Int {
            while position < bytes.count && bytes[position] <= 32 {
                position += 1
            }
            var isNegative = false
            if position < bytes.count && bytes[position] == UInt8(ascii: "-") {
                isNegative = true
                position += 1
            }
            var value = 0
            while position < bytes.count, bytes[position] >= 48, bytes[position] <= 57 {
                value = value * 10 + Int(bytes[position] - 48)
                position += 1
            }
            return isNegative ? -value : value
        }
    }

    public static func run(_ input: [UInt8]) -> String {
        var reader = Reader(input)
        let n = reader.int()
        let q = reader.int()
        var prefix = [0]
        prefix.reserveCapacity(n + 1)
        for _ in 0..<n {
            prefix.append(prefix[prefix.count - 1] + reader.int())
        }
        var output = ""
        for _ in 0..<q {
            let left = reader.int()
            let right = reader.int()
            output += String(prefix[right] - prefix[left - 1])
            output += "\n"
        }
        return output
    }
}
```

In a real submission, the bottom of `main.swift` would be `print(TemplateQueryRunner.run([UInt8](FileHandle.standardInput.readDataToEndOfFile())), terminator: "")`: one read and one print.

</Approach>
