An odometer counts in base `b`. It starts showing a single digit, 0. Each increment adds 1 to the last digit; a digit showing b − 1 rolls over to 0 and carries 1 to the digit on its left, and if the carry runs off the left end, a new leading digit 1 appears. The **cost** of an increment is the number of digits that change, counting a new leading digit as a change.

`OdometerPotential.totalChanges(increments n: Int, base b: Int) -> Int` returns the total cost of the first n increments, without simulating them.

`OdometerPotential.amortisedCosts(increments n: Int, base b: Int) -> [Int]` simulates the first n increments and returns each one's **amortised cost** under the potential method, using Φ = the number of digits currently showing b − 1:

amortised cost = actual cost + Φ after − Φ before

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `totalChanges(increments: 10, base: 10)` | `11` | nine single changes, then 9 → 10 changes two digits |
| `totalChanges(increments: 100, base: 10)` | `111` | |
| `totalChanges(increments: 7, base: 2)` | `11` | 1, 2, 1, 3, 1, 2, 1 |
| `amortisedCosts(increments: 12, base: 10)` | `[1, 1, 1, 1, 1, 1, 1, 1, 2, 1, 1, 1]` | 8 → 9 creates a 9, so Φ rises; 9 → 10 releases it |
| `amortisedCosts(increments: 4, base: 2)` | `[2, 2, 2, 2]` | |

The 10th increment in base 10 has actual cost 2 (the 9 becomes 0, and a new 1 appears), Φ falls from 1 to 0, so its amortised cost is 2 + 0 − 1 = 1.

## Constraints

- `totalChanges`: `0 ≤ n ≤ 10¹⁸` and `2 ≤ b ≤ 36`. Take O(log n) steps.
- `amortisedCosts`: `0 ≤ n ≤ 10⁵` and `2 ≤ b ≤ 36`.

<Hints>
<Hint>
For `totalChanges`, use the aggregate method: count how often each digit position changes, instead of looking at each increment. The last digit changes on every increment. When does the next digit to its left change?
</Hint>
<Hint>
Digit k (counting from the right, starting at 0) changes exactly when the new value is a multiple of bᵏ, including the moment it first appears. That's ⌊n / bᵏ⌋ times. So the total is n + ⌊n / b⌋ + ⌊n / b²⌋ + …, and you can get each term from the last by dividing by b, which never overflows.
</Hint>
<Hint>
For `amortisedCosts`, store the digits least significant first, as the lesson's odometer does, and keep Φ up to date as you go: subtract 1 for each b − 1 that rolls over to 0, and add 1 when the digit that goes up lands on b − 1. Watch the new leading digit: it lands on b − 1 only in base 2.
</Hint>
</Hints>

## Solutions

<Approach title="Simulate and count" time="O(n) amortised" space="O(log n)">

Running the odometer and adding up each increment's cost gives `totalChanges` for small n, and it's the only way to get the amortised costs one by one. For n = 10¹⁸ it would never finish, but the potential method promises each step is cheap on average, so the simulation is O(n) overall.

</Approach>

<Approach title="Aggregate for the total, potential for each step" time="O(log n) and O(n)" space="O(log n)">

The total uses the aggregate method: digit k changes ⌊n / bᵏ⌋ times, and repeatedly dividing n by b produces those terms. The sum is less than n × b / (b − 1), so at most 2n.

The amortised costs come from the potential method. An increment that rolls over t digits costs t + 1, lowers Φ by t, and raises it by 1 if the digit that goes up becomes b − 1. So every amortised cost is 1 or 2, however long the carry chain.

```swift
public enum OdometerPotential {
    public static func totalChanges(increments n: Int, base b: Int) -> Int {
        var total = 0
        var changes = n
        while changes > 0 {
            total += changes
            changes /= b
        }
        return total
    }

    public static func amortisedCosts(increments n: Int, base b: Int) -> [Int] {
        var digits = [0]
        var potential = 0
        var costs: [Int] = []
        for _ in 0..<n {
            let before = potential
            var actual = 0
            var position = 0
            while position < digits.count && digits[position] == b - 1 {
                digits[position] = 0
                potential -= 1
                actual += 1
                position += 1
            }
            if position == digits.count {
                digits.append(1)
            } else {
                digits[position] += 1
            }
            if digits[position] == b - 1 {
                potential += 1
            }
            actual += 1
            costs.append(actual + potential - before)
        }
        return costs
    }
}
```

In base 2, every increment turns some trailing 1s into 0s and one 0 into a 1: the actual cost is t + 1 and Φ changes by 1 − t, so the amortised cost is exactly 2 every time.

</Approach>
