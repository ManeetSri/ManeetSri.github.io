A divide-and-conquer algorithm's running time satisfies T(n) = a · T(n / b) + n^d · (log n)^k. Use the Master theorem to find p and q such that T(n) = Θ(n^p · (log n)^q), and return them as `(exponent: p, logPower: q)`.

`RecurrenceGrowthReader.solve(a: Int, b: Int, d: Int, k: Int) -> (exponent: Double, logPower: Int)`

## Examples

| `a` | `b` | `d` | `k` | Output | Meaning |
| --- | --- | --- | --- | --- | --- |
| `2` | `2` | `1` | `0` | `(1.0, 1)` | merge sort: Θ(n log n) |
| `3` | `2` | `1` | `0` | `(1.58496…, 0)` | Karatsuba: Θ(n^1.585) |
| `2` | `2` | `2` | `0` | `(2.0, 0)` | a quadratic combine: Θ(n²) |
| `2` | `2` | `1` | `1` | `(1.0, 2)` | re-sorting the strip: Θ(n log² n) |
| `1` | `2` | `0` | `0` | `(0.0, 1)` | binary search: Θ(log n) |
| `1000` | `10` | `3` | `0` | `(3.0, 1)` | 1,000 = 10³, a tie |

## Constraints

- `1 ≤ a ≤ 9,223,372,036,854,775,807` (any positive `Int`) and `2 ≤ b ≤ 10¹⁸`
- `0 ≤ d ≤ 100` and `0 ≤ k ≤ 10`
- The exponent is checked to within 10⁻⁹. The log power must be exact.
- b^d can be far too big for an `Int`: 2¹⁰⁰, for instance.

<Hints>
<Hint>
Compare a with b^d. If a is smaller, the root wins: Θ(n^d · logᵏ n). If they're equal, every level ties and you gain one log: Θ(n^d · logᵏ⁺¹ n). If a is bigger, the leaves win: Θ(n^(log_b a)), with no log factor.
</Hint>
<Hint>
Don't compare `log(Double(a)) / log(Double(b))` with `d`. For a = 1,000 and b = 10 it gives 2.9999999999999996, and a tie looks like "the root wins". Compare whole numbers instead.
</Hint>
<Hint>
Build b^d by multiplying, and stop as soon as it would pass a. Before each step, `power > a / b` tells you that `power * b` would be bigger than a, without ever computing an overflowing product.
</Hint>
</Hints>

## Solutions

<Approach title="Exact comparison, then three cases" time="O(d)" space="O(1)">

Multiply b in up to d times, stopping early once the power exceeds a. Integer division makes the test exact: if `power > a / b`, then `power * b > a`, and otherwise `power * b ≤ a` fits in an `Int`. Only the leaves case needs floating point, for the exponent log_b a.

```swift
import Foundation

public enum RecurrenceGrowthReader {
    public static func solve(a: Int, b: Int, d: Int, k: Int) -> (exponent: Double, logPower: Int) {
        var power = 1
        var exceeds = false
        for _ in 0..<d {
            if power > a / b {                 // power · b would be greater than a
                exceeds = true
                break
            }
            power *= b
        }
        if exceeds || power > a {
            return (Double(d), k)              // a < b^d: the root wins
        }
        if power == a {
            return (Double(d), k + 1)          // a = b^d: every level ties, one more log
        }
        return (log(Double(a)) / log(Double(b)), 0)   // a > b^d: the leaves win
    }
}
```

In the leaves case the log factor in f(n) disappears entirely: the leaves' n^(log_b a) is polynomially bigger than n^d · logᵏ n, so the logs don't matter.

</Approach>
