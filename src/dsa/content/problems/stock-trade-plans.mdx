`prices[i]` is a share's price on day i. You may hold at most one share at a time, and on any day you may sell the share you hold, buy one, or both (sell, then buy again). Answer two questions at once: the largest profit with **at most one trade**, one buy followed by a later sell, and the largest total profit with **as many trades as you like**. Doing nothing is allowed, so neither answer is ever negative.

`StockTradePlans.bestProfits(_ prices: [Int]) -> (oneTrade: Int, anyTrades: Int)`

## Examples

| `prices` | `oneTrade` | `anyTrades` |
| --- | --- | --- |
| `[9, 4, 7, 2, 8, 5]` | `6` | `9` |
| `[1, 2, 3, 4, 5]` | `4` | `4` |
| `[5, 1, 9, 0, 3]` | `8` | `11` |
| `[6, 5, 4]` | `0` | `0` |
| `[]` | `0` | `0` |

In the first example, the single best trade buys at 2 and sells at 8. With unlimited trades, 4 → 7 and 2 → 8 make 3 + 6 = 9. In the second, one long trade earns the same as four one-day trades. In the third, the highest price, 9, comes before the lowest, 0, so "highest minus lowest" would be wrong for both questions.

## Constraints

- `0 ≤ prices.count ≤ 100,000`
- `0 ≤ prices[i] ≤ 10,000`
- The tests use 100,000 days, so trying every pair of days is too slow.

<Hints>
<Hint>
For one trade: if you sell today, the best day to have bought is the cheapest day so far. Keep a running minimum. For many trades: every rise from one day to the next can be its own one-day trade.
</Hint>
<Hint>
Both questions also fit one state machine with two states at the end of each day: **hold** (you own a share) and **free** (you don't). Keep the best profit for each. Free today comes from free yesterday, or from selling: `hold + price`. Hold today comes from hold yesterday, or from buying.
</Hint>
<Hint>
The two questions differ only in what a buy starts from. With one trade, a buy is your first and only one, so it starts from zero: `0 − price`. With unlimited trades, it starts from what you've banked: `free − price`, using yesterday's `free`. Start `hold` at `Int.min / 2`, since owning a share before day 0 is impossible, and return `free`.
</Hint>
</Hints>

## Solutions

<Approach title="Every pair of days" time="O(n²)" space="O(1)">

For one trade, try every buy day and every later sell day. For 100,000 days that's five billion pairs. It doesn't answer the second question at all.

</Approach>

<Approach title="Running minimum and banked rises" time="O(n)" space="O(1)">

The two short answers from the lesson. The one-trade loop updates the cheapest price **before** working out today's profit, so the profit is never negative. The second loop's greedy proof: any plan's profit is a sum of daily changes over the days it holds a share, and taking only the positive changes can't do worse.

```swift
public enum StockTradePlans {
    public static func bestProfits(_ prices: [Int]) -> (oneTrade: Int, anyTrades: Int) {
        var cheapest = Int.max
        var oneTrade = 0
        for price in prices {
            cheapest = min(cheapest, price)
            oneTrade = max(oneTrade, price - cheapest)
        }
        var anyTrades = 0
        for day in prices.indices.dropFirst() where prices[day] > prices[day - 1] {
            anyTrades += prices[day] - prices[day - 1]     // bank every rise
        }
        return (oneTrade, anyTrades)
    }
}
```

</Approach>

<Approach title="Two states, two machines" time="O(n)" space="O(1)">

The same answers from the state machine, run side by side for the two rules. It looks like more machinery than the short answers, but it's the version that stretches: a cooldown, a fee or a limit of k trades is only a change to the states and arrows.

```swift
public enum StockTradePlans {
    public static func bestProfits(_ prices: [Int]) -> (oneTrade: Int, anyTrades: Int) {
        var holdOnce = Int.min / 2, freeOnce = 0              // holding is impossible before day 0
        var holdMany = Int.min / 2, freeMany = 0
        for price in prices {
            (holdOnce, freeOnce) = (max(holdOnce, 0 - price), max(freeOnce, holdOnce + price))
            (holdMany, freeMany) = (max(holdMany, freeMany - price), max(freeMany, holdMany + price))
        }
        return (freeOnce, freeMany)
    }
}
```

Each tuple assignment computes both new values before storing either, so every arrow reads yesterday's values, as the lesson recommends. `Int.min / 2` leaves room to add a price without overflowing, and the answer is `free`, never `hold`: ending the last day with an unsold share is never better than not buying it.

</Approach>
