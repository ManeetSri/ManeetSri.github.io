A compression tool encodes a text one character at a time with a Huffman code built from that text's own character counts. Return how many bits the encoded text takes. A text with only one distinct character still needs one bit per character, and an empty text needs none.

`HuffmanEncodedLength.encodedBits(_ text: String) -> Int`

## Examples

| `text` | Output | Why |
| --- | --- | --- |
| `"abracadabra"` | `23` | `a` gets 1 bit, the other four letters 3 bits each |
| `"mississippi"` | `21` | `i` and `s` get 1 and 2 bits, `p` and `m` 3 bits |
| `"aaaa"` | `4` | one symbol: one bit each |
| `"ab"` | `2` | |
| `""` | `0` | |

Different tie-breaks give different codes, but the total number of bits is always the same, so it's the only thing that's checked.

## Constraints

- `0 ≤ text.count ≤ 200,000` characters, any `Character`s (letters, digits, emoji, other scripts).
- A text can have thousands of distinct characters.
- The tests compare your answer with the cheapest of every possible merge order on small alphabets.

<Hints>
<Hint>
You don't need the tree or the codes. Each time Huffman's algorithm merges two trees, every character inside them gets one bit longer. How many bits does one merge add in total?
</Hint>
<Hint>
A merge of trees weighing a and b adds exactly a + b bits: the merged weight. So the answer is the sum of all the merged weights.
</Hint>
<Hint>
Count the characters, put the counts in a min-heap, and repeatedly pop two, add their sum to the answer and push the sum back. Handle one distinct character separately.
</Hint>
</Hints>

## Solutions

<Approach title="Sort, merge, re-sort" time="O(k² log k)" space="O(k)">

Keep the weights in an array, sort it, merge the two smallest, and repeat. With k distinct characters, that's k − 1 sorts. Fine for a few hundred distinct characters, too slow for thousands.

```swift
public static func encodedBits(_ text: String) -> Int {
    var counts: [Character: Int] = [:]
    for symbol in text {
        counts[symbol, default: 0] += 1
    }
    if counts.count == 1 { return text.count }
    var forest = Array(counts.values)
    var bits = 0
    while forest.count > 1 {
        forest.sort()
        let merged = forest[0] + forest[1]
        forest.removeFirst(2)
        forest.append(merged)
        bits += merged
    }
    return bits
}
```

</Approach>

<Approach title="Sum of merges with a heap" time="O(n + k log k)" space="O(k)">

Huffman's algorithm is optimal: an exchange argument shows the two rarest characters can be deepest siblings in a best tree, and merging them leaves the same problem with one fewer character. Each merge adds one bit to every character inside it, so the total is the sum of the merged weights. A min-heap hands out the two lightest weights in O(log k).

```swift
import DSAKit

public enum HuffmanEncodedLength {
    public static func encodedBits(_ text: String) -> Int {
        var counts: [Character: Int] = [:]
        for symbol in text {
            counts[symbol, default: 0] += 1
        }
        if counts.count == 1 { return text.count }      // one symbol: a 1-bit code each
        var weights = Heap(counts.values, areInIncreasingOrder: <)
        var bits = 0
        while weights.count > 1 {
            let merged = weights.pop()! + weights.pop()!
            bits += merged
            weights.insert(merged)
        }
        return bits
    }
}
```

The heap is built from all the counts at once with bottom-up heapify, in O(k).

</Approach>
