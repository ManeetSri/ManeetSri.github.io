Put a `+` or a `-` in front of every number in the list, keeping the numbers in their order, and add the result up. Count the sign patterns that make it equal `target`. The count can be huge, so return it modulo 1,000,000,007.

`PlusMinusTarget.ways(_ numbers: [Int], target: Int) -> Int`

## Examples

| `numbers` | `target` | Output |
| --- | --- | --- |
| `[1, 1, 2, 3]` | `1` | `3` |
| `[4, 1, 2]` | `-3` | `1` |
| `[0, 0, 1]` | `1` | `4` |
| `[1, 2, 3, 4]` | `0` | `2` |
| `[2, 3, 5]` | `11` | `0` |

In the first example, `+1 -1 -2 +3`, `-1 +1 -2 +3` and `+1 +1 +2 -3` all make 1; the two 1s are different numbers, so swapping their signs gives a different pattern. In the third, each 0 can be `+0` or `-0`, which doubles the count twice. In the last, even all plus signs only reach 10.

## Constraints

- `1 ≤ numbers.count ≤ 200`
- `0 ≤ numbers[i] ≤ 100`
- `-20,000 ≤ target ≤ 20,000`
- Answers are taken modulo 1,000,000,007. The tests include 200 numbers, where there are 2²⁰⁰ sign patterns.

<Hints>
<Hint>
Call the sum of the plus-signed numbers `P` and the sum of the minus-signed ones `M`. What are `P - M` and `P + M`?
</Hint>
<Hint>
`P - M = target` and `P + M = total`, so `P = (total + target) / 2`. Choosing the plus-signed numbers is choosing a subset that adds up to `P`. If `total + target` is odd, or the target is beyond the total, the answer is 0.
</Hint>
<Hint>
Count the subsets with sum `P`: `ways[0] = 1`, and for each number `x`, `ways[s] += ways[s - x]` with `s` going down to `x`, reducing modulo 1,000,000,007. Make sure the loop reaches `s = 0` when `x` is 0.
</Hint>
</Hints>

## Solutions

<Approach title="Try every sign pattern" time="O(2ⁿ · n)" space="O(n)">

A bitmask gives each number its sign. Add up each pattern and count the matches. Fine for 15 numbers, hopeless for 200.

</Approach>

<Approach title="Turn it into a subset count" time="O(n · total)" space="O(total)">

From `P - M = target` and `P + M = total`, the plus-signed numbers must add up to `P = (total + target) / 2`. Every subset with that sum is one sign pattern and the other way round, so count those subsets with the counting knapsack.

```swift
public enum PlusMinusTarget {
    public static func ways(_ numbers: [Int], target: Int) -> Int {
        let mod = 1_000_000_007
        let total = numbers.reduce(0, +)
        if abs(target) > total || (total + target) % 2 != 0 { return 0 }
        let plusSum = (total + target) / 2
        var ways = Array(repeating: 0, count: plusSum + 1)
        ways[0] = 1
        for x in numbers {
            for s in stride(from: plusSum, through: x, by: -1) {
                ways[s] = (ways[s] + ways[s - x]) % mod
            }
        }
        return ways[plusSum]
    }
}
```

Checking `abs(target) > total` first also keeps `total + target` from being negative, so the parity check `% 2 != 0` is safe. For `x = 0`, the stride runs from `plusSum` all the way down to 0 and doubles every count, which is exactly what a zero does.

</Approach>

<Approach title="DP over the running total" time="O(n · total)" space="O(total)">

You can also track every running total from `-total` to `total`, shifted by `total` so the indexes start at 0, and move each count to `t + x` and `t - x` for each number. It gives the same answers with a table twice as wide and more index arithmetic. The transformation above is shorter and harder to get wrong.

</Approach>
