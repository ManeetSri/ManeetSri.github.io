In a times table with `rows` rows and `columns` columns, the entry in row i and column j, both counting from 1, is i × j. List all `rows × columns` entries in increasing order, keeping repeated values. Return the kth entry in that list, with k counting from 1.

`TimesTableKth.kthSmallest(rows: Int, columns: Int, k: Int) -> Int`

## Examples

| `rows` | `columns` | `k` | Output |
| --- | --- | --- | --- |
| `2` | `5` | `6` | `4` |
| `2` | `5` | `10` | `10` |
| `4` | `4` | `9` | `6` |
| `1` | `7` | `3` | `3` |
| `100000` | `100000` | `3` | `2` |

The 2 × 5 table holds 1, 2, 3, 4, 5 and 2, 4, 6, 8, 10. In order, that's 1, 2, 2, 3, 4, 4, 5, 6, 8, 10, so the 6th entry is 4 and the 10th is 10. In the last example, the smallest entries are 1, then 2 twice (1 × 2 and 2 × 1).

## Constraints

- `1 ≤ rows, columns ≤ 100,000`
- `1 ≤ k ≤ rows × columns`
- The table can have 10¹⁰ entries, far too many to build.

<Hints>
<Hint>
Instead of finding the kth entry directly, ask how many entries are at most x. Row i holds the multiples of i, from i up to `columns × i`. How many of them are ≤ x?
</Hint>
<Hint>
Row i has `min(x / i, columns)` entries that are ≤ x, so one count takes O(rows). The count never falls as x grows, and the kth smallest entry is the first x whose count is at least k.
</Hint>
<Hint>
Binary search x from 1 to `rows × columns`. The x you find is always in the table, even though the search tries numbers that aren't: the count rises at x, and it only rises at values in the table. Loop over the shorter side of the table to make each count cheaper.
</Hint>
</Hints>

## Solutions

<Approach title="Build the table and sort it" time="O(mn log(mn))" space="O(mn)">

For an m × n table, generate every entry, sort, and index. It's the perfect checker for small tables, but a 100,000 × 100,000 table would need 80 GB of memory.

```swift
public static func kthSmallest(rows: Int, columns: Int, k: Int) -> Int {
    var entries: [Int] = []
    for i in 1...rows {
        for j in 1...columns {
            entries.append(i * j)
        }
    }
    return entries.sorted()[k - 1]
}
```

</Approach>

<Approach title="Binary search on the value, counting row by row" time="O(min(m, n) · log(mn))" space="O(1)">

Count the entries ≤ x one row at a time, and search for the smallest x whose count reaches k. The table is symmetric, so looping over the shorter side gives the same count more cheaply. Once `x / i` reaches 0, every later row starts above x, so the loop can stop.

```swift
public enum TimesTableKth {
    public static func kthSmallest(rows: Int, columns: Int, k: Int) -> Int {
        let short = Swift.min(rows, columns)
        let long = Swift.max(rows, columns)              // the table is symmetric, so swapping is fine
        var low = 1
        var high = short * long                          // the largest entry
        while low < high {
            let mid = low + (high - low) / 2
            if entries(atMost: mid, short: short, long: long) >= k {
                high = mid
            } else {
                low = mid + 1
            }
        }
        return low
    }

    /// How many entries of the table are ≤ x.
    private static func entries(atMost x: Int, short: Int, long: Int) -> Int {
        var count = 0
        for i in 1...short {
            let inRow = x / i
            if inRow == 0 { break }                      // later rows start even higher
            count += Swift.min(inRow, long)
        }
        return count
    }
}
```

The largest entry is at most 10¹⁰, so the search makes about 34 counts. `Swift.min` and `Swift.max` name the standard library's functions explicitly, which keeps them clear of any type member with the same name.

</Approach>
