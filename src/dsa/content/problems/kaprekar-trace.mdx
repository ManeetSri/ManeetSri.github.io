Kaprekar's routine turns a four-digit number into another one: arrange its digits from largest to smallest, arrange them from smallest to largest, and subtract. Repeat, and almost every start lands on 6174 within seven steps. Implement the routine **exactly** as the pseudocode below describes, and return every value it produces.

`KaprekarTrace.trace(from start: Int) -> [Int]`

```text
value ← start
trace ← [value]
while value is not 6174 and value is not 0:
    digits ← the four digits of value, counting leading zeros
    big ← the digits arranged from largest to smallest, read as a number
    small ← the digits arranged from smallest to largest, read as a number
    value ← big − small
    append value to trace
return trace
```

Numbers below 1000 still have four digits here: 999 is treated as 0999, and 21 as 0021.

## Examples

| Input | Output |
| --- | --- |
| `3524` | `[3524, 3087, 8352, 6174]` |
| `2111` | `[2111, 999, 8991, 8082, 8532, 6174]` |
| `6174` | `[6174]` |
| `1111` | `[1111, 0]` |
| `0` | `[0]` |

For `3524`: 5432 − 2345 = 3087, then 8730 − 0378 = 8352, then 8532 − 2358 = 6174, and the loop stops.

For `2111`: 2111 − 1112 = 999. Its four digits are 0, 9, 9, 9, so the next step is 9990 − 0999 = 8991.

## Constraints

- `0 ≤ start ≤ 9999`
- Every start reaches 6174 or 0 within seven steps, so the result has at most eight values.

## Solutions

<Approach title="Translate the pseudocode line by line" time="O(1)" space="O(1)">

Each line of the plan becomes a line or two of Swift. The only step that needs its own plan is "the four digits of value", so it gets a small helper that always produces exactly four digits, zeros included. Sorting them once gives `small` read forwards and `big` read backwards.

```swift
public enum KaprekarTrace {
    public static func trace(from start: Int) -> [Int] {
        var value = start
        var trace = [value]
        while value != 6174 && value != 0 {
            let digits = fourDigits(of: value).sorted()
            var small = 0
            var big = 0
            for digit in digits {
                small = small * 10 + digit
            }
            for digit in digits.reversed() {
                big = big * 10 + digit
            }
            value = big - small
            trace.append(value)
        }
        return trace
    }

    private static func fourDigits(of number: Int) -> [Int] {
        var n = number
        var digits: [Int] = []
        for _ in 0..<4 {
            digits.append(n % 10)
            n /= 10
        }
        return digits
    }
}
```

There are at most seven passes of four digits each, so the work doesn't grow with the input: it's constant time. The routine stops for every start, but that isn't obvious from the code. It was shown by checking all 10,000 starts, which is exactly what one of the tests does.

</Approach>

<Approach title="Pad the number as text" time="O(1)" space="O(1)">

Another way to keep the leading zeros is to write the number as text and pad it to four characters. Then sorting the characters arranges the digits, and `Int(_:)` reads them back.

```swift
public static func trace(from start: Int) -> [Int] {
    var value = start
    var trace = [value]
    while value != 6174 && value != 0 {
        let text = String(value)
        let padded = String(repeating: "0", count: 4 - text.count) + text
        let ascending = String(padded.sorted())
        let descending = String(ascending.reversed())
        value = Int(descending)! - Int(ascending)!
        trace.append(value)
    }
    return trace
}
```

The force unwraps are safe because the strings only ever hold digits. Forgetting the padding is the classic bug: 999 would become 999 − 999 = 0, and `2111` would wrongly stop at 0.

</Approach>
