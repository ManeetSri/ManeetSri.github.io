A folder holds some files and any number of subfolders, which makes a folder tree an N-ary tree. Work out how big a folder is with everything inside it, how many levels the tree has, and which folders are at least a given size.

`FolderSizes.totalBytes(_ folder: Folder) -> Int`, `FolderSizes.levels(_ folder: Folder) -> Int` and `FolderSizes.folders(atLeast threshold: Int, in root: Folder) -> [String]`

The node type is nested in the problem's enum, since DSAKit's `TreeNode` only has two children:

```swift
public final class Folder {
    public let name: String
    public let fileBytes: Int        // the files directly inside this folder
    public var subfolders: [Folder]
}

let photos = Folder("Photos", fileBytes: 5000, subfolders: [Folder("2026", fileBytes: 2500)])
```

A folder's total is its own `fileBytes` plus the totals of all its subfolders. `levels` is 1 for a folder with no subfolders. `folders(atLeast:in:)` returns the path of every folder whose total is at least the threshold, in preorder: each folder before its subfolders, and subfolders in their order. A path joins the names from the root down with `/`.

## Examples

```text
Home (10)
├── Documents (200)
│   ├── Taxes (1000)
│   └── Letters (50)
├── Photos (5000)
│   └── 2026 (2500)
└── Music (0)
```

| Call | Output |
| --- | --- |
| `totalBytes(home)` | `8760` |
| `totalBytes(documents)` | `1250` |
| `levels(home)` | `3` |
| `folders(atLeast: 1000, in: home)` | `["Home", "Home/Documents", "Home/Documents/Taxes", "Home/Photos", "Home/Photos/2026"]` |
| `folders(atLeast: 5000, in: home)` | `["Home", "Home/Photos"]` |
| `folders(atLeast: 9000, in: home)` | `[]` |

Photos totals 7,500: its own 5,000 plus 2,500 in 2026. Home totals 10 + 1,250 + 7,500 + 0.

## Constraints

- Up to 100,001 folders.
- At most 300 levels, so recursion is fine.
- `0 ≤ fileBytes ≤ 1,000,000`

<Hints>
<Hint>
`totalBytes` and `levels` are the binary-tree recursions with a loop over `subfolders` instead of two calls. For levels, `subfolders.map(levels).max()` is `nil` when there are none, so `?? 0` gives a leaf 1 level.
</Hint>
<Hint>
Calling `totalBytes` for every folder works, but it recomputes the same subtrees again and again: a folder deep down is re-added once for every ancestor. Instead, compute each total once, on the way back up, as a postorder walk would.
</Hint>
<Hint>
The order is the tricky part: totals are known after the children (postorder), but the answer is in preorder. Let a recursive `walk(folder, path)` return the folder's total. Before recursing, append `(path, 0)` to a list and remember its index; after the children return, fill in the total at that index. Then keep the entries that are big enough.
</Hint>
</Hints>

## Solutions

<Approach title="Postorder totals, preorder slots" time="O(n · L)" space="O(n)">

One walk computes every total exactly once. Each folder reserves its place in the list on the way down (preorder) and learns its total on the way back up (postorder). L is the length of the longest path: building each path string copies its parent's path.

```swift
public static func totalBytes(_ folder: Folder) -> Int {
    folder.subfolders.reduce(folder.fileBytes) { $0 + totalBytes($1) }
}

public static func levels(_ folder: Folder) -> Int {
    1 + (folder.subfolders.map(levels).max() ?? 0)
}

public static func folders(atLeast threshold: Int, in root: Folder) -> [String] {
    var entries: [(path: String, total: Int)] = []

    func walk(_ folder: Folder, path: String) -> Int {
        let slot = entries.count
        entries.append((path, 0))                 // preorder position, total filled in below
        var total = folder.fileBytes
        for subfolder in folder.subfolders {
            total += walk(subfolder, path: path + "/" + subfolder.name)
        }
        entries[slot].total = total
        return total
    }

    _ = walk(root, path: root.name)
    return entries.filter { $0.total >= threshold }.map(\.path)
}
```

`reduce` starts from the folder's own bytes and adds each subfolder's total. The nested function `walk` can append to `entries` because nested functions capture the variables around them.

</Approach>

<Approach title="Totals in a dictionary first" time="O(n · L)" space="O(n)">

Two separate walks: the first stores each folder's total in a dictionary keyed by the folder's identity, the second walks in preorder and looks totals up. `ObjectIdentifier` gives a class instance a hashable identity.

```swift
public static func folders(atLeast threshold: Int, in root: Folder) -> [String] {
    var totals: [ObjectIdentifier: Int] = [:]
    func total(_ folder: Folder) -> Int {
        let sum = folder.subfolders.reduce(folder.fileBytes) { $0 + total($1) }
        totals[ObjectIdentifier(folder)] = sum
        return sum
    }
    _ = total(root)

    var result: [String] = []
    func collect(_ folder: Folder, path: String) {
        if totals[ObjectIdentifier(folder)]! >= threshold {
            result.append(path)
        }
        for subfolder in folder.subfolders {
            collect(subfolder, path: path + "/" + subfolder.name)
        }
    }
    collect(root, path: root.name)
    return result
}
```

This is easier to get right the first time, at the cost of a dictionary and a second pass.

</Approach>
