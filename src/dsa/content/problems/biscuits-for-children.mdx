At a birthday party, each child has a **greed**: the smallest biscuit that will make them happy. You have a tin of biscuits of different sizes, and each child may get at most one. A child is happy if their biscuit's size is at least their greed. Return the largest number of children you can make happy.

`BiscuitsForChildren.happyChildren(greed: [Int], biscuits: [Int]) -> Int`

## Examples

| `greed` | `biscuits` | Output | Why |
| --- | --- | --- | --- |
| `[5, 2, 8, 3]` | `[4, 1, 3, 9, 2]` | `3` | 5 and 8 both need the 9 |
| `[1, 4, 2]` | `[3, 1, 1]` | `2` | the 3 goes to greed 2, a 1 to greed 1 |
| `[3, 3]` | `[2, 2, 2]` | `0` | every biscuit is too small |
| `[1, 1, 1]` | `[5]` | `1` | one biscuit, one happy child |
| `[]` | `[1, 2]` | `0` | no children |

## Constraints

- `0 ≤ greed.count, biscuits.count ≤ 100,000`
- `1 ≤ greed[i], biscuits[j] ≤ 10⁹`
- The tests compare your answer with trying every way to hand out the biscuits on small cases.

<Hints>
<Hint>
Sort both lists. Think about the least greedy child: is there any reason not to make them happy, if some biscuit can?
</Hint>
<Hint>
Which biscuit should the least greedy child get? A bigger one would also work, but a greedier child might need it.
</Hint>
<Hint>
Walk the biscuits from smallest to largest with a pointer to the least greedy child still waiting. If the biscuit is big enough, that child is happy and the pointer moves on; if not, the biscuit is too small for everyone left, so skip it.
</Hint>
</Hints>

## Solutions

<Approach title="Try every handout" time="O((m + 1)ⁿ)" space="O(n + m)">

Each child, in turn, either goes without or takes any unused biscuit that's big enough. Exponential, but it's the checker the tests use, and writing it first is a good habit.

```swift
public static func happyChildren(greed: [Int], biscuits: [Int]) -> Int {
    var used = Array(repeating: false, count: biscuits.count)
    func best(from child: Int) -> Int {
        if child == greed.count { return 0 }
        var result = best(from: child + 1)                   // this child goes without
        for b in biscuits.indices where !used[b] && biscuits[b] >= greed[child] {
            used[b] = true
            result = max(result, 1 + best(from: child + 1))
            used[b] = false
        }
        return result
    }
    return best(from: 0)
}
```

</Approach>

<Approach title="Greedy with two pointers" time="O(n log n + m log m)" space="O(n + m)">

Give the least greedy child the smallest biscuit that satisfies them. Two swaps prove it's safe. If some best handout leaves that child hungry, take any happy child's biscuit and give it to them instead: that biscuit satisfied a greedier child, so it satisfies this one. Then, if this child holds a bigger biscuit than necessary, swap it with whoever holds the smallest sufficient one (or with the tin): the other child gets a bigger biscuit than before, so they stay happy.

```swift
public enum BiscuitsForChildren {
    public static func happyChildren(greed: [Int], biscuits: [Int]) -> Int {
        let children = greed.sorted()
        var child = 0
        for size in biscuits.sorted() where child < children.count && size >= children[child] {
            child += 1
        }
        return child
    }
}
```

Walking from the other end works too: give the biggest biscuit to the greediest child it can satisfy, skipping children no remaining biscuit can satisfy.

</Approach>
