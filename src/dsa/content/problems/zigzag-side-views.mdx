Three questions answered from the levels of a binary tree: the values in zigzag order, and what you'd see standing to the right of the tree and to the left of it.

`ZigzagSideViews.zigzag(_ root: TreeNode?) -> [[Int]]`, `ZigzagSideViews.rightView(_ root: TreeNode?) -> [Int]` and `ZigzagSideViews.leftView(_ root: TreeNode?) -> [Int]`

- **Zigzag:** level by level, the root's level left to right, the next level right to left, the next left to right again, and so on.
- **Right view:** the rightmost node of each level, from the top down.
- **Left view:** the leftmost node of each level, from the top down.

The empty tree gives `[]` for all three.

## Examples

| Tree (level order) | `zigzag` | `rightView` | `leftView` |
| --- | --- | --- | --- |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `[[1], [3, 2], [4, 5, 6], [7]]` | `[1, 3, 6, 7]` | `[1, 2, 4, 7]` |
| `[3, 9, 20, nil, nil, 15, 7]` | `[[3], [20, 9], [15, 7]]` | `[3, 20, 7]` | `[3, 9, 15]` |
| `[1, 2, 3, 4]` | `[[1], [3, 2], [4]]` | `[1, 3, 4]` | `[1, 2, 4]` |
| `[1, nil, 2, nil, 3]` | `[[1], [2], [3]]` | `[1, 2, 3]` | `[1, 2, 3]` |

In `[1, 2, 3, 4]`, node 4 hangs below 2, on the left side. It's still in the right view: nothing on its level is further right, so from the right you can see it.

## Constraints

- `0 ≤` number of nodes `≤ 100,000`
- Trees can be 100,000 levels deep.

<Hints>
<Hint>
All three are level-order traversals with a twist at the end of each level. Start by collecting each level's values, left to right.
</Hint>
<Hint>
Zigzag: reverse the values of every odd-numbered level (counting the root's level as 0). Right view: each level's last value. Left view: each level's first.
</Hint>
<Hint>
There's also a depth-first way to get the right view: walk node, right, left, carrying the depth. The first node you reach at each new depth is the rightmost on that level, so record it when `depth == result.count`. It's recursive, though, so it needs care with very deep trees.
</Hint>
</Hints>

## Solutions

<Approach title="Levels first, then pick" time="O(n)" space="O(n)">

Collect the levels once, then each answer is a one-line transformation.

```swift
public enum ZigzagSideViews {
    /// Every level's values, left to right, top down.
    private static func levels(_ root: TreeNode?) -> [[Int]] {
        var result: [[Int]] = []
        var level = [root].compactMap { $0 }
        while !level.isEmpty {
            result.append(level.map(\.value))
            level = level.flatMap { [$0.left, $0.right].compactMap { $0 } }
        }
        return result
    }

    public static func zigzag(_ root: TreeNode?) -> [[Int]] {
        levels(root).enumerated().map { depth, values in
            depth % 2 == 0 ? values : Array(values.reversed())
        }
    }

    public static func rightView(_ root: TreeNode?) -> [Int] {
        levels(root).map { $0[$0.count - 1] }     // every level has at least one node
    }

    public static func leftView(_ root: TreeNode?) -> [Int] {
        levels(root).map { $0[0] }
    }
}
```

Reversing a level costs as much as building it, so zigzag stays O(n) overall.

</Approach>

<Approach title="Right view by depth-first search" time="O(n)" space="O(h)">

Visit the right child before the left. Then, at every depth, the first node you meet is the rightmost one on that level. Swap the two recursive calls for the left view.

```swift
public static func rightView(_ root: TreeNode?) -> [Int] {
    var result: [Int] = []
    func walk(_ node: TreeNode?, depth: Int) {
        guard let node else { return }
        if depth == result.count {
            result.append(node.value)             // first node seen on this level
        }
        walk(node.right, depth: depth + 1)
        walk(node.left, depth: depth + 1)
    }
    walk(root, depth: 0)
    return result
}
```

This uses O(h) space instead of a whole level, but it recurses once per level, so on this problem's 100,000-level chains it would overflow the stack. Rewrite it with an explicit stack of (node, depth) pairs, pushing left before right, to make it safe.

</Approach>
