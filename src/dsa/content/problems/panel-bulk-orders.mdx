A builder needs a set of rectangular panels, each given as `[width, height]`. The supplier sells panels in batches: a batch can hold any panels you like, and costs (the width of its widest panel) × (the height of its tallest panel). Every panel must be in exactly one batch. Return the smallest total cost.

`PanelBulkOrders.cheapestOrders(_ panels: [[Int]]) -> Int`

## Examples

| `panels` | Output |
| --- | --- |
| `[[100, 1], [15, 15], [20, 5], [1, 100]]` | `500` |
| `[[14, 1], [6, 4], [1, 10], [10, 2], [3, 7]]` | `80` |
| `[[2, 2], [1, 1], [2, 1], [1, 2]]` | `4` |
| `[[5, 1], [1, 5]]` | `10` |
| `[[3, 4]]` | `12` |

In the first example, `[100, 1]` and `[1, 100]` go alone (100 each), and `[15, 15]` shares a batch with `[20, 5]` for 20 × 15 = 300. In the second, the batches are `[1, 10]` alone (10), `[3, 7]` with `[6, 4]` (6 × 7 = 42) and `[10, 2]` with `[14, 1]` (14 × 2 = 28). In the third, `[2, 2]` covers every other panel, so one batch of cost 4 holds them all.

## Constraints

- `0 ≤ panels.count ≤ 70,000`
- `1 ≤ width, height ≤ 1,000,000`
- One test has 50,000 panels where no panel covers another, so an O(n²) DP over them is too slow.

<Hints>
<Hint>
If one panel is at least as wide and at least as tall as another, the smaller one can join the bigger one's batch for free. Remove every panel that's covered like that. What do the survivors look like when sorted by width?
</Hint>
<Hint>
Sorted by width, the survivors' heights fall. Then some best plan batches consecutive survivors, and a batch of survivors j + 1 to i costs `width[i] × height[j + 1]`. Write the O(n²) DP: `best[i] = min over j of best[j] + width[i] · height[j + 1]`.
</Hint>
<Hint>
Each j is a line with slope `height[j + 1]` and intercept `best[j]`, queried at `x = width[i]`. The slopes fall as j grows and the queries rise with i, which is the easiest case of the convex hull trick: a hull with a pointer, O(n) after sorting.
</Hint>
</Hints>

## Solutions

<Approach title="Try every way to batch" time="exponential" space="O(n)">

Place each panel in turn into an existing batch or a new one, and keep the cheapest total. The tests use this on up to seven panels to check the clever versions, since it shares none of their ideas.

</Approach>

<Approach title="Remove covered panels, then an O(n²) DP" time="O(n log n + m²)" space="O(n)">

Sort by width (widest first, tallest first among ties) and keep a panel only if it's taller than every panel kept so far. That leaves m survivors with widths rising and heights falling. Then try every j for every i. For random panels m is tiny, but when every panel survives this is O(n²) again.

</Approach>

<Approach title="Remove covered panels, then the convex hull trick" time="O(n log n)" space="O(n)">

The DP lines are added in falling-slope order and queried at rising points, so lines that can never be lowest are popped from the back, and the query pointer only moves forward.

```swift
public enum PanelBulkOrders {
    public static func cheapestOrders(_ panels: [[Int]]) -> Int {
        // Widest first; among equal widths, tallest first. Keep a panel only if it's taller than every
        // panel kept so far, which are all at least as wide.
        let sorted = panels.sorted { ($0[0], $0[1]) > ($1[0], $1[1]) }
        var width: [Int] = [], height: [Int] = []
        for panel in sorted where panel[1] > (height.last ?? 0) {
            width.append(panel[0])
            height.append(panel[1])
        }
        width.reverse()                                // widths rising, heights falling
        height.reverse()
        let n = width.count
        if n == 0 { return 0 }

        var slopes: [Int] = [], intercepts: [Int] = []
        var front = 0
        func value(_ line: Int, _ x: Int) -> Int { slopes[line] * x + intercepts[line] }
        func add(_ m: Int, _ c: Int) {
            while slopes.count - front >= 2 {
                let a = slopes.count - 2, b = slopes.count - 1
                // b is useless if the new line overtakes a no later than b does
                if (c - intercepts[a]) * (slopes[a] - slopes[b]) <= (intercepts[b] - intercepts[a]) * (slopes[a] - m) {
                    slopes.removeLast()
                    intercepts.removeLast()
                } else {
                    break
                }
            }
            slopes.append(m)
            intercepts.append(c)
        }

        var best = 0                                   // best[0]: no panels, no cost
        add(height[0], 0)                              // j = 0: the next batch starts at panel 0
        for i in 0..<n {
            let x = width[i]
            while front + 1 < slopes.count && value(front + 1, x) <= value(front, x) {
                front += 1
            }
            best = value(front, x)                     // best for panels 0...i
            if i + 1 < n {
                add(height[i + 1], best)               // j = i + 1: a batch starting at panel i + 1
            }
        }
        return best
    }
}
```

Why consecutive batches are enough: if a batch held survivors i and k but not some j between them, j is narrower than k and shorter than i, so it fits inside that batch's cost for free. Moving it in never costs more.

Why nothing overflows: `best[j]` is at most the cost of one batch holding everything up to j, which is at most 10⁶ × 10⁶ = 10¹². The hull test multiplies an intercept difference (up to 10¹²) by a slope difference (up to 10⁶), at most 10¹⁸, just inside an `Int`.

</Approach>
