A game keeps the player's score in a struct. Use a property observer so the score always stays in range, and so the tracker keeps its best score and a count of real changes up to date by itself, whoever sets the score.

`ClampedScoreTracker.Tracker`, with `current`, `best`, `changes`, `init(starting:)` and `static func replaying(_:)`

- **`current`** is always within `0...Tracker.maximum`, where the static constant `maximum` is 1,000. Setting it to anything outside that range stores the nearest end instead.
- **`best`** is the highest value `current` has held, including the starting value.
- **`changes`** counts how many times setting `current` actually changed its value, after clamping. Setting the value it already has, or a value that clamps back to it, isn't a change.
- **`init(starting:)`** clamps the starting value too. Starting isn't a change.
- **`replaying(_:)`** is a static factory: a tracker that starts at 0 and then has each score in the array set in turn.

## Examples

| Code | `current` | `best` | `changes` |
| --- | --- | --- | --- |
| `Tracker(starting: 1500)` | 1000 | 1000 | 0 |
| `Tracker(starting: 300)`, then `current = 5000` | 1000 | 1000 | 1 |
| then `current = 2000` | 1000 | 1000 | 1 |
| `Tracker(starting: 50)`, then `current = -7` | 0 | 50 | 1 |
| `Tracker.replaying([12, 40, 7, 33])` | 33 | 40 | 4 |
| `Tracker.replaying([-5, 2000, 2000, 999])` | 999 | 1000 | 2 |

## Constraints

- Scores are any `Int` values that don't overflow when the tests add to them.
- Keep `best` and `changes` read-only from outside: they're `private(set)` in the starter code.

<Hints>
<Hint>
Add a `didSet` to `current`. Inside it, assign `current` its clamped value: assigning to a property inside its own `didSet` doesn't run the observer again. `min(max(value, 0), Tracker.maximum)` clamps.
</Hint>
<Hint>
Compare the clamped `current` with `oldValue` to decide whether to add one to `changes`. Then raise `best` if `current` is now higher.
</Hint>
<Hint>
Observers don't run during initialisation, so `init(starting:)` has to clamp the value itself and set `best` to it. A small `private static func clamped(_:)` saves writing the clamp twice.
</Hint>
</Hints>

## Solutions

<Approach title="One didSet keeps every rule" time="O(1) per change, O(n) to replay n scores" space="O(1)">

Every way of changing `current`, including `+=`, goes through the observer, so the rules can't be skipped. The static helper does the clamping for both the observer and the initialiser, and the static factory builds a tracker without the caller repeating the loop.

```swift
public enum ClampedScoreTracker {
    public struct Tracker {
        public static let maximum = 1_000

        public var current: Int {
            didSet {
                current = Tracker.clamped(current)
                if current != oldValue {
                    changes += 1
                }
                if current > best {
                    best = current
                }
            }
        }

        public private(set) var best: Int
        public private(set) var changes = 0

        public init(starting: Int) {
            let start = Tracker.clamped(starting)
            current = start
            best = start
        }

        private static func clamped(_ value: Int) -> Int {
            min(max(value, 0), maximum)
        }

        public static func replaying(_ scores: [Int]) -> Tracker {
            var tracker = Tracker(starting: 0)
            for score in scores {
                tracker.current = score
            }
            return tracker
        }
    }
}
```

`oldValue` is the value before this assignment, which was already clamped, so comparing it with the clamped new value counts only real changes.

</Approach>
