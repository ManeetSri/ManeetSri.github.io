Profile two recursion trees level by level. Level 0 is the first call, level 1 holds the calls it makes, level 2 the calls those make, and so on. Return how many calls (boxes) sit on each level, from the top down, without running the recursions: their trees are far too big.

`RecursionTreeLevels.fibonacciLevels(_ n: Int) -> [Int]` is for the naive Fibonacci recursion, called as `fib(n)`:

```swift
func fib(_ n: Int) -> Int {
    if n < 2 {
        return n
    }
    return fib(n - 1) + fib(n - 2)
}
```

`RecursionTreeLevels.halvesLevels(_ n: Int) -> [Int]` is for the sum over halves, called on an array of n items as `total(items, 0, n - 1)`:

```swift
func total(_ items: [Int], _ low: Int, _ high: Int) -> Int {
    if low == high {
        return items[low]
    }
    let mid = (low + high) / 2
    return total(items, low, mid) + total(items, mid + 1, high)
}
```

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `fibonacciLevels(4)` | `[1, 2, 4, 2]` | `fib(4)`; `fib(3)`, `fib(2)`; then 4 calls; then the 2 calls `fib(2)` makes |
| `fibonacciLevels(5)` | `[1, 2, 4, 6, 2]` | 15 calls in total |
| `fibonacciLevels(1)` | `[1]` | a base case straight away |
| `halvesLevels(5)` | `[1, 2, 4, 2]` | ranges of 5; 3 and 2; 2, 1, 1, 1; 1, 1 |
| `halvesLevels(8)` | `[1, 2, 4, 8]` | a perfect tree |
| `halvesLevels(1)` | `[1]` | |

## Constraints

- `fibonacciLevels`: `0 ≤ n ≤ 80`. `fib(80)` makes about 7.6 × 10¹⁶ calls, but every level's count fits in an `Int`.
- `halvesLevels`: `1 ≤ n ≤ 10¹⁸`.
- Counting the calls one by one is far too slow for either. Work a whole level at a time.

<Hints>
<Hint>
Many calls on the same level are identical: in `fib`'s tree, level 2 of `fib(5)` holds `fib(3)` once, `fib(2)` twice and `fib(1)` once. Calls with the same argument make the same children, so you only need to know **how many** calls on a level have each argument. A dictionary from argument to count describes a level.
</Hint>
<Hint>
To get the next level, go through the dictionary: a `fib(a)` call with count c (and a ≥ 2) adds c to the counts of `a - 1` and `a - 2`. For the halves, describe a call by its range's size s: if s ≥ 2 it makes one call on ⌈s/2⌉ items and one on ⌊s/2⌋ items. Base cases make nothing. Stop when a level is empty.
</Hint>
<Hint>
The number of boxes on a level is the sum of the dictionary's counts. Each level has very few distinct arguments: at most about 40 for `fib`, and at most 2 sizes for the halves, which is why this is fast even when the tree has 10¹⁸ boxes.
</Hint>
</Hints>

## Solutions

<Approach title="Run the recursion with a level counter" time="O(calls)" space="O(depth)">

Pass the level down as an extra parameter and add 1 to `counts[level]` in every call. It draws the exact profile and is a great check for small n, but `fib(50)` already makes over 40 billion calls, and `total` on 10¹⁸ items makes 2 × 10¹⁸.

```swift
func profile(_ n: Int, level: Int, counts: inout [Int]) {
    if counts.count == level {
        counts.append(0)
    }
    counts[level] += 1
    if n >= 2 {
        profile(n - 1, level: level + 1, counts: &counts)
        profile(n - 2, level: level + 1, counts: &counts)
    }
}
```

</Approach>

<Approach title="Group identical calls on each level" time="O(levels × distinct arguments)" space="O(distinct arguments)">

A level is a dictionary from argument to how many calls on that level have it. Building the next level touches each distinct argument once instead of each call once. For `fib(n)` there are n levels with at most about n / 2 + 1 distinct arguments each; for the halves, sizes on one level differ by at most 1, so there are at most 2, and about log₂ n levels.

```swift
public enum RecursionTreeLevels {
    public static func fibonacciLevels(_ n: Int) -> [Int] {
        var level = [n: 1]
        var counts: [Int] = []
        while !level.isEmpty {
            counts.append(level.values.reduce(0, +))
            var next: [Int: Int] = [:]
            for (argument, count) in level where argument >= 2 {
                next[argument - 1, default: 0] += count
                next[argument - 2, default: 0] += count
            }
            level = next
        }
        return counts
    }

    public static func halvesLevels(_ n: Int) -> [Int] {
        var level = [n: 1]
        var counts: [Int] = []
        while !level.isEmpty {
            counts.append(level.values.reduce(0, +))
            var next: [Int: Int] = [:]
            for (size, count) in level where size >= 2 {
                next[(size + 1) / 2, default: 0] += count
                next[size / 2, default: 0] += count
            }
            level = next
        }
        return counts
    }
}
```

The profiles tell the story of the lesson. `fibonacciLevels(80)` doubles for 41 levels, 1, 2, 4, … up to 2⁴⁰, then falls short of doubling as the n − 2 branches run out, peaking around 10¹⁶: exponential. `halvesLevels(n)` has only about log₂ n + 1 levels, and they add up to 2n − 1: linear.

</Approach>
