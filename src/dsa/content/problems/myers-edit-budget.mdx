A diff tool's first question about two files is how different they are: the fewest lines to delete and insert to turn the old file into the new one. A code review tool only shows a diff when that number is small, so it also wants a **budget**: past `limit` edits, give up and say so. With the LCS table that takes O(n × m) time and memory, hopeless for two 100,000-line files. Myers' algorithm takes O((n + m) × D) for D edits, and with a budget, never more than O((n + m) × limit).

`MyersEditBudget.distance(from old: [String], to new: [String], limit: Int) -> Int?`

Return the fewest line deletions plus insertions that turn `old` into `new`, or `nil` if that number is greater than `limit`. A changed line counts as one deletion and one insertion, and so does a moved line.

## Examples

| `old` | `new` | `limit` | Output |
| --- | --- | --- | --- |
| `["import UIKit", "", "struct Feed {", "    var posts: [Post]", "}", ""]` | `["import SwiftUI", "", "struct Feed {", "    var posts: [Post]", "    var isLoading = false", "}"]` | `10` | `4` |
| the same | the same | `3` | `nil` |
| `["a", "b", "c", "a", "b", "b", "a"]` | `["c", "b", "a", "b", "a", "c"]` | `100` | `5` |
| `["a", "b", "c"]` | `["b", "c", "a"]` | `9` | `2` |
| `[]` | `["a", "b"]` | `5` | `2` |
| any file | the same file | `0` | `0` |

In the first example, the import changes (one deletion, one insertion), a property is added and the trailing blank line goes: 4 edits.

## Constraints

- `0 ≤ old.count, new.count ≤ 100,000`. Lines can repeat: real files are full of `}` and blank lines.
- `0 ≤ limit ≤ 2,000`.
- Your solution must stop after about `limit` rounds of work, so that two files that are nothing alike give up as quickly as two nearly identical files finish.

<Hints>
<Hint>
Think of a grid with `old` along the top and `new` down the side. Moving right deletes a line of `old`, moving down inserts a line of `new`, and where `old[x] == new[y]` you may move diagonally for free. You want the cheapest path from the top-left corner to the bottom-right.
</Hint>
<Hint>
Number the diagonals by `k = x - y`. After `d` edits, the path can only be on diagonals from `-d` to `d`, and on each one only the **furthest** point matters. Keep `v[k]`, the furthest `x` reached on diagonal `k`. Round `d` computes it from round `d - 1`: step down from diagonal `k + 1` or right from diagonal `k - 1`, whichever got further, then slide along the free diagonal while the lines match.
</Hint>
<Hint>
The first round in which some diagonal reaches `x = n` and `y = m` is the answer. Run rounds `d = 0, 1, …, limit` and return `nil` if none gets there. Diagonals only reach `-limit` to `limit`, so `v` needs `2 × limit + 3` slots, however long the files are. Mapping each distinct line to an `Int` first makes the comparisons cheap.
</Hint>
</Hints>

## Solutions

<Approach title="LCS table (too slow here)" time="O(n × m)" space="O(n × m)">

The fewest edits are `n + m - 2 × LCS`, since every line not in a longest common subsequence must be deleted or inserted. It's the reference the tests use on small files, but on two 100,000-line files the table would have 10¹⁰ cells.

```swift
func editsByLCS(_ a: [String], _ b: [String]) -> Int {
    var table = Array(repeating: Array(repeating: 0, count: b.count + 1), count: a.count + 1)
    for i in stride(from: 1, through: a.count, by: 1) {
        for j in stride(from: 1, through: b.count, by: 1) {
            table[i][j] = a[i - 1] == b[j - 1] ? table[i - 1][j - 1] + 1 : max(table[i - 1][j], table[i][j - 1])
        }
    }
    return a.count + b.count - 2 * table[a.count][b.count]
}
```

</Approach>

<Approach title="Myers' greedy search, stopped at the budget" time="O((n + m) × min(D, limit))" space="O(n + m + limit)">

Each round is one more edit, so this is a breadth-first search by cost in which only the frontier is stored: one number per diagonal. The snake (the free slide along matching lines) is what makes it fast when D is small: long unchanged stretches cost nothing but comparisons.

```swift
public enum MyersEditBudget {
    public static func distance(from old: [String], to new: [String], limit: Int) -> Int? {
        guard limit >= 0 else { return nil }
        var ids: [String: Int] = [:]
        func id(_ line: String) -> Int {
            if let known = ids[line] { return known }
            ids[line] = ids.count
            return ids.count - 1
        }
        let a = old.map(id), b = new.map(id)
        let n = a.count, m = b.count
        let rounds = min(limit, n + m)
        let offset = rounds + 1
        var v = [Int](repeating: 0, count: 2 * rounds + 3)     // v[offset + k]: furthest x on diagonal k
        for d in 0...rounds {
            for k in stride(from: -d, through: d, by: 2) {
                var x: Int
                if k == -d || (k != d && v[offset + k - 1] < v[offset + k + 1]) {
                    x = v[offset + k + 1]                         // down from diagonal k + 1: an insertion
                } else {
                    x = v[offset + k - 1] + 1                     // right from diagonal k - 1: a deletion
                }
                var y = x - k
                while x < n && y < m && a[x] == b[y] {            // the snake: equal lines are free
                    x += 1
                    y += 1
                }
                v[offset + k] = x
                if x >= n && y >= m { return d }
            }
        }
        return nil
    }
}
```

Two details make the budget work. Diagonals in round `d` only have the parity of `d`, so `k` steps by 2. And the edge cases fall out without special code: two empty files finish in round 0, and identical files slide straight to the corner in round 0 too. To recover the edits themselves, save a copy of `v` before each round and walk back from the corner, as the lesson's `myersDiff` does.

</Approach>
