Two sorted arrays need merging, and the first one has been given spare room at its end for the second. Merge them **into the first array**, without creating another array, so that all of `first` ends up sorted.

`MergeIntoFirst.merge(_ first: inout [Int], used: Int, with second: [Int])`

The first `used` elements of `first` are the real, sorted values. After them come exactly `second.count` spare slots, whose contents mean nothing.

## Examples

| `first` before | `used` | `second` | `first` after |
| --- | --- | --- | --- |
| `[1, 4, 7, 0, 0, 0]` | `3` | `[2, 3, 9]` | `[1, 2, 3, 4, 7, 9]` |
| `[10, 20, 0, 0, 0]` | `2` | `[1, 2, 3]` | `[1, 2, 3, 10, 20]` |
| `[1, 3, 3, 0, 0, 0]` | `3` | `[3, 3, 4]` | `[1, 3, 3, 3, 3, 4]` |
| `[1, 2, 3]` | `3` | `[]` | `[1, 2, 3]` |
| `[0, 0]` | `0` | `[4, 5]` | `[4, 5]` |

## Constraints

- `0 ≤ used, second.count ≤ 50,000`, and `first.count == used + second.count`
- Both sorted parts are in non-decreasing order. Values are any `Int`, including negatives.
- O(m + n) time and O(1) extra space, where m is `used` and n is `second.count`.

<Hints>
<Hint>
Merging from the front would overwrite values of `first` that you haven't placed yet. Where is there free space to write into without destroying anything?
</Hint>
<Hint>
At the back. The largest value overall is the larger of `first[used - 1]` and the last element of `second`, and it belongs in the very last slot.
</Hint>
<Hint>
Keep three indices: `i` for the last unplaced value of `first`, `j` for the last unplaced value of `second`, and `write` for the next slot to fill, starting at the end. Loop while `second` has values left. Once it runs out, the rest of `first` is already in place.
</Hint>
</Hints>

## Solutions

<Approach title="Copy, then merge into a new array" time="O(m + n)" space="O(m)">

Copy the real values of `first` out, then merge the copy and `second` back into `first` from the front, as in the lesson. It's correct and linear, but the copy uses O(m) extra memory, which the problem rules out.

```swift
public static func merge(_ first: inout [Int], used: Int, with second: [Int]) {
    let original = Array(first[..<used])
    var i = 0
    var j = 0
    for write in 0..<first.count {
        if j == second.count || (i < used && original[i] <= second[j]) {
            first[write] = original[i]
            i += 1
        } else {
            first[write] = second[j]
            j += 1
        }
    }
}
```

</Approach>

<Approach title="Merge from the back" time="O(m + n)" space="O(1)">

Fill the slots from the last one backwards, each time taking the larger of the two last unplaced values. The write position is always at or after `i`, so a value of `first` is never overwritten before it has been moved.

```swift
public enum MergeIntoFirst {
    public static func merge(_ first: inout [Int], used: Int, with second: [Int]) {
        var i = used - 1              // last unplaced value in first
        var j = second.count - 1      // last unplaced value in second
        var write = used + second.count - 1
        while j >= 0 {
            if i >= 0 && first[i] > second[j] {
                first[write] = first[i]
                i -= 1
            } else {
                first[write] = second[j]
                j -= 1
            }
            write -= 1
        }
        // Whatever is left of first is already in place
    }
}
```

Why is `write` never less than `i`? At every moment, `write` is `i + j + 1`, and `j` is at least 0 inside the loop. When `second` is used up, the loop ends and `first[0...i]` hasn't moved at all, which is exactly where it belongs.

</Approach>
