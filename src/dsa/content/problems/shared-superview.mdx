To convert a point from one view's coordinates to another's, UIKit has to find the nearest view that contains them both, and the chain of views between them. Each view knows only its superview. Given that, find the nearest common superview of two views, and the path from one to the other through it.

`SharedSuperview.nearestCommonSuperview(_ a: String, _ b: String, superviewOf: [String: String]) -> String?` and `SharedSuperview.path(from a: String, to b: String, superviewOf: [String: String]) -> [String]?`

`superviewOf[v]` is the view that directly contains `v`. A view with no entry is a window, the top of its hierarchy. A view counts as containing itself, so if `a` contains `b`, the answer is `a`. The path lists the views from `a` up to the shared superview and back down to `b`, both ends included. Both return `nil` when the views are in different windows.

## Examples

A settings screen, with an alert in a second window:

```text
window                      alertWindow
├── navBar                  └── alertLabel
│   ├── backButton
│   └── titleLabel
└── tableView
    ├── cell0
    │   ├── icon
    │   └── label0
    └── cell1
        └── toggle
```

So `superviewOf` is `["navBar": "window", "backButton": "navBar", "titleLabel": "navBar", "tableView": "window", "cell0": "tableView", "icon": "cell0", "label0": "cell0", "cell1": "tableView", "toggle": "cell1", "alertLabel": "alertWindow"]`.

| `a` | `b` | Nearest common superview | Path |
| --- | --- | --- | --- |
| `"icon"` | `"toggle"` | `"tableView"` | `["icon", "cell0", "tableView", "cell1", "toggle"]` |
| `"icon"` | `"label0"` | `"cell0"` | `["icon", "cell0", "label0"]` |
| `"titleLabel"` | `"toggle"` | `"window"` | `["titleLabel", "navBar", "window", "tableView", "cell1", "toggle"]` |
| `"cell0"` | `"icon"` | `"cell0"` | `["cell0", "icon"]` |
| `"toggle"` | `"toggle"` | `"toggle"` | `["toggle"]` |
| `"icon"` | `"alertLabel"` | `nil` | `nil` |

## Constraints

- Up to 100,000 views, and a hierarchy can be 100,000 views deep.
- The superview links never form a loop. `a` and `b` don't have to appear in the dictionary at all: a view that appears nowhere is a window of its own.

<Hints>
<Hint>
Walk up from `a`, putting every view you pass (including `a`) into a `Set`. Then walk up from `b`: the first view you meet that's in the set is the answer. If you run out of superviews first, there isn't one.
</Hint>
<Hint>
To use O(1) extra space instead, count each view's depth (how many steps up to its window). Lift the deeper view until both are at the same depth, then lift both together, one step at a time, until they're the same view.
</Hint>
<Hint>
For the path, walk up from `a` to the shared superview, collecting views, then do the same from `b`. Join the first list with the second one reversed, taking care not to include the shared view twice.
</Hint>
</Hints>

## Solutions

<Approach title="A set of a's superviews" time="O(depth)" space="O(depth)">

This is the version to reach for first in an interview: short, and obviously right.

```swift
public static func nearestCommonSuperview(_ a: String, _ b: String, superviewOf: [String: String]) -> String? {
    var seen: Set<String> = [a]
    var current = a
    while let parent = superviewOf[current] {
        seen.insert(parent)
        current = parent
    }
    var candidate: String? = b
    while let view = candidate, !seen.contains(view) {
        candidate = superviewOf[view]
    }
    return candidate
}
```

`candidate` becomes `nil` when the walk from `b` passes the top of its window without meeting a view from `a`'s chain.

</Approach>

<Approach title="Level the depths, then climb together" time="O(depth)" space="O(1)">

Two views at the same depth reach their common superview after the same number of steps, so once they're level, climbing in lockstep makes them meet exactly there. This is the parent-pointer version of [Lowest common ancestor](/dsa/learn/bt-lca), and the same trick finds where two linked lists intersect.

```swift
public enum SharedSuperview {
    private static func depth(of view: String, _ superviewOf: [String: String]) -> Int {
        var depth = 0
        var current = view
        while let parent = superviewOf[current] {
            depth += 1
            current = parent
        }
        return depth
    }

    /// Walks up `steps` levels.
    private static func lift(_ view: String, by steps: Int, _ superviewOf: [String: String]) -> String {
        var current = view
        for _ in 0..<steps {
            current = superviewOf[current]!          // safe: steps never exceed the depth
        }
        return current
    }

    public static func nearestCommonSuperview(_ a: String, _ b: String, superviewOf: [String: String]) -> String? {
        let depthA = depth(of: a, superviewOf), depthB = depth(of: b, superviewOf)
        var x = lift(a, by: max(0, depthA - depthB), superviewOf)
        var y = lift(b, by: max(0, depthB - depthA), superviewOf)
        while x != y {
            guard let upX = superviewOf[x], let upY = superviewOf[y] else { return nil }
            x = upX
            y = upY
        }
        return x
    }

    public static func path(from a: String, to b: String, superviewOf: [String: String]) -> [String]? {
        guard let shared = nearestCommonSuperview(a, b, superviewOf: superviewOf) else { return nil }
        var up: [String] = [a]
        while up.last! != shared {
            up.append(superviewOf[up.last!]!)
        }
        var down: [String] = [b]
        while down.last! != shared {
            down.append(superviewOf[down.last!]!)
        }
        down.removeLast()                            // `shared` is already the end of `up`
        return up + down.reversed()
    }
}
```

Every loop here is iterative, which matters: a recursive walk up a 100,000-view chain would overflow the stack inside a test. With many queries on the same hierarchy, binary lifting answers each in O(log depth) after O(n log n) preparation, as in [LCA with binary lifting](/dsa/learn/ag-lca-binary-lifting).

</Approach>
