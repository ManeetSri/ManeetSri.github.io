Software versions are written like `1.10.2`: a major, a minor and a patch number. Make a `Version` struct that can be read from text, compared, sorted and printed.

`VersionOrdering.Version`, with `init?(_ text: String)`, `static func < (lhs: Version, rhs: Version) -> Bool` and `var description: String`

- `init?(_ text: String)` accepts exactly three non-empty runs of digits separated by dots, and returns `nil` for anything else. Leading zeros are allowed and don't change the value: `01.02.3` is version 1.2.3.
- `<` orders by major, then minor, then patch, comparing them **as numbers**.
- `description` writes the version as `major.minor.patch`.

The struct already has `major`, `minor` and `patch` properties and a memberwise-style `init(major:minor:patch:)`. `Equatable` comes free, because all three properties are `Int`.

## Examples

| Code | Result |
| --- | --- |
| `Version("1.10.2")` | major 1, minor 10, patch 2 |
| `Version("1.2")` | `nil`: only two parts |
| `Version("1..2.3")` | `nil`: an empty part |
| `Version("1.2.0")! < Version("1.10.0")!` | `true`: 2 is less than 10 |
| `["1.10.0", "1.2.3", "0.9.9"]`, parsed and sorted | `0.9.9`, `1.2.3`, `1.10.0` |
| `"v\(Version("01.02.03")!)"` | `"v1.2.3"` |

## Constraints

- `text` has at most 30 characters.
- Each part of a valid version has at most 9 digits, so it fits in an `Int`.
- Your `<` must return `false` when the two versions are equal.

<Hints>
<Hint>
Comparing the strings `"1.10.0"` and `"1.2.0"` puts `1.10.0` first, because the character `1` comes before `2`. That's why the parts must be compared as numbers.
</Hint>
<Hint>
To compare by major, then minor, then patch, compare tuples: `(lhs.major, lhs.minor, lhs.patch) < (rhs.major, rhs.minor, rhs.patch)`.
</Hint>
<Hint>
`text.split(separator: ".")` quietly drops empty parts, so `"1..2.3"` would look valid. Pass `omittingEmptySubsequences: false` to keep them, then check you have exactly three parts and that each is a non-empty run of digits before converting it with `Int(_:)`.
</Hint>
</Hints>

## Solutions

<Approach title="Split, check, compare tuples" time="O(n) to parse, O(1) to compare" space="O(n)">

Parsing splits the text on dots, keeping empty parts so that they can be rejected, and checks each part before converting it. After that, the failable initialiser hands the numbers to the memberwise-style initialiser with `self.init`. Comparison uses tuples, which order element by element.

```swift
public enum VersionOrdering {
    public struct Version: Comparable, CustomStringConvertible {
        public let major: Int
        public let minor: Int
        public let patch: Int

        public init(major: Int, minor: Int, patch: Int) {
            self.major = major
            self.minor = minor
            self.patch = patch
        }

        public init?(_ text: String) {
            let parts = text.split(separator: ".", omittingEmptySubsequences: false)
            guard parts.count == 3 else { return nil }
            var numbers: [Int] = []
            for part in parts {
                guard !part.isEmpty, part.allSatisfy({ $0.isASCII && $0.isNumber }), let number = Int(part) else {
                    return nil
                }
                numbers.append(number)
            }
            self.init(major: numbers[0], minor: numbers[1], patch: numbers[2])
        }

        public static func < (lhs: Version, rhs: Version) -> Bool {
            (lhs.major, lhs.minor, lhs.patch) < (rhs.major, rhs.minor, rhs.patch)
        }

        public var description: String {
            "\(major).\(minor).\(patch)"
        }
    }
}
```

Why check the characters when `Int(_:)` already rejects letters? Because `Int("+1")` and `Int("-1")` succeed, and a version part shouldn't have a sign. Checking `isASCII && isNumber` allows only the digits 0 to 9.

Once `<` exists, `sorted()`, `min()`, `max()`, `>` and `<=` all work without any more code.

</Approach>
