Gray code lists every `width`-bit number so that neighbours differ in exactly one bit: step i holds `i ^ (i >> 1)`. Generate it, decode it, and use it to walk through every subset of some prices while changing one item per step.

`GrayCodeWalk.sequence(width: Int) -> [Int]` returns all 2^width Gray codes, step 0 first.

`GrayCodeWalk.step(ofCode code: Int) -> Int` returns the step i whose Gray code is `code`: the inverse of `i ^ (i >> 1)`.

`GrayCodeWalk.subsetTotals(_ prices: [Int]) -> [Int]` visits the subsets of `prices` in Gray code order, where the subset at step i holds item j exactly when bit j of `i ^ (i >> 1)` is 1. It returns the total of each subset in that order. Update the total with one addition or subtraction per step, rather than adding up each subset from scratch.

## Examples

| Call | Output |
| --- | --- |
| `sequence(width: 2)` | `[0, 1, 3, 2]` |
| `sequence(width: 3)` | `[0, 1, 3, 2, 6, 7, 5, 4]` |
| `step(ofCode: 6)` | `4` |
| `step(ofCode: 4)` | `7` |
| `subsetTotals([3, 1, 4])` | `[0, 3, 4, 1, 5, 8, 7, 4]` |

In the last example the subsets go \{\}, \{3\}, \{3, 1\}, \{1\}, \{1, 4\}, \{3, 1, 4\}, \{3, 4\}, \{4\}: each one adds or removes a single price.

## Constraints

- `sequence`: `0 ≤ width ≤ 20`. Width 0 has a single code, `[0]`.
- `step`: `0 ≤ code < 2⁶²`.
- `subsetTotals`: `0 ≤ prices.count ≤ 20`, prices between −10⁹ and 10⁹. Aim for O(2ⁿ), not O(2ⁿ × n).

<Hints>
<Hint>
`sequence` is a one-liner over `0..<(1 << width)`. For `step`, each bit of i is the XOR of all the Gray bits at or above it, so XOR together `code`, `code >> 1`, `code >> 2`, … until the shift reaches 0.
</Hint>
<Hint>
Going from step i − 1 to step i, exactly one bit of the Gray code changes, and it's bit `i.trailingZeroBitCount`. So exactly one item joins or leaves the subset at each step.
</Hint>
<Hint>
To tell whether that item joined or left, look at its bit in the new Gray code, `i ^ (i >> 1)`: if it's 1, the item was added, so add its price; if it's 0, subtract it. Start from a total of 0 for the empty subset at step 0.
</Hint>
</Hints>

## Solutions

<Approach title="Add up every subset from scratch" time="O(2ⁿ × n)" space="O(2ⁿ)">

For each step, compute the Gray code and add the price of every set bit. It's correct, and it's exactly what the lesson improved on: each subset costs up to n additions.

</Approach>

<Approach title="Change one item per step" time="O(2ⁿ)" space="O(2ⁿ) for the output">

The bit that changes on the way to step i is at position `i.trailingZeroBitCount`, because adding 1 to i flips a run of low bits and only the top of that run changes the XOR of neighbours. Checking that bit in the new code says whether the item came in or went out, so each total comes from the previous one in O(1).

```swift
public enum GrayCodeWalk {
    public static func sequence(width: Int) -> [Int] {
        (0..<(1 << width)).map { $0 ^ ($0 >> 1) }
    }

    public static func step(ofCode code: Int) -> Int {
        var value = code
        var shifted = code >> 1
        while shifted != 0 {
            value ^= shifted
            shifted >>= 1
        }
        return value
    }

    public static func subsetTotals(_ prices: [Int]) -> [Int] {
        var totals = [0]
        var total = 0
        for i in 1..<(1 << prices.count) {
            let item = i.trailingZeroBitCount
            let gray = i ^ (i >> 1)
            if gray & (1 << item) != 0 {
                total += prices[item]
            } else {
                total -= prices[item]
            }
            totals.append(total)
        }
        return totals
    }
}
```

When `prices` is empty, `1 << 0` is 1 and the loop `1..<1` doesn't run, so the answer is `[0]`: the empty subset alone. The whole walk does 2ⁿ − 1 updates, against about 2ⁿ × n / 2 additions for the from-scratch version.

</Approach>
