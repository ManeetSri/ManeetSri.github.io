Two guarantees from the pigeonhole principle: one that counts how many draws make a match certain, and one that finds a collision that's certain to exist.

`PigeonholeGuarantees.drawsToGuarantee(matching k: Int, counts: [Int]) -> Int?` A drawer holds `counts[i]` socks of colour i. You draw socks in the dark, one at a time. Return the fewest draws that **guarantee** at least k socks of the same colour, however unlucky you are, or `nil` if no colour has k socks at all.

`PigeonholeGuarantees.sharedRemainder(_ numbers: [Int]) -> (first: Int, second: Int)` `numbers` holds n + 1 values. Two of them must leave the same remainder when divided by n, so their difference is a multiple of n. Return the indexes of such a pair, first less than second. Of all such pairs, return the one whose `second` index is smallest.

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `drawsToGuarantee(matching: 2, counts: [5, 5, 5])` | `4` | 3 draws can be one of each colour |
| `drawsToGuarantee(matching: 3, counts: [2, 10, 1])` | `6` | the worst 5 draws: 2, 2 and 1 of each |
| `drawsToGuarantee(matching: 4, counts: [3, 3])` | `nil` | no colour has 4 socks |
| `sharedRemainder([3, 9, 4, 7])` | `(0, 1)` | 9 − 3 = 6, a multiple of 3 |
| `sharedRemainder([1, 5, -2, 8, 6])` | `(0, 1)` | 5 − 1 = 4, a multiple of 4 |
| `sharedRemainder([2, 7, 4, 13, 9])` | `(3, 4)` | remainders 2, 3, 0, 1, 1 modulo 4: 13 and 9 differ by 4 |

## Constraints

- `drawsToGuarantee`: `1 ≤ k ≤ 10⁹`, `1 ≤ counts.count ≤ 10⁵`, `0 ≤ counts[i] ≤ 10⁹`.
- `sharedRemainder`: `2 ≤ numbers.count ≤ 10⁵`, and values are between −10¹⁸ and 10¹⁸, so they can be negative. Take O(n) time.

<Hints>
<Hint>
For the socks, think like an adversary handing you socks: they'll give you as many as possible **without** making k of a kind. From a colour with c socks, that's at most k − 1, but never more than c. Add those up over every colour: one more draw then forces a match.
</Hint>
<Hint>
For the remainders, there are n + 1 numbers but only n possible remainders, 0 to n − 1. Walk through the numbers keeping an array `firstSeen` of size n, holding the first index with each remainder (or −1). The first time you meet a remainder you've seen before, you've found the pair with the smallest second index.
</Hint>
<Hint>
Swift's `%` keeps the sign of the left side, so `-2 % 4` is −2. Turn a negative remainder into one in `0..<n` by adding n before using it as an index.
</Hint>
</Hints>

## Solutions

<Approach title="Check every pair" time="O(n²)" space="O(1)">

For `sharedRemainder`, try each second index j from left to right and every first index i before it, and return the first pair whose remainders match. Comparing remainders instead of subtracting avoids overflow. It works, but 10⁵ numbers make about 5 × 10⁹ comparisons.

</Approach>

<Approach title="Count the worst case, and remember first remainders" time="O(colours) and O(n)" space="O(1) and O(n)">

**Socks.** The worst case is k − 1 socks of every colour that has that many, and all the socks of every colour that doesn't. Any further draw must complete k of some colour, provided some colour can reach k. That's the general pigeonhole principle: with N items in m boxes, some box gets at least ⌈N / m⌉.

**Remainders.** n + 1 values and n remainders force a repeat, so the loop always returns before it runs out of numbers. The first repeat found while scanning left to right has the smallest possible second index.

```swift
public enum PigeonholeGuarantees {
    public static func drawsToGuarantee(matching k: Int, counts: [Int]) -> Int? {
        guard counts.contains(where: { $0 >= k }) else {
            return nil
        }
        var safeDraws = 0
        for count in counts {
            safeDraws += min(count, k - 1)
        }
        return safeDraws + 1
    }

    public static func sharedRemainder(_ numbers: [Int]) -> (first: Int, second: Int) {
        let n = numbers.count - 1
        var firstSeen = Array(repeating: -1, count: n)
        for (index, value) in numbers.enumerated() {
            var remainder = value % n
            if remainder < 0 {
                remainder += n
            }
            if firstSeen[remainder] != -1 {
                return (firstSeen[remainder], index)
            }
            firstSeen[remainder] = index
        }
        return (-1, -1)
    }
}
```

The final `return (-1, -1)` is never reached: the pigeonhole principle guarantees a repeat. The sock total fits easily, since 10⁵ colours of at most 10⁹ socks is at most 10¹⁴.

</Approach>
