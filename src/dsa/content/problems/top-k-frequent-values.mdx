Return the `k` values that appear **most often** in an array, most frequent first. Values that appear the same number of times go **smaller value first**. If the array has fewer than `k` distinct values, return all of them, in the same order.

`TopFrequentValues.mostFrequent(_ values: [Int], k: Int) -> [Int]`

Aim for O(n + m log k), where m is the number of distinct values: better than sorting all m when k is small.

## Examples

| `values` | `k` | Returns |
| --- | --- | --- |
| `[4, 1, 4, 2, 4, 1, 3]` | `2` | `[4, 1]` |
| `[4, 1, 4, 2, 4, 1, 3]` | `4` | `[4, 1, 2, 3]` |
| `[7, 7, 8, 8, 9]` | `2` | `[7, 8]` |
| `[-2, -2, 5, 5, 0]` | `1` | `[-2]` |
| `[1, 2, 3]` | `5` | `[1, 2, 3]` |
| `[]` | `3` | `[]` |

In the first row, 4 appears three times and 1 twice. In the fourth, -2 and 5 both appear twice, and -2 is smaller.

## Constraints

- `0 ≤ values.count ≤ 200,000`, `1 ≤ k ≤ 200,000`
- Any `Int` values.

<Hints>
<Hint>
Start by counting: a `[Int: Int]` dictionary from value to count, in one pass. Now the question is "the k best of m (value, count) pairs", where better means a higher count, or the same count and a smaller value.
</Hint>
<Hint>
To keep the k **best**, keep a heap whose top is the **worst** of them. A new pair gets in only if it beats that top, and then it replaces it. Write one function, `isWorse(a, b)`, and use it as the heap's order.
</Hint>
<Hint>
At the end, popping the heap gives the k best from worst to best. Reverse that. Dictionary order is random, but the result isn't: the tie-break makes "better" a total order.
</Hint>
</Hints>

## Solutions

<Approach title="Count, then sort the distinct values" time="O(n + m log m)" space="O(m)">

Short and clear. When there are many distinct values and k is small, most of the sorting is wasted.

```swift
public static func mostFrequent(_ values: [Int], k: Int) -> [Int] {
    var counts: [Int: Int] = [:]
    for value in values { counts[value, default: 0] += 1 }
    let ranked = counts.sorted { $0.value != $1.value ? $0.value > $1.value : $0.key < $1.key }
    return ranked.prefix(k).map(\.key)
}
```

</Approach>

<Approach title="Count, then keep the k best in a heap" time="O(n + m log k)" space="O(m)">

The heap holds at most k pairs, so each of the m distinct values costs O(log k).

```swift
import DSAKit

public enum TopFrequentValues {
    public static func mostFrequent(_ values: [Int], k: Int) -> [Int] {
        var counts: [Int: Int] = [:]
        for value in values {
            counts[value, default: 0] += 1
        }
        // a comes before b when it's worse: fewer copies, or as many copies and a larger value
        func isWorse(_ a: (value: Int, count: Int), _ b: (value: Int, count: Int)) -> Bool {
            a.count != b.count ? a.count < b.count : a.value > b.value
        }
        var best = Heap<(value: Int, count: Int)>(areInIncreasingOrder: isWorse)
        for (value, count) in counts {
            if best.count < k {
                best.insert((value, count))
            } else if let worst = best.peek(), isWorse(worst, (value, count)) {
                best.replaceTop(with: (value, count))
            }
        }
        var result: [Int] = []
        while let entry = best.pop() {
            result.append(entry.value)
        }
        return result.reversed()
    }
}
```

There's also an O(n) approach with **buckets**: an array indexed by count, where bucket c lists the values that appear c times. Walk the buckets from the highest count down, sorting each bucket's values, until you have k. It's linear when the buckets are small, as in bucket sort.

</Approach>
