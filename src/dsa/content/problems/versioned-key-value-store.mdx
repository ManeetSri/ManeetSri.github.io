Build a key-value store that never forgets: every `set` is stamped with a time, and you can ask what any key's value was at any moment, past or present.

`VersionedKeyValueStore.Store<Key: Hashable, Value>`, with `init()`, `set(_:for:at:)` and `value(for:at:) -> Value?`

- The times passed to `set` strictly increase from one call to the next, across all keys.
- `value(for: key, at: t)` returns the value set for `key` at the latest time that is **at or before** `t`, or `nil` if the key had no value yet at `t`. `t` can be any time: before the first `set`, between two, or later than the last.
- `set` should be amortised O(1), and `value(for:at:)` O(log v) for a key with v versions.

## Examples

With `var settings = Store<String, String>()`:

| Calls | Result |
| --- | --- |
| `set("light", for: "theme", at: 10)`, `set("dark", for: "theme", at: 20)` | |
| `value(for: "theme", at: 5)` | `nil`: nothing was set yet |
| `value(for: "theme", at: 10)` | `"light"` |
| `value(for: "theme", at: 15)` | `"light"` |
| `value(for: "theme", at: 20)` | `"dark"` |
| `value(for: "theme", at: 1_000)` | `"dark"` |
| `value(for: "font", at: 15)` | `nil`: never set |

## Constraints

- Up to 100,000 calls to `set` and 200,000 calls to `value(for:at:)`.
- A single key can have tens of thousands of versions.
- `Store` is a struct: a copy is an independent store.

<Hints>
<Hint>
Give each key its own history: a dictionary from key to an array of `(time, value)` pairs. Because times only increase, appending a new version keeps each array sorted by time, with no sorting needed.
</Hint>
<Hint>
The answer for time `t` is the **last** version whose time is ≤ `t`. Scanning backwards works, but costs O(v). In a sorted array, "last element ≤ t" is one step before "first element > t", which is exactly the upper bound from [Lower bound, upper bound, first and last occurrence](/dsa/learn/bs-bounds).
</Hint>
<Hint>
Find the index of the first version with `time > t` by binary search (or with DSAKit's `partitionPoint(where:)`). If it's 0, there's no answer; otherwise the answer is the version immediately before it.
</Hint>
</Hints>

## Solutions

<Approach title="Scan each key's history from the newest" time="O(1) set, O(v) lookup" space="O(total versions)">

Store the versions the same way, but search them from the end until a time ≤ `t` turns up. Queries about the recent past are fast; queries about the distant past of a busy key walk almost the whole array.

```swift
public func value(for key: Key, at time: Int) -> Value? {
    versions[key]?.last { $0.time <= time }?.value
}
```

</Approach>

<Approach title="Sorted histories and binary search" time="amortised O(1) set, O(log v) lookup" space="O(total versions)">

`versions[key, default: []].append(...)` modifies the array inside the dictionary in place, so a key with 20,000 versions isn't copied on every `set`. The search uses DSAKit's `partitionPoint(where:)`, which finds the first element for which the condition is true.

```swift
import DSAKit

public enum VersionedKeyValueStore {
    public struct Store<Key: Hashable, Value> {
        private var versions: [Key: [(time: Int, value: Value)]] = [:]

        public init() {}

        public mutating func set(_ value: Value, for key: Key, at time: Int) {
            versions[key, default: []].append((time, value))   // in place: no copy of the array
        }

        public func value(for key: Key, at time: Int) -> Value? {
            guard let history = versions[key] else { return nil }
            let later = history.partitionPoint { $0.time > time }   // the first version after `time`
            return later == 0 ? nil : history[later - 1].value
        }
    }
}
```

If times could arrive out of order, appending would no longer keep the arrays sorted. Then each key would need an ordered map, such as DSAKit's `SortedMap` and its `floor(_:)`, for O(log v) inserts as well as lookups.

</Approach>
