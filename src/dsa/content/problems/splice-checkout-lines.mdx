Build a linked-list queue with one extra trick that arrays can't do cheaply: when a checkout closes, its whole line joins the back of another line in O(1), however many people are in it.

`SpliceableLinkedQueue.LinkedQueue<Element>`, a class with `init()`, `enqueue(_:)`, `dequeue() -> Element?`, `peek() -> Element?`, `count: Int`, `isEmpty: Bool`, `values: [Element]` and `absorb(_ other: LinkedQueue<Element>)`

- `enqueue`, `dequeue`, `peek`, `count` and `isEmpty` are O(1) in the worst case. `dequeue()` and `peek()` return `nil` for an empty queue.
- `values` lists the items from front to back, for checking; it can be O(n).
- `absorb(other)` moves every item of `other` to the back of this queue, in order, and leaves `other` empty but still usable. It must be O(1). If `other` is this same queue, nothing happens.

It's a class because its nodes are: two copies of a struct holding the same `head` and `tail` would quietly share the same chain of nodes.

## Examples

| Code | Result |
| --- | --- |
| `a` holds 1, 2 and `b` holds 3, 4; then `a.absorb(b)` | `a.values` is `[1, 2, 3, 4]` and `b.values` is `[]` |
| then `b.enqueue(9)` | `b.values` is `[9]` and `a.values` is still `[1, 2, 3, 4]` |
| `a` is empty and `b` holds 5; `a.absorb(b)`, then `a.enqueue(6)` | `a.values` is `[5, 6]` |
| `a` holds 1 and `b` is empty; `a.absorb(b)` | `a.values` is `[1]` |
| enqueue 1, dequeue twice, then enqueue 2 | `1`, then `nil`, then `values` is `[2]` |
| `a.absorb(a)` | nothing changes |

## Constraints

- Up to 200,000 operations, including up to 100,000 absorbs of queues holding thousands of items.
- Don't store the items in an array: use nodes, so that absorbing is a handful of pointer changes.

<Hints>
<Hint>
Keep `head` (the front, where you dequeue), `tail` (the back, where you enqueue) and `count`. The empty case is where bugs hide: enqueueing into an empty queue sets `head` as well as `tail`, and dequeueing the last node must clear `tail` as well as `head`.
</Hint>
<Hint>
Absorbing joins two chains: this queue's `tail.next` becomes `other.head`, and this queue's `tail` becomes `other.tail`. If this queue is empty, its `head` becomes `other.head` instead. Add the counts. Absorbing an empty queue changes nothing.
</Hint>
<Hint>
Then reset `other` completely: `head`, `tail` and `count`. If `other.tail` still pointed at the last node, its next `enqueue` would link a node onto **this** queue's chain. And check `other === self` first, or the reset would empty the queue you're adding to.
</Hint>
</Hints>

## Solutions

<Approach title="Absorb by dequeuing everything" time="O(k) per absorb" space="O(n)">

Moving the items one at a time with `while let item = other.dequeue() { enqueue(item) }` gives the right order and leaves `other` empty, but it costs one step per item moved. Lines that absorb each other back and forth, thousands of items at a time, make that far too slow.

</Approach>

<Approach title="Splice the chains" time="O(1) per operation" space="O(n)">

A queue is just a chain of nodes with a pointer at each end, so joining two queues means one `next` and two end pointers. Nothing is copied and no node is visited.

```swift
public enum SpliceableLinkedQueue {
    public final class LinkedQueue<Element> {
        private final class Node {
            let value: Element
            var next: Node?
            init(_ value: Element) { self.value = value }
        }

        private var head: Node?                  // the front: dequeue here
        private var tail: Node?                  // the back: enqueue here
        public private(set) var count = 0

        public init() {}

        public var isEmpty: Bool { head == nil }

        public func enqueue(_ element: Element) {
            let node = Node(element)
            if let tail {
                tail.next = node
            } else {
                head = node                      // empty queue: it's also the front
            }
            tail = node
            count += 1
        }

        public func dequeue() -> Element? {
            guard let front = head else { return nil }
            head = front.next
            if head == nil {
                tail = nil                       // that was the last node
            }
            count -= 1
            return front.value
        }

        public func peek() -> Element? {
            head?.value
        }

        public var values: [Element] {
            var result: [Element] = []
            var node = head
            while let current = node {
                result.append(current.value)
                node = current.next
            }
            return result
        }

        public func absorb(_ other: LinkedQueue<Element>) {
            guard other !== self, let otherHead = other.head else { return }
            if let tail {
                tail.next = otherHead
            } else {
                head = otherHead
            }
            tail = other.tail
            count += other.count
            other.head = nil                     // other must forget the nodes it gave away
            other.tail = nil
            other.count = 0
        }
    }
}
```

`private` members of a class can be reached from another instance of the same class, which is how `absorb` empties `other`.

</Approach>
