An old notebook holds a message encoded as in [Decode digit messages](/dsa/practice/digit-message-decodings): letters written as numbers, A = 1 up to Z = 26, run together into a string of digits. Some digits have been smudged and are shown as `"?"`. A smudge could be any digit from 0 to 9. Count every pair of (a way to read the smudges, a decoding of the resulting digits), and return the total modulo 1,000,000,007.

`SmudgedMessageDecoder.countDecodings(_ message: String) -> Int`

## Examples

| `message` | Output | Why |
| --- | --- | --- |
| `"?"` | `9` | 1 to 9 are letters; 0 isn't |
| `"1?"` | `19` | "10" reads one way; "11" to "19" read two ways each |
| `"??"` | `98` | 81 readings of two non-zero digits, plus the 17 numbers from 10 to 26 |
| `"?0"` | `2` | only "10" and "20" can be read |
| `"0?"` | `0` | nothing starts with 0 |
| `"2?6"` | `18` | |

## Constraints

- `1 ≤ message.count ≤ 100,000`
- `message` contains only the digits `0` to `9` and `"?"`.
- With many smudges there are up to 10¹⁰⁰⁰⁰⁰ ways to read them, so filling them in one by one is hopeless.

<Hints>
<Hint>
Start from the decode-ways DP: `ways[i]` counts the readings of the first i characters, built from `ways[i − 1]` (the last letter is one character) and `ways[i − 2]` (the last letter is two). What changes when a character could be several digits?
</Hint>
<Hint>
The last letter's characters can be read in several ways, and **each** of those combines with **every** reading of the prefix before them. So instead of adding `ways[i − 1]` once, add it once per way the last character can be a letter 1 to 9. Likewise for the last two characters and the numbers 10 to 26.
</Hint>
<Hint>
`ways[i] = singles × ways[i − 1] + pairs × ways[i − 2]`. For one character, `singles` is 9 for a smudge, 0 for a 0, and 1 otherwise. For `pairs`, work out the four cases: two digits, smudge then digit, digit then smudge, two smudges. (Two smudges give 17.) Reduce modulo 1,000,000,007 after each multiplication.
</Hint>
</Hints>

## Solutions

<Approach title="Fill in every smudge" time="O(10ᵏ × n)" space="O(n)">

For k smudges, try all 10ᵏ ways of filling them, and run the ordinary decode-ways DP on each result. It's the definition, so it's useful for checking, but even 7 smudges mean 10 million runs.

```swift
public static func countDecodings(_ message: String) -> Int {
    var digits = message.map { $0.wholeNumberValue ?? -1 }    // -1 marks a smudge
    let smudges = digits.indices.filter { digits[$0] == -1 }
    func decodings() -> Int {
        var (twoBack, oneBack) = (0, 1)
        for i in digits.indices {
            var current = digits[i] != 0 ? oneBack : 0
            if i >= 1, (10...26).contains(digits[i - 1] * 10 + digits[i]) {
                current += twoBack
            }
            (twoBack, oneBack) = (oneBack, current % 1_000_000_007)
        }
        return oneBack
    }
    func fill(_ k: Int) -> Int {
        if k == smudges.count {
            return decodings()
        }
        var total = 0
        for digit in 0...9 {
            digits[smudges[k]] = digit
            total = (total + fill(k + 1)) % 1_000_000_007
        }
        return total
    }
    return fill(0)
}
```

</Approach>

<Approach title="Count readings inside the transition" time="O(n)" space="O(n)">

Every pair (reading, decoding) ends with a last letter made of one or two characters. Group the pairs by that choice. If the last letter is the last character alone, the pair is a reading of that character as 1 to 9 (`singles` ways) together with any pair for the prefix before it (`ways[i − 1]`), and every combination is different. So that group has `singles × ways[i − 1]` members, and the two-character group has `pairs × ways[i − 2]`. The groups can't overlap, because their last letters have different lengths.

```swift
public enum SmudgedMessageDecoder {
    public static func countDecodings(_ message: String) -> Int {
        let modulus = 1_000_000_007
        let characters = Array(message.utf8)
        var (twoBack, oneBack) = (0, 1)                      // ways[i - 2] and ways[i - 1], starting at i = 1
        for i in characters.indices {
            var current = singles(characters[i]) * oneBack % modulus
            if i >= 1 {
                current = (current + pairs(characters[i - 1], characters[i]) * twoBack) % modulus
            }
            (twoBack, oneBack) = (oneBack, current)
        }
        return oneBack
    }

    private static let smudge = UInt8(ascii: "?")
    private static let zero = UInt8(ascii: "0")

    /// How many readings of one character are a one-digit letter, 1 to 9
    private static func singles(_ character: UInt8) -> Int {
        if character == smudge {
            return 9                                         // any digit but 0
        }
        return character == zero ? 0 : 1
    }

    /// How many readings of two characters make a two-digit letter, 10 to 26
    private static func pairs(_ first: UInt8, _ second: UInt8) -> Int {
        switch (first == smudge, second == smudge) {
        case (true, true):
            return 17                                        // 10...19 and 20...26
        case (true, false):
            let units = Int(second - zero)
            return units <= 6 ? 2 : 1                        // 1u always works, 2u only up to 26
        case (false, true):
            let tens = Int(first - zero)
            return tens == 1 ? 10 : tens == 2 ? 7 : 0        // 10...19, or 20...26, or nothing
        case (false, false):
            let number = Int(first - zero) * 10 + Int(second - zero)
            return (10...26).contains(number) ? 1 : 0
        }
    }
}
```

Both factors are below 1,000,000,007 (`singles` and `pairs` are at most 17), so each product fits easily in an `Int`. If the case analysis feels error-prone, compute `singles` and `pairs` by brute force instead, looping over the digits each character could be: at most 10 × 10 checks per position, still O(n).

</Approach>
