Decide whether a binary tree is a binary search tree: for **every** node, every value in its left subtree is smaller than the node's value, and every value in its right subtree is bigger.

`BSTValidate.isValid(_ root: TreeNode?) -> Bool`

Equal values make a tree invalid. The empty tree, and a single node, are valid.

## Examples

| Tree (level order) | Output |
| --- | --- |
| `[2, 1, 3]` | `true` |
| `[8, 3, 10, 1, 6, nil, 14, nil, nil, 4, 7, 13]` | `true` |
| `[10, 5, 15, nil, nil, 6, 20]` | `false` |
| `[5, 1, 4]` | `false` |
| `[2, 2]` | `false` |
| `[0, Int.min, Int.max]` | `true` |
| `[]` | `true` |

In `[10, 5, 15, nil, nil, 6, 20]`, every child is on the correct side of its own parent: 6 is smaller than 15. But 6 is in the **right** subtree of 10, so it should be bigger than 10. Checking each node against its parent alone misses this.

## Constraints

- `0 ≤` number of nodes `≤ 200,000`
- Values can be any `Int`, including `Int.min` and `Int.max`.
- Trees in the tests are at most 1,000 levels deep, so recursion is fine.

<Hints>
<Hint>
Every node has a range it must lie in, set by its ancestors. Going left from a node with value v, everything below must be less than v; going right, more than v. The root's range has no limits at all.
</Hint>
<Hint>
Pass the range down: `check(node, low, high)`. A left child gets `(low, node.value)` and a right child gets `(node.value, high)`. Make the bounds `Int?`, with `nil` meaning "no limit", so a tree that really holds `Int.min` or `Int.max` is judged correctly.
</Hint>
<Hint>
Another route: an inorder traversal of a BST visits values in increasing order, and only a BST does that. Walk inorder, remember the previous value, and fail as soon as a value isn't strictly bigger than the one before.
</Hint>
</Hints>

## Solutions

<Approach title="Inorder must be strictly increasing" time="O(n)" space="O(h)">

A binary tree is a BST exactly when its inorder traversal is strictly increasing. Walk inorder with a stack (or recursion) and compare each value with the previous one. Keeping the previous value as an `Int?` avoids a fake starting value like `Int.min`, which would reject a tree containing `Int.min`.

```swift
public static func isValid(_ root: TreeNode?) -> Bool {
    var stack: [TreeNode] = []
    var current = root
    var previous: Int? = nil
    while current != nil || !stack.isEmpty {
        while let node = current {
            stack.append(node)
            current = node.left
        }
        let node = stack.removeLast()
        if let previous, node.value <= previous {
            return false
        }
        previous = node.value
        current = node.right
    }
    return true
}
```

</Approach>

<Approach title="Bounds passed down" time="O(n)" space="O(h)">

Each node carries the open range its ancestors allow. `nil` means no limit on that side. A stack of (node, low, high) triples visits every node once; recursion with the same three parameters works equally well.

```swift
public enum BSTValidate {
    public static func isValid(_ root: TreeNode?) -> Bool {
        var stack: [(node: TreeNode, low: Int?, high: Int?)] = []
        if let root {
            stack.append((root, nil, nil))
        }
        while let (node, low, high) = stack.popLast() {
            if let low, node.value <= low { return false }
            if let high, node.value >= high { return false }
            if let left = node.left {
                stack.append((left, low, node.value))
            }
            if let right = node.right {
                stack.append((right, node.value, high))
            }
        }
        return true
    }
}
```

</Approach>
