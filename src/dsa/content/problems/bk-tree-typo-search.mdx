A spell checker needs, for each unknown word, the dictionary words within one or two edits of it. Comparing against every dictionary word is slow. A **BK-tree** uses the triangle inequality to skip most of them. Build one, and make its search report how many distances it computed, so you can see the pruning work.

`BKTreeTypoSearch.distance(_ a: String, _ b: String) -> Int` and `BKTreeTypoSearch.Tree`, with `init()`, `insert(_:)`, `count`, `root`, `children(of:) -> [Int: String]` and `search(_ query: String, tolerance: Int) -> SearchResult`

- `distance` is the Levenshtein distance: the fewest insertions, deletions and replacements of single `Character`s that turn `a` into `b`.
- `insert(word)`: an empty tree makes `word` its root. Otherwise, start at the root: compute `d`, the distance from `word` to the node. If `d` is 0, the word is already there, so do nothing. If the node has a child on the edge labelled `d`, move to that child and repeat; if not, hang `word` there.
- `count` is the number of words in the tree, `root` the first word inserted (or `nil`), and `children(of: word)` the node's edges, from edge label to child word (`[:]` for a leaf or a word that isn't in the tree).
- `search(query, tolerance: t)` visits the root. At each visited node it computes the distance `d` from the query: the node matches if `d ≤ t`, and only children on edges `e` with `|e − d| ≤ t` are visited. It returns a `SearchResult` with the matching `words`, closest first and then alphabetically, and `distancesComputed`, the number of nodes visited. An empty tree computes nothing.

## Examples

Inserting `book`, `books`, `moon`, `cake`, `boo` and `boon` in that order builds the tree from the lesson:

```text
                  book
          1 /     2 |     \ 4
        books      moon     cake
      2 /
      boo
    1 /
    boon
```

| Call | `words` | `distancesComputed` | Why |
| --- | --- | --- | --- |
| `search("bopk", tolerance: 1)` | `["book"]` | `5` | `d(bopk, book) = 1`, so edges 0 to 2 are visited and `cake` is skipped |
| `search("boo", tolerance: 1)` | `["boo", "book", "boon"]` | `5` | distances 0, 1 and 1 |
| `search("bake", tolerance: 1)` | `["cake"]` | `3` | `d(bake, book) = 3`: only edges 2 to 4, so `books` and everything below it are skipped |
| `search("xyzzy", tolerance: 9)` | all six, alphabetically | `6` | every word is 5 away |

| Call | Output |
| --- | --- |
| `children(of: "book")` | `[1: "books", 2: "moon", 4: "cake"]` |
| `children(of: "boon")` | `[:]` |
| `distance("kitten", "sitting")` | `3` |
| `distance("", "abc")` | `3` |
| `distance("café", "cafe")` | `1` |

## Constraints

- Up to 20,000 words, each up to 20 `Character`s of any Unicode. Inserting a word that's already present (including a different way of writing the same characters, like `"cafe\u{301}"` for `"café"`) changes nothing.
- `0 ≤ tolerance ≤ 5`.

<Hint>
Levenshtein distance with two rows of the DP table: `current[j]` is the minimum of `previous[j - 1]` plus 0 or 1 (keep or replace), `previous[j] + 1` (delete) and `current[j - 1] + 1` (insert). Convert both strings to `[Character]` first.
</Hint>
<Hint>
Store the tree in arrays: the words, and for each node a dictionary from edge label to child index. Also keep a dictionary from word to node index, so `children(of:)` is a lookup.
</Hint>
<Hint>
Why the pruning is safe: if a word `w` hangs below the edge `e`, then `distance(node, w) = e`. By the triangle inequality, `distance(query, w) ≥ |e − d|`. So when `|e − d| > t`, nothing below that edge can match. Search with an explicit stack: a tree built from words in an unlucky order can be deep.
</Hint>

## Solutions

<Approach title="An array-based BK-tree with a stack-based search" time="Insert O(depth × L²); search O(visited × L²)" space="O(words × L)">

Here L is the word length. Each distance costs O(L²), so the whole game is computing as few as possible. With a tolerance of 1, a search typically visits a small fraction of the tree; as the tolerance grows, the window `|e − d| ≤ t` admits more edges and the pruning fades.

```swift
public enum BKTreeTypoSearch {
    public struct SearchResult: Equatable {
        public let words: [String]
        public let distancesComputed: Int

        public init(words: [String], distancesComputed: Int) {
            self.words = words
            self.distancesComputed = distancesComputed
        }
    }

    public struct Tree {
        private var words: [[Character]] = []
        private var texts: [String] = []
        private var children: [[Int: Int]] = []                 // edge distance -> node index
        private var nodeOf: [String: Int] = [:]

        public init() {}

        public var count: Int { texts.count }

        public var root: String? { texts.first }

        public mutating func insert(_ word: String) {
            let letters = Array(word)
            guard !texts.isEmpty else {
                append(word, letters)
                return
            }
            var node = 0
            while true {
                let d = BKTreeTypoSearch.distance(letters, words[node])
                if d == 0 { return }                             // already in the tree
                if let next = children[node][d] {
                    node = next
                } else {
                    children[node][d] = texts.count
                    append(word, letters)
                    return
                }
            }
        }

        private mutating func append(_ word: String, _ letters: [Character]) {
            words.append(letters)
            texts.append(word)
            children.append([:])
            nodeOf[word] = texts.count - 1
        }

        public func children(of word: String) -> [Int: String] {
            guard let node = nodeOf[word] else { return [:] }
            return children[node].mapValues { texts[$0] }
        }

        public func search(_ query: String, tolerance: Int) -> SearchResult {
            guard !texts.isEmpty else { return SearchResult(words: [], distancesComputed: 0) }
            let letters = Array(query)
            var matches: [(distance: Int, word: String)] = []
            var computed = 0
            var stack = [0]                                      // explicit stack: depth can be large
            while let node = stack.popLast() {
                let d = BKTreeTypoSearch.distance(letters, words[node])
                computed += 1
                if d <= tolerance { matches.append((d, texts[node])) }
                for (edge, child) in children[node] where abs(edge - d) <= tolerance {
                    stack.append(child)
                }
            }
            matches.sort { ($0.distance, $0.word) < ($1.distance, $1.word) }
            return SearchResult(words: matches.map(\.word), distancesComputed: computed)
        }
    }

    public static func distance(_ a: String, _ b: String) -> Int {
        distance(Array(a), Array(b))
    }

    /// Levenshtein distance with two rows: insertions, deletions and replacements each cost 1.
    static func distance(_ a: [Character], _ b: [Character]) -> Int {
        if a.isEmpty { return b.count }
        var previous = Array(0...b.count)
        var current = previous
        for i in 1...a.count {
            current[0] = i
            for j in stride(from: 1, through: b.count, by: 1) {
                let replace = previous[j - 1] + (a[i - 1] == b[j - 1] ? 0 : 1)
                current[j] = min(replace, previous[j] + 1, current[j - 1] + 1)
            }
            swap(&previous, &current)
        }
        return previous[b.count]
    }
}
```

The tree depends on the distance being a **metric**: never negative, zero only for equal words, symmetric, and obeying the triangle inequality. Levenshtein distance is one. The "optimal string alignment" shortcut for swapped letters isn't, so a BK-tree built on it can silently miss matches, which is the trap the lesson's Damerau–Levenshtein milestone warns about.

</Approach>
