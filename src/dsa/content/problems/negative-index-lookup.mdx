Some languages let you count positions from the end of an array with negative numbers. Write a lookup that does the same safely: a position of 0 or more counts from the front as usual, and a negative position counts from the back, so `-1` is the last element and `-2` the one before it. Return `nil` for a position that's out of range in either direction.

`NegativeIndexLookup.element(in numbers: [Int], at position: Int) -> Int?`

## Examples

With `numbers = [10, 20, 30, 40]`:

| `position` | Output |
| --- | --- |
| `0` | `10` |
| `3` | `40` |
| `-1` | `40` |
| `-4` | `10` |
| `4` | `nil` |
| `-5` | `nil` |

For an empty array, every position gives `nil`.

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- `-1,000,000 ≤ position ≤ 1,000,000`
- Your function must never crash, whatever the position.

<Hints>
<Hint>
The last element is at index `numbers.count - 1`, so position `-1` means index `numbers.count + (-1)`. In general, a negative position `p` means index `numbers.count + p`.
</Hint>
<Hint>
Convert the position to an ordinary index first. Then a single bounds check works for both directions: a negative position that reaches too far back converts to a negative index, which the check rejects.
</Hint>
<Hint>
`numbers.indices.contains(index)` is `true` only for valid indexes, and it's always `false` for an empty array. Put it in a `guard ... else { return nil }`.
</Hint>
</Hints>

## Solutions

<Approach title="Convert, then check once" time="O(1)" space="O(1)">

Turn a negative position into the index it stands for by adding `count`. After that, the question is the same in both directions: is this a real index? `indices.contains` answers it without any risk of crashing, and reading by index is O(1), however long the array is.

```swift
public enum NegativeIndexLookup {
    public static func element(in numbers: [Int], at position: Int) -> Int? {
        let index = position < 0 ? numbers.count + position : position
        guard numbers.indices.contains(index) else { return nil }
        return numbers[index]
    }
}
```

Try `-5` on the four-element example: the index is `4 + (-5)`, which is `-1`, and `0..<4` doesn't contain it, so the answer is `nil`. And `-4` gives index `0`, the first element.

The common bug is checking `position < numbers.count` and forgetting that a converted index can still be negative. `indices.contains` checks both ends at once, which is why it's the safer habit.

</Approach>
