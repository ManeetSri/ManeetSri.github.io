One trick a release build's optimiser uses is deleting work whose result is never used, which is why timing a loop you never print can report almost zero. Write that pass yourself for a tiny straight-line language.

`DeadCodeEliminator.optimise(_ program: [String]) -> [String]`

Each line of the program is one of:

| Line | Means |
| --- | --- |
| `print v` | prints `v`, a variable or a whole number |
| `x = a` | stores `a` in `x` |
| `x = a + b`, `x = a - b`, `x = a * b` | stores the result in `x` |

Operands are variable names (lowercase letters) or whole numbers, and every word is separated by a single space. Return the lines to keep, in their original order:

- Every `print` is kept.
- An assignment is kept only if a **kept** line later reads the value it stores, before the variable is assigned again.

## Examples

| Program | Kept |
| --- | --- |
| `a = 4`, `b = a * 2`, `c = 7`, `print b` | `a = 4`, `b = a * 2`, `print b` |
| `x = 1`, `x = 2`, `print x` | `x = 2`, `print x` |
| `total = 0`, `total = total + 5`, `total = total + 6`, `print total` | all four lines |
| `a = 1`, `b = a + 1`, `c = b * b` | nothing |
| `n = 10`, `print n`, `n = n + 1` | `n = 10`, `print n` |
| `a = 2`, `b = a + 3`, `c = b * 4`, `d = 9`, `print d` | `d = 9`, `print d` |

In the last example, `c` is never read, so its line goes. That makes `b` unread, and then `a`: removing dead code can make earlier code dead too.

## Constraints

- Up to 10,000 lines.
- A variable may be read before it's ever assigned; treat it as coming from outside the program.

<Hints>
<Hint>
Whether a line is needed depends on what comes *after* it, so walk the program backwards, from the last line to the first.
</Hint>
<Hint>
Keep a set of the variables that are still needed: some kept line further down will read their current value. A `print v` line is kept and adds `v`. An assignment to `x` is kept only if `x` is in the set.
</Hint>
<Hint>
For a kept assignment, first remove `x` from the set (this line sets it, so nothing earlier needs to), then add each operand that's a name. That order matters for `total = total + 5`, which still needs the earlier `total`. A word is a name if its first character `isLetter`.
</Hint>
</Hints>

## Solutions

<Approach title="One backward pass with a needed set" time="O(n)" space="O(n)">

Going backwards, the set always holds exactly the variables whose current value matters to something below. So each line is decided the moment it's reached, and a chain of dead lines disappears in one pass. Working forwards instead, you'd have to delete dead lines and then go round again, once for every link in a chain like the last example. Compilers call this backward idea **liveness analysis**.

```swift
public enum DeadCodeEliminator {
    public static func optimise(_ program: [String]) -> [String] {
        var needed = Set<String>()
        var kept: [String] = []

        for line in program.reversed() {
            let words = line.split(separator: " ").map(String.init)
            if words[0] == "print" {
                kept.append(line)
                markNeeded(words[1], in: &needed)
            } else if needed.contains(words[0]) {
                kept.append(line)
                needed.remove(words[0])
                markNeeded(words[2], in: &needed)
                if words.count == 5 {
                    markNeeded(words[4], in: &needed)
                }
            }
        }
        return kept.reversed()
    }

    private static func markNeeded(_ operand: String, in needed: inout Set<String>) {
        if let first = operand.first, first.isLetter {
            needed.insert(operand)
        }
    }
}
```

This is why the timing lesson insists on using every result. A program with no `print` keeps nothing at all, and a real optimiser can do the same to a loop whose answer you never look at.

</Approach>
