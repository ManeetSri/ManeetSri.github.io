Given an unsorted array of non-negative integers, return the **largest difference between two neighbours** once the array is sorted. If there are fewer than two values, return 0. Do it in linear time.

`WidestGap.widestGap(in numbers: [Int]) -> Int`

## Examples

| `numbers` | Returns |
| --- | --- |
| `[3, 9, 1, 14, 6]` | `5` |
| `[20, 4, 12, 8, 16]` | `4` |
| `[100, 3, 99, 1, 98, 2]` | `95` |
| `[7, 7, 7]` | `0` |
| `[1, 1000000000]` | `999999999` |
| `[10]` | `0` |

Sorted, the first example is 1, 3, 6, 9, 14: the gaps are 2, 3, 3 and 5. In the third, the widest gap is between 3 and 98.

## Constraints

- `0 ≤ numbers.count ≤ 200,000`
- `0 ≤ numbers[i] ≤ 1,000,000,000`
- Sorting with `sort()` and scanning is O(n log n). Aim for O(n). (`import DSAKit` is at the top of the file if you want `radixSorted()`.)

<Hints>
<Hint>
One honest O(n) route: radix sort the numbers, then compare neighbours. Can you avoid sorting altogether?
</Hint>
<Hint>
With n values from `low` to `high`, there are n − 1 gaps adding up to `high - low`. So the widest gap is at least the average, `(high - low) / (n - 1)`. That's the pigeonhole principle.
</Hint>
<Hint>
Split the range into buckets narrower than that average. Two values in the same bucket are closer than the widest gap, so the answer is always **between** buckets: some bucket's largest value and the next non-empty bucket's smallest. Each bucket only needs to remember its smallest and largest value.
</Hint>
</Hints>

## Solutions

<Approach title="Sort, then scan" time="O(n log n)" space="O(n)">

The direct answer, and a good way to check the faster one.

```swift
public static func widestGap(in numbers: [Int]) -> Int {
    let sorted = numbers.sorted()
    return zip(sorted, sorted.dropFirst()).map { $1 - $0 }.max() ?? 0
}
```

`zip(sorted, sorted.dropFirst())` pairs each value with the next one. Swapping `sorted()` for DSAKit's `radixSorted()` makes this O(n), at the cost of eight passes over the array.

</Approach>

<Approach title="Pigeonhole buckets" time="O(n)" space="O(n)">

Choose a bucket width no bigger than the average gap, rounded down, and at least 1. Two values in one bucket differ by at most `width - 1`, which is less than the average gap, so less than the widest gap. So the widest gap can't be inside a bucket: it's a jump from one non-empty bucket's largest value to the next non-empty bucket's smallest.

```swift
public enum WidestGap {
    public static func widestGap(in numbers: [Int]) -> Int {
        guard numbers.count > 1, let low = numbers.min(), let high = numbers.max(), low < high else {
            return 0
        }
        let width = max(1, (high - low) / (numbers.count - 1))
        let bucketCount = (high - low) / width + 1
        var smallest = [Int?](repeating: nil, count: bucketCount)
        var largest = [Int?](repeating: nil, count: bucketCount)
        for value in numbers {
            let bucket = (value - low) / width
            smallest[bucket] = min(smallest[bucket] ?? value, value)
            largest[bucket] = max(largest[bucket] ?? value, value)
        }
        var widest = 0
        var previousLargest = low
        for bucket in 0..<bucketCount {
            guard let bucketSmallest = smallest[bucket], let bucketLargest = largest[bucket] else { continue }
            widest = max(widest, bucketSmallest - previousLargest)
            previousLargest = bucketLargest
        }
        return widest
    }
}
```

There are about n buckets, so the arrays are O(n), and every step is a single pass. The values inside a bucket are never sorted: only each bucket's extremes matter. Empty buckets are what make a wide gap, and the loop simply skips them, measuring from the last non-empty bucket. The first non-empty bucket always holds `low`, so starting `previousLargest` at `low` is safe.

</Approach>
