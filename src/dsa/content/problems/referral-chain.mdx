A sign-up scheme records who referred each new member: `referredBy["Dev"] == "Cleo"` means Cleo referred Dev. The founders weren't referred by anyone, so they have no entry. Starting from one person, follow the chain upwards a given number of steps and return who you reach.

`ReferralChain.ancestor(of person: String, steps: Int, in referredBy: [String: String]) -> String?`

- With `steps` equal to 0, the answer is `person` themselves.
- If the chain ends before you've taken all the steps (someone along the way has no referrer), return `nil`.

## Examples

With `referredBy = ["Ben": "Ana", "Cleo": "Ben", "Dev": "Cleo", "Eve": "Cleo"]`, so the chain above Dev is Dev → Cleo → Ben → Ana:

| Person, steps | Output | Why |
| --- | --- | --- |
| `"Dev", 1` | `"Cleo"` | Cleo referred Dev |
| `"Dev", 3` | `"Ana"` | Cleo, then Ben, then Ana |
| `"Eve", 2` | `"Ben"` | Cleo, then Ben |
| `"Dev", 0` | `"Dev"` | no steps taken |
| `"Dev", 4` | `nil` | Ana wasn't referred by anyone |
| `"Zoe", 1` | `nil` | Zoe has no referrer |

## Constraints

- `0 ≤ steps ≤ 10,000`
- `referredBy` has at most 10,000 entries.
- `person` may or may not appear in `referredBy`.

<Hints>
<Hint>
Each step is one dictionary lookup: `referredBy[current]` gives the referrer of `current`, or nil.
</Hint>
<Hint>
Keep a variable `current`, starting at `person`. Repeat `steps` times: look up the referrer, and move `current` to it. A `for _ in` loop repeats without needing the counter.
</Hint>
<Hint>
Inside the loop, `guard let referrer = referredBy[current] else { return nil }` stops as soon as the chain runs out. Careful with `for _ in 1...steps`: when `steps` is 0, `1...0` crashes. `stride(from: 0, to: steps, by: 1)` or `0..<steps` is empty instead.
</Hint>
</Hints>

## Solutions

<Approach title="One guarded lookup per step" time="O(steps)" space="O(1)">

Walk up the chain one link at a time. `guard let` unwraps each lookup, and returns `nil` the moment a link is missing. If every step succeeds, `current` is the answer.

```swift
public enum ReferralChain {
    public static func ancestor(of person: String, steps: Int, in referredBy: [String: String]) -> String? {
        var current = person
        for _ in stride(from: 0, to: steps, by: 1) {
            guard let referrer = referredBy[current] else {
                return nil
            }
            current = referrer
        }
        return current
    }
}
```

Each lookup takes about the same time however big the dictionary is, so the work grows only with the number of steps.

</Approach>

<Approach title="Chaining with flatMap" time="O(steps)" space="O(1)">

Keep the current person as an optional instead. Each step uses `flatMap` to look up the referrer *if* there's still someone to look up. Once the chain breaks, `current` becomes `nil` and stays `nil`, because `flatMap` on `nil` does nothing.

```swift
public static func ancestor(of person: String, steps: Int, in referredBy: [String: String]) -> String? {
    var current: String? = person
    for _ in 0..<steps {
        current = current.flatMap { referredBy[$0] }
    }
    return current
}
```

`flatMap` rather than `map`, because the lookup itself returns an optional: `map` would build a `String??`. This version is shorter, but it keeps looping after the chain has broken. You could add `if current == nil { break }` to stop early.

</Approach>
