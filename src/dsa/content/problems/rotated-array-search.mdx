An array of distinct numbers was sorted in increasing order, then rotated: some number of elements were moved from the front to the back, keeping their order. You aren't told how far. Return the index of `target`, or `nil` if it isn't there.

`RotatedArraySearch.index(of target: Int, in numbers: [Int]) -> Int?`

Aim for O(log n).

## Examples

| `target` | `numbers` | Output |
| --- | --- | --- |
| `10` | `[40, 50, 60, 70, 10, 20, 30]` | `4` |
| `70` | `[40, 50, 60, 70, 10, 20, 30]` | `3` |
| `35` | `[40, 50, 60, 70, 10, 20, 30]` | `nil` |
| `9` | `[1, 4, 6, 9, 12]` | `3` |
| `12` | `[12, 1, 4, 6, 9]` | `0` |
| `1` | `[3, 1]` | `1` |
| `5` | `[]` | `nil` |

The fourth example wasn't rotated at all, which counts as a rotation by 0.

## Constraints

- `0 ≤ numbers.count ≤ 1,000,000`
- All values are distinct.
- `numbers` is a rotation of an array sorted in increasing order.

<Hints>
<Hint>
Split the range at mid. The break, where a value is smaller than the one before it, can only be on one side, so at least one of the halves `low...mid` and `mid...high` is sorted. Comparing `numbers[low]` with `numbers[mid]` tells you which.
</Hint>
<Hint>
A sorted half holds exactly the values between its two ends. If the target is in that range, search that half; otherwise it can only be in the other half. Use `<=` in `numbers[low] <= numbers[mid]`: when the range is tiny, `low` and `mid` are the same index.
</Hint>
<Hint>
Another route: first find the index of the minimum, `shift`, by comparing `numbers[mid]` with `numbers[high]`. Sorted position k is then at index `(shift + k) % numbers.count`, so an ordinary binary search over positions finishes the job.
</Hint>
</Hints>

## Solutions

<Approach title="Find the minimum, then search sorted positions" time="O(log n)" space="O(1)">

The minimum's index is where sorted order starts. A first binary search finds it: if `numbers[mid] > numbers[high]`, the values drop somewhere after mid, so the minimum is to the right; otherwise it's mid or to the left. A second binary search runs over sorted positions, translating each into a real index with `%`.

```swift
public static func index(of target: Int, in numbers: [Int]) -> Int? {
    let n = numbers.count
    guard n > 0 else { return nil }
    var low = 0
    var high = n - 1
    while low < high {
        let mid = low + (high - low) / 2
        if numbers[mid] > numbers[high] { low = mid + 1 } else { high = mid }
    }
    let shift = low                              // where sorted order begins
    low = 0
    high = n - 1
    while low <= high {
        let mid = low + (high - low) / 2
        let index = (shift + mid) % n            // sorted position → real index
        if numbers[index] == target {
            return index
        } else if numbers[index] < target {
            low = mid + 1
        } else {
            high = mid - 1
        }
    }
    return nil
}
```

</Approach>

<Approach title="One pass: search the sorted half" time="O(log n)" space="O(1)">

At every step one half is sorted, and a range check against its ends says whether the target can be there. The other half might contain the break, but it doesn't matter: if the target isn't in the tidy half, it can only be in the other one.

```swift
public enum RotatedArraySearch {
    public static func index(of target: Int, in numbers: [Int]) -> Int? {
        var low = 0
        var high = numbers.count - 1
        while low <= high {
            let mid = low + (high - low) / 2
            if numbers[mid] == target {
                return mid
            }
            if numbers[low] <= numbers[mid] {
                // low...mid is sorted
                if numbers[low] <= target && target < numbers[mid] {
                    high = mid - 1
                } else {
                    low = mid + 1
                }
            } else {
                // mid...high is sorted
                if numbers[mid] < target && target <= numbers[high] {
                    low = mid + 1
                } else {
                    high = mid - 1
                }
            }
        }
        return nil
    }
}
```

The range checks leave out `numbers[mid]`, which was checked a moment ago, and include the far end of the sorted half, which hasn't. With repeated values this method can't always tell which half is sorted, and the worst case becomes O(n); that's why this problem promises distinct values.

</Approach>
