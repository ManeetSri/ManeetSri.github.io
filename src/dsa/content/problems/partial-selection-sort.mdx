Rearrange an array **in place** so that its first `k` positions hold the `k` smallest values, in increasing order. The other values can be in any order after them. If `k` is at least the array's length, sort the whole array.

`PartialSelectionSort.sortFirst(_ numbers: inout [Int], count k: Int)`

## Examples

| `numbers` | `k` | One possible result |
| --- | --- | --- |
| `[58, 41, 73, 39, 66, 45]` | `3` | `[39, 41, 45, 58, 66, 73]` |
| `[5, 1, 5, 1, 2]` | `2` | `[1, 1, 5, 5, 2]` |
| `[30, 20, 10]` | `1` | `[10, 20, 30]` |
| `[4, 2]` | `5` | `[2, 4]` |
| `[9, 8, 7]` | `0` | `[9, 8, 7]` |
| `[]` | `3` | `[]` |

Only the first `k` positions are checked exactly; the rest just have to hold the remaining values. So `[39, 41, 45, 73, 66, 58]` is also correct for the first example.

## Constraints

- `0 ≤ numbers.count ≤ 200,000` and `k ≥ 0`
- The large tests use 200,000 values with `k ≤ 5`. Aim for O(n · k) time and O(1) extra space, without sorting the whole array.

## Solutions

<Approach title="Sort everything" time="O(n log n)" space="O(1) to O(n)">

`numbers.sort()` puts the k smallest first, in order, along with everything else. It's correct, but it does far more work than needed when k is tiny, and it isn't what this problem is practising.

```swift
public static func sortFirst(_ numbers: inout [Int], count k: Int) {
    numbers.sort()
}
```

</Approach>

<Approach title="The first k passes of selection sort" time="O(n · k)" space="O(1)">

Selection sort's prefix is final after every pass, so k passes give exactly the k smallest values, in order. Each pass costs at most n comparisons and makes at most one swap.

```swift
public enum PartialSelectionSort {
    public static func sortFirst(_ numbers: inout [Int], count k: Int) {
        let passes = min(k, numbers.count)
        for i in 0..<passes {
            var smallest = i
            for j in (i + 1)..<numbers.count where numbers[j] < numbers[smallest] {
                smallest = j
            }
            if smallest != i {
                numbers.swapAt(i, smallest)
            }
        }
    }
}
```

`min(k, numbers.count)` handles both a k larger than the array and an empty array, where the loop runs no passes at all. With 200,000 values and k = 5, that's about a million comparisons, against several million for a full sort. For a large k, a heap does better, at O(n log k); you'll meet heaps in M39.

</Approach>
