A sawmill must cut a beam of length `length` at every position listed in `marks`. Each cut costs the length of the piece being cut at that moment, whatever its size. You may make the cuts in any order. Return the cheapest total cost.

`TimberCuttingCost.minimumCost(length: Int, marks: [Int]) -> Int`

## Examples

| `length` | `marks` | Output | A best order |
| --- | --- | --- | --- |
| `10` | `[7, 2, 4]` | `20` | 4 (10), then 2 (4), then 7 (6) |
| `10` | `[4, 5, 6]` | `18` | 4 (10), then 6 (6), then 5 (2) |
| `8` | `[2, 5]` | `13` | 5 (8), then 2 (5) |
| `100` | `[50]` | `100` | |
| `5` | `[]` | `0` | nothing to cut |

In the second example, starting in the middle at 5 costs 10 + 5 + 5 = 20.

## Constraints

- `2 ≤ length ≤ 1,000,000`
- `0 ≤ marks.count ≤ 200`, in any order, all different, with `0 < marks[i] < length`.
- The tests use 150 marks on a beam a million units long, so trying every order is impossible, and a table indexed by position along the beam would be enormous.

<Hints>
<Hint>
Sort the marks and add both ends of the beam: `points = [0] + sorted marks + [length]`. Every piece that ever exists runs from one point to another.
</Hint>
<Hint>
Let `best[left][right]` be the cheapest way to make every cut strictly between `points[left]` and `points[right]`. The **first** cut on that piece costs `points[right] - points[left]`, wherever it is, and leaves two pieces that never affect each other.
</Hint>
<Hint>
So `best[left][right] = points[right] - points[left] + min over k of best[left][k] + best[k][right]`, and a piece with no marks inside costs 0. Fill by increasing gap `right - left`.
</Hint>
</Hints>

## Solutions

<Approach title="Try every order" time="O(m! · m)" space="O(m)">

Simulate each order of cuts and keep the cheapest. Six marks already give 720 orders; 150 marks give more orders than there are atoms in the universe.

</Approach>

<Approach title="Interval DP over the marks" time="O(m³)" space="O(m²)">

The table has one row and column per point, not per unit of length, so the beam's length doesn't affect the running time.

```swift
public enum TimberCuttingCost {
    public static func minimumCost(length: Int, marks: [Int]) -> Int {
        let points = [0] + marks.sorted() + [length]
        let m = points.count
        guard m >= 3 else { return 0 }
        var best = Array(repeating: Array(repeating: 0, count: m), count: m)
        for gap in 2..<m {
            for left in 0..<(m - gap) {
                let right = left + gap
                var cheapest = Int.max
                for k in (left + 1)..<right {
                    cheapest = min(cheapest, best[left][k] + best[k][right])
                }
                best[left][right] = cheapest + points[right] - points[left]
            }
        }
        return best[0][m - 1]
    }
}
```

Read backwards, the cuts are merges of neighbouring pieces at the cost of their combined length. Huffman's greedy would solve it if any two pieces could merge, but only neighbours can, so it needs this DP.

</Approach>
