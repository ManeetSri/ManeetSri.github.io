Start with a one-letter word and add one letter at a time to the end, so that every step along the way is a word in the list. Return the longest word in `words` that can be built like that. If several are equally long, return the alphabetically smallest. If no word can be built, return `""`.

`LetterLadderWord.longest(in words: [String]) -> String`

A one-letter word in the list counts as built: it needs no earlier steps.

## Examples

| `words` | Output |
| --- | --- |
| `["b", "ba", "ban", "band", "bandit", "banda", "a", "an", "ant"]` | `"banda"` |
| `["a", "ab", "ac", "b", "bc"]` | `"ab"` |
| `["c", "ca", "cats"]` | `"ca"` |
| `["to", "top", "tops"]` | `""` |
| `["q"]` | `"q"` |

In the first example, "bandit" is longer than "banda", but "bandi" isn't a word, so its ladder is broken. In the second, "ab", "ac" and "bc" can all be built, and "ab" comes first alphabetically. In the fourth, there's no one-letter word to start from.

## Constraints

- `0 ≤ words.count ≤ 50,000`
- Each word holds 1 to 1,000 lowercase letters, a to z. Words may repeat.
- The tests include 50,000 words and a ladder 1,000 letters tall.

<Hints>
<Hint>
Put every word in a trie. A word can be built exactly when every node on its path from the root (except the root itself) ends a word.
</Hint>
<Hint>
So search the trie depth first, but only step into a child that ends a word. Every node you reach is a buildable word, and the deepest one is the answer.
</Hint>
<Hint>
For ties, visit children in alphabetical order and replace your best answer only when a word is strictly longer, or compare explicitly. With a ladder 1,000 letters tall, an explicit stack is safer than recursion.
</Hint>
</Hints>

## Solutions

<Approach title="Sort, then build on what's already built" time="O(n log n × L)" space="O(total letters)">

In alphabetical order, every prefix of a word comes before the word itself. So walk the sorted distinct words, keeping a set of buildable words: a word is buildable if it has one letter, or if the word minus its last letter is already in the set. Ties sort themselves out, because the first word of each length you meet is the smallest.

```swift
public enum LetterLadderWord {
    public static func longest(in words: [String]) -> String {
        var buildable = Set<String>()
        var best = ""
        for word in Set(words).sorted() where word.count == 1 || buildable.contains(String(word.dropLast())) {
            buildable.insert(word)
            if word.count > best.count {
                best = word
            }
        }
        return best
    }
}
```

</Approach>

<Approach title="A trie, searched through word nodes only" time="O(total letters)" space="O(total letters)">

Each node stores the word that ends there, if any. The search only steps into children that end a word, so it never wanders down a broken ladder.

```swift
public enum LetterLadderWord {
    final class Node {
        var children = [Node?](repeating: nil, count: 26)
        var word: String?
    }

    public static func longest(in words: [String]) -> String {
        let root = Node()
        for word in words {
            var node = root
            for byte in word.utf8 {
                let slot = Int(byte - 97)
                if node.children[slot] == nil {
                    node.children[slot] = Node()
                }
                node = node.children[slot]!
            }
            node.word = word
        }

        var best = ""
        var pending: [Node] = [root]
        while let node = pending.popLast() {
            if let word = node.word {
                if word.utf8.count > best.utf8.count || (word.utf8.count == best.utf8.count && word < best) {
                    best = word
                }
            }
            for child in node.children.reversed() {
                if let child, child.word != nil {
                    pending.append(child)
                }
            }
        }
        return best
    }
}
```

Comparing `utf8.count` is O(1) for native Swift strings, while `count` walks the characters. For lowercase letters the two always agree.

</Approach>
