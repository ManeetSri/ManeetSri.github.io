A ski slope is a grid of effort values, where negative values are downhill boosts. A run starts at any cell in the top row and goes down one row at a time: from (r, c) it moves to (r + 1, c − 1), (r + 1, c) or (r + 1, c + 1), staying on the slope. Its effort is the total of every cell it visits, including the first and last. Return the smallest effort of a run that reaches the bottom row.

`SkiSlopeDescent.cheapestRun(_ slope: [[Int]]) -> Int`

## Examples

| `slope` | Output |
| --- | --- |
| `[[4, 1, 6, 3], [2, 8, 5, 7], [9, 3, 1, 4], [6, 2, 7, 5]]` | `8` |
| `[[5, -1, 4], [2, 9, -3], [6, -2, 8]]` | `-6` |
| `[[3, -2, 5]]` | `-2` |
| `[[1], [2], [3]]` | `6` |
| `[[1, 100, 100], [100, 100, 1]]` | `101` |

In the first example the best run is 1 → 2 → 3 → 2. In the second it's −1 → −3 → −2. In the last, the two 1s are two columns apart, so no run can use both.

## Constraints

- `1 ≤ rows ≤ 500` and `1 ≤ cols ≤ 500`, and every row has the same length. The slope doesn't have to be square.
- `-1,000 ≤ slope[r][c] ≤ 1,000`
- The tests use 500 × 500 slopes.

<Hints>
<Hint>
The cheapest run ending at (r, c) must have come from one of the up-to-three cells directly above it, along the cheapest run ending there.
</Hint>
<Hint>
`best[r][c] = slope[r][c] + min` of `best[r − 1]` over columns `max(0, c − 1)` through `min(cols − 1, c + 1)`. The first row is its own base case, and the answer is the minimum of the last row.
</Hint>
<Hint>
You only need the previous row, but a single array updated left to right overwrites column c − 1 before column c reads it. Keep two rows.
</Hint>
</Hints>

## Solutions

<Approach title="Try every run" time="O(cols × 3^rows)" space="O(rows)">

From each top cell, recursively try all three moves and keep the cheapest. Fine for a few rows; hopeless for 500.

</Approach>

<Approach title="Row by row, two arrays" time="O(rows × cols)" space="O(cols)">

`previous` holds the cheapest run ending in each column of the row above. Each new row takes, for every column, its own effort plus the smallest of the up-to-three values above it. Swapping the two arrays avoids allocating a new one each row.

```swift
public enum SkiSlopeDescent {
    public static func cheapestRun(_ slope: [[Int]]) -> Int {
        guard var previous = slope.first, !previous.isEmpty else { return 0 }
        let cols = previous.count
        var current = Array(repeating: 0, count: cols)
        for row in slope.dropFirst() {
            for c in 0..<cols {
                current[c] = row[c] + previous[max(0, c - 1)...min(cols - 1, c + 1)].min()!
            }
            swap(&previous, &current)
        }
        return previous.min()!
    }
}
```

The clamped range handles both edges and the one-column slope. Negative efforts are fine: unlike Dijkstra, the DP never settles a cell before all its parents are known.

</Approach>
