A café's till looks up each ordered item's price on the menu. Anything that isn't on the menu is cooked to order as a chef's special, which costs a fixed price. Work out the bill.

`MenuBill.total(for order: [String], prices: [String: Int], specialPrice: Int) -> Int`

Prices are in pence, so they're whole numbers. An item ordered twice is charged twice.

## Examples

With `prices = ["tea": 250, "toast": 300, "water": 0]` and `specialPrice: 900`:

| Order | Output | Why |
| --- | --- | --- |
| `["tea", "toast"]` | `550` | 250 + 300 |
| `["tea", "pancakes"]` | `1150` | pancakes aren't on the menu: 250 + 900 |
| `["tea", "tea"]` | `500` | each item is charged |
| `["water"]` | `0` | on the menu, and free |
| `[]` | `0` | nothing ordered |

## Constraints

- `0 ≤ order.count ≤ 10,000`
- Every price, and `specialPrice`, is between 0 and 10,000.
- Item names are case-sensitive: `"Tea"` is not on a menu that lists `"tea"`.

<Hints>
<Hint>
`prices[item]` is an `Int?`: the price, or nil if the item isn't on the menu.
</Hint>
<Hint>
The `??` operator turns that into a plain `Int`, with `specialPrice` as the fallback.
</Hint>
</Hints>

## Solutions

<Approach title="Look up each item, with a fallback" time="O(n)" space="O(1)">

For each item, `prices[item] ?? specialPrice` is the price to charge. Adding them up is the accumulator pattern.

```swift
public enum MenuBill {
    public static func total(for order: [String], prices: [String: Int], specialPrice: Int) -> Int {
        var total = 0
        for item in order {
            total += prices[item] ?? specialPrice
        }
        return total
    }
}
```

Note that free water costs 0, not the special price: `??` only falls back when the lookup is nil, and a stored 0 is a real value. A dictionary lookup takes about the same time however big the menu is, so the whole bill takes O(n) for n items. You'll see why in Part III.

</Approach>
