A sorted array holds pairs of equal values, except for one value that appears only once. Return that value.

`SingleInPairs.single(in numbers: [Int]) -> Int`

Aim for O(log n) time and O(1) extra space.

## Examples

| `numbers` | Output |
| --- | --- |
| `[1, 1, 2, 3, 3, 4, 4, 8, 8]` | `2` |
| `[3, 3, 7, 7, 10, 11, 11]` | `10` |
| `[5, 6, 6, 9, 9]` | `5` |
| `[1, 1, 4, 4, 6]` | `6` |
| `[-9, -9, -4, -2, -2]` | `-4` |
| `[42]` | `42` |

## Constraints

- `1 ≤ numbers.count ≤ 2,000,001`, and the count is odd.
- `numbers` is sorted in non-decreasing order.
- Exactly one value appears once; every other value appears exactly twice.

<Hints>
<Hint>
XOR-ing everything together (`numbers.reduce(0, ^)`) cancels the pairs, but it's O(n) and ignores the sorted order. The tests call your function a thousand times on two million values.
</Hint>
<Hint>
Look at where pairs start. Before the single value, every pair starts at an even index. After it, every pair starts at an odd index. The single value itself is at an even index.
</Hint>
<Hint>
Binary search over even indexes: if mid is odd, subtract 1. If `numbers[mid] == numbers[mid + 1]`, the pairs are intact so far, so the single value is to the right: `low = mid + 2`. Otherwise it's at mid or to its left: `high = mid`. Stop when `low == high`.
</Hint>
</Hints>

## Solutions

<Approach title="XOR everything" time="O(n)" space="O(1)">

XOR is its own inverse, so each pair cancels to 0 and only the single value is left. It's short and doesn't even need sorted input, which is exactly why it misses the faster answer.

```swift
public static func single(in numbers: [Int]) -> Int {
    numbers.reduce(0, ^)
}
```

</Approach>

<Approach title="Binary search on pair parity" time="O(log n)" space="O(1)">

At an even index i, "does `numbers[i]` equal `numbers[i + 1]`?" is yes before the single value and no from the single value onwards. The search finds the first no. `low` and `high` start even and stay even, and each pass halves the range.

```swift
public enum SingleInPairs {
    public static func single(in numbers: [Int]) -> Int {
        var low = 0
        var high = numbers.count - 1             // the single value's index is in [low, high], and even
        while low < high {
            var mid = low + (high - low) / 2
            if mid % 2 == 1 {
                mid -= 1                         // the pair that should start here starts at an even index
            }
            if numbers[mid] == numbers[mid + 1] {
                low = mid + 2                    // an intact pair: the single value is after it
            } else {
                high = mid                       // the pattern broke at or before mid
            }
        }
        return numbers[low]
    }
}
```

Inside the loop mid is even and less than `high`, which is also even, so `mid + 1` never runs off the end.

</Approach>

<Approach title="Compare with the partner index" time="O(log n)" space="O(1)">

`mid ^ 1` is mid's partner if pairs still start at even indexes: mid + 1 for even mid, mid − 1 for odd mid. The answer to "does mid match its partner?" is yes before the single value and no from it onwards, at every index, so no adjustment is needed.

```swift
public static func single(in numbers: [Int]) -> Int {
    var low = 0
    var high = numbers.count - 1
    while low < high {
        let mid = low + (high - low) / 2
        if numbers[mid] == numbers[mid ^ 1] {
            low = mid + 1
        } else {
            high = mid
        }
    }
    return numbers[low]
}
```

</Approach>
