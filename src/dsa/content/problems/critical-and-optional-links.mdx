A connected network has nodes 0 to n − 1 and links `edges[i] = [a, b, weight]`. Classify every link by how it relates to the network's minimum spanning trees (MSTs). A link is **critical** if every MST uses it. It's **pseudo-critical** if some MSTs use it but not all. Return the indices of the critical links and the pseudo-critical links, each in increasing order.

`MSTEdgeRoles.classify(_ n: Int, _ edges: [[Int]]) -> (critical: [Int], pseudoCritical: [Int])`

## Examples

| `n` | `edges` | Returns |
| --- | --- | --- |
| 4 | `[[0, 1, 1], [1, 2, 1], [2, 3, 2], [0, 3, 2], [0, 2, 3]]` | critical `[0, 1]`, pseudo-critical `[2, 3]` |
| 4 | `[[0, 1, 5], [1, 2, 5], [2, 3, 5], [3, 0, 5]]` | critical `[]`, pseudo-critical `[0, 1, 2, 3]` |
| 2 | `[[0, 1, 3], [1, 0, 2]]` | critical `[1]`, pseudo-critical `[]` |

In the first example, every MST weighs 4 and uses links 0 and 1, then one of links 2 and 3. Link 4 is in no MST. In the second, each of the four MSTs leaves out a different link of the square.

## Constraints

- `2 ≤ n ≤ 150` and `n − 1 ≤ edges.count ≤ 600`.
- The two nodes of a link are different, and `1 ≤ weight ≤ 1,000`. The same pair may be linked more than once.
- The network is connected.
- The tests include random small networks checked against a brute force that lists every spanning tree, and a network of 150 nodes and 599 links.

<Hints>
<Hint>
Find the MST weight first. Then ask, for each link: what's the lightest spanning tree that doesn't use it?
</Hint>
<Hint>
If leaving a link out makes the best tree heavier, or leaves the network disconnected, every MST needs it: it's critical.
</Hint>
<Hint>
Otherwise, force the link in first and run Kruskal on the rest. If the result still has the minimum weight, some MST contains the link: it's pseudo-critical. If it's heavier, no MST does.
</Hint>
</Hints>

## Solutions

<Approach title="List every spanning tree" time="exponential" space="O(E)">

Try every set of n − 1 links, keep the spanning trees, find the lightest weight, and check which links appear in all or some of the lightest trees. It follows the definitions exactly, and the tests use it as a model on small graphs, but the number of spanning trees explodes quickly.

</Approach>

<Approach title="Kruskal with a link left out or forced in" time="O(E log E + E² α(n))" space="O(n + E)">

Sort the links once. A helper runs Kruskal over that order, optionally skipping one link or starting with one link already taken. Each link needs at most two runs.

```swift
import DSAKit

public enum MSTEdgeRoles {
    public static func classify(_ n: Int, _ edges: [[Int]]) -> (critical: [Int], pseudoCritical: [Int]) {
        let order = edges.indices.sorted { edges[$0][2] < edges[$1][2] }

        func treeWeight(skipping skipped: Int? = nil, forcing forced: Int? = nil) -> Int? {
            var nodes = UnionFind(count: n)
            var total = 0
            if let forced {
                nodes.union(edges[forced][0], edges[forced][1])
                total += edges[forced][2]
            }
            for index in order where index != skipped && nodes.componentCount > 1 {
                if nodes.union(edges[index][0], edges[index][1]) {
                    total += edges[index][2]
                }
            }
            return nodes.componentCount == 1 ? total : nil
        }

        guard let best = treeWeight() else { return ([], []) }
        var critical: [Int] = []
        var pseudoCritical: [Int] = []
        for index in edges.indices {
            if let without = treeWeight(skipping: index), without == best {
                if treeWeight(forcing: index) == best {
                    pseudoCritical.append(index)
                }
            } else {
                critical.append(index)
            }
        }
        return (critical, pseudoCritical)
    }
}
```

Why forcing works: Kruskal started from a forced link still builds the lightest spanning tree that contains it, by the same cut-property argument as plain Kruskal. So the forced result equals the MST weight exactly when some MST uses the link. A faster method, O(E log E), processes links of equal weight as a group and finds bridges among them.

</Approach>
