Write insertion sort once, so it sorts **any** mutable, random-access collection, in place, in any order the caller chooses: arrays, `ContiguousArray`, and slices whose first index isn't 0. It must be **stable**: elements the order treats as equal keep their original order.

`GenericInsertionSort.sort(_:by:)`, declared as `static func sort<C>(_ items: inout C, by areInIncreasingOrder: (C.Element, C.Element) -> Bool) where C: MutableCollection & RandomAccessCollection`

`areInIncreasingOrder(a, b)` returns `true` when `a` must come before `b`. Don't use the standard library's `sort()` or `sorted()`, or DSAKit's sorts.

## Examples

| Code | Result |
| --- | --- |
| `var a = [3, 1, 2]` then `sort(&a, by: <)` | `a` is `[1, 2, 3]` |
| `var w = ["pear", "fig", "kiwi"]` then `sort(&w) { $0.count < $1.count }` | `w` is `["fig", "pear", "kiwi"]` |
| `var n = [9, 8, 7, 6, 5]` then `sort(&n[1..<4], by: <)` | `n` is `[9, 6, 7, 8, 5]` |
| `var t = [5, 4, 3, 2][2...]` then `sort(&t, by: <)` | `t` is `[2, 3]`, with indexes 2 and 3 |
| `var c: ContiguousArray = ["c", "a", "b"]` then `sort(&c, by: >)` | `c` is `["c", "b", "a"]` |

In the second example, "pear" and "kiwi" have the same length, so they stay in their original order. In the third, only indexes 1 to 3 of `n` are sorted.

## Constraints

- Up to 100,000 elements. The large test is nearly sorted, so a correct insertion sort finishes quickly; the random tests use arrays of up to 40 elements.
- Never assume the first index is 0, and never add to an index: move with `index(after:)` and `index(before:)`.

<Hints>
<Hint>
Start from your `[Int]` insertion sort. Replace `items[gap - 1] > key` with a call to the closure: "must the key come before its left neighbour?" Watch the order of the two arguments.
</Hint>
<Hint>
Replace `1..<items.count` with an index that starts at `items.index(after: items.startIndex)` and advances with `items.formIndex(after:)` until it equals `items.endIndex`. Guard against an empty collection first, since `index(after:)` can't move past `endIndex`.
</Hint>
<Hint>
The inner loop stops when the gap reaches `items.startIndex`, not 0. Inside it, the left neighbour is `items.index(before: gap)`. Stop shifting as soon as the closure says the key doesn't come first: that keeps equal elements in order.
</Hint>
</Hints>

## Solutions

<Approach title="Insertion sort with collection indexes" time="O(n + d) for d inversions" space="O(1)">

The algorithm is the same shifting insertion sort as for `[Int]`. Only the index arithmetic changes: every step goes through the collection's own methods, so it's correct whatever the first index is.

```swift
public enum GenericInsertionSort {
    public static func sort<C>(
        _ items: inout C,
        by areInIncreasingOrder: (C.Element, C.Element) -> Bool
    ) where C: MutableCollection & RandomAccessCollection {
        guard !items.isEmpty else { return }
        var next = items.index(after: items.startIndex)     // everything before `next` is sorted
        while next != items.endIndex {
            let key = items[next]
            var gap = next
            while gap != items.startIndex {
                let before = items.index(before: gap)
                guard areInIncreasingOrder(key, items[before]) else { break }
                items[gap] = items[before]                    // shift it one place right
                gap = before
            }
            items[gap] = key
            items.formIndex(after: &next)
        }
    }
}
```

`MutableCollection` provides the assignments through the subscript, and `RandomAccessCollection` (through `BidirectionalCollection`) provides `index(before:)`. The `guard` stops shifting at the first left neighbour that the key doesn't strictly precede, so an equal element is never jumped over: that's what makes it stable. Passing `&n[1..<4]` hands the function a slice of `n` to change in place, and Swift writes the result back into `n`.

</Approach>
