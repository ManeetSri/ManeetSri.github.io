You've found a pile of boarding passes from one long trip, each a ticket `[from, to]` between two airports. The trip started at `start` and used every ticket exactly once. Rebuild the route as the list of airports visited, in order. If more than one route fits, return the one that's smallest alphabetically, comparing the routes airport by airport.

`BoardingPassRoute.itinerary(_ tickets: [[String]], from start: String) -> [String]`

At least one route that starts at `start` and uses every ticket is guaranteed to exist.

## Examples

| `tickets` | `start` | Returns |
| --- | --- | --- |
| `[["DOV", "ASH"], ["ASH", "CAL"], ["CAL", "DOV"], ["DOV", "BRY"]]` | `"DOV"` | `["DOV", "ASH", "CAL", "DOV", "BRY"]` |
| `[["HUB", "ASH"], ["HUB", "CAL"], ["CAL", "HUB"]]` | `"HUB"` | `["HUB", "CAL", "HUB", "ASH"]` |
| `[["ASH", "BRY"], ["BRY", "ASH"], ["ASH", "BRY"]]` | `"ASH"` | `["ASH", "BRY", "ASH", "BRY"]` |
| `[]` | `"ASH"` | `["ASH"]` |

In the second example, ASH comes before CAL, but flying to ASH first strands the other two tickets. The route has to save ASH for last.

## Constraints

- Up to 20,001 tickets. Airport codes are strings of capital letters and digits.
- The same ticket may appear more than once; each copy must be used.
- Trying every order with backtracking can take exponential time when dead ends are hidden deep in the trip.
- **One test is a trip of 20,001 tickets.** A recursive DFS goes one call deeper per ticket, which overflows the test thread's stack (see [Stack depth limits in Swift](/dsa/learn/rec-stack-limits)). Use the stack-based version of Hierholzer's algorithm from the lesson. To check a recursive version on the other tests first, run `swift test --filter BoardingPassRouteTests --skip manyRoundTrips`.

<Hints>
<Hint>
The tickets are the edges of a directed graph, and a route that uses every edge exactly once is an Euler path. Being greedy alone isn't enough: always flying the smallest ticket can walk into a dead end too early.
</Hint>
<Hint>
Hierholzer's algorithm: keep a stack of airports, starting with `start`. If the airport on top has an unused ticket, fly the smallest one and push the destination. If it has none, pop it onto the route. Reverse the route at the end.
</Hint>
<Hint>
To take the smallest unused ticket in O(1), sort each airport's destinations largest first and use `popLast()`. Removing from the front with `removeFirst()` costs O(k) each time.
</Hint>
</Hints>

## Solutions

<Approach title="Backtracking over sorted tickets" time="exponential in the worst case" space="O(E)">

Sort the tickets, then extend the route one ticket at a time, trying the smallest usable ticket first and undoing it if the route gets stuck before using every ticket. The first complete route found is the smallest. It's correct, and often fast, but a trip with many dead ends makes it explore a huge number of partial routes. You'll meet backtracking properly in M48.

</Approach>

<Approach title="Hierholzer's algorithm, recursive" time="O(E log E)" space="O(E)">

Visit an airport: while it has unused tickets, fly the smallest and visit the destination; then append the airport to the route. An airport is appended only once it's stuck, so the route comes out backwards.

```swift
public enum BoardingPassRoute {
    public static func itinerary(_ tickets: [[String]], from start: String) -> [String] {
        var departures: [String: [String]] = [:]
        for ticket in tickets { departures[ticket[0], default: []].append(ticket[1]) }
        departures = departures.mapValues { $0.sorted(by: >) }
        var route: [String] = []
        func visit(_ airport: String) {
            while let next = departures[airport]?.popLast() {
                visit(next)
            }
            route.append(airport)
        }
        visit(start)
        return route.reversed()
    }
}
```

It's short, but the recursion is as deep as the longest stretch of the trip, so it crashes on the 20,001-ticket test.

</Approach>

<Approach title="Hierholzer's algorithm with an explicit stack" time="O(E log E)" space="O(E)">

The same walk with the call stack made explicit. Sorting dominates; the walk itself pushes and pops each airport once per ticket.

```swift
public enum BoardingPassRoute {
    public static func itinerary(_ tickets: [[String]], from start: String) -> [String] {
        var departures: [String: [String]] = [:]
        for ticket in tickets {
            departures[ticket[0], default: []].append(ticket[1])
        }
        departures = departures.mapValues { $0.sorted(by: >) }

        var stack = [start]
        var route: [String] = []
        while let airport = stack.last {
            if let next = departures[airport]?.popLast() {
                stack.append(next)                     // fly the smallest unused ticket
            } else {
                route.append(stack.removeLast())       // stuck: this airport is final among those left
            }
        }
        return route.reversed()
    }
}
```

`departures[airport]?.popLast()` changes the array inside the dictionary in place, and gives `nil` both when the airport has no tickets left and when it never had any.

</Approach>
