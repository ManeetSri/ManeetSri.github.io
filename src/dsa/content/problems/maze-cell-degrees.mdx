A maze is a list of equal-length rows, where `.` is an open cell and `#` a wall. You can step up, down, left or right from one open cell to another. Treat the maze as a graph whose vertices are the open cells, and report how many open cells have each possible degree: return five counts, for 0, 1, 2, 3 and 4 open neighbours.

`MazeCellDegrees.count(_ maze: [String]) -> [Int]`

Degree 1 cells are dead ends, degree 2 cells are corridors and degree 3 or 4 cells are junctions. Don't build an adjacency list: work out each cell's neighbours as you go.

## Examples

| `maze` | Returns | Why |
| --- | --- | --- |
| `["#.#", "...", "#.#"]` | `[0, 4, 0, 0, 1]` | a plus sign: four dead ends and a centre with 4 |
| `[".#.", "...", ".#."]` | `[0, 4, 1, 2, 0]` | an H: four dead ends, a corridor, two junctions |
| `["....."]` | `[0, 2, 3, 0, 0]` | the ends of a corridor have one neighbour each |
| `[".#.", "###", ".#."]` | `[4, 0, 0, 0, 0]` | four cut-off cells |
| `[]` | `[0, 0, 0, 0, 0]` | no cells at all |

## Constraints

- `0 ≤ rows`, `0 ≤ columns`, and `rows × columns ≤ 200,000`. Every row has the same length, using only `.` and `#`.
- Cells beyond the edge of the maze don't exist; nothing wraps around.
- A row can be 100,000 cells long, and so can a column.

<Hints>
<Hint>
Use a direction array, as in [Direction arrays for grid moves](/dsa/learn/matrix-directions): `[(-1, 0), (1, 0), (0, -1), (0, 1)]`. For each open cell, add each offset to get a candidate neighbour.
</Hint>
<Hint>
A candidate is a real neighbour only if it's inside the maze and open. Check the bounds first, so you never index outside a row.
</Hint>
<Hint>
Convert the rows once at the start, with `maze.map { Array($0) }` or the faster `maze.map { Array($0.utf8) }`, so each cell lookup is O(1). Indexing a `String` by an integer isn't possible directly, and walking it each time would be slow.
</Hint>
</Hints>

## Solutions

<Approach title="Generate each cell's neighbours on the fly" time="O(rows × columns)" space="O(rows × columns) for the byte copy">

Every open cell checks four candidates, a constant amount of work per cell.

```swift
public enum MazeCellDegrees {
    public static func count(_ maze: [String]) -> [Int] {
        let cells = maze.map { Array($0.utf8) }
        let open = UInt8(ascii: ".")
        let directions = [(-1, 0), (1, 0), (0, -1), (0, 1)]
        var counts = [0, 0, 0, 0, 0]
        for row in cells.indices {
            for column in cells[row].indices where cells[row][column] == open {
                var degree = 0
                for (dr, dc) in directions {
                    let r = row + dr
                    let c = column + dc
                    if r >= 0, r < cells.count, c >= 0, c < cells[r].count, cells[r][c] == open {
                        degree += 1
                    }
                }
                counts[degree] += 1
            }
        }
        return counts
    }
}
```

`UInt8(ascii: ".")` is the byte for a full stop, so comparisons are between small integers rather than `Character` values, which matters in debug builds.

</Approach>

<Approach title="Count each edge once" time="O(rows × columns)" space="O(rows × columns)">

Every edge joins two open cells side by side or one above the other. Visit each cell and look only right and down: when both cells are open, add 1 to the degree of each, in a degree grid. Then tally the degree grid. It does half the neighbour checks, at the cost of an extra grid.

</Approach>
