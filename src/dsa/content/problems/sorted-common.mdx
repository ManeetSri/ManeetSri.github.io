Given two arrays of whole numbers, return every value that appears in **both** of them. Each value appears once in the result, even if it's repeated in the inputs, and the result is sorted in ascending order.

`SortedCommon.common(_ first: [Int], _ second: [Int]) -> [Int]`

## Examples

| `first` | `second` | Output |
| --- | --- | --- |
| `[4, 9, 5]` | `[9, 4, 9, 8, 4]` | `[4, 9]` |
| `[10, -3, 7]` | `[7, -3]` | `[-3, 7]` |
| `[1, 3, 5]` | `[2, 4, 6]` | `[]` |
| `[]` | `[1, 2]` | `[]` |

## Constraints

- `0 ≤ first.count, second.count ≤ 100,000`
- `-10⁹ ≤ first[i], second[i] ≤ 10⁹`

<Hints>
<Hint>
"In both" is one of the set operations from the lesson. Which one?
</Hint>
<Hint>
`Set(first).intersection(second)` gives exactly the shared values, each once. But a set has no order.
</Hint>
<Hint>
Calling `sorted()` on a set returns a sorted array.
</Hint>
</Hints>

## Solutions

<Approach title="Brute force: check every pair" time="O(n × m)" space="O(k)">

For each value of `first`, search `second` for it, skipping values already in the result. With 100,000 values in each array, that's up to 10 billion comparisons, far too slow.

```swift
public static func common(_ first: [Int], _ second: [Int]) -> [Int] {
    var result: [Int] = []
    for value in first where second.contains(value) && !result.contains(value) {
        result.append(value)
    }
    return result.sorted()
}
```

</Approach>

<Approach title="Set intersection, then sort" time="O(n + m + k log k)" space="O(n + m)">

Building the sets takes one pass over each array. The intersection checks each value in O(1) on average. Only the k shared values need sorting.

```swift
public enum SortedCommon {
    public static func common(_ first: [Int], _ second: [Int]) -> [Int] {
        Set(first).intersection(second).sorted()
    }
}
```

`intersection` accepts any sequence, so `second` doesn't need converting to a set by hand.

</Approach>
