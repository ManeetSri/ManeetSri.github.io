A campus network connects n buildings with cables so that there's exactly one route between any two buildings. Network engineers want to put the main router in a building that keeps the **farthest** building as few cable hops away as possible. Return every building that achieves that, in increasing order.

`TreeNetworkCentres.centres(buildings n: Int, cables: [[Int]]) -> [Int]`

Buildings are numbered from 0 to n − 1, and each cable `[a, b]` joins two of them. The cables always form a single connected network with no loops (n − 1 cables).

## Examples

| `n` | `cables` | Output |
| --- | --- | --- |
| `4` | `[[1, 0], [1, 2], [1, 3]]` | `[1]` |
| `6` | `[[3, 0], [3, 1], [3, 2], [3, 4], [5, 4]]` | `[3, 4]` |
| `5` | `[[0, 1], [1, 2], [2, 3], [3, 4]]` | `[2]` |
| `2` | `[[0, 1]]` | `[0, 1]` |
| `1` | `[]` | `[0]` |

In the second example, from building 3 the farthest building, 5, is 2 hops away; from building 4, the farthest ones (0, 1 and 2) are also 2 hops away. Every other building has something 3 or more hops away.

## Constraints

- `1 ≤ n ≤ 200,000`, and `cables` is a valid tree on the n buildings.
- The answer always has one or two buildings.
- The tests use 200,000 buildings, so running a search from every building, O(n²), is too slow.

<Hints>
<Hint>
Think about a leaf: a building with one cable. Unless the whole network is one or two buildings, a leaf is never a best spot, because its only neighbour is one hop closer to everything else. Removing every leaf at once leaves a smaller tree with the same best spots.
</Hint>
<Hint>
So peel the tree like an onion: put every leaf in a queue, remove that whole layer, lower its neighbours' degrees, and queue the neighbours that have now become leaves. Stop when at most two buildings remain. It's the same machinery as Kahn's topological sort, with degrees instead of in-degrees.
</Hint>
<Hint>
Process the queue a layer at a time: `let layer = queue` (or count the layer's size), and only start the next layer when it's done. Keep a count of remaining buildings; when it's 2 or less, the remaining ones (the last layer you would have peeled) are the answer.
</Hint>
</Hints>

## Solutions

<Approach title="A BFS from every building" time="O(n²)" space="O(n)">

For each building, run a BFS and record the largest distance it reaches, its eccentricity. Return the buildings with the smallest eccentricity. Clear, and the tests use it on small networks, but 200,000 searches of 200,000 buildings each is far too much.

</Approach>

<Approach title="Peel off the leaves, layer by layer" time="O(n)" space="O(n)">

```swift
public enum TreeNetworkCentres {
    public static func centres(buildings n: Int, cables: [[Int]]) -> [Int] {
        guard n > 2 else { return Array(0..<n) }
        var neighbours = Array(repeating: [Int](), count: n)
        var degree = Array(repeating: 0, count: n)
        for cable in cables {
            neighbours[cable[0]].append(cable[1])
            neighbours[cable[1]].append(cable[0])
            degree[cable[0]] += 1
            degree[cable[1]] += 1
        }
        var layer = (0..<n).filter { degree[$0] == 1 }
        var remaining = n
        while remaining > 2 {
            remaining -= layer.count
            var next: [Int] = []
            for leaf in layer {
                for neighbour in neighbours[leaf] {
                    degree[neighbour] -= 1
                    if degree[neighbour] == 1 { next.append(neighbour) }
                }
            }
            layer = next
        }
        return layer.sorted()
    }
}
```

The best spots are the middle of the network's longest path, its **diameter**: one building if the path has an odd number of buildings, two adjacent ones if even. Peeling a layer shortens every longest path by one building at each end, so the middle is what's left. Each building is peeled once and each cable looked at twice: O(n).

</Approach>

<Approach title="Two searches for the diameter" time="O(n)" space="O(n)">

BFS from any building to find the farthest one, a; BFS again from a to find the farthest from it, b, remembering parents. The path from a to b is a longest path, and its middle one or two buildings are the answer. Also O(n), with a satisfying proof that the second search really finds a longest path.

</Approach>
