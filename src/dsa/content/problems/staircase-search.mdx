Every row of this grid is sorted from left to right, and every column from top to bottom. Find a cell holding `target` and return its position, or `nil` if no cell holds it. Aim for O(rows + columns) time.

`StaircaseSearch.find(_ target: Int, in grid: [[Int]]) -> (row: Int, column: Int)?`

## Examples

| | col 0 | col 1 | col 2 | col 3 | col 4 |
| --- | --- | --- | --- | --- | --- |
| **row 0** | 1 | 4 | 7 | 11 | 15 |
| **row 1** | 2 | 5 | 8 | 12 | 19 |
| **row 2** | 3 | 6 | 9 | 16 | 22 |
| **row 3** | 10 | 13 | 14 | 17 | 24 |
| **row 4** | 18 | 21 | 23 | 26 | 30 |

| `target` | Result |
| --- | --- |
| `5` | `(row: 1, column: 1)` |
| `14` | `(row: 3, column: 2)` |
| `20` | `nil` |
| `0` | `nil` |

If `target` appears more than once, any cell holding it is a correct answer.

## Constraints

- `0 ≤ rows, columns ≤ 1,000`. Rows and columns are in non-decreasing order.
- The tests make thousands of searches in a 1,000 × 1,000 grid. Checking every cell, a million per search, is far too slow. A binary search of every row, about 10,000 steps per search, is much better; the staircase needs at most 2,000.

<Hints>
<Hint>
Start at a corner where one direction makes values bigger and the other makes them smaller. The top-left corner doesn't work: both right and down get bigger. The top-right corner does.
</Hint>
<Hint>
At the top-right cell, if the value is bigger than `target`, every value below it in that column is bigger still. The whole column is out: step left. If it's smaller, every value to its left in that row is smaller still: step down.
</Hint>
<Hint>
Stop when you find `target`, or when you step off the grid (`column < 0` or `row == grid.count`). Each step removes a row or a column, so there are at most `rows + columns` steps.
</Hint>
</Hints>

## Solutions

<Approach title="Binary search each row" time="O(rows × log columns)" space="O(1)">

Each row is sorted, so a binary search can check it in O(log columns) steps. Part IV covers binary search properly; this version is here for comparison. It ignores the fact that columns are sorted too.

```swift
public static func find(_ target: Int, in grid: [[Int]]) -> (row: Int, column: Int)? {
    for (row, values) in grid.enumerated() {
        var low = 0
        var high = values.count - 1
        while low <= high {
            let middle = low + (high - low) / 2
            if values[middle] == target {
                return (row, middle)
            } else if values[middle] < target {
                low = middle + 1
            } else {
                high = middle - 1
            }
        }
    }
    return nil
}
```

</Approach>

<Approach title="Staircase from the top-right corner" time="O(rows + columns)" space="O(1)">

From the top-right corner, a value that's too big rules out its column, and a value that's too small rules out its row. The path steps left and down like a staircase, and never needs to go back.

```swift
public enum StaircaseSearch {
    public static func find(_ target: Int, in grid: [[Int]]) -> (row: Int, column: Int)? {
        guard let width = grid.first?.count, width > 0 else { return nil }
        var row = 0
        var column = width - 1
        while row < grid.count && column >= 0 {
            let value = grid[row][column]
            if value == target {
                return (row, column)
            } else if value > target {
                column -= 1
            } else {
                row += 1
            }
        }
        return nil
    }
}
```

The bottom-left corner works just as well, with the directions swapped: too big, step up; too small, step right.

</Approach>
