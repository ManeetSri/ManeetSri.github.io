A calendar keeps its busy slots tidy: sorted by start, with no two slots overlapping or touching. A new slot arrives. Add it, merging it with every slot it overlaps or touches, and return the updated list, still sorted and tidy.

`InsertTimeSlot.insert(_ newSlot: [Int], into slots: [[Int]]) -> [[Int]]`

Slots are closed `[start, end]` pairs, so touching counts: inserting `[3, 5]` next to `[1, 3]` gives `[1, 5]`. Aim for one pass, without sorting.

## Examples

| `newSlot` | `slots` | Output |
| --- | --- | --- |
| `[5, 9]` | `[[1, 3], [4, 6], [8, 10], [13, 15]]` | `[[1, 3], [4, 10], [13, 15]]` |
| `[0, 1]` | `[[2, 4], [6, 8]]` | `[[0, 1], [2, 4], [6, 8]]` |
| `[4, 6]` | `[[1, 4], [6, 9]]` | `[[1, 9]]` |
| `[2, 3]` | `[[1, 5]]` | `[[1, 5]]` |
| `[7, 7]` | `[]` | `[[7, 7]]` |

In the first example, `[5, 9]` absorbs `[4, 6]` and `[8, 10]`. In the third, it touches a slot at each end and joins them both. In the fourth, it's already covered.

## Constraints

- `0 ≤ slots.count ≤ 200,000`
- `slots` is sorted by start, and each slot starts at least 1 after the previous one ends.
- Every slot, including `newSlot`, has `start ≤ end`, with values between −10⁹ and 10⁹.
- Aim for O(n) time.

<Hints>
<Hint>
The list splits into three runs: slots entirely before the new one, slots that overlap or touch it, and slots entirely after it. Handle each run with its own loop, sharing one index.
</Hint>
<Hint>
A slot is entirely before the new one when it ends before the new slot starts: `slot[1] < newSlot[0]`. Copy those across unchanged.
</Hint>
<Hint>
Then, while the next slot starts at or before the new slot's end, absorb it: the new slot becomes `[min of the starts, max of the ends]`, and its end may keep growing. Append the merged slot, then copy everything that's left.
</Hint>
</Hints>

## Solutions

<Approach title="Append, sort and merge again" time="O(n log n)" space="O(n)">

The quickest correct answer reuses the merge from **Merge overlapping time slots**: add the new slot anywhere, sort, and merge. It's a fine way to check a faster version, but it ignores the fact that the list was already sorted.

```swift
public static func insert(_ newSlot: [Int], into slots: [[Int]]) -> [[Int]] {
    var merged: [[Int]] = []
    for slot in (slots + [newSlot]).sorted(by: { $0[0] < $1[0] }) {
        if let last = merged.last, slot[0] <= last[1] {
            merged[merged.count - 1][1] = max(last[1], slot[1])
        } else {
            merged.append(slot)
        }
    }
    return merged
}
```

</Approach>

<Approach title="Three phases in one pass" time="O(n)" space="O(n)">

Phase 1 copies the slots that end before the new one starts. Everything reaching phase 2 ends at or after the new start, so if it also starts at or before the new end, the two overlap or touch: absorb it. Once a slot starts after the new end, nothing later can touch it either, so phase 3 copies the rest.

```swift
public enum InsertTimeSlot {
    public static func insert(_ newSlot: [Int], into slots: [[Int]]) -> [[Int]] {
        var result: [[Int]] = []
        result.reserveCapacity(slots.count + 1)
        var merged = newSlot
        var i = 0
        // 1. Slots that end before the new slot starts
        while i < slots.count && slots[i][1] < merged[0] {
            result.append(slots[i])
            i += 1
        }
        // 2. Slots that overlap or touch it
        while i < slots.count && slots[i][0] <= merged[1] {
            merged[0] = min(merged[0], slots[i][0])
            merged[1] = max(merged[1], slots[i][1])
            i += 1
        }
        result.append(merged)
        // 3. Everything after it
        result.append(contentsOf: slots[i...])
        return result
    }
}
```

`slots[i...]` is empty when `i == slots.count`, so phase 3 needs no special case. Because the ends of a tidy list are sorted too, a binary search could find where phase 1 stops in O(log n), but building the result still copies every slot, so the total stays O(n).

</Approach>
