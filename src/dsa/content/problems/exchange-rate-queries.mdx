You're given exchange rates between currencies, each a tuple `(a, b, r)` meaning one unit of a buys r units of b. Rates can be chained and reversed: if one EUR buys 1.25 USD, then one USD buys 0.8 EUR. Then answer queries: for each `(c, d)`, how many units of d does one unit of c buy? Return -1 when the rates don't determine it, including when c or d never appears in any rate.

`ExchangeRateQueries.answer(rates: [(String, String, Double)], queries: [(String, String)]) -> [Double]`

The rates are always consistent with each other.

## Examples

| `rates` | `queries` | Returns |
| --- | --- | --- |
| `[("EUR", "USD", 1.25), ("USD", "JPY", 150)]` | `[("EUR", "JPY"), ("USD", "EUR"), ("EUR", "EUR"), ("GBP", "GBP")]` | `[187.5, 0.8, 1.0, -1.0]` |
| `[("A", "B", 2), ("C", "D", 4), ("E", "D", 0.5)]` | `[("A", "C"), ("D", "C"), ("E", "C"), ("C", "E")]` | `[-1.0, 0.25, 0.125, 8.0]` |
| `[]` | `[("A", "B")]` | `[-1.0]` |

In the second example, A and B never trade with C, D or E, so A to C is unknown. One E buys 0.5 D, and one D buys 0.25 C, so one E buys 0.125 C.

## Constraints

- `0 ≤ rates.count, queries.count ≤ 50,000`, and every rate is positive.
- Answers are checked to within a relative error of 10⁻⁹.
- The tests include a chain of 50,000 currencies with 2,000 queries.

<Hints>
<Hint>
Currencies linked by rates form groups, and only two currencies in the same group can be compared. That's union-find. But you need more than "same group": you need the actual rate.
</Hint>
<Hint>
Store a weight on every parent link: how many units of the parent one unit of this currency buys. Multiplying the weights up to the root gives each currency's value in units of the root, and then one c buys `value(c) / value(d)` units of d.
</Hint>
<Hint>
When you compress a path, a node's new weight is the product of the weights along its old path. To union from a rate (a, b, r), with `a = valueA · rootA` and `b = valueB · rootB`, one rootA buys `r · valueB / valueA` units of rootB.
</Hint>
</Hints>

## Solutions

<Approach title="Search the graph for each query" time="O(q · (n + r))" space="O(n + r)">

Treat each rate as two directed edges, a to b with weight r and b to a with weight 1 / r. For each query, run a DFS or BFS from c, multiplying weights along the way, until you reach d. Fine for a few queries, slow for many.

</Approach>

<Approach title="Weighted union-find" time="O((r + q) α(n))" space="O(n)">

Each currency stores its parent and how many units of the parent one unit of it buys. find returns the root and the currency's value in units of the root, compressing the path as it goes. A query is answered from two finds.

```swift
public enum ExchangeRateQueries {
    private struct RatioSets {
        var parent: [Int] = []
        var factor: [Double] = []     // one unit of x buys factor[x] units of parent[x]
        var size: [Int] = []

        mutating func add() -> Int {
            parent.append(parent.count)
            factor.append(1)
            size.append(1)
            return parent.count - 1
        }

        mutating func find(_ x: Int) -> (root: Int, value: Double) {
            var path: [Int] = []
            var root = x
            while parent[root] != root {
                path.append(root)
                root = parent[root]
            }
            for node in path.reversed() where parent[node] != root {
                factor[node] *= factor[parent[node]]
                parent[node] = root
            }
            return (root, x == root ? 1 : factor[x])
        }

        mutating func union(_ a: Int, _ b: Int, rate: Double) {
            let (rootA, valueA) = find(a)
            let (rootB, valueB) = find(b)
            guard rootA != rootB else { return }
            if size[rootA] < size[rootB] {
                parent[rootA] = rootB
                factor[rootA] = rate * valueB / valueA
                size[rootB] += size[rootA]
            } else {
                parent[rootB] = rootA
                factor[rootB] = valueA / (rate * valueB)
                size[rootA] += size[rootB]
            }
        }
    }

    public static func answer(rates: [(String, String, Double)], queries: [(String, String)]) -> [Double] {
        var sets = RatioSets()
        var indexOf: [String: Int] = [:]
        func index(of name: String) -> Int {
            if let index = indexOf[name] { return index }
            let index = sets.add()
            indexOf[name] = index
            return index
        }
        for (from, to, rate) in rates {
            sets.union(index(of: from), index(of: to), rate: rate)
        }
        return queries.map { from, to in
            guard let a = indexOf[from], let b = indexOf[to] else { return -1 }
            let (rootA, valueA) = sets.find(a)
            let (rootB, valueB) = sets.find(b)
            return rootA == rootB ? valueA / valueB : -1
        }
    }
}
```

Compression goes from the node nearest the root back down, so each node's parent already holds its value in root units when the node multiplies by it. A currency that appears in no rate has no index, which is how `("GBP", "GBP")` becomes -1 rather than 1.

</Approach>
