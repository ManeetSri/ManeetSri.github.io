An editor's find bar should feel instant even in a huge document, so it uses **Boyer–Moore–Horspool**, which skips most of the text without reading it. Return every position where the pattern occurs, and also how many **alignments** the search checked, so the tests can see that it really skips.

`HorspoolSkipSearch.search(_ pattern: String, in text: String) -> (positions: [Int], alignments: Int)`

Both strings are ASCII, and positions count characters from 0. Use exactly this rule, so the number of alignments is fixed:

- With m the pattern's length, build a skip table over bytes: every byte gets m, then for each k from 0 to m − 2, the byte `pattern[k]` gets `m - 1 - k`. Later positions overwrite earlier ones, and the pattern's **last** character is left out.
- Start with the pattern's first character under `text[0]`. At each alignment s (while `s + m ≤ text.count`), count it, check whether the pattern matches there (compare in any order you like), then move to `s + skip[text[s + m - 1]]`: the skip for the text character under the pattern's last position, whether or not it matched.

If the pattern is empty or longer than the text, return no positions and 0 alignments.

## Examples

| `pattern` | `text` | Output |
| --- | --- | --- |
| `"example"` | `"here is a simple example"` | `([17], 5)` |
| `"aa"` | `"aaaa"` | `([0, 1, 2], 3)` |
| `"abra"` | `"abracadabra"` | `([0, 7], 3)` |
| `"needle"` | `"haystack"` | `([], 1)` |
| `"xyz"` | `"ab"` | `([], 0)` |

For `"example"`, the table gives `e` 6, `x` 5, `a` 4, `m` 3, `p` 2, `l` 1 and every other byte 7. The search checks s = 0 (the text character under the last position is `s`: skip 7), s = 7 (`p`: skip 2), s = 9 (`e`: skip 6), s = 15 (`p`: skip 2) and s = 17, where it matches. Five alignments, out of the 18 a naive search would check.

## Constraints

- `0 ≤ text.count ≤ 1,000,000` and `0 ≤ pattern.count ≤ 1,000`, all ASCII.
- Overlapping matches all count, as in `"aa"` inside `"aaaa"`.
- The tests search a large English-like text for long patterns and check the exact alignment count, so a naive search that tries every position fails even when its positions are right.

<Hints>
<Hint>
Work on bytes: `Array(text.utf8)` and `Array(pattern.utf8)`. The table is `[Int](repeating: m, count: 256)`, indexed by `Int(byte)`.
</Hint>
<Hint>
Fill the table with `for k in 0..<(m - 1)`, not `0..<m`. If the last character set its own entry, its skip would be 0 and the search would stand still. Every entry is then at least 1, so the loop always moves forward, even right after a match.
</Hint>
<Hint>
The skip only depends on `text[s + m - 1]`, never on where a comparison failed. So you can compare the pattern in any order, for example from the right, which tends to fail fastest, or with a slice comparison.
</Hint>
</Hints>

## Solutions

<Approach title="Try every alignment" time="O(n · m)" space="O(1)">

Check every s from 0 to n − m. It finds the right positions, but it checks n − m + 1 alignments every time, so it fails the alignment counts. It's useful as a reference for the positions.

</Approach>

<Approach title="Horspool's skip table" time="O(n · m) worst case, about n / m on typical text" space="O(1) (256 entries)">

```swift
public enum HorspoolSkipSearch {
    public static func search(_ pattern: String, in text: String) -> (positions: [Int], alignments: Int) {
        let p = Array(pattern.utf8), t = Array(text.utf8)
        let m = p.count, n = t.count
        guard m > 0, m <= n else { return ([], 0) }
        var skip = [Int](repeating: m, count: 256)
        for k in 0..<(m - 1) {
            skip[Int(p[k])] = m - 1 - k
        }
        var positions: [Int] = []
        var alignments = 0
        var s = 0
        while s <= n - m {
            alignments += 1
            var j = m - 1
            while j >= 0 && p[j] == t[s + j] {
                j -= 1                                 // compare from the right
            }
            if j < 0 { positions.append(s) }
            s += skip[Int(t[s + m - 1])]
        }
        return (positions, alignments)
    }
}
```

The skip for byte c is how far the pattern must move so that the rightmost c in its first m − 1 characters lines up with the text character that sat under its end. Any smaller move would leave a different pattern character there, so it can't skip a match. On English text most characters aren't in a long pattern, so most alignments jump by the whole pattern length. The worst case is still O(n · m): a text of `a`s with the pattern `baaa…a` moves one step at a time and compares m characters at each.

</Approach>
