Given strictly increasing values, build a binary search tree that holds them all and is **height-balanced**: at every node, the heights of the left and right subtrees differ by at most one. Return its root.

`BSTFromSortedArray.build(_ values: [Int]) -> TreeNode?`

An empty array gives `nil`. The tests also check that the tree is as short as possible, ⌈log₂(n + 1)⌉ levels for n values, which the natural approach gives you for free.

## Examples

| `values` | One correct output (level order) |
| --- | --- |
| `[1, 2, 3]` | `[2, 1, 3]` |
| `[-10, -3, 0, 5, 9]` | `[0, -3, 9, -10, nil, 5]` |
| `[1, 2, 3, 4]` | `[3, 2, 4, 1]` |
| `[7]` | `[7]` |
| `[]` | `[]` (`nil`) |

With an even number of values there are two middles, and either can be the root: `[2, 1, 3, nil, nil, nil, 4]` is also correct for `[1, 2, 3, 4]`, and so is `[0, -10, 5, nil, -3, nil, 9]` for the second example, which picks the other middle in each half. The tests accept any tree that holds the values, is height-balanced and is as short as possible.

## Constraints

- `0 ≤ values.count ≤ 200,000`
- `values` is strictly increasing.

<Hints>
<Hint>
Which value should be the root, so that the left and right subtrees get the same number of values, give or take one?
</Hint>
<Hint>
The middle one. Everything before it forms the left subtree, and everything after it the right subtree, and each of those is again a sorted array: the same problem, smaller.
</Hint>
<Hint>
Recurse on index ranges rather than slicing or copying: `build(low, high)` makes a tree from `values[low..<high]`, and returns `nil` when `low == high`. The recursion is only about log₂ n calls deep.
</Hint>
</Hints>

## Solutions

<Approach title="The middle value as the root, recursively" time="O(n)" space="O(log n)">

Each call creates one node, so there are n calls doing O(1) work each. The halves differ in size by at most one at every node, so the subtrees' heights differ by at most one too, and the tree is as short as any tree of n nodes can be. The stack holds one call per level: O(log n).

```swift
public enum BSTFromSortedArray {
    public static func build(_ values: [Int]) -> TreeNode? {
        func build(_ low: Int, _ high: Int) -> TreeNode? {     // the values at low..<high
            guard low < high else { return nil }
            let mid = low + (high - low) / 2
            return TreeNode(values[mid], left: build(low, mid), right: build(mid + 1, high))
        }
        return build(0, values.count)
    }
}
```

When a range has an even number of values, `low + (high - low) / 2` picks the later of its two middles. `low + (high - low - 1) / 2` would pick the earlier one, which is equally correct.

</Approach>
