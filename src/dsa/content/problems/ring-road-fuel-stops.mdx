A delivery van drives round a ring road with `n` fuel stations, numbered `0` to `n - 1` in driving order. At station `i` it can take on `fuel[i]` litres, and driving on to the next station (station 0 after the last) uses `cost[i]` litres. The tank starts empty and holds any amount. Return the station where the van can start and drive all the way round back to it without running out. If several stations work, return the smallest; if none does, return `-1`.

`RingRoadFuelStart.startStation(fuel: [Int], cost: [Int]) -> Int`

## Examples

| `fuel` | `cost` | Output | Why |
| --- | --- | --- | --- |
| `[4, 1, 2, 6, 1]` | `[3, 4, 3, 1, 3]` | `3` | from 3 the tank holds 5, 3, 4, 1, 0 |
| `[2, 2]` | `[3, 2]` | `-1` | 4 litres in total, 5 needed |
| `[1, 3]` | `[2, 1]` | `1` | from 0 the van can't reach station 1 |
| `[0, 0, 0]` | `[0, 0, 0]` | `0` | every start works; 0 is the smallest |
| `[5]` | `[5]` | `0` | one station: fill up, drive round, arrive empty |

Arriving at a station with exactly 0 litres is fine.

## Constraints

- `1 ≤ n ≤ 100,000` and `fuel.count == cost.count == n`
- `0 ≤ fuel[i], cost[i] ≤ 100,000`
- Trying every start is O(n²): ten billion steps for the largest tests.

<Hints>
<Hint>
Each station's gain is `fuel[i] - cost[i]`. If the gains add up to less than 0, no start can work. Surprisingly, if they add up to 0 or more, some start always works.
</Hint>
<Hint>
Suppose you start at station s and the tank first goes negative after station i. Could any station between s and i be a valid start? You arrived at each of them with a tank of at least 0.
</Hint>
<Hint>
Drive once from station 0, keeping the tank since the current candidate start. Whenever it goes negative after station i, make `i + 1` the candidate and empty the tank. At the end, return the candidate if the total gain is at least 0.
</Hint>
</Hints>

## Solutions

<Approach title="Try every start" time="O(n²)" space="O(1)">

Simulate a full lap from each station in turn and return the first that never runs dry. Clearly right, and a good checker for the fast version on small inputs.

```swift
public static func startStation(fuel: [Int], cost: [Int]) -> Int {
    let n = fuel.count
    for start in 0..<n {
        var tank = 0
        var ok = true
        for step in 0..<n {
            let station = (start + step) % n
            tank += fuel[station] - cost[station]
            if tank < 0 {
                ok = false
                break
            }
        }
        if ok { return start }
    }
    return -1
}
```

</Approach>

<Approach title="Start after the worst prefix" time="O(n)" space="O(1)">

If the van starts at s and runs dry after station i, every station from s to i fails too: each was reached from s with a non-negative tank, and starting there empty can only arrive at i with less. So skip straight to i + 1. Each reset happens where the running total from station 0 hits a new low, so the final candidate is right after the lowest point. From there, every later running total is at least as high, and after wrapping round the tank holds at least the lap total, so if the lap total is at least 0, the tank never goes negative. Because the reset happens at the **first** time the lowest point is reached, it's also the smallest valid start.

```swift
public enum RingRoadFuelStart {
    public static func startStation(fuel: [Int], cost: [Int]) -> Int {
        var total = 0
        var tank = 0
        var start = 0
        for i in fuel.indices {
            let gain = fuel[i] - cost[i]
            total += gain
            tank += gain
            if tank < 0 {
                start = i + 1
                tank = 0
            }
        }
        return total >= 0 ? start : -1
    }
}
```

</Approach>
