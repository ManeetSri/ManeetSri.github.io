An integer type with *n* bits has 2ⁿ different patterns of 0s and 1s. A **signed** type shares them between negative numbers and the rest; an **unsigned** type spends them all on zero and the positives. Given how many patterns a type has, work out its range, just as the lesson did for `Int8`.

- `BitPatternRange.signedMin(patterns: Int) -> Int` returns the smallest value of the signed type.
- `BitPatternRange.signedMax(patterns: Int) -> Int` returns the largest value of the signed type.
- `BitPatternRange.unsignedMax(patterns: Int) -> Int` returns the largest value of the unsigned type. (Its smallest is always 0.)

## Examples

| `patterns` | `signedMin` | `signedMax` | `unsignedMax` | Like |
| --- | --- | --- | --- | --- |
| `256` (8 bits) | `-128` | `127` | `255` | `Int8`, `UInt8` |
| `65_536` (16 bits) | `-32768` | `32767` | `65535` | `Int16`, `UInt16` |
| `8` (3 bits) | `-4` | `3` | `7` | no Swift type, same rule |
| `2` (1 bit) | `-1` | `0` | `1` | the smallest possible |

## Constraints

- `patterns` is a power of two, from 2 (1 bit) up to 2⁶² = 4,611,686,018,427,387,904 (62 bits), so every answer fits in an `Int`.
- Use the patterns you're given: don't look up `Int8.max` and friends.

<Hints>
<Hint>
Count the values in a signed type: there are exactly as many negative values as non-negative ones, and zero counts as non-negative. So each side gets half the patterns.
</Hint>
<Hint>
The negatives run from -1 down to `-(patterns / 2)`. The non-negatives start at 0, which uses up one pattern, so they stop one short: at `patterns / 2 - 1`.
</Hint>
<Hint>
The unsigned type's values run from 0 upwards, using every pattern, so its largest is `patterns - 1`. Since `patterns` is even, `patterns / 2` is exact.
</Hint>
</Hints>

## Solutions

<Approach title="Half the patterns each side" time="O(1)" space="O(1)">

Split the patterns in two. The negative half reaches `-(patterns / 2)`; the other half has to include zero, so its top is one lower. That's why every signed type's maximum is one less than the size of its minimum, like `Int8`'s 127 against -128.

```swift
public enum BitPatternRange {
    public static func signedMin(patterns: Int) -> Int {
        return -(patterns / 2)
    }

    public static func signedMax(patterns: Int) -> Int {
        return patterns / 2 - 1 // zero takes one of the non-negative half's patterns
    }

    public static func unsignedMax(patterns: Int) -> Int {
        return patterns - 1 // all patterns, counting up from zero
    }
}
```

For 256 patterns that gives -128, 127 and 255: exactly what `print(Int8.min, Int8.max)` and `print(UInt8.max)` show. The same three lines explain `Int16`, `Int32` and `Int64`, and even "types" with an odd number of bits that Swift doesn't have.

</Approach>
