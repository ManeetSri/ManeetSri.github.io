Move every 0 in the array to the **front**, in place, keeping all the other values in their original order.

`ZeroesToTheFront.gather(_ numbers: inout [Int])`

This is the mirror image of moving zeroes to the end. The lesson's code doesn't work as it is: think about which direction the reading and writing should go.

## Examples

| `numbers` before | `numbers` after |
| --- | --- |
| `[1, 0, 2, 0, 3]` | `[0, 0, 1, 2, 3]` |
| `[0, 5, 0]` | `[0, 0, 5]` |
| `[7, 0, 0, 0, 4, 0, 9]` | `[0, 0, 0, 0, 7, 4, 9]` |
| `[-2, 0, 5, -2]` | `[0, -2, 5, -2]` |
| `[4, -1, 7]` | `[4, -1, 7]` |
| `[]` | `[]` |

## Constraints

- `0 ≤ numbers.count ≤ 100,000`. Values are any `Int`, including negatives.
- O(n) time and O(1) extra space: no second array, no sorting, and no `insert(_:at: 0)` in a loop.

<Hints>
<Hint>
Moving zeroes to the end kept the non-zero values packed at the **front**, with `write` moving forwards. Here the non-zero values must end up packed at the **back**.
</Hint>
<Hint>
Run the read/write pattern from the right. Start `write` at the last index and walk `read` from the last index down to 0. Each non-zero value is copied to `write`, and `write` moves one step left. The invariant: `numbers[(write + 1)...]` holds the non-zero values read so far, in their original order.
</Hint>
<Hint>
When the scan finishes, every slot from 0 to `write` is spare. Fill them with zeros. For an empty array, `stride(from: -1, through: 0, by: -1)` produces nothing, so the loop is safe.
</Hint>
</Hints>

## Solutions

<Approach title="Build a new array" time="O(n)" space="O(n)">

Collect the zeros, then the other values in order, and replace the array. Correct and clear, but it uses a second array.

```swift
public static func gather(_ numbers: inout [Int]) {
    numbers = numbers.filter { $0 == 0 } + numbers.filter { $0 != 0 }
}
```

</Approach>

<Approach title="Read and write from the back" time="O(n)" space="O(1)">

Scanning from the right, `write` never gets to the left of `read`, so it only ever overwrites a slot that has already been read. The non-zero values stay in order because they're placed right to left in the same order they're read, right to left.

```swift
public enum ZeroesToTheFront {
    public static func gather(_ numbers: inout [Int]) {
        var write = numbers.count - 1
        for read in stride(from: numbers.count - 1, through: 0, by: -1) where numbers[read] != 0 {
            numbers[write] = numbers[read]
            write -= 1
        }
        // Everything from index 0 to write is now spare: fill it with zeros
        var index = write
        while index >= 0 {
            numbers[index] = 0
            index -= 1
        }
    }
}
```

Running the lesson's front-to-back version and then rotating would also work, but it's more work and easier to get wrong. Choosing the scan direction to match where the kept values should end up is the general lesson.

</Approach>
