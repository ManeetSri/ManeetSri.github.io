Count the contiguous, non-empty slices of an array whose sum lies in a band: at least `low` and at most `high`.

`SubarraySumsInBand.count(_ values: [Int], low: Int, high: Int) -> Int`

A slice is `values[i..<j]` for some `i < j`. If `low > high`, the band is empty and the answer is 0.

## Examples

| `values` | `low` | `high` | Output |
| --- | --- | --- | --- |
| `[2, -1, 3, -2, 4]` | `1` | `3` | `7` |
| `[0, 0, 0]` | `0` | `0` | `6` |
| `[-2, -2, -2]` | `-4` | `-2` | `5` |
| `[5]` | `6` | `10` | `0` |
| `[]` | `0` | `0` | `0` |

In the first example, the seven slices are `[2]`, `[3]`, `[2, -1]`, `[-1, 3]`, `[2, -1, 3, -2]`, `[3, -2]` and `[-2, 4]`, with sums 2, 3, 1, 2, 2, 1 and 2. In the second, every one of the six slices sums to 0.

## Constraints

- `0 ≤ values.count ≤ 100,000`
- `-10⁹ ≤ values[i] ≤ 10⁹`
- `-10¹⁵ ≤ low, high ≤ 10¹⁵`
- The answer can reach about 5 × 10⁹. The tests use 100,000 values, so trying every slice is too slow.

<Hints>
<Hint>
With prefix sums `P[0] = 0` and `P[j] = values[0] + … + values[j − 1]`, the slice `values[i..<j]` sums to `P[j] − P[i]`. So you're counting pairs `i < j` of prefix sums whose difference is in the band.
</Hint>
<Hint>
Rearranged, the condition is `P[j] − high ≤ P[i] ≤ P[j] − low`. Scan j from left to right: for each one, count the **earlier** prefix sums in that window, then record `P[j]`. That's the inversion-counting scan with a range of values instead of "greater than".
</Hint>
<Hint>
Prefix sums can be huge, so compress them: sort the n + 1 prefix sums and rank them. The window's ends usually aren't prefix sums themselves, so find its range of ranks with two binary searches. A Fenwick tree of counts by rank then gives the number of earlier prefixes in the window as a difference of two prefix counts.
</Hint>
</Hints>

## Solutions

<Approach title="Try every slice" time="O(n²)" space="O(1)">

Fix the start, extend the end, and keep a running sum. It's the definition, and it's how the tests check small cases.

```swift
public static func count(_ values: [Int], low: Int, high: Int) -> Int {
    var count = 0
    for start in values.indices {
        var sum = 0
        for end in start..<values.count {
            sum += values[end]
            if low <= sum && sum <= high { count += 1 }
        }
    }
    return count
}
```

</Approach>

<Approach title="Prefix sums, compression and a Fenwick tree" time="O(n log n)" space="O(n)">

The scan from [Inversions and count of smaller numbers after self](/dsa/learn/bit-inversions), applied to prefix sums. `countBelow(x)` is a lower bound: the number of distinct prefix sums less than x. Earlier prefixes in `p − high ... p − low` have ranks from `countBelow(p − high) + 1` to `countBelow(p − low + 1)`.

```swift
public enum SubarraySumsInBand {
    public static func count(_ values: [Int], low: Int, high: Int) -> Int {
        guard low <= high else { return 0 }
        var prefix = [0]
        for value in values {
            prefix.append(prefix.last! + value)
        }
        let sorted = Array(Set(prefix)).sorted()

        func countBelow(_ x: Int) -> Int {
            var lo = 0, hi = sorted.count
            while lo < hi {
                let mid = (lo + hi) / 2
                if sorted[mid] < x { lo = mid + 1 } else { hi = mid }
            }
            return lo
        }

        var tree = Array(repeating: 0, count: sorted.count + 1)   // counts by rank, 1-indexed
        func add(_ rank: Int) {
            var i = rank
            while i < tree.count {
                tree[i] += 1
                i += i & -i
            }
        }
        func countUpTo(_ rank: Int) -> Int {
            var i = rank, total = 0
            while i > 0 {
                total += tree[i]
                i -= i & -i
            }
            return total
        }

        var total = 0
        for p in prefix {
            total += countUpTo(countBelow(p - low + 1)) - countUpTo(countBelow(p - high))
            add(countBelow(p) + 1)
        }
        return total
    }
}
```

Counting before adding is what makes the pairs `i < j`: the tree only ever holds the earlier prefixes. The same count can also be found with merge sort over the prefix sums, counting the pairs across each merge with two moving pointers, as in [Counting inversions](/dsa/learn/sort-inversions).

</Approach>
