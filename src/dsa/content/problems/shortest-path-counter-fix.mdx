A teammate wrote the function below to count the shortest routes across a grid map. On the small grids in their tests it's right. On real maps, a few hundred cells across, it either crashes or takes minutes. The algorithm is fine: the trouble is three Swift gotchas. Find them, and write a version that's correct and fast.

`ShortestPathCounterFix.count(_ rows: [String]) -> Int`

The map is a list of equal-length rows: `S` is the start, `G` the goal, `#` a wall and `.` open ground. Moving one cell up, down, left or right is one step. Return how many different shortest routes lead from `S` to `G`, modulo 1,000,000,007, or 0 if `G` can't be reached. Here's your teammate's version:

```swift
func countShortestPaths(_ rows: [String]) -> Int {
    let height = rows.count, width = rows[0].count
    func cell(_ r: Int, _ c: Int) -> Character {
        let row = rows[r]
        return row[row.index(row.startIndex, offsetBy: c)]
    }
    var start = (0, 0), goal = (0, 0)
    for r in 0..<height {
        for c in 0..<width {
            if cell(r, c) == "S" { start = (r, c) }
            if cell(r, c) == "G" { goal = (r, c) }
        }
    }
    var distance = Array(repeating: Array(repeating: -1, count: width), count: height)
    var ways = Array(repeating: Array(repeating: 0, count: width), count: height)
    distance[start.0][start.1] = 0
    ways[start.0][start.1] = 1
    var queue = [start]
    while !queue.isEmpty {
        let (r, c) = queue.removeFirst()
        for (dr, dc) in [(-1, 0), (1, 0), (0, -1), (0, 1)] {
            let nr = r + dr, nc = c + dc
            guard nr >= 0, nr < height, nc >= 0, nc < width, cell(nr, nc) != "#" else { continue }
            if distance[nr][nc] == -1 {
                distance[nr][nc] = distance[r][c] + 1
                queue.append((nr, nc))
            }
            if distance[nr][nc] == distance[r][c] + 1 {
                ways[nr][nc] += ways[r][c]
            }
        }
    }
    return ways[goal.0][goal.1] % 1_000_000_007
}
```

## Examples

| `rows` | Output | Why |
| --- | --- | --- |
| `["S.", ".G"]` | `2` | right then down, or down then right |
| `["S..", "...", "..G"]` | `6` | any order of 2 rights and 2 downs |
| `["S..", ".#.", "..G"]` | `2` | the wall in the middle rules out 4 of the 6 |
| `["S#", "#G"]` | `0` | walled off |
| `["...", "S#G", "..."]` | `2` | over the wall or under it |
| a 600 × 600 open grid, `S` and `G` in opposite corners | `C(1198, 599) mod 1,000,000,007` | a number with 359 digits before the modulo |

## Constraints

- Up to 1,000 rows and 1,000 columns, each row the same length, made only of `S`, `G`, `#` and `.`.
- Exactly one `S` and one `G`, in different cells.

<Hints>
<Hint>
Strings first. What does `row.index(row.startIndex, offsetBy: c)` cost, and how many times is it called? Convert every row once, before the search.
</Hint>
<Hint>
Then the queue. `removeFirst()` on an `Array` shifts every element after it. A BFS can walk its queue with a `head` index instead and never remove anything.
</Hint>
<Hint>
Then the arithmetic. Taking `% 1_000_000_007` at the end is too late: the true counts grow far past `Int.max` partway across a big grid, and Swift stops the program with an overflow. Reduce after every addition. Each count is then below 1,000,000,007, so adding two never overflows.
</Hint>
</Hints>

## Solutions

<Approach title="The same BFS, without the gotchas" time="O(rows × columns)" space="O(rows × columns)">

The three bugs, and their fixes:

1. **String indexing.** `index(_:offsetBy:)` walks from the start of the row every time, so each cell lookup is O(width), and the search does several per cell: O(rows × columns × width) in all. Reading every row once as UTF-8 bytes makes each lookup O(1).
2. **`removeFirst()`.** It shifts the rest of the queue left, which is O(queue length) per step. A head index makes it O(1).
3. **Overflow.** The number of corner-to-corner routes across a 600 × 600 grid has 359 digits, and the counts already pass `Int.max` at cell (34, 34), 68 steps from the start, so `ways[nr][nc] += ways[r][c]` traps there. Taking the remainder after each addition keeps every value below the modulus, which is all the question asks for.

```swift
public enum ShortestPathCounterFix {
    public static func count(_ rows: [String]) -> Int {
        let modulus = 1_000_000_007
        let height = rows.count
        guard let width = rows.first?.utf8.count, width > 0 else { return 0 }
        let cells = rows.flatMap { Array($0.utf8) }          // cell r * width + c, one byte each
        guard let start = cells.firstIndex(of: UInt8(ascii: "S")),
              let goal = cells.firstIndex(of: UInt8(ascii: "G")) else { return 0 }

        var distance = [Int](repeating: -1, count: cells.count)
        var ways = [Int](repeating: 0, count: cells.count)
        distance[start] = 0
        ways[start] = 1
        var queue = [start]
        var head = 0

        /// Reaching `next` from `cell`: record its distance the first time, and add the ways from every
        /// cell one step closer
        func visit(_ next: Int, from cell: Int) {
            guard cells[next] != UInt8(ascii: "#") else { return }
            if distance[next] == -1 {
                distance[next] = distance[cell] + 1
                queue.append(next)
            }
            if distance[next] == distance[cell] + 1 {
                ways[next] = (ways[next] + ways[cell]) % modulus
            }
        }

        while head < queue.count {
            let cell = queue[head]
            head += 1                                        // O(1), where removeFirst() would be O(n)
            if cell == goal { break }                        // every path into the goal is counted
            let r = cell / width, c = cell % width
            if r > 0 { visit(cell - width, from: cell) }
            if r + 1 < height { visit(cell + width, from: cell) }
            if c > 0 { visit(cell - 1, from: cell) }
            if c + 1 < width { visit(cell + 1, from: cell) }
        }
        return ways[goal]
    }
}
```

Why the counting is right: BFS takes cells in order of distance, so when a cell leaves the queue, every neighbour one step closer to `S` has already left it and added its ways. The cell's count is final, and it can pass it on. The early `break` at the goal is safe for the same reason. Bytes work because the map is plain ASCII; with arbitrary Unicode, `Array(row)` of `Character`s would be the conversion to use.

</Approach>
