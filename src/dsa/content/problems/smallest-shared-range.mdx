Several sorted lists of numbers are given. Find the **narrowest range** `[low, high]` that includes at least one number from **every** list. A range's width is `high - low`. If several ranges are equally narrow, return the one with the smaller `low`.

`SmallestSharedRange.range(_ lists: [[Int]]) -> [Int]`, returning `[low, high]`

## Examples

| `lists` | Returns |
| --- | --- |
| `[[3, 10, 15, 24], [0, 9, 12, 20], [5, 18, 22, 30]]` | `[20, 24]` |
| `[[1, 5], [3, 7]]` | `[1, 3]` |
| `[[1, 9], [5], [5, 20]]` | `[1, 5]` |
| `[[1, 2, 3], [1, 2, 3], [1, 2, 3]]` | `[1, 1]` |
| `[[4, 10]]` | `[4, 4]` |
| `[[-8, -3, 4], [-6, 2, 9], [-7, 1, 3]]` | `[-8, -6]` |

In the first row, `[20, 24]` holds 24 from the first list, 20 from the second and 22 from the third. `[0, 5]` also touches all three, but it's wider. In the last row, `[2, 4]` is just as narrow as `[-8, -6]`, but starts later.

## Constraints

- `1 ≤ lists.count ≤ 1,000`, and every list is non-empty and sorted in ascending order (duplicates allowed).
- Up to 100,000 numbers in total, each any `Int` small enough that differences don't overflow.
- Trying every pair of numbers as the ends is far too slow at this size.

<Hints>
<Hint>
Keep one pointer per list, all starting at the front. The numbers they point at include one from every list, so the smallest and largest of them form a candidate range.
</Hint>
<Hint>
To find a narrower range, raising the largest can't help. The only move worth making is to drop the smallest and advance that list's pointer. Repeat until some list runs out: its smallest number can't be dropped any more.
</Hint>
<Hint>
A min-heap of `(value, list, position)` gives you the smallest pointed-at value in O(log k). Track the largest in a plain variable: it only ever goes up. Only replace your best range when the new one is strictly narrower, which makes earlier (smaller) lows win ties.
</Hint>
</Hints>

## Solutions

<Approach title="Merge, then slide a window" time="O(N log N)" space="O(N)">

Tag every number with its list, sort all of them, and slide a window over the sorted sequence, as in [Smallest covering window](/dsa/practice/smallest-covering-window): grow the right end until the window holds every list, then shrink from the left while it still does. Each window that covers every list is a candidate. It works, but sorting all N numbers ignores that each list is already sorted.

</Approach>

<Approach title="A heap of one pointer per list" time="O(N log k)" space="O(k)">

This is a k-way merge that stops early. The heap holds exactly one entry per list until a list runs out.

```swift
import DSAKit

public enum SmallestSharedRange {
    public static func range(_ lists: [[Int]]) -> [Int] {
        // (value, which list, position in that list), smallest value on top
        var front = Heap(lists.indices.map { (value: lists[$0][0], list: $0, position: 0) },
                         areInIncreasingOrder: { $0.value < $1.value })
        var largest = lists.map { $0[0] }.max()!
        var best = [front.peek()!.value, largest]
        while let smallest = front.pop() {
            if largest - smallest.value < best[1] - best[0] {
                best = [smallest.value, largest]
            }
            let next = smallest.position + 1
            guard next < lists[smallest.list].count else { break }
            let value = lists[smallest.list][next]
            largest = max(largest, value)
            front.insert((value, smallest.list, next))
        }
        return best
    }
}
```

Why does this find the best range? Take the best range `[low, high]`. Until the smallest pointed-at value is `low` or more, every pointer that moves was pointing below `low`. So at the first moment the smallest is `low` or more, every pointer sits at its list's first value that's at least `low`. The best range touches every list, so all of those values are at most `high`, and the list holding `low` points at `low` itself. The candidate checked then is `[low, something ≤ high]`, no wider than the best. (No list can run out before that moment: a list whose last value is below `low` couldn't be touched by the best range.)

</Approach>
