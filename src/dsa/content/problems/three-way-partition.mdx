Rearrange an array **in place**, in a single pass, so that every value less than `pivot` comes first, then every value equal to `pivot`, then every value greater than it. The order inside each group doesn't matter. Return the range of indexes that holds the values equal to `pivot`. If there are none, return the empty range at the position where they would go.

`ThreeWayPartition.partition(_ numbers: inout [Int], around pivot: Int) -> Range<Int>`

## Examples

| `numbers` | `pivot` | One possible result | Returns |
| --- | --- | --- | --- |
| `[5, 1, 9, 5, 3, 5, 7]` | `5` | `[1, 3, 5, 5, 5, 7, 9]` | `2..<5` |
| `[2, 0, 2, 1, 1, 0, 1, 2, 0]` | `1` | `[0, 0, 0, 1, 1, 1, 2, 2, 2]` | `3..<6` |
| `[4, 1, 7]` | `5` | `[4, 1, 7]` | `2..<2` |
| `[9, 8]` | `1` | `[9, 8]` | `0..<0` |
| `[3, 3, 3]` | `3` | `[3, 3, 3]` | `0..<3` |
| `[]` | `3` | `[]` | `0..<0` |

Any arrangement with the right three groups is accepted, so `[3, 1, 5, 5, 5, 9, 7]` is also a correct result for the first example. The returned range is the same for every correct arrangement.

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- One pass and O(1) extra space. (Sorting would also group the values, but it's O(n log n) and isn't what this problem is practising.)

<Hints>
<Hint>
This is the Dutch national flag with three groups: less than, equal to and greater than the pivot. Keep `low`, `mid` and `high` pointers, with `mid...high` the elements not yet examined.
</Hint>
<Hint>
Less than the pivot: swap with `low`, then move both `low` and `mid`. Equal: move `mid`. Greater: swap with `high` and move `high` only, because the element that arrives at `mid` hasn't been examined.
</Hint>
<Hint>
When `mid` passes `high`, everything before `low` is less than the pivot and everything after `high` is greater. So the equal block runs from `low` through `high`. As a half-open range, that's `low..<(high + 1)`, which is empty when `high + 1 == low`.
</Hint>
</Hints>

## Solutions

<Approach title="Count, then rebuild" time="O(n)" space="O(n)">

Collect the three groups into separate arrays and join them. It's easy to get right and works as a test oracle, but it uses O(n) extra space and isn't in place in spirit.

```swift
public static func partition(_ numbers: inout [Int], around pivot: Int) -> Range<Int> {
    let less = numbers.filter { $0 < pivot }
    let equal = numbers.filter { $0 == pivot }
    let greater = numbers.filter { $0 > pivot }
    numbers = less + equal + greater
    return less.count..<(less.count + equal.count)
}
```

</Approach>

<Approach title="Dutch national flag" time="O(n)" space="O(1)">

The four regions are `0..<low` (less), `low..<mid` (equal), `mid...high` (unknown) and everything after `high` (greater). Every pass either moves `mid` forward or `high` back, so the unknown region shrinks by one each time: exactly n passes.

```swift
public enum ThreeWayPartition {
    public static func partition(_ numbers: inout [Int], around pivot: Int) -> Range<Int> {
        var low = 0
        var mid = 0
        var high = numbers.count - 1
        while mid <= high {
            if numbers[mid] < pivot {
                numbers.swapAt(low, mid)
                low += 1
                mid += 1
            } else if numbers[mid] == pivot {
                mid += 1
            } else {
                numbers.swapAt(mid, high)
                high -= 1
            }
        }
        return low..<(high + 1)
    }
}
```

This is the partition step of three-way quicksort, which you'll meet in Part IV. Returning the equal block lets the sort skip all the copies of the pivot at once instead of sorting them again.

</Approach>
