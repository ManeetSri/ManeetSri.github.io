An office plans `meetings` meetings, numbered from 0. Each one goes either in the morning or in the afternoon. People send in rules of the form "this or that (or both)", where each half says one meeting is in the morning or in the afternoon. Return a plan that keeps every rule, as an array with `true` for morning and `false` for afternoon, or `nil` if no plan does.

`MeetingSlotPlanner.plan(_ meetings: Int, _ rules: [[Int]]) -> [Bool]?`

Each rule is a pair of codes `[a, b]`, meaning "a or b". A code `x ≥ 0` means "meeting x is in the morning", and a code `~x` means "meeting x is in the afternoon". `~` is bitwise NOT, so `~x` is −x − 1: `~0` is −1, `~1` is −2, and so on. A negative code c refers to meeting `~c`.

When several plans work, return any of them: the tests check every rule.

## Examples

| `meetings` | `rules` | Returns |
| --- | --- | --- |
| `3` | `[[0, 1], [~0, 2], [~1, ~2]]` | e.g. `[true, false, true]` |
| `2` | `[[0, 1], [~0, ~1]]` | `[true, false]` or `[false, true]`: exactly one is in the morning |
| `3` | `[[0, 0], [~0, 1], [~1, 2], [~2, ~0]]` | `nil` |
| `4` | `[]` | any plan, e.g. `[false, false, false, false]` |

The third example says: meeting 0 is in the morning; if 0 is in the morning, so is 1; if 1 is, so is 2; and if 2 is in the morning, 0 isn't. Following the chain from the first rule contradicts it.

## Constraints

- `1 ≤ meetings ≤ 100,000`, with up to 300,000 rules. A rule's two codes may be equal or refer to the same meeting.
- Trying every plan is 2ⁿ plans: hopeless past about 25 meetings.
- **One test has implication chains 100,000 steps long**, and a recursive DFS on them overflows the test thread's stack (see [Stack depth limits in Swift](/dsa/learn/rec-stack-limits)). Use the iterative SCC code from the SCC lesson. To check a recursive version on the other tests first, run `swift test --filter MeetingSlotPlannerTests --skip largePlans`.

<Hints>
<Hint>
This is 2-SAT. Turn each rule "a or b" into two implications: if not a, then b; if not b, then a. Build a graph with two nodes per meeting, one for "morning" and one for "afternoon".
</Hint>
<Hint>
Number meeting x's morning node `2 * x` and its afternoon node `2 * x + 1`. Then the opposite of node v is `v ^ 1`, and code c is node `c >= 0 ? 2 * c : 2 * ~c + 1`.
</Hint>
<Hint>
Find the strongly connected components. If a meeting's two nodes share a component, no plan exists. Otherwise, with Tarjan's numbering (components numbered in the order they're completed, sinks first), put meeting x in the morning when `component[2 * x] < component[2 * x + 1]`.
</Hint>
</Hints>

## Solutions

<Approach title="Every plan" time="O(2ⁿ · rules)" space="O(n)">

Count through all 2ⁿ plans and check every rule. It's the right tool for checking a solver on a few meetings and useless beyond that.

</Approach>

<Approach title="2-SAT with Tarjan's algorithm" time="O(n + rules)" space="O(n + rules)">

The implication graph has 2n nodes and two edges per rule. Tarjan's algorithm completes components in reverse topological order, so a smaller component number means "later in topological order", and choosing the later literal of each pair never forces a contradiction.

```swift
public enum MeetingSlotPlanner {
    public static func plan(_ meetings: Int, _ rules: [[Int]]) -> [Bool]? {
        let nodes = 2 * meetings
        func node(_ code: Int) -> Int { code >= 0 ? 2 * code : 2 * ~code + 1 }

        var implies = [[Int]](repeating: [], count: nodes)
        for rule in rules {
            let a = node(rule[0])
            let b = node(rule[1])
            implies[a ^ 1].append(b)                   // not a → b
            implies[b ^ 1].append(a)                   // not b → a
        }

        // Iterative Tarjan; component numbers come out in reverse topological order
        var index = [Int](repeating: -1, count: nodes)
        var low = [Int](repeating: 0, count: nodes)
        var component = [Int](repeating: -1, count: nodes)
        var onStack = [Bool](repeating: false, count: nodes)
        var stack: [Int] = []
        var frames: [(node: Int, next: Int)] = []
        var nextIndex = 0
        var components = 0

        for start in 0..<nodes where index[start] == -1 {
            index[start] = nextIndex
            low[start] = nextIndex
            nextIndex += 1
            stack.append(start)
            onStack[start] = true
            frames.append((start, 0))
            while let frame = frames.last {
                let v = frame.node
                if frame.next < implies[v].count {
                    frames[frames.count - 1].next += 1
                    let w = implies[v][frame.next]
                    if index[w] == -1 {
                        index[w] = nextIndex
                        low[w] = nextIndex
                        nextIndex += 1
                        stack.append(w)
                        onStack[w] = true
                        frames.append((w, 0))
                    } else if onStack[w] {
                        low[v] = min(low[v], index[w])
                    }
                } else {
                    frames.removeLast()
                    if let parent = frames.last?.node {
                        low[parent] = min(low[parent], low[v])
                    }
                    if low[v] == index[v] {
                        while true {
                            let w = stack.removeLast()
                            onStack[w] = false
                            component[w] = components
                            if w == v { break }
                        }
                        components += 1
                    }
                }
            }
        }

        var morning = [Bool](repeating: false, count: meetings)
        for x in 0..<meetings {
            if component[2 * x] == component[2 * x + 1] { return nil }
            morning[x] = component[2 * x] < component[2 * x + 1]
        }
        return morning
    }
}
```

With Kosaraju's algorithm instead, components come out in topological order (sources first), so the comparison flips: morning when `component[2 * x] > component[2 * x + 1]`.

</Approach>
