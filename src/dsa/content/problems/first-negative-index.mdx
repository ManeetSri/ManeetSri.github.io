Find the position of the first negative number in an array. If no number is negative, say so with `nil`, not with a made-up index.

`FirstNegativeIndex.find(in numbers: [Int]) -> Int?`

## Examples

| Input | Output | Why |
| --- | --- | --- |
| `[4, 7, -2, 9]` | `2` | -2 is at index 2 |
| `[5, -3, -8]` | `1` | the *first* negative wins |
| `[0, 3, 6]` | `nil` | zero isn't negative |
| `[]` | `nil` | nothing to search |

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- `-10⁹ ≤ numbers[i] ≤ 10⁹`

<Hints>
<Hint>
Loop over the indices with `for i in 0..<numbers.count`, so you know the position of each number you look at.
</Hint>
<Hint>
As soon as you find a negative number, `return` its index. There's no need to look any further.
</Hint>
<Hint>
If the loop finishes without returning, there was no negative number: `return nil` after the loop.
</Hint>
</Hints>

## Solutions

<Approach title="Linear search with an early return" time="O(n)" space="O(1)">

Check each number in order and return the index of the first one below zero. Reaching the end of the loop means there wasn't one, so the function returns `nil`. The return type `Int?` tells every caller that "not found" is possible, so they can't forget to handle it.

```swift
public enum FirstNegativeIndex {
    public static func find(in numbers: [Int]) -> Int? {
        for index in 0..<numbers.count where numbers[index] < 0 {
            return index
        }
        return nil
    }
}
```

`0..<numbers.count` is empty for an empty array, so that case needs no special handling. In the worst case, with no negatives, every number is checked once: O(n).

</Approach>
