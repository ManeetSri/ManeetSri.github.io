You're given the root of a binary search tree that may be badly lopsided, even a single chain. Return the root of a **height-balanced** BST holding exactly the same values: at every node, the heights of the left and right subtrees differ by at most 1. You may reuse the given nodes or create new ones.

`RebalanceSearchTree.balanced(_ root: TreeNode?) -> TreeNode?`

Trees are written in level order, as `TreeNode.make` takes them. Many answers are correct for most inputs; the tests accept any height-balanced BST with the right values.

## Examples

| `root` | One correct output |
| --- | --- |
| `[1, nil, 2, nil, 3, nil, 4]` | `[2, 1, 3, nil, nil, nil, 4]` |
| `[5, 4, nil, 3, nil, 2, nil, 1]` | `[3, 1, 4, nil, 2, nil, 5]` |
| `[10, 5, nil, nil, 8, 6]` | `[6, 5, 8, nil, nil, nil, 10]` |
| `[2, 1, 3]` | `[2, 1, 3]` |
| `[]` | `[]` |

The first input is a chain leaning right: 1, then 2 to its right, and so on. The fourth is already balanced, so returning it unchanged is fine.

## Constraints

- `0 ≤ number of nodes ≤ 100,000`
- The input is a valid BST with distinct values.
- The input may be a chain 100,000 levels deep, so don't recurse down it: Swift's call stack isn't that deep.

<Hints>
<Hint>
An inorder walk of a BST visits its values in sorted order, and `TreeNode` has an iterative `inorder` property. Once you have the sorted values (or the nodes themselves, in sorted order), you've reduced the problem to building a balanced BST from a sorted array.
</Hint>
<Hint>
Make the middle element the root, then build the left half into its left subtree and the right half into its right subtree, the same way. The two halves differ in size by at most one, so every node ends up balanced. This recursion is only about log2 n deep, so it's safe even though recursing down the input wasn't.
</Hint>
<Hint>
For a challenge, balance the tree in place with rotations only, using O(1) extra memory: first rotate right at every node with a left child until the tree is one chain leaning right, then fold the chain in half with left rotations at every other node, repeatedly. The second solution below spells it out.
</Hint>
</Hints>

## Solutions

<Approach title="Read out in order, rebuild from the middle" time="O(n)" space="O(n)">

Collect the nodes in inorder with an explicit stack, as in [Iterative traversals with a stack](/dsa/learn/trav-dfs-iterative). Then link them back together: the middle node is the root, and each half becomes a subtree the same way. Every node's `left` and `right` are reassigned, so nothing of the old shape survives.

```swift
import DSAKit

public enum RebalanceSearchTree {
    public static func balanced(_ root: TreeNode?) -> TreeNode? {
        var nodes: [TreeNode] = []
        var stack: [TreeNode] = []
        var current = root
        while current != nil || !stack.isEmpty {
            while let node = current {
                stack.append(node)
                current = node.left
            }
            let node = stack.removeLast()
            nodes.append(node)
            current = node.right
        }
        return build(nodes, 0, nodes.count - 1)
    }

    /// Links nodes[low...high] into a balanced subtree and returns its root.
    private static func build(_ nodes: [TreeNode], _ low: Int, _ high: Int) -> TreeNode? {
        guard low <= high else { return nil }
        let mid = low + (high - low) / 2
        let node = nodes[mid]
        node.left = build(nodes, low, mid - 1)
        node.right = build(nodes, mid + 1, high)
        return node
    }
}
```

The halves `low...(mid - 1)` and `(mid + 1)...high` differ in size by at most one at every level, so their heights do too. The array of nodes is the O(n) extra space.

</Approach>

<Approach title="Rotations only (Day–Stout–Warren)" time="O(n)" space="O(1)">

This classic algorithm, published by Quentin Stout and Bette Warren in 1986 from an idea of Colin Day's, uses nothing but the rotations from [Why balance matters, and rotations](/dsa/learn/bal-why-rotations).

1. **Make a vine.** Walk down the right spine. Whenever the current node has a left child, rotate right at it, lifting the left child into its place. When there's no left child, step right. Each rotation moves one node onto the spine for good, so this takes O(n), and leaves a chain leaning right.
2. **Fold the vine.** A left rotation at every other node of a chain halves its length and hangs the skipped nodes to the left. First fold only the extra nodes beyond the largest perfect tree size 2ᵏ − 1 that fits, which fills the bottom level partly. Then fold repeatedly, halving each time, until the tree is balanced.

A dummy node above the root lets the root take part in rotations like any other node.

```swift
import DSAKit

public enum RebalanceSearchTree {
    public static func balanced(_ root: TreeNode?) -> TreeNode? {
        let dummy = TreeNode(0, right: root)      // a stand-in parent, so the root can rotate too
        // 1. Rotate every left child up until the tree is a chain leaning right (a "vine")
        var count = 0
        var tail = dummy
        var rest = tail.right
        while let node = rest {
            if let left = node.left {
                node.left = left.right                // rotate right at node
                left.right = node
                tail.right = left
                rest = left
            } else {
                count += 1
                tail = node
                rest = node.right
            }
        }
        // 2. Fold the extra nodes beyond a perfect tree's 2^k - 1, then halve repeatedly
        var perfect = 0
        while perfect * 2 + 1 <= count {
            perfect = perfect * 2 + 1                 // the largest 2^k - 1 that's ≤ count
        }
        fold(dummy, count - perfect)
        var size = perfect
        while size > 1 {
            size /= 2
            fold(dummy, size)
        }
        return dummy.right
    }

    /// Left-rotates `times` nodes down the right spine below `parent`, one every other node.
    private static func fold(_ parent: TreeNode, _ times: Int) {
        var scanner = parent
        for _ in 0..<times {
            let child = scanner.right!
            let next = child.right!
            scanner.right = next                      // rotate left at child
            child.right = next.left
            next.left = child
            scanner = next
        }
    }
}
```

The folds do n / 2 + n / 4 + … rotations, under n in total, so the whole thing is O(n) time with only a handful of variables. Every level but the bottom ends up full, which is more than balanced enough.

</Approach>
