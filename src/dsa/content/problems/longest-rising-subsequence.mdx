A weather station logs one temperature reading per hour. Pick some of the readings, keeping them in the order they were logged, so that each reading you pick is strictly higher than the one you picked before it. Return the largest number of readings you can pick.

`LongestRisingSubsequence.length(of readings: [Int]) -> Int`

This is the length of the longest strictly increasing subsequence.

## Examples

| `readings` | Output | One longest choice |
| --- | --- | --- |
| `[10, 9, 2, 5, 3, 7, 101, 18]` | `4` | `[2, 5, 7, 101]` |
| `[3, 4, 5, 1, 2]` | `3` | `[3, 4, 5]` |
| `[7, 7, 7]` | `1` | `[7]`: equal readings don't count as rising |
| `[1, 2, 2, 3]` | `3` | `[1, 2, 3]` |
| `[]` | `0` | nothing to pick |

## Constraints

- `0 ≤ readings.count ≤ 100,000`
- `-1,000,000,000 ≤ readings[i] ≤ 1,000,000,000`
- The tests include several inputs of 100,000 readings, so an O(n²) solution will run for minutes.

<Hints>
<Hint>
Start with the O(n²) DP: `length[i]` is the longest rising run that ends exactly at reading i. It can extend any earlier run that ends at a smaller reading. The answer is the largest `length[i]`, not the last.
</Hint>
<Hint>
To go faster, keep `tails`, where `tails[k]` is the smallest reading that ends a rising run of length k + 1 so far. A lower ending is always at least as useful, because more readings can follow it.
</Hint>
<Hint>
`tails` is always sorted. For each reading, binary search for the first tail that is at least as big (the lower bound) and replace it, or append the reading if it beats every tail. The answer is `tails.count`.
</Hint>
</Hints>

## Solutions

<Approach title="Length ending at each index" time="O(n²)" space="O(n)">

For each reading, look at every earlier reading that is smaller and extend the best run ending there. It's correct and short, but 100,000 readings means about 5 × 10⁹ comparisons.

```swift
public enum LongestRisingSubsequence {
    public static func length(of readings: [Int]) -> Int {
        var length = Array(repeating: 1, count: readings.count)
        for i in readings.indices {
            for j in 0..<i where readings[j] < readings[i] {
                length[i] = max(length[i], length[j] + 1)
            }
        }
        return length.max() ?? 0
    }
}
```

</Approach>

<Approach title="Patience sorting with a lower bound" time="O(n log n)" space="O(n)">

`tails` holds the best ending for each run length, and it stays sorted, so each reading costs one binary search. Searching for the first tail that is **at least** the reading, rather than greater than it, is what keeps runs strictly rising: an equal reading replaces its twin instead of extending it.

```swift
public enum LongestRisingSubsequence {
    public static func length(of readings: [Int]) -> Int {
        var tails: [Int] = []
        for reading in readings {
            var low = 0
            var high = tails.count
            while low < high {                          // the first tail >= reading
                let mid = low + (high - low) / 2
                if tails[mid] >= reading {
                    high = mid
                } else {
                    low = mid + 1
                }
            }
            if low == tails.count {
                tails.append(reading)
            } else {
                tails[low] = reading
            }
        }
        return tails.count
    }
}
```

`tails` has the right length but isn't itself a valid choice of readings: for `[3, 4, 5, 1, 2]` it ends as `[1, 2, 5]`. Only its count is the answer.

</Approach>
