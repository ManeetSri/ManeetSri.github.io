A data centre has `n` servers, numbered `0` to `n - 1`, joined by one-way links. Each link `[from, to, delay]` carries a signal from `from` to `to` in `delay` milliseconds. A signal starts at `source` and is passed along every link as soon as it arrives. Return how many milliseconds pass until every server has received it, or `-1` if some server never does.

`SignalSpreadTime.spreadTime(n: Int, links: [[Int]], source: Int) -> Int`

## Examples

| `n` | `links` | `source` | Output |
| --- | --- | --- | --- |
| `4` | `[[1, 0, 3], [1, 2, 1], [2, 3, 1]]` | `1` | `3` |
| `3` | `[[0, 1, 4], [0, 2, 10], [1, 2, 3]]` | `0` | `7` |
| `2` | `[[0, 1, 7]]` | `1` | `-1` |
| `1` | `[]` | `0` | `0` |
| `3` | `[[0, 1, 1], [1, 0, 1]]` | `0` | `-1` |

In the second example, server 2 hears the signal at 7 ms through server 1 (4 + 3), before the direct 10 ms link delivers it. In the third, links only go one way, so server 0 never hears from server 1. In the last, nothing links to server 2.

## Constraints

- `1 ≤ n ≤ 50,000` and `0 ≤ links.count ≤ 100,000`
- `0 ≤ from, to < n`, and `0 ≤ delay ≤ 1,000,000`
- There may be several links between the same two servers, and links from a server to itself.
- The tests use 20,000 servers with 100,000 links, so an O(n · links) approach is too slow.

<Hints>
<Hint>
Each server hears the signal along its fastest route from the source. And "every server has it" happens when the **slowest** of those arrives.
</Hint>
<Hint>
So you need the shortest distance from the source to every server, then their maximum. Delays are never negative: which algorithm does that suggest?
</Hint>
<Hint>
Dijkstra with a min-heap of (time, server). Servers come out of the heap in order of arrival, so the last one settled is the answer, and if fewer than `n` were settled, return -1.
</Hint>
</Hints>

## Solutions

<Approach title="Bellman–Ford" time="O(n · m)" space="O(n)">

Relax every link n − 1 times, then take the largest distance. It's correct, and it would even handle negative delays, but with 20,000 servers and 100,000 links it's two billion relaxations.

</Approach>

<Approach title="Dijkstra with a heap" time="O((n + m) log n)" space="O(n + m)">

Build an adjacency list, then run Dijkstra with lazy deletion: push a new entry whenever a server's time improves, and skip entries that are stale when popped.

```swift
import DSAKit

public enum SignalSpreadTime {
    public static func spreadTime(n: Int, links: [[Int]], source: Int) -> Int {
        var graph: [[(to: Int, delay: Int)]] = Array(repeating: [], count: n)
        for link in links {
            graph[link[0]].append((link[1], link[2]))
        }
        var arrival = Array(repeating: Int.max, count: n)
        arrival[source] = 0
        var heap = Heap<(time: Int, server: Int)>(areInIncreasingOrder: { $0.time < $1.time })
        heap.insert((0, source))
        var settled = 0
        var latest = 0
        while let (time, server) = heap.pop() {
            if time > arrival[server] { continue }      // stale entry
            settled += 1
            latest = time
            for (next, delay) in graph[server] where time + delay < arrival[next] {
                arrival[next] = time + delay
                heap.insert((arrival[next], next))
            }
        }
        return settled == n ? latest : -1
    }
}
```

`Int.max` is safe as "not reached" here, because only settled servers, which all have real times, are ever relaxed. Ties in the heap don't matter: equal times can come out in either order without changing any distance.

</Approach>
