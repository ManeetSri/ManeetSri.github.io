A music app's shuffle mode lets you **pin** songs, such as an intro and an outro, so they stay where they are. Write the shuffle: given the playlist, the set of pinned positions and a random number generator, return a new order in which every pinned song keeps its position and the other songs fill the remaining positions in a **uniformly random** order: if m songs are unpinned, each of their m! arrangements is equally likely.

`PinnedPlaylistShuffle.shuffled(_ songs: [String], pinned: Set<Int>, using generator: inout some RandomNumberGenerator) -> [String]`

Draw every random number from `generator` (for example with `Int.random(in:using:)`), so the tests can pass a seeded generator and get the same result every run. Write the shuffle yourself rather than calling `shuffle()`.

## Examples

The unpinned songs can come out in any order, so each example shows one possible result.

| `songs` | `pinned` | One possible output |
| --- | --- | --- |
| `["Intro", "Rain", "Neon", "Drift", "Outro"]` | `[0, 4]` | `["Intro", "Drift", "Rain", "Neon", "Outro"]` |
| `["A", "B", "C"]` | `[]` | `["C", "A", "B"]` |
| `["A", "B", "C"]` | `[0, 1, 2]` | `["A", "B", "C"]` (always) |
| `["A", "B", "C", "D"]` | `[1, 2]` | `["D", "B", "C", "A"]` |
| `[]` | `[]` | `[]` |

In the first example, "Intro" and "Outro" never move, and the three songs between them come out in each of their 6 orders one time in 6.

## Constraints

- `0 ≤ songs.count ≤ 100,000`. Song titles may repeat.
- Every index in `pinned` is in `0..<songs.count`.
- O(n) time. The tests shuffle 100,000 songs, and shuffle small playlists tens of thousands of times, counting how often each order appears. A shuffle that favours some orders, even slightly, fails those counts.
- Calling the function twice with generators created from the same seed must give the same result.

<Hints>
<Hint>
Collect the unpinned positions in increasing order, say `free = [1, 2, 3]` in the first example. Shuffling the songs at those positions is the same as shuffling an array of length `free.count`, where index t stands for position `free[t]`.
</Hint>
<Hint>
Fisher–Yates over `free`: for t from `free.count - 1` down to 1, pick u uniformly from `0...t`, including t itself, and swap the songs at positions `free[t]` and `free[u]`.
</Hint>
<Hint>
The two classic mistakes both fail the tests: picking u from all of `0..<free.count` every time (biased), and picking from `0..<t` (Sattolo's algorithm, which never leaves a song in place).
</Hint>
</Hints>

## Solutions

<Approach title="Fisher–Yates over the unpinned positions" time="O(n)" space="O(n)">

```swift
public enum PinnedPlaylistShuffle {
    public static func shuffled(_ songs: [String], pinned: Set<Int>, using generator: inout some RandomNumberGenerator) -> [String] {
        var result = songs
        let free = songs.indices.filter { !pinned.contains($0) }
        guard free.count > 1 else { return result }
        for t in stride(from: free.count - 1, through: 1, by: -1) {
            let u = Int.random(in: 0...t, using: &generator)
            result.swapAt(free[t], free[u])
        }
        return result
    }
}
```

Each step fills the free slot `free[t]` with a uniformly chosen song from the ones not yet placed, so there are m × (m − 1) × … × 2 = m! equally likely sequences of choices, one for each arrangement of the unpinned songs. Pinned positions are never touched.

</Approach>

<Approach title="Shuffle a copy of the free songs" time="O(n)" space="O(n)">

Copy the unpinned songs into their own array, Fisher–Yates that array, then write it back into the free positions in order. It's the same algorithm with an extra copy, and just as uniform.

</Approach>
