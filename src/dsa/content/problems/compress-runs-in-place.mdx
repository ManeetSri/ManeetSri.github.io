Compress an array of characters with run-length encoding, **in place**. Replace each run of a repeated character with the character, followed by the run's length if the run is 2 or longer. Write the compressed form over the start of the same array and return its length; whatever is left after that length doesn't matter.

`InPlaceRunCompressor.compress(_ chars: inout [Character]) -> Int`

A run of 10 or more takes several characters for its count: a run of twelve `q`s becomes `q`, `1`, `2`.

## Examples

| `chars`, as text | Returns | First characters afterwards |
| --- | --- | --- |
| `"aabcccccc"` | `5` | `"a2bc6"` |
| `"abba"` | `4` | `"ab2a"` |
| `"xyz"` | `3` | `"xyz"` |
| twelve `"q"`s | `3` | `"q12"` |
| ten `"m"`s then `"nn"` | `5` | `"m10n2"` |
| `""` | `0` | `""` |

A run of one character is copied as it is, so text with no repeats comes back unchanged.

## Constraints

- `0 ≤ chars.count ≤ 100,000`
- The characters are never digits, so the compressed form can't be ambiguous.
- O(n) time and O(1) extra space, apart from the few characters of one count at a time.

<Hints>
<Hint>
Use two indexes. `read` finds each run: from its first character, move a second index along while the characters match. `write` marks where the next compressed character goes.
</Hint>
<Hint>
For each run, write its character at `write`, and if the run is longer than 1, write every digit of `String(length)`, one character at a time. Don't try to turn the whole count into one `Character`: `"12"` is two.
</Hint>
<Hint>
Why can't `write` overwrite a character that `read` still needs? A run of length L becomes its character plus the digits of L, and that's never more than L characters. So `write` never passes the start of the run being read.
</Hint>
</Hints>

## Solutions

<Approach title="Encode into a new array, then copy back" time="O(n)" space="O(n)">

Build the compressed characters in a separate array and copy them over the front. It's simple and correct, and a fine way to check the in-place version, but it uses O(n) extra space.

```swift
public static func compress(_ chars: inout [Character]) -> Int {
    var result: [Character] = []
    var i = 0
    while i < chars.count {
        var j = i
        while j < chars.count && chars[j] == chars[i] {
            j += 1
        }
        result.append(chars[i])
        if j - i > 1 {
            result.append(contentsOf: String(j - i))
        }
        i = j
    }
    for (index, character) in result.enumerated() {
        chars[index] = character
    }
    return result.count
}
```

</Approach>

<Approach title="Read and write pointers" time="O(n)" space="O(1)">

`read` jumps from the start of one run to the start of the next, and `write` follows behind, never overtaking it. Every character is read once, and at most as many are written, so the whole thing is linear.

```swift
public enum InPlaceRunCompressor {
    public static func compress(_ chars: inout [Character]) -> Int {
        var write = 0
        var read = 0
        while read < chars.count {
            let character = chars[read]
            var runEnd = read
            while runEnd < chars.count && chars[runEnd] == character {
                runEnd += 1
            }
            chars[write] = character
            write += 1
            let length = runEnd - read
            if length > 1 {
                for digit in String(length) {
                    chars[write] = digit
                    write += 1
                }
            }
            read = runEnd
        }
        return write
    }
}
```

</Approach>
