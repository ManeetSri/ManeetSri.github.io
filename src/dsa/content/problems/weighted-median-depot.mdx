Shops sit along a straight road, and shop i needs `weights[i]` deliveries a week. A delivery van drives from a depot to a shop and back for each delivery, so a depot at x costs `weights[i] × |x − positions[i]|` (one way) per shop, added over all shops. Choose where to build the depot, among the shops' own positions, to make the total as small as possible, in **expected linear time** with randomised selection.

`WeightedMedianDepot.bestSpot(positions: [Int], weights: [Int], using generator: inout some RandomNumberGenerator) -> (spot: Int, cost: Int)`

Return the cheapest spot and its total cost. When several positions tie for the cheapest, return the **smallest**. That spot is the smallest position p for which the shops at or before p carry at least half of the total weight, which is called the lower **weighted median**. Draw every random choice from `generator`, so the tests can count them. Don't sort.

## Examples

| `positions` | `weights` | Output |
| --- | --- | --- |
| `[1, 3, 7, 10]` | `[1, 1, 1, 1]` | `(3, 13)` |
| `[1, 3, 7, 10]` | `[1, 1, 1, 5]` | `(10, 19)` |
| `[4, 4, 2, 9]` | `[1, 2, 3, 1]` | `(4, 11)` |
| `[-5, 0, 5]` | `[2, 1, 2]` | `(0, 20)` |
| `[8]` | `[3]` | `(8, 0)` |

In the first example, any spot from 3 to 7 costs 13 (at 3: 2 + 0 + 4 + 7), so the answer is the smallest, 3. In the second, the shop at 10 carries 5 of the 8 deliveries, more than half, so the depot goes there: 1 × 9 + 1 × 7 + 1 × 3 + 5 × 0 = 19. In the third, two shops share position 4; they count together, and from 4 the cost is 3 × 2 + 0 + 0 + 1 × 5 = 11.

## Constraints

- `1 ≤ positions.count ≤ 200,000`, and `weights.count == positions.count`.
- Positions are between −10⁹ and 10⁹, and may repeat. Weights are between 1 and 1,000.
- Expected O(n) time. The tests count how many random numbers you draw, and expect them to grow like log n, not zero (a sort uses none) and not n.
- The tests include 200,000 shops at the same position, and shops already in order, where a fixed pivot or a two-way partition goes quadratic.

<Hints>
<Hint>
Moving the depot right past a shop makes every shop on the left farther away and every shop on the right closer. So the cost goes down while less than half of the total weight lies at or left of x, and stops going down once half or more does. The answer is the first position where the weight at or before it reaches half: `2 × weightAtOrBefore(p) ≥ total`.
</Hint>
<Hint>
That's a selection problem, like quickselect, but steering by weight instead of by count. Pick a random pivot position from the current range, partition the shops **three ways** (less than, equal to, greater than the pivot), and add up the weights of the first two groups. Keep `weightBefore`, the weight of everything already discarded on the left.
</Hint>
<Hint>
If `2 × (weightBefore + lessWeight) ≥ total`, the answer is among the smaller positions: keep them. Otherwise, if adding the equal group's weight reaches half, the pivot is the answer. Otherwise add both groups to `weightBefore` and keep the larger positions. Finally compute the cost in one pass. Three-way partitioning makes a range of equal positions finish in one round.
</Hint>
</Hints>

## Solutions

<Approach title="Sort, then sweep" time="O(n log n)" space="O(n)">

Sort the shops by position and walk along them adding weights until the running total reaches half. It's correct and short, and the tests use it to check your answers, but it isn't linear, and it draws no random numbers, so it fails the count.

</Approach>

<Approach title="Randomised weighted selection" time="O(n) expected" space="O(n)">

```swift
public enum WeightedMedianDepot {
    public static func bestSpot(positions: [Int], weights: [Int], using generator: inout some RandomNumberGenerator) -> (spot: Int, cost: Int) {
        let total = weights.reduce(0, +)
        var shops = Array(zip(positions, weights))       // the current range, as (position, weight)
        var weightBefore = 0
        var spot = positions[0]
        while !shops.isEmpty {
            let pivot = shops[Int.random(in: 0..<shops.count, using: &generator)].0
            var less: [(Int, Int)] = [], greater: [(Int, Int)] = []
            var lessWeight = 0, equalWeight = 0
            for shop in shops {
                if shop.0 < pivot { less.append(shop); lessWeight += shop.1 }
                else if shop.0 > pivot { greater.append(shop) }
                else { equalWeight += shop.1 }
            }
            if 2 * (weightBefore + lessWeight) >= total {
                shops = less
            } else if 2 * (weightBefore + lessWeight + equalWeight) >= total {
                spot = pivot
                break
            } else {
                weightBefore += lessWeight + equalWeight
                shops = greater
            }
        }
        let cost = zip(positions, weights).reduce(0) { $0 + $1.1 * abs($1.0 - spot) }
        return (spot, cost)
    }
}
```

The loop keeps an invariant: the answer is in `shops`, and `weightBefore` is the weight of every shop to its left. Each round keeps one side of a random pivot, so, as with quickselect, the range shrinks by a constant factor on average and the total work is O(n) expected. The `less` side can't be empty when it's chosen, because the condition can only hold if its weight is positive, and `shops` always holds the answer, so the loop ends by finding it.

</Approach>
