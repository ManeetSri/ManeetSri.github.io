A project has tasks labelled 0 to n − 1, where task i takes `durations[i]` days. Each pair `[before, after]` in `dependencies` means `after` can't start until `before` has finished. You have as many workers as you like, so any task can start the moment its dependencies are done. Return two things:

- `finishTime`: the earliest day by which every task can be finished, starting on day 0;
- `criticalTasks`: the tasks with **no slack**, in increasing order. Starting one of them even a day later than its earliest possible start would push `finishTime` back.

`ProjectCriticalPath.plan(durations: [Int], dependencies: [[Int]]) -> (finishTime: Int, criticalTasks: [Int])`

## Examples

| `durations` | `dependencies` | `finishTime` | `criticalTasks` |
| --- | --- | --- | --- |
| `[3, 2, 4]` | `[[0, 1], [0, 2]]` | 7 | `[0, 2]` |
| `[3, 6, 3, 2]` | `[[0, 1], [0, 2], [1, 3], [2, 3]]` | 11 | `[0, 1, 3]` |
| `[3, 4, 4, 2]` | `[[0, 1], [0, 2], [1, 3], [2, 3]]` | 9 | `[0, 1, 2, 3]` |
| `[4, 2, 7, 1]` | `[]` | 7 | `[2]` |
| `[2, 2, 9]` | `[[0, 1]]` | 9 | `[2]` |

In the second example, task 0 runs on days 0–3, then tasks 1 and 2 run side by side. Task 1 takes 6 days and task 2 only 3, so task 2 could start up to 3 days late without harm: it has slack. Task 3 starts on day 9 and ends on day 11. In the third, both middle branches take 4 days, so both are critical.

## Constraints

- `1 ≤ n ≤ 100,000`, `1 ≤ durations[i] ≤ 10,000` and `0 ≤ dependencies.count ≤ 200,000`.
- The dependencies never form a cycle, and labels are in range.
- The tests use 100,000 tasks. The longest chain of dependencies in them is a few hundred tasks.

<Hints>
<Hint>
A task's earliest start is the latest finish among the tasks it depends on (0 if there are none). Processing tasks in topological order means those are all known by the time you reach it. `finishTime` is the largest earliest finish.
</Hint>
<Hint>
Now go backwards. A task's latest finish, the latest it can end without moving `finishTime`, is the smallest latest start among the tasks that depend on it, or `finishTime` if none do. Processing tasks in **reverse** topological order makes those known first.
</Hint>
<Hint>
Latest start is latest finish minus the duration. A task is critical exactly when its latest start equals its earliest start.
</Hint>
</Hints>

## Solutions

<Approach title="A forward and a backward pass in topological order" time="O(n + d)" space="O(n + d)">

The forward pass is a longest-path computation in a DAG: each edge is relaxed once, keeping the **larger** finish. The backward pass does the same in reverse, keeping the smaller start.

```swift
public enum ProjectCriticalPath {
    public static func plan(durations: [Int], dependencies: [[Int]]) -> (finishTime: Int, criticalTasks: [Int]) {
        let count = durations.count
        var dependants = Array(repeating: [Int](), count: count)
        var waitingOn = Array(repeating: 0, count: count)
        for pair in dependencies {
            dependants[pair[0]].append(pair[1])
            waitingOn[pair[1]] += 1
        }
        var order = (0..<count).filter { waitingOn[$0] == 0 }
        var head = 0
        while head < order.count {
            let task = order[head]
            head += 1
            for next in dependants[task] {
                waitingOn[next] -= 1
                if waitingOn[next] == 0 {
                    order.append(next)
                }
            }
        }

        // Forward pass: relax every edge in topological order, keeping the latest finish
        var earliestStart = Array(repeating: 0, count: count)
        for task in order {
            let finish = earliestStart[task] + durations[task]
            for next in dependants[task] {
                earliestStart[next] = max(earliestStart[next], finish)
            }
        }
        let finishTime = (0..<count).map { earliestStart[$0] + durations[$0] }.max() ?? 0

        // Backward pass: the latest each task may finish without moving finishTime
        var latestFinish = Array(repeating: finishTime, count: count)
        for task in order.reversed() {
            for next in dependants[task] {
                latestFinish[task] = min(latestFinish[task], latestFinish[next] - durations[next])
            }
        }
        let critical = (0..<count).filter { latestFinish[$0] - durations[$0] == earliestStart[$0] }
        return (finishTime, critical)
    }
}
```

In reverse topological order, every dependant of a task is handled before the task itself, so its latest finish is final when it's read.

</Approach>

<Approach title="Memoised DFS for both passes" time="O(n + d)" space="O(n + d)">

Earliest start can also be computed recursively: `earliest(t) = max(earliest(p) + durations[p])` over t's dependencies, memoised so each task is solved once. Latest finish is the mirror image over the dependants. It's the same work without an explicit order, at the cost of recursion as deep as the longest chain.

</Approach>
