swift-collections' `Heap` gives O(1) access to **both** its smallest and its largest element, and O(log n) `insert`, `popMin()` and `popMax()`. Judges and interviews don't let you import it, so build your own: a double-ended priority queue, generic over any `Comparable` element.

`MinMaxPriorityQueue.Queue<Element: Comparable>`, with `init()`, `init(_ elements: [Element])`, `count: Int`, `isEmpty: Bool`, `min: Element?`, `max: Element?`, `insert(_:)`, `popMin() -> Element?` and `popMax() -> Element?`

`min` and `max` read the smallest and largest elements without removing them; the pops remove and return them. All four return `nil` when the queue is empty. Duplicates are allowed, and each copy counts separately. `init(_:)` builds a queue holding the given elements.

## Examples

| Code | Result |
| --- | --- |
| insert 5, 1, 9, 3, then `min`, `max`, `count` | `1`, `9`, `4` |
| then `popMax()`, `popMax()`, `popMin()` | `9`, `5`, `1` |
| then `min`, `max` | `3`, `3` |
| `Queue([4, 4, 2, 8, 8])`, then `popMin()`, `popMax()`, `popMax()`, `count` | `2`, `8`, `8`, `2` |
| `Queue<String>()`, insert `"pear"`, `"fig"`, `"plum"`, then `popMin()`, `popMax()` | `"fig"`, `"plum"` |
| `Queue<Int>().popMin()` | `nil` |

## Constraints

- Up to 200,000 operations in any mix.
- `insert`, `popMin` and `popMax` must be O(log n); `min`, `max`, `count` and `isEmpty` O(1). `init(_:)` should be O(n), though O(n log n) passes.
- No packages and no DSAKit: this is the version you'd write from a blank page. Keeping one sorted array fails the large tests, because inserting into its middle is O(n).
- Copying a queue gives an independent queue, as with any struct.

<Hints>
<Hint>
Two binary heaps, a min-heap and a max-heap, can each answer one end. The trouble is removal: popping the minimum from one leaves it sitting in the other. Either tag every element with an id and skip ids that were already removed when they reach the top (lazy deletion), or use one structure that orders both ways at once.
</Hint>
<Hint>
That structure is the **min-max heap**, which is what swift-collections uses. It's an ordinary array-shaped binary tree whose levels alternate: on even levels (the root is level 0) every node is no larger than everything below it, and on odd levels no smaller. So the minimum is the root, and the maximum is the larger of the root's two children (or the root itself if it's alone). The level of index i is `⌊log₂(i + 1)⌋`.
</Hint>
<Hint>
Insert at the end. If the new element is on a min level but larger than its parent, swap them and keep bubbling up through **grandparents** while it's larger than them (max levels); otherwise bubble up through grandparents while it's smaller. To pop, move the last element into the hole and trickle it down: on a min level, find the smallest of its up to two children and four grandchildren; if it's a grandchild and smaller, swap, then fix the element that came down if it's now larger than its new parent, and continue from the grandchild. Max levels mirror all of this.
</Hint>
</Hints>

## Solutions

<Approach title="Two heaps with lazy deletion" time="O(log n) amortised" space="O(n)">

Give each inserted element an increasing id and push `(element, id)` into both a min-heap and a max-heap, and keep a set of removed ids. `popMin` pops the min-heap until its top's id isn't in the removed set, then records that id as removed so the max-heap will skip it later; `popMax` mirrors it. Each element is pushed twice and popped at most twice, so everything is O(log n) amortised. It's easy to get right, at about twice the memory.

</Approach>

<Approach title="A min-max heap" time="O(log n) per change, O(1) to peek" space="O(n)">

```swift
public enum MinMaxPriorityQueue {
    public struct Queue<Element: Comparable> {
        private var items: [Element] = []

        public init() {}

        public init(_ elements: [Element]) {
            items = elements
            if items.count > 1 {
                for i in stride(from: items.count / 2 - 1, through: 0, by: -1) { trickleDown(i) }
            }
        }

        public var count: Int { items.count }
        public var isEmpty: Bool { items.isEmpty }
        public var min: Element? { items.first }
        public var max: Element? { maxIndex.map { items[$0] } }

        public mutating func insert(_ element: Element) {
            items.append(element)
            bubbleUp(items.count - 1)
        }

        public mutating func popMin() -> Element? {
            items.isEmpty ? nil : remove(at: 0)
        }

        public mutating func popMax() -> Element? {
            guard let index = maxIndex else { return nil }
            return remove(at: index)
        }

        private var maxIndex: Int? {
            switch items.count {
            case 0: return nil
            case 1: return 0
            case 2: return 1
            default: return items[1] >= items[2] ? 1 : 2
            }
        }

        private func isMinLevel(_ i: Int) -> Bool {
            ((i + 1).bitWidth - (i + 1).leadingZeroBitCount - 1) % 2 == 0
        }

        private mutating func remove(at index: Int) -> Element {
            let removed = items[index]
            let last = items.removeLast()
            if index < items.count {
                items[index] = last
                trickleDown(index)
            }
            return removed
        }

        private mutating func bubbleUp(_ index: Int) {
            guard index > 0 else { return }
            let parent = (index - 1) / 2
            let onMin = isMinLevel(index)
            if onMin ? items[index] > items[parent] : items[index] < items[parent] {
                items.swapAt(index, parent)
                bubbleUp(parent, towardsMax: onMin)
            } else {
                bubbleUp(index, towardsMax: !onMin)
            }
        }

        private mutating func bubbleUp(_ index: Int, towardsMax: Bool) {
            var i = index
            while i >= 3 {
                let grandparent = ((i - 1) / 2 - 1) / 2
                guard towardsMax ? items[i] > items[grandparent] : items[i] < items[grandparent] else { return }
                items.swapAt(i, grandparent)
                i = grandparent
            }
        }

        private mutating func trickleDown(_ index: Int) {
            let towardsMax = !isMinLevel(index)
            func better(_ a: Element, _ b: Element) -> Bool { towardsMax ? a > b : a < b }
            var i = index
            while true {
                let firstChild = 2 * i + 1
                guard firstChild < items.count else { return }
                var best = firstChild
                for candidate in [firstChild + 1, 4 * i + 3, 4 * i + 4, 4 * i + 5, 4 * i + 6]
                where candidate < items.count && better(items[candidate], items[best]) {
                    best = candidate
                }
                guard better(items[best], items[i]) else { return }
                items.swapAt(i, best)
                if best <= firstChild + 1 { return }        // a child: done
                let parent = (best - 1) / 2
                if better(items[parent], items[best]) { items.swapAt(best, parent) }
                i = best
            }
        }
    }
}
```

A grandparent is on the same kind of level as its grandchild, which is why both walks skip a level at a time: the levels in between only need the one fix-up swap. The height is about log₂ n, so every walk is O(log n). Building from an array trickles down every internal node from the bottom up, the same O(n) argument as for an ordinary heap.

</Approach>
