From across the river, a row of rectangular buildings blends into one outline against the sky. Given the buildings, describe that outline by its **key points**: the places where its height changes.

`SkylineOutline.keyPoints(_ buildings: [[Int]]) -> [[Int]]`

Each building is `[left, right, height]`. It stands on flat ground at height 0 and covers the stretch from `left` up to, but not including, `right`. A key point `[x, h]` means the outline's height becomes `h` at `x`. Return the key points sorted by x. Two neighbouring key points never have the same height, and the last one has height 0. The buildings can come in any order.

## Examples

| `buildings` | Output |
| --- | --- |
| `[[0, 4, 5], [2, 7, 3], [5, 9, 6], [11, 13, 2]]` | `[[0, 5], [4, 3], [5, 6], [9, 0], [11, 2], [13, 0]]` |
| `[[1, 3, 4], [3, 6, 4]]` | `[[1, 4], [6, 0]]` |
| `[[2, 9, 8], [3, 5, 4]]` | `[[2, 8], [9, 0]]` |
| `[[1, 4, 2], [1, 4, 6]]` | `[[1, 6], [4, 0]]` |
| `[[0, 2, 3], [5, 6, 1]]` | `[[0, 3], [2, 0], [5, 1], [6, 0]]` |
| `[]` | `[]` |

In the second example, two buildings of the same height side by side make one flat stretch. In the third, the short building is hidden behind the tall one. In the fifth, the gap between the buildings brings the outline down to the ground.

## Constraints

- `0 ≤ buildings.count ≤ 10,000`
- `0 ≤ left < right ≤ 10⁹` and `1 ≤ height ≤ 10⁹`
- Checking every building at every edge is O(n²) with a slow inner loop. Aim for a sweep: the sorted-array version from the lesson is O(n²) in the worst case but fast in practice, and a heap brings it to O(n log n).

<Hints>
<Hint>
The height can only change at a building's left or right edge. Turn each building into two events, and process the events in order of x.
</Hint>
<Hint>
Keep the heights of the buildings the sweep is currently inside. The outline's height is the tallest of them, or 0 if there are none: record a key point whenever it changes. Keep duplicates, because two buildings can share a height. A sorted array with binary-search insert and remove keeps the tallest at the end.
</Hint>
<Hint>
At the same x, order matters: starts before ends, taller starts first, shorter ends first. Encoding a start as `(left, -height)` and an end as `(right, height)`, then sorting the pairs, gives exactly that order.
</Hint>
</Hints>

## Solutions

<Approach title="Check every edge" time="O(n²)" space="O(n)">

At each building edge, the height is the tallest building covering it. Short and clearly right: use it to test the sweep on many small random cities.

```swift
public static func keyPoints(_ buildings: [[Int]]) -> [[Int]] {
    let edges = Set(buildings.flatMap { [$0[0], $0[1]] }).sorted()
    var points: [[Int]] = []
    for x in edges {
        var height = 0
        for building in buildings where building[0] <= x && x < building[1] {
            height = max(height, building[2])
        }
        if points.last?[1] != height {
            points.append([x, height])
        }
    }
    return points
}
```

</Approach>

<Approach title="Sweep with a sorted array of active heights" time="O(n²) worst case, O(n log n) for the sort" space="O(n)">

Each event adds or removes one copy of a height, and the outline is the tallest active height. The tie-breaking encoding means at most one key point is recorded at each x, and the "only record a change" check merges equal neighbours and skips hidden edges.

```swift
public enum SkylineOutline {
    public static func keyPoints(_ buildings: [[Int]]) -> [[Int]] {
        var events: [(x: Int, key: Int)] = []
        for building in buildings {
            events.append((building[0], -building[2]))   // a start
            events.append((building[1], building[2]))    // an end
        }
        events.sort { ($0.x, $0.key) < ($1.x, $1.key) }

        var active = SortedHeights()
        var points: [[Int]] = []
        for event in events {
            if event.key < 0 {
                active.insert(-event.key)
            } else {
                active.remove(event.key)
            }
            let height = active.tallest
            if points.last?[1] != height {
                points.append([event.x, height])
            }
        }
        return points
    }

    private struct SortedHeights {
        private var items: [Int] = []

        private func lowerBound(_ height: Int) -> Int {
            var low = 0
            var high = items.count
            while low < high {
                let mid = low + (high - low) / 2
                if items[mid] < height {
                    low = mid + 1
                } else {
                    high = mid
                }
            }
            return low
        }

        mutating func insert(_ height: Int) {
            items.insert(height, at: lowerBound(height))
        }

        mutating func remove(_ height: Int) {
            items.remove(at: lowerBound(height))     // one copy only
        }

        var tallest: Int {
            items.last ?? 0
        }
    }
}
```

Finding a spot is O(log n), but inserting into or removing from the middle of an array shifts the elements after it, so each update is O(n) and the worst case is O(n²). In practice the shift is a fast block move of memory. With a heap (M39), push each height at its start, and at an end only note that the height is due to go; pop noted heights when they reach the top. That **lazy deletion** makes the sweep O(n log n).

</Approach>
