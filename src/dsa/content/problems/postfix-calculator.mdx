Build a small calculator in two stages: convert an infix expression to postfix with the shunting-yard algorithm, evaluate the postfix with a stack, then put the two together.

`PostfixCalculator.postfix(from infix: String) -> [String]`, `PostfixCalculator.evaluate(postfix tokens: [String]) -> Int` and `PostfixCalculator.calculate(_ expression: String) -> Int`

- **`postfix(from:)`**: the infix expression contains non-negative integers, `+`, `-`, `*`, `/`, brackets and spaces. Return its postfix tokens: numbers as decimal strings, operators as `"+"`, `"-"`, `"*"` and `"/"`, and no brackets. `*` and `/` bind more tightly than `+` and `-`, and operators of equal precedence apply left to right.
- **`evaluate(postfix:)`**: evaluate postfix tokens. Number tokens may be negative, such as `"-4"`. Division truncates towards zero, as Swift's `/` does.
- **`calculate(_:)`**: the value of an infix expression.

## Examples

| Call | Result |
| --- | --- |
| `postfix(from: "3 + 4 * 2")` | `["3", "4", "2", "*", "+"]` |
| `postfix(from: "(3 + 4) * 2")` | `["3", "4", "+", "2", "*"]` |
| `postfix(from: "8 - 3 - 2")` | `["8", "3", "-", "2", "-"]` |
| `evaluate(postfix: ["5", "1", "2", "+", "4", "*", "+", "3", "-"])` | `14` |
| `evaluate(postfix: ["-7", "2", "/"])` | `-3` |
| `calculate("2 * (3 + 4) - 5 / 2")` | `12` |

## Constraints

- Expressions are valid, with at most 100,000 characters. There's no unary minus in the infix input, and no division by zero.
- Every intermediate value fits in `Int`.
- Aim for O(n) for each function.

<Hints>
<Hint>
Collect digits into a number until a non-digit arrives, so `"12"` becomes one token. For evaluation, push numbers; an operator pops the **right** operand first, then the left.
</Hint>
<Hint>
For the conversion, numbers go straight to the output. An operator first pops every operator on the stack with higher **or equal** precedence (stopping at a `(`), then pushes itself. `(` is pushed; `)` pops to the output until the matching `(`, which is discarded. At the end, pop everything.
</Hint>
<Hint>
In `evaluate`, check for the four operator strings before trying `Int(token)`, or rely on `Int("-")` being `nil` while `Int("-4")` is `-4`.
</Hint>
</Hints>

## Solutions

<Approach title="Shunting-yard, then a value stack" time="O(n)" space="O(n)">

A precedence dictionary does double duty: it says whether a token is an operator, and how tightly it binds. A `(` has no entry, so the popping loop stops at it, which is exactly the "wall" the algorithm needs.

```swift
public enum PostfixCalculator {
    private static let precedence: [String: Int] = ["+": 1, "-": 1, "*": 2, "/": 2]

    public static func postfix(from infix: String) -> [String] {
        var output: [String] = []
        var operators: [String] = []
        var number = ""

        func flushNumber() {
            if !number.isEmpty {
                output.append(number)
                number = ""
            }
        }

        for character in infix {
            if ("0"..."9").contains(character) {
                number.append(character)
                continue
            }
            flushNumber()
            let token = String(character)
            if let rank = precedence[token] {
                while let top = operators.last, let topRank = precedence[top], topRank >= rank {
                    output.append(operators.removeLast())
                }
                operators.append(token)
            } else if token == "(" {
                operators.append(token)
            } else if token == ")" {
                while let top = operators.popLast(), top != "(" {
                    output.append(top)
                }
            }
        }
        flushNumber()
        while let top = operators.popLast() {
            output.append(top)
        }
        return output
    }

    public static func evaluate(postfix tokens: [String]) -> Int {
        var values: [Int] = []
        for token in tokens {
            guard precedence[token] != nil else {
                values.append(Int(token)!)
                continue
            }
            let right = values.removeLast()
            let left = values.removeLast()
            switch token {
            case "+": values.append(left + right)
            case "-": values.append(left - right)
            case "*": values.append(left * right)
            default: values.append(left / right)
            }
        }
        return values.last ?? 0
    }

    public static func calculate(_ expression: String) -> Int {
        evaluate(postfix: postfix(from: expression))
    }
}
```

The nested `flushNumber()` function captures `number` and `output`, so the three places that end a number share one piece of code. The force unwraps are safe because the input is promised to be valid.

</Approach>

<Approach title="Evaluate while converting" time="O(n)" space="O(n)">

Instead of writing operators to an output list, apply them straight away to a stack of values: wherever the shunting-yard algorithm would output an operator, pop two values, combine them and push the result. This uses two stacks, values and operators, and is how many real expression evaluators work. It's a good exercise once the two-stage version passes: it should give the same answers for every test of `calculate`.

</Approach>
