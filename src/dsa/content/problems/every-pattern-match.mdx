A log viewer highlights every place a search term appears. Given a `pattern` and a `text`, return every position in the text where the pattern starts, in increasing order. Matches may overlap, and every one counts.

`EveryPatternMatch.positions(of pattern: String, in text: String) -> [Int]`

## Examples

| `pattern` | `text` | Output |
| --- | --- | --- |
| `"abra"` | `"abracadabra"` | `[0, 7]` |
| `"aa"` | `"aaaa"` | `[0, 1, 2]` |
| `"ana"` | `"bananas"` | `[1, 3]` |
| `"xyz"` | `"abc"` | `[]` |
| `"longer"` | `"short"` | `[]` |

In the second example the three matches overlap; Swift's `ranges(of:)` would report only two of them, because it skips past each match.

## Constraints

- Both strings hold ASCII characters only, so positions count characters (and bytes).
- `1 ≤ pattern.count ≤ 100,000` and `0 ≤ text.count ≤ 100,001`
- The tests include a text of 100,000 `a`s searched for 50,000 `a`s, and for 49,999 `a`s followed by a `b`. Trying every start compares tens of thousands of characters at each of them: billions of steps.

<Hints>
<Hint>
Naive matching throws away what it learned after a mismatch. If the last few characters it compared match the start of the pattern, the next attempt could start from there, without re-reading the text.
</Hint>
<Hint>
Precompute, for every prefix of the pattern, the length of its longest proper prefix that's also a suffix: the prefix function π. After matching j characters and hitting a mismatch, the pattern can safely slide so that only π[j − 1] characters stay matched.
</Hint>
<Hint>
Walk the text once with j = characters matched so far. While j > 0 and the next character doesn't match `pattern[j]`, set `j = pi[j - 1]`. On a match, j += 1. When j reaches m, record `i - m + 1` and set `j = pi[m - 1]` so overlapping matches are found too.
</Hint>
</Hints>

## Solutions

<Approach title="Try every start" time="O(n · m)" space="O(1)">

Compare the pattern with the text at every start and stop at the first mismatch. Correct, and fast on ordinary text, but on the tests' strings of `a`s each start compares almost the whole pattern before failing: about 2.5 billion comparisons.

</Approach>

<Approach title="KMP" time="O(n + m)" space="O(m)">

Build the prefix function of the pattern, then stream the text through it. The text index only moves forward; all the backing up happens in j, and the fallbacks are paid for by earlier matches, so the scan is linear.

```swift
public enum EveryPatternMatch {
    public static func positions(of pattern: String, in text: String) -> [Int] {
        let p = Array(pattern.utf8)
        let t = Array(text.utf8)
        guard !p.isEmpty, p.count <= t.count else { return [] }

        var pi = [Int](repeating: 0, count: p.count)        // pi[i] = longest border of p[0...i]
        var k = 0
        for i in p.indices.dropFirst() {
            while k > 0 && p[i] != p[k] { k = pi[k - 1] }
            if p[i] == p[k] { k += 1 }
            pi[i] = k
        }

        var result: [Int] = []
        var j = 0
        for (i, c) in t.enumerated() {
            while j > 0 && c != p[j] { j = pi[j - 1] }
            if c == p[j] { j += 1 }
            if j == p.count {
                result.append(i - p.count + 1)
                j = pi[j - 1]
            }
        }
        return result
    }
}
```

Working on `Array(text.utf8)` makes every comparison a byte comparison and every index O(1). The input is promised to be ASCII, so byte positions are character positions.

</Approach>

<Approach title="Z-algorithm" time="O(n + m)" space="O(n + m)">

Join the pattern, a separator that equals no character, and the text, and compute the Z-array: at each text position it says how much of the pattern starts there. Positions where it equals m are the matches.

```swift
public enum EveryPatternMatch {
    public static func positions(of pattern: String, in text: String) -> [Int] {
        let m = pattern.utf8.count
        let s = pattern.utf8.map { Int($0) } + [-1] + text.utf8.map { Int($0) }
        var z = [Int](repeating: 0, count: s.count)
        var l = 0, r = 0
        for i in s.indices.dropFirst() {
            if i < r { z[i] = min(r - i, z[i - l]) }
            while i + z[i] < s.count && s[z[i]] == s[i + z[i]] { z[i] += 1 }
            if i + z[i] > r { l = i; r = i + z[i] }
        }
        return (0..<text.utf8.count).filter { z[m + 1 + $0] == m }
    }
}
```

The separator `-1` caps every Z value in the text part at m. This version keeps arrays for the whole combined string, so it uses more memory than KMP.

</Approach>

<Approach title="Rabin–Karp, verifying every hit" time="O(n + m) expected" space="O(1)">

Roll a hash of each m-character window and compare it with the pattern's hash; on equal hashes, compare the characters. With a 61-bit prime modulus false alarms almost never happen, but every *real* match is verified, so 50,001 matches of 50,000 characters each would cost 2.5 billion comparisons here. Rabin–Karp is a fine answer when matches are few; for this problem's tests, either trust the hash or use KMP.

</Approach>
