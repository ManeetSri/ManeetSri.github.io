A trading desk logs the price of every trade in order. Analysts keep asking the same kind of question: "among trades `left` through `right`, what was the kth cheapest price?" Build a finder that answers each question in O(log n) after an O(n log n) set-up.

`PersistentRangeKth.Finder`, with `init(_ prices: [Int])` and `kthSmallest(_ k: Int, from left: Int, through right: Int) -> Int`

Positions count from 0, and k counts from 1, so `k = 1` asks for the cheapest trade in the range and `k = right - left + 1` for the dearest. Equal prices count separately: in `[4, 4, 1]` the second smallest is 4.

## Examples

With `prices = [5, 1, 7, 3, 8, 2, 6, 4]`:

| Call | Output |
| --- | --- |
| `kthSmallest(1, from: 1, through: 6)` | `1` |
| `kthSmallest(3, from: 1, through: 6)` | `3` |
| `kthSmallest(6, from: 1, through: 6)` | `8` |
| `kthSmallest(1, from: 4, through: 4)` | `8` |
| `kthSmallest(4, from: 0, through: 7)` | `4` |

With `prices = [4, 4, 1, 4, 9, 1]`, `kthSmallest(3, from: 0, through: 5)` is `4` and `kthSmallest(2, from: 3, through: 5)` is `4`.

In the first table, trades 1 to 6 have prices 1, 7, 3, 8, 2 and 6. Sorted, that's 1, 2, 3, 6, 7, 8, so the 3rd smallest is 3 and the 6th is 8.

## Constraints

- `1 ≤ prices.count ≤ 100,000`, and prices are between −10⁹ and 10⁹ (they may repeat).
- Every query has `0 ≤ left ≤ right < prices.count` and `1 ≤ k ≤ right - left + 1`.
- The tests ask 100,000 questions about 100,000 prices, many of them about long ranges, so sorting each range is far too slow. A merge-sort tree with a binary search on the answer, O(log³ n) per question, is also too slow in a debug build.

<Hints>
<Hint>
Replace each price with its **rank** among the distinct prices (0 for the cheapest). Now imagine one tree per prefix of the trades: tree i counts how many of the first i trades have each rank, as a segment tree over ranks. How would two of those trees give you the counts for trades `left...right`?
</Hint>
<Hint>
Tree `right + 1` minus tree `left`, node by node: both have the same shape, so the same node covers the same ranks in each. Walking down both at once, the number of range prices in the left half of the ranks is `count(left child of the newer) − count(left child of the older)`. If k is at most that, go left; otherwise subtract it from k and go right.
</Hint>
<Hint>
Storing n + 1 full trees would take O(n²) memory. But tree i differs from tree i − 1 only along one root-to-leaf path. Path copying: store nodes in parallel arrays (`lefts`, `rights`, `counts`), make a new node for each node on the path, and point the other child at the old tree's node. Node 0 can be the empty tree whose children are itself.
</Hint>
</Hints>

## Solutions

<Approach title="Sort each range" time="O(q · n log n)" space="O(n)">

Copy `prices[left...right]`, sort it and return element `k - 1`. It's the reference the tests compare against on small inputs, and far too slow for 100,000 long ranges.

</Approach>

<Approach title="A persistent tree of prefix counts" time="O(n log n) to build, O(log n) per query" space="O(n log n)">

```swift
public enum PersistentRangeKth {
    public struct Finder {
        private var lefts = [0], rights = [0], counts = [0]   // node 0: the empty tree
        private var roots = [0]                                // roots[i] counts prices[0..<i]
        private let values: [Int]                              // distinct prices, sorted

        public init(_ prices: [Int]) {
            values = Array(Set(prices)).sorted()
            var rankOf: [Int: Int] = [:]
            for (rank, value) in values.enumerated() { rankOf[value] = rank }
            let perVersion = values.count.bitWidth - values.count.leadingZeroBitCount + 1
            lefts.reserveCapacity(prices.count * perVersion + 1)
            rights.reserveCapacity(prices.count * perVersion + 1)
            counts.reserveCapacity(prices.count * perVersion + 1)
            for price in prices {
                roots.append(insert(roots[roots.count - 1], 0, values.count - 1, rankOf[price]!))
            }
        }

        // A copy of the path to `rank`, with one more price counted along it
        private mutating func insert(_ node: Int, _ low: Int, _ high: Int, _ rank: Int) -> Int {
            var left = lefts[node], right = rights[node]
            if low < high {
                let mid = (low + high) / 2
                if rank <= mid {
                    left = insert(left, low, mid, rank)
                } else {
                    right = insert(right, mid + 1, high, rank)
                }
            }
            lefts.append(left)
            rights.append(right)
            counts.append(counts[node] + 1)
            return counts.count - 1
        }

        public func kthSmallest(_ k: Int, from left: Int, through right: Int) -> Int {
            var newer = roots[right + 1], older = roots[left]
            var low = 0, high = values.count - 1
            var k = k
            while low < high {
                let mid = (low + high) / 2
                let inLeftHalf = counts[lefts[newer]] - counts[lefts[older]]
                if k <= inLeftHalf {
                    newer = lefts[newer]; older = lefts[older]; high = mid
                } else {
                    k -= inLeftHalf
                    newer = rights[newer]; older = rights[older]; low = mid + 1
                }
            }
            return values[low]
        }
    }
}
```

Each price adds one path of about log₂ m + 1 nodes, where m is the number of distinct prices, and never changes an existing node, so every earlier prefix tree stays intact. A query walks two trees in step, one level at a time. Equal prices share a rank, so they're counted at the same leaf and need no special care.

</Approach>
