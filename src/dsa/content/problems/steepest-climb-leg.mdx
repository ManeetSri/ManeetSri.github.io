A hiking app records the altitude at each checkpoint along a trail. The leg starting at checkpoint `i` goes from `altitudes[i]` to `altitudes[i + 1]`, and it climbs `altitudes[i + 1] - altitudes[i]` metres. Find the leg that climbs the most: return where it starts and how much it climbs.

`SteepestClimbLeg.steepestClimb(in altitudes: [Int]) -> (start: Int, rise: Int)?`

- If several legs share the biggest climb, return the one that starts **earliest**.
- A leg that stays level or goes down isn't a climb. If no leg climbs at all, or there are fewer than two checkpoints, return `nil`.

## Examples

| `altitudes` | Output |
| --- | --- |
| `[100, 140, 130, 190, 200]` | `(start: 2, rise: 60)` |
| `[5, 9, 1, 5]` | `(start: 0, rise: 4)` |
| `[-20, -5]` | `(start: 0, rise: 15)` |
| `[9, 7, 7, 3]` | `nil` |
| `[42]` | `nil` |

In the first example the legs climb 40, -10, 60 and 10 metres, so the leg from checkpoint 2 (130 m) to checkpoint 3 (190 m) wins. In the second, two legs climb 4 metres, and the first one starts at checkpoint 0.

## Constraints

- `0 ≤ altitudes.count ≤ 100,000`
- `-1,000,000 ≤ altitudes[i] ≤ 1,000,000`

<Hints>
<Hint>
`zip(altitudes, altitudes.dropFirst())` pairs each checkpoint with the next one, so each pair is one leg. Its climb is the second value minus the first.
</Hint>
<Hint>
You also need where each leg starts. Add `.enumerated()` to the zip, and destructure both layers in the loop: `for (start, (here, next)) in zip(altitudes, altitudes.dropFirst()).enumerated()`.
</Hint>
<Hint>
Keep the best leg so far in a variable of type `(start: Int, rise: Int)?`, starting at `nil`. Replace it only when a leg's rise is above 0 and **strictly** bigger than the best rise so far; "strictly" keeps the earliest leg when there's a tie.
</Hint>
</Hints>

## Solutions

<Approach title="Index loop" time="O(n)" space="O(1)">

Compare each altitude with the one before it. Leg `i - 1` ends at checkpoint `i`, so the start of the leg is `i - 1`.

```swift
public static func steepestClimb(in altitudes: [Int]) -> (start: Int, rise: Int)? {
    guard altitudes.count >= 2 else { return nil }
    var best: (start: Int, rise: Int)? = nil
    for i in 1..<altitudes.count {
        let rise = altitudes[i] - altitudes[i - 1]
        if rise > 0 && rise > (best?.rise ?? 0) {
            best = (start: i - 1, rise: rise)
        }
    }
    return best
}
```

The `guard` isn't only for speed. With an empty array, `1..<altitudes.count` would be `1..<0`, and Swift crashes with `Range requires lowerBound <= upperBound` before the loop even starts. The off-by-one between `i` and the leg's start is the kind of detail the next version removes.

</Approach>

<Approach title="enumerated and zip" time="O(n)" space="O(1)">

Zipping the array with itself shifted by one gives every leg as a pair, with no index arithmetic. `enumerated()` numbers the pairs from 0, and the pair numbered `start` is exactly the leg starting at checkpoint `start`. An empty or one-element array simply produces no pairs, so no `guard` is needed.

```swift
public enum SteepestClimbLeg {
    public static func steepestClimb(in altitudes: [Int]) -> (start: Int, rise: Int)? {
        var best: (start: Int, rise: Int)? = nil
        for (start, (here, next)) in zip(altitudes, altitudes.dropFirst()).enumerated() {
            let rise = next - here
            if rise > (best?.rise ?? 0) {
                best = (start: start, rise: rise)
            }
        }
        return best
    }
}
```

Comparing with `best?.rise ?? 0` handles both rules at once: before any climb is found, a leg must beat 0, so level and downhill legs never count. `dropFirst()` doesn't copy the array, so this uses O(1) extra space.

</Approach>
