An array keeps its elements in one block of memory, starting at its base address, with each element `stride` bytes after the one before. Write the two halves of the address formula: where element `index` starts, and which element a given byte belongs to.

`ElementAtAddress.address(ofIndex index: Int, base: Int, stride: Int) -> Int`

`ElementAtAddress.owner(ofByte address: Int, base: Int, size: Int, stride: Int, count: Int) -> Int?`

Each element uses the first `size` bytes of its slot. If `size` is smaller than `stride`, the bytes after it, up to the next slot, are **padding**, and they belong to no element. `owner` returns the index of the element whose bytes include `address`, or `nil` if the byte is before the array, after its last element, or padding.

## Examples

| Call | Result |
| --- | --- |
| `address(ofIndex: 5, base: 100, stride: 8)` | `140` |
| `address(ofIndex: 0, base: 4096, stride: 16)` | `4096` |
| `owner(ofByte: 140, base: 100, size: 8, stride: 8, count: 10)` | `5` |
| `owner(ofByte: 147, base: 100, size: 8, stride: 8, count: 10)` | `5` |
| `owner(ofByte: 180, base: 100, size: 8, stride: 8, count: 10)` | `nil` |
| `owner(ofByte: 99, base: 100, size: 8, stride: 8, count: 10)` | `nil` |
| `owner(ofByte: 124, base: 100, size: 9, stride: 16, count: 4)` | `1` |
| `owner(ofByte: 125, base: 100, size: 9, stride: 16, count: 4)` | `nil` |

Byte 147 is the last of element 5's eight bytes. Byte 180 would start element 10, but a 10-element array ends with element 9. In the last two rows each slot is 16 bytes but only 9 are used: byte 124 is byte 8 of element 1, and byte 125 is the first byte of its padding.

## Constraints

- `1 ≤ size ≤ stride ≤ 4,096` and `0 ≤ count ≤ 10¹²`
- `0 ≤ index < 10¹²`, `0 ≤ base ≤ 2⁴⁸` and `-2⁴⁸ ≤ address ≤ 2⁵⁰`, so no calculation overflows.
- Both functions must be O(1). The tests use arrays with a trillion elements.

<Hints>
<Hint>
`address` is the formula from the lesson: the base, plus `index` slots of `stride` bytes each.
</Hint>
<Hint>
For `owner`, work with the distance from the base, `address - base`. Dividing it by `stride` tells you which slot the byte is in, and the remainder tells you how far into that slot it is.
</Hint>
<Hint>
Three things can rule the byte out: a negative distance, a slot number of `count` or more, and a position in the slot of `size` or more. Check the negative case **before** dividing: Swift's `/` rounds towards zero, so `-1 / 8` is `0`, which would wrongly blame element 0 for the byte just before the array.
</Hint>
</Hints>

## Solutions

<Approach title="Check every element" time="O(count)" space="O(1)">

Work out where each element starts and ends, and see whether the byte falls inside. It's correct, and it's a good way to check the fast version on small arrays, but a trillion-element array means a trillion steps.

```swift
public static func owner(ofByte address: Int, base: Int, size: Int, stride: Int, count: Int) -> Int? {
    for index in 0..<count {
        let start = base + index * stride
        if address >= start && address < start + size {
            return index
        }
    }
    return nil
}
```

</Approach>

<Approach title="The formula, both ways" time="O(1)" space="O(1)">

Every slot is the same width, which is exactly what makes the formula work forwards, and it works backwards for the same reason: one division finds the slot, and the remainder finds the byte inside it.

```swift
public enum ElementAtAddress {
    public static func address(ofIndex index: Int, base: Int, stride: Int) -> Int {
        base + index * stride
    }

    public static func owner(ofByte address: Int, base: Int, size: Int, stride: Int, count: Int) -> Int? {
        let distance = address - base
        guard distance >= 0 else { return nil }      // before the array: check before dividing
        let index = distance / stride
        let offset = distance % stride
        guard index < count, offset < size else { return nil }
        return index
    }
}
```

The order of the checks matters only for the negative case. A distance of `-1` gives `index` 0 and `offset` `-1` in Swift, and `-1 < size` is true, so without the `guard` the function would return 0.

</Approach>
