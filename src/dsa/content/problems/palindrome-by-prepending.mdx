You may add letters to the **front** of `text`, and nowhere else. Return the shortest palindrome you can make this way.

`PrependPalindrome.shortest(from text: String) -> String`

## Examples

| `text` | Output |
| --- | --- |
| `"aacecaaa"` | `"aaacecaaa"` |
| `"abcd"` | `"dcbabcd"` |
| `"abb"` | `"bbabb"` |
| `"racecar"` | `"racecar"` |
| `"a"` | `"a"` |
| `""` | `""` |

In the first example, `aacecaa` at the start is already a palindrome, so only the last `a` needs a partner: one `a` in front. In the second, the longest palindrome at the start is just `a`, so `bcd` has to be mirrored in front as `dcb`.

## Constraints

- `text` holds 0 to 100,000 lowercase letters, a to z.
- The tests include 50,000 `a`s, then `b`, then 49,999 `a`s. Checking each prefix for being a palindrome, longest first, fails late on every prefix longer than the `a`s: over a billion comparisons.

<Hints>
<Hint>
Whatever you add in front, the original text sits at the end of the result. Which part of the text can stay in the middle of the palindrome without a partner being added?
</Hint>
<Hint>
Only the **longest palindromic prefix** P of the text can. Everything after P must be mirrored in front. So the answer is reverse(text after P) + text, and the whole problem is finding the longest palindromic prefix quickly.
</Hint>
<Hint>
A prefix of s is a palindrome exactly when it equals the matching *suffix* of reverse(s). So you want the longest prefix of s that's also a suffix of reverse(s): a border question. Compute the prefix function of s + separator + reverse(s) and read its last value.
</Hint>
</Hints>

## Solutions

<Approach title="Check every prefix, longest first" time="O(n²)" space="O(n)">

Try prefix lengths from n down to 1, and stop at the first palindrome. Simple and right, but on the tests' adversarial string every prefix longer than the run of `a`s fails only when the comparison reaches the `b`, so the total is about n²/8 comparisons.

</Approach>

<Approach title="Prefix function on s + separator + reverse(s)" time="O(n)" space="O(n)">

The last prefix-function value of the combined string is the length of the longest prefix of s that's also a suffix of reverse(s), which is the longest palindromic prefix. The separator, which no letter equals, stops a border from running across the middle; without it, `aa` + `aa` would claim a border of 3.

```swift
public enum PrependPalindrome {
    public static func shortest(from text: String) -> String {
        let s = Array(text.utf8)
        guard s.count > 1 else { return text }
        let combined = s.map { Int($0) } + [-1] + s.reversed().map { Int($0) }

        var pi = [Int](repeating: 0, count: combined.count)
        var k = 0
        for i in combined.indices.dropFirst() {
            while k > 0 && combined[i] != combined[k] { k = pi[k - 1] }
            if combined[i] == combined[k] { k += 1 }
            pi[i] = k
        }

        let palindromicPrefix = pi[combined.count - 1]
        let added = s[palindromicPrefix...].reversed()
        return String(decoding: added + s, as: UTF8.self)
    }
}
```

</Approach>

<Approach title="Rolling hashes, forwards and backwards" time="O(n)" space="O(1)">

Walk the prefixes from left to right, keeping two hashes of the prefix: one read forwards, one read backwards. Each grows in O(1): the forward hash multiplies by the base and adds the new letter; the backward hash adds the new letter times the next power of the base. Where the two agree, the prefix is (almost certainly) a palindrome. Keep the last length where they agree.

```swift
public enum PrependPalindrome {
    public static func shortest(from text: String) -> String {
        let s = Array(text.utf8)
        let modulus: UInt64 = (1 << 61) - 1
        func mulMod(_ x: UInt64, _ y: UInt64) -> UInt64 {
            let (high, low) = x.multipliedFullWidth(by: y)
            let sum = ((high << 3) | (low >> 61)) + (low & modulus)
            return sum >= modulus ? sum - modulus : sum
        }
        let base = UInt64.random(in: 256..<modulus)
        var forward: UInt64 = 0, backward: UInt64 = 0, power: UInt64 = 1
        var palindromicPrefix = 0
        for (i, c) in s.enumerated() {
            forward = (mulMod(forward, base) + UInt64(c)) % modulus     // s[0] … s[i] as digits
            backward = (backward + mulMod(UInt64(c), power)) % modulus  // s[i] … s[0] as digits
            power = mulMod(power, base)
            if forward == backward { palindromicPrefix = i + 1 }
        }
        return String(decoding: s[palindromicPrefix...].reversed() + s, as: UTF8.self)
    }
}
```

A collision could make it accept a prefix that isn't a palindrome. With a 61-bit prime and a random base that's vanishingly unlikely, and if you want certainty, verify the chosen prefix once by comparing letters: O(n), done once.

</Approach>

<Approach title="Manacher" time="O(n)" space="O(n)">

Manacher's radii answer "is `s[0..<L]` a palindrome?" in O(1): it is when the radius at centre L, in the string with separators, reaches L. Check every L and keep the largest that passes. It's a heavier tool than this problem needs, but it shows how the radius array turns palindrome questions into lookups.

</Approach>
