Given the root of a binary tree and two of its nodes, return their lowest common ancestor: the deepest node that has both of them in its subtree. A node counts as its own ancestor, so if one node is above the other, the upper one is the answer.

`DeepestSharedAncestor.lowestCommonAncestor(of first: TreeNode, and second: TreeNode, in root: TreeNode?) -> TreeNode?`

Both nodes are guaranteed to be in the tree. Return the node itself, not a copy: the tests compare identities with `===`. `TreeNode` comes from DSAKit, and trees are written in level order, the way `TreeNode.make` takes them.

## Examples

All of these use the tree `[10, 4, 7, 1, 9, nil, 3, nil, nil, 5, 8]`, and give each node by its value:

```text
          10
         /  \
        4    7
       / \    \
      1   9    3
         / \
        5   8
```

| `first` | `second` | Output |
| --- | --- | --- |
| `5` | `8` | the node `9` |
| `5` | `1` | the node `4` |
| `5` | `3` | the node `10` |
| `9` | `8` | the node `9` |
| `7` | `7` | the node `7` |

## Constraints

- The tree has at most 150,000 nodes and is at most about 500 levels deep.
- Values can repeat, so compare nodes with `===`, not by value.
- `first` and `second` are both in the tree, and may be the same node.

<Hints>
<Hint>
Ask each subtree what it found: nothing, one of the two nodes, or their common ancestor. A subtree whose root **is** one of the nodes can answer at once.
</Hint>
<Hint>
If the left subtree and the right subtree both found something, the two nodes are on different sides, so the current node is where their paths split. Otherwise, pass up whatever the one side found.
</Hint>
<Hint>
Another route: record every node's parent in a dictionary keyed by `ObjectIdentifier`. Collect all of `first`'s ancestors in a set, then climb from `second` until you reach one of them.
</Hint>
</Hints>

## Solutions

<Approach title="Parent map and a set of ancestors" time="O(n)" space="O(n)">

One walk records each node's parent. Then the ancestors of `first`, from itself up to the root, go into a set, and the first ancestor of `second` found in that set is the answer. After the O(n) set-up, each extra query would cost only O(h).

```swift
public static func lowestCommonAncestor(of first: TreeNode, and second: TreeNode, in root: TreeNode?) -> TreeNode? {
    guard let root else { return nil }
    var parent: [ObjectIdentifier: TreeNode] = [:]
    var pending = [root]
    while let node = pending.popLast() {
        for child in [node.left, node.right].compactMap({ $0 }) {
            parent[ObjectIdentifier(child)] = node
            pending.append(child)
        }
    }
    var ancestors: Set<ObjectIdentifier> = []
    var node: TreeNode? = first
    while let current = node {
        ancestors.insert(ObjectIdentifier(current))
        node = parent[ObjectIdentifier(current)]
    }
    var climber: TreeNode? = second
    while let current = climber, !ancestors.contains(ObjectIdentifier(current)) {
        climber = parent[ObjectIdentifier(current)]
    }
    return climber
}
```

</Approach>

<Approach title="Each subtree reports what it found" time="O(n)" space="O(h)">

A call returns `nil`, one of the two nodes, or their ancestor. Returning early at a matching node is safe because both nodes are in the tree: if the other one is below, this node is the answer, and if it's elsewhere, an ancestor will see results from both sides.

```swift
import DSAKit

public enum DeepestSharedAncestor {
    public static func lowestCommonAncestor(of first: TreeNode, and second: TreeNode, in root: TreeNode?) -> TreeNode? {
        guard let root else { return nil }
        if root === first || root === second {
            return root
        }
        let left = lowestCommonAncestor(of: first, and: second, in: root.left)
        let right = lowestCommonAncestor(of: first, and: second, in: root.right)
        if left != nil && right != nil {
            return root                              // one node on each side
        }
        return left ?? right
    }
}
```

If the nodes might not be in the tree, this would wrongly return the one that is. Count what a walk finds before trusting the answer.

</Approach>
