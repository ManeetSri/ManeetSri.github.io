A trading system must report the value at a given rank among the day's prices, and its contract promises a deadline that holds for **every** input, so a random pivot that's only fast on average isn't allowed. Write deterministic selection with the median-of-medians pivot, in two functions: `pivot(of:)` computes the pivot exactly as the rule below defines it, and `value(atSortedIndex:in:)` uses it to find the value that would be at a 0-based `index` if `numbers` were sorted.

`MedianOfMediansSelect.pivot(of numbers: [Int]) -> Int` and `MedianOfMediansSelect.value(atSortedIndex index: Int, in numbers: [Int]) -> Int`

**The pivot rule.** Split `numbers` into groups of 5 in order: `numbers[0..<5]`, `numbers[5..<10]`, and so on; the last group may be smaller. The median of a group is the element at index `count / 2` once that group is sorted (for a group of 4, the upper of the two middle values). The pivot is the median of those medians in the same sense: the value at sorted index `medians.count / 2` of the medians, which `value(atSortedIndex:in:)` can find recursively.

Both functions must be O(n) in the worst case, with no randomness and no sorting of anything bigger than a group of 5.

## Examples

| `numbers` | Call | Output | Why |
| --- | --- | --- | --- |
| `[9, 1, 7, 3, 5, 8, 2, 6, 4, 0, 11]` | `pivot(of:)` | `5` | the groups' medians are 5, 4 and 11; sorted, 4, 5, 11, the middle one is 5 |
| `[42]` | `pivot(of:)` | `42` | one group of one |
| `[4, 4, 1, 2]` | `pivot(of:)` | `4` | one group: sorted `[1, 2, 4, 4]`, index 2 |
| `[9, 1, 7, 3, 5]` | `value(atSortedIndex: 0, in:)` | `1` | the smallest |
| `[9, 1, 7, 3, 5]` | `value(atSortedIndex: 3, in:)` | `7` | sorted, it's `[1, 3, 5, 7, 9]` |
| `[5, 8, 8, 3, 8, 1]` | `value(atSortedIndex: 4, in:)` | `8` | duplicates count separately |

## Constraints

- `1 ≤ numbers.count ≤ 1,000,000`, and `0 ≤ index < numbers.count`.
- Values can be any `Int`, with any number of duplicates.
- Don't change the caller's array (you receive a copy, so that's automatic in Swift).
- The tests include large arrays that are sorted, reversed, all equal, or arranged to trap simple pivot rules.

<Hint>
Write `value(atSortedIndex:in:)` as quickselect first, with the pivot coming from `pivot(of:)`. Partition three ways, into smaller, equal and larger, then look at how many land in each part to decide whether the answer is in the smaller part, is the pivot itself, or is in the larger part (with the index shifted down).
</Hint>
<Hint>
For `pivot(of:)`, build the array of group medians: for each group of up to 5, sort that little slice and take the element at `count / 2`. Then call `value(atSortedIndex: medians.count / 2, in: medians)`. The two functions call each other, and both recursions shrink: the medians are a fifth of the input.
</Hint>
<Hint>
Why it's linear: at least about 3n/10 elements are ≤ the pivot and 3n/10 are ≥ it, so the side you continue in has at most about 7n/10 elements. The work satisfies T(n) ≤ T(n/5) + T(7n/10) + cn, and because 1/5 + 7/10 is less than 1, it adds up to O(n).
</Hint>
</Hints>

## Solutions

<Approach title="Sort, then index" time="O(n log n)" space="O(n)">

`numbers.sorted()[index]` gives the right value, and the median of the sorted medians gives the right pivot. It's a useful check, but it breaks the contract: sorting costs O(n log n), and selection can do better.

```swift
public static func value(atSortedIndex index: Int, in numbers: [Int]) -> Int {
    numbers.sorted()[index]
}
```

</Approach>

<Approach title="Median of medians" time="O(n) worst case" space="O(n)">

The pivot is computed from the groups of 5, so it's deterministic, and it's guaranteed to have a constant fraction of the elements on each side. Each round of selection discards at least about 3/10 of what's left, so the total work is a shrinking geometric series. The three-way partition makes duplicates harmless: an array of a million equal values finishes after one partition, because every index lands in the equal block.

```swift
public enum MedianOfMediansSelect {
    public static func pivot(of numbers: [Int]) -> Int {
        var medians: [Int] = []
        medians.reserveCapacity(numbers.count / 5 + 1)
        for start in stride(from: 0, to: numbers.count, by: 5) {
            let group = numbers[start..<min(start + 5, numbers.count)].sorted()   // at most 5 elements
            medians.append(group[group.count / 2])
        }
        if medians.count == 1 { return medians[0] }
        return value(atSortedIndex: medians.count / 2, in: medians)            // a fifth of the size
    }

    public static func value(atSortedIndex index: Int, in numbers: [Int]) -> Int {
        var numbers = numbers
        var index = index
        while true {
            if numbers.count <= 5 { return numbers.sorted()[index] }
            let pivot = pivot(of: numbers)
            var smaller: [Int] = []
            var larger: [Int] = []
            for value in numbers {
                if value < pivot {
                    smaller.append(value)
                } else if value > pivot {
                    larger.append(value)
                }
            }
            let equal = numbers.count - smaller.count - larger.count
            if index < smaller.count {
                numbers = smaller                                   // at most about 7n/10 left
            } else if index < smaller.count + equal {
                return pivot
            } else {
                index -= smaller.count + equal
                numbers = larger
            }
        }
    }
}
```

The continuing side is handled with a loop instead of a recursive call, so only the pivot computation recurses, and that shrinks by a factor of 5 each time: about 9 levels for a million values.

</Approach>
