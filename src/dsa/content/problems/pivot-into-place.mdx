Partition part of an array around its last element, the **pivot**, in place: every element smaller than the pivot moves before it, and every element greater than or equal to it ends up after it. Return the index where the pivot lands. This is the step that quick sort repeats.

`PivotIntoPlace.partition(_ numbers: inout [Int], low: Int, high: Int) -> Int`

Only `numbers[low...high]` takes part; the pivot is `numbers[high]`. Elements outside that range must not move. The order inside each side doesn't matter.

## Examples

| `numbers` | `low`, `high` | Returns | One possible result |
| --- | --- | --- | --- |
| `[7, 2, 9, 4, 6]` | `0`, `4` | `2` | `[2, 4, 6, 7, 9]` |
| `[3, 8, 1, 9, 5]` | `0`, `4` | `2` | `[3, 1, 5, 9, 8]` |
| `[5, 6, 7, 8, 1]` | `0`, `4` | `0` | `[1, 6, 7, 8, 5]` |
| `[2, 6, 2, 6, 2, 6, 4]` | `0`, `6` | `3` | `[2, 2, 2, 4, 6, 6, 6]` |
| `[5, 5, 5, 5]` | `0`, `3` | `0` | `[5, 5, 5, 5]` |
| `[100, 7, 2, 9, 4, 6, -100]` | `1`, `5` | `3` | `[100, 2, 4, 6, 7, 9, -100]` |

The pivot's final index is always `low` plus the number of elements in the range that are smaller than it. In the fifth example nothing is smaller than 5, so the pivot stays at index 0. In the last, 100 and −100 are outside the range and stay put.

## Constraints

- `0 ≤ low ≤ high < numbers.count ≤ 100,000`
- Any `Int` values, with duplicates.
- One pass over the range: O(high − low) time and O(1) extra space.

<Hints>
<Hint>
Keep a `boundary` index, starting at `low`. Everything in `low..<boundary` is smaller than the pivot. Scan `j` from `low` up to `high - 1`.
</Hint>
<Hint>
When `numbers[j]` is smaller than the pivot, swap it to `boundary` and move the boundary on by one. Larger or equal elements stay where they are: they're behind the boundary, on the "big" side.
</Hint>
<Hint>
After the scan, `boundary` is the first element of the big side. Swap the pivot from `high` into that slot, and return `boundary`.
</Hint>
</Hints>

## Solutions

<Approach title="Lomuto partition" time="O(n)" space="O(1)">

Three regions grow as `j` moves right: smaller than the pivot (`low..<boundary`), greater than or equal (`boundary..<j`) and not yet seen (`j..<high`). Each smaller element is swapped from the front of the big region to the end of the small one, which keeps both regions in one piece. The final swap puts the pivot between them, where it will stay for the rest of a quick sort.

```swift
public enum PivotIntoPlace {
    public static func partition(_ numbers: inout [Int], low: Int, high: Int) -> Int {
        let pivot = numbers[high]
        var boundary = low                               // low..<boundary: smaller than the pivot
        for j in low..<high where numbers[j] < pivot {
            numbers.swapAt(boundary, j)
            boundary += 1
        }
        numbers.swapAt(boundary, high)                   // the pivot moves between the two blocks
        return boundary
    }
}
```

`swapAt` with equal indexes does nothing, so no special case is needed when nothing smaller has been seen yet.

</Approach>
