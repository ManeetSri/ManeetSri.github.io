A library app keeps its catalogue numbers in a sorted array, with no number repeated. Given a number, return its index in the array, or `nil` if the library doesn't have it.

`SortedLookup.index(of target: Int, in numbers: [Int]) -> Int?`

The array can hold a million numbers, and the app looks numbers up thousands of times, so aim for O(log n) per lookup.

## Examples

| `target` | `numbers` | Output |
| --- | --- | --- |
| `23` | `[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]` | `5` |
| `2` | `[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]` | `0` |
| `91` | `[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]` | `9` |
| `13` | `[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]` | `nil` |
| `4` | `[]` | `nil` |
| `9` | `[4, 9]` | `1` |

## Constraints

- `0 ≤ numbers.count ≤ 1,000,000`
- `numbers` is sorted in strictly increasing order: no repeats.
- Values can be any `Int`, including negatives, `Int.min` and `Int.max`.

<Hints>
<Hint>
Keep two indexes, `low` and `high`, for the part of the array where the target could still be. Start with the whole array, look at the middle, and throw away the half that can't hold the target.
</Hint>
<Hint>
Pick one convention and stick to it. Closed: `high = numbers.count - 1`, `while low <= high`, and `high = mid - 1` when the middle is too big. Half-open: `high = numbers.count`, `while low < high`, and `high = mid`.
</Hint>
<Hint>
Before running the big tests, try arrays of size 0, 1 and 2, with the target first, last, and missing below, between and above. Write the middle as `low + (high - low) / 2`.
</Hint>
</Hints>

## Solutions

<Approach title="Linear search" time="O(n)" space="O(1)">

Correct, and the right tool for a single search of unsorted data. Here it ignores the sorted order, so thousands of lookups in a million numbers take billions of comparisons.

```swift
public static func index(of target: Int, in numbers: [Int]) -> Int? {
    numbers.firstIndex(of: target)
}
```

</Approach>

<Approach title="Binary search on a closed range" time="O(log n)" space="O(1)">

The invariant: if the target is in the array, its index is in `[low, high]`. Each pass compares the middle with the target and keeps only the half that could hold it, so a million numbers need at most 20 passes.

```swift
public enum SortedLookup {
    public static func index(of target: Int, in numbers: [Int]) -> Int? {
        var low = 0
        var high = numbers.count - 1
        while low <= high {
            let mid = low + (high - low) / 2
            if numbers[mid] == target {
                return mid
            } else if numbers[mid] < target {
                low = mid + 1                    // mid and everything left of it are too small
            } else {
                high = mid - 1                   // mid and everything right of it are too big
            }
        }
        return nil
    }
}
```

For an empty array, `high` starts at -1, so the loop never runs. Both updates step past mid, so the range always shrinks and the loop always ends.

</Approach>

<Approach title="DSAKit" time="O(log n)" space="O(1)">

Once you've written it yourself, DSAKit's `binarySearch(for:)` does the same job. It returns the first matching index, which here is the only one.

```swift
import DSAKit

public static func index(of target: Int, in numbers: [Int]) -> Int? {
    numbers.binarySearch(for: target)
}
```

</Approach>
