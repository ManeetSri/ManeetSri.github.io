Finish a `Point` struct with whole-number coordinates. It needs a `mutating` method that moves it, a method that returns a moved copy instead, and two ways to measure the distance to another point.

`PlanePoint.Point(x:y:)`, with `move(dx:dy:)`, `moved(dx:dy:) -> Point`, `manhattanDistance(to:) -> Int` and `distance(to:) -> Double`

- `move(dx:dy:)` changes the point itself.
- `moved(dx:dy:)` leaves the point alone and returns a new, moved one.
- The **Manhattan distance** counts horizontal plus vertical steps, like walking city blocks: `|x₁ − x₂| + |y₁ − y₂|`.
- The **straight-line distance** is the length of the direct line between them: the square root of `dx² + dy²`.

## Examples

| Code | Result |
| --- | --- |
| `var p = Point(x: 1, y: 2)`, then `p.move(dx: 3, dy: -4)` | `p` is now `(4, -2)` |
| `let q = Point(x: 5, y: 5).moved(dx: -2, dy: 10)` | `q` is `(3, 15)`; the original is still `(5, 5)` |
| `Point(x: 0, y: 0).manhattanDistance(to: Point(x: 3, y: 4))` | `7` |
| `Point(x: 0, y: 0).distance(to: Point(x: 3, y: 4))` | `5.0` |
| `Point(x: 2, y: 2).distance(to: Point(x: 2, y: 2))` | `0.0` |

## Constraints

- `-1,000,000 ≤ x, y, dx, dy ≤ 1,000,000`
- Distances are the same in both directions: `a.distance(to: b) == b.distance(to: a)`.
- Straight-line distances are checked to within `0.000000001`.

<Hints>
<Hint>
`move` changes `x` and `y`, so it must be marked `mutating`. The other three methods only read the point.
</Hint>
<Hint>
For `moved`, make a `var` copy of `self`, change the copy, and return it. You can even call `move` on the copy.
</Hint>
<Hint>
`abs(_:)` gives an absolute value. For the straight-line distance, convert the differences to `Double` first, then use `.squareRoot()` on `dx * dx + dy * dy`.
</Hint>
</Hints>

## Solutions

<Approach title="A mutating method and a copy that reuses it" time="O(1)" space="O(1)">

`move` is the only method that changes the point, so it's the only `mutating` one. `moved` works on a local copy, so the original is untouched: that's value semantics at work. Swift's own `sort()` and `sorted()` follow exactly this pattern.

```swift
public enum PlanePoint {
    public struct Point {
        public var x: Int
        public var y: Int

        public init(x: Int, y: Int) {
            self.x = x
            self.y = y
        }

        public mutating func move(dx: Int, dy: Int) {
            x += dx
            y += dy
        }

        public func moved(dx: Int, dy: Int) -> Point {
            var copy = self
            copy.move(dx: dx, dy: dy)
            return copy
        }

        public func manhattanDistance(to other: Point) -> Int {
            abs(other.x - x) + abs(other.y - y)
        }

        public func distance(to other: Point) -> Double {
            let dx = Double(other.x - x)
            let dy = Double(other.y - y)
            return (dx * dx + dy * dy).squareRoot()
        }
    }
}
```

Converting to `Double` before squaring matters for large inputs: a difference of 2,000,000 squared is 4 × 10¹², which fits in an `Int`, but converting first means you never have to think about it.

</Approach>
