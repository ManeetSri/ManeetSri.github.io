Two non-negative numbers are stored as linked lists of digits, one digit per node, the way you'd write them: **most significant digit first**, so 342 is `3 -> 4 -> 2`. Return their sum as a new list in the same format. When you return, both input lists must be exactly as they were: the same nodes, in the same order, holding the same digits.

`ForwardDigitListSum.add(_ first: ListNode?, _ second: ListNode?) -> ListNode?`

## Examples

| `first` | `second` | Result | As numbers |
| --- | --- | --- | --- |
| `7 -> 2 -> 4 -> 3` | `5 -> 6 -> 4` | `7 -> 8 -> 0 -> 7` | 7,243 + 564 = 7,807 |
| `9 -> 9` | `1` | `1 -> 0 -> 0` | 99 + 1 = 100 |
| `5` | `5` | `1 -> 0` | 5 + 5 = 10 |
| `3 -> 0 -> 1` | `0` | `3 -> 0 -> 1` | 301 + 0 = 301 |
| `0` | `0` | `0` | 0 + 0 = 0 |
| `1` | `9 -> 9 -> 9 -> 9` | `1 -> 0 -> 0 -> 0 -> 0` | 1 + 9,999 = 10,000 |

## Constraints

- Each list has 1 to 10,000 nodes, each holding a digit from 0 to 9.
- Neither number has leading zeros, except the number 0 itself, which is the single node `0`.
- The numbers can be far too big for an `Int`, so don't convert them. Aim for O(m + n) time.

<Hints>
<Hint>
Addition starts at the units, which are now at the far end of each list, and a singly linked list can't walk backwards. You need some way to visit the digits from the back.
</Hint>
<Hint>
One way: copy each list's digits into an array as you walk it. Arrays can be read from the end, so `popLast()` hands you the digits units first. Add column by column with a carry, as for units-first lists.
</Hint>
<Hint>
The digits of the answer come out units first too, but the answer must start with its most significant digit. Prepend each new digit instead of appending: `head = ListNode(digit, next: head)`. Then the last digit made, the most significant, ends up at the front.
</Hint>
</Hints>

## Solutions

<Approach title="Reverse, add, reverse back" time="O(m + n)" space="O(1) extra">

Reverse both inputs in place, add them units first, and reverse the answer. Then reverse the inputs again to put them back. No extra arrays, but the inputs are changed while it runs, so it's only safe when nothing else is reading them at the same time.

```swift
public static func add(_ first: ListNode?, _ second: ListNode?) -> ListNode? {
    let a = reverse(first)
    let b = reverse(second)
    var sum: ListNode? = nil
    var x = a
    var y = b
    var carry = 0
    while x != nil || y != nil || carry > 0 {
        let column = (x?.value ?? 0) + (y?.value ?? 0) + carry
        sum = ListNode(column % 10, next: sum)       // prepending builds the answer forwards
        carry = column / 10
        x = x?.next
        y = y?.next
    }
    _ = reverse(a)                                   // put the inputs back as they were
    _ = reverse(b)
    return sum
}

private static func reverse(_ head: ListNode?) -> ListNode? {
    var previous: ListNode? = nil
    var current = head
    while let node = current {
        let next = node.next
        node.next = previous
        previous = node
        current = next
    }
    return previous
}
```

Prepending each digit means the answer itself never needs reversing.

</Approach>

<Approach title="Digits into arrays, used as stacks" time="O(m + n)" space="O(m + n)">

Copy the digits into two arrays, then pop from their ends to add from the units upwards, prepending each digit of the answer. The inputs are only ever read, which makes this the safer choice.

```swift
import DSAKit

public enum ForwardDigitListSum {
    public static func add(_ first: ListNode?, _ second: ListNode?) -> ListNode? {
        var left = first?.values ?? []
        var right = second?.values ?? []
        var head: ListNode? = nil
        var carry = 0
        while !left.isEmpty || !right.isEmpty || carry > 0 {
            let column = (left.popLast() ?? 0) + (right.popLast() ?? 0) + carry
            head = ListNode(column % 10, next: head)
            carry = column / 10
        }
        return head
    }
}
```

`values` is DSAKit's walk from a node to the end of its list. Writing that loop yourself is just as good.

</Approach>
