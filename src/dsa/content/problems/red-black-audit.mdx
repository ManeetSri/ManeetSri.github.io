A teammate's red-black tree passes its unit tests, but you suspect its delete sometimes leaves the tree broken. Write the auditor: given a tree of coloured nodes, return its **black-height** if it's a valid red-black tree, or `nil` if any rule is broken.

`RedBlackAudit.blackHeight(of root: RedBlackAudit.Node?) -> Int?`

`Node` is written for you: `value`, `isRed`, `left` and `right`, with `init(_ value: Int, red: Bool = false, left: Node? = nil, right: Node? = nil)`. A tree is valid when all of these hold, treating every missing child as a black nil leaf:

1. It's a binary search tree with **no duplicates**: the inorder values are strictly increasing.
2. The root is black.
3. No red node has a red child.
4. Every path from the root down to a nil leaf passes through the same number of black nodes.

The black-height is that number, not counting the nil leaf. The empty tree is valid, with black-height 0.

## Examples

Trees are shown level by level, with R or B after each value.

| Tree | Output | Why |
| --- | --- | --- |
| `4B / 2B 6B / 1B 3B 5B 8R / 7B 9B / 10R` (the lesson's tree) | `3` | every path passes three black nodes |
| `2B / 1R 3R` | `1` | a 4-node: black with two red children |
| `2R / 1B 3B` | `nil` | the root is red |
| `3B / 2R / 1R` | `nil` | 2 and 1 are two reds in a row |
| `2B / 1B` | `nil` | the path to 1's nil leaves passes 2 black nodes, the path to 2's right nil passes 1 |
| `5B / 3R 8R / 1B 6B 7B 9B` | `nil` | 6 is in 5's left subtree but bigger than 5 |
| an empty tree | `0` | |

## Constraints

- `0 ≤` number of nodes `≤ 100,000`, and values can be any `Int`.
- Invalid trees can have any shape, but no tree is more than 1,000 levels deep.
- Don't change the tree.

<Hint>
Write one recursive function that returns the black-height of a subtree, or `nil` if the subtree breaks rule 3 or 4. A nil child returns 0. For a real node: if both children are valid and their black-heights are equal, return that height, plus 1 if the node is black. A red node with a red child returns `nil` straight away.

Pass down the range a subtree's values must lie in, as [Validate a BST](/dsa/learn/bst-validate) did, or check that an inorder walk is strictly increasing.
</Hint>
<Hint>
Rule 2 is the only one about a single node: check the root's colour once, outside the recursion.
</Hint>

## Solutions

<Approach title="List every path, then check" time="O(n × h)" space="O(n)">

Collect the inorder values and check they increase. Then list the black count of every root-to-nil path and check they're all equal, along with the colour rules node by node. It mirrors the definition directly, which makes it a good reference, but it walks some parts of the tree many times.

```swift
public static func blackHeight(of root: Node?) -> Int? {
    guard let root else { return 0 }
    if root.isRed { return nil }
    var values: [Int] = []
    var pathCounts = Set<Int>()
    var redRed = false
    func walk(_ node: Node?, blacksAbove: Int, parentRed: Bool) {
        guard let node else { pathCounts.insert(blacksAbove); return }    // reached a nil leaf
        if node.isRed && parentRed { redRed = true }
        let blacks = blacksAbove + (node.isRed ? 0 : 1)
        walk(node.left, blacksAbove: blacks, parentRed: node.isRed)
        values.append(node.value)
        walk(node.right, blacksAbove: blacks, parentRed: node.isRed)
    }
    walk(root, blacksAbove: 0, parentRed: false)
    let increasing = zip(values, values.dropFirst()).allSatisfy { $0 < $1 }
    return increasing && !redRed && pathCounts.count == 1 ? pathCounts.first : nil
}
```

</Approach>

<Approach title="One postorder pass with bounds" time="O(n)" space="O(h)">

Each call checks its own node against the open range its ancestors allow, then asks both children for their black-heights. Information goes down (the range) and comes back up (the black-height, or `nil` for "broken somewhere below"), so each node is visited once.

```swift
public enum RedBlackAudit {
    public final class Node {
        public var value: Int
        public var isRed: Bool
        public var left: Node?
        public var right: Node?

        public init(_ value: Int, red: Bool = false, left: Node? = nil, right: Node? = nil) {
            self.value = value
            self.isRed = red
            self.left = left
            self.right = right
        }
    }

    public static func blackHeight(of root: Node?) -> Int? {
        if root?.isRed == true { return nil }                    // rule 2: a black root
        return check(root, above: nil, below: nil)
    }

    /// The black-height of node's subtree if rules 1, 3 and 4 hold there and every value lies strictly
    /// between `above` and `below` (nil for no limit); nil otherwise.
    private static func check(_ node: Node?, above: Int?, below: Int?) -> Int? {
        guard let node else { return 0 }                         // a nil leaf: black, but not counted
        if let above, node.value <= above { return nil }         // rule 1: the BST order
        if let below, node.value >= below { return nil }
        if node.isRed && (node.left?.isRed == true || node.right?.isRed == true) {
            return nil                                           // rule 3: two reds in a row
        }
        guard let left = check(node.left, above: above, below: node.value),
              let right = check(node.right, above: node.value, below: below),
              left == right else { return nil }                  // rule 4: equal black counts
        return left + (node.isRed ? 0 : 1)
    }
}
```

Using `Int?` for the bounds, instead of `Int.min` and `Int.max`, means a node can legally hold `Int.min` or `Int.max`. The recursion depth is the tree's height, which for any valid red-black tree is at most 2 log₂(n + 1), and the constraints cap it for invalid ones.

</Approach>
