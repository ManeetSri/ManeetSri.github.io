A bank account starts with some money. Each day, one amount goes in (positive) or out (negative). Return the first day on which the balance drops **below** zero, counting days from 0, or `nil` if it never does. Once you know the answer, stop looking.

`FirstOverdraftDay.day(startingWith balance: Int, changes: [Int]) -> Int?`

A balance of exactly 0 isn't overdrawn.

## Examples

| `balance` | `changes` | Output |
| --- | --- | --- |
| `50` | `[-20, -20, 30, -70, 10]` | `3` |
| `0` | `[5, -5, -1]` | `2` |
| `100` | `[-10, 20, -50]` | `nil` |
| `0` | `[-1]` | `0` |
| `10` | `[]` | `nil` |

In the first example the balance goes 30, 10, 40, then -30 on day 3. The 10 that comes in on day 4 doesn't matter: the account was already overdrawn. In the second, the balance reaches exactly 0 on day 1, which is fine, and drops to -1 on day 2.

## Constraints

- `0 ≤ balance ≤ 1,000,000,000`
- `0 ≤ changes.count ≤ 100,000`
- `-1,000,000,000 ≤ changes[i] ≤ 1,000,000,000`

<Hints>
<Hint>
Each day's balance depends on the day before, so this needs running state: one variable that every day's change is added to.
</Hint>
<Hint>
`for (day, change) in changes.enumerated()` gives you each change together with its day number.
</Hint>
<Hint>
Return the day number the moment the balance goes below 0. If the loop finishes without returning, the account was never overdrawn.
</Hint>
</Hints>

## Solutions

<Approach title="Higher-order functions" time="O(n)" space="O(n)">

Build every day's balance with `reduce(into:)`, then find the first negative one with `firstIndex(where:)`:

```swift
public static func day(startingWith balance: Int, changes: [Int]) -> Int? {
    let balances = changes.reduce(into: [Int]()) { result, change in
        result.append((result.last ?? balance) + change)
    }
    return balances.firstIndex { $0 < 0 }
}
```

It gives the right answer, but look at the work. `reduce` walks **all** the changes and builds a whole array of balances, even when the account is overdrawn on day 0. `firstIndex` then walks that array again. The running state also had to be squeezed into `result.last ?? balance`, which takes a moment to decode.

</Approach>

<Approach title="One loop that stops early" time="O(n)" space="O(1)">

A loop keeps the running balance in a plain variable and returns as soon as it goes negative. This is both of the lesson's loop cases at once: state carried from one element to the next, and a search that can stop early.

```swift
public enum FirstOverdraftDay {
    public static func day(startingWith balance: Int, changes: [Int]) -> Int? {
        var current = balance
        for (day, change) in changes.enumerated() {
            current += change
            if current < 0 {
                return day
            }
        }
        return nil
    }
}
```

In the worst case, an account that's never overdrawn, it still reads every change: O(n). But it stores nothing beyond one balance, and when the overdraft comes early it stops right there. With 100,000 changes and an overdraft on day 3, that's 4 steps, where the `reduce` version walks all 100,000 changes and builds a 100,000-element array first.

</Approach>
