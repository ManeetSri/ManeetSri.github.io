A mosaic artist has `tiles` identical square tiles and wants to use every one of them to build solid square panels. A panel of side k uses k × k tiles, so panels come in sizes 1, 4, 9, 16, and so on, and any size can be used more than once. Return the fewest panels that use exactly `tiles` tiles between them.

`FewestSquarePanels.fewestPanels(tiles: Int) -> Int`

## Examples

| `tiles` | Output | Why |
| --- | --- | --- |
| `12` | `3` | 4 + 4 + 4; taking the biggest panel first gives 9 + 1 + 1 + 1 |
| `13` | `2` | 4 + 9 |
| `16` | `1` | one 4 × 4 panel |
| `7` | `4` | 4 + 1 + 1 + 1 |
| `43` | `3` | 25 + 9 + 9 |
| `1` | `1` | |

## Constraints

- `1 ≤ tiles ≤ 10,000`
- The tests include tile counts close to 10,000. An O(n √n) solution takes about a million steps there; trying every combination of panels would never finish.

<Hints>
<Hint>
Greedy fails: 12 shows that the biggest panel isn't always part of the best answer. Think about the last panel instead. It has some size s that fits, and the rest is a smaller problem.
</Hint>
<Hint>
Let `fewest[t]` be the fewest panels using exactly t tiles. Then `fewest[t] = 1 + the minimum of fewest[t − s]` over every square s ≤ t, with `fewest[0] = 0`.
</Hint>
<Hint>
Fill `fewest` from 1 up to `tiles`. For each t, loop over sides 1, 2, 3, ... while side × side ≤ t. Every total can be made from ones, so no entry is left at your "unknown" starting value.
</Hint>
</Hints>

## Solutions

<Approach title="Bottom-up over totals" time="O(n √n)" space="O(n)">

From [Decode ways and perfect squares](/dsa/learn/dp-decode-squares). It's the coin change shape with unlimited coins of sizes 1, 4, 9, 16 and so on: `fewest[t − s]` may itself use another panel of size s.

```swift
public enum FewestSquarePanels {
    public static func fewestPanels(tiles: Int) -> Int {
        var fewest = Array(repeating: Int.max, count: tiles + 1)
        fewest[0] = 0
        for total in stride(from: 1, through: tiles, by: 1) {
            var side = 1
            while side * side <= total {
                fewest[total] = min(fewest[total], fewest[total - side * side] + 1)
                side += 1
            }
        }
        return fewest[tiles]
    }
}
```

Adding 1 to `Int.max` never happens: `fewest[total - 1]` is always finished and finite, since 1 is a square.

</Approach>

<Approach title="Number theory" time="O(n)" space="O(1)">

Lagrange's four-square theorem says every positive whole number is a sum of at most four squares, and Legendre's three-square theorem says exactly when four are needed: when the number has the form 4ᵃ × (8b + 7). So check, in order: is it a square (1)? Is it a square plus a square (2)? Does it have Legendre's form (4)? Otherwise, 3. The tests use this as an independent check on the DP.

```swift
public static func fewestPanels(tiles: Int) -> Int {
    func isSquare(_ value: Int) -> Bool {
        var root = 0
        while (root + 1) * (root + 1) <= value {
            root += 1
        }
        return root * root == value
    }
    if isSquare(tiles) {
        return 1
    }
    var a = 1
    while a * a <= tiles {
        if isSquare(tiles - a * a) {
            return 2
        }
        a += 1
    }
    var rest = tiles
    while rest % 4 == 0 {
        rest /= 4
    }
    return rest % 8 == 7 ? 4 : 3
}
```

Here `isSquare` counts up to the root, so the two-squares check is O(√n) calls of O(√n) each: O(n) in all. Taking square roots with `Double.squareRoot()` (and checking the rounded root) brings it down to O(√n). It's elegant, but it relies on theorems you'd need to know already. The DP needs nothing but the recipe.

</Approach>
