The visualiser records a sort as frames, one per comparison and one per swap, so a player can step and scrub through them. A full copy of the array in every frame is simple, but bubble sort on 1,000 values would need gigabytes. Record insertion sort the way video does instead: a full picture every so often (a **keyframe**), and only what changed in between.

`DeltaFrameRecorder.Recording`, with `init(sorting input: [Int], keyframeEvery interval: Int)`, `steps`, `keyframes`, `frameCount` and `frame(at index: Int) -> Frame`

The frames are those of the lesson's `insertionSortFrames`:

- Frame 0 is the input.
- For each `i` from 1 to `count - 1`, with `j` starting at `i`: while `j > 0`, a **compare** frame for positions `j - 1` and `j` (values unchanged). If `values[j - 1] > values[j]`, swap them and add a **swap** frame showing the result, then move `j` down by one; otherwise stop this `i`.
- The last frame is the sorted array. An empty or one-value input has just two frames: the start and the finish.

What to store and provide:

- `steps: [Step]` holds exactly one `Step` per frame: `.start`, `.compare(j)`, `.swap(j)` or `.finish`, where `j` is the higher of the two positions involved.
- `keyframes: [[Int]]` holds the values at frames 0, `interval`, `2 × interval`, … and nothing else: `(frameCount - 1) / interval + 1` arrays.
- `frame(at:)` returns a `Frame` with the frame's `values` and `active` positions: `[j - 1, j]` for a compare or swap frame, `[]` for the first and last. It must rebuild the values from the nearest keyframe at or before the frame, in O(n + interval) time.

## Examples

`Recording(sorting: [4, 2, 3, 1], keyframeEvery: 5)` has 13 frames:

| Frame | Step | `values` | `active` |
| --- | --- | --- | --- |
| 0 | `.start` | `[4, 2, 3, 1]` | `[]` |
| 1 | `.compare(1)` | `[4, 2, 3, 1]` | `[0, 1]` |
| 2 | `.swap(1)` | `[2, 4, 3, 1]` | `[0, 1]` |
| 3 | `.compare(2)` | `[2, 4, 3, 1]` | `[1, 2]` |
| 4 | `.swap(2)` | `[2, 3, 4, 1]` | `[1, 2]` |
| 5 | `.compare(1)` | `[2, 3, 4, 1]` | `[0, 1]` |
| 6 | `.compare(3)` | `[2, 3, 4, 1]` | `[2, 3]` |
| 7 to 11 | `.swap(3)`, `.compare(2)`, `.swap(2)`, `.compare(1)`, `.swap(1)` | … | … |
| 12 | `.finish` | `[1, 2, 3, 4]` | `[]` |

Its `keyframes` are `[[4, 2, 3, 1], [2, 3, 4, 1], [2, 1, 3, 4]]`: the values at frames 0, 5 and 10. To show frame 9, start from the keyframe for frame 5 and replay the swaps of frames 6 to 9: `.swap(3)` gives `[2, 3, 1, 4]`, then `.swap(2)` gives `[2, 1, 3, 4]`, with `active` `[1, 2]`.

## Constraints

- `0 ≤ input.count ≤ 400`, so a recording can have about 160,000 frames.
- `1 ≤ interval`, and `0 ≤ index < frameCount`.
- Memory: O(frameCount) for the steps plus O(frameCount / interval × n) for the keyframes. Never store a full array per frame.

## Solutions

<Approach title="Steps for every frame, keyframes every interval" time="O(n²) to record, O(n + interval) per frame" space="O(frames + frames / interval × n)">

Recording is the sort itself plus O(1) work per frame and an O(n) copy every `interval` frames. Rebuilding copies one keyframe and replays at most `interval - 1` steps.

```swift
public enum DeltaFrameRecorder {
    public enum Step: Equatable {
        case start              // the input, before anything happens
        case compare(Int)       // positions j - 1 and j were compared
        case swap(Int)          // positions j - 1 and j were swapped
        case finish             // the sorted result
    }

    public struct Frame: Equatable {
        public let values: [Int]
        public let active: [Int]

        public init(values: [Int], active: [Int]) {
            self.values = values
            self.active = active
        }
    }

    public struct Recording {
        public let interval: Int
        public private(set) var steps: [Step] = []
        public private(set) var keyframes: [[Int]] = []

        public init(sorting input: [Int], keyframeEvery interval: Int) {
            self.interval = interval
            var items = input
            record(.start, items)
            for i in stride(from: 1, to: items.count, by: 1) {     // stride: empty, never a bad range
                var j = i
                while j > 0 {
                    record(.compare(j), items)
                    guard items[j - 1] > items[j] else { break }
                    items.swapAt(j - 1, j)
                    record(.swap(j), items)
                    j -= 1
                }
            }
            record(.finish, items)
        }

        private mutating func record(_ step: Step, _ items: [Int]) {
            if steps.count % interval == 0 { keyframes.append(items) }
            steps.append(step)
        }

        public var frameCount: Int { steps.count }

        public func frame(at index: Int) -> Frame {
            let key = index / interval
            var values = keyframes[key]
            for position in stride(from: key * interval + 1, through: index, by: 1) {
                if case .swap(let j) = steps[position] { values.swapAt(j - 1, j) }
            }
            switch steps[index] {
            case .compare(let j), .swap(let j):
                return Frame(values: values, active: [j - 1, j])
            case .start, .finish:
                return Frame(values: values, active: [])
            }
        }
    }
}
```

The interval is a dial between memory and scrubbing speed. With 160,000 frames of 400 values, full snapshots take 64 million numbers; with a keyframe every 64 frames, about 1 million plus one small step per frame, and any frame is at most 63 swaps away. Passing `items` to `record` doesn't copy the array unless a keyframe is stored, because Swift arrays are copied only when one of the sharers is changed.

</Approach>
