Numbers arrive one at a time. At any moment, report the **median** of everything that has arrived so far: the middle value when the count is odd, and the mean of the two middle values when it's even.

`RunningMedian.MedianTracker`, with `init()`, `add(_ value: Int)`, `count: Int` and `median: Double?` (`nil` before anything has arrived)

`add` should be O(log n) and `median` O(1).

## Examples

Each row adds the values in order and reads `median` after each one.

| Values | Medians |
| --- | --- |
| `6, 2, 9, 4` | `6.0, 4.0, 6.0, 5.0` |
| `5, 15, 1, 3` | `5.0, 10.0, 5.0, 4.0` |
| `1, 2` | `1.0, 1.5` |
| `-3, -8, -1` | `-3.0, -5.5, -3.0` |
| `10, 9, 8, 7, 6` | `10.0, 9.5, 9.0, 8.5, 8.0` |

In the first row, after 6, 2 and 9 the sorted values are 2, 6, 9, so the median is 6. After 4 they're 2, 4, 6, 9, and the median is (4 + 6) / 2 = 5.

## Constraints

- Up to 200,000 calls to `add`, with `-1,000,000,000 ≤ value ≤ 1,000,000,000`.
- The tests read the median after every one of 200,000 values. Keeping a sorted array costs O(n) per insert, about ten billion element moves in total: too slow.

<Hints>
<Hint>
The median only depends on the values in the middle. Split everything into a lower half and an upper half: the median is the largest of the lower half, the smallest of the upper half, or the mean of those two.
</Hint>
<Hint>
Keep the lower half in a **max**-heap and the upper half in a **min**-heap, so both middle values sit on top. Keep two rules: everything in `lower` is ≤ everything in `upper`, and `lower` has the same number of values as `upper` or one more.
</Hint>
<Hint>
To add a value: if it's bigger than `lower`'s top, it goes into `upper`, otherwise into `lower`. Then fix the sizes: if `lower` has two more, move its top to `upper`; if `upper` has more, move its top to `lower`. Convert to `Double` before averaging the two tops.
</Hint>
</Hints>

## Solutions

<Approach title="Keep a sorted array" time="O(n) per add, O(1) median" space="O(n)">

Binary-search for the insertion point and insert there. The search is O(log n), but `insert(_:at:)` shifts everything after the position, so each add is O(n).

</Approach>

<Approach title="Two heaps" time="O(log n) per add, O(1) median" space="O(n)">

```swift
import DSAKit

public enum RunningMedian {
    public struct MedianTracker {
        private var lower = Heap<Int>.maxHeap()      // the smaller half, largest on top
        private var upper = Heap<Int>.minHeap()      // the larger half, smallest on top

        public init() {}

        public var count: Int {
            lower.count + upper.count
        }

        public mutating func add(_ value: Int) {
            if let top = lower.peek(), value > top {
                upper.insert(value)
            } else {
                lower.insert(value)
            }
            if lower.count > upper.count + 1 {
                upper.insert(lower.pop()!)
            } else if upper.count > lower.count {
                lower.insert(upper.pop()!)
            }
        }

        public var median: Double? {
            guard let middle = lower.peek() else { return nil }
            if lower.count > upper.count {
                return Double(middle)
            }
            return (Double(middle) + Double(upper.peek()!)) / 2
        }
    }
}
```

Each add does at most three heap operations. The second rule means an odd count always leaves the middle value on top of `lower`.

</Approach>
