Build a set that can also hand back a uniformly random element, with every operation O(1) on average. Swift's own `Set` can't: its `randomElement()` has to step through the set's storage to reach a random position, which is O(n).

`ConstantTimeRandomSet.RandomSet<Element: Hashable>`, with `init()`, `count`, `isEmpty`, `contains(_:)`, `insert(_:) -> Bool`, `remove(_:) -> Bool`, `randomElement(using:) -> Element?` and `randomElement() -> Element?`

- `insert` returns `true` if the element was added, `false` if it was already there. `remove` returns `true` if it was removed, `false` if it wasn't there. Both results are discardable.
- `randomElement(using: &generator)` returns an element chosen uniformly at random with the given `RandomNumberGenerator`, or `nil` if the set is empty. Every element must be equally likely, whatever was inserted and removed before.
- `randomElement()` does the same with the system's generator.

## Examples

| Calls on a new `RandomSet<Int>` | Result |
| --- | --- |
| `insert(5)`, `insert(5)`, `insert(9)` | `true`, `false`, `true` |
| `count`, `contains(5)` | `2`, `true` |
| `remove(5)`, `remove(5)` | `true`, `false` |
| `randomElement(using: &generator)` | `9`: the only element |
| `remove(9)`, then `randomElement(using: &generator)` | `true`, then `nil` |

With the ten elements 0, 11, 22, …, 99, drawing 50,000 times picks each about 5,000 times.

## Constraints

- Up to 200,000 elements and 200,000 random draws.
- The tests pass a seeded generator, so they're repeatable, and check both that each draw is an element and that the draws are spread evenly.

<Hints>
<Hint>
Random access needs an array: `elements.randomElement(using: &generator)` is O(1) on an array, because it can jump straight to a random index. Membership needs a dictionary. Use both.
</Hint>
<Hint>
Keep `positions: [Element: Int]`, the index of each element in the array. Then `contains` and `insert` are a lookup and an append. The difficulty is `remove`: taking an element out of the middle of an array shifts everything after it, which is O(n).
</Hint>
<Hint>
Order doesn't matter in a set, so don't shift: move the **last** element into the removed element's slot, update its position in the dictionary, and remove the last slot. Take care when the element being removed **is** the last one.
</Hint>
</Hints>

## Solutions

<Approach title="Wrap a Set" time="O(1) insert and remove, O(n) random" space="O(n)">

Storing the elements in a `Set` and calling its `randomElement(using:)` is correct and uniform. But `Set` isn't a random-access collection: reaching the k-th element means stepping forward k times, so each draw is O(n). With 100,000 elements and 200,000 draws, that's billions of steps.

```swift
public func randomElement<G: RandomNumberGenerator>(using generator: inout G) -> Element? {
    storage.randomElement(using: &generator)     // storage is a Set<Element>: O(n)
}
```

</Approach>

<Approach title="Array plus index dictionary, with swap-remove" time="O(1) average per operation" space="O(n)">

The array gives random access; the dictionary finds any element's slot. The swap keeps the array packed with no holes, so a random index always lands on an element, and each element owns exactly one slot, which keeps the draw uniform.

```swift
public enum ConstantTimeRandomSet {
    public struct RandomSet<Element: Hashable> {
        private var elements: [Element] = []
        private var positions: [Element: Int] = [:]

        public init() {}

        public var count: Int {
            elements.count
        }

        public var isEmpty: Bool {
            elements.isEmpty
        }

        public func contains(_ element: Element) -> Bool {
            positions[element] != nil
        }

        @discardableResult
        public mutating func insert(_ element: Element) -> Bool {
            guard positions[element] == nil else { return false }
            positions[element] = elements.count
            elements.append(element)
            return true
        }

        @discardableResult
        public mutating func remove(_ element: Element) -> Bool {
            guard let hole = positions.removeValue(forKey: element) else { return false }
            let last = elements.removeLast()
            if hole < elements.count {                 // it wasn't the last one: fill the hole
                elements[hole] = last
                positions[last] = hole
            }
            return true
        }

        public func randomElement<G: RandomNumberGenerator>(using generator: inout G) -> Element? {
            elements.randomElement(using: &generator)  // O(1): arrays have random access
        }

        public func randomElement() -> Element? {
            var generator = SystemRandomNumberGenerator()
            return randomElement(using: &generator)
        }
    }
}
```

Removing the dictionary entry **first** and then checking `hole < elements.count` handles the last-element case without a special branch: if the removed element was last, `removeLast()` already took it, and there's no hole to fill.

</Approach>
