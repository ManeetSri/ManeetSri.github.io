Build a string from every `k`th character of `text`: the characters at positions 0, `k`, `2k` and so on, counting `Character`s from the start. Don't find each one by counting from the beginning of the string again: the whole walk must be O(n).

`EveryKthCharacter.pick(every k: Int, from text: String) -> String`

## Examples

| `k` | `text` | Output |
| --- | --- | --- |
| `2` | `"abcdefg"` | `"aceg"` |
| `3` | `"abcdefg"` | `"adg"` |
| `1` | `"swift"` | `"swift"` |
| `10` | `"swift"` | `"s"` |
| `2` | `"👋🏽a🇯🇵b"` | `"👋🏽🇯🇵"` |
| `4` | `""` | `""` |

In the fifth example the characters are `👋🏽`, `a`, `🇯🇵` and `b`. Each emoji is one `Character`, even though it's made of two scalars and 8 bytes, so positions 0 and 2 are the two emoji.

## Constraints

- `1 ≤ k ≤ 1,000,000`
- `0 ≤ text.count ≤ 100,000`, and `text` can contain any Unicode.
- One test uses 100,000 characters with `k = 1`, so the whole walk must be O(n).

<Hints>
<Hint>
Start an index at `text.startIndex`. While it's before `text.endIndex`, the character at it is one you want: append `text[index]` to the result.
</Hint>
<Hint>
To move on, `text.index(index, offsetBy: k)` jumps `k` characters, but it crashes if that would go past the end. `text.index(index, offsetBy: k, limitedBy: text.endIndex)` returns `nil` instead, which tells you to stop.
</Hint>
<Hint>
The limited version can also return exactly `text.endIndex`, a valid index you can't read from. The `while index < text.endIndex` check catches that on the next pass. Avoid `text.index(text.startIndex, offsetBy: i)` inside a loop: walking from the start every time makes the whole thing O(n²).
</Hint>
</Hints>

## Solutions

<Approach title="Count positions with enumerated" time="O(n)" space="O(n)">

Visit every character once and keep the ones whose position is a multiple of `k`. `enumerated()` supplies the position as an `Int`.

```swift
public static func pick(every k: Int, from text: String) -> String {
    var result = ""
    for (position, character) in text.enumerated() where position % k == 0 {
        result.append(character)
    }
    return result
}
```

It's O(n) and perfectly good. The next version makes the same walk with a `String.Index`, the tool you need when a string problem has to move in jumps, or in both directions.

</Approach>

<Approach title="Jump with limitedBy" time="O(n)" space="O(n)">

Keep a `String.Index` and move it `k` characters at a time. `limitedBy: text.endIndex` makes each jump safe: it returns `nil` when there aren't `k` characters left, and the loop ends.

```swift
public enum EveryKthCharacter {
    public static func pick(every k: Int, from text: String) -> String {
        var result = ""
        var index = text.startIndex
        while index < text.endIndex {
            result.append(text[index])
            guard let next = text.index(index, offsetBy: k, limitedBy: text.endIndex) else {
                break
            }
            index = next
        }
        return result
    }
}
```

Each jump costs O(k), because Swift still has to step over the k characters to find where the next one starts. But each jump starts where the last one ended, so across the whole loop every character is stepped over once: O(n) in total.

Compare the version people write when they miss `text[i]`:

```swift
for i in stride(from: 0, to: text.count, by: k) {
    result.append(text[text.index(text.startIndex, offsetBy: i)])
}
```

Every `offsetBy: i` starts again from the beginning. With `k = 1` and 100,000 characters that's about five billion steps, where the versions above take 100,000.

</Approach>
