A railway timetable numbers its stations from **1** to `stationCount` and lists its two-way tracks as pairs `[a, b]`. The list was merged from several sources, so the same track can appear more than once, in either order. Build the network's adjacency list: return `stationCount` lists, where the list at index i holds the stations next to station **i + 1**, in increasing order, each once.

`StationNeighbourLists.build(stationCount: Int, links: [[Int]]) -> [[Int]]`

The answer keeps the timetable's station numbers inside the lists; only the outer index is shifted down by one. The length of each list is that station's degree.

## Examples

| `stationCount` | `links` | Returns |
| --- | --- | --- |
| 4 | `[[1, 2], [2, 3], [1, 3], [3, 4]]` | `[[2, 3], [1, 3], [1, 2, 4], [3]]` |
| 3 | `[[3, 1]]` | `[[3], [], [1]]` |
| 2 | `[[1, 2], [2, 1], [1, 2]]` | `[[2], [1]]` |
| 6 | `[[2, 5]]` | `[[], [5], [], [], [2], []]` |

In the first example, station 3 touches three tracks, so its list is `[1, 2, 4]` and its degree is 3. In the third, one track is listed three times.

## Constraints

- `1 ≤ stationCount ≤ 100,000` and `0 ≤ links.count ≤ 200,000`.
- Every pair holds two different station numbers from 1 to `stationCount`.
- Stations with no tracks still get an (empty) list.
- The tests use 100,000 stations, so checking every station against every link, O(n · m), is too slow.

<Hints>
<Hint>
Make `Array(repeating: [Int](), count: stationCount)`. Station s lives at index `s - 1`. A two-way track goes into **both** stations' lists.
</Hint>
<Hint>
Repeated tracks put the same neighbour into a list more than once. Sorting the list brings the copies side by side.
</Hint>
<Hint>
After sorting, keep a station only when it differs from the last one you kept. Or build each list from a `Set` and sort that: either way, each list costs O(d log d) for d entries.
</Hint>
</Hints>

## Solutions

<Approach title="Append both ways, then sort and drop repeats" time="O(n + m log m)" space="O(n + m)">

Each of the m tracks adds two entries, and sorting all the lists costs at most O(m log m) in total.

```swift
public enum StationNeighbourLists {
    public static func build(stationCount: Int, links: [[Int]]) -> [[Int]] {
        var lists = Array(repeating: [Int](), count: stationCount)
        for link in links {
            let a = link[0]
            let b = link[1]
            lists[a - 1].append(b)          // station a lives at index a - 1
            lists[b - 1].append(a)          // undirected: both ends know about the link
        }
        return lists.map { list in
            var unique: [Int] = []
            for station in list.sorted() where station != unique.last {
                unique.append(station)
            }
            return unique
        }
    }
}
```

`unique.last` is `nil` for an empty array, so the first station is always kept.

</Approach>

<Approach title="A set per station" time="O(n + m log m)" space="O(n + m)">

Collect each station's neighbours in a `Set<Int>` while reading the links, so repeats vanish as they arrive, then return `sets.map { $0.sorted() }`. It's the same complexity with more memory per station; the sort is still needed because a set has no order.

</Approach>
