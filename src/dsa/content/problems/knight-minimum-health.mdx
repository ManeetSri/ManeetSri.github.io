A knight enters a dungeon grid at the top-left cell and must reach the bottom-right cell, moving only right or down. Every cell changes the knight's health by its value: negative values are traps, positive values are potions, and the first and last cells count too. The knight dies the moment their health is 0 or less. Return the smallest whole-number starting health that gets the knight to the bottom-right cell alive.

`KnightEntryHealth.minimumHealth(_ dungeon: [[Int]]) -> Int`

## Examples

| `dungeon` | Output |
| --- | --- |
| `[[0, -8, 20], [-1, -1, -1], [-1, -1, 0]]` | `4` |
| `[[-4, 3], [-2, -6]]` | `8` |
| `[[2, -3, 4]]` | `2` |
| `[[-5, 100]]` | `6` |
| `[[25]]` | `1` |

In the first example, going right first ends with the most health, but the −8 trap at the start means it needs 9. Going down first loses 3 overall and needs only 4. In the fourth, the potion comes too late to help with the trap. In the last, the knight still has to walk in alive, so the answer is at least 1.

## Constraints

- `1 ≤ rows ≤ 200` and `1 ≤ cols ≤ 200`, and every row has the same length.
- `-1,000 ≤ dungeon[r][c] ≤ 1,000`
- The tests use 200 × 200 dungeons.

<Hints>
<Hint>
Keeping the most health at each cell going forwards doesn't work: a route with more health now may have dipped lower earlier. What single number would describe the rest of the trip from a cell?
</Hint>
<Hint>
Let `need[r][c]` be the least health the knight can enter (r, c) with and still finish. It depends only on the cells ahead, so fill it from the bottom-right corner backwards.
</Hint>
<Hint>
`need[r][c] = max(1, min(need below, need right) − dungeon[r][c])`. Just past the goal, the knight only needs 1. The `max(1, …)` stops a potion from lending health in advance.
</Hint>
</Hints>

## Solutions

<Approach title="Binary search on the starting health" time="O(rows × cols × log S)" space="O(cols)">

If the knight survives starting with h, they survive with h + 1, so binary search for the smallest h that works. With the start fixed, a forward pass works: keep the most health the knight can have after each cell while still alive (more health is always at least as good). S is the total damage of all the traps, which bounds the answer. Correct and a good check, but slower and longer than filling backwards.

</Approach>

<Approach title="Backwards DP, one row" time="O(rows × cols)" space="O(cols)">

Fill `need` from the bottom-right, one row at a time. In a single array, `need[c]` still holds the row below when it's read, and `need[c + 1]` already holds this row's cell to the right. An extra entry past the right edge stays "impossible", and the entry below the goal starts at 1.

```swift
public enum KnightEntryHealth {
    public static func minimumHealth(_ dungeon: [[Int]]) -> Int {
        guard let cols = dungeon.first?.count, cols > 0 else { return 1 }
        let impossible = Int.max / 2
        var need = Array(repeating: impossible, count: cols + 1)
        need[cols - 1] = 1                          // just past the goal, being alive is enough
        for r in stride(from: dungeon.count - 1, through: 0, by: -1) {
            for c in stride(from: cols - 1, through: 0, by: -1) {
                let onward = min(need[c], need[c + 1])  // below (still the old value) or right (updated)
                need[c] = max(1, onward - dungeon[r][c])
            }
        }
        return need[0]
    }
}
```

The minimum is taken before subtracting, so the impossible value is never used in arithmetic: every cell inside the grid has at least one real way onward.

</Approach>
