Parcels come down a conveyor to a delivery van, one at a time, in order. Load them following these rules, and return how many parcels end up in the van.

- A weight of **0 or less** means the scanner misread the label. Skip that parcel and carry on with the next one.
- Otherwise, if the parcel fits, meaning the total load stays at most `capacity`, load it.
- The first real parcel that **doesn't** fit ends loading: the van leaves, and nothing behind it is loaded, not even parcels light enough to fit.

`VanParcelLoading.loadedCount(_ weights: [Int], capacity: Int) -> Int`

## Examples

| `weights` | `capacity` | Output | Why |
| --- | --- | --- | --- |
| `[5, 0, 8, 4, 2]` | `15` | `2` | 5 and 8 make 13; 4 would make 17, so the van leaves, though the 2 behind it would fit |
| `[4, -2, 6, 5]` | `15` | `3` | -2 is skipped; 4 + 6 + 5 is exactly 15, which fits |
| `[20, 1, 1]` | `15` | `0` | the first parcel is too heavy, so nothing is loaded |
| `[0, -1]` | `15` | `0` | no real parcels at all |
| `[]` | `15` | `0` | an empty conveyor |

## Constraints

- `0 ≤ weights.count ≤ 10,000`
- `-1,000 ≤ weights[i] ≤ 1,000,000`
- `0 ≤ capacity ≤ 10⁹`

<Hints>
<Hint>
Walk the conveyor with `for weight in weights`, keeping two variables: the load so far and the number of parcels loaded.
</Hint>
<Hint>
There are two different ways to stop. A misread label stops only *this* parcel, and the loop carries on: that's `continue`. A parcel that doesn't fit stops the *whole* loop: that's `break`.
</Hint>
<Hint>
Check whether `load + weight > capacity` **before** adding the parcel, and `break` if it is. Otherwise add the weight to the load and count the parcel.
</Hint>
</Hints>

## Solutions

<Approach title="continue to skip, break to stop" time="O(n)" space="O(1)">

The unusual cases are dealt with at the top of the loop body, each with the right keyword, so the normal work, loading a parcel, sits at the bottom with nothing wrapped around it.

```swift
public enum VanParcelLoading {
    public static func loadedCount(_ weights: [Int], capacity: Int) -> Int {
        var load = 0
        var loaded = 0
        for weight in weights {
            if weight <= 0 {
                continue // a misread label: skip this parcel only
            }
            if load + weight > capacity {
                break // the van leaves; nothing behind this parcel is loaded
            }
            load += weight
            loaded += 1
        }
        return loaded
    }
}
```

Each parcel is looked at once at most, and `break` means parcels after the van leaves aren't looked at at all.

</Approach>

<Approach title="where to skip, break to stop" time="O(n)" space="O(1)">

When a condition only decides which items to visit, a `where` clause says it directly. Misread labels never enter the loop body, which leaves just the one decision inside it.

```swift
public enum VanParcelLoading {
    public static func loadedCount(_ weights: [Int], capacity: Int) -> Int {
        var load = 0
        var loaded = 0
        for weight in weights where weight > 0 {
            if load + weight > capacity {
                break
            }
            load += weight
            loaded += 1
        }
        return loaded
    }
}
```

Mixing up the two keywords is the classic bug here. With `continue` instead of `break` for a parcel that doesn't fit, the first example would load the 2 as well and return 3: a different rule, and a different answer.

</Approach>
