Call a pair of positions i < j **lopsided** when the earlier value is more than twice the later one: `numbers[i] > 2 * numbers[j]`. Count the lopsided pairs in an array.

`LopsidedPairs.count(in numbers: [Int]) -> Int`

Values can be negative, which is where "more than twice" gets interesting: −1 is more than twice −3, because 2 × −3 = −6. Aim for O(n log n).

## Examples

| `numbers` | Returns | The lopsided pairs |
| --- | --- | --- |
| `[7, 1, 3, 2]` | `3` | (7, 1), (7, 3), (7, 2) |
| `[6, 3, 1]` | `2` | (6, 1), (3, 1) |
| `[9, 9, 4, 4]` | `4` | each 9 with each 4 |
| `[4, 2]` | `0` | 4 isn't more than 2 × 2 |
| `[-1, -3]` | `1` | −1 > −6 |
| `[1, 0, -1]` | `3` | every pair |

## Constraints

- `0 ≤ numbers.count ≤ 100,000`
- Every value fits in an `Int32` (from −2,147,483,648 to 2,147,483,647), so `2 * value` can't overflow a 64-bit `Int`.
- The answer can be close to n² / 2.

<Hints>
<Hint>
This looks like counting inversions, but the merge alone can't count it: the merge compares `a` with `b`, and you need to compare `a` with `2 * b`. Do the counting in a separate pass, just before the merge.
</Hint>
<Hint>
With both halves sorted, take each left value in increasing order. The right values it's more than twice are a prefix of the right half, and as the left value grows, that prefix can only get longer.
</Hint>
<Hint>
So one pointer `j` into the right half never moves backwards: for each `i` in the left half, advance `j` while `items[i] > 2 * items[j]`, then add `j - mid`. The pass is O(n), and then you merge as usual.
</Hint>
</Hints>

## Solutions

<Approach title="Check every pair" time="O(n²)" space="O(1)">

The reference to test against, and too slow for 100,000 values.

```swift
public static func count(in numbers: [Int]) -> Int {
    var count = 0
    for i in numbers.indices {
        for j in (i + 1)..<numbers.count where numbers[i] > 2 * numbers[j] {
            count += 1
        }
    }
    return count
}
```

</Approach>

<Approach title="Merge sort with a counting pass" time="O(n log n)" space="O(n)">

Every lopsided pair lies inside the left half, inside the right half, or across the middle. The recursion counts the first two kinds. For the across pairs, sorting the halves first lets a pair of pointers count them in one linear sweep, because "more than twice" only gets easier to satisfy as the left value grows. The merge then keeps the halves sorted for the level above.

```swift
public enum LopsidedPairs {
    public static func count(in numbers: [Int]) -> Int {
        var items = numbers
        var buffer = numbers
        return sortAndCount(&items, &buffer, 0, items.count)
    }

    /// Sorts items[low..<high] and returns the number of lopsided pairs inside it.
    private static func sortAndCount(_ items: inout [Int], _ buffer: inout [Int], _ low: Int, _ high: Int) -> Int {
        guard high - low > 1 else { return 0 }
        let mid = low + (high - low) / 2
        var pairs = sortAndCount(&items, &buffer, low, mid) + sortAndCount(&items, &buffer, mid, high)

        // Count the pairs with i in the left half and j in the right half
        var j = mid
        for i in low..<mid {
            while j < high && items[i] > 2 * items[j] {
                j += 1
            }
            pairs += j - mid
        }

        // Merge the halves
        for index in low..<high {
            buffer[index] = items[index]
        }
        var left = low
        var right = mid
        for write in low..<high {
            if right == high || (left < mid && buffer[left] <= buffer[right]) {
                items[write] = buffer[left]
                left += 1
            } else {
                items[write] = buffer[right]
                right += 1
            }
        }
        return pairs
    }
}
```

In a language with 32-bit integers, `2 * items[j]` could overflow. Swift's `Int` is 64 bits on every Apple platform, and the constraints keep values within 32 bits, so here it's safe.

</Approach>
