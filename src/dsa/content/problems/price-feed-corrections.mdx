A stock's price feed sends records of the form (time, price). Records can arrive out of order, and a record for a time that already has a price is a **correction**: it replaces the old price, which no longer counts for anything. After any record, report the latest price (the price at the largest time seen), and the highest and lowest of all current prices.

`PriceFeedCorrections.Feed`, with `init()`, `record(time:price:)`, `latest: Int?`, `highest: Int?` and `lowest: Int?`

All three properties are `nil` before the first record. Aim for O(log n) per record and per query.

## Examples

| Calls on a new feed | `latest` | `highest` | `lowest` |
| --- | --- | --- | --- |
| record (1, 100), then (3, 90) | `90` | `100` | `90` |
| …then (2, 120), which arrives late | `90` | `120` | `90` |
| …then (2, 95), correcting time 2 | `90` | `100` | `90` |
| …then (1, 85), correcting time 1 | `90` | `95` | `85` |
| new feed: record (10, 5), then (10, 7) | `7` | `7` | `7` |

After the third record, 120 is gone: it was the price at time 2, which now holds 95. The latest price stays 90 throughout the first four rows, because time 3 is still the latest time.

## Constraints

- Up to 100,000 records, with every property read after each one in the largest test.
- Times and prices are any `Int`, including negatives.
- The same price can be current at many times at once.
- Copying a feed gives an independent feed, as with any struct.

<Hints>
<Hint>
A `Dictionary` from time to price handles corrections, and remembering the largest time seen gives `latest`. For `highest`, a single running maximum doesn't work: a correction can remove the maximum, and then you'd need the next largest price.
</Hint>
<Hint>
Keep every current price in a structure that stays sorted as prices come and go. Because several times can share a price, it needs to hold repeats: a sorted **multiset**.
</Hint>
<Hint>
A `SortedMap` from price to "how many times currently have this price" is a sorted multiset. A correction decrements the old price's count (removing it at zero) and increments the new one's. The smallest and largest keys, `first` and `last`, are the lowest and highest prices.
</Hint>
</Hints>

## Solutions

<Approach title="Scan the current prices" time="O(1) per record, O(n) per query" space="O(n)">

Store time → price and scan all the prices for each query. It's correct, and a good checker, but with a query after each of 100,000 records it's billions of steps.

```swift
public struct Feed {
    private var priceAt: [Int: Int] = [:]
    private var latestTime: Int?

    public init() {}

    public mutating func record(time: Int, price: Int) {
        priceAt[time] = price
        latestTime = max(latestTime ?? time, time)
    }

    public var latest: Int? { latestTime.flatMap { priceAt[$0] } }
    public var highest: Int? { priceAt.values.max() }
    public var lowest: Int? { priceAt.values.min() }
}
```

</Approach>

<Approach title="A dictionary plus a sorted multiset" time="O(log n) per record and query" space="O(n)">

The dictionary says what each time's current price is, so a correction knows which price to take away. The `SortedMap` counts how many times hold each price, keeping prices sorted with repeats. Both are value types, so the feed is too.

```swift
import DSAKit

public enum PriceFeedCorrections {
    public struct Feed {
        private var priceAt: [Int: Int] = [:]                // time → current price
        private var timesAtPrice = SortedMap<Int, Int>()     // price → how many times hold it
        private var latestTime: Int?

        public init() {}

        public mutating func record(time: Int, price: Int) {
            if let old = priceAt[time] {
                let remaining = timesAtPrice[old, default: 0] - 1
                timesAtPrice[old] = remaining == 0 ? nil : remaining
            }
            priceAt[time] = price
            timesAtPrice[price, default: 0] += 1
            if latestTime.map({ time > $0 }) ?? true {
                latestTime = time
            }
        }

        public var latest: Int? {
            latestTime.flatMap { priceAt[$0] }
        }

        public var highest: Int? {
            timesAtPrice.last?.key
        }

        public var lowest: Int? {
            timesAtPrice.first?.key
        }
    }
}
```

Another route uses two heaps (you'll meet them in M39): push every (price, time) record, and when the top of a heap is a record that has since been corrected, pop it and look again. That "lazy deletion" is O(log n) amortised too, but the sorted multiset is simpler to get right.

</Approach>
