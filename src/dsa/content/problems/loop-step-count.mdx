Two loops are described below. For each one, return exactly how many times its `body()` runs for a given `n`, **without running the loop**: work out a formula, or a much shorter calculation, instead.

`LoopStepCount.pairChecks(_ n: Int) -> Int` counts the body runs of this loop, which compares every item with every later item:

```swift
for i in 0..<n {
    for j in (i + 1)..<n {
        body()
    }
}
```

`LoopStepCount.shrinkingPasses(_ n: Int) -> Int` counts the body runs of this one, whose passes get shorter and shorter:

```swift
var size = n
while size > 0 {
    for _ in 0..<size {
        body()
    }
    size /= 2
}
```

## Examples

| Call | Output | Why |
| --- | --- | --- |
| `pairChecks(0)` | `0` | the outer loop never runs |
| `pairChecks(5)` | `10` | 4 + 3 + 2 + 1 + 0 |
| `pairChecks(10)` | `45` | |
| `shrinkingPasses(1)` | `1` | one pass of size 1 |
| `shrinkingPasses(10)` | `18` | passes of 10, 5, 2 and 1 |
| `shrinkingPasses(1000)` | `1994` | |

## Constraints

- `pairChecks`: `0 ≤ n ≤ 10⁹`. Answer in O(1): running the loops for n = 10⁹ would take about 5 × 10¹⁷ steps.
- `shrinkingPasses`: `0 ≤ n ≤ 10¹⁸`. Take O(log n) steps or fewer, so don't run the inner loop.
- Every answer fits in an `Int`.

<Hint>
Run a counting experiment for n = 1 to 6 and write the results down. For `pairChecks`, how many times does the inner loop run when i = 0? When i = 1?
</Hint>
<Hint>
For `pairChecks`, the inner loop runs n − 1 − i times, so the total is (n − 1) + (n − 2) + … + 1 + 0. That's the triangle sum from [Analysing nested, halving and dependent loops](/dsa/learn/bigo-analysing-loops). Check that your formula also gives 0 for n = 0 and n = 1.
</Hint>
<Hint>
For `shrinkingPasses`, each pass of the `while` loop runs the body exactly `size` times. So keep the `while` loop, but replace the inner loop with `total += size`. That's only about log₂ n passes. (Integer division rounds down, which is why the answer isn't exactly 2n.)
</Hint>
</Hints>

## Solutions

<Approach title="Run the loops and count" time="O(n²) and O(n)" space="O(1)">

The direct translation: put a counter where `body()` is. It's a good way to check a formula for small n, but `pairChecks(1_000_000_000)` would never finish, and `shrinkingPasses` near 10¹⁸ would take centuries.

```swift
public static func pairChecks(_ n: Int) -> Int {
    var steps = 0
    for i in 0..<n {
        for _ in (i + 1)..<n {
            steps += 1
        }
    }
    return steps
}
```

</Approach>

<Approach title="A formula, and whole passes at a time" time="O(1) and O(log n)" space="O(1)">

`pairChecks`: the inner loop runs n − 1 times, then n − 2, down to 0. By the triangle formula, (n − 1) + … + 1 + 0 = n(n − 1) / 2. For n = 0 that's 0 × (−1) / 2 = 0, and for n = 1 it's 0, so no special cases are needed. With n up to 10⁹, n(n − 1) is about 10¹⁸, which still fits in an `Int`.

`shrinkingPasses`: the passes are n, ⌊n/2⌋, ⌊n/4⌋, …, 1. Adding a whole pass in one step makes the work proportional to the number of passes, about log₂ n, instead of the number of body runs, about 2n.

```swift
public enum LoopStepCount {
    public static func pairChecks(_ n: Int) -> Int {
        n * (n - 1) / 2
    }

    public static func shrinkingPasses(_ n: Int) -> Int {
        var total = 0
        var size = n
        while size > 0 {
            total += size
            size /= 2
        }
        return total
    }
}
```

The `shrinkingPasses` total is always less than 2n: the geometric series from the loops lesson. So the original loop is O(n), even though it looks like it might be O(n log n).

</Approach>
