A transit network has stations numbered `0` to `stationCount - 1` and one-way connections `[from, to]`. You're given a batch of questions: each query `[a, b]` asks whether you can travel from station `a` to station `b` by following connections, through any number of other stations. Every station can reach itself. Return one answer per query, in order.

`TransitReachability.canReach(stationCount: Int, connections: [[Int]], queries: [[Int]]) -> [Bool]`

## Examples

With 5 stations and `connections = [[0, 1], [1, 2], [3, 2], [2, 4]]`:

| Query | Answer | Why |
| --- | --- | --- |
| `[0, 4]` | `true` | 0 → 1 → 2 → 4 |
| `[4, 0]` | `false` | connections only go one way |
| `[3, 4]` | `true` | 3 → 2 → 4 |
| `[0, 3]` | `false` | nothing leads into 3 |
| `[2, 2]` | `true` | a station reaches itself |
| `[1, 4]` | `true` | 1 → 2 → 4 |

So the call returns `[true, false, true, false, true, true]`.

## Constraints

- `1 ≤ stationCount ≤ 300`
- `0 ≤ connections.count ≤ 10,000` and `0 ≤ queries.count ≤ 10,000`
- All station numbers are in `0..<stationCount`. Connections may repeat, or join a station to itself.

<Hints>
<Hint>
One search per query works, but with 10,000 queries the same searches are repeated over and over. Could you answer every possible pair once, up front?
</Hint>
<Hint>
Floyd–Warshall's loops work with Booleans: `reach[i][j]` becomes true if `reach[i][k]` and `reach[k][j]` are both true. Keep k as the outer loop.
</Hint>
<Hint>
Start with `reach[i][i] = true` for every station and `reach[from][to] = true` for every connection. After the three loops, each query is one lookup.
</Hint>
</Hints>

## Solutions

<Approach title="A search per query" time="O(q · (n + m))" space="O(n + m)">

Build an adjacency list and run a DFS or BFS from `a` for every query. Simple, but it repeats the same work for every query that starts at the same station.

</Approach>

<Approach title="Transitive closure with Floyd–Warshall" time="O(n³ + q)" space="O(n²)">

After round k, `reach[i][j]` says whether j can be reached from i using only stations `0...k` along the way. Skipping rows where `reach[i][k]` is false saves a lot of work on sparse networks.

```swift
public enum TransitReachability {
    public static func canReach(stationCount n: Int, connections: [[Int]], queries: [[Int]]) -> [Bool] {
        var reach = Array(repeating: Array(repeating: false, count: n), count: n)
        for i in 0..<n {
            reach[i][i] = true
        }
        for connection in connections {
            reach[connection[0]][connection[1]] = true
        }
        for k in 0..<n {
            for i in 0..<n where reach[i][k] {
                for j in 0..<n where reach[k][j] {
                    reach[i][j] = true
                }
            }
        }
        return queries.map { reach[$0[0]][$0[1]] }
    }
}
```

</Approach>

<Approach title="A BFS from every station" time="O(n · (n + m) + q)" space="O(n²)">

Run one BFS from each station and record everything it reaches in row `i` of the table. On sparse networks this beats O(n³), and it's the better choice when n grows into the thousands.

</Approach>
