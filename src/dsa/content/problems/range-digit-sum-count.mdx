Count the whole numbers x with `low ≤ x ≤ high` whose decimal digits add up to exactly `digitSum`. The range can be up to 10¹⁸ numbers wide, so you can't look at them one by one.

`RangeDigitSumCount.count(from low: Int, to high: Int, digitSum: Int) -> Int`

## Examples

| `low` | `high` | `digitSum` | Output |
| --- | --- | --- | --- |
| `0` | `253` | `7` | `21` |
| `100` | `200` | `5` | `5` |
| `1` | `1_000_000_000_000_000_000` | `1` | `19` |
| `0` | `0` | `0` | `1` |
| `1` | `9` | `10` | `0` |

The second example counts 104, 113, 122, 131 and 140. The third counts 1, 10, 100, and so on up to 10¹⁸ itself: 19 numbers. In the fourth, 0 is the only number whose digits add up to 0.

## Constraints

- `0 ≤ low ≤ high ≤ 10¹⁸`
- `0 ≤ digitSum ≤ 200` (no number up to 10¹⁸ has a digit sum above 162, so large targets give 0)
- The answer always fits in an `Int`.

<Hints>
<Hint>
Count the numbers from 0 to `high`, and subtract the count from 0 to `low - 1`. Be careful when `low` is 0.
</Hint>
<Hint>
To count from 0 to a limit, choose digits from the left, padding with leading zeros. While every digit so far matches the limit's, the next digit can't exceed the limit's next digit. The moment one digit is smaller, every later digit is free.
</Hint>
<Hint>
A loose state only needs to know how many digits are left and the sum so far, and its count doesn't depend on the limit. Memoise `(position, sum)` for loose states, or precompute `free[r][s]`, the number of ways r free digits can add up to s, and walk the limit's digits once.
</Hint>
</Hints>

## Solutions

<Approach title="Count one by one" time="O((high − low) · D)" space="O(1)">

Loop over the range and add up each number's digits. Fine for small ranges, which is how the tests check ranges below 200,000, and impossible at 10¹⁸.

</Approach>

<Approach title="Digit DP with memoisation" time="O(D · S · 10)" space="O(D · S)">

`count(position, sum, tight)` tries every allowed digit and recurses. Only loose states are memoised: there's one tight state per position, so memoising them saves nothing. The recursion is at most 19 deep.

```swift
public enum RangeDigitSumCount {
    public static func count(from low: Int, to high: Int, digitSum: Int) -> Int {
        let below = low == 0 ? 0 : upTo(low - 1, digitSum)
        return upTo(high, digitSum) - below
    }

    private static func upTo(_ limit: Int, _ target: Int) -> Int {
        let digits = String(limit).compactMap(\.wholeNumberValue)
        var memo = [[Int?]](repeating: [Int?](repeating: nil, count: target + 1), count: digits.count)
        func count(_ position: Int, _ sum: Int, _ tight: Bool) -> Int {
            if sum > target { return 0 }
            if position == digits.count { return sum == target ? 1 : 0 }
            if !tight, let known = memo[position][sum] { return known }
            let highest = tight ? digits[position] : 9
            var total = 0
            for digit in 0...highest {
                total += count(position + 1, sum + digit, tight && digit == highest)
            }
            if !tight { memo[position][sum] = total }
            return total
        }
        return count(0, 0, true)
    }
}
```

</Approach>

<Approach title="A table of free digits, then one walk" time="O(D · S · 10)" space="O(D · S)">

The same DP bottom-up. `free[r][s]` counts the ways to write r digits, each 0 to 9, adding up to s. Walking along the limit's digits, every digit smaller than the limit's leaves the rest free, which is one lookup. Staying tight to the end is the limit itself.

```swift
public enum RangeDigitSumCount {
    public static func count(from low: Int, to high: Int, digitSum: Int) -> Int {
        let below = low == 0 ? 0 : upTo(low - 1, digitSum)
        return upTo(high, digitSum) - below
    }

    /// How many numbers in 0...limit have digit sum `target`
    private static func upTo(_ limit: Int, _ target: Int) -> Int {
        let digits = String(limit).compactMap(\.wholeNumberValue)
        let length = digits.count
        // free[r][s]: ways to choose r digits, each 0–9, adding up to s
        var free = [[Int]](repeating: [Int](repeating: 0, count: target + 1), count: length + 1)
        free[0][0] = 1
        for r in 1...length {
            for s in 0...target {
                for digit in 0...min(9, s) {
                    free[r][s] += free[r - 1][s - digit]
                }
            }
        }

        var total = 0
        var used = 0                                   // digit sum of the tight prefix so far
        for (position, limitDigit) in digits.enumerated() {
            for smaller in 0..<limitDigit where used + smaller <= target {
                total += free[length - position - 1][target - used - smaller]
            }
            used += limitDigit
            if used > target { return total }          // the tight path can't come back down
        }
        return used == target ? total + 1 : total      // limit itself
    }
}
```

Leading zeros need no special care here, because a zero adds nothing to a digit sum: 007 and 7 are the same number with the same sum.

</Approach>
