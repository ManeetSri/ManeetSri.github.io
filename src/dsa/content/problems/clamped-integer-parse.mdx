Read an integer from the start of `text`, the forgiving way a calculator app might, following these rules in order:

1. Skip any space characters (`" "`) at the start. Nothing else counts as space.
2. Read one optional sign, `+` or `-`.
3. Read digits `0` to `9` until the text ends or anything else appears. Ignore the rest.
4. If no digits were read, the answer is `0`.
5. If the number is too big for `Int`, return `Int.max`, or `Int.min` for a negative number, instead of overflowing.

Don't use `Int(_:)`; the point is to handle every case yourself.

`ClampedIntegerParse.parse(_ text: String) -> Int`

## Examples

| `text` | Output |
| --- | --- |
| `"42"` | `42` |
| `"   -0012"` | `-12` |
| `"314 is pi-ish"` | `314` |
| `"+-12"` | `0` |
| `"words 987"` | `0` |
| `"9223372036854775808"` | `9223372036854775807` |
| `"-9223372036854775808"` | `-9223372036854775808` |

`"+-12"` has a sign, then another sign, which isn't a digit, so no digits are read. `"9223372036854775808"` is one more than `Int.max`, so it's clamped. The last example is exactly `Int.min`, which fits.

## Constraints

- `0 ≤ text.count ≤ 200,000`
- `text` can contain any characters. Only the ASCII digits `0` to `9` count as digits.

<Hints>
<Hint>
Convert to bytes with `Array(text.utf8)` and walk them with a single index. Each rule is one small step: a `while` for spaces, an `if` for the sign, a `while` for digits.
</Hint>
<Hint>
Build the value as `value * 10 + digit`. Use `multipliedReportingOverflow(by:)` and `addingReportingOverflow(_:)`, and return the clamped limit as soon as either reports an overflow.
</Hint>
<Hint>
Build the positive magnitude and apply the sign at the end. The magnitude of `Int.min` is one more than `Int.max`, so it overflows, but clamping a negative overflow gives `Int.min`, which is exactly right.
</Hint>
</Hints>

## Solutions

<Approach title="One index, checked arithmetic" time="O(n)" space="O(n)">

Each rule moves the same index forward. The O(n) space is the byte array; you could walk `text.utf8` with its own index instead to avoid it.

```swift
public enum ClampedIntegerParse {
    public static func parse(_ text: String) -> Int {
        let bytes = Array(text.utf8)
        var index = 0
        while index < bytes.count && bytes[index] == UInt8(ascii: " ") {
            index += 1
        }
        var negative = false
        if index < bytes.count && (bytes[index] == UInt8(ascii: "+") || bytes[index] == UInt8(ascii: "-")) {
            negative = bytes[index] == UInt8(ascii: "-")
            index += 1
        }
        var value = 0
        while index < bytes.count && bytes[index] >= UInt8(ascii: "0") && bytes[index] <= UInt8(ascii: "9") {
            let digit = Int(bytes[index] - UInt8(ascii: "0"))
            let shifted = value.multipliedReportingOverflow(by: 10)
            let added = shifted.partialValue.addingReportingOverflow(digit)
            if shifted.overflow || added.overflow {
                return negative ? Int.min : Int.max
            }
            value = added.partialValue
            index += 1
        }
        return negative ? -value : value
    }
}
```

Leading zeros never cause trouble: `value` stays 0 while they're read, however many there are.

</Approach>

<Approach title="Check before multiplying" time="O(n)" space="O(n)">

Without the reporting methods, test whether the next step would overflow before taking it: `value * 10 + digit > Int.max` is the same as `value > (Int.max - digit) / 10`, and the right side can't overflow.

```swift
// The digit loop, with the rest of parse unchanged
while index < bytes.count && bytes[index] >= UInt8(ascii: "0") && bytes[index] <= UInt8(ascii: "9") {
    let digit = Int(bytes[index] - UInt8(ascii: "0"))
    if value > (Int.max - digit) / 10 {
        return negative ? Int.min : Int.max
    }
    value = value * 10 + digit
    index += 1
}
```

</Approach>
