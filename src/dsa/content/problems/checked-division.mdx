Integer division crashes in two situations: dividing by zero, and `Int.min / -1`, whose answer is one more than `Int.max`. Write a division that never crashes and returns a `Result` instead, then use it to divide by a whole list of numbers.

`CheckedDivision.divide(_ dividend: Int, by divisor: Int) -> Result<Int, DivisionError>` and `CheckedDivision.divide(_ start: Int, byEach divisors: [Int]) -> Result<Int, DivisionError>`

- `divide(_:by:)` gives `.failure(.divisionByZero)` when the divisor is 0, `.failure(.overflow)` for `Int.min / -1`, and otherwise `.success` with the same answer as Swift's `/`, which rounds towards zero.
- `divide(_:byEach:)` divides `start` by each divisor in turn, from left to right, and returns the first failure as soon as one happens. With no divisors, the answer is `start`.

## Examples

| Call | Result |
| --- | --- |
| `divide(7, by: 2)` | `.success(3)` |
| `divide(-7, by: 2)` | `.success(-3)` |
| `divide(5, by: 0)` | `.failure(.divisionByZero)` |
| `divide(Int.min, by: -1)` | `.failure(.overflow)` |
| `divide(1000, byEach: [10, 3, 2])` | `.success(16)` |
| `divide(100, byEach: [2, 0, 5])` | `.failure(.divisionByZero)` |
| `divide(42, byEach: [])` | `.success(42)` |

## Constraints

- Any `Int` values.
- `0 ≤ divisors.count ≤ 1,000`

<Hints>
<Hint>
Check for the two dangerous cases *before* dividing. If neither applies, `dividend / divisor` is safe.
</Hint>
<Hint>
Only one pair overflows: `dividend == Int.min && divisor == -1`. Every other quotient is between `Int.min` and `Int.max`.
</Hint>
<Hint>
For the list, keep a running value and `switch` on each `divide(current, by: divisor)`. On `.success(let quotient)`, carry on with the quotient; on `.failure(let error)`, return `.failure(error)` straight away.
</Hint>
</Hints>

## Solutions

<Approach title="Guard the two traps, then switch on each Result" time="O(n)" space="O(1)">

`divide(_:by:)` is O(1). The list version calls it once per divisor and stops at the first failure.

```swift
public enum CheckedDivision {
    public enum DivisionError: Error, Equatable {
        case divisionByZero
        case overflow
    }

    public static func divide(_ dividend: Int, by divisor: Int) -> Result<Int, DivisionError> {
        if divisor == 0 {
            return .failure(.divisionByZero)
        }
        if dividend == Int.min && divisor == -1 {
            return .failure(.overflow)
        }
        return .success(dividend / divisor)
    }

    public static func divide(_ start: Int, byEach divisors: [Int]) -> Result<Int, DivisionError> {
        var current = start
        for divisor in divisors {
            switch divide(current, by: divisor) {
            case .success(let quotient):
                current = quotient
            case .failure(let error):
                return .failure(error)
            }
        }
        return .success(current)
    }
}
```

</Approach>

<Approach title="Chain with get() and try" time="O(n)" space="O(1)">

`get()` turns a `Result` back into a throwing call, so the chain can use `try`, and `Result { … }` turns the throwing code back into a `Result`. Inside the closure, the first failure stops the loop by throwing.

```swift
public static func divide(_ start: Int, byEach divisors: [Int]) -> Result<Int, DivisionError> {
    Result {
        var current = start
        for divisor in divisors {
            current = try divide(current, by: divisor).get()
        }
        return current
    }
    .mapError { $0 as! DivisionError }
}
```

`Result { … }` catches *any* error, so its failure type is the general `any Error`; `mapError` converts it back to `DivisionError`. The cast is safe because the only throwing call is `get()` on a `Result<Int, DivisionError>`. The first approach avoids this wrinkle, which is why it's the reference solution.

</Approach>
