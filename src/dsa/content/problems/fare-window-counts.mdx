`fares[i]` is the cheapest fare for a flight on day i, with days counted from 0. A travel site receives a batch of questions, each `[left, right, low, high]`: on how many days in `left...right` is the fare between `low` and `high`, inclusive? Return the answers in the order the questions are given.

`FareWindowCounts.counts(fares: [Int], queries: [[Int]]) -> [Int]`

## Examples

| `fares` | `queries` | Output |
| --- | --- | --- |
| `[5, 2, 8, 6, 3, 9, 1, 7]` | `[[0, 7, 3, 6], [2, 5, 6, 9], [1, 3, 1, 1], [0, 7, 0, 100]]` | `[3, 3, 0, 8]` |
| `[4, 4, 4]` | `[[0, 2, 4, 4], [1, 1, 5, 9], [0, 1, 0, 3]]` | `[3, 0, 0]` |
| `[10]` | `[[0, 0, 10, 10]]` | `[1]` |
| `[1, 2]` | `[]` | `[]` |

In the first example, the first question asks about the whole week with fares from 3 to 6: days 0, 3 and 4 (fares 5, 6 and 3). The second asks about days 2 to 5 with fares from 6 to 9: fares 8, 6 and 9.

## Constraints

- `1 ≤ fares.count ≤ 100,000` and `0 ≤ queries.count ≤ 100,000`
- `0 ≤ fares[i] ≤ 1,000,000,000`
- Every query has `0 ≤ left ≤ right < fares.count` and `0 ≤ low ≤ high ≤ 1,000,000,000`.
- The tests ask 50,000 questions about 50,000 days, most of them covering more than half the days. Scanning each range is well over a billion steps: too slow.

<Hints>
<Hint>
Split each question in two: (days in the range with fare ≤ `high`) minus (days in the range with fare ≤ `low - 1`). Now every part has a single threshold.
</Hint>
<Hint>
All the questions are known up front. Sort the parts by threshold and sweep the thresholds upwards. Each day becomes "affordable" once, and stays that way.
</Hint>
<Hint>
Sort the days by fare. Before answering a part with threshold t, add 1 at every day with fare ≤ t in a Fenwick tree over days. The part's count is `prefix(right + 1) - prefix(left)`. Add it to, or subtract it from, its question's answer.
</Hint>
</Hints>

## Solutions

<Approach title="Scan each question" time="O(n · q)" space="O(1) extra">

Loop over `left...right` and count the fares inside the window. It's what the tests use to check a sample of your answers, and it's far too slow for all of them.

</Approach>

<Approach title="Offline sweep with a Fenwick tree" time="O((n + q) log n)" space="O(n + q)">

Each question becomes two parts, `(threshold, query number, sign)`: `(high, q, +1)` and `(low - 1, q, -1)`. Sort the parts by threshold, sort the days by fare, and sweep both together.

```swift
public enum FareWindowCounts {
    public static func counts(fares: [Int], queries: [[Int]]) -> [Int] {
        let n = fares.count
        var tree = [Int](repeating: 0, count: n + 1)
        func add(_ index: Int) {
            var i = index + 1
            while i <= n { tree[i] += 1; i += i & -i }
        }
        func prefix(_ count: Int) -> Int {
            var i = count, total = 0
            while i > 0 { total += tree[i]; i -= i & -i }
            return total
        }

        var parts: [(threshold: Int, query: Int, sign: Int)] = []
        for (q, query) in queries.enumerated() {
            parts.append((query[3], q, 1))            // fares ≤ high count...
            parts.append((query[2] - 1, q, -1))       // ...minus fares ≤ low - 1
        }
        parts.sort { $0.threshold < $1.threshold }
        let days = fares.indices.sorted { fares[$0] < fares[$1] }

        var answers = [Int](repeating: 0, count: queries.count)
        var next = 0
        for part in parts {
            while next < n && fares[days[next]] <= part.threshold {
                add(days[next])
                next += 1
            }
            let left = queries[part.query][0], right = queries[part.query][1]
            answers[part.query] += part.sign * (prefix(right + 1) - prefix(left))
        }
        return answers
    }
}
```

A part with threshold `low - 1 = -1` simply finds nothing marked. Ties need care: a fare exactly equal to `high` must count and one equal to `low` must count too, which the `<=` and the `low - 1` together guarantee.

</Approach>

<Approach title="Online alternatives" time="O(log² n) or O(log n) per query" space="O(n log n)">

If the questions had to be answered one at a time, as they arrive, a merge-sort tree (a segment tree whose nodes hold sorted fares) answers each in O(log² n), and a persistent segment tree in O(log n). Both are covered in M60. The offline sweep gets the same speed with a few lines and a Fenwick tree.

</Approach>
