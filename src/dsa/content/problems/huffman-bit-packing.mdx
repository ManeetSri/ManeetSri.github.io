A Huffman code gives each character a string of bits, and the compressor writes those bits back to back. Computers store whole bytes, though, so the bits must be packed eight to a byte, and the decompressor must unpack them and turn them back into characters. Write both directions.

`HuffmanBitPacking.pack(_ text: String, codes: [Character: String]) -> [UInt8]` and `HuffmanBitPacking.unpack(_ bytes: [UInt8], count: Int, codes: [Character: String]) -> String?`

Each code is a string of `"0"`s and `"1"`s, and no code is the start of another (the code is **prefix-free**).

- `pack` writes the codes of `text`'s characters in order, filling each byte from its most significant bit, and pads the last byte with zeros.
- `unpack` decodes exactly `count` characters from the start of `bytes`. It returns `nil` if the bits run out first, or if the bits read so far aren't the start of any code. Bits after the last character, such as padding, are ignored.
- A table with a single character may give it the empty code `""`. Then `pack` writes no bits at all, and `unpack` returns that character `count` times without reading anything: the count says everything.

## Examples

With the lesson's code for "abracadabra", `["a": "0", "b": "110", "c": "100", "d": "101", "r": "111"]`:

| Call | Output | Why |
| --- | --- | --- |
| `pack("abracadabra", codes:)` | `[0b0110_1110, 0b1000_1010, 0b1101_1100]` | 23 bits, then one padding 0 |
| `unpack(those 3 bytes, count: 11, codes:)` | `"abracadabra"` | |
| `unpack(those 3 bytes, count: 4, codes:)` | `"abra"` | only the first 4 characters |
| `unpack(the first 2 bytes, count: 11, codes:)` | `nil` | the bits run out |
| `pack("rrbad", codes:)` | `[0b1111_1111, 0b0010_1000]` | 13 bits |
| `pack("", codes:)` | `[]` | |

| Call | Output |
| --- | --- |
| `pack("zzzz", codes: ["z": ""])` | `[]` |
| `unpack([], count: 4, codes: ["z": ""])` | `"zzzz"` |
| `unpack([0b1100_0000], count: 1, codes: ["x": "0", "y": "10"])` | `nil`: no code starts with `11` |

## Constraints

- Up to 200,000 characters of text, each a key of `codes`. Characters can be any Unicode: `"é"` and `"🙂"` are single characters.
- Up to 300 codes, each at most 30 bits long.
- `0 ≤ count ≤ 200,000`.

<Hint>
Packing: keep a byte under construction and a count of the bits in it. For each bit, shift the byte left by one and OR the bit in; when 8 bits have arrived, append the byte and start again. At the end, shift the unfinished byte left so its bits sit at the top.
</Hint>
<Hint>
Reading bit `i` of the packed data is `bytes[i / 8] >> (7 - i % 8) & 1`. Matching bits against a dictionary of code strings is slow and fiddly; there's a better structure.
</Hint>
<Hint>
Build the code tree: a binary trie where a 0 goes left and a 1 goes right, and each code ends at a leaf holding its character. Walk it one bit at a time from the root. At a leaf, output its character and go back to the root. A missing child means the data is damaged.
</Hint>
</Hints>

## Solutions

<Approach title="A bit writer, and a walk down the code tree" time="O(total bits + total code length)" space="O(total code length)">

The tree lives in arrays: `child[node][bit]` is the next node or `-1`, and `symbol[node]` is the character at a leaf. Each bit read is one step down it.

```swift
public enum HuffmanBitPacking {
    public static func pack(_ text: String, codes: [Character: String]) -> [UInt8] {
        let table = codes.mapValues { code in code.map { $0 == "1" ? UInt8(1) : 0 } }
        var bytes: [UInt8] = []
        var current: UInt8 = 0
        var used = 0
        for character in text {
            for bit in table[character] ?? [] {
                current = current << 1 | bit
                used += 1
                if used == 8 {
                    bytes.append(current)
                    (current, used) = (0, 0)
                }
            }
        }
        if used > 0 {
            bytes.append(current << (8 - used))                 // pad the last byte with zeros
        }
        return bytes
    }

    public static func unpack(_ bytes: [UInt8], count: Int, codes: [Character: String]) -> String? {
        guard count > 0 else { return "" }
        // A lone symbol with the empty code: the count says everything, and there are no bits to read
        if codes.count == 1, let only = codes.first, only.value.isEmpty {
            return String(repeating: String(only.key), count: count)
        }

        // The code tree: node 0 is the root; child[node][bit] is -1 when there's no such branch
        var child: [[Int]] = [[-1, -1]]
        var symbol: [Character?] = [nil]
        for (character, code) in codes {
            var node = 0
            for bit in code {
                let side = bit == "1" ? 1 : 0
                if child[node][side] == -1 {
                    child[node][side] = child.count
                    child.append([-1, -1])
                    symbol.append(nil)
                }
                node = child[node][side]
            }
            symbol[node] = character
        }

        var output = ""
        var produced = 0
        var node = 0
        var bitIndex = 0
        let totalBits = bytes.count * 8
        while produced < count {
            guard bitIndex < totalBits else { return nil }       // the bits ran out
            let bit = Int(bytes[bitIndex / 8] >> (7 - bitIndex % 8) & 1)
            bitIndex += 1
            node = child[node][bit]
            guard node != -1 else { return nil }                 // no code starts like this
            if let character = symbol[node] {
                output.append(character)
                produced += 1
                node = 0
            }
        }
        return output
    }
}
```

The count is what makes padding harmless: with the abracadabra code, the padding bit 0 is itself the code for `a`, so a decoder that read until the bytes ran out would add a stray `a`. That's why the lesson's file format stores the original length in its header. `Character` keys also handle Unicode for free: `"e\u{301}"` (an e followed by a combining accent) and `"é"` are the same `Character`, so they share a code.

</Approach>
