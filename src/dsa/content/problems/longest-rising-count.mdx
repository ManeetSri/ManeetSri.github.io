Given a list of values, find how many strictly increasing subsequences have the **greatest possible length**. Two subsequences count as different if they use different positions, even when their values read the same. Return 0 for an empty list.

`LongestRisingCount.count(_ values: [Int]) -> Int`

## Examples

| `values` | Output | Why |
| --- | --- | --- |
| `[3, 1, 4, 2, 5]` | `3` | length 3: `[3, 4, 5]`, `[1, 4, 5]`, `[1, 2, 5]` |
| `[1, 3, 5, 4, 7]` | `2` | length 4: `[1, 3, 5, 7]`, `[1, 3, 4, 7]` |
| `[2, 2, 2, 2, 2]` | `5` | length 1: each 2 on its own |
| `[1, 2, 2]` | `2` | length 2: the 1 with either 2 |
| `[]` | `0` | |

## Constraints

- `0 ≤ values.count ≤ 1,000`
- `-1,000,000 ≤ values[i] ≤ 1,000,000`
- The answer is less than 2⁶², so it fits in an `Int`. The tests include 1,000 values, which O(n²) handles comfortably.

<Hints>
<Hint>
Start from the O(n²) LIS, where `length[i]` is the longest rising run ending at index i. Add a second array: `count[i]`, how many runs of that best length end at i.
</Hint>
<Hint>
For each earlier, smaller value at j, the runs ending at j extend to length `length[j] + 1`. If that beats `length[i]`, the old count is for shorter runs and gets replaced by `count[j]`. If it ties, add `count[j]`.
</Hint>
<Hint>
Several indexes can end a longest run. Add up `count[i]` over every i whose `length[i]` equals the overall maximum. Equal values never extend each other, so `values[j] < values[i]` is the right test.
</Hint>
</Hints>

## Solutions

<Approach title="Length and count per index" time="O(n²)" space="O(n)">

Each index carries a pair: the best length ending there, and how many runs reach it. A longer extension takes over the pair; an equal one adds to the count.

```swift
public enum LongestRisingCount {
    public static func count(_ values: [Int]) -> Int {
        var length = Array(repeating: 1, count: values.count)
        var ways = Array(repeating: 1, count: values.count)
        for i in values.indices {
            for j in 0..<i where values[j] < values[i] {
                if length[j] + 1 > length[i] {
                    length[i] = length[j] + 1
                    ways[i] = ways[j]
                } else if length[j] + 1 == length[i] {
                    ways[i] += ways[j]
                }
            }
        }
        let best = length.max() ?? 0
        var total = 0
        for i in values.indices where length[i] == best {
            total += ways[i]
        }
        return total
    }
}
```

With values that come in swapped pairs, like `[1, 0, 3, 2, 5, 4, …]`, every pair doubles the count, so counts can grow exponentially. That's why the constraints promise the answer fits. An O(n log n) version exists, using a Fenwick tree that stores the best (length, count) pair for each value; it's a good exercise after M61.

</Approach>
