A server streams its log lines to a debugging tool, one at a time, and nobody knows how many will come. The tool keeps a fair random **sample** of at most `capacity` lines to show an engineer, using memory for those lines only. Build the sampler: at every moment, every line offered so far must be equally likely to be in the sample, and every set of `capacity` lines must be equally likely to be the sample.

`LogStreamSampler.Sampler<Element>`, a class with `init(capacity: Int)`, `offer(_ item: Element, using generator: inout some RandomNumberGenerator)`, `seen: Int` (how many items have been offered) and `sample: [Element]`

Draw every random number from the generator passed to `offer`, so the tests can use a seeded one.

## Examples

Until `capacity` items have been offered, the sample holds every item, in the order offered. After that, its order doesn't matter, and its contents depend on the random numbers.

| `capacity` | Items offered, in order | `seen` | `sample` |
| --- | --- | --- | --- |
| `3` | `"a"`, `"b"` | `2` | `["a", "b"]` |
| `3` | `"a"`, `"b"`, `"c"` | `3` | `["a", "b", "c"]` |
| `3` | `1` to `10` | `10` | three of them, for example `[1, 9, 3]`; each number is included with probability 3/10 |
| `1` | `"x"`, `"y"` | `2` | `["x"]` or `["y"]`, each with probability 1/2 |

## Constraints

- `1 ≤ capacity ≤ 10,000`
- Up to 1,000,000 calls to `offer`. Each should be O(1), and the sampler must store at most `capacity` items, whatever the length of the stream.
- The tests offer short streams tens of thousands of times with seeded generators and count how often each item, and some pairs of items, end up in the sample. A sampler that favours early or late items fails those counts.

<Hints>
<Hint>
For one item (capacity 1): keep the ith item offered with probability 1/i, counting from 1. Multiply out the chance that item i is kept and then never replaced: it telescopes to 1/n.
</Hint>
<Hint>
For k items: the first k go straight in. When the ith item arrives (i > k), it should get into the sample with probability k/i, and if it does, it replaces a **uniformly random** current member.
</Hint>
<Hint>
Both at once: draw j uniformly from `0..<i` (with i counting from 1). If j < k, replace `sample[j]`; otherwise discard the item.
</Hint>
</Hints>

## Solutions

<Approach title="Keep everything, sample at the end" time="O(1) per offer" space="O(n)">

Store every item and pick k at random when asked. It's fair, but it stores the whole stream, which is exactly what the tool can't do.

</Approach>

<Approach title="Reservoir sampling" time="O(1) per offer" space="O(k)">

```swift
public enum LogStreamSampler {
    public final class Sampler<Element> {
        public let capacity: Int
        public private(set) var seen = 0
        public private(set) var sample: [Element] = []

        public init(capacity: Int) {
            self.capacity = capacity
            sample.reserveCapacity(capacity)
        }

        public func offer(_ item: Element, using generator: inout some RandomNumberGenerator) {
            seen += 1
            if sample.count < capacity {
                sample.append(item)
            } else {
                let j = Int.random(in: 0..<seen, using: &generator)
                if j < capacity {
                    sample[j] = item
                }
            }
        }
    }
}
```

When the tth item arrives, it evicts any particular member with probability k/t × 1/k = 1/t. So an item that entered at step i survives steps i + 1 to n with probability i/(i + 1) × (i + 1)/(i + 2) × … × (n − 1)/n = i/n. It got in with probability k/i, so it's in the final sample with probability k/i × i/n = k/n. The first k items get in for sure and survive steps k + 1 to n with probability k/n: the same.

</Approach>
