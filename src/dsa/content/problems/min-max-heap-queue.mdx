An auction house serves its best bid while evicting its worst once the book is full, so it needs a priority queue that's fast at **both** ends. swift-collections' `Heap` gives exactly that, as a **min-max heap**. Build your own version, without packages.

`MinMaxHeapQueue.BothEndsQueue`, a struct with `init()`, `count`, `isEmpty`, `min`, `max`, `insert(_:)`, `popMin()` and `popMax()`. The names follow swift-collections: `min` and `max` are properties returning `Int?`, and the pops return `nil` when the queue is empty.

`min` and `max` must be O(1), and `insert`, `popMin` and `popMax` O(log n). The recommended design is the min-max heap from the lesson, a complete tree in an array whose levels alternate:

- On **min levels** (the root's level, then every second level), each node is ≤ everything below it.
- On **max levels** (the root's children's level, and every second level after that), each node is ≥ everything below it.

So the smallest value is at index 0, and the largest is at index 1 or 2 (or 0, if there's only one value).

## Examples

| Code | Result |
| --- | --- |
| insert 5, 3, 8, 1, 9, 4 | `min` is `1`, `max` is `9`, `count` is `6` |
| then `popMin()`, then `popMax()` | `1`, then `9`; now `min` is `3` and `max` is `8` |
| insert 7 twice, then `popMax()` twice | `8`, then `7`; one 7 is still queued |
| an empty queue's `popMin()`, `popMax()`, `min` and `max` | all `nil` |
| a queue holding only 42 | `min` and `max` are both `42` |

## Constraints

- Up to 200,000 operations, with values of any `Int`, duplicates allowed.
- It's a struct, so a copy is an independent queue (an array inside gives you that for free).
- The tests insert 100,000 values in increasing and decreasing order and pop from both ends, and make 200,000 random operations, so keeping a sorted array, with O(n) inserts, is too slow.

<Hints>
<Hint>
The level of index i is ⌊log₂(i + 1)⌋, and it's a min level when that's even. In Swift, `(Int.bitWidth - (i + 1).leadingZeroBitCount - 1)` computes the level without floating point. Grandparents and grandchildren matter as much as parents: the grandparent of i is the parent of its parent, and its grandchildren are the children of its children, 4i + 3 to 4i + 6.
</Hint>
<Hint>
**Insert:** append the value at index i, then compare it with its parent. On a min level, if it's bigger than its parent (which is on a max level), swap them and keep bubbling up **max** levels, comparing with grandparents. Otherwise bubble up **min** levels, swapping with the grandparent while smaller. A new value on a max level is the mirror image.
</Hint>
<Hint>
**Pop:** move the last element into the hole and **trickle down**. From a min-level index, find the smallest among its children and grandchildren. If it's a grandchild and smaller than the element, swap them; then, if the element now sits below a parent (on a max level) that is smaller than it, swap those too, and continue from the grandchild's position. If it's a child, swap if smaller and stop. `popMax` removes from index 1 or 2 and trickles down with the comparisons reversed.
</Hint>
</Hints>

## Solutions

<Approach title="A sorted array" time="O(n) insert and popMin, O(1) the rest" space="O(n)">

Keep every value in increasing order. Both ends are then right there, but each insert shifts up to n values, and so does removing from the front.

```swift
public enum MinMaxHeapQueue {
    public struct BothEndsQueue {
        private var sorted: [Int] = []
        public init() {}
        public var count: Int { sorted.count }
        public var isEmpty: Bool { sorted.isEmpty }
        public var min: Int? { sorted.first }
        public var max: Int? { sorted.last }

        public mutating func insert(_ value: Int) {
            var low = 0
            var high = sorted.count
            while low < high {
                let mid = (low + high) / 2
                if sorted[mid] < value { low = mid + 1 } else { high = mid }
            }
            sorted.insert(value, at: low)                    // O(n): shifts everything after it
        }

        public mutating func popMin() -> Int? { sorted.isEmpty ? nil : sorted.removeFirst() }
        public mutating func popMax() -> Int? { sorted.popLast() }
    }
}
```

Fine for a few hundred values, far too slow for 100,000. Another option is a min-heap and a max-heap holding every value, with lazy deletion of the copy left behind by each pop, but that stores everything twice and makes peeking at the top messy.

</Approach>

<Approach title="Min-max heap" time="O(1) min and max, O(log n) insert and pops" space="O(n)">

All the work is in two pairs of helpers. Bubbling up compares with grandparents, because those are on the same kind of level. Trickling down looks at up to six descendants, two children and four grandchildren, and after swapping with a grandchild it fixes the one parent in between, which is on the opposite kind of level.

```swift
public enum MinMaxHeapQueue {
    public struct BothEndsQueue {
        private var items: [Int] = []

        public init() {}

        public var count: Int { items.count }
        public var isEmpty: Bool { items.isEmpty }
        public var min: Int? { items.first }
        public var max: Int? {
            switch items.count {
            case 0: return nil
            case 1: return items[0]
            case 2: return items[1]
            default: return Swift.max(items[1], items[2])
            }
        }

        public mutating func insert(_ value: Int) {
            items.append(value)
            let i = items.count - 1
            guard i > 0 else { return }
            let parent = (i - 1) / 2
            if Self.isMinLevel(i) {
                if items[i] > items[parent] {
                    items.swapAt(i, parent)
                    bubbleUp(from: parent, isMax: true)
                } else {
                    bubbleUp(from: i, isMax: false)
                }
            } else {
                if items[i] < items[parent] {
                    items.swapAt(i, parent)
                    bubbleUp(from: parent, isMax: false)
                } else {
                    bubbleUp(from: i, isMax: true)
                }
            }
        }

        public mutating func popMin() -> Int? {
            remove(at: 0)
        }

        public mutating func popMax() -> Int? {
            guard items.count > 1 else { return remove(at: 0) }
            return remove(at: items.count == 2 || items[1] >= items[2] ? 1 : 2)
        }

        private mutating func remove(at index: Int) -> Int? {
            guard index < items.count else { return nil }
            let removed = items[index]
            let last = items.removeLast()
            if index < items.count {
                items[index] = last
                trickleDown(from: index, isMax: !Self.isMinLevel(index))
            }
            return removed
        }

        /// True when `a` should be nearer the top than `b` on this kind of level.
        private static func beats(_ a: Int, _ b: Int, isMax: Bool) -> Bool {
            isMax ? a > b : a < b
        }

        private static func isMinLevel(_ i: Int) -> Bool {
            (Int.bitWidth - (i + 1).leadingZeroBitCount - 1) % 2 == 0
        }

        /// Moves items[i] up through the levels of its own kind, comparing with grandparents.
        private mutating func bubbleUp(from start: Int, isMax: Bool) {
            var i = start
            while i > 2 {
                let grandparent = ((i - 1) / 2 - 1) / 2
                guard Self.beats(items[i], items[grandparent], isMax: isMax) else { return }
                items.swapAt(i, grandparent)
                i = grandparent
            }
        }

        /// Moves items[i] down, looking at its children and grandchildren for the most extreme value.
        private mutating func trickleDown(from start: Int, isMax: Bool) {
            var i = start
            while 2 * i + 1 < items.count {
                var best = 2 * i + 1                             // among children and grandchildren
                if best + 1 < items.count && Self.beats(items[best + 1], items[best], isMax: isMax) {
                    best += 1
                }
                let firstGrandchild = 4 * i + 3
                if firstGrandchild < items.count {
                    for candidate in firstGrandchild...Swift.min(firstGrandchild + 3, items.count - 1)
                    where Self.beats(items[candidate], items[best], isMax: isMax) {
                        best = candidate
                    }
                }
                guard Self.beats(items[best], items[i], isMax: isMax) else { return }
                items.swapAt(best, i)
                if best <= 2 * i + 2 { return }                  // a child: nothing below it to fix
                let parent = (best - 1) / 2                      // a grandchild: fix the level between
                if Self.beats(items[parent], items[best], isMax: isMax) {
                    items.swapAt(parent, best)
                }
                i = best
            }
        }
    }
}
```

Every operation walks one root-to-leaf path, touching a constant number of nodes per level, so it's O(log n). Min-max heaps are a little slower per operation than a plain binary heap, but one structure answers "smallest?" and "largest?" equally fast, which is exactly what a bounded queue that serves its best and evicts its worst needs.

</Approach>
