A hiking app has the heights along a trail, in order. Return the index of any **peak**: a point higher than each neighbour it has. The first and last points have only one neighbour each, so count the ground beyond both ends as lower than anything.

`PeakFinder.peakIndex(in heights: [Int]) -> Int`

Neighbouring heights are never equal. If there are several peaks, any one is a correct answer. Aim for O(log n).

## Examples

| `heights` | A correct output | Why |
| --- | --- | --- |
| `[1, 3, 2]` | `1` | 3 beats 1 and 2 |
| `[2, 9, 4, 6, 1]` | `1` or `3` | both 9 and 6 beat their neighbours |
| `[1, 2, 3, 4, 5]` | `4` | the last point beats 4 and the edge |
| `[5, 4, 3, 2, 1]` | `0` | the first point beats the edge and 4 |
| `[42]` | `0` | a single point is a peak |
| `[0, 2, 5, 9, 7, 3]` | `3` | a mountain has exactly one peak |

## Constraints

- `1 ≤ heights.count ≤ 1,000,000`
- `heights[i] != heights[i + 1]` for every i.
- Heights can be any `Int`, including negatives.

<Hints>
<Hint>
The largest height is always a peak, but finding it takes O(n). You only need *a* peak, so look for a question about the middle that tells you which half is sure to contain one.
</Hint>
<Hint>
Compare `heights[mid]` with `heights[mid + 1]`. If the ground rises to the right, walk right: the heights either rise all the way to the end, where the last point is a peak, or turn down somewhere, which is a peak. So there's a peak to the right of mid.
</Hint>
<Hint>
Loop `while low < high` with `high = heights.count - 1`. Uphill: `low = mid + 1`. Downhill: `high = mid`, since mid itself could be the peak. Because `mid < high` inside the loop, `mid + 1` is always a valid index.
</Hint>
</Hints>

## Solutions

<Approach title="Scan for the first downturn" time="O(n)" space="O(1)">

Walk from the start until the next height is lower. That point beats its left neighbour (or is the first point) and its right neighbour, so it's a peak. If the heights never turn down, the last point is the peak.

```swift
public static func peakIndex(in heights: [Int]) -> Int {
    for i in 0..<(heights.count - 1) where heights[i] > heights[i + 1] {
        return i
    }
    return heights.count - 1
}
```

</Approach>

<Approach title="Binary search uphill" time="O(log n)" space="O(1)">

Keep this invariant: the height at `low` beats its left neighbour, and the height at `high` beats its right neighbour (with the edges counted as lower). Moving `low` to `mid + 1` when the ground rises keeps the first half true, and moving `high` to `mid` when it falls keeps the second. When `low == high`, that point beats both neighbours.

```swift
public enum PeakFinder {
    public static func peakIndex(in heights: [Int]) -> Int {
        var low = 0
        var high = heights.count - 1
        while low < high {
            let mid = low + (high - low) / 2     // mid < high, so mid + 1 is a valid index
            if heights[mid] < heights[mid + 1] {
                low = mid + 1                    // uphill to the right
            } else {
                high = mid                       // downhill: mid could be the peak
            }
        }
        return low
    }
}
```

The array isn't sorted, and doesn't need to be: binary search only needs each comparison to rule out a half that can't be the only place an answer lives.

</Approach>
