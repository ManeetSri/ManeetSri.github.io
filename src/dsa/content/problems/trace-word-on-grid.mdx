A puzzle grid holds one letter per cell, given as `grid`, where each string is one row and all rows have the same length. A word can be **traced** by starting on any cell with its first letter and stepping up, down, left or right to a cell with the next letter, and so on, never using the same cell twice in one word. Return whether `word` can be traced.

`GridWordTracer.contains(_ grid: [String], word: String) -> Bool`

## Examples

With this grid:

```text
C A T S
R O P E
D U S K
```

| `word` | Output | Why |
| --- | --- | --- |
| `"CROP"` | `true` | down from C to R, then right along the middle row |
| `"DROPS"` | `true` | up from D to R, right along the middle row to P, then down to the S below it |
| `"CAPE"` | `false` | the A and the P aren't neighbours (diagonals don't count) |
| `"POP"` | `false` | there's only one P, and a cell can't be used twice |
| `"KSUD"` | `true` | a word can run right to left |

## Constraints

- `1 ≤ grid.count ≤ 6` rows and `1 ≤ grid[i].count ≤ 6` columns, uppercase letters.
- `1 ≤ word.count ≤ 40`, uppercase letters.
- The tests include grids built to make a plain search explore tens of millions of paths, such as a 6 × 6 grid of A's and a 24-letter word of A's ending in a B. Compare letter counts before searching, and start from whichever end of the word is rarer in the grid.

<Hints>
<Hint>
Try every cell as a start. From a cell, a depth-first search matches the current letter, then tries the four neighbours for the next one.
</Hint>
<Hint>
Mark a cell as used before searching onwards from it (for example, change it to `"#"` in a mutable copy of the grid), and restore it afterwards. Unlike a flood fill, the restore is essential: other paths may need the cell.
</Hint>
<Hint>
Two checks before any searching: if the word needs more of some letter than the grid has, return `false`. And a path traced backwards spells the reversed word, so if the word's first letter is more common in the grid than its last, search for the reversed word instead.
</Hint>
</Hints>

## Solutions

<Approach title="Depth-first search from every cell" time="O(cells · 3^L)" space="O(L)">

Correct, and fast on most grids, because mismatched letters end paths quickly. But on a grid of A's, a word of A's ending in a B fails only at its last letter, after every path of A's has been tried. The tests include such grids.

</Approach>

<Approach title="Letter counts, the rarer end, then backtracking" time="O(cells · 3^L) worst case" space="O(L + alphabet)">

Counting letters costs O(cells + L) and answers the missing-letter cases with no search at all. Starting from the rarer end means fewer starting cells and earlier failures. The search itself marks cells in place and restores them with `defer`.

```swift
public enum GridWordTracer {
    public static func contains(_ grid: [String], word: String) -> Bool {
        var board = grid.map { Array($0) }
        var letters = Array(word)
        guard let columns = board.first?.count, !letters.isEmpty else { return letters.isEmpty }
        let rows = board.count

        var available: [Character: Int] = [:]
        for row in board {
            for letter in row {
                available[letter, default: 0] += 1
            }
        }
        var needed: [Character: Int] = [:]
        for letter in letters {
            needed[letter, default: 0] += 1
        }
        for (letter, count) in needed where available[letter, default: 0] < count {
            return false
        }
        if available[letters[0], default: 0] > available[letters[letters.count - 1], default: 0] {
            letters.reverse()
        }

        func trace(_ row: Int, _ column: Int, _ index: Int) -> Bool {
            guard row >= 0, row < rows, column >= 0, column < columns,
                  board[row][column] == letters[index] else { return false }
            if index == letters.count - 1 { return true }
            let saved = board[row][column]
            board[row][column] = "#"                                // mark: used in this trace
            defer { board[row][column] = saved }                    // unmark on the way back
            return trace(row - 1, column, index + 1) || trace(row + 1, column, index + 1)
                || trace(row, column - 1, index + 1) || trace(row, column + 1, index + 1)
        }

        for row in 0..<rows {
            for column in 0..<columns where trace(row, column, 0) {
                return true
            }
        }
        return false
    }
}
```

A word longer than the number of cells fails the count check too, since some letter would be needed more often than it appears.

</Approach>
