A sensor hub keeps its readings in a binary search tree, and has almost no spare memory. Return the **median** of the values in the tree using O(1) extra space: no recursion, no stack, no arrays. With an odd number of values it's the middle one; with an even number, the average of the two middle ones. Return `nil` for an empty tree.

`MorrisMedian.median(of root: TreeNode?) -> Double?`

You may change the tree's links while you work, as Morris traversal does, but when the function returns, every node must have exactly the children it started with.

## Examples

| Tree (level order) | Sorted values | Output |
| --- | --- | --- |
| `[4, 2, 6, 1, 3, 5, 7]` | 1 2 3 4 5 6 7 | `4.0` |
| `[4, 2, 6, 1, 3, 5]` | 1 2 3 4 5 6 | `3.5` |
| `[10, 5, nil, 1]` | 1 5 10 | `5.0` |
| `[8]` | 8 | `8.0` |
| `[-3, -7]` | −7 −3 | `-5.0` |
| `[]` | | `nil` |

## Constraints

- `0 ≤` number of nodes `≤ 100,000`, and `-1,000,000,000 ≤ value ≤ 1,000,000,000`.
- The tree is a binary search tree: its inorder sequence is sorted (values may repeat).
- It can be a chain 100,000 levels deep, so recursion would crash. An explicit stack would work, but costs O(h) memory: the point here is O(1).
- The tests check that every node's `left` and `right` are the same objects afterwards.

<Hints>
<Hint>
The values in sorted order are the inorder sequence, and Morris traversal visits it in O(1) space. But you need to know where the middle is before you can stop there.
</Hint>
<Hint>
Walk twice. The first Morris walk only counts the nodes, n. The second walk counts visits again and records the values at positions `(n - 1) / 2` and `n / 2` (0-based). They're the same position when n is odd.
</Hint>
<Hint>
Don't `return` from the middle of the second walk. Every thread made so far must be removed, and the only way to remove them is to keep walking until `current` is `nil`. Keep counting, but stop recording.
</Hint>
</Hints>

## Solutions

<Approach title="Inorder into an array" time="O(n)" space="O(n)">

Collect the inorder values with an explicit stack, then pick the middle. It's simple and leaves the tree untouched, but it stores every value, and its stack grows with the height.

```swift
public static func median(of root: TreeNode?) -> Double? {
    var values: [Int] = []
    var stack: [TreeNode] = []
    var current = root
    while current != nil || !stack.isEmpty {
        while let node = current { stack.append(node); current = node.left }
        let node = stack.removeLast()
        values.append(node.value)
        current = node.right
    }
    guard !values.isEmpty else { return nil }
    return (Double(values[(values.count - 1) / 2]) + Double(values[values.count / 2])) / 2
}
```

</Approach>

<Approach title="Two Morris walks" time="O(n)" space="O(1)">

One helper performs a complete Morris inorder walk and calls `visit` for each value. Because it always finishes, every thread it makes is also removed, so the tree comes back unchanged however the caller uses the values. The first walk counts; the second picks out the one or two middle values and lets the walk run to the end.

```swift
import DSAKit

public enum MorrisMedian {
    public static func median(of root: TreeNode?) -> Double? {
        var count = 0
        walkInorder(root) { _ in count += 1 }
        guard count > 0 else { return nil }
        var position = 0
        var lower = 0
        var upper = 0
        walkInorder(root) { value in
            if position == (count - 1) / 2 { lower = value }
            if position == count / 2 { upper = value }
            position += 1                                    // keep walking: the threads must go
        }
        return (Double(lower) + Double(upper)) / 2
    }

    /// A complete Morris inorder walk: O(n) time, O(1) extra space, and the tree is restored.
    private static func walkInorder(_ root: TreeNode?, _ visit: (Int) -> Void) {
        var current = root
        while let node = current {
            guard let left = node.left else {
                visit(node.value)                            // nothing on the left: visit, go right
                current = node.right
                continue
            }
            var predecessor = left                           // rightmost node of the left subtree
            while let next = predecessor.right, next !== node {
                predecessor = next
            }
            if predecessor.right == nil {
                predecessor.right = node                     // first arrival: leave a thread back
                current = left
            } else {
                predecessor.right = nil                      // back via the thread: remove it, visit
                visit(node.value)
                current = node.right
            }
        }
    }
}
```

Converting to `Double` before adding keeps the sum exact and avoids overflow. Two O(n) walks are still O(n), and the only memory used is a handful of variables.

</Approach>
