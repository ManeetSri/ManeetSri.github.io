A maze generator should produce **perfect** mazes: every cell reachable from every other by exactly one route, with no loops and no sealed-off cells. Write the audit that checks a maze is perfect, and the statistic players care about: the length of the longest route between any two cells, the best place for the start and the finish.

`PerfectMazeAudit.isPerfect(openRight: [[Bool]], openDown: [[Bool]]) -> Bool` and `PerfectMazeAudit.longestRoute(openRight: [[Bool]], openDown: [[Bool]]) -> Int?`

The maze is stored as passages, as in the lesson: a grid of `rows × columns` cells, where `openRight[r][c]` says you can walk between cell `(r, c)` and the cell to its right, and `openDown[r][c]` between `(r, c)` and the cell below. Every other wall is up. `longestRoute` returns the most steps between any two cells of a perfect maze, or `nil` if the maze isn't perfect.

## Examples

Mazes drawn with `+---+` walls, and the passages that make them:

```text
+---+---+        +---+---+        +---+---+        +---+---+---+
|       |        |       |        |   |   |        |           |
+---+   +        +   +   +        +   +   +        +---+---+---+
|       |        |       |        |       |
+---+---+        +---+---+        +---+---+
```

| Maze | `isPerfect` | `longestRoute` | Why |
| --- | --- | --- | --- |
| first: passages 0–1, 1–3 and 3–2 | `true` | `3` | one route snakes through all four cells |
| second: all four passages of the 2 × 2 grid | `false` | `nil` | a loop: two routes between any two cells |
| third: passages 0–2, 2–3 and 1–3 | `true` | `3` | |
| fourth: a 1 × 3 corridor | `true` | `2` | |
| a 1 × 1 maze | `true` | `0` | one cell, no steps |
| a 3 × 3 grid with no passages | `false` | `nil` | nothing is connected |

Cells are numbered row by row, so in a 2 × 2 maze cell 1 is top right and cell 2 bottom left.

## Constraints

- `1 ≤ rows, columns`, and `rows × columns ≤ 250,000`. Both grids are `rows × columns`.
- `openRight[r][columns - 1]` and `openDown[rows - 1][c]` are always `false`: there are no passages out of the maze.
- A maze can be a single corridor 250,000 cells long, so recursion as deep as the maze will crash.

<Hints>
<Hint>
A maze of n cells is perfect exactly when it's a spanning tree: it has exactly n − 1 passages **and** every cell is reachable from cell 0. Count, then run one BFS. Neither check is enough alone: n − 1 passages can hide a loop in one place and a sealed-off cell in another.
</Hint>
<Hint>
Write `exits(cell)`, the open neighbours, from the two grids. Moving left from `(r, c)` uses `openRight[r][c - 1]`, and moving up uses `openDown[r - 1][c]`. Careful with the shortcut of comparing cell numbers: in a one-column maze, the cell below is also the next number.
</Hint>
<Hint>
For the longest route, BFS from any cell and take the farthest cell, `a`. Then BFS from `a`: the farthest distance found is the answer. In a tree, the farthest cell from anywhere is always one end of a longest route.
</Hint>
</Hints>

## Solutions

<Approach title="BFS from every cell (too slow here)" time="O(n²)" space="O(n)">

Check perfection as below, then run a BFS from every cell and keep the largest distance seen. It's obviously right, and fine for the 7 × 7 mazes in the random tests, but a 500 × 500 maze would take 6 × 10¹⁰ steps.

</Approach>

<Approach title="Count, one BFS to check, two BFS passes for the longest route" time="O(rows × columns)" space="O(rows × columns)">

Everything is iterative, with a queue and a head index, so a 250,000-cell corridor is as safe as a small maze.

```swift
public enum PerfectMazeAudit {
    public static func isPerfect(openRight: [[Bool]], openDown: [[Bool]]) -> Bool {
        guard let maze = Maze(openRight: openRight, openDown: openDown) else { return false }
        guard maze.passageCount == maze.cellCount - 1 else { return false }
        return maze.distances(from: 0).allSatisfy { $0 >= 0 }
    }

    public static func longestRoute(openRight: [[Bool]], openDown: [[Bool]]) -> Int? {
        guard isPerfect(openRight: openRight, openDown: openDown),
              let maze = Maze(openRight: openRight, openDown: openDown) else { return nil }
        let fromFirst = maze.distances(from: 0)
        let end = fromFirst.indices.max { fromFirst[$0] < fromFirst[$1] }!
        return maze.distances(from: end).max()!
    }

    private struct Maze {
        let rows: Int
        let columns: Int
        let openRight: [[Bool]]
        let openDown: [[Bool]]

        init?(openRight: [[Bool]], openDown: [[Bool]]) {
            guard let width = openRight.first?.count, width > 0, openDown.count == openRight.count,
                  openRight.allSatisfy({ $0.count == width }), openDown.allSatisfy({ $0.count == width })
            else { return nil }
            rows = openRight.count
            columns = width
            self.openRight = openRight
            self.openDown = openDown
        }

        var cellCount: Int { rows * columns }

        /// Passages inside the grid (a passage out of the last column or row doesn't lead anywhere)
        var passageCount: Int {
            var count = 0
            for r in 0..<rows {
                for c in 0..<columns {
                    if c + 1 < columns && openRight[r][c] { count += 1 }
                    if r + 1 < rows && openDown[r][c] { count += 1 }
                }
            }
            return count
        }

        func exits(_ cell: Int) -> [Int] {
            let r = cell / columns, c = cell % columns
            var result: [Int] = []
            if c + 1 < columns && openRight[r][c] { result.append(cell + 1) }
            if c > 0 && openRight[r][c - 1] { result.append(cell - 1) }
            if r + 1 < rows && openDown[r][c] { result.append(cell + columns) }
            if r > 0 && openDown[r - 1][c] { result.append(cell - columns) }
            return result
        }

        /// BFS distances from `start`; -1 for cells it can't reach.
        func distances(from start: Int) -> [Int] {
            var distance = [Int](repeating: -1, count: cellCount)
            distance[start] = 0
            var queue = [start]
            var head = 0
            while head < queue.count {
                let cell = queue[head]
                head += 1
                for next in exits(cell) where distance[next] == -1 {
                    distance[next] = distance[cell] + 1
                    queue.append(next)
                }
            }
            return distance
        }
    }
}
```

Why two passes work: start anywhere, at `s`, and let `a` be the cell farthest from it. Take any longest route, from `x` to `y`. In a tree, the route from `s` to `a` meets it somewhere, and since no cell is farther from `s` than `a`, replacing the part of the longest route beyond the meeting point with the way to `a` never makes it shorter. So some longest route ends at `a`, and the second BFS finds its other end. The trick only holds in trees: in a maze with loops, two passes can miss the longest shortest route, which is one more reason to check perfection first.

</Approach>
