Write the two halves of the level-order format yourself: build a tree from an array such as `[3, 9, 20, nil, nil, 15, 7]`, and write a tree back out as one. This is exactly what DSAKit's `TreeNode.make` and `levelOrder` do, so don't call them.

`LevelOrderBuilder.build(_ levelOrder: [Int?]) -> TreeNode?` and `LevelOrderBuilder.levelOrder(_ root: TreeNode?) -> [Int?]`

The format lists the nodes level by level, left to right. Each node that exists gets two entries for its children, in order, with `nil` for a missing child. A missing node gets no entries at all. Trailing `nil`s can be left off, and `levelOrder` must leave them off. An empty array, or a `nil` first entry, is the empty tree, and the empty tree is written as `[]`.

## Examples

| `levelOrder` | The tree |
| --- | --- |
| `[3, 9, 20, nil, nil, 15, 7]` | 3 with children 9 and 20; 20 has children 15 and 7 |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | the running example: 5 has a left child 7, 3 a right child 6 |
| `[1, nil, 2, nil, 3]` | a chain going right: 1, then 2, then 3 |
| `[1, nil, 2, 3, 4]` | 1 has only a right child, 2, which has children 3 and 4 |
| `[1, 2, nil, nil, nil]` | 1 with a left child 2; written back out as `[1, 2]` |
| `[]` or `[nil]` | the empty tree |

In `[1, nil, 2, 3, 4]`, the missing left child of 1 has no entries, so 3 and 4 belong to 2.

## Constraints

- `0 ≤ levelOrder.count ≤ 200,000`
- The input is always well formed: it describes a real tree.
- Trees can be 100,000 levels deep, so use loops rather than recursion.

<Hints>
<Hint>
Parents receive their children in the same order the parents were created: the root first, then its children left to right, then theirs. First in, first out: that's a queue. Use an array with a head index, so taking from the front is O(1).
</Hint>
<Hint>
For `build`: create the root, and put it in the queue. Keep an index into the array. Repeatedly take the next parent from the queue and read two entries: a non-`nil` entry becomes a new child, which joins the queue, and a `nil` is skipped. Stop when the entries run out.
</Hint>
<Hint>
For `levelOrder`: queue `TreeNode?` values, starting with the root. A real node writes its value and queues both its children, even `nil` ones. A `nil` writes `nil` and queues nothing. At the end, remove `nil`s from the end of the result.
</Hint>
</Hints>

## Solutions

<Approach title="A queue in both directions" time="O(n)" space="O(n)">

Both directions walk the tree level by level. `build` hands out entries to parents in queue order; `levelOrder` writes a `nil` for every missing child of a real node, which is exactly what the format records.

```swift
public enum LevelOrderBuilder {
    public static func build(_ levelOrder: [Int?]) -> TreeNode? {
        guard let first = levelOrder.first, let rootValue = first else { return nil }
        let root = TreeNode(rootValue)
        var parents = [root]                      // nodes waiting for their children
        var head = 0
        var index = 1                             // the next entry to read
        while index < levelOrder.count && head < parents.count {
            let parent = parents[head]
            head += 1
            if let value = levelOrder[index] {
                let child = TreeNode(value)
                parent.left = child
                parents.append(child)
            }
            index += 1
            if index < levelOrder.count, let value = levelOrder[index] {
                let child = TreeNode(value)
                parent.right = child
                parents.append(child)
            }
            index += 1
        }
        return root
    }

    public static func levelOrder(_ root: TreeNode?) -> [Int?] {
        guard let root else { return [] }
        var result: [Int?] = []
        var queue: [TreeNode?] = [root]
        var head = 0
        while head < queue.count {
            let node = queue[head]
            head += 1
            if let node {
                result.append(node.value)
                queue.append(node.left)
                queue.append(node.right)
            } else {
                result.append(nil)
            }
        }
        while let last = result.last, last == nil {
            result.removeLast()
        }
        return result
    }
}
```

`guard let first = levelOrder.first, let rootValue = first` unwraps twice: `first` is an `Int??`, because the array might be empty (outer optional) and the entry itself might be `nil` (inner optional). In the final loop, `result.last` is an `Int??` too, and `last == nil` asks whether the entry inside is `nil`.

</Approach>
