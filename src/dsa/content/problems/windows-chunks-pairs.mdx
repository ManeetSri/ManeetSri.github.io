Write three helpers that swift-algorithms provides, without the package: overlapping **windows** of a fixed size, non-overlapping **chunks** of a fixed size, and **adjacent pairs**. All three must work on any `Collection`, including `String` and slices, and windows and chunks must be slices of the original collection, not copies. In your own code you'd write them as extensions on `Collection`; here they're static functions so their names can't clash with the package's.

`SliceWindowHelpers.windows(of: C, count: Int) -> [C.SubSequence]`

`SliceWindowHelpers.chunks(of: C, count: Int) -> [C.SubSequence]`

`SliceWindowHelpers.adjacentPairs(of: C) -> [(C.Element, C.Element)]`

## Examples

| Call | Output |
| --- | --- |
| `windows(of: [4, 7, 5, 9, 12, 11], count: 3)` | `[4, 7, 5]`, `[7, 5, 9]`, `[5, 9, 12]`, `[9, 12, 11]` |
| `windows(of: [4, 7, 5], count: 4)` | no windows |
| `windows(of: "swift", count: 2)` | `"sw"`, `"wi"`, `"if"`, `"ft"` |
| `chunks(of: [4, 7, 5, 9, 12, 11], count: 4)` | `[4, 7, 5, 9]`, `[12, 11]` |
| `chunks(of: "abcdefg", count: 3)` | `"abc"`, `"def"`, `"g"` |
| `adjacentPairs(of: [150, 152, 149, 160])` | `(150, 152)`, `(152, 149)`, `(149, 160)` |
| `windows(of: scores[2...], count: 2)` with `scores = [10, 20, 30, 40, 50]` | slices starting at indexes 2, 3 and 4 |

The last example is the important one: a slice keeps its parent's indexes, so the first window of `scores[2...]` starts at index 2, not 0.

## Constraints

- `count ≥ 1`.
- The collection has up to 50,000 elements, and the tests use windows of 500 elements, so don't copy each window into a new array.
- The tests include a `String` (whose indexes aren't `Int`s) and a `Set` (whose indexes aren't either), so never assume indexes are integers starting at 0.

<Hints>
<Hint>
Move through the collection with `startIndex`, `index(after:)` and `index(_:offsetBy:limitedBy:)`. The `limitedBy:` version returns `nil` instead of running past `endIndex`, which tells you when a window doesn't fit or a chunk is the last, short one.
</Hint>
<Hint>
For windows, find the end of the first window once (`nil` means no window fits), then slide both ends forward one step at a time with `formIndex(after:)` until the end reaches `endIndex`. `base[start..<end]` is the slice.
</Hint>
<Hint>
Adjacent pairs is the standard library idiom from the lesson: `zip(base, base.dropFirst())`.
</Hint>
</Hints>

## Solutions

<Approach title="Index arithmetic on any collection" time="O(n)" space="O(n) for the results">

Each function walks indexes instead of integers, and every result is a slice, created in O(1). Finding the first window's end costs O(k) on a collection that can only step forward; after that, each window is one step of both ends.

```swift
public enum SliceWindowHelpers {
    public static func windows<C: Collection>(of base: C, count: Int) -> [C.SubSequence] {
        guard count > 0,
              var end = base.index(base.startIndex, offsetBy: count, limitedBy: base.endIndex)
        else { return [] }
        var start = base.startIndex
        var result = [base[start..<end]]
        while end != base.endIndex {
            base.formIndex(after: &start)
            base.formIndex(after: &end)
            result.append(base[start..<end])
        }
        return result
    }

    public static func chunks<C: Collection>(of base: C, count: Int) -> [C.SubSequence] {
        guard count > 0 else { return [] }
        var result: [C.SubSequence] = []
        var start = base.startIndex
        while start != base.endIndex {
            let end = base.index(start, offsetBy: count, limitedBy: base.endIndex) ?? base.endIndex
            result.append(base[start..<end])
            start = end
        }
        return result
    }

    public static func adjacentPairs<C: Collection>(of base: C) -> [(C.Element, C.Element)] {
        Array(zip(base, base.dropFirst()))
    }
}
```

swift-algorithms goes one step further and returns lazy collections instead of arrays, so nothing is built until you iterate. Returning arrays of slices keeps this version simple while still never copying elements.

</Approach>
