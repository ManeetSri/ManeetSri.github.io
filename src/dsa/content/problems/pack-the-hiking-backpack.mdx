You're packing for a hike. Item `i` weighs `weights[i]` and is worth `values[i]` to you, and the backpack holds a total weight of at most `capacity`. Each item is packed once or left at home. Return the **indexes** of the items to pack, in increasing order, so that the total value is as large as possible. If several packings tie for the most value, any of them is accepted.

`HikingBackpackPacking.bestPack(weights: [Int], values: [Int], capacity: Int) -> [Int]`

## Examples

| `weights` | `values` | `capacity` | Output |
| --- | --- | --- | --- |
| `[4, 2, 3, 5]` | `[10, 4, 7, 11]` | `9` | `[0, 1, 2]` |
| `[6, 5, 5]` | `[13, 10, 10]` | `10` | `[1, 2]` |
| `[6, 6]` | `[5, 8]` | `5` | `[]` |
| `[]` | `[]` | `10` | `[]` |

In the first example, items 0, 1 and 2 weigh 9 and are worth 21. Items 0 and 3 are also worth 21, so `[0, 3]` is accepted too. In the second, the most valuable item per unit of weight is item 0, but packing it leaves 4 units that nothing fits: items 1 and 2 together are worth 20. In the third, nothing fits.

## Constraints

- `0 ≤ weights.count ≤ 100`, and `values.count == weights.count`
- `1 ≤ weights[i] ≤ 10,000` and `1 ≤ values[i] ≤ 10,000`
- `0 ≤ capacity ≤ 10,000`
- The tests use 100 items with a capacity of 10,000, so trying every subset is out of the question.

<Hints>
<Hint>
Build the table `best[i][w]`: the most value from the first `i` items with room `w`. Item `i` (index `i - 1`) is either left behind or packed.
</Hint>
<Hint>
The one-row version finds the best value, but it forgets how it got there. Keep the whole 2D table so you can walk back through it.
</Hint>
<Hint>
Start at `best[n][capacity]` and go up one row at a time. If the cell equals the one above it, the item wasn't needed. Otherwise it was packed: record its index and subtract its weight from the room. Reverse the list at the end.
</Hint>
</Hints>

## Solutions

<Approach title="Try every subset" time="O(2ⁿ · n)" space="O(n)">

Each item is in or out, so a bitmask from 0 to 2ⁿ − 1 lists every packing. Keep the most valuable one that fits. It's a good referee for small tests, but 100 items means 2¹⁰⁰ subsets.

</Approach>

<Approach title="2D knapsack table, then walk back" time="O(n · capacity)" space="O(n · capacity)">

Fill the table row by row. Each cell is the better of leaving item `i` behind (the cell above) and packing it (the cell above, `weight` columns to the left, plus its value). Then reconstruct from the bottom-right corner: a cell that beats the one above it means the item was packed.

```swift
public enum HikingBackpackPacking {
    public static func bestPack(weights: [Int], values: [Int], capacity: Int) -> [Int] {
        let n = weights.count
        var best = Array(repeating: Array(repeating: 0, count: capacity + 1), count: n + 1)
        for i in stride(from: 1, through: n, by: 1) {
            let weight = weights[i - 1]
            let value = values[i - 1]
            for w in 0...capacity {
                best[i][w] = best[i - 1][w]                          // leave item i behind
                if weight <= w {
                    best[i][w] = max(best[i][w], best[i - 1][w - weight] + value)   // or pack it
                }
            }
        }
        var packed: [Int] = []
        var room = capacity
        for i in stride(from: n, through: 1, by: -1) where best[i][room] != best[i - 1][room] {
            packed.append(i - 1)
            room -= weights[i - 1]
        }
        return packed.reversed()
    }
}
```

`stride(from: 1, through: n, by: 1)` is empty when there are no items, where `1...n` would crash. The walk back visits items from last to first, which is why the list is reversed at the end. With 101 × 10,001 cells, the table holds about a million `Int`s, 8 MB, which is fine.

</Approach>
