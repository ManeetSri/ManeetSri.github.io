A navigation app has `places` places, numbered `0` to `places - 1`, joined by two-way roads. Each road `[a, b, minutes]` can be driven in either direction in `minutes` minutes. The app's routing engine has produced a table: `claimed[v]` is meant to be the fewest minutes from `start` to place v, or `nil` if v can't be reached at all. Return `true` if the table is exactly right, and `false` if any entry is wrong.

`DistanceTableAudit.isExact(places: Int, roads: [[Int]], start: Int, claimed: [Int?]) -> Bool`

## Examples

The first five use the town from the lesson: `places = 4`, `roads = [[0, 3, 10], [0, 1, 2], [1, 2, 3], [2, 3, 2]]` and `start = 0` (home, park, shop, school).

| `claimed` | Output | Why |
| --- | --- | --- |
| `[0, 2, 5, 7]` | `true` | |
| `[0, 2, 5, 10]` | `false` | the road from the shop gives school 5 + 2 = 7 |
| `[0, 2, 5, 6]` | `false` | no route to school takes 6 minutes |
| `[0, 2, 5, nil]` | `false` | school can be reached |
| `[1, 3, 6, 8]` | `false` | the start is 0 minutes from itself |
| `[0, 3, 3]` with `places = 3`, `roads = [[0, 1, 5], [1, 2, 0]]` | `false` | the true table is `[0, 5, 5]` |

The last example is the trap. Places 1 and 2 are joined by a 0-minute footbridge, so each claim of 3 looks backed up by the other: "I'm 3, and the bridge to you is free." No road can make either claim smaller. But no actual route from the start takes 3 minutes.

## Constraints

- `1 ≤ places ≤ 110,000` and `0 ≤ roads.count ≤ 200,000`, with `0 ≤ a, b < places` and `0 ≤ minutes ≤ 1,000,000,000`. There can be several roads between the same two places, and roads from a place to itself.
- `claimed.count == places`, `0 ≤ start < places`, and every claimed number is between `-10¹²` and `10¹²`.
- The tests use about 100,000 places and 200,000 roads, so re-running a relaxation loop until nothing changes is too slow. You don't need a shortest-path algorithm at all.

<Hints>
<Hint>
Relaxation never makes an estimate wrong, and when no edge can be relaxed any more, the estimates are exact. Turn that around: which checks on the table, road by road, would a correct table pass?
</Hint>
<Hint>
Two checks. First, no road can improve anything: for every road from a claimed place u to v, v must be claimed too, and `claimed[u] + minutes ≥ claimed[v]`. With `claimed[start] == 0`, that guarantees no claim is **too big**. Second, every claim must be the length of a real route, so that none is **too small**.
</Hint>
<Hint>
Call a road "tight" when `claimed[u] + minutes == claimed[v]`: it's the last road of a route that achieves v's claim. Run a BFS from the start that only follows tight roads. Every claimed place must be reached. Checking only that each place has *some* tight road into it isn't enough: in the footbridge example, places 1 and 2 are tight to each other.
</Hint>
</Hints>

## Solutions

<Approach title="Recompute the table" time="O(places · roads)" space="O(places + roads)">

Relax every road in both directions, pass after pass, until a whole pass changes nothing, then compare the result with `claimed`. It's correct, and it's how the lesson found the shortest paths, but a long chain of places can take one pass per place: far too slow at this size.

</Approach>

<Approach title="Check the two properties of relaxation" time="O(places + roads)" space="O(places + roads)">

If no road can be relaxed, then along any shortest route each claim is at most the one before it plus the road, so every claim is at most the true distance. If every claimed place is reached along tight roads, its claim is the length of that route, so it's at least the true distance. Together they pin every claim to the truth, and the first check also catches a reachable place marked `nil`, since some road would lead from a claimed place into it.

```swift
public enum DistanceTableAudit {
    public static func isExact(places: Int, roads: [[Int]], start: Int, claimed: [Int?]) -> Bool {
        guard claimed[start] == 0 else { return false }
        var graph: [[(to: Int, minutes: Int)]] = Array(repeating: [], count: places)
        for road in roads {
            graph[road[0]].append((road[1], road[2]))
            graph[road[1]].append((road[0], road[2]))             // two-way: both directions
        }
        // (1) Nothing can be relaxed, and nothing reachable is marked unreachable
        for place in 0..<places {
            guard let here = claimed[place] else { continue }
            for road in graph[place] {
                guard let there = claimed[road.to], here + road.minutes >= there else { return false }
            }
        }
        // (2) Every claimed place is reached from the start along tight roads
        var reached = Array(repeating: false, count: places)
        reached[start] = true
        var queue = [start]
        var head = 0
        while head < queue.count {
            let place = queue[head]
            head += 1
            let here = claimed[place]!
            for road in graph[place] where !reached[road.to] && claimed[road.to] == here + road.minutes {
                reached[road.to] = true
                queue.append(road.to)
            }
        }
        return (0..<places).allSatisfy { claimed[$0] == nil || reached[$0] }
    }
}
```

The force unwrap `claimed[place]!` is safe: the BFS only enters places whose claim equals a number. And `claimed[road.to] == here + road.minutes` compares an `Int?` with an `Int`, which is `false` for `nil`, so unreachable places are never entered. A claimed number can't overflow when a road is added, because both stay far below `Int.max`.

</Approach>
