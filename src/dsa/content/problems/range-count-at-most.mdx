You're given a fixed array of integers and a batch of questions. Each question names a range of positions and a threshold, and asks how many values in that range are at most the threshold. Answer them all.

`RangeCountAtMost.answer(_ values: [Int], queries: [[Int]]) -> [Int]`

A query `[left, right, x]` covers `values[left...right]`, inclusive, and counts the values `≤ x`. Return the answers in the same order as the queries. The values never change.

## Examples

With `values = [4, 9, 2, 7, 2, 5]`:

| Query | Output | Why |
| --- | --- | --- |
| `[0, 5, 4]` | `3` | 4, 2 and 2 |
| `[1, 3, 6]` | `1` | of 9, 2 and 7, only 2 |
| `[2, 4, 1]` | `0` | 2, 7 and 2 are all above 1 |
| `[3, 3, 7]` | `1` | 7 itself counts: "at most" includes equal |
| `[0, 5, 100]` | `6` | everything |

So the result is `[3, 1, 0, 1, 6]`.

## Constraints

- `1 ≤ values.count ≤ 100,000`, and `0 ≤ queries.count ≤ 100,000`
- `-10⁹ ≤ values[i], x ≤ 10⁹`
- Every query has `0 ≤ left ≤ right < values.count`.
- The tests use 100,000 values and 100,000 wide queries, so counting each range with a loop is too slow.

<Hints>
<Hint>
Split each query range into the O(log n) whole blocks of a segment tree. If every block knew its values **in sorted order**, how fast could you count the ones at most x?
</Hint>
<Hint>
With a sorted block, an upper-bound binary search finds the first value greater than x, and its index is the count. Build every node's sorted array by merging its children's, exactly like merge sort. That's a merge-sort tree: O(n log n) memory, O(log² n) per query.
</Hint>
<Hint>
There's also an offline approach, since all the queries are known up front: sort the queries by x and the values by size. Sweep x upwards, marking each value's position in a Fenwick tree as soon as it's at most the current x. Then a query is a range count of marked positions.
</Hint>
</Hints>

## Solutions

<Approach title="Count each range" time="O(n · q)" space="O(1)">

One pass over each range. Fine for a few queries, far too slow for 100,000 wide ones.

```swift
public static func answer(_ values: [Int], queries: [[Int]]) -> [Int] {
    queries.map { query in values[query[0]...query[1]].filter { $0 <= query[2] }.count }
}
```

</Approach>

<Approach title="Merge-sort tree" time="O(n log n + q log² n)" space="O(n log n)">

The structure from [Merge-sort trees](/dsa/learn/seg-merge-sort-tree). Every node stores its block sorted, built by merging its children's arrays in one pass. A query takes the whole blocks inside the range and runs an upper-bound search in each.

```swift
public enum RangeCountAtMost {
    public static func answer(_ values: [Int], queries: [[Int]]) -> [Int] {
        guard !values.isEmpty else { return queries.map { _ in 0 } }
        let tree = MergeSortTree(values)
        return queries.map { tree.countAtMost($0[2], $0[0], $0[1]) }
    }

    private struct MergeSortTree {
        private var sorted: [[Int]]
        private let count: Int

        init(_ values: [Int]) {
            count = values.count
            sorted = Array(repeating: [], count: 4 * values.count)
            build(values, 1, 0, count - 1)
        }

        private mutating func build(_ values: [Int], _ node: Int, _ low: Int, _ high: Int) {
            if low == high {
                sorted[node] = [values[low]]
                return
            }
            let mid = (low + high) / 2
            build(values, 2 * node, low, mid)
            build(values, 2 * node + 1, mid + 1, high)
            let a = sorted[2 * node], b = sorted[2 * node + 1]
            var merged: [Int] = []
            merged.reserveCapacity(a.count + b.count)
            var i = 0, j = 0
            while i < a.count && j < b.count {
                if a[i] <= b[j] {
                    merged.append(a[i])
                    i += 1
                } else {
                    merged.append(b[j])
                    j += 1
                }
            }
            merged.append(contentsOf: a[i...])
            merged.append(contentsOf: b[j...])
            sorted[node] = merged
        }

        func countAtMost(_ x: Int, _ left: Int, _ right: Int) -> Int {
            count(x, left, right, 1, 0, count - 1)
        }

        private func count(_ x: Int, _ left: Int, _ right: Int, _ node: Int, _ low: Int, _ high: Int) -> Int {
            if right < low || high < left { return 0 }
            if left <= low && high <= right { return upperBound(sorted[node], x) }
            let mid = (low + high) / 2
            return count(x, left, right, 2 * node, low, mid) + count(x, left, right, 2 * node + 1, mid + 1, high)
        }

        private func upperBound(_ values: [Int], _ x: Int) -> Int {
            var low = 0, high = values.count
            while low < high {
                let mid = (low + high) / 2
                if values[mid] <= x { low = mid + 1 } else { high = mid }
            }
            return low
        }
    }
}
```

</Approach>

<Approach title="Offline: sort the queries, sweep with a Fenwick tree" time="O((n + q) log n)" space="O(n + q)">

When every query is known before any answer is needed, the order of answering is yours to choose. Answer them in increasing order of x. Keep the values sorted, and before each query mark the position of every value that has become at most x. The answer is the number of marked positions in `left...right`, a Fenwick tree range sum. This uses DSAKit's `FenwickTree`, which M61 builds.

```swift
import DSAKit

public enum RangeCountAtMost {
    public static func answer(_ values: [Int], queries: [[Int]]) -> [Int] {
        let byValue = values.indices.sorted { values[$0] < values[$1] }
        let byX = queries.indices.sorted { queries[$0][2] < queries[$1][2] }
        var marked = FenwickTree(count: values.count)
        var answers = Array(repeating: 0, count: queries.count)
        var next = 0
        for q in byX {
            let query = queries[q]
            while next < byValue.count && values[byValue[next]] <= query[2] {
                marked.add(1, at: byValue[next])
                next += 1
            }
            answers[q] = marked.sum(in: query[0]...query[1])
        }
        return answers
    }
}
```

It's faster and uses less memory than the merge-sort tree, but it only works offline. The merge-sort tree answers each query the moment it arrives.

</Approach>
