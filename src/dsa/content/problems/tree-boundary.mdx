Return the values around the outside of a binary tree, anticlockwise, starting at the root, with each node listed once.

`TreeBoundary.boundary(_ root: TreeNode?) -> [Int]`

The boundary is four pieces, in this order:

1. **The root.**
2. **The left edge**, top to bottom. Start at the root's left child. From each node, move to its left child, or to its right child if it has no left one. Stop before you reach a leaf.
3. **The leaves**, left to right: every node with no children.
4. **The right edge**, bottom to top. Start at the root's right child. From each node, move to its right child, or to its left child if it has no right one. Stop before a leaf.

Leaves are never part of an edge, so nothing is listed twice. If the root has no left child, the left edge is empty, and likewise on the right. A root on its own is `[root]`, and the empty tree is `[]`.

## Examples

| Tree (level order) | Output |
| --- | --- |
| `[1, 2, 3, 4, 5, nil, 6, nil, nil, 7]` | `[1, 2, 4, 7, 6, 3]` |
| `[1, 2, 3, 4, 5, 6, 7]` | `[1, 2, 4, 5, 6, 7, 3]` |
| `[1, nil, 2, 3, 4]` | `[1, 3, 4, 2]` |
| `[1, 2, 3, nil, 4, nil, nil, 5, 6]` | `[1, 2, 4, 5, 6, 3]` |
| `[1, 2, nil, 3, nil, 4]` | `[1, 2, 3, 4]` |
| `[5]` | `[5]` |

In the first tree, the left edge is just 2 (its left child 4 is a leaf), the leaves are 4, 7 and 6, and the right edge is just 3. In the fourth, 2 has no left child, so the left edge carries on to its right child, 4. In `[1, nil, 2, 3, 4]` the root has no left child, so the left edge is empty and the right edge is 2.

## Constraints

- `0 ≤` number of nodes `≤ 100,000`
- Trees in the tests are at most 500 levels deep.

<Hints>
<Hint>
Build the answer from three separate walks and glue them together. The two edges are simple loops: no recursion or stack needed, because there's only one way to go from each node.
</Hint>
<Hint>
For the leaves, any depth-first traversal visits them from left to right: preorder, inorder and postorder all do. Record a node when both its children are `nil`. Remember the root alone is a special case: it's the root and a leaf, but must appear once.
</Hint>
<Hint>
Collect the right edge top to bottom, as the loop finds it, then append it reversed. Check the edge loops stop *before* a leaf, with a condition like `while let node = next, !isLeaf(node)`, or the bottom node of each edge gets listed twice.
</Hint>
</Hints>

## Solutions

<Approach title="Edge, leaves, edge" time="O(n)" space="O(h)">

Two loops for the edges and a preorder walk with an explicit stack for the leaves. Pushing the right child before the left makes the leaves come out left to right.

```swift
public enum TreeBoundary {
    private static func isLeaf(_ node: TreeNode) -> Bool {
        node.left == nil && node.right == nil
    }

    public static func boundary(_ root: TreeNode?) -> [Int] {
        guard let root else { return [] }
        var result = [root.value]
        if isLeaf(root) {
            return result
        }

        var next = root.left
        while let node = next, !isLeaf(node) {
            result.append(node.value)
            next = node.left ?? node.right
        }

        var stack = [root]
        while let node = stack.popLast() {
            if isLeaf(node) {
                result.append(node.value)
            }
            if let right = node.right { stack.append(right) }
            if let left = node.left { stack.append(left) }
        }

        var rightEdge: [Int] = []
        next = root.right
        while let node = next, !isLeaf(node) {
            rightEdge.append(node.value)
            next = node.right ?? node.left
        }
        result += rightEdge.reversed()
        return result
    }
}
```

The leaf walk starts at the root, which is safe: the root isn't a leaf by this point, so it isn't recorded again.

</Approach>

<Approach title="One recursive pass with edge flags" time="O(n)" space="O(h)">

Each call knows whether its node is on the left edge or the right edge. A left-edge node passes the flag to its left child always, and to its right child only when there's no left child; the right edge mirrors that. Leaves are recorded in preorder, which is left to right.

```swift
public static func boundary(_ root: TreeNode?) -> [Int] {
    guard let root else { return [] }
    if root.left == nil && root.right == nil { return [root.value] }
    var leftEdge: [Int] = []
    var leaves: [Int] = []
    var rightEdge: [Int] = []
    func walk(_ node: TreeNode?, onLeftEdge: Bool, onRightEdge: Bool) {
        guard let node else { return }
        if node.left == nil && node.right == nil {
            leaves.append(node.value)
        } else if onLeftEdge {
            leftEdge.append(node.value)
        } else if onRightEdge {
            rightEdge.append(node.value)
        }
        walk(node.left, onLeftEdge: onLeftEdge, onRightEdge: onRightEdge && node.right == nil)
        walk(node.right, onLeftEdge: onLeftEdge && node.left == nil, onRightEdge: onRightEdge)
    }
    walk(root.left, onLeftEdge: true, onRightEdge: false)
    walk(root.right, onLeftEdge: false, onRightEdge: true)
    return [root.value] + leftEdge + leaves + rightEdge.reversed()
}
```

One pass instead of three, at the cost of flags that are easy to get subtly wrong. The tests compare the two methods on a 100,000-node tree.

</Approach>
