You've run a timing experiment and have the durations. Write the helpers that turn them into conclusions: the best and the median run, durations in milliseconds, and what a doubling experiment says about how the work grows.

`TimingExperimentReport.best(of:)`, `median(of:)`, `milliseconds(_:)`, `ratios(_:)` and `growth(of:)`

- **`best(of:)`**: the fastest run, or `nil` when there are none.
- **`median(of:)`**: the middle run once sorted from fastest to slowest. With an even number of runs, the faster of the two middle ones. `nil` when there are none.
- **`milliseconds(_:)`**: a `Duration` in milliseconds, as a `Double`.
- **`ratios(_:)`**: for times measured at sizes n, 2n, 4n and so on, each time divided by the one before it.
- **`growth(of:)`**: judged by the average of the ratios: below 1.5 is `"constant"`, below 3 is `"linear"`, below 6 is `"quadratic"`, and anything more is `"cubic"`. `nil` with fewer than two times.

## Examples

| Call | Result |
| --- | --- |
| `best(of: [4.2 ms, 3.9 ms, 5.0 ms])` | 3.9 ms |
| `median(of: [8 ms, 2 ms, 6 ms, 4 ms])` | 4 ms |
| `milliseconds(.microseconds(250))` | `0.25` |
| `ratios([2 ms, 4 ms, 16 ms, 8 ms])` | `[2.0, 4.0, 0.5]` |
| `growth(of: [1 ms, 2 ms, 4 ms, 8 ms])` | `"linear"` |
| `growth(of: [0.22 ms, 0.79 ms, 3.13 ms, 13.94 ms])` | `"quadratic"` (the lesson's pair-counting run) |
| `growth(of: [3 ms])` | `nil` |

Here "4.2 ms" stands for a `Duration` such as `.microseconds(4_200)`.

## Constraints

- Up to 1,000 durations, all positive.
- The tests use made-up durations, so nothing depends on how fast your computer is.

<Hints>
<Hint>
`Duration` is `Comparable`, so `runs.min()` and `runs.sorted()` work directly. After sorting, index `(runs.count - 1) / 2` is the middle for an odd count and the faster middle for an even one.
</Hint>
<Hint>
Dividing one `Duration` by another gives a plain `Double`. So `duration / .milliseconds(1)` is the number of milliseconds, and `times[i] / times[i - 1]` is a ratio.
</Hint>
<Hint>
For `growth`, compute the ratios, return `nil` if there are none, then compare their average with 1.5, 3 and 6 in turn.
</Hint>
</Hints>

## Solutions

<Approach title="Let Duration do the arithmetic" time="O(n log n) for median, O(n) for the rest" space="O(n)">

`Duration` behaves like a number: it compares, sorts and divides. The doubling rule comes from the lesson: when n doubles, linear work doubles, quadratic work quadruples and cubic work grows eightfold. The thresholds sit between those ratios, so real, noisy measurements still land in the right band.

```swift
public enum TimingExperimentReport {
    public static func best(of runs: [Duration]) -> Duration? {
        runs.min()
    }

    public static func median(of runs: [Duration]) -> Duration? {
        guard !runs.isEmpty else {
            return nil
        }
        return runs.sorted()[(runs.count - 1) / 2]
    }

    public static func milliseconds(_ duration: Duration) -> Double {
        duration / .milliseconds(1)
    }

    public static func ratios(_ times: [Duration]) -> [Double] {
        guard times.count > 1 else {
            return []
        }
        var result: [Double] = []
        for index in 1..<times.count {
            result.append(times[index] / times[index - 1])
        }
        return result
    }

    public static func growth(of times: [Duration]) -> String? {
        let steps = ratios(times)
        guard !steps.isEmpty else {
            return nil
        }
        let average = steps.reduce(0, +) / Double(steps.count)
        if average < 1.5 {
            return "constant"
        } else if average < 3 {
            return "linear"
        } else if average < 6 {
            return "quadratic"
        }
        return "cubic"
    }
}
```

Keeping the measuring separate from the reading is what makes these helpers testable: the clock only produces durations, and everything after that is ordinary, deterministic code.

</Approach>
