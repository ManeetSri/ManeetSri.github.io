Write two nth-root functions without using `pow`, `sqrt` or `cbrt`. The first works on whole numbers and must be exact: it returns the largest whole number r with rⁿ ≤ x. The second works on `Double` and returns the real nth root of x, accurate to within 10⁻⁹ × max(1, the true root).

`NthRootBisection.floorRoot(of x: Int, degree n: Int) -> Int` and `NthRootBisection.root(of x: Double, degree n: Int) -> Double`

## Examples

| Call | Output |
| --- | --- |
| `floorRoot(of: 30, degree: 2)` | `5` |
| `floorRoot(of: 1000, degree: 3)` | `10` |
| `floorRoot(of: 999, degree: 3)` | `9` |
| `floorRoot(of: 7, degree: 1)` | `7` |
| `floorRoot(of: Int.max, degree: 2)` | `3037000499` |
| `floorRoot(of: Int.max, degree: 63)` | `1` |
| `root(of: 2, degree: 2)` | about `1.4142135623730951` |
| `root(of: 0.25, degree: 2)` | about `0.5` |
| `root(of: 1e18, degree: 3)` | about `1000000.0` |

`Int.max` is 2⁶³ − 1, so its 63rd root is just under 2, and the floor is 1. The square root of 0.25 is bigger than 0.25 itself, which matters when you choose bounds.

## Constraints

- `floorRoot`: `0 ≤ x ≤ Int.max` and `1 ≤ n ≤ 64`. Don't use `Double` at all.
- `root`: `0 ≤ x ≤ 10¹⁸` and `1 ≤ n ≤ 30`.

<Hints>
<Hint>
For `floorRoot`, "rⁿ ≤ x" is true for small r and false from some point on, so you want its last true. Search for the first r with rⁿ > x, then subtract 1. Handle n = 1 and x below 2 first: their answer is x itself.
</Hint>
<Hint>
Computing rⁿ directly overflows for big r. Multiply one step at a time, and before each step test `result > x / r`: if it's true, result × r would be more than x, so you can stop and answer "yes, rⁿ > x" without multiplying. Use x itself as the top of the search, not x + 1, which would overflow for `Int.max`.
</Hint>
<Hint>
For `root`, bisect on `Double` between 0 and `max(1, x)`, using `low = mid` and `high = mid`, and halve a fixed 100 times rather than looping until the interval is small. Computing midⁿ by repeated multiplication is fine, even if it reaches infinity for a huge mid.
</Hint>
</Hints>

## Solutions

<Approach title="Count up for the whole root" time="O(r · n)" space="O(1)">

Try r = 1, 2, 3, … until rⁿ passes x. It's exact and useful as a checker, but the square root of `Int.max` is about 3 billion, so it's far too slow for big inputs. It also needs the same overflow-safe power check as the next approach.

```swift
public static func floorRoot(of x: Int, degree n: Int) -> Int {
    if n == 1 || x < 2 { return x }
    var r = 1
    while !power(r + 1, n, exceeds: x) {
        r += 1
    }
    return r
}
```

</Approach>

<Approach title="Binary search on Int, bisection on Double" time="O(n log x) and O(100 · n)" space="O(1)">

Both functions are binary searches on the answer. The whole-number one finds the first r whose nth power passes x, using x as the top of the half-open range: for n ≥ 2 and x ≥ 2, xⁿ is already more than x. The `Double` one halves an interval that always contains the root, a fixed number of times, so it can never get stuck the way an epsilon loop can for large values.

```swift
public enum NthRootBisection {
    public static func floorRoot(of x: Int, degree n: Int) -> Int {
        if n == 1 || x < 2 { return x }
        var low = 1
        var high = x                                     // xⁿ > x, so the first r with rⁿ > x is ≤ x
        while low < high {
            let mid = low + (high - low) / 2
            if power(mid, n, exceeds: x) {
                high = mid
            } else {
                low = mid + 1
            }
        }
        return low - 1                                   // the last r with rⁿ ≤ x
    }

    public static func root(of x: Double, degree n: Int) -> Double {
        var low = 0.0
        var high = Swift.max(1.0, x)
        for _ in 0..<100 {
            let mid = (low + high) / 2
            var value = 1.0
            for _ in 0..<n { value *= mid }              // may reach infinity, which still compares correctly
            if value >= x {
                high = mid
            } else {
                low = mid
            }
        }
        return (low + high) / 2
    }

    /// True if baseⁿ > limit, for base ≥ 1 and limit ≥ 0, without overflowing.
    private static func power(_ base: Int, _ n: Int, exceeds limit: Int) -> Bool {
        var result = 1
        for _ in 0..<n {
            if result > limit / base { return true }     // result × base would pass limit
            result *= base
        }
        return false
    }
}
```

For whole numbers, `result > limit / base` is exactly "result × base > limit": integer division rounds down, so the two agree for every positive value. 100 halvings shrink the `Double` interval by 2¹⁰⁰, far more than a `Double` can resolve, so the answer ends up as close as the type allows.

</Approach>
