# design-swift

The companion package for the console's **System Design** course. Open the folder in Xcode, or use the
command line from this folder.

| Folder | What's in it |
|---|---|
| `Sources/DesignKit` | Helpers every kata can use: a test clock, a seeded random generator, an HTTP client you can stub, an in-memory store, a recorder. |
| `Sources/Exercises` | Your code. Each kata starts as a stub that compiles but fails its tests. The console's editor starts from the same stub; on the dev server its Save to package button writes your code here. |
| `Sources/Solutions` | Reference solutions. |
| `Tests/DesignTests` | One test suite per kata, compiled against `Exercises` by default or `Solutions` with `-DSOLUTIONS`. |
| `Examples` | Every runnable example from the lessons, generated by `npm run design:examples`. Run one with `swift Examples/<module>/<file>.swift`. |

Folders inside `Exercises`, `Solutions` and `Tests/DesignTests` are named after the course's module ids.

```bash
swift test --filter BackoffScheduleTests     # check your answer to one kata
swift test -Xswiftc -DSOLUTIONS              # every reference solution passes
```

The package uses Swift 6 language mode, so data races are compile errors. Katas use only Foundation and
Swift Concurrency, so they run on a Mac; lessons type-check their UIKit and SwiftUI code against the iOS SDK.
